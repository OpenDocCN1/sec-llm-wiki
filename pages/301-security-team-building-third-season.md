## 文章背景与系列定位

本文为 **301在路上** 微信公众号「成长型互联网企业该如何构建安全团队」系列的**第三季**，由安全从业者 **smarttang** 投稿撰写。系列前两季分别为：

- 第一季：[成长型互联网企业该如何构建安全团队—第一季](http://mp.weixin.qq.com/s?__biz=MzIwMTQ2NzY4NA==&mid=403917916&idx=1&sn=c3931efa25bdae014307d87f535b60ce&scene=21#wechat_redirect)
- 第二季：[互联网企业该如何构建安全团队第二季—安全初期](http://mp.weixin.qq.com/s?__biz=MzIwMTQ2NzY4NA==&mid=403928789&idx=1&sn=91d5ce1d3f5149e7d421bae226bca1c1&scene=21#wechat_redirect)

作者在完成业务系统渗透测试、建立初步业务认知后，进入「困惑期」：如何对全景业务进行系统梳理、分级，并用有限精力落地核心安全能力。

---

## 业务全景梳理：四大需求分类

作者将所有安全需求统一归类为四类，形成第一张业务全景图：

| 分类 | 定义 | 典型场景 |
|------|------|----------|
| **重点项目** | 公司战略级项目，需全局安全支撑，确保安全质量 | 核心交易系统、用户核心数据平台 |
| **特殊项目** | 突发型、时效短、试水性项目 | 广告业务、临时对外开放的营销活动页 |
| **安全巡检** | 上线前检测、迭代后变更测试、持续安全监控 | 例行渗透测试、上线前安全评估 |
| **运营需求** | 运营数据后台统计类平台 | BI 报表、数据分析后台 |

> **实践启示**：分类的目的是「看清当前作业情况」，为后续分级与资源分配提供坐标系。

---

## 业务分级化：权重衡量与资源倾斜

在分类基础上，作者结合**业务特性、需求紧迫度、业务体量**三个维度进行权重衡量，输出业务分级矩阵（文中附图因涉及核心业务已脱敏）。

**核心原则**：「用有限的精力，放在该着力的地方」——把需要做深的业务做起来，可放一放的事项暂缓。

### 关键转折点：CTO 的质疑与众测触动

- CTO 提问：**「你怎么知道当前业务是安全的？」**——暴露管理层对安全可信度的怀疑
- 众测服务实测中，白帽子从边缘机器跳转至核心内网机器，**瞬间击碎安全信心**
- 由此倒逼作者从「表层限制」（基线检测、堡垒机）转向「源头治理」：**围绕五大基础安全模块落地**

## 五大基础安全落地实践框架

作者按实施优先级依次展开，每模块均包含「实施、落地」两个维度的具体动作。

### 应急响应（最高优先级）

| 场景 | 核心动作 | 关键产出 |
|------|----------|----------|
| **Web 应用被入侵** | 日志分析 + 源码审计定位漏洞 → 快速修复 → 复盘溯源 | 入侵根因报告、修复验证记录 |
| **线上系统被入侵** | 从服务层排查 → 模拟攻击路径 → 痕迹追踪 → 联动运维修复 | 攻击链复盘图、加固清单 |
| **漏洞事件** | 将漏洞复现方法、利用方式通过邮件/IM 推送研发紧急处理 | 漏洞通告单、修复跟踪表 |

> **工具支撑**：自动化基线检测工具 `baseline_testing` 已开源至 GitHub：<https://github.com/smarttang/baseline_testing>

### 业务应用安全

- **上线前安全检查**：覆盖业务系统层、Web 应用层、服务层；结合商用工具与开源工具提效；输出完整检测报告
- **例行巡检**：随技术迭代周期性巡检，维持长期安全基线；输出例行巡检报告

### 终端安全

- 侧重内部 PC 端：端口扫描、开放服务弱点检查
- 定期输出终端安全状况报告

### 网络安全

- 网络设备 IOS 版本审查、风险识别
- 返厂升级 / 打补丁 / 版本更新
- 定时检查 + 弱点定期汇总汇报

### 口令安全

- 例行化工作：资产设备、应用系统口令爆破与分析
- 识别薄弱口令 → 整理输出 → 推动整改闭环

## 实践心法：汇聚与内化

> 「在基础安全上，笔者做了很多的汇聚，包括跟业内比较专业的人士交流学习，并且转化成自己的沉淀，在实践上不断的磨合尝试，最后得到的结果非常不错。」

- **外部汲取**：与业内专家交流、学习成熟方案
- **内化沉淀**：结合自身业务场景二次加工
- **实战磨合**：在落地中不断修正参数、流程、工具链

## 五大安全人才画像：团队组建与人才梯队的补充维度

在完成业务分级与基础安全落地的框架搭建后，**「人」的维度**成为决定团队能否持续演进的关键变量。301在路上同期文章《这才是互联网与安全团队需要的几种人才！》提出**五大安全人才画像**，作为团队组建与人才梯队规划的补充维度，与上述「业务-技术」双轨框架形成「人-业-技」三角支撑结构。

### 第一、实干派人才——执行层基石

| 维度 | 描述 |
|------|------|
| **核心特质** | 执行力极强、遇事先想「怎么做成」、合理试错、逆向复盘成长 |
| **典型行为** | 落地基线检测、推动口令整改闭环、执行应急响应流程、输出巡检报告 |
| **团队定位** | **落地执行主力**，将安全策略转化为可度量的工程产出 |
| **对应安全模块** | 应急响应执行、基线检测自动化、终端/网络巡检、口令整改推进 |
| **识别关键词** | 实干、执行力、激情、试错、复盘 |

> **管理启示**：实干派是团队的「肌肉」，需配合清晰的 SOP 与度量指标，避免陷入「盲目执行」的低效陷阱。

---

### 第二、专注派人才——质量守门人

| 维度 | 描述 |
|------|------|
| **核心特质** | 细节敏感、全覆盖思维、缜密心思、聚焦「可行性、落地性、完美度」 |
| **典型行为** | 代码审计深度挖掘、业务逻辑漏洞枚举、上线前检查清单打磨、基线规则微调 |
| **团队定位** | **质量基线守护者**，补齐实干派在细节上的盲区，规避低级失误 |
| **对应安全模块** | 业务应用安全（代码审计/上线前检查）、漏洞复现验证、基线规则维护 |
| **识别关键词** | 专注、缜密、处女座、细节、全覆盖 |

> **管理启示**：专注派往往不善表达，需建立「静默贡献可视化」机制（如缺陷密度、规则覆盖率），给予专业晋升通道。

---

### 第三、颠覆创新型人才——破局先锋

| 维度 | 描述 |
|------|------|
| **核心特质** | 一线实战、逆向思维、不按常理出牌、站在攻击者/友商视角重构防御体系 |
| **典型行为** | 引入威胁建模、设计主动防御/蜜签体系、攻防演练红队视角反哺蓝建、探索 SDL 新落地模式 |
| **团队定位** | **范式破局者**，打破「合规驱动」惯性，推动安全能力从「被动响应」转向「主动构建」 |
| **对应安全模块** | 威胁建模、红蓝对抗、安全运营平台设计、新技术预研（如蜜签、流量溯源） |
| **识别关键词** | 颠覆、创新、逆向思维、一线需求、友商视角 |

> **管理启示**：需为其设立「试错预算」与「创新保护期」，容忍阶段性 ROI 不可量化，防止被 KPI 扼杀。

---

### 第四、梦想模式人才——文化发酵剂

| 维度 | 描述 |
|------|------|
| **核心特质** | 乐观、激情、愿景驱动、持续输出正能量、虽想法未必全落地但能点燃团队 |
| **典型行为** | 组织内部分享会/技术沙龙、推动安全文化建设（如内部漏洞披露激励）、连接外部社区资源 |
| **团队定位** | **文化与愿景传播者**，维系团队心理契约，吸引外部人才、对内凝聚共识 |
| **对应安全模块** | 安全文化建设、内部漏洞披露机制推动、社区品牌运营、跨部门信任建立 |
| **识别关键词** | 梦想、乐观、激情、正能量、文化 |

> **管理启示**：梦想派是团队的「灵魂」，虽不直接产出硬指标，但决定团队能否跨越「存续期」走向「生长期」。

---

### 第五、自我驱动型人才——梯队核心与未来合伙人

| 维度 | 描述 |
|------|------|
| **核心特质** | 自驱力强、管理能力、稳重、激情与活力并存、愿为结果「无情」推进 |
| **典型行为** | 主动承接模糊地带任务、跨部门推进安全项目前置、培养新人、构建团队知识库/方法论 |
| **团队定位** | **团队 Leader / 未来合伙人**，连接战略与执行，输出可复制的管理范式 |
| **对应安全模块** | 团队建设、向上管理/价值量化、人才梯队规划、安全预算争取、SDL 落地统筹 |
| **识别关键词** | 自我驱动、管理、稳重、激情、合伙人潜质 |

> **管理启示**：自我驱动型人才稀缺且高流动性，需通过**股权/期权、决策授权、职业天花板打通**三维留人。

## 人才画像与业务/技术框架的映射矩阵

| 人才画像 | 业务分级支撑 | 五大基础安全落地 | 团队演进阶段适配度 |
|----------|--------------|-------------------|----------------------|
| **实干派** | 重点/特殊项目执行落地 | 应急响应、基线巡检、终端/网络/口令整改 | **初期→中期** 核心主力 |
| **专注派** | 重点项目深度审计/巡检 | 业务应用安全、漏洞验证、基线规则 | **全阶段** 质量基线 |
| **颠覆创新型** | 特殊项目/新业务安全探索 | 威胁建模、红蓝对抗、新技术预研 | **中期→成熟期** 破局关键 |
| **梦想模式** | 跨部门信任/文化渗透 | 安全文化、内部披露机制、品牌建设 | **全阶段** 文化粘合剂 |
| **自我驱动型** | 战略级资源统筹/向上管理 | SDL 统筹、预算争取、梯队培养 | **成熟期** 核心领导层 |

> **配置建议**：
> - **初创期（0-1）**：实干派 60% + 专注派 20% + 自我驱动型 1人（Leader）
> - **成长期（1-N）**：实干派 40% + 专注派 20% + 颠覆创新型 20% + 梦想模式 10% + 自我驱动型 10%（分层 Leader）
> - **成熟期（N-N+1）**：各类型均衡配置，建立人才画像标签化档案，支持内部流转与复合型培养
