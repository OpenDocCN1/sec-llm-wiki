## 概述

蔓灵花（APT-C-08）是一个活跃的高级持续性威胁（APT）组织，长期针对南亚地区的政府、军事、外交等敏感目标开展网络间谍活动。2019年12月，360威胁情报中心发布技术报告，系统性揭露了该组织针对**移动平台（Android）**的攻击活动，披露了其恶意样本技术细节、命令与控制（C2）基础设施部署及完整攻击链条。

> **来源引用**：360威胁情报中心博客《蔓灵花（APT-C-08）移动平台攻击活动揭露》  
> **原文链接**：<http://blogs.360.cn/post/analysis_of_APT_C_08.html>  
> **首披露日期**：2019-12-20（见 [[daily-security-digest-20191220]] 每日安全看点汇总）

## 攻击活动背景

### 组织画像
- **代号**：蔓灵花 / APT-C-08
- **活跃时间**：至少自2016年起持续活跃
- **攻击目标**：南亚地区政府机关、军事单位、外交部门、科研机构等高价值目标
- **攻击平台**：Windows、Android、iOS（早期以Windows为主，近年移动端攻击比例显著上升）
- **归属特征**：疑似受国家支持，攻击意图为长期情报窃取与持久化潜伏

### 移动端攻击转型动因
- 目标人员办公移动化程度提升，敏感数据向手机端迁移
- 移动端安全防护相对薄弱，EDR/杀毒软件覆盖率低
- 社工诱饵在移动社交场景（WhatsApp、Telegram等）传播更隐蔽

## 恶意样本技术分析

### 样本基本信息
| 属性 | 详情 |
|------|------|
| **包名** | 伪装为系统服务或常见应用（如 `com.android.system.service`、`com.google.play.services` 等变体） |
| **签名证书** | 自签名，部分样本窃取合法开发者证书伪造签名 |
| **最低SDK** | 通常设为 API 16 (Android 4.1) 以覆盖广泛设备 |
| **目标SDK** | 锁定较低版本（如 API 22/23）规避新版权限管控 |
| **混淆手段** | 字符串加密、类名/方法名混淆、反射调用、动态加载DEX、Native层关键逻辑下沉 |

### 核心功能模块

#### 初始化与持久化
- **设备指纹采集**：IMEI、IMSI、Android ID、序列号、MAC地址、基站信息、已安装应用列表、Root状态
- **持久化手段**：
  - `RECEIVE_BOOT_COMPLETED` 广播自启动
  - `QUICKBOOT_POWERON` / `BOOT_COMPLETED` 双重保障
  - 利用 `JobScheduler` / `AlarmManager` 定时唤醒
  - 部分样本滥用辅助功能服务实现“保活”
- **隐藏图标**：安装后通过 `PackageManager.setComponentEnabledSetting` 隐藏启动器图标，伪装为系统后台服务

#### 权限获取与提权
- **运行时权限动态申请**：READ_CONTACTS、READ_SMS、RECORD_AUDIO、CAMERA、ACCESS_FINE_LOCATION、READ_CALL_LOG、READ_EXTERNAL_STORAGE 等
- **辅助功能滥用**：诱导用户开启辅助功能，实现自动点击授权弹窗、读取通知栏内容、键盘记录
- **Root利用**：集成已知提权漏洞利用代码（如 DirtyCow、CVE-2019-2215 等），尝试获取系统级权限，部署system分区后门

#### 数据窃取能力
| 数据类型 | 采集方式 | 备注 |
|----------|----------|------|
| 通讯录 | ContentProvider 查询 | 含姓名、电话、邮箱、组织架构 |
| 短信/彩信 | ContentObserver 监听 + 数据库查询 | 含验证码、OTP、双因子认证短信 |
| 通话记录 | CallLog ContentProvider | 呼入/呼出/未接、时长、联系人匹配 |
| 定位信息 | GPS / 网络定位 / 基站定位 | 实时上报 / 定时上报 / 指令触发 |
| 音频录制 | MediaRecorder 后台录制 | 环境监听、通话录音（需Root或辅助功能） |
| 照片/视频 | MediaStore 遍历 + 拍照上传 | 含截屏、相机拍摄 |
| 文件列表 | 遍历外部存储 / 特定目录 | 窃取文档、下载文件、聊天记录数据库 |
| 应用数据 | 读取特定应用沙箱（需Root） | 重点针对 WhatsApp、Telegram、Signal 等加密通讯软件数据库 |
| 键盘记录 | 辅助功能服务拦截 AccessibilityEvent | 捕获输入法文本、密码框内容（非密码模式） |
| 剪贴板 | ClipboardManager 监听 | 窃取复制的敏感文本、链接 |

#### C2 通信协议
- **传输层**：HTTP/HTTPS（主流）、TCP原始Socket（备用）、WebSocket（新版本）
- **加密方式**：
  - 自定义对称加密（AES/RC4/XOR变体），密钥硬编码或协商生成
  - 部分流量走合法云存储API（Google Drive、Dropbox、OneDrive）隧道，利用OAuth Token认证
  - 域前置技术，将恶意流量伪装为访问高信誉CDN域名
- **通信频率**：心跳间隔 15-60 分钟可配，数据上报采用分块、压缩、断点续传
- **指令集**：
  - `CMD_UPLOAD_CONTACTS` / `CMD_UPLOAD_SMS` / `CMD_UPLOAD_CALLLOG` 等数据上传指令
  - `CMD_RECORD_AUDIO` / `CMD_TAKE_PHOTO` / `CMD_GET_LOCATION` 即时采集指令
  - `CMD_EXEC_SHELL` / `CMD_DOWNLOAD_DEX` / `CMD_UPDATE_CONFIG` 远程控制指令
  - `CMD_UNINSTALL` / `CMD_FACTORY_RESET` 自毁指令

#### 逃避分析与对抗
- **反调试/反模拟器**：检测 `ro.product.model`、`ro.hardware`、`qemu` 管道、`/sys/class/net/` 虚拟网卡特征、Sensor数量异常
- **反虚拟机/沙箱**：检测常见沙箱进程、文件路径、MAC地址前缀、电池状态（常插电）、运行时长
- **代码加密/动态加载**：核心恶意逻辑加密存放在 assets 或原生库中，运行时解密加载，静态分析难以提取完整DEX
- **Native层保护**：关键加解密、通信协议、Root利用下沉至 `.so`，配合 OLLVM 混淆、反IDA技巧
- **杀软/安全应用检测**：遍历已安装包名匹配已知安全厂商列表，检测到则延迟启动、功能降级或卸载自我

## C2 基础设施画像

### 域名与解析特征
- **注册信息**：使用隐私保护服务，注册商集中在少数几家，注册邮箱为一次性/免费邮箱
- **域名命名模式**：
  - 伪装合法服务：`google-play-services.xyz`、`android-system-update.com`、`security-patch.in` 等
  - 算法生成域名 (DGA) 作为备用通道
- **解析行为**：
  - 短TTL（60-300秒），频繁变更解析IP实现快速流量切换
  - 使用 Cloudflare 等 CDN 隐藏真实服务器IP
  - 部分域名仅解析到内网IP（配合受害端VPN/代理访问），外网直接解析为 NXDOMAIN

### 服务器端架构
- **分层部署**：
  - **第一层（前端代理/重定向）**：Nginx/Apache 反向代理，负责流量分发、TLS终结、WAF基础过滤
  - **第二层（C2控制面板）**：定制化Web管理后台（PHP/Python/Go编写），提供受害者列表、指令下发、日志审计、样本生成器
  - **第三层（数据存储/处理）**：MySQL/PostgreSQL 存储元数据，对象存储（MinIO/S3兼容）存储窃取文件，ELK栈做日志分析
- **地理分布**：服务器托管于多个国家/地区（东南亚、中东、东欧、美国云厂商），通过跳板机/VPN串联管理
- **运维痕迹**：
  - 管理面板路径固定（如 `/admin/`、`/panel/`、`/c2/`），弱口令或默认凭证
  - 使用开源C2框架二次开发（如 AhMyth、SpyNote、AndroRat、DroidJack 变种）或自研框架
  - 服务器时间时区多为 UTC+5:30 / UTC+8，疑似攻击者活跃时区

### 基础设施关联指标
| 指标类型 | 示例值 | 用途 |
|----------|--------|------|
| **IP段** | 45.77.x.x, 103.144.x.x, 185.222.x.x | 服务器托管网段 |
| **域名** | `system-update-service.com`, `play-store-security.net` | C2域名/备用域名 |
| **SSL证书** | 自签名 / Let's Encrypt / 窃取合法证书 | HTTPS通信指纹 |
| **Whois邮箱** | `admin@privacyshield.xyz`, `register@anonmail.org` | 基础设施聚类 |
| **NS服务器** | `ns1.cloudflare.com`, `ns2.cloudflare.com` | CDN隐藏真实IP |
| **样本硬编码配置** | `http://103.144.x.x:8080/api`, `wss://c2.example.com/ws` | 直接关联样本与C2 |

## 攻击链条复盘

### 侦察与武器化
- **目标画像构建**：通过开源情报 (OSINT) 搜集目标机构人员名单、职务、社交账号、常用设备型号
- **诱饵制作**：
  - 伪装成政府公文、会议通知、招聘简历、新闻热点、色情诱饵等主题的 APK
  - 合法应用重打包：下载正版应用（如政府办公APP、通讯软件）、注入恶意代码、重新签名
  - 利用“一键打包”工具生成定制化样本，自动配置C2地址、功能模块、图标/包名伪装
- **漏洞利用集成**：针对目标设备Android版本，集成对应版本的提权/沙箱逃逸Exploit

### 投递与诱导安装
- **投递渠道**：
  - 定向鱼叉钓鱼：WhatsApp/Telegram/Email 发送下载链接，话术针对性强（“请查收会议纪要APK”、“安装最新安全补丁”）
  - 水坑攻击：椒入目标常访问网站，伪装“浏览器更新”、“插件安装”提示
  - 第三方应用市场投毒：上传至非官方应用商店、论坛、云盘分享链接
  - 物理接触/供应链：极少数案例涉及预装恶意固件或通过MDM推送
- **社会工程学话术**：利用权威冒充、紧迫感、好奇心、恐惧感绕过用户警惕，诱导开启“未知来源应用安装”权限并完成安装

### 利用与植入
- **安装执行**：用户点击安装 -> 授予运行时权限 -> 诱导开启辅助功能/设备管理器 -> 图标隐藏 -> 后台服务启动
- **环境检测**：反模拟器/沙箱/Root检测 -> 若通过则激活完整功能，否则进入休眠/仅上报基础指纹
- **持久化落地**：注册自启动广播、定时任务、辅助功能服务 -> 尝试Root提权写入system分区 -> 建立多通道C2连接

### 指挥控制与横向移动
- **心跳上线**：样本周期性连接C2上报设备指纹、网络环境、安全软件状态
- **指令下发与执行**：C2根据目标价值下发采集指令、部署插件DEX、更新配置、推送新Exploit
- **数据窃取与外传**：分类打包压缩加密 -> 分块上传 -> 断点续传 -> 清理本地临时文件
- **横向拓展（移动端特有）**：
  - 窃取通讯录/短信 -> 识别高价值联系人 -> 伪装受害者发送钓鱼链接给联系人（短信/IM传播）
  - 窃取蓝牙/WiFi密钥 -> 尝试攻击同一局域网/物理邻近设备
  - 利用受害者账号凭证登录云同步服务 -> 下载更多历史数据

### 痕迹清理与持久化
- **日志清理**：删除应用自身生成的日志、数据库临时表、缓存文件
- **反取证**：加密存储配置与窃取数据、使用无文件技术（纯内存运行DEX）、定期轮换C2域名/IP
- **长期潜伏**：低频心跳、功能模块化按需加载、伪装系统进程名、利用厂商预装应用漏洞提升存活率

## 检测与防御建议

### 网络层检测
- **流量特征匹配**：
  - 固定间隔心跳、非标准端口HTTPS、异常User-Agent（如 `Dalvik/2.1.0 (Linux; U; Android 9; XXX Build/XXX)` 但访问非Google域名）
  - 证书指纹匹配：已知C2服务器自签名证书/Let's Encrypt证书指纹库
  - 域名信誉：新注册域名、算法生成域名(DGA)、伪装知名品牌域名
- **威胁情报集成**：订阅APT-C-08相关IOC（IP、域名、URL、证书哈希）实时封锁

### 终端层检测 (EDR/移动威胁防御 MTD)
- **静态特征**：
  - 样本哈希库（MD5/SHA256）、包名/签名证书黑名单、敏感权限组合画像（READ_SMS+RECORD_AUDIO+ACCESS_FINE_LOCATION+DEVICE_ADMIN+ACCESSIBILITY_SERVICE）
  - 代码特征：反射调用 `startActivity`/`sendBroadcast`、字符串解密函数、已知混淆器特征 (ProGuard/DexGuard/OLLVM)、Native库导出函数名模式
- **动态行为**：
  - 安装后即隐藏图标、请求辅助功能/设备管理器权限、注册高频广播接收器
  - 后台频繁读取联系人/短信/通话记录/定位、启动录音/拍照、建立外网长连接
  - 进程名伪装系统进程（`system_server`、`android.process.media` 等）、UID异常（非系统UID但进程名伪装系统）
- **启发式/机器学习**：基于API调用序列、权限使用模式、网络流量统计特征的异常检测模型

### 管理与运营建议
1. **移动设备管理 (MDM/EMM/UEM)**：
   - 强制策略：禁止安装非官方市场应用、禁止“未知来源安装”、强制设备加密、远程擦除能力
   - 应用白名单/黑名单、合规性检查（Root检测、调试模式检测、安全补丁版本基线）
2. **人员安全意识**：
   - 定期开展移动端钓鱼演练（模拟APT-C-08典型话术）
   - 宣讲“勿点不明链接、勿装不明APK、勿授不明权限、勿连不明WiFi”
3. **威胁狩猎**：
   - 定期导出MDM/MTD日志，结合威胁情报回溯分析
   - 重点排查：新增设备管理器/辅助功能应用、异常流量连接、敏感数据批量读取事件
4. **应急响应预案**：
   - 发现疑似感染设备即时隔离（网络隔离/企业擦除）、取证保留（镜像存储/内存转储/日志导出）、样本溯源分析、横向排查关联设备
