## 案例背景：一起真实的域名劫持事件

### 事件复盘

某公司网站运维人员（文中化名"小王"）已对 Web 程序及服务器完成加固，但网站首页仍被篡改为"黑页"。排查后发现：**并非 Web 层漏洞，而是域名解析记录被恶意篡改**。

攻击链路如下：

1. **信息收集**：攻击者通过 WHOIS 查询获取目标域名的**注册商信息**与**管理员邮箱**
2. **伪造身份**：攻击者注册一个与管理员邮箱高度相似的邮箱账号（如 `admin@company.com` → `admin@company.cn`）
3. **社会工程学欺骗客服**：攻击者向域名注册商提交工单，冒充域名持有者，通过话术诱导客服人员修改解析 IP
4. **客服验证缺失**：注册商客服未执行严格身份核验，直接受理变更请求，导致域名解析劫持

> **核心教训**：无论 Web 应用与服务器加固多么完善，若域名管理权限失守，业务仍面临"被黑"风险。域名注册商的运营安全能力直接构成供应链攻击面。

### 涉事注册商实录片段

文章记录了攻击者与某国内知名域名商（文中称为"美橙"）客服的对话截图，显示客服在未核实身份凭证、未对比邮箱真实性的情况下，仅凭工单描述即修改了解析记录。事后注册商承认失误，赔偿两年续费费用。

> **交叉引用**：此类针对注册商客服的社会工程学攻击手法，详见 [[social-engineering-attack-techniques]] 中"域名劫持"章节的实战复盘与话术分析。

## 五大核心防御措施（226安全团队建议）

针对上述攻击路径，226安全团队给出的五步防御体系，覆盖**供应链选择、凭证强度、邮箱隔离、锁定机制、信息隐藏**五个维度：

### 注册商选择：优先选择具备专属客服与严格验证流程的服务商

| 推荐策略 | 说明 |
|----------|------|
| **首选：新网** | 提供针对性的单独客服专员，身份核验流程相对规范，可降低客服被社工欺骗的概率 |
| **次选：GoDaddy 等国际大厂** | 联系流程繁琐（需工单、电话、邮件多重验证)，反而增加了攻击者冒充身份的成本 |
| **避坑指南** | 避免选择"价格极低、客服响应极快、验证流程随意"的中小注册商；此类商家常为抢占市场弱化安全审核 |

> **实操建议**：注册前以"咨询修改解析流程"为由测试客服验证强度——若仅需邮箱/工单即可改记录，直接排除。

### 账号强度：注册商后台账号使用高强度唯一密码

- **组成要求**：特殊字符 + 大小写字母 + 数字，长度 ≥ 16 位
- **唯一性**：**严禁**在其他平台复用该密码
- **防社工库撞库**：攻击者常利用泄露的"社工库"数据撞击注册商后台，唯一高强度密码可有效阻断

> **关联知识**：凭证复用风险与撞库攻击原理，可参考 [[xd-security-pentest-basic-stage-notes]] 中"信息收集与凭证利用"模块。

### 邮箱保护：域名管理邮箱独立隔离、强密码、启用 2FA

- **专用邮箱**：域名注册、WHOIS 记录、注册商通知均使用**专属邮箱**，不与日常业务、个人社交账号混用
- **强密码 + 2FA**：邮箱账号同步执行高强度密码策略，**必须开启双因子认证（TOTP/U2F）**
- **防钓鱼**：警惕伪装成注册商的钓鱼邮件，验证发件域名、链接指向

> **攻击视角**：文章中攻击者正是利用"相似邮箱"欺骗客服。若管理员邮箱开启 2FA 且不泄露真实地址（配合第 5 条 WHOIS 隐私），攻击成本将显著上升。

### 域名锁定：开启"域名绑定/锁定/禁止转移"功能

| 锁定类型 | 作用 | 操作位置 |
|----------|------|----------|
| **注册商锁** | 禁止未经授权的域名转移、信息修改、解析变更 | 注册商后台"域名安全/锁定设置" |
| **注册局锁** | 更高级别锁定，需注册局人工解锁，防内部操作失误 | 向注册商申请开启（通常需实名认证文件） |
| **解析锁定** | 禁止修改 DNS 记录（A、CNAME、MX 等） | 部分注册商提供独立"解析锁"开关 |

> **关键点**：文章案例中若开启"解析锁定"或"注册商锁"，客服即便被社工也无法直接修改记录，需走解锁流程（通常涉及人工审核、短信/邮件二次确认），形成有效阻断。

### WHOIS 隐私保护：隐藏注册人、邮箱、电话等敏感字段

- **开启隐私保护服务**：大多数注册商提供免费或低价的 WHOIS Privacy/Proxy 服务，将真实信息替换为代理信息
- **GDPR 合规效果**：欧盟注册商默认隐藏自然人信息；国际顶级域通用
- **最小化暴露**：攻击者无法直接获取管理员邮箱、电话，无法进行"相似邮箱注册+社工客服"组合拳

> **实测对比**：开启隐私保护前，WHOIS 直接显示 `admin@company.com`；开启后显示 `privacy@proxy-registrar.com`。攻击者失去精准钓鱼目标。

## 配置清单速查表

| # | 措施 | 优先级 | 验证方法 | 备注 |
|---|------|--------|----------|------|
| 1 | 选择具备专属客服/严格验证的注册商 | P0 | 模拟工单测试客服验证流程 | 新网、GoDaddy、Namecheap、Cloudflare Registrar |
| 2 | 注册商后台设置 ≥16 位唯一强密码 | P0 | 密码管理器生成+存储 | 启用注册商提供的 2FA（TOTP/短信/邮件） |
| 3 | 管理邮箱独立、强密码、强制 2FA | P0 | 登录邮箱检查 2FA 状态 | 推荐 ProtonMail、Gmail、Outlook 企业版 |
| 4 | 开启注册商锁 + 解析锁 + 注册局锁 | P0 | 后台安全设置全勾选 | 变更解析前需解锁，增加攻击链路长度 |
| 5 | 开启 WHOIS 隐私保护/代理服务 | P1 | `whois domain.com` 验证输出 | 部分国家代码域需注册商手动开启 |

## 纵深防御视角：将域名纳入资产管理与监控体系

单靠上述五步仍属"静态配置"，建议结合以下动态能力构建纵深防御：

1. **资产测绘与变更监控**  
   使用 FOFA、Quake、ZoomEye 等空间引擎定期扫描自有域名解析记录，配合 `dnsdb`、`SecurityTrails` 历史解析 API，建立**解析变更告警**（IP 变更、NS 变更、MX 变更）。  
   > 交叉引用：[[vulnerability-mining-recon-aiqicha-fofa]] 中"资产测绘语法构造"章节提供域名监控 FOFA 语法示例。

2. **证书透明度日志监控**  
   监控 crt.sh、CertSpotter 等 CT 日志，发现针对自有域名签发的异常证书（可能预示子域名劫持或中间人准备）。

3. **供应链风险评估**  
   将核心域名注册商纳入供应链安全评估清单，关注其：  
   - 是否发生过类似客服被社工事件  
   - 是否支持注册局锁、解析锁、API 权限最小化  
   - 是否具备 ISO 27001、SOC 2 等合规认证

4. **应急预案演练**  
   制定《域名劫持应急响应手册》，包含：  
   - 注册商紧急联系渠道（电话、专属客服、合规邮箱）  
   - 域名锁定/解锁操作 SOP  
   - 解析记录回滚验证步骤  
   - 法务取证与报警流程（域名属于无形资产，劫持可按《刑法》第 285 条、第 287 条处理）

## 典型误区与避坑指南

| 误区 | 现实风险 | 正确做法 |
|------|----------|----------|
| "大厂注册商绝对安全" | 文章案例即发生在国内头部注册商；大厂客服量大、外包多、流程僵化反而易被社工 | 必须开启锁定+隐私保护，不依赖单一厂商信誉 |
| "密码复杂就行，邮箱不用管" | 邮箱是找回密码、接收验证码、注册商联系的核心通道，邮箱失守 = 域名失守 | 邮箱独立、强密码、2FA 三件套缺一不可 |
| "WHOIS 隐私保护没必要，反正实名了" | 实名信息在注册商后台，WHOIS 公开仅暴露给攻击者做侦察用 | 开启隐私保护不影响实名合规，仅隐藏公开查询字段 |
| "域名锁了就麻烦，改解析还得解锁" | 这就是锁的意义——**增加攻击者操作链路长度**，迫使其面对人工审核、二次验证 | 建立内部变更工单流程：申请→审批→解锁→变更→加锁→记录，常态化运行 |
