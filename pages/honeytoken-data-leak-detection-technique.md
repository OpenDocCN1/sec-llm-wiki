## 核心概念

**蜜签 / 金丝雀令牌** 是一种主动防御技术：在敏感数据集中植入唯一、可追踪的假数据（如从未使用过的手机号、邮箱、身份证号等）。当这些假数据被触发（收到短信、电话、邮件、登录尝试）时，即可精准定位数据泄漏的来源路径与责任主体。

> 本技术源自微信公众号「301在路上」实战分享，定位为**辅助性、低成本、高威慑**的旁路检测手段，**不替代** DLP、数据分类分级、权限最小化等核心防御体系。

## 适用场景与前提条件

### 典型场景
- 用户手机号/邮箱等高频联系字段泄漏后被下游黑产用于推销、诈骗、撞库
- 多部门、多供应商共享同一数据源，难以通过日志审计单一定责
- 预算有限、无法采购商业 DLP 或部署复杂数据水印系统的中小企业

### 实施前提
| 维度 | 要求 |
|------|------|
| **业务熟悉度** | 对组织架构、数据流转流程、各部门提取字段差异「烂熟于心」 |
| **权限条件** | 拥有生产库/数仓写入权限，或至少具备数据提取审批节点的干预能力 |
| **协作机制** | 审计/合规部门全程监控植入过程，确保「公平公正」并留存证据链 |
| **号码资源** | 批量获取**从未注册、未绑定任何业务**的干净手机号（建议虚拟运营商号段或专用测试号池） |

## 实施流程

### 数据流转拓扑梳理
- 绘制「数据生产 → 提取审批 → 部门消费 → 供应商外发」全链路图
- 标注每个节点的数据字段子集、提取频次、导出格式（CSV/Excel/API/直连）

### 蜜签设计与生成
- **唯一性**：每个部门/供应商/批次分配**互不重叠**的号码集合（建议 5~20 条/批次，避免统计学推断）
- **真实性**：符合号段规则、通过运营商归属地校验、无注册记录、无通话记录
- **元数据绑定**：建立映射表 `token_id → {department, batch_id, extract_time, approver, purpose}`

### 植入注入
- 在审批通过的数据导出脚本/ETL 任务中，**动态拼接** 对应部门的蜜签记录
- 确保蜜签记录在字段分布、格式、脱敏规则上与真实数据**完全一致**
- 审计日志记录：`INSERT honeytoken INTO extract_set WHERE dept=X AND batch=Y`

### 监控与告警
| 监控手段 | 实现方式 | 响应动作 |
|----------|----------|----------|
| **语音/短信** | 绑定云通讯平台（如腾讯云/阿里云语音回调、短信上行）或物理 SIM 卡转发至专用座席 | 实时告警 → 记录来电号码、通话时长、关键词 → 触发溯源流程 |
| **邮箱/账号** | 部署 Canarytokens / Thinkst Canary / 自建蜜罐邮箱服务 | 捕获登录 IP、User-Agent、地理位置、触发时间 |
| **文件/文档** | 嵌入 Web Beacon、宏、外链图片、元数据水印 | 追踪打开路径、阅读时长、后续传播链路 |

### 溯源判定与处置
1. **命中确认**：某蜜签号码收到推销/诈骗电话/短信
2. **映射反查**：通过 `token_id` 定位到具体部门、批次、审批人
3. **排除干扰**：核对该部门是否有合规外发记录、供应商是否授权使用
4. **取证固证**：通话录音、短信截图、邮件头、访问日志 → 司法存证/区块链存证
5. **整改闭环**：
   - 责任部门：补全最小权限、脱敏规范、导出水印、操作审计
   - 供应商链：追加合同条款、定期渗透测试、数据销毁证明
   - 管理层：通报典型案例、强化威慑、纳入 KPI 考核

## 优势与局限性对比

| 维度 | 蜜签/金丝雀令牌 | 传统 DLP/水印 | 日志审计/UEBA |
|------|-----------------|---------------|---------------|
| **部署成本** | 极低（号码+脚本） | 高（硬件/软件授权+运维） | 中（存储+分析平台） |
| **溯源精度** | **单条记录级** | 文件/批次级 | 操作/会话级 |
| **对抗绕过** | 难（攻击者无法区分真假） | 中（截屏/拍照/OCR 绕过） | 低（权限滥用难察觉） |
| **威慑效果** | **极强（实战打击感）** | 中（策略拦截提示） | 弱（事后追责） |
| **覆盖范围** | 仅植入字段/场景 | 全量敏感数据流 | 全量操作行为 |
| **合规风险** | 需内部授权、隐私合规 | 合规成熟度高 | 合规成熟度高 |

> ⚠️ **关键局限**：仅能发现**被椅入字段且被主动利用（联系/登录）**的泄漏；无法检测纯数据倒卖、离线分析、未触发蜜签的泄露。**必须配合分类分级、最小权限、操作审计**构成纵深防御。

## 进阶变体与扩展

### 多维度蜜签组合
| 类型 | 示例 | 适用数据域 | 触发方式 |
|------|------|------------|----------|
| **手机号** | 170/165/199 等虚拟段 | 用户画像、订单、CRM | 语音/短信/RCS/WhatsApp |
| **邮箱** | `deptA_batch3_honey@corp.canary` | 营销名单、工单系统 | 邮件到达/点击/回复 |
| **身份证/银行卡** | 校验码合法但未发放号段 | 实名认证、风控模型 | 实名接口调用/征信查询 |
| **设备指纹** | 伪造的 `device_id`/`IDFA`/`OAID` | 埋点日志、广告归因 | 归因回调/激活上报 |
| **文档水印** | 零宽字符、隐写元数据 | 合同、设计图、源码包 | 截屏/拍照/打印溯源 |

### 自动化平台化建设
- **蜜签全生命周期管理**：生成 → 分配 → 植入 → 监控 → 告警 → 溯源 → 失效/轮换
- **与 CMDB/CI/CD 联动**：发布新版本自动注入对应环境蜜签（测试/预发/生产隔离）
- **威胁情报融合**：命中号码关联 [[osint-social-engineering-scam-investigation-case-study|社工库]]、黑产号码库、[[data-breach-45billion-chinese-platforms-analysis|已知泄露库]] 研判意图

## 法务与合规红线

1. **内部授权书面化**：由法务/合规/业务三方签署《内部数据安全演练授权书》，明确范围、周期、知情人名单
2. **隐私保护**：蜜签号码**严禁**关联真实用户画像；监控收到的通话/短信内容涉及第三方隐私时需脱敏存储
3. **劳动法风险**：**不可**将命中结果直接作为员工处分唯一依据，需走完整调查取证、听证程序；建议定性为「流程缺陷」而非「人员恶意」
4. **供应商合同**：在 DPA（数据处理协议）中明确「接受蜜签溯源机制」「配合调查」「违约赔偿」条款
5. **刑法边界**：植入虚假数据进生产库可能触犯《刑法》第 286 条「破坏计算机信息系统罪」，**必须**在隔离的提取层/数仓层实施，且有书面授权

## 实战清单

- [ ] 完成数据流转拓扑图，识别高风险提取节点
- [ ] 申请/采购干净号码资源池（建议 ≥ 3 个运营商、≥ 5 个省份）
- [ ] 开发/配置自动化植入脚本（幂等、可审计、可回滚）
- [ ] 搭建监控告警中台（语音/短信/邮件/HTTP 回调统一入口）
- [ ] 制定《蜜签溯源应急响应预案》（分级响应、通报名单、取证工具包）
- [ ] 完成法务合规审签，纳入年度安全演练计划
- [ ] 实施首轮灰度演练（单部门、单批次），复盘优化
- [ ] 全量推广并建立常态化轮换机制（建议季度轮换、重大活动前专项）
