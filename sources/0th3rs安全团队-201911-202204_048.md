# 概述

目前针对代码克隆检测的工具十分丰富，但存在如下问题：

*   工具不具有通用性，只能作用于某一特定的工作场景；
*   目前的检测工具无法应用于代码行数特别多的情况，即无法应用于大规模代码克隆检测中。

针对上述两种问题，本文提出了一种名为 SourcererCC 的检测工具。SourcererCC 是一种针对大规模代码克隆检测的软件，其优势在于可以精确检测 Type-1，Type-2 和 Type-3 三种类型的克隆代码；无关编程语言，可以应用于 C/C++，Java，C#等多种语言中；操作简单，无需分布式运行，只需要使用一个工作站，就可以检测上亿行代码。

# 实现

SourcererCC 主要思想就是优化代码块的比较过程。而最简单的比较思路就是对代码块中的 token 一个一个进行遍历比较，如果两个代码块中相同的 token 数量超过了某一阈值，就可以将其视为一组克隆对，但这样做时间复杂度就十分高。

SoucererCC 旨在优化这一简单而耗时的比较过程，采用了倒排索引及两种启发式过滤算法，将时间复杂度从  降低到了 。

*   项目，由若干代码库组成，即 ；

*   候选块，是指对于给定的代码块，与之比较的其他所有代码块；
*   克隆对，是指一对相似的代码段；

在建立索引阶段，仅仅是对部分 token 建立索引。而且使用的是倒排索引，即存放的内容不是【代码块:所包含的 token】，而是【token:出现过的代码块】。这种技术，常用于搜索引擎中，可以大大加快搜索速度。

克隆检测阶段先通过比对找到候选块，然后再去验证克隆对，最后得到结果。

下面将具体介绍两种启发式过滤方法及对应算法。

首先，对于第一种启发式过滤方法而言，其思想主要依托于集合的概念，当两个集合有较大的重叠部分时，它们的子集也应该有重叠的部分。

## 检测 Type-3 的原理

本文之所以可以对 Type-3 进行检测，是因为 token 的排序方法并不考虑 token 在代码块中的相对位置，即使丧失了部分语义信息，但保留了足够的语法信息。

# 实验

在实验部分，本文数据集选择了 IJaDataset 2.0，使用 BigCloneBench 和基于 Mutation and Injection 的框架来检测召回率，然后人工分析 BigCloneBench 的结果来计算精度。同时选择 CCFinderX，Deckard，iClones 和 NiCad 进行结果上的比较，其中 CCFinderX 只能检测 Type-1 和 Type-2，后三种工具均可检测 Type-1，Type-2 和 Type-3。

# 总结

本文提出了 SourcererCC 用于检测大规模代码克隆，文中的精华就在于提出的两种启发式方法，最终在召回率、精度和检测时间上都有很好的效果。但由于将所有的语句都 token 化了，丧失了语义上的信息，用于代码漏洞检测便不太合适。
