这是蚂蚁集团举办的一个比赛，看到 Pwn 题中有一个 QEMU 相关的题目，在 Pwn 题中属于比较简单的一题，也比较适合作为 QEMU 逃逸相关漏洞利用的上手入门题。本文主要来分析这道题的求解过程。

  

**\# QEMU 相关知识**

  

题目给了一个附件，包含一个 Docker 环境，内含 QEMU 可执行程序以及对应的启动脚本。QEMU 逃逸的题目一般是出题者通过实现一个具有漏洞的 PCI 设备，在启动脚本中加载该 PCI 设备。做题者通过发现该 PCI 设备对应实现中的漏洞以及对该漏洞的利用来实现虚拟机逃逸，从而获得位于主机的 Flag。  

  

从本题提供的启动脚本中，可以看到出题者实现了一个名为「d3dev」的设备：

  

![](../Images/b136e24a33f821acc6a5248cc47a40c6.png)

  

将题目附件中提供的 QEMU 可执行程序拖到 IDA Pro 中，使用设备名称搜索对应的实现函数，可以得到以下结果：

  

![](../Images/9534a4b90fd48086fbbd28bc4c60ea4b.png)

  

这里大致介绍一下这几个 QEMU 中的 QOM 编程模型和这几个函数的基本作用。在 QEMU 中，几乎所有的设备，包括 PCI 设备，都是由 QOM 编程模型来进行实现的，该模型中有几个关键的结构体：TypeInfo、TypeImpl、ObjectClass 和 Object。

  

TypeInfo 是 PCI 设备实现者用来定义 Type 的数据结构，实现者在添加一个 PCI 设备时，首先会指定一个初始化方法（上图的 pci\_d3dev\_register\_types）来初始 TypeInfo，在该初始化方法中，对 TypeInfo 数据设置 Object 结构体的大小，以及 class\_init和 instance\_init 方法。在 class\_init 方法中（上图的 d3dev\_class\_init），会对 ObjectClass 对象进行初始化，包括设置设备 ID 和厂商 ID 等，我们之后可以通过这里的 ID 从 lspci 中查找对应的设备文件。在 instance\_init 方法中（上图的 d3dev\_instance\_init），会对 Object 的结构体（通常是 xxxState，这个结构体会作为之后这些 I/O 操作的第一个参数）进行初始化。下图是 lspci 命令的结果：

  

![](../Images/454aa3cd7b8fa46de4bb451e505cf07c.png)

  

每一个 PCI 设备可以申请两类地址，分别是 Memory Space 和 I/O Space，对这两类地址空间的操作函数在 realize 函数（上图的 pci\_d3dev\_realize）完成，通常是类似 xxx\_mmio\_read / xxx\_pmio\_read 的函数。

  

因此，对于 PCI 设备漏洞的发现和利用，通常只需关注相应的 I/O 函数。  

  

**\# 漏洞**

  

首先，我们看一下 d3dev 设备对应的 Object 结构体（d3devState）：  

  

![](../Images/90e4b6a29c8e2474c117d96bd6ab4639.png)

  

结构体中存在一个 rand\_r 字段，该字段被赋值成了 QEMU 中的 rand\_r 函数的地址（可以在 d3dev\_instance\_init 中看到），然后在 rand\_r 字段上面存在 blocks 字段，应该是用来存储一大段内容的，因此我们可以思考是否能通过越界读取 blocks 字段的内存来泄漏 rand\_r 的地址，从而造成内存泄漏，得到 QEMU 的基地址。  

  

然后，我们查看一下 d3dev\_mmio\_read 函数：

  

![](../Images/f18d40d51777a96d0433ec20e313fab2.png)

  

可以看到函数通过传入的 addr 以及 seek 成员从 blocks 字段中读取一段内容，将该内容经过一系列的编码之后（上图的 do-while 循环）将内容返回。这里可以发现，对 blocks 字段的访问并没有检查边界，因此这里我们可以通过构造 seek 字段以及 addr 参数，来实现越界读。  

  

有了基本的越界读方案之后，我们考虑是否有相似的越界写的情况。因此，继续查看 d3dev\_mmio\_write 函数：

  

![](../Images/cf9a54fc47d2039b3fb128f6870857eb.png)

  

该函数与读取的函数逻辑类似，也可以构造出一个越界读。但是在写的过程中，会通过 mmio\_write\_part 来执行不同的操作，这里之后在利用阶段再进行分析。

  

因此，主要的利用逻辑就有了，通过 d3dev\_mmio\_read 泄漏 QEMU 的基地址，通过 d3dev\_mmio\_write 来修改 rand\_r 字段为 system 地址，从而可以执行任意代码。

  

**\# 利用**

  

在对漏洞进行利用之前，还有几个问题：

  

1.  blocks 字段和 rand\_r 字段的内存差是 0x818 个字节，而 realize 函数中指定 mmio 读写的内存范围为 0x800 大小，因此对 mmio 内存区域进行操作时最多不能超过 0x800 的大小范围，因此我们还需要对 seek 字段的值进行控制
    
2.  在对读写的内容进行编码解码的过程中，用到了 key 字段，这些字段的值是怎么来的，能否控制他们使得编码解码的过程变得简单
    
3.  在什么时候调用 rand\_r 函数
    

  

所以，我们需要继续对 d3dev\_pmio\_read 和 d3dev\_pmio\_write 函数进行查看。d3dev\_pmio\_read 函数是访问一些结构体内部的值，对于利用来说用处不大，我们主要关注 d3dev\_pmio\_write 函数：

  

![](../Images/bc00f6ea4763010c00cd2b275e07c6ee.png)  
可以看到，当 addr 为 8 的时候，d3dev\_pmio\_write 函数可以直接对 seek 字段进行写入，因此问题「1」解决。  
当 addr 为 4 的时候，可以将所有 key 字段赋值为 0，这样可以使得编码/解码的过程变得比较简单，因此问题「2」解决。  
此外，我们可以看到，当 addr 为 0x1C 的时候，rand\_r 字段以 r\_seed 的地址为参数被调用。  
接下来，我们需要分析 d3dev\_mmio\_write 的写入过程。在该函数中，如果当前 mmio\_write\_part 的值为 0，则可以将 4 个字节的 value 直接写入对应的偏移处。而如果 mmio\_write\_part 的值为 1，会从 blocks 字段的 addr 偏移处获得原始的值，并将其分成低 32-bit 和高 32-bit 的不同的值，然后进行一系列的编码之后，组合得到 64-bit 的值，写入到 addr 偏移处：  
  
![](../Images/488732c3c3522092761d9186db62d669.png)  
因此，我们需要在第一次写入时写入编码前的值，在第二次进行写入时就能向目标偏移写入 64-bit 的值，从而可以实现覆盖 rand\_r 字段的目的。下图是成功劫持 rand\_r 字段地址到 system 函数。  
![](../Images/20299c89ca18cb851cdafd3621ab2b1d.png)  
最后，我们只需要使得 r\_seed 字段的内存处的值是想要执行的命令，例如 "cat flag" 即可。通过观察 r\_seed 字段的位置，发现其正好位于 blocks 字段的上方，那么我们只需要对 blocks 的第一个 4 个字节写入 "flag"，然后将 r\_seed 的值赋值成 "cat " 即可。
