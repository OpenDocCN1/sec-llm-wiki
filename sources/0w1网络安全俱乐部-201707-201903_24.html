 Do you want the flag?

题目分析：

程序要求用户输入一串字符，猜测通过验证将会输出flag，否则输出You will never get the flag!

使用ida观察程序流程：

Main函数很简单，向s中读入用户输入，判断变量v5是否为g，如果不是则错误。

这里是题目的第一个考点：栈溢出

注意到变量s只有一个字节大小，但是put函数却可以向其中写入10个字节，明显存在越界的情况。

此时程序栈中的状态为：(这块看不明白的同学可以自行百度 函数调用栈)


…

s(bp-5)（局部变量）

v5(bp-1)（局部变量）

bp（栈帧基地址）

Ret address（返回地址）

Old bp（上一栈帧基地址）

envp(参数)

argv（参数）

argc（参数）


由于v5(bp-1)和s(bp-5)之间相差4个字节，因此只用输入5个字节第五个字节为字符“g”，就能是判断条件满足，输出flag

一秒出答案！！

 

对于没有看出来栈溢出的同学，你还有第二次机会，由于条件成立之后执行了func1函数，可以直接看看这个函数干了什么。

分别从各个地址取字符构成了一个字符串，其实只要耐心点到各个地址找出数据转换为char然后再回来换个名（快捷键n）其实就已经看得到答案了

首先看看func1做了什么：

简单分析可知这是一个凯撒加密程序：

首先判断字符是否在a-zA-Z范围内，是的话就进行+a2的移位操作（大家可以看看凯撒加密的实现然后和这段代码比对）

再分别分析check1，check2，check3三个函数：

Check1():

截图太长我就不贴了，打开就能看到其实是一个解方程的操作，解出了a1（a[0]）到a1+28(a[7])，但是要求输入有16位，通过check1()只解出了一半的flag

扒出里面的系数写python脚本求解：

Check2()：

稍微转化一下变成易于理解的代码：


int check2(int a1,int a2){

       int result;

       int v3;

      if(a1==a2)    return a1;

       if(a1<a2)     return check2(a2-a1,a1+1)

       if(a1>a2)     return check2(a1-a2,a2+1)

}


注意递归调用check2时传递的参数：


参数一：(((a1 - a2) >> 31) ^ (unsigned int)(a1 - a2)) - ((a1 - a2) >> 31)

1、(a1-a2)>>31表示将a1-a2的符号位算数右移32位，若a1<a2，成为32个1，否则为32个0

2、若a1>a2，此时a1-a2>>31为32个0（表示数字0）

此时参数一=(a1-a2)^00000000000000000000000000000000-0=a1-a2

3、若a1<a2，此时a1-a2>>31为32个1（数字-1的补码表示）

此时参数一=（a1-a2）^1111111111111111111111111111111111-（-1）

即a1-a2按位取反末位+1，也就是(a1-a2)求原码再取反符号位，得到a1-a2的相反数

参数一=a2-a1


参数二：v3

1、a1>a2时,v3=a2+1

2、a1<a2时,v3=a1+1


这段代码不断比较a1，a2两个数的大小，然后减小大数增大小数，最后只有等两个数相等时才会输出其中一个数，这个函数的返回值是一个恒不为零的整数，也就是返回值是用真的（只有一种情况会返回零：刚开始时两个参数都为0，但本题不满足条件）、

嗯对这个函数写出来就是为了扰乱你们的视线的

使用PEid中的Kanal工具发现了程序用到了base64和md5两种算法，先无视它拖进ida看看：

ida打开题目真的有点难看，而且找了半天也没找到main函数（这是我预料之外的问题，原题编写用了c++，标准库的使用使程序可读性差了不少，而且我还在里面加入了不少的花指令和混淆手法，在目标难度上又提高了不少，对得起它500分的价值）

因此使用第二种方案：OD动态分析

第一步先单步调试+不断下断点找到main函数开始的地方（对OD使用有问题的同学自行百度）

然后继续单步执行：

这两个函数调用C++标准库函数cout实现了提示字符串的输出：

这个函数就是程序获得我们输入的地方（调用了cin），输入1234567890，函数调用完之后的返回结果储存在寄存器eax，然后又将eax的值写到了栈中（ebp-0x94）

第一关：长度判断，调用strlen函数获得输入长度，然后判断长度是否大于0并小于30，我们的输入是满足这个要求的

继续单步执行看到了一条花指令

花指令的存在会影响到我们静态调试程序的可读性，

继续单步调试。

第二关：判断前7个字符是不是以0W1CTF{开头，不然会挂掉。我们老实调整我们的输入为：0W1CTF{1234567890} ，从头开始执行

第三关又挂掉了，0x1d=29,ebp-0x94存放的是我们input的位置，0x7d是右花括号}的ascii码，第三关判断input[29]是否为右花括号，调整输入：0W1CTF{1234567890123456789012}，成功绕过。

第四关进行4个判断，判断input[9]、input[15]、input[18]、input[22]是否都为下划线_(0x5f对应的字符)，再次调整输入0W1CTF{12_34567_89_012_345678}

完美！又过一关！离目标越来越近！

接着取了flag的第一部分input[7]和input[8],调用了一个函数，后面又出现了一串md5，猜测是进行md5加密并进行比对（事实上通过kanal(v2.9): CryptoSearcher工具是可以找出程序用了什么加密方法）

去查一下这个md5码发现md5(YQ) = dcfed125d6507dc8c473c49fd8ad891d

所以修改输入：0W1CTF{YQ_34567_89_012_345678}

第六关跳过很多常量赋值之后，来到了对flag第二部分的处理：

首先把5和flag的第二部分34567压入栈中，然后又调用了00e215f0这个函数，经过第五关的分析我们知道这个函数用于进行md5加密

经过无数次的f8+f7尝试，来到了关键逻辑：

所做的工作就是用34567生成的md5减去之前的md5和check数组比较：

check数组为（就是之前有一堆赋值的操作）

通过调用00e2156e对012这个字段进行了处理，

分析可知这个函数内对012进行了base64加密处理，并且将012的base64(MDEy)和MzR0进行比较

所以修改输入为0W1CTF{YQ_w4nts_89_34t_345678}

第七关PASS！！

 

第八关相对前两个就比较简单了，一直向下执行在经过一系列赋值操作后可到达关键代码

依次取出8和9两个字符跟之前赋值的数组a进行抑或运算，然后判断是不是输入的后几位，数组a的值为：

0xb,0x7c,0x0,0x5c,0x20,0x1,0x63,0x4d

注意最后进行比较的是最后8位字符，既包括下划线_(0x5f)与右花括号(0x7d)在内

因此已知0x5f和0x7d两个字符可以将8、9位置对应的字符逆推出来

input[16]=0x5f^0xb=0x54=’T’

input[17]=0x7d^0x4d=0x30=’0’

此时的输入为：0W1CTF{YQ_w4nts_T0_34t_345678}、

然后再通过抑或运算可以逆推出后八位的内容
