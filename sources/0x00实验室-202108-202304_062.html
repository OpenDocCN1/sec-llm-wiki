问题又来了

在内网的服务器中 我们是将它设置为frp的服务端 还是frp的客户端呢？

回到我们的目标上来
 我们是希望通过frp让这台机器成为我们的内网‘代理’ 从而让我们能够访问内网资源
 按照这个思路 是不是应该将内网机部署为‘代理服务器’ 让我们公网服务器的流量作为客户端先请求代理服务器再请求代理服务器才能访问到的资源呢？

像这样？

如果这样想就错了 因为这样是正向代理

正向代理 首先就需要客户端可以访问到代理服务器进而通过它来访问目标

然而在我们的实验环境中，我们本来就是因为访问不到这台内网的服务器所以才需要代理，使用正向代理的话岂不是南辕北辙？

所以frp也被称为内网穿透的反向代理工具

反向代理 我们是让内网的服务器来连接我们

因为如果目标出网，那么它是可以通过走网关走公网访问到我的公网服务器的，但是反过来就不行

这里也涉及到另一个知识点 正向连接bind与反向连接reverse

就比如 我和女神都在外面（可以互相访问） 那么我可以直接去找她【正向连接】
而如果我在外面 而女神在家里 她爸妈在家（我无法访问她）我不能直接进她家 但她可以出来找我【反向连接】

扯得有点远 回到问题上来说 既然想采取反向 那么自然要把内网服务器部署为客户端，而公网的服务器部署为服务端，并在客户端设置里让内网的服务器来主动连接公网的服务器

在frpc.ini上设置好

[common]
server_addr = 121.5.14.5 //公网服务器的IP
server_port = 7777   //想要连接的端口

[http]
type = tcp   //以什么形式
local_ip = 127.0.0.1 //本地IP
local_port = 80   //本地端口
remote_port = 6000  //指定开启哪个端口并转发到该端口

自然 公网服务器便作为FRP的服务端等待内网服务器的连接实现代理通道去访问原本访问不到的内网资源

思考

frp的原理？怎么实现的？

其实就是一个反向连接的代理
由于无法直接访问内网机器，所以需要将内网机器设为客户端，外网机器设为服务端，让内网的frpc来连接外网的frps，从而搭建代理通道，使得外网服务器能够通过这个通道来访问内网资源

这张图就能很好的解释frp工作的流程 只不过在实验中：

client和frps是部署在一起的 frpc和server也是部署在一起的

1）首先，frpc 启动之后，连接 frps，并且发送一个请求 login()，之后保持住这个长连接，如果断开了，就重试

2）frps 收到请求之后，会建立一个 listener 监听来自公网的请求

3）当 frps 接受到请求之后，会在本地看是否有可用的连接( frp 可以设置连接池)，如果没有，就下发一个 msg.StartWorkConn 并且 等待来自 frpc 的请求

4）frpc 收到之后，对 frps 发起请求，请求的最开始会指名这个连接是去向哪个 proxy 的frps 收到来自 frpc 的连接之后，就把新建立的连接与来自公网的连接进行流量互转

5）如果请求断开了，那么就把另一端的请求也断开

应该是：

我本地的xshell 与 公网的frps 以tcp代理建立了tcp通道
公网frps 与 私网frpc 建立了tcp通道
私网frpc 与 私网server 建立了tcp通道

1）frpc 向 frps 发起注册请求

2）frps收到请求 并返回注册确认

3）frps发起工作连接请求

4）frpc收到工作连接请求，返回新工作连接

5）frpc发起新的代理请求 

6）frps收到 返回新代理响应包 

7）frps开启工作连接
