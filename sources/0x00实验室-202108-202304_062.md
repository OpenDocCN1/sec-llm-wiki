#### 问题又来了

在内网的服务器中 我们是将它设置为frp的服务端 还是frp的客户端呢？

```


回到我们的目标上来
```

![](../Images/638dad74e6d893bf5fe17183283b93d9.png)

image-20211024164031256

像这样？

如果这样想就错了 因为这样是**正向代理**

```


正向代理 首先就需要客户端可以访问到代理服务器进而通过它来访问目标
```

所以frp也被称为**内网穿透的反向代理工具**

反向代理 我们是让内网的服务器来连接我们

```

因为如果目标出网，那么它是可以通过走网关走公网访问到我的公网服务器的，但是反过来就不行
```

这里也涉及到另一个知识点 正向连接bind与反向连接reverse

```


就比如 我和女神都在外面（可以互相访问） 那么我可以直接去找她【正向连接】
```

扯得有点远 回到问题上来说 既然想采取反向 那么自然要把内网服务器部署为客户端，而公网的服务器部署为服务端，并在客户端设置里让内网的服务器来主动连接公网的服务器

在frpc.ini上设置好

```


[common]type

 = tcp   //以什么形式
```

### 如果再往下剖析

应该是：

```


我本地的xshell 与 公网的frps 以tcp代理建立了tcp通道
```

![](../Images/692729fe55f6980dfa5ea172b5ed24ac.png)

image-20211024182608404

1）frpc 向 frps 发起注册请求

2）frps收到请求 并返回注册确认

3）frps发起工作连接请求

4）frpc收到工作连接请求，返回新工作连接

5）frpc发起新的代理请求 

6）frps收到 返回新代理响应包 

7）frps开启工作连接
