前言：

      在实际编写程序过程中，我们常常需要获取客户端IP地址，以此统计用户分布，用户习惯，让用户与程序的交互显得更加自然且真实。


      但是，许多开发者并未意识到一点，在获取客户端ip地址这一过程中，是存在安全风险，有可能导致安全问题的。


原理分析：


      这里我们以PHP程序为例。


      首先，我们先列举一下PHP中，获取客户端ip地址的几种方式：


      1.HTTP_X_FORWARDED_FOR


      简称XFF头，是用来识别通过HTTP代理或负载均衡方式连接到Web服务器的客户端最原始的IP地址的HTTP请求头字段。使用这种方式，可以在大型网络中，获取到最原始用户的真实ip/代理ip地址。


      2.HTTP_CLIENT_IP


      是代理服务器发送的HTTP头。


      3.REMOTE_ADDR


      默认来自于TCP连接，是客户端与服务器端进行握手时所使用的ip地址，若客户采用代理ip，则获取到的是代理ip地址。


      而在大多数程序中，获取ip的代码如下：


<?php
function GetIP(){
if(!empty($_SERVER["HTTP_CLIENT_IP"])){
  $cip = $_SERVER["HTTP_CLIENT_IP"];
}
elseif(!empty($_SERVER["HTTP_X_FORWARDED_FOR"])){
  $cip = $_SERVER["HTTP_X_FORWARDED_FOR"];
}
elseif(!empty($_SERVER["REMOTE_ADDR"])){
  $cip = $_SERVER["REMOTE_ADDR"];
}
else{
  $cip = "无法获取！";
}
return $cip;
}
echo GetIP();
?>


      乍眼一看，这段代码是没有问题的，然而我们需要明白一点：

HTTP_X_FORWARDED_FOR，

HTTP_CLIENT_IP       

      这两种客户端ip获取方式是可以进行伪造的。

      只要我们在提交请求时，拦截数据包，加上伪造ip地址即可：


      对于第一种情况，在HTTP头处加上：

      X-FORWARDED-FOR:伪造的ip地址


      对于第二种情况，在HTTP头处加上：

      CLIENT-IP:伪造的ip地址


      第三种客户端ip获取方式是获取TCP握手中的ip地址，虽然说挂了代理之后，获取到的是代理的ip地址，但是安全方面并不会出现太大的问题，因为它不管再怎么变，也是一串ip地址，然而前两种情况下，我们可以伪造成任意内容。


      嗯？前两种情况真的会导致安全问题吗？

      在以上两个例子之中，给出了由于前两种获取方式的缺陷所导致的储存性xss漏洞。难道这一缺陷只会导致xss漏洞吗？


      并不是，这一问题还可能导致sql注入，代码执行等等，伪造的内容到达哪里，危害就会涉及到哪里。
