# 程序员：记录一下用户ip地址怎么也能被黑？

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzIwMTQ2NzY4NA==&mid=2652520774&idx=2&sn=a823891e9db9de3514d7f8317d24e53d&chksm=8d03930dba741a1b79be155facebf0d9ffc9664358b1a0f0b867a7c16d8d84bea4a194685093&scene=126&sessionid=1681656737#rd](http://mp.weixin.qq.com/s?__biz=MzIwMTQ2NzY4NA==&mid=2652520774&idx=2&sn=a823891e9db9de3514d7f8317d24e53d&chksm=8d03930dba741a1b79be155facebf0d9ffc9664358b1a0f0b867a7c16d8d84bea4a194685093&scene=126&sessionid=1681656737#rd)

前言：

       在实际编写程序过程中，我们常常需要获取**客户端IP地址**，以此统计用户分布，用户习惯，让用户与程序的交互显得更加自然且真实。  

  

      但是，许多开发者并未意识到一点，在获取客户端ip地址这一过程中，是存在安全风险，有可能导致**安全问题**的。

  

原理分析：

  

      这里我们以**PHP**程序为例。

  

      首先，我们先列举一下PHP中，获取客户端ip地址的几种方式：

  

      1.HTTP\_X\_FORWARDED\_FOR

  

      简称XFF头，是用来识别通过**HTTP代理**或**负载均衡方式**连接到Web服务器的客户端最原始的IP地址的HTTP请求头字段。使用这种方式，可以在**大型网络**中，获取到**最原始用户**的真实ip/代理ip地址。

  

      2.HTTP\_CLIENT\_IP

  

      是**代理服务器**发送的HTTP头。

  

      3.REMOTE\_ADDR

  

      默认来自于**TCP连接**，是客户端与服务器端进行**握手**时所使用的ip地址，若客户采用代理ip，则获取到的是**代理ip地址**。

  

      而在大多数程序中，获取ip的代码如下：

  

> <?php  
> function GetIP(){  
> if(!empty($\_SERVER\["HTTP\_CLIENT\_IP"\])){  
>   $cip = $\_SERVER\["HTTP\_CLIENT\_IP"\];  
> }  
> elseif(!empty($\_SERVER\["HTTP\_X\_FORWARDED\_FOR"\])){  
>   $cip = $\_SERVER\["HTTP\_X\_FORWARDED\_FOR"\];  
> }  
> elseif(!empty($\_SERVER\["REMOTE\_ADDR"\])){  
>   $cip = $\_SERVER\["REMOTE\_ADDR"\];  
> }  
> else{  
>   $cip = "无法获取！";  
> }  
> return $cip;  
> }  
> echo GetIP();  
> ?>

  

      乍眼一看，这段代码是没有问题的，然而我们需要明白一点：

> HTTP\_X\_FORWARDED\_FOR，
> 
> HTTP\_CLIENT\_IP       

       这两种客户端ip获取方式是可以进行伪造的。

       只要我们在提交请求时，拦截数据包，加上伪造ip地址即可：

  

       对于第一种情况，在HTTP头处加上：

       X-FORWARDED-FOR:伪造的ip地址

  

      对于第二种情况，在HTTP头处加上：  

       CLIENT-IP:伪造的ip地址

  

      第三种客户端ip获取方式是获取TCP握手中的ip地址，虽然说挂了代理之后，获取到的是代理的ip地址，但是安全方面并不会出现太大的问题，因为它不管再怎么变，也是一串ip地址，然而前两种情况下，我们可以伪造成**任意内容**。

  

      嗯？前两种情况真的会导致安全问题吗？

      在以上两个例子之中，给出了由于前两种获取方式的缺陷所导致的储存性xss漏洞。难道这一缺陷只会导致xss漏洞吗？

  

      并不是，这一问题还可能导致sql注入，代码执行等等，伪造的内容到达哪里，危害就会涉及到哪里。

  

      当然了，并不是说第三种ip获取方式一定安全，前两种ip获取方式一定不安全。实际中还是有许多种情况的。
