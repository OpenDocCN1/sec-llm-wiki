背景


作为一个白帽子，在日常的渗透或者扫描中，经常会遇到一个恶心的东西--"waf"，最严格的"waf"一次恶意的请求就会ban ip，这时候就需要使用代理，很多人都会想着自己租vps或者手机飞行模式切换ip，但是作为一个老白嫖怪，肯定不想给钱，而quake可以查询互联网的socks协议，这时候就可以写个脚本来获取全网开放的socks代理。


- 优点 -

通过获取别人的socks代理有一个好处，可以防止溯源，就算是被防守人或者流量设备检测发现，发现的攻击ip也是别人的socks代理，如果中间再走一层代理，那肯定就更隐蔽了。

- 发现socks -

使用如下的搜索语法可以发现全网的socks协议

service:"socks"

通过quake搜索结果发现，在排除了蜜罐、CDN以及数据去重以后，全网使用socks协议的仍有36万+条数据，独立ip有24.6万+。

- 代码编写 -

笔者使用的pocsuite3框架编写的代码，核心代码如下：

def _verify(self):    result = {}    host = urlparse(self.url).hostname    port = urlparse(self.url).port    socks = ['socks4','socks5']    true_ip = self.get_true_ip()    for sock in socks:        proxy = '{sock}://{host}:{port}'.format(sock=sock,host=host,port=port)        proxies = {            'http': proxy,            'https': proxy        }        try:            res_proxy = req.get('http://httpbin.org/ip',proxies=proxies,timeout=5).json()            if res_proxy['origin'] != true_ip:                result['socks'] = proxy                result['proxy_ip'] = res_proxy['origin']                break        except Exception as e:            pass    return self.parse_output(result)def get_true_ip(self):    res_json = req.get('http://httpbin.org/ip').json()    return res_json['origin']

代码的大致思路就是，先获取当前的ip，然后通过quake发现的socks结果集进行爆破，分别爆破socks4和socks5，然后通过request的proxies代理去获取代理以后的ip，如果ip变化了则说明代理可用。


- 获取socks -

代码没问题了，但是全网有30万+的数据，总不能全部跑完吧，这肯定需要大量的时间，所以可以放vps上对全网的数据进行测试

python3 cli.py -r pocs/find_socks_proxy.py -f socks.txt --verify --threads 20

导出全网socks数据以后，使用pocsuite3进行扫描，这里建议线程不要使用太高，20左右效果最佳。放vps上跑一晚上，就可以发现自己有大量的代理可以使用了，渗透测试的时候再也不怕被ban ip了


- 后续思考 -

很多人觉得到了获取socks以后就已经结束了，但是我在获取到的代理中发现部分代理存在一个现象，那就是我们爆破出来的代理实际上只是别人的第一层代理。

这里以socks5://103.118.253.29:9100这个代理为例，从我的图中可以看出，使用的是103这个ip的代理，但是查询的ip是109的ip。






▲代理查询。


在使用quake查询ip 109.70.100.27的信息，发现这个ip是tor的代理节点，是不是很多读者到了这里就知道，这人是搭的多层代理，通过自己的vps代理socks，然后vps转到tor的流量进行隐藏（可能中间还有多层的转换）。







这次socks代理的旅程还没有结束，既然socks代理可以转发tor的流量，那么是不是也有黑客将自己肉鸡的流量通过某一台vps进行转发呢？那么攻防中常用的frp/nps这类代理工具，是不是也可能因为操作失误没有设置用户名密码的原因，导致被人"踩代理"呢？

- 关于NPS -

使用quake语法`title: "nps"`搜索全网的nps服务，通过数据统计分析发现在近一年的数据内中国的nps最多为62731，美国次之为8879，日本第三为2224。






互联网上出现过这么多的nps，这其中肯定有黑客利用nps进行攻击做内网代理转发，现在就利用quake来"踩代理"

首先通过quake搜索发现一台美国加州的nps主机





因为nps做代理基本都是临时开socks端口，这里使用nmap扫描该主机





通过nmap扫描发现该主机开放有10000、10002、10004、19008、10009等端口，使用socks检测爆破脚本测试，发现19009端口可以连接，并且该端口代理出去的ip为113.117.5.30





通过quake搜索查询113 ip开放的服务，发现该ip为中国广东省的地址。






- 总结 -

从quake上搜索nps来看，全球的nps数量不少，并且可能一台nps主机控制多台肉鸡，因此通过本文方法可以发现互联网上nps的socks代理然后通过ip来判断哪些地区被攻击控制最多，哪些地区的黑客比较活跃。所以无论是在日常的运维或者内网渗透时建议设置socks5协议的账号密码，这样可以极大的减少被“踩代理”。
