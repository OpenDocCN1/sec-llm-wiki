**0x01事件概要**

 

2021年6月8日，微软官方修复了一个存在于打印机服务Windows Print Spooler中的高危漏洞(CVE-2021-1675)。利用该漏洞，攻击者可以将普通用户权限提升至System权限。

 

然而在安全研究人员对其安全补丁验证的过程中，又发现了另一处比较严重的远程攻击漏洞（CVE-2021-34527，代号"PrintNightmare"）。利用此漏洞，攻击者可以直接在域环境中攻击域控服务器，拿下整个域控，或是在工作组环境中肆意漫游，影响所有Windows版本中的Windows Print Spooler，包括安装在个人计算机、企业网络、Windows服务器和域控制器上的版本。7月6-7日，微软连续发布out of band补丁来修复该漏洞，建议广大政企用户依据微软官方指导进行版本升级，同时360本地安全大脑可实时对该漏洞攻击行为进行检测并精准告警。

 

**360本地安全大脑对接了丰富的多源数据，包括Sysmon日志、Windows事件日志等，并对日志事件类型和字段做了范式化处理，生成关联分析规则，实现了对该漏洞攻击行为的检测。360本地安全大脑用户只需升级到最新的安全规则包，即可获得相应的检测能力。**

**0x02漏洞利用分析**

  

### **1.漏洞复现的前置条件：**

*   ### 普通域账号或目标机器本地账号。
    
*   通过SMB将恶意DLL文件共享给目标机，使其可以正常访问。
    

**2.漏洞复现过程：**

**step1:**首先攻击者使用低权限账号与目标机器建立RPC连接。

**step2:**建立连接后，通过RPC远程调用AddPrinterDriverEx方法。

在调用AddPrinterDriverEx方法时，pDriverInfo参数的结构体中，cVersion指定为3，以便绕过驱动文件兼容性检查；

  

pDriverPath指定为目标系统驱动文件UNIDRV.DLL所在路径（可通过RPC远程调用EnumPrinterDrivers方法获取）；

  

pDataFile指定为通过SMB共享的恶意DLL文件路径。

  

**pDriverInfo参数结构如下：**

typedefstruct \_DRIVER\_INFO\_2 {

  DWORD cVersion;

  LPTSTR pName;

  LPTSTR pEnvironment;

  LPTSTR pDriverPath;

  LPTSTR pDataFile;

  LPTSTR pConfigFile;

}DRIVER\_INFO\_2, \*PDRIVER\_INFO\_2;

 

**pDriverInfo参数各成员含义如下：**

**cVersion**

写入驱动程序的操作系统版本。支持的值为3。

 

**pName**

指向以 null 结尾的字符串的指针，该字符串指定驱动程序的名称(例如，"QMS 810" ) 。

 

pEnvironment

指向以 null 结尾的字符串的指针，该字符串指定为其编写驱动程序的环境(例如，Windows x86、Windows IA64 和 Windows x64) 。

 

**pDriverPath**

指向以 null 结尾的字符串的指针，该字符串指定包含设备驱动程序的文件的文件名或完整路径和文件名(例如，"c:\\driver \\pscript.dll" ) 。

 

**pDataFile**

指向以 null 结尾的字符串的指针，该字符串指定包含驱动程序数据的文件的文件名或完整路径和文件名(例如，"c:\\driver\\ Qms810" ) 。

 

**pConfigFile**

指向以 null 结尾的字符串的指针，该字符串指定设备驱动程序的配置.dll (的文件名或完整路径和文件名，例如，"c:\\driver\\ Pscrptui.dll" ) 。

 

同时，在调用AddPrinterDriverEx时，dwFileCopyFlags参数取值为：

APD\_COPY\_ALL\_FILES| APD\_COPY\_FROM\_DIRECTORY | 

APD\_INSTALL\_WARNED\_DRIVER。APD\_COPY\_ALL\_FILES用以将驱动程序所有文件（包括恶意DLL文件）复制到系统驱动程序目录中；APD\_COPY\_FROM\_DIRECTORY及APD\_INSTALL\_WARNED\_DRIVER用以绕过系统对驱动程序文件目录及签名的检测。

  

当第一次执行完AddPrinterDriverEx方法时，恶意DLL文件会被复制到系统驱动程序目录中（C:\\Windows\\System32\\spool\\drivers\\x64\\3），为接下来第三步做好准备。

  

**Step3：**经过上述步骤，恶意DLL文件已被复制到系统驱动目录。再次调用AddPrinterDriverEx()方法，cVersion指定为3，将pConfigFile参数指定为驱动目录下的恶意DLL文件，同时dwFileCopyFlags参数指定为APD\_COPY\_NEW\_FILES| APD\_COPY\_FROM\_DIRECTORY | APD\_INSTALL\_WARNED\_DRIVER 将驱动程序的配置DLL替换为恶意DLL文件，实现恶意DLL文件的自动加载，完成漏洞利用。执行SYSTEM权限级别的notepad.exe进程，如下图所示：

**0x03漏洞攻击行为检测**

  

在复现该漏洞的同时，我们通过工具Process Monitor监控产生的主机行为，提取到三类有明显特征的行为：

*   WriteFile (文件写入)
    
*   RegSetValue(注册表修改)
    
*   LoadImage (镜像加载)
    

###   

### **WriteFile**

漏洞执行过程中系统会向目录”C:\\Windows\\System32\\spool\\drivers\\x64\\3”写入攻击payloadEvilDll.dll，如下图：

  

![](../Images/2def969cbdd814f50da6f470ac1baaf8.png)

 

### **RegSetValue**

RegSetValue具体行为如下：

  

![](../Images/056fd6128c15f546718463b6d4e24bdd.png)

  

可以看到打印机服务进程spoolsv.exe向注册表地址”HKEY\_LOCAL\_MACHINE\\SYSTEM\\CurrentControlSet\\Control\\Print\\Environments\\Windowsx64\\Drivers\\Version-3”新增了注册表项”evilDriver1”,通过查询微软官方文档得知，打印机程序在安装新的驱动过程中会修改此注册表，实现驱动的注册安装，因此监控和调查这一注册表值更改事件对于检测和发现此漏洞攻击尤为关键。

  

### **LoadImage**

Load Image具体行为如下：

  

![](../Images/056fd6128c15f546718463b6d4e24bdd.png)

  

可以看到打印机服务进程spoolsv.exe 加载执行了恶意DLL文件“EvilDLL.dll”,文件目录为“C:\\Windows\\System32\\spool\\drivers\\x64\\3\\”这是打印机在安装新驱动的过程中会自动将驱动文件复制到这个目录进行加载。

  

攻击者在利用该漏洞对目标进行远程攻击时，需要向目标机器安装打印机驱动程序，在这个过程中会进行认证，认证过程会产生Windows网络登录事件，这类事件会被记录在Windows事件日志的“Security”目录下，Event ID:4624日志如下：

  

![](../Images/76f726ce4a067204d5efafd72cc44582.png)

 

在日志中可以提取到登录源地址、账号、认证过程、登录方法等特征信息。
