0X01 基础  

    域认证按我的理解是一种可信验证的机制，目的就是为了证明你是受信任的，我只允许受信任的对象访问。

    Kerberos 是一种网络认证协议，通过密钥系统为客户机 / 服务器应用程序提供强大的认证服务。该认证过程的实现不依赖于主机操作系统的认证，无需基于主机地址的信任，不要求网络上所有主机的物理安全，并假定网络上传送的数据包可以被任意地读取、修改和插入数据。也就是说在这种不信任网络中， Kerberos 作为一种可信任的第三方认证服务，是通过传统的密码技术（如：共享密钥）执行认证服务的。

    

Kerberos 认证有三个角色：

    Client（访问服务）

    Server（提供服务）

    KDC（密钥分发中心）= DC（域控制器）

KDC 服务默认会安装在一个域的域控中，而Client和Server是域内的用户或服务。  

  
  

0X02 名词解释

KDC（Key Distribution Center）：密钥分发中心，负责管理票据、认证票据、分发票据，KDC并不是一个独立的服务，它由AS和TGS组成。

AS（Authentication Server）：认证服务器,为client生成TGT的服务，AS验证是当 AS 接收到 Client 的请求之后会根据 KDC 中存储的密码hash来解密，解密成功并且验证信息。

TGS（Ticket Granting Server）：票据授权服务器

TGT（Ticket Granting Ticket）：入场券\[认证票据\]，通过入场券能够获得票据，是一种临时凭证的存在。

AD（Account Database）：存储所有client的白名单，只有存在于白名单的client才能顺利申请到TGT。存储了域中所有用户的密码 HASH，在物理上 KDC和AD 一般在一台计算机上。

SS（Service Server）：特定服务提供端

ST（TGS ticket）：票据

票据：可以看作为一种访问凭证

Master Key（Long-term Key）：长期密钥（被 Hash加密的用户密钥）

Session Key（Short-term Key）：短期会话密钥

krbtgt账户：是域默认创建的一个用户，是 KDC的服务账户，用来创建票据授予服务(TGS)加密的密钥。域中每个用户的票据都是由krbtgt的密码Hash来计算生成的。如果拿到krbtgt的密码Hash，就可以随意伪造票据，进而使用票据登录域控制器。

  

WindowsNT挑战/响应验证机制，称之为NTLM。

NTLM凭证由域名、用户名及在最初登录时所输入的加密口令所组成。

NTLM hash 就是里面加密保存了用户密码的 hash。Windows 中的用户密码被系统加密后保存在 SAM 文件中，如果是域环境则保存在域控的 NTDS.dit 中。

  

  

0X03 认证过程：

总体过程：

![](../Images/9d277e847b1c8a83fa7fc2282870f4eb.png)

1.Client（携带账户信息）向 KDC上的 AS服务发送想要访问 Server A的请求，索要入场卷（ TGT）；AS通过 AD验证，成功后返回 TGT。

2.Client（携带 TGT）请求 KDC中的 TGS服务想要访问 Server A，索要票据（Ticket）；TGS验证 Client的 TGT，具有 Server A的访问权，返回 Ticket。

3.Client（携带 Ticket）与服务器进行相互验证且成功，可以访问 Server A，但无权访问其他服务器。

详细过程：

生成TGT和session key

![](../Images/ac1c69d4f511954a87af779c635146a1.png)

1.Client发送自己的身份信息（username/host），KDC在AD中寻找Client的身份信息，找到了就提取对应的NTLM hash。

2.KDC生成一个随机的 session key 字符串，通过 Client 的 NTLM hash 来加密，作为AS数据（session key-as），使用KDC中krbtgt用户的NTLM Hash加密Session Key和客户端的信息（含时间戳），生成TGT。返回session key-as和TGT。

注：

没有Client 的 NTLM hash 的话Client是无法解密的

黄金票据的伪造会发生在这个过程

  

获取要访问的server ticket

![](../Images/0990ab3409fa9dafb1d12be98d2beec0.png)

1.Client接收到session key-as和TGT后，用它 NTLM Hash 解密出来session key。然后再用session key去加密client的身份信息（含时间戳）和TGT一起发送给KDC的TGS换取能够访问server的票据。

注:

TGT 是由 KDC 中krbtgt用户的NTLM Hash加密，Client 无法解密

这个时间戳可以防止中间人攻击，就算被窃取但短时间内无法破解，也是徒劳

2.KDC收到TGT和加密后的client信息，TGS利用krbtgt用户的NTLM Hash解密TGT，然后再用解出来的session key去解client的信息，验证时间戳有没有过期，确认client是否可信任。

3.验证通过后会生成一个新的session key（session key-tgs 加密 client用户信息和TimeStamp），我们称之为Server Session Key，主要用于和服务器进行通信。还有生成一个Ticket（Server 密码 HASH 加密 session key-tgs），也就是最终的票据。

  

client请求server

![](../Images/045266ac9c25e69c068b92c9e96b2497.png)

1.client发送Session Key和Ticket

2.server通过自己的密码hash解密Ticket得到session key-tgs，再解密Session Key得到时间戳，验证其没有过期并验证用户信息正确性后返回验证成功。

注：

Ticket客户端无法解密，因为没有 Server 密码 HASH，只能发送给 sever端。

该Ticket会一直存在客户端内存中，最后成功登陆

白银票据伪造会发生过在这个过程
