二次注入原理
恶意代码被注入到web应用程序中不会被立即执行，而是存储到后端数据库中，在处理另一次不同的请求时，从数据库中取出存入的恶意代码动态构建sql语句进行查询。


二阶注入原理流程图


也就是说在应用程序中输入恶意造的数据库查询语句时会被转义，但是在数据库内部调用读取语句的时候又被还原。

举个栗子
以sqli-labs/Less24为例
我们开始按照平常的思路进行注入无果



$username = mysql_real_escape_string($_POST["login_user"]);$password = mysql_real_escape_string($_POST["login_password"]);$sql = "SELECT * FROM users WHERE username='$username' and password='$password'";
其中mysql_real_escape_string函数会转义 SQL 语句中使用的字符串中的特殊字符。
源码中在登陆后修改密码处的语句为UPDATE users SET PASSWORD='$pass' WHERE username='$username' and password='$curr_pass'

我们只需要

UPDATE users SET PASSWORD='$pass' WHERE username='$username'#' and password='$curr_pass'

便可以修改相应用户名密码

关键是 $username'# 能成功插入users表中

我们可以尝试通过注册一个test'# 或test'-- 用户去实现


test用户是我事先注册好的用户，密码为test123



下面我们开始步入正题
我们需要通过注册将test'#存入到数据库中
我们已test'#用户的身份登录后修改密码



实际执行的是
UPDATE users SET passwd="test" WHERE username ='test'#'
最终我们成功修改了test用户的密码
同理如果admin账户存在我们可以直接去测试admin

03


一阶注入和二阶注入攻击过程比较
一阶注入：
1.攻击者在HTTP请求中提交恶意输入
2.应用程序处理而已输入，使用恶意输入动态构造sql语句
3.如果攻击实现，立刻返回响应结果
二阶注入：
1.攻击者在一个HTTP请求中提交恶意输入
2.恶意输入被保存在数据库中
3.攻击者提交第二个HTTP请求
4.应用程序处理第二个请求需要从数据库中取出之前的恶意输入并动态构建sql语句
5.如果攻击实现，在第二个请求响应中返回结果


思路
多留意强交互部分，SQL注入是存在于与数据库有交互的地方。往往在登录、修改内容、发布内容等功能上忽略了历史数据这一点，所以在遇到有修改账户密码、发布留言、发布内容的部分，我们可以尝试注册一个test或者admin’--或者admin账号，然后在测试回复的内容或者修改的内容是否达到预期。如果与预期不符，那么有可能就存在二次注入。
