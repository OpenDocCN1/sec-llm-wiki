## 0x01 引言

大家都知道，使用了 subprocess 传递数组形式的 args 过去，可以防御命令注入。我们在做代码审计时，一般默认传递数组形是安全的，不会深究。

那么真的一定没有命令注入的问题么？有的，这种写法还是有很多场景存在命令注入。

## 0x02 数组传参

我们来先看一个有问题的代码分析：

*   
*   
*   
*   
*   
*   
*   
*   

```
import osimport subprocess
host = "baidu.com"#host = "baidu.com;cowsay command_exec"
subprocess.call("ping -c 1 %s" % host, shell=True)os.system("ping -c 1 %s" % host)
```

执行结果：  

![](../Images/3a6f63e3156b01204531ae7ef7fd2a9a.png "image.png")

注：cowsay就是打印奶牛的命令

当看到奶牛时，那么我们就知道了，存在命令注入，因此以上两种写法都不可以。

然后我使用传递数组形式来进行传递args，保证安全：

*   

```

```

执行结果：

*   
*   
*   
*   

```
>>> subprocess.call(["ping", "-c", "1", host])ping: baidu.com;cowsay command_exec: Name or service not known
//没有看到奶牛，参数不存在命令注入
```

使用数组传参的方法，就不会存在命令注入了，万事大吉。因为 ping 只会去最后一个 args 中取 host，并不会自己去 parse 参数，所以传递数组写法是安全的。

但是也不是绝对的，这里很多人都有误解，事实并不是这样，这种写法还是有很多场景存在命令注入。

### 4.命令多expression 场景

以tcpdump为例，有各种 expression 作为过滤条件，假设我要执行如下命名：

*   

```

```

这种情况下，args 还是按照空格分隔的，我们写参数时应该是：

*   
*   

```
import subprocesssubprocess.call(['tcpdump', '-i', 'lo', 'tcp', 'port', '80'])
```

 而实际期望是 ：

*   
*   

```
import subprocesssubprocess.call(['tcpdump', '-i', 'lo', 'tcp port 80'])
```

这样就不能简单的去看 args 了，tcpdump 就会自己去 parse 命令行参数，可能是比较宽松的，这种情况下，如果 expression 可以被用户控制，还是可能产生命令注入的问题。

另外一个就是 tcpdump 支持参数名和值之间不写空格的写法，比如：

*   

```

```

## 0x04 解决方案

1.针对/bin/bash -c场景、远程登录并执行命令场景只需要过滤如下危险字符即可：

*   

```

```

2.针对rsync同步文件场景，可以加-s参数进行保护，就不会有远程命令执行了

*   
*   

```
import subprocesssubprocess.call(['rsync', '-s', 'user@ip:/root/test.txt;touch qxm', './'])
```

3.针对多命令多expression 场景，作为 Linux 下的通用做法，tcpdump 也支持使用 `--` 分隔参数和表达式。比如果有个文件的文件名是 `-la`，想使用 `ls -la` 查看文件的详细信息的话，就需要 `ls -la -- -la`。

*   
*   
*   
*   

```
import subprocesssubprocess.call(["tcpdump", "-i", "eth0", "-G1", "-w", "/tmp/1.pcap", "--", "-zcowsay"])
subprocess.call(["tcpdump", "-i", "eth0", "-G1", "-w", "/tmp/1.pcap", "--", "tcp port 80"])
```

无论最后一个参数怎么写，都不会出现问题了。
