当APP客户端设置了网络通信流量不走代理时，将手机设置代理后，APP所有的网络请求正常进行，但是BurpSuite等抓包工具却无法抓取到数据包，具体效果如下：

这种情况下会发现虽然设置代理后，APP依然能正常进行网络请求，但是抓包工具却无法抓取到任何数据包，这时可以猜测该APP是不是设置了网络流量不走代理，并使用以下几种方式进行尝试。

1. iptables流量转发（root权限）

设置BurpSuite为透明代理

获取目标应用的uid

  1. ps | grep <包名>

执行命令如下：

  1. iptables -t nat -A OUTPUT -p tcp -m owner --uid-owner u0_a116 -j DNAT --to-destination 192.168.137.1:8888

抓包验证

测试结束后，可使用 iptables -t nat -F 命令来清除规则。

2. Postern

vpn属于网络层，设置了vpn后，手机上会多一个接口，相当于加了一个虚拟网卡，所有的流量都会从这走。应用层和传输层的请求都可以拿到，即可绕过不走代理的限制。

3. HttpCanary

httpCanary是手机上的一个app抓包软件，采用vpn+中间人攻击的方法来抓包。

app下载地址：

httpcanarybasicv3.2.5.apk

4. HTTP Analyzer

通过HTTP Analyzer可抓取请求的网络请求数据包，如将APP在夜夜神模拟器中运行，开启HTTP Analyzer后，操作模拟器中的APP，即可抓取到相应的请求数据包。（如果在真机中测试APP使用此方式抓取数据包，可下载一个wifi热点工具，手机连接开启的热点，然后使用此工具抓取wifi热点工具进程的网络数据包即可抓到对应APP的请求数据包 ）

5. Hook方式绕过

反编译目标APP代码，搜索Proxy.NO_PROXY关键字。
