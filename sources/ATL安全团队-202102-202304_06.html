CobatStrike是基于java编写的全平台多方协同后渗透攻击框架。是近年来红队热门的攻击神器。该工具也集成了端口转发、端口扫描、socket代理、提权、钓鱼、远控木马等功能，几乎覆盖了APT攻击链中所需要用到的各个技术环节。国内外很多APT团队也都曾使用这个工具并且效果显著，但会导致许多安全防护软硬件都可以检测到工具的特征和流量，如果使用默认的证书进行渗透或测试时，环境高度安全的情况下就十分容易被检测并拦截，所有的努力都会变成徒劳，攻击计划就要重新制定。如今流量加密传输已经成为现在红队的基本素养，生成证书修改 C2 profile 加密混淆实际上就是对流量加密传输，目的逃逸流量安全审计，穿透检测器。

APT攻击

APT攻击，高级可持续威胁攻击（定向威胁攻击），指某组织对特定对象展开的持续有效的攻击活动(多种攻击手段的战术性综合利用)。
攻击者：拥有高水平专业知识和丰富资源的敌对方；攻击目的：破坏某组织的关键设施，或阻碍某项任务的正常进行；攻击手段：利用多种攻击方式,通过在目标基础设施上建立并扩展立足点来获取信息；攻击过程：在一个很长的时间段内潜伏并反复对目标进行攻击,同时适应安全系统的防御措施,通过保持高水平的交互来达到攻击目的‍

初级加密混淆方案

修改默认端口

使用vim打开teamserver文件

java -XX:ParallelGCThreads=4 -Dcobaltstrike.server_port=50050 -Dcobaltstrike.server_bindto=0.0.0.0

将默认端口50050修改为自行设定端口

修改默认证书（不建议使用默认证书）

使用keytool工具生成证书
keytool 是个密钥和证书管理工具。它使用户能够管理自己的公钥/私钥对及相关证书，用于（通过数字签名）自我认证（用户向别的用户/服务认证自己）或数据完整性以及认证服务，它还允许用户储存他们的通信对等者的公钥（以证书形式）。

使用keytool执行以下命令，输入如下命令后输入默认密码123456即可列出默认信息，下图为已经修改过的证书。

keytool -list -v -keystore cobaltstrike.store

使用如下命令对该keystore进行修改：
keytool参数说明如下# -keytool -keystore（指定密钥库的名称） cobaltstrike.store -storepass 密码# -keypass 密码# -genkey -keyalg RSA (指定密钥算法RSA)# -alias google.com -dname CN= (名字与姓氏),# OU= 组织单位名称), O= (组织名称),# L= (城市或区域名称),# ST= (州或省份名称),# C= (单位的两字母国家代码)。# -validity（指定创建的证书有效期多少天）# -delete（删除密钥库中某条目）keytool -delete -alias *** -keystore ***# -keysize (指定密钥长度)

keytool -keystore cobaltstrike.store -storepass 123456 -keypass 123456 -genkey -keyalg RSA -alias google.com -validity 365 -keysize 1024 -dname "CN=google, OU=google.com, O=Sofaware,L=Somewhere,ST=Cyberspace, C=CN"
再次查看密钥库条目此时包含旧条目和新加的条目，按需删除一个即可。

Warning:

生成的证书 uses a 1024 位 RSA 密钥 which is considered a security risk. This key size will be disabled in a future update.（上文使用1024位密钥为弱密码可尝试增加2048密钥位数）JKS 密钥库使用专用格式。建议使用 "keytool -importkeystore -srckeystore cobaltstrike.store -destkeystore cobaltstrike.store -deststoretype pkcs12" 迁移到行业标准格式 PKCS12。（根据提示将证书修改为标准模式）

修改keystore密码

keytool -storepasswd -keystore cobaltstrike.store


中级流量加密方案

修改Profile文件加密流量

BEACON与C2交互的过程中流量带有一定的特征可以被检测到，需要使用修改自定义的Profile文件来清洗交互流量，可以制定流量规则和BEACON特征，根据目标机存在的通信软件等仿造通信流量特征，起到加密流量混淆的作用。
C2-Profile的编写规则并不难，只要理解没个模块的作用以及语法就可以自己修改。
以meterpreter.profile为例，set可以设置全局的配置选项，比如文件名、心跳时间、useragent等，stage、https-certificate、http-stager、http-get、http-post，为数据包功能模块。http-stager可以通过header等语句来定义Stage通信中C2响应的http头内容。https-certificate可设置制定证书名称、存活时间、各种字段、证书密钥等。http-get定义GET请求中包含的信息。server定义各种请求服务器响应的信息。http-post定义POST请求中包含的信息。

高级加密混淆方案

域前置+使用第三方证书

域前置简介

域前置（Domain Fronting）被称为域前端网络攻击技术，是一种隐藏连接真实端点来规避互联网审查的技术。这种技术被安全人员多用来隐藏 Metasploit，Cobalt Strike 等团队控制服务器流量， 以此来一定程度绕过检查器或防火墙检测的技术，国内外如：Amazon ,Google，Akamai 等大型厂商都会提供一些域前端技术服务。
域前置原理：当域名指向CDN服务器IP，访问HTTP请求的host头域名时CDN就会根据host头将域名转发到指定网站内容
首先需要一个域名，可以在国外Freenom申请，如果有国内域名更好，方便国内解析并CDN加速，但使用国内的域名需要备案。可以在Freenom申请一个高伪装的域名，这里只做测试。


申请成功后会出现在在你的域名名单中，然后需要添加域名解析，可以使用Cloudflare，但对Freenom申请的免费域名不友好，添加解析时可能会报错，需要多次尝试或者更换域名。

也可以使用国内的DNS服务商对地址进行解析，这里使用DNSPOD，方便配置CDN。


添加完解析后，添加CDN

配置完成后多地ping测试CDN生效成功。


修改CS的域前置 profile 配置文件

需要注意修改的地方：

1.统一替换http-stager、http-get、http-post块的header “Host”值为自己配置的域名，如果添加了CND的情况下设置set trust_x_forwarded_for “true”，转发目标的真实ip。

2.https-certificate块中更改keystore和密码，keystore为生成的证书名，密码为生成的证书密码。


生成第三方证书
因为添加了CDN，所以可以直接申请第三方证书使用，如果没有添加的话可以使用自己生成的证书或者letsencrypt免费证书。

申请并部署CDN成功后可下载证书，用来生成store证书，下载选择其他，里面包含pem源证书和私钥证书

使用第三方证书生成pkcs12标准证书
# 这里xxx.tk是我的域名openssl pkcs12 -export -in server.pem -inkey server.key -out xxx.tk.p12 -name xxx.tk -passout pass:123456
keytool -importkeystore -deststorepass 123456 -destkeypass 123456 -destkeystore xxx.tk.store -srckeystore xxx.tk.p12 -srcstoretype PKCS12 -srcstorepass 123456 -alias xxx.tk
将生成keystore文件放在CS的根目录下，务必确保keystore名与密码和https-certificate中设置的一致。
设置完成后使用c2lint对profile语法进行检查，没有报错的话说明配置是ok的。
./c2lint xxx.profile


./teamserver ip password xxx.profile

启动CS后，将自己的域名设置监听

域名解析正常的情况下，HTTPS BEACON可以上线。

抓取流量包查看，目标机IP与C2服务器的交互地址为CDN加速地址，流量使用TLS协议加密传输。
