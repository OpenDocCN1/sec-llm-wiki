0x01 什么是反序列化

提到反序列化，就不得不先说说什么是序列化。

定义

序列化（serialization）在计算机科学的数据处理中，是指将数据结构或对象状态转换成可取用格式（例如存成文件，存于缓冲，或经由网络中发送），以留待后续在相同或另一台计算机环境中，能恢复原先状态的过程。依照序列化格式重新获取字节的结果时，可以利用它来产生与原始对象相同语义的副本。对于许多对象，像是使用大量引用的复杂对象，这种序列化重建的过程并不容易。面向对象中的对象序列化，并不概括之前原始对象所关系的函数。这种过程也称为对象编组（marshalling）。从一系列字节提取数据结构的反向操作，是反序列化（也称为解编组、deserialization、unmarshalling）。

序列化在计算机科学中通常有以下定义：

对同步控制而言，表示强制在同一时间内进行单一访问。
在数据储存与发送的部分是指将一个对象存储至一个存储介质，例如文件或是存储器缓冲等，或者透过网络发送数据时进行编码的过程，可以是字节或是XML等格式。而字节的或XML编码格式可以还原完全相等的对象。这程序被应用在不同应用程序之间发送对象，以及服务器将对象存储到文件或数据库。相反的过程又称为反序列化。

以上摘自：简书 作者：小智DotNet。

原文链接：https://www.jianshu.com/p/98b15a0e6806


你可能觉得以上的解释抽象又难以理解，没有关系。简单来说：对象是一个抽象的概念，没办法存储和传输，而序列化就是将抽象的对象转换为一串便于存储和传输的字符串的过程，那么反序列化也就不难理解了，自然就是将字符串转换为对象的过程。

0x02  PHP中的序列化与反序列化

PHP中的序列化与反序列化都是围绕这两个函数展开的：serialize() 和unserialize()。


serialize()：

serialize()函数用于把一个创建了的对象转化为一串字符串，也就是序列化。

我们来尝试使用一下：

<?phpclass ATL {    public $test1 = '111';        public $test2 = 222;    }$x=serialize(new ATL);echo $x;?>

这里我们创建了一个新的对象，将它序列化后的的结果显示出来：

O:3:"ATL":2:{s:5:"test1";s:3:"111";s:5:"test2";i:222;}
这里从左到右介绍：“O”表示结构类型为“类”；“3”表示类名长度；“ATL”为类名；“2”为成员个数；接下来大括号中“s”表示成员名类型为string；“test1”为成员名称；“s”值类型为string；“111”表示值为“111”；后面的test2与test1也相同，只是值的类型为“i”表示int类型。

这里还有PHP中文网中提供的其他字母的含义：

a - arrayb - booleand - doublei - integero - common objectr - references - stringC - custom objectO - classN - nullR - pointer referenceU - unicode stringN - NULL

原文链接：https://www.php.cn/php-notebook-239422.html


unserialize():

unserialize()函数用于把一串字符串转化为一个对象，也就是反序列化。

我们来尝试使用一下：

<?php$y='O:3:"ATL":2:{s:5:"test1";s:3:"111";s:5:"test2";i:222;}';echo $y;echo "</br>";$x= unserialize($y);print_r($x);?>

这里我们将刚刚序列化的字符串在进行反序列化，然后将结果输出，输出结果为：

O:3:"ATL":2:{s:5:"test1";s:3:"111";s:5:"test2";i:222;}__PHP_Incomplete_Class Object ( [__PHP_Incomplete_Class_Name] => ATL [test1] => 111 [test2] => 222 )

我们可以看到unserialize函数确实将字符串转换成了PHP的类对象。


0x03 反序列化漏洞相关魔术方法

要了解反序列化漏洞是如何产生，就要先了解PHP中的几个魔术方法：

什么是魔术方法：

在PHP中魔术方法一般是以__开头，一般会因为某些条件自动调用，而不用我们手动调用。

而反序列化漏洞一般可能由这几个魔术方法引起：

__construct()    #当一个对象创建时被调用__destruct()    #当一个对象销毁时被调用__sleep()         #在对象在被序列化之前被调用__wakeup()        #当对象在反序列化之前被调用__toString()    #当一个对象被当作一个字符串使用时被调用

我们来测试一下：

<?phpclass ATL{    public $test1 = '111';                    public $test2 = 222;    function __construct(){        echo "__construct</br>";            }        function __destruct(){        echo "__destruct</br>";    }        function __sleep(){        echo "__sleep</br>";        return array('test1','test2');    }        function __wakeup(){        echo "__wakeup</br>";    }        function __toString(){        return "__toString</br>";    }}$ser = serialize(new ATL);          #创建对象并将它序列化echo $ser;                          #输出序列化后的字符串echo "</br>";echo "ATL is serialize!</br>";
$uns = unserialize($ser);           #将刚才的字符串反序列化print_r($uns);                      #输出反序列化出来的对象echo "</br>";echo "ATL is unserialize!</br>";echo $uns;                          #尝试将对象当做字符串输出?>

执行结果如下：

__construct            #创建ATL时被调用__sleep                #序列化前被调用__destruct            #ATL被销毁时调用O:3:"ATL":2:{s:5:"test1";s:3:"111";s:5:"test2";i:222;}ATL is serialize!    #ATL序列化完成__wakeup            #反序列化前被调用ATL Object ( [test1] => 111 [test2] => 222 ) ATL is unserialize!    #反序列化完成__toString            #尝试以字符串形式输出ATL时被调用__destruct            #程序结束，ATL被销毁时调用
通过结果我们可以分析出各个魔术方法调用的时机确实像我们上面所说。同时这其中还有两处需要注意：

__sleep()方法：

serialize() 函数会检查类中是否有__sleep()方法。如果有，就会优先调用该方法，然后才执行序列化操作。同时__sleep()方法一定需要有返回值，如果该方法没有返回任何内容，则 NULL 被序列化，并产生错误。

通过__sleep()的返回值，我们还可以只序列化部分成员，比如：

<?phpclass ATL{    public $test1 = '111';                    public $test2 = '222';    public $test3 = '333';    public $test4 = '444';}$ser = serialize(new ATL);echo $ser; ?>

此时运行结果为：

O:3:"ATL":4:{s:5:"test1";s:3:"111";s:5:"test2";s:3:"222";s:5:"test3";s:3:"333";s:5:"test4";s:3:"444";}

如果我们在ATL类中，添加__sleep()方法，并使其只返回test2，和test3：

<?phpclass ATL{    public $test1 = '111';                    public $test2 = '222';    public $test3 = '333';    public $test4 = '444';            function __sleep(){        return array('test2','test3');    }}$ser = serialize(new ATL);echo $ser; ?>

此时输出结果：

O:3:"ATL":2:{s:5:"test2";s:3:"222";s:5:"test3";s:3:"333";}
可以发现，序列化后字符串中只定义了两个成员，确定了通过__sleep()方法确实可以指定部分成员进行序列化。

__toString()方法：

__toString()在直接输出对象引用时自动调用，对象引用是一个指针，我们不能直接输出对象引用，如果直接输出就会输出”Catchable fatal error: Object of class Person could not be converted to string“这样的错误。

而如果你在类中定义了__toString()”方法，在直接输出对象引用的时候，就不会产生错误，而是自动调用了该方法, 输出该方法中返回的字符。所以__toString()方法也一定需要有返回值，如果没有返回任何内容也会产生错误。并且__toString()方法会自动输出返回值。


0x04 反序列化漏洞介绍

知道了什么是序列化与反序列化，又知道了什么是魔术方法，在什么时候回自动调用，那么我们就可以分析反序列化漏洞是如何产生的了。

漏洞产生原因：

设想一下，如果服务器能够接收我们序列化过的字符串，并且未经过过滤就将其反序列化，这样就会将我们构造好的变量一起带入，如果魔术方法自动调用了我们的变量，那么就可以造成严重的漏洞。比如魔术方法中会将变量带入数据库查询，那我们就可以构造sql语句造成sql注入，如果会执行我们的变量，那就会造成代码注入。

所以漏洞产生的条件如下：

1.反序列化的内容从客户端可以控制。
2.后台脚本不正当的使用了魔术方法。

反序列化漏洞简单利用

举个简单的例子：

<?phpclass ATL{    public $test;
    function __destruct(){            echo $this->test;    }}if(isset($_GET['test'])){    $str = $_GET['test'];    $uns = unserialize($str);}else    echo "请提交test参数。"?>

这个脚本会将我们提交的参数进行反序列化，魔术方法会在对象销毁时输出test变量的值。

那么我们构造以下payload：

http://127.0.0.1:8080/test.php?test=O:3:"ATL":1:{s:4:"test";s:29:"<script>alert(/XSS/)</script>";}

访问时，我们发现页面进行了弹窗，这样我们就利用反序列化漏洞进行了一次反射型XSS攻击。当然这只是一个示例，在之后的文章我还会详细的介绍反序列化更多的利用方式。
