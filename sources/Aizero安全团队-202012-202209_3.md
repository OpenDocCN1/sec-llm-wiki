**概述**

只需几分钟便能搭建好一个完整的wifi攻击环境，针对无线破解，钓鱼诱导两种攻击方式来进行实验，此次实验使用 Ventoy 来制作 kali linux U盘启动，在使用本机自带无线网卡（WIFI 6 AX200）的情况下来完成整个实验。  

![](../Images/b3eab336695bd9ccb0bb09b576ba6037.png)

  

**Ventoy**

简单来说，Ventoy是一个制作可启动U盘的开源工具，仅需要把ISO/WIM/IMG/VHD(x)/EFI等类型的文件拷贝到U盘里面就可以启动了，无需其他操作，详细说明各位可在官网看到。

  

官网地址  

| https://www.ventoy.net  
 |
| --- |

![](../Images/29a27d807f0b475d0907fa36d38dcb92.png)

下载对应使用系统版本，在这里我们下载windows版来进行安装，解压即可使用会检测出我们已经插入的U盘，第一次安装会需要格式化U盘，此后升级都不会再格式化U盘，且不影响日常U盘使用。  

![](../Images/68b4d6e67395d481a45993398645ed80.png)

  

kali镜像下载地址：

安装完成后将kali镜像拖入U盘中，Ventoy支持多个系统，可多个系统一起使用。

![](../Images/c923e947ae545315a250feb151d78111.png)  

  

**U盘数据持久化  
**

需要将kali的数据设置为持久化存储，不然每次重启系统都重置。  

  

Ventoy数据持久化在官网上也给出详细说明，有更多需求的话建议详细看一下。

| https://www.ventoy.net/cn/plugin\_persistence.html  
 |
| --- |

我们先在U盘中创建/ventoy/ventoy.json文件（默认是没有的），文件内容为：

| {  
    "persistence": \[  
        {  
            "image": "/kali-linux-2021.1-live-amd64.iso",  
            "backend": "/persistence/kali-linux-2021.1-live-amd64.iso.dat"  
        }  
    \]  
} |
| --- |

使用官网脚本创建一个存储数据持久化镜像文件（在linux中创建）：

| wget https://www.ventoy.net/download/CreatePersistentImg.sh  
//创建一个2G大小的持久化镜像文件sudo sh CreatePersistentImg.sh -s 2048 -l persistence -c persistence.conf  
 |
| --- |

![](../Images/e1210c8c287f6c7a16420b51b81c83fa.png)

没有使用linux系统可在官网github下载：  

| https://github.com/ventoy/backend/releases  
 |
| --- |

将创建好的镜像文件放在ventoy.json中配置目录下

![](../Images/e7fef6f9479242fc44505dd6292489ec.png)

这样我们的U盘启动就算制作完成，后续只需将电脑BIOS设置为U盘启动即可，在这里百度自己电脑BIOS设置就行。

**无线网络认证  
**在正式开始攻击之前，我们先简单了解一下关于无线网络的一些知识，这样才能更好的了解到我们所攻击的一些原理，扩展更广阔的攻击面（仅简单说明我们此次攻击的WPA/WPA2类型认证）。

  

WPA2-Personal（预共用密钥模式），又称为WPA2-PSK，WPA/WPA2为混合模式，可以兼容部分老设备，在家庭和公司当中使用比较多。加密方式采用AES，而且不加密的wifi传输速度会更快。wpa在一定程度上已经算是安全的，但是还是存在一些缺陷，无法避免防碰撞，DDOS攻击，弱口令爆破，而且在最近爆出了更多的wifi设计上是缺陷，基本影响市面上大部分的wifi。详情可以访问下面地址查看（以上仅是一些说明，不是绝对正确），

| https://www.fragattacks.com/ |

**钓鱼诱导  
**

参考：https://blog.bbskali.cn/2179.html

  

我们钓鱼诱导是思路是先对客户端进行拒绝服务攻击，也就是让一个活跃的客户端与wifi断开连接，然后连接到一个我们创建的钓鱼wifi。在受害者连接到我们的wifi时，不管访问哪里站点，或是自动访问其它站点，都会通过DNS重定向到我们伪造的路由器登录页面，提示输入wifi密码信息。

  

我们使用airbase-ng来伪造一个wifi热点，在使用airbase-ng时也需要使用sudo airmon-ng  start wlan0 来开启网卡的监听

| sudo airmon-ng  start wlan0sudo airbase-ng wlan0mon -e "Crazypad5.0\_2.4G" -c 1 |
| --- |

  

或者可以使用hostapd来搭建  

| sudo apt install hostapdvim hostapd.conf  
  
// hostapd.conf 内容interface=wlan0monssid=Crazypad5.0\_2.4G #无线名称hw\_mode=gchannel=6macaddr\_acl=0ignore\_broadcast\_ssid=0 |
| --- |

  

**DHCP服务器搭建**  
DHCP服务器我们使用dnsmasp来搭建，这个是比较快速方便的方法（问题也多）。

| vim dnsmasp.conf  
// dnsmasp.conf内容  
interface=wlan0mondhcp-range=192.168.1.2,192.168.1.30,255.255.255.0,12hdhcp-option=3,192.168.1.1dhcp-option=6,192.168.1.1server=127.0.0.1log-querieslog-dhcplisten-address=127.0.0.1 |
| --- |
