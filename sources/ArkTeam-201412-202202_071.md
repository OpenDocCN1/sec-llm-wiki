# 迈向更成功的Web漏洞通知

原文标题：Didn’t You Hear Me? – TowardsMore Successful Web Vulnerability Notifications

原文会议：NDSS Symposium 2018

原文链接：http://wp.internetsociety.org/ndss/wp-content/uploads/sites/25/2018/02/ndss2018\_01B-1\_Stock\_paper.pdf

过去几年来， 随着基于WordPress，Joomla或Drupal等内容管理系统的大量搭建部署，当这些系统出现漏洞时，则会导致大量网站变得易于受到攻击。对于安全研究人员和攻击者来说，检测网站和识别网站中的漏洞通常相当简单，那么迅速有效地通知受影响的网站管理者非常重要。因此，安全社区不仅需要专注于发现漏洞，而且还要找到通知易受攻击网站的快捷方式。

该论文的研究人员选取了24000多个存在漏洞的网站，将代码寄存在git上的网站标记为git组，将以WordPress为基础搭建的网站标记为WP组，对这些站进行Web漏洞通知的实验。

在域名WHOIS数据库中获取网站管理员邮箱地址，使用四组前缀security@,abuse@webmaster@和info@作为不同的收件人进行测试。邮件内容使用六种不同类型的消息：

1.       (Plain)明文信息。该消息包含一个列表，描述已识别的安全问题以及检索详细的技术漏洞报告的说明。

2.       (S / MIME)电子邮件。考虑到漏洞通知消息的潜在敏感性，未签名的消息可能会导致收件人不信任的真实性。我们使用了与普通邮件相同的电子邮件文本，但使用有效的S / MIME证书签名。

3.       (Mailbot)明文电子邮件的第三种变体包含与明文和S / MIME相同的消息。但是，为了测试发件人名称是否对通知成功率有影响，修改了发件人电子邮件地址并显示名称为漏洞通知<notify @ ...>

4.       (Tracking)具有外部资源的HTML电子邮件。纯文本的信息无法知道收件人是否打开过本邮件，所以制作了一份HTML邮件并外链了研究机构的徽标，若打开邮件则服务器会记录。

5.       (HTML)没有外部资源的HTML电子邮件。外链可能会导致邮件系统的警告，作为对比组，将徽标作为附件发送。

6.       (Friendly)友善的通知。只通知收件人发现网站出现安全问题，要求他们提供一个负责处理网站安全的电子邮件地址。

与对照组（没有发送安全通知的网站）比较，通知组的修复率更高，WordPress的自动安全更新可能会影响WP组的通知成功率。那些没有自动更新的WP网站可能不积极维护网站，从而减低通知的成功率。

      电子邮件的安全通知存在多方面的挑战。一方面电子邮件可能因为发送量大而被邮件系统标记为垃圾邮件，或者WHOIS上的信息不正确，不存在该邮箱。另一方面，收件人不负责网站安全，会忽略掉邮件。收件人不信任该邮件信息，认为该邮件为钓鱼邮件等垃圾邮件。

在未来的Web漏洞通知工作中，首要面临的问题对邮件和发件人的信任问题，研究人员的建议是与知名组织（例如Google，微软）合作，同时在电子邮件中公开所有技术细节，并去除外链资源等方式来提高信任度。
