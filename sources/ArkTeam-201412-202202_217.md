# Android Smali代码注入之APP动态行为拦截

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzA3Mjk4MDMzMQ==&mid=2648248081&idx=1&sn=b499aa70b8eef32e2435e189ce1e922f&chksm=873bad15b04c2403ba94cf9af4d64209d67c1d0078752dc7ba265cde11058dfccd11960e93d7&scene=126&sessionid=1681400100#rd](http://mp.weixin.qq.com/s?__biz=MzA3Mjk4MDMzMQ==&mid=2648248081&idx=1&sn=b499aa70b8eef32e2435e189ce1e922f&chksm=873bad15b04c2403ba94cf9af4d64209d67c1d0078752dc7ba265cde11058dfccd11960e93d7&scene=126&sessionid=1681400100#rd)

Smali代码是安卓系统中Java虚拟机（Dalvik）所使用的一种.dex格式文件的汇编代码，Smali代码与Java代码有一定的对应关系。

将Android应用APK逆向为Smali代码，以代码注入的方式拦截一些关键的API调用，可以方便地对Android应用行为进行动态监控，常见的应用为Smali Log日志注入、弹消息框、拦截程序行为等。但是，这也给一些恶意代码以可乘之机，来获取用户的隐私数据或是实现其它恶意功能，感染正常的应用程序。近年，基于Samli代码注入的安卓恶意代码，越来越受到重视。

下图展示了Smali代码注入的基本流程：

  

![](../Images/f9845a42285fc3dc66327548dbc8a981.png)

重打包形成的APK，没有改变原来正常APK的功能，但是却被攻击者注入了恶意行为，成为了一个恶意APK。对于新形成的恶意APK，再通过下载、分享等方式传播，就可以达到攻击者窃取数据的目的了。

本文从学习的角度出发，以监控拦截手机短信为例，对Android Smali代码注入过程进行说明。

1.创建正常APK。功能是给指定号码发送一条短信。

  

![](../Images/eb0515f3320b811682e5ee4f103aecc1.png)  

  

2.创建恶意拦截APK。自定义短信管理类SmsManager，在类中创建一个公开的静态方法 void sendTextMessage(String destinationAddress,String scAddress,String text,PendingIntent sentIntent,PendingIntent deliveryIntent)，该方法Android系统源代码中定义的发送短信的方法一致。

  

![](../Images/28175d49f431fd25179b7553b8cff604.png)  

  

3.提取正常APK Smali代码。分别将正常的短信发送应用程序和恶意的短信拦截应用程序的APK利用apktool工具逆向为Smali代码。

  

![](../Images/6211b193ced5252cf534a34cf81c2f70.png)

![](../Images/fbd5d2704d3ffc46c120420ea4cf3623.png)

  

4.提取恶意APK Smali代码。将恶意的短信拦截应用程序的Smali代码从Smali文件夹根目录开始复制到正常的短信发送应用程序的Smali文件夹根目录。恶意短信拦截应用程序Smali代码的路径为com/intercept/sms，正常短信发送应用程序Smali代码的路径为com/example/sms

  

![](../Images/2f9d594ed389eaff958a5e23937cf619.png)  

  

5.替换Smali代码。在正常短信发送应用程序Smali文件夹下的MainActivity$1.smali文件中搜索sendTextMessage关键字，定位至短信发送的代码；将invoke-virtual替换为invoke-static，v0~v5寄存器替换为v1~v5寄存器，android/telephone/SmsManager替换为com/intercept/sms/SmsManager。这样做的原因是自定义的拦截短信的方法是静态的，静态方法不需要new一个对象，所以少了一个v0寄存器存放对象的占用，后面做的路径的替换是将Android源代码中sendTextMessage所在的类路径替换为自定义的类路径。此处涉及Smali代码较为详细的语法，感兴趣的同学可以深入学习一下。

  

![](../Images/316b995ef843535988152545df0c2615.png)

![](../Images/dd714b3cc682c5199aa48c18ba5e55dd.png)

  

6.重打包、重签名。将注入完毕的正常短信发送应用程序重打包、重签名，此处不再赘述重打包重签名的方法，网上有诸多教程可供参考。

7.形成目标APK。部署目标APK到Android模拟器，模拟器5554向模拟器5556发送一条短信，Logcat日志中可以成功拦截到发送的短信。

  

![](../Images/67f1250fd26f34f2035f8842a16212db.png)![](../Images/867d480e7c0a4b8bdf1f6ac48369f00d.png)

![](../Images/dec77157b7ff257d7f9e9e52b71d0ea2.png)

**结束语**

上述实验以正常短信发送程序被注入恶意短信拦截Smali代码为例，进行Smali代码注入过程的说明，成功打印出拦截到的短信信息，此处仅做技术交流分享。对于做了APK加固反汇编失败的情况，是难以使用Smali代码注入的，这也是Smali代码注入的一个局限性，可以结合一些脱壳的手段加以利用。

从防御的角度出发，如果将打印日志的地方定义为与用户交互的可选择弹窗，即可提醒用户应用在试图发送短信，由用户选择是否允许该短信发送行为，起到动态行为拦截的作用，也可拦截更多的敏感行为操作，在一定程度上对用户的隐私行为起到保护作用。
