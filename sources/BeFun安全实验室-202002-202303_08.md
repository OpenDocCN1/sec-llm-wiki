本文是路由器的`NetUSB`模块漏洞挖掘系列第一章，描述了如何自行编译一个包含用户自定义的Linux内核模块的`mips`镜像，并用`qemu`启动以作为漏洞挖掘调试的环境。

翻译自`https://blog.security.sea.com/posts/netusb-emulation/`，在原文基础上有部分修改和补充。

原作者`Bien Pham (@bienpnn)`在 Pwn2Own Austin 2021 上利用了`NetUSB`模块的漏洞对`TP-Link Archer C7`和`Netgear R6700v3`路由器完成了攻击。本文是原作者所在团队 Sea Security 对`NetUSB`模块漏洞利用的第一篇文章，总结了如何在路由器上加载并调试一个内核模块，以及如何在模拟`mips`架构运行一些用户态的程序。

## 目标

TP-Link Archer C7 router, MIPS32r2 Big Endian, firmware version 211022.

## 为什么选择`NetUSB`作为目标

> 台湾 USB 解决方案提供商 KCodes，专门从事 USB over IP 软件开发。NetUSB 是 KCodes 开发的一种内核模块连接解决方案，允许网络中的远程设备与直接插入到路由器的 USB 设备进行交互。只要路由器厂商在设备上添加 USB 端口，用户便可以通过这一端口共享联网的打印机和 USB 驱动器。

NetUSB 服务会在公网上开放一个`20005`的端口，一般我们针对路由器的攻击都是在内网（LAN）上的，谁不想要一个打全网（WAN）的洞呢？而且历史上这个组件也出过几个可以 RCE 的洞（CVE-2021-45608，CVE-2021-45388），所以 NetUSB 是一个很好的目标。

## 固件下载，解压

目前官网仍然提供漏洞版本的固件下载，直接下载就行：

```
$ wget "https://static.tp-link.com/upload/firmware/2021/202110/20211029/Archer%20C7(US)_V5_211022.zip"
$ unzip Archer\ C7\(US\)_V5_211022.zip

```

binwalk 解包拿到路由器的文件：

```
$ binwalk -e c7v5-up-ver1-1-4-P1\[20211022-rel59103\]_2021-10-22_16.38.32.bin


```

把路由器的文件系统的路径命名为`$ROUTER_ROOTFS`：

```
$ ROUTER_ROOTFS=`pwd`

```

## 环境配置

### GPL 包

> 由于 OpenWrt 和 Linux 内核遵守 GPL 协议，所以 TPLink 官方提供了修改后的源码，Archer C7 V5 的 GPL 包可在这里下载，然后在 32 位机器上用 GCC 4.x 编译。

把 GPL 的目录命名为`$GPL_PACKAGE`，分析 GPL 包后可以知道内核版本是`linux-3.3.8`（有一个配置文件位于`$GPL_PACKAGE/build/linux-3.3.config`），内核补丁位于`$GPL_PACKAGE/openwrt/target/linux`：

```
$ wget https://static.tp-link.com/resources/gpl/ArcherC7V5.tar.bz2
$ tar -xf ArcherC7V5.tar.bz2
$ cd Archer_C7_V5/
$ GPL_PACKAGE=`pwd`
$ cd ..

```

### 通过串口获取 shell

原作者一开始尝试了通过焊接主板上的串口来拿 shell，但是没成功，方法在这里，所以最后决定做一个可以加载 NetUSB 模块的 MIPS VM Buildroot 镜像，只需要把之前在 GPL 下载的补丁打上就 OK。

## 内核编译

### 环境

原作者使用的是 Ubuntu 16.04.7 LTS i386，我用的是 Ubuntu 20.04.4 LTS amd64，实测可以成功编译并启动。

### Buildroot 下载

```
$ wget https://buildroot.org/downloads/buildroot-2016.02.tar.bz2
$ tar -xf buildroot-2016.02.tar.bz2

```

### 内核下载

配置了 buildroot 的目录为`BUILD_ROOT`

```
$ cd buildroot-2016.02/
$ BUILD_ROOT=`pwd`
$ wget https://mirrors.edge.kernel.org/pub/linux/kernel/v3.x/linux-3.3.8.tar.bz2
$ tar -xf linux-3.3.8.tar.bz2

```

打补丁

```
$ rsync -av $GPL_PACKAGE/openwrt/target/linux/generic/files/ $BUILD_ROOT/linux-3.3.8/
$ mkdir $BUILD_ROOT/linux-patches
$ rsync -av $GPL_PACKAGE/openwrt/target/linux/generic/patches-3.3/ $BUILD_ROOT/linux-patches/
$ rsync -av $GPL_PACKAGE/openwrt/target/linux/malta/patches-3.3/ $BUILD_ROOT/linux-patches/

```

打包

```
$ cd $BUILD_ROOT
$ rm linux-3.3.8.tar.bz2
$ tar -cjSf linux-3.3.8.tar.bz2 linux-3.3.8

```

然后把文末的配置文件复制到`$BUILD_ROOT/linux-3.3.8.config`，这个配置文件由 GPL 包中的配置文件修改而来，例如将目标机器更改为`Malta`、启用`PCI`和`virtIO`等。

### 把 NetUSB 模块复制到镜像中

```
$ mkdir -p $BUILD_ROOT/overlay/etc/init.d/
$ mkdir -p $BUILD_ROOT/overlay/lib/modules/
$ cp -r $ROUTER_ROOTFS/lib/modules/kcodes $BUILD_ROOT/overlay/lib/modules/

```

原作者通过对 NetUSB 模块的逆向发现需要配置`br0`桥接设备和`usbcore`模块功能，所以需要配置一下网络，创建以下两个文件并给权限。此时我们还可以放一些其他的文件进去，比如`gdbserver`，直接复制到`$BUILD_ROOT/overlay/`下即可。

```


gedit $BUILD_ROOT/overlay/etc/init.d/S98bridge
```

S98bridge：

```

```

S99netusb：

### 配置 Buildroot

```
$ cd $BUILD_ROOT
$ make menuconfig

```

修改以下设置：

```


Target options
```

然后退出保存，运行`make busybox-menuconfig`，修改以下配置：

```


Networking Utilities
```

运行`make linux-menuconfig`来修改内核选项，比如开启`debug symbol`（`Kernel hacking -> Compile the kernel with debug info`），然后退出保存。

### 构建镜像

```
$ cd $BUILD_ROOT
$ make -j$(nproc) V=1

```

遇到`502 BadGateway`的时候多试几次就行，可能网不太好。

我编译的时候遇到了以下错误：

```

```

经过一番搜索找到解决方法

```
$ cd /home/a/NetUSB/buildroot-2016.02/output/build/host-m4-1.4.17/
$ sed -i 's/IO_ftrylockfile/IO_EOF_SEEN/' lib/*.c
$ echo "#define _IO_IN_BACKUP 0x100" >> lib/stdio-impl.h
$ cd $BUILD_ROOT

```

构建完成后的镜像保存在`$BUILD_ROOT/output/images/vmlinuz`
