浏览下主程序，可以发现程序接受了一个32位的输入，而且从本身程序读取了16字节的变量到buffer变量中



接着，用输入的前四个字节替换了buffer中四个字节，然后把buffer当作参数传入了md5_api函数



md5_api函数其实是一个windows crypt api，CryptCreateHash的第二个参数代表着加密算法类型，0x8003代表是md5加密



加密之后的散列值，当作了aes_ecb的密钥传入了aes解密函数(sub_00402798),密文enc解密之后和输入的前16字节进行了比较，如果通过就返回True，进入下一个阶段



sub_4028A7函数是最终验证的函数，参数是aes_key和input，而aes_key就是之前生成的散列值


这个函数类似tea加密，首先把输入和散列值的十六进制进行了异或，然后把异或后的值的前16字节当作enc_key,加密异或后的16字节，最后和v10,v11比较


那么思路就是必须先求出散列值，而散列值是由输入的前4个字节和程序本身12个字节，MD5得到的，而且会当作密钥经过aes解密和输入的前16字节比较，因此可以爆破这个4个字节，从而得到散列值和输入的前16字节

一个go的程序，不过有一个超长时间的sleep函数，patch后发现还是很慢，仔细逆向逻辑后发现，程序的是取了32个斐波那契数列的项，但是有些项数太大了，导致后面运行生成时间非常久。因此可以试着优化一下这个逻辑。



值得注意的是这个并不是普通的斐波那契数列，而是其值还要再取16的余数，这个个人感觉值肯定会收敛至1，由于斐波那契数列的特点，这样就会导致这个取余的斐波那契数列是一个循环数列。通过验证发现这个数列为24项重复。

那么后面的工作就简单了，因为有32个数作为这个数列的项数，因此对这32个数进行24取余即可，随后获得了数列的32个值，再将这32个值作为"0123456789abcdef"的索引即可获得flag。


import mathimport numpyimport string# 斐波那契数列通项公式def GetFib(n):    denominator = math.sqrt(5)    return int((numpy.power((1+denominator)/2, n) - numpy.power((1-denominator)/2, n)) / denominator) % 16def GetFibIdxs():    res = []    v1 = 1    for i in range(32):        res.append(v1 % 24)        v1 = i + 4 * v1 + 1    return respos_ls = GetFibIdxs()series = [GetFib(i) for i in range(24)]lower_hex = string.hexdigits[:-6]print(''.join([lower_hex[series[pos_ls[i]]] for i in range(32)])) # 15f559713195b57dd1f9b91d3df55971
