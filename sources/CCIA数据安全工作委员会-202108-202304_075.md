条款理解：

***《数据安全法》第二十七条****：开展数据处理活动应当依照法律、法规的规定，建立健全全流程数据安全管理制度，组织开展数据安全教育培训，采取相应的技术措施和其他必要措施，保障数据安全。利用互联网等信息网络开展数据处理活动，应当在网络安全等级保护制度的基础上，履行上述数据安全保护义务。*

  

组织战略上重视、全员参与和意识的提升、技术的加持是企业数据安全治理的基础和关键。此外，应通过覆盖数据处理全流程的完善的数据安全内部治理体系，通过丰富的、体系化的数据安全治理活动和措施，保障数据安全治理的落地性、实用性和先进性。

  

随着各类互联网业务对数据需求的加剧，面临安全的新态势、新要求，传统技术手段已经无法适应新新形势下数据安全需要，创新的技术方案成为解决数据安全与数据开发利用矛盾的破解之道。近年来，“可算不可识”等相关技术承载了数据利用在合规和发展两个主题的诸多希望，特别是面向大规模数据批量计算的场景，需要采用安全可控的技术措施和机制，确保大规模计算场景的全流程数据安全。

实施经验/案例

**领域1：金融**

**主题1：数据安全复合治理案例**

  

当前，数据作为生产要素受到高度关注，作为企业面临的数据安全和隐私保护形势也发生了较大变化。伴随着数据安全法等法律法规陆续颁布，用户隐私保护意识不断增强，数据安全的重要性愈发凸显，各企业对数据安全的重视度和投入度都在持续增加，但是数据本身具有容易复制、扩散和流转的特性，同时业务场景的多样性、安全风险的复杂性，都对企业的数据安全治理能力提出了更高的要求。为此，蚂蚁集团在过去几年的数据安全实践中，总结了一套目前来看在新形势下能够有效落地、覆盖数据全生命周期安全的数据安全复合治理模式。

  

数据安全复合治理模式强调系统性、落地性，在治理体系设计中注重对战略、管理和技术的统筹规划，强化治理过程安全与业务复合、管理与技术复合联动效能。模式特点概括为战略要位、实战牵引、全员参与、技术破局。如下图所示：

  

（1）战略要位：从战略高度明确数据安全对于组织生存发展的重要意义，完善数据安全顶层设计，包括安全方针、制度规范、组织机构、保障体系等的建立和完善。

（2）实战牵引：通过实战化红蓝对抗、风险治理和管控效果的精确度量来牵引整体治理工作落地。

（3）全员参与：通过丰富、活泼的心智运营活动设计，充分调动全员主动参与积极性，实现不同特点人群的精确触达。

（4）技术破局：依托系统、算法、数据和产品方面的科技能力创新，实现新形势下无法通过人工、协议达成数据安全治理目标难题的破局，促进数据安全治理工作的提质增效。

**领域2：不限**

**主题2：多源数据融合计算安全解决方案**

  

目前大部分企业均使用大规模数据处理计算引擎处理海量数据，如何保障大规模数据处理过程的安全性就成为了重中之重。蚂蚁集团基于法律法规要求和自身实际安全管控需求，研发了多源数据融合计算安全解决方案体系，如图2所示，通过数据流入，安全受控计算和流出安全管控，保障大规模多源数据计算过程安全可控，其中：

  

（1）数据流入管控：在数据流入环节，基于数据分类分级采用去标识化，泛化降级、脱敏等安全加固措施，确保流入的数据符合相应安全标准，基于数据资产业务标签、敏感性、数据血缘等提供自动化的审批策略机制，在提升管控效能的同时保障数据流入安全。

  

（2）安全受控计算区：在数据计算环节，安全受控计算区对流入的数据进行统一加密存储，并采用存储隔离、TEE等技术措施确保数据安全，同时建立人员和应用程序的访问权限控制机制，对数据非法访问进行识别和实时阻断，确保未审批场景和应用程序无法访问安全受控区数据，同时对数据访问和操作行为风险进行监测分析，及时进行风险告警和风险处置，确保数据处理过程的安全可控。 

  

（3）数据流出安全：计算结果数据通过脱敏、加噪、行列级过滤等措施处理后，且经敏感数据扫描识别和策略化审批评估才能流出，并在流出环节部署异常流出监测，实时对流出异常行为进行拦截阻断。同时建立数据流出后的后链路流转管控能力，全链路追溯流出的数据流向和消费场景，确保在数据流出后同样安全可控。

条款理解：

***《数据安全法》第二十七条****：开展数据处理活动应当依照法律、法规的规定，建立健全全流程数据安全管理制度，组织开展数据安全教育培训，采取相应的技术措施和其他必要措施，保障数据安全。利用互联网等信息网络开展数据处理活动，应当在网络安全等级保护制度的基础上，履行上述数据安全保护义务。*

  

本条明确了数据安全保护义务的基本要求，要求数据处理者采取相应的技术措施和其他必要措施，保障数据安全。那么，应当采取哪些技术手段？《网络数据安全管理条例（征求意见稿）》承接《数据安全法》，对此做了进一步落实细化，在第九条明确要求：数据处理者应当采取备份、加密、访问控制等必要措施，保障数据免遭泄露、窃取、篡改、毁损、丢失、非法使用，应对数据安全事件，防范针对和利用数据的违法犯罪活动，维护数据的完整性、保密性、可用性。同时明确要求数据处理者应当使用密码对重要数据和核心数据进行保护。

**领域：金融**

**主题：基于金融保险业重要数据和个人信息保护方案**

某金融集团掌握海量保险用户个人信息和企业运营数据，由于信息系统环境复杂，涉及字段类型多、数据库种类多，涉及分库分表、存储过程、模糊查询等使用场景，待保护的数据量达到亿级。因此，迫切需要有效，快速的技术，实现敏感信息的统一集中保护，同步提升集团安全运维管理能力。

  

本项目满足《网络安全法》《数据安全法》《个人信息保护法》《密码法》等法律法规的合规要求，采用了加密和去标识化技术，在免开发改造应用系统的情况下，实现对个人信息以及企业商业数据的细粒度防护。项目在结合信息系统业务需求，在服务节点上分别部署加密模块，数据安全管理平台为加密模块执行点统一下发加解密策略、负责统一管理加解密所需的密钥，实现密钥全生命周期的管理，保障密钥的安全备份与恢复，从而完成集中的数据安全管理平台的建设，实现应用系统敏感数据的分布式加密，安全策略的集中式管控。

  

本项目实现批量系统的应用数据加密和审计需求，保护客户和员工个人数据安全、企业商业数据安全，提升系统安全水平。满足国家关于个人信息保护、商用密码信息系统密码应用规范要求，免开发改造应用系统，完成了医疗、人身、财险、养老等多个系统的敏感数据数据加密、审计等功能敏捷实施。

条款理解：

***《数据安全法》第二十一条****：国家建立数据分类分级保护制度，根据数据在经济社会发展中的重要程度，以及一旦遭到篡改、破坏、泄露或者非法获取、非法利用，对国家安全、公共利益或者个人、组织合法权益造成的危害程度，对数据实行分类分级保护。国家数据安全工作协调机制统筹协调有关部门制定重要数据目录，加强对重要数据的保护。*

*关系国家安全、国民经济命脉、重要民生、重大公共利益等数据属于国家核心数据，实行更加严格的管理制度。*

*各地区、各部门应当按照数据分类分级保护制度，确定本地区、本部门以及相关行业、领域的重要数据具体目录，对列入目录的数据进行重点保护。*

本条旨在指导数据的分级分类保护：

（1）目前已经有很多地方，行业制定了数据的分级分类地方标准和行业标准。例如《金融数据安全数据安全分级指南》。未来国家也要出台统一的数据安全分级分类标准。各行业、各企业也可以基于国家的标准进行扩展和完善。

  

（2）对于关键基础设施，重要民生等国家核心数据，会有更加严格的保护措施和标准进行管理。金融、能源、卫生等行业将会是重中之重。

  

（3）国家机关，敏感行业要确定自己的哪些数据是敏感数据，各行业应在本法的规制下分析本行业业务数据特征，制定数据分类分级标准和准则，并依据数据重要性程度建立数据资产清单，针对重要数据实施重点保护工作奠定基础

  

（4）对于这些敏感数据会有更加具体的保护措施，例如脱敏，加密，不允许上传至外网等。

实施经验/案例

**领域：能源**

**主题：某电力单位数据安全管理网关应用案例**

  

**需求分析：**

1）API对于某电力单位来说是黑盒子，对接口的调用、流量无感知。在对内外数据共享的过程中无法完成对于用户级的权限控制以及接口启停等控制性动作。

2）数据增值变现业务的流转接口无任何监控、审计及防护措施、

3）数据分级分类落地效果一般，需要根据清晰可落地的分类分级标准，进行统计分析与展示。

  

**方案概述：**

采用数据安全管理网关作为某电力单位信息大区API调用的统一出口，由数据安全管理网关完成与总部Dataworks的数据调用。

数据接口变现管理：通过数据安全管理网关及接口管理流程设计实现接口申请、申请审核、接口配置、接口审核、接口监测、接口统计、动态SQL配置等能力。

本次项目中部署的数据安全监测引擎对某单位总部接口日志进行数据采集和分析；

提供数据安全分类分级管理能力：实现标签规则管理、标签处理、标签展示、标签变更，并与标签中心对接实现统一标签规则的拉取。 

  

![](../Images/807aabb3b233a721345e3e6b5ebdd44f.png)

**业务价值：**

1）减少 API 数据泄露和攻击风险，提升某电力单位信息化安全，数字化下云化、移动化、微服务化场景下提升 API 安全；保护 API 资产暴露风险和数据安全。

2）实现端到端、端到云、云到端的全链路监控追踪体系，实现预测问题，定位问题，解决问题的一体化流程；建设应急响应体系，增强业务可用性。

3）统一外部应用调用入口，提供API鉴权、安全认证、流量控制、保证服务调用的合法性和服务的正常运行。

**领域：政务**

**主题：某市大数据局数据安全治理体系建设案例**

  

该实践案例借鉴 Gartner 数据安全治理（DSG）的思路，同时充分参考数据安全能力成熟度模型（GB/T 37988-2019）等相关规范，建设数据安全治理体系框架，包括数据安全组织体系建设服务、数据安全技术体系建设服务和数据安全  运营体系建设服务三大部分。

  

针对实际政务业务场景化安全需求，以“顶层设计、分步实施、积极防御、综合防范”为指导原则，以数据全生命周期为核心，从组织结构、管理规范、制  度流程、技术保障、项目实施等多方面，全面梳理城市大数据中心实际数据处理业务场景、网络传输环境、数据处理和存储环境，极大提升城市大数据中心数据安全防控能力，并通过健全的运营管理，确保整套数据安全管理体系安全可靠、持续优化。

  

![](../Images/5502f773aa5bd64b18e24fda6cd06248.png)

  

该案例建设效果达到 DSMM3 级充分定义的要求，助力某市大数据管理局拿下“全国首个政务场景 DSMM 三级认证”。帮助其形成层层设防，重点突出，策略联动，管理为上的防护能力，极大提升了用户数据安全管理水平。   

  

该案例构建的《基于 DSMM 国家标准的数据安全治理应用实践》，在信安标委 20 周年网络安全国家标准优秀实践案例评选中斩获“一等奖”。

  
 该案例的落地，支撑相关系统通过了等保三级、密评等测评认证工作，对于满足《数据安全法》第四章 数据安全保护义务中第二十七条的要求提供了强有力的支撑。

条款理解：

***《数据安全法》第七条****：国家保护个人、组织与数据有关的权益，鼓励数据依法合理有效利用，保障数据依法有序自由流动，促进以数据为关键要素的数字经济发展。*

  

《数据安全法》第七条提出了国家鼓励数据依法合理有效利用，保障数据依法有序自由流动的权益，即在高度重视数据安全的前提下，也要获取数据合理利用带来的价值，充分发挥数据作为关键要素的作用机制。数据的依法有序自由流动涉及数据处理的各个阶段，包括数据的收集、存储、使用、加工、传输、提供、公开等，各个阶段构成了数据活动的全生命周期，维护数据安全就是要维护数据从产生到销毁的全生命周期各项处理活动的安全性，因此，维护数据安全与促进数据开发利用是相辅相成、互相促进的关系，通过开展数据安全治理能够为数据开发利用提供安全基础保障，进而保障公民个人信息、组织的合法权益以及国家安全，助力我国数字经济发展。

实施经验/案例

**领域：电信**

**主题：敏捷数据管理平台（ADM）应用案例**

  

上讯敏捷数据管理平台ADM产品是一款企业级CDM产品，通过以数据为中心，以安全为前提，以使用为导向，以敏捷为目的的产品理念，为企业提供一套面向上中下游数据高效使用与安全管控的数据安全治理解决方案，在保证数据安全使用的同时，提高数据使用效率、降低数据存储成本。

  

ADM产品对数据全生命周期的管理主要基于专有的数据虚拟化技术，在数据收集和使用上，通过获取一份具有应用一致性保证的“黄金副本”，分钟级虚拟化为多个副本直接挂载使用，数据使用效率明显得到提升；在数据存储和传输上，这些虚拟数据副本相对原始存储几乎不占用存储空间（约为0），且ADM产品将全部数据集中存放在统一的存储池中，既保证了数据传输流转的闭环管控，又大大降低了数据的存储成本；在数据加工上，数据脱离生产环境之前增设了数据脱敏环节，保障数据公开后的隐私安全，防止核心数据泄露；在数据的提供和公开上，虚拟数据副本可用于准生产、测试环境等场景的数据交付，每一份虚拟数据都是独立的，并且可读可写，数据在经过变更后可标记快照，多个快照之间可以任意切换实现数据版本的管理。

  

ADM产品的应用解决了数据开发利用需求下，数据使用流转环节遇到的安全性和效率问题。
