# 本文为广东省电力行业信息安全实验室授权发布，所分析的是刚刚发生的一件典型网络攻击迫使工厂停工事件，所用方式是已为人熟知的“勒索软件”攻击。事件发生后，实验室积极作为，第一时间进行研究分析，从事件概述、影响范围、原因分析、勒索软件、主要启示等方面作出研判，值得我们学习参考，以未雨绸缪的前瞻性和时不我待的紧迫感，积极做好应对工作。

  

# **一、事件概况**

  

据媒体报道：当地时间3月18日，挪威海德鲁公司（NorskHydro）的多个系统遭到严重的勒索软件攻击，被迫关闭位于欧洲和美国的多家工厂，不得不使用手动生产流程运营冶炼厂。在3月19日的新闻发布会上，海德鲁公司首席财务官Ifo Kallevik透露，公司系统遭到勒索软件袭击，多个商业领域IT系统受到影响，尚不清楚此次攻击的幕后黑手\[5\]。3月20日，在外部力量支持下，Hydro技术团队成功发现了问题的根本原因，正在逐步恢复和重启公司IT系统，然而，仍不清楚恢复稳定的IT运作可能需要多长时间\[2\]。

此次攻击事件初始感染发生在该公司的美国业务区，但很快就扩散到了公司全球的业务系统中，导致该公司全球业务网络宕机，且生产和办公网也受到了影响。据该公司安全小组透露，攻击发生时，该公司的全球网络出现了一些不寻常活动，袭击规模很大；勒索软件是为加密文件而设计，但是尚不能确定属于哪个恶意软件家族。发现问题后，安全人员隔离了所有工厂和操作，并切换到手动操作程序，以确保系统安全运行，减少对生产业务和公司财务系统的影响\[2\]\[3\]。

# **二、事件影响范围**

#   

# 影响范围：欧洲和美国大多数商业领域的IT系统业务,多家工厂停止运营，如挤压工厂-被迫暂时关闭\[4\]。

# 关于Hydro公司系统运作状况的最新情况

# 能源：生产正常运行

# 铝土矿和氧化铝：生产正常运行

# 原生金属：生产正常运行，手工操作程度高。

# 挤压溶液剂：无法与生产系统连通，造成了一些工厂的暂时停产，预计在周三重新启动某些系统。

# 轧制产品：无法与生产系统连通，已造成有限的操作影响，预计在周三重新启动某些系统。

# 总结：什么时间才能全面恢复正常运作，Hydro公司仍然无法掌握，现在评估具体的业务和财务影响还为时尚早\[2\]。

  

# **三、事件原因初步分析**

  

根据挪威当地媒体发布的最新消息，此次事件是因为Hydro系统感染了LockGoga勒索病毒，进而导致大多数文件加密。但是目前尚未查明Hydro公司感染LockGoga勒索病毒的原因\[1\]。

Nozomi网络实验室表示：恶意软件无法传播到其他目标。它似乎实现了一些反分析技术，以躲避分析人员。例如，它似乎检测到虚拟机的存在，并能够将自己从文件系统中删除，以避免样本收集。一些研究表明(Nozomi网络实验室尚未证实)，攻击者是利用了Active Directory作为传播恶意软件的机制，可能的推测是这样：注册在域管理组中的目标系统之所以能够被感染，可能是因为攻击者已经将恶意可执行文件放置在了Netlogon目录中，以便能够自动传播到每个域控制器(许多防火墙默认接受Active Directory)，对此，NorCERT予以证实\[1\]。

  

# **四、LockerGoga勒索软件**

  

（一）LockerGoga勒索软件特点

LockerGoga勒索病毒对受害者的重要数据进行加密，需支付赎金后才能对被加密数据进行恢复。LockerGoga可加密的数据类型包括：doc、dot、wbk、docx、dotx、docb、xlm、xlsx、xltx、xlsb、xlw、ppt、pot、pps、pptx、potx、ppsx、sldx和pdf等。据Nozomi网络实验室分析\[1\]，该恶意软件采用了多种高级手段来对抗分析，包括虚拟机检测、文件自删除等。

（二）LockerGoga的工作原理

LockerGoga勒索软件对特定扩展名的文件进行加密，加密文件时，将追加.locked锁定加密文件名的扩展名。例如，名为test.jpg的文件被加密后，重命名为test.jpg.locked，如下图1所示\[6\]。

**五、启示**  

  

针对本次攻击事件，经通报中心研判分析，紧急解决方案如下：

1. 针对个人用户：

1）不点击来源不明的邮件附件。

2）不使用外挂、破解补丁等容易传播病毒的软件。

3）保证安全软件一直处于运行状态，及时修复系统漏洞，实时拦截病毒风险。

2.针对企业用户

1）尽量关闭不必要的端口，如：445、135，139等，对3389端口可进行白名单配置，只允许白名单内的IP连接登陆。

2）尽量关闭不必要的文件共享，如有需要，请使用ACL和强密码保护来限制访问权限，禁用对共享文件夹的匿名访问。

3）采用高强度的密码，避免使用弱口令密码，并定期更换密码。建议服务器密码使用高强度且无规律密码，并且强制要求每个服务器使用不同密码管理。

4）对没有互联需求的服务器/工作站内部访问设置相应控制，避免可连外网服务器被攻击后作为跳板进一步攻击其他服务器。

5）对重要文件和数据（数据库等数据）进行定期非本地备份。

6）在终端/服务器部署专业安全防护软件。

3.网络防护与安全监测

1）对内网安全域进行合理划分。各个安全域之间限制严格的 ACL，限制横向移动的范围。

2）重要业务系统及核心数据库应当设置独立的安全区域并做好区域边界的安全防御，严格限制重要区域的访问权限并关闭telnet、snmp等不必要、不安全的服务。

3）在网络内架设 IDS/IPS 设备，及时发现、阻断内网的横向移动行为。

4）在网络内架设全流量记录设备，以及发现内网的横向移动行为，并为追踪溯源提供良好的基础。

4.应用系统防护及数据备份

1）应用系统层面，需要对应用系统进行安全渗透测试与加固，保障应用系统自身安全可控。

2）对业务系统及数据进行及时备份，并验证备份系统及备份数据的可用性。

3）建立安全灾备预案，一但核心系统遭受攻击，需要确保备份业务系统可以立即启用；同时，需要做好备份系统与主系统的安全隔离工作，辟免主系统和备份系统同时被攻击，影响业务连续性。
