# Wordpress file manager插件任意文件上传

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzUzNDYxOTA1NA==&mid=2247500685&idx=6&sn=7994e36431fc7e28bf63aa9abaa9d222&chksm=fa93754ccde4fc5a2510818527d948ea57fb34b2dc014f25233c39899d43ee05e25b487f77c6&scene=126&sessionid=1681365373#rd](http://mp.weixin.qq.com/s?__biz=MzUzNDYxOTA1NA==&mid=2247500685&idx=6&sn=7994e36431fc7e28bf63aa9abaa9d222&chksm=fa93754ccde4fc5a2510818527d948ea57fb34b2dc014f25233c39899d43ee05e25b487f77c6&scene=126&sessionid=1681365373#rd)

> 近日，Wordpress 插件file manager被爆出严重0day漏洞，本着技术研究角度，和大家分享、探讨其漏洞原因。

该修复程序已在同一天发布，并且WP File Manager插件6.9版通过删除允许未经授权的文件上传访问的端点来解决当前问题。影响版本。该安全漏洞存在于文件管理器版本，范围从6.0到6.8。WordPress的统计数据表明，目前约有52％的安装易受攻击。由于File Manager的700,000个站点中已安装的漏洞中有一半以上，因此损坏的可能性很高。运行任何这些版本的网站都应尽快更新到6.9

### **影响范围**  

file manager 6.0至6.8

### **漏洞报告**

漏洞的文件为connector.minimal.php.  
首先对`$opts`进行了初始化，这里存储了后面上传文件存储路径root信息。通过创建`elFinderConnector`对象，进而调用`$connector->run();`。

### **elFinderConnector::run()**

![](../Images/e1f3c82bb38dbf1cedffc037766d8b44.png)

方法限制了请求为POST。并且读取了所有的请求参数保存到`$src`中。其中`$cmd`为传递`cmd`变量

![](../Images/24f6fe7d4ab92484ecc8df6d0bb023a5.png)

随后对通过循环`foreach ($this->elFinder->commandArgsList($cmd) as $name => $req)`来对`$src`进行校验，需要符合请求方法的参数类型。

通过`elFinder::commandArgsList($cmd)`中我们查看`$this->commands`发现了可以调用的方法（意味着我们可以直接调用以下列表的所有方法，例如创建文件、创建文件夹、删除文件等等）

### **elFinder::exec(\\$cmd, \\$args)**

当我们控制`$cmd=upload`时，遇到第一个分支。意味着我们需要传入一个`$target`变量或`$dst`变量。

![](../Images/f840490c784ed322f8af08f556d1b62c.png)

进入`$this->volume($dst)`可以看到是对`$this-volume`进行了选择。`id`分别为`t1_`和`l1_`，我们将选择`l1_`，即传入的`$target`必定为`l1_`前缀。之所以这么做的理由是由于`l1_`中的`root=/Users/steven/Desktop/code/phpCode/wordpress/wp-content/plugins/wp-file-manager/lib/files`，而`t1_`中为`root=/Users/steven/Desktop/code/phpCode/wordpress/wp-content/plugins/wp-file-manager/lib/files/.trash`。而这个`$root`将会成为后面文件上传路径的前缀。

![](../Images/65ef587097f762a7f9692e2017f6c210.png)

![](../Images/2e3af3151e8b37840d5bd5220df30906.png)![](../Images/167912d5d6190046ebc7262db3262dfe.png)之后进入动态调用，通过`$result = $this->$cmd($args);`调用upload方法。![](../Images/1a9a45eb4a093a52c0e04e91b1de6c61.png)

### **elFinder::upload(\\$args)**

一开始初始化很多变量，但是我们不必要传入。并且也对volume进行了取值，后续还进行了校验。

![](../Images/5ee4ede1e4785ddbe4ff9dc36b8b8e48.png)

在3313行`foreach ($files['name'] as $i => $name)`通过foreach对每个上传的文件进行处理。

![](../Images/45215442f09324cd14f585ed81025197.png)

许多分支并没有执行，直接来到以下代码`if (!$_target || ($file = $volume->upload($fp, $_target, $name, $tmpname, ($_target === $target) ? $hashes : array())) === false)`，执行真正的upload函数。

![](../Images/b88dc4a2bd3ad7253bd9f41da952cfb7.png)

![](../Images/73d3032efcfbe858f75426b9c0383534.png)从上面的代码看来就是把`$target`的值截取前面volume的id，剩下的做一个base64解码，之后与`volume['root']`进行拼接，如果解码之后的值为`\\`则直接设`volume['root']`为上传路径，如果不是则需要cache索引。如果直接`$target`解码为`../`或`../css`等则会校验不通过，直接报错。最终调用到`if (($path = $this->saveCE($fp, $dstpath, $name, $stat)) == false)`实现了文件的上传。上传路径为`wp-content/plugins/wp-file-manager/lib/files/bzj.php`
