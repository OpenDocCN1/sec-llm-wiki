1.引言

2019年12月以来，我国发生了新型冠状病毒肺炎疫情，在本次疫情阻击战中，基于5G技术的远程诊疗平台发挥了极其重要的作用。在抗击疫情过程中，钟南山院士等众多医疗专家通过远程诊疗平台分析危重病人的CT(Computed Tomography)影像，来救治危重病人。在有限的医疗资源状况下，医院远程的会诊就显得弥足珍贵，成为了传统就诊形式的有效补充，给医院各科室之间协同配合和患者就医带来了极大的便利。在远程会诊中，大量的医疗数据在网络上传输，对医院的整体网络安全和数据安全水平带来了极大的挑战。

DICOM(Digital Imaging and Communications in Medicine)即医学数字成像和通信，是医学图像和相关信息的国际标准（ISO 12052），是所有医学影像技术的基础，它定义了质量能满足临床需要的可用于数据交换的医学图像格式，广泛应用于各式各样的仪器和软件厂商。从概念上理解，DICOM主要包含两方面的内容，一个是进行通信，一个是服务的对象是医学图像，也就是说DICOM可以理解为进行医学数字图像交流的格式。DICOM被广泛应用于放射医疗，包括心血管成像以及放射诊疗诊断设备（X射线，CT，核磁共振，超声等）等。DICOM协议很好地解决了如何将病人的信息与医学图像进行关联这一问题，所以在日常的会诊和远程就诊时，大量基于DICOM协议的数据被流转于医院的网络中，这些数据携带了大量的个人隐私信息和临床诊断数据，价值巨大，一旦泄露或被窃取，会给个人和社会带来很大的损失。但是，由于DICOM在设计之初并未考虑通信安全性，且在医疗设备的数字化和信息化过程中引入了大量的网络安全威胁和隐患，使得医疗设备本身容易被攻击，且设备和网络中的医疗影像数据极易被黑客窃取。自2008年以来，相关医疗设备先后暴露了大量的安全漏洞和攻击事件，如远程攻击心脏起搏器、胰岛素泵、蓝牙除颤器、X光机等，这些都对患者造成了严重的伤害和巨大的损失。**同时我国的医疗器械网络安全形势也不容乐观，以2019年为例，相关技术人员统计发现全年医疗影像数据出境212万余次，其中包含了大量的个人敏感信息**，很大部分的敏感信息被医疗影像数据携带传输出境，这其中少部分主动传输，大部分是被动流向境外的。

因此面对日益增长的安全威胁和挑战，亟需针对医疗设备的安全问题展开研究，挖掘并修复协议本身存在的安全漏洞，防止核心数据被窃取。针对DICOM库的安全问题，**本文基于Peach工具对DICOM开源库开展漏洞挖掘研究，选择开放源码库DCMTK进行测试。**

2.简介

**2.1**Peach简介

模糊测试（Fuzzing），是一种通过向目标系统提供非预期的输入并监视异常结果来发现软件漏洞的方法。Peach就是一种基于Fuzzing技术的漏洞挖掘工具，它由Deja vu Security公司的Michael Eddington创造并开发，主要开发工作已经有7年了，主要有3个版本，最初采用Python语言编写，发布于2004年，第二版于2007年发布，Peach 3发布于2013年初，第三版使用C语言重写了整个框架。Peach是一款智能模糊测试器（SmartFuzzer），它有两种模糊测试能力：基于生长的模糊测试和基于变异的模糊测试。Peach需要创建一些PeachPits文件，该文件定义了被模糊测试数据中的结构、类型信息和相互关系。此外，它允许为进行中的模糊测试进行配置，包含选择一个数据通道（Publisher）和登录接口等。Peach Fuzz其实是一种黑盒测试方法，通过发送大量的随机数据到被测试系统，再结合监视器，检测系统的运行状态，来发现被测试系统或进程中，可能存在的安全问题。

**Peach具有如下7个模块：**

**( 1 ) Modeling**\---Peach通过提供数据模型和状态模型的Fuzzing来实现操作。数据模型和状态模型是Peach的重点。对于普通的Peach用户来说，这是最花费时间的。模型中的细节水平区分了盲模糊测试和智能模糊测试。

**( 2 ) Publisher**\---它是I/O接口，描述了输入、输出和调用等抽象概念。正如在状态模型中看到的，它提供了真实的通道或实现。Peach包含有许多的Publisher，它提供了许多能力，比如写文件、通过TCP/UDP或者其他协议连接、构造web请求，甚至是调用com对象。创建自定义的Publisher是非常容易的。

**( 3 ) Fuzzing策略**\---Fuzzing策略是如何进行Fuzzing的逻辑。比如，在同一时刻，我们要修改一个还是多个数据元素？我们使用哪个变异器？是不是要修改模型部分比其他部分多？是否要修改状态模型？Fuzzing策略唯一不能做的是产生真实的数据，这部分是由变异器实现的。Peach包含的一些Fuzzing策略对于大部分使用者来说是非常重要的。

**( 4 ) 变异器**\---变异器用于产生数据。它通过修改存在的默认数据值来产生新的数据。变异器常常包含一个简单的逻辑，进而完成一个简单的变异类型。比如，产生-50到50之间的数据，或者产生1到10000长度的字符串，或者产生0到32之间的500个随机数。

**( 5 ) 代理**\---代理是特殊的peach进程，它能够在本地或者远程运行，拥有一个或者多个监视器或者远程Publisher。代理是Peach框架提供的具有健壮性的基础监视设备，它允许通过一个有许多层级的复杂系统来监视简单的Fuzzing配置。一个Peach fuzzer可拥有0个或者多个代理。

**( 6 ) 监视器**\---监视器运行在Peach代理进行中，它用来执行通用的任务，比如在Fuzzing迭代中捕获网络流量、把调试器挂载到一个进程上来探测软件崩溃、网络服务崩溃或者停止时重启它。Peach包含许多监视器，添加新的监视器并编辑它是非常容易的。

**( 7 ) 记录器**\---用来保存崩溃和Fuzzing运行信息，Peach默认拥有一个文件系统记录器。

**2.2**DICOM简介

DICOM的定义前面已经给出，它是一个在不同的计算机之间传输医学影像的国际标准和传输格式。它基于网络技术（TCP/IP协议），可以在局域网（LAN）或广域网（WAN）内工作。DICOM早期的版本是ACR-NEMA，定义于1980年左右，主要定义点对点（Point-to-Point）传输方式。DICOM发展的主要目的是为了要让医院中各色各样的医学影像仪器和软体间能够有一个共通的语言，以塑造一个无国界、无障碍的电脑化医学影像环境。DICOM发展历程如图2.3所示。

**3.Peach针对DICOM漏洞挖掘流程**

本文我们将对DICOM的三大开源库之一——DCMTK进行Fuzzing测试。

**3.1**构造测试用例

首先我们了解一下Peach的测试用例的生成。测试用例的生成方式主要有2种：

**( 1 ) 基于生成的自动化随机构造**

此构造策略采用Fuzzing测试的思想，构造随机的DICOM数据包作为输入，使用随机函数，任意改变此数据包的任意值，亦可采用循环修改的方式，将此二进制DICOM数据包的任意位修改。此种生成策略可以让计算机构造出大量的随机数据包，其优点在于成本低、自动化程度高，并可以发掘很多意料之外的漏洞，但此方法构造的畸形数据包大多是无效的，会被待测试的设备遗弃，导致最终测试过程的效率不高。

**( 2 ) 基于变异的分析构造**

基于变异的分析构造这种策略相对于随机构造有更强的目的性和针对性。根据已有的漏洞分析，大部分漏洞都容易出现在边界值上，例如，要输入的值大于系统设定的最大值。将此思想应用到构造数据包中，推测将DICOM数据包中的某一个字节置为边界值，可能会导致触发漏洞。

**我们再来了解一下DICOM的格式。**

DICOM格式包含关于患者的 PHI（protected health information，https://en.wikipedia.org/wiki/Protected\_health\_information）信息，例如姓名，性别，年龄，以及其他图像相关信息比如捕获并生成图像的设备信息，医疗的一些上下文相关信息等。医学图像设备生成 DICOM 文件，医生使用 DICOM 阅读器（能够显示 DICOM 图像的计算机软件）阅读并对图像中发现的问题进行诊断。DICOM文件是指按照DICOM标准而存储的医学文件，一般由一个DICOM文件头和一个DICOM数据集合组成，结构图如图3.1所示。

![](../Images/42d720ab38c38535eb175ae570e4d143.png)

图3.1 DICOM结构图

文件导言，由128个字节组成；DICOM前缀，可根据这长为4个字节的字符串是否等于“DICM”来判断该文件是不是DICOM文件。

**DICOM文件的主要组成部分是数据集。**包括：

**( 1 ) 标签Tag：**一个16位的无符号整数的有序对，前8位表示组号，后8位表示元素号。

**( 2 ) 值表示：**指明该数据元素中的数据类型。

**( 3 ) 值长度：**一个16位或者32位的无符号整数，表示了数据域的长度。

**( 4 ) 数据域：**存在这个字段的值的数据类型由这个数据元素的值表示决定，且它的存储长度为偶数个字节。

4．结束语

使用Fuzzing技术挖掘漏洞的方法不失为对DCIOM协议漏洞挖掘的有益尝试。尤其是在当下网络安全特别是医疗领域安全状况日益严峻的形势下，对DICOM协议进行的漏洞挖掘结果能为医疗设备开发者提供参考，并在一定程度上能降低DICOM协议可能存在的安全风险。当前，人工智能技术发展迅猛，其中在大数据生成和使用的过程中都极大提高了工作效率，尤其是生成对抗网络在大数据方面的应用效果让人欣喜，接下来将继续完善和改进实验方法，进一步结合生成对抗网络对测试用例构造、筛选和测试进行优化改造，继续发掘DICOM协议中存在的安全漏洞。**网络安全是个不断发展的领域，面对越来越复杂的针对医疗设备的攻击，必须要不断进行对漏洞的挖掘和对设备的维护，才能领先大多数攻击一步，推动医疗安全的发展。**
