一. 背景

随着科技时代的发展，物联网（IOT）设备正在快速的在各行业发展，推动产业升级以及智能化时代的到来，但是其安全性显得尤为重要，对于安全研究以及提高防护提出了行的要求。物联网安全涉及众多方面，下面我们将分享固件提取技术——解决在uboot模式下无法正确获取数据问题。

三. 相关知识点

ABootLoader

简单来说，BootLoader 是一小段程序，他在系统上电时开始执行，初始化硬件设备、准备好软件环境，最后调用操作系统内核。

Bootloader首先运行，然后将内核文件从NAND FLASHZ中复制到内存中，并将设置好的参数传递给内核，运行内核。

BootLoader 将FLASH 上压缩的文件解压后再运行。（对FLASH中存放的kernel、文件系统进行特定的解密，这一点对以后破解固件至关重要）。

BLinux 内核

挂载跟文件系统

C文件系统

包括跟文件系统和建立于Flash内存设备至上的文件系统。里面包含了Linux系统能够运行所必需的的应用程序、库等。(系统中的应用程序是漏洞分析与挖掘的对象)

ENAND Flash介绍：K9F2G08U0A型号

i. nand flash 地址机制(很重要)：

1. NandFlash的存储单元是由Block组成的，Block又是由Page组成的，数据就是存储在Page上。

2. NandFlash是以页（Page）为最小单位进行读写的。

3. 查看K9F2G08U0A datasheet中关于地址周期的介绍：

由上图可以看出，K9F2G08U0A是用5个周期来实现，由于NAND flash以页为单位读写数据，而以块为单位擦除数据，则可以分为三类地址：

  • Column Address：列地址，地址的低8位 即页内偏移地址

  • Page Address ：页地址

  • Block Address ：块地址

以0xBB8CCB8地址为例，地址传递过程需要五个地址周期：

0xBB8CCB8 = 00001011  1011 1000  1100 1100  1011 1000

  • 第一个周期：A[0:7]也就是B8

  • 第二个周期：A[8:11]取四位1100， 再添4位0，也就是0000 1100   即0C

  • 第三个周期：A[12:19]取八位1000 1100 即8C

  • 第四个周期：A[20:27]取八位1011 1011 即BB

  • 第五个周期：A[28]取一位 0，补齐八位即 0000 0000 也就是00

再往回分析，NandFlash收到前两个周期的地址A[0:11] 也就是0CB8，即1100 1011 1000，分析：A[10:0]=100 1011 1000=1208， 表示第1208个Byte

ii. nand flash 读取指令

1. 查看K9F2G08U0A 手册

2. 根据K9F2G08U0A 地址周期及Read命令，写以下读取nand flash数据代码：

void nand_select(void){  /*使能片选*/  NFCONT &=~(1<<1);}void nand_deselect(void){  /*禁止片选*/  NFCONT |= (1<<1);}void nand_cmd(unsigned char cmd){  volatile int i;  NFCCMD = cmd;  for(i=0; i<10; i++);}void nand_addr_byte(unsigned char addr){  volatile int i;  NFADDR = addr;  for(i=0; i<10; i++);}unsigned char nand_data(void){  return  NFDATA;}void wait_ready(void){  while (!(NFSTAT & 1));}void nand_read(unsigned int addr, unsigned char *buf, unsigned int len){  int i = 0;  int page = addr / 2048;  int col  = addr & (2048 - 1);  nand_select();//选择芯片  while (i < len){    /* 发出00h命令 */    nand_cmd(00);    /* 发出地址 */    /* col addr */    nand_addr_byte(col & 0xff);    nand_addr_byte((col>>8) & 0xff);    /* row/page addr */    nand_addr_byte(page & 0xff);    nand_addr_byte((page>>8) & 0xff);    nand_addr_byte((page>>16) & 0xff);    /* 发出30h命令 */    nand_cmd(0x30);    /* 等待就绪 */    wait_ready();    /* 读数据 */    for (; (col < 2048) && (i < len); col++){      buf[i++] = nand_data();          }    if (i == len){      break;    }    col = 0;    page++;  }  nand_deselect();  }
四. 从nand flash提取数据的两种方法

A常规方法——通过uboot模式提取数据

进入uboot模式，通过nand read命令将想要的数据读到内存中，然后dump内存

B非常规方法——通过芯片操作指令，直接对nand flash发送命令读取数据

将NAND FLASH中数据读到内存中时，有ECC校验，判断数据是否正确；当所读取的数据中有坏块时，则无法成功读取数据到内存，就无法通过uboot模式提取数据。

五. 提取BootLoader分区数据(有坏块)

A常规方法：通过uboot模式提取数据

i. 进入进入uboot模式，help查看命令

系统启动时，按空格键，进入uboot模式

ii. mtdpart 查看分区

可以看出，nandflash有四个分区，并能计算其每个分区的大小。

iii. 使用nand read 命令读取bootloader分区数据到内存

根据提示信息可以知道因为存在坏块原因导致读取失败。

Bbootloader分区数据存在坏块，采用非常规方法提取数据

i. OpenOCD连接到目标设备，开启4444端口

ii. 根据nand flash 的指令和地址周期特性(5个周期)，写以下脚本，单字节读取数据：

#!/usr/bin/env rubyrequire 'net/telnet'# NFCONF    __REG(0x4E000000)  //NAND flash configuration             # NFCONT    __REG(0x4E000004)  //NAND flash control                   # NFCCMD    __REG_BYTE(0x4E000008)  //NAND flash command                   # NFADDR    __REG_BYTE(0x4E00000C)  //NAND flash address  # NFDATA    __REG_BYTE(0x4E000010)  //NAND flash datadebug = Net::Telnet::new("Host" => "localhost", "Port" => 4444)dumpfile = File.open("dump_bootloader.bin", "a+")debug.cmd("halt")debug.cmd("mww 0x4E000004  1")debug.cmd("mwb 0x4E000008 0x00")   #指令debug.cmd("mwb 0x4E00000C 0x00")   #5个地址周期debug.cmd("mwb 0x4E00000C 0x00")debug.cmd("mwb 0x4E00000C 0x00")debug.cmd("mwb 0x4E00000C 0x00")debug.cmd("mwb 0x4E00000C 0x00")debug.cmd("mwb 0x4E000008 0x30")   #指令$i = 0$num = 0x1000while $i < $num  do  response =debug.cmd("mdb 0x4E000010 1")    #读取1 byte  value = response.match(/0x4e000010: ([0-9a-fA-F]{2})/)[1].hex  dumpfile.write([value].pack("c"))  $i +=1end;dumpfile.closedebug.close

iii. 通过脚本获取到 有坏块 分区的数据，与 nand dump 0 查看到的数据作对比

1. nand dump 0 数据

2. 脚本读取的固件 dump_bootloader.bin

通过对比可知，在0x125位置，dump_bootloader.bin中的数据多了一字节0D,因此通过nand read命令读取无法通过校验。

在有坏块的情况下，成功获取bootloader分区数据，说明通过芯片指令操作获取数据的方法是可行的。

六. 提取kernel分区数据

A将kernel分区数据读入内存 0地址处

nand read.jffs2 0 kernel

使用脚本，从内存中dump kernel分区数据

#!/usr/bin/env rubyrequire 'net/telnet'debug = Net::Telnet::new("Host" => "localhost", "Port" => 4444)debug.cmd("halt")debug.cmd("dump_image dump_kernel_part.bin 0x0 0x200000")debug.close

查看读取的数据

可以看到，在0x1000之后的数据都不正确。

原因：

这是因为片内内存只有4k，所以不能将超过4k 的数据 读取到 0 地址处

解决方法：

将kernel 分区数据读到闪存sdram中，sdram 的起始地址 0x30000000 （查手册）

B将kernel分区数据读入内存 sdram 的起始地址处

nand read.jffs2 0x30000000 kernel

使用脚本，从内存中dump kernel分区数据

require 'net/telnet'debug = Net::Telnet::new("Host" => "localhost", "Port" => 4444)debug.cmd("halt")debug.cmd("dump_image dump_kernel.bin 0x30000000 0x200000")debug.close

查看读取的数据
