在我们使用cobaltstrike的过程中，会涉及到二次开发，从而使其功能上更加的健壮，不至于碰到杀软就软了的地步，本文从cobaltstrike的快速反编译到二次开发环境的准备作为二次开发cobaltstrike的起步。

IntelliJ IDEA自带了一个反编译java的工具，有时候我们需要对cobaltstrike的整个jar包进行反编译，使用这个IntelliJ IDEA双击之类的反编译时要是对整个源码层面进行搜索并不是很方便，可使用其自带的反编译工具，可以做到批量的整个反编译。

**二、****CobaltStrike二次开发环境******

打开 IntelliJ IDEA 选择Create New Project一直选择Next。

![](../Images/494098f3e556c094b4f8f6effcce3a5d.png)

这里选择路径跟起个名。

![](../Images/1dd201f1bbe882b970c1f5096c438ae5.png)

创建好后需要先建立两个文件夹，右击选择New Directory建立一个decompiled\_src文件夹，之后再建立一个lib文件夹。

![](../Images/ceeac5f521ad9ebf682b101b9385da26.png)

把在CSTips001中反编译好的CobaltStrike复制到decompiled\_src中，然后把它解压出来，可看到一个完整的反编译后的目录。

![](../Images/731bdf3dc11e8c040a6d2b1e3f42aeab.png)

随后把原始的未编译的CobaltStrike放到刚刚新建的lib中去。

![](../Images/fc533b9cdab65c957c8afe8ed7d97cac.png)

接下来需要对这个项目进行设置,点击File中的Project Structure在Modules对Dependencies进行设置。

![](../Images/d7b5f3a629dff5a144efe9e5850ee147.png)

选择lib中的cobalt strike.jar，确认是Compile之后勾选一下，然后选择Apply。

![](../Images/b0680805a53b18cbc002385be5cd78b8.png)

![](../Images/4be065639d57a3a4aca12905d4359472.png)

至此依赖关系设置完了，现在进入Artifacts——>JAR——>From modules with dependencies

![](../Images/203f122050b2f9530e7668c2a5e7d969.png)

这里需要一个填写一个Main Class

![](../Images/7e390dac2fa0807795a14392f50ab0fe.png)

目前我们还不知道这个Main Class该填什么，可以点在lib中的META-INF里双击MANIFEST.MF，我们可以看到Main Class，复制aggressor.Aggressor

![](../Images/1f6a0ce181b796fe34a15bf818114fd5.png)

再次打开Artifacts——>JAR——>From modules with dependencies在Main Class处填入aggressor.Aggressor选择OK,这里就设置完成了。

![](../Images/0cb5583d115363c65a58db4f4228e73a.png)

接下来在decompiled\_src目录中找到已经反编译完的aggressor主类,右击选择Refactor ——Copy File

![](../Images/35ede1471d159973717063cedd1df7d5.png)

![](../Images/e503c4224c86beeedd1a0ccb43fa66c4.png)

在To directory点击添加，选择之前创建的src在其中添加一个aggressor名字要一致，最后点击Refactor

![](../Images/ca4a3ba0708313c7db2e7c7525716be8.png)

![](../Images/4a8b601133a056c61131cdd81fbb3f61.png)

这样aggressor就自动的被拷贝到src目录里去了，这里可以看一下,如图。

![](../Images/aed5a32c55785fb9d04a809513596089.png)

测试一下，修改文件，保存。

![](../Images/28bbeebc24fc4c2cb5eb147ca237d727.png)

到这里我们的整个准备工作就完成了，之后就是我们要修改哪个文件，就可以在完整的源码中找到那个文件，然后右键Refactor然后Copy File到这个目录然后进行修改，修改完成之后就可以选Build——>Build Artifacts ——>Build进行编译。

![](../Images/f54fe1ee7c08af4a3c6f5ae90a082164.png)

当提示Build completed successfully in 4 s 227 ms (a minute ago)的时候，会生成一个out文件夹,其中可看我们的编译好的MycustomCS.jar

![](../Images/37faa20c15a97b49977ff512c32bd407.png)

在每次调试运行的时候，不需要切换到命令行环境，可以直接选择Run中的Profile设置参数。

![](../Images/e73ab2a8ac3cf04797fb708f074c9fe9.png)

选择➕号，在JAR Applic添加一个配置文件。

![](../Images/eb1b200fac3c536056893bf6b765bdad.png)

在Path to JAR中选择out文件中我们修改并编译好的jar包，选择好后点击Apply

![](../Images/212b51898234a30acf5b4a44f78af85e.png)

最后在Run中选择Run CustoomRUn即可看到消息窗。

![](../Images/a58bcd1267b7d33ff40542cdc80cc1dd.png)

![](../Images/d5b0d5f3e4c7d3a7314dce15374903d5.png)

点击确定，发现弹出提示，没关系，继续点击确定。

![](../Images/929c79b25bf55ce590cdd4f911a2742a.png)

我们把-XX:+AggressiveHeap复制下来。

![](../Images/8cbffc35e751ccc8a7dd6561ff5ba51f.png)

再放到Run的Profile这里就直接选择之前创建的CustomRun填入VM options 最后选择Apply

![](../Images/2ca8a8db5908c5101d2433072811e9ec.png)

![](../Images/45c39bef7b8377868f91b150303c3ae4.png)  

再次Run运行,继续复制-XX:+UseParallelGC

![](../Images/ac44572c2d48cca6d8f807ac2f284768.png)

继续在添加到VM options中，记得要用空格隔开。

![](../Images/0f7ffd8b3525e732446444f7aa89a8a3.png)

再次运行，提示auth文件找不到。

![](../Images/1a6c2aeb3f708d88bd1abba1c7afb8f2.png)

这里把初始的cobaltstrike.auth文件复制到MycustomCS.jar同目录下。

![](../Images/510ee25811e867ee2af3b043f77b2113.png)

最后运行,到这里我们需要进行二次开发的环境就搭建好了，接下来就可以根据我们的需要通过关键字在源码中定位到具体的功能实现的代码，从而进行修改，或作一些功能上的增强。

![](../Images/69016ef06efe48d27033ed41a642c621.png)

**三、总结**

本文使用IntelliJ IDEA自带的java反编译工具，对cobaltstrike进行了快速的反编译，并展示了修改后的效果，权当抛砖引玉，具体的插件开发各位师傅可以结合具体场景进行编写。
