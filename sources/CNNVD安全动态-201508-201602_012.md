**介绍**

**Kasidet 分析**

**安装：**

Kasidet安装目录为%APPDATA%文件夹。木马创建一个名为“Y1FEZFVYXllb”的文件夹，这个硬编码的字符串在恶意样本中。同样的字符串作为互斥体名称，并创建注册表项以确保系统重启的持久性。

**AntiVM****检查：**

再执行下面的一系列检查，Kasidet尝试检测分析系统：通过Windows的API函数"IsDebuggerPresent"和"CheckRemoteDebuggerPresent"检查调试信息。同样检查下面的比较流行的沙箱相关的字符串：

  

> User Name: "MALTEST", "TEQUILABOOMBOOM", "SANDBOX", "VIRUS", "MALWARE"
> 
> File Name: "SAMPLE", "VIRUS", "SANDBOX"

同样通过检查kernel32.dll是否导出函数”wine\_get\_unix\_file\_name”来检测wine软件。通过注册表项检查Vmware、VirtualBox、QEMU以及Bochs。

![](../Images/2e40a3a410e449c4c7cd2dffdf7adf3b.png)

**总结**

恶意的Office文档是攻击者们传播他们payload的一种比较流行的做法。Direx的作者使用这种技术已经一年多了，很有趣的是通过Kasidet的payload也是通过类似的做法。然而这并不意味着在这两个恶意软件家族存在什么联系，只是说明一个事实，很多技术方法正在被网络犯罪团伙共享。
