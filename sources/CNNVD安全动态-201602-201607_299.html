DameWare迷你远程遥控漏洞（CNNVD-201603-259）

在做安全评估的时候，常常会碰到一些允许管理员在网络上远程管理系统的软件。虽然很便利，但是各式各样的包导致远程访问系统存在着一些安全隐患。

在这篇文章中，将详细说一下在一个叫做DameWare迷你遥控的软件包里发现的漏洞CVE-2016-2345（CNNVD编号为CNNVD-201603-259）。

这个漏洞是我们在检查DWRCS服务中的信息解析函数时所发现的。由于应用程序使用了LoadString函数生成字符串常量，因此这个漏洞很不容易被发现。下图是漏洞的伪代码：



在执行文件中的资源表里我们发现了一条ID为0×11的字符串，如下所示：

The desktop user disconnected the session via the MRC Tray menu UserID: %s

（桌面用户通过MRCTray目录用户id断开会话：%s）

大致看这个漏洞的出现是由于0×210大小的dst_buf缓冲区发生了溢出。但实际上这个漏洞真正特殊的地方是栈帧的安装方式。格式字符串缓冲区被放在了wsprintf函数的缓冲区后面，这意味着当dst_buf溢出，我们就可以控制住格式字符串并随意添加标识符。因此这个bug已经不仅仅是一个简单的缓冲区溢出问题了，还可以被定义为一个能够泄露内存地址的格式字符串漏洞。

基于这点，我们开始通过这个漏洞测试获得对可执行文件的控制权。首先，先确认哪个内存保护已经被编译成二进制文件。在分析堆栈转储中发现，二进制文件通过栈cookies来防止溢出栈返回的指针。于是我们使用了Corelan的mona.py脚本进行探测，结果并没有其他正在使用的内存保护。


尽管能利用这个漏洞通过二进制数据部分中默认的Cookie来解决栈的金丝雀值（canary），但由于这并没有启用SAFESEH，我们决定重写栈帧顶部的异常处理。不过实际过程中还是出了点小问题，于是重写了SEH链直接跳转到shellcode，然后发送一个正在使用的协议的原始包以便应用到适当的处理功能。

此漏洞自从发现后就一直由Solarwinds维护。
