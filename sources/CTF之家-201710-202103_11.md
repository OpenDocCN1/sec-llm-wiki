0x01 原理

  

首先要明确CBC字节翻转攻击的本质：**通过破坏密文字节从而达到修改明文的目的**

（To change a byte in the plaintext by corrupting a byte in the ciphertext）  

  

关于CBC的详细介绍可以在wikipedia上查看：  

http://en.wikipedia.org/wiki/Block\_cipher\_mode\_of\_operation#Cipher-block\_chaining\_.28CBC.29

这里我们只关心实际的攻击过程

  

**关于加密过程**

![](../Images/d2e884dc8551aba35d77131563681f8a.png)

各种参数介绍：

Plaintext：待加密的明文数据

  

IV：initialization vector（初始化向量），随机产生的比特序列，用来保证即使每次对相同的明文序列进行加密，也可以得到不同的密文序列

  

Key：在AES、DES、3DES等对称加密算法中使用

  

Ciphertext：密文数据

  

还有很重要的一点是，CBC基于固定长度的比特组，称之为**块**。

  

在示例中，采用的块大小为16字节  

  

由于作者讨厌高数，所以他采用了如下的定义：

Ciphertext-0 = Encrypt(Plaintext XOR IV)——只作用于第一个块

Ciphertext-N= Encrypt(Plaintext XOR Ciphertext-N-1)——作用于第二及之后的块

  

正如我们在加密过程中所看到的那样，**后一块的密文由前一块的密文产生**

  

**关于解密过程**  

![](../Images/4cf79c78c40071ac53cb5143e50a4fb8.png)

  

Plaintext-0 = Decrypt(Ciphertext) XOR IV——只作用于第一个块

Plaintext-N= Decrypt(Ciphertext) XOR Ciphertext-N-1——作用于第二及之后的块

  

重点来了（快圈起来考试要考的！）：**Ciphertext-N-1（密文-N-1）是用来产生下一块明文**

  

这就是字节翻转攻击厉害的……不对，开始发挥作用的地方了

如果我们改变Ciphertext-N-1（密文-N-1）中的一个字节，然后与下一个解密后的块异或，就可以得到一个不同的明文了

0x02 举个栗子

  

假设有如下明文序列：

a:2:{s:4:"name";s:6:"sdsdsd";s:8:"greeting";s:20:"echo 'Hello sdsdsd!'";}

  

这是一个经过了序列化的明文序列，CTF关于php反序列化的相关知识我会在近期发出来，大家也可以自己去搜索一下相关的内容

  

OK，刚才说到哪了？对，说到我们有这样一个明文序列，而我们的目标是没有蛀牙……呸，我们的目标是将明文序列中的数字6转换成数字7，那么首先我们需要将明文序列分成16字节大小的块：  

Block 1: a:2:{s:4:"name"; 

Block 2: s:6:"sdsdsd";s:8

Block 3: :"greeting";s:20 

Block 4: :"echo 'Hello sd 

Block 5: sdsd!'";}

  

我们的目标字符位于块2，也就是说我们需要改变块1的密文从而改变块2的明文

  

有一条经验法则是，**你在密文中改变的字节，只会影响到在下一明文当中具有相同偏移量的字节**

  

经过简单计算发现我们目标字符的偏移量是2

  

因此我们要改变块1中偏移量为2的字符

  

那么问题来了，我们怎么改变块1中的字符从而得到我们想要的值呢？  

  

基于上述的解密过程，我们知道有，A = Decrypt(Ciphertext)与B = Ciphertext-N-1异或后最终得到C = 6，即：

C = A XOR B 等价于 A = B XOR C

  

我们知道，任何数与自身异或的结果为零

  

于是，A XOR B XOR C = 0

  

从而，A XOR B XOR C XOR D = D

  

而D，就是我们需要的值
