# 挖掘过程

概述：从HashMap触发TreeMap的get()从而进入到compare()。

![](../Images/bd0fa135715af8c45ce8f7ae18e1cbf7.png "null")

  

web.xml中声明了servlet路由，在其代码中进行了反序列化

![](../Images/9f31dbba0dc34ba681eb4a532904dd4d.png "null")

而`this.appClassLoader`将反序列化能用的类限制在jdk标准库和classpath中。

![](../Images/28b3be5ecb244fd747b18a50aca50b9f.png "null")

其中cc库为2.1没有InvokerTransformer或InstantiateTransformer。

![](../Images/1e220d66b94fbbe5b86888f6742cbdbf.png "null")

  

cc库走不通，看cb库 `org.apache.commons.beanutils.BeanComparator`，很明显可以调用任意对象的getter方法。

![](../Images/f65b96c640ad15abbe4ecfbb571c38e3.png "null")

  

在yso中是使用`PriorityQueue`来自动进入compare方法中，而目标环境是jdk1.4，没有`PriorityQueue`类。低版本的jdk肯定有对`PriorityQueue`自动排序队列的另一种实现，即如下调用栈


我这里使用的是jdk1.8的代码，大差不差最后都能触发compare()。那么现在的关键点就在于如何触发TreeMap.get()。

在HashMap反序列化时会调用到`putForCreate()`：

![](../Images/1eff746a80f89fc5ecc4e82d4fa3ce8f.png "null")图来自原文

putForCreate用于判断hash是否一致，可以通过构造值一样但引用地址不一样的两个对象来解决。

```
TreeMap treeMap1 = new TreeMap(comparator);treeMap1.put(payloadObject, "aaa");TreeMap treeMap2 = new TreeMap(comparator);treeMap2.put(payloadObject, "aaa");HashMap hashMap = new HashMap();hashMap.put(treeMap1, "bbb");hashMap.put(treeMap2, "ccc");
```

这样就完成了从反序列化入口`readObject()`到`BeanComparator.compare()`的调用。

现在的问题就是找到RCE的最终点。而在`org.apache.commons.beanutils.BeanComparator`中是可以调用任意getter方法的，通过`PropertyUtils.getProperty()`。
