# Kerberos Bronze Bit Attack 绕过约束委派限制

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzU0ODg2MDA0NQ==&mid=2247485506&idx=1&sn=44bc30bc6b458c6bc84f67368c4affda&chksm=fbb9f1a0ccce78b628f16f4fd06b044fd39ab25721630d2a80005fa58c3b6625778099d2a057&scene=126&sessionid=1681400063#rd](http://mp.weixin.qq.com/s?__biz=MzU0ODg2MDA0NQ==&mid=2247485506&idx=1&sn=44bc30bc6b458c6bc84f67368c4affda&chksm=fbb9f1a0ccce78b628f16f4fd06b044fd39ab25721630d2a80005fa58c3b6625778099d2a057&scene=126&sessionid=1681400063#rd)

Kerberos Bronze Bit Attack又称Kerberos青铜比特攻击，由国外netspi安全研究员Jake Karnes发现的漏洞，并且申请了CVE-2020-17049编号。

# 概述

该漏洞解决了两个问题

1.禁止协议转换/协议过渡2.受保护的用户和敏感用户不能被委派

具体设置表现为DC上设置Service1计算机账户为“仅使用Kerberos”而非“使用任何身份验证协议”

![](../Images/dfa1438e4d87e5776d2c6b90f440efd7.png "null")

  

spn服务账户sql设置为“敏感用户不能被委派”或者添加到“受保护的组”中（两者任选其一）

![](../Images/06130985466c185f7986125c6f5cbf1c.png "null")![](../Images/ef98752aa9175cc343d61f58ae8a184e.png "null")

  

  

![](../Images/14c7b2cfa14bcef35208195546cf101d.png "null")

利用场景：

1.传统的约束委派2.基于资源的约束委派（滥用域账户的MachineAccountQuota属性）

下面进行复现

# 基于资源的约束委派绕过

先配置环境，首先删除上一步service1的委派权限

![](../Images/989cf99b273ef0542235b75a12558c2c.png "null")

  

用adsi编辑器赋予域用户jack对service2写入权限

![](../Images/f2681674b3bcc7cf79e30cd7e4e62a07.png "null")

  

开始利用，首先需要通过powermad新加入一个计算机账户AttackerService，密码为AttackerServicePassword，用域账户jack登录service1

*   
*   

```
Import-Module .\Powermad\powermad.ps1New-MachineAccount -MachineAccount AttackerService -Password $(ConvertTo-SecureString 'AttackerServicePassword' -AsPlainText -Force)
```

![](../Images/33f5ae4bce9a4660ad640a69ec1e066a.png "null")

  

因为密码是我们自定义的，所以可以用mimikatz计算出hash

![](../Images/6bf8e8ab307975135172ecfd4660b89b.png "null")

  

然后使用PowerShell Active Directory模块添加基于资源的约束委派，即从AttackerService到Service2的传入信任关系。

`Microsoft.ActiveDirectory.Management.dll`在安装powershell模块Active Directory后生成，默认只在域控上有，可以从域控上导出。

*   
*   
*   
*   

```
Import-Module .\Microsoft.ActiveDirectory.Management.dllGet-ADComputer AttackerService #确认机器账户已经被添加Set-ADComputer Service2 -PrincipalsAllowedToDelegateToAccount AttackerService$Get-ADComputer Service2 -Properties PrincipalsAllowedToDelegateToAccount
```

![](../Images/fa9b05bb640e4d8604ff5c3b1208c4e6.png "null")

# 总结

Kerberos Bronze Bit Attack可以绕过“敏感用户不能被委派”和“受保护的组”进一步利用约束委派，扩大了Kerberos的攻击面。
