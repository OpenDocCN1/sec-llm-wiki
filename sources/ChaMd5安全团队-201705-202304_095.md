# Netgear R8300栈溢出漏洞分析

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzIzMTc1MjExOQ==&mid=2247504734&idx=1&sn=bd3460522925d8ab88d041039d551c30&chksm=e89dfb86dfea72901ff681045ec44ded966ff123fba2aafd2326a1eab95eecf07d1daf819057&scene=126&sessionid=1681403426#rd](http://mp.weixin.qq.com/s?__biz=MzIzMTc1MjExOQ==&mid=2247504734&idx=1&sn=bd3460522925d8ab88d041039d551c30&chksm=e89dfb86dfea72901ff681045ec44ded966ff123fba2aafd2326a1eab95eecf07d1daf819057&scene=126&sessionid=1681403426#rd)

漏洞描述：

在upnpd文件sub\_25E04函数中，存在栈溢出漏洞。strcpy时未检查长度，造成溢出并可构造ROP攻击实现命令执行。  
版本：1.0.2.134  

**漏洞分析与复现**  
**一、固件模拟**  
利用qemu系统模拟：

```

 -net nic -net tap -nographic#! /bin/sh 

#！/bin/sh 

bind

```

**二、漏洞分析与调试**  
逆向分析upnpd文件如下，v51变量recvfrom获取内容后，调用sub\_25E04函数，其中的strcpy函数将v51超长数据直接赋值给v39较小的缓冲区，造成栈溢出：

![](../Images/9decaebd3d2278e0f6e78e9a610c6501.png)

![](../Images/9d859afa8fb7fb93937f937f98a2a9bc.png)

  

利用gdbserver进行调试：

```

qemu端：# echo 0 > /proc/sys/kernel/randomize_va_space 关闭地址随机化
# ps | grep upnp

# ./gdbserver-7.7.1-armhf-eabi5-v1-sysv :12345 --attach 2446

set
 architecture armset

 endian little
```

返回地址所在栈空间和strcpy目标地址如下图：

![](../Images/a596530c9b7a684a769498d90bb6a500.png)

![](../Images/867a92320d85c29bb35ca6296b51aeeb.png)  

因此可知strcpy目标地址距离返回地址长度为：0x7ec6bc1c-0x7ec6b5ec=0x630  
构造数据包发送：

  

```
#!/usr/bin/python3

"<L"

, x)'a'

 +print
(payload)'192.168.100.2'

, 1900))
```

但是这样发送不能成功覆盖返回地址，报错如下：

![](../Images/725bf304063efacc6f6c2f02007f1ae2.png)

因为漏洞函数内的v39指针曾经存储到v41,v41在后续还被调用，如果被覆盖为无效地址后会产生异常，因此发送payload时，要把v41指针，即\[R7-#8\]所在的栈空间覆盖为有效地址，这里将其覆盖为原先v39的地址，调试得到与strcpy目标地址的偏移为0x604  

![](../Images/d26c7b887b1513fbb1a8788a469031ec.png)

因此构造新的数据包发送：

  

```
#!/usr/bin/python3

"<L"

, x)'a'
 +  # v41
'a'

 +  '192.168.100.2'

, 1900))
```
