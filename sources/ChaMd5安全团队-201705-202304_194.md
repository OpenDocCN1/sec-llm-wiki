**⼯控安全异常取证分析 **

  

解题思路

解压出来两个⽂件，⼀个1122，⽂件挺⼤，另⼀个是 112233，1kb ⼀看就知道是个vmdk。

![](../Images/3ad4c8e2efb1712e93ab96a1a7069951.png)

将 112233 改名为 Windows Server 2003 Web Edition-1.vmdk 

将 1122 改名为 Windows Server 2003 Web Edition-1-ﬂat.vmdk 

⽤ DiskGenius 打开，应该是个NTFS分区FDD，没有分区表的那种。

![](../Images/37f860bcd5a40f2e513d0cf8ffd2bae5.png)

从名为 mp4.mp4 的⽂件中提取出⼀段 ascii 字符串。 

![](../Images/782f55f637565714fe13d4ba45601afe.png)

提取出字符串

HEX -> HEX -> B32 -> B32 -> B32 -> B64 -> B64 -> HEX -> B32 -> B64 -> B64

**恶意文件分析**

  

解题思路

![](../Images/132c222df2c22a9c8eb60ef8993ae140.png)

无壳。进去类似一个shell

![](../Images/0a00276ad0d1e28a24a3bfbdca4e340e.png)

程序流程，输入32长度的哈希字符串，bytes.fromhex然后运行关键 crackme 函数。

![](../Images/6093bc42df028cffd0c5782cfd44b9a8.png)

findcrypt发现文件中有CRC32常量。

![](../Images/22f4be751bd4a05f04dae6c7b5d52b23.png)

crackme函数中包含了一个硬编码的key，

![](../Images/e93fdd35f3de480cbd7c038a100d0d06.png)

从开源项目中可以检索到。

https://github.com/TurboPack/LockBox3/blob/master/run/ciphers/uTPLb\_AES.pas

https://chromium.googlesource.com/chromiumos/platform/ec/+/refs/heads/stabilize-7797.B/test/tpm\_test/crypto\_test.xml

输入与硬编码的Key、加密结果作比较。16轮。

![](../Images/3a0946e0f2d6005532ab0b33922e8ddb.png)

循环16次看ECX值即可dump出预期输入。拼起来可以得到：22d72a581f3a61e61e5b127e47ad8c0c

![](../Images/73e41b612198babdd531e3875b15d990.png)

将这个值输入程序，得到flag

![](../Images/9d3a9d389ed3ef3a480176ca9a75db8a.png)
