Adminer（以前被称为phpMinAdmin）是用PHP编写的功能齐全的数据库管理工具。与phpMyAdmin不同，它只由准备部署到目标服务器的一个文件组成。Adminer可用于MySQL，MariaDB，PostgreSQL，SQLite，MS SQL，Oracle，Firebird，SimpleDB，Elasticsearch和MongoDB。

开始

在使用最新版本的软件后，我遇到了某些问题，需要在题目功能正确之前解决。两个主要问题是密码锁定（因为等待游戏并不有趣），以及应用程序如何使用响应码来确定响应。

对于第一个问题，我准备通过将源代码修改为不包含if语句来移除密码锁定，(该if语句)确定用户是否尝试登录多次。

  1. 获取php文件并通过一个php美化器来运行它。
  2. 定位到 check_invalid_login 函数
  3. 注释掉if语句，该语句检查了是否有太多次失败的(登录)尝试：

这实际上将完全禁止检查是否无效登录了太多次，从而使该功能无效。

我的下一个问题是响应码。我希望选手既能够泄漏源代码，又能够通过同一Adminer应用程序与后端服务进行交互。

现在，有一个问题，由于Adminer应用程序专注于响应代码是否以2XX开头这一事实。如果返回的不是2XX响应码，它将显示用于返回该状态码的应用程序的源代码，否则它将仅返回例如“无效登录”的基本响应消息。

为了解决这个问题，我将后端配置为如果指定了密码，仅使用2XX响应码响应。这允许选手通过不指定密码来访问后端应用程序并泄漏源代码，同时一旦获得源代码，他们就可以通过包含password参数来登录。

<?php

if($_SERVER['PHP_AUTH_PW'] == ""){
    http_response_code(1337);
}else{
    http_response_code(200);
}

CVE-2018-7667和POST参数走私的绕过

CVE-2018-7667指出，一个SSRF漏洞存在于Adminer4.3.1及之前版本中，并在之后的版本中进行了修补。修补补丁仅简单限制了对1024以下端口的访问。可以在以下PHP文件中找到此检查：

if (isset($_GET["username"]) && is_string(get_password()))
{
    list($Ed, $ig) = explode(":", SERVER, 2);
    if (is_numeric($ig) && ($ig < 1024 || $ig > 65535)) auth_error(lang(93));
    check_invalid_login();
    $h = connect();
    $m = new Min_Driver($h);
}

如您所见，它使用:分割，这意味着它将使用:作为分隔符来分割字符串，然后将每个字段放入数组中，选择第二个值。然后检查该值是否大于65535或小于1024，若为真，它将返回认证错误。此处的trick(诀窍)是在if语句中使用了is_numeric，因此，如果我们向此检查传递的非数字的值，则该值将不能通过检查，不会返回错误。因此，只要我们能找到服务器字段的输入，在端口字段中输入非数字值，但仍遵循有效的URL语法，我们就可以绕过该检查。

让我们通过一个绕过示例来解决这个问题：

  1. 输入我们的payloadlocalhost:80#或localhost:80/到服务器字段中。
  2. GET用户名和密码检查通过，因为它们默认情况下即为空。
  3. 应用程序通过:分割服务器值并限制为2，$Ed表示第一部分——主机(host)，$ig表示端口(port)值。
  4. 应用程序中存在漏洞的检查开始起作用了，它获取到$ig(80#)并查看该值是否为数字，由于#的存在，它不是，因此它跳过错误并尝试连接到服务器。
  5. 由于#是锚点的合法URL语法，之后调用的file_get_contents不会出错，它只是会忽略#及其后面的内容。
