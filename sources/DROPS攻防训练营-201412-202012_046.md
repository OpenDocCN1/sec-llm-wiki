### Brute Force 暴力破解

* * *

暴破学名：穷举法、枚举法。常用在密码的破解、网站路径搜寻等情况下使用。在网站路径搜寻方面，网站基本都没有限制，所以才有一大堆的扫后台扫目录的小工具；在防范登录密码暴力登陆方面，现在网站都做的很严谨，但是总有一些旧网站和马虎的程序员留给我们暴力破解的机会。

密码来源：1、常用弱口令，例如Top100、Top500 2、借助脚本生成小字典。 3、借助第三方网站（例如：caimima.net)，结合对方实际情况分析得到字典。

### Command Injection 命令行注入

* * *

这里说的命令是windows和linux下常用的操作命令。存在命令行注入的网站，恶意用户就能未经授权、随心所欲的执行操作系统命令。命令行注入能用的位置比较局限，需要web的应用程序调用系统命令作为参数的，才有机会插入自己的恶意命令。由于命令行中能用到的连接符号也就屈指可数的那么几个，放到shell中又不能进行编码，所以在防范措施上利用黑名单进行过滤，对输入内容进行严格的验证基本可以防范命令行注入的攻击。虽说防范方法很容易，但是还是需要了解如何利用的，说不定那天就碰上个这样的漏洞呢。

1、low级别：  
题目让输入一个ip，果断127.0.0.1，然后返回了ping命令的信息。  
看一下代码：

```


<?php 
```

可以看到，服务器通过判断操作系统调用shell\_exec()来执行不同ping命令，但是对ip参数并未做任何的过滤，导致了严重的命令注入漏洞。  
stristr函数搜索字符串在另一字符串中的第一次出现，返回字符串的剩余部分。php\_uname('s')返回操作系统类型。

以下测试利用linux系统，windows略有区别。  
正常使用时候是输入ip地址，例如：`127.0.0.1`  
执行代码：`$cmd = shell_exec( 'ping -c 4 ' . 127.0.0.1 );`  
返回信息：

```


PING 127.0.0.1 (127.0.0.1) 56(84) bytes of data.
```

恶意利用这个漏洞：

例如：`ip=127.0.0.1 ; pwd`  
执行代码：`$cmd = shell_exec( 'ping -c 4 ' . 127.0.0.1 ; pwd );`  
返回信息：

```


PING 127.0.0.1 (127.0.0.1) 56(84) bytes of data.
```

得到目录信息。分号`;`连接的情况下从前往后依次执行，不存在影响关系。

例如：`ip=127.0.0.1 | pwd`  
执行代码：`$cmd = shell_exec( 'ping -c 4 ' . 127.0.0.1 | pwd );`  
返回信息：

```
/var/www/html/dvwa/vulnerabilities/exec
```

管道符`|`在这里只可以来执行后面的命令的。

例如：`ip=127.0.0.1 || pwd`  
执行代码：`$cmd = shell_exec( 'ping -c 4 ' . 127.0.0.1 || pwd );`  
返回信息：

```


PING 127.0.0.1 (127.0.0.1) 56(84) bytes of data.
```

`||`连接的情况下，前面成功执行则不执行后面的，前面不成功才会执行后面的,所以把`127.0.0.1`换成不存在的`999.999.999.999`就可以达到执行pwd命令的目的了。

例如：`ip=127.0.0.1 %26 ls` （需要对&编码为%26）  
执行代码：`$cmd = shell_exec( 'ping -c 4 ' . 127.0.0.1&ls );`  
返回信息：

```


help
```

`&`情况下两个命令同时会执行，不会相互产生影响。

例如：`ip=127.0.0.1%26%26pwd` （需要对&&编码为%26%26）  
执行代码：`$cmd = shell_exec( 'ping -c 4 ' . 127.0.0.1&&pwd );`  
返回信息：

```


PING 127.0.0.1 (127.0.0.1) 56(84) bytes of data.
```

`&&`情况下，前面成功执行才会执行后面的，前面不成功则不执行后面的。

由于对；的过滤，所以又带来了：`127.0.0.1%26;%26ls`这种姿势。

这种过滤方式是拿出第一组从字符串中遍历一遍，再拿出第二组从字符串中遍历一遍，每组依次进行…… 由这种过滤方式就产生一个问题，把aaaabbbb中的a替换成b，b替换成a就不可以这么写了，不然过滤完后就变成bbbbbbbb。

### Cross Site Request Forgery 跨站请求伪造

* * *

跨站请求伪造是指利用受害者未失效的身份认证信息，诱骗其点击恶意链接或者访问包含攻击代码的页面，在受害人不知情的情况下以受害者的身份向服务器发送请求，从而达到恶意目的。 说白了就是坏人利用受害者的身份干了只有受害者才能干的事情，比如：修改密码、盗取钱款、修改个人信息……好多好多事情。

### File Inclusion 任意文件包含

* * *

写程序时候去包含其他代码文件可以大大减少程序代码量，因为有包含所以才产生了文件包含漏洞。通过这个漏洞就想包啥包啥，想看啥看啥——只能看不能修改。包含文件的过程其实就是个文件代码执行的过程，所以结合文件上传漏洞上传带有恶意代码的文件，再去包含这个文件，就可以的达到很好的效果。  
任意文件包含漏洞分类：本地文件包含和远程文件包含。涉及到的危险函数：`include()`、`require()`、`include_once()`、`require_once()`。 涉及到的`php.ini`设置：`allow_url_fopen`、`allow_url_include`。  
四个危险函数区别：  
`require`找不到被包含的文件时会产生致命错误，并停止脚本运行。  
`include`找不到被包含的文件时只会产生警告，脚本将继续运行。  
`include_once`与`include`类似，唯一区别是如果该文件中的代码已经被包含，则不会再次包含。  
`require_once`与`require`类似，唯一区别是如果该文件中的代码已经被包含，则不会再次包含。

1、low级别：

### File Upload 文件上传

* * *

文件上传漏洞，通常是由于对上传文件的类型、内容没有进行严格的过滤、检查，使得攻击者可以通过上传木马获取服务器的webshell权限。所以对于网站的上传位置要格外小心。

1.low级别：  
新建空的png和php文件，都可以上传，貌似没有限制上传的文档格式。  
看源码：

```


$target\_path  = DVWA\_WEB\_PAGE\_TO\_ROOT . "hackable/uploads/";
```

$\_FILES数组内容如下:

```


$\_FILES\['myFile'\]\['name'\] 客户端文件的原名称。
```

`basename()` 函数返回路径中的文件名部分。  
`move_uploaded_file()` 函数将上传的文件移动到新位置。  
整个过程没有对文件类型进行检查，可随意上传，危险代码。

2、medium级别  
这个对文件类型进行了判断，上传png文件可上传，上传php文件上传不了。  
通过抓包修改`Content-Type`可实现任意文件上传，后端只检测了type类型。  
看一下代码:  
`if( ( $uploaded_type == "image/jpeg" || $uploaded_type == "image/png" ) &&( $uploaded_size < 100000 ) )`  
判断了type类型和文件大小，很显然大小对一句话限制没什么作用。

3、high级别：  
直接看代码：

```

$uploaded\_ext  = substr( $uploaded\_name, strrpos( $uploaded\_name, '.' ) + 1);
```

第一行的是用strrpos() 函数来查找“.”在变量$uploaded\_name中最后一次出现的位置，然后将得到的数值加1，最后利用substr()函数从变量$uploaded\_name的指定位置截取部分，是用于截取扩展名的，第二行的if进行扩展名白名单判断。解析一般是从前往后解析，那么利用00截断构造一个文件名为 1.php%00.png 的文件还是有机会正常执行的。
