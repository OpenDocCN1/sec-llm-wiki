K8s的重要性不用我多说，大家都能达成共识。

 

它已经是云计算领域中，平台层当仁不让的事实标准，几乎所有的大型分布式应用都在面向K8s编程。 

 

K8s的精髓在于，“把简单交给用户，把复杂留给自己”。

 

比如它的核心能力，“声明式”的应用定义方式，其背后的设计思想，就是在 YAML 文件（Kubernetes API 对象）中描述应用的“终态”。然后K8s通过“控制器模式”不断地将整个系统的实际状态向这个“终态”逼近，并且达成一致。

 

你只需要在YAML里描述清楚这个应用长什么样子，那么剩下的所有事情，就都可以放心地交给K8s自动完成了。

 

当然，这一切的前提，是K8s集群的顺利构建和高效管理。K8s并没有提供一个高可用的、开箱即用的集群使用方式，实际构建和管理过程中产生的复杂度，往往会带来各种各样的问题和挑战，比如：

  • Node的生命周期管理要怎么管理

  • Kubeadm、Kubespray、KOPS 等常用方案要怎么选

  • 如何基于声明式 API 管理高可用集群

  • 如何掌握Cluster Autoscaler的工作与扩展机制

  • 怎么做好故障监测和自动恢复……


而解决这些痛点的关键，就是掌握背后的机制和原理，然后在此基础上，选择正确的工具和方法，一切问题就会迎刃而解。
