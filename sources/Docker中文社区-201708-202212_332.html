自从 2013 年 Docker 发布开始，容器技术就为各家大厂打开了新世界的大门，国内的阿里巴巴、美团、京东、滴滴，国外的 IBM 等等都在把自己的核心业务 Docker + Kubernetes 化。（上个月字节跳动全资收购了才云科技，可见对容器化的战略布局）

 

最近这2年，我也看到了中小企业在逐渐向 Kubernetes 迁移。百家争鸣加快了各家公司对 AI、云计算、微服务、基础设施的战略布局速度，也推动着“新基建”的进程。

 

我们完全可以说：容器是必然趋势，而 Kubernetes 就是容器的标准。（如果你有不同的理解，可以在评论区留言）

 

敏锐的开发者，早就意识到 Kubernetes 要尽快掌握，但学习起来其实很困难：

 

  • 抽象名词太多，初学者很难串联起来并理解其中的关联关系。

  • Kubernetes 版本更新过快，网上或图书资料很难跟上版本更新的进度。

  • 抽象实现、组建和模块非常多，硬啃代码收效甚微。

 

其实这些难题，都是因为你在学的时候，没有从正确的学习方式入手，知识学习只浮于表面。但只有理顺各个组件工作模式，以及各个对象之间的串联关系，才能更好地在实战中应用。
