背景

在进行查询操作的性能测试或者 sql 优化时，我们经常需要在线下环境构建大量的基础数据供我们测试，模拟线上的真实环境。

创建测试数据的方式

  1.     1. 编写代码，通过代码批量插库（本人使用过，步骤太繁琐，性能不高，不推荐）

方式1：采用存储过程和内存表

  • 创建内存表

  1. 利用 MySQL 内存表插入速度快的特点，我们先利用函数和存储过程在内存表中生成数据，然后再从内存表插入普通表中

  3. CREATE TABLE `t_user_memory` (
  4.   `id` int(11) NOT NULL AUTO_INCREMENT,
  5.   `c_user_id` varchar(36) NOT NULL DEFAULT '',
  6.   `c_name` varchar(22) NOT NULL DEFAULT '',
  7.   `c_province_id` int(11) NOT NULL,
  8.   `c_city_id` int(11) NOT NULL,
  9.   `create_time` datetime NOT NULL,
  10.   PRIMARY KEY (`id`),
  11.   KEY `idx_user_id` (`c_user_id`)
  12. ) ENGINE=MEMORY DEFAULT CHARSET=utf8mb4;

  • 创建函数和存储过程

  1. # 创建随机字符串和随机时间的函数
  2. mysql> delimiter $$
  3. mysql> CREATE DEFINER=`root`@`%` FUNCTION `randStr`(n INT) RETURNS varchar(255) CHARSET utf8mb4
  4.     ->     DETERMINISTIC
  5.     -> BEGIN
  6.     ->     DECLARE chars_str varchar(100) DEFAULT 'abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789';
  7.     ->     DECLARE return_str varchar(255) DEFAULT '' ;
  8.     ->     DECLARE i INT DEFAULT 0;
  9.     ->     WHILE i < n DO
  10.     ->         SET return_str = concat(return_str, substring(chars_str, FLOOR(1 + RAND() * 62), 1));
  11.     ->         SET i = i + 1;
  12.     ->     END WHILE;
  13.     ->     RETURN return_str;
  14.     -> END$$
  15. Query OK, 0 rows affected (0.00 sec)

  17. mysql> CREATE DEFINER=`root`@`%` FUNCTION `randDataTime`(sd DATETIME,ed DATETIME) RETURNS datetime
  18.     ->     DETERMINISTIC
  19.     -> BEGIN
  20.     ->     DECLARE sub INT DEFAULT 0;
  21.     ->     DECLARE ret DATETIME;
  22.     ->     SET sub = ABS(UNIX_TIMESTAMP(ed)-UNIX_TIMESTAMP(sd));
  23.     ->     SET ret = DATE_ADD(sd,INTERVAL FLOOR(1+RAND()*(sub-1)) SECOND);
  24.     ->     RETURN ret;
  25.     -> END $$

  27. mysql> delimiter ;

  29. # 创建插入数据存储过程
  30. mysql> CREATE DEFINER=`root`@`%` PROCEDURE `add_t_user_memory`(IN n int)
  31.     -> BEGIN
  32.     ->     DECLARE i INT DEFAULT 1;
  33.     ->     WHILE (i <= n) DO
  34.     ->         INSERT INTO t_user_memory (c_user_id, c_name, c_province_id,c_city_id, create_time) VALUES (uuid(), randStr(20), FLOOR(RAND() * 1000), FLOOR(RAND() * 100), NOW());
  35.     ->         SET i = i + 1;
  36.     ->     END WHILE;
  37.     -> END
  38.     -> $$
  39. Query OK, 0 rows affected (0.01 sec)

  • 调用存储过程

  1. mysql> CALL add_t_user_memory(1000000);
  2. ERROR 1114 (HY000): The table 't_user_memory' is full
  3. 出现内存已满时，修改 max_heap_table_size 参数的大小，
  4. 我使用64M内存，插入了22W数据，看情况改，不过这个值不要太大，默认32M或者64M就好，
  5. 生产环境不要乱尝试。

  • 从内存表插入普通表

方式2：采用临时表

  • 创建临时数据表tmp_table

  1. CREATE TABLE tmp_table (
  2.     id INT,
  3.     PRIMARY KEY (id)
  4. );

  • 用 python或者bash 生成 100w 记录的数据文件（python瞬间就会生成完）

  1. python(推荐): python -c "for i in range(1, 1+1000000): print(i)" > base.txt

  • 导入数据到临时表tmp_table中

  1. mysql> load data infile '/Users/LJTjintao/temp/base.txt' replace into table tmp_table;
  2. Query OK, 1000000 rows affected (2.55 sec)
  3. Records: 1000000  Deleted: 0  Skipped: 0  Warnings: 0

  5. 千万级数据 20秒插入完成

注意：导入数据时有可能会报错，原因是mysql默认没有开securefilepriv（ 这个参数用来限制数据导入和导出操作的效果，例如执行LOAD DATA、SELECT … INTO OUTFILE语句和LOAD_FILE()函数。这些操作需要用户具有FILE权限 ）。

解决办法：在mysql的配置文件中（my.ini 或者 my.conf）中添加 securefilepriv = /Users/LJTjintao/temp/`, 然后重启mysql 解决

  • 以临时表为基础数据，插入数据到t_user中，100W数据插入需要10.37s

  1. mysql> INSERT INTO t_user
  2.     ->   SELECT
