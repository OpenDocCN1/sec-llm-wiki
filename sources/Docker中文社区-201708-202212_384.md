# Docker大力拥抱Kubernetes

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzI1NzI5NDM4Mw==&mid=2247483959&idx=1&sn=80da1006d1442981ee123093af6f72bf&chksm=ea18eb77dd6f626102a8511720d372dedd029ae19a6692d485edee79d6eed69c1d423cded5e6&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzI1NzI5NDM4Mw==&mid=2247483959&idx=1&sn=80da1006d1442981ee123093af6f72bf&chksm=ea18eb77dd6f626102a8511720d372dedd029ae19a6692d485edee79d6eed69c1d423cded5e6&scene=27#wechat_redirect)

  

![](../Images/a67939613483d01726d816c72d5b49e2.png)

  

    应用程序容器的兴起引发了关于容器最终是否会取代虚拟机的争论。可以说，这一天不会很快到来，其中安全性是最大障碍。

  

    上周，Docker发布了其容器平台的最新企业版，表示它可以帮助自动化“从开发到生产”的管道，同时允许用户在数据中心、混合云或边缘设备上运行传统和云原生应用程序。

  

    上周早些时候，戴尔宣布扩展其在超融合戴尔EMC基础设施上运行的VMware云，目标与Docker类似。由虚拟机技术支持的配置也被称为跨数据中心到边缘应用程序的服务。

  

    Docker表示，其第三版企业容器平台采用新的开发工具覆盖应用程序”滨水区“，以及重视容器安全问题，保证简化且安全的Kubernetes堆栈。

    去年年底，当Kubernetes 编排器的1.0及更高版本和红帽OpenShift容器平台出现了一个名为“特权升级漏洞”的问题时，引发对集群编排器安全性的担忧。红帽将该漏洞评级为“关键”，表示其对生产运营存在一定潜在影响。

  

    因此，Docker和其他采用者在推出平台新版本时都强调安全性。Docker的Enterprise 3.0版本于4月30日发布，宣称是部署和扩展容器和基于Kubernetes的应用程序的一种简单而安全的方式。

  

    最新的Docker平台强调了新的Kubernetes部署和扩展服务，进一步强化了Kubernetes作为容器编排事实标准的地位。Docker还提到其新的Kubernetes服务与内部编排器Docker Swarm协同工作。

  

    和戴尔一样，Docker将其升级的容器平台称为数据中心或云部署的托管服务。这一旨在帮助客户提供和运行在本地或公有云中运行的Docker容器平台的企业服务，最初将由Docker与CapGemini合作提供。

    戴尔的VMware云平台在AWS上运行。该公司还宣布扩展云合作伙伴关系，也可在Microsoft Azure上运行应用程序。

  

    新Docker平台还添加了一套自动化工具，旨在消除开发和生产之间的障碍，包括开发人员桌面、可访问Docker Hub的安全镜像注册表以及符合Kubernetes的生产部署。

  

    Docker Enterprise 3.0现在可用于beta测试。
