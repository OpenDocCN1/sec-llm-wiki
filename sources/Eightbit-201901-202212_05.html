0x1 物联网理论基础

在一切开始之前我们需要先对现代化物联网有一个清晰的认知,从物理结构,逻辑结构,软件结构,系统结构,运行结构等方面入手.只有当我们对物联网设备的一切都了如指掌的时候才能展开对物联网设备的渗透分析.在这一章中会给大家详细介绍现代物联网设备的运行状态以及设计架构.

0x1.1 物联网架构

历史起源:

  1. Peter T. Lewis 在1985提出这个概念

  2. 比尔·盖茨在1995年出版的《未来之路》一书中提及物互联

  3. 1998年麻省理工学院提出了当时被称作EPC系统的物联网构想

  4. 1999年,在物品编码(RFID)技术上Auto-ID公司提出了物联网的概念

  5. 2005年11月17日,世界信息峰会上,国际电信联盟发布了《ITU互联网报告2005:物联网》,其中指出"物联网"时代的来临

什么是物联网设备:

  1. 物联网设备首先拥有网络访问权限.一般是通过移动网络或者wifi来实现

  2. 物联网设备一般会通过某些手段搜集到一些目标数据

  3. 物联网设备将采集到的数据传递给服务器处理,并根据服务器返回的结果做出相应的操作

  4. 物联网设备的核心是尽可能的让所有设备进行自动化交互,最终为人类服务

  5. 目前研究趋势是将自主控制和物联网结合在一起成为AIoT(人工智能物联网)

  6. 在未来,物联网可能是一个非决定性的、开放的网络,其中自组织的或智能的实体和虚拟物品能够和环境交互并基于它们各自的目的自主运行

典型的物联网设备:

  • 智能手机:

  • 智能手机拥有安装第三方软件的功能,这使得现代的智能手机几乎可以满足所有工作,社交,生活相关的需求.

  • 随着移动互联网的发展,智能手机成为核心的通信工具,移动应用程序市场及移动商务、手机游戏产业、社交即时通信网络高度繁荣

  • 通信技术的发展,万物互联概念的提出,使得智能手机成为了重要的终端设备,进驻了现代社会的方方面面,已经是不可取代的物品

  • 智能门锁: 门锁集成上网功能诞生了智能门锁.实现了自动开锁,不再需要随身携带钥匙

  • 智能监控: 监控系统集成上网功能产生了智能监控.现在可以在千里之外实时观察人员的走动情况

以上这些都是比较传统的一些物联网设备,他给我们的生活带来大量的变化.除了这些传统的物联网设备,目前有一股新兴的物联网设备厂商:智能家居.

智能家居的核心是让所有家居产品连接到物联网,当大量看似无关的产品都连接到互联网时他们之间就会产生化学反应:

  1. 假设我们走出办公室,手机此时检测到我们正在走向停车场,并且观察到目前正是下班时间.手机立即发出指令->启动汽车

  2. 汽车启动后立即通过gps获取当前的位置,随后通过互联网查询到当前地区的温度较高->启动空调制冷

  3. 汽车出发后检测到行驶在回家的路上->自动开启回家的导航,并且通知家中的扫地机器人开始清理地面

  4. 回到家后门口的智能摄像头通过人脸识别识别出身份信息->自动开门,并且自动打开咖啡机

  5. 走进卧室后利用 语音助手打开电视机

这就是所谓的万物互联,也就是物联网的终极目标.但是这也随之产生了一个问题:安全

  1. 手机可以直接启动汽车->如何保证这个权限不会被非法分子窃取

  2. 汽车会自动通过互联网获取一些数据信息->如何保证汽车在这个过程中不会被控制

  3. 扫地机器人拥有完整的视觉导航功能->摄像头是否会被黑客控制

  4. 语音助手通过识别语音信息来工作->如何保证语音助手没有非法搜集语音信息

以上只是安全问题中最不起眼的一部分,为了更深入的了解物联网设备的安全问题,接下来会从物联网设备的硬件结构以及软件结构来介绍物联网.

0x1.2 物理结构

  1. 物联网设备也没有逃脱电子设备的范畴,一般存在以下几个核心部件:

  2. rom

  3. cpu

  4. 内存

  5. 接口

  6. 外设

  7. 在开始学习物联网设备信息安全前需要对这些部件有一个详细的了解

  8. 学习物理结构有助于我们理解物联网设备一些与硬件相关的渗透漏洞

0x1.2.1 rom

  1. rom:半导体存储介质,容量低,性能低,成本低

  2. 根据不同的需求,rom可分为只读与可写

  3. 现代化的物联网设备一般使用可擦写rom(EPROM/EEPROM)

  4. rom一般用来保存操作系统以及设备运行中产生的一些重要数据

  5. 一些不需要升级甚至不需要记录历史数据的物联网设备会采用只读rom

  6. 采用编程器可以直接读取rom中的数据信息

  • 路由器等小型物联网设备一般为8个针脚,芯片上有详细的型号可以查询

0x1.2.2 cpu

物联网设备选用处理器的标准以及处理的特性都和传统电子设备不同

  1. 传统的x86指令集系列的处理器功耗特别高,不适用于物联网平台

  2. 物联网平台目前比较流行mips以及arm指令集的处理器

  3. 厂商一般选用低功耗的处理器,极端的连1w都没有

  4. 成本非常低,性能很低,功能非常少

0x1.2.3 串口

  1. 串口串行通信接口或串行通讯接口,是采用串行通信方式的扩展接口

  2. 串行接口是指数据一位一位地顺序传送

  3. 其特点是通信线路简单,只要一对传输线就可以实现双向通信

  4. 大降低了成本,特别适用于远距离通信,但传送速度较慢

  5. 串口只是一种定义:网线,usb,com接口都可以作为串口的载体

0x1.2.4 调试端口

  1. 每一个物联网设备都有对应的调试端口,一般为uart

  2. uart就是串口的一种

  3. 通过调试端口可以获得一个linux系统下的shell

  4. 通过usb 转ttl按照下图链接线路就可以调试设备了

  5. 在Linux下可以通过minicom -D /dev/ttyUSB0来获得调试端口

  6. windows下可以使用putty来链接

连接后在电脑的设备管理器中应该可以看到有usb ... com的设备,这个就是usb上的调试端口了

0x1.2.5 GPIO

  1. GPIO的英文全称是General-Purpose Input / Output Ports,中文意思是通用I/O端口

  2. cpu可以直接控制这些gpio接口上的电流

  3. GPIO 接口一般用于控制一些外部设备

0x1.3 系统结构

  1. 物联网操作系统是运行在物联网硬件上的一类系统软件

  2. 物联网系统负责管理系统资源,为用户提供调用接口,方便用户应用程序开发

  3. 一般来说,物联网操作系统是由启动程序(Bootloader),核心(Kernel),根文件系统(Root File System)组成的

  4. 通过特殊的烧录工具可以把编译好的物联网系统文件镜像烧写到目标的只读存储器(ROM)或者Flash存储器中

0x1.3.1 物联网系统

  1. 一个物联网系统的性能好坏很大程度上决定了整个物联网系统的性能

  2. 按照实际需求,物联网操作系统可以分成实时系统和分时系统

  3. 随着技术的升级,目前主流的物联网服务商主推Ubuntu/Windows为主的分时系统

实时系统:

  1. 如果有一个任务需要执行,实时操作系统会马上执行

  2. 后来的任务只能等着

  3. 主要用在控制和通信领域

  4. 一个函数永远以恒定的时间执行结束

  5. 嵌入式操作系统一般首选这类操作系统

分时系统:

  1. 计算机把它的运行时间分为多个时间段,并且将这些时间段平均分配给指定的任务

  2. 每个任务获得的计算机资源不确定

  3. 同个任务的执行时间也不确定

  4. 以前主要用在消费类电子产品,很少用于物联网设备

  5. 但是目前已经有一部分的iot设备开始采用分时操作系统

接下介绍一下常见的几种物联网操作系统

0x1.3.2 VxWorks

  1. VxWorks是美国WindRiver公司(国内也称做风河公司)开发的高性能实时嵌入式操作系统

  2. 其特点是使用了自己开发的WIND内核,有着很高的实时性能

  3. 该系统支持多种处理器,包括PowerPC,x86,MIPS,ARM等,内核具备很好的裁剪能力,支持应用程序动态下载和链接

  4. VxWorks系统提供了强大的集成开发工具Tornado,用户可以在主机通过网络连接目标板的TargetServer直接调试目标板的程序,就好像在本地调试一样

  5. VxWorks还具有很好的兼容性,其接口符合POSIX(可移植操作系统接口)标准

  6. VxWorks系统内核是由进程管理,存储管理,设备管理,文件管理,网络协议等组成.内核占用很小的存储空间,最小的WIND内核可以配置到编译后仅有十几KB大小

  7. VxWorks系统被用在美国的火星探测器上,可见其稳定性和实时性确实很高

  8. 国内最早在1996年引进VxWorks系统,主要应用在通信,国防,工业控制和医疗设备领域

  9. VxWorks系统是研究物联网操作系统的一个很好平台,不过它是一个商业操作系统,开发和使用成本都非常高

  10. 最典型的使用就是机器人

0x1.3.3 Windows CE

  1. Windows CE是微软公司为物联网产品设计的一种物联网操作系统,主要针对需要多线程,多任务而且资源有限的设备

  2. 该系统采用模块化设计,开发人员可以定制不同的功能

  3. Windows CE系统支持丰富的外部硬件设备,包括键盘,鼠标,触摸板,串口,网口,USB,音频设备等

  4. 该系统有与Windows一致的图形界面,可以很好地提高用户体验

  5. Windows CE的最大特点就是支持上千个微软Win32编程接口(Microsoft Win32 API)

  6. 在Windows下开发过应用程序的程序员可以很快地熟悉Windows CE

  7. Windows CE还支持PC上的模拟器,用户可以从模拟器上开发应用,调试完毕后再下载到目标板执行,提高了开发效率

  8. Windwos CE系统设计简单灵活,主要应用在各种小型设备,例如掌上电脑,餐厅点餐器等设备上

0x1.3.4 Android things

  1. Android Things (代号为Brillo )是Google在2015年I/O大会上宣布的基于安卓的嵌入式操作系统

  2. 该操作系统基于 安卓,针对嵌入式设备对安卓做了大量的精简操作

  3. 系统原生接口是c++实现的,但是现在同时也提供了对java的支持

  4. 该操作系统统一由谷歌维护升级,开发者不需要关心底层系统的问题

  5. 凭借 安卓手机庞大的 供应链,基于Android Things的物联网设备已经在市面上大量铺货

0x1.3.5 ThreadX

  1. ThreadX是由Express Logic 公司发布的实时操作系统

  2. 该操作系统的安全等级是目前嵌入式设备中做的最好的

  3. ThreadX是多任务系统,采用抢占式调度,快速的中断响应,独立内存管理,支持线程间通信,互斥,事件和线程同步.

  4. ThreadX 支持的架构包括 ARM,X86, ARC, MIPS,Xtensa等等, 几乎涵盖所有主流CPU架构

  5. 该操作系统于2019年被微软收购

  6. 截至2017年,ThreadX RTOS已成为世界上最受欢迎的RTOS之一,已部署在超过62亿个设备中,包括消费电子,医疗设备,数据网络应用,和SoC

0x1.3.6 win10 iot

  1. 从 2015年开始,微软以win10为主干创建了iot分支Windows 10 IOT

  2. win10 iot是windows ce的替代版本,用于取代老旧的ce

  3. 针对小型和低成本工业设备进行了优化,还免费提供给Raspberry Pi等设备用于爱好者

  4. 该操作系统包含了完整的windows平台下的api,同时兼容第三方库,开发测试都非常方便

0x1.4 物联网Linux

  1. 与商业系统相比,Linux系统在功能上一点都不差,甚至在许多方面要超过一些著名的商业操作系统

  2. Linux不仅支持丰富的硬件设备,文件系统,更主要的是它提供了完整的源代码和开发工具

  3. 对于物联网开发来说,使用Linux系统可以帮助开发者快速的建立一套完整的可移植的物联网操作系统

  4. 目前最大多数新兴的物联网设备都是基于linux

0x1.4.1 精简linux

  1. 目前有些物联网设备使用的是精简版的linux系统

  2. 这些操作系统小的连1M都没有

  3. 只有一些非常基础的命令行功能,甚至没有telnet

  4. 主要负责启动软件

  5. 保存在rom中

  6. 考虑到系统兼容性,开发门槛,开发速度等条件,目前linux是使用最广泛的 物联网系统

物联网linux系统拥有类似pc系统的特性,被硬件激活后会进行以下软件操作:

  1. 启动 Bootloader

  2. 启动 操作系统

  3. 启动 相关软件

0x1.4.2 Bootloader

  1. Bootloader 是物联网软件开发的第一个环节,它把物联网系统的软件和硬件紧密衔接在一起

  2. 硬件启动后运行的第一段代码就是Bootloader

  3. Bootloader 可以理解为操作系统运行前的一段初始化代码

  4. uboot 是 Bootloader 在物联网系统上的主要实现

  5. 最初的uboot 仅支持PowerPC架构的系统,称做PPCBoot,现在已经支持多种架构

  6. uboot是一个引导程序,相当于linux中的grub负责启动操作系统

  7. uboot实际上也是一个精简linux 环境,也拥有一些命令

  8. 每个厂商的uboot都有不同的功能

  9. uboot最后一般会启动linuxrc进程,这个程序相当于linux中的int进程

  10. 保存在rom中

0x1.4.3 busybox

  1. 在常规的操作系统中每一个程序都需要一个单独的文件来保存,这会非常消耗空间

  2. 物联网设备虽然也是linux但是并没有使用使用传统的方式来保存linux 命令,而是使用busybox

  3. busybox是一个程序,它将多个程序封装到一个程序中

  4. 虽然busybox能将多个程序压缩在一个程序中,但是考虑到是物联网程序,实际上这些被整合的linux命令在功能上也会有相应的精简

0x1.4.4 squashfs

  1. 物联网设备rom中的数据一般是按照squashfs格式来保存的

  2. Squashfs是一套供Linux核心使用的GPL开源压缩文件系统

  3. Squashfs能够为文件系统内的文件,inode及目录结构进行压缩,并支持最大1024千字节的区段,以提供更大的压缩比.

  4. Squashfs的设计给资源紧张的设备使用,这正符合物联网设备需求

0x1.5 管理模式

  1. 目前市面上充斥大量的物联网设备

  2. 这些设备往往由大小不同的厂家控制

  3. 以设备规模划分的话,可以划分出大量数十万,数百万,甚至是上千万等不同规模的物联网设备集群

  4. 由于集群的数量不同,厂商的技术能力不同,不同的厂商一般会采取不同的策略来管理这些数以万计的物联网设备

  5. 以下三种模式是目前物联网设备比较常见的管理模式

0x1.5.1 独立运行

  1. 客户通过定制软件直接连接到具体的物联网设备

  2. 这是最传统的方式,简单,高效,安全

  3. 配置比较复杂,一般需要手动配置

  4. 只适合少量的设备,设备数量很庞大时就不能使用这种方式管理

  5. 设备安装后一般需要专业人员配置后才能正常互联

  6. 由于设备一般部署于独立的网络环境中运行,有一定的安全保障

下图中就是比较传统的摄像头,只有专属网络环境才能查看

0x1.5.2 自主管理

  1. 物联网设备厂商自主创建 云数据中心

  2. 自主编写云端软件以及客户端软件,非常自由

  3. 物联网设备自动连接到数据中心,用户发送的指令不是直接发送到物联网设备,而是由云数据中心转发

  4. 研发压力较大,安全和性能都难以保障

  5. 早期的物联网企业比较喜欢采用这种方案

下图所示是比较成熟的iot数据中心

0x1.5.3 iot hub

  1. 由第三方公司(一般是云服务器公司)来封装一整套完整的云端系统以及客户端软件

  2. 性能和安全都有保障

  3. 由于专业的云服务厂商已经封装好了开发环境,运行环境 因此 开发很快

  4. 目前为了提升稳定性,以微软为代表的云公司一般只兼容主流操作系统和主流设备

  5. 一般采用成熟的物联网硬件:pc设备标准,iothub认证设备,树莓派,工控方案
