0x1 漏洞介绍


       


       介绍漏洞之前首先介绍一下虚拟内存，在操作系统中，为了防止直接分配和使用物理内存造成的诸如内存不足、安全性不足、内存碎片化等问题，采用了虚拟内存空间，利用这一手段，只有在进程真正需要访问内存资源时才产生缺页中断，建立虚拟内存地址和物理地址的映射，从而避免了内存浪费。

       虚拟内存分配于内核空间和用户空间之间。在windows下4G 地址空间中低2G，0x00000000-0x7FFFFFFF 是用户地址空间，4G地址空间中高2G，0x80000000-0xFFFFFFFF 是系统地址空间。访问系统地址空间需要程序有ring0的权限。而Linux对4G空间的划分不同于windows。以x86为例，在x86上，每个进程都有一个内存映射，该内存映射分为两部分，用户空间最大为3GB（地址0xC0000000），最后一个GB是为内核保留的。尽管存在特权分离，但它们都共享相同的地址空间：

空指针解引用（null pointer dereference）漏洞是一个内核中比较古老的漏洞，该漏洞首次发现于2009年，影响了自2001年以来的所有2.4到2.6Linux内核。该漏洞成因就是对未初始化的指针进行引用就会寻址到0地址，也就是null引用，如果程序中有未初始化的函数指针，当调用这一指针时就会实现类似call 0x00000000的行为，转而去执行0x00000000处的代码。基于这一原理，当存在该漏洞时，如果我们用用户进程访问，mmap映射一段从0开始的内存，布置shellcode，然后调用未初始化的指针，就会触发该漏洞执行我们的shellcode。

从2.6.22开始，Linux加入了针对性保护措施，主要是设置mmap_min_addr以阻止用户对0地址的使用。此时如果查看当前系统中可以映射的最低内存地址，会得到如下结果：

0x2 驱动模块实现



        这里我们选择沿用之前实现的驱动模块代码，这里也可以重构一个简单点的模块代码来复现这个漏洞，但是既然我们都已经有现成的可用驱动模块了，直接改动一下还是省事不少。

我们使用之前实现设备申请的代码，加入如下内容：

static ssize_t chardev_write(struct file *, const char *, size_t, loff_t *);
struct file_operations chardev_fops = {
  .write = chardev_write,
};
void (*myFunPtr)(void);   // 定义一个空指针
static ssize_t chardev_write(struct file *filp, const char __user *buf, size_t count, loff_t *f_pos)
{
   myFunPtr();    // 利用chardev_write触发漏洞
   return count;
}


将漏洞模块进行编译生成null.ko，这里依旧使用之前4.4.75的内核版本。

这里需要注意因为该漏洞在后续Linux内核版本中被修复了，所以我们需要关闭mmap_min_addr限制。这里编写文件系统中的init脚本。

#!/bin/sh

mount -t proc none /proc
mount -t sysfs none /sys
mount -t devtmpfs devtmpfs /dev

echo 0 > /proc/sys/kernel/kptr_restrict // 限制地址读取权限
echo 0 > /proc/sys/kernel/dmesg_restrict // 限制日志读取权限
exec 0</dev/console
exec 1>/dev/console
exec 2>/dev/console

sysctl -w vm.mmap_min_addr="0"// 解除内存映射限制
insmod null.ko // 插入漏洞模块
chmod 777 /dev/chardev0 // 设置访问权限


echo -e "\nBoot took $(cut -d' ' -f1 /proc/uptime) seconds\n"
setsid cttyhack setuidgid 1000 sh// 降权用户启动sh

umount /proc
umount /sys
poweroff -d 0 -f
