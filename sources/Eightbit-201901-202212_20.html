0x1 内核编译


       

       如果是做题，其实关于内核编译和文件系统构建都可以忽略，因为题目中有现成的东西，可以直接拿来用。这块内容主要适用于想要自己出题或者自己编写测试模块样例进行分析的情况。

首先你需要一个内核，之前的文章编译内核用的都是系统的内核，这里如果需要模拟ctf题目，则需要手动编译一个内核。

下载内核源码

https://mirrors.edge.kernel.org/pub/linux/kernel/

可以在上述网站进行下载，如果没有梯子也可以使用国内源，例如：

https://mirrors.tuna.tsinghua.edu.cn/kernel/

安装相关环境

这里我其实也没有具体验证哪个是不可或缺的，反正一通安，多了总比少了好：

sudo apt-get install git fakeroot build-essential ncurses-dev xz-utils qemu flex libncurses5-dev fakeroot build-essential ncurses-dev xz-utils libssl-dev bc bison libglib2.0-dev libfdt-dev libpixman-1-dev zlib1g-dev libelf-dev

之后可以进入解压的内核文件进行处理。这里我使用ubuntu20.04，内核使用5.5.6。

配置编译选项

make menuconfig

这里我们主要关注调试方面的选项，保证勾选如下配置（默认都是勾选了的）：

  • Kernel hacking —-> Kernel debugging

  • Kernel hacking —-> Compile-time checks and compiler options —-> Compile the kernel with debug info

  • Kernel hacking —-> Generic Kernel Debugging Instruments —> KGDB: kernel debugger

  • Kernel hacking —-> Compile the kernel with frame pointers（不一定有，和内核版本有关）

编译内核

编译时需要有较大磁盘空间

make bzImage

也可以根据机器核数来使用多个核进行编译，-jn，n最大可以支持2*(cpu * 每个cpu核心)

make -j8 bzImage

这里我用ubuntu16编译4.x.x的内核可以直接成功，用ubuntu20编译5.x.x的内核会有报错，应该是和gcc的变动有关，简单说一下我遇到的报错和处理方法：

报错1

make[1]: *** 没有规则可制作目标“debian/canonical-certs.pem”，由“certs/x509_certificate_list” 需求。停止

处理方法：

vim ./.config输入/，之后输入CONFIG_SYSTEM_TRUSTED_KEYS将CONFIG_SYSTEM_TRUSTED_KEYS = "debian/canonical-certs.pem"修改为CONFIG_SYSTEM_TRUSTED_KEYS = ""

报错2

BTF: .tmp_vmlinux.btf: pahole (pahole) is not availableFailed to generate BTF for vmlinuxTry to disable CONFIG_DEBUG_INFO_BTFmake: *** [Makefile:1079：vmlinux] 错误 1

处理方法：

vim ./.config输入/，之后输入CONFIG_DEBUG_INFO_BTF将CONFIG_DEBUG_INFO_BTF = y修改为CONFIG_DEBUG_INFO_BTF = n

完成后在./arch/x86/boot下拿到bzImage文件，在内核文件夹根目录拿到vmlinux，这两个文件是一般CTF中会接触的两个文件。

  • bzImage：目前主流的 kernel 镜像格式，即 big zImage（即 bz 不是指 bzip2），适用于较大的（大于 512 KB） Kernel。这个镜像会被加载到内存的高地址，高于 1MB。bzImage 是用 gzip 压缩的，文件的开头部分有 gzip 解压缩的代码，所以我们不能用 gunzip 来解压缩。

  • vmlinux：静态链接的 Linux kernel，以可执行文件的形式存在，尚未经过压缩。该文件往往是在生成 vmlinuz 的过程中产生的。该文件适合于调试。但是该文件不是 bootable 的。


02

0x2 构建文件系统



内核编译完成之后需要构建文件系统，这里使用busybox进行构建。

获取busybox

版本可任意更改

wget https://busybox.net/downloads/busybox-1.33.0.tar.bz2
tar -jxvf busybox-1.33.0.tar.bz2

编译busybox源码

make menuconfig

勾选Settings —-> Build static binary file (no shared lib)配置静态编译

编译

make install

编译完成后会生成一个_install目录，接下来我们将会用它来构建我们的磁盘镜像。这块内容大同小异。

初始化文件系统

cd _install
mkdir -pv {bin,sbin,etc,proc,sys,home,lib64,tmp,lib/x86_64-linux-gnu,usr/{bin,sbin}}
touch etc/inittab
mkdir etc/init.d
touch etc/init.d/rcS
chmod +x ./etc/init.d/rcS

配置初始化脚本

配置etc/inttab，写入如下内容

::sysinit:/etc/init.d/rcS
::askfirst:-/bin/sh
::ctrlaltdel:/sbin/reboot
::shutdown:/sbin/swapoff -a
::shutdown:/bin/umount -a -r
::restart:/sbin/init

配置etc/init.d/rcS，写入如下内容：

#!/bin/sh
mount -t proc none /proc
mount -t sys none /sys
/bin/mount -n -t sysfs none /sys
/bin/mount -t ramfs none /dev
/sbin/mdev -s

配置用户组

echo "root:x:0:0:root:/root:/bin/sh" > etc/passwd
echo "ctf:x:1000:1000:ctf:/home/ctf:/bin/sh" >> etc/passwd
echo "root:x:0:" > etc/group
echo "ctf:x:1000:" >> etc/group
echo "none /dev/pts devpts gid=5,mode=620 0 0" > etc/fstab

在这里建立了两个用户组root和ctf，以及两个用户root和ctf

/etc/init.d/rcS写入如下内容

#!/bin/sh

mount -t proc none /proc
mount -t sysfs none /sys
mount -t devtmpfs devtmpfs /dev

chown root:root flag
chmod 400 /flag
exec 0</dev/console
exec 1>/dev/console
exec 2>/dev/console

insmod xxx.ko
chmod 777 /dev/xxxxxx


echo -e "\nBoot took $(cut -d' ' -f1 /proc/uptime) seconds\n"
setsid cttyhack setuidgid 1000 sh

umount /proc
umount /sys
poweroff -d 0 -f

主要就是在启动脚本中规定flag的权限，加载模块，定义设备文件权限，并且以1000的降权用户启动sh。

如果有需要也可以找个lib文件夹，把内容贴进去，一般也不需要。

这里也可以直接写init脚本实现上述启动功能，看个人喜好。

打包文件系统

find . | cpio -o --format=newc > ./rootfs.cpio

得到rootfs.cpio文件




03

0x3 qemu模拟运行



得到bzImage和cpio之后将其放在同一目录下

编写boot.sh

#!/bin/sh
qemu-system-x86_64 \
    -m 128M \
    -kernel ./bzImage \
    -initrd ./rootfs.cpio \
    -monitor /dev/null \
    -append "root=/dev/ram rdinit=/sbin/init console=ttyS0 oops=panic panic=1 loglevel=3 quiet nokaslr" \
    -cpu kvm64 \
    -smp cores=2,threads=1 \
    -netdev user,id=t0, -device e1000,netdev=t0,id=nic0 \
    -nographic \
    -s

  • -kernel：内存镜像路径

  • -initrd：磁盘镜像路径

  • -monitor：将监视器重定向到主机设备/dev/null，防止CTF取巧拿flag

  • -append：附加参数选项。其中nokaslr表示关闭地址随机化，rdinit指定初始启动进程，/sbin/init会默认以/etc/init.d/rcS作为启动脚本loglevel=3 quiet表示不输出log，console=ttyS0指定终端为/dev/ttyS0，这样一启动就能进入终端界面

  • -cpu：设置CPU安全选项

  • -s：相当于-gdb tcp::1234的简写，后续我们可以通过gdb连接本地端口进行调试

开启vmware的虚拟化

模拟运行

root下运行boot.sh

05

0x5 驱动调试


 

如果对于CTF题目，一般需要有以下步骤：

1.如果没有提供vmlinux，则我们需要使用extract-vmlinux工具，项目地址：

https://github.com/torvalds/linux/blob/master/scripts/extract-vmlinux

提取vmlinux

./extract-vmlinux ./bzImage > vmlinux

2.解包cpio，将poc放入重新打包，同时修改启动脚本中sh的权限，将1000改为0000。以root进行调试。

对于自己编写的测试用例，直接按需求进行准备就好。

调试方法

在qemu运行内核时，可以在指定端口挂起一个gdb_server，之后我们可以使用gdb连上去进行调试。这需要我们在qemu命令下加入参数-gdb tcp::1234，一般情况下，我们也可以在boot.sh使用简写的-s实现，当然如果要修改端口则需要用-gdb指定

加载基址

如果想要加载ko文件的符号，以方便以函数名下断点，则需要add-symbol-file xxx.ko textAddr，这里的textAddr是指ko装载进内核空间后的.text段地址（其实就是装载基址）。这个地址可以在/sys/module/core/sections/.text读到，但是需要root权限。

运行环境，执行如下命令

cat /proc/modules | grep io


在gdb中加载之后就可以用函数符号下断点了

注，与 vmlinux 不同，使用 add-symbol-file 加载内核模块符号时，必须至少指定内核模块的 text 段基地址。

需要注意的是，加载符号文件时，越多指定每个 section 的地址越好。否则如果只单独指定了 .text 段的基地址，则有可能在给函数下断点时断不下来，非常影响调试。

对于ubuntu16编译的4.x.x的内核，加载text段即可，这里我用ubuntu20编译的5.5.6版本的内核不能只添加text地址，此时查看目标内核模块的各个 section 加载首地址

grep "0x" /sys/module/io/sections/.*

使用add-symbol-file尽可能多的指定section地址

add-symbol-file ./escalation.ko 0xffffffffc02e1000 \
    -s .bss 0xffffffffc02e3480 \
    -s .data 0xffffffffc02e3000 \
    -s .rodata.str1.1 0xffffffffc02e2262 \
    -s .rodata.str1.8 0xffffffffc02e2040 \
    -s .symtab 0xffffffffc02e6000 \
    -s .text.unlikely 0xffffffffc02e1000


运行程序，加载exp，程序成功断下

这里关于调试还有个小问题，之前在做普通linux pwn时gdb调试直接使用n和s即可实现汇编单步调试，再对内核模块进行调试时使用n和s会直接执行几行汇编语句，其实此时是执行了一行高级语言，所以直接运行了多行汇编，此时使用ni和si可以进行正常汇编级单步调试，另外当访问完内核代码返回到exp中执行时需要使用si，此时如果使用ni会直接跑飞，具体我没试过有没有不跑飞的情况。
