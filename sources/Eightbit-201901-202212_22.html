0x1 linux内核



1.1 内核

内核是操作系统的核心，扮演的是夹在硬件和软件中间的那个角色，说白了就是管理硬件设备，为应用程序提供运行环境。通常情况下，硬件设备包括CPU、内存、硬盘、I\O设备等等。内核基本上分为两种：单内核和微内核。Windows       NT内核和Mach（Mac OS X 的组成部分）是微内核结构，Linux内核是单内核结构。

原理
优势
劣势
单内核整个内核都在一个大内核地址空间上运行。1. 简单。2. 高效：所有内核都在一个大的地址空间上，所以内核各个功能之间的调用和调用函数类似，几乎没有性能开销。一个功能的崩溃会导致整个内核无法使用。
微内核内核按功能被划分成各个独立的过程。每个过程独立的运行在自己的地址空间上。1. 安全：内核的各种服务独立运行，一种服务挂了不会影响其他服务。内核各个服务之间的调用涉及进程间的通信，比较复杂且效率低。
简单讲就是：单内核所有事情都自己做，效率高但是体积大；微内核统领全局，把任务交给手下干，效率低但是体积小。linux虽然是单内核，但是经过多年发展，也具备一些微内核的特性，比如：支持动态加载内核模块模块。

1.2 版本号

如果去下载内核进行编译（这里以ubuntu为例），会发现内核版本号一般由三个数组成：

如果把它看成A.B.C：

    A - 内核主版本号

    B - 内核次版本号，是指一些重大修改的内核。偶数表示稳定版本；奇数表示开发中版本。

    C - 内核修订版本号

但是当我们查看ubuntu虚拟机内核版本时会看到另一种版本号，即major.minor.patch-build.desc


major - 主版本号
minor - 次版本号，新增功能时才发生变化，一般技术表示测试版，偶数表示生产版
patch - 补丁包数或次版本的修改次数
build - 编译（或构建）的次数，每次编译可能对少量程序做优化或修改，但一般没有大的（可控的）功能变化
desc - 当前版本的特殊信息，其信息由编译时指定，具有较大的随意性
如果对于上面示例：
   5 - 主版本号
    11 - 从版本号或副版本号
    0 - 修订版本号
    43 - 当前内核版本4.15第142次微调patch
generic - 当前内核版本为通用版本


1.3 Ring Model

kernel pwn不同于linux pwn，后者是通过与程序交互尝试获取shell，只要获得shell也就拿到了flag，而前者是给你一个shell，不过是降权的shell，只有当你实现提权才能查看flag。这里简单介绍一下特权模式，intel CPU 将 CPU 的特权级别分为 4 个级别：Ring 0, Ring 1, Ring 2, Ring 3。Ring 0 只给 OS 使用，Ring 3 所有程序都可以使用，内层 Ring 可以随便使用外层 Ring 的资源。大多数的现代操作系统只使用了 Ring 0 和 Ring 3。

由于特权分离，导致内核态的数据和代码与用户态的数据与代码被对方访问或执行时会受到限制，正常程序进入kernel态之前会保存用户态的各个寄存器，以及执行到代码的位置。从kernel返回到用户态会执行swapgs（64位）和 iret 指令，当然前提是栈上需要布置好恢复的寄存器的值。

0x2 linux驱动开发


LKMs(Loadable Kernel Modules)称为可加载核心模块(内核模块)，其可以看作是运行在内核空间的可执行程序，因为其可以动态加载到内核中而无需重新编译内核，因此常被作为驱动程序，除此之外，还会被用作内核功能扩展。内核模块其实也是一种程序，其文件格式与用户态文件格式相同，即linux下为elf，windows下为exe/dll。

内核模块程序和普通程序的区别如下：


C语言应用程序内核模块程序
使用函数libc库内核函数
运行空间用户空间内核空间
运行权限普通用户超级用户
入口函数main()module_init()
出口函数exit()module_exit()
编译gccgcc
运行直接运行insmod


目前linux kernel pwn题目大多漏洞出现在出题人自写的内核模块(Loadable Kernel Modules) 中。
内核模块一般是.ko文件，可以使用如下命令对其进行操作：


查看模块
    cat /proc/modules
    lsmod
插入模块
    insmod xxx.ko
卸载模块
    rmmod xxx.ko
查看内核模块符号表
    cat /proc/kallsyms
    cat /proc/ksyms
查看内核缓冲区
    dmesg
查看开启的保护
    cat /proc/cpuinfo


2.2 驱动开发

一般情况下，驱动模块由以下部分组成：


头文件（必选）
头文件一般至少包含以下三个：
#include <linux/module.h>
#include <linux/init.h>
#include <linux/kernel.h>
模块参数（可选）

即驱动模块加载时需要传递给驱动模块的参数。例如一个驱动需要完成两种功能，那么可以通过模块参数选择完成哪一种功能。

模块加载函数（必须）

即模块加载时，需要执行的函数，这是模块的初始化函数，就如main()函数一样。

模块卸载函数（必须）

即模块卸载时，需要执行的函数，可以清除加载函数里分配的资源。

模块许可声明（必须）

模块许可声明表示模块受内核支持的程度，需要使用MODUEL_LICENSE表示该模块的许可权限。内核可识别的许可权限有：

MODUEL_LICENSE("GPL") /*任一版本的GNU公共许可权*/
MODUEL_LICENSE("GPL v2") /*GPL版本2许可权*/
MODUEL_LICENSE("GPL and additional rights") /*GPL及其附加许可权*/
MODUEL_LICENSE("Dual BSD/GPL") /*BSD/GPL双重许可权*/
MODUEL_LICENSE("Dual MPL/GPL") /*MPL/GPL双重许可权*/
MODUEL_LICENSE("Proprietary") /*专有许可权*/

如果一个模块没有包含任何许可权，会被认为不合规范。

因此有如下框架代码：

#include <linux/kernel.h>
#include <linux/module.h>
#include <linux/init.h>

init __init xxx_init(void)
{
    /*这里是模块加载时的初始化工作*/
    return 0;
}

void __exit xxx_exit(void)
{
    /*这里是模块加载时的销毁工作*/
}
module_init(xxx_init); /*指定模块的初始化函数的宏*/
module_exit(xxx_exit); /*指定模块的卸载函数的宏*/
MODUEL_LICENSE("GPL")


2.3 字符设备驱动

设备类型分为字符设备、块设备和网络设备：
  • 字符型设备是指能一个字节一个字节读取数据的设备，如键盘、鼠标等。
  • 块设备一般是像磁盘一样的设备。
  • 网络设备主要负责主机间数据交换

可以通过查看/dev/下文件属性进行识别：

第一位c表示字符型设备，b表示块设备，2、3、4字段对于驱动开发没有影响，5、6字段表示主次设备号，之后是最后修改时间及设备名。其中主次设备号统称设备号，主设备号表示某种特定的驱动程序，次设备号用来表示使用该特定驱动的各个设备。


2.3.1 设备号


查看设备号
cat /proc/devices

申请设备号
静态申请使用register_chrdev_region()函数，动态申请使用alloc_chrdev_region()函数：
int register_chrdev_region(dev_t from, unsigned count, const char *name);
int alloc_chrdev_region(dev_t *dev, unsigned baseminor, unsigned count, const char *name);

静态申请from是要分配的设备号的起始值，count是需要申请的连续设备号的个数，name是和该范围编号关联的设备名称。执行成功返回0，错误时返回负的错误码。

动态申请dev作为输出参数，在执行成功后将保存已经分配的设备号，如果申请一段连续的设备号则dev返回第一个设备号。baseminor表示要申请的第一个设备号，通常设置为0，count和name与静态申请相同。
释放设备号

void unregister_chrdev_region(dev_t from, unsigned count);

其中from表示要释放的设备号，count表示从from开始要释放的设备号个数。


2.3.2 cdev结构

在Linux内核中，使用cdev结构体来描述一个字符设备，cdev结构体的定义如下：

<include/linux/cdev.h>
struct cdev { 
    struct kobject kobj;                  //内嵌的内核对象.
    struct module *owner;                  //该字符设备所在的内核模块的对象指针.
    const struct file_operations *ops;           //该结构描述了字符设备所能实现的方法，是极为关键的一个结构体.
    struct list_head list;                 //用来将已经向内核注册的所有字符设备形成链表.
    dev_t dev; //字符设备的设备号，由主设备号和次设备号构成.
    unsigned int count; //隶属于同一主设备号的次设备号的个数.
};

简单来说，当程序打开设备文件A，系统就会产生一个inode节点，可通过其i_cdev字段找到cdev字符结构体，再通过cdev结构体的ops指针找到file_operations结构，即对设备A的操作函数。

在字符设备的加载函数中，应该实现对字符设备号的申请和对cdev的注册，相反，在字符设备的卸载函数中，应该实现字符设备号的释放和cdev的注销，对于cdev通常还会包括特定设备的特定信息，这些信息会和cdev本身信息封装在一起形成新结构体。例如如下代码：


struct xxx_dev                                                              /*自定义设备结构体*/
{
    struct cdev cdev;                                                     /*cdev结构体*/
    ... /*特定设备的特定数据*/
};
static int __init xxx_init(void)                                            /*设备驱动模块加载函数*/
{
    ...
    /*申请设备号，当xxx_major不为0时表示静态指定；当为0时表示动态申请*/
    if(xxx_major)
        result = register_chrdev_region(xxx_devno, 1, "DEV_NAME"); /*静态申请设备号*/
    else
    {
        result = alloc_chrdev_region(xxx_devno, 0, 1, "DEV_NAME"); /*动态申请设备号*/
        xxx_major = MAJOR(xxx_devno); /*获得申请的主设备号*/
    }
/*初始化cdev结构，传递file_opretions结构指针*/
    cdev_init(&xxx_dev.cdev, &xxx_fops);
    dev->cdev.owner = THIS_MODULE; /*指定所属模块*/
    err = cdev_add(&xxx_dev .cdev, xxx_devno, 1) /*注册设备*/
}
static void __exit xxx_exit(void) /*模块卸载函数*/
{
    cdev_del(&xxx_dev.cdev); /*注销cdev*/
    unregister_chrdev_region(xxx_devno, 1); /*释放设备号*/
}


2.3.3 file_options结构体

file_operations结构体中的成员函数都对应着驱动程序的接口，用户可以通过内核来调用这些接口，从而控制设备，大多数字符设备驱动都会实现read()、write()和ioctl()三个函数，以read()为例。

/*文件操作结构体*/
static const struct file_operations xxx_fops = 
{
    .owner = THIS_MODULE, /*模块引用，任何时候都赋值THIE_MODULE*/                 
    .read = xxx_read, /*指定设备的读函数*/
};
/*读函数*/
static ssize_t xxx_read(struct file *filp, char __user *buf, size_t size, loff_t *ppos)
{
    ...
    copy_to_user(buf, ..., ...); /*使用copy_to_user()将内核态数据拷贝到用户态，一般用于数据较大，较小时使用put_user()效率较高*/
    ...
}



总结

这块内容先介绍这么多，后续会介绍内核模块编写，其实对于出题来说，以上内容了解即可，因为真正的功能也好漏洞也罢，一般出现在一些模块功能函数中，而相比之下，从代码实现的角度讲模块加载函数中如何实现对设备的申请注册，模块卸载函数如何实现对设备的删除释放实际上没有本质区别，完全可以照搬，真正题目分析一般也不会关注这块的内容，而题目编写则更是考验对模块功能函数的设计实现。
