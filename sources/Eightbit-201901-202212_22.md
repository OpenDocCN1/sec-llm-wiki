### **1.1 内核**

内核是操作系统的核心，扮演的是夹在硬件和软件中间的那个角色，说白了就是管理硬件设备，为应用程序提供运行环境。通常情况下，硬件设备包括CPU、内存、硬盘、I\\O设备等等。内核基本上分为两种：单内核和微内核。Windows       NT内核和Mach（Mac OS X 的组成部分）是微内核结构，Linux内核是单内核结构。

|   
 || 原理  
 || 优势  
 || 劣势  
 |
| --- | --- | --- | --- |
| 单内核 || 整个内核都在一个大内核地址空间上运行。 || 1\. 简单。2. 高效：所有内核都在一个大的地址空间上，所以内核各个功能之间的调用和调用函数类似，几乎没有性能开销。 || 一个功能的崩溃会导致整个内核无法使用。 |
| 微内核 || 内核按功能被划分成各个独立的过程。每个过程独立的运行在自己的地址空间上。 || 1\. 安全：内核的各种服务独立运行，一种服务挂了不会影响其他服务。 || 内核各个服务之间的调用涉及进程间的通信，比较复杂且效率低。 |

**简单讲就是：**单内核所有事情都自己做，效率高但是体积大；微内核统领全局，把任务交给手下干，效率低但是体积小。linux虽然是单内核，但是经过多年发展，也具备一些微内核的特性，比如：支持动态加载内核模块模块。

### **1.3 Ring Model**

kernel pwn不同于linux pwn，后者是通过与程序交互尝试获取shell，只要获得shell也就拿到了flag，而前者是给你一个shell，不过是降权的shell，只有当你实现提权才能查看flag。这里简单介绍一下特权模式，intel CPU 将 CPU 的特权级别分为 4 个级别：Ring 0, Ring 1, Ring 2, Ring 3。Ring 0 只给 OS 使用，Ring 3 所有程序都可以使用，内层 Ring 可以随便使用外层 Ring 的资源。大多数的现代操作系统只使用了 Ring 0 和 Ring 3。  

![](../Images/5f05cef79f345b206849061ab4d63f7e.png)

由于特权分离，导致内核态的数据和代码与用户态的数据与代码被对方访问或执行时会受到限制，正常程序进入kernel态之前会保存用户态的各个寄存器，以及执行到代码的位置。从kernel返回到用户态会执行swapgs（64位）和 iret 指令，当然前提是栈上需要布置好恢复的寄存器的值。

0x2 linux驱动开发  

  
LKMs(Loadable Kernel Modules)称为可加载核心模块(内核模块)，其可以看作是运行在内核空间的可执行程序，因为其可以动态加载到内核中而无需重新编译内核，因此常被作为驱动程序，除此之外，还会被用作内核功能扩展。内核模块其实也是一种程序，其文件格式与用户态文件格式相同，即linux下为elf，windows下为exe/dll。

**内核模块程序和普通程序的区别如下：**

|   
 || C语言应用程序 || 内核模块程序 |
| --- | --- | --- |
| 使用函数 || libc库 || 内核函数 |
| --- | --- | --- |
| 运行空间 || 用户空间 || 内核空间 |
| 运行权限 || 普通用户 || 超级用户 |
| 入口函数 || main() || module\_init() |
| 出口函数 || exit() || module\_exit() |
| 编译 || gcc || gcc |
| 运行 || 直接运行 || insmod |

### **2.3 字符设备驱动**

设备类型分为字符设备、块设备和网络设备：

*   字符型设备是指能一个字节一个字节读取数据的设备，如键盘、鼠标等。
*   块设备一般是像磁盘一样的设备。
*   网络设备主要负责主机间数据交换

可以通过查看/dev/下文件属性进行识别：

![](../Images/3b1aa9ce9508ad611d45fed1e35a0306.png)

第一位c表示字符型设备，b表示块设备，2、3、4字段对于驱动开发没有影响，5、6字段表示主次设备号，之后是最后修改时间及设备名。其中主次设备号统称设备号，主设备号表示某种特定的驱动程序，次设备号用来表示使用该特定驱动的各个设备。

#### **2.3.2 cdev结构**

在Linux内核中，使用cdev结构体来描述一个字符设备，cdev结构体的定义如下：

```

<include/linux/cdev.h>struct cdev {
 struct kobject kobj;                  //内嵌的内核对象.
struct module \*owner;                  //该字符设备所在的内核模块的对象指针.
const struct file\_operations \*ops;           //该结构描述了字符设备所能实现的方法，是极为关键的一个结构体.
struct list\_head list;                 //用来将已经向内核注册的所有字符设备形成链表.
dev\_t dev; //字符设备的设备号，由主设备号和次设备号构成.
unsigned int count; //隶属于同一主设备号的次设备号的个数.

```

简单来说，当程序打开设备文件A，系统就会产生一个inode节点，可通过其i\_cdev字段找到cdev字符结构体，再通过cdev结构体的ops指针找到file\_operations结构，即对设备A的操作函数。
