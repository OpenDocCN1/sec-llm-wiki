漏洞信息：https://cwiki.apache.org/confluence/display/WW/S2-052

当Struts2使用了 Struts2-Rest-Plugin 插件时，如果http请求的 Content-type 为 application/xml ，则会使用 XStreamHandler 解析器实例化 XStream 对象来反序列化处理我们传入的XML数据，且在默认情况下是可以引入任意对象的（针对1.5.x以前的版本），因此我们可以通过反序列化引入任意类造成远程命令执行漏洞。

漏洞复现

影响范围

Struts 2.1.2 - 2.3.33，Struts 2.5 - 2.5.12

漏洞分析

Struts2-Rest-Plugin 是让Struts2能够实现 Restful API 的一个插件，其根据 Content-Type 或 URI 扩展名来判断用户传入的数据包类型，可以看到 xml 格式的处理器对应 org.apache.struts2.rest.handler.XStreamHandler

  1. <!--struts-plugin.xml-->
  2. <bean type="org.apache.struts2.rest.handler.ContentTypeHandler" name="xml" class="org.apache.struts2.rest.handler.XStreamHandler" />
  3.     <bean type="org.apache.struts2.rest.handler.ContentTypeHandler" name="json" class="org.apache.struts2.rest.handler.JsonLibHandler" />
  4.     <bean type="org.apache.struts2.rest.handler.ContentTypeHandler" name="html" class="org.apache.struts2.rest.handler.HtmlHandler" />
  5.     <bean type="org.apache.struts2.rest.handler.ContentTypeHandler" name="x-www-form-urlencoded" class="org.apache.struts2.rest.handler.FormUrlEncodedHandler" />
  6.     <bean type="org.apache.struts2.rest.handler.ContentTypeHandler" name="multipart/form-data" class="org.apache.struts2.rest.handler.MultipartFormDataHandler" />

toObject 方法调用 XStream 反序列化XML获得对象，fromObject 方法调用 XStream 序列化对象为XML。

在 Struts2-Rest-Plugin 插件的拦截器 org.apache.struts2.rest.ContentTypeInterceptor 中下断点。获取到请求解析器之后，如果请求体长度不为0则调用其 toObject 方法。

然后就到了 XStreamHandler 的 toObject 方法中，并调用 xstream.fromXML(in, target); 把我们传入的XML数据进行反序列化且并没有做任何限制。

前面的触发流程很简单，后面主要就是XML反序列化payload构造。java unmarshal 反序列化利用工具 marshalsec 可以生成 XStream 的很多 gadgets。

上面的poc利用的是 ImageIO 这条gadgets。

  1. java -cp target/marshalsec-0.0.3-SNAPSHOT-all.jar marshalsec.XStream ImageIO calc

调用栈

XStream反序列化的逻辑，实际上是解析XML DOM重组对象的一个过程。流程比较复杂，这里仅大致写一下。

跟到 MapConverter 中的 putCurrentEntryIntoMap 方法

因为我们最终将 NativeString 对象放到了 hashMap 里然后对 hashMap 进行序列化，所以当反序列化重组对象的时候，会触发NativeString 的 hashCode 方法。

  1. public int hashCode() {
  2.         return this.getStringValue().hashCode();
  3. }
  4. private String getStringValue() {
  5.         return this.value instanceof String ? (String)this.value : this.value.toString();
  6. }

这里的 value 是payload中传入的 com.sun.xml.internal.bind.v2.runtime.unmarshaller.Base64Data 的对象，所以进入 Base64Data 的 toString() 方法，跟进 get 方法。

  1. public String toString() {
  2.     this.get();
  3.     return DatatypeConverterImpl._printBase64Binary(this.data, 0, this.dataLen);
  4. }

解析出我们传入的 dataSource 对象并返回 CipherInputStream 对象，然后传给 baos.readFrom()

继续跟到 FilterIterator 的 next 方法，advance 会调用 FilterIterator$Filter 的 filter() 方法。此时的 FilterIterator$Filter 是我们传入的 javax.imageio.ImageIO$ContainsFilter 。

  1. public T next() {
  2.     if (next == null) {
  3.           throw new NoSuchElementException();
  4.     }
  5.     T o = next;
  6.     advance();
  7.     return o;
  8. }
  9. private void advance() {
  10.     while (iter.hasNext()) {
  11.       T elt = iter.next();
  12.       if (filter.filter(elt)) {
  13.         next = elt;
  14.         return;
  15.       }
  16.     }

  18.     next = null;
  19. }

参数 elt 则是我们payload中传入的 java.lang.ProcessBuilder 对象，最终调用 javax.imageio.ImageIO$ContainsFilter的 filter 方法反射执行命令，其中的 method 也是我们传入的 java.lang.ProcessBuilder 类的 start 方法。

漏洞修复

在 XStreamHandler 类中修改了 createXStream 方法

  1. protected XStream createXStream(ActionInvocation invocation) {
  2.     XStream stream = new XStream();
  3.     LOG.debug("Clears existing permissions");
  4.     stream.addPermission(NoTypePermission.NONE);

  6.     LOG.debug("Adds per action permissions");
  7.     addPerActionPermission(invocation, stream);

  9.     LOG.debug("Adds default permissions");
  10.     addDefaultPermissions(invocation, stream);
  11.     return stream;
  12. }

新添代码的主要作用是将 xml 中的数据白名单化，把 Collection 和 Map、一些基础类、时间类放在白名单中，这样就能阻止 XStream 反序列化的过程中带入一些有害类。

  1. private void addPerActionPermission(ActionInvocation invocation, XStream stream) {
  2.     Object action = invocation.getAction();
  3.     if (action instanceof AllowedClasses) {
  4.         Set<Class<?>> allowedClasses = ((AllowedClasses) action).allowedClasses();
  5.         stream.addPermission(new ExplicitTypePermission(allowedClasses.toArray(new Class[allowedClasses.size()])));
  6.     }
  7.     if (action instanceof AllowedClassNames) {
  8.         Set<String> allowedClassNames = ((AllowedClassNames) action).allowedClassNames();
  9.         stream.addPermission(new ExplicitTypePermission(allowedClassNames.toArray(new String[allowedClassNames.size()])));
  10.     }
  11.     if (action instanceof XStreamPermissionProvider) {
  12.         Collection<TypePermission> permissions = ((XStreamPermissionProvider) action).getTypePermissions();
  13.         for (TypePermission permission : permissions) {
  14.             stream.addPermission(permission);
  15.         }
  16.     }
  17. }

  19. protected void addDefaultPermissions(ActionInvocation invocation, XStream stream) {
  20.     stream.addPermission(new ExplicitTypePermission(new Class[]{invocation.getAction().getClass()}));
  21.     if (invocation.getAction() instanceof ModelDriven) {
  22.         stream.addPermission(new ExplicitTypePermission(new Class[]{((ModelDriven) invocation.getAction()).getModel().getClass()}));
  23.     }
  24.     stream.addPermission(NullPermission.NULL);
  25.     stream.addPermission(PrimitiveTypePermission.PRIMITIVES);
  26.     stream.addPermission(ArrayTypePermission.ARRAYS);
  27.     stream.addPermission(CollectionTypePermission.COLLECTIONS);
  28.     stream.addPermission(new ExplicitTypePermission(new Class[]{Date.class}));
  29. }

  31. private static class CollectionTypePermission implements TypePermission {

  33.     private static final TypePermission COLLECTIONS = new CollectionTypePermission();

  35.     @Override
  36.     public boolean allows(Class type) {
  37.         return type != null && type.isInterface() &&
  38.           (Collection.class.isAssignableFrom(type) || Map.class.isAssignableFrom(type));
  39.     }

  41. }
