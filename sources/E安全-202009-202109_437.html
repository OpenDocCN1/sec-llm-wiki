No.1

前言

问题：

抓包时，安装burp suite的CA证书，但有时app不信任第三方发行证书时，无法抓到https通讯流量。

国外有人尝试4种MITM中间人，修改流量方法:

  1. 自定义CA添加到受信任的证书存储中（只适合Android 6.0及以下）

  2. 自定义CA证书覆盖打包（用apk studio用自定义CA覆盖UniversalRootCA证书）

  3. frida hook和绕过ssl证书检查

  4. 逆向自定义证书代码

这时尝试SSL Pinning，绕过验证，需要hook应用程序的代码。

方法一 SSL pinning 绕过

1.使用模拟器，已root，android版本为6.0

以下示例是Frida JavaScript脚本的简化版本：

var so = Java.use("o.so");

    so.a.overload().implementation = function(){

}

劫持了该方法，并使其始终返回true。

2.绕过SSL固定的尝试基于SSLContext操作

将SSL Pinning Java代码移植到了Frida JavaScript。

1. 从设备加载我们的恶意CA证书
2. 创建包含信任的CA的自己的KeyStore
3. 创建一个信任我们的KeyStore中的CA的TrustManager

当应用程序初始化其SSLContext时，我们劫持了SSLContext.init（）方法，并在调用该方法时，将第二个参数（即应用程序TrustManager）与我们先前准备的我们自己的TrustManager 交换。（SSLContext.init（KeyManager，TrustManager，SecuRandom））。

这样，我们基本上将应用程序重新固定到我们自己的CA！
