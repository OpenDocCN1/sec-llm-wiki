# 前言

在远古时代用python3.5写过一个用 `socket`实现类似ftp的程序，前天部署在阿里云的时候发现报错了，在上传文件的时候，发现沾包了，后来当天写了一篇文章解决了一下这个问题。

当时的解决方法是，在发送数据后，加一个 `time.sleep(3)`停止三秒，让服务器那边先响应过来，然后再发送文件内容过去

后来 `胖虎`大佬在微信上给了一个新的解决方案（膜拜dalao Orz）

![](../Images/1f51e21d299f83c3b8276f4e04a55433.png)

  

在我原本的程序中，服务器从客户端那里接收了数据（文件大小）后，开始接收文件内容

但是因为服务器没响应过来，所以导致了后面的数据（文件内容）和第一个包的数据连在一起了

![](../Images/137243a2667908f4e9ea595ddfe7ef06.png)

  

画图说明一下

![](../Images/2704a2f09707d29452f03d764231a8ff.png)

  

我之前的做法是，给个时间让服务器响应过来就好了，但是这样治标不治本，假设那个时间后服务器还是没响应过来，那么这个沾包问题还是存在

而新的解决方法是，直接将字节大小这部分的数据固定住，利用模块 `struct`将数据包组包，这样一来，只需要接收4字节的数据就好了

![](../Images/a855f9071997a957f798526f97941b1c.png)

  

# 正文

获取了文件大小后，先将数据包进行组包然后发送

```
1.  `import struct`
    
2.  `filename=xxxx`
    
3.  `def encode_data(data):`
    
4.  `    return struct.pack('I',data)`
    
5.  `file_size=os.stat(filename).st_size`
    
6.  `client.send(encode_data(file_size))`
    
```

然后是服务端的事，反手写一个解码的程序，因为考虑到客户端可能因为找不到文件然后发送的数据为 `fail`，所以这里要加个判断

```
1.  `import struct`
    
2.  `receive_file_size = decode_data(conn.recv(4))`
    
3.  `def decode_data(data)；`
    
4.  `    if data.decode()==("fail"):`
    
5.  `        return data.decode()`
    
6.  `    else:`
    
7.  `        return struct.unpack('I',data)[0]`
    
8.  `if receive_file_size==("fail"):`
    
9.  `    print("file not found")`
    
10.  `else:`
     
11.  `    print(receive_file_size)`
     
```

这样就能接收关于数据大小的包和文件内容的包就区分开来了
