最近从天融信某表哥那了解到了神器工具Sysmon，这款工具第一眼看到就感觉很适合在应急响应中、后期对相关windows资产的行为监控。唯一觉得可惜的就是不能批量集中分析，需要一台一台的进行分析。  

Sysmon是由Windows Sysinternals出品的Sysinternals系列中的工具。它以系统服务和设备驱动程序的方法安装在系统上，并保持常驻性，是一款轻量级且强大的安全监控工具。

**运行于：**

客户端：Windows 7 及更高版本。

服务器：Windows Server 2008 R2 及更高版本。

![](../Images/936a888d39cfb656bcbf230d113441b5.png)

**1、安装使用**

**下载链接**：https://docs.microsoft.com/en-us/sysinternals/downloads/sysmon

里面很多详细的用法，可以去下载链接看下。看不懂英文就用谷歌或者翻译软件翻译一下。这边就不做详细的具体介绍了。

下载后解压，里面覆盖了32位和64位平台的程序。

![](../Images/c592eb845a57bf291a5b30516aa0ccdc.png)

简单看下用法。

![](../Images/049a9805537cf610ad423363a6507ac4.png)

**使用方法：**

安装：Sysmon.exe -i \[<configfile>\]

更新配置：Sysmon.exe -c \[<configfile>\])

安装事件清单：Sysmon.exe -m

打印模式：Sysmon.exe -s

解除安装：Sysmon.exe -u \[force\] -c

\-c 更新已安装的Sysmon驱动的配置，如果没有提供其他参数，则转储当前配置。

如果没有提供其他参数，则更新已安装的Sysmon驱动的配置或转储当前配置。可以选择取一个配置文件。

\-i 安装服务和驱动程序。可选择接受一个配置文件。

\-m 安装事件清单（在安装服务时也是如此）。

\-s 打印指定版本的配置模式定义。

指定'all'以转储所有模式版本（默认为最新版本））。

\-u 卸载服务和驱动。添加强制导致卸载继续进行

即使某些组件没有安装。

  

服务会立即记录事件，而驱动会作为启动驱动安装，以捕捉启动初期的活动。

在启动初期捕获活动，服务将在启动时写到事件日志。

 

在Vista和更高版本中，事件被存储在

"Applications and Services Logs/Microsoft/Windows/Sysmon/Operational"。在旧的系统中，事件被写到系统事件日志中。

 

使用'-? config'命令获取配置文件。更多的例子可以在Sysinternals网站上有更多的例子。

 

指定 -accepteula 来自动接受EULA否则，你将被交互式地提示你接受它。

 

安装和卸载都不需要重新启动。

 

**最常用的安装方式：**

sysmon -accepteula  –i -n

推荐使用大佬们配置好的配置文件，以下给出的配置文件链接预定义了高质量的事件跟踪模板：

https://github.com/SwiftOnSecurity/sysmon-config

**3、Sysmon辅助分析工具**

Sysmon虽然很方便，可以在日志管理中进行分析日志，但仍不够直观，查询不够方便快速，以下介绍的三款Sysmon辅助工具将大大提升使用Sysmon的日志分析工具时的效率。

 

Sysmon View：离线Sysmon日志可视化工具。#只能读取xml格式日志。

Sysmon Shell：Sysmon配置实用程序。

Sysmon Box：Sysmon和网络捕获日志实用程序。

 

下载地址：

https://github.com/nshalabi/SysmonTools

![](../Images/f2d127dbaaa1238f4b1052b1c9837f55.png)

**②**

**Sysmon Shell**

Sysmon Shell 可以通过简单的 GUI 界面帮助编写和应用 Sysmon XML 配置。

![](../Images/a60cc6df19a519ae92f4d15217ec3acd.png)

🔹 Sysmon Shell 还可用于探索 Sysmon 可用的各种配置选项，除了导出 Sysmon 事件日志外，还可以轻松应用和更新 XML 配置，简而言之：

🔹 Sysmon Shell 可以加载 Sysmon XML 配置文件：当前版本支持所有 Sysmon 模式。（该工具不直接从注册表加载任何配置，仅从 XML 文件加载）。

🔹 它可以将最终的 XML 导出/保存到文件中。

🔹 它可以通过Sysmon.exe -c command直接调用（在安装Sysmon的同一文件夹中创建一个临时的XML文件）来应用生成的XML配置文件，因此，如果使用该功能，Sysmon Shell将需要提升权限（这个需要继承来自 Sysmon 进程本身），应用配置的输出将显示在预览盘中（这是 Sysmon 生成的输出）

🔹 保存在预览窗格中之前可以预览 XML 配置

🔹 最后一个选项卡（标记为“日志导出”）可以方便地将 Sysmon 事件日志快速导出到 XML，稍后可以与“Sysmon 视图”一起用于事件分析，导出有三个选项：

🔹 仅出口

🔹 导出并清除 Sysmon 事件日志

🔹 导出、备份evtx文件并清除事件日志

🔹 该实用程序对取自 Sysmon Sysinternals 主页 ( https://docs.microsoft.com/en-us/sysinternals/downloads/sysmon ) 的所有事件类型进行了说明

🔹 Sysmon Shell捆绑了许多由其他安全专家创建的 Sysmon 配置模板

![](../Images/8146cdc1ed9216d220a78760d0b4b937.png)

**它不会做什么：**警告您关于包含/排除冲突或尝试验证规则本身，但是，一旦应用配置，预览窗格将显示应用配置时从 Sysmon.exe 捕获的输出（输出Sysmon -c command)，从中可以识别错误

说白了这个功能就是给大佬用的，咱们就用用别人配置好的就行了

![](../Images/478e76b4cbd87402c980858ecf829813.png)

**③**

**Sysmon box**

Sysmon Box 是一个小型实用程序，可以帮助构建捕获的 Sysmon 和网络流量的数据库。

![](../Images/8af03b16de9ec6c38cf82ab1c3c0dd7d.png)

要运行 Sysmon Box，请使用以下命令（Sysmon 需要与 tshark 一起启动并运行）：

SysmonBox -in Wi-Fi

**然后该工具将执行以下操作：**

🔹 开始捕获流量（在后台使用tshark，这就是为什么必须指定捕获接口的原因），完成后，按CTRL + C结束会话。这里需要注意一下如果wireshark不是默认安装的话，需要使用“-ts tshark路径包含文件名”来指定tshark进程。否则无法启动抓包。

🔹 然后，Sysmon Box 将停止流量捕获，将所有捕获的数据包转储到文件中，并使用 EVT 实用程序导出会话开始和结束时间之间记录的 Sysmon 日志

🔹 使用从 Sysmon 导入的日志和捕获的流量构建 Sysmon View 数据库（备份现有）文件，您所要做的就是从同一文件夹运行 Sysmon 视图或将数据库文件 (SysmonViewDB) 与 Sysmon View 放在同一文件夹中（保留数据包捕获在同一位置）

  

**使用范例：**

进入wireshark的安装目录，使用tshark或直接打开wireshark看哪个网卡是正在用的。

./tshark.exe -D #检测正在使用的网卡

![](../Images/a949ca6ed148a0567273e45da682825f.png)

在用的网卡是编号6

![](../Images/b201fb5c54ad87d12ab482d3020f9ff6.png)

完整命令“SysmonBox.exe -in 6 -ts tshark.exe路径”然后就会开始抓包。最底下的数字231是补货的数据包数量。

![](../Images/42ca2a1c7be1a1342a65c258fe6f975f.png)

结束后会生成对应的文件可以直接使用工具导入。非常好用！

![](../Images/611fbdc12ebecb684004f7e8811ca31a.png)
