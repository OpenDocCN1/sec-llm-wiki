nginx爆整数溢出漏洞

原文：http://mp.weixin.qq.com/mp/appmsg/show?__biz=MjM5NjA0NjgyMA==&appmsgid=10000133&itemidx=1&scene=27#wechat_redirect

今天，360安全团队的safe3在国外提交了一份报告，称近日发现了nginx的一个严重漏洞，该漏洞存在于nginx的ngx_http_close_connection函数，攻击者可以构造r->count小于0或大于255恶意HTTP请求，该漏洞可能会远程执行任意代码，据360透露，目前影响nginx所有版本。

节选一些微博转发网友评论：

淘李子  ：ngx_http_discarded_request_body_handler里面根本就没有count++操作。而是在请求没有读取完的时候，挂上这个回调的时候才会去+1，之后就不用再+1了，也就是只+1次。

Thomas：对溢出攻击完全不了解，但是有人看懂这个漏洞了么？文中说“The vulnerability is caused by a int overflow error within the Nginx ngx_http_close_connection function when r->count is less then 0 or more then 255"，可r->count的类型声明是 unsigned count:8，不懂。

github精选：ngx_http_read_discarded_request_body()接口读取客户端过来的请求体并丢弃。如果客户端并没有一次将请求体发过来，函数会返回，剩余的数据等到下一次读事件交给ngx_http_discarded_request_body_handler()来处理，这时， 外请求的引用数(r->count)++

根据国外最新公开的数据，Apache虽然仍然排名第一，但是Nginx已崭露头角，在排名前1000的网站中，Nginx占据了将近三分之一的席位（29.1%），已经取代了IIS（仅为12.7%）第二名的位置。

目前nginx官方尚未确认是否真的存在该漏洞，本站也将继续关注。
