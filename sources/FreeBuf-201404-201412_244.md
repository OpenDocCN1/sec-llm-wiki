# Discuz 5.x/6.x/7.x投票SQL注入分析

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MjM5NjA0NjgyMA==&mid=200439100&idx=1&sn=1a20d4eaa5ac7c51161cf15c9344c365&chksm=28e9e7b71f9e6ea13017d9186a38073c42a8ff084d48f806e594cfd8574d86116284c0d3f153&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MjM5NjA0NjgyMA==&mid=200439100&idx=1&sn=1a20d4eaa5ac7c51161cf15c9344c365&chksm=28e9e7b71f9e6ea13017d9186a38073c42a8ff084d48f806e594cfd8574d86116284c0d3f153&scene=27#wechat_redirect)

作者 diroverflow

  

看乌云有人爆了这个漏洞：http://www.wooyun.org/bugs/wooyun-2014-071516  

  

感觉应该是editpost.inc.php里投票的漏洞。因为dz已经确定不会再修补7.x以前的漏洞了，所以直接贴细节吧 。

  

问题出在 editpost.inc.php的281行，对用户提交的polloption数组直接解析出来带入SQL语句，因为默认只对数组值过滤，而不过滤键，所以会导致一个DELETE注入。

  

```
$pollarray\['options'\] = $polloption;
if($pollarray\['options'\]) {
if(count($pollarray\['options'\]) > $maxpolloptions) {
showmessage('post\_poll\_option\_toomany');
}
foreach($pollarray\['options'\] as $key => $value) { //这里直接解析出来没处理$key
if(!trim($value)) {
$db->query("DELETE FROM {$tablepre}polloptions WHERE polloptionid='$key' AND tid='$tid'");
unset($pollarray\['options'\]\[$key\]);
}
}
```

**利用方法：**

  

用注册账户发布一个投票帖子，然后点击“编辑”，如下图

  

![](../Images/583b9094bfdee960958626da0c354d44.png)

  

然后用burp拦截请求，点“编辑帖子”，修改其中的polloption为注入语句：

  

![](../Images/f51fc9a6c9791eddcf079efddf9c3db7.png)

  

因为代码判断trim($value)为空才执行下面的语句，所以一定要把范冰冰删掉。

  

返回结果已经成功注入了：

  

![](../Images/c17dcb46b4dc737d65b0cec6c5901d8f.png)

  

**修补方法：**

  

如果不方便升级到Discuz X的话，可以修改editpost.inc.php文件，增加一行：

  

```
$key=addslashes($key);
```
