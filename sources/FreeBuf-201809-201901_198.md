# WordPress Plugin Quizlord 2.0 XSS漏洞复现与分析

## 前言

**WordPress是使用PHP语言开发的博客平台，用户可以在支持PHP和MySQL数据库的服务器上架设属于自己的网站。也可以把 WordPress当作一个内容管理系统（CMS）来使用。**

WordPress经常爆出漏洞基本都是它的插件存在安全问题。

## 漏洞复现

首先搭建worepress，我的版本是4.4。然后进入后台下载插件Quizlord，版本是2.0。

![](../Images/c130495085f1eeb96ba879aff875e128.png)![](../Images/58c909a4d01224bef301961d7f64766b.png)下载、安装完成后，需要点击启用插件。

![](../Images/66fad6c4a07bf25f47bac0f94aadb5e6.png)根据exploit-db给出的漏洞详情，找到触发漏洞的位置。

![](../Images/b13705d7eb511fa7831d5e1fbf1aaa17.png)

进入后台选择Quizlord插件  
![](../Images/7293f2df7ce1adac556b68d5249b80cc.png)

此时浏览器的地址栏正好对应poc中的referer内容，现在只要使用火狐插件hackbar并根据POC构造POST请求。  
![](../Images/445e81f5463a5233da4c0b243bb0cddd.png)点击execute即可发送该POST请求。

![](../Images/837adce3b2030fff5ad30faadf14588a.png)请求成功后，返回是一个空白页。

![](../Images/dafc1e65d4dd56311d57cb12121b2b21.png)返回上一页并刷新即可触发该漏洞。

![](../Images/d2b912372c6fbec38d6bcbacc3247fa9.png)

通过复现这个漏洞，我们可以知道它属于后台存储型XSS，且它的危害其实并不是很大。

需要进入后台，因此必须得知道后台用户的账号和密码。

下面我们来简单分析一下漏洞的成因。

## 漏洞成因分析

WordPress插件源码位置：

```
\wp4_4\wp-content\plugins\
```

进入Quizlord插件目录，找到quizlord.php文件。

![](../Images/1fd3d00cd700b2cd813822fe796bbef1.png)下图是quizlord.php文件的内容

![](../Images/7d273dc6f90b0e27c51d3520e8268575.png)

根据POC快速定位到函数。发现POST传入的数据并没有被程序过滤就写入了数据库中。  
![](../Images/0b7b9662c33d6cbc82309d449e4f807d.png)

## 修复方案

利用htmlentities()函数转义html实体。

![](../Images/a94677768cd4095c1810a771af3034b1.png)再次提交POC后，无法触发XSS漏洞。
