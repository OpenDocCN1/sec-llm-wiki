# 利用graph.facebook.com中的反射型XSS实现Facebook账户劫持

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MjM5NjA0NjgyMA==&mid=2651079518&idx=3&sn=dfafc7f50ef157abddda80f00455284a&chksm=bd1fd1d58a6858c380ecabaef28b7f74b0d81ae37b0b6d9a96c65798109d8cde4ec9a3c30f2d&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MjM5NjA0NjgyMA==&mid=2651079518&idx=3&sn=dfafc7f50ef157abddda80f00455284a&chksm=bd1fd1d58a6858c380ecabaef28b7f74b0d81ae37b0b6d9a96c65798109d8cde4ec9a3c30f2d&scene=27#wechat_redirect)

**![](../Images/b667bb1e7f85ccabd3a9d8158c6dabef.png)**

**本文分享的是graph.facebook.com中存在的反射型XSS漏洞，攻击者利用该漏洞可以构造恶意链接引诱受害者访问，添加账户绑定邮箱或手机号，从而实现对受害者Facebook账户的劫持。**

## 漏洞情况

该漏洞只在IE和Edge浏览器中有效，漏洞原因在于graph.facebook.com中的某些API端点，在处理HTML代码响应时未实施完善安全的转义措施。响应消息存在于JSON格式中，HTML代码被当做其中一个字段的值也包含在内，而且响应消息不附带Content-Type 或 X-Content-Type-Options头，这样我就能有机会在IE/Edge中构造代码执行了。（这两类浏览器会扫描整个页面确定MIME文件类型，而其它浏览器只检查前几个字符）。

```

```

## 漏洞修复

> 1、在file\_type参数中加入对HTML代码处理的安全转义措施；
> 
> 2、给每个响应中加入“Content-type: application/json” 头避免进一步的攻击。
