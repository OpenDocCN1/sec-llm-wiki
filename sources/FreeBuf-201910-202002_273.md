# Apache Axis 1.4远程命令执行诡异探索之路

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MjM5NjA0NjgyMA==&mid=2651079367&idx=3&sn=12f3112c41a1bcade2b9cb78b8ad1687&chksm=bd1fd04c8a68595a907c49336634cf3d6ca87bfc5fb9a4913e640a5290d6cda30728b36b31f7&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MjM5NjA0NjgyMA==&mid=2651079367&idx=3&sn=12f3112c41a1bcade2b9cb78b8ad1687&chksm=bd1fd04c8a68595a907c49336634cf3d6ca87bfc5fb9a4913e640a5290d6cda30728b36b31f7&scene=27#wechat_redirect)

## 概述

**axis 全称Apache EXtensible Interaction System 即Apache可扩展交互系统。axis 为创建服务器端、客户端和网关SOAP等操作提供基本框架。axis 目前版本主要面向Java，面向C++的版本正在开发中。axis 并不完全是一个SOAP引擎，还可以作为一个独立的SOAP服务器和一个嵌入Servlet引擎（例如Tomcat）的服务器。**

## 本地漏洞复现

从apache axis官网下载1.4的版本。

在本地tomcat搭建，可以看到下载下来后的WBE-INF，其中并没有有些文档中写的server-config.wsdd文件

![](../Images/22e8c51e2327e24ef97fe7b6a63aa13b.png)然后去查看web.xml中的文件，也未打开AdminService的注释。

![](../Images/ab650ae261814fee9b7b0a3d0da4a16a.png)

此时我们直接本地利用poc来本地注册服务攻击，发现可以正常注册，并向服务对应的jsp文档里写入shell内容。

![](../Images/05c1e561a888fbb48c35039b682eb3f1.png)

注册完之后，此时是通过AdminService本地注册了一个RandomService服务，然后绑定了一个日志操作，日志操作将日志输入到一个jsp文件中，于是就可以构造操作去写日志，并执行jsp文件，造成远程命令攻击。

### 诡异的事情

**阶段一：**

根据漏洞利用的POC，先将本地之前利用的代码生成的webshell文件ha233.jsp删除，再在远程主机利用POC、此时将webshell的名称改为webshell.jsp，居然可以直接生成shell文档，且名称为ha233.jsp

删除本地利用时生成的webshell文件ha233.jsp

![](../Images/44bac1409fb65783374c8b468e52b97b.png)

再在虚拟机执行利用的exp，此时将webshell文件改名为webshell.jsp

![](../Images/bf879657c74a6588dfb03a719c65f8d7.png)

发现此时本地仍然生成了一个ha233.jsp

![](../Images/92e8bbf38cd391c9783aa381adcc7448.png)

查看tomcat服务器，日志中表明拒绝了远程IP访问的方式

![](../Images/c1ad79be7340498ac8221555868bf7cc.png)

通过上述的一系列操作，可以得知本地注册服务，远程是可以调用，但是仅仅如此嘛？

**阶段二**

与阶段一上边基本一致，但是此时我们将虚拟机里边的exp再次修改一下，将写的文件内容修改，命名仍为webshell.jsp，只是将参数改为hacker，本地的exp为c

![](../Images/8cd4b72ed45b8daed4f4df6135cfb5bb.png)  
查看写入到本地的webshell文件，肯定命名是ha233.jsp，但是内容却改变了，此时参数就为hacker

![](../Images/0e0496411245839b8c99562ccde2ed8d.png)

### 诡异的事情总结

在原生的状态下，可以从本地来注册服务，在注册的服务中绑定日志操作，且日志操作对应的日志文档为jsp文件时，可以从远程直接调用该服务，此时进行的操作都会记录到日志文件中，从而可以将jsp码写入其中。

**利用前提**

> 1.本地注册服务的名称要知道
> 
> 2.本地注册服务有日志记录，且日志记录使用jsp文件格式

## 远程漏洞复现

### 过程

在本地漏洞复现中，我们发现axis下载下来后并没有server-config.wsdd文件，但是在本地注册一个服务后，该文件就会出现

![](../Images/f13f0e6ae7859c1ce5c3fcd011bbdad2.png)

将该文件中的enableRemoteAdmin配置为true

![](../Images/9abf652e1f60071c18c8d4ae927584f5.png)

此时在虚拟机执行exp，可以看到正常注册一个服务，并写入shell.jsp文件

![](../Images/68e5d931537f94e8e2d130080d7ea200.png)

### 总结

通过我们的测试，发现只需要将server-config.wsdd文件中enableRemoteAdmin配置为true，就可以远程注册服务，并不需要将web.xml中的AdminServlet注释掉
