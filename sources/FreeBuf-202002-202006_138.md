# 发现Google Tez的XSS漏洞

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MjM5NjA0NjgyMA==&mid=2651083073&idx=4&sn=21b7e4df7db20bece851f14e32cef26d&chksm=bd1fc3ca8a684adcb945795391f55f1b4779fc6be539555ac71e093e690e95c32551bad23aae&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MjM5NjA0NjgyMA==&mid=2651083073&idx=4&sn=21b7e4df7db20bece851f14e32cef26d&chksm=bd1fc3ca8a684adcb945795391f55f1b4779fc6be539555ac71e093e690e95c32551bad23aae&scene=27#wechat_redirect)

![](../Images/b6edb2303106933eefa8b18e26294975.png)

**该篇Writeup讲述的是作者发现Google Tez网站的一个DOM based XSS漏洞，从而收获$3133.7奖励的经历，漏洞非常非常简单，我们一起来看看。**

某天，我使用了Knock Subdomain Scan和Sublist3r等其它工具去探测谷歌子域名信息，大致如下：

![](../Images/448fe8a1247c739ee9658fa871bebe41.png)

之后，我收集到了很多的谷歌在用子域名，有意思的是，当我访问其中的子域名https://tez.google.com/（现在已更名为Google Pay），我发现在其URL链接后包含了名为referrer\_id的赋值参数，看似是用来传递某些变量值。

我当即就用谷歌搜索大法来查找referrer\_id是否涉及到特定参数的链接，刚好有：

*   

```

```

![](../Images/1cd9afd940253d67a1f20142a5a8d219.png)

我想方设法对这个referrer\_id参数进行了构造利用，都不奏效。但是有意思的是，我发现referrer\_id的参数值会响应在https://tez.google.com/的页面中，如下：

![](../Images/9eda05af9a6a681aadf2546157ff7bf6.png)

于是，我顺手就往其参数值中构造插入了一个XSS Payload -

![](../Images/4dc0088daa64887526fa9752dda9af5e.png)

立马，我把该漏洞上报给了谷歌安全团队，之后，谷歌立即对该漏洞进行了分类并告知我漏洞等级和奖励赏金还需要等待评估。

![](../Images/e404cae51f9287e3312682ed3d545d3c.png)

数日过去，我终于收到了谷歌安全团队回复我的邮件，其中说明该漏洞只是一个DOM based XSS，但是谷歌还是奖励了我$3133.7。

![](../Images/7e6e30a1c91fef153596df92772b2dac.png)

按照谷歌漏洞奖励计划，我上报的漏洞符合以下“客户端代码执行”XSS部分的“谷歌一般应用”$3133.7奖励标准：

![](../Images/7b010f0e30eeaa856eeab8797a28ca04.png)

同时，我也被谷歌列入了漏洞名人堂的致谢名单：
