# Docker化自动采集&模拟恶意软件环境

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MjM5NjA0NjgyMA==&mid=2651107951&idx=3&sn=29ab31310ed03b181de7798626cec0d6&chksm=bd1f20e48a68a9f2ef8ab99c54e179c86baa6660fd90c66626f0ee9919c49b79717e0d3287fd&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MjM5NjA0NjgyMA==&mid=2651107951&idx=3&sn=29ab31310ed03b181de7798626cec0d6&chksm=bd1f20e48a68a9f2ef8ab99c54e179c86baa6660fd90c66626f0ee9919c49b79717e0d3287fd&scene=27#wechat_redirect)

## ****概述****

一个真实的Linux恶意软件入侵环境，往往包含有病毒文件、病毒进程、恶意启动项、网络通信流量等病毒项，若我们只获得单一的病毒文件，很难还原出恶意软件的整个攻击环境，从而不便于对攻击链进行全面的研究分析，以及产品安全能力测试。下面，介绍一种基于Docker的方法，可以自动化地采集及还原恶意软件的整个攻击场景，以最大程度地模拟主机中毒的环境，方便后续对恶意软件进行研究与分析。

该方法的原理是，使用bash脚本自动化收集中毒主机上的病毒项，然后打包成容器环境，最后通过Docker在本地模拟运行，这时生成的Docker容器就包含了完整的恶意软件环境。

![](../Images/2c5a3f3fde7151b5e514175bc2027f37.png)

## ****详细步骤****

如下，以StartMiner（8220挖矿家族）的中毒环境作为演示，通过命令可以看到主机中包含有恶意定时任务、病毒文件、病毒进程等信息。

![](../Images/a3a15806cc30fdaeb3e3ead4561853bb.png)

采集脚本具体的代码如下，主要采集以下目录的文件：

*   /tmp/、/root/、/opt/ 病毒文件常见目录
    
*   定时任务文件
    
*   ssh缓存文件
    
*   syslog和audit安全日志
    
*   进程信息
    
*   网络信息
    

![](../Images/3bd5e5069987623bce0a91e28bcf80a8.png)

然后自动化生产docker-compose.yml文件，用于一键创建docker容器。

![](../Images/17fbd8d3bf13dc8a7a109bcc90da9cdf.png)

malbox.sh脚本运行数秒后，即可打包好所有病毒项，生成文件malbox.tar.gz。

![](../Images/b563145b28168602b91446dceee78c1c.png)

将malbox.tar.gz在本地解压缩，malbox目录便包含Docker环境的所需的文件系统和配置文件，docker-compose.yml的功能为映射关键目录，及模拟执行恶意命令。在运行之前需要自定义下docker-compose.yml的信息，填上病毒家族名，以及启动时要运行的命令（可以参考ps.txt及netstat.txt填上需要模拟的病毒进程命令）。

![](../Images/db0f74d784984ba58c6f99a386ee8749.png)

修改完后，使用命令docker-compose up -d即可一键部署容器，查看容器列表，若出现了startmienr\_2010便说明容器运行成功了。

![](../Images/5d607342144d135d576e44928ea582f2.png)

恶意软件容器所使用的基础镜像为malbox，该镜像在ubuntu镜像基础上新增了恶意软件常用到的一些命令及服务（wget、curl、ssh、crontab等），以达到更好的模拟效果。

![](../Images/dd3d837f0960a23b84179a00c1043a7e.png)

使用docker exec -it startminer\_2010 /bin/bash命令，就能进入到容器，此时的环境就跟中毒主机的环境几乎一样了，可以在该环境中进行排查分析。

![](../Images/b3a3b12f8b86d1777d5ac1699c7ffa82.png)

查看进程，也能清晰地看到恶意的下载进程，以及CPU占用率极高的挖矿进程。

![](../Images/e837f6c3b06f1d9d6e8affb1548b173b.png)

容器中的syslog日志和audit.log日志，也有助于研究员对整个恶意软件的攻击链进行溯源。

![](../Images/8f4d9c64028f9467756536b7aa9b9f5c.png)

audit可以使用自定义规则进行监控，将可疑行为按照ATT&CK矩阵进行分类。

![](../Images/7975c8b22fabbfacc2078d71dc37c6b0.png)

## ****总结****

模拟出来的恶意软件容器，方便搭建及部署，若有蜜网或EDR环境，还可以将容器接入到其中以更好地检测收集恶意软件的恶意流量、恶意行为。
