# 揭秘APT团体常用的秘密武器——AsyncRAT

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MjM5NjA0NjgyMA==&mid=2651197833&idx=1&sn=5f50ad39820286b4f10d96107b11deb7&chksm=bd1d83028a6a0a14607676726a973095bbb41d6fc349ed0b7928eb9455e960561a27ddf6e01c&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MjM5NjA0NjgyMA==&mid=2651197833&idx=1&sn=5f50ad39820286b4f10d96107b11deb7&chksm=bd1d83028a6a0a14607676726a973095bbb41d6fc349ed0b7928eb9455e960561a27ddf6e01c&scene=27#wechat_redirect)

AsyncRAT 是 2019 年 1 月在 GitHub上开源的远控木马，旨在通过远程加密链接控制失陷主机，提供如下典型功能：

> 截取屏幕键盘记录上传/下载/执行文件持久化禁用 Windows Defender关机/重启DOS 攻击

GitHub 上提供了免责声明，但 AsyncRAT 仍然被许多攻击者，甚至是 APT 组织所广泛使用。Netskope 的研究人员最近发现了一个零检出的恶意脚本，该脚本通过 Amazon S3 存储桶下载 AsyncRAT 恶意软件。在分析时，VirusTotal 上的所有检测引擎都没有检出。  
![](../Images/daacfd13d25b1ae93e2bf14a628bd96b.png)【攻击链】

##   

## **阶段 01 - 零检出 Downloader**

起始的批处理脚本，就是 VirusTotal 零检出的文件。  
![](../Images/5f6b50a82ddb58b84503d4a91f76c9e9.png)【零检出 Downloader】  
尽管没有检测引擎检出，但该样本仍然能够被沙盒动态分析中的 Sigma 和 IDS 规则进行检出。  
![](../Images/7397d9ce805305bfa1c2aeb2547bd355.png)【Sigma 规则检测恶意行为】  
检测引擎未能静态检出可能是由于攻击者在文件中增加了超过一百个长字符串进行干扰。  
![](../Images/7eab7042f448d194220482788419a62e.png)【注释字符串】  
字符串都是相同的日文文本，翻译过来都是无用的废话。  
![](../Images/b5ea386690afe4f3d8bbad31891c7e8c.png)【文本翻译】  
恶意的命令反而非常简单，夹杂在无意义的长字符串间。经过了混淆也可能是导致没有检出的原因之一。  
![](../Images/fa806d6d2ca7cf10e1030c7a025178f6.png)【恶意命令】  
恶意命令通过 PowerShell 从 Amazon S3 存储桶下载并执行后续阶段攻击。

##   

## **阶段 02 - PowerShell**

从 Amazon S3 存储桶下载的文件是一个 PowerShell 脚本。它首先在 `C:\ProgramData`中创建一个名为 `Not`的文件夹。  
![](../Images/480492e3f1c99ecbc273b86016c3de9c.png)【创建目录】  
随后在目录中创建五个文件，链式执行另一个 PowerShell 脚本。  
![](../Images/e240e2b178d1869f48f23693d410ed35.png)【链式执行】  
最后一个 PowerShell 脚本中包含两个 PE 文件：  
![](../Images/622b8ee7c107acd8a47e0bad1719e601.png)【PowerShell 脚本】  
第一个文件名为 `RunPE`，第二个文件用于将 AsyncRAT 注入到的合法进程中。  
![](../Images/14f1062b2218f84883e17191760e94dc.png)【运行命令】  
PowerShell 脚本将 RunPE 直接加载到内存中，因此所有 PE 文件都不会落地。

##   

## **阶段 03 - RunPE**

该文件负责使用 Process Hollowing 技术将 AsyncRAT 注入另一个进程，攻击者使用 .NET 开发该恶意软件并使用 Confuser 进行加壳。  
![](../Images/f0cc36c4a677b1c745e104a25c6a9c29.png)【RunPE 文件信息】  
后续由 PowerShell 脚本将 RunPE 加载到内存中，调用 `Execute`方法。该方法接收可执行文件路径 `C:\Windows\Microsoft.NET\Framework\v4.0.30319\aspnet_compiler.exe`与参数中的 AsyncRAT 数据。  
![](../Images/8fe523338599113f1e9c3fe096544e88.png)【执行函数】  
去除混淆后，可以明确看出 AsyncRAT 是通过 Process Hollowing 注入的。  
![](../Images/f7516f7491cee19e1114cba855ff7152.png)【函数调用】

##   

## **阶段 04 - AsyncRAT**

AsyncRAT 样本在 2022 年 7 月 22 日编译。  
![](../Images/572adc62a96d58778a3fab5417634502.png)【AsyncRAT 样本】  
样本没有经过混淆，可以直接进行反编译。  
![](../Images/4b3f24c4138583c2ee6fc8f8f9b6c495.png)【反编译 AsyncRAT 样本】  
AsyncRAT 样本的主要执行流程如下所示：  
![](../Images/97b189697215968b9e72685ba13061a0.png)【多个方法】  
AsyncRAT 的配置在 `InitializeSettings`函数中被解密。  
![](../Images/8ee88ae4903d4272f5646417fa5c1072.png)【解密的配置参数】  
AsyncRAT 在 CBC 模式下使用 AES-256 算法来解密字符串：  
![](../Images/c9ac334e11b36d74c72414d854e7560f.png)【使用 AES 解密】  
该函数读取 base64 编码的字符串，前 32 个字节代表 HMAC，后面 16 个字节是解密向量 IV，其余字节是加密数据。  
![](../Images/000bdcefd5a057f284416743ad462e67.png)【加密数据】  
研究人员提供了解密 AsyncRAT 的 Python 脚本。  
![](../Images/14b197fb876fb65ef8402717ffd48d80.png)【配置解密】  
该样本并未启用反分析功能，但也使用了反虚拟化的技术，检查了硬盘大小、操作系统制造商和型号等。  
![](../Images/fe70525bf86576cc12a77a2aed86a0f9.png)【AsyncRAT 反分析】  
样本还通过注册表与计划任务来实现持久化。  
![](../Images/f33f18397f281c2a6c0fcb7dda7eb394.png)【持久化机制】  
AsyncRAT 将 C&C 地址和端口存储在其配置中，还提供了从 Pastebin 下载获取配置的选项。  
![](../Images/45ff7a4f72a3f35ed9539342146ca38d.png)【从 Pastebin 下载获取配置】  
AsyncRAT 与 C&C 服务器进行加密通信，通过界面控制设备。  
![](../Images/9bb580ca7cc5f9e7143c0a47ae97d10c.png)【AsyncRAT 控制面板】

## **结论**
