信息安全领域四大顶会——USENIX Security、S&P、NDSS、CCS，代表了信息安全领域研究的前沿方向，其论文涵盖的安全领域非常广泛，一直以来备受关注。我们将2022年四大顶会中与Fuzz技术相关的论文进行了统计，并对此次分享的论文在研究方向上进行了分类，以供大家查阅、参考。接下来就一起来看下论文及摘要情况吧。





StateFuzz: System Call-Based State-Aware Linux Driver Fuzzing


覆盖引导的模糊测试在软件漏洞挖掘领域取得了巨大成功。现有的覆盖引导的模糊测试工具普遍更倾向于能触发新代码的测试用例，同时会丢弃遍历相同代码的用例。然而，这种策略并不是最优解。遍历相同代码的新的测试用例可能会比之前的测试用例更好，因为它可能会触发程序新的状态，而这些状态对于代码遍历和漏洞挖掘都会更加有帮助。


本文评估了覆盖引导的模糊测试方法的局限性，并提出了一种状态感知的模糊测试方案：StateFuzz。本文首先用状态变量对程序状态进行建模，并且利用静态分析技术识别这些变量；接着指导目标程序跟踪这些变量的值并且在运行时判断程序状态转换；最后基于状态信息，优先考虑能够触发新的状态的测试用例，同时应用一个三维反馈机制对覆盖引导模糊测试器的进化方向进行微调。本文实现了一个StateFuzz原型，并在Linux驱动和安卓驱动上进行了评估。结果显示StateFuzz在覆盖新代码和挖掘漏洞方面均有效，发现了18个未知的漏洞和2个已知但是还没有进行修补的漏洞。相较于该领域最优的Syzkaller算法而言，提升了19%的代码覆盖率和32%的状态覆盖。



FIXREVERTER: A Realistic Bug Injection Methodology for Benchmarking Fuzz Testing


随着当前针对漏洞发布补丁速度的提升，模糊测试成为了一个热门的研究邻域。随之诞生的是一些基于经验的提问：他们能比现状表现的更好吗？这样的评估需要一个包含了良好定义的、真实漏洞的目标程序的基准。为了缓解构建这样的基准的困难，本文提出了FIXREVERTER，一个可以在程序中自动注入真实漏洞的工具。该工具将补丁模式作为输入，这个模式包含了代码的语法和语义条件。在满足语义条件的情况下，经过静态分析后，任何与特定语法（补丁语法）匹配的代码都将被删除，从而重新引入可能的漏洞。论文聚焦于研究三种特定的补丁模式，conditional-abort，conditional-execute，conditional-assign。这些模式是基于针对CVEs的一系列补丁的研究总结的。


本文利用FIXREVERTER建立了REVBUGBENCH，包含了向来自FuzzBench和Binutils的10个程序中注入的近8000个漏洞，并且展示了模糊测试评估的常见目标。论文将REVBENCH和FuzzBench服务结合起来，利用其评估了5个fuzzer，如预期，模糊测试的效果随着fuzzer和程序变化，总体来说，报告了219个特有的漏洞，其中19%的漏洞是同一个工具检测出来的。



FRAMESHIFTER: Security Implications of HTTP/2-to-HTTP/1 Conversion Anomalies


HTTP/2的接受度不断提高，但在实际应用中，互联网中较少使用端到端的HTTP/2通信。这是因为内容分发网络CDNs（Content Delivery Networks）和其他反向代理等一些在互联网生态中重要的常见组件，仅支持在客户端使用HTTP2，不支持在服务器上的前向连接。而代理技术主要依赖于连接的两个分支之间的HTTP/2到HTTP/1的协议转换。


本文首次系统性研究了HTTP2到HTTP1的协议转换中异常情况和安全问题产生的影响。针对HTTP2开发了一个新的基于语法的fuzzer，通过对HTTP2的帧序列和内容的操作，在12种流行的反向代理技术和CDNs上进行了实验，发现了大量新的web应用程序攻击向量，其可能导致请求黑洞、拒绝服务、致命查询和请求夹带攻击。



SGXFuzz: Efficiently Synthesizing Nested Structures for SGX Enclave Fuzzing


Intel的SGX（Software Guard Extensions）提供了一个不可入侵的可信执行环境。这项保护措施只有在个人enclaves是安全的前提下才能发挥作用。对于普通软件而言保证其安全性都是一项有挑战性的任务，当整个环境都是有潜在危险性时，保证enclaves的安全性就变得更加困难。同样，许多enclaves暴露了常见的漏洞，例如内存损耗和空指针引用等。模糊测试逐渐成为一种评估软件安全性的流行技术，但因为enclaves应该是不可入侵的，所以利用模糊测试对enclaves进行动态分析也是有难度的。同时，需要提供的输入是已分配的多指针结构，而不是普通的缓冲区。


论文提出SGXFuzz，一个以覆盖率为引导的fuzzer，这个fuzzer提出了一个新的二进制结构合成方法，在无法接触到源代码的前提下进行漏洞挖掘。为获得enclaves的代码覆盖率反馈，论文展示了如何从分布式结构中提取enclave代码。论文还提供了一个enclave运行程序，它允许以本地速度将提取的enclave代码作为用户空间应用程序执行，同时模拟enclave的所有相关环境交互。论文使用这种设置来利用最先进的快照fuzzing引擎，这个引擎部署了论文中新的结构合成阶段，以此对enclave进行模糊测试。该阶段基于故障信号，动态地合成多层指针结构和大小字段。此外，它在没有任何先验知识的情况下匹配enclave的预期输入格式。论文在30个开源和封闭源代码包上评估了所提出的方法，总共发现了79个新的bugs和漏洞。



AMPFUZZ: Fuzzing for Amplification DDoS Vulnerabilities


放大型DDoS攻击对互联网造成了极大的威胁，近期的攻击量级已经达到了Tbps。然而，迄今为止已知的所有放大型攻击都是由研究人员在实验室进行人工分析或者在大型攻击发生之后进行分析识别。但最理想状态还是在第一次攻击产生之前就能发现并减缓攻击向量。


本文提出了AMPFUZZ，首次系统的在UDP（User Datagram Protocol）服务中利用了协议无关的方式寻找放大型攻击向量。AMPFUZZ是基于目前最先进的灰盒测试技术，在新的UDP可感知基础上，显著的提升了性能。在28个Debian服务上进行了测试，发现了7个未知和6个未报告的放大型漏洞。



BARKTOOTH: Causing Havoc on Bluetooth Link Manager via Directed Fuzzing


论文提出、设计和评估了一种系统定向模糊测试，对任意蓝牙类设备的漏洞进行自动挖掘。该fuzzer首次利用了无线方式对主机的BT（Bluetooth Classic）的controller和baseband进行控制。可以拦截并修改任意数据包，同时还可以对底层封闭源的BT栈注入异常数据包，例如LMP(Link Manager Protocol)和baseband中。论文提出了一种在无线连接过程中，新的可扩展的基于规则自动构建协议状态机的方式。特别的，论文设计了一个简单的规则集对协议信息进行识别，可以动态建立一个抽象的协议状态机，对由状态产生的数据包进行模糊测试并且评估来自目标设备的有效回应。


迄今为止，一共测试了来自11个厂商的13个蓝牙设备，并且发现了18个安装错误，包含了24个常见的CVE。并且为了证明所提的框架在蓝牙设备之外的应用，论文对其他无线协议进行了模糊测试，同时挖掘了针对特定Wi-Fi和BLE主机栈的6个未知漏洞。



Fuzzing Hardware Like Software


硬件的漏洞具有更加持久和更强的影响力：硬件一旦制造完成就无法进行修复，并且硬件的任何漏洞都会破坏在其上运行的经过正规验证的软件。因此，对硬件设备的验证要在使用之前。由于硬件设备的设计规模大，对其进行设计验证的黄金法则是动态随机测试。然而，由于其无方向性的本质，这项技术的效率很低。


相较于实现大量对于现存的动态硬件验证方法的改进，我们利用了现有的软件fuzzer提供的方案，并且因此将其应用于硬件验证。特别的，我们将RTL（Register Transfer Level）硬件翻译为软件模型并且直接对这种模型进行模糊测试。我们解决的核心问题是如何减少硬件和软件执行模型之间的区别。这项工作包括了：（1）如何表示测试用例；（2）什么样的硬件和软件的crash是等价的；（3）一个合适的覆盖评估准则是怎样的；（4）如何为硬件制造一个通用的模糊测试harness。


为了评估我们的方法，我们设计、实现并且开源了Hardware Fuzzing Pipeline，这项工具可以在仅使用开源工具的基础上对一定规模的硬件进行模糊测试。我们从Google的OpenTitan中对五个IP块的Root-of-Trust chip、四个SiFive TileLink外围设备、三个RISC-V CPU和FFT加速器进行了模糊测试。实验显示，与传统的动态验证模式达到相同的有限状态机覆盖的情况下，本文提出的方案运行时间减少了两个数量级。同时，相较于之前的工作，提升了26.70%的HDL行覆盖。此外，通过我们以总线为中心的harness，在不提供初始种子的情况下，我们研究的五个OpeTitan的IPs中的四个都达到了超过83%的HDL行覆盖，并且能够检测我们在研究的五个OpenTitan IPs中植入的所有bug（四个合成错误Hack@DAC和一个真实的），耗时少于10小时。



SyzScope: Revealing High-Risk Security Impacts of Fuzzer-Exposed Bugs in Linux kernel


模糊测试已经成为最有效的软件bug发现方法之一。近年来出现了时长一周的连续模糊测试平台，用于测试软件的关键部分，如Linux内核。尽管其能够发现许多bug并提供复制程序(例如，概念证明)，但他们忽略了一个本应内置的关键功能，即评估bug的安全影响。众所周知，缺乏对安全影响的理解会导致bug修复和补丁传播的延迟。在本文中，我们开发了SyzScope，这是一个在给出看似“低风险”影响的bug时，可以自动发现新的“高风险”影响的系统。通过在syzbot上分析超过1000个低风险bug, SyzScope成功地确定了183个实际上包含高风险影响的低风险bug(超过15%)，例如控制流劫持和任意内存写入，其中一些仍然没有可用的补丁。



MundoFuzz: Hypervisor Fuzzing with Statistical Coverage Testing and Grammar Inference


管理程序是用于管理和运行虚拟机的系统软件。由于管理程序位于典型系统软件堆栈的最低层，所以它存在重大的安全隐患。因为管理程序拥有访问这些组件的所有权限，一旦管理程序受到攻击，在管理程序之上运行的整个软件组件（包括所有客户虚拟机和在每个客户虚拟机中运行的应用程序）也会受到损害。本文提出了MUNDOFUZZ，一种可以实现覆盖引导和语法感知的虚拟机管理程序fuzzer。我们发现，由于管理程序的异步系统事件处理，管理程序中的覆盖测量受到噪声的影响。为了滤除此类噪声，MUNDOFUZZ 开发了一种统计差分覆盖测量方法，允许 MUNDOFUZZ 捕获管理程序输入的干净覆盖信息。此外，我们观察到管理程序输入具有复杂的输入语法，因为其支持许多不同的设备且每个设备都有自己的输入格式。因此，基于给出不同的语法正确（或不正确）的输入管理程序会以不同方式运行的想法，MUNDOFUZZ 通过检查给定管理程序输入的覆盖特性来学习输入语法。我们使用流行的虚拟机管理程序QEMU和Bhyve评估MUNDOFUZZ，在覆盖率方面，MUNDOFUZZ以超出 4.91% 到 6.60% 不等的表现优于其他先进的虚拟机管理程序fuzzer。更重要的是，MUNDOFUZZ 发现了 40 个以前未发现的bug（包括9个CVE），证明了其在发现现实世界中的虚拟机管理程序漏洞方面的强大实用性。



TheHuzz: Instruction Fuzzing of Processors Using Golden-Reference Models for Finding Software-Exploitable Vulnerabilities


现代处理器日益增长的复杂性给硬件验证工具和安全关键漏洞检测方法带来了许多挑战。最近对处理器的攻击也展示了发现和利用硬件漏洞带来的致命后果。模糊测试已经成为一种很有前途的软件漏洞检测技术。最近，也提出了一些硬件模糊测试技术。但是，其受到一些限制，包括不适用于Verilog和VHDL等常用硬件描述语言 (HDL)、需要大量人工干预以及无法捕获许多内在硬件行为，例如信号转换和浮动线。在本文中，我们介绍了一种新的硬件模糊测试器TheHuzz的设计和实现，它克服了上述限制并显著提高了现有技术的性能表现。我们分析了HDL中硬件设计的内在行为，然后对这些行为建模并测量覆盖率。TheHuzz生成汇编级指令以增加覆盖率，以此从软件层面发现许多硬件错误。我们在四个流行的开源处理器上评估TheHuzz，与行业标准随机回归方法和先进的硬件模糊测试器DifuzzRTL相比，速度分别提高了 1.98 倍和 3.33 倍。使用TheHuzz，我们在这些处理器中检测到 11 个bug，其中包括 8 个新bug，并且对检测到的bug进行了利用。通过与Cadence JasperGold的发现进行比较，我们还表明TheHuzz克服了半导体行业形式验证工具的局限性。



Morphuzz: Bending (Input) Space to Fuzz Virtual Devices


整个云生态系统的安全性很大程度上取决于管理程序在客户虚拟机与主机系统之间提供的隔离保证。为了使得虚拟机能与环境通信，管理程序提供了大量的虚拟设备，包括网络接口卡和性能优化的VIRTIO-based SCSI适配器。由于这些设备直接位于管理程序的隔离边界并接收潜在的攻击者控制的输入(例如，来自恶意云租户的输入)，因此设备实现过程中的bug和漏洞有可能使管理程序的隔离失效。先前的工作将模糊测试应用于简单的虚拟设备，专注于巨大输入空间的一个狭窄子集，而最先进的虚拟设备fuzzer, Nyx需要精确的手动编写的规范来运行复杂的设备。在本文中，我们提出一种通用的MORPHUZZ，它利用对管理程序设计的深度了解与覆盖引导的模糊测试来发现虚拟设备实现过程中的bug。关键的是，MORPHUZZ不依赖于特定某个设备的专业知识。MORPHUZZ是第一个自动提取现代云中现实世界虚拟设备复杂I/O行为的方法。为了印证这种能力，我们在QEMU和bhyve中评估MORPHUZZ，并对33个不同的虚拟设备(前面的工作分析的16个设备的超集)进行模糊测试。此外，通过对3个额外的ARM设备模糊测试，证明 MORPHUZZ 不依赖于特定的 CPU 架构。对于13/16的虚拟设备，MORPHUZZ达到或超过Nyx获得的覆盖率，并识别出Nyx报告的所有崩溃(44)中的一个超集(110)。我们向开发人员报告了所有新发现的bug。值得注意的是，MORPHUZZ在没有初始种子输入或专家指导的情况下实现了这一点。



Fuzzware: Using Precise MMIO Modeling for Effective Firmware Fuzzing


随着嵌入式设备在日常生活中变得越来越普遍，它们也成为了攻击者的诱人目标。尽管它们价值高、攻击面大，但对其应用自动化测试技术(如模糊测试)却并不简单。由于在受约束的嵌入式设备上对固件进行模糊测试效率低下，因此最先进的方法选择在模拟器中运行固件(通过称为重托管的过程)。然而，现有的方法要么使用硬件行为的粗粒度静态模型，要么需要手动重新托管固件。因此，我们提出了轻量级程序分析、重新托管和模糊测试的新组合来应对这些挑战。我们提出了FUZZWARE的设计和实现，这是一个以可扩展方式对未修改单片固件进行模糊测试的软件系统。通过明确固件逻辑如何实际使用硬件生成的值，FUZZWARE可以自动生成模型来将模糊测试过程的重点放在改变重要的输入上，这大大提高了其有效性。我们在合成目标和现实目标上评估我们的方法，共包括19个硬件平台和77个固件映像。与最先进的工作相比，FUZZWARE实现了高达3.25倍的代码覆盖率，且建模方法减少了高达95.5%的输入空间大小。合成样本包含66个用于各种硬件交互的单元测试，本方法是第一个自动通过所有测试的通用重托管解决方案。FUZZWARE发现了15个全新的bug，包括之前由其他工作分析过的目标中的bug；共报告了12个CVE。



FuzzOrigin: Detecting UXSS vulnerabilities in Browsers through Origin Fuzzing


通用跨站脚本(UXSS)是一种浏览器漏洞，能够使易受攻击的浏览器在加载的任何网页上执行攻击者的脚本。UXSS 被认为是比经过充分研究的跨站点脚本(XSS)更严重的漏洞。这是因为UXSS不仅限于影响一个Web应用程序，而是只要受害者运行易受攻击的浏览器，它就会影响每个Web应用程序。我们发现UXSS漏洞很难找到，尤其是通过模糊测试，原因有以下两个。首先，检测UXSS具有挑战性，因为它是一个语义漏洞。对UXSS进行检测，需要了解网页之间复杂的交互语义。其次，很难生成触发UXSS的HTML输入，因为需要驱动浏览器执行复杂的交互和导航。本文旨在提出一种检测UXSS漏洞的浏览器fuzzer—— FUZZORIGIN。FUZZORIGIN通过以下方法来解决上述挑战：(i)设计具有静态源标记机制的源清理器(ii)生成处理专用事件的链式导航操作来优先处理源更新操作。我们实现了FUZZORIGIN，它适用于大多数现代浏览器，包括Chrome、Firefox、Edge和Safari。在评估过程中，FUZZORIGIN发现了四个以前未知的UXSS漏洞，一个在Chrome中，三个在Firefox中。这些漏洞都得到了供应商的确认，突出了其在发现新的 UXSS 漏洞方面的强大有效性。



Drifuzz: Harvesting Bugs in Device Drivers from Golden Seeds


现代计算机的外围硬件通常被认为是安全无恶意的，且设备驱动程序信任来自硬件的输入。然而，Broadpwn等最近发现的漏洞表明，攻击者可以通过易受攻击的外围设备来利用主机。这凸显了保护操作系统外围边界的重要性。在本文中，我们提出了一种针对WiFi和以太网驱动程序的无硬件且附带动态符号执行的 fuzzer，以及一种称为黄金种子的高质量初始种子的生成技术，其允许模糊测试在驱动程序初始化期间绕过困难的代码结构。与使用符号执行或灰盒模糊测试的先前工作相比，Drifuzz在自动查找允许网络接口完全初始化的输入方面更成功，并将WiFi驱动程序的模糊测试覆盖率提高了214%(3.1×)，以太网驱动程序提高了60%(1.6×)。在对14个PCI和USB网络驱动程序的实验中，我们发现了12个以前未知的bug，其中两个被指定为CVE。






Effective Seed Scheduling for Fuzzing with Graph Centrality Analysis


种子调度，即选择种子的顺序，可以极大地影响模糊器的性能。现有的方法基于种子的历史突变数据调度种子，但忽略了控制流图(CFG)的结构性质。可以通过检测观察CFG来预测某种子突变后提高代码覆盖的可能，从而为种子调度提供思路支持。


理想的策略是根据种子通过突变后所有的可达和可行边的数量来调度种子，但是计算所有边可行性时间空间开销均很大。因此，种子调度策略应当是一个近似值。我们观察到，一个近似计数应该有3个属性——(i)如果一个种子可以到达更多的边，数值应该增加;(ii)如果突变历史信息表明一个边缘很难到达或位于距离当前访问的边缘很远的地方，数值应该减少;(iii)这个近似计数的方法面对大型CFG的计算时，其计算成本应当是可以接受的程度。


我们观察到，来自图分析的中心性度量自然地提供了这三个属性，并可以大致提供种子变异后到达未访问边的可能性。因此，我们构建了一个称为边缘视界图的图，该图将种子与它们最近的未访问节点连接起来，并计算种子节点的中心性，以衡量突变种子带来的潜在边缘覆盖增益。


我们在K-Scheduler中实现了我们的方法，并与许多流行的种子调度策略进行了比较。我们发现，在谷歌FuzzBench程序上，K-Scheduler比Entropic增加了25.89%的特征覆盖率，比次最优的基于afl的种子调度器增加了4.21%的边缘覆盖率。它还多发现了3个以前未知的错误。



BEACON : Directed Grey-Box Fuzzing with Provable Path Pruning


基于覆盖的模糊处理对代码的每个部分给予同等关注，而与之不同的定向模糊处理，则是旨在将模糊器的测试方向指向代码中的特定目标，例如，具有潜在漏洞的代码。尽管这一方法目前取得了很大的进步，但我们观察到现有的定向模糊器仍然不够高效，因为它们经常象征性地或具体地执行大量无法到达目标代码的程序路径。因此浪费了大量的计算资源。


本文提出了一种名为BEACON的定向模糊测试方法，它能以一种可证明的方式有效地指导灰盒模糊器在极为复杂的路径中的工作。也就是说，在轻量级计算复杂度的静态分析的辅助下，计算达到目标的抽象前提条件后，我们可以在运行时删除82.94%的执行路径，分析开销可以忽略不计(少于5小时)，但要保证被修剪的路径必须是与目标相关的假路径。我们已经将BEACON成功运行起来，并将其运行结果与漏洞复制应用场景中的五种最先进的(定向的)模糊器进行了比较。评估结果表明，BEACON比现有的有向灰盒模糊器平均快11.50倍，还可以提高传统覆盖导向模糊器AFL、afl++和Mopt的速度，对特定bug的重现速度分别提高6.31倍、11.86倍和10.92倍。


更有趣的是，当用于测试漏洞补丁时，BEACON在现有的CVE识别地漏洞中发现了14个不完整的补丁和8个新bug，这其中有10个漏洞是可以被利用攻击的。



JIGSAW: Efficient and Scalable Path Constraints Fuzzing


覆盖引导的测试已经被证明是漏洞挖掘的有效方法。如果我们将覆盖引导测试建模为一个搜索问题(即寻找可以覆盖更多分支的输入)，那么它的效率主要取决于两个因素:(1)搜索算法的准确性(2)每单位时间可以评估的输入数量。因此，提高搜索吞吐量是提高覆盖引导测试性能的有效方法。


在这项工作中，我们提出了一种改进搜索吞吐量的新设计:使用JIT编译的约束路径来评估新生成的输入。这种方法可以显著提高单线程吞吐量，并扩展到多核。我们还开发了一些优化技术来消除这个过程中的主要瓶颈。


对我们的原型JIGSAW的评估表明，我们的方法可以实现比现有模糊器高三个数量级的搜索吞吐量，并可以扩展到多核。我们还发现，在如此高的吞吐量下，一个简单的梯度引导搜索启发式算法可以比使用更复杂的搜索启发式算法的SMT求解器更快地解决从大量实际程序中收集的路径约束。对端到端覆盖引导测试的评估也表明，我们的JIGSAW驱动的混合模糊器的分析效果优于最先进的测试工具。



PATA: Fuzzing with Path Aware Taint Analysis


污点分析通过推断有影响的输入字节，帮助模糊器解决复杂的模糊约束。


实际程序中的执行路径经常包含循环，这些循环中的约束可以被多次访问和记录。传统的污点分析技术在区分同一循环内相同约束的多次出现时遇到困难。在本文中，我们提出了PATA，一个实现路径感知污点分析的模糊器，即基于执行路径信息来区分多次出现的同一变量。PATA通过以下步骤做到这一点。首先，PATA识别约束中使用的变量，并构造代表变量序列(RVS)，由所有代表约束变量及其值的出现情况组成。接下来，PATA扰动输入，将其RVS与原始输入的RVS匹配，并查找值更改，以确定RVS中每个条目的影响输入字节。最后，PATA修改相应的输入字节，以解决给定路径中的约束。


为了证明PATA优于传统污染分析方法的有效性，我们在谷歌的fuzzer-test套件和LAVA-M的基准上对AFL、MOPT、TortoriseFuzz、VUzzer、Angora、REDQUEEN和GREYONE进行了性能评估。在谷歌的模糊器测试套件上，PATA在发现的唯一路径数量和覆盖的基本块数量上分别优于这些最先进的模糊器29%-1830%和7%-87%。更重要的是，它较之所比较的模糊器发现了更多的错误，包括17个未列出的错误。在LAVA-M上，PATA在所有评估的模糊器中表现最好，发现2602个bug。在开源项目中，PATA发现了40个之前未知的bug，其中12个被确认为cve。



FUZZUSB: Hybrid Stateful Fuzzing of USB Gadget Stacks


USB (Universal Serial Bus)是外设和移动设备(如U盘和智能手机)所支持的现实协议。对于许多设备来说，USB Type-C端口是充电，传输文件、音频、视频等的主要接口。因此，攻击者利用了USB堆栈中的不同漏洞，通过BadUSB攻击或从USB连接越狱的iphone从而危及主机。虽然有专门用于USB漏洞发现的模糊测试框架，但它们都专注于USB主机堆栈，而忽略了USB 配件堆栈，这些堆栈支持现代外设和智能设备中的所有功能。


在本文中，我们提出了FUZZUSB，这是第一个用于商品操作系统内核中的USB配件堆栈的模糊测试框架，利用静态分析、符号执行和状态进行模糊测试。


FUZZUSB结合静态分析和符号执行，从USB驱动程序中提取内部状态机信息，并利用它们通过多通道输入实现状态引导的模糊测试。我们在syzkaller内核模糊器上实现了FUZZUSB，并将其应用于最新的主流的Linux、Android和FreeBSD内核。结果，我们在Linux和Android内核中发现了34个之前未知的bug，其中8个确认为cve。此外，与baseline相比，FUZZUSB也展示了不同的改进，包括提高了3倍的更高的代码覆盖率，提高了50倍的Linux USB小工具堆栈的bug查找效率，提高2倍的FreeBSD USB小工具堆栈的代码覆盖率，并重现了作为baseline的模糊器无法检测到的已知bug。我们相信FUZZUSB为开发人员提供了一个强大的工具，以阻止现代设备中的USB相关漏洞，并完成当前的USB模糊范围。






COOPER: Testing the Binding Code of Scripting Languages with Cooperative Mutation


在商业软件中，binding layer链接高级语言脚本(python\js)和用于软件实现的低级语言(C\C++)。由于高级语言和低级语言两者之间的复杂性，binding layer部分的代码容易出现语义不一致和安全漏洞。现有测试binding layer代码的方式只关注到了脚本端，因此错过了与程序初始输入相关的bug。本文针对以上问题，提出了cooperative mutation-协同突变，首先基于语义相似度分析对程序初始输入中的类进行聚类，减少初始输入突变的空间。然后，依赖对执行路径的分析推断初始输入与脚本代码之间的关系。记录初始文件中的类和脚本代码，搜集应用打开初始文件之后的执行路径。如果执行成功与某些具体类高度相关，则判定这些类与脚本语言有关。最后，定义了一组使用推荐关系的突变策略来指导对象修改和脚本生成。在对Adobe Acrobat、Foxit Reader、Microsoft Word软件进行测试后,检测出了134个未知漏洞。其中33具有CVE编号。



MobFuzz: Adaptive Multi-objective Optimization in Gray-box Fuzzing


现有基于覆盖率的模糊测试无法同时为多个目标找到最优解。本文提出了一个多目标优化的灰盒模糊测试器MobFuzz。首先，将现有基于多目标的CGF（gray-box fuzzing）建模为 multi-player multi-armed bandit 问题。通过对目标组合建模为具有不同目标的player，以解决组合选择的问题，选择对当前模糊测试奖励最大的最佳组合。接着，将种子建模为bandit's arm，并将状态分为 探索和利用，通过自适应的能量分配算法，在特定的目标组合下，分配合适的能量给不同种子。最后，提出了非支配排序遗传算法，通过将目标组合转换为相应的变异算子的组合，设计了一种新的变异策略，更有可能增加目标值的突变体被选择的机会更大。此外还提出了共享种子池以减少性能开销。为了证明有效性，在真实程序和MAGMA数据集上进行了测试。实验表明，MobFuzz可以同时优化多个目标，最多增加了6%的程序覆盖率，与实验对象AFL、MemLock、FuzzFactory相比MobFuzz多发现了3倍的bug数量。



EMS: History-Driven Mutation for Coverage-based Fuzzing


基于突变策略产生测试用例的方式具有很强的随机性，从而降低了漏洞发现的概率。本文发现fuzzing history(正在执行的\已经结束的)中包含了丰富的变异策略信息，而这些信息中包含了发现稀有路径和崩溃的信息。从种子测试用例到触发唯一执行路径的突变用例之间，可能包含公共策略。这些策略导致特定的分支路径行为触发，这些行为同样可能存在于其他执行路径之中。为了利用这些信息，本文提出了PBOM模型。首先，将变异策略分为覆写、删除和插入。对于每个用于测试用例的变异策略，记录输入字节值、字节长度、突变类型和突变字节值。如果发现其触发了新的执行路径或者崩溃，将其记录到训练集中。然后，利用训练集去构建PBOM模型。PBOM模型根据输入的字节值和字节长度概率性地提供所需要的变异值和变异策略。为了验证PBOM模型的有效性，将其与AFL、QSYM、MOPT、MOPT-dict、EcoFuzz、AFL++在9个真实的目标上进行对比。实验表明，该设计可以发现更多的漏洞，在多数情况下可以发现更高的代码覆盖率。



Semantic-Informed Driver Fuzzing Without Both the Hardware Devices and the Emulators


现有的驱动模糊测试需要硬件支持或仿真模拟。搭建硬件环境需要大量的人力，而仿真模拟又无法支持大量的硬件类型。此外，这两种方式都无法生成大量合乎格式且能覆盖大量执行路径的输入。本文提出了一种新颖的不需要硬件设备支持的驱动模糊器DR.Fuzz。通过自动创建驱动程序初始化器，适当地构造设备相关的数据结构以通过代码路径中必须的验证。核心是一个语义信息机制，它推断各种语义信息，为后续验证生成有效输入。本文主要实现了一个不需要硬件设备支持的驱动模糊测试器原型DR.Fuzz，并在Linux驱动上进行测试。实验结果显示在24小时之内，在没有仿真和硬件支持的情况下成功运行214个驱动中的149个，而现有的其他驱动模糊器则一个都无法成功运行。在配备硬件环境或仿真器环境之后，与syzkaller相比，DR.Fuzz提高了70%的代码覆盖率和18%的吞吐量，同时还发现了46个新的bug



Registered Report: DATAFLOW Towards a Data-Flow-Guided Fuzzer


在现有的基于路径引导的灰盒模糊测试器中，大多都依赖控制流覆盖率去发现bug。但是控制流只是程序行为的一个粗粒度的描述。现有基于数据流覆盖驱动的模糊器研究相对较少，主要与污点分析、符号执行等重量级程序分析技术结合应用。而这些重量级的程序分析会大大降低效率和吞吐量。本文提出了一个由数据流驱动的轻量级灰盒模糊测试器DATAFLOW，此外还建立了一个关于数据流覆盖的框架，平衡精确度与计算成本。实验结果显示，在72%的测试目标上，以控制流驱动的模糊器的效果较好，但在控制流与语义解耦的测试目标上，以数据流驱动的模糊器体现出了一定的效果。



Context-Sensitive and Directional Concurrency Fuzzing for Data-Race Detection


现有针对并发的模糊测试研究中存在两个主要的限制。第一，使用上下文不敏感的覆盖率作为反馈，可能错过只发生在特定运行上下文中隐藏的数据竞争。第二，采用执行随机线程交错探索，频繁重复已经覆盖的线程交错，而遗漏了许多不常见的线程交错。本文提出了一种新颖的并发模糊测试框架CONZZER, 是上下文敏感的定向并发模糊测试方法。首先，该方法使用了一个新的并发覆盖率度量指标，将线程交错及其运行时调用上下文描述作为模糊反馈。其次，使用面向邻接指向突变和断点控制方法。面向邻接的突变算法根据已经覆盖的线程交错推断新的可能的线程交错。断点控制方法通过使用断点自适应地影响线程调度。此方法可以有效地覆盖具有具体上下文信息的不同线程交错，帮助发现难以找到的数据竞争。实验表明，CONZZER在8个最新版本的用户级程序以及Linux5.4的4个内核级文件系统中发现了95个真实的数据竞争，未出现误报，其中75个数据竞争被证实会对程序产生影响。






DriveFuzz: Discovering Autonomous Driving Bugs through Driving Quality-Guided Fuzzing


自动驾驶已经成为现实；价格在可承受范围内的半自动驾驶汽车已经出现在街道上，主要的汽车供应商正在积极开发全自动驾驶系统，以便在今后十年中部署它们。在向用户推出最终产品之前，测试和确保自动驾驶系统的安全性是至关重要的，自动驾驶系统由多个层面交织在一起组成的。然而，尽管影响安全的关键bug可能存在于任何层，甚至跨层，但相对而言，很少有人关注跨所有层去测试整个驾驶系统。之前的工作主要集中在单个层的白盒测试和防止对每个层的攻击。


在本文中，我们的目标是对自动驾驶系统进行整体测试，该系统具有完整的集成层。我们关注的不是各个层次，而是车辆的状态，即系统在驾驶环境中不断变化。这使得我们设计的新的系统模糊测试框架DriveFuzz可以发现潜在的任何位置的漏洞。DriveFuzz利用高保真驾驶模拟器，根据不同的因素自动生成和突变驾驶场景。我们基于现实世界的交通规则构建了新的驾驶测试oracle，以检测事关安全的关键错误行为，并通过参考车辆物理状态的驾驶质量指标来引导模糊器发现这些错误行为。


DriveFuzz在两个自动驾驶系统(Autoware和CARLA Behavior Agent)的不同层中发现了30个新bug，并在CARLA模拟器中发现了3个新bug。我们进一步分析了这些漏洞的影响，以及对手如何利用它们作为安全漏洞在现实世界中造成重大事故。



Jit-Picking: Differential Fuzzing of JavaScript Engines


提升用户体验感的需求驱动着为网站甚至Web上的完整应用程序提供支持的现代JavaScript引擎的发展。这些引擎使用几种复杂且容易出错的机制来优化其性能。不出所料，不可避免的复杂性导致了巨大的攻击面和各种类型的软件漏洞。在防御方面，模糊测试已被证明是发现不同类型的内存安全违规的宝贵工具。尽管很难以自动化的方式测试解释器和JIT编译器，但最近提出的基于语法或特定目标的中间表示的输入生成方法有助于发现许多软件错误。然而，JIT引擎中优化过程中产生的微妙的逻辑错误和计算错误仍然无法通过最先进的测试方法解决。虽然这些缺陷乍一看似乎没什么大不了的，但在实践中它们往往仍然是可以被利用的。在这篇论文中，我们提出了一种新的技术，以有效地在模糊测试中发现这类微妙的bug。关键思想是利用JavaScript引擎解释器与其对应的JIT编译器之间的紧密耦合作为特定领域的通用bug oracle，从而产生高度敏感的故障检测机制。我们在一个叫做Jit-Picker的工具中设计并实现了该方法的原型。在一种经验评估中，我们证明我们的方法能够检测到之前工作遗漏的微妙软件错误。我们总共发现了32个不为人知的bug，并从Mozilla获得了10,000美元的bug赏金，作为我们对JIT引擎安全性贡献的奖励。



LibAFL: A Framework to Build Modular and Reusable Fuzzers


AFL的发布标志着软件安全测试领域的一个重要里程碑，使模糊测试重新成为一个主要的研究课题，并推动了大量的研究以试图改进和评估模糊测试管道的不同方面。


其中的许多研究通过AFL代码库的各种分支实现了他们的技术。虽然这种选择一开始似乎是合适的，但将多个分支组合成一个模糊器需要很高的工程开销，这阻碍了该领域的进展，也阻碍了对不同技术的公平和客观的评估。模糊测试生态系统的高度碎片化也阻碍了研究人员将其与主体技术结合，使得端用户难以采用新的原型解决方案。


为了解决这一问题，本文提出了LibAFL框架来构建模块化的和可重用的模糊器。我们讨论了模糊测试中经常使用的不同组件，并将它们映射到一个可扩展的框架。LibAFL允许研究人员和工程师扩展核心模糊器管道，并共享他们的新组件以便进一步的评估。作为LibAFL的一部分，我们集成了20多个以前工作的技术，并进行了广泛的实验，以显示我们的框架在组合和评估不同方法的好处。希望本文的研究成果能够对模糊测试研究的进展有所帮助，并为今后的比较和可扩展研究提供坚实的基础。



MC2: Rigorous and Efficient Directed Greybox Fuzzing


有向灰盒模糊测试是针对目标软件测试的一种流行技术，它试图找到到达程序中一组目标站点的输入。大多数现有的有向灰盒模糊器都没有对其性能或最优性提供任何理论分析。


在本文中，我们引入了一个复杂性理论框架，将有向灰盒模糊测试作为oracle引导的搜索问题，其中通过查询oracle来接收关于输入空间的反馈(例如，输入距离目标站点有多近)。我们的框架假设每个oracle查询可以返回任意内容，其中包含大量但不变的信息。因此，我们使用模糊算法找到达到目标的输入时所需的oracle查询数量作为性能指标。利用我们的框架，我们设计了一个随机有向灰盒模糊算法，进行对数(所有可能的输入数量)数量的查询，期望找到一个达到目标的输入。我们进一步证明了我们的算法所需的oracle查询的数量是最优的，即，没有模糊算法可以通过超过一个常数因子来提高(即最小化)查询计数。


我们在MC2中实现了我们的方法，并在具有挑战性的基准测试(Magma和Fuzzer测试套件)中比最先进的定向灰盒模糊器的性能平均高出两个数量级(即134倍)。MC2还发现了15个以前未被发现的bug，这是其他最先进的定向灰盒模糊器无法发现的。
