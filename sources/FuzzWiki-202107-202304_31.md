# 区块链智能合约Fuzz技术

我们的生活中每分每秒都在经历着合同的创建与签订，可以是买卖合约，甚至购物、外卖都是在与相关的公司签订合约。可以说，**合约与我们的日常生活息息相关**。合约具有法律效益以及**不可篡改性**，而把现实当中的合约**搬到计算机当中实现**，就是我们常说的**智能合约**了**。**

![](../Images/f10601e34fa9eb069d80d5f64c7c55e5.png)01 什么是智能合约？  

智能合约的概念在1995年就被提出，它将**现实生活中的合约搬到计算机当中实现**，**是一种旨在以信息化方式传播、验证或执行合同的计算机协议**。设计一个智能合约就是将与合约相关的所有的条款以及逻辑全都编写到**一段代码**当中去。设计好之后，因为这个智能合约已经是制定好的逻辑，所以它可以进行**自我执行以及自我验证**，并且在执行的过程中**不需要人工干预**的。智能合约被设计出来的目的，就是为了提高传统合同执行的效率，同时减少执行的成本。区块链领域的智能合约有以下特点：（1）规则**公开透明**，合约内的规则以及数据对外部可见；（2）所有**交易公开可见**，不会存在任何虚假或者隐藏的交易；（3）智能合约具有**不可篡改**的特性。

  

![](../Images/c902cde1f8faff71224c97f4bab526b8.png)  
![](../Images/d27c53b1af591a6f35869e9121104c7d.png)  

如上图，合约的**部署**跟发送一笔交易是一样的操作，调用****transaction****函数****，from为**发布者的地址**，to为0，data为合约的****evm****操作码******，**在矿工打包的时候会生成智能合约地址。智能合约地址的生成是由创建者的**账号和发送的交易数作为随机数输入**，通过Kecca-256加密算法重新创建一个地址作为账号，也就是说最后合约地址对应合约的代码会保存在区块链数据库。调用者只需要有**合约地址**和****abi****文件****就可以**调用合约**的代码。

![](../Images/c902cde1f8faff71224c97f4bab526b8.png)  
![](../Images/07b5ca443a69f50eecd440d7b5c3972f.png)  

合约的**调用**如上图所示，要调用合约需要合约的**地址**和合约的**方法**。智能合约是部署在区块链的代码，区块链本身**不能执行代码**，代码的执行是在本地的EVM中，实际上，部署在区块链上代码是能够在本地产生原智能合约代码的代码，可以理解区块链为一个**数据库**，而客户端从数据库中读取了存储的运行代码，并在本地**运行后**，将结果写入到了区块链这个数据库中。

![](../Images/f10601e34fa9eb069d80d5f64c7c55e5.png)**02 智能合约安全吗？**

智能合约本身也存在一定的安全风险，目前智能合约已经发生过重大安全事件，黑客手法是利用漏洞入侵系统，进而对智能合约用户造成巨大损失。其中较为严重的事件是著名的****The Dao****事件****，攻击者窃取了350万个以太币，造成了6000万美元的损失。目前智能合约存在的安全风险主要有**隐私泄露**、**交易溢出与异常**、**合约故障**、**拒绝服务**这四项。智能合约中出现频率最高的****10****类安全问题****为分别：代码重入、访问控制、整数溢出、未严格判断不安全函数调用返回值、拒绝服务、可预测的随机处理、竞争条件/非法预先交易、时间戳依赖、短地址攻击以及其他未知漏洞类型。因此，在智能合约部署到区块链之前，需要对智能合约进行**漏洞检测**，以最大程度的**规避或降低**安全风险。**模糊测试**（Fuzzing），是一种通过向目标系统提供非预期的输入并监视异常结果来发现软件漏洞的方法，在近几年来被运用于智能合约的漏洞挖掘上。模糊测试的工作过程由四个主要阶段组成：**测试用例生成阶段**、**测试用例运行阶段**、**程序执行状态监视**和**异常分析**。

![](../Images/f10601e34fa9eb069d80d5f64c7c55e5.png)**03 智能合约fuzz及相关工作**

2018年发布的文章****《****ContractFuzzer: Fuzzing Smart Contracts for Vulnerability Detection****》****是第一个基于Ethereum 平台的智能合约安全漏洞**模糊测试框架**，支持gas耗尽终止、异常处理混乱、重入、时间戳依赖、区块号依赖、危险的delegatecall 调用和以太币冻结**七种漏洞**的检测。ContractFuzzer工具包括一个****线下的****EVM****插桩工具****以及一个**线上的模糊测试工具**。线下的EVM插桩工具通过对EVM进行插桩，使得模糊测试工具能够监视智能合约的执行并提取执行日志用于漏洞分析。

ContractFuzzer实现了一个**网络爬虫**从Etherscan网站上爬取以太坊平台上**已经部署**的智能合约，爬取内容包括合约**创建代码**、****ABI****接口****与**构造函数参数**。将爬取的智能合约重新部署在自己搭建的以太坊测试网络中，一方面作为之后模糊测试的对象，另一方面作为使用合约地址作为参数的合约调用的输入。线上的模糊测试过程如图所示：

**分析**测试智能合约的ABI接口以及字节码，提取ABI函数的每一个参数的数据类型以及ABI函数中所使用到的**函数签名**；对于所有从以太坊平台上爬取的智能合约进行ABI签名分析，并根据各个智能合约所支持的函数签名将其**进行索引**；生成与ABI规范相符的**合法模糊测试输入**以及越过有效边界的**突变输入**；启动模糊测试，通过**随机的函数调用**，使用生成的输入调用相应的ABI接口；分析模糊测试过程中生成的**执行日志**，检测**安全漏洞**。

![](../Images/7c2fc5f6240d10d087218706dd6cfc8a.png)  

2020年发布的文章**《****sFuzz: An Efficient Adaptive Fuzzer for Solidity Smart Contracts》**是基于著名模糊测试工具AFL的智能合约模糊测试器。sFuzz是一个**反馈引导**的模糊引擎，应用成本低廉。sFuzz补充了现有的基于符号执行的测试引擎，因为众所周知模糊化和符号执行是互补的。虽然基于AFL的模糊算法通常是有效的，但它也有其局限性，即它通常需要覆盖有严格条件保护的分支。为了解决这一问题，sFuzz将基于AFL的模糊技术与一种有效的轻量级自适应种子选择策略相结合。sFuzz主要以下三个贡献：**代码（分支）覆盖率、自适应策略度量选择种子、变异测试用例**。其测试用例生成算法如下图所示。

![](../Images/c902cde1f8faff71224c97f4bab526b8.png)  
![](../Images/ad8efa0b88bf7e59f0e309057ddf1f62.png)  

sFuzz利用反馈引导自适应模糊化，将测试生成问题转化为**优化问题**，并以某种形式的反馈作为目标函数求解优化问题。sFuzz只模拟与智能合约中的漏洞相关的网络或区块链的细节，在C++中有一个高度优化的实现。initPopulation()生成初始测试用例、生成多个交易序列（函数调用）、根据函数类型为每个参数生成随机值、执行测试用例。fitToSurvive()评估种子的**适应度**、记录每个测试用例覆盖的分支（缓慢，无法满足条件严格的分支），sFuzz自适应策略根据**距离度量**选择种子。crossoverMutation()通过变异在种子中生成新的测试用例。

![](../Images/f10601e34fa9eb069d80d5f64c7c55e5.png)**04 结语**

随着区块链和智能合约技术的普及，数以百万计的智能合约被部署在区块链平台上，以实现分散应用的构建。然而，智能合约的安全漏洞对其未来构成了**巨大的威胁**。在未来的工作中，智能合约的模糊测试技术还可以有更大的发展空间。为了减少误报，可以研究这些类型的智能合约漏洞的漏洞**攻击模式**，这可以指导fuzzer生成更有效的漏洞触发输入。还可以**扩展**智能合约fuzz的工具，以检测与EVM或底层区块链平台相关的更多类型的智能合约漏洞。最后，也可将智能合约fuzz的工作推广到除EVM以外的其他智能合约平台的安全测试。
