除了 Log4Shell 漏洞 ，Apache 还有别的 bug

这段时间提到Apache，安全从业者最大的感受恐怕是“麻了”。毕竟月初爆出的Apache Log4Shell 漏洞堪称“核弹级别”，持续半个月影响还在扩散，全球半数企业纷纷自危，且新的相关漏洞也接连出现。可谓是天长地久有时尽，Log4Shell 漏洞绵绵无绝期。



不过在关注Log4Shell进展的同时，也不要忽略了其他影响巨大的漏洞。前两天，Apache 发布更新，修复了同样应用广泛的 HTTPD 服务器中的两个漏洞，两个漏洞都影响 Apache HTTPD Server 2.4.51 及更早版本。



Apache HTTPD Server 是Apache软件基金会的一个开源网页服务器，可以在大多数电脑操作系统中运行。由于易于跨平台使用且安全性高，它成为了世界上最广泛使用的Web服务器端软件之一。



此次被修复的两个漏洞如下：


  • CVE-2021-44790 缓冲区溢出漏洞：Apache HTTP Server 2.4.51 及更早版本的 mod_lua multipart 解析器在解析某些特殊设计的HTTP请求时，可能出现缓冲区溢出。Apache 表示，虽然目前尚未发现漏洞利用，但未来可能会出现。攻击者在成功触发缓冲区溢出漏洞后，可以在目标服务器上执行任意代码。

  • CVE-2021-44224服务器端请求伪造漏洞：Apache HTTP Server 2.4.51 及更早版本的转发代理配置中可能存在空指针引用和服务器端请求伪造 (SSRF)。 攻击者可以利用这个漏洞远程访问本地网络中的敏感信息，或者从易受攻击的系统向其他服务器发送恶意请求。


根据VluDB的报道，CVE-2021-44790 与“mod_lua Multipart Parser”组件的函数“r:parsebody”有关。“使用未知输入进行操作会导致内存损坏漏洞”，影响系统的机密性、完整性和可用性。


VulDB还指出，这类问题很容易被利用，攻击者可以远程发起攻击，且无需经过任何形式的身份验证。



Sophos 首席安全研究员 Paul Ducklin 则指出，这两个漏洞可能不会直接暴露出来，因为在实际运行中，可能并不会用到相关模块。但一旦使用了那些模块，就可能导致服务器崩溃、数据泄露以及远程代码执行。


毕竟，HTTPD无处不在。


“3,000 多个文件、接近一百万行源代码”支撑起了庞大的 Apache HTTPD 服务器。因此，HPPTD 不仅“大型且功能强大”，而且具有“无数模块和选项的组合，让其在强大的同时也面临着更多风险。”


就像 Log4j 一样，HTTPD 也容易融入到软件项目中，作为内部服务或者与其他产品或服务绑定。如果在 Shodan 上搜索，能发现大约有 300 多万台公共设备在运行不同版本的 HTTPD，这可能意味着 HPPTD 的漏洞也可能与 Log4j 一样影响深远。


不过，与 Log4j 相比，HTTPD更加可控。Apache 在其mod_lua站点上有这样的警告：

mod_lua模块对 HTTPD 拥有很大的控制权，这既是一个优势，也是一个潜在的安全风险。不建议您在与您不信任的用户共享的服务器上使用此模块，因为它可能会被滥用而影响到HTTPD。

目前 Apache 官方已发布更新补丁，用户可及时自查并下载安装更新补丁：

https://httpd.apache.org/download.cgi#apache24
