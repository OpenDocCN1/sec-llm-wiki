看到这里，你不禁要问题目里说程序员故意留 bug 呢......这难道不是代码写多了，神经错乱了吗？


原来，这是知名英文问答社区 Quora 上的一个问题，并且收到了 72 个回答。Curtis Poe 也是回答者之一，作为一个资深码农的他，这个回答获得了 2.4w 个赞。



Curtis 回顾了自己曾经工作过的一家公司，在那里写的所有东西都会被老板检查一遍。


不仅如此，老板还总是对 Web 应用程序的布局提出修改建议，而机智的 Curtis 渐渐掌握了老板想要的 style，试图让老板称心如意。


然而，剧情并不是这样发展的。



Curtis 的老板依旧提出其他修改建议，有的甚至因为布局需要对后端进行重新改写。


Curtis 和老板之间常常爆发争吵，结局往往是两败俱伤。



Curtis 越是写下详细说明，强调“一切都是最好的安排”，他越是感觉到挫败，因为老板总能找到需要改的地方。


直到有天，Curtis 顿悟出一个道理：那些修改建议其实源于老板想要通过“改进一些事情”而获得的成就感。


所以无论 Curtis 有多么认真努力，他总是无法写出能够让老板直接通过的东西。



自那以后，Curtis 开始故意在前端留下一些缺陷，例如选择难看的色彩搭配、让提交按钮出现的不合时宜，又或者段落间排列不整齐。


“我总是故意留下一些东西，等他去发现。”



于是老板发现问题，提出修改需求。


Curtis 就会回到工位上，完成他已经准备好了的“修改”，但是他并不会直接提交代码，而是默默开始下一个项目。


直到几个小时之后，他提交更新，老板无比欢乐。不久后，Curtis 还升职了，理由是“效率提升”。


这个故事告诉我们，产品经理是很需要成就感的职业。（ 这句是开玩笑的）
