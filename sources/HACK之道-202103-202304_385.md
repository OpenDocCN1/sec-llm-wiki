## **0x01：绕过**

之前安全狗就像没开发完一样，简单内联就过去了，但是现在的安全狗摇身一变，变得稳重了起来。

就连报错界面都变成了大人的模样。

![](../Images/b1aaca9a496929f9fbd6fb46340d7ac9.png)

首先 and 内敛注释依旧是可以过的，看来安全狗并没有太过关注and，可能是觉得后面的规则比较牛，知道有注入也没用？

![](../Images/aadb11b8056ed7e2f217a0fd5adc809d.png)

然后是order by ，从这里开始，事情就变得微妙了起来

![](../Images/d6c3c94f170ccf76b97fb9b74bec63cb.png)

猜测规则是order by 组合强规则，意思就是order by中间无论加什么都过不去

随便试一试

![](../Images/433028d674d6123a0cba03fa809e7934.png)

果然，但是有没有发现，我fuzz的符号里没有加＃号，因为加了就会这样

![](../Images/b1f194d891e0a274b8d9260e768af599.png)

由于锚点这个特殊性，盲猜这是一个突破点

可能安全狗遇到注释也会直接截断掉后面的语句（类似某锁），那就好说了，构造个注释在语句前面即可

![](../Images/f2edb8249da4a461ed7e0d4d69e3970c.png)

居然没过，小看你了安全狗，看来order by规则还没失效，那么 尝试隔断order by

中间加个%0a

![](../Images/f1c336ae6e34a11f1be8fb722e67c564.png)

轻轻松松

接下来是union select 组合

同理，也可以这样过

*   

```
`1'  REGEXP "[…%0a%23]"    /*!11444union %0a select*/ 1,2,3 --+`
```

![](../Images/b7ade5639f60519d2d8b1c3ac75705cc.png)

下一个是user()这类函数，这里也是个坑，发现直接括号会被拦

![](../Images/6a850273c6a638518b4be1fe5ff0838c.png)

  
去一个右括号就没事了，这规则也是无语

![](../Images/eeef9aa9b0aa1b09188f1d26843d307e.png)

  
既然如此，在括号里下文章即可

依然是换行加注释绕过

```
`-1'  REGEXP "[…%0a%23]"    /*!11444union %0a select*/ 1,user(%0a /*!80000aaa*/),3 -- +`
```
