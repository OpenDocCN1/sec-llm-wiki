而本文通过IDA进入更详细的深入分析。  

  
0x02 分析过程

    本章恶意程序采用的是恶意代码中Lab5-1的dll文件。

    实验思路：掌握IDA静态分析恶意程序

1、DLLMain的地址是什么？  

    在C中，控制台程序入口函数为main，而在DLL文件中，DLLMain就是入口函数，载入IDA直接就定位到了入口函数地址。

![](../Images/e75a77f5b9747b9d1182b9f7f5ab691d.png)

2、使用imports窗口并浏览到gethostname的调用，导入函数定位到什么地址？

通过导入表直接可以找到gethostname这个导出函数。

![](../Images/d51e9780d9c7544ed467d7a4f9e6cb97.png)

3、有多少函数调用了gethostbyname?        鼠标放到这个函数，并ctrl+x即可查看  
         在下图中，type分为p和r，p是调用，r是读。

![](../Images/b563668c9b35645ef460e64c5d8ead6e.png)

4、观察位于0x10001757处的gethostbyname调用，你能找出哪个DNS请求将被触发么？按下G键，定位到10001757处，查看以下内容，可以看到gethostbyname这个函数有一个参数，而eax就是参数(off\_10019040)，

*   
*   
*   
*   

```
.text:1000174E                 mov     eax, off_10019040.text:10001753                 add     eax, 0Dh.text:10001756                 push    eax             ; name.text:10001757                 call    ds:gethostbyname
```

![](../Images/d826caef8aacf052950fee60715457d0.png)

    继续往下跟，可以找到这个域名，但是在上方中，有一个 add eax, 0Dh操作，这是因为10019040处存的\[This is RDO\]，需要加上0D才能看见完整的域名。如下图已经标注：  

    

![](../Images/b42abd4962cc1a46343e7c36f6948970.png)

6、使用strings窗口，来在反汇编中定位字符串\\cmd.exe /c。它位于哪？

    通过View-->open subviews-->string来进行查找字符串

    查找到之后，可以看见是谁调用了他。而跳转过去之后，通过以下字符串可以判断开启了一个shell会话。

![](../Images/c782404b1ddd611a9c49754ae79de83f.png)

    为了进一步证实我们的猜测，可以双击跟进去，可以发现recv这个函数。证明我们的猜测是正确的。由于时间关系，没有进一步深入分析做了哪些操作，可以清楚是这是一个后门程序。  

![](../Images/bf26d60f82e2a1eb776ade44a4e6388a.png)
