## 0x01 交互与非交互式shell的定义与判断

### 简单解释

交互式shell，指的是你可以输入命令并获得执行结果的shell。

非交互式shell，一般是执行一个命令、一个脚本的shell，它们通常不需要人工干预，例如系统维护脚本、后台脚本等。

交互式shell和非交互式shell启动时会加载不同的环境配置文件，不同的配置文件会有不同的初始化脚本和环境变量。根据**bash手册**上的解释可以看到：

http://www.gnu.org/software/bash/manual/html\_node/What-is-an-Interactive-Shell\_003f.html  

> 交互式shell指的是在shell启动时没有**不属于选项的参数**(non-option argument)并且也没有`-c`选项，并且标准输入流和标准错误流都连接到终端的shell，或者启动shell时有`-i`选项的shell。如果一个shell是交互式shell，`$PS1`变量会被设置，且`$-`变量包含`i`字符，在shell脚本中可以使用这两个变量来判断当前shell是不是交互式shell。

### 不属于选项的参数解释

Linux的命令定义：以空格分割开的为参数(argument)，可以看到下图这条命令被空格分成了5个参数。命令执行时，在`ls`脚本的内部，可以使用`$0`来获取到`ls`这个字符串，同理，`$1`可以获取到`-a`，使用`$2`来获取到`-l`选项等等。“arguments”就是`$0`, `$1`, `$2`….等等以空格分割命令行后的**每个部分**。  

![](../Images/351248332c0802992904352a1b554bb7.png)

而`-l`和`-a`这种可以改变`ls`命令的行为的为**选项(即option)**，它们一般会被写在命令使用文档(help)中：

![](../Images/ad4dcc440f6b3c8375220ca6bc57bd42.png)

再来看一个命令，比如`sqlmap -u`后面不加任何参数，就会提示`sqlmap错误：-u选项需要一个参数`。这个参数是`-u`选项后必须要接的，假设我接`www.baidu.com`，那么`www.baidu.com`这个参数，就是属于选项`-u`的。所以再说白一点，就是我输入了选项，但是命令仍然会正常执行，并不会在终端中报错等。  

![](../Images/a590bf6cf8ccb07634f8a84f372542ae.png)

### 交互式shell与非交互式shell特点对比  

有了上面的理解，再来看bash手册的交互式shell官方定义就简单了，非交互式就是完全与交互式相反的。

| 交互式shell || 非交互式shell |
| --- | --- |
| 没有【不属于选项】的参数 || 有【不属于选项】的参数 |
| --- | --- |
| 启动时有`-i`选项 || 启动时**没有**`-i`选项 |
| `echo $-`得出的值中含有字母`i` || `echo $-`得出的值中**不含有**字母`i` |
| 没有`-c`选项 || 有`-c`选项 |
| `echo $PS1`有值 || `echo $PS1`没有值 |

### 鉴别验证与判断

根据上面的学习，我们再看自己手里的shell到底是交互还是非交互，就简单多了。

![](../Images/2424347862eaeb3c2d534205becc02c5.png)

可能会有朋友问了，`$PS1`是个啥？`$PS1`是Linux中的一个变量。  

## 0x02 Linux中的变量

我们先来重新简单回顾Linux系统的大致结构组成。Linux系统分为内核和应用程序，而无论是内核、应用程序都是文件。Linux系统启动时，会在界面停留，这时的黑框框就是内核的`Grub`引导程序，`Grub`也是一个文件，在`/root`下。

![](../Images/c79c34a5682230d33760623aedebe313.png)

而我们使用的命令，也都是文件，在`usr/bin`或者`usr/sbin`目录下。(在老版本中的Linux，`bin`和`sbin`目录在根目录下，/usr下没有bin和sbin。但是新版本有`/usr/bin`和`/usr/sbin`，是为了兼容老版本，保留了根目录的`bin`和`sbin`，只不过变成了指向`/usr/bin`和`/usr/sbin`的软链接)  

![](../Images/34b1af5474dbf0eaa4e5c001155611b1.png)

而在Linux中，不但有命令，还有**变量**。我们可以创建变量并且给变量赋值。也可以通过`set`命令来查看有哪些变量。  

*   
*   
*   
*   

```
aaa=/home/sss/Desktop/1.txt #定义变量aaaecho $aaa #输出变量aaacat $aaaset #列出设置的所有变量
```

![](../Images/fd64f6a47e7784271f5cceec3e11ad44.png)

我们常用的history命令，输出出来的行数是有一定的限制的，这个限制就是通过一个变量来定义的。即`$HISTSIZE`(或者`$HISTFILESIZE`)。这个变量被写入到了`/etc/profile`文件中。`/etc/profile`文件就是系统级别的环境变量，关于Linux的环境变量，之后会写文章进行分析的哈。这里不多说了。

## 0x04 交互式shell在Linux提权中的应用

近期出现了不少的Linux提权漏洞，比如CVE-2021-4034、CVE-2022-0995、CVE-2022-0847，再包括之前的脏牛提权，都是很有名的。

大多数网上的复现都是拿着exp，直接在kali或者ubuntu系统执行就成功了。

**这是因为，在实战的环境，获取的shell都是蚁剑等的虚拟终端，均为非交互式shell，而只有想办法生成交互式shell才能提权成功。所以我们会先bash反弹shell到本地，再提权。**  

### 交互式shell生成方法

1、bash反弹。因为bash反弹回来的是一个交互式shell。  

![](../Images/c64ef145cb9ff26a3909185165bb6e15.png)  

当然，也不排除一种例外，就是遇到下面这种情况，bash反弹没有权限。这个到底是为什么，大家思考一下吧！**以后我会写一篇关于bash反弹的文章来解释哈。**  

**2、python一句话，于我们而言其实也够用了。为什么这么说呢**

*   **拿到webshell后如果成功bash反弹，那么我们获得的就是一个交互式shell(上面那么多的实验已经证明了)，完全可以进行提权，不需要python一句话**
    
*   **python一句话生成虚拟交互式shell，确切地讲，是为了能够执行某些命令或者让已经bash反弹回来的shell更加完整而已。我们提权并不一定要用python一句话，只要能够bash反弹成功即可。**
    
*   通常为了保险，可能为了避免发生某些意外，提高容错率，才使用python一句话，毕竟不用白不用。但是时间长了，大家可能就混淆了，就认为提权一定要用python生成shell。
    

*   
*   
*   
*   
*   

```
python -c "import pty;pty.spawn('/bin/bash')" ##或者写到文件里面import ptypty.spawn('/bin/bash')
```

3、有兴趣的话，可以看看其他的生成完整交互式shell的方式：

## 总结

1、交互式shell是bash启动时不带有不属于选项的参数；不带有`-c`选项；并且`echo $PS1`有值、`echo $-` 回显结果中有英文字母`i`，非交互式shell与其相反。

2、通过脚本或者其他工具RCE获得一个shell后，可以通过`echo $-`与`echo $PS1`来判断是否为交互式shell。

3、在蚁剑的非交互式shell中无法进行有效提权，需要bash反弹生成交互式shell到本地进行提权。这就是为什么我们获取webshell之后要先bash反弹到本地的原因。

4、提权只需要能够bash反弹shell到本地即可，而python一句话生成交互式shell，只是为了让bash反弹回来的交互式shell更加完善而已，如使用top命令等。

5、**留个问题：centos7机器bash反弹没有成功，提示没有权限(攻击机与靶机互通，靶机为centos7，ip端口防火墙都没问题)。当我知道答案的时候我已经扇了自己两个巴掌了。**
