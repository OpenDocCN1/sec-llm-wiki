前几天正在公司导一些数据，突然公司停电。我人直接炸裂，所幸数据和机器没有损坏。

但是这让我突然想到了之前实战的时候，遇到的一个很蛋疼的问题。

我们试想一下，某一天兴致勃勃地用VPS渗透，刚刚上线一个目标，渗透到了第二层内网，你还没来得及将session转到CS上，这时候突然断网或者电脑死机，你的X-shell或者Final Shell链接VPS突然掉了，这真的是要吐血了。

再次链接VPS，你的MSF会话早就没了。

蛋疼不？于是怒写这篇文章，和大家分享一波，解决这个痛点！！


0x01 环境搭建

我就不用VPS了，之前忘了关，欠费了我@&@#&……

我这里就假设kali是我的远程VPS机器了

开启kali ssh链接

 vim /etc/ssh/sshd_config systemctl restart ssh

X-shell链接kali

0x02 场景复现

好了，现在，我们利用X-shell链接的终端，模拟在VPS上安装了MSF，然后开启MSF并假装上线了一台机器

这时，突然X-shell断开了链接，心都凉了。

怎么解决？

安装tmux

1、kali自带的tmux，但是VPS上是ubuntu系统，毕竟不是kali，所以安装一下tmux


2、输入下面这个命令，表示新建一个tmux会话，msf是名字，随便起，随后会进入到这样的界面

 tmux new -s msf

3、在这里面尽情的使用msf，我们假设现在获取到一个session

4、之后，我们假装掉线了，然后我们再次链接VPS

5、按照平常，不使用 tmux的时候，MSF刚刚回连的session就已经消失不见了。但是我们输入这条命令，msf是刚才我起的会话名字，可以看到，MSF还是健在。

 tmux a -t msf

6、惊不惊喜？意不意外？所以这相当于一个入栈出栈的一个操作，将MSF保存到一个tmux创建的空间里面，并不会因为ssh链接掉线，导致MSF消失。

现在对tmux的其他参数命令做一个总结拓展，下面这个命令是在会话之外做的操作：

 tmux new -s test #新建会话test tmux ls #查看所有会话 tmux kill-session -t test#删除会话test tmux rename -t test test2#将test会话改名为test2

7、你现在肯定有一个疑惑，我进入到刚创建的会话中了，怎么回到外面？看下面这些命令哈：

 ctrl+b d #从创建的会话中跳出来，不会删除会话 ctrl+d #从创建的会话中跳出来，删除会话 ctrl+b s#在创建的会话中查看会话列表 ctrl+b b $#在创建的会话中重命名会话

你肯定又蒙了，ctrl+b d这样的命令是什么鬼？？ctrl+b是个快捷键，按下后，再按d即可，相当于你告诉会话，我要在里面做一些操作。


总结

tmux不仅仅可以用到VPS掉线，大家发挥想象力吧，利用到别的地方。

1、关闭终端,再次打开时原终端里面的任务进程依然不会中断，在渗透过程中，意外因网络等原因ssh掉线,tmux可以恢复session会话

2、备份大数据文件时，不用担心传输过程中X-shell断网断电

3、这也算是一种持续性渗透、权限维持的一种方法吧。
