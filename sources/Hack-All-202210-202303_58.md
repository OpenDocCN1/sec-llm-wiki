# Kaspersky Endpoint Security (KES) 安装程序

在进行这项研究并为了测试这些不同的卸载程序时，我还安装了有问题的 AV 产品，在使用 KES 安装程序时，我从 KES 收到了以下提示：![](../Images/b5e08897d2a1e58c4690824f6bd45c49.png)启动“进程监视器”并继续卸载过程。看到 procmon 的结果，我们得到了一个非常熟悉的程序：

![](../Images/47a697ca885a068f87e35e3480a6b4f5.png)

“act3CB2.tmp”与我们之前使用“kavremover”查看的二进制文件具有相同的参数，这使我们得出这样的理论：KES 安装程序使用相同的方法来删除其他AV。现在让我对此非常感兴趣的是，KES 如何检测到我安装了 AVG 2015。通过查看进程树，我们可以看到“act3CB2.tmp”有一个名为“cleanapi.exe”的父进程，这听起来很有趣，所以我开始在 KES 安装程序中寻找这个“cleanapi.exe”。通过双击安装程序，它首先将自身解压缩到指定位置。如果我们查看未压缩数据的目录结构，我们会看到两个可能与“清理”功能相关的有趣文件。

*   
*   

```
cleaner.cabincompatible.txt
```

“incompatible.txt”的内容是一长串安全产品（AV、EDR、VPN、防火墙……），从文件名我们猜测 KES 可能不兼容（即，如果同时安装了这两个软件可能会导致问题） 。![](../Images/56085cb7d7d54a489b8ecc82729b6552.png)

要查看“cleaner.cab”文件的内容，我们首先需要使用 7zip 之类的工具将其解压缩。![](../Images/9a15b306034fa2f6e30726c3d1d68894.png)乍一看，我们可以看到“.ini”文件的名称与“incompatible.txt”文件中的名称一一对应。稍后我们将回到“.ini”文件。向下滚动一点，我们找到了我们正在寻找的二进制文件“cleanapi.exe”。回到最初的问题，KES 如何确定我安装了 AVG 2015？好吧，在更清洁的文件夹中，我发现了以下“.ini”文件：

```
avg_free_av_2015_x64.iniavg_free_av_2015_x86.ini
```

里面有以下内容：![](../Images/ebd7fe4d389edafb17a81ac143cb1bca.png)

有三个关键信息：

```
detect-registry=HKEY_LOCAL_MACHINE\SOFTWARE\Avg\Avg2015....type=uninstall....env-registry=HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\AVG\UninstallString->UninstallString
```

“AVG”的检查是通过检查注册表中“detect-registry”变量中指定的键来完成的。如果找到，则运行“env-registry”指向的值。为了测试这一点，我做了以下步骤：

*   从系统中删除 AVG
    
*   创建注册表表项*“HKEY\_LOCAL\_MACHINE\\SOFTWARE\\Avg\\Avg2015”*
    
*   创建注册表项*“HKEY\_LOCAL\_MACHINE\\SOFTWARE\\Microsoft\\Windows\\CurrentVersion\\Uninstall\\AVG\\UninstallString”*并将其指指向“notepad.exe”
    
      
    
*   ![](../Images/521c11e01c4eb5541454e53dac3bb35a.png)
    
*   运行 KES 安装程序成功调用记事本程序
    
      
    
*   ![](../Images/618b9e84120b5ff4dec0a3458e94c425.png)
    

由此可见：只要我们模拟 KES“不支持”的 AV 以触发卸载过程，我们现在就能够从已签名的 Kaspersky 进程的上下文中执行任意命令和进程。

请注意，这当然需要管理员权限才能修改必要的注册表项 (HKLM) 并运行 KES 安装程序。另一方面，这可以为可能偶然发现已经在运行卡巴斯基的组织的攻击者提供一个有趣的设置，因为这可以用来执行来自卡巴斯基进程的命令，该进程可能已经被安全团队列入白名单，或者可能是用作某种后门/持久性，每次安装 KES 时都会发生这种行为。

# 任意 DLL 加载

在我结束这件事之前的最后一件事。如果您在我们查看进程树时注意到，“cleanapi.exe”有一堆命令行参数。

```
"C:\\Users\\lab\\AppData\\Local\\Temp\\282527F5EDA44439AD3CC23FD270EE91\\clr\\flt\\cleanapi.exe" -r -t 1 -n cleanapi.dll -d C:\\Users\\lab\\AppData\\Local\\Temp\\282527F5EDA44439AD3CC23FD270EE91 \\clr\\flt\\
```

其中一个有趣的参数是“-n”，我们向它传递了一个 DLL，特别是“cleanapi.dll”。如果我们减少前面的命令，只使用“-n”标志和一个随机 DLL

```
cleanapi.exe -n malware.dll
```

我们可以通过“进程监视器”清楚地看到有问题的进程正在寻找我们的随机 DLL：

![](../Images/383c90f4139584a3a99138d83bd84790.png)

我们可以快速创建一个“calc”POC 来测试它是否加载了任意 DLL。事实上，一旦 POC 运行，我们就会弹出一个计算。（当然，“cleanapi.exe”二进制文件已签名。）![](../Images/8c34f3d709db55686932601bc618708d.png)
