首先我们要了解预编译的两种形式：


- 模拟预编译

- 非模拟预编译


通俗来说一种是假预编译和真预编译


模拟预编译：


此方法是在客户端进行预处理模拟，最终拼接好sql语句发送到mysql。也就是说mysql会对sql语句进行

parsing->resolution->optimization->execution

分为两步：

- 第一步是prepare接端，然后发送带有占位符的sql语句到musql服务器也就是：

parsing->resolution

- 第二步以多次发送占位符参数给mysql服务器进行执行也就是：


optimization->execution


总而言之，使用模拟预编译的方式就是一次发送完整的sql语句给mysql执行，不需要mysql做额外的处理（如：保存会话状态等）。


另外，使用模拟预编译的处理方式制定在exec阶段才能发现（因为：模拟方式拼接好sql在exec接端才会发送到mysql服务器）


参数化查询:


参数化查询的时候MySQL的连接驱动进行了转义处理，所谓的防止SQL注入其实也是在代码层完成的。

总结下：如果模拟预处理开启，那么客户端程序内部会模拟mysql数据库中的参数绑定这一过程。也就是说，程序会在内部模拟prepare的过程，当执行execute时，再将拼接后的完整SQL语句发送给mysql数据库执行


PDO::prepare:

PDO::prepare — 准备要执行的SQL语句并返回一个 PDOStatement 对象(PHP 5 >= 5.1.0, PECL pdo >= 0.1.0)

语法：

public PDOStatement PDO::prepare ( string $statement [, array $driver_options = array() ] )

- statement

  -  合法的sql语句

- driver_options

  - 此数组包含一个或多个 key=>value 对来设置 PDOStatement 对象的属性， 最常使用到是将PDO::ATTR_CURSOR值设置为PDO::CURSOR_SCROLL来请求一个可滚动游标

- 返回值

  - 如果成功，PDO::prepare()返回PDOStatement对象

  - 如果失败返回 FALSE 或抛出异常 PDOException


PDO::ATTR_EMULATE_PREPARES参数:

名为PDO::ATTR_EMULATE_PREPARES ，表示是否使用PHP本地模拟prepare，此项参数默认值未知。而且根据我们刚刚抓包分析结果来看，php 5.3.6+默认还是使用本地变量转，拼接成SQL发送给MySQL Server的，我们将这项值设置为false

我们将设置PDO::ATTR_EMULATE_PREPARES为false，见下图：


这里明显有prepare和execute两个过程，显然在将PDO::ATTR_EMULATE_PREPARES设置为false后，使用的是mysql数据库预编译


Bypass模拟预编译


就是在预编译阶段即prepare阶段，sql语句的模板中参数名可控，导致的sql注入。具体的可以参见这篇文章
