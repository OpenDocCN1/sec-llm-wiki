上一次在这个地方卡住了，明明这个desc关键字能进到数据库中执行并引发报错，将desc替换为desca成功引发报错，但desca被自动添加了反引号而且无法闭合出去。

![](../Images/1315cff1a5f548400d4b10b5ccf393e8.png)

回顾一下当时的语句吧！

*   
*   

```
SELECT XX FROM XX WHERE `student_id` = 6023 AND `is_delete` = 1 ORDER BY `apply_number` desc
```

首先猜测参数中的desc是可控的，因此我尝试传入desca引发报错。

![](../Images/97733a5df2e9955311002b4ea8b57e24.png)

根据报错信息，此时语句为：

*   
*   

```
SELECT XX FROM XX WHERE `student_id` = 6023 AND `is_delete` = 1 ORDER BY `apply_number` `desca`
```

由于desc时没报错，desca时自动添加的反引号测了很久都没有出去

![](../Images/57075aa9ddf142d0fb9c80bdede42afe.png)

我实在孤陋寡闻一时半会没想到利用方式只好另寻出路。经过k1ea4c师傅一番指点茅塞顿开。  

k1：没道理desc反引号处理的，可能desca他认为不是关键字，所以才反引号

经过k1师傅提示既然desc作为sql语句关键字执行，就可以用如下姿势：  

*   

```

```

根据报错信息，传入后语句成为：  

*   
*   

```
SELECT XX FROM XX WHERE `student_id` = 6023 AND `is_delete` = 1 ORDER BY `apply_number` desc,exp(710)
```

成功报错并确认了报错注入点，直接传入

*   

```

```
