GitHub出手，宕机组再拿一分。留给数据泄露组的时间不多了。

18年9月，在Facebook、SHEIN、英国航空公司网站等的努力下，数据泄露组可谓是占尽了风头，把宕机组远远的甩在了后面。

￼

不过，到了18年的十月，宕机组终于耐不住寂寞，接连出招。

10月16日，微博和twitter这对两兄弟分别在国内外几乎同时向数据泄露组打响了第一枪。

￼

这一枪，博尽了眼球。

次日，Youtube紧随其上。

在微博、Twitter和Youtube三位接连上阵之后，数据泄露组丝毫没有要应战的意思。

已经连下三城的宕机组看来已经遥遥领先了。但是他们好像没并有准备罢手。

10月22日，周一刚一上班。全球最大的脱光、哦不、代码托管网站GitHub用实力告诉对手什么叫做碾压。以摧枯拉朽之势打了所有人一个措手不及。

￼

这次，GitHub给出的理由是：数据存储系统存在问题。

看来，GitHub这是准备为日后投靠数据泄露组做铺垫啊。

以下是GitHubStatus上给出的网站状态日志。

￼

可以看到，从07：09分网站开始发生异常。持续到21：18分还未完全恢复。

根据 GitHub 问题热力图显示，此次 GitHub 网站宕机受影响最严重的地方有美国西海岸、日本、马来西亚以及澳大利亚东南部地区。
￼

这一次，来自中美日的程序员终于站在了统一战线上。
￼

宕机组本次能把刚刚找了个新爹的GitHub派出来，看来他们对于10月份的冠军是势在必得了。

不过，这可苦了MicroSoft了，很多网友开始找家长了。

￼

宕机组已经连拿4分了，数据泄露组再不努努力的话，别说冠军了，亚军可能都要背数据造假组给拿下了。。。
