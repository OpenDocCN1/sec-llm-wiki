到底面向？编程

面向过程编程（ ProcedureOriented、简称 PO） 和 面向对象编程（ ObjectOriented、简称 OO） 我们一定听过，然而实际企业级开发里受用更多的一种编程思想那就是：面向接口编程（ Interface-Oriented）！

接口这个概念我们一定不陌生，实际生活中最常见的例子就是：插座！

我们只需要事先定义好插座的接口标准，各大插座厂商只要按这个接口标准生产，管你什么牌子、内部什么电路结构，这些均和用户无关，用户拿来就可以用；而且即使插座坏了，只要换一个符合接口标准的新插座，一切照样工作！

同理，实际代码设计也是这样！

我们在设计一个软件的代码架构时，我们都希望事先约定好各个功能的接口（即：约定好接口签名和方法），实际开发时我们只需要实现这个接口就能完成具体的功能！后续即使项目变化、功能升级，程序员只需要按照接口约定重新实现一下，就可以达到系统升级和扩展的目的！

正好，Java中天生就有 interface这个语法，这简直是为面向接口编程而生的！

所以接下来落实到代码上，举个通俗一点的小例子唠一唠，实际业务代码虽然比这个复杂，但原理是一模一样的。


做梦了

假如哪一天程序羊真发达了，一口豪气买了两辆豪车，一辆五菱宏光、一辆飞度、并且还专门聘请了一位驾驶员来帮助驾驶。

两辆豪车在此：

  1. publicclassWuling{
  2. publicvoid drive() {
  3. System.out.println("驾驶五菱宏光汽车");
  4. }
  5. }

  7. publicclassFit{
  8. publicvoid drive() {
  9. System.out.println("驾驶飞度汽车");
  10. }
  11. }

驾驶员定义在此：

驾驶员定义了两个 drive()方法，分别用来驾驶两辆车：

  1. publicclassDriver{

  3. publicvoid drive( Wuling wuling ) {
  4.         wuling.drive(); // 驾驶五菱宏光的方法
  5. }

  7. publicvoid drive( Fit fit ) {
  8.         fit.drive();    // 驾驶飞度的方法
  9. }

  11. // 用于测试功能的 main()函数
  12. publicstaticvoid main( String[] args ) {

  14. // 实例化两辆新车
  15. Wuling wuling = newWuling();
  16. Fit fit = newFit();

  18. // 实例化驾驶员
  19. Driver driver = newDriver();

  21.         driver.drive( wuling ); // 帮我开五菱宏光
  22.         driver.drive( fit );    // 帮我开飞度
  23. }
  24. }

这暂且看起来没问题！日子过得很融洽。

但后来过了段时间，程序羊又变得发达了一点，这次他又豪气地买了一辆新款奥拓（Alto）！

可是现有的驾驶员类 Driver的两个 drive()方法里都开不了这辆新买的奥拓该怎么办呢？


代码的灵活解耦

这时候，我想应该没有谁会专门再去往 Driver类中添加一个新的 drive()方法来达到目的吧？毕竟谁也不知道以后他还会不会买新车！

这时候如果我希望我聘请的这位驾驶员对于所有车型都能驾驭，该怎么办呢？

很容易想到，我们应该做一层抽象。毕竟不管是奥拓还是奥迪，它们都是汽车，因此我们定义一个父类叫做汽车类 Car，里面只声明一个通用的 drive()方法，具体怎么开先不用管：

  1. // 抽象的汽车类Car，代表所有汽车
  2. publicclassCar{
  3. void drive() { } // 通用的汽车驾驶方法
  4. }

这时，只要我新买的奥拓符合 Car定义的驾驶标准即可被我的驾驶员驾驶，所以只需要新的奥拓来继承一下 Car类即可：

  1. publicclassAltoextendsCar{
  2. publicvoid drive() {
  3. System.out.println("驾驶奥拓汽车");
  4. }
  5. }

同理，只需要我的驾驶员具备通用汽车 Car的驾驶能力，那驾驶所有的汽车都不是问题，因此 Drvier类的 drive()方法只要传入的参数是父类，那就具备了通用性：

  1. publicclassDriver{

  3. publicvoid drive( Car car ) {  // 方法参数使用父类来替代
  4.         car.drive();
  5. }

  7. publicstaticvoid main( String[] args ) {
  8. Alto alto = newAlto();
  9. Driver driver = newDriver();
  10.         driver.drive( alto );
  11. }
  12. }

问题暂且解决了！

但是再后来，程序羊他好像又更发达了一些，连车都不想坐了，想买一头驴（Donkey）让司机骑着带他出行！

很明显，原先适用于汽车的 drive()方法肯定是不适合骑驴的！但我们希望聘请的这位驾驶员既会开汽车，又会骑驴怎么办呢？

害！我们干脆直接定义一个叫做交通工具（ TrafficTools）的通用接口吧！里面包含一个通用的交通工具使用方法，管你是驾驶汽车，还是骑驴骑马，具体技能怎么实现先不管：

  1. // 通用的交通工具接口定义
  2. publicinterfaceTrafficTools{
  3. void drive();  // 通用的交通工具使用方法
  4. }

有了这个接口约定，接下来就好办了。我们让所有的 Car、或者驴、马等，都来实现这个接口：

  1. publicclassCarimplementsTrafficTools{
  2. @Override
  3. publicvoid drive() { }
  4. }

  6. publicclassWulingextendsCar{
  7. publicvoid drive() {
  8. System.out.println("驾驶五菱宏光汽车");
  9. }
  10. }

  12. publicclassFitextendsCar{
  13. publicvoid drive() {
  14. System.out.println("驾驶飞度汽车");
  15. }
  16. }

  18. publicclassAltoextendsCar{
  19. publicvoid drive() {
  20. System.out.println("驾驶奥拓汽车");
  21. }
  22. }

  24. publicclassDonkeyimplementsTrafficTools{
  25. @Override
  26. publicvoid drive() {
  27. System.out.println("骑一头驴");
  28. }
  29. }

这个时候只要我们的驾驶员师傅也面向接口编程，就没有任何问题：

  1. publicclassDriver{

  3. // 方法参数面向接口编程
  4. publicvoid drive( TrafficTools trafficTools ) {
  5.         trafficTools.drive();
  6. }

  8. publicstaticvoid main( String[] args ) {
  9. Driver driver = newDriver();
  10.         driver.drive( newWuling() );  // 开五菱
  11.         driver.drive( newFit() );     // 开飞度
  12.         driver.drive( newAlto() );    // 开奥拓
  13.         driver.drive( newDonkey() );  // 骑一头驴
  14. }
  15. }

很明显，代码完全解耦了！这就是接口带来的便利。


代码的扩展性

面向接口编程的优点远不止上面这种代码解耦的场景，在实际企业开发里，利用接口思想对已有代码进行灵活扩展也特别常见。

再举一个例子：假设程序羊有一个非常豪气的朋友，叫：程序牛，他们家出行可不坐车，全靠私人飞机出行：

  1. // 通用的飞机飞行接口
  2. publicinterfacePlane{
  3. void fly();
  4. }

  6. // 程序牛的专用机长，受过专业训练（即：实现了通用飞行接口）
  7. publicclassPlaneDriverimplementsPlane{
  8. @Override
  9. publicvoid fly() {
  10. System.out.println("专业的飞行员操控飞机");
  11. }
  12. }

  14. // 出门旅行
  15. publicclassTravel{

  17. // 此处函数参数也是面向接口编程！！！
  18. publicvoid fly( Plane plane ) {
  19.         plane.fly();
  20. }

  22. publicstaticvoid main( String[] args ) {
  23. Travel travel = newTravel();  // 开启一段旅行
  24. PlaneDriver planeDriver = newPlaneDriver(); // 聘请一个机长
  25.         travel.fly( planeDriver ); // 由专业机长开飞机愉快的出去旅行
  26. }
  27. }

但是突然有一天，他们家聘请的机长跳槽了，这时候程序牛一家就无法出行了，毕竟飞机不会驾驶。

于是他跑来问我借司机，想让我的驾驶员来帮他驾驶飞机出去旅行。

我一看，由于他们的代码面向的是接口，我就肯定地答应了他！

这时候对我这边的扩展来说就非常容易了，我只需要安排我的驾驶员去培训一下飞行技能就OK了（实现一个方法就行）：

  1. // 让我的驾驶员去培训一下飞行技能（即：去实现通用飞行接口）
  2. publicclassDriverimplementsPlane{

  4. publicvoid drive( TrafficTools trafficTools ) {
  5.         trafficTools.drive();
  6. }

  8. // 实现了fly()方法，这下我的驾驶员也具备操控飞机的能力了！
  9. @Override
  10. publicvoid fly() {
  11. System.out.println("普通驾驶员操控飞机");
  12. }
  13. }

这时候我的驾驶员 Driver类就可以直接服务于他们一家的出行了：

  1. publicclassTravel{

  3. publicvoid fly( Plane plane ) {
  4.         plane.fly();
  5. }

  7. publicstaticvoid main( String[] args ) {
  8. Travel travel = newTravel();

  10. // 专业飞行员操控飞机
  11. PlaneDriver planeDriver = newPlaneDriver();
  12.         travel.fly( planeDriver );

  14. // 普通驾驶员操控飞机
  15. Driver driver = newDriver();
  16.         travel.fly( driver );
  17. }
  18. }

看到没，这一改造过程中，我们只增加了代码，却并没有修改任何已有代码，就完成了代码扩展的任务，非常符合开闭原则！
