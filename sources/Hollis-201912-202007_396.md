# 远程办公第一天，你掉线了吗？

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzI3NzE0NjcwMg==&mid=2650126122&idx=2&sn=ec11f0e5aac8f057098b4674a62d1800&chksm=f36baa0bc41c231d0f3d7ad9fa55410c7f4714b64e627e4f90a7daa088c4dfcc6a5eaabf5a39&scene=126&sessionid=1681657610#rd](http://mp.weixin.qq.com/s?__biz=MzI3NzE0NjcwMg==&mid=2650126122&idx=2&sn=ec11f0e5aac8f057098b4674a62d1800&chksm=f36baa0bc41c231d0f3d7ad9fa55410c7f4714b64e627e4f90a7daa088c4dfcc6a5eaabf5a39&scene=126&sessionid=1681657610#rd)

作者丨赵钰莹、Tina、陈思、李冬梅线上远程办公的第一天，不知道各位使用的远程办公工具还流畅吗？工作效率怎么样？ 

为防控新型肺炎疫情，国内不少省市号召延长假期，各大互联网公司积极响应。根据此前公布的互联网公司复工时间表，大部分互联网公司选择将假期延长至 2 月 2 日，2 月 3 日至 2 月 7 日在家办公，2 月 10 日正式上班。线上远程办公的第一天，不知道各位使用的远程办公工具还流畅吗？工作效率怎么样？

   

**1\. 远程办公第一天，你掉线了吗？** 

线上开工第一天，从早上 9 点开始，各大办公软件迎来流量高峰，朋友圈里各大协作办公工具卡顿的消息瞬间刷屏。钉钉消息迟迟显示未读，视频会议卡顿；其他线上工具也出现了不同程度的问题。企业微信也出现崩溃，许多网友吐槽：全国远程开工第一天，企业微信就炸了，然后发现腾讯 10 号才开始办公。不过 QQ 倒是被网友评为今日视频会议的最佳神器。

![](../Images/06c1eb692262e74c3d69a0388b3517e5.png)

钉钉一位企服顾问在回复用户反馈时称：钉钉视频服务器正在扩容以承载更多并发多方会议支持。作为一款 ToB 产品，钉钉的业务场景与 ToC 的 IM 产品有很大区别，架构上也有所侧重，对于可能的大流量冲击本已有所准备。比如在节日场景下，一些大群的消息发送频率过高，可能超过系统整体容量，影响 IM 系统稳定性。如果对每个群设置较低的发送阈值，系统又没有完全发挥出容量，从而提供足够流畅的用户体验。针对这个问题，钉钉设计了一种智能限流的方法，当总体流量超过系统阈值时，自动根据当时情况对消息发送频率相对较高的大群进行限流。

即便如此，钉钉、企业微信可能也没有想到今天会迎来如此大的线上流量冲击。截至发稿时，各方软件已经开始陆续恢复。

远程办公软件的状态足以反映出今日线上开工企业之多，而这次远程办公也曝光了不同企业遇到危机事件时的态度。

**2\. 裁员、监工：****远程下的企业百态** 

线上办公，除了使用钉钉进行沟通外，还涉及到文档协作、视频会议、任务管理各个方面，工作怎么协同是个问题。

在家办公，在国外的名字叫 SOHO（Small Office，Home Office），在 IT 界并不是一个生僻的词，有不少大企业有这样的职位。2017 年前后的数据统计显示，IBM 有将近 40% 的雇员都是 SOHO 一族。在 IBM 之后，Google、Facebook、Yahoo 等一众硅谷巨头也加入了 SOHO 办公阵营。企业节省费用，员工得到自由，这种办公方式在全球越来越受欢迎。

但是在疫情之下，“全民”远程办公却是个创举。现在很多企业被动参与，也有很多员工并没有远程办公经验，那企业和员工双方都是如何应对的呢？

先说说我们 InfoQ 自己的研发团队吧。InfoQ 研发团队的同事表示：“除了上午有一阵钉钉的消息同步有问题，剩余别的都没问题，毕竟我们前几天都小范围预演过了，做了相应的调整和方案来应对远程办公。”

年前没有预料，年后却需要就地工作的 IT 人有不少，清除掉各种干扰外，还得配备出合适的工作条件来。InfoQ 采访到一位某“四大”员工，他在重庆家中上班。办公条件是一台电脑，通过客户 VPN 登录系统。他遇到的问题是远程办公，负载太高，但是 VPN 上不去，邮箱也收不到邮件，最重要的是电源线忘带了，还在想办法解决。

在回答是否觉得远程办公对自己工作有影响时，他表示：”比如现在要迁移平台，因没有带电脑的员工较多，所以项目上电脑和 VPN 都缺，而且没办法集中开会研究解决方案。肯定有影响，这种情况下肯定要去现场才能完成。“

另外一位身处青海西宁的”某新零售平台“员工在接受 InfoQ 采访的时候表示：”我基本上没遇到啥问题。”

![](../Images/7a543a412d29695c63e694379c16d9f4.png)

（该员工的工作台照片）

并表示很享受远程工作状态：“在家舒服啊，不用考虑工作之外的事，但是对于国内厂来说，在家办公是新的尝试，所以一开始签到机制会比较严格，和国外的在家办公相比还是有些差距的吧。”

相对员工，开展远程工作的企业，却各有各的做法。

InfoQ 采访了一家做直播产品的企业，谭总（化名）告诉 InfoQ：“我们没有用远程办公工具，就是靠自觉。写代码的写代码，做设计的做设计，制定目标任务，各自完成。不自觉的人，将来会被淘汰。**远程办公是老板筛选人的一个机会。**个别员工肯定会偷懒，不过偷懒带来的结果是**被优化掉。**IT 行业很多时候就是一台电脑的事，不存在办公条件太差从而影响工作的事情，用输出就能看到有没有在偷懒。”

一位保险公司的 IT 员工在接受 InfoQ 采访时表示：“之前基本只有 IT 员工需要使用 VPN 进行远程工作，如今所有员工都需要连接 VPN，导致负载过高，非常慢。由于突发疫情影响，导致保险业务营收受到影响，但工资还需要照发、各类 IT 设备和机房也需要维护，成本高昂，这种状态对公司发展非常不利。”

通过脉脉平台，我们得知有企业要求**全天开放摄像头，**并且还需要“早上打卡，发工作计划，晚上发总结，每天写日报”。

![](../Images/b6335154e2a2b20e4b5371b7ce8f2a85.png)

阿里巴巴也提出了要求：“每天两次打卡，增加每天晨会和日报，工作时间要求 10 分钟内必须响应钉钉，其他时间必须 30 分钟响应。”

远程办公的核心是工作进度，可以要求及时提交代码或输出其他成果来判断工作效率，但全程开放摄像头却是一个“管理上的信任缺失”问题了。

怎么让大家在远程条件下做好工作？我们也整理了一套要点指南。

**3\. 除了工具，远程办公还要注意什么？** 

除了必备的硬件工具和稳定的信号接收保障之外，远程办公需要注意的地方还有很多，但关键的点就那么几个。

首先，最重要的是信任和认可，在这种必须要使用远程协作开发的模式下，一定要让团队里的所有人认可这种模式，如果不认可，就很难有好结果。而公司也需要给予员工足够的信任，远程办公由于都在线上，无法进行面对面交流和沟通，所以对同事委以信任十分重要。由于团队成员性格的差异化，沟通种稍有偏差就容易产生误会。这时就需要相信同事的立意点是公正客观的，存在质疑应立即进行沟通，不要心存疑虑，相互猜忌。

其次是合理的规划。远程协作，需要对工作任务按照迭代版本和功能合理划分。高效的协作办公就是要有取舍和权重观念。了解事情的重要程度，合理规划优先等级，知道需要做什么，怎么做更高效，与团队成员达成共识。此外，规模越小的团体在执行工作目标时的效率也会更高，这是因为省了很多中间环节，省去了不必要的繁琐沟通和汇报，多一个人的参与就意味着多一份沟通成本。

不同的部门，工作中需要协作的程度也不一样。内容部门的线上协作程度其实并不高，每个编辑完成好自己的稿件将信息及时同步就可以。但例如营销、技术等协作程度相对较高的部门一定要做好异步编辑和协作工作。比如技术团队要从零开始一个项目，那么可能需要几个人共同将代码框架和结构搭建好，随后协作同事将内容填充完善，借助石墨文档和 GitHub 这样工具让协作更加高效。

然后是选择合理的远程协作工具，轻量级、服务稳定且可以保证全球的访问速度。当然，这些工具可能会因为员工的分布、公司的规模等因素而有所不同，以 PingCAP 为例，这家公司的员工呈现全球分布的特点，建立伊始就在践行远程办公文化，其联合创始人兼 CTO 黄东旭分享了几个可选的工具以及实际的研发工作流：

*   GitHub：代码托管，公开的 RFC，社区 Issue 反馈，产品发布，Code Review 等。
    
*   Zoom：在线会议。
    
*   Slack：即时通讯，机器人消息中枢。
    
*   微信、企业微信：即时通讯（没错，我们两个都用，但以企业微信为主）。
    
*   在线文档：文档协作，幻灯片，表格。
    
*   邮件，日历。
    
*   Confluence：内部的文档，包括已成型的设计文档（如内部的 RFC 文档），Wiki 等。
    
*   Jira：Bug 和 Milestone 跟踪。
    
*   Trello：看板，记录一些重要客户和事件的备忘。
    
*   Jenkins：持续集成，daily build。
    

**研发工作流：**

1.  假设我们需要做一个新功能，从构思开始，可能第一个会使用的工具是在线文档，负责的同事会草拟一个文档，将大致的想法在其中描述，然后通过 Share 的功能，分享给相关的同事，大多数时候这些设计文档都会 share 到所有的工程师都会在的邮件组里，任何人都可以上去评论或者编辑。
    
2.  文档经过沟通讨论定稿之后（沟通环节我会在下面一节重点介绍），会同步到 Confluence 和 GitHub 中（如果可以公开的话，英文版会发到 GitHub 上）。
    
3.  接着该项目将被拆分成多个子项目，通过 JIRA 分配到具体的人，完成后直接提交到 GitHub 上，项目的该模块的 Reviewer（也包括 Maintainer）会参与 Code Review，收集到两个 LGTM（Looks good to me） 并通过各种持续集成工具的测试后，最终合并到主干。
    

最后，让所有工作成果可见，并定期进行复盘也是很重要的。远程办公对协作和沟通存在一定影响，而且由于各自分散的办公条件可能不少人会忽视复盘的重要性。远程期间，哪些工作做完了，哪些工作还没有做，哪些工作效果欠佳需要优化，哪些工作行之有效，这一列问题需要进行及时复盘和跟踪。复盘能够知道在远程办公过程中存在哪些薄弱环节，如何打磨细节，不在同一个问题上重复犯错。

由于远程办公缺乏一定的监管和监督，且身边没有同事沟通多少会产生孤独感。因此强大的自我管理能力是远程办公成败的决定性因素。团队中的每个人需要明确自己所承担的工作目标，制定 deadline 机制，还可以借助番茄钟、日历等个人时间管理工具合理规划工作时间。同时，在生活中要保持规律的作息习惯，个人生活习惯的自律是工作自律的基础。

**4\. 结束语** 

对于很多企业，尤其是中小企业来说，之前从未远程办公过，所以心里没底，不知道应该制定什么样的规则、流程，也不知道应该采用什么样的远程办公工具。InfoQ 编辑部为此特别汇集了很多有远程办公文化、基因的企业的经验，供大家参考。最后，希望所有公司、所有人都可以平安渡过难关。
