“ 鲲之大，不知其几千里也；堆之大，ZGC亦可速清也。”



1、什么是ZGC


ZGC(Z Garbage Collector) 是一款在JDK 11引入的低延迟垃圾收集器，并在之后的JDK版本里被持续优化，官方声称具有以下四大特性：

  1. 支持TB级别的内存
  2. 最大GC延迟时间在10ms内(在JDK 16中这一数值达到了1ms)
  3. 应用程序吞吐量最多减少15%
  4. 为未来的GC新特性奠定基础

下面的内容会先对ZGC做一个详细介绍，然后逐一说明这四大特性背后是如何实现的



2、内存布局


与G1一样，ZGC也采用基于Region的堆内存布局，不一样的是ZGC的Region具有动态性：动态创建销毁、动态容量大小

一共分为三种Region：

小型Region：容量固定为 2MB，存放小于256KB的对象

中型Region：容量固定为 32MB，存放大于256KB小于4MB的对象

大型Region：容量为 2*N MB,可以动态变化，每个大Region中只会存放一个大对象，并且不会被重分配(即后文介绍的对象的复制)，因为大对象的复制代价高昂

3、GC信息存储


1. 传统方式

对象实例在堆内存有一部分数据是对象头，对象头由Mark Word，指向类的指针和数组长度三部分组成。Mark Word记录了对象和锁相关的信息，下图是其在64位JVM下的存储结构。

可以看到分代年龄、GC标记这种GC相关的信息被存储在对象头中，这种方式在有对象访问的情况下是很自然合理的，但是对象在内存中会因为GC的原因经常被移动，会有访问失败的可能。我们知道访问内存中的对象是通过指针来访问的，那么这种GC相关的信息是否可以存储在指针上呢？毕竟指针相较于对象稳定多了。


2. 染色指针

染色指针是一种直接将少量额外的信息存储在指针上的技术，具体信息在64位平台中如下图所示

  • Unused(18 bits)：用来给未来的GC新特性预留的扩展点
  • Finalizable(1 bits)：标记该对象是否将要被回收
  • Marked1&Marked0(各1 bits)：用于标记对象
  • Object Address(42 bits)：可管理的内存为4TB (2的42次幂)


3. 内存屏障

染色指针如何能够生效，内存屏障是很关键的一项技术。简而言之就是从堆中加载类引用的时候执行的一段额外逻辑，是不是有一点AOP的味道？

Object o = obj.fieldA; //从堆中加载类引用<内存屏障的逻辑会在这里执行>
Object p = o; //不会执行内存屏障逻辑，不是从堆中获取引用o.doSomething(); //不会执行内存屏障逻辑，不是从堆中获取引用

4、执行过程


ZGC的执行过程可分为以下四个大阶段，这四个阶段都是可以并行的


1. 并发标记(Concurrent Mark)

从GC ROOTS遍历对象图做可达性分析


2. 并发预备重分配(Concurrent Prepare for Relocate)

统计本次需要清理哪些Region，将这些Region组成重分配集(Relocation Set)


3. 并发重分配(Concurrent Relocate)

这个阶段会把重分配集(Relocation Set)中存活的对象复制到新的Region中，并为每个Region维护一个转发表(Forward Table)，记录从旧对象到新对象的转向关系。由于染色指针的特性，仅从引用就可得知一个对象是否处于重分配集中(Remapped 标记)，这次访问会被内存屏障截获，根据转发表中新的对象地址进行访问，并修正更新引用的值，使其指向新对象。这是指针的自愈(Self-Healing)能力，只有第一次访问旧对象会被转发，仅会被影响一次。


清理后的Region可以立即释放用于新对象的分配，不用担心很多指向旧对象的指针还未更新(图中红色箭头)，旧对象的指针访问对象的时候会被转发表路由到新的对象。

是不是很像你去访问一个老朋友(旧对象)，但是老朋友搬家了(内存复制)，但是家门口(转发表)写着新家的地址。


4. 并发重映射(Concurrent Remap)

重映射就是修正整个堆中旧对象的所有引用，但是由于自愈能力的存在，这个阶段并不紧迫，所以这个阶段通常伴随着下一次垃圾收集循环的并发标记(Concurrent Mark)阶段执行了，反正都是要遍历对象图，这样节省一次遍历。一旦所有指针都被修正后，记录新旧对象的转发表就可以释放了



5、总结


最后再来看官方声称的四大特性分别是如何做到的

支持TB级别的内存：Region分区管理、染色指针寻址

最大GC延迟时间在10ms内：全并发处理(仅对GC ROOTS进行遍历时会暂停)

应用程序吞吐量最多减少15%：当生命周期很短的对象分配速率很高的时候，大量对象不会被进行标记收集，会产生大量浮动垃圾从而影响吞吐量，并且堆中可转移对象的空间就会越来越小

为未来的GC新特性奠定基础：染色指针中未被使用的18 bits
