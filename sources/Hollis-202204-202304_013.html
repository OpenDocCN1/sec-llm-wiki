在这几年写代码的过程中，发现了很多非常实用的插件，绝大部分都是为了提效而生的，只要你是写Java的，并且在用Idea开发，就一定能够找到它们的用武之处！

这里我会先简单介绍一下这8款插件的功能，有一些插件的具体使用方法我会在今后的文章中具体介绍。

1、save action


没想到吧，第一个推荐的插件居然是它，不知道你们有没有用过它，但这也是我入职阿里后用的第一个插件，因为大公司通常会有代码格式化模板。

原因很简单，就是为了保证所有人都使用统一的代码格式提交commit，避免你在比较代码变更时发现有一大堆的差异居然都是格式的修改！

插件作用：主要就是在保存代码时自动完成代码格式化、以及import的整理，你无需手动进行格式化。使用save action插件，配合上idea的代码格式化模板，你就可以随心所欲的写代码了，不必担心任何格式化的问题。

2、generateAllSetter


这个插件的功能一看它的名字就可以猜出一二，写Java最讨厌的就是重复代码和一些繁琐的转换代码，比如我要把一个Java bean转换成另一个Java bean，那么你就必须要一个个属性地进行set，如果这两个bean有很多的属性，那么就更加酸爽了，光写set就要老半天，一不留神还可能写错，这个时候这个插件就派上用场了。

插件作用：为对象生成全属性的set方法，不仅支持set默认值，还支持set另一个bean的同名属性值，如果两个bean的属性一模一样，那么直接一键生成代码就搞定了，不可谓不方便！

3、JunitGenerator


又是一个功能就写在名字上的插件，用来生成单元测试类的神奇插件。

一般在大公司中经常要求工程师写单元测试，保证自己代码的基本功能可用，这本身是一个比较花时间的事情，但是一定程度上也保证了代码质量。作为开发者，我们自然不希望花太多时间在单测上，因此一些自动化的插件也是必不可少的。

这个插件就是用来帮你生成指定类的单元测试代码，当然了，它只是帮你生成基本的方法和目录，但是确实也是可以省不少时间的。

插件作用：一键生成junit的单元测试类，并且保证生成的目录结构和Java包下的代码一致

（在maven项目中，Java和test这两个包分别用来放工程代码和测试代码，同一个类的源码和测试代码应该保持路径一致，这样才能支持单元测试框架比如Junit这类工具进行代码覆盖率的统计）

4、GenerateSerialVersionUID


插件作用：不需要多做介绍，很明显，它是用于生成Java类的SerialVersionUID的

5、JSON 2 POJO & POJO to JSON


写web的同学们都知道，我们用springboot或者springmvc最经常打交道的就是JSON格式数据，这两个插件和名字一样简单，就是把JSON和Java bean互相转换。

插件作用：一键粘贴JSON生成Java bean，一键复制Java bean为JSON，当遇到大对象或者大JSON时，你就知道它有多好用了！

6、alibaba Java coding Guidelines


idea中必备插件之一，阿里巴巴代码规范，没少好说的，不管什么公司要制定团队代码规范，用这个准没错。

插件作用：自动检测代码规范问题，一般分为几个严重程度，正常来说把major级别的问题修复就好了，阿里巴巴十多年Java编程的沉淀，不会让你吃亏的。

7、JavaDoc


懒人福音，自动生成Java代码注释，写完代码没有注释看着不舒服，用它就对了。

插件作用：一键为所有类和方法生成JavaDoc注释。当然了自动生成的语法可能有点问题，最好还是手动修改一下。

8、maven helper



写Java基本离不开pom，当我们发现代码里出现了maven依赖异常，而不知道具体是哪里出错的时候，就可以通过maven helper 来排查出现依赖的冲突，maven helper支持图形化界面，也可以一键跳转到依赖对应的pom，以及一键exclude，是我们在编写Java程序时必不可少的插件之一。

插件作用：更方便地执行 maven 命令，分析和排除 Maven 冲突；
