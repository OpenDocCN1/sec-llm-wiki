# API安全应用场景系列：API业务异常侦测

针对OWASP公布的前10的API安全问题，我们现简单快速的理解下这些安全问题都是什么，这样才能找到明确侦测、防护的思路。

  

  

**A1 - 失效的对象级授权**

攻击者通过尝试攻击对象级别授权的API接口，来获得未经授权的数据，比如通过可预测订单ID值来查询所有订单信息。

  

  

**A2 - 失效的用户认证**

开发者对API身份认证机制设计存在缺陷或无保护设计，导致身份认证机制无效，比如弱密码、无锁定机制而被暴露破解等。

  

  

**A3 - 过度的数据暴露**

本来只是想给客户端三个数据信息，但没有设计好就可能是把整个数据集在客户端都展示出来了。

  

  

**A4 - 缺乏资源和速率控制**

未对API做资源和速率限制或保护不足，导致被攻击。比如用户信息接口未做频次限制导致所有用户数据被盗。  

  

  

**A5 - 失效的功能级授权**

通过修改HTTP方法，从GET改成DELETE便能访问一些非授权的API。

  

  

**A6 - 批量分配**

也就是本来应该只能是能够看某个人的某条信息，但结果我直接用了一个 users ，我没做任何授权，就把所有人的用户都返回回去了。

  

  

**A7 - 安全性配置错误**

系统配置错误导致API的不安全，比如传输层没有使用TLS导致中间人劫持；异常堆栈信息未处理直接抛给调用端导致敏感信息泄露。

  

  

**A8 - 注入**

与OWASP Web安全注入类型相似，主要指SQL注入、NoSQL注入、命令行注入、XML注入等。

  

  

**A9 - 资产管理不当**

对于API资产的管理不清，比如测试环境的、已过期的、低版本的、未升级补丁的、影子API等接口暴露，从管理上没有梳理清楚，导致被黑客攻击。

  

  

**A10 - 日志记录和监控不足**

缺失有效的监控和日志审计手段，导致被黑客攻击时缺少告警、提醒，未能及时阻断。

通过上述对OWASP API Top10的分析，可以看出A1、A2、A7、A9这四个安全问题可以通过基于Swagger文件的方式对现网上API业务进行风险侦测，Imperva API Specification功能可以自动化形成API业务基线（同时可导出Swagger文件），基于基线我们可以针对业务进行异常检测，业务基线包括了以下内容：

●API接口清单

●API接口请求方法

●API接口认证信息

●API接口传递参数的参数名、参数类型等信息

以上4个风险问题的侦测思路：

  

  

**OWASP API A1**

通过Imperva API Parameter Pinning功能，结合Specification文件作为基线结合认证Token，以及Session id多重方式来识别用户情况，防止越权访问

![](../Images/90d6897496bde36670d4a92e276dd152.png)

  

  

**OWASP API A2**

默认情况下会学习到Authentication Header，无需额外进行配置

![](../Images/98c344c0ea2f242bcbc4a4c76c797c68.png)

  

Imperva也支持用户自定义的验证HTTP Header

![](../Images/a5b193249c76ca785f8ece61204ace4f.png)

  

  

**OWASP API A7**

Imperva Microsensor可以通过监听流量情况，来识别是否使用https协议。

![](../Images/d78cac82b543b34389c3730ac4602b90.png)

  

  

**OWASP API A9**

利用已经建模好的API业务接口、参数等信息作为基线模版，同时结合在Swagger文件定义中对于“Depredated Parameter”的定义，结合这两个方面，我们就可以对A9安全风险进行很好的侦测。
