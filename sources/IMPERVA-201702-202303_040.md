# API正被广泛使用，我们需要先于攻击者加强保护

IDC 最近的一项调查报告称，有38% 的公司或组织认为，网络安全带来的直接威胁，以及相关的法律法规，会极大地影响了其未来两年的技术投资规划。该调查还显示，企业技术投资的主要动机通常是为了实现统一的安全性，对于数字驱动业务的企业这一动机更为强烈。这样的分析合情合理，因为采用统一的安全技术才能使组织能够更有效地应对新的网络安全威胁、数据隐私和数字主权要求。

  

![](../Images/458770b4e0a2dcf741814521154b7e48.png)

  

同时，IDC 的调查报告也反映了许多企业认可API 是未来创新的关键。如今，四分之一的企业至少有 10% 的营收来自于开放的API服务。IDC 预计这一数字在未来还会不断增加。然而，这些企业中有 27% 认为，安全、隐私和合规问题阻碍了更广泛地采用API扩展业务的进程。企业特别担心创新加速环境中，如果引入开放的生态系统的方法，自己会逐渐失去对 API 的控制。

![](../Images/75ad3f4d0cc66e6d5a2c6d4cba297e07.png)

图 1：公司年营收中API占比的增长。 资料来源：IDC

从IDC报告指出的这些发现中，我们可以认识到最重要的结论是：虽然许多组织认为 API 对加速发展至关重要，但他们同样担心随之而来的网络威胁。与此同时，企业正在积极投资统一的安全技术，以应对安全、合规和数据隐私方面的挑战。构建有效的安全系统使他们能够减轻威胁，并且利用 API 技术获取更多营收机会。 在这篇博文中，我们将阐述对 API 安全构成的几类威胁，并解释在过去企业如何管理这些威胁，以及他们需要采取哪些不一样的措施来真正实现API 保护。

## **按优先级考量****API ****的风险和安全**

API 服务面临的最明显的是错误的配置和分布式拒绝服务攻击 DDoS 。与这两类威胁相比，代码注入以及其他在 OWASP 排名前 10 的特别针对API 的威胁，目前则鲜有耳闻。 由于当前快速发展变迁的网络安全环境，使得一些真实存在的威胁可能被忽视，例如：恶意机器人、数据泄露、数据欺诈和权限滥用，恶意行为者和黑客们往往会瞄准这些盔甲上的细小裂缝。在分析了大量API 相关的安全事件后，我们发现三分之二的问题涉及不当的 API配置，而这类问题后果严重，往往会导致敏感的个人数据泄露。确定一个API服务是正常发布还是未知的暴露，是面向公众的还是仅限于内部使用的，是受批准受控的还是未经批准未记录的，在全面考量API 安全性时，上述这些都是重要的变量。

**WAAP****范畴之外的****API ****安全问题**  

## 

API 访问管理通常作为 API 解决方案的一部分提供。许多网关包含完整的 API 管理功能选项，例如数据转换、呼叫路由和排队能力，但这些通常不被视为安全功能。传统的 API 访问管理网关方案中，一些与安全相关的功能侧重于访问的授权验证、访问速率限制和功能调用的验证。

  

认识到 Web 应用程序防火墙 (WAF) 在保护 API 方面发挥的关键作用，WAF 方案的供应商们正在将产品类别逐渐调整为“Web 应用程序和 API 保护 (WAAP)”。除了机器人保护、DDoS 预防等WAF 传统功能外，现今的WAAP 方案中还能实现API 模式验证等针对性的保护能力。

  

对安全专家而言，如果可以获得最新 API 接口定义，可以更新上传到 WAAP 防护中，这样便可以验证每一次 API 请求。然而，现实的情形是并没有多少安全人员能够找到最新的、准确的 API 规范，更不消说让 DevOps 主动更新它们了，因为API 的实现确实会经历频繁地更改。实际上，当今大多数安全团队所能做的安全措施都在应用 WAF+API 网关组合来完成的，这不是真正意义上的WAAP保护。

  

真正的API 安全方案，需要能够自动地处理和满足所有API 服务相关的所有特定安全需求。 需要提供了更完整的视图，包括检测影子 API、完成数据发现和分析、能够针对恶意机器人的攻击提供高级保护、可以自动检测在线欺诈，以及实现下一代安全分析。API 服务的推出与繁荣，旨在实现快速有效的通信，并提供无冲突的服务体验。为了让安全性也能匹配API服务的性能水平，企业需要实现全面的应用安全性：包括增强 API 网关，更好地利用WAAP，或者采用提供上述功能的专用 API 安全解决方案。

### **成功管理 API 安全的 3 个步骤**

### 1.  **明确职责分工**

### 若有可能，应该在编码阶段将安全性“嵌入”到 API 实现中。如若不然，您需要一个独立安全团队和一个专门的解决方案，来确保API服务创建后能够正确实施安全性保障。

### 2.  **增强促进合作而不是相互竞争**

### DevOps 和 SecOps 团队通常会面临对需求实现及优先级的相互竞争问题。 DevOps 团队优先考虑发布速度；而SecOps 在发布时则会优先考虑安全性。 管理层必须通过设立相关的指标和合理的 KPI ，确保在两个团队间取得平衡。

### 

### 3.  **安全平台不是可选的而是刚需**

### 企业需要一个集成的、多功能的、统一的安全解决方案，管理和应对针对应用及 API的所有安全威胁。
