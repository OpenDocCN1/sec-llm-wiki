职业银行劫匪威利·萨顿 (Willie Sutton)在上世纪中叶的“职业生涯”里，盗取了大约 200 万美元的赃款。据说记者问及萨顿为什么选择抢劫银行时，他回答说：“钱就在那里。”虽然在后来的采访中，萨顿矢口否认说过这句话。无论如何，这句话一点没错，甚至仍然适用于今天的金融服务业。

虽然老式的银行抢劫案可能不会绝迹，但直接从实体银行偷钱在很大程度上是一种“上世纪”的做法。今天，网络犯罪分子追逐的货币是个人数据，攻击面变成了用来进行各种在线金融交易的 Web 应用程序，因为客户、合作伙伴和员工们每天都在使用着这些程序。

毫无疑问：金融机构面临的处境仍然是“钱在那里”。所有的数据泄露事件中，金融服务占比35%，无愧为 “最易受破坏的部门”。令网络犯罪分子高兴的是，COVID-19的大流行推动了在线银行业务的大规模增长，显著增加了可供窃取的敏感客户数据量。Imperva的研究展示了这些现实如何改变金融服务行业的威胁格局。随着 COVID-19 大流行拖入 2021 年，Imperva 研究实验室报告显示：在 2021 年 1 月至 2021 年 5 月期间，对金融服务行业的 Web 应用程序攻击增加了 38%。

金融服务面临的5大安全威胁

敏感数据泄露

网上银行业务的激增和金融服务领域更广泛的数字化，导致大多数组织需要管理更大量和更复杂的数据。上述一点，再加上即将出台的更严格的数据隐私法，使敏感数据保护成为前所未有的挑战。
行业的变化速度让所有数据存储的安全控制都显得脆弱，许多金融服务组织面临更大的数据泄露风险。 网络犯罪分子知道这一点。 对敏感数据的攻击正以惊人的速度升级。Imperva 研究实验室报告称，仅在 2021 年 1 月就有超过 8.7 亿条记录遭到破坏。 这超过了 2017 年全年被盗记录的总数。

分布式拒绝服务(DDoS)攻击

应用层的分布式拒绝服务(DDoS)攻击，其目标是 OSI 模型的顶层(也即应用层)。网络攻击通过连接请求的形式发起，其目标是用海量流量淹没服务器，从而使服务器资源不堪重负，直到它(们)不再能够响应。每秒请求数(RPS)越高，攻击就越激烈。
数字银行报告指出，“改善银行客户体验”应该是金融服务提供商的首要目标。而那些通过安全投入减轻攻击威胁，保障客户体验的公司拥有更高的推荐率、更大的市场份额，并且旗下的产品和服务更有可能向现有客户行销。从反面角度看，如果客户访问自己的网上银行服务被拒绝，他们通常的反应是生气。通常的后果是，不满的客户在社交媒体平台上抱怨，并转向不同的金融服务供应商，这样会严重损害银行的品牌形象。
Imperva 研究实验室发现，自 2021 年 4 月以来，针对金融服务的7 层 DDoS 攻击中的每秒请求数(RPS)增加了两倍。

勒索式拒绝服务(RDoS)威胁

2020 年末，Imperva 注意到严重的勒索式拒绝服务 (RDoS) 威胁数量大幅增加。该类针对全球数千家大型商业组织，其中包括许多金融服务机构。
RDoS 活动是基于勒索的分布式拒绝服务(DdoS)威胁，其动机是经济利益。勒索者经常在他们的勒索电子邮件中利用知名威胁组织的名称来要求以比特币付款，以防止对目标网络的 DDoS 攻击。
在 2021 上半年，Imperva 研究实验室注意到这类威胁的数量正在上升。今年的攻击模式与 2020 年的非常相似：
1. 勒索者发送一封电子邮件，有时会伴随着样本攻击，通常会使公司应用短时间下线。
2. 给目标一个星期的通知，以期按约获得付款(赎金)。
3. 勒索者威胁要在预定时间进行大规模袭击。

客户端攻击

当正常访问网站的用户(无意间)下载了恶意内容，不法分子就会通过拦截用户会话、插入恶意内容或网络钓鱼等方式进行利用和攻击，这样的情况我们称为客户端攻击。在金融服务领域，这类攻击的重灾区集中在支付信息窃取方向，通常利用跨行业的数千个网站的第三方脚本来实现。
金融网站往往很依赖第三方脚本，以期为客户提供更好的服务，但由于处理金融资产和其他敏感数据的数字交易量很大，它们很容易成为客户端攻击的目标。一旦信用卡详细信息被盗，网络犯罪分子可能会立即使用这些数据来攫取利益，或者出售给其他犯罪分子以供日后利用，任一种情形都会带来严重的风险。消费者及其金融服务提供商或许能发现这类攻击，但往往已为时已晚。

供应链攻击

自 1999 年以来， CVE系统已报告了超过 150,000 个零日漏洞，分布于各种常用软件、应用程序和组件之中。尽管人们普遍认为绝大多数软件漏洞并未报告，但仍有超过 11,500 个被定性为严重级别。所有金融服务的前端到后端处理势必集成了一组复杂的软件应用程序，这些应用程序涉及广泛：后台、中台、风险管理系统、业务开发、财务和IT等等。
应用可编程接口 (API) 往往是这些应用程序的核心，使各种应用能够相互通信的关键。API 通常会自行记录信息，例如各自的实现和内部结构，这些信息自然可以用作攻击软件供应链的情报。弱身份验证、缺乏加密、业务逻辑缺陷和不安全端点等因素使得 API 端点更容易受到攻击。随着金融服务组织与其他公司开展更多的合作，供应链攻击面不断扩大，攻击风险不断提高。
缺乏安全保护的供应链使很容易成为网络犯罪分子的目标，软件应用程序和 API 中的漏洞是渗透和破坏业务行之有效的一种方式。如今大多数软件都不是专有软件，攻击者会想方设法利用公司机构可能使用的各种各类软件框架及应用程序进行尝试。自 2020 年末的 Sunburst 攻击以来，随后又有多起类似其他攻击，人们自然会期望供应链安全会得到重视，但遗憾的是事实并非如此。
直接的结果是，监管机构开始聚焦这个问题。举例来说，金融服务行业的监管机构，如新加坡金融管理局和美国的 FFIEC（联邦金融机构考试委员会），已发布最新的指南，以期解决金融行业对供应链健壮性的需求。此外，2021 年 4 月，网络安全和基础设施安全局 (CISA) 和美国国家标准与技术研究所 (NIST) 也不约而同地发布了有关防御各种软件供应链风险的新指南。

正在被窃取的是什么样的数据？

Imperva 研究实验室发现，过去几年被盗的数据中有 74% 是个人数据。 这通常的定义是，单独使用或与其他信息一起使用可以识别、联系或定位单个人，或在上下文中识别个人的信息。
对个人数据的广泛窃取无可争议地表明，许多组织没有采取足够的保护措施。 因为在金融服务行业中，系统、人员和供应商会定期共享类似个人信息这类数据以完成交易，使得在很多情形下，从金融机构窃取个人数据变得比其他渠道更容易。 随着管理数据隐私的法规变得越来越严格，每个组织都必须做到在其数据资产中发现、识别和分类个人数据。实现这一点至关重要，因为只有知道个人数据的托管位置以及应用、用户的访问情况时，才能扩展保护范围，实现对个人数据的安全控制。

可采取哪些措施来减轻面临的风险

简单的答案是：首先确保数据可见可监控，然后才能有效地保护数据，以及所有的访问数据的所有途径。换言之，我们期望在不影响关键业务流量的情况下，保护组织的网站、移动应用程序和 API 免受自动化攻击；并且，还必须做到防御网络核心之外的 (应用层)DDoS 注入和帐户冒用等攻击。同时，全面的保护还意味着，通过 Web 应用程序防火墙 (WAF)、机器人管理、程序运行时保护和API 端点保护，为您的业务应用提供全功能的纵深防御。 
最重要的是，应对目前的风险，我们必须能够发现和标记敏感的个人数据，并对原始信息进行丰富和关联，从而为威胁预防和缓解提供准确的行为分析。这使得公司机构能够自动将安全控制扩展到管理的所有数据：无论是本地的、还是基于云的，当前处理的、还是已经存档的——以确保所有数据源的持续符合合规标准、可治理、有安全保障。
