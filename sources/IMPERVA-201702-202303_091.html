借助Imperva云数据安全解决方案（CDS）确保AWS RDS中的安全性和合规性

如果您是AWS RDS的用户，那您所在的企业正身处在全球的潮流之中。当前，全球各地富有远见的公司都在积极拥抱数据库即服务(DBaaS)，以更快地将新应用程序和服务推向市场，或降低数据库操作的成本和复杂度。


然而，对这些企业来说，他们所面对的冗长复杂的安全性和合规性要求依然没有改变。无论数据在哪里储存或使用，未能妥善保护好数据都是每起数据泄露事故的根本原因。



Imperva云数据安全（Cloud Data Security，简称“CDS”）是确保AWS RDS数据库安全性和合规性的优秀解决方案。CDS可用于AWS RDS支持的所有数据库类型，包括MySQL、PostgreSQL、Microsoft SQL Server、MariaDB、Oracle、Amazon Aurora和Amazon Redshift。


不过，在进一步讨论CDS之前，我们先深入探讨一个问题——如何在AWS RDS中实现高级别的安全性和合规性。



AWS RDS的安全性还不够高吗？



答案见仁见智。作为一种基础架构，AWS RDS本身所提供的安全性表现优异。


AWS RDS中支持的各种数据库类型也提供了一些内置的安全功能，包括访问控制、加密和日志等。虽然这些功能提供了一些关键的预防性安全控制，但是仍有一些关键要素缺失。




安全性和合规性方面的不足



01

可见性


在AWS RDS中可以非常方便地创建新数据库，且成本低廉，所以其中极有可能存在着大量数据库，而其中又有许多数据库不在安全和合规团队的监控之内。因此，这种情况下，最大的安全挑战之一是清楚掌握公司使用的全部数据库。而且，在所有的数据库中，您还要清楚最敏感和最有价值的数据存储在哪里。您的安全团队不可能保护他们根本不知道的数据。


02

监控


假设您可以找到全部数据库并知道所有敏感数据的存储位置，那么如何监视这些庞大的数据资产，以确保您能觉察到任何可能影响安全性或合规性的操作？试图通过查看日志来实现这个目标是不现实的，不仅因为事件数量庞大，而且需要先解析才能理解日志的含义。



03

责任


数据治理的最佳实践表明，您必须能够跟踪和报告所有信息——当前自己拥有哪些信息、信息的存储位置以及谁在访问这些信息。上述要求绝非可有可无，尤其是在拥有大量数据库的情况下。根据云安全联盟(Cloud Security Alliance)的一项研究，使用公有云资源的公司中，超过四分之三的公司表示，在他们转移数据库到云端后的很长一段时间内，合规性审计仍然是一个重大挑战。



为改进不足而需要采取的措施



为应对这些挑战并确保您的AWS RDS数据库保持安全性和合规性，您需要完成以下五大关键任务。


1.  盘点您的所有数据库（该任务需要持续整理）

2.  确定敏感数据的存储位置

3.  为您的所有数据库建立一套统一的安全政策，并在出现违反规定的活动时，及时向安全团队发送警报

4.  确认正常用户的行为表现，从而检测并标记出异常行为

5.  为合规审计做好准备




Imperva云数据安全帮您实现目标



作为保护AWS RDS数据库的云原生解决方案，CDS补充了AWS RDS中已有的预防性控制机制，为您的数据库提供了一套完整的安全性和合规性解决方案。


为达成上述目标，CDS提供了如下几种关键功能：


●  发现——只需几分钟，CDS就能发现您所有数据库的位置

●  分类——自动检测敏感数据的存储位置

●  告警策略——在任何违反安全策略的事件发生时及时通知

●  合规审计——按需提供开箱即用的合规性报告

●  安全洞察——通过观察常规用户行为模式，识别出您没有意识到的安全问题，并在出现异常活动时通知您。


凭借这些优势，CDS可以让您在合规失效或数据泄露事件之前发现并解决问题。作为一个SaaS解决方案，CDS无需安装软件。借助专利技术，CDS仅仅检查您的数据库日志，而无需扫描或访问您的数据，因此不需要数据库登录凭据。
