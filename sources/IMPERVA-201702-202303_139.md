# 云环境下的API安全自动化

当今网络环境下，API已经成为最常见的数据传输和交换方式。然而，状态异常、缺乏保护或遭受攻击的API端点，由于天生存在向公众服务暴露敏感数据的隐患，往往会成为重大数据泄漏事件的肇因。API服务的保护非常重要，Imperva对这个领域也相当重视，推出了对应的API安全解决方案。除了同类方案耳熟能详的功能之外，该方案特色在于能够建立一个动态的、主动的安全模型，保证API端点发布的第一时间即可受到保护。对端点实施持续的安全防护，保持对最新部署更新的实时同步，可能需要巨大的开销和运维投入。这是由于，一旦有API部署更新，每个相关API安全工具/设施都需要被通知到，做相应的模型更新，才能保障您的API端点得到精确的防护。要实现上述需求，其中一种途径是通过手动提供Swagger文件，同步新的API部署配置描述，以实现防护的实时更新。但如同其他很多手动流程一样，该方法存在较高的出错风险。同时，也很可能遭遇协调/编排上的瓶颈。由于围绕API的开发、运维、安全保障的过程，牵涉了包含安全部门，开发运维一体化，研发部门等诸多团队形形色色的人员。**AWS云服务与API安全**为应对这项挑战，我们开发了自动化获取API描述Swagger文件的方法。AWS云服务提供了”Amazon API 网关”这个产品，简化了API的定义、部署、分享和运维一系列操作。通过Amazon API网关服务的无服务器开发门户页面，部署或更新一个API的操作变得迅捷简单，成千上万的API可以在一天之内得到更新。如同前文所述，为了有效地保护API部署，似乎不可避免地涉及日常运维的投入，而我们推出的新功能，实现了快速自动化的操作，旨在减少甚至完全消除相关的运维开销。

## **入门指引**

从登录我们的云账户管理服务开始，用户可一步步实施解决方案。Imperva云应用安全系统账号一俟创建完毕，即时生成了一份CloudFormation模版。用户会被定向到AWS的CloudFormation控制台页面，完成AWS账号登录后，就可以根据提示一步步部署服务栈。**该方案部署的技术栈组成如下：**

*   使用AWS的CloudTrail创建一个Trail服务，将API网关的所有操作日志都记录到S3存储
    
*   设立一个CloudWatch事件规则，在API网关部署发生改变的时候触发
    
*   一个无服务器应用Lambda函数，获取(描述API服务的)Swagger文件，然后通过AWS消息通知服务(SNS)发送给Imperva
    

Imperva收到上述更新操作的提示，事件会立即被推送至Kafka消息队列，最后被相关的应用安全服务读取(此例中仅涉及API安全部分)。![](../Images/c2c2676f09e3c393ef7a9535380ed13b.png)亚马逊AWS云服务AWS提示服务堆栈部署成功后，便大功告成。今后每回API做更改，再不用惦记着去Imperva服务更新配置了，我们已经将这一系列操作都自动化实现了，为您免除后顾之忧。
