# Imperva支持AWS Security Hub集成：扩展客户安全可视性

本文旨在介绍Imperva安全应用产品与AWS Security Hub的集成方法，两者集成将使客户获得更佳的安全可视性，进一步提高对客户基于AWS应用的安全情况反馈效率。

  

保护AWA应用安全

缩减成本开支、简化操作程序等优势正驱动各大企业逐渐将应用迁移到AWS交付平台上，因为AWS将负责该平台上的所有基础架构维护。在企业向云服务迁移的同时，需要特别注意的是云服务提供商提供的服务是普遍基于共担安全责任模式的。关于此模式，AWS在其白皮书中进行了详细说明(**请点击左下角的“阅读原文”查看**)。

  

Imperva解决方案可利用多重防御手段为企业提供3-4层和7层的分布式拒绝服务(DDoS)攻击、OWASP十大应用安全风险以及零日攻击防护，帮助各类企业在其IT环境(包括AWS)中对所有应用实现统一保护。Imperva应用安全方案是获得Gartner及Forrester最高评分的WAF与DDoS防御解决方案。

![](../Images/b23337805df7c4d0b73bc7759435b454.png)

高安全可视性带来积极影响

Imperva Attack Analytics可进一步增加企业的WAF安全性，该产品利用机器学习技术将Imperva WAF资产中的无数安全事件进行关联，并按优先事件进行小范围分组，使安全团队能够更高效的对企业内部环境进行清晰了解并采取可行性的措施。

  

AWS Security Hub是一款新型web服务，可在AWS服务及第三方解决方案中实现统一安全届面。Imperva将其Attack Analytics 平台接入AWS Security Hub，从而通过Security Hub控制台即可完成安全事件的Attack Analytics功能。

  

集成方法简介

利用AWS Security Hub界面即可进行集成工作，找到Findings Provider(FP)工具，即所谓的“外部数据连接器”。FP可帮助AWS Security Hub从Attack Analytics中提出标准化信息，然后对该信息进行解析、分类与显示。FP是面向Imperva及AWS客户的免费工具，可从本文末的Imperva’s GitHub页面中获取。

  

![](../Images/3380becee04737371d9e922c6c770293.png)

AWS Security Hub中Attack Analytics信息的截屏

  

Attack Analytics与AWS Security Hub间的数据交换方式为Attack Analytics将安全事件导出到客户帐户内的一个AWS S3 bucket中，然后Imperva FP将此类信息上载。

  

![](../Images/4b7a95dd4493d4466fc2a29035ba6b2c.png)

Attack Analytics 与AWS Security Hub间的事件流动示例

  

在启动AWS Security Hub以使用Imperva FP工具前，客户需按照AWS Security Hub文件中的规定进行几项配置。在启动AWS Security Hub过程中，FP在客户环境中运行时需要从AWS Security Hub中获取产品导入口令。在FP启动后，FP即被授权将其发现以AFF格式导入到AWS Security Hub帐户中，这一过程可按设定的时段执行。

  

最关键的是企业通常要在构建或迁移应用至AWS架构上时，保持稳定的应用安全控制。Imperva帮助企业确保各类应用都能获得已知攻击及零日攻击威胁，并通过与AWS Security Hub集成，Imperva Attack Analytics可确保企业始终了解其企业应用安全的最新且最准确情况。

  

Security Hub初期还只是公开预览版。我们正寻找对此功能感兴趣的现有的Attack Analytics客户，与我司一起对该集成工作进行精练。如您对此感兴趣，请立刻联系我们。SecurityHub面向公众开放后，我司将在Imperva’s GitHub account中将Security Hub集成方案作为开放源项目提供给大家。
