# 顺应SecOps趋势--Imperva发布Python SDK

 企业WAF管理是一项复杂的工作。需要自定义策略、签名、应用模型学习、网关插件设置等，最合理的原因当然是认为自己设置的都是最佳方案。

  

在安全团队负责处理十多台WAF堆栈及应用时，还相对容易管理。但现在，安全团队都转向了云与微服务，企业不得不自己处理成千上万个网络端点的安全问题，更何况这些端点又会随时变化。

  

有位Imperva AWS客户采用严格的还原策略，即：每60天就还原整个网络环境，重新开始部署。在此过程中，所有不受控与自动化程序都将被清除，包括其对应的安全产品与配置。虽然这一特殊情况给安全专家们带来了特殊挑战，但我们Imperva有了相应的解决方案。

  

我们近期发布了**Imperva GitHub**，这是全球社群都可从中获取工具、代码库及其它纯净资源等有助于实现协作并简化开发工作的社区平台。

  

也就是说，我们开发的**Imperva-sdk****是一种基于****Imperva GitHub****的开源项目。**遍布全球的Imperva员工都可以用自己的方式来帮助SDK及完成更多项目的实施。对于Imperva专业人士与有经验的Imperva客户来说，这种新型协作方式将有助于进一步推动知识共享，并加快产品交付。

  

***保障数以万计的网络端点安全并不是痴人说梦***

长久以来，Imperva SecureSphere一直致力于提供自动部署支持以及扩大其管理REST API的覆盖。但管理员还需自行编写自己的wrapper并与粒度API集成。

本文中介绍的是*Imperva-sdk* –Imperva SecureSphere Open API使用的Python SDK，包括如何利用SKD自动化管理企业的SecureSphere，适应各种环境迁移，从源头控制相关配置，并转换到更为SecOps的理念。

Imperva-sdk 最强大的特性之一就是其能够将SecureSphere管理服务器的整体配置导入到JSON中（注：仅支持在SDK中部署的API的导入与导出）。此功能方便企业用户拷贝管理服务器间的配置，从源头控制其WAF配置，并轻松将WAF设置纳入企业的CI/CD过程。
