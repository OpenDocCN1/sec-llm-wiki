# 物联网安全干货丨使用AFL++对物联网二进制文件fuzz

American Fuzzy lop 是一种面向安全的模糊器，它采用一种新型的编译时工具和遗传算法来自动发现干净、有趣的测试用例，这些测试用例会触发目标二进制文件中的新内部状态。这大大提高了模糊代码的功能覆盖率。

![](../Images/8704c46d16ff036cf1e6bf0e0cab2e1f.png)

AFL 有一段时间没有更新了。虽然 AFL 仍然可以正常工作，但有一个新项目 AFL++，它是 AFL 的一个分支，有很多改进和新功能。AFL++ 可以在https://aflplus.plus/上找到，它的源代码在GitHub 上。在本文中，我们将研究使用 AFL++ 来模糊 IoT 二进制文件。

当我们有相关二进制文件的源代码时，模糊测试效果最好。但对于物联网二进制文件，情况通常并非如此。AFL++（和 AFL）附带一个配套工具（afl-gcc、afl-clang 等），作为 gcc、clang 或任何其他标准构建工具的替代品。该工具用于在编译源代码时在生成的二进制文件中注入检测。然后可以使用 afl-fuzz 对检测过的二进制文件进行模糊测试。

Fuzzing 闭源应用程序很棘手。为了对此类二进制文件进行模糊测试，AFL++ 可以使用 Qemu、unicorn 或 Frida，并分别命名为 qemu 模式、unicorn 模式和 Frida 模式。这些是纯二进制检测模式，不如源代码检测模式高效。我们将在本文中使用 Qemu 模式。

在 Qemu 模式下，AFL++ 使用 qemu 用户模式仿真来运行二进制文件。它使用 Qemu 的修改版本，在程序执行时检测基本块。由此生成的检测信息用于生成新的测试用例，这些测试用例触发不同的代码路径，从而提高代码覆盖率。qemu 模式下的 AFL++ 也可用于检测外部架构二进制文件（如 x86\_64 主机上的 arm 二进制文件）。这对于模糊物联网固件二进制文件非常有用，这些二进制文件通常是 ARM 或 MIPS 架构。

需要注意的重要一点是 AFL++ 和类似的模糊器（AFL、hongfuzz、radamsa ）仅适用于文件输入，即程序必须只接收来自文件的模糊输入。不支持从套接字获取输入的程序。

**对于基于套接字的模糊测试程序，我们可以采用以下任一方法：**

*   如果应用程序的源代码可用，则重写应用程序以接受来自文件的输入。大多数时候不需要重写整个应用程序。我们可以编写一个小测试函数，读取文件并使用数据调用另一个我们想要进行模糊测试的函数。
    
*   对于闭源应用程序，重写源代码不是一种选择。在这种情况下，有一些技巧可以将套接字的二进制文件转换为使用文件。这些方法通常使用 LD\_PRELOAD 来覆盖套接字函数并使它们从文件中读取/写入。Preeny和desockmulti就是两个这样的脱套工具。

 编译 AFL++ 

![](../Images/ae082ded321b4ef6995b6a9d8a5780a7.png)

AFL++ 可以在任何 Linux 系统上编译。这里我们使用的是 Ubuntu 20.04 LXD 容器。步骤如下：

$ sudo apt update

$ sudo apt install git make build-essential clang ninja-build pkg-config libglib2.0-dev libpixman-1-dev

$ git clone https://github.com/AFLplusplus/AFLplusplus

$ cd AFLplusplus/

$ make all

$ cd qemu\_mode

$ CPU\_TARGET=arm ./build\_qemu\_support.sh

  

![](../Images/18ce5aff01d4e24f3ee3444cde905bf3.png)

   模糊 xmlparser1   

![](../Images/ae082ded321b4ef6995b6a9d8a5780a7.png)

在进行模糊测试之前，我们需要知道程序如何接受输入。使用qemu-arm-static和 --help 参数运行xmlparser1会显示用法。它接受带有 -f 参数的文件名。-d 参数代表调试。

![](../Images/add7b6d69f7df89a515977faae790f3b.png)

我们可以创建一个测试 XML 文件并运行xmlparser1。

![](../Images/5bbd1603a4d4e11e9d7147e49ed107cf.png)

xmlparser1显示test.xml文件的解析内容。我们现在可以继续进行模糊测试。要运行模糊器，我们需要提供一个输入文件，模糊器将使用该文件生成进一步的测试用例。我们将指定test.xml作为我们的输入文件。

创建两个目录input-xml和output-xml并将test.xml文件移动到input-xml中，如图所示。

![](../Images/07a929c0070189cfba4d0f3fd8e4b288.png)

我们现在可以启动afl-fuzz

![](../Images/648cb674f97079555baef93f233920e3.png)

$ QEMU\_LD\_PREFIX=./squashfs-root/ ../AFLplusplus/afl-fuzz \\

            -Q \\

            -i input-xml/ \\

            -o output-xml/ \\

            -- ./squashfs-root/usr/sbin/xmlparser1 -f @@

选项解释如下：

*   \-Q：在 Qemu 模式下使用 AFL++
    
*   \-i：输入目录的路径
    
*   \-o：输出目录的路径。该目录将包含在二进制文件上触发有趣行为的文件，例如崩溃或挂起
    

双连字符 (--) 之后的所有内容都指定要与其参数一起运行的目标程序。@@ 参数代表文件名。在运行时，AFL++ 会将@@ 参数替换为输入文件的名称。

fuzzing 会话开始如下所示。我们可以随时按 Ctrl+C 退出。

![](../Images/beb6b9878afb2c122f8252e7cb6e0ea3.png)

在我们的简短测试中，AFL++ 无法使应用程序崩溃。

  

![](../Images/18ce5aff01d4e24f3ee3444cde905bf3.png)

   模糊 jsonparse   

![](../Images/ae082ded321b4ef6995b6a9d8a5780a7.png)

Jsonparse 是一个类似的二进制文件，但它解析 JSON 文件而不是 XML。不带任何参数运行程序会显示其用法。

![](../Images/fea9f256b7196e89cfba554f4148504c.png)

我们可以创建一个测试 JSON 文件并在其上运行 jsonparser。

![](../Images/78ba4b192f40f84347588389de500ad4.png)

我们可以使用相同的test.json文件作为 fuzzer 的输入。以类似的方式，在 input-json 目录中使用 test.json 创建两个名为input - json和\*\*output - json的目录。

![](../Images/82849ae773dd894968ff80b2ab5c450c.png)

我们可以运行 fuzzer，如下所示：

![](../Images/0c8cfd5558611867a1ca13034eab0bf6.png)

$ QEMU\_LD\_PREFIX=./squashfs-root/ ../AFLplusplus/afl-fuzz \\

            -Q \\

            -i input-json / \\

            -o output-json / \\

            -- ./squashfs-root/usr/sbin/jsonparser @

![](../Images/db0d5d00353768fa9a10ca22c4319f38.png)![](../Images/0cfc92e258d660f9e999f88286160819.png)
