2019年6月，在移动开发领域做消息推送8年的极光，跨界推出了定位于IoT设备的接入管理平台JIoT平台，2020年极光JIoT物联网服务下线。


当初选择JIoT物联网平台的企业，面临设备迁移的挑战。吸取教训，我们选择迁移到国内最大的阿里云IoT物联网平台，避免遭遇到类似美团云关闭，苏宁云关闭等黑天鹅事件。


1.极光JIoT平台分析


极光JIoT在设备接入中使用与阿里云物联网平台类似的身份标识，并提供MQTT作为设备数据和控制通道，提供HTTP作为OTA固件下载通道。

  • 使用product key、device name和device secret来标识设备

  • 提供MQTT作为设备数据和控制通道，建联时使用设备标识来鉴权并连接极光IoT平台

  • 提供HTTP作为设备固件下载通道，当设备从MQTT通道上收到OTA信息时，可使用HTTP从指定URL获取固件

设备端C-SDK分析

  • 极光IoT C-SDK地址：https://github.com/jpush/JIoT-SDK-C

  • 阿里云IoT Link SDK 4.x 地址：https://code.aliyun.com/linksdk/base

极光IoT C-SDK与Link SDK 4.x对比


2.设备迁移方案

  • 极光IoT C-SDK默认适配以上5种平台，可使用Link SDK 4.x进行替换，android（可复用 linux）、freertos、linux这3种平台已提供默认适配。

  • 极光IoT C-SDK仅提供MQTT和OTA两个功能，可对应到Link SDK 4.x的相同功能组件，参考demo进行替换即可

设备端SDK API对比及迁移建议如下:


2.1 属性上报API示例对比

极光SDK:

// 极光IoT属性上报
Property property[2] = {
    {
        .name = "LightSwitch",
        .value = "1";
        .time = 1586766316
    },
    {
        .name = "WorkMode",
        .value = "0";
        .time = 1586766316
    }
};

PropertyReportReq req；

memset(&req, 0, sizeof(PropertyReportReq));
req.seq_no = 0;
req.version = "1.0.0";
req.property_size = 2;
req.pProperty = &property;

jiotPropertyReportReq(handle, &req);


阿里云IoT Link SDK:

// 阿里云IoT Link SDK 4.x 属性上报
aiot_dm_msg_t msg;

memset(&msg, 0, sizeof(aiot_dm_msg_t));
msg.type = AIOT_DMMSG_PROPERTY_POST;
msg.data.property_post.params = "{\"LightSwitch\":1,\"WorkMode\":0}";

aiot_dm_send(handle, &msg);


2.2 事件上报API示例对比

极光SDK:

// 极光IoT事件上报
Event event = {
    .name = "Error",
    .content = "{\"ErrorCode\":0}",
    .time = 1586766316
};

EventReportReq req;

memset(&req, 0, sizeof(EventReportReq));
req.seq_no = 0;
req.pEvent = &event;

jiotEventReportReq(handle, &req);


阿里云IoT Link SDK:

// 阿里云IoT Link SDK 4.x 事件上报
aiot_dm_msg_t msg;

memset(&msg, 0, sizeof(aiot_dm_msg_t));
msg.type = AIOT_DMMSG_EVENT_POST;
msg.data.event_post.event_id = "Error";
msg.data.event_post.params = "{\"ErrorCode\":0}";

aiot_dm_send(handle, &msg);


这样我们轻松搞定了设备端切换到阿里云IoT物联网平台。
