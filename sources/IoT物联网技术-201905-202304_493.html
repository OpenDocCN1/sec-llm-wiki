在物联网场景中，很多设备都是上传二进制数据的，IoT物联网平台的消息Payload同样支持二进制数据的传输，并非强制JSON格式。本教程我们通过nodejs模拟设备端以自定义Topic上传二进制数据的Payload，并通过规则引擎处理，保存到数据库中，供业务系统使用。

2.2 设备端代码

获得设备身份后，我们通过Nodejs代码来模拟硬件设备上报二进制数据，对应Topic和Payload如下：

完整程序代码如下：

/**
 npm i alibabacloud-iot-device-sdk
*/

const aliyunIoT = require('alibabacloud-iot-device-sdk');

// 设备身份信息
const deviceInfo = {
    productKey: '替换产品code',
    deviceName: '替换设备code',
    deviceSecret: '替换设备secret',
    region: 'cn-shanghai'
}

// 创建 aliyunIoT.device 对象将会发起到阿里云IoT的连接
const device = aliyunIoT.device(deviceInfo);

const topic = `/${deviceInfo.productKey}/${deviceInfo.deviceName}/user/update`;

// 监听 connect 事件
device.on('connect', () => {
    console.log('connected!');
    // 上报数据
    doPublish();
});

// 监听 message 事件
device.on('message', (topic, payload) => {
    console.log(topic, payload.toString());
});
// 监听 error 事件
device.on('error', (err) => {
    console.log(new Date().toString(), err.toString());
});

// publish 二进制数据
function doPublish() {
    var payloadArray = [0, 78, 0, 1, 0, 0, 39, 18, 2, 49, 51, 15, 52, 54, 48, 48, 52, 48, 54, 48, 56, 49, 48, 54, 54, 52, 52, 2, 49, 52, 17, 49, 53, 45, 56, 57, 45, 50, 101, 45, 98, 101, 45, 56, 97, 45, 101, 49, 2, 49, 53, 8, 83, 80, 69, 67, 45, 86, 49, 48, 2, 49, 54, 7, 81, 89, 68, 45, 86, 49, 48, 2, 49, 50, 2, 50, 57, 0];

    device.publish(topic, new Buffer(payloadArray), { qos: 1 })
}

2.3 云端规则引擎配置

为了接收设备端二进制数据，我们提供规则引擎的to_base64(*)函数进行编码，并存储到表格存储数据库中。


数据处理SQL如下：

SELECT 
  deviceName() as deviceName,
  timestamp() time, 
  to_base64(*) payload 
FROM 
  "/${productKey}/+/user/update"

至此，我们掌握了自定义Topic传输二进制数据的完整过程。我们数据库存储的是base64的字符串，给我们业务系统带来额外的工作量。因此，我们建议给产品定义物模型，通过云端js解析脚本直接在云端把二进制转换成json数据，再存储到数据库中，这样我们业务系统就可以直接使用数据，减少base64编解码的工作量。
