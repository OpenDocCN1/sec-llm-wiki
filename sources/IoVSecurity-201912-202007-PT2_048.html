加密应用程序的安全性严重依赖于不断保密的对称密钥和私钥。用来保密的方法也受到保护。



现代加密技术使用两种基本类型的算法-非对称密钥和对称密钥。非对称密钥算法使用私钥和公钥的组合，而对称算法仅使用私钥（通常称为私钥）。该表提供了每种算法方法的主要功能的快照。



现在，让我们研究如何使用这两种算法来实现每个加密目标。


使用对称密钥算法的机密性


您记得，机密性的主要目标是使信息不受所有不了解信息的人的保护。在对称密钥密码系统中，这非常简单，可以通过加密在发送方和接收方之间交换的数据来实现。发件人和收件人都可以访问用于加密和解密交换的消息的同一密钥（图1）。



  1. 对称密钥算法使用私钥或秘密密钥帮助实现机密性。




只要密钥是安全的，只有发送者和接收者都可以访问加密/解密密钥，即使传输中途被截获，其他人也无法接收到该消息。因此，该消息保持为“机密”。


使用非对称密钥算法的机密性


在非对称密钥系统中，接收者自由分配其公共密钥。发送者获取公共密钥并验证其真实性。完成此步骤需要几个步骤（图2），我们将在下一篇文章“加密算法”中解释该过程的详细信息。但为简单起见，我们假设发件人可以访问收件人的已验证公共密钥。然后，发件人使用该公钥加密消息并将其发送给收件人。


2.非对称密钥算法通过使用公钥和私钥来帮助实现机密性。


收件人的公钥在数学上与收件人的私钥相关。发件人以及与此相关的任何其他人都无法访问收件人的私钥。收件人收到消息后，将使用私钥对消息进行解密。收件人的私钥是唯一可用于解密使用相关公钥加密的邮件的私钥。由于私钥仅位于收件人的手中，因此其他人或组织无法解密已发送的消息。因此，该消息保持为“机密”。

为什么我们需要一个“ Nonce”？


冒名顶替者可以控制接收者发送的最新摘要，然后对该摘要进行“身份验证”。这些类型的攻击称为“重播攻击”，即重新发送以前使用的摘要。使用“随机数”或一次性使用的随机数进行身份验证可防止此类攻击。在这种情况下，身份验证将失败，因为对于每次身份验证，发送方都需要一个具有全新随机数的新摘要。这些数字通常使用批准的随机数生成器生成。

在进入下一个主题之前，我们需要了解以下两个概念之间的区别。


  • Secure Hash 安全散列

  • HMAC（Hashed Message Authentication Code 散列消息身份验证码）


图8说明了HMAC和安全散列之间的区别。本质上，Secure Hash使用散列算法（例如SHA-3）来生成消息的固定长度散列，而与消息长度无关。HMAC与之类似，但是它使用密钥作为散列引擎的附加输入。不管输入消息的长度如何，它也会产生固定长度的散列。


8. HMAC和安全散列之间有相似之处，但主要区别。



使用对称密钥算法维护完整性


保持邮件完整性的目的是确保收到的任何邮件或正在连接的任何新设备都不会携带不需要的代码或信息。


让我们看一个示例，该示例说明如何使用对称密钥算法（例如SHA-3）来实现此目标。稍后，我们将详细介绍这些算法的工作原理。


在图9中，发送方使用特定的密钥来计算消息的摘要。由于这是对称密钥方案，因此该密钥在发送方和接收方之间共享。我们将在后面的文章“加密算法”中讨论密钥共享的安全方法。使用密钥生成的摘要或散列称为HMAC（基于散列的消息身份验证代码）。



9. SHA-3对称密钥算法保留完整性。


这是通过将消息和密钥提供给SHA-3引擎生成的。然后将生成的HMAC和消息发送给收件人。接收者随后使用她的密钥生成自己的HMAC。然后将两个HMAC进行比较，如果它们匹配，则表明邮件未被篡改。


在这种情况下，某人可以同时拦截HMAC和消息，更改消息，生成新的HMAC，然后将其发送给收件人。但是，这将不起作用，因为拦截器将没有收件人的秘密密钥，并且HMAC将不匹配。


使用非对称密钥算法保持完整性


保持邮件完整性的目的是确保收到的任何邮件或正在连接的任何新设备都不会携带不需要的代码或信息。我们来看一个使用非对称密钥算法（例如ECDSA）如何实现此目标的示例。


其基本思想是，发件人使用数字签名对邮件进行签名，而收件人则对签名进行验证，以确保收到的邮件的完整性。


在图10中，发送方通过将消息提供给SHA-2散列引擎来计算消息的摘要。由于这是非对称密钥方案，因此发件人和收件人之间不会共享此密钥。发送者拥有一个永不共享的私钥，而接收者拥有一个可以与许多人共享的公钥，反之亦然，与对称密钥算法不同，在对称密钥算法中，生成的摘要/散列不使用密钥。


10. ECDSA非对称密钥算法有助于保持消息的完整性。



然后将生成的摘要与发送者的私钥一起馈送到ECDSA引擎，以生成邮件的数字签名。该签名和消息一起发送给收件人。这样就完成了已发送消息的签名过程。


现在，收件人已经从发件人接收到消息和数字签名，可以开始验证过程了。此过程包括两个不同的步骤：


接收者根据接收到的消息计算出消息摘要。

然后，新计算的摘要，从发件人接收到的数字签名以及发件人的公钥将被送入ECDSA引擎进行验证。

在验证过程中，ECDSA引擎产生“是”或“否”结果。如果结果为“是”，则消息完整性得以保留。如果结果为“否”，则表明消息完整性受到损害。


使用非对称密钥算法的不可否认性


由发件人使用数字签名签名的消息可用于证明该消息是发件人发送的，并且该消息未更改。但是，数字签名不能证明发件人的身份。身份证明是通过使用数字证书来实现的。

主要思想是，发送者和接收者都需要彼此证明自己的身份，并且各自的公共密钥需要由受信任的第三方证明是真实的。


为什么使用数字证书如此重要？如果没有它，假装为发送者的人（即冒名顶替者）可以发送使用收件人的公钥加密的消息以及用冒名顶替者的私钥签名的数字签名。然后，冒名顶替者会将其伪造的公共密钥发送给接收者。随后，接收者将使用该公钥来验证数字签名，并且所有内容都将得到验证。但是冒名顶替者发出的消息可能包含恶意信息，收件人永远不会怀疑。可以通过使用数字证书来避免此问题，该证书可验证收到的公钥确实确实属于发送者而不是冒名顶替者。
