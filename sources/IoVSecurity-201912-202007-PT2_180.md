# 全自动驾驶汽车不切实际：网络安全专家

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzU2MDk1Nzg2MQ==&mid=2247485659&idx=2&sn=2117b5816761471169e88fbaa9467d3d&chksm=fc015811cb76d107501e351999fc7092aeda76ed2a6bb83c7f0398b7cd4461576d8ea3dc12d5&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzU2MDk1Nzg2MQ==&mid=2247485659&idx=2&sn=2117b5816761471169e88fbaa9467d3d&chksm=fc015811cb76d107501e351999fc7092aeda76ed2a6bb83c7f0398b7cd4461576d8ea3dc12d5&scene=27#wechat_redirect)

GuardKnox的首席执行官Moshe Shlisel忙于为汽车开发强大的网络安全解决方案，但他承认，此时的全自动驾驶汽车提出了许多艰巨的挑战。（GuardKnox）  
GuardKnox的创始人兼首席执行官Moshe Shlisel拥有开发飞机安全解决方案的背景，因此对运输车辆安全方面的挑战并不陌生。出于对汽车安全方面无数技术难题的关注，Shlisel相信全自动驾驶汽车的愿景不会很快实现。  
Shlisel认为，公众接受自动驾驶汽车的道德问题是一大障碍。他说，出于安全考虑，人们乘坐它们会感到舒适。以机械手为例，Shlisel问：“您要让一位家庭成员登上其中一辆吗？”  
Shlisel说：“我们永远不会看到5级（完全自动驾驶）车辆。除了道德问题之外，您还面临明显的网络安全挑战。车辆的连接性越强，安全问题就越多。”  
  
如果有人有资格就运输车辆的安全性问题发表演讲，那就是Shlisel。他是以色列空军的资深人士，曾担任特种作战部副司令官，并监督了高度复杂产品的开发和应用，包括基于硬件的安全解决方案的开发和实施。  
Shlisel希望利用GuardKnox的专业知识，该公司专门研究基于硬件的解决方案，以实现汽车网络安全，防止车辆被盗以及为电动汽车充电。该公司还为OEM，一级或售后市场开发可定制的网络安全解决方案，仅使用软件或使用客户指定的硬件。  
该公司的解决方案使用了Shlisel所说的“通信锁定”方法，该方法是从以色列喷气式飞机上部署的安全硬件中借用的，从而在车辆的各个网络之间实施了经过正式验证和确定性的通信配置。根据Shlisel的说法，GuardKnox已与一级汽车OEM厂商达成了许多开发协议。  
Shlisel说，对于汽车来说，这涉及一个中央网关ECU（电子控制单元），通常将5到10个网络和100到150个单独的ECU链接起来，以控制各种汽车功能。诀窍是使所有这些元素互相配合，而不会造成干扰或对汽车的运行产生不利影响。  
由于调试软件的复杂性，Shlisel绝大多数赞成基于硬件的方法。“使用硬件，您只需插入即可。如果更改一段软件代码，则存在将该代码与不同公司的系统集成的问题。”  
Shlisel补充说，由于车辆不在固定路径上行驶，这使汽车的网络安全挑战变得复杂，就像它在导轨上那样，例如，在机场候机楼之间载客的自动列车就是这种情况。  
朝着提高车辆安全性迈出的一步可以是标准，Shlisel指出，ISO / SAE 21434“道路车辆–网络安全工程”将是朝正确方向迈出的一步。该提议的标准定于今年晚些时候推出，它将通过一套通用的术语集为汽车网络安全提供全球标准，该术语集将部署在整个汽车供应链中。
