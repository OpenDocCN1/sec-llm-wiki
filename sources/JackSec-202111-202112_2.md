去网上搜了搜Gerapy，是开源的爬虫工程师的可视化工具，用python开发，基于Django框架。

  

**0x01 环境准备**

*   
*   

```
pip install gerapy==0.9.6    ##我们的主角pip install scrapyd  ##主角通过这个工具实现的爬虫
```

![](../Images/90c1e9f6b9152cbe08e2d4c2bf799e15.png)

*

gerapy init [--folder=<folder>] ##初始化cd gerapy   ##进入工作目录gerapy migrate ##自动创建数据库gerapy createsuperuser   ##设置管理员账号密码gerapy runserver 0.0.0.0：8000   ##开启服务

**0x02 漏洞分析复现**

使用小工具查一下哪个文件里面涉及Popen命令，发现了如下几个文件。

![](../Images/d7203f130c23e59e43252599f5915d33.png)

  

挨个排查，在views.py文件中发现了友商说的project\_clone端点：  

![](../Images/b8108164653e43f5d412a7a836f86b2c.png)

  

因为之前没有研究过django，不知道url和后端处理类是怎么链接的，只能在web页面上试着找**克隆**字眼，创建项目处发现了：  

![](../Images/e5ef006e3361bf95c841e0feb143fe1d.png)

  

随便打个地址，抓个包：  

![](../Images/b6e0f638a8ba5407866276525775fd57.png)

  

也不知道对应的后端对应的类是不是这块，鉴于我不会在django里面打断点，只能用笨办法，直接修改views.py文件，加个打印  

![](../Images/2c5c7c75d20b1e2e88c94ff983b2695e.png)

![](../Images/8eec302f55b5b9a073a26253cad276ec.png)

**0x003 总结**  

这个漏洞需要登录系统才能触发，利用有难度。  

该文件还有两处Popen：  

![](../Images/fa6a32787783c2cd9675787a5aeb0328.png)

  

![](../Images/bcfbb89ada78af5579c98ae088c2c35a.png)

第一张图中可以执行命令的地方是project\_name参数，可以看到上面是对该参数做了安全处理的，将一些特殊字符删了。这里试了试没有发现可利用的。

第二张图没有对执行的前端传入的project\_path和spider\_name做处理，理论上是存在漏洞的。由于我弄了半天，实在是不会用这个工具爬虫，不是爬虫工程师的料，所以没有复现这点。
