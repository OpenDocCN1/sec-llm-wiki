**议题简介**

  

EDR（Endpoint Detection and Response，端点检测与响应）是最近几年最为流行的安全技术之一。相比传统终端安全软件，EDR 产品通过对操作系统上相关事件的细粒度监控与记录，在高级威胁检测、入侵事件溯源等方面有着更为明显的优势。

  

在国内，安全厂商推出的 EDR 产品基本面向 Windows，而面向 macOS 的 EDR 产品却屈指可数，即便是安全社区关于 macOS EDR 技术的讨论也寥寥无几。与此同时，MacBook 的流行使得企业对 Mac 设备的采购数量急剧上升，而针对 macOS 的恶意软件、攻击事件等在数量和复杂性上也呈现出明显的增长趋势，为了保护公司的资产安全，一些企业不得不选择自己研发 macOS EDR 产品。

  

实现一个 macOS EDR 客户端，有多种技术方案可供选择，如 Kernel Extension、Endpoint Security Framework 等。抛开技术实现难度，这些方案都有较高的“使用门槛”：开发 Kernel Extension 模块需要从 Apple 获得 kext 签名权限；使用 Endpoint Security Framework 要求 macOS >= 10.15，而且该框架提供的安全能力和 macOS 的版本也存在较大的关联性，此外也需要从 Apple 获得对应的 entitlement 权限。对于新入场的开发者而言，前者基本不可能申请到，后者的申请难度和审批周期也都是难以接受的，仅申请周期就能长达数月甚至超过一年。

  

因此，开发一个不依赖于 Endpoint Security Framework 的用户态 EDR 客户端，成为了一种可行却又必须选择的技术路线：既能缓解权限申请带来的时间成本，又能覆盖最近五年、甚至是未来一段时间内不同版本的 macOS 操作系统。

  

本议题将详细介绍在 macOS 下实现一个不依赖于 Endpoint Security Framework 的用户态 EDR 客户端可能用到的各种技术方案，以及实现过程中需要注意的各种问题和对应的解决方案。
