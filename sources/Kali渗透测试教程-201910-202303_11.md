# 开源SOC实现（七）-自动调查之目的IP地址

[上一篇文章](http://mp.weixin.qq.com/s?__biz=MzI3NDYwMzI4Mg==&mid=2247486122&idx=1&sn=eeeea8195d42504c1cdff28fdec07318&chksm=eb10c6d7dc674fc18835a73a4787189b4e32b80765eaf84ca1f662f1840110fb503bb0e395f8&scene=21#wechat_redirect)中利用Graylog自带的Geo-Location Processor对目的IP这个字段进行了富化，并且结合Grafana的Worldmap仪表盘展示地理位置相关的数据，可以观察是否有主机连接到了境外的IP，但如果有全球的业务，还是不能直观的看到这些目的IP是否为恶意，于是这一章节需要对日志中的目的IP字段进行自动化调查，通过Graylog本身开放性结合GreyNoise的API进行自动化调查。

那么GreyNoise是什么？

> GreyNoise collects, analyzes, and labels data on IPs that scan the internet and saturate security tools with noise.
> 
> https://www.greynoise.io/

**1.获取API KEY**

Graylog通过使用GreyNoise的威胁情报，可以快速发现恶意IP地址。在使用GreyNoise的API之前需要先进行注册，登录官网点后击SIGN UP FOR FREE注册账号  

![](../Images/8ad386a019b3631d015877a8faf8c624.png)

注册完成后点击右上角账号名称，在弹出菜单中选择MY API KEY  

![](../Images/0e3ef0272bc847df637462bc6a92440b.png)

点击VIEW API KEY，查看后续使用的使用API KEY信息

![](../Images/dc538195dd26ce83254c5079ee6d0789.png)

**2.Graylog配置**

登录Graylog控制台，点击System-Lookup Tables，点击Data Adapters  

![](../Images/8b37459e14022cbe58fc5adcac925404.png)

在页面中点击Create data adapter  

![](../Images/7ae654f02d5da5a3cd7407c304506df4.png)

在弹出窗口中选择GreyNoise Community IP Lookup

![](../Images/ab3d90f0d2357ad0d6a71352a7b5d92f.png)

接下来对参数进行配置，Title以及Description配置成GreyNoise，API Token填写刚才获取到的API KEY，其他参数保持不变，配置完成点击Create Adapter  

![](../Images/5f33ef6071b49a123664aa9f58ff393a.png)

配置完成如下图所示，点击刚才创建的data adapter测试是否有效  

![](../Images/48015e3382b4f6d99f62aa38c8a6f2c9.png)

输入需要调查的IP地址，如185.3\[.\]94.183，查询结果如下图所示，调查结果为malicious

![](../Images/dfeb10a35cec943f54553192cd3e9c59.png)

大多数的API接口都会限制用户一段时间内访问数量，会导致当使用次数超限制之后改变自动调查失效。Graylog通过创建数据缓存来解决该问题，在调用GreyNoise接口进行调查前会先检查缓存中的数据，如果需要查询的数据已在缓存中，则会直接利用缓存数据，缓存允许根据业务以及资源设置缓存时间，以便最少程度调用GreyNoise。缓存时间越长占用的内存越多。

点击System-Lookup Tables，点击Caches

![](../Images/7655a096cf94ee6453ce012ed32323a0.png)

在页面中点击Create cache

![](../Images/12d1acc3ddb3a79da2a947883123cb0a.png)

在弹出窗口中Cache Type选择Node-local,in-memory cache

![](../Images/9e707141a05e2edf1c52c96480a3271f.png)

接下来对参数进行配置，Title以及Description配置成GreyNoise cache，Expire after access选择60minutes，配置完成点击Create Cache

![](../Images/5113ba1fd9ec2a367ba825c2634af8ae.png)

配置完成如下图所示  

![](../Images/71e56d6635c17eeb11a254cd3b691765.png)

接下来配置Lookup Tables，把刚才创建的data adapter以及cache进行关联，点击System-Lookup Tables，点击Create lookup table

![](../Images/c9d56ff7e65241f8034bb6f83bc2cff0.png)

在弹出窗口中Title、Description以及Name设置成GreyNoise table，Data Adapter选择GreyNoise，Cache选择GreyNoise cache，配置完点击Create Lookup Table

![](../Images/45b48725ddd7803dd670fa47f4f86529.png)

创建完如下图所示  

![](../Images/37076d5f7d8ed9ad5c9df6b785dc236c.png)

接下来需要创建Pipelines，通知Graylog日志中什么字段为目的IP地址字段，需要进行自动化调查，点击System-Pipelines，点击Manage rules

![](../Images/40aa885a734df0f526cc53fdd16c454d.png)

在弹出窗口中点击Create Rule  

![](../Images/b6c52fd35e00d0c8069152cdd69c4eeb.png)

把Description字段设置为GreyNoise Lookup on data\_win\_eventdata\_destinationIp，对应的Rule source规则如下所示，使用时对目的IP字段进行替换，配置完点击Apply，再点击Save&Close

```
rule "GreyNoise Lookup on data_win_eventdata_destinationIp"when    has_field("data_win_eventdata_destinationIp")then    let ldata = lookup(        lookup_table: "GreyNoise table",        key: to_string($message.data_win_eventdata_destinationIp)    );    set_fields(        fields: ldata,        prefix: "GreyNoise_"        );end
```

通过之前查看日日志目的IP地址字段为data\_win\_eventdata\_destinationIp

![](../Images/7b9fee4ff56f621870844a082a166100.png)

配置完如下图所示

![](../Images/c008addcdb9b5e9ab9f3d4ed7a859f0f.png)

点击Manage Pipelines  

![](../Images/3a11dfe189572d398857f2db994e132a.png)

点击Add new pipeline  

![](../Images/bc2187ff485f42d30084837d97b26375.png)

在弹出窗口中Title以及Description都设置成GreyNoise pipeline，完成后点击Save

![](../Images/a39bc9d031337b7850eef6d935311901.png)

在弹出页面中点击Stage 0后的Edit按钮  

![](../Images/2d517b8b1f4bf1ce290c5c92e9b6175d.png)

Stage rule选择刚才创建的rule，点击Save  

![](../Images/ea08b6528fc727cfe9b123764fe8cf2f.png)

在Pipeline connections后点击Edit connections，选择wazuh alert这个Stream，点击Save

![](../Images/77cc668d0d3acc15b9213e6ed5f44340.png)

（上面有点笔误，需要先配置Stream，再配置Stage，Pipeline中的两步写反了）完成后如下图所示

![](../Images/9092b225ec0cd73b4a944306ebf80e2c.png)

最后点击System-Configurations，把Message Processors Configuration栏中，Pipeline Processor位置调整到Message Filter Chain下方

![](../Images/d7c8c2c88b817b464b6afc1680e3e68f.png)

完成之后查看新收到的日志中已经带有GreyNoise\_字段，如下图所示

![](../Images/dd943aacf79ef151a061ccf51259d673.png)

这样子就完成了对于日志中目的IP地址的自动化调查，下一篇将介绍如何把防火墙日志接入，由于防火墙的流量比终端上捕捉到的流量大很多，目的IP地址的调查优势会进一步放大。欢迎订阅收看开源SOC实现（八）-pfSense防火墙日志接入。
