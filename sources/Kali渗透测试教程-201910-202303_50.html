我们开始枚举靶机上的不同文件。这时我们偶然发现了tickd.conf时，这意味着涉及端口knocked。我们看到我们在这里配置了带有序列的openSSH。我们记下此序列，然后按此序列中的SSH端口启动并运行它

 [openSSH] sequence = 7469,8475,9842

我们使用knock命令进行端口敲门。这可以通过许多不同的方法来完成。在按顺序knock端口之后，我们再次运行NMAP扫描以确保knocked工作正常，并且SSH端口应立即打开。我们打开了SSH端口。这是我们的方法。

sudo apt-get install knockd

knock 192.168.1.37 7469 8475 9842nmap -p 22 192.168.1.37

现在我们有了SSH服务，我们需要登录凭据才能进入。我们尝试了与在WebApp上使用的相同的凭据，但这是不行的。我们回到了前面列举的用户数据库。在此过程中，我们使用了该表中的用户名和密码列。

创建了login字典之后，我们使用msf中爆破工具对目标计算机上的SSH服务进行了暴力破解。经过一番尝试后，我们看到用户管理员是具有SSH访问权限的用户。现在，我们拥有适当的凭据，可以通过SSH登录。
