# 恶意流量分析训练三

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzUyMTA0MjQ4NA==&mid=2247488770&idx=1&sn=0668f43435736041a38f5bccdbc652db&chksm=f9e07a59ce97f34f413598058b0c4e62d721f261d25e17a519ea4f84a46298433d57b36281ed&scene=126&sessionid=1681663416#rd](http://mp.weixin.qq.com/s?__biz=MzUyMTA0MjQ4NA==&mid=2247488770&idx=1&sn=0668f43435736041a38f5bccdbc652db&chksm=f9e07a59ce97f34f413598058b0c4e62d721f261d25e17a519ea4f84a46298433d57b36281ed&scene=126&sessionid=1681663416#rd)

了解使用wireshark进行恶意流量分析，培养流量分析的思维和能力，本次实验涉及知识包括善用搜索引擎、技术分析文章整合、snort日志分析、以及关于Locky ransomware和Angler EK部分攻击流量特征。  
  

试根据给出的数据包等文件，分析解答如下问题Q1:用户的姓名？Q2:用户windows机器的主机名？Q3:用户windows主机的ip地址？

Q4:用户电脑的mac地址？  

Q5:用户被感染了哪些恶意文件？  

  

打开wireshark上方的菜单，统计->ipv4 statics->all address,如图所示

![](../Images/a5993dd4697fb6fb4e7fbc897a57936b.png)

  

可以看到通信流量基本全部是由10.0.21.136发起的，所以用户主机的ip地址是10.0.21.136那么主机名该如何找到呢？我们先来看看数据包都有哪些协议。

![](../Images/ea4ab41094a2344b9f9008b2a01ade0e.png)

我们知道NetBIOS是Network Basic Input/Output System的简称，一般指用于局域网通信的一套API，它在基于 NetBIOS 名称访问的网络上提供主机名和地址映射方法。所以通过NBNS协议我们可以找到主机名。

所以选中一条nbns的数据。

![](../Images/6fe51e4283a28cbdd2d50382f56900ca.png)

红框定位的就是mac地址及主机名

那么使用者的姓名呢？

在电脑自带的通信过程中，一般人是不会设置完整的姓名的，题目既然这么问说明要从其他地方入手，比如用户在网站注册，或者他的邮件的名字，都有可能是姓名，所以我们尝试过滤出http请求数据。

过滤后的数据也不多，往下翻就可以看到。

![](../Images/b9cea05fbcf73ac3c1e62c561c806526.png)

出现了signup的关键字我们跟踪其tcp流

![](../Images/e2137df40cf5d34dc622a5d1b46c7006.png)

可以看到post的最后一行发现了姓名。

  

  

接下来我们分析下用户感染了哪些恶意软件，以及如何被感染的。可以看到在用户注册之后，紧接着是google analytics,这是Google开发的网站流量跟踪工具。

![](../Images/db88da5aacc088422ac60480270e255e.png)

然后后面就出现了一些奇怪的http get 和 post请求针对第一条get

  

![](../Images/6f888b9815a07643c95c865f9613ca3d.png)

将full request uri右键-》复制-》值，然后再搜索引擎中查询。

![](../Images/d8e48b7c85d204bc870d80bfe898de31.png)

可以看到这是恶意软件而这条链接分析博客的分析是恶意脚本下载的源链接，其模式与博客给出的其他链接相同。  

![](../Images/828a2a4cc3b5bc20321cb3ac51812464.png)

最后指出这是Locky Malware后面的post请求是用户被感染之后访问其他网页产生的流量。

  

那么只有感染这一个恶意软件吗？我们再继续分析，往下翻

![](../Images/42ef154422144a937604932f1d549cf7.png)

看到了.top域名，这就要非常敏感了，很多恶意软件都会去注册使用.top选中第一条get，跟踪tcp流

![](../Images/64f04479e3d28973c1a73a38f2369c77.png)

可以看到referer信息，referer表示是从该页面链接过来的，所以此处的话表明用户访问正常的网页http://www.emidioleite.com........然后被定向访问到了.top。接下来结合snort日志分析，根据目的ip去日志中检索。  

![](../Images/cc1db36f5bba32a8a2bd7d22b9a8d874.png)

可以看到snort检测到是属于Angler exploit-kit发起的攻击，后面还提示是landing page，那么一定会传递载荷我们进一步分析其他的tcp流

![](../Images/250c81c74ebffa9f82cc7b602d58e1b8.png)

可以看到传递了大约443k的载荷文件我们通过搜索引擎检索到第一篇捕捉到该攻击的推文

![](../Images/8cb25abcea278bcb4f2f08197418701d.png)

所以就可以推测这443k的文件就是伪装成swf格式的flash文件。 继续往下看看剩余有没有可疑的流量。在最后的一系列post userinfo.php这种用户正常访问的额流量之前我们有看到了奇怪的流量。  

![](../Images/7ee28890480dff90d3f76bca86de19b3.png)

跟踪tcp流，可以看到这个referer，说明也是从其他网页链接过来的。

![](../Images/2282e8072005db04ec686a8b2093dfc4.png)

去snort日志了按照目的ip检索。

![](../Images/066114fed24b562fb2b8418712f757c7.png)

可以看到也是Angler Exploit-Kit不过这次的攻击手法是什么呢？我们取消过滤条件，看看。  

![](../Images/fa03e985731878a71e5c85ad833935e7.png)

接下来我们要有侧重点，因为实际攻击中ip是可能动态变化的，而一般端口是不会变得，所以我们的办法就是在source ip为10.0.21.136时，看看目的端口有哪些。

![](../Images/e168fe39d6cd3c87122fc2161f2b6200.png)

可以看到主要是80和443接下来结合关键字Agnler exploit-kit一起去搜索引擎搜索。  

![](../Images/8f23b4fe91e0a86f1c992c4b5b44f20d.png)

点击查看，关键信息如下。

![](../Images/bc5bf73905f53fecb6d24698538fab3a.png)

可以看到与443,80有关的通信是由于Crypt ransomware。从文章的分析思路中可以看到Crypt ransomware是由Angler EK派生的。  

![](../Images/7647809f3452132c549e555d8b806f25.png)

所以我们就可以得出结论了：用户受到了三次感染，第一次是来自malware spam的Locky ransomware,第二次是Angler EK的文件（由分析文章推知是伪装的swf文件），第三次是Angler EK的CryptXXX ransomware。.net
