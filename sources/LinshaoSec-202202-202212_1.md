# IIS短文件名漏洞

  

⬤ 基本信息：

```
Windows系统为了兼容16位MS-DOS程序，为文件名较长的文件和文件夹生成了对应的Windows 8.3短文件名。比如文件名direct~1.asp中间有一个波浪号，这种就是短文件名了。
```

⬤ 作用：

```
猜解敏感文件,例如备份的rar、zip、.bak、.sql文件等
```

⬤ 局限性：

```
只能猜解前六位,以及扩展名的前三位。
名称较短的文件是没有相应的短文件名的。
不支持中文文件名
如果文件名前6位带空格，8.3格式的短文件名会补进，和真实文件名不匹配
```

通用荷载（存在短文件名文件的情况下）

笔者在win10、2012、win7上搭建各个版本的测试结果如下：

| iis版本 || 方法 || 存在的文件\*~1.\* || 不存在的文件\*~1.\*xxx |
| --- | --- | --- | --- |
| iis10 || OPTIONS || 404 || 200 |
| --- | --- | --- | --- |
| iis8.5 || OPTIONS || 404 || 200 |
| iis7.5 || OPTIONS || 404 || 200 |
| iis10 || TRACE || 404 || 501 |
| iis8.5 || TRACE || 404 || 501 |
| iis7.5 || TRACE || 404 || 501 |

  

可以看出：

```
存在文件：都是404
不存在：OPTIONS 返回 200、TRACE 返回501
```

  

也就是说：

```
对于任意一个iis网站
条件1=（对它的\\\*\_1.\*路径进行OPTIONS请求==响应码404）
条件2=（对它的\\\*\_1.\*xxx路径进行OPTIONS请求==响应码200）
则表示它存在短文件名漏洞
否则不存在或者其根目录下不存在短文件名文件(此时可尝试其子目录)
实战中，可以尝试使用单词模糊匹配获取到该单词开头的所有单词进行爆破
```
