5年后，Oracle-Sun的合并效果究竟如何?

五年又两周之前，我和一大批记者、分析师和Oracle客户一起参加了Oracle在其巨型红木海岸大厦的大会议厅举办的新闻发布会。那天对Oracle来说是个值得纪念的日子。在经历了痛苦等待美国司法部和欧盟委员会长达9个月的审批终于通过之后，Oracle收购Sun一案尘埃落定。

埃里森长期以来就在寻求硬件/软件的集成堆栈，这一次他终于如愿以偿了。如今，他的Exdata和Exalogic服务器都由Sun生产，而不必再去求惠普和富士通了。更好的是，他终于可以向其客户提供集成了Oracle预装软件的全集成交钥匙系统了。

Oracle曾经做过很多承诺，其中多数都是关于MySQL的。而欧盟委员会之所以迟迟没有批准此次并购，也主要是因为Richard Stallman和Ralph Nader对于MySQL技术支持的担忧所致，因为这一部分对于Oracle的业务来说是微不足道的。同时，Sun由于销售下滑，每月亏损1亿美元而痛苦不堪。

埃里森和Oracle对于Sun的硬件、Java以及MySQL做了大量的承诺。那么这些产品的现状究竟如何了呢?让我们来看一看。

1) 对MySQL的支持

2009年12月，Oracle对MySQL做出了10项承诺，范围涉及从开发到许可证到开放。我不是数据库行家，但有一位数据库开发专家认为Oracle兑现了很多承诺，做了不少好事情，例如增加了员工和QA部门。说到底，Oracle也只是拥有MySQL的所有权而已，还不足以砍掉它，因为人们可以通过联合抵制来避免此事发生。

还有一件事本人也不是行家，但我认为是一个有效的案例，那就是Oracle向非结构化数据、大数据的大规模迁移，以及NoSQL的兴起。反Oracle的MySQL社区就在并购完成之前创建了MariaDB，但现在很少能听到MariaDB的消息了。如今听得最多的是NoSQL/Hadoop。

2) 关注高端硬件

从一开始，埃里森就说他对商品化服务器市场没兴趣，会淘汰掉Sun的众多产品线，只集中于非常强大的高端产品。可以肯定地说，他实现了这一承诺。SuperCluster和著名的Exdata、Exalogic服务器等都是非常有特色的高端硬件。

埃里森肯定是看到了商品化服务器的没落。根据Gartner的估算，从2010年到2014年的服务器交货量一直持平，这意味着即便在最好的情况下，服务器会有更新换代，但并没有新的部署出现。虚拟化意味着买1台服务器就能替换10台服务器，而云则意味着很多企业根本不需要购买服务器。购买商品化服务器的只有云服务商，如亚马逊、微软和谷歌等，但这些厂商也更倾向于自己开发而不是购买服务器。

所以，尽管Oracle的硬件销量只以数百或数千台计，但却并未失去其庞大的营收基础，因为它的系统是如此高端。在Sun的最后一个财年，即2009财年中，其报告的硬件销售和支持业务总额为67亿美元。而在Oracle截至6月底的2014财年中，其报告的硬件销售和支持业务总额为53亿美元。但其硬件的单位销量的确下降的很快。在Gartnber的服务器单位交货量排名中，网络公司思科已经取代Oracle进了前五。

Oracle一直在致力于让其设备和工程系统成为交钥匙产品，其中已经预装和集成好了所有用户需要或想要的OS、数据库、中间件、应用程序和Java等等。用户可以即插即用。所以尽管在主机已不时兴的今天，依然是不少企业真正需要的产品。

3) Sparc或x86

由于x86拥有了越来越多原先只能在主机上有的特色和功能，它也在缓慢地扩充着服务器堆栈，从部门级逐渐向关键任务级扩展。而x86的所得正是RISC的所失，后者如Sun的Sparc、惠普的PA-RISC、IBM的POWER，以及英特尔的安腾等，都在一退再退。

惠普已经放弃了为安腾开发的PA_RISC。IBM在将其x86服务器业务卖给联想之后依然执着于其POWER处理器。那么Sparc如何呢?Sun一直将其束之高阁，Oracle也没有计划对其进行支持或继续发展。它的大多数高端系统和设备都是x86的。

Sun所发布的Sparc开发路线图还是在2010年和2011年，但之后的产品交付便越来越滞后了。2011年和2012年虽然交付了T系列和M系列处理器，但自那以后其路线图便付之阙如，发布日期也一拖再拖。部分问题可能是因为其销售已无力再作进一步的开发了。

4) Solaris

至于Solaris则更加令人沮丧。Oracle已经放弃了OpenSolaris，这个开源实验版本。Solaris 11于2011年发布，自后只发布了两个次版本。

与之相反的是，Oracle似乎更加注重所谓Unbreakable Linux，也就是它自己的Red Hat企业Linux版本。它的所有高端系统都预装了这套OS，Oracle还将Solaris中很有名的一个功能DTrace移植到了Unbreakable Linux上。

5) Java

就在合并之后不久，Java的发明人James Gosling便离开了Oracle，并带走了不少原先Sun公司的同事。此举并不令人意外。因为企业文化的冲突必定让原先很悠闲的Gosling和Sun的其他员工感觉很不适应。

这之后的Java行程就相当糟糕了。当然，这也不能全怪到Oracle头上。它毕竟花了多年的时间理清了混乱的Java代码，和无穷无尽的关键性错误。Java的巫术漏洞导致由美国国土安全局资助的卡内基梅隆大学的一个安全小组建议说，除非你绝对需要，否则就不要安装Java。

自合并以来，Java标准版只发布了两个主版本：2011年的Java SE 7和2014年的Java SE 8。而在Java SE 7之前，该平台差不多每年或每两年就要发布一个新的主版本。

Java的开发需要从埃里森的队伍中专门抽出人来交付新产品。所以自合并以来只交付了Java企业版(Java EE)第7版。Java EE 8预计得等到2016年的某个时候才能交付。

换句话说，Oracle在倾听JCP合作伙伴，尤其是IBM的意见方面已经做得相当不错了。Oracle制定了两项颇有野心的计划，其一的拼图项目旨在让Java可缩小到更小型的设备上;其二的Lamda项目则试图为Java 8增加多核支持。

有看法认为，Java对Oracle来说是个麻烦。实际上，Oracle在这上面花费了大量的精力，而且Java已成为其Fusion产品线和交钥匙服务器的一个核心组件。

结论

Sun是一家管理不善的企业。这也是为什么该公司经常把出售自己当成了第一要务的缘故。Jonathan Schwartz并不适合CEO这个角色，也做了很多非常错误的决策，诸如花费10亿美元购买当时仅值500万美元的MySQL公司，将全部精力放在了将Sun的软件开源上，而不是放在挽救销售下滑的趋势上。

Oracle则带来了纪律和对迫切需求的关注。在硅谷，工作场所是很随意任性的，而Oracle则跟英特尔、苹果和Nvidia更像。在这里工作是艰苦的，人人都要按点上下班。尽管Oracle的老板应年逾古稀，身价超过70亿美元，但仍然会每天都出现在总部大楼。他虽然会驾驶帆船横跨世界，享受轻松的生活，但他依然会继续工作。而Sun的文化与此不同，所以有很多人离去一点儿也不奇怪。

Oracle正在成为最老派的硅谷企业，它们的时代已经过去了。Sun销售服务器。那个时候很多人都买服务器，但很少有人会在购买之前进行比较。如果不是Oracle买下了Sun，Sun很可能分分钟就死去，而它的很多专利则会被IBM、惠普和EMC等硬件厂商纳入囊中。

Sun继续在以一种不同的方式存在着，但是否像埃里森所承诺的那样正在走出低谷，尚待观察。
