# 关于《Linux 内核里的数据结构——双向链表》一文的原创冲突的说明

大家好，想必关注“Linux 中国”的朋友们都知道我们背后有一个强大的志愿者翻译小组 LCTT （ https://lctt.github.io/ ），也从这里以及我们网站（https://linux.cn/）上看到了很多 LCTT 成员辛勤选题、翻译和校对的文章——当然，也有不少盗版网站“随随便便”的转载得到处都是（之所以说是“随随便便”，是因为经常被转载得格式错乱、内容残缺，原本的作者、来源链接、译者等信息都“自然而然”的没了。）  

  

最近，我们翻译发布了一篇文章《Linux 内核里的数据结构——双向链表》（今天也推送了），这是 0xAX 在 GitHub 上写的一系列关于内核的技术深入文章之一。我们 LCTT 对其中的部分文章进行了翻译，并将译文推送到了原文的仓库。

  

其实，对于这种比较高深的稿件，笔者是表示“不懂的”，但是这篇文章却得到了不少爱好者的好评，所以，按照惯例，我们在“Linux 中国”的网站发表之后，由于排期的原因，这篇稿件安排在第二天发表到我们的微信公众号上。

  

但是，令人愕然的是，发送时居然通知我们，这篇稿件被别人申请了原创——好吧，这也有可能，因为这种 CC 授权的文章别人也能翻译发表，也许是抢在我们之前了。可是点开链接一看？居然用的配图是主页君自己选择的，格式居然是我们特有的排版格式。

  

然而，该“原创”并没有写我们的相关信息，包括译者、译文链接，连英文原文地址也没有。

  

第一时间，我们考虑的不是投诉，而是通过各种渠道联系该公众号。经过几番辗转沟通，该公众号先是在评论中自述了译者、译文等信息，然后做了致歉。

  

这期间，该文章一直保持“原创”标示，后来有人投诉，才被撤销了“原创”标示。

  

今天，该公众号按照我们沟通的结果，发布了一篇道歉申明：

  

![](../Images/b5080f395df0b35421c6ec3a5b482899.png)  

  

好吧，其实我们在意的不是不能转载，而是转载不保留来源链接、译者信息等内容；而且还申明原创。

  

不过，同作为技术号，这样解决了，我们也算能接受。

  

就着这个事情，我们申明一下我们对于版权的态度：

  

1.  我们所有原创的文章和按照许可翻译的文章，都欢迎转载。
    
2.  一般我们都不会专门打上“原创”标示，便于大家转载时可沿用自己的版式。但是请在转载时保留文章的各种版权信息，包括作者、译者、原文链接、译文链接等等。
    
3.  有些文章我们会加上“原创”标示，大家如果可以接受我们的版式，就可以径直转载；如果希望使用自己的版式，请留言给我们即可，一般都会授权的。
    
4.  千万不要将我们的原创文章打上你的“原创”标示。
    
5.  对于我们转载的来自别人的文章，我们都会在文章首末加上作者、译者、原文链接、译文链接等信息。
