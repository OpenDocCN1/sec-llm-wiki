一份关于任何可以写入到你的文档中 <head> 部分的清单。

最小推荐

下面是基本的、最低限度的网站基本标签：

  1. <meta charset="utf-8">
  2. <meta http-equiv="x-ua-compatible" content="ie=edge">
  3. <meta name="viewport" content="width=device-width, initial-scale=1, shrink-to-fit=no">
  4. <!-- 以上 3 个 meta 标签 *必须* 放在 head 的最前面；其他任何的 head 内容必须在这些标签的 *后面* -->
  5. <title>页面标题</title>

网页元素

  1. <!-- 文档标题 -->
  2. <title>页面标题</title>
  4. <!-- 基本 URL 作用于文档中所包含的所有相对 URL -->
  5. <base href="https://example.com/page.html">
  7. <!-- 外部的 CSS -->
  8. <link rel="stylesheet" href="styles.css">
  10. <!-- 文档内的 CSS -->
  11. <style>
  12.   /* ... */
  13. </style>
  15. <!-- JavaScript -->
  16. <script src="script.js"></script>
  17. <noscript><!--无 JS 时的替代--></noscript>

Meta 标签

  1. <!-- 设置文档的字符编码 -->
  2. <meta charset="utf-8">
  3. <meta http-equiv="x-ua-compatible" content="ie=edge">
  4. <meta name="viewport" content="width=device-width, initial-scale=1, shrink-to-fit=no">
  5. <!-- 以上 3 个 meta 标签 *必须* 放在 head 的最前面；其他任何的 head 内容必须在这些标签的 *后面* -->
  7. <!-- 允许控制资源的过度加载 -->
  8. <meta http-equiv="Content-Security-Policy" content="default-src 'self'">
  9. <!-- 尽早地放置在文档中 -->
  10. <!-- 仅应用于该标签下的内容 -->
  12. <!-- Web 应用的名称（仅当网站被用作为一个应用时才使用）-->
  13. <meta name="application-name" content="应用名称">
  15. <!-- 针对页面的简短描述（限制 150 字符）-->
  16. <!-- 在*某些*情况下，该描述是被用作搜索结果展示片段的一部分 -->
  17. <meta name="description" content="一个页面描述">
  19. <!-- 控制搜索引擎的抓取和索引行为 -->
  20. <meta name="robots" content="index,follow"><!-- 所有搜索引擎 -->
  21. <meta name="googlebot" content="index,follow"><!-- 仅对 Google 有效 -->
  23. <!-- 告诉 Google 不显示网站链接的搜索框 -->
  24. <meta name="google" content="nositelinkssearchbox">
  26. <!-- 告诉 Google 不提供此页面的翻译 -->
  27. <meta name="google" content="notranslate">
  29. <!-- 验证 Google 搜索控制台的所有权 -->
  30. <meta name="google-site-verification" content="verification_token">
  32. <!-- 验证 Yandex 网站管理员的所有权 -->
  33. <meta name="yandex-verification" content="verification_token">
  35. <!-- 验证 Bing 网站管理员中心的所有权 -->
  36. <meta name="msvalidate.01" content="verification_token">
  38. <!-- 验证 Alexa 控制台的所有权 -->
  39. <meta name="alexaVerifyID" content="verification_token">
  41. <!-- 验证 Pinterest 控制台的所有权 -->
  42. <meta name="p:domain_verify" content="code from pinterest">
  44. <!-- 验证 Norton 安全站点的所有权 -->
  45. <meta name="norton-safeweb-site-verification" content="norton code">
  47. <!-- 用来命名软件或用于构建网页（如 - WordPress、Dreamweaver）-->
  48. <meta name="generator" content="program">
  50. <!-- 关于你的网站主题的简短描述 -->
  51. <meta name="subject" content="你的网站主题">
  53. <!-- 基于网站内容给出一般的年龄分级 -->
  54. <meta name="rating" content="General">
  56. <!-- 允许控制 referrer 信息如何传递 -->
  57. <meta name="referrer" content="no-referrer">
  59. <!-- 禁用自动检测和格式化可能的电话号码 -->
  60. <meta name="format-detection" content="telephone=no">
  62. <!-- 通过设置为 “off” 完全退出 DNS 预取 -->
  63. <meta http-equiv="x-dns-prefetch-control" content="off">
  65. <!-- 在客户端存储 cookie，web 浏览器的客户端识别 -->
  66. <meta http-equiv="set-cookie" content="name=value; expires=date; path=url">
  68. <!-- 指定要显示在一个特定框架中的页面 -->
  69. <meta http-equiv="Window-Target" content="_value">
  71. <!-- 地理标签 -->
  72. <meta name="ICBM" content="latitude, longitude">
  73. <meta name="geo.position" content="latitude;longitude">
  74. <meta name="geo.region" content="country[-state]"><!-- 国家代码 (ISO 3166-1): 强制性, 州代码 (ISO 3166-2): 可选; 如 content="US" / content="US-NY" -->
  75. <meta name="geo.placename" content="city/town"><!-- 如 content="New York City" -->

  1. <!-- 表明一个 CSS 样式表 -->

  4. <!-- 有助于防止出现内容重复的问题 -->

  11. <link rel="amphtml" href="https://example.com/path/to/amp-version.html">
  13. <!-- 链接到一个指定 Web 应用程序“安装”证书的 JSON 文件 -->
  14. <link rel="manifest" href="manifest.json">
  16. <!-- 链接到文档的作者 -->
  17. <link rel="author" href="humans.txt">
  19. <!-- 指向一个适用于链接内容的版权申明 -->
  20. <link rel="license" href="copyright.html">
  22. <!-- 给出可能的你的另一种语言的文档位置参考 -->
  23. <link rel="alternate" href="https://es.example.com/" hreflang="es">
  25. <!-- 提供了关于作者或其他人的信息 -->
  26. <link rel="me" href="https://google.com/profiles/thenextweb" type="text/html">
  27. <link rel="me" href="mailto:name@example.com">
  28. <link rel="me" href="sms:+15035550125">
  30. <!-- 链接到一个描述历史记录、文档或其他具有历史意义的材料的集合的文档。 -->
  31. <link rel="archives" href="https://example.com/archives/">
  33. <!-- 链接到层次结构中的顶级资源 -->
  34. <link rel="index" href="https://example.com/">
  36. <!-- 给出一个自我参考 - 当文档有多个可能的参考时非常有用 -->
  37. <link rel="self" type="application/atom+xml" href="https://example.com/atomFeed.php?page=3">
  39. <!-- 分别是在一系列文件中的第一个、下一个、上一个和最后一个 -->
  40. <link rel="first" href="https://example.com/atomFeed.php">
  41. <link rel="next" href="https://example.com/atomFeed.php?page=4">
  42. <link rel="prev" href="https://example.com/atomFeed.php?page=2">
  43. <link rel="last" href="https://example.com/atomFeed.php?page=147">
  45. <!-- 当使用第三方服务来维护 blog 时使用 -->
  46. <link rel="EditURI" href="https://example.com/xmlrpc.php?rsd" type="application/rsd+xml" title="RSD">
  48. <!-- 当另一个 WordPress 博客链接到你的 WordPress 博客或文章时形成一个自动化的评论 -->
  49. <link rel="pingback" href="https://example.com/xmlrpc.php">
  51. <!-- 当你在自己的页面上链接到一个 url 时通知它 -->
  52. <link rel="webmention" href="https://example.com/webmention">
  54. <!-- 加载一个外部的 HTML 文件到当前 HTML 文件中 -->
  55. <link rel="import" href="/path/to/component.html">
  57. <!-- 打开搜索 -->
  58. <link rel="search" href="/open-search.xml" type="application/opensearchdescription+xml" title="Search Title">
  60. <!-- Feeds -->
  61. <link rel="alternate" href="https://feeds.feedburner.com/example" type="application/rss+xml" title="RSS">
  62. <link rel="alternate" href="https://example.com/feed.atom" type="application/atom+xml" title="Atom 0.3">
  64. <!-- 预取，预载，预浏览 -->
  65. <link rel="dns-prefetch" href="//example.com/">
  66. <link rel="preconnect" href="https://www.example.com/">
  67. <link rel="prefetch" href="https://www.example.com/">
  68. <link rel="prerender" href="https://example.com/">
  69. <link rel="preload" href="image.png" as="image">
  70. <!-- 更多信息：https://css-tricks.com/prefetching-preloading-prebrowsing/ -->

指南

HEAD 仓库由两个分支组成：

1、master

对该分支包含的 README.md 文件的修改会自动反映在 <Head> Cheat Sheet[33] 网站上。 所有对照表内容的更改都应该针对此文件。

请按照下列步骤 pull 请求：


◈ 只修改一个标签，或一次一组相关的标签
◈ 对属性使用双引号
◈ 请不要在自我闭合的元素中使用斜线 —— 即便 HTML5 规范中说，他们是可选的
◈ 考虑在文档中加入链接以支持你所提到的变化


2. gh-pages

该分支负责 <Head> Cheat Sheet[34] 网站。我们使用 Jekyll[35] 通过 GitHub Pages[36]服务来部署 README.md Markdown 文件。所有网站相关的修改必须集中在这里。

你可能需要通过 Jekyll 文档[37] 来了解 Jekyll 是如何在该分支上工作的。
