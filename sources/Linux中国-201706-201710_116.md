# Minikube：使用 Kubernetes 进行本地开发

如果你的运维团队在使用 Docker 和 Kubernetes，那么建议开发上采用相同或相似的技术。这将减少不兼容性和可移植性问题的数量，并使每个人都会认识到应用程序容器是开发和运维团队的共同责任。

这篇博客文章介绍了 Kubernetes 在开发模式中的用法，它的灵感来自于一个视频教程，你可以在“无痛 Docker 教程\[1\]”中找到它。

![](../Images/bdef37e1a9317e004cd19a1beb18ad99.png)

Minikube 是一个允许开发人员在本地使用和运行 Kubernetes 集群的工具，从而使开发人员的生活变得轻松。

在这篇博客中，对于我测试的例子，我使用的是 Linux Mint 18，但其它 Linux 发行版在安装部分没有区别。

```
1.  `cat /etc/lsb-release `
    
```

```
1.  `DISTRIB_ID=LinuxMint`
    
2.  `DISTRIB_RELEASE=18.1`
    
3.  `DISTRIB_CODENAME=serena`
    
4.  `DISTRIB_DESCRIPTION=”Linux Mint 18.1 Serena”`
    
```

![](../Images/4fec2975e487bbe118831c4df1f27ce8.png)

先决条件

为了与 Minkube 一起工作，我们应该安装 Kubectl 和 Minikube 和一些虚拟化驱动程序。

  

◈

对于 OS X，安装 xhyve 驱动\[2\]、VirtualBox\[3\] 或者 VMware Fusion\[4\]，然后再安装 Kubectl 和 Minkube。

```
1.  `curl -LO https://storage.googleapis.com/kubernetes-release/release/$(curl -s https://storage.googleapis.com/kubernetes-release/release/stable.txt)/bin/darwin/amd64/kubectl`
    
2.  
    
3.  `chmod +x ./kubectl`
    
4.  
    
5.  `sudo mv ./kubectl /usr/local/bin/kubectl`
    
6.  
    
7.  `curl -Lo minikube https://storage.googleapis.com/minikube/releases/v0.21.0/minikube-darwin-amd64 && chmod +x minikube && sudo mv minikube /usr/local/bin/`
    
```

◈

对于 Windows，安装 VirtualBox\[5\] 或者 Hyper-V\[6\]，然后再安装 Kubectl 和 Minkube。

```
1.  `curl -LO https://storage.googleapis.com/kubernetes-release/release/v1.7.0/bin/windows/amd64/kubectl.exe`
    
```

将二进制文件添加到你的 PATH 中（这篇文章\[7\]解释了如何修改 PATH）

下载 `minikube-windows-amd64.exe`，将其重命名为 `minikube.exe`，并将其添加到你的 PATH 中。在这\[8\]可以找到最新版本。

◈

对于 Linux，安装 VirtualBox\[9\] 或者 KVM\[10\]，然后再安装 Kubectl 和 Minkube。

```
1.  `curl -LO https://storage.googleapis.com/kubernetes-release/release/$(curl -s https://storage.googleapis.com/kubernetes-release/release/stable.txt)/bin/linux/amd64/kubectl`
    
2.  
    
3.  `chmod +x ./kubectl`
    
4.  
    
5.  `sudo mv ./kubectl /usr/local/bin/kubectl`
    
6.  
    
7.  `curl -Lo minikube https://storage.googleapis.com/minikube/releases/v0.21.0/minikube-linux-amd64 && chmod +x minikube && sudo mv minikube /usr/local/bin/`
    
```

  

使用 Minikube

我们先从这个 Dockerfile 创建一个镜像：

```
1.  `FROM busybox`
    
2.  `ADD index.html /www/index.html`
    
3.  `EXPOSE 8000`
    
4.  `CMD httpd -p 8000 -h /www; tail -f /dev/null`
    
```

添加你希望在 index.html 中看到的内容。

构建镜像：

```
1.  `docker build -t eon01/hello-world-web-server .`
    
```

我们来运行容器来测试它：

```
1.  `docker run -d --name webserver -p 8000:8000 eon01/hello-world-web-server`
    
```

这是 `docker ps` 的输出：

```
1.  `docker ps`
    
2.  
    
3.  `CONTAINER ID        IMAGE                          COMMAND                  CREATED             STATUS              PORTS                    NAMES`
    
4.  `2ad8d688d812        eon01/hello-world-web-server   "/bin/sh -c 'httpd..."   3 seconds ago       Up 2 seconds        0.0.0.0:8000->8000/tcp   webserver`
    
```

让我们提交镜像并将其上传到公共 Docker Hub 中。你也可以使用自己的私有仓库：

```
1.  `docker commit webserver`
    
2.  `docker push eon01/hello-world-web-server`
    
```

删除容器，因为我们将与 Minikube 一起使用它。

```
1.  `docker rm -f webserver`
    
```

启动 Minikube：

```
1.  `minkube start`
    
```

检查状态：

```
1.  `minikube status`
    
```

我们运行一个单一节点：

```
1.  `kubectl get node`
    
```

运行 webserver：

```
1.  `kubectl run webserver --image=eon01/hello-world-web-server --port=8000`
    
```

webserver 应该会暴露它的端口：

```
1.  `kubectl expose deployment webserver --type=NodePort`
    
```

为了得到服务 url 输入：

```
1.  `minikube service webserver --url`
    
```

使用下面的命令得到 Web 页面的内容：

```
1.  `curl $(minikube service webserver --url)`
    
```

显示运行中集群的摘要：

```
1.  `kubectl cluster-info`
    
```

更多细节：

```
1.  `kubectl cluster-info dump`
    
```

我们还可以使用以下方式列出 pod：

```
1.  `kubectl get pods`
    
```

使用下面的方式访问面板：

```
1.  `minikube dashboard`
    
```

如果你想访问 Web 程序的前端，输入：

```
1.  `kubectl proxy`
    
```

如果我们要在容器内部执行一个命令，请使用以下命令获取 pod id：

```
1.  `kubetctl get pods`
    
```

然后像这样使用：

```
1.  `kubectl exec webserver-2022867364-0v1p9 -it -- /bin/sh`
    
```

最后完成了，请删除所有部署：

```
1.  `kubectl delete deployments --all`
    
```

删除所有 pod：

```
1.  `kubectl delete pods --all`
    
```

并且停止 Minikube。

```
1.  `minikube stop`
    
```
