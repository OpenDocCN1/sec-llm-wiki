# 为什么我在 Linux 上使用 exa 而不是 ls？ | Linux 中国

我们生活在一个繁忙的世界里，当我们需要查找文件和数据时，使用 ls 命令可以节省时间和精力。但如果不经过大量调整，默认的 ls 输出并不十分舒心。当有一个 exa 替代方案时，为什么要花时间眯着眼睛看黑白文字呢？

exa 是一个常规 ls 命令的现代替代品，它让生活变得更轻松。这个工具是用 Rust 编写的，该语言以并行性和安全性而闻名。

![](../Images/0fa02ac221b6f378c54fd74013b7945c.png)

安装 exa

要安装 `exa`，请运行：

```
1.  `$ dnf install exa`
```

![](../Images/0fa02ac221b6f378c54fd74013b7945c.png)

探索 exa 的功能

`exa` 改进了 ls 文件列表，它提供了更多的功能和更好的默认值。它使用颜色来区分文件类型和元数据。它能识别符号链接、扩展属性和 Git。而且它体积小、速度快，只有一个二进制文件。

![](../Images/0fa02ac221b6f378c54fd74013b7945c.png)

跟踪文件

你可以使用 `exa` 来跟踪某个 Git 仓库中新增的文件。

![](../Images/ab27a1362a838e046050130b0866a100.png "Tracking Git files with exa")

*Tracking Git files with exa*

![](../Images/0fa02ac221b6f378c54fd74013b7945c.png)

树形结构

这是 `exa` 的基本树形结构。`--level` 的值决定了列表的深度，这里设置为 2。如果你想列出更多的子目录和文件，请增加 `--level` 的值。

![](../Images/4b7c5e4562c4d19e75fba6880bfc55de.png "exa's default tree structure")

*exa's default tree structure*

这个树包含了每个文件的很多元数据。

![](../Images/ee328bcc6dc2e0d04797cdc45c556cf9.png "Metadata in exa's tree structure")

*Metadata in exa's tree structure*

![](../Images/0fa02ac221b6f378c54fd74013b7945c.png)

配色方案

默认情况下，`exa` 根据 内置的配色方案 来标识不同的文件类型。它不仅对文件和目录进行颜色编码，还对 `Cargo.toml`、`CMakeLists.txt`、`Gruntfile.coffee`、`Gruntfile.js`、`Makefile` 等多种文件类型进行颜色编码。

![](../Images/0fa02ac221b6f378c54fd74013b7945c.png)

扩展文件属性

当你使用 `exa` 探索 xattrs（扩展的文件属性）时，`--extended` 会显示所有的 xattrs。

![](../Images/1bcc1fbe1a55c4d19c354447a3e852ac.png "xattrs in exa")

*xattrs in exa*

![](../Images/0fa02ac221b6f378c54fd74013b7945c.png)

符号链接

`exa` 能识别符号链接，也能指出实际的文件。

![](../Images/51e324fdc7b39ed971c0734a79d517e9.png "symlinks in exa")

*symlinks in exa*

![](../Images/0fa02ac221b6f378c54fd74013b7945c.png)

递归

当你想递归当前目录下所有目录的列表时，`exa` 能进行递归。

![](../Images/03f7acc7103d4fa5d371f3f6b4470292.png "recurse in exa")

*recurse in exa*

![](../Images/0fa02ac221b6f378c54fd74013b7945c.png)

总结

我相信 \`exa 是最简单、最容易适应的工具之一。它帮助我跟踪了很多 Git 和 Maven 文件。它的颜色编码让我更容易在多个子目录中进行搜索，它还能帮助我了解当前的 xattrs。
