2021 年对于 DevOps 来说是激动人心的一年，开发团队不断适应远程和混合工作模式。这一年最受欢迎的 DevOps 文章展示了我们的社区如何关注工具、创新、最佳实践和转型。

![](../Images/23b84789889298afb0333ccf047bbbe0.png)

DevOps 工具和创新

该行业的工具仍然是读者的首选读物。Nimisha Mukherjee🔗 opensource.com 是红帽的一名工程经理，她编写了 面向开发人员的 13 个开源工具🔗 opensource.com。她将工具分为“内环”和“外环”两个部分，“内环”是开发人员最常见的任务，“外环”是开发人员的代码通过持续集成和交付（CI/CD）部署到生产环境的地方。

我们的读者对实现 DevOps 工具链的兴趣也很高。首次投稿的 Tereza Denkova🔗 opensource.com 是一家 IT 专业服务公司 Accedia 的营销助理，他撰写了 如何实现 DevOps 工具链🔗 opensource.com，并将其与创新紧密联系在一起。

![](../Images/23b84789889298afb0333ccf047bbbe0.png)

DevOps 实践

Daniel Oh🔗 opensource.com 是我们的主要支持者，也是一位多产的内容创作者，他写了 2021 年需要关注的 3 个无服务器策略🔗 opensource.com，概述了当今无服务器应用程序开发和部署方法是如何加速采用 DevApps 实践的。

Evan “Hippy” Satis🔗 opensource.com 在他的文章 解决 CI/CD 中的存储库阻抗不匹配🔗 opensource.com 中提供了调整部署映像和描述符的策略。他是红帽公司的高级顾问，他在文章中采用的有条不紊的方法证明了他的行业经验。另外，请参阅他的文章 在 shell 中处理模块化和动态配置文件🔗 opensource.com。

在我的文章 DevOps 文档指南🔗 opensource.com 中，我提出了让文档成为 DevOps 讨论的一部分的理由。我从读者那里得到了一些有见地的评论，因此我正在为未来的一篇文章跟进这些评论。

![](../Images/23b84789889298afb0333ccf047bbbe0.png)

DevOps 转型

我们有时不相信 DevOps 能够适应组织需求。理解其他形式的运维的潜在影响是非常必要的，这些运维可能在现在或将来补充或增强 DevOps。Bryant Son🔗 opensource.com，一个自称是章鱼猫(Octocat)的人，在 GitOps 和 DevOps 有何不同？🔗 opensource.com 中提出 GitOps 是 DevOps 的进化形式。

Mike Calizo🔗 opensource.com 是新西兰奥克兰的一位红帽公司解决方案架构师，他撰写了 如何成功采用 DevSecOps🔗 opensource.com。本文将介绍他作为解决方案架构师的经验。他解释了在你迁移到 DevSecOps 的过程中可能会遇到的一些安全挑战。

我写了一系列关于 DevOps 到 DevSecOps 转型的文章。它们是：

◈ 启动从 DevOps 到 DevSecOps 的转型🔗 opensource.com◈ 开始 DevSecOps 转型的 3 个阶段🔗 opensource.com◈ 遵循 DevSecOps 成熟度模型🔗 opensource.com◈ DevSecOps 转型的另外 3 个阶段🔗 opensource.com◈ 使 DevSecOps 的采用成为团队努力的 4 个步骤🔗 opensource.com![](../Images/23b84789889298afb0333ccf047bbbe0.png)

2022 年和 DevOps 的未来

看到 DevOps 的文章登上了 2021 年最受欢迎的名单，说明 DevOps 将迎来一个更加有趣的 2022 年，因为组织正在继续掌握他们的工具，改进他们的战略，并继续他们的 数字化转型🔗 enterprisersproject.com，以便在不断变化的市场中有效地竞争。
