Web应用作为企业对外开放的常见服务，其0day、nday漏洞一直被各大APT组织用于各种攻击事件当中，该类漏洞的利用具备构造难度低、攻击影响大等特点，一旦在外网暴露风险，可能会直接导致攻击者利用其突破边界网络，植入Webshell并进一步渗透进内网，给企业带来不可估量的影响。其中Java反序列化是近些年安全研究的重要领域之一，在Weblogic、JBoss、WebSphere、CommonsCollections等知名容器和组件当中都曾被披露出存在反序列化风险，由于加载了不受信任的序列化数据，导致在还原对象的过程中被攻击者控制代码逻辑走向，从而造成命令执行、XXE、代码执行、SSRF等风险，虽然各大企业已经在这个过程中引入黑名单等防御措施，但还是难逃被绕过的命运。

  

  

Weblogic 7u21绕过 反序列化漏洞

Weblogic作为一款优秀的商业中间件产品，有着极大的用户基数。自 2017 年以来，Weblogic 的反序列化漏洞频繁出现，攻击者通过向默认开启的7001端口发送T3、IIOP协议数据实施攻击，Oracle官方对此采取措施通过使用类黑名单的方式进行防御，但每个季度仍然有不少绕过黑名单的利用链出现，今年攻防演练期间我们再次观察到新的绕过利用链，该链基于原生 JDK 利用链 7u21 进行改造，通过 T3 协议可以直接对 Weblogic 容器进行未授权代码执行攻击。

  

该漏洞影响默认 JDK 版本在 7u21 之前的 Weblogic 环境（集中在 10.3.0.0 - 12.1.3.0 版本）。

  

这条利用链的核心是在 JDK 7u21 利用链基础上的绕过，Weblogic 将该利用链中的 com.sun.org.apache.xalan.internal.xsltc.trax.\* 拉入黑名单，导致该链无法继续使用，而本次绕过主要使用了 MarshalledObject 类，该类不在 Weblogic 的黑名单中，通过使用动态代理在反序列化过程中触发对 MarshalledObject#get 的调用，实现二次反序列化的目的，其中会对 objBytes 成员变量执行反序列化操作，通过提前在此变量中保存 JDK 7u21 PoC即可实现绕过。

Weblogic 7u21绕过相关代码

  

利用该漏洞可以将自定义的字节码发送至目标服务器执行，结合 MemWebshell 字节码实现对目标 Weblogic 内存马的注入，并使用魔改过的冰蝎进行控制。

CVE-2021-44228

Apache Log4j2 是对 Log4j 的升级，它比前身 Log4j 1.x 版本的功能更加强大，该组件被广泛用于日常的开发、测试和生产环境中，主要用于业务日志、运行日志的记录工作，根据MVN Repository显示有接近 7000 的项目引用了 Log4j2，应用范围十分广泛。Log4j2组件于2021年12月被爆出CVE-2021044228漏洞（别称：Log4Shell），极大范围的互联网业务、开源项目、商业产品等都受到了影响。

  

该漏洞影响的组件版本：2.0-beta9 =< Apache Log4j 2.x < 2.16.0（2.12.2 版本不受影响）。

  

本次漏洞造成的主要原因就是 Log4j2 提供的 “Property Support” 特性所造成的，利用该特性可以在打印日志的时候引用配置好的属性，并替换到日志当中，支持从配置文件、系统变量、环境变量、线程Context以及事件中存在的数据中引用所需的变量到日志中，功能十分强大。

  

在org.apache.logging.log4j.core.lookup包中提供了一系列的插件，支持用户从自定义的渠道来获取属性，其中JndiLookup插件允许用户通过JNDI来检索变量。由于其中未对查询地址做好过滤，导致产生JNDI注入漏洞，从而造成代码执行、命令执行等风险。该漏洞利用难度低、影响范围极大，可能在未来几年被广泛利用，成为日志调用的“噩梦”。

![](../Images/1a8c77e52900c9ada93dae3633060cb0.png)

漏洞触发点

  

该漏洞类型为 JNDI 注入，触发后会拉取远端的 Java 字节码回来执行，最终可以达到代码执行、命令执行等目的，利用该漏洞可以直接注入 MemWebshell 到内存中，实现对 Web 权限维持。由于该组件被广泛应用于各种业务中，导致出现许多不同的漏洞利用场景：

*   企业在业务项目中直接引用该组件，导致直接一次传播漏洞到业务模块中，例如：认证授权、搜索功能等；
    
*   Apache Solr、Apache Druid 等开源应用的使用，导致二次传播该漏洞到服务架构；
    
*   Ghidra 逆向工具，构造特殊的 ELF 文件，使用该工具打开文件时会触发漏洞的利用；
    
*   物联网应用场景下，控制云端采集设备名、设备描述、设备活动等信息时，通过替换EXP到回收信息中实现对云端服务的攻击；
    
*   游戏客户端、服务端等项目引用该组件，通过聊天框实现对目标的攻击；
    
*   ...
