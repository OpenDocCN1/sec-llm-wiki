今年Exchange最值得关注无疑是Proxylogon，Proxyshell和CVE-2021–42321，三个漏洞都可以实现RCE。又因为 Exchange 在 Active Directory 域中拥有过高的特权，甚至很多运维人员为了方便，直接就是域管权限进行维护。即使不是域管权限维护，因为Exchange Windows Permissions 组对 Active Directory 中的 Domain 对象具有 WriteDacl 访问权，这使得该组的任何成员都可以修改域特权，其中包括执行 DCSync 操作的特权，具有此特权的用户或计算机可以执行域控制器通常用于复制的同步操作，包括同步活动目录中所有成员的密码哈希，以至于在 Exchange 服务器上拿到管理员权限就足以升级到域管理员权限。



Proxylogon

受影响版本

Exchange 2019 <=CU8

Exchange 2016 <=CU19

Exchange 2013 <=CU23


ProxyLogon是由多个漏洞组成的攻击链，包含四个漏洞(CVE-2021-26855, CVE-2021-26857, CVE-2021-26858, CVE-2021-27065)，流传最广也是使用最多的是由SSRF（CVE-2021-26855）和任意文件写入（CVE-2021-27065）组成的exploit。


该漏洞影响Microsoft Exchange Server 2013（15.00.1497.012之前版本）、Microsoft Exchange Server 2016（15.01.2106.013之前版本）、Microsoft Exchange Server 2019（15.02.0721.013之前版本）。


其中核心是SSRF漏洞，漏洞代码出现在Microsoft.Exchange.HttpProxy.BEResourceRequestHandler中，这里进行了两个判断：一是通过后缀名来判断本次请求是否为请求静态资源，二是请求中是否存在 Cookie的值X-BEResource。构造满足条件的请求头，即可发起ssrf请求。

BEResourceRequestHandler中的漏洞代码


成功利用此漏洞可写入webshell，而且是system权限，利用exchange管理员的特权，可同步域内所有成员的密码哈希，再利用PTH即可获取域管权限。

ProxyShell

受影响版本

Exchange Server 2013 Versions < Builder 15.0.1497.012

Exchange Server 2016 CU18 < Builder 15.1.2106.013

Exchange Server 2016 CU19 < Builder 15.1.2176.009

Exchange Server 2019 CU7 < Builder 15.2.0721.013


同样基于exchange的CAS架构，ProxyLogon的SSRF是利用了无需认证的BEResourceRequestHandler对cookie的错误处理，ProxyShell的ssrf只是换了另一个无需认证的接口autodiscover进行利用。


该漏洞影响Microsoft Exchange Server 2013（15.0.1497.012之前版本）、Microsoft Exchange Server 2016 CU18（15.1.2106.013之前版本）、Microsoft Exchange Server 2016 CU19（15.1.2176.009之前版本）、Microsoft Exchange Server 2019 CU7（15.2.0721.013之前版本）。


漏洞点在Microsoft.Exchange.FrontEndHttpProxy.dll的AutodiscoverProxyRequestHandler()中,关键点在GetClientUrlForProxy()，需要IsAutodiscoverV2Request()返回为false，执行下面的RemoveExplicitLogonFromUrlAbsoluteUri()。就可以从absoluteUri中删除explicitLogonAddress。

GetClientUrlForProxy中的问题代码


explicitLogonAddress值通过从cookie中设置Email值获取，必须包含有效的邮箱地址。


IsAutodiscoverV2Request()函数进行了两个判断，结合前面的条件，最终的请求URL为/autodiscover/autodiscover.json?a=email@doamin.com，cookie中添加的Email字段同样为此，之后便可访问/mapi/nspi进行SSRF验证，后续的整个exp流程都基于此SSRF。


成功利用此漏洞可写入webshell，而且是system权限，利用exchange管理员的特权，可同步域内所有成员的密码哈希，再利用PTH即可获取域管权限。

CVE-2021-42321

受影响版本

Microsoft Exchange Server 2016 Cumulative Update 21

Microsoft Exchange Server 2016 Cumulative Update 22

Microsoft Exchange Server 2019 Cumulative Update 10

Microsoft Exchange Server 2019 Cumulative Update 11


CVE-2021–42321一经发布便引起了极大关注，这是一个反序列化漏洞。通过跟踪发现，反序列化的位置在OrgExtensionSerializer.TryDeserialize()函数。


该漏洞影响Microsoft Exchange Server 2016 CU21、CU22，Microsoft Exchange Server 2019 CU10、CU11。

TryDeserialize()中stream从userConfiguration获取


在TryDeserialize()中的userConfiguration可以由用户设置，最终可以在GetUserExtensions()触发反序列化。成功利用此漏洞可写入webshell，而且是system权限，利用exchange管理员的特权，可同步域内所有成员的密码哈希，再利用PTH即可获取域管权限。
