CVE-2021-22555

该漏洞是由于Linux Netfilter模块中memcpy()、memset()函数在使用过程中存在缺陷，导致攻击者可以利用漏洞实现权限提升，如果在容器场景下，可以从docker、k8s容器中实施容器逃逸。该漏洞影响Linux Kernel2.6.19之后版本，并于内核版本5.12修复。

  

在兼容模式下调用IPT\_SO\_SET\_REPLACE 或 IP6T\_SO\_SET\_REPLACE函数，在将内核结构从32位转换到64位过程中转换的分配大小没有正确计算，最终导致xt\_compat\_target\_from\_user()函数中0字节越界写。

通过msgsnd构造堆排布，之后通过msgrcv释放掉一些主消息，这时候调用setsockopt(IPT\_SO\_SET\_REPLACE)触发漏洞，申请的struct xt\_table\_info对象会有较大概率分配到制造的空洞中，通过溢出写两个\\x00，覆写相邻的主消息m\_list->next指针的后两位。之后通过堆排布使得skb与pipe\_buffer占据同一块内存空间，重新构造skb，劫持pipe\_buffer->ops至本内存空间，伪造pipe\_buffer->ops->release为ropchain地址，实现执行流程控制。将 RBP 的值保存在内核中的某个暂存地址处，以便稍后恢复执行，然后调用commit\_creds(prepare\_kernel\_cred(NULL)) 进行权限提升，最后调用 switch\_task\_namespaces(find\_task\_by\_vpid(1), init\_nsproxy) 进行切换进程1的命名空间到 init 进程。之后，恢复 RBP 的值并返回继续执行。回到用户空间， 现在拥有更改 mnt、pid 和 net 命名空间的 root 权限，以逃离容器并脱离 kubernetes pod。

CVE-2021-31440

2021年5月27日ZDI官网披露一个Linux内核eBPF verifier边界计算错误漏洞，由于eBPF验证器在Linux内核中没有正确计算64位转32位操作的寄存器边界，导致本地攻击者可以利用此缺陷进行内核信息泄露或特权提升。

  

为了防止ebpf程序访问map之外的内存，ebpf在verifier的代码中添加了一些检查防止访问越界，并增加了一个32bit bounds tracking的功能，该功能实现了用64位寄存器上的已知范围来推断该寄存器低32位的范围。

  

漏洞出现在 \_\_reg\_combine\_64\_into\_32() 函数中，这是32bit bounds tracking功能实现的一个函数，但是实现的代码中在更新无符号低32位边界时，判断不严格，错误计算了寄存器的约束边界，导致检查与运行时不一致，实现越界读写。

```

```

  

这个漏洞的根本原因在于(1)/(2)处认为64位的最小值和32位的最小值/最大值一定相等，但是并不是这样，假如64位最小值是0x100000000，那么低32位最小值就是0，两者并不相等，假如一个64位的值在32位的范围内，这个才是成立的。当传入的reg->umin\_value=1, reg->umax\_value=0x100000000时，在(1)处判断通过，因此会更新reg->u32\_min\_value=1,但是在(2)处，因为0x100000000并不在32位的范围内，因此不会判断通过，此时reg已经出现了错误的范围更新，但是运行时reg的范围是正常的，会使后面的一些check绕过，导致任意地址读写。

  

该漏洞影响 linux kernel 5.7之后的版本，5.13-rc1及之后发布的版本已修复。
