# 年报解读｜年度高可利用漏洞——Windows提权漏洞

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzkyMTI0NjA3OA==&mid=2247486751&idx=1&sn=581373fdfed271c655b77819b1953c5f&chksm=c187cd0ef6f04418ae4fa180c592460c7b7d46dbe54f6e549ee24d82e2ba201f0a9e9e4aa81f&scene=126&sessionid=1681403749#rd](http://mp.weixin.qq.com/s?__biz=MzkyMTI0NjA3OA==&mid=2247486751&idx=1&sn=581373fdfed271c655b77819b1953c5f&chksm=c187cd0ef6f04418ae4fa180c592460c7b7d46dbe54f6e549ee24d82e2ba201f0a9e9e4aa81f&scene=126&sessionid=1681403749#rd)

  

Windows提权漏洞在各大APT组织的攻击活动中都起到了关键的作用，相关0day、1day漏洞被广泛用于各种攻击事件。该类漏洞一般被攻击者用于在获取目标主机的执行权限后，进一步提升执行权限，从而实现对目标主机的完全控制，并为后续植入木马、留存后门等行为提供支撑。

  

  

CVE-2021-1648

CVE-2021-1648是出现在splwow64.exe地址空间内的任意指针解引用漏洞，该漏洞影响当时Windows 8.1到Windows 10及Windows Server 2012到Windows Server 2019全版本，微软官方于2021年1月发布补丁修复。splwow64.exe是Windows中一个中完整性（Medium integrity level）级别进程，当32位应用程序对打印机进行访问时，splwow64将会被调用。该漏洞的主要原因在于splwow6.exe4处理其他进程发送来特定的LPC消息过程时，会将个别字段作为参数传递给gdi32full.dll中的GdiPrinterThunk函数，后者会调用memcpy函数对splwow64特权地址空间进行读写操作，而函数的参数可以由用户发来的LPC消息控制：

![](../Images/aebf3c98853045c8d479a4c8e11e5435.png)

CVE-2021-1648漏洞代码

  

通过发送特定的LPC消息可以获得任意地址读写原语从而控制程序流程执行任意代码。

  

该漏洞是CVE-2020-0986补丁的绕过，在CVE-2020-0986的基础上绕过了对传入数据的校验，共包含了一个任意地址写权限提升漏洞和两个信息泄漏漏洞。漏洞的最大特点在于在Internet Explorer的安全策略中，splwow64.exe可以作为一个中完整性级别进程被代理执行：

![](../Images/fcbe33cfeb16bdbc62224a77985033f5.png)

splwow64.exe情况

  

攻击者若利用其他漏洞控制IE内代码执行流程，再配合此漏洞进行沙箱逃逸从而可以在中完整性级别权限下执行任意代码。另外值得一提的是由于微软从漏洞被报告到修复漏洞花费了较长时间，超过了GoogleProjectZero 90 天的披露期限，所以该漏洞有一段时间实际是一个公开的0day，在当时具有严重的危害性。

  

CVE-2021-1732

CVE-2021-1732漏洞最早是蔓灵花（BITTER）组织在APT攻击中作为0day漏洞使用，该漏洞通过捕获在野利用的方式发现。微软2月月度更新中对其进行了修复。

![](../Images/32fe6f25c6e9c026c48f027b78fbbf6d.png)

CVE-2021-1732利用效果

  

CVE-2021-1732是win32kfull.sys中的一个越界写漏洞，成功利用该漏洞可以实现本地提权。漏洞成因是在win32kfull!xxxCreateWindowEx回调xxxClientAllocWindowsClassExtraBytes时产生，通过混淆console窗口和一般窗口，该回调将导致内核对象的越界访问。win32kfull!xxxCreateWindowEx会调用win32kfull!xxxClientAllocWindowClassExtraBytes引发回调，并在用户态将窗口转换为console窗口。攻击者利用该漏洞可以实现本地提升权限至system权限。

  

该漏洞影响范围包括：Window 10 1803、1809、1909、2004、20h2等，以及Windows server2019、版本2004、20H2等版本。

CVE-2021-31956

CVE-2021-31956是由Kaspersky捕获的一个在野利用漏洞，该漏洞最初被用在Chrome浏览器中配合Chrome中远程命令执行漏洞进行沙箱逃逸，成功利用此漏洞后可以获取系统权限。该漏洞影响当时Windows 7到Windows 10及Windows Server 2008到Windows Server 2019全版本，微软官方于2021年6月发布补丁修复。

  

漏洞点位于ntfs.sys的NtfsQueryEaUserEaList函数中，该函数在处理文件的扩展属性列表时，会将数据暂时存储到内核池中：

![](../Images/099e5f3a71b77a56a2136b3ca82cb097.png)

CVE-2021-31956相关代码

  

程序会对每条数据进行4字节对齐处理，数据存储后会记录下已存储长度并计算剩余缓冲区长度与补齐需要的长度：

![](../Images/a4cd869003b7901416b6fc62cd9dca0f.png)

CVE-2021-31956相关代码

  

漏洞出现在对存储空间校验时未进行整数溢出检查，经巧妙构造数据后，剩余缓冲区与补齐长度做差可以导致整数下溢，从而绕过检测最终导致内核池溢出。

  

该漏洞具有高可利用性，首先文件扩展属性的数据可由用户通过NtSetEaFile函数在一定大小范围内构造，其次用来存储数据的内核池大小是用户可控的，通过对合适的对象进行内核池喷并通过溢出覆盖其数据就有可能构造出读写原语，从而替换当前进程Token实现权限提升。

CVE-2021-36934（HiveNightmare）

2021年7月20日国外研究员在社交媒体上发布该漏洞信息，称其可在最新的Windows 11上以普通用户权限查看系统的SAM文件。该文件存储有系统中所有用户登录的凭据哈希值。随后经过测试该问题同样存在于Windows 10系统上。

  

该漏洞的主要问题在于权限限制出错，导致普通用户可以通过访问卷影备份中的SAM、SECURITY和SYSTEM等文件，并最终导致提权操作。具体来说是BUILTIN\\Users可以访问c:\\Windows\\System32\\config\\SAM，属于系统权限管理的问题。SAM文件是系统中敏感的注册表配置单元，而BUILTIN\\Users中包含非管理员用户。从而造成了信息窃取并最终实现权限提升。

  

攻击者成功利用该漏洞可以获取目标系统中的用户登录凭据，配合其他工具，最终可以实现将本地权限提升至系统权限。

![](../Images/6548264b59a7a3c0b62e6f30b2a1d7a1.png)

CVE-2021-36934演示效果

  

该漏洞影响Windows 10 1809、1909、2004、20h2、21h1等版本。

CVE-2021-40449

CVE-2021-40449是Kaspersky捕获的一个在野漏洞，该漏洞曾配合有效载荷在被称为MysterySnail的活动中进行攻击利用，攻击者成功利用此漏洞后可以获取系统权限并执行恶意代码。该漏洞影响当时Windows 7到Windows 10及Windows Server 2008到Windows Server 2019全版本，微软官方于2021年10月发布修复补丁。

  

漏洞出现在Win32k.sys中，用户调用ResetDC函数最终会调用其内部函数GreResetDCInternal，继续执行到hdcOpenDCW内部会执行用户模式回调函数。若将回调函数设置再次执行ResetDC函数，则会对同一个DC第二次执行进入GreResetDCInternal函数，这次忽略掉回调函数执行，执行过程会销毁旧的DC并创建新的DC，回调结束会返回到原GreResetDCInternal函数，由于原函数没有执行完，继续执行还会对原DC进行操作，这将会导致use after free问题，漏洞触发位置如下图所示：

![](../Images/aff38bfa26183c4c9d3001e042156b5d.png)

CVE-2021-40449漏洞代码

  

此处调用的函数地址及参数随原内存被释放而清除。对于漏洞利用，可以在回调返回前将已释放的这部分内存回收并修改其数据，就可以去调用受控参数的任意函数，从而构造漏洞利用原语，最终获取系统权限。

CVE-2021-36942

CVE-2021-36942漏洞于今年7月被 Lionel Gilles 发现，同时利用该漏洞的攻击方法还有一个别名--PetitPotam。该漏洞允许攻击者使用MS-EFSRPC（微软的加密文件系统远程协议） 连接到目标主机劫持NTLM认证，使得目标主机向攻击者指定的地址进行NTLM认证。由于该漏洞能够操纵NTLM流量，因此适用于NTLM认证流量的中继和劫持。

  

该漏洞影响Windows Server 2008、2008R2、2012、2012R2、2016、2019、2004、20H2等版本系统。

  

攻击者滥用 Windows API 函数 EfsRpcOpenFileRaw，通过发送一个 EfsRpcOpenFileRaw请求，并在FileName字段指定UNC路径，受害主机则会访问该地址并进行NTLM认证，达到了强制\[主机B\]向指定目标进行NTLM认证的目的。

![](../Images/6f5db3de02061b5620c9058ae5c11c77.png)

CVE-2021-36942指定unc路径数据包

  

该漏洞单独使用只能达到NTLM强制认证的目的，但是结合NTLM中继可以达到抓取NTLM 认证数据和提权的效果。

CVE-2021-42287

2021年11月14日微软发布了编号为KB5008602、KB5008382、KB5008380、KB5008383的补丁，分别修复了编号为CVE-2021-42278、CVE-2021-42282、CVE-2021-42287、CVE-2021-42291组合的AD域权限提升漏洞。该组漏洞于11月9日由Cliff Fisher在推特中首次透露，并由Charlie Clark首次公布了该漏洞的利用细节。该组漏洞影响从Windows Server 2008到Windows Server 2022的多个服务器版本，组合使用会致使攻击者可在AD域中以普通用户权限获取到域管理员权限的服务票据ST。攻击者使用管理员权限的服务票据后可调用管理员权限，如从活动目录数据库中同步任意AD域账户的密码哈希，影响极为严重。

  

CVE-2021-42278允许攻击者修改计算机帐户的sAMAccountName属性伪造域控制器账户。CVE-2021-42282允许攻击者添加重名的服务主体名称SPN。CVE-2021-42287允许攻击者假冒域控制器，漏洞的关键在于KDC授予服务票据时对PAC的判断不严谨。CVE-2021-42291允许攻击者以普通用户创建机器账户后，修改机器账户的安全描述符。

  

由于这些漏洞的同时存在，攻击者组合利用可达到从普通用户权限提升到域管理员权限的效果。首先攻击者以普通用户权限添加一个域机器账户。然后将域机器账户的sAMAccountName属性修改为域控制器名称，然后申请TGT并将sAMAccountName还原。之后攻击者再次使用该机器账户的TGT申请服务票据时，域控制器会误以为该TGT属于域控制器账户。同时利用S4U2self可以模拟域管理员账户，最终可以获得属于管理员账户的服务票据。漏洞的完整利用流程如下图所示。

![](../Images/a5ed91540ca2c3ee4586d848a9d82c1d.png)

CVE-2021-42287等漏洞利用链时序图

  

由于该组漏洞横跨了多个Windows服务器版本，且能直接从普通域用户权限直接提升到域管理员权限，因此影响十分严重，预计在未来几年的内网渗透中将会被大量使用。但是利用该漏洞的弊端也十分明显，因为漏洞攻击过程会按顺序产生创建机器账户、清除SPN、sAMAccountName属性修改、申请票据、S4U2Self等Windows日志，很容易被防御者检测到。
