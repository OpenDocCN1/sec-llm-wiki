Print Spooler是Windows的打印后台处理服务。作为Windows最古老的服务之一，Print Spooler似乎一直没有变化。而自从去年“PrintDemon”被公开以来，更多人开始重视这一历史悠久的Windows服务。由于打印机服务的特殊性，在进行文件操作时通常以模拟System权限运行。而Print Spooler又是Windows中默认开启的服务，一旦出现问题就很可能被攻击者利用进行权限提升甚至远程执行命令。今年Print Spooler又爆出了一系列漏洞，其中最被广泛关注的便是被称为“PrintNightmare”的CVE-2021-34527与其前身CVE-2021-1675，漏洞影响当时Windows 7到Windows 10及Windows Server 2008到Windows Server 2019，微软官方于2021年7月发布补丁修复。



01 CVE-2021-1675

CVE-2021-1675是Windows Print Spooler服务的漏洞。由于其设计中存在的一个严重缺陷，用户可以要求该服务执行任意指定的代码，从而获得权限提升，同时在域环境中合适的条件下，无需任何用户交互，未经身份验证的远程攻击者就可以利用该漏洞以SYSTEM权限在域控制器上执行任意代码，从而获得整个域的控制权。该漏洞由绿盟科技天机实验室发现并获得微软致谢，也获得Pwnie Award 2021 “最佳提权漏洞”和“最佳服务端漏洞”两项提名。


漏洞出现在RpcAddPrinterDriverEx函数中，根据微软官方文档[1]，RpcAddPrinterDriverEx函数声明如下：

 DWORD RpcAddPrinterDriverEx(
   [in, string, unique] STRING_HANDLE pName,
   [in] DRIVER_CONTAINER* pDriverContainer,
   [in] DWORD dwFileCopyFlags
 );


其中漏洞关键点在于dwFileCopyFlags，该参数的作用是设置添加驱动时的标志位，若将此参数设置为特定的标志，用户可绕过驱动文件签名、驱动文件目录等一系列安全检测最终调用到localspl.dll的InternalAddPrinterDriver函数从而在Print Spooler服务进程中加载任意DLL，实现权限提升。CVE-2021-1675的修复补丁在AddPrinterDriverEx加入了用户权限校验，未通过校验的用户身份所设置的标志位会失效，从而无法加载任意驱动文件。

02 CVE-2021-34527

CVE-2021-34527是CVE-2021-1675的补丁绕过，是通过另外一个Windows Print Spooler服务的RPC API RpcAsyncAddPrinterDriver，查看官方文档[2]，其声明如下：

 DWORD RpcAsyncAddPrinterDriver(
   [in] handle_t hRemoteBinding,
   [in, string, unique] wchar_t* pName,
   [in] DRIVER_CONTAINER* pDriverContainer,
   [in] DWORD dwFileCopyFlags
 );


可以看到此API同样允许用户设置dwFileCopyFlags参数，由于执行过程缺乏权限校验，通过设置特定参数调用服务内部用于添加驱动的函数InternalAddPrinterDriver，依然可以达到加载任意驱动的目的。


CVE-2021-1675与CVE-2021-34527漏洞的危害性之大，在于漏洞不仅可以在本地完成提权利用，同样在合适的域环境下可以实现远程文件加载，其原理在于RpcAddPrinterDriverEx与RpcAsyncAddPrinterDriver的另外一个参数pDriverContainer，其声明如下：

 typedef struct _DRIVER_INFO_2 {
   DWORD cVersion;
   [string] wchar_t* pName;
   [string] wchar_t* pEnvironment;
   [string] wchar_t* pDriverPath;
   [string] wchar_t* pDataFile;
   [string] wchar_t* pConfigFile;
 } DRIVER_INFO_2;


在本地提权过程中，只需要设置好pConfigFile为需要加载的DLL路径即可，在远程利用下需要加载一个远程DLL，而pConfigFile参数限制了UNC路径，绕过办法是首先利用pDataFile参数，该参数允许使用UNC路径，并最终将远程DLL文件复制到本地目录，再次使用同样参数进行调用会将其复制到缓存目录，由于该目录可以通过遍历预测到，第三次调用可以将pConfigFile设置成目标机器路径，从而实现远程加载的目的。
