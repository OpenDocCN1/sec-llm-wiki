01 CVE-2019-17564

漏洞简介

Apache Dubbo是一款高性能、轻量级的开源Java RPC服务框架。Dubbo可以使用不同协议通信，当使用http协议时，Apache Dubbo直接使用了Spring框架的org.springframework.remoting.httpinvoker.HttpInvokerServiceExporter类做远程调用，而这个过程会读取POST请求的Body并进行反序列化，最终导致漏洞。


在Spring文档中，对HttpInvokerServiceExporter有如下描述，并不建议使用：

WARNING: Be aware of vulnerabilities due to unsafe Java deserialization: Manipulated input streams could lead to unwanted code execution on the server during the deserialization step. As a consequence, do not expose HTTP invoker endpoints to untrusted clients but rather just between your own services. In general, we strongly recommend any other message format (e.g. JSON) instead.


这个漏洞影响Apache Dubbo 2.7.4及以前版本，2.7.5后Dubbo使用com.googlecode.jsonrpc4j.JsonRpcServer替换了HttpInvokerServiceExporter。


影响版本

• 2.7.0 <= Dubbo Version <= 2.7.4

• 2.6.0 <= Dubbo Version <= 2.6.7

• Dubbo 所有 2.5.x 版本（目前已不支持）


环境搭建

下载Dubbo，https://github.com/apache/dubbo-samples，进入http示例目录，修改Dubbo版本，修改pom.xml中dubbo.version为2.7.3

03 GHSL-2021-034

漏洞简介

由于CVE-2020-11995修复不完善，导致可以绕过。

https://securitylab.github.com/advisories/GHSL-2021-034_043-apache-dubbo/


影响版本

• Dubbo 3.0.0 to 3.0.1

• Dubbo 2.7.0 to 2.7.12

• Dubbo 2.6.0 to 2.6.11

• Dubbo all 2.5.x versions (not supported by official team any longer)


漏洞分析

• org.apache.dubbo.rpc.protocol.dubbo.DecodeableRpcInvocation#decode


在2.7.12版本中，解码的过程中，在添加对调用服务的方法名的判断的基础上，还对调用方法的参数类型进行了判断。限制了Asrs参数处的Hessian2反序列化，因为Hessian2反序列化，需要Map类型的参数。但是在请求额外参数Attachments处，可以直接传入Map类型的对象，进行反序列化。
