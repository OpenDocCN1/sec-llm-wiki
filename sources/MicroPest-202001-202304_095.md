## 1、CollaRE

  

观点是: CollaRE 促进了协作性逆向工程。它集中了相关文件的存储，并允许用户使用相应的工具打开数据库。CollaRE 客户端提供了一系列插件，用于导入和导出一些数据(注释和函数名) ，以便在最常用的逆向工程工具之间共享。

![](../Images/0ac9b4b5dfdb42bd3a6477cb8a789965.png)

  

2、CTO – Call Tree Overviewer

  

观点： CTO 插件提供了函数调用图的近似视图风格的表示。它允许您检查函数之间的路径(并将生成新的专用图表显示这些路径)。此外，该插件还提供了一个替代函数列表，其中包括交叉引用、字符串文字和许多其他内容的摘要(这些信息也可以作为图形提示)。

![](../Images/75db0559912d3946e24358dc105c59ee.png)

  

3、D-810

  

观点是: 受到 Rolf Rolles 的 HexRaysDeob 插件的启发，作者编写了一个灵活而强大的可扩展和可配置的 deobfuscator。这个插件提供了一个令人印象深刻的规则集合，这些规则以 Python 类的形式实现，以及一组预定义的模板(项目)。每个项目都包含集合中的某些规则，可以使用特殊对话框进行微调(添加/删除规则)。这个插件提供了一个 Python API，可以用来定义规则，并提供帮助来寻找新规则的模式。一个值得注意的特性是基于 z3的微代码优化，它有助于以更广义的方式编写规则。

![](../Images/7b039baafa17072308bda58d32360884.png)

  

4、FunctionInliner

  

观点是：可以用来简化二进制文件的反转，二进制文件已经通过函数大纲(例如 clang-moutline)进行了空间优化。

![](../Images/21ff63ddaf5236518c9346ee21adeb49.png)

  

5、IDA2Obj

  

观点是: IDA2Obj 提供了一种新颖的封闭源码二进制文件插装方法。它使用 IDA 来分析文件，然后转储数据库内容以重新定位带有插装钩子的对象文件。然后将对象文件与插装存根代码链接在一起，提供与原始存根行为等效的插装二进制文件。目前它只实现了对 x64 PE 文件的支持，但是同样的方法也可以扩展到其他平台。

![](../Images/f01c5caa56e0c8652c13ba9b39a4dc67.png)

  

6、IDAPatternSearch

  

观点是: IDAPatternSearch 为功能识别提供了另一个角度: 它(部分地)实现了 Ghidra 的功能模式格式，以查找 IDA 在自动分析过程中没有发现的功能。虽然理想情况下 IDA 的自动分析应该揭示所有的函数，但在实践中可能会失败，并且能够重新使用已经存在的模式列表是一个很好的补充！

![](../Images/7ed970a201a6d1c3a56b727db63c3574.png)

  

7、IPyIDA

  

观点是: IPyIDA 提供了对 IDAPython API 的 IPython 内核的集成。对于 idapython 的新手和中级用户来说，它在自动完成、文档检索和使用 Jupyter 笔记本的能力方面帮助极大。

![](../Images/9ac1d4aef017f85f2b5b8dfbe715124e.png)

  

8、jside

  

观点是: jside 将 JavaScript 脚本添加到 IDA 中，包括一个带有语法突显、自动补全和交互式调试器的 IDE。该项目由一个插件组成，该插件在 IDA 中实现 RPC 服务器(使用 windows 消息) ，以及一个外部 IDE，该 IDE 可以连接到任何 IDA 实例并使用 JavaScript 控制它。这个简约的 IDE 是用 VB6编写的，即使在最新的 Windows 版本中，它也能很好地与 x64 IDA 协同工作。提供了几个示例脚本。总的来说，这是一个有趣的扩展 IDA 的方法，尽管目前仅限于 Windows。

![](../Images/fc217391daa17c6e3c0ca5c6ed68947b.png)

  

9、nmips

  

观点是: 该插件为 IDA 增加了nanoip 支持。Nanoips 是 IDA 本身尚不支持的 MIPS 指令集的新编码。作者在可能的情况下巧妙地重用了现有的 MIPS 指令，并为新指令添加了自定义指令。ELF 加载程序扩展程序自动获取用于 nanoips 文件的 MIPS 处理器模块，处理器扩展程序处理解码(使用 binutils 中的反汇编程序)。反编译扩展处理标准 MIPS 反编译程序没有涵盖的指令的微代码生成。通过这种方式，可以在 IDA 中打开 nanoMIPS 文件(带有一些警告) ，提供对 nanoips 代码的反汇编和反编译。

![](../Images/1461cf4fd27f3d2401582ceebf0978ba.png)

  

10、qscripts

  

观点是: QScripts 桥接 IDA 和您最喜欢的文本编辑器。在编写复杂的脚本或者在繁重的开发过程中，它将特别有用。它所知道的脚本列表与默认的“最近脚本”小部件相同，这一事实也非常舒适，因为它允许您在使用 QScripts 和内置列表之间进行无缝切换。

![](../Images/04439b3883166c4c430f2b16f4bf7c76.png)

  

11、RefHunter

  

观点是: RefHunter 提供了一个函数引用的摘要，其中包含了比内置的“ Function calls”小部件(特别是: 字符串文本和数据引用)更多的信息。摘要是可单击的(跳转到反汇编视图中的地址) ，并且可以用颜色突出显示引用行。

![](../Images/3d408b8254156bbfef85e0df392497bf.png)

  

12、SyncReven

  

观点是: SyncReven 允许用户将 IDA 连接到一个正在运行的 Reven/Axion 实例，以便调查以前捕获的执行跟踪。在这种设置中，IDA 和 Axion 之间的通信可以是双向的: IDA 不仅在 Axion 会话中扮演可视化工具/浏览器的角色，还可以驱动它并在“转换”(即指令执行)之间切换。

![](../Images/22c7554c3b40ea27398da87599cdc64a.png)

  

13、Tenet

  

观点是: 我们花了几分钟的时间才适应了 Tenet 的用户界面，但是一旦我们熟悉了它，我们就会明白这个看似简单的用户界面背后还有很多潜力。我们尝试了提供的测试用例和一个自定义用例(我们在 linux 上构建了 pin 跟踪程序，并将其与/bin/ls 一起使用) ，并且由于易用性和响应性(/bin/ls trace 大约为30mb，这当然不是很大，但也不是微不足道的)而受到了喜欢·一个人。作者将这个插件称为研究软件中复杂执行模式的插件，他的努力已经得到了回报: 一堆非常好的想法，包装在一个易于安装、易于使用的插件中！

![](../Images/40bf9eaac6def6d16680b8f3f20dbb60.png)

  

14、wilhelm

  

观点是: wilhelm 在解决“处理反编译数据”问题上做了一次有趣的尝试，他提供了一种(据我们所知)尚未探索的方法: 使用 xmlpath 样式的路径(所谓的“ wilpaths”)获取数据。这与更传统的树遍历方法相比，在某些情况下非常有用。一个聪明的，设计良好的 API！从历史上看，我们 Hex-Rays 一直关注核心 SDK api 的可用性和健壮性，部分原因是不清楚更高级、更“ python 化”的 api 应该是什么样的。Wilhelm 提供了关于理想状态下应该存在什么的有趣见解——至少可以帮助处理某些用例。

![](../Images/c506f841636c383c81d931e183bfd92a.png)

  

15、Yagi

  

观点是： 这个插件集成了 Ghidra 的反编译器到 IDA。这是非常有趣的，因为它允许 IDA 反编译比它支持的开箱即用架构更多的架构。Yagi 能够从 IDA 自身内部调用 Ghidra 的核心反编译引擎，并在一个定制的交互式源代码查看器窗口中显示反编译结果。它甚至允许用户交互式地编辑变量类型，这令人印象深刻。这个插件很复杂，但是也很干净。它有很大的改进潜力，并且可以很容易地添加对更多体系结构的支持。它肯定有一个很有前途的未来！

![](../Images/cf4053c60eb36e6e4cbc796a0d3e2f49.png)
