    有时候一抓就是一大把数据，全部堆在一起，想要找到我们需要的，犹如大海捞针，这个时候你就需要过滤了。在最上方，有一个搜索框，可以用来输入Wireshark的过滤表达式，比如我只想看其中的HTTP数据包，只需输入“http”即可。

    你可以通过IP、端口、协议等多种组合式过滤，如下面的一些例子：

> *   eth.src\[0:3\] == 00:00:83
> *   ip.addr == 192.168.0.1
> *   tcp.flags.syn == 1
> *   tcp.port in {443 4430..4434}
> *   http.request.uri == "https://www.wireshark.org/"

  

    今天，我们就来详细地学习下它的过滤表达式。

  

**1、表达式**

1）比较运算符  

| English || C-like || Description || Example |
| :-- | :-- | :-- | :-- |
| eq || \== || Equal || `ip.src==10.0.0.5` |
| :-- | :-- | :-- | :-- |
| ne || != || Not equal || `ip.src!=10.0.0.5` |
| gt || \> || Greater than || `frame.len > 10` |
| lt || < || Less than || `frame.len < 128` |
| ge || \>= || Greater than or equal to || `frame.len ge 0x100` |
| le || <= || Less than or equal to || `frame.len <= 0x20` |
| contains ||   
 || Protocol, field or slice contains a value || `sip.To contains "a1762"` |
| matches || ~ || Protocol or text field matches a Perl-compatible regular expression || `http.host matches "acme\.(org|com|net)"` |
| bitwise\_and || & || Bitwise AND is non-zero || `tcp.flags & 0x02` |

  

2）字段类型

**无符号整数：**

可以是8、16、24、32或64位，可以用十进制、八进制或十六进制表示整数。下列显示过滤器是等效的:

`ip.len le 1500`

`ip.len le 02734`

`ip.len le 0x5dc`

  
**带符号整数：**

可以是8、16、24、32或64位，可以用十进制、八进制或十六进制表示整数。

  

**布尔：**  

无论布尔字段的值是真是假，它都是存在的。例如，不管 SYN 标志是0还是1，所有包含标志的 TCP 数据包中都会出现 TCP.flags.SYN。为了只匹配设置了 SYN 标志的 TCP 数据包，您需要使用 TCP.flag.SYN = = 1。

  

**以太网址址：**

以冒号(:)、点(.)或破折号(-)分隔的6个字节，分隔符之间有一个或两个字节:

eth.dst == ff:ff:ff:ff:ff:ff

eth.dst == ff-ff-ff-ff-ff-ff

eth.dst == ffff.ffff.ffff

  

**IPv4地址：**

ip.addr == 192.168.0.1

无类域间路由(CIDR)表示法可用于测试 IPv4地址是否在某个子网中。例如，这个显示过滤器可以找到129.111 Class-B 网络中的所有数据包:

ip.addr == 129.111.0.0/16

  

** IPv6地址：**

ipv6.addr == ::1

与 IPv4地址一样，IPv6地址可以匹配一个子网。

  

**文本字符串：**

http.request.uri == "https://www.wireshark.org/"

  

3）例子

```
udp contains 81:60:03
```

显示过滤器匹配包含3字节序列0x81、0x60、0x03的数据包，该数据包包含 UDP 头部或有效负载中的任何位置。  

  

```
sip.To contains "a1762"
```

显示过滤器匹配数据包，其中 SIP To-header 包含头中任何位置的字符串“a1762”。  

  

```
http.host matches "acme\\.(org|com|net)"
```

显示过滤器匹配 HOST 头包含 acme. org、 acme. com 或 acme. net 的 HTTP 数据包。  

  

```
tcp.flags & 0x02
```

显示过滤器将匹配包含“tcp.flags”字段的所有包，并设置0x02位，即 SYN 位。  

  

**2、组合表达式**  

1）过滤逻辑操作符

| English || C-like || Description || Example |
| :-- | :-- | :-- | :-- |
| and || && || Logical AND || `ip.src==10.0.0.5 and tcp.flags.fin` |
| :-- | :-- | :-- | :-- |
| or || || || Logical OR || `ip.src==10.0.0.5 or ip.src==192.1.1.1` |
| xor || ^^ || Logical XOR || `tr.dst[0:3] == 0.6.29 xor tr.src[0:3] == 0.6.29` |
| not || ! || Logical NOT || `not llc` |
| \[…\] ||   
 || Subsequence || See “Slice Operator” below. |
| in ||   
 || Set Membership || http.request.method in {"HEAD" "GET"}. See “Membership Operator” below. |

  

2）切片操作符  

Wireshark 允许您以相当复杂的方式选择序列的子序列。在标签之后，您可以放置一对方括号\[\] ，其中包含逗号分隔的范围说明符列表。

  

```
eth.src\[0:3\] == 00:00:83
```

使用 n: m 格式指定单个范围。在这种情况下，n 是起始偏移量，m 是指定范围的长度。  

  

```
eth.src\[1-2\] == 00:83
```

使用 n-m 格式指定单个范围。在这种情况下，n 是开始偏移量，m 是结束偏移量。  

  

```
eth.src\[:4\] == 00:00:83:00
```

使用了: m 格式，它从序列的开始到偏移 m。相当于0：m。

  

  

```
eth.src\[4:\] == 20:20
```

使用了n: format，从偏移量 n 到序列末尾的所有内容。  

  

```
eth.src\[2\] == 83
```

使用 n 格式指定单个范围。在这种情况下，在偏移量 n 的序列中的元素被选中。这等价于 n: 1。  

  

```

eth.src\[0:3,1-2,:4,4:,2\] ==
```

Wireshark 允许您以逗号分隔列表将单个范围串在一起，从而形成复合范围，如上所示。  

  

3）成员操作符  

Wireshark 允许您在一组值或字段中测试字段的成员身份。在字段名之后，使用 in 运算符，后跟大括号{}包围的集合项。例如，要显示 TCP 源端口或目标端口为80、443或8080的数据包，可以在{80 443 8080}中使用 TCP.port。值集还可以包含 range: tcp.port in {443 4430..4434}。

  

**注意：**  

```
tcp.port in {80 443 8080}
```

相当于  

```
tcp.port == 80 || tcp.port == 443 || tcp.port == 8080
```

但，显示过滤器：

```
tcp.port in {443 4430..4434}
```

并不等同于  

```
tcp.port == 443 || (tcp.port >= 4430 && tcp.port <= 4434)
```

这是因为当任何字段与过滤器匹配时，比较操作符都满足，因此源端口为56789、目的端口为80的数据包也将与第二个过滤器匹配，因为56789 >\= 4430 && 80 <\= 4434为真。相反，成员关系运算符根据范围条件测试单个字段。

  

集合不仅仅局限于数字，其他类型也可以使用:

```


http.request.method in {"HEAD" "GET"}frame.time\_delta in {10 .. 10.5}
![](../Images/51a05c780a325134292f54ac32e87120.png)（无糖反诈宣传图）

```

  
**3、功能**  

1）显示过滤函数

| Function || Description |
| :-- | :-- |
| upper || Converts a string field to uppercase. |
| :-- | :-- |
| lower || Converts a string field to lowercase. |
| len || Returns the byte length of a string or bytes field. |
| count || Returns the number of field occurrences in a frame. |
| string || Converts a non-string field to a string. |

  

upper、lower函数可以用来强制不区分大小写的匹配: lower(http.server) contains “apache”。

  

查找具有长请求 uri 的 HTTP 请求: len (HTTP.request.uri) > 100。注意，len 函数以字节而不是(多字节)字符为单位生成字符串长度。

  

通常一个 IP 帧只有两个地址(源和目的地) ，但在 ICMP 错误或隧道，一个单独的数据包可能包含更多的地址。这些数据包可以在 count (ip.addr) > 2中找到。

  

字符串函数将字段值转换为字符串，适合与“ matches”或“ contains”等操作符一起使用。整数字段被转换为它们的小数。它可以用于 IP/Ethernet 地址(以及其他地址) ，但不能用于字符串或字节字段。

  

例如，匹配奇数帧号码:

string(frame.number) matches "\[13579\]$"

  

为了匹配一组子网中以255结尾的 IP 地址(172.16到172.31) :

```
string(ip.dst) matches "^172\\.(1\[6-9\]|2\[0-9\]|3\[0-1\])\\..{1,3}\\.255"
```

  

**4、！=**  

使用！= 操作符，组合表达式如 eth.addr、 ip.addr、 tcp.port 和 udp.port 可能不会像预期的那样工作。当你使用它时，会显示警告字样”！= “可能会有意想不到的结果”。

  

人们经常使用过滤器字符串，比如 IP.addr = = 1.2.3.4来显示包含 IP 地址1.2.3.4的所有数据包。然后他们使用 ip.addr！= 1.2.3.4期望看到所有包中不包含 IP 地址1.2.3.4。可惜，这并没有达到预期的效果。

  

  

相反，对于源 IP 地址或目标 IP 地址等于1.2.3.4的数据包，这个表达式甚至也是正确的。这是因为表达式 ip.addr！= 1.2.3.4被读作“the packet contains a field named ip.addr with a value different from 1.2.3.4”。由于 IP 数据报同时包含源地址和目标地址，只要两个地址中至少有一个不同于1.2.3.4，表达式就会计算为 true。

  

如果您希望过滤掉所有包含 IP 数据报到或从 IP 地址1.2.3.4的数据包，那么正确的过滤器是！(ip.addr = 1.2.3.4)当它被读取时，“显示所有的数据包，如果名为 ip.addr 的字段的值不是1.2.3.4”，或者换句话说，“过滤掉所有没有出现名为 ip.addr 的字段的数据包，如果该字段的值不是1.2.3.4”。

  

**5、字段改名**

随着协议的发展，它们有时会更改名称或被更新的标准所取代。例如，DHCP 扩展并大量取代了 BOOTP，TLS 取代了 SSL。如果一个协议解析器最初使用协议的旧名称和字段，Wireshark 开发团队可能会更新它以使用新的名称和字段。在这种情况下，他们将从旧的协议名添加到新的协议名，以便更容易地进行转换。

  

例如，DHCP 解析器最初是为BOOTP协议开发的，但是在 Wireshark 3.0中，所有的“BOOTP”显示过滤器字段都被重命名为等价的“DHCP”。你仍然可以暂时使用旧的过滤器名称，例如“bootp.type”等同于“dhcp.type”，但 Wireshark 会在你使用它时显示警告“bootp”已被弃用。将来可能会删除对已弃用字段的支持。
