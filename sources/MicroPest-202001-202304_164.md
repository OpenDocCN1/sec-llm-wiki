    这是一篇老外的文章，介绍了一种通过“Divide and Conquer(分而治之)”绕过“下一代反病毒”（NextGen AV）检测的技术思路。我认为是一种非常有意思的想法，介绍给大家。

原文地址：https://theevilbit.github.io/posts/divide\_and\_conquer/

  

**一、背景**

  

    下一代AV试图检测恶意行为的进程，因此AV会时时刻刻监控恶意软件的活动。很多时候，我们发现meterpreter shell会一直存活到你执行如hashdump或lsass access之类的危险操作时，你的进程被发现并被杀死。

  

主要有以下两种监测方式：

    1. 在内核上的监控，通常Windows不是很友善。对于文件和注册表操作或进程加载，只能执行有限的回调。你不能一般地监视API调用。

  

    2. 由于这些限制，每个AV都会在用户模式下放置钩子，通常在ntdll中，但也会在很多其他地方，常在被恶意软件滥用的API中。AV的DLL是从内核模式强制执行到我们的进程中的，因此我们无法避开它。

  

    总的来说，检测将依赖于监视我们所做的API调用，如果它们符合某种模式，我们将被检测并被杀死。如，最典型的过程注入之一发生在调用以下API调用时：

  

*   OpenProcess
    
*   VirtualAlloc
    
*   WriteProcessMemory 
    
*   CreateRemoteThread 
    

  

    如果我们做这些，我们就死定了。

  

    一个典型的绕过方法是取消用户模式挂钩，或者只是从我们的代码中进行直接系统调用，从而完全避免了ntdll。我们所处理的AV找到了一种方法来检测这些钩子或当我们进行直接系统调用时，因此我们不得不进行调整，于是产生了下文的技术。

  
**二、介绍“分而治之”**  

  

    早在2019年，我是一个红色团队的一部分，我们的日常活动是绕过特定的下一代AV。我有一个叫做“分而治之”的想法。我对此感到非常兴奋，以至于不得不将其命名为:)。

  

    那个时候我不想公开地写它，而且我也没有在互联网上找到任何描述此想法的资源。时间过去了，到我本该写的时候，我忘了。然后几天前，亚当（@Hexacorn）发布了以下内容：

  

    规避概念: 喷射操作产生了一个级联的进程，新实例执行单个原子操作，这可能不足以触发检测并扰乱操作/进程归属。例如: 

  

1 - Spawn Notepad  
2 - Open process handle (pass to child process)  
3 - Allocate buffer in notepad memory, pass handle and address to child process  
4 - Mark it RWX and pass handle and address to child process  
5-N - each instance injecting a few bytes of payload  
N+1 - Triggers payload

  

    他完美地描述了我的所作所为。根据对他的推文的回复，其他人正在默默地做同样的事情。还发现Kyriakos Ispoglou（ispo）和Mathias Payer开发了malWASH（https://github.com/HexHive/malWASH），它以更可扩展的方式进行了操作。那是5年前发布的，所以我想，无论您在InfoSec中做什么，都可能有人曾经做过:)。

  

    因此，我认为是时候发布一些关于我所做工作的细节了。

  
**三、一些想法**  

  

    既然检测依赖于检测进程中的 API 调用，为什么不在多个进程之间拆分 API 调用呢？我们可以通过两个(或更多)步骤向远程进程注入代码。我们根据“恶意软件”它最初得到的输入做不同的事情，下面是我们可以做的，    

  

    1. 首次运行时，我们将调用以下API：

  

*   OpenProcess
    
*   VirtualAlloc
    
*   WriteProcessMemory
    

  

2\. 第二次运行中：

  

*   OpenProcess
    
    (although with handle inheritance I think this call could be eliminated) 
    
*   CreateRemoteThread
    

  

    就是这样。AV会看到两个不同的进程都只进行部分注射，但是没有一个进程可以完成全部。因此，如果有一个涉及多个API调用的操作、并且我们可以拆分它，那我们就胜利了。

  

    由于特定的AV在检测过程注入方面非常强大，因此我对该方法采用了3种不同的注射技术，并且在每种情况下我都设法绕过AV。

  

    我们发现将 API 调用分成两个就足以绕过，但是正如 Adam (@Hexacorn)所述，我们可以做得更疯狂，甚至可以分成更多的 API 调用。
