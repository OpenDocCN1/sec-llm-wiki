# Volatility-GUI做CTF内存取证题

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MjM5NDcxMDQzNA==&mid=2247484749&idx=1&sn=e7d2a4b1bdbe4b62e2fb0c633e24b928&chksm=a682d38091f55a961e143dda1778286b9712ed0f4114822a2bfaceb0eea3f06d5b1ebda2932c&scene=126&sessionid=1681666341#rd](http://mp.weixin.qq.com/s?__biz=MjM5NDcxMDQzNA==&mid=2247484749&idx=1&sn=e7d2a4b1bdbe4b62e2fb0c633e24b928&chksm=a682d38091f55a961e143dda1778286b9712ed0f4114822a2bfaceb0eea3f06d5b1ebda2932c&scene=126&sessionid=1681666341#rd)

    Volatility，内存取证工具，一直以来都很“清高”地以命令行方式“行走江湖”，完全不顾自己“参数众多”这个“爆炸”形象，有种“任我行”的味道，直接影响“我等小白”的用户体验。自2018年作者根据用户需求开发了GUI界面以来，受到了热烈地、广泛地欢迎，最近抽空升级改造，形成了目前的2.0版本。现结合一个CTF的内存取证题来做个功能讲解。

  

**一、程序界面**

![](../Images/08abab4ddeb50d4c2835fc289f253c8d.png)

    一眼看去，界面上功能众多，眼花缭乱。我在这里用“=======”进行功能分层隔离，介绍如下：

  

    1)最上面一是Volatility程序的位置，毕竟作者只是做了个GUI，还是要调用Volatility程序的；二是指定设置了外部插件的位置，可以用python进行定制开发插件。

  

    2)接下来的区域，一是内存镜像文件的位置；二是内存镜像中的操作系统；三是Volatility自带的内部命令参数，作者作了每个命令的中文说明，下拉框中能看到。

  

    3)再接下来的区域，是导出文件类型和导出的文件名。

  

    4)再下来的区域，是以上所有选项、命令的合成区域，将上面所有选择的参数进行组合后形成的命令行，方便查看以及修改、添加命令参数。

  

    5)最下面的是一个结果显示区，将命令执行后的回显结果展示出来。

  

**二、CTF内存取证**  

1、查看内存镜像文件中的操作系统

imageinfo命令，

![](../Images/f9479f3c1ac756e910cfe4f4633f89b7.png)

这个命令可以用来获取内存镜像的摘要信息，比如系统版本，硬件构架等。程序最下面红框处给出了结果，可能为64位的win7sp1x64等。

  

2、pslist命令：

![](../Images/5ab9bdf5790db7cfae9f13aa7c1f7687.png)

pslist可以直接列出运行的进程，如果进程已经结束，会在Exit列显示日期和时间，表明进程已经结束。在这里我们发现有“cmd.exe”。

  

3、cmdscan命令，  

![](../Images/2318e930b6eb6be1385658cf17052894.png)

这个命令是提取内存中保留的cmd命令使用情况。我们发现

存在flag.ccx文件且密码和Administrator密码相同。

  

4、filescan命令，  

![](../Images/aaa1c2110455502a05b65cb3d7f01648.png)

![](../Images/0ea3daef546e88c49258a0307419ac9a.png)

查找得知flag文件地址为0x3e435890。在这里，我们在命令框中手动加入了“ | grep flag”，进行命令行的补充。

  

5、dumpfiles命令，

![](../Images/701740682b4fcc3a24aebc17c29beb87.png)

导出内存中缓存的目标文件，直接导出上面搜索flag得到的flag.ccx文件。

  

6、printkey命令，  

![](../Images/5c9b480494407a7371d4c76211678754.png)

列出SAM表的用户。

  

7、hivelist命令，

![](../Images/743907cac4e745cd5b1e3b2004491a71.png)

获取System和ASM的虚拟地址，

![](../Images/405e7275ea7942d0d3f31b5e87682248.png)

  

8、hashdump命令，获取用户密码的hash值，  

![](../Images/72854741b8dd6c2fc410da6d24a9347d.png)

 -y （注册表 system 的 virtual 地址 ）-s （SAM 的 virtual 地址）。

  

得知Administrator密码的hash值为0d546438b1f4c396753b4fc8c8565d5b。

解码得到ABCabc123

![](../Images/a3bb639a784b5362d14b7836306150d9.png)

  

9、加密磁盘  

![](../Images/520c2fd1ebab8a08b8dd6ac477c51862.png)

在列进程时，发现有个“CnCrypt”的进程，这是个TC的加密磁盘工具。

  

加载那个flag.ccx文件，密码已经知道了，上面有提示，同administrator相同啊。

![](../Images/99ee5dab408eb1b0aaa004c8a6cccdbd.png)

  

  

![](../Images/434c586c628e302da0b50f7df80785fd.png)

得到了flag。
