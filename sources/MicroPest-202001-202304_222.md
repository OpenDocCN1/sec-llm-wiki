# Parent PID (PPID) Spoofing

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MjM5NDcxMDQzNA==&mid=2247484598&idx=1&sn=41169c4176b0ea9b00654292f69c6c0f&chksm=a682d27b91f55b6d8f3e091f05370fff76fb347c0e32ff3ccc0de6842770f509625770769f81&scene=126&sessionid=1681666346#rd](http://mp.weixin.qq.com/s?__biz=MjM5NDcxMDQzNA==&mid=2247484598&idx=1&sn=41169c4176b0ea9b00654292f69c6c0f&chksm=a682d27b91f55b6d8f3e091f05370fff76fb347c0e32ff3ccc0de6842770f509625770769f81&scene=126&sessionid=1681666346#rd)

    安全团队经常通过对父子进程间关系的检测来判断该进程是否存在异常，但是，很多攻击者可以使用Parent PID (PPID) Spoofing这一技术来绕过检测，并允许从任意父进程执行恶意进程。

  

    在过去，攻击者经常能在不被检测到的情况下通过网络，但随着EDR（终端检测和响应）的增加和威胁检测的提升，这种情况出现转变，尤其是对父子进程关联关系的分析，更是成为了检测攻击链的常用技术。

  

    现在最常见的网络传播方式是利用带有恶意宏的文档，当宏触发后，通常会启用新的进程，例如：cmd, PowerShell, regsvr32和certutil等，如winword进程生成rundll32进程的实例，这就很反常。所以，这种行为现在很容易被检测到。

  

    现在，换成这种手法：以预期的父进程（比如Explorer或cmd）启动有效负载。这样当查看父进程时为正常血统，可信度很高。
