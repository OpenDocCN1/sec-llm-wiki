**0x04 攻击内网 **通过之前拿下的web服务器，进行内网攻击  
4.1、使用msf查看当前服务器的网络信息    run get\_local\_subnets  
  

![](../Images/f3fbd0963d0faef8b1b5558856c1c737.png)

  
发现有一个22网段  
4.2、添加到该网络的路由        run autoroute -s 0.0.0.0/0   

![](../Images/75f337432fef8a5450d6f43f113ccd61.png)

  
  
关于路由这里，我个人理解：我的靶机1本身就能访问靶机2，因此这个添加路由，并不是给我的靶机1添加，而是给我msf的这个session添加这个路由。  
遇到的难点：我新开一个msf窗口，发现我居然没有session？！那我正在链接的是什么？经过排查和请教，发现应该是shell的问题，导致于我的新开msf窗口，会算是另外一个新的msf进程，它不会关联到我之前的session，使用session命令不会看到有session。需要我在当前窗口先background退出当前的连接，然后输入session命令才看到。如下图  
4.3、msf起代理    

Msf起socks4a，记住设置的端口

  

![](../Images/837ab3922f542df41b3dc81c47e8ecb9.png)

  

在kali本地文件修改代理配置文件/etc/proxychains.conf

取消注释

![](../Images/c3a3f35839607cca89b5a01d56b3702f.png)

  
    添加代理：

这个地方是因为，msf起了一个socks4的代理，端口为6666，我在kali的配置文件添加这一行，意味着，要是我通过6666的端口进行访问，流量就会通过这个代理走

![](../Images/3a929f4424d99461be588156dbcadda7.png)

  

  

对于这个代理的个人理解：

首先我有一个session，我的路由是添加在这个session上面的，然后我的这些设置都是在我当前的msf进程上面，现在我这个msf进程起了一个代理，那么我的代理也是和之前的设置关联在一起的。通过这个session，我可以访问靶机1，然后通过这个路由，我想要访问靶机2的流量会传到靶机1上面，然后可以通过靶机1去往靶机2.

  

4.4、扫描靶机2 的网段，确定存活主机  

   未添加代理之前，使用portscan模块无法成功扫描一直在进行中，使用arp\_sweep扫描却扫不出靶机2（22.132）

  添加代理后，使用nmap扫描（耗时太久了，我就直接扫靶机了）(使用我们之前开启的代理去扫)

    proxychains nmap -Pn -sT 192.168.22.132 -p1-1000

  

![](../Images/a1103c2d573feb667cdc2d4d685ad61b.png)

  

4.5、访问该主机

在浏览器设置代理为之前在代理配置文件/etc/proxychains.conf的配置  
然后访问靶机2 的IP。
