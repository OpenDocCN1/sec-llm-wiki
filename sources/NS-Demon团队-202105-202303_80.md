需要注意的是，爬虫过程中在百度搜索页面这里出现的 url 都是经过百度加密过的url。比如：

因此还需要我们进行解密，解密的方法是点击搜索页面中所对应的 url 即可，比如：

![](../Images/4b0aa5dff64eadba174223df9d582e3f.png)

发现点击之后，url 就变成正常的 url 了。

如果我们细心点击 url 的时候，还会发现有时候的一些搜索结果并不符合我们的搜索语法，比如说我在搜索inurl:"?uid="的时候，他经常会有些不包含参数的 url，因此我们在爬虫时，考虑到效率，还要对这些 url 进行特殊处理，不能与包含参数的 url 存放在一起。

  

综合上面几点，我们写的 url 爬虫脚本必须要访问 url 之后再获取解密后的 url，并且还要对不包含参数的 url 进行特殊处理。

  

以上就是我编写爬取 SQL 注入点的爬虫脚本思路，根据此爬虫我爬取到了一两千条的数据，并且通过

**https://github.com/Martin2877/sqlmapapi-M**

批量化验证 SQL 注入的工具实现了自动化验证，最终有 43 个 SQL 注入漏洞，其中只有 6 个漏洞是重复的。由此可见现在的 SQL 注入漏洞是越来越少了，当然也有可能是因为我使用的是百度搜索引擎进行挖掘，如果要是换成其他搜索引擎的话应该会好很多，考虑到 SQL 注入漏洞一般都是高危漏洞只有极少部分下才会是中危漏洞，因此推荐在空闲的时候进行挂机挖掘。

  

二、挖掘身份证信息泄露

  

挖掘身份证信息泄露使用到最多的语法是 filetype:xls，我们在这个语法的基础上再添加一些其他的语法就能获取更多的 url，比如说 filetype:xls intext:"学" 身份证。我挖掘身份证信息泄露漏洞的时候是手工的，因此我这里是采用谷歌语法进行搜索，即使有人工验证也不怕。

![](../Images/e60f1e9891edd26e4b5b423266ae2d54.png)

挖掘身份证信息泄露的优点是比较无脑的，不需要任何编程技术也可以做到，但缺点是漏洞盒子审核信息泄露的时候太慢了，差不多半个月才会审阅信息泄露漏洞，因此只推荐前期的时候进行挖掘，不推荐在后期进行挖掘，不然很有可能导致信息泄露的分数变为下个月的分数了，对我们打榜十分不利。

![](../Images/376da6c0fa4efb2c4122df10aba1eab4.png)

  

三、一些心得

  

最后总结一下挖 SRC 需要注意的几点：

1.  注意时间，因为漏洞盒子的审阅速度很慢，靠近月底提交的洞会变成下一个月的分数了，所以建议在上一个月的月底开始提交，持续到本月的月中。
    
2.  持续交洞，挖 SRC 就是拼速度的过程，保持交洞频率，保证在开始审阅漏洞后有持续的分数保证在榜上。
    
3.  如果是零基础，先从简单的开始挖起，慢慢熟练搜索语法，并自己总结出挖洞技巧，学有所成。
