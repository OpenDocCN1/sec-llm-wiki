使用零拷贝提升文件传输速度的方法很简单，在你需要的时候，用 os.sendfile 或 socket.sendfile 发送你的文件就行了。

或者你可以使用一个更高级的库 —— Shutil，这个库是 Python 的标准库，在使用时只需要使用 shutil.copyfile 或 shutil.copytree（复制目录的）就行了。

后面还提到了一个叫 Psutil 的库，这个库实现了很多常用 Linux 命令的功能，如：ps、top、iotop、lsof、netstat、ifconfig、free 等，需要做一些自动化运维操作的时候，就不需要自己调用并解析命令行了，非常方便。

Google SRE 体系核心基础解读 —— 刘征

Elastic 广告，不过神奇的是内容还挺干的，没有全程巴拉巴拉一堆全是自家广告的情况，比上海场的《分层次构建应用系统的可观测性》要好（那一场也是他讲，具体情况请看上次那篇文章）。

内容主要是讲了一下 Google 搞出来的一套叫作 SRE 的体系，中文名叫“网站可靠性工程”，介绍的时候顺便还提到了一本书 —— 《SRE Work Book》。

SRE 是 DevOps 的一个 Class，是一个构建和运行高可靠性系统的、普遍适用的最佳方式。

SRE 主要有三个东西：SLA、SLO、SLI，这次这个演讲主要说的是 SLO 和 SLI。

SLO：SRE 实施策略的核心，专注于跟踪客户的使用体验，是一个目标指标。假如客户是满意的，那么 SLO 就达标了。

SLI：根据某一个服务的类型的特定测量指标，比如 API 可以对应可用性、响应时间、质量（错误率？）。例如：响应时间 200ms。

SLI 的收集策略：比如可用性可以收集 HTTP 状态码，像非 200 状态码的数量之类的。

得到 SLI 数值后，将其转成 SLO 百分位（具体看PPT），然后就可以得到像：“在最近的一个月里，请求 API 时有 90% 的请求是 200ms（平均值）就能返回”这种结论。

然后定义一个 SLO 初始值，比如：产品团队认为，客户能接受的 API 响应时间是 99% 的请求都是 200ms 以内。

接着根据实际监控得到的 SLO，判断是否达到目标。

最后根据 SLO 是否达标 + 发布周期内琐事是否很多（BUG 是否很多） + 客户反馈的满意度是高还是低，决定后面的操作是可以继续快速发版，还是需要先把 BUG 都解决了之类的。

一行代码加速科学计算 —— 解超

介绍了一下数据处理的流程（建议等回放）并吐槽 Pandas 在数据量大的时候实在是太慢了，然后介绍了一波目前流行的数据处理工具。

MB 级：NumPy、Leaun、Matplotlib、Pandas。

TB 级：Hadoop、Dask、Hive、Spark。

MB 级和 TB 级的处理工具之间不能互用，MB 级的工具处理 TB 级会性能过低，TB 级的工具处理 MB 级的又太浪费资源，而 Modin 就是为了解决这种问题而产生的工具。

Modin 在一台 144 核的机器上处理 18GB 的数据时只需要不到 18 秒，但如果使用 Pandas 的话则需要 400 秒。

这是因为 Pandas 只能单核运行，无法利用到多核的性能，但 Modin 可以使用所有的CPU核心，速度自然就快了。

为了方便 Pandas 使用者迁移，Modin 的 API 是模仿 Pandas 设计的，可以直接上手使用，将老代码更换成使用 Modin 也很简单，改个导入的地方就行了，其他的都不用动。

不过简单地概括一下的话，就是：

FPGA 是一种能通过编程、烧录的方式把算法写进芯片里的东西，在 FPGA 中执行的算法时，速度会比用 CPU 快很多（几百倍？没注意听）。

以他们展台的光流 Demo 为例，由于执行速度非常快的关系，使用 FPGA 可以在与树莓派同等大小的开发板上轻松实现实时、高分辨率的效果；如果用树莓派来做的话，不仅分辨率不高，而且视频处理起来还会有一定延迟，无法做到实时（确实如此）。

FPGA 执行算法速度这么快是因为算法的实现非常底层的关系（使用门电路写算法...），好像是需要用一种叫做 RTL 的语言来编写程序才可以，然后因为 RTL 写起来太繁琐了的关系，他们公司就搞了一个叫 Vivado HLS 的工具，可以将C语言代码转换成RTL代码，大大降低了开发时间，不过仍然需要开发者使用硬件设计的思路来写代码（据讲师所说是类似于函数式编程的写法）。

然后在自己写程序时使用 FPGA 来加速原本是一件很麻烦的事情，但是他们公司就搞了一个叫 PYNQ 的 SDK，可以很轻松地调用 FPGA 中的算法（貌似要配合他们的硬件使用），使用时只需要在适当的位置调用一下需要的算法，就可以享受到 FPGA 的加速效果了。

然后他们公司展台用来演示的那块板子貌似是 2000+RMB，陈博士在演讲的时候提到如果想体验一下的话，那块板子是性价比最高的...（玩硬件真烧钱系列）。

内容巨多...然而真的太干了...不太适合 PyCon。

既然提到了 FPGA，那我就干脆扩展一下来讲吧（非讲师演讲内容）：

FPGA 有个兄弟叫作 ASIC，如果了解数字货币矿机的朋友应该知道，目前最好的矿机都是ASIC 矿机，而不是 GPU/CPU 矿机，原因是 ASIC 这种定制的芯片要比 GPU 快很多，而且耗电也比 GPU 低很多，至于 CPU...那就更不用说了。

那么为什么矿机没有用 FPGA 呢？其实是因为 FPGA 相当于是 ASIC 的 DEMO 版本，你可以在 FPGA 上搞一些你需要用上的算法，但是到了生产环境（量大了）还是做成 ASIC 比较划算，因为 ASIC 的性能比 FPGA 要高，并且大批量制造时的成本比 FPGA 要低。

不过 ASIC 也是有缺点的，它被制造出来之后就不能再更改里面的算法了。就是因为这个原因，之前 BCH 和 BSV 闹分叉的时候才会有那么多人说矿机要废了，毕竟挖矿需要的算法一改，芯片里的又没法改的话，机器就跟报废了一样，损失极大。
