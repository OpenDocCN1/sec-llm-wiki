RE题目



由于前几次的空指针题目太难了，所以这次出了一道较为简单的题（要不然每次都0解太难看了// 向期待高难度赛题的选手们说一声抱歉，你们可以期待一下今年的N1CTF~
这个程序实现的功能为从一张图的0结点出发，向它的每一个相连的结点进行DFS，每到一个新的结点就再开启一个线程继续DFS，并记录下当前的路径长度，直到走到最后一个结点时判断当前长度是否小于最小长度，若是则更新最小长度。
不难看出这就是一个典型的使用DFS求最短路径问题，但是路径数量很多，DFS复杂度较高，而且多线程存在竞争，导致原程序几乎不可能跑出正确的结果，所以把最短路算法重新实现一遍就行了。
此题的图是个DAG，所以可以先进行一次拓扑排序再按序进行松弛操作即可求得最短路径。当然用Dijkstra Floyd SPFA之类的一把梭也行

WEB题目



首先观察题目功能： 
1. 登陆
2. 注册
3. 填写信息
4. 上传、裁剪头像。
经过简单的测试可以发现，登陆、注册、填写信息这几处因为严格的输入限制，基本问题不大。那么就要研究一下头像上传处的功能了。
通过测试，发现上传功能是把头像存到OSS云存储里了，OSS相当于一个第三方数据库，通过API存取数据。通过查阅阿里云OSS文档，我们了解工作原理就可以排除一些测试项。比如这里就不用考虑上传webshell了，即使上传了也是无法被解析的。正常上传头像后要求用户裁剪，这里和正常的裁剪功能不同，没有传递裁剪的坐标等信息。但是注意到有url：http://nu1l-avatar.oss-cn-hangzhou.aliyuncs.com/user-avatar/test?x-oss-process=image/crop,x_51,y_213,w_259,h_146再次查阅文档，了解到OSS不仅提供了存储功能，还提供了一定的数据处理功能，这里使用的就是oss的图片裁剪API。这里提供的功能是前端把裁剪后图片按照oss裁剪API格式拼接好URL后，发送给后端，后端上传到OSS中后返回用户头像的URL。
0x0:猜想功能逻辑
首先整体的功能逻辑大概就是后端获取传入的url，请求URL获取裁剪后的图片，获取到数据后重新上传，同时更新用户头像。
1.parse_url
首先进行一些测试，通过下面两个数据包，我们可以发现后端对url进行了类似如下代码的检查。（下面伪代码）
$host = parse_url($ur)if( ’nu1l-avatar.oss-cn-hangzhou.aliyuncs.com’ in $host[‘host'] )    进行下一步操作else    地址有误内容验证
这里通过以下两个数据包可以得知后端请求url后对数据格式进行了验证。输入url为//nu1l-avatar.oss-cn-hangzhou.aliyuncs.com/../../../../../../../etc/passwd提示格式有误，说明请求了，但格式错误。输入url为data://nu1l-avatar.oss-cn-hangzhou.aliyuncs.com/image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAAC0lEQVQIHWP4DwQACfsD/Qy7W+cAAAAASUVORK5CYII=提示成功，验证我们的猜想，后端进行了格式验证。
2.ext参数
通过修改ext参数，我们可以发现，程序抛出了异常。

这里我们可以推测后端功能的大概伪代码如下：

$host = parse_url($ur)if( ’nu1l-avatar.oss-cn-hangzhou.aliyuncs.com’ in $host[‘host'] )  $target = xxxx . $_POST['ext']if (copy($url, $target))  if (checkFileType(xxxx) == 图片 )      $oss -> upload(xxxx)  else      delete xxxx      格式有误！else地址有误
这里貌似是一个任意文件写的漏洞，通过简单测试，我们发现我们的猜想是正确的。但尝试向默认Web目录写shell，无法成功，可能的原因有路径不对或没有权限。无法获取shell。
但至此我们得到了一个有限条件的任意文件写漏洞！
3.条件竞争
进一步思考，我们可以想到这里大概率会存在条件竞争（Race Condition）。我们可以开启三个线程：
线程1：url输入//nu1l-avatar.oss-cn-hangzhou.aliyuncs.com/../../../../../../../etc/passwd
线程2：url输入data://nu1l-avatar.oss-cn-hangzhou.aliyuncs.com/image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAAC0lEQVQIHWP4DwQACfsD/Qy7W+cAAAAASUVORK5CYII=
线程3：请求自己的头像（http://nu1l-avatar.oss-cn-hangzhou.aliyuncs.com/2c7428db4958221b3dfdc39d62df69ba%3Favatar）如果存在某个时刻，线程2刚好运行到$oss -> upload(xxxx)处，线程1刚好执行copy，把/etc/passwd的内容覆盖了xxxx文件，那么线程2就会把/etc/passwd的内容上传至云存储！测试一下：

至此，我们得到了一个任意文件读漏洞！

4.获取webshell
通过竞争读取源代码、nginx配置文件我们发现，目标项目为单入口，即使写入shell也无法访问。这里通过阅读framework.php，我们可以发现只需向web的Controller目录写入一个符合格式的Controller即可执行，这里不再赘述。
