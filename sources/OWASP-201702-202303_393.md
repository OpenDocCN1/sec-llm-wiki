# 深度好文 | 软件安全与SDLC融合的技术要点

无论是使用敏捷、瀑布或者其他软件开发方法，在软件开发生命周期(SDLC)中保障软件安全可以降低组织的成本。本清单包含了将软件安全与SDLC融合的要点。

**1**定义用户故事和需求时，添加安全性

*   合理表述安全性需求。确保这些需求可以像其他事物一样进行调度和测试。
    
*   如果可能的话，尽量避免表述纯技术类的用户故事。事实证明， 影响客户使用的用户故事内容应当优先交付。
    

**2**调校工具，将工具的默认配置调校最佳状态。

*   执行测试结果处理跟踪，以帮助开发人员修复代码中的错误。
    
*   提供指导培训。一对一的培训基础课题，或对全部人员提供最典型问题的指导。
    
*   使用SAST工具。当开发人员工作时，使用SAST工具检查代码。
    

**3**单元测试期间，覆盖不同的输入情况

*   解决功能性安全问题。 某些安全测试可能适用于上下文，但是其他安全测试则可能适合作为独立测试模块
    

**4**集成测试期间，整合并测试单个软件模块

*   QA团队与安全测试人员共同为棘手的业务逻辑提供测试数据和程序。
    
*   执行模糊测试，以发现跨模块输入。
    
*   运用DAST搜索单独模块，以发现更多的漏洞。
    

**5**验收测试期间，在正常使用场景和意外事件中测试软件

*   测试异常情况中可能妨碍产品业务逻辑的安全漏洞。
    
*   测试攻击者可能会采取的创造性方法。
    
*   在验收测试期间实现DAST以查找运行环境问题。
    
*   执行交互式应用程序安全测试（IAST），以产生比SAST或DAST单独测试更好的结果。
    

**6**整合开发和运营活动，提高生产与合作效率

*   如果测试无法像保证软件业务重要性那样保障安全性，则测试失败。
    
*   通过自动部署的方式来解释安全控制，并将在持续交付过程中融入安全性。
    

**7**后期部署和实时测试期间，识别产品代码和环境配置中的安全问题

*   执行安全扫描，识别产品框架中任何新发现的安全问题。
    
*   扫描基础结构以确认所有模块都已修补，避免出现未修补的漏洞。
    
*   发布一个bug赏金计划，并分类和调查用户报告的问题。
    
*   制定事件响应计划，以至于让团队知道发生安全事件时需要做些什么。
    
*   实施威胁情报计划，使团队能够主动回应新发现影响应用程序和平台的安全问题。
    
*   执行连续持续，以深入了解特定应用程序正在接收的流量类型以及指标，以帮助识别恶意用户的模式。基于此数据实施网络控制，评估、限制或阻止违规IP地址。
