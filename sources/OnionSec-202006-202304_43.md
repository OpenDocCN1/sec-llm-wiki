遇到问题

分析海莲花组织的一例老样本时遇到一个小问题，在发现内存加载执行的恶意文件痕迹时将其从进程内存中dump到本地便于分析，但是之后打开IDA对其进行静态分析时发现出现了很多红色的硬编码地址，这其实是在许多脱壳场景过程中很常见的现象，属于dump文件时重定位表加载过程未得到修复，如果不对其修复，在静态分析将会存在不便，且对dump文件进行动态分析时由于获取不到正确的值而无法调试后续的逻辑。

![](../Images/f72e6b38c16d1e33187d200931da033d.png)

  

  

重定位表背景知识

要对其进行修复，首先还是需要补充重定位表相关的知识，这块互联网上的资料非常丰富。

  

链接器在生成 PE 文件时，它假设执行时 PE 文件会被装载到默认的基地址处，于是将代码和数据的绝对地址都写入到 PE 文件中。如果装载时 PE 文件确实装载到了默认基地址处，就不需要进行重定位；但是，如果转载时 PE 文件装载到了别处，此时文件中的绝对地址就都失效了，因为装载基地址已经改变，代码和数据的实际地址也相应的改变了，这时就需要通过重定位修复绝对地址，使其都能指向正确的位置。

  

对于 EXE 文件，每个文件在执行时都会使用独立的虚拟地址空间，即总是能装载到在默认基地址处，也就不需要重定位信息；但是，同一个虚拟地址空间中可能存在多个 DLL，可能有的 DLL 就会面临默认基地址已经被占用的情况，所以 DLL 需要重定位信息。

对重定位表结构体的描述暂时不详细记录了，有需求的可以进行查询。这里着重提及下重定位的过程，因为这个在实际运用过程中比较重要。

  

重定位过程

利用重定位表定位需要修改的地址，比如在 me.dll 中，重定位表的开头部分如下：

RVA       Data      Description

00005000  00001000  页 RVA        // page RVA = 0x1000

00005004  00000118  重定位块大小 size   

00005008      3013  Type|Offset   //   offset = 0x013

...

由 0x1000+0x013 算出待重定位的数据在文件偏移 0x1013 处，加上默认的 imagebase 就是 0x10001013。如下：

.text:10001012 68 9C 20 00 10        push 1000209C

即，文件偏移 0x1013 处的 1000209C 可能需要重定位。

修改待重定位数据，程序运行后，me.dll 被加载到了 0x633C0000 处：

![](../Images/ad889203145bff742035d874f38592cb.png)

  

计算待重定位修正后的值，然后将修正的值写到待重定位地址处：

计算待重定位数据地址：

(0x10001013 - DefaultImageBase) + ImageBase

即 (0x10001013 - 0x10000000) + 0x633C0000 => 0x633C1013

  

计算待重定位数据修正后的值：

(0x1000209C - DefaultImageBase) + ImageBase

即 (0x1000209C - 0x10000000) + 0x633C0000 => 0x633C209C

最后：\*0x633C1013 = 0x633C209C，查看内存中实际的值：

探究出错原因

以上IDA分析结果出现的红框地址属于在解析PE文件结构时虽然已经经过上述正常重定位的过程，但是由于dump内存数据时由于对重定位表所定位到的数值未根据当前加载的PE镜像基址进行差值修正，导致上述计算结果存在偏差，于是出现了索引的地址超过了实际文件大小的情况，自然引用到的值为无效的值，导致该dump文件实际是无效的PE文件。

  

经过分析当加载基址为0x10000000时通过正常引用值计算对应的偏移时如下，而实际IDA加载后由于本身重定位表所定位的需要修正的值已经存在偏差，导致出现了例如0x1D9E7896地址，明显偏离了原本应当出现的VA地址0x10087864，于是我们可以通过获取到差值，之后对需要定位的数据进行修正，即可使IDA加载分析文件时正常显示对应的值，从而使原本无效的PE文件变成正常的PE文件。

![](../Images/78137b1ef802d6c2006ac11d6f19f82f.png)

![](../Images/7a69fbf1d7a3fb95ad4e78d17f310da7.png)

  

经过上述的探究得到了相应的解决方法，需要在源文件内对每个重定位表索引到的值整体减去0xD960000。

![](../Images/e55df0a729b28f0e31b06891108abf0d.png)
