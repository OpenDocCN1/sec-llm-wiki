近来遇到一个APT组织的攻击样本，不过是x64版本比较蛋疼，本身也遭遇的比较少。采用x64dbg调试的时候遭遇好几次无故区段跳转，而且由于在源样本上调试会经历过几次内存解密加载的过程，最终才会执行后最核心的shellcode。于是为了方便快速分析与后续的效率提升，不如自己编写一个shellcode的loader进行加载调试，这样子也能避免x64dbg的无故异常影响调试，以后再次遇到这类情况可以复用。

  

x86的shellcode与x64的shellcode区别不大，主要是笔者使用的调试工具不同导致会有不同的调试体验，不过作为工具的使用者只能互相体谅下了。

  

一个简单的shellcode的loader其实非常简单，不用考虑免杀等需求，很多病毒木马都会采用这种方式在内存中执行核心shellcode，这里就以最简单理想情况的loader进行编写实现，不过要选择输出的版本为x64架构即可。

  

采用C++或者C编写loader总体来说其实差别不大，这里笔者就采用C++语言实现，**需要注意的是这里只是简单实现，并没有考虑太多文件加载读取例外的情况**。

| #include <windows.h>#include <iostream>#include <shlwapi.h>#pragma comment(linker, "/INCREMENTAL:NO")#pragma comment(lib, "Shlwapi.lib")void shellcode(){       //用于存储当前路径       CHAR szCurrentDirectory\[MAX\_PATH\];       DWORD dwCurDirPathLen;       dwCurDirPathLen = GetCurrentDirectory(MAX\_PATH, szCurrentDirectory);       if (dwCurDirPathLen == 0)       {              std::cout << "获取当前目录错误。\\n";       }       HANDLE hFind;       WIN32\_FIND\_DATA findData;       strcat(szCurrentDirectory, "\\\\\*.\*");       hFind = FindFirstFile(szCurrentDirectory, &findData);       if (hFind == INVALID\_HANDLE\_VALUE)       {              std::cout << "Failed to find first file!\\n";              return;       }       do       {              // 忽略"."和".."两个结果              if (strcmp(findData.cFileName, ".") == 0 ||  strcmp(findData.cFileName, "..") == 0 || StrStr(findData.cFileName, ".exe") != 0)                     continue;              else                     break;       } while (FindNextFile(hFind, &findData));       LPCSTR inFilename = findData.cFileName;       HANDLE inFile = CreateFile(inFilename, GENERIC\_READ, 0, NULL,  OPEN\_EXISTING, FILE\_ATTRIBUTE\_NORMAL, NULL);       int size = GetFileSize(inFile, NULL);       LPVOID Memory = VirtualAlloc(NULL, size, MEM\_COMMIT | MEM\_RESERVE,  PAGE\_EXECUTE\_READWRITE);       DWORD bytesRead = 0;       ReadFile(inFile, Memory, size, &bytesRead, NULL);       ((void(\*)())Memory)();}int main(int argc, char\*\* argv) {       shellcode();       return 0;} |
