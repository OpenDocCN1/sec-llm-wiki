procmon

  

可以查找访问 IP 地址的进程

  

在使用Wireshark 时发现有一些奇怪的网络行为，并且需要找出发起该通信的进程。那么如何办呢？首先启动 procmon并添加以下过滤规则集，这些过滤规则将事件限制为仅具有单个 IP 地址目标的本地发起的网络流量。

  

Operation is TCP Send Include

Operation is UDP Send Include

Path contains -> Include

Event Class is Network Include

  

还有一些需要注意的点，当请求并不频繁的时候，为了捕获并记录到一次网络请求则需要长时间的启动procmon进行监控，这时就会遇到长时间运行会影响性能的问题。

  

**那么如何降低影响性能问题呢？**

  

首先需要删除过滤事件，当 procmon 运行捕获时，它会捕获所有事件。可以创建和应用事件过滤器，但这些过滤器只会隐藏屏幕上的事件；它们不会阻止 procmon 捕获它们。如果打算执行更长时间运行的 procmon 捕获，从Filter菜单中选择Drop Filtered Events总是一个好主意，如下所示。

![](../Images/32f1db2326fca6ca30d0a1d8005eda57.png)

  

一旦选择了Drop Filtered Events项目，procmon 会立即开始丢弃所有已过滤的事件。Procmon 不会在屏幕上显示它们，也不会将它们保存到虚拟内存或日志文件中，删除不需要的事件完全有助于节省资源。

WireShark

  

遇到一个场景，逐一排查发现是一个Windows环境的DNS服务器，然而DNS服务器未记录到终端请求DNS的日志，也就是说发起请求的来源IP我们是未知的，但现在的问题是我们需要定位到最初发起请求的终端地址。

![](../Images/1bbf6f5311e7e41d2322dd3cfbe3ed75.png)

  

问题来了，首先笔者想了一个个办法：

1、我们可以先配置下DNS服务，当然这个前提在于这个驻留的木马会不断的发起网络请求，目的是只要发现来源IP就行了；

2、或者有条件的wireshack抓下包，当然这个的前提也是驻留的木马会不断的发起网络请求；

  

配置DNS服务，主要是要启用下调试日志，短时间看看，因为每隔一小时就会有请求这个域名。当然这个会对服务器造成较大的改动，属于下下策。

https://superuser.com/questions/1229515/windows-dns-server-how-to-find-out-who-made-a-query
