1 归因的疑问

最近checkpoint安全公司发布了一篇文章，其中在归因方面提及了说中文的攻击者，我对这个比较有疑问，对于关联性非常弱的归因证据私下里团队内部可以做出非常多的假设，但是在对外发布时最好是不要轻易去假设而下结论，非常容易误导读者，所以带着疑问去探究结论是否正确而最终写下了这篇文章。


原文报告链接：

https://research.checkpoint.com/2021/uyghurs-a-turkic-ethnic-minority-in-china-targeted-via-fake-foundations/



2 探究过程

摘抄一下关键结论内容：


英文原文

Attribution

Although we were unable to find code or infrastructure similarities to a known threat group, we attribute this activity, with low to medium confidence, to a Chinese-speaking threat actor. When examining the malicious macros in the delivery document, we noticed that some excerpts of the code were identical to VBA code that appeared in multiple Chinese forums, and might have been copied from there directly.


翻译结果

归因

虽然我们无法找到与已知威胁组相似的代码或基础架构，但我们将这一活动（低到中等可信度）归因于说中文的攻击者。在检查交付文档中的恶意宏时，我们注意到部分代码摘录与出现在多个中文论坛中的VBA 代码相同，并且可能是直接从那里复制的。


从上面截图的VBA代码可以简单看出，这是一段获取当前操作系统版本的VBA代码。如果仔细一看，两张图片里代码相似度会非常高，会让人自然而然想到代码也许就是从上述中文站点里摘抄的。然而，我们一开始就不能钻入牛角尖而先入为主，从客观的角度而应该想到这段代码是否存在普遍性？中文站点截图里的代码是否是最初的源头？


带着这两个问题，我从文章的内容往上翻看发现了比较完整的VBA代码截图，而当与出现在中文站点里的代码进行全部比对时会发现，代码确实不一样了，既然代码不一样了，那么是如何确定这是从该站点而复制的代码呢？仔细一对比会发现相似的只有几行代码，所以问题点就出在这几行代码。从这里也可以看出无外乎存在两种结果，假设checkpoint的结论是正确的，那么截图里的代码确实是最初源头，或者说一开始假设就是错误的，截图里的代码并不是最初源头，所以归类到攻击者熟悉的语言是中文就是错误的结论。


中文站点来源：https://www.office-cn.net/access-function/338.mhtml



存在普遍性的代码片段

经过互联网搜索，以下是我找到的相似代码，变量名一致，但并不是从中文站点获取的。

（以下来源英文站点）

Function GetOSVersion ()

strComputer = "."

Set objWMIService = GetObject ("winmgmts:\\" & strComputer & "\root\cimv2")

Set colItems = objWMIService.ExecQuery ("Select * from Win32_OperatingSystem")

For Each objItem in colItems

strOSVersion = objItem.Version

    OSVersion = objItem.Caption

Next

GetOSVersion = OSVersion

End Function


（以下来源中文站点）

Public GetOsVersion() As String

    Dim objWMIService, colItems, objItem, strOSversion As String

    Set objWMIService = GetObject("winmgmts:\\.\root\cimv2")

    Set colItems = objWMIService.ExecQuery("Select * from Win32_OperatingSystem")

    For Each objItem In colItems

        strOSversion = objItem.Version

    Next


虽然通过简单的搜索可以发现很多是中文结果，但是请不要忘了搜索结果会依据搜索人的当前语言环境与地区而适当受影响，不过抛开这些外在因素不论，就从那几句非常相似的VBA代码来看，其实就能发现VB语言获取操作系统版本的代码确实存在很大的普遍性，如果一开始就假设攻击者非常懒而不愿意修改代码则自然会出现上述文章里提及的结论了，但是这种结论太过于脆弱了，从严谨研究的角度不应该随便就定位攻击者熟悉的语言。


再接着举几个例子，例如在发布于2010年的文章里出现的代码就已经存在很大的相似性，其中包括变量名与相关执行的命令，文章来源：http://vbadud.blogspot.com/2010/05/how-to-get-os-version-using-vba.html。




又例如发布于2012年的英文站点里出现的VBA代码，文章来源：https://www.petri.com/forums/topic/desktop-icon-scripts-for-objshortcut-targetpath。





2013年出现的中文站点里的VBA代码，文章来源：http://www.hackdig.com/?03/hack-2178.htm，涉及攻击的恶意文件里就已经存在相似的代码，但请注意这并不是这段代码的出现的最初源头。



2015年出现的俄语站点，文章来源：https://it-blojek.ru/imya-polzovatelya-v-opisanii-kompyutera-v-active-directory/comment-page-1/。



2016年出现在百度知道回答里的VBA代码，回答来源：https://zhidao.baidu.com/question/111642853.html，里面的代码还是存在些许不同的，同样这也并不是出现的最初源头，并不能因为相似就归类到文章里的结论。



又例如搜索结果排名靠前的又一个英文站点里出现的VBA代码，文章来源：https://titanwolf.org/Network/Articles/Article?AID=8b4ad358-39fc-496d-8653-8b60308d7fcf#gsc.tab=0。




3 结论

checkpoint的文章表明攻击活动发生在2020年，2021年也在持续，但是从搜索结果来看，可以发现2013年中文站点就已经有相似的VBA代码了，而该VBA代码随后又被搜索并回溯发现在上述的2012年的英文站点里出现了，所以最初的源头既有可能是出现在英文站点，而由于互联网的开放性，相关转载与复制摘录盛行，自然而然会出现在某一特定语言网页与站点中，比如俄语。加之翻译工具的流行，对于识别与阅读其余语言的难度大大较低，对于攻击者所使用的语言猜测难度大大加大，并且由于国外使用的是谷歌搜索，对于英文搜索的结果会更倾向于排名次序，如果靠前的是中文站点则大大增加了曝光率，所以对于文章中提出从代码层面来源这种证据进行归因攻击者所熟悉的语言自然是不严谨的，所以直接提及并给出假设攻击者是说中文的用户是非常不现实的。


最后，从这一案例也可以了解到，对于关联性非常弱的归因证据私下里内部可以做出非常多的假设，但是在对外发布时最好是不要轻易去假设而下结论，非常容易误导读者。
