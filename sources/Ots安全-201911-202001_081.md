# 核卫星通信

2011年的福岛第一核电站事故导致安全变化，可能对反应堆安全产生有趣的连锁反应。

由于随后断电，洪水期间的遥测损失使对事故的评估变得难以管理。无法获得有关反应堆和相关基础设施状态的关键数据，因此，围堵和补救措施没有达到应有的效果。

  

结果，包括USNRC在内的几个监管机构就“开发简单的自供电遥测设备以允许远程监视关键参数”提出了建议,如果发生事故时，其他用于遥测数据的通信传输被中断，这导致数家工厂运营商将卫星连接性作为备份进行调查。

  

我们认为，这是一个合理的结论。只要卫星终端仍由电池供电并可以运行，就不依赖工厂周围的任何其他通信基础设施。此外，不依赖于可能遭受损坏的第三方陆基基础设施，例如手机信号塔。

  

**卫星通信**

我们已经花费了数年的时间研究海事和航空领域中使用的卫星终端。尽管安全性最近有所改善，但这主要是由于包括我们在内的几名研究人员暴露了一些非常严重的漏洞而导致的。我们在卫星通讯中一直发现什么问题？

  

**一些是配置问题：**

1.  如果您知道正确的搜索词，则可以使用shodan在公共互联网上轻松找到终端
    
2.  具有默认管理员凭据的终端
    
3.  终端公开显示它们已过期和易受攻击的软件版本
    
4.  运营商由于供应商缺乏警报或无法普遍应用OT的“永不中断”的观点而无法应用更新
    
5.  –这也无济于事，许多较旧的OT设备由于缺少可用内存而无法支持更新，这意味着这些更新通常是无用的
    

  

**一些是供应商问题：**

1.  缺乏固件签名，因此可以回滚到较不安全的软件版本或终端
    
2.  Web界面中的漏洞，例如跨站点脚本，缺少SSL / TLS甚至是可爱的管理员帐户登录绕过
    
3.  公开的telnet接口
    
4.  终端本身成为不太敏感的IT网络和更敏感的OT环境之间的“桥梁”
    
5.  甚至存在暴露的漏洞，这些漏洞可能允许终端接管，从而破坏其上行链路连接或更改其传输能力。
    

  

**核通信卫星**

尽管核部门受到严格监管，但对卫星通信和终端硬件的理解并不像更广泛的IT网络安全性那么广泛：

固定在卫星终端中>连接至遥测系统>添加UPS  >随身携带

即使已经进行工作以确保卫星连接被锁定，但可以想象的是，由于核经营者和所涉供应商都缺乏知识，导致了错误。

  

**谁会想到卫星终端具有远程执行代码漏洞和琐碎的管理员帐户漏洞？**

OT与IT安全人员之间的互动通常受到限制；对彼此角色的理解通常也很有限。通过共同努力并为两个网络建立适当的控制措施，可以提高安全性并降低风险。

Satcoms面临着“缩小IT和OT之间的中间鸿沟”的风险。它是谁的设备，谁负责其安全性？即使最初配置正确，谁来负责其持续的安全性？

OT团队首先获得了适当的帮助以确保其安全吗？有人甚至考虑过它的安全性吗？
