# 分析WordPress远程执行代码漏洞CVE-2019-8942和CVE-2019-8943

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzAxMjYyMzkwOA==&mid=2247484134&idx=2&sn=9f7d902ffb7b8d24d4c24994fb64a7fa&chksm=9bae4badacd9c2bb2d7e935cf4b81302665eac1eaffd947d8f4b7c8d8096ff7aae871ea5397e&scene=126&sessionid=1681670248#rd](http://mp.weixin.qq.com/s?__biz=MzAxMjYyMzkwOA==&mid=2247484134&idx=2&sn=9f7d902ffb7b8d24d4c24994fb64a7fa&chksm=9bae4badacd9c2bb2d7e935cf4b81302665eac1eaffd947d8f4b7c8d8096ff7aae871ea5397e&scene=126&sessionid=1681670248#rd)

作者：Suraj Sahu和Jayesh Patel（漏洞研究人员）

凭借其开源，功能丰富且用户友好的内容管理系统（CMS），WordPress 为当今网站的近33％提供了支持。这种受欢迎程度也使他们成为明显的网络犯罪目标。它所可能要做的就是一个漏洞，可以立足于网站的敏感数据。过时的网站或使用不安全的第三方插件或组件可能带来的安全问题可能会使情况更加复杂。

  

在2019年2月19日，RIPS Technologies的Simon Scannell 发表了有关WordPress中可能导致远程代码执行（RCE）的核心漏洞的调查结果。这些已分配为CVE-2019-8942和CVE-2019-8943。简而言之，如果成功利用这些安全漏洞，则可能使具有作者权限的攻击者能够执行超文本预处理程序（PHP）代码并获得完全的系统控制权。受影响的WordPress版本包括版本5（5.0.1之前）和版本4（4.9.9之前）。该漏洞也已经泄露给WordPress的安全团队。

  

这篇博客文章详细说明了这些漏洞的技术细节，尤其是潜在攻击的外观以及为利用脆弱的WordPress网站而添加的参数。

  

**漏洞分析和攻击链**

具有作者特权的攻击者可以将嵌入图像文件中的PHP代码上传到WordPress站点。上传的文件将保存在 wp-content / uploads   文件夹中；该文件的条目也将保存在数据库的postmeta表中。

![](../Images/a3ee7693a580e3f026b14b006c29d80e.png "1577289096377538.png")

图1.屏幕快照显示如何利用CVE-2019-8942

通过利用CVE-2019-8942，攻击者可以将\_wp\_attached\_file  meta\_key（用于检索从数据库保存的值并将其显示）修改为任意值。要利用此漏洞，需要向精心制作的帖子发送编辑请求。良性请求通常在请求中没有文件参数。攻击者提出的请求可以具有文件参数，该参数允许黑客更新\_wp\_attached\_file meta\_key。如图3所示，在数据库表中也可以看到相同的内容。

![](../Images/6a72c2b909950cfb9c53c230a56ae5b7.png "1577289151941567.png")

图2.屏幕截图显示了如何嵌入特制的PHP文件（突出显示）

![](../Images/f814a3d87b44a9bdd33f2c399a9af066.png "1577289168986158.png")

图3.屏幕快照显示了数据库中修改后的文件名（突出显示）

  

WordPress的修补版本（在4.9.9和5.0.1之前）没有检查以验证哪些MetaData字段将通过请求进行更新。攻击者可以利用此优势将\_wp\_attached\_file meta\_key值更新或更改为任意值。

  

在补丁版本中，  在admin / includes / post.php  中添加了新函数  \_wp\_get\_allowed\_postdata（），  以检查是否在编辑 请求中发送了“文件”，“ meta\_input”或“ guid”，并在更新POST请求之前将其删除。图3显示，利用CVE-2019-8942可以使黑客修改数据库中的文件名，类似于遍历路径（例如evil1.jpg？../和../evil1.jpg）。

  

攻击者可以将CVE-2019-8942的利用与另一个漏洞联系起来，这次利用CVE-2019-8943。后者可以使攻击者将上传的文件移动到任意目录，嵌入式PHP代码可以成功执行。

  

图4显示了CVE-2019-8943的含义。在wp\_crop\_image  函数（允许WordPress用户将图像裁剪为给定的大小或分辨率）中，wp-admin / includes / image.php  在保存文件之前不会验证.dst（工程图纸文件）文件路径。

![](../Images/41d7deb597177f7908b67066a58ad028.png "1577289217173479.png")

图4.屏幕截图显示了wp\_crop\_image函数未验证.dst文件路径。图5. wp\_crop\_image函数如何尝试本地访问文件

![](../Images/cad8b5673e0b53eb697a6f166ccc9b6d.png "1577289235279818.png")

在可能的攻击情形中，一旦修改了meta\_key中的文件名，就不会在上载目录中找到该文件（例如，图3中的evil1.jpg？../../ evil1.jpg）。因此，它将回退到wp\_crop\_image函数中的下一个If条件，它将尝试通过URL访问文件。它要求在WordPress站点中安装文件复制插件。该请求将如下所示：

  

hxxps \[：\] // vulenrablewesbite / wp-content / uploads / evil1.jpg？../../ evil1.jpg

  

加载图像时，它将忽略“？”之后的路径，并且图像将成功加载。攻击者将裁剪图像，并在保存时将遵循路径遍历并将其保存在任意目录中。

  

**警告和最佳实践**

修补CVE-2019-8942使CVE-2019-8943无法被利用，因为前者在成功利用后者方面起着至关重要的作用。这是因为\_wp\_attached\_file中的 meta\_key  首先需要更新或修改为路径遍历文件名，然后才能执行嵌入式PHP代码。

  

更重要的是，这些漏洞凸显了开发人员通过设计实践安全性以及管理员采用安全卫生措施以减少其网站的受攻击面的重要性。定期更新CMS或使用虚拟补丁程序来解决尚不可用的补丁程序以及需要不断启动和运行的系统上的漏洞。一致地审查网站及其基础结构或组件以防止可利用的漏洞。强制执行最小特权原则，并禁用或删除过时或易受攻击的插件。
