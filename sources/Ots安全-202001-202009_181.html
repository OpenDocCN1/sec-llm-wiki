利用内存损坏错误-CVE-2020-1362分析

WalletService在上周二的补丁程序中修复了特权提升错误，其中一个错误已分配给CVE-2020-1362。该错误利用服务中的边界错误。在这里，我们分享了利用它的技术。

根本原因分析

我们对以下功能进行了二进制分析walletservice.dll：

  • Wallet::WalletCustomProperty::SetGroup

SetGroup函数将用户控制的数据写入用户控制的偏移量的存储器中。

signed __int64 __fastcall Wallet::WalletCustomProperty::SetGroup(__int64 this, int a2, int a3, int a4)
{
  signed __int64 result; // rax

  result = 0i64;
  if ( a2 == 1 )
  {
    if ( a3 & 0xFFFFFFDF )
      return 0x80070057i64;
  }
  else if ( a3 == 0x20 )
  {
    return 0x80070057i64;
  }
  if ( a4 == -1 )
  {
    *(_DWORD *)(this + 8i64 * a2 + 0x74) = 0;
    *(_DWORD *)(this + 8i64 * a2 + 0x78) = 0x7FFFFFFF;
  }
  else
  {
    *(_DWORD *)(this + 8i64 * a2 + 0x74) = a3;
    *(_DWORD *)(this + 8i64 * a2 + 0x78) = a4;
  }
  return result;
}

我们可以注意到该函数没有检查用户可以控制的偏移量范围。所以这就是漏洞发生的地方。

从超出范围的内存写入WWW（在何处写入）

现在，我们可以超出范围地写入内存。通过观察，我们可以发现在同一类中有一个函数可以设置和获取BSTR：

  • Wallet::WalletCustomProperty::SetLabel

  • Wallet::WalletCustomProperty::GetLabel

因此，我们可以通过oobw轻松修改指向BSTR的指针，以获得读取和写入任何地址的能力。

从WWW到任意代码执行

一旦有了WWW（在哪里写），我们就可以在堆上编写Wallet :: WalletCustomProperty对象的vtable来控制RIP。开始时，我们尝试直接使用oobw对其进行修改，但是我们发现oobw与8个字节不对齐。因此，我们必须使用竞争条件对vtable hijack进行两次写入。但这可能会使漏洞利用变得不稳定。还有其他一些方法可以解决此问题。但是在我们的POC中，我们仅使用另一个信息泄漏漏洞（CVE-2020-1361）泄漏堆地址，并使用www直接写入vtable。顺便说一句，尽管CVE-2020-1361被标记为信息泄漏漏洞，但它实际上可用于实现EOP。以后我们会为它做文章。

我们发现其中的ATL::CComObject<CDXGIAdapter>::`vector deleting destructor功能dxgi.dll可以帮助我们从执行任意功能到执行任意代码。该函数调用该loadlibraryEx函数，并以全局指针作为的第一个参数loadlibraryEx。然后，我们可以通过加载自定义dll来实现任意代码执行。
