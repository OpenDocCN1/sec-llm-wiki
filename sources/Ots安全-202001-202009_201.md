# CVE-2020-8558：Kubernetes本地主机边界绕过漏洞警报

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzAxMjYyMzkwOA==&mid=2247487000&idx=1&sn=55065c7098cc1477f9a6be661113f95e&chksm=9bae4753acd9ce45b23b1d2535e36a056cf36a1bdcea2681aaffb2b816a319d485986b9c2af0&scene=126&sessionid=1681670172#rd](http://mp.weixin.qq.com/s?__biz=MzAxMjYyMzkwOA==&mid=2247487000&idx=1&sn=55065c7098cc1477f9a6be661113f95e&chksm=9bae4753acd9ce45b23b1d2535e36a056cf36a1bdcea2681aaffb2b816a319d485986b9c2af0&scene=126&sessionid=1681670172#rd)

Kubernetes正式发布了风险通知，指出Kubernetes节点设置允许相邻主机绕过本地主机边界。的漏洞数目是CVE-2020-8558，以及脆弱性级别是平台。

  

安全研究人员在kube-proxy中发现了一个安全问题。攻击者可以通过同一LAN或群集节点上的容器访问同一第二层域下相邻节点上的本地TCP / UDP 127.0.0.1。如果未将绑定到该端口的服务设置为用于身份验证，则它将使该服务容易受到攻击。

![](../Images/9c09ca1a223fba1f43c9fad7d30ebdfe.png)

如果出现以下情况，您可能会受到攻击：

*   您正在运行易受攻击的版本（请参见下文）
    
*   您的群集节点在不受信任的主机与节点共享同一第2层域（即相同的LAN）的环境中运行
    
*   您的集群允许不受信任的Pod使用CAP\_NET\_RAW运行容器 （Kubernetes的默认设置是允许此功能）。
    
*   您的节点（或主机网络Pod）运行任何不需要任何进一步身份验证的仅限localhost的服务。要列出可能受影响的服务，请在节点上运行以下命令：
    

*   
*   

```
–  lsof + c 15 -P -n -i4TCP@127.0.0.1 -sTCP：LISTEN–  lsof + c 15 -P -n -i4UDP@127.0.0.1
```

在主节点上，像这样的lsof条目指示API服务器可能正在使用不安全的端口进行侦听：

*   
*   

```
COMMAND        PID  USER FD   TYPE DEVICE SIZE/OFF NODE NAMEkube-apiserver 123  root  7u  IPv4  26799      0t0  TCP 127.0.0.1:8080 (LISTEN)
```

**受影响的版本**

*   kubelet / kube-proxy：v1.18.0-1.18.3
    
*   kubelet / kube-proxy：v1.17.0-1.17.6
    
*   kubelet / kube-proxy：<= 1.16.10
