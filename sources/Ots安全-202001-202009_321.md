最近，国外安全研究人员Andrew Danau偶然发现了在举旗竞赛期间php-fpm组件处理特定请求的错误（CTF：捕获标志）：特定的构造请求可能导致php-fpm处理Nginx + PHP产品组合在Web应用程序开发中占有很高的市场份额，因此该漏洞具有广泛的应用范围。影响范围。

### 漏洞概述

PHP-FPM在特定的Nginx配置中具有任意代码执行漏洞。特别是：  
使用Nginx + PHP-FPM构建的服务器使用nginx.conf类似于以下配置：

```




1   location ~ [^/]\.php(/|$) {
```

Nginx中的fastcgi\_split\_path\_info将在处理存在'\\ n'（％oA）的path\_info时将传递给PHP-FPM的PATH\_INFO保留为空（PATH\_INFO =“），影响键指针的方向，从而导致后续path\_info \[0\]的受控零位置= 0操作。通过构造对特定长度和内容的请求，您可以覆盖特定位置数据，插入特定环境变量并导致generationsCode执行。

### 漏洞分析

首先，分析其补丁：在初始化request\_info结构的静态void init\_request\_info（void）函数中，将大小检查添加到堆积的对象和对象的slen中，以避免意外的指针回溯。

```










































 1    // php-src/sapi/fpm/fpm/fpm_main.c
```

其中

```
















Take http://localhost/info.php/test?a=b for example
```

  

可见，当PATH\_INFO为空时，path\_info指向长度测试的前向偏移量。然后path\_info \[0\] = 0; 您可以在特定位置将单个字节清零。但是，零的公共位置不会导致RCE，进一步的使用要求特定的控制位置为零，这恰好控制着写入位置。这是request-> env- > data-> pos位于。这里您需要解释每个变量的存储方式。

通过fastcgi协议传递的每个环境变量都存储在fcgi\_request-> env结构中，该结构定义如下：

```













































 1    // php-src/sapi/fpm/fpm/fastcgi.c
```

其中，我们专注于get / set操作，其实现方式如下：

```















































































 1    static char *fcgi_hash_get(fcgi_hash *h, unsigned int hash_value, char *var, unsigned int var_len, unsigned int *val_len)
```

  

由此，我们可以得出结论，request-> env-> data-> pos的方向直接影响我们的环境变量Key（在其中写入Value），并且只要我们控制char \* pos的方向，我们可能会覆盖现有的数据。但是，要实现RCE，存在以下要求和限制：

1.  指针向前受当前fcgi\_hash\_seg空间结构的影响。太短的char \* pos不能为零，并且太长的char \* pos被分配给新的fcgi\_hash\_seg空间。（传递“ like” http://127.0.0.1/Somefile\_exits/AAAAA.php/也会导致指向向后移动）
    
2.  path\_info \[0\] = 0只能将单个字节（最好是最低位）清零，否则将导致过多的指针位置偏移。
    
3.  鉴于条件2应该以最小的0位覆盖，然后是合格的可覆盖环境变量。
    
4.  覆盖的位置环境变量的键必须与预期要写入的键相同：要读取的var，hash\_value和var\_len。
    
5.  当执行FCGI\_PUTENV（请求，'ORIG\_PATH\_INFO'，orig\_path\_info）时，分别写入ORIG\_SCRIPT\_NAME，orig\_script\_name（ORIG\_SCRIPT\_NAME / index.php / PHP\_VALUE \\ nAAAAAA）。
    

因此，我们可以：

1.  通过控制query\_string的长度，path\_info恰好位于新fcgi\_hash\_seg的数据中，此时我们只需要移动8 + 8 + 8 + len（“ PATH\_INFO \\ 0”）+ N = 34 + N以完成对char \* pos的篡改，满足条件1,2的要求。
    
2.  通过自定义http标头，操纵请求标头的长度可将环境变量的预期替代放置在特定位置（0x\_u\_00 + len（“ ORIG\_SCRIPT\_NAME”）+ len（“ /index.php/”）。要求3,5为（在NGINX中，HTTP中的请求标头以“ HTTP\_XXX”的形式传递到PHP-FPM中，然后写入到request-env中）
    
3.  Exp作者提供了EBUT，这是一个自定义标头，其环境变量名称HTTP\_EBUT的长度和hash\_value等于PHP\_VALUE，在后续处理中将尝试读取PHP\_VALUE（ini = FCGI\_GETENV（请求，'PHP\_VALUE'）；条件4下的要求是遇见。

### 漏洞利用

Exp作者使用PHP\_VALUE将多个环境变量传递给PHP，从而导致PHP产生错误，将Web Shell作为错误日志输出到/ tmp / a，并通过auto\_prepend\_file在/ tmp / a中自动执行恶意代码以实现getshell。

```










 1    var chain = []string{
```

### 影响范围

使用前面提到的配置，此漏洞影响以下版本的PHP：  
7.1.x <7.1.33   
7.2.x <7.2.24   
7.3.x <7.3.11

### 错误修复

可以通过向Nginx添加配置try\_files％uri = 404php来设置cgi.fix\_pathinfo = 0选项，以暂时避免漏洞影响。您还可以选择使用正式发布的更新进行全面修复。
