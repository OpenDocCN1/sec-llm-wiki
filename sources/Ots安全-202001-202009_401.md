# 在线编码平台中的安全风险

**在线编码平台的威胁建模**

在选择云集成开发环境（IDE）之前，您（即开发人员）通常需要将所需的一切下载和/或安装到自己的工作站上。但是，随着DevOps的发展和云计算使用量的增加，您现在也可以在线进行编码。方便，是的，但是在线IDE安全吗？为了回答这个问题，我们将专注于两个流行的基于云的IDE：AWS Cloud9和Visual Studio Online。

  

在在线编码中，IDE呈现在浏览器内部，浏览器JavaScript引擎使用WebSocket在后台启动与链接设备\[例如虚拟专用服务器（VPS）\]的SSH（安全外壳）连接，从而为您提供熟悉的终端执行命令的界面。该环境（即链接的云VM / VPS或SSH可访问的设备）包括工具配置（例如包含哪些令牌或云配置文件），源代码的副本，编译器以及您要使用的其他工具。

![](../Images/9d08000a792b977965b31c5d6f0faf55.png "1583658443954114.png")

图1.本地与基于云的IDE

本地和基于云的编码平台之间的区别在于大部分环境都位于其中。在云IDE中，环境是云提供商内部的虚拟机实例。在安全性方面，这意味着您将信任委托给云提供商，但您有责任防止打开“后门”或将错误配置问题引入虚拟机。如果将自己的设备与AWS Cloud9结合使用，则您有责任安全地配置设备。

**链接的设备/ VM并不总是安全的**

问题是后端上正在运行什么。如前所述，要使用这些在线编码平台，必须有一个SSH链接的设备。对于Visual Studio Online（在撰写本文时仍处于预览模式），我们可以找到在计算机上运行的   Visual Studio（VS）代码服务器。

![](../Images/5377b79698d2d746653a7a91b3104569.png "1583658712114212.png")

图4.链接的VM内部的vscode-remote示例

代码服务器本身是您的浏览器将连接到的Node.js应用程序。您还可以下载整个〜/ .vscode-remote文件夹，然后在本地环境中运行服务器。

  

值得注意的是，作为链接设备的所有者，您有权升级自己的root用户并安装或配置所需的任何东西。默认情况下，您还预先安装了Docker和Git。

  

对于由AWS托管的Cloud9，情况要复杂一些。平台通信所需的后端位于链接的设备内部，而前端仍托管在其他位置。但是像在VS中一样，您也可以提升自己的扎根能力。

![](../Images/7e4301e7b26fdde63293fce6f54d1a8e.png "1583658736807750.png")

图5. Cloud9根终端访问

这使我们想到了第一个安全问题：链接的设备/ VM有多安全？链接的设备包含机密信息-访问令牌，应用程序配置，源代码等。不用说，应该保护它们免受未经授权的访问。

![](../Images/23a86e478a274ddcd46c56242117957b.png "1583658761992376.png")

图6.平台机密信息示例

默认情况下，平台由提供商保护。但是，请记住，与您的根访问权限一起，您还应负责防止配置错误，尤其是在使用第三方插件时。AWS不为非他们开发的插件提供插件支持。

  

您可能会进行可能的错误配置，从而导致安全问题，例如，如果您将IDE设置为可从外部访问，则是出于有意共享的目的，或者是出于无意的目的。另外，将访问令牌存储在加密令牌库中并不常见。通过明文配置文件可以查看其中的许多内容。如果没有其他安全措施，您的访问令牌最终可能会暴露给外部人员。

  

一旦网络犯罪分子获得了未经授权的访问，他们就可以利用自己的利益来破坏您的代码（例如，针对使用恶意软件修改软件更新的软件公司的供应链攻击）。

  

**浏览器可能引入恶意扩展或漏洞**

下一个安全问题是浏览器本身。由于可以从Web浏览器访问在线编码平台，因此从公用，非域，共享或不受保护的计算机访问这些站点时，应格外小心。

  

恶意的浏览器扩展是一种众所周知的现象。尽管可能被恶意软件感染的不受信任的计算机存在明显的风险，但我们还通过PoC（概念证明）通过实验证实了攻击者可能使用恶意Web浏览器扩展来窃取代码。

![](../Images/a96dca8c671090b9da4bce9a31df8734.png "1583658801434880.png")

图7.恶意浏览器扩展PoC发送的数据示例

**代码扩展和插件也可能包含恶意软件**

Visual Studio Online（通常是VS Code平台）的主要优点是可用扩展的数量。但是，这本身就是另一个可能的攻击面。

  

让我们想象一下一个恶意的VS Code扩展，它是具有嵌入式后门的有用外观扩展。在安装或使用过程中缺少对扩展名的权限检查（例如磁盘访问，网络访问，进程访问等）成为一个安全问题。扩展发布期间的安全检查范围仅限于具有有效的PublisherId和一些与图像有关的限制。因此，基本上，您必须完全信任扩展开发人员。

![](../Images/da253bcde133f316b1f0c42eab189639.png "1583658829814750.png")

图8.我们的恶意VS Code扩展说明

安装VS Code平台扩展时，有两种选择：（1）在VS Code扩展市场中找到它，或（2）从.vsix文件安装。

为了演示，我们创建了一个包含反向外壳功能的自定义恶意扩展PoC。

![](../Images/496f4310a8b3da7d7b6afb193a3c9450.png "1583658859939446.png")

图9.我们的恶意VS Code扩展说明的示例

开发VS Code扩展时，存在一些限制。但是，对于扩展产生新进程没有任何限制或担心。

知道了这一点，我们确认在安装恶意扩展并加载环境时可以执行反向Shell。像这样的情况在链接的VM下为攻击者提供了具有根权限的完全远程代码执行（RCE）功能。请注意，当开发人员关闭VS Online网页时，连接将终止。

![](../Images/e91b3b5aafe78ee410ed816a772fd58c.png "1583658885575627.png")

图10. Visual Studio Online平台内的生成的反向shell

  

经验表明，即使主要或核心软件代码是安全的，社区或第三方开发的插件也可能会引入漏洞，从而破坏软件的整体安全性。

  

没有软件应用程序没有错误

还必须考虑各种软件中存在的漏洞的可能性。对于在线编码平台，由于IDE是Web应用程序，因此它们可能会受到Web类漏洞的影响。例如，允许攻击者执行自己的JavaScript代码的漏洞可以控制IDE或远程链接的设备。

  

最近一个影响Visual Studio Live Share扩展的漏洞（也可用于VS Code）显示，我们可以期待在不久的将来看到另一个影响在线编码平台的漏洞。

  

确保云IDE安全是DevOps的必备条件

威胁建模使我们能够了解可能影响计算环境整体安全性的各种因素。Cloud IDE应当与其他软件没有什么不同，即使对安全性而言更为重要。以下是针对我们提出的每个安全问题的一些建议：

*   为了确保链接的设备安全 -安装值得信赖的软件。保持该软件更新。不要随意打开互联网端口。
    
*   对于浏览器 -在受信任和安全的环境中工作。尝试避免使用共享计算机。仅安装来自受信任供应商的浏览器扩展。
    
*   对于VS Code扩展名 -避免安装来自未知来源或作者的扩展名。
    
*   对于一般漏洞 —确保您的环境已更新到最新版本。
