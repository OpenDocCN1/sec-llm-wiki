# 修补Tomcat和JBoss实例以缓解新的高风险GhostCat漏洞

*   这个新发现的漏洞可能允许恶意攻击者接管未打补丁的系统。 
    
*   漏洞跟踪为CVE-2020-1938。
    

![](../Images/2c83bdff773dac259c895ddbe71c4f05.png)

过去13年中发布的Apache Tomcat服务器容易受到名为GhostCat的高风险漏洞的攻击。这个新发现的漏洞可能允许恶意攻击者接管未打补丁的系统。

  

**关于缺陷**

由中国网络安全公司Chaitin Tech发现的GhostCat是Tomcat AJP协议中的缺陷。漏洞跟踪为CVE-2020-1938。

  

GhostCat漏洞可以使远程攻击者读取易受攻击的Web服务器或Servlet容器上任何文件的内容，并获取敏感的配置文件或源代码。如果服务器允许文件上传，则该漏洞也可以被利用来执行代码。

  

“由于Tomcat AJP协议存在缺陷，攻击者可以读取或包含Tomcat的webapp目录中的任何文件。例如，攻击者可以读取WebApp配置文件或源代码。此外，如果目标Web应用程序具有文件上传功能，则攻击者可能通过利用Ghostcat漏洞利用文件包含功能在目标主机上执行恶意代码，”研究人员在博客中解释道。

  

**哪些版本受到影响？**

GhostCat漏洞影响所有6.x，7.x，8.x和9.x Tomcat分支。如果启用了AJP连接器并且攻击者可以访问AJP连接器服务端口，则可以利用此缺陷。

  

**如何解决？**

Apache Tomcat已发布版本9.0.31、8.5.51和7.0.100来修复此漏洞。为了正确修复此漏洞，必须首先确定在其服务器环境中是否使用了Tomcat AJP Connector服务。
