Zimbra - 一项针对拥有约 200,000 家企业的全球企业的网络邮件解决方案计划，其中包含两个漏洞，如果合作，威胁参与者可以未经授权访问 Zimbra 的网络邮件服务器。


如果任何用户打开恶意电子邮件，攻击者在云环境中运行时可能会不受限制地访问整个邮件服务器。这两个漏洞中的第一个是跨站点脚本( XSS ) 漏洞，其编号为CVE-2021-35208，能够使用其 JavaScript 负载访问受害者的所有电子邮件和 Web 会话。第二个是服务器端请求伪造( SSRF ) 漏洞，跟踪为CVE-2021-35209，可以与第一个集成以从云框架中提取CVE-2021-35209。

SonarSource 的安全研究员Simon Scannell首先确定了这些漏洞，并报告了两者之间的联系。SSRF 漏洞可以通过属于受害组织成员的经过身份验证的帐户启动。


Scannell报告说“第二个漏洞允许攻击者向任意主机或端口发送 HTTP 请求。” 他还补充说：“结合协议走私，这可能导致RCE。它还可能使攻击者窃取高度敏感的元数据，例如与可能被利用的实例关联的帐户的访问令牌。”

这两个漏洞在 CVSSv3 等级中都被评为中等严重性。Scannell 表示，“这两个漏洞都适用于默认配置并影响Zimbra核心。Zimbra的网站称，他们的解决方案已被超过 200,000 家企业使用，这些企业可能会成为这些漏洞的目标。”


根据Scannell在其博客中提到的时间线，SonarSource于2021年5月19日联系Zimbra并交换了PGP密钥。经过一番努力，Zimbra于28日发布了针对这两个漏洞（8.8.15和9.0系列）的安全补丁。2021 年 6 月。


CVE-2021-35208（CVSS 分数：5.4）：ZmMailMsgView.java 中存储的 XSS 漏洞

CVE-2021-35209（CVSS 评分：6.1）：代理 Servlet 开放重定向漏洞


SSRF 攻击可以通过禁用 HTTP 请求处理程序跟随重定向来缓解，而 XSS 漏洞可以通过丢弃转换表单标签的代码来修复。


一个类似的 SSRF 漏洞被用来破坏美国银行资本，导致该公司在 2019 年被罚款 8000 万美元。Scannell 表示，“在云原生应用程序中，攻击者可以利用 SSRF 漏洞作为进入云 基础设施内部网络的入口。它可能导致敏感信息的泄露，例如与目标实例关联的云托管帐户的访问密钥。”
