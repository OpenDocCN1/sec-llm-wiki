介绍

Microsoft Windows 图形设备接口+，也称为 GDI+，允许各种应用程序在视频显示器和打印机上使用不同的图形功能。Windows 应用程序不直接访问设备驱动程序等图形硬件，但它们与 GDI 交互，然后 GDI 又与设备驱动程序交互。这样，就有了一个 Windows 应用程序的抽象层和一组通用的 API 供所有人使用。


由于其格式复杂，GDI+ 有各种漏洞的已知历史。我们 McAfee 不断地模糊测试各种开源和闭源软件，包括 Windows GDI+。在过去几年中，我们向 Microsoft 报告了各种 Windows 组件（包括 GDI+）中的各种问题，并收到了针对它们的 CVE。


在这篇文章中，我们详细分析了我们使用 WinAFL 发现的一个此类漏洞的根本原因分析：CVE-2021-1665 – GDI+ 远程代码执行漏洞。此问题已于 2021 年 1 月作为 Microsoft 补丁的一部分得到修复。

WinAFL 是如何工作的？

WinAFL 使用内存模糊测试的概念。我们需要为 WinAFL 提供一个函数名称。它将在函数开始时保存程序状态，并从语料库中获取一个输入文件，对其进行变异，并将其提供给函数。


它将监视任何新的代码路径或崩溃。如果它找到了一个新的代码路径，它会将新文件视为一个有趣的测试用例，并将其添加到队列中以进行进一步的修改。如果发现任何崩溃，它会将崩溃文件保存在 crashes 文件夹中。

EMF 文件格式：

EMF 也称为增强型元文件格式，用于独立存储图形图像设备。EMF 文件由各种长度可变的记录组成。它可以包含各种图形对象的定义、绘图命令和其他图形属性。

信用：MS EMF 文档。

通常，一个 EMF 文件由以下记录组成：

  1. EMF Header – 这包含有关 EMF 结构的信息。

  2. EMF 记录——这可以是各种可变长度的记录，包含有关图形属性、绘制顺序等的信息。

  3. EMF EOF 记录- 这是 EMF 文件中的最后一条记录。


EMF 文件格式的详细规格可以在 Microsoft 站点的以下 URL 中查看：

https://docs.microsoft.com/en-us/openspecs/windows_protocols/ms-emf/91c257d7-c39d-4a36-9b1f-63e3f73d30ca

执行流程总结：

  1. 在“ Builtline::BuildAllLines”函数内部，有一个while循环，程序在其中分配了0x60字节的内存。然后它调用“ Builtline::BuiltLine”

  2. 该“Builtline :: BuiltLine”功能将数据迁移到新分配的内存，然后将其称之为“ BuiltLine :: GetUntrimmedCharacterCount ”。

  3. “ BuiltLine::GetUntrimmedCharacterCount ”的返回值被添加到循环计数器中，即ECX。此过程将重复进行，直到循环计数器 ( ECX ) < 字符串长度 ( EAX )，此处为 0x14。

  4. 循环从 0 开始，因此它应该在0x13 处终止，或者应该在“ GetUntrimmedCharacterCount”的返回值为0时终止。

  5. 但是在易受攻击的DLL 中，由于循环计数器增加的方式，程序不会终止。这里，“ BuiltLine::GetUntrimmedCharacterCount”返回0，它被添加到循环计数器（ECX）并且不会增加ECX值。它分配 0x60 字节的内存并创建另一行，破坏数据，后来导致程序崩溃。循环执行了21次而不是20次。
