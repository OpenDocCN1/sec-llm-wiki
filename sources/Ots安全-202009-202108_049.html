在趋势科技漏洞研究服务漏洞报告的摘录中，趋势科技研究团队的 Kc Udonsi 和 Yazhi Wang 详细介绍了 Cisco HyperFlex HX 数据平台中最近的一个代码执行漏洞。该漏洞最初是由 Positive Technologies 的 Nikita Abramov 和 Mikhail Klyuchnikov 发现的。以下是他们关于 CVE-2021-1497 的文章的一部分，并做了一些最小的修改。


Cisco HyperFlex HX 数据平台是一个高性能、可扩展的分布式文件系统，支持多个虚拟机管理程序，提供广泛的企业级数据管理和优化服务。由于不正确的输入清理，产品中报告了一个远程执行代码漏洞。


未经身份验证的远程攻击者可以通过向目标服务器的基于 Web 的管理界面发送精心设计的请求来利用此漏洞。成功的利用可能会导致在 root 用户的上下文中执行任意代码。思科于 2021 年 5 月修补了此漏洞。


漏洞

Cisco HyperFlex HX 数据平台安装程序使用基于 HTTP 的 Web 控制台。可通过以下地址访问：

https://<server_name>

<server_name>安装 Cisco HyperFlex HX 的机器的名称在哪里。HTTP 是 RFC 7230 - 7237 和其他 RFC 中描述的请求/响应协议。请求由客户端发送到服务器，服务器又将响应发送回客户端。一个 HTTP 请求由一个请求行、各种标头、一个空行和一个可选的消息体组成：

Request = Request-Line headers CRLF [message-body] Request-Line = Method SP Request-URI SP HTTP-Version CRLF Headers = *[Header] Header = Field-Name ":" Field-Value CRLF

其中 CRLF 表示由回车 (CR) 字符后跟换行 (LF) 字符组成的行终止符序列，SP 表示空格字符。参数可以在请求 URI 或消息正文中作为名称-值对从客户端传递到服务器，具体取决于使用的方法和内容类型标头。例如，使用 GET 方法传递名为“param”且值为“1”的参数的简单 HTTP 请求可能如下所示：

GET /my_webapp/mypage.htm?param=1 HTTP/1.1 Host: www.myhost.com

使用POST方法的类似请求可能如下所示：

POST /my_webapp/mypage.htm HTTP/1.1 Host: www.myhost.com Content-Type: application/x-www-form-urlencoded Content-Length: 7 
param=1

如果有多个参数/值对，它们被编码为&-delimited name=value 对：

var1=value1&var2=value2&var3=value3...

远程用户可以向/auth/Cisco HyperFlex HX 服务器的端点提交请求，以便在安装操作之前对自己进行身份验证。以下是提交以/auth/执行系统还原和重新启动操作的请求示例：

POST /auth/ HTTP/1.1 Host: 172.16.20.56:8080 Connection: keep-alive Content-Length: 27 [... truncated for readability ...] 
username=<someName>&password=<somePass>

前端 NGINX 服务器会将 HTTP 请求转发到侦听 TCP/8082 的后端 HTTP 服务器：

location ~ /auth/ {     proxy_pass          http://127.0.0.1:8082;     proxy_set_header    Host $host;     proxy_read_timeout  3600; }

HTTP 服务器是在 ELF 可执行文件中实现的/opt/springpath/auth/auth。当它接收到发送到/auth/端点的 HTTP 请求时，它会调用函数main_loginHandler()来处理请求。该函数将首先/etc/shadow使用usernameHTTP 请求中提供的值从文件行中提取盐值。然后它将调用函数main_validatePassword()来验证用户提供的密码。这个函数最终调用了main_checkHash()函数。为了计算提供的密码的哈希值，此函数使用生成的 Python 代码如下：

 python -c 'import crypt; print crypt.crypt("<somePass>", "<salt>")'

这<somePass>是 HTTP 请求中提供的密码，<salt>是从/etc/shadow文件中提取的值。


这里存在一个 Python 代码注入漏洞。该代码password在使用它生成 Python 代码字符串之前未能正确验证 的值。攻击者可以在password参数值中包含 Python 命令注入字符以注入任意 Python 代码。例如，如下所示的值：

",eval(compile("""__import__('os').popen(r'COMMAND').read()""",'','single'))#

意味着生成的 Python 代码将类似于：

import crypt; print crypt.crypt("",eval(compile("""__import__('os') .popen(r'COMMAND').read()""",'','single'))#", "<salt>")

因此，在调用生成的 Python 代码时将执行OS 命令COMMAND。


未经身份验证的远程攻击者可以通过向目标服务器发送精心设计的请求来利用此漏洞。成功利用可导致在 root 用户的安全上下文中执行任意命令。


结论

思科在 2021 年 5 月修补了这个漏洞。在他们的公告中，他们提到没有解决方法。受影响的客户应应用供应商补丁以确保他们免受此漏洞的影响。
