**文件**

使用 tcache 利用 glibc

*   exploit\_nss.py自动检测 /etc/nsswitch.conf 中的所有要求和条目数
    
*   exploit\_nss\_manual.py简化版的exploit\_nss.py 以便更好地理解漏洞利用
    
*   exploit\_timestamp\_race.c覆盖 def\_timestamp 和竞争条件来修改 /etc/passwd
    

  

在没有 tcache 的情况下利用 glibc

*   exploit\_defaults\_mailer.py漏洞覆盖结构默认修改邮件程序二进制路径。它需要在没有禁用 root-mailer 的情况下编译 sudo，例如 CentOS 6 和 7。
    
*   exploit\_userspec.py该漏洞利用覆盖 struct userspec 以绕过身份验证并在 /etc/passwd 中添加一个新用户。仅支持 sudo 版本 1.8.9-1.8.23。
    
*   用于理解的exploit\_cent7\_userspec.py简化版exploit\_userspec.py 但仅针对具有默认配置的CentOS 7
    
*   exploit\_nss\_d9.py覆盖 Debian 9 上的 struct service\_user 但仅支持默认的 /etc/nsswith.conf
    
*   在 Ubuntu 16.04 上利用exploit\_nss\_u16.py覆盖struct service\_user 但只支持默认的/etc/nsswith.conf
    
*   在 Ubuntu 14.04 上利用exploit\_nss\_u14.py覆盖struct service\_user 但只支持默认的/etc/nsswith.conf
    

  

其他

*   asm/ tinyelf 库和可执行文件，用于嵌入 Python 漏洞利用
    
*   gdb/用于调试 sudo 堆的脚本
    

  

**选择利用**

对于 glibc 支持并启用了 tcache 的 Linux 发行版（CentOS 8、Ubuntu >= 17.10、Debian 10）：

*   首先尝试exploit\_nss.py
    
*   如果错误与 glibc tcache 无关，您可以尝试接下来的exploit\_timestamp\_race.c
    

  

对于 glibc 不支持 tcache 的 Linux 发行版：

  

*   如果目标是 Debian 9、Ubuntu 16.04 或 Ubuntu 14.04，请先尝试特定版本的exploit\_nss\_xxx.py
    
*   接下来，尝试exploit\_defaults\_mailer.py。如果您知道目标 sudo 是使用--disable-root-mailer编译的，则可以跳过此漏洞利用。该漏洞尝试从 sudo 二进制文件中检查根邮件程序标志。但是某些 Linux 发行版上的 sudo 权限是 4711 (-rws--x--x)，这是不可能在目标系统上检查的。（已知的工作操作系统是 CentOS 6 和 7）
    
*   最后，尝试exploit\_userspec.py
