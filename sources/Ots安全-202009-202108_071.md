# 未修补的 Linux 市场漏洞允许蠕虫攻击，路过 RCE

一对影响基于 Pling 的市场的零日可能会允许对毫无戒心的 Linux 爱好者进行一些丑陋的攻击 - 看不到补丁。

  

研究人员发现，一个影响 Linux 市场的未打补丁的存储跨站点脚本 (XSS) 安全漏洞可能允许未经检查的、可蠕虫的供应链攻击。

  

Positive Security 的研究人员发现该漏洞会影响基于 Pling 的市场，包括 AppImage Hub、Gnome-Look、KDE Discover App Store、Pling.com 和 XFCE-Look。

  

为了启动，PlingStore 应用程序受到一个未修补的远程代码执行 (RCE) 漏洞的影响，研究人员表示，该漏洞可以在应用程序运行时从任何网站触发——允许偷渡式攻击。

  

PlingStore是一个安装程序和内容管理应用程序，它充当上述各种提供Linux 软件和插件的站点的综合数字店面。它允许用户直接使用“安装”按钮下载、安装和应用桌面主题、图标主题、壁纸、鼠标光标等。

  

Positive Security 的 Fabian Bräunlein在周二的一篇博客文章中表示，无法联系到 Pling 团队——“这就是为什么我们决定发布这些未修补的漏洞以警告用户，”他说。

  

**可蠕动的 XSS Linux 漏洞**

存储的 XSS 错误首先被发现影响 KDE Discover。存储型 XSS，也称为持久型 XSS，当恶意脚本直接注入易受攻击的 Web 应用程序时就会发生。与反射型 XSS 不同，存储攻击只需要受害者访问受感染的网页。

  

“在创建我自己的列表来测试 Discover 的 URI 处理时，我偶然发现了一个设计上看起来像 XSS 的字段，”Bräunlein 解释说。“虽然简单的 XSS 负载不起作用，但首先添加 iframe，然后在单独的行中添加恶意 JavaScript 负载就足够了。”

  

在 HTML 代码部分添加 XSS 负载后，他发现在访问受影响市场中的恶意列表时可能会触发 XSS。

研究人员警告说，攻击者可以利用该漏洞修改活动列表，或在其他用户的上下文中在基于 Pling 的商店中发布新列表，从而导致可蠕虫的 XSS。

  

“除了典型的 XSS 影响之外，这将允许使用 JavaScript 负载的供应链攻击 XSS 蠕虫执行以下两个步骤：上传他们软件的新（后门）版本；\[并且\] 将受害者列表的元数据更改为自身包含此恶意负载，”他说。

  

Bräunlein 说，从本质上讲，任何可下载的资产都可能受到损害，因此应警告用户，任何受影响市场上的任何列表都可能通过 XSS 劫持用户在平台上的帐户。

  

PlingStore RCE

据 Bräunlein 称，PlingStore 应用程序同时也允许触发 XSS 漏洞——但损害也可以升级到 RCE。那是因为设计的应用程序可以安装其他应用程序，具有在操作系统级别执行代码的内置机制。

  

“事实证明，当 PlingStore 应用程序在后台打开时，任何网站都可以利用这种机制来运行任意本机代码，”他解释道。

  

当应用程序内部触发 XSS 时，payload 可以与本地 WebSocket 服务器建立连接并发送消息以执行任意本机代码（通过下载和执行AppImage 文件）。

  

“当 PlingStore 应用程序启动时，它还会启动 ocs-manager，这是一个本地 WebSocket 服务器，用于侦听来自 \[应用程序\] 的消息，”Bräunlein 解释说。“ocs-manager 实现了各种功能，\[app\] 可以调用这些功能来检索信息或触发操作。”

  

他发现通过组合三个函数调用，可以执行任意代码：

  

调用“ItemHandler::getItem”从任何 URL 下载 AppImage 类型为 bin

调用“ConfigHandler::getAppConfigInstallTypes”泄漏完整的bin目录路径（默认在home目录，因此依赖于用户名）

使用 AppImage 路径作为参数调用“SystemHandler::openUrl”（为 AppImage 文件实现特殊处理以执行它们，而不是使用默认应用程序启动它们）

“浏览器不会为 WebSocket 连接实施同源策略，”Bräunlein 说。“因此，验证源服务器端或通过 WebSocket 连接实施额外的身份验证非常重要。而 ocs-manager 则不是这样，这意味着任何浏览器中的任何网站都可以发起与 WebSocket 服务器的连接，并且 ocs-manager 会很乐意接受任何发送的命令。”

  

研究人员发布了一个概念验证漏洞，表明可以通过在任何浏览器中访问恶意网站来进行攻击。

  

**看不到补丁**

Bräunlein 表示，他在 2 月份首次尝试联系 Pling，但经过数月尝试各种途径（包括发送电子邮件至“联系”地址、支持聊天、致电组织及其首席执行官，以及创建支持论坛帖子），他决定公开披露这些问题。

  

然而，其中一个市场 KDE Discover 立即做出了响应，并在 3 月份发布了补丁和建议。

  

“应用市场处于两个世界的交汇点：用户提供的内容，主要通过网络技术呈现给用户；以及管理和安装本机应用程序，”Bräunlein 总结道。“虽然第 1 位通常被认为是高度不受信任且受到严重沙盒影响的，但 App Store 集成创建了通往第 2 位的桥梁，这是一个需要高度信任的领域。在这种环境下，即使是相对较小的漏洞（例如缺少来源检查）也可能导致严重后果（来自任何浏览器的 RCE，易受攻击的应用程序在后台运行）。此类应用程序的开发人员必须进行高度审查以确保其安全性。”

  

他敦促基于 Pling 的市场的用户避免使用 PlingStore 应用程序，并在问题得到解决之前退出受影响网站的帐户。
