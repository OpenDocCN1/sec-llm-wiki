我喜欢在具有很多功能的应用程序中查找错误。应用程序越复杂，它就越有可能存在错误。

几次前，我有机会在其中一个 Private 中进行 Bug Hunting 活动。在这个程序中，有一个具有各种功能的复杂应用程序。该应用程序的功能之一是`Localization`. 我们可以通过上传`XLIFF`文件来更改应用程序的本地化。

* * *

### **什么是 XLIFF 文件？**

根据维基百科：

> XLIFF（XML 本地化交换文件格式）是一种基于 XML 的双文本格式，旨在标准化本地化过程中工具之间传递本地化数据的方式，也是 CAT 工具交换的通用格式。

如您所见，XLIFF 文件基于 XML。哪里有 XML，哪里就有 XXE 漏洞。

最初的测试是通过添加 XXE 负载并将请求指向 Burp Collaborator。我`parameter entities`用于我的有效载荷，因为`general entities`不起作用，我不知道为什么。

我们可以看到在错误消息中有一个 URL，我们将其放入有效负载中。这可用于获取本地文件的完整内容。

  

可以在@pwnfunction 的精彩视频中查看有关此技术的详细信息：XXE 挑战赛 - Google CTF

https://www.youtube.com/watch?v=0fdpFQXWVu4

  

这个想法是通过获取本地文件并将其内容添加为文件文件名。因为该文件在服务器中不存在，所以服务器将抛出一个错误，文件名是本地文件的内容。

  

最初的测试是通过修改 DTD 来获取non-exist服务器中的文件并检查路径是否反映在错误消息中。

  

DTD文件：

*   
*   
*   
*   

```
<!ENTITY % data SYSTEM "file:///etc/passwd"><!ENTITY % foo "<!ENTITY &#37; xxe SYSTEM 'file:///nofile/'>">%foo;%xxe;
```

服务器响应：

*   

```

```

伟大的！该non-exist文件反映在错误消息中。接下来是添加文件内容。

  

DTD文件：

*   
*   
*   
*   

```
<!ENTITY % data SYSTEM "file:///etc/passwd"><!ENTITY % foo "<!ENTITY &#37; xxe SYSTEM 'file:///nofile/%data;'>">%foo;%xxe;
```

并且文件已成功提取！

![](../Images/558a8ca903cb0365c6fba716aad435a9.png)

该漏洞报告为 P1 严重性，现在已修复。
