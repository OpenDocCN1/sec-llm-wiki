## 介绍

ZX Security 对 Accellion 的 kiteworks 应用程序进行了安全测试。审查是使用 kiteworks 虚拟机 (VM) 的副本以及对客户端预生产实例的访问进行的。

在测试过程中，我们发现了多个问题，这些问题可以组合在一起，以允许 Web 管理员获得对托管 kiteworks 实例的服务器的 root SSH 访问权限。这篇文章概述了这些漏洞的技术细节、如何利用它以及对用户和组织的潜在影响。

帖子中描述的问题已在 7.3.1-ng9 版本中进行了修补，该版本自 2021 年 3 月 4 日起公开可用。

## 什么是Accellion？

Accellion 的 kiteworks 是一个安全的文件共享平台，允许内部和外部用户在任何类型的设备上从任何内容存储共享、发送、同步和编辑文件，从而促进对企业内容源的访问。

## 漏洞搜寻

由于我们提供了一个 VM 来进行测试，因此首要任务是查看我们是否可以从中获取任何源代码以使我们的生活更轻松。结果证明这很容易，因为 kiteworks.vmdk 文件可以直接挂载到我们的主机上。

事实证明，有*很多*齿轮可以让风筝作品滴答作响。有主要的 PHP 网站、一个内部 Python/gunicorn API、一个外部 PHP API、一个 MySQL 数据库、一个 MongoDB 数据库和一个 Python CLI 工具（由 API 和网站调用），仅举几例。完全专注于网站似乎是寻找错误的最简单方法，所以这就是我们采取的方法。

### 获得 SSH 访问

在调查 kiteworks 管理界面时，我们发现有一个选项允许 Accellion（公司）通过 SSH 连接到设备以进行维护。Web 管理员必须首先通过 Web 界面启用此功能，然后将随机生成的“远程管理密码”发送给 Accellion。这种 SSH 访问似乎仅供 Accellion 使用，并且 Accellion 的客户不应该能够访问。下面的屏幕截图显示了一个示例生成的密码：

![](../Images/a8626e542d4b07a40bd0ee8bc795af74.png)

尝试使用此密码通过 SSH 连接到 kiteworks VM 并没有奏效，因此我们需要深入挖掘。通过生成其中一些密码，我们注意到了几种模式。破折号之前的一切似乎都是随机的，而后面的字符则是静止的。在检查源代码后，我们确定“远程管理密码”实际上由两个带连字符的值组成：一个由十个字符组成的随机字母数字字符串，称为*阶段，*以及许可证签名的前 10 个十六进制字符。

但是，我们需要的不仅仅是获得访问权限的*阶段*。源代码确定了 SSH 密码的另一个必要组成部分，称为*filex\_key*。Python CLI 工具表明它来自数据库，但它实际设置的时间有点神秘。

很多兔子洞之后，我们终于找到了这个值的来源：应用程序的许可文件。我们现在可以轻松地从许可证中获取*filex\_key*，只需对文件进行 base64 解码并使用静态密钥`062d21090b89ba04b031b825f2ce7da6`（实际上是嵌入源代码中的 RSA 公钥的哈希值）通过 AES-128-CBC 对其进行解密。按照代码，然后可以通过`sha1_hex(phase + filex_key)[:10]`授予用户*prometheus*访问权限来生成 SSH 密码。下面的屏幕截图显示了从此过程中获得的经过身份验证的 SSH 会话：

![](../Images/c4635e002b337da3b8e82a2c7b2cceae.png)

但是如果攻击者无法访问原始许可证怎么办？

10.  运行该命令`ssh prometheus@<server_ip>`并为其提供上一步生成的密码。
     
11.  观察到使用生成的密码 SSH 登录成功。
     

### **从*****prometheus*****到*****root 的*****权限提升**

在研究 kiteworks 时，我们偶然发现了Shubham Shah在 2016 年在 kiteworks 中发现的一些漏洞\[2\]。CVE-2016-5662 \[3\]的存在让我们认为机器上可能还有其他提权路径。

我们检查的第一件事是运行命令`sudo -l`，它描述了用户可以使用 root 权限运行哪些命令。对于 prometheus 用户，这包括命令`/opt/prometheus/bin/admin.py`. 检查命令的路径，我们注意到该目录`/opt/prometheus`是指向 的符号链接`/home/prometheus/prom-source`，该链接归当前用户所有。这意味着，尽管*bin*文件夹及其内容归 root 所有，但目录本身可以自由重命名或删除。

为了利用此错误配置，将*bin*文件夹重命名为*bin2*并创建一个新的*bin*文件夹。符号链接放置在此文件夹中，名称为*admin.py*，指向`/bin/bash`. `sudo /opt/prometheus/bin/admin.py`然后可以运行该命令，该命令将`/bin/bash`在 root 用户的上下文中执行。这允许用户轻松地将他们的权限提升为 root。以下命令利用了这一点：

## 如何修复

确保安装的 kiteworks 版本为 7.3.1-ng9 或更高版本。阻止对端口 22 的访问也可以缓解这种情况。
