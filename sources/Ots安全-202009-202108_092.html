概括

发现了一个路径注入问题django，如果django.contrib.admindocs启用了该模块，则允许恶意管理员用户披露文件系统上文件的存在。

产品

django

测试版

3.2.2

细节

views.py中有一个不安全的Path连接操作，它允许攻击者提供模板目录 (1) 之外的路径。

class TemplateDetailView(BaseAdminDocsView):    template_name = 'admin_doc/template_detail.html'
    def get_context_data(self, **kwargs):        template = self.kwargs['template']        templates = []        try:            default_engine = Engine.get_default()        except ImproperlyConfigured:            # Non-trivial TEMPLATES settings aren't supported (#24125).            pass        else:            # This doesn't account for template loaders (#24128).            for index, directory in enumerate(default_engine.dirs):                # NOTE(1): `template` is controled by an attacker.                template_file = Path(directory) / template                if template_file.exists():                    # NOTE(2)                    template_contents = template_file.read_text()                else:                    template_contents = ''                templates.append({                    'file': template_file,                    'exists': template_file.exists(),                    'contents': template_contents,                    'order': index,                })        return super().get_context_data(**{            **kwargs,            'name': template,            'templates': templates,        })

通过以管理员身份登录并请求以下页面，攻击者可以检测文件系统中任意文件的存在，在这种情况下，存在/etc/passwd：

http://localhost:8000/admin/doc/templates//etc/passwd/

在（2）中，我们看到文件被读取并将其内容传递给渲染方法。我们找不到显示结果的方法，但更深入地研究这似乎是可取的。

影响

经过身份验证的恶意管理员可以披露任意文件的存在。
