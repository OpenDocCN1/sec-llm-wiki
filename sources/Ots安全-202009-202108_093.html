执行摘要

  • SentinelLabs 在戴尔的固件更新驱动程序中发现了五个影响戴尔台式机、笔记本电脑、笔记本电脑和平板电脑的严重缺陷。

  • 攻击者可能会利用这些漏洞在本地升级到内核模式权限。

  • 自 2009 年以来，戴尔已在全球发布了数亿台 Windows 设备，其中包含易受攻击的驱动程序。

  • SentinelLabs 的调查结果已于 2020 年 12 月 1 日主动报告给戴尔，并被跟踪为 CVE-2021-21551，标记为 CVSS 评分 8.8。

  • 戴尔已向其客户发布了安全更新以解决此漏洞。

  • 目前，SentinelOne 尚未发现野外滥用的证据。

介绍

几个月前，我开始调查固件更新驱动程序版本 2.3 ( dbutil_2_3.sys) 模块的安全状况，该模块似乎至少从 2009 年就开始使用。今天，固件更新驱动程序组件，它负责通过戴尔固件更新Dell Bios Utility 预装在大多数运行 Windows 的戴尔机器上，以及已更新的全新安装的 Windows 机器上。数亿台戴尔设备定期为消费者和企业系统推送更新。

由于 Process Hacker，驱动程序引起了我的注意，它有一个很棒的功能，每次创建或删除服务时都会弹出通知消息：

这导致发现了 12 年未公开的五个高度严重的错误。Dell 软件中的这些多个高严重性漏洞可能允许攻击者将权限从非管理员用户升级到内核模式权限。多年来，戴尔发布了 BIOS 更新实用程序，其中包含适用于全球数亿台计算机（包括台式机、笔记本电脑、笔记本电脑和平板电脑）的易受攻击的驱动程序。

戴尔指定了一个 CVE 来覆盖固件更新驱动程序中的所有缺陷，但这个单个 CVE 可以分解为以下五个单独的缺陷：

  • CVE-2021-21551：本地特权提升 #1 – 内存损坏

  • CVE-2021-21551：本地特权提升 #2 – 内存损坏

  • CVE-2021-21551：本地特权提升 #3 – 缺乏输入验证

  • CVE-2021-21551：本地特权提升 #4 – 缺乏输入验证

  • CVE-2021-21551：拒绝服务 - 代码逻辑问题

在今天的帖子中，我将描述该驱动程序的一些一般问题。但是，为了让戴尔客户有机会修复此漏洞，我们将在 2021 年 6 月 1 日之前拒绝分享我们的概念证明。该概念证明将演示第一个由内存损坏问题引起的本地 EOP。

技术细节

固件更新驱动程序的第一个也是最直接的问题是因为它接受 IOCTL（输入/输出控制）请求而没有任何 ACL 要求。这意味着它可以被非特权用户调用：

允许任何进程与您的驱动程序通信通常是一种不好的做法，因为驱动程序以最高权限运行；因此，某些 IOCTL 功能可能会被“设计”滥用。

针对此漏洞的经典利用技术是覆盖我们要提升其特权的进程内的 Token 特权成员中的Present和值：EnabledEPROCESS

此驱动程序中另一个有趣的漏洞是可以在内核模式下使用任意操作数（LPE #3 和 LPE #4）运行 I/O (IN/OUT) 指令。这不太容易利用，可能需要使用各种创造性技术来实现特权提升。

由于IOPL（I/O权限级别）等于CPL（当前权限级别），显然可以与HDD和GPU等外围设备进行交互，直接对磁盘进行读/写或调用DMA操作。例如，我们可以与 ATA 端口 IO 通信以直接写入磁盘，然后覆盖由特权进程加载的二进制文件。

以下代码说明了使用 ATA 端口 IO 的直接读/写，并展示了如何调用这些 IOCTL（IN/OUT 包装器被抽象化）：

void port_byte_out(unsigned short port, unsigned char payload) {unsigned char data[16] = { 0 };  *((unsigned long *)((unsigned char *)data)) = port;  *((unsigned char *)((unsigned char *)data + 4)) = payload;  bResult = DeviceIoControl(hDevice, IOCTL_BYTE_OUT, data, sizeof(data), data, sizeof(data), &junk, NULL);if (!bResult) {printf("error in port_byte_out: %x\r\n", GetLastError());  }}
unsigned char port_byte_in(unsigned short port) {unsigned char data[16] = { 0 };  *((unsigned long *)((unsigned char *)data)) = port;  bResult = DeviceIoControl(hDevice, IOCTL_BYTE_IN, data, sizeof(data), data, sizeof(data), &junk, NULL);if (!bResult) {printf("error in port_byte_in: %x\r\n", GetLastError());  }return data[0];}

直接写入硬盘而不为该磁盘写入创建 IRP 基本上绕过了操作系统中的所有安全机制，并允许攻击者写入磁盘上的任何扇区。

例如，以下是LearnOS存储库中的代码，它利用 IN/OUT 指令直接写入 HDD：

void write_sectors_ATA_PIO(uint32_t LBA, uint8_t sector_count, uint32_t* bytes) {  ATA_wait_BSY();  port_byte_out(0x1F6,0xE0 | ((LBA >>24) & 0xF));  port_byte_out(0x1F2,sector_count);  port_byte_out(0x1F3, (uint8_t) LBA);  port_byte_out(0x1F4, (uint8_t)(LBA >> 8));  port_byte_out(0x1F5, (uint8_t)(LBA >> 16));   port_byte_out(0x1F7,0x30); //Send the write command
for (int j =0;j<sector_count;j++) {    ATA_wait_BSY();    ATA_wait_DRQ();for(int i=0;i<256;i++) {      port_long_out(0x1F0, bytes[i]);    }  }}

有趣的是，与 IOCTL 处理程序错误无关，驱动程序文件本身位于 中C:\Windows\Temp，这本身也是一个错误，并为其他问题打开了大门。利用此漏洞的经典方法是将任何 BYOVD（自带易受攻击的驱动程序）转换为特权提升漏洞，因为加载（易受攻击的）驱动程序意味着您需要管理员权限，这基本上消除了对漏洞的需求。因此，使用这一边指出的漏洞实际上意味着您可以将任何 BYOVD 提升到特权级别。

影响

高严重性缺陷可能允许计算机上的任何用户，即使没有特权，也可以提升他们的特权并在内核模式下运行代码。此类漏洞的明显滥用包括它们可用于绕过安全产品。

有权访问组织网络的攻击者还可能获得在未打补丁的戴尔系统上执行代码的权限，并利用此漏洞获得本地特权提升。然后攻击者可以利用其他技术转向更广泛的网络，例如横向移动。

修复

Dell 安全咨询 DSA-2021-088中描述了此漏洞及其补救措施。我们建议戴尔企业和消费者客户尽快应用补丁。

虽然戴尔正在发布补丁（一个固定的驱动程序），请注意证书尚未撤销（在撰写本文时）。这不被认为是最佳实践，因为如前所述，易受攻击的驱动程序仍可用于 BYOVD 攻击。请参阅戴尔安全公告以了解完整的修复详细信息。

结论

这些高严重性漏洞自 2009 年以来一直存在于戴尔设备中，影响着全球数亿台设备和数百万用户。与我之前披露的一个隐藏了 12 年的漏洞类似，这可能对未能修补的用户和企业产生深远而重大的影响。

虽然到目前为止，我们还没有看到任何迹象表明这些漏洞已被广泛利用，目前有数亿企业和用户容易受到攻击，但攻击者不可避免地会寻找那些不采取适当行动的人。我们发布这项研究的原因不仅是为了帮助我们的客户，而且是为了帮助社区了解风险并采取行动。

我们要感谢戴尔对我们的披露和修复漏洞的方法。
