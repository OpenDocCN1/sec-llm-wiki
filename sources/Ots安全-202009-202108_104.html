当用户提供的数据以不安全的方式反映到响应头中时，就会出现 HTTP 响应头注入漏洞。

主机标头指定哪个网站或 Web 应用程序应该处理传入的 HTTP 请求。主机头攻击可能，攻击者可以操纵 Web 应用程序看到的主机头，并导致应用程序以意想不到的方式运行。

Host 标头确定 Web 应用程序应处理接近的 HTTP 请求的站点。

它们带来许多风险并诱发各种攻击媒介，即
⦁ 密码重置中毒/邀请功能中毒
⦁ 缓存中毒
⦁ 访问其他内部主机/应用程序
⦁ XSS 等。

TIP

如果网站使用任意主机标头，则客户端可以修改主机标头以包含任何内容。如果然后在应用程序中使用主机标头，这可能会引入安全问题。

攻击场景

⦁ 攻击者通过使用任何恶意站点修改请求中的主机头，向另一个用户发送重置密码请求。
⦁ 用户收到一封用于重置密码的电子邮件，单击该链接并进一步处理恶意链接。
⦁ 通过这种方式，攻击者可以获得任何用户的有效密码重置令牌。

我在 Bugcrowd 平台的一个私有程序中发现了这个漏洞。我开始测试诸如 XSS、CSRF 等漏洞。有趣的是，该应用程序接受任意主机头，因此我决定在密码重置端点上测试缓存中毒。

我已经在下面解释了如何重现主机头注入以毒害密码重置链接并接管帐户。写上去，密码重置页面如下所示。
