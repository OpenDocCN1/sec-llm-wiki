当用户提供的数据以不安全的方式反映到响应头中时，就会出现 HTTP 响应头注入漏洞。

主机标头指定哪个网站或 Web 应用程序应该处理传入的 HTTP 请求。主机头攻击可能，攻击者可以操纵 Web 应用程序看到的主机头，并导致应用程序以意想不到的方式运行。

Host 标头确定 Web 应用程序应处理接近的 HTTP 请求的站点。

它们带来许多风险并诱发各种攻击媒介，即  
⦁ 密码重置中毒/邀请功能中毒  
⦁ 缓存中毒  
⦁ 访问其他内部主机/应用程序  
⦁ XSS 等。

TIP

如果网站使用任意主机标头，则客户端可以修改主机标头以包含任何内容。如果然后在应用程序中使用主机标头，这可能会引入安全问题。

攻击场景

⦁ 攻击者通过使用任何恶意站点修改请求中的主机头，向另一个用户发送重置密码请求。  
⦁ 用户收到一封用于重置密码的电子邮件，单击该链接并进一步处理恶意链接。  
⦁ 通过这种方式，攻击者可以获得任何用户的有效密码重置令牌。

我在 Bugcrowd 平台的一个私有程序中发现了这个漏洞。我开始测试诸如 XSS、CSRF 等漏洞。有趣的是，该应用程序接受任意主机头，因此我决定在密码重置端点上测试缓存中毒。

我已经在下面解释了如何重现主机头注入以毒害密码重置链接并接管帐户。写上去，密码重置页面如下所示。

![](../Images/28be1e0cd6034a8773e9258d0b3ee801.png)

现在，只需输入电子邮件以重置密码并启动 Burp Suite 拦截流量，然后单击重置密码。

![](../Images/8eccdcca0066606c71ec92869638a05b.png)

现在在 Burp Suite 上，捕获请求并将 HTTP Request Header Host 参数从原始 URL 更改为您希望的任何站点。我使用 google.com 作为下面的例子。

现在，当您分析上面的屏幕截图时，Host 标头已更改为恶意站点，转发请求，当请求通过时，就会触发攻击。

包含密码重置链接的电子邮件将发送给用户。

![](../Images/03ab24ef65a5c543a1f43762b728a9a8.png)

如您所见，收到的密码重置链接已发送，其中包含中毒密码重置链接。

![](../Images/882f2fd5ecfa4f05cc286008888cf2e7.png)

这使我能够窃取用户的密码重置令牌。

  

由于明智地报告了此漏洞，我获得了 800 美元的奖励 💰
