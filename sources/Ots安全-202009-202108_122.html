漏洞描述

SwordBytes 研究人员通过滥用“overwolfstore://” URL 处理程序中存在的反射跨站点脚本 (XSS) 问题，在 Overwolf 的客户端应用程序中发现了一个未经身份验证的远程代码执行 (RCE) 漏洞 。该漏洞允许未经身份验证的远程攻击者执行任意通过将XSS问题与Chromium嵌入式框架（CEF）沙箱转义相结合，可以使攻击者有可能在受害者的计算机上实现远程执行代码。

技术说明

Windows应用程序可以向操作系统注册自定义URL方案，从而使它们可以在被调用时运行特定的已安装应用程序。一个常见的示例是通过使用自定义方案（例如，“ overwolfstore：// app /：uid / reviews /：commentId”）导航到URL，从而直接从浏览器中使用此方案。在这种情况下，攻击者可以通过将有效用户重定向到滥用来自 Overwolf 的自定义 URL 处理程序的恶意链接（“overwolfstore://”）来实现这一点。客户端应用程序容易受到跨站点脚本注入攻击，通过滥用后端。


该“overwolfstore：//”自定义方案是由一个注册的内置扩展名为‘Overwolf的Appstore’（UID ojgnfnbjckbpfaciphphehonokbggjhpnnoafack。），这是Overwolf此URL处理器核心部件的一部分，从Web浏览器打开时，调用“ Overwolf Appstore.exe”进程，此行为在Windows注册表中定义，如下所示：

图1 –带有自定义方案“ overwolfstore”的注册表项


请注意，“％1”将替换为URL上提供的值。启动Overwolf Client后，CEF应用程序将继续分析和分析提供的URL以确定应呈现哪个UI。可以触发多个操作, 负责解析 URL 并决定采取哪些动作的代码位于扩展的 JavaScript 源代码中. 特别是以下文件 ( overwolf-extension://ojgnfnbjckbpfaciphphehonokbggjhpnnoaack/scripts/controllers/window.js )管理大部分解析的代码：

    _this.decodeUrlSchemeParams = function (info) {        const decodedUrl = decodeURIComponent(info.parameter);        const url = new URL(decodedUrl);        const urlParts = url.pathname.split('/');        const params = {origin: info.origin};        if (urlParts[2] !== 'app') {        return null;        }
        if (urlParts[3]) {        params.section = urlParts[3];        }
        if (urlParts[4]) {        params.category = urlParts[4];        }
        if (urlParts[5]) {        params.extra = {            id: urlParts[5]        };        }
        return params;    }

在 Scheme 参数解码期间，会从 URL 中检索多个值。这些URL的结构通常如下：

定制方案：
overwolfstore://app/<SECTION>/<CATEGORY>/<EXTRAS>

URL中的不同元素使应用程序可以了解幕后正在调用的功能。但是，对应用程序接受的值没有限制；这使攻击者可以制作不同的有效负载，这些有效负载可能在应用程序上产生意外的结果。


以下各节描述了两个漏洞，这些漏洞操纵Overwolf处理这些自定义URL的方式来实现1-Click远程代码执行。

反射式跨站脚本

当前面描述的 URL的“SECTION”部分等于 “apps”时， Overwolf 客户端使用“CATEGORY”中提供的值向后端生成请求，以尝试获取有关正在调用的扩展的信息。例如，通过访问URL “ overwolfstore：// app / apps / UNEXPECTED_VALUE / 4/5/6”，将生成以下请求：

图2 –请求发送到后端API

请注意，值“UNEXPECTED_VALUE”作为错误消息的一部分反映在响应正文中，并且“Content-Type”设置为 “text/html”。当此响应反映在Overwolf商店UI（本质上是Chromium嵌入式浏览器（CEF））的上下文中时，受控内容将逐字注入DOM中，如下所示：

图 3 – 嵌入到浏览器 DOM 中的错误消息

通过将CATEGORY值的缺乏卫生性与Overwolf Store UI的DOM中反映的后端错误消息相结合，可以在具有以下负载的Overwolf客户端应用程序中触发Reflected Cross-Site脚本漏洞：


概念证明：

overwolfstore://app/apps/<img src=x onerror=alert(document.location)>/4


图 4 – Overwolf 客户端应用程序中触发的反射跨站点脚本

如果识别出CEF沙箱转义，通常可以将CEF应用程序中的跨站点脚本升级为远程代码执行。


逃离CEF沙箱

在这种特殊情况下，SwordBytes 研究人员能够通过使用“ overwolf-extensions:// ”方案在 URL 上下文中使用 Overwolf JavaScript API 来逃脱沙箱。主 CEF 进程“OverwolfBrowser.exe”在启用内部 Overwolf 标志（--ow-enable-features和 --ow-allow-internal）的情况下运行，从而可以调用诸如“ overwolf.utils.openUrlInDefaultBrowser 之类的函数” 2。顾名思义，此方法旨在在默认浏览器（例如 Chrome、Firefox 或其他浏览器）中打开 URL；但是，如果提供了诸如“ calc.exe ”之类的值，则将 调用“ CreateProcess”将被制作，并执行二进制 “ calc.exe ”，允许攻击者运行任意命令：

图 5 – Overwolf 客户端应用程序执行 C:\Windows\System32\calc.exe

所述“openUrlInDefaultBrowser”方法不允许对正在执行的命令提供额外的参数，因此，附加的矢量需要接管正在执行的命令的完全控制。在分析了文档3 中提供的不同 API 方法后，SwordBytes 研究人员发现了该方法“ overwolf.io.writeFileContents” 4。此方法允许用户在Windows文件系统上创建具有任意内容的新文件。通过滥用此功能，可以创建一个新的“ .bat”（批处理）文件，以后可以通过使用前面提到的“ openUrlInDefaultBrowser”方法来执行该文件 。请注意权限“文件系统”需要执行 “ writeFileContents”。但是，在此扩展的清单中，分配了此特权。


概念验证

SwordBytes 研究人员结合本文档中描述的问题构建了最终的漏洞利用程序，可以总结如下：

  1. 受害者打开调用 Overwolf Store 应用程序的 URL 并触发 XSS 负载。


  2. 利用“ writeFileContents”方法将新的批处理文件写入 “ C：\ windows \ temp \”文件夹中的 磁盘中，该文件包含攻击者选择的命令，在本例中为“ start cmd / k whoami”。


  3. 该“openUrlInDefaultBrowser”方法用于执行在上一步中创建.bat文件，实现远程执行代码。


概念证明：

overwolfstore://app/apps/<img+src=x+onerror=%22overwolf.io.writeFileContents('C:\\windows\\temp\\d.bat','start%20cmd%20%252fk%20whoami','',false,console.log)%2526overwolf.utils.openUrlInDefaultBrowser('C:\\windows\\temp\\d.bat')%22>/CCCCCC

请注意，某些值会进行两次 URL 编码，以绕过 CEF 浏览器以及后端服务器的限制。“/”和“&”等值将改变自定义方案的解析方式，以及后端返回的错误消息。因此，“/”和“&”的编码如下：“%252f”和“%2526”。
