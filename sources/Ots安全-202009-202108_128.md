**介绍**

**影响的限制和分析**

此漏洞有一个重要限制，即verify\_urls必须明确禁用该选项。在verify\_urls做以下检查：

*   
*   
*   
*   
*   
*   

```
def sha  unless app.secret    raise CannotGenerateSha  end  OpenSSL::HMAC.hexdigest('SHA256', app.secret, to_unique_s)[0,16]end
```

该变量to\_unique\_s是通过展平用户提供的 base64 编码数组并连接所有字符串而获得的字符串。此代码生成HMAC-SHA256用于验证REST请求的签名。除非可以获取应用程序秘密（即，硬编码的秘密），否则此选项从根本上缓解了此漏洞。

  

虽然不常见，但我们观察到一些 Web 服务器故意禁用此选项，立即使其资产易受攻击。

  

**如何修复**

确保verify\_urls启用了默认的 Dragonfly选项。Dragonfly 还为所有受影响的版本发布了补丁，因此将 Dragonfly Ruby Gem 更新到 1.4.0 或更高版本可以缓解这个问题。
