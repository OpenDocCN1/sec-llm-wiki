CVE-2021-21985 - 漏洞分析

披露日期：

2021 年 5 月 26 日 • （上次更新时间：2021 年 5 月 28 日） ▾


描述

由于在 vCenter Server 中默认启用的 Virtual SAN Health Check 插件中缺少输入验证，vSphere Client (HTML5) 包含一个远程执行代码漏洞。具有网络访问端口443的恶意角色可能会利用此问题在托管vCenter Server的基础操作系统上以不受限制的特权执行命令。


技术分析

威胁状态：即将发生的威胁

攻击者实用程序：网络基础设施受损


描述

2021 年 5 月 25 日星期二，VMware 发布了安全公告 VMSA-2021-0010，其中包含有关 CVE-2021-21985 的详细信息，这是 vCenter Server 和 VMware Cloud Foundation 的 vSphere Client (HTML5) 组件中的一个关键远程代码执行漏洞。该漏洞源于 Virtual SAN 运行状况检查插件中缺少输入验证，该插件在 vCenter Server 中默认启用。成功利用需要网络访问端口 443，并允许攻击者在托管 vCenter Server 的底层操作系统上以不受限制的特权执行命令。CVE-2021-21985 的 CVSSv3 基本得分为 9.8。


VMware 发布了一篇关于 VMSA-2021-0010的博客文章和补充常见问题解答，其中强调了勒索软件的威胁加剧，包括针对运行 vCenter Server 的组织。截至 2021 年 5 月 26 日，没有关于野外剥削的报告——但是，这种情况不太可能持续下去。


受影响的产品

  • vCenter Server 6.5

  • vCenter Server 6.7

  • vCenter Server 7.0

  • 云基础（vCenter 服务器）3.x

  • 云基础（vCenter 服务器）4.x

有关固定版本的信息，请参阅 VMware 公告中受影响产品和更新的矩阵：https : //www.vmware.com/security/advisories/VMSA-2021-0010.html


Rapid7 分析

与之前的 vCenter Server 漏洞一样，我们将 CVE-2021-21985 归类为迫在眉睫的威胁：它是高级和商品威胁参与者的高价值攻击目标，我们预计漏洞利用会迅速大规模发生。截至 2021 年 5 月 26 日，Rapid7 Labs 确定了大约 6,000 个暴露于公共 Internet 的 vCenter Server 实例。

Virtual SAN 运行状况检查插件的默认日志位置是/var/log/vmware/vsan-health. 并且用户可以通过修改logdir下配置文件中的配置项“ ”来更改/usr/lib/vmware-vpx/vsan-health。在适用于 Windows 的 vCenter Server 上，该文件位于%VMWARE_LOG_DIR%\vsan-health. 日志文件中未记录安全相关信息。

  • https://www.vmware.com/content/dam/digitalmarketing/vmware/en/pdf/products/products/vsan/vmw-gdl-vsan-health-check.pdf


vCenter Server 日志放置在磁盘上的不同目录中，具体取决于 vCenter Server 版本和部署的平台：

  • Windows 服务器上的 vCenter Server 6.x 及更高版本：C:\ProgramData\VMware\vCenterServer\Logs\

  • vCenter Server Appliance 6.x：/var/log/vmware/

  • vCenter Server Appliance 6.x 闪存：/var/log/vmware/vsphere-client

  • vCenter Server Appliance 6.x HTML5：/var/log/vmware/vsphere-ui

  • https://kb.vmware.com/s/article/1021804

指导

组织应立即更新到不受影响的vCenter Server版本，而不要等待其常规补丁程序周期。具有紧急补丁程序或事件响应程序的用户应考虑调用它们，尤其是如果（或最近）将其vCenter Server的实现暴露给公共互联网。如果您无法立即修补，VMware 在此处提供有关禁用 Virtual SAN Health Check 插件的说明。请注意，虽然禁用插件可能会降低可利用性，但并不会消除漏洞。


网络管理员应确保 vCenter Server 不会暴露于 Internet。
