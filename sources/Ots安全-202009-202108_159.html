在本文中，我将解释Microsoft Azure虚拟机（VM）扩展的 工作方式，以及我们如何在扩展机制中发现影响Azure VM Linux系统的致命漏洞。作为负责任的披露政策的一部分，我们已将该漏洞报告给了Microsoft安全响应中心（MSRC）。他们很快打了补丁，并将其分配给CVE-2021-27075。


此漏洞将允许没有特权的用户泄漏任何Azure VM扩展的私有数据。与VMAccess扩展的设计（用于帮助系统管理员的正式Azure扩展）配合使用，我们将演示如何将其用于实现特权升级 和可能的横向移动。

概念验证

Azure VM扩展

Azure VM为开发人员和管理员提供了一个集成的插件系统，以将其他组件安装到他们的计算机上。通过此机制既可以提供第一方（例如Microsoft Azure Diagnostics和Microsoft Azure Network Watcher），也可以提供第三方应用程序（例如Datadog Agent）。


为了管理扩展安装并保持最新状态，系统上安装了Microsoft Azure Guest Agent。该组件是开源的，并托管在GitHub上。该代理以及Azure扩展安装在/ var / lib / waagent中。非root用户无法访问此目录，因为该目录包含与扩展相关的机密。


扩展程序安装在该目录中自己的子目录中，例如：

/var/lib/waagent/Microsoft.Azure.NetworkWatcher.NetworkWatcherAgentLinux-1.4.1587.1

许多共享配置都位于根扩展目录/ var / lib / waagent中。

将扩展添加到VM后，扩展的配置文件将在Azure VM管理器（也称为结构控制器）中在后台更新。WAAgent不断轮询该文件的结构控制器，更新后，便下载并部署了扩展名。在Microsoft Azure云中，WAAgent与“线服务器”（属于光纤通道控制器的HTTP服务）进行通信。


WAAgent通过访问特殊IP地址168.63.129.16与Fabric Controller通信。通过一些测试，我们发现此终结点与169.254.169.254相同，即众所周知的Azure实例元数据服务 IP地址。

缺陷1：证书端点无法验证运输证书

攻击者可以创建自己的运输专用密钥及其相应的运输证书。攻击者使用证书端点提供自己的传输证书，并从有线服务器接收加密形式的密钥（在我们的示例中为F54265F38F8D16C35C0E1FD3190882831A6C4384密钥）。

令我们惊讶的是，在与root用户一起开发PoC之后，它将无法与非特权用户一起使用。看来发往Wire Server端点168.63.129.16的数据包没有被服务器发送出去。这是因为iptables规则将非用户ID 0（根）的数据包丢弃到端点：

Azure VM IP表

缺点2：绕过Wire Server无特权的访问防御

如前所述，我们发现164.254.164.254与168.63.129.16是同一台计算机。我们用164.254.164.254将每个请求替换为168.63.129.16，这使我们可以在没有特权用户的情况下与Wire Server通信。


此外，此iptables防御不适用于在Docker容器中运行的进程（即使PoC以非特权用户身份运行），也允许容器通过Wire Server泄漏有关其主机的信息。该问题也由MSRC修复。


结合缺陷

利用这两个缺陷，无特权的用户可以泄漏任何Azure VM扩展的私有设置。当与处理敏感数据的扩展名配对时，这尤其危险。


一个特别严重的例子是VMAccess 扩展，这是一个官方的Microsoft Azure扩展，用于在受控计算机上方便地更改密码。Guardicore 先前已记录到，即使在完成用户密码更改后，VMAccess仍将密码保留在protectedSettings字段中，并且不再需要将其保留在磁盘上。


结合我们发现的漏洞，攻击者可以通过泄漏VMAccess管理员密码将自己提升为特权更高的用户。此外，如果VMAccess密码与其他Azure VM共享（通常是这样），则攻击者可以在整个系统上执行横向移动。流程如下所示：

结论

微软发布的CVE也适用于其他Azure产品，例如Azure Spring Cloud，这是由研究人员Wouter ter Maat 后来独立发现的，他也将其归功于CVE。


Microsoft在改进了整个Linux扩展机制后解决了此问题，并且不需要用户交互即可更新VM。


这项研究旨在进一步围绕云服务提供商（CSP）与客户之间的关系进行讨论。最终，客户应对发生的任何数据泄露负责。为了获得更完整的云安全策略，Intezer建议采用两管齐下的方法。做一些基础工作，例如修复已知的漏洞和强化系统以减少受到攻击的可能性。您还需要运行时威胁检测，以识别和响应由于未知漏洞利用或供应链中的后门而发生的攻击。
