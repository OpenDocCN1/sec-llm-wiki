执行摘要  
  
  
Express render API设计为仅传递模板数据。通过允许模板引擎配置选项直接通过Express渲染API传递，Express模板引擎的下游用户可能会无意中将不安全行为引入其应用程序，其影响范围从跨站点脚本（XSS）到远程代码执行（RCE）。  
  
  
  
  
技术摘要  
  
  

Express JS允许开发人员使用各种模板渲染引擎。这些引擎通过检查应用程序提供的对象来替换模板中的内容。例如，以下代码段呈现了一个名为“ index”的模板，并传递了一个带有两个元素（标题和消息）的对象。app.get('/', function (req, res) { res.render('index', { title: 'Hey', message: 'Hello there!' })})模板引擎通常需要一种方法来设置其配置参数，例如模板目录的路径，模板的名称以及其他引擎特定的参数。为此，许多模板引擎选择直接通过Express render API接收其配置选项。如果对象是用户控制的，则通过Express render API传递模板引擎配置参数可能会导致漏洞。下游应用程序通常选择直接通过远程用户控制的req.query对象传递其模板数据。这导致远程攻击者可能能够通过恶意模板引擎配置选项来破坏易受攻击的应用程序。安全影响特定于应用程序所使用的引擎，但影响范围从XSS到RCE。重要说明：这是库/引擎级别的API滥用，导致下游应用程序代码中潜在的漏洞。Express并不打算让渲染引擎在同一对象中混合模板数据和配置选项。我们已经在与ExpressJS团队的讨论中确认了这一点。当应用程序将用户控制的对象（例如req.query）直接传递到通过Express渲染界面接受配置选项的渲染引擎时，就会出现现实世界中的下游漏洞。我们的研究表明，此漏洞模式很普遍，并且许多模板引擎都在遵循这种意外的Express渲染API使用模式，从而导致数量不明的受影响下游应用程序。通过在引擎级别报告此API滥用，我们希望能比试图寻求每个受影响的应用程序更广泛地捕获此问题，并防止将来API滥用。

  
  
  
  
  
细节  
  
  

问题：模板引擎配置选项通过Express render API传递

Express-handbarbars通过Express render API将纯模板数据与引擎配置选项混合在一起。更具体地说，该layout参数可能会触发下游应用程序中的文件泄露漏洞。

  

此潜在漏洞在某种程度上受到限制，因为只能包括具有现有扩展名（即file.extension）的文件，而缺少扩展名的文件将.handlebars附加到它们之后。

```

`app.engine('handlebars', exphbs());``app.set('view engine', 'handlebars');``app.get('/', function (req, res) {``   res.render('home', req.query);``});``app.listen(3000);`
```
