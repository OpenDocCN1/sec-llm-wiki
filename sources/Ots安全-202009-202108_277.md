# CVE-2021-1732 ＃添加漏洞

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzAxMjYyMzkwOA==&mid=2247490277&idx=4&sn=b8693a976fafedd0212341c03fb08225&chksm=9bae53aeacd9dab821e7fb5905cad4f796b59e1df21560d1fbf62c261bb976acaa55673564fe&scene=126&sessionid=1681670087#rd](http://mp.weixin.qq.com/s?__biz=MzAxMjYyMzkwOA==&mid=2247490277&idx=4&sn=b8693a976fafedd0212341c03fb08225&chksm=9bae53aeacd9dab821e7fb5905cad4f796b59e1df21560d1fbf62c261bb976acaa55673564fe&scene=126&sessionid=1681670087#rd)

这为CVE-2021-1732添加了一个漏洞，该漏洞是win32k中的一个漏洞。通过调用`NtUserConsoleControl`回调函数并传递当前正在创建的窗口，尽管包含攻击者控制的值，也可以将字段切换为偏移量。这用于构建读写原语以访问内核内存。构建后，将使用原语从PID 4窃取SYSTEM令牌。

在我的测试中，漏洞利用非常可靠。当它工作时，它会正常运行，并且不会导致BSOD，尽管从理论上讲它可以做到，但我只是没有观察到这种行为。我已经在从1803到20H2的所有6个受影响的Windows 10版本上进行了测试。我也测试了1709，但该漏洞利用程序似乎不适合该漏洞利用程序，尽管它据认为是易受攻击的。版本1709不再服务，因此MSRC并未将其列为受影响的系统。

从用户的角度来看，开发过程非常简单，没有特殊选择。整个事情发生在内存中。与许多RDLL一样，利用漏洞创建一个进程来承载DLL，然后在执行有效负载之前将其提升。实际上，在很多地方都使用了这种逻辑，因此我将其移到了Mixin中，因为它已经被复制并粘贴到许多漏洞利用程序中。

## 确认

列出确保此功能正常运行所需的步骤

*    开始 `msfconsole`
    
*    在受支持的目标上打开x64 Windows Meterpreter会话（Windows 10 1803-20H2）
    
*    运行检查方法，确保报告为似乎易受攻击
    
*    运行漏洞利用，获得更高级别的会话
    

  

```








































msf6 payload(windows/x64/meterpreter/reverse_tcp) > sessions -i -1
```
