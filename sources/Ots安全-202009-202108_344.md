# 威胁简介：Windows IPv4和IPv6堆栈漏洞

**执行摘要**

对于2021年2月的Microsoft补丁程序星期二，该公司发布了56个已知漏洞的补丁程序，其中包括：

*   CVE-2021-24086和CVE-2021-24094：Windows IPv6堆栈中的两个拒绝服务（DoS）漏洞。
    
*   CVE-2021-24074：Windows IPv4堆栈中的远程代码执行（RCE）漏洞。
    
*   CVE-2021-24086获得了7.5 / 6.5的通用漏洞评分系统（CVSS）评分，并且获得了Microsoft“重要”安全等级。
    
*   CVE-2021-24094和CVE-2021-24074的CVSS评分为9.8 / 8.4，并且获得Microsoft的“严重”安全评级。
    

  

**CVE-2021-24086和CVE-2021-24094概述**

攻击者可能发送许多精心制作的IPv6数据包（多个标头，无效的标头，多个片段标头等），这会导致DoS错误。具有PAN-OS的Palo Alto Networks下一代防火墙客户能够阻止此类恶意数据包以缓解攻击。

  

启用了IPv6防火墙的Palo Alto Networks下一代防火墙客户已经收到针对这两个漏洞的保护。可以在设备>设置>会话下的用户界面（UI）中启用IPv6防火墙：选中“启用IPv6防火墙”复选框，然后提交防火墙。有关IPv6防火墙的更多详细信息，请参见知识库文章“如何启用和禁用IPv6防火墙”。

![](../Images/be15b21cd8971ebdc9329a6d90c41dd7.png)

图1.启用IPv6防火墙。

**CVE-2021-24074的下一代防火墙缓解措施**

运行PAN-OS 8.1或更高版本的Palo Alto Networks下一代防火墙客户可以配置其网络区域保护配置文件设置，以通过为格式错误，严格和松散的源路由IP选项启用IP投递来保护自己免受与CVE-2021-24074相关的攻击。

  

请注意，作为IP协议的最佳实践，Palo Alto Networks建议启用丢弃数据包，以丢弃格式错误，严格和松散源路由选项的数据包，因为允许这些选项允许对手绕过使用目标IP地址作为匹配条件的安全策略规则。这些选项的更多详细信息可以在TechDocs文章“基于数据包的攻击防护”中找到。

  

“配置基于数据包的攻击防护”页面包含配置区域保护配置文件以丢弃具有IP选项的特定数据包的步骤。

  

使用以下选项将区域保护配置为丢弃IP数据包：

  

步骤1：创建区域保护配置文件并配置基于数据包的攻击保护设置。

1.  选择网络>网络配置文件>区域保护，然后添加新的配置文件。
    
2.  输入配置文件的名称和可选的描述。
    
3.  选择基于数据包的攻击防护。
    
4.  在“ IP丢弃”选项卡上，选择“基于数据包的攻击防护”设置选项卡，然后选中“ IP选项丢弃”下的“格式错误，严格源路由和松散源路由”复选框。
    
5.  单击确定。
    

![](../Images/8078c45916a6c321363b0611d2b58ee2.png)

图2.使用IP Drop选项配置区域保护配置文件。

步骤2：将区域保护配置文件应用于分配给您要保护的接口的安全区域。

1.  选择网络>区域，然后选择要在其中分配区域保护配置文件的区域。
    
2.  添加属于该区域的接口。
    
3.  对于“区域保护配置文件”，选择刚创建的配置文件。
    
4.  单击确定。
    

![](../Images/f155b4ccc176a6516016540a2012f4b3.png)

步骤3：提交您的更改。

1.  访问CLI。
    
2.  使用可操作的CLI命令集系统设置extra-threat-log on。默认为关闭。

例如，命令show counter全局过滤器增量 match flow\_dos\_pf\_badoption允许查看自上次发出命令以来丢弃的IPv4数据包。

对于CVE-2021-24074，当启用“格式错误”的区域保护IP丢弃选项时，格式错误的数据包会导致对后续数据包的错误的宽松/严格的源选项，从而被丢弃。由于内部防火墙数据包过滤，后续具有不良宽松/严格来源的IP数据包不会传输到防火墙。由于IPv4源路由被认为是不安全的，因此当启用“松散源路由”和“严格源路由”区域保护IP丢弃选项时，具有源路由的其他IPv4数据包将被丢弃。

  

**适用于CVE-2021-24074，CVE-2021-24086和CVE-2021-24094的Cortex XDR缓解措施**

如果您是Palo Alto Networks Cortex XDR代理客户版本7.1或更高版本，则可以从2月10日开始利用您的代理修改系统设置，以保护未打补丁的终结点不受这些漏洞的影响，直到安装Windows更新为止。

  

解决方法是通过Endpoint Exploit安全配置文件管理的，并且需要最新的内容更新。您可以编辑任何现有配置文件，也可以创建新的配置文件以根据需要包含解决方法。

  

在“未修补的漏洞保护”部分下，通过选择以下选项之一来定义CVE-2021-24074，CVE-2021-24086和CVE-2021-24094的解决方法设置：

  

*   **不修改系统设置（默认）：**不管当前值是原始值还是作为此变通办法一部分修改的值，都不要修改端点上当前设置的IPv4和IPv6设置。
    
*   **修改系统设置，直到修补了端点：**Cortex XDR代理在端点上运行以下命令以临时修改IPv4和IPv6设置，直到修补了端点。修补端点后，所有修改后的Windows系统设置都会自动恢复为修改前的值。帕洛阿尔托网络公司（Palo Alto Networks）强烈建议您在网络中应用此变通办法之前，先阅读以下命令，以确保不会影响或损害您的业务关键组件。
    

1.  要在端点上禁用IPv6分段，请执行以下操作：netsh int ipv6 set global reassemblylimit = 0
    
2.  要禁用IPv4的松散源路由：netsh int ipv4 set global sourceroutingbehavior = drop
    

*   将系统设置恢复为以前的设置：作为此解决方法的一部分，无论是否修补了端点，都将所有Windows系统设置恢复为修改前的值。

**结论**

作为Microsoft Active Protections计划（MAPP）计划的成员，Palo Alto Networks收到了该漏洞的早期详细信息，从而进一步了解了该威胁，从而帮助我们实现了强大的产品覆盖范围。与往常一样，我们建议为您的Microsoft产品提供最新的修补程序，以缓解此漏洞。

  

Palo Alto Networks将使用可用的新信息和建议来更新此威胁简介。
