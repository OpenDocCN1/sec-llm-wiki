# CVE-2021-1280 Cisco AMP中的本地特权升级

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzAxMjYyMzkwOA==&mid=2247489876&idx=2&sn=bf82926128593b2c2795d77e6af63bc0&chksm=9bae501facd9d909980959c88a50d73af745f1f7aaef523fcc1161bcf9d5917f106565602118&scene=126&sessionid=1681670097#rd](http://mp.weixin.qq.com/s?__biz=MzAxMjYyMzkwOA==&mid=2247489876&idx=2&sn=bf82926128593b2c2795d77e6af63bc0&chksm=9bae501facd9d909980959c88a50d73af745f1f7aaef523fcc1161bcf9d5917f106565602118&scene=126&sessionid=1681670097#rd)

![](../Images/83c533a06964c2068336a554a4b8cd5f.png)

**Cisco Immunet和Cisco AMP中的本地特权升级**

  

ZeroPeril最近研究了两种用于Windows的思科安全产品：Cisco Immunet和Cisco AMP。我们发现了影响两个产品的本地特权升级。

  

这两种产品共有的一个特定组件是SFC.exe，它是一项系统服务，该服务会定期以SYSTEM权限执行子进程Freshclam.exe。Freshclam.exe是ClamAV的一部分，已集成到Cisco AMP和Cisco Immunet中，用于更新产品中的ClamAV签名文件。

  

使用Sysinternals的ProcMon进行的调查显示，SFC.exe和Freshclam.exe都试图从用户C驱动器上的路径读取不存在的文件：

![](../Images/3a79e88555deb2f2f88dac5466465cc0.png)

freshclam.exe尝试读取C：\\ SSL \\ openssl.cnf

![](../Images/5c86622e127d86614e724aaaaf6f43aa.png)

试图读取C：\\ SSL \\ openssl.cnf的sfc.exe

在Windows上，任何标准的非特权用户都可以在C：驱动器中创建任意目录（如果尚不存在），因此我们决定创建此目录，其中包含一个名为openssl.cnf的空白文件。ProcMon的另一次运行显示，两个进程确实会读取该文件（如果存在）。

![](../Images/2d082f749e4417ff39bed57fa0fc3493.png)

sfc.exe和freshclam.exe读取openssl.cnf（如果存在）

我们通过查阅openssl.cnf文档研究了利用此方法的方法，然后我们立即着眼于有关引擎配置的部分，特别是给出了用于加载动态链接库的示例：

*   
*   
*   
*   
*   
*   
*   
*   

```
[engines]foo = foo_engine
[foo_engine]dynamic_path = /some/path/fooengine.sosome_ctrl = some_valuedefault_algorithms = ALLother_ctrl = EMPTY
```

接下来，我们决定通过复制WinLogon.exe进程中的主令牌（在与交互式用户相同的会话中作为SYSTEM运行）来复制交互式会话中产生命令提示符的简单DLL。我们将此dll放在以下路径中：C：\\ ampwn \\ ampwn.dll

  

使用特制的openssl.conf文件，如下所示：

*   
*   
*   
*   
*   
*   
*   
*   
*   

```
openssl_conf = openssl_init[openssl_init]engines = engine_section[engine_section]ampwn = ampwn_section[ampwn_section]engine_id = ampwndynamic_path = c:\ampwn\ampwn.dllinit = 0
```

然后，我们就可以强制sfc.exe和freshclam.exe来加载我们的dll。

![](../Images/cb2d1a0d6e2d794791c4b6c10c39980d.png)

sfc.exe加载我们的dll ampwn.dll

通过以这种方式滥用openssl.cnf文件，我们然后获得了具有完整系统特权的交互式命令提示符进程：

![](../Images/83c533a06964c2068336a554a4b8cd5f.png)

由sfc.exe系统服务启动的以SYSTEM身份运行的命令提示符

包容性

  

如果您在项目中使用OpenSSL库，则值得检查是否存在低特权用户可以写入的默认SSL配置路径，因为该服务可以由SYSTEM服务或高特权进程使用，如本文所述。。
