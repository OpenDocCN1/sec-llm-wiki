修补从来都不是一件容易的事，但是不完美地进行修补可能会再次咬住您。
因此，我们今天发布了一个漏洞，如果缓解不当，该漏洞可能再次出现。

Microsoft最近在10月发布了针对IPv6堆栈中令人讨厌的CVE-2020-16898的补丁程序，该补丁程序能够触发BSOD（死亡蓝屏）。这个被称为“坏邻居”的漏洞是IPv6邻居发现协议中的一个专门漏洞。当它不正确地处理ICMPv6路由器公告数据包时，就会出现该错误。

这是一个严重的安全漏洞（严重性得分为8.8），因为网络罪犯可以使用它来进行其他特定的攻击，例如远程执行代码（RCE），它可能导致比BSOD更糟糕的结果。

CVE-2020-16898如何使您的系统受到远程利用

该错误最优雅但又最具威胁性的元素是，驻留在同一子网中的攻击者可以远程利用易受攻击的系统。这就是为什么在事情失控之前进行修补非常重要。但是，在我们深入研究修补程序细节之前，我们必须对CVE-2020-16898有深刻的了解。


了解漏洞-详细信息和分析

该漏洞导致长度字段值为偶数时，使用RDNSS（递归DNS服务器选项）对ICMPv6路由器通告的不正确处理导致基于IPv6堆栈的缓冲区溢出。根据RFC 8106，RDNSS的长度选项可以分为八个八位位组单位，最小值应始终为奇数，对于单个IPv6地址，至少应为3个单位。

随着单个RDNSS地址的增加，八位字节的单位长度增加了2。使用适当的比例（称为“字段”）来确定IPv6地址的总数。它具有一系列有关IPv6，RDNSS和八位字节单位的值，这些值排在秤的顶部。

攻击者如何链接易受攻击的端点以使您的网络无法使用


如前所述，恶意行为者可以通过使用远程代码执行来触发链式反应，将一台易受攻击的计算机链接到另一台计算机并为攻击者提供一个受到破坏且无法使用的系统网络，从而远程利用易受攻击的系统。

如果IPv6路由器广告包是使用RDNSS选项恶意制作的，则它可能会触发Windows操作系统中的tcpip.sys文件并导致DoS攻击。出现此漏洞的原因是tcpip.sys驱动程序错误地解析了ICMPv6消息。由于该漏洞出现在ICMPv6邻居发现协议的路由器公告数据包中，因此才有了坏邻居名称。

此漏洞影响以下操作系统：

  • Windows 10版本1709

  • Windows 10版本1803

  • Windows 10版本1809

  • Windows 10版本1903

  • Windows 10版本1909

  • Windows 10版本2004

  • Windows Server 2019核心安装

利用CVE-2020-16898 /坏邻居

要利用CVE-2020-16898，攻击者必须对自己的行为有正确的了解。

该漏洞本身通过以下步骤得以实现：

  • 网络罪犯发送均匀长度的RDNSS选项

  • 同时，它们还发送仅8个字节的IPv6地址值，或者相对而言比要求的16个字节短8个字节，以及以前设置为偶数长度的RDNSS选项流

  • 这导致TCP / IP协议相信它实际上是第二个选项的开始，从而导致缓冲区溢出或潜在的RCE（通过利用RCE漏洞实施恶意软件）

Windows驱动程序tcpip.sys可能无法使用偶数选项解析此类请求，从而导致拒绝服务或蓝屏死机。由于tcpip.sys是Windows驱动程序，可通过设置TCP / IP协议的属性与连接到Internet的各种设备进行通信，因此风险被放大了。

攻击方面–该漏洞伤害最大

该漏洞对Windows 10用户的影响很大，即使Microsoft最近发布了一个更新程序，该更新为源自不同内部版本的Windows 10用户修补了该漏洞。

Shodan.io是一种广受赞誉的工具，用于揭示同一网络中连接的两台计算机的位置，该工具将具有IPv6地址的Windows服务器计算机的数量增加到了数百（如果不是数千）。这种有限的攻击面映射的原因是，防火墙保护了许多服务器的安全，而其他服务器则由云服务提供商操作和管理，从而使Shodan.io扫描无法访问它们。

当端点保护不起作用时如何检测“坏邻居”

检测CVE-2020-16898漏洞非常简单。您可以通过简单的试探法（也可以使用自我发现和捷径来解决问题来解决问题）来做到这一点。

启发式算法将解析所有传入的ICMPv6流量，同时查找ICMPv6类型字段为134的数据包，该数据包指示路由器通告。所有这一切，而ICMPv6选项字段为25表示RDNSS。该存储是一个0x20字节的静态缓冲区，无法处理数据包，从而导致导致BSOD的缓冲区溢出。

在将利用漏洞或漏洞的可能性缩小到两个最可能利用CVE-2020-16898的可信度后，您可以进一步确认当前的RDNSS选项是否也具有一个偶数的length字段值。

然后，启发式操作将在此条目的末尾放下一个红旗，因为它很可能是使用远程协助的潜在攻击者设计的不良邻居利用的一部分。检测工具还可能将您在该处看到的危险标记用于其他漏洞。如果您的检测工具的数据库正在使用CVE-2020-16898更新，则可能会发生这种情况。不幸的是，目前没有很多检测工具可以识别该漏洞。

最重要的提示：如果您在运行扫描时遇到一些危险信号，但不知道它们是否表明不良邻居漏洞，请检查IP部分。如果它与IPv6远程关联或显示在侧面写有ICMPv6，则可能是CVE-2020-16898。

请注意，仅当找不到修补程序或修补程序无法帮助您缓解漏洞时，才打算执行该解决方法。

缓解不良邻居/ CVE-2020-16898，因此不会卷土重来

最佳做法是从修补程序开始，因为Microsoft已经发布了CVE-2020-16899漏洞修补程序。

但是，如果这在您的情况下似乎不可行，则可以随时通过故意丢弃所有ICMPv6流量来开始在网络接口控制器或网络外围禁用IPv6 –如果目前不是必需的或不需要的话。

此外，您还可以使用与网络边界上的ICMPv6通信相同的方式来阻止或丢弃路由器通告。启用后，Windows防火墙和Windows Defender无法阻止概念验证。因此，您冒着无法通过在IPv4上建立ICMPv6流量隧道来确认攻击是否成功的风险。

要完全确认预期的补丁程序将对您有所缓解，并且该漏洞不会再变得更强大，请检查攻击者可以利用各种操作节点来进一步利用系统中的漏洞，即使应用了补丁程序或IPv6流量也是如此完全被封锁。

如果恶意行为者可以使用IPv4继续进行攻击，那么当前补丁将无法完全解决问题，并且可能迟早会浮出水面。您可能需要与经验丰富的开发人员或安全工程师合作，以找到这些操作途径。在此之前，最好的选择是安装Microsoft最新的October补丁程序。

如果由于某种原因而发现自己无法应用补丁，则可以使用以下PowerShell命令寻求解决方法，并完全禁用IPv6通信：

netsh int ipv6设置为int * INTERFACENUMBER * rabaseddnsconfig = disable


上面的shell脚本仅适用于Windows 10（版本1709）和更高版本的用户，并且在执行命令后不需要立即重启。请记住，仅当找不到该问题的十月补丁程序并且正在寻找解决方法时，才使用此命令。

要在应用补丁后重新启用ICMPv6 RDNSS，请运行以下PowerShell命令（无需重新启动）：

netsh int ipv6设置为int * INTERFACENUMBER * rabaseddnsconfig = enable
