Windows 10通过利用硬件的信任根来实现此目的，确保平台固件的健康和可信是保证强大的平台安全功能（如受保护的Hypervisor保护程序代码（HVCI）和Windows Defender Credential Guard）正常运行的基础。，该信任根可确保在Windows引导加载程序启动之前，需要授权的代码（如统一可扩展固件接口（UEFI）恶意软件）就不会扎根。

防御虚拟机管理程序（以及扩展整个操作系统的其余部分）以及此类低级威胁的关键是保护系统管理模式（SMM），它是基于x86的处理器中的一种执行模式，以比管理程序更高级别的有效特权运行。由于SMM传统上没有限制地访问内存和设备资源，因此SMM是获得对OS和硬件访问权限的已知攻击媒介。SMM特别容易受到代理攻击之类的威胁的攻击，在这种攻击中，恶意代码会欺骗具有大量特权的另一个代码来执行某些活动。一个人可能在SMM中拥有完美的代码，但仍然会受到踩踏到安全内核代码等行为的影响。

OEM有时将SMM有时称为“ Ring -2”，与其他NV RAM的硬件进行交互，模拟硬件功能，处理硬件中断或勘误以及执行其他功能。SMM以中断处理程序的形式运行，这些中断处理程序由计时器触发或访问某些内存，寄存器或硬件资源。OEM驱动程序和运行时固件服务可能会明确捕获SMM以控制某些硬件功能。

要阻止复杂的攻击通过SMM控制系统，操作系统必须对SMM的行为进行强制执行或监督。作为安全核心PC和System Guard的一部分，英特尔和AMD开发了通过强制执行和报告SMM可以访问哪些资源来将SMM与操作系统隔离的机制。

SMM隔离

隔离SMM分为三个部分：OEM实施一项政策，阐明他们需要访问的内容；芯片供应商在SMI上执行此策略；芯片供应商会向操作系统报告是否遵守此政策。

OEM提供的策略是一个列表，详细列出了SMI处理程序需要访问的资源。芯片集供应商的特定执行机制将在后面详述该策略并进行实施。操作系统对策略是什么没有任何控制;仅保证执行所述政策。

Windows信任动态根（DRTM）实施中约会的可信计算库（Tcb）启动，从芯片供应商的报告机制中获得强制执行的策略。由于资源访问是特定于平台需求的，因此Tcb Launch将OEM的SMM访问策略与Windows SMM隔离要求的多个级别进行比较，并以其提供的隔离级别。OEM的策略所达到的隔离级别将进行认证，并报告给OS。

隔离等级包括对SMI可以访问的内容的日益严格的限制，以及系统所需的强制执行功能。隔离要求的一个示例是SMI可能无法访问OS拥有的内存。体积，这些要求可能包括对以下资源的限制：

  1. SMM页面配置锁定

  2. 静态页表

  3. 特定型号寄存器（MSR）访问

  4. IO端口访问

  5. 处理器状态保存访问

为了确保在不满足最低要求的情况下使用安全核心PC的客户获得一致的安全保证，对DRTM的测量设置了上限，并且本地和远程认证都失败了。SMM隔离与DRTM息息相关，因为如果没有DRTM，则OS无法信任引导环境评估的任何内容，因为它无法免受SMM的影响。SMI在DRTM期间被挂起，因此DRTM建立的新的信任根可以评估SMM访问策略的安全性。

Windows将会将这些保护用作本地机器密保护，并且远程证明工具还可以利用此信息来确定特定设备的安全状态。该证明报告可用于防止访问敏感的网络文件，例如，除非存在某些特定功能组合。

AMD解决方案（SMM主管）

在UEFI引导阶段，将SMM主管作为UEFI驱动程序加载。在DRTM启动时，此驱动程序由AMD签名并由平台安全处理器（PSP）进行身份验证。身份验证失败将使DRTM失败。（它也受到PSP的固件防回滚保护。）

SMM Supervisor提供并初始化SMI输入例程（触发SMI后执行的第一个代码块）。此例程也由AMD签名，并在DRTM启动时由PSP验证。在发生DRTM事件时，PSP还将验证SMI条目是否已正确配置到此经过身份验证的块。此身份验证失败还将导致DRTM失败。

SMM Supervisor将关键页面（包括SMM Supervisor代码块，内部数据，页面表本身，异常处理程序以及处理器保存状态）标记为超级用户页面，只能从当前特权级别0（CPL0，最特权级别）访问。

触发SMI之后，SMI输入例程会立即将系统降级为在CPL3（最低特权级别）下执行，然后再执行任何第三方SMI处理程序。从CPL3环境中，MSR，IO和超级用户页访问，关键寄存器更改（例如CR3）以及特权指令（例如“ hlt”和“ cli”）最终都将作为CPU硬件强制执行的常规保护错误。

为了使CPL3下的SMI处理程序能够访问特权数据并进行注册，SMM Supervisor提供了syscall接口，以允许第三方SMI处理程序发出此类请求。驻留在SMM主管中的syscall接口的后端由SMM安全策略控制。所述策略是一个拒绝列表，可以针对每个平台进行自定义，以确定可以从CPL3访问哪些MSR，IO或内存区域。在DRTM事件期间，SMM安全策略会报告给OS安全加载程序并由OS安全加载程序进行验证。

英特尔硬件盾

英特尔®硬件防护罩是英特尔®博锐®平台的一部分，使用CPU硬件和固件来实施平台的SMM访问策略。这些功能代代相传地使用新的CPU硬件功能与现有的CPU功能一起发展，以加强相关的微体系结构流程并提供新的寄存器锁定，以支持相关的固件强化*。

  • 具有第8代Intel®Core™vPro®处理器的IntelvPro®平台引入了固件强化和硬件锁定的静态页表支持，以减少关于内存的SMM特权并锁定内存配置。这些新锁包括：CR3锁，MSEG锁，SMBASE锁等。

  • 具有第9代Intel Core vPro处理器的Intel vPro平台添加了Intel签名的SMM模块，可通过PCR17使用Intel®Hardware Shield的组件Intel®Trusted Execution Technology（Intel®TXT）来证明SMM内存配置。该模块首先验证用于实施SMM访问策略的强化SMM代码的完整性。然后将其以及策略的详细信息报告回操作系统。因此，OS可以验证SMM的可信度并评估平台的SMM访问策略，而不会受到SMI处理程序的干扰。

  • 带有第10代Intel Core vPro处理器的Intel vPro平台增强了经过验证的CPL0 SMM组件，以使用SMI处理程序创建权限分离，从而将策略实施扩展到MSR，IO端口和SMM状态保存（访问策略可能因平台而异）。报告机制已扩展为包括这些功能。

*任何产品或组件都不是绝对安全的。
