CrowdStrike®情报高级研究团队在Palo Alto Networks GlobalProtect VPN客户端（CVE-2019-17435，CVE-2019-17436）的Windows，Linux和macOS版本中发现了两个明显的漏洞。该漏洞使没有特权的用户可以可靠地升级到使用GlobalProtect软件的计算机上SYSTEM或root该计算机上。固定版本于2019年10月15日由Palo Alto Networks发布。我们要感谢Palo Alto Networks及时专业地处理和解决所报告的问题。

这是由两部分组成的系列博客中的第一篇，该系列涵盖了如何利用GlobalProtect for Windows。第二部分将介绍Linux和macOS客户端的利用。

CVE-2019-17435漏洞

Windows GlobalProtect VPN客户端包括以下两个组件：

  • PanGPS.exe:PanGPS在启动期间启动一次。它负责协商VPN连接，配置网络设备并相应地调整路由，以及安装软件更新。为了完成这些任务，它具有SYSTEM特权运行。PanGPS在上侦听传入的TCP连接127.0.0.1:4767。

  • PanGPA.exe：PanGPA在每个登录会话中自动启动一次，并以登录用户的权限运行。PanGPA负责显示图形用户界面（GUI），向用户通知状态更改以及下载软件更新等。PanGPA将任何特权操作委派给PanGPS。与PanGPS的进程间通信（IPC）通过与的TCP连接实现127.0.0.1:4767。

GlobalProtect IPC

发现在PanGPA和PanGPS之间交换的所有消息都是使用AES-256在密码块链接（CBC）模式下加密的。初始化向量（IV）是固定的，由16个空字节组成。可以从计算机的安全标识符（SID）派生AES密钥，如下所示：

AES_KEY = MD5(SID + MD5(“pannetwork”)) + MD5(SID + MD5(“pannetwork”))

每条加密的消息都有一个16字节的标头作为前缀，该标头以ASCII编码的十进制声明主体的长度，并用空字节填充。加密示例消息的开头如下所示：

软件升级

在正常使用期间， 我们发现GlobalProtect VPN客户端无需任何用户交互即可自动更新自身。发现该更新过程分为两个部分。首先，PanGPA下载潜在的更新并将其%Temp%作为文件存储在当前用户的目录中.MSI。之后，PanGPA将软件升级请求发送到特权PanGPS进程。该请求包含该MSI文件的绝对路径：

<request>
  <type>software-upgrade</type>
  <command-line>C:\Users\USER\AppData\Local\Temp\_tempXXXX.msi</command-line>
</request>

然后，PanGPS验证文件的签名，如果验证成功，则将其复制到C:\Windows\Temp\globalprotect.msi。如果目标文件不存在，则新创建文件的所有者为SYSTEM; 否则，现有文件将被覆盖并保留所有权。复制后，将删除源文件，并再次验证复制文件的签名。如果验证成功，PanGPS将写入一个批处理文件，将实际的更新过程编排为C:\Program Files\Palo Alto Networks\GlobalProtect\update_tmp.bat。批处理文件指示Windows的服务控制管理器停止PanGPS服务。然后，它进入延迟三秒的循环，以等待PanGPS进入“停止”状态。使用（以红色突出显示）实现三秒钟的延迟，该延迟timeout.exe至少被调用一次：

echo off
set /a _count=0
"C:\Windows\system32\sc.exe" stop pangps > null
:loop
if %_count% GTR 300 goto exittimeout
"C:\Windows\system32\timeout.exe" /t 3 /nobreak > null
set /a _count=_count + 3
"C:\Windows\system32\sc.exe" query pangps | find "STOPPED"
if errorlevel 1 goto loop
cd C:\Program Files\Palo Alto Networks\GlobalProtect
"C:\Windows\system32\msiexec.exe" /x "{D7FDA55F-21EC-43A9-A917-CCBABE5A708A}" /qn /norestart    KEEPREGISTRIES="YES" /l+* "C:\Program Files\Palo Alto Networks\GlobalProtect\PanGPMsi.log"
"C:\Windows\system32\msiexec.exe" /norestart /qn /i "C:\Windows\TEMP\globalprotect.msi"
    TARGETDIR="C:\Program Files\Palo Alto Networks\GlobalProtect"  BENICE="yes" /l+*
    "C:\Program Files\Palo Alto Networks\GlobalProtect\PanGPMsi.log"
goto normalexit
:exittimeout
echo %date% %time% - PanGPS service cannot be stopped. time out 300. >> "C:\Program Files\Palo
    Alto Networks\GlobalProtect\PanGPS.log"
exit 1
:normalexit

循环后，将卸载旧的GlobalProtect VPN客户端（以绿色突出显示），并从文件中安装新版本C:\Windows\Temp\globalprotect.msi（以蓝色突出显示）。

此行为允许一个三秒钟的窗口，在此期间C:\Windows\Temp\globalprotect.msi可以用恶意负载替换已复制并已验证的MSI安装程序。但是，必须满足以下先决条件，无特权的用户才能成功利用此漏洞来实现将本地特权提升为SYSTEM：

  • globalprotect.msi除非特权用户拥有该文件，否则该全局临时目录中的文件不能被非特权用户删除或替换。在先前的更新之后留在临时目录中的GlobalProtect安装程序通常属于SYSTEM。在这种情况下，要么必须首先更改所有权，要么必须删除安装程序。

  • 为了利用此漏洞而不必等待真正的更新发生，必须找到一种启动伪造更新的方法。但是，制作虚假的软件升级消息，对其进行加密并将其发送到PanGPS TCP套接字应该完全可以做到这一点。

  • PanGPS守护程序仅在其侦听套接字上接受单个TCP连接，并且该连接必须源自从中的PE映像创建的进程C:\Program Files\Palo Alto Networks\GlobalProtect。

有一些方法可以满足所有这些先决条件，并可靠地触发更新过程，该更新过程globalprotect.msi将以特权执行攻击者提供的文件SYSTEM。

漏洞利用

如前所述，漏洞利用程序必须能够向PanGPS发送升级请求，而且还必须用恶意文件替换有效的升级文件。

触发升级

为了使利用在实际情况下有用，需要用于手动触发更新过程的原语。通过PanGPA和PanGPS之间基于TCP的通信协议，这应该是可能的。但是，Windows版本的PanGPS不允许与其监听套接字的多个并发连接，并且PanGPA进程通常已经建立了单个允许的连接。此外，Windows版本的PanGPS会对每个传入的连接进行检查，以确保连接过程的PE映像指向下方的可执行文件C:\Program Files\Palo Alto Networks\GlobalProtect。非特权用户通常不允许写入以下目录C:\Program Files。

通过将DLL注入PanGPA，可以绕过PE映像检查和连接限制。然后可以按以下方式触发更新过程： 

  1. 首先，注入器帮助程序可执行文件计算基于机器的AES加密密钥，对伪造的软件升级请求消息进行加密，然后将其写入磁盘。

  2. 接下来，注入程序使用请求当前的IPv4 TCP连接表，  GetExtendedTcpTable()并在结果集中搜索已建立与的连接的PanGPA进程127.0.0.1:4767。如果找到，则OpenProcess()使用所需的访问权限打开相应的进程ID PROCESS_ALL_ACCESS。然后，通过注入准备好的DLL CreateRemoteThread()。

  3. 然后，注入的DLL枚举属于该进程的所有套接字句柄。找到连接到的套接字句柄后127.0.0.1:4767，将从磁盘读取先前加密的数据包并将其发送到该套接字，然后触发更新过程。

替换升级文件

仅当C:\Windows\Temp\globalprotect.msi非特权用户可写MSI文件路径时，才能成功利用此漏洞，以便在更新过程中可以用恶意负载替换该文件。但是，如果以前有合法的软件更新，则该文件可能已经存在并属于SYSTEM用户，这将阻止常规的，没有特权的用户删除或替换文件。在这种情况下，必须先删除该文件。这可以通过更新过程的一些副作用来实现：

文件删除

开始安装PAN签名的MSI文件后，PanGPS将源MSI文件复制到，然后将其删除C:\Windows\Temp\globalprotect.msi。因此，如果发出了以该路径作为源的软件升级请求，则PanGPS会验证源的签名，将源文件复制到其自身上，然后将其删除。签名的第二次验证将失败，并且将不执行任何实际升级。

为了使PanGPS执行这些操作，源文件（即globalprotect.msi必须删除的文件）必须由PAN进行数字签名，而在实际情况下可能并非总是如此。为了提高漏洞利用的可靠性，因此可以在文件删除之前添加另一个以已知的，良好的PAN签名的MSI文件作为源的软件升级请求。该“升级”通常应成功完成，并将正确签名的MSI文件保留在中C:\Windows\Temp\globalprotect.msi，然后可以通过先前记录的技术删除该文件，以确保对非特权用户进行写访问。

文件替换

执行完这些步骤后，系统将进入状态，其中没有globalprotect.msi文件C:\Windows\Temp，并且没有特权的用户可以通过触摸它来简单地声明所有权。接下来，可以使用PAN签名的MSI文件作为源启动软件更新过程。PanGPS验证的真实性后C:\Windows\Temp\globalprotect.msi，它将执行批处理文件。该timeout.exe进程将被调用，并且相应的进程列表条目可用作漏洞利用的指示器，该漏洞利用的时机正是用攻击者控制的版本替换文件的时间globalprotect.msi。超时循环结束后，将删除旧的GlobalProtect安装，并安装现在由攻击者控制的MSI文件。 

有效载荷

为了将特权提升到SYSTEM，我们的利用程序使用了产生外壳程序的MSI文件SYSTEM。它还会触发真正的GlobalProtect客户端的重新安装，以维护GlobalProtect软件安装的完整性。

结论

在此博客中，我们展示了如何利用GlobalProtect for Windows中几个看似较小的问题的组合来成功提升Windows的特权。回顾一下：

  • GlobalProtect代理由PanGPS和PanGPA两个组件组成，其中PanGPS以提升的特权运行，因此它可以执行特权操作，例如升级代理软件。

  • 要触发软件升级，非特权用户必须通过本地TCP连接与PanGPS通信。PanGPS试图确保只有PanGPA可以建立这样的连接，但是可以通过将代码注入PanGPA来绕过此检查。

  • 触发升级后，没有特权的用户可以与更新过程进行竞争，并用恶意的有效负载替换经过签名的良性MSI文件，然后以提升的特权执行该文件。

  • 仅当用户能够操作文件时，此文件替换才能成功。并非总是这样，但是PanGPS中的其他缺陷使无特权的用户可以删除任何有冲突的文件，并在开始实际的特权升级利用之前进行控制。
