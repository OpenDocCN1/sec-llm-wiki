# CVE-2018-14558：通过以前未知的缺陷对Ttint IoT特洛伊木马进行了攻击

一个未知的黑客组织正在利用一种称为Ttint的先前未知的恶意软件，该恶意软件被归类为IoT特定的木马。我们所知道的是，黑客开发人员正在使用两个零日漏洞来侵入目标设备。安全分析已导致进行调查，从而揭示了两个已发布的通报中的弱点：CVE-2018-14558和CVE-2020-10987。从捕获的样本中可以看出，该恶意软件基于Mirai代码。

  

**CVE-2018-14558和CVE-2020-10987用作交付Ttint IoT特洛伊木马的机制**

新型危险的IoT Trojan攻击了全世界的设备。根据已发布的代码分析，该代码基于Mirai代码并由未知的黑客组织开发。与该类别的其他病毒一样，当发生一次感染时，它将自动尝试入侵其他类似的主机，从而在此过程中创建一个大型僵尸网络。因此，如果进行了适当的配置和目标，则此类攻击活动将被视为非常有效。

  

通过使用直接网络攻击的典型方法来渗透这种特定恶意软件-黑客将使用自动框架，这些框架带有必要的漏洞。如果未修补目标网络，则感染将自动发生。之所以将这些入侵视为对其潜在破坏至关重要的原因之一，是因为这些弱点被标记为“零时差”，在感染之前它们是未知的。

  

Ttint IoT木马是针对Tenda路由器所有者的，于2019年11月检测到首次攻击。第一次攻击使用了这两个漏洞，并于2020年7月进行了公开披露。第二次攻击波于2020年8月进行，再次针对Tenda设备。Ttint木马专注于使用以下两个建议：

  

*   **CVE-2018-14558** —在带有固件通过V15.03.06.44\_CN（AC7）的Tenda AC7设备，带有固件通过V15.03.05.19（6318）\_CN（AC9）的AC9设备以及带有固件通过V15.03.05.19（CN9）的AC10设备上发现了一个问题V15.03.06.23\_CN（AC10）。命令注入漏洞使攻击者可以通过精心设计的goform / setUsbUnload请求执行任意OS命令。发生这种情况是因为“ formsetUsbUnload”函数使用不受信任的输入执行dosystemCmd函数。
    
*   **CVE-2020-10987** — Tenda AC15 AC1900版本15.03.05.19的goform / setUsbUnload端点允许远程攻击者通过deviceName POST参数执行任意系统命令。
    

根据现有信息，大多数袭击是针对南美的受害者。

  

**Ttint IoT木马功能**

Tting Iot木马基于Mirai，因此包括类似的感染序列。尽管它包括相同的分布式拒绝服务方法，但黑客还实施了另外的12条控制指令。

  

当感染在受影响的计算机上运行时，第一个操作将是隐藏病毒跟踪以免被检测到。这是通过监视操作系统来完成的，目的是查找所有已安装的安全系统。如果发现任何木马，它将尝试禁用它们，这适用于程序和服务，例如防病毒程序，防火墙，虚拟机主机等。如果无法绕过这些程序，此恶意软件引擎可能会自行删除。

  

在给定系统上找到特洛伊木马后，它将阻止系统重新启动，这是永久安装的一个示例。这是有意的，不同于其他类似的威胁，这些威胁仅在设备通电时启动病毒。

  

与该恶意软件相关联的进程所使用的实际名称将被重命名，这是试图隐藏它们的存在。与操作相关联的所有配置文件和数据均已加密，从而仅可供黑客使用。Ttint IoT木马的一些独特功能如下：

*   **特洛伊木马高级操作**–本地安装的代理程序将连接到由黑客控制的服务器，并允许远程攻击者完全控制设备。但是，此特定病毒将使用Websocket协议而不是使用标准连接，这使跟踪数据包非常困难。
    
*   **代理服务器的使用**–本地计算机与远程黑客控制的服务器之间的通信将通过由罪犯操作的代理服务器进行中继。
    
*   **网络访问劫持**–恶意软件将重新配置目标设备的重要配置文件。由于这样做主要是路由器，因此犯罪分子将拥有对用户网络访问的完全访问权限。
    
*   **网络暴露**–通过重写防火墙规则，威胁将能够暴露内部网络后面的计算机上部署的其他私有服务。
    
*   **升级**–在给定的时间间隔内，主要恶意软件将检查是否发布了新版本。它可以自动更新到任何较新的迭代。
    

像该类别的其他病毒一样，它能够从主机设备劫持敏感信息，包括可用的硬件组件。收集的数据将在网络传输过程中报告给犯罪分子。

目前，最好的补救措施是从设备制造商那里升级到最新的可用固件。目前，腾达是唯一已知的目标设备制造商。考虑到攻击的规模和广泛的功能列表，我们预计未来的攻击将针对更广泛的IoT设备。
