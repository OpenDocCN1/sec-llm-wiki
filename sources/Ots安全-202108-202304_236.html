绕过 .NET 序列化绑定器

序列化绑定器通常用于验证序列化数据中指定的类型，以防止危险类型的反序列化可能对运行时序列化程序产生恶意副作用，例如BinaryFormatter.


在这篇博文中，我们将研究这可能会失败并因此可能允许绕过验证的情况。我们还将介绍 DevExpress 框架 (CVE-2022-28684) 和 Microsoft Exchange (CVE-2022-23277) 中不安全的序列化绑定器的两个真实示例，它们都允许远程代码执行。


介绍

类型名称

类型名称用于标识 .NET 类型。在完全限定的形式（也称为程序集限定名，AQN）中，它还包含有关应从中加载类型的程序集的信息。此信息包括程序集的名称以及指定其版本、文化和签名的公钥标记的属性。这是此类程序集限定名称的（广泛）示例：

此程序集限定名称由具有多个组件的两个部分组成：

  • 程序集限定名称 (AQN)

  • 输入全名

  • 命名空间

  • 类型名称

  • 通用类型参数指示器

  • 嵌套类型名称

  • 泛型类型参数

  • 嵌入式AQN ( EAQN )

  • 程序集全名

  • 程序集名称

  • 装配体属性


您可以看到，同样的细分也可以应用于嵌入式类型的 AQN。为简单起见，类型信息将被称为类型名称，程序集信息将被称为程序集名称，因为这些是 .NET 使用的通用术语，因此也在本文中。


运行时使用程序集和类型信息来定位和绑定程序集。该软件组件有时也称为CLR Binder。


序列化绑定器

在其最初的意图中， aSerializationBinder应该像运行时绑定器一样工作，但只能在使用 、 和 的序列化/反序列化上下文BinaryFormatter中SoapFormatter工作NetDataContractSerializer：


一些用户需要控制加载哪个类，因为类在程序集之间移动，或者服务器和客户端需要不同版本的类。—SerializationBinder类为此， aSerializationBinder提供了两种方法：

public virtual void BindToName(Type serializedType, out string assemblyName, out string typeName);

public abstract Type BindToType(string assemblyName, string typeName);

在BindToName序列化期间被调用，并允许控制写入序列化流的assemblyName和值。typeName另一方面，BindToType在反序列化期间被调用，并允许Type根据传递的assemblyName和typeName从序列化流中读取的来控制返回。由于后一种方法是abstract，派生类需要提供自己的该方法的实现。


在 2017 年 .NET 反序列化问题出现期间，文档中添加了“也可用于安全性”的注释SerializationBinderSerializationBinder。到了 2020 年晚些时候，这句话变成了完全相反的说法：

这可能就是为什么开发人员（错误地）使用它们作为一种安全措施来防止恶意类型的反序列化。而且它仍然被广泛使用，即使那些序列化程序已经因为明显的原因被拒绝。


但是使用 aSerializationBinder来验证要反序列化的类型可能会很棘手，并且存在可能允许绕过验证的陷阱，具体取决于验证的实现方式。


什么可能出错？

为了验证指定的类型，开发人员可以


仅处理指定程序集名称和类型名称的字符串表示形式，或

尝试解析指定的类型，然后使用返回的Type.

这些策略中的每一个都有其自身的优点和缺点。


类型绑定之前/之后验证的优点/缺点

前者的优点是类型解析成本高，因此有些人建议不要使用它，以防止可能的拒绝服务攻击。


然而，另一方面，类型名称解析并不是那么直接，并且 .NET 的内部类型解析器/绑定器允许一些意想不到的怪癖：


空白字符（即 U+0009、U+000A、U+000D、U+0020）通常在标记之间被忽略，在某些情况下甚至更多字符

.类型名称可以以“ ”（句点）开头，例如，.System.Data.DataSet

程序集名称不区分大小写，可以引用，例如，MsCoRlIb和"mscorlib"

程序集属性值可以被引用，甚至是不正确的，例如，PublicKeyToken="b77a5c561934e089"和PublicKeyToken='b77a5c561934e089

.NET Framework 程序集通常只需要PublicKey/PublicKeyToken属性，例如，System.Data.DataSet, System.Data, PublicKey=00000000000000000400000000000000或System.Data.DataSet, System.Data, PublicKeyToken=b77a5c561934e089

程序集属性可以是任意顺序，例如，System.Data, PublicKeyToken=b77a5c561934e089, Culture=neutral, Version=4.0.0.0

允许任意附加程序集属性，例如，System.Data, Foo=bar, Version=4.0.0.0, Culture=neutral, PublicKeyToken=b77a5c561934e089, Baz=quux

程序集属性可以包含几乎任意数据（支持的转义序列：\"、\'、\,、\/、\=、\\、\n、\r、 和\t）

这使得根据名称检测已知的危险类型基本上是不切实际的，顺便说一句，这总是一个坏主意。相反，应该只允许已知的安全类型，其他任何东西都应该导致抛出异常。


与此相反，在验证之前解析类型将允许使用该类型的规范化形式。但是类型解析/绑定也可能失败。并且根据自定义SerializationBinder处理此类情况的方式，它可以允许攻击者绕过验证。
