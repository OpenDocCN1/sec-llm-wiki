在这篇博文中，我们展示了我们的研究团队如何从 APT 团队的角度来接触 Zimbra。结果，我们在unrar实用程序中发现了一个 0-day 漏洞，该实用程序是 Zimbra 中使用的第 3 方工具。该漏洞最终允许远程攻击者在易受攻击的 Zimbra 实例上执行任意代码，而无需任何事先身份验证或相关知识。

  

**受影响的软件和版本**

在本节中，我们将详细介绍哪些版本的unrar会受到影响。尽管这篇博客文章重点介绍了 Zimbra 以展示此错误的影响，但任何依赖  unrar未修补版本来提取不受信任档案的软件都会受到影响。 

  

**攻击者能做什么？**

我们在开发 WinRAR 的同一家公司 RarLab开发的unrar二进制文件中发现了文件写入漏洞 (CVE-2022-30333) 。

  

当应用程序或受害者用户提取不受信任的存档时，攻击者能够在目标提取目录之外创建文件。如果他们可以写入已知位置，他们很可能能够以一种导致在系统上执行任意命令的方式利用它。 

  

在 Zimbra 的案例中，成功的利用使攻击者可以访问受感染的电子邮件服务器上发送和接收的每一封电子邮件。他们可以默默地后门登录功能并窃取组织用户的凭据。通过这种访问，他们可能会升级对组织更敏感的内部服务的访问。此攻击的唯一要求是在服务器上安装unrar，这是预期的，因为它是 RAR 存档病毒扫描和垃圾邮件检查所必需的。

  

  

**我受到影响吗？**

RarLab 的官方安全补丁包含在 UnRar 源代码版本6.1.7中，并包含在版本6.12的二进制文件中。任何以前的版本都可能存在漏洞。只有 Unix 二进制文件（不包括 Android）受此漏洞影响。WinRAR 没有这个错误。

  

易受攻击和修补的版本可能会有所不同，具体取决于您使用的 Linux 发行版以及二进制文件是从哪个存储库下载的。如果您想确保使用包含安全补丁的版本，我们建议您直接从 RarLab 的网站下载。

  

unrar有多种流行的实现。只有依赖 RarLab 代码的实现会受到影响。

  

**这与 Zimbra 有什么关系？**

Zimbra 对这个unrar漏洞没有过错，但由于与受影响的服务相关的广泛权限，它才有可能被利用。例如，未经身份验证的攻击者可以将 JSP shell 写入 web 目录，而这是一个不相关的服务。 

  

如果安装了unrar ，Zimbra 实例会受到影响，这是预期的，因为它是 RAR 档案的垃圾邮件检查和病毒扫描所必需的。由于调用unrar的方式，也预计安装了 RarLab 的实现，这是易受攻击的。

由于 Zimbra 是一个一体化解决方案，它带有用于发送和接收电子邮件的预配置软件。它还会在收到电子邮件时尝试检测垃圾邮件并扫描病毒。

Postfix 通过 SMTP (1) 处理传入的电子邮件。Postfix 然后将电子邮件传递给 Amavisd (2)。Amavis 解析收到的电子邮件，递归提取 ZIP 和 RAR 文件等附件，然后将所有文件发送到 Spam Checker Spamassassin 和杀毒 ClamAV (3)。如果电子邮件被认为是干净的，则将其传递给 Zimbra 的代码 (4)。

**符号链接提取逻辑**

unrar面临的挑战之一是恶意制作的 RAR 档案可能包含符号链接。攻击者可以提取指向提取目录之外的符号链接，然后使用第二个文件取消对它的引用。 

  

防止符号链接攻击被证明是复杂的，因为 RAR 存档可以在 Windows 和 Unix 上创建和提取，在文件系统路径处理方面存在显着差异。符号链接也可以是相对的和绝对的。以下是 Unix 和 Windows 文件系统的恶意符号链接示例：

![](../Images/b43afb8dfc5caa553503a2578ff7333e.png)

为了防止对 Unix 系统的符号链接攻击，unrar通过检查第一个字符是否为正斜杠 ( / ) 来禁止任何具有绝对路径的符号链接。

  

验证相对符号链接由IsRelativeSymLinkSafe()函数完成，其片段如下所示：

```
bool Dot2=TargetName[0]=='.' && TargetName[1]=='.' &&(IsPathDiv(TargetName[2]) || TargetName[2]==0) &&(Pos==0 || IsPathDiv(*(TargetName-1)));if (Dot2)// …
```

可以看出，此函数检查符号链接目标是否包含两个点，后跟一个路径分隔符（Unix上的../和 Windows 上的..\\）。当检测到路径遍历尝试时，符号链接被认为是不安全的。

  

**绕过符号链接验证**

我们提到检查符号链接是否包含路径遍历序列（../）有效。但是，这种检查被一种常见的漏洞模式所否定，在这种模式中，不受信任的数据在经过验证后会被修改。

  

一旦符号链接被验证，它就会被unrar标准化。我们之前提到，RAR 存档可以在 Windows 或 Unix 系统上创建，并且这些操作系统会显着处理文件路径。 

  

为确保在 Windows 上创建的 RAR 存档可以在 Unix 系统上提取，反斜杠 ( \\ ) 将转换为正斜杠 ( / )。

  

以下片段显示了当表示符号链接的 RAR 存档条目的类型为FSREDIR\_WINSYMLINK时会发生这种情况，如果存档是在 Windows 系统上创建的，情况就是如此：

  

ulinks.cpp

*

*   
*   
*   

```
if (hd->RedirType==FSREDIR_WINSYMLINK || hd->RedirType==FSREDIR_JUNCTION){// …DosSlashToUnix(Target,Target,ASIZE(Target));}
```

  

DosSlashToUnix ()函数简单地将所有反斜杠转换为正斜杠。攻击者可以利用此行为，因为此操作打破了先前对验证步骤的假设。 

  

让我们假设攻击者制作了一个 RAR 存档，其中包含FSREDIR\_WINSYMLINK类型的符号链接，目标为..\\..\\..\\tmp/shell。由于存档是在 Unix 系统上提取的，因此符号链接目标被认为是安全的，因为没有检测到../序列。

  

但是，由于DosSlashToUnix()的规范化，最终的符号链接目标是../../../tmp/shell。通过利用这种行为，攻击者可以在目标文件系统的任何位置写入文件。

  

与我们的研究一样，我们选择不发布任何利用代码。我们可以在我们的内部研究实例中成功利用这些漏洞，并相信如果威胁行为者还没有重现它，他们将能够重现它。我们强烈建议升级您的系统以使用最新版本的 unrar。

  

  

**Zimbra 的开发利用**

如前所述，当收到带有 RAR 存档附件的电子邮件时，Amavis 会通过unrar自动将其提取以供分析。在 Zimbra 中，包括 Amavis 服务器在内的大多数服务都以zimbra用户身份运行。 

  

因此，文件写入原语允许在其他服务的工作目录中创建和覆盖文件。攻击者可以通过多种方式实现 RCE 影响，此处解释了其中的一些方式，以帮助管理员加强自身抵御这些攻击的能力。

  

**将 JSP shell 写入 web 目录**

最简单的利用路径是在 web 目录中创建一个 JSP shell，这是一个已知路径（/opt/zimbra/jetty\_base/webapps/zimbra/public/）。由于 Jetty 也以zimbra用户运行，因此该目录是可写的。
