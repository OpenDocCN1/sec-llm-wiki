6月21日-反病毒逃逸

CVE-2022-26134 - OGNL 注入漏洞。

利用影响 Atlassian Confluence 7.18 及更低版本产品的远程代码执行漏洞的脚本概念验证。OGNL 注入漏洞允许未经身份验证的用户在 Confluence 服务器或数据中心实例上执行任意代码。


受影响的版本

所有受支持的 Confluence Server 和 Data Center 版本都会受到影响。

Confluence Server 和 Data Center 1.3.0 之后的版本和 7.18.1 以下的版本会受到影响。

该漏洞的 CVSS 得分为 10 分（满分 10 分）的严重性。


依赖项：

Python 3.3+

可以通过 pip install -r requirements.txt 满足依赖关系

特征

加密：

  • 绕过 VirusTotal 上使用的 AMSI 和所有现代 AV（截至撰写时）

  • 压缩和加密 powershell 脚本

  • 具有最小甚至通常为负（由于压缩）的开销

  • 随机化变量名称以进一步混淆解密器存根

  • 随机化加密、压缩甚至语句在代码中出现的顺序以获得最大熵！

  • 超级容易修改以创建您自己的加密器变体

  • 支持递归分层（加密器加密加密输出），测试多达 500 层。

  • 支持 Import-Module 以及标准运行，只要输入脚本也支持它

  • GPLv3——免费和开源！

  • 所有功能都在一个文件中，因此您可以随身携带！

  • 尽管以上所有这些都不是每种配置的灵丹妙药 - 警告购买者！


用法

Import-Module ./xencrypt.ps1Invoke-Xencrypt -InFile invoke-mimikatz.ps1 -OutFile xenmimi.ps1

您现在将在当前工作目录中拥有一个加密的 xenmimi.ps1 文件。您可以像使用原始脚本一样使用它，所以在这种情况下：

Import-Module ./xenmimi.ps1Invoke-Mimikatz

它还通过 -Iterations 标志支持递归分层。

Invoke-Xencrypt -InFile invoke-mimikatz.ps1 -OutFile xenmimi.ps1 -Iterations 100

但是警告，文件可能会变大，生成输出文件可能需要很长时间，具体取决于脚本和请求的迭代次数。
