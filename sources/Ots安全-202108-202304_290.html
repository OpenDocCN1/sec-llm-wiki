介绍

作为一名可靠的黑客，入侵Bank是您必须从清单中划掉的事情之一。对外界来说，银行（Bank）本应拥有无懈可击的安全性，或者至少它们通常是这样推销自己的。更贴近现实，更符合黑客的能干态度，银行与其他组织和行业一样容易受到攻击。


几个月前，我的一个朋友Hussein带着一个有趣的软件来找我，这是一家大型银行正在使用的名为 dotCMS 的软件。这家银行正在运行一个漏洞赏金计划。他知道白盒源代码审计是我的难题，并问我是否可以仔细研究一下，以破坏这家银行。


通过源码分析，可以发现任意文件上传漏洞，可以让我们写入本地系统的任意目录。虽然我们无法在有限的时间内找到可访问 Web 的目录来上传 Web Shell，但我们能够替换系统上已经存在的任意 JavaScript 文件的内容。


这篇博文介绍了在这家大型银行上发现此漏洞的过程和利用过程。


什么是点CMS？

dotCMS 是一个用 Java 编写的开源内容管理系统，用于管理内容和内容驱动的站点和应用程序。


dotCMS 提供其内容管理系统的社区版，可免费下载和使用。他们还提供企业版，这是一种基于 SaaS 的产品，您可以按年或按月订阅购买。


代码分析

dotCMS 是一个 Java 应用程序，用于javax.ws.rs在应用程序中声明 API 路由。由于它使用javax.ws.rs，可以通过在代码库中搜索来很好地理解一些攻击面@Path(——这类似于 Spring 应用程序。


dotCMS 中有很多攻击面，但是我们将重点关注使用javax.ws.rs. 在半天的源代码审计中，我们发现该文件com/dotcms/rest/ContentResource.java包含大量与dotCMS内部“内容”操作（锁定、搜索、上传内容）相关的代码。


我们注意到很多这些 API 端点默认情况下不需要任何类型的身份验证即可访问，并开始深入研究分段文件上传的逻辑。


这个文件中有很多代码，所以让我们一步一步地遍历它，直到我们到达我们的接收器。

使用我们从源代码中推断出的这些信息，我们现在可以构建一个 PoC，它允许我们使用目录遍历在系统上上传任意文件。


不检查文件名或内容，允许我们将任意文件上传到系统以实现命令执行。

漏洞利用

现在，我们不想忘记我们最初审核该软件的原因。我们试图用这个软件入侵一家银行。


不幸的是，与本地开发环境不同，生产环境可能非常复杂，并且软件的部署方式可能与完美的本地环境不同。证明影响并不那么直接。

尽管我们认为我们已经用这个巧妙的技巧获得了成功，但事实证明银行已经强化了他们的环境，并且目录中的任何目录或文件ROOT/html都无法写入。


从理论上讲，在系统上写入任意文件的能力可以通过多种方式导致 RCE（替换 JAR 文件、替换系统文件、通过文件添加系统配置），我们在报告中向团队提到了这一点，但我们仍然想要一个通过我们的任意文件上传来证明影响而不造成任何重大中断的方法。


我们发现了一个小工具来替换 JavaScript 文件，这些文件可以使用我们的任意文件上传来写入。这条链的第一步是通过直接访问来获取 JavaScript 文件的 E-Tag 值：

为了在本地系统上替换这个 JavaScript 文件，我们通过以下规范重建了它所在的本地路径：

filename="../FIRST-CHAR/SECOND-CHAR/FULL-ETAG/fileAsset/FILE-NAME"

所以，在我们的例子中，这是：

filename="../2/3/23f890f7-ac11-30fe-1e50-a4f446a11211/fileAsset/file.js"

使用这个文件名发送我们的 PoC 允许我们写入应用程序提供的任意 JavaScript 文件。


如果有更多的时间，我们相信由于这个错误的性质，我们可以实现命令执行。但是，由于此漏洞影响了属于该银行的 100 多项资产，因此我们报告了该漏洞。
