日志……这些是存储服务器上所有活动的文件。这些用于监控、故障排除、修复错误（漏洞）等等。

为不同的事物记录活动，例如代理、Web 服务器等，但在这里，我们正在学习有关 Web 日志中毒的知识。

那么，Web 服务器可能会记录哪些内容？因此，最常见的是 IP 地址、日期和时间以及 User-Agent。查看最常见的 Web 服务器 Apache 2 的日志：

![](../Images/ce536a7e5e595ccae795c1aabd524593.png)

在上面，您可以看到我在计算机上运行的 Apache 2 Web 服务器的日志。首先是 IP 地址（即本地 IP-127.0.0.1），其次是日期和时间，然后是请求方法、Web 路径、用户代理和其他一些内容。所以我们先来看看我们可以轻松控制什么

*   IP 地址：不，它由 ISP 控制，我们不能在其中注入有效负载
    
*   时间和日期：这是网络服务器上的日期和时间，我们无法控制
    
*   请求方法和路径：可以，可以控制URL和方法。
    
*   用户代理：再次，是的。我们可以控制它。
    

  

**执行攻击**

所以现在，让我们继续讨论我们可以用它执行哪些攻击。管理员和管理员可以手动查看日志。所以最有可能的是他们会在网络浏览器中打开它。那么对此最可能的攻击是什么？最有可能的是 XSS。因此，由于 URL、User-Agent 和 Request 方法是我们可以控制的，我们可以在其中注入有效负载。这将是一个盲目的 XSS，因为负载不会在我们的浏览器上执行（这很可能是在系统管理员的浏览器上）。为此，我们可以使用 XSS Hunter，这是一个免费的 XSS 检测平台。

  

现在假设服务器没有太多空间，因此它可能不会记录所有请求，但它可能会记录错误以进行故障排除并改善用户体验。所以搜索/创建错误：

*   检查所有子域，是否返回 4xx 或 5xx 错误（您可以使用我的工具httpselfie轻松查看所有子域的屏幕截图）
    
*   发送格式错误的请求（下面的命令会导致错误）
    

*   
*   

```
curl -X "<payload_here>" -H "User-Agent: <payload>" http://target.com/<payload>cat <wrong_host_header_request>.txt | nc target.com 80
```

**在失败的登录日志中注入有效负载**

有一些用于监视和管理的服务器的端点，例如/admin，但它们需要登录。它们是非常敏感的端点，因此要记录每个可疑操作。如果我们尝试在所有参数中使用有效负载对其进行暴力破解，那么它可能会被记录（就像上面的 SSH 示例中一样），并且如果在没有适当清理的情况下渲染，那么它将导致有效负载被执行。

  

同样，您可以在有更多机会记录的不同端点注入有效负载。并确保让您的用户代理充满一些有效负载
