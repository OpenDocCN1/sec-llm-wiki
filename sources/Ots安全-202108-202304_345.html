什么是 PDF？

PDF 代表“可移植文档格式”。当您需要保存无法修改但仍需要轻松共享和打印的文件时，使用此格式。今天，几乎每个人的电脑上都有一个可以阅读 PDF 文件的 Adobe Reader 或其他程序版本。


PDF的结构是什么？

PDF 主要分为 3 个部分：-

  1. 对象

  2. 外部参照表，也称为“交叉引用表”

  3. 预告片


1. 对象

PDF 中的对象基本上由文档的内容组成，这些对象存在于文件正文中。对象可以是与图像、字体、注释或任何其他此类数据相关的数据。

在上图中，您可以看到对象在实际 PDF 代码中的样子。首先，我们有对象的名称，在本例中为“1”。第二个数字是“0”，即修订号。它的使用并不多，因为在大多数 PDF 格式中它似乎总是为零。接下来，我们有“obj”部分，它基本上告诉我们整个事物是一个对象。它实际上表示一个对象的开始。


尖括号 ( <<>> ) 表示此对象 1是字典类型。字典是 PDF 文件中常用的数据类型，它包含键值对列表。


紧随其后的是一个字典键，用/Pages表示，2 0 R是字典键的值。在这里，R表示这是一个参考编号，因此它正在寻找此特定实例中的第二个对象。这就是为什么，这里的第一个数字是2。后面的数字是0，即修订号。/Pages字典基本上允许您定义 PDF 中的页数。


在这种情况下，它使用对第二个对象的引用，该对象将定义 PDF 文件中显示的信息。


2. CROSS REFERENCE TABLE（外部参照表）

交叉引用表包含指向 PDF 文件中所有对象的链接。它可用于导航到文件中的其他页面或内容。因此，每当有人更新 PDF 时，它都会在外部参照表中自动更新。

上图描绘了以xref关键字开头的外部参照表。在这里，PDF 文件中的第一个对象从第 10 个位置开始。startxref关键字基本上告诉您外部参照表在文档中的哪个位置开始，因此在此特定实例中，外部参照表从位置编号 413 开始。


3. TRAILER

PDF 代码中的预告片以预告片关键字开头。它基本上包含指向交叉引用表的链接。最后，我们有一个文件结尾(EOF)标记来标记 PDF 文件的结尾。

所以，这就是一个PDF文档的整体结构！

PDF 文件中的解析过程

注入点很可能发生在对象本身中，然后在呈现文档时，有效负载将在对象内部执行。


如何在 PDF 中注入输入？

服务器端 PDF 生成无处不在。它几乎无处不在，就像发票、收据、电子机票、工资单、登机牌一样，而且清单无穷无尽。因此，有很多机会在 PDF 文档中获取用户输入。

如果您将 PDF 注入想象为 XSS 注入并想象您正在注入括号，这与您在 PDF 代码中注入时发生的情况非常相似。

与 javascript 一样，您必须始终确保语法有效。您必须在注射前和注射后修复括号

测试 PDF 生成库的方法

测试 PDF 生成库以检查它们是否易受 PDF 注入攻击的方法包括 3 个主要步骤，识别库中的 PDF 注入漏洞，构建有效负载，然后利用。

  1. 首先，您需要确定是否可以注入括号或反斜杠。

  2. 一旦您确定该库存在漏洞，您就可以尝试查找使用该库的站点。然后，构造一个包含注入的 PDF，该注入通过调用“alert(1)”或使用 submitForm 函数进行回调，该函数将向外部 URL 发送 POST 请求。

现在，这在您不知道 PDF 的结构或内容但仍可能导致注入的盲目场景中很有用，同样在不支持 Javascript 的应用程序上，您可以使用 submitForm 操作并执行回调。

3. 现在，您已经确定您的 PDF 现在已使用注入的有效负载成功呈现，并且您已经收到了回调，在这种情况下，您可以通过使用 submitForm 操作窃取 PDF 的内容来利用它。


避免 PDF 注入风险的补救措施

考虑到库级别，您应该始终确保括号在注释、URL 和文本流中正确转义。PDF 库应始终转义 PDF 字符串，包括括号和反斜杠。

如果我们考虑 Web 应用程序级别，则应始终确保在插入 PDF 之前执行内容验证，以确保没有不需要的 Javascript 或 submitForm 操作。
