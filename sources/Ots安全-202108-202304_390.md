这是一个公开的远程代码执行漏洞的故事，该漏洞不知何故被忽视并且大部分被忽视了四年半，同时被多次重新发现，武器化，并最终在今年 10 月以意想不到的方式得到修复。

  

早在 2017 年 5 月，安全研究员 Shay Ber 就发布了有关影响 Windows DNS 服务的漏洞的详细信息。他们发现DNSAdmins域组的任何成员都可以使用他们的特权让运行 DNS 服务的计算机以本地系统的身份运行任意代码 - 这等于完全接管所述计算机。由于许多域控制器都在运行 DNS 服务，这可能意味着 Windows 域的完全接管。

  

请注意，DNSAdmins是一个强大的群体：能够更改域 DNS 配置允许导致各种问题 - 但它不会自动允许他们接管域。通常，不允许 DNS 管理员登录运行 DNS 服务（通常是域控制器）的计算机，并使用利用远程过程调用 (RPC) 的 DNS 管理工具从他们自己的工作站配置 DNS。

  

Shay 注意到，这些远程过程调用的合法功能由 Windows dnscmd.exe工具方便地提供，可用于远程配置 DNS 服务，以从网络共享加载任意 DLL 并执行其代码。这是由于 DNS 服务在启动时检查注册表值ServerLevelPluginDll的存在，如果存在，则从其中指定的路径加载 DLL。DNSAdmins组的成员可以使用dnscmd.exe工具远程设置此值。

  

在向微软报告此事后，Shay 被告知“它\[将\] 通过基本上只允许 DC 管理员更改ServerLevelPluginDll注册表项来修复，并且它\[将\] 可以在未来版本中关闭此功能。”

  

尽管在他们的文章中，Shay 慷慨地将这个问题描述为“一个可爱的功能（当然不是错误！）”，但不可否认的是，这是一个权限提升——从非域管理员到域管理员——以及一个远程代码执行问题——来自一台可以运行代码的电脑，一台不能正常运行代码的电脑。

  

无论如何，这个问题在很大程度上被遗忘了，可能是因为它的“非错误”分类，直到一年半后另一位安全研究员 Sean Metcalf 在他们的文章中提出。14 个月后，安全研究员 Dhiraj Sharma 重新审视了原始文章并发表了一篇新文章。又过了九个月没有发生任何事情，Metasploit 中添加了一个漏洞利用模块，使各种帽子颜色的攻击者更容易利用此漏洞。我们还没有完成。2021 年 4 月和 5 月，安全研究员Phackt写了一篇关于这个问题的两部分分析，进一步剖析它并阐明“为什么”和提供使用过度许可的DNSAdmins组的替代方法。 

  

最后，今年 10 月的 Windows 更新带来了一个修复程序，指定了问题CVE-2021-40469，并且令人惊讶的是，（仅）承认（仅）Windows 漏洞的定期记者Yuki Chen发现并报告给微软。

  

多好啊。

  

 

  

**微软的修复**

微软在 2021 年 10 月更新的修复完成了 2017 年的承诺：它引入了一个新的注册表项HKEY\_LOCAL\_MACHINE\\SYSTEM\\CurrentControlSet\\Services\\DNS\\InternalParameters，其权限仅允许管理员修改其内容。该ServerLevelPluginDll值已经从移动参数关键就在这新的密钥，使得它不可能与所提供的权限更改DNSADMINS组。据我们所知，这是一个不错的修复。

  

唯一没有修复的是受影响的 Windows 服务器不再接收正式的 Windows 更新：Windows Server 2008 R2 和 Windows Server 2008 没有扩展安全更新。这是我们进来的地方。

  

  

  

**我们的微贴**

与微软的修复程序相比，我们的微补丁，它的全部 19 个 CPU 指令，采用了一些不同的方法。当应用（启用）时，我们的微补丁会强制 DNS 服务忽略ServerLevelPluginDll值，即使它存在于注册表中。基于在谷歌搜索ServerLevelPluginDll并过滤掉有关利用此值的文章时绝对没有命中的情况，我们评估很少有组织在使用此功能，因此简单地删除它 - 我们的补丁有效地做到了 - 是最佳方法。这一决定符合我们使用最少代码修复漏洞的目标。但是，如果客户报告他们正在使用此功能，我们将用功能上更接近 Microsoft 的补丁替换该补丁。
