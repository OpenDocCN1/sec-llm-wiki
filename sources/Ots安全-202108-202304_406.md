**JavaScript 背景**

在讨论如何使用数组值绕过某些输入验证并导致潜在的安全漏洞之前，让我们先回顾一下有关 JavaScript 工作原理的一些基本概念。它们稍后会很有帮助，尤其是在我们讨论原型污染案例研究时。

  

**比较值：===和==**

在 JavaScript 中，有两种不同的运算符可用于比较值： 

*   严格平等 ===
    
*   松散平等 ==
    

它们之间的主要区别之一是，如果两个操作数的类型不同，则===运算符总是返回false（它不执行任何形式的强制）。在==运算符的情况下，如果两个操作数的类型不同，则首先将它们强制转换为公共类型，然后进行比较。有关这些运算符如何工作的更多详细信息，请参阅严格相等运算符和松散相等运算符的官方文档。   

  

以下示例显示了此行为：

*   
*   
*   
*   
*   
*   

```
let a = "test"console.log(a == "test") // trueconsole.log(a === "test") // truelet b = ["test"]console.log(b == "test") // true: ["test"] is first converted to "test" and then comparedconsole.log(b === "test") // false!
```

如果在具有相同值和类型的操作数之间进行比较，则==和===运算符都返回true（第 2 行和第 3 行）。但是，在我们比较具有另一个操作数的相同字符串表示形式的数组的情况下，只有true在使用==运算符时才会返回。在第 6 行，我们看到该值\["test"\]首先被强制转换为其字符串表示，然后与另一个操作数进行比较"test"。在操作数具有不同类型的情况下，运算符===将始终返回false（第 7 行）。

  

注意：上述注意事项也适用于!==和!=不等式运算符。

  

获取值的字符串表示的可能方法有：

*   调用toString()方法（第 2 行）
    
*   使用String函数转换为字符串（第 2 行）
    
*   使用+运算符将值与空字符串连接起来（第 3 行） 
    

*   
*   
*   
*   

```
let arr = ["test"]console.log(arr.toString() === "test") // trueconsole.log(String(arr) === "test") // trueconsole.log(('' + arr) === "test") // true
```

在数组值的情况下，它的字符串表示是由逗号分隔的元素的串联。

  

**属性访问器**

JavaScript 的另一个重要特性是，在使用方括号表示法时，可以指定不同类型（不仅是字符串）的值来访问对象属性。如果该值不是字符串（或Symbol），则首先将其强制转换为字符串，然后用于访问对象属性。

  

让我们考虑以下示例：

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   

```
let obj = {}
let prop1 = ["test"]obj[prop1] = 1console.log(prop1.toString()) // 'test'console.log(obj["test"]) // 1
let prop2 = {} // empty objectobj[prop2] = 2console.log(prop2.toString()) // [object Object]console.log(obj['[object Object]']) // 2
let prop3 = [] // empty arrayobj[prop3] = 3console.log(prop3.toString()) // ''console.log(obj['']) // 3
```

正如我们所见，用于访问属性的键可以是不同的类型。在第 4 行，属性\["test"\]首先转换为字符串（即"test"值），并将此操作的结果用作访问对象属性的键。事实上，如果我们使用第"test"6 行的字符串，我们可以获得第 4 行设置的值。

  

同样，如果我们使用一个空对象{}（第 9 行），其字符串表示为\[object Object\]，写入一个对象值，然后我们可以直接使用该字符串\[object Object\]（第 11 行）访问相同的值。 

  

**String和Array方法**

有一些在String和上定义的内置方法Array，它们具有相同的名称。一些例子是includes，indexOf，lastIndexOf，等。

  

为什么这与这篇博文相关？这些方法的行为有所不同，具体取决于调用它们的输入类型。如果使用这些方法之一来验证用户输入，如果提供了不同类型的输入（例如数组）并且不执行检查，则验证可能容易被绕过。

  

下面的例子说明如何内置两个定义的方法String和Array不同的表现：

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   

```
let a = "<script>"console.log(a.includes("<script>")) // trueconsole.log(a.indexOf("<")) // 0
let b = ["<script>"]console.log(b.includes("<script>")) // trueconsole.log(b.indexOf("<")) // -1
let c = [["<script>"]]console.log(c.includes("<script>")) // falseconsole.log(c.indexOf("<")) // -1
console.log(a.toString() === b.toString()) // trueconsole.log(b.toString() === c.toString()) // true
```

注：在本例中的所有值（"<script>"，\["<script>"\]，和\[\["<script>"\]\]）具有相同的字符串表示。

  

例如，在第 3 行，将调用的方法是String.prototype.indexOf()。此方法将检查字符<是否在字符串中，然后返回其第一次出现的索引，否则返回-1.

  

但是，如果输入是数组，则将调用的方法是Array.prototype.indexOf()，它将检查元素<是否在数组中。由于数组只有一个元素（字符串"<script>"），函数将返回-1，防止对该字符进行可能的清理。 

  

**JavaScript 核心概念总结**

让我们总结一下我们所看到的：

*   如果操作数有不同的类型，===运算符总是返回false 
    
*   可以使用不同类型的键来访问对象属性（使用括号表示法时）
    
*   定义在String和Array类型上的一些内置方法（如indexOf或includes）可能会根据输入的类型而有所不同

**案例研究：原型污染 object-path**

object-path是一个用于使用路径访问深层属性的库。该库还接受一个数组路径，这意味着可以以\['part1', 'part2', etc.\]. 该库已经容易受到原型污染漏洞 ( CVE-2020-15256 ) 的影响。引入的修复如下：

*   
*   
*   
*   

```
if (options.includeInheritedProps && (currentPath === '__proto__' ||  (currentPath === 'constructor' && typeof currentValue === 'function'))) {throw new Error('For security reasons, object\'s magic properties cannot be set')}
```

当路径具有这些危险组件之一（并且它们是字符串）时，此修复程序会正确引发异常。实际上，使用以下有效负载，该函数将引发错误：

*   
*   
*   
*   

```
const objectPath = require('object-path');
objectPath.withInheritedProps.set({}, ['__proto__', 'polluted'], 'yes');console.log(polluted); // Error: For security reasons, object's magic properties cannot be set
```

然而，正如我们之前看到的：

*   当括号表示法用于访问对象属性时，可以使用任何键类型
    
*   该===运算符返回false如果操作数的类型是不同的。如果是  （同样适用于），则条件currentPath === '\_\_proto\_\_'将返回。falsecurrentPath\['\_\_proto\_\_'\]constructor
    

这意味着将危险的密钥包装在一个只有一个元素（密钥本身）的数组中将绕过修复并仍然会导致原型污染：

*   
*   
*   
*   

```
const objectPath = require('object-path');
objectPath.withInheritedProps.set({}, [['__proto__'], 'polluted'], 'yes');console.log(polluted); // yes
```

**修复**

Snyk 于 2021 年 8 月 25 日私下联系了维护者，该问题于 2021 年 8 月 27 日在v0.11.6. 引入的修复通过在检查之前将路径组件转换为字符串（如果它们与数字或字符串类型没有不同）来防止这种情况：

*   
*   
*   
*   
*   
*   
*   
*   
*   

```
var currentPath = path[0];if (typeof currentPath !== 'string' && typeof currentPath !== 'number') {  currentPath = String(currentPath)}var currentValue = getShallowProperty(obj, currentPath);if (options.includeInheritedProps && (currentPath === '__proto__' ||  (currentPath === 'constructor' && typeof currentValue === 'function'))) {throw new Error('For security reasons, object\'s magic properties cannot be set')}
```

以前的有效载荷将不再起作用：

*   
*   
*   
*   

```
const objectPath = require('object-path');
objectPath.withInheritedProps.set({}, [['__proto__'], 'polluted'], 'yes');console.log(polluted); // Error: For security reasons, object's magic properties cannot be set
```

  

**案例研究：edge.js 中的跨站脚本 (XSS)**

edge.js是一个 Node.js 模板引擎。该库具有内置功能，可以启用这些功能以防止安全漏洞，例如 XSS。特别是，根据文档“插值的输出（花括号内的代码）是HTML转义以避免XSS攻击”。负责转义 HTML 危险字符以防止 XSS 的原始函数如下：

*   
*   
*   
*   
*   
*   
*   
*   

```
// https://github.com/edge-js/edge/blob/1ade7fbb81fbc1b52757650214d6baca140d3eb0/src/Template/index.ts#L183public escape<T>(input: T): T extends SafeValue ? T['value'] : T {return typeof input === 'string'    ? string.escapeHTML(input)    : input instanceof SafeValue    ? input.value    : input}
```

正如我们所看到的，input只有当它是 类型时才被 HTML 转义string。这意味着，如果用户控制的输入是 object 类型（即数组）而不是 a SafeValue，即使{{ }}在模板中使用，它也会被返回而不被转义（没有错误或异常返回），从而导致潜在的 XSS脆弱性。
