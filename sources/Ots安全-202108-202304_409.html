今年早些时候，我正在评估一个包含 Parallels Remote Application Server (RAS) 的网络。Parallels RAS 是一种远程工作解决方案，可提供对虚拟桌面和应用程序的访问。它可以在 Windows 和 Linux 上运行，通常可以在标准 HTTPS 端口上看到。


该平台之前曾受到目录遍历缺陷的影响。该问题允许未经身份验证的远程攻击者利用该漏洞从易受攻击的系统读取任意文件 (CVE-2017-9447)。


在这种情况下，测试表明 RAS 服务不再容易受到目录遍历缺陷的影响，该问题已在 2017 年 9 月发布的 RAS 版本 15.5 Update 4 中得到缓解。


但是，已经确定了一个似乎与先前缺陷的修复相关的问题。虽然不再可能通过目录遍历缺陷检索/读取文件。发现可以通过利用相同的负载来确定远程 RAS 服务器上是否存在文件或文件夹。这可以通过收到的不同服务器响应来实现：


存在文件夹/文件时收到 HTTP 403（禁止）响应

当文件不存在时收到 HTTP 404（未找到）响应


对于 Windows 安装，可以从未经身份验证的角度利用此问题来枚举有效的本地 Windows 用户名，假设它们在目标系统上有一个主目录。一旦枚举了帐户名称，它们显然会受到密码猜测攻击。

受影响的版本：

原始文件目录遍历缺陷CVE-2017-9447在 2017 年 9 月发布的 RAS 版本 15.5 Update 4 中得到修复。


此处讨论的文件存在/用户名枚举缺陷已在 2020 年 7 月发布的 RAS 版本 17.1.2 中修复。最终由于非最佳修复，此问题已存在近 3 年。


尽管与供应商进行了沟通，但他们还是选择在原始 2017 CVE 下报告这个新的 2020 缺陷的修复程序，最终与具有不同影响的问题相关。
