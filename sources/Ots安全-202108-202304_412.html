介绍

2008 年 2 月，我发表了一篇名为横向 SQL 注入 [1] 的论文，介绍了一种新颖的方法通过以控制格式的方式操纵环境来利用 SQL 注入缺陷数据类型，例如 DATE。这种环境操纵开辟了一个攻击向量，以前可以利用无法利用的问题。上一篇论文 [1] 通过证明即使 NUMBER 数据类型可以被操纵以促进利用，但它忽略了利用细节。本文提出那些缺少的利用细节，以便读者可以充分了解该技术的工作原理。必须预先强调，虽然这些发现很重要，但利用在一定程度上是有限的：攻击者需要 CREATE PUBLIC SYNONYM 系统特权作为实施此攻击的先决条件，这有助于降低风险。人们不应仅仅相信这一先决条件来负担得起保护，因为将来可能会发现绕过此特权需求的方法。相反，它是使用变量绑定的最佳实践是为了完全减轻这种技术带来的风险。


利用数字连接

为了理解所呈现的技术，从一个示例程序开始是有帮助的。容易受到 SQL 注入攻击。图 1 中的 PL/SQL 代码包含一个易受攻击的示例过程名为 NUM_PROC。

CREATE OR REPLACE PROCEDURE NUM_PROC(n NUMBER)ISstmt VARCHAR2(2000);BEGINstmt := 'select object_name from all_objects where object_id = ' || n;EXECUTE IMMEDIATE stmt;END;

图1

图 1 中的代码创建了一个名为 NUM_PROC 的过程，它将名为 n 的数字作为输入。这输入连接到第 5 行的 SQL 查询，然后在第 6 行执行。参数第 1 行的定义指定必须传递 NUMERIC 数据类型，第 5 行转换 NUMERIC数据类型为连接前的字符串。由于无法注入 SQL 字符串，因此这段代码可以被认为是无懈可击的 SQL 注入。然而，如果我们探索操纵通过将这个数字转换为字符串的方式，我们可以扩大我们对执行的 SQL 语句的影响在第 6 行。


操作 NUMERIC 到字符串转换的一种方法是更改用于表示小数点分隔符。根据[3]，Oracle使用会话变量NLS_NUMERIC_CHARACTERS 将 NUMERIC 值转换为字符串时。的格式NLS_NUMERIC_CHARACTERS 是一个字符串，其中第一个字符指定小数点分隔符和第二个字符指定组分隔符。对于一个具体的例子，考虑在图 2。

 SQL> SELECT TO_NUMBER('1.01', '0D00') FROM dual; TO_NUMBER('1.01','0D00') ------------------------ 1.01 SQL> ALTER SESSION SET NLS_NUMERIC_CHARACTERS='P '; Session altered. SQL> SELECT TO_NUMBER('1P01', '0D00') FROM dual; TO_NUMBER('1P01','0D00') ------------------------ 1P01

图2

图 2 中的会话显示了一种检查 NUMERIC 值在转换为字符串。在图 2 中，第 1 行调用 TO_NUMBER 函数指定值 1.01。在第 1 行调用该函数后，函数 TO_NUMBER 将接受字符串输入并将其转换为 NUMERIC 值。当该值显示在第 4 行时，它是从NUMERIC 值 1.01 回到字符串值“1.01”。


图 2 中第 5 行的命令将 NLS_NUMERIC_CHARACTERS 的值更改为一个值指定十进制字符应为 P 字符，组分隔符应为空格特点。当在第 7 行再次调用 TO_NUMBER 时，第 10 行的输出现在是“1P01”，如与之前的“1.01”输出相比。读者应该注意到 ALTER SESSION 权限是不需要像第 5 行那样更改 NLS_NUMERIC_CHARACTERS 的值。


虽然图 2 中显示的字符串操作展示了我们影响转换的能力从 NUMERIC 值到字符串，图 2 中的示例对于利用 NUM_PROC 没有多大用处。直接的问题是分词器不会转换数字后跟字符后跟数成任何有价值的东西。然而，碰巧的是，Oracle 会在如果整数部分为零，则为十进制字符。

 SQL> ALTER SESSION SET NLS_NUMERIC_CHARACTERS='P '; Session altered. SQL> SELECT TO_NUMBER('0P01', '0D00') FROM dual; TO_NUMBER('0P01','0D00')  ------------------------ P01

图 3

如果我们可以导致 NUMERIC 到字符串的转换导致字符串被错误解释tokenizer 作为 NUMERIC 以外的东西，这对利用 NUM_PROC 会有一些用处。图 3 展示了我们以生成的方式操作 NUMERIC 到字符串转换的能力一个有效的对象标识符。在第 3 行，表示为“0P01”的值 0.01 被转换为数字函数 TO_NUMBER 以及当返回值转换为字符串以供在线显示时6、转换为“P01”。您可以在图 4 中看到将值 0.01 传递给NLS_NUMERIC_CHARACTERS 值已更改的 NUM_PROC 过程。
