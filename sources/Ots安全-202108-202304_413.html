一位安全研究人员解释了如何通过 HTTP 标头走私攻击利用亚马逊网络服务 (AWS) API 网关中的弱点。


Intruder 的研究员兼渗透测试员 Daniel Thatcher 在11 月 10 日的博客文章中表示，标头走私——一种相关的新型请求走私技术——可用于隐藏选定服务器的 HTTP 请求标头，同时让其他人看到它们.


在服务器链期间篡改请求的可见性可导致成功部署恶意请求和请求走私。后端和前端服务器上的不匹配请求可能会导致数据和机密泄露，以及绕过 IP 限制和缓存中毒。


绕过安全控制

Thatcher 创建的标头走私方法在标头请求中创建了一个突变，旨在将其发送到后端基础设施，而无需由受信任的前端服务处理。


Thatcher 说，在扫描漏洞赏金计划时，他观察到使用 AWS API Gateway 的 API 允许标头走私。


如果攻击者在空格后将字符附加到标头名称 - 例如，通过将X-My-Header: test切换为X-My-Header abcd: test，则会发生突变，从而导致 Amazon 的安全控制被规避。


此外，前端的服务器正在剥离和重写X-Forwarded-For标头，使其容易受到类似的篡改——因此，AWS 资源策略 IP 限制绕过。


“后端服务器通常依赖前端服务器在 HTTP 请求标头中提供准确的信息，”撒切尔说。“[要]准确提供这些信息，前端服务器必须过滤掉客户端提供的这些标头的值，这些标头是不受信任的，不能依赖于准确。”


但是，当采用报头走私时，可以避免这些过滤器，并且可以将信息发送到后端系统，在那里它被视为可信数据。


协调披露

撒切尔夫人将他的发现报告给了 AWS安全团队，IP 规避问题很快得到解决。


但是，经过进一步测试，网络安全研究人员表示，仍然可以使用相同的变异方法和Host标头将标头走私到后端服务器，从而导致“容易被利用的缓存中毒问题”。


在渗透测试中，研究人员还在 AWS 资源访问和控制应用程序 AWS Cognito 中发现了类似的 IP 限制绕过问题。


在这种情况下，该漏洞被认为“非常小”，因为它允许攻击者在可疑 IP 地址被阻止之前总共只发出 10 次忘记密码请求。
