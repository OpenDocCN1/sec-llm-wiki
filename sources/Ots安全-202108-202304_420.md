**执行摘要**

SentinelLabs 在 Linux 内核的 TIPC 模块中发现了一个堆溢出漏洞。

该漏洞可以在本地或远程网络内被利用以获得内核权限，从而允许攻击者破坏整个系统。

  

TIPC 模块随所有主要 Linux 发行版一起提供，但需要加载才能启用该协议。

10 月 29 日发布了一个补丁，影响了 5.10 和 5.15 之间的内核版本。

目前，SentinelOne 尚未确定野外滥用的证据。

**什么是 Linux TIPC 协议？**

透明进程间通信 (TIPC) 是一种协议，它允许集群中的节点以一种可以最佳处理大量剩余容错节点的方式相互通信。

  

为了使本节保持简短，本文将重点介绍关键组件。有关实际 TIPC 协议的更详细和高级描述，包括执行消息传递的各种方式以及服务跟踪的工作原理，最好参考官方 sourceforge 页面。

  

该协议在所有主要 Linux 发行版打包的内核模块中实现。当由用户加载时，它可以用作套接字，并且可以使用 netlink（或使用tipc将执行这些 netlink 调用的用户空间工具）作为非特权用户在接口上进行配置。

  

TIPC 可以配置为在诸如以太网或 UDP 之类的承载协议之上运行（在后一种情况下，内核在端口 6118 上侦听来自任何机器的传入消息）。由于低权限用户无法创建原始以太网帧，因此将承载设置为 UDP 可以更轻松地编写本地漏洞利用程序。

  

尽管在这些协议之上使用了 TIPC，但它有一个单独的寻址方案，节点可以借此选择自己的地址。

  

TIPC 协议以对用户透明的方式工作。所有消息构建和解析都在内核中执行。每个 TIPC 消息都有一个通用的头格式和一些特定于消息的头（因此头的总大小可变）。

**TIPC 漏洞概述**

2020 年 9 月，引入了一种名为 的新用户消息类型MSG\_CRYPTO，它允许对等方发送加密密钥（目前似乎仅支持 AES GCM）。这是2021 年 TIPC 路线图的一部分。

  

消息的正文具有以下结构：

*   
*   
*   
*   
*   

```
 struct tipc_aead_key {  char alg_name[TIPC_AEAD_ALG_NAME];  unsigned int keylen;   /* in bytes */  char key[]; };
```

哪里TIPC\_AEAD\_ALG\_NAME是 32 的宏。当收到此消息时，TIPC 内核模块需要将此信息复制到该节点的存储中：

*   
*   
*   
*   
*   
*   
*   
*   
*   

```
 /* Allocate memory for the key */  skey = kmalloc(size, GFP_ATOMIC);/* ... */
  /* Copy key from msg data */  skey->keylen = ntohl(*((__be32 *)(data + TIPC_AEAD_ALG_NAME)));  memcpy(skey->alg_name, data, TIPC_AEAD_ALG_NAME);  memcpy(skey->key, data + TIPC_AEAD_ALG_NAME + sizeof(__be32),         skey->keylen);
```

用于分配的大小与消息有效负载的大小相同（根据从消息大小中减去头大小计算得出）。密钥算法的名称被复制，然后密钥本身也被复制。

  

如上所述，标头大小和消息大小都根据实际数据包大小进行验证。因此，虽然这些值保证在实际数据包的范围内，但对于消息的keylen成员MSG\_CRYPTO或密钥算法名称本身TIPC\_AEAD\_ALG\_NAME的大小( ) 没有针对消息大小的类似检查。这意味着攻击者可以创建一个体型较小的数据包来分配堆内存，然后使用keylen属性中的任意大小写入该位置的边界之外：

**CVE-2021-43267 的可利用性**

此漏洞可在本地和远程利用。由于对内核堆中分配的对象的更大控制，本地利用更容易，由于 TIPC 支持的结构，可以实现远程利用。

  

至于被覆盖的数据，乍一看似乎溢出将包含不受控制的数据，因为用于分配堆位置的实际消息大小已得到验证。但是，再次查看消息验证函数会发现它只检查报头中的消息大小是否在实际数据包的范围内。这意味着攻击者可以创建一个 20 字节的数据包并将消息大小设置为 10 字节而不会失败：

*   
*   

```
if (unlikely(skb->len < msz))    return false;
```

**修复**

由于此漏洞是在引入代码库后一年内发现的，因此 TIPC 用户应确保其 Linux 内核版本不在 5.10-rc1 和 5.15 之间。

  

**结论**

SentinelLabs 进行的漏洞研究使我们能够在恶意行为者之前识别和修复漏洞，从而在全球范围内保护用户。就 TIPC 而言，该漏洞在其引入代码库后的一年内就被发现。虽然 TIPC 本身不是由系统自动加载，而是由最终用户自动加载，但从非特权本地角度配置它的能力以及远程利用的可能性使其成为在其网络中使用它的人的危险漏洞。更令人担忧的是，利用此漏洞的攻击者可以在内核中执行任意代码，从而导致系统完全被攻陷。
