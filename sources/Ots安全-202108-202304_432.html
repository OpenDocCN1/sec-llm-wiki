介绍

跨站脚本攻击，也称为 XSS，是一种安全漏洞，涉及将恶意脚本注入正常安全的网站。此注入旨在影响网站的其他用户。注入包含的 XSS 负载alert(1)允许在执行负载时弹出一个窗口。弹出的窗口证明有效载荷已运行。因此，基于这里的代码被执行，有可能是注入恶意代码的潜力。这也是一种通过漏洞赏金报告的漏洞！


警报(1) XSS Payload

使用alert(1)XSS 负载的第一个明显优势是它非常直观。您可以注入代码并在它执行时非常清楚地看到这对于具有大量输入的网页来说很方便。通过改变 JavaScriptalert()函数的参数，您可以快速定位 XSS 注入起作用的位置。

使用 的第二个好处alert(1)是，有一些带有模板的客户端浏览器 JavaScript 框架允许某些有限形式的 JavaScript，例如打印范围变量或进行相对基本的数学运算。由于框架施加的限制，您实际上无法注入恶意代码，但您可以使用window.alert(1)，因为该window对象是网页功能所必需的。同一个window对象还包含攻击者最感兴趣的信息，例如window.localStorage或window.document.cookie。在这种情况下，成功执行alert()可能表明您的 XSS 发现具有很高的严重性，应该报告。

alert(1) 在它所有

不完全是，不幸的是。让我们来研究一下原因。通过在我们的代码中更改alert(1)为alert(document.domain)，我们有一个有效负载，它将告诉我们我们实际将代码注入到哪个域。在我们的例子中，它是usersubdomain.blogspot.com，而不是 blogger.com。如果您使用开发人员工具查看网页代码，原因就很清楚了。你会看到blogger.com网页嵌入usersubdomain.blogspot.com在一个网站iframe，有效载荷发送到后者的领域，这解释了为什么触发没有输出blogger.com，而是usersubdomain.blogspot.com。


此时我们问自己的一个重要问题是：为什么 Google 会使用两个不同的域来实现博客服务？嗯，XSS就是原因。为了保护他们自己和他们的用户，他们使用沙箱，正如这里提到的。

沙盒

谷歌特别规定他们使用


一系列沙盒域，以安全地托管各种类型的用户生成的内容。其中许多沙箱专门用于隔离用户上传的 HTML、JavaScript 或 Flash 小程序，并确保它们无法访问任何用户数据。

那么这一切有什么重要的呢？XSS 攻击的重点是访问您认为不允许访问的数据。以另一个用户的cookies为例；这些将在blogger.com域中，因此由于同源策略，从usersubdomain.blogger.com网站使用的 XSS 攻击无法访问 cookie。同源策略确保第一个网页中包含的脚本只有在页面具有相同的来源时才能访问第二个网页。在我们的例子中，我们的博客和它的脚本在我们的沙箱中，但它不能访问任何其他人的沙箱，因为这些网页没有相同的来源。


单源策略确保我们上的 XSSusersubdomain.blogspot.com无法访问 上的 cookie blogger.com。

这就是我们想要使用alert(document.domain)或alert(window.origin)有效载荷的原因；这样做可以准确地告诉我们 XSS 在哪个域上执行，也就是我们可以访问的域。在这种情况下，它是usersubdomain.blogger.com.


总而言之，Google 允许用户向他们的博客添加自定义 HTML（以及 JavaScript）功能，以便用户有机会进一步自定义内容。这是一个很棒的功能！为确保此功能不能用于通过 XSS 注入攻击其他博主，他们将每个用户的数据置于其沙盒环境中，然后blogger.com使用iframe. 因此，利用XSS有效载荷，使用的时候alert(document.domain)还是alert(window.origin)这样你就可以确信什么域或子域的XSS是越来越上执行。这是确定您发现的是实际安全问题还是无用问题的决定性因素。
