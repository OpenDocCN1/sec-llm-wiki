什么是Pardus？

Pardus 是 在土耳其政府的支持下开发 的 Linux 发行版。Pardus 的主要重点是与办公室相关的工作，包括在土耳其 政府机构中的使用。尽管如此，Pardus 以多种语言提供服务。它的易用性和免费可用性已经在世界各地催生了众多社区。[1]


在开发自己独特的身份之前，它作为一个基于 Gentoo 的项目开始了它的生命。自 2012 年底以来，该发行版基于 Debian GNU/Linux。


它是基于 Debian 的发行版。那么，目标在哪里？

2009 年，我曾经是 Pardus 的志愿者之一。在那个年代，这是一个非常出色且充满希望的项目。但是 Pardus 选择将他们的 Linux 基础转移到 Debian。据我所知，从 2012 年开始，他们主要围绕新内核开发包。


出于这个原因，我决定不加考虑地专注于包管理器的 GUI。

漏洞：不安全提取

在我审查该项目的过程中，我的脑海中出现了一个问题。这些应用程序图标来自哪里？不可能通过一个 Pardus 包运送所有图标，是吗？


以下函数取自MainWindows.py文件，在第 706-712 行之间。所以看起来图标来自服务器。

    def getIcons(self):        if self.Server.connection:            # self.splashbar.pulse()            print("Getting icons from server")            self.splashlabel.set_markup("<b>{}</b>".format(_("Getting icons from server")))            self.serverappicons = self.Server.getAppIcons()            self.servercaticons = self.Server.getCategoryIcons()

让我们看看它是如何获取和使用图标的。getAppIcons() 在 Server.py 文件中定义。

    def getAppIcons(self):        if not self.isExists(self.cachedir + self.serverappicons):            print("trying to downlad " + self.serverappicons)            try:                response = requests.get(self.serverurl + self.serverfiles + self.serverappicons + self.serverarchive)            except:                print(                    "server error getting " + self.serverurl + self.serverfiles + self.serverappicons + self.serverarchive)                return False            if response.status_code == 200:                if self.createDir(self.cachedir):                    with open(self.cachedir + self.serverappicons + self.serverarchive, "wb") as file:                        file.write(response.content)                    if self.extractArchive(self.cachedir + self.serverappicons + self.serverarchive,                                           self.serverappicons):                        return True                return False            else:                print("{} : {}".format("error getting app icons, status code", response.status_code))                return False        else:            return True

简而言之，Pardus 软件中心将图标作为档案提取并在第 15 行提取它们。听起来不错。但我必须问两个问题：

1 – 任何类型的网络级加密？

2 – 它如何提取档案？

先来看看Server的类变量，回答第一个问题。其实，这应该不是问题。因为它获取了一个包含大量图像的无害存档文件。

我在存档文件中没有看到对文件名的任何验证。当文件具有目录遍历目标时，tarfile 包的 extractall() 方法不会将文件提取限制到不同的路径。（例如：../../../backdoor.sh）。存档文件通过 HTTP 流量获取。你看我要去哪里..

额外发现：隐私问题：HTTP 上的 Mac 地址泄漏

在研究过程中，我发现 Pardus 软件中心正在发送一个 HTTP POST 请求（到 store.pardus.org.tr ），其中包含用户单击应用程序图标时计算机的 MAC 地址。
