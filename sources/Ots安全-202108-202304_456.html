TL;DR：与 PhantomJs 一起运行的 PDF 导出功能无法读取带有文件协议的 iframe 的本地文件，但通过简单的 AJAX 读取，我们可以获得任何本地文件或服务的内容。

大家好，希望你们今天过得愉快，这是我写的一篇关于最近在 PhantomJs 中找到的 SSRF 的新文章。


故事开始于我在 HackerOne 上收到一个私人程序的新邀请，这个程序对我来说很有趣，因为我喜欢程序的类型，它是关于仪表板和面板的……


无论如何，我开始检查程序中哪些功能可以被滥用，并且能够找到一些 XSS 和访问控制中断问题，但我想在该程序中找到一些关键的东西，所以我开始检查更多的功能，我遇到了一个页面将用户的历史记录记录在他的帐户中，它有一个包含一些信息的表格，如（姓名、时间、页面、操作等），还有一个按钮可以将此日志导出为 CSV 或 PDF。


肯定存在 CSV 注入问题，但我对 PDF 感兴趣，我想如果我能在其中一列中找到 XSS，我将能够在 PDF 导出中注入我的自定义 HTML/J，所以我进行了测试用户可以控制的所有列......不幸的是，它们都被清理了，我又想也许PDF导出没有与表单连接，导出时我可以执行HTML，所以我测试了我的名字并导出但是它没有用:(


第二天，我又开始想我必须对这个进行更多测试，因为我已经涵盖了大部分应用程序，这是最后一部分，所以我再次考虑测试所有列，但使用 PDF 导出......工作😎，一列存储了一些难以追踪的发布请求中的值，但最终当我这样做时，它没有做任何事情，直到我导出 PDF 并且我看到我的<img src=xhzeem>有效负载在 PDF 文件中显示了一个图像。


现在是时候检查我在处理什么了，所以我开始向hookbin.com注入一个 iframe ，我得到了这个：

我确认iframe是从服务器的IP地址加载的，发现他们是用PhantomJs导出这个PDF文件的，现在想着/etc/passwd直接读文件，于是尝试了iframe file:///etc/passwd，结果只是返回一个空白页 ：（


我想我现在必须测试 javascript，所以我首先用一个简单的 payload 进行了测试<script>document.write('xhzeem')</script>，它奏效了！


导出的列只有一个词xhzeem，表示支持我的 javascript，这里我测试的第一件事是检查我是否在 afile或http协议中，所以我使用了以下有效负载

<script>document.write(JSON.stringify(window.location))</script>

我得到了整个位置对象，我看到我在file:///tmp/export/[UUID].html每次再次导出它时都会创建一个新的唯一 UUID，然后我考虑使用测试当前页面上的 iframe

<script>document.write('<iframe src="'+window.location.href+'"></iframe>')</script>

并且整个页面都是内部框架的......所以我应该能够访问file://协议，但出于某种原因，PhantomJs 阻止了这个访问，因为我无法理解为什么我无法对页面进行 iframe 我留下了 XHR为我读取文件，然后我开始创建有效负载

<script>    xhzeem = new XMLHttpRequest();    xhzeem.open("GET","file:///etc/passwd");    xhzeem.send();    xhzeem.onload = function(){document.write(this.responseText);}    xhzeem.onerror = function(){document.write('failed!')}</script>

希望你从中学到了一些东西，最重要的是永远不要测试某些端点并期望应用程序的其余部分表现相似，始终单独测试每个可能的错误。
