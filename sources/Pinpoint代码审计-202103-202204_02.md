# 我的自述

  大家好，我是pinpoint，我本身的意思是在人海茫茫中找到“你”，而这个“你”意思就是bug，简单说一下就是我会在很多代码中找到这个bug。

  我整个系统叫软件静态代码分析系统，静态就是我不运行这个程序，就可以直接对他进行分析。

  我分析的目标有两种：第一种是分析源代码，第二种是分析源代码编译后的结果也就是二进制代码。我的核心分析技术是基于编译结果进行分析的，主要找的问题有这么几类：

  第一是代码缺陷，其实就是找bug，编译器本身其实也能找到一部分bug，编译器找bug的原理在很多情况下也跟我们类似，但是编译器主要工作是产生可以运行的代码，所以一是他不可能花很多时间找bug，二是有些bug他没有办法去深度挖掘，而我就是在它的基础上去找更深入更多的bug。

  第二是编码规范的违反，相对应的就是使用后IDE编写的代码，IDE在我们写代码的时候会报出一部分错误直接提示给我们，我们这方面的原理跟这个差不多，但是我们的编码规范也有一些很复杂的编码规范。

  第三类就是恶意行为，恶意行为就是代码本身在做坏事，比较常见的就是比如说APP里面在偷你的联系人或者是当前你的位置信息之类的，还有一类就是违规行为，违规行为的意思是一些不应该出现在代码里的东西。

  你们为什么要用到我呢？一是为什么要用自动化扫描？二是自动化扫描可以实现什么东西做一些人做不到的事情？

  第一个原因是可行性，现在我们的代码是很多的，如果人工看的话，除非是对代码很熟悉的人，如果换一个人，哪怕是经验很丰富的人他也需要很多精力去看这个东西。

  第二个原因是时效性，就是说人都有疲倦的，人看代码第一遍可能有兴趣，但是如果一直看，第二遍第三遍天天看一样的东西是会疲劳的，但是如果我看的话就不会疲劳，而且不会厌烦。

  第三个原因是可度量性，就是人们对代码熟悉程度不一样，或者本身的水平不一样，都会影响分析的结果，用软件检测的话相对来说比较客观一点。

  第四个原因就是流程化，很多说做项目开发上线的时候，才会发现一些问题，而这时他们会开复盘会，复盘程序出现的事故是什么情况，以后我们通过什么方法去避免这些问题。一般来说，开发工程师在会上就会说以后不会这么写了，要换成XXX更有效率或者安全的方法，但是安全工程师是不可能随时盯着开发工程师进行代码编写的，而我就可以随时盯着开发工程师，来避免因开发不当导致的事故复现。

  其实我刚开始不是商业产品，是香港科技大学有一个互联网安全实验室，他们研究的内存安全问题，几个博士生研究了七八年，然后在深圳注册了公司，把我商业化并做了很多对企业开发流程的优化。

  第一是本身检查的优化，我们发现对开发者来说，他对误报率速度要求很高。

  第二是开发流程的优化，使其真的在开发流程中能用起来。

  第三个是本地化的团队，国内少有的自己在做这个技术的团队。
