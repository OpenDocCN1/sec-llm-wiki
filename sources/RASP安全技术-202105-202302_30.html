传统检测方式


        传统检测方式，只查看进程打开的文件，对于java进程来说会检测打开的jar文件，然后分析jar文件的版本和依赖。这种方式存在2个问题：


  • 不准确。磁盘检测方式，只能关注文件是否被进程打开，而不能检测文件是否被真正被JVM加载，因为JVM对于类文件是懒加载方式，存在一定程度的误报；


  • 性能低。为了准确性，会全量扫描web运行根目录，这个过程会检测大量文件，效率非常低，对系统IO影响大；


以open-sca(https://github.com/XmirrorSecurity/OpenSCA-cli)

为例说明磁盘检测的原理。

  • 检测的核心还是选择web运行根目录


  • 解析各个文件节点获取依赖信息

  • 排除pom中不包含的依赖信息



检测耗时长达10分钟（jar包版本的检测必须依赖mvn仓库）


RASP检测原理


    RASP注入到业务进程里面，可以在运行时获取JVM运行时信息，包括加载了哪些类、jar包以及版本等信息。真正做到了准确无误报、无大量磁盘读写的高性能。

  • 获取加载的jar包绝对路径

    例如在业务中使用到了fastjson包，我们只需要获取fastjson中一个class对象即可

import com.alibaba.fastjson.JSONObject;
import java.security.ProtectionDomain;
public class Main {    public static void main(String[] args) {        ProtectionDomain protectionDomain = JSONObject.class.getProtectionDomain();        System.out.println(protectionDomain.getCodeSource().getLocation());    }}

输出结果：fastjson包文件的绝对路径

file:/Users/xxx/.m2/repository/com/alibaba/fastjson/1.2.78/fastjson-1.2.78.jar

  • 获取已经加载的全部class对象即可


dependency 插件


    依托JRASP灵活的架构，可以增加依赖jar包的检测插件，并且插件在运行时即可生效，无需重启进程。

    复制插件模版实现jar包检测逻辑，即可以实现jar包检测逻辑：


01

功能基础


    JRASP将java.lang.instrument对象注入到插件module中，使得插件具备强大的功能。instrument包不仅是进行类转换的核心工具包，还可以获取系统已经加载的全部类，功能非常强大。

02

具体实现

  • 给模块注入instrument对象

@Resourceprivate Instrumentation instrumentation;

    给模块注入对象的具体实现参考jrasp-agent实现：https://github.com/jvm-rasp/jrasp-agent/blob/master/jrasp-core/src/main/java/com/jrasp/core/manager/impl/DefaultCoreModuleManager.java#L307


  • 获取已经加载的全部类

Class[] allLoadedClasses = instrumentation.getAllLoadedClasses();

  • 获取类所在的jar包绝对路径

Class clazz = allLoadedClasses[i];                                                            ProtectionDomain domain = clazz.getProtectionDomain();                                        if (domain != null &&                                                                                  domain.getCodeSource() != null &&                                                               domain.getCodeSource().getLocation() != null) {                                           String path = domain.getCodeSource().getLocation().getPath();                                 if (path != null && path.length() > 0) {                                                          if ((path.endsWith(".jar")                                                                            || path.endsWith(".jar!")                                                                     || path.endsWith(".jar!/")                                                                    || path.endsWith(".jar/")                                                                     || path.endsWith(".jar!" + File.separator))                                                  ) {                                   if (!path.endsWith(".jar")) {                                                                     int start = path.contains("/") ? path.indexOf("/") : path.indexOf("\\");                      path = path.substring(start, path.lastIndexOf(".jar") + 4);                               }                                                                                             System.out.println("jarPath="path);                                                                 }                                                                                         }                                                                                         }

  • jar包版本和依赖检测

这部分检测与磁盘检测方式实现是相同，不再重复。值得一提的是，这部分可以在jrasp-daemon(单独的进程)中完成，从而降低对宿主jvm的影响。这部分实现参考open-rasp。
