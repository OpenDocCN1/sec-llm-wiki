# Apache Tomcat信息泄露漏洞(CVE-2021-24122)

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=Mzg5MjQ1OTkwMg==&mid=2247483747&idx=1&sn=f6d4435c4ffb630a77eb1cdebdcd1931&chksm=c03c8f72f74b06644ee8ca975c0cec6514a11490bf528e7672e3b08cbdbc63352bd7685057a1&scene=126&sessionid=1681366133#rd](http://mp.weixin.qq.com/s?__biz=Mzg5MjQ1OTkwMg==&mid=2247483747&idx=1&sn=f6d4435c4ffb630a77eb1cdebdcd1931&chksm=c03c8f72f74b06644ee8ca975c0cec6514a11490bf528e7672e3b08cbdbc63352bd7685057a1&scene=126&sessionid=1681366133#rd)

**背景介绍      **

    Tomcat是Apache软件基金会下属的Jakarta项目开发的一个Servlet容器，实现了对Servlet和JavaServer Page（JSP）的支持，由于Tomcat本身也内含了一个Http服务器，它也可以被视作一个单独的Web服务器。

  

**漏洞详情**

    2021年01月4日，Apache官方发布安全公告，公开了Tomcat的一个信息泄露的漏洞（https://cve.mitre.org/cgi-bin/cvename.cgi?name=CVE-2021-24122）。

 官方描述如下：

![](../Images/27e048504c4053ac68e57265bbfd87ed.png)

大体意思是说由于Windows平台上的API在某些情况下获取路径的行为与JDK的getCanonicalPath函数获取的路径不一致导致了tomcat的信息泄露。  

  

    目前影响范围波及下面这些tomcat版本：

    Apache Tomcat 10.0.0-M1-10.0.0-M9  
    Apache Tomcat 9.0.0.M1-9.0.39  
    Apache Tomcat 8.5.0-8.5.59  
    Apache Tomcat 7.0.0-7.0.106

  

**Exploit**

*   下载一款受影响的tomcat部署到windows平台，这里做实验选取的是8.5.54版本；
    
*   启动tomcat服务器，正常访问：/examples/jsp/plugin/plugin.jsp，可以看到页面加载成功

**拓展**

从这个漏洞可以深思如下一些点：  

*   漏洞的攻击大多数情况下不是一个或者几个攻击点的事，与业务本身、组件、平台以及操作系统都是密切相关的，就如上面看到的，单单JDK组件是无法引起这个问题的，windows平台恰恰正好提供了这样的执行环境，使得漏洞有机可乘；举一反三来看，类似的漏洞依然存在，零Day更是防不胜防；
    
*   Tomcat这种中间件，已经在企业的服务部署中随处可见，应用更是数不胜数，如何确保开发时的漏洞规避、上线前的漏洞测试以及上线后的主动防御，依然是需要急切关注的问题；
    
*   数据泄露、数据安全问题也逐渐加大了在传统网络安全中的比例，上面的漏洞仅仅也只是数据泄露中的冰山一角，但往往这冰山一角，也足够瞬间摧毁诸多公司的业务，所以更应该得到重视和敬畏。
    

  

**推荐与寄语**

除了官方推荐的升级Tomcat的策略可以达到一劳永逸的效果，在生产环境，往往有大量的老旧应用是无法随意重启的，所以面对大多数情况，RASP可以起到应急规避风险的作用，RASP除了能够阻断反序列化引起的命令执行、sql注入等诸多漏洞的攻击，还能有效防御诸如Tomcat、Jetty等中间件引起的信息泄露问题。
