### api

所谓api就是，是一些预先定义好的函数。作为开发者只需要了解函数的输入输出即可，而不需要去了解函数内部的具体实现，换一种更好听的名字就是接口。

比如日站的时候遇到的各种开放平台。

但一般没啥用，因为都是类似于文档。既然不要你了解内部构造，函数怎么用得知道吧，所以一般会提供api文档，也就是使用手册。

https://wiki.open.qq.com/wiki/【QQ登录】API文档

![](../Images/d25f4859f9c8f19999e4fbc956d66cd8.png)

ok，说了这么多，总结一下，api = 函数 = 接口

### sdk

那么什么是sdk呢，全称软件开发工具包，简单的来说就是开发工具的集合。可以这么说sdk就是很多很多的api(函数)和一些以其他文件(一些依赖)的集合体。形象的说就是，api是具体的功能，sdk是多功能集合体的工具。

![](../Images/cb6c4e128d51406a21c3a6d8e0419854.png)

妹子看到这里，应该懂了吧。

那么开始进入这篇的主题，sdk的安全案例介绍。

## 微信 sdk xxe漏洞

参考链接

http://seclists.org/fulldisclosure/2018/Jul/3  
https://xz.aliyun.com/t/2426  
https://xz.aliyun.com/t/2427

源码下载：

https://pay.weixin.qq.com/wiki/doc/api/download/WxPayAPI\_JAVA\_v3.zip

问题代码：

```


String notifyData = "...."; // 支付结果通知的xml格式数据<String, String>

 notifyMap = WXPayUtil.xmlToMap(notifyData);  // 转换成map`        if (wxpay.isPayResultNotifySignatureValid(notifyMap)) {``             。。。。。。`

        }
```

这里的问题在于：

`WXPayUtil`工具类中的`xmlToMap()`可以在解析xml时没有对外部实体进行限制。

xmlToMap具体实现

```
 public static Map
```

直接对传入的`strXML`进行了处理  
而传入`xmlToMap`的参数`notifyData`就是商家接受微信回调的数据,也就是说如果商家接受回调数据的url也就是notify_url泄露了，攻击者就能控制微信回调给商家的数据`notifyData`，利用没有限制外部实体的`xmlToMap`从而实现xxe攻击。

具体的实现方法：

```








POST merchant_notification_url HTTP/1.1
```

如果通过任意文件读取能够读取到商家的安全密钥 就能实现0元购买。  
然而微信团队已经修复了漏洞，所以baofu的机会已经没有了。

## XG SDK 目录穿越注入漏洞

参考链接

http://www.droidsec.cn/一个目录穿越引发的注入及后续-xg-sdk漏洞回顾与/

XG SDK在运行的时候会周期性地启动一个`libtpnsWatchdog.so`的可执行文件,通过逆向可以发现源码的逻辑。  

![](../Images/1a05f60b3f82f096867cbdac00a58ca8.png)

![](../Images/cfd392f66d8bf6a202acd846a9948f3b.png)

先判断目录是否存在，然后调用system启动对应的组建。这里的问题就在于没有对传入的参数进行过滤。  

那么如果要利用system执行命令，就要跨过两个障碍：

1.  sdk可以访问并且真实存在的目录
    
2.  目录名中存在可执行的代码，并且能够被system执行
    

绕过方法：  
在scard目录下面建立一个文件名  
`&& shellcmd #`

然后发送的命令通过目录穿越，控制apk能够访问的目录。  
发送的参数是`xxxx/../../../../../../../sdcard && shellcmd #xxxxx`

最后就可以成功的命令执行。

## 友盟 SDK 越权调用未导出组件漏洞

参考链接

https://www.anquanke.com/post/id/89222

漏洞版本中的sdk的AndroidManifest文件导入了一个UmengIntentService，该IntentService的作用是在不同app之间唤醒时起作用的，

其中onMessage方法可以接受Intent携带的参数的body数据，并且通过UMessage得到V3，然后通过设置V3的值可以启动任意的Service。

![](../Images/1c69564f8f719cc643cda54f45d5ee7a.png)

Umessage函数构造如下：  

![](../Images/33604520b30c4a92b9304ae55b8fc122.png)

可以看到Umessage只是进行了取值操作。  

那么根据逻辑只需要设计一个intent，将display\_type置成pullapp，pulled\_service和pull\_package置成想要的service，再putExtra进intent即可实现拉起任意service。  

![](../Images/d1ece95864017244adcfc744603b1462.png)

通过该漏洞针对不同的app有不同的效果，例如Vulpecker提出的案例，通过拉起WebAppUpdateService可以实现下载任意的zip文件并解压到当前的应用目录中，就可以进行类似于添加html、js文件的恶意操作了。
