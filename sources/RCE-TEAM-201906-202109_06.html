        当今社会是一个网络发展迅速的社会，互联网已经遍及了世界的每一个角落，在其为我们带来便利的同时，也为我们埋下了不少的安全隐患。使用SSL来进行网络通信成为了很多mobile app的默认选择，但是我们可以发现一些app并没有采用“额外的措施”来保证窃听不可以发生：这个“额外的步骤“就是SSL Pinning。

连接模式

        client 和server建立一个连接，server返回其 SSL证书。如果这个证书是被OS信任的证书机构签发，那么这个连接就正常进行下去。随后交换session key进行通信。这个关键点就在于“信任“。如果攻击者进行中间人攻击，mobile device很可能也会信任攻击者的证书。

        SSLPining可以简单描述为在客户端存储一份ssl证书，当访问服务器的时候，验证服务器端的证书与客户端的证书是否一致，若不一致则不进行连接，从而可以防范中间人攻击。iOS上面自定义键盘可以使用输入框的inputView属性来进行自定义。而反编译则可以使用编译前的脚本对代码进行混淆处理。

相关知识

https

        我们传统的网络通信都是基于超文本传送协议来进行的，但是由于对其安全性的考虑，HTTPS应运而生。HTTPS是以安全为目标的HTTP通道，简单讲是HTTP的安全版。即HTTP下加入SSL层，HTTPS的安全基础是SSL，因此加密的详细内容就需要SSL。它是一个URI scheme，句法类同http:体系，用于安全的HTTP数据传输。https:URL表明它使用了HTTP，但HTTPS在HTTP与TCP之间存在不同于HTTP的默认端口及一个加密/身份验证层。现在它被广泛用于万维网上安全敏感的通讯，例如用户输入身份证信息等。

ssl及握手过程

        SSL是一种分层协议，它以一个记录层以及记录层上承裁的个同消息类型组成，而该记录层又会由某种可靠的传输协议如TCP来承载。其握手过程大致如下：

        1.客户端将它所支持的算法列表和一个用作产生密钥的随机数发送给服务器；

        2.服务器从算法列表中选择一种加密算法，并将它和一份包含服务器公用密钥的证书发送给客户端；该证书还包含了用于认证目的的服务器标识，服务器同时还提供了一个用作产生密钥的随机数；

        3.客户端对服务器的证书进行验证并抽取服务器的公用密钥，然后再产生一个称作pre_master_secret的随机密码串，并使用服务器的公用密钥对其进行加密，并将加密后的信息发送给服务器；

    4.客户端与服务器端根据pre_master_secret以及客户端与服务器的随机数值独立计算出加密和MAC密钥；

        5.客户端将所有握手消息的MAC值发送给服务器；

        6.服务器将所有握手消息的MAC值发送给客户端。

        第5步与第6步的mac交换可以有效的防止握手过程中遭到攻击被篡改，因为客户端的MAC是根据原始消息计算得出的，而服务器的MAC是根据攻击者修改过的消息计算得出的，通过检查就会发现不匹配。由于客户端与服务器所提供的随机数为密钥产生过程的输入，所以握手不会受到重放攻击的影响。

https的局限性

        HTTPS的局限性主要在于客户端被动的接受服务器的证书，当提示证书不是被信任的机构颁发时，若客户选择继续访问，则其安全性得不到保障。所以导致其易于受到中间人攻击。比如说我们可用Frida绕过SSL证书检查，或者是使用工具攻破ssl，在这里我们以SSLSplit攻击github为例进行说明。

首先我们需要伪造证书，之所以伪造证书是为了达成中间人欺骗的效果，终端进入管理员模式后，先生成key

openssl genrsa -out ca.key 2048

生成公钥证书

openssl req -new -x509 -days 1096 -key ca.key -out ca.crt

开始攻击，首先iptables -F清除原有设置，打开ip_forward功能，接下来使用iptables进行流量转发，进行arp攻击

sysctl -w net.ipv4.ip_forward=1iptables -t nat -Fiptables -t nat -A PREROUTING -p tcp --dport 80 -j REDIRECT --to-ports 8080iptables -t nat -A PREROUTING -p tcp --dport 443 -j REDIRECT --to-ports 8443arpspoof –i eth0 –t 被攻击ip 网关ip

另一个终端中输入

sslsplit -D -l connection.log -j sslsplit -S   /logdir/ -k ca.key -c ca.crt ssl 0.0.0.0  8443 tcp 0.0.0.0 8080

ssl pinning实现原理

        所谓SSL Pinning是指客户端直接保存服务端的证书，建立https连接时直接对比服务端返回的和客户端保存的两个证书是否一样，一样就表明证书是真的，不再去系统的信任证书机构里寻找验证。这适用于非浏览器应用，因为浏览器跟很多未知服务端打交道，无法把每个服务端的证书都保存到本地，但CS架构的像手机APP事先已经知道要进行通信的服务端，可以直接在客户端保存这个服务端的证书用于校验。
