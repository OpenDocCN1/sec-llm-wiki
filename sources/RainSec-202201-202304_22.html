02


前期准备



缓存是指代理服务器或客户端本地磁盘内保存的资源副本。利用缓存可减少对源服务器的访问，因此也就节省了通信流量和通信时间。
为了影响到其他用户，我们这里只关注下使用代理服务器的情况，此时我们称它为缓存服务器。收到资源文件的请求时，缓存服务器会保存一份资源的备份，当再次收到同样的请求时它会直接返回保存的资源。这里我们使用nginx的缓存功能来实际感受下，在配置文件中添加proxy_cache_path等信息：
http {......    //缓存配置信息    proxy_cache_path /tmp levels=1:2 keys_zone=one:10m inactive=60m loader_threshold=300 loader_files=200 max_size=200m;        server {    listen       80;    listen  [::]:80;    server_name  localhost;        //缓存空间    proxy_cache one;    location / {      proxy_pass http://172.17.0.1:81; //需要缓存的服务器地址      //设置缓存1分钟过期      proxy_cache_valid any 1m;    } }}
使用python3 -m http.server 81启动一个http服务，在一分钟内访问同一个路由及参数，后端只会收到一次请求

只有当缓存过期，或者是指定了不同的参数后才会继续继续发送给后端

如果想多维度进行缓存可以使用proxy_cache_key进行配置：

语法：proxy_cache_key string;

默认值：proxy_cache_key $scheme$proxy_host$request

可配置段：http, server, location

除了以上基本信息之外，还有一些请求/响应头可以帮助我们确定缓存的一些信息，这里以阿里云CDN为例：

03


漏洞利用



由上文可知，大多数缓存服务器判断协议、URI相同时返回同一个缓存资源，而此时如果存在一个请求头可以影响到响应内容，那就会导致缓存资源被污染，用实例来感受一下：

启动如下代码

from flask import Flask, requestapp = Flask(__name__)
@app.route('/host')def host():    forward = request.headers.get('X-Forwarded-Host')    script = '/js.js'    if forward != None:        script = 'http://' + forward + script    return '<script src="{0}" ></script><h1>Hello World</h1>'.format(script)
if __name__ == '__main__':    app.run(host='0.0.0.0',port=81)

带有X-Forwarded-Host发送后响应内容中的js就可控了

而结合上文中的nginx缓存，只要在缓存时间内将该链接发送给受害者，即可触发XSS

除此之外还有一种场景很适合使用缓存投毒:

在Burp中可以正常进行XSS

但是由于浏览器会进行编码，所以直接访问是无法触发XSS的

用上文的缓存配置是无法被利用的，所以修改下nginx的缓存key: proxy_cache_key $scheme$proxy_host$uri$arg_name; 这表示请求参数name发生变化时可以被缓存，而其他参数则不会对缓存造成影响，所以我们可以构造
