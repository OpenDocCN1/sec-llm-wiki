**02**

  

前期准备

  

  

> 缓存是指代理服务器或客户端本地磁盘内保存的资源副本。利用缓存可减少对源服务器的访问，因此也就节省了通信流量和通信时间。

为了影响到其他用户，我们这里只关注下使用代理服务器的情况，此时我们称它为缓存服务器。收到资源文件的请求时，缓存服务器会保存一份资源的备份，当再次收到同样的请求时它会直接返回保存的资源。这里我们使用`nginx`的缓存功能来实际感受下，在配置文件中添加`proxy_cache_path`等信息：

```
http {......    //缓存配置信息    proxy_cache_path /tmp levels=1:2 keys_zone=one:10m inactive=60m loader_threshold=300 loader_files=200 max_size=200m;        server {    listen       80;    listen  [::]:80;    server_name  localhost;        //缓存空间    proxy_cache one;    location / {      proxy_pass http://172.17.0.1:81; //需要缓存的服务器地址      //设置缓存1分钟过期      proxy_cache_valid any 1m;    } }}
```

使用`python3 -m http.server 81`启动一个`http`服务，在一分钟内访问同一个路由及参数，后端只会收到一次请求

![](../Images/10e0a8e11252bd8584c4dd0d9fd940f3.png)

只有当缓存过期，或者是指定了不同的参数后才会继续继续发送给后端

![](../Images/e31694f343af8d23c215ded94a16101f.png)

如果想多维度进行缓存可以使用`proxy_cache_key`进行配置：

```
语法：proxy\_cache\_key string;

默认值：proxy\_cache\_key $scheme$proxy\_host$request

可配置段：http, server, location
```

除了以上基本信息之外，还有一些请求/响应头可以帮助我们确定缓存的一些信息，这里以阿里云CDN为例：

> https://help.aliyun.com/document\_detail/27136.html

![](../Images/3ceaa0b8ed6c411bd027d357f2ae4acc.png)  

这两个响应头可以帮我们判断请求到的是否是同一个缓存文件。此外还有些字段是控制是否使用缓存，或者缓存过期时间的：

![](../Images/9588ea6f6e8684aa6a6588d3a9db41a6.png)

**03**

  

漏洞利用

  

  

由上文可知，大多数缓存服务器判断协议、URI相同时返回同一个缓存资源，而此时如果存在一个请求头可以影响到响应内容，那就会导致缓存资源被污染，用实例来感受一下：

启动如下代码

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   

```
from flask import Flask, requestapp = Flask(__name__)
@app.route('/host')def host():    forward = request.headers.get('X-Forwarded-Host')    script = '/js.js'    if forward != None:        script = 'http://' + forward + script    return '<script src="{0}" ></script><h1>Hello World</h1>'.format(script)
if __name__ == '__main__':    app.run(host='0.0.0.0',port=81)
```

带有`X-Forwarded-Host`发送后响应内容中的`js`就可控了

![](../Images/d8c2c91cf65b974d4d19dc6fa51aed29.png)

而结合上文中的`nginx`缓存，只要在缓存时间内将该链接发送给受害者，即可触发`XSS`

![](../Images/272d14ae561a103c5def76718ab413f0.png)

除此之外还有一种场景很适合使用缓存投毒:

在`Burp`中可以正常进行`XSS`

![](../Images/0007a36b5ff6b46805f905a43f562023.png)

但是由于浏览器会进行编码，所以直接访问是无法触发`XSS`的

![](../Images/929442243179d6fc8d140c0d2204e518.png)

用上文的缓存配置是无法被利用的，所以修改下`nginx`的缓存key: `proxy_cache_key $scheme$proxy_host$uri$arg_name;` 这表示请求参数`name`发生变化时可以被缓存，而其他参数则不会对缓存造成影响，所以我们可以构造

![](../Images/be7514cec5bcc2498b11bafe336b1977.png)

接下来只要访问：`http://172.16.220.130/query?name=1` 即可触发`XSS`
