每个现代公司都是软件公司。无论您销售的是技术产品，食品还是保险服务，您都可以通过应用程序与客户进行交互，而这些应用程序是攻击者的主要目标。实际上，与实际破坏相关的最常见的攻击模式通常在Web应用层面。
在整个软件生命周期中为您的应用程序提供持续保护是至关重要的。尽早将应用程序安全性实践插入开发过程中将有助于您更快地发现弱点，节省团队纠正问题的时间，并改善安全人员与DevOps团队之间的协作。但是，无论您从一开始实现的安全程度如何好，都无法最终忘记它。您需要实时监视和‍分析应用程序行为。
简单来说，您需要融合 Dynamic application security testing(DAST) 和 runtime application self-protection(RASP) 两个方面的解决方案。
持续改善应用安全
虽然DAST和RASP只是完整的应用程序安全规划的两个部分，但它们确实代表了两个非常重要的环节。
DAST是一种主动解决方案，用于在运行环境中扫描应用程序。它在构建和测试阶段使用，并且在测试过程中可以持续进行交付和生产，通过 DAST simulates attacker behavior 去检查应用的弱点。

虽然DAST是主动的，RASP意味着是被动的，但是RASP可以保护使用中的应用程序。RASP在运行时位于您的应用程序中，以监视和分析其流量和行为方式。
Rapid7 RASP解决方案：Learn more about Rapid7’s RASPsolution, tCell
您的应用程序安全解决方案应同时具有主动测试和被动防护的能力，以取得最大的成功。当识别到威胁时，可以清楚地看到像RASP这样的响应式工具的好处，而测试过程中，也可以看到像DAST这样的主动式解决方案的好处。
什么是SDLC：identifying and remediatingvulnerabilities occurs earlier in the SDLC.
DAST解决方案的优势
DAST解决方案提高了安全可视化，并帮助安全团队了解其Web应用程序的行为方式。该技术不受特定语言或技术的约束，因此您可以在所有自定义应用程序中使用相同的工具。DAST工具往往易于部署和管理。例如，我们看到DAST客户在短短五分钟之内即可扫描其应用程序。
应用程序安全仍然是一个相对较新的领域。许多安全专业人员更习惯于发现传统软件或基础结构中被称为CVE的漏洞。应用程序漏洞是不同的。Web application vulnerabilities 通常最好将其描述为缺陷-正是DAST旨在解决的问题。DAST从攻击者的角度审视‍了‍您的应用程序的行为，发现了可以利用的弱点，并说明了攻击者如何侵入系统。
安全团队的职责是识别和评估风险，但最终还是由开发或DevOps团队来解决问题。DAST工具有助于开发与安全团队之间的通信和协作。通过将DAST集成到您的SDLC中，它将成为常规质量检查流程（QA）的一部分。您的开发团队应该习惯进行质量检查，将DAST集成到SDLC中可以进一步推动组织内的安全自动化。
如果在DevOps遇到阻力，那么DAST生成的数据可以帮助您返回同一页面。您将获得有关问题的具体证据，并将能够轻松重现您的发现并验证它们的存在，以向开发人员展示。
您可能已经在使用静态应用程序安全测试（SAST）工具。静态工具直接集成到开发环境中并改善代码安全。它们有自己的位置，但是与DAST不同，它们只关注代码而不是行为。应用程序行为的某些方面只能在应用程序运行时进行检查。
DAST和RASP协同工作
DAST和RASP并不是您的企业应该拥有的仅有的应用程序安全工具，但是它们都是可靠的关键组成部分。每种类型的应用程序安全工具都有其作用。DAST允许在开发生命周期的早期阶段实施安全测试。尽早发现漏洞是一个重要目标，但您永远无法提前发现所有问题。这就是RASP的用武之地，因为它可以实时监控和保护您的应用程序。
如果没有DAST，您将花费时间和金钱来解决本可以避免的错误，但是如果没有RASP，您将很容易受到新的攻击。DAST和RASP相辅相成，并且最好一起使用。
