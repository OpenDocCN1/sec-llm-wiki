在Metasploit一系列的开发日志中记录着Rapid7的专业研究团队是如何来分析漏洞，并将其纳入Metasploit Framework中的--换句话说，您可以在这里找到以前Metasploit的开发日志，从中了解一个漏洞是如何通过严格的开源委员会审核，成为一个成熟的Metasploit测试模块的。本季度，我们将略微改变方向，详细介绍远程代码如何在一个被广泛使用的NAS上执行的。

Metasploit的研究团队最近在Framework中添加了一个模块，该模块用于检查通过Metasploit针对Equation Group，利用 SMB植入的DoublePulsar。DoublePulsarRCE 模块允许用户远程禁用植入物，这使得它成为Metasploit模块中罕见的（虽然不是唯一的）类别，除了自身的攻击价值之外，还具有特定的事件响应功能。


介绍

由于RDP漏洞近来风靡一时，我决定重新思考当SMB漏洞还处于流行状态时，我尚未完成的想法。

如果在两年前infosec可以恢复其内存，那么Shadow Brokers就会泄露所谓EquationGroup的Windows开发工具包。该版本中最具有破坏性的代码可能是ETERNALBLUE，它针对于各种Windows版本的SMB远程漏洞。该代码可以使WannaCry蠕虫快速的进入系统，将成千上万的系统锁定。

就在EternalBlue诞生的同一天，DoublePulsar也被公开面向于大众，DoublePulsar是通常由漏洞利用程序生效的内核模式的植入物。DoublePulsar（以下简称为DOPU或”植入物“）具有感染SMB和RDP的能力，但是由于EternalBlue的巨大影响力，SMB还是大多数研究人员关注的焦点。尽管大多数工作都是通过”ping“功能来检测植入物的，但植入物具有执行任意内核shell代码或远程禁用的能力。但是，或许这值得庆幸，植入物本身缺乏身份验证机制，世界各地的Windows系统的后门并没有黑客归属权。

zerosum0x0是最早分析DoublePulsar的研究人员之一,正是他的工作让我开始了解到DoublePulsar植入物及其功能。文章的其余部分涉及了我们为执行植入程序的代码执行而进行的分析。

我们为什么要这么做?

当EternalBlue和DoublePulsar公诸于世时，有许多人使用Fuzzbunch（Shadow Brokers的一部分）对目标执行或利用EternalBlue，用DOPU感染目标，然后利用DOPU的DLL注入功能（从“exec“功能引导）将DLL加载注入到用户进程中，从而使平凡的ring3代码执行成为ring0植入程序。

尽管这个过程很有趣，但是却向人们提出了一个危险的问题：为什么一个人故意用所谓的NSA武器感染目标，却只是为了获得执行任意代码的权力？当然，这是攻击没有更新补丁的Windows系统最方便快捷的办法，但是许多人并没有多加考虑可能出现的后果。幸运的是，研究社区致力于以开源的方式探索EternalBlue的漏洞利用方式，从而避开了我们知之甚少的国家工具箱。

那么，如果目标已经感染了DoublePulsar应该怎么办？通常情况下，您对威胁事件的判断和评估会成为事件响应的第一手资料。在这种情况下，我们的研究可能会有助于防御者在无需重启系统的情况下，就可以阻断植入物与攻击者的通信。另外，对于渗透测试人员（经过授权）来说，能够使用完全经过审查的开源工具对植入物进行代码执行，而无需再进行漏洞利用。目前已经有针对恶意软件执行代码的先例，其中一些示例存在于Metasploit中。在任何情况下，对可能受到感染的的系统进行检查都是有必要的，同时禁止植入物并不会修复漏洞，必要的漏洞修补还是必须的。

因此，我们在没有道德压力的两年之后，试图在Metasploit中开源架构中，研究DoublePulsar的代码执行方式和补救措施。

Metasploit有一个广泛的代码库供开发使用，我将继续将其添加到Rex :: Text.xor方法中。这将是DoublePulsar的XOR流密码的要求，该密码将用于加密shellcode。

print_status("Generating kernelshellcode with #{datastore['PAYLOAD']}")

shellcode =make_kernel_user_payload(payload.encoded, datastore['ProcessName'])

shellcode <<Rex::Text.rand_text(MAX_SHELLCODE_SIZE - shellcode.length)

vprint_status("Total shellcodelength: #{shellcode.length} bytes")

  

print_status("Encrypting shellcodewith XOR key 0x#{@xor_key.to_s(16).upcase}")

xor_shellcode =Rex::Text.xor([@xor_key].pack('V'), shellcode)

因为DoublePulsar会将shellcode以4096字节的块分块，而我们的shellcode代码总大小恰好在这个块的大小之内，所以我们在有效负载之后用随机字节填充差异，并仅发送一个4096字节的块。这样可以确保一致的shellcode大小和对齐方式，并且使用了一些混淆手段。由于内核shellcode调用了Create Thread函数，并且Metasploit中的EXITFUNC选项设置为thread，因此，随机填充不存在问题。是的，这很像黑客的手法。

最后的难题

当我制作SMB TRANS2_SESSION_SETUP数据包时，我要将其参数清零，因为他们对于ping和kill命令都不是必须的。但是，exec命令需要发送特定的参数。我还不知道该用什么填充，但是很明显这涉及到XOR键。

当参数为零时，代码执行会被植入程序中的检查阻止。我花了整整一个晚上的时间来处理这个问题，但是还没有确定正确的参数（除了winDbg以外），所以我把这个问题暂时搁置起来处理另一个任务。过了一段时间，我联系了Jacob，问他是否有兴趣弄清楚剩下的部分。

这个比较检查存储的全局值[rbp+54h]是否等于XORed的前4个字节的SESSION_SETUP参数块。存储在[rbp+54h]处的数据为零或先前已为shellcode分配的字节数。如果先前分配的字节与4字节块匹配，则跳过该代码段的其余部分。否则，将调用nt! ExAllocatePool为shellcode分配缓冲区。Shellcode指针存储在[rbp+4Ch],分配的字节数存储在[rbp+45h].

由于在前面的代码块中可能发生分配，因此以下的块是用来检查NULL shellcode指针：

fffffa80`0226e140 4885c0          test    rax,rax

fffffa80`0226e143 745b            je      fffffa80`0226e1a0  ; ALLOC failed

fffffa80`0226e145 4801f7          add     rdi,rsi            ; Offset within buffer + Size ofshellcode data in request

fffffa80`0226e148 4839df          cmp     rdi,rbx

fffffa80`0226e14b 774f            ja      fffffa80`0226e19c  ; Invalid parameters

如果shellcode指针为空，则代码将跳转到会返回“分配失败“状态码0x30的位置。若分配成功，则执行另一项检查以验证将要复制到shellcode缓冲区中的数据的大小。如果将要复制到缓冲区中的偏移量加上Trans2请求中的全部shellcode数据超过分配的shellcode缓冲区大小，则下一个检查将失败。此检查可确保不会将数据复制到已分配的缓冲区之外。

数据将会复制到shellcode缓冲区的偏移量中，该偏移量由SESSION_SETUP参数指定。之后,将会使用XOR密钥对复制的数据进行解码，这意味着Trans2请求中的shellcode数据必须先进行解码，然后才能发送到目标位置。循环完成后，将最后解码的地址与shellcode缓冲区的预期结束地址(shellcode缓冲区的开始+shellcode的总大小)进行比较。如果地址不匹配，则返回“成功“状态。但是在执行内存中的shellcode之前，将来的请求中将需要更多数据。如果地址匹配，则执行shellcode，并释放缓冲区。

注意事项

尽管Doublepulsar是一种复杂的内核模式植入物，但其网络签名已被充分研究，所以可以非常准确的检测出该植入物是否存在。在系统层面，可以通过分析内核内存进行内存取证来检测其是否存在。所以，您通过植入程序执行的任何代码或命令都可能被用户检测到。
