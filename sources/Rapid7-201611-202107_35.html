2019年9月6日，Exim的开发团队发布了一个新的补丁：CVE-2019-15846,修复（fixed）了一个privileged, unauthenticated remote code execution (RCE)漏洞，这个漏洞存在于Exim最流行的邮件转发服务（MTA）上，在互联网上，这个服务非常常见。

针对这个漏洞的成功攻击，可以让攻击者在目标系统上获得Root权限。

Rapid7强烈建议运行Exim的组织（包括大公司、区域的ISP、大学和其他大型组织）立即修补其系统，因为Exim团队已经有一个针对此漏洞的有效利用代码（exploit）、可以实现对漏洞的利用（POC）。目前，还没有已知的CVE-2019-15846的公开利用程序，但这种情况随时可能改变。当然，客户也可以选择不应用补丁程序，也能够缓解风险，但这需要禁用发送加密邮件的功能，出于隐私保护的原因，不建议这样做。

4.80之前的Exim版本似乎不易受此特定RCE漏洞的攻击，但却存在其他远程代码执行问题和其他严重漏洞，最好的选择还是运行最新补丁的版本。

使用cPanel 管理Exim的组织可以遵循cPanel的补丁指导（cPanel’s patch guidance ），以确保它们运行的Exim版本不易受到cve-2019-15846的攻击。cPanel是Exim最流行的GUI管理器之一，在Exim部署中广泛使用。

截至2019年9月7日，Rapid7InsightVM和Nexpose客户已对此漏洞提供了完整的扫描覆盖。

  • 互联网上的Exim
Rapid7 实验室在通过声纳项目（ Project Sonar）常规扫描互联网的过程中，发现了超过500万台存活的 Exim服务器, 其中450万台可以探测到有效的版本信息。

超过 73% 的 Exim 版本为 4.92.0, 这是最新补丁发布之前的版本。这是好消息，看起来大多数的组织一致在保证Exim的及时升级。我们希望下一次Sonar扫描的时候，多数设备已经进行了最新的更新。

不出意外，美国的组织和托管提供商在Exim部署中占有很大的比列（>51%），在大多数其他国家，Exim的部署集中在1%-5%的范围内，这些国家的互联网系统数量位居前列。

一个变化是大多数云服务供应商都不在前10名之列。这在一定程度上是由于Exim在unified layer中的高度集中，unified layer是一家主机提供商，在电子邮件保护方面有着相当麻烦的记录。如果您在“前10名”中的任何一家托管运营商中运行Exim并自行管理它，那么您应该努力更快地修补，因为一旦出现公开攻击代码，这些将成为对攻击者非常诱人的目标。

  • SMTP 扫描和攻击行为

Rapid7实验室也在关注SMTP扫描和攻击行为，通过 Project Heisenberg项目

自今年上半年以来出现了一些大型的smtp垃圾邮件和信息泄露活动，但公布了这一Exim漏洞之后，活动似乎并没有显著增加。

如果我们放大到2019年9月，我们会看到补丁发布后，探测器略有上升。

这些活动似乎都没有试图利用这个新的Exim漏洞，当然有效载荷还没有公开；公开攻击很可能很快就会存在。

Rapid7实验室将监视SMTP活动，监视公开攻击方法的披露，并根据需要提供更新。
