# 前言

最近我们的威胁侦察团队收集和分析了来自多个APT小组的活动数据。我们分析了今年前段时间他们针对位于韩国，美国和东亚的攻击文件。他们使用的是恶意的CAB文件，还有单独的配置文件，这些配置文件有相应的功能，最后是BYpass UAC。  
本文简要介绍了他们当时使用的恶意附件的感染方法以及使用的Bypass UAC模块。

# 感染方法

攻击者使用很多步骤去生成他们的恶意软件，最初的感染来自附加在电子邮件中的恶意文档，这里使用的是鱼叉式钓鱼攻击的方法，当用户执行附加的文件时，文档中的脚本会从远程站点下载base64编码的BAT文件。

  
![](../Images/bba2ee92c04578f5276ec996556440d9.png)

  

下面是他们使用的感染方法的顺序。

1.  通过嵌入在恶意文档的脚本下载base64编码的数据`1.txt`文件
    
2.  解码`1.txt`然后创建`1.bat`并运行`1.bat`
    
3.  1.bat根据Windows平台环境（32位/ 64位）下载2.txt（32位）或3.txt（64位）
    
4.  解码`2.txt`或`3.txt`然后创建`setup.cab`
    

每个文件的头部有像使用字符串`- BEGIN CERTIFICATE -`的SSL证书，但实际上是base64编码的cab和bat文件。  
￼

![](../Images/1448d21f128c86366c5f09905a4a191c.png)

  

CAB文件是包含的内容：

1.  包含主要payload文件执行的BAT文件
    
2.  包含攻击者服务器地址的INI文件
    
3.  用于Bypass UAC的DLL文件
    
4.  恶意的EXE文件
    

## 为什么UAC会运行？

恶意软件的第一个批处理文件（1.bat）会去执行第二个批处理文件，第二个文件包含攻击者主要的恶意payload。通常会向用户显示UAC窗口，问你是否执行，这是由于BAT文件中的代码引起的。它还将INI配置文件和恶意的EXE复制到System32文件夹中。

通常，将文件复制到System32文件夹时，出于安全原因将运弹出UAC窗口。在正常情况下不回去修改此文件夹，会询问你是否继续执行。

￼![](../Images/a0438bfe516757b472ee1d1bf232f3ae.png)

  

## BAT文件细节

第一个批处理文件（1.bat）负责从远程服务器下载文件，并使用`net session> null`命令判断当前用户的权限并执行以下操作：

1.  如果是admin：删除UAC绕过DLL，直接payload和BAT文件
    
2.  如果不是admin：使用rundll32.exe 去执行dll模块，bypass UAC
    

￼![](../Images/78f0f47f84ce352bf20c7576df62d7eb.png)

  

用于执行主要的payload的批处理文件将payload可执行文件和INI配置文件复制到System32文件夹中，然后运行移动到System32文件夹的主有效负载。

## UAC

UAC就是用户访问控制，在执行某些高权限操作时会弹出，作为告警提示。  
￼

![](../Images/1a3a1bd62fde1cb8e419637d0ac586a3.png)

  

## 运行流程

当用户登录Windows时，每个用户都会获得一个访问令牌。访问令牌包含安全标识符（SID），操作权限以及授予用户的访问级别的信息，Windows系统使用访问令牌来验证用户的权限。登录时生成的访问令牌是：

1.  标准用户：生成标准用户的访问令牌
    
2.  administrator：生成标准用户访问令牌和管理员访问令牌
    

系统根据登录用户的令牌权限分配以下完整性级别。系统通过将对象的安全描述符的访问权限与用户的SID进行比较来执行访问权限控制。  
￼

![](../Images/a14ff4991fffb6f2656353748ee8cd41.png)

发布的令牌用于创建流程等事件。重要的是，在发布令牌后创建进程时，管理员还要使用标准用户访问令牌执行新的进程。

通常，作为大多数用户进程的父进程`explorer.exe`在中等完整性级别运行，因此大多数进程与explorer.exe运行在同一级别。但是，当进程需要高完整性级别时，在用户批准的情况下，进程可以获得权限提升。

所以结论就是进程通常使用标准用户的访问令牌，并在需要管理员访问令牌时使用UAC去获取用户的授权。

下面是会触发的实例：

1.  以管理员身份运行应用程序
    
2.  一些系统设置
    
3.  去更改普通用户没有权限的文件夹中的文件（在大多数情况下为％SystemRoot％或％ProgramFiles％）
    
4.  对访问控制列表（ACL）的更改，通常称为文件或文件夹权限
    
5.  安装设备驱动程序
    
6.  安装ActiveX控件
    
7.  更改Windows防火墙
    
8.  更改UAC设置
    
9.  配置Windows Update 
    
10.  添加或删除用户帐户
     
11.  更改用户的帐户类型
     
12.  启用Guest帐户（Windows 7和8.1）
     
13.  打开文件共享或媒体流
     
14.  设置家长控制
     

## Bypass UAC module

但是，在这种情况下，攻击者会使用特定的DLL模块来绕过UAC。它似乎是通过引用UAC-TokenMagic.ps1的文件的源代码来创建，该文件在GitHub上是开源的。

```text

https://github.com/FuzzySecurity/PowerShell-Suite/blob/master/UAC-TokenMagic.ps1
```

首先，它创建了一个以高完整性级别运行的wusa.exe进程（可以自动升级的进程）。这个进程是Windows Update独立安装程序，它具有auto-elevate属性，因此如果系统UAC弹出的话是`仅当程序/应用程序尝试对我的计算机进行更改时通知我`，不会弹出UAC。

创建wusa.exe后，它会复制该令牌并使用令牌通过`CreateProcessWithLogonW`运行`cmd.exe`进程。最后，`cmd.exe`以高权限运行并执行`"/c EntryPoint"％Temp％\[bat file install main payload]"`，批处理文件也会继承cmd.exe的权限。

如果攻击者使用Bypass UAC Module，则运行paylaod的批处理文件将通过从wusa.exe复制用户的访问令牌生成的cmd.exe来工作。总之，即使将文件移动到批处理文件中的System32文件夹的代码，UAC也不会弹出。

## 摘要

攻击者使用其他组件来压缩Bypass UAC模块，并以CAB文件格式分发它们。我们看到攻击者组主要使用用俄语，英语和韩语编写的钓鱼文档，并使用BABYFACE，SYSCON恶意软件变体作为主要的payload执行。这种活动可能部分与先前已知的团体活动有关。
