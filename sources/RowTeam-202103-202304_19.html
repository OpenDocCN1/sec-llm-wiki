0x01 获取 Token

特别提醒：不同的账户类型，具有不一样的URL。

账户类型URL
AzureADMyOrg（单租户）https://login.microsoftonline.com/{tenantid}/oauth2/v2.0/authorize
AzureADMultipleOrgs（多租户）https://login.microsoftonline.com/organizations/oauth2/v2.0/authorize
AzureADandPersonalMicrosoftAccount（多人和个人）https://login.microsoftonline.com/common/oauth2/v2.0/authorize
PersonalMicrosoftAccount（仅限个人）https://login.microsoftonline.com/consumers/oauth2/v2.0/authorize

1.1 获取 Authorization code

访问以下连接。

https://login.microsoftonline.com/consumers/oauth2/v2.0/authorize?client_id={client_id}&redirect_uri=http://localhost:65001/rowteam&scope=files.readwrite offline_access&response_type=code



1.2 获取 Access Token 和 Refresh Token

https://login.microsoftonline.com/consumers/oauth2/v2.0/token
httpbody:code={0}&client_id={1}&client_secret={2}&redirect_uri=http://localhost:65001/rowteam&grant_type=authorization_code


1.3 通过 Refresh Token 获取 Access Token

https://login.microsoftonline.com/consumers/oauth2/v2.0/token
httpbody:refresh_token={0}&client_id={1}&client_secret={2}&grant_type=refresh_token

0x03 使用上传会话上传大文件

请求创建一个上传会话，以便允许当前应用可以上传大文件。上传会话允许在上传过程中遇到网络波动等情况断开请求连接，可进行恢复上传，简单的说就是可断点续传。 要使用上传会话上传文件，有两个步骤：

1.创建上传会话2.使用 PUT 方法，将数据代入上传会话中

3.1 创建上传会话

想要上传大文件，则必须先请求一个新的上传会话：该请求将会创建一个临时存储，已上传的内容会保存在这个临时存储中，直到上传完整的文件。 要上传新文件，请指定父文件夹的ID或路径。如果更新现有文件，请指定要更新的文件的ID或路径。在上传文件的最有一个字节后，该上传会话也已完成，文件最终显示在OneDrive的文件夹中。

3.1.1 HTTP 请求

以下请求链接，选择一款适合自己的即可。

POST /drives/{driveId}/items/{itemId}/createUploadSessionPOST /drives/{driveId}/items/{itemId}:/{fileName}:/createUploadSessionPOST /groups/{groupId}/drive/items/{itemId}/createUploadSessionPOST /me/drive/items/{itemId}/createUploadSessionPOST /sites/{siteId}/drive/items/{itemId}/createUploadSessionPOST /users/{userId}/drive/items/{itemId}/createUploadSession

3.1.2 请求正文

{  "@microsoft.graph.conflictBehavior": "rename | fail | replace",  "description": "description",  "fileSystemInfo": { "@odata.type": "microsoft.graph.fileSystemInfo" },  "name": "filename.txt"}

例如，要控制文件名已被使用时的行为，可以在请求正文中指定冲突行为属性。

{  "item": {    "@microsoft.graph.conflictBehavior": "rename"  }}

3.1.3 响应

HTTP/1.1 200 OKContent-Type: application/json
{  "uploadUrl": "https://sn3302.up.1drv.com/up/fe6987415ace7X4e1eF866337",  "expirationDateTime": "2015-01-29T09:21:55.523Z"}

然后摘取uploadUrl进行下一步的使用即可。

3.1.4 你可能需要的备注

POST /me/drive/root:/{path_to_item}:/createUploadSessionHost: https://graph.microsoft.com/v1.0Content-Type: application/json
{  {path_to_item}: {{        "@odata.type": "microsoft.graph.driveItemUploadableProperties",        "@microsoft.graph.conflictBehavior": "replace",    }}}

3.2 使用 PUT 方法，将数据代入上传会话中

这部分不知道是不是官方文档[1]有问题还是咋滴。以下是描述：

To upload the file, or a portion of the file, your app makes a PUT request to the uploadUrl value received in the createUploadSession response. You can upload the entire file, or split the file into multiple byte ranges, as long as the maximum bytes in any given request is less than 60 MiB. The fragments of the file must be uploaded sequentially in order. Uploading fragments out of order will result in an error. Note: If your app splits a file into multiple byte ranges, the size of each byte range MUST be a multiple of 320 KiB (327,680 bytes). Using a fragment size that does not divide evenly by 320 KiB will result in errors committing some files.

对于这段话，我个人有些歧义：

1.是否是对于超过 60MB 的文件就需要拆分进行上传2.整个文件不计大小，而如果要拆分，则拆的包要小于 60MB

经过后期验证，当然，我只验证了一次性上传整个文件（120MB），能正常上传。因此应该是第二点定义正确，但我没去验证。

注意：如果将文件进行拆分，那么大小必须是 320 KB（327,680 byte）的倍数。

3.4 关闭上传会话

要取消上传会话，需要向上传 URL 发送 DELETE 请求。这会清理保存先前上传的数据的临时文件。在到过期时间后，临时文件及其随附的上传会话会自动清理。
