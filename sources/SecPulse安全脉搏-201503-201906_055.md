# 【干货】Drupal Core RESTful RCE (CVE-2019-6340)

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzAxNDM3NTM0NQ==&mid=2657034093&idx=1&sn=6a2de29afd3b5d2b0f27b039a2c93a18&chksm=803fffb3b74876a507f91211177da680ea8e836ab696206cd697b19f7b57aa65f96bc4d06e14&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzAxNDM3NTM0NQ==&mid=2657034093&idx=1&sn=6a2de29afd3b5d2b0f27b039a2c93a18&chksm=803fffb3b74876a507f91211177da680ea8e836ab696206cd697b19f7b57aa65f96bc4d06e14&scene=27#wechat_redirect)

![](../Images/5877508d27dd5cb84018504779f43e21.png)

近日，Drupal官方更新了一个非常关键的安全补丁，修复了因为接受的反序列化数据过滤不够严格，在开启RESTful Web Services拓展模块的情况下，可能导致PHP代码执行的严重安全。

![](../Images/3011c7477d24b57f7659d4cab7a3130c.png "image-20190224222445382-1024x397.png")

漏洞条件  

根据官方公告和自身实践，8.6.X(<8.6.10)两种情况可能导致问题出现：  

*   RESTful Web Services 拓展开启，并且启用了REST resources（默认配置即可），不需要区分GET，POST等方法即可完成攻击。
    
*   JSON:API服务模块开启，此服务尚未分析。
    

攻击步骤  

这里使用drupal-8.6.5作为测试版本，搭建REST服务进行漏洞分析

  

配置RESTful服务  

在拓展中安装RESTful对应的WEB服务  

![](../Images/135fe480bdb7daea2e78ad7d2957c636.png "image-20190224224642823-1024x457.png")

RESTful服务开启后，对于REST resources的设置比较麻烦，安装REST UI拓展进行图形化的管理，方便查看（不安装也是可以的）。

RESTful服务开启后，其中/node/{node}这个REST resources是默认配置中就启用的，可以通过REST UI查看，发现确实如此，默认配置即可被攻击者利用。

![](../Images/ead4a2ac2ecf734f131cc3b7e9a06ebf.png "image-20190224225107777-1024x400.png")

漏洞分析  

官方公告中(现已修正)一开始仅仅说开启POST/PATCH两种请求方式才会收到攻击，其实并不区分类型，上图就是GET请求的攻击，因为程序在进入在对请求进行deserialize的时候，是还是通过php://input进行获取请求内容。

  

![](../Images/b79ce3105de452cf037fe6e48aaf297b.png "image-20190224232428879-1024x407.png")  

跟进$request->getContent

![](../Images/6be7f2af7a19448fe96740decc9d650d.png)

获得请求内容后，使用$this->serializer->decode对请求内容进行解码并赋值$unserialized。

![](../Images/db4c3983a908bfcf08382a44c0494dc2.png "image-20190225113720396-1024x300.png")

然后传入$this->serializer->denormalize函数，Drupal 8的Serialization API是主要基于Symfony Serializer组件，具体可参加文档。

![](../Images/586f9f7c2355e2464ebf95347a9b8957.png "serializer_workflow.png")
