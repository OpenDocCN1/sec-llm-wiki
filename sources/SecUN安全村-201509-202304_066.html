摘要：“零信任”安全理念已被全球众多企业广泛接受。2020年8月NIST发布的零信任架构标准正式版，既是对零信任架构的全面总结，也是在前人实践基础上的系统性方法论阐述，同时NIST也提出实践建议。本文从零信任架构的基本思想出发，结合一类场景，提出零信任架构应用的一个实践思路。


一、前言

“零信任”是一种安全理念，摒弃了原有网络安全实践中对部分人员、角色、乃至网络位置赋予默认信任的理念。在具体实践中，这种“零信任”是一种从“首先不信任”再经过“全面的检验和验证”，之后才“信任”的过程。正如我们不可能无“凭”无“据”即信任一个陌生人一样，当“凭”和“据”经过真实有效地检验，才能对个陌生人信任，进而开始交流、合作。

“零信任”既然是一种理念，就会存在不同的理解和不同实践探索，从而诞生了不同领域、不同分支、不同视角的实践方法和经验。本文更多的是借鉴美国国家标准与技术研究院（NIST）发布的相关标准和实践方法、指南，结合自身实际的一个应用思路。

二、零信任架构概要

  • 零信任架构历史概要

2004年，杰里科论坛（Jericho Forum）提出了去边界化的想法，并进一步衍生出了零信任理念。2010年，Forrester研究公司的分析师约翰·金德维格（John Kindervag）正式提出“零信任”这个概念。

2014年，谷歌发表6篇有关零信任落地的论文。同年，国际云安全联盟发布了SDP（软件定义边界）标准规范1.0。2017年，Gartner发布CARTA模型同时提出零信任是实现CARTA宏图的初始步骤。2018年，Forrester提出零信任架构，将安全能力从微隔离进一步扩展到可视化、分析、自动编排等维度。2019年，Gartner发布零信任网络ZTNA，融合了SDP安全模型。2020年8月，NIST发布《零信任架构标准》正式版（NIST Special Publication 800-207）[1]。

笔者认为， NIST发布《零信任架构标准》正式版发布，意味着一种较为完善的零信任网络安全架构方法学诞生。它融合了风险管理框架有关内容，特别是对零信任核心框架理念的阐述，使其在各种场景下的适用性更广，同时它也包含构建、迁移等方面建议。虽然也还需要有从理论到实践的探索过程，但相较零信任网络ZTNA以及SDP在局部方面的实践模型，对于从全局视角解决网络安全架构问题则显得非常重要。

  • 零信任架构理念基础

《零信任架构标准》中指出——“零信任架构是一种端到端的企业资源和数据安全方法，包括身份（个人和非个人实体）、凭证、访问管理、操作、端点、承载环境（hosting environments）以及互连基础设施。”正如文中阐述——零信任 (ZT) 提供了一系列概念和设想，目的在于在可能遭受侵害的网络环境下运行的信息系统和服务中执行准确的、基于每个访问请求的最小权限访问决策，以最大限度降低不确定性[2]。

对架构师而言，接受这种零信任理念，并将零信任架构方法运用到架构设计中，才会产生基于零信任网络基础设施（物理和虚拟）和（网络安全）运营策略。

三、零信任架构应用遵循的原则


在零信任架构应用过程中，笔者认为，需要遵循如下几个基本原则：

1.遵循零信任的7个基本原则，即：
  1. 一切视为资源。所有数据资源和计算服务都被视为资源。
  2. 无处不在的通信安全。无论网络位置如何，所有通信必须是安全的。
  3. 每会话安全。对企业资源的访问授权应该基于每个会话。
  4. 动态策略管控。对资源的访问由动态策略（包括客户端身份、应用/服务和被请求资产以及的可观测状态）决定，并可能包括其他行为或环境属性。
  5. 本质上任何资产都不可信。企业监控和衡量所有自有资产和相关资产的完整性和安全状况。
  6. 动态认证和授权。所有资源认证和授权都是动态的，并且在被允许访问之前强制执行。
  7. 全面态势感知。企业尽可能多地收集关于网络基础设施当前状态的信息，并用于改善其安全态势。

3.关注外围逻辑组件。

作为网络安全架构的方法学，通过图2阐述了零信任架构密切相关的一系列组件。

图2 零信任架构的逻辑组件[4]

其中：
  1. CDM系统组件，持续诊断和缓解系统。可看做是信息资产基本信息、状态的管理系统。
  2. 威胁情报组件，提供内外部的威胁信息，帮助策略引擎做出访问决策。
  3. 企业合规系统组件和数据访问策略组件。它与威胁情报组件一道，为策略引擎（PE）提供了基本的策略输入。在实践中，可能还需要例如应用访问策略组件、端点安全组件，共同构成策略输入。
  4. PKI组件和ID管理组件，是两个重要的身份管理组件。。
  5. 活动日志组件和安全信息和事件管理系统（SIEM）组件，共同实现对信息系统的安全监控和事件响应。
（注：附带一句，NIST并不关注SOC，被认为落后的SIEM，反而在多个报告和标准中反复使用。准确的说，SOC关注全面的网络安全运营，SIEM是一个特定功能系统。）

笔者认为，将图1以及图2的组件结合起来，可以看出零信任架构的几个特点：
  1. 忽略边界，而关注“信息流”的控制，特别是强调动态控制。
  2. 更多地体现从“不信任”到“信任”的一个过程。
  3. 突出“身份管理”的重要地位。


4.零信任的边界可能更多了

如图3所示，零信任的出发点看似是“去边界化”的，但实际仍然存在“边界”，只是这些“边界”被隐含在一些控制点中，而且变得更多了。很显然，这样符合安全CIA三角关系的描述，但也势必带来较高的复杂度和管控难度。

四、零信任架构实践思路


选择使用零信任架构方法构建自身的信息系统架构，笔者认为，至少需要从两个方面评估：一是，从零信任架构的优点中获得的改进和提升远大于零信任架构的一些缺点带来的影响；二是，其应用场景也与零信任架构高度或大部分契合。

3.架构案例设计思路示例
  • 确定实践场景——一个提供多种测试服务的信息同


  • 确定基本设计原则

始终不能忽视两个问题：
  • 控制点越多，系统复杂度和耦合度就高。
  • 可用简单方法处理的场景，不宜增加复杂度。
  • 设计控制平面

在本案例中，笔者将控制引擎和安全代理整合为分布式部署“执行平面”。如图4所示。访问主体可能在访问客体资源过程中所需经历的一系列执行平面的识别和控制机制。即数据安全等级或系统安全等级越高，可能实体（用户或程序）需经历的执行层面的检测就越多。它与传统边界访问控制的关键差异在于：可信任即可访问。而不是固守于一次认证，访问资源锁定的策略。

图4 零信任架构控制平面示意图

执行平面不再是局限于防火墙、网闸这类传统的简单控制手段，而可以是一组控制实体（身份认证系统、授权系统、应用网关等）。在基于SDN网络技术、云计算技术原生的安全机制基础上，一方面，可以将访问请求调度到执行主体（身份认证系统、应用网关等）进行检验和策略验证，执行灵活的区域内控制；另一方面，也可以实现跨区域的控制。

  • 确定策略逻辑
  1. 用户验证结果决定对用户分类评级；
  2. 根据用户分类评级确定可访问的资源。
  • 确定控制原则
在访问策略控制的执行中，秉承如下基本原则：
  1. 被网络隔离成不同功能区块的分段，并在内部根据需要进一步实现微隔离；
  2. 内部用户虽然不经过接入网关，但在局域网接入时有特定的网段IP地址分配、更多的行为检测和验证；
  3. 基本的静态边界控制仍然保留，但保留足够弹性（可根据需要不设置源IP白名单等）；
  4. 根据用户身份、应用身份的检验结果确定之后的授权；

  5. 从基本资源向高级资源的访问都需经应用网关控制。

  • 验证有效性
验证有效性，是检验零信任架构设计发挥了其应有作用的重要一步，至少需要：
  1. 用详细的证据衡量（或评估）是否提高了网络防御效率。
  2. 验证工作负载（微分段/微隔离）分割的有效性，不能存在违反规则的穿透点。
  3. 通过持续的安全测试防止安全性减弱，并发现薄弱环节。
  4. 检验和评估安全事件处理的表现，这需要有完备的记录。
要实现上述验证的一个核心是需要数据完备地收集以及精确地、全面地分析，同时也是对SIEM的检验。


五、结语

实施零信任是需要大量的时间和精力的，它不可能一蹴而就，特别是在现有应用运行的状态下，由使用零信任架构直接取代传统架构而实现颠覆性改变，则更加不可能。美国国家安全局（National Security Agency，NSA）也提出了将零信任工作作为一个不断成熟的路线图来规划，从最初的准备到基础、中级和高级阶段，不断完善网络安全保护、响应和操作[7]。本文也仅仅是提出一种实践探索思路，供参考。
