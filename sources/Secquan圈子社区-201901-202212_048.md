**0x3 不规范的写法导致的注入**

我们先来说一下 Laravel 是可以记录语句的

![](../Images/2a7002dc33400789fad6330495b37af7.png)

我们来看下面的风骚怪一号写法：

![](../Images/124ff3d5899a5648322fa0d0e6c7c23a.png)

这是百分百会出现注入的一个写法，他没有过滤直接就拼接了语句拿去执行。我们去执行一下看看。

![](../Images/5e3431bc679586ca367fef21b3066613.png)

返回了 true ，那么我们去加一个单引号呢？

![](../Images/806589d128d4fd3719c795ba7ec7d1bb.png)

多么熟悉的数据库报错！这就是典型的 SQL 注入。 

我们的 Laravel 是带了有直接拼凑语句的写法的。

就是使用 whereRaw或者selectRaw

![](../Images/017ba690c08564f131bc7ffe1b11af2c.png)

这时候我们去查询一下。

![](../Images/3c64f05f04c80808f098c11b076cdbdc.png)

正常是都可以查出来的，这时候我们去注入一下。http://a.com/index?id=1 union select 1,2,3,4 #

![](../Images/1ac8e73c00a0ff88543d4c5eda99741e.png)

然后我们可以看到这里引发了注入。如果说见到了拼凑出来的 SQL 语句，这里我们就要当心一下了，我们如何在这里修复这个漏洞 呢？

  

修改这一条语句为：

$data = DB::table("users")->whereRaw("id=?",$id)->get(); 

这样就不会存在注入了。我们再去查询一下

![](../Images/59592519d4f7c4926bd81613b9bfda5a.png)

我们就发现会把绑定值带进去，这里下面的带入 SQL 语句就无效了。我们下面就来大概分析一下这个注入是怎么产生的。

![](../Images/5dcee4e174bfefb2b3f70cc02a3d62b5.png)

首先得到 $id ，我们跟进去看到实例化对象

![](../Images/89b97b91d85aac79c66b9d86f2936ebf.png)

我们继续走，来到 whereRaw

$this->wheres\[\] = \['type' => 'raw', 'sql' => $sql, 'boolean' => $boolean\]; 这里我们走下去看一下 $this 的值

![](../Images/0068a3aec2b32d3b044bad173408c293.png)

然后 addBinding

![](../Images/d3e65e3129fc9efddb515531ff0983fa.png)

也是对 $this 进行赋值，继续走来到 get()

![](../Images/667bbc556325f02705b00fec097b79bf.png)

我们来看一下它怎么带入我们的 SQL 语句的 来到 onceWithColumns 还是跟之前分析一样走进 SQL 查询，我们直接走到 compileSelect ，看 他如何进行拼接

![](../Images/bfb13dca494edabe0d1e804b22468ca2.png)

我们可以看到经过拼凑的语句是带着注入的，然后一路 F8 到 getBindings

![](../Images/0f35b50a65ef8e452be03faa9411e9a8.png)

我们可以看到我们的 Bindings 值是空的，所以不会进行任何替换 紧接着来到了 select ，走进去

![](../Images/27199f2e39152f4fc350d120273c5108.png)

跟到 prepared 这里

![](../Images/f8ec19b72be1312b1f9483e8a91b9585.png)

我们的 $query 没有任何变化，所以执行之后就会引发注入。这就是我们完整的注入流程
