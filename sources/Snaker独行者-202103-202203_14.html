记录自己的权限维持测试，主要介绍RID劫持姿势，没那么多理论解释，先学会利用再好好深入研究其原理吧。文章末尾会针对实战场景对此方法进行评价。

 

如有错误之处，望各位师傅们斧正。



0x01 实验环境


受害机：Windows Server 2008 R2（假设此服务器已被控制并获得system权限）



0x02 利用姿势


首先使用 runas 命令指定用户起一个cmd

runas /user:snaker cmd



然后使用 whoami /user 命令查看用户RID为1005，对应的十六进制为0x3ED（下面会用到）



尝试写文件至 C:\Windows 目录，显示拒绝访问，显然权限不够。



接着利用 PsExec 工具以 system 权限打开注册表

PsExec.exe -i -s -d regedt32.exe




找到 HKEY_LOCAL_MACHINE\SAM\SAM\Domains\Account\Users\ 路径，因为snaker用户的RID十六进制为0x3ED（上面有解释），所以对应的是000003ED文件。



修改F键的二进制数值，将此处的 "ED 03"（即 snaker 用户的RID十六进制0x3ED）修改成 "F4 01"（即 Administrator 用户的RID十六进制0x1F4，十进制为500，默认项）



通过这种方式可以让 snaker用户在不加入管理员组的情况下拥有管理员权限，现在再利用 snaker 用户查看写文件至 C:\Windows 目录验证，如图：



这时的 snaker 用户已经具备 Administrator 权限，但是很显然，这种用户是很容易被发现的，哪怕是隐藏用户也一样，所以为了不引人注目，要使用 Guest 用户进行才可以，前提是要激活 Guest 用户。
## 激活方法net user guest /active:yes
如果存在360/火绒等，用免杀 manager.exe 绕过检测激活 Guest 用户
免杀manager.exe可以通过回复 guest 获得



当然此工具还有很多用法

## 添加snaker用户manager.exe /add snaker 123456
## 删除snaker用户manager.exe /del snaker
## 激活guest用户manager.exe /active guest yes
## 关闭guest用户manager.exe /active guest no
## 修改guest用户密码manager.exe /change guest admin123456


激活 Guest 用户后，先修改密码，再指定 Guest 用户起一个cmd，再按照如上的RID劫持操作即可，这里就不重复 snaker 用户的操作步骤了。




0x03 检测方法


检查除 Administrator 外的用户的RID值是否为500（只有管理员用户的RID默认值为500）



0x04 总结想法


这里暂且先不讨论实战的应用性、隐秘性强不强，单论检测方法来说，就可以发现其实隐秘性不强，从第三点的检测方法可以看到，排查的方法很简单，所以单是这一点，我觉得以这种方法做持久化权限维持，就已经不现实了。
 
接着我们继续考虑一点，相信你们也发现了，上面的利用姿势是需要与目标Windows桌面进行交互的，也就是说我们要远程登录到目标主机上才可以进行RID劫持，那么要远程登录，最关键的是获取目标主机的明文密码，然而Windows Server 2012版本及其以上的只能读到Hash，只有Windows Server 2012版本以下的可以获得明文密码，所以对于无法远程登录的目标主机，就无法使用RID劫持了。
 
在实战中，通常我们都是先拿到webshell，然后再想办法提权。假设此时是利用webshell版的烂土豆提权成功（大多实际情况也如此），得到的也只是webshell版的最高权限shell，这是无法与Windows桌面进行交互的，只能cmd执行命令。又因为远程登录目标主机存在一定局限性，所以我觉得RID劫持的权限维持方法，效果一般吧。
