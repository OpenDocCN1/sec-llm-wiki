**0x01   Avatar Uploader1**

第一题比较简单，主要考的是两个函数对文件判断的区别。

  

  
  
  

<?php

error\_reporting(0);

  

require\_once('config.php');

require\_once('lib/util.php');

require\_once('lib/session.php');

  

$session = new SecureClientSession(CLIENT\_SESSION\_ID, SECRET\_KEY);

  

// check whether file is uploaded

if (!file\_exists($\_FILES\['file'\]\['tmp\_name'\]) || !is\_uploaded\_file($\_FILES\['file'\]\['tmp\_name'\])) {

  error('No file was uploaded.');

}

  

// check file size

if ($\_FILES\['file'\]\['size'\] > 256000) {

  error('Uploaded file is too large.');

}

  

// check file type

$finfo = finfo\_open(FILEINFO\_MIME\_TYPE);

$type = finfo\_file($finfo, $\_FILES\['file'\]\['tmp\_name'\]);

finfo\_close($finfo);

if (!in\_array($type, \['image/png'\])) {

  error('Uploaded file is not PNG format.');

}

  

// check file width/height

$size = getimagesize($\_FILES\['file'\]\['tmp\_name'\]);

if ($size\[0\] > 256 || $size\[1\] > 256) {

  error('Uploaded image is too large.');

if ($size\[2\] !== IMAGETYPE\_PNG) {

  // I hope this never happens...

  error('What happened...? OK, the flag for part 1 is: <code>' . getenv('FLAG1') . '</code>');

}

看一遍代码可以发现奇怪的地方，在对上传的文件进行类型判别的时候，第一次使用的是finfo\_open，第二次使用的是getimagesize。

  

而我们要拿到flag的条件是第一次被判定为png图片，第二次被判定不是png类型。所以问题就在于这两个函数的差异判断。

**0x02   Avatar Uploader2**

  

比较有意思的是这个第二题，首先题目自定义了个session相关的类  

  

  
  
  

<?php  
class SecureClientSession {  
 private $cookieName;  
 private $secret;  
 private $data;  
  
 public function \_\_construct($cookieName = 'session', $secret = 'secret') {  
   $this->data = \[\];  
   $this->secret = $secret;  
  
   if (array\_key\_exists($cookieName, $\_COOKIE)) {  
     try {  
       list($data, $signature) = explode('.', $\_COOKIE\[$cookieName\]);  
       $data = urlsafe\_base64\_decode($data);  
       $signature = urlsafe\_base64\_decode($signature);  
  
       if ($this->verify($data, $signature)) {  
         $this->data = json\_decode($data, true);  
       }  
     } catch (Exception $e) {}  
   }  
  
   $this->cookieName = $cookieName;  
 }  
  
 public function isset($key) {  
   return array\_key\_exists($key, $this->data);  
 }  
  
 public function get($key, $defaultValue = null){  
   if (!$this->isset($key)) {  
     return $defaultValue;  
   }  
  
   return $this->data\[$key\];  
 }  
  
 public function set($key, $value){  
   $this->data\[$key\] = $value;  
 }  
  
 public function unset($key) {  
   unset($this->data\[$key\]);  
 }  
  
 public function save() {  
   $json = json\_encode($this->data);  
   $value = urlsafe\_base64\_encode($json) . '.' . urlsafe\_base64\_encode($this->sign($json));  
   setcookie($this->cookieName, $value);  
 }  
  
 private function verify($string, $signature) {  
   return password\_verify($this->secret . $string, $signature);  
 }  
  
 private function sign($string) {  
   return password\_hash($this->secret . $string, PASSWORD\_BCRYPT);  
 }  
}  

  
  
  

  

这里的cookie值是在save函数中定义的

将传入的data转成json类型，然后value值分为两部分

  

第一部分是 明文的json转为base64类型

第二部分是 明文的json经过sign函数加密再转为base64类型

  

我们登录题目 解密一下它给的cookie

  

![](../Images/5f28fe74560696ca4038c40aca130032.png)

  

后面的是一串看不懂的字符，不过没关系，我们看看它的加密方法

  

  
  
  

  private function sign($string) {

    return password\_hash($this->secret . $string, PASSWORD\_BCRYPT);

  }

  
  
  

  

传入的string经过 password\_hash处理，而这个password\_hash有一个问题，就是只能处理72个字符，多余的会忽略掉。

  

![](../Images/096095f01fee6701b7cccf55bb8566e5.png)

  

也就是说如果当前session的字符超过了72个，那么它后面无论添加什么，加密出来的字符都是一样的。说这个有什么意义呢？

  

session中定义了一个verify函数，并且在\_\_construct函数中用到

  

  
  
  

  private function verify($string, $signature) {

    return password\_verify($this->secret . $string, $signature);

  }

  

public function \_\_construct($cookieName = 'session', $secret = 'secret') {

    $this->data = \[\];

    $this->secret = $secret;

  

    if (array\_key\_exists($cookieName, $\_COOKIE)) {

      try {

        list($data, $signature) = explode('.', $\_COOKIE\[$cookieName\]);

        $data = urlsafe\_base64\_decode($data);

        $signature = urlsafe\_base64\_decode($signature);

  

        if ($this->verify($data, $signature)) {

          $this->data = json\_decode($data, true);

        }

      } catch (Exception $e) {}

    }

  
  
  

  

构造函数的意思就是，将我们的cookie拿出来，通过.分割为两部分，再进行base64解码

  

然后再判断 明文data和经过加密的值是否匹配。

  

所以如果我们第一次构造出一个超过72字符的明文data，我们无论加什么字符再后面把它拼回去，都能和经过加密的值匹配上。

  

那这又有什么用呢？

  

  
  
  

<html>  <head>    <meta charset="utf-8">    <title>Avatar Uploader</title>    <style>/\* common.css \*/<?php include('common.css'); ?>/\* light/dark.css \*/<?php include($session->get('theme', 'light') . '.css'); ?>/\*\*/

  public function get($key, $defaultValue = null){

      return $defaultValue;

    return $this->data\[$key\];
