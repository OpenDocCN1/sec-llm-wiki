### oxo1 前言

在日常的漏洞挖掘中，js文件往往能带来不少惊喜。今天碰到在 JS文件中发现了一枚SQL注入，下面就记录一下，希望可以对您有一点点帮助。（水了这么多垃圾废话就是为了 300 个字发原创，真的不容易。）

  

### oxo2 过程

打开网站，右键查看源代码，看哪个 JS 比较顺眼就打开。快速浏览发现一个有意思的请求，不妨请求看一看

![](../Images/6a9c652f075e1fd6632d08513bc0e517.png)

明显的 SQL 注入报错，捡到宝了

![](../Images/05e5b4d3090a57de68fb49f129ce5252.png)

当时的想法，分别给三个参数来确认可控位置，因为报错也没看到它原始SQL语句

![](../Images/dce5ef4c6d0fd3ff9e7ed7d02a3c1397.png)

给一个单引号就可以看到 sys\_where 也是可控的

![](../Images/07202eb740c9b7edea6ee28ef7b156a1.png)

尝试查询 user ，发现 sys\_Table 语法不对

![](../Images/39a224382eaa35cf13bdf94833250077.png)

Table 这可能是要填一个表名，随手输入一个 admin。admin不存在，尝试 Fuzz ，但没有字典就先放弃这个办法

![](../Images/43ee866c3d9b69610c6080a41656f764.png)

突然想到，他的 JS 好像就有写。

![](../Images/a08ba0ea3de1c01206d0e1bd71b3e04d.png)

成功得到 user ，sys\_Table 是  base64 ，因为上面的 JS 会解开。不加密发现也可以，使用双引号引起来就好了。

![](../Images/30ed55316d8244f643d2985386d5ea24.png)

查询当前数据库库名

![](../Images/10fab7460475f79c1caf39733cf29ab1.png)

点到为止，就不继续深入下去。
