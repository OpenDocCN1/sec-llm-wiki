《Incident Response & Computer Forensics, Third Edition》阅读笔记系列——开展事件调查确认初步事实（一）。

1. 收集初步事实

关于事件的最初事实是开始调查前所必须的，而且收集有关这些事实的其他信息也很重要，这样您就可以建立上下文。例如，如果您知道 IP 地址属于哪个系统以及该系统执行承担什么角色会更有用。此外，如果您不知道相应的时区，那么事件发生的时间就没那么有用了。如果没有这种背景信息，很容易就事件的含义得出错误的结论。

接下来的几节介绍了我们设定的Checklists、调查技巧以及建立攻击时间线的重要性。

1.1 Checklists

我们在本节中介绍了五个清单：事件摘要、事件检测方式、系统详细信息、网络详细信息和恶意软件详细信息。我们当然可以为其他领域制作清单，但我们发现这些领域对于事件响应调查来说是最常见和最有用的。此外，这些清单并不意味着包罗万象。您可能需要添加、删除或更改项目以使清单更适合您的组织。我们将本书中的这些和其他清单作为附录 A 包含在的配套网站 ir3e.com 上。

事件摘要Checklist

您应该完成的第一个清单用于收集事件的基本生命信息；它被称为事件摘要Checklist。此Checklist的目的是记录有关事件的信息。收集的信息应该让您大致了解所发生的事情，并且应该有助于确定您的响应协议可能需要注意的领域。

  • 报告事件的日期和时间。

  • 检测到事件的日期和时间。通常，报告事件的时间比实际检测时间晚。确保在实际检测到问题时进行跟踪和记录。

  • 记录此信息的人的联系信息。

  • 报告事件的人的联系信息。

  • 检测事件的人的联系信息。如果组织是由外部方通知的，请确保记录所有详细信息并保留原始的书面沟通。

  • 事件的性质。提供检测到的分类：大规模恶意软件、鱼叉式网络钓鱼尝试、登录失败、未经授权的访问等。

  • 受影响资源的类型。有时，检测或通知会提供有关可能受到影响的数据或资源的详细信息。

  • 如何检测到事件。提供检测方法的简要摘要，例如EDR告警、IDS 告警或用户报告的可疑行为。

  • 受事件影响的计算机的唯一标识符和位置。确保获得真正唯一的标识符获取主机名或资产标签号通常更有用。

  • 自检测以来谁访问了系统？记录自检测以来访问系统的人员非常重要，以防调查人员需要有关他们所做工作的详细信息。有时，IT 人员或其他人可能会采取他们认为“有帮助”但难以与恶意活动区分开来的行动。

  • 谁知道该事件？

  • 事件当前是否正在进行。

  • 是否需要在“需要知道”的基础上保持对事件的了解。

事件检测Checklist

下一个清单用于收集有关如何检测事件以及检测系统本身的更多详细信息。仅通过彻底收集和检查有关检测的详细信息，我们就解决了许多“事件”。查看细节让我们看到有些事情被误解了，并且帮助证实没有发生任何事件。根据我们的经验，花额外的时间来验证检测是值得的。

  • 检测是通过自动还是手动过程？是否有人工或自动化系统检测到事件？请注意，此检测可能来自外部来源，因此了解自动化系统是否提示它们或是否是手动分析的结果对于考虑其有效性很重要。

  • 什么信息是最初检测的一部分？记录有关初始检测中存在的信息的详细信息。如果最初的检测是一个警报，你有它的副本吗？如果检测来自一个人，您是否与他们交谈以记录他们所看到的内容？保持合理的怀疑态度，并确保关注原始数据，以确认您被告知的内容。

  • 哪些来源提供了有助于检测的数据？如果来源是一个人或多个人，请记录他们的联系信息。如果来源是一个或多个自动化系统，请提供有关有助于检测的每个系统的详细信息。注意自动化系统存储的时区。

  • 是否有人获得并验证了源数据的准确性？如果有，是谁？如果有人参与了检测，是否有人验证了他们检查的方法和数据？如果它是一个自动化系统，是否有人验证了原始数据和检测所依据的标准？

  • 是否保留了所涉及的源数据？根据所使用的系统或方法，与检测相关的数据可能不会自动保存。它可能会在若干小时或数天内从系统中清除。注意确保与检测相关的信息不会丢失。

  • 检测源运行了多长时间？谁在运行它们？有时我们会发现一个检测系统最近上线，并且正在产生误报，或者可能由于缺乏经验而导致输出被误解。记录每个系统已经存在多长时间以及谁负责维护和审查它。

  • 检测率和错误率是多少？与运行系统的人员交流并查看告警，了解此类检测的检测率和误报率。

  • 与数据源相关的任何内容是否发生了变化？在某些情况下，我们发现管理员最近对系统进行了调整或升级。您应该与负责数据源系统的人员交流，并了解最近是否进行了任何维护。

收集其他详细信息

如果您的检测细节看起来准确且一致，下一步是继续收集有关与检测相关的特定元素的其他信息。您应该向下一层收集有关各个系统、网络和潜在恶意文件的详细信息。此外，请随时深入研究事件摘要清单中收集的任何其他数据点。

单个系统详细信息

对于涉及的每个系统，请考虑收集以下信息。您应该避免将系统组合到一个文档中，因为如果您不花时间询问有关每个单独系统的这些问题，很容易忽略细节。

  • 物理位置：包含信息，以便您组织之外的人能够清楚地确定系统的物理位置，例如完整地址、建筑物编号、楼层、房间号或机架号。

  • 资产标签编号：这是IT人员用来跟踪资源的编号。它可能与系统的序列号一样简单，也可能是由第三方应用程序分配的编号。

  • 系统的品牌和型号：了解品牌和型号非常重要，这样您就可以适当地计划您可能采取的任何行动。

  • 安装的操作系统：记录操作系统的类型和版本对于规划目的也很重要。您可能没有特定操作系统所需的工具或内部专业知识。

  • 系统的主要功能：了解系统的主要功能有助于建立上下文。系统是网络服务器？数据库服务器？提供了哪些网站或数据库？系统是某人的笔记本电脑吗？这是谁的笔记本电脑？他们在组织中的什么位置？您对工程师系统采取的响应步骤将与您对会计部门的服务器采取的响应步骤不同。

  • 负责的系统管理员或用户：如果您需要保存证据，您可能需要系统管理员的帮助。在某些时候，管理员需要被告知正在发生的事情——当然，如果他们不是调查的对象。

  • 分配的IP地址：请注意，某些服务器具有多个接口，包括物理接口和虚拟接口。记录当前 IP 地址并附上说明该地址是通过 DHCP 分配还是静态配置的注释。后续线索可能是 DHCP 日志的收集。

  • 系统的主机名和域：在处理基于 Microsoft Windows 的系统时，不要忘记包括工作组或域名。后续线索之一将是查询域生成的日志。

  • 存储在系统中的关键信息：这将基于系统的主要功能。如果系统是源代码存储库，您应该找出其中存储了哪些项目。如果系统是员工的笔记本电脑，那么该员工会做什么？也许他们在人力资源部门，他们的笔记本电脑包含人事档案和其他敏感信息，或者是具有与特定程序相关的原理图的工程师。

  • 系统是否存在备份：及时的快照可以为调查提供有价值的信息。重要的是要知道系统的备份是否存在、它们可用的时间范围、它们被覆盖的时间以及如何请求访问它们。

  • 系统是否仍连接到网络：如果系统已断开连接，它现在在哪里？响应者如何访问它？

  • 检测到的恶意软件列表，从调查时间到日志数据的开始：记录恶意软件检测的详细信息——日期、时间、文件名、目录以及反病毒系统记录的类型和系列。查明恶意软件是否已提交给您的 AV 供应商或任何第三方扫描站点。如果事件响应团队以外的人员拥有恶意软件的副本，您应该提醒他们不要保留它，并让他们向您提供副本。

  • 已采取的任何补救措施的列表：用户是否删除或复制了文件？也许管理员进行了配置更改或执行了密码重置。对系统的任何更改、更改人员以及更改时间都必须记录在案。在许多事件中，我们无法区分攻击者活动和响应者活动，因为它们重叠并且没有进一步的信息可以提供帮助。

  • 如果有任何数据被保存，正在使用什么流程以及存储在哪里：我们遇到过许多事件，工作人员非常乐于保存信息，但不了解取证做法。您应该了解正在保存哪些数据以及如何保存这些数据。确保所有相关工作人员都了解并使用事件响应团队记录的公认做法。

网络详细信息

  • 涉及的所有外部恶意 IP 地址或域名的列表：记录与事件有关的任何 IP 地址、域名或主机名。进行一些快速研究——检查 whois 服务。

  • 是否正在执行网络监控：如果网络管理员设置了网络捕获设备，请确定执行该设备的人员、执行捕获的位置（物理上和逻辑上）、存储数据的位置以及谁可以访问它。明确应用于捕获的过滤规则以及捕获是否包含会话的完整内容或仅包含标头（连接）信息。

  • 已采取的任何补救措施的列表：确定诸如阻止 IP 地址或某些域名之类的步骤是否已被重定向到“黑洞”。找出这些控制措施是何时实施的。

  • 如果有任何数据被保存，正在使用什么流程以及存储在哪里：与单个系统详细信息类似，请确保与网络检测相关的任何数据都得到正确处理和跟踪。

  • 网络图和配置的更新：获取网络图和配置的任何更新.

恶意软件详细信息

  • 检测日期和时间。

  • 如何检测到的恶意软件。

  • 发现恶意软件的系统列表。

  • 恶意文件的名称，以及它所在的目录。

  • 检测机制确定的内容，例如恶意文件的名称和家族。

  • 如果恶意软件在事件响应期间处于活动状态并且存在活动的网络连接。

  • 是否保留恶意软件的副本，无论是手动还是通过隔离过程。

  • 任何分析的状态。是否对恶意软件进行了网络和主机入侵指标分析？

  • 恶意软件是否通过自动化流程或通过员工的直接行动提交给第三方。

2. 事件案例笔记

在响应事件的整个过程中，做笔记很重要。从最初检测或通知的那一刻起，到最终报告和披露文件，保存案例记录至关重要。当发生很多事情并且同时发生多起事件时，案例笔记将使您保持清醒。

案例笔记有三个主要目的：它们让你保持专注，它们允许其他团队成员从你中断的地方继续调查，它们允许第三方复现你所做的事情。

我们通常将案例记录保存在结构松散的非正式文档中。你应该很容易写下关于你做了什么、你在想什么、你所做的发现、其他人做了什么以及你接下来打算做什么的快速笔记。通常按时间顺序记录这些信息。我们并不是说你需要记录你的一举一动，而是更高级别的任务及其结果。保持你的笔记专业，因为它们可能会被外界阅读。

最后，不要将记录案例笔记与记录攻击者活动混为一谈——案例笔记是您所做的，而不是攻击者。

2.1 建立攻击时间线

在我们执行的每项调查中，我们都会维护事件时间线。

时间线让我们有条不紊，帮助识别出异常之处，并提供所发生事件的总体情况和背景信息。

        将新信息与时间线进行比较有助于验证新线索。例如，如果您发现表明初始攻击发生在您当前记录的最早日期前六个月的信息，您要么在案件中取得重大突破，要么正在查看不相关的信息。

        另一个例子可能是事件序列。想象一个场景，您发现攻击者创建了一个文件，然后将其传输出网络。将信息放入时间线后，您会注意到您的代理服务器为传输记录的时间戳早于文件的创建日期。因为文件必须在传输之前存在，所以您正在查看的数据或您解释它的方式有问题。

        攻击时间线侧重于重要的攻击者活动。例如攻击者何时访问系统、何时创建文件、何时传输数据以及何时执行工具。在时间线上记录数据的来源也很重要。例如，如果您输入了攻击者访问系统的目录，请包括您在何处找到该信息。

3. 了解调查重点

要进行成功的调查，必须考虑目标和期望的结果。每种案件类型都有其自身的考虑因素——无论目标是诉讼还是仅仅为了加强安全态势。

什么是证明要素？

在法律意义上，证明要素定义了主张的支持要素。例如，如果您要调查一项盗窃指控，您的主要证据要素可能是证明材料的获取是为了剥夺他人的财产。然而，企业事件响应团队执行的调查可能并不像盗窃或侵犯版权那么容易定义。在入侵调查期间，我们对“证据要素”进行了更广泛的定义，其中声明在开始时很少且范围很广，随着时间的推移会发展出更多的细节。

关键是要记住您将生成的报告的主要消费者。例如，许多入侵调查的目标很简单。您需要确定谁闯入、何时发生、他们访问了什么。另一方面，在怀疑账户数据丢失的支付卡行业 (PCI) 调查中，目标需要包括生成可能受损的帐号列表和丢失发生日期的需求。其他类型调查的目标可能不太明显，可能需要与法律顾问进行额外计划。

与管理层设定预期目标

当您的组织考虑启动调查时，您应该花点时间回顾影响您的目标合理性的因素。这将帮助您对管理层设定适当的预期目标，并让他们以及你做出正确的决定。您需要考虑可用的证据来源、事件的类型、必须回答的问题以及必须花费的时间。例如，在网络入侵期间，攻击者经常使用海外跳板，如果违规发生在几个月或几年前，则可能几乎没有证据可供审查。这些因素在调查期间可能会发生变化，因此最好定期重新评估它们以确保预期仍然合理。一旦您对根据当前情况的预期有一个合适的想法，确保您与管理层有效沟通，并做出明智的决定。
