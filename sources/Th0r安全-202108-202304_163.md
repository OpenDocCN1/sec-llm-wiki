正文  

  

ingress可以配置用于提供外部可访问的服务url、负载均衡流量、SSL终端和提供虚拟主机名配置。ingress controller负责实现（通常使用负载均衡器(loadbalancer)）入口（ingress）。但是它也可以配置你的边缘路由器或额外的前端来帮助处理流量。  
ingress不暴露任何端口或协议。将HTTP和HTTPS之外的服务公开到因特网通常使用类型是NodePort或loadbalance的service。

Ingress和Pod关系:

Pod和ingress通过service关联的

ingress作为统一入口，由service关联一组pod

  

不用ingress实现的对外:

1、把端口号对外暴露，通过ip+端口号进行访问

   #使用service里面的NodePort实现

2、NodePort缺陷

在每个节点上都会起到端口，在访问时候通过任何节点，通过节点+暴露端口号实现访问

意味着每个端口只能使用一次，一个端口对应一个应用.实际访问中都是用域名，根据不通域名跳转到不同端口服务中

Helm是一个Kubernetes的包管理工具，就像linux下的包管理器，如yum/apt等，可以很方便的将之前打包好的yaml文件部署到kubernetes上

helm  是一个命令行毒客户端，主要用于kubernetes应用chart的创建、打包、发布和管理

chart : 应用描述，一系列用于描述k8资源相关文件的集合，把yaml打包，是yaml集合

Release:基于chart的部署实体，一个chart被helm运行后将会生成对应的一个release；将在k8s中创建出真实运行的资源对象

  

优势:

使用helm可以把这些yaml文件作为一个整体管理

实现yaml高效复用

使用helm应用级别的版本管理

  

第一步下载  helm安装压缩文件，上传到linux系统中

第二步 解压helm压缩文件，把压缩之后helm目录复制到usr/bin目录下

  

![](../Images/c48b18417d50e398c88bd26a24ec13ae.png)

  

helm repo  add 仓库名称

  

使用helm快速部署应用

第一步使用命令搜索应用

helm search repo 名称

  

第二步 根据搜索内容，选择安装

helm install  安装之后名称，搜索之后应用名称

  

查看安装之后状态

  

helm list

helm status 安装之后名称

应用升级

helm upgrade web1 mychart/
