# ShadowHammer活动分析

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzUxMDk3ODEwOA==&mid=2247484044&idx=1&sn=c4d60f665f633dab5d705bbfc906ca17&chksm=f97bf3dfce0c7ac9510a7cd73360077ab1e5935227190034d157048d332032caca2af95b299c&scene=126&sessionid=1681272454#rd](http://mp.weixin.qq.com/s?__biz=MzUxMDk3ODEwOA==&mid=2247484044&idx=1&sn=c4d60f665f633dab5d705bbfc906ca17&chksm=f97bf3dfce0c7ac9510a7cd73360077ab1e5935227190034d157048d332032caca2af95b299c&scene=126&sessionid=1681272454#rd)

    ShadowHammer供应链攻击活动，也就是2018年6月至11月期间对某APT组织对华硕Live Update Utility的供应链攻击，有攻击组织入侵华硕公司电脑补丁更新服务器，借助华硕产品的合法签名攻击者隐藏在在线升级补丁功能下，利用Setup.exe感染真正的目标。卡巴斯基2019年3月25日发布报告，此事件从公开伊始便受到了广泛关注，国内国外安全厂商和技术大牛都做了分析。今天就还原下事件，多方面梳理下ShadowHammer供应链活动。

**【1、时间线**】

  

*   ## **2018年6月：攻击开始**
    

在第一个已知版本中，Setup.exe部分中的嵌入式可执行文件已被另一个包含shellcode的较小可执行文件部分覆盖。可执行文件没有加密，并且有一个PDB字符：D:\\C++\\AsusShellCode\\Release\\AsusShellCode.pdb

目标MAC地址哈希的数量非常少。在发现的最早的样本中，范围内只有18个设备。如果匹配成功，shellcode将从以下URL下载文件并执行它。

hxxps://asushotfix.com/logo.jpg  

*   ## **2018年7月初：增加INI文件**
    

7月时间内，setup.exe添加了一些有意思的功能。如果与任何目标MAC地址都不匹配（大多数设备都是这种情况），则将创建或更新INI文件“idx.ini”写入不同的条目，其日期值对应于7天/一周后。例如：如果它是2019-03-29创建的，那么idx.ini中的时间就是2019-4-5：

\[ IDX\_FILE \]

XXX\_IDN = 2019 - 04 - 05

XXX\_IDE = 2019 - 04 - 05

XXX\_IDX = 2019 - 04 - 05

INI文件存储在存储setup.exe的目录结构中的2级目录中。每次迭代添加了更多MAC哈希值，在2018年7月23日编制的样本中目标数量增加到200多个。

*   ## **2018年8月中旬：静默前行**
    

这段时间，疑似攻击者花了更多时间重写一些代码来更好地隐藏攻击载荷。恶意有效载荷这8月的样本中已经完全加密，并且已经成为真正的shellcode。PDB字符串消失，并且不再有编译时间戳，这使得确定创建的确切日期变得更加困难。目标MAC列表再次增长，现在有近300台设备。

*   ## **2018年9月初：新的文件**
    
    ## 一个小变化是URL改为：
    

hxxps://asushotfix.com/logo2.jpg

此外，还增加了几个目标哈希值，共计307个条目。

*   ## **2018年9月下旬：目标变化**
    

到2018年9月以后，目标MAC地址发生有趣的变化：攻击者只增加了目标MAC。换句话说，较旧的样本始终包含MAC是较新样本的子集。在持续一个多月的袭击的最后阶段，这种情况发生了变化。新变种的出现，一些目标MAC的数量开始波动 ，一些被删除，一些被添加。截止到3月28日，安全厂商共计统计出619个目标MAC地址。下面链接是完整的583个目标MAC地址。

https://skylightcyber.com/2019/03/28/unleash-the-hash-shadowhammer-mac-list/list.txt

  

*   **2018年6月至2018年11月：渗透攻击**
    

外媒称，有黑客在2018年6月至2018年11月期间获得了华硕服务器的权限。

**【3、受害者分析】**

  

   根据600多个MAC地址，其实可以粗略的分析出攻击者对于目标范围的限定，华硕主机（台湾）、LITE-ON公司（台湾）、VM主机、英特尔、华为设备、鸿海精密工业股份有限公司（富士康）、Azurewave Technology（台湾厂家）和00ff5e开头的虚拟机等等都是攻击者的目标。下图是360威胁情报中心给出的受害者MAC分布图：

**【4、攻击者分析】**

  

  在卡巴斯基的报告中，卡巴斯基表示攻击者可能是BARIUM组织。卡巴斯基的原文是这样描述的：“certain evidence we have collected allows us to link this attack to the ShadowPad incident from 2017. The actor behind the ShadowPad incident has been publicly identified by Microsoft in court documents as BARIUM”卡巴斯基表示，本次事件有充足的证据可以与另一起发生在2017年报道的ShadowPad（木马）供应链攻击活动关联起来，而ShadowPad攻击活动的发起者已经被微软定义为BARIUM组织所做。卡巴斯基表示，4月8日新加坡的SAS 2019会议期间将公布完整的结果和技术论文。利用微软的报告，我们可以简单梳理下BARIUM的TTP特征：  

*   BARIUM通过公开信息和社交媒体收集有关其员工的大量信息，利BARIUM使用hostay88@gmail.com电子邮件地址注册域名nott3ed.com和operatingbox.com，Barium还将相同的电子邮件地址链接到使用的Microsoft帐户（johnxl9@hotmail.com） 在Microsoft论坛网站TechNet上创建恶意配置文件。某些情况下，该组织已使用具有代码签名证书的可执行文件来避免检测。
    
*   使用网络钓鱼技术进行传播“Barlaiy”和“PlugXL”恶意软件。另外利用四三方工具“升级”等功能分发“ShadowPad”恶意软件。触发漏洞或者执行木马的方式多种多样，包括MS宏文档触发执行、MS漏洞触发执行，CHM文件执行、LNK文件执行、压缩文件隐藏、恶意链接等等。
    
*   BARIUM将C2命令放置在博客或者其他正常网站中躲避网络恶意C2检测，涉及的网站包括领英、github、微软博客等。
    
*   BARIUM在攻击NetSarang的活动中，将恶意代码ShadowPad利用高级算法加密并且注入到具有高访问权限的DLL文件目录中躲避检测。ShadowPad使用“DGA”域名算法生成域名。通讯过程中，为避免被日志记录或者白名单，BARIUM通过DNS协议发送C2指令。ShadowPad恶意软件在查找C2时先按照自定义域查找，然后在通过公共域查找，还可以在受害者本地利用DNS查找。
    

那么卡巴斯基手中到底有哪些“证据”呢？不妨我们来猜一下（若猜不对，观众姥爷图一乐就行）:

*   网络基础复用，包括域名、邮箱、IP等多次使用。
    
*   样本同源分析，可能涉及ShadowPad、Winnti、PlugXL、Barlaiy。
    
*   TTP相似度
    
*   攻击日志被捕获（特别是攻击华硕服务器日志）
    
*   攻击使用VPS或者木马控制端被取证。

**【5、溯源分析】**  

  

  写这个标题其实不是真的做溯源分析，是想提出一些可以溯源分析的线索。拿本次案例举例：本次案例中攻击者使用的C2是：asushotfix.com。攻击时间线在上文中我已经写好，主要时间线为2018年6月-11月。那么我们先开看一下C2的解析以及WHOIS情况：

域名asushotfix.com注册时间为2018-05-03T10:26:36，域名做了WHOIS保护。

域名PassiveDNS解析如下表：

| Time || PassiveDNS |
| :-: | :-: |
| 2018-05-03 2018-05-13 || 107.161.23.204、192.161.187.200、209.141.38.71 |
| 2018-05-22   2018-10-25 || 141.105.71.116 |

可以看到，攻击活动期间的IP地址为：141.105.71.116。而这个IP的解析记录如下：

| simplexoj.com || 2018-09-11 || 2018-10-27 |
| --- | --- | --- |
| homeabcd.com || 2018-09-05 || 2018-10-27 |
| asushotfix.com || 2018-05-22 || 2018-10-25 |

  在对IP：141.105.71.116的定义为VPS后，我们认为域名simplexoj.com、homeabcd.com与攻击者存在某种关联，当我们再次查询simplexoj.com、homeabcd.com的解析记录后和注册记录后，我们发现simplexoj.com、homeabcd.com、asushotfix.com这三个域名惊奇的一致。我们确定了simplexoj.com、homeabcd.com是攻击者拥有的网络资产。

   那么知道这3个域名之间有关联，然后呢？然后怎么做呢？提几点想法：

1.  找另外两个域名在网络中的活动指纹，包括历史页面、恶意记录、端口情况等
    
2.  分析这两个域名可能被攻击者用来做哪些活动。钓鱼？
    
3.  怼141.105.71.116同段（怎么怼自己考虑）
    

  

**还有哪些溯源的线索可以挖掘？**

  我们回头想想攻击者的攻击流程，攻击者真正的目标不是华硕，而是利用华硕电脑升级软件感染“受害者”。攻击者的目的无论是窃取信息还是破坏系统，都需要下一步指令，那么也就是说，C2:asushotfix.com和ShadowPad恶意软件起到了“前锋”作用，老鼠啦镐头，大头在后头！攻击者真正的战略行为还未可知。回到本文中，我们考虑以下线索值得注意：

1.  攻击者登录VPS控制台的IP（跳板、肉鸡）。
    
2.  攻击者购买域名和VPS记录
    
3.  攻击者攻击华硕服务器日志（网络日志、主机日志、软件日志等）
    
4.  攻击者使用的攻击跳板或者VPN。
    
5.  攻击者在华硕内网留下的横向移动或者提权等指纹。
    
6.  攻击者是否对真正“MAC”受害者做了操作，哪些操作，指令如何？
    
7.  ……
