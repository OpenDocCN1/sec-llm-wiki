最近在工作中完成了一个基于spark-streaming的nginx日志大数据实时分析平台，在整个过程中遇到了很多坑。所以在这里主要写一下spark集群的详细搭建指南，以及如何优雅的实现spark的任务管理和动态资源分配。希望这篇文章可以给有同样需求的同学们带来一些帮助。

## 0\. 关于spark的部署模式

spark最常见的部署方式是 **standalone** 和 **yarn**。在尝试过使用yarn来部署之后，我决定还是使用standalone的方式来部署spark。一方面是standalone模式下，集群里每台机器的资源很好做配置, 而且可以通过启动 **history-server** 来方便的查看spark任务执行时的效率和每步操作的资源占用与时耗。所以这里我比较推荐使用standalone的方式来部署spark集群。下面我会一步一步来介绍集群搭建过程中的配置操作。

  

## 1\. 基础配置

以三台位于同一局域网的 CentOS7 机器为例:

首先要做的是在三台机器上安装Java: `yum install java-1.8.0-openjdk-devel.x86_64 java-1.8.0-openjdk-devel.x86_64` 并配置一下JAVA\_HOME

然后安装Scala: scala下载地址

我推荐直接下载scala的rpm安装包, 然后在服务器上执行 `yum install scala-<version>.rpm`

> 这里需要注意的是你的Scala版本需要和编译Spark使用的Scala版本一致。比如我用的是Scala 2.12.8, 那么我之后下载的Spark安装包也一定需要是用Scala 2.12编译的。

接下来需要配置机器间SSH免密码登录:

假设我这三台主机的IP地址为 10.10.0.1、10.10.0.2、10.10.0.3 其中第一台为master节点，后两台为slave节点。以master节点为例, 我们需要将另外两台机器的ssh公钥添加到 `~/.ssh/authorized_keys` 文件中, 然后在 `/etc/hosts` 文件中添加:

```
`10.10.0.1 master 10.10.0.2 slave1 10.10.0.3 slave2`
```

这样你在master节点上就可以直接通过 `ssh slave1` 或 `ssh slave2` 来免密码登录另外两台服务器了。

同样的操作也需要在另外两台slave机器上进行。

  

## 2\. 配置Hadoop集群

这里以 hadoop-2.7.7 为例 (其他版本的hadoop配置也是基本一样的):

首先下载hadoop的压缩包到master节点上, 解压。这里我以解压目录为 `/opt/hadoop-2.7.7`、数据存储路径为`/data/hdfs`为例:

进入解压后的目录, 所有hadoop的配置文件都在 `etc/hadoop`子目录中，然后需要修改 `etc/hadoop` 中的下列文件:

*   1\. core-site.xml
    

该文件配置了hdfs的访问地址以及运行文件的存储路径，可做如下配置:

```
`<configuration>          <property>         <name>fs.defaultFS</name>         <value>hdfs://master:9000</value>     </property>           <property>         <name>hadoop.tmp.dir</name>         <value>/data/hdfs/tmp</value>     </property> </configuration>`
```

*   2\. hdfs-site.xml
    

该文件配置了hdfs datanode 和 namenode 上的文件存储地址, 可做如下配置:

```
`<configuration>          <property>         <name>dfs.namenode.name.dir</name>         <value>/data/hdfs/namenode</value>     </property>          <property>         <name>dfs.datanode.data.dir</name>         <value>/data/hdfs/datanode</value>     </property> </configuration>`
```

*   3\. hadoop-env.sh
    

在文件末尾添加 JAVA\_HOME 路径即可:

```
`export JAVA_HOME=/usr/lib/jvm/java-1.8.0-openjdk-1.8.0.212.b04-0.el7_6.x86_64/jre`
```

*   4\. slaves
    

在文件中添加两台slave的主机名即可

```
`slave1 slave2`
```

由于没有使用yarn, 所以无需配置yarn相关的配置文件。完成上述配置之后，在master节点上将整个hadoop目录scp至另外两台slave机器的 **相同目录** 即可。然后在hadoop目录下执行:

```
`# 格式化datanode bin/hadoop namenode -format  # 启动hdfs sbin/start-dfs.sh`
```

在主master点上执行jps, 可以看到 **NameNode**。在两台slave节点上执行jps, 可以看到 **DataNode**，说明集群配置成功。

  

## 3\. 配置Spark集群

在Spark配置这里, 我建议下载 without-hadoop 版本的spark压缩包, 然后在spark的classpath中配置hadoop的classpath即可，这样可以防止hadoop版本冲突。

下载spark: spark下载地址

由于我之前安装的是scala-2.12.8版本, 所以我下载的spark版本为 spark-2.4.3-bin-without-hadoop-scala-2.12.tgz

解压文件, 这里以解压目录为 `/opt/spark-2.4.3-bin-without-hadoop-scala-2.12/` 为例:

进入解压后的目录, 所有的配置文件都在`conf`子目录中，然后需要修改`conf`中的下列文件:

*   1\. spark-env.sh:
    

如目录下没有该文件、需要执行 `cp spark-env.sh.template spark-env.sh` 后再修改:

在文件中配置如下内容:

```
`# hadoop home export HADOOP_HOME=/opt/hadoop-2.7.7 # java home export JAVA_HOME=/usr/lib/jvm/java-1.8.0-openjdk-1.8.0.212.b04-0.el7_6.x86_64/jre # spark master export SPARK_MASTER_HOST=master # spark master port export SPARK_MASTER_PORT=7077 # spark worker的虚拟内存最大空间，并不是物理内存的概念 export SPARK_WORKER_MEMORY=18g # spark worker的虚拟core的最大数，并不是物理核心的概念 export SPARK_WORKER_CORES=12 # 由于下载的是without-hadoop版本, 需要配置hadoop classpath export SPARK_DIST_CLASSPATH=($HADOOP_HOME/bin/hadoop classpath)`
```

*   2\. spark-defaults.conf
    

这里可以配置很多参数, 比如很多人不知道如何开启的spark restful服务, 就可以在这里配置。你可以根据自己的需求在这里做各种spark的参数配置, 比如:

```
`# 开启rest服务 spark.master.rest.enabled = true spark.master.rest.port = 6066`
```

你也可以选择不配置该文件

*   slaves
    

配置worker节点, 比如我们将slave1和slave2作为worker:

```
`slave1 slave2`
```

配置完成之后, 同样将spark目录scp至另外两台slave机器的 **相同目录** 即可。然后在spark目录下执行 `sbin/start-all.sh`即可以启动集群。

在主master点上执行jps, 可以看到 **Master**。在两台slave节点上执行jps, 可以看到 **Worker**，说明spark集群配置成功。

  

## 4\. Spark任务管理

在完成如上操作后，我们就完成了整个spark集群的配置。下面我介绍一下我是如何做spark任务管理的。单纯的使用`spark-submit`来做任务提交，你难以去跟踪这个任务的状态，也无法优雅的kill掉它。

其实一开始其实尝试了使用apache livy来做任务管理，后来发现有很多jar包版本冲突的情况，然后又正好在网上看到有人在使用spark的隐藏restful接口做任务管理，于是就在spark-defaults.conf中配置好restful服务，通过防火墙做好访问控制，就可以很舒服的做任务的下发、状态查询和KILL了:

restful服务默认启动在6066端口, 由于基本没有官方文档，我介绍一下任务下发、状态查询和删除的接口示例:

*   下发:
    

```
`# 请求参数 curl -XPOST http://<spark-ip>:6066/v1/submissions --header "Content-Type:application/json" --data '{     "action": "CreateSubmissionRequest",     "appArgs": [arg1, arg2, ...], # 任务参数     "appResource": xxx.jar, # 提交的jar包文件地址, 如 hdfs://master:9000/xxx.jar     "environmentVariables": {         "SPARK_ENV_LOADED": "1"     },     "clientSparkVersion": "2.4.3",     "mainClass": <class_name>, # 执行的class name     # spark的参数配置     "sparkProperties": {         "spark.submit.deployMode": <deploy_mode>, # 可选 cluster/client         "spark.master": <spark-master> # master地址 如 spark://<master-ip>:7077,         "spark.port.maxRetries": 128, # 最大并行任务数         "spark.app.name": <app-name>,         "spark.executor.memory": "2g", # driver占用的虚拟内存, 默认1g         "spark.executor.cores": 1, # driver占用的虚拟core, 默认1         ......     } }  # 响应结果 {     "action": "CreateSubmissionResponse",     "message": "Driver successfully submitted as driver-20190603175350-0002",     "serverSparkVersion": "2.4.3",     "submissionId": "driver-20190603175350-0002",     "success": true }`
```

之后通过响应拿到的 submissionId, 就可以做任务状态的查询和Kill了:

*   查询状态:
    

```
`# 请求: curl -XGET http://<spark-ip>:6066/v1/submissions/status/<driver-submission-id>  # 响应结果: {     "action": "SubmissionStatusResponse",     "driverState": "RUNNING",     "serverSparkVersion": "2.4.3",     "submissionId": "driver-20190603175350-0002",     "success": true,     "workerHostPort": "10.10.0.2:40375",     "workerId": "worker-20190603173812-10.10.0.2-40375" }`
```

*   KILL:
    

```
`# 请求: curl -XPOST http://<spark-ip>:6066/v1/submissions/kill/<driver-submission-id>  # 响应结果: {     "action": "KillSubmissionResponse",     "message": "Kill request for driver-20190603175350-0002 submitted",     "serverSparkVersion": "2.4.3",     "submissionId": "driver-20190603175350-0002",     "success": true }`
```
