# Apache Tomcat Exploit准备攻击，窃取文件（CVE-2020-1938）

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzI4MDQ1MzQ0NA==&mid=2247484815&idx=5&sn=876f311a80bb1f2630413efb495c3a20&chksm=ebb90da4dcce84b2e573a0f0cf0849503ba9fa901aebdaa3587ad1e51a9090c3e706b343b614&scene=126&sessionid=1681311126#rd](http://mp.weixin.qq.com/s?__biz=MzI4MDQ1MzQ0NA==&mid=2247484815&idx=5&sn=876f311a80bb1f2630413efb495c3a20&chksm=ebb90da4dcce84b2e573a0f0cf0849503ba9fa901aebdaa3587ad1e51a9090c3e706b343b614&scene=126&sessionid=1681311126#rd)

研究人员表示，GitHub上泄漏的**CVE-2020-1938**的可利用漏洞很容易危及Web服务器。

  

得益于概念验证（PoC）漏洞在GitHub上的出现，流行的Apache Tomcat Web服务器中的漏洞已经很容易受到主动攻击。现在修补的错误会影响Tomcat 7.0、8.5和9.0版本。

![](../Images/5a5d3b5c347cb588316068cf4b8e3773.png)

根据Flashpoint分析师Cheng Lu和Steven Ouellette的说法，该漏洞已被“ Ghostcat”利用，其安全漏洞（跟踪为CVE-2020-1938，于2月20日首次公开披露）可靠地允许通过易受攻击的服务器上的文件检索进行信息泄露，而无需进行身份验证。或被诱骗的用户破坏性的互动。他们说，并且在某些情况下，它可以允许远程执行代码。

  

研究人员在上周五的一篇文章中解释说：“由于漏洞的性质，可以在没有任何用户交互的情况下利用\[漏洞利用\]，并且具有很高的可靠性，而导致受攻击的服务器崩溃的可能性很小。”两人说，他们已经确认PoC可以使用。

  

Apache Tomcat开源Web服务器支持各种基于JavaScript的技术，包括该漏洞所在的Apache JServ协议（AJP）接口。

  

AJP二进制协议（本质上是一种连接器）允许Tomcat servlet容器（称为Catalina）与Web应用程序进行通信，以支持网站的扩展功能。

  

Lu和Ouellette写道：“ AJP连接器处理（来自应用程序的）入站请求，并传递给Catalina。” “ Catalina然后将请求传递到适当的Web应用程序，并接收动态生成的内容。然后，该内容由AJP连接器通过网络发送回去，作为对请求的响应。”

  

研究人员警告说，该连接器“受到高度信任...并且不应通过不受信任的网络公开，因为它可能被利用来获得对应用程序服务器的完全访问权限，并补充说，”它预计仅在内部公开。”

  

但是，在Windows 10上的默认Tomcat安装中，暴露了Tomcat的AJP端口8009，从而允许外部用户与Tomcat服务器本身进行交互并获得对Tomcat服务器本身的访问权限。PoC漏洞演示了如何使用这种状态来公开文件。

  

PoC代码用Python编写，能够创建AJP请求并将其发送到指定的IP地址，并带有攻击者希望接收的有效文件路径和名称。容易受到攻击的服务器会将文件作为流返回到PoC代码，并在攻击者的屏幕上显示。如果请求的文件不是纯文本文件，则可以保存输出流并使用适当的应用程序打开。

  

“通过AJP连接器，攻击者可以通过ServletContext.getResourceAsStream（）函数从Tomcat的Web根检索任意文件，包括驻留在'WEB-INF'和'META-INF'目录中的文件，” 。“此外，易受攻击的Tomcat服务器上Web应用程序中的任意文件都可以通过AJP连接器作为JSP页面处理。”

  

研究人员称，该漏洞确实为RCE打开了大门。如果易受攻击的Tomcat服务器还允许文件上传（顺便说一下，不是默认设置），则攻击者可以通过AJP连接器上传自己的代码。

  

但是，有很大的收获。为了完成RCE，攻击者需要找到一个Web应用程序，该应用程序接受在易受攻击的Tomcat服务器上运行的文件上传。攻击者本身不能简单地更改服务器设置以允许文件上传。

  

分析称：“文件上传要求只能由Web应用程序开发人员实施，而不能由攻击者实施。” “因此，只有部分易受攻击的Tomcat服务器可能会受到此漏洞的代码执行的影响。”

  

此外，即使具备前提条件，公开可用的PoC代码也不支持在易受攻击的服务器上执行文件。研究人员警告说：“但是，可以在PoC代码的基础上相对轻松地实现这种功能。”

  

Web管理员应将其Apache Tomcat实例更新为8.5.51版，以避免成为受害者；或者，如果他们不使用AJP连接器，则只需禁用它们即可。Lu和Ouelette指出。他们补充说：“用户还可以考虑仅在受信任的网络段中公开连接器，而不是将其公开给整个网络，以减少攻击面。”

  

否则，剥削的壁垒非常低，因此企业应做好应对攻击的准备。

  

“公开可用的PoC和利用代码使所有技能水平的威胁参与者更容易利用此漏洞。大规模扫描活动可以识别容易受到攻击的面向Internet的Tomcat实例。因此，Flashpoint分析师以中等信心评估此漏洞可能会在恶意攻击中进行积极的利用尝试。
