# 思科解决了Webex Player中严重的RCE漏洞

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzI4MDQ1MzQ0NA==&mid=2247484481&idx=1&sn=9c4b91d3d3c02bcbf9b83fd4471e2af0&chksm=ebb90c6adcce857c277b5fef1e012e52de19fc5485c65556a7f16c31829ef9b83e5b91c93ba7&scene=126&sessionid=1681311134#rd](http://mp.weixin.qq.com/s?__biz=MzI4MDQ1MzQ0NA==&mid=2247484481&idx=1&sn=9c4b91d3d3c02bcbf9b83fd4471e2af0&chksm=ebb90c6adcce857c277b5fef1e012e52de19fc5485c65556a7f16c31829ef9b83e5b91c93ba7&scene=126&sessionid=1681311134#rd)

思科已经发布了安全更新，以修复各种产品中的多个漏洞，包括Webex Player中的两个远程代码执行漏洞。

思科修复了两个远程代码执行漏洞，分别已跟踪到CVE-2020-3127和CVE-2020-3128。该漏洞已被评为高度严重，其CVSS评分为7.8。

  

该漏洞是由于未对存储为ARF（高级记录格式）或WRF（Webex记录格式）的Webex记录中的元素进行充分的验证而导致的。

远程攻击者可以通过发送恶意ARF / WRF文件并诱骗受害者打开它们来利用这些漏洞。该漏洞可能触发具有当前用户权限的任意代码的执行。

  

“该漏洞是由于对以高级记录格式（ARF）或Webex记录格式（WRF）存储的Webex记录中某些元素的验证不足而引起的。攻击者可以通过链接或电子邮件附件向用户发送恶意的ARF或WRF文件，并诱使用户在本地系统上打开文件，从而利用这些漏洞。”阅读思科发布的建议。“成功利用漏洞可以使攻击者利用目标用户的特权在受影响的系统上执行任意代码。”

  

这些缺陷会影响Webex Meetings（WBS 39.5.17或WBS 39.11.0之前的Webex Network Recording Player和Webex Player版本），Webex Meetings Online（早于1.3.49的Webex Network Recording Player和Webex Player版本）以及Webex Meetings Server （Webex Network Recording Player的发行版早于3.0MR3SecurityPatch1和4.0MR2SecurityPatch2）。

  

思科证实，它不了解利用这些漏洞进行的野蛮攻击。

这家技术巨头还发布了针对其他两个严重漏洞的安全更新，这两个漏洞是Cisco Intelligent Proximity SSL证书验证漏洞（CVE-2020-3155）和Cisco Prime Network Registrar中的跨站点请求伪造漏洞（CVE-2020-3148）。

  

可以远程利用CVE-2020-3155漏洞查看或更改Webex视频设备和Cisco协作端点上共享的信息。

  

该缺陷是由于在连接到Webex视频设备或Cisco协作终端时缺少对收到的SSL服务器证书的验证引起的。在这种情况下，攻击者可能会实施中间人（MITM）。

  

CVE-2020-3148漏洞影响了主要网络注册器（CPNR）的基于Web的界面，并且可以被未经身份验证的远程攻击者利用，以发起跨站点请求伪造（CSRF）攻击。

  

思科还修复了9个中等严重程度的漏洞，这些漏洞可能导致信息泄露，命令执行，拒绝服务，跨站点脚本（XSS）或资源耗尽。

  

这些缺陷影响适用于MacOS的Webex Meetings Client，网真管理套件，远程PHY设备软件，主要协作配置，身份服务引擎（ISE），IOS XR软件，用于电子邮件安全设备（ESA）的AsyncOS软件以及ESA，Web安全设备（ WSA）和内容安全管理设备（SMA）。
