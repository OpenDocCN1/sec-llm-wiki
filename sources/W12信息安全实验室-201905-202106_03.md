**DEP** Data execution protection

Windows 下最为早期的漏洞缓解机制之一， DEP 防止在内存的非可执行部分中执行任意代码，它迫使研究人员采取其他的利用方法。

DEP 在内核模式和用户模式下的实现非常相似，因为 DEP 是通过页表条目在分页内存的基础上强制执行的。PTE(*Page Table Entry) *的高位部分几个负责为指定范围的虚拟地址强制执行各种权限和属性。虚拟内存的每个块称为页(通常为4Kb)，通过 (byte\* PTE)\[1\] 标记整个页块的读写执行权限。而 DEP 则保证了不能同时存在写和执行。

**CFG/kCFG** Control Flow Guard

控制流执行保护，微软在Windows 10和Windows 8.1 Update 3中默认启用

**Security Cookie(GS For VS)**

经常逆VS编译的应该能很频繁的看到一个函数名为 \_\_security\_cookie 包括在开头和结尾。GS的开启就会对函数的入口和出口代码都添加针对安全cookie检查的指令。

```
push    ebpmov     ebp,espsub     esp,0x10mov     eax,[__security_cookie]mov     [ebp-0x4],eax;...用户逻辑代码add     esp,0xCxor     eax,eaxmov     ecx,[ebp-0x4]call    __security_check_cookie;...收栈
```

主要原理是在进入函数的时候多压入栈一个安全cookie，然后在出栈的时候进行检查，如果返回地址被溢出覆盖，则安全cookie也应该被溢出覆盖导致不同。

  

**Stack Protector(For Linux)**

又称之为 Stack Canary（栈金丝雀）因为在很久以前的煤矿井内没有一氧化碳检测器，于是矿工会带着对一氧化碳比较敏感的金丝雀一同下矿，用作报警。

与GS的实现基本相同，在栈内而外压入Cookie(Canary)，如果返回地址被覆盖则会检测到，以触发栈保护。
