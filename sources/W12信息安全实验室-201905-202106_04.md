> 找了个简单的IOT设备尝试入手进行分析，于是看了看，DIR-865L居然被一次爆出来6个，那想着一次能尝试6个也是蛮开心的了，于是找了个固件试试。

### 基础环境与文件

*   固件版本：DIR-865L\_v1.05
    
*   固件(官网)：legacyfiles.us.dlink.com - /DIR-865L/REVA/FIRMWARE/ 里面有D-Link几乎全部固件.
    
*   百度网爬：链接：https://pan.baidu.com/s/1v-SNayUWZfLbHoNasSlJmg 提取码：w12w
    
    懒得提文件系统的，也可以直接在网盘链接里拿。
    
*   需要用到的工具：`FAT 、IDA >= 7.5 \ Ghidra 、QEMU 、Firmwalker ( 可有可无 ) 、binwalk ( 装全 )`
    
    工具链接放文末吧。
    

> 文件系统不太方便在WSL里面提，是变形的 `squashfs` 所以需要 `sasquatch`  请注意开头是 sa 并且，如果没有装的话使用 `binwalk -Me` 会报错，内容大概为：`failed to run external extractor 'sasquatch` 然后提出来一个空的 `squashfs-root` 。而在WSL装 `sasquatch` 会出现一些问题，很是麻烦。
> 
> 所以建议 还是开个Linux来弄好，如果想要的人多的话，我们之后也可以放一个IOT分析环境出来。

## CVE-2020-13786 跨站请求伪造（CSRF)

直接通过在http请求中增加 Cookie 中的正确 uid 即可绕过登录。主要原因为没有引入有效的 token 等。
