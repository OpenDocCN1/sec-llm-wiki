一个微信小程序，所有的接口url都是一样的，通过post体中的一个字段来判断行为  
url都是：  
https://xxxxx.cn/gateway/link.do  
![](../Images/f738e0204b8e7f51ea1a346fe0114056.png)  
这些接口都需要data\_digest做校验，类似sign值的作用，修改请求后就会校验失败  
这个值怎么算的呢：  
先把小程序代码拿下来，搜索data\_digest  
![](../Images/5c022e3da3a2188023c5d1683a41aa30.png)  
然后顺着往上找，b方法是自己实现的，详细下面说明  
![](../Images/53b6e51ea0c64c5f8a32617c681c1728.png)

实际上g是下面的值（通过我打码的几个参数与抓包的请求比较），上面这个应该是测试环境或者开发环境  
![](../Images/c023acca1f886146984d158add5663e6.png)  
上面截图说的 b = new c.default.MD5().b64  
看data\_digist的值，有“/”，肯定不是正经的base64  
这个MD5是在一个hashes.js里实现的，b64也是在这里  
![](../Images/bd4be1ac9090167da4c52003582097ab.png)  
具体怎么实现的不管了，把相关代码（指存在依赖关系的）拿下来  
![](../Images/a2618108ee4e16fcad55db8d2fbb1bfa.png)  
![](../Images/663deb9d60f8e2ec86f21d0f1cd6cfe1.png)

我们先把content（来自抓包的参数）与g（来自小程序源码）相加，然后调用b函数即可得到data\_digest
