#### 3.后台备份与恢复数据-执行sql语句getshell

EmpireCMS7.5及之前版本中的admindbDoSql.php文件存在代码注入漏洞。

也就是后台提供了一个sql语句执行

![](../Images/d7c94b62d8af7c1b4c90b251f5a61f63.png)

只要服务器mysql配置secure\_file\_priv 不当，就可以向服务器写入文件

**Payload**

```
select '' into outfile '绝对路径/e/admin/lyy.php'
```

因为要向站点写入文件，所以必须知道绝对路径才行。

因为是无回显执行，也不能通过show mysql变量获取部分路径，所以也pass了

```
show variables like '%datadir%';
```

##### 原理分析

因为手里有源码，就跟了一下这个漏洞

**首先定位**

直接全局搜索config.php就找到了

![](../Images/5fbdc2c2ab24f5516bc53f238b164a86.png)

在e/admin/ebak/class/functions.php文件中Ebak\_DoEbak存在文件写入操作

![](../Images/f5a16688df630b9f313f380f5adb16eb.png)

```
$string="
```

```
    \\$b\_table\=\\"".$b\_table."\\";    ".$d\_table."    \\$b\_baktype=".$add\['baktype'\].";    \\$b\_filesize=".$add\['filesize'\].";    \\$b\_bakline=".$add\['bakline'\].";    \\$b\_autoauf=".$add\['autoauf'\].";    \\$b\_dbname=\\"".$dbname."\\";    \\$b\_stru=".$bakstru.";    \\$b\_strufour=".$bakstrufour.";    \\$b\_dbchar=\\"".addslashes($add\['dbchar'\])."\\";    \\$b\_beover=".$beover.";    \\$b\_insertf=\\"".addslashes($insertf)."\\";    \\$b\_autofield=\\",".addslashes($add\['autofield'\]).",\\";    \\$b\_bakdatatype=".$bakdatatype.";    ?>";
```

```
    $cfile\=$bakpath."/".$add\['mypath'\]."/config.php";
```

```
    WriteFiletext\_n($cfile,$string);
```

可以看到直接对$d\_table变量进行拼接

再看看写函数WriteFiletext\_n

![](../Images/9fc8344bd09ce5360d8403bd3368a90b.png)

也没有对写入内容进行过滤，那么只需要知道如何控制$d\_table变量值即可

crtl+左键跟到上面

![](../Images/6d392dac809ae98c82a85060a74cc4b6.png)

而$count是$tablename的数量，$tablename是$add中tablename的键值

![](../Images/66c6452fb57b8bde712769ae795f950d.png)

找到调用Ebak\_DoEbak函数的位置，知道$add就是$\_POST

![](../Images/d6726164230edf73b31c7d45075d97e7.png)

那就很清楚了，他对POST传参的tablename进行了处理产生两个变量

$b\_table和$d\_table，其中$b\_table是被双引号包裹无法利用的

但是$d\_table没有双引号被包裹，且没有任意过滤直接写入.php文件，导致命令执行

##### 为什么不是其他参数？

其他参数大部分是被双引号包裹的

没有被双引号包裹的参数都被强转int，如果传str会返回0 所以pass
