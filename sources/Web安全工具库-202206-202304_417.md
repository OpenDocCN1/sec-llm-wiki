一、 http-staging流量分析(1)stage 下载stager 可执行文件 artifact.exe 运行后会有一个 payload 下载过程，使用 http 协议从指定服务器下载 stage 。

![](../Images/82a7ace0e72d50cc27c4c4f2decf60d9.png)

  
其中 http 请求路径不唯一，但都符合一个 checksum8 规则，即：路径的 ascii 之和与 256 取余计算值等于 92 。\#  /Yle2、/cKTZ、/wQPD  

![](../Images/c08b9d97916bd8f8a60de8457650abe6.png)

而下载的文件约 211kb，解析后可以看到回连地址、加密字段、公钥等配置信息。  

![](../Images/8ac2eaecdfd796b48773245522e97b17.png)

  
(2)beacon 上线随后 beacon 按设置的频率以 get 方法向 c2 服务器发起心跳请求，通过 cookie 携带靶机信息。  

![](../Images/b54997b02748623d7795c58439f97133.png)

二、dns-stagless流量分析

![](../Images/0316b6ec2dc22c623bb1f43d26145319.png)

(1)beacon 上线与 staging 阶段不同，stagless 不需要额外加载 stage，运行 dns-beacon.exe后，beacon 端发起一个A记录查询，查询内容为16进制字符串地址，表示靶机信标已上线，c2 服务器收到请求后回复 0.0.0.0 表示确认消息。  

![](../Images/ea02d208f832a8aa83635426d33234c9.png)

此时，在客户端可以看见一个不同于 http(s)上线的黑框记录。  

![](../Images/8b4285abfbb13777e46ff1f21a265833.png)

(2)beacon 激活客户端控制台输入 checkin 或其他指令激活窗口，dns-beacon服务器支持A、TXT、AAAA三种方式下发payload，激活后默认使用TXT记录，流量中表现为 0.0.0.243，除此之外还可以通过 mode 指令切换为A、AAAA 记录，流量中表现为 0.0.0.241、0.0.0.245，随后 beacon 端发起以 www 为首的A记录请求，向 c2 服务器传递靶机基础信息。  

![](../Images/87d54a8e0e746a3ca16d0a82b234a293.png)

(3)命令下发beacon 准备接收 c2 任务，先发送以 api 开头的A记录请求告知 c2 服务器可以开始下发任务，即图中的 0.0.0.243-TXT 方式，随后发起以 api 开头的 TXT 记录请求等待 c2 服务器返回数据。  

![](../Images/9bca601aaa1c8fe0af67c714fd8b5585.png)

  
(4)结果回传beacon 端执行完命令后，再向 c2 服务器发起以 post 开头的A记录查询回传执行结果。

![](../Images/01363fa69712acf96cd6e058575110e5.png)
