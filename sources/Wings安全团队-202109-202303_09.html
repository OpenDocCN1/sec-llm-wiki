前言

每当面对大量目标时，如何能在短时间内尽可能全的发现漏洞，是一个至关重要的问题。

目前的各种漏洞验证工具，确实帮助我们解放了双手，不过最近发现都存在一定的局限性，请求包中很可能存在敏感参数、敏感字符组合等信息，导致请求时被waf拦截，甚至直接被封IP，影响后续的自动化漏洞验证；漏洞库也是需要自己进行更新，否则远跟不上新漏洞更新的脚步。既然如何，为何不从一个新的角度，重新定义漏洞发现，此工具即由此而来。

# 下载地址：https://github.com/jx4321/vuldirscan

新思路

开始的设想只是做一个纯URL的目录字典，按照不同漏洞类型收集漏洞验证/利用的URL，但即使是互联网上已经有一些相关的字典合集，但收集过程相对比较困难，尤其是各种应用系统类、OA类、设备类、CMS框架类等不同类型的漏洞，大多是需要个人一点点的收集。

若按照传统目录扫描的方式，仅仅请求漏洞URL，判断状态码，会产生非常高的误报率，不实用。

此时就想到曾经在测试一些文件上传类漏洞时，仅GET请求目标的漏洞文件或漏洞接口时，目标会返回类似405状态码、报错信息等一些比较有特征的内容。通过这个思路，好像是找到了一条新的漏洞发现的野路子，在经过一顿思考过后，说干就干，开始进行漏洞库的收集。

为了能尽可能的提高精确度，收集期间遇到了一系列问题，比如：

  • 只通过返回包判断存在漏洞，返回包不匹配，状态码又是200的怎么办

  • 很多系统无论怎么请求，状态码都是200

  • 请求遇到跳转怎么处理

  • 同一类存在漏洞的系统，不同的系统返回不同的特征，如何处理；返回特征不明显，需要组合特征，如何处理


为了解决过程中遇到的问题，从最开始的设想中，逐渐丰富漏洞库的内容，增加了指纹、返回包内容判断等内容,最早是使用json格式的文件存储漏洞库，随着漏洞库数量的增多，后续维护不方便，改为数据库存储。

在后续的程序实现、漏洞库丰富过程中，又增加了新的漏洞库字段switch，以保证在现有字段不新增的情况下，通过灵活处理每字段多个特征间的或、与关系，更高效的提高漏洞判断的准确性。

漏洞库字段释意：

id：唯一值，方便追溯到具体的漏洞库位置cms：框架/系统类型baseurl：不带任何参数的漏洞验证/利用/或其他能证明漏洞存在的URL；（有时为了提高漏洞精确度，偶尔会添加一两次（不会触发WAF规则的）带参数的URL）vulurl；完整的漏洞利用URL，以及可能的其他信息，比如POST包，此字段内容不参与请求，只在输出时写入到Excel结果文件中，方便复现/利用finger：每类CMS/系统首页访问的指纹，可写多个，多个关系为或，关系亦可调整msgtrue：baseurl请求的返回结果中，能标识存在漏洞的某特征字符串，可写多个，多个关系通过switch字段调整msgfalse：baseurl请求的返回结果中，能标识不存在漏洞的某特征字符串，格式为字符串，后续有需要可调整为列表flag：漏洞名称switch：用于调整字段中有多个内容的关系，true为与，false为或，目前仅设置了msgtrue字段的调整，后续可根据需要增加其他字段的调整

通过指纹、返回包结果是否存在某些特征、动态调整与/或的关系，可以很大程度上解决上述遇到的问题，

比如无论请求任何，均返回200状态码的问题，很多在返回包中是有location跳转链接的。

当然，即使如此，依然会有不少的无法通过状态码、返回包、指纹来精确判断是否存在漏洞的案例，比如后台类的漏洞、GET请求漏洞URL无响应，但确实存在漏洞等等这种特殊的存在。

此类均在输出时标记为可能存在，需要手工验证，这也是在录入时，输入详细的漏洞验证/利用内容的意义所在。

代码实现

读取漏洞库，按照使用习惯做了判断，使用全部库验证还是部分库验证，灵活化处理，方便日后小范围漏洞验证使用。

def readdb(queue, bigtype, smalltype, filename):    res_list = []    url = queue.get()    tmpdb = sqlite3.connect("vuldir.db")    cursor = tmpdb.cursor()    if bigtype == "all":        # 查表名        cursor.execute("select name from sqlite_master where type='table';")        tables = cursor.fetchall()        for tmpt in tables:            if 'sqlite' not in tmpt[0]:                try:                    # 查表内内容                    cursor.execute("select * from " + tmpt[0] + ";")                    tmpcontent = cursor.fetchall()                except Exception as bb:                    # print(bb)                    pass                else:                    res_list1 = gethttp(url, tmpcontent)                    res_list.extend(res_list1)    else:        table = bigtype        if smalltype == "all":            cursor.execute("select * from " + table + ";")            tmpcontent = cursor.fetchall()        else:            try:                cursor.execute("select * from " + table + " where cms='" + smalltype + "';")                tmpcontent = cursor.fetchall()            except Exception as aa:                # print(aa)                pass        res_list = gethttp(url, tmpcontent)    return res_list, filename

主体部分，请求、判断等，当前版本通过优化，也已大幅减少了请求量。

  • 先请求目标主体，判断指纹（改版过来的，最早是请求完漏洞URL，再判断指纹）

  • 判断返回包是否存在漏洞

  • 判断返回包是否不存在漏洞（解决状态码正常，但确实不存在漏洞的情况）

  • 判断状态码是否不在黑名单中

  • 退出多个指纹特征的循环，判断结束

其中特殊处理了一些漏洞，比如某友的某漏洞，无论是否存在漏洞，仅GET请求漏洞URL，都是返回404状态码

def gethttp(url1, tmpcontent):    res_list = []    # 取字典中的flag，状态码为404的白名单列表，便于某些漏洞的检查    ext404 = ["某友目录遍历漏洞", "某友任意文件读取漏洞"]    header = {        'User-Agent': 'Mozilla/5.0 (Windows NT 10.0; WOW64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/78.0.3904.108 Safari/537.36',        'Content-Encoding': 'deflate',        'Content-Disposition': 'attachment; filename="filename.jpg"'    }    try:        res_ori = requests.get(url1, headers=header, verify=False, allow_redirects=True, timeout=3)        restxtori = res_ori.text    except:        pass    else:        for tmp1 in tmpcontent:            finger = ast.literal_eval(tmp1[4])            if finger:                for ftmp in finger:                    if ftmp in restxtori:                        id = tmp1[0]                        cms = tmp1[1]                        baseurl = tmp1[2]                        vulurl1 = tmp1[3]                        msgtrue = ast.literal_eval(tmp1[5])                        msgfalse = tmp1[6]                        flag = tmp1[7]                        switchtmp = tmp1[8]                        switch_msgtrue = json.loads(switchtmp)['msgtrue']                        url = url1 + baseurl                        vulurl = url1 + vulurl1                        try:                            res = requests.get(url, headers=header, verify=False, allow_redirects=False, timeout=5)                            status = res.status_code                            restxt = res.text                        except:                            pass                        else:                            if flag in ext404:                                status = 200  # 假的200，这里也必定存在很多误报                            if msgtrue:                                # 与关系                                if switch_msgtrue == 'true':                                    if all(mttmp in restxt for mttmp in msgtrue):                                        res_list.append([id, cms, url, vulurl, str(finger), "存在" + flag])                                        print(url + "  |  " + "存在 " + flag)                                        # break                                # 或关系                                elif switch_msgtrue == 'false':                                    for mttmp in msgtrue:                                        if mttmp in restxt:                                            res_list.append([id, cms, url, vulurl, str(finger), "存在" + flag])                                            print(url + "  |  " + "存在 " + flag)                                        break                                    # break                            elif status not in [301, 302, 403, 404]:                                res_list.append([id, cms, url, vulurl, str(ftmp), "指纹匹配，可能存在" + flag])                                print(url + "  |  " + "指纹匹配，可能存在" + flag)                                # break                        break        return res_list
