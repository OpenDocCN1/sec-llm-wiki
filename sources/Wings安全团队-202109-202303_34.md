会发现即使在开启了ASLR的情况下，每个程序的exe加载基址不同，但是每个程序中都会导入这两个dll文件，并且ntdll.dll和kernel32.dll等dll文件加载的基址是完全相同的。这是因为在windows系统中，这两个dll实际只会在系统中加载一次，然后其他的程序对该dll文件中的handle和指针进行引用，因此，当我们找到其他进程中该dll的地址，我们即可找到该dll以及其所包含的所有函数的绝对地址。

## 查找DLL的绝对地址

  

一个不是很冷的冷知识：FS段寄存器中在3环下存放的为TEB，在0环下存放为KPCR。

  

TEB（Thread Environment Block,线程环境块），TEB中存放着线程的各种信息，每一个线程都有自己的TEB。(各结构体的详情见附录)

  

而TEB中0x30位置为`Ptr32 _PEB`，即指向PEB的指针。

  

PEB（Process Envirorment Block,进程环境块），PEB是存放进程信息的结构体。在PEB中0x0c的位置为`Ptr32 _PEB_LDR_DATA`，同样是一个指针，指向了进程加载的模块的信息的结构。

  

`_PEB_LDR_DATA`中在0x14处有一个双向链表`InMemoryOrderModuleList`，该双向列表存放着内存中按顺序加载的所有dll，从上面截图中可以发现，ntdll.dll是排在首位的dll，第二个即为kernel32.dll，因此我们找的时候沿着链表跳转两次即可得到kernel32.dll的`_LDR_DATA_TABLE_ENTRY`,然后从`InMemoryOrderModuleList`到`DllBase`的偏移为0x10，即指针地址+0x10即可找到kernel32加载的绝对地址。

  

汇编代码

  

```


xor esi, esi	          ; esi = 0
```

## 查找相关函数的绝对地址

  

我们需要的调用计算器的函数为*WinExec*。然后我们找此函数的绝对地址。

  

根据PE的结构（PE的结构自己百度吧，有本书是专门介绍PE结构的）

  

1.  找到`E_lfanew`的RVA地址（DllBase+0x3c）
    
2.  找到PE文件签名地址（DllBase+1中保存的RVA）
    

3.  找到导出表的RVA(2中得到的地址+0x78)
    
4.  找到导出表的绝对地址（DllBase+3中的RVA）
    

5.  找到导出函数的数量（4中地址+0x14）
    
6.  找到导出地址表的RVA(4中地址+0x1c)
    

7.  找到导出地址表的绝对地址（DllBase+6中RVA）
    
8.  找到导出名称表的RVA(4中地址+0x20)
    

9.  找出导出名称表的绝对地址（DllBase+8中的RVA）
    
10.  找到导出序号表的RVA（4中地址+0x24）
     

11.  找到导出序号表的绝对地址（DllBase+10中的RVA）
     
12.  遍历名称表，找到*WinExec*并记住遍历过的数量。
     

13.  在序号表在对应位置处找到WinExec并得到其序号（序号表的绝对地址+（12中的值\*2））
     
14.  在地址表里找到WinExec的RVA（地址表的绝对地址+（13中得到的序号\*4））
     

15.  找到WinExec的绝对地址（RVA+DllBase）
