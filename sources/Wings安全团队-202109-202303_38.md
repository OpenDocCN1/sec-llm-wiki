# VMware vRealize 认证后任意文件上传漏洞

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzIzNTczNTc0Nw==&mid=2247484519&idx=1&sn=006d98dff2d3cbb7d24bbf49b5940c0b&chksm=e8e3dbcbdf9452dd8fe0567b1b75bf427a962961494fd16cf1588006ef4fec018cc44f5e5688&scene=126&sessionid=1681445055#rd](http://mp.weixin.qq.com/s?__biz=MzIzNTczNTc0Nw==&mid=2247484519&idx=1&sn=006d98dff2d3cbb7d24bbf49b5940c0b&chksm=e8e3dbcbdf9452dd8fe0567b1b75bf427a962961494fd16cf1588006ef4fec018cc44f5e5688&scene=126&sessionid=1681445055#rd)

# 漏洞简述

vRealize 路由中存在一上传功能，由于未对上传做任何安全过滤，导致可在有认证凭证的情况下，实现任意文件上传，获取服务器控制权限。

编号CVE-2021-21983。

**亲测，上一波漏洞****[CVE-2021-21975](http://mp.weixin.qq.com/s?__biz=MzIzNTczNTc0Nw==&mid=2247484415&idx=1&sn=52a4908a070418e719ba53869c590803&chksm=e8e3dc53df945545e21ae183ebca5297d83e48aa1240341aa8668035a69cf458fd7b821f60b6&scene=21#wechat_redirect)中获取到认证信息，但无法通过web管理端登录的问题，此漏洞可不受其限制，只要认证信息准确，依然能够实现任意文件上传，获取控制权限。**

  

# 影响范围

vRealize\_operations\_manager: 8.0.0, 8.0.1, 8.3.0, 8.1.0, 8.1.1, 8.2.0, 7.5.0

cloud\_foundation: 4.x 3.x

vRealize\_suite\_lifecycle\_manager: 8.x

  

**限于环境问题，最高测试到****vRealize operations manager的8.3.0.17501340版本，都是存在该漏洞的，虽然8.3版本开始，不再存在CVE-2021-21975的SSRF漏洞，但若能在知晓认证信息的情况下，依然能获取到控制权限的。**

  

# 漏洞分析

casa/classes/com/vmware/vcops/casa/appconfig/CertificateController.class位置 存在一路由，这里使用POST方法接收了两个参数name和file

![](../Images/427ec2bb66d645cf4715b9de2312b6f8.png)

跟进CertificateService#handleCertificateFile，这里创建了一个File对象，直接使用transferTo函数上传文件，两个参数都可控，没有任何过滤，就出现了任意文件上传漏洞。

![](../Images/e19453633f5ddbdd6eb678f90f4ab7ed.png)

  

  

# 漏洞验证

  

网上文章的复现，文章内容截图都一样，也看不出利用的POST包，这里自己根据漏洞分析的代码部分，构造上传的POST包。

URL为第一张图中的路由，访问该URL，登录抓包，看到其中熟悉的header头，Authorization字段，在[CVE-2021-21975](http://mp.weixin.qq.com/s?__biz=MzIzNTczNTc0Nw==&mid=2247484415&idx=1&sn=52a4908a070418e719ba53869c590803&chksm=e8e3dc53df945545e21ae183ebca5297d83e48aa1240341aa8668035a69cf458fd7b821f60b6&scene=21#wechat_redirect)中获取的就是这个东东。**亲测默认的admin账号也可以实现效果，格式为admin:password的base64加密**。

POST包为常规的文件上传的Content-Type格式，主要有两个核心上传参数name和file。name的value为文件名，file的value为文件内容。

尝试确认默认上传到操作系统上的位置为/storage/vcops/user/conf/ssl/，上传之后无法通过web访问到；灵机一动，想到在文件名的位置通过../构造切换web可访问的位置，果然可行。

路径切换的时候，发现上传的文件并不能保存到操作系统根目录下，但可借助切换到根目录时，无缝衔接切换到根目录下的其他文件夹下，就有了下面POST包中的name参数的value。这样文件上传后的URL就为：https://ip:port/casa/test1.jsp，自行更改上传的文件名哈。
