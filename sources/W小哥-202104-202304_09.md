## 一、漏洞挖掘

### 1、逻辑缺陷

熟悉的页面，熟悉的弱口令测试，但无果

![](../Images/8ae48e19a8699d2e68bc5b049a125be8.png)

我就把目光转向js审计，果不其然有新发现，可以根据账号自动登录

![](../Images/b61a3dae53e806adae584372aa24ac21.png)

于是直接构造请求绕过登录

![](../Images/4f1c6626179a3e9e9a7ffa6c78340b70.png)

经典的管理员权限

### 2、存储型XSS

寻找文本输入

![](../Images/265cda4edeed26c7cc65f23359c98053.png)

浅析： 前端：这里的标签都是普通标签，没有像`RCDATA`元素(`RCDATA elements`)，有`<textarea>`和`<title>`，会做一次HTML编码，所以可以直接插入危险的js代码。 后端：没有任何过滤（xs~

![](../Images/c3b1b835d4a81bbe5d89425cd63cde5f.png)

所以就简单了，直接插入`<script>alert('1')</script>`即可

![](../Images/f2216d9ef5e024a01471fb8514aa3be1.png)

### 3、SQL注入

![](../Images/e57d43261155ea8eaf822bcad7b19225.png)

测试无果

![](../Images/0bd6c50fd65b4ce0b2e5c69c80814ca8.png)

最后发现注入点在第一个函数，果然任何一个输入点都可能是不安全的，是布尔型盲注

![](../Images/323ffffec22495db07d2e537c8679cea.png)

后面就是经典Sqlmap了

## 二、继续通杀

根据系统指纹在fofa上搜索：`"xx系统" && icon_hash="11xxxx"`有32个IP，看了下，有重复的

![](../Images/76780cc8d694c19f64098939cf5722fa.png)

使用fofa\_viewer导出目标 这里我根据第一个逻辑漏洞的漏洞指纹信息，写了一个简单poc

```


import requests
```

以上漏洞均已报告给相应学校且已修复

## 三、思考总结

1）在访问系统当中的时候F12查看源码是一个不错的习惯（尤其是有前端弹框的）

2）前端代码的一切展示行为完全可控(一定要理解这句话)

3）了解程序的底层逻辑，你才能更清晰的知道每一个参数的意义
