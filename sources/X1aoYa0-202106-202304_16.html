 1 工作组 

工作组可以认为是同一网络内，功能相似的电脑进行的分组。

在一个网络内，可能有成千上百台电脑，如果这些电脑不进行分组，都列在“网上邻居”内，可想而知会有多么的乱。为了解决这个问题，Windows9x/NT/2000就引用了“工作组”这个概念，将不同的电脑一般按功能分别列入不同的组种，如财务部的电脑都列入“财务部”工作组中，人事部的电脑都列入“人事部”工作组种。你要访问某个部门的资源，就在“网上邻居”里找到那个部门的工作组名，双击就可以看到那个部门的电脑了。

这就是工作组，但是工作组中的电脑还是各自管理。当其中一台计算机访问另外一台计算机的时候，还是要经过另一台计算机的认证


  • 域

域，是一群相互信任的计算机的集合。

想要访问域中资源就必须经过一台负责每一台联入网络的电脑和用户的验证工作的服务器。这个服务器叫做域控（域控制器 domain controller 简称DC）的安全认证，每个域至少有一个域控。

当某计算机连入域时，DC就会鉴别这台电脑是否属于这个域内的，用户使用的登录账号是否存在、密码是否正确。如果以上信息不正确，域控制器就拒绝这个用户从这台电脑进行登录。不能登录，就不能访问服务器上有权限保护的资源。


  • 工作组和域的区别

工作组是一群计算机的集合，仅仅是一个逻辑的集合，各自计算机还是各自管理的。

域是一个有安全边界的计算机集合，在同一个域中的计算机彼此之间已经建立了信任关系，在域内访问其他机器，不再需要被访问机器的许可。

 2 两大认证协议 

  • NTLM

  1. 用户输入账号密码，本地把密码加密为一个hash值，称为NTML-hash

  2. 客户端向服务器发送用户名（这个数据称为TYPE 1 Negotiate）

  3. 服务端接收请求，判断数据库中该用户名是否存在，若存在则生成一个16位随机数称之为chanllane。同时将chanllane返回给客户端（type2）

  4. 客户端收到chanllage后将其用上面生成的hash值来加密这个chanllange，并与用户名chanllange等组合到一起得到net-NTLMhash最后讲Net-NTLMhash封装到TYPE 3 NTLM_AUTH消息中发往服务器。

  5. 服务器收到TYPE3后，用自己数据库中该用户的密码的NTLM-hash加密chanllage，并比较自己计算出的net-ntlmhash与客户端发送过来的net-ntlmhash，若相同则认证通过。

  6. 若在域中，那么服务端在第五步收到type3后不会自行进行比对，而是将net-ntlm-hash转发给域控DC，由DC进行最后的net ntlm-hash比较认证。


  • Kerberos

Kerberos协议，是一个域内常用的认证与授权协议。

主要参与角色

  1. client：application client 应用客户端

  2. AS：authentication server 用来认证用户身份

  3. TGS：ticket-granting service 用来授权服务认证

  4. SS：service server 用户所请求的服务

  5. 其中AS和TGS都属于KDC系统（密钥分发中心），可以认为是DC上的两服务。
