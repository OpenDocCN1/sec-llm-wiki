# 文件包含戏精引言

## 一、概述

在 Web 后台开发中，程序员往往为了提高效率以及让代码看起来更加简洁，会使用 “包含” 函数功能。比如把一系列功能函数都写进 function.php 中，之后当某个文件需要调用的时候直接在文件头中写上一句 就可以调用函数代码。

但有些时候，因为网站功能需求，会让前端用户选择需要包含的文件（或者在前端的功能中使用了“包含”功能），又由于开发人员没有对要包含的这个文件进行安全考虑，就导致攻击者可以通过修改文件的位置来让后台执行任意文件（代码）。这种情况称为“文件包含漏洞”。

文件包含漏洞有“本地文件包含漏洞”和“远程文件包含漏洞”两种。

包含函数

通过 include() 或者 require() 语句，可以将 PHP 文件的内容插入另一个 PHP 文件（在服务器执行它之前）。

include 和 require 是相同的，除了错误处理方面：

require 会生成致命错误（ E\_COMPILE\_ERROR ）并停止脚本

include 只生成警告（ E\_WARNING ），并且脚本会继续

## 三、远程文件包含File inclusion (remote)

远程文件包含漏洞和本地文件包含漏洞是差不多的，只是说在远程文件包含漏洞中，攻击者可以通过外部访问地址来加载远程代码。

  

对了，如果使用了includer 和 require，那么php.ini配置如下：

allow\_url\_fopen = on

allow\_url\_include = on

我们打开目标：

![](../Images/478712224667de9042f5dd705e185bfb.png)

在目标里，远程文件包含和本地包含是一样的，同样是通关前端上传文件到后台包含

![](../Images/42b4b7d6e05f680c05291182d6443b73.png)

我们可以通过搭建一个恶意的站点，输入到URL中进行测试：

http://192.168.1.42/pikachu/test/yijuhua.txt

![](../Images/22cb250c065474bad81306fe1d0dc721.png)

 提交之后，页面没什么显示，但是目标的目录下，已经有了我们的一句话木马：

![](../Images/cddfab75fb45b9e09b02b3b84bda3482.png)

然后我们可以利用我们所上传的PHP文件来进行相关的操作，我们所上传的文件是和后台服务器在同一级的目录下的，所以只要在页面URL中修改我们访问的文件名和上传的参数即可：

![](../Images/6bf8496b77a944e93188d040a9093c25.png)

![](../Images/d22c2dc1d2648c8951353d6ce4c37270.png)

查看代码：可以看到和本地文件包含一样，没有做任何的安全限制就进行包含了。因为在演示中，我们把PHP的配置文件php.ini中的默认远程选项手动打开了，这样就相当于允许include去调用任何的文件，导致了漏洞的产生！
