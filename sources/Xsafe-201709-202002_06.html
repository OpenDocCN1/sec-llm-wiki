 过滤函数：

判断是否开启get_magic_quotes_gpc,没有开启使用addslashes()函数进行过滤单引号

function _RunMagicQuotes(&$svar){ if(!get_magic_quotes_gpc())    {   if( is_array($svar) ){    foreach($svar as $_k => $_v) $svar[$_k] = _RunMagicQuotes($_v);    }  else{     $svar = addslashes($svar);  }   } return $svar;}

漏洞详情：
通过addslashes()已经过滤了单引号，带入单引号则会报错把单引号改为 \
在这个注入中无法使用union联合查询，因为是在order by之后进行注入

可以使用procedure analyse参数进行报错注入，从而绕过单引号限制
payload：procedure analyse(extractvalue(rand(),concat(0x3a,(select version()))),1);

从上述的sql 语句中我们可以看出，我们的注入点在order by 后面的参数中，而order by
不同于的我们在where 后的注入点，不能使用union 等进行注入。如何进行order by 的注
入，我们先来了解一下mysql 官方select 的文档。


 order by {col_name| expr| postion}[ASC| DESC ] order by 后可以使用字段名，列名，升序降序 postion 查询字符串返回 substr字符串在str出现的位置，没有返回0
注入方式：
直接操作SQL语句运行，我们是获取不到字段信息、所以这里我们考虑使用报错注入或者布尔注入
①直接添加注入语句运行，?sort=(select ****)
SQL语句可正常带入查询，但是无法回显
②利用mysql自带函数，例如rand()函数，?sort=rand(sql 语句)
Ps：此处我们可以展示一下rand(ture)和rand(false)的结果是不一样的，通过可以通过盲注继续测试
③利用and，例如?sort=1 and (加sql 语句)
SQL语句可正常带入查询，但是无法回显
