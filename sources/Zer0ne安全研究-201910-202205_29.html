一、LD_PRELOAD

(一) 原理

LD_PRELOAD是linux系统的一个环境变量，它可以影响程序运行时装载的动态链接库。

装载动态链接库，一般情况下按照以下顺序进行：

LD_PRELOAD>LD_LIBRARY_PATH>/etc/ld.so.cache>/lib>/usr/lib

这里通过编译一个包含ptrace()的动态链接库，并将其设为LD_PRELOAD环境变量，从而替换掉原来的ptrace()函数，从而达到绕过ptrace()反调试的目的。

(二) 代码

# antiPtrace.c

enum __ptrace_request

{

    PTRACE_TRACEME = 0,

#define PT_TRACE_MEPTRACE_TRACEME

PTRACE_ATTACH = 16,

#definePT_ATTACH PTRACE_ATTACH

 

};

 

long ptrace(enum__ptrace_request request, unsigned long pid,

                   void *addr, void *data)

{

    return 0;

}

(三) 编译

$NDK_GCC_arm_64$NDK_CFIG_amr_64 -fPIC -shared antiPtrace.c -o libantiPtrace.so

(四) 配置

  1. 将libantiPtrace.so,推送到手机设备上

    1. adb push libantiPtrace.so      /data/local/tmp

    2. chmod 755      /data/local/tmp/libantiPtrace.so

  2. 设置环境变量

    1. export      LD_PRELOAD=/data/local/tmp/libantiPtrace.so

(五) 运行

1.程序1

#1206_2.c

if(ptrace(PTRACE_TRACEME)==-1){

printf("Debugger\n");

}else{

printf("hello ptrace\n");

}

2.程序2

#1206_3.c

if(ptrace(PTRACE_TRACEME)==0){

printf("Debugger\n");

}

else{

printf("hello ptrace\n");

}

(六) 总结

  1. 正常情况一个没有被其他进程ptrace的进程执行ptrace(PTRACE_TRACEME)后得到一个大于0的整数值，因而这里两个程序都应输出“hello ptrace”，但这里因为设置LD_PRELOAD环境变量，因而ptrace()返回值为0，也就是第二个程序输出“Debugger”

  2. 运行后可以发现，对于在android shell中运行的二进制可执行文件起到作用，但是使用了ptrace()的apk并没有起到什么作用

    2. 猜测这里是因为apk是由zygote进程fork出来的，而zygote是在开机时运行的。

    3. 那么如果想要起作用的话，应该设置一个全局环境变量。

  3. 如何设置全局环境变量：

    1. 根据参考资料，全局环境变量存放在/init.environ.rc文件中

    2. 但/目录下是没有写权限的。

    3. 要修改只能修改源码中的init.environ.rc.in文件，然后编译，刷机…..
