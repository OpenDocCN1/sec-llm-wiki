序列化和反序列化


序列化就是把对象转换为字节方便存储和网络传输，反序列化就是把字节还原为对象这么一个过程，这个过程主要涉及到了以下方法：


序列化：ObjectOutputStream：翻译过来通过字面好理解，就是对象输出流，你想啊，对象转换为字节，也就是Object输出为Stream。FileOutputStream：ObjectOutputStream既然要输出流，那就需要传入一个流来处理，也就是FileOutputStream。writeObject：写对象的意思，对象转换为流总得有目的地，就是通过写来实现的。反序列化：反序列化就好理解了，把Output换成Input即可，相关方法是ObjectInputStream和FileInputStream。相对应写的就是读：readObject

序列化和反序列化示例


了解了概念，下面通过示例加深理解，比如现在有一个Person类，代码如下：


import java.io.Serializable;
public class Person implements Serializable {    private String name;    private int age;    private String sex;
    public Person() {    }
    public Person(String name, int age, String sex) {        this.name = name;        this.age = age;        this.sex = sex;    }
    // get和set方法省略}


注意这里要实现Serializable接口，Serializable只是用来标识这个类是可以进行序列化的，不实现的话，对其进行序列化会报错，该接口仅仅就是用来标识用到，并没有任何实现。


下面写个测试类来测试下：


public class SerializableTest {    public static void main(String[] args) throws IOException, ClassNotFoundException {        Person person = new Person("afa", 18, "男");        SerializerPerson(person);        // DeserializerPerson();    }
    public static void SerializerPerson(Object object) throws IOException {        ObjectOutputStream objectOutputStream = new ObjectOutputStream(new FileOutputStream("d:/test.txt"));        objectOutputStream.writeObject(object);        objectOutputStream.close();    }
    public static void DeserializerPerson() throws IOException, ClassNotFoundException {        ObjectInputStream objectInputStream = new ObjectInputStream(new FileInputStream("d:/test.txt"));        Person person = (Person) objectInputStream.readObject();        System.out.println(person.getName());        objectInputStream.close();    }}


安全问题


那么为什么会产生安全问题，在反序列化时，会把字节还原为对象，而这个还原的过程，会加载这个对象的类，会进行实例化然后执行原先序列化的代码，这也就是上面示例中，我们反序列化后，可以得到person的name值为afa。


也就意味着，如果序列化的对象中有恶意代码，或者调用了恶意类等，在反序列化时就会触发其执行，造成一个命令执行的效果。


而这种反序列化执行恶意代码大致有以下几种形式：


1，就是入口类的readObject直接调用危险方法。这里的入口类，就是指直接序列化和反序列化的那个类，由该类开始进入，然后开始执行链条的相关类和方法，简单理解，就是利用链条从这个类开始的，所以这个类可以叫它入口类。


向上面的那个示例，Person就是入口类，那么很多类都有自己相关的需求，需要重写writeObject和readObject方法，如果重写的该方法中有恶意代码，则在反序列化时就会被直接执行，这也是最简单最直观的一种形式。


比如还以Person类为例，给Person添加一个readObject方法，代码如下：


private void readObject(ObjectInputStream ois) throws IOException, ClassNotFoundException {    ois.defaultReadObject();    Runtime.getRuntime().exec("calc");}


再次反序列化时，就会执行计算器，defaultReadObject代表原生的readObject依然会执行有效，所以测试时发现名字afa依然可以获取，如果不写，那么打印名字就是null。


2，上面是最直接的，除此外，比如在readObject中没有恶意代码，但是引用的其它类有，如下示例，有个ManPerson类的testexec方法，执行了计算器：


public class ManPerson {    public void testexec() throws IOException {        Runtime.getRuntime().exec("calc");    }}


在Person的readObject中调用了ManPerson的testexec方法，那么反序列化Person时，也会触发计算器。


private void readObject(ObjectInputStream ois) throws IOException, ClassNotFoundException {    ois.defaultReadObject();    new ManPerson().testexec();}


3，再就是多层调用，类相互调用嵌套，例如ManPerson中没有恶意代码，而调用了另一个WomanPerson类，该类有恶意代码。


public class ManPerson {    public void testexec() throws IOException {        new WomanPerson().testexec();    }}


WomanPerson类代码如下：


public class WomanPerson {    public void testexec() throws IOException {        Runtime.getRuntime().exec("calc");    }}


这个例子很方便我们理解相关概念，即：入口类source，调用链gadget和执行类sink。


入口类就是Person，因为它重写了readObject方法，反序列化时会调用，利用链就是从这个方法开始的，所以叫它入口类。调用链就是这个过程：Person.readObject->ManPerson.testexec->WomanPerson.testexec。执行类就是最后WomanPerson下的testexec方法，也就是最后用来执行攻击命令的那个方法。


4，再有就是静态代码块、构造函数这些，当类实例化时，代码也会被执行，例如Person类有以下静态代码块。


{    try {        Runtime.getRuntime().exec("calc");    } catch (IOException e) {        throw new RuntimeException(e);    }}


反射


再来看下反射，在Java的序列化中，也会涉及到一些反射的点，反射也很好理解，就是程序运行后，依然可以修改类的相关属性和方法。比如Person类的age属性默认是20，如果实例化时不传值那就是20了，这时我实例化了个Person，然后程序跑起来了，跑起来后我觉的18岁好，那么怎么可以在不停止程序的情况下，修改我的年龄呢，就可以用反射。


类运行中时我们可以通过反射获取它的字段、方法、构造函数、父类、接口以及注解等。


还是以Person为例，来获取其类名、包名、字段、属性值、构造方法、方法等，具体参考注释，注释加到代码中了：


package com.afa.test;
import java.lang.reflect.Constructor;import java.lang.reflect.Field;import java.lang.reflect.Method;
public class ReflectTest {
    public static void main(String[] args) throws ClassNotFoundException, NoSuchFieldException, NoSuchMethodException {        // 首先需要获取类的class对象，这里采用Class.forName的方法        Class c1 = Class.forName("com.afa.dao.Person");        // 获取包名        System.out.println(c1.getName());        // 获取类名        System.out.println(c1.getSimpleName());        // 获取类的属性，只能获取public属性        Field[] fields = c1.getFields();        // 获取类的属性，所有的包括public，注意区别，多了个Declared，翻译是公开声明，所以包括私有的，不仅用于字段，方法也同样适用        fields = c1.getDeclaredFields();        for (Field field : fields){            System.out.println(field);        }        // getDeclaredField可以传入属性名称从而获取其值，注意这个方法没有s，是用来获取单个属性值用的        Field name = c1.getDeclaredField("name");        System.out.println(name);        // 获取类的方法，注意它获取的是本类以及父类的所有public方法        Method[] methods = c1.getMethods();        for (Method method : methods){            System.out.println(method);        }        // 而getDeclaredMethods就是用来只获取本类的public方法的        Method[] methodss = c1.getDeclaredMethods();        for (Method method : methodss){            System.out.println(method);        }        // 获取指定方法，形式一样，这里是getMethod，第一个参数传入方法名，后面参数传入方法接收的参数，没有参数传入null        Method getName = c1.getMethod("getName", null);        Method setName = c1.getMethod("setName", String.class);        System.out.println(getName);        System.out.println(setName);        // 获取构造器，只获取public        Constructor[] constructors = c1.getConstructors();        for (Constructor constructor : constructors){            System.out.println(constructor);        }        // 获取构造器，包括private私有的        constructors = c1.getDeclaredConstructors();        for (Constructor constructor : constructors){            System.out.println(constructor);        }    }}


除了获取这些信息外，我们也可以通过反射获取实例对象，然后通过实例对象来设置相关的属性，实例代码和注释说明如下：


package com.afa.test;
import com.afa.dao.Person;
import java.lang.reflect.Constructor;import java.lang.reflect.Field;import java.lang.reflect.InvocationTargetException;import java.lang.reflect.Method;
public class ReflectTest2 {    public static void main(String[] args) throws ClassNotFoundException, InstantiationException, IllegalAccessException, NoSuchMethodException, InvocationTargetException, NoSuchFieldException {        // 获取class对象        Class c1 = Class.forName("com.afa.dao.Person");        // 构造一个对象，本质是调用了类的无参构造        Person person =(Person) c1.newInstance();        System.out.println(person);        // 当然，通过有参也可以创建对象        Constructor constructor = c1.getDeclaredConstructor(String.class, int.class, String.class);        Person person2 = (Person) constructor.newInstance("afa", 18, "男");        System.out.println(person2);        // 通过反射获取某个方法并进行调用        Method setName = person.getClass().getDeclaredMethod("setName", String.class);        setName.invoke(person, "aaa");        System.out.println(person.getName());        // 通过反射操作属性        Field name = person.getClass().getDeclaredField("name");        // 如果属性是私有的，那么不能直接操作，需要setAccessible为true，即关闭安全监测        name.setAccessible(true);        name.set(person, "bbb");        System.out.println(person.getName());    }}

静态代理


就以大家常说的租房示例来测试，这个例子更容易理解。


房东出租房屋，客户来了房东要带着去看房，然后介绍，还得签合同等等工作得做，很麻烦，房东只想躺着收钱，于是就想了个办法，把这些活交给他人，房东自己只需要仅仅出租屋子收钱就行了，这个替房东工作的人就是代理，自己只和代理对接，有单子给代理一定的钱就可以了。


编程中也是这样，上面角色是房东、代理、租房的人，而在代码中分为抽象角色、真实角色、代理角色、客户。


一样的，只是换了个词，解释如下：


真实角色：被代理的角色，谁需要被代理，谁就是真实角色，也就是房东。

抽象角色：哪些业务需要被代理，就需要提供接口出去，抽象的，也就是租房接口，比较房东要出租，总要有个租房接口给代理。

代理角色：代理真实角色，也就是中介。

客户：使用代理角色来进行一些操作的就是客户，这里就是租房的人，通过代理来租房。


下面通过代码实现，首先我们先写个抽象角色，也就是接口，这里是租房的接口：


package com.afa.service;
public interface Rent {    public void rent();}


有了租房接口后，我们再写个真实角色，也就是房东，让房东来实现租房接口，对外提供租房服务：


package com.afa.impl;
import com.afa.service.Rent;
public class Host implements Rent {
    @Override    public void rent() {        System.out.println("房屋出租");    }}


好了，现在差个代理，代理除了要对接房东出租房屋后，还有额外的功能要实现，例如带客户看房、介绍、签合同等等。


package com.afa.proxy;
import com.afa.impl.Host;import com.afa.service.Rent;
public class Proxy implements Rent {    private Host host;    public Proxy(){}    public Proxy(Host host){this.host = host;}
    @Override    public void rent() {        seeHouse();        signContract();        host.rent();        fare();    }
    // 带客户看房    public void seeHouse(){        System.out.println("带客户看房并进行介绍");    }
    // 签合同    public void signContract(){        System.out.println("和客户签合同");    }
    // 收中介费    public void fare(){        System.out.println("收中介费");    }
}


现在，客户就可以找中介租房了，代码如下：


package com.afa.test;
import com.afa.impl.Host;import com.afa.proxy.Proxy;
public class Client {    public static void main(String[] args) {        // 房东要出租房屋，先来个房东        Host host = new Host();        // 中介帮房东出租，帮哪个房东，就传哪个房东进来        Proxy proxy = new Proxy(host);        // 调用代理的rent方法，相当于客户对接代理进行租房        proxy.rent();    }}


其实就是测视类去调用一个方法，完事没有直接调用，而是中间加了一层，这种写法有很多好处，首先是真实角色很清晰，只提供核心的业务，其它一些公共的业务不用再关注了。其次公共的业务给到了代理，实现了业务的分工。最后后续如果功能需要扩展，会更加方便。


上面是按照生活中租房的例子写的测试代码，下面我们再写一个接近于业务的场景，增上改查添加日志的例子。


service接口层的增删改查接口代码：


package com.afa.service;
public interface UserService {    void add();    void delete();    void update();    void query();}


impl实现层代码如下：


package com.afa.impl;
import com.afa.service.UserService;
public class UserServiceImpl implements UserService {    @Override    public void add() {        System.out.println("增加了一个用户");    }
    @Override    public void delete() {        System.out.println("删除了一个用户");    }
    @Override    public void update() {        System.out.println("更新了一个用户");    }
    @Override    public void query() {        System.out.println("查询了一个用户");    }}


现在项目上线了，随着业务的扩展的流量的增加，有了新需求，需要对sql语句执行的操作进行日志记录，便于后续业务的跟踪和排查，我们可以在实现类的每个方法中去调用日志记录方法，但是这样我们就改动了原有的代码，在编程中，有个思想就是尽量不要改动已有的代码，当代码多了业务多了，改动原有代码可能会产生非预期的问题，那么该怎么解决呢，我们可以使用代理来处理，从中间加一层。


现加代理类如下：


package com.afa.proxy;
import com.afa.impl.UserServiceImpl;import com.afa.service.UserService;
public class UserServiceProxy implements UserService {    private UserServiceImpl userService;    public void setUserService(UserServiceImpl userService){        this.userService = userService;    }    @Override    public void add() {        log("add");        userService.add();    }
    @Override    public void delete() {        log("delete");        userService.delete();    }
    @Override    public void update() {        log("update");        userService.update();    }
    @Override    public void query() {        log("query");        userService.query();    }
    public void log(String msg){        System.out.println("执行了" + msg +"方法");    }}


测试类代码如下：


package com.afa.test;
import com.afa.impl.UserServiceImpl;import com.afa.proxy.UserServiceProxy;
public class Client2 {    public static void main(String[] args) {        // 真实业务，再怎么加功能，加层数，最终都需要调真实业务，所以先把真实业务拿过来        UserServiceImpl userService = new UserServiceImpl();        // 代理        UserServiceProxy userServiceProxy = new UserServiceProxy();        // 调用代理中的set方法，需要给哪个业务记录日志，就传哪个业务进来        userServiceProxy.setUserService(userService);        // 调用相关增删改查即可        userServiceProxy.add();    }}


上面例子看起来代码好像写多了，如果直接在原有实现类调用log的话，代码会少，其实不是。上面的代理模式有个很重要的思想就是原先的核心业务代码没有变动，不会影响原有的业务。再有就是如果项目大了，需要添加日志的地方很多，我们一个一个地方加log很不现实，而代理的话，只需要一个代理类即可，给谁加，就调用谁就可以了。


动态代理


上面了解了静态代理，虽有好处，但也有不足，比如我们项目很大的时候，类多的情况下，每个类都需要单独的对应一个代理类，这时就增加了工作量，使得开发效率变低。


那么怎么解决呢，就可以使用动态代理，还是以上面租房为例，下面边写代码边解释。


抽象类租房接口Rent和真实角色房东Host不动，代理类不用了，改为生成代理的类，后续代理类都自动生成，即动态代理。


package com.afa.proxy;
import com.afa.service.Rent;
import java.lang.reflect.InvocationHandler;import java.lang.reflect.Method;import java.lang.reflect.Proxy;
public class ProxyInvocationHandler implements InvocationHandler {    private Rent rent;    public void setRent(Rent rent){        this.rent = rent;    }
    // 该方法用来生成代理类    // 主要就是调用newProxyInstance方法，该方法有三个参数，第一个就是传入类加载器，第二个是获取类实例，第三个是调用处理器，我们在当前类重写了，填this即可    // 这个基本就是固定写法，结合三个参数简单理解就是通过类加载器去加载指定的类并实例化，完事指定调用处理器，去调用其方法，调用时再加上我们自己的扩展业务代码即可，和静态代理思路是一样的，只不过代理类换成这个方法自动生成了而已    public Object getProxy(){        return Proxy.newProxyInstance(this.getClass().getClassLoader(), rent.getClass().getInterfaces(),this);    }
    // invoke是调用类，就是调用真实角色的，第一个参数是代理类，第二个是要调用的方法，第三个是方法的参数    @Override    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {        seeHouse();        signContract();        // 原先是host.rent调用的，我们现在利用反射去调用rent        Object result = method.invoke(rent, args);        fare();        return result;    }    // 带客户看房    public void seeHouse(){        System.out.println("带客户看房并进行介绍");    }
    // 签合同    public void signContract(){        System.out.println("和客户签合同");    }
    // 收中介费    public void fare(){        System.out.println("收中介费");    }}


有了生成代理的类，我们修改下原有的客户端代码即可实现一样的效果，修改代码如下，说明参考注释：


package com.afa.test;
import com.afa.impl.Host;import com.afa.proxy.ProxyInvocationHandler;import com.afa.service.Rent;
public class Client {    public static void main(String[] args) {        // 房东要出租房屋，先来个房东，这不变        Host host = new Host();        // 原先是新建代理类，帮哪个房东出租就传哪个房东进行        // Proxy proxy = new Proxy(host);        // 现在还是需要代理类，只不过代理类需要调用代理生成程序来生成        ProxyInvocationHandler pih = new ProxyInvocationHandler();        // 哪个房东出租就传入哪个房东        pih.setRent(host);        // 调用getProxy动态生成        Rent proxy = (Rent) pih.getProxy();        // 这句不变，还是通过代理调用rent，注意invoke中的方法都会默认执行，真实角色提供的业务，通过反射调用，要调用谁就proxy点就可以了，比如要调用rent租房接口，proxy.rent即可        proxy.rent();    }}


同样的思路，再来改下log增加日志那个例子，写法基本都一样，只要把Rent改一下就行，就不添加注释了。


package com.afa.proxy;
import java.lang.reflect.InvocationHandler;import java.lang.reflect.Method;import java.lang.reflect.Proxy;
public class ProxyInvocationHandler2 implements InvocationHandler {    private Object target;    public void setTarget(Object target){        this.target = target;    }    public Object getProxy(){        return Proxy.newProxyInstance(this.getClass().getClassLoader(), target.getClass().getInterfaces(), this);    }    @Override    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {        log(method.getName());        Object result = method.invoke(target, args);        return result;    }    public void log(String methodName){        System.out.println("执行了" + methodName + "方法");    }}


测试类也是类似的，如下代码：


package com.afa.test;
import com.afa.impl.UserServiceImpl;import com.afa.proxy.ProxyInvocationHandler2;import com.afa.service.UserService;
public class Client2 {    public static void main(String[] args) {        UserServiceImpl userService = new UserServiceImpl();        ProxyInvocationHandler2 pih = new ProxyInvocationHandler2();        pih.setTarget(userService);        UserService proxy = (UserService) pih.getProxy();        proxy.delete();    }}


关于动态代理的好处，静态代理有的动态代理有，静态代理没有的，动态代理还有。最大的好处就是解决了静态代理的不足之处。


原先静态代理的话，每个类都需要有对应的代理类，比如有了房东1，房东2，还有购物的中介，日常生活的其它中介，我们需要实现很多代理类，但有了动态代理，哪个需要代理，只需要传给动态的代理类来动态生成代理即可。


那么动态代理在序列化中会在哪用到呢，主要就是invoke方法，和readObject类似，拥有自动执行代码的能力。


比如A类有个test方法可以执行命令，此时有个B类参数可接收Object，并且接收后会调用这个Object的test方法，那么这就是一个很好的利用链。那么也可能B接收Object后，没有调用test，而是test2，此时链条就不通了，但是如果这时有个代理类，代理类中可接收一个Object且调用test，那么就可以把代理类传到B中，此时利用代理类的invoke自动执行机制，也可以自动调用到A的test，完成链条执行。


类加载


在此之前我们先回顾下代码块的加载顺序，例如Person类提供了静态代码块，初始化，无参和有参构造以及静态方法，那么它们的执行顺序是什么呢：


package com.afa.dao;
public class Person {    private String name;    private int age;
    public Person() {        System.out.println("无参构造方法");    }
    public Person(String name, int age, String sex) {        this.name = name;        this.age = age;        System.out.println("有参构造方法");    }
    static {        System.out.println("静态代码块");    }
    {        System.out.println("构造代码块");    }
    public String getName() {        return name;    }
    public void setName(String name) {        this.name = name;    }
    public int getAge() {        return age;    }
    public void setAge(int age) {        this.age = age;    }
    public static void statieMethod(){        System.out.println("静态方法");    }
}

package com.afa.test;
import com.afa.dao.Person;
public class Test {    public static void main(String[] args) {        Person person = new Person();        person.statieMethod();    }}


作用如下：


静态代码块：被static{}标识，类加载的时候执行，由于类只能被加载一次，所以静态代码块也只运行一次，一般用来初始化成员变量，对类进行初始化。

构造代码块：在类被创建的时候执行，可以用来放重复的代码，减少构造方法代码量。因为先于构造方法执行，所以无参有参等共同的代码可以放到构造代码块中。

无参有参构造：这个就不用解释了，实例化对象时调用。

静态方法：被static标识的方法属于静态方法，是类的方法，而不是对象的方法。


可以看到这个顺序和类加载很想，类首先加载到内存，而加载时会调用静态代码块，加载完后会进行创建，创建时会调用构造代码块，创建完后进行实例化，实例化会调用无参或有参，最后通过实例化对象去调用其方法。


这里也可以了解下双亲委派，便于我们后续了解，关于双亲委派，可以参考之前的那篇文章《Java打破双亲委派浅析》。


简单了解后，我们来看下类加载的几种方式，因为类只要加载就会执行静态代码块，所以我们把测试代码放到静态代码块中，测试类HelloURL如下：


import java.io.IOException;
public class HelloURL {    static{        try {            Runtime.getRuntime().exec("calc");        } catch (IOException e) {            throw new RuntimeException(e);        }    }}


注意不要在包下建，不然带有packge，后续远程加载时路径会错误，直接在src目录下建就可以，下面通过几种方式来测试，加载HelloRUL类执行恶意代码。


1，通过URLClassLoader和file协议远程加载。


首先构建项目，把HelloURL.class文件放到其它位置，这里放到d盘的test目录下，随后把src目录下的HelloURL文件删除，也就是说我们的项目中并不存在HelloURL这个类，测试代码如下：


package com.afa.test;
import java.net.URL;import java.net.URLClassLoader;
public class Test {    public static void main(String[] args) throws Exception {        // 通过URLClassLoader指定个路径，这里采用file形式        ClassLoader urlClassLoader = new URLClassLoader(new URL[]{new URL("file:///D:\\test\\")});        // 然后加载路径下指定的类        Class<?> clazz = urlClassLoader.loadClass("HelloURL");        // 实例化执行        clazz.newInstance();    }}


执行后可以看到成功运行了HelloURL，URLClassLoader除了可以使用file协议外，也可以使用http协议。

3，通过URLClassLoader和jar协议远程加载。


除了file和http，还支持远程加载jar包，jar包的话是需要在原来的file和http基础上应用，这里以file为例在原有的file协议前添加jar:，然后末尾跟jar文件加!/即可（按语法文档写法需要添加!/），如下：


package com.afa.test;
import java.net.URL;import java.net.URLClassLoader;
public class Test {    public static void main(String[] args) throws Exception {        // 通过URLClassLoader指定个路径，这里采用file形式        ClassLoader urlClassLoader = new URLClassLoader(new URL[]{new URL("jar:file:///d:\\test\\HelloURL.jar!/")});        // 然后加载路径下指定的类        Class<?> clazz = urlClassLoader.loadClass("HelloURL");        // 实例化执行        clazz.newInstance();    }}

那么这种应用在哪呢，URLClassLoader可以实现远程加载任意类的效果，在反序列化中，可以更方便的让我们去调用相关的类。


除了URLClassLoader外，在我们自定义类加载器时，有一个defineClass方法，该方法也可以远程加载类，defineClass属于ClassLoader下的方法，如果我们想调用来自定义，可以使用反射获取ClassLoader的class对象然后再获取defineClass方法进行相关操作，代码和注释如下：


package com.afa.test;
import java.lang.reflect.Method;import java.nio.file.Files;import java.nio.file.Paths;

public class Test {    public static void main(String[] args) throws Exception {        // 思路就是通过反射调用ClassLoader下的defineClass方法，然后把相关参数传入即可        // 调用时需要传入ClassLoader对象，这里使用程序当前的类加载器即可        ClassLoader clazz = ClassLoader.getSystemClassLoader();        // 通过反射获取defineClass        Method defineClassMethod = ClassLoader.class.getDeclaredMethod("defineClass", String.class, byte[].class, int.class, int.class);        // 设置可访问        defineClassMethod.setAccessible(true);        // defineClass参数需要传入字节码，这里进行获取        byte[] code = Files.readAllBytes(Paths.get("d:\\test\\HelloURL.class"));        // 进行调用，第一个参数传入类加载器，第二个传入要调用的类，第三个是字节码，第四个和第五个是字节码的起始位置和终止位置        Class c = (Class) defineClassMethod.invoke(clazz, "HelloURL", code, 0, code.length);        // 加载好后实例化即可        c.newInstance();    }}


defineClass通过传入的字节码来调用相关的类，和URLClassLoader的file是类似的，和http区别在于，http需要出网加载，defineClass只要传进去字节码即可。


这个defineClass的话，还有一个类有该方法，就是unsafe，我们也可以通过unsafe对象来调用defineClass，代码和注释如下。


package com.afa.test;
import sun.misc.Unsafe;
import java.lang.reflect.Field;import java.lang.reflect.Method;import java.nio.file.Files;import java.nio.file.Paths;

public class Test {    public static void main(String[] args) throws Exception {        // 思路就是通过反射调用unsafe下的defineClass方法，然后把相关参数传入即可        // 调用时需要传入ClassLoader对象，这里使用程序当前的类加载器即可        ClassLoader clazz = ClassLoader.getSystemClassLoader();        // 下面的这几句代码就是获取一个unsafe对象        Class c1 = Unsafe.class; // 获取unsafe的类对象        Field theUnsafeField = c1.getDeclaredField("theUnsafe"); // 获取其字段theUnsafe，因为在unsafe的静态代码块中把对象赋值给了该字段，所以只要获取该字段即可        theUnsafeField.setAccessible(true);        Unsafe unsafe = (Unsafe) theUnsafeField.get(null); // get获取，静态方法，所以传入null即可        // defineClass参数需要传入字节码，这里进行获取        byte[] code = Files.readAllBytes(Paths.get("d:\\test\\HelloURL.class"));        // 进行调用，还是传入相关的参数        Class c2 = (Class) unsafe.defineClass("HelloURL", code, 0, code.length, clazz, null);        // 加载好后实例化即可        c2.newInstance();    }}


总结：上面记录了类加载的三种方法：1，URLClassLoader的file、http、jar协议。2，ClassLoader的defineClass方法。3，Unsafe的deineClass方法。
