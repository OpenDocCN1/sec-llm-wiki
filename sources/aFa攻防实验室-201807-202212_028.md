**介绍**  

  

SNMP、简单的网络管理协议，Simple Network Management Protocol。  
SNMP在Windows、Linux、Unix、路由、交换机上经常存在，可用来获取目标网络的一些信息，比如系统信息、用户名、进程名、运行时间、网络信息、端口情况等。

  

**场景**

  

例如我要对公司的一些设备进行性能监控，如果哪台设备CPU超过阈值，则进行报警，类似于这样的多台机器操作的需求。首先我要在被监控的机器上开启Snmp并安装一个Agent，然后这些Agent统一把信息汇总到管理员那里，示例图如下。

**Snmp版本概述**

Snmp分为三个版本，v1、v2c、v3，v1是32位系统上的，且传输时使用的明文，v2c进行了改进，适用了64位系统，但传输依然是明文，v3则对传输进行了加密处理，使用了密文。

  

除此外v1和v2验证时使用的是Community String，一般叫做团体名，相当于密码的作用，即知道了Snmp的访问密码，便可以利用Snmp去查询相关的设备信息。到v3时，改为了用户名和密码验证的情况，添加了一个用户名，添加了相关的加密功能，所以安全性更高了。

  

Snmpv3支持以下验证：

  

1，noAuthnoPriv：无需身份验证，密码不加密。

2，authNoPriv：需要身份验证，密码不加密。

3，authPriv：需要身份证，密码加密。

  

**MIB和OID**

MIB简称为管理信息库，参考上面场景那张图，把各个设备的相关信息存储到Snmp管理端，就是MIB管理信息库，其实相当于一个数据库。而OID是对象标识符，如果我们要从管理库中查询某个信息，则需要标识符，就是OID，相当于数据库查询时的ID。

  

OID的格式稍微复杂点，类似于这样子：1.3.6.1.2.1.1.3.0，不同的设备有自己不同的OID。

**Snmpwalk v3**

  

Snmpwalk也可查询Snmpv3的相关信息，不过需要根据相关的用户名和密码，而不是团体名，首先配置下Snmp，在/etc/snmp/snmpd.conf文件中添加以下内容：

  

![](../Images/5b3f1cdd361ee4d13c3b1267fb8c4f19.png)

  

上面user1是没密码没加密，user2是有密码没加密，user3是有密码有加密，其中1.3.6.1.2.1指的是该OID以下的内容查询需要进行身份验证，而136121是所有信息的开头数字，代表了所有信息。

  

查询相关语句如下，具体参数说明可参考帮助文档：

  

*   
*   
*   
*   
*   
*   
*   
*   

```
# 无密码无加密的情况，但需要用户名snmpwalk -v 3 -l noAuthNoPriv -u user1 127.0.0.1
# 有密码但无加密的情况snmpwalk -v 3 -l authnoPriv -u user2 -a MD5 -A user2password 127.0.0.1
# 有密码有加密的情况snmpwalk -v 3 -l authPriv -u user3 -a MD5 -A user3password -x DES -X user3encryption 127.0.0.1
```
