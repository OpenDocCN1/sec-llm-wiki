**前言**

  

前端时间发过一篇CS安全配置的总结，属于CS本身一些特征的修改，除此外CS在传输过程中隐藏自身真实IP也属于安全配置中的一项，常用的方法有三种，分别是CDN、域前置和重定向，也看到过通过云函数来隐藏真实IP的，本节先总结CDN。

  

**准备条件**

  

1，CDN服务，可以选择CloudFlare，免费提供，不需要实名。

  

2，域名一个，例如Godaddy的xyz，比较实惠，或者找一个免费的域名，Freenom之类的。

  

3，一台VPS，VPS可以选择Vultr，如果Vultr收不到Shell，可以选择老毛子的，国内的也可以。

  

**相关配置**

  

首先需要在Godaddy有一个域名，如果实战用的话，建议购买时把域名信息隐藏的服务勾选上，避免被溯源，免费域名不用管。

  

有了域名后，在CloudFlare上添加站点，如下图：

  

![](../Images/7aa059146891df9fc3da7f983ed42909.png)

  

添加站点后，CloudFlare会提供两个NS记录（NS记录用来指定域名由哪一台DNS服务器来解析），转到Godaddy上把自带的两个NS记录替换成CloudFlare的，位置在DNS管理处：

  

![](../Images/5dcc30e6d1dd024e31d222b18fc3ef3b.png)

  

这时，访问域名时，NS记录指向的服务器就变成了CloudFlare的CDN地址，最后还需要在CloudFlare上配置一个A记录，A记录指向自己的VPS地址（A记录指定域名绑定的IP）。

  

![](../Images/739c8d881ca8876e7d39996f54325697.png)

  

此时就配置好了，整个流程就是Godaddy购买域名，然后替换NS为CloudFlare，即把域名托管到CloudFlare，去使用CloudFlare的CDN服务，CloudFlare上又配置了A记录，可以成功把域名解析到自己的VPS上。

  

也就意味着我们访问自己的域名，Ping IP会显示CDN地址，但实际访问的是我们自己VPS上的内容，其实就是添加CDN。

  

提醒：这里需要在CloudFlare上把缓存关一下，否则CDN会进行内容缓存，那么CS与目标机交互的命令结果就不会实时返回。

  

![](../Images/f279b2680d38b62130829f68f751b572.png)

  

默认打开3小时后会自动关闭，这个可以通过CloudFlare的页面规则进行，找到页面规则，将缓存级别设置为绕过，如下图：

  

![](../Images/892278e5d38611184c4adcaaeee5212f.png)

  

使用多地Ping检测，确认CDN已配置：

  

![](../Images/35b22c222fd5696ab10ba5a2d7c53261.png)

**HTTPS证书**

  

CS使用CDN后，可以一定程度隐藏IP地址，使用WireShark抓包交互IP都是CDN地址，但是传输协议使用的HTTP，传输内容是没有加密的，如果要加密，则可以使用HTTPS。

  

还以CloudFlare为例，切换到SSL/TLS栏，证书类型选择完全，如下图：

  

![](../Images/8d6ca08571fa040eea751a61b1e7022e.png)

  

切换到源服务器，进行创建证书，类型选择ECC：

  

![](../Images/1b889c677ac27e63429d2752a608858b.png)

  

将生成的内容分别存储为a.pem和a.key（名字可以随便起），传到CS所在的服务器：

  

![](../Images/83bc3bf557157453b8c2d3bc47128c61.png)

  

随后可以把CS自带的cobaltstrike.store备份一下，然后生成新的store文件，执行下面命令，生成相关的store文件：命令中xxx.xxxx.xyz替换为自己的域名：

  

*   
*   

```
openssl pkcs12 -export -in a.pem -inkey a.key -out a.p12 -name xxx.xxxx.xyz -passout pass:123456keytool -importkeystore -deststorepass 123456 -destkeypass 123456 -destkeystore cobaltstrike.store -srckeystore a.p12 -srcstoretype PKCS12 -srcstorepass zjhnzyq -alias xxx.xxxx.xyz
```

  

teamserver启动时的配置文件中要确保https-certificate的配置，我这里测试时没有加载配置文件，后续也正常运行，默认估计就是加载的cobaltstrike.store，默认密码也是123456，忘记CS哪里配置的了，如果改名和密码了，那估计就需要配置这一段了：

  

*   
*   
*   
*   

```
https-certificate {    set keystore "cobaltstrike.store";    set password "123456";}
```

**总结和思考**

  

思路流程：给域名设置一个CDN，CS马上线使用域名上线，这样查自己的时候，查的是CDN地址，一定程度隐藏了C2的真实地址，CDN厂商那里把VPS地址绑定到域名上，保证可以和VPS通信。

  

上面操作流程中有优点也有缺点：先说优点，匿名、隐藏了IP、免费的CDN、不用实名等等，都算的上是优点，但相对说缺点可能比重更多，例如上线端口的限制（不过付费的可能选择会更多），一定程度上会影响渗透的效率，另外CDN在国外，响应比较慢，尤其是使用了HTTPS。

  

所以整体上看这种方法也是可以用的，也可以按照CDN变换下思路，例如CDN我们使用国内的，但需要有备案域名和实名，总之各有利弊。
