PTH简介  
  
不论是网站还是windows系统，都不会去明文存储用户的密码，是最基本的一条安全准则。那么进行相关登录验证的时候，就会获取用户输入的明文密码然后经过加密处理后再和数据库中的散列值进行对比，从而进行相关校验。  
所谓PTH即Pass the Hash缩写，字面理解密码就是hash的意思。我们一般拿到windows的ntlmhash后会进行相关破解，如果密码复杂度高可能一般破解不容易，那么我们可以直接拿hash去进行相关服务的访问，拿hash当作密码给服务器校验。总结一句话：用户使用哈希而不需要原始密码就能进行身份验证。  
pth攻击首先就是域内机器以本地管理员身份登录，这种情况进行pth的话，攻击的对象是其他的机器，其他机器上存在相同账号和密码的，就会被拿下，这种情况很多，像管理员administrator的密码因为各种情况就会一样。然后就是域内机器域账号登录的，这种ntlm、kerberos等身份验证协议都会利用sso单点登录，拿到一个域账号的hash后利用pth攻击就可以访问相关服务，例如数据库、文件服务器和域控等。最后重复上面过程，这个重复利用的过程可以叫hash喷射攻击，从而进行横向渗透扩大战果。

  

PTH攻击

  

我们首先试一下本地用户的pth攻击，便于理解，pth不仅用于域中，工作组的局域网也可以尝试（也就是上面说的域内机器以本地管理员身份登录的情况），我这里目标机是一台192.168.150.148的机器，首先我们在攻击机运行mimikatz获取ntlmhash：

  

![](../Images/34e072fcff32783dff5daedba10c53ac.png)

  

然后我们执行sekurlsa模块下的pth命令，domain参数用来指定目标ip，user指定用户名，ntlm指定hash：

  

![](../Images/1f812b3d7a4d747097b628ed4f423cdb.png)

  

运行后会弹出一个cmd框，这时运行相关命令就可以访问的目标机了：

  

![](../Images/c200dadfc4d3f1e3d625f384c80dbcca.png)

  

然后就是域内的pth攻击，了解域内pth攻击前，先来看看kb2871997补丁，这个补丁前几篇笔记提到过，说是有了它lsass进程就不会再缓存明文了。除此之外，该补丁它会禁止本地管理员与远程计算机连接，也就意味着像psexec、wmi、smbexec、schtasks都不能使用了，远程主机的文件共享也无法访问，同理pth攻击也无法进行。但唯独sid为500的账号可以例外，它可以不受kb2871997的影响。

  

域内主机进行pth攻击时，如果是本机账号登录则需要是管理员权限，如果是域内账号登录则需要属于本地管理员组。下面先以本地账号登录为例，用法和上面的工作组局域网攻击方法一样，区别在于domain跟的是域名。注意：非域账户而是本地管理员登录域内机器是可以在域内执行pth的，效果就是攻击其他机器存在相同密码的情况。

  

例如域内机器以管理员administrator进行pth，域控机器的本地管理员密码一样：

  

![](../Images/641f90d439ac852a49ec410b546cca8f.png)

  

第二种情况就是域内账户登录的情况，值得注意的是域内账户需要属于本地管理员组，先来看看不属于本地管理员组的情况，执行whoami /groups看看builtin是users还是administrators，users说明不属于本地管理员组，那么像mimikatz这些工具是无法获得调试权的。

  

![](../Images/c2d541b6e36be82aec3c7c1a134b488e.png)

  

解决办法：使用本地管理员账户登录，在用户账户控制，把域账号添加进去即可，windows server2008操作图如下，其他版本机器都差不多，具体位置可以去网上搜索。

  

![](../Images/96f08754e1e6c09e35ae5c7099b4b0f4.png)

  

添加后，域账户从新登录，再次查看然后执行mimikatz即可。

  

![](../Images/b5539137a0b31f3673fc65388bd1b9ed.png)

  

这里说一个注意点，就是我们没有进行pth攻击的时候，如果你执行dir这种命令是可以列出来相关内容的，因为对面共享开着，一个网下，是可以访问共享的，而进行了pth攻击后也可以进行共享查看，但有区别，看下图。

  

![](../Images/a7fb30e81e7256d9dfd02b892003c0db.png)

  

直接打开命令行是可以成功通过dir查看对方共享的，但如果是pth攻击的话，是新弹出了一个命令行，账号或密码错误时会提示你，不会去执行相关命令，所以这里可以看出来pth弹出的命令行是以账号和相应hash去访问的，和本机命令行不是一回事。

  

PTK简介

  

PTK指的是pass the key密码即密钥的意思，用密钥来代替密码来进行认证操作。当目标机安装了kb2871997时，获取不到ntlm时，可以考虑使用ptk，在域中经常使用kerberos协议，kerberos协议处理过程中加密等操作用到了密钥，因为密钥和密码、票据等一样，也会存在lsass进程中，我们可以使用mimikatz来提取密钥，有了密钥，我们就可以使用它冒充身份进行相关的认证。

  

PTK攻击

  

ptk密钥传递攻击使用的是kerberos协议中的加密密钥为基础进行的，我们需要先通过mimikatz等工具获取它的加密密钥，这里以mimikatz的sekurlsa::ekeys为例进行操作，sekurlsa模块主要用来获取lsass进程中的一些信息，而ekeys的作用是列出kerberos的加密密钥，密钥一般就是aes128和aes256。

  

获取到密钥后，攻击和pth一样，只不过把ntlm参数换成了aes256，示例如下。

  

![](../Images/193921589928a7c7725a0a22b2e2ced2.png)

  

对于ptk的注意点一个是被利用的攻击机需要装kb2871997，否则执行pth后会提示拒绝访问。二是像dir这类命令需要跟机器名，ip的话会报用户名密码错误。三是除了aes256，aes128也可以进行pth攻击。四是mimikatz结果不能复制，标记的话会崩溃，可以使用log把结果导出来。

  

PTT简介

  

ptt即pass the tickets密码就是票据，在域中通过伪造票据来进行攻击，票据传递工具不需要本地管理员权限。

  

PTT攻击

  

这里还是以mimikatz为例，首先使用mimikatz将内存中的票据导出来，执行以下命令（这里不截图了，输出结果把命令顶没了）：

  

*   
*   

```
privilege::debugsekurlsa::tickets /export
```

  

  

执行上述命令，在当前目录下会生成多个服务的票据文件，以kirbi为后缀的文件，它是windows下的票据文件，例如krbtgt、cifs、ldap等，然后清除内存中的票据，将所需的票据文件注入到内存中即可。

  

*   
*   
*   

```
kerberos::purgekerberos::listkerberos::ptt "c:\xxx.kirbi"
```

  

  

上面就是mimikatz执行ptt攻击的步骤，除此外还有类似的kekeo(github搜索下载即可)，用法和mimikatz类似，通过域名、用户名、nthash来生成票据，然后进行导入，最后连接远程计算机，相关命令如下。

  

*   
*   
*   
*   
*   
*   

```
# 运行kekeo，生成票据文件tgt::ask /user:administrator /domain::xxx.com /ntlm:xxxxxxxxxxxxxxxxxxxxx# 然后清除机器内存中的票据kerberos::purge# 将票据导入内存kerberos::ptt xxxxx.kirbi
```

  

  

总结

  

上面简单记录了pth、ptk、ptt的基本使用。pth攻击即用nthash代替密码，可用来攻击用户名和密码一样的机器，或用来访问相关服务。ptk即用key密钥来代替密码，windows server2008、win7及以前的版本只有当机器安装kb2871997补丁时才可利用key密钥传递来进行攻击。ptt即伪造票据攻击，主要是生成高权限的票据然后导入内存进行利用。
