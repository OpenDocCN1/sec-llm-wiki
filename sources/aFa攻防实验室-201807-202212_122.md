**介绍**  

  

何为设计模式？设置模式只是一种开发思想，并不是什么固定模式，前人的好的思想，我们后人拿过来用，比如前人程序写出的某种结构，方便管理、维护、操作、复用等，这种结构久而久之沉淀下来的，我们就叫它设计模式。

 

设计模式常用的有很多种，例如单例模式、观察者模式等等，Mixin也是其中之一。设计模式并不绑定语言，它只是一种开发思想，Python适用，拿到PHP、Java中也可以使用。

 

何为mixin设计模式？mix混合in进入，作用和字面意思差不多，它可以在不对类内容修改的前提下，扩展类的功能，其实就是类的继承。

 

**单继承示例**

 

例如有一个水果类Fruit.

  

*   
*   

```
class Fruit:    pass
```

  

水果类分为南方水果和北方水果，它们都继承自水果类。

  

*   
*   
*   
*   
*   
*   

```
#南方水果class SouthFruit(Fruit):pass#北方水果class NorthFruit(Fruit):    pass
```

  

然后我们再定义四个具体的水果类，例如苹果和梨，它们继承北方水果类，香蕉和橘子，它们继承南方水果类，代码如下。

  

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   

```
#苹果类class Apple(NorthFruit):pass#梨类class Pear(NorthFruit):pass#香蕉类class Banana(SouthFruit):pass#橘子类class Orange(SouthFruit):    pass
```

  

上面采用的是单继承方式，继承图如下。

  

![](../Images/3c3c518b39b21600ef28e518924f22c8.png)

  

**添加分类**

 

上面单继承是没问题的，但比如现在要加一个分类，是否可以当作礼物送出的类，这样的话按照上面单继承的写法，应该再添加四个类，分别是南方礼物水果类、南方非礼物水果类、北方礼物水果类、北方非礼物水果类。

 

可以看到我们只添加了一个分类，而实际中却需要新添加四个类，这四个类继承南方水果类和北方水果类，代码如下。

  

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   

```
#南方礼物水果class SouthGiftFruit(SouthFruit):pass#南方非礼物水果class SouthNotgiftFruit(SouthFruit):pass#北方礼物水果class NorthGiftFruit(NorthFruit):pass#北方非礼物水果class NorthNotgiftFruit(NorthFruit):    pass
```

  

而且水果类也要修改，它们不能再继承南方类或北方类了，而要继承礼物类和非礼物类。比如苹果，代表平平安安，那么它应该继承北方礼物水果类，梨寓意不好，那么它就应该继承北方非礼物水果类。

  

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   

```
#苹果类class Apple(NorthGiftFruit):pass#梨类class Pear(NorthNotgiftFruit):pass#香蕉类class Banana(SouthNotgiftFruit):pass#橘子类class Orange(SouthGiftFruit):    pass
```

  

到此就改完了，可以看到，我们仅仅添加了一个礼物分类，就需要加四个类以及修改后面所有的水果类。

 

上面修改还可以接受，那么如果还需要添加一个分类，比如说水果吃的时候需不需要去皮，那么就需要在原来的礼物类和非礼物类上继续划分，这时候就得再加八个类，这八个类是：南方礼物去皮、南方礼物不去皮、南方非礼物去皮、南方非礼物不去皮、北方礼物去皮、北方礼物不去皮、北方非礼物去皮、北方非礼物不去皮。如果后面再加一个分类添加类数就变成了16，再加就32。

 

上面我们假设的仅仅是两种分类的，如果是多种呢，比如说按水果颜色来分，可以发现需要添加的类是指数增长的。

  

**混合多继承模式**

 

为例解决上面问题，我们设计出了混合模式多继承来解决，可以发现，上面的礼物分类、去皮分类等之间是没有联系的，那么我们可以把它们单独写出来。

 

首先还是水果类，然后香蕉、橘子等水果继承水果类，如下。

  

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   

```
#水果类class Fruit:pass#苹果类class Apple(Fruit):pass#梨类class Pear(Fruit):pass#香蕉类class Banana(Fruit):pass#橘子类class Orange(Fruit):    pass
```

  

这时比如要添加南方北方分类，我们不让水果去继承它们了，而是单独写两个类，一个南方类，一个北方类。

  

*   
*   
*   
*   
*   
*   

```
#南方类class South:pass#北方类class North:    pass
```

  

这样的话我们只需要给水果添加南北方类，让它们多继承即可。

  

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   

```
#苹果类class Apple(Fruit, North):pass#梨类class Pear(Fruit, North):pass#香蕉类class Banana(Fruit, South):pass#橘子类class Orange(Fruit, South):    pass
```

  

现在的多继承方式，结构已经改变了，继承图如下（为了看清楚，水果继承间使用了不同颜色剪头表示）。

上面可能优势不够明显，因为单继承也是写了七个类，多继承也是写了七个类，而把礼物类也加上，单继承则需要写11个，多继承九个就够了，这时候mixin就体现出了优势，图例如下，为例方便清晰，只画香蕉和苹果。

**总结**

 

1，当需要多个类，且各个分类不相关时，我们应该考虑使用mixin模式来编写程序。

2，将各个功能实现为可插拔的mixin组件，然后使相关类继承自己需要的那些组件，便可以定制该类示例所具备的行为。

3，把简单行为封装到mixin组件里面，然后就可以用多个mixin组合出复杂的行为。
