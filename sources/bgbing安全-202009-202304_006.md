# 0x03 文件包含漏洞

看到这个主题配置功能点的数据（模板标题，模板描述等）之前没有在数据库中见到  
![](../Images/012a4bdb49786b9c22e2e3625675e132.png)

全局搜索了一下发现数据存放在主题模板目录下的`config.json`文件中  
![](../Images/196e023803f853a166189d9412e0f56b.png)

想到是应该包含了这个 json 文件，在源码中找了一下  
![](../Images/3457786be767f1ff8eb3b5f68a35cb86.png)

跟进`load_json()`  
![](../Images/b468c64e1050ca4c42f960e4d69d8d8c.png)

看到调用了`json::get($file)`，继续跟  
![](../Images/bf37b9bb88eebd60e13dbb14e190fd79.png)

确定是调用了`require`函数进行包含。接下来的思路就是找可以修改`config.json`文件的功能点。找了一圈才发现该 cms 提供了一个在线插件进行修改(插件只能从官方提供的插件市场进行下载)，我在写本文的时候，官方已经将该插件升级到了 V1.1，已经不适配 cmsV1.2 版本(下面会说明)  
![](../Images/43529e57966cb8797185f01ad179c7f6.png)

安装完成后，就可以点击修改对`config.json`文件进行修改  
![](../Images/abc3c50524f183300a0b258287583598.png)

![](../Images/02627e2c17eee0ed21a3c82e2f0e78b0.png)

当然直接修改会报错，因为在插件V1.1版本中的方法命名做了修改  
![](../Images/2540378636c17876c8855b51c961f206.png)

![](../Images/eb69d70b9bf4f26183ddb2de3da6e813.png)

v1.1插件版本对应的是最新版的cms源码，在最新cms版本中该处代码命名为`delSlashes()`  
![](../Images/d6ac7e86ffa455aab6a8201fd39c4e73.png)

而cmsV1.2版本源码没有`delSlashes()`方法导致报错，而是命名为`delFilter()`  
![](../Images/8df7a025c998d520bcb4566f5989d86c.png)

我们做一下修改，回滚插件代码为对应的v1.2时的情况复现当时情景

可以正常对`config.json`文件进行修改之后

![](../Images/3c9fde85bd84e05d4bf8ca4c65f4dee4.png)

![](../Images/286fd61517ffdb4c9c9387fec7c340e6.png)

成功包含并且执行 php 代码  
![](../Images/ce097b10653b1de3d45b2e10f1e83629.png)

写入webshell  
![](../Images/1dfacdcb7f54c6f60bb56a1dcbfe78c3.png)

![](../Images/65bb750c66a2271d2a281baa724ba632.png)

在最新版本中的修复方法是使用了`htmlspecialchars()`函数将`<、>`实体化编码成`&lt;&gt;`  
![](../Images/89a61ca7b35c903a13e7eb7ef4f3788b.png)

# 0x04 文件上传漏洞

前面的文件包含因为插件更新的缘故，所以现在无法利用。继续寻找别的漏洞点

看到一个 ueditor 编辑器，尝试附件上传 php一句话木马失败  
![](../Images/f197111efda4ebd5f5320341e2cea2bc.png)

找到对应源码  
![](../Images/0bf082138bc89fd6ff37d00dd39ca2f1.png)

关键判断为

```
upload::files(
```

跟进`upload`类的`files`方法，一共有两个关键判断

![](../Images/a2b2b3dc4e0f4bb972d75c29a2804346.png)

首先看判断一，判断文件后缀在不在`$type`列表里对应的后缀，而前面我们传进来的`$type=code|zip|word|excel|powerpoint|audio|text|pdf`中，code对应的后缀列表是含有`.php`的  
![](../Images/bab3f20ab3f43c918051998adec5933b.png)

接着看判断二，判断文件后缀在不在`$extension`数组中  
![](../Images/8881a6c844807da5d72d4a558f37dab6.png)

`$extension`数组是从数据库表中取出，没有`.php`导致文件上传失败  
![](../Images/e47b13890b1babe2b61f37f5949d80e3.png)

知道了原因之后我们开始找可以修改数据库中表的功能点，最后发现有个文件上传类型可以直接更改  
![](../Images/9b6fd9a221b5eebebe76f5f2463cba9b.png)

添加上`.php`后缀保存，再上传  
![](../Images/e382cd77b87d78e14b0608e6ee983bd9.png)

成功上传webshell  
![](../Images/20662f0598932c3a3f031dc05331005a.png)

最新版修复办法是将`$type`参数的内容改成了`null`  
![](../Images/d4f255c53b96c39facbe6f3d0dae9948.png)
