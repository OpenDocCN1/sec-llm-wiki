# 一次任意文件下载引发的渗透

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzkwNzEzMTg3MQ==&mid=2247486250&idx=1&sn=c546be55a02442c50b7f2a7e1b9116d9&chksm=c0dca59af7ab2c8c776e82862e09018067e2f2b4da3971ba8dfb08de110d90d637081b090a75&scene=126&sessionid=1681655086#rd](http://mp.weixin.qq.com/s?__biz=MzkwNzEzMTg3MQ==&mid=2247486250&idx=1&sn=c546be55a02442c50b7f2a7e1b9116d9&chksm=c0dca59af7ab2c8c776e82862e09018067e2f2b4da3971ba8dfb08de110d90d637081b090a75&scene=126&sessionid=1681655086#rd)

起因

## 

故事的开始，是一个老套的任意文件下载漏洞

![](../Images/54770ecbd0c4000c1f208efbbc3d731a.png)

发现这个漏洞，自然要利用起来，读读文件  

![](../Images/39d6400cc988fd0a1f99f390d62073fe.png)

一看这个的dbconn.asp，就是跟数据库连接有关的，于是读取一下：

![](../Images/bc75261e1b7cf10f7f7902305904f7f2.png)

连接密码啥的没直接写，不过略微思考就能想到：不写在这个文件里面，那就是写在了web.config里面了。然而直接读取根目录的web.config并没有，一番寻找之后发现在admin/web.config里面。。。

![](../Images/d9d1606f9575f49d4b97b37e2f148112.png)

可惜不能直接连，扫了下端口发现就开了80。

继续寻找

没办法，读了几个文件发现这个系统参数都做了sql过滤，看了下过滤得还挺细，大概是将关键字像单引号、select啥的直接替换掉，想绕估计得找黑名单之外的关键字进行代替，有些麻烦，暂时先放这。  
扫目录发现了fckeditor：

![](../Images/77b47551e0efda069b300111fbe3140d.png)

  

然而不能用，fckeditor目录下所有asp文件都不能执行。

![](../Images/271fa0efc62dcbc579c092f0e799f90e.png)

这下也没别的办法了，只能找找上传点。  
于是我根据目录扫描的结果继续读取后台的文件：  

![](../Images/98203b34538109a1eb58c474de505486.png)

可以看到这个菜单文件，里面没有直接写出后台各个部分的路径。  
试试直接访问：

![](../Images/d7b134f77fb60ba6570f5f69ba23fb8b.png)

找到源码中对应的部分，发现直接访问也获取不到，估计是没登陆的缘故（后面拿到账户密码证实了这一点）。  

没有办法，扫目录没什么进展，而且直接读文件没有找到上传的地方或者其他可利用的点，卡在这里卡了好一会

峰回路转

经过一番仔细地观察，我发现扫admin子目录的时候，有个report目录，直接访问是403的：

![](../Images/d7b172608d24bff0869c3fd8dce6d2d3.png)

再看上上张图里面的html源代码，正好有个#report超链接。因此，可以大胆的猜测，会有/board、/sys这些与menu.asp这个菜单文件中的菜单同名的目录。  
测试发现确实如此：  

![](../Images/3e93e1b82d062a672ca315bd89dbfbef.png)

因为前台的/board目录有附件，所以后台对应应该有上传，于是去猜测/admin/board/这个目录下的文件，最后找到个news.asp，于是读取一下：

![](../Images/69e7c5eaf9c677f1273ac3f8bdb4121c.png)

根据源码，一路跟踪到news\_edit2.asp这个文件才发现上传表单，但是需要登陆：

![](../Images/c84a374fabd78161ee74a9a9fec7888f.png)

## 终于突破

又迷茫了好一阵。。。  
没办法继续找，常规的思维告诉我们，后台的系统设置什么的可能存在上传，比如上传logo什么的，于是我又跑去猜admin/sys目录下的文件：

![](../Images/10e2a2ca14402b80c22b6a6c63aa4304.png)

好家伙，有个upload.asp（前面居然没扫出来。。。），访问：

![](../Images/701371d439db87534ce19214281cf03d.png)

然而难受的是点击上传之后会跳转到登陆。。。  
就当我以为gg的时候，看了眼burp，发现是上传成功了，然后跳转的：  

![](../Images/16a93ae41175075af9a9ed8972dbafc7.png)

于是开始针对这个上传点，不过直接上传是不行的：  

![](../Images/7a33e39da3a8c2644a0da70417c16b16.png)

没关系，我们可以读源码：

![](../Images/fa38efc1b0be5aa061f4dc9b2f809924.png)

好家伙，后缀控制得很死。  
然而文件名可以钻空子，让我们看看文件名的构成：

  

  

*   

```

```

  

前面三个参数都是我们可控的，这样我们直接进行在前三个参数进行截断就行了：

  

![](../Images/a5b2d2c11d29a851183001dcb2e11fdd.png)

这里我还跳转了一下目录，跳到上面一层去了，因为默认的那个目录，不管访问啥都是403：

![](../Images/47ad5be11a7c21e71587fdd024b7af90.png)

好家伙，终于拿到了shell：  

![](../Images/4ceef8ab241f29af6a609f861d96c3b4.png)
