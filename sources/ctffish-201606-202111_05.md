        原题某大赛的真题，之前培训老师给讲过一次，但是重点讲的是内存取证，后续套路没有展开讲，题给了，索性就从头解了一遍。

例题一 easy\_dump.img

1、拿到镜像先放到diskgenies里进行分区和文件恢复，无果。

![](../Images/99f61bdfb77087d0375f968868225568.png)![](../Images/99f61bdfb77087d0375f968868225568.png)

  

2、在/tmp目录下挂载此镜像，无果。

root@kali:/tmp# mkdir 1

root@kali:/tmp# mount easy\_dump.img ./1

![](../Images/9420bbf7f422b545109909dcc5122955.png)![](../Images/9420bbf7f422b545109909dcc5122955.png)

 使用file命令查看easy\_dump.img显示为data数据文件。

3、使用root@kali:/tmp# volatility -f easy\_dump.img imageinfo分析img文件，通过Suggersted Profile可以看出此镜像为win7SP1x64内存镜像。

![](../Images/ff3cc385c2fd33cc01376bcf5ea54abc.png)![](../Images/ff3cc385c2fd33cc01376bcf5ea54abc.png)

 4、使用volatility -f easy\_dump.img --profile=Win7SP1x64 psscan 查看内存镜像中的进程清单。

![](../Images/941c048b5a2208223db8b7bb98b80502.png)![](../Images/941c048b5a2208223db8b7bb98b80502.png)

发现可疑进程“DumpIt.exe"

5、使用root@kali:/tmp# volatility -f easy\_dump.img --profile Win7SP1x64 memdump -p 2500 -D /tmp 把此进程dump至/tmp目录

![](../Images/03917a8d851d904e2419ffb411444b5a.png)![](../Images/03917a8d851d904e2419ffb411444b5a.png)

6、使用foremost 2500.dmp分离此文件得到一些文件，其中有一个zip压缩文件较为可疑，内部压缩着一个message.img文件（可以用binwalk或file命令前期先对2500.dmp进行分析，确定文件类型）

![](../Images/2314b0b99c7e0c18db140d1963f2d9c9.png)![](../Images/2314b0b99c7e0c18db140d1963f2d9c9.png)

 7、使用root@kali:/tmp/output/zip# file message.img命令分析为：message.img: Linux rev 1.0 ext2 filesystem data, UUID=c12b8ec9-5ef5-4b91-8b4d-f827e81f83cf (large files），一个标准的linux磁盘系统镜像。

![](../Images/89656981d9f4475bdbeffe8364b56037.png)![](../Images/89656981d9f4475bdbeffe8364b56037.png)

 8、创建临时目录，使用mount命令把磁盘镜像挂到当前的test目录里，进入test目录。

![](../Images/071744ddc16a46ab046050b50c0c1f81.png)![](../Images/071744ddc16a46ab046050b50c0c1f81.png)

 9、进入目录后发现hint.txt文件，查看后发现是一组座标值。

![](../Images/1ef23c77de876182b4772a0f581603f1.png)![](../Images/1ef23c77de876182b4772a0f581603f1.png)

 10、把hint.txt放到windows下使用gunplot(已经加入系统变量可以直接在命令行调用）输入plot "hint.txt"得到座标，使用扫码软件得到一提示“Here is the vigenere key: aeolus, but i deleted the encrypted message。”简直是老母猪带胸罩。。。。

![](../Images/fe6db6c19cefc88025b45ef5527296f8.png)![](../Images/fe6db6c19cefc88025b45ef5527296f8.png)

11、根据二维码的提示，使用testdisk对刚才挂载的message.进行数据恢复。

![](../Images/d3f4fde4af84040d97142fe3f37b1c81.png)![](../Images/d3f4fde4af84040d97142fe3f37b1c81.png)

 使用df -h 确定挂载的驱动器名称，再用testdisk调用他。

  testdisk回车键继续（下一步）q键后退，左右箭头键切换上下级目录。

![](../Images/6b956342b497fe7f2339fc1791de589b.png)![](../Images/6b956342b497fe7f2339fc1791de589b.png)

![](../Images/aedb681202661265247f5ced60fca11d.png)

  

 选择list或undelete均可以

![](../Images/7bbac15b8d91da5f9eecfda11bb1c7a6.png)

找到了被删除的文件，字体是红色字体。

![](../Images/19dc00b44c518f32def097c2145709a1.png)

按C键后选择恢复目录，选择/tmp目录后再按C键，显示copy down! 1OK,0 failed.

![](../Images/15e9bff817d3c184440df41984b27495.png)

12、进入tmp目录一开始没找到这个文件，使用了ls -alh才看到，才注意到是隐藏文件，swp是vim的非正常关闭时留下的文件，使用:Vim -r .message.swp 进入恢复模式

![](../Images/941c048b5a2208223db8b7bb98b80502.png)![](../Images/d058e48636e2bcd21c5745b7a54bdb9c.png)

 到此找到了密文：yise!dmsx\_tthv\_arr\_didvi

![](../Images/697055d63212f2a9ef911e4d05fd92a9.png)![](../Images/697055d63212f2a9ef911e4d05fd92a9.png)

 13、配合一开始二维码里找到的提示：维吉尼亚加密和密文得到flag:ayeet!just\_find\_and\_solvea

![](../Images/de0e0e907390f4cf8c17a34b267e6d59.png)
