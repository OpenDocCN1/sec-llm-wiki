# Java用户可能将面临安全威胁

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzI1OTA1MzQzNA==&mid=402851942&idx=1&sn=f8e0d16411a5a605c7ba219ce5708727&chksm=77896a7340fee365b04f70a2e30df9f7db3b063c005f126a36e3b23ef9ce895a81517a26eed3&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzI1OTA1MzQzNA==&mid=402851942&idx=1&sn=f8e0d16411a5a605c7ba219ce5708727&chksm=77896a7340fee365b04f70a2e30df9f7db3b063c005f126a36e3b23ef9ce895a81517a26eed3&scene=27#wechat_redirect)

        最近，Oracle宣布，公司正在计划撤销其对于Java浏览器插件的支持。这一举动无疑为攻击者创造了重新利用已知漏洞的机会。现在的你可以做些什么来减轻这些风险呢？

        我们先来看一看Java是如何被用做攻击媒介的。然后，我们再看看如何转型到其它插件，最后我们就知道现在能做些什么了。

**Java插件被用作攻击媒介的程度？**

        这很难确定，不过我们可以先来简单看一下最新CVE details揭露的大量安全漏洞，还有对“未明确漏洞”的描述。

        这就暗示需要一个明确的修复，有很多组件都需要修复。此外，大部分组件都不需要身份验证，并且都是不复杂的，可以远程控制的。考虑到在这些组件当中还有一些细节和实际的代码漏洞，所以说很难确定可能的公共漏洞有多少。

         另外，想到Oracle最近解决的与联邦通信委员会关于代码后台升级的诉讼案件，禁用旧版浏览器插件可能是Oracle的一种手段，为的就是减少未来可能的法律问题、关闭已经打了补丁的仍然被主动攻击的漏洞。

****开发人员在过渡期会面临的挑战****

        任何完全依赖Java插件的应用程序或是要通过Java才能在浏览器中呈现的供应商都不再可行。我知道很多金融和医疗保健相关的应用程序都是纯Java的，而这些都将不得不去适应其他的替代品。在过渡期，一些专业人士比如放射科医生或是理财规划师，，只要还在用旧式应用程序或浏览器，对于用户和数据来说都有着潜在的风险，解决办法就是换用新版本。

        Java Web Start漏洞的利用和applet类似，所以即使不再支持插件也还会有风险，用户仍旧需要持续更新Java来减少安全漏洞，但是可能解决不了旧版本残留或是EOL浏览器支持。

****Oracle提供的两种选择的利弊——本机安装和反转浏览器控制****

        从技术上来说，二者都是脆弱的，不过浏览器插件可以被网站远程利用，而本机安装就是针对这一点。应用程序的安装或是启用都需要批准。传统意义上，本机应用程序更安全一点，因为它们需要权限来进行安装。

**对于某些行业来说过渡期可能会很长**

        考虑到有数百万的Windows 2003服务器正在使用，除此之外还有像Windows XP的服务器。可能有无数的电脑为了维持业务的正常运行还在使用易受攻击的旧版本Java。由于要遵从法规以及缺乏浏览器插件支持，最快转型的可能是卫生保健系统和金融机构。而其他行业将可能落后很多年。  

****现在能做什么？****

**实施一个可行计划，来减轻旧版本Java威胁，并且明确出正在使用Java浏览器插件的应用程序：**

1、用Retina或是Retina CS来识别整个企业网络中易受攻击的版本，通过更新到最新版本来进行补救。

2、利用PowerBroker for Windows来区分正在使用Java插件的应用程序。

3、联系您的供应商，并要求他们提供更新应用的时间表：

（1）消除对Java插件的依赖；

（2）验证其支持的最新版本Java可以消除已知风险；

（3）确定其在将来缓存和完整安装程序的路径通过Web Start。
