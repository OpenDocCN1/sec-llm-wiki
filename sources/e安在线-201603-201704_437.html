第一节 生命周期简介

在百度百科中，对生命周期是这样描述：生命周期就是指一个对象的生老病死。相应的，我们应用的生命周期就是为：

Active：处于屏幕前景（当前task的栈顶Activity处于Active状态），同一时刻只能有一个Activity处于Active状态；

Paused状态：处于背景画面画面状态，失去了焦点，但依然是活动状态；

stopped：不可见，但依然保持所有的状态和内存信息。

最后可以调用finish()结束处理Paused或者stopped状态的Activity。

活动状态（Active）

老是一种动态的过程。在这个状态下，应用处于手机当前屏幕。同时，也只有一个应用处于活动状态。但在Android M中有黑科技，新特性。支持双Activity处于Active状态。但当前M的市场才过3%（2016年3月24日）。

它有三个方法：一个是onStart，onRestart以及onResume。而这三个方法不同的是：

  • 当Activity处于可见状态的时候就会调用onStart方法。

  • 当Activity可以得到用户焦点的时候就会调用onResume方法。

  • 当Activity没有被销毁的时候重新调用这个Activity就会调用onRestart方法

第三节 设备旋转与Android生命周期

3.1 问题产生的原因

旋转设备会改变设备配置。而设备配置是用来描述设备当前状态的一系列特征。这些特征有且不仅有：屏幕方向、屏幕密度、屏幕的吃寸、键盘类型等等。

可能你会说，哇这么麻烦，这么多的手机/平板厂家，要适配多难啊？还不如学IOS得了。是的，在Android开发中，业务处理有时所花费的时间会远低于处理不同设备样式处理时间。但也想想，你有苹果套件么？没有的话就安心跟着学吧。有的话还是真心推荐学习苹果开发。若有机会，也会出个IOS开发系列的教程。

3.3 设备旋转前保存数据

在3.2中，适时的使用备选资源虽然是比较完善的解决方案，但是设备的旋转带来的销毁与新建也同时带来麻烦。原先旧的数据会丢失等。

要修正这个问题，需要在旋转导致销毁前，要将mCurrentIndex通知到新的Activity中。Android中的onSaveInstanceState(Bundle outState)是比较好的解决方案。而这个方法通常是在onStop、onPause及onDestroy方法调用前由系统调用。

方法onSaveInstanceState(...)默认的实现要求所有的activity的视图将自身状态数据保留在Bundle对象中。Bundle对象是存储字符串键与限定类型值之间映射关系（键-值）的一种结构。接下来可通过覆盖（@Override）onSaveInstanceState(Bundle outState)方法，将一些数据保存在Bundle中，然后在onCreate(...)方法中取回这些数据。在设备旋转中，将使用这种方式保留mCurrentIndex值。

首先创建键

代码清单8 添加键值对的键

public class QuizActivity extends AppCompatActivity {    
private static final String TAG ="QuizActivity";    
private static final String KEY_INDEX ="index";
...
}

其次覆盖onSaveInstanceState(Bundle outState)方法

代码清单9 覆盖onSaveInstanceState(Bundle outState)方法

@Override

public void onSaveInstanceState(Bundle savedInstanceState){  

super.onSaveInstanceState(savedInstanceState);    
Log.i(TAG,"onSaveInstanceState");    
savedInstanceState.putInt(KEY_INDEX,mCurrentIndex);
}

最后，在onCreate方法查看是否获得该值。

代码清单10 在onCreate(...)方法中检查存储的bundle信息

if (savedInstanceState!=null){

}
