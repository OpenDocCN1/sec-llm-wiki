第一节 XML如何转换为视图

在创建安卓项目时，会在src文件夹中创建一个名为QuizActivity的Activity子类。目录src是Java源代码的存放处。

此Java文件包括三个方法：onCreate(Bundle),onCreateOptionsMenu(Menu)以及onOptionsItemSelected(MenuItem)。其中onCreateOptionsMenu(Menu)以及onOptionsItemSelected(MenuItem)暂时不用去理会，后续章节将详细说明作用及使用范围。

在activity子类创建后，onCreate(Bundle)方法就会被调用。同时要获取并管理自己的用户界面，可用onCreate(Bundle)中的setContentView(int layoutResID)方法。通过方法，传入布局的资源ID，此方法将生成指定布局的视图并将其放置在屏幕上。布局视图生成后，布局文件包含的组件也随之以各自的属性定义完成实例化。

我们可以通俗的理解，创建一个新的Activity子类时，可以通过setContentView(int layoutResID)方法中将根据所传的资源ID生成布局。那疑问来了，资源ID是啥玩意？

第二节 资源与资源ID 

可以确定一点，通过资源ID确定资源。而布局也是资源的一种。所谓资源是指在项目中以非代码存在的内容，如图像、音频及XML文件等。项目中所有的资源文件都是存放在res的子目录中。

4.2 资源存放路径.png

布局的XML文件activity_quiz.xml则是存放在res/layout/下。字符串资源则是放在res/values/下。

各个文件夹与资源作用如下：

1.drawable-hdpi系列文件夹

此系列文件是用于保存不同像素的图片资源。

(1)drawable-hdpi里面存放高分辨率的图片,如WVGA(480x800),FWVGA (480x854)

(2)drawable-mdpi里面存放中等分辨率的图片,如HVGA (320x480)

(3)drawable-ldpi里面存放低分辨率的图片,如QVGA (240x320)

(4)drawable-xhdpi：至少960*720

         系统会根据机器的分辨率来分别到这几个文件夹里面去找对应的图片。

将同一张图片的高分辨率版本放到hdpi目录下，中分辨率版本放到mdpi目录下，低分辨率版本放到ldpi目录下，系统会根据手机屏幕的密度自动加载不同目录下的图片，但是如果在对应的drawable目录下没有找到对应的图片怎么办？

答案是会从其他的文件夹中找，例如ldpi的手机屏幕在ldpi文件夹中没有找到某张图片，在hdpi中找到了这张图片，但是系统会认为它原本是给hdpi的屏幕用的，所以在使用前会进行缩小处理，所以我们在平时要注意，明明都是一张图片，只是放在不同的文件夹中，显示出来的效果就很不同。

2.layout文件夹

存放所有的布局文件，例如在第一节中方法setContentView(int layoutResID)读取相应的布局ID后，对用户页面进行布局。

3.menu文件夹

拿起身旁的Android，随意打开个应用。点击手机上的Menu按钮，是不是有菜单出来？menu文件夹就是存放相应菜单的布局文件。而且是通过方法onCreateOptionsMenu(menu)进行创建菜单。以后章节将详细介绍。

4.values文件夹

可以被编译成很多种类型的资源的XML文件。注意: 不像其他的res/文件夹，它可以保存任意数量的文件，这些文件保存了要创建资源的描述，而不是资源本身。XML元素类型控制这些资源应该放在R类的什么地方。

5.values-v11与valuse-v14文件夹

values-v11代表在API 11+的设备上，用该目录下的styles.xml代res/values/styles.xml。而values-v14代表在API 14+的设备上，用该目录下的styles.xml代替res/values/styles.xml。其中API 11+代表android 3.0 +，API 14+代表android 4.0 +。

6.AndroidManifest.xml

在应用执行时，必须要用到这个XML。它最重要的作用是描述程序中哪些组件是在应用执行时存在的，同时对程序的各种配置进行管理。像.NET的web.config文件。


在包浏览器中打开gen目录，找开R.java文件，可看到应用所有的资源ID。R.java文件在Android编译过程中自动生成。请勿修改！

在应用启动时，程序获取到这两个Button资源ID。那接下来如果用户有点击按钮，程序该如何进行判断与执行？

Android应用属于典型的事件驱动型。与命令行或脚本程序不同，事件驱动应用启动后，就开始等待行为事件的发生，例如用户点击按钮或后退操作。应用等待某个特定的事件发生，也可以说该应用正在监听特定事件。为响应某个事件而创建的对象叫监听器（listener）。监听器是实现特定监听接口的对象，用来监听某类事件的发生。

在Android SDK中就集成了很多监听器接口。当前需求要对按钮的单击事件进行监听，需要实现View.OnClickListener接口。接下来先处理True按钮监听事件。请在QuizActivity.java中，在onCreate(Bundle)方法的变量赋值语句中输入如下代码：
代码清单4-6 为True按钮设置监听器

@Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_quiz);
        mTrueButton = (Button)findViewById(R.id.true_button);
        mTrueButton.setOnClickListener(new View.OnClickListener() {
 
            @Override
            public void onClick(View v) {
                //Does nothing yet,but soon!
 
            }
        });
}V

在上面的代码中，我们设置了一个监听器。当mTrueButton被点击后，监听器会立该通知我们。setOnClickListener(OnclickListener)方法以监听器作为参数被调用。具体来说，该方法以一个实现了OnClickListener接口的对象作为参数被调用。

使用匿名内部类

传入setOnClickListener(OnclickListener)方法的监听器参数是一个匿名内部类实现，语法看上去可能会复杂，然而只要记得最外层括号内的全部实现代码是作为整体参数传入setOnClickListener(OnclickListener)方法内即可。该传入的参数是新建一个匿名内部类的实现代码。

以后章节所有的监听器都作为匿名内部类来实现。有两个好处，第一，因为匿名内部类的使用，我们可在同一处实现监听器方法，代码清晰可读；第二，事件监听器一般只在一处使用一次，使用内部类可避免不必要的命名类实现。

匿名内部类实现了OnClickListener接口，因此他也必须实现该接口的唯一方法：onClick(View)。实现监听器需求实现onClick(View)，具体是如何实现，则是要看具体的业务需求所定。

创建提示信息

接下来要实现的是分别点击两个按钮，弹出我们称为toast的提示消息（类似页面的弹出框）。Android的toast用来通知用户的简短弹出消息。但无需用户的输入或操作。这里我们就是用toast用来通知用户选择的答案正确与否。

首先到res/values/string.xml文件,为toast添加消息显示用的字符串。

  <string name="correct_toast">Correct!</string>
  <string name="incorrect_toast">Incorrect!</string>

通过调用如下方法可创建一个toast:

public static Toast makeText(Context context,int resId,int duration)

该方法的Context参数通常是Activity的一个实例。第二个参数是toast提示信息的字符串资源ID。Toast类必须通过context才能找到并使用字符串资源ID。第三个参数通常是两个Toast常量中的一个，用来指定toast持续显示的时间。
代码清单4-7 创建提示消息（QuizActivity.java）
