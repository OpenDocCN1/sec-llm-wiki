# 干货丨传统网络方案的八大硬伤及对策

导读：网络运维过程中难免遇到种种难题，网络工程师们屡次遭遇屡次奋力应对，总思考如何才能提升故障解决的效率，却忽视了很多子问题的产生是源于传统网络方案本身的局限性。

  

**八大硬伤  
**

  

**1.硬件多，人力投入多**

传统网络在多AP场景下需要AC统一管理；多分支企业甚至每个站点都需要AC，每台设备需要WEB网管，总部还得需要网管、认证服务器等。硬件数量多，软件平台多，运维有苦说不出。

  

**2.线下设备不互联，分管效率低**

传统网络每个AC仅能呈现其下挂AP的状态和业务信息，在面对多分支站点场景时，运维人员还得逐一登录AC，逐一管理，非常繁琐。

硬件设备诸如交换机，防火墙，路由器等，更是台台都要独立管控，IT工程师每天就在若干个设备和各自的网管系统间辗转，耗时耗力。

  

**3.多分支企业管理难**

对于多分支的企业，传统网络不仅设备数量多，而且在每个分支分布，非常零散。

IT工程师在收到网络异常信息后，往往需要亲赴故障分支点，先判断故障设备，再逐台处理，差旅成本高，故障恢复慢，人也辛苦。

  

**4.故障排查难，可回溯性低**

无线用户具有不固定性的特点，其上网体验容易受到所在区域无线信号覆盖强度、无线干扰等因素的影响，无法接入网络、上网速度慢、经常掉线等问题，都是运维人员经常遇到的用户报障。

但传统网络只能呈现当前情况，无法反映过去时段用户接入的具体设备和时间点，故障可回溯性差，工程师往往很难精确判断出具体问题设备和故障原因。

  

**5.传统命令行运维难度高、易出错**

传统网络的设备很多采用命令行方式提供运维能力，运维工程师需要掌握每个型号设备的命令行，操作时更是要逐台登录操作。

技术难度高，效率低下，而且还容易出错。

  

**6.设备升级耗时长、效率低**

传统网络的设备升级需要逐个操作，对于运维工程师来说最痛苦的事情莫过于熬夜给设备升级版本，夜里在冰凉的机房的感觉也许只有运维工程师自己能懂。

  

**7.数据全靠本地收集**

传统网络的设备提供的报表统计功能有限，且由于每个设备的网管功能和数据统计功能独立，即使某个设备支持数据分析，企业也没有办法将所有设备的数据融合拉通，这样的数据分析没有太大价值。（比如，一个空间内多台AP分别统计了一天的接入终端数量，由于无法知悉其中多少是同一用户，所以并不能推算出当日该空间的访客数量）老板要起统计数据时，还得自己逐台收集，本地汇总分析，十分麻烦。

  

**8.应用拓展能力弱**

传统方案基于本地管理，基本无法实现应用的拓展，基于当下媒体形态的变革巨大，企业不免对应用拓展有诉求，期待通过无线网络内置部分功能构建企业的用户画像、品牌宣传、商业合作等，而这恰巧是传统方案无法企及的。

  

**一个对策  
**

  

传统网络的硬伤是运维效率的致命伤，不仅加重运维人员负担，还使管理成本居高不下，然而随着SDN技术、云化技术、NetConf协议、Yang模型和Restful接口的快速成熟，公有云基础能力的不断提升，AI和大数据技术的应用，全网络的云化管理已成为现实，网络管理势必迎来由传统到云端的完全转型。

云化管理也将完美解决传统方案的八大硬伤：

  

**1、针对硬件过量和人力负担：**

**实现极简网络、集中管理**

网络管理云化后架构极简，设备即插即用，在连接到云管理网络平台 （以下简称：云平台）后，便可通过web浏览器和移动端APP实现云端运维。不管设备类型，数量，位置如何，都可以实现集中纳管，这极大地整合了WLAN AC、网管和认证服务器的能力，大大减少了实际物理设备的部署，也减轻了运维人员的负担。

![](../Images/9bff03f8228e126ad5d5a8a956151d3e.png)

  

**2、针对硬件不互联：**

**实现一站式网络监控**

云平台跟分支站点中的每个设备建立了http2.0通道，设备的性能数据将通过http2.0通道上报至云平台做统一呈现，完美实现硬件互联，一个平台即可洞悉所有网络运行、业务运营情况，实现随时随地全设备的云端监控。整个网络的站点状态、设备状态以及终端连接数信息实时监控：

![](../Images/5a4be6be46799c794798221a1235a151.png)![](../Images/1d7aea37ca81ed9ce7166b7fee2da49a.png)![](../Images/2942ebca281d3f96a4a563bd8c137b9d.png)

集成GIS地图还可呈现站点的位置分布，实现设备定位，便于在云端掌控各地各站点：  

![](../Images/c457e26edad1328b2539be0f73b856f8.png)

  

**3、针对多分支企业：**

**实现云端排障，一键智能优化**

云平台上的站点与企业分支实现一一对应，出现问题/告警的马上就能定位站点，选中站点就可实现从全局管理者到站点运维者的视角切换，在云端实现监控运维，不再需要奔赴现场逐台处理。

云平台实时反馈的多样数据可以满足工程师各种不同的运维需求。

设备的版本、MAC、注册离线时间、端口状态以及SSID状态：

设备的CPU、内存，流量和在线用户等信息：

![](../Images/09b67d61e9354d478fc6b4403434c888.png)

  

**4、针对故障回溯困难：**

**利用大数据分析，实现故障随时回溯**

云平台集成的FI大数据系统，可详细记录终端网络体验全过程。如下，运维工程师获取报障用户的终端MAC地址后即可从云平台搜索到该终端，进而了解到该终端当前的网络体验。

![](../Images/b724fb6ee02959ec73c9f9fd65862a8c.png)

点击该终端，运维人员可审阅该终端24h内的时延、丢包率，重传率以及RSSI等信息，运维人员根据上述信息找到终端体验故障点（时间点和连接设备），进而对设备进行诊断修复，将问题解决。

![](../Images/1218aa9007a2d69bcb4e87064474d842.png)

  

**5、针对命令行运维：**

**利用多种可视化工具,免除命令行烦恼**

云平台上丰富的web化诊断工具，可以避免专业的命令行式诊断，直观呈现各维度的数据，同时保留命令行方式，双管齐下使得运维效率大大提升。

云平台还实现了MSP代维能力，企业赋予代维的账号权限， MSP便可协助企业远程运维，彻底实现管理减负。

  

**6、针对网络升级：**

**云端自动升级，不用再熬夜伤身**

因为网络管理已经云化，升级设备好比更新软件，不需上传版本，也不用现场保障，在办公室登录平台设置夜间升级就可以自动更新。

  

**7、针对数据统计：**

**报表统计，展现运维工程师的价值**

云平台纳管了所有设备，智能数据统计和分析，为企业提供丰富的运营报表功能。

比如在业务层面，可呈现站点下接入用户数、网络速率、TOP N 终端、TOP N SSID、TOPN AP、应用分类、应用流量以及攻击检测等信息，这些数据都可以作为用户行为分析的来源，让运维者轻松掌握该站点下业务的运营运行情况。

**优势总结**

传统方案正在承受着云化方案的强烈冲击，网络管理的云化转型必将成为行业的趋势所在，最后总结一下传统网络八大硬伤在云化后的成功解决：

1、简化的网络架构，给企业降低成本和运维难度；

2、强大的云监控能力，让IT工程师随时随地掌握网络情况；

3、集中式云端分析和排障能力，把排障从现场搬到云端，大幅提升排障效率，给运维工程师减负；

4、终端级大数据分析能力，以往用户报障无法复现的老大难问题，如今变得轻松简单；

5、为工程师提供各种丰富易用的云端运维工具，革命性改变以往命令行式的传统运维模式；

6、全站点自动化升级能力，云端预约，自动升级，告别过去的夜间人工升级；

7、集中式的报表统计功能，协助运维和运营，更是直观体现运维人的价值；

8、丰富的OpenAPI，满足各类定制化开发需求。
