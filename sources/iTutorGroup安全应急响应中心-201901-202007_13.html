一.前言

url跳转漏洞是个很常见的漏洞，OWASTOP_TOP10对其定义为应用程序经常将用户重定向到其他网页，或以类似的方式进行内部转发。有时，目标网页是通过一个未经验证的参数来指定的，这就允许攻击者选择目标页面。这种重定向可能试图安装恶意软件或者诱使受害者泄露密码或其他敏感信息。不安全的跳转可能允许绕过访问控制。本文讲一下日常工作中url跳转漏洞的绕过与修复。


二.url跳转漏洞的产生

url跳转漏洞是十分常见的漏洞，当Web应用程序接受不受信任的输入时，可能导致未经验证的重定向和转发，这可能导致Web应用程序将请求重定向到包含在不受信任的输入中的url。通过修改对恶意站点的不可信url输入，攻击者可以成功启动网络钓鱼诈骗并窃取用户凭据。

用户登录、统一身份认证处，用户分享、收藏内容及评论过后，内容提交后，等等场景

而在Web开发中，如果不对前台传入url进行校验的话，就会产生url跳转漏洞。以下是几种常见框架中url跳转代码的实现。

# java
public class ForwardServlet extends HttpServlet 
{
  protected void doGet(HttpServletRequest request, HttpServletResponse response)
                    throws ServletException, IOException {
    String query = request.getQueryString();
    if (query.contains("fwd"))
    {
      String fwd = request.getParameter("fwd");
      try 
      {
        request.getRequestDispatcher(fwd).forward(request, response);
      }
      catch (ServletException e)
      {
        e.printStackTrace();
      }
    }
  }
}

三.常见绕过方法总结

假设要跳转的域名为www.itutorgroup.com ，攻击者需要跳转到evil.com

3.1 直接跳转

没有对url做任何限制，直接可以跳转

http://www.xxx.com/?url=http://www.evil.com

3.2 域名字符串欺骗

3.2.1 漏洞修复绕过场景一

开发人员修复url跳转漏洞会判断域名是否包含在字符中，是子字符串里就会验证通过,比如这一段java代码：只验证跳转url包含itutorgroup.com 这样的字符串。

public static void checkUrl(String url) {
    String domain = "itutorgroup.com";
    int result = url.indexOf(domain);
    if(result != -1){
        System.out.println("url is ok");
    }else{
        System.out.println("url is illegal");
    }

攻击者可以这样构造链接
http://www.xxx.com/?url=http://www.itutorgroup.comevil.com
只需要去买一个comevil.com的域名就可以绕过这样的检测，当然类似的代码还有正则不严谨的，比如http://([\w-]+\.)+[www.itutorgroup.com]+(/]*)?

3.2.2 漏洞修复绕过场景二

开发人员会检测域名结尾是不是当前域名，是的话才会跳转，Django示例代码如下：

  redirect_url = request.GET.get("url")
  if redirect_url.endswith('itutorgroup.com'):
      HttpResponseRedirect(redirect_url)
  else:
      HttpResponseRedirect("https://www.writedomain.com")

攻击者构造链接
http://www.xxx.com/?url=http://www.evil.com/www.itutorgroup.com
或者买个xxxitutorgroup.com域名，然后绕过:
http://www.xxx.com/?url=http://www.xxxitutorgroup.com

3.3 可信站点绕过

这里以百度为例子说明，

http://www.baidu.com/link?url=1yWvB9QgjSARX_W9u8A8KDs_2iKalASVl3OWyh7k5E8SG60HjsOM60LYacWQzsrA&wd=&eqid=d2bc241b00006556000000055dd385be百度搜索都会存在url=这样的重定向地址，如果碰到url跳转仅信任baidu.com域名，就可以采取这样的方法

3.4.2 \\\\协议混淆等

在测试中通过一些不正确的协议：

http://www.xx.com/?url=http:////auth.xxx.com ，

http://www.xx.com/?url=http://auth\.xxx.com

这些不提供正确的协议以\ // 符号混淆后，有的应用程序依然正确的解析了domain并重定向，有的应用则会出现错误信息，由于使用不同框架和中间件的特性导致。

3.4.3 特殊字符截断

java中对url跳转的修复是校验传入的跳转url参数值，判断是否为预期域名。

String url = request.getParameter("returnUrl");String host = "";try {
    host = new URL(url).getHost();
} catch (MalformedURLException e) {
    e.printStackTrace();
}if host.endsWith(".bbb.com"){
          //跳转}
else{    //不跳转，报错}

反斜杠会被代码认为是将要跳转即returnUrl=http://www.aaa.com\www.bbb.com跳转到bbb.com，而实际在浏览器中反斜线被纠正为正斜线(\——>/)，跳转到www.aaa.com/www.bbb.com，最终还是跳到www.aaa.com的服务器，ChangeS在FreeBuf的文章（见参考文章链接）中测试到不同的JDK版本下getHost()方法的结果在不同JDK版本中对#号的处理结果不同，通常#号被用作页面锚点，对于https://www.aaa.com#www.bbb.com?x=123这个url，较高版本的JDK中，取出结果为www.aaa.com，低版本中为www.aaa.com#www.bbb.com，从而低版本又可绕过endsWith(“.bbb.com”)方法，成功跳转。即低版本的getHost()方法会被’#’ ‘\’ 截断从而读取后面的域名导致绕过。 经测试JDK1.8.0_221对'\'可以绕过，'#'不可以绕过。JDK1.6.0_45'\'和'#'都可以绕过.测试代码和验证图片如下:

#java
public class Main {

    public static void main(String[] args) {
        String url = "https://www.aaa.com\\www.bbb.com?x=123";
        String host = "";
        try {
            host = new URL(url).getHost();
        } catch (MalformedURLException e) {
            e.printStackTrace();
        }
        System.out.println("host---"+host);
        System.out.println("url---"+url);
    }
}

四.总结与修复

url跳转漏洞的修复不仅仅是修复一个点，而是需要结合很多层面来修复，安全域以及正确的跳转

  • 在可能的情况下，让用户提供短名称，ID或令牌，这些短名称，ID或令牌将在服务器端映射到完整的目标url。这样可提供最高级别的保护，以防止篡改url。

  • 如果无法避免用户输入，请确保提供的值有效，适合于应用程序并且已授权给用户。

  • 通过创建url白名单列表（主机列表或正则表达式列表）来清理输入。

  • 强制所有重定向首先进入一个页面，通知用户他们正离开网站，并清楚显示了目的地，然后让他们单击链接进行确认。
