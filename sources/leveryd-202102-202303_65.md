# 背景

本实验主要为了验证pf\_ring.ko^(\[1\])内核模块是否能够提升抓包率。

实验思路很多参考自 PF\_RING与NAPI结合的捕包性能优化和仿真.pdf^(\[2\])

通过分析源码得知：

*   pf\_ring.ko未加载到内核时，libpcap^(\[3\]) 会使用PCAP\_MMAP方式来抓包
*   pf\_ring.ko加载到内核时，libpcap^(\[4\]) 会通过libpfring^(\[5\])配合pf\_ring.ko内核模块来抓包
*   pf\_ring基本没有对 tcpdump^(\[6\]) 做改动

实验思路：

*   使用pf\_ring项目中的tcpdump抓包，计算抓包率
*   使用pktgen发包
*   在"加载pf\_ring.ko"和"不加载pf\_ring.ko"两种场景下分别测试三次

实验环境：

| 机器用途 || 配置 || 操作系统 || 备注 |
| --- | --- | --- | --- |
| 发包机 || 2核4G、pps 40w || CentOS 7.5 || 云虚机 |
| --- | --- | --- | --- |
| 收包机 || 2核4G、pps 40w || CentOS 7.5 || 云虚机 |

# 过程

## 准备测试环境

*   收包机器编译安装tcpdump
    
    安装依赖
    
    ```
    
    yum install flex bison kernel-headers kernel-devel gcc stress -y
    ```
    
    依次编译pf\_ring.ko^(\[7\])、libpfring^(\[8\])、libpcap^(\[9\])、tcpdump^(\[10\])
    
*   发包机器编写发包脚本
    
    此bash脚本配置来自网络
    
    ```
    # 定义一个工具函数，方便后面配置各种测试选项
    function pgset
    () {local
     result# 定义一个工具函数，方便后面配置各种测试选项
    echo $1 > $PGDEV
    
    $PGDEV | fgrep "Result: OK:"
    `if [ "$result" = "" ]; then
    $PGDEV
     | fgrep Result:fi
    
    # 为0号线程绑定eth0网卡
    
    "rem_device_all"   # 清空网卡绑定
    "add_device eth0"  # 添加eth0网卡
    
    # 配置eth0网卡的测试选项
    
    "count 2000"    # 总发包数量
    "delay 0"       # 不同包之间的发送延迟(单位纳秒)
    "clone_skb 0"      # SKB包复制
    "pkt_size 64"      # 网络包大小
    "dst 172.16.32.12" # 目的IP
    "dst_mac fa:28:00:06:df:6c"  # 目的MAC
    
    # 启动测试
    
    "start"
    
    ```
    
    modprobe pktgen
    
*   人为调高收包机cpu利用率
    
    为什么要调高呢？因为实验过程中发现，如果不调高，即使收包机pps达到最大值40w，机器cpu仍然很低、tcpdump不会丢包，这样就看不出来效果。
    
    怎么调高cpu利用率？可以使用 `stress -c 2` 命令 故意占用cpu。
    

## 观察测试数据

*   发包为`pgset "pkt_size 64"`时，收包机的收包率
    
    ```

    # ./tcpdump  'src host 172.16.32.25' -w a.pcap
    ```

    可以看到上面收包机tcpdump的数据：

# 结论

*   pf\_ring版本的tcpdump抓包率更高
