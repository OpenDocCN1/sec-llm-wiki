# 0x03 尝试注入数据

取数据的时候，是需要用到函数的，但是这里又有一个问题，无论输入什么函数，只要有`()`的，都会connection reset

![](../Images/76055137d63c0119657ab08c9d298948.png)

第一反应可能是拦截了关键字，比如一些`if()`、`ascii()`、`substring()`这种的，都会拦截，所以我直接掏出来了mysql函数进行fuzz，发现没有一个不拦截的

![](../Images/884323c4376de57443007f0cae76af39.png)

感觉不是拦截关键词的原因，可能是waf的特征了 这里我尝试了很多方法，内联注释、`%0a`一些字符的换行，注释符等等发现都不行

`/*!if*/()`、`if/**/()`、`if%0a()`……

后面也是用注释符乱试，发现了一个语句竟然可以成功`'&&if(/**/1=1,/**/1, current_user)='1'||'`

![](../Images/81a2c7ef293a2fa2f3861251b7a9f4a2.png)

解释下这里第二个的表达式为什么是`current_user`

一般来说，我们会使用`if(1=1,1,0)`来进行注入数据的 但是这里是不行的

![](../Images/67d1948d2a085a4ec5f166abd2d7d595.png)

直接reset了

本地尝试下还有哪些参数可以用的

![](../Images/3c0243a816ede1c0cb0591434d382112.png)![](../Images/f20e864b55c2b15811c7e69bd7fa9bf4.png)

本地来看，也就是存在有效参数就可以执行语句

实际环境中，是不行的

用id、甚至是sql语句里的字段直接都是reset

![](../Images/28034e499ac50944aae474b2094ddcc3.png)![](../Images/0a62552a0beafc0fae23c04d0bd78fb8.png)
