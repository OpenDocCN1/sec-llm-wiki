0x01什么是SSP

SSP是英文 SecuritySupportProvider的缩写，它实际上是一个DLL，当系统进行安全认证的时候，会调用当前已注册并激活的SSP，类似于 Linux中的 pam_unix.so，它的调用链如下图所示，应用产生的认证请求会由 SSPI进行分发

通过引入 Security.h头文件，调用 EnumerateSecurityPackagesA可以获取当前系统已经注册的 SSP

  1. #define SECURITY_WIN32
  2. #include <windows.h>
  3. #include <Security.h>
  4. #include <stdio.h>

  6. int main() {
  7.        unsigned long pcPackages = 0;
  8.        PSecPkgInfoA pSecPkgInfoA;
  9.        EnumerateSecurityPackagesA(&pcPackages, &pSecPkgInfoA);
  10.        for (int i = 0; i < pcPackages; i++) {
  11.               printf("Name: %s\n", pSecPkgInfoA[i].Name);
  12.        }
  13. }

0x02 SpAcceptCredentials

实现一个 SSP需要实现一系列的回调函数，其中核心的回调函数是 SpAcceptCredentials，每当产生认证的时候，都会调用该函数进行凭证的存储，因此理论上只需要在该方法中增加一个记录用户密码的操作，即可实现认证的劫持但是如果定义一个新的 SSP，需要我们修改注册表 HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\Lsa\SecurityPackages的同时重启电脑，这导致了在实际的渗透过程中利用非常不方便

0x03 memssp

如果我们没有办法定义一个新的 SSP，那我们是不是可以patch现有的 SSP？答案当然是可以的， mimikatz中的 memssp就是这样做的，让我们跟进代码进行分析

首先是获取 lsass.exe的句柄，然后找到它所加载的 msv1_0.dll的 DllBase根据 MSV1_0AcceptReferences中的特征，我们去 msv1_0.dll中搜索，可以看到对应的函数正是 SpAcceptCredentials

由于搜索到的地址不是函数起始地址，因此需要-16，得到起始地址后，我们插入了一条 JMP指令新分配的 内存1后面

然后在新分配的 内存1的末尾插入一条 JMP 指令

随后分配新的 内存2，并将前面插入的 JMP指令的地址改为原始函数的实际调用

最后将劫持的函数写到 内存2中，然后将 内存1的首地址指向了 内存2，最后覆写内存，让 SpAcceptCredentials指向了内存1
