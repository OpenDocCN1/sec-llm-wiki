01
前言



drozer确实是一个很不错的Android安全渗透测试框架，但为什么要分析drozer的源码呢？

在大量的移动应用需要安全评估的场景下，单靠人力完成是很困难的，这种场景下安全评估工程化就显得很需要了，而安全评估工程化离不开安全工具的支撑。在构建我们自己的安全工具的时候，一般都会借鉴或引入已有开源能力或解决方案，这里，我们就简单聊聊，drozer的那些值得我们借鉴或引入的优秀思路和功能。




02
drozer简介




Drozer 是一款开源的适用于Android安全渗透测试框架，分为安装在PC端的控制台、安装在移动终端的agent APP两部分，通过PC端的控制台，您可以与Dalvik VM、其它移动应用程序及操作系统进行交互。

  

 drozer具备如下特点：


（1）便捷式Android安全评估：

可以发现并与Android应用程序暴露的攻击面进行交互，在Android设备上执行动态Java代码，从而无需编译和安装小型测试脚本。

（2）对真实的Android设备进行测试：

drozer既可以在Android模拟器中运行，也可以在真实设备上运行。它不需要启用USB调试或其他开发功能。

（3） 自动化和扩展：

drozer提供自定义执行模块功能，可以根据您的需求，按照官方文档的api说明，自行编写满足您的需求执行模块，以便发现、检测和利用移动应用中的安全风险或者自动化的排查安全风险。


   （4）测试或利用漏洞：

drozer提供了许多公共Android漏洞利用的即点即用实现。您可以使用它们来识别组织中的易受攻击的设备，并了解它们带来的风险。



03
整体的架构介绍




drozer整体的实现思路可以总结为：其完美的利用java的反射机制，使用C/S 架构，可以通过在PC端使用 python 来编辑 java 代码，并通过protobuf协议将其传输至移动端的agent，最终移动端agent通过java反射机制动态执行java代码。同时使用了python动态加载技术importlib，实现插件化的执行脚本框架，使得执行脚本可以互不干扰，相互独立，且可以任意增加或卸载。

源码分析




这里将drozer核心能力归纳为三大核心模块：通信模块、java反射模块和插件化模块，本文也是重点分析这三大核心模块的实现思路及方式。


1、通信模块分析

drozer由两部分组成，一是PC端的控制台、二是移动终端agent。这两者间的通信通道有两种方式建立如图1-2，本文主要是分析PC端的控制台 connect to 移动终端agent这种方式，即PC端控制台向移动终端Agent发送请求，移动终端Agent接收请求，并处理消息，最终返回执行结果至PC端控制台。


1-2

两者间通信，为了能在信息收发的时候快速无误的解析其内容的含义，一般都会提前约定好一种数据存储格式。drozer在众多的数据存储格式中，采用了Protocol Buffers协议（简称Protobuf）。Protobuf是Google出品的序列化框架，是一种轻便高效的结构化数据存储格式，可以用于结构化数据串行化，或者说序列化。它很适合做数据存储或 RPC 数据交换格式。可用于通讯协议、数据存储等领域的语言无关、平台无关、可扩展的序列化结构数据格式。

科普一下两个概念



序列化：将数据结构或对象转换成二进制串的过程。

反序列化：将在序列化过程中所生成的二进制串转换成数据结构或者对象的过程。

进入正题，我们从drozer conosle connect 命令执行，开始跟踪分析PC端与Agent端的通信逻辑。

drozer运行的起点，在bin目录下的drozer文件，我们安装drozer的时候该文件会被释放到python安装目录的script目录下。这就是为什么我们能在cmd命令下直接敲入drozer就可以使用该工具。

该文件逻辑很简单，就是通过python的动态import加载python模块，根据cmd命令行的参数，加载工程下指定的python模块代码。从代码可以得知drozer.cli 目录即是所有命令的入口。


drozer


drozer.cli.console.py


在drozer.cli.console.py中可以得知conosle命令实现代码在drozer.console.console.py的Console类，命令行中的第二个参数往后都是属于Console类的参数。Console().run() 方法是用来根据命令行的参数，定位为具体方法并执行它。这里就很巧妙使用了python的getattr()做了一个反射机制，阅读完整个代码，需要动态调用方法的结构里面都采用了该方式。



connect参数就是执行console.do_connect()，该方法主要做了如下三件事

1、建立连接

device = self.__get_device(arguments) 获取Agent的id，可以理解为用来生成session_id

server = self.__getServerConnector(arguments) 建立一个socket连接

2、创建session

response = server.startSession(device, password)

3、初始化插件模块并等待输入待执行命令

session = Session(server, session_id, arguments)

session.cmdloop()

跟进 self.__getServerConnector()可以看到整个通信连接是怎么建立和维护的，该方法是返回一个ServerConnector 对象，ServerConnector 就是PC端控制台和Agent之间的连接，负责连接的建立和收发消息。其代码在drozer.connector.server_connector.py



ServerConnector 类继承了pydiesel.api.transport.SocketTransport 类，socket的建立、管理、消息收发都在这个类里面。



噢，对了server.startSession() 是用来做什么的？其基本功能是向Agent发送一个device_id然后构建两者间一个session。返回是否构建成功以及Agent端生成的session_id



self. sendAndReceive() 字面意思就是消息的发送和接收，该方法是父类pydiesel.api.transport.SocketTransport上实现的，整个PC端控制台所有的消息收发都是使用该方法。这里还是比较简洁的，发送一个message和接收一个receive，这个message就是使用protobuf构造一个数据格式对象，在java反射机制分析会详细介绍，这里我们先提前认识一下。


至此，PC端与Agent已完成一个session建立即将通信通道建立，接下来就是创建一个session对象，以供PC控制台使用。

 session = Session(server, session_id, arguments) 就是用来初始化一个session，这里面包括了ServerConnector、session_id、modules、Reflector等对象，modules是插件化模块的初始化，Reflector这个就是用来搞java反射的模块，ServerConnector为后续消息收发提供socket服务支撑，你会在这几个地方pydiesel.reflectio.reflector.py、drozer.console.session.py等看到sendAndReceive()这个方法，其本质是调用ServerConnector对象的sendAndReceive()，这里是多层封装方便各模块间的调用。
