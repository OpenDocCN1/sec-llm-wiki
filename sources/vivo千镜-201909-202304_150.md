简介

Android Security Test Suite (STS)，是谷歌的关于Android安全补丁安装情况的一个测试套件，其本质上是CTS测试中添加的一项安全测试套件。从2018-09开始，Android系统版本都需要上传STS报告，进行google认证，若STS测试失败，则会导致Google认证不通过。

主要的功能为测试Android Security Patch 是否生效，其patch包括CVE和Android自定义编号的漏洞，涵盖kernel、驱动、框架和应用程序等的安全漏洞和安全策略。本文目标为了解如何获取STS及其对Android系统漏洞检测的能力。

  

搭建环境

1基础配置Windows10 子系统Ubuntu 18、JDK1.8、adb 、aapt（PS：因笔者硬件配置有限，开虚拟机编译性能跟不上，故采用WSL）2编译环境sudo apt install git-core gnupg flex bison gperf build-essential zip curl zlib1g-dev gcc-multilib g++-multilib libc6-dev-i386 lib32ncurses5-dev x11proto-core-dev libx11-dev lib32z-dev ccache libgl1-mesa-dev libxml2-utils xsltproc unzip3下载Android源码

（友情提示同步源码时间巨长，耐心等待就好）

右键新建文件Android9.0，WSL目录和win10共存的，win10上的分区都挂载在/mnt/ 上

切换至新建目录：cd /mnt/f/Android9.0

初始化 ：

repo init -u https://android.googlesource.com/platform/manifest

可以使用 -b 来指定相应分支，如：

repo init -u https://android.googlesource.com/platform/manifest -b android-9.0.0\_r30

同步源码：repo sync

  

编译

    使用WSL的时候有一个坑，windows上创建的文件名称是大小写不敏感的，起初笔者直接创建目录，导致编译报错

  

![](../Images/7d04aa0554a75ef28273a88aa1382442.png)

该问题解决方式也较简单，新建一个目录，然后开启区分目录大小写功能即可  

  

![](../Images/6a734a6716a705aaa066274b51ca8e53.png)

fsutil.exe file SetCaseSensitiveInfo xxxx enable

上面命令是开启单个文件夹的名称区分大小写功能（关闭对此文件夹的大小写支持，enable 改为 disable即可），如果需要开启其他文件夹，需要多次执行这样的命令。但是从windows10的build 17692版本开始新建的子目录可以继承上级目录的大小写敏感属性，所以可以先创建大小写敏感的目录再进行repo初始化同步源码。

  

**开始编译**：

$:source build/envsetup.sh

$:lunch

$:make cts

其中testcase 目录存放的是测试案例，进入该目录会发现很多jar、apk、二进制等文件，我们只需关注CVE相关的二进制文件和安全测试模块相关的即可。tools目录存放的是启动文件和相关的工具类，results存放结果（启动测试之后才出现的目录）  
  

运行

CTS在Google上配置是很繁琐的，但是本次只关心安全漏洞相关的检测case，所以简单设置手机允许adb安装apk、不锁屏即可。

( PS : 因为是在WSL上进行的试验，WLS上的adb 需要和Windows10上的adb版本一致，WLS才可以正常使用adb操作手机。可能是笔者姿势不对每次都需要在windows10上先启动adb-server才能正常使用。)

  

USB连接手机，运行CTS：进入工具目录：cd /out/host/linux-x86/cts/android-cts/tools启动cts console：./cts-tradefed

![](../Images/5258a003baa19579bfd98c4a9e0387cd.png)

查看测试模块列表：list m

![](../Images/63fc79b2fae536994fc74ba3230cf2f0.png)

  

整个模块列表里面我们只关心与安全漏洞相关的测试模块，如下：  
“

1、CtsAppSecurityHostTestCases

2、CtsJdwpSecurityHostTestCases

3、CtsSecurityHostTestCases

4、CtsSecurityTestCases

”

  

其中，CtsAppSecurityHostTestCases、CtsJdwpSecurityHostTestCases不包含CVE，了解到的其是一些App层安全检测和安全策略检测，我们现在主要关心的系统漏洞相关的，所以可以先跳过这两个模块着重介绍CtsSecurityHostTestCases和CtsSecurityTestCases。CtsSecurityHostTestCases模块主要测试Linux内核和各类驱动的漏洞，都是以C/C++实现的漏洞检测PoC，对应的源码路径在：/cts/hostsidetests/security；CtsSecurityTestCases模块基于动态检测，采用的是触发漏洞来检测的方式，使用Java或者JNI来触发漏洞，直到数据被传递到底层漏洞位置。这个模块所在源码的路径是/cts/test/test/security。  
在cts console 中，可以用以下命令启动测试：整个模块测试：run cts –m CtsSecurityHostTestCasess单个case测试：run cts -m CtsSecurityHostTestCases -t android.security.cts.Poc17\_09#testPocCVE\_2016\_3809

  

Case说明：那年那月的安全补丁、CVE安全补丁编号或Google与之对应的编号

android.security.sts.Poc【年\_月】#testPro【CVE安全补丁编号】

android.security.sts.Poc17\_07#testPocBug\_33299365

  

cts console上运行：run cts -m CtsSecurityHostTestCases![](../Images/0bf5f0df297f2ccf10d0c096a993700c.png)
