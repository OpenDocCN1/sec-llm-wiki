## 阶段1：枚举

首先通过 nmap 对其进行开放端口枚举：

![](../Images/0494cf3887a0b2acc7814d80fc6ed5b0.png)

从结果中看开放的端口很少，解题的顺序应该是从Web获取到用户名及密钥或者上传Webshell，或者SSH。

![](../Images/240788e6a60c7e6df8bef4578ac5bcac.png)这里给的信息很很少，但是在页面源代码中提示了一个博客的路径：`/nibbleblog/`

![](../Images/eb158fcf9fa016186d2eb951a454c07c.png)  
打开后如图所示，查看了一下超链接全是一些html锚点，没有新页面了。

![](../Images/e0b6185cba1aafb2e7fcbee7a2ab8600.png)

从页尾处看到了署名就是 `Nibble Blog` ，但是并没有版本信息。这里使用之前从IPPSEC那学习的技巧，下载 `.ico` 文件查看文件时间，然后反推系统版本发布时间。

> `wget "http://10.10.10.75/nibbleblog/themes/simpler/css/img/favicon.ico"`

![](../Images/dffeb55ebb38b13895a8fd85d40d2127.png)  
接着去找这套系统的CVE漏洞，这套系统早已经不更新了，最后的版本为 `4.0.5`  
![](../Images/938df0ed19b23bfa6209ed70ae26965e.png)

> CVE-2018-16604 - 使用管理员的用户名和口令，攻击者可以通过更改用户名来执行任意PHP代码。

从这里这个CVE编号中来看，需要找用户名和口令。

然后在其他平台找到一个新的 CVE 描述，里面描述了 `install.php` 的用户名参数。

![](../Images/af8f3470ca534522d1c5375da788feea.png)`install.php` 存在，内容含有另一个脚本的指向  
![](../Images/581b041625dd19e9602ac12e2b316eb9.png)![](../Images/6e18878136636e33362abc6532b281ac.png)

获得两个新的xml文件路径，以及系统对应版本号 `4.0.3`

```

http://10.10.10.75/nibbleblog/content/private/config.xml
```

`config.xml` 获取到两个疑似用户名的内容：`admin、noreply`

![](../Images/9677d973e63e000a867653321cd612d7.png)`comments.xml` 暂时未知，从标签和参数来推测应该是一个黑名单的东西。  
![](../Images/5e55ede63bd173f21ef551a04f706431.png)

## 阶段2：工具及利用

### 阶段2.1：Fuzzing密码

找到管理员登录页面 `admin.php`，尝试口令枚举（sqlmap试过了，失败）。

![](../Images/6ef2bd0f91e2de56134fd68862199706.png)

当登录失败次数过多时会返回该错误：  
![](../Images/7949fa960fb1ebe1ffe9dc89bfe909a9.png)

尝试利用 hydra 加字典枚举下口令：

`hydra -l admin -P /usr/share/wordlists/rockyou.txt 10.10.10.75 -V http-form-post '/nibbleblog/admin.php:username=^USER^&password=^PASS^:Incorrect username or password'`

![](../Images/2d326c9fdba525fecbf06bf43fcfd313.png)  
显示很多组口令都可以登录，但实际尝试下来都是失败的，将其导出让后用burp代理下看看详情。  
![](../Images/f4542ad9f6d1a365435c6754ac09f601.png)

![](../Images/f942e336de4418f1ea3b584dd828318d.png)

明显看到，工具提示成功是因为安全机制生效了。

在 Hackthebox 的论坛社区里搜了一圈，按照出题的尿性，如果口令不在字典中那就可以是没有枚举出正确的路径文件，或者口令就是题目名称。所以我尝试了一下 `nibbles`，发现进行了302的页面跳转。

![](../Images/8940c95e2f1a323eb2c153bc9e8630c2.png)

成功进入管理员后台。

![](../Images/c01d2c85432ba79d9a4d804d15998b81.png)

## 阶段3：权限提升

在 nibbler 用户文件夹下发现有个压缩文件，通过nc传回本地在分析。  
![](../Images/857198bab81affeaf815803c4c746955.png)  
压缩包解压后发现，它与 sudo 配置中已 root 身份执行特定文件的目录存在相似性。  
![](../Images/0ef721af508e274956c8d0ea5a8daae0.png)  
查看下该文件的权限（注意时间为2015，并非当前kali用户root下创建的，也就是说这个脚本具备root身份运行的权限）：  
![](../Images/abc7ec07787dd4365b7eaa0c52413feb.png)会到服务器，发现该目录并不存在，所以直接解压这个压缩包。  
![](../Images/41b3db9ce0fc3a13a47f53fbb8029cd2.png)在服务上查看下权限，OK与kali里的一致的，直接将 python reverse 写入该文件即可。  
![](../Images/3292dbfa5e66e0317fa3067021ebe88f.png)
