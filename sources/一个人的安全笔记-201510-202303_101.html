1. PHP5-APC/PHP5-APCu

从最配置LNMP环境时就知道APC这个模块的好处，所以每次安装环境的时候，基本上这个模块我都会安装上去。

  • apt-get 一建安装

    sudo apt-get install php5-apc

注意：我本机PHP安装版本是PHP 5.6.11 所以装的扩展是PHP5-APCU，查看了APC的最后PIP上发布的时间是2012年，而APCU对新版本提供新的支持项。

APC是一个通过缓存PHP源码和用户变量，来高效显著加速你的PHP程序的opcode缓存。在应用中使用APC，通常伴随着提升程序响应时间、减轻服务器负载和愉悦用户的功效。

作用：

  1. 缓存期限：

    APC的缓存分两部分:系统缓存和用户数据缓存。

    系统缓存，是自动使用的,是指APC把PHP文件源码的编译结果缓存起来,然后在再次调用时先对比时间标记。

    用户数据缓存，由用户在编写php代码时用apc_store和apc_fetch函数操作读取、写入的。如果量不大的话我建议可以使用一下。如果量大，建议使用memcache缓存吧（最好别用，缓存频繁的数据用户会出现奇葩的错误）。

  2. 状态控制和分析： PHP APC的源码包自带了一个apc.php。
    可以将这个文件上传到web服务器的某个目录下，用浏览器访问，这会显示当前的状态。我们可以从这里的表格分析当前的缓存状况，作出进一步优化（也就是图形化NoSql数据查看而已）。

    我们需要通过统计调整apc.shm_size、apc.num_files_hints、apc.user_entries_hint的值，直到最佳。

注意：在配置文件中默认apc.stat=1，这样每次请求都会访问需要使用的php文件，看看这个文件是否更新了，已决定是否重新编译php文件。这个是很耗性能的，直接赋值0将其关闭。反正每次修改了配置文件后干掉php5-fpm，重新开启即可。

php5-apcu 下载地址：https://github.com/krakjoe/apcu

2. Xdebug + kcachegrind 分析ThinkPHP框架函数调用图

Xdebug 是什么我就不过多赘述了，windows下的安装方式请自行百度。

sudo apt-get install php5-xdebug

更改配置文件： vim /etc/php5/mods-available/xdebug.ini

zend_extension=xdebug.so # .so文件地址
xdebug.profiler_enable=on # 始终开启
xdebug.trace_output_dir="/tmp/xdebug" # 文件保存地址
xdebug.profiler_output_dir="/tmp/xdebug" # 文件保存地址

随后在/tmp建立文件夹xdebug并赋予相应的读写权限：

cd /tmp
mkdir xdebug
sudo chmod 777 xdebug

不给全部权限也可以，根据自己制定，让后重启php5-fpm 让起其生效。

此时当我们打开浏览器运行我的网站时，随便点击点页面，在xdebug文件夹内会产生类似文件：

-rw-r—r— 1 nobody nobody 4615252 Oct 27 17:31 cachegrind.out.29293

此时我们来安装kcachegrind，win下请安装wincachegrind

sudo apt-get install kcachegrind

安装完成后直接在终端下运行kcachegrind启动即可，并用其打开/tmp/xdebug中的文件就可以进行性能分析了。
