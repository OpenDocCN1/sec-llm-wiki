###### git的暂存

场景：

软件开发中，bug就像家常便饭一样。有了bug就需要修复，在Git中，由于分支是如此的强大，所以，每个bug都可以通过一个新的临时分支来修复，修复后，合并分支，然后将临时分支删除。  
当你接到一个修复一个代号101的bug的任务时，很自然地，你想创建一个分支issue-101来修复它，但是，等等，当前正在dev上进行的工作还没有提交：

```
$ git status
# On branch dev
# Changes to be committed:
#   (use "git reset HEAD <file>..." to unstage)
#
#       new file:   hello.py
#
# Changes not staged for commit:
#   (use "git add <file>..." to update what will be committed)
#   (use "git checkout -- <file>..." to discard changes in working directory)
#
#       modified:   readme.txt
#
```

并不是你不想提交，而是工作只进行到一半，还没法提交，预计完成还需1天时间。但是，必须在两个小时内修复该bug，怎么办？

幸好，Git还提供了一个`stash`功能，可以把当前工作现场“储藏”起来，等以后恢复现场后继续工作：

```
$ git stash
Saved working directory and index state WIP on dev: 6224937 add merge
HEAD is now at 6224937 add merge
```

现在，用git status查看工作区，就是干净的（除非有没有被Git管理的文件），因此可以放心地创建分支来修复bug。

修改完Bug合并后删除bug分支，随后我们切换回之前的工作分支继续工作。因为之前已经暂存了此分支上的工作，我们只需`$ git stash pop`，好了还原到之前的作案现场了。是不是很方便呢？

###### git回退(回滚)

场景：  
当我们在使用中，不小心将敏感信息或不必要的显示push到了远程端，如果在本地中去除，再次push虽然可以在代码中去除掉，但在提交的日志中仍然能够看到。又要更改code，又要去除上次的提交记录，此时就用到了版本回退功能。

`$ git reset --hard HEAD^`

`$ git push`

如果需要回退至某一个特定的版本，那么就必须这样使用

*   先用`$ git log`查看commit编码
*   找到需要回滚的编码后`$ git reset --hard xxxxxxx...` commit可以不填写全，前七位即可
*   确认你是否是你所需的版本，没问题之后`$ git push -f`

完整的bug分支操作

```
    $ git st  # 查看下当前状态

    $ git stash  # 暂存

    ﻿$ git checkout master # 切换至主分支

    ﻿$ git checkout -b issue-101 # 创建issue-101 分支并切换

    ﻿......修改完bug并add/push后......

    ﻿$ git checkout master # 切换回主分支

    ﻿$ git merge --no-ff -m "merged bug fix 101" issue-101 # 合并分支

    ﻿$ git branch -d issue-101 # 删除临时的bug分支

    ﻿$ git checkout branch-name # 切换回开发分支

    ﻿$ git stash pop # 导出暂存内容
```

###### git在合作开发时的回退规则

前一种“回退”就是在没有历史记录的，如果有其他人也在用你的remote，你push -f 会出大问题的，与他人合作开发更漂亮的做法是用`revert`

```
$ git log
commit e7c8599d29b61579ef31789309b4e691d6d3a83f
Author: fsword <li.jianye@gmail.com>
Date:   Sat Jun 8 14:27:11 2013 +0800

    补充后续计划和调整方案

commit d501310d245fe50959e8bcc1f5465bb64d67d1c8
Author: fsword <li.jianye@gmail.com>
Date:   Fri Jun 7 14:36:49 2013 +0800

    完成基本的设计

...
```

决定放弃最近提交的 e7c8599d29b61579ef31789309b4e691d6d3a83f

`git revert e7c8599d29b61579ef31789309b4e691d6d3a83f`

现在查看log，发现多了一次commit，其内容就是回到了原来的那个阶段

```

Author: fsword <li.jianye@gmail.com>
```

###### git如何查看某一个文件的详细提交记录

`$ git log -p filename`

这样就知道改动前的内容了。

###### git和分支合并

合并某分支到当前分支：`$ git merge <name>`

###### git删除远程分支

如果不再需要某个远程分支了，比如搞定了某个特性并把它合并进了远程的 `master` 分支（或任何其他存放稳定代码的分支），可以用这个非常无厘头的语法来删除它：git push [远程名] :[分支名]。

`git push origin :exportcv`
