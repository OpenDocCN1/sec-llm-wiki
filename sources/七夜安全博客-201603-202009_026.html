strace 命令

在之前的文章，讲解腾讯哈勃linux沙箱实现时，涉及到strace命令。strace用来监控linux系统调用，主要用于调试，分析诊断应用程序的问题。你将发现他是一个极好的帮手，在你要调试一个无法看到源码或者源码无法在编译的程序时候。做过linux开发的同学，会经常用到这个命令。

在安全领域，strace 可以作为linux syscall的应用层监控方案，不需要安装驱动，原理是借助ptrace功能来实现，可以作为沙箱方案中的syscall监控组件。

命令参数

  1. -c 统计每一系统调用的所执行的时间,次数和出错的次数等.
  2. -d 输出strace关于标准错误的调试信息.
  3. -f 跟踪由fork调用所产生的子进程.
  4. -ff 如果提供-o filename,则所有进程的跟踪结果输出到相应的filename.pid中,pid是各进程的进程号.
  5. -F 尝试跟踪vfork调用.在-f时,vfork不被跟踪.
  6. -h 输出简要的帮助信息.
  7. -i 输出系统调用的入口指针.
  8. -q 禁止输出关于脱离的消息.
  9. -r 打印出相对时间关于,,每一个系统调用.
  10. -t 在输出中的每一行前加上时间信息.
  11. -tt 在输出中的每一行前加上时间信息,微秒级.
  12. -ttt 微秒级输出,以秒了表示时间.
  13. -T 显示每一调用所耗的时间.
  14. -v 输出所有的系统调用.一些调用关于环境变量,状态,输入输出等调用由于使用频繁,默认不输出.
  15. -V 输出strace的版本信息.
  16. -x 以十六进制形式输出非标准字符串
  17. -xx 所有字符串以十六进制形式输出.
  18. -a column 设置返回值的输出位置.默认为40.
  19. -e expr 指定一个表达式,用来控制如何跟踪.格式：[qualifier=][!]value1[,value2]...
  20.    qualifier只能是 trace,abbrev,verbose,raw,signal,read,write其中之一.
  21.    value是用来限定的符号或数字，默认的 qualifier是 trace，感叹号是否定符号。例如:-eopen等价于 -e trace=open,表示只跟踪open调用.
  22.    而-e trace=!open 表示跟踪除了open以外的其他调用.有两个特殊的符号 all 和 none.
  23.    注意有些shell使用!来执行历史记录里的命令,所以要使用\!,例如 -e trace=\!open.
  24. -e trace=value 只跟踪指定的系统 调用.例如:-e trace=open,close,read,write表示只跟踪这四个系统调用.默认的value=all.
  25. -e trace=file 只跟踪有关文件操作的系统调用.
  26. -e trace=process 只跟踪有关进程控制的系统调用.
  27. -e trace=network 跟踪与网络有关的所有系统调用.
  28. -e strace=signal 跟踪所有与系统信号有关的 系统调用
  29. -e trace=ipc 跟踪所有与进程通讯有关的系统调用
  30. -e abbrev=set 设定strace输出的系统调用的结果集.-v 等与 abbrev=none.默认为abbrev=all.
  31. -e raw=set 将指定的系统调用的参数以十六进制显示.
  32. -e signal=set 指定跟踪的系统信号.默认为all.如 signal=!SIGIO(或者signal=!io),表示不跟踪SIGIO信号.
  33. -e read=set 输出从指定文件中读出 的数据.例如: -e read=3,5
  34. -e write=set 输出写入到指定文件中的数据.
  35. -o filename 将strace的输出写入文件filename
  36. -p pid 跟踪指定的进程pid.
  37. -s strsize 指定输出的字符串的最大长度.默认为32.文件名一直全部输出.
  38. -u username 以username的UID和GID执行被跟踪的命令

常用参数说明

1.系统调用统计 strace不光能追踪系统调用，通过使用参数-c，它还能将进程所有的系统调用做一个统计分析给你，这次我们执行带-c参数的strace 调式ls：


  1. [root@VM_0_13_centos ~]# strace -c ls


2. 跟踪子进程并将日志输出到文件中(添加时间戳和耗时)

  1.  [root@VM_0_13_centos ~]# strace -f -tt -T -e trace=all -o strace.log  ls
  2.  [root@VM_0_13_centos ~]# tail strace.log  -n 20

3.跟踪一个现有的进程 strace不光能自己初始化一个进程进行trace，还能追踪现有的进程，参数-p就是取这个作用的，用法也很简单，具体如下。

  1. strace -p pid

日志结构化

虽然strace能很好地监控syscall调用，但是有个问题是不利于工程化，因为strace的定位是程序员用来调试程序，日志显示的方式利于人类观察，不利于程序直接分析，所以需要对strace日志进行解析。在github中，搜索了一下strace parser ,发现了不少项目，看来这个问题，大家都曾遇到过呀，经过挑选，有6个开源项目还是不错的。

  1. https://github.com/zom3y3/stracer
  2. https://github.com/johnlcf/Stana
  3. https://github.com/vstinner/python-ptrace
  4. https://github.com/dannykopping/b3
  5. https://github.com/wookietreiber/strace-analyzer
  6. https://github.com/burner1024/strace-io-parser

其中 https://github.com/dannykopping/b3， 基于nodejs开发，可以将strace日志转化为json，还是很令人欣喜的。

执行以下命令安装b3并解析日志为json:

  1. [root@VM_0_13_centos ~]# npm i -g b3-strace-parser
  2. [root@VM_0_13_centos ~]# strace -f -T -o strace.log ls
  3. [root@VM_0_13_centos ~]# cat strace.log | b3
