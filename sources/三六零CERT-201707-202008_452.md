# SSH 命令注入漏洞(CVE-2017-1000117)分析

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzU5MjEzOTM3NA==&mid=2247483872&idx=1&sn=ae4d0c77255615a38070b41daf681b57&chksm=fe2504e1c9528df7fae91502e3d09cb74750f870852b458a4dc858ae4c7a436778ff0ab9ccd3&scene=126&sessionid=1681374327#rd](http://mp.weixin.qq.com/s?__biz=MzU5MjEzOTM3NA==&mid=2247483872&idx=1&sn=ae4d0c77255615a38070b41daf681b57&chksm=fe2504e1c9528df7fae91502e3d09cb74750f870852b458a4dc858ae4c7a436778ff0ab9ccd3&scene=126&sessionid=1681374327#rd)

![](../Images/dd7bbdb4b547c9a4b36348f65ae6522f.png)

  

**0x00 背景介绍**  

  

* * *

  

A malicious third-party can give a crafted"ssh://..." URL to an unsuspecting victim, and an attempt to visitthe URL can result in any program that exists on the victim's machine beingexecuted. Such a URL could be placed in the .gitmodules file of a malicious project,and an unsuspecting victim could be tricked into running "git clone--recurse-submodules" to trigger the vulnerability.

  

\-- https://www.mail-archive.com/linux-kernel@vger.kernel.org/msg1466490.html  

2017年8月10日，Junio C Hamano发布了这一问题。

  

**0x01 漏洞概述**

* * *

  

恶意人员可以通过巧妙构造“ssh://…”链接，让受害人在执行程序等情况下访问该恶意链接，从而达到命令执行的目的。该链接可以被放在 git项目的 .gitmodules 文件下，这样当受害人对一个项目进行“git clone --recurse-submodules”操作时，就会引发安全问题。

  

360CERT进行了紧急分析，目前该分析报告仅以Git为例，但漏洞影响包括但不限于Git，SVN，CVS，HG，Gitlab，GithubDesktop，SourceTree等。

  

**0x02 漏洞攻击影响**

* * *

  

**1、影响面**

该漏洞主要由“ssh://…”链接造成，如Git，SVN，CVS，HG等工具，在解析SSH链接的时候都会触发这个漏洞。此外，若是其他程序在解析SSH链接的时候，不做相应的处理，就会触发该漏洞。

  

经过360CERT研判后确认，漏洞风险等级高，影响范围广。

**2、影响版本**

Versions prior to 2.14.1 of the Git

**3、修复版本**

Git v2.14.1

  

**0x03 漏洞详情**

* * *

  

**1、技术细节**  

该漏洞主要由于SSH链接在hostname部分，若是用“-”开头，那么会导致ssh命令将hostname误认为这是一个选项。因此，我们可以利用“-oProxyCommand”选项来达到命令执行的目的。

在进行git clone 时候会调用到git/connect.c中“struct child\_process\*git\_connect(int fd\[2\], const char \*url,const char \*prog, int flags)”函数。其接受到的参数url为命令中“git clone xxx://xxxxxxxxxx/xx(.git)”的xxx://xxxxxxxxxx/xx(.git)部分。在该函数中会对传入的这个字符串进行parse，提取其协议部分。在满足协议为ssh://的时候会进入该函数的else部分。

![](../Images/cf89e7aaa8808c85b2bceea5309538b3.png)

然后根据下面的流程调用本地的ssh

![](../Images/31b48977c747d7a9659a27052a439abe.png)

•   首先获得本地的ssh路径，然后push进conn->args

•   然后获得url中ssh\_host部分再拼接路径

•   最后调用start\_command函数进行命令执行

start\_command的定义在git/run-command.c

int start\_command(structchild\_process \*cmd)

![](../Images/2ae44d92241d508ebc2144b90658c1eb.png)

将传入的cmd经过处理赋值给argv

![](../Images/c35984a1c560aad6bbd04641f96194b4.png)

经过execve这个函数进行命令执行。但是在这个这个命令执行的内容是“/usr/bin/ssh \`ssh\_host\` path”而ssh命令的-o参数在一定程度上是可以执行命令的

例如

“ssh-oProxyCommand=gnome-calculator xxx”将会在本地打开gnome的计算器

所以如果我们在clone 操作的时候将连接指定为

git clonessh://-oProxyCommand=gnome-calculator/cert

将取得同样的命令执行的效果

  

**2、漏洞修复**

在v2.14.1的commit中，可以看到git\_connect函数中执行之前对ssh\_host进行了验证

![](../Images/010ba7defc5fa85d197e698c852b8ff2.png)

验证内容为新增的这个函数

![](../Images/a826748b9418f3d133413d39aebf01dc.png)该函数对ssh\_host的第一个字符进行了校验防止为-的情况抑制了向ssh传递参数的情况，并且在多处对传入的host，port都做了该函数的过滤。
