1  
 简述  
  
  

目前360CERT了解到，组织机构在排查Log4j漏洞时，仅以jar包的文件名，或路径中包含特定字符串为检测和排查标准。该方式存在一定的误报，360CERT根据实战攻防经验，特别为业界的安全人员研发了一款在磁盘中扫描 Log4j 存在漏洞的 class 文件扫描工具，希望能够帮助安全人员减轻负担，提升调查响应效率！

该工具可以自动递归扫描`zip、jar、war、ear`此类常见 zip 衍生格式。

```


http://pub-shbt.s3.360.cn/cert-public-file/log4jhash-check-darwin-amd64
```

```


f7d132dad804a5765d676524caeccd2b  log4jhash-check-darwin-amd64
```

  
2  
 使用指南  
  
  

以 linux x64 为例

```


./log4jhash-check
```

以搜索 solr-7.7.1 为例

```


./log4jhash-check -d ./solr-7.7.2
```

以搜索 tomcat 为例

```


./log4jhash-check -d apache-tomcat-8.5.73/webapps
```

以搜索存在嵌套的 jar 包为例

```


unzip -l log4j-core-2.2.jar | grep jar
```

以搜索 jar 包特定路径的class为例，该方式会输出满足条件的 class 的 sha256

```


./log4jhash-check -d log4j-core-2.0.1.jar --inner PluginAliases.class
```

list 显示指定 jar 包的所有 class sha256hash

```


./log4jhash-check -d log4j-core-2.0.1.jar -l
```

  
3  
 扫描原理  
  
  

360CERT 经过分析定位到存在问题的3个重点class文件

```


org/apache/logging/log4j/core/net/JndiManager.class
```

log4j2 的存在漏洞的 sha256 列表

```


log4j-core-2.12.0.jar org/apache/logging/log4j/core/net/JndiManager.class 1fa92c00fa0b305b6bbe6e2ee4b012b588a906a20a05e135cbe64c9d77d676de
```

log4j1.x 的存在漏洞的 sha256 列表，注意该漏洞非log4shell(CVE-2021-44228)，而是(CVE-2021-4104)。

```


log4j-1.2.5.jar org/apache/log4j/net/SocketNode.class ed5d53deb29f737808521dd6284c2d7a873a59140e702295a80bd0f26988f53a
```

根据上述文件 Hash ，对磁盘路径中的指定类型文件进行扫描，以实现对存在漏洞的文件进行发现。

同时 360CERT 对 maven 仓库中的各类组件的各版本共计`8,228,588`个 pom 进行分析发现。很多高级组件存在二次依赖的相关问题。

![](../Images/4a11a3a1b7fba87eda1484895a50e551.png)

虽然在正常情况下，都会以jar包情况进行打包，但在Java 开发过程中为解决多版本共存的问题以及开发人员打包习惯的不同，会存在递归打包、fatJar 等特殊情况。

此处以编写的一个 http server 为例，在使用 fatJar 打包方式时，包内不会存在 log4j-core.jar而是将其所有的 class 内嵌到了该应用程序的jar包中。

```


unzip -l logdemo-1.0.jar  | grep -i jndi
```
