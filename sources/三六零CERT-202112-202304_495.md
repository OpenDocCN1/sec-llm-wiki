 漏洞简述  
  
  

2021年12月09日，360CERT监测发现`Apache Log4j 2`存在JNDI远程代码执行，漏洞等级：`严重`，漏洞评分：`10.0`。

Apache Log4j 2是一个开源的日志记录组件，使用非常的广泛，使用情况参考：

*https://mvnrepository.com/artifact/org.apache.logging.log4j/log4j-core/usages*

对此，360CERT建议广大用户尽快将·Apache Log4j 2进行升级，以免遭受黑客攻击。

 漏洞详情  
  
  

### 2.14.0

log4j2 对`error msg`的处理在`MessagePatternConverter#format`在方法内，`noLookups`默认`false`，于是进入if判断。

```
 if (this.config !\= null && !this.noLookups) {
for(int i \= offset; i < workingBuilder.length() \- 1; ++i) {
if (workingBuilder.charAt(i) \=\= '$' && workingBuilder.charAt(i + 1) \=\= '{') {
\= workingBuilder.substring(offset, workingBuilder.length());
.setLength(offset);
.append(this.config.getStrSubstitutor().replace(event, value));
}
}
}

```

`workBuilder`是`log`前缀加上`msg`。

![](../Images/112026ce87d7d56605eda5b6ba1c805e.png)

这里会进行匹配，如果匹配到了`${`的字符，`value`是从前缀之后的部分开始，接着调用`StrSubstitutor#replace`一直跟到`StrSubstitutor#substitute`， 获取prefix（`$,{`）和suffix（`}`）的匹配。

![](../Images/c49d09aa047ce0b4c29c6c4df5c5d212.png)

该方法会进行递归调用，提取`${}`之间的`value`进行解析（这也是网上的一些嵌套其他协议绕过的点）。

![](../Images/2df3343451454bd59a8fc92fc910b39e.png)

然后调用`StrSubstitutor#resolveVariable`。

![](../Images/732195ecb7eb07d7fc339f9f97973667.png)

在`Interpolator#lookup`里对协议进行匹配，然后调用对应的`lookup`方法，这里还会对协议进行`toLowerCase`调用（也就存在一些特殊字符对`waf`的绕过）。

![](../Images/dbb39b51d3d58de7ce6112313efa216b.png)

部分调用栈如下：

![](../Images/8da3f654a2175c6c588e6b22d3138f1b.png)

#### 为何只能error/fotal触发

![](../Images/b846edeabd323cf74699bf04455cc1aa.png)

想要触发后续流程，需要调`logMessage`方法，需要`isEnable`为`true`，跟进，发现会对`level`进行判断，`info`的`level`是`400`，只要小于等于`200`，才会返回`true`。

![](../Images/a3540e08763aa3311c5a64a397fd7e0c.png)

小于等于`200`的只有`100/200`。

```
static {
\= new Level("OFF", StandardLevel.OFF.intLevel());
//100        FATAL \= new Level("FATAL", StandardLevel.FATAL.intLevel());
//200        ERROR \= new Level("ERROR", StandardLevel.ERROR.intLevel());
//300        WARN \= new Level("WARN", StandardLevel.WARN.intLevel());
//400        INFO \= new Level("INFO", StandardLevel.INFO.intLevel());
//500        DEBUG \= new Level("DEBUG", StandardLevel.DEBUG.intLevel());
//600        TRACE \= new Level("TRACE", StandardLevel.TRACE.intLevel());
//2147483647        ALL \= new Level("ALL", StandardLevel.ALL.intLevel());
}

```

### 2.15.0-rc1

在遍历`formatter`的时候，由之前的`MessagePatternConverter`变为`MessagePatternConverter$SimpleMessagePatternConverter`。

![](../Images/081e0462a894f63b4db41d3d8c9736be.png)

`MessagePatternConverter$SimpleMessagePatternConverter`不存在危险操作，而另一个类存在`lookup`的是`MessagePatternConverter$LookupMessagePatternConverter`。

![](../Images/32d9c43680ca5088e7c7e254ac2c73d5.png)

看下初始化`Converter`的逻辑：

![](../Images/f1548110845f23f8bd9fd77d9540edd6.png)

想要拿到`LookupMessagePatternConverter`，必须要`lookups`为`true`，而默认情况下是`false`，跟一下`loadLookups`，需要设置`options`。

![](../Images/d04578c69682a20dc351fdc6b04ea06e.png)

手动设置`options`之后，一路跟到`JndiManager`。

![](../Images/7696d46b3c8170d06469018d84b4f257.png)

在`lookup`内部执行了几个方法，会对协议内容进行检测，`allowedProtocols`检测协议，`allowedHosts`对`ldap`请求的`host`进行了检测，只允许请求本地`ip`，所以，看似这里已经对`ldap`做了检测，但是注意`catch`错误的时候，并没有`return`，所以可以利用抛出错误进行绕过。

![](../Images/f971967e6fb8a1b4437d59780f347b4e.png)![](../Images/453b615af0f224929c10a0720d57069a.png)

具体绕过方式可以直接参考官方示例。

![](../Images/2ca3b9785fb10b9de06633f2fc7235fd.png)

### 2.15.0-rc2

`catch`错误之后，`return null`，也就走不到`lookup`方法里了。
