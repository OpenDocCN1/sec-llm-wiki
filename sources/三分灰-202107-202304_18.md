**Struts2**

Struts2 是一个相当强大的 Java Web 开源框架。早几年流行于 Java 服务端开发，不过随着时间推移也在慢慢被淘汰。其本质上相当于一个 Servlet。

**s2-001**

s2-001 是 Struts2 上的一个远程代码执行漏洞。

该漏洞是因为，用户提交表单数据并且验证失败时，后端会将用户之前提交的参数值，使用 OGNL 表达式 %{value} 进行解析，然后重新填充到对应的表单数据中。

**漏洞复现**

这里我直接使用 Vulnhub 上的靶场。

打开靶场环境。

![](../Images/e3be3f559222939bfd6a640f10fbadd9.png)

首先简单验证一下漏洞是否存在，输入账号，密码输入 `%{2*2}`，提交。

![](../Images/07035f7ec9ad5547db87f3616199c6f1.png)

可以看到密码返回了 4，而这正是 `2*2` 的结果，说明是存在远程代码执行的。

![](../Images/35810c3eee85c60b89a3644fad2a70df.png)

接下来使用 `%{"tomcatBinDir{"+@java.lang.System@getProperty("user.dir")+"}"}` 获取一下 tomcat 的执行路径。

![](../Images/9451afde12bc1cd70a9f2e5926fa2265.png)

可以看到已经返回了 tomcat 执行路径，就在 `/usr/local/tomcat` 下。

![](../Images/f271448f9ee7cab2690d442480d5727e.png)
