前言

在网络攻防对抗升级的大背景下，攻击者越来越多地采用新技术来逃避基于签名和规则的检测机制，现代恶意软件变得越来越难以被发现。其中，隐写术和信息隐藏可用于绕过安全框架，通过搜索进程之间的通信或其他隐蔽通道进行渗透尝试。由于潜在载体非常大（例如：恶意软件可以隐藏在硬件资源、各种多媒体文件或网络流中），导致检测此类威胁非常困难，通过网络沙箱或者恶意文件规则匹配需要收集多个行为信息，非常耗时，缺乏可扩展性，并可能导致性能下降。新环境下，需要更有效的方式跟踪和监视软件进程的行为。


01

为什么要重视系统安全？

在长期的网络攻防中，网络和系统是防守方非常重要的两个检测和防御渠道，常见的网络安全设备有DDOS防御设备、WAF、IPS、NGFW等等，主要原理是还原出网络中的请求、传输文件和远程命令等，通过签名或者规则检测以上内容是否存在安全问题。但网络检测也存在诸多问题，如：加密流量检测困难、东西向大流量检测效率低下、网络恶意文件的检测困难，动态检测影响业务效率，静态检测准确率较低。

在业务稳定和效率要求越来越高的环境下，需要通过操作系统层面补充安全检测和防御，系统安全越来越凸显它的重要性。现代应用使用多阶段加载架构、模块化设计或采用复杂的服务框架，攻击方正在逐步引入新技术来躲避签名和基于规则的检测系统，这种趋势最终将导致恶意软件具有某种形式的信息隐藏特性，将数据隐蔽的传输到远程命令与控制 (C&C) 设施，并将攻击内容嵌入到看似无害的图像文件中。这也使得传统基于规则的系统安全技术有效性越来越低，我们将以eBPF为例，简单介绍在系统内核层面跟踪和监视进程的行为，从而高效地检测恶意软件和隐蔽的对外连接。


02

系统安全的技术实现

BPF（Berkeley Packet Filter），中文翻译为伯克利包过滤器，是类 Unix 系统上数据链路层的一种原始接口，提供原始链路层封包的收发。2013 年 BPF 技术进行重大改写，名为「extended BPF」。eBPF 实现的最初目标是针对现代硬件进行优化。当时 BPF 程序仍然限于内核空间使用，只有少数用户空间程序可以编写内核的 BPF 过滤器。2014 年 3 月， eBPF 提交到 Linux 内核中。2014 年 12 月 系统调用 bpf 提交到 Linux 3.18 中。随后，Linux 4.x 加入了 BPF 对 kprobes、uprobe、tracepoints 和 perf_evnets 支持。至此，eBPF 完成了架构演变，eBPF 扩展到用户空间成为了 BPF 技术的转折点。当前 eBPF 不再局限于网络栈，成为内核顶级的子系统。


BPF 是一个通用执行引擎，能够高效地安全地执行基于系统事件的特定代码。BPF 内部由字节码指令，存储对象和帮助函数组成。从某种意义上看，BPF 和 Java 虚拟机功能类似。BPF 开发人员可以使用编译器 LLVM 将 C 代码编译成 BPF 字节码，字节码指令在内核执行前必须通过 BPF 验证器进行验证，同时使用内核中的 BPF JIT 模块，将字节码指令直接转成内核可执行的本地指令。编译后的程序附加到内核的各种事件上，以便在 Linux 内核中运行该 BPF 程序。

eBPF可以根据事件源插入探针，通过这些探针监视和追踪进程的行为，下图显示了eBPF在linux内核中的静态探针：

除了上图中的静态探针，eBPF还支持对内核的动态探针，可以支持对任何内核函数进行插桩，甚至可以支持函数内部的指令进行插桩。


例如我们在execve syscall设置探针，编写如下程序：

#include <linux/bpf.h>#define SEC(NAME) __attribute__((section(NAME), used))
static int (*bpf_trace_printk)(const char *fmt, int fmt_size,                               ...) = (void *)BPF_FUNC_trace_printk;
SEC("tracepoint/syscalls/sys_enter_execve")int bpf_prog(void *ctx) {  char msg[] = "Hello World!";  bpf_trace_printk(msg, sizeof(msg));  return 0;}
char _license[] SEC("license") = "GPL";

该程序被加载后，系统检测到execve系统调用跟踪点被执行后，BPF程序将运行，此处，execve是执行其他程序的指令，所以当其他程序被执行时，我们会看到消息输出：Hello World!


现在，我们拥有了设置探针的能力，可以从内核角度去监控和跟踪触发事件的进程，比如，我们关注操作系统的隐蔽外连，我们可以在sys_enter_connect设置探针，通过上下文(context)获取调用sys_connect的进程，以及struct sockaddr*，结构如下：

struct sockaddr {  short int sin_family;  unsigned short int sin_port;  struct in_addr sin_addr;  unsigned char sin_zero[8];};
struct in_addr {  in_addr_t s_addr;}

我们通过sockaddr->sin_addr.s_addr即可获取外联地址，sockaddr->sin_port即可获取外联端口，探针处可以通过对外连地址和内容的分析和统计，基于内核层面的信息检测隐蔽的通道。


我们再举一个例子，下面我们以chmod-stego为例，讨论一下eBPF检测和跟踪隐藏的恶意软件。Chmod-stego(https://github.com/operatorequals/chmod-stego)是一个python程序，它通过UNIX 文件特权号（RWX Triplets）传递数据PoC，它由两个对等体组成，即秘密数据发送者和秘密数据接收者。

为了进行通信，发送者将Linux中关联的访问权限编号内的秘密消息编码为存储在两个端点都可以访问的目录中的文件。首先，它通过在所需 chmod(s) 的两次连续调用之间施加延迟来设置通道容量。发送者保存所有文件的初始“状态”（通过使用 OS 模块中的 stat 系统调用）。此外，它将要发送的秘密消息分成固定大小的块。块中的每个字符都转换为整数值，直接映射到目标文件集的权限。重复此操作，直到找到特殊的 EOF 字符。为了实现同步，发送者使用一种滴答机制来通知字符的编码，即每次更改权限时，它都会切换目录中第一个文件的所有者读取位。因此，接收方继续监听文件的所有者读取位（即，滴答位），以便了解权限是否对新信息进行编码。如果是，则接收方获取所有文件的访问权限，并使用ASCII编码对字符进行解密。重复该过程，直到完整地传输秘密消息。为了避免由于文件系统的不一致而容易被发现通信，在传输结束时，秘密发送者将文件权限恢复到原始状态。


由于chmod-stego是基于对文件系统的操作，设计检测策略的最佳方法是跟踪 sys_chmod内核函数，使用eBPF在sys_chmod内核函数下设置探针来追踪其调用并报告其相关参数，包括文件和权限、进程 ID 和线程 ID。通过态势感知或其他数据分析平台对隐藏的恶意程序或数据传输进行发现。


03

系统安全技术的应用

通过上面的介绍，我们使用eBPF在操作系统内核层面检测和跟踪进程，不仅在异常检测上，而且在具有信息隐藏能力的威胁防御中也能起到作用，在系统安全领域发挥着很大的作用。下面介绍几种使用到eBPF的场景。


HIDS可以通过eBPF检测隐藏的外联流量，也可以通过eBPF发现类似于chmod-stego的隐藏恶意程序，这些都是传统基于规则的安全产品比较薄弱的内容，弥补了基于规则的系统安全技术性能和可扩展性的不足。


eBPF也可以在sys_mkdir、sys_rename、sys_chmod、sys_link等内核函数设置探针，同时通过相关参数的判断，包括文件路径等内容，达到网页防篡改的内容，当文件路径和保护目录相同时，禁止进程调用增加、修改、删除文件的相关内核函数。


eBPF的巨大灵活性，可以应对不同的场景，根据不同场景设计不同的产品，欢迎各位读者来信交流。



总结

eBPF让我们在内核层面有了极大的自由，但它也不是万能的，也有一些限制，如：

1、与用户空间的交互通过map进行

2、不是图灵完备

系统安全作为企业安全建设中的关键一环，在网络攻防对抗升级的大背景下扮演着越来越重要的角色，如何做好系统安全也是所有安全从业人员的一个长期挑战。同时，系统安全中既有基于操作系统内核层面对安全事件的监控和发现，也包含通过操作系统，对恶意文件或者隐匿通信进行阻断的事件响应能力，如何将系统安全技术更好地嵌入于安全运营的SOAR支撑企业安全运营也是未来努力的方向。
