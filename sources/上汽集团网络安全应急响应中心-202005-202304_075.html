01

文件上传漏洞概述


什么是文件上传漏洞？顾名思义，就是由于服务器未对上传的文件进行严格的限制和验证，导致攻击者可以在不被允许的情况下，上传不合规的文件到网站服务器上。这些不合规的文件可以是木马、病毒、恶意脚本或者后门文件等可执行文件，最终达到入侵目的。


文件上传攻击一般流程如下：发现上传点->上传文件至网站页面->服务器保存文件->攻击者执行文件。

文件上传本身无可厚非，可一旦被攻击者利用，执行恶意文件，后果不堪设想。它的危害比注入、跨站等漏洞来得更加直接。攻击者可以通过文件上传漏洞上传木马文件至网站服务器，从而获取网站权限；上传含有菠菜、赌博等非法内容的html文件来进行百度快照劫持；以及上传恶意程序诱导用户点击下载进行钓鱼等。

上传绕过

2.1

为了避免文件上传漏洞，大多数网站都会对上传的文件类型做限制。尽管如此，但还是存在攻击者通过一些“手段“绕过上传限制的情况。


2.1.1

JS前端绕过

以下示例为JS前端对文件上传类型做了限制，仅允许上传jpg、png、gif文件。

function checkFile() {

    var file = document.getElementsByName('upload_file')[0].value;

    if (file == null || file == "") {

        alert("请选择要上传的文件!");

        return false;

    }

       var allow_ext = ".jpg|.png|.gif";

    var ext_name = file.substring(file.lastIndexOf("."));

    if (allow_ext.indexOf(ext_name + "|") == -1) {

        var errMsg = "该文件不允许上传，请上传" + allow_ext + "类型的文件,当前文件类型为：" + ext_name;

        alert(errMsg);

        return false;

    }

}

在文件上传点选择要上传的文件，选择php文件提示如下。

既然“前门”不通肯定就会有人试试“后门”，选择符合要求的文件类型上传并抓包，修改文件后缀及文件内容后再放包，文件成功上传。


2.1.2

大小写绕过

前端校验不可靠，有些网站会在后端做校验。如下示例为一网站对上传文件类型做限制的代码。

if (file_exists(UPLOAD_PATH)) {

        $deny_ext = array(".php",".php5",".php4",".php3",".php2",".html",".htm",".phtml",".pht",".pHp",".pHp5",".pHp4",".pHp3",".pHp2",".Html",".Htm",".pHtml",".jsp",".jspa",".jspx",".jsw",".jsv",".jspf",".jtml",".jSp",".jSpx",".jSpa",".jSw",".jSv",".jSpf",".jHtml",".asp",".aspx",".asa",".asax",".ascx",".ashx",".asmx",".cer",".aSp",".aSpx",".aSa",".aSax",".aScx",".aShx",".aSmx",".cEr",".sWf",".swf",".htaccess",".ini");

        $file_name = trim($_FILES['upload_file']['name']);

        $file_name = deldot($file_name);

        $file_ext = strrchr($file_name, '.');

        $file_ext = str_ireplace('::$DATA', '', $file_ext);

        $file_ext = trim($file_ext);

通过源码可以看出，网站对上传文件后缀做了黑名单限制，但没有对后缀名大小写进行统一，此时就可以利用大小写进行绕过。


2.1.3

其他绕过

0x00绕过：在一些语言的函数中0x00为终止符，在上传文件时系统文件遇到0x00会认为文件已经结束。可以通过抓包将a.php.png 改成a.php_jpg(下划线为0x00)。从而导致服务器将a.php.jpg的内容识别为a.php。


MIME类型绕过：服务器通过对Content-Type的内容检测以判断文件类型是否合法，可通过修改数据包Content-Type的内容实现上传绕过。


文件头绕过：服务器根据文件头判断上传文件的类型，可在上传文件前加入合法文件头实现绕过，如：GIF89a

服务器解析

2.2

常见的解析漏洞有Nginx解析漏洞、IIS解析漏洞、Apache解析漏洞等，这些漏洞看起来只是服务的自身特性，与文件上传结合起来却是1+1>2的效果。


以nginx配置不当导致的文件解析漏洞为例，在nginx配置fastcgi使用php时，会出现文件解析问题，如a.png文件以a.png/b.php形式访问，由于nginx直接根据后缀直接把b.php交给php处理，导致服务器把a.png文件以php文件形式解析。



IIS解析漏洞：以IIS6为例，当上传的文件为a.asp;b.png，由于”;”将文件名截断，IIS6会将文件解析为a.asp。此外上传文件到带文件名后缀为.asp的文件下也会被IIS6当成asp文件解析，即a.asp/b.png中b.png会被解析为asp。

第三方应用

2.3

此外还有很多使用第三方应用导致的文件上传漏洞，如编辑器、办公系统的文件上传漏洞等等。


以编辑器为例，为了方便网站的编辑，很多网站都会使用第三方的编辑器，常见的编辑器有xhEditor、eWebEditor、UEditor、CKEditor、KindEditor等。有些编辑器就曾被发现存在文件上传漏洞。如Kindeditor编辑器漏洞，仅使用下面这条简单的命令即可上传文件至服务器。

curl -F "image=@1.html" http://vulnerable.com/kindeditor/asp/upload_json.jsp?dir=file

03

文件上传漏洞防护


文件上传漏洞“姿势“千姿百态，以上所述仅仅是冰山一角，在了解了文件上传漏洞的一些基本方法后，我们就可以有方向的采取漏洞防御措施。


设置上传限制

3.1 

如非必要功能建议关闭网站文件上传功能。也可采取以下措施降低文件上传带来的危害：

1、对网站做严格的白名单文件上传限制，仅允许上传必要的文件类型。

2、对上传路径的文件去掉可执行权限，设置为只读权限。

3、执行上传操作后不要返回文件路径，上传至服务器的文件路径及文件名要以随机字符串命名。


加强系统维护

3.2

实时关注威胁情报预警，对涉及相关漏洞的系统、应用等及时做好对应的修复处理。及时更新版本、官方发布的漏洞补丁等。


定期对网站系统进行安全扫描，及时修复漏洞。


使用安全防护设备，定期对安全设备巡检，对可疑入侵行为及时排查。


04

结语


没有绝对安全的系统，文件上传漏洞带来的问题不容小觑，我们都应该加强网络安全防范意识，对已知的漏洞坚决“扼杀”，对未知的漏洞时刻“戒备”，防患于未然。
