本周我们分享一篇发表在ICSE 2022上的利用深度学习框架对于Python程序进行类型预测的工作：Type4Py: Practical Deep Similarity Learning-Based Type Inference for Python。一作是来自Delft University of Technology的Amir M. Mir。

现如今以Python为代表的一众动态类型语言火爆兴起，相比于静态类型语言，动态类型语言由于具备更为灵活的类型规则从而有利于减小开发难度并缩短开发时间，但灵活的类型规则在带来便利的同时也会导致程序中更多由类型导致的错误。为了弥补这一缺陷，Python官方发布了PEP484，在Python3.5以及之后的版本当中，引入了静态类型标注这一功能来帮助进行静态类型推导。但静态类型推导这一技术本身存在两个缺陷:

  • 第一项其一是由于动态类型语言复杂的语言特性所导致的不准确;

  • 其二是由于其本身需要考虑整个程序以及程序的所有依赖项，导致其速度较慢并可能花费大量计算资源。

由于以上两点原因的存在，目前学界将动态语言的类型推导这一任务的研究重心放在了基于机器学习的框架中。自2015年起，就陆续有工作针对不同的动态类型语言提出相应的基于机器学习框架的类型推测方法，但目前的各类方法总体上均存在以下两点问题：

  • 首先，在对于模型进行训练之前，需要人为的进行类型信息标注的工作，而在这一步过程中可能会引入错误的类型标注从而影响之后的训练以及评估与测试；

  • 其次，目前已有的方法都无法很好的在较高的顺位推荐出正确的类型，也就是类型推导的准确性较低，而一般在用户使用类型推导工具时会更倾向于选择排名更为靠前的推荐，因此这项缺陷会大大影响类型推导工具的实际使用性能。

而这篇文章则针对以上两点存在的问题，提出了相对应的解决方法。

Type4Py首先从Python源代码转化而来的抽象语法树中提取了三类不同的类型提示信息，分别为：


  • Natural Information，变量名，函数名，参数名；

  • Code Context，变量与参数的上下文调用情况，函数返回语句；

  • Visible Type Hints，程序之间的依赖关系图。

在得到了以上三类信息之后，将这三类信息通过自然语言处理以及word embedding技术转换为向量传入2-RNN网络之中，经过网络运算后得到存有element成为每种类型的可能概率的向量，最后经过线性全连通层来生成类型聚类，相似类型的elements会更为靠近。在查询阶段会采用KNN的搜索来返回被查询对象的推测类型。

本篇文章除了提出Type4Py模型之外的另一大贡献是在测试阶段生成了ManyTypes4Py这一测试集。研究团队在对原始测试集进行代码去重，类型标注之后还添加了一步类型检查的过程来去除错误的类型标注信息，从而解决了上述提到的现有工作的第一个普遍问题。而针对第二个普遍问题，这篇研究工作选用了mean reciprocal rank (MRR)评估指标：

该指标普遍用于搜索算法的测试当中，简单来看模型给出正确预测的排名越高，MRR给予模型的分数则越高。利用此评估手段则可以有效观察类型推导工具的准确性。

该工作的实验阶段主要关注了以下三个方面：

  • Type4Py的整体类型推导能力；

  • Type4Py针对不同类型推导任务的表现，比如推导变量类型，推导函数返回类型等；

  • 三种类型提示信息对于Type4Py模型的影响大小。

针对第一点的实验结果如下图所示：


实验中主要对比了另外两个基于机器学习框架的Python类型推导工具：Typilus与TypeWriter，其中Typilus的实现使用的是GNN网络，而TypeWriter的可推导类型范围较小。从实验结果可以看到Type4Py整体的类型推导能力还是要强于其他两个工具，对于超常见的变量类型的一次预测成功概率更是达到了喜人的100%。唯一不足之处是在推导罕见类型时的准确率不如Typilus，而导致这一点的主要原因可能为在生成类型聚类时过于激进，合并了一些罕见类型。

针对第二点的实验结果如下图所示：

从整体来看Type4Py在进行不同的类型预测任务时都具有较好的表现。而TypeWriter在面对常见类型的参数以及函数返回值的推导任务时稍稍优于Type4Py，导致这一点的主要原因是Type4Py相比于TypeWriter具有更大的可推导类型范围，牺牲了一小部分推导精度但在整体设计上更为优秀。

针对第三点的实验结果如下图所示：

该部分实验设计思路很清晰，分别去掉每个类型提示信息再对模型进行训练以及评估。从结果可以看到，在去掉code context后模型预测准确度下降最为严重，其次为visible type hints，最后为natural information，从而验证了这三者对于模型训练的重要程度依次递减。

该工作与之前最新的工作：Typilus相比最为重要的一点就是用RNN来替换了GNN，这使得类型提示信息可以被充分的映射到高维的向量空间中而非如GNN网络一般将类型提示信息过分的压缩到定长的向量中从而影响训练。

目前Type4Py源码在github开源，并配套有实验所用数据集ManyTypes4Py。在实际应用场景中，Type4Py被转换成了ONNX model以便支持GPU以及CPU上的快速运行。除此之外，工作团队还向社区提供了Type4Py的Web服务，以及Vscode插件以供开发者进行类型推导。
