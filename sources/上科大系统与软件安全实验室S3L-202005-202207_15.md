# 每周一篇paper赏析： Matrix Multiplication: Verifying SUSP:寻找大SUSP加速矩阵乘法

本篇文章发表在SAT 2020上，作者为Matthew Anderson，主要研究矩阵乘法复杂度中，如何寻找更大的Strong Uniquely Solvable Puzzle（SUSP）的方法，从而减少矩阵乘法的复杂度。接下来我们将介绍矩阵乘法以及SUSP的相关背景。  

  

在线性代数中，矩阵乘法是最基础的运算方式之一。两个n\*n的矩阵相乘时，传统的计算方法中，结果矩阵中的每一个元素都要通过原矩阵中的一行和一列相乘得到，因而整体的复杂度为O(n\*n²)=O(n³)。1969年，Volker Strassen基于递归分治的思想，提出了O(n^(2.808))复杂度的矩阵乘法算法。在其后，新的矩阵乘法算法不断被提出，如下图所示，到2014年，复杂度已经被缩减到了O(n^(2.3728639))。

  

![](../Images/81dc829d5e013a4e58f5554fabc6e5b4.png)

  

我们知道，由于我们至少要遍历所有的矩阵元素，矩阵乘法算法复杂度O(n^ω)中ω一定大于2，但我们依然不知道ω的理论下确界，这仍然是个开放问题。

  

Cohn在2005年证明了如果我们能找到一个s\*k的SUSP，我们便可以将n\*n矩阵乘法的矩阵乘法算法复杂度O(n^ω)中的指数项ω缩减到一个数值，这个数值和s, k相关，如下图所示。其中m为一个任意的大于二的整数，在找到一组s, k之后，我们取不等式右侧关于m的最小值。

  

![](../Images/b8460b098e15c4a6b209c0782d67a19e.png)

  

接下来我们介绍什么叫做SUSP。

  

首先，一个(s, k)-puzzle是集合{1,2,3}^k的一个长度为s的子集。如下图所示，P为一个(5, 4)-puzzle。我们可以将其理解为一个行与行之间没有顺序的矩阵。

  

![](../Images/8c8f2d9cbd0b34db618de2aa060b389a.png)

  

如下图所示，我们将这个矩阵中的1、2、3单独拆成三个子puzzle，同一行之间对齐，并尝试对每个子puzzle单独进行行与行之间的交换。

  

![](../Images/4e5e4e1e782d3b0d5893c00cd819c0a0.png)

  

对于1所属的子puzzle，我们不进行交换，其交换策略为π[1] = (1)(2)(3)(4)(5)。

  

对于2所属的子puzzle，我们将第二行换到第三行，第三行到第五行，第五行到第二行，首尾相接，所以其交换策略为π[2] = (1)(2 3 5)(4)。

  

同理，对于3所属的子puzzle，π[3] = (1)(2 5 3)(4)。

  

通过以上三次交换，如下图中间三个puzzle所示，我们得到了三个新的子puzzle。我们将这三个新的子puzzle合并起来，得到了下图最右侧的新puzzle，我们发现这个新的puzzle没有任何一个位置是有数字重合或者空缺，在这种情况下，我们将这三个子puzzle的变换方式称为这三个子puzzle的一个解。

  

![](../Images/3909368c4ca2040311fc08e40a38332c.png)

  

这样，三个子puzzle就有了上图最左边和最右边两个解。我们就说最左侧的原始puzzle不是一个唯一解（Uniquely Solvable Puzzle）。

  

我们进一步对这个定义加强约束，我们规定，若一个puzzle是一个Uniquely Solvable Puzzle，并且对其他任何的子puzzle的行交换策略，其都存在某一行的某一一个位置有恰好两个数字重叠，那我们将这个puzzle称之为Srong Uniquely Solvable Puzzle(SUSP)。下图为SUSP的标准定义，其中Sym[p]为P的所有行交换策略，π[1 ](r)为实行交换策略π[1]后的行r，以此类推。

  

![](../Images/31ce32b940153e748116e009fdf51776.png)

由于puzzle的行与行之间是无序的，我们可以将第一行的顺序固定下来，转化为：

  

![](../Images/93c8e6b4b98b49389b2fc5b854ded8b1.png)

  

注意上图中红色的部分，给定一个puzzle P，我们可以提前算出所有符合该条件（该行中有一个位置数字个数不为2）的对子puzzle进行行交换并重新组合后的行的集合T[p]，其中每一个行都是由从三个1、2、3的子puzzle中分别挑选一行组合而得到的，对于给定的π[2]、π[3]，我们将这一行记为（r, π[2](r), π[3](r)）。由于要遍历所有的组合，并遍历每一行中的每一个位置，计算T[p]的的时间复杂度为O(s³\*k)。这样，我们可以将其等价转化为：

  

![](../Images/78188b354327985db50f30dbe528c684.png)

  

若采取暴力搜索的方式，我们要遍历所有的π[1]、π[2]及其二者的组合,复杂度为O((s!)²),加上后面计算T[p]的复杂度，总的复杂度为O(k\*s³\*(s!)²)。显然，对于稍大的s，这个复杂度都是对于现代计算机来讲无法接受的。因此，我们要考虑一些不同的手段去优化解决这个问题。

  

该问题可进一步转化为3D-matching问题。首先用一个例子介绍一下3D-matching问题，假设有n个男人、n个女人、n只宠物，他们之间要相互选择组成一个家庭（一个男人、一个女人、一只宠物），若有一组男、女、宠物都觉得彼此合适，我们就把他们三个互相连接起来，形成一个三角形（超边）。给定这样的一个图（注意一个个体可能同时在很多个三角形中），3D-matching问题希望能够找到一组匹配，使得每个个体都能有且只有一个家庭。

  

在SUSP的问题中，我们可以将一组互相觉得合适的男人、女人和狗具体化为T[p]中的一个元素——一组三个子puzzle中行的组合。我们的最终目标是要在T[p]中找到一组子puzzle中行组合的方式，从而使得每个子puzzle中的每一行都能被匹配恰好一次，这样就能也就找到了一组符合条件的π[2]和π[3]。

  

3D-matching问题是经典的NP-complete问题之一，本篇文章接下来用多种方式尝试解决转化后的3D-matching问题。例如可用动态规划和二分搜索解决，或将其转化为3-SAT问题后用SAT solver解决，或者转化为Interger Programming问题后用优化工具Gurobi解决，有兴趣的读者可以查看原文章进一步了解，这里限于篇幅不作赘述。

  

除此之外，作者还根据SUSP的性质，介绍了一系列的启发式算法来进一步提升算法性能，这里介绍一个作者认为最重要的启发式算法。

  

首先，若一个puzzle P是一个SUSP，那么其任意的子puzzle P′ ⊆P也是一个SUSP。我们可以这样理解这个引理，将集合P-P′中的行不作行交换，此时剩下的交换策略依然会符合SUSP的定义，也就是说P′依然是一个SUSP。

  

根据这个性质，在判断较大的Puzzle时，我们可以并行的抽取其中的几行，判断它是否为SUSP，若不是，我们可以断言这个较大的Puzzle也不是SUSP。

接下来作者做了两件事，一是寻找给定k值时，s的最大值；二是寻找尽量大的SUSP，从而缩小ω的值。

  

对于寻找给定k值时，s的最大值，给定k时，我们知道有3^k个不同的行。作者采取了枚举他们所有的组合的方法，然后再调用前述判断是否为SUSP的算法，所以复杂度较高，因而如下图所示，作者最大只给到了k=6时的s最大值。

  

![](../Images/754e22821b6190252576b4dafd174fb8.png)

  

对于k>6的值，虽然没有给出确定的s的最大值，但作者同样给出了一个计算出的s的下界，如下图所示，计算出的s下界比之前的相关工作提升了很多。

对于寻找尽量大的SUSP，对于给定的s, k值，作者采用了随机产生一些puzzle，然后判断他们是不是SUSP的方式。如下图所示，横轴为s的大小，图中的width为k的大小，虚线代表在当前的s, k值下检查为SUSP的puzzle占所有随机产生的puzzle的比例。我们可以看到，其混合算法的工作效果整体上是最好的。

  

![](../Images/d35b875d45aa3c0badb097b1a87b1e43.png)

  

最后，这篇文章虽然没有能够在当前的计算机算力下计算出一组s，k使得我们可以进一步缩小ω的值，但提出了一个判断SUSP的框架，让我们看到了在未来，随着算力的提升，或通过进一步优化算法，找到更快速的SUSP寻找算法，从而缩小ω值的希望。
