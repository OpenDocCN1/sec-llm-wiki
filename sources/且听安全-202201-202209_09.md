**漏洞信息  
**

  

![](../Images/f1921f19472c1e7a60dc789defb0fd49.png)

  

Django 数据库函数 \`Trunc\` 和 \`Extract\` 主要用于进行日期操作，定义如下：

  

![](../Images/17faf66600089a2ff6b07a5cbca424d0.png)

  

![](../Images/81242f333cf77608144e470b9ad3e7de.png)

  

\`Extract\` 用于提取日期，比如我们可以提取日期字段中的年、月、日等信息， \`Trunc\` 则用于截取，比如 \`2000-01-01 11:11:11\` ，可以根据需求获取到日期 \`2000-01-01\` 。如果将未过滤的数据传递给 \`kind\` 或 \`lookup\_name\` 时，将会出现 SQL 注入漏洞。影响版本：

  

*    Django 3.2.x prior to 3.2.14
    
*    Django 4.0.x prior to 4.0.6
    

  

**补丁对比  
**

  

在 Django 新版本 \`operations.py\` 的 \`BaseDatabaseOperations\` 类中新增了 \`extract\_trunc\_lookup\_pattern\` 正则表达式：

  

![](../Images/72c708239e409808193e6e4c2267d969.png)

  

然后在 \`datetime.py\` 的 \`Extract\` 和 \`Trunc\` 类中 \`as\_sql\` 函数分别加入了对 \`self.lookup\_name\` 和 \`self.kind\` 参数的正则表达式检查：

  

![](../Images/e34a869fd1175b93c087ddfb986bc41b.png)

**漏洞分析  
**

  

以 \`Extract\` 为例，构造请求 \`/extract\_test/?lookup\_name=year\` ，顺利进入 API 函数入口：

  

![](../Images/7d081ecfa43a49c52ceefd8474863278.png)

  

在 Django 框架自带的 ORM 模型中，当进行 SQL 查询操作时，将调用 \`\\django\\db\\models\\query.py\` 的 \`QuerySet\` 类中对应方法进行处理。比如 \`Demo\` 中的查询将调用 \`QuerySet#exists\` 函数：

  

![](../Images/9b06d2efb8f95bf58a32c86222b8decc.png)

  

经过多次传递后，进入 \`SQLCompiler#compile\` ：

  

![](../Images/95724d4a44f647abf344d07ddb8001f2.png)

  

最终到达此次存在漏洞的 \`Extract\` 类中函数 \`as\_sql\` ：

  

![](../Images/afa79acadc1d7791d2e9d7dde032f926.png)

  

因为 \`demo\` 中选择的字段 \`start\_datetime\` 属于 \`DateTimeField\` 类型，所以将进入第 \`58\` 行的 \`datetime\_extract\_sql\` 函数：

  

![](../Images/cefea3814be1c783ad93f9f28c2e3357.png)

  

跟进 \`date\_extract\_sql\` ：

  

![](../Images/48188f3e627af059da9ca4bf5a891cd7.png)

  

\`date\_extract\_sql\` 函数将根据输入的 \`lookup\_type\` 取值生成不同的 SQL 语句，比如 \`demo\` 中设置为 \`year\` ，最终返回如下 ：

  

![](../Images/fd52a82a56eaf15bf5b1c58aba7eee8f.png)

  

![](../Images/bf8cc8f06bd2b72ce22a489d87f65e0a.png)

  

对来自 GET 请求的 \`lookup\_name\` 参数只是完成大写转换，但没有进行任何检查，直接拼接到 SQL 查询语句中，存在注入漏洞：

  

![](../Images/d0a12e03c73aebc679e5db8098afa730.png)

  

![](../Images/ab89253f39218abc71c929eaebfb94c4.png)

  

报错回显测试：

  

![](../Images/06ec2d93550d283b2c9edc54edf4742e.png)

**

  

前面补丁对比已经提到，新版本中对传入参数新增了正则表达式检查规则。
