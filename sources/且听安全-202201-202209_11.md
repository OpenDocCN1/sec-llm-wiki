**漏洞信息  
**

  

![](../Images/1e6c321b28d01c156b173b5a5f072a6a.png)

  

Atlassian Jira 存在服务端伪造请求漏洞 CVE-2022-26135，该漏洞是由于 Mobile Plugin for Jira 组件造成的，攻击者可通过 Jira REST API 发送特殊请求，从而发起 SSRF 攻击。

  

**漏洞分析  
**

  

 CVE-2022-26135 漏洞触发的 API 接口位于 \`com.atlassian.jira.plugin.mobile.rest.v1\_0.BatchResource\` ：

  

![](../Images/cff2ba16d1f39e06541280f2800ef097.png)

  

存在名为 \`executeBatch\` 的接口函数：

  

![](../Images/1cdb1e91218afee5f024dba7cc0dc07a.png)

  

进入 \`BatchService\` 接口的实现类 \`BatchServiceImpl\` ，定位函数 \`batch\` ：

  

![](../Images/44536bba5dc623e009e0a0a0042a654b.png)

  

跟进 \`execute\` 函数 ：

  

![](../Images/c1a567415035596d3e10372c20735e27.png)

  

\`relativeLocation\` 来自于 \`requestBean\` 中的 \`location\` ：

  

![](../Images/9327009d58ed03a8271e9a7c5c05279a.png)

  

接着传入 \`toJiraLocation\` 函数：

  

![](../Images/beaaebb8b7354beacb7c9d2f41e2e1b1.png)

  

![](../Images/799a14acae18a51020c1bfb68c105c2b.png)

  

\`path\` 来自于输入参数 \`location\` ，是完全可控的。回到 \`execute\` 函数，获取到 \`URL\` 对象后，最终会调用 \`httpClientProvider\` 发送 HTTP 请求：

  

![](../Images/69b9a49c687c87627bb5a4b3babfaca6.png)

  

因为 \`URL\` 后半部分是可控的，如果设置 \`location\` 为 \`@a.com\` ，那么 \`URL\` 最终为 \`http://jiraserver.com@a.com\` ， \`httpClientProvider\` 实际是向 \`a.com\` 发送 HTTP 请求，导致出现 SSRF 漏洞。

  

**修复方式**

  

![](../Images/61a199825436db54fef783efc6db65bf.png)

  

在 \`BatchResource#validate\` 函数中新增了对参数的验证：

  

![](../Images/5b40fdc0034681bc5104b0b0ce22228e.png)

  

\`UriUtils.arePathsSafe\` 函数也是在新版本中加入的，定义如下：

  

![](../Images/be9347a74e6b765a6c59da40b8a0ceb5.png)

  

新增正则表达式规则 \`PATH\_TRAVERSAL\` 对 \`location\` 参数进行检查。
