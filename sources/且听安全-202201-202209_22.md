**漏洞信息  
**

  

最近在网上看到 Nexus Repository Manager 爆出存在所谓的认证绕过漏洞 CVE-2022-31289：

  

![](../Images/1b00a1aff83c129b9b2c650784668812.png)

  

经过分析发现这其实是一个“伪绕过漏洞”。后来看到网上也有文章指出这确实是一个伪漏洞：

  

> CVE-2022-31289: Neither Bug nor Vulnerability
> 
> https://blog.sonatype.com/nexus-repo-issue-neither-bug-nor-vulnerability

  

自己本着好玩的心态“复现”了一下这个伪漏洞![](../Images/fd6cb9b72dcd5aeb2a692db04b43b008.png)。

  

**环境搭建**

  

采用 docker 来搭建环境，下载 3.37.1 版本的 docker 镜像：

  

![](../Images/ad83207ca41b6acee570cb6ea531a4c9.png)

  

通过命令行成功启动。

**漏洞复现**

  

首先点击登录系统：

  

![](../Images/8f5ac67fb05be8f1e75eca61c8c4e2b7.png)

  

使用 burpsuite 拦截 Response 响应请求：

  

![](../Images/7960b836fcc3b273cbf97b0f1b665c52.png)

  

将返回的状态修改为 \`HTTP/1.1 200 OK\` ：

  

![](../Images/d7fe5023a5493062009d22d1ef2af168.png)

  

点击 Forward 按钮，提示 \`admin\` 用户成功登录：

  

![](../Images/a96ac92a7323c4db5658e09916ffe873.png)

  

这实际上仅仅修改了客户端认证，也就是一个伪登录而已，依然无法访问后端其他的接口：

  

![](../Images/8af4d3a991b01477829124194137adeb.png)
