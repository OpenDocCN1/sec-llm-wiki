**漏洞信息**

  

Photo Gallery 是一个拥有 30 万以上安装量的主流 WordPress 插件：

  

![](../Images/d7fbb127798d7a273cd0061cc9fb508f.png)

  

WordPress  Photo Gallery 插件 v1.6.3 以下版本存在匿名 SQL 注入漏洞 ，编号 CVE-2022-1281。

**漏洞点分析**

  

WordPress 安装过程可以参考之前公众号的文章。下载 Photo Gallery 插件 v1.6.2 版本并完成安装：

  

![](../Images/fc2bc25fe4dc8f53cc21d58cca771943.png)

  

首先进行补丁对比，其中位于 \`\\frontend\\models\\BWGModelGalleryBox.php\` 中类 \`BWGModelGalleryBox\` 的函数 \`get\_image\_rows\_data\` 的修改值得关注：

  

![](../Images/f9cd67c6ec7729726005eb9944c9af18.png)

  

主要是对参数 \`$filter\_tags\` 的数据类型进行了限制：

  

![](../Images/5df008bf2935c381d15d7e6f7fa47246.png)

  

\`$filter\_tags\` 来自于 HTTP 请求的参数 \`filter\_tag\` ，接着往下看：

  

![](../Images/5bf6e41e2cd79c7fc5a0b12ceb1b2faa.png)

  

没有进行任何过滤检查，直接将 \`$filter\_tags\` 拼接进入了 SQL 语句中，从而导致出现了注入漏洞。

**调用链构造**

  

下面搜索下函数 \`get\_image\_rows\_data\` 被调用的情况：

  

![](../Images/806f6311870814d96791df1fe1e56b48.png)

  

经过分析，位于 \`BWGViewGalleryBox#display\` 中的调用值得关注。接着直接搜索 \`BWGViewGalleryBox#display\` 调用关系不太理想，先回过头看一下 Photo Gallery 插件的启动过程。在 \`photo-gallery.php\` 文件中通过 \`add\_actions\` 函数注册了很多 WordPress Ajax 请求接口：

  

![](../Images/6ae4abc54aeb60dd18be9e729b5a9f0a.png)

  

其中的 \`wp\_ajax\_GalleryBox\` 和前面分析的 \`BWGViewGalleryBox\` 从命名上看可能存在某种联系，重点进行分析，定位其处理函数 \`frontend\_ajax\` ：

  

![](../Images/1b3ee650326d9d0c2012091dca1d49db.png)

  

请求接口将提交的 \`action\` 参数进行了限定，并且根据取值的不同分别加载不同的控制器类，当 \`action\` 为 \`GalleryBox\` 时，将加载 \`BWGControllerGalleryBox.php\` 文件，并调用其中的 \`BWGControllerGalleryBox#execute\` 函数，跟进：

  

![](../Images/112163ef5512125634e855b8bc2636dd.png)

  

接着调用 \`BWGViewGalleryBox#display\` 函数，正好与前面分析的 SQL 注入触发点连接起来了，构造出完整漏洞触发链。
