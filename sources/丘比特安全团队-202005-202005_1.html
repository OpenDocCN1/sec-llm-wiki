0x01

什么是延迟绑定


    延迟绑定是动态链接过程的优化

  在程序模块中一般存在大量的函数引用，如果在程序开始执行时便将所有的函数引用进行符号查找及重定位，则会浪费大量的时间在链接的过程中，影响程序的执行。实际上在函数执行的过程中，大量的函数引用可能在执行中不被用到，所以延迟绑定的机制就诞生了

    延迟绑定就是在程序中用到函数时进行绑定，没有用到的函数不进行绑定。即用即取

    ELF文件的延时绑定通过PLT( Procedure Linkage Table)和GOT(Global Offset Table)实现

0x021 示例程序 

// resolve.c#include<stdio.h>#include<unistd.h>#include<stdlib.h>#include<string.h>#define MAX 1024// 以read()函数的延迟绑定为例int main(void){    char *p;    int rt;    p = (char*)malloc(MAX*(sizeof(char*)));    memset(p,0,MAX);    printf("Please enter the string in the buffer:\n");    rt = read(0,p,MAX);    printf("The output of the buffer is:\n");    for (int i = 0; p[i] != '\n'; i++)    {        printf("%c",p[i]);    }    printf("\nbye!\n");    free(p);}


0x022 基础分析 

编译链接生成resolve

gdb加载resolve程序，观察read函数的命名特点: read@plt

可知相关外部函数引用的绑定通过PLT实现

现代操作系统不允许修改代码段，只能修改数据段

PLT: 存放动态链接的代码段

GOT: 存放地址数据

基于现代操作系统的特点，需要有中转过程来实现延迟绑定

查看PLT和GOT的权限

    GOT是具有写的权限的，并且是存放地址数据的区域，所以可以通过改写这一区块数据实现延迟绑定

0x023 进阶分析

分析之前先对基础分析的内容做下疑问归纳

1、PLT中存放的代码段是什么样

2、是谁改写了GOT中的数据

3、详细的流程是什么样

针对第一个问题，我们查看下read@plt函数的地址信息

我们观察到指令中最主要的指令是，jmp、push、jmp

在第一条jmp指令后有一个#0x601038的地址，关于这个地址我们可以通过objdump查看动态重定位入口

现在查看下这个地址的信息

我们可以清晰的看到0x00400556这个地址是0x400550的下一条地址即：push 0x4

通过objdump查看一下动态表

PLT节的第一项为公共PLT项，objdump在操作时将第一项命名为距离他最近的项的名字

看到跳转到公共PLT项，然后进行push操作，早进行jmp操作，查看jm地址信息

其值为0，然后我们运行程序，再次查看其值，发现其值已被改写

查看其值，我们发现了_dl_runtime_resolve_xsave这便是问题二中改写GOT的函数【关于_dl_runtime_resolve会在后续文章中做分享】

查看一下GOT表项，并查看其值

其值已被更改为read函数的真实地址

这样整个延迟绑定的过程就完成了，也就解决了问题三
