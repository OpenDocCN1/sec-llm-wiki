编者按：知道创宇创建了漏洞平台Seebug，并开始尝试在白帽子之间进行有价值漏洞的分享，促进漏洞公开透明交流。我们邀请了平台的主要负责人余弦，分享他对漏洞的看法，以及对漏洞交易的探索。

“这个世界有规则，不过是用来打破的。”

—— XEYE Team


2009 年，我创建了黑客团队 XEYE，在一次黑客大会上做了一个关于 XSS（跨站脚本攻击）的首次分享，当时我们已经把 XSS 玩得足够娴熟。会上，忍不住说了上面这句话。

打破规则的正是漏洞，漏洞世界观是一个漫长的沉淀过程，每个漏洞都应该有自己的灵魂，尤其是那些好洞。今天要和大家分享的是我的漏洞世界观。

漏洞过程

关于漏洞挖掘的成就感，垃圾漏洞就不提了，并没什么成就感。真的有成就感的是：不仅挖了，而且总结了模式写了脚本 Fuzzing，然后写了两年漏扫，接着明白基于主动爬虫漏扫的天生缺陷，于是乎写了半自动化挖洞框架（半成品），这样的好处是融入了人的逻辑思考，能更系统地总结目标场景缺陷，也能挖到更多好洞。

其实到这一步，还达不到我期望的成就感，要明白下面这个过程的重要性：

Bug ->漏洞 ->PoC ->Exp -> Attack

这是一个漂亮的漏洞过程或黑客过程，每个环节都充满艺术性。你说你佩服挖洞厉害的人？就如爱因斯坦那样；其实我还敬佩搞出原子弹的奥本海默以及他的团队，这是漏洞到PoC到Exp的过程；我还敬畏投下原子弹的这个团队，这是 Attack 的过程。

PoC指：漏洞概念验证，仅仅是验证是否有漏洞；Exp全称 Exploit，指漏洞利用，在验证的基础上进入实际利用；Attack指：攻击过程。

就我来说，挖到的经典漏洞大多经历了这个“Bug ->漏洞 ->PoC ->Exp -> Attack”的生命周期。

漏洞的商业力量

上面这个漏洞过程多少具备技术人典型的英雄主义情结，当过了这个阶段后，我们的思考就需要跳出来，不再是纯粹的技术人，而应该融入商业思维。

好洞是挖不完的，洞分几十种，一个人再强也没法面面俱到，靠一个团队也很难达到这种水平。可是商业的力量却可以，早年黑客说不谈商业，怀念早年的单纯，这种话不信也罢。

有谁认真思考过老牌 0DAY 交易厂家 ZDI 的商业模式？有谁认真思考过地下 0DAY 交易平台 1337DAY 的商业模式？有谁认真思考过HackingTeam的 0DAY 及相关工具的商业模式？有谁认真思考过新秀 0DAY 交易厂家Zerodium的商业模式？

看看Zerodium公布的这张图：

全是好洞，苹果iOS的一个 Remote Jailbreak 值 320 多万人民币，最低的 Joomla 一个 Remote Code Execution 就值 65000 人民币。

他们的商业模式本质都是“提供一个可信的平台，收取漏洞交易过程中的差价，并可能在平台之下，悄悄做些商业转换”。

这些年流行的口号，正好诠释了一个漏洞的价值：No More Free Bug，No More Cheap Bug。

好的商业模式带来好的漏洞流通。这种成就感才是终极追求。

阳光下的漏洞交易

这是我们正在做的一种商业模式，希望和大家分享讨论。2015年9月开始，我们打造的漏洞平台Seebug开始尝试一种新颖的漏洞商业模式：阳光下的漏洞交易。

Seebug在过去的九年，积累了大量漏洞，这些漏洞都是具体组件的漏洞，我们称之为通用型漏洞，通用指的是：这个漏洞可以影响多个目标（如网站、服务器、设备、PC、手机等），而相对应的另一类漏洞是事件型漏洞，比如“某某网站存在 SQL注入导致百万用户资料泄露”，这种漏洞往往是针对具体某个目标的。

Seebug上积累的通用型漏洞有5万多，这个数字对于我们来说已经很大，而其中真正有价值的历史漏洞实际上差不多5000左右。对安全人员来说，看重的是这5000左右有价值的历史漏洞及之后新增的有价值的漏洞，而那些垃圾漏洞意义就非常小了，如果只是为了充数，那么带来的反而是干扰。

过去这一年，Seebug尝试对有价值的漏洞进行补贴，比如补贴白帽子提交的漏洞详情与PoC，以此促进更多优质的白帽子在Seebug上提交有价值漏洞需要的关键信息。同时，允许其他白帽子去购买提交者的漏洞详情与PoC，这种购买是点对点的。补贴与购买使用的都是Seebug平台自己的“货币”KB，每次购买实际上都是一次交易。

通过这种“曝光在阳光下”的交易模式，可以很好促进白帽子之间的漏洞价值转换，促进漏洞流通。不过这种交易模式还处在几个缺陷：

1.这种交易只是发生在白帽子之间，如果想更大促进白帽子的积极性，应该怎么做呢？这是Seebug下一步会进行改进的点；

2.漏洞交易存在一定的法律风险，法律问题应该如何规避？

漏洞交易确实存在一定的法律风险，谢君泽律师的文章《“漏洞”交易的法律思考——以法律价值观为视角》已经做了很全面的探讨，感兴趣的读者可以看看。虽然我的观点里，更倾向觉得应该合理对待漏洞交易，或者说只要漏洞交易的运转模式是良性的，都应该被鼓励。而对于漏洞平台来说，应该努力思考与规避可能存在的法律风险，并真的做到“良性”发展。

关于法律风险规避这块，Seebug做了一些事，如：

1.必要的免责声明；

2.交易对象里最具争议的也仅是PoC，这仅仅是漏洞验证，证明一个通用漏洞是否是真实的概念验证程序，离所谓的黑客工具还远着呢，也不会触碰到“传播黑客工具”这个刑法点。而且这里的PoC并没针对具体的目标，和上面描述过的事件型漏洞有很大差别；

3.在这个漏洞平台上的文字措辞上进行了必要优化，避免让一些人误会；

4.与相关监管机构构建合作关系，共同保障这个漏洞平台的良性运作。

最后

最后，我得提下，上面描述的漏洞过程本质上是一种“攻”的过程。如果只是“攻”，那么这个漏洞过程并不完整，最终得闭环到“防”，于是整个过程就变成了如下：

Bug ->漏洞 ->PoC ->Exp -> Attack ->Defense

“防”是我们做安全的最终目标，未知攻、焉知防，这就是我们为什么需要去了解“攻”。而如果引入了“防”，那么漏洞的商业力量将更加丰富更加有趣。

“攻”是一门艺术，“防”也是，商业化更是，这个过程再做好法律风险的规避，那么，漏洞的生态也将会是个良性生态，这里面，太多东西需要平衡了。

其实，平衡才是最大的一门艺术。（本文刊登于《中国信息安全》2016年第7期）
