Notes

题目直接给出了源码app.js

整个代码，我们要注意的地方是这些：

var express = require('express');
var path = require('path');
const undefsafe = require('undefsafe');//引用undefsafe
const { exec } = require('child_process');//调用child_process

这是这道题的关键，题目引用了undefsafe，而undefsafe函数在2.03版本下是有漏洞的。

CVE-2019-10795，是一个有关于原型链污染的漏洞。

所以也提醒各位同学，平时的CVE都要记录好，至少有个印象。

不过undefsafe函数是什么？

我们来举个例子！

var test={a:1};
console.log(test);
//a:1 正常显示
console.log(test.b);
//undefined 我们未定义b，当然回显undefined，也正常。
console.log(test.b.c);
//Uncaught TypeError: Cannot read properties of undefined (reading 'c')
//这个时候就出现问题了，我们确实没有定义b，更没有定义b的属性c，但它直接抛出错误了

抛出错误的时候，程序就会终止，那如果我们不想这样，那该怎么办呢？

我们就可以使用undefsafe，其实从函数名也可以看出来，我们的undefsafe就是防止这种情况的。

让我们看看效果

const undefsafe = require('undefsafe');
var test={a:1};
console.log(test);
console.log(undefsafe(test,'test.b.c'));
//undefined，得到了我们想要的结果，程序这个时候不会自动退出

但就是这样一个方便的函数，会对我们的原型链造成污染，再举个例子：

const undefsafe = require('undefsafe');
var test={a:1};
console.log(test.toString);
//[Function: toString]
var payload ="__proto__.toString";
undefsafe(test,payload,"just test");
console.log(test.toString);
//just test

也就是说，只要我们可以操控undefsafe函数的第二个与第三个参数，我们就可以污染object的任意属性。

这道题调也用了child_process，大家看了上道题应该就理解了，这个是我们实现命令执行的关键，此时我们的exec关键字就可以直接调用系统指令命令执行。

那么现在思路其实很明确了，找到undefsafe和exec两个关键字的所在位置，就是我们的重中之重。

调用undefsafe的一共有两个函数，get_note()、edit_note()。

get_note(id) {
        var r = {}
        undefsafe(r, id, undefsafe(this.note_list, id));
        return r;
    }
edit_note(id, author, raw) {
        undefsafe(this.note_list, id + '.author', author);
        undefsafe(this.note_list, id + '.raw_note', raw);
    }

第一个函数，显然可以控制的参数不够，那么第二个函数，就是我们可以操控的重点了，他可以传入三个变量，id、author和raw，刚好满足我们刚才说的，第二个、第三个参数。

那我们接着找exec所在的地方，也就是我们的status路由，也就是当你访问status这个网页路径下，会执行的操作。

app.route('/status')
    .get(function(req, res) {
        let commands = {
            "script-1": "uptime",
            "script-2": "free -m"
        };
        for (let index in commands) {
            exec(commands[index], {shell:'/bin/bash'}, (err, stdout, stderr) => {
                if (err) {
                    return;
                }
                console.log(`stdout: ${stdout}`);
            });
        }
        res.send('OK');
        res.end();
    })

这里使用了exec进行命令执行，然后调用的是bash解释器，执行的命令既是我们commands的所有属性。那么我们的目标很明确了，就是污染commands。

构造payload，目的是获取目录下的flag文件，然后反弹发送到外网的服务器上，当然也可以直接反弹shell，不过这两者都需要你有一台外网的服务器。
