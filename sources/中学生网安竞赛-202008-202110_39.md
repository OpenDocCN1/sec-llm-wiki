02

  

简单的分析  

经典的“菜单题目”

八个选项，除了message外还有top message

 

1.add message

2.show all message

3.delete message

4.set top message

5.show top message

6.delete top message

7.change top message

8.exit

  

03

  

结构总览

数据存储由三层结构体组成

 

msg-set保存msg-info结构，由一个msg-info变量和一个msg-info数组组成

 

msg-info存储msg的信息，以及指向真正msg内存的指针

 

message的大小由每次add时动态指定

 

msg-set为全局变量，msg-info和message存储在堆中，随着add动态生成

![](../Images/267c4ee4f83a28571905fc3ee02772cc.png)

04

  

msg-info  

  

used：message是否已释放，used的初始值为1，释放后置0

size：message的大小，在修改message时使用

msg：char \*指针，指向实际的msg内存区域

 used和size都使用了long长度，msg-info的大小为8\*3=0x18

![](../Images/b1140ff372889e5565ccc035a2507818.png)

  

  

05

  

Message  

![](../Images/d4771535dda3b6b6a5d7eeee03218628.png)

message存储在堆中  

message的数量上限由msg-set决定：Max=5

当使用add message添加message时，会遍历msg-set中的set数组，选取第一个未使用msg-info

删除message，修改message时使用idx指定message

index的值是动态的：在msg-set.set中的第一个msg-info的idx为1，紧随其后的idx为2，以此类推

07

  

其他的菜单选项  

  

show message & show top message：一个打印全部的message，另一个只打印top指向的message

delete message & delete top message：删除指定的message，或者直接删掉top指向的message

 

change top message：可以让top指定任意一个已经存在的message(将set中的指定msg-info拷贝到top中)

change top message：只有top指向的message可以被编辑

 

(虽然如此，但是我们可以指定top，所以间接地，每个message都是可以被编辑的)

  

08

  

悬指针漏洞  

![](../Images/e516330e049c333be2be4efa2adbbb10.png)

使用delete top message时，除了清空top的值，还会置空与top对应的set中的指针

 

使用delete message时，top没有被处理，top成为悬指针

 

在delete message后，使用change top message，我们可以向一块已释放的堆内存写入数据

 

Unlink攻击

  

09

  

程序信息  

已开启的防护：

 

ASLR：内核默认

NX：shellcode无效

Canary：和本题关系不大

 

未开启的防护：

 

PIE：不需要更多info-leak了

RELRO：覆写GOT的攻击是有效的

  

10

  

Glibc信息  

  

Glibc版本：2.24，不需要考虑tcache

 

题目提供了目标服务器的Glibc文件：不需要Dynamic Leak

 

装载随机化：默认开启，我们需要定位Glibc的基址

  

11

  

攻击思路  

  

存在可以利用的全局指针(msg-set)

GOT表可以被覆写

 

1.利用Unlink攻击，将msg-set.set中的某个指针指向msg-set.set自身

2.向被篡改的指针写入数据，将msg-set.set中的某个指针指向GOT表中的函数，比如free

3.继续写入，将free函数的地址修改为system的地址

4.触发“free”过程，通过在message中提前布置“/bin/sh”字符串，执行system(“/bin/sh”)
