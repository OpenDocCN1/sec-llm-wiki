先看看读入字符串后第一个执行的sub\_4012A0  

这个sub就是这题反调试的代码：

![](../Images/67bcacb6a53d6bca57fbef0032f2988b.png)

![](../Images/6ef07e242102af22047c82f2de521223.png)

很低级的方法，简单粗暴直白地调了两个API去检测调试器

所以OD有很简单的方法绕过这种检测，等会会展示一下

  

接下去看：

![](../Images/0c4cc50b78471e4a6d8e30e527ff6e56.png)

Sub401000是个strstr函数，这里就是检测输入的开头是不是

flag{，后半个条件就是判断最后一个字符是不是’}’

如果不是的话

![](../Images/a88f64cdbb9b1ceed2aa7dd4eb2d3033.png)

注意这里有几个算是隐含的条件吧，看一下函数里几个变量的的地址

![](../Images/028fb3625717502ba2b04f831db5b817.png)

Str地址为bp-38h

Src地址为bp-33h

v9地址为bp-13h

因此如果假设Str是个数组

&Src = &Str\[5\]

&v9 = &Str\[37\]

  

因此这里条件 v9==‘}’ 说明flag长度为38

（所以按照这里的判断如果在长度为38的flag后加些字符还是可以过验证）

  

继续往下

sub\_401360(&Dst, &Src, 0x20u);

进去看可以发现这里直接调用了一个strncpy函数

这里直接从输入的flag的第5个字符拷贝了32个字符到Dst

  

接下来 sub\_4011A0(&Dst);

这里对输入flag进行了第一次处理

![](../Images/4fba538c882d463799be6b32374ffd0e.png)

下面又调用了一次反调试检测，不再赘述

sub401220进行了第二次处理

![](../Images/31950b5c1173538f812900be2f0e5f0f.png)

![](../Images/09ff91999e51d571fb7154d9e48556e0.png)

这里a1的偏移量为4\*v5

是因为a1为int型变量，占用4字节

  

最后得到的a3跟23gjf13au98hk3a1090zp8qjs41h39jp进行比较

  

刚刚那段算法其实类似密码学里的置换算法，

a1为置换盒（S盒）

  

这里对置换算法不做赘述，反向求出置换算法明文的方法就是

求出逆S盒，S盒的地址为4030C0，内容为

4, 15, 11, 30, 14, 20, 31, 9, 

23, 2, 25, 28, 18, 16, 0, 8, 

17, 1, 21, 3, 10, 29, 12, 22, 

24, 13, 27, 5, 7, 6, 19, 26

  

可以用下面代码简单地求出逆S盒

myIP = \[4, 15, 11, 30, 14, 20, 31, 9, 23, 2, 25, 28, 18, 16, 0, 8, 

               17, 1, 21, 3, 10, 29, 12, 22, 24, 13, 27, 5, 7, 6, 19, 26\]

a = \[0\]\*32

for i in range(0,32):

a\[ myIP\[i\] \] = i

print a

  

逆S盒为

14, 17, 9, 19, 0, 27, 29, 28, 

15, 7, 20, 2, 22, 25, 4, 1, 

13, 16, 12, 30, 5, 18, 23, 8, 

24, 10, 31, 26, 11, 21, 3, 6

  

使用逆S盒，套用相同的置换算法可以由原来的密文输出明文

然后把结果跟403040处的数据异或即可得到flag

![](../Images/56e63772912ff6a00d06b4d11626499a.png)
