**1.**

![](../Images/8d3074a56f1223f69f7bd4f95dce9bcd.png)

题目首先创建了一个对我们传入的value参数进行逐位判断的for循环，显而易见，这里的value参数应该是一个数组，并且这个数组中的每一个元素应是大于32且小于127的数字,否则value参数会被进行unset()操作。  

**补充知识：**

*(PHP 4, PHP 5, PHP 7)unset — 释放给定的变量*

如果我们这里的value值满足了>32 and <127的条件，那么该元素经过chr()处理后会被拼接进$username字符串

**补充知识：**

*“chr() 函数从指定的 ASCII 值返回字符。”*

ASCII 值可被指定为十进制值、八进制值或十六进制值。八进制值被定义为带前置 0，而十六进制值被定义为带前置 0x。

02

  

解决题目  

自核心到表层的思考，想要得到flag,我们需要满足上文提到的两个条件

$username字符串需要”==”‘w3lc0me\_To\_xid1an’

嗯，是要得到这样一个字符串，那么我们找找代码中与$username相关的操作有哪些

![](../Images/d9a435334ab5eb78142443b2a083566d.png)

$username会被拼接字符，那我们是不是只要给value赋值相关字母对应的ascii值就成功了呢？答案是否定的，ascii字符取值为a-z：97-122，A-Z：65-90，0-9：48-57。  

显然因满足了 >32 && <127 的条件从而会被unset()掉。  

我们可以利用chr()的特性绕过限制：

**Chr()会对输入值模256处理**

即

Chr(99)===chr(99+256)

将value参数的值设为w3lc0me\_To\_xid1an所对应的ascii码加上256得到结果即可绕过该条件限制。

**补充知识：**  

intval()在处理16进制时存在问题,经过测试在intval(‘16进制字符串’,16)转换正常,而intval('16进制字符串')时会出错返回0,

只有对base进行相关设置,'0x123'此类字符串才会被作为16进制转换，否则按十进制转换;而在强制转换时,即intval($password + 1)时,里面的password+1时,已经做了转换,所以再用intval()函数时就不会出错
