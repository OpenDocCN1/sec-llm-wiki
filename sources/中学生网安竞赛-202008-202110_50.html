既然POST参数中用到了字符串“flag”，IDA搜索+交叉引用二连找到函数sub_14000B480


画箭头的函数是获取输入的函数。sub_14000AFA0应该就是验证函数了。动态调试走起。

不过注意sub_14000B250中新建了一个线程循环检测调试器（调用IsDebuggerPresent），所以提前patch处理一下，用x64dbg的兄弟们也可以使用HideDebugger命令绕过检测。

第二关的代码：

 

signed __int64 __fastcall sub_140032260(__int64 a1, char a2)//每次对输入的一位进行操作，a1是key，a2是当前操作的字符。

{

  signed __int64 result; // rax

  __int64 v3; // [rsp+30h] [rbp+8h]

  unsigned __int8 v4; // [rsp+38h] [rbp+10h]

 

  v4 = a2;

  v3 = a1;

  if ( isdigit(a2) )

  {

v4 = (**v3 + (v4 - 48)) % 0xAui64 + 48;

//有点像凯撒密码的变换方式，逆的时候注意一下正负（详细的写在脚本里了）

  }

  else if ( isupper(v4) )

  {

    v4 = (**v3 + (v4 - 65)) % 0x1Aui64 + 65;

  }

  else if ( islower(v4) )

  {

    v4 = (**v3 + (v4 - 97)) % 0x1Aui64 + 97;

  }

  std::basic_string<char,std::char_traits<char>,std::allocator<char>>::operator+=(*(v3 + 8), v4);

  result = **v3 + 1i64;//key++；

  **v3 = result;

  return result;

}

调试技巧：

1. 不要在读入字符串后马上就下硬件断点，因为输入可能被复制很多次，陷入系统的memcpy函数中就很闹心。

2. 主要看sub开头的函数，先忽略掉C++标准库的函数。执行完一个sub函数后，选中下一个sub函数F4运行到那，然后分析参数。如果有输入内容或者特殊字符串，就要特别注意。

3. 在函数运行前对参数字符串下硬件访问断点，可以快速定位到对输入的操作处。（别忘了用完了删除断点hhhh）

 

最后一关加密是sub_140032570，用上一关的密文每字节异或，前16位异或的是“Congratulations!”，后48位异或的是密文的前48位（这步可以直接在伪代码“v21 = *v10 ^ v20;”对应的汇编“xor ecx,eax”下断，就可以看到异或的key）
