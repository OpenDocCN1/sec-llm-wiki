1、背景简介


2015年7月30日，Vitalik Buterin和以太坊基金会创建了第一个基于区块链的图灵完备智能合约平台。这一天以太坊正式和公众见面。接着Sock.it设计了The DAO以太坊合约，并在2016年4月30日正式部署The DAO智能合约。



The DAO是一个去中心化的自治风险投资基金，通过发布的智能合约来募集资金，参与者可以通过投票的方式来投资以太坊上的应用，如果盈利，参与者就能获得回报。该项目在2016年5月27日完成了当时全世界最大规模的众筹，一共筹集了1170万以太币，并创造了当时众筹历史之最。


但The DAO项目由于智能合约的漏洞造成资金被黑客转移。2016年6月17日，The DAO被黑客攻击并盗取了大量的以太币(3,641,694 ETH)，让该项目蒙受了巨大的损失，这就是著名的The DAO攻击事件。



2、漏洞原理研分析


本节分析The DAO代码的缺陷，完整的代码可在Github网站上下载

https://github.com/TheDAO/DAO-1.0


让我们一起回顾下这次事故的主要原因——splitDAO函数


根据白皮书的设计，splitDAO的本意是要保护投票中处于弱势地位的少数派防止他们被多数派通过投票的方式合法剥削。通过分裂出一个小规模的DAO，给予他们一个拒绝的机制，同时仍然确保他们可以获取分裂前进行的对外资助产生的可能收益。


简单的说就：是用户拿钱给The DAO基金会投资，中间用户如果反悔可以随时退钱。


这里我们截取DAO.sol中splitDAO函数存在问题的代码段：

https://github.com/TheDAO/DAO-1.0/blob/master/DAO.sol#L668
function splitDAO(uint _proposalID, address _newCurator) noEther onlyTokenholders returns (bool _success) {    ...    //利用平衡数组计算应转移多少以太币并赋予新的代币    uint fundsToBeMoved = (balances[msg.sender] * p.splitData[0].splitBalance) / p.splitData[0].totalSupply;    if (p.splitData[0].newDAO.createTokenProxy.value(fundsToBeMoved)(msg.sender) == false)
        throw;    ...    // Burn DAO Tokens    Transfer(msg.sender, 0, balances[msg.sender]);    withdrawRewardFor(msg.sender);  // 转移对应的金额给用户    // XXXXX Notice the preceding line is critically before the next few    totalSupply -= balances[msg.sender]; //记录扣减DAO币总量       balances[msg.sender] = 0;   // 余额置为0    paidOut[msg.sender] = 0;    return true;}


在该段代码中，第14行中msg.sender和第13行中totalSupply等都发生在withdrawRewardFor函数之后，这就造成了Race-to-Empty攻击，此处不过多阐述，详细内容可参考该篇文章分析

https://vessenes.com/more-ethereum-attacks-race-to-empty-is-the-real-deal/


接下来跟进withdrawRewardFor函数，这里主要问题在于第7行paidOut[_account] += reward 放在了payOut函数调用之后


function withdrawRewardFor(address _account) noEther internal returns(bool _success) {    if ((balanceOf(_account) * rewardAccount.accumulatedInput()) / totalSupply < paidOut[_account])        throw;    uint reward = (balanceOf(_account) * rewardAccount.accumulatedInput()) / totalSupply - paidOut[_account];    if (!rewardAccount.payOut(_account, reward))    // XXXXX vulnerable        throw;    paidOut[_account] += reward;    return true;}


所以我们继续跟进payOut函数，发现代码第4行中对_recipient发出call调用


function payOut(address _recipient, uint _amount) returns (bool) {    if (msg.sender != owner || msg.value > 0 || (payOwnerOnly && _recipient != owner))        throw;    if (_recipient.call.value(_amount)()) { // XXXXX vulnerable        PayOut(_recipient, _amount);        return true;    } else {        return false;    }}


这里介绍两个需要用到call函数的知识点：

1、当call函数不加.gas() 修饰器时，调用默认会使用当前剩余的所有gas。

2、当call函数没有找到对应函数可调用时,会默认调用fallback函数。

https://solidity-cn.readthedocs.io/zh/develop/

所以当call.value(_amount)的时候，会把所有的gas发送到合约地址上并执行默认函数。此时call调用所执行的代码步骤数可能很多，且基本只受攻击者可用的gas限制。包括重新调用原合约的接口。


最后总结下整个流程：


用户提出分裂（退钱）—>合约计算应退款金额—>调用call函数发送金额给用户—>用户的账户余额归为0。


即先调用splitDAO—>splitDAO中调用withdrawRewardFor—>withdrawRewardFor中调用payOut执行转账。


将以上这些内容拼凑起来，就形成了一条完整的攻击链:


3、攻击手法研究


前期准备：攻击者先是通过自己创建了一个合约Child Dao，设定适当的gas，同时该合约带有一个匿名的fallback函数，该函数的作用就是将通过递归触发多次调用TheDAO中的splitDAO函数。


开始攻击：攻击者提出split proposal（退款申请），接收地址是Child Dao的地址，结合第二部分的代码分析，开发者的代码先是在函数withdrawRewardFor中调用payOut执行转账，把金额退还给了攻击者，该流程结束后在splitDAO函数中将用户的余额置为0。


关键点：但是攻击者在withdrawRewardFor和余额置为0这个过程之间，利用payOut中call函数fallback的机制，在合约中再次调用splitDAO，由于上一次转账申请的余额还没有更新置0，所以第二次转账申请也会成功，相当于在循环中进行递归调用。


简单画一个调用栈方便理解：

攻击者提交split proposal  ---> splitDAO函数（round 1）   ---> withdrawRewardFor函数（向child dao发起转账，此时余额未置零）     ---> papOut函数     ---> Child Dao调用fallback函数     ----------round 2--------------      --->调用split DAO函数（round 2）      ---> withdrawRewardFor函数（由于攻击者余额仍未置零，可继续转账）       ---> payOut函数        --->Child Dao调用fallback函数        ----------round 3--------------         --> 调用split DAO函数（round 3）         ---> ..........


由于可以反复的利用同一个split proposal进行攻击，这个漏洞的严重程度被放大了许多倍，使得攻击者可以在短时间内盗走大量的以太币。



4、后续


幸运的是，The DAO设计中有缓冲期，黑客控制的以太币要在27天后才可拿走，这留给了以太坊团队足够的应对时间。他们设计的解决方案分两步：

（1）采用软分叉(soft fork)技术，锁定The DAO及其子DAO的账号，不允许发生任何交易，相当于冻结了黑客的以太币，使其无法出售获利。软分叉实际上是在以太坊软件中增加约束性的规则（例如不允许某账号转账等），好处是不影响任何以太坊上已发生的交易，无需回滚区块链的数据。


（2）实行硬分叉(hard fork)技术，以太坊团队修改了以太坊合约代码实行硬分叉，在第1920000个区块强行把The DAO及其子DAO的所有资金全部转到一个特定的退款合约地址，进而“夺回”了黑客所控制DAO合约上的币。


但这种改动需要永久性改动以太坊的协议规则，相当于直接修改The DAO和黑客的账户余额，有违区块链数据不可变更的原则。所以这个修改也被一部分社区成员所拒绝。



因而形成了两条链，一条为原链(以太坊经典，ETC)，一条为新的分叉链(ETH)，他们各自代表了不同社区的共识和价值观。
