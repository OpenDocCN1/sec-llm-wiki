#### 子句字段探测:

```
PayLoad: order by n   n可递归枚举,如正常访问则继续累加,直至报错
```

**报错Payload:**

```
http://www.*****.com/zhn/news_wz.jsp?pid=1576047418491%20order%20by%2014
```

这里是递归到了第14位就报错了,也就是这个表的字段只有13位

ORDER BY讲解

ORDER BY 语句用于根据指定的列对结果集进行排序

那么这里的我们进行了SQL注入此时后端SQL语句应该是这样的

```
select  * from data_tables where pid = {$pid} order by 14
```

这里我做了个示范,查询linksoup\_task表里所有的内容用order by 进行排序,此时表内字段为6,当我输入order by 7 时就会出现报错,因为表内只有6个字段无法进行第7位排序

测试了一番，这里上传报错了，说明存在文件验证。

存在文件验证一般分前端检测和后端检测

前端检测

前端检测一般为JS脚本检测文件的扩展名,可以使用burp进行截包,更改文件属性进行绕过

后端检测

后端检测一般分为,白名单,黑名单以及MIME验证,MIME验证可以更改MIME属性为image进行绕过。

绕过上传
