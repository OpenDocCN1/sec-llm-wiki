## **对网站的渗透**

端口扫描

![](../Images/3c0e88f491460fb67a3f44e0e67ad0b8.png)

存在`mysql`,`ftp`,`ssh`,`http`,`ajp`,`tomcat` 多个服务ajp 存在漏洞 `2020-10487 Tomcat apj`存在任意文件读 ，但没啥用`WEB-INF/web.xml` 里没有任何东西

![](../Images/5987522156bb5ed344d47ed22158c094.png)

app上抓了个包，发现了比较可以的api

![](../Images/edd27e26dc3e696162eb1d32430788af.png)

对`name`进行注入， 输入`"||1||"` 返回正常数据 ，但无法注释后面的内容，只能`布尔注入`

![](../Images/e2f156377e804cb728cdf034d70fbb73.png)

sqlmap 一把梭`python .\sqlmap.py -r res --tamper=space2comment --level 5 --dbs --random-agent`

![](../Images/c873f1e9e2646225418f77477d49b584.png)

存在读文件

![](../Images/a7afc428e32fffd17c1249ada3ecd998.png)

不知道`nginx` 和 `web目录`,默认路径不存在

![](../Images/f24a1b222cff9968b5f675348d9faaf4.png)

读到mysql的目录，根据大佬的猜测，同目录下存在nginx 服务，于是读取`***/nginx/conf/nignx.conf`成功读到配置文件, 存在多个应用 以及对应的路径

```


        location /\*\* {
```

两个后台（其中一个还挂了），和一个应用

![](../Images/3030035799952acbbd70e0ed29c2f979.png)

暴露了 框架和绝对路径

![](../Images/cb06574603e86ed375567792a0c2b782.png)

存在目录遍历，发现了个比较有意思的页面`mysql.inc.php`，读取获取了 mysql 的账号密码

![](../Images/5b96256a632dfa7575c7e618e44e6935.png)

企图直接连接，但失败了，看了看数据库，只能本地登录和指定ip登录

![](../Images/531bcde744e302ac89edf4962864152c.png)

然后发现是`tp3.0`的远古框架 ，根据框架读了一下配置文件（也就是入可文件index.php)

![](../Images/1e586d621e652c037b3953acd06f2474.png)

按照这个配置文件本搭建了一下，目录结构清晰可见

```


├─caches
```

根据手册 `tp3`的编程风格，确定 项目的文件为`IndexAction.class.php`，通过sql注入读取发现乱码。。。然后尝试`tp3.0`的RCEpoc如下

```

http://\*\*/index.php/Index/index/name/$%7B@phpinfo%28%29%7D
```

直接打不行仔细看了一下 发现必须为精简模式下才可以使用,即index.php得包含如下

```
define('MODE\_NAME','Lite'
);
```

未果 想起还有管理的账号密码通过之前注入拿到数据库，找到管理员的账号密码，然后登入（后台有点东西

![](../Images/fadab2d3a44c205ef357e040d47401cc.png)

后台同样存在注入漏洞（随便一个地方就有），并存在 联合注入，并且具有写文件权限

```

0 union select tohex('webshell'),1,2 into outfile '/\*\*/\*\*/\*\*/shell.php'
```

蚁剑连接上

![](../Images/d27a6c4ba60f09a03f352458d8497224.png)

但自己是 www用户

![](../Images/f5f7d6a2271f30b1c313f38b39cd1346.png)

查看进程

![](../Images/570d901a982c47080570e8c397629be8.png)

发现root启动的 tomcat尝试往tomcat 写 jsp马

![](../Images/72b97f05049caf8c6ebdf505b1e88534.png)

但是没有写权限在检索可操作文件时，存在所有服务的一个日志文件夹发现tomcat日志可读（心想 tomcat不是个空壳来着，怎么还有日志

![](../Images/c82edc0d936c382d1de20b3aba5276b0.png)

![](../Images/010cc728dd718d079653b32ad8a2382b.png)

看日志才发现还运行服务检索对应文件发现在tomcat外的目录 部署了服务并运行在8080上，且属性位777，写个jsp马

![](../Images/0da7b3bb5724a72952af9303773d1989.png)

![](../Images/0993a13bc6b9dc025d3d0c1bd1e38bf1.png)

看了看源码 （蒙🖊 怪不得是乱码

![](../Images/bc31b762db8dbf15b062cd1362f76e7a.png)

根据`PM9SCREW` 检索了一下 是`screw` 加密根据教程先获取 编译好的`php_screw.so` 文件

![](../Images/394f52d58fdb41876f2fc381d4ba0c27.png)

下载下来拖到`IDA`找到`_pm9screw_ext_fopen` 加密函数
