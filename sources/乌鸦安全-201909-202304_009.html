前言

年前在群里放下豪言壮志，要自己设计一套靶场玩玩，这不在经历了各种各样的玄学问题后靶场终于算设计建设完了，在这里浪费大家一点时间，听听我的想法，本来个人想设计一种带有带外管理和一些安全设备的场景，但是由于一些原因，导致未能成功实现，下图是原本设计的靶场拓扑，但是由于日志服务器未能找到合适免费的环境，某终端不联网的情况下，甚至随便一个木马都不进行查杀，因此最后还是选择将设计暂时抛弃，设置为3台设备的靶场环境，也就是本地靶场的网络拓扑。至于后期可能还会再设计其他的带有安全设备的靶场，那就是后话了，温馨提示，本次靶场中部分靶机需要进行手动设置，由于VMware制作靶机时的处理器和当前不一致可能会导致无法恢复快照。最后祝大家新的一年里多挖0day，情人节快乐，没有情人的好兄弟，就在电脑中new一个吧。

我这边网络环境有点问题，所以我从浏览器中下载，拷贝进去

wget https://people.debian.org/~aurel32/qemu/mipsel/debian_wheezy_mipsel_standard.qcow2 && wget https://people.debian.org/~aurel32/qemu/mipsel/vmlinux-3.2.0-4-4kc-malta

固件模拟启动

qemu-system-mipsel -M malta -kernel vmlinux-3.2.0-4-4kc-malta -hda debian_wheezy_mipsel_standard.qcow2 -append "root=/dev/sda1" -netdev tap,id=tapnet,ifname=tap2,script=no -device rtl8139,netdev=tapnet -nographic -net user,hostfwd=tcp::8080-:80 -net nic

这里将qemu虚拟机中的端口映射到本地的8080端口上。启动完成默认密码是root/root，IP直接DHCP了。

通过wget下载固件打包文件，并上传至虚拟机根目录。

模拟固件启动

这里采用user用户模式启动

qemu-arm-static -L ./ bin/httpd

从br0的网卡启动成功，此时只能虚拟机内部访问192.168.6.11的80端口，Ubuntu机器外部是无法访问的。

iptables转发端口

接下来做一下端口转发，使得可以通过Ubuntu机器的NAT网卡进行访问

sudo iptables -t nat -A PREROUTING  -p tcp -d 192.168.126.140 --dport 60080 -j DNAT --to-destination 192.168.6.11:80sudo iptables -t nat -A POSTROUTING -p tcp -s 192.168.6.11 --sport 80 -j SNAT --to-source 192.168.126.140sudo iptables-save
192.168.126.140是NAT网卡，相对虚拟机来说是物理网卡192.168.6.11  是qemu虚拟网卡，相对虚拟机来说是虚拟网卡
