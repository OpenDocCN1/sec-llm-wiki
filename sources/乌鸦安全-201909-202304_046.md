# 1\. Burpsuite特征

关于`Burpsuite`来说，基本上是`Web`选手的人手必备的工具，但是现在似乎发现某些站点在使用`bp`的时候，无法对其抓包，甚至无法访问，这里面就可能被目标站点识别到了`bp`的指纹信息，目标站点积极拒绝访问。本文使用`Burpsuite`版本为`2.1.06` 本文只从简单的`js`层面来讨论。

## 1.1 http://burp

其实关于`Burpsuite`的特征来说，第一个就是`http://burp`，当`Burpsuite`在本地起来之后，随之也会起来一个`http`的服务，当前的浏览器使用`8080`端口（`Burpsuite`的默认端口）的时候，就可以直接访问到这个页面：

![](../Images/f7d8e0830da5a650ab623e0b983a1450.png "null")

显示网页源代码之后，可以发现更多的信息：

```

<html><head><title>Burp Suite Professional</title>
```

![](../Images/ae1888bd72c68546ffc40f3076f20951.png "null")

## 1.2 http://burp/cert

在`http://burp/cert`界面能够直接将证书下载下来：

![](../Images/d8a2b8007ec54615c0561935ddece59a.png "null")

## 1.3 http://burp/favicon.ico

在当前界面能够直接访问到`Burpsuite`的`ico`图标：

![](../Images/416d338f3228c97c6b13493d0a3a5981.png "null")

### 2.1 img标签

当从目标站点去访问访问者的站点的时候，需要跨域，一般的事件是不行的，所以在这里使用`img`标签，`img`标签中的`img`其实是英文`image`的缩写。所以`img`标签的作用，就是告诉浏览器我们需要显示一张图片。在这里使用`onload`来判断事件是否成功：

*   • `onload `事件会在页面或图像加载完成后立即发生。
    
*   • `onload `通常用于 `<body>` 元素，在页面完全载入后(包括图片、`css`文件等等。)执行脚本代码。
    

在刚刚的`html`中加入下面的`img`标签：

```
<img src=
```

![](../Images/f53f53cea2224cd2fc40b86173ee269f.png "null")

刷新之后，发现当前加载`ico`文件成功，并且弹出警告信息。在这里可以使用一个简单的跳转防止起对网站的访问：

```
<img src=
```

当请求之后，会自动跳转到百度：

![](../Images/f6728384edf9af47541e7085e993ea3d.png "null")

### 2.2 iframe标签的误区

`iframe`是`html`元素，用于在网页中内嵌另一个网页。

```
<iframe src=
```

将其添加之后，同样能够检测到当前的`Burpsuite`，但是这里是存在误区的：如果出现下面的这种图，并不一定代表确定是检测到了`burp`：

![](../Images/3d09b2cda2157ae122d07db734a96bff.png "null")

比如将上面的代码稍微修改为`baidu.com`试试：

```
<iframe src=
```

同样会弹出一模一样的界面，但是这并不代表此种方式有错误，这里主要要看报错内容：一个是百度的页面：

![](../Images/400cef4d208125fc236eff66c9f09af3.png "null")

还有一个是burp的页面：

![](../Images/5a0c40fd67638c423a244c878a823367.png "null")

可以通过相关的关键字来进行判断。在下面的文章中，师傅对其进行了优化：

```
https:
```

将报错隐藏：

```
<iframe src=
```

![](../Images/a7696169ac421cff1c348e5ee28491f5.png "null")

但是这里和刚刚说的一样，貌似是错误的，因为当将错误隐藏的话，我们就没法使用报错字段来判断是否存在`burp`了，比如将师傅的句子中的`burp`修改为`baidu.com`：

```
<iframe src=
```

在这里看到当前请求了百度，但是依旧进行了弹窗，所以在这里这种方法貌似不严谨。

![](../Images/8e869b9af36efd2cf492b27ff4124e96.png "null")

在这里主要为原因就是使用了`onload`标签的问题，`onload`标签的定义是：`onload`事件会在页面或图像加载完成后立即发生。也就意味着是否加载了`burp`，下面的弹窗情况都会发生。

# 3\. Burpsuite简单去特征

### 3.1 禁止访问burp代理

在这里禁止访问`burp`可以防止对方使用`img`标签来访问`ico`图标。

![](../Images/09e3ebb1fafd7f97d6970244ce0eed72.png "null")

当设置之后，使用前面的`img`标签试试：

```
<img src=
```

此时无法请求`burp`，获取不到`ico`图标：

![](../Images/e01bb33b75963ed258431985fa12efbd.png "null")

同理也可以防止`iframe`标签，因为禁止访问了`burp`，得不到报错之后的数据：

```
<iframe src=
```

虽然依旧会弹窗，但是由于没有报错信息，因此无法判断当前是否加载了`burp`。

![](../Images/3ae669db5ba728b89bace4b3456d1db5.png "null")

### 3.2 配置Burpsuite权限

在`Burpsuite`的`Options`界面，关闭如下两个选项：

![](../Images/545f813231af43b23e1297782f12bfa0.png "null")

当没有在代理端配置禁止`burp`访问的时候：

![](../Images/b8395dbe82f54fdbb1b7ca109c415a83.png "null")

此时去访问`http://burp/favicon.ico`

![](../Images/ec2383316e3473a73a9e2cb8c9896fde.png "null")

此时已无法访问，在这里是`Burpsuite`本身配置了防止`Burp`的访问。再去访问`img`标签下的值，此时发现`burp`的状态码直接不再显示了：

![](../Images/7e123439e8b823b4da22a2aa190e41b5.png "null")

# 4\. 总结

以上两种方法均可在一定程度上防止`Burpsuite`被识别到，可以二选一，也可以全选。

但是注意第二种方法在你重启`bp`之后，还会失效，一定要注意下。

当然，通过流量层等其他方法还是会识别到`Burpsuite`，后续有机会再学习下。
