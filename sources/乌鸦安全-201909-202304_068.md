# 1\. 环境搭建

事情的起因是这样，最近突然心血来潮，学起了代码审计，看教程看得我热血沸腾，我连忙上谷歌随便找了个开源的`cms`练练手，直接开搞：下载地址：

```
https://www.sourcecodester.com/php/12268/attendance-and-payroll-system-using-php.html
```

搭建环境： `Windows7` + `XMAPP ` 至于搭建的方法，这在国际上面一堆人用，至于安装就不说了，谷歌吧

# 2\. 审计

## 2.1 存储型xss

打开网站一看发现是个员工打卡上班的系统，看了一下前台发现没有可以下手的地方，眼看这着我这火越来越旺盛：

![](../Images/03264833fa32241443ab986ec5fbe106.png "null")

我急忙打开文件目录，发现一个admin目录：

![](../Images/7d09fe23ab18eea431b05a40b0a8b009.png "null")

我连忙访问，下面是进来之后的界面：

![](../Images/1f6fbe44058935e20b5d64d733f13c8d.png "null")

先随便点击熟悉一下功能点，我访问了左侧：点击`Employees`-->在点击` Employeelist`，发现他们的功能有搞头，搞`web`的同学看到这些功能肯定很熟悉他们对应的漏洞了：

![](../Images/eef923656587d6af7d964340fef5ba15.png "null")

我先来点击新建，看看新建的功能点，点开发现有框和上传口，我就先测试了一次`xss`,开启`burp`抓包：

![](../Images/0fbd480bd0ca73fcbe1cbab5d678aee1.png "null")

发现我们的`xss`大法见框就插成功了，而且我重复刷新了几遍，发现依然存在，这可能就是传说中的存储型`XSS`吧。

![](../Images/4056ebf07cb32145ce91745543eaad10.png "null")

找到了实现改功能的文件：`/apsystem/admin/employee_add.php`

![](../Images/9ff8220498e5b5d50470fc6629ee1856.png "null")

我打开文件一看，我直呼好家伙，这是不把我们脚本小子放在眼里？这时心中的火终于熄灭了一点,然后对应刚刚`burp`抓包，`xss`语句输入的点，对比一下：

![](../Images/d39e0b58610858b72b348d4cb9d61e22.png "null")![](../Images/cf6ff0fd0cb107bbed35d9a81a7fbe06.png "null")

发现就是对输入的数据没进行过滤导致的存储型`XSS`。

![](../Images/cc5f91ea5e08beb8672e22edcda4930c.png "null")

点击`save`，`burp`抓包：

![](../Images/ba159f58b7ec907cd3dadecddc147605.png "null")

我们再找一下对应的语句 `name="photo"`

![](../Images/ed18d63c0443a6a27a224729d147c3d1.png "null")

发现也是没有过滤才导致的任意文件上传漏洞的出现；
