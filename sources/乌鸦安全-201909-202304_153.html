04  代码审计

（在 thinkphp 目录下的  \thinkphp\library\think\ 中，名字叫 Request.php ）


漏洞点：filterValue 函数

我们可以通过搜索 filterValue 来找到漏洞的位置（也是报错的位置），filterValue 函数位于 1054 - 1082 行


filterValue 函数 中，用到了一个 call_user_func 函数（1060 行），在 php 手册中查找，可以看到，为 回调函数，用 phpstorm 跟进可以看到，用到的是 foreach 进行的循环。

第一次，call_user_func 函数 的 $filter 值为 system，然后会到 1080 行， return $this->filterExp($value);，把 $value 值代入到 filterExp 方法中


在注释中可以看到，应该是用来过滤的（我也不知道是啥，感觉怪怪的，可能是因为太菜了吧）


带入 $value 值，用 is_string 判断是否是 字符串，然后用 preg_match 正则匹配有没有匹配到的字符，

如果匹配到的就将 $value 与 " "，进行组合


可以自己测试一下，如下图所示，匹配到 “1”，就变为 "1 "

（注意，是有空格的），如果没有匹配到就结束呗



第二次，经过了 call_user_func 函数，$value 的值为 whoami，$filter 值为 system，而  call_user_func 函数会把第一个参数回调回去，执行，

$value = call_user_func($filter, $value);


即：回调了  system 去执行 whoami

$value = call_user_func($filter, $value); ==> system("whoami");

从而导致了代码执行（用 system 去执行 whoami）


而 1089 行的 filterExp 函数，

05  扩展


在上面简单的分析可以看出来，

payload ：s=whoami&_method=__construct&method=&filter[]=system


是用 回调函数 call_user_func 去回调了 system  执行 参数 whoami ，导致的代码执行

那如果想执行其他的呢，比如 phpinfo()   ？


我们可以试试，用 eval 去执行 phpinfo(); ，康康能不能导致代码执行

结果：没反应，显然是 8 行的


我们可以自己写一写测试康康（如下图）

结果：显然，eval 是无效的



那是不是这个想法就胎死腹中了呢？除了 eval ，php 是否还有哪些函数可以执行 phpinfo();  ?

那就是   assert()

结果：在 回调函数 call_user_func 中，  assert 是可行的，可以用 assert ，但是 eval   8行



所以可以将 payload 修改为  

 s=phpinfo();&_method=__construct&method=&filter[]=assert


（用 assert 执行 phpinfo();）

即可执行 phpinfo();
