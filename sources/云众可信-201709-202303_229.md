# 新型移动设备间谍技术，影响超过10亿人

![](../Images/f79e9be802f29d6f9e70b2d148eb7565.png "箭头引导关注")

  

近日，国外一家安全公司发布了一个SIM卡相关的漏洞，国内已有不少媒体平台开始关注和报道，我们特此翻译原文帮助大家全方位了解Simjacker的攻击方式细节以及相关漏洞。

> 以下是原文翻译结合我们收集的资料和理解。

我们认为，这个漏洞至少在过去两年中被多个国家的高级黑客组织团队所利用，他们的主要目的是对设备/信息进行监控。从我们的分析来看，该漏洞除了对其受害者有影响之外，与先前在核心移动网络上发现的攻击相比，Simjacker及其相关漏洞的复杂性和精密度已大幅提升。这表明，谋求通过移动网络发动攻击的攻击者的能力有了相当大的提升。

在本文中，我们将概述Simjacker它的工作原理、幕后可能的利用者，以及为何我们认为它是如此重要的新型攻击类型。  

  

**攻击流程**

简单来说，Simjacker主要的攻击方法只需一条包含一种特定类型攻击代码的短信，然后将其发送到受害者手机上，受害者手机收到含攻击代码的短信后里会指示手机内的UICC系统（SIM卡）“接管”手机，以便于检索和执行敏感命令。当一条被我们称之为Simjacker的含有攻击代码的短信发送到目标手机时，攻击就完成了。这种被称为Simjacker攻击的短信可以从另一个手机、GSM调制解调器或连接到A2P账户的SMS账户进行发送。Simjacker “攻击短信”通常包含一系列SIM卡工具包（STK）指令，并且为传递到设备中的UICC/eUICC（SIM卡）而专门设计的。为了使这些指令起作用，攻击利用了一种在UICC上被称为 S@T浏览器 的特定软件。一旦Simjacker攻击消息被UICC接收，它将使用S@T浏览器 库作为UICC上的执行环境，在UICC上它可以触发手机系统上的逻辑。我们观察到的主要攻击是在UICC上运行的Simjacker代码会获取当前手机的位置和特定设备信息（IMEI），一旦检索到这些信息，，运行在UICC上的Simjacker代码就会对其进行整理，并通过另一条SMS(我们称之为数据消息)将合并后的信息发送给接收方号码，同样，这也是通过在手机上触发逻辑实现的。这种数据消息是一种将位置和IMEI信息发送给攻击者进行远程控制的途径。

![](../Images/ffa6991f467597b313ee1a20afeab656.png)

在攻击期间，用户完全不会意识到他们收到了带有Simjacker的“攻击短信”，但是带有攻击性质的短信已被UICC检索，并且将用户的IMEI、位置信息通过数据短信向账户的攻击者发送了—无论在收件箱或发件箱中均没有相关被发送的信息。

  

**攻击原理与特殊之处在哪？**

这种攻击能成功的条件有2个，即运营商允许使用这些特定的SMS信息，而且目标手机的UICC上存在S@T浏览器 软件。之前已经证明了针对UICC的特定SMS信息能被用于恶意目的。但Simjacker攻击则采用了不同的方法，它通过使用 S@T浏览器 软件作为执行环境来大大简化和扩展此攻击。S@T（发音为sat）浏览器（全称SIMallianceToolbox 浏览器）是SIMalliance指定的应用程序，可以安装在各种UICC（SIM卡）上，包括eSIM卡。S@T浏览器 已经相当老了，并且很少人知道其存在，S@T浏览器其最初目的是提供一些服务，比如通过SIM卡获得账户余额等。在全球范围内，其功能已被其他技术取代，而且其相关技术自2009年以来从未更新。但是，与许多遗留的技术一样，它仍然在后台被使用。在这种情况下，我们观察到至少30个国家的移动运营商正在使用S@T协议，其累计使用人口超过10亿人，因此有相当数量的人可能受到此漏洞影响，而其他国家/地区的移动运营商也很可能会继续在特定SIM卡上使用该技术。

这种攻击方式同样也是独特的，因为Simjacker 的“攻击短信”在逻辑上可归类为携带完整恶意软件的payload，例如特定的间谍软件。这是因为它包含了SIM卡要执行的指令列表。但软件本质上是一个指令列表，此处的恶意软件是具有恶意性质的“坏”的软件，单独则无法运行成功，那么这可能使Simjacker成为利用SMS中发送恶意代码作为间谍活动的第一个真实案例的恶意软件（间谍软件）。先前通过SMS发送的恶意软件（例如我们在此处分析的事件

https://www.adaptivemobile.com/blog/singapore-sms-worm-goes-international

）只涉及到发送的恶意软件的链接，而不是在一个已发送的完整的信息里包含了恶意软件本身。

  

**它不仅仅可以获取位置信息**

然而，Simjacker的新颖性和潜力并不止于此。检索一个人的位置是一方面，但通过使用相同的技术，并通过修改“攻击短信”，攻击者可以指示UICC执行一系列其他攻击。这是因为攻击者可以使用相同的方法访问到完整的STK命令集（

https://portal.3gpp.org/desktopmodules/Specifications/SpecificationDetails.aspx?specificationId=1807

），这些STK命令的一些示例如下：

> *   播放音乐
>     
> *   发送短消息
>     
> *   设置通话
>     
> *   发送USSD
>     
> *   发送SS
>     
> *   提供本地信息（如位置信息，IMEI，电池，网络，语言等）
>     
> *   使卡断电
>     
> *   执行命令
>     
> *   发送DTMF命令
>     
> *   启动浏览器
>     
> *   打开通道：CS承载，数据服务承载，本地承载，UICC服务器模式等
>     
> *   发送数据
>     
> *   获取服务信息
>     
> *   提交多媒体消息
>     
> *   地理位置请求
>     

通过在我们自己的测试中使用这些命令，我们能够让目标手机打开web浏览器、呼叫其他手机、发送文本类型的短信等等。  

这些攻击可用于实现诸如以下此类目的：

> *   误导信息（例如通过发送带有攻击者控制的内容的SMS/MMS消息）
>     
> *   欺诈（例如通过拨打会有附加费率的号码），
>     
> *   间谍活动（与定位检索攻击一样，被攻击的设备也可以通过拨打一个号码来充当监听设备），
>     
> *   恶意软件传播（通过强制浏览器打开包含恶意软件的网页）
>     
> *   拒绝服务（例如禁用SIM卡）
>     
> *   信息检索（检索语言，无线电类型，电池电量等其他信息）
>     

以上攻击会取决于手机类型，进一步来说，甚至可能会有更先进的利用手法，关于这些内容我们将在VB2019演示中进行讨论。令人担忧的是，我们并不是唯一想到这些额外攻击的人，在过去几周和几个月里，我们观察到攻击者自己也在试验这些不同的能力。

最后，从攻击者的角度来看，Simjacker的另一个好处是，它的许多攻击似乎是独立于手机的设备类型进行工作，因为漏洞依赖于UICC上的软件，而不是设备。我们观察到几乎所有手机制造商的设备都能被成功定位并检索到手机位置，例如：苹果、中兴、摩托罗拉、三星、谷歌、华为，甚至是带有SIM卡的物联网设备。值得注意的是，对于某些特定的攻击，手机类型确实很重要。例如设置一个呼叫，需要用户交互确认，但这不能保证旧手机或没有键盘或没有屏幕的设备（如物联网设备）可能不会要求需要用户交互确认就能执行成功，因为设备不支持。

  

**幕后黑手是谁？**

接下来的问题是谁在使用这个漏洞，为何使用？我们有理由相信这个漏洞是由一个与政府有关的用于监控个人的特殊私人公司开发的。除了生产间谍软件外，这家公司还可以任意访问SS7和Diameter核心网络，因为我们已经观察到一些与被Simjacker攻击的受害者也通过SS7网络成为攻击目标，SS7攻击手段被用作当Simjacker攻击不成功时的备用方法。到目前为止，我们已经发现来自几个国家的电话号码成为这些攻击的目标，我们相信其他国家的个人也是被Simjacker当成攻击目标的。通过我们的SignallingIntelligence(SIGIL，

https://www.adaptivemobile.com/products/sigil-signalling-intelligence-layer

) 威胁情报系统，我们可以关联到一个与Simjacker相关的高度活跃的试图使用SS7在全球范围内攻击目标的组织。![](../Images/ececf176addcd87e7310b73c6625bcdd.png)

在同一个国家里，我们观察到每天大约100-150个特定的个人电话号码成为Simjacker的攻击目标，尽管我们目睹了一天内试图跟踪的多达300个各不相同的电话号码的爆发趋势，但尝试追踪的人群分布却各不相同。一些电话号码（可能是某些具有高价值的人的）在7天内被试图跟踪数百次，但大多数电话号码的数量要小得多。在每天的攻击活动中也发现了类似的规律，许多电话号码在几天、几周或几个月的时间里不断成为攻击目标，而其他号码则是一次性的攻击目标。这些规律和跟踪数量表明它不是大规模监视行动，而是旨在为某种目的来跟踪大量个体目标，这些目标和优先级会随着时间的推移而变化。

从这个角度来看，在第一次就使用Simjacker攻击手段是有意义的，因为使用SS7或Diameter方法进行这种大范围跟踪可能会将这些攻击源暴露给检测系统，因此保留这些方法以进行更新或遇到困难时才使用会更有意义。

  

**防范措施和思考**

为了应对这一漏洞，我们和移动行业已经采取了一系列措施。1、我们一直在与我们自己的移动运营商客户合作以阻止这些攻击，我们感谢他们帮助检测这一活动。2、我们还向GSM协会（移动运营商社区的贸易机构）通报了此漏洞的。此漏洞已通过GSMA CVD计划进行管理，允许在整个移动社区中共享相关信息。3、作为SIM联盟的一分子，我们还向SIM联盟共享了该漏洞信息，SIM联盟是代表主要SIM卡/UICC制造商的贸易机构，他们也为 S@T 浏览器技术提出了新的安全建议。

一般而言，我们针对移动社区处理威胁的直接建议是移动运营商需要分析和阻止包含 S@T浏览器命令的可疑消息。移动运营商还可以尝试远程更改本地UICC的安全设置，甚至可以完全卸载和停止使用 S@T浏览器技术，但此进度可能会很慢，也更难以实现。然而，这只是第一步而已，因为Simjacker攻击的造成影响确实很大。

Simjacker的存在意味着当涉及到移动核心网络的安全性时，我们需要彻底改变我们的思维方式。我们认为，当运营商开始保护其SS7和Diameter基础设施时，Simjacker的攻击出现正出现弥补了对移动网络进行攻击的攻击者丢失掉的能力。但是，虽然确保能执行成功的SS7攻击需要特定的SS7知识（可访问https://www.adaptivemobile.com/blog/can-they-hear-you-now-hacking-team-ss7），而Simjacker的攻击短信却需要更广泛的特定SMS、SIM卡、手机、SIM工具包、S@T 浏览器和SS7知识来编写。

这项投入显然为攻击者带来了回报，所有的设备只需仅仅10美元的GSM调制解调器和目标电话号码即可控制任何国家的任何手机。简而言之，Simjacker的出现意味着针对移动运营商的攻击者已经在新的攻击技术上投入了大量资金，而这种新的投入和技能组合意味着我们未来将会面临更多的这类复杂的攻击。

因此，这意味着我们在移动安全领域还需要提高我们自己的能力。对于移动运营商而言，这也意味着依赖现有的安全建议将不足以保护自己，因为像这样的攻击者将不断地通过升级来试图绕过现有的安全措施。而且移动运营商则需要不断调查可疑的恶意活动，以发现“潜在的”攻击行为。我们可以也应该预料到，其他同样逃避现有防御的弱点和攻击也会被发现和滥用。由于攻击者已经不是仅仅会利用不安全的网络进行攻击，现在的他们已经扩展了发动自己的能力，可以涵盖非常复杂的协议、执行环境和发动攻击的技术进行组合来发动攻击，运营商还需要增加自己的能力和投入来检测和阻止这些攻击。

  

**未来**

在本文中，我们只是介绍了Simjacker的皮毛。在我们将于2019年10月3日在伦敦举行的VirusBulletinConference上的演讲中，我们将详细介绍Simjacker攻击的细节，比如攻击者试图逃避检测的方式以及他们如何操作他们的系统，并介绍自攻击被检测到和阻止以来他们的反应。我们还将对我们认为这些攻击将演变为下一代的间谍活动给出我们的看法。我们期待这一消息被公之于众，我们将公开展示并揭露他们的恶意活动(如果有的话)。

Simjacker攻击方式和其利用的漏洞代表了从以往的SMS或SS7/Diameter的攻击到类似震网的巨大复杂性的飞跃，并向我们展示了核心网络受到的攻击范围和可能性比我们过去想象的要复杂的多。现在是确保我们在未来保持领先于这些袭击的时候了。
