CTF PWN 题目中 patch ELF 程序的一些技巧

根据大佬们的博客整理一下 ctf 题目中的 hook/patch 程序的方法。文章中用到的 patch 工具为 lief。

工具开源地址：https://github.com/lief-project/LIEF

pip 安装方法：sudo pip install lief

sudo apt-get install software-properties-commonsudo add-apt-repository ppa:ubuntu-toolchain-r/testsudo apt-get updatesudo apt-get install gcc-4.9sudo apt-get upgrade libstdc++6


常见方法


使用 LD_PRELOAD 劫持系统/动态库函数

特点：每次运行时需要设置 LD_PRELOAD 环境变量。

举一个绕过 ptrace 反调试的例子。

c 源码：

#include <stdio.h>#include <stdlib.h>#include <sys/ptrace.h>#include <string.h>
void pt(){        if(ptrace(PTRACE_TRACEME,0,1,0)==-1){                fprintf(stderr,"don't ptrace me!\n");                exit(-1);        }

        puts("Hello!");}void main(){
        pt();}

程序的大意是如果检测到有调试器对他进行动态调试的话，就直接退出。

为了绕过反调试，就可以利用外部的共享库，劫持 ptrace 函数，修改返回值为一个非 -1 的值。

ptrace_p.c 代码：

enum __ptrace_request{    PTRACE_TRACEME = 0,#define PT_TRACE_ME PTRACE_TRACEME};
long ptrace(enum __ptrace_request request, unsigned long pid,                   void *addr, void *data){    return 0;}

编译，并设置环境变量：

gcc -shared -fPIC patch_pt.c -o patch_pt -gexport LD_PRELOAD=$PWD/patch_pt

此时再进行 gdb 调试的话，就正常了。

原因是先设置了这个环境变量之后，链接器会优先加载 LD_PRELOAD 指向的共享库文件。

替换符号表的方法劫持函数

特点：

  1. 只能替换成 libc 库中已有的 symbol 的函数，要自定义自己的函数的话，除非在 libc 中添加一个段，但是这种方法和下面要介绍的方法一样，所以这个方法就用来简单的替换就行。

  2. 需要设置 LD_LIBRARY_PATH 环境变量。

举一个简单的例子：

这里我想直接把 puts 函数替换成 system 函数。

#include <stdlib.h>int main() {  puts("/bin/sh");  return 0;}

可以使用上面中方法，劫持 puts 函数，在自定义的 puts 函数中执行 system 函数即可。

替换的方法有两种，一种是直接更改 ELF 文件中的 symbol 即可，另一种需要更改 libc 中的 symbol，通过设置 LD_LIBRARY_PATH 来加载我们自定义的 libc 库的路径。

第一种方法中替换符号表的方法如下：

import lief
f = lief.parse("test1")
# 获取 puts 的符号表puts_sym = filter(lambda e: e.name == "puts", f.imported_symbols)[0]puts_sym.name = "system"
f.write("aaa")

puts 的 plt 表也直接被替换成了 system。

另一种方法是通过修改 libc 来实现，这个方法就不需要修改本身的 ELF 文件。这里参考了 hac425 大佬的代码：

import lief
hashme = lief.parse("test1")libc = lief.parse("/lib/x86_64-linux-gnu/libc.so.6")

puts_sym = filter(lambda e: e.name == "puts", libc.dynamic_symbols)[0]system_sym = filter(lambda e: e.name == "system", libc.dynamic_symbols)[0]
puts_sym.name = "system"system_sym.name = "puts"libc.write("libc.so.6")

本地文件中会生成一个新的修改过的 libc，使用命令 set LD_LIBRARY_PATH=./，运行程序即可。

添加新的 segment 段来劫持 plt 表

特点：可以将程序调用的库函数更改成自定义的函数。

例如在 ctf 比赛中，某个 pwn 题存在 uaf 漏洞，需要进行 patch 修复，大家都知道，修复方法是把悬浮指针置为 0。但是当没有办法直接在 IDA 中添加汇编语句时，那么就可以使用这种方法。

实例代码：

#include <stdio.h>#include <stdlib.h>#include <string.h>int list[10];
int main(){        char pass[] = "123456\x00";        char *p;        p = (char *)malloc(0x10);
        if (p == NULL){                perror("malloc error!");                exit(-1);        }        memcpy(p,pass,sizeof(pass));
        list[0] = (int *)p;
        puts(p);        free(p);        printf("pointer addr: 0x%x\n",list[0]);
        return 0;}

编译：

gcc test_uaf.c -o patch_uaf

有一处很明显的 uaf 漏洞，这时候我们的目的是需要修复它。

接着编写、编译我们的 hook.c 文件（仅做测试）：

int myfree(){        return 1;}

  • 在 hook 脚本中，如果需要调用外部函数的话，因为编译选项不依赖外部函数库（如下），只能使用 syscall 或者内嵌汇编的方式来进行调用。

使用下面的命令进行编译：

gcc -nostdlib -nodefaultlibs -fPIC -Wl,-shared hook.c -o hook

patch 脚本：

import lief
c = lief.parse("patch_uaf")hook = lief.parse("hook")
segment_added = c.add(hook.segments[0])
f = hook.get_symbol("myfree")
addr = segment_added.virtual_address + f.value
c.patch_pltgot('free',addr)             # addr patch
c.write("uaf.patch")
print("Done!")

程序运行是正常的，再把他加载到 IDA 中，在 got 表中发现有一个表项跳转到了一个陌生的地址。

在 main 函数中，原来的 free 被换成了 sub_400590 函数，这个函数里就调用了我们的 patch 函数。

使用patach_address来劫持call调用 


这里不能使用替换 free 函数的 got 表的方法来增加段了，因为这里需要调用他，free 函数也不在 syscall 调用表里。

正确的操作方法如下：

hook.c

  • 因为 call 函数使用的是相对偏移，所以在这里需要先填充为 NOP 指令，后面再来补上。

int myfree(char *s){
        asm(                "nop\n"         // 预留 5 字节 nop，后面来填充成 call free                "nop\n"                "nop\n"                "nop\n"                "nop\n"                "movl $0x00,0(%rdi)\n"      //*ptr = NULL;        );        return 1;}

使用同样的方法编译。

patch.py

这里也就是把  main 函数中的 call free 指令替换成了 call 自己构造的段 的地址。

import lieffrom pwn import *
call_free_addr = 0x400780c = lief.parse("patch_uaf")hook = lief.parse("hook")
segment_added = c.add(hook.segments[0])print segment_addedf = hook.get_symbol("myfree")
addr = segment_added.virtual_address + f.valuedis = (addr - call_free_addr - 5)&0xffffffff
c.patch_address(call_free_addr,[ord(i) for i in ("\xe8"+p32(dis))])
c.write("uaf.patch")
print("Done!")

生成可执行文件之后，加载到 IDA 中，这里看到成功 call 了我们添加的段了。

在 0x08032D8 处，把 nop 使用 keypatch 重新 patch。

patch 之后查看伪代码发现这里已经成功解决了 uaf 的问题。

当然也可以不用 IDA 手动 patch，还是使用 python 脚本：

c.patch_address(call_free_addr,[ord(i) for i in ("\xe8"+p32(dis))])c.patch_address(addr+8,[ord(i) for i in ("\xe8"+p32((addr+8-free_plt-5)&0xffffffff))])

  • 还有种类似的方法是通过将 patch 后的代码添加到 .eh_frame 段中，这样有点就是不用自己增加一个新的段，同样劫持 call 函数的调用 。但是可能会导致程序出错，在比赛中可能会过不了 check。具体可以看一下参考文章 3。
