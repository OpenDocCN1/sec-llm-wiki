0x00 序言

跟着表哥学逆向，接受了很多新知识，也学习了一些花指令的原理和手工去除花指令的实际操作方法。
我们接下来要逆向破解的是这个名为easy_junkcode的二进制文件。

0x01 修复

首先将它拖入ida64.exe中找到main函数。
按F5键将main函数反编译成伪代码的形式，方便阅读，而且我们也可以明显的main函数里调用了一个名为loc_4006D6的函数。
双击跟进，发现左面的地址为红色，说明该段汇编代码存在一些问题，导致ida无法正确识别。
这里用F5查看伪代码当然也是不会成功的，没有办法更直观的去逆向分析。

我们在下面的代码中找到了一处错误的调用。

可以看到0x4007A2地址处CALL了一个错误的0FFFFF........地址，那里显然没有函数代码可调用，不过向上我们可以看到0x40079D~0x4007A0地址存在两条汇编指令。
xor  rax, raxjz    short near ptr loc_4007A2+1

在这里第一行的xor结果永远为0，向下执行可以发现该行指令一定会跳转到loc_4007A2函数的下一个地址，也就是0x4007A3，不过ida会错误的从0x4007A2地址处开始反编译，而0x4007A2的代码是错误的，SO，这两行汇编指令成功的干扰了ida的反编译功能，也被成为花指令。

我们按下快捷键d，可以将loc_4007A2函数转换为数据格式，同时也就可以看到0x4007A3地址。

然后再按快捷键c，将本该运行到的0x4007A3地址转换为汇编指令，这样就可以还原本该反编译出的逻辑代码，成功去除一部分的花指令。

我们尝试将0x4006D6地址处的汇编指令定义为函数入口，但ida抛出一个错误。

这里显示给我们0x4007A2地址存在没有定义的结构或者数据，因为原先那个错误的call指令已经被我转换为了数据格式，但ida并不能正确的识别它，所以我们要将它的数据改为nop。

定位到该地址对应到原始文件的位置。

将E8改为90，90转换为汇编指令即为nop，表示跳过。

然后按下快捷键c，将该地址转换为汇编指令。

然后我重新尝试定义函数入口，结果ida又抛出一个错误。

这里显示0x4007AA地址处又存在一个未定义的结构或者数据，继续跟。

发现该地址处存在一些连续的数据。
尝试按下快捷键c，将该地址的数据转换为汇编指令。
继续尝试定义函数入口，定义成功。
但在尝试F5反编译为伪代码时，ida又抛出了一个报错。
这里显示我们的40074F的栈针存在一些问题，跟过去看看。
可以很明显的发现0x40074B地址及以上的地址处都为058，但0x40074B的汇编指令让058变成了-0C，影响了栈平衡，同时在0x40076~0x400749地址段处也可以发现和上面同样的花指令，这里就不再详细分析。我们将0x40074B的错误代码nop掉。
可以看到该处的栈恢复了正常。
去花成功，F5，成功看到该函数的整个伪代码。

0x02 逆向

经过简单的分析后，我们将代码的一些变量重命名一下
int sub_4006D6(){  char *v0; // rax  int result; // eax  signed int i; // [rsp+Ch] [rbp-44h]  char dest[8]; // [rsp+10h] [rbp-40h]  __int64 v4; // [rsp+18h] [rbp-38h]  int v5; // [rsp+20h] [rbp-30h]  char key[8]; // [rsp+30h] [rbp-20h]  __int64 v7; // [rsp+38h] [rbp-18h]  int v8; // [rsp+40h] [rbp-10h]  unsigned __int64 v9; // [rsp+48h] [rbp-8h]   v9 = __readfsqword(0x28u);  *(_QWORD *)dest = 0x7672757F6A636D66LL;  v4 = 0LL;  v5 = 0;  printf("enter the secret:");  *(_QWORD *)key = 0LL;  v7 = 0LL;  v8 = 0;  __isoc99_scanf("%16s", key);  for ( i = 0; i <= 7; ++i )  {    key[i] += i;    key[i + 8] ^= i;  }  v0 = strcat(dest, src);  result = strncmp(key, v0, 16uLL);  if ( !result )    result = puts("you are right!");  return result;}
这里可以发现我们用户最终输入并处理后的变量为key，我们的key要与v0变量进行比较，如果值相等就输出you are right！，那么思路很清晰，只需要分析出我们输入什么数据可以输出right。

dest指针指向的地址为：0x4006EF

src数据的地址为：0x400894

使用ida的python调试功能，写出解密代码，Get Key！

0x03 结语

在逆向工程中，遇到一些做调试对抗的汇编指令时，因为ida并不能联系上下文进行判断，所以可能导致反编译错误，这时需要我们人工去识别这些指令并修复ida的识别逻辑，以达到逆向工程的目的，也方便我们后面进一步对该程序进行分析。
