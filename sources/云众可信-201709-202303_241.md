# 0x00 序言

跟着表哥学逆向，接受了很多新知识，也学习了一些花指令的原理和手工去除花指令的实际操作方法。我们接下来要逆向破解的是这个名为easy\_junkcode的二进制文件。![](../Images/6b6a24d893593f8f798499311433e033.png)

# 0x01 修复

首先将它拖入ida64.exe中找到main函数。![](../Images/6f9ae834d8169b5b4b8e7df36132e891.png)按F5键将main函数反编译成伪代码的形式，方便阅读，而且我们也可以明显的main函数里调用了一个名为loc\_4006D6的函数。![](../Images/10745415f702195d516be3007bf5fdf9.png)双击跟进，发现左面的地址为红色，说明该段汇编代码存在一些问题，导致ida无法正确识别。![](../Images/083b5c4458268cda0b5ff586fed967ef.png)这里用F5查看伪代码当然也是不会成功的，没有办法更直观的去逆向分析。

我们在下面的代码中找到了一处错误的调用。

![](../Images/5b9ef1bc4bd926d23520a399faa426d4.png)可以看到0x4007A2地址处CALL了一个错误的0FFFFF........地址，那里显然没有函数代码可调用，不过向上我们可以看到0x40079D~0x4007A0地址存在两条汇编指令。  

*   
*   

```
`xor  rax, rax``jz    short near ptr loc_4007A2+1`
```

在这里第一行的xor结果永远为0，向下执行可以发现该行指令一定会跳转到loc\_4007A2函数的下一个地址，也就是0x4007A3，不过ida会错误的从0x4007A2地址处开始反编译，而0x4007A2的代码是错误的，SO，这两行汇编指令成功的干扰了ida的反编译功能，也被成为花指令。

我们按下快捷键d，可以将loc\_4007A2函数转换为数据格式，同时也就可以看到0x4007A3地址。

![](../Images/6daf470eed522d9069bde56fdef7c926.png)然后再按快捷键c，将本该运行到的0x4007A3地址转换为汇编指令，这样就可以还原本该反编译出的逻辑代码，成功去除一部分的花指令。![](../Images/56b35c1c97dafddda97e901bb281bb68.png)

我们尝试将0x4006D6地址处的汇编指令定义为函数入口，但ida抛出一个错误。

![](../Images/e48700ab7af60bbdd828e5fda793aa96.png)这里显示给我们0x4007A2地址存在没有定义的结构或者数据，因为原先那个错误的call指令已经被我转换为了数据格式，但ida并不能正确的识别它，所以我们要将它的数据改为nop。

定位到该地址对应到原始文件的位置。

![](../Images/2ecb072050a35aa18a41d3a4712e062e.png)将E8改为90，90转换为汇编指令即为nop，表示跳过。

![](../Images/97a93e7d7dfcd4f87afa5563e0ef8b6d.png)

![](../Images/c836fb5c79567d0f079226359e6c1868.png)

然后按下快捷键c，将该地址转换为汇编指令。

![](../Images/47a38b3a338239a43d9f21ec12c0c529.png)

然后我重新尝试定义函数入口，结果ida又抛出一个错误。

![](../Images/157c6a8f28ed448ec4f24ff5cfb09873.png)

这里显示0x4007AA地址处又存在一个未定义的结构或者数据，继续跟。

![](../Images/8f119ef54de0a6eeff8d0db8a0f855db.png)发现该地址处存在一些连续的数据。尝试按下快捷键c，将该地址的数据转换为汇编指令。![](../Images/97c2f99bff5302b6362d2177031aa535.png)继续尝试定义函数入口，定义成功。![](../Images/819200a52b8205526c3ae8c9df0832a5.png)但在尝试F5反编译为伪代码时，ida又抛出了一个报错。![](../Images/e0bc15b07ec4e5c4259c5251a07c4e93.png)这里显示我们的40074F的栈针存在一些问题，跟过去看看。![](../Images/8d3e7b45c8b1ecd07255e58f16433980.png)可以很明显的发现0x40074B地址及以上的地址处都为058，但0x40074B的汇编指令让058变成了-0C，影响了栈平衡，同时在0x40076~0x400749地址段处也可以发现和上面同样的花指令，这里就不再详细分析。我们将0x40074B的错误代码nop掉。![](../Images/cea75937a828737e49871ebf980930b7.png)可以看到该处的栈恢复了正常。![](../Images/fbee74125f47896489dea52fe1502d9b.png)去花成功，F5，成功看到该函数的整个伪代码。![](../Images/a1d6a2c7c8fab8fa009d249bb178a6a9.png)

# **0x03 结语**
