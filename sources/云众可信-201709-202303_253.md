# 前言

此篇文章所演示的是被用来当做靶机的CMS，漏洞百出。在AWD比赛中，我方不仅需要对CMS进行快速代码审计，编写漏洞漏洞利用程序，还需要修复漏洞，抵挡敌方的进攻。此篇文章着重分享这其中的代码审计过程和漏洞利用方法。

我们将源代码的文件结构大致地阅览了之后，使用D盾webshell查杀，和Seay源代码审计工具对危险函数进行定位。

![](../Images/6d2af1af2395459c9a00678140140821.png)

![](../Images/60fd861be71cd494cec54a1dadb6cc53.png)

剩下的事情，就是对危险函数的数据流进行回溯，定位数据入口，并分析其中的数据处理方法。

代码审计：

首先我们就定位到了/install/index.php这个文件上的fwrite()函数，该函数可以在服务器上写入文件。

![](../Images/5427cb88279be4a8cc45e9451880a844.png)

fwrite()函数的第一个参数，是被写入文件的文件句柄，该文件句柄由fopen()函数生成，文件名为../config/data.php，文件可以执行;第二个参数是写入文件的内容，该内容中有5处可控，意味着我们可以向一个php文件中插入任意的数据。接下来再看，我们应该如何触发这个文件写入。很简单，在第三行，只要post方式发送的数据中有save=1，即可。

我们可以控制的有3、4、5、6、7行，在漏洞利用中，也应当注意不破坏程序的原有功能，所以将第7行的cms\_admin替换为cms\_admin’);eval($\_POST\[a\]);\\\\即可在data.php中插入一句话木马，\\\\为单行注释，负责把后面的’);注释掉，防止语法错误。

# 二、后台SQLi

SQL注入漏洞的挖掘相对来说要麻烦一点，我们需要仔细审计用户传入的数据有没有被过滤函数处理，如果被过滤，要找出函数是如何对我们的数据进行处理变形的，应该怎样绕过。

1. 第一个后台SQL注入漏洞

代码审计：

定位到/admin/cms\_addon.php页面上。

![](../Images/a9aa0f5f273474db09cf205739d3c485.png)

我们的关注点在第26行代码上的SQL语句中，变量名为$data，往上看可以发现，$data其实是一个数组，这个数组的每个元素都是通过POST数据传入的，也就是说这个数组的值可控。在第23行发现null\_back()函数对$data数组变量进行了处理，我们跟进这个函数看一下。

![](../Images/93e63afdc72a5c1cf6cb7b3c9047e0b7.png)

可以发现null\_back()函数仅仅是判断第一个参数的值是否为空，为空的话就将第二个参数使用JavaScript的alert()输出到页面上，该函数没有对数据进行处理。

继续跟进arr\_insert()函数。

![](../Images/67747b4898b44edc209cc09f1f66903a.png)

该函数会将传入的数组变量拼接为INSERT语句中的字段和值，例如：

$arr = \[‘a’ => ’one’, ‘b’ => ‘two’\]

则返回：(\`a\`,\`b\`) VALUES (‘one’,’two’)

同样没有对数据进行过滤的处理。那么就到了最后的查询方法$dataops->ops()，跟进它。

这里应该如何找到该方法呢，用Seay在全部源代码文件中查询function ops是行不通的，因为可能有很多个类中都存在同名的ops()方法。好的方法是顺藤摸瓜，找到$dataops对象是由哪个类New过来的。

![](../Images/694e8586853e5cb7cf734a98a84cf0b2.png)

![](../Images/47f222bf7542be1c959a4e2164856283.png)

![](../Images/b87dd85c41f5f88c16ec691f2b8f8607.png)

又被传入了当前方法中\_db属性指向的query()方法中，还是先看看\_db属性是由哪个类New过来的。

![](../Images/ce6966442577697febdc178dd45669f5.png)

$GLOBALS数组是全局变量数组，so，查一下$GLOBALS\[‘db’\]是由哪个类New过来的。

![](../Images/8723236c89d111bca8b9098cb3254d3b.png)

发现是DataObject()类实例化来的，并把实例化的句柄引用到$GLOBALS\[‘db’\]上。

这里要讲一下&$db这种用法，可以把它理解为C语言的指针，我们对&$db对象的属性操作同样会影响到$db对象，因为他们本身就是同一个对象，可以这样理解。

继续跟进。

![](../Images/629ad4e85cf46d44b85c2ad353390e73.png)

很容易就找到了query()方法，不过不要急，箭头处可以看到SQL语句又被Sql类的parse()方法处理了，继续跟进。

![](../Images/1b351850bf1691cb4dd4fced0f15bae2.png)

跟到了Sql类中，发现我们的SQL语句最终会经过这段正则替换，它要干嘛？这里给一个简单的方法，我们调试这段代码就好了。

调试之前我们注意一下DATA\_PREFIX 这个变量，为什么感觉如此眼熟？？

![](../Images/5478b952f68646e314c2ca6f60c9bdea.png)

表前缀，ok，随便是什么都不重要。

![](../Images/162363f5982f2a3795ed1e4cdf2e2d6a.png)

就是加个表前缀，也没有对数据进行处理。

下一行为$this->pdo->query()，这就是真正的带入数据库查询了。可以发现从我们传入数据到最终带入数据库查询，都没有对数据进行关键词过滤，那就说明该处存在SQL注入漏洞了。

漏洞利用：

不慌，我们仅仅是找到了SQL注入漏洞，现在要研究一下如何触发这个漏洞了。

![](../Images/89d3a1b81573aa797c441a57797da735.png)

第3行和第4行引用了../library/inc.php和../library/cls.page.php，这两个文件会判断当前访问的页面是否后台页面，如果是的话，会鉴别当前权限，很显然这个../admin/cms\_addon.php页面是后台页面，如果我们不登录的话，一定不会走到第16行的代码处，通过搭建网站调试输出也可以发现这点。此处就不再赘述权限验证的过程。

我们直接关注第16行，如何让$act变量的值为’add’。

在../library/inc.php中我们找到了这一行。

![](../Images/f2b8ba8d233ae7eadbb49026c6f034a5.png)

可以发现$act变量也是用户可控的，ok，那么此处漏洞利用的分析就结束了。

只要我们在登录情况下，传入变量act=add，再传入我们控制的SQL语句变量，即可完成SQL注入漏洞的利用。

![](../Images/78011a3ae1ed51e7d961ee8c56376bdd.png)

访问该页面可以很清楚的找到此处的漏洞触发点。

![](../Images/49279a757bfd1434434d67702502ee85.png)

![](../Images/e7cb41a7193cb321606481ba648e2c2f.png)

Bingo!

# 三、前台SQLi

前台的SQL注入漏洞危害就比较大了，不需要管理员的权限。

代码审计：

这次直接定位到了Detail类中的公共方法getDetail()，而且SQL语句中的$id变量是该方法的形参。

![](../Images/880f4db65be23fe30dab14e56519475d.png)

该方法中，SQL语句被传入到了getRow()方法执行，该方法没有任何过滤，上文已经审计过，恕不赘述。

漏洞利用：

接下来使用逆向思维，我们应该寻找这个类在哪里进行了实例化。

![](../Images/b088bf498f8ad94831c68e0d89866ba8.png)

![](../Images/65f0326672150f483935ac924c3f6677.png)

![](../Images/481a68751810c42864baa31057b201c2.png)

我们发现该方法在inc.php被实例化以后，被inc.php中的第95行逻辑分支进行了调用，但该调用需要我们的is\_admin()返回为FALSE，is\_detail()返回不为FALSE。

![](../Images/39476cbaadde7d6996fa12e027fde546.png)

很巧的是这两个函数都在一起，方便了审计。

可以发现他们的功能是相似的，如果访问的路径存在detail，is\_detail()返回就不为FALSE，is\_admin()也一样。那么我们只需要找到哪个页面的名存在detail字符串，并且包含有inc.php，这样的页面即可触发该SQL注入漏洞。

![](../Images/32bd00caffcff9a798ca65652b930900.png)

我们找到了detail.php，很巧，该页面也包含有inc.php。

![](../Images/0d4b7261cefb731af8f5bf0bedb5cc21.png)

不过在利用的时候我发现并不能利用成功，原因是我没有审计detail.php中对$id变量的处理，这其中存在着过滤。

还好，在channel.php页面中我用同样的方法找到了前台注入并利用成功，如愿以偿。

![](../Images/ce771818543771fd5d0a28135813e6bf.png)
