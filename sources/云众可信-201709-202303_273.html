时隔一年，再次参赛强网杯，发现自己是依旧的弱小，记一下这次艰辛的代码审计过程。

打开题目，一个登陆框。

注册一个admin用户，登陆进去，可以看到一个上传图片的点。

上传一张图片名为upload.jpg的图片。

通过审查元素可以看到图片被上传到upload文件夹下，且上传后的图片名为原图片名的md5值加上.png。

功能点就这些，下面开始寻找漏洞。

起初我是没找到任何大问题的，只有一个upload目录遍历漏洞，扫描网站目录和备份文件也没扫到什么，但是我观察到主板方给各方队伍的靶场，是在同一个ip上的不同端口，于是我尝试了一下寻找其他队伍的webshell，果不其然。

这里感觉有点坑，翻了别人的靶场才看到备份文件名是 www.tar.gz，也是我备份文件字典不够全面导致的。

简单的查看了一下源代码，发现是thinkphp框架搭建的，这里一共有四个文件是主要功能页面。

遍历了全部源代码后，首先引起我关注的点是Index.php反序列化

其次就是Profile.php的__call()和__get()魔术方法。

这两个魔术方法的触发方式：

__get() //用于从不可访问的属性读取数据__call() //在对象上下文中调用不可访问的方法时触发

如何触发这个__call()魔术方法呢？这里需要寻找一个在类属性值后继续进行方法调用的点，发现只有Register.php的checker属性后，对index()方法进行了调用。

将registed属性值改为FALSE，即可进入到第61行。

如果将Register类的checker属性值更改为Profile，而Profile类中并没有index()方法，就会触发Profile的__call()魔术方法，此时的$name变量为index，而在第89行中，调用了$this->index，这个属性并不存在，于是就会触发__get()魔术方法，并返回except['index']，在89行对$name进行替换，90行即可执行$name()。

except、registed、checker都为我们可控的属性，这样我们可以自定义except['index']值，进行任意方法执行。

如果我们可以控制filename_tmp和filename属性，即可Getshell

需要绕过前两个判断逻辑，第一个判断令Profile类的checker属性值为False即可跳过，第二个很简单，不上传文件即可。

为什么要绕过第一个判断？

login_check()

 public function login_check(){     $profile=cookie('user');     if(!empty($profile)){         $this->profile=unserialize(base64_decode($profile));         $this->profile_db=db('user')->where("ID",intval($this->profile['ID']))->find();         if(array_diff($this->profile_db,$this->profile)==null){             return 1;         }else{             return 0;         }     } }

第一个判断会重新调用该方法。第一次的调用是必然，为了让我们进行反序列化，但第二次的调用可能会让我们一直循环进入反序列化的操作，造成程序运行异常报错停止。

第二个判断会将原本可控的filename_tmp和filename属性重新赋值，变为不可控，所以也需要绕过。

第三个判断令ext为True，即可进入。有一个注意点是getimagesize()函数，如果我们上传的文件不能被解析为图片，就无法继续执行，所以需要在原本的图像数据中插入一句话木马。
