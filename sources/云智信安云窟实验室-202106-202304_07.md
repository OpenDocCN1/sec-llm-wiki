Mythic使用和分析

环境安装

有详细的官方文档：

https://docs.mythic-c2.net/installation

  

实际使用命令：

// 下载主体程序  
$ git clone https://github.com/its-a-feature/Mythic  
  
// 安装payload  
sudo ./mythic-cli install github https://github.com/MythicAgents/Apollo  
  
// 安装C2配置文件  
sudo ./mythic-cli install github https://github.com/MythicC2Profiles/http  
  
// 启动Mythic  
./mythic-cli start

等待启动命令运行完成。查看当前状态：

./mythic-cli status

框架

参考官方文档，Mythic主要分为3部分，Mythic Server、Payload、C2 Profiles。Mythic Server主要起到整体控制作用联合作用，Payload负责生成payload可执行文件。C2 Profiles是C2的配置文件。它们分别运行在不同的docker容器中，方便维护。

![](../Images/6ac9fc0d8125349f8d5cafe7e61d97e9.png)

\_\_init\_\_.py

![](../Images/254458db1154ebe1ef4262f7562f24c5.png)

  

routes/

这个目录下主要是应用的基础功能，通俗讲就是页面有按钮的部分。包括认证、选项、报告、登陆功能、文件服务、websocket等等。

![](../Images/464e02b97d5d272858eb72d4f986b46a.png)

  

api/

这部分是C2的逻辑部分，主要是后端运行的和后端应用交互的部分。文件名基本可以知道文件的作用。

![](../Images/9ed2afadab961226dfa919c4f35e8357.png)

拿apollo举例，源码主要包括两部分，agent\_code（agent端的源码，最终编译成可执行文件）和mythic（agent命令相对的py源码文件）

agent\_code/

每种payload的这部分都不一样，可能用不同的代码语言，可能执行方式不同。最终都会生成在目标机可运行的文件。这个是用C#编写，最终编译成exe可执行文件。上传到目标机运行即可。

mythic/

这部分代码主要是agent的命令配合Mythic服务端。

目录下的agent\_functions为python源码，用来从服务端向agent发送要执行的命令。

![](../Images/3501dbbcc086fc92b7424efa9cd37265.png)

  

C2 Profiles

C2 Profiles是C2的配置文件。官方一共给出了6种。

https://github.com/MythicC2Profiles

| 类型 || 描述 |
| --- | --- |
| tcp || 基于 TCP 网络套接字的 P2P 通信 |
| http || 这是一个名为 http 的 Mythic C2 配置文件。 它只是提供了一种从网络中获取 HTTP 消息并将它们转发到 Mythic 服务器的方法。 |
| websocket || 这是一个名为 websocket 的 Mythic C2 Profile。 它为代理提供了一种通过静态 websocket 连接进行连接的方法，然后在单个连接中进行标准的信标流量。 |
| smb || 命名管道的 P2P 通信 |
| dns || 这是一个名为 dns 的 Mythic C2 配置文件。 它实现了一个 DNS 服务器，用于侦听来自代理的 TXT 查询。 |
| dynamichttp || 这是一个名为 dynamichttp 的 Mythic C2 Profile。 它只是提供了一种从网络中获取 HTTP 消息并将它们转发到 Mythic 服务器的方法。 |

使用体验

不得不说，跟CobaltStrike相比，差远了。上线的agent没有删除功能。发送exit命令后，也不会掉。这点很尴尬

![](../Images/fb3864f55cd1956c7e4d5104197da65f.png)

  

再之后，怎么滴都不上线了。尝试了好几种payload和C2 Profile都没有反应。（服务端监听的端口可以正常访问）

![](../Images/549092ef74010c75fce31ebd0c46fdd6.png)

  

很多命令无法执行，可能跟使用的payload有关。

![](../Images/a9cdf609c53ef6e8bc841af99dca74b8.png)

  

  

总的来说，感觉Mythic挺复杂的，用到了很多组件，启动的时候，还需要启动一堆docker容器。C2本来不应该是短小精悍吗？
