CYBER SECURITY


一、需求背景

l《中华人民共和国网络安全法》

第三章 网络运行安全 第一节 一般规定 第二十一条，（三）采取监测、记录网络运行状态、网络安全事件的技术措施，并按照规定留存相关的网络日志不少于六个月。

l《信息安全技术 网络安全等级保护基本要求》 （GB/T 22239-2019）

第三级和第四级网络完全要求，应对分散在各个设备上的审计数据进行收集汇总和集中分析，并保证审计记录的留存时间符合法律法规要求。

l《信息安全技术 关键信息基础设施安全保护要求》 （GB/T 39204-2022）

7 安全防护 7.5.4 安全审计，应采取网络审计措施、监测、记录系统运行状态、日常操作、故障维护、远程运维等,留存相关日志数据不少于6个月。

l网络安全威胁发现

把各类设备产生的日志信息汇集在一起，通过相似日志信息进行关联分析，实现快速、有效的发现针对信息系统的攻击和入侵，以及来自内部的违规和信息泄露，为事后的事件分析和调查取证提供必要的信息。

二、日志审计

云智日志审计与分析系统是用于全面及不间断收集用户网络环境中常见的网络设备、安全设备、主机、操作系统、中间件、数据库、应用系统等设备产生的海量日志信息，并进行集中化的存储、监控、分析、审计、告警、响应，实现全生命周期的日志管理。

三、日志服务资源及采集

1.操作系统

lLinux日志

/var/log/boot.log，记录系统在引导过程中的各种事件信息。

/var/log/cron，记录计划任务相关事件信息。

/var/log/messages，记录系统内核消息及各种应用程序的公共日志信息，包括启动、IO错误、网络错误、程序故障等。

/var/log/secure，记录用户认证相关的安全事件信息。

/var/log/lastlog，记录每个用户最近的登录事件。（二进制格式）

/var/log/wtmp，记录每个用户登录、注销及系统启动和停机事件。（二进制格式）

/var/log/btmp，记录失败的、错误的登录尝试及验证事件。（二进制格式）

如想通过syslog协议将系统日志发送到日志审计与分析系统，在/etc/rsyslog.conf进行配置。

lWindows日志

Windows日志主要有三类日志记录系统事件，应用程序日志、安全日志、系统日志。

系统日志，记录操作系统组件产生的事件，主要包括驱动程序、系统组件和应用软件的崩溃以及数据丢失错误等。

默认位置：%SystemRoot%\System32\Winevt\Logs\System.evtx。

安全日志，记录系统的安全审计事件，包含各种类型的登录日志、对象访问日志、进程追踪日志、特权使用、帐号管理、策略变更、系统事件。

默认位置：%SystemRoot%\System32\Winevt\Logs\Security.evtx。

应用程序日志，包含由应用程序或系统程序记录的事件，主要记录程序运行方面的事件，如数据库程序可以在应用程序日志中记录文件错误，程序开发人员可自行决定记录哪些事件。

默认位置：%SystemRoot%\System32\Winevt\Logs\Application.evtx。

如想通过syslog协议将系统日志发送到日志审计与分析系统，借助Agent客户端程序采集Windows系统日志。

2.中间件

lNginx日志

Nginx日志主要分为两种：access_log(访问日志)和error_log(错误日志)。

访问日志，记录客户端IP地址、客户端浏览器信息、请求处理时间、响应状态码等信息。

错误日志，记录客户端访问Nginx出错时的日志。

日志位置：如/var/log/nginx。

如想通过syslog协议将Nginx日志发送到日志审计与分析系统，在/etc/nginx/nginx.conf进行配置。

lApache日志

Apache运行后会有两个日志文件生成，分别是访问日志access_log（在Windows上是access.log）和错误日志error_log（在Windows上是error.log）。

访问日志，记录请求时间、远程主机地址、请求方式、服务器资源位置、客户端向服务器发送请求时的协议和协议版本信息、状态码等。

错误日志，记录处理请求时遇到的任何错误相关信息，如访问404错误、CGI程序错误信息等。

日志位置：如，/usr/local/apache/logs。

通过日志审计与分析系统以远程文件访问方式，主动请求Aapche服务器和文件所在路径，将日志信息传输到日志审计与分析系统。

lTomcat日志

Tomcat日志分为两类，访问日志和运行日志。

访问日志，记录客户端访问的IP地址、时间、来源、访问的资料、状态码等信息。

运行日志，记录运行过程中错误、异常及数据库连接等信息。

日志位置：如，home/tomcat/logs。

通过日志审计与分析系统以远程文件访问方式，主动请求Tomcat服务器和文件所在路径，将日志信息传输到日志审计与分析系统。

lWeblogic日志

Weblogic日志有三种日志，access log、Server log、domain log。

access log，记录客户端访问的IP地址、时间、服务器文件路径、状态码等信息。

Server log，记录Weblogic的启动及关闭等其他运行信息。

domain log，记录记录了一个domain的运行情况。

日志位置：如，domains/domainname/servers/AdminServer/logs。

通过日志审计与分析系统以远程文件访问方式，主动请求Weblogic服务器和文件所在路径，将日志信息传输到日志审计与分析系统。

3.数据库

lMySQL日志

MySQL日志主要有重做日志（redo log），回滚日志（undo log），二进制日志（binlog），错误日志（errorlog），慢查询日志（slow query log），一般查询日志（general log），中继日志（relay log）。

错误日志，记录 MySQL 服务实例启动、运行、停止等过程信息。

一般查询日志，记录了所有对MySQL数据库的执行qsl。

慢日志查询，记录响应时间超过参数 long_query_time的查询语句。

二进制日志，记录数据库的所有变化，简单的说，所有涉及数据变动的操作，都会记录下来。

日志位置，如/var/lib/mysql

通过日志审计与分析系统以远程文件访问方式，主动请求MySQL服务器和文件所在路径，将日志信息传输到日志审计与分析系统。

通过日志审计与分析系统以数据库访问方式，主动请求MySQL数据库并进行数据查询，将日志信息传输到日志审计与分析系统。

lOracle日志

Oracle日志主要有：警告日志、trace日志、audit日志、redo日志、归档日志。

警告日志，主要包括以下信息：

（1）所有的内部错误（ORA-600）信息，块损坏错误（ORA-1578）信息，以及死锁错误（ORA-60）信息等。

（2）管理操作，例如CREATE、ALTER、DROP语句等，以及数据库启动、关闭以及日志归档的一些信息。

（3）与共享服务器或调度进程相关功能的消息和错误信息。

（4）物化视图的自动刷新过程中出现的错误。

（5）动态参数的修改信息。

audit日志，记录用户对数据库进行的操作，如语句审计、权限审计、对象审计、网络审计。

日志位置，如/home/oracle/oracle/product/11.2.0/db_1/rdbms/log。

通过日志审计与分析系统以远程文件访问方式，主动请求Oracle服务器和文件所在路径，将日志信息传输到日志审计与分析系统。

通过日志审计与分析系统以数据库访问方式，主动请求Oracle数据库并进行数据查询，将日志信息传输到日志审计与分析系统。
