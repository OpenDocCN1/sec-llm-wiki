# **pocsuite3****简介**

Pocsuite3 是由知道创宇 404 实验室打造的一款基于 GPLv2 许可证开源的远程漏洞测试框架。自 2015 年开源以来，不断更新迭代，代码更新非常活跃。

可以直接使用 Pocsuite3 进行漏洞的验证与利用，也可以基于 Pocsuite3 进行 PoC/Exp 的开发，因为它也是一个 PoC 开发框架；同时，还可以在你的漏洞测试工具里直接集成 Pocsuite3，它也提供标准的调用类。

Pocsuite3 还具有一些其他的特性：

• 支持 verify、attack、shell 三种模式，不仅为扫描而生，也可用于其他场景，比如漏洞利用、获取目标的交互式 shell

•从任何地方动态加载 PoC 脚本（本地文件、redis、数据库、Seebug...）

•从任何地方加载目标（CIDR、本地文件、redis、数据库、ZoomEye...）

•结果可以轻松导出

•插件系统，用户可自定义 TARGETS、POCS、RESULTS 类型插件，可拓展性强

•动态 hook urllib3、requests，方便 PoC 编写及全局控制

•既可以当成一个命令行工具使用，也可以当成 Python 模块导入

•IPv4/IPv6 支持

•全局 HTTP/HTTPS/SOCKS 代理支持

•集成 Seebug (通过 Seebug API 读取指定组件或者类型的漏洞的 PoC)

•集成 ZoomEye、Shodan 等网络空间搜索引擎 (通过 API 批量获取测试目标)

•集成 Ceye、Interactsh (DNSLog 盲打平台)

•代码全开源

和 Metasploit 相比，Pocsuite3 目前不具有后渗透阶段的能力，比较轻量级。而相比于 YAML 格式的 PoC 框架，Pocsuite3 更加灵活，可以直接使用大量的第三方库，用户只要会写 Python，就能快速上手。

# **PoC 脚本编写规范**

保证编写的PoC能够在PocSuite3上正常运行，就需要遵守PocSuite3编写PoC脚本的一些规范，这小结会介绍一下PocSuite3中PoC脚本的三种运行模式（不同云模式要求PoC取得的结果是不同的）、如何使用 \-n 参数自动生成PoC 模板、以及PocSuite3中定义的通用方法。

其他的脚本编写规范可查看官方文档：

https://pocsuite.org/guide/what-is-pocsuite3.html

## **PoC 脚本的三种模式**

在 Pocsuite3 中，PoC 脚本有三种运行模式，分别为：

**verify 模式**，验证漏洞存在。验证方式取决于具体的漏洞类型，比如检查目标的软件版本、判断某个关键 API 的状态码或返回、读取特定文件、执行一个命令并获取结果，结合 DNSLog 带外回显等。该模式用于批量漏洞排查，一般不需要用户提供额外参数 ，且应尽可能对目标无害。

**attack** 模式，攻击模式，可实现某种特定需求。比如获取特定数据、写入一句话并返回 shell 地址、从命令行参数获取命令并执行、从命令行参数获取文件路径并返回文件内容等。

**shell 模式**，获取交互式 shell，此模式下会默认监听本机的 6666 端口（可通过 \--lhost、\--lport 参数修改），编写对应的代码，让目标执行反连 Payload 反向连接到设定的 IP 和端口即可得到一个 shell。

## **自动生成模板**

PoC 文件会包含漏洞编号、PoC版本、作者、漏洞公开事件、PoCket编写时间、PoC修改时间、参考链接、漏洞名称、漏洞类型、厂商、系统名称、受影响版本等一些其他信息，每次编写都需要手动去输入这些信息，但从Pocsuite3 \>=1.9.4 版本支持使用 \-n 或 \--new 参数自动生成 PoC 模版，具体操作见下图所示。

# **PoC 编程技巧**

## **PoC 自定义参数**

有时 pocsuite3 自带的参数不能满足我们 PoC 编写的需求，通常需要再自定义一些参数（例如：有的 PoC 脚本需要填写登录信息，或者任意命令执行时执行任意命令等情况），pocsuite3 中支持自定义参数，在 POCBase 类中的核心代码如下所示：

self.options \= OrderedDict()  
*\# module options init*  
**if** hasattr(self, "\_options"):  
    self.options.update(self.\_options())

自定义的参数必须按照特定的格式：

•方法名为：\_options()

•返回值为：OrderedDict 对象

同时，pocsuite3 定义了一系列定义参数的字段类型，在文件头部引入下面的代码即可开始自定义字段：

from pocsuite3.api import (  
    OptString,  
    OptDict,  
    OptIP,  
    OptPort,  
    OptBool,  
    OptInteger,  
    OptFloat,  
    OptItems,  
)

**代码示例**：自定义登录信息参数

from collections import OrderedDict  
  
from pocsuite3.api import Output, POCBase, POC\_CATEGORY, register\_poc, requests, VUL\_TYPE  
from pocsuite3.api import OptString  
  
  
**class** DemoPOC(POCBase):

        o\["password"\] \= OptString('', description\='这个poc需要用户密码，请输出用户密码', require\=False)  
        **return** o  
  
register\_poc(DemoPOC)

代码中定义了两个参数：username 和 password，默认值都为空，其中username 为必须项，passoword 为可选项。注意多个单词拼接的参数使用下划线链接

## **目标状态检查**

在对目标进行漏洞验证之前，先对目标进行一些列检查，避免做一些无用功。该功能主要是调用 POCBase 基类中已经实现的 \_check() 方法，\_check() 方法包含的功能为：端口开放性检查、http/https 协议自动纠正、首页关键词 check、关键词蜜罐检查。

•**端口开放检查**: 根据提供的目标信息截取到(ip, port)，并做一个全连接来判断目标服务的状态。

•**http/https**** 协议自动纠正**: 尝试HTTP连接并根据返回信息判断正确的链接，最后根据成功连接修改协议和端口。

•**首页关键词 check**: 在成功连接返回的请求头和请求体中判断是否存在 dork 参数，若不存在返回 False，\_exploit() 方法后续代码不会再执行。

•**关键词蜜罐检查**: 判断成功连接返回的请求头和请求体中是否存在指定的关键字，若数量大于等于3，则为蜜罐；判断<title>标签数量，若大于5，则为蜜罐；判断basic realm=数量，若大于5，则为蜜罐；判断server:数量，若大于5，则为蜜罐。

**def** \_exploit(self, param\=''):  
        *\# 状态检查（端口开放检查、http/https 协议自动纠正、首页关键词 check、关键词蜜罐检查）*  
        *\# dork='' 指定一个服务响应中有标志性的字符串*  
        *\# allow\_redirects=False 拒绝默认的 301/302 重定向*  
        *\# return\_obj=False # 是否返回 response 对象*  
        *\# is\_http=True*  
        *\# honeypot\_check=True # 是否判断蜜罐*  
        **if** **not** self.\_check(dork\='<title>Login to Webmin</title>'):  
            **return** False

## **请求链接处理**

我们在做编写poc时，不可避免会遇到url拼接的问题，这个主要问题在于***目标参数***上，如 \-u 参数，https://www.baidu.com/ 和 https://www.baidu.com 这两种形式都接受，但是我们不知道用户到底传的是那种形式（虽然有时多个斜杠没啥问题，但有时会影响到PoC的验证）。这里提供两种实现思路：

•**第一种方式**：判断传入的参数是否以正斜杠结尾，若以斜杠结尾，则添加不以斜杠开头的参数；若不以斜杠结尾，则添加以斜杠开头的参数。

•**第二种方式**：不管有没有斜杠，先做一个清除斜杠的操作，在拼接以斜杠开头的参数。

**代码示例**：判断是否以斜杠结尾再决定拼接方式

**def** \_verify(self):  
        result \= {}  
        param \= 'Item/list.asp?id=34'  
        **if** self.url.endswith('/'):  
            url \= self.url + param  
        **else**:  
            url \= self.url + '/' + param  
          
        logger.info(url)  
        **return** self.parse\_output(result)

**代码示例**：先处理斜杠再拼接（推荐）

**def** \_verify(self):  
        result \= {}  
        param \= '/Item/list.asp?id=34'  
        url \= self.url.rstrip('/') + param  
          
        logger.info(url)  
        **return** self.parse\_output(result)

注：

在 >= 1.9.5 的版本中已经采用第二种方式处理了请求链接的中的斜杠问题。具体的情况为：

代码示例：

*\# 对传入的 url 进行容错处理*  
url\_parse\_result \= urlparse(self.url)  
path\_uri \= ''  
**if** url\_parse\_result.path.endswith('.php'):  
    path\_uri \= url\_parse\_result.path\[:url\_parse\_result.path.rfind('/')\]  
**else**:  
    path\_uri \= url\_parse\_result.path  
    *\# logger.debug(path\_uri)*  
    vul\_url \= urljoin(self.url, path\_uri + uri)

## **调试打印日志**

在编写poc时，可能因为环境问题或理解问题，导致漏洞验证结果与我们想象的结果有出入时，经常需要打印中间变量的信息来帮助我们定位问题所在的行，pocsuite3 中定义了格式化的日志打印模块：logger。  
logger 是 pocsuite3 自定义的一个格式化日志打印接口，是通过对 Python3 内置的 logging 模块进行封装，实现了 DEBUG、INFO、WARNING、ERROR、CRITICAL五种日志等级（logger 的核心代码在 pocsuite3\\lib\\core\\log.py 中）。

•DEBUG: 用来调试程序的，不会影响程序运行。

•INFO: 程序正常运行时，记录一些需要的信息。

•WARNING: 程序运行过程中，有不正常的地方，可能会导致错误，但目前对程序影响不大。

•ERROR: 程序运行过程中，发生错误，但程序可以自我修复，继续运行。

•CRITICAL: 十分严重的错误，程序无法自我修复，导致程序停止运行。

**代码示例：**

*\# 使用之前必须添加 logger 模块*  
from pocsuite3.api import (  
    Output,  
    POCBase,  
    logger  
)  
  
  
**class** DemoPOC(POCBase):  
    **def** \_verify(self):  
        result \= {}  
  
        logger.debug('this is a debug!')  
        logger.info('this is a info!')  
        logger.warning('this is a warning!')  
        logger.error('this is a error!')  
        logger.critical('this is a critical!')  
  
        **return** self.parse\_output(result)  
        

## **请求信息打印**

使用 requests 发送请求时，我们有时想要知道我们发送的请求到底发送了哪些信息？是否能以 burpsuite 抓到的请求一样以 Raw的格式展示出来？目前 pocsuite3 并未实现一个接口来做这件事情，但其安装的依赖库：requests\_toolbelt，可以帮助我们实现该功能。具体的实现代码如下所示：

from requests\_toolbelt.utils import dump  
  
**def** \_exploit(self, param\=''):  
        ...  
  
        headers \= {  
            'Content-Type': 'application/x-www-form-urlencoded',

            }

        *\# 格式化打印请求信息*  
        logger.debug(dump.dump\_response(res, b'').decode('utf-8').split('>')\[0\])  
        *\# 这里使用了一个非常妙的技巧处理返回信息*  
        *\# 使用 split() 方法只截取部分字符串返回*  
        **return** res.text.split('The current password is incorrect')\[\-1\].split('</h3></center>')\[0\]

## **编写验证模式**

验证模式主要分为三步：参数构造，调用 \_exploit() 方法，判定结果并返回。

**命令执行有回显类 ****\_verify()**** 代码示例：**

**def** \_verify(self):  
        *\# 定义返回结果*  
        result \= {}  
        *\# 验证漏洞是否存在的标志*  
        flag \= random\_str(6)

        **return** self.parse\_output(result)

## **编写 shell 模式**

shell 模式主要分为三步：参数构造，调用 \_exploit() 方法，判定结果并返回。

**命令执行类 ****\_shell()**** 代码示例：**

**def** \_shell(self):  
        **try**:  
            *\# 只需要一步*  
            *\# self.\_exploit(REVERSE\_PAYLOAD.BASH.format(get\_listener\_ip(), get\_listener\_port()))*  
            self.\_exploit(REVERSE\_PAYLOAD.PYTHON.format(get\_listener\_ip(), get\_listener\_port()))  
        **except** Exception:  
            **pass**

## **解决 **webshell** 被本地查杀**

说明：好不容编写了一个漏洞利用的 PoC，（例如：利用文件上传漏洞写入 webshell）获取目标主机的 webshel，手还没有捂热直接就被本地的杀软给删了，漏洞特征太过明显直接就被杀的无法保存，虽然可以通过设置白名单的方式来避免被本地查杀，但要是换到另一个设备上还是会被查杀，如何避免 PoC 中的 payload 被查杀呐？

## **在结果中显示请求包信息**

**场景描述**：

在 attack 模式中，向目标主机写入了一个 webshell，并请求了 webshell 的地址以判断是否攻击成功。

**需求目标**：

在结果中显示 webshell 的地址，以及连接 webshell 的密码。

**代码示例：**

**def** \_attack(self):  
    result \= {}  
    pwd \= self.get\_option('pwd')  
    *\# 密码为空则随机生成*

        pwd \= random\_str(6)  
    param \= f'xxxxxx shellcode(包含pwd) xxxxxx'

        result\['WebShell'\]\['pwd'\] \= pwd

说明：
