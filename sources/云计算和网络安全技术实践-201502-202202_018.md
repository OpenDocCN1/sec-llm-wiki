国庆假期比较懒，没实践新的东西，就把节前做的rancher的安装部署记录发出来吧，

rancher的安装部署真是太简单了，比kubesphere简单很多，

只需一条命令就完成了，

docker run -d --restart=unless-stopped -p 80:80 -p 443:443 --privileged rancher/rancher，

这里得解释一下，所需要的是docker环境，而不是在kubernetes下安装部署的，这一点就跟kubesphere不同，kubesphere是在kubernetes下安装部署的，也就意味着rancher是可以独立于kubernetes之外的，比如你可以单独搞一个rancher的管理机，

另外还有一个需要注意的地方是，privileged参数必须得给，也就是rancher容器必须要特权，不然起不来，

当然80和443端口也得是空着没用的，不然你就得换发布端口，

最后一个问题，直接执行docker run会有失败的情况，那就提前把rancher的镜像pull下来，docker pull rancher/rancher-agent:v2.6.0，

接着就是把kubernetes注册到rancher上来了，

需要先在kubernetes里安装组件，

先查一个用户，

master@master:~$ cat .kube/config | grep user  
    user: kubernetes-admin  

然后创建集群角色绑定，

kubectl create clusterrolebinding cluster-admin-binding --clusterrole cluster-admin --user kubernetes-admin，

打开rancher的界面，添加kubernetes集群，得到kubernetes注册的命令，

curl --insecure -sfL https://10.90.11.166/v3/import/kdldnsndrwb4sl8zggf8hr8mwqxz482qc6qdshts24qb6dwdmwxbhm\_c-m-4gqcpclz.yaml | kubectl apply -f -，

其实就是从rancher上下载一个yaml模板来执行，结果就是在kubernetes集群的每个node里安装rancher的agent容器，并注册到rancher上来，

执行成功后，就可以正式访问rancher的界面了，

界面很简单，相比kubesphere来说，个人感觉要差一些，唯一好处是rancher支持多kubernetes集群的注册，而kubesphere仅支持单kubernetes集群，另外rancher的生态感觉要强一些，支持应用市场，可以自行安装所需的应用，比如prometheus，因为这个已经被kubesphere默认安装过了，我就没再安装了。
