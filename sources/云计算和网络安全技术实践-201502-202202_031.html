本周兑现fwknop的实践，为啥要实践fwknop呢，因为fwknop是一个开源的单包授权（端口敲门）的项目，单包授权（端口敲门）又是零信任方案里的关键技术之一，值得研究吧，

奇怪的是零信任方案炒的这么火，而fwknop项目三年前就停了，看来单包授权（端口敲门）的技术在实际业务使用中还是问题不少，不管怎么样，实践了就知道了，

先说我的组网，client—>NAT—>server，

先给server安装fwknop服务端软件，sudo apt-get install fwknop-server，

再给client安装fwknop客户端软件，sudo apt-get install fwknop-client，

先是用client的地址生成了认证密钥，验证发现单包认证过不去，

因此改成用SNAT后的地址地址生成认证密钥，就能认证过去了，

sudo fwknop -A tcp/22 -a 192.168.137.134 -D 192.168.137.100 --key-gen --use-hmac --save-rc-stanza，

查到client本地生成的认证密钥，

sudo cat /home/ubuntu/.fwknoprc，

把KEY_BASE64和HMAC_KEY_BASE64的内容拷贝到server上，

sudo vim /etc/fwknop/access.conf，

还要编辑server的配置文件，指定接口，

sudo vim /etc/fwknop/fwknopd.conf，PCAP_INTF ens32，

接着给server配置iptables策略，注意先后顺序，

sudo iptables -I INPUT 1 -i ens32 -p tcp --dport 22 -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT，

sudo iptables -I INPUT 1 -i ens32 -p tcp --dport 22 -j DROP，

此时外网已经无法再ssh访问server，需要进server的控制台去启动服务，

sudo fwknopd，

然后就可以去client上做验证了，

直接ssh访问server，ssh ubuntu@192.168.137.100，发现不通，

单包授权（端口敲门）后，sudo fwknop -n 192.168.137.100，

再次ssh访问server就通了，

验证过程中发现两个问题，

一是新起一个client，不安装fwknop客户端软件，但是跟之前的client在同一个网络里，也是通过SNAT访问server，当之前的client通过单包授权（端口敲门）后，这个没安装fwknop客户端软件的client也能ssh访问server，这个问题可能是单包授权（端口敲门）技术最大的漏洞，

二是虽然单包授权（端口敲门）后，client能够访问server，但是很快会话就断了，还需要重新单包授权（端口敲门），这样可能对一些长连接业务影响很大，

fwknop的实践就这一期吧，下期内容是啥还没想好，肯定不会跳票，再见。
