本周接着实践Elastic Security，

还是上周的环境，为了能验证做攻击的效果，把ubuntu换成了metasploitable3，最开始想用metasploitable2的，但是验证发现Elastic Security的agent不支持，

这个metasploitable3也是折腾了不少时间，

先是想自己build，

参考官方指南，https://github.com/rapid7/metasploitable3/，

本地先安装最新版本的VirtualBox，

然后安装最新版本的Vagrant，

Packer不能是最新版本，验证1.5.6可以，不用安装，但是要添加环境变量，

还得安装vagrant插件，vagrant plugin install vagrant-reload，

build windows的metasploitable3，

packer build -force --only=virtualbox-iso ./packer/templates/windows_2008_r2.json，

build linux的metasploitable3，

packer build -force --only=virtualbox-iso ./packer/templates/ubuntu_1404.json，

结果折腾大半天，一个都build不成功，只能用rapid7两年前build好的，

https://app.vagrantup.com/rapid7/boxes/metasploitable3-win2k8，

https://app.vagrantup.com/rapid7/boxes/metasploitable3-ub1404，

我这里只用linux版本，

vagrant box add --name metasploitable3-ub1404 D:\metasploitable3-ub1404.box，

vagrant init metasploitable3-ub1404 --force，

vagrant up，

metasploitable3的插曲就说到这儿，还是回来说Elastic Security，

这就windows和linux的agent都注册上来了，

策略我是三个插件都装了，

Endpoint Security这边也都上线正常，

做攻击前，先查了一下各自目前的进程监控情况，

windows的，

linux的，

开始攻击，

windows用的以前实践过的CVE-2020-0796，

linux用的metasploitable3的一个漏洞利用，

后头看Elastic Security上的监控情况，windows没啥变化，

linux的进程监控有变化，

整体威胁监控没反应，

总结就是Elastic Security离实用还差不少，保持关注吧。
