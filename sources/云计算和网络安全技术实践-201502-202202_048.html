本篇是kubernetes之istio的第一次实践，目的是看看sidecar的防火墙能力，基本达到目的，

首先安装istio环境，

curl -L https://istio.io/downloadIstio | sh -，
export PATH="$PATH:/home/ubuntu/istio-1.9.0/bin"，
istioctl install --set profile=minimal -y，

注意这里我选择了功能最小集，实践sidecar够用了，

如上图，安装成功后，环境中多出来istiod的pod，

配置让新创建的deployment自动注入sidecar，

kubectl label namespace default istio-injection=enabled，

如果要取消，kubectl label namespace default istio-injection-，

新创建个httpd-sidecar的deployment，

sudo vim httpd-sidecar-deployment.yaml，
apiVersion: apps/v1
kind: Deployment
metadata:
  name: httpd-sidecar
  labels:
    app: httpd-sidecar
spec:
  replicas: 3
  selector:
    matchLabels:
      app: httpd-sidecar
  template:
    metadata:
      labels:
        app: httpd-sidecar
    spec:
      runtimeClassName: kata-containers
      containers:
      - name: httpd-sidecar
        image: docker.mirrors.ustc.edu.cn/library/httpd
        imagePullPolicy: IfNotPresent
        ports:
        - containerPort: 80

注意到上面模板中我继续使用了kata-containers，算是混合实践了，

给httpd-sidecar的deployment创建个service，

sudo vim httpd-sidecar-service.yaml，
apiVersion: v1
kind: Service
metadata:
  name: httpd-sidecar-service
spec:
  type: NodePort
  selector:
    app: httpd-sidecar
  ports:
  - protocol: TCP
    nodePort: 31699
    port: 80
    targetPort: 80

接下来就可以访问验证了，

再创建个AuthorizationPolicy，拒绝外部的访问，

sudo vim AuthorizationPolicy.yaml，
apiVersion: security.istio.io/v1beta1
kind: AuthorizationPolicy
metadata:
  name: deny-all
  namespace: default
spec:
  {}

再次验证，无法访问了，

这个过程中访问之前没注入sidecar的httpd-deployment和service，不受影响，本次实践就到这里。
