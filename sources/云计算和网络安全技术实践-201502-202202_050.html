之前实践过kubevirt下起虚机，这里面有个问题，就是为啥要用虚机，其实并不是业务需要用，而是vnf需要用，接着问题又来了，由于kubernetes下容器只能有一个集群网络的网卡，就算能起vnf虚机了，又能有啥用，这就引出了本周实践的内容，multus，能够让kubernetes下起的vnf虚机使用多网卡，

在一个普通kubernetes环境下安装multus软件，

git clone https://github.com/intel/multus-cni.git，

kubectl apply -f multus-cni/images/multus-daemonset.yml，

看到multus的系统pod启动成功就算成了，

接着就可以做实验了，创建一个网络，这里跟宿主机管理接口同一网络，

sudo vim network.yaml，
apiVersion: "k8s.cni.cncf.io/v1"
kind: NetworkAttachmentDefinition
metadata:
  name: macvlan-conf
spec:
  config: '{
      "cniVersion": "0.3.0",
      "type": "macvlan",
      "master": "ens32",
      "mode": "bridge",
      "ipam": {
        "type": "host-local",
        "subnet": "192.168.137.0/24",
        "rangeStart": "192.168.137.200",
        "rangeEnd": "192.168.137.216",
        "routes": [
          { "dst": "0.0.0.0/0" }
        ],
        "gateway": "192.168.137.1"
      }
    }'

kubectl apply -f network.yaml，

创建容器pod，使用annotations，

给下期留点空间，我就不用vnf了，就用个普通容器吧，

sudo vim sshd-multus-pod.yaml，
apiVersion: v1
kind: Pod
metadata:
  name: multus-sshd
  annotations:
    k8s.v1.cni.cncf.io/networks: macvlan-conf
spec:
  containers:
  - name: multus-sshd
    image: docker.mirrors.ustc.edu.cn/rastasheep/ubuntu-sshd:14.04
    ports:
    - containerPort: 22
kubectl apply -f sshd-multus-pod.yaml，

进入容器里查看，kubectl exec -it multus-sshd bash，

能够看到容器里除了一个集群网络的网卡，还多了一个新创建网络的网卡，


从外部网络访问验证一下，完美可达，
