之前不是研究kubernetes without docker么，感兴趣的往前边翻两个blog，那时说到这不用docker了，本地镜像不能用，很麻烦，就想着如果自己搭建一个本地私有的docker镜像仓库是不是就能方便很多，

解这个问题得分两步，第一步是搭建个本地私有的docker镜像仓库，这个拿docker环境做测试就可以；第二步是让containerd能够使用这个本地私有的docker镜像仓库，

本周咱们先来说第一步......中的第一种情况（哈哈，为了能多发几期blog），

1、http不带用户名密码认证的情况

这个最简单，docker run -d -p 5000:5000 --restart=always --privileged=true -v /root/docker/registry:/var/lib/registry registry，

测试也很简单，先从docker hub上下载个镜像，

docker pull rastasheep/ubuntu-sshd:14.04，

然后给这个镜像改个标签，

docker tag rastasheep/ubuntu-sshd:14.04 192.168.137.25:5000/rastasheep/ubuntu-sshd:14.04，

本地再修改docker的配置，指示可以不安全的访问这个本地仓库，

sudo vim /etc/docker/daemon.json，
{ "insecure-registries":["192.168.137.25:5000"] }

重启服务，sudo service docker restart，

这就可以向仓库传镜像了，docker push 192.168.137.25:5000/rastasheep/ubuntu-sshd:14.04，

查看镜像，curl http://192.168.137.25:5000/v2/_catalog，

把本地的镜像删掉，再从这个本地仓库把镜像下载回来，

docker pull 192.168.137.25:5000/rastasheep/ubuntu-sshd:14.04，

如果是kubernetes环境的话，创建个deployment，

sudo vim sshd-deployment.yaml，
apiVersion: apps/v1
kind: Deployment
metadata:
  name: sshd
  labels:
    app: sshd
spec:
  selector:
    matchLabels:
      app: sshd
  template:
    metadata:
      labels:
        app: sshd
    spec:
      containers:
      - name: sshd
        image: 192.168.137.25:5000/rastasheep/ubuntu-sshd:14.04
        imagePullPolicy: IfNotPresent
        ports:
        - containerPort: 22

kubectl apply -f sshd-deployment.yaml，
kubectl get pod -o wide，就能看到使用本地镜像仓库创建的pod了，
