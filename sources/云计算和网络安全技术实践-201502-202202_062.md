# OpenStack下trunk接口的使用（二）

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzA3MjM5MDc2Nw==&mid=2650746097&idx=1&sn=d6f0a7524949f1e1ce0d80083e9031f5&chksm=87148df1b06304e79ec8d02560bae6bc2ac255208aa40b2491a6305c214bdfe547860e7eb15f&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzA3MjM5MDc2Nw==&mid=2650746097&idx=1&sn=d6f0a7524949f1e1ce0d80083e9031f5&chksm=87148df1b06304e79ec8d02560bae6bc2ac255208aa40b2491a6305c214bdfe547860e7eb15f&scene=27#wechat_redirect)

之前继续实验的OpenStack下trunk接口的使用，是用vxlan网络里的接口做的trunk port，subport也是vxlan网络里的接口，本周实验了flat网络里的接口做trunk port，vlan网络里的接口做subport的情况，

实践环境还是devstack跑出来的一个all in one的OpenStack，

默认的配置不支持trunk接口，需要更改neutron的配置，

sudo vim /etc/neutron/neutron.conf，

service\_plugins = router,trunk，

需要重启neutron服务，devstack下就把所有服务都重启了算了，

sudo service "devstack@\*" restart，

下面是一个flat网络和一个vlan网络，  

![](../Images/b7f66a29ace5be531d5848265ab03b41.png)

在flat网络里创建trunk port，

![](../Images/0fc14f6feab9f120efc74a74758fc623.png)

在vlan网络里创建subport，注意subport要关闭安全检查，

![](../Images/627b18e4c122eed3e89078ac2f61f514.png)

然后就可以在命令行下创建trunk了，

openstack network trunk create --parent-port flat-trunk-port flat-trunk，  

然后创建一个虚墙使用这个trunk port，并在vlan网络里创建一个测试业务虚机，

![](../Images/35076dd28563dad839c9efc8bdb69cf4.png)

再在命令行下把这个subport配置给上面创建好的trunk，需要给分配一个内部没使用的vlan id，这里直接跟外部网络vlan一样就行，不一样也行，

openstack network trunk set --subport port=vlan-subport1,segmentation-type=vlan,segmentation-id=100 flat-trunk

然后在虚墙里配置好subport的子接口，

![](../Images/a8261bbea034f6cf004707c53283b145.png)

整个测试拓扑就是这样了，vrouter是完全没用上，防火墙虚机也不用伸接口到业务子网里去，

![](../Images/fcb7c9a97b2e0bd4071a7acd19fbd109.png)

下面来看测试效果，在外面vlan网络里再创建一个虚墙，并配置好子接口，

![](../Images/900cb3c55c63b7d458c6bc3dd1d3f7ba.png)

在外面vlan网络的虚墙里分别ping内部trunk port墙的子接口和vlan网络里的业务虚机，都是通的，

![](../Images/195cbd450e01b5f7b59d9c1644a2388b.png)

方案验证完成，trunk port的使用原理之前分析过，这里就不重复分析了。
