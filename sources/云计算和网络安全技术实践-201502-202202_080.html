很多人都搞不清楚kubernetes的ingress是怎么个机制，实践是检验真理的唯一标准，本周末咱们就总结一下，

先安装一个kubernetes的calico环境，这个往期有详细的讲解，就不说了，

咱们从ingress的安装说起，ingress有多种，我实践的是ingress-nginx，

下载安装模板文件，

wget https://raw.githubusercontent.com/kubernetes/ingress-nginx/master/deploy/static/provider/baremetal/deploy.yaml，

可以先看看这个模板文件，主要有两个地方值得关注，

这个地方说的是ingress-nginx容器实体是怎么个情况，没啥好说的，

这个地方说的是ingress-nginx服务是怎么个情况，值得注意的是，ingress-nginx服务是NodePort方式发布的，而且NodePort没有静态预置，就意味着动态分配，

执行安装模板文件，kubectl apply -f deploy.yaml，

等待ingress-nginx相关的容器实体都成功running，

可以查看ingress-nginx相关的容器和服务，能够看到ingress-nginx容器实体所在的node节点，以及ingress-nginx服务以NodePort方式发布时动态分配的NodePort，30514是http的端口，

接下来咱们就可以创建ingress来做业务效果验证了，

前提是先创建好后端的httpd-deployment和httpd-service，这个往期也有详细介绍，也不说了，直接看ingress的创建，测试ingress的模板如下，

apiVersion: extensions/v1beta1
kind: Ingress
metadata:
  name: ingress-nginx
  namespace: default
spec:
  rules:
  - host: nginx.test.com
    http:
      paths:
      - path:
        backend:
          serviceName: httpd-service
          servicePort: 80

我写了个最简单的，域名向后端service的loadbalance，

执行完这个ingress模板文件后，查看ingress的情况，能够看到域名对应的NodePort地址，以及loadbalance到后端服务的endpoints情况，

在访问机上本地填上域名和地址的静态解析关系，

sudo vim /etc/hosts，192.168.137.102 nginx.test.com，

访问看效果，成功，完美，
