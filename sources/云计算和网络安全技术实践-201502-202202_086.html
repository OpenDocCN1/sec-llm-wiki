很早以前实践过OpenStack下trunk接口的使用，那时对这个功能的使用理解的不太对，最近有时间重新实践一下，更新一下知识，

参考https://docs.openstack.org/neutron/ussuri/admin/config-trunking.html，

实践环境就是devstack跑出来的一个all in one的OpenStack，

默认的配置还不支持trunk接口，需要更改neutron的配置，

sudo vim /etc/neutron/neutron.conf，

service_plugins = router,trunk，

需要重启neutron服务，devstack下就把所有服务都重启了算了，

sudo service "devstack@*" restart，

首先创建一个网络做trunk使用，

然后在这个网络里创建一个接口做为trunk接口使用，

然后就可以在命令行下创建trunk了，

openstack network trunk create --parent-port admin-trunk-port admin-trunk，

接着就可以创建虚机使用这个trunk接口了，这里就创建一个防火墙虚机，

然后拿既有的业务网络做实验，先在业务网络里创建网关接口，注意放开安全检查，

然后在命令行下把这个网关接口配置给上面创建好的trunk，需要给分配一个内部没使用的vlan id，

openstack network trunk set --subport port=admin-trunk-service-subport1,segmentation-type=vlan,segmentation-id=100 admin-trunk

防火墙虚机里需要配置相应的子接口，并配置上网关地址，

这就可以测试效果了，在业务虚机里ping网关地址，通了就对了，

整体的组网就是这样，vr是完全没用上，防火墙虚机也不用伸接口到业务子网里去，

到ovs下看看原理，首先是br-int bridge，多了跟trunk bridge互相patch的两个接口，用来一发一收，发就是从业务虚机出来的包，收就是发给trunk接口的包，后者有些奇怪，竟然还带着tag，但是流量还通，说明这个tag并不起作用，

然后是trunk bridge，有两个跟br-int bridge互相patch的接口，也是一收一发，收的是从br-int转过来的包，在trunk bridge里转vlan id，发的是转回br-int bridge的包，
