从SUSE的安装盘到支持Cloud-Init的虚机镜像

之前写过从CentOS的安装盘到支持Cloud-Init的虚机镜像的实践，最近碰到又有一个合作小伙伴的产品是基于SLES-11-SP3的，为了研究它的Cloud-Init安装我这是一路披荆斩棘，终于取到真经，

首先是找SLES-11-SP3安装盘，这个费劲，好不容易搜到了哪个好心人分享到云盘的压缩包，下了一宿，解压一看是两个ISO，只用第一个就好，

然后还是按照以往的经验，先在Workstation下装了个虚机，然后把vmdk传到OpenStack下转成qcow2，注册镜像再重新起虚机，

启动到一半，提示找不到磁盘分区sdb，此路不通，

于是又尝试直接在OpenStack下用光盘安装虚机，

这条路说起来都是一把辛酸泪，先是发现本地的OpenStack无法创建volume了，于是也不知道哪根筋不对，竟然删了想重装，没想到家里网络无法访问任何openstack安装源了，好在公司还有一个环境，又不知道哪根筋不对，竟然给unstack了，然后再重新stack，发现公司网络无法访问任何pip安装源，这个悲催啊，没办法，只能把公司的环境到回到本地再重新stack，这算终于把本地OpenStack环境弄好了，就这个就浪费了大半天的时间，

继续说怎么用光盘在OpenStack下安装虚机，

首先把光盘的iso上传并注册成镜像，然后再创建一个空volume当系统盘，

这就能把虚机安装出来了，安装过程中要把ssh打开，以便好从外面访问做软件安装，

安装完就可以把这个volume上传成镜像了，然后再重新起虚机，

又是一个坎，启动到一半提示找不到磁盘分区/dev/disk/by-id/...-part，

好在从网上搜到了解决办法，编辑两个文件，

vi /etc/fstab，vi /boot/grub/menu.lst，

把凡是/dev/disk/by-id/...-part的地方都改成/dev/vda，再重启虚机，

能正常启动，说明改了也能生效，然后再把volume上传成镜像，最后再重新起虚机，这就成功了，总算完事儿了，

不对，还没说cloud-init呢，这个才是正事儿啊，

cloud-init的安装也是废了很多劲儿，好不容易找到的安装源，

安装过程如下，

zypper ar http://download.opensuse.org/repositories/home:/garloff:/OTC:/cloudinit/SLE_11_SP3/home:garloff:OTC:cloudinit.repo，
zypper refresh，
zypper install cloud-init，
chkconfig cloud-init-local on，
chkconfig cloud-init on，
chkconfig cloud-config on，
chkconfig cloud-final on，

最后又验证了一下新镜像的cloud-init是否有效，启动虚机时注入了密码，

#cloud-config
ssh_pwauth: True
chpasswd:
  list: |
    suse:password
    root:password
  expire: False

结果正确，终于完成了，不容易啊，累个半死啊，

第二天醒来又琢磨了一下以后重新安装openstack怎么办，最后的结论是从公司环境下载openstack安装目录，然后导到本地，就能正常安装了，这样也不错。
