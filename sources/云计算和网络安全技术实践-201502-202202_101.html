咱们都知道Cloud-Init是用于云里虚机启动时初始化的技术手段，这段时间研究的比较多，总结两点，


1、用runcmd还是bootcmd

咱们都知道runcmd和bootcmd都能在虚机启动时注入shell命令，但是区别是啥呢，咱们通过实验来说明，

首先用runcmd，起一个centos虚机，user-data如下，

#cloud-config
password: centos
chpasswd: { expire: False }
ssh_pwauth: True
runcmd:
 - echo nameserver 8.8.8.8 >> /etc/resolv.conf

启动后输入centos作为密码进入虚机，nameserver被正确的写入了，

咱们手动把这个新写入的nameserver删掉，然后重启虚机，

效果出来了，nameserver没有被重新写入，

这个时候咱们执行一条命令，sudo cloud-init clean，再重启虚机，

看到了吧，nameserver又重新被写入了。

接下来咱们继续做bootcmd的实验，起一个centos虚机，user-data如下，

#cloud-config
password: centos
chpasswd: { expire: False }
ssh_pwauth: True
bootcmd:
 - echo nameserver 8.8.8.8 >> /etc/resolv.conf

启动后输入centos作为密码进入虚机，nameserver被正确的写入了，

咱们还是手动把这个新写入的nameserver删掉，然后重启虚机，

这回的效果是nameserver又被重新写入了，

因此总结来说，user-data里用runcmd还是bootcmd，就看你希望首次启动执行命令还是只要重启就执行命令了。


2、怎么更改虚机的user-data

这个技术含量还是有点儿的，就是目前没有API，必须进数据库改数据，

还是这个centos虚机，咱们进入nova_cell1数据库，能够查看到它，

高亮的部分就是它原始的user-data，

#cloud-config
password: centos
chpasswd: { expire: False }
ssh_pwauth: True
bootcmd:
 - echo nameserver 8.8.8.8 >> /etc/resolv.conf

这个时候咱们创建一个临时虚机cirros，把希望centos虚机后面用的新user-data给它配置上，我这里就是改个密码，

#cloud-config
password: password
chpasswd: { expire: False }
ssh_pwauth: True
bootcmd:
 - echo nameserver 8.8.8.8 >> /etc/resolv.conf

注意，黑科技来了，通过下面操作把cirros虚机的user-data更新给了centos虚机，

create temporary table instances1 like instances;

insert into instances1 select * from instances where uuid='622614a3-f84b-4405-9929-c6823e0e419f';

update instances set user_data = ( select user_data from instances1 ) where uuid = 'd9a141ff-869d-4636-83db-81f2cfa44c1f' limit 1;

咱们再来查看一下centos虚机，

硬看的话能看出来user-data已经跟原来不一样了，

这个时候咱们在centos虚机里执行一下sudo cloud-init clean，然后重启虚机，再登录虚机，centos当密码就不好使了，变成password了，更改虚机的user-data成功。
