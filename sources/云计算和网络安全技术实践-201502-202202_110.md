# 在OpenStack中优雅的使用NAT虚机（阶段性完美）

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzA3MjM5MDc2Nw==&mid=2650745436&idx=1&sn=4f703549ea30d82453300c64c1733aaf&chksm=87148b5cb063024a2dbfcae79fe4fc65bc13dec1b12482aa34370837ee9be7af54ed40d601da&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzA3MjM5MDc2Nw==&mid=2650745436&idx=1&sn=4f703549ea30d82453300c64c1733aaf&chksm=87148b5cb063024a2dbfcae79fe4fc65bc13dec1b12482aa34370837ee9be7af54ed40d601da&scene=27#wechat_redirect)

之前写过几次在OpenStack中优雅的使用NAT虚机，记得最近一次的方法是在路由器上给防火墙虚机创建一个互联网络，然后在路由器上配置默认路由指向虚拟防火墙，这就相当于在路由器外面部署一台虚拟防火墙，完全的南北向控制能力，业务子网间的控制就无能为力了，

随着OpenStack的不断进步，其实这个方案也可以变得更加优雅，本周末我们来看另外一个更漂亮的用法，它解决了业务子网间的控制问题，

首先创建两个做实验的网络，一个是业务网络，另一个是防火墙网络，

![](../Images/6b7645e61be94ddebe59b4575a150205.png)

然后创建路由器，只给防火墙网络加上网关接口，

![](../Images/f357b65f5965b75e89afdd9fe23f437c.png)

注意，最关键的地方来了，

在业务网络里创建一个port，指定成业务网络的网关地址，并放开安全检查，这个以前都是命令行操作的，现在直接在界面里一个去勾选就搞定了，

![](../Images/32d27e59193362dc674fe96833d0639f.png)

接着就可以创建实验的虚机了，一个是业务虚机，另一个是防火墙虚机，防火墙虚机用了两个接口，一个是防火墙网络里的，另一个就是上面给业务网络创建的网关port，并给防火墙网络的接口绑定一个弹性IP，

![](../Images/f3a5ec9d643871013614c1953ed08a91.png)

这样下来，整体拓扑就变成了这样，

![](../Images/ac4d0e6451bd5aac6207eca600524cdc.png)

接下来我们要验证一下SNAT业务了，

首先要到防火墙虚机里配置一下访问控制策略和SNAT策略，防火墙虚机用的我司产品，这个就不细说了，  

最后到业务虚机里验证一下，没毛病，

![](../Images/ed364b324c911c75dd457b8d81dcf812.png)

不知道各位看官发现没有，整个过程我都没有动一次命令行，这就是跟之前用法的区别，也就是我说的更优雅的地方，当然这只是玩儿了SNAT，如果想玩儿DNAT的话，或者说想玩儿的更好的话，就得动命令行了，那个没意思，咱们就等OpenStack的继续进步。
