# 详解calico网络的跨node流量

书接前文，上文书中说到多node环境中deployment的pod是分布式部署的，本周记录一下跨node的容器间流量是怎么走的，  

上周用的httpd容器镜像不太友好，连ifconfig都没有，给它换成rastasheep/ubuntu-sshd:14.04，

在master和slave节点上都docker pull rastasheep/ubuntu-sshd:14.04，

然后也部署一个3pod的sshd的deployment，yaml模板如下

sudo vim sshd-deployment.yaml，

apiVersion: apps/v1  
kind: Deployment  
metadata:  
  name: sshd  
  labels:  
    app: sshd  
spec:  
  replicas: 3  
  selector:  
    matchLabels:  
      app: sshd  
  template:  
    metadata:  
      labels:  
        app: sshd  
    spec:  
      containers:  
      - name: sshd  
        image: rastasheep/ubuntu-sshd:14.04  
        imagePullPolicy: IfNotPresent  
        ports:  
        - containerPort: 22

执行命令进行部署，kubectl apply -f sshd-deployment.yaml，

![](../Images/cb66193c828c5eb8a7a5717d2c9f7211.png)

我们看到3个pod被分布到两个node里，master里有一个，slave里有两个，  

注意到master里的容器地址是10.244.219.x，而slave里的容器地址是10.244.25.x，这两个地址范围很重要，后面看路由的时候是关键信息，  

我们先看看master的网络，

![](../Images/2e5ad44b608190777b4115d79a57ad38.png)

物理接口是ens32，192.168.137.101，隧道口是tunl0，

![](../Images/9869fe88806061cb43896b1cee2c9048.png)

注意到有一条路由是，去往10.244.25.0网络（这个正是slave上容器的地址范围）的流量的下一跳是192.168.137.102，出接口是tunl0，

我们再继续看看slave的网络，

![](../Images/a23232d00c7fba28b99e3c05aede3035.png)

物理接口是ens32，192.168.137.102，隧道口是tunl0，

![](../Images/fb58d48b50b2ce8eeb924fd0b94e23ee.png)

注意到有一条路由是，去往10.244.219.64网络（这个正是master上容器的地址范围）的流量的下一跳是192.168.137.101，出接口是tunl0，

至此我们大概明白了跨node的容器间流量是怎么走的，具体是什么样的呢，  

咱们来抓包看看，

![](../Images/1aff3decb5461602c356e1960e9655be.png)

在master上进入master上的这个容器，让它ping一个slave上的容器，  

![](../Images/2f97bcf661dcd4f2528678bee3700d2d.png)

从抓包上看，跨node的容器间流量是IPIP封装模式，内层是容器地址，外层是宿主机的物理接口地址，
