# 实践证明K8S环境真的需要入侵检测或防御

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzA3MjM5MDc2Nw==&mid=2650745294&idx=1&sn=4812152b3f75af924d089de4ab527589&chksm=871488ceb06301d8c07c36862d86ac2bde26f7c8db0a3f63e78e9701a842cfb7997945bad907&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzA3MjM5MDc2Nw==&mid=2650745294&idx=1&sn=4812152b3f75af924d089de4ab527589&chksm=871488ceb06301d8c07c36862d86ac2bde26f7c8db0a3f63e78e9701a842cfb7997945bad907&scene=27#wechat_redirect)

  
K8S环境需要做网络安全这个事儿没啥争议，争议的是做到什么程度，网络层防火墙和流量监控是否刚需，只做网络层防火墙和流量监控是否足够，入侵检测或入侵防御真的没有必要吗？

本周实践了一个K8S环境下的远程漏洞利用，并证明仅做网络层流量监控是无法解决问题的，

首先得能做网络层流量监控，用PacketBeat+EK，EK部署在外面，PacketBeat以DaemonSet方式部署在K8S的Node上，

EK上就能看到监控过来的网络层流量数据了，  

![](../Images/92906cbd6341dc8f7c765f7d24bdfaca.png)

这都皮毛，下面整毛皮，

在K8S里起一个靶机容器，

sudo vim apache-struts2-cve-2017-5638.yaml，

apiVersion: apps/v1  
kind: Deployment  
metadata:  
  name: apache-struts2-cve-2017-5638  
  labels:  
    app: apache-struts2-cve-2017-5638  
spec:  
  selector:  
    matchLabels:  
      app: apache-struts2-cve-2017-5638  
  template:  
    metadata:  
      labels:  
        app: apache-struts2-cve-2017-5638  
    spec:  
      containers:  
      - name: apache-struts2-cve-2017-5638  
        image: piesecurity/apache-struts2-cve-2017-5638  
        imagePullPolicy: IfNotPresent  
        ports:  
        - containerPort: 8080  

kubectl apply -f apache-struts2-cve-2017-5638.yaml，

从外面可访问，  

![](../Images/b233bd66a7b2eca3fe6c0082b8f10c40.png)

当然也可从外面用metasploit做漏洞利用攻击，

可以选择linux/x64/shell/bind\_tcp做payload，

![](../Images/61fd095852d7b4048a03a4c6079a8a72.png)

攻击完成拿到shell，由于是容器，默认就是root权限，哈哈，

![](../Images/1584cda439e5b28398d9de9f9a2c5b15.png)

也可以选择linux/x64/meterpreter/reverse\_tcp做payload，

![](../Images/54bc9dd1379454f04f24b3ccf1ecb3f8.png)

攻击完成拿到meterpreter shell，

![](../Images/ebf727feff39bdd7dcca16800f65489e.png)

看看EK上都能发现啥，

在知道被攻击情况的前提下，定向搜索，只能看到http业务被访问，无法看到漏洞利用攻击，  

![](../Images/e61393239b69570ad23ad802ee093679.png)

在知道攻击方法的前提下，定向搜索，只能看到靶机向外的TCP端口连接，无法看到shell和meterpreter shell的通信，  

![](../Images/53ca6f1eaf1418ac889a4763219c7364.png)

结论，K8S环境真的需要入侵检测或防御，网络层的防火墙和流量监控在漏洞利用入侵的情况下无能为力。
