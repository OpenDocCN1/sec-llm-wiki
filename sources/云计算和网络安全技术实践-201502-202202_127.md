# 在OpenStack中优雅的使用NAT虚机（二）

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzA3MjM5MDc2Nw==&mid=2650745264&idx=1&sn=19f54f32ed15c0f1dbc764373baeae8c&chksm=871488b0b06301a6ff27c2d5ec6a78f9345ea0716d25cced152a5890a0dd0b3de473162b9a10&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzA3MjM5MDc2Nw==&mid=2650745264&idx=1&sn=19f54f32ed15c0f1dbc764373baeae8c&chksm=871488b0b06301a6ff27c2d5ec6a78f9345ea0716d25cced152a5890a0dd0b3de473162b9a10&scene=27#wechat_redirect)

  
之前实践过在OpenStack中优雅的使用NAT虚机，那个方案有两个不方便的地方，一是虚拟防火墙的外网接口必须直接连到外部网络上，这个对计算节点有特殊要求，另一个是还得通过命令行给防火墙外网接口放开IP检查，

本周找到一个更好的方案能够解决上面两个问题，

组网跟之前差不多，在一个普通租户下，还是要有一个互联网络，虚拟防火墙就是起在这个网络里的，比之前好的是，虚拟防火墙只需要这一个单臂接口就可以了，  

![](../Images/7b00a5746aa6e9fe693e5f63b612f1fd.png)

把业务虚机和虚拟防火墙虚机都给它起来，所有虚机所在网络都是连接到租户的虚拟路由器上的，因此可以给每个虚机都先绑一个弹性IP，咱们先验证连通性，

![](../Images/23c321cb79d9daecc61d5748bdba8082.png)

此时可以看到连通性都没问题，

![](../Images/66f6afc0e416b8110fae5bf60e403599.png)

下面先给虚拟防火墙的接口新增两个同网段IP，不支持界面操作，只能用命令行，

openstack port set --fixed-ip subnet=demo-inter-net,ip-address=172.16.1.241 --fixed-ip subnet=demo-inter-net,ip-address=172.16.1.242 d4254271-fbb9-474a-8b31-fe203a0a3db6，

然后把原来绑给业务虚机的弹性IP解绑再重新绑给虚拟防火墙接口新增的内网IP上，

![](../Images/23f896ea060ef8451f6080ebfb480fb3.png)

接下来就是进虚拟防火墙为两个业务虚机都配置好相应的DNAT策略，

然后再从外网访问业务虚机，验证连通性，

![](../Images/d0edf495b8fa1f696338cef857e6bcbe.png)

没问题，这个方案可是比之前那种是方便多了。

本周只验证了DNAT，下周再通过策略路由验证一下SNAT的情况。
