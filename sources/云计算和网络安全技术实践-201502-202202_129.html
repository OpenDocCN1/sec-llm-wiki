书接上回，上回书说到kubernetes的calico模式，这回咱们接着说防火墙功能，NetworkPolicy，

就拿上回书中创建的几个容器实例做实验，

默认是全通的，

咱们先给它搞个deny all，

sudo vim policy-deny-all.yaml，

apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: default-deny
spec:
  podSelector: {}
  policyTypes:
  - Ingress
  - Egress

kubectl apply -f policy-deny-all.yaml，

验证一下，

咱们给sshd容器写个策略，允许外部ssh访问，

sudo vim policy-sshd-access.yaml，

apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: sshd-network-policy
  namespace: default
spec:
  podSelector:
    matchLabels:
      app: sshd
  policyTypes:
  - Ingress
  - Egress
  ingress:
  - from:
    - ipBlock:
        cidr: 192.168.137.0/24
    ports:
    - protocol: TCP
      port: 22
  egress:
  - to:
    - podSelector:
        matchLabels:
          app: httpd

kubectl apply -f policy-sshd-access.yaml，

验证一下，

虽然策略里放开了sshd容器可以访问httpd容器，但是验证是不通的，因为httpd容器的策略还没有开，给httpd容器开个允许sshd容器访问的策略，

sudo vim policy-httpd-access.yaml，

apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: httpd-network-policy
  namespace: default
spec:
  podSelector:
    matchLabels:
      app: httpd
  policyTypes:
  - Ingress
  ingress:
  - from:
    - podSelector:
        matchLabels:
          app: sshd

kubectl apply -f policy-httpd-access.yaml，

验证一下，

这就calico模式下的NetworkPolicy功能，可用于防火墙业务，如果你是专业防火墙的用户，能够看到NetworkPolicy其实不是太易用，为了让sshd容器访问httpd容器，必须两边都要做策略才行。
