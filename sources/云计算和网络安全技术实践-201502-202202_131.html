之前说过要再研究用K8S来部署抓包容器实例，本周就兑现了吧，

抓包容器的镜像得重新做，

sudo vim Dockerfile，

FROM debian
RUN apt-get update && apt-get install -y \
tcpdump net-tools sshpass
CMD while true ;do tcpdump -i cni0 -G 900 not host 10.244.0.2 and not host 10.244.0.3 -w - | sshpass -p ubuntu ssh -o StrictHostKeyChecking=no ubuntu@192.168.137.200 "cat - > $(ifconfig ens32 | grep "inet " | awk '{print $2}')-$(date +%Y-%m-%d-%H:%M:%S).pcap"; done;

利用K8S的DaemonSet功能，

sudo vim tcpdump-daemonset.yaml，

apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: tcpdump
  namespace: kube-system
  labels:
    k8s-app: tcpdump
spec:
  selector:
    matchLabels:
      name: tcpdump
  template:
    metadata:
      labels:
        name: tcpdump
    spec:
      hostNetwork: true
      containers:
      - name: tcpdump
        image: tcpdump
        imagePullPolicy: IfNotPresent
      terminationGracePeriodSeconds: 30

kubectl apply -f tcpdump-daemonset.yaml，

在K8S环境里一顿访问操作，然后去文件服务器查看，

完美实现抓包并远程存储。

多说一句，我这个是一个All In One的K8S环境，重启后K8S服务自动起不来，找到了一个处理办法，重启后，

sudo swapoff -a，

strace -eopenat kubectl version，

稍等片刻，环境就自动恢复了。

这个就是目前找到的最完美的K8S环境抓包方案了，
