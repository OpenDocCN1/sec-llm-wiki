书接上回，有人问，K8S环境下是不是也这么抓包，对，也是，下面是实践过程，

这里我再把K8S的手动安装过程再贴一遍，

宿主机用了ubuntu最新的版本19.04，docker的安装简单了很多，

sudo apt install docker.io，

让docker服务能够在宿主机重启后自动启动，

sudo systemctl enable docker，

为了让普通user能够执行docker命令，

sudo gpasswd -a ubuntu docker，newgrp docker，

安装K8S，

curl -s https://packages.cloud.google.com/apt/doc/apt-key.gpg | apt-key add -，

vim /etc/apt/sources.list.d/kubernetes.list，

deb http://apt.kubernetes.io/ kubernetes-xenial main，

apt-get update，

apt-get install -y kubelet kubeadm kubernetes-cni，

swapoff -a，

kubeadm init --pod-network-cidr=10.244.0.0/16 --apiserver-advertise-address=127.0.0.1，

mkdir -p $HOME/.kube，

sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config，

sudo chown $(id -u):$(id -g) $HOME/.kube/config，

kubectl taint nodes --all node-role.kubernetes.io/master-，

kubectl apply -f https://raw.githubusercontent.com/coreos/flannel/master/Documentation/k8s-manifests/kube-flannel-rbac.yml，

kubectl apply -f https://raw.githubusercontent.com/coreos/flannel/master/Documentation/kube-flannel.yml，

kubectl get pods --all-namespaces，

下面开始做抓包实验，

目前还没研究明白用K8S在全局上创建抓包容器，那就还在docker下搞，

过程跟之前一样，只是Dockerfile要改一下，因为抓包的接口不一样了，改成cni0，

然后就是只想抓容器实例之间的通信，不想抓API的通信，需要在抓包命令里面做过滤，

FROM debian
RUN apt-get update && apt-get install -y \
tcpdump
RUN mkdir /pcap
RUN cd /pcap
WORKDIR /pcap
CMD tcpdump -i cni0 -G 900 -w '%Y-%m-%d_%H:%M:%S.pcap' -W 96 not host 10.244.0.2 and not host 10.244.0.3

创建两个实验部署，

kubectl run --image rastasheep/ubuntu-sshd:14.04 ubuntu，

kubectl run --image httpd web，
kubectl get pods -o wide，

进到ubuntu部署的容器里访问web部署的容器，

kubectl exec -it ubuntu-6cf68d94b7-qjb4w bash，
