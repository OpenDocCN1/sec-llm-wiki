本周继续研究DevStack+DPDK，

经过研究，继续更正上期中的错误，

localrc脚本中，\[\[post-config|$NOVA\_CONF\]\]部分无用，可去掉，

OVS\_BRIDGE\_MAPPINGS无用，可去掉，换回PUBLIC\_INTERFACE，

绑定了物理网卡的OVS接口啥用没有的结论也是不对的，可以等环境安装完成后，在br-ex上绑dpdk类型的接口，这样网络就通了，

环境安装完成后，

sudo ovs-vsctl del-port br-ex ens192，

sudo ifconfig ens192 down，

sudo /usr/local/share/dpdk/usertools/dpdk-devbind.py --bind=igb\_uio ens192，

sudo ovs-vsctl add-port br-ex dpdk0 -- set Interface dpdk0 type=dpdk options:dpdk-devargs=0000:0b:00.0，

有一个比较诡异的事情，就是需要在整个stack过程中dpdk刚安装完成时去手动启动dpdk，不然等都安装完成再搞的话，创建虚机就不是dpdkvhostuser类型port，这个问题也是让我比较感慨，有时候科研真的需要运气的，这是我无意之中解决的。

sudo ovs-vsctl --no-wait set Open\_vSwitch . other\_config:dpdk-socket-mem="1024"，

sudo ovs-vsctl --no-wait set Open\_vSwitch . other\_config:dpdk-init=true，

sudo /usr/share/openvswitch/scripts/ovs-ctl start，

sudo ovs-vsctl get Open\_vSwitch . dpdk\_initialized，

grep "Huge" /proc/meminfo

另外，不给大页内存的flavor，虚机也能启动并得到dpdkvhostuser类型port，但无法dhcp到ip地址，网络不通，由此可认为dpdk的host只能起大页内存flavor的虚机了。
