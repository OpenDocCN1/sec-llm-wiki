更正上期的一个错误，经过本周的验证，DevStack主线版本安装DPDK环境是没问题的，只是要手动下载最新的OVS和DPDK版本给DevStack用，不要让DevStack自己自动找版本，

git clone https://github.com/openvswitch/ovs.git /opt/stack/ovs，

git clone http://dpdk.org/git/dpdk /opt/stack/DPDK-v17.11，

DPDK的开启还是得手动，这个还没找到原因，

OVS-Agent不工作是指环境重启后，确实没能有效解决，只好安装后不重启了，实在不行就unstack，再重启后重新stack，

本周的研究成果非凡，竟然把ovs接口绑物理网卡和OpenStack下直接用dpdkvhostuser类型都搞出过来了，

我的localrc脚本如下，

[[local|localrc]]
############################################################
# Customize the following HOST_IP based on your installation
############################################################
#PUBLIC_INTERFACE=ens33
SERVICE_PASSWORD=password
ADMIN_PASSWORD=password
SERVICE_TOKEN=password
DATABASE_PASSWORD=password
RABBIT_PASSWORD=password
GIT_BASE=${GIT_BASE:-git://git.openstack.org}
enable_plugin networking-ovs-dpdk ${GIT_BASE}/openstack/networking-ovs-dpdk
OVS_DPDK_MODE=controller_ovs_dpdk
OVS_DATAPATH_TYPE=netdev
OVS_NUM_HUGEPAGES=2048
OVS_BRIDGE_MAPPINGS="default:br-ens33"
[[post-config|$NOVA_CONF]]
[DEFAULT]
ovs_use_usvhost = True
firewall_driver=nova.virt.firewall.NoopFirewallDriver
scheduler_default_filters=RamFilter,ComputeFilter,AvailabilityZoneFilter,ComputeCapabilitiesFilter,ImagePropertiesFilter,PciPassthroughFilter,NUMATopologyFilter
[libvirt]
use_hugepages = True

安装完成后会发现绑物理网卡的OVS接口是报错的，那是因为DPDK没有自动开启，手动开启后，重建这个接口就没问题，

然后搞一个大页内存的flavor，

创建两个虚机试试，

查看OVS，接口类型都是dpdkvhostuser，

验证一下虚机的网络，是通的，

由于虚机网卡走了DPDK，就无法在宿主机的kernel层面监控了，

有没有发现个问题，在这里，那个绑定了物理网卡的OVS接口啥用没有，于是我手动把他们都干掉，又换回了br-ex通外网，虚机就都能被外部访问了。
