更正上期的一个错误，经过本周的验证，DevStack主线版本安装DPDK环境是没问题的，只是要手动下载最新的OVS和DPDK版本给DevStack用，不要让DevStack自己自动找版本，

git clone https://github.com/openvswitch/ovs.git /opt/stack/ovs，

git clone http://dpdk.org/git/dpdk /opt/stack/DPDK-v17.11，

DPDK的开启还是得手动，这个还没找到原因，

OVS-Agent不工作是指环境重启后，确实没能有效解决，只好安装后不重启了，实在不行就unstack，再重启后重新stack，

本周的研究成果非凡，竟然把ovs接口绑物理网卡和OpenStack下直接用dpdkvhostuser类型都搞出过来了，

我的localrc脚本如下，

\[\[local|localrc\]\]  
############################################################  
\# Customize the following HOST\_IP based on your installation  
############################################################  
#PUBLIC\_INTERFACE=ens33  
SERVICE\_PASSWORD=password  
ADMIN\_PASSWORD=password  
SERVICE\_TOKEN=password  
DATABASE\_PASSWORD=password  
RABBIT\_PASSWORD=password  
GIT\_BASE=${GIT\_BASE:-git://git.openstack.org}  
enable\_plugin networking-ovs-dpdk ${GIT\_BASE}/openstack/networking-ovs-dpdk  
OVS\_DPDK\_MODE=controller\_ovs\_dpdk  
OVS\_DATAPATH\_TYPE=netdev  
OVS\_NUM\_HUGEPAGES=2048  
OVS\_BRIDGE\_MAPPINGS="default:br-ens33"  
\[\[post-config|$NOVA\_CONF\]\]  
\[DEFAULT\]  
ovs\_use\_usvhost = True  
firewall\_driver=nova.virt.firewall.NoopFirewallDriver  
scheduler\_default\_filters=RamFilter,ComputeFilter,AvailabilityZoneFilter,ComputeCapabilitiesFilter,ImagePropertiesFilter,PciPassthroughFilter,NUMATopologyFilter  
\[libvirt\]  
use\_hugepages = True
