一直在尝试DevStack下的networking-ovs-dpdk插件自动化安装DPDK的OpenStack环境，一直都不成功，

本周偶然用当前最新版本尝试竟然安装成功了，

[[local|localrc]]
############################################################
# Customize the following HOST_IP based on your installation
############################################################
PUBLIC_INTERFACE=ens192
SERVICE_PASSWORD=password
ADMIN_PASSWORD=password
SERVICE_TOKEN=password
DATABASE_PASSWORD=password
RABBIT_PASSWORD=password
GIT_BASE=${GIT_BASE:-git://git.openstack.org}
enable_plugin networking-ovs-dpdk ${GIT_BASE}/openstack/networking-ovs-dpdk

但问题是，用sudo ovs-vsctl get Open_vSwitch . dpdk_initialized命令查看DPDK状态不支持，看来版本不对，

还是偶然，发现DevStack还有个StarlingX版本，尝试用这个版本安装，

git clone -b stx/stein https://github.com/starlingx-staging/devstack.git，

虽然状态是false，但支持查询状态了，版本对了，

下面尝试手动开启DPDK，

sudo ovs-vsctl --no-wait set Open_vSwitch . other_config:dpdk-init=true，

sudo /usr/share/openvswitch/scripts/ovs-ctl start，

再查询OVS的DPDK状态，true了，

问题是，OVS-Agent不工作了，

还得再继续研究。

自动安装的huge pages还真生效了，实在不行可以先不管OVS的DPDK问题，先验证一下huge pages的flavor是否可用，就像之前实践CPU Pinning一样。

看OVS DPDK安装的官方文档，还要求Host OS的grub里添加huge pages和iommu的参数，

sudo vim /etc/default/grub，

GRUB_CMDLINE_LINUX="default_hugepagesz=1G hugepagesz=1G hugepages=16 hugepagesz=2M hugepages=8192 iommu=pt intel_iommu=on"，

sudo update-grub，
sudo reboot，

重启后可以验证一下，

dmesg | grep -e DMAR -e IOMMU，

cat /proc/cmdline，
