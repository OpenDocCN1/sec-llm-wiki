# Meltdown/Spectre的POC实践

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzA3MjM5MDc2Nw==&mid=2650744410&idx=1&sn=5ef46f6e75bf29f9ae71db77d9ca9ae2&chksm=8714875ab0630e4ca3ef3c3ed732919d21f6f142b1545711214dafa50e85a29916a123870861&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzA3MjM5MDc2Nw==&mid=2650744410&idx=1&sn=5ef46f6e75bf29f9ae71db77d9ca9ae2&chksm=8714875ab0630e4ca3ef3c3ed732919d21f6f142b1545711214dafa50e85a29916a123870861&scene=27#wechat_redirect)

本周安全圈最火的事件就是CPU漏洞，

三个CVE，2017-5715，2017-5753，2017-5754，

原理上是现代流水线CPU通过指令推测执行和多级缓存来提升性能的漏洞导致，  

出现了两个攻击方法，Spectre（幽灵）和Meltdown（熔断），

Meltdown是允许没有授权的进程访问系统级的内存数据，

Spectre是允许其它用户进程访问另一用户进程的任何内存地址，

安全圈史无前例的为这两个攻击方法单独开了一个网站，可见问题有多严重，

https://spectreattack.com/，上面有各种详细的信息，感兴趣的自己去看，

严重归严重，从两个攻击方式的解释上看，都是系统内部的事儿，虚拟机反攻宿主机的可能并没有被提到，我个人认为对于全虚拟化的IAAS业务来说，应该还是没啥影响的，但是容器业务确实有很大影响，这应该是各大云平台都抓紧打补丁的原因。

技术的事儿，能动手还是尽量别BB，因为BB的也不一定对，

咱自己没有能力写POC代码，所以这两天我就不断的在github上找，目前找到了两个典型的，https://github.com/paboldin/meltdown-exploit，

https://github.com/crozone/SpectrePoC，

第一个勉强还看得懂，没有授权的进程访问到了系统级的内存数据，

第二个怎么也没看明白，在同一个用户程序内，怎么就证明其它用户进程访问另一用户进程的任何内存地址了？

主要对第一个进行了多个环境的实践，

i5+WorkStation+ubuntu，POC有效，有趣的是我这个WorkStation可是14.0版本，VMware的官方声明里竟然说不受影响，让我很蒙圈啊，

这个是E3直接装ubuntu的，POC有效，

![](../Images/1c5e7c2534c56551341796bce20f155b.png)

所以我的结论是，如果这个Meltdown的POC没问题，那就只跟CPU有关。

Spectre的POC虽然怀疑是否靠谱，也还是做了两个实践，

i5+WorkStation+ubuntu，POC有效，

![](../Images/256d803e5f05de818bda8ef032a8c216.png)

Xeon+WorkStaion+ubuntu，POC还是有效，尽管有几个字母没读全，

![](../Images/fdc56c6cb431e9828ddfe04840efa1a3.png)

如果这个Spectre的POC没问题，那就只能说Spectre的影响更大了，反正我是不信。

结束本期内容之前再多说一句，对于网络安全来说，能被远程利用的漏洞是问题最大的，就有人站出来说CPU的漏洞能够通过浏览器远程利用，说什么能够通过JS脚本获取到敏感信息，如果JS脚本能随便执行，都用不着利用CPU的漏洞吧。

水平有限，不知所言。
