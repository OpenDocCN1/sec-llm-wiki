首先说一下，本周Ocata版本按照官方指南安装还是没有成功，据说placement和cell的配置是必须的，官方安装指南里一直都不提啊，以后我可不浪费这时间了，啥时候官方安装指南里有了placement和cell的配置再说。

本周主要还在千方百计的折腾Networking-SFC，Mitaka手动、Newton手动、DevStack Mitaka自动、DevStack Newton自动、DevStack Ocata自动。还是那句话，因为热爱，所以坚持，最后通过DevStack Ocata自动找到了思路，一开始Newton手动是对的，只是当时把logical-source-port的报错当成了配置错误，而反倒是把配置改错了，导致不下流表，又重新Newton手动，给上logical-source-port参数，这次终于看到了期盼已久的流表，虽然还不完美。

把整个过程记录一下，

git clone -b stable/newton git://git.openstack.org/openstack/networking-sfc.git，

pip install -r requirements.txt，

python setup.py install，

pip install -e /home/ubuntu/networking-sfc，

vim /etc/neutron/neutron.conf，

service_plugins = networking_sfc.services.flowclassifier.plugin.FlowClassifierPlugin,networking_sfc.services.sfc.plugin.SfcPlugin，

[sfc]
drivers = ovs

[flowclassifier]
drivers = ovs

vim /etc/neutron/plugins/ml2/openvswitch_agent.ini，

[agent]
extensions = sfc

su -s /bin/sh -c "neutron-db-manage --config-file /etc/neutron/neutron.conf \
  --config-file /etc/neutron/plugins/ml2/ml2_conf.ini --subproject networking-sfc upgrade head" neutron，

service neutron-server restart，

service neutron-openvswitch-agent restart，

这就可以做实验了，

neutron port-create --name vfw-service-1 cirros，

neutron port-create --name vfw-service-2 cirros，

neutron flow-classifier-create \
  --description "ICMP traffic from 10.0.0.12 to 10.0.0.10" \
  --logical-source-port 8ab811b8-a46a-486e-bcda-9fed40388dca \
  --ethertype IPv4 \
  --source-ip-prefix 10.0.0.12/32 \
  --destination-ip-prefix 10.0.0.10/32 \
  --protocol icmp FC1，

neutron port-pair-create \
  --description "vfw" \
  --ingress vfw-service-1 \
  --egress vfw-service-2 PP1，

neutron port-pair-group-create \
  --port-pair PP1 PPG1，

neutron port-chain-create \
  --port-pair-group PPG1 \
  --flow-classifier FC1 \
  --chain-parameters symmetric=true PC1，

查看流表，

虽然指示了原路返回，但没有反向流表，正向流表倒是对的，重要的是，流量从vfw上过了以后就不通了，而且造成了cirros-1虚机的网络故障，怀疑是从egress口出来的流量又重新送给了ingress，造成了环路，但从流表上看，又不应该这样，下周找高人帮忙看看。
