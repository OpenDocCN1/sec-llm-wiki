# 思科Nexus 1000V的实践（二）

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzA3MjM5MDc2Nw==&mid=2650743980&idx=1&sn=639574e6cf7c096774d378e69b397cea&chksm=871485acb0630cba53b0b127ef9b5d24a344258e84c189154481c7fff90a0ab36c6f6c8e8b21&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzA3MjM5MDc2Nw==&mid=2650743980&idx=1&sn=639574e6cf7c096774d378e69b397cea&chksm=871485acb0630cba53b0b127ef9b5d24a344258e84c189154481c7fff90a0ab36c6f6c8e8b21&scene=27#wechat_redirect)

去年实践过思科的Nexus 1000V，当时比较懒，没有额外给它分配硬性要求的管理VLAN，switch和端口组能正常创建和使用，虚机也能正常通信，当时还嘲笑了一把思科提供的默认安装方案的繁琐。

本周因工作需要，在Nexus 1000V下实践流量镜像，发现之前自己实践成功的方法纯属碰巧，VSM上看不到VEM，当然也看不到接口，谈何流量镜像啊，

研究了好久也没手动改明白，只好回到思科提供的默认安装方案。

首先在想导入VSM的宿主机上创建一个新的标准交换机和vlan1的端口组，VSM的三个网卡都连到这个端口组里来，当然要配置外面的交换机使这个vlan1里的VSM能跟不在vlan里的vCenter进行通信，

![](../Images/6d9ea754f67de3f4307a4eab284e54a3.png)  
接下来就用思科提供的安装工具来安装了，先把VSM连接到vCenter，这个过程上次说过，就不详述了，这次主要说安装VEM和把VEM连接到VSM，

![](../Images/8f7692344a40f2644046846353ba79c9.png)

安装完VEM和连接到VSM的宿主机，你会发现之前在默认标准交换机vSwitch0上的管理网卡被移走了，

![](../Images/85aa7062120f6f8330b84bfe14cb14ea.png)

原来是被移到了Nexus 1000V的switch上，在这个过程中，自动创建了一个叫n1kv-eth-2的上行trunk链路，和一个叫n1kv-veth-vlan-1-l3的管理端口组，宿主机之前的管理地址就被放到了这个端口组里，

![](../Images/094913765acb6495a7fa3e517478872d.png)

再去看模块信息，就能看到VEM了，当然接口也都能看见了，

![](../Images/627c2af921155adf1421b334432eb859.png)  
这就可以实践流量镜像了，

monitor session 1

source vlan 10 both

destination interface Vethernet16

no shutdown
