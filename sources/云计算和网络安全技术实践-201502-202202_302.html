去年有一期《OpenStack的实践（四）》里面介绍了一种Service Chain的玩儿法，Service Node的接口是3层接口，路由模式，本期给你们看另一种玩儿法，Service Node的接口是2层接口，透明模式，更符合实际业务的需要。

环境还是这个环境，拓扑还是这个拓扑，这次是让访问web虚拟机的流量从monitor虚拟机绕一圈，流量镜像可以用来做IDS，而流量转向则可以直接做IPS，

给monitor虚拟机安装ovs，apt-get install openvswitch-switch，

创建br，ovs-vsctl add-br br-int，

把业务口绑在br上，ovs-vsctl add-port br-int eth1，

如何做到业务口将收到的流量再扔回去，

ovs-ofctl add-flow br-int priority=100,in_port=1,actions=in_port，

看一下计算节点的接口，16口是monitor虚拟机的业务口，17口是web虚拟机的接口，5口是web虚拟机所在网络网关的接口，


在计算节点上添加引流表项，

ovs-ofctl add-flow br-int priority=100,ip,dl_src=fa:16:3e:4d:b5:97,actions=strip_vlan,output:16

ovs-ofctl add-flow br-int priority=100,ip,dl_dst=fa:16:3e:4d:b5:97,actions=strip_vlan,output:16

ovs-ofctl add-flow br-int priority=300,in_port=16,dl_dst=fa:16:3e:4d:b5:97,actions=output:17

ovs-ofctl add-flow br-int priority=300,in_port=16,dl_dst=fa:16:3e:58:9d:8b,actions=output:5

在外面ping web虚拟机，然后在monitor虚拟机上抓包，能够看到双向收发都完整的经过了monitor虚拟机，

怎么样，简单吧，你看着简单，我可是做了大量的试验的，最开始我一直在研究如何让linux bridge上的接口将收到的流量再扔回去，尝试用brctl hairpin br interface on的方法，但是ubuntu、centos、rhel都试过了，均无效，只好放弃，转而使用ovs的ovs-ofctl add-flow br priority=100,in_port=1,actions=in_port方法，有研究明白linux bridge的brctl hairpin br interface on方法的看官可以给我留言，咱们交流一下，谢谢。
