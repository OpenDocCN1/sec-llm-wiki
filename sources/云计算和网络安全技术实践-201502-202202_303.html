书接上回，

本期实验了一种破掉二次桥接的方式，直接把流量镜像到虚拟机接口的方案，需要关闭掉neutron driver的security group，

编辑/etc/neutron/plugins/ml2/ml2_conf.ini，

enable_security_group = False，

firewall_driver = neutron.agent.firewall.NoopFirewallDriver，

编辑/etc/nova/nova.conf，

#security_group_api = neutron，

重新创建测试虚拟机，还是这个拓扑，


在计算节点上ovs-vsctl show看看都有哪些接口，


其中tap0a7c63d1-d3是web虚拟机的接口，tap006f794e-23是monitor虚拟机的port接口，看出问题了吧，上期内容中这步的接口名是qvo开头的，本期关掉了eutron driver的security group，接口名就变成tap开头的了，

brctl show一下你就更明白了，


虚拟机的接口都直接挂在ovs的br-int上了，不再二次桥接了，

还是同样的手段做流量镜像，

ovs-vsctl \
  -- --id=@m create mirror name=mymirror \
  -- add bridge br-int mirrors @m \
  -- --id=@tap0a7c63d1-d3 get port tap0a7c63d1-d3 \
  -- set mirror mymirror select_src_port=@tap0a7c63d1-d3 select_dst_port=@tap0a7c63d1-d3 \
  -- --id=@tap006f794e-23 get port tap006f794e-23 \
  -- set mirror mymirror output-port=@tap006f794e-23

多说一句，怎么删除之前创建的mirror，

ovs-vsctl -- --id=@m get mirror mymirror -- remove bridge br-int mirrors @m，

ovs-vsctl clear bridge br-int mirrors，

如果不删除，那就不要再新建了，直接做镜像流量的动作即可，

ovs-vsctl \
  -- --id=@tap0a7c63d1-d3 get port tap0a7c63d1-d3 \
  -- set mirror mymirror select_src_port=@tap0a7c63d1-d3 select_dst_port=@tap0a7c63d1-d3 \
  -- --id=@tap006f794e-23 get port tap006f794e-23 \
  -- set mirror mymirror output-port=@tap006f794e-23

外面ping web虚拟机，再ssh到monitor虚拟机上抓包，


怎么抓到的包又都是没有vlan tag的，把监听接口配置成trunk模式，

ovs-vsctl set port tap006f794e-23 vlan-mode=trunk，再重新抓包，


vlan tag又出来了，原理不多说，上期解释过了，

其实你在业务中真正需要做流量镜像时还真没必要让流量带vlan tag进来，因为可能处理不了，我只是证明一下镜像过来的流量到底带不带vlan tag而已。
