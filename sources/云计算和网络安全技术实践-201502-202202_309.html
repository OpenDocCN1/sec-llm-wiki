上个月我做过一期趋势Deep Security的实践，本期的内容属同类，Palo Alto VM-Series NSX Edition的实践，有人反馈，说你能否别像教程一样这么客观，加一些主观的评论，行文不至于这么枯燥，接受建议，从本期开始改善。

‍Palo Alto VM-Series NSX Edition的原理如下，在每个ESXi主机中都部署一个Palo Alto的vNGFW，靠NSX的分布式防火墙给做引流，这里就可以讨论一下，既然NSX已经有分布式防火墙了，为啥还要引流给第三方的安全虚机，原因是NSX的分布式防火墙仅能做网络层标准端口服务的访问控制，没有应用层的入侵防御能力，事实上仅通过标准端口识别服务和应用，就已经落后了，太多的应用使用标准协议的知名端口（如HTTP的80端口）进行传输，或者直接承载在标准协议中的，你们懂的。

部署Palo Alto VM-Series NSX Edition也是一个很费劲的过程，先要部署一个Palo Alto的网管设备虚机Panorama，然后把Panorama注册到NSX Manager，再在vCenter中操作NSX业务部分将Palo Alto的vNGFW部署到每个ESXi主机上，业务使用过程中，习惯使用vSphere软件客户端管理vCenter和ESXi主机的用户，这时发现，必须使用vSphere Web客户端先在vCenter中操作NSX业务部分将要做安全防护的流量引给Palo Alto的vNGFW，然后还要单独登录Panorama配置防护策略下发给每个vNGFW去执行，也许部分用户需要很长时间去适应，

我搭出的实践环境是这样，

参照Palo Alto的官方安装指南，选好配套版本，ESXi和vCenter都是5.5，NSX Manger是6.0，Panorama是6.0，PA-VM没有找到6.0的NSX版本，用6.1代替，当然我也尝试将找到的PA-VM非NSX的6.0版本hack成NSX版本，也是成功的，不得不说，版本配套问题是个很麻烦的事情，ESXi版本不对会导致虚机模板不适用，vCenter版本不对会导致不支持NSX Manger，NSX Manger版本不对会导致API接口不适配Panorama，Panorama版本不对会导致不能管理PA-VM，反正最后的结论就是，如果你不小心搞定了一套环境，千万不要升级任何一个组件，

ESXi和vCenter的安装我就不说了，从NSX Manager开始，把NSX Manager的模板从vCenter导入，启动后配置注册到vCenter，然后再通过vSphere Web客户端登录vCenter就能看到NSX业务部分了，


把NSX分布式防火墙装上，要求ESXi主机必须在集群里，

把Panorama虚机从vCenter导入，启动后需要在控制台下通过命令行手动配置地址信息，才能通过WebUI访问Panorama虚机，

configure

set deviceconfig system ip-address 192.168.1.64 netmask 255.255.255.0 default-gateway 192.168.1.1 dns-setting servers primary 114.114.114.114

commit

接下来把Panorama注册到NSX Manager，你会发现PA-VM模板要求必须放到一个支持文件下载的Web服务器上，为了它我不得不找了一个HFS服务器软件，因为我手里没有授权码，直接就把官方安装指南里的给填上了，还能注册成功，

然后到vCenter的NSX业务部分去部署PA-VM，首先为PA-VM配置管理地址池，


完成PA-VM的部署，


安装就都完事了，下面就是业务的使用了，先在vCenter的NSX业务部分中做引流配置，有几个步骤，

首先要配置需要被引流的端口组，


然后配置流量重定向规则，NSX的网络安全业务逻辑还是很合理的，流量重定向规则上面是防火墙规则，如果防火墙规则配置成阻断，也就没必要再引流了，防火墙规则配置成允许，然后再引流给第三方安全虚机去做入侵防御，这样才能把合作双方的价值都发挥出来，


最后把安全策略绑定给安全组，安全组可以理解为虚机组，

也许是之前在Panorama里填的授权码不对，PA-VM没有正常注册到Panorama上来，在Panorama上配置防护策略下发给每个vNGFW去执行就没法实践了，


尝试hack，登录每一个vNGFW去单独配置防护策略，发现每个vNGFW中已经内置了一些默认的配置，如两个通过虚拟线连在一起的接口，应该是用于转发被重定向过来的流量的，奇怪的是管理接口并没有显示，


默认策略是所有流量阻断，这确实是防火墙产品的白名单风格，然而手动改成允许，流量还是不通，这种hypervisor层引流的方案就是这样，耦合度太大，出了问题很难定位，


手动在vCenter中关闭vNGFW虚机，流量还是不通，说明这个方案里并没有做bypass机制，实践过程中还发现了NSX的一些问题，如NSX分布式防火墙安装后无法正常卸载，NSX Manager注册到vCenter后不知道怎么卸载，EXSi6.0+vCenter6.0+NSX Manager6.1环境中安装完分布式防火墙后（不配置任何策略）导致流量不通。

因此，总结来说，NSX本身还处在不成熟的阶段，NSX引入合作的第三方安全方案也更加的不可靠，用户需要谨慎。
