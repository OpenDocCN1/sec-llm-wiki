本期续一次OpenStack的实践。

OpenStack的Liberty版本发布有一个月了，不知道其它OpenStacker怎么看，我是看到了中意的东西，那就是网络方案上明确了私有云和公有云，即Provider和Self Service模式，且首次不再推荐使用OVS，跟我的SDN无用论不谋而合，闲话少叙，看干货。

Provider模式架构如下，

![](../Images/8e234b23ce6224b7af2fc474e92e1bca.png)

怎么样，如果你玩过vCenter，是否感受到了熟悉的组网思路，还不明白的话，我给你看一个更清晰的，

![](../Images/b3e903797a10b00da392d980b2f7dd94.png)

OVS、L3、DHCP、Metadata都不再需要了，私有云里的虚机通过VLAN隔离开，网关都在外面的交换机上，这就是一个简洁高效的私有云，下面跟我实践一下吧，

我开始是准备在Liberty上实践的，但是安装过程中发现docs.openstack.org不知道抽了什么风，前一秒还能看着安装指导，后一秒就打不开页面了，好不容易断断续续完成了一个all in one节点的安装，Dashboard打开缓慢不说，Linux Bridge Agent起不来，创建虚机失败。新版本就这样，习惯了，记得Juno版本出来的时候，我连续几周试了4、5次装出来的环境都用不了。为了不浪费时间，我找出来一个以前装好的Icehouse版本的环境，改造一下。

啰嗦这么多，我想说的是啥呢，这个明确了私有云和公有云的Provider和Self Service模式是跟版本无关的，只是说明了OpenStack社区对业务模式清晰化的一种态度，不再推荐使用OVS也是一种态度，所以OpenStacker是没必要为了哪种模式去换你已经打磨的稳定可靠的某个版本的，我最喜欢的是Icehouse，Dashboard秒开。

改造的第一步就是把没用的干掉，

apt-get remove neutron-plugin-openvswitch-agent，

apt-get remove openvswitch-switch，

apt-get remove neutron-l3-agent，

apt-get remove neutron-dhcp-agent，

apt-get remove neutron-metadata-agent，

然后把Linux Bridge Agent装上，

apt-get install neutron-plugin-linuxbridge-agent，

再把ml2的相关配置都改成linuxbridge的，

vim /etc/neutron/plugins/ml2/ml2\_conf.ini，

\[ml2\]  
type\_drivers = vlan  
tenant\_network\_types = vlan  
mechanism\_drivers = linuxbridge

\[ml2\_type\_vlan\]  
network\_vlan\_ranges = physnet1:100:200

\[securitygroup\]  
firewall\_driver = neutron.agent.linux.iptables\_firewall.IptablesFirewallDriver  
enable\_security\_group = True

vim /etc/neutron/plugins/linuxbridge/linuxbridge\_conf.ini，

\[linux\_bridge\]  
physical\_interface\_mappings = physnet1:eth1

创建两个网络，启几个虚机看看，

![](../Images/29e2bf65380dc688cfe263b010b3e3fd.png)

虽然干掉了DHCP，但虚机的地址还是被指定的，这样也好，管理员不用费心去记哪个虚机用哪个地址，当然，虚机起来以后静态配置的地址必须跟指定的相同，否则由于有安全控制，报文是出不去的，管理员想给某台虚机使用某个特定的地址怎么办，只能用命令行，例如上图中的第四台虚机，我在启动时指定了它使用的地址，

nova boot --image cirros-0.3.3-x86\_64 --availability-zone nova:controller --flavor m1.tiny --nic net-id=076e7ca8-67f6-485c-8cb1-8188adf896c7,v4-fixed-ip=10.0.1.100 vm4，
