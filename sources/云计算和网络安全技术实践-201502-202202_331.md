# OpenDaylight的实践

OpenDaylight是目前最流行的开源SDN Controller，正像我上期中说的，如果不用北向接口（一般是RESTful API）去自动化驱动SDN Controller给vSwitch下流表，使用SDN Controller还不如直接在vSwitch下配置OpenFlow规则。

事实上，OpenStack本身也是一个SDN APP，可以通过配置让其将网络转发交给OpenDaylight来控制，然并卵，需要给NFV设备引流时，还是需要手动在OpenDaylight的UI上去操作。而且由于OpenDaylight和OpenStack各种版本之间配合的不稳定性，常常导致还没给NFV设备引流呢，基本的网络转发就跑不起来了。因此建议，即使是工程中，也不要用OpenStack直接做SDN APP，而是引入独立的SDN APP，让OpenDaylight或商用SDN Controller仅控制OpenStack下的OVS即可。

本人目前还没有本事写个独立的SDN APP出来，因此本期内容无法实践SDN的北向接口，仅实践一下OpenDaylight跟OpenStack下OVS的配合吧。

https://www.opendaylight.org/downloads提供了OpenDaylight的迭代版本（氢、氦、锂），但是经过实践，实在是不敢恭维，还是其最初提供的一个数据中心虚拟化专用版本要好用一些，下载地址http://nexus.opendaylight.org/content/repositories/opendaylight.release/org/opendaylight/integration/distributions-virtualization/0.1.1/distributions-virtualization-0.1.1-osgipackage.zip，安装就选一个干净的Ubuntu Server，先把JRE环境安装一下，apt-get install openjdk-7-jre，然后把zip包解压开，unzip distributions-virtualization-0.1.1-osgipackage.zip，如果Ubuntu Server之前没安装过unzip，那就先执行apt-get install unzip，解压完成后进入文件夹cd opendaylight，启动OpenDaylight，./run.sh -virt ovsdb，这就完了，就这么简单。

到OpenStack的各节点上配置OVS可被OpenDaylight管理，ovs-vsctl set-manager tcp:192.168.1.23:6640，我实践的环境是all in one的，效果如下，
