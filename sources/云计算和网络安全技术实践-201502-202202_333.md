继续OpenStack的实践，本周的内容是NFV。

我们用上期中使用过的ubuntu-14.04-server来做一个NAT网关。

理想的方案是直接替换OpenStack中的逻辑VR，就像下面这样，

![](../Images/fa38e5eae8d9ca86e6a733c8824c00e8.png)  

但是经过实践发现，在OpenStack中，虚机直接连外部网络不能正常使用Metadata服务，也就无法注入公钥或密码，于是采用了如下组网方案，

![](../Images/e76b024fb0f18f9334e98afa092b7396.png)  

单独搞一个内部的公网子网，让VR跨接在外部网络和这个内部公网子网之间，而我们的Ubuntu模拟的NAT网关跨接在这个内部公网子网和其它业务私网子网之间，这样就能达到我想要的效果。美中不足的是需要给Ubuntu的外网接口绑定一个浮动IP，外网访问业务私网子网内虚机的过程需要两次DNAT进来。

![](../Images/8ccb78f720d4e928aea8fee69c11857a.png)  

事实上，越简单的方案才是越美的方案，AWS的VPC、阿里云的VPC，以及用OpenStack包装的公有云（如联通沃云）都是采用的这样的NFV方案。当然也有用SDN引流的，如移动大云、京东企业云，他们在用复杂的方案解决同样的问题，并没有产生更多的价值，但是高大上的SDN总还是会让技术控们引以为豪，咱们以后会讲这方面的实践，但本期我们还是只讨论简单实用的NFV。啰嗦了这么多，你应该能读懂我对SDN和NFV的态度。

按照上面的组网，我们启动Ubuntu虚机，这时你会发现在OpenStack的Dashboard上是没法指定内网接口的地址是10.0.0.1的，就得用命令行创建虚机时指定了，但是命令行启动虚机怎么注入密码呢，先创建一个password-injection文件，把密码注入的脚本写进去，然后在命令行启动虚机时通过--user-data调用，

![](../Images/03d7010993ec32a9129ed5c75be97400.png)  

最终启动Ubuntu虚机的命令行就是这样，

nova boot --image ubuntu-14.04-server --availability-zone nova:controller --flavor m1.small --nic net-id=6dc15492-7989-41e2-99b4-54538cf9b965 --nic net-id=5a508946-644e-43a5-bf85-3bc90131913d,v4-fixed-ip=10.0.0.1 --user-data /home/ubuntu/password-injection Ubuntu

启动后你会发现ubuntu-14.04-server这个镜像做的并不完善，只能自动给第一个接口eth0获取动态地址，需要手动通过dhclient eth1命令给第二个接口eth1获取动态地址，然后为了让这个Ubuntu虚机能够做NAT网关，你需要编辑/etc/sysctl.conf，手动打开它的路由能力，

net.ipv4.ip\_forward = 1，

再添加两条NAT规则，

iptables -t nat -A POSTROUTING -s 10.0.0.0/24 -o eth0 -j MASQUERADE，

iptables -t nat -A PREROUTING -d 172.16.0.3 -p tcp --dport 22 -j DNAT --to 10.0.0.3

既然22端口被DNAT用了，就得把Ubuntu的SSH端口改掉，

编辑/etc/ssh/sshd\_config，Port 2222，重启服务service ssh restart，

如果此时你重启一下Ubuntu，你会发现eth1的地址和NAT规则都没了，为了不再次手动配置，你需要编辑/etc/rc.local，把dhclient eth1和那两条NAT规则都写进去，这样就不怕重启了。

经过了以上实践，你会发现从外网访问业务私网子网内的虚机还是不通，那是因为OpenStack默认不允许普通虚机的接口转发源地址不是本接口地址的报文，你需要如下命令把这个接口转发任意源地址报文的能力打开，

neutron port-update 4618359f-31f9-4eb3-83fd-613d21a66440 --allowed-address-pairs type=dict list=true ip\_address=0.0.0.0/0

你再从外网访问业务私网子网内的虚机就通了，注意，你访问的是那个绑定到Ubuntu上的浮动IP，

![](../Images/b2ce262628ff7244b47e1e0383dbbed5.png)
