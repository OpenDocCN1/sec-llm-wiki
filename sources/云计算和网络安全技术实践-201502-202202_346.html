继续Suricata的实践。

1、安装Snorby（费老劲了）

我这里用的是Ubuntu14.04，首先更新一下安装源apt-get update，

安装Snoby所需的基础软件apt-get install apache2 git imagemagick wkhtmltopdf ruby1.9.3 libyaml-dev libxml2-dev libxslt1-dev zlib1g-dev build-essential openssl libssl-dev libmysqlclient-dev libreadline6-dev，

下载Snorby的代码git clone http://github.com/Snorby/snorby.git，

安装Snorby当前版本所需的rails版本gem install rails -v '3.1.12'，

进入Snorby文件夹cd snorby，打开Gemfile文件vim Gemfile，把文件头的https://rubygems.org改成http://rubygems.org，为啥要这样做，失败了多次试出来的，别怪我有阴谋论，怀疑国内访问https://rubygems.org被中间人劫持，信息被篡改导致安装失败，

以开发模式进行bundle安装RAILS_ENV=production，bundle install --deployment，为啥是开发模式，也是失败了多次试出来的，普通模式收到入侵检测日志不显示事件，开发模式能显示事件，但dashboard不出统计图，开源的东西就是这么难用，没办法，开发模式还算能用，

安装mysql数据库apt-get install mysql-server，编辑配置文件vim /etc/mysql/my.cnf，更改bind-address = 192.168.1.13（ubuntu的地址），重启数据库服务service mysql restart，完成初始化mysql_install_db，mysql_secure_installation，创建snorby数据库，允许外部访问，mysql -u root –p，CREATE DATABASE snorby；GRANT ALL PRIVILEGES ON snorby.* TO 'snorby'@'localhost' IDENTIFIED BY 'snorby'；GRANT ALL PRIVILEGES ON snorby.* TO 'snorby'@'%' IDENTIFIED BY 'snorby'；quit，

配置Snorby，进入config文件夹cd config，创建配置文件cp database.yml.example database.yml，cp snorby_config.yml.example snorby_config.yml，打开database.yml文件vim database.yml，修改配置username: snorby password: "snorby"，

启动Snorby，bundle exec rake snorby:setup，bundle exec rails server -e production，

此时可以用浏览器访问http://192.168.1.13:3000，默认用户名：snorby@snorby.org，默认密码：snorby。

2、配置Suricata

配置知识库，因为第二个和第三个要注册，我只选了第一个和第四个，


把知识库升级到最新，


添加入侵检测接口，


选择检测规则，我直接点了Select All，


选择防护模板，因为我要测的是Web扫描，因此选了一个相应的模板，


配置Barnyard2，让其将入侵检测日志同步到Snorby的数据库中，


启动Suricata和Barnyard2，


3、效果验证

在外面用NetSparker对http://192.168.1.25进行扫描，前面配置过端口转发规则，DNAT到http://192.168.226.11（Metasploitable2）上，一会儿就能在Snorby上看到效果，


具体看一条日志，能分析出攻击源和所使用的扫描器，
