# 安全事件缘何无响应？

Target、索尼、12306……,安全事件此起彼伏，大有愈演愈烈之势。但一份调查显示，如今仍有超过三分之一(38%)的公司未制定事件响应计划来应对安全事件；那些制订了安全响应计划的企业，在安全事件出现时计划往往成为摆设。有些企业在安全事件发生数周、甚至数月后才知道被攻击。显然大多时候企业还没有做好安全事件响应的准备。

**企业尚未做好应对安全事件的准备**

不久前公布的一份经济学人智库的调查显示，尽管在过去两年里有 77% 的企业曾遇到过网络安全事件，但如今仍有超过三分之一(38%)的公司未制定事件响应计划来予以应对。目前全球只有 17% 的企业为应对网络安全事件做好了充分准备。

这份题为《网络事件响应：企业领袖是否已然做好准备？》的报告基于对360 位资深全球企业领袖的调查。

Verizon公司2012年发布的数据泄漏调查报告则显示，很多企业被攻击后，在数周（29%）、甚至数月（54%）后才知道网络遭遇攻击，发生了数据泄漏。很多企业显然没有做好漏洞检测和应对安全事件准备。

具备事件响应计划、准备就绪程度较高的企业通常依靠 IT 部门来领导这一进程，但大多数企业同时也会借助外部资源的力量——主要包括 IT 取证专家、专业法律顾问和执法专家等。

经济学人智库资深编辑 James Chambers 表示，“如今企业网络安全事件准备工作的正规化趋势令人备受鼓舞。但随着威胁的来源和影响力变得更加难以预测，企业管理人员应确保让网络突发事件响应成为组织的一种本能反应，而不仅仅是一份平时束之高阁、遇事临时取用的计划”。

安全专家指出，从零售行业最近发生的几起高度引人注目的针对性网络攻击事件中可以看出，企业快速识别和归类网络安全事件并执行响应计划的能力，不仅对于保护企业资产和客户数据非常重要，而且对于保护企业品牌、美誉度和财务底线也非常重要。“正如这些调研结果所表明的那样，当涉及到网络攻击问题时，我们应该为‘何时发生’积极做准备，而不是为‘如果发生’消极做准备。

**安全事件响应不力是通病**

许多企业遭到网络攻击后请来帮忙的调查人员表示，在许多情况下，企业根本缺乏有效的事件响应计划。但是为什么那么多的企业未能为不可避免的问题作好防备呢？

最根本的问题是，许多企业的人员仍然不认为网络攻击是不可避免的，因为他们要么认为自己的防御体系足够好，要么认为自己不会成为攻击对象。

GuidanceSoftware公司的欧洲销售主管Ken Yearwood表示，欧洲企业认为，由于欧洲大陆报告的数据泄密事件数量比较少，这个问题不如在美国来得严重。法律已要求在美国的企业报告个人数据泄密事件，因而造成了一种假象：这种攻击在欧洲比较少见。

Yearwood说：“欧洲企业应从美国的泄密事件中汲取教训，有理由认为同一种攻击会出现在世界上的其他地方，可能很快会袭击它们。”

下一个问题是，企业并不明白有效的事件响应计划的真正价值：安全事件响应计划在识别攻击源头，迅速让攻击停止，从而减小攻击范围方面颇有成效。

据Jirasek咨询服务公司的总经理Vladimir Jirasek表示，事件响应计划与迅速恢复之间的关系很明确。他说：“企业遭到针对性攻击后恢复有多迅速，取决于事件响应计划准备有多充分。”

GuidanceSoftware公司负责专业服务的高级主管NickPollard表示，缺乏事件响应计划意味着，企业可能需要长达10周的时间才会明白发生了什么事情。他说：“如果企业被迫请来第三方事件响应人员，那么这段期间所需的费用可能高达9万英镑左右。”

Pollard表示，除了缺乏事件响应计划外，常常让问题复杂化的是这个事实：就算企业确实搞清楚什么地方出了问题，IT管理人员也可能不会告诉他人，以保全自己的声誉。

这就通常意味着，汲取的经验教训没有在公司上下传开来，也没有作为事件响应计划的一部分而记入日志，这意味着企业在未来仍然很容易遭到类似攻击。

安全顾问声称，制定事件响应计划这一做法会给企业带来价值。

信息安全论坛的高级研究分析师DaveClemente表示：“单单初步规划就可以揭露企业在沟通、政策、技术能力、角色和责任方面存在的可能需要立即关注的缺口。”

**安全事件响应计划成摆设**

但是即便在企业已制定了安全事件响应计划的情况下，调查人员也发现，这些计划并不总是有效，原因是计划从来没有得到过测试。

ArborNetworks公司的解决方案架构师主管DarrenAnstee认为，这是由于许多人对任何影响访问数据容易程度的安全增强计划漠不关心。他说：“我们在已实施事件响应计划的多家企业当中发现，实际测试这些计划以确保计划发挥最佳实际效果的企业所占比例极少。”

据Clemente声称，模拟活动可以让所有主要的利益相关者参与进来，共同确定清晰的预期目标、泄密后采取的措施以及各自所负的责任，从而防止有关人员一头雾水。

NTT ComSecurity公司主管安全战略的高级副总裁GarrySidaway用数字表明了这个问题的严重性。他告诉媒体：“在我们接手的80%的案例中，企业要么没有事件响应计划，要么没有测试计划以确保计划切实可行。”

Sidaway举了一个案例：由于糟糕的事件响应计划，一家企业用了整整三个月的时间才使攻击停止。他说：“每个人都以为别人会搞定，这表明沟通是任何事件响应计划的一个重要组成部分。”

据Sidaway声称，沟通包括内部沟通和外部沟通，以便分析事件根源、如何减小威胁。

他说：“内部沟通常常被遗漏，但正如这个案例表明，内部沟通与外部沟通来得完全一样重要。内部沟通还应该包括一些准则，明确一旦安全事件公诸于众，要是亲朋好友问起来，员工应怎么回答才合适。”

然而，Sidaway认为，除了没有制定或没有测试事件响应计划外，完全一样司空见惯的是，没有确保基本的安全控制措施落实到位，没有测试这些措施取得预期的效果。

他说：“我们仍看到有些企业投入时间和金钱来处理备受关注的攻击和安全漏洞，专注于下一个安全层，却没有确保现有的控制措施真正有效。”

Sidaway表示，这种疏忽造成的后果是，企业在由来已久的、有据可查的攻击工具和手法面前依然不堪一击。他说：“企业还需要专注于简化和整合安全系统，以便更好地管理和测试。复杂性是安全头号大敌。”

据美国波耐蒙研究所（PonemonInstitute）调查IT安全专业人员的结果显示，大部分受访者认为自己完全被安全事件和事件数据拖住了。这意味着他们觉得没有时间来确定哪些事件应该需要深入调查或开展任何调查工作。

据61%的受访者表示，端点安全产品发出的警报实在太多了；85%的受访者表示，所在企业无力优先处理紧迫的安全事件。
