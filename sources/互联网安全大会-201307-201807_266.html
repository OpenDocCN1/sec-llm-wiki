OpenSSL 发补丁修补八项漏洞

1月8日， OpenSSL项目发布了OpenSSL1.0.1k、OpenSSL 1.0.0p和OpenSSL 0.9.8zd三项升级，修补了此前三个版本存在的八项漏洞，其中两项会导致拒绝服务攻击（DoS），在漏洞危害程度上被视为中级。

安全专家表示，漏洞CVE-2014-3571是DTLS 协议在dtls1_buffer_record函数条件下的段错误，这就可以解释为什么“精心制作的DTLS信息会由于空指针引用导致OpenSSL出现段错误”，从而导致拒绝服务攻击。OpenSSL1.0.1、OpenSSL 1.0.0和OpenSSL0.9.8三个版本受到此漏洞影响。

漏洞CVE-2015-0206是DTLS 协议在dtls1_buffer_record函数条件下的内存泄漏，会通过内存耗尽的方式导致拒绝服务攻击。这意味着“dtls1_buffer_record函数在一定条件下会出现内存泄漏”，尤其是如果攻击者用相同的序列数字重复发送DTLS纪录时。OpenSSL1.0.1、OpenSSL 1.0.0两个版本受到影响。

其余六个漏洞----–CVE-2014-3569, CVE-2014-3572, CVE-2015-0204, CVE-2015-0205, CVE-2014-8275, andCVE-2014-3570 –---属于低级安全漏洞，会导致各种问题，其中有的涉及证书相关问题。

安全人士指出，尽管上述漏洞都没有达到心脏出血漏洞的严重程度，但系统管理员还是应该做未来数日内更新运行OpenSSL服务器环境。

导致拒绝服务攻击的漏洞是比较严重的。为了保护服务的稳定性，应该对OpenSSL进行升级，用不受到这些漏洞影响的SLL库，比如LibreSSL。

据悉，对OpenSSL 1.0.0 版和 0.9.8版的技术支持将在2015年12月底终止。对OpenSSL 1.0.1版的支持将持续到2016年12月31日，OpenSSL 1.0.2版届时将会得到技术支持。目前还没有对OpenSSL 1.0.3版的发布计划。

用户可以参考OpenSSL安全建议以获取其他信息，并进行必要的升级。

八个漏洞详解：

1. dtls1_get_record 段错误 (CVE-2014-3571)

安全级别：中

影响版本：OpenSSL 1.0.1, 1.0.0 和 0.9.8

漏洞描述：攻击者可以精心构造一个DTLS消息，引发OPENSSL的一个空指针引用，导致拒绝服务攻击。

2.dtls1_buffer_record内存泄漏 (CVE-2015-0206)

安全级别：中

影响版本：OpenSSL 1.0.1 和 1.0.0.

漏洞描述：在特定的条件下，攻击者通过重复发送DTLS，将在dtls1_buffer_record()函数引发一个内存泄漏漏洞。

3. no-ssl3 配置选项引发空指针引用 (CVE-2014-3569)

安全级别：低

影响版本：OpenSSL 1.0.1, 1.0.0 和 0.9.8.

漏洞描述：当OpenSSL的no-ssl3选项打开，接收一个SSL V3 ClientHello包将引发一个空指针引用。

4. ECDHE 降级到 ECDH [客户端] (CVE-2014-3572)

安全级别：低

影响版本：OpenSSL 1.0.1, 1.0.0 和 0.9.8.

漏洞描述：当使用ECDH加密集时，如果服务端在KEY交互时忽略请求，OpenSSL客户将接受一个握手，引发一个降级攻击

5. RSA 降级到 EXPORT_RSA [Client] (CVE-2015-0204)

安全级别：低

影响版本：OpenSSL 1.0.1, 1.0.0 和 0.9.8.

漏洞描述：在RSA key 交互过程中，OpenSSL客户端将接受使用一个RSA临时key,服务端会引发一个降级攻击。

6. DH 客户端认证接受一个无效的确认 [服务端]

安全级别：低

影响版本：OPENSSL 1.0.1和 1.0.0.

漏洞描述：当客户端认证时，没有使用证书验证消息，OpenSSL服务端将接受一个DH认证，这将允许客户端不使用私钥来认证

7. 证书指纹能被修改 (CVE-2014-8275)

安全级别：低

影响版本：OpenSSL 1.0.1, 1.0.0 和 0.9.8.

8. Bignum 平方将产生不正确的结果 (CVE-2014-3570)

安全级别：低

影响版本：OpenSSL 1.0.1, 1.0.0 和 0.9.8
