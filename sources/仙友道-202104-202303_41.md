SQL注入是指web应用程序对用户输入数据的合法性没有判断或过滤不严，攻击者可以在web应用程序中事先定义好的查询语句的结尾添加额外的SQL语句，在管理员不知情的情况下实现非法操作，以此来实现欺骗数据库服务器执行非授权的任意查询，从而进一步得到相应的数据信息。  

  

以上为百度百科的解释，可能不是很形象，这里举一个例子方便大家理解。  

  

程序员开发登陆界面时考虑的场景是用户在表单中输入用户名和密码进行登陆。

![](../Images/eac1102a29829836061de1647dceba2e.png)

  

当用户输入的参数传到服务器端后数据库会执行如下语句在数据库中进行查询：

*   
*   
*   

```
SELECT COUNT(*)FROM UsersWHERE username='admin'and password='p@$$w0rd'
```

没想到某些了解开发的用户动了坏心思，在用户名中输入了 admin' or 1=1 --。  
  

![](../Images/159c6052c62610027b66a7999883006d.png)

  

这就导致传递到后端的数据被错误的当做数据库语句的一部分去执行。原本数据库语句的意思是在数据库中查询输入的用户名和密码是否存在，从而判断用户可不可以登陆。而传递参数改为“admin ' or 1=1 --”后，“or 1=1”使语句中的布尔值一直为真，无论username和password的值为多少，都会登陆成功。这也就是一次SQL注入攻击。

*   
*   
*   

```
SELECT COUNT(*)FROM UsersWHERE username='admin' or 1=1 -- 'and password='1'
```
