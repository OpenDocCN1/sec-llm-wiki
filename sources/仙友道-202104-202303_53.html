Em..Nice还是看看代码

这里的报错内容是未定义的变量CONFIG，定位一下action=uploadimage代码位置，整个action_upload.php文件代码不多，只有66行，下面这些就是action=uploadimage的内容了

// Action_upload.phpswitch (htmlspecialchars($_GET['action'])) {    case 'uploadimage':        $config = array(            "pathFormat" => $CONFIG['imagePathFormat'],            "maxSize" => $CONFIG['imageMaxSize'],            "allowFiles" => $CONFIG['imageAllowFiles']        );        $fieldName = $CONFIG['imageFieldName'];        break;     ……

Ok,根据报错内容也就是这里的$CONFIG[...]找不到，这个文件里找不到$CONFIG，那么在文件开头include "Uploader.class.php";包含了uploader.class.php文件内，看看这个文件，Uploader.class.php文件什么都没做，就只定义了一个uploader类

在action_upload.php中实例化一个uploader对象，而$config是这个实例化对象的参数，到这里貌似有断层了，链条断在了这个$CONFIG这个变量是从哪里来的，这里重新去看看controller.php文件，controller.php文件更简单，开头

$CONFIG = json_decode(preg_replace("/\/\*[\s\S]+?\*\//", "", file_get_contents("config.json")), true);

这里从config.json文件里读取json内容并赋值给$CONFIG，

后面依旧是action参数获取upload...,然后包含对应的文件

switch ($action) {    case 'config':        ...    case 'uploadfile':        $result = include("action_upload.php");        break;    case 'listimage':       ...  ...

那么，到这里基本此编辑器的正常工作流程已经很清楚了

1、首先上传动作会访问controller.php文件，使用action参数控制上传文件类型

2、Controller文件获取到action的值后包含对应的文件，

3、对应文件首先会获取传递过来的$CONFIG变量，也就是config.json文件中对应的键值对,然后赋值给$config，

4、最后实例化一个uploader对象进行上传动作。


em...$CONFIG他来了，不过这里能获取到$CONFIG的前提是入口文件是controller.php文件，而config.json文件里已经把可以上传的文件后缀等等写死了，那么漏洞出在哪里了呢。

 

回想起最开始报错的内容，找不到CONFIG的内容，如果我从请求参数中给你提供一个呢，也就是$CONFIG['imageAllowFiles']=.php等等，到这里证明了poc是没问题的，问题出在了register_globals的问题上，

 

变量覆盖register_globals这个问题从5.3.0起废弃并从5.4.0移除，之后把php版本换成了5.2.17并把register_globals修改为On以后成功上传php文件。
