    前些时候我在测试中发现了一个IDOR漏洞。通过遍历ID 值，可以越权下载应用程序中的任何文件，虽然没法确定每个ID对应的文件内容，但有时候也会有意外之喜(例如：证件照、pass.docx、通讯录.xls...)，通常响应如下。

```
HTTP/1.1 200 OKContent-Disposition: attachment; filename=xxContent-type: text/plain;charset=UTF-8Content-Encoding: noneContent-Transfer-Encoding: binaryConnection: close
...File_Content...
```

    关于这种漏洞，最快的方法就是利用Burp的Intruder遍历，将有内容的响应提取、保存为文件。  

![](../Images/0bc1e63895329dd7095cd3de6392fdb8.png)

    首先需要遍历ID值来确定有内容的ID。在Intruder中，使用"Sniper"的爆破类型，Payload则选择Number，选择起始ID、结束ID、步长，点击"Start Attack",获取结果。

    在这里如果遍历的ID值过多，可以通过"Grep-Match"匹配结果，相对而言可以比较有效的筛选有效结果。通常通过"Content-Disposition"字段来匹配，这里有个坑，在"Grep-Match"选项的最后一个标签"Exclude HTTP Headers"这里，默认是勾选状态，也就是说默认是不匹配响应头部分的，需要把他去掉，才能匹配到"Content-Disposition"字段。

![](../Images/a77f312f8071ce29b201f36e99eca3d6.png)

    随后在结果中通过"Content-Disposition"字段排序，选中有效item，"Save Selected Items"。  

![](../Images/86442ffa61afd986c5b0f698fc99940c.png)

    这里默认保存的是xml文件，这个XML文件包含在UI中看到的所有信息，包括请求、响应和关联的元数据。当批量选择项目时，可以右键单击并选择“保存所选项目”，这会将所有请求和响应包含到单个XML文件中。
