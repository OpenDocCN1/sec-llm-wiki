# 谷歌修复Chrome问题：泄露VPN用户的真实IP地址

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzI2NTg4OTc5Nw==&mid=2247485913&idx=6&sn=cdbbed93cc365aaf2392c4e1d60def30&chksm=ea9738b3dde0b1a5d5b845f749ab735e447817e5375c8d8d822cc09fdd8f48994aa88c8e9d11&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzI2NTg4OTc5Nw==&mid=2247485913&idx=6&sn=cdbbed93cc365aaf2392c4e1d60def30&chksm=ea9738b3dde0b1a5d5b845f749ab735e447817e5375c8d8d822cc09fdd8f48994aa88c8e9d11&scene=27#wechat_redirect)

安全专家在今年2月份发现WebTRC中存在问题，它可通过某些设置步骤泄露通过VPN联网的用户真实公共及本地IP地址。

  

WebRTC是一个用于语音及视频通信的网络协议，并且仅被三大浏览器提供商支持：谷歌、Mozilla以及Opera。当WebRTC与STUN服务器同时用于网站时，VPN用户的真实IP地址可能会被泄露。

  

**之前通过关闭****WebRTC****支持修复问题**

问题发现于Firefox以及谷歌Chrome中，但两家提供商均未将其严重程度列为高优先级，只认为是隐私问题且不与安全相关。

  

随后，Firefox确实指导用户在”about:config”页面将”media.peerconnection.enabled”设置为”false”可以解决这一问题，而对于Chrome用户来讲，BrowserLeaks.com团队提供了一个扩展完全禁用了浏览器中的WebRTC支持。几个月过后，Opera也公布了一个Chrome扩展试图在不完全禁用WebRTC的情况下解决这个问题，但据悉它导致WebRTC的某些功能如VoIP不能正常运行。

  

**Chrome****团队推出****Chrome****扩展**

谷歌表示称，“一旦安装扩展，WebTRC将只会使用与网络流量界面相关的公共IP地址”，而这些地址“一般跟已提供给HTTP请求站点的地址一样。”遗憾的是，跟Opera扩展一样，WebRTC Network Limiter也有不足之处，通过限制“潜在的网络路径，WebRTC会选择一种可导致严重延时或质量更低的路径。”
