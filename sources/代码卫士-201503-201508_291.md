# 台企盈码科的NetUSB软件中出现漏洞 影响全球数百万台设备

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzI2NTg4OTc5Nw==&mid=2247485961&idx=1&sn=1ec2ba84d4cf2041551249cffae0c1b8&chksm=ea973b63dde0b275989a540410a52f66fe2fa970e699ebd6f8831993ca52fb896e5207b2cfdb&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzI2NTg4OTc5Nw==&mid=2247485961&idx=1&sn=1ec2ba84d4cf2041551249cffae0c1b8&chksm=ea973b63dde0b275989a540410a52f66fe2fa970e699ebd6f8831993ca52fb896e5207b2cfdb&scene=27#wechat_redirect)

SEC Consult 漏洞实验室在台湾企业盈码科（KCodes）公司的软件组件NetUSB中发现一个远程可攻击的内核栈溢出漏洞。由于输入验证不充分，过长的计算机名称可溢出“计算机名称”内核栈缓冲区，导致产生内存破坏的情况，从而发展为远程代码执行。

  

**POC**

以下是从vulnerable run\_init\_sbus（）函数（虚拟码）中得到的摘要：

```
int computername\_len;
```

```
char computername\_buf\[64\];
```

```
// connection initiation, handshake
```

```
len = ks\_recv（sock, &computername\_len, 4, 0）;
```

```
// ...
```

```
len = ks\_recv（sock, computername\_buf, computername\_len, 0）; // boom!
```

研究人员已经写出一个POC”netusb\_bof.py”可利用这个漏洞，但由于许多厂商并未修复漏洞因此将不会公开。用例表明会导致拒绝服务（内核内存破坏导致设备重启）：

./netusb\_bof.py 192.168.1.1 20005 500

**解决方案**

TP-LINK已经开始发布已修复的固件。受影响产品的状态可从上述所列的产品清单中查看。更多详细信息，可参见CERT/CC漏洞通知：http://www.kb.cert.org/vuls/id/177092。

  

**权变措施：**

有时候可通过网络界面禁用NetUSB，但至少在NETGEAR设备上，这种办法行不通。NETGEAR表示，目前还没有其他变通方法，TCP端口无法设置防火墙并且没有办法禁用设备上的NetUSB服务。

  

**更多背景信息**

根据盈码科公司的介绍，该公司主要提供移动打印，音频及视频通信，文件共享，iPhone、iPads、智能手机及平板电脑（安卓及Windows）、MacBook以及Ultrabook的USB应用程序服务。

  

NetUSB是由台湾盈码科公司开发而成，旨在提供“USB over IP（在IP上提供USB服务）”的功能。USB设备（如打印机、外部硬件驱动器、闪存驱动器）被插入Linux嵌入式系统（如路由器、访问接入点或专门 的USB over IP盒子），并且可通过使用Linux内核驱动器的网络获取，而Linux内核驱动器会启动一台服务器（TCP端口20005）。客户端在Windows 及OS X环境下的软件执行。NetUSB连接到服务器，同时促使连接到嵌入式系统的设备在本地启动。用户体验就像是一个USB设备从物理意义上插入了一个客户端 系统。值得注意的是，NetUSB的功能可在我们所检查的所有设备上使用，**而且服务器在没有插入****USB****设备的情况下还在运行！**

安全研究人员首先在TP-LINK设备上发现了NetUSB内核驱动器。为了建立服务器连接，需要通过一个简单的互相验证检查。验证根本没用，因为 AES密钥是静态的而且可在内核驱动器以及Windows跟OS X的客户端软件中找到。作为连接的一部分，客户端需要发送自己的计算机名称。问题出现了：客户端可指定计算机名称的长度。通过指定一个长度大于64字符的 名称，从套接字中获取到计算机名称时，栈缓冲区溢出。于是，轻而易举地，’90s在调用并且想取回漏洞，栈缓冲区溢出。所有的服务器代码都以内核模式运 行，因此这是一种“罕见的“内核栈溢出。

  

每个厂商在提到NetUSB功能时会使用不同的术语，比如NETGEAR称其为ReadySHARE，其它厂商称其为“打印共享”或“USB分享端口”。

  

虽然无法从研究人员所拥有的设备网络中获取NetUSB，但有迹象表明一些设备将TCP端口20005暴露到了网上。研究人员无从知晓造成这种后果的原因是用户错误配置还是一些设备的默认设置。但这样做就导致攻击者可访问潜在受害者的USB设备并且成为另外一个漏洞。

  

时至今日，只有TP-LINK发布了漏洞修复，并且公布了约40种产品的修复期限。

  

此外，安全研究人员表示在嵌入式系统安全方面还有其他值得但有的地方，并且指出构建未来物联网设备的厂商是同一批厂商。我们将进行后续跟进。
