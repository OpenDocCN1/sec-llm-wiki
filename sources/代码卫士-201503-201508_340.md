# Rombertik恶意软件检测安全分析并破坏MBR

思科Talos 安全情报及研究集团的安全研究人员针对窃取受感染设备敏感信息的恶意软件进行了一次深入分析。为了确保不被分析，这款恶意软件的作者使用了一些非常狡猾的机制。

  

Rombertik通过附加在垃圾信息及钓鱼信息作为文件来传播。一旦被执行，恶意软件就会执行反分析检查以确保它不会在沙箱中运行。

  

这款恶意软件使用的逃避方法之一是使用垃圾数据。专家表示97%的可执行Rombertik由75张图片及愈8000个未使用功能组成。

  

许多沙箱是为了仅在某段时间内监控文件以确定是否为恶意文件。这就是恶意软件开发人员为何在启动恶意程序之前开始将其设置为休眠状态。

  

Rombertik不会休眠，而是会在内存中编写9.6亿次一个字节的随机数据来逃避沙箱。虽然这个方法与休眠类似，但在反追踪工具及沙箱中更为有效。

  

“沙箱可能不能立即确定应用程序是否是有意停止。另外一个劣势是，重复编写可能会堵塞应用程序追踪工具，”思科在博文中表示，“如果一款分析工具试 图记录所有的9.6亿次写入指示，那么记录就会超过100G。即便分析环境可以处理那么大的日志，但将这么多数据写入硬盘驱动所需时间也会超过25分钟。

  

如果某次反分析检查失败，恶意软件就会终止。如果没有检测到分析工具，Rombertik就会开始在内存中解密并执行解压代码。代码中包含函数重叠以及增加复杂度并阻止分析的不必要指令。

  

思科表示，Rombertik与臭名昭著的Dyre木马相似，然而，Dyre主要是为了从在线银行站点中窃取信息，而Rombertik则是从受害者浏览的所有网站中收集用户名及密码。

  

它通过检查运行进程来查看网络浏览器是否存在。如果Chrome、IE、或者Firefox在运行，那么恶意软件就会将其注入进程并抓取处理明文数据的API函数。这样，网络威胁就会捕获到用户输入网站的未加密数据。

  

但在开始信息窃取之前，恶意软件会进行最后一次检查以确保自己未被分析。如果检查失败，网络威胁就会抹掉数据。首先，恶意软件会尝试覆盖MBR（主 引导记录）让受感染设备变得不可运行。如果它没有覆盖MBR的许可，Rombertik会通过一个随机生成的RC4密钥尝试加密存储在主文件夹的文件。

  

一旦MBR被覆盖，计算机就会重启，受害者也会得到一条“Carbon破解尝试失败”的信息。除了阻止计算机重启之外，恶意软件还会为磁盘分区覆盖 字节，让其难以恢复数据。“虽然过去Talos已经在恶意软件样本中观察到反分析及反调试技巧，但Rombertik的特别之处在于，如果它检测到与恶意 软件分析相关的某些属性，它会积极尝试破坏电脑。”思科安全专家指出。
