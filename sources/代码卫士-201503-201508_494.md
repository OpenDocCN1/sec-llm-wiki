# Stuxnet Redux：微软修复潜伏达5年的Windows漏洞

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzI2NTg4OTc5Nw==&mid=2247486007&idx=2&sn=f59021ca0e52874062cb0d65ee7c23de&chksm=ea973b5ddde0b24bc45d7faee56e2127c1db4acc3d779070b050b3305019c1dd9887c0dd2b5b&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzI2NTg4OTc5Nw==&mid=2247486007&idx=2&sn=f59021ca0e52874062cb0d65ee7c23de&chksm=ea973b5ddde0b24bc45d7faee56e2127c1db4acc3d779070b050b3305019c1dd9887c0dd2b5b&scene=27#wechat_redirect)

虽然微软补丁星期二的焦点主要集中在修复FREAK加密漏洞上，但微软还发布了修复另外一个长久以来的Windows威胁：Stuxnet（震网病毒）。

  

很多人以为微软在2010年Stuxnet病毒大肆传播之时便已修复，其实不然。很遗憾的是那次紧急修复并未解决问题。

  

惠普的TippingPoint安全机构最近发布的一份报告指出，“补丁并没有完全修复Windows shell中的.LNK问题，还有一些缺陷并未被修复”。结果导致无数Windows机器易受到Stuxnet及其他在过去五年内类似病毒的攻击。

  

这些阴魂不散的漏洞最初由德国安全研究员Michael Heerklotz发现，他表示已在1月份将该漏洞披露给惠普的0 Day计划。

  

这些漏洞见于Windows的所有版本，包括从Vista、Windows Server 2003一直到最新的Windows 8.1版本以及Windows Server 2012 R2。

  

幸运的是，微软认为这次的漏洞已被修复。具体修复可见MS15-020。目前尚不得知这些漏洞是否已被利用。惠普TippingPoint漏洞研究员Gorenc指出漏洞利用代码很容易生成而且并不需要绕过Windows的内存保护机制便可运行。如被成功利用，攻击者能够执行任意代码，而这也是微软把每个被感染平台上的MS15-020补丁都评为“严重”等级。

  

卡巴斯基实验室披露一个秘密组织“方程组”培养出的复杂恶意软件已有20年之久，且可能包含Stuxnet本身时，有报道称微软的Stuxnet补丁修复并不完整。

  

虽然卡巴斯基不愿说出“方程组”的真实面目，但跟美国情报社区有关联的来源告知路透社称“方程组”的幕后凶手正是NSA。当问起微软为何2010年补丁并未完全修复Stuxnet时，微软表示随着技术的发展，网络犯罪分子所采用的手法已发生变化，因此补丁也需要进行更新。
