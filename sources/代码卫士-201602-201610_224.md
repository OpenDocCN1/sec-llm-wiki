# 由糟糕UI设计引发的宏威胁

**多家安全企业指出，大量恶意软件变体使用内潜在****Office****文档中的宏脚本感染用户。****US-CERT****随后发布官方告警信息。**

宏从本质上来说并不是恶意的。宏恶意软件依靠附加在当文件打开时就会执行的Office文件中的宏脚本感染用户，如果没有安全限制措施的话。这些脚本会在Office应用程序运行的情境下执行多种行为。

**20****多年前曾流行的宏恶意软件**

宏恶意软件在20世纪90年代时非常流行，它帮助传播多种蠕虫和病毒。起初，宏能够在用户打开文件时执行。从Office 97开始，微软开始通过弹出消息告警人们避免打开带有自动执行宏的文件。这些弹出消息设法打压了宏恶意软件的流行程度，而且随着Office 2000版本的推出，此类恶意软件传播几乎消失殆尽。

不幸的是，微软从Office 2007版本开始犯了一个非常大的设计错误，在文件开启前的弹出消息删除，而是在用户打开文件之后将其显示在应用程序中的通知栏中。微软依然会在文档开启时拦截自动宏执行，但通知栏在安全告警方面的作用非常小。显示在通知栏中的信息无法让Office用户了解到宏是什么以及它们所造成的直接后果是什么。

**宏恶意软件重现因糟糕的用户界面设计而起**

从Office 97版本的告警信息“一些宏可能会包含损坏您计算机的病毒”，改为之后的六个字即“告警：宏被禁用。”微软并未告知为何要禁用宏，也未说明如果开启宏会带来什么后果。从Office 2010开始，告警信息旁边甚至还多了个“启用内容”的按钮，也就是用户可以启用宏。

犯罪分子起初并未注意到这个变化，不过他们最终得以发现，于是宏恶意软件又重新出现。

用户界面和用户体验设计对各方面都起着重要作用，对于恶意软件也是如此。没有了显著的通知信息，用户又开始启用宏脚本“查看文件内容”，而这正是恶意软件作者诱骗用户启用宏并执行恶意软件的方法。

如今几乎每周都有报告称发现了新的恶意软件家族利用这个方法进行传播，或者一些网络间谍组织利用恶意Office文档发动针对性攻击。不过US-CERT针对宏恶意软件提出了一些应对建议。例如，禁用所有的宏和受信任地址、禁用所有的宏但允许被控制的受信任地址等。
