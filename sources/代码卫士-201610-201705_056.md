**子域名枚举就是为一个或多个域名找到有效（可解析）子域名的过程。除非DNS服务器暴露了一个完整的DNS区域，那么要获取已有子域名的清单并不容易。常见的做法是使用常用名称的字典尝试解析。虽然这种方法在某些情况下是有效的，但它并不包含名称不平常的子域名。另外一种方法是爬下二级域名从而找到子域名链接（更快的方法是直接使用搜索引擎）。**

  

子域名枚举是网络杀伤链 (cyber kill chain) 中侦察阶段的重要部分。网络攻击者会勾勒出目标的数字足迹找到弱点从而获取比如访问内网的权限。

  

举个例子，完成子域名枚举进程后，攻击者在目标的DNS区域中找到blog.example.com作为其中一个子域名。攻击者会将这个结果上升到网络应用程序层并发现这个博客使用Wordpress作为内容管理系统。攻击者随后会运行wpscan找出Wordpress漏洞。幸运的是，目标的WordPress实例使用了一个易受攻击的插件，攻击者能获取对这个环境的访问权限并进一步深入网络。这例子可能看似有点夸张，然而，这恰恰就是巴拿马文件安全事件中发生的事情。

  

接下来我们说的是子域名枚举所使用的最流行的开源工具和技术。

  

**区域转换**

  

最简单也最基本的技巧是直接在DNS服务器上尝试一个AXFR请求：

  

dig @ns.example.comexample=.com AXFR

  

区域转换用来复制首选和备选DNS服务器的区域内容。最佳实践建议管理员允许来自授权DNS服务器的AXFR请求，因此上述技巧可能不会起作用。不过如果起作用的话，你找到的就是一个金矿。

  

跟区域转换类似的是一种名为NSEC行走攻击的技巧，它美剧的是DNSSEC签名的区域。

  

**Google Dorking**

  

很幸运，你可以使用多个运营商来提炼搜索查询（我们通常将这些查询称为“Google dorks”）。如上所述，很多子域名可通过爬虫目标的方式实现。谷歌（以及其它搜索引擎如必应）将其作为副产品。我们可用site运算符查找谷歌所找到的所有子域名：

  

site:example.com

  

**Rapid7 DNS数据集**

  

Rapid7公开在scan.io库中公开提供Forward DNS研究/数据集。这个DNS数据集旨在发现所有从互联网中找到的域名。虽然做得很好，但上面的清单并不完整。你可扩展阅读下他们是如何编译数据集的。下载最新快照后，我们可运行jq来发现子域名：

  

zcat snapshop.json.gz |

jq -r 'if (.name |test("\\\\.example\\\\.com$")) then .name else empty end'

  

jq通过测试正则表达式 ”ending with .example.com” 来找到数据集中的所有子域名。

  

免费网络服务产品DNSDumpster用的就是这种技术。

  

**主体别名**

  

主体别名（SAN）是x.509证书的一个扩展，旨在为某个证书中的主体提供不同的名称。企业通常会为多个子域名生成一个证书以节约成本。我们看下这些证书，通过两个不同来源来查找下SAN中的子域名。

  

**Censys.io**

  

Censys.io是scans.io发布的数据子集的一个接口。它的优点是允许在证书中搜索关键字，从而会披露一些新的子域名：

  

https://censys.io/certificates?q=.example.com

  

**Crt.sh**

  

Crt.sh是COMODO提供的证书搜索网络服务。它使用的数据集不同于Censys，但原则是一样的即找出证书中的子域名。

  

https://crt.sh/?q=%25.example.com

  

需要注意的是，尽管一些域名会以NXDOMAIN来响应，它们仍然可能存在于内网中。管理员有时候会在内联网服务器中为公开服务器复用证书。

  

**Sublist3r**

  

最流行的子域名枚举开源工具之一是Sublist3r。它会从很多不同来源聚合输出，包括谷歌、必应、Virustotal、crt.sh等。

  

虽然这些数据在多数情况下是正确的，但你可能会遇到无法解析的子域名（以NXDOMAIN响应的域名）。这是因为Sublist3r严重依赖于被动数据，而且它并不会验证所找到的子域名是否真的存在。

  

Sublist3r还会使用一个单独的项目subbrute。后者使用常见的子域名名称字典来找到可解析的子域名子集。

  

要使用Sublist3r，只需运行

python sublist3r.py-d example.com

就可得到example.com的子域名清单。

  

**theHarvester**

  

另外一个开源情报收集工具是theHarvester，它能找到目标域名以及子域名还有虚拟主机上的邮件地址。然而，跟Sublist3r比起来，它提供的子域名结果更少。可通过以下命令来运行theHarvester。

  

pythontheHarvester.py -d example.com -b all

  

**智能DNS暴力破解器（SDBF）**

  

子域名枚举工具通常会包含试图解析的常见子域名清单。这种方式可通过Markov链来扩展从而发现子域名名称结构（例如如你有www1，那么很可能也存在www2等）。CynthiaWagner等人写了一篇研究论文对此有更加详细的阐述。SDBF所生成的结果要比简单的子域名关键字枚举好得多。

  

**结论**

  

定期查看你的网络竞争对手能发现哪些子域名是一个很好的实践。持续侦察你的环境会让你的可见性提高。被忘记的子域名会暴露你的环境以及所在公司，从而带来威胁如子域名控制甚至是完全攻陷。
