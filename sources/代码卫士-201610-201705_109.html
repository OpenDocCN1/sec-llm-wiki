Java AMF库存在缺陷 可导致远程代码执行

CERT/CC表示，多个AMF3的Java实现中出现跟反序列化有关的漏洞，可导致未经验证的远程代码执行和XXE攻击发生。


来自Code White公司的资深渗透测试人员Markus Wulftange将这些漏洞报告给CERT/CC和供应商。其中一些受影响产品目前已有相关补丁。


序列化数据被提取的进程就称为反序列化，如果处理不当则会引发重大安全问题。


AMF3是Adobe的Action Message Format的最新版本，它是一个用于序列化ActionScript对象图片的压缩二进制格式。AMF首次于2001年引入Flash播放器6中，而AMF3自Flash播放器9推出以来就存在。前几年出现了多份跟远程代码执行漏洞相关的报告，序列化实现不当导致Java应用程序中出现了这些漏洞。


Wulftange发现一些AMF3反序列化器的Java实现引入了潜在的严重漏洞，导致未经验证的攻击者能够远程执行代码或引发DoS条件。这名研究人员还发现一个XXE漏洞，可导致服务器中的敏感数据遭披露。


CERT/CC发布的安全公告中提到三个漏洞。第一个漏洞能导致攻击者欺骗或控制一台RMI服务器执行代码。据称影响Atlassian’s JIRA、Exadel’s Flamingo、GraniteDS、Spring spring-flex和WebORB for Java by Midnight Coders。第二个漏洞也可被利用执行任意代码，从而欺骗或控制信息。它影响Flamingo、Apache’s Flex BlazeDS和GraniteDS。这个XXE漏洞也影响WebORB产品。一些易受攻击的库如GraniteDS和Flamingo已被停止。Atlassian和Apache已为受影响的相关产品发布补丁。


CERT/CC指出，来自HPE、SonicWall和VMware产品也受影响。该组织机构建议开发人员使用实现了序列化黑名单过滤器版本的JDK并确保他们的产品已正确处理了来自不受信任来源的反序列化数据。
