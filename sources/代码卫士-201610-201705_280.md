# 勒索软件盯上Hadoop和CouchDB数据库

**前段时间，MongoDB和Elasticsearch数据库遭受了一系列的勒索攻击，如今很多CouchDB和Hadoop数据库用户也难逃一劫。**

  

攻击者利用自动化工具针对联网但安全措施薄弱的数据库发动攻击，或删除或窃取数据，并留下勒索信息。不安全的MongoDB首当其冲，至今也有超过3.3万个数据库沦为受害者。然而，随着更多的黑客牵涉其中，攻击者又开始转向其它数据库，Elasticsearch数据被暴露在聚光灯下。在最开始只有几百个数据库遭受攻击，不过截至目前这个数字已经超过4600。

  

据报道，针对MongoDB数据库的攻击已经降温，表明黑客专注对Elasticsearch等数据库发力。有人在积极出售MongoDB和Elasticsearch的勒索软件工具包，不过是否还会有其他攻击者参与还有待观察。

  

截至目前来看，联网CouchDB和Hadoop分布式文件系统（HDFS）是这类攻击的潜在受害者。不过攻击出现的一个重要变化是黑客可能不会窃取数据并以此进行勒索，而只是将所有数据删除以造成损失。

  

虽然CouchDB数据库遭受勒索的数量现在还不多，但已经有约4000个被暴露的实例，而如果管理员不及时部署安全措施的话，数量可能会急速增长。

  

根据对Hadoop服务器的追踪来看，有126个服务器被肆意破坏，有3名攻击者正在积极对其利用。这些服务器中有8000到10000个HDFS，意味着攻击者的攻击面不小。

  

研究人员表示针对HDFS的攻击（始于上周）是很可能发生的 ，因为管理员使用了最小安全并且可从互联网访问到；另外，近年来DoS攻击由上涨趋势，尤其是在企业部分。

  

由于HDFS使用的是默认配置，导致攻击者在不经验证的情况下访问，任何基本熟悉Hadoop的人都可删除文件。安全研究人员指出，在1月5日到6日，由于攻击者对开放的HDFS进行了扫描，端口50070的流量骤升。

  

作为保护措施，管理员应该遵循适用于所有数据库的简单规则，那就是避免将其暴露在互联网环境下，除非在非常必要的情况下；使用强验证设置（不更改默认设置意味着无需验证）；定期备份数据，这样在被攻击后可快速恢复。

  

全球已有成千上万个数据库遭攻击，管理员应该采取措施加固安全。研究人员已经通过联系当地GovCert团队告警系统管理员相关的暴露情况，这一举措使得关键的Hadoop服务器断网。
