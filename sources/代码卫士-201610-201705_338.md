# 测试时间：你的加密代码能经受住Google的攻击么？

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzI2NTg4OTc5Nw==&mid=2247485615&idx=3&sn=548830cc420215e9042e2f08cc55ce8d&chksm=ea9739c5dde0b0d3b3d186c6fa7ae6617df2d5687f0e77b77219782ab9fd9abb734c5516093b&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzI2NTg4OTc5Nw==&mid=2247485615&idx=3&sn=548830cc420215e9042e2f08cc55ce8d&chksm=ea9739c5dde0b0d3b3d186c6fa7ae6617df2d5687f0e77b77219782ab9fd9abb734c5516093b&scene=27#wechat_redirect)

**谷歌发布****Project Wycheproof****，这是一组安全测试来检查加密库对已知漏洞的敏感性。**

该工具由谷歌的安全工程师维护，以Wycheproof山命名（世界上最小的山），其目的是为全职密码学家和计算机科学家的代码寻找明显的编码错误，而不是找出根深蒂固的数学缺陷。

  

谷歌专家已开发了超过80个测试用例，发现了40多个安全漏洞。其中包括一些常见漏洞，如从DSA和ECDHC实现中恢复私钥。

  

谷歌的团队也提供即时可用的工具来检查Java加密架构提供程序（如Bouncy Castle和OpenJDK中的默认提供程序）。

  

“在密码学中，微妙的错误可能会导致灾难性的后果，并且开源密码软件库中的错误经常重复出现，但很少会被发现。”工程师在博客中解释道，“但良好的实施指南很难实现，理解如何安全地实施密码需要消化几十年的学术文献。”

  

“软件工程师使用单元测试防止漏洞，我们发现很多加密问题可以通过相同的方式解决。”

  

“通过测试并不意味着库就是安全的，只意味着它不容易受到 Project Wycheproof尝试检测的攻击。密码学家还在不断地发现加密协议的新缺陷。”
