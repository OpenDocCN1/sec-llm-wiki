# 网站遭泄露？明文存储密码？Tripwire 统统告诉你

> **美国加州大学圣迭戈分校**** (UCSD) ****的三名研究人员开发出一款工具****Tripwire****，它能够检测出基于用户注册的网站是否遭受数据泄露事件以及网站是否以明文形式存储数据。**

Tripwire 的运行理念很简单。研究人员表示Tripwire 用一个不作其它用的唯一邮件地址在网站上注册一个或多个账户。每个邮件账户和网站资料都使用同一个密码。Tripwire 将定期查看是否有人使用这个密码访问邮件账户，如有则表明网站遭受数据泄露，攻击者使用被盗数据登录到关联邮件账户。

  

在测试阶段发现19起数据泄露事件

  

在真实测试中，研究人员表示在2300多个站点上注册了账户。在研究期间，攻击者访问了其中19个站点中的邮件账户，包括一个用户基数为4500万的站点。

USCD 研究人员跟每个网站都进行了联系，但令人惊讶的是，没有一个网站通知用户相关泄露情况。USCD计算机科学的教授 Alex C. Snoeren表示自己对大型网站严肃对待这件事而备受鼓舞，但是对于他们并未对研究成果采取任何措施感到有点吃惊。不过他表示并不会披露这些网站的名称。现实情况是，这些网站并未自愿参加这项研究活动，因此如披露它们的名字可能导致它们蒙受巨大的经济损失和法律风险，因此决定让这些网站自行处理。

  

Tripwire 还能暴露以明文形式存储密码的网站

  

不过研究工作并未到此结束。Tripwire 背后的简单理念还能暴露哪些网站以明文形式存储密码。

例如，可使用 Tripwire 记录同一网站上的多个蜜罐账户发现有人设置的密码很简单，而有些人的密码很复杂很长。

如果攻击者同时访问了这两种密码，那么说明网站是以明文形式存储密码，或者使用了易遭攻破的密码哈希系统如 MD5。

如果攻击者只访问了密码简单的账户，那么说明网站存储密码的方式是安全的，而攻击者可能使用了基本的暴力字典攻击猜测一些用户的密码。

  

Tripwire 已在 GitHub 上开源

  

另外，研究人员表示他们还开展了更多测试以判断数据泄露事件发生在真实的网站上还是托管着邮件地址的邮件提供商处。

研究人员表示创建了10万多个邮件账户作为对照账户。如果攻击者仅访问了跟在线资料相关联的邮件地址，而非其它10万个测试账户，那么说明数据泄露事件发生在第三方网站上而非邮件提供商处。

研究人员已将 Tripwire 工具的源代码发布在 GitHub 上，他们希望企业能在内部使用这款工具作为一种额外的泄露检测系统。

11月份，研究人员在伦敦举办的 ACM 互联网测量会议上展示了自己的研究成果，他们的论文题目是《Tripwire：推断互联网网站妥协 (Tripwire: Inferring Internet Site Compromise)》。
