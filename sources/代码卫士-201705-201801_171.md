# 黑客能窃取Windows登录凭证 无需用户交互

微软最近修复了一个危险漏洞，它能导致攻击者在无需用户交互的情况下就能窃取Windows NTLM密码哈希。

  

攻击易于执行，而且并不需要任何高级技术技能。攻击者需要做的就是将一个恶意SCF文件放入公开可访问的Windows文件夹中。

文件放好后，它就会凭借一个神秘的bug执行，手机目标的NTLM密码哈希并将它发送给攻击者配置的服务器。通过公开可用的软件，攻击者就能破解NTLM密码哈希并获得访问用户计算机的权限。

而这种攻击能让直接访问受害者网络的攻击者将权限提升，访问临近系统。

**并非具有共享文件夹的计算机都易受攻击**

带有共享文件夹并受密码保护的计算机是安全的。因为在Windows中它是一个默认选项，因此多数用户并不易受该攻击影响。

不过在企业、学校和其它公用网络中的用户通常会因为寻求便利性而在不设密码的情况下共享文件夹，这就导致很多系统易遭攻击。

  

![](../Images/8ff27c2cf655750456cca8addc4fab1d.png)

  

**补丁仅覆盖****Windows10****和****Server 2016**

这种攻击是由研究员JuanDiego于4月份告知微软的。微软在本月的补丁星期二中通过ADV170014安全公告予以修复。但补丁仅适用于Windows 10和Windows Server 2010用户。

老旧的Windows版本依然易受攻击，因为注册表修改跟老旧的WindowsFirewall版本并不兼容。

**攻击利用的根本漏洞还是谜**

Diego指出，ADV17001拦截了他所发现的攻击，但他无法解释为何会出现这种攻击。

攻击是通过一个恶意SCF文件实施的。SCF即Shell Command File，它是一种文件格式，支持非常有限的Windows Explorer命令，如打开一个Windows Explorer窗口或显示Desktop。我们每天都在用的“Show Desktop（显示桌面）”就是一个SCF文件。

Diego表示，“攻击者仅需将SCF文件上传至易受攻击的文件夹即可。”他强调称攻击无需任何用户交互。

此前涉及SCF文件的攻击只有在受害者访问了文件夹的情况下才会执行。而这次如Diego发现的那样，SCF文件中包含的恶意命令能在攻击者将SCF文件上传到共享文件夹中就可运行，而无需等待用户查看文件的内容。

为何会出现这种情况对于Diego而言是个谜。他指出，“这种攻击是自动化的。我仍然不知道触发这个问题的底层原因。微软对于这类问题一贯都会当做机密保守。”

**补丁试图解决“传递哈希”攻击**

微软发布的补丁实际上解决的并非是Diego无法解释的SCF自动执行问题，而是试图修复一个已存在20年的攻击“传递哈希 (pass-the-hash)”，即通过位于用户网络之外的服务器自动共享NTLM哈希。Diego曾在这次入侵中使用了这种技术。

问题是旧问题，而且常用于多种类型的Windows攻击中。就在今年春天，一次结合了Chrome和SCF文件的“传递哈希”攻击就用于窃取用户凭证，而2015年和2016年也曾发生过类似攻击。

微软推出的补丁阻止攻击者诱骗本地用户在本地网络之外的服务器上进行验证。

虽然是Diego将攻击告知微软的，但收到微软感谢的是德国研究员StefanKanthak，因为后者在2017年3月份也将该问题告知微软。

Kanthak表示，“微软的工作做得不好，这个月发布的更新仅修复了我所报告的6个问题中的2个。”这表明利用“传递哈希”攻击的方法仍然存在。

Diego表示，“我目前正在着手研究利用这个漏洞的其它方法”。这也呼应了Kanthak的说法，他认为微软远未修复这个存在相当长时间的安全漏洞。

虽然ADV170014是一个可选补丁，但强烈建议安装该更新，因为它能阻止Diego发现的危险攻击，以及还有其它可能存在的“传递哈希”攻击。
