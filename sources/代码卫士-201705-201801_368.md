# 利用PayPal服务器“文件上传”漏洞远程执行代码

**安全研究人员****Vikas Anil Sharma****利用了一个****PayPal****服务器中的不受限制的“文件上传”漏洞，远程执行代码。**

Vikas通过Burp软件访问PayPal漏洞奖励页面后在得到的响应下打开页面http://paypal.com/bugbounty/。

  

![](../Images/a60ee8a54ea2f52f8ab6340f6f344705.png)

  

他主要分析了 “Content Security Policy:” Response Header中提到的PayPal域名列表，具体是“https://\*.paypalcorp.com”。

  

Vikas在第一阶段主要想找到尽可能多的有效子域名以在攻击中利用。Subbrute、Knockpy、enumall是实施此类分析的有用工具。不过他使用了VirusTotal枚举子域名，从这个网址可看到这些域名列表：https://www.virustotal.com/en/domain/paypalcorp.com/information/。

  

Vikas本地复制了子域名列表并运行”dig-f paypal +noall+answer”检查这些子域名到底指向哪里。Vikas注意到域名 “brandpermission.paypalcorp.com”指向托管Online Support Ticket System的站点，该站点供PayPal厂商、供应商和合作伙伴获取PayPal品牌许可。用户可通过该网站上传跟品牌相关的模型标识和图片。Vikas决定通过上传一张简单的图片来创建一个标签 (ticket) 并分析图片的文件夹位置。

  

他指出，“于是我首先通过上传一个名为‘finished.jap’的简单图片文件创建了一个标签，它存储于目录‘/content/helpdesk/368/867/finishedthumb.jpg’中，存储为 ’finished\_thumb.jpg’。’finished\_thumb.jpg’是目录’/867/’中新创建的文件，我很快检查了我们上传的这个真实文件是否存在于这个目录中，很幸运地它存在于相同的目录中。”

  

Vikas发现上述链接包含标签号码，具体到他的案例这个号码是 “368”，而 ”867” 是文件夹的号码，这个文件夹存储着所有跟标签相关的文件，包括模型文件在内。

  

Vikas上传了一个名为 “success.php”的文件，因此比对上传图像的相似之处后他认为文件被存储为 “success\_thumb.php”。

  

于是，Vikas决定暴力攻击文件的文件夹id。

  

![](../Images/5118532322bc141e0e38ad8f7ff31f55.png)

  

获取文件的文件夹id后，Vikas尝试执行代码：https://www.paypal-brandcentral.com/content/\_helpdesk/366/865/success.php?cmd=uname-a;whoami。他表示“通过cat+/etc/passwd后我认为发现了一个远程代码执行漏洞”。  

  

Vikas在7月8日18:03提交了这个漏洞，PayPal公司于6月11日18:03修复了该漏洞。
