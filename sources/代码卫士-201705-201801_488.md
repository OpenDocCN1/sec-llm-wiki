# 利用Windows系统的RegisterApplicaitonRestart函数绕过沙盒检测环境

**RegisterApplicationRestart函数的作用是当应用程序崩溃或因其他原因无法运转（或者是一款安装程序需要重启系统并再次启动）时，Windows操作系统会重启启动该应用程序。**

  

但为了避免循环重启，程序需要至少运行60秒。假设某程序需要执行如下动作：

  

检查某个命令行参数是否存在

    如是

        运行恶意软件

    如不是

        通过RegisterApplicaitonRestart注册并提供一个命令行f.ex./nosandbox

        利用Sleep休眠60秒

        引发崩溃(f.ex. divide by 0)

  

如果这款应用程序未在沙盒环境下运行，那么它崩溃后会被操作系统重启并通过/nosandbox参数执行恶意软件。

  

![](../Images/9fbe181402c4a34f40831290db56a8f7.png)  

  

如果这个应用程序是在沙盒下运行，那么沙盒引擎将很可能影响Sleep函数的运行，而这将会禁用RegisterApplicationRestart函数的功能。这个程序运行的时间将会少于60秒，因此崩溃后不会重启。沙盒报告会空空如也。

  

注意，Windows10的默认设置会重启应用程序：

  

![](../Images/599a30df913dd3d4a75a11d9406af5a0.png)  

  

在更早的操作系统版本中，可能要求用户选择是否想要重启这款应用程序（取决于Windows出错报告设置）。值得注意的是，如果此类对话在样本在沙盒中运行时弹出，那么有可能沙盒会自动点击“重启”选项。但我们必须首先等待60秒。

  

**额外取证信息**

  

RegisterApplicationRestartAPI较少使用的选项跟安装程序有关。如果跟ExitWindowsEx.EWX\_RESTARTAPPS结合使用，那么它就会在下次登录时让系统执行这个应用程序。这个临时持续机制的机制很有意思。

  

在用户登出之前，csrss.exe进程会注册一个位于以下位置的RunOnece条目：HKCU\\Software\\Microsoft\\Windows\\CurrentVersion\\RunOnce\\ApplicationRestart #<NUMBER>

  

它实际上指向被重启的应用程序

  

因此，如果你看到如下条目：

  

o   HKCU\\Software\\Microsoft\\Windows\\CurrentVersion\\RunOnce\\ApplicationRestart #0

o   HKCU\\Software\\Microsoft\\Windows\\CurrentVersion\\RunOnce\\ApplicationRestart #1

  

那么很有可能它是未完成的安装程序的结果。

  

它会不会变成一个持续性机制？可能会吧，但作者表示尚未找到一种在不启动系统的情况下实现这个目的的实际方法。
