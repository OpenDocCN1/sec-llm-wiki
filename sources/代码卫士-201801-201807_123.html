昨天，NPM JavaScript 包管理器的用户收到了一条诡异的出错信息。每当他们更新或安装一个新的 JavaScript/Node.js 包时，控制台和应用程序就会闪现一条名为“ERR! 418 I’m a teapot（出错！418 我是一只茶壶）”的信息。

全球所有的 JavaScript 开发人员都收到了这个出错信息，无论他们位于世界的哪个角落，都不能“幸免于难”。

仅使用代理服务器的用户受影响

这个 bug 并未影响所有的用户，只是使用代理服务器的用户。尽管如此，大量开发人员均受影响，因为多数大型开发公司通常都使用代理服务器，规范并控制内部网络流量。

这个 bug 的原因在于，某些代理服务器将一个端口值附加到指向 NPM 软件包注册表的请求上，导致在 HTTP 请求中它看起来像 registry.npmjs.org：443，而不是 registry.npmjs.org。

这个额外的端口443值导致 NPM 注册表的服务器很困惑，从而触发 418 错误代码。NPM 团队在7个小时后修复了该问题。开发人员对这个有趣的出错代码感到“又惊又喜”。

源自20年前的梗

这个错误信息并非标准的服务器错误类型。故事得回到1998年的一个愚人节玩笑，当时一群开发人员开玩笑地向创建并管理互联网标准的组织机构互联网工程任务组 (IETF) 提出“超文本咖啡壶控制协议 (Hyper Text Coffee Pot Control Protocol , HTCPCP)”的提议。

RFC 2324 恶搞标准中包含很多有趣的出错代码，其中就包含这个 “出错！418我是一只茶壶”。

这个梗横行1998年，很多开发团队都在自己的应用程序内部以内部玩笑的方式执行了“出错！418 我是一只茶壶”的信息，通常代指未知来源的 bug。

这么看来，NPM 团队也很喜欢这个梗啊。
