Windows CLI 应用易受新型 Ctrl-Inject 进程注入攻击

enSio 公司的研究员 Rotem Kerner 发现了一种新型进程注入技术，恶意人员可通过这种技术将恶意软件隐藏到基于 Windows 的 CLI 应用中。

这种新技术名为 “Ctrl-Inject”，它滥用的是 Windows “CtrlRoutine” 函数。命令行应用使用该函数确保用户和应用之间的基于键盘的对接。

Ctrl-Inject 仅适用于 CLI 应用

Kerner 在技术 write-up 中说明了恶意人员可滥用这个函数在合法 CLI 应用进程中引发恶意线程并运行恶意代码。

Kerner 指出，相比一般的线程注入技术，这种新型注入技术的优势在于，远程线程是由受信任的 Windows 进程 csrss.exe 创建的，这就导致它更具隐秘性。从本质上来讲，在这个进程注入技术中，我们会将代码注入目标进程中，但从不会直接调用而是让 csrss.exe 调用它。由于这种行为属于正常范围，因此也不太可疑。Ctrl-Inject 的劣势在于它仅限于控制台应用。

Ctrl-Inject 绕过 CFG 和指针编码防护措施

可经由 Ctrl-Inject 技术遭滥用的应用包括 cmd.exe 或 powershell.exe，它们都是存在于多数 Windows 版本中的标准应用。

但 Kernel 在关于 Ctrl-Inject 的技术 write-up 中也提供了关于如何绕过这两种防护措施的路线图。

截止目前为止，Ctrl-Inject 技术仅在理论层面得到详细阐述，恶意软件集成这种技术尚需时日，不过这一天肯定会到来。

本周，SynAck 勒索软件在感染链中集成由 ensile 研究人员去年发现的代码注入技术 “Process Doppelgänging”。
