# 这个严重的 DVR 漏洞还会被一直忽视下去吗？

> **阿根廷研究员**** Ezequiel Fernandez ****刚公布了一款强大的新工具，它可轻易提取多个品牌的**** DVR ****的明文凭证并可导致攻击者访问这些系统以及所记录的视频内容。**

该工具名为 getDVR\_Credentials，它是 CVE-2018-9995 的 PoC。该漏洞是由 Fernandez 于上个月月初发现的。

漏洞严重但被忽视

Fernandez 发现通过 cookie 的头部 “Cookie: uid=admin”就可访问某些具体 DVR 的控制面板，DVR 会以明文形式的设备管理员凭证作为响应。整个利用非常小，甚至可写到一条推特中：

$> curl"http://{DVR\_HOST\_IP}:{PORT}/device.rsp?opt=user&cmd=list" -H"Cookie: uid=admin"

最初，Fernandez 发现 CVE-2018-9995仅影响由 TBK 制造的 DVR 设备，但他周一发布更新报告称，其它厂商生产的系统也易受攻击，其中多数似乎是原始 TBK DVR4104 和 DVR4216 系列的更名版本。

至少数万台设备受影响

Fernandez 推测受影响的设备数量至少有数万台。Shodan 搜索显示，超过5.5 万台 DVR 出现在网上，而另外一次搜索后显示1万多台。

![](../Images/169d8b43fb4d2794d2c8d247bdff0123.png)

Fernandez 还公布了通过利用 CVE-2018-9995获得访问权限的设备的截屏及他使用的工具。这些截屏显示 Fernandez 能够完全访问 DVR 的设置以及实时视频内容。

过去曾有多个网站利用安全缺陷从被黑的安全摄像头和 DVR 中窃取实时视频内容，因此 Fernandez 发布的工具可能会导致类似网站卷土重来。

漏洞已被证实，尚未检测到攻击

多名安全研究人员评估了这款攻击的运行状态和效果。结果显示，Fernandez 的工具功能和作者所述一致。另外，Shodan 搜索提供了获得可能遭利用的设备，使得攻击者获得了两个重要问题的答案即攻击“谁”以及“如何”实施攻击。GitHub 仓库中也包含了用于找到易受攻击设备的 Shodan 搜索结果。

Fernandez 拒绝就此事置评，担心由于自己的英语能力有限己而遭误解或者自己的话被错误引用。而他的英语能力可能也是为何 CVE-2018-9995 在上个月被公布后并未在物联网僵尸网络中变得流行起来的原因。按理说，利用代码如此容易遭利用而所获权限又如此之多，不应该受到忽视。

之前并未大规模扫描到 CVE-2018-9995，而且似乎 Fernandez 发布工具后也并未出现对该漏洞的扫描。

CVE-2018-9995 是下一个 GoAhead 大灾难

但网络安全公司 NewSky Security 的研究员 Ankit Anubhav 认为该漏洞不会被“雪藏”太久，尤其是其 PoC 公布在 GitHub 上后。他指出，NewSky Security 公司最近发现一些 IoT 利用代码遭利用但它们都是和某个厂商相连的，如 CVE-2017-17215（华为）、CVE-2017-18046（DaSan）和 ChimayRed (Mikrotik)。如今 CVE-2018-9995 加入遭利用阵营后，会有更多的人扫描该漏洞并造成和另外一个跨厂商物联网利用代码 CVE-2018-8225 (GoAhead) 一样的损害。

Anubhav 所说的漏洞影响的是 IP 安全摄像头的固件 GoAhead。厂商将其以“白标（无品牌）”产品的形式出售给其它多家公司。过去两年中，这些摄像头每天都会遭到多数物联网僵尸网络的攻击。

由于网上存在数万台不同品牌名下的 TBK DVR，PoC 代码已公布且存在易于利用的脚本友好例程，因此 CVE-2018-9995 一定会成为今年遭扫描次数最多且遭利用次数最多的安全漏洞。

缓解措施

Anubhav 认为，截至目前，除非对 PoC 代码进行修改，那么企业能检测到并阻止攻击。

Anubhav 表示，能很轻易地发现该 PoC 代码遭利用，因为它使用了拼写错误的 “Morzilla” 和 “Pinux x86\_128” 而不是 “Mozila 和 Linux x86\_128” 模仿用户代理。然而，如果攻击者具有基本技能，那么他们就能更改该脚本为己所用，因为利用代码非常容易理解。这是指攻击者能够更改脚本中的用户代理字符串和其它常量。

尽管如此，企业仍然能检测到访问 /login.rsp 或/device.rsp URL 路径的尝试并阻止它们，仅允许受信任的 IP 访问 DVR 的管理接口。

Anubhav 警告称，利用代码被公开后，问题不在于易受攻击的设备是否会遭攻陷而是攻击者利用它的速度有多快。
