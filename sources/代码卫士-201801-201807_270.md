# 微软发布的 Outlook 漏洞补丁被指不完整

CERT/CC 的漏洞分析师 Will Dormann 在2016年11月报告了从微软 Outlook 中发现的一个漏洞 CVE-2018-0950，他指出微软在这次“补丁星期二”中提供的补丁并不完整，需要额外的应变措施。

未获用户同意即检索远程 OLE 内容

CVE-2018-0950 漏洞的问题在于，Outlook 将会在不提醒用户的前提下，自动提交内嵌在富格式邮件中的远程 OLE 对象的内容，微软在其它 Office 应用如 Word、Excel 和 PowerPoint 中都是这么做的。而自动提交 OLE 对象会带来很多问题，它是恶意软件作者常用的一种攻击向量。

Dormann 表示在试验中，他能够利用这种 Outlook OLE 处理设计决策从 Windows 计算机中窃取用户账户密码（更确切地说是 NTLM 哈希）。他将包含向远程恶意 SMB 服务器提出请求的 OLE 对象的邮件发送给 Outlook 用户。从设计上来讲，受害者的 Windows 系统将通过共享用户的 NTLM 哈希在远程（恶意）SMB 服务器上进行验证。

攻击者只需收集这些哈希、离线破解并将它们用于渗透用户计算机随后是内部网络的其它部分。

微软仅修复 SMB 攻击向量

Dormann 表示距离漏洞报告提交近18个月的时间后，微软最终提供的补丁并未解决核心问题。微软为 CVE-2018-0950 提供的补丁仅仅在预览富格式邮件时禁用 Outlook 初始化 SMB 连接。但 Dormann 表示 Outlook 仍未在为邮件预览提供 OLE 对象时提醒用户以获得权限。另外，Dormann 强调称获取 NTLM 哈希的方法还有很多，比如将 UNC 和 SMB 服务器的链接内嵌在邮件中，而这些链接会被 Outlook 设置为自动可点击模式。如果用户点击此类链接，那么产生的影响无异于该漏洞遭利用。

不过，虽然补丁并不完整，但该补丁意味着虽然 Outlook 将继续在邮件预览中提供 OLE 对象，但至少这些对象无法被用于通过 SMB 窃取 NTLM 哈希。

Dormann 提出的较为全面的方法是，建议系统管理员应用其它操作系统级别的权变措施，如在网络边界拦截流入和流出的 SMB 连接；拦截 NTLM 单点登录 (SSO) 认证；以及使用复杂密码阻止 NTLM 遭快速破解。
