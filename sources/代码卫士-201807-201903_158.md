# WebKit 漏洞影响最新版 Safari

> **研究员**** Linus Henze****发布**** WebKit ****漏洞**** PoC****，指出它利用**** WebKit ****在对正则表达式匹配中的优化错误，可导致任意**** shellcode ****遭执行。****WebKit ****是一款**** web ****浏览器引擎，****Safari ****以及**** macOS****、****iOS ****和**** Linux ****上的**** app ****都在使用。**

Henze 表示，漏洞已在 WebKit 源中修复，但 Safari 浏览器尚未使用它。

**最新 Safari 版本受影响**

![](../Images/96277899360a0133ec807fa26151bc68.png)

Henze 强调称，iOS 和 macOS 版本的 Safari 浏览器均受影响，尽管目前他开发的代码并不支持苹果移动平台。

他指出，易受攻击的 WebKit 变体存在于 iOS 版本修订版 12.0及后续版本。至于桌面版本，如果 Safari 在 macOS10.14及后续版本中运行，则可遭利用。

Henze 在 GitHub 上说明了利用详情并表示，该利用适用于 Safari 最新版本（自2018年12月6日起），在最新版本中已修复。他还指出成功利用步骤和  Samuel Groß为CVE-2018-4233 创建的利用一致，后者是在今年 Pwn2Own 大赛中演示的一个远程代码执行漏洞。

CERT/CC 的漏洞分析师 Will Dormann 尝试了 Henze 的利用代码并在最开始时复现失败。Henze 提供线索后，Dormann 成功复现。

技能有限的攻击者无法实际利用该 bug，因为 Safari 的沙箱保护措施应该会阻止代码在浏览器之外运行。因此，Henze 提供的 PoC 应该被整合到利用沙箱逃逸漏洞的利用链中。

**潜在危害**

![](../Images/96277899360a0133ec807fa26151bc68.png)

但是该 PoC 能够在苹果浏览器中执行 shellcode 并可导致攻击者会做出 Safari 允许做的所有事情。其中一个合理的场景是，绕过浏览器的同源策略。  

如果攻击者的代码在 Safari 限制环境中运行，那么“该 shellcode 不必遵循阻止其访问任意 Safari 有权访问的任意敏感信息的策略。”

Dormann 表示，并未发现该场景的在野演示情况，但从理论上来讲，很可能利用 Henze 发布的 PoC 绕过 Safari 的同源保护策略并从任意加载页面访问信息。他通过设置一个新的 RAX 值的方式展示了最容易的 shellcode，并未遭到 Safari 拒绝。这个 shellcode 很可能下令 Safari 做出它有能力做的任何事情。

![](../Images/ef8c27003f7a38d06ab1502065b4b76a.png)

该漏洞还可能影响将 JavaScriptCore 作为 JavaScriipt 引擎的其它除 Safari 之外的产品。由于 Chrome 依靠的是 V8 引擎，因此并不受该漏洞影响。另外，这些应用应该使用“一个相对较新的 WebKit 版本”。
