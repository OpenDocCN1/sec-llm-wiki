# Signal 升级时竟然把未加密信息留在了磁盘上！

> **自诩为用户提供加密通讯服务的**** Signal ****这次食言了：在将**** Chrome ****扩展升级为桌面版本时，将用户信息导出为非加密的文本文件。**

升级过程要求用户选择保存信息数据（文本和附件）的位置以自动将其导入新版本中。升级后，黑客兼安全研究员 Matt Suiche 注意到 Signal 将信息在没有提前加密的情况下保存在了他选择的位置。他在推特上公布了这一发现并提交了一份漏洞报告。

他在推特中评论说，“疯了。真是疯了”，并附上一张截屏，展示了 Signal 在升级过程中推送的文本数据。主目录包含了每个 Signal 联系人的个人文件夹，文件夹名称是联系人的姓名及其电话号码；这样，只要打开主目录就会出现敏感详情。会话存储在每个文件夹内部的 JSON 文件中。

Suiche 在收到 Signal 的 Chrome 扩展更新通知时，在 macOS 上发现了该问题。本文作者在 Linux Mint 上的多个测试账户上也发现了同样的行为。在测试过程中并未发现关于数据以未加密形式存储的警告信息。而且，即使升级过程完成且 Signal 新版本导入信息后，信息仍然存在磁盘上。用户不得不手动删除这些文件夹以降低私密会话信息遭暴露的风险。

**Chrome 版本已过时**

![](../Images/1dafdbf099b6e09ade846f3ccb574066.png)

从一开始，Signal 就是为手机设计的，不过为了便利性，桌面版也出现了并以 Chrome 扩展的形式现身。也就是说，只有当谷歌 Chrome 运行时，Signal 桌面版才会提供加密通讯服务。自从2017年10月末开始，单独的 Signal app 摆脱了 Chrome 的束缚，这也标志着 Chrome 版本的终结，它将在一个月不到的时间里寿终正寝。

要保存会话和经由 Signal 通信信道安全传输的媒体文件，Chrome 版本中的数据被提取至本地文件夹，之后被自动导入单独版本。

**问题还有很多**

![](../Images/1dafdbf099b6e09ade846f3ccb574066.png)

然而，版本升级不能成为 app 将传输及之后过程中加密的信息以未加密形式遗留在磁盘上的理由。Suiche 表示，Signal 不应该以这种方式执行升级进程，因为它暴露了 Chrome app 的所有用户基。  

Red Canary 公司的联合创始人兼首席安全官 Keith McCammon 表示，Signal 桌面版在清除被附加到正在消失的信息上的媒体文件方面做得也较差。该功能会在某个既定时间内删除设备中的信息。McCammon 表示，查看文件系统后肯定会找到本应被删除的媒体文件。

安全专家 Dan Tentler 以戏谑的方式说明了自己在 macOS 上升级 Signal 桌面 Chrome app 的经历：
