# 如何才能更有效地攻破WPA2 协议？

> **继去年发现**** WPA2 ****协议中存在多个安全问题导致其易受**** KRACK ****（****Key Reinstallation****，密钥重装）后，研究人员公布了更多的实际攻击版本。**

去年，Mathy Vanhoef 和 Frank Piessens 解释称，KRACK 可在受害者范围内为恶意人员提供访问被认为安全加密的信息。这些问题存在于 WAP2 WiFi 标准中，影响所有的实现，包括安卓、Linux、Apple、Windows、OpenBSD、MediaTek、Linksys 等。

这两名研究人员解释称，KRACK 针对的是 802.11 标准中的多次握手，操纵握手信息重装已经被使用的键，从而导致随机复用以及中继攻击。

**攻破 WPA2 协议的新方法**

![](../Images/60b1c41235bf467a309b960181e034c7.png)

研究人员在一份将于本月举行的计算机和通信安全 (CCS) 大会上公布的新报告中，他们将详细说明 KRACK 变体的改进版本以及展示如何绕过去年部署的应对措施。

这些新攻击针对是4次握手，它不再依靠难以获得的竞争条件，而是应用更加实际的方法来获得中间人位置。

研究人员还披露称，尚未实际部署的快速初始连接设置 (FILS) 和通道直接链路建立 (TPK) 握手也易受密钥重装攻击，而且能够滥用无线网络管理 (WNM) 节电功能触发对群组密钥的重装。

这两名研究人员表示，“此外，我们绕过（并改进）802.11 官方应对措施。通过组合 EAPOL-密钥和 WNM-Sleep 框架，仍然可能实施群组密钥重装攻击。我们还发现便于实施该攻击的实现缺陷。”

原先的攻击依靠难以获得的竞争条件来触发密钥重装，而新的方法滥用的是 802.11 的节点功能使得访问点 (AP) 临时减缓重新传输的信息3。AP 随后以加密形式将信息3的重新传输发送至新谈判的会话密钥下。论文指出，“这种加密的信息3将总是受客户端接受，即使它已经安装了 PTK。例如，未修复的安卓、macOS 和OpenBSD 版本均接受重新传输的信息3，之后重装会话密钥。”

此前，执行 KRACK 攻击需要拥有多渠道中间人位置，而现在可通过伪造 CSA 诱骗客户端转换至恶意信道。此前使用了专门堵塞某些信道的特殊设备，但现在这种新方法在安卓和 Chromium 上已经成功通过测试。

研究人员还发现，在信息3被捕获后，可以延迟对它的传输（这样无需立即出发密钥重装）。这样，更多的框架就会在攻击发生之前发送，也就是说增强影响。这种延迟已经在 Linux、安卓、iOS 和 macOS 上得到成功测试，而且也可能适用于加密信息。

研究人员表示，“结果显示，阻止密钥重装攻击的难度要比想象的大。我们认为漏洞仍然存在的原因是因为 WPA2 标准的内容很多，而且仍然在扩展新的功能，而且要求具有域名方面的知识予以理解。”

研究人员还表示，“可通过拥有全部和 WiFi 安全功能相关的高级别描述（或正式模型）克服这些障碍。另外，我们认为 WiFi 联盟不应仅测试产品的互操作性，而且也应该模糊测试漏洞问题。”
