美国政府正在采取措施修复近年来充斥着各种问题的公共漏洞列表 (CVE) 系统。

CVE 系统由 MITRE 公司在美国政府资助下创建于1999年，它是包含安全漏洞识别符（追踪号码）的一个数据库。自创立以来，CVE 系统得到公共和私营企业的采用。多数网络安全软件使用 CVE 编号来识别并追踪利用某些软件 bug 的网络攻击。

虽然由美国创建，但 CVE 系统已被全球各国所采用，MITRE 员工和行业合作伙伴发布的 CVE 编号得到使用和认可。

CVE数据库充斥着各种问题

但近年来，CVE 系统饱受压力。2015年末问题显现，而在2016年初，大量安全研究员报告称获取自己所提交的漏洞的 CVE 编号被严重延迟。曾有一小批安全研究人员联合创建了另外一种漏洞数据库 DWF （Distributed Weakness Filing，分布式弱点归档）。

当时，MITRE 表示 CVE 编号分配延迟是因为相比上世纪90年代和21世纪早期软件供应商的增长，同时也是 SCADA 设备和物联网设备激增造成的。这两个因素造成漏洞报告的数量急剧上升，而 CVE 员工无法跟进。2016年末期发布的一份报告显示，MITRE 创建的 CVE 系统未能向2015年发现的6000多个漏洞分配 CVE 编号。

美国参议院于2017年开始调查 CVE 项目

经过媒体的大量报道，美国参议院下属能源和商务委员会在2017年3月末启动对 CVE 项目的调查。

参议院之所以有权调查 CVE 项目的运行情况，是因为 MITRE 从美国国土安全部国家网络安全处获得运行 CVE 数据库的资助。

本周一，经过对 CVE 项目长达一年的调查后，能源和商务委员会向美国国土安全部和 MITRE 公司发出多份信函。委员会在信函中说明了调查结果以及对修复 CVE 系统中存在的问题提出了一些解决方案。

  问题1：资助缺乏连续性且数额减少

信函中提到，“从2012年到2015年，项目受到的资助数额平均同比减少37%。”另外，“国土安全部和 MITRE 的文档显示，CVE 合同不稳定而且易受计划安排和资金的剧烈影响。”

为解决这个问题，委员会提议国土安全部官员将对 CVE 的资助从合同资助计划转移至国土安全部预算，作为 PPA（计划、项目或活动）资助线。

委员会认为这样做会为 CVE 系统提供持续的资助流，减少剧烈的预算波动，并能让 MITRE 持续运行 `CVE 数据库而非总是担心未来的资助问题。

问题2：缺乏监管

第二，委员会还发现 CVE 项目缺乏监管。

信函中提到，“管理 CVE 项目的历史实践显然是不够的。除非取得重大进展，否则它们可能会再次引发问题，对整个社会利益相关者产生直接的负面影响。”

委员会建议国土安全部和 MITRE 进行两年一次的审查，以确保项目未来的稳定性和有效性。这些审查的目的是在问题渗入下游的网络安全行业之前发现它们。
