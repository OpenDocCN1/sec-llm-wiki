# 谷歌用两款开源利器发现压缩库 Libarchive 漏洞可导致代码执行，影响 Linux 和 BSD 发行版本

**漏洞概述**

![](../Images/5527f40c330689a5beebb77ca9eb59d4.png)

Libarchive 库用于读取并创建压缩文件。它是一款强大的用户处理存档文件的多合一工具包，同时捆绑了其它 Linux/BSD 实用程序（如 tar、cpio 和 cat），这使得它成为各种操作的理想选择，也成为被操作系统广泛使用的原因所在。上周，多个 Linux 和 FreeBSD 发行版本推出更新，其中包括向用户推出的 Libarchive 版本的补丁，这使得影响该库的一个重大bug 详情曝光。该 bug 的编号是 CVE-2019-18408，是一个释放后使用漏洞，允许攻击者通过恶意存档文件在用户系统上执行代码。该漏洞的利用场景包括用户从攻击者或使用 Libarchive 多种文件解压组件的本地应用中接受恶意文件。虽然该漏洞早在6月份就已被修复，但补丁到达所有操作系统还需要花一定的时间。该漏洞已在 Libarchive 3.4.0中修复。

**不影响 Windows 和 macOS**

![](../Images/5527f40c330689a5beebb77ca9eb59d4.png)

易受攻击的使用 Libarchive 的操作系统和软件实用程序非常庞大，为恶意人员提供了一个巨大的攻击面，包括桌面和服务器操作系统、数据包管理器、安全实用程序、文件浏览器和多媒体处理工具。大家耳熟能详的大品牌如 pkgutils、Pacman、CMake、Nautilus、KDE’s ark 和 Samba 都受影响。虽然受影响的操作系统已经推出更新解决所报告的漏洞问题，但其它应用中 Libarchive 的补丁状态目前尚不可知。幸运的是，当前最流行的两大操作系统 Windows 和macOS 并未受影响，否则该漏洞将成为令全球用户头疼的问题，就像今年春天早些时候出现的已存在19年之久的 WinRAR 漏洞那样。截止本文发稿前，并未出现该漏洞的 PoC 或任何在野利用尝试。谷歌的两款开源利器地址：

*   OSS-Fuzz: 

https://github.com/google/oss-fuzz

*   ClusterFuzz: 

https://github.com/google/clusterfuzz
