# 90天期限后，影响 phpMyAdmin 所有版本的0day 详情和 PoC遭公开

**安全研究员兼渗透测试员**** Manuel Garcia Cardenas ****发现并公开了最流行的**** MySQL ****和**** MariaDB ****数据库管理应用程序之一**** phpMyAdmin ****中一个未修复**** 0day ****漏洞的详情和**** PoC****。**

PhpMyAdmin 是一款管理MySQL 和 MariaDB 的免费开源工具，广泛应用于管理通过 WordPress、Joomla和很多其它内容管理平台创建的网站数据库。

Cardenas 指出，该漏洞是一个跨站点请求伪造 (CSRF) 缺陷，可导致经验证用户执行不必要的动作。该漏洞的编号为 CVE-2019-12922，严重程度为中危（CVSS评分4.3分），因为它仅允许攻击者删除受害者服务器上 phpMyAdmin 控制台设置 (Setup) 页面中配置的任意服务器。

大家不必过于担心该漏洞的危险，因为攻击不允许攻击者删除存储在服务器上的任意数据库或表格。

攻击者实施攻击需要做的就是向已经登录到同样浏览器 phpMyAdmin 面板的目标 web 管理员发送一个构造的 URL，诱骗他们毫无戒心地通过一次点击就删除已配置服务器。

Cardenas 解释称，“攻击者可轻易创建一个包含希望以用户身份执行的请求的虚假超链接，以此希望借助错误的 HTTP 使用方法来执行 CSRF 攻击。”

不过该漏洞易于利用，因为攻击者只需要知道目标服务器的 URL 就能实施攻击，而无需了解其它信息如数据库的名称等。


该缺陷影响4.9.0.1 及以上版本的 phpMyAdmin 版本。4.9.0.1 版本是当前的最新版本。Cardenas 表示，该缺陷还存在于于2019年7月发布的 phpMyAdmin 5.0.0-alpha1 中。

Cardenas 早在2019年6月份就发现了这个漏洞，并负责任地将其告知项目维护人员。然而，phpMyAdmin 维护人员未能在90天期限内修复该漏洞，因此 Cardenas 决定在9月13日公布漏洞详情和 PoC。

**修复建议**

![](../Images/4a75e8e17d7911cca4b2e63d39f8a6c4.png)

要修复该漏洞，Cardenas 建议“在每次调用中实现对令牌变量的验证，和在其它 phpMyAdmin 请求中所做的一样”。

在漏洞修复前，强烈建议网站管理员和托管提供商不要点击任何可疑链接。
