刚刚，思科更新其 IOS XE 操作系统，修复了一个 CVSS v3评分为10分的严重漏洞，它可导致远程攻击者绕过运行过时虚拟服务容器版本设备上的身份验证。
虚拟服务容器用于在隔离环境中运行进程，它们通常是开放的虚拟应用程序 (OVA) 数据包，能够运行适用于多种目的的应用程序。管理员能够为该设备配备故障排除工具以及实现常见的网络功能或分析和监控的工具。它的常见用途是扩展主机网络的功能。

严重漏洞，无缓解措施

该漏洞的编号是CVE-2019-12643，它的 CVSS v3 评分为满分10分，存在于思科操作系统的 REST API 虚拟服务容器中。
受该缺陷影响的产品如下：

  • Cisco 4000 Series Integrated Services Routers

  • Cisco ASR 1000 Series Aggregation Services Routers

  • Cisco Cloud Services Router 1000V Series

  • Cisco Integrated Services Virutal Router

如果仅向目标设备发送恶意 HTTP请求就满足特定条件，则漏洞可被利用。如果管理员进入 REST API 接口，则攻击者可获取“token-id”并以提升权限运行命令。
除了需要验证管理员身份外，目标设备同时需要启用是易受攻击的思科 REST API 虚拟服务容器版本。
网络管理员应该安装 RESTAPI 虚拟设备容器的16.09.03 版本 (“iosxe-remote-mgmt.16.09.ova”)，修复该漏洞。对于项目客户而言，思科发布了 IOS XE 软件的加固版本，禁止安装或激活易受攻击的容器设备。
思科在安全公告中指出，目前尚不存在缓解措施，且并未发现漏洞遭滥用的情况。

高危和中危漏洞

思科在安全公告中还发布了影响联合 Unified Computing System (UCS) Fabric Interconnect、FXOS、NX-OS和Nexus 9000 Series Fabric Switches 的9个高危和中危漏洞。
其中4个高危漏洞存在于NX-OS 软件中：2个可导致未认证的远程攻击者使设备崩溃 (CVE-2019-1962)，或者导致 netstack 进程异常重启 (CVE-2019-19624)；另外2个可使登录的攻击者重启 SNMP 应用程序 (CVE-2019-1963) 或当远程连接终止时，通过阻止虚拟shell (VSH) 进程删除而耗尽系统内存 (CVE-2019-1965)。
高危漏洞存在于思科Fabric Interconnect 中，编号为 CVE-2019-1966，可将本地权限提升至根权限级别。攻击者可利用“local-mgmt 上下文中为特定 CLI 命令提供的外部子命令选项”。
思科在安全通告中发布的所有漏洞都是由思科内部团队在进行安全测试时发现的，或者在解决客户支持案例时发现的。
