系统管理员用于管理远程基于 Unix 系统（如 Linux、FreeBSD 或 OpenBSD）的 web 应用程序 Webmin 中被曝存在后门机制。

该后门机制可允许远程攻击者以 root 权限在运行 Webmin 的机器上执行恶意命令。一旦机器遭攻陷，攻击者将攻击通过 Webmin 管理的系统。

超百万 Webmin 工具易受攻击

不算Webmin 管理的设备，该攻击的攻击面也是巨大的。Webmin 团队在GitHub 上表示，该应用“的全球安装量已超过100万次”。Shodan 搜索查询显示出21.5万个公开的 Webmin 实例，而无需攻陷内部网络或绕过防火墙即可攻击这些实例。

Webmin 项目本身因为其便捷性在 Linux 系统管理员中及其受欢迎。系统管理员可以在一台服务器上安装 Webmin，之后通过 web 浏览器修改远程 Unix 系统。

这些修改并非只是基础的磁盘配额更新以及启动或停止一些守护进程。Webmin 可允许系统管理员修改 OS 设置和内部设置，创建新用户，甚至是更新在远程系统上运行的 app 的配置如 Apache、BIND、MySQL、PHP、Exim 等等。

该项目在Linux 生态系统中非常庞大，扩展其核心功能的模块超过100个，支持所有的主流发行版本以及分支项目如 Virtualmin 和 Usermin。

如何发现 Webmin 后门

然而，尽管Webmin 如此流行，但Webmin 代码中的后门仍然在该项目的源代码中隐藏了一年多的时间。

土耳其的安全研究员Ozkan Mustafa Akkus 在本月初从 Webmin 源代码中发现了一个漏洞。该漏洞可导致未认证攻击者在运行 Webmin app 的服务器上运行代码。该漏洞的编号是 CVE-2019-15107，他在 DEF CON 27 安全大会上发布了自己的研究成果。（详情见文末。）

不过，在如此高规格的大会上发布该成果后，其他研究人员也开始深挖一款非常流行的 Linux 工具中的一个非常危险的安全缺陷。于是，在上周末他们又有了新发现。

Webmin 甩锅“遭攻陷的版本基础设施”

Webmin 的一名开发人员指出，该漏洞并非是编程错误，而是“注入遭攻陷的版本基础设施中的恶意代码”。

该恶意代码仅存在于通过 SourceForge 下载的 Webmin 数据包中，GitHub 页面中并不存在该漏洞。然而，这并未降低该问题的影响，因为 Webmin 网站将 SourceForge 链接列为官方下载 URL。

Webmin 团队也并未说明，该“遭攻陷的版本基础设施”是否为用于创建代码的受攻陷的开发者设备，还是遭攻陷的 SourceForge 账户被攻击者用于将恶意 Webmin 版本上传到 SourceForge 上。

SourceForge 公司的董事长表示，黑客并未利用平台上的任何漏洞，而 SourceForge 仅托管了项目管理员通过账户上传的版本。

默认安装的 Webmin 版本不受影响

Akkus 在最初发布的技术分析文章中指出，该漏洞存在于 Webmin 的一个功能中。该功能可使 Webmin 管理员为 Webmin 基于 web 的账户执行密码过期策略。

如果启用该Webmin 功能，则攻击者能够借此通过在发送到 Webmin 服务器的一个 HTTP 请求中使用“|”字符来添加shell 命令的方式接管Webmin 安装程序。

Webmin 团队表示，所有从 Sourceforge 平台上下载的 1882 到1921 之间的版本都包含该恶意后门代码。

Webmin 版本1930 于8月18日发布，删除了该后门机制，这也意味着存在后门的 Webmin 版本已在2018年3月以来的一年多的时间里被下载了数十万次。

好在Webmin 的默认下载版本并未默认启用密码过期功能。Webmin 管理员必须修改 Webmin 配置文件才能启用密码过期功能，也就是说多数 Webmin 安装程序都不易遭利用。

但糟糕的是，攻陷Webmin 版本基础设施的黑客似乎已尝试更改 Webmin 1890 版本中的密码过期功能的默认状态，该版本默认为所有 Webmin 用户开启该功能。

然而，这种草率的修改导致错误发生，Webmin 管理员为此回滚到此前的默认状态。

Webmin 团队在安全公告中表示，“不管从哪方面来讲，强烈建议更新至版本1930。如果运行的是1900至1920之间的版本，则编辑 /etc/webmin/miniserv.conf，删除 passwd_mode= 一样，之后运行 /etc/webmin/restart。”

利用该漏洞的唯一条件是必须启用 webmin 中的“用户密码更改”功能。人很多 webmin 管理者都启用了该功能，允许用户设置新密码。

当搜索webmin 应用时，Akkus注意到一些耐人寻味的“.cgi”文件。其中一个文件是“password_change.cgi”。 

该文件中该参数起作用的唯一要求是，“minister.conf”配置文件的 “passwd_mode” 值设为 “2”。

$miniserv{'passwd_mode'} == 2 || die "Password changing is not enabled!"; 

那么，管理员如何激活该配置呢？我们来看一下。

在 "Webmin>Webmin Configuration> Authentication" 部分，勾选“提示密码过期的用户输入新密码”。也就是说“minister.conf”中的“password_change”值被设为“2”。



配置完成后，用户能够通过验证旧密码的方式更改过期密码。那么漏洞到底在什么地方呢？我们回到“password_change.cgi”。


“password_change.cgi”将旧密码发送到 “acl/acllib.pl” 的 “encrypt_password” 函数中。该函数调用另外一个函数“unix_crypt”。

在另外一个部分，同样的函数“unix_crpt”再次被调用，以“验证旧密码”。

这时，我们将通过在验证旧密码过程中读取影子文件的方法使用“竖线 (|)”。我们先来通过 burp suite 发送一个请求。


我们以普通的“POST”数据发送一个请求，并给出错误“密码更改失败：当前密码不正确”。该漏洞就存在于“旧”参数中。不管用户名是什么，旧密码或其它信息是正确的。文件“password_change.cgi”将检查服务器上“旧”参数的信息，它甚至不会检查用户名是否正确。我们将使用“竖线 (|)”尝试在服务器上运行一个不同的命令。

命令“ifconfig”被服务器执行并输出结果。现在我们向服务器发送一个恶意 payload并接受 shell 会话。Akkus 使用“netcat”payload 作为证据，原因是他知道服务器上存在netcat。

结果成功获得shell。当访问命令“pwd”时，可以看到该恶意payload 在“acl”文件夹中被执行，原因是该函数在此处被调用。
