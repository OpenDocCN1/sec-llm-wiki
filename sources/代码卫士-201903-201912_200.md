# 新型 HTTP/2 缺陷导致未修复 Web 服务器易遭 DoS 攻击

**HTTP/2 ****协议的多种实现都易受攻击，消耗足够资源，在未修复服务器上引发拒绝服务条件。**攻击者可通过利用支持 HTTP/2 通信的服务器上的多个漏洞触发该攻击。 W3Techs 数据显示，当前互联网上40%的网站都支持HTTP/2 通信协议。

**多种变体**

![](../Images/eaf6789fd2bd14eec93974a6376b7eeb.png)

当前，触发这种拒绝服务条件的漏洞共有8个。多家厂商已经修复系统解决这些问题。这些漏洞可遭远程客户端利用，其中一些漏洞可从单一的终端系统遭利用，影响多个服务器，要更为严重。然而其它漏洞可用于 DDoS 攻击。其中7个欧东是Netflix 公司的研究员Jonathan Looney 发现的，另外1个是由谷歌公司研究员Piotr Sikora 发现的。这8个漏洞是：CVE-2018-9511 数据流 (Data Dribble)：攻击者通过多个流从制定资源请求大量数据。它们操纵窗口大小和流优先级来强制服务器以1字节块的形式对数据进行排队。根据此数据排队的效率，这样做可能会消耗更多的 CPU、内存或消耗两者，从而导致拒绝服务。CVE-2019-9512 Ping 洪水:攻击者向 HTTP/2 对等体发送连续 ping，导致对等体建立内部响应队列。根据此数据排队的效率，它可消耗过多的 CPU、内存或消耗两者，从而可能导致拒绝服务。CVE-2019-9513 资源循环：攻击者创建多个请求流并以一种导致优先级树大量流失的方式不断地改变流的优先级。这样做可能会导致消耗过多的 CPU，从而导致拒绝服务。CVE-2019-9514 重置洪水：攻击者打开多个流，并在每个流上发送无效请求，该请求应从对等方请求 RST\_STREAM 帧流。根据对等体如何对 RST\_STREAM 帧进行排队的情况，可能导致内存、CPU 或两者消耗过度，从而可能引发拒绝服务。CVE-2019-9515 设置洪水：攻击者向对等体发送SETTING帧流。由于 RFC 要求该对等体对每个SETTING 帧进行确认，因此空SETTING 帧在行为上几乎等同于 ping。根据该数据排队的效率，它可能导致 CPU、内存或两者被消耗过多，从而导致拒绝服务。CVE-2019-9516 长度为0的标头泄漏：ttacker发送带有长度为0的标头名称和长度为0的标头值的标头，可选择将霍夫曼编码为1字节或更大的标头。某些实现为这些标头分配内存并使分配在会话终止前保持活跃状态。它可导致内存被过多消耗，从而引发拒绝服务。CVE-2019-9517 内部数据缓冲：攻击者打开HTTP/2 窗口，以便对等体可以无限制发送；但是，它们可使 TCP 窗口关闭，因此对等体实际上无法在线路上写入（许多）字节。之后，攻击者发送大量响应对象的请求流。根据服务器对响应进行排队的方式，可能会导致过多的内存、CPU 或二者被过多消耗，从而导致拒绝服务的后果。CVE-2019-9518 空帧洪水：攻击者发送payload 为空且没有流终端标志的帧流。这些帧可以是 DATA、HEADERS、CONTINUATION 和/或PUSH\_PROMISE。对等体花费时间处理和攻击带宽不成比例的每个帧，从而导致 CPU 被过度消耗，进而导致拒绝服务。

**供应商发布补丁**

![](../Images/eaf6789fd2bd14eec93974a6376b7eeb.png)

Netflix 公司在一份安全公告中指出，所有的攻击向量都是同一种主题的变体，客户端触发源自易受攻击服务器的响应，之后拒绝读取。根据从服务器管理这些队列的方式，客户端之后可强制服务器过度使用内存和 CPU 处理进入的请求。DoS 攻击可导致服务器无响应并拒绝访问者访问网页。在不太严重的情况下，页面加载需要更长的时间。CERT协调中心的漏洞记录表明，多家供应商可能受这些 DoS 漏洞的影响，如亚马逊、Apache、苹果、Facebook、微软、nginx、Node.js 和 Ubuntu。其中很多供应商已经修复了这些问题。Cloudflare 发布了影响其中7个负责HTTP/2 通信协议的Nginx 服务器漏洞。CloudFlare 公司指出，已经发现攻击者正在利用这些漏洞，不过尚未大规模传播。在漏洞公开前，CloudFlare 及其它供应商提前从 Netflix 收到关于这些 DoS 安全风险的通知。微软也发布了补丁，修复影响 HTTP/2 协议栈 (HTTP.sys) 的5个漏洞。Nginx发布更新主线版本1.17.3的更新变更日志，通知用户修复其中3个 DoS 漏洞。稳定版也更新至1.16.1，修复这些漏洞。苹果公司也修复了影响 SwiftNIO 应用程序框架的5个缺陷，它们影响自Sierra 10.12 版本以后的 macOS 版本。
