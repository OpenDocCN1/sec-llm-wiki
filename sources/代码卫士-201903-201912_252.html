微软刚刚发布7月份的补丁星期二安全更新，其中发布了1个安全通告、一个服务栈更新以及77个漏洞的安全更新。在这77个漏洞中，15个被评估为“严重”级别。值得注意的是，微软此次修复了5个被公开披露但未遭利用的 0day 以及2个已遭在野利用的 0day。用户应尽快安装更新以免遭风险。

2个已遭利用的 0day

微软修复了2个已遭利用的 0day，它们可导致程序以最高权限级别运行。

第1个0day 是“CVE-2019-1132 – Win32k权限提升漏洞”，是由 ESET 公司的资深恶意软件研究员 Anton Cherepanov 发现的。

微软在公告中对该漏洞的描述为，“当 Win32k 组件未能正确处理内存中的对象时，会造成 Windows 系统中产生权限提升漏洞。成功利用该漏洞的攻击者能够在内核模式下运行任意代码。攻击者之后可以安装程序；查看、更改或删除数据；或以完整的用户权限创建新账户。要利用该漏洞，攻击者首先必须登录系统，之后运行特殊构造的应用程序以便利用该漏洞，最后即可控制受影响系统。安全更新通过修正了 Win32k 处理内存中对象的方式修复了这个漏洞。”


鉴于 Cherepanov 是 ESET 公司的恶意软件研究员，因此该漏洞可能是在感染过程或类似情况下被发现的。Cherepanov 表示后续将提供更多详情。

第2个已遭利用的0day 是“CVE-2019-0880 – 微软 splwow64权限提升漏洞”，是由 ReSecurity 公司的研究员 Gene Yoo 发现的。该公司曾在3月份发现了思杰 (Citrix) 公司被黑。目前该研究员尚未作出任何置评。

微软在公告中对该漏洞的描述为，“splwow64.exe 处理某些调用时触发了一个本地提权漏洞。成功利用该漏洞的攻击者能够将受影响系统上的权限从较低级别的完整性提升为中等级别的完整性。该漏洞本身并无法导致任意代码执行；然而，如果攻击者结合使用其它漏洞（如远程代码执行漏洞或另外一个提权漏洞）则可在尝试执行代码时导致提权，从而导致任意代码执行。”


5个遭公开披露的 0day


微软还发布了5个已遭公开的漏洞补丁。不过微软表示它们并未遭在野利用。

这5个漏洞中包含谷歌 Project Zero 团队研究员 Tavis Ormandy 因微软未在规定期限内修复而公开的一个 SymCrypt DoS 漏洞。它们是：

  • CVE-2019-0865：SymCrypt 拒绝服务漏洞

微软在报告中指出，“SymCrypt 以不正确的方式处理了一个特殊构造的数字签名，触发拒绝服务漏洞。攻击者可通过创建一个特殊构造的连接或信息利用该漏洞。”

该漏洞影响的产品为 32位系统和基于x64 系统的Windows 10 版本1703；32位系统、基于 ARM64系统和基于x64系统的 Windows 10 版本1709；32位系统、基于 ARM64系统和基于 x64 系统的 Windows 10 版本1803；32位系统、基于 ARM64 系统和基于 x64 系统的 Windows 10 版本1809；32位系统、基于 ARM64 系统和基于 x64 系统的 Windows 10 版本1903；Windows Server 2019；Windows Server 2019（服务器核心程序）；Windows Server 版本1803（服务器核心程序）和Windows Server 版本1903（服务器核心程序）。


  • CVE-2018-15664：Docker 提权漏洞

报告指出，“Docker运行时（以及底层社区项目 Moby）中存在一个漏洞，恶意/受攻陷容器能够在容器运行时获取对主机操作系统完整的读/写访问权限。该漏洞依靠的是 Docker 运行时处理符号链接的方式以及可通过 Docker 复制 API（Docker CLI 中的 ‘dockercp’）遭直接利用。”

  • CVE-2019-0962：Azure 自动化提权漏洞

微软在报告中指出，“Azure Automation具有贡献者 (contributor) 角色的用户 ‘RunAs账户’ 操作手册中存在一个提权漏洞，可导致组织机构成员即使在没有访问权限的情况下通过操作手册访问 Key Vault 机密信息。要利用该漏洞，攻击者必须是组织机构中能够运行操作手册的成员，只有全局 admins/co-admins 能够创建 ‘runas’ 账户。”

  • CVE-2019-1068：微软 SQL 服务器远程代码执行漏洞

报告指出，“微软 SQL 服务器不正确地处理内部函数时会触发远程代码执行漏洞。成功利用该漏洞的攻击者能够在 SQL 服务器数据库引擎服务账户上下文中执行代码。要利用该漏洞，认证攻击者需要向受影响的 SQL 服务器提交一个特殊构造的查询请求。”

该漏洞影响的产品包括：Microsoft SQL Server2014 Service Pack 2 for 32-bit Systems (CU+GDR)、Microsoft SQL Server 2014 Service Pack 2 for 32-bit Systems (GDR)、Microsoft SQL Server 2014 Service Pack 2 for x64-based Systems (CU+GDR)、Microsoft SQL Server 2014 Service Pack 2 for x64-based Systems (GDR)、Microsoft SQL Server 2014 Service Pack 3 for 32-bit Systems (CU+GDR)、Microsoft SQL Server 2014 Service Pack 3 for 32-bit Systems (GDR)、Microsoft SQL Server 2014 Service Pack 3 for x64-based Systems (CU+GDR)、Microsoft SQL Server 2014 Service Pack 3 for x64-based Systems (GDR)、Microsoft SQL Server 2016 for x64-based Systems Service Pack 1 (CU+GDR)、Microsoft SQL Server 2016 for x64-based Systems Service Pack 1 (GDR)、Microsoft SQL Server 2016 for x64-based Systems Service Pack 2 (CU+GDR)、Microsoft SQL Server 2016 for x64-based Systems Service Pack 2 (GDR)、Microsoft SQL Server 2017 for x64-based Systems (CU+GDR) 和Microsoft SQL Server 2017 for x64-based Systems (GDR)。


  • CVE-2019-1129：Windows 提权漏洞

报告指出，“当 AppXSVC 不正确地处理硬链接时会发生提权漏洞。成功利用该漏洞的攻击者能够在提权上下文运行进程。之后攻击者能够安装程序；查看、更改或删除数据。要利用该漏洞，攻击者首先必须登录系统，之后运行特殊构造的应用程序以利用漏洞并控制受影响系统。”

受影响产品包括：32位系统和基于x64 系统的Windows 10 版本1703；32位系统、基于 ARM64系统和基于x64系统的 Windows 10 版本1709；32位系统、基于 ARM64系统和基于 x64 系统的 Windows 10 版本1803；32位系统、基于 ARM64 系统和基于 x64 系统的 Windows 10 版本1809；32位系统、基于 ARM64 系统和基于 x64 系统的 Windows 10 版本1903；Windows Server 2019；Windows Server 2019（服务器核心程序）；Windows Server 版本1803（服务器核心程序）和Windows Server 版本1903（服务器核心程序）。


修复 SandboxEscaper 提交的0day

另外，微软还修复了“CVE-2019-1130 –Windows 提权漏洞”。它是由女黑客SandEscaper （别名：Polar Bear）提交的。SandEscaper 一反过去率先公开 Windows 0day 的做法，这次看似是私下提交给微软了。

微软对该漏洞的描述为，“当 Windows AppX 部署服务 (AppXSVC) 以不正确的方式处理硬链接时会导致提权漏洞产生。成功利用该漏洞的攻击者能够在提权上下文中运行进程，随后即可安装程序；查看、更改或删除数据。要利用该漏洞，攻击者首先需要登录系统，随后即可运行特殊构造的应用程序以利用该漏洞并控制受影响系统。安全更新通过修正 Windows AppX 部署服务处理硬链接的方式修复了该漏洞。”
