**影响**

![](../Images/bfc76ca72be125103db176f03a87fb37.png)

未认证攻击者如成功实施攻击，则可持久地将 JavaScript payload 注入 Magento 商店的管理员后端。如被触发，该 JavaScript payload 能够在受害者浏览器中执行自动化利用步骤。如下视频以基于 JavaScript 的 RIPS shell 的形式将这些利用步骤进行可视化。

当商店员工登录到该管理员仪表盘时，被注入的 JavaScript payload 运行并劫持该员工的管理会话。随后，经认证的远程代码执行漏洞遭利用，从而导致商店遭全面接管。攻击者随后可对运行该商店的公司造成进一步的经济损失。例如，攻击者可以将所有付款重定向至自己的银行账户或窃取信用卡信息。

如果 Magento 商店使用了这个内置的核心 Authorize.Net 支付模块（它是 Visa 支付方案，允许清理信用卡付款），那么这些漏洞就能够被利用。需要注意的是，Authorize.Net 中并不包含其中任一漏洞，而是 Magento 的实现中存在。由于 Authorize.Net 是一款热门的信用卡支付清理服务，因此这一利用链影响很多 Magento 商店。鉴于我们很容易测试某个目标商店是否使用了 Authorize.Net 模块，而且可以自动测试，因此可能出现大规模利用的情况。

我们认为该利用链的严重程度为**高**，因为无需任何储备知识或访问 Magento 商店，也无需任何社工，攻击者即可利用它。鉴于所有 Magento 商店的年交易额超过1550亿美元，因此攻击者极有可能利用这类漏洞。

**技术分析**

![](../Images/bfc76ca72be125103db176f03a87fb37.png)

在下文中，我们分析了可链接的两个独立的安全漏洞。鉴于问题的严重程度，我们故意省略了某些利用详情。

**未认证的存储型**** XSS**

Magento 提供了多种不同的清理方式。本节将详细说明绕过清理方法escapeHtmlWithLinks() 以及这种绕过如何导致取消新产品订单时产生未认证存储型 XSS 漏洞。

在正式讨论之前，我们先来了解一下 Magento 的清理  (sanitization) 方法以及其主要的清理方法 `escapeHTML()`:

![](../Images/678c457f7719c18b064da72948a9994e.png)

对于 `escapeHTML()`，只需知道它解析用户输入 (`$data`) 并删除所有未在用户输入字符串中第二个参数 $allowedTags 中未明确的所有 HTML 即可。如果第二个参数未设置，那么整个用户输入字符串会被转义。另外，该方法仅允许在每个允许标记中设置一些 HTML 属性，如 id、class、href、style等。

我们并未提出 `escapeHTML()``的绕过，因此搜索了对通过``escapeHTML() ``清理``后的用户输入起作用的代码，因为修改清理``后的数据通常会导致漏洞的产生。我们发现了`escapeHtmlWithLinks() 方法。我们将通过下一段内容和片段解释该方法如何起作用以及该方法中存在的一个逻辑缺陷如何可导致 XSS 漏洞的产生。

escapeHtmlWithLinks() 的目的是从用户输入字符串中删除白名单标记集以外的所有 HTML 标记。它和escapeHTML()的不同之处在于，它将从用户输入字符串中的<a>标记中删除除href属性以外的所有属性以便让链接变得更加安全。

escapeHtmlWithLinks() 通过用户输入字符串中响应的%s替换掉所有的<a>标记后，它将最终的用户输入传递给 escapeHTML()，从而安全地清理用户输入（下一个片段中的第172行）。然而，它之后会将清理后的链接通过vsprintf()插入已清理的字符串。而 XSS 漏洞正是在此处产生。接下来我们讨论一下这个 XSS 漏洞到底是如何起作用的。

![](../Images/93325af5d0b984b829c4bacaa7e69265.png)

 

如上表可见，<a>标记被%1s所取代，而用户输入字符串之后被清理。由于%1s并非危险值，因此它通过了清理步骤。当 escapeHtmlWithLinks()将清理后的链接通过vsprint()重新插入后，又有一个双引号被插入<i>标记中，从而导致属性注入问题。

攻击者可以在生成的字符串中注入任意 HTML 属性。注入恶意onmouseover 事件清理程序以及样式属性，使链接成为整个页面上的不可见覆盖。一旦受害者访问包含此类 XSS payload 的页面并移动鼠标时，就会触发 XSS payload。

 `escapeHtmlWithLinks() ``方法用于清理用户通过`` Authorize.Net ``启动订单流程但随后取消的订单取消通知。通过滥用以上提到的绕过，攻击者能够将任意`` JavaScript ``注入刚刚取消的订单的订单预览中。当用户查看已取消订单时，就会触发`` XSS payload``。`
