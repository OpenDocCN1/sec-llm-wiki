微软管理控制台被曝 XXS 和 XXE 漏洞，可导致设备遭接管

Check Point 研究人员 Eran Vaknin 和 Alon Boxiner 表示，微软管理控制台 (MMC) 中存在多个 XSS漏洞和一个 XXE 漏洞（编号统一为 CVE-2019-0948），可导致攻击者安装恶意 payload，甚至是接管目标权限设备。

MMC 可允许系统管理员以管理员级别配置并监控系统。研究人员指出，“MMC 的目的是提供创建和托管负责管理微软 Windows 环境的编程平台并提供简单、持续的集成管理用户接口和管理模型。”这些漏洞披露于本周一。受攻陷的计算机将提供一系列权限功能和访问的权限。

这些问题包括多个跨站点脚本 (XSS) 漏洞和一个 XML 外部实体 (XXE) 漏洞。一系列缺陷包括存在于 WebView 中的多个 XSS 漏洞。研究人员表示，攻击者能够滥用MMC 中的“snap-in”机制利用这些 bug。MMC snap-in 是平台提供的真正的管理工具。该控制台有时候被职位“工具主机”，它是添加 snap-in 的框架。Snap-in 包括 ActiveX Control、Link to Web Address 等。

如何利用漏洞

要利用这个漏洞，攻击者需要创建一个 snap-in 文件（.msc 为文件扩展），其中包括特殊构造的 XML 内容，之后说服认证用户使用任何社工技术导入文件。

研究人员解释称，如果攻击者通过 Link to Web Address snap-in 创建文件，则可将 URL 链接插入自己的服务器中，从而将受害者定向至带有恶意 payload 的 HTML 页面。

研究人员还指出，“受害者打开恶意的 .msc 文件时，就会打开 WebView（位于 MMC 窗口内），之后就会执行恶意 payload。我们成功地设法插入一个包含恶意 payload 的恶意 URL 链接，如重定向至将捕获用户 NTLM 哈希的 SMB 服务器。另外，也有可能通过之前提到的 WebView 在受害者主机上执行 VBS 脚本。”

同样，攻击者可选择通过 ActiveX Control snap-in 创建文件，且将其保存为一个 .msc 文件。研究人员解释称，“在 .msc 文件中，在 StringsTables 部分，攻击者将第三个字符串值改为受控制的恶意 URL，其中包含带有恶意 payloadde HTML 页面。”

该CVE 中还包括因默认 XML 解析器造成的一个 XXE 漏洞。

研究人员表示，“受害者打开 MMC并选择时间查看器 snap-in 并点击‘Action’，之后点击‘Import Custom View’。从受害者主机中选择的任何包含 XXE  payload 的恶意 XML 文件就被发送给攻击者。”

微软在安全公告中将其归类为中危信息泄漏 bug，“Windows 时间查看器 (eventvwr.msc) 中存在一个信息泄漏漏洞，当其不正确地解析包含对外部实体引用的 XML 输入时就会产生。成功利用该漏洞可经由 XXE 声明读取任意文件。”

微软在六月份的补丁星期二中修复了这些问题。

可导致设备遭接管

然而，Vaknin 和 Boxiner 表示这些漏洞可导致更加严重的后果，而不仅仅是信息泄漏问题。

研究人员指出，“最引人注目的是，MMC 文件由 IT管理员使用，杀毒软件不会将这些文件归为恶意内容，因此攻击者可能利用这些漏洞控制受害者电脑。”该电脑将具有管理员状态，导致攻击者渗透至网络。

Windows 7、Windows 8.1、Windows 10 和 Windows Server 2008 至 Windows Server 2019 均易受攻击，因此应及时更新。目前尚未发现漏洞遭利用的情况。
