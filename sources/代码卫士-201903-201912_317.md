# 谷歌公开大宕机事件原因

**谷歌发布了关于****6****月****2****日发生的“灾难性”大宕机事故的技术详情报告。该事件导致多种服务宕机事件长达****4****个半小时，影响**** YouTube****、****Gmail****和谷歌云用户如**** Snapchat****和****Vimeo****。**

大宕机事件回顾可参见本公号发布的文章：

**[突发！Google Cloud、YouTube、Snapchat 等服务大面积瘫痪，原因不明](http://mp.weixin.qq.com/s?__biz=MzI2NTg4OTc5Nw==&mid=2247490090&idx=1&sn=fdc14cb271cd06427de8e20ab93b89d7&chksm=ea972b40dde0a256024e6123a462420168f7446ef2cea16dbd2cb495e0c577d4de04afbfd79e&scene=21#wechat_redirect)  
**

本周早些时候，谷歌工程副总裁 Benjamin Treynor Sloss 向客户道歉，承认服务恢复的时间要比预想的“长的多”，而这种宕机是由于配置错误导致的，结果使 YouTube 流量下降10%，谷歌云存储流量下降30%。同时还影响超过1亿名 Gmail 用户。

谷歌发布技术详情报告说明了受影响的客户群体，以及为何谷歌工程师在几分钟内检测出的配置错误会导致4个半小时的服务宕机，主要使北美地区的用户受影响。

谷歌在技术详情报告中指出，“客户可能会遇到更多的延迟、间歇性错误以及和us-central1、us-east1、us-east4、us-west2、northamerica-northeast 1 和 southamerica-east1 实例的连接丢失。Us-west11、以及所有欧洲地区和亚洲地区的谷歌云实例并未出现区域网络拥堵情况。”

这些区域受影响的谷歌云平台服务包括Google Compute Engine、App Engine、Cloud Endpoints、Cloud Interconnect、Cloud VPN、Cloud Console、Stackdriver Metrics、Cloud Pub/Sub、Bigquery、区域性Cloud Spanner 实例、以及Cloud Storage 区域存储桶。这些地区的 G Suite 服务也受影响。

谷歌再次向客户道歉，并表示已采取“立即措施”提升性情和可用性。

受影响的大牌客户包括 Snapchat、Vimeo、Shopify、Discord 和 Pokemon GO。

**配置出错和软件bug 导致大宕机**

![](../Images/3a93cbf5e7ec0b56c46dee8380bcead9.png)

简单解释而言，旨在某地区的一小撮服务器的配置更改被错误地适用于多个相邻区域的更多服务器中，导致受影响区域使用的能力不到平时的一半。  

谷歌表示，自动化软件中出现一个 bug，也是大宕机事件的一个原因，“两个正常情况下非恶意的错误配置和一个特定的软件 bug导致大宕机：首先，网络控制平面任务和其支持的受影响区域的基础设施被配置为在维护时间下停止服务的状态。第二，运行网络控制平面的集群管理软件的多个实例被标记特定的、相对少见的维护时间类型的合法包含。第三，启动维护事件的软件中存在一个特定错误，允许其同时解决多个独立的软件集群，即使这些集群位于不同的物理位置也是如此。”

至于网络能力下降的问题，谷歌表示在这种情况下保护网络可用性的方法“导致服务和用户观测到的网络能力严重下降，以及某些 Google Cloud 区域不可访问。”

Sloss 指出，谷歌工程师“在事件发生后的两分钟内”就检测到了情况并予以响应。然而，新报告指出，调试“遭严重故障，原因是大量工具在争着使用当前已非常拥堵的网络失败。”

**服务恢复措施和后续计划**

![](../Images/3a93cbf5e7ec0b56c46dee8380bcead9.png)

尽管谷歌拥有大量资源和备份计划，但还采取了多项措施，如“工程师前往旨在抵御多数灾难性失败的安全设施”等。  

另外，谷歌通信工具受损，导致工程师识别对客户的影响能力受阻，从而限制了他们和客户准确沟通的能力。

谷歌目前已暂停使用其负责在维护期间重新调度任务的数据中心自动化软件。在确保它不会同时在多个物理位置取消任务计划后才会重新启用该软件的使用。

谷歌还计划审查其相应工具和程序，以确保这些工具能够应对类似网络失败情况且能够和客户获得准确通信。谷歌表示，验证仍然还处于“相对较早的阶段”，未来将可能识别出更多的动作。

谷歌表示，“将审查、更新并测试谷歌的紧急响应工具和程序，以确保它们能够应对此类网络失败，包括和客户群进行通信的工具。另外，我们将把持续的灾难恢复测试机制扩展到包含这种情况和其它类似灾难性失败的范围。”

至于影响情况，受影响最严重的服务是位于美国西部地区的 Google Cloud Storage，存储桶的出错率为9.2%，其次是南美东部，出错率为79.3%。

Google Cloud Interconnect （谷歌云互联）受到严重影响，受影响地区的报告丢失率为10%至100%。
