0day！远程桌面服务 0day 可导致会话遭劫持，微软近期不修复

研究人员发现一个新0day，可导致攻击者劫持现有的远程桌面服务会话，获取对计算机的访问权限。该 0day 可被用于绕过 Windows 设备的锁屏，即使双因素认证如 Duo Security MFA 开启也不例外。组织机构可能设置的其它登录配置也可遭绕过。

本不应如此

该 0day 的CVE 编号是 CVE-2019-9510，被指为使用可选路径或频道的认证绕过。

卡内基梅隆大学软件工程学院的 CERT 协调中心刚刚发布安全通告警告称，会话锁定能够以异常方式在远程桌面会话使用 NLA 的最新 Windows 系统上行动。

即使用户专门在 RDP 会话过程中锁定了 Windows 设备，如果会话被临时断开，那么自动重新连接会把会话恢复为未锁定状态，“不管远程系统是如何被留下的”。该0day 影响 Windows 1803起的 Windows 10 以及 Server 2019 或更新版本。

攻击场景

CERT/CC 的漏洞分析师 Will Dorman 描述了如下攻击场景：

1. 用户连接到远程 Windows 10 1803或Server2019或使用 RDP 的更新系统

2. 用户锁定远程桌面会话并将客户端设备留下

3. 能够访问这台客户端设备的攻击者能够破坏其网络连接并在无需任何凭证的情况下访问远程系统

攻击者之后能够破坏 RDP 客户端的网络连接，从而导致网络重新连接并绕过 Windows 屏幕锁定。这样做可导致本地攻击者在远程桌面会话结束时获取对未锁定计算机的访问权限。也就是说该漏洞极易遭利用，因为攻击者仅需破坏目标系统的网络连接即可。不过由于攻击者需要获得对目标系统的物理访问权限（如锁定屏幕的活跃会话），该场景本身导致攻击面不会太过扩大。

Dormann 表示，“通过破坏系统的网络连接，能够访问被当作 Windows RDP 客户端的系统的攻击者可获取对联网远程系统的访问权限，不管远程系统是否遭锁定。”

Dormann 表示，“它可能不太真正会遭利用，但确实是一种异常行为。”

无补丁

CVE-2019-9510 是由卡内基梅隆大学软件工程学院的 Joe Tammariello 发现的，严重程序评分为4.6（总分为10）。

微软已于4月19日获悉该 0day，回复称，“该行为不满足微软Windows安全服务标准”，也就是说微软并未打算近期修复。完整声明如下：

“调查该场景后，我们认为这种行为并不符合微软 Windows 安全服务标准。您所观测到的是 Windows Server 2019 中的网络层认证 (NLA)。NLA 要求在最早期的连接阶段通过用户凭证进行连接。这些凭证也被用于用户会话登录（或重新连接）。只要网络被连接，客户端将会在需要自动重新连接时缓存所使用的凭证以连接并重用，以绕过 NLA。”

研究人员指出，用户可通过锁定本地系统而非远程系统的方式，或通过断开远程桌面会话而非仅锁定会话的方式避免遭该漏洞影响。

BlueKeep 缓解措施不受影响

当 BlueKeep (CVE-2019-0708) 漏洞的详情遭公开时，微软表示，开启 NLA 是对抗该“蠕虫式”恶意软件的缓解因子。

这种临时解决方案依赖的是 NLA 要求在触发该漏洞前进行认证，因此攻击者需要合法凭证才能访问易受攻击的系统。

即使 CVE-2019-9510 更改了 NLA 的行为，但这种影响并未出现在受 BlueKeep 影响的版本 Windows 7 和 Server 2008 系统上。NLA 仍然是可靠的安全功能。这个 RDS 0day 展现的是一种异常行为，管理员应该意识到它在更新 Windows 版本上产生的结果。

BlueKeep 是一种严重漏洞，可导致 Windows 操作系统远程代码执行问题。它影响远程桌面服务，使得它在部署蠕虫式恶意软件时非常具有吸引力。

安全研究人员已经开发出 PoC，网络犯罪分子应当不久就会跟上。易受 BlueKeep 漏洞影响的系统多达100万左右，而与此相对的 web 扫描活动还在增加。

从安全研究员 Daniel Gallagher 控制的 RDP 蜜罐中收集的数据来看，针对易受 BlueKeep 攻击的计算机扫描活动呈现上升趋势。
