# 华为苹果三星等均受影响：博通 WiFi 驱动被曝漏洞，可导致 RCE 和 DoS

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzI2NTg4OTc5Nw==&mid=2247489762&idx=2&sn=74a7aa82de7def2e844ab6dff1b8d8ff&chksm=ea972988dde0a09ea4b42144f922c135a00541345ddaec391449eab29d100efd6db339677bfc&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzI2NTg4OTc5Nw==&mid=2247489762&idx=2&sn=74a7aa82de7def2e844ab6dff1b8d8ff&chksm=ea972988dde0a09ea4b42144f922c135a00541345ddaec391449eab29d100efd6db339677bfc&scene=27#wechat_redirect)

**DHS/CISA ****发出警告且**** CERT/CC ****漏洞说明指出，博通**** WiFi ****芯片集驱动被指包含多个漏洞，影响多个操作系统，可导致潜在攻击者远程执行任意代码并触发拒绝服务。**

Quarkslab 公司的实习生 Hugues Anguelkov 在逆向工程并模糊测试博通 WiFi 芯片固件时，发现并报告了从“博通 wl 驱动和博通 WiFi 芯片集开源 brcmfmac 驱动”中找到的五个漏洞。

他发现“博通 wl 驱动易受两个堆缓冲溢出漏洞影响，而开源的 brcmfmac 驱动易受一个框架验证绕过和一个堆缓冲溢出漏洞影响。”

按照 CWE-122 的描述，堆缓冲溢出可导致系统崩溃或导致受影响软件进入无限循环，同时导致攻击者“执行通常不在程序安全策略范围内的任意代码”。

Anguelkov 在分析中指出，“你几乎可从任何地方看到这些芯片，如智能手机、被基本电脑、智能电视和物联网设备等不一而足。你可能不知不觉地在使用它，例如如果你使用的是一台戴尔电脑，那么你使用的可能是 bc43224 或 bcm43552 卡。如果你是用的是 iPhone、Mac 笔记本、三星手机或华为手机等，那么你可能在使用博通 WiFi 芯片。由于这些芯片的使用范围如此之广，因此是攻击者的高价值目标，这些芯片中的任何漏洞都应被认为具有高风险。”

Trent Novelly 在CERT/CC 漏洞备注中指出，潜在的远程未验证用户可能通过发动恶意构造的 WiFi 数据包的方式利用博通 WiFi 芯片集驱动漏洞，在易受共计的机器上执行任意代码。然而，Novelly 认为，“更典型的场景是，这些漏洞将导致拒绝服务攻击。”

Anguelkov 也证实了这一点，他指出，“其中两个漏洞同时存在于 Linux 内核和博通芯片固件中。最常见的利用场景将导致远程拒绝服务。尽管从技术方面存在苦难，但远程代码执行并非最糟糕的场景。”

CERT/CC 漏洞备注说明了其中的四个博通 wl 驱动漏洞（CVE-2019-8564、CVE-2019-9500、CVE-2019-9501、CVE-2019-9502 和 CVE-2019-9503）：

**存在于开源 brcmfmac 驱动中的漏洞**

![](../Images/b05eefbcf4ca72facc4321f42d888219.png)

•CVE-2019-9503：如果brcmfmac驱动程序从远程源接收固件事件帧，则is\_wlc\_event\_frame函数将导致该帧被丢弃而不被处理。如果驱动程序从主机接收固件事件框架，则调用适当的处理程序。如果使用的总线是USB（例如通过wifi加密狗），则可以绕过该帧验证，可允许处理来自远程源的固件事件帧。

•CVE-2019-9500：如果配置了无线局域网唤醒功能，则可以构造恶意事件框架以在brcmf\_wowl\_nd\_results函数中触发堆缓冲区溢出。受损的芯片组可以利用此漏洞来破坏主机，或者当与上述帧验证旁路结合使用时，可遭远程利用。

注：brcmfmac驱动程序仅适用于Broadcom FullMAC芯片组。

**存在于博通 wl 驱动中的漏洞**

![](../Images/b05eefbcf4ca72facc4321f42d888219.png)

这两个漏洞可在客户端解析访问点4次握手中的 EAPOL 信息3时触发。

•CVE-2019-9501：通过提供数据长度大于32字节的供应商信息元素，在wlc\_wpa\_sup\_eapol中触发堆缓冲区溢出。

•CVE-2019-9502：如果供应商信息元素数据长度大于164字节，则在wlc\_wpa\_plumb\_gtk中触发堆缓冲区溢出。

注：当wl驱动程序与SoftMAC芯片组一起使用时，这些漏洞将在主机内核中触发。使用FullMAC芯片组时，这些漏洞将在芯片组的固件中触发。

共计166家供应商在使用易受攻击的博通 WiFi 芯片集，具体见 CERT/CC漏洞备注文末 (https://www.kb.cert.org/vuls/id/166939/)。

从 Anguelkov 发布的披露时间轴来看，博通在2019年2月14日修复了FullMAC 卡中开源 brcmfmac Linux 内核无线驱动中的两个漏洞。

苹果也修复了 CVE-2019-8564 漏洞，作为 macOS Sierra 10.12.6、macOS High Sierra 10.13.6 和 macOS Mojave 10.14.3 的安全更新的一部分。苹果公司在4月15日也就是早于研究人员公开该漏洞的一天前发布了该问题的说明。

除苹果和博通公司以外，唯一一个提供漏洞状态详情的一家公司是 Extreme Networks。该公司在4月9日发布的一份声明中指出，“对于 VU#166939 而言，WiNG 无线产品并未受影响，因为我们并未使用受影响的芯片集或驱动”。
