苦熬10年后，证明我是对的：终于有杀软大厂修复了这个漏洞

四家反病毒提供商已发布补丁，修复了 Thierry Zoller 早在2009年就已经详述的一个问题。
Zoller早在2009年发布报告称，该 bug 在于攻击者能够构造可由用户访问但无法被反病毒产品扫描的压缩文档。

影响程度

Zoller解释称，该缺陷并非指单个文档格式，指的是用户能够修改压缩文档导致杀毒软件无法访问它。文档格式的类型多样，包括ISO、ZIP和Bz2。
该 bug 对客户端的影响较小，因为用户可以在提取后检查该文件，但对任何邮件网关或反病毒基础设施影响严重，原因是文档无法被自动压缩检查其内容。
距离首次发现该 bug 的10年后，Zoller 决定重新查看该问题并评估杀毒软件厂商在产品中的解决方式。他还将问题告知厂商。
但结果让人失望：该 bug 不仅被忽视，而且他最近联系的某些厂商对他提交的漏洞报告并不积极。
2019年11月，该 bug 被滥用于通过邮件传播恶意软件的攻击活动中而再次引发关注。

厂商反应不同

Zoller在博客中表示，受影响的厂商如下：
  • F-Secure
  • Avira
  • Mcafee
  • Securecomputing
  • Ikarus
  • Nod32
  • Bitdefender
  • Trendmicro
  • Panda
  • Computer Associates (CA)
  • Comodo
  • AVG
  • Sophos
  • Avast
Zoller表示，该bug 影响多家厂商的多款产品，包括Avira、Bitdefender、ESET 和卡巴斯基等公司。他指出，“影响的严重程度取决于该产品和引擎在客户所在机构组织中的上下文使用情况。网关产品（邮件、HTTPProxy 等）可能允许文件在未经扫描的情况下通过并认为它是健康的。服务器端的杀毒软件可能无法从该ZIP 文件中发现任何代码或样本，因此即使确切知道自己在寻找的东西也不会引起怀疑。”
受影响的 ESET 产品遍布各大平台，包括 Smart Security Premium、Internet Security、NOD32 Antivirus、Cyber Security Pro (Mac)、Cyber Security (Mac)、Mobile Security forAndroid、SmartTV Security 和NOD32 Antivirus 4 for Linux Desktop。该问题已在该文档的解压模块版本1294中修复。
卡巴斯基已为四款产品推出补丁，包括Kaspersky Secure Connection 4.0 (2020)、Internet Security 2020、Total Security 2020 和 Security Cloud 2020。
卡巴斯基实验室表示，“我们还在和 ZIP 文档协作的其中一款反病毒引擎组件中修复了三个bug，主要是修正了该组件在反病毒扫描特殊构造的ZIP 文档的情况下的行为。这些恶意文档可用于规避我们的反病毒扫描进程。这些bug 影响具有反病毒数据库的卡巴斯基产品。”
虽然这两家厂商快速修复了该缺陷，并向Zoller 致谢，但Avira 和Bitdefender 并非如此。Zoller表示，Avira从一开始就拒收该漏洞报告。经过一个月的沟通之后且和该公司的首席信息官联系之后，才静默发布了补丁。
而 Bitdefender 虽然证实该 bug 的存在，原先发布了3个 CVE 和一个补丁，但之后撤回补丁和 CVE 编号。然而，该厂商在12月份静默修复了该问题而且时隔数周之后在反复沟通之后才向Zoller 表达谢意。

问题澄清

Zoller还针对人们对该bug 的一些偏见做出说明，如下：
偏见1、 有人认为该bug 和向ZIP 文件添加密码产生的影响一样，因此不是安全问题。
Zoller 指出，网关扫描器明确标记出有密码的文档，如邮件网关扫描器在主题行或另外一个地方添加“未扫描附件”。因此它表明文件并未扫描，因此用户清楚必须额外谨慎。但它和绕过的情况不同，扫描引擎并不会说明未扫描附件，在多数情况下引擎根本不会扫描内容或者以其它方式扫描。另外，有密码保护的文档文件可根据内容策略轻易过滤，因此用户能够控制它是否通过还是拒绝，而它和绕过的情况也不同。
简言之，绕过是恶意软件/蠕虫作者传播代码的理想方式，也是躲避网关扫描器的更有效方式，它们可以长期不被检测到并且将代码植入企业更深处。
2、有人认为绕过问题仅存在网关产品中。
未由终端用户主动提取文档的每个环境均受影响，如文件服务器、数据库等。另外多年来我见到很多受该“bug”影响的最奇怪的环境。我认为客户值得拥有更好的安全性。
3、有人认为它并非漏洞，因为如果网关被绕过的话，那么客户端的反病毒软件将会在文档提取上发现恶意软件。
这种看法危险地假定所有的发病毒扫描器会检测到某种特定的恶1意软件（但事实上并非总是如此，看看virustotal.com的数据就知道了）。多数企业为获得最佳结果会结合使用多种厂商的产品。想象一下这种场景：
（1）    网关本来已经检测到恶意代码（通过签名或启发式）但被绕过；
（2）    客户端杀毒软件并未检测到该样本，因为后者并不具备签名
（3）    ??opps
做企业杀毒软件解决方案的人都知道这种情况非常常见，并不罕见。如果你想要证据，那么看看virustotal的数据就知道了。
4、 行为分析会检测到这种情况吗？
不能，内容无法由杀毒软件引擎读取，因为不存在这类检查机制。
5、 它们不是安全问题，只是一些bug。
如果你读到这里仍然有这种想法，那么注意一下我发布的安全公告(见原文链接）中从未包含任何风险评估，原因就在于我无法评估在客户的某个特定环境中运行的应用程序的风险情况。因此我把绕过的风险问题抛给他人来解决。NIST 对绕过的风险评估是CVSS 5分到10分；XForce 也对绕过做评估而 Secunia 对绕过的评估为低危。
Zoller指出，“2019年报告漏洞的曲折过程让人惊讶，同时让人惊讶的是漏洞奖励平台如何可能被用于封杀报告和/或研究人员的情况。这些平台的条款和用途为研究人员和厂商之间的关系又增加了新的变数。”
