# 麻省理工研究员发现苹果 M1 CPU 中无法修复的新缺陷

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzI2NTg4OTc5Nw==&mid=2247512281&idx=3&sn=1bae3c23b647e073efcb6df3fa15dcce&chksm=ea9481b3dde308a5b6ece11817a148a6d20a38c366288e9c3183f774bd4a6768612fac6f33cb&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzI2NTg4OTc5Nw==&mid=2247512281&idx=3&sn=1bae3c23b647e073efcb6df3fa15dcce&chksm=ea9481b3dde308a5b6ece11817a148a6d20a38c366288e9c3183f774bd4a6768612fac6f33cb&scene=27#wechat_redirect)

麻省理工学院的多名研究员发布论文表示，发现一个名为 “PANMAN” 的硬件攻击，恶意人员可借此攻击苹果的M1处理芯片集，在macOS 系统上获得执行任意代码的能力。  
  

PACMAN 利用“推断性执行攻击绕过重要的、用于执行指针完整性的内存防护机制 ARM Pointer Authentication（ARM 指针认证机制）。”

更令人担忧的是，“虽然 PACMAN 使用的硬件机制无法通过硬件特性进行打补丁，但可修复内存损坏漏洞。”

PACMAN 根植于指针认证代码 (PACs) 中，这些代码是在arm64e架构中引入的防御措施，旨在检测并防护对内存中指针（存储内存地址的对象）异常变化的情况。

PACs 旨在解决软件安全中的常见问题如内存损坏漏洞等。恶意人员常通过覆写内存（如指针）中的控制数据利用这些漏洞，将代码执行重定向到受攻击者控制的任意位置。

虽然人们通过地址空间布局随机化（ASLR）等策略来提高执行缓冲区溢出攻击的难度，但PACs 的目标是确保“最小化大小和性能影响的指针的有效性”，从而阻止恶意人员创建 exploit 中使用的有效指针。

完整性通过加密哈希（指针验证代码，PAC）保护指针来实现。苹果对PAC的解释为：“指针验证通过提供特殊CPU指令，在存储指针前，将加密签名或PAC添加到指针未使用的高阶位。另外一个指令在从内存读取指针后删除并验证该签名。修改写入和读取之间的存储值使签名无效。CPU将验证失败解读为内存损坏并在指针内设置高阶位，使指针无效并导致应用程序崩溃。”

但PACMAN “删除了在通过指针验证保护的平台上执行控制流执行攻击的主要障碍。”它结合内存损坏和推断性执行规避该安全特性，“通过微架构侧信道攻击泄露PAC验证结果，而不会触发任何崩溃”。

简言之，该攻击方法能够区分正确的PAC和不正确的哈希，使得恶意人员能够“暴力攻击正确的PAC值，同时挂起崩溃，在启用PA的受害者程序或操作系统上构建控制流劫持攻击。”

通过Prime+Probe 攻击的变换先行缓冲器，利用定时侧信道攻击可推断性猜测出每个PAC值，从而成功阻止崩溃。

如在 Spectre 和 Meltdown 攻击中观测到的推断性执行漏洞那样，这种漏洞利用了乱序执行技术。这种技术用于通过预测程序执行流最可能的路径，改进现代微处理器的性能。

然而，值得注意的是，该威胁模型假设受害者程序（内核）中已经存在一个可利用的内存损坏漏洞，而它反过来可导致低权限攻击者（恶意app）将恶意代码注入受害者进程中的某些内存位置中。

研究人员总结称，“该攻击对于执行具有指针验证机制的未来处理器的设计者而言，具有很重要的意义，对于未来的控制流完整性原语的安全性而言，具有广泛的意义。”
