# Gmail 邮件AMP 特性中的XSS 漏洞价值5000美元

**Gmail 的动态邮件特性AMP 中存在一个跨站点脚本 (XSS) 漏洞，研究员为此获得5000美元的奖励。**

AMP for Email 使富文本的交互性邮件拥有AMP 功能。AMP本身是一个开源HTML框架，用于优化手机上的网站web浏览性能。

Adi Cohen 发现了该漏洞，他表示在AMP中找到触发XSS的向量并不难，但绕过Gmail的XSS过滤器的难度很大。

  

**渲染上下文**![](../Images/458d49604ea5f4bc7949543f20b2796f.png)

  

Cohen 在博客文章中指出，“规避XSS过滤器的最容易的方法是，诱骗过滤器位于不同的渲染上下文而非浏览器将真正用于渲染既定代码的上下文中。”由于用于邮件的AMP 禁止模板、SVG、math 和CSS，而是将样式表作为具有多种渲染上下文的XSS payload 的潜在路径。这就要求该样式表被过滤器和浏览器渲染的方式不同，或者“诱骗过滤器相信虚假的样式标记是真实的”或“相信完全相反的情况”。

Cohen 的初始向量在沙箱中是起作用的，因为AMP“在CSS 上下文遇到 ‘</style’ 字符串时就会离开CSS上下文，即使并不存在右中括号(>)或至少在其后存在一个空格。”之后，他能够“诱骗过滤器相信我们又返回 HTML 上下文，而浏览器显然完全忽视了 </styleX>，并完好地处于CSS管控下”。

  

**Substance 上的</styl>**![](../Images/458d49604ea5f4bc7949543f20b2796f.png)

  

Cohen 表示，“AMP中看似很好的向量，在Gmail 上就没有那么管用。”不过他通过一个CSS 筛选器迎来了突破，确保Gmail 返回的 payload 是未更爱的，“不存在逃逸或其它变种”。

然而，当AMP沙箱遇到 ’</styl>’ 时，恶意payload 提示出错，因此 Cohen 尝试了</styl>，但Gmail的过滤器将其视作</style>的相似体。起作用的是测试具有编码筛选器的非恶意payload，因为Gail 对其解码，因此他可以使用该筛选器注入一个关闭标签。

2021年3月27日，Cohen 将漏洞报告Gmail，后者在7月7日将其修复。

谷歌此前曾在2019年修复了用于 Email 的AMP 中的XSS 漏洞，研究员Michal Bentkowski 利用标签中的id 属性发动了 “DOM clobbering”攻击。
