# Drupal 修复第三方库Guzzle 的多个“高危”缺陷

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzI2NTg4OTc5Nw==&mid=2247512301&idx=1&sn=f13cc63071db6f27fb31c7ef38d91a90&chksm=ea948187dde3089134cbd061aca2d4429d9d7cfbc97455eb652fac7f38843bd09997c8713c3b&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzI2NTg4OTc5Nw==&mid=2247512301&idx=1&sn=f13cc63071db6f27fb31c7ef38d91a90&chksm=ea948187dde3089134cbd061aca2d4429d9d7cfbc97455eb652fac7f38843bd09997c8713c3b&scene=27#wechat_redirect)

Drupal 安全团队发布安全公告，提醒用户关注第三方库 Guzzle 中的两个严重漏洞（CVE-2022-31042和CVE-2022-31043），提醒称黑客可利用这些漏洞远程劫持受 Drupal 驱动的网站。  
  

这两个漏洞位于 Guzzle 中。Drupal 使用该第三方库处理 HTTP 请求和对外部服务做出响应。

Drupal 安全公告指出，“这些漏洞不影响 Drupal 核心，但可能影响 Drupal 站点上的某些项目或自定义代码。”公告指出，“我们在常规安全发布窗口排期之外发布该安全公告，是因为 Guzzle 已发布关于这些漏洞的信息，而漏洞可能存在于使用 Guzzle处理站外请求的模块或自定义模块中。”

Guzzle 将这些漏洞评级为高风险，Drupal 警告称这些漏洞可能影响 Drupal 站点上的一些项目或自定义代码。

该团队提醒称，“利用该漏洞可导致远程攻击者控制受影响网站。”Guzzle 发布独立安全公告，称这些漏洞未能除去主机或HTTP降级中变化的Cookie标头，且未能除去 HTTP 降级上的授权标头。

Drupal 安全团队建议用户安装最新版本（Drupal 9.2至Drupal 9.4）。值得注意的是，Drupal 早于 9.2.x 的 Drupal 9 版本已达生命周期，不会获得任何安全更新。
