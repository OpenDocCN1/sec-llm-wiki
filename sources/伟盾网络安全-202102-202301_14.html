02 调试后的思考

回顾刚才的调试，我们来看下org.mozilla.javascript.ScriptableObject#getImpl方法

    private Object getImpl(String name, int index, Scriptable start) {        ScriptableObject.Slot slot = this.getSlot(name, index, 1);        if (slot == null) {            return Scriptable.NOT_FOUND;        } else if (!(slot instanceof ScriptableObject.GetterSlot)) {            return slot.value;        } else {            Object getterObj = ((ScriptableObject.GetterSlot)slot).getter;            if (getterObj != null) {                if (getterObj instanceof MemberBox) {                    MemberBox nativeGetter = (MemberBox)getterObj;                    Object[] args;                    Object getterThis;                    if (nativeGetter.delegateTo == null) {                        getterThis = start;                        args = ScriptRuntime.emptyArgs;                    } else {                        getterThis = nativeGetter.delegateTo;                        args = new Object[]{start};                    }
                    return nativeGetter.invoke(getterThis, args);                } else {                    Function f = (Function)getterObj;                    Context cx = Context.getContext();                    return f.call(cx, f.getParentScope(), start, ScriptRuntime.emptyArgs);                }            } else {                Object value = slot.value;                if (value instanceof LazilyLoadedCtor) {                    LazilyLoadedCtor initializer = (LazilyLoadedCtor)value;
                    try {                        initializer.init();                    } finally {                        value = initializer.getValue();                        slot.value = value;                    }                }
                return value;            }        }    }


根据this.getSlot获取到的slot对象来判断，如果为null，则返回notfound，那如果不为空呢，继续往下走呢，我们现在就带着假设性思维来分析，不为空进入else if (!(slot instanceof ScriptableObject.GetterSlot))，如果获取的slot对象不是GetterSlot的实例，则进入else if方法返回slot.value，这个好像和命令执行也没啥关系，那还是得往下走，让slot为GetterSlot的实例，进入else代码块。

先是取出slot对象的getter成员变量赋值给getterObj，然后当getterObj不为null时，进入if判断。然后再次判断getterObj是否是MemberBox的实例，现在我们假设他是MemberBox的实例，进入if方法，将getterObj赋值给nativeGetter，如果nativeGetter.delegateTo为空，将start赋值给getterThis，然后空对象赋值给args，再往下走调用nativeGetter.invoke(getterThis, args)，看到这里好像有点希望，因为getter可控，所以nativeGetter可控，但是getterThis不可控，为NativeError对象，这个时候我们已经可以执行一些静态方法了，因为静态方法执行时，invoke传入任意对象都是可以的，前提是无参数的静态方法，因为args为空对象。但很显然，这个并不能满足我们执行命令的需求。

那我们目光再来转向else代码块

else {    Function f = (Function)getterObj;    Context cx = Context.getContext();    return f.call(cx, f.getParentScope(), start, ScriptRuntime.emptyArgs);}


将getterObj赋值给了f，f是Function对象，然后调用Function的call方法，这里的Function是一个接口，调用的是他的实现类，我们来看一下有哪些实现类


这里我们主要关注NativeJavaMethod类，看一下call方法是啥样的

    public Object call(Context cx, Scriptable scope, Scriptable thisObj, Object[] args) {        if (this.methods.length == 0) {            throw new RuntimeException("No methods defined for call");        } else {            int index = findFunction(cx, this.methods, args);            if (index < 0) {                Class<?> c = this.methods[0].method().getDeclaringClass();                String sig = c.getName() + '.' + this.getFunctionName() + '(' + scriptSignature(args) + ')';                throw Context.reportRuntimeError1("msg.java.no_such_method", sig);            } else {                MemberBox meth = this.methods[index];                Class<?>[] argTypes = meth.argTypes;                Object[] newArgs;                int i;                Class c;                Object varArgs;                Object wrapped;                if (meth.vararg) {                    ...                } else {                    ...                }

代码进行了一些省略，主要是当this.methods.length不为0，然后找到this.methods数组中的方法的下标数index，通过下标将this.methods[index]数组中的方法取出来赋值给meth变量，经过一系列判断会走到meth.invoke(javaObject, args)方法，这里感觉希望更大一点，如果meth和javaObject可控的话，那么是不是就可以执行任意对象的空参方法了。

因为meth来自this.methods数组，我们看一下methods是否可控


可以看到methods是可控的，而且没有使用transient修饰，是可以通过反序列化赋值的，那么方法可控的话，就看javaObject是不是可控的，如果该变量也可控的话，那么命令执行就能成立了

if (o instanceof Wrapper) {    javaObject = ((Wrapper)o).unwrap();    if (c.isInstance(javaObject)) {        break;    }}


当o对象是Wrapper的实例的时候，就会进入if代码块，o被赋值为thisObj，也就是NativeError对象，来看一下Wrapper的实现类中有没有NativeError


很显然，答案是没有。那么javaObject岂不是无法自定义了吗！别急，仔细观看代码可以发现该方法是处于while循环中，最后一行代码是o = o.getPrototype()，嗯？要是我们可以控制该方法的返回结果，设置为Wrapper的实现类，那么不就可以在第二次循环中进入if判断了吗。

我们来看一下getPrototype()是否可控，调用的是org.mozilla.javascript.ScriptableObject#getPrototype方法


可以看到prototypeObject是可以设置的，那么就是可控的，这样的话，那么我们要给prototypeObject设置为哪个对象才比较合适呢？从Wrapper实现类中，经过查看，发现只有NativeJavaObject能满足我们的需求


可以看到unwrap返回的javaObject是可以通过NativeJavaObject的构造方法进行赋值的，那么我们只要将getPrototype方法中的prototypeObject变量设置为带有恶意javaObject变量的NativeJavaObject对象，然后第二次循环时，即可满足if判断，再通过((Wrapper)o).unwrap()取出恶意的javaObject对象，即可自定义javaObject对象。

但是这里还有一个小问题要解决，可以看到if代码块中还有一个if判断，if (c.isInstance(javaObject)){break;}，这里需要满足该条件才能顺利走到下面的反射调用，不然会继续while循环，当第二次调用o.getPrototype()，会返回null，因为NativeJavaObject是没有getPrototype方法的，所以之后会进入if (o == null) { throw Context.reportRuntimeError3("msg.nonjava.method", this.getFunctionName(), ScriptRuntime.toString(thisObj), c.getName()); }，抛出异常导致程序终止，也就无法走到下面的反射调用了。

c变量是来自meth.getDeclaringClass()，meth是MemberBox对象，通过this.methods数组获取，所以是可以控制的，这里就拿TemplatesImpl恶意对象来举例，将TemplatesImpl的newTransformer方法设置到MemberBox对象中，newTransformer方法调用meth.getDeclaringClass()，返回的是TemplatesImpl的Class类对象，这时c.isInstance(javaObject)就成立了，可以满足判断。之后就可以调用meth.invoke(javaObject, args)。

但是到这里还没结束，因为meth是MemberBox，所以会进入MemberBox的invoke方法，我们看一下


可以看到从this.method()中获取method，然后就是经典的反射执行method，target已经是可控的了，只要method可控，那么就可以执行TemplatesImpl对象的newTransformer方法了，在这里是我们的假设下的推导。我们来看一下method()方法返回的是什么


可以看到method()的返回内容也是可控的，可以通过NativeJavaMethod去实例化一个MemberBox对象，构造方法传入恶意方法。下面我们来总结一下需要完成哪些条件才能执行命令。

小结：

  1. getSlot方法返回ScriptableObject.GetterSlot类型对象slot

  2. slot对象的getter变量值要为NativeJavaMethod方法

  1. NativeJavaMethod初始化时候要传入带有恶意的method方法，例如newTransformer

  2. o.getPrototype()需要返回NativeJavaObject对象

  1. NativeJavaObject对象初始化时需要传入恶意对象，例如TemplatesImpl对象
