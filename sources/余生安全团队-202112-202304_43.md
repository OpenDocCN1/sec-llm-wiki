# BurpSuite 多重代理

## 1\. 前言

### 1.1 遇到的问题

在某些特定的情形下，我们访问目标的网站需要走代理。举个例子，当我们访问 google.com 的时候已经给浏览器设置了 SS 代理（默认 127.0.0.1:1080），然而我们想对 google.com 进行渗透测试抓包（BurpSuite 默认设置 127.0.0.1:8080），这时不能简单的把浏览器代理设为 BurpSuite 的代理，因为那样虽然可以抓包，但是由于没有了 SS，我们是不能访问 google.com 的，抓包也就没有意义了。这时候该怎么办？

### 1.2 解决办法

如果遇到上述的情况，我们可以借助代理链进行解决。代理链就是一系列的代理形成的链条。

*   设置浏览器的代理为 BurpSuite 代理以便能够抓包
*   为 BurpSuite 再设置一个上游代理，也就是 SS 代理。
*   再访问 google.com 时，请求的数据会先经过 BurpSuite，这样实现了抓取数据包。然后数据再流向 SS，通过 SS 服务器到达 google.com。服务器端返回的响应则刚好相反。

通过上面的 BurpSuite-SS 代理链，就解决了我遇到的问题。

在 BurpSuite 的 User options 下的 Connections 页面中，有「Upstream Proxy Servers」和「SOCKS Proxy」这两个配置项，都是跟代理链相关的。这里推荐使用「SOCKS Proxy」，简单粗暴的话直接看 2.2 章节。

## 2\. 说明

### 2.1 Upstream Proxy Servers

该设置项中可以设置多个上游代理服务器规则，只要是满足规则的请求就会被发送至相应的代理服务器。下面还是以 google.com 为例进行说明。为了对 google.com 进行抓包分析，首先是需要设置浏览器的代理为 BurpSuite(127.0.0.1:8080)，这一点是毫无疑问的。为了能正常访问 google.com，还需要设置 BurpSuite 的上流代理为 SS(127.0.0.1:1080)。点击 Upstream Proxy Servers 列表框左侧的 Add 按钮，打开 Edit upstream proxy rule 对话框。

![](../Images/727a8839052c1d85ca43a85443831ba3.png)

打开后一共有 8 个设置选项，一般我们只关注前 4 个内容：

*   Destination host：这里填入目标网站域名或者 IP，支持通配符（\* 表示 0 个或者任意个字符，? 表示除点号之外的任意一个字符）。在本例中，我们可以填入 \*.google.com。
*   Proxy host：填入 SS 代理服务器的 IP 地址，即 127.0.0.1。如果为空表示直接连接。
*   Proxy port：填入 SS 的代理地址，即 1080。
*   Authentication type：这里选择认证类型，由于 SS 本地代理无需认证，这时选择 None。

如果 Authentication type 选择 None，那么后面的 4 项内容不用填写，否则需要根据实际情况填写以下 4 项内容。

*   Username：用户名。
*   Password：密码。
*   Domain：域。仅用于 NTLM 认证类型。
*   Domain hostname：域主机名。仅用于 NTLM 认证类型。

设置内容如下图所示，最后点击 OK 即可。

![](../Images/3bdcf6cdac759ebf66439ef6ead528d8.png)

完成以上的操作再对 google.com 进行访问时，就可以在 BurpSuite 上抓取到相应的请求报文了。我们也可以同时设置多个 Upstream Proxy Servers，在使用过程中，BurpSuite 会按顺序将请求的主机与 Destination host 中设置的内容进行比较，并将请求内容发送至第一个相匹配的 Proxy server。因此，Proxy Server 的顺序很重要。

### 2.2 SOCKS Proxy

与 Upstream Proxy Servers 的作用类似，SOCKS Proxy 的功能也是将请求内容发送至相应的代理服务器。而他们的不同之处在于，SOCKS Proxy 是作用在 TCP 协议层，所以如果设置了该项，那么所有的请求数据都会被发送至SOCKS 代理服务器。SOCKS Proxy 的设置更简单。同样以 google.com 为例，先在下方的输入框中依次填入 SOCKS 代理服务器的 IP、端口（如果 SOCKS 代理服务器需要认证，还需要填写用户名和密码），然后勾选 Use SOCKS proxy 即可（如果在未输入用户名和密码的情况是不能勾选的）。举个简单的例子，比如你 BurpSuite 的代理是 127.0.0.1:8080，而 vps 的代理是 127.0.0.1:1080，那么你只需要在 SOCKS Proxy 下配置 vps 的代理，让 BurpSuite 走 vps 的代理，也就是将 SOCKS proxy host 配置为 127.0.0.1，SOCKS proxy port 配置为 1080，然后打上 2 个钩即可。

![](../Images/bc0d15c59b38e0614e6625a1130cccbc.png)

配置好后访问百度输入 IP，发现此时百度返回的 IP 就是你 vps 的 IP 了。此外还需要注意的一点是，如果同时设置了 Upstream Proxy Servers 和 SOCKS Proxy，则根据规则应该发送至上游代理的请求将会通过 SOCKS Proxy 发送。
