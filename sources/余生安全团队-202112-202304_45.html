0x01 Web 基础之 Web 概述

如果要想学习 Web 渗透测试，首先就要了解有关 Web 的内容，本文对于 Web 基础中的概念进行了 Web 概述，当然 Web 的内容远不止这些，这里只做简单介绍。

1. Web 概述

1.1 Web 概念

Web（全称：World Wide Web) 是一种分布式应用架构，一种基于超文本 (HTML) 和 HTTP 协议的、全球性的、动态交互的、跨平台的分布式图形信息系统，目的是要分享 Web 服务器中相互链接的信息。

World Wide Web 是指全球范围内的 Web，由于叫起来复杂后面直接改叫 Web，它以 Internet 为网络，Internet 是世界上所有互联计算机和其它设备的集合。

1.2 Web 特征

Web 一般有三个特征:

  1. 使用超文本技术 HTML 来表达信息，建立信息和信息的联系
  2. 使用同一定位技术 URL 来进行信息的精确定位
  3. 网络应用层使用 HTTP 协议来进行浏览器和 Web 服务器之间通信

Web 采用 B/S 结构（Browser/Server，浏览器/服务器模式）的网络模式。Web 使用超文本技术来链接网络上的信息，信息存放在服务器端，客户机通过 Web 浏览器查找服务器上的信息。

1.3 Web 应用

1.3.1 Web 应用概念

Web 应用是多个 Web 资源的集合，是供浏览器访问的程序，也称为 Web 应用程序。一个 Web 应用由多个静态 Web 资源和动态 Web 资源组成。

  1. 静态资源：是指静态 HTML 页面的集合，所有用户访问后，得到的结果都一样无法实现和用户的交互。静态资源可以直接被浏览器解析，如：html,css,JavaScript。
  2. 动态资源：是指页面中的数据都由服务器程序产生，每个用户访问相同资源后，得到的结果可能不一样，具有交互性且页面的内容可以动态更新。动态资源被访问后，需要先转换为静态资源，再返回给浏览器，如：servlet/jsp,php,asp 等。

1.2.2 Web 应用举例

  • Webmail（网页邮件）
  • Online shopping（在线购物）
  • Wikis （维基百科）
  • Instant messaging（即时通信）
  • Internet forum（网络论坛、贴吧）
  • Blog（博客）
  • Web search engine（搜索引擎）
  • Browse game（网页游戏）
  • Webcam（网络摄像）

1.4 Web 的五大要素

1.4.1 URL

URL(uniform resource locator) 中文叫统一资源定位系统，是因特网的万维网服务程序上用于指定信息位置的表示方法。URL 可以由字母组成，如「baidu.com」，或 IP 地址：192.68.20.50。

URL 的规则为：scheme://host.domain:port/path/filename，比如一个实例是 http://www.baidu.com:80/upload/test.html

对各参数进行说明：

  • scheme：定义了因特网服务的类型，最常见的类型是 http 协议。
  • host：定义了域主机（http 的默认主机是 www）。
  • domain：定义了因特网域名，比如 baidu.com。
  • port - 定义主机上的端口号（http 的默认端口号是 80，可以省略）。
  • path - 定义了服务器上的路径（如果省略，则文档必须位于网站的根目录中且需要在配置文件中进行默认文件名的配置）。
  • filename - 定义了文档/资源的名称。

1.4.2 HTTP

HTTP 协议是 Hyper Text Transfer Protocol（超文本传输协议）的缩写，是基于 TCP/IP 通信协议用于从万维网（WWW:World Wide Web ）服务器传输超文本到本地浏览器的传送协议。

1.4.3 HTML（及 XML）

  • HTML：HTML 是 HyperText Markup Language（超文本标记语言）的缩写，是一种用于创建网页的标准标记语言。HTML 运行在浏览器上，由浏览器来解析，可以使用 HTML 来建立 Web 站点。可以理解为一种编程语言。
  • XML：XML 是 eXtensible Markup Language（可扩展标记语言）的缩写，被设计用来传输和存储数据。可以理解为一种传输格式。

1.4.4 Web 浏览器

Web 浏览器又叫叫网络浏览器，是一个显示网页服务器或档案系统内文件，并让用户与此些文件互动的一种软件。

常见的 Web 浏览器有：

  • Chrome
  • Firefox
  • Edge
  • IE
  • Safari
  • Opera

1.4.5 Web 服务器

Web 服务器一般指网站服务器，是指驻留于因特网上某种类型计算机的程序，可以处理浏览器等Web客户端的请求并返回相应响应，也可以放置网站文件，让全世界浏览；可以放置数据文件，让全世界下载。常见的 Web 服务器有 Apache、 Nginx 、IIS、Tomcat。

  1. Apache: 一个开放源码的网页服务器，可以在大多数计算机操作系统中运行，由于其多平台和安全性被广泛使用，是最流行的 Web 服务器端软件之一。它快速、可靠并且可通过简单的 API 扩展，将 Perl/Python 等解释器编译到服务器中。
  2. Microsoft IIS: IIS 是一种 Web 服务组件，其中包括 Web 服务器、FTP 服务器、NNTP 服务器和 SMTP 服务器，分别用于网页浏览、文件传输、新闻服务和邮件发送等方面，它使得在网络（包括互联网和局域网）上发布信息成了一件很容易的事。
  3. Tomcat: Tomcat 服务器是一个免费的开放源代码的Web 应用服务器，属于轻量级应用服务器，在中小型系统和并发访问用户不是很多的场合下被普遍使用，是开发和调试 JSP 程序的首选。实际上 Tomcat 是 Apache  服务器的扩展， Apache 为 HTML 页面服务，而Tomcat 实际上运行 JSP 页面和 Servlet，当然 Tomcat 和 IIS 等 Web 服务器一样，具有处理 HTML 页面的功能
  4. Nginx: Nginx 是一款是由俄罗斯的程序设计师开发的高性能的 Web 和 反向代理 服务器，也是一个 IMAP/POP3/SMTP 代理服务器。在高连接并发的情况下，Nginx 是 Apache 服务器不错的替代品。

1.5 Web 工作原理

用户通过 Web 浏览器发起 HTTP 请求，HTTP 请求通过互联网传递给了指定的 Web 服务器，Web 服务器解析请求后去数据库中获取相应的数据，再将获取到的数据（如：HTML 等文档）通过互联网返回给 Web 浏览器，Web 浏览器解析了数据内容并展示给用户。

4. 请求与响应

4.1 TCP 连接

4.1.1 什么是 TCP 连接

为实现数据的可靠传输，TCP 要在应用进程间建立传输连接。它是在两个传输用户之间建立一种逻辑联系，使得通信双方都确认对方为自己的传输连接端点。

4.1.2 TCP 连接过程

第一步：Client 向 Server 发出一个数据包并将 SYN 设置为 1 ，表示希望建立连接。这个包中的序列号假设是 X。第二步：Server 收到 A机器发过来的数据包后，通过 SYN 得知这是一个建立连接的请求，于是发送一个响应包并将 SYN 、ACK 标记都置为 1。假设这个包中的序列号是 y ，而确认序列号必须是 x+l ，表示收到了 发过来的 SYN，TCP 中， SYN 被当作数据部分的一个字节。第三步：A 收到 的响应包后需进行确认，确认包中将 ACK ，并将确认序列号设置为 y+ ，表示收到了来自B 的 SYN。

4.2 HTTP 请求

4.2.1 请求数据包

HTTP 的 request 请求数据包一般分为 3 部分，第一部分 request line， 第二部分叫 request header，第三部分是 body。要注意的是 header 和 body 之间有个空行。

METHOD /path-to-resource HTTP/Version-number
Header-Name-1: value
Header-Name-2: value

Optional request-body

Method 表示的是请求方法，比如常见的 POST 和 GET，Path-to-resoure 表示请求的资源，其中 Http/version-number 表示 HTTP 协议的版本号，而当我们使用 GET 方法的时候，body 是为空的。

4.2.2 负载均衡

负载均衡，英文名称为 Load Balance，其含义就是指将负载（工作任务）进行平衡、分摊到多个操作单元上进行运行，例如 FTP 服务器、Web 服务器、企业核心应用服务器和其它主要任务服务器等，从而协同完成工作任务。负载均衡构建在原有网络结构之上，它提供了一种透明且廉价有效的方法扩展服务器和网络设备的带宽、加强网络数据处理能力、增加吞吐量、提高网络的可用性和灵活性。

4.3 HTTP 响应

4.3.1 响应数据包

服务器端响应 HTTP 请求：

HTTP/Version-number status-code message
Header-Name-1: value
Header-Name-2: value

Optional response-body

第一部分：状态行，由 HTTP 协议版本号，状态码，状态消息三部分组成。第一行为状态行，（HTTP/1.1）表明 HTTP 版本为 1.1 版本，状态码为 200，状态消息为 (ok)。

第二部分：消息报头，用来说明客户端要使用的一些附加信息 第二行和第三行为消息报头，比如常见的有：

  • Date: 生成响应的日期和时间。
  • Content-Type: 指定了 MIME 类型的 HTML(text/html)，编码类型是 UTF-8。

第三部分：空行，消息报头后面的空行是必须的

第四部分：响应正文，也就是服务器返回给客户端的文本信息。

4.3.2 常见响应状态码

常见的响应状态码有：

状态码状态码中文描述状态码中文描述
200OK请求成功。一般用于 GET 与 POST 请求。
302Found表示临时移动。
400Bad Request客户端请求的语法错误，服务器无法理解。
404Not Found服务器无法根据客户端的请求找到资源。
500Internal Server Error服务器内部错误，无法完成请求。
502Bad Gateway从远程服务器接收到了一个无效的响应。

4.3.3 响应流程

当浏览器接收到服务器的响应报文后，首先会进行 HTML 解析，将字节流通过定义的编码格式转为字符流，然后根据 HTML 规范将字符分词，每个字符都有自己的属性和规则，最后将次元进行词法分析生成节点对象，将节点对象组成 DOM 树。此时如果遇见 JS 外链请求将阻塞 DOM 树的生成，遇见 CSS 和图片的外链则不会对其阻塞影响。

解析完 DOM 后则会触发 DOMContentLoaded 事件。

CSS 的解析步骤跟 DOM 一样，当计算完 CSS 样式后，两者会进行组合生成渲染树，渲染树会进行图像的绘制，此时如果全部文件已经加载完毕将触发 Loaded 事件。
