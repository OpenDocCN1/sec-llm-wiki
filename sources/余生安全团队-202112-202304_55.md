# Discuz!X 3.4 任意文件删除漏洞

## 1\. 漏洞说明

### 1.1 漏洞介绍

该漏洞通过配置属性值，可以造成任意文件删除，虽然原有的利用方式已经被修复，添加了对属性的 formtype 判断，但修复方式不完全导致可以绕过，通过模拟文件上传可以进入其他 unlink 条件，从而实现任意文件删除漏洞。

具体原理请参考：https://lorexxar.cn/2017/09/30/dz-delete/

### 1.2 影响版本

Discuz!X ≤3.4

## 2\. 漏洞环境

去 vulhub 上下载环境，https://github.com/vulhub/vulhub/tree/master/discuz/x3.4-arbitrary-file-deletion，或者将如下代码保存为 docker-compose.yml

```
version: '2'

4

"80:80"


```

执行如下命令启动 Discuz!X：

```

docker-compose up -d
```

![](../Images/a86a19be7fa863412ac03cf166083c61.png)

## 3\. 环境搭建

环境启动后查看机器 IP，浏览器中输入 IP 地址即可安装。

![](../Images/396fd8bce7b4387e31521d494f5be5aa.png)

一路下一步，在安装数据库处需要修改数据库服务器为 db，添上自己设置的管理员密码。

![](../Images/3256f845142bb6b54b697077f899417e.png)

接着就安装成功了。

![](../Images/2535831ea969ee2559be1785e89f7006.png)

## 4\. 漏洞复现

访问 `http://your-ip/robots.txt` 可以看到文件是存在的。

![](../Images/1dcf380fb070b60ecd54a454625131f4.png)

进入网站注册新用户，然后在个人设置页面找到自己的 formhash。

![](../Images/e7d44682618d4d0a3dff7dcedca1cd2f.png)

带上自己的 Cookie、formhash 发送如下数据包：

```


POST /home.php?mod=spacecp&ac=profile&op=base HTTP/1.1"formhash"

"birthprovince"

"profilesubmit"


```

提交成功之后，用户资料修改页面上的出生地就会显示成下图所示的状态：

![](../Images/a822595692a6618a24eca116a303fb07.png)

说明我们的脏数据已经进入数据库了。

然后，新建一个 `upload.html`，代码如下，将其中的 `[your-ip]` 改成网站的域名，`[form-hash]` 改成你的 formhash：

```

<body>"http://[your-ip]/home.php?mod=spacecp&ac=profile&op=base&profilesubmit=1&formhash=[form-hash]" method="post" enctype="multipart/form-data"
>type="file" name="birthprovince"
 />type="submit" value="upload"

 />
```

用浏览器打开该页面，上传一个正常图片，接着使用 BurpSuite 对上传的数据包进行拦截，并将 Cookie 的值修改为自己在网站下的 Cookie 信息。

![](../Images/91c2e659059f2ca3efdb0c745d2a984b.png)![](../Images/1fb28edece504193ba21bdf6a0f5e24e.png)

上面这一步非常的关键，不然就会被系统给拦截。

![](../Images/9e8bc52db744c30a68edf690d1441ef0.png)

此时脏数据应该已被提取出，漏洞已经利用结束。

再次访问`http://your-ip/robots.txt`，发现文件成功被删除：

![](../Images/7974fed1963ea358575ac9ac000c1b8e.png)

## 5\. 注意事项

1.  每次登录时 formhash 和 Cookie 都会刷新。
2.  上传文件时一定要加上自己的 Cookie。
