### Dotnet 结构解析

.net 的文件结构是基于PE结构的，可以说是对 PE 结构的一个扩展，主要是对 Text 节进行了魔改，使用 VS 编写一个 .net 程序使用 010 和 PEView 打开

读取 PE 文件 IMAGE\_NT\_HEADERS 中的 IMAGE\_OPTIONAL\_HEADER 的数据目录最后一项

![](../Images/818401ec3176aeb7bbe23bb797a8af86.png)

该 RVA 指向 IMAGE\_COR20\_HEADER 结构  

```
typedef structIMAGE\_COR20\_HEADER
{
ULONG cb;
USHORT MajorRuntimeVersion;
USHORT MinorRuntimeVersion;
// Symbol table and startup information
IMAGE\_DATA\_DIRECTORY MetaData;
ULONG Flags;
union{
DWORD EntryPointToken;
DWORD EntryPointRVA;
};
// Binding information
IMAGE\_DATA\_DIRECTORY Resources;
IMAGE\_DATA\_DIRECTORY StrongNameSignature;
// Regular fixup and binding information
IMAGE\_DATA\_DIRECTORY CodeManagerTable;
IMAGE\_DATA\_DIRECTORY VTableFixups;
IMAGE\_DATA\_DIRECTORY ExportAddressTableJumps;
IMAGE\_DATA\_DIRECTORY ManagedNativeHeader;
} IMAGE\_COR20\_HEADER;
```

其中 MetaData 表示了元数据的 RVA 和 SIZE

```
IMAGE\_DATA\_DIRECTORY
{
DWORD VirtualAddress；
DOWRD SIZE;
}
```

元数据的起始位置是一个 MetaData Root 结构

![](../Images/2b37145a641b49adc77077a4a3821b46.png)

lSignature 是一个魔术字符串“BSJB”，iVersionString 代表后面版本号字符串有多长  

![](../Images/abe58f464412dc5dc6e32549834b3586.png)

接着是一个 STORAGEHEADER 结构  

![](../Images/a0501ab8029c71f95d1256ded45158a5.png)

iStreams 表示有几个流  

往后是 STORAGESTREAM 结构用来描述这些流

![](../Images/5bbe6dd7fcbdd1c7dd1fb9d867e7d025.png)

iOffset 表示从元数据的起始也就是 BSJB 开始的偏移  

![](../Images/c20cc94714467747ea7b05634d31033d.png)

`30C+6C=378`，#~流的起始地址为 378  

378 处是一个 Metadata Table Stream 结构

![](../Images/0874847dc853509125b21a678f6c9dde.png)

该结构需要解析 Heaps 字段和 MaskValid 字段，Heaps 字段指定了后面索引的长度，MaskValid 字段表示一共有几个表，8 个字节可以表示 64 个表，但是 Dotnet 只定义了 45 个表  

![](../Images/f963a2ec76310b86cc613f26f4542093.png)

MaskValid 等于 `0x0900021547`，转换为二进制 `100100000000000000100001010101000111`  

对照表

![](../Images/67a093408cd9673858d3962b268bd962.png)

可知一共有十个表，打开 dnspy 将程序进行反编译  

![](../Images/348e8fbca173d070143a8900479bb8e0.png)

接着是一个数组，数组的长度等于表的数量，数组的内容是表示表中有多少项记录  

![](../Images/1ca24a489aee7bb4b1f6f43995585a51.png)

数值是与 dnspy 反编译后小括号中的值对应的，第一个 DWORD 表示 Module 表中有一项，第二个 DWORD 表示 TypeRef 表中有 0x12 个项，也就是 18 个项，以此类推……

Filed 表的定义:

![](../Images/c05560bd9b6b1c5b2e90420c2cb21bd4.png)

```
Typedef struct Filed
{

WORD Name；
WORD Signature；
}

```

Filed 表指的是类中的成员变量，Flags 字段表示该变量的一些属性，Name 代表相对于 `#String` 流的偏移，Signature 字段代表相对于 `#Blob` 的偏移，这里 Signature 表示的是加密后的类型，书中专门有一节讲 Dotnet 的一些表中 Signature 字段的含义:

### 后记

实际上所谓的混淆器都是混淆这些成员方法，常量名字，成员变量的名字，再加上一些控制流混淆和压缩加密技术就组合成了混淆器，貌似 dotnet 平台上有带虚拟机的壳……不过不是很常见，有兴趣的可以拜读一下 de4dot 程序看是如何脱壳的。壳这个东西啊，还是 win32 上面的叼啊……
