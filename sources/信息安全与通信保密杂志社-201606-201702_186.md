# 联网PLC面临的信息安全风险分析

**摘要  **

  

  

  

  

  

  

  

工业控制系统是由生产过程和控制过程构成的一个整体。如今的基础设施高度依赖工控系统，在互联网如此普及的趋势下，作为很多工控系统的核心，大多数 PLC 几乎没有采取任何安全措施就直接接入互联网，存在很大安全隐患。过去 PLC系统的安全性往往被忽略甚至被禁用，因为它的某些操作和安全性是相矛盾的。但如果现在继续对 PLC 系统的安全性不加考虑，PLC 系统很有可能遭遇病毒入侵。安全性的缺失除了会给 PLC 本身带来重大隐患，还极有可能成为公司的生产网络甚至整个集团网络的后门。本文对于入侵 PLC 的方法进行了分析探讨，为了展示本文的研究成果，在 PLC 的 STL 语句表中开发了 SNMP扫描器和 SOCKS 代理。本文对于研究病毒入侵 PLC 之后的行为具有很好的参考意义。

  

  

  

  

**引言  **

  

  

  

  

  

  

  

  

工业控制系统（ICS）包括生产过程和控制过程两个部分，如今的基础设施高度依赖工控系统。智能制造（工业 4.0）技术的提出将进一步增加对于工业控制系统的依赖。近年来，基础设施已经成为网络攻击的目标 \[1\]，并为其提供了宽广的攻击面，从简单的 XSS（跨站脚本攻击）漏洞到严重的协议设计缺陷都是网络攻击的范围 \[2-3\]。

  

  

  

  

  

  

  

  

本文特意通过 STL(PLC 语句表 )，由 MC7 字节代码编译而成开发了针对对西门子 PLC 的 SNMP 扫描器和 SOCKS代理，可以在不干扰 PLC 正在运行的程序的情况下直接部署到 PLC 上。

  

  

  

  

  

  

**1\. 攻击实现  **

  

  

  

  

  

  

  

  

以下几种方案执行周期时间的不同：

  

  

  

  

  

（1）一个简单的控制程序，作为基准程序；

  

  

  

  

  

（2）基准程序的修改版本，是在待机模式下通过预置SOCKS 代理的方式实现的；

  

  

  

  

  

（3）负载状态下的基准程序修改版本。

  

  

  

  

  

  

  

  

待机模式表示代理已经被加入到控制代码当中，但是还没有建立代理连接。基准线程序将输入存储器逐位复制到输出存储器中，这会产生 81920 个复制指令。为了测量，需要在数据块中增加了一小段代码，用来储存最后的周期时间，西门子 PLC 将最后的执行周期时间存储在 OB1 中的一个叫做OB1\_PREV\_CYCLE 的局部变量中。在每一个方案中，都测量了 2046 个周期，所有的方案都没有出现正态分布。文中是通 过 Kruskal–Wallis 和 Dunn’sMultiple Comparison Test 来做统计显著性分析，分析结果如图所示，三种方案的执行时间存在显著的差异。

表 2 表示了修改之后的基准程序在空运行状态和负载状态下的差别，只有 1.35ms，SOCKS 代理添加到基准程序中的最大传输速率大约是 40KB/s。如果 SOCKS 代理在 PLC 中单独运行时，速度将会达到 730KB/s。所有网络测量都使用100Mbit/s 的以太网直接连接到 PLC 上面的。最后，通过在实验室中测试整套攻击方案，本文验证了黑客还可以利用 DoS漏洞 CVE-2015-2177 开发利用程序，通过 SOCKS 通道程序可以按照黑客的控制正常运行。

当然，文中的方法也存在局限性。为了确保 PLC 始终反应灵敏，采用看门狗程序监控主程序的执行时间，如果执行时间过长，将立即切断主程序。我们和原程序一起上传的SNMP 扫描仪和代理代码不能超过 150ms 的最大执行时间，扫描仪和代理的写入基本不会触发超时，因为负载时代理的平均附加执行时间才 1.35ms，这和 150ms 比起来几乎微不足道。此外，利用系统函数 RE\_TRIGR 在写入程序执行完毕之后重置时间计数器也可以避免超时 \[19\]。

  

  

  

  

  

**2\. 防护措施  **

  

  

  

  

  

  

  

  

最早避免上述攻击的方法是保证 PLC 处于离线状态，或者使用虚拟专用网络（VPN）。如果现场的系统不属于这两种情况，西门子 PLC 将启动三级保护措施，此时 PLC 允许一个基于口令认证的读写保护，没有正确的口令黑客将无法修改 PLC 程序。根据实践经验，这种方法在实际中很少使用。

  

  

  

  

  

  

  

另外一种可行的保护机制就是采用具有深度包检测的工业防火墙，它里面包含了各种工业控制协议，可以阻挡住大多潜在的不安全访问，比如上文中提到的尝试重写 PLC 程序的攻击方式，此外工业防火墙对于大多数攻击都有一定的防御能力。

  

  

  

  

  

  

**3\. 结语  **

  

  

  

  

  

  

  

  

本文描述了一种新的入侵方法，通过这种方法外部黑客可以将 PLC 当做一个 SNMP 扫描仪或者后门进入内部生产网络，这使得通过面向互联网的 PLC 进入控制系统内部成为可能。测量结果显示和控制程序并列运行的攻击代码会造成一个显著的时间差异，但是和执行周期时间来比是微不足道的，这就使得攻击不会中断 PLC 服务，也增大了攻击无法察觉的可能性。以前关于扫描互联网 ICS 的研究只是提到了由于控制系统直接接到互联网而存在风险，尽管 PLC 不是直接连到互联网，但本文的研究显示如果对系统进行风险评估，就必须把 PLC 也考虑进去。因此，所谓的深度工业控制网络也属于互联网访问的工控系统。
