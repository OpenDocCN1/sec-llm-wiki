0 引 言

网络攻击流量对于网络安全研究和网络防护设备的测试具有重要意义。一方面，可以重放网络攻击流量来检测网络防护设备的有效性；另一方面，可以根据攻击流量编写合适的网络防御规则。


Metasploit是一个使用Ruby脚本语言实现的、开源的渗透测试框架，是当前最流行的渗透测试框架[1]。Metasploit自带大量的攻击脚本，这些脚本的攻击目标涵盖Windows、Linux、Android、iOS等多种操作系统。同时，Metasploit还提供了多种组件，以支持新攻击脚本的快速开发。Metasploit拥有一个活跃的社区，有众多安全研究人员为其添加新的攻击脚本，而这些新的攻击脚本会在网络上迅速流传。Metasploit在方便了安全研究人员的同时，也降低了发起网络攻击的门槛，使得缺乏网络安全知识的“脚本小子”也能造成安全危害。


传统的攻击流量提取方法是运行真实的攻击代码对受控靶机进行攻击，然后抓取网络流量。这种方式虽然能获取准确的攻击流量，但是也存在着一些缺点。首先，Metasploit框架中的攻击脚本的攻击目标范围广泛，涵盖个人电脑、手机、物联网设备甚至工业控制设备等多种平台，而为每个攻击脚本都搭建受控的靶机环境费时费力，十分困难。其次，直接抓取攻击流量难以对流量中不同部分的属性进行区分，如哪些是攻击必需的固定部分，哪些是填充的随机部分。这些属性对编写准确的防御规则具有重要意义。


符号执行是一种在20世纪70年代提出的程序分析技术[2]，常用于软件测试、漏洞挖掘和程序分析等领域。Ruowen Wang和Peng Ning利用符号执行技术分析Metasploit中的Ruby攻击脚本，以获取可用于对抗脚本的防御规则[3]。邱洋和王轶骏实现了基于符号执行的Python攻击脚本分析平台PyExZ3+[4]。


本研究利用符号执行技术，实现对Metasploit中攻击脚本的快速分析，获取其对应的攻击流量。本研究具有以下特点：（1）可以在没有靶机的情况下运行攻击脚本，获取其攻击流量；（2）可以对攻击流量的不同部分进行标记，在保证准确的前提下，尽量化简流量，仅关注攻击流量的固定部分；（3）记录脚本运行时的攻击状态转移，以获取其发送攻击载荷时的上下文；（4）可同时探索攻击脚本中多条执行路径，一次性获取攻击脚本针对所有目标的攻击流量。


1　背景介绍


1.1　Metasploit攻击框架


Metasploit项目由HD Moore于2003年夏季创立，是目前最流行的渗透测试框架。它的设计尽可能采用模块化理念，提升了代码复用率。Metasploit可分为5个部分，即基础库、模块、插件、接口和功能程序。基础库为框架和模块的开发提供了基础功能的支持，如包装的网络套接字、网络应用协议客户端与服务端的实现等[5]。模块是通过Metasploit框架所装载、集成并对外提供的最核心渗透测试功能实现代码。按照用途，模块分为辅助模块、攻击模块、后渗透攻击模块、shellcode模块、空指令模块和编码器模块。本研究的目标是通过对Metasploit中基础库文件进行改造，利用符号执行技术，获取攻击模块中攻击脚本对应的流量。


同一个漏洞可能存在于多个版本的应用程序中，同一个应用程序也会有不同的运行环境。因此，同一攻击脚本会对应多个攻击流量，每个攻击流量对应一个包含漏洞的应用程序版本及运行环境。通常，Metasploit框架中的攻击脚本会执行四个步骤来发起一次攻击：（1）脚本通过网络探测攻击目标的版本和运行环境；（2）脚本基于探测结果和脚本中的知识库，判断目标是否存在漏洞，而脚本中的知识库通常是一个所有可攻击目标相关信息的列表；（3）脚本针对此目标构建特定的攻击载荷；（4）脚本向目标发送载荷以利用漏洞。


在所有的步骤中，构建和发送攻击载荷是最重要的。一个攻击载荷通常可以分为四个部分：（1）利用漏洞所需的特殊且固定的字节；（2）一段漏洞利用成功后被执行的shellcode，Shellcode是攻击者选择的一段恶意代码，通常实现了建立反向链接等恶意功能，Shellcode可以被混淆，通常是变化的；（3）随机或者特殊（例如，x86处理器上的NOP指令0）的填充；（4）其他网络协议相关的字节。


攻击载荷发送时，攻击目标所处的状态非常关键。只发送一个孤立的攻击载荷将无法完成攻击。部分网络协议或服务是有状态的，这就决定了攻击过程也是存在状态的。对于某些漏洞，只有在攻击目标处于特定状态时向其发送攻击载荷，才能实现漏洞利用。所以，攻击脚本在发送攻击载荷前会进行一些操作，使攻击目标处于可攻击状态。这些操作与构造攻击载荷无关，却是漏洞利用过程中不可缺少的。对于某些复杂的漏洞利用，可能会发送多个攻击载荷。攻击状态转移和发送攻击载荷会交替进行，攻击载荷发送完成后，可能还需要发送特殊命令来触发漏洞。如果不考虑攻击状态，根据获取的攻击流量进行重放时，不能反映真实的攻击过程；在编写防御规则时，也会产生大量错误的网络攻击报警。完整的攻击过程如图1所示。



攻击框架中的脚本可以调用框架提供的API来进行目标探测、构建攻击载荷等步骤，简化攻击脚本的开发过程。

1.2　Ruby语言的符号执行


符号执行，即以符号而不是确切值作为输入。在正常的程序执行过程中，程序以确切值作为输入，只会执行一条控制流路径；相反，在符号执行过程中，程序以符号作为输入，可以同时探索在某种输入下会执行的多条控制流路径。符号执行的核心思想是允许程序以符号而不是确切值作为输入，程序中与输入有关的变量表示为符号的表达式。当程序执行到条件分支语句时，会将进入分支的条件送到求解器中进行求解。如果有一组解满足条件，程序就会进入该分支。符号执行需要一个符号执行引擎来维护进入当前执行路径需要满足的布尔表达式和程序中的变量与符号表达式或确切值之间的映射关系。


Ruby编程语言是一种面向对象的、跨平台的脚本语言[7]，是Metasploit框架使用的开发语言。


不同于C语言等编译型语言，Ruby和Python等解释型语言需要解释器才能执行。实现一个解释型语言的符号执行引擎有两种方式：（1）修改语言的解释器，实现符号执行引擎；（2）以对等架构，即语言库的形式实现符号执行引擎[8]。Joseph P和Daniel Jackson提出了一个利用对等架构的Ruby符号执行引擎的方法[9]。本文采用以语言库的形式实现符号执行引擎，实现了一个轻量级的Ruby语言符号执行引擎。采用这种方法实现符号执行引擎需要的代码量较小，可以适用于各版本的语言解释器。


2　对Metasploit的符号化改造


2.1　概览


本文的目标是，对于给定的Metasploit的攻击脚本，可以在没有靶机环境的情况下，利用符号执行技术，自动化提取其对应攻击流量，并且标注攻击流量中不同部分的属性，记录发送攻击流量时的协议状态转移。


为了达成上述目标，对Metasploit框架进行符号化扩展。首先，要实现一个针对Ruby脚本语言的轻量级符号执行引擎。其次，利用此符号执行引擎对Metasploit框架进行符号化扩展，即对目标探测API的符号化，对攻击载荷构造API的符号化，对攻击状态转移API的符号化。最后，要对Metasploit的输出API进行劫持，使其把攻击载荷直接输出到文件。在图1的例子中，smb_fingerprint属于目标探测API，smb_login属于状态转移API。对Metasploit改造的整体架构如图2所示。



2.2　轻量级Ruby符号执行引擎的实现


一个采用对等架构的轻量级脚本语言符号执行引擎利用了面向对象的脚本语言提供的动态派发原子操作特性。在面向对象的脚本语言中，包括整型和字符串类型等变量。当执行如“1+2”等语句时，调用的其实是整型的“+”方法。可以利用方法重载的方式编写新的代理类型，以覆盖整型等类型的原有操作。


对等架构符号执行引擎的架构如图3所示。符号执行引擎是与目标程序运行在同一进程中的一个库。不同于使程序以确切值运行，符号执行引擎向程序传递符号（代理）作为输入。这些代理是特殊的对象，可以使符号执行引擎观测目标程序对这些输入的操作。当目标程序对一个代理执行操作（例如“+”）时，语言解释器会动态将这个操作发送给符号执行引擎提供的回调函数，而这些回调函数会记录代理输入如何影响其他变量。当目标程序遇到与代理有关的条件分支语句时，符号执行引擎会再次被调用，然后符号执行引擎会将约束条件发送给SMT（Satisfiability Modulo Theories）求解器来确定进入哪个分支，以确保每条被探索的路径都是合理的。



目前，符号和执行仅可以处理条件分支语句，不能处理循环语句。当循环语句的终止条件与符号有关时，符号执行引擎不能获取足够的信息进行求解。研究总结发现，攻击脚本的代码长度一般较短，执行路径较为简单，只有极少的攻击脚本中循环次数会与输入有关。所以，即便不处理循环语句，符号执行引擎仍能处理大部分攻击脚本。


简单的Ruby语言代理对象和表达式的示例如下：


1.def SymblicObject

2.    def method_missing(meth, *args)

3.        Exp.new(meth, [self] + args)

4.    end

5.    def +(other)

6.        Exp.new(:add, [self, other])

7.    end

8.    def ==(other)

9.        pid = fork()

10.        if pid then

11.            return true

12.        else

13.            return false

14.        end

15.    end

16.end

17.class Exp < SymblicObject

18.    def initialize(rator, rands)

19.        @rator = rator

20.        @rands = rands

21.    end

22.end


当程序对符号执行“+”操作时，不会生成一个确切的值，而是产生一个表达式，使程序中与符号有关的变量都表示成符号的表达式。当程序执行“==”操作时，程序可以fork出两个进程，分别进入不同的分支。实际实现中会引入SMT求解器，对路径约束条件进行求解。如果条件满足，才会进入分支，以去掉不可达分支。


本研究的求解器基于Z3求解器[10]。Z3求解器是微软公司开源的一款求解器，对整型符号求解支持得较为完善。本研究扩展了其对字符串符号类型的求解能力，目前仅支持有限的字符串操作，如相等、包含、前缀、后缀等布尔操作和追加、子串等操作。


攻击载荷的本质是一串字节流，可以用字符串类型表示。为了表示字符串，字符串符号采用以下表示：


<sym_string,content=[(o,c)…],label=xxx,length=yyy>


其中，content是一个列表，每个元素表示为（o，c），其中o为在字符串中的偏移，c为内容；label表示字符串的属性，可以使rand_text、shellcode等；length是字符串的长度。


符号执行引擎还会记录所有的约束条件，将约束条件与流量相关联，以确定获取的攻击流量属于哪个攻击目标。


2.3　API的符号化扩展


2.3.1　目标探测API符号化扩展


目标探测API是Metasploit中用来探测攻击目标版本即运行环境的API，如用来探测Samba服务版本即运行环境的smb_fingerprint。


正常运行时，目标探测API会与攻击目标进行交互，通过目标返回的结果，返回目标版本和运行环境，其返回值通常是字符串类型或者整型。对这类API进行符号化扩展时，省略其与攻击目标的交互，使其直接返回整型或字符串型的代理对象。


当脚本需要根据目标探测API判断目标是否含有漏洞或构造相应版本的攻击载荷时，符号执行引擎会遍历所有可能的分支，从而获得所有攻击目标版本对应的攻击载荷。


2.3.2　攻击载荷生成API符号化扩展


攻击载荷生成API是Metasploit中用来生成攻击载荷的API，如生成随机填充的rand_text_alpha。


这类API通常不需要网络交互，其返回值一般是字节流。这些API可以分成以下两类：


（1）返回长度固定但内容随机字节流的API，如rand_text_alpha(N)可以返回长度为 但内容随机的一段字符串；（2）攻击者选择的内容和长度都可变的API，如payload()会根据攻击者的选择返回一段shellcode，这段shellcode的功能可能是建立一个反向连接，也可能是窃取某个密码，其长度和内容都是不确定的。


使用带标签的字符串类型符号对这类API进行扩展。带标签的字符串类型符号有两个属性——字符串的长度和描述其性质的标签。它的性质可以是rand_text、payload、nop_padding等，用于描述API的返回值在攻击载荷中的作用。如果API返回字符串的长度是已知的，则其长度属性是确切值；若长度与其他符号有关，则表示为符号的表达式。例如，对于rand_text_alpha(50)可以使其返回“<SymString,content=null,label=rand_text,length=50>”


2.3.3　攻击状态转移API符号化


攻击状态转移API是Metasploit改变攻击状态的API。在攻击过程中，攻击目标的状态基本等同于攻击状态，如smb_login会使Samba服务变为已经登陆的状态。


这类API会与目标进行网络交互，一般没有返回值或有布尔类型的返回值。对于这类API的符号化扩展的重点在于记录其在攻击流程中的调用顺序。记录可以表示为<编号，函数名>的格式，其中编号保存在一个全局变量中，初始值为0。每次状态转移API被调用时，先产生一条调用记录，然后将编号加1。例如，图1的攻击脚本的状态转移API如下所示：


<0,connect>

<1,smb_login>


2.3.4　输出API劫持


在完成构造攻击载荷后，攻击脚本会通过网络向目标发送攻击载荷进行漏洞利用。为了获取完整的攻击载荷，劫持发送攻击载荷的输出API。


劫持从网络层到应用层的所有输出API，改变输出API的功能，使其将数据保存到文件里，而不是发送到网络上，这样就能获取完整的攻击流量。


为了维护攻击流量的上下文信息，将输出到本地文件中的攻击流量与攻击状态转移记录和路径约束记录相关联。


3　实验与评估


为了证明本文提出的攻击流量提取方法是可行的，选取多个Metasploit中的攻击脚本进行测试。其中，图1所示的攻击脚本产生的攻击流量如下：

使用传统的流量抓取方法提取此攻击脚本针对Windows 2000目标的攻击流量，与使用符号执行方法获取的攻击流量在语义上是匹配的，但本文对攻击流量的表示方法更适合编写相应的防御规则。


4　结　语


本研究首先对当前最流行的攻击框架Metasploit进行分析与研究，归纳了框架的整体架构，对框架提供的API进行分类，总结了攻击脚本的执行步骤和攻击流量的组成。其次，研究针对Ruby语言的符号执行，利用对等架构实现了一个轻量级的Ruby符号执行引擎。最后，利用符号执行技术对Metasploit攻击框架进行改造。对给定的攻击脚本，可以在没有靶机环境的情况下，提取相应的攻击流量，并标记攻击流量不同部分的属性，记录发送攻击载荷时的目标状态。


下一步的研究工作可以从以下两个方向展开：


（1）完善符号执行引擎。目前的符号执行引擎仍然存在不足，一是缺少对字符串的相关操作，尤其是涉及正则表达式操作的求解器；二是当循环语句的结束条件与符号有关时，符号执行引擎不能正确处理循环。


（2）对Metasploit进行更全面的改造。本研究为了验证文中提出的攻击流量提取方法，对Metasploit中部分网络协议的API进行了改造。将来可以对更多的网络协议API进行改造，以支持更多的攻击脚本。
