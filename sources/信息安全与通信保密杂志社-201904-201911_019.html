着重研究了相关安全防护机制

资源弹性伸缩、数据动态迁移以及平台租户共享等云计算技术，在最大限度发挥IT资源集约化管理效益的同时，也为云上应用引入了潜在的安全风险。

云平台系统特权、软件缺陷和数 据泄漏等引发的安全问题，已成为云租户敏感应用上网入云的最大障碍。
围绕如何构建安全可信的云租户应用环境，系统研究了云计算安全架构，基于分域防护安全策略和安全服务链防护思想， 提出了“域安全+流防护”云安全架构，并着重研究了相关安全防护机制。
云计算技术作为当前信息领域影响最大的技术 之一，其发展应用给社会生产和生活带来了显著影响。云计算本质是一种新的IT资源组织和应用技术, 引入了资源弹性共享、数据动态迁移以及多租户资 源共享等新的应用架构和管理模式，在最大限度发 挥IT资源集约化应用效益的同时，也为云上应用 带来了潜在的安全隐患。
在云虚拟化环境中，租户安全是云安全防护的重点。简单来说，租户是云平台为特定用户分配的各类IT资源的集合，是该用户在云计算环境下的私人虚拟网络空间。
如何有效隔离租户与底层平台、租户与租户之间的安全风险, 如何有效应对租户数据泄露、用户仿冒、恶意程序破坏、安全漏洞以及DDoS攻击等安全威胁，是云安全防护需要重点研究的问题。需要站在整个云平台的角度，系统研究云平台安全防护机制，构建合理的安全防护体系框架。

本文围绕如何构建安全可信的云租户应用环境，研究分析现有云平台主要安 全防护架构，针对国家关键应用领域安全性和灵活性的防护需求，在选择性吸收和借鉴现有研究成果的基础上，基于分域防护安全策略和安全服务链防护思想，提出了一种域安全和流防护相结合的安全防护机制，探讨了其安全防护框架、防护机制和防 护技术，试从安全性和灵活性方面优化和改进现有云计算安全防护方案。

云计算安全风险

云计算基于传统信息技术发展而来，存在传统网络信息系统的安全风险。同时，云计算引入一系列新的特性，在改变传统信息系统使用模式和管理 模式的同时，带来了一系列新的安全风险。

一是物理资源虚拟化引发的安全风险，包括主机虚拟化、 存储虚拟化、网络虚拟化以及桌面虚拟化等带来的一系列新的虚拟化安全问题；
二是物理资源共享使 用以及系统边界模糊引发的租户安全隔离问题；
三是用户数据的所有权和管理权分离引发的一系列新 的隐私保护和信任风险问题。
云安全联盟(Cloud Security Alliance, CSA )最新发布的《云计算关键 领域安全指南》，总结了云环境常见的12大安全威胁田，如图1所示，分为数据、系统、人员和监 管4大类，包括数据泄露、永久数据丢失、风险共享、 拒绝服务攻击、系统漏洞利用、APT攻击、界面和接口攻击、账户劫持、凭证和身份验证机制被破坏、恶意内部人士、调查不足和云服务滥用。
云安全问题已成为人们应用云计算的最大顾虑，成为制约其 进一步发展应用的最大障碍。

云计算安全架构

云计算环境是一个复杂的生态系统，面临各种各 样的安全威胁。它的安全防护难以通过传统安全手段简单堆砌而成，需要站在科学的体系框架上进行系统性防护设计。

目前，有不少云计算安全架构研究成果, 比较典型的有5种一基于角色的安全架构、基于分层的安全架构旧、基于隔离的安全架构倒、基于可 信根的安全架构和基于服务的安全架构回。
2.1基于角色的安全架构
比较典型的基于角色的安全架构有美国国家 标准技术研究所(National Institute of Standards and Technology, NIST)提出的云计算安全参考架构。
该架构将云生态角色划分为云消费者、云提供者、云基础网络提供者、云审计者和云代理者5类。在安全防护设计时，强调在5类角色框架基础上，附 加安全功能层实施安全防护，基于各类角色进行安全责任分解和细化，明确各方安全职责和防护措施, 从而形成云计算安全防护整体框架，如图2所示。

图2 NIST云计算安全参考架构

该安全架构包括云服务协同安全、服务管理安全、服务聚合安全、服务仲裁安全、服务中介安全、云 审计环境安全以及安全传输支持等组成部分。
整个架构从各个角色参与云活动的角度，提出了云服务安全保障、云部署安全防护、云系统配置和用户迁移的安全管理、用户身份认证、系统安全审计以及云网络数据传输安全支撑等安全防护职责要求。
2.2基于分层的安全架构
目前，比较典型的云安全分层架构模型有CSA 云安全控制模型和我国信安标委在“等保2.0”中 提出的云计算安全防护技术框架。
2.2.1 CSA安全控制模型
美国NIST提出的云计算参考架构是一个典型 的分层模型。该模型将云平台分为物理资源层、资 源抽象和控制层以及服务层（laaS、PaaS、SaaS层）等多个层次。
CSA在NIST分层模型基础上，按照 系统分层模型进行安全控制模型映射，基于云服务 的层次类型和云安全合规性要求进行差距分析，将安全控制模型映射到SPI（ SaaS、PaaS和laaS ）分层模型上，通过差距分析输出整个云平台的安全状 态和防护策略，形成云安全分层模型，如图3所示。
CSA安全控制模型的特点是关注云服务的层次结构，针对不同层次的云服务提供备选安全措施。

2.3基于隔离的安全架构
租户隔离是云平台现有资源共享服务模式的内 生安全需要。云安全隔离机制必须为租户提供一个由底至顶的资源逻辑隔离环境，将租户活动和权限 限定在相对独立的逻辑空间范围，确保租户间资源 和数据互不侵犯。
基于隔离的安全架构研究主要集 中在软件隔离和硬件隔离两个不同层面上，通过纵 向到底、横向到边的资源隔离编配策略，构建多层次的云平台隔离防护架构也如图5所示。
软件隔离主要是采用软件虚拟化技术，在云环境中构建具 备隔离机制的软件协议栈，通过横向编配实现租户之间访问的安全管控，通过纵向编配实现租户内资源调用的安全管控。
硬件隔离主要是通过部署支持逻辑隔离防护能力的硬件设备，实现了对网络、存储等各个环节的高效隔离。软件隔离具有较高的灵 活性，硬件隔离具有较高的安全性和效率。

2.4基于可信的安全架构
可信云计算的基本思想是将可信计算技术融 入云计算环境，基于一个植入的可信根，从物理 层到虚拟机通过信任链传递构建一个层层可信的运行计算环境。
用户对上传云端的数据和应用安全表示担忧，为防止黑客甚至云服务供应商内部恶意员工通过特权侵犯用户隐私，2009年文献提出了一种基于可信平台模块(Trusted Platform Modlue, TPM)的可信云计算平台架构(Trusted Cloud Computing Platform, TCCP ),如图 6 所不。

TCCP由可信节点(Trusted Nodes, TNs )和可信协 调者(Trusted Coordinator, TC )组成° TN 运行可信虚拟机监视器(Trusted Virtual Machine Monitor, TVMM),基于可信机制构建虚拟机安全封闭运行 环境，防止内部入侵者窃取和篡改用户VM的内部 数据。
系统可信管理者称为外部可信实体(External Trusted Entity, ETE ),通过部署的TC对云平台的 TN状态进行管理，验证TN的完整性，确保其可 信机制正常运行。云平台管理者(Cloud Manager, CM)作为不可信云平台管理方，由于在TCCP机制之外，只具有平台资源调度权限，不具备用户数据和应用管理权限。

可信云平台将TPM硬件模块植入硬件服务器，构 建服务器可信计算平台、可信VMM以及可信TPM 管理环境，并通过TPM硬件模块虚拟化技术，生成若干虚拟可信平台模块(virtual Trusted Platform Modlue, vTPM)实例。

2.5基于服务的安全架构
随着SDN和NVF等技术出现，安全即服务的 理念逐渐成为云安全发展方向。为满足租户多样化 的安全需求，需要采取一种可按需配置、动态构建 的安全服务措施。
IBM公司基于面向服务的体系架构(Service Oriented Architecture, SOA )服务化理念， 提出了一种面向云计算的通用SOA安全架构回，如图8所示。

它的主要思想是把安全和安全策略作为一种通 用服务支持用户定制和配置，满足不同租户在安全方面的个性化需求。
基于服务的安全架构强调安全服务化，强调安全与平台松耦合。云安全资源通过 服务化、资源池化、虚拟化管理，对外提供统一的 服务接口，能够整合不同厂商的安全服务，屏蔽不同安全产品之间的差别，实现安全措施平滑更换和 升级，同时给予用户更加灵活的选择权。

上述5种云安全架构总结起来体现了 “三分两 融“的云安全防护思想。“三分“是分别从系统分层、 应用分域和角色分类3个维度着手，基于分而治之 的防护思想，逐步细化安全问题和防护措施，从而形成完整安全防护方案。
“两融”是基于可信融入 云平台和安全融入云服务的防护理念，采用信任链 传递机制构建自底向上、多层次的云平台可信执行 环境，强化云平台安全管控机制，采用安全虚拟化 技术构建服务化和弹性化的云虚拟安全资源池，强 化云平台安全服务机制。
云安全防护是一项复杂的系统工程，往往不是 单一安全架构和防护机制能够完全解决的。云的各种安全架构及防护机制各有优势和不足，安全互补性较强，应该取长补短，综合运用各类安全机制，将云生态、云平台和云应用3个侧面的安全防护机制有机组合，通过安全即服务动态赋能，形成“系 统分层、应用分域、角色分类、多维协同”的云安 全综合防护体系，如图9所示。

在云安全防护具体实践中，可以根据具体应用 需求灵活选取一个或多个维度安全机制有机组合，协同防御，从而构建面向具体应用需求的最佳安全方案。
域安全+流防护安全机制研究

3.1域安全+流防护体系

与传统商业云应用环境不同，在国家关键信息领域，云平台作为重要基础设施具有更高的安全防护要求。如何构建一个安全托底、兼具灵活性、平台适应性、以云租户安全为核心的云计算安全防护机制是本文研究的重点。
在现有主要安全防护机制中，基于角色的安全框架比较宏观，不适用于具体 安全防护；基于可信的安全机制，在开放性、灵活 性和平台适应性方面略显不足。
本文选择性借鉴基 于分层、基于隔离和基于服务的安全防护思想，面向国家关键领域高安全防护需求，针对商业云平台现有隔离机制安全性不足、安全部署手段灵活性和适应性不足等问题进行方案改进设计，将密码作为 安全托底手段，提出了以租户安全域构建为核心， 以服务链提升安全灵活性为手段的“域安全+流防 护”的云租户安全架构，如图10所示。

“域安全+流防护”安全架构是一个以安全域 为核心的分层、分域防护模型，融合了分层防护、 隔离防护和安全即服务的防护思想。基于分而治之的思想，整个云计算安全防护由系统域安全和应用域安全两个部分组成。
系统域是指云服务提供商赖以支撑各类云服务的基础云平台环境，其安全防护 采用分层架构，包括基础硬件与网络层安全、云虚拟化层安全以及虚拟资源层安全等3部分组成。应用域是依托云平台共享资源环境及安全隔离措施构 建的租户业务应用环境。
系统域安全是应用域安全的基础。应用域采用密码机制构建强隔离管控的租 户应用安全隔离环境（即安全域）。不同租户基于不同密码构建不同安全域，通过安全域密码防护机 制实现域内业务应用安全交互和域间业务应用安全隔离。
由此，整个云计算系统的安全问题分解并映 射为安全域的划分与防护问题。安全域之间采用密码构筑牢固防线，安全域内部通过“流防护”策略 强化流量管控与应用安全防护。
针对安全域内不同 应用安全需求，基于“服务链”的思想构建租户级 安全资源池，通过业务流量引导（而非传统服务调 用），将业务流量导入安全资源池，实现租户应用和数据的安全防护。
密码机制提高了安全域的安全性，基于服务链的导流防护机制提高了安全防护的 灵活性和平台适应性。
3.2域安全防护机制
面对复杂系统问题，分而治之是简化复杂问题 的一种有效方法。安全域是一个具有相同安全边界、责任区域、安全使命以及防护措施等要素所组成的安全防护逻辑区域气通过安全域细分，云计算安 全问题可以归结为系统域安全和应用域安全两类问题。
本文主要研究与租户密切相关的应用域安全防护问题，包括云平台资源隔离方法、安全域密码隔离机制等内容。
3.2.1云平台资源隔离方法
云平台资源隔离技术是构建租户安全域环境的 关键技术。理论上，云平台实现资源隔离有3种基本方法：时间隔离、空间隔离和密码隔离圓。
时间隔离通常针对虚拟机共享的CPU、内存等资源，通 过时间分片复用方式进行使用切换调度。
空间隔离主要采用基于分组路由控制的网络逻辑切片技术，对不同用户流量在云平台网络路径上实施分割，避免不同平面的网络间相互影响。
密码隔离采用网络传输加密技术，对不同租户业务流量采用不同 数据密钥进行加密保护，构建相互隔离的VPN加 密网络环境。
目前，主流云平台采用的虚拟专有云 (Virtual Private Cloud, VPC )租户隔离机制属于空 间隔离，实现技术包括虚拟局域网(Virtual Local Area Network, VLAN )、虚拟可扩展局域网(Virtual extensible Local Area Network, Vxlan )、通用路由 协议封装(Generic Routing Encapsulation, GRE ) 和无状态传输隧道(Stateless Transport Tunneling, STT)等。
由于空间隔离机制采用路由标签转发控 制技术实现空间隔离，数据明文传输，难以有效应 对网络嗅探、数据篡改以及数据重定向等安全威胁。在国家关键基础设施等高安全应用环境，它的安全 性缺乏足够保障。在开放共享云平台环境，提高租 户隔离机制的安全性需要满足两个条件：
一是安全强度足够高，能够抵御各种外部攻击；
二是安全机 制无法被旁路，能够防止云平台内部特权人士暗中破坏。
基于密码的加密隔离机制采用数据加密、安全协议等高安全防护措施，密钥由租户自行掌管，平台管理者无权访问，因而能够有效应对上述威胁, 满足租户高安全防护需要。
3.2.2安全域密码隔离机制
云平台普遍采用Vxhn技术在传统IP网络层之上构建虚拟的比层网络环境，以满足SP虚拟机数量扩展和大规模动态迁移的需求。云平台通过Vxlan 隧道边缘设备(Vxlan Tunnel End Point, VTEP)进 行Vxlan报文封装与解封装处理。Vxlan报文为多层 嵌套封装格式，外层为传统IP分组报文和中间层的 Vxlan分组报文，最上层为虚拟IP分组报文。

3.3流安全防护机制
3.3.1流安全防护框架
在云安全防护架构中，安全域是一个面向租户 的虚拟化资源池，包括计算资源池、存储资源池、安全资源池以及基于密码隔离保护的虚拟网络。租户虚拟机具有动态迁移的特性，虚拟机位置及业务流量具有不确定性，导致安全域边界随租户虚拟机 迁移而动态变化。
安全域内业务应用难以部署传统的固守在网络边界的静态防护手段，需要改变传统 的网络边界即安全部署点的防护思路，弱化边界防护，强化流量防控，实现安全服务与部署位置解耦, 重点关注需要保护的业务数据流，通过流量引导与控制，使安全措施不再跟着虚拟机迁移，使租户虚 拟机业务流量主动流经提前部署好的安全资源池进 行安全防护处理。具体防护架构如图12所示。

3.3.2租尸安全资源池
安全资源池基于安全服务链的思想构建。每个安全域设置相应的租户级虚拟安全资源池，虚拟安全资源池通过虚拟化技术与云平台物理安全资源池建立一个租户级的虚拟映射。云平台各类物理安全设备在虚拟资源池中映射为虚拟安全服务节点。
安全域内用户数据报文在网络中传递时，通过流量引导技术将业务流量导入对应的虚拟安全资源池，依次经过虚拟资源池内的各种安全服务节点，各服务节点依次为用户提供的安全服务即所谓的安全服务链。
常见的安全服务节点包括防火墙(Fire Wall, FW )、入侵检测系统(Intrusion Detection System, IPS)、病毒防护(Anti-Virus )以及Web应用防火( Web Application Firewall, WAF )等。
通过对不同业务流量实施基于安全策略的按需安全防护编排，使得业务流量按照安全策略的编排顺序经过安全资源池的不同安全服务节点完成对应安全功能处理，为租户提供按需灵活的安全防护服务。
3.3.3流引导及防护机制
流安全防护机制以流量引导和管控为核心。这里的“流”是指云计算环境下业务信息系统引发的 所有网络流量，包括南北向流量和东西向流量。云 平台主要有3种流引导方式。
一是基础网络导流，即通过传统网络设备重定向或通过SDN网络控制器 配置流表策略将租户业务数据流量引导到虚拟资源池；
二是云平台导流，通过云平台VMM网络组件 或虚拟交换机截获业务流量进行流量引导与控制；
三是云安全导流，通过安全虚拟机/安全导流代理 实施基于安全标签和安全规则的流量引导与控制流引导防护机制如图13所示。

云安全导流防护机制包括3个核心组成部分：安全资源池、流量引导和安全策略管控。安全资源 池管理平台是管理租户级安全资源的服务平台。云平台通过虚拟化技术构建租户级虚拟安全虚拟资源池。
虚拟安全资源池基于安全服务链的思想，将租户所需的所有安全服务节点组合成链式结构，通过 安全策略进行安全服务编排，对租户流量按相应的安全策略进行防护处理。
流量引导机制主要依靠网络导流、云平台导流和安全虚拟机导流等形式构建一个云平台导流控制网络，对东西向流量和南北向流量按照既定的规则实施流转处理，包括流监控与流过滤。
前者不需要改变流原来的路由，需要将全 部的流量复制一份交给安全设备处理即可；后者需 要对流的路由进行修改，让流“绕弯”进入安全设备，处理后再返回目标。
安全策略管控平台是导流 防护机制的核心，主要负责租户安全导流策略制定、 安全资源池安全服务编排，负责基于流量引导防护 体系的态势感知和安全管理，是流量防护机制的“安全大脑”。
在云计算应用推广及发展进程中，租户安全问 题成为制约安全敏感业务上网入云的最大障碍。租户是用户在云中的计算、存储、网络和安全资源的 集合，是用户在云中数字资产的普遍存在形式。租户安全需求主要体现在租户边界的加固和业务应用的防护两个方面。
在边界模糊的云平台环境下，基于密码的网络加密技术能够构筑流动的、无形的安 全边界，特别适合于边界无形的云租户环境；基于安全服务链和流量引导技术，能够构筑按需编排的、松耦合的安全防护机制，特别适合于业务和应用动 态迁移的云应用环境。
两者结合的方案具有较高的安全性、较强的灵活性和适应性，不足之处在于部 分导流机制会依赖于云平台和云基础网络，并且会引发一定网络流量额外开销，但总体可控。
