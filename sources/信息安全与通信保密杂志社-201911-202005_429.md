# 2020年云计算十大新兴趋势：多云变成全云、安全领域更多收购

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzkwMTMyMDQ3Mw==&mid=2247545175&idx=2&sn=cfa734b1bb2b02a2be614da67820bdc8&chksm=c0b4eb21f7c3623732d92c171c26c1f7a6a81d8b3f88f60bb2eef848f4a1eddff6c68e3a84ae&scene=126&sessionid=1681312245#rd](http://mp.weixin.qq.com/s?__biz=MzkwMTMyMDQ3Mw==&mid=2247545175&idx=2&sn=cfa734b1bb2b02a2be614da67820bdc8&chksm=c0b4eb21f7c3623732d92c171c26c1f7a6a81d8b3f88f60bb2eef848f4a1eddff6c68e3a84ae&scene=126&sessionid=1681312245#rd)

> 云基础设施的孤岛现象越来越弱，这使得工作负载的移植性更强、数据流的移动性更强。快速发展的云计算行业已经出现了重大趋势，外媒CRN称它们将成为2020年市场的主基调。

![](../Images/e6e468afad5fb33cd6d2395d13cec919.png)

云计算行业的发展日新月异，让人无所适从，也无法预测。但是将成为明年市场主基调的一些重大趋势正成为人们关注的焦点，即使最终支持它们的技术以及推动技术的供应商似乎在不断变化之中，极容易被颠覆。云基础设施（公共云、托管私有云和本地）的孤岛现象越来越弱，这使得工作负载的移植性更强、数据流的移动性更强。那些趋势有许多源自行业进入了标准化和兼容性加强这个阶段，而标准化和兼容性加强是任何一个技术行业趋于成熟的标志。

这种标准化主要得益于开源运动，得以将重心向架构的上游转变，涌现出了新的渠道角色以支持应用程序级流程，从助力AI和高性能计算，到交付新颖的SaaSOps和应用程序开发服务，不一而足。

**多云变成全云**

2019年，由于企业开始经常在多家基础设施即服务提供商之间部署工作负载，我们跨入了多云时代，这已成为陈词滥调。  
但随着应用程序变得更易于移植，计算周期更易于实时获取，数据集成平台简化连接，供应商组成跨平台联盟，在不久的将来这个多云趋势可能开始看起来更像是全云趋势。一般来说，最大的企业可能很快会成为所有超大规模计算供应商以及一些小众供应商的客户，从而使它们得以充分利用日益差异化的服务和特定协议，并避免锁定现象。

旗下拥有360多家公司的赫斯特集团（Hearst Corp.）就是一个典例。总部位于纽约的这家媒体、信息和服务公司最近跨AWS、微软Azure和谷歌云进行了数字化转型。这种多云方法让赫斯特的开发人员和各部门在所有的相关市场拥有最好的竞争地位。

**Kubernetes打破并模糊云壁垒**

企业纷纷选择最能满足其独特运营需求和功能的Kubernetes平台。这可能是与Red Hat OpenShift模式结合使用的规范性解决方案、Pivotal的底层实现、Docker或Rancher Labs提供的独立发行版，或者谷歌GKE、微软AKS和AWS EKS之类的原生提供商服务。  
这种容器编排工具随后常常成为使它们能够跨不同的云基础设施扩展应用程序的基础，从而兑现多云承诺。正因为如此，Kubernetes不仅有力地打破了云壁垒，还带来了奇怪的市场行情。云基础设施软件供应商与建有大楼以摆放服务器机架的提供商日益脱离开来，这带来了几年前难以想象的一些产品。以谷歌的Anthos服务为例，它在AWS或微软Azure上运行起来就如同在谷歌云平台上一样轻松。还有即将发布的VMware Tanzu，它还可以连接到异地，覆盖所有那些超大规模计算供应商。

多云世界似乎是这样子：不仅仅客户的工作负载横跨云，云提供商本身也经常扩大到竞争对手的地盘。

**Kubernetes配套技术带来新的孤岛**

Kubernetes已大获成功，但这种容器编排工具开创的跨云统一时代将受到围绕它开发的配套服务的挑战。云原生计算基金会（CNCF）牢牢控制着核心Kubernetes项目，它一直在孵化Kubernetes配套技术，以完善这一架构。CNCF通过CNCF路线图来推广那些项目，路线图详细叙述了基于企业使用场景全面采用容器的路径。该路线图上有一项技术对于部署混合应用程序的企业来说必不可少，那就是Istio服务网格。其他开源项目是越来越重要的组件，从监控和检测容器化应用程序的Prometheus、用于日志记录和故障排除的ELK（Elasticsearch、Logstash和Kibana）堆栈、生产环境中高可用性所需的容器注册中心Harbor，到跨微服务跟踪应用程序日志的新兴标准技术Jaeger，不一而足。虽然云计算巨头们没有远离上游的Kubernetes功能，但它们日益向CNCF路线图上的其他项目推广竞争性技术。比如说，AWS建议客户使用其CloudWatch服务（而不是Prometheus）进行监控，谷歌在Stackdriver方面的做法如出一辙。

由于Kubernetes配套技术的分裂会破坏跨云统一方面的进展，随着更多的企业采用云原生基础，紧张局势可能会加剧。

**更多的Kubernetes合并**

无论是公共服务提供商还是本地软硬件供应商，每一家云基础设施公司都必须有强大的Kubernetes方案，才能在当前市场保持竞争力。  
事实一致证明，收购是传统巨头们为自己新兴的Kubernetes部门增添活力，或构建全新产品的一种有效手段。在这个类别尤其值得关注的是，IBM斥资340亿美元收购了Red Hat，凭借OpenShift和早些时候收购的容器先驱CoreOS，IBM构建了一套强大的Kubernetes方案。2017年，微软在全面承诺支持Deis后收购了这个项目，因此扩展了Kubernetes工具包。而NetApp收购StackPointCloud后一举进入该市场。VMware收购Heptio后可能达成了最好的交易，这家初创公司为Tanzu的开发奠定了基础，而Tanzu这个平台将在随后几年支持戴尔科技公司的跨云愿景。

不过外头专注于容器的初创公司比以往任何时候都要多（Docker是其中一家），因此预计各大云供应商在未来一年会大举并购它们。

**安全领域发生更多收购**

决定选择云提供商的企业常常想要使用一整套的平台原生安全工具，而不是第三方解决方案。  
无力在内部开发现代安全架构所有功能的公司只好考虑收购。这就是为什么在过去一年安全领域的收购一直是一大主题。VMware夯实了自身的安全开发工作，先收购了Carbon Black这家端点保护专业公司，后来又收购了Intrinal，以提升其在应用程序安全领域的实力。今年早些时候，微软收购了BlueTalon，加强了其在数据安全和治理领域的地位。谷歌将母公司Alphabet旗下的一家姊妹公司Chronicle收入囊中（不过有媒体发文称这起收购并不成功）。博通刚完成了收购赛门铁克的交易。去年，思科收购了Duo Security，而AT&T收购了AlienVault，成立了网络安全部门。但如今安全是个很复杂的系统，似乎总是有更多的缺口需要弥补。2020年，并购趋势几乎肯定会继续下去，甚至加快。

外面不乏能帮助形形色色的云提供商构建一整套原生安全功能的初创公司。

**私有云回归热**

工作负载向公共云迁移的不可阻挡的势头开始更像是一条双向街道。  
容器及有助于应用程序可移植性的其他技术使企业更容易回归私有基础设施。许多公司变得更熟悉不同环境的差异化优势，正在发挥优势。这并不意味着迁移到公共云的步伐会慢下来，或甚至减速。但是随着一些客户用户意识到一些工作负载在在软件定义的数据中心中运行时，实际上可以获得节省成本、提升性能和加强安全等好处，工作负载会更自由地双向迁移。

而私有云的回归会进一步刺激这个炙手可热的支持混合云环境的市场。

**SaaS智能化**

目前，每一款软件即服务（SaaS）、IT运维、分析和商业智能（BI）产品都以不同的方式和不同的程度融合了机器学习，无论是不是需要机器学习。  
除了在自动化和洞察力方面带来非常切实而重大的优势外，AI这个术语还是一大卖点，添加到产品宣传资料中根本不会有坏处。从聊天机器人到推理引擎再到预测分析，AI很容易进入到几乎任何云软件产品。

一些基于机器学习的功能确实有用，另一些功能只是跟风而已。不过到明年，很难找到一款不号称智能的产品。

**SaaSOps 兴起**

随着SaaS遍地开花，管理这些基于云的应用程序的迁移、运维和支出的更专业平台也层出不穷。  
为了紧跟形势，SaaSOps的地位日益牢固，成为专业化的IT专家的一种新角色，常常与一批新兴的云访问安全代理（CASB）提供的产品配合使用。除了Salesforce及其他知名SaaS供应商的解决方案套件外，像BetterCloud、CloudManager和Blissfully这些供应商还提供微软Office 365和谷歌G Suite等解决方案套件的全面管理。

Cumulus Global的首席执行官Allen Falcon解释道：“SaaSOps这个术语现在含糊不清，但它可以适用于安全、许可证管理、支出管理、影子IT的发现/缓解、跨平台和业务领域的创建/注销管理。”

**重心转向应用程序交付**

从许多方面来看，Kubernetes为动荡的云基础设施市场带来了秩序。这种容器编排工具现在俨然是部署基础设施以支持云原生工作负载的标准技术。  
云原生计算基金会（CNCF）的执行董事Dan Kohn称，这使得竞争可能向堆栈的上游发展，专注于改进应用程序交付。会涌现出主要的开源项目以支持“应用程序开发”实践，交付有助于包装和部署应用程序的服务。

为了兑现这一承诺，CNCF成立了新的应用程序交付特别兴趣小组。

**HPC终于垂青云**

高性能计算工作负载通常零星、分批次地运行，在这种使用场景下，公共云的独特弹性似乎是一大卖点，颇有吸引力。  
然而，尽管借助一家超大规模计划供应商能够迅速扩大和缩小规模有明显的好处，但HPC市场基本上限于本地环境。直到最近几年，HPC用户才开始经常涌入云端，缓解访问资源方面的瓶颈。怀疑云的根源主要与HPC系统上处理的工作有很大关系――它们常常帮助开发新产品设计、专有数据建模和高级仿真。科学家、工程师和产品开发人员一直谨小慎微，不允许那些最重要的工作负载在异地处理。形势在发生变化。很快，执行高级计算所需的昂贵的多核系统将转向公共云提供商。事实将证明，不升级资本密集型数据中心以及能够保证资源按需提供的动力将不可阻挡，即便云端的HPC成本难以预测。https://www.crn.com/news/cloud/10-emerging-cloud-computing-trends-to-watch-in-2020
