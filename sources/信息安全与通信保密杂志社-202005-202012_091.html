摘　要

介绍 IPSec 协议的工作原理，阐述高安全性要求的企业对 IPSec VPN 技术运用于互联网环境提出的抗阻断、高隐蔽等需求。随后对现有的基于 IPSec 协议的集成运用和改造运用类解决方案进行分析对比，提出了一种利用 TCP 及应用层协议承载进行 NAT 穿越和密钥协商的IPSec 协议改造思路。通过在专用 IPSec VPN 网关设备上突破 TCP 加速关键技术，一定程度上弥补协议封装导致的性能损失，验证了新 IPSec 协议具有较强的网络穿透性和隐蔽性。

关键词：IP 层安全；虚拟专用网络；NAT 穿越；TCP 加速；高隐蔽

0 引言

 
租用运营商专线或利用互联网构建跨区域的虚拟专用网络（VPN），能够高效便捷且低廉地解决企业远程互联、网上办公的问题。但是，由于企业用户对虚拟专网的承载业务类型、安全等级、信道质量、组网规模、接入方式以及运营商依赖度等方面需求各异，通常无法依赖于某一种具体 VPN 技术满足所有需求。

从TCP/IP 网络协议栈的角度看，运营商的 ATM 网络、FR 网络可以提供传统虚电路专线方式，但市场逐渐萎缩。而 IP 分组域网络环境下，二层的 L2TP VPN、三层的 MPLS VPN、GRE VPN、IPSec VPN，四层的 SSL VPN 等 VPN 技术，均通过独立或组合运用的方式为企业用户构建不同组网需求的 VPN 提供了技术保障。本文围绕对安全性要求较高的企业总部与分支机构通过互联网环境构建 VPN 的需求，研究 IPSec 协议框架改造设计思路，提升 IPSec VPN 组网的高隐蔽性能力。

1 IPSec 协议概述

1.1 IPSec 协议工作原理
IPSec（Internet Protocol Security， 互联网协议安全）是位于 TCP/IP 协议栈网络层和传输层之间的一套互联网安全协议合集。IPSec 协议框架设计初衷是要弥补 TCP/IP 协议栈安全性的不足，用以保障通信双方 IP 层之上的协议安全。由于框架内各子协议综合运用了数据加密技术、身份认证技术、隧道技术和密钥管理技术 [1] 构建加密 VPN 所必须的四大关键技术，使 IPSec在 IP 网络上为企业构建高安全 VPN 具有先手且完整的优势。

IPSec 协议框架如图 1 所示，主要包括 AH（Authentication Header， 认证头） 协议、ESP（Encapsulating Security Payload， 封装安全载荷） 协议、IKE（Internet Key Exchange， 互联网密钥交换）协议、ISAKMP（Internet Security Association and Key Management Protocol，互联网安全与密钥管理协议）及各种认证、加密算法等。

  
图 1 IPSec 协议框架
 
AH 主要提供的功能有数据源验证、数据完整性校验和防报文重放。AH 不加密所保护的数据报文。ESP 除提供 AH 协议的所有功能外，还提供对 IP 报文的加密和可选认证功能。IPSec 通过 AH 和 ESP 两个安全协议实现数据报在网络上传输时的机密性、完整性、真实性和防重放。IKE 具有一套自我保护机制，可以在不安全的网络上安全分发密钥、验证身份、建立 IPSec SA（Security Association，安全联盟）。

IPSec 有隧道和传输两种封装模式，具体定义了 AH 或 ESP 协议相关的字段插入到原始 IP 数据包的位置，以实现身份认证（ESP 的数据完整性校验不包括 IP 头）和加密，如图2 所示。


 图 2 IPSec 协议封装模式
 
IPSec 隧道建立过程的关键是协商出 SA。可以通过手工方式配置对等体地址、封装模式、安全协议、相关算法、出 / 入方向相关密钥等安全参数，也可以通过 IKE 协议动态协商。IKE是一个应用层协议，本质是 IPSec 的信令协议， 使用 UDP 端口 500，有 2 个版本。IKEv1 中使用了两个阶段为 IPSec 进行密钥协商并建立 SA。

第一阶段，通信各方彼此间建立一个已通过身份验证和安全保护的隧道即 IKE SA，会生成认证密钥和加密密钥。第二阶段，利用第一阶段建立的安全隧道为 IPSec 协商安全服务，建立IPSec SA，生成真正用于用户数据加密的加密密钥。IKEv2 对协商过程进行了简化，一次协商可直接产生 IPSec 密钥，生成 IPSec SA。更具体的IPSec 安全框架及协议原理相关解释需详阅 RFC 文档。

1.2 IPSec 高隐蔽性需求

从 IPSec 相关 RFC 文档的沿袭来看，该安全框架仍在持续改进完善以适应不同的应用环境。高安全企业在互联网上构建 IPSec VPN 还存在如下安全性风险：
（1）阻断性风险，IPSec 的 AH 和 ESP 协议在 IP 头中协议号字段是 51 和50，IKE 使用UDP 知名端口500，在NAP（Network Address Port Translation，网络地址及端口转换）环境中会使用 UDP 的 4500 端口号，均容易被识别和恶意阻断；

（2）窥探性风险，IPSec 安全框架下，即使不被阻断，攻击者也能够利用流量信息进行 VPN 拓扑发现、敏感字段分析等行为。因此，需要研究对 IPSec 协议的改造，增强其隐蔽特性，在保障其提供 IPSec VPN 功能的前提下，提高 VPN 的抗跟踪抗分析能力。

2 IPSec 协议组合或改造运用方案分析

2.1 组合运用类方案
2.1.1 GRE over IPSec 运用
GRE 是三层 VPN 隧道协议，支持单播、组播和广播数据的封装，能穿越异构网络（如IPv6—IPv4—IPv6），适合网络到网络的互联。通信双方需要运营商内部的公网 IP，可运用于分支机构与企业总部、分支机构之间的连接，也可运用于运营商 CE 到 PE 段的逻辑隔离。其他运用场景也有，可阅读相关学者的研究运用实例 [2]， 这里不再细述。GRE 由于不提供身份认证和数据加密，所以往往需要与IPSec 相结合，实现优势互补，于是出现了 GRE over IPSec 的组合运用。

以 IPSec 高隐蔽性需求来评判，由于用户网络边界外扩、依赖 GRE 路由器（集成 IPSec 功能） 甚至延伸至了运营商内部，IPSec 的阻断性风险和窥探性风险并未降低。对特殊行业或机构， 将安全保密边界太靠近运营商，某种程度上也是巨大的安全风险。

2.1.2 L2TP over IPSec 运用
L2TP 是二层隧道协议，是虚拟私有拨号网VPDN 隧道协议的一种，已经形成 IETF 有关二层通道协议的工业标准，在企业网络互连的需要穿越 PSTN/ISDN 网络、移动无线网络的应用场景中发挥了积极作用。穿越 IP 网络时，依靠UDP 的 1701 知名端口承载。

L2TP 依赖于 PPP 协议可实现用户身份认证，但是对业务数据没有加密功能，而早期 IPSec 的 IKEv1 又不能对远程用户进行身份认证，所以 L2TP over IPSec 也是利用 IPSec 弥补业务加密的短板，可参见学者运用该方案进行移动终端利用运营商网络访问企业内部桌面云系统应用的案例介绍 。

L2TP over IPSec 更适合移动接入，能够利用 L2TP 协议方便地为终端动态分配内网 IP 地址，支持动态接入。相较于分支机构与总部间固网对固网的互联，各子网往往有独立 IP 规划。L2TP over IPSec 可视作保护用户 L2TP 设备投资的一种折中方式，随着 IP 技术渗透到网络边缘，L2TP 的推广应用压力剧增。



以 IPSec 高隐蔽性需求来评判，L2TP 帮助IPSec 解决了早期版本不支持 NAPT 穿越的问题， 由于自身仍使用知名端口 UDP 的 1701，阻断性风险和窥探性风险并未降低。

2.2 改造运用类方案
2.2.1 IPSec over UDP 运用
IPSec 设计之初，AH 或 ESP 头均位于 IP 头和传输层头部之间。但是，IPSec VPN 网关之间若部署了 NAT 设备，则仅有 ESP 隧道模式能适应这种场景。若 NAT 设备运行了 NAPT 功能，则传统 IPSec 封装无法穿越 NAPT 网关 [4]。直至 2005 年 RFC3947、3948 发布， 定义了协商包和业务包如何利用 UDP500、4500 端口。

标准的 RFC 做法是在 IP 头和 ESP 头之间插入UDP 头的方案，因此仅支持 ESP 封装，不支持AH 封装。随后的数年，有学者提出使用新加IP 和 UDP 头承载原 IP 包的方案，于是这种封装方式同时支持了 AH 和 ESP 封装。也有学者使用 IPSec over DNS 的方案，UDP 端口号使用知名端口 53 来“欺骗”防火墙，同时支持 AH 和 ESP 封装，不仅适应 NAT 环境，还具备“隐蔽通信”思想。可见，IPSec over UDP 方式有许多“变种”，增强了网络适应性，且利用基于 UDP 的应用层协议承载增强了 IPSec 的隐蔽性。

2.2.2 IPSec over TCP 运用
有学者研究用 TCP 承载 IPSec 协议，最初的动因是要解决 IPSec 的 NAT 穿越问题， 通过使用新加 IP 和 TCP 头承载原 IP 包的方案，可同时支持 AH 和 ESP 封装，采用了“一帧一转发”方式。但是，这种实现方式未能普及，因为某种程度上受到了 SSL VPN 网络扩展模式的冲击 。后者通过 TLS 的记录协议“多帧一转发”方式和可选的压缩处理能够极大地提升吞吐率，且安全措施不断完善。RFC8446 的 TLS1.3 版本已于 2018 年发布。

同期也有学者使用 IPSec over HTTP 的方案， 将密流量伪装为正常流量，同时支持 AH 和ESP 封装。虽然性能损耗不小，但由于开放网络终究有知名 TCP 端口必须开放，否则影响正常业务，所以学者的这些改造同样具备了一定的“隐蔽通信”思想 [5]。可见，IPSec over TCP 方式的运用改造增强了网络适应性， 且利用基于 TCP 的更多应用层协议承载增强了 IPSec 的隐蔽性。

3 IPSec 协议高隐蔽性改进与验证 

3.1 IPSec 协议框架改进
如表 1 所示，组合运用或改造运用方案均各有优劣。为了满足 IPSec 高隐蔽性需求，提出在用户网络边界部署专用 IPSec VPN 网关设备，采用 IPSec over TCP 封装思路进行新的 IPSec 协议框架设计并着力提升性能，重点对 IPSec 协议框架的密钥交换协议和安全封装协议进行改进。如图 3 所示，由分支机构发起 IKE SA 高隐蔽协商，总部仅作被动响应。VPN 网关内网的 IP 包经过高隐蔽 IPSec 封装后发往总部 VPN 网关解封，再发往总部内网，反方向的业务进行逆过程处理。


图 3 IKE 协商与 IPSec 业务处理过程示例
 

3.2 IKE 协商过程改进主要改进：

（1）协议交互消息数精简、简化协议状态机，提升协商效率；（2）引入基于身份的密钥协商、协议交互不再传递证书、减少颁发机构、证书有效期等敏感明文信息暴露；（3）策略配置时确立使用何种应用层协议头前置于 ESP 头增强隐蔽性。
 


图 4 改进的 IKE 协商过程

如图 4 所示，由发起方建立 TCP 连接隧道， 协商包可以不用考虑重传、单包大小等因素。发起方A 发送 IKE SA 协商请求，携带协议版本、支持算法、SA 存活时间、重协商时间以及随机数 rand_a 等信息。

响应方 B 匹配 IKE SA，发送IKE SA 协商响应确定 IKE SA 参数，并携带 B 的身份 ID、随机数 rand_b 等。发起方 A 结合双方身份 ID 计算共享的消息认证密钥，通过 B 的身份 ID 计算 B 的公钥，发送 IPSec SA 协商请求， 用 B 的公钥加密敏感信息，包括兴趣流、封装方式、密钥材料、随机数 rand_c（此时，B 收到IPSec SA 协商请求后，已经能够与发起方 A 基于rand_a、rand_b、rand_c 计算出共同的会话密钥， 可以扩展出相同的业务加密密钥等）以及携带发起方 A 的身份 ID 等，还要用消息认证密钥将已交互的 3 条消息的计算消息认证码带给响应方 B。

B 收到 IPSec SA 协商请求后，用双方计算共享的消息认证密钥和自己的私钥解开敏感信息，扩展出业务加密密钥等，用消息认证密钥对已交互的 3 条消息的摘要计算的消息认证码进行核对。最后，响应方 B 再发送 IPSec SA 协商响应，同理对交互的 4 条消息的摘要计算消息认证码，发起方A 收到后也进行验证，若通过， 则协商过程完毕。

3.3 业务封装过程改进
业务封装设计为类 ESP 隧道模式，如图 5 所示。配置 IKE 安全策略时，需确立响应端的 TCP监听端口。双方隐蔽时采用的应用层协议（可选）相较于标准 IPSec 封装，攻击者封堵传输层端口以及分析密报头等信息的难度都将大大增加。例如，安全策略可以灵活配置使用 0 ～ 1023 的TCP 知名端口，如 53（DNS）、80（HTTP）、443（HTTPS）等，也能灵活使用 1024 级以上的动态端口（防火墙可能缺省封堵）。

如果防火墙开启了应用层代理或检测功能，高隐蔽 IPSec 协议要想“翻墙”，则不仅要使用知名端口， 更要携带应用层协议头甚至要维护应用层协议的会话状态进行“欺骗”，这与躲避攻击者机理一样。




图 5 高隐蔽 IPSec 业务封装
 
基于上述改进思路，在原理样机 CPU 上以软件方式实现高隐蔽 IPSec VPN 网关功能。由于是 TCP 承载，按照传统实现，需通过虚拟网卡将内网 IP 包收至 Linux 用户态，再进行应用层头部封装、TCP 承载与转发，较内核态实现标准IPSec 性能损伤较大。

因此，提出在用户态管理TCP 连接，在内核态进行 TCP 业务封装与转发的思路。核心是在 Linux 协议栈源码的 Socket 层调用收（kernel_recvmsg、sys_select 等）、发送函数（kernel_sendmsg），接管收发的 TCP 业务包。一方面利用协议栈完成TCP 包的拼段、分段、收发，使编程实现与用户态相似；另一方面避免内核与用户态 TCP 数据拷贝提升处理效率。结果表明，TCP 通信性能提升明显。

4 结语

本研究以提升 IPSec 协议隐蔽性为出发点， 对协议框架、协商协议及业务封装协议均进行了改进设计。在安全与性能相互制约的天然矛盾下，通过内核态 TCP 加速处理关键技术的突破，一定程度上弥补了引入高隐蔽特性而带来的性能损伤，为高安全性企业隐蔽性组网提供了一种解决方案。目前，互联网环境的 VPN 组网技术已经出现相互借鉴甚至同质化实现、组合化运用的事实，类似深暗网这种系统性运用也是数不胜数，IPSec 如何进一步发展演进值得思考与探索。
