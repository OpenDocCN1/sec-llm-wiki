达雷克·科米尼克

达雷克·科米尼克（Darek Kominek）是Matrikon（Honeywell）公司的高级咨询经理。在过去的15年中，达雷克在 Matrikon 公司担任过各种角色，包括销售、市场传播、产品经理和战略营销。在加入Matrikon之前，达雷克在通用电气（HP）担任专业软件工程师，并经营着自己的软件咨询业务。达雷克是具有理学学士学位的专业工程师，获得了艾伯塔大学（University of Alberta）计算机工程专业的博士学位。


在与来自 Matrikon（Honeywell）公司的OPC专家达雷克·科米尼克的访谈中，您将会了解到内置安全性的概念、IT-OT 缺陷、防止黑客/恶意软件攻击以及使OPC UA成为安全数据交换标准的一系列最新动向。

迈克尔·克拉克：达雷克，请向我们的读者介绍一下您自己，您所在的公司——Matrikon，以及您参与OPC 基金会的情况。


达雷克·科米尼克：我的背景是计算机工程。在职业生涯的前十年，我从事软件开发工作，然后转向市场营销和产品管理。


我在Matrikon公司工作了15年 , 作为公司的营销总监，我负责战略营销和产品定位。我还运营技术解决方案咨询小组，该小组为使用基于OPC解决方案的直接合作伙伴提供协助。我还负责一个平等的合作伙伴计划，该计划与使用Matrikon Flex OPC UA SDK的合作伙伴打交道。


在Matrikon之外，我是OPC Foundation市场营销控制委员会的成员。在那里，我参与塑造OPC Foundation品牌的活动并与OPC UA合作。


迈克尔·克拉克：如今，安全已成为一个很热门的话题。OPC UA在其中扮演什么角色？OPC UA有什么保护作用？


达雷克·科米尼克：很好的问题。我们在新闻中听到世界各地发生的各种事情——我们必须应对的各种威胁，包括对网络通信的威胁。由于每个人都依赖网络，因此将面临更多的威胁。当我们谈论工业自动化时，无论是欧洲的工业4.0，还是工业物联网（IIoT），一切都基于来自底层数据源的信息。OPC UA恰好处于本主题的最佳位置，因为它专注于将数据从A点移动到B点。


当谈论安全性以及数据如何被处理时，数据基本上处于三种状态：


第一种状态是静态数据。这包括将其存储在数据库、历史记录器或设备中。

第二种状态是正在处理的数据。这描述了正在使用的数据。

第三种状态是动态数据的概念。这是传输数据的事件。


OPC UA 主要关注第三种状态，即动态数据。它从整体上审视数据，不仅是数据在传输过程中如何加密，还包括谁应该有权访问这些信息， 以及他们被允许使用这些信息做什么。

您问 OPC UA 保护什么？所有工业数据，从车间最底层的源头开始，一直到云应用程序内的数据存储，都是 OPC UA 保护的对象。


迈克尔·克拉克：据说 OPC UA 具有“内置” 安全性。那是什么意思？


达雷克·科米尼克：这是OPC UA中的一个重要组成部分，它从一开始就被设计成是安全的。它的安全性是基于过去二十多年的经验教训。OPC Foundation认识到的一项关键原则是，目标不仅仅是在于连通，安全也是目标的组成部分。在行业中，IT部门试图保护其网络，而OT员工则试图保持其工厂运转，这一点尤其正确。前进的道路必须包括OT通信标准中内置的最佳 IT 实践。值得注意的是，基于这些目标，OPC UA标准包含14个核心部分，其中有6个直接受到安全主体的影响。


迈克尔·克拉克：OPC UA对工业物联网（也称为工业4.0）的适用性如何？就安全性而言，OPC UA是否能解决IT-OT的空白？


达雷克·科米尼克：当然！虽然 OPC Foundation 并未发明如何将IT与OT结合起来，但是它利用了两个学科的最佳实践来提供端到端的安全性，从而确保我们知道数据的来源和去向。


OPC UA安全性吸收了其他组织的专有技术。例如，国家安全局（NSA）及其纵深防御的概念可确保实现多层安全保护，从而使用户不仅仅依赖于一条路径。这些类似于由多条护城河和多堵城墙组成的城堡结构。另一个例子是NIST（美国国家标准技术研究院）对算法的处理。尽管加密技术在当今可能已经很成熟，但是事情还在继续发展。某些部门正在监视哪些算法开始变得脆弱或不再有效。


由于OPC UA具有继续发展的能力，因此它不受任何特定技术的约束。它的范围更加全球化。无论我们是在谈论小型微处理器（甚至连板载操作系统都没有的东西），还是大型服务器或基于云的系统，每个实体都有使用证书的能力。包括基于角色的安全性的一些最新进展，这使得减轻配置安全系统的麻烦变得更加容易。“列表”还在继续，所有这些最佳实践都已内置在OPC UA标准中。


迈克尔·克拉克：让我们更详细一点。有哪些关键的安全概念？


达雷克·科米尼克：安全的话题如此之大，以至于人们有时会被必须了解的广博知识所淹没。由于 OPC UA 将其范围限制为数据传输（我之前提到的动态数据方面），我建议我们谈论更广泛的信任概念。那么，使通信值得信任的方面是什么？共有七种通用安全原则，可分为三类。第一类具有三个方面，称为安全性的三重“A”，即身份验证（Authentication）、授权（Authorization）和可审核性（Auditability）。


（1）身份验证用于在A和B之间进行通信时，确认设备A确实是A，设备B确实是B。这是使用PKI（公共密钥基础设施）在打算相互通信的两个实体或应用程序之间建立信任的情况。

（2）授权处理的是在系统上对数据进行身份验证后，允许谁对数据进行处理。

（3）可审核性是跟踪实际发生情况的能力。例如，如果您要进行事后分析，则可以查看谁发出了哪些请求，何时发出以及从何处发出请求。


下一类安全性原则是 CIA 三合一，它代表数据的机密性、完整性和可用性。

（1）机密性是指将实体之间发送的信息进行保密。

（2）完整性是指数据没有被更改。

（3）可用性确保通信尽可能保持在线。


安全性的最后一个类称为不可否认性。通过对传输的数据进行签名，可以确保收件人知道数据的完整性和来源，并且不会对其进行欺骗。


迈克尔·克拉克：用户如何知道在给定的产品中实现了哪些安全功能？


达雷克·科米尼克：如果产品启用了OPC UA，那么用户将认识到OPC UA服务器公开了客户端可以建立安全连接的端点。当我们谈论端点时，寻求与OPC UA服务器建立连接的OPC客户端将在该服务器内看到可用于建立此类连接的安全机制的列表。


迈克尔·克拉克：您刚刚提到了端点。您能和我们的读者分享一些端点的例子吗？


达雷克·科米尼克：对于那些熟悉安全性概念的人来说，他们可能知道一些用于标识各种算法和安全性系统的名称，但是对于其他人来说，听起来似乎有些神秘。服务器可能公开的端点包括加密，如AES-128、SHA-256、AES- 256等。这些端点反映了服务器可以实施的各种安全策略。


为了提供一些启示，我们可以将其与一个免下车餐厅的菜单板进行比较。您可以公开地从整个菜单中选择您想要吃的和喝的东西，或者您可以点一份套餐——套餐1或套餐2。将此与OPC UA服务器中的安全策略进行比较；它们结合（或创建一个组合）不同类型的算法和交换，这些算法和交换可以在客户端和服务器之间建立，以相互证明它们的身份。接下来，有必要建立客户端和服务器将如何签名消息的加密标准，以及它们将如何加密并随后解密数据。


这种用于创建令牌和哈希值的不同算法组合在一起，称为安全策略。端点是暴露这些组合的要素。最终取决于您是选择对数据进行签名，对其进行加密还是同时对两者进行加密。最坏的情况是不执行任何操作，这称为无操作，也就是既不签名也不加密数据。显然，这是最不安全的实现。


迈克尔·克拉克：用户如何知道给定 OPC UA 服务器中有哪些端点可用？


达雷克·科米尼克：当用户开始从OPC UA 客户端建立连接时，服务器将向客户端通知其可用端点，它将对其进行通告。然后，用户可以选择他们要使用的那些功能（端点）。当然，供应商文档将指定 OPC UA 服务器中可用的安全选项。


迈克尔·克拉克：OPC UA 如何防止常见的黑客或恶意软件攻击？


达雷克·科米尼克：有十种常见的攻击类型，每一种都试图破坏我前面提到的安全功能。我举几个例子：


邮件泛洪是一种拒绝服务（DoS）攻击。根据 CIA 三合一的定义，这种攻击试图影响“可用性”。OPC UA服务器通过尽可能少地处理传入数据包来解决此问题。如果数据包中的信息没有立即对齐，则服务器就将其丢弃。它不会尝试恢复数据、找出数据或尝试与该客户端进行进一步的交换，而只是丢弃数据。此功能最大程度地减少了OPC UA服务器的处理，从而保留了服务器的弹性。


另一种攻击类型是消息欺骗，或者换句话说，伪造消息。这有时被称为中间人攻击，其中消息被操纵为看起来好像它们是真实的，而实际上却不是。由于OPC UA数据包使用加密、证书、嵌入式会话ID和信道ID，因此只要您选择应用这些安全措施，虚假消息就很有可能像滚雪球般地到来。


消息更改或重放是黑客试图获取有效消息并尝试多次重放的另一种方式。想象一下，如果这条信息是激活阀门定位器的命令。如果被允许通过，可能会造成灾难性的后果。OPC UA会话ID、信道ID、时间戳序列号、请求ID等都考虑到这些因素，从而防止消息的重放。


最后，最明显的漏洞是窃听。通过使用数据加密，OPC UA消除了这种可能性。预防措施的列表还有很多，但这些都是一些有效的例子。


迈克尔·克拉克：每个启用 OPC UA 的产品都必须实现所有的安全配置文件吗？


达雷克·科米尼克：不，没有必要。为了使 OPC UA标准适用，有必要为具有不同功能的服务器定义特定的配置文件，如nano、micro、嵌入式配置文件和标准配置文件。通常，计算能力与特定子组件正在处理的复杂程度成正比。如果您的产品太小而无法运行OPC UA安全性的完整实现，那么请回到深度防御的想法。必须采取措施，确保 IT（或 OT）人员正确隔离这些设备，并通过在组件周围使用其他保护方法来减轻风险，这些保护方法未充分利用 OPC UA安全策略的实施。


迈克尔·克拉克：实现 OPC UA 安全性是否会使产品更安全？


达雷克·科米尼克：这是一个非常重要的问题，我希望供应商和终端用户一样重视我的回答。如果正确实施 OPC UA 安全性，是的，它是有效的，但是供应商正确实施产品的其他方面也极为重要。让我说明一下：


OPC UA 使用证书在对等组件之间建立信任。想象一下，如果一个产品将其根证书存储在不受保护的区域，即产品的任意某个地方。即使该产品已正确部署了OPC UA 安全功能，如果某人以某种方式获得了这些根证书的访问权而损害了该产品的网络存在，那么该产品的安全性也会受到损害。至关重要的是，制造商在制造产品时要全面考虑。此外，最终用户管理员必须正确配置他们的系统和支持网络。


迈克尔·克拉克：您能分享一些关于 OPC UA 内置安全性的经验证据吗？


达雷克·科米尼克：好的。OPC Foundation 当然已经在其自己的实验室中进行了测试，但是德国政府完成了更为深入的检查的示例。


德国联邦信息安全局 BSI 有义务系统地测试可用标准以支持工业 4.0 计划。他们雇用了一家第三方公司进行全面的测试，其中包括证明和实施验证。OPC UA 表现出色，通过了严格的测试。这极大地增强了行业信心。


此外，已经在其他国家进行了测试。例如， OPC UA 是中国的国家标准之一，已被纳入其“中国制造 2025”计划。


迈克尔·克拉克：安全是黑客与安全社区之间的猫捉老鼠游戏。OPC UA 如何跟上节奏？


达雷克·科米尼克：这绝对是一个永无止境的故事。定义 OPC UA 的分层方法及其服务体系结构跨越不同的层，旨在解决不断发展的问题。这意味着您可以继续使用当前已实现的功能，但是，当下一个产品版本发布时，可能有必要更新某些板载安全特性。例如，加密算法可能需要更新。OPC UA 规范遵循NIST准则， 该准则建议了各种算法的失效日期。OPC UA 已经弃用了其中的一些算法。


迈克尔·克拉克：对于那些想进一步了解OPC UA 安全性的实际实现的人，您可以建议哪些信息来源？


达雷克·科米尼克：好的。OPC Foundation 当然已经在其自己的实验室中进行了测试，但是德国政府完成了更为深入的检查的示例。


达雷克·科米尼克：OPC Foundation 网站是最好的起点之一。在这里的许多资源中，您会发现一本小册子，它描述了如何安全地部署OPC UA。还有一个有关 OPC UA 安全性的维基百科页面，可从 OPC Foundation 网站直接访问。此外，您始终可以自己免费参考 OPC UA 标准。OPC 成员还可以预览正在进行的项目。我认为这些都是很好的起点。
