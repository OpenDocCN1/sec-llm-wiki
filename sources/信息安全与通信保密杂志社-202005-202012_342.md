第2部分：知识共享和数字证据胶囊（CODE）

  

  
  

**摘　要 ●●**

  

尽管有许多潜在的好处，但数字取证领域内的知识共享仍有待实现。实现这一目标已经引起了许多从业者和学术界的争论，但是对于“我们如何共享知识”和“我们共享什么”这两个基本问题的解决方案尚有待探索。目前，已经有一些可行的协议可以解决两个问题中的任何一个，但是对整个领域的共享构成了障碍。这项工作的重点是解决后一个问题，并指导从业者必须共享哪些内容才能使任何数据对其他专业人员有价值。本文提出了数字证据胶囊（CODE）的概念，该框架旨在为共享可靠的数字取证知识设定必要的因素。检验了CODE 结构及其必要内容，以及其在数字取证领域支持现场知识共享的适用性。

**引　言**

  
15年来，学术界、研究者和从业者一直在讨论数字取证（DF）知识共享的需求。作为一门学科，DF的从业者认识到需要共享知识及其所能提供的好处，其中包括诸如对从业者的培训辅助工具和用于调查质量保证措施的用途。取证分析的主题是技术，其在软件和硬件方面的快速变化意味着没有任何一名DF从业者可能拥有足够的理解力来解决其角色可能遇到的所有问题。  
DF知识的共享提供了一种支持现场开发的方法，在这种情况下，从取证学的角度理解我们数字社会的所有方面的唯一选择，可以说是通过合作努力。鉴于DF中活动和数据类型的多样性，存在一系列可能共享的知识类型，其中“知识共享”成为一个模糊的术语，不需要进一步的描述。接下来的问题仍然是“应该分享什么样的知识？”之前的建议包括过去的测向调查结果和测试数据集。本文提出了共享“新知识”的代码，如下所述。  
全世界每天都会进行数百次数字调查，在许多情况下，从业者很可能会在系统上遇到过 “以前从未遇到过的数字痕迹”，并且不存在对数字痕迹的书面或可靠记录的解释。在这种情况下，通过强大的测试，从业者必须生成自己对数据的解释，然后应用并将其添加到他们所找到的数据中。这项工作的成果是创造了“新知识”，这是该领域以前可能从未遇到过的新知识，这是CODE旨在捕获和共享的知识类型。拥有这种“新知识”的从业者正在提供以下潜在利益：  
·从业者利益：从业者分享新发现的准确知识将为共享此内容的人们带来利益。这可能在多个级别上发生。首先，如果另一位从业者在同一案件中遇到了相同的数字痕迹，则其共享的“经过测试和验证的解释”在其当前案件中支持P2。如果我们假设P10的解释没有错误，那么P2就有可能将其应用于当前情况。尽管仍然应该进行方法论上的验证，但P10的解释在当前情况下为P2提供了支持，从而防止了它们重复相同的步骤。  
·一致性应用：同样，假设P10共享的数字痕迹解释是准确的，则应将其视为解释该痕迹未来出现情况的基本标准。通过共享此信息，当其他从业者遇到相同的数字痕迹时，将鼓励他们应用此含义。这有助于在DF检查中坚持质量标准，防止出现歧义的解释，可以减少依赖任何现有的或造成误解的机会。此外，在可以始终如一地解释某个数字痕迹的情况下，这有助于DF之外但仍使用数字证据的人成为理解此内容含义的法律程序的一部分。  
·质量保证：共享新发现的知识可以进行同行评审。在理想的世界中，任何共享的知识都是可靠的，但是仍然可能发生人为错误。P1承担的共享数据和相关测试方法可以由DF领域的其他具有适当专业知识的人进行审查。这可以导致三个输出：  
（1）确认：其他从业者可以确认任何提供的解释的准确性。（2）争议：其他从业者可能会对所提供解释的准确性提出质疑，并提供反驳全部或部分解释的证据。（3）增加：其他从业者自从开发或更新了解释性数字痕迹后，便可以在提供的解释中增加附加内容。  
支持一个共同目标：特别是在犯罪行为方面，在DF中工作的人正在支持一个共同的目标， 即提供证据以使刑事司法系统能够适当可靠地应用其适用法律。知识共享有助于维持和促进调查标准。  
此外，从业者们虽然不认为这是一项全领域的收益，但他们还应考虑到“新知识”的创造和传播是持续不断的职业发展的一项活动，既支持他们自身也促进了领域的发展。  
虽然分享知识有多种好处，但可以说，这种情况尚未在广泛一致的基础上发生。目前，知识共享存在障碍。  
有人认为，那些在DF中工作的人容易受到“孤单心态”的影响，因为他们不愿共享信息。毫无疑问，以下是在可能发生跨领域知识共享之前必须克服的障碍：  
·从事这一领域的工作：在大多数情况下，分享知识将是一项活动，一个从业者除了从事其专业工作外，还将从事这项专业外的活动。这使得参与知识共享成为个人负担，几乎没有金钱激励，而在大多数情况下，个人荣誉可能是唯一的动机。结果，参与的热情可能有限。尽管有些人可能认为共享内容是一种道德和道义上的义务，但这并不是一种预期的笼统心态。此外，个别情况可能会阻止那些甚至想参与共享的人这样做。结果，很少有鼓励人们持续参与DF领域的激励措施，虽然偶尔或短暂的接触可能会发生，但为了从知识共享中获得最大价值，这种接触必须是可持续的。在可能的情况下，应鼓励知识共享，以支持参与。  
·“孤立的心态”：如上所述，“孤立的心态”是共享的障碍，在组织和从业者层面上都可能发生。在组织层面，知识可以创造金钱报酬，在这种情况下可以看到某些取证技术的垄断。在这种情况下，很难争辩说应该将这种方法换为公开、透明的数据共享，这最终将影响财务回报。在个人从业者层面，拥有专家知识可能会获得“专家身份”并在DF领域或其他工作机会领域享有较高声誉。可以说，这也可以通过分享知识的人来实现，但是这种立场可能并不总是被采纳。  
·不愿意共享：共享知识允许他人通过使用此内容来学习和发展。然而，对于任何知识的作者来说，公众监督的恐惧和焦虑可能会阻止他们做出贡献。因此，在制定任何知识共享协议时，必须制定具体的行为准则，防止个人在工作声誉方面受到损害或受到控制。有争议的信息必须以正式和专业的方式处理。  
·我们该怎么做？假设可以获得广泛的参与，那么实现这一目标的机制很少，这是一个令人担忧的问题。有两个问题必须解决：  
（1）我们如何共享？还需要一个合适的协议来共享知识。必须为共享知识开发一个合适的框架和方式，供该领域采用。但是目前还没有。（2）我们共享什么？决定共享什么是一个至关重要的方面。尽管共享“新知识”是症结所在，但还有一些要考虑的因素可以使其他从业者信任，包括进行中的或已开发的任何测试方法，知识的解释方式，以及责任者和可靠性。“我们共享什么？”的挑战构成了这项工作的重点。  
在本文的范围之外，确保从DF领域获得投资以作出贡献仍然面临着自身的挑战，其中开发合适的知识共享协议仍然是重点。这项工作提出了数字证据胶囊（CODE）的概念，用于在存在和讨论CODE结构的DF中共享知识。第2节讨论了 CODE，第3节说明了如何在实践中实现它。最后给出了总结性思想。  

02

**数字证据胶囊**  

  
CODE结构是基于DF中有效知识共享所需条件的概念，在此条件下，从业者在单个“胶囊” 中共享知识案例。每次从业者发现并验证“新知识”时，CODE都会定义要求他们以胶囊形式捕获和共享此信息的条件，并要求所有从业者可靠使用此信息的所有元素。CODE模式为共享知识对所有从业者都有价值所需的元素提供了形式化的指导。  
CODE模式如图1所示，其后是其组成部分的完整说明。  
![](../Images/55828ff10fc0ebaeab045f03952444db.png)图1  CODE 框架  
  
CODE定义了对数据描述符的三个关键类别的要求：每个胶囊中必须包含“提交元数据”“核心连续性元素”和“核心数字数据描述符”。所有这些都由一系列子标准组成，这些子标准有助于证明所含“新知识”的可靠性。在高层次上，任何寻求依靠胶囊内容的从业者都必须能够确定以下三点：  
·问责制的连续性要求：所有提交的胶囊必须包含信息，以保持连续性。这包括胶囊数据原始作者的详细信息，以及可能使用了该信息，添加或反驳了这些发现的后续从业者与胶囊的其他任何接触。这可以通过 CODE“提交元数据”和“核心连续性元素”数据描述符来解决。  
·完成工作的透明度：胶囊必须包含生产知识所涉及的所有过程的记录。这包括测试细节、使用的测试数据、进行的任何验证过程以及对胶囊进行的同行评审记录。这是通过CODE“核心数字数据描述符”和“核心连续性元素”数据描述符来解决的。  
·胶囊的主要贡献：产生胶囊的目的是分享从业者对他们发现并决定分享的“新知识”的解释。这必须有明确的定义和背景。这是通过CODE“核心数字数据描述符”来解决的。  
**2.1　提交元数据**  
每个胶囊必须附有描述胶囊来源的提交元数据。这提供了胶囊内容的责任，并允许胶囊作者和信息的任何后续用户之间的对话。必须提交以下三个方面的内容：  
·CODE 提交的详细信息：不得匿名提交CODE，以便对其内容负责。这一点很重要，原因有两个：第一，确定胶囊内容物的来源；第二，确保提交者和胶囊数据的任何后续用户之间存在通信渠道。这确保了如果发现胶囊内容物有问题，可以联系原始提交人。提交元数据必须包括作者的详细信息，包括联系信息和位置、胶囊内容的概述以及创建胶囊的日期和时间。  
与数字证据报告和决策支持（DERDS）框架和数字证据验证（VODE）框架的合作证明：CODE 旨在容纳通过参与可靠的取证方法而生成的可靠知识，这些方法支持准确的知识创造。提交的任何胶囊必须包含通过与保证质量的VODE和DERDS框架相结合而开发的知识。  
·CODE提交参考：每个胶囊都有一个唯一的参考号，用于识别和存档。  
**2.2　核心数字数据描述符**  
必须创建六个核心数字数据描述符，以创建完整可靠的信息集，以便胶囊中的内容被其他人使用。  
·披露假说/数据源自以下情况的初始假设和假定影响：最终，每个胶囊将提供从业者对某种形式的数字痕迹的解释，这是其案例研究的一部分。要了解从业者为何创建此数据的胶囊，该胶囊必须包括有关发现该胶囊的情况的详细信息。其中包括对最初发现时可能被怀疑为特定伪像/数据的描述，以及如何感知其用途/功能/状态和原因的描述。此外，应强调其对起源的影响。从业者还应提供已解释过的原始数据/工件的净化版本。从业者应提供有关净化过程如何完成的详细信息，以免在进一步的测试/验证工作中损害数据的价值。  
·关于案件情况和相关元数据的伪像/数据记录：从业者必须披露所有围绕伪像/数据的情况，包括案件类型、涉嫌犯罪、文件路径、命名约定、内部结构、指示文件类型和相关的应用程序以及导致其出现在系统上的软件或服务。  
·迭代测试以及与每个子测试有关的伪像/数据：为了使其他子程序依赖于胶囊中提供的解释，必须提供充分记录和透明的测试实践，以显示如何解释所讨论的任何数字痕迹。这也包括提交任何测试中使用的数据，以及从业者执行的测试动作的描述。由于测试将是迭代的， 因此还必须公开每个伪像副本，并记录所有相关的“测试动作”，以解释数据中可能存在的任何修改。从业者还应证明任何结果的可重复性。  
·完全披露所遵循的测试方法以及所涉及和采取的步骤：应披露所采取的测试方法的全部设计和实施情况，以便在今后对工作的任何同行审查中确定透明的审查和方法缺陷。从业者应参考可靠的实验设计框架（FRED）以获得方法论设计支持。  
·披露任何可能对作品的发现或局限性产生潜在影响的相互竞争的假设：从业者应注意并披露可能限制有关解释的可信度的相互竞争的发现。反过来，必须说明测试的任何限制以允许将来进行工作。  
·研究结果的最终解释：共享此类知识的好处之一是，其他DF从业者可以从他人中受益， 这些人开展了扎实的工作，以了解特定数字伪像/数据的工作方式并共享这种解释。因此，对结果的最终解释以及用于分析和显示结果的任何已开发的迭代方法的披露是胶囊的核心。  
**2.3　核心连续性要素**  
DF中的知识共享必须是一个动态且可持续的过程，允许不断的迭代和发展。正如霍斯曼所建议的那样，数字伪像的研究具有特定的使用寿命，其中许多数字伪像本身在软件更新后会经常发生结构变化。结果，每个胶囊内的数据必须能够在可获得附加信息的情况下进行更新，并由承担此项补充工作的从业者添加进一步的验证记录。这些动作构成了每个胶囊的“核心连续性元素”。  
·迭代链：迭代链是所有对原始胶囊中提交的数据进行了额外测试和开发并进一步了解了产品/数据的人员的列表。胶囊内容必须是动态的，以便在数据/产品更新时（例如由软件供应商更新）保持其适用性。然而，这一更新过程必须受到监测，每次数据解释的迭代都明显归因于其作者。每次迭代还必须有所有六个核心的“数字数据描述符”，以便进行任何新的测试。  
·分销链：分销链是所有访问和利用了胶囊中知识的人士的分类账。这包括从业者的详细信息和地理位置。此外，如果胶囊内发生任何数据迭代，则与胶囊互动的人必须注意他们使用了哪个迭代。这样可以进行“知识跟踪”，这有两个好处。首先，通过确定与DF字段的互动程度，有助于量化每个特定胶囊的影响力。其次，如果一个胶囊（如果以后被发现受到威胁并且其内容被识别）是不正确的，则可以追踪所有依赖此知识的人员，并可以防止此不正确信息的任何进一步传播。需要注意的是，应该考虑谨慎对待所有级别的知识共享，但这是有益的。  
·验证链：验证链是按照原始提交者的调查结果列出的所有已对胶囊中提出的调查结果进行验证的人员的列表。这是同行评审的正式记录，有助于确保CODE模型中提供的信息的准确性。  
在理想情况下，如果正确创建胶囊数据， 则数据应该是可靠的。但是，这并不总是现实，因此核心连续性要素是旨在验证共享知识并防止共享不良做法和不准确内容的机制。  

03

**如何创建和共享胶囊，以及何时提交**

  
虽然第2节定义了胶囊必须包含的内容，但接下来的问题涉及如何创建胶囊、何时提交胶囊以及如何共享胶囊。  
**3.1　创建胶囊**  
尽管第2节介绍了胶囊的内容，但以“胶囊格式”收集和存储这些数据提出了挑战，必须解决该问题才能使CODE正常运行。所以必须考虑以下格式方面的困难。  
收集内容：从业者必须从他们的案例中提取数据并进行测试，以便填充胶囊。这项工作可以在一系列工具上进行，每个工具都具有不同的功能和数据导出格式。此外，一些工具可能无法提供合适的导出过程，而该过程很容易被捕获以创建胶囊。这一问题的症结在于，从业者要负担手动填充其胶囊，这可能是一项繁重的任务，可能阻止从业者参与 CODE。结果， CODE成为全面运行的要求之一，就是需要一种“插件”样式的过程，该过程可以快速有效地自动捕获胶囊所需的信息，胶囊可能来源于世界各地的从业者目前正在使用的许多工具中的任何一个。  
一致的、可查询的格式：胶囊的结构必须一致。这样可以自动执行胶囊内容验证，以防止将不完整的胶囊提交给项目，并允许大量查询胶囊内容，以进行分析、搜索和检索。  
胶囊的创建仍然是CODE项目的下一阶段，尽管这项工作的目的是概述CODE必须包含的内容，但未来的工作将涉及其设计和实现。需要与相关DF社区进行接触和协商，以确定CODE在工业实验室环境中运行所需的要求。  
**3.2　何时提交胶囊**  
确定何时提交胶囊是适当的取决于图2中概述的一些因素。第一阶段发生于从业者正进行案件处理工作，这是他们作为DF从业者主要工作的一部分。在进行调查时，如果从业者在系统上遇到“他们以前从未遇到过，并且不存在任何记录或可靠记录的数字痕迹解释”，而他们不得不自己解释此数据，则应创建一个胶囊来捕获该解释。如果在强大的测试后已经生成了解释，则从业者可以在胶囊中共享该解释。其次，从业者作为其案例研究的一部分，可能会遇到已知的数字痕迹，并通过强大的测试来验证现有的解释。这项工作也很有价值，从业者在捕获信息方面有两种选择。如果已知伪像的胶囊已经存在，他们可以更新该胶囊的“核心连续性元素”，以反映他们已经掌握了该知识并对其进行了验证/驳斥。如果胶囊还不存在，那么从业者的工作可以放在胶囊内。

**3.3　如何共享胶囊**  
在DF中，无论形式如何，知识共享都是有益的，但是CODE存在两个主要选项（见图3）。  
![](../Images/ca0a1f0234e3ee2ef478070c5a5ae555.png)图3  与CODE共享知识的选项  
  
内部共享：当被选中的组织存储从业者胶囊并使其可供其从业者使用时，会发生内部共享。胶囊信息的共享不超出组织的权限。尽管此选项不提供跨领域知识共享的好处，但它是当前唯一在物流上可行的选项。胶囊的管理和存储可以由组织内部控制。  
全域共享：全域共享可以说是任何知识共享模式的目标，并且有可能使DF领域获得最大利益。但是，直到像内部共享那样的组织可以负责管理胶囊提交之前，几乎没有等效的机构可以在整个领域内担当此角色。这种方法需要管理机构来管理胶囊，存储并跟踪提交的内容以及与之交互的人员。一种解决方案是在线托管此类项目，其功能应以自治为目标，从而减轻其数据管理的负担。  

04

**结　论**  

  
数字证据图式的胶囊被提供作为促进DF领域“新知识”共享的一种手段。概述了有效共享的要求，并详细介绍了“提交元数据”“核心连续性元素”和“核心数字数据描述符”三类数据描述符。讨论了CODE项目和胶囊结构，强调了DF中其他人可靠利用共享知识所需的要求。胶囊被设计为数字取证调查的质量保证机制，通过提供可靠信息的访问来支持从事案件处理工作的人员。
