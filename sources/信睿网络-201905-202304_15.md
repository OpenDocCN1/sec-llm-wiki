# 如何让未来的物联网更安全

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=Mzg4MDA2NjExMA==&mid=2247488580&idx=1&sn=151cf16c184a9076daa2f1f261f8ecbe&chksm=cf7bbf15f80c360380470d5a57604feab98f7a84be1ff0b178e5a6d2a07244d142411175d2f8&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=Mzg4MDA2NjExMA==&mid=2247488580&idx=1&sn=151cf16c184a9076daa2f1f261f8ecbe&chksm=cf7bbf15f80c360380470d5a57604feab98f7a84be1ff0b178e5a6d2a07244d142411175d2f8&scene=27#wechat_redirect)

物联网安全始于构建安全软件。了解如何将安全性嵌入您的 SDLC 以避免成为黑客的容易目标。

![](../Images/caee9489cce5e296d784ec0620f5e6ec.png)

关于未来的一些事情很容易预测。

将会有更多的设备——数十亿。正如一些专家几年前开始所说的那样，物联网 ( IoT ) 正在迅速成为万物互联 ( IoE )，因为一切都变成了电脑——你的恒温器、炉子、冰箱、洗衣机、烘干机、车辆、门锁——甚至诸如割草机和吸尘器之类的东西。

  

  

   物联网的发展   

  

事实上，连接设备的数量在过去三年内呈爆炸式增长，从大约 70 亿增加到估计的 300 多亿。这种增长没有放缓的迹象。

更难预测的是这对社会意味着什么。如果连接设备的安全和隐私状态继续保持目前的轨迹，那可能是一个反乌托邦的未来。据推测，“智能”设备将充满漏洞，黑客将利用这些漏洞窃取凭据和身份，并通过威胁用户的人身安全来敲诈或勒索用户。Big Tech 扩大的数据收集将使智能手机比现在更具侵入性的监控跟踪器。

  

  

 更强大的物联网安全性 

  

![](../Images/3ab0ac24d9a72de4ef85e0b2b4f40640.png)

但不一定是这样。这可能是一个为所有设备提供动力的软件内置了安全和隐私控制的世界。它还可以设计为在发现漏洞和威胁演变时允许更新和补丁。

它不会使物联网设备防弹—没有什么可能—但它可以使它们更具弹性。更好的软件安全性可能是安全带、安全气囊、防抱死刹车、车道辅助和其他汽车安全功能的数字版本。它们并不能消除事故，但它们可以帮助驾驶员避免事故发生并在事故发生时提供更多保护。

这都是有可能的。现存的工具、技术和方法可以使运行连接设备的软件更加安全和有弹性。他们只是没有被合理的使用。

其原因之一已被广泛报道：用户不关心安全性——至少现在不关心。他们主要关注设备的功能和价格。安全性只是事后才想到的，它还不是消费者的“差异化因素”。因此，制造商为他们提供了他们想要的东西：酷炫的功能和优惠的价格——而没有过多考虑物联网的安全性。

Synopsys网络安全研究中心(CyRC)的高级安全策略师 Tim Mackey表示，最近许多连接的设备不安全的另一个原因是它们的使用寿命，比更新或更换的应用程序、笔记本电脑和智能手机的使用寿命要长几年，少至几个月多到几年。

他说，炉灶、冰箱、洗碗机、洗衣机和烘干机等主要电器的使用寿命长达 10 年以上。

它们也是由制造优质硬件的专家制造的，但在软件安全方面没有太多深度，特别是从长期来看。Mackey说：“10 年前根据当时的最佳实践设计了一些东西，但现在需要应对今天的网络威胁，这意味着什么？” 

  

  

 向安全的范式转变 

  

为这一现实计划需要范式转变。如上所述，虽然困难，但也可能实现。使未来物联网更安全的方法是将安全性构建到软件开发生命周期 ( SDLC ) 中。

那些隶属于软件公司的人可能早就熟悉 SDLC。但是对于那些最近进入连接设备世界的人来说，这里有一个简短的教程。

![](../Images/c0a6921cdf9784bc19cb17e857d00e63.png)

标准的 SDLC 有八个阶段，从企业家眼中的微光到产品在其整个使用寿命期间的维护。这些阶段是：

  

**1.计划**

此阶段包括定义软件将要做什么的要求，并估计成本、调度、采购需求和所需的人员。

但它还应该包括一个安全组件：威胁建模。有时被称为“像黑客一样思考”，目标是超越已知攻击的标准列表，并识别可能的威胁    ，这些威胁是系统构建方式或应用程序或设备预期用途所特有的。

良好的威胁建模包括突出显示资产、威胁代理和控件，以确定攻击者最有可能针对的组件。然后制定补救措施以减少这些威胁。

威胁建模有很多好处，但最重要的是它可以节省时间和金钱。在编写一行代码之前及早发现潜在问题，可以发现传统测试和代码审查可能遗漏的设计缺陷。尽早修复或避免它们更便宜、更快捷。

  

  

**2.代码**

就像它听起来一样。编写软件代码以满足设计要求。

  

  

**3.构建**

现代软件很少是由一个开发团队编写的。它被组装好了。有些组件是专有的，但其他组件来自商业或开源库。

  

  

**4.测试**

这不再是安全团队在 SDLC 结束时探测软件漏洞的单独阶段。它需要无处不在，从威胁建模开始，甚至开始编码，一直到生产。它需要多种测试工具，包括整个开发过程中的静态、动态和交互式测试，以及软件组合分析(SCA)，以查找与开源代码的漏洞或许可冲突。它还需要在部署软件之前进行渗透测试（下面将详细介绍）。

像智能编排这样的解决方案可以管理所有这些 AppSec 分析工具，而不会减慢开发速度。通过使用每个组织设置的预定义风险策略，它可以在正确的时间触发正确的安全测试。结果是向开发人员和安全团队提供正确的信息，以确保在所有管道中遵守其策略。

  

  

**5.发布**

此阶段涉及开发团队在不同环境中打包、管理和部署版本。

  

  

**6.部署**

软件发布到生产环境中。

  

  

**7.操作**

该软件用于生产环境。

  

  

**8.监控**

该团队跟踪软件的性能，包括系统性能、用户体验、新的安全漏洞以及系统中的错误或错误分析。这是向用户推送更新或补丁以关闭漏洞或响应新威胁的阶段。

请注意，有效的 SDLC 不应在产品发货时结束。它一直持续到该产品的使用寿命。尽管在开发过程中“构建安全性”可以最大限度地减少错误和其他缺陷，但现实情况是没有完美的软件。因此，保护物联网设备意味着维护它们。

  

  

SDLC的演变

  

使安全性成为构建软件的基本组成部分的另一个主要关键是了解SDLC是如何演变的。如今，软件开发的速度甚至比几年前快了几个等级——从马车时代到现代汽车高速公路的数字版本。

为了使安全性跟上敏捷和DevOps交付实践的步伐，必须实现软件开发和测试的自动化。

这是构建成熟度安全模型 （BSIMM） 所指出的趋势，这是 Synopsys 的免费年度报告，用于跟踪各个垂直行业组织的软件安全计划 （SSI）。最近的报告 BSIMM12 对 128 个参与组织的 SSI 进行了深入分析。

该报告指出，安全团队正在向DevOps团队提供资源，人员和知识，以确保将安全工作内置到软件交付的路径中。BSIMM12 还观察到，QA 自动化中的安全测试在过去两年中翻了一番，许多组织都在收集数据并推动其 SDLC 或治理流程的改进和效率。

  

  

开发人员在线学习

  

但是，要跟上开发速度，安全性需要的不仅仅是自动化。可以这么说，人类仍然必须主持节目。

以当前的开发速度构建安全软件不仅需要为开发人员提供所需的工具，还需要提供培训 - 这是一个好的学习计划可以提供的。

**1.课程介绍**

本课程主要根据物联网的组成部分中存在的安全问题进行讲解,同时讲解IOT安全研究中常用的技巧,比如硬件调试、固件提取、固件模拟、协议分析、逆向分析、动态调试等。

  

  

**2.课程效果**

通过本课程的学习，能够对物联网的组成有更深入详细的理解，并且可培养 运算逻辑能力，并对各层面存在的安全问题有一定见解，能完成简单的物联网安全分析。
