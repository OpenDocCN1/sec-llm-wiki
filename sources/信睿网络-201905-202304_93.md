## 11.misc1

仔细观察此密文发现字符是从0-f的，猜测是一个十六进制的密文，两个为一组的十六进制转换成10进制后-128（偏移量为128）在转成ascii码得到flag值

```
import re
s = 'd4e8e1f4a0f7e1f3a0e6e1f3f4a1a0d4e8e5a0e6ece1e7a0e9f3baa0c4c4c3d4c6fbb9e1e6b3e3b9e4b3b7b7e2b6b1e4b2b6b9e2b1b1b3b3b7e6b3b3b0e3b9b3b5e6fd'
num = re.findall('\\w{2}' ,s)
flag = ''
for i in num:
    ch = chr(int(i,16)\-128)
    flag += num
 print(flag)
    
```

15.hit-the-core  

下载文件发现文件后缀是.core文件，strings看一下字符串发现了一个较长的字符串。  

![](../Images/23968932ff113cd937ca07904c2b58e9.png)

  

这么 长的字符串，{}位置正确，就不可能是凯撒，栅栏。仔细观察这个字符串，发现前面大写的字符串为alexctf，每个字母之间只隔了四个字母，用python写一个脚本提取以下，最后便得到了flag值

  

```
num\='cvqAeqacLtqazEigwiXobxrCrtuiTzahfFreqc{bnjrKwgk83kgd43j85ePgb\_e\_rwqr7fvbmHjklo3tews\_hmkogooyf0vbnk0ii87Drfgh\_n kiwutfb0ghk9ro987k5tfb\_hjiouo087ptfcv}'
flag = ''
for i in  range(3,len(num),5):
    flag += num\[i\]
print(flag)

```

## 17.2-1

打开这个png文件发现，无法显示，用winhex打开，发现文件头错误，更改文件头为89 50 4E 47

![](../Images/a4b58a71cd8bb3ac38c70efe32967a6c.png)

  

修改完毕后，还是无法打开，我们可以看到，第二行的位置，前四字节代表宽度，后四字节代表高度，宽度字节都为0，在这里如果不会判断的小伙伴可以扔到linux里，windows下可以打开，但是linux里会报错的。那这里就涉及到一个crc校验检验错误分析的知识点，感兴趣的小伙伴可以去自行查阅，接下来我们用python爆破crc宽度

![](../Images/195a8927f23056fc9d01e380799a22dd.png)

爆破出宽度为709,十六进制转换后得到，0x2c5

![](../Images/647c083e844d52bfa301dfe9834af33f.png)

  

接下来我们在winhex中将宽度字节改为02C5便得到了flag为wdflag{Png\_C2c\_u\_kn0W}

![](../Images/b7c189a730e9c53139f953799aedf021.png)
