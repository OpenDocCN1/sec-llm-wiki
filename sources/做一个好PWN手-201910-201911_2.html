工欲善其事,必先利其器
做pwn的时候脚本的自动化程度越高也就越能将精力放在漏洞利用上面，所以参考大牛的脚本对自己的exp模板做了一些修改。

主要解决的三个问题如下

  1. 高版本libc调试

  2. libc源码调试

  3. PIE地址偏移


  • 高版本libc调试

现在很多PWN题目都考察新版本libc中的tcache相关利用,附带着libc2.27 或2.29的文件, 但是ubuntu16.04的默认是libc2.23, 之前都是直接开新的虚拟机，但其实也可以通过patch文件实现高版本libc的调试。

以护网杯mergerheap题目为例,给出的是libc-2.27.so，本机环境ubuntu 16.04，通常情况下使用pwntools 设置环境变量去加载特定libc

例如
from pwn import *p = process("./mergeheap",env={"LD_PRELOAD":"./libc-2.27.so"})p.interactive()

但是这样会启动失败

把ubuntu18.04 的ld拷贝到当前目录，使用patchelf 修改程序的ld路径

patchelf –set-interpreter ./ld-linux-x86-64.so.2 ./mergeheap

再执行exp.py 就能跑起来了


  • 源码调试和处理PIE偏移

libc源码调试能够加深对于libc中heap分配,IO处理等流程的理解,也更利于快速定位问题，例如错误提示"corrupted double-linked list"，从源码中定位到如下
    if (__builtin_expect (FD->bk != P || BK->fd != P, 0))             \      malloc_printerr (check_action, "corrupted double-linked list", P, AV);  \

就知道是unlink操作 fd和bk的校验没有通过，再检查内存中对应的值即可


  • 什么是PIE


    PIE全称是位置独立的可执行区域(position-independentexecutables)，它本质上是一种随机化，将data和code段的地址都随机化变得不可预测。heap题目一般都是保护全开的，可以用checksec来检测。

开启之后反汇编如下

只能看到一些偏移，从堆的角度来看无非是多泄露一个地址，但是PIE保护给调试带来了一些困难。如果想断到程序中某函数的位置，开启PIE时我们只能用偏移+基地址的方式下断点。


首先看一位大佬的exp
from pwn import *
context.terminal = ["tmux","splitw","-h"]def dbg(breakpoint):    glibc_dir = '/opt/glibc-2.23/'    gdbscript = 'directory %smalloc\n' % glibc_dir    gdbscript += 'directory %sstdio-common/\n' % glibc_dir    gdbscript += 'directory %sstdlib/\n' % glibc_dir    gdbscript += 'directory %slibio\n' % glibc_dir    elf_base = int(os.popen('pmap {}| awk \x27\x27'.format(io.pid)).readlines()[1], 16)if elf.pie else 0     gdbscript += 'b *{:#x}\n'.format(int(breakpoint) + elf_base) if isinstance(breakpoint, int) else breakpoint
    gdb.attach(io, gdbscript)    time.sleep(1)
elf = ELF("./mergeheap")io = process("./mergeheap",env={"LD_PRELOAD":"./libc-2.27.so"})dbg(0xbd5)
io.interactive()
这段exp解决了上面的两个问题

  1. 使用gdb directory命令指定libc源码的目录,当调试到libc相关函数的时候即可定位到源码

  2. 使用pmap将程序地址取出来，指定偏移即可断到特定函数地址


  • 最后

    最后我还是采用了编译自带符号的libc.so,好处是不用麻烦指定很多路径，先都编译好一劳永逸。使用时指定libc版本同时让脚本适配一下程序对应的ld和libc路径。

下载编译libc时借用了ray_cp大佬的脚本 

https://github.com/ray-cp/pwn_debug/blob/master/build.sh

一键运行，下载了很多版本的libc，从2.19到2.29


完整的exp模板如下

#!/usr/bin/env python2# -*- coding: utf-8 -*-from pwn import *import sysimport osdebug = 1exe = "./mergeheap"
r = lambda x:io.recv(x)ru = lambda x:io.recvuntil(x)rud = lambda x:io.recvuntil(x,drop=True)rul = lambda x:io.recvline()sd = lambda x:io.send(x)sl = lambda x:io.sendline(x)sea = lambda x,y:io.sendafter(x,y)sela = lambda x,y:io.sendlineafter(x,y)
context.terminal = ["tmux","splitw","-h"]elf = ELF(exe)context.arch = elf.arch
if debug:    context.log_level = "debug"
def pre(libc_version):    glibc_dir = '/glibc/{arch}/{libc}/lib/libc-{libc}.so'.format(arch=elf.arch,libc=str(libc_version))    io = process(exe,env={"LD_PRELOAD":glibc_dir})    ld_dir = '/glibc/{arch}/{libc}/lib/ld-{libc}.so'.format(arch=elf.arch,libc=str(libc_version))    cmd = "patchelf --set-interpreter {} {}".format(ld_dir,os.getcwd()+"/"+exe)    os.system(cmd)    return io def dbg(breakpoint):    elf_base = int(os.popen('pmap {}| awk \x27\x27'.format(io.pid)).readlines()[1], 16)if elf.pie else 0     gdbscript = 'b *{:#x}\n'.format(int(breakpoint) + elf_base) if isinstance(breakpoint, int) else breakpoint    gdb.attach(io, gdbscript)    time.sleep(1)
if len(sys.argv)>1:    io = remote(sys.argv[1],int(sys.argv[2]))    #libc = ELF("./libc.so.6")else:    io = pre(2.27)    libc = elf.libc
io.interactive()
