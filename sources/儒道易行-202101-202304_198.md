## 0x02.CSRF(Medium)

相关代码分析![](../Images/934fc30f6bc1efe156f83b49b7c0d8d3.png)eregi(string pattern, string string)检查string中是否含有pattern（不区分大小写），如果有返回True，反之False。可以看到，Medium级别的代码检查了保留变量 HTTP\_REFERER（http包头的Referer参数的值，表示来源地址）中是否包含SERVER\_NAME（http包头的Host参数，即要访问的主机名），希望通过这种机制抵御CSRF攻击。![](../Images/fbbdc0ceb457251b4371577fbcd22ef8.png)过滤规则是http包头的Referer参数的值中必须包含主机名（这里是x.x.x.x）我们可以将攻击页面命名为x.x.x.x.html（页面被放置在攻击者的服务器里，这里是x.x.x.x）就可以绕过了构造CSRF的poc，保存成HTML文档

*   

```
`<iframe src="../csrf/" onload=alert(frames[0].document.getElementsByName('user_token')[0].value)>`
```

![](../Images/da025088e81f4832950f8401f3ce69f4.png)放包后，每次打开页面都会弹出 token 值![](../Images/c3384a16c980bb042259175e2cf342bc.png)在页面弹出的iframe框里修改密码，就可成功修改![](../Images/cc2651063ba82de2f91d2081a9659bf3.png)之后可以用修改后的密码去登陆了
