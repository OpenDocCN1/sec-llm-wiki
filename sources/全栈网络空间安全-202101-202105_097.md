# 通俗地聊零信任架构搭建

简单通俗的观点——“组织可以通过改造4A实践零信任架构。”着急的读者看到这里可以返回了，下面进行解释。

 

经过最近数次内、外部交流，大家对零信任这个话题还有疑惑。本文将结合我的职业经历，试图用一种更容易理解的方式对其进行解释，期望对零信任架构实践起到一定帮助。

 

有段时间，国内零信任市场被分为两个流派：传统厂商及零信任厂商。对于后者，俨然一种“零信任只有新晋力量才能掌握”的现场仰视感。这种局面直到2019年9月才逐渐被打破，彼时NIST发布了第一版《零信任架构》草案。随着2020年8月《零信任架构》正式版的发布，终于为业界开启了一盏明灯，指引着我们到达零信任的彼岸。

 

按照NIST的定义，零信任有三种实践架构，分别是增强身份治理、微隔离和软件定义边界。通过增强身份治理实现零信任架构，说的是以IAM为基础，将主体身份作为策略创建的关键组件实现零信任架构，使原有以系统账号、口令为中心的静态管理方式上升为以自然人为中心，再加上设备身份和状态提供辅助支撑的动态方式。以便提供比账号、口令更可靠的基于上下文的身份确认与授权。  

![](../Images/c33ca3ffbd5c0026ef204b0ab4b63a39.png)

而微隔离和软件定义边界这两种技术实现零信任架构则将IAM作为了它们的基础支撑。所以，无论实践哪种架构，IAM都是一个绕不过的话题。再说得绝对点：无论谁把零信任作何种变化，都离不开身份、权限、认证这些IAM的基本能力！

 

IAM是什么？某百科上这样介绍：  

![](../Images/3df2ecbf5bb8695026560ecb8e6d9a3c.png)

Gartner这样定义：

IAM的主要目标是确保正确的人或“物”出于正确的原因，能够在正确的时间、正确的地点从正确的设备中获取到正确的资源（应用、数据等）。

 

文字都看得懂，但对应不上实际的东西，这会显得特别的抽象和空洞。进而沦为口号、概念，却不知其为何物。且慢，4A见过吧？可以将4A看作是IAM的一种实现。如果不知道4A的话，堡垒机呢？可以将4A理解为“更强大的堡垒机”，这样聊下去我们就在一个频道上了。

 

在国内说到4A，就不得不提起它和《萨班斯法案》的关系。2001年安然和2002年的世通事件，彻底打击了（美国）投资者对（美国）资本市场的信心。在这种情况下，美国国会和政府加速通过了《萨班斯法案》。法案对在美国上市的公司提供了合规性要求，使在美国上市的公司不得不考虑控制IT风险在内的各种风险。在这一背景下，部分赴美上市的中国企业开始了漫长的4A平台建设。就这样，4A平台从设想到落地，十多年来不断迭代完善。

 

不过可惜的是，尽管4A在这些大企业中与业务结合得很深，但更多的企业却无法接纳。4A难以落地很大原因与大量的资产和主、客体账号梳理导致的人力财力投入大；建设周期长；执行层面存在阻碍有关。各种其他客观原因在此就不表了，可参考市场分析报告。多种因素叠加最后的结果是，国内市场对4A并不认可，“养在深闺人未识”。

 

回到前面所说的4A是IAM的一种实现，那将4A进行改造以适应零信任对IAM的需求这条路，真香！现在看来零信任架构的IAM部分有着落了，那么“信任算法”怎么办，这可是零信任的大脑。“信任算法”实现起来难么？有难度，但如有积累不怕，用UEBA支撑岂不美哉？在4年前，我作为早期采用者将其引入到国内，并带领团队进行了产品化实践，用于持续关注内部威胁，可移步[《正确开启用户实体行为分析(UEBA)番外篇：SIEM与UEBA》](https://mp.weixin.qq.com/s?__biz=MzI3OTQxNDg5MQ==&mid=2247483708&idx=1&sn=ff7221383b0879c2a53f70f47fa3a47c&scene=21#wechat_redirect)进行了解。

 

最后，还差什么没讨论？PEP！总得有可以被指挥的安全能力充当门户、网关吧。可以将堡垒机中内置的IAM能力进行卸载。这一刻，堡垒机充当了运维场景下的PEP。再接着捋：将负责应用的安全能力作为PEP，可以支撑应用访问场景；将负责系统间API数据交换的安全能力作为PEP，可以支撑API互访、交换场景；将负责工作负载保护的安全能力作为PEP，可以支撑微隔离场景，等等。

 

至此，零信任架构实践解构完毕。
