> 我们知道，OSPF 路由器想要建立邻居，会先互相发送 Hello 包确认对方跟自己是否“合适”，只有合适才会建立成功。

# 6、网络类型不一致

修改 R3 的 OSPF 网络类型

```
interface GigabitEthernet0
```

*   1
    
*   2
    

![](../Images/8ab0a1f52d9b1f199c7ed1f3bb7475e0.png)  
![](../Images/76b4cd23ebe38ef3f52ebe8d6f011e8a.png)  
可以看到，R3 虽然与 R1 建立了 Full 的邻接关系，但是却没有 R2 的路由信息，导致 R3 并不能与 R2 进行通信。  
造成这种现象的原因是由于路由信息是由 LSA 计算得来的，而网路类型的不同会导致 LSA 不同，所以路由信息就会有错。这里不讲解关于 LSA 的信息，可以自行了解。

> 我们知道，OSPF 有四种网络类型，上述只是展示了广播网络与 P2P 的情况，那关于其他类型呢？  
> 其实，能否建立邻居关系，就是看这种网络类型下的 Hello Timer，上述广播网络与 P2P 网络的 Hello Timer 正好相同（10s）所以可以建立邻居关系，  
> 而 NBMA 与 P2MP 的 Hello Timer 是 30s。这就导致有些网络类型的hello时间间隔不一致导致邻居建立不起来。

# 总结

影响 OSPF 邻居关系建立的的原因有以下几点  
1、MA 网络（以太网、FR、ATM）掩码不一致（点到点网络不受掩码影响 ）  
2、OSPF 设备 RID 相同  
3、同一链路区域不同  
4、Hello 于 Dead 时间不匹配  
5、MTU 不同（华为设备默认不检测 MTU，需要手动配置<接口下 ospf mtu-enable>）  
6、网络类型不一致 （由相应网络类型对应的 Hello Timer 影响）

7、接口认证类型不一致

8、接口认证KEY不同
