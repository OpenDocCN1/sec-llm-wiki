容器和微服务正在彻底改变计算。但是防火墙可以帮助保护这些安全吗？下一代防火墙（NGFW）应该能够处理最新的威胁和数据中心设计，但在新的云微服务环境中却不足。这是下一代防火墙与容器防火墙的比较。


在我们了解下一代防火墙与容器防火墙的功能之前，让我们看一下容器和微服务的属性。容器是虚拟化应用程序工作负载趋势的一部分。虚拟化的工作负载，无论是容器，IoT设备还是无服务器计算，都提供了大量的声明性元数据，可以从中导出安全策略和决策。

微服务的属性–东西方流量激增

从单一应用程序到基于容器的微服务的迁移带来了很多好处，但同时也改变了通信模式。从网络和安全性角度来看，最重大的变化是现在主机内部以及主机之间的东西方流量（或内部流量）激增。尽管可以对每个运行中的容器进行加固并公开有限的接口，但攻击者还有更多机会可以探查和发现漏洞。
容器的设计可以在几秒钟内完成部署，编排系统可以根据服务需求和可用的主机资源在同一主机上或跨主机启动新容器。每个容器都有自己的映射网络接口，这些接口可以动态分配和释放。

容器部署的安全性问题

随着容器的不断启动和停止，以及通过持续集成和持续交付（CI / CD）管道快速将更新部署到应用程序，在网络层监视和保护容器流量变得非常困难。传统防火墙和下一代防火墙的设计主要是为了作为外部或南北向流量的网关，不能保护容器流量。
传统防火墙不仅很难看到主机内部或主机之间的东西向内部流量，而且它们也无法跟上容器启动和消失时不断变化的趋势。正如一位网络安全架构师所说的那样：“在容器化的世界中，您不能搞砸iptables或手动更新防火墙规则。”

为什么在运行时监视容器很重要？原因之一是频繁使用开源软件来构建容器应用程序。通常，开发人员可能不理解随使用的每个开源软件包或库引入的应用程序漏洞。而且一旦投入生产，通常很容易就无法确定哪些容器易受发现的新漏洞的影响，而这些漏洞通常在投入生产后数年就可以找到。

云原生容器防火墙的主要功能

那么什么是容器防火墙？容器防火墙提供了与下一代防火墙在边缘提供的大部分相同的保护，但是在云原生环境中可以处理所有容器流量。这包括东西向，南北向以及集装箱到非集装箱的运输。
原生云容器防火墙能够隔离和保护工作负载，应用程序堆栈和服务，即使单个容器在向上，向下或跨主机扩展时也是如此。它也必须像传统网关防火墙一样保护外部网络和传统应用程序的入口和出口，除了容器感知。

这是云原生容器防火墙的主要功能

  • 基于意图的情报。通过元数据和行为分析了解应用程序的意图。特点包括：
  • 声明式自动保护。发现应用程序行为和安全要求，并适应更改和更新。
  • 基于白名单的规则。假设零信任模型并定义允许的行为。
  • 基于应用程序（第7层）的策略。不使用IPtables或仅使用L3 / L4规则。
  • 容器级保护。丢弃可疑连接或隔离整个容器。
  • 与容器编排集成。可跨主机，云扩展并适应更新。
  • 支持容器平台和运行时引擎。与系统安全性库，覆盖网络和Docker引擎无缝运行。
  • 支持常见的容器化应用程序协议。基于流行的应用程序协议（例如redis，mysql，mongodb）识别并执行策略。
  • 适合CI / CD流程。使用REST API集成到自动化管道中，以支持脚本，Jenkins等。
    • 容器防火墙还包括许多下一代防火墙功能，例如：
  • 第7层深度数据包检查（DPI）。许多微服务通过HTTP进行通信，因此基于应用程序协议进行检测和保护至关重要。
  • 威胁防护。防御内部应用程序级别的攻击，例如Web应用程序防火墙（WAF）设备中常见的DDoS和DNS攻击。
  • 黑名单规则。能够基于IP地址，范围或其他L3 / L4策略设置规则。
    • 因为容器防火墙主要是为了保护容器流量，所以并不意味着要在边缘取代NGFW，IDS / IPS或WAF。但是，它必须防御可能源自内部的常见的已知应用程序攻击。

    下一代防火墙（NGFW）的主要功能

    下一代防火墙为传统数据中心提供了高级保护，在传统数据中心中，需要保护来自互联网或不受信任网络的流量。
    通常，下一代防火墙将包括以下功能：
  • L7应用程序意识。通过检查第2-4层以及第7层网络上的应用协议来监视连接。
  • 通过入侵检测/保护系统（IDS / IPS）进行威胁检测。IPS系统将通过使用签名，行为和其他检测技术来检测和阻止已知攻击。
  • 状态检查。流量检查和保护策略基于连接状态。NGFW不仅可以基于L2-4，而且还可以基于第7层强制执行有状态检查策略。
  • 用户身份策略。对资源的访问可以由用户身份控制，而不仅仅是IP地址或连接类型。在容器防火墙中，类似的功能是基于行为学习来限制容器之间的通信量。
  • 支持路由和桥接模式。根据拓扑和要求，防火墙可以部署为网桥（L2）和/或路由器（L3）。容器防火墙是在主机上部署的，并且像桥接器一样运行（监视线路），以监视数据包并在启用后进行阻止。

    像任何环境一样，容器化环境需要具有多个保护层的分层安全策略。在整个“ 构建，运送和运行”周期中构建安全性至关重要。对于运行时可见性和保护，容器防火墙扮演着核心角色。
    容器防火墙解决方案不仅可以提供网络层检查和保护，而且可以监视主机和容器进程。由于其分布式性质，基于主机的容器防火墙可提供有效的本地监视和保护。通过与Docker引擎，业务流程和容器管理工具的集成，容器防火墙还可以提供主机和容器过程检查，安全审核和测试以及资源监视。容器防火墙通常包含以下附加功能：
  • 主机进程监视和安全性，用于特权升级，可疑进程和突破
  • 注册表，主机和运行中的容器中的漏洞扫描
  • 审核并遵守CIS Benchmarks安全测试
  • 数据包捕获，用于取证和调试。
    • 保护容器部署需要一些新技术，例如容器防火墙以及传统解决方案，例如下一代防火墙。对于新的虚拟化工作负载，需要应用程序智能，声明性策略以及与云原生编排工具的集成来监视和保护它们。
