cookie

```







Cookie实际上是一小段的文本信息。客户端请求服务器，如果服务器需要记录该用户状态，就使用response向客户端浏览器颁发一个Cookie
```

cookie的缺点

```





如果浏览器使用的是 cookie，那么所有的数据都保存在浏览器端，
```

ssession

```





Session机制是一种服务端的机制，服务器使用一种类似散列表的结构来保存信息。
```

session缺点

```





一般是寄生在Cookie下的，当Cookie被禁止，Session也被禁止
```

cookie与session区别

```



具体来说cookie机制采用的是在客户端保持状态的方案，而session机制采用的是在服务器端保持状态的方案。同时我们也看到，由于采用服务器端保持状态的方案在客户端也需要保存一个标识，所以session机制可能需要借助于cookie机制来达到保存标识的目的
```

token

```









令牌，是用户身份的验证方式。
```

session与token

```


作为身份认证，token安全行比session好；
```

token与cookie

```

Cookie是不允许垮域访问的，但是token是支持的， 前提是传输的用户认证信息通过HTTP头传输；`token就是令牌，比如你授权（登录）一个程序时，他就是个依据，判断你是否已经授权该软件；cookie就是写在客户端的一个txt文件，里面包括你登录信息之类的，这样你下次在登录某个网站，就会自动调用cookie自动登录用户名；session和cookie差不多，只是session是写在服务器端的文件，也需要在客户端写入cookie文件，但是文件里是你的浏览器编号.Session的状态是存储在服务器端，客户端只有session id；而Token的状态是存储在客户端。`
```
