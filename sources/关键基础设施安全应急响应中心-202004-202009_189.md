# 构建基于攻防实效的安全体系，有效解决通报问题

最近出去走访了几个大客户，每次交流都有很大收获。这种收获并不在于技术本身，实际上网络安全除了应用场景有切换之外，十几年来本质从来没有变过，不管包装了多少新的名词和概念，说一千道一万，最终还是要看你是否防得住。收获是从另一个维度，我能更加对大甲方的现状感同身受，设身处地的想一想，大家就不像以前那么偏激。

网络安全市场这五年来的发展是很明显的，针对网络安全的法律法规快速增加和完善，从网络安全法、151号文、到漏洞管理办法、隐私数据相关的法律，以及来自各垂直行业的网络安全管理制度，都预示着风雨欲来。与此同时，各种由安全监管部分发起的“攻防演练”以及“漏洞通报”把各单位逼到一个不得不处理的疲惫状态。**以前网络安全部门是个肥差，现在变成摊手山芋，唯恐避之不及。**

排名不好都算了，不求有功但求无过。但现在无过都是个奢望，被抓典型揪小辫子，行业内来一个公开批评，都是大单位，这个污点实在有损形象影响发展，无路如何都要解决，于是加大安全投入力度，增加费用。**国家一旦真要把网络安全上升到国家安全，就把最后一张窗户纸给捅破了。**你们是国家关键信息基础设施单位，任何时候你们的业务断了国家也就处于很危险的领地。你们在“战时”首当其冲，必然会被敌人的精英部队的炮火瞄准，狂轰乱炸，守不住你就要掉脑袋。

所以突然一下，雷锋多了，等待扶着过马路的老奶奶就不够用了。安全服务人员的待遇水涨船高，以前一天1000不算少了，现在一天10000也不算多。阿猫阿狗全部进来混水摸鱼，连大厂也扛不住这么大的需求量，都是重要客户，没办法，刚招一个新员工就急不可待地往外派，你没有火眼晶晶还真没办法挑出来谁是南郭先生。

于是，大单位也开始意识到这个问题了，“你说，我们该买的产品也买了，内部也经常进行安全评估测试，什么服务都不落下，来交流的公司我们也都愿意试试…”，领导苦笑了一下，“但是，为什么还是老被通报呢？” 今天来一起刚处理完，还没缓过神，啪，又扔过来一个。一个月下来十几个，源源不断，没完没了。这种局面还要维持多久，什么时候是个头哇？领导们都是业务出身，能力都很强，一门心思想着发展业务，没想到今天，做业务的雄心万丈还没来得及部署，大量的精力花在了打蚊子这件事上，它们在你耳边呅呅呅个不停，你重重一出手，抱着同归于尽的心，给自己狠狠来了一巴掌。脸都红了，手掌翻来，啥也没有。它们又呅呅呅的过来了…

演习防不住，通报无休止。安全厂商还在跟唐僧一样说“漏洞是不可杜绝的，事件是一定会发生的”，得了，跑赢其他单位成为了行业“共识”，我不想我有多高，只要他们垫底了，今年我们就算没白费。

究其原因，**战时需求就是扛得住打，就逼着大家从“合规型”思维往“价值型”思维发生转变。**国家进一步要求，你们不仅仅是要满足部署防护的基本动作，同时也要对最终的防护结果负责，至于怎么做，你们自己看着办。

以前我并不会陷入这种纠结，落后就挨打，你不重视安全所以出了问题，那是你活该。现在，当我越来越了解客户的实际情况，越来越从客户角度来看待这些问题，我发现我们能做的很多，尤其是一些基础工作。当我们尝试帮助其中几个大客户来切实解决这些问题，以及也得到了明显的效果验证后，感觉是时候做一个阶段性的总结。

首先一个根本思路的转变，咱们确实不应该想着去杜绝漏洞，这是不可能的，咱们也不要想着跑赢其他单位，倾巢之下焉有完卵，死的时候只有先后顺序之分，没有本质区别。真正的目的是为了跑赢盯着我们“黑客”，我们不妨假设对方是一个国家的网络部队，是一群商业黑客，亦或者是“友善”的通报方。基本的原则还是通过构建核心能力形成有效的防御体系和响应速度。

**我们稍微看一下关基单位现在出现的问题：**

**一）网络资产数量庞大：**我们从早期接触数万的“海量”资产，到后来几十万，几百万，几千万，最后我们看到过亿资产的时候，我们才知道情况有多么复杂；

**二）业务更新迭代速度快：**频繁上线下线业务，没有人有意识先要告知安全部门；

**三）资产组成结构多样：**大单位对应上百家子公司，网络设备多种多样，网络组成异常复杂；

**四）大量精力放在“漏洞噪音”，容易放弃治疗：**十个漏洞轻松修；一千个漏洞努努力也能修，十万个漏洞无从下手；

**五）大量基层员工缺乏安全意识：**千里之堤溃于蚁穴

**六）安全技术团队的管理事务性工作太多：**四个安全工程师，三个做信息安全，只有一个做网络安全，管学习上层的指导文件和处理通报时间都不够；

**七）现有防护体系没有经过实战的攻击检验**

**八）目标制定不清晰，并行任务太多，没有很好的聚焦主要矛盾**

基于我们之前跟相关单位配合的经验，不是所有漏洞都会被通报，如果这样，大家很快也会放弃治疗，而且通报方也容易失去公信力。通常通报的漏洞满足几个基本情况：首先是重点关注关基单位；其次一定是高危漏洞；再有漏洞必须是准确的，也就是说肯定是该漏洞能够明确带来肉眼可见的危害。有没有特殊情况？也是有的，比如最常见的沟通在于资产归属的正确性问题，一个说是你的，一个说不是我的；还比如有时候低危漏洞也会被通报，那是有人要做“政绩”，那你自认倒霉吧。有时候可能行业主管单位无法聚焦到主要矛盾，眉毛胡子一把抓，无法很好的引导技术的正确发展方向，作为关基厂商要淡定，这并不是你的错，当然大体上的通报还是很有公信力的。大家很容易进入两个死胡同，要么是什么也不做，但自我感觉良好，“我过了等保，你凭什么说我有漏洞”的质疑，这种诡辩曾经让我瞠目结舌；再有就是很容易管他漏洞级别什么问题都必须解决，而且要求立刻马上。**所以关基单位年年都要构建“全面宏伟”的整体防护工程，过一两年又全面要求重新建设**。

就好像共产主义不是一天建成的一样，你如果生生的将他拆成两年计划，喊口号要分两期达到目标，那就把自己逼成了大跃进。大家高举拳头呼声震天，内心茫然，机器一般往后执行，疲惫不堪，但是看着周围人眼里的“坚毅”，又觉得还是自己不够好，于是声音就喊得越发大声。结局怎么样，大家其实也都清楚，累死了活也没干成。**通报是手段，不是目的，不是为了通报而通报，而是为了更好地构建有效的防护体系，真正的达到动态安全。**

如果再要类比，我觉得可以类比为教育小孩，刚出生连爬都不会，我们看着连眼睛还睁不开的小朋友，想象着某一天他叱咤风云。但是你知道没有知识是不行的，学知识肯定要上大学吧，要上大学肯定要上中学吧，那就肯定要上小学吧，上小学至少要先学会走路吧……你再看着这个连眼睛还睁不开的小朋友，暗自决定，还是先教他学会叫爸爸再说。

计划终归是要做的，防护效果终归还是要达到的，我们想想看安全防护的终极目标是什么？我个人理解是能够实现对未知威胁的发现，以及在造成损失前进行有效地解决。如果你把终极目标定义为“消除一切漏洞”，我只能说理想可以有的。警察叔叔的理想如果是“消灭一切小偷”，那你可以通过上下五千年的历史来做个总结，再预判一下未来的五千年小偷这个词会不会成为历史。而如果我们正确理解警察叔叔是来维护国家安全和保护人民，我们就能明白保持一种动态的相对安全，才是一种可能的效果。最终网络安全的体系能否有效，也是一种动态的持续的效果，我认为最根本的判断标准就是，能否把黑客的成本增加到足够高，以及把黑客的风险增加到足够高，因为整体上“黑客的驱动力=收益/（技术成本+风险成本）”。对应关基单位而言，在黑客眼里就是一个香馍馍，敌对势力看着都垂涎欲滴，所以收益非常大且是恒定的。风险成本对于来自内部的攻击者是威慑力非常高的，但是对于外部尤其是对视国家而言，风险陡然降低。那么最后影响黑客攻击欲望的，只剩下技术层面防护的有效性了。

大家的目标倒是高度一致的，无论从监管方的角度，还是从甲方单位的角度，加上乙方安全公司的角度，大家最终是可以达成一致意见的，总之就是帮助关基单位达成最终能够感知未知威胁和动态防御的效果。所以，这不是一个战略的问题，只是一个战术的问题，这就好办多了。

**构建攻防实效的安全体系，整体可以分三个阶段：**

**一）摸清家底，构建完整的资产库，聚焦“靶标漏洞”**

这个阶段一定要学会抓大放小，聚焦主要矛盾，而不是一口吃个大胖子。这里的资产库是从网络安全角度梳理的“暴露攻击面”，不是传统的资产台账系统。一个不能清晰的梳理暴露面的企业，安全防护就是典型的“马奇诺防线”，就是纸老虎，一打就溃。同时，如果我们把精力花在了大量的“漏洞噪音”上，很容易进入无的放矢，疲于奔命，最终由于没有效果而放弃治疗。很多人可能不愿意相信和接受，自己连这个第一阶段都还没有达成。我们有一个非常容易的判断方法：每月平均通报次数是不是低于5个？通报涉及的IP资产在不在内部的安全资产库内？如果答案都是否定的，我建议咱们先不要随大流去讨论住别墅的事情，先把茅草屋加固一下，避免一阵风就刮跑了。

**二）结合业务，联防联控，构建快速响应机制**

通常到过了第一个阶段，咱们能够比较有效的解决通报的问题，一来是被通报漏洞涉及的资产都属于已知资产，二来漏洞也是已知漏洞进行了提前处理，所以就能将通报的每月次数压低到3个以下。经过我们的实际测试，在一个大单位资产太多变化太快，我们尽可能的去降低未知资产的比例，前期比较明显，一旦做到了未知资产占比控制在8%以下的时候，就很难再提升了，总会有新的资产上线或者变动，导致比例曲线的波动起伏。

这个阶段，不能再只满足于已知资产和已知漏洞，我们会发现即使关基单位由瞎子变成明眼人了，咱们能看到各种问题，但是这种问题要落地到业务执行中去，否则咱们就相当于脑瘫，头脑清楚，手脚不听使唤。举个很简单的例子，发现一个ip存在漏洞，你知道是哪个业务以及责任人是谁？这些责任人从拿到一个严重漏洞能否在24小时之内修复解决？

一旦你有了完整的资产库，我们就尽快把互联网边界资产纳入整体防护体系。黑客没有底线，狗洞他也钻，只要有缝，他们就一定进来。所以防火墙，ids，威胁情报，soc全开起来，把日志收集起来，把流量收集起来，先守边界，再守核心网络。分田到户，还是那句话，抓大放小。实在梳理不清楚或者说实在还没有来得及防护的网络，你就假设一定会丢，网络上做好相应的隔离或者白名单。总结一下，已知重大漏洞的零容忍，防护的全面有效性，以及对风险的快速应急响应能力是这个阶段需要建设好的。

这个阶段顺带手再解决一些边角料的问题：那些自动化工具无法发现的漏洞比如业务层漏洞，以及类似于弱口令社工库等问题。我觉得不必要在业务逻辑漏洞上过分纠结，一个很简单的原因：真到战时，谁还来玩这个，对于关基单位内部一通打，瘫了就算赢。当然，有能力有精力的当然修复了最好，我是说如果必须要丢车保帅情况下的优先级排序的原则问题。

**三）识别未知风险**

网络安全防范于未然的概念就是要解决不可预知的各种突发状况。你凭什么认为黑客没有0day，你凭什么认为黑客不能突破防护规则？所以我们一定要假设，黑客具备我们不知道的技能，以及他们进来了我们应该怎么办。

红蓝对抗网络朱日和是必须的，蜜罐是知道自己被搞的最后一招棋（很多人把它作为第一步），流量apt分析是必须的，终端防护是必须的。其实到这里已经开始有点失控，涉及到方方面面各型各色的细分产品，每一点看起来都需要，但是就跟研发一样，你说的每一行代码我都看得懂也能开发，但是全像是在衣服上打补丁，这一块那一块五颜六色，缺少一种干净利落的架构。所以大家正在寄期望于新的技术架构，能够统领全局。一种新的技术应该是能够基于全流量全终端的数据，结合行为异常模型的自动化系统。回到蜜罐技术来，我为什么说是最后一招，你可以想象有贼进了你的屋子，你坐在大厅冷眼旁观，东西都快被偷完了，他看到你了，用手狠狠甩了你一耳光，你痛的大喊“有贼啊”。有用是有用，我们不免想着早干嘛去了。

态势感知和零信任的话题，我不是不信，是目前还没有看到真正落地管用的，以后可能会有，短时间内我个人持观望态度。另外关于机器学习未来能不能帮我们做决策，我推测大概率能，但是人类自己不方便判断的事情交给机器，他能推测一部分，那不能推测的一部分会怎么办呢？

都到这个阶段了，是应该立一个将军专门来干这个事情了，组织结构上要建立有高话语权的能力全面的网络安全团队。

以上的三个阶段不能跳跃式发展，时间可以压缩，只能到了一个阶段就能走向下一个阶段，但是不能迈大步跳过某个阶段。大家在早起阶段很焦虑这个我是非常能够理解的，但是不同单位发展有自己的阶段，有些之前就很好的理解并且做了布局，所以人家就想跑了一段，比我们强也是正常的。从另一个角度来看，早跑的不一定就是最终的胜利者嘛，这个阶段拼的是谁更快的进入到最终阶段，所以学习成长性非常重要，历史上出身一贫如洗胸无点墨的“大老粗”，后来变成了指点江山流芳百世的开国君主的也不少嘛。

另外大家应该可以看出来，我在后两部分其实是不具体不清晰的，因为我在描述一个未来的共产主义，那是假设的还没有到来的愿景。现阶段攻击比防护要容易，我们以功促防的根本原因在于，如果你连现有攻击的手段都防不住，再往后讲就太早了。未来会怎么样我们只能做一些假设，我们觉得未来十年漏洞不会消失，未来的攻击会越来越智能越来越高效，未来的防护还是道高一尺魔高一丈，防护的边界会越来越大越来越细。所以网络安全不是一个持久战，他可能是个永恒的战役。

安全是为了保障业务，而不是约束业务，取平衡是一个哲学问题。我们的目标不是杜绝漏洞，也不可能杜绝漏洞，而是比黑客快，比通报快，跑赢大盘就是胜利。为了让大家过的更轻松一点，我们选择做一些断离舍的操作：没有黑客利用的漏洞都不是漏洞，网络不可达的资产都不是资产。想明白了，大家是不是舒服多了？
