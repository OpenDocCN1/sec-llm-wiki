基于区块链的信息网络信任支撑环境构建研究

网络信任体系是信息网络安全的重要基础设施。针对网络信任体系建设中存在的身份认证技术体制不统一、跨信任域互信互认难实现、跨体制统一信任管理缺手段、统一信任服务应用难满足等突出问题，通过采用安全可控的联盟区块链技术，研究构建信息网络信任支撑环境，建立全网统一信任源，实现多认证体制互信互认、统一身份认证服务和网络信任安全监管，为信息网络安全保障能力建设和信息网络共享应用提供有效支撑。

0　引　言

网络信任体系是信息网络安全的重要基石，国家《网络强国战略实施纲要》和《关于加强网络安全和信息化工作的意见》对推进网络信任体系建设做出重要部署，国家《网络安全法》明确了国家实施网络可信身份战略，将网络信任上升到了国家法律高度。2007年国家信任源根认证中心(CA)建成，为国家网络信任体系标准化、规范化建设提供了信任源点，为以电子身份标识为基础的网络信任体系奠定了基础。

网络信任体系是包含身份信息管理、身份认证、授权、责任认定和网络信任服务等系列分体系的集合，解决网络空间中实体身份鉴别、权限控制、行为审计、事件追查与责任认定等系列信任问题。身份信息管理和身份认证体系作为网络信任体系的重要基础，在当前建设运行中仍存在着一些突出问题：

一是信任域隔离难于达成互信。不同业务领域独立建设运行CA系统和数字证书系统，基于各自的根证书颁发用户证书，形成相互隔离且难于互信的多个信任域。跨信任域访问信息系统时证书管理难度大，用户使用复杂。

二是身份信息不能在系统间互认。不同业务信息系统通常部署有用户身份管理功能，对用户身份和属性信息进行独立管理。用户身份属性信息的变更往往难以在不同系统间及时同步，易造成身份属性信息不一致，甚至引入严重安全风险。

三是多认证体制下认证服务无法统一。网络信任服务采用PKI认证、用户名口令认证、生物特征认证等多种认证技术体制，认证体制不同导致认证系统无法互通。即使采用同一种认证技术体制，也会因认证系统独立建设运行，相互之间对信任源和认证结果难于互认，无法有效提供全网统一的身份认证服务。

区块链是一种由多方共同维护，使用密码学保证传输和访问安全，具有分布式存储、信息共享透明、不可篡改、不可伪造、可追溯、安全抗毁等特点的技术体系。利用区块链智能合约、共识等机制，协同多个信任主体共同管理实体证书，在统一信任源管理的同时，分散单一信任根证书管理风险；采用区块链构建底层身份信息管理平台，利用区块链的分布式多方协同、单一总账等机制，打通多个信任域之间互通互信通道，构建统一信任服务和安全监管，实现用户身份、属性的全局同步和跨域互认，为多业务领域信息系统共享应用提供跨域协作支撑。

1　相关工作

网络信任体系可突破隔离的信任域，实现不同用户信息在不同系统或不同认证体制下的互相信任。网络信任体系以密码技术为基础，目前较多应用的基于公开密钥的认证框架有：基于可信中心CA（Certification Authority, 认证机构）的PKI（Public Key Infrastructure，公钥基础设施）体系和基于身份的密码体制 ( Identity Based Cryptography，IBC)，但都存在对中心化服务器的依赖问题。

自2008年中本聪提出比特币以来，区块链技术快速发展，经历了以加密数字货币为标志的“区块链 1.0”和以智能合约为标志的 “区块链 2.0”的阶段，目前进入了构建价值互联网的“区块链 3.0”阶段。近年来，研究者们通过“命名-存储”方式将用户的密钥和身份绑定到区块链，实现分布式的PKI认证，以 Blockstack、Cecoin为代表的方案已经成功实施。

为防止身份隐私信息被滥用和误用，Axon提出物联网设备身份隐私保护的PKI方案。针对区块链中证书信息交换和同步过程中通信量大、处理速度慢的问题，K Lewison基于以太坊实现PKI认证体系，通过优化区块链证书使用来达到减少通信量，降低维护成本的目的，文献在此基础上设计了基于区块链的PKI跨域认证方案。Muneeb Ali等人提出的Blockstack，以全球部署的Namecoin区块链为基础，保障身份数据的完整性和共识机制的有效达成，同时增强了在注册和更新区块链时的网络可靠性和安全性的设计。

现有研究和应用实践主要还是针对基于PKI认证体系下的证书信息交换、跨域认证和身份隐私保护等，尚没有以区块链底层为支撑服务，实现多认证管理域互信互认、多认证体制统一信任源管理、全网统一信任服务的应用研究，本文便针对这一应用问题展开。

2　网络信任联盟区块链平台

2.1　平台结构

网络信任联盟区块链平台主要由背书节点、记账节点、共识节点和客户端构成。其中，背书节点接收客户交易，执行智能合约，使用安全密码服务对背书结果进行签名，并对共识节点生成的区块进行签名验证。记账节点之间通过P2P网络服务同步区块，采用分布式区块存储技术使每一个记账节点都维护一个完整的区块链账本，并利用多通道技术进行数据隔离， 基于特定通道只能访问自己的账本。

共识节点负责为系统中产生的交易达成共识，并打包出块。共识节点中不同通道的数据也相互隔离。客户端使用安全密码服务，对发送至背书节点和共识节点的交易进行数字签名，防止交易在传输过程中被篡改。安全密码服务支持SM2、SM3、SM4等国家密码算法，并以组件化方式实现不同密码算法间替换。智能合约集提供支持多种业务逻辑的链码程序。共识算法集汇集Kafka、PBFT、RBFT、Raft等多种共识算法，采用组件化方式实现不同共识算法的选择切换。网络信任联盟区块链平台结构如图1所示。

2.2　部署模式

区块链部署模式需要根据不同应用场景和设计体系，采用不同的开放共享和节点权限方案对其进行组织。联盟链部署模式仅由一组具有利益相关的特定区块链服务客户使用，仅有授权节点可接入，接入节点可按规则参与共识和读写数据。联盟链在继承区块链通用特性的同时，还具备高可用、高性能、可编程、隐私保护保障、节点数量可控、系统运维方便等特点，能有效解决信任支撑环境运行高效、可靠监管的问题。信息网络信任支撑环境的区块链平台以联盟链部署模式构建，以多个信任实体为共识节点，使相互独立的信任域系统形成全网信任联盟。

网络信任联盟区块链各节点通过共识记账保证信任策略、CA证书、证书状态信息、身份属性信息等信任数据的全网一致性。信任根被多个信任主体共同进行分布式管理，部分信任系统的信息泄露不会导致信任根不安全。通过共识成员的统一管理，保证经授权的信任域系统可以加入联盟，并在统一信任策略的控制下， 通过智能合约访问核验证书等信任数据。联盟成员通过多中心达成互信，同时具备较高区块生成效率和处理速率。

2.3　共识机制

网络信任联盟区块链平台的共识机制使信任联盟成员节点在区块链平台中进行事务（或状态）的验证、记录、修改等行为时达成一致确认。网络信任联盟区块链平台采用共识算法组件化方式，进行共识算法选择切换，共识算法包括Kafka、PBFT、RBFT、Raft等。其中PBFT和RBFT等具备拜占庭容错能力的共识算法，共识确认时间短 , 运行效率高，且在共识节点数量为3f+1时，可容忍f个无效或恶意节点丢弃响应、伪造数据、故意返回错误以及欺诈行为，因此可提供较高的安全性。

网络信任联盟区块链平台采用的RBFT（Raft-BFT）共识算法，结合了PBFT的安全性优势和Raft的效率优势，可针对不同的应用场景通过参数配置实现共识安全性和效率的折中。RBFT能够防范拜占庭节点存在的各种威胁，算法对消息签名、哈希增量、选举验证、提交验证的改进，提高了系统的安全性；对客户干预、投票验证的改进，保证了系统的灵活性。同时， 算法增加了对拜占庭节点的容纳能力，节点各自进行提交验证的方式也减少了共识流程，缩短了请求确认时间，提高了共识效率。

2.4　数据存储

网络信任联盟区块链平台成员节点通过P2P网络服务，对数据交互回执、区块头信息等具有连续性特征的区块数据，以及智能合约存储的业务数据等随机性特征的状态数据进行分布式存储。全网数据同时存储于加入通道的所有联盟节点上，各节点共同参与上链数据的验证、存储与维护，确保任一网络信任联盟成员节点都保存有整条区块链，且各节点间互为备份。即使部分节点失效，区块链主链数据仍可完全恢复，不会影响后续区块数据的记录与更新。

网络信任联盟区块链平台采用了基于双数据库的区块存储设计，即底层数据库和世界状态数据库。区块链的数据结构分散存储在底层数据库，最终存储形式是[k,v]键值对，使用的[k,v]型底层数据库为 LevelDB。每个区块里含有多条交易，与区块对应的有一个世界状态数据库。每次新交易执行完，只同步更新一个数据库，有效提升了数据存储性能。区块存储设计中主要涉及数据存储、账户和交易实现两个方面。数据存储主要基于Merkle树，通过区块的方式和链式结构实现，以键值对数据库的方式实现数据持久化。账户和交易实现基于数字签名、哈希函数和非对称加密技术等多种密码学算法和技术，保证交易过程及交易数据的安全。

2.5　智能合约

网络信任联盟区块链平台基于EVM、JVM、HVM等多种智能合约引擎，支撑智能合约代码组件化部署和灵活安装执行。在智能合约代码开发部署上，平台采用基于excel的智能合约模版开发方法，按照excel模版提供业务逻辑涉及的相关规则及字段，根据上传的excel规则及字段为用户生成相应的智能合约代码，形成用户自定义的智能合约，并完成智能合约在链上的部署及初始化。智能合约部署后，根据业务需求的变更可对智能合约进行升级。

在智能合约运行监管上，平台对智能合约协议的各项基本属性（机密性、认证性、不可抵赖性）以及匿名性、不可链接性和零知识性等高级属性进行形式化分析，并对智能合约代码的安全性进行检测分析，各区块链节点无需考虑智能合约执行的安全性问题，可更好提高节点业务能力。通过平台统一下发安全可信的智能合约，安装部署到区块链网络各节点，保证区块链网络节点均执行统一的共识协议。同时，可将智能合约的状态数据导入到监管信息库中，使智能合约运行状态可视化、可监控，实现基于智能合约的业务进展情况统计和分析。

2.6　安全保密

网络信任联盟区块链平台通过结合密码技术实现区块链用户及链上数据的隐私保护，通过设置监管方密钥对用户身份和交易内容进行监管。平台从算法、协议两方面设计并定义接口标准，提供简洁、便利的可监管匿名隐私保护组件，实现区块链应用的安全保密和可监管。平台安全隐私保护架构包含算法层和协议层，密码算法层为应用协议层提供所需的密码组件支持，包括密码协议及应用接口。

密码算法主要包括国密标准算法（SM2公钥密码算法、SM3哈希算法、SM4对称加密算法、SM9标识密码算法）、同态承诺算法、范围证明算法、双密钥对算法、Merkletree算法、白盒密码算法、属性混淆算法等。应用协议层提供多种类型的隐私保护协议，且通过监管服务接口实现对匿名数据的监管。应用协议主要包括口令登录认证私钥封装协议、双密钥对封装保护协议、MH数据保护封装协议等。

3　基于区块链的信息网络信任支撑环境

3.1　多认证管理域互信互认

目前，网络信任体系中多种认证系统并存，各自形成独立信任域的现象仍为突出。由于认证系统之间不能互认，用户无法跨信任域实现认证，并访问相应的信息系统。通过网络信任联盟区块链平台，各认证系统成为信任联盟成员，将各自的CA根证书或多级CA证书上链，并通过分级互认智能合约达成证书互认，实现跨信任域的认证信息登记入链、证书互认、信任分级、信任策略和访问控制，有效支撑网络信任联盟内的跨信任域信息系统应用。基于网络信任联盟区块链的多CA认证系统互信互认如图2所示。

图2  基于网络信任联盟区块链的多CA认证系统互信互认

网络信任联盟区块链平台基于智能合约服务，支撑智能合约代码的部署与执行。通过信任传递智能合约簇实现：证书服务机构及其CA系统加入或退出信任联盟；管理CA机构之间的信任关系（等级），并以信任列表方式或桥CA方式，为CA颁发互认证书；建立连接不同域的证书撤销机制，并以信任列表向跨域用户证书提供状态信息（有效性信息/撤销）；为跨域用户认证、服务器认证提供认证支持；记录跨域证书认证等服务，提供追溯与记账服务。

基于网络信任联盟区块链的跨信任域证书认证过程：

( 1 ) CA_A与 CA_B认证系统作为网络信任联盟区块链成员，分别将根证书RootCertA和 RootCertB上链，通过智能合约达成两个认证系统间的根证书互认；

( 2 ) 当持有 CA_B用户证书CertB的用户，访问CA_A认证管理域的业务信息系统时，业务信息系统向网络信任联盟区块链发起对用户证书CertB的核验；

( 3 ) 网络信任联盟区块链通过分级验证智能合约，验证CA_A与CA_B认证系统间的互信关系，进而将认证结果返回业务信息系统；

( 4 ) 通过用户证书CertB核验后的持有者，可对CA_A认证管理域的业务信息系统进行应用访问操作。

3.2　多认证体制统一信任源管理

作为基础信任源的多种CA认证系统，以及提供用户身份、属性信息的各类业务系统用户身份管理分系统，均相互独立地管理着业务领域的信任信息。基于网络信任联盟区块链跨认证体制的技术特点，集成多种CA认证系统、用户身份管理系统，构建统一的信任源管理与服务机制，实现全局同步的身份管理与互认，从而支撑全网统一信任管理。基于网络信任联盟区块链的多认证体制统一信任源管理如图3所示。

图3  基于网络信任联盟区块链的多认证体制统一信任源管理

网络信任联盟区块链上信任源信息内容主要来源于属性提供方（一般指权威和可信机构），提供的信息为CA证书信息和用户身份信息。其中，CA证书信息包括证书版本号、签发机构名称、签发机构ID、证书获得人、证书获得人ID、有效期等内容；用户身份信息主要为用户基本身份信息、用户身份认证信息、用户相关社会信息、用户相关业务信息等内容。链上信任源信息的安全保护依赖于可监管匿名隐私保护算法（双密钥对算法）或Merkletree技术实现。

基于网络信任联盟区块链的多认证体制统一信任源管理实现过程：

( 1 ) 作为基础信任源CA认证系统的管理机构，以及各类用户身份管理系统的业务机构， 可构成网络信任联盟区块链成员节点，这些节点具有一定的权威性和代表性，对已认证的用户身份具有较强的背书能力；

( 2 ) 基础信任源的各种CA认证系统，将其根证书和信任列表登记上链，各类业务身份管理系统将用户身份和属性信息登记上链，从而使网络信任联盟区块链成为具备广泛信任基础的统一信任源；

( 3 ) 在网络信任联盟区块链创建智能合约 ，通过智能合约制定互信互认规则，包括各种认证体制的信任等级、各业务信息系统的安全等级、业务信息系统采信其他系统身份认证结果的信任列表，以及业务机构身份管理系统背书的用户身份认证结果的互信互认范围等。

3.3　全网统一身份认证服务

基于网络信任联盟区块链统一信任源管理技术机制，建立统一的用户身份认证入口，将各业务信息系统既有的身份管理系统认证方式与网络信任联盟区块链的统一信任源认证方式， 进行身份认证入口集成，屏蔽各种认证体制的差异性，实现基于PKI、用户名/口令等多种认证体制下的跨认证体制、跨信任域的统一身份认证服务，满足跨业务系统的用户身份互信和系统互操作。基于网络信任联盟区块链的统一身份认证服务如图4所示。

基于网络信任联盟区块链的统一身份认证服务流程：

( 1 ) 为业务终端（认证终端）提供集成的用户身份认证入口，包括业务系统既有身份认证入口和基于网络信任联盟区块链统一认证入口；

( 2 ) 业务系统原有用户发起对系统的信息访问时，可通过业务系统既有身份认证入口，保留由业务系统所属的身份认证服务器对其用户进行身份认证的模式，经身份认证合法后， 用户可执行业务系统访问操作；

( 3 ) 用户发起对非所属业务系统的跨系统信息访问时，可通过基于网络信任联盟区块链的统一认证入口，发送用户认证请求，由网络信任联盟区块链的智能合约验证用户已申请的背书机构提供的身份认证信息，并反馈验证结果（统一认证入口可采用信任等级较高的PKI体制进行认证，也可采用信任等级较低的用户名/口令或其他认证体制，低信任等级的认证体制采信高信任等级认证体制的认证结果），用户身份经验证合法后，可执行跨业务系统访问操作；

( 4 ) 业务系统原有用户和新创建用户，可采用系统最常用的背书机构提供的身份认证信息，提交至网络信任联盟区块链，并创建相应的身份验证智能合约，从而逐步向统一认证入口模式过渡，实现真正的统一信任服务。

3.4　敏感信息保护与监管

区块链服务的安全和隐私保护涉及数据存储、数据传输和数据应用等多方面的存取控制、保密性、完整性和可获得性。基于网络信任联盟区块链的统一信任服务，尤其需要对节点存储的用户身份属性、用户行为等敏感信息提供有效的隐私保护和监管机制，降低区块链账本公开性给用户属性和行为等敏感信息泄露带来的风险。

同时，可依据相关管理要求，对用户行为进行全局、全程监管，及时发现和处置潜在风险、违规行为和安全事件。网络信任联盟区块链通过采用可监管敏感信息保护技术，提供敏感信息保护服务。在区块链平台记账过程中，用户使用派生匿名签名密钥和数据加密密钥，以保护账本中的敏感信息；监管机构通过相应的监管密钥对区块链平台上账本记载的用户及其行为进行关联分析；监管机构不可篡改和伪造用户行为，从而在降低敏感信息泄露风险的同时，保证链上数据的可审计性。可监管敏感信息保护技术实现途径如图5所示。

4　基于区块链的信息网络信任支撑系统

系统主要由统一信任服务平台、网络信任联盟区块链服务平台、身份属性提供节点、身份属性依赖节点、应用客户端等五个部分组成。其中，统一信任服务平台包括CA及密钥管理、身份管理服务、信任数据分析及监管等子节点，完成CA证书及密钥的管理、身份管理服务、信任数据分析、应用客户端协助管理等功能。网络信任联盟区块链服务平台包括共识节点群、背书与记账节点（智能合约执行）和区块链监管节点，完成链上记账行为背书、协同共识、身份认证智能合约执行和区块链运行监管等功能。

5　结　语

网络信任体系建设作为网络安全与信息化建设的重要基础，近年来得到了有力推进发展。但同时也应看到，在不少重要的行业领域，仍存在着认证体制多样和身份管理孤岛的现象，影响着跨部门、跨领域的统一、便捷、高效信任服务的实现，制约着各行业领域信息系统互通、信息资源共享的实施。立足当前网络信任体系建设现状，着眼区块链新技术的发展，构建面向各行业领域信息系统的统一信任源管理和统一信任服务的信息网络信任基础设施，是提升信息网络安全保障能力，提高信息资源共享共用效益的有效途径。
