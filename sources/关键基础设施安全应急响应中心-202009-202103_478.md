# 基于运营商的应用安全可编程防御系统

**摘要：**基于运营商的资源，针对运营商 IDC 的客户，提供具有应用层防御能力的带宽接入服务。利用软件定义安全的概念，构建可编程防御系统，采用在线模式实现引流和回注， 使用负载均衡资源池和安全内核，实现全流量可视化为基础的安全增值服务。将安全功能抽象出来，实现跨产品、跨平台的重定义、封装和编排，对攻击实现更快的发现和处置。以更快的交付速度和模式，实现应用防御服务。防御系统具有识别非人类行为流量的能力， 对模拟人类行为的攻击方式具有显著的拦截效果。

# 引言

伴随 TB 级网络层和 KB 级应用层攻击时代的来临，任何一个实体数据中心在遭受混合攻击时，都是有限资源和无限资源的对抗。几十个 G 的数据中心入口能力在混合攻击流量面前几乎没有胜算的可能。因此运营商在这种非对称的对抗中将扮演非常重要的角色，但这种场景只会在国内出现。国外的情况与国内迥异的根源在运营商的特征差异，核心就是带宽成本。国外带宽成本较低，安全厂商一般都自己购买带宽，搭建基于运营商链路的清洗服务架构。由于国内运营商资源相对集中，且比国外获得带宽的成本较高，加之国内比较封闭的互联网生态环境，导致国外安全厂商的安全服务无法进入，但用户的客观需求又是刚性存在的。因此基于运营商为最终客户提供安全服务成为一种资源最优配置的商业模式，具有非常广阔的商业空间和客观用户需求。从 2015 年开始，国内运营商开始有基于链路的安全服务出现，经过几年时间的发展，已经形成骨干网、区域节点和省级等多层级服务框架。

# 1  全维度的新型攻击威胁

**1.1 攻击即谋利**网络攻击早已不是个人的“炫技”行为， 攻击者开始变得越来越唯利是图，以最小的成本最隐蔽的方式获取最大的利益回报，才是现阶段网络攻击的主要目标，随着“比特币、以太坊”等电子货币的兴起，这种完全隐匿交易双方的支付方式，彻底打通了网络攻击的最后一个链条，网络攻击变得越来越肆无忌惮，“攻击敲诈”越来越受到攻击者的青睐，作为防守方需要深刻的认识到，我们所面对的是全球化的高度专业的， 已经具备“工业化、产业化” 规模的黑客组织，需要转变观念对此有新的认识。**1.2 量身定制的攻击手段**网络攻击手段复杂繁多，本文以攻击目标为视角主要讨论防守方的门户“企业对外 Web应用”，作为企业内、外系统对外的窗口，企业 Web 应用极易成为攻击者的攻击目标，其攻击手段主要有两种。**( 1 ) 渗透型攻击：**从事安全行业的人员都很熟悉 OWASP（开放式 Web 应用程序安全项目） 和“网络杀链（Cyber Kill Chain）”如图 1 所示，\_x001D\_ 渗透型攻击的特点是通过隐秘的手段在不被客户发现的情况下获取客户内部系统权限、客户 IT 资产信息等，绝大多数企业和事业单位几乎每天都在遭受此类攻击的危害，随着“人工智能”技术的发展，大部分的攻击手段已经变成了程序化的自动化攻击，它们以“低频、拟人”的方式不知疲惫不眠不休，不断对企业的业务系统进行渗透，这就是当前客户面对的安全态势。

![](../Images/2ec2c5bc51cc570203fc9f50fbe4a29c.png)

图1  网络攻击链**( 2 ) 资源耗尽型攻击：**资源耗尽型攻击主要分为两种“网络层 DDoS、应用层 DDoS”， TB 级网络层 DDoS 攻击已不罕见，这种程度的攻击普通客户由于带宽的限制根本无法防御， 这是资源条件限制，非技术原因，企业只能去购买运营商的清洗服务。应用层 DDoS 攻击是在网络层 DDoS 攻击的基础上发展起来的，应用层DDoS 攻击是一种新型的攻击方式，这类攻击方式的本质还是基于洪水式的攻击方式，即攻击者通过代理服务器或者僵尸网络向攻击目标发送大量的高频“合法请求”，以达到消耗主机资源的目的。应用层 DDoS 不同于网络层 DDoS，应用层DDoS 攻击与正常业务的界限比较模糊，如“http flood（CC 攻击）、慢速连接攻击（slow post）、HTTP Get flood、HTTP Post flood、SSL flood”等， 甚至网络中充斥的各种搜索引擎工具“网络爬虫”。其产生的结果跟应用层 DDoS 攻击也很像，而今天大部分的商业 DDoS 设备对抗网络层DDoS 时效果较好，而对应用层 DDoS 攻击方法不多。随着运营商和客户网络层 DDoS 技术的成熟应用，以及计算机与网络技术的发展，计算机的处理能力迅速增长，内存大大增加，这使得网络层 DDoS 攻击的困难度和攻击成本越来越高，当前单纯网络层 DDoS 攻击已不常见，多数是“混合攻击”即“网络层 + 应用层”，而应用层攻击由于其低成本、隐蔽性高、防御难度大越来越成为攻击者首选的攻击手段。**1.3 企业安全面临的挑战****( 1 ) 攻击特点：**混合型攻击、思路明确攻击手段繁多精准；攻击手段灵活多变，可随时变更攻击手法，应对防守方的防御变化；获利为目的，攻击时间长隐蔽性高；网络攻击手段专业开放程度高，“入行”门槛低；基于用户场景的攻击越来越普遍如“撞库攻击、薅羊毛攻击”，攻击与正常业务访问边界越来越模糊。**( 2 ) 企业防御现状：**采购不同的安全防御设备，没有有效整合，各自为政；需要对不同安全设备进行操作，被动防御效率低；大多数客户无法长期保持一支具备实战经验的高素质安全管理队伍；高效的安全防御架构同时也意味着更高的成本投入，企业需要在安全防御与成本之间找到合理平衡，甚至不得不牺牲安全保业务；面对新型攻击威胁，传统安全防御架构手段不多。

# 2  基于运营商的应用安全可编程防御系统

可以试想一下，有一支专业的安全团队为客户提供 7\*24 小时专业的安全对抗实战服务， 一套价值不菲的高效的安全防御架构，企业如果独立建设虽然会带来极高的安全防御效果， 但是也将付出巨大的人力和设备投入成本，这对大多数企业来讲是难以承受的，企业需要在安全与成本之间被动选择，企业可能对安全的要求很高但又无法付出高昂的成本，难道真的是“鱼和熊掌不可得兼”吗？答案当然是否定的，如果我们把这套防御架构和人员前移，让它为更多的客户服务，从而分摊运营成本，这就是“安全 SaaS 服务”，这也是安全 saas 服务最大的价值和意义。如图 2 所示，运营商作为网络的承载方，其无可匹敌的“数据调度优势、数据节点优势、资源优势”与安全相结合，将带来一个全新的安全生态与理念，将使企业安全建设更新到一个全新的阶段。

# 3  应用安全可编程防御体系

**3.1 技术架构**

![](../Images/b19fdcdc3edc41032a1bfdf1ee33b143.png)

图3  技术架构如图 3 所示 ，基于运营商的应用安全可编程防御系统，是根据 Gartner 公司提出的“软件定义安全”的理念，它打破传统的安全防御思路， 将安全产品真正整合成统一的防御架构避免各自为战，基于 Gartner 提出的软件定义安全的理念，以国内外先进的可编程安全工具为基础， 通过 API 接口对接的方式，重新编辑将安全产品功能抽离，形成可定制的防御模板，通过“智能化、自动化、模块化”的基于脚本对抗的可编程防御架构，实现对应用全生命周期的自动化持续监控与响应。可编程防御架构方案，通过不断的安全大数据分析学习，丰富攻击签名库，使防御效果越来越精准高效。**3.2 产品架构**

![](../Images/96acb1eb64a5e8d8aa5f5fce6e925a0d.png)

图4  产品架构如图 4 所示，大部分云安全解决方案依然采用的是普通串行架构，存在单一节点性能瓶颈的问题，对于应用层防御而言，并发量的增大和安全防御策略的增加，必然会对防御节点性能有更高的要求，串行架构无法解决此类问题，基于运营商的应用安全可编程防御架构采用“负载均衡 + 安全资源池”的方式，通过负载均衡设备承载大并发数据然后负载到安全资源池，虚拟化资源池可根据实际情况动态调整， 有效解决了应用层防御“时效性、高效性、可靠性”的问题。**3.3 防御原理**

![](../Images/a6f68b36b80778e23e4e151cad6de916.png)

图5  引流方案如图5 所示，采用 DNS 解析方式（A 记录或 CNAME）更改被攻击客户域名解析地址，将被攻击的网站解析为平台发布地址，从而将数据流指向防御平台，访问数据经过平台甄别处理后发送给源站。**3.4 安全防护能力**基于运营商的节点带宽优势和动态可扩展资源池架构，可编程防御系统在防御性能和功能上具备很强的扩展能力，通常来讲如果是单机或者自建防御中心，都会存在设备性能瓶颈的问题，而且安全防御策略加载的越多，检查越细。虽然越安全，但是对系统的性能消耗也越大，“应用负载 + 安全资源池”的架构可以很好的解决这个矛盾，理论上来说此架构方案只受限于带宽和硬件资源部署的限制，在防护能力上无性能瓶颈。

# 4  应用安全可编程防御系统

**4.1 产品功能****( 1 ) 网站防护：**针对 Web 应用层攻击实时检测防御， 如 OWASP 常见威胁、0day 防护、CC 攻击、API DDoS、僵尸机器人检测、Web 表单参数等数千种应用层攻击实现精细化防御；采用国际领先的检测规则和 AI 双引擎架构，可进行策略预定义，用户无需直面繁琐的安全策略；网站恶意爬虫防护、撞库防护、网站动态参数篡改、API 接口防护、越权访问、网页篡改监测、黑 / 白名单、漏洞扫描、恶意文件上传、僵尸检测、cookie 劫持、URL 访问控制等功能。**( 2 ) 安全可视化：**安全态势呈现，安全威胁数据可视化、攻击信息、溯源信息等，实时查看业务安全态势，助力用户安全研判；安全态势总览，客户端 / 服务端攻击流量趋势、攻击来源 / 类型统计、告警信息热力分布、客户端 / 服务端连接数趋势等可视化呈现；攻击详情呈现：URL 访问次数排名、浏览器类型统计、威胁信息统计、告警级别及异常返回码统计等可视化呈现。**( 3 ) 安全日志 / 报表：**详细的攻击日志及报表服务，支持日志导出，助力用户溯源分析 及安全运维。**4.2 应用场景**如图 6 所示，通过对业务流量的引流和清洗确保各行业的源站稳定可靠，业务正常运行。

![](../Images/cc627b1da1e695070cb08804b524eb96.png)

图6  可编程平台运营商技术架构**政企门户：**针对政企门户业务网站（政务、医疗、教育、社保、税务等）免受攻击、篡改等， 维护政府公信力，保证企业业务正常可用。**金融网站：**为银行、保险、第三方支付等金融客户提供应用层业务防护，有效识别僵尸机器人等 Bot 程序行为，协助泛金融企业定制化防护策略，避免企业信息外泄等风险。**电商站点：**针对电商高并发抢购等各类营销活动业务，提供超高并发防护能力和智能过滤恶意攻击及爬虫垃圾访问，保障电商业务可靠运营。**互联网业务：**解决互联网业务安全，避免业务入侵、篡改、窃取等，过滤各类攻击及垃圾流量，助力互联网类业务正常稳定运营。**4.3 产品优势****高效防御：**智能安全分析为中心的主动性对抗防御架构，支持 40 大类上千种 Web 攻击防护，快速迭代“攻击样本”提升防御效果。**稳定可靠：**运营商级云资源池架构，集群+ 冗余高可用模式，消除单点故障，彻底解决大规模应用层防御的性能瓶颈问题。**弹性防御：**秒级弹性防御架构，可随时扩展防御功能与防御能力。**网站隐身：**基于运营商的可编程防御架构， 通过修改 CNAME 方式引流，不再对外暴露用户源站服务器地址、避免攻击者绕过 Web 防护直接攻击用户业务站点。**4.4 产品优势**某金融服务网站系统建设在云资源池，虽然解决了软件部署与敏捷开发的问题，但是由于传统硬件安全架构无法部署在资源池中，故采用普通虚机版安全架构，上线后发现由于安全虚机配置问题导致网页无法正常访问，由于安全虚机不支持灵活的策略协议定制，导致其无法采用，且在进行压力测试时无法达到客户要求，购买可编程服务后，每天检测发现有约 5 万次不同类型的攻击，大部分为漏洞扫描网页爬虫，同时有针对登陆场景的撞库攻击，通过调整不同的防御模板，有效降低了攻击客户攻击威胁。

# 5  结语

信息安全是非常特殊的行业，在其它行业领域，多数情况下是需求引导技术发展，技术需求是实实在在发展目标，但是信息安全行业的顶尖技术很多时候都掌握在黑客手上，他们不断寻找新的攻击机会，而安全厂商只能不断的追改攻击者的脚步，完善自己的安全架构，这就是信息安全行业的真实写照，可编程的理念将安全从业人员的对抗经验以程序化的方式保存下来，通过自动化软件与攻击者进行对抗， 开启网络攻防新的发展阶段。选自《信息安全与通信保密》2020年增刊１期（为便于排版，已省去原文参考文献）
