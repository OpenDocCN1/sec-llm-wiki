《中华人民共和国数据安全法》于2021年9月1日正式实施，在国家强化数据安全监管的大形势下，所有企事业单位将面临着数据安全如何合规合法这一问题。本文试图站在操作系统角度初步提出数据安全中基于元数据重构的数据标签解决途径。

 01.从open函数看文件操作与系统调用的关系

通常我们在系统中对一个文件的使用有打开、读、写、执行、链接等多种操作，以gnu open函数为例，从user_space看，编码只要写到int open(const char * pathname, int flags, mode_t mode)的调用就结束了。如果我们深究一下，这个open函数操作系统又是如何最终执行的呢？下面，以linux kernel4.19.188为基础，从两个维度简要讨论一下这个问题：    

1、系统调用层面

在io/fcntl.h中有对open函数的定义，它对应的就是在user_space的open函数，即：externint open (__const char *__file, int __oflag, ...) __nonnull ((1))，其宏定义在intl/loadmsgcat.c中，即：# define open(name,flags) open_not_cancel_2 (name, flags)sysdeps/unix/sysv/linux/not-cancel.h　　#define open_not_cancel_2(name, flags) \　　INLINE_SYSCALL(open, 2, (const char *) (name), (flags))

往后继续跟踪，会发现内核通过swi软中断进行用户模式切换，对应的解释程序位于arch/…/kernel/entry.s中，至此从user_space的实现及编译的过程就将应用层open操作与kernel_space的sys_open联系上了，其中的调用编号对应于sys_call_table调用参数。

2、数据流转层面

如前所述，open函数中的const char *pathname对应于具体文件的路径名称，通过系统调用，逐步跟踪，大致流程经过(struct file -struct dentry – struct inode)实现元数据映射，具体可查阅include/linux/fs.h。至此，我们知道，inode定义了各个文件系统对“文件”客体的格式定义与要求，这里面需要注意两个细节：

  • 不同的文件系统对于内存inode的定义各不相同，例如windows系统常用的fat32/64、ntfs和Linux类系统的ext4对于文件的定义决定了不同类型文件解析的涵盖度，这也就是往往使用IOS系统拿到的数据在一些windows系统中经常出现数据丢失或被破坏的主要原因。
  • 内存inode和磁盘inode的数据结构是不同的，从数据安全治理角度看，治本还是应考虑如何利用磁盘inode的数据结构重定义来解决，目前大部分的数据安全考虑往往出于兼容性或复杂度的考虑，而更多地利用内存inode数据结构重定义进行实现。

 02.数据安全治理实现系统级解决的思考

参照2021年6月10日第十三届全国人民代表大会常务委员会第二十九次会议通过的《中华人民共和国数据安全法》中对“数据安全治理体系”提出的明确要求，结合业界众多专家提倡的“本质安全”与“内生安全”的理念，我们认为立足于信息系统安全体系考虑，应考虑如何从数据源头上解决安全治理问题。从软件系统平台来看，操作系统是作用于硬件/固件平台的第一道软件层，它是衔接应用与物理硬件的“必经之道”，对于数据的操作最终往往是定位到其inode定义中。因此，要实现系统级解决方案，可以考虑基于内核级元数据重定义来实现访问控制与数据安全保护机制，我们通过过往工程实践总结一下这里面需要关注的两个方面：

1、基于访问控制等安全手段来解决用户/进程/服务对数据的操作能力。《GB/T20272-2019 信息安全技术 操作系统安全技术要求》中对不同安全等级操作系统提出了明确的规范要求。从工程实现案例看，其核心的安全模型建模往往就是对现有文件系统进行改造和利用，例如通过VFS(如Ecryptfs)等应用级虚拟文件系统重定义安全标签(sec_label)来实现访问控制，尤其是在保障系统兼容性和稳定性的高要求下，可以很好地实现可用与安全的平衡。对于安全强度要求较高的场景，则应考虑直接在磁盘inode结构中加入安全旗标(FLAG)，通过定制专用化系统来实现从元数据级进行权限的定义与分配规则。

2、基于数据标签(data_label)体系来规范约束数据在流动过程中的安全保障，数据流动主要分为在本机流动和网络流动两类，正是因为数据的流动才使得数据会产生不同的价值，所以应根据数据的敏感度来确定使用数据安全治理的强度。数据标签是对数据流动过程中具备唯一性的安全媒介，围绕数据标签进行设计可以很好地实现数据治理平台安全底座。例如，针对特殊应用场景下的专用型数据平台系统，可以在磁盘inode中加入数据标签结构，结合数据完整性标签制定数据安全传输策略，在专用业务系统平台中只有在符合数据安全传输策略规则的前提下才允许该数据的传输。更进一步，结合整体安全策略模型，用户和该用户可操作的数据均带有唯一性标签，一方面数据标签伴随着该数据的全生命周期，另一方面，通过将数据标签与用户进行对应性绑定，可以从根源上实现用户责任与数据流动的挂钩，尤其是敏感数据泄露的溯源问题具有不可抵赖性。

 结语

2021年1月13日，工业和信息化部印发《开展工业互联网企业网络安全分类分级管理试点工作的通知》中对于工业控制信息系统中的数据安全部分提出了要求。同年6月发布的《中华人民共和国数据安全法》中第三章第21条，明确提出“……根据数据在经济社会发展中的重要程度，以及一旦遭到篡改、破坏、泄露或者非法获取、非法利用，对国家安全、公共利益或者个人、组织合法权益造成的危害程度，对数据实行分类分级保护”。以此可见，重大行业的数据安全治理工作是刻不容缓的。   从具体工程实践来看，在建设信息系统整体安全体系中应加强对数据安全的保障，一方面从信息化手段，考虑结合软硬件一体化的方式(如“可信芯片+安全内核”)来确保安全底座，另一方面也应同步加强安全制度的规范化标准化，例如很多在信息系统安全体系设计中引入的“三权分立”思想在现实中往往归于同一个具体人员，使得“分立”遇到很大的挑战。又比如，在很多具体的业务信息系统场景中，无法通过信息安全手段避免值班业务人员手动抄写敏感文件带来的数据泄露问题等。
