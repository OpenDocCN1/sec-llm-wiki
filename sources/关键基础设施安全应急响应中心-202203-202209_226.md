# 如何正确保护 API 变得越来越紧迫

Imperva发布了一项新研究，揭示了易受攻击或不安全 API 的全球成本不断上升。对近 117,000 起独特的网络安全事件的分析估计，API 安全隐患每年会导致 41-750 亿美元的损失。

这项由 Marsh McLennan 网络风险分析中心进行的研究发现，在统计上，较大的组织更有可能发生更高比例的 API 相关事件。事实上，收入至少为 1000 亿美元的企业遇到 API 不安全的可能性是中小型企业的 3-4 倍。数据表明，随着这些成熟的组织加速数字化转型，大公司特别容易受到与暴露或未受保护的 API 相关的安全风险的影响。

API 是无形的结缔组织，使应用程序能够共享数据以改善最终用户体验和结果。企业使用的 API 数量正在快速增长；近一半的企业内部或公开部署了 50-500 个，而有些企业拥有超过一千个活动 API。

许多 API 直接连接到存储敏感数据的后端数据库。因此，黑客越来越多地将 API 作为通往底层基础设施的途径，以窃取敏感信息。如今，每 13 起网络事件中就有多达 1 起可归因于 API 不安全。随着生产中的 API 数量成倍增加，预计这一数字将在未来几年增长。

该研究还发现了行业之间的巨大差异。IT、专业服务和零售最有可能遭受与 API 相关的安全事件：

“如果没有解决 API 安全问题的战略，世界各地的企业每年将继续损失巨额资金，”产品管理高级副总裁Karl Triebes说。Imperva 应用程序安全总经理。“为了缓解与 API 相关的安全威胁数量不断增长，组织需要能够发现其环境中的所有 API，并了解流经每个 API 的数据。”

**提高 API 安全性的建议：**

识别和分类流经每个 API 的数据：可见性对于理解每个 API 的完整架构以及识别和分类流经它的数据以便评估风险至关重要。

自动发现：API 的生成速度很快，并且经常修改，这使它们成为许多组织的盲点。通过自动化，组织可以消除流氓或影子 API。此外，通过自动化 API 清单，安全团队将了解开发人员何时在生产中修改 API。

启用 API 治理：对于高度监管行业的组织，API 治理模型至关重要。这只有在可见性超出 API 端点并进入底层有效负载的情况下才有可能，因此可以充分保护敏感数据。

“每个与 API 相关的安全事件的根源都是数据”Triebes 补充道。保护 API 需要转变思维方式；一种专注于对数据进行分类并了解生产中每个 API 如何访问数据的方法。这种方法需要安全和开发团队共同努力，将安全嵌入到开发生命周期中。在那之前，网络犯罪分子将继续利用易受攻击的 API 来大量泄露敏感数据。
