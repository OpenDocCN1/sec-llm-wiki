# “N-days”危机：漏洞与补丁也存在“漏洞”

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=Mzg4MDU0NTQ4Mw==&mid=2247496356&idx=1&sn=562927c46b4849aeaa1c46db169fe371&chksm=cf712900f806a016597add78d144b92597b28f8062c472d8d36a5824068cf76a6a09c028d238&scene=126&sessionid=1681575123#rd](http://mp.weixin.qq.com/s?__biz=Mzg4MDU0NTQ4Mw==&mid=2247496356&idx=1&sn=562927c46b4849aeaa1c46db169fe371&chksm=cf712900f806a016597add78d144b92597b28f8062c472d8d36a5824068cf76a6a09c028d238&scene=126&sessionid=1681575123#rd)

![](../Images/1c9ffca4a7331c1079c4bf65c0b41759.png)  

日前，趋势科技 ZDI 团队的研究员 Brian Gorenc 和 Dustin Childs 在2022年黑帽大会上发表报告表示，不仅修漏洞打补丁是一项挑战，辨别漏洞修补的优先级更是棘手的难题。

  

![](../Images/39ef99372845a6bd9e7d2564a0ae9331.png)  
自2005年以来，ZDI 已向整个行业的供应商披露了10,000多个漏洞。在此期间， ZDI 客户关系经理 Childs 表示，他注意到一个令人不安的趋势，即补丁质量下降和围绕安全更新的沟通减少。  
“**真正的问题在于，供应商发布了有缺陷的补丁，或是关于这些补丁的不准确和不完整的信息**，可能导致企业错误估计其风险，”他指出。“**有缺陷的补丁也会被广泛利用，因为‘N-days’比0-day更容易利用**。”  
  
***01*****CVSS 评分和补丁优先级的问题**  
大多数网络安全团队人手不足且面临压力，不能始终保持所有软件版本最新。多数企业会根据通用漏洞严重程度量表(CVSS)中的严重等级来优先打补丁。  
但是，Childs 指出，这种方法存在严重缺陷，可能导致资源被花费在不太可能被利用的漏洞上。这是因为 CVSS 评分没有提供有价值的关键信息。  
“很多时候，企业只关注 CVSS 基础核心确定修补优先级，”他说。“但是 CVSS 并没有真正关注可利用性，或者漏洞是否可能在野利用。**CVSS 不会告诉你漏洞是否存在于15个系统或1500万个系统中，也不会告诉你它是否在可公开访问的服务器中**。”  
他补充说：“**最重要的是，它并没有说明这个漏洞是否存在于关键系统中**。”  
因此，即使一个错误在 CVSS 量表上的关键评级为10分（满分10分），它的真正影响可能远没有那么糟。  
“像 Microsoft Exchange 这样的电子邮件服务器中的未经身份验证的远程代码执行(RCE)漏洞将引起漏洞利用编写者的极大兴趣，”他说。“像 Squirrel Mail 这样的电子邮件服务器中的未经身份验证的 RCE 漏洞可能不会引起那么多关注。”  
为了填补上下文空白，安全团队经常求助于供应商建议——Childs 指出，这些建议有其自身的明显问题：“**不公开即安全**”。  
  
***02*****补丁公告缺乏细节**  
比如，2021年，微软决定从安全更新指南中删除执行摘要，仅通知用户 CVSS 分数确定优先级。  
“这种变化消除了确定风险所需的背景，”他说。“例如，信息泄露漏洞是否会转储随机内存或 PII？或者对于安全功能绕过，绕过了什么？这些文章中的信息不一致且质量参差不齐。”  
![](../Images/3d5048f5258a8fb86280461a926daf0a.png)  
除了微软“删除或隐藏指导信息”，“补丁星期二”的信息也变得更加简略，例如不提示每个月修补了多少漏洞。  
“现在你必须自己数，这是我做的最困难的事情之一。”Childs 指出。  
此外，**关于有多少漏洞受到主动攻击，有多少公开已知的信息可用，这些现在都隐藏在公告中**。  
“例如，本月修补了121个 CVE，很难挖掘所有这些 CVE 以找出哪些受到主动攻击，”Childs 说。“相反，人们现在依赖其他信息来源，如博客和新闻文章，而不是来自供应商的权威信息来帮助其确定风险。”  
微软安全响应中心的企业副总裁 Aanchal Gupta 在 Black Hat USA 与 Dark Reading 的对话中强调，微软限制发布 CVE 信息的目的是保护用户。Gupta 指出，这样做的原因是让安全管理员拥有足够的时间打补丁，“如果在我们的CVE信息中，提供了漏洞可如何遭利用的全部详情，那将是对客户实施 0-day 利用。”  
  
***03*****多数供应商 CVE 披露缺少细节**  
微软并不是唯一一个在漏洞披露中提供少量细节的公司。Childs 表示，许多供应商在发布更新时根本不提供 CVE。  
“他们只是说更新修复了几个安全问题，有多少？严重程度如何？可利用性如何？最近甚至有供应商专门对我们说，我们不发布有关安全问题的公共咨询。这非常大胆。”  
此外，一些供应商将安全建议放在付费墙或支持合同之后，进一步掩盖了他们的风险。或者，他们将多个漏洞报告合并到一个 CVE 中，尽管普遍认为 CVE 代表一个独特的漏洞。  
“这可能会导致风险计算出现偏差，”他说。“例如，如果您考虑购买一种产品，并且您看到10个 CVE 在一定时间内已被修补，您会推算这个产品大概的风险评估。但是，如果您知道这10个 CVE 基于100多个漏洞报告，您可能会得出不同的结论。”  
  
***04*****补丁几乎成了安慰剂**  
除了披露问题之外，**安全团队还面临补丁本身的问题。根据 Childs 的说法，“安慰剂补丁”是一种实际上没有进行有效代码更改的“修复”**，这种情况并不少见。  
“所以，漏洞仍然存在并且可以被威胁行为者利用，除了通知给攻击者外毫无用处。”他说。“漏洞非常好，我们只好二次修复。”  
![](../Images/1c8fcbb6ebc70b7a96ee7c5895d2d7d1.png)  
另外经常出现不完整的补丁；事实上，ZDI计划认为，研究人员所分析的** 10% 到 20% 的漏洞是因为补丁不正确或不完整直接导致的**。他以 Adobe Reader 中一个整数溢出问题为例。该问题导致堆分配过小，当向其中写入过多数据时会导致缓冲区溢出。“我们希望Adobe 将超过某个点的值设为不正确，修复这个问题；但实际上并非如此，就在更新发布的60分钟内，补丁就被绕过，因此他们不得不再次修复。节目重播可不止发生在电视节目中。”  
  
***05*****补丁优先级成了用户的难题**  
漏洞披露后的敏捷性是组织机构需要关注的另一个重要领域。  
  
ZDI 的资深总监 Gorenc 指出，网络犯罪分子争分夺秒地将具有庞大攻击面的漏洞集成到自己的勒索软件工具集或利用包中，在企业修复之前利用新披露的漏洞。这些所谓的 n-day 漏洞就是攻击者的“猫薄荷”，他们能够在48小时内逆向漏洞。  
Gorenc 指出，“大多数情况下，攻击团体使用的是存在公开补丁的 n-day 漏洞。在披露时了解该漏洞实际是否将被利用很重要，但很多厂商并未提供与可利用性相关的信息。”  
因此，企业风险评估需要具有足够的动态性，以改变披露后的情况。安全团队应该监控威胁情报来源，以了解漏洞何时被集成到一个漏洞工具包或勒索软件中，或漏洞何时在网上发布。  
企业需要考虑的一个重要时间表是，在整个组织中实际推出一个补丁需要多长时间，必要时是否有可动用的紧急资源。  
Gorenc 解释称，“当威胁情况发生改变时（补丁修订、公开的 PoC 以及利用发布），企业应当调配资源满足需求并对抗最新风险。不仅是最近公开和命名的漏洞，要观察威胁局势的情况、判断自己的资源并决定何时行动。”
