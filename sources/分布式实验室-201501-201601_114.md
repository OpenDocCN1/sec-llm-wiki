在运维领域中一个比较新鲜也比较有意思的技术是ChatOps， 即通过与一个控制机器人对话来做运维工作。在本文中Digia 高级架构师Jussi Nummelin介绍了他在这方面的一些实践。

ChatOps

近来有趋势将团队协作搬到在线消息应用上， 例如Slack、Flowdock 或者其它类似工具。一些组织甚至走的更超前，已经将他们的一些运维工具集成到这些消息应用里。 实际上这项工作比听起来简单的多，因为这些工具提供了相当直白的API和客户端库很方便做集成。当我发现情况如此时实在忍不住一试。: )

通过Slack消息控制Kontena

作为Kontena和Slack的用户，我觉得如果能够使用Slack来控制我的Kontena grid将会是非常的酷。优点就是运维现在对于整个团队来说都是透明的，因为与Kontena的通讯都是通过与一个cahnnel里面的机器人对话来完成的。与同事一起做调试也变得十分的简单，只需要你们建立一个私聊的会话然后邀请机器人加入就行了。通过这种方式你们两人都可以看见与Kontena grid实时的控制流。

集成

机器人是使用Node.js和Slack的Node客户端写的。Slack客户端简化了我的工作，因为它提供了几个简单的回调来对进来的消息做反馈。接下来的一步是解决如何与Kontena做集成。Kontena本身已经有了一个相当好的命令行工具，我真的不想再另外写一个选项解析和其它类似的“样板“工具。所以这个Node.js APP就直接使用Kontena命令行工具来集成Kontena grid。由于Slack客户端使用WebSocket并且机器人来管理连接（与Kontena的模型一致）， 你就可以在任何地方运行它了。我们现在正在我们的Kontena grid中运行它。 ；）

与机器人交互

在Slack上控制机器人与普通的对话无异。只需要邀请机器人加入你的channel或者给它发一个1对1的消息。

```
kontenabot: service list
```

之后机器人便会将命令结果返回。因为是使用命令行工具做的集成， 所以机器人使用的命令与命令行工具里面的一模一样。以下是几个例子：

![](../Images/20fa9716bcd59e1f202551aee3b9ff38.png)  

在容器中运行机器人

我们已经将机器人做成了Docker 镜像， 所以现在你要搭的话也相当容易。在Slack上创建一个新的机器人集成来获得所需的api token。 在命令行上指定所需的token（slack 和kontena都要有）以及其他的选项作为环境变量，然后就搞定！

```
docker run -d -e SLACK\_TOKEN=xoxb-1243576874-XXXXXXXXXXXXXXXXXXX \\  
\-e KONTENA\_TOKEN=kontena-token -e KONTENA\_URL=https://192.168.100.100:8443 \\
\-e KONTENA\_GRID=my-grid -e SSL\_IGNORE\_ERRORS=true -e BOT\_NAME=kontenabot \\ 
\-e ALLOWED\_USERS=user1,user2 --name kontenabot jnummelin/kontena-slack-bot:latest
```

在上面的例子中我们指定了`SSL_IGNORE_ERRORS`因为测试环境我们的证书是自签名的。需要注意的一点： 在容器里面和slack的配置里面对机器人命名要一致。这样机器人就知道你是发消息给一个特定的bot。`ALLOWED_USERS` 这个列表配置组织里哪些用户被允许控制机器人。 如果你忽略的话， 任何用户就都可以控制它。
