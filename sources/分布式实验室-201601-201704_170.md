# Cloud Foundry Foundation部署容器案例

到底容器应用部署在哪里最好，现在有着大量的争论。裸机服务器，虚拟机和平台即服务（PaaS）环境都在讨论之中。但是，最新的对于来自参加Cloud Foundry峰会的328位IT专业人士调查显示，71％的IT专家已经在使用容器。

这些人之中，88％使用Docker，55％使用Garden，39％使用Warden。Garden和Warden是Cloud Foundry本地的两个容器平台。只有11％使用LXC，3％使用rkt，2％使用LXD。

与此同时，只有35％的受访者表示，他们完全依靠Cloud Foundry进行所有的容器管理。这表明许多受访者都在使用多个平台来管理容器。

事实上，由于Docker这样的容器是高度可移植的，大多数IT组织会同时发现在虚拟机、裸机服务器和PaaS环境中管理容器。调查发现，其PaaS的大多数实施都在Amazon Web Services上运行（59％）；其次是VMware vSphere 55％，OpenStack 45％，Microsoft Azure 23％。几乎所有这些PaaS实例都由内部IT组织而不是外部IT服务提供商安装。有趣的是，超过半数的参会者（55％）报告实用如AWS和VMware vSphere的混合云是最流行的。

Cloud Foundry基金会营销主管Devon Davis说，当涉及到在生产环境中部署容器应用程序时，Cloud Foundry PaaS环境的丰富性使其可以大规模地管理容器应用程序。

大多数使用Cloud Foundry的IT环境实际上是在Docker在IT领域创建很长时间之前在Cloud Foundry创建的本地容器之上运行Docker镜像。即使如此，Cloud Foundry正在向平台的一些相对新手寻求支持。 Ultimate Software的系统架构师Fidel Torre Michieli表示，他的公司提供了作为服务交付的人力资源软件，评估了部署和管理容器的几种方法。由于需要能够在工业规模上实现作为软件即服务（SaaS）应用提供商的目标，Cloud Foundry PaaS被证明是不可或缺的。

Cloud Foundry Foundation调查发现，59％的与会者已经在生产环境中部署了Cloud Foundry。另有19％的人正在开发或测试，11％的人说他们仍处于概念学习（PoC）阶段。

不管这些组织争论到哪里，很明显，很大一部分容器将最终运行在PaaS环境中，可用于托管微服务，同时使访问后端遗留应用程序变得更加简单。 IT组织面临的挑战是，鉴于自己独特的DevOps要求，确定容器平台的组合，这样才是最有意义的。
