# OpenStack 开始衰落了吗？

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=Mzg5Mjc3MjIyMA==&mid=2247542605&idx=1&sn=0c956d65f0f673b94ec43d9204adc1f2&chksm=c03b6d5ef74ce4485df2ee8cbe5618fa7e7c40ae38bf3851cc5e5cc5d72bbdd728d3329b688a&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=Mzg5Mjc3MjIyMA==&mid=2247542605&idx=1&sn=0c956d65f0f673b94ec43d9204adc1f2&chksm=c03b6d5ef74ce4485df2ee8cbe5618fa7e7c40ae38bf3851cc5e5cc5d72bbdd728d3329b688a&scene=27#wechat_redirect)

今年早些时候，在 Austin 举办的一次 OpenStack 会议上，与一位来自重量级公司的架构师的对话让我仍印象深刻。他当时很疑惑，拥有 OpenStack 云平台的 IT 团队，它们的用户（开发者）不再像往常一样启动和终止虚拟机，只是部署一堆虚拟机，并长期保持运行。调查之后，IT 人员发现这些虚拟机其实是 Docker 虚拟机，开发者将所有东西都部署到了容器中。现在有很多动态的应用部署，只是不在虚拟机层面。

最近，Mirantis 宣布将会移植 OpenStack IaaS 平台为容器方式运行，并使用 Kubernetes 编排，这样通过 Fuel 配置工具就可以轻易地安装 Kubernetes。很明显，这对 OpenStack 咨询公司是一个重大转变，因为它志在成为 Kubernetes 的主要贡献者。

OpenStack、容器以及 Kubernetes 的存在都是为了同一个目的：使云端软件的构建和部署更加容易和快速。关注企业内部从事软件构建和部署工作员工的需要是至关重要的。所以说，OpenStack 现在是香饽饽。

![](../Images/012972ae036968155329ba4bf0391f18.png)对 OpenStack 的一些质疑

如果我站在开发者的角度看，我也不是很确定为什么要关注虚拟机 和 OpenStack。**伴随 Docker 容器的到来，相比于虚拟机，打包及部署微服务显得更加容易**。而且围绕容器技术，目前有着强大的生态系统来填补空白，扩展性能，使得所有东西都可以部署到生产环境。短时间内容器应用已取得了显著增长。对于普通企业，现在的问题是,容器的部署是选择裸机还是选择现有的管理程序，目前已有工具比如 Puppet、Chef、Salt， 未来可能选用 Fuel。

当然，上述聚焦从事新工作或者重构应用的开发者，对于现有的大型系统，容器技术涉及较少，因为现在很多东西并未容器化，未来几年可能也不会很好地兼容。所以，目前对虚拟机还是有需求的，可以说这是 OpenStack 仍然重要的原因吗？

问题之一是，最初的 OpenStack 是一个平台，帮助服务提供商与 AWS 竞争，然而并未成功。之后重新为新应用提供基础设施即服务（IaaS）。之前有段时间，没听说过 “pets vs. cattle”， 阅读 OpenStack 相关的文章会感到吃力。OpenStack 是被设计用来管理 cattle 的，所以即使可以使用 vSphere 或者 Hyper-V 自动部署，仍然需要部署 OpenStack。在不做任何改变的情况下，将现有的虚拟化引用迁移到 OpenStack 是比较困难。

问题之二是，OpenStack 本身是一个庞大而复杂、用于部署的软件集合。OpenStack 庞大而复杂，这就是 Mirantis 和 其他人可以通过提供服务、软件及培训来谋生的原因。所以，一次 OpenStack 部署，代价和时间成本看起来都很高，但并没有启用可以让人兴奋的云端原生新功能，但是这些在数据中心的一些地方，都早已良好地运行。所以，这让人很难接受。

这也是我质疑 OpenStack 未来发展的一个原因。

并不是说使用 OpenStack 的组织犯了错：提供给用户所需的云端应用环境是好的。然而，如果今天他们再做相同的决定，这些企业仍将需要努力思考他们的开发人员及 DevOps 团队将更喜欢哪种方式：可能是基于 Fuel、Docker 以及 Kubernetes 的一个动态的容器环境——在本地或者是公有云中，或者相反，一个预置私有的 IaaS 比如 OpenStack。

前路仍坎坷。
