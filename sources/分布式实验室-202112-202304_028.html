Docker发布其WebAssembly工具预览版第二版

原文：http://mp.weixin.qq.com/s?__biz=Mzg5Mjc3MjIyMA==&mid=2247561750&idx=1&sn=ccfdba3bad79914f59a5358c03192dff&chksm=51b69165effd828ae14ef7dddd35d414cd23d0ce224995b3c5a5d9fe61d89fccd3ba5c485b87&scene=27#wechat_redirect
去年 10 月份 Docker 发布了其首个 Wasm 工具预览版，这个特殊 build 可以使用 WasmEdge 运行时通过 Docker 运行 Wasm 容器。从 Docker Desktop 4.15 开始，用户可以轻松激活 containerd 镜像存储这项实验功能来试用这些新成果。
这不是努力的终点。自去年 10 月以来，我们一直与合作伙伴努力配合，希望简化 Docker 的 Wasm 工作负载运行方式并支持更多运行时选项。
现在，我们宣布 Docker+Wasm 的全新技术预览版将支持以下三种新的运行时：

  • Fermyon 的 spin：https://www.fermyon.com/spin

  • Deislabs 的 slight：https://deislabs.github.io/spiderlightning/

  • 字节码联盟的 wasmtime：https://wasmtime.dev/
包括 WasmEdge 在内，这些运行时均使用 Runwasi 库。
Runwasi 是什么？
Runwasi 是一个多公司合作项目，致力于在 Rust 当中创建一个库，降低 Wasm 工作负载的 containerd shims 编写难度。去年 12 月，Runwasi 的 GitHub 代码仓库已被捐赠并移交至 CNCF 的 containerd 团队。
随着微软、Second State、Docker 等厂商的大量投入，Runwasi 现在已经拥有完备的功能，可以使用 Docker 或在 Kubernetes 集群中运行 Wasm 容器。我们的工作并未结束，但现有功能积累已经足够让大家开始新一轮测试了。
如果你想跟我们或其他 Runwasi 维护者交流，请加入我们 CNCF 的 #runwasi 频道：
https://cloud-native.slack.com/archives/C04LTPB6Z0V

准备好亲自体验了吗？很好，在动手之前，我们要再强调一下：这只是 Docker Desktop 的技术预览版，所以可能还存在很多问题。在实际使用前，请务必备份你的容器和镜像。
请下载并安装适合你系统的版本，之后激活 containerd 镜像存储（Settings > Features in development > Use containerd 以拉取和存储镜像），接下来就可正式使用了。

小试身手

Docker Desktop 仍提供 WasmEdge 运行时，所以你可以运行：

$ docker run --rm --runtime=io.containerd.wasmedge.v1 
--platform=wasi/wasm secondstate/rust-example-hello:latest
Hello WasmEdge!
你甚至可以使用 wasmtime 运行时运行同一镜像：
$ docker run --rm --runtime=io.containerd.wasmtime.v1 
--platform=wasi/wasm secondstate/rust-example-hello:latest
Hello WasmEdge!

在以下示例中，我们尝试用 slight 运行时在 Docker Desktop 的 Kubernetes 集群上部署一个 Wasm 工作负载。首先，请确保在 Docker Desktop 设置中激活 Kubernetes，之后创建一个 example.yaml 文件：

cat > example.yaml <<EOT
apiVersion: apps/v1
kind: Deployment
metadata:
  name: wasm-slight
spec:
  replicas: 1
  selector:
    matchLabels:
      app: wasm-slight
  template:
    metadata:
      labels:
        app: wasm-slight
    spec:
      runtimeClassName: wasmtime-slight-v1
      containers:
        - name: hello-slight
          image: dockersamples/slight-rust-hello:latest
          command: ["/"]
          resources:
            requests:
              cpu: 10m
              memory: 10Mi
            limits:
              cpu: 500m
              memory: 128Mi
---
apiVersion: v1
kind: Service
metadata:
  name: wasm-slight
spec:
  type: LoadBalancer
  ports:
    - protocol: TCP
      port: 80
      targetPort: 80
  selector:
    app: wasm-slight
EOT

请注意这里的 runtimeClassName，Kubernetes 会用它为你的应用程序选择正确的运行时。

现在，大家可以运行：
$ kubectl apply -f example.yaml
在 Kubernetes 下载镜像并启动了容器之后，即可进行 curl 操作：
$ curl localhost/hello
hello

现在你已经拥有了运行在本地 Kubernetes 中的 Wasm 容器，干得漂亮！🎉

注意：你也可以将同一 yaml 文件运行在 AKS 当中。现在我们来看如何用它来运行 Bartholomew。Bartholomew 是 Feymyon 开发的微 CMS，能够与 spin 运行时配合使用。你需要克隆此代码仓库（https://github.com/docker-xyz/docker-wasm-bartholomew），这是一个微调过的 Bartholomew 模板。

代码仓库中已经包含一个 Dockerfile，可用于构建 Wasm 容器：

FROM scratch
COPY . .
ENTRYPOINT [ "/modules/bartholomew.wasm" ]
Docker 负责将仓库中的所有内容复制到镜像当中，并将 build bartholomew Wasm 模块定义为镜像的入口点。
