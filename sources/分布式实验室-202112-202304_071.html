我们选择了Rust，因为它太快了

我们选择Rust作为我们下一个项目的编程语言，它没有让我们失望。


— 1 —
背景


我在一家名为314e的公司担任后端开发工作，这是一家以医疗为中心的软件公司。在大多数情况下，我们使用Python作为我们主要的技术栈。我所开发的产品涉及大量的计算和转换，每个请求-响应的过程都要处理从几千到一百万行的JSON数据。

最初项目是用Python写的，使用的是FastAPI，但在某些时候，它的速度开始达到了极限。典型的往返时间（RTT）在最好的情况下是5秒，在最坏的情况下是超过1分钟。

就在那时，我们决定给Rust一个机会。虽然Rust的网络框架仍然不如Python（和许多其他语言）的框架成熟，而且我们在314e也没有精通Rust的员工，但我们选择咬紧牙关。

一旦我们准备好了Rust中的等效代码流，我们最终能够在最好和最坏的情况下分别实现1秒到10秒以内的RTT。因此，选择Rust是一种风险，但它的回报很不错。18个月后，我们不仅仅是为我们的选择感到高兴。

— 3 —
但是，我们可以直接使用C或C++，不是吗？


首先，我们想开发一个Web应用。问题是，如果不是一些深奥难懂的业余项目，谁会真的用这些语言开发一个Web应用？更不用说他们为了避免重复大量的东西而不得不写的模板和抽象的东西了，这让人匪夷所思。

但是，问题的关键在这里。C和C++都有一个许多其他语言试图解决但无法解决的问题，至少不能没有垃圾收集器。这就是内存安全。简单地说，内存安全意味着一个变量所指向的每一个内存地址都必须存在并包含隐含的值。

事实上，Tony Hoare把空指针的问题称为“价值十亿美元的错误[3]”。内存安全的缺失是造成应用程序中很多bug和安全漏洞的原因，尽管在理论上可以通过手工编写内存安全的代码，但我们毕竟是人类。

Rust自带的USP保证编译时的内存安全。Rust有一个叫做Borrow Checker的机制来处理这个问题，这已经超出了本文的范围（但它真的很酷，我保证）。

Rust没有垃圾收集器，再加上它的静态类型系统（这使得代码非常容易理解），以及极其优雅（和现代）的语法，使得它成为我们的最佳选择。


— 4 —
易于交付和部署（加上代码所有权）


在我们过去的Python部署方式中，我们不得不面对的一个巨大挑战是如何处理代码。在一个特定的层次结构中存在一系列的文件，我们必须在部署环境中维护这些文件。

那么带来的问题是谁可以访问我们的代码。如果部署环境是客户提供的，那他们基本上也可以访问我们的专有代码。而且，即使是经过编译的Python字节码也很容易被反编译。所以这就是问题所在。

再加上版本和运行时维护等问题，这个问题很快就变得巨大了。熟悉Java的人都知道这是多大的痛苦。

Rust仅仅通过作为一种汇编编译语言就解决了所有这些问题。它直接编译成汇编，一举消除了代码交付和所有权问题。


— 5 —
写代码的纯粹便利


当谈到为一项工作选择合适的工具时，有一个普遍的趋势。通常，较简单的工具容易学习，但要实现更复杂的任务就会变得更难，而复杂的工具则完全相反，它们的学习曲线更陡峭，但随着时间的推移会变得更方便。


这一点也适用于Rust。它迫使你从一开始就做某些事情。比如确保你用蛇形命名你的变量和函数，删除不用的导入、变量和函数等等。

fn main() {
    let fooCount = 11;
}

比如，上述代码片段回产生一个编译器警告。

warning: unused variable: `fooCount`
 --> src\main.rs:2:9
  |
2 |     let fooCount = 11;
  |         ^^^^^^^^ help: if this is intentional, prefix it with an underscore: `_fooCount`
  |
  = note: `#[warn(unused_variables)]` on by default

warning: variable `fooCount` should have a snake case name
 --> src\main.rs:2:9
  |
2 |     let fooCount = 11;
  |         ^^^^^^^^ help: convert the identifier to snake case: `foo_count`
  |
  = note: `#[warn(non_snake_case)]` on by default

是的！一个编译器警告。这不是一个你需要的额外工具来检查你的代码，而是编译器本身在为你做这件事。

而且你注意到那些极其有用的信息吗？包括关于如何解决这个问题的建议。好吧，这只是Rust无数美好事物中的一个，会让你越来越爱它。


— 6 —
那么，现在去哪里呢？


尽管我很想一整天都在谈论Rust，但使用它的理由是无穷无尽的（我甚至没有说到宏）。当你不得不在性能、效率、内存安全、强大的包管理器、令人惊奇的检查工具（也是内建的）和现代语法之间做出选择时，为什么不选择都要呢？为什么不选择Rust呢？

不要相信我，没有什么不好的感觉，但也许那些连续7年将Rust作为最受欢迎的编程语言的开发者可能会说服你。
