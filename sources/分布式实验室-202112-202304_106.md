# 写给Java工程师的Rust入门教程

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=Mzg5Mjc3MjIyMA==&mid=2247557700&idx=1&sn=8c226af3e15d7359a01aebdd4f6be2ff&chksm=c03aa857f74d2141e7bea875c1c8610ada71d46949bcd23d475d42ba217a7961e3664f2c6ea0&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=Mzg5Mjc3MjIyMA==&mid=2247557700&idx=1&sn=8c226af3e15d7359a01aebdd4f6be2ff&chksm=c03aa857f74d2141e7bea875c1c8610ada71d46949bcd23d475d42ba217a7961e3664f2c6ea0&scene=27#wechat_redirect)

你是 Java 开发人员吗？听说过 Rust 吗？你想试试 Rust 吗？本文将尝试从基础知识开始，对比 Java 和 Rust 之间的区别，尽量帮你避免未来写 Rust 代码时犯错，并不停的修改 IDE 提出的修改建议。本文的目的是帮助 Java 开发人员建立 Rust 的开发思维。

本文不会介绍如何安装 Rust，关于如何安装 Rust，我们可以参考官网：

 https://www.rust-lang.org/tools/install

让我们开始深入研究一下，看看 Java 程序与 Rust 程序有何不同？我们将使用 Hello, World! 这个示例为基础，从不同的角度对比 Java 和 Rust，来奠定一些 Rust 入门基础。

  

## *—****1*** *—*  
**运行我们的第一个程序**

  

当我们说 Java 时，它代表的是 Java 语言本身，还有 JDK 类、JDK 工具和 Java 虚拟机。我们需要使用所有这些来打印 Hello, World! 到我们的计算机显示器上。例如 HelloWorld.java 程序：

```


class HelloWorld {"Hello, World!"

);
```

我们首先声明了一个 class，命名为 HelloWorld。它包含了一个静态方法，就像在许多 C 风格的语言中一样，它通常被命名为 main。最后，main 方法接受一个实例数组，String 表示传递给程序的参数，这些参数将在调用时由运行时填充。

方法主体对任何 Java 开发人员来说都相当简单：将字符串 Hello, World! 传递给方法 System.out.println()。 

让我们尝试运行它，在这里我们使用 Java 19，因此我们可以直接调用 Java 源文件而无需先将其编译到 Java 虚拟机：

```


$ java --version
```

一切都非常简单。让我们看看在 Rust 中实现相同的程序有何不同？首先，我们需要用 Rust 编写等效程序 hello.rs：

```
fn main
() {"Hello, World!"
); 
```

源代码非常相似，但我们注意到，我们除了 main 方法外没有任何外部类或其他修饰。我一般称其为函数，main 既不附加到类实例也不附加到类，就像 Java 中的静态方法一样。Rust 中使用名称声明一个函数，就像在 Java 中一样，该名称以 fn 关键字为前缀，发音为 “fun ”。我们可能期望 Rust 函数可以接受参数，就像在 Java 中一样，但我们的 main 函数作为程序的入口点，不接受任何参数。我们稍后再详细解释。

最后，函数体位于大括号内，与 Java 一样，两者没有太大区别。它调用一个 类似函数的宏。在 Rust 中，这些宏带有后缀 !，这使得它们很容易被识别。你可能好奇宏来自于哪里？在 Java 中，我们会显示的调用 System.out.println()，但在 Rust 中我们看不到任何指示该宏来自何处的信息。其实宏的定义在 std::println!，考虑在 std 在某种程度上等同于 java.lang，比如 String 就来自于 java.lang，跟在 Java 中一样，我们没有必要显示的导入来自 std 的宏，编译器会为我们解决这一切。

我们将使用 Rust 编译器 rustc 编译我们的程序，此处我们使用 1.66 版本：

```


$ rustc --version
```

我们必须显式的完成编译步骤，这一点与 Java 稍有不同。Rust 程序不需要虚拟机来运行，而 Java 程序的运行依赖于 Java 虚拟机。虽然我们也可以提前将 Java 示例编译为本机代码，在这种情况下，生成的二进制文件不需要 Java 运行时来执行。但一般情况下，Java代码都运行在 Java 虚拟机中。这也是 Java 和 Rust 的区别之一。

现在我们已经了解了如何在 Rust 中运行一个程序，让我们继续在做一些更有趣的尝试。

  

## *—****2*** *—*  
**让我们更进一步**

  

我们可以修改我们的代码小例子，使其变得更有趣，我们可以向某人打招呼而不是向整个世界打招呼。这只需要简单的几步操作，首先提取被问候人员为变量：World。当没有提供参数时，我们可以继续使用 World 作为默认变量。在 Rust 中我们可以这样做：

```
let who = "World"
;"Hello, {who}!");
```

如你所见，这非常简单。我们使用关键字 let 声明绑定，绑定变量 who。在第二行，我们使用 {who} 替换变量，最终将打印  Hello World。

我们也可以给程序传递参数，以覆盖 who 的默认值。如果是 Java 代码，我想大家都会这样写：

```


public class Greeter {"World"
;if

 (args.length > 0) {"Hello, " + who + "!"

);
```

但是在 Rust 程序中我们遇到了一些问题。首先，我们应该从哪里获取参数？如前所述，我们的 main 函数不接受任何参数。这时，我们就需要用到标准库，标准库为我们提供了 std::env::args()。此函数返回一个 Args 迭代器，可以为我们返回 String 实例作为参数。

另一个问题是，在 Rust 中，变量绑定默认是不可变的。这意味着我们无法像在 Java 中那样为 who 重新赋值。或者至少不是像 Java 那样。有一种方式是，我们可以使用 mut 关键字将变量声明为可变的。

```
let mut who = "World";
```

但一般在 Rust 中，我们不会这样做。我们有充分的理由不这样做。如上代码表示，无论在什么情况下，who 都是可变的。但是我们只想重新赋值一次。其实我们还可以 if let 条件绑定。这有点类似于 Java 中的三元运算符：<booleanExpression> ? <expression1> : <expression2>。在 Java 中，我们会这样实现 who 的赋值：

```
var who = args.length > 0 ? args\[0\] : "World" ;
```

接下来，让我们看看 Rust，示例 greeter.rs：

```


 1 use std::env; main

() {let

 arguments: Vec<String> = env::args().collect();let

 anybody\_at\_all = arguments.get(1);let who = if let

 Some(one) = anybody\_at\_all {else
 {"World"

"Hello, {who}!"
);
```

Rust 程序的第 1 行声明了使用模块 std::env ，相当于在 Java 中导入了一个包。模块之间使用两个冒号 ( ::) 分隔，在 Java 中我们使用点 ( .) 分割。

在第 5 行，我们使用关键字 let 声明了一个变量 arguments。但是这次变量名后面跟着一个冒号和一个类型定义。这就是在 Rust 中将变量声明为某种类型的方式。在这种情况下，我们需要为变量声明类型 ，因为编译器无法为我们推断出迭代器将收集到什么类型的变量。Vec 相当于 Java 的 ArrayList。

在 Rust 中，我们可以像 Java 中一样使用泛型。但是 Rust 中，String 是 UTF-8 编码的，而在 Java 中是 UTF-16 编码的。最后，从我们如何填充 Vec 可以看出，Rust 的迭代器更类似于 Java Streams。

现在我们已经将所有参数传递给了 Rust 程序，我们需要验证一下。在程序的第 7 行，通过.get(index) 使用 Vec<String> 中的值。但你可能会惊讶地发现我们在这样做之前没有进行任何检查！在 Java 中，如果索引超出范围，我们可能会期望它返回空值。但在 Rust 中不一样，在 Rust 中没有空值的概念。相反，在 Rust 中我们得到了 Option<&String>。在概念上等同于 Java 中的 Option<String>。而 anybody\_at\_all 代表的意思是，要么有人问候，要么没有人。Rust 使用蛇形命名法而不是驼峰命名法。

我们注意到 arguments.get(1)，这不是说 Rust 索引从 1 开始。Rust 和 Java 一样使用从零开始的索引。但是索引的第 0 位代表的是程序在启动时调用的实际二进制文件的名称，如：./greeter。

最后在让我们聊聊 Option<&String> 中的 ＆ 符号。Rust 中的 & 符号表示一个引用。与我们在第 5 行看到的不同，第 5 行确实构造了一个变量，即包含实际字符串值的变量，而引用只包含这个变量的地址，并没有字符串的复制，该字符串的所有权仍然属于 arguments。Rust 中的 &String 相当于 Java 中的 String，都是引用地址。

第 9 行，我们使用 if let 表达式对 who 进行条件赋值。首先，if let Some(one) = anybody\_at\_all 表达式测试 anybody\_at\_all 是不是 Option::Some(T)，如果是，则代码进入第一个分支，如果不是，则进入 else 分支。该 if let 语句还执行 Rust 中所谓的解构。等号的左边代表我们期望匹配的形式。它声明了一个变量 one，它将绑定 Option::Some 中的值。

第 10 行和第 12 行的代码可能有点让人费解，代码的末尾都缺少尾随分号（;）。在 Rust 中，几乎一切都是表达式。为了定义这样的表达式的计算结果，当没有分号时，块的最后一条语句将成为表达式的计算结果。所以这两行的作用是返回 one（对从参数列表中读取的字符串值的引用，存储在 arguments 中）或 "World" 从 if let 表达式中返回。另一方面，第 13 行有一个尾随分号，它标志着 if let 语句的结束，为 who 变量赋值。接下来，我们就可以重新运行我们的 Rust 程序：

```


$ rustc greeter.rs
```

如果我们现在为 Rust 程序提供一个参数：

```

$ ./greeter John
```

我们成功了！这很容易，不是吗？

如果你觉得这个 let if 表达式有些奇怪，我们还可以使用另一种解决方案。一个在 Rust 中也很常见的 match 声明。类似于 Java 中的 switch 表达式：

```
let

 who = match anybody\_at\_all {"World"
,
```

当使用 match表达式来为 who 赋值时，与 let if 稍有不同。最终还是有两个分支。但是这一次，我们不必声明 if/else 块，我们使用 ⇒ 来表示不同的分支情况。

  

## *—****3*** *—*  
**Strings 只是 String 的实例吗？**

  

通过上面的示例，我们已经了解了两个重要的概念：String 类型和引用，用前导的 & 字符表示。让我们仔细看看上面示例中不同字符串的情况。我们已经看到 Rust 编译器可以为我们推断出许多类型，从而消除了我们显式声明类型的负担。我们仍然可以显式声明这些类型，这有助于程序员阅读代码，包括我们自己。请看下面的例子：

```


 1 use std::env;main
() {let everyone: &str = "World"

;let
 arguments: Vec<String> = env::args().collect();let

 anybody\_at\_all: Option<&String> = arguments.get(1);let who: &str = if let

 Some(one) = anybody\_at\_all {else

 {"Hello, {who}!"
);
```

代码略有修改，引入了显式类型和一个新变量。当程序没有提供参数时，就使用新变量 everyone 的默认值 "World"，正如代码的第 4 行所示。"World" 并不是 String，而是某种 &str 类型！对于 & 符号我们已经很熟悉了，它代表一个引用。对 str 的一个引用。

在解释之前，让我们先了解编译程序时，"World" 发生了什么？"World" 在编译时是已知的，因为它就在我们的源代码中。实际值将出现在编译结果的二进制文件中，即本例中的可执行文件。当程序被加载到内存中时，everyone 变量指向了 "World" 在内存中的位置。这就解释 str不是String，而是引用地址！

有几个原因 everyone 不能是 String。一方面，String 实例在 Rust 中是可变的。但 everyone 不应该被改变。话虽如此，rustc 已经禁止该引用可变，即 &mut str。此外， String 始终是堆分配的，它实际上由 Vec 组成，包含 UTF-8 编码的字符串字节，是一个 str 切片，一个视图，一个有效的 UTF-8 字节序列。实际上我们并没有直接使用 str，而是通过引用。str 也被称为 !Sized，这意味着它的大小在编译时是未知的。

因此，everyone: &str 指向内存中 World 所在的地址。引用对该位置及其指向的字符串的长度进行编码。

在代码的第 6 行，我们通过 arguments: Vec<String> 收集所有的变量。最终，我们只会打印值的引用，而不是值本身。Rust 和 Java 之间另一个非常重要的区别，是 Rust 没有垃圾收集器。所以我们需要手动的释放资源。但是，当我们查看代码时， 我们并没有看到类似 free 或者 delete 关键字。

Rust 使用 C++ 开发人员熟知的：RAII（Resource Acquisition Is Initialization）。编译器确保当一个对象超出作用域时，它就会被释放。在我们上面的例子中，当 main 函数结束时，通过 let arguments: Vec<String> 创建的资源就会被释放，不会造成内存泄露。Rust 编译器确保我们的程序只有在所有引用都指向有效的情况下才能编译。假设我们把代码修改成如下所示：

```
let anybody\_at\_all = env::args().collect::<Vec<String>>().get(1);
```

代码无法编译。它的问题在于 Vec<String>，anybody\_at\_all 指向的 &String，在创建后立即被释放，因此引用将指向可能无效的内容。编译器给了我们一个很好的错误消息，不仅解释了问题所在，还解释了如何修复：

```

$ rustc greeter.rswhile

 borrowedlet

 anybody\_at\_all = env::args().collect::<Vec<String>>().get(1);which is freed while still in

 uselet who: &str = if let

 Some(one) = anybody\_at\_all {help: consider using a \`let

\` binding to create a longer lived valuelet
 binding = env::args().collect::<Vec<String>>();let anybody\_at\_all: Option<&String> = binding.get(1);
```

现在我们不需要将所有参数都保存在内存中，因为我们只使用第一个。我们的代码可以进一步修改。首先 .skip(n)，过滤掉前 n 个条目，只保留余下的条目。最终返回 Option<String>。

```
let
 anybody\_at\_all: Option<String> = env::args().skip(1).next();let who = anybody\_at\_all.as\_ref().map\_or("World", String::as\_str);
```

在第二行，我们首先调用 .as\_ref()，返回 Option<&String>。最后调用 .map\_or()，这个方法做两件事，要么没有值，返回默认值 "World"；要么返回 &str。

你现在可能想知道为什么我们不必在以前的版本中显式映射 one: &String 到 &str。

```
let who: &str = if let

 Some(one) = anybody\_at\_all {else

 {
```

为什么第 10 行没有读取 one.to\_str()？实际上编译器为我们负责转换。不需要使用 .to\_str()，而是使用 .deref()，它来自于 trait，trait 类似于 Java 中的接口 std::ops::Deref。所以第 10 行中的 one.deref() 被隐含了。这种机制被称为 Deref coercion。

或者，我们也可以使用显式表示法，这会解除 &String 的引用，使其变成 String，然后通过使用 &\*\*one。这是一种非常奇怪的语法，实际上 Rust 语法检查器也不鼓励你这样做：

```
warning: deref which would be done

 by auto-derefhelp
: try this: \`one\`
```

Rust 语法检查器 clippy 在众多项目中被使用，它可以帮助写出更好的，符合最佳实践的 Rust 代码。  

## *—****4*** *—*  
**最后，让我们回顾一下**

  

我们已经了解了如何使用 fn 关键字在 Rust 中声明函数。函数等同于 Java 中的静态方法，但它不绑定到类。我们使用 let 关键字声明变量。在很多情况下，编译器可以推断出变量的类型，但我们可以通过在变量名前加上冒号 : 后跟类型来显式的指示类型信息。

在 std::Option 中，我们看到 Rust 的 enum 与我们在 Java 中了解到的不同。我们使用几种方式 let if 和 match 语句进行模式匹配，并利用公开的功能更强大的样式 API 有条件地分配给变量。

最后，在为程序提供第一个参数时，我们更多地考虑了数据存在的位置及其生命周期。介绍了两种不同类型的字符串：String 和 str，学会了使用引用以及如何解引用。

我们希望，从现在开始，通过以下的小项目，让我们更多的学习 Rust。

```


$ cargo new playgroundcd

 playgroundmain
() {"Hello, world!"

);in

 0.78s
```

又见 Hello, world!，但这会稍有不同，我们使用了构建工具 cargo，类似于 Java 中的 Maven 或 Gradle。

当你开始编写 Rust 代码时，请确保定期运行 cargo clippy，我保证这个会非常有用！
