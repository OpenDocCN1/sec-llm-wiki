Kafka母公司收购Flink核心团队创建的新公司Immerok，收购金额未知

美国东部时间 1 月 6 日早上 9 点，科技巨头 Confluent 联合创始人兼 CTO Jay Kreps 在 Confluent 官方博客撰文宣布收购了初创公司 Immerok。Immerok 是由 Flink 项目核心团队在 2022 年成立的商业化公司。2019 年阿里巴巴花 9000 万欧元收购了 Flink 项目母公司 Ververica，Ververica 的核心团队成员在之后陆续离职，然后创办了 Immerok，Immerok 与 Ververica 做的事情几乎一样，即在云上商业化 Flink。以下内容翻译自 Confluent 官方博客。

我非常高兴地宣布，我们已经签署了收购 Immerok 的最终协议，Immerok 是一家为 Apache Flink 提供完全托管服务的初创公司。他们将加入 Confluent 帮助我们向 Confluent Cloud 添加完全托管的 Flink 产品。对于 Confluent 来说，这是非常令人兴奋的一步，我想解释一下我们在流处理、Immerok 团队方面的战略，以及为什么我们对 Flink 如此兴奋。

先让我说一下为什么 Confluent 专注于流处理。我们的使命是让数据运转起来——也就是说，让流数据成为新的默认值，并让数据流平台成为现代数据架构的核心。但是，为了使流式传输成为默认设置，我们需要让它变得简单！

这包括两个部分——一是在操作上容易获得流媒体功能，二是使使用流媒体的应用程序的开发像批处理或任何其他现代应用程序一样容易和自然。在运营方面，我们通过 Confluent Cloud 解决了这个问题，它让客户获得一个令人难以置信的以 Apache Kafka 为中心的数据流平台，作为一种弹性、可扩展、安全的服务。但是，为了使流式传输成为默认设置，我们需要使数据流的开发，也就是流处理，变得同样容易。  

长期以来，Confluent 一直通过 Kafka Streams、KSQL 和 Kafka 中的一些底层事务功能为围绕 Kafka 的新兴流处理生态系统做出贡献，这些功能有助于实现所有流技术的正确性。

为什么要加入 Flink？好吧，多年来，我们一直在关注 Flink 的发展，并看到它在我们的许多客户中得到采用。Flink 拥有最好的多语言支持，对 SQL、Java 和 Python 的支持一流。它有一个原则性的处理模型，可以泛化批处理和流处理。它具有出色的状态管理和容错模型。也许最重要的是，它拥有一个非常聪明、创新的社区来推动它向前发展。在考虑我们的云产品和我们想用流处理做什么时，我们意识到提供 Flink 服务将帮助我们提供客户想要的接口和功能，并且可以作为我们未来流处理战略的核心。

简而言之：我们相信 Flink 是流处理的未来。我们已经从开源的方向、商业产品的数量以及我们从客户那里听到的信息中看到了这一点。就像 Kafka 是整个组织中读写和共享流的明确事实标准一样，Flink 正在成为构建处理、反应和响应这些流的应用程序的明确事实标准。

这使我想到了为什么我们对 Immerok 团队如此兴奋。首先，他们建立了一个团队，在帮助建立 Flink 和发展其社区方面做出了令人难以置信的工作。他们利用这些专业知识构建了世界上最先进的 Apache Flink 服务。他们也是一群聪明、谦虚的人，他们有远大的计划，所以他们很适合 Confluent。

当然，我们会继续投资 Kafka 流、KSQL 中的原生功能，并支持与 Spark、Materialize 等外部系统的集成。特别是 Kafka Streams 作为简单事件驱动应用程序的基础已证明非常成功，并且在 Kafka 生态系统中占有重要地位。我们看到了一个围绕流媒体的开放的生态系统，并试图鼓励它蓬勃发展。

我们的努力将不仅仅围绕我们的产品。我们认为这些技术的力量来自于它们的社区。我们将像为 Kafka 一样为 Flink 做出贡献。Flink 社区正在蓬勃发展，但我们认为我们也可以为其做出贡献。毕竟，我们的目标是帮助使流处理和事件驱动的应用程序成为处理数据的默认机制。而这在很大程度上需要整个社区的努力，而不仅仅是一个公司。

在我们的产品计划方面，我们计划在今年晚些时候在 Confluent Cloud 中推出我们的 Flink 产品的第一个版本，从支持 SQL 开始，随着时间的推移扩展到整个平台。

我们希望遵循我们引入 Kafka 产品的相同关键原则：构建一个真正的云原生服务（不仅仅是在云实例上托管开源），是一个完整的、完全集成的产品，并在所有主要的云上随处可用。除此之外，我们认为巨大的机会是构建比自己动手要更简单、更安全、更具可扩展性的东西。我们认为我们可以让 Kafka 和 Flink 无缝衔接，就像数据库的查询和存储层一样，这样你就不必担心所有的繁琐环节，把这些层作为独立的系统来管理、保护、监控和操作。你可以专注于真正重要的事情，建立很酷的实时应用程序，这是真正的价值。

我们对这个方向以及 Immerok 团队加入 Confluent 感到无比兴奋。我们认为他们在 Flink 方面拥有深厚的专业知识和技术，以及我们将其集成到我们的服务中的能力，使我们能够继续重新定义数据流平台的标准。我希望你和我一样对此感到兴奋。请继续关注未来的发展。
