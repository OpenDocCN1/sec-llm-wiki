“ 权限不一定非要通过弱口令、RCE、文件上传、注入等漏洞去获取 ”



五月初的某个晚上，有个女孩子私聊我，问我怎么绕过修改密码的界面，此界面使用初始密码登录后，强制要求修改符合密码复杂度的密码。


由于这个年龄晚上睡不着很正常，所以就帮妹妹看了一下这个学校



信息收集

—


妹妹告知了我该学校的一部分信息（学号和学校情况），然后我就想着能不能拿下一个站点权限，毕竟不能 Getshell 的安服仔不是一个好的安服仔！


在信息搜集的时候发现了一个可能可以获取权限的站点


站点如下，这里有个 "我要咨询" 栏



点进去之后发现可以上传附件，但是有白名单限制了上传文件的后缀




测试发现此处无上传漏洞，但是在对 js 进行分析的时候，发现了一个图片管理的接口，此处可以预览部分被上传的图片，如下图：





发现入侵痕迹

—


在此处发现了疑似是 webshell 的文件，上传时间点主要是去年年中和今年年初



在其中一个图片中找到了 webshell 的代码

(由于写文章的时间，和之前测试时不一样，原先发现的 webshell 部分已经被删除)



那么这里大胆猜测一下，应该有一个技术还不错的骇客已经成功拿到了该站的权限了，目前漏洞已经被修补了，我们现在能做的就是通过别人留下来的马拿到权限


通过分析此处路径可知，上传成功后，文件被保存在服务器的路径是：/uploadfiles/文件后缀/年月/日/文件名


此时直接访问以下两个目录，以此来判断是否存在 jsp 或者 jspx 的马在服务器


http://x.x.x.x/uploadfiles/jsphttp://x.x.x.x/uploadfiles/jspx

访问发现存在 jspx 目录，此时就说明该站点曾经应该被上传过一个 jspx 的 webshell


那么现在的思路就是去进行迭代爆破，先爆破年月，拿到年月再爆破日期，最后再尝试爆破 shell 文件名




成功帮妹妹拿到shell

—


时间爆破范围应该是在 2020年-2022年

通过爆破，找到了 webshell 的上传年月

继续爆破发现了日期

此时只差确定 webshell 的文件名了，这里随缘爆破 1-9999

结果是没想到真爆的出来了一个 111.jspx

直接上 github 搜这个返回内容，找到马的密码进行连接


通过查询 edu 上该校漏洞的历史提交记录发现，当前时间节点无任何 getshell 的高危漏洞，因此确认是被恶意上传的木马后门


整体复盘

—


此漏洞已报告给学校！
