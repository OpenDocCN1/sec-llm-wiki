# 帮妹妹获取学校权限

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=Mzk0OTM5MTk0OA==&mid=2247483797&idx=1&sn=bfb6ef5c2287b3cab32942a7f6abce5d&chksm=c35846b6f42fcfa0fa21a5fc4fd17903147653b1bf1f7216e103464c514a822ad33da2ac3d40&scene=126&sessionid=1681666711#rd](http://mp.weixin.qq.com/s?__biz=Mzk0OTM5MTk0OA==&mid=2247483797&idx=1&sn=bfb6ef5c2287b3cab32942a7f6abce5d&chksm=c35846b6f42fcfa0fa21a5fc4fd17903147653b1bf1f7216e103464c514a822ad33da2ac3d40&scene=126&sessionid=1681666711#rd)

**“ **权限不一定非要通过弱口令、RCE、文件上传、注入等漏洞去获取 **”**  

  

  

五月初的某个晚上，有个女孩子私聊我，问我怎么绕过修改密码的界面，此界面使用初始密码登录后，强制要求修改符合密码复杂度的密码。

![](../Images/7958fe552357ce79d5d7a498442c9234.png)

  

由于这个年龄晚上睡不着很正常，所以就帮妹妹看了一下这个学校

  

  

信息收集

—

  

妹妹告知了我该学校的一部分信息（学号和学校情况），然后我就想着能不能拿下一个站点权限，毕竟不能 Getshell 的安服仔不是一个好的安服仔！

  

在信息搜集的时候发现了一个可能可以获取权限的站点

  

站点如下，这里有个 "我要咨询" 栏

  

![](../Images/b472264c1e9d4cb76086a2852b68bc9d.png)

  

点进去之后发现可以上传附件，但是有白名单限制了上传文件的后缀

  

![](../Images/84ce77a0ba1cbae9825ccf46cc176d59.png)  

  

测试发现此处无上传漏洞，但是在对 js 进行分析的时候，发现了一个图片管理的接口，此处可以预览部分被上传的图片，如下图：

  

![](../Images/14b9aacff289050dae40d7f93651202e.png)

  

  

  

发现入侵痕迹

—

  

在此处发现了疑似是 webshell 的文件，上传时间点主要是去年年中和今年年初

  

![](../Images/50d09db1e4b4dab9e8d96887d96206fd.png)

  

在其中一个图片中找到了 webshell 的代码

(由于写文章的时间，和之前测试时不一样，原先发现的 webshell 部分已经被删除)

  

![](../Images/92b377225aea9d95f6e439d865e01c28.png)

  

那么这里大胆猜测一下，应该有一个技术还不错的骇客已经成功拿到了该站的权限了，目前漏洞已经被修补了，我们现在能做的就是通过别人留下来的马拿到权限

  

通过分析此处路径可知，上传成功后，文件被保存在服务器的路径是：/uploadfiles/文件后缀/年月/日/文件名

![](../Images/68617623e8955ef6dbcc1c7f7d040c57.png)  

此时直接访问以下两个目录，以此来判断是否存在 jsp 或者 jspx 的马在服务器  

  

*   
*   

```
http://x.x.x.x/uploadfiles/jsphttp://x.x.x.x/uploadfiles/jspx
```

访问发现存在 jspx 目录，此时就说明该站点曾经应该被上传过一个 jspx 的 webshell  

![](../Images/fabe08663f65392122b810328a6391f6.png)

  

那么现在的思路就是去进行迭代爆破，先爆破年月，拿到年月再爆破日期，最后再尝试爆破 shell 文件名

  

  

  

成功帮妹妹拿到shell

—

  

时间爆破范围应该是在 2020年-2022年

![](../Images/26aded78061c502002fae8683a449504.png)

通过爆破，找到了 webshell 的上传年月

![](../Images/98db9ca1fbb375c5a6c423075c02baba.png)

继续爆破发现了日期  

![](../Images/16d8df6a4a210dc10c726e40ae6bed2e.png)

此时只差确定 webshell 的文件名了，这里随缘爆破 1-9999

![](../Images/039b728c5149697f1822d753f57b5b20.png)

结果是没想到真爆的出来了一个 111.jspx

![](../Images/9a6b2e32d55b18abf2854273034962a9.png)

直接上 github 搜这个返回内容，找到马的密码进行连接  

![](../Images/add00b2a567c41312b6588458eb27c6d.png)

  

通过查询 edu 上该校漏洞的历史提交记录发现，当前时间节点无任何 getshell 的高危漏洞，因此确认是被恶意上传的木马后门

![](../Images/1b80de07c4e23cdab9052d5b07bb1fb5.png)

  

整体复盘

—

![](../Images/b379b289a5fcdaf9c630331105f0d4bc.png)

![](../Images/afffe0606bc6d4db73d79eb843afc355.png)

  

此漏洞已报告给学校！
