### **4.13 操作系统的控制**

####   

#### \--os-cmd和\--os-shell 执行任意操作系统命令

若数据库管理系统是MySQL、PostgreSQL或微软的SQL Server且当前用户有相关权限Sqlmap就能利用SQL注入执行任意的操作系统命令。

当数据库管理系统是MySQL或PostgreSQL时，Sqlmap会通过前面介绍过的文件上传功能上传一个包含用户自定义函数sys\_exec()和sys\_eval()的二进制共享库文件，然后创建这两个用户自定义函数，通过这两个函数之一来执行用户指定的命令。选择哪个函数取决于用户是否想要显示命令执行的标准输出。  

  

当数据库管理系统是微软的SQL Server时，Sqlmap通过存储过程xp\_cmdshell来执行任意命令。若xp\_cmdshell被禁用（SQL Server >= 2005时默认禁用）Sqlmap会启用它；若xp\_cmdshell不存在，Sqlmap会创建它。当用户想要看到命令执行的标准输出时，Sqlmap使用可列举的注入技术（盲注、联合查询和报错注入），而当用户不想看到命令执行的标准输出时，堆查询注入技术将被用于执行命令。  

python sqlmap.py -u "目标链接" --os-cmd

 

![](../Images/227b0036f6e1915b794cd76e5ad06f9b.png)

####   

#### \--os-pwn, --os-smbrelay, --os-bof, --priv-esc, --msf-path和--tmp-path 带外TCP连接：Meterpreter及相关  

若数据库管理系统是MySQL、PostgreSQL或微软的SQL Server且当前用户有相关权限Sqlmap就有可能在攻击者的主机和数据库所在主机之间建立带外TCP连接。根据用户的选择，此连接可以是交互式命令shell，Meterpreter会话或图形用户界面（VNC）会话。

Sqlmap要靠Metasploit生成shellcode，在数据库所在主机执行shellcode有以下四种技术：

Ø 数据库通过Sqlmap创建的用户自定义函数sys\_bineval()在内存中执行Metasploit的shellcode。支持MySQL和PostgreSQL。参数“--os-pwn”。

Ø 通过Sqlmap自己的用户自定义函数（MySQL和PostgreSQL中的sys\_exec()，微软SQL Server中的xp\_cmdshell()）上传并执行Metasploit的“stand-alone payload stager”。参数：“--os-pwn”。

Ø 利用远程代码执行漏洞MS08-068。攻击者的机器要用Metasploit的smb\_relay监听来自目标机器的连接。要求在Linux/Unix上以root权限运行Sqlmap且目标DBMS在Windows上以管理员权限运行。参数：“--os-smbrelay”。

Ø 在微软SQL Server 2000和2005中可通过存储过程sp\_replwritetovarbin的堆缓冲区溢出漏洞（MS09-004）在内存中执行Metasploit的shellcode。Sqlmap有自己的数据执行保护绕过技术可以成功利用漏洞，但需要Metasploit生成shellcode以便在成功利用漏洞时执行shellcode。参数：“--os-bof”。  

  

在Windows中Mysql默认以SYSTEM身份运行，但PostgreSQL无论是在Windows还是在Linux中都以低权限的用户postgres运行。SQL Server 2000默认以SYSTEM身份运行，但SQL Server 2005到2008大多数时间以NETWORK SERVICE身份运行，少数时候以LOCAL SERVICE身份运行。使用参数“--priv-esc”可以执行Metasploit的getsystem命令以尝试提升权限。

### **4.14 Windows注册表操作**

满足以下条件就可以对Windows注册表进行操作：

目标数据库管理系统是运行在Windows上的

目标数据库管理系统是MySQL、PostgreSQL或微软SQL Server

支持堆查询

目标数据库管理系统当前用户有足够的权限  

  

#### \--reg-read 读取Windows注册表项值

#### \--reg-add写入Windows注册表项值

#### \--reg-del 删除Windows注册表项  

#### \--reg-key, --reg-value, --reg-data和--reg-type 辅助注册表选项

适当使用上列参数就可以在命令中添加或修改一个Windows注册表键值而不用在Sqlmap运行时以问答方式提供数据。

Ø \--reg-key：指定Windows注册表键值的路径

Ø \--reg-value：指定Windows注册表键值的键

Ø \--reg-data：指定Windows注册表键值的值

Ø \--reg-type：指定Windows注册表键值的值的数据类型

 python sqlmap.py -u  "目标链接" --reg-add  

\--reg-key="HKEY\_LOCAL\_MACHINE\\SOFTWARE\\sqlmap"  

\--reg-value=Test --reg-type=REG\_SZ --reg-data=1

### **4.15 通用选项**

####   

#### \-s 从SQLite文件中载入Sqlmap会话

Sqlmap会自动地为每一个目标创建长久保存的会话SQLite文件，该文件统一存储在特定目录（如：~/.sqlmap/output/）中，其中保存着恢复会话所需的所有数据。若用户想要明确地指定SQLite文件（例如想要将多个目标的数据存储到同一个SQLite文件中），可使用此参数。

####   

#### \-t 将HTTP(S)流量记录到日志文件中

该参数后跟一个文件路径，用于将HTTP(S)请求和响应以文本格式记录到文件中作为日志。这样的日志在调试时是很有用的。

####   

#### \--answers 为问题设定答案

如果用户希望自动设置问题的答案，即使\--batch使用，也可使用此选项，可以通过在等号后提供问题的任何部分和答案来完成这一操作。另外，不同问题的答案可以用分隔符分割逗号。

python sqlmap.py -u "目标链接" --answers="extending=N" --batch

####   

#### \--base64 声明包含base 64编码数据的参数

如果目标web应用程序使用base 64编码将数据存储在特定参数(例如base 64编码的JSON字典)中，用户可以使用选项声明它--base64从而指示sqlmap正确地测试基础值。

python sqlmap.py -u "目标链接" --base64=value

####   

#### \--batch 非交互模式

使用该参数可以让Sqlmap以非交互模式运行，所有要求的输入都会取默认值。

python sqlmap.py -u "目标链接" --batch

####   

#### \--binary-fields 二进制内容检索

在二进制内容检索的情况下，类似于具有存储二进制值的列的表(例如，列)。password使用二进制存储的密码散列值)，可以使用选项。--binary-fields为了(额外)用平面图进行适当的处理。然后检索所有这些字段(即表列)，并以它们的十六进制表示形式表示它们，因此之后可以使用其他工具正确地处理这些字段(例如，john).

python sqlmap.py -u "目标链接" --binary-fields

####   

#### \--charset 设置字符编码

为正确解码数据，Sqlmap会使用Web服务器提供的信息（如HTTP头部中字符编码的设置），或是使用第三方库chardet来启发式地确定字符编码。可以使用参数“--charset”来指定字符编码，如“--charset=GBK”。

python sqlmap.py -u "目标链接" --charset=GBK

####   

#### \--crawl 从目标URL开始爬取目标站点

Sqlmap可以从目标URL开始爬取目标站点并收集可能存在漏洞的URL。使用该参数还需要设置爬取深度，深度是相对于开始爬取的目标URL而言的。只有所有新链接都被递归地访问过后才算爬取结束。建议该参数与“--delay”配合使用。

python sqlmap.py -u "目标链接" --batch --crawl=3

  

![](../Images/28fffbfe552b6edfff34f997aafa8084.png)

####   

#### \--crawl-exclude 从目标URL排除爬取目标站点

在此参数后跟一个正则表达式可以排除不想爬取的URL。若URL匹配正则，则不被爬取。如用“--crawl-exclude=logout”来排除所有含有字符串“logout”的URL。

python sqlmap.py -u "目标链接" --crawl-exclude=logout

####   

#### \--csv-del CSV输出中使用的分隔字符

当数据被输出到CSV文件（\--dump-format=CSV）时，默认以“,”分隔，可以使用此参数指定分隔符。如：

python sqlmap.py -u "目标链接" --dump-format=CSV ---csv-del=”;”

####   

#### \--dbms-cred 数据库管理系统认证凭据

在某些情况下由于数据库管理系统当前用户权限较低从而导致动作执行失败，此时可以用此参数提供admin用户认证凭据，Sqlmap就会对执行失败的部分特地使用“run as”机制（如：微软SQL Server的OPENROWSET）以admin用户身份重新执行失败的动作。当然，得知道admin用户认证凭据才行。

####   

#### \--dump-format 导出数据格式

Sqlmap对列举的数据有三种不同的输出格式：CSV、HTML和SQLITE。默认为CSV格式，每个数据表都被保存到一个文本文件中，一行是一条记录，以逗号分隔（或是用“--csv-del”指定分隔符）。选择HTML格式，所有数据被保存在一个HTML文件中，数据存放在一个个table中。选择SQLITE格式，所有数据被保存在一个SQLITE文件中，SQLITE中表名和结构会和原表相同。

python sqlmap.py -u "目标链接" --dump-format=HTML

####   

#### \--encoding 用于数据检索的强制字符编码

为了正确解码字符数据，sqlmap使用Web服务器提供的信息(例如HTTP报头Content-Type)来获得编码格式。在某些情况下，该值必须被覆盖，特别是在检索包含国际非ASCII字符的数据时(例如：--encoding=GBK)必须指出，由于存储的数据库内容与目标端使用的数据库连接器之间隐含的不兼容性，字符信息可能会不可逆转地丢失。

####   

#### \--eta 估计完成时间

该参数用于显示估计的完成时间。

python sqlmap.py -u "目标链接"  -b --eta

sqlmap首先计算查询输出的长度，然后估计到达时间，以百分比表示进度，并计算检索到的输出字符数。

####   

#### \--forms 解析和测试表单的输入字段

除了用“\-r”和“--data”来测试表单数据（POST）是否存在注入点外，还可以使用参数“--forms”来测试表单数据是否存在注入点。

同时使用参数“--forms”和“\-u”，Sqlmap会解析目标URL（“\-u”指定的那个URL）返回页面中的表单，测试表单是否有注入点，而不对目标URL进行注入测试。

python sqlmap.py -u "目标链接"  --forms

####   

#### \--fresh-queries 忽略会话文件中的查询结果

使用此参数用于忽略会话文件中的查询结果重新执行查询

python sqlmap.py -u "目标链接"  --fresh-queries

####   

#### \--flush-session 刷新会话文件

使用该参数可以刷新会话文件，以避免Sqlmap默认的缓存机制可能造成的一些问题。使用该参数的前提是真正理解会话文件的概念。另外一个可行的方法是手工删除会话文件。

python sqlmap.py -u "目标链接"  --flush-session

####   

#### \--hex 使用DBMS十六进制函数进行数据检索

非ASCII数据很容易在传输时出错，使用hex函数可以将目标数据库中数据以十六进制返回。

python sqlmap.py -u "目标链接"  --banner --hex -v 3

 

![](../Images/8e28102a213949275d8af7162d321d4d.png)

####   

#### \--output-dir 自定义输出目录路径

Sqlmap默认将会话文件和结果文件保存到某个子目录output中，可以使用此参数指定输出目录，如：“--output-dir=/tmp”。

python sqlmap.py -u "目标链接" --output-dir=/tmp

####   

#### \--parse-errors 从响应页解析DBMS错误消息

若是Web应用被配置成Debug模式则很可能在HTTP响应页面中显示SQL错误信息。这些错误信息对于理解某操作失败的原因是很有用的。例如因为权限不足导致的失败错误信息是类似这样的：“Access denied for user ”。

python sqlmap.py -u "目标链接" --parse-errors

####   

#### \--preprocess 预处理响应数据

使用此选项，可以在sqlmap检测引擎使用之前对(HTTP)响应数据使用预处理脚本(例如解码数据或删除垃圾)。例如，将所有小写字符转换为大写字符的预处理脚本可以是：

def preprocess(page, headers=None, code=None):

return page.upper() if page else page, headers, code

####   

#### \--save 在配置INI文件中保存选项

使用该参数可以保存Sqlmap命令行参数到配置文件中，该文件可编辑并且可以使用参数“\-c”加载。配置文件是INI格式的。

#### \--update 更新sqlmap

python sqlmap.py --update

###   

### **4.16 杂项**

####   

#### \-z 使用简写

有些参数组合是被经常用到的，如

\--batch --random-agent --ignore-proxy --technique=BEU

这样写一大串很不好看，在Sqlmap中，提供了一种简写的方式来缩短命令长度。利用参数“\-z”，每个参数都可以只写前几个字母，如“--batch”可以简写为“bat”。简写的原则是能够有所区别、对应的参数唯一就行。各个参数用逗号隔开。如：

python sqlmap.py --batch --random-agent --ignore-proxy --technique=BEU -u "目标链接"

可以简写为：

python sqlmap.py -z "bat,randoma,ign,tec=BEU" -u "目标链接"

####   

#### \--alert 在成功检测到注入点时报警  

python sqlmap.py -r data.txt --alert "找到漏洞了"

####   

#### \--beep 在找到sql注入时发出蜂鸣声

使用此参数可以在成功检测到注入点时发出“嘟”声。使用“\-m”从日志文件中检测大量网站时该参数会格外有用。

####   

#### \--cleanup 从sqlmap特定的UDF和表中清除DBMS

强烈推荐在测试结束后使用此参数清除Sqlmap创建的临时表和自定义函数，Sqlmap会尽可能地清除数据库管理系统和文件系统上的入侵痕迹。

python sqlmap.py -u "目标链接" --cleanup

####   

#### \--dependencies 检查依赖

Sqlmap的有些功能依赖第三方库，在用到时发现没有这些库会报错退出。使用此参数可以检查依赖的第三方库是否安装

python sqlmap.py -u "目标链接" --dependencies

####   

#### \--disable-coloring 禁用控制台输出着色

在默认情况下，sqlmap在写控制台时使用着色。如果效果不理想(例如控制台外观未解释的ANSI着色代码，如\\x01\\x1b\[0;32m\\x02\[INFO\])可以使用此开关禁用控制台输出着色。

####   

#### \--gpage 指定使用Google dork结果的某页

使用参数“\-g”默认选择Google dork结果的前100条做注入测试。结合使用此参数，可以指定使用Google dork结果的某页。

python sqlmap.py -g "inurl：aspx?id=" --gpage 20

####   

#### \--hpp 使用HTTP参数污染

HTTP参数污染(HPP)是绕过WAF/IPS保护机制的一种方法。这对于ASP/IIS和ASP.NET/IIS平台尤其有效。如果怀疑目标是这样的保护，可以使用这个开关绕过。

python sqlmap.py -u "目标链接" --hpp

####   

#### \--identify-waf 彻底测试WAF/IPS保护

Sqlmap可以识别WAF/IPS/IDS以便用户进行针对性操作（如：添加“--tamper”）。目前Sqlmap支持检测30多种不同的WAF/IPS/IDS，如Airlock和Barracuda WAF等。检测WAF的脚本可以在安装目录的waf目录中找到。

python sqlmap.py -u "目标链接" --identify-waf

####   

#### \--skip-waf 禁止发送虚假playload试探

默认地Sqlmap会发送虚假的SQL注入playload以试探目标是否有保护措施。如有任何问题，用户可以使用参数“--skip-waf”来禁用这一技术。

python sqlmap.py -u "目标链接" --skip-waf

####   

#### \--mobile 模拟智能手机

有些网站对智能手机和桌面环境的返回是不同的。当需要测试这种网站的智能手机页面时可以设置一个智能手机的User-Agent，或者更简单地，使用此参数，Sqlmap会在执行时询问要模仿成流行的手机中的哪种。

python sqlmap.py -u "目标链接" --mobile 

####   

#### \--offline 在脱机模式下工作(仅使用会话数据)

使用此参数\--offline sqlmap将仅在数据枚举中使用以前的会话数据。这基本上意味着在这样的运行过程中将出现零连接尝试。

python sqlmap.py -u "目标链接" --offline 

####   

#### \--purge 安全地从数据目录中删除所有内容

与参数“\-g”一起使用，这会使Sqlmap向Google发起更多的请求并展示页面权重。

python sqlmap.py -g "inurl：aspx?id=" --purge

####   

#### \--smart 快速扫描

当有大量URL要进行测试（如：“\-m”），目的是尽快找出其中存在的某些注入点而有所遗漏也没有关系时可以使用“--smart”进行正向启发式扫描。此时只有让数据库管理系统报错的参数才会做进一步测试，其余URL均被跳过。

####   

#### \--test-filter --test-skip 通过关键词使用或跳过payload

若只想使用包含关键词“ROW”的payload可使用参数“--test-filter=ROW

python sqlmap.py -u "目标链接" --batch --test-filter=ROW

若不想使用包含关键词“BENCHMARK”的payload可使用参数“--test-skip=BENCHMARK”。

python sqlmap.py -u "目标链接" --batch --test-skip=BENCHMARK

####   

#### \--sqlmap-shell 交互式Sqlmap Shell

使用此参数可以打开一个交互式的Sqlmap Shell，支持历史记录  

![](../Images/d1293a55a57b844a12597827fc1fe5d3.png)  

python sqlmap.py --sqlmap-shell

####   

#### \--wizard 为初学者准备的简单向导

Sqlmap特地为初学者准备了一个有着尽可能少问题的工作流的向导。用户输入目标后若一直按回车选择默认回答到工作流的最后也会得到一个正确的结果。
