# 企业级渗透测试流程

渗透测试需遵照以下流程开展：

Ø  确定授权和授权范围：渗透测试人员在作业之前需根据项目的需要，确定本次项目的测试范围，允许使用的测试方法，是否允许使用暴力破解、拒绝服务等手段，需要在《渗透测试授权委托书》中明确体现；

Ø  渗透作业：根据授权测试范围和授权的测试方法，依据手册标准中提供的漏洞识别测试指导技术进行对系统的渗透测试作业，按照相应的测试方法对web系统进行相应的测试即可；

Ø  项目结束及报告输出：渗透过程中发现的高危漏洞需及时通知项目授权方进行修复，项目结束后可依据本手册标准中提供的渗透测试报告模板进行报告输出。

测试主要包括主动模式和被动模式两种。在被动模式下，测试人员尽可能的了解应用系统逻辑、收集信息：比如用工具分析所有的HTTP请求及响应，以便测试人员掌握应用系统所有的接入点（包括HTTP头，参数，cookies等），了解应用系统使用的CMS类型查找已存在的相关漏洞；在主动模式中，测试人员以黑客的身份来对应用及其系统、后台等进行渗透测试，其可能造成的影响主要是数据破坏、拒绝服务等。

一般测试人员需要先熟悉目标系统收集相关信息，即被动模式下的测试，然后再开展进一步的带有攻击性的测试分析，即主动模式下的测试。主动测试会与被测目标进行直接的数据交互，而被动测试不需要。

 ![](../Images/e58b631b82829ecaadf651d8c2e59edd.png)

l  Web安全测试的执行，对于被测系统，或多或少都会存在一些影响（比如性能、垃圾数据），因此建议只在测试环境中进行；如果一定要在实际应用环境中执行，那么必须要配置专门的测试数据，测试执行时应该慎重选择要使用的测试手段，只能修改或删除已配置的测试数据，禁止修改、删除现有系统中的其他数据。

l  如果是内部试验环境进行测试，可以考虑去除一些防护措施或设备（如防火墙），以保证发现问题的全面性。

l  根据最严格的方式对目标进行测试，如果产品线对安全的要求不高且有自身的安全策略规定时，可以视情况对测试项进行部分测试。例如密码策略测试项中，测试人员可以根据测试目标的密码位数要求进行测试，而不需要完全依照测试项里面规定的位数进行测试。
