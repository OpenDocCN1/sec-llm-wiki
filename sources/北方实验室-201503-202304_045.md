# Apache Log4j-2任意代码执行漏洞及修复建议

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzU2Mjg2NjkzOA==&mid=2247489438&idx=1&sn=1d1c77d1d75aa7aa275c42e17041a5c3&chksm=fc63a80bcb14211d20a03a01228bc8733211b247e818e28ed3faa5c5e7f57a454a6d2173b177&scene=126&sessionid=1681668595#rd](http://mp.weixin.qq.com/s?__biz=MzU2Mjg2NjkzOA==&mid=2247489438&idx=1&sn=1d1c77d1d75aa7aa275c42e17041a5c3&chksm=fc63a80bcb14211d20a03a01228bc8733211b247e818e28ed3faa5c5e7f57a454a6d2173b177&scene=126&sessionid=1681668595#rd)

日前曝出的Apache Log4j-2任意代码执行漏洞影响范围广，利用门槛低，危害大，需要广大网络安全运营者尽快采取措施。

  

**0****1****漏洞描述**  
  

开源的东西用的人多了，自然漏洞就多。Apache Log4j 是 Apache 的一个开源项目，用于日志记录，使用非常灵活，在相当多的开源项目中都有使用。Apache log4j-2 是 Log4j 的升级，可以控制日志信息输送的目的地为控制台、文件、GUI组件等，通过定义每一条日志信息的级别，能够更加细致地控制日志的生成过程。

Log4j-2中存在JNDI注入漏洞，当程序将用户输入的数据进行日志记录时，即可触发此漏洞，成功利用此漏洞可以在目标服务器上执行任意代码。

  

**0****2****漏洞危害**  
  

攻击者可以通过发送专门设计的数据请求到受影响的应用来触发此漏洞。在应用使用Apache Log4j 组件进行日志记录，并对攻击者的恶意输入进行打印的情况下，将触发远程代码执行漏洞。

  

**0****3****影响版本**  
  

     ![](../Images/ba56f6873c7d5c79d049f329856d8e7c.png)

  

**0****4****修复方案**  
  

1\. 等保云防用户无需升级，该漏洞默认已支持拦截。

2\. 建议排查Java应用是否引入log4j-api , log4j-core 两个jar，若存在使用，极大可能会受到影响，强烈建议受影响用户尽快进行防护。

3\. Apache Log4j 官方已经发布了解决上述漏洞的安全更新，建议受影响用户尽快升级到安全版本，如：log4j-2.15.0-rc1。

下载链接：

https://github.com/apache/logging-log4j2/releases/tag/log4j-2.15.0-rc2

4\. 建议对 Apache Struts2/Apache Solr/Apache Flink/Apache Druid 等已知受影响的应用及组件进行升级。
