# 企业采用IPFS的几大理由

筑起围墙的花园

在过去15年里，数据存储供应商围绕着他们的云端服务建造了巨大的“围墙”。正如Wasabi首席执行官David Friend指出：“亚马逊和微软正在围绕各自的云端产品打造互不兼容的“花园”——云供应商在技术层面和商业模式方面都缺乏跨全行业的独立标准。”许多组织都已经意识到他们被锁定在一个僵化的、孤立的世界中。在这个世界中，将数据存储在一个“云端”或另一个“云端”中可以减少控制并增加成本。这是一个与开放的世界正好相反的世界，存储供应商间的相互操作减少了与供应商锁定的依赖关系，避免了设备故障，并允许组织利用各种供应商提供专门的服务。然而，我们还没有一个有效的方法来做到这一点，组织数据目前无法移植。  

数据可移植性  

数据可移植性是一个经常与终端用户相关联的术语，根据维基百科资料记载，“数据可移植性是一个防止用户的数据存储在彼此不兼容的‘孤岛’或‘筑起围墙的花园’的概念”，即封闭的平台，从而使他们受制于供应商锁定。数据可移植性需要通用的技术标准来促进从一个数据控制器到另一个控制器的传输，提高互操作性。”  

这是Web3生态系统中经常讨论的一个伟大想法。但是，数据的可移植性不应该仅仅被认为是终端用户的事情。初创企业到企业的组织也应该能够轻松地跨供应商移植数据，并具有互操作性。  

IPFS是用于数据存储的众创空间

![](../Images/35fb0f92126ecbe4f339d3c095d9ef6f.png)

理想的情况是：只需要动动手指，组织就可以通过任何云端提供商转移和存储数据，包括内部选项。正如数据可移植性的定义所指出的，你需要一个标准和一个协议。不管云端提供商或支持它的底层设备是什么，IPFS允许你轻松地存储和转移数据。这允许组织以供应商的方式来存储数据。

“更改数据存储提供商应该要像更改CDN供应商一样容易。”  

在今天的背景下，更改数据存储提供程序应该与更改CDN提供程序一样容易。数据存储应该是易于交换的、便捷的，这样你就可以根据组织在成本或性能方面的需求进行优化。换句话说，IPFS将使数据存储像众创空间（WeWork）提供办公空间一样简单和灵活。这是因为IPFS允许低交换成本和多种可用选项。  

“IPFS将使数据存储变得轻松灵活，正如WeWork可以提供办公空间一样。”  

这样做将使组织能够开始以以前无法做到的方式存储和移动数据。这将为终端用户开启新的商业模式和效率，包括推动普及数字身份。那么，这个IPFS世界将会是什么样子呢?  

通过IPFS进行组织数据控制  

![](../Images/91aa98a92510626122ba1273441a9c07.png)

本地数据存储  

上图显示了一个组织的实例，该组织使用自己的本地服务器将数据存储在IPFS上。从控制的角度来看，拥有数据及其存储位置，组织可以对数据进行最大程度的控制。有了IPFS，组织就可以：  

1. 使用本地服务器存储数据

2. 有效地利用本地桌面硬件进行额外存储

3. 连接组织中多个位置的存储可用性

就像我们最初用云计算的原因一样：本地存储很昂贵，而且难以扩容。那么我们该如何使用IPFS的云存储功能呢?  

![](../Images/76558588537d18b7baa5db626c3b3b0b.png)

本地和云端数据存储

上面的图展示了一个拥有一个本地数据存储的组织，同时还使用Cloud A供应商作为数据存储。由于IPFS的数据可移植性，组织能够轻松地将其本地数据复制到Cloud A提供商，从其基础架构中获益，同时保持对其数据的控制。此外，IPFS允许组织利用Cloud A的数据中心位置来：  

1. 根据需要将供应商的存储成本和自己的存储成本混合在一起

2. 通过物理上的距离来优化对客户的内容传递

3. 通过多样化降低服务中断的风险

更进一步说，如果Cloud A没有提供组织所需的必要性能或成本优势，那该怎么办呢?  

![](../Images/7abf5934a71d574b8d5b1f2b345bb586.png)

本地、Cloud B和Cloud C数据存储

同样，由于IPFS能够降低转换成本，并为拥有数据的组织提供对数据的控制，你还可以轻松地切换到另一个提供者。上图描述了一个使用内部架构的组织，Cloud B和Cloud C作为数据存储的提供者。这能够被用于真正的混合云设置中。和Cloud A样，组织能够轻松地将其内部数据复制到其他供应商，从以下方式中获得收益:  

1. 根据需要将不同供应商的存储成本与您自己的成本混合在一起  

2. 通过使用提供者的数据中心位置来优化对客户的内容，使其在物理上更接近端点

3. 通过跨供应商的多样化来降低服务中断的风险

到目前为止，所有的示例是建立在本地数据存储的假设上。对许多人来说，这是一个牵强的假设。那么，如果我们像许多组织一样只在云端中运行，那么IPFS的优势是什么呢?

![](../Images/787342b79340240223301d1995cd8e03.png)

Cloud A, Cloud B, and Cloud C数据存储

这看起来完全一样，但是，你将通过云端提供商控制数据，而不是从本地位置控制数据。现在，从技术上讲，这确实减少了一些控制，因为只依赖于提供者会带来依赖风险。但是，你仍然能够通过在提供者之间进行分配来控制对于单一供应商的依赖所带来的风险。在上图中，我们看到IPFS被用于全云端架构中，以促进多个云端或混合云端设置，其中多个提供者为组织存储和移动数据。利用这个IPFS设置，组织将能够轻松地利用多个云端的各种优势，同时维护数据的可移植性。  

为什么组织会采用IPFS？  

简而言之,IPFS为组织提供的灵活性是对孤岛式的云存储的一个绝佳的范例转换。由于交换成本低、跨存储提供商的互操作性以及混合和匹配云端存储提供商特性的功能，组织将会采用IPFS。这种灵活性将创造更高的效率和商业模式，这在以前是不可能的，因为当前的云存储成本过高。正因为如此，我们迫不及待地想看看IPFS将带我们走向何方。
