新的缓存侧信道攻击可以对目标在线用户进行去匿名化处理

来自新泽西理工学院（NJIT）的一组学者警告说，一种新技术可以用来击败匿名保护并识别独特的网站访问者。


“对网站拥有完全或部分控制权的攻击者可以了解特定目标（即独特的个人）是否正在浏览该网站，”研究人员说。“攻击者仅通过公共标识符（例如电子邮件地址或Twitter句柄）知道此目标。


基于缓存的针对性去匿名化攻击 是一种跨站点泄漏 ，涉及攻击者利用Google云端硬盘，Dropbox或YouTube等服务与目标私下共享资源（例如图像，视频或YouTube播放列表），然后将共享资源嵌入攻击网站。


这可以通过以下方法实现：例如，使用受害者的电子邮件地址或与服务关联的适当用户名与目标私下共享资源，然后使用<iframe> HTML 标记插入泄漏资源。


在下一步中，攻击者诱使受害者访问恶意网站并单击上述内容，导致共享资源作为弹出式窗口（而不是弹出窗口）或浏览器选项卡加载 - 广告商用来偷偷加载广告的方法。


此漏洞利用页面由目标的浏览器呈现，用于确定访问者是否可以访问共享资源，成功访问表明访问者确实是预期目标。


简而言之，该攻击旨在通过一段共享内容将与这些个人绑定的帐户列表与其社交媒体帐户或电子邮件地址联系起来，从而揭开攻击者控制下网站的用户的面目。


在假设的场景中，不良行为者可能会使用目标的电子邮件地址共享Google云端硬盘上托管的视频，并通过将此视频插入诱饵网站来跟进。因此，当访问者登陆门户网站时，成功加载视频可以用作判断受害者是否是其中之一的标准。


这些攻击在具有多个CPU微架构和不同Web浏览器的桌面和移动系统中是切实可行的，通过基于缓存的侧信道来实现，该侧信道 用于收集共享资源是否已加载，从而区分目标和非目标用户。


换句话说，这个想法是观察当两组用户访问共享资源时出现的细微计时差异，这反过来又是由于根据用户的授权状态从Web服务器返回适当响应所需的时间的差异而发生的。


这些攻击还考虑了客户端的第二组差异，当 Web 浏览器根据收到的响应呈现相关内容或错误页面时，会发生这种差异。


“在目标和非目标用户之间观察到的侧信道泄漏差异有两个主要原因 - 服务器端时序差异和客户端渲染差异，”研究人员说。


虽然大多数流行的平台，如谷歌，Facebook，Instagram，LinkedIn，Twitter和TikTok的平台都容易受到影响，但一个不受攻击的值得注意的服务是Apple iCloud。


值得指出的是，去匿名化方法基于目标用户已经登录到服务的先决条件。作为缓解措施，研究人员发布了一个名为Leakuidator+的浏览器扩展程序，可用于Chrome ，Firefox 和Tor浏览器。


为了应对计时和呈现侧信道，建议网站所有者将 Web 服务器设计为以恒定时间返回其响应，而不管用户是否被设置为访问共享资源，并使其错误页面尽可能类似于内容页面，以最大程度地减少攻击者可观察到的差异。


“举个例子，如果授权用户要展示一个视频，那么非目标用户的错误页面也应该被制作成一个视频，”研究人员说，添加网站也应该要求用户在渲染内容之前进行交互。


“了解当前正在访问网站的人的准确身份可以成为该网站运营商可以执行的一系列恶意目标活动的起点。


几周前，德国汉堡大学的研究人员证明 ，移动设备通过Wi-Fi探测请求泄漏了密码和过去的度假地点等识别信息。


在一项相关发展中，麻省理工学院的研究人员上个月揭示了网站指纹识别攻击 背后的根本原因，这不是由于缓存争用（也称为基于缓存的侧信道）生成的信号，而是由于系统中断 ，同时表明基于中断的侧信道可用于发起 强大的网站指纹识别攻击。
