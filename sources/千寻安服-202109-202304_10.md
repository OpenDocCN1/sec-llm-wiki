前段时间部门大哥分享了 CS RCE 的利用过程，分享了自己在调试过程中踩的坑，收获颇丰，自己下来也复现成功了。也知道了该漏洞是哥斯拉的作者北辰师傅发现的，而且哥斯拉也存在同样的漏洞，心想如果哥斯拉也能 RCE，感觉应该要比 CS 好利用一些，当时就去找了找哥斯拉的利用链，结果太菜没找到。虽然没找到，但过程还是值得分享给大家的，抛砖引玉。

![](../Images/0bcf57712eeb84dc3ca595281f2eae7d.png)**CS RCE**

这里简单回顾一下 CS RCE 的原理和利用过程。

首先就是 java swing 库支持 html 标签，但只支持部分：

![](../Images/6b80b7f0969ce60fb73db0383d95717e.png)

每个标签对应自己的 View，像 img 标签对应 ImageView，而不支持的标签，如 applet 则对应HiddenTagView：

![](../Images/3efb79b413cd9141bebc82a140826cf8.png)

*![](../Images/2aa8239592c6fe074a7075454b836f35.png)*

 使用 swing 相关方法生成的 ui 界面是可以解析这些 html 标签的：

![](../Images/a5107b96223b5bca6eb2bb1c2c06ff9b.png)

swing 支持的标签中有一个特殊的存在，*<object>*： ![](../Images/dba277dcf9a5e9612e8b85f36f397ac4.png)

查看其对应的 ObjectView，通过注释可以知道，利用 object 标签可以去调用满足一定条件的方法，但必须满足四个条件：

classid 传入需要实例化的类，类必须继承于 Component；

必须有无参构造方法；

必须存在一个 setXXX 方法的XXX属性；

setXXX 方法的传参数必须是接受一个 string 类型的参数。

![](../Images/dba277dcf9a5e9612e8b85f36f397ac4.png)

如果相关方法存在漏洞，是可以通过 object 标签触发的，其他师傅已经找到：

org.apache.batik.swing.JSVGCanvas --> setURI

对应的 payload 应该就是：

<html><object classid='org.apache.batik.swing.JSVGCanvas'><param name='URI' value='xxxx'>

![](../Images/f22274083093f1ef8fa1424e4d1673da.png)

攻击的是服务端，但受害的是客户端，这里本地试了下 payload，是可以执行命令的：

![](../Images/89b1392da8c6173c6b945ab20ee6a054.png)

web 请求记录可以发现，先请求了 svg 文件，之后再请求恶意的 jar 文件，svg文件内容如下：

![](../Images/782ffbc6641d6989f65c748d7fd72e09.png)

CS 的首页有三个位置可以通过伪造上线包来控制：

![](../Images/12d3f4e4f7e704f7fc5b073bf08625a8.png)

伪造 CS 上线需要用到两个工具：

• https://github.com/Sentinel-One/CobaltStrikeParser（获取cs公钥、c2等信息）

• https://github.com/LiAoRJ/CS\_fakesubmit（发送cs上线包）

CS 生成的 exe 有两种，artifact 和 beacon，如果说 beacon 是一个完整的马，那么 artifact 就是一个小马，点了之后会进行一个拉大马的操作，会去请求一个四位随机字符的 URI：

![](../Images/f6ee422d94971fb46578fcc7751d6307.png)

*![](../Images/984f84a606c32dd51f223bb4212e481a.png)*

访问该 URI，下载之后，使用上面的工具即可获取到 CS 的公钥和 C2的信息：

![](../Images/35c2f2857cdd478b78f3c39dc264991f.png)

使用上面的工具，修改公钥和用户名内容，即可伪造 CS 上线：

![](../Images/b517ccc11d559fe2945e27d1bac36755.png)

![](../Images/5c6e8a333739c5083c93fb8aec410c8d.png)

但是首页这里可控的位置长度是有限制的，payload是远远超出了限制：

![](../Images/e12871790234c63434053f647efa3047.png)

缩短 payload 的话只能尝试使用 frame 标签去加载远程的页面，但由于父组件类型的问题会报错：

![](../Images/f460efe8aff77e41ec7d9b7fd7a75189.png)

所以只能更换触发方式，通过 hook win api，攻击者浏览进程列表时返回进程名替换为payload，可以直接使用下面的脚本修改：

• https://github.com/TomAPU/poc\_and\_exp/blob/master/CVE-2022-39197/cobaltfire.py

使用该脚本运行 beacon，CS 可看到上线：

![](../Images/fb7bb81a495aecda6418d0faa02bc5d6.png)

*![](../Images/e2822d691b39cebee621b7d29843bed8.png)*

只要浏览进程列表，就会触发 paylaod，可以看到进程名为空白，就被替换成了 payload：

![](../Images/d8635c040c62c22beef5a9917561b597.png)

最近我放在公网上的 CS 就被攻击了，下面是远程加载的 jar，该 jar 的作用主要是收集 CS 的配置信息，包括帐号、密码等等，然后 RSA 加密发送到攻击者的服务器：

![](../Images/aa301a1feb8b6b3c6418151aaa5790fe.png)

补丁如下，运行客户端时，加载该 jar 即可：

• https://github.com/burpheart/CVE-2022-39197-patch

筛选的部分结果如上，其中有一条让我一见钟情，setSvgResourcePath，是不是和 CS 的 setURI 很像，和 svg 相关，也是设置路径，一切都是那么的熟悉，那把路径设置成......，心里美滋滋的想着，当我跟进去看具体的代码时，才知道往往一见钟情的都是不会有结果的：

com.kitfox.svg.app.beans.SVGPanel --> setSvgResourcePath

就是单纯的通过 getResource 获取文件路径，还只能传入物理路径，所以直接寄：

![](../Images/1d25f6f18ad2604ab5e018e57f679711.png)

之后又找到了一条，感觉有角度：

org.fife.ui.rsyntaxtextarea.RSyntaxTextArea-->setTemplateDirectory

还是简单利用下 XSS 吧，家人们，在上面找的触发点位置尝试通过 img 标签加载远程图片，发现会报错，URL 的格式不对：

![](../Images/ee57eeb37caa1f2bcf281e19792e5b44.png)

因为这里会做类似过滤的操作，过滤 */*，从而在文件夹中显示目录，所以一个 URL 过滤了 */* 后格式就不对了：

![](../Images/d204bd10b02d55126a04b47505df2b79.png)![](../Images/d02667dd4324fa9aab7754ee1a214222.png)

![](../Images/d67f26de06d909aa59938361adbd7473.png)
