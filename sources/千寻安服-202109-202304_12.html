ssl漏洞
ssl漏洞常见于各大扫描器中。大部分客户并不关注这个漏洞，但仍有少数对安全管理要求较为严格的客户，会要求对这类漏洞进行修复。本文将对web中间件、windowsserver-3389中openssl的漏洞情况，进行复现和修复。
1.工具准备
sslscan。
下载地址：https://github.com/rbsec/sslscan
工具界面如图：Kali已集成该工具：旧版kal命令格式为：sslscan ip:port，如果目标为web，可写为sslscan https://ip:端口
2.web中间件
使用kali sslscan工具，扫描目标主机:图中的DES-CBC3、RC4、AECDH-AES-SHA算法，为扫描器报警常见的漏洞算法。
修改中间件配置，在加密算法的选项中，禁用相关算法。禁用方法为在算法前加!。
Nginx对nginx.cnf进行修改:Apache根据http.conf中的配置进行修改，如图所示指向httpd-ssl.conf修改httpd-ssl.conftomcat修改对应的server.xml文件，使其不包含弱加密算法：weblogic，修改对应的config.xml，在<ssl>标签下禁用算法：在禁用相关算法，重启中间件后，再次使用工具检测：3.windows server 2012
使用工具检测windows server 2012 R2的3389端口：1.修改注册表，禁用RC4算法：
进入
[HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\SecurityProviders\SCHANNEL\Ciphers\]目录添加或修改：RC4128/128、RC440/128、RC456/128项，添加Enabled，类型为DWORD，值全为0
重启后，RC4漏洞已修复：
如果存在3DES算法的漏洞，则在注册表[HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\SecurityProviders\SCHANNEL\Ciphers\]同样位置，添加：
Triple DES 168
Triple DES 168/168
Enabled，类型为DWORD，值全为0。
2. SSL/TLS 服务器瞬时 Diffie-Hellman 公共密钥过弱
访问HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\SecurityProviders\SCHANNEL\KeyExchangeAlgorithms\目录
新建KeyExchangeAlgorithms，将ServerMinKeyBitLength的值更改为00000800（十六进制）
新建PKCS，将ClientMinKeyBitLength的值更改为00000800（十六进制）
