前言

大家都说，目标资产信息搜集的广度，决定渗透过程的复杂程度。目标主机信息搜集的深度，决定后渗透权限的持续把控。

渗透的本质是信息搜集，而信息搜集整理为后续的情报跟进提供了强大的保证。

GitHub

本节主要介绍信息收集的GitHub敏感信息收集，通常很多开发会把自己负责的代码托管在Github上，Github虽然方便开发者，但其中也埋藏着一些安全隐患，往往会在不经意间泄漏各种敏感信息。

Google Hack

利用google命令语句，构造关键字。

例如：site:github.com smtp @lenovo.com 即可找到邮件配置信息泄漏。


如果想找其他敏感信息，如数据库之类的利用语句构造关键字就好了。

GitHub命令语法（这部分直接借取网上已有文章）

q+关键字

q对应的正是要搜索的关键字


https://github.com/search?utf8=✓&q=aliyuncs&type=；


in:file,path
https://github.com/search?o=desc&p=1&q=aliyuncs+in:file,path&ref=searchresults&s=indexed&type=Code&utf8=%E2%9C%93

观察一下可以看到，在关键字后边多了in:file,path。另外，这里面的参数s用来对搜索结果进行排序。S对应的有三个值:s=，默认是以最佳匹配的方式进行排序；o=asc&s=indexed，选择以最近更新的;o=desc&s=indexed选择最近被索引的。

repo:项目名
https://github.com/search?o=desc&p=1&q=aliyuncs in:file,path repo:XXXXX &ref=searchresults &s=indexed&type=Code&utf8=%E2%9C%93
repo：xxxx字符串。这个字符串是用来指定在哪个项目中搜索包含关键字的信息。


stars:条件

在有些情况下，我们需要对搜索结果进行筛选，使用星数搜索进行搜索是一个较好的方式。使用该语法，程序会展示星数大于要求的项目。这样带来的好处是可以快速找到好的项目。这里面的条件可以是简单的>或者..。1..10表示搜索项目星数介于1到10之间的。

高级搜索

高级搜索可以指定多个搜索选项，例如项目名，项目创建者，创建时间，星数等

其链接如下：https://github.com/search/advanced


GSIL(Github敏感信息泄露)

Gsil详细介绍：https://feei.cn/gsil/

Github地址：https://github.com/FeeiCN/GSIL

作为一款开源的github信息泄漏的实时监控，可以通过添加特有的特征来更快更好的找到泄漏的敏感信息。
配置好可以放在服务器上设置实时监控，定时定点发送监控报告。

总结

上面就是常规的github敏感信息泄漏收集方法，主要是通过关键字的搜索来查询敏感信息，通常关键字和特征比较完善的话，我们获取到的信息往往会出乎意料。

IP

本节主要介绍信息收集的IP信息收集。有些网站可能不是那么容易入侵。那么就可以通过从同一网段的ip进行入手，大多时候会有不错的收获。

C段扫描

C段在线查询：http://www.webscan.cc/

御剑

查询真实ip
通过ip段来收集更多的信息，首先要确保是查询的ip不是CDN
可以使用多地ping服务来检测是否接入了CDN

http://ping.chinaz.com

如果得到的地址是用一个，很可能没有接入CDN，如果是不同的ip可能就接入了CDN或者使用了负载均衡。

在线查询

如果cdn是接入的 CloudFlare，可以试试这个地址来获取真实ip: http://www.crimeflare.com/cfs.html
   如果用的是F5，可以获取他的内网ip:https://penturalabs.wordpress.com/2011/03/29/how-to-decode-big-ip-f5- persistence-cookie-values/

通过查询子域名来获取真实ip

CDN还是不便宜的，所以很多站长可能只会对主站或者流量大的子站点做了 CDN，而很多小站子站点又跟主站在同一台服务器或者同一个C段内，此时就可以通过查询子域名对应的IP 来辅助查找网站的真实IP

查询历史DNS记录

查看IP与域名绑定的历史记录，可能会存在使用CDN前的记录，相关查询网站有：


https://dnsdb.io/zh-cn/ DNS查询https://x.threatbook.cn/ 微步在线http://toolbar.netcraft.com/site_report?url= 在线域名信息查询http://viewdns.info/ DNS、IP等查询https://tools.ipip.net/cdn.php CDN查询IP


总结

对于信息收集中的ip收集，主要就是C段扫描没有其他多的东西，需要注意的就是获取到真实ip之后再进行扫描。

域名爆破

我们可以利用域名爆破工具以dns协议查询是否存在相应的A记录来获取子域名

工具：

1、FuzzDomain：https://github.com/Chora10/FuzzDomain

2、Layer子域名挖掘机：http://www.cnseay.com/

3、subdomainsbrute：http://www.lijiejie.com

字典

为了更全面地爆破子域名，除了工具的默认字典，我们往往需要自行配置字典。

  • 首先需要配置基础的字母随机组合:

crunch 1 4 "abcdefghijklmnopqrstuvwxyz"

考虑到字典大小影响到爆破的速度，一般构造1-4位即可

  • 然后采集所有英文单词

https://github.com/dwyl/english-words

46.6万个单词（扩展：添加所有动词的其他形式）

所有拼音（国内）

https://zhidao.baidu.com/question/39222979.html

  • 最后去重，然后相应的进行组合

比如单词+单词，拼音+拼音，拼音+拼音+拼音等等

社工

根据收集资产的特性来构造字典，比如企业名，企业常用子域名前缀后缀等。

综合以上2种方式，我们再爆破多级的子域名，剩下的就是时间问题了。

总结

上面就是常规子域名收集方法，利用搜索引擎和公开的平台可以收集到大量子域名，还有一部分需要通过持续的爆破才能发现，这就考验到字典的强度以及灵活性。越庞大的集团拥有更多的子域名，也有着越多的缺陷和漏洞，只要收集的子域名足够多，渗透测试的攻击面就越广。

端口收集

本节主要介绍信息收集的端口收集，通过探测开放的端扣以及端口对应的服务，对可利用端口进行爆破、攻击等。

常见端口服务映射

21 >> FTP

22 >> SSH

23 >> Telnet

110 >> POP3

445 >> SMB

1433 >> Sqlsever

1521 >>Oracle

3306 >> Mysql

3389 >>Mstsc

5432 >> PostgreSQL

5900 >>Vnc

6379 >>Redis

7001 >>Weblogic

8080 >>Tomcat/Jboss

8443 >>Openssl

9090 >>WebSphere

27017 >> MongoDB等

Nmap

最常用的端口扫描工具，可探测端口开放情况和检测一些常见漏洞

查看使用方法：nmap --help

缺点：速度慢

Masscan

一款基于无状态的急速扫描技术，无状态连接端口扫描工具

查看使用方法：./masscan --help

缺点：可能误报

总结

以上是两种最常用且比较好用的工具，探测出端口以及对应的服务后便可根据情况选择使用工具爆破或是直接浏览器访问，采取相对应的渗透手法进一步发起攻击。
//

历史漏洞

本节主要介绍信息搜集的历史漏洞查找，一方面是查找被白帽子提交的公开的漏洞，另一方面查找某框架的版本存在的历史问题，从而找到更多的敏感信息和突破口。

乌云镜像站

查询地址：https://shuimugan.com

直接搜索相应的厂商名称即可查询到白帽子以前提交过的漏洞，例：交通银行

 

其中可能有很多未打码的敏感信息，例如内网ip，员工的邮箱，用户的身份证号，后台地址等等。

SeeBug漏洞平台

查询地址：https://www.seebug.org

直接搜索相关的框架名称即可看到历史爆出的漏洞，例discuz 

其中大部分都有详情，如遇到没有的，可google/baidu进一步查找

Exploit-db平台

查询地址：https://www.exploit-db.com

同样的，直接搜索相关的框架名称即可看到历史爆出的漏洞，例：wordpress

搜索到的均已公开exp，可直接下载exp进行利用

CVE details平台

查询地址：https://www.cvedetails.com

直接搜索CVE编号即可查看漏洞的细节，例：CVE-2019-0708

总结

上面就是常规的历史漏洞查找的方法，通过这些搜索能够发现更多的敏感信息和历史版本漏洞，从而进一步发现、利用、挖掘漏洞。
