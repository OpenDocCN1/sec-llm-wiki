前言

论坛里表哥之前审计过此cmsEcshop3.6版本后台任意目录删除可导致格盘(漏洞分析与修复)

本着前人栽树，后人乘凉的原则，再次看看是否还有漏洞（捡漏），话不多说，直接看图。

官方直接注册好后下载最新版本3.6.0，这里我选择了UTF8版本。

下载完后，解压商城的目录文件如下图：

接着进行安装，这里不在过多描述。

依据之前表哥的思路，这里直接定位到功能删除点，template.php文件。


if ($_REQUEST['act'] == 'delete') {

    admin_priv('delete');

    $template = trim($_GET['tpl_name']);

    $curr_template = $_CFG['template'];

    $template = str_replace(['..', '/', '\/'], ['', '', ''], $template);

    $folder = ROOT_PATH . 'themes' . '/' . $template;

    if ($template != $curr_template &amp;&amp; file_exists($folder) &amp;&amp; delete_tree($folder)) {

        make_json_result('');

   } else {

        make_json_error('');

    }

}

 

我们看到，这里文件的825行已经对$template变量进行了过滤，将出现的..、/、\/ 替换为空。这么来看确实是可以对文件路径与文件名进行限制，启到防护作用。

然而经过黑盒的fuzz，实际上是可以绕过的。

先登录后台

接着下载模板到本地

安装本地模板

点击删除进行抓包


修改模板文件名

既然无法使用诸如 .. / \/ 等遍历的符号，经过fuzz，可以使用././进行绕过，达到恶意删除目的。当我们转发此数据包后，网站目录文件将被删除。
