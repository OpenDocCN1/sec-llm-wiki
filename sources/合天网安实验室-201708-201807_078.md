## **前言**

论坛里表哥之前审计过此cmsEcshop3.6版本后台任意目录删除可导致格盘(漏洞分析与修复)  

本着前人栽树，后人乘凉的原则，再次看看是否还有漏洞（捡漏），话不多说，直接看图。

官方直接注册好后下载最新版本3.6.0，这里我选择了UTF8版本。  

![](../Images/892a1a43d463a1ff7aaf1fb68823fedd.png)

下载完后，解压商城的目录文件如下图：  

![](../Images/9d946496caf62e1f0aaeb57ca252d1fc.png)

接着进行安装，这里不在过多描述。

依据之前表哥的思路，这里直接定位到功能删除点，template.php文件。  

![](../Images/cf24de2dd36bdfa76d888dbbc0884510.png)

|   
 || if ($\_REQUEST\['act'\] \== 'delete') {    admin\_priv('delete');    $template \= trim($\_GET\['tpl\_name'\]);    $curr\_template \= $\_CFG\['template'\];    $template \= str\_replace(\['..', '/', '\\/'\], \['', '', ''\], $template);    $folder \= ROOT\_PATH . 'themes' . '/' . $template;    if ($template != $curr\_template &amp;&amp; file\_exists($folder) &amp;&amp; delete\_tree($folder)) {        make\_json\_result('');   } else {        make\_json\_error('');    }}  |
| --- | --- |

我们看到，这里文件的825行已经对$template变量进行了过滤，将出现的..、/、\\/ 替换为空。这么来看确实是可以对文件路径与文件名进行限制，启到防护作用。  

然而经过黑盒的fuzz，实际上是可以绕过的。

先登录后台  

![](../Images/0fff4a11d7eac6bf0f4b116dc55b983c.png)

接着下载模板到本地  

![](../Images/ab2e9be69bdacdb6f63031dd999b5f74.png)

安装本地模板  

![](../Images/edd4648a92f05ca0b45477c2d067bf50.png)

点击删除进行抓包  

![](../Images/9a38d01afe361732b5e212fe0ca75371.png)

**![](../Images/e1684f747a2daf6538bc3af6aa987625.png)**

  

修改模板文件名  

![](../Images/1a2652278966641b527cb3ef394070ce.png)

既然无法使用诸如 .. / \\/ 等遍历的符号，经过fuzz，可以使用././进行绕过，达到恶意删除目的。当我们转发此数据包后，网站目录文件将被删除。
