**第十一关**：

 

http://127.0.0.1/xss/level11.php?keyword=good job!

  

![](../Images/ea63e4ad2adab6872ec9f17a7c1f42a1.png)

  

这里跟第十关一样，想必还是隐藏了form表单的input标签属性。

  

审查元素发现多了一个t\_ref参数，这个参数接收了上一关的url？直接看源码。

  

![](../Images/869bd2702fce40e19ce0e2e7bc9ba4e5.png)

  

源代码：

  

![](../Images/1df883ac1a1c5b6084c86306f60a9ca8.png)

  

<?php

ini\_set("display\_errors", 0);

$str = $\_GET\["keyword"\];

$str00 = $\_GET\["t\_sort"\];

$str11=$\_SERVER\['HTTP\_REFERER'\];

$str22=str\_replace(">","",$str11);

$str33=str\_replace("<","",$str22);

echo "<h2>没有找到和".htmlspecialchars($str)."相关的结果.</h2>".'<center>

<form id=search>

<input name="t\_link"  value="'.'" type="hidden">

<input name="t\_history"  value="'.'" type="hidden">

<input name="t\_sort"  value="'.htmlspecialchars($str00).'" type="hidden">

<input name="t\_ref"  value="'.$str33.'" type="hidden">

 

  

分析：

 

发现与上一关不同的是，多了一个

  

$str11=$\_SERVER\['HTTP\_REFERER'\]; 

  

此代码是获取前一页的URL地址，然后赋值给$str11

  

经过str\_replace()函数匹配掉<>，最后在t\_ref 的vlaue值输出

  

先用burpsutie抓包，发现了head 部分的 Referer 指向了前一关的过关url

  

![](../Images/ab82bcfe9a0cb10864d90d4607bdcfdf.png)

  

既然t\_ref参数的vlaue值是接受Referer的参数，可以直接修改Referer，最后参数再给到t\_ref

  

然后成功绕过

 

故payload：QIANAN " onclick="alert(1) " (上一关使用了鼠标移动事件，这关用onclick事件)

  

![](../Images/1315778d0b21519367818ff90a996408.png)

  

成功插入，修改input的属性为Text

  

![](../Images/54dfdd410753ec142239636bde418b44.png)

  

然后点击文本框，触发XSS

  

![](../Images/7670362b2d5cd3761aae8c06abb77c73.png)

  

**第十二关**：

 

http://127.0.0.1/xss/level12.php?keyword=good job!

 

  

![](../Images/216cb5519fb5402dde7ab118d2a815b5.png)

  

十二关跟第十一关相同套路

  

上一关使用了input标签接受Referer的参数赋给value。

  

而此关是获取客户端的user-agent信息然后赋值给input标签的t\_ua值，如下图：

  

![](../Images/775ab48619fcb5373ae47e8a158b247b.png)

  

源代码：

  

![](../Images/8b02ecaa1bf04e5b0cd98325f5637e9c.png)

  

<?php

ini\_set("display\_errors", 0);

$str = $\_GET\["keyword"\];

$str00 = $\_GET\["t\_sort"\];

$str11=$\_SERVER\['HTTP\_USER\_AGENT'\];

$str22=str\_replace(">","",$str11);

$str33=str\_replace("<","",$str22);

echo "<h2>没有找到和".htmlspecialchars($str)."相关的结果.</h2>".'<center>

<form id=search>

<input name="t\_link"  value="'.'" type="hidden">

<input name="t\_history"  value="'.'" type="hidden">

<input name="t\_sort"  value="'.htmlspecialchars($str00).'" type="hidden">

<input name="t\_ua"  value="'.$str33.'" type="hidden">

 

  

分析：

  

比上一关多了这一段代码：

  

$str11=$\_SERVER\['HTTP\_USER\_AGENT'\];

  

PHP中HTTP\_USER\_AGENT是用来获取用户的相关信息的，包括用户使用的浏览器，操作系统等信息，所以此关跟上关一样。

  

采用抓包工具 修改数据包绕过。

 

故payload：QIANAN " onclick="alert(1) "

  

![](../Images/9b4eed93066725cceaf13a54fa3d62a6.png)

  

插入成功，修改input的属性为Text

  

![](../Images/6b87390da8a9181224b3dbf5d7622fb2.png)

  

点击Text文本框，触发XSS

  

![](../Images/77e4ca42b98547c8b6837b0c85b3c708.png)

  

**第十三关：**

 

http://127.0.0.1/xss/level13.php?keyword=good job!

 

![](../Images/07c0a1cc973259473f01bf8258698a0d.png)

  

这关依然有隐藏的form表单，有个t\_cook参数有值

  

![](../Images/c7e35a76b9bf8ddfca13c80596c7e3dd.png)

  

源代码：

  

![](../Images/28317e58f4995280cfc890771ded0cba.png)

  

<?php

setcookie("user", "call me maybe?", time()+3600);

ini\_set("display\_errors", 0);

$str = $\_GET\["keyword"\];

$str00 = $\_GET\["t\_sort"\];

$str11=$\_COOKIE\["user"\];

$str22=str\_replace(">","",$str11);

$str33=str\_replace("<","",$str22);

echo "<h2>没有找到和".htmlspecialchars($str)."相关的结果.</h2>".'<center>

<form id=search>

<input name="t\_link"  value="'.'" type="hidden">

<input name="t\_history"  value="'.'" type="hidden">

<input name="t\_sort"  value="'.htmlspecialchars($str00).'" type="hidden">

<input name="t\_cook"  value="'.$str33.'" type="hidden">

 

  

分析：

  

多了两段代码

  

setcookie("user", "call me maybe?", time()+3600);

$str11=$\_COOKIE\["user"\];

 

Setcookie()函数创建一个名为”user”的cookie，然后把” call me maybe?” 赋值给user。

  

$str11接受cookie的值，然后又是一个str\_replace()函数匹配去掉<>符号。

  

然后在t\_cook的value值输出$str33的值。

  

因此，只要在抓包工具里修改cookie值字段的user就能达成绕过。

 

故payload：QIANAN " onclick="alert(1) "

  

![](../Images/0ff220758188c8f254f010f608e09778.png)

  

插入成功

  

![](../Images/49f2ef7dff38931625978b5ad0bedfa8.png)

  

修改input的属性为Text，点击文本框触发XSS

  

![](../Images/ef658b8a446bbb9ab746ac579c472364.png)

**第十五关：**

 

通过十四关的源码得到十五关的url：

 

http://127.0.0.1/xss/level15.php?src=1.gif

  

![](../Images/5efc97d862514f6715ca40ce5b403221.png)

  

右击查看了源代码。

  

![](../Images/41ceef93485a6fdf38da587bddce763c.png)

  

分析：

  

发现了 这段代码：

  

<span class="ng-include:1.gif"></span>

  

span便签里面引用了AngularJS ng-include 指令。

  

ng-include 指令用于包含外部的 HTML 文件。

  

这段代码是引用了1.gif，我回去看了xss小游戏的所有文件里面并没有发现这个1.gif文件，恰恰是一个提示

  

ng-include默认情况下包含的文件是要在同一个域名下，所以可以直接引用其他关卡的文件来触发XSS。

  

这里直接引用没有的1.gif

 

故payload：'level1.php?name=<img src=1.gif onerror=alert(1)>'

 

好吧，结果发现并没有什么卵用，并没有执行，好了装逼失败

  

百思不得其解，然后回到源代码看看

  

上面有段js代码引用了一个js文件，发现是一个google的一个站点，我没有挂vpn，所以打不开

  

![](../Images/2ceb7081ec94a37f3978cdcb07df9a36.png)

  

挂上了一个国外的一个vpn，再次访问：

 

127.0.0.1/xss/level15.php?src='level1.php?name=<img src=1.gif onerror=alert(1)>'

 

触发XSS 成功~
