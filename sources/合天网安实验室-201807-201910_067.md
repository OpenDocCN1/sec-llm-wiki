# **前言**

  

上次记录过一篇提权到内网初探，但感觉收尾有些仓促，最近刚好遇到了很好的实战过程，故本篇为过程记录复现，着重围绕着目标进行测试。希望看完本篇能给您带来一些思路或启发。

假设本次测试前提为：仅知道刘书源为某学校的学生，目的是尽可能的收集刘书源的信息，以此进行展开。

 PS：截至投稿前，已将漏洞提交eduSRC平台并验证已完成修复。

# **内网资产嗅探**

  

首先通过谷歌语法搜索该学校的学号。这是个众人皆知的小技巧，通过收集的学号，可以生成学号字典去爆破弱口令用户。如下获得了该校的学号格式。

![](../Images/e6ef4da4d19675e7ea84cb867fb8d9cb.png)

  

 通过以下公告通知，获取到默认的密码为身份证号的某段构成，故此处获得了学号之后，可以考虑如何获取学号对应的身份证号码。

  

![](../Images/0ca96f9567b153b6004c2305b7a31758.png)

  

![](../Images/72ca6e0ed99d7c246b1e431954948e1e.png)

**弱口令爆破**

  

通过上述获取到的学号生成字典，找到一处无验证码的学生系统进行爆破。

![](../Images/cb754a88e70928b8a650803d405c13a2.png)

  

![](../Images/53b5b22f5f1bc3480a3c1e3f0b929916.png)

  

![](../Images/4357b71e376b71549293451d2b91dfed.png)

  

如上成功爆破出尾数50的学号存在弱口令，通过弱口令可以登录该系统，登录后可以获取到该学生的身份证号码。此时，我们掌握了一个学号、姓名及身份证号，如果时间足够可以多去爆破几个。

但此时并不知道刘书源的学号，若能得到刘书源的学号应能获取更多的信息。

 通过对该学校网站继续浏览，发现网站存在VPN系统，此处为突破口。

  

![](../Images/277ceda83261edda6a080f9c656dfcc8.png)

**内网资产嗅探**

  

通过上述获取到的学号+身份证后6位成功登录VPN系统，若登录不成功，则可以多爆破几个学号，尝试通过他们的身份证号进行登录，总有学生没有改默认密码的。

![](../Images/fb21fdecf7bc87532d0bb36ba1e3b8f8.png)

  

![](../Images/92736fc30a411065dea0f3ebe2b92b76.png)

  

如上成功登录VPN系统，进入学校内网。通过对内网的资产进行了大概的浏览及信息收集，发现存在以下IP段：

192.168.25x.0

192.168.4.0

192.168.5.0

  

扫描该网段开放WEB服务的服务器，同时后台扫描SQLServer及MySQL的弱口令。如下，内网还是存在很多的网站服务器。

![](../Images/d8dc843e7cbdf8eb109c2a90b37aae45.png)

  

通过对几个网段的Web系统的逐个浏览测试，发现主要存在以下漏洞：

  

**1****、在线考试管理系统存在****SQL****注入**

  

此系统最有可能存在刘书源的学号信息，故对此系统进行检测。

![](../Images/c622177f78e9cca3b49a6bfd8f112fba.png)

抓包使用Sqlmap进行测试，一片红证明存在安全防护软件。

![](../Images/72c935cddaed2c7b81a432dd43937b69.png)

  

![](../Images/b2002455784e477c22038c210e5c38f9.png)

  

![](../Images/7b71298485ad9d4594fa0d1f4e45aa1f.png)

  

**2****、资产管理系统存在****SQL****注入**

  

用户名处加单引号报错

![](../Images/2742924a0179f923e77b24a9190502a5.png)

  

![](../Images/06ef8448aa41639c97ccb37ad21c0c1b.png)

  

抓包使用Sqlmap进行测试

![](../Images/bd40f0058e77c8655712ee1d3c927828.png)

  

![](../Images/17c14efcea80e4c583389e688a86ffbe.png)

  

同样抓包使用Sqlmap进行测试，但此处未被拦截。

分析后发现该站点和上面站点不是一个网段，考试管理系统的是192.168.25x.0网段，而当前系统是192.168.4.0网段，可能是WAF的部署位置缺陷导致未防护到192.168.4.0网段。推测其大概网络拓扑图如下：

![](../Images/397f3362acfd0716b93f87ef0cf46af0.png)

虽然当前注入点为SA权限，但不支持os-shell，也未找到后台管理页面，且该系统很大可能不存在我们需要的信息。此处暂且先放一边。

  

**3****、后台弱口令**

  

发现一系统后台弱口令，成功登录后，并未有可以利用的功能点，且该站点有WAF进行防护。

![](../Images/6f14948d8781509fa96f3c654bdacf74.png)

  

此时服务扫描那一块已经扫描完成，扫到存在sa弱口令的服务。

  

**4****、****SA****弱口令**

  

如下，发现两台存在弱口令的服务器，且为192.168.25x.0网段。可以通过获取该服务器权限建立代理，然后去跑同网段考试系统的注入点，即可绕过WAF的防护，进而可获取数据库的信息。

![](../Images/d160c4cfd0615ea74fb46162ee1b4ce8.png)

  

通过SQL工具连接后可以执行cmd，且当前权限为system权限。

![](../Images/a520f2a45ac6c9e46bdfa32d3cf46f81.png)

  

通过以下命令查找RDP服务的端口号

tasklist/svc | find "TermService"

netstat-nao | find "3220"

发现当前RDP服务的端口号为8080

![](../Images/e2a32b596c76ab8d86cef751dd177e69.png)

  

![](../Images/63d52c8ddc63b2c5e9eb6cd34dd1eca3.png)

  

![](../Images/1afa957080d9f084143d5acc2ccece71.png)

  

直接远程内网IP:8080，提示访问拒绝，表示VPN并未对外开放8080端口的访问。本想通过reGeorg脚本建立代理，但是80端口访问为报错，测试默认网站路径写入文件也404。测试本服务器为纯内网环境，不可访问互联网。

  

![](../Images/a6c301aa12d00d42effa5626ec9fdb35.png)

**端口复用及Socks代理**

  

通过对当前环境的分析，目前已经获取了25x的服务器的system权限cmd，想通过这台服务器建立代理，及登录服务器，在服务器上进行同网段的扫描探测，以此来绕过安全设备的防护。

  

**1****、端口复用**

  

但当前是通过VPN连接到内网，且VPN仅对外开放了某些特定端口。此时我首先想到的是利用端口复用，正好当前的80端口的网站为报错页面，于是上传了利用工具。

![](../Images/c2e29fa6ec9b1c99e14e2e0e29782e44.png)

  

在目标服务器上执行以下两条命令，此时相当于把本地的8080端口映射到80端口上。

c:\\wmpub\\drivers.exe

c:\\wmpub\\Changeport.exelocalhost 8080

  

执行上述两条命令后，在本地nc目标IP80

发送chkroot2007

即开启端口复用，80端口的web服务会无法访问。

![](../Images/f886a0d8a6b02441ba060d4ab7066134.png)

  

此时远程目标IP:80端口，即可访问服务器RDP

![](../Images/1acc9c7b1d51620469ddf39f9783f466.png)

  

![](../Images/6de40bde240e1e6c46f9bf523b77574e.png)

  

![](../Images/12574fb8a1b4ce7fdecb999dc6bea88f.png)

  

如上，成功登录该服务器，通过该服务器即可当跳板登录内网更多的服务器，且可以对内网进行扫描。

![](../Images/f5339750bc906a9df5f404e957e3a652.png)

  

但在测试过程中发现端口复用并不稳定，不时就会断开，有可能是安全设备防护的原因。于是对目标IP进行了全端口扫描，看看开放了哪些端口，扫描后发现被封了访问20多分钟。待解封后对端口逐个访问测试，发现存在9527存在web服务。

![](../Images/2b3c4de818e6337d05684a56bfd7e280.png)

  

![](../Images/b60d9bb24d3b2f84548904f0a0402452.png)

  

此时需要找网站的物理路径写shell，以下两种方式即可：

dirf:\\2013103011494215.jpg /s

typeC:\\WINDOWS\\system32\\inetsrv\\MetaBase.xml | findstr "Path"

![](../Images/abe6aa4a9fbcbb6be937600ce14c8190.png)

  

找到路径后写入菜刀一句话shell

![](../Images/3b39b531ca7eb4cfaf7ec003b5d35ec2.png)

  

如上连接被重置证明存在安全设备，直接上传reGeorg代理脚本访问也是连接被重置。此处用到神器冰蝎，上传后成功连接。

  

![](../Images/1272dcfe6eba9936f099c7ae9bb4ebb2.png)

  

![](../Images/580854d8acd10cb1664b4c001c5699d2.png)

  

**2****、开始****Socks****代理**

  

开启Socks代理，sqlmap挂上代理进行考试系统注入测试![](../Images/b85c1781c443c617abcaee25a1ac9145.png)

  

sqlmap.py--proxy=socks5://192.168.0.110:10086![](../Images/af7ad1cd0fcbc5f96d43df9e47f79c5b.png)

如上没有报一片红，当前注入点权限为root，绕过了安全设备的防护

![](../Images/34e0bc72906ceb86c45cae20024195bc.png)

  

![](../Images/6e9ea7ff237d256805578b028792d08a.png)

# **学生信息获取**

  

通过对数据库的浏览，发现存在member表，且数量为近5w，可以估计此约为全校学生信息，包含学号，姓名，身份证号等。

![](../Images/bfc6ca5f7e37563ca04cd91af64b1d2f.png)

  

通过以下SQL语句即可获取刘书源的信息:

selectusername,name,idcard from user\_data where name='刘书源';

![](../Images/78c4240d9908ed7c6061812872011caf.png)

  

如上，即可获取刘书源的学号及身份证号码，通过身份证号码后六位即可登录大部分系统。

![](../Images/d44f0ee16545acdae5f2f8c764ab69e2.png)

  

![](../Images/477bf3d7fe9b26bc9ab634b29bf21ad1.png)

  

如上达成此次测试的目的，成功获取刘书源的相关信息。

  

![](../Images/ef64c0ca2a033c45e45e4e5ef3fb9cd0.png)
