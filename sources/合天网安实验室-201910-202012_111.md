##### 浏览器访问主页初步发现

系统：`Windows server`中间件 `IIS7.5`语言：`ASPX`

##### 端口扫描

```
nmap -sV -T4 -p- 11x.xx.xxx.xx
```

![](../Images/51a50066b243b3c1b8405ffa6f107b77.png)

开放的端口真不少其中web服务的有几个：80(当前主页)、81、82、88、47001`81`：是这个棋牌站的后台`82`：也是个后台，不知道是什么系统的后台，有验证码`88`/`47001`：访问失败

`1433`：数据库 mssql

还开了 `139`、`445` 但是被过滤了，不知道是不是有防火墙，后面再看

**3**

**漏洞探测**

重点先放在前面找到的 81 端口，也就是网站的后台管理页面

![](../Images/660bef091eeec954b420d5b7240112ec.png)

没有验证码，用户名 / 密码随便写个 admin / admin，抓包

![](../Images/0127b67b2ccf8c8ca64b86b5ef8201c8.png)

用户名加了个引号发送请求直接返回报错了，不出意外应该会有报错注入或者盲注啥的

![](../Images/61e499c5c956584012b6c6fee905544e.png)

##### 兵分两路

一路把这个数据包保存到本地 qipai.txt，用 sqlmap 去扫，前面已经知道是 mssql 数据库，加上 --dbms 参数指定数据库类型节约时间


![](../Images/b0bc664dbeab822b821771625fecf539.png)

**4**

**提权/维权**

前面得知这个机器是 `windows server 2008`，尝试用土豆提权（MS16-075）

  

![](../Images/7f5d3dbe6ea073038a8805ba2979cd09.png)

执行后稍等了一会儿，比较幸运，这个机器没打补丁，一次就提权成功，拿到 system 权限，开始为所欲为😊

![](../Images/e0f038b82bff5dffa8dceecafc7e1fb9.png)

进入文件管理，能看到前面信息收集时的 test.html 文件

![](../Images/2e8f6ae1864426e6460edcdf7081b33e.png)

`netstat -ano` 看一下端口开放情况，3389 没有开

![](../Images/cdfc430ed308d86f3e63e3dfdd3a864d.png)

手动开启一下

![](../Images/ef32caf124f1b252d70ffb2d6de40984.png)

可以访问远程桌面了

![](../Images/9c3c290864cf3e4cd7bba1bcd32f2ab7.png)

cobaltstrike 操作我不是很熟练，还是用 metasploite 吧，通过 cs 上传一个 msf 生成的马，msf 开启监听

> 注：cs 可以直接派生 shell 给 msf，但是当时我尝试的老半天 msf 一直没有返回 session，所以才无奈先手动上传一个 msf 的马曲线救国

![](../Images/d91d5703ca545483dbdf73e42ee9cdd1.png)

msf 开启监听

![](../Images/682d87bc3228b29fa854ef930a76bd2d.png)

在 cs 上运行上传的马

![](../Images/a66b229cf6f94a8f799763f8413b7a03.png)

msf 成功拿到 shell，是继承的 system 权限

![](../Images/5e279e323f54bd0078bd50d94307cd63.png)

查看密码哈希，不能获取，因为msf的这个马是32位的，系统是64位的

![](../Images/f2d097cbaef514713faba70db63cdc13.png)

`ps` 查看进程，在进程中找一个以 system 权限运行的 64 位的程序，迁移进程后再获取哈希

![](../Images/95a5aaaa3b68cf5c4d4d4a2a8c5d4438.png)

到在线破解哈希的网站查一下 administrator 的密码，密码不算复杂，几秒钟就查到了

![](../Images/b423868ee3ecbe90820a0db021b6823c.png)
