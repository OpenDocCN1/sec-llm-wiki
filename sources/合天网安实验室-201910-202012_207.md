# 记一次实战给朋友站点测试

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MjM5MTYxNjQxOA==&mid=2652857440&idx=1&sn=c2bc8ed6d3c1f4fd672bb74d4e045751&chksm=bd5918ad8a2e91bbf7af5ddba01b6ee431f542ae56dea1c7389b256b81ffaacfe233fbda76d7&scene=126&sessionid=1681573671#rd](http://mp.weixin.qq.com/s?__biz=MjM5MTYxNjQxOA==&mid=2652857440&idx=1&sn=c2bc8ed6d3c1f4fd672bb74d4e045751&chksm=bd5918ad8a2e91bbf7af5ddba01b6ee431f542ae56dea1c7389b256b81ffaacfe233fbda76d7&scene=126&sessionid=1681573671#rd)

*   **一、前言**  
    

# 

本篇文章为给朋友网站测试的过程，主要记录测试中的思路。期间用了差不多两个周末，期间断断续续，整篇没啥奇淫技巧，大佬略过。  
PS：截至投稿前，已将漏洞详细报告提交朋友，并验证已经修复。

![](../Images/5f9804f27540994114e661365b91bcdc.png)

*   # **二、信息收集**
    

通过朋友给的域名进行子域名爆破，得到如下：

![](../Images/524e7d1eea977da8a5244a3012345cc3.png)

*   
*   
*   
*   
*   

```
查询成功：www.abc.cn-139.1.2.3查询成功：API.abc.cn-47.1.1.1查询成功：home.abc.cn-47.1.1.1查询成功：hd.abc.cn-139.1.2.3查询成功：oc.abc.cn-47.1.1.1
```

  

  

![](../Images/ee94cbfa77ff128a4146e3d34d7a947c.png)

其中www.abc.cn为官网，139开头的为阿里云服务器，通过手工测试并未发现漏洞，使用扫描器会被封IP。47开头的应该为本地服务器映射到公网的IP地址，测试重点为47开头的站点。  
访问api.abc.cn为API接口站点，如下

![](../Images/453306cbef53341c13bf91296c482656.png)

访问home.abc.cn则跳转到https://oc.abc.cn/login/login.html

![](../Images/51a2f8d4b5023c82d3b50cff39c9c970.png)

测试SQL注入，并不存在，存在验证码，暴力破解未尝试，扫目录也无有价值的信息。

![](../Images/df43e62fe83a882670c98616d9fe0210.png)

访问manager为Tomcat管理登录页面,访问app为登录界面

![](../Images/73a2d8c86ff6d3038a3f0e4a9cedc735.png)

通过对上面子站点的初步踩点，因为API站点接口较多，优先测试API接口，功能越多的地方越容易出错。

  

*   # **三、API接口测试**
    

发现API接口功能很多，顺手进行测试，大部分为401，未登录

![](../Images/c32a7573b52b6fd7248a7acea584fd7e.png)

![](../Images/708a629980d3b26532b5dca91437cd58.png)

  
接下来就是逐个进行测试，测了半天，终于发现一个未授权访问，可任意文件下载，此为突破口，如下

![](../Images/76fd01255bea0e6867d2b08561b02739.png)

  
测试下载passwd文件，构造访问以下地址https://api.abc.cn/downFile?filePath=/etc/passwd&fileName=

![](../Images/d84537f62cfcd3125b30c18cd4d4d248.png)

![](../Images/4aa04d68087bd7c1274721a17de7af59.png)

  

继续尝试获取敏感信息，下载bash\_history文件，可以查看历史命令https://API.abc.cn/downFile?filePath=/root/.bash\_history&fileName=

![](../Images/c25a4cdea1af57e98115dee04d65f8ea.png)

![](../Images/f969a2150f71c047973d186307a32931.png)

  
通过对历史命令的查看，获取到两个可能存在敏感信息的文件，如下：/etc/mail.rc/backup/mysql\_bask.sh继续利用任意文件下载上述两个文件

![](../Images/2f1d5ef0d47fe935220bf856da2a5962.png)

![](../Images/f540885e57993fbef2ec5a05ffe9dab6.png)

如上成功获取邮箱账号密码及数据库root账号密码，但公网并未开放数据库端口，无法连接数据库进行利用。接下来本地设置账号密码，即可登录邮箱。

![](../Images/6a2b34f52a25a2f6ed6abe7d0f17d93b.png)

通过对邮件进行搜索，发现以下信息

![](../Images/1366997617e53680f946840b1a783661.png)

用上述网站的账号密码，成功登录网站后台管理，但权限较低，测试了文件上传等，并未存在漏洞。

![](../Images/c663a24482db3c8f92e5ce14094765c6.png)

由于当时较晚，第一周测试到此结束，主要利用API接口的未授权任意文件下载，获得敏感信息，未获取到shell，但还是向朋友炫耀了成果。

![](../Images/f35f8f88684dd2f059a79de3a3b47784.png)

  

合天网安实验室的相关实验室推荐：任意文件下载漏洞的代码审计 

https://www.hetianlab.com/expc.do?ec=ECID06a1-2876-4bfb-8e59-a0096299c167

通过本节的学习，了解文件下载漏洞的原理，通过代码审计掌握文件下载漏洞产生的原因以及修复方法。

*   # **四、文件上传**
    

第二个周末，由于上周只找到一个任意文件下载，没拿到shell，感觉还可以再突破一下。于是让朋友不要修复先，我再尝试下，他回复限制了API页面的访问。

![](../Images/6a9965323aed895e92575f7e387a90fd.png)

于是再访问API站点，页面如下

![](../Images/4a0d45dd35508725c97ac6ded9fa4b06.png)

去访问任意文件下载的接口

![](../Images/f005ba7dbb61df3687cf920f01ebc59a.png)

发现仍旧可以访问，此处是没有填要下载的文件，所以报错，通过下载历史命令文件，查看朋友的配置修改，发现其配置了nginx配置文件

![](../Images/7976a409e797b157ade087f71e774cc9.png)

然后下载nginx配置文件

![](../Images/e5b9778b99393c7aaf954722743f2dea.png)

  
发现其修改的配置，允许18的ip访问该页面，禁止其他所有；只禁止访问首页，但仍旧可以访问接口地址，所以仍旧可以进行任意文件下载。于是对18的IP进行全端口扫描，发现其中一个端口访问则是API界面。

![](../Images/b8a6bfc3541f2ba4a9ff033abd217882.png)

![](../Images/87387c2b8cd7ac0e93454871de39aff2.png)

于是又可以去测试接口了，在一番测试后，发现一处任意文件上传接口，如下

![](../Images/e08d32cc51c6d1821b35097f8beea4cd.png)

![](../Images/86ab546d608f0fa0e594b8bc36d15cd3.png)

  

此处可以任意文件上传，但返回的地址是D盘下，Linux的服务器，怎么会返回D盘目录的地址，此处测试了很久，无法找到该文件路径。问了下朋友，他们是否有Windows的服务器，他回复都是Linux的。

![](../Images/e82131e694571dff9339684c157b4957.png)

*   # **五、SQL注入**
    

由于上述文件上传一直都找不到地址，便继续往下测试，因为他们的API接口功能很多，很多都是要登录才能访问的，很花费时间，但还是被我找到一个SQL注入。正常访问页面返回

![](../Images/1f6920cf13bceb96d4a917ad59659a06.png)

加个单引号，返回

![](../Images/3c3331da89688cd6ae1271a52bb26454.png)

使用Sqlmap进行测试

![](../Images/df17ad4949748113937a3ba6d844d70b.png)

想通过SQL注入获取用户密码，尝试登录上传拿Shell，看了一下密码应为自写加密，无法解密

![](../Images/c29f066f9231927b8ffbc3a0d8a585b0.png)

且Linux一般目录权限较严格，测试了下并未成功写Shell，到这里发现SQL注入好像并达不到我的Getshell目的。

*   # **六、文件上传getshell**
    

梳理一下当前的思路，有个任意文件下载、有任意文件上传（但找不到路径）、有SQL注入（无法获取密码），目的是获取网站的Shell。  
往往有些时候可以利用的点越多思路可能就会越乱，一方面想去找上传的路径，另一方面又想去SQL注入写Shell，也测试去下载Tomcat的用户配置文件，想登录Tomcat管理部署war，但下载了发现是默认配置。

![](../Images/e1b790b5fa073fbb4ebb570222dfa835.png)

还下载了一些配置文件进行分析

![](../Images/9217cf2144dd2d3d356df9d2a5cb9815.png)

但仍旧没找到突破口，于是只能继续分析API功能接口，发现一处指定文件夹上传，瞬间充满了希望

![](../Images/4f985bc954f0068966d75f1d1bb0e6a8.png)

  

![](../Images/f104b1715435be95a712b12dd0a5f3df.png)

返回地址很友好，访问

![](../Images/2a39723418bbc3042c75e3f8cdda6b2f.png)

使用工具进行连接，当前为root权限，服务器为内网IP，成功Getshell

![](../Images/891991eb0e203567819b5a31d858fffa.png)

然后看看目录，发现了D的路径，但之前的文件并未上传成功到该路径。

![](../Images/7bb7f2ca4a92f13bcc1f15eac09ad536.png)

  

*   # **七、总结**
    

本文从信息收集到任意文件下载、到文件上传、SQL注入，最后拿到一个站点的shell，并无太多亮点，主要还是细心和耐心，因为API的功能接口确实有点多，几乎都是每个大概去看了，总体来说，还是运气比较好。
