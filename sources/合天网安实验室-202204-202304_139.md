事情是这样的，国庆前期某地HVV，所以接到了客户通知他们收到了钓鱼邮件想要溯源

![](../Images/310879d47aa27b76ab481817e7d0a96f.png "null")

  

直接下载文件逆向分析一波。钓鱼邮件，图标什么的做的还是挺逼真的，还真的挺容易中招的，但是这里的bug也明显，丹尼斯没有客户端，百度一下能够辨别这是钓鱼的。

#### 逆向分析

查壳工具`DIE`看是否加壳

![](../Images/b56f202304ec0dd95f1992f9f018a60c.png "null")

  

当然其他查壳工具也可以exeinfope等，看到的东西不一样

![](../Images/c4524dd6de2fd78f63110d6662b6d8fa.png "null")

  

可以看到是64位的应用，无壳，IDA静态分析

![](../Images/da9010b72d76b79b57580512ed8af052.png "null")

  

直接进入主函数，直接F5逆向main函数c代码

![](../Images/2bb588789552a85769778f4a5a9fc01c.png "null")

  

主函数中使用的函数比较少

```





















int __cdecl main(int argc, const char **argv, const char **envp)
```

简单来看就是先查找资源，DATA应该为加密的`shellcode`，加载资源赋

给`Resource`,计算资源空间大小，`malloc`分配空间大小，`memset` 将申请的内存初始化为0，`memcpy`函数的功能是从源内存地址的起始位置开始拷贝若干个字节到目标内存地址中,跟进`sub_140001070`

![](../Images/f573cd2e863ad210bf6b7c427bc826c2.png "null")

  

可以看到反汇编之后在第52行创建进程，在56行分配虚拟内存，60行写入内存，61行创建线程，这里创建的线程即为恶意进程。这里使用动态调试x96dbg验证我们的分析另外，需要分析一下外联的地址以及注入的进程是什么，64位的应用使用x64dbg，依次下断点

简单计算一下地址，IDA的起始地址为`00000001400015C4`

![](../Images/07798dce4620c67e9ad2f55389823916.png "null")

  

`FindResourcew`地址为`00000001400015C4`

![](../Images/e89e20c5b459a68af1462ba36e29f22d.png "null")

  

在x64dbg中找到起始地址`00007FF638B915C4`

![](../Images/b288004b04d0f4acb7910c1fe795fe46.png "null")

  

根据偏移量跳转下断点

![](../Images/cdbc84f60686260347f9c24f8f560621.png "null")

  

![](../Images/2d0674d26d9b04d43737eab6245befac.png "null")

  

F7按步调试

![](../Images/25e6481452fe4869590b0662ee0d8bb5.png "null")

  

在`loadResource`函数中追踪内存

![](../Images/cb48e4d27ad9ed8e99230ff202dc392a.png "null")

  

这里加载的是`DATA`的内容，即为加密的`shellcode`,我们直接用`Resouce hacker`直接查看一下恶意进程`dennis.exe`的DATA内容

![](../Images/db498ccf98686987b768782067e6aab5.png "null")

  

说明我们的分析没有问题，继续向下调试

![](../Images/dc61ef6e8e07cdd6cc78beab0b84b85c.png "null")

  

因为这个应用比较小，所以代码量也不大，f5反编译之后可以直接找到函数下断点，这里不需要计算偏移量了，计算方法跟上面差不多。

![](../Images/429091dd58b8585096527e0b3789e6c1.png "null")

  

调试走到这里，可以发现走的是循环

![](../Images/137318a25ccdf2a10174642fd42ddccb.png "null")

  

可以明显的看到有`xor`异或指令，这里对shellcode即DATA的内容做异或，异或的对象为`byte ptr`指向的地址，内存数据为`key`,那么key的内容为

![](../Images/26a61dee2e78fafafdbc1876ff5b5797.png "null")

  

因为是按字节异或所以这里异或的内存应该为78，整个循环异或的key应该为`12345678`，shellcode加密的时候应该用的key为12345678加密的，所以这里解密使用key去解密，跳出循环RIP一下，到断点`CreateProcessW`

![](../Images/e7435741b0a9afd043d6f8eec85d978c.png "null")

  

可以清晰的看到注入的进程为`C:\\windwos\\system32\\svchost.exe`，向下调试

![](../Images/c902593477e855c25ee3e2c77b918a9c.png "null")

  

申请虚拟空间内存，然后向下为写入内存

![](../Images/3fd615cdf0556181cd9dfad41ae1869d.png "null")

  

解密完成后写入内存，所以在这里是可以看到外联的ip地址或者说是域名的，这里使用的是ip，查询之后发现是`TX云`的服务器。

![](../Images/bb126eb6e1460fa48946da58f24c2059.png "null")

  

在向下就是创建进程起服务`svchost.exe`了
