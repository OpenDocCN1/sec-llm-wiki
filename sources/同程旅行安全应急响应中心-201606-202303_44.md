**漏洞背景**

  

详情见360-CERT的[报告](https://www.anquanke.com/post/id/103122)这边不再叙述，只讲如何快速探测和应急处置。

  

E文好的同学可以看这篇

[https://embedi.com/blog/cisco-smart-install-remote-code-execution/](https://embedi.com/blog/cisco-smart-install-remote-code-execution/)

**探测**

搭建了[巡风](https://github.com/ysrc/xunfeng)的可以搜索 port:4786

  

![](../Images/54dbda4fc784cd2078ed5f784ee56a6f.png)

下载搜索结果，或者使用 nmap、masscan扫描4786端口。

![](../Images/af4058d36dc0997fe39ed589374d4949.png)

  

使用下面的脚本探测对应IP端口是否确实开放的是思科SMI协议

[https://github.com/Cisco-Talos/smi\_check/blob/master/smi\_check.py](https://github.com/Cisco-Talos/smi_check/blob/master/smi_check.py)

协议特征可以参见msf扒拉出来的

[https://github.com/rapid7/metasploit-framework/commit/c67e407c9c5cd28d555e1c2614776e05b628749d](https://github.com/rapid7/metasploit-framework/commit/c67e407c9c5cd28d555e1c2614776e05b628749d)

  

\# python smi\_check.py -i targetip

**应急处置**

#conf t

Enter configuration commands, one per line.  End with CNTL/Z.

NSJ-131-6-16-C2960\_7(config)#no vstack 

NSJ-131-6-16-C2960\_7(config)#exit

  

关键的就是这句 **no vstack** 

  

再看，端口已经关掉了。
