0x1 本周话题TOP3


话题1：金融机构数据安全法、个人信息保护法以及客户信息保护工作的安全负责人分别由什么角色担任？


针对该份问卷，在1天内共有73位群友参与填写，覆盖如下行业：



Q1：贵公司客户信息保护工作由哪个部门牵头？



Q2：数据安全法第二十七条明确要求重要数据处理者应当明确数据安全负责人和管理机构，此次的数据安全负责人由贵公司的哪个角色担任？



Q3：个人信息保护第五十二条，处理个人信息达到国家网信部门规定数量的，应当指定个人信息保护责任人，贵单位的个人信息保护负责人由哪个角色单位？



从调查结果看，一是客户信息保护工作由IT部门牵头占比最大，还有很多单位目前不明确；二是数据安全、个人信息保护负责人是首席信息官或分管IT的管理层领导居多，不然就是公司一把手。当然，群友们也对此展开了讨论：


A1：这个事情没有结果，谁牵头都行，关键就是支持力度，估计很多没明确，而且每个公司特点不同。


A2：数据安全与客户信息保护，这个题目太泛了，应该叫信息系统数据安全，数据安全都不是it能干的。同时，国内的个人信息保护，我倾向称呼为隐私保护，主要还是从客户那里要授权的问题：客户授权个人信息给 服务商使用，是一个法律问题。个人信息保护，容易被看到 信息保护，进而跟 信息安全关联到一起。


A3：这个调查也填写了，我相信大多数同仁都有这样的痛点，权责不对等。做好用户信息安全，承担数据安全第一责任人通常不是信息安全部门完全能控制或是主导的，但是往往在公司内部大部分人（包括高层）默认认知上会认为就是信安部门的责任，出了事情就是安全部门的事情。


A4：那可能主要解决权责不对等的问题，通过比如 信息委、信息安全领导小组的组织例会上，抛出议题，让高管们定出来谁是第一责任方。某厂为了应对 gdpr的一些要求，也是设置了一个岗位，叫做cpo，首席隐私保护官， 这个岗位是律师，是法律合规团队的。我们现在倾向于 把 隐私保护的职责定义到 法律合规部，因为都是合同、协议的落实。当然信息安全部本来的防泄漏职责是没有异议的。


话题2：2021中国网络安全产业分析报告解读


话题背景：2021中国网络安全产业分析报告解读

10月11日国家网络安全宣传周期间，网络安全产业联盟发布了《2021中国网络安全产业分析报告》。看了下，挺有意思。发出来和大家共赏，并尝试做一些解读，报告从法律法规、市场观察、热点方向、资本洞察、总结与展望五个部分展开。


A1：作者，也是群友，写了几个点，汇总：

1、网络安全产业，2020年可能因为疫情原因，首次超过小龙虾产业。

2、报告显示，安全产业的发展增速只有11.3%，这个数字，感觉没办法说服自己，网络安全是“朝阳行业”。

3、法律法规层面，2021年一年（十四五开局），干了过去五年的事情（十三五），还不止。

4、十三五是网络安全法律法规的关键时刻，十四五将是网络安全产业发展的关键时刻。

5、四川居然是网络安全客户第一大省，和重庆一对比，看来金融实践群跑去重庆办闭门会，有点跑偏了

6、热点方向top3是 数据安全、安全托管服务和API安全。

7、2021年安全公司融资数量和金额大概率不会超过2020年。


A2：网络安全，中小型企业还几乎为0。关键是汇报给上面的领导懂一点也行，领导基本上都是关心业务系统，不会把精力及资金用在这个看不成绩的上面。基础安全还是有的，但是进一步提升除了领导层的重视以外，还要依靠安全人员的从业能力和推动力度。不是安全出身的领导，对安全的认识还是有限，有些甲方单位的高层领导对信息技术理解还停留在修电脑层面，更不用说安全了。


A3：所以说不能花100w去保护10w的资产，关键就是是业务和安全的平衡，评估好当前的业务规模安全需要做到什么程度。对于领导层对安全的重视程度，我觉得从合规和满足法律法规要求的角度来看，各行各业都有活生生的例子，领导层基本的sense是有的，关键在于平衡好业务和安全，找到业务和安全的契合点，评估好风险，明确好优先级。


话题3：拟态防御技术讨论



A1：不知道自己理解的对不对，核心逻辑是：1. 所有的异构体要均能处理正常的业务逻辑；2. 由于攻击包在不同系统处理上存在差异，所以当存在差异时会根据表决算法来决定是否进行输出，而正常的请求在各个异构体上不会存在差异，所以可以正常输出；所以是不是可以理解成，对于系统差异化输出特征明显的攻击效果很好，如果是某一种攻击，在各个异构体上处理结果是一致的，拟态是否也无法区分，会表决成功，但这种普适性的攻击较少存在，所以风险可控。


A2：通过冗余部署提供相同功能的不同类别资源、不同算法组件等方式，实现系统相关组成部分的异构性和多元性。拟态系统会把用户的原始请求复制成多份，分发给多个异构体。每个异构体的实现各不相同，但都能处理用户请求，各异构体的处理结果经过表决得到最终结果。系统只有在表决通过时才认为是合法的输出结果，否则作为异常处置。这要求好高啊。


假设某个组件或者框架出了个rce，恰好某个异构执行体满足漏洞利用条件，使用不依赖响应结果的攻击方式，发一条反弹shell出来的攻击请求，这台主机就沦陷了，网络上没有做出网限制的话，这么搞确实增加了风险暴露面吧，本来不用这个组件就没漏洞，搞很多套异构体就用上了。所以理论上采用拟态这种方案是不是还有很多前置安全条件需要满足。除了业务逻辑类漏洞，再举个例子，比如ssrf盲打内网这类漏洞，这种防御应该也无效。


A3：拟态防御Web服务器的异构性主要通过两种方式获得:一种是利用软件、操作系统在实际应用中的多样性直接获得一定的异构性, 如服务器软件层由Apache, Nginx, IIS等现有软件构成可选集, 虚拟机操作系统和物理机操作系统由Redhat, Centos, Windows Server 2008等操作系统构成可选集.另一种是人为异构化, 对于sql查询语句、文件 (包括文件目录) 等不具备多样性的数据, 采用了关键字标签化、文件标签化、目录随机化等方法, 使执行体上的数据具备人为的异构性.基于多样性产生的异构性在一定程度上存在“同源”的问题, 相对而言, 人为异构化产生的异构性更强.人为异构化的方法多种多样, 根据不同的对象形式和特点, 通过较小的改变可以取得较大的异构性, 异构化方法相对私密, 破解难度较大, 因而, 人为异构化方法能够通过较小的代价实现较高的异构性, 从而增强拟态防御模型的内生安全。


这篇论文《拟态防御Web服务器设计与实现》写的比较清晰了。

http://www.jos.org.cn/html/2017/4/5192.htm



个人理解异构主要在系统基础软件中间件这一层来做，业务逻辑层如果也异构的话成本会非常高。如果业务逻辑层实现没有异构，那这种的防御对业务逻辑类漏洞应该无效。越复杂的系统架构，带来更高的运维管理成本，也会带来更多其他安全风险（配置等）。
