存在的漏洞：任意密码重置漏洞










利用点：

通过忘记密码，输入123，得到

ork.cn:7180/ptt/sched/JcResetPass_toSafeInfo.action?type=0&userAccount=123





打开源代码分析

存在漏洞的代码：



首先这段代码是变量parmas类型函数，声明了useraccount，sysOrgquestionld参数，实际上看到JcResetPass_checkSafeInfo.action

是用来校验post提交的地址

那么实际上，我们只需要看这里，初始化变量type，如果data的结果为空

var _processing = false;var type = "0";var submitType;
function change(type) {    if (type == 0) {        $('tr.changeJsp').show();        $('tr.orgQuestion').hide();        $('tr.orgName').hide();        $('tr.resetPass').hide();        $('tr.ver').hide();        submitType = 0;    } else if (type == 1) {        $('tr.changeJsp').hide();        $('tr.orgQuestion').show();        $('tr.orgName').hide();        $('tr.resetPass').hide();        $('tr.ver').show();        $('tr.orgQuestion#one').after($('tr.ver'));        refresh();        submitType = 1;    } else if (type == 2) {        $('tr.changeJsp').hide();        $('tr.orgQuestion').hide();        $('tr.orgName').show();        $('tr.resetPass').hide();        $('tr.ver').show();        $('tr.orgName#two').after($('tr.ver'));        refresh();        submitType = 2;    }


     

也就是说userAccount参数存在的时候，需要回答问题

那么由type参数分别控制验证问题的结果

我们只需要，在type默认是1的，我们看看正确实际上就是0

我们抓包的方法，然后修改





这里需要用到burp的response功能，修改返回值再提交

修改type的值：0

把type直接改成0

即可绕过重置





但是返回信息是回答错误

改成type还是错误，为什么呢，0不是已经成功了吗，为什么还是回答错误呢，接下来我们还是需要再回到代码段分析，

我们得回到result结果这里



注意这一段代码

这里做了一个判断,function函数装入data，result就是返回的结果，这里为空的情况下

refresh()做了一个加载，二次调用用到,弹出结果，否则执行resetpass的内容



这里相当于是function函数传入的data参数对象

Data就是装入的parmas类型参数，那么这里做了一个if else，最关键的就是success,这段代码明显是有问题的

他的意思是说，当我提交去验证parmas类型去验证答案的时候这里result结果为空，依然会执行success，，那么就很好解释了为什么填入type还是0，为什么还是错误，那么我们就利用代码的缺陷去绕过任意重置密码，即可

这时候我们需要注意的就是把type改成0，然后把result的结果改成null即可绕过，因为result如果出错，还是会回到1的状态，也就是这里



0的可控就是为null，然后使用post提交即可修改密码





通过修改密码即可绕过重置
