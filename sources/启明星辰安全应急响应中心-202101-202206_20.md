# VMware OpenSLP漏洞引发勒索事件通告

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzI1Mjg4NzAzMg==&mid=2247483685&idx=1&sn=d6f74d54a5890236386d28f50ebe4f7f&chksm=e9ddabb2deaa22a4cd80828379d35d52ed49c4e1fdf099fc5957006cc83120fa4e9adbf225ac&scene=126&sessionid=1681380727#rd](http://mp.weixin.qq.com/s?__biz=MzI1Mjg4NzAzMg==&mid=2247483685&idx=1&sn=d6f74d54a5890236386d28f50ebe4f7f&chksm=e9ddabb2deaa22a4cd80828379d35d52ed49c4e1fdf099fc5957006cc83120fa4e9adbf225ac&scene=126&sessionid=1681380727#rd)

### **0x00 事件概述**

2021年03月19日，有用户反馈称其VMWare ESXi上的虚拟机感染勒索病毒，该勒索病毒主要利用了VMware 2019年12月安全公告中披露的一个OpenSLP远程代码执行漏洞（CVE-2019-5544）进行攻击，启明星辰VSRC已于当月发布了该漏洞的预警。

今年2月，维他命简讯也发布了相关信息，据称是多个勒索软件团伙都在利用VMWare ESXi产品中的漏洞，攻击者使用了ESXi中影响服务定位协议（SLP）CVE-2019-5544和CVE-2020-3992漏洞。该攻击于去年10月首次发现，与RansomExx团伙有关，1月Babuk Locker也发起了类似的攻击活动。威胁情报公司KELA称，黑客去年还在暗网上出售过ESXi实例的访问权限。

目前该漏洞已在2020年发布了相关补丁，建议参考下表进行升级：

| ESXi || 6.7 || Any || ESXi670-201912001 || KB76372 |

| ESXi || 6 || Any || ESXi600-201912001 || KB76372 |

**临时措施**

（使用 SLP 通过端口 #427 查找CIM 服务器的 CIM 客户端将无法找到该服务。）

1.使用以下命令停止 ESXi 主机上的 SLP 服务：

/etc/init.d/slpd stop

注意：仅当 SLP 服务未在使用中的时候才能将其停止。使用以下命令可查看服务位置协议守护进程的运行状况：

esxcli system slp stats get

 

2.运行以下命令以禁用 SLP 服务：

esxcli network firewall ruleset set -rCIMSLP -e 0

要使此更改在重新引导后仍然有效，请执行以下操作：

chkconfigslpd off

检查重新引导后此更改是否仍然有效：

chkconfig --list | grep slpd

output: slpd off

 

要移除适用于 CVE-2019-5544 的临时措施，请执行以下步骤：

1.运行以下命令以启用 SLP 服务的规则集：

esxcli network firewall ruleset set -rCIMSLP -e 1

2.运行以下命令以更改 slpd 服务的当前启动信息：

chkconfig slpd on

运行以下命令以检查运行上述步骤（步骤 2）后更改是否有效：

chkconfig --list | grep slpd

output: slpd on

3.运行以下命令以启动 SLP 服务：

/etc/init.d/slpd start

4.禁用并启用 CIM 代理，请参见：

https://kb.vmware.com/s/article/1025757

 

VMware官方公告及下载链接：

https://www.vmware.com/security/advisories/VMSA-2019-0022.html
