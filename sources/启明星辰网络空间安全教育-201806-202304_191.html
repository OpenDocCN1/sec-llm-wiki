2021年12月9日，Apache Log4j2远程代码执行漏洞POC被国外友人公开，安全圈注定是个无眠之夜。从9日至今，漏洞细节相继被披露，各SRC也陆续发布公告暂停接收此相关漏洞，各dnslog平台也迎来了访问与被ban高峰期。由于此漏洞波及面极广，CVSS评分满分10分。目前启明星辰集团知白网络安全演练系统正式复现被安全圈自嘲可以喂饱两年的Apache Log4j2漏洞环境，基于此环境可以复现此漏洞与进行修复，让“错误”与“不可控”发生在靶场。


Apache Log4j2演练靶场介绍    

漏洞描述

Apache Log4j2是一个基于Java的日志记录工具，是Log4j的升级，是目前最优秀的Java日志框架之一。该日志框架被大量用于业务系统开发，用来记录日志信息。


日志在打印时当遇到 ${ 后，Interpolator 类以 : 号作为分割，将表达式内容分割成两部分，前面部分作为 prefix，后面部分作为 key。然后通过 prefix 去找对应的 lookup，通过对应的 lookup 实例调用 lookup 方法，最后将 key 作为参数带入执行。


关于lookup具体细节可参考：

https://www.docs4dev.com/docs/zh/log4j2/2.x/all/manual-lookups.html

Apache Log4j 2.x<=2.14.1

漏洞复现

启动环境，环境主要涉及实操靶机、Log4j2环境靶机、虚拟化IDS等。

通过实操靶机访问Log4j2环境靶机，利用工具&poc获取Log4j2环境靶机权限

虚拟化IDS检测

漏洞修复

1、添加jvm启动参数-Dlog4j2.formatMsgNoLookups=true；


2、在应用classpath下添加log4j2.component.properties配置文件，文件内容为log4j2.formatMsgNoLookups=true；


3、系统环境变量中将LOG4J_FORMAT_MSG_NO_LOOKUPS设置为true；


PS：目前厂商已发布升级补丁以修复漏洞，详情请关注厂商主页：https://github.com/apache/logging-log4j2/releases/tag/log4j-2.15.0-rc2
