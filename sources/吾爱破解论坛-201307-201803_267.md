# 【Android 原创】360加固保v1.8.0 动态脱壳

**0x1 对比**

  

![](../Images/84bdb05062e91d93fb80bd4157a0e190.png)

上传demo进行加固，解包后对比下原包和加固包，发现加固包在assets文件夹下多了libjiagu.so，libjiagu\_x86，lib文件夹下多了libjiagu\_art.so，同时修改了dex文件和AndroidManifest文件

  

![](../Images/e042b927e255efa806ab3618a8edd79c.png)

打开manifest文件，看到360加固对Application标签做了修改，添加了壳入口，也就是我们反编译后看到的StubApplication.smali这个文件。

  

相比于之前版本的加固，自1.7.0.3加固版本之后，多了几次反调试，使得动态难度稍微增大了一些，不过针对脱壳机脱壳，再多了反调试也是无用。或者通过修改系统源码，也能达到消除反调试的作用。

  

**0x2 动态调试**

（1）把app安装到手机，以调试模式打开app

（2）以shell模式root权限打开IDA的android\_server监听

（3）tcp转发

（4）打开IDA，修改配置为在进程开始时下断

  

![](../Images/879401533cf534553a0e5f92bc36f830.png)

  

（5）搜索到进程后jdwp转发，pid值即为我们进程号，并在命令行下附加。

  

![](../Images/23409e1ce21d9185c234edf172774f72.png)

成功附加后，可以下段了，打开Debugger Option

  

![](../Images/b65282cb0b20cbc9d45eab0aa1ce824a.png)

  

我们选择在线程开始和库加载时下断，修改成功后，jdb附加，点击运行

![](../Images/1691b58d8406c92e87232ef532e0ef1f.png)

  

程序会断在elf头处，按下G键，搜索mmap，在mmap函数的段首和断尾下段

![](../Images/95046713879252a7a089f0254ccba07b.png)

  

F9运行，来到断尾时F8单步，

![](../Images/3baae4a8f48f09f166188b3462fc7a97.png)

  

来到此处时，在 BLunk\_5C999C2C下断，F9一下，F7跟进去

![](../Images/148aa6b7d3ffb9934061aa03853cf1e5.png)

  

跟进去今后在BLX LR处进行下断，此处就是进行反调试的地方，原理依然是获取TracePid的值判断当前是不是处于调试状态，建议第一次调试的人在fgets和fopen处下断，再f7跟进此调用就可以看到TracePid的值了。

![](../Images/2e979b4db2e8499a223cae72611e54f6.png)

  

跟进去之后，我们直接把方法移到最下方，就可以看到kill符号了，这就是杀进程的地方，如果当前处于调试状态，则直接结束进程。

我们在此函数的所有cmpR0,#0处下断，F9一下后即断在断点处，观察寄存器窗口的R0值，实质就是当前的TracePid的16进制的值

![](../Images/9b981dc61961c3387bf7d1f74ee1cb82.png)

  

不确定的可以使用cat /proc/pid/status进行对比一下，我们直接把R0置0，右键选择Zero Value即可清0，继续F9

![](../Images/c711fbce05b3727fe8bd0a451a0ba0c6.png)

  

我们看到程序又来到了mmap处，继续f9

![](../Images/1948241c21283b5b486a25db7c0c7899.png)

  

当继续断在调用反调试功能的方法时，继续F7跟进，依然在所有的cmp R0，#0处下断，断下后把R0清0后继续F9运行

目前的规律是，调用BLXLR的第一次，第二次和第四次是进行反调试判断的，第三次并不影响，可以直接f9跳过去，三次反调试搞定后，就可以愉快的F9运行并观察堆栈窗口了

![](../Images/47b3ffc8c3d9357fcb4c915212d75700.png)

  

当看到出现如下所示时：

![](../Images/cdd5edaa8c0523b5dc0ad9ef35e02e59.png)

  

  

说明壳已经开始解密并释放dex文件了，我们直接F8单步十几步，最后F9一下就可以看到我们需要的dex头了

![](../Images/1a52d2debb07060eaa200dd5b7d75d08.png)

  

直接脚本dump出来即可，最后把libjiagu的所有文件删除，并修复下Application标，如果存在则修复，不存在删除即可。
