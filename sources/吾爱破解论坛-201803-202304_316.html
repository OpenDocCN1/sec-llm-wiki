0x2破解过程：
首先我们双击下:auditworkbench.cmd启动fortify的界面程序，在启动界面的时候它就进行了证书校验，如果你没有有效的license，则会提示你Your license dose not allow access to Foritfy SCA。


这里，我们可以暴力搜一下这串字符，定位到相应的位置再做分析，但是，我一般会先看下程序的日志。


一般程序的一些配置信息和日志信息会放在AppData/Local这个目录下，我们在Local目录下找到相应的文件夹。

由以上traceback信息我们可以知道，程序在启动会后会在com.fortify.sca.cmd.SCAConfiguration类的initialize函数中调用license校验类来对license信息进行校验，以下是initialize中的校验逻辑：

这里代码的大概意思是通过调用Licensing.requireCapability函数来校验当前license信息是否有效，之后就是开始进行代码分析了。


这里我们只要将这些校验逻辑出去，然后使用以下指令单独编译即可：
`Javac SCAConfiguration.java -cp lib/*   将lib目录下的所有jar包包含进来，有依赖关系。`
这里也可以使用idea或者eclipse等ide对该类文件进行单独编译，只要将依赖的库都引入项目即可，比较容易，具体不细说了。


我们将重新编译出来的SCAConfiguration类替换掉原来的类之后，重新启动auditworkbench.cmd发现仍旧无法启动。那么这里我们有必要再看之前的代码，梳理下它的license校验机制。


跟入Licensing.requireCapability函数我们发现了如下函数调用关系：
requireCapability->getCapabilityConfig


public static Licensing.Config getCapabilityConfig(Capability capability) throws LicenseExpiredException, UnlicensedCapabilityException, InvalidLicenseFileException, MissingLicenseFileException {

        loadLicensing();

        Licensing.Config config = (Licensing.Config)capabilities.get(capability.getKey());

        if (config == null) {

            throw new UnlicensedCapabilityException(capability);

        } else if (config.expirationDate != null && config.expirationDate.before(new Date())) {

            throw new LicenseExpiredException(capability, config.expirationDate);

        } else {

            config.parameterize(capability.getTypes());

            return config;

        }

}


在getCapabilityConfig中会先从config这个静态类中获取到相应的配置信息，然后判断下配置文件是否为空&license有效期是否为空&license有效期是否比当前时间靠前。


Ok，这里我们知道是从哪里取的了，那么它是怎么把license信息写到config中的呢？这里我们从之前的这个traceback信息可以看到，这个licensing类是专门用于处理license的，那么其中肯定封装了一些获取license信息的方法，优秀的研发工程师都是这么写程序的。

这里它要加载我们就让他加载好了，我们将里面所有throw证书异常的代码全部去掉，这样我们即可对整体进行破解。


这里我们总结下破解要点：
1、patch com.fortify.sca.cmd.SCAConfiguration类的initialize函数中的证书校验，将证书校验部分的代码去除。
2、patch 证书加载的地方com.fortify.licensing.licenseLoader类的doload函数，将所有的异常处理去除。
