# IDA动态调试逆向分析Android so

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=Mzg2NzUzNzk1Mw==&mid=2247484148&idx=1&sn=269ddfa70f832a9ef01df7402bb0e9d4&chksm=cebb47baf9ccceac5147bf99428ff0ebf1d37696268f0e5fc3be0417f7c0895ded50230e343c&scene=126&sessionid=1681666923#rd](http://mp.weixin.qq.com/s?__biz=Mzg2NzUzNzk1Mw==&mid=2247484148&idx=1&sn=269ddfa70f832a9ef01df7402bb0e9d4&chksm=cebb47baf9ccceac5147bf99428ff0ebf1d37696268f0e5fc3be0417f7c0895ded50230e343c&scene=126&sessionid=1681666923#rd)

**使用IDA进行动态调试Android so，有两种方式进行调试****，****如下所示:**

  (1).一种是调试启动方式，调试启动可以调试jni\_onload ，init\_array处的代码，可以在较早的时机得到调试权限，一般反调试会在较早的时候进行启动。

  (2).另一种则是附加调试，附加调试是在App已经运行起来的时候进行附加调试，这两种方式与Windows上的调试启动和附加调试概念很相似。

  

**实践环境:Windows 10 + IDA Pro 7.0 + Nexus5(Android 7.1.2)**

  

**第一种****:****调试启动**

  

**1.以调试的方式启动程序（可以在jni\_onload、init\_array处下断点）**

adb shell am start -D -n com.\*\*\*.\*\*\*/.MainActivity

![](../Images/b8dd2d03305aef19abbfd0bd6074128b.png)

 

**2.在IDA的主目录dbgsrv目录下，找到android\_server，拷贝到手机的**data/local/tmp/目录下

![](../Images/9ad03a4154043f2a3f01d4b5944c657d.png)

  

adb push （android\_server所在目录） /data/local/tmp

![](../Images/96f972921570462b0f63b500d7b62ea7.png)

   

**3.使用chmod修改android\_server程序的执行权限并执行**

adb shell chmod 755 /data/local/tmp/android\_server 

![](../Images/58b433df59846d3a45bcd4ac84c2ca72.png)

  

  

adb shell

su

cd data/local/tmp

./android\_server

![](../Images/0f7c460d8260685064ab5486250f60d6.png) 

**4.新开一个cmd窗口使用forward程序进行端口转发**

adb forward tcp:23946 tcp:23946

![](../Images/59367d125e4305404768fe88a202cc42.png)

  

**5.打开方法调试**

打开IDA，选择菜单Debugger -> Attach -> Remote ARM Linux/Android debugger

![](../Images/b5668e32db14b2bdd773e3a630a29bb9.png)

  

**6.Hostname填写127.0.0.1或者locahost**

Port端口自动填23946 

![](../Images/996e769f0fb779d1823c5e98a724832b.png)

  

**7.选择要进行调试的App**

![](../Images/8738a6a2518ddd7d92b53118ad61f22b.png)

 

点击OK按钮则进入调试界面，注意，这时候还不能进行动态调试

![](../Images/40d5fb31abbe7d97141e6c437d35b653.png)

  

8.点击菜单Debugger->Debugger Opitions在弹出的Debugger setup窗口的Events中选择Suspend on Process entry和Suspend on thread start/exit以及Suspend on library load/unload，再点击OK退出。通过此操作可以设置程序在创建新线程和加载so时自动中断

![](../Images/368aa596ad2f932bcc2dabd2fbc0a60c.png)

  

通过DDMS获取相应进程的端口号，然后使用jdb -connect com.sun.jdi.SocketAttach:hostname=127.0.0.1,port=XXXX（DDMS查询到的端口号，一般ddms进行转发后的端口都是8700） 

![](../Images/da1684a08a278fd2e380a3c09098bcb0.png)

  

如果成功执行jdb -connect DDMS上虫子图标会变成绿色 

![](../Images/bae57d07f438c777b7e4e5249f7252af.png)

  

连接成功后，在IDA按F9后手机上的“waiting for debugger"提示会自动消失，这个时候应该已经断在新线程，或者加载so处了。

![](../Images/522090a73b57d9b9fe411bbf35d2b81e.png)

  

9.现在就可以在IDA中按下快捷键CTRL + S来查看要调试的so是否已经加载了，如果没有就按F9，直到加载了为止；如果已经有了，就记下该so的start位置，然后另开一个ida分析.so库，找到JNI\_ONLOAD的偏移地址，那么该JNI\_OnLoad函数在进程中的真实地址就是so.start + JNI\_OnLoad\_Offset

![](../Images/99efefab9b274b81f217257267730610.png)

  

![](../Images/eba4b5f5e2047318c5c55231f06f8402.png)

  

0x753030000 + 0x1B9C = 0x75304B9C（JNI\_OnLoad在App进程中的地址）

  

这里需要说明的是:有可能在快捷键CTRL + S跳出的窗口中有两个同名的so，我们应当选择权限为RX的这个，RX一般是代码段，RW一般是数据段。

  

10.得到真实地址后，在IDA中按下快捷键G跳转到这个地址，然后按下快捷键F2就完成在JNI\_OnLoad函数入口处下断点了。如果想直接在native函数下断点，那么另开一个IDA进行静态分析查看函数地址，然后转换成为动态加载起来的地址，接着按快捷键G跳转到该地址下断点即可

![](../Images/a2c8db8942635e71d5d114f304700db5.png)

 

**11.再次按下F9，则在JNI\_OnLoad断了下来，接着就可以进行动态调试逆向分析功能**

![](../Images/7bd92fe1395308b0a7ce9ed8b9b2fd11.png)

 

**第二种****:****附加方式调试so**

  

**1.拷贝android\_server**

adb push （android\_server所在目录） /data/local/tmp

  

**2.修改执行权限并执行**

adb shell chmod 755 /data/local/tmp/android\_server

adb shell

su

cd data/local/tmp

./android\_server

  

**3.转发端口**

adb forward tcp:23946 tcp:23946

  

**4.启动android\_server**

发现一个小问题，就是退出调试以后再次调试，android\_server没有close，按道理是可以再一次连接的，但是这里则是无法进行再次连接调试，所以需要重新启动一下

android\_server

如下:(14061是pid)

root@android:/ # ps | grep android\_server

root 14061 13574 11180 9504 ffffffff 40183da0 S /data/local/tmp/android\_server 

root@android:/ # kill -s 9 14061 

  

**5.打开IDA，选择菜单Debugger -> Attach -> Remote ARM Linux/Android debugger**

![](../Images/b5668e32db14b2bdd773e3a630a29bb9.png)

 

Hostname填写127.0.0.1或者locahost

Port端口自动填23946

![](../Images/996e769f0fb779d1823c5e98a724832b.png)

   

选择要进行调试的App

![](../Images/935e0ad89f64d121b92cbd89db557d8f.png)

 

得到进程中的地址后，在IDA中按下快捷键G跳转到这个地址，然后按下快捷键F2就完成在JNI\_OnLoad函数入口处下断点了。如果想直接在native函数下断点，那么另开一个IDA进行静态分析查看函数地址，然后转换成为动态加载起来的地址，接着按下快捷键G跳转到该地址下断点即可 

![](../Images/3744ea3c0036442a4e253629a8495d57.png)

  

运行程序指定功能，触发断点，接着就可以到达该函数进行动态调试逆向分析功能

![](../Images/05d5928e7253e6c9d82b336b52291f19.png)
