为什么使用Charles+Drony来抓包?  

在对app进行抓包时，其实用什么方案并不是唯一的，有Fiddler，也有Charles的，也有我们所说的这种方式，Charles+VPN的方式(这里的vpn指的是像Drony来进行转发的一类app)

方式并不是唯一的，适合的就是最好的！

之所以采用Charles+VPN方式，是因为现在的app很大可能会进行wifi代理检测！

而vpn转发请求和wifi代理检测没关系，所以并不太会受影响，所以现在这种方式越来越多！

当然，除了wifi代理检测，还有vpn转发检测，还有证书校验等，但是现在遇到最多的还是wifi代理检测！

## 配置证书

### 保存证书到指定位置

点击`Save Charles Root Certi...`

![](../Images/e8fbbeaa0a635377be6b9276259191eb.png)

选择一个路径保存

![](../Images/295fd4ee8b5bca96d96e73c5a2518b69.png)

### 证书推送到手机上

将保存的证书推送到手机上

```

adb push C:\Users\Ti\Downloads\1.pem /sdcard/1.pem
```

![](../Images/1e528c54c740a8dd1062c8d364485cea.png)

成功推送到手机上

![](../Images/e73649fd35ae40cbca6c41e2808c2b93.png)

### 手机端安装证书

点击从存储设备安装证书

![](../Images/459b66340427b889a7a59d42e41265a0.png)

点击证书，安装

![](../Images/aae1e19b28feebd07e1d18066f8fb1f1.png)

证书名字随便写

![](../Images/1cf6f1f85bcae64f07e3651253c1cf67.png)

安装好之后是可以在信任的凭据中看到的

![](../Images/1923f4f6cd806f7bdc6b4402aa362334.png)

查看用户证书

![](../Images/7b34215c3ae5c7506c01216bc5448556.png)

### 证书存放目录

```


系统证书路径 /etc/security/cacerts
```

虽然此时证书已经安装完成，但是可能对APP抓https还是失败的。

因为Android7以后，只信任系统证书，所以还需要将用户证书移动成系统证书。

### 移动证书

这里使用Magisk的`Move Certificates`模块来安装证书

直接安装即可

![](../Images/bd0acd522287c2fc23fda2950dfb9202.png)

然后重启手机，你就会发现证书移动成功。

## 配置Drony

**PS**：如果打算使用drony的话，wifi代理就可以关了，wifi代理能干的事，drony都能干！

首先要安装drony，这就不用多说了吧！

安装完成之后，往左划一下进入设置，然后点击不是**无线网络...**

![](../Images/9fca401ee0968c4d4e80708cbf70c196.png)

### 配置ip和端口

先设置**主机名**和**端口**，和wifi代理配置的是一样的

![](../Images/109a249111e3140d3ff72e184fbc8c6d.png)

### 配置过滤器

然后继续往下滑，滑到**过滤器**，选择这个**引导全部**

![](../Images/1fa6dae128bec1cdc74ddb3d0ca26df6.png)

### 配置规则(添加要抓包的app)

然后点击**规则**

![](../Images/126d380afa79f70739967d9a41d13842.png)

点击右上角+号

![](../Images/a794f2a1928eb08d5657c84c733bcf77.png)

添加一个app，行为是**允许所有**，然后点击右上角保存！

![](../Images/8d8111ad0931b599936a2172d7e8153c.png)

这样就出现在规则列表中了，并且只会抓这一个app的包。

![](../Images/83fc0a9bd66999bf3a1dc4b1e6e5db10.png)

如果需要抓其他app，继续添加app即可！

### 启动drony

都配置完成后，回到主页面，点击：开，就可以对指定app进行转发了！

![](../Images/a2990ba4b56dfe3ba69b5905f323b869.png)
