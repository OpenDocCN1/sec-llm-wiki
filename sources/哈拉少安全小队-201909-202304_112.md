## 0x03科技

马不停蹄开始冲刺

![](../Images/84686fcde8073a94c376cfd279cbfb51.png)

内容为图片，显然有waf检测后缀，没啥好办法一个个进行测试过程就直接省略了。结论：在"filename"最后位置加一个“ " ”直接就可以绕过。

![](../Images/b682b0b724b327af7b690dcdae6384a6.png)

既然存在waf检测后缀那肯定也存在内容检测，直接上免杀马，就在自我感觉良好的时候免杀马分分钟被烂了。

![](../Images/290e46ae967b131feb96ec13d17a6954.png)

这样那就只能和后缀一样一点一点进行测试，这里使用二分法测试下到底是哪儿触发了waf的规则被拦截然后再想办法进行绕过。经过测试有三个点触发waf规则 1、：<%后面跟任何字母都不行(<%try-------)

![](../Images/c21e9f3f64f449913765892920429f3a.png "null")

2、：`<%@ Page Language="CS" %>` 有它就不行猜测也是和1类似。3、：中间代码位置`new System.IO.MemoryStream(); object o.....`

![](../Images/0103edaf4942be0e2c2f8763c497c7a2.png "null")

1和3可以使用同一种方式绕过:利用注释添加脏字符

```
/*asdasd--------asdas*/
```

![](../Images/2929f5d4a90bb4ad52a55c0d7c3a057b.png)

2可以使用另一种方式进行替换

```
 <script            language=csharp runat=server>
```

![](../Images/a767c3d5bf6e66a3d8c59718021a4495.png)

成了！

![](../Images/0393495c60a0e5c0b1e34430151360ae.png)

## 0x04狠活
