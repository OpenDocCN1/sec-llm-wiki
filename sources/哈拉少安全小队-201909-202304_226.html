一、漏洞简介：

__wakeup魔术方法：会在反序列化恢复对象之前调用该方法

当反序列化字符串中，表示属性个数的值大于真实属性个数时，会绕过 __wakeup()魔术方法的执行



影响版本：

PHP5 < 5.6.25

PHP7 < 7.0.10




二、漏洞实例：

本次使用的是极客大挑战2019 php的ctf题进行讲解，题目源码结构，由于本地搭建的原因，我对题目中的flag进行了更改，思路不变：


访问题目环境：



原题是通过扫描备份文件拿到源码，这步就省略了，我们直接看：

index.php，在36-40行左右，include包含了class.php文件，然后利用GET接受select参数，然后利用unserialize()函数对传参进行反序列化



然后来分析下class.php：



首先使用include包含了flag.php文件，类Name中有两个私有属性username和password，在__construct()构造方法中对私有属性进行赋值，__wakeup()魔术方法中将username属性赋值为guest，__destruct()析构方法中首先对password属性的值进行判断，如果不等于100就会die()退出掉，然后对username属性进行判断，如果username属性的值等于admin就输出flag，代码分析完毕



利用思路：

我们要让password属性的值为100，username属性的值为admin，才能的到flag的值，但由于__wakeup()魔术方法会在反序列化之前先调用，其将username赋值为了guest，我们是得不到flag的，所以我们要想办法绕过__wakeup()魔术方法的执行，可以利用CVE-2016-7124绕过。



构造EXP：

<?php
class Name{  private $username = 'admin';  private $password = 100;}
$mosen = new Name();echo serialize($mosen);


访问执行exp得到序列化之后的字符串：


由于username和password属性是私有属性，private属性被序列化的时候属性名会变成%00类名%00属性名，所以我们对序列化后的字符串进行处理：

O:4:"Name":2:{s:14:"%00Name%00username";s:5:"admin";s:14:"%00Name%00password";i:100;}



补充：

private属性序列化的时候格式是%00类名%00成员名（类名两边加%00）

protect属性序列化的时候格式是%00*%00成员名（*号两边加%00）



然后我们要绕过__wakeup()魔术方法的执行就需要让构造的属性个数的值大于真实的属性个数，将Name类名后的属性个数改为3(大于真实存在的属性个数即可)：


O:4:"Name":3:{s:14:"%00Name%00username";s:5:"admin";s:14:"%00Name%00password";i:100;}



然后访问index.php，通过GET方法传入select参数的值为序列化后的payload即可得到flag：
