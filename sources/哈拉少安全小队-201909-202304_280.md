**Header头注入**

查看其他审计出来的敏感参数，发现一个记录网站ip的地方，一般网站记录ip的方式有俩种，第一种是通过调用其他第三方的api接口查询，第二种是通过网站的server头，当然还有其他的方式，此代码明显就是我说的第二种，记录的ip一般都是会存储到数据库当中，而这种server头的方法记录ip是可以进行伪造的，那么这个地方就可能存在注入，于是全局搜索哪里调用了这个函数。

![](../Images/5d88eecdc04fddc74a876902a06f94b0.png)

跟进到comment.php，这个文件是处理文章评论的地方。通过函数getip()获取到了ip的值，然后插入到数据库中执行。那么这个地方是可能存在sql注入漏洞的。  

![](../Images/00034c581d642635ca4561f5491302f8.png)

在测试的时候网站需要有一篇文章才能评论，发布文章需要先发布分类，但是在发布分类的地方会报错，需要将选择分类的判断给注释掉。

![](../Images/d01ee91a2919cde84dc159c375ebb5de.png)

构造的payload如下：

```
X-Forwarded-For:
00','1'),('','1','0','1','6',(selectconcat(admin\_name,':',pwd)fromblue\_admin),'1','1
```

sql语句INSERT可以插入多行语句，其中00','1')是为了能正常插入第一行评论，之后的内容是为了第二次插入，于是我们再插入第二行内容，但是前面由于定义好了插入的行数，要保证sql语句不报错所以后面就需要插入相同的行数，payload选择插入到content的地方是因为前端能正常显示content，但是文章所有人可见，如果这是在真实的渗透当中碰到这种漏洞，注入出来的密码很可能会被访客看到，所以根据ad\_js.php这个文件里面的思路修改了payload如下:

```
X-Forwarded-For:
00','1'),('','1','0','1','6',(selectconcat('<u-',admin\_name,'-u><p-',pwd,'-p>')fromblue\_admin),'1','1
```

在全局搜索的时候还发现comon.inc.php这个文件调用了getip()并且赋值给变量$online\_ip。
