前言


客户端脚本语言指的是运行在浏览器上，而非服务器上的语言。客户端语言成功执行的前提条件是浏览器拥有正确的解释以及执行该语言的能力。这也是为什么浏览器上直接禁用JavaScript是件非常容易的事情。由于很难让所有浏览器厂商都认可同一个标准，所以客户端语言比服务器端语言要少很多，不过对数据采集而言，意味着需要处理的语言类型也变少了。到目前为止，JavaScript是网络上最常见，也是支持最多的客户端脚本语言，它可以收集用户的跟踪数据，不需要重新加载页面，只需要直接提交表单即可，而那些看起来非常简洁的页面背后通常也会使用非常多的JavaScript文件，这些可以在页面的源代码<script>标签内进行查看。




1、JavaScript


JavaScript是一种脚本语言,已被广泛用于Web应用开发,常用来为网页添加各式各样的动态功能,为用户提供更流畅美观的浏览效果。通常JavaScript脚本是通过嵌入在HTML中来实现自身的功能的。

例如下面的Javascript程序通过递归方式计算Fibonacci序列，最后把结果打印在浏览器内。注意Javascript里面所有的变量都是通过var关键字进行定义的。

function fibonacci(a, b){
var nextNum = a + b;
console.log(nextNum+" is in the Fibonacci sequence");
if(nextNum < 100){
fibonacci(b, nextNum);
}
}
fibonacci(1, 1);

2、Ajax 异步的 JavaScript 和 XML


AJAX = Asynchronous JavaScript and XML，可通俗的理解为是异步的 JavaScript 和 XML，Ajax是一种使用现有标准的新方法。AJAX不是新的编程语言，而是一种使用现有标准的新方法。最大的优点是在不重新加载整个页面的情况下，可以与服务器交换数据并更新部分网页内容。运行AJAX不需要任何浏览器插件，但需要用户允许JavaScript在浏览器上执行。获取Ajax数据有几种方式，今天我们以Selenium+WebDriver的方式模拟浏览器的行为来获取数据，如下2种方式。




(1)Selenium

Selenium是一款支持多种语言、多种浏览器、多个平台的开源web自动化测试软件，测试人员可用python、java等语言编写自动化脚本，使得浏览器可以完全按照你的指令运行，大大节省了测试人员用鼠标点击测试的时间。  通过Python可以执行JavaScript来模拟正常用户访问浏览器的操作。

在Python中 Selenium 可以通过 pip install selenium 或 pip3 install selenium 命令导入




(2)WebDriver

Selenium需要浏览器配合才能使用，所以我们还需要安装浏览器的驱动WebDriver。WebDriver通过调用浏览器原生的自动化API直接驱动浏览器。

在本次示例中，我们安装的是Chrome的Webdriver。在使用WebDeriver测试之前，启动浏览器是至关重要的一个准备工作，可以通过以下代码实现：

from selenium import webdriver
chrome_driver = 'C:\chromedriver.exe'
browser  = webdriver.Chrome(executable_path=chrome_driver)

注意：chrome_driver之后填写的是chromedriver.exe的实际路径。在互联网上有一个简短的使用Ajax的Demo网站：http://www.pythonscraping.com/pages/javascript/ajaxDemo.html，访问这个Demo页面之后会看到一些简短的文字，打开页面2秒钟之后，页面就会被替换成一个Ajax生成的内容。如果我们用之前提到的传统的方法采集这个页面，只能获取到加载之前的页面，而我们真正需要的信息，即那些在Ajax执行之后的页面，就无法抓取到了。

我们通过把Selenuim与Webdriver相结合就能用来处理cookie、JavaScript、Header等Ajax背后的内容，示例如下：

from selenium import webdriver
import time
driver = webdriver.Chrome(executable_path='C:\chromedriver.exe')
driver.get('http://www.pythonscraping.com/pages/javascript/ajaxDemo.html')
time.sleep(3)
print (driver.find_element_by_id('content').text)
driver.close()

但是这个方法效率还不是很高，中间我们设置了3秒钟的时间，用来确保页面已加载完毕。一种更有效的方法是，让Selenium不断的检查某个元素是否存在，以此确定页面是不是已经完全加载，如果页面加载成功，则继续往下执行。

from selenium import webdriver
from selenium.webdriver.common.by import By
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC

driver = webdriver.Chrome(executable_path='C:\chromedriver.exe')
driver.get('http://www.pythonscraping.com/pages/javascript/ajaxDemo.html')
try:
    element = WebDriverWait(driver,10).until(EC.presence_of_all_elements_located((By.ID,'loadedButton')))
finally:
    print (driver.find_element_by_id("content").text)
    driver.close()

程序在这里导入了一些新的模块，最需要注意的是WebDriverWait 和 expected_conditions，这两个模块组合起来，构成了Selenium的隐式等待（implicit wait）。

隐式等待与显式等待的不同之处在于，隐式等待式是等DOM中某个状态发生后再继续运行代码（没有明显的等待时间，但是有最大等待时限，只要在时限内就可以），而显式等待明确设置了等待时间，如之前代码中的time.sleep(3)等待三秒钟时间。在隐式等待中，DOM触发状态是用expected_conditions定义的（这里导入后使用了别名EC，也是经常使用的简称）。在Selenium库里面元素被触发的期待条件（expected condition）有很多种，包括：

  • 弹出一个提示框

  • 一个元素被选中

  • 页面的标题被修改

  • 一个元素在DOM内可见

  • 一个元素从DOM中消失


元素用定位器locator指定，定位器是一种抽象的查询语言，用By对象表示。在以下的示例中，一个定位器被用来查找id是loadedButton的按钮：

EC.presence_of_all_elements_located((By.ID,'loadedButton'))

定位器还可以用来创建选择器，配合WebDriver的find_element函数使用：

print(driver.find_element_by_id(By.ID,"content").text)

关于Python selenium 三种等待方式详解，读者可自行参考以下学习资料：

3、处理重定向


作为知识的积累，说到重定向我们需要先了解下客户端重定向Redirect以及服务器端重定向Dispatch：

Redirect(客户端重定向)

标准意义上的“重定向”指的是HTTP重定向，它是HTTP协议规定的一种机制。这种机制是这样工作的：当client向server发送一个请求，要求获取一个资源时，在server接收到这个请求后发现请求的这个资源实际存放在另一个位置，于是server在返回的response中写入那个请求资源的正确的URL，并设置reponse的状态码为301（表示这是一个要求浏览器重定向的response)，当client接受到这个response后就会根据新的URL重新发起请求。重定向有一个典型的特征，即，当一个请求被重定向以后，最终浏览器上显示的URL往往不再是开始时请求的那个URL了。这就是重定向的由来。


Dispatch(服务器端重定向)

Dispatch（Forward)指的是服务器在处理request的过程中将request先后委托多个servlet或jsp接替进行处理的过程。最为常见的是先由一个Servlet处理（比如实现业务逻辑的计算），然后forward给一个JSP进行视图的渲染。在Servlet里，实现dispatch是通过RequestDispatchers来实现的，而这个类有两个方法，一个是forward,另一个是include,相应的在JSP里实现dispatch的标签也有两个：<jsp:forward/>和<jsp:include/>.  不管是forward还是include，我们可以清楚的看到，从一个servlet或jsp向别一个servlet或jsp跳转，request和reponse始终在期间传递，这是服务器端能实现dispatch模式的关键。换句话说，我们可以把request和reponse看作是一种资源，一系列的servlet和jsp都是在基于同一份资源完成它们职责范围之内的计算。

实际中，当浏览器访问页面的时候，有时很难区分这两种重定向，由于客户端重定向执行的很快，加载页面的时候，你甚至感觉不到任何延迟，所以往往就会产生一种错觉，以为就是服务器端重定向。

但是，在网络数据采集的时候，这两种重定向的区别会变得比较明显，根据具体情况，服务端重定向一般都可以通过Python的urllib库解决，不需要使用Selenium。客户端重定向却不能这样处理。

Selenium可以执行这种Javascript重定向，但是主要是问题什么时候停止页面监控，如何识别一个页面以及完成了重定向？我们可以用检测DOM元素的方式来实现，首先，从页面开始加载时就“监视”DOM中的一个元素，然后重复调用这个元素直到Selenium抛出一个StaleElementReferenceException异常，也就是说，元素不在页面的DOM里面了，说明该页面已完成跳转。

from selenium import webdriver
import time
from selenium.webdriver.remote.webelement import WebElement
from selenium.common.exceptions import StaleElementReferenceException

def waitForLoad(driver):
    elem = driver.find_element_by_tag_name("html")
    count = 0
    while True:
        count += 1
        if count > 20:
            print ("Timing out after 10 seconds and returning")
            return
        time.sleep(.5)
        try:
            elem == driver.find_element_by_tag_name("html")
        except StaleElementReferenceException:
            return


driver = webdriver.Chrome(executable_path='C:\chromedriver.exe')
driver.get('http://www.pythonscraping.com/pages/javascript/ajaxDemo.html')
waitForLoad(driver)

print (driver.page_source)

这段程序会每半秒钟检查一次网页，看看HTML标签是否还在，时限是10秒钟。
