数据采集之使用API接口

VSRC唯科普 | 第4/14篇


在上期唯科普3中我们提到了多种数据的采集方式，并且在最后还介绍了Scarpy爬虫框架。虽然这些方法都可以帮助我们获取到网站信息，但是今天的内容将会让我们用另外一种方法获取更多的信息——API接口。


1、什么是API接口？


API（Application Programming Interface,应用程序编程接口）是一些预先定义的函数，目的是提供应用程序与开发人员基于某软件或硬件得以访问一组例程的能力，而又无需访问源码，或理解内部工作机制的细节。


API的应用开发需要按照API发布者提供的的规范进行开发。站点在推出基于开放API 标准的产品和服务后，无需花费力气做大量的市场推广，只要提供的服务或应用出色易用，其他站点就会主动将开放API 提供的服务整合到自己的应用之中。


同时，这种整合API 带来的服务应用，也会激发更多富有创意的应用产生。例如你可以在以下URL后面加入IP：http://freegeoip.net/json/116.232.83.99


便会得到下列返回信息：

{"ip":"116.232.83.99","country_code":"CN","country_name":"China","region_code":"31","region_name":"Shanghai","city":"Shanghai","zip_code":"","time_zone":"Asia/Shanghai","latitude":31.0456,"longitude":121.3997,"metro_code":0}


2、API的通用规则


和大多数的网络数据采集方式不同，API使用一套非常标准的规则生成数据，而且生成的数据也是按照非常标准的方式组织的。


API请求使用非常严谨的语法，使用JSON或则XML格式表示数据，而不是HTML格式。


因为规则很标准，所以一些简单、基本的规则很容易上手，可以帮助我们快速的掌握API的使用方法。


2.1、使用HTTP获取信息的四种方法


  • GET方法：通过浏览器访问一个网站获取信息；

  • POST方法：将表单内容发送给服务器；

  • PUT方法：在API中常用来更新一个对象或者信息；

  • DELETE方法：用于删除对象；


虽然在HTTP规范里面还有一些信息处理方式，但是这四种基本是我们使用API过程中可能遇到的全部了。

 

2.2、验证信息获取


虽然很多API不需要验证，也就是说任何人都可以使用API，并且不需要注册，但是仍然存在很多新式的API在使用之前都要求客户端验证。


有些是为了计费，而另外一些则是为了限制用户使用（例如调用次数调用频率等），还有一些可能不要求验证但也会为了市场营销策略而跟踪用户的使用行为。


通常的，API验证的方法都是通过类似令牌Token的方式调用，每次API调用都会把令牌传递到服务器上，这些令牌可以是在用户注册时候分配的，也可以是在用户调用时候才提供的。


可能是长期固定的值，也可能是频繁变化的，通过服务器对用户名和密码的组合之后产生。Token除了在URL内传递，也可能通过请求头部header中的cookie传递给服务器。

 

请求头部可以使用urllib包进行传递：

token = "<your api key>"

webRequest = urllib.request.Request("http://myapi.com", headers={"token":token})

html = urlopen(webRequest)


3、服务器响应


API有一个重要的特征是他们会反馈格式友好的数据，大多数反馈的数据格式都是XML和JSON。除了共同的准则之外，不同API的调用语法也各不相同。


例如以下这个API接口可以获取到ID是201用户在2016年1月至2月期间所购买的所有电影票：

http://mytestmovie.com/users/201/posts?from=20160101&to=20160201


许多API会通过文件路径path的形式返回API版本、数据格式和其他属性。


还有一些API会通过请求参数的形式指定数据格式和API版本：

http://mytestmovie.com/users/201/posts?format=json&from=20160101&to=20160201

 

4、The Echo Nest


“The Echo Nest's customers reach over 100,000,000 music fans every month.”


The Echo Nest音乐数据网站是一个依靠网络爬虫建立的企业级案例。


虽然很多其他同类型的网站基本靠人工干预完成音乐的分类与说明，但是The Echo Nest是通过自动智能技术，以及博客与新闻信息采集，来完成艺术家、歌曲和专辑的分类工作。更令人兴奋的是，他的API可以经非商用用途免费使用。


使用API得需要一个key，我们可以通过在Echo Nest网站注册获取key。


The Echo Nest的API返回信息响应结果由以下四部分组成：artist、song、track专辑和genre风格。除了风格之外，所有信息都带有唯一的ID，我们可以通过API调用把信息展示成不同的形式：


http://developer.echonest.com/api/v4/artist/search?api_key=<key>&name=Akon


例如我们可以使用以下调用来检索Akon的ID，那么就会返回以下信息：


{"response": {"status": {"version": "4.2", "code": 0, "message": "Success"},"artists":[{"id":"AR5HF791187B9ABAF4","name":"Akon"},{"id": "ARWCIDE13925F19A33", "name": "Akon"},{"id": "ARVPRCC12FE0862033", "name": "Akon's Graham Chapman"}]}}


使用同一个ID，我们也可以查找相似风格的艺术家列表：

http://developer.echonest.com/api/v4/artist/similar?api_key=<key>&id=AR5HF791187B9ABAF4&format=json&results=10&start=0

6、Google的API


使用Google账号可以直接查看API列表，并通过Google开发者控制台创建API的key。

https://console.developers.google.com/



在凭证页面可以通过新建APIkey，你也可以多建立结果为每个项目都单独分配一个API key，但是Google的APIkey是根据流量收费的，这么做虽然可以方便管理你的key了，但是其实并不能提高你的可用流量。


下面我们来看几个使用GoogleAPI的示例。


不可否认，Google最受欢迎的API都在Google地图API套件中，而且地图API远比嵌入式地图的功能丰富得多，比如我们可以把街道信息解析成经纬度longitude/latitude坐标值，地球上任意一点的海拔高度，做出基于位置的可视化图形，获取任意位置的时区信息，以及其他一些地图相关的事情。


而用Google的Maps Geocoding API功能可以在浏览器里实现一个简单的GET请求，把街道解析成纬度和经度。


Google Maps Geocoding API 请求必须采用以下形式：

https://maps.googleapis.com/maps/api/geocode/output?parameters


其中，output 可以是以下值之一：

（1）以 JavaScript 对象标记 (JSON) 输出；

（2）以 XML 格式输出；


而对于请求中包含敏感用户数据（例如用户的位置）的应用，不建议使用 HTTP。

以 JSON output 标志为例：


https://maps.googleapis.com/maps/api/geocode/json?address=1600+Amphitheatre+Parkway,+Mountain+View,+CA&key=YOUR_API_KEY
