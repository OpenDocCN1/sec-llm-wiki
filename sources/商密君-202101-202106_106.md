# 个人信息匿名化只是远方的想象吗？

近年来，技术的飞速发展提高了对高质量数据的需求。各方为了实现数据的共享流动，普遍考虑将匿名化作为平衡数据利用和个人数据基本权利的一种技术手段。然而，各方在使用匿名化技术的过程中，对于匿名化的理解仍然不够透彻，实践中经常出现错误使用匿名化的问题。为了解决这些问题，**西班牙数据保护机构AEPD**和**欧盟数据保护主管机构EDPS**联合发布了关于匿名化的文件——**《涉及与匿名化有关的10个误解》**，目的在于**提高各方对匿名化的认识，消除误解，规范匿名化技术的应用。**【关键词】匿名化 数据保护 假名化  
![](../Images/5085cbbd01ecf10bcd66cff5839af03c.png)**一、相关背景**

  

**EDPS****与成员国数据保护机构发布联合文件的形式并不常见。**EDPS是欧盟内部主要负责欧盟机构和组织个人数据保护工作的机构。根据2018年欧盟公布的《关于欧盟机构和组织的个人数据保护条例》，EDPS的职权主要包括：监督欧盟机构和组织的个人数据保护法执行情况并展开执法调查；向欧盟机构和组织提供与处理个人数据有关的建议；关注可能影响个人信息保护的新技术；就解释数据保护法提供专家意见；与成员国数据保护监管机构和其他监管机构进行合作。EDPS并没有直接发布指南的权力，在欧盟内部，EDPS更类似于以专家的身份存在，通过发布意见、文件等形式对个人数据保护的相关问题展开探讨。  
此前，EDPS曾多次与欧盟数据保护委员会EDPB联合发布了关于《数据战略》《数据治理法》《人工智能法》等的意见文件。但与成员国数据保护机构联合发布文件，在历史上仅有两次，且均是与AEPD针对匿名化问题进行合作。第一次是2019年11月，《涉及与匿名化有关的10个误解》即是第二次合作。AEPD在欧盟成员国中属于执法非常频繁、罚款案件较多的国家，截止今年5月初，自GDPR生效以来，西班牙的罚款案件数量为222件，位于欧盟成员国第一名，而第二名的意大利罚款案件数量仅为73件。据了解，欧盟近期对匿名化问题非常关注，EDPS与AEPD联合发布文件，可能也从侧面证明，AEPD在执法实践中遇到的匿名化问题较多。  
从法律效力上来看，这种联合发布的文件并不具有强制力，但是，作为欧盟的重要个人数据保护机构，EDPS与AEPD发布文件中所表达的观点也是在执法实践中可能会遵从的思路和做法。

  

![](../Images/5085cbbd01ecf10bcd66cff5839af03c.png)**二、匿名化相关概念和问题**

  

匿名化是使个人数据被匿名的过程。根据欧盟《通用数据保护条例》（GDPR）及其他相关立法，匿名数据是指“与已识别或可识别的自然人无关的数据，或个人数据通过匿名化之后不再能够识别到个人的数据”。包含个人数据的数据集可能包括直接和间接的标识符，这两种标识符都可能识别到个人或使得个人变得具有可识别性。直接标识符是指个人的特定数据，如姓名或身份证号。间接标识符(也称为准标识符)是指由对某个个人有一定了解的主体单独使用或与其他准标识符相结合使用，目的是重新识别数据集中的个人。重新识别是指在给定数据集中，通过使用数据匹配或类似技术将匿名数据转换回个人数据。数据集的效用是衡量该数据对预期目的(如对某一特定疾病的研究)的有用程度的指标。  
实践中已经出现将个人数据错误进行匿名化从而又导致个人被重新识别出来的案例。2006年，一家电影流媒体服务公司公开了一个数据集，其中包含了50万名用户所做的1000万部电影的排名，公司声称该数据集是匿名的，但之后证明，不法分子只需再掌握一些其他的用户数据，就能在数据集中识别出特定用户的相关记录。2013年，纽约市出租车和豪华轿车委员会公布了一份涉及超过1.73亿次出租车出行的数据表，其中包含接送地点、时间和声称已被匿名的牌照号码。但由于数据集没有正确地使用匿名技术，这份数据表极有可能识别出原始的牌照号码，甚至是出租车司机个人。

  

![](../Images/5085cbbd01ecf10bcd66cff5839af03c.png)**三、匿名化的十个误解及解释**

  

匿名数据在医学、人口统计、市场营销、经济、统计和其他许多领域的研究中发挥着重要作用。然而，匿名化使用中的相关误解也十分普遍。

  

**误解一**

**“假名化和匿名化是一样的”**

**事实：假名化不同于匿名化。**

  

GDPR将“假名化”定义为“是指以如下方式处理个人数据，即：除非使用额外数据，否则无法将个人数据连结到某个具体的数据主体，且上述额外数据应当被独立存储并采取适当的技术和组织措施，以确保个人数据不会连结到某个已识别或可识别的自然人”。这意味着假名数据与“额外数据”共同使用可以识别到个人，这就是为什么假名个人数据仍然是个人数据的原因。  
另一方面，匿名数据不能与特定的个人相关联。一旦数据是按照要求被匿名化的，相关的个人通过该数据就不再是可以被识别的，这些数据将不属于GDPR的监管范围。

  

**误解二**

**“加密是匿名化技术”**

**事实：加密不是匿名化技术，但可以是一个强大的假名化工具。**

  

在加密过程中，密钥是用来转换数据的工具，可以降低数据被滥用的风险，同时也使得数据在特定的时间段内保持机密性。但由于原始数据还有被访问和使用的必要性，所以加密算法的应用被设计为是可逆的，即所谓的可被解密。用于解密的密钥则是“误解一”中所说的“额外数据”，可以使个人数据被访问，从而识别到个人。  
  
理论上，删除加密数据的加密密钥会使数据被匿名化，但实践中并非如此，从长期来看，影响加密数据保密性的因素还有很多，如加密算法和密钥的强度、数据泄露、技术实施问题、加密数据量或技术的发展程度(例如量子计算)，因此不能因为解密密钥被称为“已擦除”或“未知”，就认为加密数据无法解密。

  

**误解三****“将数据进行匿名化是绝对可能的”**

**事实：在保留用于特定处理活动的原始数据集的同时，不可能总是将重新识别的风险降低到先前定义的阈值以下。**

  

匿名化是一个过程，试图在降低再识别风险和保持数据集用于预期目的之间找到平衡。然而，根据上下文或数据的性质，重新识别的风险并不能被完全消除，尤其在以下情况下，这种风险更不容易被消除或减轻：当数据集涉及个体的数量很少(例如，匿名数据集仅包含欧洲议会的705名成员)，当个体之间的数据类别差异太大以至于有可能在全部个体中找出这些特殊的个体时(例如，访问某个网站系统的设备指纹)，或者当数据集中包括大量人口统计属性或位置数据时。  

  

**误解四****“匿名化是永恒的”****事实：一些匿名化的数据存在将来可能被还原的风险。**

  

随着时间的推移，新的技术发展和额外数据的积累等情况的发生可能会使得之前的匿名化技术变得不再有效。  
  
随着不法分子可以利用的资源和技术在未来发生变化，重新识别匿名数据集的可能性加不断提高。如今，云计算以几年前不可想象的水平提供了高超的计算能力。在未来，量子计算机也可能改变现在被认为是“合理手段”的技术。  
另外，随着额外数据不断披露(如个人数据泄露)的发生，可以参考的数据越来越多，以前被匿名的数据也存在与已识别的个人联系起来的风险，如包含高度敏感数据的记录(犯罪记录)的泄露仍可能对个人或其亲属产生严重的不利影响。

  

**误解五**

**“匿名化将数据集被重新识别的概率降至零”**

**事实：匿名化过程及其实施方式对重新识别风险的可能性产生直接影响。**

  

匿名化流程旨在将重新识别的风险降低到某个阈值以下。此类阈值将取决于现实中的多种因素，如现有的安全控制措施、在重新识别的情况下对个人隐私的影响、攻击者重新识别数据的动机和能力。  
  
从个人数据保护的角度来看，虽然对个人数据进行100%的匿名化是最理想的目标，但在某些情况下这是不可能的，技术人员必须要考虑到个人数据被重新识别的潜在风险。

  

**误解六**

**“匿名化是一个无法衡量的二元概念”**

**事实：分析和衡量匿名化的程度是可能的。**

  

除了数据高度一般化的特定情况(例如，统计每个国家一年网站访问者数量的数据集)，重新识别到个人的风险永远不会为零。  
“匿名数据”这一表述不能被理解为数据集可以简单地被标记为匿名或不匿名。任何数据集中的信息都有被重新识别的可能性。技术人员应当对所有匿名化流程进行评估，以确定重新被识别的风险程度，从而采取措施使得这些风险在一定程度内得到管理和控制。

  

**误解七**

**“匿名化可以完全自动化”**

**事实：自动化工具可以在匿名化过程中使用，但是，考虑到使用场景在整个过程中的重要性，需要人工专家进行干预。**

  

匿名化过程需要对原始数据集、其预期目的、应用的技术以及所得数据的再识别风险进行分析。  
  
直接标识符的识别和删除是匿名化过程的一个重要部分，但必须始终考虑对其他(间接)识别来源的谨慎分析(通常通过准标识符)。直接识别符的识别风险很容易被发现，但间接识别符的识别风险则比较隐秘，忽略这种风险会导致匿名化过程的逆转(即重新识别)，从而危害个人隐私。  
自动化工具是匿名化过程中某些步骤的关键，但在识别准标识符等情况下，完全自动化并不能达到人工干预所能产生的良好效果。

  

**误解八**

**“匿名化使数据变得无用”**

**事实：适当的匿名化过程可以确保数据在给定目的下发挥应有作用。**

  

对数据进行匿名化的目的是防止数据集中的个人被识别。匿名化技术会限制结果数据集的使用方式，例如，将出生日期分组为年间隔将降低重新识别的风险，但在某些情况下也同时降低了数据集的效用。这种对立并不意味着匿名数据将变得无用，匿名数据的作用取决于给定目的和可接受的再识别风险程度。

  

**误解九**

**“使用其他人成功使用的匿名化流程可以取得同等的结果”**

**事实：匿名化流程需要根据处理的性质、范围、背景和目的等因素进行调整。**

  

由于数据处理的性质、范围、原因和目的是不同的，因此匿名化不能照抄照搬其他人的经验。当数据只对有限数量的接收者可用时，匿名化过程可能具有低于特定阈值的重新识别风险，而当数据对公众可用时，重新识别的风险将不能满足该阈值的要求。  
另外，不同的数据集在不同情况下的可用性是不一样的。例如，在瑞典，纳税人个人数据的细节是公开的，而在西班牙则不是。因此，即使包含西班牙和瑞典公民信息的数据集按照相同的程序被匿名化，再识别的风险也可能是不同的。

  

**误解十**

**“对匿名数据进行重新识别不存在市场需求和风险”**

**事实：个人数据本身就有价值，对个人的重新识别会对个人的权利和自由产生严重影响。**

  

对匿名数据进行的攻击包括：故意和非故意的对数据进行重新识别、数据泄露或向公众公开数据。由于不同场景所限，重新识别对个人私生活的影响是很难被准确评估出来的，如，在一般的场景下重新识别一个数据主体的电影偏好，极有可能导致推断出此人的政治倾向或性取向。根据GDPR的规定，这些类型的数据属于特殊类别的个人数据，需要得到强化保护。  

  

![](../Images/5085cbbd01ecf10bcd66cff5839af03c.png)**四、小结**

  

**在欧盟的法律制度中几乎没有匿名化数据的存在空间。**匿名化数据并非GDPR的规制对象，欧盟《非个人数据自由流动条例》将其归类为“非个人数据”，允许自由流动。但是，个人数据的定义和对匿名化的高要求使得匿名化数据较难实现。**一方面，**欧盟立法中规定了非常广泛的个人数据范围，GDPR规定个人数据是指能够直接或间接识别到个人的数据，且没有对间接识别的程度进行限制，个人数据的范围非常广泛，正如EDPS和AEPD所说，匿名化数据并非绝对可能的，在与上下文（数据）进行进一步联系之后，仍有可能识别到个人。而且，欧盟《非个人数据自由流动条例》规定个人数据和非个人数据形成的“混合数据集”如果无法区分，即使个人数据仅占其中很小一部分，整个数据集也应当按照GDPR的标准进行保护。实践中，各个企业也不会对数据的类型进行区分，而是统一作为个人数据进行保护。**另一方面，**欧盟对匿名化技术有非常高的规定。GDPR是这样定义对匿名信息的：“与识别或可识别自然人无关的信息，或以数据主体不能或不再可识别的方式匿名提供的个人信息。” 第29条工作组表示，匿名化数据不能识别出特定个人是指：不论是对于掌握该数据的数据控制者，还是其他获得该数据的任何主体，采取一般可能的措施、手段也无法将该数据关联到特定个人。那么，根据EDPS和AEPD发布的文件可以看出，由于技术发展、每个数据控制者掌握技术能力等的不同，匿名化后的数据根本不存在完全不被识别的可能性，特定的时期、特定的主体都有可能再次对匿名数据进行识别。  
**我国《网络安全法》的规定与欧盟的规定类似，一方面，**“个人信息”的直接识别与间接识别的定义使得实践中判定的个人信息的范围非常广，**另一方面，**第四十二条明确“经过处理无法识别特定个人且不能复原的”的信息可以不经个人同意而向他人提供，《个人信息安全规范》中也明确“匿名化”需要满足个人信息主体无法被识别或者关联、且处理后的个人信息无法被复原的标准。根据EDPS和AEPD发布的文件，这不可能实现。  
综上所述，我们可以看出，实现数据的匿名化并非如我们所想象的那般简单，无论是在技术、场景、法律等方面仍存在很多难题有待解决。想要充分实现个人数据的匿名化、完全消除对个人进行再识别的风险几乎是不可能的，这对数据处理者提出了极高的要求。数据控制者在实施匿名化技术时，不仅仅需要仅从技术角度判断是否可以达到个人数据的保护要求，而且还要考虑相关的场景、未来的技术发展、存在的风险等多方因素，以最大程度减少对个人权利和自由可能产生的潜在危害。
