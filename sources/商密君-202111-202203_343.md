## **“Log4j2”****漏洞的主要挑战**

Log4Shell 漏洞之所以全球关注，是因为Log4j库非常普遍，而且很容易被利用。而且，鉴于Java打包的工作方式，通常甚至很难确定哪些应用程序受到影响。例如，Java 归档 (JAR) 文件包含所有依赖项，包括 Log4j 库。然而，一个JAR文件也可以包含另一个JAR文件（它也可能包含另一个 JAR 文件）——**本质上是将这个漏洞嵌套在几层深处。 这是一个非常普遍的问题，安全团队很难发现。这是关键挑战之一。****关键挑战之二，API中的Log4Shell漏洞。API 充当多个应用程序和系统之间的中介，Log4Shell 对 API 造成了两个重大问题。**首先是易受Log4Shell 攻击的API服务器现在为攻击者暴露了一个新的攻击面。大多数组织对其API清单及其 API 行为的可见性有限，这使得 API 成为威胁参与者的首选目标。其次，如果攻击者利用 Log4Shell 漏洞访问系统，API能够扩大攻击者的影响范围和可能造成的损害。例如，许多企业信任可能暴露于 Log4Shell 漏洞的第三方API。即使企业本身不使用Log4j 日志记录框架，第三方 API 也可能会暴露风险。**对于企业而言，对其API具有更精细的可见性和可观察性以了解其信任风险敞口至关重要。**
