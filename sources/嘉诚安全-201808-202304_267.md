# 【资讯】新的 Linux 恶意软件隐藏在日期无效的 cron 作业中

安全研究人员发现了一种新的 Linux 远程访问木马(RAT) ，它隐藏在计划于2月31日执行的任务中，从而保持了一个几乎看不见的配置文件。

  

该恶意软件被称为 CronRAT，目前以网络商店为目标，使攻击者能够通过在 Linux 服务器上部署在线支付抓取器来窃取信用卡数据。

  

CronRAT 具有独创性和复杂性的特点，就在线商店的恶意软件而言，许多防病毒引擎都无法检测到它。 

**有效载荷的巧妙藏身之处**  
  

CronRAT 滥用 Linux 任务调度系统 cron，该系统允许调度任务在日历中不存在的日子运行，例如 2 月 31 日。

  

Linux cron 系统接受日期规范，只要它们具有有效的格式，即使日历中不存在这一天，这意味着计划任务不会执行。

  

这就是 CronRAT 实现其隐身所依赖的。荷兰网络安全公司 Sansec 今天的一份报告解释说，它在计划任务的名称中隐藏了一个“复杂的 Bash 程序”。

  

“CronRAT 将许多任务添加到 crontab 中，并带有奇怪的日期规范：52 23 31 2 3。这些行在语法上是有效的，但在执行时会产生运行时错误。但是，这永远不会发生，因为它们计划于 2 月 31 日运行，”Sansec 研究人员解释说。

  

![](../Images/08f36835df040022d76f3617c9e6798e.png)

  

有效载荷通过多层压缩和 Base64 编码进行混淆。清理后，代码包括用于自毁、定时调制和允许与远程服务器通信的自定义协议的命令。

  

研究人员指出，该恶意软件使用“Linux 内核的奇特功能，通过文件启用 TCP 通信”联系命令和控制 (C2) 服务器 (47.115.46.167)。

  

此外，连接是通过端口 443 通过 TCP 完成的，使用 Dropbear SSH 服务的虚假，这也有助于恶意软件保持在雷达之下。

  

接触C2服务器后，在伪装下，发送和接收多个命令，获取恶意动态库。在这些交换结束时，CronRAT 背后的攻击者可以在受感染的系统上运行任何命令。

  

CronRAT 已在世界各地的多家商店中被发现，它被用来在服务器上注入窃取支付卡数据的脚本——即所谓的 Magecart 攻击。

  

Sansec 将新恶意软件描述为“对 Linux 电子商务服务器的严重威胁”，因为它具有以下功能：

  

● 无文件执行

● 定时调制

● 防篡改校验和

● 通过二进制混淆协议控制

● 在单独的 Linux 子系统中启动串联 RAT

● 伪装成“Dropbear SSH”服务的控制服务器

● 有效负载隐藏在合法的 CRON 计划任务名称中

  

所有这些功能使 CronRAT 几乎无法检测到。在 VirusTotal 扫描服务上，12 个防病毒引擎无法处理恶意文件，其中 58 个未将其检测为威胁。 

  

![](../Images/6136a58dfbffe7e6c08f87a7da67f48c.png)

  

Sansec 指出，CronRAT 的新颖执行技术也绕过了其检测算法 eComscan，研究人员不得不重写它以捕获新威胁。
