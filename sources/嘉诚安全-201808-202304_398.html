漏洞背景


2020年6月9日，Microsoft发布了6月份的安全更新公告，修复了其多款产品存在的129个安全漏洞。涵盖了Microsoft Windows、Internet Explorer、Office、Microsoft Edge、Windows Defender等众多组件和软件。129个CVE中共有11个被微软官方标记为Critical，118个被标记为“Importent”。此外，在本月的安全补丁中，有23个针对远程代码执行漏洞，5个针对拒绝服务漏洞，70个针对权限提升漏洞以及11个针对信息泄露漏洞。嘉诚安全提醒广大Microsoft用户尽快下载补丁更新，避免引发漏洞相关的网络安全事件。

漏洞详情


经研判以下漏洞影响较大：

CVE-2020-1299---LNK远程代码执行漏洞。

与以往的LNK远程代码执行漏洞一样，用户在处理特制LNK时即可触发漏洞。要利用此漏洞，攻击者可以向用户提供包含恶意的.LNK文件和关联的恶意二进制文件的可移动驱动器或远程共享，当用户在Windows资源管理器或任何其他解析.LNK文件的应用程序中打开此驱动器（或远程共享）时，恶意二进制文件将在目标系统上执行攻击者指定的代码。
成功利用该漏洞的攻击者可以在目标系统上以当前用户权限执行任意代码。由于该漏洞影响范围较广，且利用方式简单，因此需要引起重视，不要访问来源不明的驱动器或共享文件。

CVE-2020-1300---Windows远程代码执行漏洞。

该漏洞主要是由于Windows在处理cab格式文件时发生错误导致。.cab文件是Windows系统上的一种压缩文件，可以使用WinRAR或者IE5以上自带的IExpress打开。要利用此漏洞，攻击者需要诱骗目标用户打开特制的.cab文件，或者将.cab文件伪装成打印机驱动程序进行安装来触发漏洞。

成功利用此漏洞的攻击者可以实现远程代码执行。此漏洞影响Windows版本众多，且多为国内用户使用的主流系统，用户需提高警惕，不要打开来源不明的.cab文件。

CVE-2020-1281---Windows OLE远程代码执行漏洞。

该漏洞主要是因为Windows OLE未能正确处理用户输入导致。OLE是微软开发的一项专有技术，允许嵌入和链接到文档和其他对象，即允许编辑应用程序（Word、Excel等）将文档的一部分导出到另一个编辑应用程序。要利用此漏洞，攻击者需要先特制一个文件，然后诱骗目标用户打开，文件来源可以是web网页或者钓鱼邮件。

同样，该漏洞影响范围广泛，需要引起重视，不要下载来源不明的文件或者打开来源不明的邮件。

CVE-2020-1301---Windows SMB远程代码执行漏洞。

SMB(Server Message Block) 是网络文件共享系统（Common Internet File System，缩写为CIFS），一种应用层网络传输协议，由微软开发，主要功能是使网络上的机器能够共享计算机文件、打印机、串行端口和通讯等资源。
该漏洞位于SMBv1的驱动中，SMBv2和SMBv3版本不受影响，漏洞触发点位于在处理MS-FSCC协议中的FSCTL_SIS_COPTFILE请求时，没有完整验证SI_COPYFILE结构，导致整数溢出。要利用该漏洞需要先通过SMB用户认证，这提高了漏洞的利用难度。但SMBv1部署在Windows 7- Windows 10的所有版本中，因此漏洞影响范围较广，需要引起重视。（微软已在 2014 年弃用了 SMBv1 协议，在 Windows 10 操作系统上 SMBv1 默认禁用。）

成功利用该漏洞的攻击者可以实现在目标主机上执行任意代码。

CVE-2020-1213/1216---VBScript 远程代码执行漏洞。

这两个漏洞都位于IE的VBScript Engine中，但漏洞类型不同。CVE-2020-1213是一个UAF漏洞，CVE-2020-1216是一个类型混淆漏洞，均可以导致远程代码执行。要想利用此漏洞，攻击者采取的主要方式仍然是钓鱼形式，可以构造一个钓鱼网站诱使目标用户进行访问，或者在承载IE呈现引擎的应用程序或Microsoft Office文档中嵌入标记为“初始化安全”的ActiveX控件。
漏洞主要影响IE 9和IE 11，相对来说降低了影响范围。为保证不受漏洞影响，应警惕访问一些网站或者打开一些来源不明文件，尽可能降低受攻击风险。

CVE-2020-1301缓解措施：

1.使用强密码进行SMB用户认证，避免使用弱密码被破解登录。
2.建议关闭SMBv1，SMBv1存在诸多安全问题，如非必要，建议关闭SMBv1，使用SMBv2或更高版本协议进行替代，各Windows系统版本关闭SMBv1的方法可参考微软官方推荐方案：https://docs.microsoft.com/zh-cn/windows-server/storage/file-server/troubleshoot/detect-enable-and-disable-smbv1-v2-v3
