Apache James 服务器反序列化漏洞（CVE-2017-12628）分析和利用

今天早上，我发现了一条提到“Apache James 3.0.1 JMX服务器反序列化”漏洞的推文 ，漏洞编号是CVE-2017-12628，这引起了我的注意，因为我之前写过一个通用的JMX反序列化漏洞利用方式，它包含在我的RMI攻击工具 —— BaRMIe中。通过快速搜索可以了解CVE-2017-12628的更多详细信息，在  安全性公告中声明了该漏洞只能用于本地特权升级，并提及升级到的库版本信息。

这极大的引起了我的兴趣，因为JMX使用了RMI，并且RMI对象可以远程访问，即使它们绑定到了本地主机，因为Java将对象引用绑定到了“0.0.0.0”。BaRMIe利用本地端口转发来攻击绑定到本地或内部IP地址的对象。

漏洞分析

我在一个虚拟机中来运行Apache James 3.0.0（3.0.1修复了这个问题），而我注意到的第一件事就是 “libscommons-collections-3.2.1.jar” 文件。我们可以使用ysoserial来生成一个使用该库的POP小工具链，以便能够通过反序列化实现任意的命令执行。

我通过运行“bin/run.sh”来启动James服务器，然后在VM上执行netstat，并且在宿主主机上运行nmap，发现在VM上有一个侦听外部的Java RMI端口。

C:ToolsNmap>nmap.exe -sV --version-all -p33148,46299 192.168.174.40

Starting Nmap 7.31 ( https://nmap.org ) at 2017-10-22 12:37 GMT Daylight Time

Nmap scan report for 192.168.174.40

Host is up (0.00076s latency).

PORT      STATE SERVICE     VERSION

33148/tcp open  rmiregistry Java RMI

46299/tcp open  tcpwrapped

使用BaRMIe枚举此服务后，表明它是RMI对象服务而不是RMI注册服务，因此BaRMIe无法远程攻击该服务。

C:ToolsBaRMIe>java -jar BaRMIe.jar 192.168.174.40 33148

Scanning 1 target(s) for objects exposed via an RMI registry...

192.168.174.40:33148 appears to be an RMI object endpoint, rather than a registry.

在VM上本地运行nmap显示Apache James RMI注册服务绑定到了127.0.0.1:9999。我将BaRMIe复制到虚拟机来枚举这个RMI注册服务，发现外部的RMI服务实际上是JMX对象的RMI对象服务。

RMI Registry at 127.0.0.1:9999

Objects exposed: 1

Object 1

  Name: jmxrmi

  Endpoint: 127.0.1.1:33148

  Classes: 3

    Class 1

      Classname: javax.management.remote.rmi.RMIServerImpl_Stub

使用BaRMIe的攻击模式与通用JMX漏洞和Commons Collections 3.2.1有效载荷，可以利用此服务执行任意命令，导致本地权限升级。除此之外，还值得注意的是，如果服务器使用过时的Java运行时环境（<= 6u131,7u121或8u112），那么它也容易受到ysoserial RMI注册漏洞的攻击。

远程利用

安全发布公告说明了这只是一个本地特权升级漏洞，但是鉴于JMX对象是在外部暴露出来的，所以我认为这一定是可以远程利用的。

在我继续远程利用之前，我想说明这个漏洞是可以远程利用的，但是远程攻击涉及到基于网络的暴力攻击。

为了快速实现概念证明，我在虚拟机上使用tcpdump来捕获到JMX对象服务的流量，同时运行BaRMIe JMX漏洞利用工具执行命令“touch fooobaaar”。

sudo tcpdump -i lo -w apache-james-jmx-exploit.pcap port 33148

从我的主机进行远程重放，可以成功的发起攻击，证明远程攻击的确是可以实现的。

不过，我怀疑，在重新启动Apache James服务后，这个快速而肮脏的PoC不再奏效。我生成了更多的捕获到的数据包来进行比较，并进行了一些进一步的测试，似乎可以降低漏洞利用的第三个出站数据包的一些差异。以下是该数据包的前27个字节：

50aced00057722 9c4cdbcfdd205cf8 8304129e 0000015f43 47bba0

以蓝色突出显示的部分（47bba0）是动态变化的，但是它们的值可以从服务器先前返回的响应数据包中提取出来。以橙色突出显示的部分（9c4cdbcfdd205cf8 ）是当服务器启动时生成的RMI对象标识符。这个值来自RMI注册服务，它仅在服务器本地进行侦听。如果攻击者可以强制或以其他方式获取到这个8字节的值，那么远程命令执行漏洞就可能实现了。
