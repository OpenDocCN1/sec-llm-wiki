# 修补DoublePulsar支持攻击Windows Embedded系统

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzI0MDY1MDU4MQ==&mid=2247488562&idx=2&sn=b554ca3d736d8210c324b4e55406c96b&chksm=e916c408de614d1e5ce40d59db9f756674b6cc9b6807366a6733907872c9dfa8d45eb4916255&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzI0MDY1MDU4MQ==&mid=2247488562&idx=2&sn=b554ca3d736d8210c324b4e55406c96b&chksm=e916c408de614d1e5ce40d59db9f756674b6cc9b6807366a6733907872c9dfa8d45eb4916255&scene=27#wechat_redirect)

![](../Images/420eebaabdd6d1a2df52ecface4cf38c.png)

在我的一次渗透测试中，我发现了一些受MS17-010漏洞影响的Windows设备。其中一个设备引起了我的注意，因为以前我从未遇到过Windows Embedded操作系统。

![](../Images/7ae32de1b4f6477ca1565d2099338e7f.png)

由于存在MS17-010漏洞，我尝试了相关的Metasploit模块。但是他们都无法工作，并返回一个错误，说明目标操作系统不支持。

![](../Images/b601c4c8b6bf33e91fb2be9dbd45ee75.png)

即使是最新的MS17-010利用模块（exploit / windows / smb / ms17\_010\_psexec）也不起作用。

![](../Images/f8275628c5993a64951dff2c4f16c0a4.png)

这比较奇怪。也许无国界医生的辅助模块是误报。或者，漏洞模块的作者可能忘记了对Windows Embedded操作系统的支持。

![](../Images/a27a7b20212a531e9ce49bc381714b79.png)

为了验证目标是否真的易受攻击，我决定使用MS17-010的原始漏洞利用框架Fuzzbunch。所以我启动了Fuzzbunch，然后使用了SMBTouch。结果表明，目标实际上是存在MS17-010漏洞。

![](../Images/82f1a16ad92d09d25ce75bb032235130.png)

然后我使用了EternalBlue模块，并且漏洞利用成功，后门成功安装在目标上。所以我猜想MSF漏洞模块的作者忘记添加对Windows Embedded系统的支持。

![](../Images/b046379fc0aa1d6ce51bed60368219af.png)

由于后门已经安装完毕，为了获得一个shell，需要做的最后一件事就是使用DoublePulsar注入dll。首先，我生成一个dll文件。

![](../Images/c2ea80e801595e99abd905c41d69beff.png)

然后我使用DoublePulsar将生成的DLL注入到目标主机。但是，它的错误消息是失败\[-\] ERROR unrecognized OS string。我想是因为MSF模块不支持Windows Embedded版本。

![](../Images/bfd5459eabf15a0263d0aa3406c7eff2.png)

在渗透测试结束之前还有几个小时，我决定深入挖掘DoublePulsar。首先，我尝试使用DoublePulsar时搜索了我收到的错误消息。这个字符串在上面的.text部分找到0x0040376C。

![](../Images/a81f5f9d634c69d9d74b93c782355dd1.png)

为了更好地理解DoublePulsar如何结束该错误消息，我决定使用IDA的图形视图来跟踪程序的流程。

![](../Images/58dfe7195c162502ea05fff72a39ae93.png)

从图形视图中可以看出，如果目标机器正在运行Windows 7，它将采用左侧路径，然后继续检测其架构是x86还是x64。如果目标不是Windows 7，它将采用正确的路径并执行其他操作系统检查。由于没有检查Windows Embedded，程序最终输出错误消息\[-\] ERROR unrecognized OS string。

![](../Images/cdfa179e537c7b8360b1f1b36a58dedc.png)

通过进一步分析——Windows 7操作系统检查，我观察到我可以通过修改指令来“强制”程序走左边的路径。jz short loc\_403641jnz short loc\_403641

![](../Images/38a75812f9cd0a32a93081c52799d22e.png)

为此，我去了Edit> Patch program> Change byte。

![](../Images/0358dff2c56e6e7167ce79740fd74047.png)

然后我将值74（JZ的操作码）更改为75（JNZ的操作码）。

![](../Images/2146d525b2b2ba83b71ae25f9683d541.png)

这是修改跳转指令后的样子。

![](../Images/a679847402c2821ba55b34433842de18.png)

然后我通过File> Produce file> Create DIF file ...创建了一个DIF文件。

![](../Images/7ac43b17342fbc99118e69db296eff3b.png)

然后使用@ stalkr\_的脚本（https://stalkr.net/files/ida/idadif.py）来修补修改后的exe文件。

![](../Images/366a390e49477890a772f7284ea3baa4.png)

然后将修改后的Doublepulsar-1.3.1.exe移回原始位置。

![](../Images/7763bca2215b77b34cab75103c8ea1df.png)

使用修改的DoublePulsar，我能够将生成的DLL有效载荷注入到目标主机。

![](../Images/674f0d2e99092e0d13079b90391d6882.png)

并获得了一个SYSTEM权限shell。

![](../Images/5636016e69e16342fff7478de16f4b05.png)

![](../Images/30336af193b69a7423004e67e6cf619c.png)
