基于容器的新型挖矿恶意软件LibMiner攻击Redis服务器

Qualys安全研究团队近日在几个docker实例中发现了一类被称为“LibMiner”的新型恶意软件。LibMiner具有部署和执行加密货币矿机的能力。它使用一种独特的技术在容器和Linux系统中横向移动，能在不受保护的Redis服务器上执行并启动挖矿进程。LibMiner同时还能保护其终端，因此无法对其进行控制。本文将对LibMiner的技术和策略做介绍。

技术细节

下面图1显示了LibMiner的完整执行流程。恶意软件的各种组件都托管在可公开访问的服务器上，包括bash shell脚本、ELF文件、python脚本和一个配置文件。攻击分两个阶段进行：在第一阶段，通过bash shell脚本“ lib_tmp”安装LibMiner，该脚本也用于启动下一阶段和用于挖掘加密货币的加密组件“ glib”。LibMiner会启动其他几个组件，如lib_config_t、sider_t、lib_rook_t等，每个组件在执行期间都用于特定的目的。

图1：LibMiner执行流程

初始感染机制目前尚不清楚，但我们发现了一些设置了ENTRYPOINT节以执行bash shell脚本的容器。Docker的ENTRYPOINT部分在运行时充当docker的初始执行点。它执行图2所示的shell脚本内容。

图2：在Docker Entrypoint执行的Shell脚本

此Shell脚本调度CronJob，在特定时间间隔后执行一组命令。它将重置/ etc / hosts文件中的内容，以解除对攻击者服务器的访问权限。此外，它还利用cURL或Wget等第三方包从攻击者的服务器下载“lib_tmp”文件。

lib_tmp文件是一个shell脚本。它会检查腾讯的云盾(Cloud Aegis)和阿里巴巴的服务器卫士(Server Guard)等安全工具是否存在，杀死进程并删除相关文件。(参考图3)

图3:卸载安全工具的代码片段

它将/etc/resolv.conf中的名称服务器更新为Google的公共DNS，还会杀死与自身相关的进程，并从攻击者的服务器下载最新的“ lib”二进制文件，即LibMiner恶意软件，该恶意软件以4个字符的随机名称保存在/ var / lib目录中。

LibMiner是一个ELF恶意软件组件，用UPX打包的。该二进制文件中的例程以无限循环执行，并从攻击者的服务器中获取多个文件，如上图1所示。在这些文件中，非ELF组件包含以明文形式检索的编码内容，方法是应用“ -3”（减3）作为其关键字的Caesar Cipher（凯撒加密），然后进行Base64解码。

LibMiner组件

在本节中，我们将深入了解这些组件，并详细介绍它们在LibMiner执行过程中的作用:

· lib_rook_t / lib_kill_t: LibMiner的清理模块

LibMiner的执行是通过获取、解码和执行这些bash shell脚本来启动的。该脚本负责清除恶意软件执行的所有早期痕迹。为此，它完成以下任务：

1.枚举进程名称并杀死与此矿机关联的进程

2.终止网络连接以获取IP地址和端口的预定义列表

图4：lib_rook_t和lib_kill_t中的已解码代码

· lib_boot_t：LibMiner的提权和持久性

此组件由LibMiner中的Boot_Monitor()例程下载，解码数据是一个shell脚本(图5)，该脚本负责下载LibMiner文件的最新副本，将其随机保存在/tmp文件夹中并执行。

图5：lib_boot_t中的解码代码段

该文件也被复制为/etc/init.d/symcfget。下面的图6显示了为持久性创建服务“ symcfget”的代码的反汇编。该服务执行文件/ usr / bin / symcfget。

图6：创建服务“ symcfget”

· lib_config_t和glib：LibMiner的有效负载——XMRIG Miner及其配置

lib_config_t和glib这两个组件由LibMiner中的Down_Miner()例程下载。Glib是有效负载XMRIG二进制文件，用于在受感染的系统上挖矿。lib_config_t组件中的已解码数据包括矿池和钱包地址。在执行XMRIG二进制文件时，这些信息作为参数传递。矿机使用的钱包地址为：“41mu5eumztbmauwjpxay1auz9sgj4xvr67zrcxtg8rbo9usnrwscrmdynpkm5aewxhzuwxceq3dah62htjagahcogm”并连接到“pool[.]minexmr[.]com: 443“矿池。截至2020年1月，与该钱包地址相关的过去6个月的总收入高达40.41 XMR，价值约为2,146美元。

· sider_t：使用Redis进行横向运动

此组件由LibMiner中的Redis()例程下载。该组件中的已解码数据是一个python脚本，负责以未保护模式运行Redis的容器为目标，并使用LibMiner对其进行感染。

该脚本使用ifconfig获取容器IP地址，并使用图7中的代码段准备目标IP列表。下面的代码强制执行IP地址中的最后两个部分，从而扩大了从暴露端口6379的docker容器到Linux系统的暴露端口6379的感染范围。

图7：准备目标IP列表的代码段

对于IP列表中的每个IP地址，它将尝试在端口6379上创建远程连接，该端口是Redis服务器的默认侦听端口。成功建立连接后将远程执行下面图8所示的代码。它将bash shell内容作为值存储在Redis的“key-value”条目中，然后配置“ dbfilename”和“ dir”字段。RedisServer的save API将bash shell内容转储到“dbfilename”根目录下的路径/var/spool/ croname，并以类似的方式，将另外两个文件转储为/ var / spool / crontabs / root和/etc/cron.d/root

图8：使用Redis服务器感染Docker容器的代码片段

这里值得注意的一点是，通过Redis转储到上述文件路径的内容与与我们针对此Docker威胁进行分析的起始位置相同。这就是LibMiner打算横向扩展和挖掘加密货币以获得最大收益的方式。在我们的分析和观察中，由于存在Redis DB特定的字节，在远程系统上执行转储cron内容的尝试未能按预期执行。

LibMiner的逃避检测行为

“lib”中的ChangeName()和ChangePid()例程负责维持逃避检测行为。因此，它没有使用任何特殊的组件来掩饰它的执行。ChangePid派生一个子进程，退出父进程，然后使用一个新的PID继续执行。新创建的进程使用不同的名称执行，该名称是从图9所示的预定义文件路径列表中随机选择的。文件路径是列入白名单或真实应用程序的路径。

图9：用于规避的文件路径列表

逃避技术伴随着一些反分析技术，这些反分析技术的协作使得手动识别和终止LibMiner变得更加困难。以下是一些技巧:

· 文件属性设置为不可变，以防止修改或重命名文件操作。

· root控制台的超时非常低。

· 控制台输入的命令不可见。

结论

植入加密矿机的方式可能仍是攻击者最偏好的赚钱方式。攻击者已将重点转移到配置错误且未受保护的Docker容器上，我们预计在未来将会看到这种攻击的广泛使用。

检测与修复

Qualys建议以下安全做法：

· 使用QID 19994：无需使用Qualys Vulnerability Management进行身份验证即可访问Redis服务器，以检测易受攻击的系统。

· 在主机上使用最新的软件包和应用程序。

· 在保护模式下使用Redis DB可以避免来自外部客户端的访问，并应用策略来限制root访问。Qualys能提供容器的安全评估和运行时保护。
