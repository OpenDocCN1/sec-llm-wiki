该线程首先会解密以下信息：

![](../Images/a0a80500e9eb39d2b80f3cd2894f6a18.png)

Darkside勒索软件的版本也被解密，如下所示：

![](../Images/1566badc1bc354e3e92f9931e3edc78f.png)

然后，该软件将解密另一个JSON结构，将用于收集本地机器的数据：

![](../Images/c53b01785ce6f0eb4339b6214f268473.png)

之后，该进程会检查驱动器的类型，并寻找DRIVE\_REMOVABLE（0x2）、DRIVE\_FIXED（0x3）和DRIVE\_REMOTE（0x4）：

![](../Images/617594334b539490f11e399e701f2a2d.png)

GetDiskFreeSpaceExW函数用于检索目标驱动器的信息，如存储容量和可用空间：

![](../Images/56b3af37403dc23d73a3182884897408.png)

NtDuplicateToken被用来复制一个现有的令牌，并获得一个新的访问令牌的句柄（0xC = TOKEN\_DUPLICATE | TOKEN\_IMPERSONATE | TOKEN\_QUERY 和 0x2 = TokenImpersonation）： 

![](../Images/16f902637700df2ad06f35121a4dafc3.png)

然后，通过调用ZwSetInformationThread例程来修改线程的模拟令牌，如图所示（0x5 = ThreadImpersonationToken）：

![](../Images/e66dc0dd43f8e2f4eb0ec108eddf8c6e.png)

同时，该勒索软件还会检索与当前线程相关的用户名，以及本地机器的NetBIOS名称：

![](../Images/c0b86ecf555e9d36d2e4f008ed6049fb.png)

![](../Images/ed5270c89a20dcfeb8f8d5b2fd8a8543.png)

另外，机器的当前语言是从“LocaleName”值中检索的，如下图所示：

![](../Images/d03791a3db7d28e392e18fc919a19f74.png)

NetGetJoinInformation用于获取本地计算机的联接状态信息：

![](../Images/2abb0470ad1f02eea1478c64d8e9bb67.png)

通过查询“ProductName”值可以提取Windows的产品名称，通过查询“ProductID”值可以提取Windows产品ID，具体如下图所示：

![](../Images/ba5882a4d8e50924dc238ec3fb93ebed.png)

![](../Images/d8ef376f262764e91982c0cf6f8bd818.png)

该恶意软件构造了以下JSON，其中包含要传输给C2服务器的数据：

![](../Images/606033a2660ea25748408f526ac4a7d1.png)

最终数据如下JSON格式所示：

![](../Images/47dcfd649814a05da3137060ffb39317.png)

上面的数据将通过自定义加密算法进行加密：

![](../Images/702344755bb75f98a0a47c6f4e9c21f1.png)

![](../Images/f20dcdb6558a3dc3094fb231b6e2ab7e.png)

加密运算的结果是base64编码的，如下所示：

![](../Images/692b62f434d30393e8defea495dbc6c4.png)

![](../Images/9c6dcdcf29144b1827807a7d323c9952.png)

下面的函数用于生成2个随机的4字节值，这些值将用于网络通信。实际上，该恶意软件是使用诸如RDRAND和RDSEED之类的指令来生成随机数（如果支持的话）的，我们将下文对其进行更深入的解读（它也用于生成Salsa20矩阵）：

![](../Images/6b7851f541700f259966b7ebc68f43ee.png)

网络请求的参数具有以下结构:random\_number1=base64(encryptionresult)&random\_number2=visit\_uid：

![](../Images/8a297df82d09084278e89485b46309e6.png)

InternetOpenW函数是使用恶意软件解密的用户代理作为参数调用的：

![](../Images/bb731789791da8e96208849cf3643204.png)

InternetConnectW用于连接到端口443上的一个C2服务器(Baroquetees\[.\]com)：

![](../Images/6e7545c749b1b725dc893c30d6b71616.png)

然后使用HttpPopenRequestW例程创建HTTP请求句柄，如图所示：

![](../Images/09fe6784d567547eadd1f77f21175642.png)

此外，这里还有一个对InternetSetOptionW API的调用，该API用于设置句柄的安全标志(0x1f=INTERNET\_OPTION\_SECURITY\_FLAGS)：

![](../Images/7d5964ac2ec21426a11112d8644956f5.png)

然后，该恶意软件使用HttpSendRequestW将POST请求发送到C2服务器：

![](../Images/43a356405aee2206bc32d1fb883ddffd.png)

![](../Images/f557bed53b5c0b143aec1458dd4940f5.png)

服务器返回的状态代码可以使用HttpQueryInfoW API进行检索(0x13=HTTP\_QUERY\_STATUS\_CODE):

![](../Images/7f25abc2461d66f901d54498ee629358.png)

有趣的是，该勒索软件预期的并不是200状态代码，而是500（内部服务器错误）。如果状态代码不是500，它将使用第二个C2服务器Rumahsia\[.\]com，并重复上述所有步骤：

![](../Images/fffabdd84fe47f6ac0c68116fdad9e08.png)

![](../Images/9aa498701496b570c81a34125dcf7955.png)

接下来，我们继续分析主线程。

这个二进制程序将遍历机器上可用的卷，并使用CreateFileW例程来打开它们：

![](../Images/af6dc73461ad485eabbdc8941233bf2b.png)

DeviceIoControl被用来获取关于磁盘分区的类型、大小和性质方面的信息（0x70048 = IOCTL\_DISK\_GET\_PARTITION\_INFO\_EX）：

![](../Images/85acf0da2c50eea2016ce73d504d6b19.png)

然后，使用CreateThread创建了一个新的线程：

![](../Images/be896e341033e294e3cf8bb6ccd7a888.png)

![](../Images/902da532fc8a52f6aed9f24aabf046ed.png)       线程活动：sub\_407558

该线程做的唯一活动是使用GetLogicalDriveStringsW API来检索本地机器上的有效驱动器：

![](../Images/0936f76585e1e7c927901599a38e2462.png)

如果卷没有与其相关联的驱动器号，那么该勒索软件就会调用SetVolumeMountPointW API，如下图所示：

![](../Images/fd317b4d4699a73c703e4c4e29402857.png)

该恶意程序的目标位以下类型的驱动器：DRIVE\_REMOVABLE（0x2）、DRIVE\_FIXED（0x3）和DRIVE\_REMOTE（0x4）：

![](../Images/8eb62cd75fc1eebb8c38582647a06f20.png)

CreateFileMappingW函数被用来创建一个命名的文件映射对象（名称为“Local\\job0-< Process Id>”则意味着该对象是在会话命名空间中创建的）：

![](../Images/51f4c35d3b1b25621c136a2cc5dd37ab.png)

然后，通过调用MapViewOfFile例程(0xF001F=FILE\_MAP\_ALL\_ACCESS)，将文件映射的视图映射到进程的地址空间：

![](../Images/64db83d97e4d9f9db4f4fd825e279507.png)

同时，它还会创建名为“local\\\\job0-< process id >-event”的命名事件对象：

![](../Images/64db83d97e4d9f9db4f4fd825e279507.png)

该勒索软件利用3个参数启动自己，新进程将执行相应的加密操作：

![](../Images/3a6b1146d13f300666712b68a01d3eab.png)

OpenMutexW用于打开名为“global\\\\t-job0-< process id >”的命名互斥锁（目前不存在）：

![](../Images/fcc79b3e54aa97aef9a4337beb666836.png)

通过调用OpenEventW API(0x1F0003=EVENT\_ALL\_ACCESS)打开前面创建的事件对象，如图所示：

![](../Images/70b25433258f8df396ca1f6e05abeb3b.png)

之后，它将创建一个与文件句柄无关的I/O完成端口，主线程将使用该端口向辅助线程发送待加密的数据：

![](../Images/ed1306554773a5a5279025b7936d6db4.png)

使用CreateThread例程创建了两个不同的线程来处理文件的加密任务：

![](../Images/32004f1a879a965bf3382205b8682065.png)

创建用于赎金说明的README< RansomPseudoValue >.TXT文件，并填充到恶意软件加密的每个目录中：

![](../Images/90a60fd2cac52f412c892128d3a48de0.png)

不过，该进程会避免加密某些特定文件，如下图所示：

![](../Images/768d488c8e9e0fe1bcf565beb40a9bc5.png)

对于扩展名包含在前面解密的文件扩展名列表中的文件，也不会被加密：

![](../Images/e9f21c170ca65e0a32958129b0e726b1.png)

使用CreateFileW和ReadFile函数打开和读取每个目标文件：

![](../Images/3423f7385925e665753de47013da5c92.png)

![](../Images/9fa77abc1848300a1f2f3a52d9e5792f.png)

修改文件扩展名，使其包括< ransompseudovalue >，如下所示：

![](../Images/b5beb1bd241c4bcbf5f5c92c4106ae59.png)

同时，还会调用CreateIoCompletionPort函数，将现有的I/O完成端口与FileHandle参数相关联：

![](../Images/86c4ef71c04b2e562321afcd2feae216.png)

RSA公开指数和RSA模将用于Salsa20矩阵的加密过程，我们将在后面介绍：

![](../Images/603c6f6c5b05f61651080c4ad1f4e7fb.png)

该勒索软件会检查处理器是否支持RDRAND和RDSEED指令。如果支持的话，它将使用其中一个指令来生成56个随机字节，并将8个NULL字节添加到生成的缓冲区中。如果这些指令都不支持的话，该恶意软件将使用rdtsc指令生成确定性的时间戳，以用于提供一个64字节的Salsa20矩阵。

![](../Images/bcb9e730ce6c79683ede6e6f95e2acd9.png)

![](../Images/c46a9c1c2529384fc82d5ced5ccc42ea.png)

该线程给出了RSA-1024算法的自定义实现（它不依赖于Windows API）。简单说，就是数据d通过公式（d^exponent）%modulus来生成相应的密文。原始模数的计算是使用加法和减法进行的，下面显示的是部分实现代码：

![](../Images/19ca0e948140574028cb2267af62b934.png)

![](../Images/6446ac730bdddc7555426f3c72496b4e.png)

![](../Images/aabdd1ad6d378e735ae0d34df6749b7e.png)

![](../Images/6f368362ce719bb0da89200fd7ef62c4.png)

将被加密的文件内容追加到将发送到工作线程的缓冲区中：

![](../Images/3af48e0023ba6b425fd288f8c0366ece.png)

Salsa20矩阵也被添加到缓冲区中，它将被工作线程用来加密文件：

正如我们在分析开始时所指出的那样，这个二进制程序可以用不同的参数运行：

◼1个参数：filename，表示只对指定的文件进行加密

◼2个参数：“-path” directory，表示只对指定的目录进行加密

◼3个参数：“-work”worker0job0-< process id >，这是由初始进程产生的，前面已经讲过了

在处理快捷方式文件（.lnk文件）时，该勒索软件会以不同的方式处理不同的情况。简单来说，它希望从这个链接中提取文件的完整路径。为此，它会使用{000214F9-0000-0000-C000-0000000046}（IShellLinkW接口）的CLSID来调用CoCreateInstance API：
