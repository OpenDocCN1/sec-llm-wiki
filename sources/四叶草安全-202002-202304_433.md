# Ripple20 漏洞曝光，影响全球数亿设备

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MjM5MTI2NDQzNg==&mid=2654528568&idx=1&sn=94352699eeff8c25fc61ad8658a27678&chksm=bd747fe38a03f6f5bace56c92eee7c10fa2e9ec74775aca435896aae1d63583ff2f3a78e646c&scene=126&sessionid=1681375096#rd](http://mp.weixin.qq.com/s?__biz=MjM5MTI2NDQzNg==&mid=2654528568&idx=1&sn=94352699eeff8c25fc61ad8658a27678&chksm=bd747fe38a03f6f5bace56c92eee7c10fa2e9ec74775aca435896aae1d63583ff2f3a78e646c&scene=126&sessionid=1681375096#rd)

![](../Images/b9ae547d49c1c576fa4ed326d9ccb1b3.png)

近期，位于以色列的一家专门从事物联网和嵌入式设备安全的JSOF公司，针对Treck TCP/IP协议栈进行安全研究，发现了一系列安全问题。这些安全问题可能导致敏感信息泄露和远程代码执行。 

Treck一直专注于设计、分发和支持实时嵌入式系统的Internet协议。Treck TCP /IP协议栈是专为嵌入式系统而设计的高性能协议栈，广泛应用于嵌入式设备和物联网设备。 

受到供应链的影响，该协议栈大量组织制造的设备中，应用范围包括工业、医疗、智能家居、企业、零售、能源和运输系统等不同行业和其他关键基础设施。因此，大量关键基础设施都会受到该系列漏洞的影响，暴露在危险之下。

当处理数据包的时候，程序会按照协议对数据包层层剥离并处理。当协议处理分片时，会使用 tsUserPacket 中的 pktuLinkNextPtr 指针进行链接作为链表，如下图所示。

程序会对收到的数据包进行相关的检验：

![](../Images/1977d6c10b3fa4ae1f40c349777cb474.png)

其中 data\_available 使用 pktuChainDataLength 进行计算。当 total\_length<= data\_available 为真时，表明实际收到的数据比宣称的要多，于是会进行下面的删减操作：

![](../Images/0556bf971209d3a48cea3c94743d0846.png)

当函数 tfIpIncomingPacket 处理内部IP数据包时，会处理进入的分片数据。内部IP数据包通过了IP标 头完整性检查，因为仅考虑了 tsUserPacket 的 pktuChainDataLength 字段，而没有考虑 pktuLinkDataLength 。内部IP数据包的总长度（32）小于链数据长度（1000 + 8 + 20 = 1028），因 此Treck协议栈将尝试不正确地截断数据包，方法是将字段 pktuLinkDataLength 和pktuChainDataLength 设置为相同的值，即IP总长度(示例中为32)。这导致由链接在一起的两个 tsPacket 结构的内部IP数据包的总长度为40字节，这就大于了 pktuChainDataLength 字段的32字节。

![](../Images/16071618e56157b8c5136b21b57d66ad.png)

![](../Images/8d974abf84aa912cb6958342295fd6b6.png)

其中有个关键函数 tfGetSharedBuffer ，这个函数负责分配一个新的数据包，然后将数据包的不同片 段复制到新分配的数据包中。负责执行复制功能的函数是 tfCopyPacket 函数，如下：

![](../Images/da2a95dac49a1c5fdaca37351da1488a.png)

可以看出，函数 tfCopyPacket 没有考虑到它写入缓冲区的长度。

最终，我们得出结论，如果受影响的设备上有一个UDP端口在监听，且UDP数据包接收队列为空，并以 足够快的速度将多个UDP数据包发送到同一端口。则在到达发生溢出的位置 tfSocketIncomingPacket 之前，数据包会经过 tfUdpIncomingPacket 进行与UDP相关的安全性检 查。确保UDP长度字段等于 pktuChainDataLength 字段减去内部IP报头的大小，再发送一个UDP分片 数据包即可触发漏洞。
