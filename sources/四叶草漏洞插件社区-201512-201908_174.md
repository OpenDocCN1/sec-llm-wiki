**题目内容：“BugScan Chaos Memos ”**  

 

首先打开题目地址，发现是一个备忘录系统，开始的时候找不到突破点，群里各种xss都被玩坏了。

![](../Images/42637a4424e6ced15944ef7246d50bc3.png)打开微信发的那篇活动文章，有提示，有关老司机技能，顺便查看了一下网页源代码。  

 ![](../Images/1184c020a817d0de698cc2a63c0dfe6b.png)  
![](../Images/70b5c41f1f2e0d4b8f3e88a39d42802e.png)  
这个时候 tips更新了，说flag在服务器里，那么肯定就是要入侵服务器了，那么第一步，首先要确定是到底是什么鬼CMS和什么鬼运行环境了。memoshow.phpmemoedit.aspmemodeleteconfirm.jsp又是 .php， 又是 .asp 的，还有 .jsp, .aspx。随便输入一个地址看报错页面：![](../Images/ee5a9bb3756f8301e4ac6fe6cee34314.png)  
果真都是套路啊！经典的误导。利用排除法，首先排除asp和php ，因为后缀伪造方面这两个语言很难伪造。剩下的jsp和 django，知道bugscan的人都会django，首先测试了django的常见漏洞http://target/../../../../etc/passwd首先打开 Bugscan 开发工具包 打开里面的burp ![](../Images/522f42581d800caa0e00c7ae66cde806.png)  
然后使用 Repeater 模块![](../Images/f387328b7d9c191666c622be013caae3.png)  
发现并没有什么鸟用。这个时候 群里404发了张 ognl console的图  ![](../Images/a160a6dde5184798090fce054b136af8.png)  
那应该就是 tomcat容器了，然而这个时候 ![](../Images/c3da55a0a92519bef841006f88699d1d.png)  

不流畅突然紧张了,哈哈(现在想想可能是因为巧合，这不巧了了这不是)

并且 Burp里面有个细节

![](../Images/2d874e50d19aa131376155fc528d5d7c.png)  

jsessionid是jsp的session使用存储方式, nginx是前端反代容器。

那么确定无疑，肯定是 tomcat了。

 

突破口应该在tomcat了，之前对服务器的端口进行了扫描 ，只开了22 和80端口。22端口返回的是sshd的信息，服务器是Linux

结合着网页上面提示信息“关注最近热门漏洞”，Java系最近爆了两个高危漏洞： 

S2-033  Remote Code Execution can be performed when using REST Plugin with ! operator when Dynamic Method Invocation is enabled.

s2-032  Remote Code Execution can be performed via method: prefix when Dynamic Method Invocation is enabled. 

而且这个 UI，跟 struts2 测试站点里面 struts2-rest-showcase 是一模一样。s2-033 的 exp 现在还没一个好用的软件，不过 s2-032 已经有了。打开 https://www.exploit-db.com/webapps/

有个细节，不知道这算不算提示。

![](../Images/9d87d1de92e9f17b08da69399c914180.png)  

抄起K8

![](../Images/b76b4eb3b8901b7f9d22e26b7b048cfe.png)  

哈哈，果真有漏洞！

然而套路不仅仅这么简单

看到nt\_authority\_system ，习惯性的敲了几个windows下的命令，然而都没有执行成功，想了想应该是linux啊，试了几个Linux果断可以
