# 哨兵小科普丨工控系统防止SQL Injection的建议

     目前在工控系统中像PLM、EMS/MOM、SCADA等工业软件采用B/S架构的应用越来越多，因为B/S在安装部署、升级维护、设备带宽、软件成本等方面都有无可比拟的优势；有优点固然也有缺点其一就是SQL Injection的安全风险。

SQL注入攻击(SQL Injection)指的是通过构建特殊的输入作为参数传入Web应用程序，而这些输入大都是SQL语法里的一些组合，通过执行SQL语句进而执行攻击者所要的操作，其主要原因是程序没有细致地过滤用户输入的数据，致使非法数据侵入系统。

  

![](../Images/6394222fc0d9ec3f0df8aa53475aabde.png)

危害性很大，数据是一个系统的核心，尤其涉及一些敏感信息，如生产核心数据的泄露，设备数据的篡改等。涉及敏感信息的web网站必须做好防御SQL注入的工作。

**SQL注入的产生原因通常表现在以下几方面**：

  

不当的类型处理；

  

不安全的数据库配置；

  

不合理的查询集处理；

  

不当的错误处理；

  

转义字符处理不合适；

  

多个提交处理不当。

  

**情景分析**

在工控系统中曾今出现过很多经典案例，根据乌云主站的漏洞库显示包括有天津鑫然智能DCS监控平台、中华工控网SQL注入导致全网数据沦陷90W会员数据、哈药集团分公司sql注入(影响大量同服网站数据库)、天津鑫然智能DCS监控平台等SQL注入事件。

  

![](../Images/f6491dff4975b85f12deba3ac9309974.png)

  

SQL注入式攻击的主要形式有两种。一是直接将代码插入到与SQL命令串联在一起并使得其以执行的用户输入变量；由于其直接与SQL语句捆绑，故也被称为直接注入式攻击法。二是一种间接的攻击方法，它将恶意代码注入要在表中存储或者作为原数据存储的字符串。在存储的字符串中会连接到一个动态的SQL命令中，以执行一些恶意的SQL代码。

  

**防止SQL注入**

1、永远不要信任用户的输入。对用户的输入进行校验，可以通过正则表达式，或限制长度；对单引号和双"-"进行转换等。

  

检查特殊字符

![](../Images/9427b732a5aae8ce4f3cc7b4f043f4c4.png)

![](../Images/433ddc6bf3fbedd318e5b88c57eb87ca.png)

  

  

2、永远不要使用动态拼装sql，可以使用参数化的sql或者直接使用存储过程进行数据查询存取。（不要拼sql，使用参数化）

不要使用动态拼装sql，可以使用参数化的sql或者直接使用存储过程进行数据查询存取。（不要拼sql，使用参数化）

![](../Images/2f0cb1b92e45a1478a95713a2f0829de.png)

  

  

3、永远不要使用管理员权限的数据库连接，为每个应用使用单独的权限有限的数据库连接。（给程序分配合理的数据库操作权限）

![](../Images/48862549228bf1762a1ef0b530186d2a.png)

  

  

4、不要把机密信息直接存放，加密或者hash掉密码和敏感的信息。（敏感信息加密）

![](../Images/1be25543d84c6134ea5427b71efd7422.png)

  

  

5、应用的异常信息应该给出尽可能少的提示，最好使用自定义的错误信息对原始错误信息进行包装。

![](../Images/8c7ad838ab8c67f7d6b3620bced3bd96.png)
