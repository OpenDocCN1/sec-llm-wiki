# 新兴命令与控制框架Sliver的狩猎研究

> **关键词**

> C2框架、Sliver、威胁狩猎

微软观察到 Sliver 命令和控制 (C2) 框架正在被民族国家威胁行为者、直接支持勒索软件和勒索的网络犯罪组织以及其他威胁行为者采用，并集成到入侵活动中来逃避检测。已经看到有威胁行为者将 Sliver 与 Cobalt Strike 一起使用或替代 Cobalt Strike。鉴于 Cobalt Strike 作为一种攻击工具的受欢迎程度，针对它的防御也随着时间的推移而有所改善。因此，Sliver 为那些寻求低门槛、鲜为人知的工具集的参与者提供了一个吸引人的替代方案。Sliver2019年底首次公开，它是一个开源框架，可以在GitHub上获取，包括许多常见的C2框架特性，如支持多个同步操作、多种侦听器类型、用户开发的扩展和有效负载生成。自2020年12月以来，已经观察到有威胁行为者将Sliver纳入他们的武器库。采用者之一是多产的勒索软件即服务 (RaaS) 附属机构 DEV-0237。最近，历史上采用人工操作的勒索软件相关的网络犯罪分子也开始在初始入侵阶段使用 Bumblebee 恶意软件（也称为 COLDTRAIN）投递 Sliver 和各种后威胁工具。本文中，我们分享了 Microsoft Defender Experts for Hunting 研究人员如何分析 Sliver，并通过对实验室模拟的攻击和现实世界威胁活动的分析来实现对Sliver和其他的C2 框架的狩猎。1\. 威胁狩猎：艺术（事实）与科学的结合  
  

对于安全研究人员来说，狩猎和检测是有区别的。对于新的威胁，研究人员试图在识别特定的已知恶意软件系列、威胁参与者或行为类别的高保真检测规则和低保真狩猎规则之间取得平衡，这会产生更多误报，但会捕获到新技术及其衍生物。

接下来部分说明了这些低保真规则如何帮助威胁猎手衡量可疑观察并将其置于情境中，以发现新的或隐秘的威胁的艺术和科学。

**(1)Sliver侦查**威胁行为者在入侵期间使用 C2 框架来管理对受感染主机和网络的访问。C2 框架通常包括一个接受来自受感染系统上的植入物的连接的服务器，以及一个允许 C2 操作员与植入物交互并启动恶意命令的客户端应用程序。许多威胁行为者将公开的开源 C2 框架选项集成到他们的武器库中，因为这些选项的进入门槛低，并且为攻击者提供了一些例如低成本、易于修改和难以归因的优势。 如前文所述，Sliver 就是这样一种开源框架。尽管 Sliver 有点新，但它实现的 TTPs 在许多框架中都很常见。以下是 Defender 专家如何寻找这些 TTP 以识别客户环境中的 Sliver 和其他新兴 C2 框架的示例。**(2)基础结构**Sliver 与许多 C2 框架一样，支持各种网络协议，如 DNS、HTTP/TLS、MTLS 和 TCP。它还可以模拟合法Web服务器接收来自植入物或操作人员的连接和托管文件。测试任何 C2 框架的第一步都是启动监听器，同时扫描它们来识别异常。一些常见的工件是唯一的 HTTP 标头组合和 JARM 哈希，后者是 TLS 服务器的主动指纹技术。RiskIQ 分享了这种用于 Sliver 和 Bumblebee 检测的方法。

**(3)有效负载**

由于 Sliver 是用 Go 编程语言 (GoLang) 编写的，因此它的植入程序是跨平台兼容的。默认情况下，操作员可以生成多种格式的植入物，包括：

*   Shellcode
    
*   Executable
    
*   Shared library/DLL
    
*   Service
    

Sliver 还支持 stagers——具有少量内置功能的较小有效负载，主要用于获取和启动完整的植入物。许多 C2 框架使用 stagers 来最大限度地减少初始负载中包含的恶意代码（例如，在网络钓鱼电子邮件中）。这会使基于文件的检测更具挑战性。

但是，操作人员不需要使用 Sliver 的默认 DLL 或可执行程序负载。威胁参与者可以生成一个 Sliver shellcode，并将其嵌入到 Bumblebee 等自定义加载程序中，然后在受感染的系统上运行 Sliver 植入程序。检测工程师可以创建特定用于加载程序的检测规则，或者如果 shellcode 没有被混淆，则可以为嵌入在加载程序中的 shellcode 有效负载创建检测规则。

**(4)配置提取**

在响应可疑入侵时，安全分析师可能会发现自己几乎没有恶意软件负载的上下文信息。从恶意软件中快速提取关键配置细节，如 C2 地址、网络配置和其他植入细节，是在网络中寻找受影响设备的关键步骤。

包括 Sliver在内的许多植入物，严重混淆或加密了有用信息用来延长分析和检测尝试。Sliver 和其他基于 GoLang 的植入程序一样，使用公共 gobfuscate 库来达到此目的。一些研究人员已经创建了工具来帮助“去混淆”有效载荷中的字符串，但是这仍然是一个需要相当多手动操作的过程。

在这种情况下，我们可以在加载到内存时更轻松地提取我们感兴趣的配置。Sliver 必须对它的配置进行去混淆和解密才能使用它们，因此我们可以扫描内存来查找这些值，同时以编程方式提取它们以获得类似配置数据的结果，如下图 1 所示：

图1：从 Sliver 测试植入物中提取样本配置

Cobalt Strike 也有类似的公共反混淆工具，例如 Apr4h/CobaltStrikeScan 和 CCob/BeaconEye。一些恶意软件也会尝试混淆或加密内存中的配置。Cobalt Strike 的“sleep\_mask”就是一个很好的例子。但是，重要的是要注意，即使在这些情况下，恶意软件在想要与 C2 服务器签入以获取新指令时也必须解密配置。**(5)代码执行**Sliver 包括各种内置技术和后期开发功能。进程注入是C2框架使用的最常见的底层技术之一，也是一种在单独的实时进程的地址空间内运行任意代码的方法。攻击者将进程注入用于防御规避、访问或特权提升、避开有风险的代码执行等。正如微软研究人员解释的那样：“进程注入使攻击者能够运行伪装成合法程序的恶意代码。通过代码注入，攻击者不必使用可以快速检测到的自定义进程。相反地，他们将恶意代码插入到常见的受信任进程（例如 explorer.exe、regsvr32.exe、svchost.exe 等）中，从而提高了操作的隐蔽性和持久性。”下面的图 2 说明了进程注入通常是如何工作的：

![](../Images/da8a398444471f699db130619c094d49.png)

图2：进程注入的工作原理图

像其他的C2 框架一样，Sliver 将进程注入作为许多默认命令或功能的核心部分，例如：

*   migrate (command) – migrate into a remote process
*   spawndll (command) – load and run a reflective DLL in a remote process
*   sideload (command) – load and run a shared object (shared library/DLL) in a remote process
*   msf-inject (command) – inject a Metasploit Framework payload into a process
*   execute-assembly (command) – load and run a .NET assembly in a child process
*   getsystem (command) – spawn a new Sliver session as the *NT AUTHORITY\\SYSTEM* user
*   extensions/aliases – Beacon Object Files (BOFs), .NET apps, and other third-party tooling

Sliver 还使用常见的进程注入实现手段。例如，在撰写本文时，Sliver内置的迁移命令使用VirtualAllocEx、WriteProcessMemory、VirtualProtectEx和CreateRemoteThread Windows API 调用的经典组合迁移到远程进程。Sideload、SpawnDll 和 Execute-Assembly 等其他命令也依赖于这种组合。这一系列与注入相关的 API调用有说明文档的，Microsoft Defender for Endpoint 会根据此类 API 调用的组合生成警报，例如一个进程被注入了潜在的恶意代码：

图3：与注入相关的 API 调用的 Microsoft Defender for Endpoint 警报示例

**(6)Surfacing Sliver威胁活动**

基于对 Sliver 框架的分析，Defender Experts 设计了高级狩猎查询来发现与 Sliver 相关的威胁活动。这些狩猎查询利用了一种专门设计的用于处理 Azure 中的大型数据集的查询语言 (KQL)。 除非另有说明，否则本篇中的检测和狩猎指南是为撰写本文时可用的官方非定制 Sliver 代码库而设计的。

**(7)GetSystem**

以下查询查找内置 GetSystem 命令的潜在启动，其中 spoolsv.exe 的默认目标进程用作注入的目标进程。该查询查找要添加到进程的 SeDebug 权限，然后是30秒内同一进程在spoolsv.exe中创建一个远程线程。

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   

```
// SeDebugPrivilege constant used to identify if this privilege is enabled in Tokenlet SeDebugPriv = 1048576;DeviceEvents| where FileName == 'spoolsv.exe'| where ActionType == 'CreateRemoteThreadApiCall'| where InitiatingProcessFileName !~ 'csrss.exe'| project InitiatingProcessId, DeviceId, CreateTime=Timestamp, FileName| join kind=inner (    DeviceEvents    | where ActionType == 'ProcessPrimaryTokenModified'    | extend TokenModTime = Timestamp  ) on DeviceId, InitiatingProcessId| where TokenModTime between ((CreateTime - 30s) .. CreateTime)| extend JSON=parse_json(AdditionalFields)// This line looks for SeDebugPrivilege being the ONLY privilege changed, which is how it is implemented in Sliver| where binary_xor(tolong(JSON.OriginalTokenPrivEnabled),tolong(JSON.CurrentTokenPrivEnabled)) == SeDebugPriv// Optionally comment out the above and use this line, which is more generic and simply checks for SeDebugPrivilege not being initially enabled//| where binary_and(tolong(JSON.OriginalTokenPrivEnabled), SeDebugPriv) == 0| where binary_and(tolong(JSON.CurrentTokenPrivEnabled), SeDebugPriv) != 0 // Confirming SeDebugPrivilege is enabled in Current Token| extend TargetProcessFileName=FileName| project-reorder DeviceName, InitiatingProcessFileName, TargetProcessFileName, InitiatingProcessId
```

**(9)Sideload/SpawnDll/Execute-Assembly**

Sideload、SpawnDll 和 Execute-Assembly 命令默认生成并注入到 notepad.exe。以下查询查找同一进程在 10 秒内创建并注入 notepad.exe 的进程创建事件。

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   

```
DeviceProcessEvents| where ActionType == 'ProcessCreated'| where ProcessCommandLine =~ 'notepad.exe'| distinct InitiatingProcessId, DeviceId| join kind=inner (    DeviceEvents    | where ActionType == 'CreateRemoteThreadApiCall'    | where ProcessCommandLine == 'notepad.exe'    | where Timestamp between (ProcessCreationTime .. (ProcessCreationTime+10s))) on DeviceId, InitiatingProcessId
```

**(10)PsExec**以下查询查找使用 Sliver 的 PsExec 命令时安装在远程系统上的服务的 ImagePath、DisplayName 和 Description 的默认值。

*   
*   
*   
*   
*   

```
DeviceRegistryEvents| where ActionType == 'RegistryValueSet'| where (RegistryValueName == 'ImagePath' and RegistryValueData matches regex @'^[a-zA-Z]:\\windows\\temp\\[a-zA-Z0-9]{10}\.exe') or        (RegistryValueName == 'DisplayName' and RegistryValueData == 'Sliver') or         (RegistryValueName == 'Description' and RegistryValueData == 'Sliver implant')
```

以下查询是在服务安装事件而不是注册表项中搜索相同服务属性的另一种方法。


2. 通过威胁狩猎建立抵御未来攻击的能力  
  

对 Sliver 源代码和功能的分析揭示了狩猎思路，这些思路也适用于其他恶意软件框架。此外，Sliver 和许多其他 C2 框架是威胁行为者不断尝试如何逃避自动安全检测的又一个例子。威胁狩猎为其他安全缓解措施提供了一个附加层，可以帮助解决防御规避领域的问题。通过将研究工作集中在 Sliver 中使用的底层攻击技术上，检测和威胁狩猎策略对未来实施这些技术的攻击者工具集的变化更具弹性。
