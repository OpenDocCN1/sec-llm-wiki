01

简介


2019年，F-Secure在调查一起针对加密货币公司(以下简称“目标”)的攻击时，发现了有关拉撒路组织(Lazarus Group)[1]作案手法的技术细节。这次攻击与一场正在进行更为广泛的全球网络钓鱼活动有关。本报告中的内容，将为蓝队防止他们的组织被拉撒路组织攻击，提供检测方式。

根据2019年联合国的一份报告[2]，拉撒路组织至少从2017年开始就把目标对准了加密货币公司。与对该组织活动的公开报告一致，F-Secure发现其攻击的主要目的是获取经济利益。

根据所观察到的恶意软件、策略、技术、流程（TTPs）的相似性以及该组织活动的其他情报，F-Secure认为该攻击者是拉撒路组织。F-Secure在对恶意软件的分析中表明，其与其他拉撒路组织活动中的样本具有高度的相似性，Kaspersky[3]和ESET[4]在先前发表的研究中对此进行了详细介绍，发现拉撒路组织结合自定义恶意软件和本机系统（OS）组件来攻击其目标。

调查发现，为了避免被发现以及能够及时清除他们活动的证据，拉撒路组织在安全操作上投入了大量时间。在F-Secure的调查之前，拉撒路组织试图通过删除工具和日志数据来清除其在目标上的证据。然而，有些样本是可以检索的，还有一些可以通过目标的终端检测和响应（EDR）方案自动捕获。

F-Secure评估了攻击目标，发现这一活动与至少自2018年1月以来的全球网络钓鱼活动有关系。通过从调查样本、开放源代码存储库和专有情报资源中的IOC指标，发现这次攻击与一系列更为广泛的活动有关。本报告的正文和附录中都包含有这些证据，如果可能的话，安全行业可以充分利用这些信息，并得出自己的结论。


02

首次发现


F-Secure的调查显示，目标组织的一名系统管理员在他的LinkedIn帐户收到了网络钓鱼文件。该文件伪装成在区块链科技公司的招聘广告，其招聘的职位与该员工的技能刚好相符。

虽然目标主机上的文件在执行后被修改删除了恶意内容，但F-Secure发现原始文件与VirusTotal[5]上公开提供的样本（请参见下图）或者相同或者相似。这些内容是通过对系统资源管理器（SRUM）中相关执行记录的分析得到的。

03

网络后门植入


拉撒路组织利用了两个独立的网络后门植入，与卡巴斯基在2016年报道[8]首次使用的“被动式后门”类似。F-Secure分析的样本加了Themida的壳，尽管是x64变种，但分析发现其主要代码与2016年使用的x86变种很相似。

后门在执行时需要在命令行上输入一个端口作为参数，并使用Windows netsh实用程序在Windows防火墙中打开该端口。观察发现该植入在TCP端口443、3388、3399、5500和5555上运行；目标网络上记录的活动样本如下所示。

C:\ProgramData\mcc.exe 3388netsh firewall add portopening TCP 3388 Assistance

尽管指令集有所不同，但仍然可以看到他们使用了相同的操作来隐藏控制台窗口，并且在继续运行之前定义了相同的时间等待操作完成和休眠。这些相似之处可以在下面的截图中看到。

图9:网络后门代码的相似性


F-Secure分析的样本还与拉撒路组织在2018年ESET报告[9]中针对赌场攻击所使用的“TCP后门”具有相似之处。解压缩后的“mmc.exe”（f8915227c25c5ac552d66f3708f615cd517363953829d3715f38666d7dfa9770）样本与ESET报告（8b6887c5ec6fadaefee78f089e9a347a539bceff49f8948394）中的其中一个VMProtect脱壳后的样本相同。图10展示了，三次攻击中植入的不同样本，脱壳后可以看到相同的字符串。

04

自定义PE加载器


F-Secure调查发现了自定义PE加载器 “LSSC.dll”（72e0965385eae2d3a2f20feb361ce542235fe44c08991644a0a231f595039e68）。通过 “HKLM \ SYSTEM \ CurrentControlSet \ Control \ Lsa \ Security Packages”注册表项将文件伪装成“Security Packae” [10]加载到lsass.exe进程中。

F-Secure发现拉撒路组织使用windows中的reg命令在本地修改密钥，并通过相同的实用程序检查是否成功。一旦确认成功，系统将重新启动加载DLL，下面是一些示例。

reg query HKEY_LOCAL_MACHINE\\SYSTEM\\CurrentControlSet\\Control\\Lsa /v Security Packagesreg add HKEY_LOCAL_MACHINE\\SYSTEM\\CurrentControlSet\\Control\\Lsa /v Security Packages /t REG_MULTI_SZ /d lssc /f
reg query HKEY_LOCAL_MACHINE\\SYSTEM\\CurrentControlSet\\Control\\Lsa /v Security Packages
shutdown /t 0 /r /f
在随后的入侵中，拉撒路组织使用schtasks windows实用程序远程修改了此注册表项，如下面的代码片段所示。
cmd.exe /c "schtasks /Create /S <IP ADDRESS> /P <PASSWORD>! /U "<DOMAIN>\<USER> " /TN "MSC" /TR "reg add /"HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\Lsa/" /v /"Security Packages/" /t REG_MULTI_SZ /d /"ldap/" /f" /SC ONSTART /RU SYSTEM /F >C:\Windows\TEMP\TMPD2E6.tmp 2>&1"

所分析的样本在使用之前被编译过，文件的内部名称为“xml.dll”。该文件被放到System32目录中，并且一旦执行就会硬编码对文件“ LDAP.dat”使用自定义PE加载代码。虽无法检索“ LDAP.dat”的副本，但F-Secure认为，它包含最终的有效媒介，其可以让拉撒路组织能够执行其他命令。



05

主要植入


主要的植入程序都具有下载其他文件、解压缩内存中的数据、启动C2通信，执行任意命令以及窃取多来源认证的功能。观察到该植入还被用于连接到其他目标主机上的网络后门植入程序。

“LSSVC.dll”(519f100ddc98cfb9aca3e13c0095bddeadf11c50397096953171d042ca376fbd)被放入System32目录并加载到lsass .exe进程中。分析表明该文件具有以多种方式加载的功能。该植入程序是x64 DLL，包含Zlib 1.2.7和Libcurl 7.47.1软件库，这表明它能够下载和解压其他的数据。

一旦加载了，它将从存储在“%WINDIR%\AppPatch\”中6816字节的“ .sdb”文件中读取并解密配置信息。F-Secure分析的样本专门寻找配置文件名称是“mscmain.sdb” 或 “msomain.sdb”的文件，并使用RC4密钥 “F9 5E 06 0B E3 1B 18 03 24 3F 00 CC DE AB F6 93 1B 2A CB 5B 6A C3 67 36 62 60 EC 82 46 37 D2 4A”解密。该植入还能够加密这些数据并写入磁盘，从而允许拉撒路组织在需要时更新这些信息。“ .sdb”文件包含C2信息以及引用其他恶意文件的硬编码目标特定目录（“ C：\ Users <rededed> \ AppData \ Roaming \ Microsoft \ CLR \”）。然而这个植入程序的“LSSVC.dll”变体，似乎没有与这些文件进行进一步交互的功能。

“NTUSER.cat”(831ba6efa4a49eb1c7ff749fe442b393c5a614f383bf1efb52512a183b4362fc)是另一个类似于“LSSVC.dll”的x64 DLL。但是这个变体被放到了“C:\Users\”目录中，并且没有被设计加载到lsass.exe进程中。

“ NTUSER.cat”使用与“ LSSVC.dll”相同的软件库，并且还从相同的“ .sdb”文件中读取配置信息。但是，此植入程序具有从磁盘加载引用文件并将其注入另一个进程的功能。通过以下步骤加载文件：

l 将文件读入内存缓冲区

l 读取前0x80字节，但仅将前0x60字节作为RC4密钥以解密文件的其余部分

l 根据此密钥和RC4算法解密数据

l 如果生成的数据是PE文件，则将其注入并加载到“explorer.exe”进程中。

为防止进一步分析，F-Secure检索到的这些其他文件的副本已被随机数据覆盖。


06

其他的策略、技术和流程（TTPs）


F-Secure还发现了攻击过程中拉撒路组织利用的其他几个TTP。为了避免检测，拉撒路组织禁用了Windows Defender监视，这是他们对所访问的每个主机的第一个操作，通过执行下面PowerShell命令来完成。

cmd.exe /c C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe Set-MpPreference -DisableBehaviorMonitoring $false 2>&1cmd.exe /c C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe SetMpPreference -DisableRealtimeMonitoring $true 2>&1

根据ESET的报告，发现拉撒路组织使用自定义版本的Mimikatz收集认证信息。但是，从下面命令可以看出它们并没有混淆常用的函数。

cmd.exe c:\users\public\pmp.dat privilege::debug sekurlsa::logonPasswords

拉撒路组织通过下面的注册表修改，禁用认证保护并使用凭据在内存中的存储。

cmd.exe /c reg add HKLM\\System\\CurrentControlSet\\Control\\Lsa /v LsaCfgFlags /t REG_DWORD /d 0 /f 2>&1cmd.exe /c reg add HKLM\\System\\CurrentControlSet\\Control\\SecurityProviders\\WDigest /v UseLogonCredential /t REG_DWORD /d 1 /f 2>&1

在F-Secure的调查过程中，很明显拉撒路组织有意识地避免被发现，并会删除他们存在的证据，如下面的代码段所示。

cmd.exe /c "wevtutil epl security "/q:*[System[(EventID=4778 or EventID=4624)]]"c:\users\public\evt2.dat >C:\Windows\TEMP\TMP1AC9.tmp 2>&1"

除了单个主机以外，所有主机都在入侵过程中关闭而无法访问，拉撒路组织能够安全地删除他们使用任何恶意软件的痕迹和证据。但对特定文件类型具有自动捕获功能的第三方EDR代理的存在成为了此次删除中保留的有价值证据的来源。此外，实时EDR数据还记录了该组织活动的重要细节。


07

检测


这些命令的执行为所有组织的EDR检测提供了重要的机会。虽然某些命令的最终目标是避免被检测并保持隐身状态，但这些行为本身就是“噪音”，从而会被检测。上面提供的禁用windows安全控制的示例在任何网络中都应该是异常的，并且可以用于设计较高准确度检测的例子。

还观察到拉撒路组织始终在目标网络上通过cmd.exe和其他本机OS实用程序执行大量命令。虽然也试图避免检测并融入到网络上的正常活动，但其所使用的命令元素通常是异常的，还使用特定的复杂字符串，这就给蓝队提供了检测机会。在拉撒路组织执行的大多数命令中，一个明显的特点是在命令后附加了字符串“2>&1”，当被某些工具使用时，在父-子进程过滤时会是异常的，这也提供了一个很好的检测机会 。

F-Secure建议在拉撒路组织的威胁检测规则中覆盖这些本地OS技术，以最大限度地提高检测机会。这些命令可以与正常活动混合使用，因此可能无法为所有使用的技术建立高准确度的检测。在这种情况下，使用较低的准确度检测，然后在主机上汇总，以便将各活动关联起来并在警报系统中建立智能阈值功能，可以帮助检测恶意活动而不会产生过多的误报情况。

自定义PE加载程序和主植入程序的一种变种都以无符号DLL加载到lsass.exe进程中，这对于监测任何的模块加载来说都是一个高准确度的指标。添加用于加载这些文件的注册表项也是一个高准确度指标，可以通过执行命令行或注册表扫描在该路径中创建键来检测到该指标。

拉撒路组织在磁盘上创建了很多文件，其中最值得注意的是在"％WINDIR％\ Temp \"目录中创建了"perflog.dat"和"perflog.evt"，这在之前的广告活动中就观察到了。此外，对主要植入的分析发现在"％WINDIR％\ AppPatch \"目录中创建了文件"mscmain.sdb"或"msomain.sdb"。在这两种情况下，这些文件似乎是该组织唯一使用的，由此也提供一种用于检测和潜在归因的高准确度指标。

除了主机级的检测之外，还有很多检测网络层各种植入程序活动的机会，这些植入程序会使用异常端口在工作站和服务器之间通信，这就会在标准流量中凸显出来。但安装了基于人工智能的网络检测安全工具的目标组织在此期间并没有引发任何警报。在调查期间，该工具是一个有用的证据来源，收集的遥测数据确实包含了可行的检测数据，蓝队可以利用这些数据主动采取措施。


08

结论


拉撒路组织在实施长期且成功的网络犯罪活动中展现了精湛的技术和操作安全意识。美国财政部最近发表的一项关于拉撒路组织洗钱问题的声明[12]，就证明了这场活动是成功的。F-Secure的调查结果与战略情报的情况是一致的，但提供了该组织当前策略、技术和流程的更多细节。

拉撒路组织的活动是一个持续的威胁，据观察，与此攻击相关的钓鱼活动一直持续到了2020年，这提高了在目标领域活动组织的意识和持续的警惕性。根据F-Secure的评估，该组织将继续以加密货币行业为目标，虽然是可以获利的，但他们也可能扩展至加密货币领域的供应链的其他要素，以增加活动的回报和寿命。此外，一些较新的C2基础设施表明，该组织可能正在寻找金融投资领域的组织。

F-Secure还认为，其他领域的组织可能会成为拉撒路网络行动的目标，可以多注意这份报告中包含的内容。在拉撒路组织最近的一份报告[12]中，有证据表明，他们利用了与此次活动中观察到的类似的技术，比如将LinkedIn作为一种传递媒介，以损害其他行业的组织。如本报告前面所述，拉撒路组织在多个活动中重复使用工具的证据也证明了这一点。

拉撒路组织还在继续使用2016年发现的同一系列工具，不过对几个样本的分析表明，该系列工具会随着时间的推移而更新。根据F-Secure的评估，其在恶意软件反分析技术和操作安全上的投资可以消除他们存在的证据，这为拉撒路组织保留了该工具的操作有效性。还有一种可能是，该组织没有简易重组的能力，因此只能最大限度地利用现有工具来发挥作用。但是，其他工具已经被公开归于该组织，这表明如果目标控制需要，可以利用其他功能。

F-Secure还发现，拉撒路组织的活动虽然有效，但也存在一些漏洞，给了保护组织重要的检测机会。被拉撒路组织瞄准的组织应该对照本报告中提到的技术以及拉撒路组织的MITER ATT＆CK框架[13]中的技术来审查其在技术和人员方面的检测能力。

这次调查的目标安装了先进的EDR和网络安全工具，用来捕获拉撒路组织行动的数据，但这并没有主动检测到该活动。F-Secure认为，在建立有效的检测能力方面，工作人员起着重要作用，这次事件就是一个需要在人员和技术上投资的例子。
