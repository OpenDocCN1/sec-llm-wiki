**概要：**

本文主要描述了Drovorub的背景、Drovorub恶意软件的详细技术信息、如何在受感染系统上检测Drovorub、以及缓解建议。

Drovorub是一种Linux恶意软件工具集，包括与内核模块rootkit耦合的植入物，文件传输工具、端口转发工具以及命令与控制（C2）服务器。当部署在受害机器上时，Drovorub植入物（客户端）将提供与C2基础设施(由攻击者控制)直接通信的功能、文件下载和上传功能、以“ root”身份执行任意命令功能以及将网络流量的端口转发到网络上的其他主机功能。

许多补充检测技术可以有效地识别Drovorub恶意软件活动。Drovorub工作组件通常隐藏在用于大规模实时响应的工具中，因此检测其模块对于利用主机大规模检测是一项挑战。可以使用网络边界的数据包检查来检测网络上的Drovorub或者是基于主机检测。基于主机的检测方法包括探测，安全产品，实时响应，内存分析和媒体（磁盘映像）分析。

为了防止系统受到Drovorub的隐蔽性和持久性的影响，系统管理员应更新系统版本到Linux Kernel 3.7或更高版本以充分利用内核签名。此外，建议系统所有者将系统配置为仅加载具有有效数字签名的模块，从而提高攻击者将恶意内核模块引入系统的难度。

**一、介绍**

**（1）什么是Drovorub**

Drovorub是一种Linux恶意软件工具集，包括与内核模块rootkit耦合的植入物、文件传输工具、端口转发工具以及命令与控制（C2）服务器。当部署在受害机器上时，Drovorub植入物（客户端）可以与由攻击者控制的C2基础架构直接通信（T1071.0011）、使用文件下载和上传功能（T1041）、以“ root”身份执行任意命令（T1059.004）、以及将网络流量的端口转发到网络上的其他主机（T1090）。内核模块rootkit使用多种方法来隐藏自身和植入物到被感染的设备上（T1014），并在被感染机器重新启动后一直存在，除非在“完全”或“彻底”模式下启用了UEFI安全启动。

![](../Images/0bd0d2ab8b4ed5831193fc084698840e.png)

**图1.Drovorub的组件**

Drovorub恶意软件套件由四个独立的可执行组件组成：Drovorub-agent，Drovorub-client，Drovorub-server和Drovorub-kernel模块。组件之间通过WebSockets上的JSON进行通信。Drovorub-agent，Drovorub-client和Drovorub-server通讯时需要配置文件和RSA公共密钥或私钥。下面提供了每个组件的简要概述。

**（2）Drovorub-server**

安装在角色控制的基础架构上的Drovorub-server可为Drovorub-client和Drovorub-agent启用C2。Drovorub-server使用MySQL数据库来管理连接的Drovorub-client和Drovorub-agent。该数据库存储用于Drovorub-client和Drovorub-agent注册数据、身份验证和任务分配的数据。

**（3）Drovorub-client**

攻击者将Drovorub-client组件安装在目标端点上。该组件从其远程Drovorub-server接收命令，并提供与受害者之间的文件传输功能，端口转发功能和远程Shell功能。此外，Drovorub-client与Drovorub-kernel模块打包在一起。打包后的模块提供基于rootkit的隐藏功能用于隐藏客户端和内核模块。

**（4）Drovorub-kernel模块**

Drovorub-kernel模块实现了在用户空间隐藏自身和各种工作组件的基本功能，包括指定的文件和目录、网络端口和会话、Drovorub-client流程以及Drovorub-client子流程。

**（5）Drovorub-agent**

Drovorub-agent可能会安装在可访问Internet的主机或由攻击者控制的基础结构上。Drovorub-agent可以从其配置的Drovorub-server接收命令并执行。除了远程功能之外，该组件还包括与Drovorub-client相同的功能。此外，Drovorub-agent不与Drovorub-kernel模块的rootkit一起打包。Drovorub-agent的主要职责是：将文件上传到Drovoru-client端点、从drovorub-client端点下载文件以及通过端口中继转发网络流量。

**二、归属**

**（1）为什么该恶意软件被称为“Drovorub”？**

Drovorub的名称来自Drovorub文件中发现的各种工作组件，以及GTsSS使用此恶意软件进行的操作。它是GTsSS攻击者本身使用的名称。Drovo \[дрово\]译为“firewood”或“wood”。rub\[руб\]的意思是“fell”或“chop”。

**（2）Drovorub植入操作**

**1）Drovorub-client和Drovorub-kernel模块安装**

当安装并执行Drovorub-client和Drovorub-kernel模块时，将执行以下设置活动：

1.Drovorub-kernel模块设置了其rootkit功能所需的所有系统调用的钩子

2.Drovorub-client将自己注册到Drovorub-kernel模块

3.Drovorub-kernel模块将Drovorub-client的正在运行的进程和Drovorub-client的可执行文件隐藏在磁盘上

如果Drovorub-client无法与Drovorub-kernel模块通信，它将停止执行。一旦Drovorub-client和Drovorub-kernel模块完成了设置活动，Drovorub-kernel将尝试与其配置的Drovorub-server进行身份验证。成功在Drovorub-server上注册后，Drovorub-client会立即请求隐藏任何其他文件、模块或网络端口的列表，然后等待来自Drovorub-server的命令。

**2）Linux内核模块持久性**

GTsSS网络程序使用各种专有的和公开的技术来访问目标网络并将其恶意软件持久的运行在受感染的设备上。不同于特定的网络参与者或工具包，内核模块可以使用Linux内置的功能持久保存，以便在引导时加载内核模块。在基于RedHat®的发行版中，这可能包括但不限于在.etc / sysconfig / modules /中放置.modules可执行脚本，在/etc/modules.conf中添加内核模块或放置.conf文件在/etc/modules-load.d/。在基于Debian的发行版中，这可能包括但不限于将内核模块添加到/ etc / modules或将.conf文件放在/etc/modules-load.d/中。内核模块通常位于/ lib /modules / <KERNEL\_RELEASE> / kernel / drivers /中，其中<KERNEL\_RELEASE>是目标计算机的Linux内核发行版。

**3）网络通信**

Drovorub组件（即客户端，代理和服务器）之间的所有网络通信均使用静态链接到每个组件WebSocket协议。WebSocket协议是一种在TCP上运行的应用程序层协议，由初始握手和用于数据传输的消息帧组成。可以将Drovorub配置为使用非标准TCP端口进行WebSocket通信。所有Drovorub网络通信都通过Drovorub-server。Drovorub-client和Drovorub-agent不会直接对话，而是通过Drovorub-server进行通信。这意味着Drovorub-clients和Drovorub-agent只能与连接到同一Drovorub-server的其他客户端和代理通信。

**4）隐藏技术**

Drovorub-kernel模块实现了用于在用户空间隐藏各种组件的基本功能，包括隐藏指定的文件、目录、进程、“ / proc”文件系统中进程的证据、网络端口、会话、指定的已加载内核模块、以及自身 。

对于实现其隐藏功能至关重要的是，可以通过直接修补功能或覆盖指向功能的功能指针来内核功能。Drovorub-kernel模块使用这种技术来建立：进程隐藏，文件隐藏，套接字隐藏，netfilter隐藏以及从原始套接字接收中隐藏。

**①进程隐藏**

Drovorub内核模块可以对系统调用和proc文件系统（/ proc）隐藏进程。根据Linux内核版本，Drovorub-kernel模块可能会钩住find\_pid\_ns()，ind\_pid()或find\_task\_by\_pid\_type（）内核函数，从而将进程隐藏在系统调用之外。隐藏proc文件系统中的进程是通过挂钩多个内核函数来实现的，具体取决于Linux内核版本。这些函数可能包括include\_lookup（），iterate\_dir()或vfs\_readdir()。Drovorub-kernel模块还挂钩存储在文件“ / proc”的f\_path.dentry-> d\_inode->i\_op-> lookup中的查找功能。最后，Drovorub-kernel模块挂钩do\_fork()内核函数以隐藏从隐藏进程产生的子进程。

**②文件隐藏**

为了隐藏文件，Drovorub-kernel模块根据内核版本挂钩iterate\_dir()或vfs\_readdir()内核函数。隐藏文件被从目录列表中过滤掉，但是如果知道该名称,仍然可以利用文件名使用该隐藏文件。

**③socket隐藏**

为了隐藏网络套接字，Drovorub-kernel模块将钩住适当的内核功能并过滤掉隐藏的套接字。它通过在proc文件系统的/ proc / net目录中打开适当的接口来确定要挂接的功能。对于TCP连接，Drovorub-kernel模块访问/ proc / net / tcp和/ proc / net / tcp6。对于UDP连接，它访问/ proc / net / udp和/ proc / net / udp6。钩上适当的功能后，Drovorub内核模块将连接条目与配置的隐藏列表进行比较，并过滤掉隐藏的连接。Drovorub-kernel模块可以基于源或目标端口过滤掉TCP连接、仅基于源端口过滤掉UDP连接或者隐藏进程拥有的任何连接。

**④Netfilter隐藏**

在Linux中，Netfilter是一个组件，可用于过滤内核中的数据包。防火墙通常使用它执行数据包过滤。Drovorub-kernel模块在LOCAL\_IN和LOCAL\_OUT处注册一个Netfilter的钩子。

Drovorub-kernel模块还秘密地钩住内核的nf\_register\_hook()函数，该函数用于注册Netfilter钩子。调用nf\_register\_hook()时，Drovorub-kernel模块首先调用原始的nf\_register\_hook（）函数，从而允许添加新的Netfilter钩子。然后，它使用nf\_unregister\_hook()内核函数注销以前在相同的挂钩号处注册过的所有挂钩。最后，Drovorub-kernel模块将使用nf\_register\_hook()函数重新注册其Netfilter挂钩。删除并重新添加Drovorub-kernel模块Netfilter挂钩的目的是为了确保在相同的挂钩号下，在调用其他任何非Drovorub注册的挂钩之前，先调用其Netfilter挂钩。

当调用Drovorub-kernel模块Netfilter挂钩时，Drovorub-kernel模块将先确定数据包是隐藏TCP连接的一部分，还是与隐藏进程之间的TCP连接的一部分。如果是隐藏TCP连接，其Netfilter挂钩将返回NF\_STOP，从而防止为该数据包调用任何其他已注册的Netfilter挂钩。

为了方便识别进出隐藏进程的数据包，drovoru-kernel模块秘密地挂钩内核套接字函数，用于建立或接受连接以及删除连接。它使用sock\_create()内核函数创建一个内核套接字，并在s->ops->accept、s->ops>connect和s->ops->release返回的套接字结构(假设这里命名为“s”)中查找这些函数。每当钩接的accept调用被发出(传入连接)或钩接的connect调用被发出(传出连接)时，drovorru-kernel模块都会检查调用进程是否被隐藏。如果是，套接字被保存在一个全局列表中，由Drovorub-kernel模块Netfilter钩子检查每个数据包。(注意:内核模块的Netfilter钩子不支持UDP，只支持TCP。)

**⑤隐藏原始套接字接收**

drovoru -kernel模块挂钩skb\_recv\_datagram()内核函数。作为隐藏网络会话一部分的任何数据包都会从原始套接字接收的数据包中过滤。必须显式地隐藏网络会话，以便过滤其数据包。

**(5)****检测**

**1)检测方法**

许多补充检测技术可以有效地识别Drovorub恶意软件活动。Drovorub工作组件通常隐藏在用于大规模实时响应的工具中，因此检测其模块对于利用主机大规模检测是一项挑战。以下是可用于Drovorub恶意软件的各种检测方法的优缺点的讨论

**①基于网络的检测**

网络入侵检测系统（NIDS）可以在Drovorub-client或Drovorub-agent与Drovorub-server之间切实地识别命令和控制消息。具体来说，某些NIDS（例如Suricata®，Zeek®，Snort等）可以通过脚本功能动态消除“被隐藏的” WebSocket协议消息的混淆。在网络边界使用TLS代理,即使在TLS加密通道下也可以检测命令和控制消息。具体而言，某些NIDS（例如Snort，Suricata，Zeek等）可以通过脚本编写功能动态消除对“掩盖的” WebSocket协议消息的混淆。

**优点：高可信度，大规模（全网络）检测网络命令和控制。**

**缺点：如果在信息格式发生改变的情况下，可经由TLS规避。**

**即时回应**

事件响应者通常使用实时响应技术，例如使用本机系统二进制文件和库（使用内核提供的系统调用）在运行的系统上搜索特定的文件名、路径、哈希、Yara规则以检测企业规模的恶意活动。Drovorub内核模块通过挂钩（修改逻辑和输出）某些内核功能来隐藏自身以及相关的文件，进程和网络连接，从而大大降低或完全避免了这种检测方法的有效性。因此，这种检测方法会增加假阴性的风险（无法检测到受损的端点）。

**记忆分析**

捕获和分析端点的运行内存是检测Drovorub-kernel模块的最有效方法，因为它可以最大程度地了解rootkit在系统中隐藏自身和其他工作组件的行为。可以使用诸如Linux MemoryGrabber（LMG），LiME andVolatility或Rekall之类的公共工具来获取和分析内存。

**优点：提供对特定rootkitc行为和工作组件（例如文件，其他进程和恶意软件隐藏的网络连接）的最大可见性。**

**缺点：对系统稳定性（在采集过程中）的潜在影响较大，并且无法扩展到大量端点。**

**(6)****预防性或者缓解性措施**

注意：以下缓解措施并非旨在防止初始访问媒介。缓解措施旨在仅防止Drovorub的持久性和隐藏技术。

**1）应用Linux更新**

系统管理员应定时检查供应商提供的软件版本，保持更新，以便及时修补漏洞。对于linux kernal，建议更新到3.7或更高版本，这样可以充分利用内核签名的功能。

**2）****防止不受信任的内核模块**

建议系统所有者将系统配置为仅加载具有有效数字签名的模块，从而使攻击者更加难以将恶意内核模块引入系统。攻击者可能使用恶意内核模块来控制系统，隐藏系统或在重新启动后持续存在。

必须激活UEFI安全启动，以确保只能加载签名的内核模块。一旦启用，Secure Boot通过验证固件、引导加载程序和机器所有者密钥(MOK)的签名在引导时创建一个完整性链。然后，通过此MOK验证内核，初始文件系统和内核模块，该MOK与支持安全启动的Linux发行版一起分发。安全启动策略拒绝执行具有不可信或不存在签名的组件。启用安全启动可能会阻止某些产品加载，从而可能影响系统功能，而且可能需要自定义配置。
