     概    要          

在这篇paper中，我们将分析cve-2018-4441漏洞的细节。WebKit是Apple Safari浏览器中的Web浏览器引擎，也是其他macOS、iOS和Linux系统中应用的浏览器引擎。该漏洞在公开披露后，被发现会影响最新版本的苹果Safari浏览器和依赖JavaScriptCore作为JavaScript引擎的相关应用。应用开发者应该选择使用最新的WebKit版本。


序  言

我们都知道JavaScript数组的元素之间是可以不连续存储的，例如，a=[];a[0]=1;a[3]=1; 此时a[2]没有被赋值。我们称这样的数组为含有“洞”的数组。查看上面的代码片段，我认为这个函数的目的是为了阻止带有“洞”的JavaScript数组执行到这句代码storage->m_numValuesInVector -= count上，但是带有“洞”的JavaScript数组若能让this->structure(vm)->holesMustForwardToPrototype(vm, this))返回false的话，那么storage->m_numValuesInVector -= count还是能执行到的。除非带有“洞”的JavaScriptarray含有索引访问或者在原型链上有代理对象，否则this->structure(vm)->holesMustForwardToPrototype(vm, this))就返回false。所以storage->m_numValuesInVector就可以被攻击者控制了。


POC

function main() {

// [1]

let arr = [1];

// [2]

arr.length = 0x100000;

// [3]

arr.splice(0, 0x11);

// [4]

arr.length = 0xfffffff0;

// [5]

arr.splice(0xfffffff0, 0, 1);

}


main();


漏洞成因分析

在调试器中运行poc，我们会发现程序崩溃在向一个不可写内存写数据

（exec bad access）：

更精确一点，这个崩溃发生在JSArray::unshiftCountWithArrayStorage的循环中，该函数正试图清空vector的元素。

// [...]


for (unsigned i = 0; i < count; i++)

vector[i + startIndex].clear();


// [...]

startIndex（$rdi）值为0xfffffff0，vector（$r13）指向0x10000fe6a8 ，最后vector偏移指向无效内存，所以程序崩溃了。

初始化创建了一个类型是ArrayWithInt32的数组，这个数组可以保存任何类型的数据（例如：对象类型、double类型），但是此时该数组还没有ArrayStorage 或者“洞”。针对不同类型数组是用什么方法进行存储的，webkit官方给了一个很详细的介绍，链接地址如下：https://github.com/WebKit/webkit/blob/1d7d66b8201bfe83e09a7cceb38db151f8407279/Source/JavaScriptCore/runtime/ArrayConventions.h#L29-L53

简而言之，一个没有ArrayStorage的Jsarray含有一个“蝴蝶”结构，Jsarray的结构如下：

接下来，设置数组长度为0x100000，这会把数组变成ArrayWithArrayStorage结构，事实上，将数组长度设置为大于等于MINSPARSEARRAY_INDEX将会把Jsarray变成含有“蝴蝶”结构的ArrayWithArrayStorage。需要注意的是此时Jsarray的“蝴蝶”结构指向 ArrayStorage 而非数组的第一个元素。

javascirptcore通过shift[左移]和unshift[右移]来实现splice（）函数，到底是shift还是unshift,基于两个变量的值，itemCount 和 actualDeleteCount.

因此，若itemCount < actualDeleteCount，那么splice 最终会调用JSArray::shiftCountWithArrayStorage.

由于在报告最开始已经说过了，数组若既没有索引访问器 ，在原型链上也没有任何代理对象，holesMustForwardToPrototype将会返回false，storage->mnumValuesInVector -= count将会被调用。在我们的poc中，count=0x11，storage->mnumValuesInVector在减之前是 1，减完之后就是0xfffffff0。此时也就发生了整数溢出。

// [4]

arr.length = 0xfffffff0

// - Object @ 0x107bb4340

// - Butterfly @ 0x10000fe6e8

// - Type: ArrayWithArrayStorage

// - public length: 0xfffffff0

// - vector length: 1

// - m_numValuesInVector: 0xfffffff0

此时，mnumValuesInVector已经被控制了，通过设置publicLength 的值为mnumValuesInVector，hasHoles 也能被控制。

bool hasHoles() const

{

return m_numValuesInVector != length();

}

最终，由于itemCount > actualDeleteCount，splice（）就会调用，此时可以触发unshift而不是shift，hasHoles将会返回false，此时我们就在JSArray::unshiftCountWithArrayStorage函数中获得了越界读写能力。
