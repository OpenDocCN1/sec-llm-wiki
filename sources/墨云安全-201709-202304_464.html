EOSBet是全球首款EOS公链上的菠菜游戏平台，其首款游戏DICE（骰子）是目前EOS公链上最成功的DAPP，日均活跃用户约600人，日均流水约150万EOS。

不过平台在今年的9月和10月遭受了两次黑客攻击。黑客利用了EOSBet游戏合约的2个漏洞，通过第一个窃取到4万多个EOS币，通过第二个漏洞窃取到14万多个EOS币，相当于窃取到近100万美金。笔者对这两个漏洞进行跟踪分析，发现这2个漏洞比较类似的，漏洞出现在游戏合约的apply（）函数，漏洞成因都是没有对transfer通知的参数进行充分校验导致。

漏洞分析

上面代码其实就是一个事件分发器，Eosbet游戏合约设计是接收来自eosio.token的 EOS币，但是上面的代码收到transfer 事件时，就已经认为收到真的EOS，存在漏洞。

有漏洞的代码就发生在这条if语句里：if( code == self || code == N(eosio.token) || action == N(onerror) ) ；从上面的这句if判断代码可以看到，无论code是N(eosio.token)，还是self，EOSIO_API(TYPE,MEMBERS) 都将会执行。Code参数是用来表示事件的发起者是来自哪个合约；当用户通过eosio.token合约转账时，code等于N(eosio.token)，表明事件来自eosio.token合约。但是攻击者是可以完全构造出一个假EOS转账，此时code==self而不是eosio.token，那么他就可以绕过eosio.token合约转账了。只有eosio.token transfer来的币才是真的EOS。 

关于这个漏洞，eosbet官方觉得是个比较严重的漏洞，而且可能很多其它的合约也会存在类似的问题，他在官方公布了漏洞的细节，供其它合约开发者自查：

漏洞二：eosbet apply函数接收假通知漏洞


攻击过程

10月10日，账号“iwasagoodboy”当天通过67次伪造转账通知行为共获利345.5个EOS。而追踪发现，10日与15日期间，共计有“iwasagoodboy”  “hereisstocks  ”“iwanttoloveu” “ilovedice123”、” iamthewinnee”五个账号采用此种方式套利，其中最大的一次攻击行为正是10月15日，由账号ilovedice123所发起的。通过该轮攻击，黑客共计获利138,724.325个EOS，至此该攻击行为被媒体报道，由安全公司介入分析，开始浮出水面。

攻击为同一ID所为。

据PeckShield态势感知平台监测发现，10月15日下午13:27到13:38之间，账号ilovedice123总共发起了10余笔大额转账指向交易所平台，其中72,150 EOS流入了Bitfinex，65,100 EOS流入了Poloniex。通过继续追踪几个攻击者资金流向分析，PeckShield安全人员发现，以上五个不同账号的获利资金经过多次转账后最终在向Bitfinex和Poloniex交易所发起转账时，都流入了所在交易所的同一账号ID，给交易所Bitfinex（bitfinexdep1）充值的ID为0aa03fbec9a3b2bec49e97575b506644，Poloniex（poloniexeos1）充值ID为9bb2aa5fc22a1bb2，因此判断，采用“伪造转账通知“实施攻击的不同账号为同一黑客所为，黑客先是进行了多笔小额攻击尝试，最后于10月15日发起了大额攻击。


漏洞分析

这个漏洞是eosbet 假EOS充值漏洞的升级版，上个漏洞补丁之后，黑客觉得补丁修复的不太完美，又找到了攻击的路径。这次黑客开始转真的EOS，他并没有转到eosbet的账号，而是转到了黑客自己的账号里。黑客是怎么做的呢，黑客手里有2个账号，一个是普通账号a，一个是合约账号b；黑客接收EOS的账号是个合约账号。

如下，黑客通过eosio.token 合约 从a向b转账时，eosio.token 合约会通过require_receipt （）函数来通知接收账号，当该账号收到 EOS时，会触发攻击合约代码执行，由于事件是从eosio.token合约传来的，所以此时code值还是eosio.token .

该合约代码通过require_receipt去调用 eosbet 游戏合约，此时由b进入eosbet，eosbet的apply函数被调用，但是事件的code值还是eosio.token，所以漏洞1的修复补丁是没法检测这个调用路径的。那为什么会出这个漏洞呢？

因为eosbet合约并没有检查EOS的去处，只有转账到eosbet自己账号的EOS才是有效的。

Eos官方给了这个漏洞的修复建议：

Any contract relying on transfer notifications from eosio.token should add this check immediately: if (transfer.to != _self) return;

只需要在esobet的transfer函数加上下面检查，确保这笔交易的收款方是eosbet。
