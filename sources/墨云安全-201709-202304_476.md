**门罗币（XMR）假充值逻辑漏洞——你中招了吗？**

门罗币官方在修复这个漏洞时给出了critical级别（严重），这在漏洞评级中是最高级别，代表这个漏洞能造成很大危害。门罗币的这个漏洞可以让攻击者恶意盗取交易所里的所有门罗币，若交易所无法负担这笔损失，那只能破产或者跑路，最终受损失的还是在交易所里存门罗币的投资者。同时，若这个洞被攻击者大量使用，门罗币的市值也会受到很大影响，造成门罗币市值大跌。

**关于门罗币你了解多少？**

门罗币是一个创建于2014.4 的开源加密货币，和比特币相比，它具有更好的匿名性，因而受到了不少数字货币投资者的喜爱。今年8月2日，hackone 漏洞提交平台公开了xmr的一个假充值漏洞。

墨云科技尖峰安全实验室对这个漏洞进行了跟踪分析。目前，门罗币最新版的钱包已经修复了这个漏洞。

**漏洞分析**

**hackone****的链接如下：**

https://hackerone.com/reports/377592

 

**下面这是关于这个漏洞的英文描述：**

PR #3985 fixed a wallet balance display bug, which seems innocuous enough, but this bug also extends to exchanges: a transfer of, e.g., 1 XMR to an exchange with a duplicated TX pub key will show up on an exchange as a 2 XMR deposit, which then allows the attacker to withdraw 2 XMR from the exchange's wallet. An attacker could exploit this repeatedly to siphon of all of the exchange's balance.

 

**翻译过来既是：**

PR#3985修复了一个钱包余额显示的漏洞，这个漏洞好像是无害的，但是这个漏洞可以扩展到（攻击）交易所。例如，我们使用重复的tx pub key 向交易所转账1 xmr，交易所在显示交易记录时会显示收到了2 xmr，这导致攻击者可以从交易所的钱包里提取2xmr。攻击者可以重复前面的操作，直至把交易所钱包里的xmr全都提取出来。

那么这个钱包余额显示的漏洞是个什么漏洞呢？笔者根据hackone的指引搭建了一个xmr的编译调试环境，重现了这个漏洞。

  

**重现步骤如下：**

1、恶意的给一笔交易添加2个tx pub key，这个操作很容易实现。由于xmr钱包的源码是公开的，我们把代码下载下来之后，将src/cryptonote\_core/cryptonote\_tx\_utils.cpp. 的add\_tx\_pub\_key\_to\_extra(tx, txkey\_pub);这行代码复制黏贴成2行就行。

这个tx pub key是用来标识一笔交易的，同一笔交易对应同一个tx pub key，我们将这笔交易的tx pub key添加了2次，那么这相当于我们发起了2次重复的交易。

那么为什么发起2次重复的交易（第二次是无效的）会让show\_transfers 显示错误的转账记录呢？我对关键点函数进行了追踪，这个函数是wallet2::process\_new\_transaction（），该函数在收到新的转账时会被调用，并更新转账记录信息。这个漏洞的成因是 该函数在处理第二次无效的交易时，并没有考虑这个情况，还接着把它当成有效的，并把2次收到的转账金额进行了累加，存入到了钱包对应的结构里。

那么这个漏洞为什么能够适用于攻击交易所呢？  

交易所网站有个门罗币钱包，所有在该交易所转币的人都共用这个钱包。当我们向交易所钱包转币时，若交易所只通过show\_transfers 来看你给它转了多少xmr，那它就被欺骗了，例如，攻击者Alice实际转了1个xmr，那么show\_transfers 显示收到了2个xmr，交易所然后在它的数据库里记录 了 Alice 持有2个币，然后Alice就可以提现2个币了（交易所的xmr 钱包里除了Alice的一个xmr，还有其他人的xmr），交易所收到了损失。
