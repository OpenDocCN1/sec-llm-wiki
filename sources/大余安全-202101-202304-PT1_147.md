大家好，这里是 **大余安全**的第 **137** 篇文章，本公众号会每日分享攻防渗透技术给大家。

靶机地址：https://www.hackthebox.eu/home/machines/profile/161

靶机难度：中级（4.0/10）

靶机发布日期：2019年4月3日

靶机描述：

Vault is medium to hard difficulty machine, which requires bypassing host and file upload restrictions, tunneling, creating malicious OpenVPN configuration files and PGP decryption.

  

请注意：对于所有这些计算机，我是通过平台授权允许情况进行渗透的。我将使用Kali Linux作为解决该HTB的攻击者机器。这里使用的技术仅用于学习教育目的，如果列出的技术用于其他任何目标，我概不负责。

nmap仅发现开放了apache和ssh服务...

![](../Images/3ba0564a09c613c3a42df260ffeb031c.png)

这里提示了Sparklays信息...我猜测是目录或者用户名...

![](../Images/30ef9e8309a38e91c4a8284d2242c5e4.png)

尝试爆破发现是目录信息...存在/desig等目录信息...

![](../Images/635e0c5bfa05334fe635dd768b62f664.png)

根据爆破获得的信息，正常访问

![](../Images/5d654b5c7c40af3c71c58b705e60fdb7.png)

点击进去后，这是个文件上传的页面...文件上传漏洞利用

![](../Images/bc0f654afef60cc6563952f902a607a6.png)

随意上传个简单的php\_shell发现格式名称不对...

![](../Images/7e4f226e30b222ebc91e2a377a2fbe3c.png)

经过多次尝试，需要.php5后缀名称才可成功上传....

![](../Images/3dd17c13847c88fb7870bad7dcfcab2f.png)

通过简单的shell，获得了反向外壳...

这里提示下，文件上传是其中爆破出来的一个目录，还有另外的登录用户的页面和别的页面，都存在兔子洞，坑是挺多的....

进来后发现dave用户桌面下存放着三个文件....都是重要信息，两个密码...一个服务存在的现状IP...

![](../Images/dcd2e72930fed7cc984cdb4111cd0278.png)

查看了ssh密码，登录即可...

![](../Images/0144bdde92ac933df888ebd998c85473.png)

ssh登录进来后，发现存在虚拟网桥接口...192.168.122.1

![](../Images/d5d88886c9b325330c4bab7276e0a8b6.png)

查看本地存在的一些端口，是虚拟网桥开放的22和80端口...

![](../Images/b9cc125c2e3cb1827a4a61f20963403d.png)

这里熟悉的技术，利用SSH把流量转发到本地即可...

![](../Images/f019637a1eb7e3b01dad4627e7e6bea3.png)

然后通过本地访问网桥IP开放的web服务...DNS和VPN，这里存在DNS设备和VPN链接情况...

DNS访问404报错...

![](../Images/f16cbdfb56dfc56b1bd1e6dbbd851194.png)

VPN页面可以输入，google看看

![](../Images/eb37eafe957d4e180062799853667c5e.png)

google openvpn reverse shell发现一些shell提权的文章，利用看看...

![](../Images/70e9a03dc8c3f18f935371cf4ade18cb.png)

修改后...靶机监听即可

![](../Images/965edbf6b69bb7450340c1428e510aa1.png)

通过openvpn shell成功进入了root\_DNS用户权限下...查看根目录发现了一些文件...

![](../Images/449c6f3d2136ae2ade6389eb936d94e2.png)

获得了user\_flag信息...

![](../Images/9de2c7e5ba6a62fdc8f9a38e4d14f4c4.png)

这里可以知道本环境IP192.168.122.4...

![](../Images/940b68fba45eb5db4effa5fbb67b1535.png)

回看下前面发现的三个文件中servers网络情况...里面标注了，DNS是.4的IP，还存在防火墙是.5的IP，说明.1的IP到.4的IP之间有台防火墙串联着，IP是.5....

![](../Images/de389908f7b52293b2ba3ac494d14c40.png)

继续查看路由情况，是添加了条192.168.5.0的路由...

看看本地域名...存在Vault域名：192.168.5.2...

发现此环境安装了nmap，对192.168.5.2扫描了端口情况...存在53和4444的潜在端口...

重新理清下思路...

![](../Images/527a0550cbb4e3822ccee1becfceb212.png)

情况是这样的，看图即可...

需要绕过FW进入5.2环境...还是需要SSH或者流量等转发技术...

![](../Images/adcdb978b015f8a9438caad35fabd1b8.png)

将4444作为源端口，利用nmap绕过防火墙并找到另一个开放端口...987

![](../Images/c978c31a5fb452bffd2e1469c4abeee9.png)

当然，在查看历史记录日志里，也发现了该操作...他是利用ncat生成侦听器进行连接...

![](../Images/f8a2224a2017dab7f6c14fd36d1c72de.png)

我们也利用ncat侦听器进行生成，该侦听器在更改源端口时重定向到端口987...

然后利用ssh成功登录...并查看到了root.txt.pgp文件...pgp格式下，在5.2环境里无法查看...

查看了三个环境下，在最初的dave@ubuntu：10.10.10.109环境下，可以使用gpg...当然本地也可以...

![](../Images/53bc2699d240059506aa5353019f0b53.png)

由于5.2环境无法使用base64...这里利用scp将文件传回到DNS环境....

![](../Images/8bade07eb3a948b63812a7d4c39c641b.png)

通过base64进行复制文件即可...

![](../Images/cc96eb5078244b90b7359ae1b8db4711.png)

转储....

![](../Images/3bf4b46ddf057256d707acf48034ad57.png)

放回dave@ubuntu：10.10.10.109环境下后，利用gpg -d成功获得了root\_flag信息...
