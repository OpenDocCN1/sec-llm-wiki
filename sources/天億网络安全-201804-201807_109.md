# **渗透测试概述**

     渗透测试是风险评估中的技术层面评估的一个方面，有效的渗透测试可以直接发现被测试目标真实存在的一些安全风险，如可以发现操作系统、应用程序、数据库、网络设备等存在的漏洞以及漏洞利用的可能性，也可以发现各种设备的口令脆弱性、网络设备的易攻击性、防火墙设备策略的严谨性；也就能初步发现和估算出被测试网络中存在安全方面的技术风险。从而达到发现管理方面的一些风险的目的，这也是渗透测试的主要出发点和真实作用。

主要检查手段依据安全专家已经掌握的安全漏洞和安全检测工具，模拟黑客的攻击方法在环保部负责人的授权和监督下对相关网络进行非破坏性的攻击测试。

1.  直观地表现网络安全漏洞的危害；

2.  定量、具体地报告网络系统中存在的可能被利用的网络安全漏洞；

3.  详细呈现渗透方法与过程，为设计安全解决方案提供事实依据。

# **渗透测试原则**

渗透测试过程中遵循以下原则：

*   标准性原则
    

渗透测试方案的设计和实施都在充分吸纳国内外相关标准如：GB/T 18336.2-2001 信息技术安全性评估准则：安全功能要求、OWASP、CVE、CNNVD以及CNVD等基础上进行。

*   规范性原则
    

渗透工作中的过程和文档，严格按照国家规范操作，严格执行项目的跟踪和质量控制。

*   可控性原则
    

渗透测试过程和所使用的工具具有可控性。

*   整体性原则
    

渗透测试服务从组织的实际需求出发，结合业务需求、安全管理和业务运营等方面进行渗透测试，而不是仅仅局限于网络、主机等单个的安全层面。

*   最小影响原则
    

渗透实施过程中制定充分细致的工作计划，尽可能不对现有网络的运行和业务的正常运转产生显著影响，同时采取必要控制措施尽可能小地影响系统和网络的正常运行。

*   保密性原则
    

从公司、人员、过程三个方面进行保密控制：公司双方签署保密协议，不得利用渗透测试中的任何数据进行其他有损甲方利益的用途；所有参与项目的人员签订个人保密协议；在渗透测试过程中对测试相关的数据执行严格的保密控制措施；项目结束后确保有关敏感数据被安全清除。

# **渗透测试方法**

  

应用层渗透测试

**漏洞扫描**

通过对应用漏洞扫描可以发现应用系统各种重要信息，也有可能直接发现系统重要的安全漏洞。安全扫描充分了解系统安全的真实情况，也充分了解外部攻击者所能探测到的信息。

**常见风险漏洞** 

直接发现SQL注入、跨站等漏洞。

系统结构分析

通过对系统进行智能搜索扫描，从结构上剖析了整个系统的组织结构，可以更加直观的看到整个系统的实施。

1、通过分析系统整个结构上的目录和文件取名习惯，以及系统结构层次的分析，能够得到管理员的建站习惯，可能导致恶意用户猜测管理员密码。

隐藏文件探测

通过隐藏文件的智能探测，除了已有的所有公开页面以外，智能搜索并探测在这些目录下是否存在隐藏文件。这些文件很有可能就是系统的一些配置文件，或者是系统管理员忘记删除的程序说明书，或者是系统后台登陆的重要文件。这些文件极有可能导致系统重要数据的泄漏，最终导致整个系统权限的沦陷。

2、隐藏文件有可能是各种重要的程序页面，通过分析隐藏，有可能暴露出后台登陆的细节内容，以及其他重要的程序文件。

备份文件探测

通过备份文件的智能探测，除了已有的所有公开页面以外，智能搜索并探测在这些目录下是否存在备份文件。这些文件很有可能就是系统的一些重要文件的备份信息，或者是系统管理员忘记删除的系统数据库备份。这些文件是最有可能导致系统重要数据的泄漏的风险点，直接威胁着整个系统的整体安全。

3、源代码泄漏、私密文件泄露。

用户名和密码猜解

通常，系统是不提供用户注册的，但是由于内部用户的粗心大意留下了简单密码的帐户，导致外部人员可以使用内部功能。于此同时，内部功能上的风险也暴露给了外部人员。

4、导致外部用户可以登陆管理员后台等内部功能，使用高权限功能，并造成内部功能缺陷的暴露。

错误信息挖掘

通过发送特殊的字符串参数导致系统错误，根据返回的错误信息分析得到有价值的内容。

5、攻击者通过错误信息，经过对错误信息的分析，可能会进一步发现攻击的路径。

跨站脚本漏洞挖掘。

跨站脚本攻击漏洞通常出现在用户和应用程序进行信息交互的接口处，这种漏洞使用户访问应用程序的时候执行恶意代码，可以直接导致用户数据的泄漏，最终不但有损系统的信誉度，同时还威胁到服务器的安全性。

6、攻击者可以欺骗用户访问包含恶意JavaScript代码的页面，使得恶意代码在用户浏览器中执行，从而导致目标用户权限被盗取或数据被篡改。

SQL注入漏洞挖掘

SQL注入类型的漏洞通常是出现在用户和服务器进行信息交互的接口处，这种漏洞使得服务器的后台数据库内的信息很有可能直接暴露出来，造成机密信息的泄漏。如果其中包含管理员的账号信息，其危害也就不言而喻了。更重要的是站在系统用户的角度来说，这种问题的出现严重影响到了系统在客户心中的信誉度。

7、未授权用户可能通过该漏洞获取数据库敏感资料，造成敏感信息泄漏，也可能导致非法执行系统命令。

越权访问

当取得一定权限或信息后，尝试手工绕过逻辑验证的攻击，获取到更高的权限，或者浏览私密信息。

8、越权访问系统功能，可能会造成非法文件上传、信息泄露、数据被篡改等方面的风险。

文件上传漏洞挖掘

由于文件上传功能实现代码没有严格限制用户上传的文件后缀以及文件类型，导致允许攻击者向某个可通过 WEB 访问的目录上传任意文件，并能够将这些文件传递给WEB解释器，就可以在远程服务器上执行任意脚本。

9、文件上传漏洞是一个非常恐怖的漏洞，如果你的程序里面有这种漏洞，那么恶意攻击者可以直接向你的服务器上传一个 webshell，从而控制你的网站或信息系统。

任意文件读取漏洞

攻击者可以通过或者后台登录之后读取任意文件包括数据库配置文件。可导致入侵者获得数据库权限并利用数据库提权进一步获得系统权限。

10、信息泄漏、系统提权。

目录遍历漏洞检测

服务端将WEB服务器路径直接输出到页面的隐藏表单中或其他地方，攻击者操纵输入参数使应用系统执行或透露任意文件内容，或对服务器任意文件目录进行读写删除等操作。

11、信息泄露、越权访问。

功能滥用漏洞

攻击者滥用WEB应用提供的功能（如邮件发送，找回密码等）导致资源耗尽，访问控制机制被绕过，信息泄露等。

12、功能滥用可能会造成一些超出预料之外的风险，如：敏感信息泄漏、越权访问等。

命令执行漏洞

用户通过浏览器提交执行命令，由于服务器端没有针对执行函数做过滤，导致在没有指定绝对路径的情况下就执行命令，可能会允许攻击者通过改变 $PATH 或程序执行环境的其他方面来执行一个恶意构造的代码。命令注入攻击中WEB服务器没有过滤类似system(),eval()，exec()等函数是该漏洞攻击成功的最主要原因。

13、权限提升、感染病毒、执行恶意代码。

跨站请求伪造漏洞  

在跨站请求伪造（CSRF）攻击里面，攻击者通过用户的浏览器来注入额外的网络请求，来破坏一个网站会话的完整性。而浏览器的安全策略是允许当前页面发送到任何地址的请求，因此也就意味着当用户在浏览他无法控制的资源时，攻击者可以控制页面的内容来控制浏览器发送它精心构造的请求。

14、攻击者利用该漏洞可以用户访问链接导向精心设计的钓鱼网站，普通用户有时候很难区分钓鱼网站和真正网站，会导致用户信息泄漏，严重是会造成用户财产损失。

文件包含漏洞

文件包含漏洞的产生原因是在通过引入文件时，由于传入的文件名没有经过合理的校验，或者校检被绕过，从而操作了预想之外的文件，就可能导致意外的文件泄露甚至恶意的代码注入。当被包含的文件在服务器本地时，就形成了本地文件包含漏洞，可以查看系统任意文件内容，如果具备一些条件，也可以执行命令文件。

15、敏感信息泄漏、越权访问

WebShell检测

   WebShell就是以asp、php、jsp或者cgi等网页文件形式存在的一种命令执行环境，也可以将其称做为一种网页后门。黑客在入侵了一个网站后，通常会将asp或php后门文件与网站服务器WEB目录下正常的网页文件混在一起，然后就可以使用浏览器来访问asp或者php后门，得到一个命令执行环境，以达到控制网站服务器的目的。

16、攻击者在网站系统留有WebShell后门后，通常可以完全或部分控制用户服务器，窃取用户数据给用户造成经济损失。

组件泄露漏洞

指的是开发人员使用的组件含有漏洞，这些漏洞能被自动化工具发现和利用。然后攻击者根据需要定制攻击代码并实施攻击。

17、一般开发组件有漏洞的话，使用该组件开发的信息系统通常包含漏洞，严重的组件漏洞如struts2漏洞可直接导致服务器被远程控制。

信息泄露漏洞

信息泄露大致分为跟客户相关的信息和服务器相关的信息泄露两种。泄漏服务器的敏感信息，使攻击者能够通过泄露的信息进行进一步入侵。服务器信息泄漏包含：内网IP泄露、数据库信息泄露、网站调试信息泄露、网站目录结构泄露、绝对路径泄露、电子邮件泄露、网站后台登录地址泄漏、源代码泄露等。客户信息泄漏包含：手机号、身份证号、银行卡号、社保号、家庭住址等信息。

18、泄漏服务器的敏感信息，通常会让攻击者可能寻找到攻击服务器的途径，给服务器带来很大的安全风险。泄漏客户信息，可能会给客户带来经济损失。
