1.漏洞概述

2020年4月，Eclypsium的安全研究人员在GRUB2引导程序中发现了一个被称为“BootHole”的漏洞，成功利用该漏洞使攻击者可以绕过安全引导（Secure Boot），在引导过程中获得任意代码执行能力。同时，攻击者利用这个漏洞可以安装持久性和隐蔽性的引导程序或恶意引导加载器，从而完全控制受害者的设备。

 

即使没有使用GRUB2，使用Secure Boot的系统也会受到该漏洞的影响。几乎所有签名版本的GRUB2都存在漏洞，这意味着几乎所有的Linux发行版都会受到影响。此外，GRUB2还支持其他操作系统、内核和管理程序，如Xen。这个问题还延伸到任何使用安全启动与标准的微软第三方UEFI证书授权的Windows设备。因此，大多数笔记本电脑、台式机、服务器和工作站都会受到影响，以及工业、医疗、金融和其他行业使用的网络设备和其他特殊用途设备。这个漏洞使得这些设备容易受到攻击者的影响，比如最近发现的使用恶意UEFI引导程序的威胁行为者（https://twitter.com/ESETresearch/status/1275770256389222400）。

 3.漏洞详情 

Linux系统安全启动（Secure Boot）过程：

1.固件加载包含可信证书（称为 "shim"）的smol第一级引导加载器二进制文件。

2.Shim加载GRUB二进制文件(另一个bootloader)并使用证书进行验证。

3.GRUB加载任何位于grub.cfg中需要的配置，它指向可以加载内核映像的地方。

4.GRUB通过存储在固件信任数据库中的密钥（db和dbx，分别是授权和禁止的签名数据库）来验证内核。

5.GRUB将控制权交给内核

6.内核启动操作系统

 

  这个漏洞存在于步骤#3。GRUB使用语言解析器（通过flex和bison生成）来读取配置文件。正常情况下，如果配置文件中的文本过大，flex引擎会退出或停止。但是在GRUB的实现中，GRUB直接把它复制到缓冲区里，继续执行函数，从而导致了缓冲区溢出。



4.影响范围

所有从外部grub.cfg文件读取命令的签名版本的GRUB2都存在漏洞，影响到所有Linux发行版。到目前为止，已知有超过80个shims受到影响。除了Linux系统外，任何使用标准Microsoft UEFI CA的Secure Boot的系统都会受到这个问题的影响。因此，目前使用的大多数现代系统，包括服务器和工作站、笔记本电脑和台式机，以及大量基于Linux的OT和物联网系统，都可能受到这些漏洞的影响。此外，任何依赖UEFI安全启动的硬件信任机制也可能被绕过。

 

受影响的部分厂商列表：

Microsoft

Oracle

Red Hat (Fedora and RHEL)

Canonical (Ubuntu)

SuSE (SLES and openSUSE)

Debian

OEM厂商

5.缓解措施 

- 更新GRUB2以解决该漏洞。

- 使用 GRUB2 的 Linux 发行版和其他供应商需要更新他们的安装程序、引导加载器和shims。

- 新的shims将需要由微软第三方UEFI CA签署。

- 受影响设备的管理员需要更新现场安装的操作系统版本以及安装程序镜像，包括灾难恢复媒体。

- 最终需要更新每个受影响系统固件中的UEFI撤销列表（dbx），以防止在启动过程中运行这个存在漏洞的代码。

 

缓解措施将需要签署和部署新的引导加载程序，并应撤销易受攻击的引导加载程序，以防止对手在攻击中使用旧的、易受攻击的版本。这可能是一个漫长的过程，需要相当长的时间来完成组织的补丁。。UEFI相关的更新曾有过让设备无法使用的历史，厂商需要非常谨慎。如果撤销列表(dbx)在给定的Linux引导加载器和shim更新之前更新，那么操作系统将无法加载。因此，对撤销列表的更新将随着时间的推移而进行，以防止破坏尚未更新的系统。还有一些边缘情况下，更新dbx可能会很困难，例如双启动或去掉配置的机器。当安装或启动任何操作系统时，在将撤销应用于系统之前，需要更新引导加载器和操作系统。

 

微软将发布一组已签名的dbx更新，可应用于系统，以阻止可用于加载GRUB2含漏洞版本的shims。由于有可能导致系统无法启动或以其他方式破坏操作或恢复工作流程，这些dbx更新最初将提供给感兴趣的各方手动应用到他们的系统，而不是推送撤销条目并自动应用它们。这将使IT专业人员、爱好者和其他人员有机会在其个人系统上测试撤销更新，并在强制撤销之前确定任何问题。

 

此外，组织应确保他们有适当的能力来监控UEFI引导加载器和固件，并验证系统中的UEFI配置，包括撤销列表。组织还应该在更新可用时测试恢复能力，包括 UEFI 设置中的 "重置为出厂默认值 "功能。这将确保他们能够在设备受到更新的负面影响时恢复设备。最后，组织应该监控他们的系统，以防止威胁和勒索软件利用脆弱的引导加载器来感染或破坏系统。
