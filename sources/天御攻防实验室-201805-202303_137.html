1.背景

    迅猛增长的加密流量正不断改变着威胁形势。随着越来越多的企业实现全数字化,大量的服务和应用都采用加密技术作为确保信息安全的首要方法。更具体地说,加密流量同比增长已超过 90%,对流量进行加密的网站数量已从 2015 年的 21% 上升到 2016 年的超过 40%。据 Gartner 预测,到2019 年,80% 的网站流量都会被加。


    遗憾的是目前主流的NIDS无法直接对加密流量进行检测。当然对于加密流量也不是没有办法，我们今天主要分享第一种方式（软件sslproxy），如果有公司赞助，我们会放出基于机器学习的方法。

3.基于sslproxy检测加密流量威胁

3.2 原理

    网关部署SSLPROXY（Inline SSL模式），所有经过网关的加密流量由SSLPROXY解密，然后发送给IDS（Bro/Snort/Suricata）分析。
3.3 实战

# 环境说明：
网关：
IP地址：192.168.8.2
接口0：加密流量
接口1：解密后的流量
OS：Kali
NIDS：
IP地址：192.168.8.3
Bro/Snort/Suricata
内网主机：
IP地址：192.168.8.x
OS：CentOS 7.x
# 配置：
# 1.网关
openssl genrsa -out ca.key 4096
openssl req -new -x509 -days 1826 -key ca.key -out ca.crt
echo 1 > /proc/sys/net/ipv4/ip_forward
iptables -t nat -F
# 把所有443端口的流量重定向到8443端口（SSLPROXY监听的端口）
iptables -t nat -I PREROUTING -p tcp --dport 443 -j REDIRECT --to-ports 8443
# SSLPROXY监听8443端口，把解密的流量发到NIDS主机：192.168.8.3
sslproxy -D -k ca.key -c ca.crt -l connect.log -L sample.log https 0.0.0.0 8443 -T 192.168.8.3 -I 接口1
# 2.NIDS：
启动Bro/Snort/Suricata即可
# 3.内网主机：
ip route change default via 192.168.8.2 dev ens192 proto static metric 100
curl -I https://www.tianyulab.com -k
echo "1.1.1.1 www.tianyulab.com" >> /etc/hosts
# 恢复默认路由
systemctl restart NetworkManager
