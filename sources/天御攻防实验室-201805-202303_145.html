1.What's Rule Profiling（规则分析）

2.配置

2.1编译选项


./configure --enable-profile --enable-file-inspect --enable-sourcefire --enable-debug --enable-gdb
理论上只需要--enable-sourcefire（包含--enable-perfprofiling and --enable-ppm）

2.2 Snort.conf 配置


vi /etc/snort/snort.conf
config profile_rules: \
        print [all | <num>], \
        sort <sort_option> \
        [,filename <filename> [append]]
# 解释
all，表示所有（是默认值）
<num>，规则号或10，20..N标识Top 10..N
<sort_option>，可以是checks，matches，nomatches，avg_ticks，avg_ticks_per_match，avg_ticks_per_nomatch，total_ticks
<filename>，输出文件名，保存在snort日志目录，如果没有配置，默认会在snort退出时打印在console
[append]，附加，如果没有配置，默认是会在filename后面加上时间戳

2.3 配置举例


1.打印所有rules,以avg_ticks排序(此为默认配置)
# config profile_rules
2.打印所有rules,以avg_ticks排序，结果附加到rules_stats.txt
# config profile_rules: filename rules_stats.txt append
3.根据最高平均时间打印前10个规则
# config profile_rules: print 10, sort avg_ticks
4.打印所有规则，按检查次数排序
# config profile_rules: print all, sort checks
5.根据总时间打印前100个规则
# config profile_rules: print 100, sort total_ticks

2.4 输出解读


# Microsecs == Ticks == 微秒
Checks:(在fast pattern匹配引擎或any -> any规则之后，评估规则的次数）
Matches:(匹配规则的次数，对于没有选项的规则将为高）
Alerts:(此规则生成的警报数）
CPU Ticks：CPU cycles（CPU周期）
Avg Ticks per Check：每次检查的平均微秒数
Avg Ticks per Match：每次匹配的平均微秒数
Avg Ticks per Nonmatch：每次不匹配的平均微秒数
1.Avg/Check 其值如果比较大，表示此规则性能比较差，通常包含PCRE
2.High Checks和low Avg/Check，对于包含规则选项但是没有content的any -> any规则是正常的
