**一，Docker 镜像**

  

Docker镜像是UnionFS(联合文件系统)，是一种分层、轻量级并且高性能的文件系统，它支持**对文件系统的修改作为一次提交来一层层的叠加**，同时可以将不同目录挂载到同一虚拟文件系统下。  

**1.1 Docker 镜像加载原理**  

docker的镜像实际上由一层层的文件系统组成，bootfs主要包含bootloader和kernel，bootloader主要是引导加载kernel，Linux刚启动时会加载bootfs文件系统，在Doceker镜像的最底层是bootfs。这一层与我们典型的Linux/Unix系统一样，包含boot加载器和内核。当boot加载后，整个内核就在内存中，内存的使用权由bootfs转交给内核，此时系统会卸载bootfs。

rootfs,在bootfs之上，包含的就是linux的目录文件。

分层结构的好处是：共享资源，即镜像的每一层都可以被共享。

## ****二，Docker 容器数据卷****

  

## 

将运用与运行的环境打包形成容器运行，运行可以伴随容器，但是我们对数据的要求要求持久化。容器之间希望共享数据。

Docker容器产生的数据，如果不通过docker commmit生成新镜像，容器删除后，数据将会消失。为了保存数据在Docker中使用卷。

特点：容器数据持久化和容器间继承+共享数据

• 数据卷可在容器之间共享或重用数据

• 卷中的更改可以直接生效

• 数据卷中的更改不会包含在镜像的更新中

• 数据卷的生命周期一直持续到没有容器使用它为止

###   

### ****2.1 数据卷命令操作****  

直接命令添加数据卷

docker run -it -v /宿主机绝对路径目录:/容器内目录 镜像名  
数据共享：添加成功后可在宿主机路径下操作，无论容器是否开启，达到操作容器的功能，实现数据共享  
  
docker run -it -v /宿主机绝对路径目录:/容器内目录:ro 镜像名  
主机单向写入，容器内目录：只读

 

dockerFile添加

Docker image==>DockerFile  
  
1、根目录新建目录   
    mkdir mydocker  
2、可在Dockerfile使用VOLUME指令来给镜像添加一个或多个数据卷  
    VOLUME\["/容器内目录","/容器内目录","/容器内目录"\]  
3、File构建(dockerFile脚本)  
    FORM centos  
    VOLUME\["/容器内目录","/容器内目录"\]  
    CMD echo"finished,-----sussess"  
    CMD /bin/bash  
4、build后生成镜像  
    docker build -f /mydocker/DockerFile -t test    -f指定将打包的目录 \-t指定镜像名  
5、run生成的容器  
    没有指定宿主机，在容器内创建文件，会在宿主机的Docker的默认目录共享

### ****2.2 数据卷容器****  

命名的容器挂载数据卷，其它容器通过挂载这个（父容器）实现数据共享，挂载数据卷的容器，称之为数据卷容器。

1、以同一个镜像运行多个容器，dc1/dc2/dc3。在dc1上创建一个文件夹，想要创建dc  

2、也拥有这个文件夹，只需要继承dc1即可。  
继承的命令：docker run -it --name dc2 --volumes-from dc1  镜像名  
    dc1/dc2/dc3同时共享，父到子，子到父都能共享。  
    dc1删除后，dc2/dc3正常使用，正常共享  
        新建dc4继承dc3，dc1/dc2/dc3都共享给dc4  
        容器间的配置信息传递，数据卷的生命周期一直持续到没有容器为止。

## ****三，Docker 解析 ****

  

DockerFile是用来构建Docker镜像的构建文件，是由一系列命令和参数构成的脚本。

构建的3步骤：

    1、手动编写一个dockerfile文件，文件符合file的规范。

    2、docker build命令执行，获得一个定义的镜像

    3、docker run  

  

### ****3.1 DockerFile构建过程解析****  

**DockerFile内容基础：**

  1、每条保留字指令都必须为大写字母且后面要跟随至少一个参数。  
  2、指令按照从上到下，顺序执行。  
  3、#表示注释。  
  4、每条指令都会创建一个新的镜像层，并对镜像进行提交。

  

**Docker执行DockerFile的大致流程：**

  1、docker从基础镜像运行一个容器，  
  2、执行一条指令并对容器作出修改  
  3、执行类似docker commit的操作提交一个新的镜像层  
  4、docker基于新的镜像运行一个新容器  
  5、执行DockerFile的下一条指令直到所有指令都执行完成。  

  

![](../Images/fd7cc869dfd90ffd7efbd1b9b8ed3d98.png)

  

### ****3.2 DockerFile 保留指令****  

**FROM：**基础镜像，当前这个镜像是基于哪个镜像  
**MAINTAINER：**镜像维护者的姓名和邮箱地址  
**RUN：**容器构建时需要运行的命令  
**EXPOSE：**当前容器对外暴露出的端口  
**WORKDIR：**指定在创建容器后，终端默认登陆的进来工作目录，一个落脚点  
**ENV：**用来在构建容器中设置环境变量  
**ADD：**在宿主机目录下的文件拷贝进镜像且ADD命令会自动处理URL和解压tar压缩包  
**COPY：**从构建上下文目录中的《源路径》的文件/目录复制到新的一层的镜像内。COPY src dest/COPY \["src","dest"\]  
**VOLUME：**容器数据卷，用于数据保存和持久化工作  
**CMD：**指定一个容器启动时要运行的命令。DockerFile中可以有多个CMD指令，最后一个生效，CMD会被docker run 之后的参数代替  
**ENTRYPOINT：**指定一个容器启动时要运行的命令。ENTRYPOINT和CMD目的一样。都是指定容器启动时的参数。不会被docker run 覆盖,追加命令时使用。  
**ONBUILD：**当构建一个被继承的DockerFile时运行命令，父镜像在被子镜像继承后父镜像的onbuild被触发。

### ****3.3 案例  
****

Base镜像（scratch）:Docker Hub中几乎所有的镜像都是通过base镜像中安装和配置需要的软件构建出来的。

**案例一：**

自定义镜像：  
1、新建一个文件，写入dockerfile语句。  
  FROM centos  
  MAINTAINER zzyy<zzyy11@163.com>  
  ENV MYPATH /usr/local  
    

  WORKDIR $MYPATH  
  RUN yum -y instll vim  
  RUN yum -Y install net-tools  
  
  EXPOSE 80  
  CMD echo $MYPATH  
  CMD echo "success---ok"  
  CMD /bin/bash  
2、生成新镜像  
  docker build -f /文件名 \-t 新镜像名字:版本号 .  #.表示当前路径 \-f 当前目录下可省略  
3、docker history 镜像名 查看镜像历史

  

**案例二：**

1、新建一个文件，写入dockerfile语句。  
  FROM centos  
  RUN yum install -y curl  
  CMD "curl" ,"-s","http://ip.cn"  
2、生成新镜像  
  docker build -f /文件名 \-t 新镜像名字:版本号 .  
3、docker history 镜像名 查看镜像历史

  

**案例三：**

1、新建一个文件，写入dockerfile语句。  
  FROM centos  
  MAINTAINER zzyy<zzyy@163.com>  
  COPY c.txt /usr/local/cincontainer.txt   #把宿主机当前上下文的c.txt拷贝到容器/usr/local路径下  
  ADD jdk.gz /usr/local/  #把java和tomcat添加到容器中  
  ADD apche.gz /usr/loacal/  
  RUN yum -y install vim   #安装vim编辑器  
  ENV MYPATH /usr/local  #设置容器运行时访问的路径  

  WORKDIR $MYPATH  
  ENV JAVA\_HOME /usr/local/jdk1.8  #配置java与tomcat环境变量  
  ENV CLASSPATH $JAVA\_HOME/lib/dt.jar:$JAVA\_HOME/lib/tools.jar  
  ENV CATALINA\_HOME /usr/local/apache-tomcat-9  
  ENV CATALINA\_BASE /usr/local/apache-tomcat-9  

 ENV PATH $PATH:$JAVA\_HOME/lib:$CATALINA\_HOME/lib:$CATALINA\_HOME/lib  
  EXPOSE 8080  #容器运行时监听的端口  
  #ENTRYPOINT\["/usr/local/apache-tomcat-.../bin/startup.sh"\]  #启动时运行tomcat  
  #CMD\["/usr/local/apache-tomcat-.../bin/startup.sh","run"\]  
  CMD /usr/local/apache-tomcat-9/bin/startup.sh && tail -F /usr/local/apache-tomcat-9/bin/logs/catalina.out  
  
2、生成新镜像  
  docker build -f /文件名 \-t 新镜像名字:版本号 .  
  
3、生成新的容器  
docker run -d -p 9080:8080 --name myt9 -v /zzyyuse/mydockerfile/tomcat/test:user/local/apache-tomcat-9/webapps/test -v /zzyyuse/mydockerfile/tomcat/tomcatlogs/:user/local/apache-tomcat-9/logs --privileged=ture zzyytomcat   -v 将主机的目录挂载到容器的目录下

### ****4.2 发布   
****

  

镜像空间的管理中有发布的命令

![](../Images/20ff3d1946f4bef3fc32c18939843ae8.png)

  

**登录阿里云Docker Registry**

$ sudo docker login --username=wt\*\*\*\* registry.cn-hangzhou.aliyuncs.com

用于登录的用户名为阿里云账号全名，密码为开通服务时设置的密码。

您可以在访问凭证页面修改凭证密码。

**从Registry中拉取镜像**

$ sudo docker pull registry.cn-hangzhou.aliyuncs.com/roderickzome/roderickimages:\[镜像版本号\]

**将镜像推送到Registry**

  $ sudo docker login --username=wt\*\*\*\* registry.cn-hangzhou.aliyuncs.com  

$ sudo docker tag \[ImageId\] registry.cn-hangzhou.aliyuncs.com/roderickzome/roderickimages:\[镜像版本号\]  

$ sudo docker push registry.cn-hangzhou.aliyuncs.com/roderickzome/roderickimages:\[镜像版本号\]

请根据实际镜像信息替换示例中的\[ImageId\]和\[镜像版本号\]参数。

**选择合适的镜像仓库地址**

从ECS推送镜像时，可以选择使用镜像仓库内网地址。推送速度将得到提升并且将不会损耗您的公网流量。

如果您使用的机器位于VPC网络，请使用 registry-vpc.cn-hangzhou.aliyuncs.com 作为Registry的域名登录。

**示例**

使用"docker tag"命令重命名镜像，并将它通过专有网络地址推送至Registry。

$sudo docker images  

REPOSITORY     TAG     IMAGE ID     CREATED     VIRTUAL SIZEr  

egistry.aliyuncs.com/acs/agent   0.7-dfb6816   37bb9c63c8b2  7 days ago   37.89 MB  

$ sudo docker tag 37bb9c63c8b2 registry-vpc.cn-hangzhou.aliyuncs.com/acs/agent:0.7-dfb6816

  

使用 "docker push" 命令将该镜像推送至远程。

$ sudo docker push registry-vpc.cn-hangzhou.aliyuncs.com/acs/agent:0.7-dfb6816
