1.1 Docker是什么


Docker 是一个开源的应用容器引擎，让开发者可以打包他们的应用以及依赖包到一个可移植的镜像中，然后发布到任何流行的 Linux或Windows机器上，也可以实现虚拟化。容器是完全使用沙箱机制，相互之间不会有任何接口。将开发人员的镜像（整体环境、系统、代码、数据等都打包) 放到容器内。


 

之前在windows服务器安装了一系列环境，配置，软件等，到了Linux又需要重新安装。Docker的出现，透过镜像将作业系统核心除外，运行应用的系统环境，由下而上的打包，从而达到跨平台的运行。

 

Docker的主要目的 Build,Ship and Run Any App,Anywhere.也就是通过对应用组件的封装、分发、部署、运行等生命周期的管理，使用户的APP及运行环境能够做到“一次封装，到处运行”


Docker 解决了运行环境和配置问题软件容器，是方便做持续集成并有助于整体发布的容器虚拟化技术。

 

1.2 Docker能做什么

• 传统的虚拟机会模拟硬件和操作系统的全部环境，Docker的虚拟化技术只会虚拟化精华部分，保证软件的正常运行即可。

• 一次构建，随处运行。更快速的应用交付和部署，更便捷的升级和扩容，更简单的系统运维，更高效的计算资源利用。

 

1.3 Docker安装

条件

Windows和Linux都可以进行安装。

Docker运行在Centos7要求系统为64位，内核3.10以上

Docker运行在Centos6.5以上要求系统为64位，内核2.6.32以上

 

Docker的架构图

Docker基本组成

镜像（image）：就是一个只读模板，镜像可以用来创建Docker容器，可创造多个容器。相当于类。

容器(Container)：独立运行的一个或一组应用。容器是用镜像创建的运行实例。容器的定义和镜像一摸一样，也是一堆层的统一视角，唯一区别在于容器的最上面那一层是可读可写的。

仓库（repository）:集中存放镜像文件的场所。仓库和仓库注册服务器（Registry）是有区别的。仓库注册服务器存放多个仓库，每个仓库中又包含了多个镜像。仓库分为公开仓库和私有仓库。

最大的公开库：https://hub.docker.com

 

总结

Docker本身是一个容器运行载体或称为管理引擎。我们把应用程序和配置依赖打包形成一个可交付的运行环境，这个打包好的运行环境就相当于image镜像文件。你有通过镜像文件才能生成Docker容器，image可以看作容器的模板。一个镜像可生成多个容器。至于仓库，就是存放镜像的地方，我们可以把镜像发布到仓库里，需要的时候从仓库拉下来。

 

安装步骤

以Centos6.5安装
$ yum install -y epel-release
$ yum install -y docker-io
配置文件：/etc/sysconfig/docker
启动Docker后台服务：$ service docker start
验证：$ docker version

以Centos7安装
https://docs.docker.com/engine/install/centos/

$ sudo yum install -y yum-utils
$ sudo yum-config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo
$ sudo yum install docker-ce docker-ce-cli containerd.io
配置文件：/etc/docker/daemon.json
启动Docker后台服务:$ sudo systemctl start docker

二，使用方法


2.1 帮助命令

docker info  查看docker信息
docker --help


2.2 镜像命令

docker images 查看本机镜像文件，显示中REPOSITORY：表示镜像仓库源，TAG：表示镜像的标签，IMAGEID：镜像ID，CREATED：镜像创建时间，SIZE：镜像大小
options
    -a：列出本地所有镜像（含镜像中间映像层）
    -q:显示镜像ID
    --digests:表示镜像的摘要信息
    --no-trunc:显示完整的镜像信息

docker search ImageName  在https://hub.docker.com上搜索镜像
options
    --no-trunc:显示完整的镜像描述
    -s:列出收藏数不小于指定值的镜像
    --automated:只列出automated build类型的镜像

docker pull ImageName 等价于 docker pull ImageName:lastest 拉取镜像到本地

docker rmi -f ImageName  等价于 docker rmi ImageName:lastest 删除单个镜像
docker rmi -f ImageName ImageName1 ImageName2 删除多个
docker rmi -f $(docker images -1a) 删除全部镜像
options
    -f：强制删除
   

2.3 容器命令

拉取镜像后才能生成容器,以centos为例
docker pull centos

新建并启动容器
docker run
options
    --name="容器新名称"：为容器重命名
    -d:后台运行容器，并返回容器ID，也即启动守护式容器
    -i:以交互模式运行容器，通常与-t同时使用
    -t:为容器重新分配一个伪输入终端，通常与-i同时使用
    -P：随机端口映射
    -p:指定端口映射，有以下四种格式
        ip:hostPort:containerPort
        ip::containerPort
        hostPort:containerPort
        containerPort


docker run -it centos

列出所有正在运行的容器
docker ps     显示中CONTAINER ID：容器ID，IMAGE：镜像ID，COMMAND：命令方式，CREATED：创建时间,STATUS：容器状态（up,down）,POTRS:端口号，NAMES:随机命名
options
    -a:列出当前所有正在运行的容器+历史上运行过的容器
    -l:显示上次运行的
    -n:显示最近n个创建的容器
    -q:静默模式，只显示容器编号
    --no-trunc:不截断输出

退出容器
exit 容器停止
Ctrl+P+Q 容器不停止退出

重启容器
Docker restart 镜像ID/镜像名

停止容器
docker stop 容器ID/镜像名

强制停止容器
docker kill 容器ID/镜像名

删除已停止的容器
docker rm 容器ID/镜像名   -f可选关闭正在运行容器

一次删除多个容器
docker rm -f $(docker ps -a -q)
docker ps -a -q | xargs docker rm

重要指令

启动守护式容器
docker run -d 镜像名  后台运行容器，并返回容器ID，也即启动守护式容器，docker ps 查不到容器，前台无应用，后台已经自动退出。

查看容器日志
docker logs -f -t --tail 容器ID -t是加入时间戳 -f跟随最新的日志打印 --tail 数字 显示最后多少条

查看容器内的进程
docker top 容器ID

查看容器内部细节
docker inspect 容器ID

进入正在运行的容器并以命令行交互
docker attach 容器ID 进入容器
docker exec -t 容器ID ls -l /tmp 在宿主机执行命令

从容器内拷贝文件到主机上
docker ps 容器ID:文件绝对路径 宿主机路径
