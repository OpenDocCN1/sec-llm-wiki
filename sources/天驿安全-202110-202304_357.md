#### 0x01:前言  

目标是一大学，在一次挖洞过程中遇到个sql注入，尝试进一步利用扩大危害，漏洞已报送平台进行了修复

#### 0x02:sql注入getshell失败

在id处连续加两个单引号都报错，经过探测发现是数字型的注入且过滤了空格，这里可以用/\*\*/代替  

![](../Images/dd1420e750cf08b340616f4fa0a82115.png)

![](../Images/e96a3a6323230cdd5d1c4cab8ff60d7b.png)

于是直接上sqlmap  

```
python sqlmap.py \-u url \--batch \--tamper\=space2comment.py –dbs

```

![](../Images/d94fb09f29d1f15d5deb1898a71bb068.png)

发现是dba权限：  

```
python sqlmap.py \-u url \--batch \--tamper\=space2comment.py \--is\-dba

```

![](../Images/2a2d793844f7a4fb6a34152c990d74ef.png)

试了很多方法找web路径  
最后注意到操作系统是FreeBSD  
无意中看到这个  

![](../Images/a5cf26c623644aba8777ac9cd8a50a47.png)

char(47)就是’/’，立马想到可以通过这个遍历目录、找路径  

![](../Images/71735dae9099cea3934af453c3a49ad7.png)

通过从根目录开始逐层遍历，最终找到网站根目录：  

![](../Images/d3f215683543417c34b0e7198cf8cdf9.png)

写入shell失败，转换成16进制规避单引号还是不行  
但是这个注入可以读取服务器上的任意敏感文件（包括非web目录），危害巨大  

#### 0x03:从其它点继续尝试

读取sql注入处代码，发现并没有代码层面的过滤，explode() 函数把字符串打散为数组，这里以空格为分隔，取数组的第一个，变相地过滤了空格，把空格换成内联注释就能注入  

![](../Images/073348576e63d0f4f6caddeac399a857.png)

根据泄露的数据库账号、密码尝试连接3306端口失败，估计绑定了本地ip  
继续遍历目录，发现了mysql的登陆界面  

![](../Images/03099cd6a1c47ff81f99ec89222bd93c.png)

登录之后却是空白界面，读取处理登录逻辑的代码发现登陆成功直接设置session但不跳转，登陆后直接访问首页就行  
查一下secure\_file\_priv，发现是空值，并没有限制  

![](../Images/2f09eb993d8d10bedcc3ed9248f09d8c.png)

尝试利用日志写入webshell，发现没有权限设置日志路径  

![](../Images/ed71a46711c656a6c12c6c2c95bd7724.png)

  
找到了网站后台  

![](../Images/2fa7429f7546258d98be2a8ac3332be7.png)

数据库里面查到的账号和密码hash值  
在线网站解密hash值得到明文  
登录失败，读取一下源码

![](../Images/6b783dc06310fec2c211c8d02e5ab78c.png)

  

![](../Images/4fb10ff472d37dd092afcee84c7a617a.png)

发现是加了盐的，于是加盐再解密得到正确密码  
成功登陆后在人員資料管理新增处发现一个上传照片的地方  

![](../Images/f0a8d48475e8ef6dcb35b80d57ee938f.png)

但是只能上传图片文件  

![](../Images/ba78364d1ea8b39f2d4b1ba0875eac5f.png)

上传成功之后，突然想到了sql写shell失败是不是因为目录权限问题，网站限制了除上传目录外其它目录都不可写？  

于是尝试写入shell  

![](../Images/ac51799432ca35faed4db41cfb109018.png)

成功，果然是目录写权限问题  

![](../Images/0a56edde3131cb14d8ab27b21bc77697.png)

发现蚁剑连不上，估计waf拦截了流量。看了一下蚁剑的流量加密，蚁剑流量有一个重要特征就是User-Agent为antSword/版本，另外使用了编码器的话还要将解码函数发过去，所以解码函数这里也是一个特征，需要自定义编码器和解码器。  
修改antSword-master/modules/request.js和antSword-master/modules/update.js两个文件的User-Agent后成功连接，waf仅仅拦截了UA这一明显特征  

![](../Images/76fb81e1fad1675a3a5d056823a59e9b.png)

反弹shell失败，nc是基于tcp/udp协议的，所以可能的原因有：反弹的命令不存在、禁止出站IP、禁止tcp协议出站端口  
确认sh存在：  

![](../Images/d56ebf256195d1bb466762afb3b34248.png)

出站端口为访问外网，查询网络连接发现54454端口可以出站  

![](../Images/d68d082804c0b7c6e5e133839decd45c.png)

于是监听54454端口后成功反弹shell  

![](../Images/bca77a413b701f60de48e1dd4ed0fbf1.png)

提权失败。服务器内核版本过高，无法利用内核漏洞提权，尝试计划任务、环境变量、和suid提权发现没有可以利用的地方，sudo提权也不行，第三方服务中udf提权发现插件目录不可写，几个文件权限也配置正常，也没有发现其它敏感信息泄露
