Javassist
分析ysoserial代码前，先补充一点Javassist操作字节码的知识。

Javassist 就是一个用来处理 Java 字节码的类库。它可以在一个已经编译好的类中添加新的方法，或者是修改已有的方法，同时也可以去生成一个新的类对象，通过完全手动的方式，相对来说学习成本较低，当然也可以使用效率更加高效的ASM来处理。

常用类：

  • Javassist.CtClass 表示类文件，一个CtClass对象可以处理一个class文件。

  • Javassist.ClassPool 表示一个基于哈希表（Hashtable）实现的CtClass对象容器，其中 key 是类名称，值是表示该类的CtClass对象。

  • Javassist.CtMethod 表示类中的方法，通过CtMethod对象可以实现对方法的修改。

  • Javassist.LoaderClassPath类是用于通过 getResourceAsStream() 在java.lang.Class 中获取类文件的搜索路径。

例如：
ClassPool pool = ClassPool.getDefault();   CtClass cc = pool.get("test.Veraxy");  cc.setSuperclass(pool.get("test.Haha")); cc.writeFile();

首先获取了一个 ClassPool 对象，使用 getDefault() 方法表示使用的是默认系统的类搜索路径。使用 ClassPool.get() 方法来从 ClassPool 中获得一个类名为“test.Veraxy”的 CtClass 对象，调用 setSuperclass() 方法将 test.Veraxy 的父类设置为 test.Haha。writeFile() 会将 CtClass 对象转换成类文件并写到本地磁盘。

Java代理
下文代码中涉及Java动态代理实现，这里学习一下什么是动态代理，以及为什么要有动态代理。


静态代理

提到动态代理，可以先研究一下什么是静态代理。

假设现在项目经理有一个需求：在项目现有所有类的方法前后打印日志。

你如何在不修改已有代码的前提下，完成这个需求？

首先想到的解决方案是静态代理。


怎么做？


1.为现有的每一个类都编写一个对应的代理类，并且让它实现和目标类相同的接口


2.在创建代理对象时，通过构造器塞入一个目标类实例对象，然后在代理对象的方法内部调用目标对象同名方法，并在调用前后打印日志。

代理对象 = 增强代码 + 目标对象（原对象）。



静态代理缺陷：程序员要手动为每一个目标类编写对应的代理类，如果当前系统有成百上千个类，工作量也太大了。如何少写或者不写代理类，优化代理功能呢？


JVM创建对象的过程

A a = new A()


JVM执行这行代码时，会有以下流程：

1.类加载检查

当虚拟机遇到 new 指令时，首先会去检查这个指令的参数是否能在常量池中定位到一个类的符号引用，并且检查这个符号引用代表的类是否已被加载、解析和初始化过。如果没有，先执行类加载过程。

2.为对象分配内存

在Java堆中划分一块大小确定的内存空间。

3.内存空间初始化

将分配到的内存空间都初始化为零值，这一步保证了对象实例字段在Java代码中可以不赋初值就直接使用，程序能访问到这些字段的数据类型所对应的零值。

4.对象信息初始化

JVM设置对象头信息，如类元数据信息、对象的哈希码等

5.执行对象方法

此时，对于JVM来说，对象已经产生，对于Java程序来说，执行方法进行初始化完毕，一个对象才算真正创建完成。

注意区分Class类是描述类的，如Person类、Student类。在创建对象的过程中，首先要有具体的Class类对象，才能有类的实例对象。


思考如何简化获取代理类以及代理对象的过程：可以不写代理类，通过某种方式生成代理Class类对象，然后用它直接创建代理实例对象。


动态代理

通过上文的分析引出动态代理做的事情，动态代理实际上实现了在运行期动态创建某个接口的实例。

JDK提供了java.lang.reflect.InvocationHandler接口和java.lang.reflect.Proxy类，两者相互配合，入口是Proxy。


Proxy中提供的getProxyClass()静态方法可以用来获取一个代理Class对象，其接受的参数为类加载器和目标类实现的接口。这个方法会从你传入的接口Class中，“拷贝”类结构信息到一个新的Class对象中，新的Class对象带有构造器，是可以创建对象的。

public static Class<?> getProxyClass(ClassLoader loader, Class<?>... interfaces)



在代理类中，会向构造器中传入一个目标类对象的引用，代理对象的内部有个成员变量invocationHandler 用来接受它，而且代理对象的每个方法内部都会调用handler.invoke()。此时 InvocationHandler对象成了代理对象和目标对象的桥梁，不像静态代理这么直接。

实际编程中还有更方便的方法，Proxy类提供的另一个静态方法newProxyInstance()可以直接获取代理实例对象，连创建代理类对象的过程都封装起来了。

public static Object newProxyInstance(ClassLoader loader, Class<?>[] interfaces, InvocationHandler h)h: 一个InvocationHandler对象，表示的是当动态代理对象调用方法的时候会关联到哪一个InvocationHandler对象上，并最终由其调用。

例子：

public class ProxyTest {  public static void main(String[] args) throws Throwable {    CalculatorImpl target = new CalculatorImpl();    Calculator calculatorProxy = (Calculator) getProxy(target);    calculatorProxy.add(1, 2);    calculatorProxy.subtract(2, 1);  }  private static Object getProxy(final Object target) throws Exception {    Object proxy = Proxy.newProxyInstance(        target.getClass().getClassLoader(),  //获取类加载器        target.getClass().getInterfaces(),  //获取目标类实现的接口        new InvocationHandler(){  //默认会执行代理对象的invoke方法          public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {            System.out.println(method.getName() + "方法开始执行...");            Object result = method.invoke(target, args);            System.out.println(result);            System.out.println(method.getName() + "方法执行结束...");            return result;          }        }    );    return proxy;  }}

7u21反序列化利用点

LinkedHashSet.readObject

LinkedHashSet里面的方法都是调用了其父类HashSet中的方法，但是之所以不直接用HashSet的原因是LinkedHashSet里数据的下标和我们插入时的顺序一样，而HashSet顺序就不一样了。


LinkedHashSet继承了的父类HashSet的同名方法，即LinkedHashSet.readObject()

有一个for循环，将LinkedHashSet中的每个元素都反序列化


关注readObject中for循环的第二轮，即遍历HashSet的第二个元素，动态代理生成的Proxy对象，进入LinkedHashMap.put()方法，此时参数key为动态代理生成的Proxy对象，value为新建的Object对象。


大概流程就是判断key和k的hash是否一致 如果不一致则证明是一个新的元素，加入到当前的HashMap对象中，如果hash一致，则判断该元素是否存在于当前的HashMap中，如果存在则返回oldValue，如果不存在则加入当前HashMap对象中。


此时的key指向的是通过动态代理生成的Proxy对象，因为生成Proxy对象时传入的参数是InvokcationHandler的子类AnnotationInvocationHandler，所以会调用AnnotationInvocationHandler.invoke()方法。

invoke()方法中对方法名进行判断，由于上一步调用的是"equals"方法，所以进入该分支，后面会走equalsImpl，var3[0]是TemplatesImpl实例对象

public V put(K key, V value) {

    if (key == null)

        return putForNullKey(value);

    int hash = hash(key);

    int i = indexFor(hash, table.length);

    for (Entry<K,V> e = table[i]; e != null; e = e.next) {

        Object k;

        if (e.hash == hash && ((k = e.key) == key || key.equals(k))) {

            V oldValue = e.value;

            e.value = value;

            e.recordAccess(this);

            return oldValue;

        }

     }


    modCount++;

    addEntry(hash, key, value, i);

    return null;

}

  • if语句中根据逻辑短路原理，必须让e.hash == hash为true，并且(k = e.key) == key为false，才能执行到最后一个表达式equals
