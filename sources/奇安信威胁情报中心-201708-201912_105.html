Bluehat是微软专门针对全球Windows系列产品的安全研究者打造的一场安全会议，自2005年，已经在美国微软总部及以色列举办了多次。2019年5月29-30日，Bluehat也首次进入中国，在魔都上海开幕，此次 BlueHat 安全大会主要是面向中国以及亚太地区的白帽子、安全工程师和安全从业者的一个专注于漏洞挖掘、响应与防护的安全大会。

 

作为微软在中国的长期合作伙伴，奇安信（Legendsec）也受邀参加了此次会议，接下来笔者将和大伙分享一下首届Bluehat中国大会的旅程。

5月29日当天的议题一共有10个，笔者接下来会就各个议题给大伙带来简单的分享，由于笔者本身只是漏洞和恶意代码相关的研究人员，其中一些议题并没有涉猎，因此如有疏漏，请各位读者多多包涵，另由于中国的演讲人员名字在微软官网只显示了拼音，为保证对演讲人员的尊重，防止误念，下文中都统一以安全研究员代替，如果笔者熟悉的安全人员，会直接使用对应的姓名。

 

首先第一个议题来自于微软的Eric Doerr先生，作为主办方的开幕致辞，其主要分享了多年来微软MSRC相关的安全建设，并对中国各个长期合作的安全厂商进行了致谢。

接下来是来自于中国CNCERT的老师带来的2018年中国网络安全态势的总结议题，该议题对整个2018年中国网络安全的各个方面进行了权威的整理汇总（图中有幸被引用的数据也来源于笔者所在团队，由于品牌更替，目前已更名为奇安信威胁情报中心，RedDrip Team）。

 

第三个议题来自绿盟科技的张云海老师的议题，

” Liar Game: The Secret of MitigationBypass Techniques”，该议题主要总结演讲者在过去多年针对微软漏洞缓解机制对抗中的经验，从最早的DEP一直到现在的CIG，用最通俗的语言还原了整个对抗过程，干货满满。

 

第四个议题来自于微软公司的Christian Seifert，“Advances in Machine Learning at Microsoft Threat Protection”，这个议题主要介绍了最近几年来微软内部通过机器学习来解决威胁防御的进展，有意思的是演讲过程中PPT抽风了，Christian Seifert是在全场PPT疯狂切换的情况下完成了演讲。


到此上午的议题结束，经过一场丰盛的W自助，具体就不放实图了，我们进入下午的议题。

下午一开始的两个议题都来自于平底锅Palo Alto Networks的安全研究员，“Is my Container Secure? - Large-Scale Empirical Study on ContainerVulnerabilities”

“Advanced Lateral Movement on KubernetesCluster”

放在一块是因为这两个议题都选取了Docker容器这个方向，第一个议题主要对现有的Docker 容器的问题经行了统计汇总，并针对企业中的相关容器安全提供了建议。而第二个议题就比较偏技术了，主要介绍了Kubernet中的相关的渗透技术，对相关技术比较感兴趣的渗透小伙伴可以了解一下。


下午第三个议题来自于阿里云的两位安全研究员，“Enhance SecurityAwareness with Data Mining: Data-driven Intrusion Detection Solutions inAlibaba Cloud”，主要介绍了阿里云在云上是如何针对暴力攻击，恶意行为链，恶意Web脚本，攻击载荷回溯等方向和攻击者进行对抗的经验。


第四个议题来自奇虎360 GearTeam的安全研究员，"From Dvr to See Exploit of IoT Device"，这个议题主要详细介绍了一款IOT设备漏洞从挖掘到利用的过程，对于希望在IOT方向上启程的同学是个不错的参考，同时这个议题也是目前为止气氛最为活跃的一个演讲。


第五个议题来自于韩国的安全研究员，"Betrayal ofReputation: Trusting the Untrustable Hardware and Software withReputation"，由于当时有事儿，这个议题笔者只听了后续的小部分，其主要介绍了英特尔可信执行技术（TXT）和可信平台模块（TPM），并介绍了演讲者发现的两个睡眠过程相关的漏洞CVE-2017-16837和CVE-2018-6622，这两个漏洞可以在没有物理访问的情况下破坏TPM。

 

下午最后一个议题来自于百度的X-Lab实验室的安全研究员，"MesaTEE SGX: Redefining AI and Big Data Analysis with IntelSGX"，这个议题主要介绍了如何通过Rust语言为因特尔SGX开发一系列内存安全库，从而使得用户在这套开源项目上轻松开发英特尔SGX应用程序，而这套开源项目也在开源社区中收到了不少区块链相关用户的青睐。


至此，2019年5月29日的Bluehat大会内容基本完毕，就笔者个人而言最获益匪浅的是张云海老师微软漏洞机制相关的议题，可以看到当天这几个议题的方向还是比较多的，从漏洞到Docker，再到IOT，基本覆盖当下比较热门的方向，而5月30号，笔者将带来更多Bluehat相关的议题的最新实况。

 

当然今晚最刺激的还是鸡尾酒会，由于太过于刺激，笔者就不放图了。


5月30日

今天进入大会的第二天，同时也是笔者比较感兴趣的一天，因为今天的议题中包含了大量漏洞及高级威胁相关的议题，进入会场前我们先来看看经过一天之后的CTF战况如何，果然哪里都有alert呀。

大会第二天一共有9个议题，如上所述大部分为漏洞及高级威胁相关。

 

上午第一个议题来自于微软的David Weston，“Advancing Windows Security”，作为微软的Windows设备安全和攻击性安全研究团队的负责人，David Weston就Windows最新的安全特性和未来和在座的听众进行了分享，除了漏洞利用上的缓解机制的更新，还包括Windows上权限及对应固件上相关的安全性的更新升级。


第二个议题来自于信工所和清华大学的老师，“Exploring the Maze ofMemory Layouts Towards Exploits”，该议题主要介绍了如何通过自动化的方式实现由POC到EXP的过程，目前这套系统已经实现了针对大多数CTF题目的测试。


第三个议题来自于360高级威胁团队的安全研究人员，“Needle in A Haystack: Catch Multiple Zero-Days Using Sandbox”，该议题讲述了这一团队如何从零构建沙箱，到最终捕获多起0day攻击事件的相关经验，作为同样的捕获过Flash 在野0day的RedDrip Team 一员，笔者深知这一过程的困难，也从中借鉴到不少经验，强烈将这一议题推荐给各位高级威胁相关的研究人员。

 

上午最后一个议题来自于百度的安全研究人员，”How to Find TwelveKernel Information Disclosure Vulnerabilities in Three Months”，该议题主要讲述了演讲者是如何在三个月发现12个内核信息泄露漏洞，其思路主要是通过hook污染内核堆/栈，并在用户态检测的方式来监控是否存在对应的内核信息泄露问题。这一发掘方式并不是常规的Fuzz，只要计算机运行即可自动发现，和之前360一位安全研究员的打一场游戏就发现多个CVE有异曲同工之妙（笔者一时想不起是哪位研究人员了，欢迎读者指正），对于内核漏洞研究的同学可以了解一下。


下午的第一个议题来自于卡巴斯基的安全研究人员，“Momigari: Overviewof the Latest Windows OS Kernel Exploits Found in the Wild”，卡巴斯基团队近两年发现了多起0day的在野攻击事件，尤其擅长于对Windows内核提权漏洞的捕获，该议题介绍了其内部是如何实现这一成果的，并针对其中几个内核漏洞进行了相关的分析，也强烈推荐给各位高级威胁相关的同仁。


下午第二个议题来自于百度的安全研究人员，"New and EffectiveMethods to Probe Vulnerabilities in Hardware Devices"，该议题详细介绍了智能硬件中研究方法，包括各个类型芯片的焊接处理，各种网络连接的嗅探和编辑方法，包括WiFi实时解密，挂钩模式和GPRS中间人攻击，并展示如何结合这些方法并最终发现控制设备中的高风险漏洞，对硬件安全有兴趣的小伙伴可以研究一下，演讲者PPT中有各种详细介绍及Tips。

 

下午的第三个议题来自于趋势的安全研究人员，“Browser Script EngineZero Days in 2018”，该议题主要就2018年浏览器脚本引擎相关的漏洞进行了总结，包括flash/vbs/jscrip及Chakra这几个类型的漏洞，同时介绍实现了一套VBS相关的去混淆工具，同时可以实现VBS脚本中上帝模式及ROP相关操作的检测，对于Windows下脚本引擎漏洞感兴趣的同学可以研究一下。


第四个议题来自微软的安全研究人员，"Fighting MaliciousInsider Threat with User Profile Based Anomaly Detection"，这个议题主要介绍了通过Windows Office 365如何基于历史数据来检查内部的恶意行为。


下午最后一个议题来自于数学工程与高级计算国家重点实验室及清华大学老师带来的议题，

“Discovering Vulnerabilities with Data-FlowSensitive Fuzzing”，该议题主要分析了市面上类AFL相关Fuzz工具的缺点，并在此基础上推出的一款新型的基于数据流控制的Fuzz工具，挖到了多个CVE漏洞，并在性能上有所提升。
