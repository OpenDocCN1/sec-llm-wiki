0x01  什么是模糊测试

模糊测试是一种软件测试技术，主要通过自动、半自动的方式产生未预期的数据输入到程序中，并通过监视软件的状态，行为等，来发现计算机程序的缺陷，比如内存错误，内存泄漏等，常用于发掘软件安全漏洞。

模糊测试常用于黑盒测试，模糊测试工具主要分为三类，分别是基于生成的fuzzer、基于变异的fuzzer和反馈演进的fuzzer。

基于生成的fuzzer 根据用户的定义的配置文件规则来自动生成对应的样本，输入到程序中进行测试，而基于变异的fuzzer 则是由用户提供的样本，对这些样本进行变异，如：字节翻转，比特翻转，增加减小等变异策略，最后将变异后的样本输入到程序中执行，看看程序是否发生未预期的行为。反馈演进的fuzzer 主要根据程序执行样本的代码覆盖率来反馈性的变异样本，从而来达到更高的覆盖率。

0x02  获取样本

样本的来源可以由自己开发生成器来生成，对于一些著名开源软件，其自身也携带了一些提供测试的原始样本，比如:在项目ffmpeg 中，http://samples.ffmpeg.org 就提供了用于测试的样本集，模糊PDF 文件格式时，可以从开源项目PDFium 中获取PDF 测试样本。较为方便的方法，直接在google 上面通过匹配文件格式和文件magic 来获取对应文件格式的样本。收集到越多的测试样本越可能提高代码覆盖率，进而提高发现漏洞的概率。

0x03  代码覆盖

在模糊测试中，很重要一个概念代码覆盖率，代码覆盖率讲的是，样本输入到程序中，程序所执行的指令在程序全部指令中的覆盖情况，一个好的样本覆盖率往往有较高的覆盖率。fuzzer 在计算代码覆盖率通常有以下几种：

1.编译时插桩

对于有源码的情况，直接在编译时插入用于标志的代码，较流行的AFL fuzzer 使用afl-gcc 来编译目标源码，afl-gcc 实际是一个gcc wrapper ，在编译时插入既定的汇编可用于记录代码执行的情况。

AFL

cur_location = <compile_time_random_value>; bitmap[(cur_location ^ prev_location) % BITMAP_SIZE]++; prev_location = cur_location

2.二进制插桩

在无源码的情况下，可以使用二进制插桩来获取代码覆盖的情况，如：pin、DynamoRIO 工具。这里推荐个lighthouse IDA插件，可以可视化代码覆盖情况。如：使用DynamoRIO 来进行可视化获取代码覆盖情况：

> drrun -t drcov -- /bin/ls @@

3.基于硬件

第六代Intel 处理器开始具有Intel Processor Trace(https://github.com/intelpt)功能，可以用于追踪程序执行的代码覆盖的情况。。如:honggfuzz 就使用Intel PT技术。

4.使用0xcc 断点来手工获取代码执行的情况

0x04 精简化样本

在将样本投入测试前，还要对样本进行精简化，以减小对fuzzer 效率的影响，过滤掉低覆盖率的样本，减小无用的模糊。对于AFL ，可以使用afl-cmin 来简化样本。

0x05 运行程序

对于命令行界面的程序直接通过参数的方式将样本传入，而对于图形界面的程序，从打开到载入样本执行这一过程代价较高，其实我们可以选择一个攻击面选择某个dll 或函数去写一个wrapper 来fuzz，这就需要动用一些逆向工程方法来逆向找到感兴趣的接口。在Linux 系统中，通过execve 来创建新的进程代价仍然过高，为此，AFL 实现fork server 机制，通过在编译时期嵌入的fork server 代码，程序在运行时接受AFL 发出的fork 指令来进行fork 新的子进程，并结合共享内存shm 的方式来提高fuzzer 效率。除此之外，AFL 还可以通过并行执行，持续模糊等方式来提高效率。

0x06 变异

dumb fuzz 讲的是使用毫无规律的策略来进行模糊测试，这种策略效率低下，找到漏洞的概率很小。那么如何变异样本以获得更高的代码覆盖率呢？在什么地方变异以及如何来变异呢？我们知道如：要模糊网络协议，网络协议一般有一些固化的标志，如果fuzzer 变异这些标志，对应程序处理直接将样本drop 掉，那么我们不可能去变异这部分，而在不去了解协议内容或是不去逆向协议的情况下，如何更好的避开这些标志，这就可以通过代码覆盖率来进一步指导样本变异，即反馈演进fuzz。其变异的算法有：

1.bitflipping 比特翻转，从1 bit 到连续4 bit 进行翻

2.byteflipping 字节翻转，使用随机的字节代替特定的字节

3.special ints 插入宽度为2和4的特殊的整数用不同的字节序

4.add subtract binary 在随机位置处加上减去随机的数

5.chunk spew 将输入中的一个数据块取出放入另一个位置

6.append/truncate 在样本的末尾添加随机的活基于现有的数据，或者截断为特定的大小

还有radamsa 变异引擎https://gitlab.com/akihe/radamsa

0x07 检测

在模糊测试过程中，检测异常，未预定的行为直接关系fuzzer 效率。不同的漏洞导致程序出现不同的行为，漏洞可以导致程序发生崩溃，但也可以不导致崩溃，对于一些逻辑漏洞，越权漏洞，程序出现以管理员行为来执行某操作，漏洞是存在的也并没有导致程序崩溃，又如条件竞争，有可能在某些情况下会出现崩溃现象，也有可能不会。所以在检测崩溃情况上较为容易，像AFL 直接设置handler

  /* Various ways of saying "stop". */

sa.sa_handler = handle_stop_sig;

sigaction(SIGHUP, &sa, NULL);

sigaction(SIGINT, &sa, NULL);

sigaction(SIGTERM, &sa, NULL);

/* Exec timeout notifications. */

sa.sa_handler = handle_timeout;

sigaction(SIGALRM, &sa, NULL);

针对于LLVM，可以使用一些sanitizers 来进行检测，如：Address-Sanitizer，在使用clang 编译时加上-fsantize=address，用于检测OOB 漏洞，UAF 等；memory-sanitizer，编译参数为-fsanitize-memory，用于检测未初始化内存，UndefinedBehaviorSanitizer, 编译参数为 -fsanitize=undefined，用于捕获为定义的行为。

也可以通过编写调试器，WinDbg 插件、监控日志的形式来检测。不同的程序可以采用不同的方式来检测，这又可以讲上几天。
