# **前言**

# 近日，360安全监测与响应中心根据客户的反馈捕获到一种新型HTA格式木马，经过分析发现攻击者用来制作HTA样本的就是CactusTorch无文件攻击框架，该框架可以生成js、vbs、hta、vbe等多种格式的攻击样本并执行自定义shellcode，值得注意的是，目前很多杀软并没有关注CactusTorch框架使用的加载方式，导致杀软对CactusTorch生成的样本查杀非常不力，而国内杀软目前只有360及瑞星可以查杀此框架生成的样本

**0x01  技术分析 **  

  

我们将会通过此次捕获的HTA样本对CactusTorch框架使用的加载技术进行分析，HTA样本MD5为1181acaec859f9f0f4b65624086e1a4b

  

CactusTorch将一个注射器dll序列化并Base64编码后存储在脚本中，HTA样本执行后，首先将dll数据Base64解码并反序列化，这样就得到了一个在内存中的注射器dll，此样本中dll名为SharpRoman.dll

  

  

![](../Images/f0f365ca61f9f211b8e29e213e0e8fbe.png)

之后通过DynamicInvoke的方式调用内存中注射器dll的Start函数，传入三个参数分别为压缩并编码后的shellcode，要注入的进程名，shellcode支持的CPU架构，其中第三个参数为样本作者加入，原版CactusTorch并没有这个参数  

  

![](../Images/d063a93b9bf26d249f635a19b9579e4d.png)

编写代码将dll解密并dump后发现并没有混淆，可以直接使用dnspy导出源码为VS工程从而便于分析

  

![](../Images/0a0179aa9fbe2dae2bf4b9bb8e06c813.png)

SharpRoman.Dll的Start函数调用Light函数进行CPU架构判断，注入目标进程路径拼接等准备工作之后调用Inject函数进行注入，注入方式为经典的挂起进程注入

  

![](../Images/c7a4759cb40bfbe20cbcfb0ab0010084.png)

  

被注入的shellcode通过经典的TEB->PEB->LDR->InMemoryModule的方式获取API地址，之后通过WinInet.dll中的InternetOpen系列函数从https\[:\]//api.zixcorp.app/XUcl下载第二阶段shellcode

  

  

![](../Images/d5dc0a1af958ca2ca438b4ce6c5947f7.png)

经分析二阶段数据为shellcode + 加密数据，最前面0x46字节的shellcode负责解密0x46偏移后的数据

  

![](../Images/fdec64c54b1ec5d4c2262d3448cdeade.png)

从数据的0x4B偏移开始为加密数据，数据结构如下:

  

| struct CodeData**{**    DWORD dwInitXorCode**;** // 初始密钥    DWORD dwLength**;**    // 加密数据的长度    Byte**\*** bData**;**  // 加密数据内容**}** |
| --- |

  

  

![](../Images/a2fe942021b43b2d6f298944d6487a5e.png)

解密后的文件为DLL文件，从导出表可见使用了反射加载技术，导出模块名为beacon.dll，疑似为cobalt-strike的payload

  

![](../Images/4647822c059d51d603f115374027d729.png)

  

分析发现样本会将0x10032030开始，大小为0x1000的数据通过0x69异或解密，解密后为cobalt-strike的配置文件

  

![](../Images/0ec5125dc02ed65fd5f8f2f3434f85e0.png)

解密后可以看到通信C&C地址，URL，User-Agent等配置信息

  

![](../Images/40621c7e3fd931d33325e6db7aca03e5.png)

此次捕获的cobalt-strike样本使用https与C&C通信
