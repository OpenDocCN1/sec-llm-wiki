【安全预警通告】Windows WPAD/PAC 远程代码执行漏洞

近日，谷歌的安全研究团队发现了一个Windows 默认开启的WPAD服务的远程代码执行漏洞，可导致Windows 系统被攻击者远程控制，且最高权限被攻击者远程窃取。



01

—


漏洞描述


Windows 默认开启的 WPAD 服务将从网络中获取PAC文件并解析执行。PAC文件本质上是一个 Javascript 文件，WPAD 服务获取到此文件后，将使用一个存在漏洞的的 Js 解析引擎（jscript.dll） 来解析此 PAC 文件。PAC 文件中的恶意代码将在低权限账户下被执行，与其他本地提权漏洞配合使用时，可导致Windows 系统被攻击者远程控制，且最高权限被攻击者远程窃取。



02

—


风险等级


360安全监测与响应中心风险评级为：高危

预警等级：蓝色预警（一般网络安全事件）




03

—


影响范围


理论上该漏洞影响所有主流 Windows 版本，但目前未见有成熟的利用工具出现。

—


处置建议


目前微软官方已经在每月公布的例行补丁中修复了此漏洞，请及时下载并更新。需要注意的是，谷歌发布的报告中提到微软的补丁并不能保证以后完全没问题。360安全监测与响应中心将持续关注该漏洞并第一时间为您更新最新情况。


临时处置手段：


1.  将注册表中 HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\WinHttpAutoProxySvc 的‘Start’值改为 4，以禁用 WPAD 协议。

2.  禁用自动代理，避免被攻击者利用。

技术分析


WPAD （网络代理自动发现协议）


该协议所使用的配置文件为 PAC 格式的文件，PAC 本质上是 Javascript 文件。


Windows 系统默认启用此协议以自动查找网络中存在的WPAD服务器，并下载并解析其 PAC 文件。


Windows 可通过以下方式查找网络中的 WPAD 服务器并获取 PAC 文件：


  • 通过 DHCP


Windows 系统利用 DHCP 获取 IP 地址时，Windows 会DHCP 服务器回发的 DHCP OFFER/DHCP ACK 报文中的 Option 252 指定的 URL 处下载 PAC 文件。


攻击场景：攻击者可以内网中模拟 DHCP 服务器，并通过 Option 252 向客户端发送恶意 PAC 文件的链接。导致此 PAC 文件中的恶意代码在客户端被执行。 


  • 通过 DNS/NETBIOS/LLMNR


Windows 利用 DNS 解析 WPAD 并尝试获取其 PAC 文件。如果 DNS 解析失败 ，则会同时使用 NETBIOS（或 WINS） 与 LLMNR 对 WPAD 进行解析并尝试获取其 PAC 文件。


攻击场景：攻击者可以利用 DNS 污染的方式，将 WPAD 解析到攻击者可控的 IP，并向客户端提供恶意的 PAC 文件，导致PAC 文件中的恶意代码在客户端被触发。


  • 通过 WPAD.tld


Windows 将尝试以递归的方式解析 wpad 与当前机器的计算机名的拼接，并获取 PAC 文件。如当有计算机名为 bb.aa.company.com，由 Windows 将尝试利用 DNS 解析以下域名：

  • wpad.aa.company.com

  • wpad.company.com

  • wpad.com


获取到 PAC 文件后，Windows 将利用存在漏洞的 jscript.dll 来解析此文件。 Jscript.dll 在早年被 IE7/IE8 用来解析网页中的 Javascript 代码。


攻击场景：

攻击者可提前注册相关的恶意域名，并提供恶意的 PAC 文件供客户端下载，导致恶意的 Javascript 代码在客户端被执行。
