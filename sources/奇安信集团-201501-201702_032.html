安全领域的人机对抗赛

实际上，以人工智能技术为基础的人机对抗比赛，并非只发生在棋类比赛，以及某些纯粹娱乐性的电视节目中。2016年8月，在安全领域进行的一场人工智能机器对抗赛以及随后进行的人机对抗赛，也同样引起了整个安全领域的高度关注，使人们对人工智能技术在安全领域及网络攻防中的应用有了一个全新的认知。

这两场引人关注的安全大赛，分别是机器大赛CGC（Cyber Grand Challenge），以及由CGC大赛夺冠系统首次参与的，人类顶级黑客夺旗赛DEF CON CTF决赛。两场比赛均在美国拉斯维加斯举办，CGC决赛是8月4日举行的， DEF CON CTF决赛则是在8月5日举行的。也就是说，为机器大赛设计的攻防系统在夺冠之后，其研发团队可能并没有充分的时间对其进行人机对抗的改造设计，就让该系统参加了一场高水平的人类对抗赛。

但令人兴奋的是，尽管CGC的冠军Mayhem系统在2天半的DEF CON CTF决赛中最终成绩垫底，但其在比赛首日缺赛1天的情况下，仍然在第二天的比赛结束时领先了两支人类参赛队，在14+1支参赛队伍中，排名第13。而且根据人类战队的赛后反馈，Mayhem系统对某些人类战队认为很难利用的漏洞生成了有效攻击。

机器战队在人机对抗赛中的出色成绩与表现，使我们有理由相信：网络安全领域正在向智能化全面迈进。下面，我们就来详细介绍一下CGC大赛与DEF CON CTF大赛，以进一步分析人工智能技术在在安全领域应用的现状与前景。

01

CGC大赛

CGC是DARPA（Defense Advanced Research Projects Agency，美国国防部的一个下属研究机构）于2013年发起的全球性网络安全挑战赛，是DARPA为前沿科技拓展所设计的多项全球竞赛之一。CGC旨在推进自动化网络攻防技术的发展，即实时识别系统缺陷、漏洞，自动完成打补丁和系统防御，并自动生成攻击程序，最终实现全自动的网络安全攻防系统。DARPA为了推动自动攻防技术的研究，专门构建了这样一个已有两年多历史的比赛，希望鼓励人工智能技术在信息安全领域的尝试和发展。

CGC的比赛过程全部由计算机组成，无任何人为干预。所以，CGC是机器之间的CTF（Capture The Flag，夺旗赛）比赛。该赛事希望通过推动自动软件攻防的能力，推进全自动的网络安全攻防系统发展，最终使机器达到超越人的自动攻防能力。

CGC自2013年12月发布以来，共有来自全球100多支战队参加了角逐，到2015年夏天，有7支队伍获得了决赛资格。 2016年8月4日举办的是 CGC的决赛，是由七支决赛队伍带来的他们各自设计实现了一年多的自动化攻防系统，通过一个全自动的，无人工干预的比赛，决出机器比赛的冠军。

最终，由来自美国卡内基梅隆大学（Carnegie Mellon University，CMU）研究团队For All Secure研发的自动攻防系统Mayhem在CGC决赛中获胜。虽然在随后的DEF CON CTF比赛中， Mayhem系统最终在与人类战队的比赛中排名垫底，但是机器表现出来的潜力得到广泛认可。

CGC的技术亮点和挑战都是系统的全自动化，其主要的难度在于如何在无限的状态下尽快找到触发漏洞的输入，尤其是在复杂输入和有不确定因素（例如随机数生成）等情况下。同时比赛还要对发现的漏洞进行自动修复并生成攻击。CGC 比赛成功展示了当前机器系统在攻防上的能力，其具体表现又可以分为以下两个方面：

首先是漏洞的发现能力。参加决赛战队的系统都展示了自动发现漏洞，修复并生成攻击的能力。决赛工程中，多数系统在几分钟的时间内可以发现关键漏洞，例如很多参赛的自动系统都能够模拟曾经发生过的 Heartbleed、Slammer和 Glibc Address Resolution 等著名安全事件，同时会为相关程序生成补丁修复漏洞，并成功防范对应的攻击。

第二是漏洞利用能力。发现了漏洞之后，还要有能力生成有效的攻击代码，才能真正成功夺旗。这一点在CGC冠军Mayhem后来参加的 DEF CON CTF 决赛中表现的更加明显。Mayhem不仅解决了大部分比赛中给出的问题，而且根据人类战队赛后的反馈，机器还对某些人类战队认为很难利用的漏洞生成了有效攻击。

2016 年进行的CGC比赛标志着网络安全领域迈向智能化的开始。CGC比赛的结果展示了计算机系统自动进行漏洞发现和防御，自动化修补和攻击生成的能力。在简单环境中，自动系统比人类有明显的速度优势和应对大量攻击的能力。但面对复杂问题时，自动系统目前还无法与人类专家抗衡。CGC 比赛的举办开启了智能化自动攻防的深入研究。

02

DEF CON CTF大赛

DEF CON CTF是目前全球知名度最高，影响力最广，且历史悠久的CTF竞赛，已经举办了24届，相当于安全竞赛领域的“世界杯”。其主要特点是题目复杂度高，偏向实际软件系统的漏洞挖掘与利用。

DEF CON CTF分为线上的预选赛和线下的决赛，线上预赛采用解题模式，通常在每年的5月份面向全球安全团队开放；而现场决赛采用攻防模式，通常在每年的8月份于美国拉斯维加斯举行。

线上预赛排名前列的队伍才能够入围拉斯维加斯的现场决赛。虽然说是预赛，但是题目难度一点都不低，题目类型以二进制程序分析和漏洞利用为主，Web安全和杂项题只占非常少的比例，尤其近年来的趋势更是如此。

而除了参加预选赛这种方式外，还能通过参加其他“外卡赛”入围决赛。这些外卡赛通常也是一些质量很高的重量级竞赛，比如2016年就包括有32C3 CTF、Boston Key Party、HITCON CTF、PlaidCTF、RuCTFE、0CTF、SECCON CTF等，只有获得这些竞赛的冠军才能够获得DEF CON CTF决赛的入场券，所以难度也非常高。

最终入围现场决赛的队伍通常为15-20支，每年数量不一定相同，依据规则而定。而决赛采用的是攻防模式的竞赛，这比起解题模式的初赛来说，不同参赛队之间的强弱差距会变得异常明显。顶尖强队通常是一种压制全场的王者姿态，在初始分几千的情况下最终得分可以到数万甚至数十万之多；中等水平的强队则只能在守好自己的前提下尝试去弱队身上捞一点分数，最终得分通常都在初始分上下；而弱队在强队的碾压之下则往往毫无喘息之机，更不用谈还手之力了，每年都会有若干支队伍难逃被血刷成零分的命运。DEF CON CTF决赛的残酷性也由此可见一斑。

决赛的题目类型仍然以二进制漏洞利用为主，难度会比预赛的题目更高。所以DEF CON CTF整个竞赛更注重选手在二进制程序分析方面的实力，而不太像国内的大多数传统安全竞赛主要考察选手在Web和渗透方面的实力。

来自清华大学的Blue-Lotus战队于2013年成为首支成功入围DEF CON CTF决赛的中国战队，其后来自台湾的HITCON战队于2014年成为第二支入围决赛的中国战队，来自上海交通大学的0ops于2015年成为第三支入围决赛的中国战队。在2016年的DEF CON CTF决赛中，由中国Blue-Lotus战队和0ops战队组成的b1o0p联队斩获全球第二名的佳绩，这也是中国战队在DEF CONCTF赛场上创造的最好成绩。

由此可以想见，CGC的冠军Mayhem，在首次参加水平如此之高的DEF CON CTF的情况下，能够阶段性的压制部分人类高手，已实属不易。同时，考虑到人工智能的“学习”速度常常快于人类，机器在网络攻防战中，战胜人类也是一种可以期待的现实。

CGC与人工智能安全技术发展趋势

CGC的首届自动攻防比赛对于安全领域的意义类似于1970年的首届机器国际象棋比赛。虽然CGC系统的初期表现还没有迹象能够全面超越人类黑客的能力，但自动系统用于安全攻防实践可能来的很快。就像无人驾驶技术在三届Grand Challenge比赛之后，技术成熟程度就已经很清晰了。

在CGC成功举办之后，人工智能至少会在以下几点引发安全领域研究的变革：

首先，自动系统将会开始替代人力来完成重复性强的安全攻防工作，例如部分软件逆向以及漏洞挖掘工作。在漏洞挖掘自动化的研究中，将符号执行（Symbolic Execution）与模糊测试（Fuzzing）结合已经成为一个学术届认可的研究方向。CGC比赛中多支战队采用了这个方法。360 公司研发设计的自动漏洞发现系统也使用了这种技术来提高自动测试及分析程序的能力。

CGC带来的另外一个变革是对系统分析的智能化。自动测试在CGC比赛之前也已经被工业界大范围采用，但分析的系统化和智能化在赛后开始得到了更多的重视。例如我们的研究发现：通过对二进制程序的特定部分重写（例如分拆复杂的分支跳转条件）会提高漏洞挖掘的效率。在这方面 360公司已经实现了一些实例，包括对复杂条件判断和一些常用库函数的重写，并已经有在常用模糊测试工具（例如AFL）上的成功扩展。

DARPA对安全自动化的推进也会促进对系统弱点进行智能预测的研究。例如，当需要分析大量程序的时候，要首先判断哪些程序模块或者流程更容易出现问题，尤其是哪些部分含有易被强大的对手发现并利用的漏洞。这类风险预测有很多数据可以作为参照，例如程序复杂度，开发人员过往表现，程序风格，使用框架等等。

CGC也会促进安全对抗环境中的自动决策和博弈的研究。

自动攻防系统将会面临很多策略型选择，包括如何从多种防御方式中选择或组合形成最有效的防御手段。例如对于每个发现的漏洞，自动防御系统可以通过种方法对潜在的攻击进行防范。比如，利用网络防火墙规则对攻击进行过滤，或者是对有缺陷的程序进行修补。但这两个防御措施都有各自的利弊。在探索每个自动防御措施的同时，自动系统还需要考虑如何在不同应用场景中自动调配防御方案，以达到安全防御和高效无误判的目标。

博弈策略的研究对于一个攻防透明的对战环境也尤为重要。例如，一个加固了的程序一旦被对手获得，对手就有可能会复用自己编写的补丁，所以自动系统在完成了补丁编写的情况下，还需要考虑修补系统的时机，以及是否在补丁中增加自动混淆甚至是后门。反过来，当一个有效的攻击生成完成之后，在正式发起攻击前还需要考虑对手可能通过攻击回放的手段来发现相关漏洞并复制自己的攻击。

总而言之，CGC已经开启了人工智能在安全领域应用的一个新纪元。在接下来的几年里，相信我们还会看到更多的自动系统的新应用，以及自动系统和人类在安全领域中的有机结合。
