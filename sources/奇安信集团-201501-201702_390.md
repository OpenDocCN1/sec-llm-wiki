# RubyGems严重漏洞可导致恶意应用的安装

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzU0NDk0NTAwMw==&mid=2247490802&idx=2&sn=5d3f239f8d8b62faae088efb667f9966&chksm=fb753af6cc02b3e0a13db4b1cbad3ed08393e9030b68a5616a68fe2426560ee88aab8424893b&scene=126&sessionid=1681374184#rd](http://mp.weixin.qq.com/s?__biz=MzU0NDk0NTAwMw==&mid=2247490802&idx=2&sn=5d3f239f8d8b62faae088efb667f9966&chksm=fb753af6cc02b3e0a13db4b1cbad3ed08393e9030b68a5616a68fe2426560ee88aab8424893b&scene=126&sessionid=1681374184#rd)

**RubyGems****是由Ruby语言编写的包管理器，Trustwave研究员已发现其存在这一具有严重危害性的漏洞，该漏洞可被恶意用户利用，进而安装恶意软件，这些恶意软件来源于攻击者控制的gem服务器。**

  

该漏洞每天大概可影响120万软件，此数据是在OpenDNS安全研究员Anthony Kasza的协助下统计的。RubyGem被许多商业应用使用包括start-ups，社交网站和付款网关公司。  
  

Ruby gem是一种标准的包格式，它被使用于发布Ruby库和应用。Gem由开发人员推动到gem服务器，用户可在其服务器中下载它们。

  

“RubyGems客户端有一种'Gem Server Discovery'功能，它使用一DNS SRV请求来发现gem服务器。这种功能不需要DNS从相同的安全域（初始的gem源）中响应，进而让攻击者控制的gem服务器随意重定向。”安全研究员解释道。

  

“CVE-2015-3900漏洞允许攻击者将某一使用HTTPS的RubyGem客户端重定向到攻击着控制的gem服务器；这有效地绕过了攻击者控制的原HTTPS gem源的授权。这意味着攻击着可强制用户安装恶意/木马gems。

  

开发者对他们的Ruby gems签名可能可以缓解这种风险，但是无法彻底避免。在五月中旬，RubyGems开发者提供了一种修复方案，它确实能解决此类问题。

  

因为研究员发现了一种新的漏洞，攻击者利用该漏洞可将用户重定向到域（原安全域，如：attackercontrolledrubygems.org），所以也需要另一种解决方案。6月8日已修复了第二个bug。

  

研究人员指出：“这些问题影响RubyGems客户端和任意嵌入了RubyGems客户端的环境。已确认Ruby, JRuby, 和 Rubinuius都嵌入了RubyGems客户端并且都受CVE-2015-3900的影响。”

  

已建议用户们升级到最新版本，但是记住升级到已修复版的RubyGems（使用一样有漏洞的功能）的机制，因此在安全的网络环境中升级是一种好想法。

  

“在野外”并没有发现利用那些漏洞的攻击案例，但这仅仅是短时间内的调查，因此建议用户尽快升级。

  

在建议将gem的“producers”签名的同时，也让用户确认所有Ruby gem源使用HTTPS，进而让用户可以有效识别它们。
