# 安全预警 | 思科ASA安全设备发现远程执行代码和拒绝服务漏洞（第二次更新）

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzU0NDk0NTAwMw==&mid=2247490236&idx=2&sn=01f1e98f98b86cc046243fb630e91d2e&chksm=fb753cb8cc02b5aef7c7ba6b2fcbc22dbdc809899577a10705898c620ee40b70225e9aaae402&scene=126&sessionid=1681373942#rd](http://mp.weixin.qq.com/s?__biz=MzU0NDk0NTAwMw==&mid=2247490236&idx=2&sn=01f1e98f98b86cc046243fb630e91d2e&chksm=fb753cb8cc02b5aef7c7ba6b2fcbc22dbdc809899577a10705898c620ee40b70225e9aaae402&scene=126&sessionid=1681373942#rd)

思科公司最近发布了针对ASA和FTD设备软件的补丁程序，该补丁修复影响ASA和FTD产品的SSL VPN功能存在的远程代码执行和拒绝服务漏洞。该漏洞影响版本基本覆盖了近8年的所有ASA, 新出的FTD产品也部分受影响。

  

攻击者可以发送精心构造的认证数据包到受影响系统来利用此漏洞，成功利用此漏洞会导致设备拒绝服务甚至执行任意代码而被控制。设备被控制以后会直接导致网络边界的安全被突破，攻击者可能操纵网络流量或以设备为立足点对内部网络执行进一步的攻击。

  

**1.1  背景**

思科ASA(Adaptive Security Appliance)是一款兼具防火墙，防病毒，入侵防御和虚拟专用网（VPN）功能的安全设备。

  

思科FTD(Firepower Threat Defense)是一个统一的软件映像，其中包括思科ASA功能和FirePOWER服务。这个统一的软件能够在一个平台上提供ASA和FirePOWER的硬件和软件的所有功能。

  

思科公司在周一发布了针对ASA和FTD设备软件的补丁程序，该补丁修复影响ASA和FTD产品的SSL VPN功能存在的远程代码执行和拒绝服务漏洞。该漏洞影响版本基本覆盖了近8年的所有ASA, 新出的FTD产品也部分受影响。

  

**1.2  漏洞描述**

该漏洞是由于在启用了webvpn服务的思科ASA设备上，程序未正确处理内存造成的。攻击者可以发送精心构造的认证数据包到受影响系统来利用此漏洞，成功利用此漏洞会导致设备拒绝服务甚至执行任意代码而被控制。设备被控制以后会直接导致网络边界的安全被突破，攻击者可能操纵网络流量或以设备为立足点对内部网络执行进一步的攻击。

  

之后攻击者可监视所有经过设备的网络数据、对内网进行渗透或利用设备对其他受害者做出DDOS攻击，当攻击者渗透进内网后，可窃取内网环境中的商业资料、商业情报、人员信息等敏感数据。

  

该漏洞获得CVE编号CVE-2018-0101，CVSS 评分为满分10分，因为它很容易遭利用，且漏洞利用无需用户验证。思科表示已注意到漏洞详情遭公开，不过指出尚未发现漏洞遭利用的迹象。

  

目前利用漏洞导致设备拒绝服务的POC已经公开，请在接下来几天时间内密切关注设备功能是否正常。

  

**1.3  触发条件**

\- ASA配置并使用了Webvpn特性；

\- webvpn暴露在Internet上，访问来源不可控；

\- ASA运行的版本是受影响的版本。

**1.7  技术分析**

在VPN用户登录时，用户信息会以XML格式发送认证数据包给asa服务器，在XML中认证信息用config-auth节点来表示。在服务器中对此数据包的处理，会调用aggregateAuthDataHandler函数来处理节点value，此函数以xml\_tag数组中来表示用户提交的信息，当处理节点中一个名为 host-scan-reply的子节点时，会分配一个大小为0x2000的内存并且此内存指针存放在xml\_tag数组的相应字段，之后程序会判断此次登录是否正确，若不正确则释放掉相应的host-scan-reply数据内存块。由于此时可能是用户不小心输入了错误的密码，故服务端用一次会话来标记此次登录，即保留xml\_tag来标记此次登录时的信息，注意，由于此时已经释放掉了host-scan-reply字段所在的内存区域，导致xml\_tag数组中相应的字段指向了一块已经释放的内存区域。在用户第二次发送了认证请求则进入第二次认证过程，程序继续使用刚才建立的xml\_tags数组来标记此次会话提交的数据，此时由于此字段指针值已经不为0而未重新分配内存，在之后认证不通过后，则释放此字段指定的内存区域时导致double free而产生错误。

  

由于此漏洞属于double free问题，利用时可“占坑“此内存，在认证结束后free掉此内存后可导致代码执行。
