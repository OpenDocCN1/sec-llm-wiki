# 解读|等保2.0的核心变化

引言

  

12月1日，等保2.0正式实施，标志着我国正式迈入了等保2.0时代。在上一篇文章中，我们对等保2.0内涵与定级备案重点进行了介绍，作为等级保护落地保证的技术要求，在等保制度2.0体系中，核心技术要求会有哪些变化呢？

  

![](../Images/8634651953b917eab0c1c5c3762bda44.png "分割线 gif 动图")

  

网络安全等级保护是我国信息安全保障的基本制度，是网络空间安全保障体系的重要支撑。等保2.0在技术上除了继续关注传统网络系统，重点对云计算、移动互联、物联网、工业控制以及大数据安全等进行全面安全防护，确保关键信息基础设施安全。

  

  

![](../Images/ff1358fedc15b2c95b529bd88e36e5cf.png)**一、架构调整**![](../Images/be100dce12170b8e8aaad4f7b5ee58a0.png)

  

  

  

从2014年公安部牵头修订，等级保护2.0在编制过程中总共经历了三次大的变化：

  

*   **第一次：**
    

为适应新的网络发展需要，从2015年草稿开始将基本要求（GB/T22239）、设计要求（GB/T25070）、测评要求（GB/T28448），加入云计算、物联网、移动互联、工业控制、大数据要求，并与基本要求一起，形成五个分册（分册不含大数据要求）；

  

*   **第二次：**
    

在2017年8月根据网信办和公安部的意见将基本要求、设计要求、测评要求三个标准的5个分册进行了合并，形成一个标准，并在2017年10月修订完成报批稿；

  

*   **第三次：**
    

在2018年7月根据专家的意见再次调整分类结构和强化可信计算，充分体现一个中心、三重防御的思想并强化可信计算安全技术要求的使用。

  

**调整后每一级的安全要求均包括安全通用要求，安全扩展要求（包括云计算安全、移动互联安全、物联网安全、工业控制系统）。**

*   针对共性化保护需求，安全通用要求提出，等级保护对象无论以何种形式出现，必须根据安全保护等级实现相应级别的安全通用要求；
    
*   针对个性化保护需求，安全扩展要求提出，需要根据安全保护等级和使用的特定技术或特定的应用场景选择安全扩展要求。
    

  

*   **云计算安全扩展要求：**
    

针对云计算提出特殊保护要求。对云计算环境主要增加的内容包括“基础设施的位置”、“虚拟化安全保护”、“镜像和快照保护”、“云服务商选择”和“云计算环境管理”等方面。

  

*   **移动互联安全扩展要求：**
    

针对移动互联提出特殊保护要求。对移动互联环境主要增加的内容包括“无线接入点的物理位置”、“移动终端管控”、“移动应用管控”、“移动应用软件采购”和“移动应用软件开发”等方面。

  

*   **物联网安全扩展要求：**
    

针对物联网提出特殊保护要求。对物联网环境主要增加的内容包括“感知节点的物理防护”、“感知节点设备安全”、“感知网关节点设备安全”、“感知节点的管理”和“数据融合处理”等方面。

  

*   **工业控制系统安全扩展要求：**
    

针对工业控制系统提出特殊保护要求。对工业控制系统主要增加的内容包括“室外控制设备防护”、“工业控制系统网络架构安全”、“拨号使用控制”、“无线使用控制”和“控制设备安全”等方面，针对工业控制系统实时性要求高的特点调整了“漏洞和风险管理”和“恶意代码防范管理”方面的要求。

调整后，标准正文已经没有明确的“技术要求”、“管理要求”提法，可以预见，在未来的网络安全建设中技术、管理将深度融合，也越来越难以区分。但通过内容，依然能够分辨相应的“技术部分”、“管理部分”（图中用颜色进行了区分），以下对两部分分别阐述。

  

  

  

*   **管理要求：**“从元素到活动”提出安全要求。“安全管理制度”、“安全管理机构”和“安全管理人员”主要提出了管理不可缺少的制度、机构和人员三要素，“安全建设管理”及“安全运维管理”主要提出了建设过程和运维过程的安全活动管理要求。这部分主体架构和1.0版本变化较小，主要吸收了1.0版本在工程实践中的经验，并结合新时期安全需求，进行了优化、更新、改名。
    
      
    
*   **技术要求：**“从面到点”提出安全要求。“安全物理环境”主要对机房设施提出要求，“安全通信网络”和“安全区域边界”主要对网络整体提出要求，“安全计算环境”主要对构成节点（包括业务应用和数据）提出要求，“安全管理中心”主要对系统管理、集中管控等提出要求。这部分几乎在逻辑上颠覆了1.0版本标准，原有标准参照NIST SP800-53等控制措施，以物理安全、网络安全、主机安全、应用安全、数据安全及备份恢复为控制措施分类，因而参照IATF制定的安全设计技术要求（GB/T 25070-2010）提出的一个中心、三重防护在基本要求中难以体现，等保建设方案与基本要求项难以调和。等保2.0现将这两个标准进行了统一。
    

  

  

![](../Images/ff1358fedc15b2c95b529bd88e36e5cf.png)**三、新增安全管理中心安全类别**![](../Images/be100dce12170b8e8aaad4f7b5ee58a0.png)

  

  

  

除了第一级要求外，新标准都引入“安全管理中心”作为单独的安全类别。包括系统管理、审计管理、安全管理、集中管理，核心思想包括三权监管、安全管理区域划分、网络安全设备组件管理、网络运行状况监测等，相应的配套标准《GB/T 36958-2018 网络安全等级保护安全管理中心技术要求》已于2018年12月28日发布，2019年7月1日开始实施。

  

  

![](../Images/ff1358fedc15b2c95b529bd88e36e5cf.png)**四、新增可信验证控制点**![](../Images/be100dce12170b8e8aaad4f7b5ee58a0.png)

  

  

  

对可信控制点有所增加，各个级别和层面均增加了可信验证控制点，从第一级到第四级均在“安全通信网络”、“安全区域边界”和“安全计算环境”中增加了“可信验证”控制点。

无论在新旧等保的制度中，并没有要求使用任何一种产品，仅仅只是要求网络安全空间达到一个什么样的安全程度的具体要求。但是制度如何实施？这需要根据网络运营者业务系统，结合风险、业务安全需求、合规等进行个性化设计、实施、运维。

  

  

进入等级保护2.0时代，复杂的网络应用与环境，业务安全需求越发明显，意味着等保1.0时代将网络安全产品数量和种类堆叠的思路势必逐步退出历史舞台。等保2.0建设中，在安全产品上，从安全体系的角度合理规划、合理建设、甚至适度精简，将资源投放在如何抵御网络安全风险上，同时建议在信息化建设的同时统筹考虑网络安全的建设，做到同步规划、同步建设、同步运营，做到全生命周期网络安全，打造以等保2.0为核心的网络空间安全时代。
