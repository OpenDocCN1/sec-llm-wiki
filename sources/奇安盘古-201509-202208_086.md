**\>\>\>\>>>>****USE-AFTER-USE-AFTER-FREE:EXPLOIT UAF BY GENERATING YOUR OWN**

![](../Images/559dd5e907b393e8748020f30d6b7e43.png)

![](../Images/42483b54fef943dd0c7e3346a0522499.png)

我的议题在第二天上午。议题除了介绍Flash中现有的缓解措施们，还详细讲解了一种在现有缓解措施下仍然可用的 use-after-free 的利用方法，虽然具有一定的通用性，但针对目标对象和临近对象需要很多逆向分析，掌握每个虚函数的行为。

对于mediacore包大家可能不太熟悉，这里简单介绍下哈。mediacore 由于采用新的堆分区，虽然没有公开文档，但逆向发现很多逻辑设计的不够完善，可以算是一个新的攻击入口点。利用代码中用到的例子是正是mediacore.psdk 的一个UAF，在 32 和 64 位环境下编写了完整的利用代码（下载地址：http://www.hhjack.com/psdk.zip）。目前使用 string 完成了反复释放和填充，实现了内存任意读，但如果可以用其他 array 结构替换 string 实现利用，将获得任意读写。

**\>\>\>\>>>>FLIP FENGSHUI: ROWHAMMERING THE VM'S ISOLATION**  

![](../Images/f0aeff4d99764d3165833cea9be5f091.png)  

rowhammer漏洞作为硬件产生的问题，软件厂商真是防也不是不防也不是。

演讲者展示了一种零知识情况下的虚拟机隔离级别代码执行（感觉还不够零，起码知道对方操作系统的一些基本情况），通过一定的暴力测试，攻击者在 A 虚拟机中对/etc/apt/trusted.gpg 和/etc/apt/source.list 进行位翻转测试。也就是通过高速不断读取这两个文件缓存所在的临近内存，造成内存电压泄露。通过发掘特定的读取顺序，找到合适的读取位置，进而翻转两个文件中的比特。

由于 B 虚拟机和 A 虚拟机对相同文件会使用同一物理内存，最终导致 A 可以影响 B 中的这两个文件内容。随后被修改了文件内容的 B 在进行 apt-get 时将安装 A 指定的不可信源和不可信的证书。最后 A 让 B 装了有后门的 ls 命令，取得的 B 的控制权。

![](../Images/72b51991ae4f75b1c134ec6e39d5f12e.png)

****\>\>\>\>>>>******EFFECTIVEFILE FORMAT FUZZING – THOUGHTS TECHNIQUES AND RESULTS**

![](../Images/c1f27922254f2258219163dfa652aafe.png)  

演讲者讲了非常多的内容，所以每一部分也不好太细致，基本上是他这几年 fuzzer 编写的技巧总结。比如他在测试 Flash 的 loader 函数时，由于代码覆盖率记录器出现尖峰增长，他发现了文档外 loader 所支持的新格式。

另外他在测试不同平台软件时，发现很多软件类似 ida pro 一样，有 accept-format 的函数，可以不启动软件就快速知道产生的测试样本是否可以被目标软件识别。基本上，他的幻灯片内容非常适合当字典一样索引查看每个经验总结。

![](../Images/c1d1b956c4580ba27926e1349a245ca4.png)

******\>\>\>\>>>>********ROOTING EVERYANDROID: FROM EXTENSION TO EXPLOITATION**

![](../Images/120ecdb5f17fa974dfc77d8841373528.png)  

议题围绕博通，联发科，高通的 wifi 芯片三个漏洞案例展开。这种接口普通用户就可以触发，特别是在 selinux 时代，是难得的内核入口。另外还说了下 google 最新缓解措施。

有趣的一点是，例子中栈溢出也可以利用，是因为编译模块的 gcc 版本不够，产生的代码不包含 stack cookie。发现中国人的英语更亲切，但外国人的英语更好懂哈。

![](../Images/356f6547b60918457f17d094a8deb255.png)

********\>\>\>\>>>>**********STUMPING THEMOBILE CHIPSET**

![](../Images/9b5f8414f50e135df04b75eeb13a95bd.png)  

估计是幻灯片做的最好的，构图很有设计感。适当的动画很好的说明了如竞争条件这样复杂的利用过程。不过讲的内容和他在 defcon 说的差不多。其中 CVE-2016-2059 事后也按他的思路试过一直没触发，后来自己用 read 文件造成的链表读和 ioctl 造成的链表写互相竞争才得以触发（但这样就不构成利用条件了）。

问了他本人，才知道他用的是 ioctl 和 close 的双线程路径来触发内存写。并且很肯定的说，利用过程 80% 会成功。感觉他的双线程需要按照特定顺序往复交替四次，比较苛刻，期间 还要heapspray，应该更多时候是崩溃才对呀。可惜的是，他说目前很多厂商还不修复，所以半年内都未必放出来代码。

**文末彩蛋**

这次Black Hat邀请了很多国际级黑客参与，有机会在世界级安全大会上分享自己的研究成果感觉好开心，还能与来自世界各地的安全研究人员沟通交流。最后分享下在Black Hat上一些有趣的见闻。

从上海起飞，辗转了10多个小时，来到了大洋彼岸的伦敦。下次记得一定要赶在工作日走，这样可以弄到一排三座一个人横躺的特殊待遇（或者干脆就买商务舱~）。伦敦彼时已经深秋，winter is coming，天气倍儿凉，但依然可见棉袄短袖齐飞的异景。会场里大小黑客叽叽喳喳的交流个不停，虽然一半听不懂，但入耳的熟悉词汇还是亲切感倍加。
