![](../Images/af6adf313b7a8b046fd7e940325ed3de.png)

就像上面的实验室中讨论的那样，在这种情况下，系统中也缺少库。如果是这种情况，可能有一些方法可以将恶意共享库加载或注入到进程中。

这次在 `/etc/ld.so.conf` 文件和 `/etc/ld.so.conf.d` 目录中找不到任何漏洞。在检查动态部分时，发现该文件包含设置为` /tmp/lib/` 目录的 `RPATH` 值。

## 加载顺序问题

在这个案例下，在寻找 `suid` 二进制文件时，发现安装了 `sudo` 但没有找到可疑的 `suid` 二进制文件。

![](../Images/e0803f0b23bf9ea4daac49cba311c4e0.png)

在检查当前的 `sudo` 权限时，一切看起来都正常，但 `env_keep+=LD_PRELOAD` 引起了注意。通常，父进程会向子进程传递环境变量，但在 `sudo` 的情况下，只向子进程传递在`env_keep`配置的环境变量。

![](../Images/51a34a2b6d717d108a52ba823223ba4e.png)

所以,写了一个调用`system`函数的程序。由于`sudo`原因，程序将以 `root` 用户身份运行。也就可以忽略多余的 `setuid()` 和 `setgid()` 调用。

如果想知道为什么必须在调用 `system() `之前取消设置 `LD_PRELOAD` 环境变量，请上一篇文章。

![](../Images/c6b12aa047d70d634211a76ee33a2ab7.png)

使用 `GCC` 编译代码，这里不需要 `lib` 前缀，并在指定 `LD_PRELOAD` 环境变量后调用 `apache`。

```


$ gcc -shared -fPIC -o inject.so exploit.c
```
