## 疯狂的cron任务2

在检查 `sudo` 权限时，发现用户可以管理 `cron` 服务，并且有一个名为 `message` 的文件由`root` 拥有。

![](../Images/af80c92d8da03430df8a54cc77fd0a23.png)

发现 `/tmp/` 目录中有另一个同名文件和一条消息“Hey!! you are not root :(”

![](../Images/a41bc5749459637cbcd2eabd9f8c42b4.png)

使用 `grep` 命令在可能的目录中递归搜索其中包含`/tmp/message`的文件。幸运的是，找到了一个文件，而且它是全局可写的。所以在这种情况下，可以将恶意代码写入这个文件并接管系统。

![](../Images/da80756aca3c263b3a2651382d2d3040.png)

如在 `bash` 程序中添加一个 `suid` 位

```

chmod +s /bin/bash
```

![](../Images/f368768cc4aa7d2735ababd6707e04d2.png)

当定时任务再次执行，可以看到 `/bin/bash` 启用了 `SUID` 位。在运行命令 `/bin/bash -ip` 时，将获得一个特权交互式 `shell`

## 黄金日志

在检查 `sudo` 权限时，发现有两个服务在运行。`postfix` 服务基本上是一个 `SMTP` 服务器，与 `cron` 一起使用以发送执行状态。`cron`也可以配置成e用邮件发送错误消息。

![](../Images/7914d8c58cdd6c9e0f131bb82e0ba8ab.png)

在这种情况下，两个服务都在运行。

![](../Images/82def40ed37c84869559a05287fa423e.png)

  

所有电子邮件的基本目录都存储在 `/var/mail/[username]` 中。这里的 `root` 用户的电子邮件内容是全局可读的，这可能是一个宝藏。

![](../Images/da98e666f4bd0b4d29b6c5a3c1c69ac5.png)

正如预期的那样，有命令失败的信息（`/bin/sh /opt/exec.sh`），执行频率为 1 分钟，请参阅黄色标记中的日期

![](../Images/2d6fd34556c4c4b53ac4dc989ca591cb.png)

在这个案例下，错误配置是 `/opt/` 目录是全局可写的。在此，可以创建一个 `exec.sh` 文件并添加恶意内容以获取 `root shell`。

![](../Images/1d5877fa357a6afc6dadad941637c01c.png)

  

在这里，在 `/bin/bash` 上设置 `SUID` 位以使用 `bash -p` 命令获得特权 `shell`

```
chmod u+s /bin/bash
```

![](../Images/c6be4154557d6e5065551680d278d1ce.png)

在下一次执行时，`cron` 将运行 `/opt/exec.sh` 脚本并在目标文件上设置 `SUID` 位。
