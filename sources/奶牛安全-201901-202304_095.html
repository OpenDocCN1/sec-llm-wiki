堆内存损坏的问题怎么定位呢？我们看看valgrind如何吧。

用上一篇的代码corrupt.c

#include <unistd.h>
#include <stdlib.h>
#include <stdio.h>
#include <string.h>

void a(size_t n)
{
    char* p = malloc(n);
    if( p != NULL )
    {
        memset(p, 0, n);
        free(p);
    }
}

void b(size_t n)
{
    char* p = malloc(n);
    if( p != NULL )
    {
        memset(p, 0, n + 16);
        free(p);
    }
}

void c(size_t n)
{
    char* p = malloc(n);
    if( p != NULL )
    {
        memset(p, 0, n + 24);
        free(p);
    }
}

int main(int argc, char* argv[])
{
    size_t i = 8;
    unsigned seed = atoi(argv[1]);
    srand(seed);
    for ( ; i < 100; i++ )
    {
        int r = rand()%seed;
        printf("count:%u,random:%d, type:%u\n",i, r, r%3);
        switch( r % 3 )
        {
            case 0:
                a(r);
                break;
            case 1:
                b(r);
                break;
            case 2:
                c(r);
                break;
        }
    }
    return 0;
}

编译它，注意：是没有调试符号

cc -o corrupt corrupt.c

可以看到，它完美地定位出哪块内存做了坏事，也定位出这块内存是在哪里申请的。从上面也可以看出，它实际上用它的malloc,memset来替换了glibc的函数，从而来记录它的踪迹，来进一步定位。

基本上，如果不想费心思在上面，用valgrind就可以了。如果程序实在太大，可以切割成几个小模块，每个小模块有一个测试代码，通过valgrind跑测试代码找出问题。
