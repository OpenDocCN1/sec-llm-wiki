使用python脚本扩展gdb来定位内存泄露

上一篇Linux内存泄露定位4：eBPF+uprobes 篇已经讲述到ebpf+uprobes  方案，它可以很完美地追踪到内存泄露的问题，无论追踪的程序有无调试符号。这一点比valgrind和mtrace都要强。但如果是基于它来写东西，学习曲线非常陡峭，要求实在太高。

那么，有没有简单点的方案呢？

在Windows下，调试器windbg可是有gflags命令集用来定位内存泄露的。那么，在Linux下，调试器GDB有没有定位内存泄露的命令呢？

没有。从08年到现在，类似的命令都没有出现。

幸好，GDB支持python扩展，可以考虑自己写python脚本来实现定位内存泄露的功能。

先按照第3篇Linux内存泄露定位3：hook+backtrace篇所说的原理，在GDB里是怎么操作呢？只考虑malloc/free。

  1. 在malloc和free打断点

    break malloc
    break free

  2. 运行程序run

  3. 命中malloc断点时，直接使用fin命令返回，然后执行bt获取调用栈，把返回的内存记录和调用栈保存起来

  4. 命中free断点时，获取参数，在第3步获取的记录中查找到相应项，并删除

  5. 程序结束时，还剩下哪些记录

那么，用python脚本实现内存泄露的功能，就是把上面操作自动化。

按照https://sourceware.org/gdb/onlinedocs/gdb/Python-API.html的说明，大概是如下实现：

  • 要实现一个malloc的断点类，由于malloc断点命中后，还要执行fin命令的，所以malloc这个断点类就这样定义：

    class MallocBeforeBreakpoint(gdb.Breakpoint):

  • 在fin命令执行完之后，程序也会停止下来，这其实是命中了一个临时断点，所以，这里又定义一个断点类

    class MallocAfterBreakpoint(gdb.FinishBreakpoint):

  • 释放内存时，命中free断点，所以也要定义一个free断点类

    class FreeBreakpoint(gdb.Breakpoint):

  • 程序结束时，要打印出泄露的内存地址，所以需要定义一个退出事件的处理函数

    def exitHandler(event):

  • 退出事件处理函数需要注册

    gdb.events.exited.connect(exitHandler)

  • 像MallocBeforeBreakpoint和FreeBreakpoint可以在脚本运行时直接用malloc/free的字符串来打断点，那么MallocAfterBreakpoint应该在哪打断点呢？由于它是由malloc断点命中执行fin命令时的结果，fin命令相当于break和continue的组合。所以，MallocAfterBreakpoint的实例应该在MallocBeforeBreakpoint的stop函数时初始化

如果看不明白的，请看GDB源码。如果懒得看源码，请看张银奎老师写的《软件调试》

呃，其实，上面两样东西都不好搞，还是下载个美团注册骑手吧。

完整脚本leaks.py如下：

import sys
import gdb
import json

entries = {}

bps = []

class MallocAfterBreakpoint(gdb.FinishBreakpoint):
    def __init__(self, frame, internal, size):
        super(MallocAfterBreakpoint, self).__init__(frame, internal)
        self._size = size;

    def stop(self):
        frs = []
        fr = gdb.newest_frame()
        rval = int(fr.read_register("rax"))
        if rval == 0:
            print(self._size)
            return True 
        rval = "0x%x"%rval
        while fr is not None and fr.is_valid():
            pc = fr.pc()
            info = {
                    "pc": "0x%x"%int(pc),
                    "address": gdb.execute("info symbol %d"%pc, to_string=True)
                    }
            frs.append(info)
            fr = fr.older()
        entries[str(rval)] = frs
        global bps
        bps.append(self)
        return False 

class MallocBeforeBreakpoint(gdb.Breakpoint):
    def stop(self):
        global bps
        for b in bps:
            b.delete()
        bps=[]
        fr = gdb.newest_frame()
        sz = str(fr.read_register("rdi"))
        fin = MallocAfterBreakpoint(gdb.newest_frame(), internal=True, size=sz)
        return False 

class FreeBreakpoint(gdb.Breakpoint):
    def stop(self):
        fr = gdb.newest_frame()
        v = str(fr.read_register("rdi"))
        v = "0x%x"%int(v)
        if v in entries:
            del entries[v]
        return False 

def exitHandler(event):
    print(json.dumps(entries,indent=4))

arch = gdb.selected_inferior().architecture()
if "x86-64" not in arch.name():
    sys.exit(1)
mallocBp = MallocBeforeBreakpoint("malloc")
freeBp = FreeBreakpoint("free")
gdb.events.exited.connect(exitHandler)
gdb.execute("r")

上面代码有两处地方比较卷，主要是解决无符号情况下

read_register("rax"): 这是因为在x86 64位下，一般是rax存放返回值

read_register("rdi")：这是因为在x86 64位下，一般是rdi存放着函数第一个参数。如果有错误，请分析一下相应的汇编。

这些都要熟悉调用约定才能够干的活。

测试例子a.c如下

#include <unistd.h>
#include <stdlib.h>
#include <string.h>

char* a()
{
    return malloc(200);
}

char* b()
{
    return malloc(400);
}

char* c()
{
    return malloc(800);
}

int main()
{
    int i = 0;
    for ( ; i < 100; i++ )
    {
        switch(i%3)
        {
            case 0:
                char* a1 = a();
                free(a1);
                break;
            case 1:
                char* b1 = b();
                break;
            case 2:
                char *c1 = c();
                free(c1);
                break;
            default:
                break;
        }
    }
    return 0;
}
