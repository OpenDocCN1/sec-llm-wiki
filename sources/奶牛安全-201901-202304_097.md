> 使用python脚本扩展gdb来定位内存泄露

上一篇[Linux内存泄露定位4：eBPF+uprobes 篇](http://mp.weixin.qq.com/s?__biz=MzU4NjY0NTExNA==&mid=2247486499&idx=1&sn=3c03433040e67bb96489ef0178f3e8fb&chksm=fdf96736ca8eee20c425778515cf36aecd312822e2538dd688fbd55f26b72d916984b0c6b61a&scene=21#wechat_redirect)已经讲述到`ebpf+uprobes`  方案，它可以很完美地追踪到内存泄露的问题，无论追踪的程序有无调试符号。这一点比`valgrind`和`mtrace`都要强。但如果是基于它来写东西，学习曲线非常陡峭，要求实在太高。

那么，有没有简单点的方案呢？

在`Windows`下，调试器`windbg`可是有`gflags`命令集用来定位内存泄露的。那么，在`Linux`下，调试器`GDB`有没有定位内存泄露的命令呢？

没有。从08年到现在，类似的命令都没有出现。

幸好，`GDB`支持`python`扩展，可以考虑自己写`python`脚本来实现定位内存泄露的功能。

先按照第3篇[Linux内存泄露定位3：hook+backtrace篇](http://mp.weixin.qq.com/s?__biz=MzU4NjY0NTExNA==&mid=2247486495&idx=1&sn=c740654a1a9bbe06104200b75dcc0989&chksm=fdf9670aca8eee1c0c5b5921b3a13ff024fb52dc0fd11c66c267725fd622bf429d7b0ddf03ea&scene=21#wechat_redirect)所说的原理，在`GDB`里是怎么操作呢？只考虑`malloc/free`。

1.  在`malloc`和`free`打断点
    
    ```
    
    
    break malloc
    ```
    
2.  运行程序`run`
    
3.  命中`malloc`断点时，直接使用`fin`命令返回，然后执行`bt`获取调用栈，把返回的内存记录和调用栈保存起来
    
4.  命中`free`断点时，获取参数，在第3步获取的记录中查找到相应项，并删除
    
5.  程序结束时，还剩下哪些记录
