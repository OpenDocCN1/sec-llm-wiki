更深一层讲述定位内存泄露的手段

从上一篇文章Linux内存泄露定位1：valgrind篇，可以知道valgrind是类似JVM的方式来进行内存泄露。虽然它很好用，但用过的朋友都知道，它非常慢。这种沙箱类的技术，需要对很多函数进行打桩，是非常消耗性能。而且，由于它并不是为了针对内存泄露实现的，代码一复杂，往往跑不出结果来。

再者，valgrind是通过代码打桩技术，如果程序本身对malloc加钩，实现内存池，它有可能对程序本身的功能有影响。

那么，glibc本身有没有内置的对内存泄露的功能呢？

根据man 3 mtrace的介绍

The  mtrace()  function installs hook functions for the memory-allocation functions (malloc(3), realloc(3) memalign(3), free(3)).  These hook functions record tracing information about memory allocation and deallocation.  The tracing information can be used to discover memory  leaks  and  attempts to free nonallocated memory in a program.

也可以从https://www.gnu.org/software/libc/manual/html_node/Tracing-malloc.html的介绍，它好像是可以定位内存泄露的。

代码memtrace.c:

#include <stdlib.h>
#include <mcheck.h>

void* func(size_t sz)
{
    return malloc(sz);
}

int main()
{
    mtrace();
    char* a = NULL;
    for ( size_t i = 8; i < 10; i++ )
    {
        a = func(i);
    }

    return 0;
}

编译

cc -g -o memtrace memtrace.c

运行

export MALLOC_TRACE=trace.txt
./memtrace

看结果

$mtrace ./memtrace $MALLOC_TRACE

Memory not freed:
-----------------
           Address     Size     Caller
0x00005578ab263690      0x8  at 0x5578a955d161
0x00005578ab2636b0      0x9  at 0x5578a955d161

这个是什么结果，可以说是一点用处都没有。而且，这个memtrace程序还是用-g选项编译出来，有调试符号，却识别不了。

是的，虽然用objdump -d memtrace出来这样的结果

0000000000001149 <func>:
    1149:       55                      push   %rbp
    114a:       48 89 e5                mov    %rsp,%rbp
    114d:       48 83 ec 10             sub    $0x10,%rsp
    1151:       48 89 7d f8             mov    %rdi,-0x8(%rbp)
    1155:       48 8b 45 f8             mov    -0x8(%rbp),%rax
    1159:       48 89 c7                mov    %rax,%rdi
    115c:       e8 cf fe ff ff          call   1030 <malloc@plt>
    1161:       c9                      leave  
    1162:       c3                      ret

按照4K大小内存页的方式，也可以知道是func这个函数调用malloc申请的内存没有释放，但这种定位是没有意义的。就像strdup也调用了malloc，但真正导致内存泄露往往是调用strdup函数的调用者或者整个栈有逻辑错误。

所以，结论是：

mtrace是一个废物。

作为一个广东人，我只想对写mtrace这个功能的人说句“生块叉烧好过生你，你简直是浪费粮食”
