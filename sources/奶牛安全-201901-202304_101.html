讲述valgrind在定位内存泄露和定位原理探究

先上一个C语言的代码

#include <unistd.h>
#include <stdlib.h>


int main()
{
    char* a = NULL;
    for ( size_t i = 8; i < 10; i++ )
    {
        a = malloc(i);
    }
    sleep(50);
    return 0;
}

加上sleep(50)是为了探究原理用的。

上面代码命名为mem.c, 以debug模式编译后

cc -g -o mem mem.c

运行一下valgrind

valgrind --leak-check=full ./mem

按照4K内存页对齐，0x10916E对应的地址也是16E结尾(不懂的同学请《linker and loader》或《程序员的自我修养)，从这两行来看，

    116a:       e8 c1 fe ff ff          call   1030 <malloc@plt>
    116f:       48 89 45 f0             mov    %rax,-0x10(%rbp)

再考虑代码打桩，应该就是116a( 并不是116e，可是打桩里大小端)。

从这里看，valgrind在定位内存泄露时，能够把泄露的申请栈打印出来，可以很好地定位代码，虽然在没调试符号情况下非常复杂而已。
