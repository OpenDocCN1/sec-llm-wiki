按照容器设计的理念，在命名空间里的进程应该尽量少知道它所在的宿主机，不知道宿主机运行的进程，也不知道宿主机上挂载的分区。为什么会这样呢？

按照`man 7 mount_namespaces`的结果

> *“When a process creates a new mount namespace using clone(2) or unshare(2) with the CLONE\_NEWNS flag, the mount point list for the new namespace is a copy of the caller’s mount point list.”*

根据上面所述，新的`Mount`命名空间是直接复制调用者的挂载点列表，这也是`/proc/mounts`为什么会显示宿主机的挂载列表。按照容器设计理念，需要清除宿主机的挂载信息，达到隔离效果，需要用到`pivot_root`系统调用。

## pivot\_root系统调用

`pivot_root`允许进程设置新的根文件系统，就是可以改变`/`的位置。它允许在其它位置挂载当前根文件系统，同时把新的根文件系统挂载到`/`。一旦原先的根文件系统移动后，它可以卸载。由此，就有了一种在新的`Mount`命名空间卸载宿主机挂载点的机制：把它们旋走，然后卸载。

这也是可以在`Ubuntu`上跑类似`CentOS`之类的其它发行版的原因。只要`Ubuntu`宿主机磁盘有`CentOS`文件系统的影像，就可以创建一个新的`Mount`命名空间，调用`pivot_root`把根文件系统指向`CentOS`文件系统，然后在这个命名空间运行的任意进程都会认为它们在`CentOS`上运行。

按照上面描述，`pivot_root`应该是在命名空间创建之后，运行任何进程之前进行。这也是上一篇`[用Go探究命名空间：reexec篇](http://mp.weixin.qq.com/s?__biz=MzU4NjY0NTExNA==&mid=2247486432&idx=1&sn=e8c70386cbc016d4e3bdaa8b4d496d89&chksm=fdf960f5ca8ee9e3b3711b7b636f641e3a99cd37d0f6a85d25338cf3fed191320760421d537f&scene=21#wechat_redirect)里reexec`发挥的时候。
