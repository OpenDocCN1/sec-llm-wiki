使用Go语言探究如何在命名空间创建后进程运行前设置环境。

译自: https://medium.com/@teddyking/namespaces-in-go-reexec-3d1295b91af8

上一篇文章用Go探究命名空间：User命名空间篇已经介绍如何在ns-process使用UID/GID映射，使得可以在命名空间的shell以root运行。本文是介绍reexec包的使用，它是Docker代码库的一部分，解决Go如何处理进程复制的问题。

考虑这样的场景：更新一下ns-process的代码，使得一旦进入新的UTS命名空间会自动设置一个随机生成的主机名。出于安全考虑，这个主机名应该是命名空间创建完和/bin/sh运行前设置。毕竟，不希望任何在ns-process运行的程序发现宿主机的主机名。

Go并没有提供一种内置的方式可以做到这一点。命名空间是通过在\*exec.Cmd上设置属性创建的，也是设置要运行进程的地方。比如

cmd := exec.Command("/bin/echo", "Process already running")
cmd.SysProcAttr = &syscall.SysProcAttr{
 Cloneflags: syscall.CLONE_NEWUTS,
}
cmd.Run()

一旦cmd.Run()被调用，命名空间立马创建，然后进程直接运行了。在命名空间创建和进程启动之间，没有任何地方可以加钩子。这也是reexec的作用。

先看一下reexec包里面的实现。由于环境是在Linux下运行，所以相关的文件就两个。

https://github.com/moby/moby/blob/master/pkg/reexec/reexec.go

https://github.com/moby/moby/blob/master/pkg/reexec/command_linux.go

现在Docker引擎的代码库名称由docker/docker变成moby/moby了。

先看一下reexec.go

package reexec // import "github.com/docker/docker/pkg/reexec"

import (
 "fmt"
 "os"
 "os/exec"
 "path/filepath"
)

var registeredInitializers = make(map[string]func())

// Register adds an initialization func under the specified name
func Register(name string, initializer func()) {
 if _, exists := registeredInitializers[name]; exists {
  panic(fmt.Sprintf("reexec func already registered under name %q", name))
 }

 registeredInitializers[name] = initializer
}

// Init is called as the first part of the exec process and returns true if an
// initialization function was called.
func Init() bool {
 initializer, exists := registeredInitializers[os.Args[0]]
 if exists {
  initializer()

  return true
 }
 return false
}

func naiveSelf() string {
 name := os.Args[0]
 if filepath.Base(name) == name {
  if lp, err := exec.LookPath(name); err == nil {
   return lp
  }
 }
 // handle conversion of relative paths to absolute
 if absName, err := filepath.Abs(name); err == nil {
  return absName
 }
 // if we couldn't get absolute name, return original
 // (NOTE: Go only errors on Abs() if os.Getwd fails)
 return name
}

可见它提供了三个接口

  • Register：允许通过名称注册任何函数的方法，可以用它注册一些初始化命名空间的函数
  • Init：判断调用reexec后，进程是否已经运行，如果已经运行，那么就运行在Register注册的函数
  • naiveSelf：返回程序的路径

再看一下command_linux.go

package reexec // import "github.com/docker/docker/pkg/reexec"

import (
 "os/exec"
 "syscall"

 "golang.org/x/sys/unix"
)

// Self returns the path to the current process's binary.
// Returns "/proc/self/exe".
func Self() string {
 return "/proc/self/exe"
}

// Command returns *exec.Cmd which has Path as current binary. Also it setting
// SysProcAttr.Pdeathsig to SIGTERM.
// This will use the in-memory version (/proc/self/exe) of the current binary,
// it is thus safe to delete or replace the on-disk binary (os.Args[0]).
func Command(args ...string) *exec.Cmd {
 return &exec.Cmd{
  Path: Self(),
  Args: args,
  SysProcAttr: &syscall.SysProcAttr{
   Pdeathsig: unix.SIGTERM,
  },
 }
}

它提供两个接口：

  • Self：返回当前执行程序
  • Command: 返回Path为当前二进制文件的*exec.Cmd，它可以用来指定执行通过Args[0]指定在registeredInitializers注册的函数。

在明白上面的原理之后，修改一下ns-process.go的代码。

先定义包的初始化函数init，让它使用reexec来注册初始化命名空间的函数。

func init() {
 reexec.Register("nsInitialisation", nsInitialisation)
 if reexec.Init() {
  os.Exit(0)
 }
}

按照上面，需要定义nsInitialisation函数

func nsInitialisation() {
 fmt.Printf("\n>> namespace setup code goes here <<\n\n")
 nsRun()
}
func nsRun() {
 cmd := exec.Command("/bin/sh")

 cmd.Stdin = os.Stdin
 cmd.Stdout = os.Stdout
 cmd.Stderr = os.Stderr

 cmd.Env = []string{"PS1=-[ns-process]- # "}

 if err := cmd.Run(); err != nil {
  fmt.Printf("Error running the /bin/sh command - %s\n", err)
  os.Exit(1)
 }
}

在这里，nsRun用来运行了/bin/sh。

接着修改main函数，使得它通过reexec和nsInitialisation来调用/bin/sh

func main() {
    cmd := reexec.Command("nsInitialisation")
    # ...
}

整体代码如下

// Git tag: 3.0
// Filename: ns_process.go
package main

import (
    "fmt"
    "os"
    "os/exec"
    "syscall"
    "github.com/docker/docker/pkg/reexec"
)

func init() {
    fmt.Printf( "program %s pid %d init\n", os.Args[0], os.Getpid() )
    reexec.Register( "nsInitialisation", nsInitialisation )
    if reexec.Init() {
        os.Exit(0)
    }
}

func nsInitialisation() {
    fmt.Printf( "\n>> namespace setup code goes here << \n\n" )
    nsRun()
}

func nsRun() {
    cmd := exec.Command( "/bin/sh" )
    cmd.Stdin = os.Stdin
    cmd.Stdout = os.Stdout
    cmd.Stderr = os.Stderr

    cmd.Env = []string{"PS1=-[ns-process]- # "}

    if err := cmd.Run(); err != nil {
        fmt.Printf("Error running the /bin/sh command - %s\n", err)
        os.Exit(1)
    }
}


func main() {
    fmt.Printf( "program %s pid %d main\n", os.Args[0], os.Getpid() )
    cmd := reexec.Command("nsInitialisation")

    cmd.Stdin = os.Stdin
    cmd.Stdout = os.Stdout
    cmd.Stderr = os.Stderr

    cmd.Env = []string{"PS1=-[ns-process]- # "}

    cmd.SysProcAttr = &syscall.SysProcAttr{
        Cloneflags: syscall.CLONE_NEWNS |
        syscall.CLONE_NEWUTS |
        syscall.CLONE_NEWIPC |
        syscall.CLONE_NEWPID |
        syscall.CLONE_NEWNET |
        syscall.CLONE_NEWUSER,
        UidMappings: []syscall.SysProcIDMap{
            {
                ContainerID: 0,
                HostID:      os.Getuid(),
                Size:        1,
            },
        },
        GidMappings: []syscall.SysProcIDMap{
            {
                ContainerID: 0,
                HostID:      os.Getgid(),
                Size:        1,
            },
        },
    }

    if err := cmd.Run(); err != nil {
        fmt.Printf("Error running the /bin/sh command - %s\n", err)
        os.Exit(1)
    }
}

译者注：这段程序比较绕。它的基本逻辑是：

  1. 通过包的init函数先创建一个进程，可以认为是fork
  2. 再通过fork进程执行/bin/sh

译者在程序里特意加了两行代码

fmt.Printf( "program %s pid %d main\n", os.Args[0], os.Getpid() )

fmt.Printf( "program %s pid %d init\n", os.Args[0], os.Getpid() )

来更好地理解的
