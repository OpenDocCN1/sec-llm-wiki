上一篇文章[用Go探究命名空间：User命名空间篇](http://mp.weixin.qq.com/s?__biz=MzU4NjY0NTExNA==&mid=2247486428&idx=1&sn=c2cad74e6b3472e5061df1ca5cf716be&chksm=fdf960c9ca8ee9dfb99dc437d86bf73e5cca6fa79b40e62d6a954cf2eeb96bbecbd3c3f42f66&scene=21#wechat_redirect)已经介绍如何在`ns-process`使用`UID/GID`映射，使得可以在命名空间的`shell`以`root`运行。本文是介绍`reexec`包的使用，它是`Docker`代码库的一部分，解决`Go`如何处理进程复制的问题。

考虑这样的场景：更新一下`ns-process`的代码，使得一旦进入新的`UTS`命名空间会自动设置一个随机生成的主机名。出于安全考虑，这个主机名应该是命名空间创建完和`/bin/sh`运行前设置。毕竟，不希望任何在`ns-process`运行的程序发现宿主机的主机名。

`Go`并没有提供一种内置的方式可以做到这一点。命名空间是通过在`\*exec.Cmd`上设置属性创建的，也是设置要运行进程的地方。比如

```





cmd := exec.Command("/bin/echo", "Process already running")
```

一旦`cmd.Run()`被调用，命名空间立马创建，然后进程直接运行了。在命名空间创建和进程启动之间，没有任何地方可以加钩子。这也是`reexec`的作用。
