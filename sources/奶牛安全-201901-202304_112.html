使用Go语言写一个简单程序体会了命名空间

译自: https://medium.com/@teddyking/namespaces-in-go-user-a54ef9476f2a

本文是紧接着上一篇文章Linux命名空间，虽然unshare命令挺好用，但它却满足不了精细化的要求，所以这里用Go编写示例程序ns-process来理解命名空间。

ns-process相当简单，它在新一组命名空间中创建/bin/sh进程。

// Git repo: https://github.com/teddyking/ns-process
// Git tag: 1.0
// Filename: ns_process.go
package main

import (
    "fmt"
    "os"
    "os/exec"
    "syscall"
)

func main() {
    cmd := exec.Command("/bin/sh")

    cmd.Stdin = os.Stdin
    cmd.Stdout = os.Stdout
    cmd.Stderr = os.Stderr

    cmd.Env = []string{"PS1=-[ns-process]- # "}

    cmd.SysProcAttr = &syscall.SysProcAttr{
        Cloneflags: syscall.CLONE_NEWUTS,
    }

    if err := cmd.Run(); err != nil {
        fmt.Printf("Error running the /bin/sh command - %s\n", err)
        os.Exit(1)
    }
}

代码逻辑相当简单，只是创建了一个*exec.Cmd，从父进程继承标准输入/标准输出/标准错误的句柄，设置新进程的PS1环境变量（只是用来识别新进程）

有趣的部分是cmd.SysProcAttr，在明白SysProcAttr之前，先看一下命名空间API底下的系统调用。

命名空间API

在namespaces(7)的手册页上，有3个系统调用构成了命名空间API：

  1. clone(2): 创建新进程
  2. setns(2): 允许调用该接口的进程加入一个已经存在的命名空间
  3. unshare(2)：把调用该接口的进程移动到新命名空间

unshare(2)有点类似上一篇文章Linux命名空间的unshare命名。unshare命名是基于它实现的。这次主要是关注clone()，因为它是由Go的exec.Run()调用。

当调用clone时，可以传递一个或多个CLONE_*标志。每个命名空间都有相应的CLONE标志：

  • CLONE_NEWNS: mount命名空间
  • CLONE_NEWUTS:  UTS命名空间
  • CLONE_NEWIPC：IPC命名空间
  • CLONE_NEWPID: PID命名空间
  • CLONE_NEWNET: Network命名空间
  • CLONE_NEWUSER: User命名空间
  • CLONE_NEWCGROUP: cgroup命名空间
  • CLONE_NEWTIME: Time命名空间

克隆进程的执行上下文在一定程度上是由传入的标志定义的。

回到示例程序和SysProcAttr。SysProcAttr允许在*exec.Cmd上设置属性。通过指定cloneflags属性，可以把CLONE_*之类的标志传递给clone。因此，可以控制进程在哪个命名空间执行。

编译和运行程序，会发现/bin/sh在一个新的UTS命名空间上运行。注意，程序需要用root用户 运行。

$ go build
$ sudo ./ns-process
-[ns-process]- #

来验证一下

-[ns-process]- # readlink /proc/self/ns/uts
uts:[4026532410]
-[ns-process]- # exit
$ readlink /proc/self/ns/uts
uts:[4026531838]

/proc/self/ns/uts/的内容包括了命名空间类型和命名空间的inode。两个不同的inode意味着这两个进程是运行在不同的UTS命名空间。

上面示例只是请求一个新的命名空间。下面在cloneflags上加上其它标志，使得/bin/sh在新的Mount, UTS, IPC, PID, Network和User命名空间中运行。

// Git repo: https://github.com/teddyking/ns-process
// Git tag: 1.1
// Filename: ns_process.go
package main

import (
    "fmt"
    "os"
    "os/exec"
    "syscall"
)

func main() {
    cmd := exec.Command("/bin/sh")

    cmd.Stdin = os.Stdin
    cmd.Stdout = os.Stdout
    cmd.Stderr = os.Stderr

    cmd.Env = []string{"PS1=-[ns-process]- # "}

    cmd.SysProcAttr = &syscall.SysProcAttr{
        Cloneflags: syscall.CLONE_NEWNS |
        syscall.CLONE_NEWUTS |
        syscall.CLONE_NEWIPC |
        syscall.CLONE_NEWPID |
        syscall.CLONE_NEWNET |
        syscall.CLONE_NEWUSER,
    }

    if err := cmd.Run(); err != nil {
        fmt.Printf("Error running the /bin/sh command - %s\n", err)
        os.Exit(1)
    }
}

可见，除了cgroup和time命名空间还是一样之外，其它命名空间的inode都不一样了。

当请求新的User命名空间时同时请求其它命名空间，User命名空间先创建。User命名空间不需要root权限来创建，意味着可以不需要sudo，以非root用户运行运行。

上面是使用Go在新命名空间运行程序的最基本版本。在现实中，这并没有多少用处。上面例子忽略了大多用来初始和配置命名的设置操作。比如：

  • 请求了新的Mount命名空间，却还是使用宿主机的挂载点和根文件系统
  • 请求了新的PID命名空间，却没有挂载新的/proc文件系统
  • 请求了新的Network命名空间，却没有在命名空间里创建任何网络接口
  • 请求了新的User命名空间，却没有提供UID/GID的映射
