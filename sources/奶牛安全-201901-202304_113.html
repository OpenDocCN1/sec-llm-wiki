简单介绍了一下Linux命名空间，并且通过unshare命令来体验了一把UTS命名空间

译自: https://medium.com/@teddyking/linux-namespaces-850489d3ccf

大多数现代容器实现的基础技术，Linux命名空间是其中部分。在较高层次上，它们允许在独立进程之间隔离全局系统资源。比如，PID命名空间隔离了进程ID的数字空间。这意味着在同一台宿主机上的两个进程可以有相同的PID。

这种层次的隔离在容器世界非常有用。没有命名空间，在容器A的进程可以卸载容器B的一个重要文件系统，或者改变容器C的主机名，或者删除容器D的网络接口。通过命名空间隔离这些资源，容器A的进程甚至无法感知容器B, C, D里的进程存在。

命名空间提供了一种限制进程感知的方式，使得它觉得自己是唯一在宿主机上运行的进程。

命名空间并没有限制对物理资源（如CPU，内存和磁盘）的访问，这些访问是由cgroups度量和限制的。

通过一个实际例子来熟悉命名空间吧。

$ unshare -h

Usage:  
 unshare [options] <program> [<argument>...]

Run a program with some namespaces unshared from the parent.

Options:  
 -m, --mount[=<file>]      unshare mounts namespace
 -u, --uts[=<file>]        unshare UTS namespace (hostname etc)
...

unshare命令允许在某些与父命名空间不共享的命名空间下运行程序。这意味着，unshare可以在新一组命名空间里运行任何程序。

下面在UTS命名空间上运行一个程序。UTS命名空间提供了主机名和域名系统的隔离。这种隔离可以通过在UTS命名空间/bin/sh程序里运行hostname my-new-hostname来测试，并且可以确认这种主机名变更并不影响进程外的环境。

$ sudo su                   # become root user
$ hostname                  # check current hostname
dev-ubuntu  
$ unshare -u /bin/sh        # create a shell in new UTS namespace
$ hostname my-new-hostname  # set hostname
$ hostname                  # confirm new hostname
my-new-hostname  
$ exit                      # exit new UTS namespace
$ hostname                  # confirm original hostname unchanged
dev-ubuntu

  • 运行sudo su变成root用户。大多数命名空间需要root权限来创建（user命名空间是例外）。

  • 运行hostname来确认当前的主机名。

  • unshare -u /bin/sh在一个新的，单独的UTS命名空间运行shell。

  • 运行hostname my-new-hostname在新的UTS命名空间设置主机

  • 运行hostname确认主机名已经修改

  • exit新的UTS命名空间，运行hostname。可以看到主机名变成原来的名字，即使运行hostname my-new-hostname修改过。这是因为那个变更只是在新UTS命名空间生效

八种命名空间

上面例子展示了UTS命名空间，它只是八种命名空间的一种：

  1. Mount：隔离文件系统的挂载点
  2. UTS：隔离主机名和域名
  3. IPC：隔离进程间通信资源
  4. PID：隔离PID数字空间
  5. Network：隔离网络接口
  6. User：隔离UID/GID数字空间
  7. Cgroup：隔离cgroup根目录， 4.6版本引入
  8. Time：隔离系统时间，类似UTS， 5.6版本引入

大多数容器实现都使用了上面的命名空间在单独的容器进程中提供最高级别的隔离。由于Cgroup和Time这两种比其它都新，使用并不广泛。
