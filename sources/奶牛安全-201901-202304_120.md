> 使用`windbg`从`powershell`的`dump`文件提取命令记录，用于恶意行为分析
> 
> 译自：https://www.leeholmes.com/extracting-activity-history-from-powershell-process-dumps/

假设正在调查一个被黑客使用`powershell`入侵的系统，而这个系统的`powershell`的日志功能被停用了，而手上只有一个`powershell`进程的`dump`文件。该怎么办？

`dump`文件是取证黄金，而`windbg`的托管代码调试扩展（“SOS”--Strike之子）可以用来研究它。

在菜单选中打开`dump文件`，可以看到

![](../Images/fa124c2328a0ba3d4ed6702262962be1.png)

image

执行如下操作，加载`SOS`

```



.loadby sos clr
```

使用`!help`命令可以看到 `SOS CLR`调试扩展所有特性，其中一个很有用的命令是`!DumpHeap`，用来枚举托管内容所有对象，并且可以根据类型过滤。

`Powershell`把命令历史记录在`HistoryInfo`对象，使用`!DumpHeap –Type HistoryInfo`看一下，如果有报错，重新操作一下。

![](../Images/1a7c6f79874b1a22908a0d73d4d424c1.png)

image

可以看到有6条`HistoryInfo`（黑客执行的命令），有7组`HistoryInfo`（内部数据）。堆是包含暂时在用的数据，所以不是所有都表示唯一的命令。

点击`HistoryInfo`的`MT`列，可以知道对象的类型。然后再点击出来的地址，就可以看到`HistoryInfo`对象的内容。这些点击操作其实就是下图`windbg`下两条命令`!DumpHeap /d -mt 00007ff8a140be70`和`!DumpObj /d 0000024226256100`

![](../Images/08f08a9df0fbc975fa3426c8a1268a54.png)

image

有一个偏移量为8的字符串的名称叫`_cmdline`，使用`!DumpObj /d 0000024226255a30`看一下内容

![](../Images/5c162a8e04838d73d00188de73a709ab.png)

image

可以看到是执行`whoami`命令。

手工一个个地看`HistoryInfo`很费事，使用`windbg`的脚本语言来看。

```
.foreach (historyinfo { !dumpheap -
```

对`!dumpheap`的结果遍历，把每个内存地址分配给`historyinfo`变量，再打印这个变量内容，使用`poi`函数计算`_cmdline`的地址，然后使用`!dumpobj`把`_cmdline`内容打印出来。

![](../Images/71fcec2f148bb6ea83f7be024154f619.png)

image

可以看到，攻击者使用`whoami`获取管理域的用户密码，再使用`powershell`远程连接域控。
