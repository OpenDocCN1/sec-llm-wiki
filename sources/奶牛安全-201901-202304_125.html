检测

如果一个管理员怀疑有webshell蛰伏在他们系统或只是进行巡检，需要检查下列内容。

首先，服务的访问和错误日志应该筛选webshell通用关键词。这包括文件名和参数名。下面例子允许你在Apache HTTP服务的访问日志的URL搜索字符串file

root@secureserver:/var/www/html# cat /var/log/apache2/access.log | awk -F\" ' { print $1,$2 } ' | grep "file"

--> 192.168.5.26 - - [30/Feb/2020:08:30:53 +0100] GET /demo/shell.php?file=/etc/passwd

必须在文件系统(通常是Web服务器根目录)中搜索文件或文件名中的通用字符串。

root@secureserver:/var/www/html/demo# grep -RPn "(passthru|exec|eval|shell_exec|assert|str_rot13|system|phpinfo|base64_decode|chmod|mkdir|fopen|fclose|readfile) *\("

--> Shell.php:8: eval($string);

防护

以下是针对webshell应采取的防护措施的非详尽列表。

  1. 如果不使用，禁用潜在危险的PHP函数，如exec,shell_exec,passthru,system,show_source,proc_open, pcntl_exec, eval和assert
  2. 如果确实有必要使用这些函数，那么确保未授权用户无法访问这些脚本。另外，使用escapeshellarg和escapeshellcmd来确保用户输入不会注入shell命令，导致命令注入漏洞
  3. 如果web应用使用上传表单，确保它们是安全并且只允许白名单的文件类型上传
  4. 决不相信用户输入
  5. 不要盲目使用那些在论坛或网站上找到的代码
  6. 在WordPress情况下，避免安装那些不必要的第三方插件。如果需要使用一个插件，确保它是名声好且经常更新
  7. 禁止PHP在敏感目录下执行，如图片或上传目录。
  8. 锁定web服务用户的权限

结语

正如我们已经看到的，编写和使用webshell并不困难。不幸的是，许多Web服务器的配置，使得即使一个简单的脚本也足以造成重大破坏。这就是为什么有数以千计的公开可用的webshell的主要原因。由于存在如此之多的变体，入侵检测和入侵防御系统(IDS/IPS)很难检测到它们，特别是当它们使用特征来检测此类webshell时。有些webshell非常复杂，即使用行为分析也几乎不可能检测到它们。这意味着防止攻击的最好方法是从一开始就阻止它们被上传。
