当我们访问网页时，我们每个人都会得到一个唯一的指纹，这已经不是什么秘密了。客户指纹识别可以帮助网站跟踪我们在其他网站上的活动。

指纹是关于您的设备、浏览器、屏幕大小、IP地址和许多其他变量的多种因素的组合。当它们结合在一起时，会使得我们被网站高度辨识。

关于客户端代码的一句话

像eBay这样的网站在我们的电脑上无休止地运行代码。他们过去只用JavaScript就能做到这一点。多年来，前端技术不断发展，比如，Javascript(ECMAScript)、TypeScript、Deno(安全快速的javascript虚拟机，用Rust编写)，

自从javascript是浏览器唯一支持的语言开始，浏览器的javascript API一直被恶意软件滥用。随着近几年发展中的下一代网页技术(如WebAssembly)的出现，下一代恶意软件可能会变得更加复杂。

WebAssembly(WASM)虚拟机允许编程语言编译成二进制代码，当你访问网页，浏览器的WebAssembly虚拟机可以在浏览器中执行这些底层代码。除了更快（编译代码通常比JS更快， 但不总是这样），WASM解耦了编程语言，并聚焦在“做什么”。

WebAssembly虚拟机是让人惊讶的，它给浏览带来了不少新API和新特性，但并没有免费午餐。WASM是安全研究员和黑客的大目标。毕竟，就算它是公开的，WASM也有大量代码只有少量人检视过。

这就是为什么许多新语言，如Rust、Go和Deno，为WebAssembly提供开箱即用的支持，将其作为目标架构/虚拟机。今天，你可以用Go, Rust和还有许多编程语言来写代码，不仅仅是使用基于javascript的语言。因此，系统编程语言在开发人员中正变得广泛适应，他们想要达到超越我们曾经认为的“跨平台”的能力。

研究WebAssembly虚拟机(使用Go)

当用户访问我的网站时，从浏览器上下文映射主机上的开放端口(活动的侦听服务)会有多容易？我能湒用一种底层语言来做这事吗？

作为一个网站所有者，假设我想确认一个用户是不是开发人员。端口扫描技术每一秒都在发现资产和服务器。“开放端口”字面上是指绑定到NIC设备上特定端口的服务器。有些服务必须手动运行，但许多操作系统在启动时运行服务，暴露了许多可在本地主机上的应用程序API(如IPC、SMB/Samba、SSH、SMTP、FTP等)。

因此，非常容易发现那些存在1day（公开但未披露）漏洞的资产。这只是谁先掌握这信息和是否上报（和修复）的问题。

自从几年前我第一次听说WASM以来，我一直相信它。我开始玩它。我选择Go是因为其简单的网络/套接字和HTTP标准库API。顺便说一句，Rust还获得了开箱即用的大量WebAssembly编译支持。

了解消息流

现在，用户的浏览器将初始化WebAssembly虚拟机。然后，它将自动运行我的Go 端口扫描器，它被编译成WebAssembly二进制文件。

开始写一个端口扫描器

我通过Go的syscalls/js绑定使用Javascript API。当我使用HTTP go API时，我发现浏览器很喜欢它，而且它不能很好地与(可能没有完全实现的)Net Go API一起工作。

浏览器(目前)不支持WebAssembly裸的TCP会话和UDP。社区还在研究新的WASI标准，总有一天，它最终会要求浏览器实现裸的TCP/UDP会话。

在尝试了几种滥用WebAssembly的裸TCP会话和接收裸TCP响应，我明白使用原生TCP会话扫描的编程是不可行的。出于安全原因（如CORS和危险端口），Chrome代理（有时候会拦截）WebAssembly的请求和响应。

func ScanPort(ip string, port int, timeout time.Duration, portsMapping map[int]bool) {
 target := fmt.Sprintf("%s:%d", ip, port)

 // TODO: WASI - add supprt for TCP/UDP session. only HTTP/HTTPS is supported in WASM JS today.
 //conn, err := net.DialTimeout("tcp", target, timeout)

 // HTTP session - supported from browsers API
 tr := &http.Transport{
  TLSClientConfig: &tls.Config{
   InsecureSkipVerify: true,
  },
 }
 client := http.Client{
  Transport: tr,
  Timeout:   timeout,
 }
 target = fmt.Sprintf("http://%s", target)
 req, err := http.NewRequest("GET", target, nil)
 if err != nil {
  fmt.Print("Failed to initiate request ", err)
 }

 trace := &httptrace.ClientTrace{
  DNSDone: func(dnsInfo httptrace.DNSDoneInfo) {
   fmt.Println("DNS Info: %+v\n", dnsInfo)
  },
  GotConn: func(connInfo httptrace.GotConnInfo) {
   fmt.Println("Got Conn: %+v\n", connInfo)
  },
  GotFirstResponseByte: func() {
   fmt.Println("Got first byte!")
  },
 }

 // IMPORTANT - enables better HTTP(S) discovery, because many browsers block CORS by default.
 req.Header.Add("js.fetch:mode", "no-cors")
 fmt.Println("(GO request): ", fmt.Sprintf("%+v", req))

 req = req.WithContext(httptrace.WithClientTrace(req.Context(), trace))
 // if _, err := client.Do(req); err != nil {
 // ERROR HANDLING WILL BE HERE.
 // }
}

Go的http API获得了一些很大的好处，比如用于HTTP跟踪的“GotFirstResponseByte”处理程序。我希望它能起作用，但它没有。

更好的做法是利用Go著名的http包，毕竟浏览器都是关于应用程序的。使用HTTP这样的应用程序协议应该会更容易。

理解响应

如何使用上层HTTP会话一致地扫描端口？获得响应是一回事。理解它们并对它们进行正确的分类是一个挑战，因为我们看不到原样的反应。端口扫描器通常使用原始数据包和会话对网络进行分类在WebAssembly虚拟机内，是不可能进行的。

我们可以尽量地对以下回应进行细分：

  • 连接拒绝（端口关闭）
  • 超时（端口可能是开或关）
  • HTTP响应（端口开，并且对端有一个HTTP服务）

我发现相对较小的超时非常可靠

随着事情进行，我遇到了更多的问题。浏览器阻止了缺少CORS头的有效HTTP响应，将其显示为通用的FETCH错误，掩盖了错误的真正原因，并将请求标记为“不安全”。浏览器甚至没有将错误内容转发到WASM虚拟机。它只是失败，没有进一步的细节。

CORS怎么办？

本地HTTP服务经常会忽略c-****头。Cross-Origin（与window.location不同的主机+端口的组合）防护是默认启动，所以HTTP请求没有这些头部是会失败的。由于CORS是在WebAssembly上下文，你都不知道请求已经失败。

必须通过某种方法解决。在传统的JS中，用户只需在FETCH()请求中添加一个no-cors模式即可。在研究了一下，想出了一种覆盖JS的Fetch() API调用的方法后，我发现了一个非常简单的方法，它非常有效！

// IMPORTANT - enables better HTTP(S) discovery, because many browsers block CORS by default.
req.Header.Add("js.fetch:mode", "no-cors")

所以CORS对Demo来说不再是问题，但这并不意味着它可以在明确指定Access-Control-Allow-Origin头的网站上工作。

我们无法处理这种情况。尽管如此，世界各地仍有很多网站可以成功运行此WASM代码。

支持具有TLS/SSL服务的端口

如果没有SSL握手，我们将“跳过”浏览器默认激活的许多SSL安全功能。这有助于我找到任何TCP开放端口，而不仅仅是接受SSL传输的服务。

我们必须记住，WebAssembly虚拟机的TCP堆栈是由Chrome本身的TCP堆栈代理的。如果证书不匹配，浏览器就会终止我们的SSL请求，但没有说明原因--这看起来就像是典型的“拒绝连接”。SSL增加了复杂性和安全性，因此我继续使用纯文本HTTP。

定义启动函数：

func (ps *PortScanner) Start(f int, l int, timeout time.Duration, portsMapping map[int]bool) {
 wg := sync.WaitGroup{}
 for port := f; port <= l; port++ {
  // GO in WASM must be SYNC as of today
  ps.lock.Acquire(context.TODO(), 1)
  wg.Add(1)
  go func(port int) {
   defer ps.lock.Release(1)
   ScanPort(ps.ip, port, timeout, portsMapping)
   defer wg.Done()
  }(port)
 }

 time.Sleep(5 * time.Second)
 wg.Wait()
}

func main() {
 portsMapping := make(map[int]bool)
 ps := &PortScanner{
  ip:           "0.0.0.0",
  lock:         semaphore.NewWeighted(10),
  portsMapping: portsMapping,
 }

 // TODO: Enable port range input
 // ps.Start(1, 65535, 10*time.Millisecond, portsMapping)
 document := js.Global().Get("document")
 documentTitle := document.Call("createElement", "h1")
 documentTitle.Set("innerText", "WebAssembly TCP Port Scanner")
 document.Get("body").Call("appendChild", documentTitle)
 placeHolder := document.Call("createElement", "h3")
 placeHolder.Set("innerText", "Scanning...")
 document.Get("body").Call("appendChild", placeHolder)

 // Edit the ports,
 ps.Start(50800, 50900, 1000*time.Millisecond, portsMapping)
 fmt.Println("Finished. Ports Mapping:")

 var openPorts []string
 for k, v := range portsMapping {
  if v == true {
   portString := strconv.Itoa(k)
   openPorts = append(openPorts, portString)
   openPortsParagraph := document.Call("createElement", "li")
   openPortsParagraph.Set("innerText", portString)
   document.Get("body").Call("appendChild", openPortsParagraph)
  }
 }
 fmt.Println("Scanned Ports: ", portsMapping)
 fmt.Println("Open Ports", portsMapping)
 placeHolder.Set("innerText", "Open Ports:")
}

毕竟，localhost并不是本地，而是远程

今天，当在个人电脑上配置和工作，我们都认为Localhost是一个安全或防护的环境。

曾经，攻击本地主机服务似乎要困难得多。

我们安装的持久性应用程序通常分配和侦听本地主机上的端口。

操作系统在启动后往往会打开本地主机网络接口上的端口。无论是Windows、Mac还是Linux，您的计算机都会在本地主机上侦听某些内容。正如我所展示的--Javascript或WebAssembly应用程序可以轻松地扫描这些本地主机服务。他们也可以滥用它们。

场景1：使用单次访问利用Linux客户端的RPC漏洞造成服务拒绝

https://cve.mitre.org/cgi-bin/cvename.cgi?name=CVE-2017-8779 RPC炸弹是一个示例漏洞，可让攻击者使用单个恶意UDP数据包，通过过时的Linux内置RPC服务(Rpcbind)对操作系统发起拒绝服务攻击。

想象一下：你访问一个网站。一秒钟后-您的计算机停滞或重置，破坏您最近未保存的工作。1.查找该易受攻击的端口是否打开(111)。2.向localhost的111端口发送精心构建的TCP数据包。3.您已成功关闭访客的计算机。

场景2：Windows打印机服务远程代码执行漏洞（CVE-2021-34527）

当Windows打印机服务不正确地执行特权文件操作时，存在远程代码执行漏洞。成功利用此漏洞的攻击者可以使用系统权限运行任意代码。然后，攻击者可以安装程序；查看、更改或删除数据；或者创建具有完全用户权限的新帐户。

由于浏览器可以访问localhost、0.0.0.0、192.168.1.1等，此漏洞可用于攻击数百万用户。我们许多人都在使用Windows，这项易受攻击的服务在启动时就会启动并运行。通过绑定到可网络访问的0.0.0.0上时，黑客可以利用此漏洞渗透组织。

开发人员经常在localhost上运行本地服务器/容器。我也经常忘记关闭它们(例如，在运行带有START=ALWAYS的docker容器时)。除了利用漏洞，还可以识别开发人员(例如，通过经常访问的StackOverflow/LinkedIn/Facebook页面)，以了解我们在开发中使用了哪些技术。

在我的拙见中，浏览器的WASM攻击面将随着时间的推移被更多地滥用。在本文中，我演示了关于浏览器的安全特性，网页如何与用户本地主机网络上的服务进行通信和映射。我给出了一个场景的例子，其中linux主机可以通过浏览器访问网页，利用WASM攻击流来遭受服务拒绝-以及如何使用微软的新漏洞CVE-2021-34527。WASI太棒了。WebAssembly非常棒。浏览器却没那么棒--它们总是会给我们所有人带来严重的风险和攻击向量，因为随着时间的推移，它们会变成支持即将到来的WASI规范的操作系统。
