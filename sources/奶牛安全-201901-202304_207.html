回顾一下第3章“栈布局”的内容。函数运行时，栈的示意图大致如下：

当函数退出时，ebp所指向的fp（桢指针）就会放入ebp里，而紧挨着这个fp的ret（返回地址）就会放入eip，然后CPU取eip的值所指向的指令来执行。如果在函数执行时，往局部变量（var）写内容越界了，导致局部变量的数据淹没了fp和ret。那么，ebp，eip就会被写入非法值。这种情况叫栈溢出。如下图

在栈溢出情况下，fp/ret对的链表关系就损坏，不完整，调试器就无法显示正确的函数栈了。比如下图

这种coredump往往让人无法从何入手，即使连现在的很多讲到栈溢出利用的书，也只是一次次地调试来找到崩溃指令，在遇到难重现的情况下，这种方法就不太可行了。

实际上，这种coredump还是有根可寻。如果仔细观察上面的栈和函数退出时的指令(大多如此)

或


的话，会发现这样的规律:

  1. esp的值不会被覆盖。它永远指向栈顶。
  2. fp/ret对所组成的链表没有完全被破坏，其它地方还是会维持这样的关系。
  3. 由于栈地址从栈顶到栈底是由低到高的原因，如果桢指针fp1的内容是fp2，桢指针fp2的内容是fp3.那么，它们和esp是存在这样的关系: esp < fp1 < fp2 < fp3
  4. 如果有两对fp/ret对 （fp1，ret1），（fp2，ret2），fp1的内容刚好是fp2.那么它们满足第3点外，ln ret1和ln ret2都能够列出函数符号，除非是dll被strip得非常干掉，但无论如何，ret2上一条指令肯定是调用ret1所在的函数。可以通过反汇编来验证（当然这是dll里面的符号被strip得非常干净的情况下）

由上面这4条规律，可以得到这样的定位方法：

  1. 通过dd esp查看由esp开始的内存。

  2. 找到某个内容比esp值大，且数值相差不是很大的内存单元，命名为M11。把M11的下一个单元叫做M12.

  3. 用ln命令来查看M12的内容，如果没有显示函数符号，跳过M11，回到第2步。

  4. 用dd M11 L 2来得到两个内容（M21，M22）。如果M21的内容小于M11的内容，则跳过M11，回到第2步。

  5. 用ln命令来看M22,如果没有显示函数符号，跳过M11，回到第2步。如果OK，则直接跳到M21，回到第4步
