回顾一下第3章“栈布局”的内容。函数运行时，栈的示意图大致如下：

![](../Images/332577470fdd84eb8e55b871c857d72a.png)

当函数退出时，**ebp**所指向的`fp`（桢指针）就会放入**ebp**里，而紧挨着这个`fp`的`ret`（返回地址）就会放入**eip**，然后CPU取**eip**的值所指向的指令来执行。如果在函数执行时，往局部变量（`var`）写内容越界了，导致局部变量的数据淹没了`fp`和`ret`。那么，**ebp**，**eip**就会被写入非法值。这种情况叫栈溢出。如下图

![](../Images/14089a79338833c99a0c207aa59af0f2.png)

在栈溢出情况下，`fp/ret`对的链表关系就损坏，不完整，调试器就无法显示正确的函数栈了。比如下图

![](../Images/8f4d3907e6834640868cc70f5db28d4d.png)

这种`coredump`往往让人无法从何入手，即使连现在的很多讲到栈溢出利用的书，也只是一次次地调试来找到崩溃指令，在遇到难重现的情况下，这种方法就不太可行了。

实际上，这种`coredump`还是有根可寻。如果仔细观察上面的栈和函数退出时的指令(大多如此)

![](../Images/6a912949261ea14d61af43460a50948a.png)

或

  

![](../Images/d3fb183f9907a70f0748c0e6293555bb.png)

的话，会发现这样的规律:

1.  **esp**的值不会被覆盖。它永远指向栈顶。
2.  `fp/ret`对所组成的链表没有完全被破坏，其它地方还是会维持这样的关系。
3.  由于栈地址从栈顶到栈底是由低到高的原因，如果桢指针`fp1`的内容是`fp2`，桢指针`fp2`的内容是`fp3`.那么，它们和**esp**是存在这样的关系: `esp < fp1 < fp2 < fp3`
4.  如果有两对`fp/ret`对 `（fp1，ret1），（fp2，ret2）`，`fp1`的内容刚好是`fp2`.那么它们满足第3点外，`ln ret1`和`ln ret2`都能够列出函数符号，除非是dll被strip得非常干掉，但无论如何，ret2上一条指令肯定是调用ret1所在的函数。可以通过反汇编来验证（当然这是dll里面的符号被strip得非常干净的情况下）

由上面这4条规律，可以得到这样的定位方法：

1.  通过`dd esp`查看由**esp**开始的内存。
    
2.  找到某个内容比**esp**值大，且数值相差不是很大的内存单元，命名为M11。把M11的下一个单元叫做M12.
    
3.  用`ln`命令来查看M12的内容，如果没有显示函数符号，跳过M11，回到第2步。
    
4.  用`dd M11 L 2`来得到两个内容`（M21，M22）`。如果M21的内容小于M11的内容，则跳过M11，回到第2步。
    
5.  用`ln`命令来看M22,如果没有显示函数符号，跳过M11，回到第2步。如果OK，则直接跳到M21，回到第4步
