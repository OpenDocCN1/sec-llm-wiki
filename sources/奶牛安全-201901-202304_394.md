在C语言里，数组就是相同类型变量的集合体。由这个定义，可大致得知数组的特征：

1.有首元素。而首元素的地址和数组地址一样，即有基地址

2.每个元素的大小是一样的。那么每个元素相对基地址的偏移值应该是元素大小和索引值的乘积。

也就是说，基地址和与索引值成比例的偏移值有可能是数组的特征。

还是按照上面的方式来逐个对各类型的数组进行探究。

先看一下char型的数组

![](../Images/c3dd4f924ed45c5111eb5ed352cc3e74.png)

再看一下它的汇编：

| ![](../Images/449ded9c46b25597a70ebb9b5876e532.png) |
| --- |
| Ø   esi存放着printf的地址Ø   第一次printf时，第一个参数是0x004020f4,第二个参数是ebp-0x14h, 第三参数是ebp-0x5.由第三章可知，ebp-0x14h是buf\[0\]的地址，而ebp-0x5是buf\[15\]的地址。Ø   ebp-0x14是基地址Ø   由ebp-0x5是尾元素和ebp-0x14是首元素，可知，数组首元素的地址比尾元素的小。即数组在内存的布局是递增Ø   第二个红圈是for循环，由“inc eax”可以看出,char型数组的元素是递增，且由” mov  byte ptr \[ebp+eax-14h\],bl”知递增的步幅为1。和char的大小是一样的。Ø   局部变量c貌似没有存放在栈上，只是放在bl上。这是被优化了。Ø   ebp-4存放着的东西不是程序里面定义的，是windows安全技术的一种。在后面的章节会讲到这个话题。 |

打一下断点来验证一下上面结论

| ![](../Images/828250396106919cbbcf315da97a5370.png) |
| --- |
| Ø   ebp-14单元里存放的值是0x64636261,由于intel CPU是little endian,所以，正好是abcd.Ø   元素之间确实是有序地递增，步幅为1 |

继续看一下short的数组：

![](../Images/3fb6bf614eb69ac540fba14d77e9a474.png)

看一下相应的汇编：

| ![](../Images/7680ac055800e8aa2e7ebdfe810605f8.png) |
| --- |
| Ø   ebp-0x24是首元素地址，也是基地址。ebp-0x6是尾元素地址。Ø   数组在内存的布局是递增的。Ø   在第二个红圈里，eax存放着索引值i, si放着0x32 = 50.Ø   在第二个红圈里，word ptr说明是short型。Ø   在第二个红圈里，ebp+eax\*2 – 24h 如果写成ebp-24h + eax\*2,就可以看出，它表示的地址  ＝ 基地址 + 索引值\*2。而short的大小刚好是2. |

继续对int, long,float,double,可以得到下表：

| 类型 || 特征 |
| --- | --- |
| char || 基地址 + 索引值\*1 |
| short || 基地址 + 索引值\*2 |
| int || 基地址 + 索引值\*4 |
| long || 基地址 + 索引值\*4 (即使在64-bit windows系统下，因为windows 64采用LLP64标准).其实在windows系统，long和int是等同的。 |
| float || 基地址 + 索引值\*4 (因为单精度是占4个字节的),要配合浮点计算的指令确认 |
| double || 基地址 + 索引值\*8 (双精度占8个字节) ,要配合浮点计算的指令确认 |
| 指针 || 基地址 + 索引值\*4 |

其实，基地址+索引值\*sizeof( element)这些方式，用汇编可以有很多种表示形式。如下面也算是一种

| lea eax, base  // 把base地址放到eax里mov ecx, index // 把index放到ecx里。mul ecx, 4add eax, ecx   //这里eax就存放了index指向的元素地址了。 |
| --- |
