在C语言中，基本的数据类型无非是char, short, int,long, float, double及相应的指针。那么它们在内存里是怎样存放的，在汇编指令里显示怎么样的特征呢？在这里就分别来探究一下char, short, int, long, float, double的特征。

先用一个例子来看一下char的特征：

![](../Images/b5c060b718dfa7823057823bedb3aba1.png)

选择“release”，但不要优化，设置可以见第3章。编译它。用windbg打开它，反汇编这个函数：

![](../Images/ea1cd175bdf0ba47f535196e24e50593.png)

试一下在红圈的那一条指令打断点再运行它。看一下程序的输出和windbg的数据

![](../Images/75ff58998b8282614ebf5b5e4a13aab4.png)

由上面来看，可以看到c1-c3的地址分别是0x0012ff76, 0x0012ff75,0x0012ff77.和ebp的值0x0012ff7c, esp的值0x0012ff74相差不远。虽然在第3章，已经知道局部变量是存放在栈，可从汇编的角度理解是不太友好，用这个例子会更直观点。放开这些题外话，从上面还可以看到’a’, ‘b’, ‘c’的顺序是bac，和预期不一样。但无论怎样，来看一下，a,b,c的数值表示61,62,63是在哪些指令存放到这几个地址的。

![](../Images/386a895e5f150128f56b6093f9bbf437.png)

从上面可以看到,存放61,62,63那几条指令，都有一个共同的特征，都是”byte ptr”。在x86汇编里，byte ptr说明操作数是字节。一个char型数据占一个字节。也就是说，byteptr是指操作char型数据的特征。

接着看一下相应的指针。

![](../Images/b28423520c08d9978fb2e93e9e9e0b11.png)

可以看到ebp-4存放着就是c1的地址0x0012ff76,可以知道，它就是指针p.它是怎么把c1的指针放过去的呢？

![](../Images/ef54d8228f0453ea1989f7896f4876d2.png)

在x86汇编中，lea指令就是把内存单元的地址放进寄存器里。

lea eax, \[ebp-6\]的意思就是 eax = ebp-6，和mov eax, ebp-6的意思一样。再看一下:

![](../Images/77a44148074491b7fc43293a61c51602.png)

![](../Images/ef2b756cf9eb24f8b569298871be5d15.png)

可以看出，lea指令是用来获取一个内存单元的地址，也就是说，它就是指针的特征指令。

 

由上面已经得到了char类型及相应指针的特征，现在把上面的程序改一下，来获取一下short的特征。

![](../Images/56bd79cc24529ec9dc4a70031eaa665d.png)

再看汇编

![](../Images/4051876de989b294457a4ac3da249796.png)

上面汇编和char类型的程序的差不多，差别只是在红线圈出来的：

1.      short是两个字节的，所以，word ptr就是它的特征码。

2.      short不会像char那样挤压在一起，而占四个字节空间。

3.      short\*指针和char\*指针的特征一样。

 

如果继续对int,long, float, double这些类型进行类似的探究，会得出类似的结论。综合一下，如下表

| 类型 || 特征 |
| --- | --- |
| char || byte ptr |
| short || word ptr |
| int || dword ptr |
| long || dword ptr(即使在64-bit windows系统下，因为windows 64采用LLP64标准).其实在windows系统，long和int是等同的。 |
| float || dword ptr(因为单精度是占4个字节的),要配合浮点计算的指令确认 |
| double || qword ptr(双精度占8个字节) ,要配合浮点计算的指令确认 |
| 指针 || lea |
