一、Linux为什么需要加固？

Linux操作系统是一个通俗且被混淆的说法，它应该是GNU/Linux。我们不是咬文嚼字，因为这和它的稳定及安全性有重大关系。


二、开源软件与Linux Kernel

GNU/Linux 是GNU（通用公共许可证(GPL)）软件与Linux Kernel 的统称。由于 Linux 实际是一个操作系统的核心（ Kernel ）而不是一个完整的操作系统，它缺少正常使用中许多必要的软件，而 Linux 发行版则是将 Linux kernel 、GNU 软件包、工具集和文档、桌面环境等打包在一起的一个完整操作系统。(如下Linux与GNU的组合图标)。

GNU software 开源社区的一个很明显的问题是，很多项目都活不长，开发者在丢出最初几个版本后就弃坑的项目比比皆是。造成这种情况的原因是多种多样的，总的来说分享源码是开发者的权利，不在提供后续支持也是某个人的权利。毕竟社区不是公司，没有强制约束力，也不对社区软件的后续维护、版本更新付法律责任（仅有版权约束）。

目前 Linux 发行版可以分为由公司维护的版本如 Red Hat (Red Hat)， openSUSE (SUSE)和 Ubuntu (Canonical Ltd. )，以及由社区维护的版本如 Debian 、Arch Linux 、Mandriva 。中国的第一个 Linux 发行版红旗 Linux 于1999年8月发行。

GNU/Linux系统经过几十年的发展已经稳定安全了许多，但是这种安全稳定是建立在操作人员的专业素质上。


三、工业环境的特殊性

工业主机需要与工业控制系统进行实时数据交互，以保证工业控制系统能够稳定、高效运转，工业主机的安全关乎整个工业控制系统的安全等级。同时，工业主机作为工业控制系统的HMI接口，是工业控制系统与外界进行交互的重要途径，因此工业主机安全在工控信息安全的建设工作中事很重要的一个环节。

在《工业控制系统信息安全防护指南》中:

1、安全软件选择与管理

（一）在工业主机上采用经过离线环境中充分验证测试的防病毒软件或应用程序白名单软件，只允许经过工业企业自身授权和安全评估的软件运行；

2、配置和补丁管理

（一）做好工业控制网络、工业主机和工业控制设备的安全配置，建立工业控制系统配置清单，定期进行配置审计；

3、物理和环境安全防护

（二）拆除或封闭工业主机上不必要的USB、光驱、无线等接口。若确需使用，通过主机外设安全管理技术手段实施严格访问控制。

同时，在《国家能源局关于印发电力监控系统安全防护总体方案等安全防护方案和评估规范的通知》(国家能源局36号文)的《附件1电力监控系统安全防护总体方案》中(2.1.4信息安全等级保护划分)明确了生产控制大区内各系统与《信息安全技术网络安全等级保护测评要求》中各等级的对应的关系。下面我们就简单介绍等保中关于Linux主机加固部分的一些知识。


四、GNU/Linux如何加固？

出于安全性的考虑，工控企业采用由国产服务器硬件平台和Linux Kernel的国产定制操作系统组成的基础架构平台已经十分普遍。如：电力行业的用户会首先考虑采用国产的操作系统（主要是基于Linux kernel定制的操作系统），并在此基础上做一些安全方面的重大改进。电力行业的重要服务器（AVC/AGC服务器/光功率服务器等）及工程师站都采用此类操作系统。   

基于Linux Kerne系统的安全性和工控行业特殊性，现场工业主机在投入使用后基本没有采取更新安全补丁、安装加固软件、配置安全策略等手段来维护其安全。对比现场Windows操作系统工业主机其安全方面也并无太多优势。


五、系统专用

停止不必要的服务及软件，在GNU/Linux上配置则比较麻烦，因为不同发行版本的检查方式、配置方式都不一样。限于篇幅问题，不过多介绍仅举3例示意，毕竟专业的事还需要专业的人去做；

a.多余账户禁用

首先备份配置文件：

#cp -p /etc/passwd /etc/passwd_winicssec

检查系统能可登录的账户情况：

#cat /etc/passwd|egrep -v “#|false|nologin”

解读：此条命令是查看当前系统中能登录的用户，需注意不常见的shell和陌生用户；

编辑配置文件：

#vim /etc/passwd

如图所示，在不需要的账户前面加上”#”，将该账户禁用掉。如果恢复某个用户，则将前面的”#”去掉即可。如果忘记了该用户的密码时则使用passwd xxx，设置新密码即可（xxx　表示要设置密码的用户名）；

b.用户密码复杂性要求设置

此处涉及２部分。一个是 /etc/login.defs 配置文件，另一个是使用 PAM的cracklib 模块，cracklib能提供额外的密码检查能力。CentOS、Fedora、RHEL 系统已经默认安装了 cracklib PAM 模块。在Debian、Ubuntu 或 Linux Mint 系统上需执行如下面的操作：

# apt-get install libpam-cracklib

进行模块安装（安装过程如下图所示）。

为了强制实施密码策略，我们需要修改 /etc/pam.d 目录下的 PAM 配置文件。一旦修改，策略会马上生效。

注意： PAM中cracklib 模块的密码策略只对非 root 用户有效，对 root 用户无效。

  • 下面就login.defs配置文件进行说明；

备份方法：

#cp -p /etc/login.defs  /etc/login.defs_winicssec

加固方法：

已修改所有账户的登录密码.  符合8位长度，三种不同类型。

#vim /etc/login.defs修改配置文件

PASS_MAX_DAYS 90 #新建用户的密码最长使用天数

PASS_MIN_DAYS 0  #新建用户的密码最短使用天数

PASS_WARN_AGE 7 #新建用户的密码到期提前提醒天数

PASS_MIN_LEN 8   #最小密码长度8

对cracklib模块进行说明；

找到同时有 “password” 和 “pam_unix.so” 字段并且附加有 “remember=5” 的那行，它表示禁止使用最近用过的5个密码（己使用过的密码会被保存在 /etc/security/opasswd 下面）。下面分别演示Debian系列及RedHat系列Linux系统的配置；

Debian、Ubuntu 或 Linux Mint 系统上：

# vim /etc/pam.d/common-password
 password [success=1 default=ignore] pam_unix.so obscure sha512 remember=5

CentOS、Fedora、RHEL 系统上：

# vim /etc/pam.d/system-auth
 password sufficient pamunix.so sha512 shadow nullok tryfirstpass  useauthtok remember=5

c.设置密码复杂度

找到同时有 “password” 和 “pam_cracklib.so” 字段并且附加有 “ucredit=-1 lcredit=-2 dcredit=-1 ocredit=-1” 的那行，它表示密码必须至少包含一个大写字母（ucredit），两个小写字母（lcredit），一个数字（dcredit）和一个标点符号（ocredit）。

Debian、Ubuntu 或 Linux Mint 系统上：

#vim /etc/pam.d/common-password
 password requisite pam_cracklib.so retry=3 minlen=10 difok=3 ucredit=-1  lcredit=-2 dcredit=-1 ocredit=-1

CentOS、Fedora、RHEL 系统上：

# vim /etc/pam.d/system-auth
 password requisite pam_cracklib.so retry=3 difok=3 minlen=10 ucredit=-1  lcredit=-2 dcredit=-1 ocredit=-1


六、配置优化加固

系统通用优化配置主要有Linux Kernel优化、网络访问加固、用户权限配置、远程控制方式优化配置、日志优化配置、操作监控配置、异常报警配置等；

服务软件优化配置则根据不同用途的应用软件有很大关系，比如优化配置WEB 服务器和优化配置数据库服务器是完全不一样的，而工业环境中的应用软件配置优化则又完全不同，需要根据实际情况进行针对性的配置优化,下面就对几个常用项进行配置为实例进行演示，专业的事还需要专业的人去做；

  • Kernel 优化(仅以WEB服务器优化为例，列出几个常用项；

#vim /etc/sysctl.conf

net.ipv4.tcp_syncookies = 1
 net.ipv4.tcp_tw_reuse = 1
 net.ipv4.tcp_tw_recycle = 1
 net.ipv4.tcp_fin_timeout = 30

net.ipv4.tcp_keepalive_time = 1200
 net.ipv4.ip_local_port_range = 10000 65000
 net.ipv4.tcp_max_syn_backlog = 8192
 net.ipv4.tcp_max_tw_buckets = 5000

#sysctl -p

配置内容解释：

net.ipv4.tcp_syncookies = 1

#表示开启SYN Cookies。当出现SYN等待队列溢出时，启用cookies来处理，可防范少量SYN攻击，默认为0，表示关闭；

net.ipv4.tcp_tw_reuse = 1

#表示开启重用。允许将TIME-WAIT sockets重新用于新的TCP连接，默认为0，表示关闭；

net.ipv4.tcp_tw_recycle = 1

#表示开启TCP连接中TIME-WAIT sockets的快速回收，默认为0，表示关闭；

net.ipv4.tcp_fin_timeout

#修改系統默认的 TIMEOUT 时间。

net.ipv4.tcp_keepalive_time = 1200

#表示当keepalive起用的时候，TCP发送keepalive消息的频度。缺省是2小时，改为20分钟。

net.ipv4.ip_local_port_range = 10000 65000

#表示用于向外连接的端口范围。缺省情况下很小：32768到61000，改为10000到65000。（注意：这里不要将最低值设的太低，否则可能会占用掉正常的端口！）

net.ipv4.tcp_max_syn_backlog = 8192

#表示SYN队列的长度，默认为1024，加大队列长度为8192，可以容纳更多等待连接的网络连接数。

net.ipv4.tcp_max_tw_buckets = 6000

#表示系统同时保持TIME_WAIT的最大数量，如果超过这个数字，TIME_WAIT将立刻被清除并打印警告信息。默 认为180000，改为6000。

sysctl -p是在命令行shell上执行，使内核配置立即生效。

  • 远程控制方式优化配置

Linux 服务器默认使用SSH服务进行远程管理，SSH是SecurityShell的简写，是最常用的远程登录服务，虽然其比telnet安全多，但是也存在一定的安全配置漏洞。一些不友好的小伙伴们会使用一些不和谐程序对ssh服务进行暴力破解。对ssh服务进行适当的配置可以完全杜绝暴力破解。同时对sshd服务进行优化配置可以加快连接速度，减少耗费带宽。

Ssh 的默认配置文件为/etc/ssh/sshd_config,我们该服务的加固优化主要基于此配置文件的参数配置；

#cp /etc/ssh/sshd_config  /etc/ssh/sshd_config.winicssec

#vim /etc/ssh/sshd_config

Port 56789                    #修改ssh连接使用的端口为56789(默认22)

ListenAddress 192.168.1.10 #仅监听此服务器上的此ip地址；

PermitRootLogin no         #不允许以root超级用户进行ssh连接

PermitEmptyPasswords no    #不允许使用空密码的用户连接

UseDNS no                        #不能通过DNS进行ssh连接

PubkeyAuthentication yes #使用秘钥方式进行验证登录

AuthorizedKeysFile      .ssh/authorized_keys  .ssh/authorized_keys2

PasswordAuthentication no#不允许密码验证登录

KerberosAuthentication no#不允许Kerberos方式验证

PrintMotd no#不打印信息

PrintLastLog yes #打印最后一次登录信息

TCPKeepAlive yes#开启TCP保活心跳

ClientAliveInterval 0#推送客户端配置，重试验证

ClientAliveCountMax 3#推送客户端设置，最多重试３次

Banner none#不打印版本信息

修改配置文件后需要重启ssh服务，命令如下：

#/etc/init.d/sshd restart

GNU/Linux系统上有没有病毒？黑客或恶意软件入侵后是否有办法排查？能否有一套系统能将他们拒之门外？

答案：有。

GNU/Linux 主要活跃在服务器领域，在互联网时代初期就被攻击者们盯上，不过自动传播的病毒较少，因为攻击者们主要的目的不是破坏掉Linux服务器而是利用服务器做别的坏事。
