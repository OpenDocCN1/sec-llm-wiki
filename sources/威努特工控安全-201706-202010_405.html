2017年12月7日，美国ICS-CERT爆出CODESYS Runtime 2.3.X和2.4.X中发现严重漏洞，该漏洞可对基于CODESYS开发的控制设备进行远程操作，影响范围广泛。威努特ICS-Radar（https:// radar.winicssec.com）扫描引擎，对国内外采用CODESYS Runtime服务接入互联网的工控设备做了针对性的扫描探测，详细分析结果见下文。


一、CODESYS Runtime高危漏洞

1.1、漏洞简介


CODESYS Runtime（2.3.X和2.4.X）中发现允许未经身份验证的用户可以通过远程操作访问该系统。CODESYS Runtime包含一项以CODESYS Root权限运行的“plclinux_rt”服务，攻击者可向其端口2455发送特制数据包触发以下功能： 

1. 读/写/删除PLC任意文件；

2. 跳过当前执行PLC程序中的功能；

3. 循环执行当前执行PLC程序中的任何功能；

4. 删除当前执行PLC程序的当前变量列表。


1.2、漏洞分析

CODESYS是控制器开发系统（controller development system）的首字母缩略字，是针对可编程逻辑控制器（PLC）应用的集成开发环境，符合IEC 61131-3标准，是与硬件及制造商无关的集成开发环境。CODESYS支持IEC 61131-3标准的IL、ST、FBD、LD、CFC、SFC六种PLC编程语言，CODESYS软件的工作示意图如图1所示，CODESYS Runtime多被集成到PLC设备上，因此针对CODESYS Runtime的攻击就是针对PLC设备的攻击。

图1、CODESYS Runtime工作示意图


CODESYS是由位于德国肯普滕的软件公司3S-Smart Software Solutions公司所开发，V1.0版本于1994年发行。当前国内PLC用户使用的版本多为CODESYS V2.3， 最新的版本是CODESYS V3.5。

2012年，IOActive的安全研究人员Reid Wightman发现CODESYS Runtime 2.3.x和2.4.x版本中存在安全绕过漏洞（CVE-2012-6068），允许攻击者未经授权远程获取受影响PLC的管理访问权限，从而执行特权操作，并执行相当于对设备进行重新编程的文件修改操作。

针对该漏洞的漏洞利用工具codesys-shell.py已经公开，图2显示了利用该工具连接一个暴露在公网的工控设备，获取了命令执行权限。该漏洞利用工具的功能，相当于通过CODESYS软件，执行PLC-Browser功能，如图3所示。该漏洞针对PLC的文件读写操作，相当于通过CODESYS软件，执行Write file to PLC 或 Read file from PLC功能，如图4所示。

图2、CODESYS Runtime 2012年漏洞的利用工具

图3、CODESYS软件的PLC-Browser功能

图4、CODESYS软件的Write file to PLC或 Read file from PLC功能


2017年，SEC Consult在CVE-2012-6068的研究基础上发现了全新的安全绕过漏洞，允许未经身份验证的用户进行远程访问，读写删除任意文件，并篡改PLC正在执行的程序。

CODESYS Runtime 2.3.x和2.4.x版本中包含一项以CODESYS Root权限运行的“plclinux_rt”服务，该服务存在安全绕过漏洞。根据SEC Consult研究人员的研究成果，攻击者可向TCP端口2455发送特制数据包触发以下功能：


1. 读/写/删除任意文件，不需要任何的身份验证。

1）读取 "/etc/shadow"。

echo '[PoC removed]' | xxd -r -p | nc <PLC-IP> <Port>

2）删除 "/etc/test"。

echo '[PoC removed]' | xxd -r -p | nc <PLC-IP> <Port>


2. 正在运行的PLC程序中的功能可以被篡改。

1）跳过当前执行的PLC程序中的功能。

echo '[PoC removed]' | xxd -r -p | nc <PLC-IP> <Port>

2）循环执行当前执行的PLC程序中的任何功能。

echo '[PoC removed]' | xxd -r -p | nc <PLC-IP> <Port>

3）删除当前执行PLC程序的当前变量列表。

echo '[PoC removed]' | xxd -r -p | nc <PLC-IP> <Port>


该漏洞在漏洞利用过程中的攻击功能选取，是通过对CODESYS Runtime协议（TCP端口2455上的交互协议）报文的第七个字节的选择来达到的。第七个字节的功能选择如下：

0x31 -> 读取文件；

0x36 -> 删除文件；

0x0a -> 跳过当前方法；

0x24 -> 循环执行当前方法；

0x15 -> 删除变量列表。


在该漏洞的利用过程中，针对默认启用了SSH功能的PLC，未经身份验证的黑客可以利用本漏洞重写/etc/shadow文件（存储哈希密码），并取得PLC设备的Root权限，如图5所示。

1.4、联网设备漏洞影响范围统计

根据威努特ICS-Radar的扫描结果，发现全球采用CODESYS Runtime服务（TCP端口2455）接入互联网的工控设备的数量为1106个（如图6所示），其中德国数量最多，含有244个，占比22%；土耳其含有135个，占比12%。

该漏洞主要影响欧洲，对亚洲的影响较小，其中中国仅发现1台运行了CODESYS Runtime服务的设备接入互联网，如图7所示。

1.5、漏洞的安全解决方案

1.应急方案：

建议客户禁用“plclinux_rt”服务或关闭编程端口（TCP 2455），对于确需使用“plclinux_rt”服务或编程端口（TCP 2455）的设备，通过工业防火墙限制对其编程端口的访问（TCP 2455端口，仅允许指定的IP地址访问）。


2.最终方案：

针对WAGO PFC200系列PLC，更新固件版本到FW11的固件。

参考：https://store.codesys.com/codesys-control-for-pfc200-sl.html


使用CODESYS V3.X版本的软件进行PLC编程开发，比如CODESYS V3.5 SP12，可免除上述漏洞的影响。
