ISASecure认证简介:


在介绍ISASecure认证之前，首先了解一下相关的组织机构。

ISA：International Society of Automation，国际自动化协会，为工业和关键基础设施中使用的自动控制系统提供改善管理、安全、和网络安全工程技术标准。

ICSI：The ISA Security Compliance Institute，国际自动化协会的安全合规机构，成立于 2007 年，致力于为工业自动化控制系统的网络安全提供保障。 

ISASecure认证是ISCI基于 IEC62443 标准开发的合规性认证，目前工业控制领域最具权威安全认证。ISASecure认证包括3大类：

1.EDSA（Embedded Device Security Assurance）认证：嵌入设备安全保障认证，侧重设备级别的安全性保障，认证对象是独立的工控设备，比如PLC等。

2.SSA（System Security Assurance）认证：系统安全保障认证，侧重系统级别的安全性保障，认证对象是工控系统，比如DCS、SCADA、SIS等。

3.SDLA（Security Development Lifecycle Assurance）认证：安全开发生命周期保障认证，侧重安全开发过程的保障，确保安全被正确的设计和落地，认证对象是研发团队。

目前EDSA认证推广的比较好，有9个厂商的19款产品获得EDSA认证，包括：Honeywell、Schneider、Yokogawa、TOSHIBA、RTP、Hitachi、HIMA、Azbil、Beijing Consen。

ISASecure为每一类认证都定义了一套详细的规范文档及测试用例，方便厂家对照规范进行自检。

所有经过认证的产品或系统，都在ISASecure的官网（www.isasecure.org）有公布，这也方便最终工业厂商参考该列表进行工控设备选型，可以有效提升整个工控产业的安全保障。


EDSA认证:


EDSA认证是ICSI的第一个 ISASecure 认证项目，也是目前最受大家认可的安全认证，其目的在于促进工业行业加强工业自动化和控制系统（IACS）网络安全，项目提供一套通用的业界公认的设备及过程规范，从设备开发、生产、采购等各阶段保障嵌入式设备安全。

EDSA认证主要包含下面4种评估要素：

1.ERT（Embedded Device Robustness Testing），包括VIT（Vulnerability Identification Testing）和CRT（Communication Robustness Testing），遵循技术规范 ISA Secure EDSA 310,401-406，测试设备的已知漏洞及协议健壮性。VIT即漏洞扫描，一般使用Nessus来测试，当前ISASecure定义了一套Nessus的配置规范进行安全扫描。CRT即通信健壮性测试，一般采用Fuzzing测试等黑盒测试方法。

2.FSA-E（Functional Security Assessment for Embedded Device )，遵循技术规范 ISASecure EDSA 311，测试设备的功能是否安全实现，比如：账号管理、接入控制、公钥基础设施管理、防暴力登录、会话管理、加密算法、错误处理、防DoS、备份恢复等。

3.SDLPA（Security Development Lifecycle Process Assessment），审核评估安全特性的开发维护生命周期管理，这一部分的详细说明参见SDLA认证。

4.SDA-E（Security Development Artifacts for Embedded Devices），审核评估安全特性设计开发落地情况，即具体待测试产品的过程文档。

EDSA安全认证的思路：底层支撑（协议、平台）安全保障+功能安全保障+开发过程安全保障，最终实现全流程透明化安全检查，彻底保证产品安全性。

EDSA的认证对象是单个工控设备，比如一个PLC，具有很强的可实施性，是现在最受欢迎的认证。

CRT测试认证是所有级别认证的基础，也是所有认证里面最容易实施的认证测试。CRT定义了一套测试用例，覆盖了Ethemet、ARP、IP、ICMP、TCP、UDP六种协议，包含协议的基本功能测试、压力测试和Fuzzing测试。CRT测试要求所有的测试用例可以复现，并可以保存复现条件（测试报文），所以CRT的测试报告可信度很高，有利于发现设备的未知问题。


SSA认证:


SSA认证指对工控系统的安全保障认证，一个工控系统产品需要符合下面的条件才能进行SSA认证：


1.该系统包含超过一个工控设备。

2.该系统可以从单一的供应商购买，尽管它可能包含来自不同厂商的硬件和软件。

3.该系统具有唯一产品标识，供应商把它作为一个整体来销售。

4.该系统具有良好的配置管理和版本管理。


SSA认证主要包括下面5种评估要素：

1.SRT：系统健壮性测试，最基本的安全测试，包括：IP/Port扫描、漏洞扫描、漏洞挖掘、网络健壮性测试等。

2.FSA-E：设备级别的功能安全性保障，包括：身份认证授权、数据加密保护、限流、资源可用性、过载保护。

3.FSA-S：系统级别的功能安全性保障，功能和FSA-E类似，但属于系统级别的功能点，可能涉及多个设备。

4.SDLPA：安全开发生命周期过程保障，检查系统开发及维护过程是否符合安全标准要求，主要检查开发过程是否具有标准流程要求并考虑了安全因素。比如是否进行了安全培训；是否进行了安全的配置管理；是否进行了威胁建模等。这一部分的详细说明参见SDLA认证。

5.SDA-S：系统级别的安全开发过程资产审核，主要检查系统在设计开发过程中留下来的文档或代码资产。


SSA认证分为4个级别（Level-1、Level-2、Level-3、Level-4），Level-4是最高级别，级别越高，对安全方面的要求越高。

SSA认证的思路是：底层支撑（协议、平台）安全保障 + 组件功能安全保障 + 系统功能安全保障 + 开发过程安全保障，最终实现全流程透明化安全检查，彻底保证产品安全性。

SDLA认证:


和前面两个认证不同，SDLA认证是对研发团队做认证，不针对具体的某一款工控产品做认证。

SDLA认证对研发团队的基本要求是有文档化的基于版本控制的生命周期管理体系，否则无法进行SDLA认证。

SDLA不针对具体某一款产品，所以可以绑定多款产品，也分为设备基本的SDLA和系统级别的SDLA。

SDLA认证涉及的要素非常多，简单列举其中的一部分：

1.安全需求管理。

2.安全开发计划。

3.安全培训。

4.安全威胁建模。

5.安全开发工具及配置管理。

6.开发环境及配置管理。

7.文档管理及配置。

8.代码管理及配置。

9.变更管理及配置。

10.组件管理及配置。


SDLA认证分为4个级别（Level-1、Level-2、Level-3、Level-4），Level-4是最高级别，级别越高，对安全方面的要求越高。

SDLA认证的思路是：安全从需求、设计到实现，包括任何变更和后期维护，都有标准的流程规范可以遵守，并且都有相应的安全输出可以审查。

SDLA认证对象是一个研发团队，涉及到产品开发流程，对研发团队的规范化有很高的要求。目前获得SDLA认证的主要Schneider Electric和Honeywell的几个研发机构。

前面讲的EDSA认证和SSA认证，都有涉及到SDLA认证的内容，这部分内容是可以同时申请两个认证。比如一个工控设备的EDSA认证可以同时申请SDLA认证，也可以只申请EDSA认证，进行开发过程的安全审查但不申请SDLA认证。

不管哪种认证，都需要进行安全开发生命周期的安全审查，必须有规范的过程，才能有合规的产品；必须有安全的全生命周期管理控制，才能保证最终产品的安全性。


总结：

通过上面的介绍可以看出，ISASecure认证体系是一个完备的安全认证体系，也是目前国际上最受认可的工控安全认证体系。这个认证体系覆盖了设备安全、系统安全、安全开发生命周期，针对每一种协议和安全特性功能，都定义了详细的测试用例和说明，体系完备并且可落地。

几年前，日本已经把ISASecure认证体系全套移植到日本，积极参加ISA相关规范的制定和推广，ISASecure认证体系也是日本的工控安全认证体系，ISASecure在官网有专门的日文网站。

近几年，随着工业4.0、工业互联网、智能制造等概念的提出和推广，我国对工控系统的安全也越来越重视，把工控系统的安全列为国家关键基础设施的安全范畴。

工控系统的安全，需要一套标准和规范来约束，标准和规范的落地实施，就依赖与安全认证体系，希望在不久的将来，我们国家也能建立自己的工控安全认证体系，从根本上保证工业控制设备和工业控制系统的安全。
