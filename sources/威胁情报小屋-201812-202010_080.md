macos分析

  

dropper

  

    dropper用于将后门安装到受感染的系统中并建立其持久性

    

![](../Images/4ba0d7dcb4d8f49dddc6744624c2aede.png)

  

    dropper中的所有字符串以及后门都使用硬编码的RSA256密钥加密。有两种形式的加密字符串：RSA256加密字符串，以及自定义base64编码和RSA256加密字符串。  

![](../Images/81cf185256b5659d0127c7f1eef0a0c5.png)

    使用*setStartup（）*方法之前，dropper首先检查它是否以root身份运行。*GET\_PROCESSPATH*和*GET\_PROCESSNAME*方法将解密应安装后门的硬编码路径和文件名。不同用户对应路径如下

*   对于root用户
    

路径：*/Library/CoreMediaIO/Plug-Ins/FCP-DAL/iOSScreenCapture.plugin/Contents/Resources/*  
processname: *screenassistantd*

*   对于普通用户
    

路径：*〜/ Library / Spelling /  
*processname：*spellagentd*

确定路径后，利用*Loader :: installLoader*方法，读取硬编码的64位Mach-O可执行文件（魔术值0xFEEDFACF），写入确定好的路径文件中。

![](../Images/c692caec158677b3bfcbd603fabcf724.png)

    

    当dropper安装后门时，它将其属性设置为“hidden”，并使用touch命令将文件日期和时间设置为随机值：touch -t YYMMDDMM“/ path / filename”> / dev / null。然后访问权限将更改为0x1ed = 755，相当于u = rwx，go = rx。  

![](../Images/aa76d1f8b9658473a408a2c4debd93ca.png)

  

    之后，将在/ Library / LaunchDaemons /或〜/ Library / LaunchAgents /文件夹中创建持久性文件。 RunAtLoad键将命令launchd在操作系统启动时运行守护程序，而KeepAlive键将命令launchd以使进程无限期运行。 此持久性文件也设置为隐藏随机生成的文件日期和时间。

![](../Images/002bf848abc76db6e7df205f5223a74c.png)

  

*launchctl load /Library/LaunchDaemons/filename.plist> / dev / nul*或*launchctl load~ / Library / LaunchAgents / filename.plist> / dev / nul*然后命令操作系统在登录时启动释放的后门文件。dropprt将在流程结束时删除自己。

    在发送到C＆C服务器之前，所有这些数据都经过加密和加密。该过程详述如下：

  

1.混淆  

        Class *Parser*有几种方法，每种方法对应一种变量类型 - *Parser :: inBytes*，*Parser :: inByte*，*Parser :: inString*和*Parser :: inInt*。

![](../Images/34f20db5eca465830cbd9ed0e12d692e.png)

  

    如果*clientID*等于以下字节序列B4 B1 47 BC 52 28 28 73 1F 1A 01 6B FA 72 C0 73，则使用第三个参数（0x10）计算加扰版本，该参数被视为DWORD。每个四字节字节与它进行异或，如下面的示例所示。

![](../Images/d353736bc7797f24a57f2135c8f17782.png)

    当加扰一个字节时，加扰器首先确定字节值是奇数还是偶数。 如果该值为奇数，则将该字节以及一个随机生成的字节添加到该数组。 在偶数值的情况下，首先添加随机生成的字节，然后添加字节。 在上面的情况中，第三个参数是'1'= 0x31，这是一个奇数。 这意味着它将字节'1'和一个随机生成的字节添加到最终的加扰数组中。  

![](../Images/e108ab553576f293d413756ff7bd1b3e.png)

    当加扰字符串时，加扰器生成一个5字节长的序列。首先，它生成一个随机字节，然后是三个零字节，一个随机字节，最后是字符串长度的字节。假设我们想要争夺字符串'Mac OSX 10.12'。其长度为13 = 0x0d，两个随机字节为0xf3和0x92。最后的5字节序列看起来像F3 00 00 00 92 0D。然后用5字节序列对原始字符串进行异或。

![](../Images/7c27aeabbcf1d7c6905bc77ebe906a35.png)

  

2.  加密
    

    加扰的字节序列被传递到*Packet :: Packet*类的构造函数，该类创建一个随机的AES256密钥并使用此密钥加密缓冲区。

3.  编码加密密钥
    

        为了使C＆C服务器解密加密数据，随机生成的AES256密钥必须与加密数据一起包含在数据包中。但是，该键也会被操作XOR 0x13加扰，然后对每个字节应用ROL 6操作。

反调试和反沙箱

  

    与OceanLotus macOS二进制文件一样，该示例使用UPX打包，但大多数打包程序识别工具都不会识别它，可能是因为它们主要包含依赖于“UPX”字符串存在的签名，而且， MACH-O签名不太常见，不经常更新。这种特殊的特性使静态检测更加困难。解压缩后，一个有趣的事情是入口点位于.TEXT段的\_\_cfstring部分的开头。此部分具有图1中所示的标志属性。

  

![](../Images/cde661b9b3539dcff91ee6068c7b15be.png)

  

    代码位于\_\_cfstring部分欺骗了一些反汇编工具以将代码显示为字符串。

![](../Images/0bac458a19ad97918c6b22fc61745377.png)

    运行时，二进制文件首先创建一个线程作为反调试检测，其唯一目的是不断检查是否存在调试器。以下是检测方式：

![](../Images/d763a904157fbd2f456623355cb8d066.png)

如果监视程序检测到存在调试器，则调用exit函数。此外，样本然后通过发出以下两个命令来检查其环境：  
ioreg -l | grep -e“Manufacturer”和sysctl hw.model  
并根据已知虚拟化系统字符串的硬编码列表检查返回值：oracle，vmware，virtualbox或parallels。最后，通过命令：  
system\_profiler SPHardwareDataType 2> / dev / null | awk'/ Boot ROM Version / {split（$ 0，line，“：”）; printf（“％s”，line \[2\]）;}  
检查机器是否为以下之一：“MBP”，“MBA” ，“MB”，“MM”，“IM”，“MP”和“XS”。这些代码代表系统的模型。例如，“MBP”代表MacBook Pro，“MBA”代表MacBook Air等等......

字符串解密

  

    与以前的变体一样，字符串使用AES-256-CBC（十六进制编码密钥：9D7274AD7BCEF0DED29BDBB428C251DF8B350B92用零填充，IV用零填充）加密，使用CCCrypt 功能。密钥已从以前的版本更改，但由于该组仍使用相同的算法来加密字符串，因此可以自动解密。与本文一起，我们发布了一个利用Hex-Rays API来解密二进制文件中存在的字符串的IDA脚本。该脚本可能有助于将来对OceanLotus的分析以及我们尚未获得的现有样本的分析。这个脚本的核心是一个通用的方法来获取传递给函数的参数。此外，它会查找参数分配以查找其值。可以重用此方法来检索函数的参数列表，然后将它们传递给回调。

解密脚本地址：https://github.com/eset/malware-research/blob/master/oceanlotus/macOS\_scripts/OL\_OSX\_decryptor.py 

  

知道了*解密*函数的原型，脚本首先找到对该函数的所有交叉引用，找到所有参数，解密数据并将明文放在交叉引用地址的注释中。为了使脚本正常工作，必须在脚本中设置base64解码函数使用的自定义字母，并且必须定义包含键长度的全局变量

在“ *函数”*窗口中，可以右键单击解密函数，然后单击“提取解密参数”。脚本应该将解密的字符串放在注释中
