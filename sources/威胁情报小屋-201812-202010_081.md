# 新处理器架构编译的mirai

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=Mzg5NDA1OTQxMA==&mid=2247484054&idx=1&sn=c45ec5bc057d5603f5868dfecc0a0341&chksm=c024146bf7539d7d71d85ede6c713a48e5ca65b1ca8418f7f5ffd56bd531d18eda54abf87981&scene=126&sessionid=1681278930#rd](http://mp.weixin.qq.com/s?__biz=Mzg5NDA1OTQxMA==&mid=2247484054&idx=1&sn=c45ec5bc057d5603f5868dfecc0a0341&chksm=c024146bf7539d7d71d85ede6c713a48e5ca65b1ca8418f7f5ffd56bd531d18eda54abf87981&scene=126&sessionid=1681278930#rd)

*1*概述![](../Images/362f877e30f366c19e254721f2765a85.png "大树分割线")

    在2019年2月下旬，unit42发现了为之前未见过的新处理器/架构编译的Mirai样本。尽管源代码已公开发布 2016年10月，但迄今为止，恶意软件仅针对一组固定的处理器/体系结构。

  第42单元发现新发现的样本是为Altera Nios II，OpenRISC，Tensilica Xtensa和Xilinx MicroBlaze处理器编译的。这不是Mirai第一次针对新的处理器架构进行扩展，2018年1月发现了针对ARC CPU的样本。然而，这一发展表明Mirai开发人员继续积极创新，针对越来越多的物联网设备。该恶意软件因其在Dyn和安全博客Brian Krebs的网站上遭受大规模拒绝服务攻击开始闻名。如果最新的创新导致受感染设备的数量增加，这意味着Mirai攻击者可以获得额外的火力用于拒绝服务攻击。

   在本博客中，我们展示了我们在这些新样本中发现的新功能，讨论了我们观察到的基础架构，展示了使用已知漏洞的其他Mirai样本如何与新样本托管在同一基础架构上，并给出了妥协指标（IoC） ）这些新样品。

   为了防范Mirai和其他威胁，组织应优先考虑使用最新更新和非默认密码保护其物联网设备

***2***新的功能![](../Images/362f877e30f366c19e254721f2765a85.png "大树分割线")

除了为这些新架构编译之外，我们还发现这些新样本还包含以下新功能：

    加密算法：这些示例使用原始Mirai源代码中使用的标准字节XOR（在toggle\_obf函数中实现）的修改版本。

   它使用11个8字节密钥，所有这些密钥都按字节顺序进行XOR编辑，以获得最终的结果密钥。

![](../Images/fcd11d0f435405da688393942156a0d0.png)

  

attack\_method\_ovh：示例包含带有以下参数的DDoS攻击选项：

![](../Images/24bfb8c11d276bf1303f4c0a8f18c343.png)

  

    这些参数与原始Mirai源中的攻击方法“TCP SYN”（attack\_method\_tcpsyn）完全相同，因此使用相同参数合并新攻击方法的原因仍不清楚。

    在AutoFocus中采用这种攻击方法，我们发现样本自2018年11月开始在野外流传.

***3***基础设施![](../Images/362f877e30f366c19e254721f2765a85.png "大树分割线")
