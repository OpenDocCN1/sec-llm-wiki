**概述**

* * *

   威胁侦察团队继续收集和分析来自多个APT小组的活动相关数据。我们分析了今年早些时候针对位于韩国，美国和东亚的组织的黑客攻击活动中使用的恶意软件。他们使用压缩恶意软件的CAB文件，单独的配置文件和特定的用户访问控制（UAC）旁路模块。本文简要介绍了他们当时使用的恶意软件的感染方法以及使用的UAC旁路模块

**感染方法**  

* * *

    攻击者使用了相当多的步骤来生成他们的恶意软件，最初的感染来自附加在鱼叉式网络钓鱼电子邮件中的恶意文档。当用户执行附加到电子邮件的文件时，通过文档中包括的脚本下载用于从远程站点下载base64编码的CAB文件的批处理文件

![](../Images/d19b431d1c9a8dd6fd5ba85b0d038ed4.png)

感染链

通过嵌入恶意文档的脚本下载base64编码数据1.txt

解码“1.txt”以创建“1.bat”并运行“1.bat”

“1.bat”根据Windows平台环境（32位/ 64位）下载2.txt（32位）或3.txt（64位）

解码“2.txt”或“3.txt”以创建“setup.cab”

每个文件看起来像使用字符串“ - BEGIN CERTIFICATE - ”的SSL证书，但这实际上是base64编码的cab和bat文件。

![](../Images/a78e893c44c65629de25c7494a835bd0.png)

CAB文件是根据Windows平台环境通过以下文件创建的：

用于主有效负载文件执行的BAT文件

包含攻击者服务器地址的INI文件

用于UAC绕过的DLL文件

主要EXE有效负载

**为什么UAC会运行**

    此恶意软件的第一个批处理文件（1.bat）执行第二个批处理文件，该文件安装主要负载。通常会向用户显示UAC弹出窗口，这是由安装主有效负载的BAT文件中的代码引起的。它将INI配置文件和主有效负载EXE复制到System32文件夹中。

    通常，将文件复制到System32文件夹时，出于安全原因将运行UAC弹出窗口。在正常情况下不应修改此文件夹，因为它包含用于操作系统的重要文件

![](../Images/23b587a270e44216fce6c9fcf5315d33.png)

**BAT文件细节**

* * *

    第一个批处理文件（1.bat）从远程服务器下载文件，并使用“net session> nul”命令验证当前用户权限并执行以下操作：

1.如果是admin：删除UAC绕过DLL，执行主有效负载和BAT文件

2.如果不是admin：使用rundll32.exe   
3.命令执行以下命令：“\[UAC Bypass Module\]，EntryPoint \[主要有效负载执行BAT文件\]”

![](../Images/09639a7cb26b3a6ba32fc65c00a141e0.png)

    用于安装主有效负载的批处理文件将主有效负载可执行文件和INI配置文件复制到System32文件夹中，然后运行移动到System32文件夹的主有效负载。

![](../Images/0039e79db936b167852eadcc41ecf0ac.png)

**怎么运作**

* * *

    当用户登录Windows时，每个用户都会获得一个访问令牌。此访问令牌包含有关安全标识符（SID），Windows操作系统特权以及授予用户的访问级别的信息，Windows系统使用访问令牌来验证用户的权限。登录时生成的访问令牌是：

*   标准用户：生成标准用户访问令牌
    
*   administrator：生成标准用户访问令牌，管理员访问令牌
    

系统根据登录用户的令牌权限分配以下完整性级别。系统通过将对象的安全描述符的访问权限与用户的SID进行比较来执行访问控制。

![](../Images/1bd0160b38c278c17668c2705b75ede0.png)

  

  

    发布的令牌用于创建流程等事件。这里重要的是，在发布令牌后创建进程时，管理员还使用标准用户访问令牌执行新进程。

    通常，作为大多数用户进程的父进程的explorer.exe在中等完整性级别运行，因此大多数进程与explorer.exe运行在同一级别。但是，当进程需要高完整性级别时，如果用户批准，进程可以获得提升的权限。

    这基本上意味着进程通常使用标准用户访问令牌，并在需要管理员访问令牌时使用UAC获取用户的授权。

**UAC旁路**

* * *

    但是，在这种情况下，攻击者使用特定的DLL模块来绕过UAC。它似乎是通过引用名为UAC-TokenMagic.ps1的文件的源代码创建的，该文件在GitHub上是开源的。

    首先，它创建了一个以高完整性级别运行的wusa.exe进程（一个可自动升级的进程）。此过程是Windows Update独立安装程序，它具有auto-elevate属性，因此如果系统UAC弹出设置为“仅当程序/应用程序尝试对我的计算机进行更改时通知我”，则不会弹出UAC。

    创建wusa.exe后，它会复制该令牌并使用复制的令牌通过CreateProcessWithLogonW运行cmd.exe进程。最后，cmd.exe以高完整性级别运行并执行“/ c EntryPoint”％Temp％\\ \[bat file install main payload\]“，此批处理文件继承cmd.exe的提升权限。

![](../Images/20ff89fc1b52ff902673990c4c753978.png)

    如果攻击者正在使用UAC旁路模块，则运行主有效负载的批处理文件将通过从wusa.exe复制访问令牌生成的cmd.exe工作。总之，即使执行将文件移动到批处理文件中的System32文件夹的代码，UAC也不会弹出。

**总结**

* * *

    攻击者使用其他组件压缩UAC旁路模块，并以CAB文件格式分发它们。我们已经看到这个威胁演员组主要使用用俄语，英语和韩语编写的诱饵文档，并使用BABYFACE，SYSCON恶意软件变体作为主要有效载荷。这种活动可能部分与先前已知的威胁行动者团体的活动有关。我们的威胁侦察团队将继续监控这些网络威胁。
