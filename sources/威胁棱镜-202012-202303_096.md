# 使用 PassiveDNS 发现 SUNBURST 的受害者

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzkyMzE5ODExNQ==&mid=2247483730&idx=1&sn=5e16ad7d6db443b3234af511308914cc&chksm=c1e9f69ef69e7f88179c177caf932af3412ff22d780ccb91b5e3787016a9b08e8c93fdc4071e&scene=126&sessionid=1681278728#rd](http://mp.weixin.qq.com/s?__biz=MzkyMzE5ODExNQ==&mid=2247483730&idx=1&sn=5e16ad7d6db443b3234af511308914cc&chksm=c1e9f69ef69e7f88179c177caf932af3412ff22d780ccb91b5e3787016a9b08e8c93fdc4071e&scene=126&sessionid=1681278728#rd)

受害者在安装了包含 SUBURST 后门的 SolarWinds Orion 更新后，将向 avsvmcloud.com 发送看似是随机子域名的 DNS 请求。这些 DNS 请求中实际上包含着被编码到子域名中的受害者的内部活动目录域，因此 NETRESEC 开发了 SunburstDomainDecoder 工具用于从 PassiveDNS 数据中识别受害者。

**SUNBURST 后门的三个阶段**

幸运的是，大多数 SUNBURST 的受害者并未真正受到攻击者的攻击。这意味着绝大多数人永远不会越过感染过程中的第一阶段。尽管如此，攻击者的确选择了一些受害者进行了第二阶段的攻击。如 FireEye 的博客文章中所述：C2 coordinator 可以**通过响应返回 DNS A 记录来引导受害者进入下一个阶段**，该 A 记录指向以下三个 IP 段中的任意 IP 地址：

*   18.130.0.0/16
    
*   99.79.0.0/16
    
*   184.72.0.0/15
    

进入第二阶段的 SUNBURST 将通过响应返回 DNS CNAME 记录用作新的 C&C 域名。

![](../Images/9e6d835e98141e8eb3684c76b904ca59.png)

SUNBURST 后门使用了请求的 avsvmcloud.com 的子域名中的单个比特来标记是否进入第二阶段接受 CNAME 记录中的新 C&C 域名。在 SUNBURST 的 Implant 中，该比特被称为 flag、ext 或dnssec，可以从编码了时间戳的 DNS 查询（例如表明已安装哪些安全产品的 DNS 查询）中提取。

**检测第二阶段的 DNS 请求**SunburstDomainDecoder 工具现已更新，可以为第二阶段的 DNS 请求标记 STAGE2。**这意味着国家级的 CERT 可以使用 SunburstDomainDecoder 进行事件响应处理并协调通知进入第二阶段的受害者**。
