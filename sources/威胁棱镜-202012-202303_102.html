Cobalt Strike 现在似乎已经成为全球使用最为广泛的恶意软件，从 APT41 到 APT32，甚至是业界震动的 SolarWinds 供应链攻击也使用了 Cobalt Strike。本文旨在简要介绍如何对其进行快速识别和进一步分析。



寻找 Cobalt Strike 的服务器


几个月前，Salesforce 安全团队发布了一个名为 JARM 的工具指纹，其等效于此前发布的 JA3。基于远程服务器的 TLS 配置（例如 TLS 版本或 TLS 扩展等配置信息）生成对应的 JARM 指纹。该指纹识别某些工具使用的自定义 Web 服务器特别有用，Cobalt Strike 就是其中之一。


使用该工具计算Cobalt Strike 的 JARM 指纹为：07d14d16d21d21d07c42d41d00041d24a458a375eef0c576d23a7bab9a9fb1。


最近，JARM 指纹已经被全球诸多主动探测平台纳入跟踪范围，例如 Shodan、BinaryEdge 和 SecurityTrails。Shodan 专门为此建立了检索符 ssl.jarm 方便用户快速寻找相关应用。


以 Shodan 搜索引擎为例（ssl.jarm:07d14d16d21d21d07c42d41d00041d24a458a375eef0c576d23a7bab9a9fb1）进行检索：




Shodan 通过该 JARM 指纹发现了 5623 个 IP 地址上部署了 Cobalt Strike，主要分布在 Amazon 和 Digital Ocean 上。


再进一步，保留 443 端口还有 3423 个 IP 地址。使用第一个 IP 地址的 443 端口可以计算 JARM 指纹进行验证：


$ python jarm.py 78.152.61.71Domain: 78.152.61.71Resolved IP: 78.152.61.71JARM: 07d14d16d21d21d07c42d41d00041d24a458a375eef0c576d23a7bab9a9fb1


实际上，该 JARM 指纹是运行在 Java 11 上的 Java Web 服务器的签名。所以，除 Cobalt Strike 外，还有 Burp Suite。值得注意的是，不使用 Java 11 的 Cobalt Strike 的 JARM 指纹也与之不同。Cobalt Strike 还专门写了一篇关于这个的文章。


寻找 Cobalt Strike 的 Beacon


Cobalt Strike 使用 checksum8 算法校验 URL 来决定下载 32 位或 64 位版本的 Beacon。Cobalt Strike 的反编译代码已经在 GitHub 上发布了，也从代码层面提供了佐证：


public static long checksum8(String text) {    if (text.length() < 4) {        return 0L;    }    text = text.replace("/", "");    long sum = 0L;    for (int x = 0; x < text.length(); x++) {        sum += text.charAt(x);    }
    return sum % 256L;}
public static boolean isStager(String uri) {    return (checksum8(uri) == 92L);}
public static boolean isStagerX64(String uri) {    return (checksum8(uri) == 93L && uri.matches("/[A-Za-z0-9]{4}"));}


可以通过暴力破解的方式找到匹配的地址：


from itertools import productimport string
def checksum8(strr):    j = 0    if len(strr) < 4:        return 0    strr = strr.replace("/", "")    for c in strr:        j += ord(c)    return j % 256
chars = string.ascii_letters + string.digitsto_attempt = product(chars, repeat=4)for attempt in to_attempt:    word = ''.join(attempt)    r = checksum8(word)    if r == 92:        print("{:30} - 32b checksum".format(word))    elif r == 93:        print("{:30} - 64b checksum".format(word))

解密 Cobalt Strike 的 Beacon


我们拿到的文件其实并不是 PE 文件：


$ file *aaa9:     dataaab9:     data


下载 Beacon 后会在内存中执行，所以文件并不是完整的 PE 文件。而是在开头包含 Shellcode，该 Shellcode 会解密 Beacon 并执行。


通过 miasm 分析 Shellcode 可见：



第一个 jmp 指令在加密密钥和加密 Beacon 之前跳到 call。跳到 Shellcode 的下一个指令 POP EDX 可得到密钥的地址，loc_f 处的代码可以获取 EBX 中存储的密钥、EAX 中存储的 Payload 的长度和存储在栈中的 Beacon 地址。循环 loc_1d 处进入 Beacon，然后使用密钥进行异或。


在 Python 中可以很容易的复现，难点在于找到基址。loc_47 紧挨着密钥、长度和加密的 Payload 的地址。因此，基址是 0x47+5（call 指令的长度）。基址会随着 Payload 的变化而变化，但是可以通过搜索最后一个 call 指令找到它。


import struct
def xor(a, b):    return bytearray([a[0]^b[0], a[1]^b[1], a[2]^b[2], a[3]^b[3]])
with open("aaa9", "rb") as f:    data = f.read()
ba = 0x4ckey = data[ba:ba+4]print("Key : {}".format(key))size = struct.unpack("I", xor(key, data[ba+4:ba+8]))[0]print("Size : {}".format(size))
res = bytearray()i = ba+8while i < (len(data) - ba - 8):    d = data[i:i+4]    res += xor(d, key)    key = d    i += 4
with open("a.out", "wb+") as f:    f.write(res)


据此，最终得到了该攻击基础设施上最终所部署使用的PE 文件（3c9a06b2477694919b1c77d3288984cb793a47dd328ef39e15132cd0cfb593ab）。


最后的 call 指令会直接执行该 PE 文件，此时已经是一个有效的 PE 文件（Cobalt Strike 称其为 stageless payload）。已经可以发现 PE 文件的 MZ 标识了：



该文件修改过 DOS 头，使其包含跳到二进制文件 0x8157 地址的有效指令。该地址是导出函数 _ReflectiveLoader@4 的地址，该函数基于 RefelctiveDLLInection 实现，在调用入口点之前加载和映射导入函数。


请注意，在 Cobalt Strike 中这是可选项，许多 Cobalt Strike 的 Payload 都不是 PE 格式的，而是类似于 Shellcode 格式的 Payload。


提取配置信息


Cobalt Strike 的配置信息在 Payload 中进行了加密，并根据 Cobalt Strike 版本的不同使用不同的密钥（0x23 或 0x69）。解密后，配置以 TLV 格式存储：


  • 数据的密钥列表（Cobalt Strike 的源码可见）

  • 两个两个短字节代表数据类型（Int，Short，String 等）及其长度

  • 数据本身


要找到配置信息的起始地址，可以查找第一个密钥的编码值，即 1（DNS/SSL）、1（Short）、2（2 个字节），经过密钥 0x69 编码为 ihihik 或者使用密钥 0x23 编码为 ././.,。

许多样本中都能提取到相同的配置信息，因为使用了 Cobalt Strike 的 Malleable C2。这些配置文件实际上是 Cobalt Strike 的 Beacon 配置，可以通过配置文件进行共享。例如，海莲花（APT 32）仿造 Google Safebrowsing URL 的公共配置文件。也有在 GitHub 整理好的不同 APT/犯罪组织使用的配置文件。


配置中值得注意的是 watermark，这是从许可证文件生成的数字，是许可客户端独有的，可以通过该数字将 Cobalt Strike 和配置关联起来。因此，许多 Cobalt Strike 的破解版都禁用了 watermark，防止 Cobalt Strike 标识出是哪个付费用户提供了破解来源。
