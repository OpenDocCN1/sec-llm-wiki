    为什么会出现这个问题呢？  
    再次翻找/root/seal\_market资产库里nginx的配置文件时，发现了这样一个配置：

![](../Images/334053cf5fc75cbbb1fd276888bcc40a.png)

    依着不懂就百度或者google的原则，查找到了服务器是进行了双向的证书验证。这个配置，不仅客户端会校验证书，服务器同样会校验证书，当证书不正确时，访问特定的页面就会返回403。  
    解决证书验证的问题可以参考这个链接：  
https://blog.csdn.net/weixin\_26740495/article/details/108958573  
    大概的解决方法是，在浏览器中导入服务器启用的pkcs12格式自签名证书。  
![](../Images/565bd5702f400c62afedeb5fd7588d5a.png)

    但是再次查看资产库时，并没有找到这个证书，因此我们只能使用其他方法来绕过这个限制。

    首先，我们先访问/manager/status这个页面来查看管理控制台的状态信息，并且验证之前获得的凭证是否可以访问管理控制台：

![](../Images/3b346f6b24720daad26812a598005f2a.png)

    截图中表明是可以的。  
    既然我们可以访问/manager/status,那么我们是不是也可以以另一种方式访问/manager/status呢？-/manager/html/../status  
    答案是肯定的  
    因此我们可以使用目录遍历来绕过nginx的双向证书验证检查。

    不过，单纯的使用../目录遍历符是绕不过nginx检查的，不管是直接在浏览器中输入还是在Burp中输入，效果是一样的。我们还需要增加‘；’来绕过检查，最终访问的uri为：

/manager/status/..;/html:

![](../Images/073c5d6e5e02afb10ad2c799223a6ff5.png)

    最后再进行root权限的提升。

    在使用sudo -l命令查看目标用户的sudo权限时，发现了luis这个用户使用sudo /usr/bin/ansible-playbook命令不用输入密码：

![](../Images/2a1f8b43bcdb56b000168d0c2afa8799.png)

    我们先来看看什么是playbook：

![](../Images/c55b69c3b6204797fdc0739b3e597198.png)

    介绍言简意赅，与shell类似，playbook可以执行预先编辑在yaml文件中的一系列命令。因此，我们可以创建一个yaml文件，然后使用/usr/bin/ansible-playbook命令来执行该文件。

模仿run.yaml文件中复制文件的操作，我们来将/root/root.txt这个文件复制/dev/shm这个目录下，并且指定属主和属组。

| \- name: Ansible Copy Example Local to Remote  hosts: localhost  tasks:    \- name: copying file with playbook      become: true      copy:        src: /root/root.txt        dest: /dev/shm        owner: luis        group: luis               mode: 0777 |
| --- |
