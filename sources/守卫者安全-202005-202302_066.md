# Linux内核本地提权漏洞(CVE-2019-13272)

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzIwMDcyNzM0Mw==&mid=2247484300&idx=1&sn=23e3a5dd41a82f4d0cfe3a7c559563d0&chksm=96f98dcca18e04da30600d356093cb68f7827fded255b82b1f99e0ddd8995a613959be3773d1&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzIwMDcyNzM0Mw==&mid=2247484300&idx=1&sn=23e3a5dd41a82f4d0cfe3a7c559563d0&chksm=96f98dcca18e04da30600d356093cb68f7827fded255b82b1f99e0ddd8995a613959be3773d1&scene=27#wechat_redirect)

### 一、漏洞描述

kernel 5.1.17之前的版本中存在安全漏洞，该漏洞源于kernel/ptrace.c文件的ptrace\_link没有正确处理对凭证的记录。　

当调用PTRACE\_TRACEME时，ptrace\_link函数将获得对父进程凭据的RCU引用，然后将该指针指向get\_cred函数。但是，对象struct cred的生存周期规则不允许无条件地将RCU引用转换为稳定引用。　　　　　

PTRACE\_TRACEME获取父进程的凭证，使其能够像父进程一样执行父进程能够执行的各种操作。如果恶意低权限子进程使用PTRACE\_TRACEME并且该子进程的父进程具有高权限，该子进程可获取其父进程的控制权并且使用其父进程的权限调用execve函数创建一个新的高权限进程。

总体来说这个漏洞的利用限制还是很大的，首先要找到一个内部有减权的suid程序,pkexec是linux桌面freedestop上的验证程序，非桌面版本就可能没有这个东西。也就是说想要利用这个来提权只能是**需要目标服务器有桌面环境**，所以这是一个很鸡肋的漏洞。

并且在通过ssh连接靶机想要提权的时候，发现提权失败。这是因为通过ssh登录时执行提权脚本是没有桌面环境的。因此就更加印证了这个漏洞是存在的，但是想要利用怕是想得太多了。
