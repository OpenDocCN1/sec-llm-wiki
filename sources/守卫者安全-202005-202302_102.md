# CPN Tools——简单传输协议建模

       本文将通过使用CPN Tools工具来实现一个简单的传输协议的建模。该协议的作用是通过一个发送器（sender），传输若干的数据包（data packets）到一个接收器（receiver）。通信发生在一个不可靠的网络，即数据包可能会丢失而且超越也是可能的。协议利用序列号、确认和重传技术以确保数据包被准确传输，保证没有重复传输，而且在传输结束后数据包的顺序是正确的。被传输的数据包中包括一个序列号及数据（有效载荷）。确认中包括一个序列号，用于指明接收器期望接收的下一个数据包的编号。

       一个CPN模型通常是像绘制图形一样被创建出来的，下图展示了简单传输协议的基本CPN模型。

![](../Images/f89050f0eb4ab2dc7ab20141b26e12f6.png)

       左面的部分为发送器建模，中间部分为网络建模，右边的部分为接收器建模。该CPN模型中包含了8个库所（places）（形状像圆一样），5个变迁（transitions）（形状像矩形一样），还有一些直接连通库所和变迁的有向弧（arcs），最后是一些靠近库所、变迁、有向弧的标注（inscriptions）。这些标注在CPN ML编程语言中有记录，它是Standard ML语言的扩展。库所和变迁被统称为节点（nodes），通过有向弧的连接，他们就构成了一个网结构（net structure）。

       一个弧总是把一个库所连接到一个变迁或把一个变迁连接到一个库所。在两个同类的节点间是不允许有弧的，即在两个库所间或两个变迁间都不允许有弧。

       下面结合模型来详细说明如何构建简单传输协议模型（下文统称为Simple protocol）。

       建模系统的状态是由库所表示的。每个库所都可以被一个或一个以上的令牌（tokens）标识，而且每个令牌自身都附有一个数据值，这个数据值是所谓的令牌颜色（token colour）。在每一个单独的库所中的令牌数量和令牌颜色合起来，就构成了系统的状态（marking）。在一个特定库所上的令牌数构成了那个库所的状态。

       按照惯例，我们在椭圆形内写下库所的名字。这些名字本身没有规范的意义-但他们对CPN模型的可读性具有重要实际意义。发送器（Sender）的状态是由两个库所packets to tend和next send 确定的。接收器（Receiver）的状态是由两个库所data received和next rec确定的，而网络的状态则是由库所A、B、C和D确定的。

       在每一个库所附近，都有一个标注决定了此库所的令牌允许使用的令牌颜色集（数据值）。一个令牌颜色集是由一个类型（如已知的编程语言的类型）指定的，它被称为库所的颜色集。按照惯例，颜色集是写在库所下面的。从图中可以看到库所next send，next rec，C和D都有颜色集NO。在CPN Tools中，颜色集是使用CPN ML关键字colset定义的，并且这里的颜色集NO是用来表示序列号的，所以应该被定义成整数类型：

colset NO = int;

![](../Images/fe272d42155770d48e69a4adf5cda473.png)

       这意味着四个库所next send、next rec、C和D将有一个整数作为他们的令牌颜色。颜色集NO被用来建模协议中的序列号。在工具中，整数类型的大小，取决于编写这种工具的编程语言。例如，在CPN Tools中int 类型是31位整数。

       库所data received 的颜色集 DATA 被定义为包含所有的文本内容的字符串类型。因为颜色集DATA是用来为数据包的有效载荷建模的。其余的3个库所的颜色集NOxDATA，它则是定义为NO 的类型和DATA的积。该类型包含所有第一个要素是一个整数而且第二个要素是一个字符串的两元组。元组是用逗号分割不同元素并加上括号来区分的。颜色集NOxDATA是用来为传输过程中的数据包建模的，这些数据包包括序序号和具体的数据。颜色集的定义如下：

colset DATA = string;

colset NOXDATA = product NO \* DATA;

![](../Images/8ba2d644106e341df7170c6176e3e09f.png)

       每一个库所旁边，我们可以看到还有另一个标注，该标注决定了这个库所的初始状态（initial marking）。最初的原始库所的状态，按照惯例都是写在库所的上面的。举例来说，在库所next send右上方的标注标明库所的原始状态是由一个带有颜色（值）1的1个令牌构成的。这表明，我们希望序列号为1的数据包作为第一个被传送的数据包。类似地，库所next rec也有一个初始的状态，它包括一个带有颜色1的单一令牌。这表明接收器最开始期望接受序列号为1 的数据包。库所data received 有一个初始的状态，这个状态包括一个带有颜色""（这是空的文本串）的令牌。这标志着该接收器目前还没有接受到任何数据。在库所packets to send 左上方的Allpackets标注是一个常量，定义为：

 val AllPackets = 1\`(1,"aaa") ++ 1\`(2,"bbb") ++

1\`(3,"ccc") ++ 1\`(4,"ddd") ++

1\`(5,"eee") ++ 1\`(6,"fff");

![](../Images/8e0a08f570c5a126976cbf53d63a1fd2.png)

这里需要说明一下，这个库所的初始状态有以下数据值的令牌：

(1,"aaa")，(2,"bbb")，(3,"ccc")，(4,"ddd")，(5,"eee")，(6,"fff")。

       上面的++与\` 运算符，允许构成包括令牌颜色的多态集。多态集类似于集合，只不过值可以出现不止一次。该中缀运算符\`左边要求是一个正整数以指明右边的参数提供的元素出现的次数。++符号需要两个多态集作为参数，并且返回他们的并集。Packets to send的最初状态有6个令牌，代表我们希望传送的数据包的内容。没有标注指明的初始状态就意味着库所最初是没有令牌的。库所A，B，C，D就是这种情况。

       每一个库所的当前状态（current marking）都紧靠库所。在当前状态中库所上令牌的数量都在小圆圈中显示出来了。初始状态在packets to send上有6个令牌，而且在库所next send、next rec和 data received上均有一个令牌。

       创建好库所以及库所上的颜色集之后就该说到变迁了。变迁代表可以在系统中发生的事件。如库所一样，我们在矩形里写下变迁的名字。变迁的名字也没有规范的含义，但他们对该模型的可读性都非常重要。当一个变迁发生（occurs）时，它从其输入库所（input places）（那些指向变迁的弧连接的库所）中去除令牌，而且它向其输出库所（output places）（那些由变迁指向的库所）中增加令牌。当变迁发生时从输入库所移走，到输出库所增加的令牌的颜色值由弧表达式（arc expressions）决定。这些弧表达式就是在单个弧上的文本标注。如下图中箭头指向所示

![](../Images/89be9d45e7551a7534ee9ac9badc30a1.png)

       弧表达式可以在CPN ML编程语言里写出，并通过确定类型的变量、常量、运算符和函数构建。当在一个表达式中的所有变量可以给定值时（正确类型的），表达式的值是可以计算出来的。一个弧表达式可以由一个令牌颜色的多态集赋值。作为一个例子，考虑连接在变迁send packet 上的3个弧上的2个弧表达式:n和(n,d)。他们包含的变量n和d的声明如下（变迁上不能直接传输令牌，只能传输代替令牌的变量）：

var n : NO;

var d : DATA; 

![](../Images/fc850c74ebc2252a7099f000ae25eea4.png)

   

       这意味着n必须捆绑到一个NO类型的值上（即一个整数），而d必须绑定到DATA类型的值上（即一个字符串）。例如，我们考虑绑定：

<n=3, d="ccc">

       把n赋值为3，d赋值为"ccc"。这样把弧表达式赋成下面的数值，这里"→"应该被理解为“值为”：

n → 1\`3

(n,d) → 1\`(3,"ccc")

       弧表达式赋值为令牌颜色的多态集，这意味着有可能没有或者只有一个或者一个以上的令牌被从输入库所中删除或是被添加到一个输出库所里。如果一个弧表达式值为一个令牌，那么这个1\`，通常来说可以从表达式中略去。举例来说，弧表达式n和(n,d)就是1\`n 和1\`(n,d)的简记形式。 

       前期工作铺垫好之后接着梳理一下协议的传输过程。现在我们考虑一下变迁send packet。当这个变迁发生时，它可以从每一个输入库所next send和packets to send中去掉一个令牌。这两个弧的弧表达式分别是n和(n,d)。

       库所next send最初的状态包含一个单独的令牌与颜色1 。这意味着该变量n必须绑定为1 。否则，来自next send的弧上的表达式将得到一个不出现在next send中的令牌颜色，这意味着变迁对于那个绑定来说是不可以的。现在让我们考虑来自packets to send的弧表达式(n,d)。我们已将n绑定为1 ，现在看一下d的绑定，使得弧表达式(n,d)绑定为这6个令牌颜色中的一个，并且这个令牌颜色出现在packets to send上。很明显，唯一的可能是把d赋值为字符串"aaa"。因此，我们推测绑定：

<n=1, d="aaa">是SendPacket唯一的使能绑定（在初始状态）。

![](../Images/9b0121bf953470cec82db1a846a92e7b.png)

       带有这个绑定的send packet的发生将从输入库所next send中删除颜色为1的令牌，并且从输入库所packets to send 中删除带有颜色(1,"aaa")的令牌。因为send packet是通过双向弧与packets to send和next send连接的，带有这些绑定的send packet的发生也将添加一个颜色为(1,"aaa")的令牌到packets to send中，同时增添一个颜色为1的令牌到next send 中。这意味着根据弧表达式的结果，从库所packets to send 和next send中删除的令牌数，立即就被新增的同样颜色的令牌数代替了。因此当变迁发生时，这些库所的状态并没有改变。这就允许数据包被重新发送（从数据丢失中恢复）。Send packet的发生也给输出库所A 增加了一个新的颜色为(1,"aaa")的令牌。直观来看，这代表了第一个数据包(1,"aaa" )，已经被送往网络。

       由于前文说了传输是在一个不稳定的网络上，所以存在数据包丢失的可能。因此在transmit packet和B库所之间的弧上的表达式就是用来判断数据包是否传输成功的。实现判断功能肯定就要设计到true和false两个可能。这里的success就被定义成了一个可以布尔类型的变量。变量success的声明为：var success : BOOL;

CPN Tools本身就定义了颜色集BOOL为布尔值的集合({true, false})。

       此时库所A 有一个颜色为(1,"aaa")的令牌。变量success仅在transmit packet 的输出弧上找到。这意味着变量可以被赋值为一个它的颜色集（这是BOOL类型的）中的任意值。因为来自A的输入弧的弧表达式为(n,d)，可以直接推论出变迁transmit packet存在两种不同绑定使能

bsucc = <n=1, d="aaa", success=true>

bfail = <n=1, d="aaa", success=false>

  

这些绑定中第一个bsucc,代表数据包在网络上传递成功。这时将会出现： 

1、数据包(1,"aaa")被从输入库所A中去掉

2、一个代表相同数据包的新的令牌被添加到输出库所 B中（在if-then-else表达式中，条件success的值为true，此时1\`(n,d)的值为1\`(1,"aaa"))。

![](../Images/67e94fbba07e2016ab4e6c8cc1d8b4bc.png)

第二个绑定bfail代表一个不成功的传递，即该数据包在网络中丢失了。如果它发生的话将出现以下情况：

1、数据包(1,"aaa")被从输入库所A中删除。

2、没有令牌被添加到输出库所B中（在if-then-else表达式中，条件success的值为false，前面定义的常量empty 的值为 empty 多态集）。

传输失败之后系统又回到了初始状态开始重新传输数据包(1,"aaa")。

       现在，我们考虑传输成功之后数据包的接收问题。在库所next rec上的令牌，代表接收器期待收到的下一个数据包的序列号。变量k赋值为这个序列号的数值。变量data声明为DATA数据类型（即文本串）：var data : DATA;

变量data将被赋值为文本串，这个文本串代表所有已经被接收器接收到的数据包中数据的拼接。 

      当一个数据包出现在了库所 B中时 ，那接下来就有两种不同的可能性。要么n=k的值为true，这意味着被收到的数据包就是接收器期望接收的那个；要么n = k的值为false，这意味着它不是预期的数据包。如果在库所B上的数据包是预期的数据包（即n = k），就有下列情况发生：

1、数据包被从库所B中删除

2、数据包中的数据，拼接到接收器已接收到的数据最末端（运算符 ˆ 是文本串的拼接运算符）。 

3、库所next rec上的令牌颜色将从k变为k+1，这意味着接收器正在等待接收下一个数据包。 

       接收端在等待接收下一个数据包，可是发送端又不知道发送的数据是否被成功接收，也不知道接下来应该发送哪一个编号的数据包。这个时候就需要由接收端发送一个确认编号来通知发送端接下来应该发送哪一个数据包。在库所C中会有一个确认。该确认包括接收器期待接收的下一个数据包的序列号。

![](../Images/b7e848f5012a75cddd7ce064a2d56092.png)

另一种情况是如果在B上的数据包不是预期接收的数据包（即n≠k）有下列情况发生：   

1、数据包被从库所B中删除。

2、数据包中的数据被忽略（data received的状态没有改变） 。 

3、在库所next rec上的令牌颜色没有改变，这意味着接收器等待接收当前期待的数据包。 

4、在库所C中会有一个确认。该确认包括接收器期待接收的下一个数据包的序列号。

  

       最后就是发送端接收确认的过程了。变迁transmit ack有一个行为类似于transmit packet，也是用来判断确认好在网络上是否成功传输。在成功传递的情况下，它会消除库所C中的确认令牌，而且把他们增加到库所 D中。

![](../Images/e62d791d7c7c14f8fd5dd4cd31c1c513.png)

       现在，我们考虑一下确认的接收。当变迁receive ack发生时，从库所 D中删除了一个确认而且更新next send上的令牌来包含在确认中指定的序列号。

![](../Images/e8444c3183cabeb359b424e2dbb01c59.png)
