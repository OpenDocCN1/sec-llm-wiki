Bugshop的核心架构



什么是bugshop,bugshop是监控整个h1项目资产的工具,与其说它是一个工具,倒不如说它是一个架构。这里我简单的介绍一下它是由什么部件组成的。

它是由:docker,Kubernetes,argo组成。这些部件的用法和原理,我会在以后的文章中提到,这里我就说一下这三个部件在bugshop的作用吧:为了让更好的理解我会把bugshop比喻成为公司。


Docker,它是一个容器,配置了工具所需要的环境,并且可以一次配置多次使用的功能,如果在公司中你可以想象他是一个员工,负责干活的。

Kubernetes,它是编排,部署,管理容器的一个平台,在可以让容器变得自动化起来,比如调度,自动修复,水平伸缩等等。在bugshop中属于核心框架的存在,如果在公司中它就是项目的流水线。

Argo,它的作用是运行和管理Kubernetes上的作业很应用程序的,它的出现赋予了Kubernetes的一个工作弹性,可以整个架构变的灵活和自动化。它可以实现一键部署整个框架和项目,让Kubernetes实现真正的自动化。如果在公司中它就是项目的策划和工序。

Azure-brute-perf.yml


定义了三个参数分别指定了不同的值

arguments

  parameters:    - name: domains-list-url      value:    - name: words-wordlist-url      value: "https://raw.githubusercontent.com/infosec-au/altdns/master/words.txt"    - name: resolvers-list-url      value: "https://raw.githubusercontent.com/blechschmidt/massdns/master/lists/resolvers.txt"

domains-list-url的值为空,因为这个是目标站点的任务队列。在后面会说明原因

创建了5个模板分别如下:

entrypoint,massdns,parse-massdns,get-buckets-wfuzz,get-listable-buckets-wfuzz

下面创建了步骤工作流,顺序如下:

Massdns -> parse-massdns -> get-buckets-wfuzz -> get-listable-buckets-wfuzz


parse-massdns,get-buckets-wfuzz,get-listable-buckets-wfuzz,输出绑定到results工件中。


模板分析

  • Massdns模板是第一个运行,模板里面有两个参数分别是domains和resolvers。

  • domains是把domains-list-url下载到/tmp/domains.txt ,domains-list-url指向的是任务队列

  • resolvers是把resolvers-list-url下载到/tmp/resolvers.txt上面可以看到resolvers-list-url的值是指向一个地址的。

  • Massdns 导入的镜像是s14ve/massdns:1.0并且定义了容器的以下运行的参数

args: ["-r","/tmp/resolvers.txt","--verify-ip","-t","CNAME","-o","S","-w","/tmp/raw_massdns.out","/tmp/domains.txt",]

定义了输出文件和文件的路径,path: /tmp/raw_massdns.out,name是results上面可以看到parse-massdns,get-buckets-wfuzz,get-listable-buckets-wfuzz,输出绑定到results工件中,所以它们的输出文件都是raw_massdns.out。


parse-massdns



把parse-massdns的输入到/tmp/raw_massdns.out。模板导入的镜像是alpine:3.9,并且运行以下命令

"sed '/CNAME/!d' /tmp/raw_massdns.out | cut -d ' ' -f1 | sed 's/.$//' > /tmp/accounts.txt"

,输出参数名是results,路径是/tmp/accounts.txt。


get-buckets-wfuzz



这个模板并行了不同的内容,内容如下:

words参数把words-wordlist-url下载到/tmp/words.txt文件里面,输入参数名是words,路径是/tmp/accounts.txt文件中,容器的镜像为brokenscripts/wfuzz容器的运行命令是

"-w /tmp/accounts.txt -w /tmp/words.txt -oF /tmp/readable-buckets.txt --sh 213 -Z 'https://FUZZ/FUZ2Z/test'"

输出参数名是results,路径是/tmp/readable-buckets.txt。


输入参数名是input路径是/tmp/readable-buckets.txt,容器的镜像为brokenscripts/wfuzz容器的运行命令是

"-w /tmp/readable-buckets.txt  -oF /tmp/listable-buckets.txt --hh 221 -Z 'FUZZ/?restype=container&comp=list'"

输出参数是results,路径是/tmp/listable-buckets.txt

这里要注意的是这两个步骤都是并行的

Buckets

Altdnsgen,generatedomainfile,parsealtdns,second-altdns,parse-s3-input,s3-massdns,parse-s3-massdns,bucketsperm-aws,bucketsperm-other-providers,push-results,

这些定义名都是并行运行的,下面讲解每一个模板运行的流程。


parsealtdns

second-altdns



导入模板second-altdns依赖parsealtdns和 generatedomainfile。参数名input将parsealtdns输出绑定results,参数名domainfile将generatedomainfile输出绑定到results

subdomain.yml


模板如下:

subdomainenum,amass,subfinder,prepare-wordlist,massdns,parsemassdns,altdns,merge-and-resolve,final-merge-and-resolve,push-results,exit-handler


amass:输入参数绑定wordlists,路径是/wordlists/resolvers.txt,输出参数results,路径是/tmp/amass.txt,最多dns查询50000

subfinder:输入参数绑定config,路径是/wordlists/resolvers.txt,输出参数results:路径是/tmp/subfinder.txt,

prepare-wordlist输入参数绑定wordlists路径是: /wordlists/subdomains.txt,输出参数绑定到results,路径是/tmp/massdns_input.txt,运行命令

sed -e 's/$/.{{workflow.parameters.domain}}/' /wordlists/subdomains.txt > /tmp/massdns_input.txt

parsemassdns:输入参数绑定input,路径是/tmp/raw_massdns.out ,输出参数绑定results路径为/tmp/massdns.txt,运行命令

cut -d ' ' -f1 /tmp/raw_massdns.out | sed 's/.$//' > /tmp/massdns.txt

altdns:输入参数绑定有两个参数 input,路径是/tmp/domains.txt和wordlists路径是/wordlists/words.txt,输出绑定results路径是/tmp/altdns.txt

push-results:建立输出结果

cd /targetdatagit pullmkdir "/targetdata/{{workflow.parameters.domain}}"cp /tmp/resolvable.txt "/targetdata/{{workflow.parameters.domain}}/resolvable.txt"cp /tmp/subdomains.txt "/targetdata/{{workflow.parameters.domain}}/subdomains.txt"

已经看完了其他的参数了,可以看subdomainenum了,这个模板写了整个subdomain.yml的步骤,图下是整个步骤的思维导图

步骤是从左到右的,在分叉的地方的子主题步骤都是并行的。

剩下的两个文件都是输出结果的处理

Subtakeover.yml

cut -d ',' -f1-4 /tmp/tko-subs.out | grep 'true' | cut -d ',' -f1-3 > /tmp/tko-subs.csv

总结


已经读完了bugshop的整个流程代码,这里可以宏观的了解bugshop是如何工作的,在workflows的工作流程文件夹里面分别有5个yml文件,上面已经详细分析了每一个文件,那么我来总结一下这些文件的具体功能吧:

  • azure-brute-perf.yml:配置s3桶的运行环境,

  • buckets.yml: 处理并调取整个框架

  • subdomains.yml: 扫描目标域名的实现

  • subtakeover.yml: 处理扫描后的结果,并整理成表格

  • gitsecrets.yml: 将输出结果写入到gitlab的储存库中


bugshop已经给创造人获得了7个漏洞的成就并且获取了几千刀的奖励。
