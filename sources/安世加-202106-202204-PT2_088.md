 **执行摘要**

*   Mandiant最近应对了多起涉及Pulse Secure VPN设备被破坏的安全事件。
    
*   这篇博文研究了多种相关技术，用于绕过Pulse Secure VPN设备上的单因素和多因素认证，在升级中持续存在，并通过Webshells维持访问。
    
*   Pulse Secure的调查确定，先前的漏洞和2021年4月发现的一个先前未知的漏洞CVE-2021-22893的组合，是最初感染载体的原因。
    
*   Pulse Secure的母公司Ivanti发布了与这些恶意软件家族有关的一个被利用的漏洞的缓解措施，以及Pulse Connect安全完整性工具，供其客户确定其系统是否受到影响。解决该漏洞的最终补丁将在2021年5月初推出。
    
*   Pulse Secure一直在与Mandiant、受影响的客户、政府合作伙伴和其他取证专家密切合作，以解决这些问题。
    
*   没有迹象表明，所发现的后门是通过对公司的网络或软件部署过程的供应链入侵而引入的。
    

**简介**

  

Mandiant目前正在追踪与利用Pulse Secure VPN设备有关的12个恶意软件家族。这些系列与规避认证和后门访问这些设备有关，但它们之间没有必然的联系，并在不同的调查中被观察到。可能有多个行为者负责创建和部署这些不同的代码系列。

本报告的重点是UNC2630针对美国国防工业基地（Defense Industrial Base）网络的活动，但在技术附件中提供了在美国和欧洲受害者组织观察到的所有样本的详细恶意软件分析和检测方法，以协助网络防御者识别受影响设备上的大量恶意活动。目前正在进行分析，以确定活动的范围。

Mandiant继续与Ivanti和Pulse Secure团队、微软威胁情报中心（MSTIC）以及相关政府和执法机构合作，调查这一威胁，并为受影响的Pulse Secure VPN设备所有者制定建议和缓解措施。

作为调查的一部分，Ivanti已经发布了与此活动有关的漏洞的缓解措施，以及Pulse Connect Secure Integrity Tool，以协助确定系统是否受到影响。

**Details 详细内容**

今年年初，Mandiant调查了世界各地的国防、政府和金融组织的多个入侵事件。在每一次入侵中，攻击者活动的最早证据都可以追溯到受影响环境中属于Pulse Secure VPN设备的DHCP IP地址范围。

在许多情况下，我们无法确定攻击者是如何获得对设备的管理员级访问权的。然而，根据Ivanti的分析，我们怀疑一些入侵是由于利用了先前披露的2019年和2020年的Pulse Secure漏洞，而其他入侵是由于利用了CVE-2021-22893。

我们观察到UNC2630从各种Pulse Secure VPN登录流中获取凭证，这最终使行为者能够使用合法的账户凭证横向进入受影响环境。为了保持被入侵网络的持久性，该行为人在VPN设备上利用了合法但经过修改的Pulse Secure二进制文件和脚本。这样做是为了达到以下目的：

1. 用恶意代码木马化共享对象，以记录凭证和绕过认证流程，包括多因素认证要求。我们追踪这些木马化的程序集为SLOWPULSE及其变种。

2. 将我们目前跟踪的Webshells作为RADIALPULSE和PULSECHECK注入到合法的互联网访问的设备的Pulse Secure VPN设备管理网页上。

3. 在只读和读写模式之间切换文件系统，以允许在典型的只读文件系统上修改文件。

4. 在管理员进行的VPN设备总体升级中保持持久性。

5. 在使用后取消修改过的文件并删除实用程序和脚本以逃避检测。

6. 利用基于行为者定义的正则表达式的THINBLOOD工具，清除相关的日志文件。

在2021年3月的一个单独事件中，我们观察到UNC2717在一个欧洲组织使用RADIALPULSE、PULSEJUMP和HARDPULSE。虽然我们没有观察到UNC2630对美国DIB公司使用的PULSEJUMP或HARDPULSE，但这些恶意软件家族具有共同的特征，并且与UNC2630使用的其他代码家族有类似的目的。我们还观察到一个OpenSSL库文件以类似于其他木马共享对象的方式被修改。我们认为，这个被修改的库文件，我们将其命名为LOCKPICK，可以削弱设备使用的通信加密，但没有足够的证据来证实这一点。

由于目前缺乏背景和取证证据，Mandiant不能将本报告中描述的所有代码家族与UNC2630或UNC2717联系起来。我们还注意到，一个或多个相关团体有可能负责开发和传播这些不同的工具，并在松散有联系的的APT行动者之间传播。除了UNC2630和UNC2717之外，可能还有其他团体采用了这些工具中的一种或多种。尽管我们的理解存在这些差距，但我们在技术附件中包括了对所有代码族的详细分析、检测技术和缓解措施。

**SLOWPULSE**

在我们调查UNC2630的活动期间，我们发现了一个新的恶意软件家族，我们称之为SLOWPULSE。这种恶意软件及其变种被作为合法Pulse Secure文件的修改，以绕过或记录合法Pulse Secure共享对象libdsplibs.so中存在的认证流中的凭证。在发现的四个变体中，有三个变体使攻击者能够绕过双因素认证。本节将简要介绍这些变体，更多细节请参考技术附件。

**SLOWPULSE 变体1**

如果攻击者提供一个秘密的后门密码，这个变体负责绕过LDAP和RADIUS-2FA认证程序。该样本检查了在每个协议的相关例程开始时使用的登录凭证，如果提供的密码与攻击者选择的后门密码相匹配，则战略性地强制执行成功的认证补丁。

绕过LDAP认证 (LDAP Auth Bypass)

例程DSAuth::LDAPAuthServer::authenticate开始LDAP认证程序。这个变体在绑定例程后插入了对后门密码的检查，因此返回值可以被有条件地踩踏，以欺骗成功的认证。

（图一: :绕过LDAP认证 (LDAP Auth Bypass)）

绕过RADIUS双因素认证

例程(Routine) DSAuth::RadiusAuthServer::checkUsernamePassword开始RADIUS-2FA认证程序。该变体在收到认证服务器发回的RADIUS认证数据包后，插入了对后门密码的检查。如果后门密码是由攻击者提供的，数据包类型和成功认证状态标志被覆盖，以欺骗成功认证。

**SLOWPULSE 变体2**

ACE双因素认证凭证记录

这个变种记录了在ACE-2FA认证程序DSAuth::AceAuthServer::checkUsernamePassword中使用的凭证。这个变种不是绕过认证，而是将用户名和密码记录到一个文件，供攻击者以后使用。

**SLOWPULSE 变体3**

绕过ACE双因素认证

该变体负责绕过从DSAuth::AceAuthServer::checkUsernamePassword开始的ACE-2FA登录程序。认证程序的流程被修改，以绕过负责验证用户名和密码（如果提供了后门密码）的程序。通过这种修改，攻击者可以欺骗成功的认证。

**归属(Attribu****tion)**  

我们正处于收集证据和进行归因评估的早期阶段，我们对UNC2630、UNC2717和这12个代码家族的理解还存在一些差距。然而，Mandiant和Ivanti团队正在积极地发布这一分析，以协助网络防御者分流和识别受影响设备上的恶意活动。

Mandiant能够评估：

● UNC2630早在2020年8月至2021年3月就以SLOWPULSE、RADIALPULSE、THINBLOOD、ATRIUM、PACEMAKER、SLIGHTPULSE和PULSECHECK等美国DIB公司作为目标。

*   我们怀疑UNC2630代表某政府运作，并可能与APT5有联系。
    

●UNC2717在2020年10月至2021年3月期间使用HARDPULSE、QUIETPULSE和PULSEJUMP针对全球政府机构。

*   我们没有足够的关于UNC2717的证据来确定政府的赞助或与任何已知的APT组织的可疑联系。
    

● 我们没有足够的关于使用LOCKPICK的信息来做出归属声明。

**UNC2630**

UNC2630的基础设施、工具和网络行为的组合似乎是独一无二的，我们没有在任何其他活动或任何其他活动中观察到它们。尽管有这些新的工具和基础设施，Mandiant分析员注意到与可追溯到2014年和2015年、由某国家间谍行为者APT5进行的历史性入侵有很大的相似之处。我们还发现了有限的证据，表明UNC2630代表某政府运作。目前仍在进行分析，以确定可能与该组织有关的全部活动范围。

尽管我们无法将UNC2630与APT5或任何其他现有的APT组织明确联系起来，但一个受信任的第三方已经发现了证据，将这一活动与Mandiant追踪的某国家间谍行为者APT5的历史活动联系起来。虽然我们不能建立同样的联系，但第三方的评估与我们对APT5及其历史TTP和目标的理解是一致的。

APT5对破坏网络设备和操纵支持这些设备的底层软件表现出极大兴趣。他们还一直针对美国、欧洲和亚洲的国防和技术公司。

*   早在2014年，Mandiant Incident Response就发现APT5对另一个技术平台的嵌入式操作系统的文件进行了未经授权的代码修改。
    
*   2015年，APT5入侵了一家为私人和政府实体提供服务和技术的美国电信组织。在这次入侵中，行为人下载并修改了与该公司网络路由器有关的一些路由器图像。
    
*   也是在这段时间，APT5从一个南亚国防组织窃取了与军事技术有关的文件。观察到的文件名表明，行为人对产品规格、有关技术产品的电子邮件、采购投标和建议以及有关无人驾驶飞行器（UAVs）的文件感兴趣。
    
*   APT5坚持以高价值的企业网络为目标，并经常在多年后重新破坏网络。他们的主要目标似乎是位于美国、欧洲和亚洲的航空航天和国防公司。次要目标（用于促进对其主要目标的访问）包括通常位于美国的网络设备制造商和软件公司。
    

  

**建议**

所有Pulse Secure Connect客户应评估Pulse Secure缓解措施的影响，并在可能的情况下应用它。企业应该利用2021年3月31日发布的最新版本的Pulse Secure的完整性保证工具。如果设备不能通过该完整性保证实用程序，网络管理员应遵循这里的说明，并联系他们的Pulse CSR以获得更多指导。

企业应检查可用的取证证据，以确定攻击者是否泄露了用户凭证。Ivanti强烈建议重设环境中的所有密码，并审查配置，以确保没有服务账户可用于验证该漏洞。

技术附件中包含了额外的检测、缓解措施和相关的MITRE ATT&CK技术。包括Hashes和分析的样本，使防御者能够快速评估他们各自的设备是否受到影响。Yara规则、Snort规则和hashes在Mandiant GitHub上的公布。

**技术附录**

  

**SLIGHTPULSE**  

文件meeting\_testjs.cgi (SHA256: 133631957d41eed9496ac2774793283ce26f8772de226e7f520d26667b51481a）是一个能够进行任意文件读写和命令执行的webshell。恶意逻辑被插入到合法逻辑的末尾，以响应POST请求。我们认为这个webshell可能负责放置额外的webshell，并用于修改合法的系统组件，导致其他观察到的恶意软件家族由于其功能。

在多个地方，汇编被写入合法功能之间的填充区域。由于这些区域非常小，约20字节，恶意逻辑通过无条件地在多个填充区域之间跳转而将自己缝合在一起。汇编的编写方式与函数中间的钩子非常相似，通常是在注入的逻辑前后推送和弹出所有的标志和寄存器。通过这种方式保留寄存器和标志，如果需要的话，恶意逻辑能够作为一个被动的观察者执行和实施其恶意逻辑，只在特定条件下影响控制流。这在两个地方被采用，即LDAP和RADIUS认证程序，DSAuth::LDAPAuthServer::authenticate和DSAuth::RadiusAuthServer::checkUsernamePassword分别。

***绕过LDAP认证***

在DSAuth::LDAPAuthServer::authenticate的典型执行中，合法的应用程序构建了C++对象DSAuth::LDAPAuthServer::ldap，然后将其与用户名和密码一起传递给DSLdapServer::bind用于登录。这个绑定可能失败或成功，这决定了LDAP协议的认证失败或成功。插入应用程序的恶意逻辑在构建ldap对象后将执行重定向到DSLdapServer::bind之前。在执行的这一点上，用户名和密码很容易通过函数中间的钩子技术从内存中提取出来，样本将其复制到两个函数之间的内存中的一个代码洞中作为临时存储位置。然后，恶意逻辑像正常逻辑一样调用DSLdapServer::bind，它将返回寄存器EAX设置为0或1，表示失败或成功。然后执行一项检查，将先前制作的临时密码副本与硬编码的后门密码进行检查。如果该检查通过，后门逻辑将EAX覆盖为1，以迫使应用程序进入成功认证的执行路径，尽管实际上认证失败了。

**绕过RADIUS双因素认证**

在DSAuth::RadiusAuthServer::checkUsernamePassword的典型执行中，合法应用程序通过RadiusAuthPacket::sendRadiusPacket发送一个带有用户名和密码的RADIUS-2FA认证包。然后，响应被例行程序DSAuth::RadiusAuthServer::handleResponse检索和解析。在数据包检索后，数据包类型被验证为3，不知道这个数据包类型指定的是什么，但这是一个成功的认证响应的数据包类型。如果数据包类型检查通过，那么样本就会读取数据包的一个字段，指定认证是否成功，然后再检查这个状态。插入的恶意逻辑在DSAuth::RadiusAuthServer::handleResponse之后劫持执行，在那里，发送到RADIUS服务器的密码会被检查为后门密码。如果该检查通过，恶意逻辑就会用表明其类型为3且认证成功的值覆盖检索的数据包。然后，恶意逻辑重新加入原始执行流程，在那里对数据包类型进行检查。如果写的是欺骗性的值，就会迫使应用程序进入成功认证的执行路径，即使在现实中认证失败。

**PACEMAKER**

文件memread（SHA256：68743e17f393d1f85ee937dffacc91e081b5f6f43477111ac96aa9d44826e4d2）是一个凭证窃取器。该样本有使用信息。

用法: memread \[-t time(minute)\] \[-m size(MB)\] \[-s sleep\_interval(second)\] 。

这个例子开始时设置了一个警报，在一个可配置的分钟数后杀死应用程序，默认为14分钟。然后它进入一个循环，每2秒读取一次/proc/条目，寻找一个目标程序，这个时间间隔也是可以配置的。通过打开/proc/<process\_name>/cmdline文件夹中的每个条目找到目标，然后读取该文件，在命令行中寻找字符串dswsd。一旦发现目标程序的proc/<target\_pid>/mem被打开，用PTRACE连接该进程，然后分块读取内存，大小不超过512字节。对于每个块，字符串20 30 20 0A 00 ( 0 \\n)被作为针头进行搜索。如果找到了，样本会通过第一个空格，然后是破折号-来分割数据。预计会找到两个破折号，这些破折号会立即被转换成十六进制数字，示例形式。-<number>。如果第二个数字减去第一个数字>8191，则样本从第一个数字的文件偏移量开始读取数据，直到第二个数字减去第一个数字指定的大小。

**LOCKPICK**

文件libcrypto.so（SHA256：2610d0372e0e107053bc001d278ef71f08562e5610691f18b978123c499a74d8）是一个包含openssl加密逻辑的共享对象。该样本包含对例程bnrand\_range的修改，破坏了生成的随机数的安全性。在这个例程中，有三种路径用于生成一个给定范围之间的随机大数。第一种情况是未修改的，生成一个归零的大数，另外两种情况是经过修补的，这样一个常量值就会覆盖生成的随机值，并且总是返回成功。这就破坏了随机数的生成，用一个攻击者在所有情况下都知道的值来替换它。

**LOCKPICK Patcher**

哈希值为b990f79ce80c24625c97810cb8f161eafdcb10f1b8d9d538df4ca9be387c35e4的文件是一个补丁程序，负责插入称为LOCKPICK的恶意逻辑。补丁程序首先在设备内置的完整性检查器脚本上运行sed，插入一个早期退出程序。这是由sed -i '12aexit 0' /home/bin/check\_integrity.sh命令插入的，当应用该命令时，会导致该脚本退出而不执行其预定的检查。在这之后，样本使用python文件读写API插入长串的汇编，这些汇编代表了被称为LOCKPICK的逻辑。这个文件与我们发现的其他补丁程序不同，它是python的，专门针对系统完整性程序。
