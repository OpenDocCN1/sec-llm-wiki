一**前言**

实践与灼见的初衷是在第一时间发现或看到国内外的红队技术文章，经过实践后觉得这个技术还不错，把实践的过程以及实践过程中吸取到的知识点和营养拿出来跟大家分享。

从技术的角度上讲，大多数人可能只是一味的关注一线渗透。比如我怎样把一个域控拿下来，把现有的拿域控的方法全部都学一个遍，觉得就是他想要的。但实际上如果仅仅会这些东西，到一定阶段后就会发现自己已经干不动了。  

正因为这个原因，要想真正的提升一个层次，不光要知道一些现有的方法，而且还要能研究出来新的方法，这才是作为一个红队选手最终要达到的一个层次，而不是说仅仅追求别人给你的方法，一味的把别人的技术拿过来，这对于一个有追求的红队选手是不行的。  

二**ABU技术**  

ABU技术是红队研发一个很重要的分支，既 Anti（对抗技术）、Bypass（绕过技术）、Undetect（隐匿技术）。  

目前做一线渗透的人心里都很清楚，有些时候你喜欢用CobaltStrike，但是发现生成出来的beancon往目标电脑上一扔就被杀，辛辛苦苦做的一个静态免杀一运行又被杀，这样渗透过程举步维艰，整个东西都运用不起来，这个时候就要用到ABU技术从而解决这种情况。  

三**Covenant**  

我们今天要讲的Covenant，也为后续的课程起一个铺垫作用。  

我是推崇C2技术的，为什么说我推崇C2技术，是因为C2本身在渗透当中它占据的位置很重要，它不光是一个衔接，一个承上启下的东西。由于C2在渗透当中如此重要，我后来转为技术研发之后，首先就是要把C2搞好。现在大家都在用CobaltStrike，它确实是一个不错的C2。但由于它获取途径的原因，使用起来也不是很方便。  
其实除了CobaltStrike外我们还有很多可以选择的东西。所以今天要给大家推荐的是一个不管是整体功能以及二次开发可扩展性都不会比CobaltStrike差的Covenant。  
Covenant的整个项目都是基于C#写的。Covenant的好处第一它是用C#写的，本身就是Windows的源生语言。第二它的可扩展性非常好，想做扩展的话有两种方法，第一种就是它本身提供了强大的API接口和自定义功能，仅仅依靠它提供给你的API和自定义接口，我们就可以把它完善的非常好，绝对不会比CobaltStrike差。另外一种就是二次开发，这个可以根据你的喜好来定制，因为它的代码模块化做的非常之好，即便你要大改也非常容易。  
01**简介**  

Covenant是一个.NET命令和控制框架，旨在突出.NET的攻击面，在Covenant的帮助下，研究人员可以更加轻松地去利用.NET的攻击面，而且它还可以作为红队研究人员的协作命令和控制平台。

接下来，在Docker容器中运行Covenant，确保已经将”</absolute/path/to/Covenant/Covenant/Data>”替换成我们的绝对路径：  

docker run -it -p 7443:7443 -p 80:80 -p 443:443 --namecovenant -v </absolute/path/to/Covenant/Covenant/Data>:/app/Data covenant

该“\-it”参数是Docker参数，指示我们应该在交互式tty中开始Covenant，如果您不想附加到tty，可以将其排除。  
这些“\-p”参数将端口公开到Covenant Docker容器。你必须公开端口7443和要启动侦听器的任何其他端口。  
该“\-v”参数在主机和容器之间创建一个共享的数据目录。确保指定数据目录的绝对路径，相对路径将不起作用。  
一定要把Covenant映射到Docker镜像里面对应的目录，如果没有的话，就跑不起来，因为所有的功能模块都在Data目录里面。  
注意：如果你是Mac系统，那么绝对路径需要去Docker Preferences中的File Sharing中添加一下。

**Launchers：启动器  
**启动器用于启动Grunt，Covenant支持9种Launchers，大家在Web页面上能看见名称和介绍。  
这里要说一下Grunt，这种都会分是否进行staging，一个shellcode在里面一般叫Loader,相当于一个中间转发端，这个Loder会去Team server端去拉取真正的core dll把它拉到内存里去执行，为一个stager的过程。stager一般都是不具备独立运行的，这里需要一个launcher加载器，相当于一个bootstrop引导程序。**  
![](../Images/c6ff4fac4ab511bcccfa43454f632175.png)****Binary启动方式**  
我们单击Binary名称进入配置页面，Binary默认生成一个.NET的程序集，就是把stager生成成一个Binary，先选择我们之前建立的监听器。下一步选择通信模板，如果监听器选择的是走HTTP的，那么模板也选择HTTP的，如果是SMB的那么就选GruntSMB的。SMB在内网用的比较多，既其他机器可以通过另外一个已经运行了这个Grunt的机器来上网，而不直接外连走SMB协议。  
KillDate在实际渗透当中比较有用，在实际情况中因为某些原因权限丢失无法连接，这个时候你的Grunt如果还在目标机器上跑着就很容易被人发现，这种情况下你设置一个KillDate，可以降低被发现的风险。

四**SILENTTRINITY**  

另外一个比较推崇的C2是SILENTTRINITY，SILENTTRINITY是一个由Python3和.NETs DLR支持的现代、异步、多层和多服务器C2/post开发框架。基于python代码，实际传过去的代码是python不过叫lronPython,可以理解为.NET的python。调用所有python库的同时还可以调用.net的东西。SILENTTRINITY最早的时候是基于lronPython去做的，后来换成了boolang语言，语法上极大借鉴了python，编写简单。  
项目地址：https://github.com/byt3bl33d3r/SILENTTRINITY

![](../Images/5315ff884bb8ecf955d1a428cfd43be9.png)  
SILENTTRINITYS端代码为python编写，目标端口Launcher。  
Core dll(Beacon)-->Stager(c#,c/c++)-->Launcher(Binary powershell)  
Launcher用的是.NET程序，由.NET程序负责这个语言对应的解释器，如lronPython解释器对应的DLR，需要把它拉取到目标机器上直接在内存加载，加载完成之后目标机器就具备了解析执行lronPython的能力，后面用到的所有功能像mimikatz等，实际传回去的都是python编码，因为解释器的DLR已经被加载到内存了，会去解析python，用python代码去执行。  
SILENTTRINITYS的好处是在对内存动态免杀这方面有着先天的优势，为什么这么说？当使用C2传输东西的时候，有的EDR或AV软件会监控你的socket通讯，每当你开辟一块内存，尤其是不被信任的进程，像调用WindowsAPI之类往里面存东西的时候，它都会对内存扫描一遍。CobaltStrike传一个模块过去的时候，过程就是在C端开辟一块内存，然后从Team Server端取拉取模块，拉取模块过来后就会存到内存里，然后再去执行，当它存到内存的时候就会被扫一遍，这个时候你的代码免杀不过关的话，一到内存部分就会被干掉。  
SILENTTRINITYS是一开始传输过去的是脚本，比如传一个python代码过去，可以在传输的过程中，就可以对python代码进行免杀封装，这样到达目标内存之后就是加密的，扫描也不会被发现。比Covenant、CobaltStrike基于Binary要方便许多。
