影子经纪人这是不甘心 啊，卖不出去就爆猛料，昨天，他们新披露了一批资料，称美国国家安全局NSA曾经入侵过 环球银行间金融通信协会（SWIFT） 。这是有史以来，影子经纪人抛出的最激进的内容了，不仅仅包含了工具，来自外媒的消息如下。

一个国家用多0days攻击另一个国家的关键基础设施，最后一次是Stuxnet发起针对伊朗核浓缩项目。这次NSA也是使用多个0days，以便获取预期目标基础设施大范围的入侵。在这种情况下，如果 影子经纪人 的说法确实验证，看来，NSA试图完全占领国际金融体系的中坚力量，在SWIFT服务部门以及相关成员网络中安插一个上帝之眼。这种做法确实是隐蔽行动的标准程序，尽管从技术层面来说可能合法或不合法。如果美国在该地区的金融系统有一个特定的目标，NSA就会用其他手段，而不是仅仅依靠诚信合规程序、标准的外交要求，或与SWIFT服务部门合作。

### **SWIFT**

IMHO，这是最吸引人的内容，其中提到两个程序

*   JEEPFLEA\_MARKET
    
*   JEEPFLEA\_POWDER
    

这是在不到两年的时间里发现的第二起重要的 swift 黑客攻击事件, 上一次据称是由北韩政府进行的 swift 黑客攻击。文件包含了swift 中东最大服务部门eastnets的若干证据、凭证、内部架构信息，该部门提供许多与 swift 交易相关的服务, 如法规遵从性、KYC、反洗钱等

据TreasuryAndRisk称，SWIFT 70%都会选择服务部门，以避免前期投入高，以及维持与SWIFT基础设施连接的运营成本。   
我们在官方合作伙伴网站上可以看到，在全球有74个SWIFT服务部门，包括eastnets及其在巴拿马/委内瑞拉的合作伙伴BCG。

#### **JEEPFLEA\_POWDER**

根据BCG官方网站显示，bcg 商业计算机集团是 EastNets 在拉丁美洲服务巴拿马及委内瑞拉的战略合作伙伴。从文件撰写时间来看，bcg 分支机构尚未受到影响。

![](../Images/4aae46fbc255c1bfbfd083e9f9e5d5e6.png)

这样做会有很大的意义, nsa 入侵这个特定的 swift 服务部门反洗钱服务 (aml) 原因，是为了找到与恐怖分子集团的联系。但是, 鉴于 swift 服务部门成员的数量很少（120）, 想要入侵他们很容易 (例如每家银行一个 ip)，那我们要为这些服务部门中有多少已经被入侵了？

此外, 这是否确实代表了对 swift 本身存在直接威胁？确实如此, 因为这是迄今首次公布了如此多的信息, 说明 swift 服务部门是如何运作的，以及其内部基础设施的。所有这些都是攻击者非常有价值的信息 (如基础架构拓扑图、脚本、工具等)。

对攻击者来说，了解前端/中间件/后端接口之间的关系，非常有价值。还记得吗, 去年 ShadowBrokers 利用释放 EPICBANANA 和 EXTRABACON 后, 思科被迫为 asa 防火墙发布紧急补丁程序。

### **替代 SWIFT?**

外媒称，我国和俄罗斯在过去几年中专注于开发SWIFT的替代品, 如2015以来中国国际支付系统 (cips) , 上个月俄罗斯宣布了他的替代方案的金融信息转移系统 (SPFS) 。

尽管我们刚刚看到 swift 服务部门的开发需要防火墙和 windows 远程利用, 但只是用SWIFT的替代方案是不能阻止攻击者的。 只要公司不真正了解网络安全问题的技术根源--或者更糟的是否定他们--这些问题仍然存在, 并可能将关键的国家基础设施置于危险之中。

### **我们该做什么 ?**

If you are using a version of Windows equal or below Windows Vista, you are doomed forever because those version of Windows aren’t supported anymore. If you are using Windows 7 and above, you can disable SMB as mentioned on the MSDNuntil Microsoft issues official patches:

如果你使用的Windows版本等于或低于Windows Vista，你肯定是要出问题的，因为这些版本的Windows不再支持。如果你使用的是Windows 7及以上的，可以按照MSDN的建议禁用SMB，直到微软发布官方补丁：

  

> ```
> PS C:\\WINDOWS\\system32> Get-SmbServerConfiguration | Select EnableSMB1Protocol, EnableSMB2Protocol
> ```

```
EnableSMB1Protocol EnableSMB2Protocol
\------------------ ------------------
              True               True
```

```
PS C:\\WINDOWS\\system32> Set-SmbServerConfiguration -EnableSMB1Protocol $false
PS C:\\WINDOWS\\system32> Set-SmbServerConfiguration -EnableSMB2Protocol $false
PS C:\\WINDOWS\\system32> Get-SmbServerConfiguration | Select EnableSMB1Protocol, EnableSMB2Protocol
```

```
EnableSMB1Protocol EnableSMB2Protocol
\------------------ ------------------
             False              False
```

  

上述漏洞在Windows 10是无效的，虽然安全漏洞可能仍然存在，但比在Windows 7上利用要难得多。微软这个方面的安全措施做的不错，如果你还没有升级你的操作系统到Windows 10，那建议你尽快。
