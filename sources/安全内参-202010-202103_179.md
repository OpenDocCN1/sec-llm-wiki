# RansomExx勒索软件技术分析

**概述**  

RansomExx是一种勒索软件，在2020年的几次重大攻击（如大规模RansomExx勒索软件攻击巴西的法院信息系统）中，该勒索软件已经显示出进一步发展和活动的迹象。Linux版RansomEXX的发现标志着一个主要用于Windows系统的勒索软件首次被移植到Linux上。

我们的监视发现，RansomExx影响了美国、加拿大和巴西的公司，并且该勒索软件的Linux版本正在持续活动。以下详细介绍了我们对RansomExx活动的分析，其使用IcedID作为初始访问载体，使用Vatet loader作为Payload的传递方式，使用Pyxie和Cobalt Strike作为入侵后工具。这种工具组合从最初的访问开始仅用了5个小时就将勒索软件部署完毕。

![](../Images/60fbe25c643a1062a8eae8f1a6be1fc8.png)

  

  

RansomExx以前由一个威胁组织运营，SecureWorks将其命名为GOLDDUPONT，该组织自2018年以来一直活跃。根据其最近的攻击，该组织显示出一种快速有效的方法来破坏系统环境。Vatet loader、PyXie、Trickbot和RansomExx等恶意软件，以及Cobalt Strike等一些入侵后工具，通常是这个威胁组织的武器库的一部分。

这种恶意软件值得研究，因为它使用了2020年勒索软件攻击中经常观察到的技术，包括使用特洛伊木马软件来提供恶意Payload和全面、短且快速的攻击。

 

 

### **调查**

我们观察到的这起事件首先被标记为附带受密码保护的ZIP文件的钓鱼电子邮件，该文件实际上是一个带有恶意宏的Word文档（检测为Trojan.W97M.SHATHAK.A）。它显示了一条诱使用户启用宏的信息：

![](../Images/1e386d009731339c849916194a808436.png)

通过允许该文档内的宏，它将尝试从一个恶意URL下载IcedID木马（检测为TrojanSpy.Win32.ICEDID.BP）。如果下载成功，木马会使用regsvr32.exe执行。

![](../Images/5b8f33a3817ed169ed2d998b7efc1109.png)

  

作为一种常见的IcedID（银行木马）方法，它使用隐写术作为从恶意URL下载的.png文件传递Payload的方法。当文件被解密，Payload会被注入内存。为了实现持久化，IcedID创建了一个每小时运行一次的计划任务，在该任务中，它再次使用regsvr32.exe运行其恶意DLL。以下是初始化的恶意计划任务：

![](../Images/a7749d87969a5558f3d0f1fd491de99a.png)

  

在这次事件中，我们观察到msiexec.exe被用来注入和部署最后的IcedID Payload，之后，攻击者就能够加载并执行Cobalt Strike Payload，使其能够与命令和控制（C&C）服务器通信。

用于交付其它组件（在环境中执行）的工件是特洛伊木马版本的Notepad++-Vatet  loader（检测为Trojan.Win32.VATET.SM）。 正如我们在之前的文章中所描述的，Vatetloader使用基于XOR的方法解密文件（在我们的分析中称为config.dat）。XOR操作之后，它分配内存，将config.dat解密的代码注入到其自己的内存中，然后执行Payload。以下是Vatet loader的代码片段： 

![](../Images/a332e0037e016672144f4f018bd3a00f.png)

  

Vatet loader会加载任何Payload，只要它遵循config.dat的文件路径进行正确的XOR操作。我们发现一个不同的config.dat文件被用于不同的目的，比如通过Pyxie、Lazagne、Mimikatz以及RansomExx本身的最后一个攻击阶段的信息收集。一个主要的观察结果是，用于信息收集的config.dat在其Payload的配置中、特别是在与用于发送收集信息的服务器地址有关的部分中，包含了一个内部IP。我们有证据表明，这个内部IP被用作渗透点，并传递给前面提到的C&C服务器。这种行为让我们认为整个攻击的速度非常快且其中某些组件是在事件发生时创建的。

 

 

### **Linux版本的用法**

将所描述的事件与RansomExx的最新攻击相关联，我们观察到攻击者使用RansomExx的新Linux版本来破坏Linux服务器。我们没有有关恶意软件如何发送到Linux服务器的信息，但是我们观察到它通常针对VMware环境，特别是作为VMware文件存储的机器。

我们使用趋势科技Telfhash发现了三个针对Linux系统的RansomExx变种，三个样本都有相同的行为。我们从这三个样本中分析出的样本是一个64位ELF可执行文件，其所有的加密方案都来自一个名为mbedtls的开源库。该样本是多线程的，直接用于加密。它没有任何网络活动、反分析技术或其它超出其主要议程的活动。该样本还有一些可用的调试信息，让我们可以检查函数名和源代码文件名等特征：

![](../Images/cc6f2621d7278c88e3b935926222a9a4.png)

  

执行后，样本开始调用一个名为GeneratePreData的函数，该函数负责使用本地Linux函数中的伪随机值和mbedtls操作创建256位AES密钥。AES密钥使用硬编码的RSA-4096公钥进行加密，结果写入一个全局变量中。该全局变量的内容将被追加到每个文件中，以便将来在ECB模式下使用AES进行加密。下图显示了硬编码的RSA公钥：

![](../Images/a31b1d305ba00c6fa3cb871d65b24c08.png)

### **安全建议**

攻击者不断提高其武器库和方法的效率。在主要Payload部署之前，使用基于内存的技术、合法的Windows工具以及众所周知的入侵后工具，似乎对操纵勒索软件的攻击者而言具有更大的成功机会。

对于用户而言，预防是阻止勒索软件攻击的关键。如果从一开始就拒绝初始访问，那么该恶意勒索软件赖以生存的速度和敏捷性将不再重要。因此，用户应仅从受信任的合法来源下载文件，以防止恶意文件进入其系统。此外，用户应避免启用宏，否则应警惕启用宏的文档。

通常，强大的安全措施可以防止勒索软件和其它威胁对系统产生重大影响，比如采用最低权限标准和确保系统是最新版本。如果无法避免使用遗留系统，则允许虚拟补丁的解决方案可以确保遗留系统仍然受到保护。
