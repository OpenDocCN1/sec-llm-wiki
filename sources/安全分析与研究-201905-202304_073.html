1 前述

随着 IT 和 OT 环境变得越来越复杂，攻击者很快会更新他们的攻击策略以求适应。比如用户工作环境多样化，攻击者就使用了 TTPs 来渗透到他们的系统当中。最近，我们向威胁情报门户网站的客户报告了一个类似恶意软件框架 —— MATA。MATA 恶意软件框架具有多个组件，例如加载程序，协调器和插件。这个全面的框架能够针对 Windows、Linux 和 Mac OS 系统。

我们是在 2018 年 4 月首次发现了使用 MATA 的样本。此后，这个高级恶意软件框架幕后者积极地使用它来渗透全球的企业。我们从遥测技术中找出了几名受害者，并弄清了该恶意软件框架的目的。


2 Windows 版的 MATA

Windows 版的 MATA 是由几个组件组成。根据我们的遥测技术，攻击者使用了恶意加载程序来加载下一阶段加了密的 Payload。我们不确定加载的 Payload 是否是协调器恶意软件，但是几乎所有受害者都将加载器和协调器安装在了同一台计算机上。

2.1 加载器

加载器的作用是将一个硬编码的十六进制字符串转换为二进制并对其进行 AES 解密，以获得 Payload 文件的路径。从一个受感染的受害者计算机中，我们发现执行恶意加载程序的父进程是  C:\Windows\System32\wbem\WmiPrvSE.exe 。WmiPrvSE.exe 进程是 WMI Provider Host 进程，这意味着攻击者已从远程主机执行了该恶意加载程序，以便再进行横向移动。因此，我们猜测攻击者使用加载程序来破坏同一网络中的其他主机。


2.2 协调器和插件

我们在受害者计算机上的 lsass.exe 进程中发现了协调器恶意软件。该协调器恶意软件从注册表项加载加密配置数据，并使用 AES 算法对其进行解密。除非注册表值存在，否则恶意软件会使用硬编码的配置数据。以下是来自一个协调器恶意软件样本的配置值示例：

协调器可以同时加载 15 个插件，有三种加载方式：

(1)从指定的 HTTP 或 HTTPS 服务器上下载插件；

(2)从指定的磁盘路径加载 AES 加密的插件文件；

(3)从当前的 MataNet 连接下载插件文件；

恶意软件作者将其基础架构称为 MataNet。对于隐蔽通信，他们采用 TLS 1.2 连接。此外，MataNet 节点之间的通信会使用随机的 RC4 会话密钥加密。MataNet 同时实现客户端和服务器模式。在服务器模式下，将加载证书 c_2910.cls 和私钥文件 k_3872.cls 以进行 TLS 加密。但是，此次并没发现用到。

MATA_Plug_WebProxy 插件中有一个有趣的字符串 Proxy-agent：matt-dot-net ，它是对 Matt McKnight 的开源项目的引用。Matt 的项目是用 C# 而不是 C ++ 编写的。MATA 代理明显更简单，比如它没有缓存，也没有 SSL 支持。MATA 的作者有可能找到并使用了 Matt 代理服务器早期版本的源代码。看来恶意软件作者将代码用 C ++ 重写，但此足迹没有变化。

3 非 Windows 版的 MATA

MATA 框架不仅针对 Windows 系统，而且还针对 Linux 和 macOS 系统。

3.1 Linux 版的 MATA

在研究过程中，我们还发现了一个包含不同的 MATA 文件和一套黑客工具的软件包。在这种情况下，可以在合法的分发站点上找到该软件包，这可能表明这是分发恶意软件的方式。它包括 Windows MATA 协调器，用于列出文件夹的 Linux 工具，用于利用 Atlassian Confluence Server ( CVE-2019-3396 ) 的脚本，合法的 socat 工具以及与一组插件捆绑在一起的 MATA 协调器的 Linux 版本。中国的安全厂商 Netlab 也发布了有关该恶意软件的详细博客。

3.2 macOS 版的 MATA

我们在 2020 年 4 月 8 日发现上传到 VirusTotal 上的针对 macOS 平台的恶意软件样本，此恶意样本是基于名为 MinaOTP 的开源身份验证应用程序的 macOS 木马应用程序。

TinkaOTP 模块负责将恶意 Mach-O 文件移动到 Library 文件夹，并使用以下命令执行该文件：

cp TinkaOTP.app/Contents/Resources/Base.lproj/SubMenu.nib ~/Library/.mina > /dev/null 2>&1 && chmod +x ~/Library/.mina > /dev/null 2>&1 && ~/Library/.mina > /dev/null 2>&1

启动后，恶意 Mach-o 文件从 /Library/Caches/com.apple.appstotore.db 中加载初始配置文件。就像在不同平台上运行的另一种病毒一样，macOS MATA 恶意软件也基于插件运行。它的插件列表与 Linux 版本几乎相同，除此之外还包含一个名为 plugin_socks 插件。plugin_socks 插件类似于 plugin_reverse_p2p ，负责配置代理服务器。


4 受害者分布

基于我们的遥测技术，已经能够识别出一些被 MATA 框架感染的受害者。感染不限于特定区域。在波兰，德国，土耳其，韩国，日本和印度都存在。而且，攻击者破坏了包括软件开发公司，电子商务公司和互联网服务提供商在内的各个行业的系统。

我们评估了 APT 组织成员使用了 MATA，并从一名受害者中确定了他们某个意图。在部署 MATA 恶意软件及其插件之后，攻击者试图找到受害者的数据库并执行多个数据库查询以获取客户列表。我们不确定他们是否完成了客户数据库的筛选，但是可以确定受害者的客户数据库是他们的兴趣之一。此外，MATA 还用于向一名受害者分发 VHD 勒索软件，有关内容将在即将发布的博客文章中进行详细介绍。


5 溯源

我们评估了 MATA 框架与 Lazarus APT 之间的联系。MATA 协调器使用两个独一无二的文件名，c_2910.cls 和 k_3872.cls，这些文件名以前仅在几种 Manuscrypt 变体中才能看到，包括在 US-CERT 出版物中提到的样本 ( 0137f688436c468d43b3e50878ec1a1f ) 。

独一无二的文件名

此外，MATA 使用全局配置数据，包括随机生成的会话 ID，基于日期的版本信息，Sleep 间隔以及多个 C2 和 C2 服务器地址。我们已经看到，其中一个 Manuscrypt 变体 ( ab09f6a249ca88d1a036eee7a02cdd16 ) 与 MATA 框架具有相似的配置结构。这个旧的 Manuscrypt 变体是一个活动的后门，它具有类似的配置数据，例如会话 ID，Sleep 间隔，C2 地址的数量，受感染的日期和 C2 地址。它们不相同，但是结构相似。


6 结论

MATA框架很重要，因为它可以针对多个平台：Windows，Linux 和 macOS。此外，这个高级恶意软件框架的幕后者利用它进行了网络犯罪攻击，这种攻击窃取了客户数据库并分发了勒索软件。我们猜测该恶意软件将会发展，因此我们将监视其活动以保护我们的客户。
