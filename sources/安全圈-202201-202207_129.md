# 【安全圈】黑客利用未修补的关键Atlassian Confluence零日漏洞

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzIzMzE4NDU1OQ==&mid=2652000243&idx=3&sn=c6c90309ad48789ceb09aa849e2437a8&chksm=f36f63b3c418eaa5cb7a3aaa6938f035e1bed468573c6e095efcbb61f0ca387f220a698b4357&scene=126&sessionid=1681311560#rd](http://mp.weixin.qq.com/s?__biz=MzIzMzE4NDU1OQ==&mid=2652000243&idx=3&sn=c6c90309ad48789ceb09aa849e2437a8&chksm=f36f63b3c418eaa5cb7a3aaa6938f035e1bed468573c6e095efcbb61f0ca387f220a698b4357&scene=126&sessionid=1681311560#rd)

**关键词**

网络漏洞

  

![](../Images/b991d80473856ea2305ab63190825e5d.png)

  

Atlassian警告说，一个严重的未修补远程代码执行漏洞会影响Confluence Server和Data Center产品，据称该漏洞正在被广泛利用。

  

这家澳大利亚软件公司认为网络安全公司Volexity发现了该漏洞，该漏洞被跟踪为CVE-2022-26134。

  

“Atlassian已经意识到当前正在积极利用Confluence数据中心和服务器中严重严重的未经身份验证的远程代码执行漏洞，”它在一份公告中说。

  

“目前没有可用的Confluence Server和Data Center的固定版本。Atlassian正在以最高优先级发布修复程序。” 在软件补丁可用之前，该安全漏洞的细节已被保留。

  

Confluence Server版本7.18.0已知已在野外被利用，尽管Confluence Server和Data Center版本7.4.0及更高版本可能存在漏洞。

  

在没有修复的情况下，Atlassian敦促客户限制来自Internet的Confluence Server和Data Center实例，或者考虑完全禁用Confluence Server和Data Center实例。

  

攻击链涉及利用Atlassian零日漏洞（一种命令注入漏洞）在服务器上实现未经身份验证的远程代码执行，从而使威胁行为者能够利用立足点来删除Behinder Web Shell。

  

“ Behinder为攻击者提供了非常强大的功能，包括仅内存的 webshell以及对与Meterpreter和Cobalt Strike交互的内置支持，”研究人员说。“同时，它不允许持久化，这意味着重启或服务重启会将其清除。”

  

随后，据说web shell被用作将两个额外的web shell部署到磁盘的管道，包括China Chopper和自定义文件上传 shell，用于将任意文件泄露到远程服务器。

  

在Atlassian Confluence中另一个严重的远程代码执行漏洞（ CVE-2021-26084，CVSS得分：9.8）被积极武器化以在受感染的服务器上安装加密货币矿工之后不到一年的时间。

  

“通过利用这种漏洞，攻击者可以直接访问高度敏感的系统和网络，”Volexity说。“此外，这些系统通常难以调查，因为它们缺乏适当的监控或日志记录功能。”
