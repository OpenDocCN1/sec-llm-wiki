1. Problem

结合UCO利用Twitter信息对网络安全相关事件做出威胁预警。

[相关解释]

UCO，全称Unified Cybersecurity Ontology, 网络安全信息集成本体，融合了STIX,CVE,OpenIOC等多个本体标准。

UCO论文：https://ebiquity.umbc.edu/file_directory/papers/781.pdf[2]，

UCO-Github仓库: https://github.com/Ebiquity/Unified-Cybersecurity-Ontology[3]

图片来自 UCO: Unified Cybersecurity Ontology[4]

2. Motivation

(1). 互联网公司 (eg.Githubstatus, AdobeSecurity)会在twitter上发布有关自身平台、产品的安全事件信息；

(2). 安全研究人员/组织会在twitter发布他们最新发现的相关漏洞信息。

3. Method

本文构建了名为“CyberTwitter”的系统，结合UCO根据Twitter中安全事件相关信息发起预警.系统分为两个模块: Cybersecurity Knowledge Base(收集Twitter上有关网络威胁和脆弱性/漏洞的相关信息) 和 Alert System(根据相关规则生成预警), 具体内容如下：

图3-1 系统概要图

A. User System Profile

收集有关用户的系统信息并将其存储为“User System Profile”文件，该文件具体包括操作系统信息、系统所安装的软件信息和版本信息, 例如Table1所示。“User System Profile”文件将作为发起威胁预警的部分规则。

B. Twitter Collection

从User System Profile中提取关键词，通过Twitter API从Twitter中获取与这些关键词有关的推文，再用WordNet对获取的数据进行清洗。

C. Security Vulnerability Concept Extractor

Security Vulnerability Concept Extractor(SVCE)是用于从网络安全公开博客、官方安全报告和CVE描述信息中提取脆弱性/漏洞相关实体的命名实体识别系统(NER)。它会为每个实体打上如下标签:Means of attack, Consequence of an attack, affected software, hardware, operating system, version numbers, network related term, filename, technical term。SVCE从对句子中命名实体的识别结果(如图3-2)，将用于对数据的过滤和清洗。

图3-2 SVCE打标结果样例

D. Filtering and Cleaning Data

Cybersecurity Knowledge Base中存储的是与安全相关的推文，因此需要对存储前的数据进行过滤和清洗，这一工作结合SVCE的打标结果进行:如果一条推文中识别出的安全相关实体不少于Threshold,则认为该推文是与安全相关的，反之则不对这条推文进行存储。在实验中，作者令Threshold=2。

E．Cybersecurity Ontologies and Knowledge Bases

使用UCO为系统提供网络安全领域的知识，基于DBpedia和YAGO对SVCE提取的概念与现实中实例建立连接(eg. http://dbpedia.org/page/Adobe_Flash_Player ，建立连接后的数据以RDF三元组的形式存储与Cybersecurity Knowledge Base。终端用户可以通过SPARQL语言进行查询使用。

在本文的知识库中，ontology还包含如下属性:

(1) hasCounter (int:Intelligence, X): 表示与X事件相关的推文数量；

(2) hasBegingTime (int:Intelligence, Y):表示第一条与Y相关推文的出现时间；

(3) hasLastIntelTime (int: Intelligemce, Z): 表示最后一条于Z相关推文出现时间；

(4) hasVulnerability (int: Intelligene, uco: Vulnerability): 表示Vulnerability;

(5) productInUSP (int: Intelligence, L): 布尔类型，如果L=True,则说明4中vulnerbility存在于user system profile中的某个产品中；

(6) isCurrentlyValid (int:Intelligence, M): 如果一条情报是valid and current，则M=True;其中，如果一条情报能够给出具有时效性的漏洞信息，则认为它满足valid & current。

F. Cybersecurity Alerts

这一环节的作用是根据cybersecurity knowledge base和user system profile生成预警，具体通过两个小的模块完成。

(1) 情报时效性判断 根据hasLastIntelTime和时间窗阈值T用来判断情报是否valid & current。例如，如果时间窗T=24h，且某情报最后被报告的时间在过去24h以内，则认为该情报是有效的。

(2) Consequent

在时效性基础上验证推文数量，然后发起预警。对于(1)中确认为valid & current的情报，如果至少有N条推文报告过此信息，则认为可以向该情报中涉及的相关用户发起预警。

4. Others

关于User System Profile: 文中没有细写是什么user，个人理解应该是关于哪些厂商、哪些用户使用了什么系统、什么产品，这样当出现与这些系统、产品相关漏洞时，向这些使用者发起预警即可。
