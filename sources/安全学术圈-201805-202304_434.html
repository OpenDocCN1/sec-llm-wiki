本文主要探讨了一种远控框架MarioNet，它本身是基于JavaScript和一些HTML5API实现的，这类脚本应该在受限的代码执行环境中运行，但是为了应对日益丰富的场景各类API出现，API的滥用给用户端安全带来了极大的隐患，但是API滥用的恶意代码由于生命周期受到用户在页面停留时间长短的限制导致其影响微乎其微。MarioNet的创新主要体现在其可以在受害用户离开当前网页后，其恶意代码仍然驻存在浏览器中运行和计算，同时也不会触发浏览器内置安全检测机制。MarioNet本质是浏览器内置组件，同时也是远程C&C类型的框架系统，其不同于传统僵尸网络是它不需要安装也不利用系统漏洞。

1 背景

1.1 HTML5特性

  • Web Workers

    将JavaScript代码执行和页面渲染隔离到不同进程下，所以web worker与父对象只能通过消息传输传递数据，web worker会监听来自父对象传来的消息直到父对象将其关闭，或用户离开当前页面。

    两种不同类型的web worker：

  1. dedicated workers，与父页面共存；

  2. shared workers，可以和多个网页通讯，即使父页面关闭也不影响其继续存活，其生命周期终于于所有与其通讯的页面都被关闭；

  • Service Worker

    service worker是一种浏览器内置的完全异步组件，也是运行在和主页面不同的进程。一旦注册且激活后，会长期贮存在后台，并不需要用户持续停留在对应的网页，也就是说，所以其生命周期独立于页面的生命周期，不受其影响。Service worker也提供了独有的机制，例如推送提醒，异步后台运行等。Service worker同时也可以拦截处理网络请求和服务器的响应缓存，优化了用户体验。

    Service worker只能在HTTPS连接下通过serviceWorkerContainer.register(scriptURL, opts)进行注册。由于安全因素控制，这个函数所引入的JavaScript脚本文件只能从同域下获取，不能跨域加载资源。主页面上的iframe和第三方脚本也不能注册service worker。重要的是没有哪个浏览器扩展或者浏览器内部实体可以访问到浏览器对service worker的搜索和注册的代码。

    在用户离开当前网站页面的时候，service worker会被挂起知道被重新访问主页面才会被重新启动和激活。但是通过定期同步的方法可以保持service worker的持续活跃状态。Service worker的注册和运行不需要得到用户的允许，service worker同样不能访问DOM节点，而是通过postMessage接口响应来自父页面的消息。

  • WebRTC

    WebRTC（Web Real-Time Communication）是一种流行的在线即时通讯应用，Web Skype，Google Hangouts等都是基于WebRTC API的，这是一种端到端连接的浏览器下的连接机制。

  • CORS

    在HTML5之前，针对外部域的AJAX请求是被同源策略限制的，它只能去请求加载本域资源。CORS技术的出现允许进行跨域的资源读取加载。

    • 1.2 Web扩展

    现代化浏览器扩展允许两种脚本：

    1) Content脚本：可访问操作页面数据和一部分WebExtension JavaScript API；

    2) background脚本：运行在后台，与浏览器的生命周期一样长的；可访问所有WebExtension API和chrome.* API；

    两者可以互相通信，间接实现content脚本访问WebExtension API，background脚本访问页面数据。重点是没有哪一个浏览器允许扩展访问service worker API，所以浏览器扩展不能部署service worker。

    1.3 安全分析

    上表总结了不同API的具备的特性，基本可以分为4类：代码执行模型；网络可达；持久化存储；是否可访问DOM节点；

    Local JavaScript code 可以通过WebStorage API使用持久化存储功能，也可以使用XHR，WebSockets，WebRTC进行通信，也能访问并操作DOM节点和网络请求响应数据，但是不能脱离页面也不能在渲染进程被阻断的情况下运行，所以很容易影响用户体验，也会被浏览器扩展监测。

    Web Worker 因为运行在不同的进程下所以完全不影响用户体验，所以它可以去无影响地使用主机CPU核心。

    Service worker 可以运行在后台所以是完全脱离主页面的，也不会被浏览器扩展检测到，且可以拦截HTTP请求数据。

    CORS 可以在服务端设置为Access-Control-Allow-Origin:*允许页面向任意第三方域发送GET，POST请求，WebRTC在这样的情况下允许端到端传输任意数据，这样的特性可以导致非法操作传输数据以及匿名通讯。

    2 威胁模型和目标

    2.1 威胁模型

    场景：一个包含恶意代码的网站在用户浏览器上加载后台进程。一旦页面渲染成功，恶意代码就会通过service worker加载到后台，并且可以在用户关闭该网页后继续执行。

    威胁：攻击者可以基于这种模型实现DDoS和挖矿等操作。

    有几个实际场景符合这个威胁模型：

    1. 网站注册了包含不可信第三方动态脚本的service worker；

    2. 网站引入了可以将用户导航到恶意站点的第三方库；

    3. 网站被攻击者直接在前端植入了恶意JavaScript脚本来注册他们的后台service worker；

    4. 网站引入了包含了可以动态从第三方域加载数据的iframe。虽然iframe无法注册service worker，但是可以通过社会工程学等方法打破iframe的跨域限制和非法service worker注册限制并逃逸出来，从而在新的标签页中加载，再去注册service worker实行新的恶意攻击。

    2.2 挑战

    1. 必须要将用户端设备尽可能地长时间受控，困难的原因在于服务器只有可能在用户访问当前网页时与客户端设备保持连接，但实际上用户停留在页面的时间基本不会超过1分钟；

    2. 需要绕过浏览器扩展的安全检测；

    3. MarioNet也不能干扰浏览器的正常工作来影响用户体验，否则用户会因为卡顿关闭或重启浏览器，导致攻击受到影响。

      总的来说，MarioNet需要具备隔离性，持久性和隐蔽性这三个特点。

    3 系统概览

    3.1 系统组件

    MarioNet有以下三个主要的组件：

    • Distributor

      攻击者通过可控的站点向用户投递Servant组件，这里注意攻击者只需要用户访问一次网站即可将Servant部署到后台运行，无需用户过多停留。

    • Servant

      MarioNet的浏览器内置组件，嵌在service worker中，它被植入到用户的浏览器。一旦部署成功，它就会建立一个与Puppeteer的连接来传输心跳信息保证各自的存活状态能被对方知晓，以及接收来自Puppeteer分发下来的恶意代码。Servant是在主页面的进程以外的一个进程执行，所以是不会因为主页面的关闭而受到干扰。

    • Puppeteer

      远程C&C组件，这个组件向Servant下发执行任务并编排恶意指令。

    所以，根据上图，MarioNet的整体部署步骤分为三步：

        1) 用户访问站点（Distributor）来；

        2) Distributor使用一些冗余资源（不影响用户体验的前提下）来传送JavaScript代码给Servant；

        3) Servant在页面渲染的同时部署到浏览器，并且在初始化与Puppeteer的连接来获取恶意脚本；

    3.2 设计细节

    MarioNet的三个设计目标：隔离性，持久性和隐蔽性。

    Web worker实现的攻击措施虽然实现了进程隔离，不会干扰到用户体验和页面进程的运行，但是其本身是伴随着父页面的生存周期，如果父页面被关闭其生命周期也被终止。同时，web worker也会受到来自浏览器扩展的流量监测和脚本污染。

    • 隔离性

      MarioNet使用了service worker来作为内置代理，保证了进程隔离；

    • 持久性

    1. Servant的独立性和生命周期保证了MarioNet的持久性，允许在浏览器窗口生命周期里保证攻击不会断开；

    2. 使用SyncManager接口来使用同步功能触发因用户离开页面而导致后台挂起的service worker促使其处于活跃状态；

    3. 使用Push API来保证在浏览器重启后也能使MarioNet继续贮存运行。这个API是允许浏览器传递异步提醒和升级service worker的，通过滥用该机制，MarioNet可以使Puppeteer周期性探测Servant并在浏览器重启后重新激活它。与用户不透明的service worker注册不同，现代浏览器的安全策略只有在用户允许后才可以禁止Push提醒机制。但是一个高级攻击者可以使用一些社会工程学技巧户同意开启push提醒机制。

  • 隐蔽性

    1. Service worker与C&C服务器的通信是无法被浏览器扩展监测到的。MarioNet采用TLS加密数据同时保证了网络流量不被监听和篡改。

    2. Service worker的注册初始化过程发出的GET请求是可以被浏览器扩展监测到的，但是该GET数据包仅表明了是一个service worker在进行注册。而其主要的恶意数据通讯都在这之后才会被传送，这期间的恶意流量是无法被发现的。

    3. 风扇噪音变大，电源耗电量加大等硬件异常也可能导致用户主动关闭重启页面并报告页面异常。MarioNet通过将资源利用压缩至最低，并使用HTML5的API时刻观察设备的硬件状态（CPU，电源等），大大降低了人为发现异常的可能性。

    4 攻击向量

    4.1 DDoS攻击

    JavaScript语言的限制使其不能直接实现网络层泛洪攻击，但是JavaScript使用了更高级的方式，例如XMLHttpRequest，跨平台库的函数方法，例如jQuery的get()，post()，ajax()等。

    • XHR实现DoS攻击

      MarioNet使用XMLHttpReuqst API来操作AJAX请求并且不缓存任何响应数据包。如果服务器没有设置CORS为Access-Control-Allow-Origin:*，那么AJAX的请求将获取不到任何响应。但是攻击者还是可以攻击成功，因为不一定需要服务器返回数据，只要入站连接超过阈值，服务器也不会接受来自其他源的HTTP请求了。

    • WebSocket API实现DoS攻击

      这种攻击的前提是需要目标服务器启用了WebSockets协议。即使目标服务器未启用该协议，恶意的JavaScript脚本还是可以通过请求资源滥用WebSockets协议握手机制达到攻击效果。因为虽然目标服务器会丢弃包含有WebSockets HTTP头字段的数据包，但是还是会接受WebSockets握手包作为HTTP请求数据包。MarioNet使用WebSocket()函数方法初始化连接，并且通过send()方法发送泛洪数据。

    • TCP SYN Flooding

      网络层泛洪使用XMLHttpRequest.send()，jQuery的ajax()和WebSockets的send()可以向任意主机发送TCP握手包初始化连接，即使目标服务器不是HTTP服务器也不是WebSocket服务器，但是仍然可以接收到TCP SYN握手数据包以达到DoS的攻击效果。WebSockets API也支持建立各种形式的连接，攻击者可以实现HTTP慢速攻击。虽然MarioNet由于现代浏览器的限制机制无法发送高资源消耗数据，但是通过分布式攻击一样可以达到DDoS效果。

    4.2 算力挖矿

    攻击者当前已经将挖矿算法迁移到JavaScript脚本，但是短暂的网页访问无法为挖矿提供有效的算力。MarioNet通过后台代码执行为挖矿提供高效的算力资源。

    4.3 分布式密码破解

    分布式密码破解是通过利用不同的web workers提升并行计算，或使用现代GPU的WebGL/WebCL API进行算力提升。MarioNet的主要功能在于通过Puppeteer来将多个受感染的浏览器并行联动进行分布式密码破解，主要原理是每个节点（每个受感染的浏览器）由Puppeteer分配一段hash然后用eval()函数执行计算，一旦其中一个节点匹配成功，也就是破解成功就会通知Puppeteer，尤其告知所有节点破解成功任务完成。

    4.4 非法数据托管

    MarioNet建立的僵尸网络可以实现数据托管和共享，并隐藏数据来源。原因是因为启用了WebRTC的端到端通信，利用分布式特性和持久性，可以使用WebTorrent API在WebRTC上实现数据托管，WebTorrent也允许用户通过各自的浏览器进行播种和数据传输，可以使用seed()函数创建torrent文件并开始播种，接着别的用户浏览器可以通过获取种子链接以端到端形式使用mgnetURL下载文件。

    4.5 其他攻击

    • 中继代理

    完全匿名和透明的中继代理可以端到端传输数据，这就是暗网。通过MarioNet即可建立一个暗网模型，受感染的浏览器可以作为中继代理，也就是匿名用户，他们可以从形成的暗网模型中获取非法资源而不被发现。在以前的技术基础上，MarioNet可以形成一种由WebRTC形成的匿名电路链（类似mixnets）。

    • 点击欺骗

    大型僵尸网络可以产生黑产利益，通过滥用数字广告，将受感染的浏览器作为机器人来读取广告流量以变现。

    5 评估

    5.1 原型建模

    作者用了一台带有简单web页面的Apache服务器和一台C&C服务器建立了原型。Puppeteer下发任务给Servant，一旦页面被访问就会注册后台service worker和一个用于将挂起的service worker触发成活跃状态的同步管理器。注册完成后，servant会使用WebSocket API与C&C服务器开启双工通信模式来获取恶意JavaScript脚本并在CSP允许的条件下用eval()执行。

    上图是各个浏览器对service worker的兼容性总结，作者经过测试因为其用户体验不佳排除了在Safrai上实现MarioNet。

    5.2 操作评估

    作者在不同硬件平台和浏览器下的环境对MarioNet进行了测试，目的为测试其多平台可行性，并发现如果使用WebAssembly可以提高整体效能。

    • 网络资源滥用

    下图表现在不同的浏览器和不同的网络环境下，使用XMLHttpRequest.send()发送的HTTP请求的数量，同时通过tcpdump分析了入站流量，可以看得出来最差的网络环境下也可以实现DDoS攻击。

    • 算力滥用

    下面左图展现在Chrome平台下不同的CPU使用率递增情况下的区块链hashrate。可以看得出来hashrate和不同CPU以及CPU使用率基本符合线性相关。下面中图可以是以在Windows 7，i7-4790K，4.0GHz下针对不同电源模式下的状态，可以看出由于电源模式的限制，CPU的使用率也随之变化，平衡模式中等，省电模式下CPU使用率最低，最佳模式下算力最佳。下面右图是在i7-5557U CPU下，不同浏览器实现的hashrate的不同，可以看出Firfox比Chrome和Opera算力要高出34.55%，Chrome和Opera相同是因为它们都是基于Chromium开发的。

    算力与收益公式：Earnings = ((total hashrate × block reward)/current difficulty) × time

    模拟一个场景，就是一个每天有10000用户访问的站点，假设这些用户都拥有差不多中等水平的设备，根据上述公式，攻击者可以每12个小时赚取0.5门罗币，这种收益是可观的。

    再把这种算力用在分布式密码破解，下图展现了破解一个10位字母数字密码的速率，可以看得出来所有的浏览器表现能力差不多，也就是说一个单独的浏览器的可以每秒暴破500K MD5 hash或者300K SHA-256 hash。

    • 持久性和隐蔽性的利用

      通过以下实验验证MarioNet的持久性和隐蔽性的能力。

      1）打开tcpdump；

      2）在Chrome安装工具：Tamper Chrome HTTP capturing，Chrome DevTools，WebSniffer，HTTP Spy；

      3）页面渲染完毕后植入Servant再关闭页面。再从Puppeteer推送挖矿任务给Servant并要求其连续运行3天；

      实验结果：从tcpdump可以发现检测到挖矿流量，但浏览器扩展并没有监测到异常GET流量。

      比较：与最先进的web僵尸网络进行比较可以发现在部署同样的密码破解算法的情况下，web僵尸网络只能够在用户浏览网页时最大化运行，这难免会破坏用户体验导致进程终止，所以基本用户只能在这些页面上平均停留1分钟。

    从上图可以看出，作者将MarioNet的表现分成两种情况：

    1. 最佳情况（不会影响用户体验）；

    2. 可能会影响到用户其他进程；

      在第二种情况下，作者做了一个实验，就是同样用web botnet和MariNet部署一个pi计算器并充分利用8核心的CPU，可以发现web botnet使用了8倍以上的资源，而MarioNet由于其持久性，在浏览器打开18分钟后拥有了更高的效率。而web botnet更致命的问题在于它需要吸引用户停留在页面不离开。

    6 防御

    6.1 浏览器内置机制

    • 限制或禁用service worker

    1. 通过当用户离开页面时挂起service worker或者为其设置一个时间限制来限制service worker的资源消耗，如果彻底禁用反而会影响用户体验；

    2. 针对一些可信站点开放service worker权限也能有效减缓攻击效能。禁止使用eval()以及类似的函数可以破坏这种攻击的隐蔽性，攻击者被禁用eval()等函数后会采用别的可能会被监测到的函数；

  • 白名单/黑名单

    建立源的白名单，允许白名单内的站点使用service worker，同时通过web爬虫和分析平台来检测恶意网站和脚本代码。

  • 点击激活

    这种缓解方式是通过设置用户权限来控制service worker的注册和激活。在默认情况下service worker关闭，需要用户手动点击确认才能启用。

    • 6.2 基于主机的防御

    • 签名检测

    1. 借用反病毒，防火墙的签名检测机制对网络流量进行检测；

    2. 如果攻击者通过SSL来加密流量数据，还是可以通过检测其数据包大小和流量模式来判断其是否为恶意流量。

  • 行为分析和异常检测

    字符串搜索和正则匹配都是传统的恶意代码检测手段，攻防对抗一直在升级，需要通过更高级的代码检测来发现JavaScript当中的恶意行为。比如，JaSPIn是创建了一个JavaScript的应用资源消耗文档并日益强化它，IceShield则使用了线性决策函数来将恶意代码从普通代码段中区分出来。
