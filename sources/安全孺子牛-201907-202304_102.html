1、应急概述

根据网络流量分析，发现主机有异常连接，需要进入主机进行查看分析

2、分析步骤

2.1 网络分析

1.查看网络连接信息

netstat -antup

查看主机有连接其他机器的情况

2.2 进程分析

1.根据进程ID分析，查看信息

ps -aux | grep 4053

2.查看父进程信息

cat /proc/4053/status

查看父进程ID为4052

3.查看父进程信息

查看有一个1.sh文件信息

ps -aux | grep 4052

4.分析4052的父进程信息

cat /proc/4052/status

查看4052进程的父进程为4051

5.分析4051进程信息

ps -aux | grep 4051

6.分析4051的父进程信息

cat /proc/4051/status

查看4051的父进程是4049

7.分析4049的进程信息

ps -aux | grep 4049

查看4049的进程为crontab计划任务

2.3 查看计划任务

1.查看计划任务

crontab -l

2.查看root目录下计划任务

cd /var/spool/cron/
 cat root

查看计划任务还是提示没有内容

3.使用vim进行查看root计划任务文件

vim root

发现有计划任务后门，只能通过vim编辑才能看到

4.进入root目录中，查看文件详细信息

发现1.sh文件为root账号，同时存在2.sh文件

5.查看2.sh文件信息

cat 2.sh

查看2.sh文件创建执行1.sh的任务

2.4 处置方法

1.删除root目录下1.sh和2.sh文件

rm -rf 1.sh 2.sh

2.删除计划任务

crontab -e
或者
vim /var/spool/cron/root

3、攻击路径分析

1.文件权限分析

根据文件权限为root账号，怀疑账号为通过SSH弱口令或者爆破进入

2.root登录日志分析

1.查看SSH登录日志

cd /var/log/
ls -lah | grep secure

2.统计登录日志

grep -o "Failed password" /var/log/secure* |uniq -c

在secure-20200601中有76条登录失败记录，在secure-20210420中有1716条登录失败记录，结合1.sh与2.sh文件的日期，猜测是在20211020日被暴力破解的

3.查看爆破的第一行和最后一行

# 查看第一行
grep "Failed password" /var/log/secure-20210420|head -1

# 查看最后一行
grep "Failed password" /var/log/secure-20210420|tail -1

查看爆破时间主要在20210420 03:28:39-03:43:24

4.查看哪些IP地址进行爆破

grep "Failed password" /var/log/secure-20210420|grep -E -o "(25[0-5]|2[0-4][0-9]|[01]?[0-9][0-9]?)\.(25[0-5]|2[0-4][0-9]|[01]?[0-9][0-9]?)\.(25[0-5]|2[0-4][0-9]|[01]?[0-9][0-9]?)\.(25[0-5]|2[0-4][0-9]|[01]?[0-9][0-9]?)"|uniq -c

其中发现爆破IP地址主要为192.168.184.1和192.168.184.146

5.查询被爆破的用户名称

grep "Failed password" /var/log/secure-20210420|perl -e 'while($_=<>){ /for(.*?) from/; print "$1\n";}'|uniq -c|sort -nr

被爆破的用户均为root账号

6.查询登录成功的用户

grep "Accepted " /var/log/secure-20210420 | awk '{print $11}' | sort | uniq -c | sort -nr | more

查看爆破登录成功用户有192.168.184.1和192.168.184.146

7.查看登录成功的时间

grep "Accepted " /var/log/secure-20210420 | awk '{print $1,$2,$3,$9,$11}'

3.总结分析

    • ✅爆破时间：20210420 03:28:39-03:43:24

    • ✅爆破账号：root

    • ✅爆破IP地址：192.168.184.1和192.168.184.146

4.修复方法

修改root账号为强口令，限制登录频率
