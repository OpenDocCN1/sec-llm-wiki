1、简介

我们简要介绍了三种主要的有效负载类型：singles, stagers 和stages。Metasploit包含许多不同类型的有效负载，每种有效负载在框架中都扮演着独特的角色。让我们简要看一下可用的各种类型的有效负载，并了解何时应使用每种类型的有效负载。


1.1 Inline(non staged) 内联（非分段）

单个有效负载，包含选定任务的利用和完整的shell代码。嵌入式有效负载在设计上比同类负载更稳定，因为它们将所有内容全部包含在一个组件中。但是，某些漏洞利用将不支持这些有效负载的最终大小。

1.2 Stager

暂存器有效负载与暂存器有效负载协同工作，以执行特定任务。登台者在攻击者和受害者之间建立通信通道，并读取登台有效载荷以在远程主机上执行。

1.3 Meterpreter

Meterpreter是Meta-Interpreter的缩写，是一种高级的，多方面的有效负载，可通过dll注入进行操作。Meterpreter完全驻留在远程主机的内存中，硬盘上没有任何痕迹，这使得使用常规取证技术很难检测到。可以根据需要动态地加载和卸载脚本和插件，并且Meterpreter开发非常强大并且不断发展。

1.4 PassiveX 被动X

PassiveX是一种有效负载，可以帮助绕过限制性出站防火墙。它通过使用ActiveX控件来创建Internet Explorer的隐藏实例来执行此操作。使用新的ActiveX控件，它可以通过HTTP请求和响应与攻击者进行通信。

1.5 NONX

NX（No eXecute）位是某些CPU内置的功能，可防止代码在某些内存区域中执行。在Windows中，NX被实现为数据执行保护（DEP）。Metasploit NoNX有效负载旨在规避DEP。

1.6 ORD

顺序有效负载是基于Windows登台的有效负载，具有明显的优缺点。优点是，它可用于Windows 9x之前的Windows的每种风格和语言，而无需明确定义返回地址。它们也很小。但是，两个非常具体的缺点使它们不是默认选择。首先是它依赖于这样一个事实，即在利用之前将ws2_32.dll加载到正在利用的进程中。第二个原因是它比其他平台设备的稳定性差。

1.7 IPV6

顾名思义，Metasploit IPv6有效负载旨在在IPv6网络上运行。

1.8 REFLECTIVE DLL INJECTION 反射式DLL注入

反射DLL注入是一种技术，可将阶段有效负载注入到运行在内存中的受损主机进程中，而不会触碰主机硬盘驱动器。VNC和Meterpreter有效负载均利用反射DLL注入。

2、生成payload

在漏洞利用程序开发期间，需要生成shellcode以便在漏洞利用程序中使用。在Metasploit中，可以从msfconsole内部生成有效负载。当您使用某个有效负载时，Metasploit将添加generate，pry和reload命令。

use payload/windows/shell_bind_tcp
2.1 generate

运行generate命令使用-h，查看各种选项。

generate -h

2.1.1 直接生成shellcode

要生成不带任何选项的shellcode，只需执行generate命令。

generate

2.1.2 移除坏字符

在没有任何坏字符的情况下生成这样的shellcode的可能性很小。通常会根据目标机器使用不良字符和特定类型的编码器。

上面示例代码包含一个几乎通用的坏字符，即空字节（\ x00）。允许我们使用某些漏洞，但数量不多。仅这次我们生成相同的shellcode，我们将指示Metasploit删除此不需要的字节。

为此，我们发出generate命令，然后执行-b开关，并附带我们希望在生成过程中禁止使用的伴随字节。


generate -b '\x00'

通过查看此shellcode，不难发现，与之前生成的bind shell相比，已成功删除了空字节。这样就给了我们一个空字节的有效载荷。由于我们在生成过程中进行了更改，我们还看到了其他重大差异。第一次生成的字节为328 bytes，清除坏字符以后生成的字节为355 bytes。

在生成期间，需要替换（或编码）空字节的原始意图或代码中的有用性，以确保一旦进入内存，我们的绑定shellcode仍可正常工作。

另一个重大变化是增加了编码器的使用。默认情况下，Metasploit将选择最佳的编码器来完成手头的任务。编码器负责除去使用-b开关时输入的不需要的字符（除其他外）。稍后我们将更详细地讨论编码器。

当指定不良字符时，框架将使用最佳的编码器来完成工作。如果在代码生成期间仅限制了空字节，则使用x86/shikata_ga_nai编码器。如果我们再添加一些不良字符，则可以使用其他编码器来完成相同的任务。让我们再添加几个字节到列表中，看看会发生什么。

generate -b '\x00\x44\x67\x66\xfa\x01\xe0\x44\x67\xa1\xa2\xa3\x75\x4b'

我们看到使用了另一个编码器，以便成功删除不需要的字节。Shikata_ga_nai可能无法使用我们的受限字节列表对有效负载进行编码。另一方面，Fnstenv_mov能够完成此任务。

2.2 载荷生成失败

无需使用某些字符即可生成shellcode的能力是此框架提供的重要功能之一。这并不意味着它是无限的。

如果给出的限制字节太多，则没有编码器可以完成该任务。此时，Metasploit将显示以下消息。

generate -b '\x00\x44\x67\x66\xfa\x01\xe0\x44\x67\xa1\xa2\xa3\x75\x4b\xFF\x0a\x0b\x01\xcc\6e\x1e\x2e\x26'

2.3 载荷生成期间使用编码器

如前所述，当生成有效载荷时，框架将选择最佳的编码器。但是，有时无论Metasploit的想法如何，都需要使用一种特定的类型。假设只有一个包含非字母数字字符的漏洞利用程序才能成功执行。在这种情况下，“ shikata_ga_nai”编码器不适用，因为它几乎使用了所有可用于编码的字符。

查看编码器列表，我们看到存在x86/nonalpha编码器。

show encoders

使用-e 参数指定编码器

generate -e x86/nonalpha

如果一切都按计划进行，则我们的有效载荷将不包含任何字母数字字符。但是，当使用默认编码器以外的其他编码器时，我们必须小心。因为它倾向于给我们更大的有效载荷。例如，此示例比我们之前的示例大得多。

使用-o 参数能够将生成的有效负载保存到文件中，而不是将其显示在屏幕上。与往常一样，它跟随带有文件路径的generate命令。

generate -b '\x00' -e x86/shikata_ga_nai -o /root/payload.txt

通过使用cat命令，就像从命令shell一样，我们可以看到有效负载已成功保存到文件中。如我们所见，生成shellcode时也可以使用多个选项。

cat /root/payload.txt

2.4 多次进行载荷编码

-i 指定编码次数。简而言之，它告诉框架在产生最终有效负载之前必须进行多少次编码。这样做的原因之一是隐身或逃避病毒。MSFU的另一部分详细介绍了防病毒规避。

因此，让我们比较一下使用相同Shellcode的1次迭代和2次迭代生成的绑定Shell负载。

generate -b '\x00' -i 2

比较两个输出，我们可以看到第二次迭代对有效负载的明显影响。首先，字节大小大于第一个。迭代次数越多，有效载荷就越大。其次，比较突出显示的代码的前几个字节，我们还看到它们不再相同。这是由于第二次迭代或第二次编码遍。它对我们的有效载荷进行了一次编码，然后再对该有效载荷进行了编码。让我们看一下我们的shellcode，看看5次迭代有多大的不同。与所有先前的输出进行比较时，此更改非常重要。它稍大，我们的字节几乎没有相似之处。从理论上讲，这将使此版本的有效负载不易于检测。

我们从一开始就花费了大量时间来生成默认值的shellcode。对于绑定外壳，默认侦听端口为4444。通常必须更改此端口。我们可以通过使用-o开关后跟我们想要更改的值来完成此操作。让我们看看我们可以为该有效负载更改哪些选项。我们将从msfconsole发出show options命令。

注：-o 参数已经变成文件输出选项

generate -o LPORT=1234,EXITFUNC=seh -b '\x00' -e x86/shikata_ga_nai

2.5 使用NOP产生有效载荷

最后，让我们看一下NOP长度和输出格式选项。生成有效负载时，默认的输出格式为“红宝石”。尽管ruby语言非常强大且流行，但是并不是所有人都在其中编写代码。我们有能力告诉框架以不同的编码格式（base32,base64,bash,c,csharp,dw,dword,hex,java,js_be,js_le,num,perl,pl,powershell,ps1,py,python,raw,rb,ruby,sh,vbapplication,vbscript,asp,aspx,aspx-exe,axis2,dll,elf,elf-so,exe,exe-only,exe-service,exe-small,hta-psh,jar,jsp,loop-vbs,macho,msi,msi-nouac,osx-app,psh,psh-cmd,psh-net,psh-reflection,python-reflection,vba,vba-exe,vba-psh,vbs,war）提供有效载荷。生成我们的shellcode时，也可以在开始添加NOP底座。

首先，让我们看一下几种不同的输出格式，并了解如何使用-t开关。像所有其他选项一样，所有需要完成的工作就是键入开关，然后输入帮助菜单中显示的格式名称。

generate -f c

generate -f java
