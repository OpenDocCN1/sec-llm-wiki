**1、简介**

  

  在安装完elasticsearch以后，按照系统默认的配置后数据量增大的时候会导致OOM，需要针对elasticsearch进行相关的配置优化  

  

**2、配置优化**  

   2.1. 内存锁定，禁止内存不够使用swap

  

    当elasticsearch使用到swap缓存时，Elasticsearch的性能较差。将*bootstrap.memory\_lock*设置设置为true，以便Elasticsearch将进程地址空间锁定到RAM中。

*   
*   

```
vim /etc/elasticsearch/elasticsearch.yml# 取消bootstrap.memory_lock注释
```

![](../Images/7701f1728977fb61ae2fe4ddb636672d.png)

    

    2.2  修改system指定系统限制

*   
*   
*   
*   
*   

```
mkdir -p /etc/systemd/system/elasticsearch.service.d/cat > /etc/systemd/system/elasticsearch.service.d/elasticsearch.conf <<EOF[Service]LimitMEMLOCK=infinityEOF
```

  

   2.3 调整 elasticsearch的jvm参数设置  

  

        如果Elasticsearch尝试分配的内存超过可用内存，则先前的配置可能会导致节点不稳定，甚至导致节点死亡。JVM堆限制将有助于限制内存使用并防止这种情况。

  

        设置Elasticsearch堆大小时，官方建议有两个要重要规则：

*           分配的JVM内存不能超过实际物理机内存的50％
    
*           使用的内存不超过32 GB
