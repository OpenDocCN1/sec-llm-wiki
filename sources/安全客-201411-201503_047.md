# 记录一次OFFICE恶意宏分析

垃圾邮件的附件中通常存在大量恶意的word文档，这些文档常常会把自己伪装成发票、收据。今天要说的这个吸引了我的注意，我不知道这个方法以前有没有人用过，但我确实没见过。这是一个不错的方法，相当聪明。

 

这封电子邮件附有一个zip文件，解压后便是一个word文档，用着糟糕的英语写着：“感谢你的付款，你的发票。。。在附件中。谢谢你的惠顾，我们非常感谢”。

![](../Images/49584db0bca0e3dd8131f5ca3c0fe8c7.png "t012f90e5de93fb01ac.png")

 

打开word文档，你首先看到的是安全警告，下面便是一堆乱码。用红色字写着的是：“如果文件显示乱码，请启用宏。”

![](../Images/22e0f642e03fc145cfac42bcc21ac755.png "t0156b68fc0289119c0.png")

点击“启用宏”按钮，你便看到了发票内容。这让文件有了一点信服力，足以让那些不设防的人相信其真实性。

![](../Images/3cffbc2f7471025ff31400beef6808fd.png "t01494ec39ae93ee58a.png")

使用 OfficeMalScanner，你可以将宏导出来以便分析。这儿值得注意的是“ThisDocument”这个宏。

![](../Images/645df6161b6363c91c732268e242204a.png "t014479bcd4e7d192bb.png")

这儿我们使用 OleDump，他能很好的显示出文档的内部对象。

![](../Images/8bca2ac7819d89e410aa887317c57da2.png "t013427bd8a204d25b4.png")

我们还能导处‘ThisDocument’对象。

![](../Images/ed2cc8bc86d41e5debabb60a9e11a9c1.png "t018c8592697fa32d29.png")

从这个宏中，可以看到一堆像垃圾一样的字符串连接存在于VBA代码中，很典型。

 ![](../Images/e51c2c682da4dadae34416ebc5c04483.png "t01270b0538e1b9f8d8.png")

再往下，你会发现一些URL。

 ![](../Images/68e652c6a1cf652832c7c0c841eb7c2c.png "t01276a748daa690c0b.png")

这个VBA宏生成了VBS脚本，并重定向到文件中。

 ![](../Images/1ca9550bf235bd83615572fd27af4dc9.png "t0134e975683cf8f964.png")

有趣的是这个脚本还调用了一个Powershell 脚本，真会赶时髦啊。现在就很清楚它在干嘛了：从互联网上下载并执行一个文件，然后再下载一个图片用来做统计并清理。

![](../Images/caf41d453458de0a8bc97b418c64532b.png "t01fdbe9d90c92e1f41.png")

现在我们就来下载这个文件

 ![](../Images/fb0adf2b3195b2b816fd31b003d8eab7.png "t01b128c60c9d2c6186.png")

来看看这个VirusTotal到底是什么。。。

 ![](../Images/561ebd4b6c737b7de92cfdace82cb161.png "t01380186d590f39014.png")

这便是所下载的图片

![](../Images/cb82a7aeafa7e9826b9f6620000c13e8.png "t0162cf94010880955a.png") 

下图红框中的内容便是下载统计。不清楚其中到底有多少是受害者还是安全研究人员，但单纯看数字的话还是不少的。

![](../Images/9489388bca0af0d6b0d93a26f048fe7e.png "t016c686d25ee9b141e.png") 

再来看看这个宏，我想查出它是怎么将一堆乱码转换成文字的。 

在靠近底部，并在清理代码的上方，我看到对“findText”和“secondText”的调用。

 ![](../Images/ec8351b1021774d3e3c2b921e9224469.png "t01d20b6a3a83aaf9fb.png")

通过查看“findText”函数，发现它查找“<select></select>”标签并删除其中的内容。

 ![](../Images/9f7259ecf4accac47fe377d28e58ac24.png "t0128e436e7669af41b.png")

“secondText”函数查找“<inbox></inbox>”，并将其中字体颜色改为黑色。

 ![](../Images/0b1348d0e95dd58347c30976286144fa.png "t015569c2d02a41f7c1.png")

Duang!!! 这家伙根本就没做什么解码工作，只是耍了个小花招。发票的文字从开头就一直在那，只是被设置成白色，和背景色相同，所以你看不到。只要改变字体的颜色（如绿色），哈哈，看到没：

 ![](../Images/67e95638cc55b8609d0c64bab220e1db.png "t01ff7d3849dd7fe441.png")

真他妈太狡猾了。
