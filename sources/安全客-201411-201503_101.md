# Samba文件共享服务远程命令执行漏洞(CVE-2015-0240)

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzA5ODA0NDE2MA==&mid=202964775&idx=1&sn=2d7bf1ea4703902673858d58bdf81164&chksm=197bcf482e0c465e6625643fd9e133e7412952b499097580e75133df96a14b8b0a5bfdc90cd9&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzA5ODA0NDE2MA==&mid=202964775&idx=1&sn=2d7bf1ea4703902673858d58bdf81164&chksm=197bcf482e0c465e6625643fd9e133e7412952b499097580e75133df96a14b8b0a5bfdc90cd9&scene=27#wechat_redirect)

被暴的CVE-2015-0240安全漏洞出现在smbd守护进程，他能够被恶意的samba客户端利用，攻击者通过发送一个精心构造的包到samba服务器，不需要认证，就能够导致远程服务器以root权限执行任意命令。

漏洞产生的原因是未初始化的指针传到了TALLOC\_FREE()函数，它能够在NetLogin终端，通过IPC空会话，调用ServerPassowrdSet RPC API来触发利用。

提示：下面的代码段来自RedHat企业版6，samba-3.6（samba >=3.5均受此漏洞影响），在 \_netr\_ServerPasswordSet()函数，cred是一个指向结构体的指针，但是没有初始化

  

|   
 || `1203 NTSTATUS _netr_ServerPasswordSet(``struct` `pipes_struct *p, ``1204 ``struct` `netr_ServerPasswordSet *r) ``1205 { ``1206 NTSTATUS status = NT_STATUS_OK; ``1207 ``int` `i; ``1208 ``struct` `netlogon_creds_CredentialState *creds;` |
| --- | --- |

  

之后netr\_creds\_server\_step\_check()函数调用了cred

  

|   
 || `1213 status = netr_creds_server_step_check(p, p->mem_ctx, ``1214 r->in.computer_name, ``1215 r->in.credential, ``1216 r->out.return_authenticator, ``1217 &creds);` |
| --- | --- |

  

如果 netr\_creds\_server\_step\_check调用失败，creds将一直处于未被初始化的状态，之后再 \_netr\_ServerPasswordSet() 函数，cred使用TALLOC\_FREE()做内存释放，这将导致一个未初始化的指针释放漏洞。通过发送精心构造的包，有可能控制cred这个值，导致 TYALLOC\_FREE（）执行任意代码

正如上面所说的，这个漏洞仅仅在netr\_creds\_server\_step\_check()调用失败，才能触发，因此需要依赖samba的配置方式

在samba 4.1以及以上版本，当“server schannel = yes”时，漏洞会出现。再老版本的samba(samba-3.6在 Red Hat Enterprise Linux 5和6用的最多， samba-4.0Red Hat Enterprise Linux 6用的最多)，均会受到此漏洞的影响。
