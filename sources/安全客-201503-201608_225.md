# 「const」写成「var」也有安全隐患

上次写的《Flash 权限反射》有点累赘,今天再简明的讲解一下。同时提供一个可用的Demo做参考。

Flash和权限相关的概念很多,我们从最底层的开始聊。

  

**变量权限**

Flash 支持「var」和「const」作为变量修饰符。

「const」不仅作用于编译期,事实上在运行时动态修改常量成员,也是不允许的。除了增加语言健壮性,它更像是一个读写权限的开关。

  

**成员权限**

Flash也支持经典的 OOP 成员访问权限,例如public、private 等等。但不同的是,Flash给予「public」太大的权限。

在传统语言里,public成员只对当前项目的其他模块可见。但由于Flash缺少类似export的关键字,因此就将public成员对外导出。这意味着,标记了public的成员是可以跨项目共享的!

  

**项目权限**

类似传统程序的动态链接库,Flash的swf文件,也是可以相互加载的。前提是被加载的swf主动授权,允许被哪些可信站点使用。

但一些开发者为了图方便,直接授予了Security.allowDomain(\*)。因此任何一个站点的Flash都可以加载它。

通过反射机制,攻击者的swf可以提取所有的类模块。同时public成员默认被导出,因此就能在外操控其内部流程。

  

**资源权限**

类似浏览器的同源策略,Flash也有自己的一套。加载跨源资源时,默认会读取目标站点下的crossdomain.xml 文件,根据其中的策略决定能否加载。

尽管攻击者的站点未被授权,但也许存在上述问题的Flash正好在白名单里。因此,就可以利用这它做跳板,间接读取目标站点的资源。

  

**实战**

下面举一个实现中的案例,将上述提到的都利用起来。

例如,我们的网站希望能读取用户的微博信息。首先查看微博授予了哪些站点:

![](../Images/610bffb6419c678880c10fc77113ac51.png)

从中选择一个,搜索其站点下的 swf 文件,例如「size:js.t.sinajs.cn type:swf」,就以第一条结果为例吧(http://js.t.sinajs.cn/t5/album/static/swf/video/player.swf)。

反编译后开始观察。首先搜索 allowDomain(\*),存在!

![](../Images/5503104c1ddc60105d98f049ba715d90.png)

虽然其中也设置了一个白名单列表,但allowDomain是追加而不是覆盖的,因此这个列表没有任何意义。

第一步,也是重要的一步。通过!

接着寻找网络加载相关的,搜索URLLoader。在utils::PlayerLog.logReq方法里有一个,同时该方法是public的。但美中不足,此处仅仅用于日志发送,没有回调流程。因此无法控制返回数据。

继续寻找,发现comp::VideoPlayer 类中,有个 \_shareLoader 成员变量。虽然是private的,但能通过addShareLayer 这个public方法操控它,发起网络请求。

![](../Images/f374895359fd2f4692ee416c3d53bf56.png)

但请求的url不是通过参数传入的,而是从配置comp::VideoPlayer.SHARE\_URL读取。

不过值得庆幸的是,这个字段没有写死。虽然是个大写单词,但它确确实实不是常量,而是变量!是用「var」定义的,而不是「const」。(作为强迫症患者,完全无法忍受~~

![](../Images/ec6ba9326c5be244c6aa986e10d5dc89.png "[抓狂]")

)

![](../Images/779e4d1585daaf7d78662f3afe1b4dee.png)

同时它还被public修饰,因此能从外部访问。我们只要先修改它,再调用那个addShareLayer方法,就可以请求任意 url 了!

在处理接收数据时,它使用了JSON 解码。当解码失败时,会抛出异常,并且包含整个字符串。因此通过全局异常捕获,即可获得收到的内容。

![](../Images/ad53fd535ce8273f3bdbb8fe7079c535.png)

到此,我们可以在任何网站上,读取已登录的微博用户信息了。例如查看私信:

![](../Images/30149c9a1bfd9d5dee34675b091736e3.png)

\[演示\] http://www.etherdream.com/hack/weibo/weibo.html 

  

**后记**

虽然这是个比较老的攻击方式,但目前不少网站都能被利用,包括邮件、社交网站等等,很容易形成蠕虫。

当然最好的防范措施,还是用户自己禁用浏览器的第三方 cookie,才能根本上避免这类攻击。
