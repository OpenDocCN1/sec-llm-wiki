## 调试带符号的musl libc

### **0x01源码编译**

题目提供的libc.so不带符号，很难通过调试去理解musl堆管理器的数据结构，可以通过源码编译，生成一份带调试符号的libc.so，进行源码级debug。

```

tar -xzvf ./musl-1.2.2.tar.gzcd

 musl-1.2.2cd

 build"gcc" CXX="g++"
 \\             "-g -g3 -ggdb -gdwarf-4 -Og -Wno-error -fno-stack-protector"
 \\"-g -g3 -ggdb -gdwarf-4 -Og -Wno-error -fno-stack-protector"
 \\disable

\-werror
```

在`/src/x64/`下找到编译好的libc.so通过patchelf将ld.so改成libc.so即可，gdb调试时加上`dir /path/to/musl-1.2.2/src/malloc/`和`dir /path/to/musl-1.2.2/src/malloc/mallocng`便可源码调试。

### **0x02安装调试符号**

此方法要在ubuntu 20.04下才能成功下载musl\_1.2.2-1\_amd64.deb、musl-dbgsym\_1.2.2-1\_amd64.ddeb在ubuntu20.04安装

```
sudo dpkg \-i musl\_1.2.2-1\_amd64.deb
sudo dpkg \-i musl-dbgsym\_1.2.2-1\_amd64.ddeb

```

`active = {0x56042ee901d0,0,0...`：堆管理器依据申请的size，将chunk分成48类chunk，由sizeclass指定。每类chunk由一个meta结构管理，meta管理的chunk个数有限，由`small_cnt_tab`指定。当申请个数超出一个meta所能管理的最大数量，堆管理器会再申请同类型meta管理更多的chunk，并且以双向链表结构管理这些相同类型的meta。  
`usage_by_class = {0x1e, 0x0, 0x0, 0x7,...`：表示当前各meta管理着的chunk个数。`secret = 0x69448097523526a7`：在meta域每个page大小的首8个byte，都会存在一个校验key。![](../Images/a26c28d430674c97a62d54133dd58f0c.png)musl libc用以下的结构管理着meta、group以及chunk![](../Images/eaae0e27c2000cddff5a904092e559c3.png)分配了两个0x30的chunk，未释放。
