我发现了一种绕过 403 的新技术，想与您分享。研究 HTTP 协议已有一段时间了,发现可以用HTTP协议的1.0版本来绕过403。利用过程如下：在 lyncdiscover.microsoft.com 域上进行 FUZZ，发现了几个 403 禁止访问页面。![](../Images/8f2221b38004654297d4dd8a2bdefc19.png)403 禁止访问“reach%2fsip.svc”检查后得出的结论是，当我清除所有header值时，服务器对Host做出反应。  
提示1：  
将 HTTP 协议版本更改为 1.0。  
而且我没有在 header 中设置任何值。  
提示 2：  
如果服务器和任何其他安全机制未以正确的方式配置，我们就不会将 Host 放在 header 中。 ![](../Images/8120affc6febc0c09cad602c79e6ab0d.png)                                             200 成功“reach%2fsip.svc”  
![](../Images/ce8fd33ef253021ff4e31535ad348398.png)我用同样的方法尝试了另一个文件，它再次被绕过。  
![](../Images/aa066b87dd734bf1e8ea479ed18f7431.png)  
403 禁止访问“Reach/Sip.svc?wsdl”![](../Images/196ba95d1299b0cf264ff3c7ed3c0501.png)200 成功“Reach/Sip.svc?wsdl”我想在本文中再补充一点……您也可以使用此方法绕过（CDN）并获取服务器真实IP。![](../Images/3b0a80550a2ed6ee520f19ba2de7a5c4.png)位置标头响应正如您所见，在 Location 中它在返回中向我们显示了域本身的地址。我们再次使用相同的方法发送请求，这次它将向我们显示服务器的地址。![](../Images/bcf4eb561f358128fa298ce649db777f.png)                                                    位置响应
