0x01 使用含有已知漏洞的组件

MurphySec Code Scan


这里我向大家强烈推荐一款墨菲安全团队开发的IDEA插件——MurphySec Code Scan。该插件让开发者在 IDE 中即可检测代码依赖的安全问题，轻松识别代码中使用了哪些存在安全缺陷的开源组件，通过准确的修复方案和一键修复功能，快速解决安全问题。


因为封装成了IDEA的插件，所以使用起来是非常友好的。首先来到插件市场，搜索MurphySec，下边这个就是



安装完毕后，点击MurphySec->快速认证->输入令牌->认证身份->确定，配置完毕后，点击左边的开始按钮即可



可以看到扫描结果还是很详细的



同时也支持Web控制台查看（https://www.murphysec.com/control/project）

0x03 SQL注入


同样采用正则匹配Mybatis配置文件

order by \$\{.*\}|like \$\{.*\}|\$\{.*\}


有不少，主要是order by注入



这里我们关注一下这个ProductMapper.xml，可以看到这里的id为select



我们知道每一个Mapper.xml都对应一个接口，所以我们来到ProductMapper.java



按住Ctrl点进去，会来到对应的Impl实现类（熟悉结构也可以直接去实现类），可以看到是getList()方法调用的mapper接口中的select方法，这里还需要注意的是，未经过预编译处理的点是order by的值，也就是getList()方法的第三个参数，是一个OrderUtil对象



所以我们关注一下OrderUtil()，当构造参数的第一个值可控，并最终拼接SQL语句带入查询时，就会有SQL注入，这里直接手写规则

new OrderUtil\(\w.*\)


可以看到有5条结果，这就大大缩小了我们的狩猎范围，并且这5个大概率就是注入点



来到controller\fore\ForeProductListController.java#searchProduct()，这是一个不需要认证的点，可以看到程序接收我们的参数后，直接拼接到了OrderUtil()中，并最终带入getMoreList()、getList()中查询
