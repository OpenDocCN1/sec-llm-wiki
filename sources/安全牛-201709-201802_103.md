# 打上熔断和幽灵补丁后 CPU哭了

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MjM5Njc3NjM4MA==&mid=2651075490&idx=2&sn=c0b6ac4db1f30afce08b960889ea39c8&chksm=bd1483718a630a675794380c899420cf0379ba3e0689d406bfb333935a83295d11f30584413b&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MjM5Njc3NjM4MA==&mid=2651075490&idx=2&sn=c0b6ac4db1f30afce08b960889ea39c8&chksm=bd1483718a630a675794380c899420cf0379ba3e0689d406bfb333935a83295d11f30584413b&scene=27#wechat_redirect)

> CPU使用率上升，吞吐率下降。

  

![](../Images/67d6e63d80185927bcf08d2768e3f816.png)

  

**SolarWinds**是一家IT综合监控与管理服务提供商，近日该公司在其AWS基础设施上记录了熔断(Meltdown)/幽灵(Spectre)补丁应用的情况，而其结果令人不忍直视。

  

下图显示的是SolarWinds的Python工作者服务层在半虚拟化AWS实例上的性能表现：

  

![](../Images/33f505706323a1b472d8e6987aef6901.png)

  

该公司还观察了其弹性计算云(EC2)实例在不同AWS可用域上随该补丁的推出而产生的CPU使用率变化（如下图所示），结果并不好看：

  

![](../Images/5aaff9c13e39eb2204a0f2d450ef30ee.png)

  

SolarWinds还对其云实例在熔断/幽灵补丁推出后的性能表现做了其他的可视化统计，绝大部分结果都很难看。其Kafka分布式流平台的**吞吐率降低了**40%，而Cassandra数据库的**CPU使用率****则上升了**25%。

  

不过，也不是没有好消息：该公司注意到某些实例的CPU使用率有所下降，并猜测是因为新版熔断/幽灵补丁比AWS的第一版补丁更优雅的缘故。

  

“

 

新的EC2补丁放出了？之前的CPU使用率猛增似乎从1月12号格林威治时间10：00以后就开始下降了呢。

——Mike Heffner (@mheffner)，2018年1月12日  

  

我们现在只能希望SolarWinds的猜测是对的，因为其之前放出的大量统计图都显示的是熔断/幽灵补丁会增加很多设备的运营成本，造成工作负载阻塞。
