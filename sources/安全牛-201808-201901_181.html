微软不再支持2008 容器领头羊Docker发布Windows Server迁移工具

原文：http://mp.weixin.qq.com/s?__biz=MjM5Njc3NjM4MA==&mid=2651080396&idx=2&sn=b27f7d9c9265d8cce4983dfd06c39675&chksm=bd14f61f8a637f09cca76c98aa4181159ed6b0ea8d40f75cac47f30cd5ac4d041184aae2fb50&scene=27#wechat_redirect

微软对 Windows Server 2008 和 2008 R2 的支持到2020年初结束。为了早应对，Docker在其 Enterprise 2.1 中添加 Windows Server 应用迁移程序。



成立于2013年的容器化领头羊Docker，将本次发布的工具集描述为：微软 Windows Server 2008 支持结束前预先容器化并保护遗留 Windows Server 应用的唯一途径。


除了 Windows Server 2016，Docker Enterprise 2.1 还添加了对 Windows Server 1709、1803 和 Windows Server 2019 的支持。


另有免费托管试用版可供尝鲜。


随着开发人员和IT部门都寻求能在不受技术或基础设施限制的条件下构建、管理和保护应用，容器用例飞速增长。


容器就是打包了代码及其所有依赖的标准软件单元，可供应用程序快速且可靠地从一个计算环境迁移到另一个计算环境。


迁移迟滞可导致安全问题和维护成本上升


拖延遗留应用及系统迁移进程的公司企业会面对更高的安全风险和维护代价。


Docker首席产品官在声明中称：


“

传统方法，比如升级底层操作系统或迁移应用到新系统或云端，都要求巨大的资源投入，只会增加已经存在的技术债。


而用Docker，用户可以快速发现、容器化，并迁移 Windows Server 应用，直接节省成本开销。


Docker Enterprise 2.1：新功能


Docker Enterprise 的新功能包括性能及对 Windows Server 应用兼容性的提升：更新了对 Windows Server 2016、1709、1803 和 2019的支持，且镜像体积更小，兼容性更高，联网选择更多。


Docker Enterprise 2.1 还增强了安全及合规：支持行业安全标准及身份验证，包括 SAML 2.0 身份验证和Docker引擎里的加密模块——Windows和Linux版的 Docker Enterprise 2.1 都通过了 FIPS 140-2 密码模块安全需求标准验证。


Mitchell International 研发总监称：


“

我们的很多遗留产品都运行在 Windows Server 上，需要能容器化我们全部应用的解决方案，以便能够享受敏捷开发运维(DevOps)的好处，提高可移植性，并在各方面贴合操作模式。只有 Docker Enterprise 可以为我们提供健壮的企业级解决方案，让我们可以转型遗留应用栈，同时减少运营成本，最小化数千台虚拟机的占用空间，采纳混合云托管架构。
