导读

Web Shell可被用来获取未经授权的访问，且经常在APT攻击以及一些犯罪团伙制造大型网络安全事件时被使用，很容易造成非常广泛的网络危害。本文中我将对其威胁进行详细描述、并提供其预防、检测以及缓解的策略。


Web shells详解

Web shells 是一种可被上传到服务器从而对远程服务器进行管理的脚本。受感染的服务器可能是面向外网或者内网的，如此可进一步的感染内部主机。其可以使用任意一种目标服务器支持的语言来写，常用的语言包括 PHP、ASP.Perl、Ruby、Python，另外Unix shell scripts也常被用到。


攻击者通常使用网络探测工具来识别网站可利用的漏洞，这种漏洞一般存在于CMS和网页服务器软件中。一旦Webshell被上传，那么攻击者就可以通过该webshell来进行提权和远程命令执行。而通过webshell提供的功能，我们可以对Web服务器进行包括添加、删除、执行shell命令等操作。


Web shells为什么会被利用？如何利用？

Web shells因为其远程访问和功能的结合，所以经常被用于进行入侵，很多时候一个非常简单的web shells却可能造成非常大的影响。


其主要用途包括以下几点：

1、获取敏感信息和证书

2、上传其他恶意软件从而造成潜在威胁 （比如用水坑攻击来进一步的感染和扫描受害者）

3、作为中继点对没有直接连到网络的主机发出有问题的命令

4、为了进一步的去使用命令控制型基础设施，可以实施潜在的僵尸网络或支持其进行进一步的入侵。这些手段一般出现在攻击者打算进行长期性的入侵。


虽然web shells通常不会被用作DOS攻击，但其可以作为一个平台来上传一些工具，比如DOS工具。


实例

常见的Web shells包括WSO、C99和B374K，当然还有中国出名的webshells管理工具”中国菜刀”，当然这些只是很小的一部分。


中国菜刀：主要特点是对小型webshell打包，另外还有几个命令控制功能，包括密码的暴力破解。

WSO：web shell by Orb ,可以伪装成一个隐藏登陆表单的错误页面。

C99：WSO的一个版本，增加了一些额外的功能。可以展示服务器的安全措施，并且包含自删除（self-delet）功能。

B374K: 以PHP为基础的web shell ，主要是一些比较常见的功能，查看进程以及执行命令。


上传策略

Web shells可被大量web应用漏洞利用或者配置缺陷来进行上传：

1、跨站脚本攻击 （xss）

2、SQL注入

3、应用程序或者服务的漏洞

4、上传文件处理不当

5、RFI（远程文件包含）和LFI(本地文件包含）漏洞

6、暴露的管理接口


上述的策略可以进行一些有规律的结合，比如一个暴露的管理接口也可能需要一个文件上传选项，或者上述其他的利用方法，最终使得上传成功。


影响

一个成功被上传的shell脚本可能导致远程攻击者绕过安全策略并获得系统未经授权的访问权限。


解决方案

预防和缓解策略

安装webshell通常需要web应用存在漏洞或者配置存在缺陷，因此识别并修复这些漏洞是避免遭受入侵的关键所在。下面是一些比较安全的做法：


1、安装防护软件，比如：安全狗。

2、定期更新web应用和主机系统，以确保防范已知的漏洞。

3、在web服务器上实现一个最小特权的策略，从而：

1、减少攻击者进行提权或者以其为支点对其他主机进行攻击。

2、对文件的创建和执行进行控制，特别是在目录中。

4、如果不是已经出现的漏洞，那么就要考虑在WebFacing系统和公司内部网络之间建立DMZ（控制区），从而限制两者之间的互动和日志流量，来识别可能的恶意行为。

5、确保web服务器的安全配置，所有不必要的端口和服务应该禁用或者关闭。所有必要的服务应该是受限但可行的。这包括：使用白名单或者阻止外部访问管理面板并且不使用默认凭证进行登录。

6、利用反向代理或者替代服务，比如网站安全狗，可以限制访问已知且合法的URL路径。

7、经常建立离线备份，这样在出现问题时可以恢复到上一版本。

8、使用用户输入验证来限制本地或者远程文件包含漏洞。

9、对系统和应用进行定期的扫描，从而及时发现某一区域的风险。虽然这无法防止零日漏洞的攻击，但却可以尽可能的将危险的地方暴露出来。

10、部署一个web应用防火墙并定期检查病毒签名、Fuzzing应用、代码审计以及服务器网络分析。


而由于webshell的可以很好地潜藏并且简单易于修改的特性，使得对其的探测非常困难。很多防病毒产品在对webshell进行检测时都显得黔驴技穷。


检测

以下是一些能够判断出你的系统已经被感染webshells的特征，不过要注意这些特征可能有许多是和合法文件相同的。任何可疑文件都应该对其其他特征进行认真的考量从而决定是否需要进一步的检测或必要的验证。


1、网站被异常性高频的访问（潜在的上传或者下载活动造成的）

2、文件使用了一个不寻常的时间戳（比如：比最近一次的更新时间还要近）

3、在网络访问的位置（Web根目录）出现可疑文件

4、文件中包含引用了可以的关键词，比如cmd.exe 或者 eval

5、对日志意想不到的连接，1、一个文件类型产生反常的网络流量（比如一个JPG文件请求POST参数）2、可疑的登陆：从内部子网到DMZ或者从DMZ到内部子网。

6、任何行迹可疑的shell命令，比如通过web服务器进程进行目录遍历。


另外对于研究多种类型的shell来说，搜索引擎是非常有帮助的。web shells 通常被用来传播恶意软件，这些都会在搜索引擎中被看到。但是许多web shells 检测了User-Agent从而在搜索引擎爬虫上产生与普通用户不同的显示。所以寻找shell时，可能需要你去根据不同的搜索引擎的bots去改变你的User-Agent，一些浏览器的插件就可以轻松的做到。一旦找到，那么接下来要做的就是删除。


除此之外，客户端特征同样也可以表明可能存在web shells。举例来说，通常情况下用户在访问时通常会加载网页或者其他更多内容，而web shells则仅仅只访问URI。因此，通过对网络访问日志的执行频率进行分析就可以确认web shells的所在。另外大多数合法的用户代理通常都包含不同的user-agents，而web shells的一般只会被创建者访问，所以其user-agents变量是非常有限的。
