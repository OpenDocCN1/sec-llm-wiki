    Red Canary 正在跟踪一个由外部驱动器传播的蠕虫，该蠕虫利用 Windows 安装程序联系与 QNAP 相关的域并下载恶意 DLL。

    在过去的几个月里，Red Canary Intelligence一直在跟踪一组我们称之为Raspberry Robin的恶意活动。请继续阅读，详细了解Raspberry Robin是什么，检测已知行为的高保真机会，以及我们如何决定如何聚类此活动的背景。

“Raspberry Robin”是Red Canary对我们在2021年9月首次观察到的一组活动的名称，该活动涉及通常通过USB驱动器安装的蠕虫。此活动群集依赖其基础架构（通常是受损的 QNAP 设备）使用包含受害者用户名和密码的 HTTP 请求来调用其基础设施， 这些设备往往受到威胁。我们还观察到Raspberry Robin使用TOR出口节点作为附加的命令和控制（C2）基础设施。msiexec.exe

像我们跟踪的大多数活动集群一样，Raspberry Robin最初是我们在多个客户环境中看到的具有相似特征的少数检测，首先被注意到杰森·基拉姆来自红金丝雀的探测工程团队。我们早在2021年9月就看到了Raspberry Robin活动，尽管大多数相关活动发生在2022年1月或之后。当我们观察到额外的活动时，除了关于VirusTotal的一些发现我们怀疑是基于C2域中的重叠而相关的。

到目前为止，我们已经在与技术和制造有联系的组织中观察到Raspberry Robin，尽管目前尚不清楚受害者之间是否存在其他联系。我们围绕这个集群有几个情报差距，包括运营商的目标。虽然我们还没有全面了解，但我们希望分享我们迄今为止对这一活动集群的了解，以丰富对这一威胁的集体理解，并使捍卫者能够识别这一活动。我们使用集群名称“Raspberry Robin”来指代下面描述的整个活动链，包括初始访问方法、蠕虫本身以及后续执行和 C2 活动。

下面我们对已知的覆盆子知更鸟行为进行了全面分析，并在此过程中提供了相应的检测机会。

情报缺口

关于这个集群的几个未解答的问题仍然存在。首先，我们不知道Raspberry Robin如何或在哪里感染外部驱动器以使其活动永久化，尽管这很可能发生在离线或以其他方式超出我们的可见性。我们也不知道为什么Raspberry Robin会安装恶意DLL。一种假设是，这可能是试图在受感染的系统上建立持久性，尽管需要额外的信息来建立对该假设的信心。

也许我们最大的问题与运营商的目标有关。如果没有关于后期活动的其他信息，就很难对这些活动的目标做出推断。尽管如此，我们希望这些信息有助于为跟踪和更好地检测Raspberry Robin活动的更广泛努力提供信息。我们希望开始对话，帮助整个社区更多地了解这种威胁。如果您一直在跟踪类似活动，我们很乐意听取您的意见并进行协作。联系intel@redcanary.com有任何意见或问题。

感谢所有帮助这项研究成为可能的研究人员，特别是杰夫·费林来自Red Canary Intelligence和来自Red Canary Detection Engineering的Jason Killam。
