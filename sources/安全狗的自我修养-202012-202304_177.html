在之前的博客中，我们对 Industroyer2 进行了高级概述，这是高级持续威胁 (APT) 组织 Sandworm 用来针对乌克兰电网的最新工具。正如 ESET 创造的名称所暗示的那样，该样本与其前身 Industroyer 存在许多共性，后者曾在 2016 年 12 月臭名昭著的乌克兰电网攻击中使用。在本博客中，我们将通过并排分析来比较这两个样本以发现相似之处，这有助于我们更深入地了解攻击者的想法。


在我们提出将这两个样本联系起来的证据之前，我们将首先关注 Industroyer2 的主要任务，即操纵 IEC-104 信息对象地址 (IOA)。

与 Industroyer 不同，后者主要通过不同的动态链接库 (DLL)（ie101.dll、104.dll、61850.dll、OPC.exe 和 OPCClientDemo.dll）针对 IEC-101、IEC-104、IEC 61850 和 OPC 数据访问，被称为 Industroyer2 的恶意软件是一个独立的可执行文件，专门针对 IEC-104。

在对样本的分析过程中，我们发现了现代恶意软件中的一些不寻常之处：作者没有费心隐藏其活动，也没有进行任何形式的混淆。恶意软件的核心由其配置组成，除了下面描述的其他参数外，还包含要操作的 IOA 的硬编码列表。此配置在可执行文件中不受保护，而是作为常规 Unicode 字符串嵌入。

对端点检测缺乏关注表明威胁参与者对目标环境中部署的安全措施有相当完整的了解。同时，IOA 的硬编码列表表明了两件事：

  1. 运营商对运营技术（OT）环境有透彻的了解；和

  2. Industroyer2 示例旨在在特权环境中执行，并直接访问目标设备。

初始访问和 Industroyer2 启动之间的时间间隔是未知的。但是，根据恶意活动，我们可以假设访问和攻击之间的时间间隔在几天而不是几小时之内。

Nozomi Networks Labs 对 Industroyer2 的分析表明，威胁参与者对目标环境中部署的安全措施有相当完整的了解。

IEC-104 配置

我们分析的样本包含三个不同站点的硬编码配置。对于每个站，配置包括：

  1. Station Configuration Header：配置站交互的Header

  2. IOA 配置格式：包含多个 IOA 及其对应参数的表格

站配置标题

其中一个站的配置使用以下标头：

10.xyz 2404 3 0 1 1 PService_PPD.exe 1 “D:\OIK\DevCounter” 0 1 0 0 1 0 0 44

10.xyz → 被控站本地IP地址

2404 → 受控站端口

3→ASDU地址

0 → 操作模式。如果设置为 0，则使用 IOA 的硬编码表。如果设置为 1，则需要跟随两个参数，指定开始和结束 IOA 编号，然后用于设置 IOA 的范围以进行迭代。

1 → 需要 9 个参数的开关：

a) 1 → 布尔值，可接受的值：0, 1

b) PService_PPD.exe → 要杀死的进程的名称

c) 1 → 控制是否应该重命名文件名，接受值：0（跳过重命名），1（重命名）

d) “D:\OIK\DevCounter” → 存放被查杀和重命名的可执行文件的文件夹

e) 0 → 以分钟为单位的休眠时间，在开始与站点交互之前执行

f) 1 → 以秒为单位的睡眠时间

g) 0 → 休眠时间，以秒为单位

h) 0 → 休眠时间，以秒为单位

i) 1 → 布尔值，可接受的值：0, 1

0 → 如果设置，它将再次与每个 IOA 交互，SCO/DCO On/Off 反转

44 → 标头后面的 IOA 数

IOA 配置格式

图 1。IOA 配置。

160921 1 0 1 1 2

  • 160921 → IOA 地址

  • 1 → 设置单命令或双命令，接受值：0（双），1（单）

  • 0 → 设置 SCO/DCO 选择/执行，接受值：0（执行），1（选择）

  • 1 → 设置 SCO/DCO 开/关，可接受的值：0（关），1（开）

  • 1 → 优先级

  • 2→配置列表中的IOA入口索引

分析

图 2。IEC 104 交互。

终止后PServiceControl.exe，根据配置PService_PPD.exe（然后将其重命名.MZ并附加到其名称），示例开始 IEC 104 交互（图 2）。


从恶意样本发送到变电站的流量在样本的调试输出中以 MASTER ->> SLV 为前缀，反之亦然。交互从一系列 TESTFR 帧开始：TESTFR act从恶意样本发送，然后由TESTFR con帧确认。TESTFR 帧用于检查两个节点之间是否存在连接问题。

发送到接收站的下一帧是STARTDT act，这是一个数据传输激活请求，期待STARTDT con回复作为确认。一旦数据传输被启用，接下来是询问命令(C_IC_NA_1)。

示例使用其硬编码站配置执行的下一步是遍历每个站的 IOA 硬编码列表并C_SC_NA_1 or C_DC_NA_1根据每个 IOA 的配置发送类型帧。除了指定 IOA 是要与单命令还是双命令一起使用外，如上面的配置中所述，还可以指定用于控制单/双 (SCO/DCO)、开/关和选择的位/执行。

建议

以下是公司可以增加保护的一些方法：


    • 基本的网络卫生：重置密码、检查员工和供应商帐户/网络访问和权限、扫描网络以查找任何打开的端口并关闭/保护它们等。

    • 利用 YARA 规则搜索相关恶意软件活动并生成警报

    • 使用异常检测工具检测恶意软件的任何变化或变化，以及 OT 环境中发生的任何异常活动

    • 将自动防火墙与异常检测工具结合使用，以阻止进一步的攻击命令

    • 威胁搜寻网络中的可疑活动；这可能有助于及早发现攻击者


如果这些安全措施尚未实施，我们还建议遵守CISA 2017 年的建议。
