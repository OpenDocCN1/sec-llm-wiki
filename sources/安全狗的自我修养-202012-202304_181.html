Cluster25的研究团队追踪了一项最近的活动，该活动始于 2022 年 4 月的第一天，来自一名 DPRK-nexus 威胁参与者，使用包含具有不同诱饵的基于韩国的恶意文档（如下例）的鱼叉式网络钓鱼电子邮件来危害其受害者。

此活动的恶意 Word 文档中使用的诱饵彼此非常不同。它们从冒充韩国互联网信息中心(KRNIC) 到冒充各种韩国互联网安全公司（例如AhnLab、Menlo Security、SaniTOX）或加密货币公司（例如Binance）。

该活动的目标似乎很笼统，旨在窃取韩国个人的数据。实际上，在大多数已确定的感染中，受害者是在 naver dot com 上注册邮件的用户，naver dot com是一个包含免费邮箱、新闻和搜索引擎功能的韩国网络平台。Cluster25将此活动归因于与 DPRK-nexus 的对手，因为已确定与Kitty Phishing [1]操作有相似之处

活动见解

网络钓鱼电子邮件附带的 Word 文档利用了模板注入漏洞 ( CVE-2017-0199 )，该漏洞允许威胁参与者从远程源下载新的武器化文档。一旦打开文档，就会联系远程 URL（例如，http://naveicoipd.tech/ACMS/0lvNAK1t/accountsTemplate）以下载恶意远程模板。

下载的模板嵌入了一个 VBA（Visual Basic 应用程序）脚本，由于已经报告的漏洞，该脚本会自动执行。此 VBA 代码使用两个嵌入式远程URL（下一阶段有效负载的32 位和64 位版本）充当下一阶段杀伤链的下载器。VBA 项目中的所有嵌入字符串都通过 base64 编码和使用硬编码XOR密钥的字节 XOR加密进行了混淆。

一旦下载了下一阶段的有效负载，各种API在运行时通过LoadLibraryA和GetProcAddress API（例如RtlMoveMemory、CryptBinaryToString、DispCallFunc）解析，并且有效负载通过用于嵌入字符串的相同过程进行解码。最后，解码后的有效负载被放到路径%LOCALAPPDATA% \Microsoft\TokenBroker\RuntimeBroker.exe 下，并通过DispCallFunc API（ Invoke方法的低级实现）执行。

可执行的RuntimeBroker.exe受到UPX打包程序的保护，它充当后期植入程序的释放器。RuntimeBroker.exe执行从两个规避检查开始，旨在避免在沙盒或虚拟化环境下执行。特别是，第一个检查由通过GetTickCount API 的基于时间的沙箱规避来表示，以检查可能的沙箱延迟跳过功能。

相反，第二个检查是通过CreateFileA API 进行基于硬件的规避，并直接访问物理驱动器\\.\PhysicalDrive0以检查已知的HDD 供应商 ID（例如，VBOX、VMware）。

之后，恶意软件会对可能的防病毒进程进行一些检查。特别是，如果有一个名为v3l4sp.exe的活动进程（AhnLab Inc 的 V3 Lite Antivirus），恶意软件会自行删除并立即退出。随后，恶意软件尝试访问C:\ProgramData\Intel目录检查写入权限。

如果此子目录的所需权限可用，恶意软件会继续向远程 URL 发出 HTTP POST 请求，以下载最终有效负载。下载有效负载后，可执行文件将放在C:\ProgramData\Intel\IntelRST.exe路径下，并创建一个新的注册表项以确保持久性。通过使用ASProtect打包工具的双重保护，最终的有效负载 ( IntelRST.exe ) 被大量打包。由于IAT重建损坏，这会导致第二层保护的部分解包。

尽管有打包机制，但还是可以提取一些有用的信息；首先，恶意软件联系存储在Dropbox云服务器上的远程 TXT 资源（即https://dl.dropboxusercontent.com/s/k288s9tu2o53v41/zs_url.txt?dl=0）以获取 C&C 服务器的域（即，naveicoipd.tech）。一旦获得命令和控制域，以下有关受害系统的信息将通过HTTP POST请求泄露到 C&C 服务器：

  • uid：字符串Cjtpp17D_与当前登录的 Windows 用户的用户名相结合。

  • avtype : 指定受害机器感染状态的整数

    • 如果未检测到任何防病毒软件，则指定值 1。

    • 如果系统上存在AYAgent.exe ，则指定值 3 （韩国 ESTsecurity Corp 的 ALYac Enterprise）

    • 如果系统上存在v3l4sp.exe进程，则指定值 2 （韩国AhnLab Inc的V3 Lite Antivirus）

  • majorv和minorv：用于指定受感染操作系统的主要和次要版本的整数

最后，恶意软件等待 来自 C&C 服务器的可能响应，这可能导致其他功能的渗出和执行。在此活动中，所有域都是通过DGA（域生成算法）生成的 ，并且因有效负载而异。在大多数情况下，drop-point 域和 C&C 域遵循naveicoip[az]{1}[.](online|tech)模式，并且看起来在Hostinger或Contabo平台上注册。在最近的一些案例中，某些域也在OVH平台上注册。

相关活动

我们确定了所描述活动的变体，该变体在杀伤链中显示出最小的变化。这个通过Windows 帮助文件 (CHM)和新的中间层 dropper呈现不同的初始访问向量，而不是之前的模板注入。更详细地说，CHM文件具有不同的内置文件，一旦打开文件就会被删除。

特别是，最相关的文件是一个 HTML 文件（称为1hh.htm ）和一个代表中间层释放器的可执行文件（称为WINWORD.exe ）。一旦打开CHM文件，HTML 文件就会被注入 CHM 视图以执行一些恶意 JavaScript 代码，这些代码会强制在C:\ProgramData\chmtemp\下创建指向WINWORD.exe的快捷方式。

一旦创建了快捷方式，这个中间层 dropper 的执行就会通过刚刚创建的Object实例上的Click()方法启动。简而言之，winword.exe负责解密和执行真正的UPX打包的dropper。中间层投放器执行与属于其他活动的投放器RuntimeBroker.exe中已经看到的相同检查。
