INCONTROLLER：新的国家支持的网络攻击工具针对多个工业控制系统

2022 年初，Mandiant 与施耐德电气合作，分析了一组针对机器自动化设备的新型工业控制系统 (ICS) 攻击工具——我们称之为 INCONTROLLER（又名 PIPEDREAM）。这些工具可以与嵌入在多个行业的不同类型机械中的特定工业设备进行交互。虽然使用此工具集的任何操作环境的目标尚不清楚，但该恶意软件对利用目标设备的组织构成重大风险。INCONTROLLER 很可能是由国家赞助的，并且包含与破坏、破坏和潜在物理破坏相关的功能。

INCONTROLLER 代表了一种极其罕见和危险的网络攻击能力。它与TRITON相媲美 ，后者在 2017 年试图禁用工业安全系统；INDUSTROYER，2016 年导致乌克兰停电；和 STUXNET，它在 2010 年左右破坏了伊朗核计划。为了帮助资产所有者发现和防御 INCONTROLLER，我们在本报告中包含了一系列缓解和发现方法。由于未来可能会对这些工具进行修改，我们相信基于行为的狩猎和检测方法将是最有效的。

INCONTROLLER 旨在操纵和破坏工业流程

工业自动化网络依赖于各种设备，使操作员能够将信息和指令转化为物理动作链。鉴于工业网络中资产的多样性，工业自动化设备通常在网络的不同部分使用不同的语言，这可以使用标准化的工业通信协议来实现。

INCONTROLLER 包括三个工具，使攻击者能够使用工业网络协议（例如 OPC UA）向 ICS 设备发送指令；Modbus；Codesys，由 EcoStruxure Machine Expert 和 SoMachine 使用；和欧姆龙鳍。虽然该工具的功能可以使参与者与来自不同原始设备制造商 (OEM) 的各种产品进行通信，但参与者为施耐德电气和欧姆龙的特定控制器开发了模块。目标设备包括机器自动化解决方案，其用例从支持简单、重复的机器到分布式架构中的复杂模块化机器：

  • OPC 服务器

  • 施耐德电气 Modicon M251、Modicon M258 和 Modicon M221 Nano PLC

    • 其他使用 Modbus 和 Codesys 的设备也可能受到影响

  • Omron NX1P2 和 NJ501 PLC 和 R88D-1SN10F-ECT 伺服驱动器

    • NJ 和 NX PLC 系列的其他设备也可能受到影响

我们高度怀疑攻击者会随机针对这些设备。选择它们更有可能是因为对特定目标环境的侦察。我们注意到这与以前的 ICS 恶意软件（例如 TRITON）是一致的，后者针对一个关键安全系统，该系统几乎可以肯定地在破坏目标的工业环境之前被识别。

INCONTROLLER：工具概述

TAGRUN

TAGRUN 的功能，例如扫描和枚举 OPC UA 服务器的能力，暗示了侦察的作用。OPC 充当中央通信协议，用于从工业环境中的 ICS 资产中收集和存储数据。访问这些数据可以为攻击者提供生产系统和控制过程的详细概述。该工具可能是为侦察而开发的，但它也可以写入和更改标签值，这些值可用于修改数据以支持攻击或掩盖过程更改。TAGRUN 还会验证目标环境是否运行 Windows 操作系统，并根据此检查的返回值提供不同的 ping 命令。这表明参与者可能使用非 Windows 设备来执行 TAGRUN。

TAGRUN 的能力包括：

  • 扫描网络上的 OPC UA 服务器

  • 读取 OPC UA 服务器的结构

  • 读取/写入 OPC UA 服务器上数据的变量值

  • 暴力破解凭据

  • 输出日志文件

编解码器

CODECALL 使用 Modbus 协议与 ICS 设备进行通信，这可能使其能够与来自不同制造商的设备进行交互。但是，该工具包含一个特定模块，用于使用 Codesys 与施耐德电气的 Modicon M251 (TM251MESE) PLC 交互、扫描和攻击，该公司专有的 EcoStruxure Machine Expert 协议使用该模块。我们有理由相信该工具还针对施耐德电气的 Modicon M221 Nano PLC 和 Modicon M258 PLC，它可能会影响利用这些协议的其他设备。

CODECALL 的一般能力包括：

  • 识别网络上的施耐德电气和支持 Modbus 的设备

  • 通过 Modbus 或 Codesys 连接到特定设备

  • 通过 Modbus 读/写设备寄存器

  • 通过 Modbus 从会话请求设备 ID

  • 定义、转储或加载命令宏文件

  • 通过 Codesys 执行设备特定的命令，例如：

    • 尝试使用用户名/密码登录，并使用提供的字典文件暴力破解凭据

    • 下载/上传文件到 PLC 设备

    • 检索文件/目录列表

    • 删除文件

    • 从 PLC 设备断开会话

    • 尝试 DDoS 攻击

    • 使用特制数据包使设备崩溃

    • 如果设备网关 IP 存在于不同的接口上，则添加路由

    • 发送自定义原始数据包

OMSHELL

OMSHELL 旨在获得对 Omron PLC 的外壳访问权限，包括 Omron NX1P2、NJ501、R88D-1SN10F-ECT 伺服驱动器，以及可能来自 NJ/NX 产品线的其他类似设备。该工具主要使用 HTTP 协议运行，但它也利用 Omron 专有的 FINS over UDP 协议进行扫描和设备识别。该框架是模块化的，这意味着攻击者可以开发附加功能并将其部署到该工具中。

OMSHELL 的能力包括：

  • 扫描并识别网络上的欧姆龙设备

  • 擦除设备的程序存储器并重置设备

  • 从设备加载备份配置和备份数据或将数据恢复到设备

  • 在设备上激活 telnet 守护进程

  • 通过 telnet 守护程序连接到设备，上传和可选地执行任意有效负载或命令

  • 连接到设备上的后门并提供任意命令执行

  • 执行网络流量捕获

  • 杀死设备上运行的任意进程

  • 将文件传输到设备

  • 与连接的伺服驱动器连接和通信

我们有理由相信，基于指标的检测无法有效检测受害环境中的 INCONTROLLER，部分原因是攻击者几乎肯定会在特定受害环境中使用该工具之前对其进行修改或自定义。相反，防御者应该将精力集中在这些工具的基于行为的狩猎和检测方法上。

潜在的支持 Windows 工具

我们还在跟踪影响可能与此威胁活动相关的基于 Windows 的系统的另外两个工具。通过在 IT 或运营技术 (OT) 环境中利用基于 Windows 的系统，这些工具有可能用于支持 INCONTROLLER 攻击中的整个攻击生命周期。

  • 其中一个工具利用 AsrDrv103.sys 驱动程序中的CVE-2020-15368  ，这将导致安装和利用易受攻击的驱动程序。华擎主板可用于 OT 环境中的一些人机界面 (HMI) 和工程工作站。

  • 我们跟踪为 ICECORE 的另一个工具是一个后门，提供侦察和指挥和控制功能。

攻击场景

每个工具可以独立使用是可行的，或者参与者可以使用这三个工具来攻击单个环境。我们强调，INCONTROLLER 所针对的设备通常集成在自动化机械（例如铣床或压力机）中，并且即使在用户没有明确知识的情况下也可能出现在各种工业部门和过程中。

我们开发了三种网络物理攻击场景，突出了使用 INCONTROLLER 进行攻击的一系列可能结果。在这三种情况中的每一种中，TAGRUN 都可以在早期阶段用于枚举受害环境、识别其目标并了解物理过程。

这些场景的影响将取决于受害设施的性质以及攻击者对受控物理过程的理解和交互的程度。我们注意到，我们目前对 INCONTROLLER 的理解仍然有限，因为它利用了可支持作者实现的新功能的可扩展结构。

INCONTROLLER 很可能是国家支持的恶意软件

我们认为，鉴于恶意软件的复杂性、构建它所需的专业知识和资源，以及它在出于经济动机的操作中的有限效用，我们认为 INCONTROLLER 很可能与国家资助的组织有关。在我们的分析阶段，我们无法将 INCONTROLLER 与任何先前跟踪的组相关联，但我们注意到该活动符合俄罗斯对 ICS 的历史兴趣。虽然我们将 INCONTROLLER 与俄罗斯联系起来的证据在很大程度上是间接的，但我们注意到它是鉴于俄罗斯的破坏性网络攻击历史、目前对乌克兰的入侵以及对欧洲和北美的相关威胁。

  • 至少自 2014 年以来，Russia-nexus 威胁行为者已经使用多个 ICS 定制的恶意软件系列（PEACEPIPE、BlackEnergy2、INDUSTROYER、TRITON 和 VPNFILTER）针对 ICS 资产和数据。

  • INCONTROLLER 的功能与俄罗斯先前的网络物理攻击中使用的恶意软件一致。例如，2015 年和 2016 年乌克兰停电都涉及物理过程操作以及针对嵌入式设备的破坏性攻击。INCONTROLLER 同样允许恶意软件操作员操纵物理过程，同时还包含拒绝服务 (DoS) 功能以破坏 PLC 的可用性。

建议

尽管任何潜在的预期受害者的性质仍然不确定，但 INCONTROLLER 对拥有兼容设备的组织构成了重大风险。目标设备嵌入多种类型的机械中，并且可能出现在许多不同的工业部门中。鉴于与先前的俄罗斯关系威胁活动的一致性，我们认为 INCONTROLLER 对乌克兰、北约成员国和其他积极响应俄罗斯入侵乌克兰的国家构成最大威胁。组织应立即采取行动，确定目标 ICS 设备是否存在于其环境中，并开始应用供应商特定的对策。

我们还建议处于风险中的组织进行威胁搜寻，以检测其网络中的这种活动。Mandiant Advantage 威胁情报订阅者可以访问包含威胁搜寻指南和 YARA 检测的附加报告。

缓解措施

OPC UA

我们建议采取几个步骤来降低使用此协议的环境中的风险和对抗恶意活动：

  • 对 IT 和 OT 网络进行适当分割，以帮助防止攻击者从公司网络转移到工业环境。

  • 允许列出已接受的主要/从属设备、行为模式和命令，以帮助建立批准的基线并借助网络监控检测异常。

  • 实施具有深度数据包检查的工业防火墙，以帮助控制访问和批准的功能。

  • 实施 ICS 感知入侵保护系统，以帮助监控来自潜在恶意来源的功能代码。

  • 在可能的情况下，监控和阻止到 OPC UA 端口的外部流量，以帮助检测异常流量并防止指向 OPC UA 相关端口的外部网络流量。

  • 启用和聚合 OPC 服务器和客户端的审计日志。

  • 定期审查审计日志以发现不一致或恶意的连接、安全选项协商、配置更改和用户交互。

施耐德电气

为帮助确保施耐德电气产品的安全和受保护，实施施耐德电气网站上提供的网络安全最佳实践文档中所述的网络安全最佳实践符合您的最大利益： 推荐的网络安全最佳实践白皮书 | 施耐德电气。

此外，  EcoStruxure Machine Expert、Modicon 和 PacDrive 控制器及相关设备用户指南的网络安全指南 可以帮助您确保只有合法用户才能访问您的施耐德电气产品：  EcoStruxure Machine Expert、Modicon 和 PacDrive 控制器及相关设备的网络安全指南，用户指南| 施耐德电气。

您应特别注意有助于限制仅授权用户访问的功能和网络安全设备。这包括入侵检测系统、网络防火墙、安全远程访问、设备身份验证、设备防火墙、禁用/过滤不安全或编程协议等示例。

欧姆龙

根据公开的漏洞公告，欧姆龙此前已经发现了其他使用与 OMSHELL 相同或相似的 FIN 端口的漏洞。如其 安全简报中所述，Omron 针对未修补漏洞的指南表明，可以使用对已识别 FIN 端口进行外部防火墙过滤作为缓解措施。Mandiant 认为推荐的方法可能是一种可行的缓解措施，尽管这种机制尚未使用 INCONTROLLER 进行测试。与 Omron 之前的建议相关的其他指南可以在  针对该旧漏洞的相关ICS 咨询中找到。

发现方法

TAGRUN

  • 搜索和调查与 OPC UA 端点的不规则连接，并为 OPC UA 应用程序启用强大的审计日志记录。将 OPC UA 日志和审计记录汇总到适用的中央位置。

  • 查看 OPC UA 审计记录以获取凭据暴力破解、恶意证书使用、不规则连接尝试、配置更改和 OPC 标签更改的证据。

  • 搜索并调查 TAGRUN ping 命令执行情况。

  • 查看 OT 网络流量以获取 pingsweep 活动的证据。

编解码器

  • 为 Schneider Electric PLC 设备启用强大的日志记录，并将日志汇总到适用的中央位置。

  • 查看 Schneider Electric 设备日志以获取以下活动的证据：

    • 凭证暴力破解

    • 与异常设备崩溃/重启相关的错误代码

    • 上传或下载的文件

    • 文件删除

    • 未经授权更改设备配置和执行命令

    • 与设备和环境记录规范之外的设备的连接

  • 搜索并调查 ARP 扫描的证据，然后是与环境基线不同的异常 Modbus/Codesys 流量。

  • 搜索与环境基线相比异常的 Modbus 和 Codesys 流量。

欧壳

  • 在可以访问 OT 资源和连接（例如，数据包捕获）的系统上搜索和调查创建/存在与 OMSHELL 相关的基于主机的指标的证据。

  • 为 Omron PLC 设备启用强大的日志记录，并将日志汇总到适用的中央位置。

  • 查看 Omron 设备日志以获取以下活动的证据：

    • 在设备上激活 Telnet 守护程序。

    • 未经授权的 Telnet 连接尝试，包括使用默认凭据。

    • 擦除程序存储器和设备复位。

    • 未经授权更改设备配置和执行命令。

    • 与设备和环境的书面规范之外的设备的连接。

    • 上传或下载的文件。

  • 识别和调查可访问和连接到 OT 资源/设备的系统上的恶意 pingsweep 扫描活动、telnet 流量和 HTTP 流量：

  • 搜索并调查 Omron FINS 流量超出标准规范和环境基线的证据。

收集、识别和调查包含 Omron API 命令的 Omron 设备的恶意 HTTP POST 数据。
