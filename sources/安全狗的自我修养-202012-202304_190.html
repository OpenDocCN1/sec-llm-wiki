GIMMICK 恶意软件袭击 macOS

2021 年底，Volexity 在作为其网络安全监控服务的一部分监控的环境中发现了入侵。Volexity检测到一个运行 frp 的系统，也称为快速反向代理，随后不久检测到内部端口扫描。该流量被确定为未经授权，系统，即运行 macOS 11.6 (Big Sur) 的 MacBook Pro，被隔离以进行进一步的取证分析。Volexity 能够运行Surge Collect以获取系统内存 (RAM) 并从机器中选择感兴趣的文件进行分析。这导致了恶意软件植入体 Volexity 调用GIMMICK的 macOS 变种的发现。Volexity 之前曾多次遇到过 Windows 版本的恶意软件家族。

GIMMICK 被用于攻击亚洲各地组织的中国间谍威胁组织Storm Cloud的针对性攻击。它是一个功能丰富的多平台恶意软件系列，使用公共云托管服务（例如 Google Drive）作为命令和控制 (C2) 渠道。新发现的 macOS 变体主要使用 Objective C 编写，Windows 版本使用 .NET 和 Delphi 编写。尽管使用的编程语言和目标操作系统存在核心差异，但由于所有变体使用的共享 C2 架构、文件路径和行为模式，Volexity 以相同的名称跟踪恶意软件。

图 1. GIMMICK 工作流程

这篇博文对 GIMMICK 的 macOS 变体进行了深入分析，同时也展示了 Windows 变体的特性和特点。Volexity 通过对受感染系统的内存分析发现了这个样本，并能够从内存和磁盘中恢复植入物。文件名和安装路径对于受害系统是唯一的，并且已以旨在与用户的工作职能相融合的方式进行配置。此外，GIMMICK 被配置为仅在工作日与其基于 Google Drive 的 C2 服务器通信，以进一步融入目标环境中的网络流量。

Volexity 能够从磁盘获取的文件的 SHA1 哈希是“fe3a3e65b86d2b07654f9a6104c8cb392c88b7e8”。

Volexity 与 Apple 密切合作，在其用户群中增加对 GIMMICK 恶意软件的保护。2022年 3 月17日，Apple 向 XProtect 和 MRT 推送了新签名，以阻止和删除 GIMMICK。 虽然默认情况下，用户可以通过验证“安装系统数据文件和安全更新”框在他们的设置中被选中来确认他们被自动保护（可以在 此处找到说明）。

启动和初始化

在 macOS 上，发现 GIMMICK 支持作为系统上的守护程序或由用户启动。如果 GIMMICK 由用户直接启动，而不是由守护程序启动，它会通过将包含内容的 PLIST 文件（类似于下面显示的内容）放到/Users/<username>/Library/LaunchAgents来安装自己作为启动代理。二进制文件、PLIST 和代理的名称因样本而异。在 Volexity 观察到的案例中，植入物被定制为模仿目标用户通常启动的应用程序。值得注意的是，Windows 版本的 GIMMICK Volexity 观察到没有设置自己的持久性的概念。

C2 协议

初始化后，GIMMICK 恶意软件的操作是高度异步的。以前为 Windows 编写的恶意软件变种使用程序内部的线程池技术来管理这一点，由 Delphi 的 System.Threading.TThreadPool 和 .NET 的 System.Thread 和 System.Action 提供。然而，macOS 变体使用 Apple 的Grand Central Dispatch (GCD)技术管理协议。此功能允许开发人员将任务分发到系统管理的线程池以供以后处理。这些任务被封装到称为块的自包含对象中它们被安排在调度队列上进行处理。GCD 的精确结构和实现细节相当复杂，超出了本文的范围；附录中提供了一些资源。

恶意软件中有三个自定义的 ObjectiveC 类来管理 C2 协议的关键方面：DriveManager、FileManager 和 GCDTimerManager。

DriveManager 有几个职责：

  • 管理 Google Drive 和代理会话。

  • 在内存中维护 Google Drive 目录层次结构的本地映射。

  • 管理用于在 Google Drive 会话上同步任务的锁。

  • 处理与 Google Drive 会话之间的下载和上传任务。

根据恶意软件枚举命令文件的方式，Google Drive 似乎填充了每个受感染主机的目录。此目录的名称因平台而略有不同。Windows 植入程序生成一个唯一的 GUID 作为其 ID 运行，而 macOS 植入程序使用 Apple 自己的硬件 UUID 来执行任务。

FileManager 管理本地目录层次结构，其中包含各个完成阶段的 C2 信息和命令任务。GIMMICK 的旧变体使用稍微不同的目录名称，但它们在最近的几个变体中保持一致。macOS 植入程序将此层次结构存储在应用程序主包的根目录中名为“MGD”的目录中。目录结构中的每个文件夹都被指定用于在通过 C2 进程时保存单一类型的文件。下表给出了所有目录及其用途的摘要。

姓名释义内容
时间暂时的写入文件的临时安全位置；没有调度代码正在检查此目录中的文件
C证书存储在初始化期间解码的 AES 加密凭证 JSON
e错误将错误日志存储为单个文件；错误报告为通常为四位数的不透明整数值
p代理存储由主机和端口组成的代理定义文件，由“：”分隔
你上传命令存储的 AES 加密命令结果等待上传
d下载命令存储挂起的下载命令文件，每个文件都包含要下载的命令文件的 Google Drive 路径
ds下载成功等待处理的已下载 AES 加密命令文件的存储位置
df下载失败失败下载命令的临时位置，直到可以重试或清除它们
l列表命令存储命令文件的待处理列表，指示从中下载命令的 Google Drive 目录
ls列出成功存储包含要下载的远程 Google Drive 文件路径的临时列表文件
如果列表失败失败列表命令的临时位置，直到可以重试或清除它们

并非所有 GIMMICK 变体都使用所有目录。例如，macOS 植入程序不使用“df”目录，它创建但不访问“lf”和“p”目录。

GCDTimerManager 管理各种 GCD 对象，确保定期为植入程序分派工作，并保存分派计时器的集合及其相应的块。该恶意软件创建了几个命名调度队列来管理特定的 C2 相关任务：

姓名目的
发送基本信息队列定期生成并向C2发送系统侦察心跳消息，包含以下内容：


  • 硬件 UUID

  • eth0接口的MAC地址

  • CPU 型号字符串

  • 操作系统版本字符串

list_request_queue在“l”目录中生成一个列表请求文件，其中包含格式为“/<HardwareUUID>”的路径
ls_cmd_queue从“ls”目录解析文件，并为每一行将相应的下载命令文件写入“d”目录
读取命令队列从“ds”目录解密和解析文件，并执行其中包含的命令，将结果保存到“u”目录
信用检查检查 Google Drive 会话是否超时，并在必要时重新进行身份验证
DriveClearTrashQueue定期删除 Google Drive 垃圾文件
DriveDownQueue解析存储在“d”中的文件，并将相应文件从 Google Drive 下载到“ds”目录
驱动上传队列上传存储在“u”目录中的反馈文件
DriveFailUploadQueue第二次尝试上传任何失败的上传项目。无论结果如何，第二次尝试都标记为成功。
文件列表队列解析存储在“l”目录中的文件，并为每个文件更新 Google Drive 的 DriveManager 目录映射，并在“ls”目录中生成要下载的文件列表

此外，GCDTimerManager 使用在初始化期间解码的静态配置信息来设置植入程序的工作时间，限制可能引起防御者注意的非工作时间连接。它从配置数据最开始的字符串中解析工作周期。此字符串以一组由连字符分隔的单位数字开头，后跟两个冒号字符和两个再次由连字符分隔的两位数字。第一组数字表示恶意软件活动的日期，第 0 天是星期日。第二组两位数表示活动小时数范围。取“1-2-3-4-5::00-23”的初始值，植入物将在工作日的上午 12 点到晚上 11 点处于活动状态——这是在图 4 中显示的配置 blob 中看到的第一个数据。

命令生命周期

由于恶意软件操作的异步性质，命令执行需要分阶段的方法。尽管各个步骤异步发生，但每个命令都遵循相同的步骤：

  1. 攻击者将加密的有效负载上传到 Google Drive。

  2. “list_request_queue”上的调度计时器触发。

  • 要写入“l”目录的新请求文件

  • “fileListQueue”上的调度计时器触发。

    • 从“l”目录读取列表请求

    • 从 Google Drive 会话更新 DriveManager 状态

    • 将列表文件拖放到“ls”目录

  • “ls_cmd_queue”上的调度计时器触发。

    • 从“ls”目录解析列表文件

    • 删除“d”目录中每个远程文件的下载命令文件

    • 从“ls”目录中删除列表文件

  • “DriveDownloadQueue”上的调度计时器触发。

    • 枚举“d”目录中的文件

    • 将命令文件的下载排队到“ds”目录

    • 下载完成后排队删除远程 Google Drive 文件和本地下载命令文件

  • “ReadCmdQueue”上的调度计时器触发。

    • 从“ds”目录读取和解密命令文件

    • 处理命令执行

    • 删除本地命令文件

    • 将加密的“反馈”文件写入“u”目录

  • “DriveUploadQueue”上的调度计时器触发。

    • 枚举“u”目录下的文件

    • 排队上传结果文件

    • 上传完成后排队删除本地结果文件

    命令和反馈

    命令以“ds”目录中的加密文件形式到达系统，一旦使用植入物的静态 AES 密钥解密，就会生成一个 JSON 对象。命令解析器仅读取四个 JSON 字段。

    姓名类型
    CMD 类型数字
    内容细绳
    参数细绳
    保存路径细绳

    虽然每个命令 JSON 都必须有一个 CMDType 字段，但所需的字段因命令而异。下表总结了可用的命令及其必填字段。

    枚举描述其他必需的 JSON 字段
    0传输基地系统信息没有
    1上传文件到C2参数
    2下载文件到客户端内容，保存路径
    3执行shell命令并将输出写入C2参数
    4设置客户端 Google Drive 计时器间隔参数
    5为客户端信息心跳消息设置客户端计时器间隔参数
    6覆盖客户工期信息参数

    对 C2 的反馈也采用 JSON 格式，其字段与命令非常相似。但是，所有反馈 JSON 对象都有一个额外的必填字段“uuid”，其中填充了设备的硬件 UUID。

    结论

    Storm Cloud 是一个先进的多功能威胁参与者，它调整其工具集以匹配其目标使用的不同操作系统。他们利用内置的操作系统实用程序、开源工具和自定义恶意软件植入物来实现其目标。利用 C2 的云平台，例如使用 Google Drive，增加了网络监控解决方案未检测到操作的可能性。再加上恶意软件仅在受害者工作日发出信标这一事实，这一点尤其正确。

    无论平台如何，GIMMICK 恶意软件家族的样本都相当庞大和复杂，部分原因是它们的异步设计复杂，例如所需的线程和锁定机制。移植此恶意软件并将其系统调整为新操作系统 (macOS) 所涉及的工作并非易事，这表明其背后的威胁参与者资源充足、熟练且多才多艺。值得注意的是，Volexity 只观察到 Storm Cloud 使用 GIMMICK（macOS 和 Windows）。但是，尚不清楚该恶意软件植入物是否由他们专门开发或以其他方式使用。

    为了通常防止类似的攻击成功，Volexity 建议如下：

    • 定期审核和监控持久性位置，例如端点 macOS 设备上的 LaunchAgents 和 LaunchDaemons。这可以通过 EDR 解决方案和/或使用BlockBlock和KnockKnock等免费工具来完成。

    • 监控异常代理活动和内部扫描的网络流量。

    • 确保 Apple 的 XProtect 和 MRT 已启用并在 macOS 系统上运行。

    为了防止这些特定的攻击成功，Volexity 建议如下：
