了解进程注入对于在 macOS 上的利用至关重要，因为访问控制的许多元素取决于应用程序的签名，尤其是嵌入式权限。有些权限不那么重要，而其他权限，尤其是 Apple 私有的权限，则非常强大。


在本模块中，我们将探索两种不同的技术，将动态链接库 (dylib) 注入应用程序。我们最终将利用它在应用程序的上下文中运行，这将为我们提供以前不一定拥有的权限。我们将在后续教程中讲到这些技术来攻击，例如 XPC 服务或隐私访问 (TCC)。


我们将从研究依赖于环境变量的代码注入技术开始。为了了解它的局限性，我们将练习深入研究 Apple 的源代码以了解 macOS 的内部结构。接下来，我们将介绍 dylib 劫持技术，这是实现进程注入的另一种方式。


DYLD_INSERT_LIBRARIES 在 macOS 中的注入

DYLD_INSERT_LIBRARIES 注入技术是 macOS 上非常古老且经典的技术。对于熟悉 Linux 系统的人来说，它类似于LD_PRELOAD方法。DYLD_INSERT_LIBRARIES 是一个环境变量，它指示 dyld 动态库加载器在主应用程序启动之前加载任何 dylib。加载的 dylib 将在我们所针对的应用程序的上下文中运行，这从攻击者的角度来看非常有用。


DYLD_INSERT_LIBRARIES 包含在 dyld 的手册页中：


DYLD_INSERT_LIBRARIES 这是一个以冒号分隔的动态库列表，在程序中指定的库之前加载。这使你可以通过仅加载新模块的临时动态共享库来测试平面命名空间图像中使用的现有动态共享库的新模块。请注意，这对使用动态共享库构建的两级命名空间images(镜像、模块)没有影响，除非还使用了 DYLD_FORCE_FLAT_NAMESPACE。


如手册页所述，该变量应包含要在程序启动之前加载的 dylib 列表，实质上是强制将 dylib 注入应用程序。


执行注入

我们将通过一个练习实战 DYLD_INSERT_LIBRARIES 技术。首先，让我们创建一个可以注入目标应用程序的简短动态库。该库将打印到标准输出并生成一条日志消息。


#include <stdio.h>#include <syslog.h>
__attribute__((constructor))static void myconstructor(int argc, const char **argv){     printf("[+]  haidragon dylib constructor called from %s\n", argv[0]);     syslog(LOG_ERR, "[+]  haidragon dylib constructor called from %s\n", argv[0]);}

让我们检查一下这段代码。属性((constructor)) 是 GCC 特定的语法，它指示编译器将下一个函数视为构造函数。当动态加载器加载编译后的二进制文件时，它将运行构造函数下指定的函数。函数的名称是任意的。我们的函数将打印到 STDOUT（标准输出）并创建一个日志条目，我们可以使用它来验证我们的代码是否已运行。


我们将使用 gcc 来编译动态库。-dynamiclib 选项会将文件编译为 dylib 而不是 Mach-O 可执行文件。-o 选项指定输出文件的名称。


让我们编译动态库。


gcc -dynamiclib example.c -o example.dylib

接下来，我们将在 C 中创建一个简单的 Hello World 应用程序。我们将动态库注入到该应用程序中。




#include <stdio.h>int main(){   printf("Hello, World!\n");   return 0;}

同样，我们将使用 gcc 来编译它：


gcc hello.c -o hello

为了设置要执行的应用程序的环境变量，我们需要在命令行中指定 DYLD_INSERT_LIBRARIES= 和 dylib 的路径。


让我们在有和没有注入的情况下运行它们。


haidragon@haidragondeMacBook-Pro ~ % ./helloHello, World!
haidragon@haidragondeMacBook-Pro ~ % DYLD_INSERT_LIBRARIES=example.dylib ./hello [+] haidragon dylib constructor called from ./helloHello, World!

清单显示了使用和不使用注入执行的应用程序。如果我们查看输出，我们会发现我们的 dylib 中的 printf 函数在主应用程序启动并打印“Hello World”之前被调用。


现实世界的应用程序，例如 MachOView：


haidragon@haidragondeMacBook-Pro ~ % DYLD_INSERT_LIBRARIES=example.dylib /Applications/MachOView.app/Contents/MacOS/MachOView [+] haidragon dylib constructor called from /Applications/MachOView.app/Contents/MacOS/MachOView...

与使用控制台应用程序相比，使用命令行监控日志输出对我们来说可能更方便，如下所示。


haidragon@haidragondeMacBook-Pro ~ %  log stream --style syslog --predicate 'eventMessage CONTAINS[c] "constructor"'

让我们分解上面的命令以更好地理解它。此命令在消息正文中记录所有包含构造函数字的事件消息。我们使用 stream 选项连续查看来自系统的日志， --style 指定格式， --predicate 是我们应用于流的过滤器。eventMessage CONTAINS[c] 将根据消息体的内容过滤事件，[c] 是为了不区分大小写。


一旦我们运行它，我们将收到类似这样的输出：


haidragon@haidragondeMacBook-Pro ~ %  log stream --style syslog --predicate 'eventMessage CONTAINS[c] "constructor"'Filtering the log data using "composedMessage CONTAINS[c] "constructor""Timestamp                       (process)[PID]    2021-01-15 08:35:14.505743-0600  localhost MachOView[94732]: (example.dylib) [+] haidragon dylib constructor called from /Applications/MachOView.app/Contents/MacOS/MachOView


这种技术对于注入来说非常方便，因为我们只需要一个dylib，并且只需设置一个环境变量，我们就可以在另一个应用程序的上下文中实现代码执行。下面我们将探讨这种技术的局限性。
