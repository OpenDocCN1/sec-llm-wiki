# 高级恶意PowerShell分析- 调试分析

恶意 PowerShell 脚本是当今最流行的威胁之一。有许多 APT 参与者使用 PowerShell 作为交付或迁移机制。商业恶意软件也使用 PowerShell 很长时间了。在许多情况下，Office 宏恶意软件使用 PowerShell 脚本进行进一步的攻击。MITRE ATT&CK 矩阵很好地总结了这些趋势。有使用 PowerShell 作为主要实现语言的PowerShell Empire和PowerSploit等攻击工具包。

如今，PowerShell 在攻击者中如此受欢迎的原因有很多。自 Windows 7 以来的最新 Windows 平台默认安装了 PowerShell。PowerShell 在与 Windows 子系统交互方面非常强大。大多数常见的恶意软件活动，如删除文件、运行文件以及与 C&C 服务器通信，都可以通过 PowerShell 轻松实现。一些攻击框架通过在内存上反射加载下载的可执行文件来支持无文件操作。在这些方面，PowerShell 是执行无文件离地攻击的完美工具。反恶意软件行业的传统防御机制真正专注于基于文件的威胁，在覆盖这些新的无文件趋势方面仍有很大的技术差距。

从攻击者的角度来看，PowerShell 的唯一问题是源代码很容易泄露。为了避免简单的分析和检测，他们投入了大量精力来混淆 PowerShell 脚本。他们还将脚本拆分为许多组件并逐个交付，在多次混淆的 PowerShell 执行后交付最终威胁。这些策略在许多情况下都非常有效。由于这些事实，在大多数情况下分析和理解基于 PowerShell 的威胁是非常耗时的工作。

通过本文，我们将分析使用混淆和有效负载拆分的最典型案例之一，并将讨论一种可以帮助分析师更有效地执行工作的新方法。

## 混淆的 PowerShell 代码

以下代码显示了通过Office Excel VBA 脚本传递的 PowerShell 威胁之一。沙盒技术可以很好地观察到这种威胁的行为。例如，通过any.run 会话，你可以观察 Excel 如何运行 PowerShell 脚本来运行进一步的攻击。在将混淆脚本设置为 cmd.exe 中的 Windows 环境变量后，将使用 PowerShell 实例。

![](../Images/eb8b454d70030124699eea6a3bf277d9.png)*\[Process tree \]*

PowerShell 脚本代码被严重混淆，手动去混淆这种代码可能需要人研究，然而人员要付出相当大的时间才能完全理解这些代码。

![](../Images/1f25f0a42c4d81133da2d0a3ebe75bae.png)

*\[严重混淆的 PowerShell 代码\]*

有许多元素使这个脚本很难分析。首先，它将 PowerShell 类和函数名称拆分为多个字符串，并动态组合它们。其次，它使用 base64 编码对下一阶段的脚本进行编码并随机化它们的顺序，以防止对脚本进行暴力破解。第三，它使用压缩来防止对编码的 base64 代码进行部分解码。此外，它使用多个变量在代码的不同位置拆分逻辑。

## 介绍 PowerShell 调试器

幸运的是，PowerShell 中嵌入了调试器功能。本文对使用 PowerShell ISE 的调试功能提供了很好的指导。可以使用 ISE 分析恶意 PowerShell 代码。但是，在大多数需要某种程度的自动化的情况下，自定义 PowerShell 调试器可能会更好地工作。

## 介绍 PowerShellRunBox

你可以将 PowerShell 调试器嵌入到独立程序中，并注册你自己的 StopEvent 回调来实现一些自动化功能。PowerShellRunBox该开源项目使用 PowerShell 调试为分析高度混淆的 PowerShell 代码提供了一些便利功能。我们将分享这个新工具如何帮助分析高度混淆的 PowerShell 代码。

## 混淆的 PowerShell 脚本概述

整体感染流程如下所示。它具有三个检查例程（黄色块），可确保意大利语言代码在Windows 语言环境中运行。

![](../Images/efed96f390257e56560812719cf804e0.png)

*\[恶意PowerShell脚本执行流程\]*

它使用 https://ipinfo.io/country 进行额外检查，以检查机器和网络的公共 IP 地址是否属于意大利。基本上，它具有多级语言包和地理定位检查，当它没有发现它在具有特定语言包的特定区域运行时，它不会下载下一阶段的有效负载。

这是动态分析的一个大问题。例如，通过像 any.run 这样的引爆服务运行的会话将不会完成，除非它在恶意软件所期望的非常特定的环境中运行。如果不分析 PowerShell 代码本身，您一开始就不会拥有这些信息。这可能是攻击者逃避动态分析的策略之一。

## 结论

我们完成了最复杂的恶意 PowerShell 脚本之一的调试会话。手动分析这些威胁代码需要大量的时间。了解 PowerShell 内部级别行为（如语言检查或隐写操作）的沙盒或引爆技术并不多。PowerShellRunBox可用于解决此问题，其它更多自动化功能 - 例如，自动循环检测和代码覆盖蛮力与自动变量修改可以看源码。
