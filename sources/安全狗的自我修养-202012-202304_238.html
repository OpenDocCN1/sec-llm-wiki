Frida 最近变得越来越流行，因为它可以方便地使用 JavaScript 语言安装钩子。我看到很多研究将 Frida 用于移动平台，但最近似乎 Windows 有更多的使用吸引力。我们正在研究安全研究人员可以在日常工作中使用的新方法。Frida 是我们认为可用于 Windows 逆向工程的工具之一。但是，在我们的测试过程中，我们发现符号查找功能是该工具更广泛使用的限制因素。我们进行了改进，现在可以在 Frida 12.9.8 中使用。我们非常感谢Ole André Vadla Ravnås帮助合并更改。

我们将简要介绍我们所做的更改，并将解释如何在现实世界的问题解决中使用改进的符号查找功能。

Frida 12.9.8 改进

基本上，Frida 使用 dbghelp.dll API 在 Windows 平台上查找符号。但它缺少的是使用符号服务器支持。我们添加了符号服务器支持并改进了在 Windows 中传递符号字符串。在较旧的 Frida 实现中，查找每个符号需要一些时间，因为它使用通配符模块名称来查找任何符号。现在您可以指定模块名称以加快符号查找速度。

New Frida 将附带 symsrv.dll 和 dbghelp.dll 以支持符号服务器，包括 Microsoft 符号服务器。

这些是我们在 Ole 的帮助下所做的更改。

  • Frida 12.9.8

    • Add load_symbols() and improve the DbgHelp backend

    • Migrate agent to new DbgHelp layout on Windows

符号查找：resolveName

Frida JavaScript API 在API 文档中有很好的描述。

使用 Frida 进行挂钩的第一步是找到目标函数。

如果函数是导出的，那么您只需调用 Module.findExportByName 方法，导出函数名称和 DLL 名称即可。

Module.findExportByName(dllName, name)


但是，如果函数没有被导出，例如只记录在 PDB 符号文件中，则可以调用 DebugSymbol.getFunctionByName 方法。在 Frida 12.9.8 中，您可以传递“DLLName!FunctionName”符号，以便在指定特定函数时更准确，并在定位它们时获得更好的性能。

有时，为模块加载符号可能会很慢，因为它可能来自远程符号服务器。因此，您需要调用 DebugSymbol.load 方法来启动符号的加载，以便我们加载最少数量的符号。

这是一个示例代码，它使用 Module.findExportByName 和 DebugSymbol 方法来查找任何符号化或导出的函数。它使用字典来缓存其发现以删除任何重复的作品。如果您要连接大量函数，这可以节省整体符号查找时间。

vbe.js

var loadedModules = {}var resolvedAddresses = {}
function resolveName(dllName, name) {  var moduleName = dllName.split('.')[0]  var functionName = moduleName + "!" + name
  if (functionName in resolvedAddresses) {    return resolvedAddresses[functionName]  }
  log("resolveName " + functionName);  log("Module.findExportByName " + dllName + " " + name);  var addr = Module.findExportByName(dllName, name)
  if (!addr || addr.isNull()) {    if (!(dllName in loadedModules)) {      log(" DebugSymbol.loadModule " + dllName);
      try {        DebugSymbol.load(dllName)      } catch (err) {        return 0;      }
      log(" DebugSymbol.load finished");      loadedModules[dllName] = 1    }
    try {      log(" DebugSymbol.getFunctionByName: " + functionName);      addr = DebugSymbol.getFunctionByName(moduleName + '!' + name)      log(" DebugSymbol.getFunctionByName: addr = " + addr);    } catch (err) {      log(" DebugSymbol.getFunctionByName: Exception")    }  }
  resolvedAddresses[functionName] = addr  return addr}


设置符号路径

在 Windows 环境下设置符号服务器有不同的方法，我们建议从命令行设置 _NT_SYMBOL_PATH 变量。Windows 调试器的符号路径对变量的使用有很好的描述。

下面将使用“c:\symbols”作为其本地符号存储来缓存微软官方符号服务器。

setx _NT_SYMBOL_PATH SRV*c:\symbols*https://msdl.microsoft.com/download/symbols
以下命令将让系统使用默认符号存储目录。
setx _NT_SYMBOL_PATH SRV*https://msdl.microsoft.com/download/symbols

显示调用函数

有趣的 API 之一是DispCallFunc 函数。该函数用于调用 COM 方法。通过监控这个 API，我们可以更好地了解恶意软件试图做什么。

该函数的原型如下所示。

HRESULT DispCallFunc(  void       *pvInstance,  ULONG_PTR  oVft,  CALLCONV   cc,  VARTYPE    vtReturn,  UINT       cActuals,  VARTYPE    *prgvt,  VARIANTARG **prgpvarg,  VARIANT    *pvargResult);

第一个参数 pvInstance 具有指向 COM 实例的指针，第二个参数 oVft 具有此函数正在调用的方法的偏移量。通过一些计算，您可以找到 COM 调用最终将调用的函数。

下面是这个函数的钩子，它将打印出实际的 COM 方法名称及其说明。Frida 具有反汇编指令的 API，在这种情况下非常有用。



function hookDispCall(moduleName) {  hookFunction(moduleName, "DispCallFunc", {    onEnter: function (args) {      log("[+] DispCallFunc")      var pvInstance = args[0]      var oVft = args[1]      var instance = ptr(ptr(pvInstance).readULong());
      log(' instance:' + instance);      log(' oVft:' + oVft);      var vftbPtr = instance.add(oVft)      log(' vftbPtr:' + vftbPtr);      var functionAddress = ptr(ptr(vftbPtr).readULong())
      loadModuleForAddress(functionAddress)      var functionName = DebugSymbol.fromAddress(functionAddress)
      if (functionName) {        log(' functionName:' + functionName);      }
      dumpAddress(functionAddress);
      var currentAddress = functionAddress      for (var i = 0; i < 10; i++) {        try {          var instruction = Instruction.parse(currentAddress)          log(instruction.address + ': ' + instruction.mnemonic + ' ' + instruction.opStr)          currentAddress = instruction.next        } catch (err) {          break        }      }    }  })}

结论

Frida 是我在 Windows 平台上使用过的最方便好用的动态分析工具。有用于高级逆向工程的WinDbg、OllyDbg和PyKD 。它们有它们的位置和用途。但是，对于真正快速和重复的分析工作，Frida 绰绰有余，并且具有强大的转储和分析程序行为的能力。使用 Frida 12.9.8，现在我们有了更好的符号处理，这将提高整体可用性和生产力。
