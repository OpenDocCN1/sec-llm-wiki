    前面写了几篇基于文件格式的注入，其实是同类型的静态注入，这篇文章主要讲的是在macOS系统中如针对一个正在运行的进程注入代码(shellcode或者模块)，然而这种注入就是叫动态代码注入，在windows中动态代码注入实现的方式大部分是远程线程注入，利用的api是CreateRemoteThread，msdn文档介绍如下图所示。

在linux中也有对应的动态注入，利用的api是ptrace,ptrace的介绍如下图所示。

同样在macOS中也有动态注入，其实macOS和linux系统都是一个祖先，都是类unix系统，但是由于ptrace这个函数功能实在太过强大，而大家都知道linux是开源的，macOS只内核开源。而ptrace又是一个3环的api接口，它能干的事实在太多了，因此macOS直接去掉这个接口，提供几个功能有限的api，如下图所示。

linux也是有这些类似的进程操作api，ptrace也可以操作，而macOS只有Mach原语这些有限的几个api(api还有各种权限限制。)，这里我们用到的api有vm_allocate、vm_protect、vm_write。

    现在我们开始写实现代码，思路是接收一个参数，这个参数是提供进程pid或者进程文件名，如下代码所示。

pid_t Injector::getProcessByName(const char *name){    int procCnt = proc_listpids(PROC_ALL_PIDS, 0, NULL, 0);    pid_t pids[1024];    memset(pids, 0, sizeof pids);    proc_listpids(PROC_ALL_PIDS, 0, pids, sizeof(pids));
    for (int i = 0; i < procCnt; i++)    {        if (!pids[i]) continue;        char curPath[PROC_PIDPATHINFO_MAXSIZE];        char curName[PROC_PIDPATHINFO_MAXSIZE];        memset(curPath, 0, sizeof curPath);        proc_pidpath(pids[i], curPath, sizeof curPath);        int len = strlen(curPath);        if (len)        {            int pos = len;            while (pos && curPath[pos] != '/') --pos;            strcpy(curName, curPath + pos + 1);            if (!strcmp(curName, name))            {                return pids[i];            }        }    }    return 0;}

第二个参数就是要注入的模块全路径，最后就是利用vm_*这些api实现进程注入(具体细节联系作者。)。这里还有一个地方要提下，就是macOS中使用这些api要root权限，我们测试的被注入进程是水果自带程序App Store,我们先启动它，然后用xcode附加上去查看模块，如下图所示。
