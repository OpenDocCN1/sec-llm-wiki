# G.O.S.S.I.P 学术论文推荐 2021-07-02

今天推荐的论文是来自CCS 2021的"Preventing Dynamic Library Compromise on Node.js via RWX-Based Privilege Reduction"。

![](../Images/1a8e3ca493fd44a8cd7958a3f474055b.png)

下图展示了在Node.js中，main程序通过引入serial程序实现（反）序列化。而攻击者可以利用serial程序，传入特定的代码实现RCE。为了解决此类问题，作者设计了MIR工具，MIR记录了代码中的库、库之间的调用以及库周围的库的RWX（read-write-execute）授权模型，以削弱此类注入攻击。

![](../Images/997330f7f0713eebba85e19e2cf0e94a.png)

下图是上述代码的权限模型。当攻击者想要利用serial覆盖写info时，会触发写警告，因为只有lg.info具有访问日志的权限，而非seiral；当想要利用serial检查内置代码时，会触发读警告，因为serial不具备此功能；同理，当攻击者想要利用serial访问全局变量时，会触发读警告。

![](../Images/f79a1fa622cdba988c2381ddc852a71f.png)

下面我们来系统的看一下MIR。首先是威胁模型：攻击者会将恶意的、精心构造的payload通过web接口、运行中的API或共同的接口传递给这些库，实现攻击。

其次是MIR的设计。

*   **权限模型和语言**。MIR利用DSL语言（domain-specific language）构建了一个权限任务模型来表示读写执行权限（RWX）。下图为核心权限模型。
    
    ![](../Images/64c8e4662b4e128065d6597cce569455.png)
    
    下图为上面例子的权限模型。
    
      
    
    ![](../Images/16dea09df8704b1f3604f448ac6be082.png)
    
*   **权限推理**。作者使用了程序内的、流敏感的、面向的数据流分析的静态分析方法。在每对控制流图进行遍历时，MIR会更新两个数据结构，一个是<API, 权限>对，一个是DefToAPI（如，当遍历x = require("foo").bar语句，将x与require.bar绑定在一起）。下图为MIR在更新数据结构时的转换函数。上述例子中main程序最终生成的分析结果为{(“serial′′, R), (“serial.dec′′, R), (“serial.dec′′, X)}。
    
    ![](../Images/812630b6064f09ee61141be9c96a2232.png)
    
    除了静态分析之外，作者使用了动态分析作为辅助，用于捕获所有的对第三方库的访问。  
    
*   **量化削弱权限**。在分析出程序每个库的权限基础上，为了更高的安全性，作者量化削弱了库的权限。作者为所有的权限设立了一个基本权限，并在此基础上设置了白名单。如上述例子，白名单仅为P(Ms,Mt ) = {⟨require,X⟩, ⟨serial.dec,X⟩}，否则权限将有P\_base (Ms,Mt ) = {⟨globals.\*, RWX⟩, ⟨fs.read, RWX⟩, ...}。
    
*   在执行过程中，MIR运行时组件将会强制执行预设好的权限。
    

最后，作者实现了MIR原型，并评估了1000多个库。结果表明：MIR能够防御61/63次对现实世界中易受攻击的包的攻击，(2)平均对每个库的攻击面缩小了143.48X，(3)Mir可以正确地推断出99%的访问，(4)每个库的权限推断平均仅需2.1秒，运行时执行开销为1.93%。
