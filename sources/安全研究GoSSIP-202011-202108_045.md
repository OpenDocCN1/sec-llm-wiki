今天给大家推荐的是USENIX Security 2021的一篇关于苹果AirDrop隐私安全研究的论文。文章出自SEEMOO，作者针对AirDrop协议中存在的隐私缺陷，引入了PSI协议来增强认证过程的隐私性，设计并实现了PrivateDrop。

![](../Images/c1092f4113c9f479796e6e0fc8b65beb.png)

Private Set Intersection(PSI) 协议简单来说，就是让拥有集合A的sender和拥有集合B的receiver，通过协议交换，计算出AB的交集而不泄露交集外的其他元素。作者开源了他们实现的PrivateDrop，其界面如封面所示，集成了原生AirDrop和PSI套件。

  

  

***AirDrop介绍***  

AirDrop相关的研究论文之前也有推荐过，这里大致介绍一下：AirDrop是苹果的文件共享服务，集成在所有的iOS和macOS设备上。这个服务基于AWDL和BLE，流程如图1所示，分为发现、认证、传输三个阶段。本文的研究着眼于发现和认证过程，设计并实现了图5的流程。

![](../Images/6162bbd4caa8195793e8e0db5aa544d9.png)

AirDrop的发现和认证过程是基于Contacts应用的，下文讨论“仅限联系人”的模式。具体来说，AirDrop采用电话号码和邮箱地址来识别联系人，这两项信息也是苹果验证的。  

  

**发现阶段：**sender发送包含自己ID短哈希的BLE广告包，receiver将这个哈希过的ID与自己的地址簿对比，若该ID是自己的联系人，则激活AWDL接口，并提供AirDrop服务信息。

**认证阶段：**sender和receiver用苹果签名的设备特定的证书 σUUID 和验证记录VRσ来相互验证身份，其定义为VR = (UUID,SHA-256(ID1),...,SHA-256(IDm))，VRσ = (VR,sign(σVR,VR),σVR)。完成认证后，sender的AirDrop界面就会出现receiver，可以选择对象传输。

  

## ***Contact ID泄露***

作者在AirDrop协议上发现了两个设计缺陷，攻击者能够利用它们来获取周围苹果设备的Contact ID。

**第一个设计缺陷在于输入空间小/可预测：**哈希难以掩盖电话号码和邮件地址。电话号码可以直接爆破，例如美国电话号码包含一个区号和7位数字，搜索空间仅10^7。对于邮箱，则可以字典攻击或是从数据泄露中生成email查找表。

**第二个设计缺陷在于认证阶段：**

*   恶意的receiver只需静候sender主动发送HTTPS POST/Discover消息，其中包含contact ID哈希和验证记录VRσ；
    
*   恶意的sender可以借助一些社会工程学（例如公司领导往往在职员联系人列表中），来收到来自receiver的HTTPS 200 OK回复，其中同样包含contact ID哈希和验证记录VRσ。
    

  

## ***PrivateDrop设计***

作者设计的目标就是利用PSI协议让sender和receiver在不泄露任何ID的前提下得到彼此地址簿的交集，交集不为空则说明互为联系人。这里的PSI协议需要满足两个要求：

*   仅在双方互为联系人时才披露验证记录；
    
*   仅在验证记录中包含对方已知的联系人标识符。

考虑到地址簿的大小通常远小于100k，因此使用公钥加密即可。而且需要能抵御恶意sender和receiver，同时不需要分发加密库。最后作者选择了Jarecki和Liu提出的基于公钥的PSI协议。进一步，如同4所示，通过对DO2（绿色部分）和DOS（橙色）部分的优化和交错执行，得到最后的设计（看似复杂，但是配合论文食用，还是能够消化的）。
