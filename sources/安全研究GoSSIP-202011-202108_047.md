# G.O.S.S.I.P 学术论文推荐 2021-06-29

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=Mzg5ODUxMzg0Ng==&mid=2247486468&idx=2&sn=fe0ba0ed0353d277b574db6725768256&chksm=c06022ddf717abcb5a95125d050261ba79828f8a249b91cba150c11e37d4d405a7b2cf04b9e2&scene=126&sessionid=1681404294#rd](http://mp.weixin.qq.com/s?__biz=Mzg5ODUxMzg0Ng==&mid=2247486468&idx=2&sn=fe0ba0ed0353d277b574db6725768256&chksm=c06022ddf717abcb5a95125d050261ba79828f8a249b91cba150c11e37d4d405a7b2cf04b9e2&scene=126&sessionid=1681404294#rd)

今天为大家推荐的是来自NDSS 2020的一篇关于内容安全策略的论文——“Complex Security Policy? A Longitudinal Analysis of Deployed Content Security Policies”。  

![](../Images/11cf9bbb26d146065c19a4ddfab5ff60.png)

内容安全策略(CSP)在2010年被Stamm等人提出，由浏览器执行的安全策略，主要是为了防御内容注入攻击。本文作者对CSP演化过程进行了深入研究，分析了CSP存在的问题以及在实际应用中开发者部署失败的原因。

  

作者首先利用Internet Archive获取了10,000个流行网站的快照，从中搜集CSP headers来研究CSP是如何发展的，以及CSP的采用和维护情况。

下图展示了采用CSP-only模式，report-only模式和both模式的网站数量随时间的变化。  

![](../Images/7e7a366ab9b037b4555231284a6620f8.png)

作者发现：

*   report-only模式能够使开发者在部署前对策略进行试验，但是这种模式远不如CSP-only模式流行，这说明开发者并没有在实际部署之前对CSP策略进行评估，这可能会导致宽松的CSP策略，从而在实际使用时无法防御攻击。
    
*   开发者很少采用both模式，这表明开发者可能感觉report模式较复杂，在实际当中并不经常使用。
    

  

作者统计了CSP的变化情况：

![](../Images/7ca2ebb54dfacbfb7631b3adff8cf402.png)

在许多情况下，网站每月需要更改数十次CSP策略，这表明CSP策略需要不断更改和维护，尤其是复杂的脚本白名单，需要开发者持续的维护。

  

作者将CSP策略分为了三类(相互可以重叠)：Script Content Restriction，TLS Enforcement，Framing Control。

![](../Images/43540b1124c6734b31c969bd165f984e.png)

在内容限制方面作者发现：

*   CSP的大量特性并没有被很好的使用，例如hash，nonce和strict-dynamic采用率不足5%。
    
    ![](../Images/084262b6f7d076d5a6fddefeba4c0121.png)
    
*   之前的研究表明排名越靠前的网站安全性越高，所以开发者在CSP中信任非流行网站会削弱网站的安全性。
    
      
    
    ![](../Images/04d34f11dfeb4b8f74b3cd288aaa9230.png)
    
*   可以实施白名单域名攻击：过期域名重新注册 ，拼写错误域名注册，IP地址控制等。
    
      
    
    ![](../Images/d6e9b47d817398b0a17465dd174ad85a.png)
    

TLS方面，作者在部署了upgrade-insecure-requests的网站例如wired.com，aol.com等发现仍然有一些HTTP资源的加载，这表明了upgrade-insecure-requests是非常有用的机制，超过70%的网站选择它来升级到HTTPS。

![](../Images/9686470ebc19475bc1e86f4d7167e57c.png)

在framing control方面，作者分析了CSP framing control策略和XFO的灵活性和有效性，以及二者在不同浏览器实现的不一致性。作者在USENIX Security 2020的文章“A Tale of Two Headers: A Formal Analysis of Inconsistent Click-Jacking Protection on the Web” 中对该现象进行了更加深入的分析，详见：[G.O.S.S.I.P 学术论文推荐 2021-03-15](https://mp.weixin.qq.com/s?__biz=Mzg5ODUxMzg0Ng==&mid=2247485215&idx=1&sn=1d68f0e432c9ab77ca4f3727c72572c4&scene=21#wechat_redirect)

[](https://mp.weixin.qq.com/s?__biz=Mzg5ODUxMzg0Ng==&mid=2247485215&idx=1&sn=1d68f0e432c9ab77ca4f3727c72572c4&scene=21#wechat_redirect)

  

从上述的分析可以看到，CSP策略较为复杂，CSP策略的安全部署对于开发者来说并不是一件简单的事情。作者进一步讨论了影响CSP成功部署的原因，例如第三方可能会侵犯CSP策略而网站依赖第三方，开发者认为framing control并不重要以及资源无法升级到HTTPS等。
