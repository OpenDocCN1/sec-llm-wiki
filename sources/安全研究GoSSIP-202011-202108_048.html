今天给大家推荐的是来自ICSE 2021的一篇关于修改过的开源软件重用识别的论文——"CENTRIS: A Precise and Scalable Approach for Identifying Modified Open-Source Software Reuse"。

软件开发人员常常会重用开源软件 (OSS) 来提高开发效率，但不安全的OSS组件也会造成漏洞传播等风险。目前识别目标软件中的OSS组件主要存在以下挑战：

  • 修改过的OSS组件。开发人员通常只使用OSS的一部分，或对部分源代码进行过修改。

  • 嵌套的OSS组件。一个OSS组件可能包含多个子OSS组件，可能会造成识别错误（将某个OSS组件识别为其子OSS组件）。

现有针对OSS组件重用识别主要包括以下两种技术：

  • SCA (Software Composition Analysis) 技术：现有的SCA技术都是假设重用的OSS几乎未经过修改，因此会产生漏报。

  • 代码克隆检测技术：现有代码克隆检测技术对于嵌套的OSS项目会产生误报。

本文作者提出了一种精确且可扩展的方法——CENTRIS，用来识别修改后OSS重用。CENTRIS旨在在源代码级别识别OSS组件，而不管OSS是全部还是部分在目标软件中重用。

CENTRIS主要包含两个过程：

（1）OSS组件数据库构建

如果只是简单地存储来自每个OSS的所有版本的所有函数，会使组件识别阶段效率极低。因此，如果多个版本共有的功能与目标软件只进行一次比较，可以极大的降低空间和时间复杂度。

作者首先对OSS组件数据库进行冗余消除：1）提取OSS所有版本（假设为n个）中的所有功能；2）创建n个bin数据库；3）当某个函数出现在i个不同版本的OSS中，将该函数及其版本信息、每个版本内的路径信息存储在第i个bin中。

作者利用所生成的n个bin来进行识别，这种方法能够减少不必要的比较，也能够提高可扩展性。

（2）识别目标软件中重用的OSS组件

接下来，CENTRIS识别目标软件中重用的OSS组件。

在此之前，作者将一个软件项目分为应用代码和借用代码两部分，其中借用代码是指重用其他OSS组件的部分，即第三方软件；应用代码指软件项目的其他部分。

作者分析了识别OSS组件产生误报，是由于目标软件中包含嵌套OSS，或该软件仅包含OSS借用代码。因此，作者提出了两个概念来减少识别过程中的误报：

  • Prime OSS：指不包含其他第三方软件的OSS。如果Prime OSS与目标软件存在大量相同功能，则认为目标软件使用了Prime OSS。作者利用公共函数的出现时间和相似性来判断Prime OSS。

  • Code segmentation：如果在组件识别中只考虑OSS的应用代码（除了Prime OSS），则不会因为第三方软件而产生误报。

作者实现了CENTRIS，将其应用于10,241个广泛使用的GitHub项目来对其识别准确率、可扩展性、冗余消除的效果进行了评估。结果表明，CENTRIS能够以 91% 的准确率和 94% 的召回率在每个应用程序平均不到一分钟的时间内识别出重复使用的OSS组件。此外，作者还发现修改的OSS重用是软件开发中的一种常见情况，其发生频率是一般重用的20倍。
