Session 10A: Program Security and Cyber-Physical Systems

SoK: Security and Privacy in the Age of Commercial Drones

论文关注的是无人机和当前社会的对立关系，即无人机本身可能遭到用户之外的方方面面的威胁（例如新闻报道过有人击落闯入自家领空的无人机），同时无人机也会威胁到社会民众的安全和隐私。作者针对无人机涉及的五个关键因素——无人机本身、FPV（first person view，用户视角）信道、GCS（Ground control station，控制台），飞手和服务器面临的安全攻击和提出的对应防御措施进行了总结，研究了社会民众面临的无人机威胁。

详细内容请阅读：G.O.S.S.I.P 学术论文推荐 2020-08-25 。

Session 10B: Web Attacks

Revealer: Detecting and Exploiting Regular Expression Denial-of-Service Vulnerabilities

论文对ReDos攻击进行了研究，在扩展的NFA (extended NFA，e-NFA)上对ReDos攻击进行了建模，提出了易受攻击的e-NFA 模式和相应的攻击字符串模式，并设计了REVEALER工具来检测此类攻击。作者评估了REVEALER的有效性，与其他三个最先进的ReDos检测工具进行了比较。

详细内容请阅读：G.O.S.S.I.P 学术论文推荐 2021-05-14 。

Session 11A: Malware and Attacks

Runtime Recovery of Web Applications under Zero-Day ReDoS Attacks

论文同样是对ReDos攻击进行了研究，作者设计了REGEXNET工具，REGEXNET基于DNN模型进行预测，能够快速分析并预测出Web请求是否会导致长时间的执行，当预测结果为恶意时，REGEXNET会将请求隔离到沙箱中执行，以保证服务器能够快速恢复。作者将其与HAProxy和Node.js集成在一起，并将REGEXNET与Rampart进行了比较，结果表明REGEXNET在标准化吞吐量方面显著优于Rampart。

详细内容请阅读：G.O.S.S.I.P 学术论文推荐 2021-05-21 。

Session 11B: Mobile Security 2

Happer: Unpacking Android Apps via a Hardware-Assisted Approach

针对Android平台上加壳保护的应用app的安全分析，系统性的研究工作最早发表在2015年的ESORICS和RAID安全会议上：由香港理工大学罗夏朴教授研究团队和我们G.O.S.S.I.P分别设计的DexHunter和AppSpear系统，有效地对抗了当时就已经非常流行的应用加固保护技术，使得那些使用加固技术逃避恶意代码检测的app没法继续逍遥法外。随着Android系统的一步步进化，我们的AppSpear系统也不断升级，支持ART且能够处理更多的加固方案；同时后续的一些新型系统如PackerGrind、DroidUnpack、DexLego和TIRO也被研究人员设计出来以对抗更为复杂的加固保护。但是这些系统都存在一个通病，即如果加固的dex代码在运行时并不是一次性解密释放，而是按执行的需要解密，那么所有的脱壳方法都没法完整地恢复原始的dex字节码。

因此，在今年的SP会议上，来自多个研究团队的研究人员一起攻关，设计出了名为Happer的硬件辅助脱壳系统，可以全面满足作者所期望的三种功能指标（Effectiveness，Extensibility，Adaptivity）

在和以往学术界提出的其它分析系统的对比（下图），可以看到Happer的优势非常明显：

Happer的主要特色是其利用的ARM处理器的两类硬件特性：Embedded
Trace Macrocell（ETM）和 Hardware Breakpoints（HBRKs）。通过运用ETM机制，Happer可以透明记录代码运行的所有指令，不容易被反调试机制发现；通过使用HBRKs，Happer可以在特定的系统函数被调用时中断并获取相关参数。

尽管Happer有很多优点，但是我们注意到其实它还是只能捕获所有那些被释放到内存中的解密后的字节码，如果被加壳保护的字节码没被执行到，Happer目前也无法通过分析或强制执行令其解密

Session 12A: Web Security

Journey to the Center of the Cookie Ecosystem: Unraveling Actors’ Roles and Relationships

用户跟踪一直是大众关注的焦点问题，Web cookies在其中扮演了重要的角色。之前对于cookies的研究难以捕获到不同组织的代码片段之间的关系，这会导致以下问题：

  • 网站的拥有者忽略cookies的创建者和cookies所经过的不同的参与者。

  • 之前研究的只是第三方cookies，而这只是冰山一角。

  • 两个参与者可能在同一网站创建同名cookies。

  • 之前的研究考虑的是cookie在双方之间的共享，而在实际中，包括三个参与者：创建cookie者，获取cookie者和接受cookie者。

所以本文的研究目标是捕获cookie整个生命周期，揭示cookie生态里无数参与者之间复杂的关系网络。

作者引入ghosted first-party cookies，例如h提供JS代码来创建cookie，而该cookie作为网站W的一部分。根据cookie tree来创建creation chains和sharing chains，来捕获不同实体和行为之间的依赖关系。主要角色有：cookie创建者（例如w，a，d等），中间人（例如a，c对于h），发送者（发送cookie，例如a，b等），接收者（接受cookie，例如f，i等）。

作者基于上述思想，实现了cookie分析框架，对1M网站进行了分析。

有52.45%的网站存在至少一个cookie共享或碰撞。28M的cookies是ghosted cookies，即使用户禁止第三方cookies，这些first-party ghosted cookies也仍然有可能继续追踪用户。

作者进一步分析了cookie生态系统中主要的参与者。

通过cookie链来揭示各个组织之间的cookie传递。

总的来说，本文使用cookie分析框架对大量网站和cookie进行了分析，展示了cookie生态系统的复杂性。由于这种复杂性，数据保护的立法并不能保证用户隐私不受侵犯，而这种细粒度的分析可以帮助检测出试图违反规则的参与者。本文也列举了大量的例子，通过这篇论文，读者也可以比较全面地理解cookie生态系统。

Detecting Filter List Evasion with Event-Loop-Turn Granularity JavaScript Signatures

内容过滤器一般使用源的URLs来对资源进行辨识，如果URLs被识别为恶意的，过滤器会对资源进行阻隔。然而在当下，攻击者可以通过改变URLs或域、将代码与良性代码捆绑或内联页面代码来避免被检测。在本篇论文中，作者通过构建一个系统，该系统可以生成为执行的JS代码生成与隐私和安全行为相关的签名，以代替URLs解决上述问题。

首先作者描述了构建该系统的三个难点：

  1. 如何及时捕获JS DOM和Web API操作带来的变化？

  2. 如何定位带来变化的原始代码？

  3. 如何定位需要被签名的JS代码？

为了解决上述问题，作者提出了以下四个解决方案。

  1. 作者使用了扩展的PageGraph技术，准确地将DOM修改和Web API访问归为负责的JavaScript代码单元。

  2. 对于给定的固定段的代码，枚举确定性发生的事件，并排除在不同页面执行的事件。

  3. 提取每个事件循环的直接和下游活动，以及确定性行为的枚举，确定每个JS单元在每个事件循环期间的行为。为了提高效率，作者只对涉及到隐私的行为进行签名。对于提取出每个子图，系统会生成一个散列表示。

  4. 处理提取的签名，解决可能的歧义。

最后，作者爬取了Alexa 100K的页面，并为已知恶意脚本的事件循环生成签名，作者使用这些签名来测量攻击者逃避过滤器的频率。作者为EasyList和EasyPrivacy拦截的11212个脚本中构建了1,995,444个签名。作者发现了3589个脚本托管了已知有害代码，但它们被过滤列表漏掉了，这将会影响到12.48%的测量网站。

Reading between the Lines: An Extensive Evaluation of the Security and Privacy Implications of EPUB Reading Systems

论文深入讨论了97个电子书阅读系统的安全与隐私问题，发现大部分系统并没有考虑EPUB设计中的安全要求，在电子书被恶意构造的情况下，往往会泄露运行平台上的用户数据（例如平台上其它文件的内容）。作者针对EPUB安全测试设计了一套半自动化的分析，对各个平台设备进行了安全审计。

详细内容请阅读：G.O.S.S.I.P 学术论文推荐 2020-09-25 。

Session 13B: Dynamic Analysis

A Novel Dynamic Analysis Infrastructure to Instrument Untrusted Execution Flow Across User-Kernel Spaces

论文针对恶意代码检测，提出了一种新颖的动态分析方法Execution Flow Instrumentation (EFI)。该方法将analyzer的执行流与检测目标的用户、内核模式的执行流选择性地相交织，克服了代码插桩和基于硬件的事件捕捉方法的不足，通过在有无基于OASIS的EFI的guest中运行LMbench工具评估了EFI对guesy kernel的影响。

详细内容请阅读：G.O.S.S.I.P 学术论文推荐 2020-10-13 。

DynPTA: Combining Static and Dynamic Analysis for Practical Selective Data Protection

随着控制流劫持攻击的缓解措施被广泛部署，攻击者逐渐关注针对内存破坏漏洞和信息泄露漏洞的data-only attack。在一定的条件下，通过破坏一些数据仍然能达到劫持控制流的目的。数据泄露同样会带来很大的安全隐患，例如secret server keys、用户隐私信息等。近年来出现的瞬态执行攻击同样可以用于敏感信息的泄露。

虽然各种针对于数据泄露攻击的缓解措施被提出，从保护思路是可以主要分为缓解memory corruption bugs的方案以及选择性的保护部分数据的方案。前者通过memory safety、dataflow integrity等方式消除攻击原语，但是这些方案通常会带来很高的性能开销且unscalable，即很难应用在一些复杂的real-world程序上，而且无法抵御瞬态执行攻击。后者则是通过权限隔离、安全执行环境、沙箱、细粒度内存隔离等方式有选择性的保护程序中的一部分数据。然而这些技术需要对代码进行较大规模的重构，对于较大规模的程序而言是一个挑战。

考虑到选择性保护数据方案的实用性，近年来的一些方案选择让开发者在源代码中对security-critical的变量进行标记，随后在编译时对这些被标记的变量进行保护。具体的有Datashield、Glamdring、Selective in-memory encryption等方案。

为了高准确度（减少插桩带来的开销）、合理的复杂度（能够应用于较大规模程序的分析），作者提出了DynPTA，结合静态程序分析和动态数据流追踪（DFT）技术使得被标记的数据在内存中一直处于加密状态。

作者基于LLVM实现了DynPTA并将其成功应用于Nginx with OpenSSL, Apache Httpd, and OpenVPN，之前的实验。Nginx with OpenSSL的开销为19.2%，MbedTLS的开销仅为4.1%（13% for in-memory encryption, 35% for DataShield）。作者使用Heartbleed漏洞、Spectre-PHT、Spectre-BTB以测试DynPTA保护的有效性。

Example

举一个例子来说明DynPTA对敏感数据保护的优势，指针ptr1可能指向的内存对象为pts(ptr1) := {mem1, mem2, mem3, mem4}，pts(ptr2) := {mem3, mem4}。

如果仅用来静态分析的结果，则如（b）所示。虽然理论上只需要对真正的敏感内存mem4进行加解密，但是由于没办法确定ptr1、ptr2运行时指向的内存对象是否敏感，即ptr1、ptr2可能指向敏感内存对象，故只能将ptr1、ptr2指向的所有内存对象均当作是敏感内存对象来处理。对ptr1、ptr2所指向的内存对象进行写入/读取时均需要进行加/解密。从而导致开销急剧上升。

通过借助动态数据流追踪技术，DnyPTA可以确定ptr1、ptr2指向的是否为敏感内存对象，因此可以选择性的加/解密：当ptr1、ptr2指向敏感内存对象时进行加解密，否则正常读取写入。

Design

DynPTA分析的主要流程为：

  • 通过开发者的标注，识别出初始敏感内存对象集合

  • 使用Steensgaard’s指针分析算法并结合上下文敏感堆建模方式确定访问敏感内存的内存操作指令集合

  • 对内存操作指令进行进一步分析，以找出从初始敏感内存对象到其他变量的value flow

  • 对上述识别出的可能操作敏感内存的指令进行插桩，以在运行时通过DFT判断其是否读/写敏感数据，若为敏感数据，则在使用前对其进行加/解密。

DICE: Automatic Emulation of DMA Input Channels for Dynamic Firmware Analysis

论文主要解决的技术问题是在嵌入式固件动态分析（模拟执行）中，如何处理Direct Memory Access (DMA) 。作者设计了一个名为DICE的解决方案，其核心思想是对嵌入式设备上五花八门的外设进行抽象，在固件中识别输入输出并将其模拟成同一类DMA input channel，用来解决固件分析中输入输出指令无法处理的情况。作者分析了5家vendors的设备，其中包含了9类DMA controllers，使用DICE能够检测出其中33个DMA input channels（总共有37个），而误报率是0。

详细内容请阅读：G.O.S.S.I.P 学术论文推荐 2020-07-24 。

Session 13C: Cryptography 2

CRYLOGGER: Detecting Crypto Misuses Dynamically

我们在G.O.S.S.I.P 学术论文推荐 2020-07-09这一期曾经为大家介绍了来自哥伦比亚大学的研究人员发表的关于密码学误用的研究论文中。该论文采取了与我们G.O.S.S.I.P在多篇论文中提出的研究思路一致的策略：通过动态分析来精确发现密码学误用问题。作者整理了26条密码学误用规则，并设计了CRYLOGGER这一动态密码学误用检测系统，专门针对Android和Java代码进行安全检测。

然而我们不得不说，在这篇论文公开之后，经过仔细的阅读，我们发现它仅仅是采用了动态追踪和分析，工作原理并不复杂，其主要特色只在于如何搜集整理更全面的rules：作者研究了很多已有的工作，整理了一个全面的列表

尽管作者发现了许多Android app中的密码学误用问题，但是我们作为这个领域的专业研究团队，不得不说这篇论文有失IEEE SP的技术水准，同时在论文中还出现了巨大的错误：作者自己研究Java代码，就张冠李戴把我们的K-Hunt系统也归结为 “K-Hunt detects badly-generated keys, insecurely-negotiated keys and recoverable keys by analyzing execution traces of Java programs”，这简直是闹了个大笑话呢！（我们去年就已经给第一作者邮件指出错误并希望其改正，但是作者似乎已经忘记了自己曾经做过这项研究工作了）
