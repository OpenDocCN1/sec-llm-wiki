今天给大家推荐的是一篇来自Usenix Security 2021的关于漏洞检测的文章--“Understanding and Detecting Disordered Error Handling with Precise Function Pairing”。

程序运行会遇到形如内存分配失败的错误，代码中会利用错误处理（error-handling）的方式来处理。在实际的错误处理中，程序会执行一系列清理操作，例如释放内存或者减小引用计数。错误处理代码本身也可能出现问题，进而导致安全问题。

本文作者指出，以下的处理模式可能会导致安全问题：

  1. 以错误顺序进行清理操作

  2. 重复进行清理操作

  3. 缺少正确的清理操作

针对上述问题，本文作者总结了一种关于错误处理代码的bug类别，称之为Disordered Error Handling (DiEH)。

在此基础上，作者实现了名为HERO (Handling ERrors Orderly) 的DiEH漏洞自动化检测工具，并对Linux Kernel，FreeBSD，OpenSSL进行了试验评估，最终发现了239个DiEH bug。

作者分别将正常的资源申请函数和与之对应的资源清理函数称为leader function和follower function。并在此基础上提出了error-handling stack的概念，用来表示在不同阶段代码进行出错处理的执行流程。例如下图表示的分别是第4、7、13、17行的函数执行出错时，代码的执行流程。

基于上述概念，作者提出了检测DiEH漏洞的方法：

  1. 识别函数内的error-handling struct并区分正常路径和出错路径；

  2. 利用相邻error-handling stack的增量，识别不同的leader function以及与之对应的follower function，并将其称之为function pair；

  3. 将2作为先验知识，收集不同函数内的leader function列表，并推测与之对应的follower function列表。最终与代码中实际的follower function列表进行对比，不匹配时表示存在潜在的DiEH；

  4. 最终利用一系列方法，过滤第3步结果中无害或者无法触发的DiEH bug，得到最终的报告结果；
