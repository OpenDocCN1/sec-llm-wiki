大家好，今天我们推荐的是来自USENIX Security 2021的一篇论文—— “Sharing More and Checking Less: Leveraging Common Input Keywords to Detect Bugs in Embedded Systems”




这篇文章由我们上海交通大学网络空间安全学院陈力波老师、蔡洤朴、薛质教授等师生和奇安信技术研究院王衍豪等安全研究员、宾夕法尼亚州立大学胡宏助理教授、清华大学张超副教授、段海新教授联合发表。研究人员基于前后端的共享输入关键字，设计实现了一种新颖的嵌入式系统漏洞挖掘方法SaTC (Shared-keyword aware Taint Checking)，并实际应用于IoT设备漏洞挖掘中，取得了不错的效果。


首先，作者展示了一个由前后端共享关键字触发的命令注入漏洞：

图中左侧JS代码中的deviceName关键字同时出现在右侧的后端二进制执行体中，并导致了命令注入的安全漏洞。在这个发现的基础上，作者通过在实际物联网设备中进行动态测试，用于验证前后端共享关键字的情况是否具备普遍性。

通过对上图中所示5个品牌的10个真实设备的测试，作者验证了平均92.4%的前端数据包中内嵌的输入参数名字会出现在后端执行体中。因此，作者提出可以通过提取前后端共享关键字来实现后端有针对性的污点分析方法,即共享关键字感知的污点分析SaTC，提高执行效率和精确性，并设计实现了该方法的原型系统，包含输入关键字提取（Input Keyword Extraction）、输入引入点识别（Input Entry Recognition）、输入敏感的数据流分析（Input Sensitive Data Flow Analysis）三个部分，总体架构如下：

  1. 输入关键字提取模块
    通过在HTML、JS、XML等配置文件中，利用正则匹配、AST提取输入各类对象的id、name、value等可能用于传递参数的属性值，并且应用多种类过滤规则，得到输入相关的关键字集合，再和后端执行的字符串进行匹配，定位相应边界服务的二进制文件（例如web服务对应的*.cgi、httpd、 goahead等）

  2. 输入引入点识别
    在后端执行二进制定位对上述匹配关键字的引用位置，并且应用启发式方法扩展类似上下文调用的其他输入关键字，这些关键字并没有出现在前端文件中，但同样会导致安全漏洞，如图中所示的“usbName”关键字并没有出现在前端的任何文件中：
    此外，通过定位NVRAM配置、ENV环境变量的相关函数操作，获取多个二进制之间数据传递的输入引入点，从而可以对不同进程之间的通信数据进行跟踪，如图中所示的“url_filter_mode”变量：

  3. 输入敏感的数据流分析
    在前端输入关键字的支撑下，作者通过静态分析方法得到输入引入位置到sink function的敏感路径sensitive path集合，在此基础上应用指令层次的粗粒度污点分析方法，并且在三个方面对污点分析和符号执行进行优化：

  • 在污点分析中将函数调用分为summarizable、nested、general三类函数，其中对于污点数据参与的非叶子调用函数（即nested类函数）的处理是直接通过污染返回值或者参数实现污点传播，这个策略平衡了污点分析的效率和精确度，同时在函数摘要的支持下实现从引入点到sink function位置的符号执行，判断触发安全漏洞的路径执行条件是否存在。

  • 在符号执行的路径探索中，通过合并同一个输入引入点的sensitve path集合中的重复路径，将符号执行对象从单一call trace合并为call tree，从而将路径中调用的函数分为Guiding Function和Sink Function两个集合:
