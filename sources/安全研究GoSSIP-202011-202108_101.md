# G.O.S.S.I.P 学术论文推荐 2020-04-23

2018年CCS会议上，我们在binary code analysis这个session上有幸结识了好几位杰出的华人研究人员，其中一位是专注于Windows平台代码脱壳研究的程斌林老师。时隔三年，程老师和合作者又为我们带来了代码脱壳研究新作，今天我们就为大家介绍这篇USENIX Security 2021的论文：

![](../Images/61540ba90a783f3b5141d3738fe7bdff.png)

在这篇论文中，作者利用了处理器的硬件特性，设计了一款名为API-Xray的脱壳工具，这款工具的核心竞争力是基于BTS和NX bit等硬件辅助特性支持的Hardware-Assisted API Micro Execution。其核心目标是实现更为通用且能够对抗恶意代码的import table（IAT）重建，从而帮助分析人员实现对加壳代码更为全面的理解  

  

![](../Images/874791a63efe87ec40c184c00fc16066.png)

  

API-Xray工具的详细工作流程图如下所示，其信息搜集跨越了处理器、内核和用户态三层，在各个层面上获取需要的信息，并通过对已有的加壳保护技术的总结，判断哪些信息标志了API调用。同时，作者引入的一种轻量级执行技术——API Micro Execution，只针对trampline code释放API调用信息进行执行，从而获取相关的API信息进而恢复调用表。  

  

![](../Images/87b1e0663a851f83a2c9a18c0be85adf.png)

  

  

  

通过对常见的packer中的trampoline code进行总结，作者列举了常见的API调用混淆方案：

![](../Images/5131c59de9d69b9405ea3b080d7d8303.png)

  

![](../Images/67b44feef2d2c684677066403fc0ba68.png)

  

作者比较了API-Xray和以前的相关工作，可以看到API-Xray在处理更为复杂的控制流转移（例如从host程序到trampoline，再到反调试代码后才进入API调用的情况）具有明显的优势：

  

![](../Images/94f9dc5f879c9aca09150c180f489175.png)

  

接下来作者继续比较针对现在主流的加壳工具，API-Xray能在恢复API方面做到什么样的程度，从下表可以看到，即便那些使用了多种API混淆技术的壳（例如Obsidium和Armadillo），API-Xray都可以100%搞定，而此前的相关工作均没有办法做到如此完善：
