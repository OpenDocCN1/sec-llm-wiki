不知大家是否对近期某链安的大新闻有所耳闻，我们安全研究者还是专心搞安全吧。言归正传，今天给大家推荐的是来自USENIX Security 2020的一篇研究以太坊智能合约安全的论文。

区块链用户可以借助智能合约在交易中执行自定义的计算逻辑，但同时，这种自定义的计算逻辑的设计和实现也存在很多漏洞。针对智能合约的检测，目前大多漏洞检测工具主要从合约的二进制文件入手，很少有针对与交易执行的信息进行漏洞分析的工作。

本篇文章提出了TxSPECTOR方案，尝试从交易的信息入手进行攻击检测，表1的比较就可以显示出这个工作的特点。从上层来看，本文的方案重现历史交易，记录以太坊二进制级别的trace，然后将控制信息和数据之间的联系编码成逻辑关系。同时，本文方案允许用户自定义用于检测攻击的规则。

如图1所示，TxSPECTOR包含了以下四部分：

  1. Trace Extractor 在EVM中执行以太坊交易，并将执行过程中的二进制级别的信息记录下来。每个二进制级别的信息都是一个三元组{<PC>;<OPCODE>;<ARGS>}；

  2. Execution Flow Graph Generator(EFG Generator)将会把执行过程中的控制流和数据流信息转换成EFG；

  3. Logic Relation Builder首先解析EFG，转换成IR以便于后续分析，然后通过定义逻辑规则，提取表示交易语义的逻辑关系。最后将逻辑关系存储在数据库中；

  4. Attack Detector 根据用户自定义的查询规则作为输入，查询逻辑关系数据库。如果检查到攻击的存在，将会输出详细的攻击信息。


本文利用此方案去检测三类以太坊攻击（重入攻击、未检查调用攻击和自杀式漏洞）来评估该方案的性能。具体来说，本文对9,661,593份交易进行检测，有336,909份（3.5%）运行超时。对于剩余的交易进行检测，有3357份（0.04%）被标记为有此漏洞。结果证明本文方案能有效的检测出交易中的攻击信息，同时也检测出了对应的智能合约的漏洞。同时，TxSPECTOR还与四个工具进行了对比，如表3、4所示。


本文在最后也展示了如何将本文方案用于对交易的取证分析，并提供了可以用于检测其他攻击的检测规则。
