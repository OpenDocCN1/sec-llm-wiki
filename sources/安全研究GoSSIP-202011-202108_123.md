今天给大家推荐的是来自NDSS 2021的一篇论文—— "On the Insecurity of SMS One-Time Password Messages against Local Attackers in Modern Mobile Devices"。这篇文章中，作者总结了Android和iOS上，应用程序访问用户手机上短信消息中一次性口令的三类途径，并分别分析了恶意程序利用各类途径，非法窃取一次性口令的方式。

![](../Images/bf35576719ff96d86bcb6d9ab4c0fba8.png)

**包含一次性口令（One-Time Passwords，OTP）的SMS（Short Message Service）消息**被广泛应用于身份验证中，其基本验证流程如下图所示。  

![](../Images/cf9954d1eea1373757c64eabf390689f.png)

作者依据访问OTP过程中，所需要的**用户交互类型**，将应用程序访问OTP的方式分为了三类：其一，methods requiring per-message user interaction，每一次OTP的获取，都需要用户的交互操作；其二，methods requiring SMS-related permissions，需要用户手动一次性为该应用分配SMS相关权限；其三，fully-automated methods that do not require user interaction，应用程序直接使用“**Modern SMS API**”，无需用户的参与。  

*   针对第一类途径，作者提出，恶意应用可以通过欺骗用户窃取到OTP，并进行了用户研究实验。
*   针对第二类途径，作者提出，恶意应用可以通过绕过操作系统限制和绕过应用市场限制窃取到OTP，并进行了实验验证。
*   针对第三类途径，作者重点研究了Android系统中引入的三种“Modern SMS API”：**SMS Retriever**、**SMS Token**和**SMS Token+**，分析了它们的认证过程和存在的安全问题。
*   针对SMS Retriever，作者提出，该API在设计上是安全的，但常被开发人员不安全地使用——很多开发人员将**哈希值的计算过程**放在了**应用程序端**进行，再由应用程序端发送给服务器端，而该计算过程本应被放在**服务器端**进行。

![](../Images/5d5c4b26feb2ba6bbfd3c0d998c08583.png)

*   针对SMS Token和 SMS Token+，作者提出，该API在设计上就是不安全的，并且已将相关问题反馈给了相关单位。

![](../Images/c612313638750622216d04b6c4e92c85.png)

*   此外，作者还提出了现有“**Modern SMS API**”存在的其他问题，包括SMS Inbox管理不当、SMS Retriever 中哈希算法强度不足等。
