# G.O.S.S.I.P 学术论文推荐 2021-03-25

2021年AsiaCCS会议的第二批录用论文中，有一篇关于进程内隔离的研究文章引起了我们的关注：来自德国CISPA的两位研究人员介绍了一种将进程主要代码和其使用的库进行模块间隔离的技术

  

![](../Images/416ebeda5a63a7f87365c7f20a50f510.png)

  

作者设计了名为Cali的系统，能够自动将一个程序和其使用的库进行隔离，其核心思想是借助Program Dependence Graph (PDG)来分析哪些内存被主程序和库共享，然后将其余的内存进行隔离，让库代码能访问到的资源最小化，从而减少攻击面。

  

Cali并不是第一个提出程序内隔离想法的系统，或者说，已经有非常多的研究关注这个方向并且产生了大量成果，Cali的作者因此对一些系统和技术进行了总结并和Cali进行了对比（如下图所示）

  

![](../Images/763522a83e4ba76cefed8dc805aecfda.png)

Cali的isolation非常朴实无华，它对主程序和库的代码进行分析，标记出所有交互调用的点，然后将原有的库函数调用进行重写，用一个wrapper来封装并管理库函数调用过程中存在的内存传递，这样就可以让隔离机制几乎不需要依赖任何特定的硬件或平台特性就可以实现。

  

![](../Images/5a756cb78390a09892ae74bf9e34c579.png)

  

Cali还为所有的库建立了一个称为compartment的隔离环境，在其中运行库代码，限制它们可访问的资源。实际实现中，Cali修改了nsjail（https://nsjail.dev/）这个Google开发的 process isolation tool 来帮助实现compartment

  

实际上Cali面临的最困难问题是如何开展精确的程序分析来确定哪些部分内存需要（或者不需要）隔离，这部分的设计也是Cali论文中的大头，感兴趣的读者可以参考论文的第五章，阅读其中的很多有意思的细节。

  

最后，作者对Cali进行了评估，实验对象包括Ghostscript, OpenSSL, SQLite三个著名的三方库以及它们在ImageMagick，socat和Filezilla工具中进行隔离时的安全性和运行性能。
