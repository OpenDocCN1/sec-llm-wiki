# G.O.S.S.I.P 学术论文推荐 2021-03-03

今天给大家推荐的是来自ACSAC 2020的一篇研究ROP AEG（Automatic exploit generation）的论文。通常AEG依赖fuzzing或symbolic execution，但这篇文章的工作则另辟蹊径，可以参考一下其思路。

![](../Images/55b9152a5bd620c125bd376c916f1af2.png)

这篇文章针对的是ActionScript Virtual Machine (AVM)这类language VM（LVM）。据作者调查，近五年来，有700多个AVM相关的漏洞披露，其中约八成的漏洞能通过ROP实现任意代码执行。因此其AEG研究的对象也就是AVM漏洞的ROP攻击脚本的自动生成（严格来说是semi-automatic）。

  

对于LVM的AEG，通常使用的fuzzing或是symbolic execution都有各自的缺陷：fuzzing由于其test case的生成是依赖随机变换的，因此要生成语法有效的输入是困难的；符号执行则会面临老生常谈的路径爆炸问题。但很多研究也在改进这两种方法，例如fuzzing中引入一些语料或是预定义的模式进行辅助。

![](../Images/e2ab88735855447a8807c065e37bf8de.png)

作者则是采用穷搜法（我寻思fuzzing也是吧），设计了GuidExp，整体方法结构如图2所示。给我的第一感受就是：这不就是个弱化版fuzzer吗？不断循环“构造攻击脚本+测试验证“的过程来生成ROP exploit，而且也是有反馈的。所以我觉得可以把GuidExp当成一个弱化版fuzzer，也方便去理解作者的设计。

![](../Images/20a88f7d395007208019c785018dd2c1.png)

既然是穷搜，那么关键就是要缩小搜索空间。作者的核心方法是，将ROP进行分解，分而治之。如图1所示，作者将ROP分解成Trigger Slicing和若干子目标。其中trigger slicing是触发bug的一段代码，会将VM驱动到buggy state，但是往往这样是不足以实现严重的攻击的。于是以此为基础，再一步步添加利用代码，例如内存破坏、内存泄露等，最后劫持控制流形成ROP chain。

![](../Images/dbba6b40aaa1dd54560c7ee09ca61781.png)

回到图2，GuidExp的输入为目标exp的子目标和对应的不变式（这是需要安全专家预先定义的）。这个不变式是用于检查是否实现子目标的。但我觉得主要是因为作者没实现AVM的插桩，所以无法靠runtime信息去检查。exploit构造的过程可以结合图3理解，每个子目标都是个状态机（绿色的checkpoint），中间的红点和灰点则是中间的状态。通过子目标将整个搜索空间进行了分割，逐个击破，从而大幅提高了效率。

![](../Images/fae12bd047076ddaf5b0fb5bb36f9e65.png)

![](../Images/3bc3c26f8b4f65a7b8e8a0ec2fe89d8b.png)

作者对十个漏洞进行了exploit生成的测试，以中间生成的slices数目和用时作为指标进行评估。就结论来说，作者的子目标分解方法将AEG的复杂度降低了10的45次方数量级。

![](../Images/c4aa22aaf6ed103377dc3b0196dd112f.png)
