今天给大家推荐的是一篇关于IoT Fuzzing技术的论文——"DIANE: Identifying Fuzzing Triggers in Apps to Generate Under-constrained Inputs for IoT Devices"，已被IEEE S&P 2021接收。  

  

![](../Images/fa7e49e34f73e9f2dda3c56220c3e0d1.png)

现有的IoT Fuzzing方法大多是针对应用UI上用户输入相关的函数参数来为IoT设备生成有效的模糊输入，但是这种方法是在从UI获取变量后立即对变量进行变异，一旦应用对输入进行筛选或格式匹配，Fuzzing的有效性就会大大降低。  

本文作者针对这种应用端验证代码约束的问题提出并设计了一种新的IoT Fuzzing工具——DIANE，该工具能够分析得到IoT设备配套应用中的fuzzing triggers函数，并以此来生成有效的模糊输入（不受验证代码的约束），从而大大的提高fuzzing的效率。

  

![](../Images/2755499e4d9adf629cdc1a2a020929df.png)

![](../Images/6cd836fd7007f13d8141eb3e7a5fc80e.png)

该工具主要分为两大部分：fuzzing trigger函数的识别以及fuzzing过程。  

（1）Fuzzing Trigger Identification

DIANE首先通过静态/动态分析技术识别出应用中的fuzzing trigger。直观的说，Fuzzing trigger函数指的是应用程序控制流中位于应用验证逻辑和网络消息发送函数之间的函数。识别算法主要分为四个步骤：

*   sendMessage Candidates Identification
    

*   作者将应用中实现发送消息功能的函数称为sendMessage。
    
*   作者通过识别所有执行网络I/O功能的函数来收集sendMessage。  
    

*   sendMessage Validation
    

*   作者对收集到sendMessage函数进行验证，验证方法包括多次动态执行该函数并检查是否生成网络流量，以及阻止应用执行该函数并检查是否仍生成网络流量。
    
*   为了防止程序崩溃，作者采用了一种基于时间戳和机器学习的方式来对sendMessage进行筛选。
    

*   Data-Transforming Function Identification
    

*   数据转换是指对应用数据的整体格式进行转换，例如编码方法。
    
*   在数据转换函数和sendMessage函数之间生成模糊输入可能会导致无效输入，为了提高效率，DIANE需要找到数据转换函数。
    

*   Top-Chain Functions Collection
    

*   找到函数转换功能函数链的第一个函数。
    

（2）Fuzzing

*   Test Case Generation
    

*   作者通过改变识别的fuzzing triggers的参数来生成一组测试用例，包含以下策略：
    

*   改变字符串长度，以尝试触发缓冲区溢出和越界访问。
    
*   改变数值，以尝试整数溢出和越界访问。
    
*   提供空值，以尝试未初始化变量漏洞、空指针引用等。
    
*   通过删除或添加元素来修改数组内容。
    

*   Identifying Crashes
    

*   DIANE能够自动分析设备响应以识别崩溃。具体来说，如果满足以下任一条件，则认为输入可能导致崩溃。
    

*   连接中断。
    
*   HTTP服务器错误（500）。
    
*   网络流量大小异常。
    
*   心跳监测，如果响应时间高于10秒则认为崩溃。
    

  

作者实现了DIANE，并挑选了11台物联网设备对其进行了性能评估。  

![](../Images/2e075976b5ce723840cf1acf787a9a80.png)

*   首先，作者测试了DIANE在检测fuzzing triggers过程中的精度，并通过人工逆向app来进行确认。
    

![](../Images/6a5583dbf6f08d9db733fa11b219d64a.png)

*   然后，作者使用DIANE对挑选的11台设备进行测试。
    

*   DIANE在5台设备中发现了11个bug，包括9个0 day。
    
*   所有情况下DIANE的运行时间不超过10小时。
    

![](../Images/f6798aa46e76405fc74b9aadc4c950d9.png)

*   此外，作者还将DIANE与之前的工作IoTFuzzer进行了比较。
    

*   作者使用之前的11台设备进行测试，结果表明DIANE性能明显优于IoTFuzzer。
    
*   作者研究了应用程序端验证的频率，来衡量其对IoTFuzzer性能限制的影响。结果表明，51%的应用包含应用端输入验证。
    

*   最后，作者将DIANE与现有的网络级别fuzzing工具进行比较。
    

*   结果表明，网络级别的fuzzing工具无法在测试的设备中发现bug。
