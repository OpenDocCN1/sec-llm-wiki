今日推荐的论文是发表在CCS 2019上的《MalMax: Multi-Aspect Execution for Automated DynamicWeb Server Malware Analysis》。作者介绍了用于检测Web服务器恶意软件的系统MalMax。

作者指出，PHP是一种高度动态的语言，恶意软件被触发通常需要将恶意代码注入到良性PHP代码中，这给恶意软件的分析和检测带来了极大的挑战。为了解决该问题，作者提出了MalMax。MalMax有以下两大亮点。

  1. 多方面执行（Multi-Aspect Execution）

    此点的目的是为了探索目标程序的多个方面。首先，MalMax采用了反事实执（Counterfactual Execution），可以即使分支条件不满足也会执行到分支中。如下图所示，即使第一行没有GET到数据，MalMax也会检测后面的分支。


其次，MalMax采用了控制流削减（Control Flow Trimming），实现了对恶意软件故意拖延恶意执行行为的绕过。图二是图一的控制流图，MalMax根据代码执行次数，总结出经常被执行的代码为一个隔离块（第3、4、5、8行），并继续探索新的路径（第6行）。这里的“经常“作者使用了设定的阈值来衡量，该策略也确保了分析能够在合理的时间内完成。

    2. 合并孤立执行（Cooperative Isolated Execution）

    MaxMal提供了一个合并得孤立执行环境（沙箱），以(1)隔离程序的每个执行路径，(2)协作共享在每个独立执行中解析的资源，以帮助发现动态加载的代码片段(例如，通过include)。如下图所示，MaxMal能够在隔离执行1中建立一个数据库连接，2中利用数据库填充一个全局变量，3中利用全局变量加载一个含有恶意代码的插件。

进一步，为了评估MalMax恶意软件分析的能力，并与当前最先进的恶意软件检测工具对比，作者在MalMax框架基础上构建了PhpMalScan工具，该工具能够判断出给定的程序是否是恶意的。PhpMalScan使用恶意分数（MS）和潜在恶意函数比例（PMFR）进行决策。


作者使用PhpMalScan对基准套件和1TB真实网站部署进行了评估，结果显示MalMax在假阳性和假阴性方面都优于恶意检测器VirusTotal，PhpMalScan识别出的1485个恶意样本即使7个月后在野外也没有被VT检测到。
