今天推荐的论文是来自DSN 2020的《JSKernel: Fortifying JavaScript against Web Concurrency Attacks via a Kernel-like Structure》。作者总结了一类名为Web Concurrency Attack的Web攻击类型，并设计了JSKERNEL框架用于抵御此类型的攻击。

现下，针对Web攻击多采用两种手段进行防御。第一种是使用缩小攻击面的方法，作者指出该方式无法应对新的Web攻击形式；另一种是通过精准的捕捉攻击的触发条件并阻止攻击，对危险JS API进行重定义是一种常见阻止的手段，作者指出该方法无法应对Web Concurrency Attack类型的攻击。


Web Concurrency Attack有以下两种表现形式。第一种是利用Web隐式时钟（如postMessage函数的onmessage回调）进行侧信道攻击。由于攻击过程与多个JS函数的调用顺序有关，因此此前的方法难以捕捉；第二种是use-after-free漏洞，攻击通常涉及三个函数——获取初始web请求，Web Worker的错误中止，以及请求的中止信号。此前的防御手段由于无法捕捉到三个函数的内在关系，因此无法检测到该攻击。


作者针对这两类攻击分别制定了相应的策略，并设计了JSKERNEL框架用以实现策略，如下图所示。对于第一种攻击，通过将所有的事件以确定的顺序安排执行，以防止侧信道攻击。对于第二种攻击，策略设置了主线程与Web Worker线程的通信信号，以防止Web Worker被内存释放而导致主进程意外退出。


作者在自己设计的JSKERNEL实现了上面提到的防御策略。JSKERNEL包含两个部分：Kernel和User Space（Website）。Kernel Interface提供了用户使用的API接口。内核由四个部分组成，其中最为关键的是Scheduler，它负责根据手动指定的策略或确定性的调度，将事件放入事件列表中。


最后，作者评估了JSKERNEL的鲁棒性和可用性，结果表明，JSKERNEL能够抵御隐式时钟攻击和其他Web Concurrency Attacks类型的攻击，能够向后兼容且性能开销较低。
