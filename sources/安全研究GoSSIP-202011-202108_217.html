今天推荐的是来自滑铁卢大学和阿尔托大学的一篇研究代码防御的论文，针对的是ROP这类修改返回地址的攻击。文章录用于USENIX Security 2021，并且通过了ARTIFACT EVALUATION。

Return-oriented programming (ROP)是通过触发内存漏洞来修改储存在栈上的返回地址从而达到劫持控制流的攻击技术。借助多个gadget的串联，ROP能够实现图灵完备的攻击。为了抵御这种修改返回地址的攻击，Shadow stack技术通过将返回地址记录到受完整性保护的内存中来检测这类攻击行为。基于软件的shadow stack通常会带来较大的开销，而且shadow stack的地址是有可能被泄露从而绕过的。基于硬件的shadow stack虽然安全、有效且快速，但是开发与部署上会有较大开销，因为这类shadow stack是依赖于硬件特性与机制的。

在ARM架构上，从ARMv8.3-A开始引入了Pointer Authentication（PA）功能，在指针的高地址位存储Pointer Authentication Code（PAC）。PAC实际上是对指针地址和一些额外的上下文进行哈希签名。例如表1，借助PA在函数头对返回地址（ARM上的LR寄存器）进行签名后再压到栈上，然后在函数return前验证签名。

然而，ARM本身的这套标准并不是足够安全的。Project Zero去年写的一篇文章就针对ARM本身标准的PAC和iPhone XS上的PAC进行了研究与比较。其中也指出了具有读/写权限的攻击者能够利用signing gadget来绕过PAC保护。例如，攻击者通过触发从内存读取指针、添加PAC并写回的函数，能够为任意指针伪造PAC。因此，对于具有读/写能力的内核攻击者，ARMv8.3的PA标准是不足够的，像苹果则采用了一些“dark magic”来强化PAC。

本文中，作者考虑的攻击者虽然对进程内存具有arbitrary control，但是受到W⊕X策略的限制，难以对代码页进行修改。针对这种攻击模型，作者提出了四点防护要求：Return address integrity、Memory disclosure tolerance、Compatibility和Performance。

作者设计了authenticated call stack (ACS)。其关键思想是将call stack中所有的返回地址作为上下文加入到哈希中，也就是利用chained message authentication codes (MACs)，如图2所示。具体来说，这些authentication token和return address在栈帧上的存储如图3所示。

为了保障安全性，作者使用称为chain register（CR）的CPU寄存器来专门保存当前经过验证的返回地址。另外，结合粗粒度的forward-edge CFI，作者可以确保token的更新是安全的。

为了缓解hash碰撞攻击，作者使用从先前的aret值派生的伪随机值作为掩码与auth异或。为了缓解暴力猜测攻击，作者采用“re-seeding”的方式，在创建线程或是fork之后重新计算auth。除此之外，针对setjmp / longjmp这类不规则的stack unwinding，作者也有相应的设计。

作者对ACS的安全性进行了探讨，对图4中对AG-Load和AG-Jump这两个攻击目标的难度进行了论证。作者还对tail calls和signing gadget带来的威胁进行了讨论。通过严格的安全性分析，作者表明PACStack无需专用硬件即可达到与硬件辅助的shadow stack相当的安全性。最后，作者评估了性能，开销约3%，还是比较小的。

值得一提的是，这篇文章通过了ARTIFACT EVALUATION。这个评估是从USENIX SEC‘20开始的，是向软工会议学习，为了解决“一纸空文”的弊端，提高研究成功的可用性，主要是对文章相关的软件、硬件、数据、文档等进行评估。这篇文章的项目在GitHub已经开源：https://pacstack.github.io。
