International Conference on Software Engineering (ICSE) 和 International Conference on Program Comprehension (ICPC) 是软件工程领域两大著名的学术会议，2017年这两大会议联合在南美大陆、几乎是上海往地球中心连线延长的另一端的阿根廷首都布宜诺斯艾利斯召开，LoCCS实验室的胡易坤博士的论文Binary Code Clone Detection across Architecturesand Compiling Configurations在ICPC会议上发表，他也前往参会并为我们带来了下面的见闻感想：


“我于5月22日至23日参加了在阿根廷布宜诺斯艾利斯举办的第25届 International Conference on Program Comprehension (ICPC’17)，并在24日至26日“蹭会”了一同召开的第39届 International Conference on Software Engineering (ICSE’17)，这次是两个会议首次在南美洲召开，ICPC的主题是程序理解，主要包括文档理解、代码推荐、变量命名等内容，我们比较关注的代码语义理解相对而言是一个比较小众的内容了。我被安排在Smells and Clones这个议题的第一个作报告，因为有了之前上台的经验，加之二进制程序分析对于做软工的人而言是一个比较陌生的内容，他们提的问题偏向概念性，所以这次报告就淡定了许多，整个过程也非常顺利；议题的第二篇文章是来自加拿大萨省大学的Identifying Code Clones having High Possibilities of Containing Bugs，核心思想是通过克隆代码检测将问题代码与同一软件其他版本程序相关代码对应以检测漏洞；第三篇文章是关于代码风格检测的Smells Are Sensitive to Developers! On the Efficiency of (Un)Guided Customized Detection，旨在发现工程当中不良的代码实现，以便后来的理解和维护.


ICPC另一个和我们比较相关的主题是Bugs. 第一篇是由德州大学达拉斯分校的Tien N. Nguyen老师带来的Bug Localization with Combination of Deep Learning and Information Retrieval，利用已有的bug report作深度学习定位其他代码中的漏洞，通过机器学习分析程序也是Nguyen老师比较擅长的方法；第二篇文章是来自香港理工罗夏朴老师组的Bug Report Enrichment with Application of Automated Fixer Recommendation，他们将多个bug report整合起来，以辅助代码修补；第三篇文章How Does Execution Information Help with Information-Retrieval Based Bug Localization?则将代码动态信息和bug report相结合定位漏洞。以上几篇文章当中，bug report和information retrieval这两个关键字经常出现，说明如何利用已有的bug report综合其他信息（比如动态运行时信息等）定位代码漏洞是软件工程当中大家比较关注的问题。


ICSE是软件工程方向的顶级会议，此次会议注册人数超过1000人，其中中国人的人数为65人，虽然相较美国（220人）等强国还有差距，但华人已经逐渐成为软工圈子当中一股不可忽视的力量；同时会议的日程安排也非常紧凑，每个时段有三个议程同时进行，使得大家必须在自己感兴趣的文章当中做出取舍，会议期间能够看到许多人在不同会场间来回穿梭，场面十分热闹。


Program Analysis这个议题中我个人最关注两篇文章：一篇是NTU的SPAIN: Security Patch Analysis for Binaries towards Understanding the Pain and Pills，另一篇是UCB的Travioli: A Dynamic Analysis for Detecting Data-Structure Traversals. 前者是利用代码克隆检测做二进制代码的补丁分析，从提问环节的问题来看，大家对二进制分析处于了解不多、但兴趣浓厚的状态，我觉得二进制程序分析在ICSE当中还是很有潜力的; Travioli通过识别遍历代码检测程序的性能缺陷，里面涉及的循环检测、递归分析等基本技术和我们都是十分相关的。另一篇比较有意思的文章是来自首尔国立大学的Machine-Learning-Guided Selectively Unsound Static Analysis，他们利用机器学习算法辅助静态分析以获得更好的分析效果，在程序分析技术发展遭遇瓶颈的现在，结合机器学习辅助分析不失为一种好的尝试。


多年以来，ICSE在代码修补方面都有专题，这次也开设了Program Synthesis and Repair这一题目，其中和我们最相关的就是北大熊英飞老师的Precise Condition Synthesis for Program Repair，通过文档、变量依赖关系对修补方案排序，解决代码修补问题搜索空间过大、准确率低下的问题。此外，会议在Testing、Debugging等议题当中还有很多在技术（错误代码定位、测试用例生成等）上对我们可能存在帮助的工作，因为日程的原因不能一一听全，我准备在会议结束后把这些文章再仔细阅读一下。


在听取报告过程中，我感受到顶会文章往往都有详尽而完备的实验，这和过去听一些顶会审稿人说的“以实验为先”的审稿原则相吻合，也和小组一直以来文章写作的导向一致，我想只要有耐心和恒心、构建逻辑严密的实验并且一丝不苟地完成，我们今后将更有把握在顶会上发表文章。另外，在会议闭幕式上，ICSE’18组委会宣布下一届会议将历史首次引入双盲审制度，当时整个礼堂响起了整一周我听到的最热烈的欢呼声，希望ICSE系列会议以后能够越办越好，更希望有朝一日我们能够在ICSE的舞台上分享自己的工作。”
