# G.O.S.S.I.P 阅读推荐 2023-01-17 xNIDS

今天为大家推荐的论文是来自纽约州立大学布法罗分校安全研究团队投稿的关于通过解释基于深度学习的网络入侵检测系统来实现动态入侵响应的工作 “xNIDS: Explaining Deep Learning-based Network Intrusion Detection Systems for Active Intrusion Responses”。目前该工作已发表于USENIX Security 2023, 并获得了Amazon Research Award （ARA）的支持！![](../Images/6a6e47dd9fe9bde0de4c1a4b2bfde6dc.png)「背景介绍」如今基于深度学习 (Deep Learning) 的网络入侵检测系统（NIDS）已经被广泛研究并且表现出极高的检测精度，但是由于网络入侵检测系统的输出结果（detection results）和可执行的网络入侵响应解释 (actionable interpretation) 之间存在语义差异（semantic gap）所以基于深度学习的网络入侵检测系统并不能有效的做出动态网络入侵响应（actively respond）。同时，由于误判代价（error cost）过高，网络管理者（network operator）不愿意仅依赖检测结果 (detection result) 来做出响应 (response)。造成这些问题的原因在于基于深度学习的网络入侵检测系统缺乏可解释性。虽然目前已经有方法可以解释通用深度学习系统，但是它们没有考虑历史信息（history inputs）和结构化数据中复杂的特征依赖关系 (complex feature dependencies of structured data)，所以不能很好的解释基于深度学习的网络入侵检测系统。  
在这项工作中，作者开发了xNIDS，一个通过解释基于深度学习的网络入侵检测系统来执行动态网络入侵响应的框架。本文的解释模型（explanation method）有两个亮点：（1）对历史信息进行近似和采样；（2）捕捉结构化数据的特征依赖。然后基于解释模型输出的解释结果，本文的网络防御规则生成模块（rule generation methodology）可以生成可执行网络响应规则（actionable defense rule）。评估表明该方法比现有的方法有更好解释效果，同时作者展示了该方法可以有效生产网络防御规则，帮助理解基于深度学习的网络入侵检测系统，以及排除错误。![](../Images/61ce09bb1c4b4749e36be2317c29a4f1.png)  
图1:基于深度学习的网络入侵检测系统存在的问题（红色）和本文给出的解决方案（蓝色）  
「研究工作概览和亮点」  
为什么需要 （1）解释基于深度学习的网络入侵检测系统， 和 （2）动态入侵响应本文作者针对 IEEE S&P 2020 “Test of Time Award”（时间检验奖）获奖论文《Outside the Closed World: On Using Machine Learning For Network Intrusion Detection》中提出的问题从以下三个方面论述了可解释性和动态响应的重要性：  
语义差异（sematic gap）：基于深度学习的网络入侵检测系统的输出通常是一个标签（label）或者一个得分数值（score），网络管理者需要花费大量时间来手工研究分析这些数值背后的意义来制定合适的网络防御规则。因此，解释基于深度学习的网络入侵检测系统并生成可理解的输出对网络管理者来说非常有帮助。排除错误（troubleshoot errors）: 在网络入侵检测时误判的代价非常高，但是排除深度学习系统的错误非常困难，因此解释基于深度学习的网络入侵检测系统可以减轻排除错误的工作负担。动态响应（active response）: 虽然基于深度学习的网络入侵检测系统可以及时检测出网络攻击，但是网络管理者需要花费大量时间来做手工分析后才可以做出合适的响应与此同时攻击者可能已经击穿了网络，因此及时的动态入侵响应对保护网络来说非常重要。  
（1）解释基于深度学习的网络入侵检测系统的挑战：  
本文作者总结了解释技术深度学习的网络入侵检测系统的两个难点：  
历史信息（history input）：网络入侵检测系统在判断当前输入是正常或攻击时通常会参考历史信息。因此在解释当前检测结果的时候我们同样需要考虑历史信息的影响。复杂的特征依赖关系（complex feature dependencies）: 网络入侵检测系统的输入的特征之间存在者复杂的依赖关系，比如共存关系 （tcp 和tcp.flag), 互斥关系 （tcp 和 udp)。![](../Images/4d13a09a95fbe21647c559350096226d.png)图2: 作者比较了现有方法和本文方法在解释基于深度学习的网络入侵检测系统的优劣  
针对以上难点，作者首分析了现有方法的缺点：![](../Images/57028029e714c49f02a6596cf1218fa4.png)Integrated Gradients (IG) 和 Layer-wise Relevance Propagation (LRP), 如上公式所述， 这两种解释方法假定每一个特征都是独立的。![](../Images/860a3ece212b3cc66bc6b6256f678472.png)LIME和SHAP, 如上公式所述， 这两种解释方法同样假定每一个特征都是独立的。![](../Images/973d5c9d9129e6c4377fd9a4550c5f7f.png)LEMNA， 这种解释方法假设相邻的特征之间具有相似的重要性， 这是一种过于强的假设，对基于深度学习的网络检测系统来说不一定一直正确。  
鉴于现有方法没有很好的解决以上两个难点，本文作者设计了针对基于深度学习的网络入侵检测系统的解释方法：![](../Images/46fbeaad84c53faf8631cebd0505a55e.png)本文的解释方法通过（1）对历史信息进行近似和采样（s.t.）；（2）使用分组稀疏约束（sparse group lasso）捕捉结构化数据的特征依赖，得到了更好的解释结果。另外通过使用 sparse group lasso， 本文的方法可以获得更好的组稀疏性和特征稀疏性（sparsity）。![](../Images/9ae3b0634bdbeb0b7508ede06ff5ca99.png)  
（2）生成网络响应规则的挑战：  
基于上一步的解释结果，本文的网络防御规则生成模块可以生成可执行网络响应规则。本文作者总结了生成网络响应规则的两个难点：  
平衡精确性和通用性（precision and generalization）：在生成网络防御规则的时候需要平衡精确性和通用性，过于精细的规则会使得生的防御规则数目庞大，同时过于通用的规则可能会影响网络的正常使用。可适用性（universally applicable defense rules）：虽然不同的网络防御工具可以达成相似的防御效果，但是不同的工具会有不同的防御规则形式（formats）和粒度（granularity）。  
  
针对以上两个难点，本文的网络防御规则生成模块设计了（1）规则范围（rule scope），（2）安全约束（security constraints），和 （3）统一的防御规则（unified defense rule）三种机制。  
规则范围（rule scope）：规则范围定义网络防御规则的应用范围。本文定义了三种规则范围(1) per-flow scope; (2) per-host scope 和 （3）multiple-host scope。以下列举了三种不同规则范围的网络防御规则。  
![](../Images/bb71a401463812231a2e86e59d32d98c.png)图3: per-flow 规则范围![](../Images/345799d2e4a03e74b493783cf2a82318.png)图4: per-host 规则范围![](../Images/6699edae93eceb6e0792c04c51641fb9.png)图5: multiple-host 规则范围  
安全约束（security constraints）：网络环境通常有不同的状态，同时网络管理者会有不同的需求，因此需要根据不同的需要来调整网络防御规则。本文设计了两种机制 （1）whitelist 和（2） block stratedy 来保证网络的正常使用以及防御有效性。同时本文定义了三种block strategy：a) passive strategy；b) assertive strategy；和 c） aggressive strategy。  
统一的防御规则（unified defense rule）：为了支持不同的网络防御工具，本文设计了统一的防御规则来作为解释结果和可执行防御规则之间的桥梁。每一个统一的防御规则有四个部分组成 ⟨entity, action, priority, timeout⟩。entity 是防御规则的执行对象（e.g. host)，action 是要执行的动作（比如drop）, timeout 约束防御规则的执行时间， 以及priority 定义防御规则的优先级。![](../Images/2d08f39043733b65faf40c33259bd8ef.png)图6: 统一的防御规则（unified defense rule）  
生成防御规则（rule generation）：按照上述步骤，本文可以先解释基于深度学习的网络检测系统，然后通过分析解释结果来生成防御规则。  
![](../Images/5ecb7b24284315031bbff82bedfcd03e.png)图7:作者展示的基于解释生成防御规则的一个例子   
「评估及讨论」  
评估解释模型（Evaluation of Explanation）：本文详细的比较了各个不同解释方法在 fidelity, sparsity, completeness, 和 stability 四个方面的表现。实验结果表明本文的解释方法在解释基于深度学习的网络入侵检测系统比现有方法有更好的表现。![](../Images/81cfe2f2e45f214c3162d6a4c6c676ab.png)图8:作者展示的解释方法评估结果（详细的比对请查看原文）  
评估规则生成（Evaluation of Rule Generation）：本文通过 supported tools, covered attacks 以及 latency 三个方面比较了本文的规则生成模块和现有工作。实验结果表明本文的规则生成方法能更好的生成可执行防御规则。![](../Images/3e9663d4ba7172a9befbab9aaf9ce28b.png)图9：作者展示的规则生成评估结果（详细的比对请查看原文）  
排除误判（Troubleshooting Detection Errors）：本文定义了三种误判：(1) Infected Benign， (2) Disturbed Benign，和 (3) Unseen Benign。以下是通过 casestudy 展示的排除误判的效果。![](../Images/5f47a6011b46356709297753a88b8143.png)图10：作者展示的排除故障的结果  
动态响应（Active Responses）：本文展示了在三种不同block strategies下的动态响应效果。实验结果显示执行passvie stratedy会有较高的false negative rate, 而执行aggressive stratedy 会有比较高的false postive rate。 同时可以看到通过排除故障可以改善动态响应的效果。![](../Images/ab152a4370cd56d751871195404a7589.png)图11：作者展示的动态响应的效果![](../Images/36e3256e2a6fcdfede5cabe69c25e3ff.png)图12：作者展示的排除故障后动态的效果
