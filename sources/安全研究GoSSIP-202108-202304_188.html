周末让我们放松放松，去看看研究人员对前段时间一直很火热的代码辅助（编程作业作弊）小能手——GitHub Copilot的测评。这篇论文 An Empirical Evaluation of GitHub Copilot’s Code Suggestions 来自MSR 2022

在这篇只有5页（于是让阅读变得更有乐趣）的论文中，作者对Copilot这个传说中的“自动coding神器”进行了测试，试图更科学地回答两个非常难衡量的问题：

  1. Copilot的自动化代码建议有多么正确（correct）？

  2. Copilot的自动化代码建议（对人类而言）可读程度有多高？

那么你猜，作者会怎么样去测试Copilot呢？为了回答第一个问题，他们想到了诸多为了找工作而刷题的同学，于是也求助于LeetCode，拿上面Python、Java、JavaScript和C语言的测试题来测试Copilot的表现。同时，作者借助SonarQube来评估Copilot在LeetCode刷题的过程中输出代码的质量（用cognitive complexity和cyclomatic complexity来评估）。

让我们来看看测试的结果：作者选择了33道题目让Copilot来做，结果表明，在各种语言中，Copilot最擅长提供Java代码相关的建议，能够输出答案让57%的Java测试题目全部通过，而其它三种语言（Python、C和JavaScript）的通过率分别是42%、39%和27%，看起来好像也还不赖。

但是，故事总归会有转折的。。。作者仔细检查了上图这个题目（Longest Increasing Path in a Matrix），发现除了Java之外，Copilot为其它三种语言输出的代码要么不能编译，要么就是运行出错。原来Copilot一次只能输出单个函数的实现，在这个题目中，Copilot在代码建议里面使用了一个外部函数（depth-first search），而刚好撞大运撞到Java本身有这个函数（不需要再提供实现），所以就只有Java代码能运行，而其它代码就不能运行了。这样看来，Copilot也不是那么智能了。

如果大家对作者的测试细节感兴趣，可以去看看论文Artifact里面33道题目的测试结果:

https://figshare.com/articles/dataset/An_Empirical_Evaluation_of_GitHub_Copilot_s_Code_Suggestions/18515141

针对代码的可读性，小编也不太懂cognitive complexity和cyclomatic complexity如何表征代码的人类可理解语义，但是作者提供了一个很有意思的参考：Copilot输出的代码在这两项指标的复杂度上（对各类语言）都低于静态代码分析工具通常会设定的阈值，也就是说，至少现有的静态分析工具能够很好处理Copilot的输出代码，不至于因为复杂度而无法完成分析。

总之，如果你的coding能力还不能在LeetCode上搞定超过30%的题目，那你可能就要被Copilot取代了。不过最后，小编想到了小时候看过的一个科幻故事（应该是发表在中国最早的科幻杂志《智慧树》上），大意是有一个国王在自己的国家发明了医疗机器人之后，觉得没必要再要医生了，就把医生都赶跑了。后来有一台，国王肚子疼，让机器人来做手术，机器人诊断是阑尾炎，开始做手术，可这个国王赶上了万里挑一的体质——阑尾长在下腹的左侧而不是右侧，机器人的代码没法handle这种异常，最后给国王的一段好的肠道给切除了。。。这个给小编留下了童年阴影的小故事，直接导致小编至今也不敢去学AI，这样说不定过几天也会被能写代码（公众号文章）的AI驱逐出境了。。。
