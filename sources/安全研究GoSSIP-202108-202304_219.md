# G.O.S.S.I.P 阅读推荐 2022-08-15

二进制代码的相似性检测（Binary Code Similarity Detection， BCSD）一直是程序分析和软件安全领域的重点问题，应用场景广泛，包括已知漏洞发现，恶意软件检测以及软件剽窃检测等等。G.O.S.S.I.P 每日论文推荐专栏的开篇之作（2020年2月14日）就介绍了一篇相关研究论文。今天我们为大家介绍的ISSTA 2022研究论文——*jTrans: Jump-Aware Transformer for Binary Code Similarity Detection*——继续探讨相关主题，作者提出了一种不依赖CFG，同样可以学习指令之间以及程序块之间相关性的方法，并以此实现了一个新的二进制代码相似性检测系统`jTrans`。

要识别两个二进制代码片段之间的相似程度，传统方法非常依赖二进制代码的CFG以及手工设计的特征，鲁棒性差，且通常耗时耗力。而基于深度学习的方法要么只考虑了指令序列，没有考虑到CFG；要么对于CFG内部的指令没有足够的重视。即便采用了GNN来学习CFG，也因为GNN的难以训练，导致效果欠佳。作者为了解决上述问题，设计了`jTrans`，构建了新的模型用以适配二进制代码相似性检测。

为了能够让传统的BERT模型学习到二进制文件的特征，作者参照NLP的方式对二进制文件进行了tokenization。

*   采用IDA对二进制文件进行反编译。
    
*   将单个mnemonic以及operand视为单个token。
    
*   引用的字符串以及常量值分别采用`<str>`以及`<const>`作为token。
    
*   对于引用的外部函数，采用其名字或者标签作为token，但是引用的内部函数全部采用`<function>`作为token。
    
*   对于有跳转关系的，源地址以及目的地址构成了一个jmp pair，作者将其token定义为JUMP\_XXX，XXX为目的地址所在的token索引。比如`0x40046A: js 0x40047c`，目的地址0x40047c经过token化后，索引为20，因此该条语句token化后成为`JUMP_20`。
    

经过上列处理，`jTrans`的模型已经可以能够在一定范围内处理二进制文件了，然而BERT模型天然并不能够识别到token的顺序关系，因此还需要position embeddings。

对于NLP任务来说，position embeddings直观体现了两个不同距离token的相关性。距离越近，其相关性越强，上下文联系越紧密。对于程序的跳转来说，跳转关系可能距离比较远，但是彼此之间的关系却非常紧密，一起分享上下文信息。为了能够引导模型注意到这一点，作者将跳转关系中源token embedding作为目的地址的positional encoding，比如图中P14P14的参数即来源于EJUMP\_14EJUMP\_14。作者在文中详细地给出了这种方法可以有效解决远距离跳转相似性问题的证明。

作者将模型的训练分为两部分：无监督的预训练过程以及有监督的微调过程。

在无监督的预训练过程中，作者进行了两方面的工作。一方面（Figure 4）采用与BERT相同的masking策略：80%的指定token被`<MASK>`替代（即这部分信息需要被重构，希望模型能够根据上下文预测到这些token），10%的token被随机其他token替代（即这部分信息可能错误，希望模型不要给与单个token过高权重），10%的token完全保留。而另一方面（Figure 5）则被称为Jump Target Prediction，顾名思义，将跳转的源地址采用`<LOC>`mask掉，然后让模型预测跳转地址。很明显，这要求模型具有非常强的上下文理解学习能力才能够做到。

有监督的预训练过程中，作者采用有标签的函数数据集对模型进行了微调训练。

作者基于ArchLinux以及Arch User Repository，采用不同的编译器不同的优化策略构建了一个丰富的数据集。

![](../Images/0cc98ad7c617ec758d6fbe7a530d238f.png)

为了实验结果具有说服力，作者收集了其他六款二进制相似性分析工具：Genius、Gemini、SAFE、Asm2Vec、GraphEmb、OderMatters。评价指标则采用了Recall以及MRR。

作者从以下几个方面对`jTrans`进行了评估：

1.  `jTrans`在BCSD任务方面和其他工具相比怎么样？  
    我们选取了两张具有代表性的表。可以看到在不同的Poolsize（即待评估的函数集合）下，不论是MRR还是Recall，`jTrans`的效果都是最佳。尤其是Poolsize增长到10000时，其他工具的评价指标都大幅度降低，而`jTrans`依然可以拥有0.693的MRR以及0.625的Recall。  
    ![](../Images/0d6479de725741485600823ac10bb421.png)
    
2.  不同的工具在不同的PoolSize下表现怎么样？  
    作者测试了不同的工具在不同的PoolSize下的性能，从下图中可以看到所有的工具在PoolSize增大时，性能都欠佳，作者提出的`jTrans`效果最佳，下降幅度相对于其他工具来说较低。  
    ![](../Images/a5d60af56c97699a8fd6fa8140e0f1db.png)
    
3.  `jTrans`在漏洞检测方面能力如何？  
    作者从已知的数据集中选出8个CVE，为了尽可能还原真实的场景，同样采用不同的编译器和优化策略进行编译。与Asm2Vec以及SAFE的对比中可以看到`jTrans`在所有的任务中表现都是最出色的。  
    ![](../Images/95fe38e8abe3a00867ce66a911afd25b.png)
    
4.  作者也对前面预训练过程中提到的跳转预测的效果做了评估。  
    通过与没有进行这一步的模型做对比，可以看出经过了跳转预测训练的模型在程序上下文理解方面能力更强，直观表现在其Recall上面。  
    ![](../Images/b1455ea5c01b30a676c5bbc0c55722bb.png)
    
5.  模型训练过程中微调的作用怎么样。  
    在第一部分的评估中，*jTrans-zero*即为直接预训练，没有进行微调的模型。可以看到即使是没有进行微调的模型，效果也要优于其他人的工作，而微调过程则进一步大大增强了模型在BCSD任务中的能力。
