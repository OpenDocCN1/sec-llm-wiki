又是一个美好的周一，今天为大家推荐的论文是来自清华大学WingTecherLab投稿的关于数据库安全的工作 Unicorn: Detect Runtime Errors in Time-Series Databases With Hybrid Input Synthesis，目前该工作已被ISSTA 2022录用。


在对数据安全至关重要的物联网领域，时间序列数据库的使用无处不在，这就对时序数据库的安全性和正确性提出了更严格的要求。过去的研究和工业实践证明，模糊测试是一个检测数据库漏洞的有效方法，它已经在传统的关系数据库中自动地检测出了数百个漏洞。然而，现有的模糊测试技术不能轻易地应用于时序数据库漏洞的检测，主要由于以下两点挑战：


  1. 由于时序数据库和关系数据库不一致的查询规范(时序输入特性)，大部分的时间序列逻辑代码无法被现有的模糊测试工具覆盖。

    物联网应用的一个主要特点就是时序数据的大量使用，它代表了从一段时间的连续测量中观察到的数据值的集合。在实际应用中时序数据总量巨大，而且需要连续更新。为了降低存储成本和提升查询效率，时序数据库引入了独有的存储模型和查询规范。




  2. 由于时序数据库的隐式异常处理机制的存在，许多严重的漏洞都会被现有的漏洞检测方法忽略掉。

    物联网设备被广泛应用于许多关键领域，因此，可用性和可靠性对于时间序列数据库来说是不可或缺的。在物联网实际应用场景中，时序数据库被设计为具有复杂的分布式结构。具体来说，它们必须稳定地处理来自数百个物联网设备客户端的每秒数千万个物联网数据点的摄入。因此，时序数据库通常包含数百个组件，其中各组件在运行时均与其他组件有复杂的通信交互。为了确保时序数据库服务端尽可能的不会宕机，时序数据库引入了隐式异常处理机制，即使组件内部出现了异常，整个服务器也可以保证正常运行。



「设计」

针对上述两个挑战，作者设计了Unicorn：它包含两个部分，即Hybrid Input Synthesis和Proactive Exception Detection。Hybrid Input Synthesis在传统的SQL规范上引入了时间序列模型，通过时序敏感的变异来生成具有时序语义的语法正确的种子。Proactive Exception Detection通过在桩代码中插入Agent来直接从运行环境中收集时序数据库运行中抛出的异常信息。Agent收集到的漏洞由Anomaly Detector进行后续的判定，去重，和报告。



「实验」

作者在应用广泛的6个时序数据库IoTDB、KairosDB、TimescaleDB、TDEngine、QuestDB和GridDB上进行测试，并与最流行的SQL数据库模糊测试工具进行了对比实验，实验结果表明Unicorn比SQLsmith和SQLancer分别多覆盖21%-199%和34%-693%的基本块并且发现了42个之前未知的漏洞。
