在这个美好的周四，我们为大家推荐的是来自加州大学河滨分校[尹恒](http://mp.weixin.qq.com/s?__biz=Mzg5ODUxMzg0Ng==&mid=2247483824&idx=1&sn=3e2e02cfdd8b0fa247fe6de2d7860c96&chksm=c0602f69f717a67f366e998e612fd1670d9972238f591e67240b6502efe0c9cea6d47314aa7b&scene=21#wechat_redirect)研究组投稿的，关于利用图神经网络反汇编x86指令的工作***DEEPDI: Learning a Relational Graph Convolutional Network Model on Instructions for Fast and Accurate Disassembly***，该工作已经被USENIX Security 2022录用。

  

![](../Images/60b25f3b7788aaffeab7927b2c4082c1.png)

这篇文章主要介绍如何利用图神经网络(GNN)来快速且准确的反汇编x86指令。反汇编是二进制文件分析的基础，x86指令因为其变长的特性，再加上允许代码和数据混合出现，让反汇编变得较为困难。常用的反汇编方式例如线性扫描和递归分析无法保证结果的正确性和完备性，而商用的反汇编工具如IDA Pro和Binary Ninja含有复杂的启发式算法而导致分析大文件缓慢。在机器学习盛行的现在，使用机器学习做二进制文件分析的方式屡见不鲜，但反汇编常常成为其瓶颈而使其整体效率不高（例如Gemini）。本文将展示如何通过将指令序列构造成图，并使用图神经网络来提高反汇编的效率和准确度。整体工作流程如下图所示。

  

![](../Images/50c2e7b30599694cadd5e7f24f92af8e.png)

  

**方法介绍**

**步骤1，完整的反汇编**

由于x86指令特性，二进制文件中每一个字节都有可能是一条指令的起始。这里作者采取的思路是首先获取所有可能的反汇编结果，再从中去掉错误的部分（数据当作指令或错误的指令起始位置）。作者将二进制文件中每个字节作为指令的起始位置来解析指令，这样对于有n个字节的文件作者将获得n条指令。这一步作者使用CUDA函数来实现使其效率最大化，并抽取指令中的Opcode, ModRM, SIB和REX prefix作为特征。

  

**步骤2，指令向量化**

由于抽取到的指令特征是自然数，则需要将离散值变为连续向量使其更适合模型的学习。其次，单条指令本身并不包含多少信息。严格来说，任何能成功解码成指令的字节序列，哪怕这条指令几乎不可能出现在程序中，都可以认为是合法的指令，但这并不意味着这是其“正确”的。要确定其正确性，还需要考虑这条指令的上下文。如果一些指令组合（指令序列）非常罕见或者不合理（例如重复写入同一个寄存器却不读取），那么就可以比较肯定这个指令序列是错误的。这样考虑指令序列而不是单条指令能让模型的学习难度下降。作者使用RNN来让每条指令包含其接下来两条指令的信息（作为上下文信息），而输出就是向量化后的指令。

  

**步骤3，使用图神经网络找出正确的指令序列**

根据正常的程序执行流程可知，一旦能确认某个指令是正确的，那么这个指令接下来的指令也是正确的（反汇编中递归分析用的就是这一点），这是一种正向的反馈。同理，如果认为某条指令是错误的，那么所有指令序列中包含这条指令的序列也是错误的（正常的程序执行不会跳入错误的指令）。这是一种负向的反馈。以及，当两条指令出现重合的时候，即一条指令的起始在另一条指令之中，至多只能有一条指令是正确的（正常编译器不会产生重合的指令）。根据以上3点，再加上向量化后的指令，能让模型较为容易地从所有反汇编结果中找出正确的序列。

这里使用的模型叫R-GCN，是一种图卷积神经网络。反汇编得到的每一条指令都是图中的一个点，而点与点之间可能存在3种边。一种边连接着一条指令和其下一条指令（例如指令正常执行到下一条，或跳转到某个位置），一种是前一条边的反向连接，最后一种边连接着互相重合的指令。这3种边对应着之前说的3种反馈。图网络的优势在于图中的每个点都能并行第向相邻的点传播或正向或负向的反馈，而不需要针对每条指令序列单独分析。这些点经过图传播之后，能很容易被分类器判断出其是否是正确的。

  

![](../Images/24b6f5c7dd1eb0394cf6c2985221dc8f.png)

  

**步骤4，还原函数入口点**

二进制文件分析中常常以函数为单位来分析，所以作者也添加了检测函数入口点的功能。整理思路与之前的反汇编类似，在前一步获得所有正确的指令之后，可以从中找出有可能是函数入口点的指令，再从中去除错误的部分。由于在反汇编代码中函数的边界更为模糊且函数主体不保证连续，作者在这一步更多的是考虑性能。作者将call指令的目标地址，以及所有不可达的指令作为函数入口点的候选。从经验来看，call指令的目标地址一般都是函数，而且那些不可达的指令通常是因为间接跳转或调用导致难以被静态分析找出。这样生成的函数候选数量将远远小于指令的数量。为了更好地找出函数入口点，作者将所有候选指令的前3条和后3条指令作为候选指令的上下文并使用GRU将候选指令向量化，并使用分类器判断其是否是正确的函数入口。

  

**实验分析**

作者将其的方法与一些开源工具（例如Ghidra）和常见的商业软件（例如IDA Pro）比较了反汇编的准确性与速度。在准确性方面，对于常规程序（未加壳、混淆等）而言，作者的方法的准确性与商业软件十分接近（F1的差别在0.1%~0.2%）。而对于混淆后的程序而言，作者的方法相比其他工具有明显的提升。

  

![](../Images/f442ce7e4f1fa48a37af614c7f42e127.png)

  

性能方面，作者的方法在GPU上的表现远远超出其他工具，且即使在CPU上的性能也能与IDA Pro持平。
