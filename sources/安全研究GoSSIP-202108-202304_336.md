今天给大家推荐的是来自NDSS 2022的一篇论文——“Building Embedded Systems Like It’s 1996”，本文主要针对嵌入式设备攻击相关的缓解措施展开研究，作者发现大多数嵌入式设备固件都没有采用攻击缓解措施，并且旧版本的内核仍然被广泛使用。此外，作者还深入探究了嵌入式设备缺乏攻击缓解措施的原因，并构建了针对嵌入式固件和内核的缓解识别工具。

![](../Images/8133cb3e11ec3e84635dc947a1bdb561.png)

本文构建了一个针对嵌入式二进制文件和内核的缓解措施的识别工具，其工作流程如图1所示，主要包含四个过程：

![](../Images/bf9b059421a9a883f490d36f98b91619.png)

**（1）固件收集**  
作者利用爬虫扫描主流嵌入式供应商网站来收集固件。如表3所示，作者从38个供应商收集了18000多个固件，这些固件发布时间从1998到2021年，运行在4000多种不同的产品中。

![](../Images/beb3e939cb4183f9f8d68ceae69de5eb.png)

![](../Images/78839513c34ea42e27f64145666d59be.png)

**（2）固件解包**  
作者对收集的固件进行解包，并从中提取二进制程序和Linux内核。其中固件解包是基于FIRMADYNE实现的，之后根据签名来识别Linux内核，再通过Vmlinux-to-ELF将内核转换为可分析的ELF文件。  
对于18020个固件，作者成功提取了10685个（59%）；在这些解包成功的固件中，作者收集了9037个文件系统，包含大概30万个ELF二进制文件；此外，作者提取了7977个Linux内核，并成功将其中3287个转换为带符号的ELF文件。

![](../Images/7f8c7694ca63a20a5fe0fd0640cd3651.png)

**（3）缓解措施识别**  
作者主要针对五类攻击的缓解措施进行识别，分为User-space Binaries和Kernel两部分。

![](../Images/bf0d79af229de869b2595f287de4271a.png)

*   **User-space Binary**：识别给定的二进制文件中的缓解措施。以Stack Canaries为例，通常情况下，在检测到堆栈冲突时，\_\_stack\_chk\_fail会打印以“stack smashing detected”为开头的错误信息；因此，作者通过在二进制文件中搜索该字符串来定位到使用该字符串的函数（\_\_stack\_chk\_fail），如果该函数被其他函数调用，则考虑采用了stack canaries。
    
*   **Kernel**：如表2所示，作者指出可以根据体系结构、内核版本以及构建配置来确定内核级的缓解措施。
    

*   Recovery of Kernel Version：在内核中搜索字符串常量来推测其版本，如Linux version 2.6.36 (root@automake)。
    
*   Analysis with Building Configuration：检查表2中制定的关联选项在.config文件中是否启用（例如CONFIG\_HAVE\_CC\_STACK\_PROTECTOR=y），来确定内核中是否启用了相关缓解措施。
    
*   Analysis without Building Configuration：在没有.config文件的情况下，利用从内核转换的ELF文件来判断缓解措施，例如通过检测\_\_stack\_chk\_fail的存在和使用来检测Stack Canaries。
    

**（4）Mitigation Analysis**  
作者对识别到的攻击缓解措施进行进一步的研究分析。

*   **User-space Mitigation**：作者将嵌入式二进制文件用户空间缓解措施与Debian二进制文件缓解措施进行对比。
    

*   大多数嵌入式二进制文件都是动态可执行文件，其比静态文件更多的采用攻击缓解措施（表6）
    
*   不同的体系结构攻击缓解措施采用率不同（图3）。其中MIPS是二进制文件的第二大类，而其采用率最低，作者认为这是由于MIPS施加了一些硬件限制；AArch64和x64二进制文件缓解措施采用率相对较高，这是由于这两种体系结构是最近发布的，其上运行的二进制文件往往具有较新的构建环境和执行环境，更利于缓解措施的实施
    
*   不同的供应商（表5）与设备使用场景（表7）也会影响缓解措施的采用情况。
    
*   总体上，嵌入式二进制文件攻击缓解采用率不高，且明显落后于桌面二进制文件（以Debian为代表），如表5所示。

*   **Kernel-level Mitigation**：如表9所示，嵌入式设备很少采用内核级的缓解措施。作者认为一个主要原因是由于供应商倾向于使用旧版本的内核（如图14所示），而这些旧内核无法支持缓解措施。作者进一步分析了内核级缓解措施的演变（图6），结果显示缓解措施的采用率一直在增加，作者认为其背后驱动力是由于内核的升级。
