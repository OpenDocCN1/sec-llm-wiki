今天给大家带来的是，来自阿里安全双子座实验室投稿的其发表于USENIX Security 2022的一篇文章Cheetah: Lean and Fast Secure Two-Party Deep Neural Network Inference。“Cheetah”是猎豹的意思，本文通过巧妙的密码学设计，不仅将安全两方神经网络推理的速度提升到了一个新的水平，而且所需传输的密文体积也大大降低了，正好符合猎豹lean且fast的特性。

什么是安全两方神经网络推理？它解决的是这么一个问题：甲方拥有源数据(例如图片)，乙方拥有一个基于DNN的AI模型 (例如可以判断图片是否违规或者侵权)。甲自己不具有AI能力，希望能购买乙的服务来智能判断自己的数据是否有问题；但是双方的数据都是商业机密，甲不愿意把自己的图图直接交给乙，乙也不愿意直接把自己的模型参数告诉甲。乍看起来，这样的需求似乎是不可能实现的，但是安全两方神经网络推理就可以基于安全多方计算技术（MPC），让双方合作算出图片是否违规，同时甲无法获取乙的模型参数，乙也不知道甲的图图到底是什么，实现所谓的“隐私计算”，“数据可用不可见”。

在本文之前的工作如MIT的Gazelle（USENIX Security 2018)，伯克利的DELPHI（USENIX Security 2020) 由于速度太慢，基本上只能支持很小的模型，只能处理MNIST/CIFAR这种小图片。能支持ResNet50这么大的模型，处理IMAGENET这么大的图片的，唯有微软研究院出品的CryptFLOW2 （CCS 20），但是按照CryptFLOW2论文里的数字，它跑一次ResNet50需要起码十分钟，双方的密文通信量30GB起步。这明显离实用还是有很大距离的。如何进一步提升呢？猎豹从两个方向进行了突破：

突破1：同态加密

  1. CryptFLOW2需要使用秘密共享Secret Sharing（SS）+OT来处理RELU这类非线性层，通常SS有两种做法：mod 素数p（即把a拆分为r mod p和a-r mod p)，或mod 2^k（即把a拆分为r mod 2^k和a-r mod 2^k)，且CryptFLOW2已经观察到OT在mod 2^k的SS上运行代价更低。

  2. CryptFLOW2需要使用RLWE同态加密来处理卷积、全连接这类线性层，但是一般的RLWE用法中为了支持SIMD packing功能，其明文域只能是mod p。

SIMD packing在RLWE中是非常重要的，它可以把多个整数编码到多项式中, 使一次密文计算可以完成多次明文计算。下面举例说明：

可以看到，一次多项式运算正好完成了n次整数运算。这就是SIMD packing。在RLWE同态加密中，SIMD基本上是必选的。SIMD packing的数学特性限制了它的计算域必须为素数域Z_p，想支持mod 2^k的话需要进行CRT extend（怎么做本处略去），会带来数倍的计算和通信成本。


综上所述，CryptFLOW2没有办法两全其美，要么用mod p并忍受相对低效的OT，要么用mod 2^k然后用不高效的同态。

作者又观察到了一个点：

  • 数学上，卷积其实就是多项式乘法。

例：u = [1 0 1]; v = [2 7]; conv(u,v) = [2 7 2 7]， u =x^2+1, v = 2x+7, u*v = 2x3+7x2+2x+7;

而基于RLWE的同态加密中，明文正好就是多项式形式表示的！我们可以把整数编码到多项式的系数上而不是SIMD pack到多项式里面。这样去掉了SIMD的约束，计算域就不要求mod p了，可以支持mod 2^k，两全其美！

注：这里只是最简单的概念描述，为了符合DNN中的卷积、FC等操作，还需要精细的编码设计。

突破2：截断 与 Silent OT

截断协议

截断（Truncation）这个难点在2020年之前，几乎没有人提及过，其问题出在MPC的数据表示上：一般MPC下我们很难表示浮点数，因此都是用带scale（scale可以理解为精度）的定点数来描述小数的：

但是这样会带来一个问题：乘法会让数字增大一个scale的量级，这样下去只要做几次乘法，空间就会溢出了：


必须找到方法能够将Secret-share的密文截断scale倍，维持scale不变，才能继续后续的操作。

在超大规模数据应用中，这个概率将是不可忽略的（2020年之前，很多工作并没做过这么大数据量，因此这一问题并没有凸显）。

  • 注：上述概率只是按保留4~5位小数的精度来算的。如果要求更高的精度，X就会增大，出错概率还会增加。

为了解决这一问题，要么增大L（性能会降低），要么降低精度，要么放弃本地截断，设计新的不出错的截断协议。CryptFLOW2做的是后者，实现了一套昂贵的无错截断协议。而猎豹设计了一种新的截断协议，最多只会出1bit错误，比CryptFLOW2的高效得多，如下图所示。而相关工作已经表明在MPC定点数表达的背景下，原始数据本身就是小数近似而来，完全无错是没有必要的，多浮动一个比特是完全可接受的（例如上面例子里面8192变成8191）。

Silent OT

自【CCS19】起，一些新型的OT方案开始出现：Alice和Bob在进行一定的准备工作之后，双方可以近乎免费的运行Random OT！随后也有其他的类似方案【Ferret，Crypto21】被提出。本文统一将它们称为Silent OT方案。

  • 注：其实【Crypto21】认为Ferret没有完全免除通信，不能称为Silent，不过我们觉得这个争论意义不大，因为我们并不是只用Silent OT，整个MPC协议中其他步骤是无法免除通信的，所以Silent OT是否完全免除通信，对整体MPC方案的影响微乎其微。据此本文的定义是只要能做到Silent OT代价极小的，就可以称为是Silent OT方案。

Cheetah可以基于任一种Silent OT进行构造，当前我们从上手难度、国产化等角度，选择使用的是我国学者杨糠为第一作者发明的Ferret。我们简单介绍一下Ferret方案：

Ferret 是在 【CCS19 】 等研究者的一系列前沿工作上所提出的具有突破性性能改善的COT方案，同时取得了低通信量和低计算开销的双重性能指标。

这一系列方案的工作原理，是让 Sender/Receiver 双方先生成一些correlated的随机种子，然后通过一个 Extend 过程扩展出大量的VOLE，而这个Extend过程可以做到零通信，因此称为 Silent OT。Ferret 之前的方案要么 Extend 计算开销过大，要么通信下降不理想。Ferret 同时解决了这两个研究难题，并且提出了bootstrap的架构：迭代式地生成固定量的OT，并且预留一部分OT作为下一次迭代的驱动“燃料”。Ferret相比传统的OT能降低至少两个数量级的通信量。

CryptFLOW2的RELU等非线性协议是在传统OT背景下设计的，其选择的某些做法在Silent OT下有一些已经不再成立，猎豹基于Silent OT对其进行了进一步优化，大大降低了通信体积。


总结

综合上述关键突破，再加上一些其他的优化，猎豹将安全两方神经网络推理的速度提升了一个档次，最好能比CryptFLOW2快5倍，通信量下降90%。最惊人的是，猎豹还与honest majority的三方计算框架【SecureQ8】进行了对比，在带宽较低的WAN下甚至比三方计算还快！了解MPC的同学应该知道，通常情况下三方的MPC方案性能是要远胜于纯两方计算方案的。



对于近似截断协议的影响，文章还进行了大量实验, 结果发现对于所有实验图片, 猎豹输出标签向量几乎与CryptFLOW2相同, 定点数计算的预测准确度也与相应的浮点数计算的预测准确度相匹配.
