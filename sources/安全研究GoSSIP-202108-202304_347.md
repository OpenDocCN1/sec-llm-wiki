今天是三八国际妇女节，祝各位女同胞们节日快乐！今天给大家推荐的是来自USENIX Security 2022的一篇物联网协议设计的论文——“ProFactory: Improving IoT Security via Formalized Protocol Customization”。作者设计并实现了一个安全协议定制系统——ProFactory来对物联网协议进行建模、检查模型正确性并生成相应安全的协议实现。

![](../Images/7b1cea9bc06155f79ab619f8ebdd90e1.png)

目前物联网协议安全问题可以大致分为两类：

*   消息解析漏洞：如图1所示的CVE-20171000251，该漏洞能够导致缓冲区溢出，由于没有遵守请求字段长度的上限（64字节）。
    
*   状态转化错误：如图2所示的协议状态机，当设备处于info\_start状态时，可能请求消息丢失。
    

![](../Images/9e5fa1c1c1f7a0fb3c6d6e0298c7f570.png)

![](../Images/a86bacd58cb2149b7df7b416b8f2fd45.png)

这些协议漏洞促使安全协议定制变得尤为重要，其中Domain Specific Language（DSL）是目前研究协议规范设计、保证安全协议生成的一种较为常见的方法。因此，本文作者开发了一种新的DSL来定制协议消息格式和动态行为，并基于该DSL提出了一个高效安全协议定制系统——ProFactory，来促使安全的协议的设计与实现。ProFactory主要包含三个阶段：

![](../Images/45ca02df74f8f0198ea517482c8474bd.png)

（1）Protocol Modeling  
首先，开发人员使用DSL对协议进行建模/定制，ProFactory执行符号模型检查以验证模型的正确性（例如，网络状态转换不易受攻击）。

*   如图4所示，协议可以由一组与消息格式、套接字和状态机相关的抽象数据结构表示，进而被实例化为具体的类型。
    
*   因此，作者开发了一种新的DSL，利用DSL将所有协议元素抽象为分层数据类型，每种类型会在下一阶段对应一组特定的数据结构和代码块。
    

![](../Images/3d5b8fe62a7034139efefefb7aa02ffa.png)

![](../Images/75813c426448793abeedf43fd2303f7e.png)

（2）Code Generation  
ProFactory根据输入的定制协议模型生成具体的C代码。

![](../Images/dafe76cf152674d9bd0827ea4b55bef3.png)

（3）Automated Verification  
ProFactory需要保证生成的协议实现的安全性，即在消息解析和并发控制中不会存在内存安全漏洞和消息多路复用漏洞，具体包括三个方面：

*   使用VCC验证并发控制的正确性
    
*   使用Frama-C验证内存安全性
    
*   使用Z3验证状态机的正确性
    

![](../Images/5756c17dc437ec49525dbaa1c3183b8f.png)

![](../Images/307d62995b2427c34d12a3404c2d3a6b.png)

作者实现了ProFactory的原型，并用其定制了8个物联网协议，包括Linux内核中各种蓝牙协议和ZBOSS模拟器Zigbee NWK层，如表1所示。通过比较相关协议的原始实现以及ProFactory生成的协议实现，作者评估了ProFactory的性能和有效性：

*   System Performance：作者比较了原始协议实现和使用ProFactory定制后的协议实现的性能，如图9和图10所示。结果表明，总体上定制实现的运行效率略低（蓝牙降低4%，Zigbee相当），作者认为这是由于对字段进行了健全性检查以及缺乏结构布局优化所导致的；对于内存占用情况，定制实现与原始实现占用内存大小相当。
    
*   Vulnerability Averting：为了测试ProFactory生成协议的安全性，作者检索了蓝牙和Zigbee相关CVE，并在ProFactory定制实现中进行检查，结果表明ProFactory可以帮助避免82个已知CVE。
