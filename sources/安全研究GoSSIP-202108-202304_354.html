今天给大家推荐的是来自ICSE 2022的一篇讨论自动化静态分析工具错误警报的论文——“Detecting False Alarms from Automatic Static Analysis Tools: How Far are We?”，其中作者对目前已有的一些检测ASAT虚假警报工具的有效性进行了深入的探讨。

目前自动化静态分析工具（ASAT）被广泛用于开源项目的问题代码检测中，但是这些工具并不能保证所有的警报都是真正的bug，即存在虚假警报的问题。已有工作大多采用机器学习的技术来识别和删减这些虚假警报，例如通过从工具警报和修复的历史数据中提取相关特征（“Golden Features”）来判断警报的真实性。

尽管相关实验结果表明目前已有的检测ASAT虚假警报的方法和工具能够达到很好的效果，但他们的有效性却并没有得到深入的讨论。因此，本文作者从两个方面来分析并测试这些已有检测ASAT虚假警报方法的表现：

RQ1: Why do the Golden Features work?

如前所述，一些工具使用从ASAT历史警报数据中提取出相关Golden Features，来实现进一步的模型训练与虚假警报识别。因此，作者首先对这些Golden Features的实用性进行了分析测试，发现这些特征的使用存在两个问题：

  • Baseline using data leakage.
    尽管Golden Features一共包含23个特征，但有五个特征会对最终的结果产生决定性的影响。在这五个特征被删除后，测试结果F1从0.88降到了0.38，作者将这五个特征称为leaked feature。这些leaked feature会影响之前工作中分类器的有效性，并且在测试中仅使用这5个leaked features就能够得到与全部Golden Features相当的基线。

  • Data duplication.
    作者还发现已有工作中的所使用的训练数据集和测试数据集中包含了大量相同的测试实例，这会导致一个不切实际的实验环境，无法准确的判断已有工作的有效性。

作者修复了相关问题之后，在真实环境中对已有工作重新进行了测试。结果表明，尽管Golden Features具有一定错误警报检测能力，但其性能低于strawman baseline。

RQ2: How suitable is the closed-warning heuristic as a warning oracle?

训练与测试的数据集会对“Golden Features”相关机器学习模型的有效性产生重要影响。在大多数情况下，已有工作都是采用了一种closed-warning heuristic的方法来构建数据集。具体而言，该方法通过将选择的测试版本（之前）与参考版本（之后）进行比较，如果参考版本中不再出现警报（即关闭警报），则认为测试版本中的警报是可操作/修复的，否则则认为是虚假警报。

  • Choosing a different reference revision
    理论上，测试版本与参考版本间隔时间越长，关闭警报的可能性越大，那么更多的警报会被标记为可操作。作者分别测试了间隔二年、三年、四年的数据集，发现结果确实如此，这会让这种closed-warning heuristic方法的稳健性受到挑战。

  • Unconfirmed actionable warnings.
    作者进一步调查了关闭警报是否确实为可修复的警报。作者随机挑选了1357个关闭警报来检查其关闭原因，如果其中包含代码修改，则认为该警报是真实的可操作警报。
    结果表明，有176个（13%）关闭警报是虚假警报，有660个（49%）关闭警报是真实的可操作警报。这也意味着closed-warning heuristic方法的准确性有待考量，因为很多关闭警报只是偶然关闭，而不是经过真实修复的。

总的来说，本文对ASAT虚假警报的识别工作进行了深入的分析与探讨，发现目前对ASAT虚假警报的识别问题远未得到解决，已有工作强大的性能仅仅建立在有限的leaked features和重复的测试数据的基础上，而其健壮性和真实有效性仍然存在着一定的局限性，需要进一步测试与改进。
