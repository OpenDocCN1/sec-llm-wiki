今天给大家介绍的是一篇来自 RAID 2021 的论文，关注的是主流 Web 框架中部署的 CSRF 防御的有效性。作者首次对44个流行的 Web 框架中的 CSRF 防御进行了安全评估，全面系统地涵盖了源代码、CSRF防御设计、文档等方面。论文作者通过研究发现，尽管很多Web 框架中已经部署了 CSRF 防御措施，但其正确性和安全性仍然取决于开发人员对 CSRF 的认知

论文作出以下贡献：

  • 对流行的 Web 框架实现的 CSRF 防御进行了首次安全评估。

  • 对现有的防御措施和潜在威胁进行了详尽的审查，确定了16种防御措施和18种安全威胁。

  • 总结了44个最流行的 Web 框架，对550万个代码点进行了评估，以确定此框架实施的防御措施及其对18个安全威胁的应对情况。

  • 论文作者在37个流行的 Web 框架中发现了157个明显的安全漏洞，其中17个是可直接利用的，并列举出3个可以完全绕过CakePHP、Vert.x-Web 和 Play 的例子。

以下是作者排序挑选出五种语言（JavaScript, Python, Java, PHP, and C#）中最受欢迎的框架作为研究题材。


在确定好研究框架后，作者调查了一些学术文献，确定了四种不同类别的 CSRF 攻击行为。然后确定了16个不同的防御措施和18个不同的威胁模型。

下图左边的部分显示的是总结的 CSRF 防御，右侧显示的是每个防御和潜在威胁之间的映射。


在这些工作做完之后，作者对44个框架进行了安全分析。论文作者总共发现了157个影响37个框架的安全漏洞，但是这些风险的可利用性可能有所不同。

下表总结了作者对每种语言的前五个框架的安全评估结果：


作者还给出了三个严重漏洞的示例，分别是CakePHP、Vert.x-Web 和 Play 框架中的，作者指出，这三个漏洞可以被直接利用，危险性极高。

作者认为，尽管 Web 框架实现了CSRF，但它们的不正确使用也会严重影响 Web 应用程序的安全性。然而这些不正确的使用可能源于文档记录不足、缺少或误导文档、错误或缺少代码示例以及不安全的默认和配置。因此在最后，作者对这些框架的文档和 API 进行了分析。并从六个维度对文档质量进行量化排行。

在论文最后的讨论部分，作者指出，虽然研究结果表明大部分框架存在 CSRF 防御的实现，但其正确和安全性在很大程度上仍然取决于开发人员对 CSRF 攻击、防御威胁和实现特定行为的认识。
