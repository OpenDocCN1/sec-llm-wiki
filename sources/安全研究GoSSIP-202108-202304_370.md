当当当！寒假状态解除！学术论文推荐又回到了正常的状态啦~今天我们为大家介绍一篇来自NDSS 2022的论文，这篇论文关注了在Linux Kernel中存在的一类特殊gadget——transient execution gadget，看到这个名字大家都应该很清楚，这篇论文探讨的还是CPU瞬态执行漏洞（meltdown、spectre等）相关的安全问题，接下来让我们深入阅读

![](../Images/8796e7ca92f32a1a8ed97764cfb204f3.png)

来自著名的VUSec研究团队的研究人员和ETH Zurich的合作者一起，设计开发了名为`KASPER`的分析工具，去深入搜索内核中的transient execution gadget。大家可能要问，相关的问题2018年开始就已经有人深入研究了，这北京冬奥会都已经开幕了，`KASPER`有什么新特点吗？善解人意的作者首先专门做了一个“你问我答”页面，上面回答了很多疑问，这个形式非常值得我们学习：https://www.vusec.net/projects/kasper/

![](../Images/bca540fd0c0e2735cd84fc90668e27fa.png)

那接下来就是技术细节时间了，论文中，作者首先将spectre攻击必备的三个步骤进行了总结：

![](../Images/170c31037bed16f62c1938b0187fd04b.png)

然后也罗列了一些已有的方法可能找不到的gadget

![](../Images/0db23570d0cf91dc27e35f686a4764e5.png)

作者对前人的工作进行了细致的分析后，很有底气地提出自己的分析建模方法，具体地，  
(1) 使用 speculative emulation 对 transient execution 进行建模；  
(2) 开发了一系列 vulnerability detector 来建模不同的软硬件漏洞；  
(3) 利用动态污点分析技术追踪所关注的软硬件漏洞在体系结构层面和微架构层面的不同影响；  
(4) 使用 fuzzing 来对攻击者的可能覆盖能力进行建模

![](../Images/ce9765b8f5299c4566656a88c3695267.png)

针对每个步骤和组件的具体技术实现在论文中有详细描述，这里不再展开。我们接下来关注一下实现细节。`KASPER`在LLVM工具链的基础上加入了三个组件：*Kernel Speculative Emulation Unit (KSPECEM)*，*Kernel DataFlow Sanitizer (KDFSAN)* 和 *Taint Manager (TMANAGER)*, 同时还改造了syzkaller来进行kernel fuzzing

![](../Images/183fead03740073f86fac4f226f483b8.png)

作者使用`KASPER`找到了1379个此前未发现的transient execution gadget：
