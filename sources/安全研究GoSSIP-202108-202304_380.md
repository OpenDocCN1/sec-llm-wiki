# G.O.S.S.I.P 学术论文推荐 2022-01-20 D-Box

在即将召开的NDSS 2022上，有一篇关于嵌入式设备MCU上内存细粒度隔离的研究论文D-Box，今天我们就给大家介绍这篇论文的一些有趣技术细节

![](../Images/2e90d9b16d7529be9598ceb52f03c642.png)

要了解这篇论文，首先需要了解一下嵌入式MCU中常见的ARM Cortex-M系列中使用的Memory Protection Unit（MPU）的概念。MPU类似桌面平台x86/64处理器中提供的MMU，也是用来限制代码访问特定内存地址的硬件加速特性。

![](../Images/4b829cd425490fca9ddcab60cba26fa1.png)

在嵌入式设备中，单纯依赖MPU这一特性对内存访问进行限制，往往会遗漏掉一些比较特殊的内存读写渠道，本文关注的是Direct Memory Access（DMA）这一渠道，并为之针对性地设计了相关的增强型访问控制解决方案——D-Box

![](../Images/db8d07ebcc29baf31b52aee01a0c41f8.png)

在现实中，DMA从执行流程上一般可以分为如下图所示的三个阶段（设备读取DMA相关配置信息、设备执行DMA操作、设备进行DMA操作之后的清理），而作者在他们发表于IEEE S&P 2021的论文中已经指出，攻击者一般会在第一阶段和第三阶段发起攻击，因此需要针对这两个阶段设计相关的特殊防御

![](../Images/9f36bf59e4efb3255ab70867284acd21.png)

![](../Images/2bfb1fc4fa984fcca627442e6b338aa6.png)

具体地，作者基于FreeRTOS-MPU（关于FreeRTOS-MPU的更多信息，可以参考它的官方文档：https://freertos.org/MPU\_Chapter.pdf ）方案进行了改进，设计并实现了D-Box细粒度隔离机制。D-Box首先对DMA的配置信息在MPU层面上进行了细化保护，一方面它定制了更为精细内存区域划分（如下图所示），另一方面它也对DMA读写进行了分析，同时还针对FreeRTOS的内核进行了额外的增强，不允许DMA task访问起其它task的stack或者用户空间，更不允许用户空间被映射为task stack

![](../Images/7a7e1b0a77e96ecbdfd54a10abf248ff.png)

在实际执行中，和许多基于domain isolation的方案一样，D-Box首先需要等待特定的触发机制（在本文中是SuperVisor Call，SVC）来决定是否开始切换使用不同的保护策略，实际上作者的实现中进行上下文切换只需要三行汇编指令，为性能优化提升做出了很大贡献；在实现了不同的隔离保护策略的切换之后，D-Box引入了很多访问控制的经典思路来限制DMA只能执行安全的内存访问

![](../Images/6686720261fc4678d7bf27f6ff41680b.png)

和已有的一些隔离技术相比， D-Box能够执行相当全面的隔离（除了代码隔离稍弱，其它项均全面支持）：

![](../Images/c5a6b792b480042b5f25d0c61f5b9f7c.png)

另外，所有此类隔离机制都特别注重效率和可用性（此处是不是要@一下某个古都），而D-Box在这方面表现和已有系统比较起来，在提供了更为细粒度的保护的同时，开销并没有显著增加：
