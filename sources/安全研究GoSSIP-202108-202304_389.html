作为互联网世界最重要的入口之一，Web浏览器从诞生之日起就面临了最多的攻击，安全分析人员在浏览器安全上也投入了海量精力（不论是漏洞挖掘还是安全防护），那今晚我们来为大家推荐一篇关于Web浏览器安全分析的SoK论文，系统性回顾这方面的研究工作

从早年的网景（Netscape）大战IE，到如今浏览器四国大战（Chrome、Safari、Firefox和Edge/IE），浏览器作为计算机上最为复杂的软件之一，其设计和实现面临的最大挑战，是在维护上千万行代码、适应大量Web标准的同时，还要保证程序中尽可能不要有bug，或者有bug被攻击者利用时，能被防护机制拦截下来。如下图所示，现代Web浏览器的架构大都采取了诸多隔离和分割策略，来保证组件之间尽可能少的影响，同时还部署了沙盒来限制那些负责解释网页代码的组件部分；同时，浏览器还要应付令人头疼的JavaScript代码just-in-time编译问题；当然，随着网络上涌现出越来越多的媒体内容，今天的浏览器甚至要解析各种各样的文档、音频和视频格式，这足够让开发人员抓狂了吧。

作为浏览器安全的主要防护机制，沙盒一直是浏览器的“免疫系统”核心部分，除了浏览器本身的设计，充分利用运行的操作系统提供的安全隔离机制也是非常重要的设计手段。下表对运行在Windows、Linux和macOS上不同浏览器的沙盒实现细节进行了对比。特别地，作者还指出，在移动平台上，受资源所限，沙盒的实现往往有所差异。例如在Android设备上，在内存不足1.9G的时候，Chrome会默认关闭掉Site Isolation（参考Google在2019年USENIX Security上发表的论文Site Isolation: Process Separation for Web Sites within the Browser）来节省资源。

有盾就有矛，在实际场景下，不论浏览器部署了多么复杂的防护方案，攻击者往往还是能找到空子，这是因为浏览器实在是太复杂了，不论是经典的内存破坏漏洞，还是更高层的逻辑漏洞，更不要提一些利用side-channel进行的信息泄露攻击，攻击者只要能发现一个缺口，就可以逐步瓦解各种防御（如下图所示）

因此，浏览器作为CVE大户，给Pwn2Own选手和专攻bounty的漏洞赏金猎人们带来了丰厚的回报！而且这些年来，浏览器代码的膨胀速度丝毫不见减慢，漏洞挖掘机们简直笑开了花！

当然，随着时间的推移，开发者和安全专家也不会坐以待毙：随着越来越新型防护机制的部署，许多传统的攻击面很大程度上逐渐被堵住了（或者利用门槛变得非常之高）。下图显示了近年来针对浏览器各组件中攻击面利用的变化情况：

作者通过对近年来的浏览器bug进行统计分析，总结了如下一些经验教训（血泪史）：

  1. Using memory safe languages is an effective mitigation against memory-safety bugs （约等于废话）

  2. Higher payouts motivate more bug reports（又是一句废话）

  3. UAF mitigations are effective towards reducing DOM bug exploits

  4. Mitigating JS engine bugs is difficult（哈哈哈）

  5. UXSS bugs are mostly mitigated by Site Isolation

为了保护浏览器，安全研究社区也是殚精竭虑，挖空心思，从2010年起就不断有相关研究发表，我们专栏在去年也曾经介绍过，来自学术界的隔离防护机制都已经部署到Firefox浏览器上了！因此作者总结：Collaborative efforts on mitigations are good！

其次是已有的安全分析工具（主要是动态的fuzzing工具和静态的代码分析工具）在发现和确认bug（特别是复杂的逻辑类bug）方面，还不如人工审计+奖金激励更有效!

在很多时候，浏览器的防护还跟在攻击者之后亡羊补牢，如果能把一些更为主动的防御机制（例如Google的Site Isolation）积极应用在浏览器上，可能会有更好的防御效果（对抗更多的0-day攻击）
