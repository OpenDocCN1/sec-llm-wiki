# G.O.S.S.I.P 学术论文推荐 2022-01-06 IRQDebloat

在过去的10年中，有很多在 G.O.S.S.I.P 学习生活过的同学远渡重洋，前往欧美深造，他们在海外也取得了很多新的成果。今天我们就为大家介绍一篇由前G.O.S.S.I.P成员、目前在NYU学习的胡正浩作为一作发表的IEEE S&P 2022学术论文

  

![](../Images/b4e72b62ee62e7c0c419afa74d4ee9d0.png)

  

在这篇论文中，作者关注嵌入式设备中常见的中断请求（interrupt request，IRQ）的风险以及对应的防护。IRQ在上世纪个人计算机的BIOS配置中也经常见到，是外部设备对主系统发起请求传递信息的特定信号，当系统接收到IRQ时，会调用事先注册的相关例程（interrupt handler）来处理请求

  

![](../Images/326714565a3602792e2c4c9d8934d4e7.png)

  

作者指出，在嵌入式固件中，可能有很多不必要的中断处理例程，特别是在设备的driver中存在这种冗余代码。为此，作者设计了一套名为IRQDebloat的二进制代码重写系统，自动化分析并去除固件中无用的中断处理例程，对固件进行“瘦身”的同时，也提升了设备的安全性。

  

具体地，IRQDebloat充分利用了一些前序的研究成果，首先它使用了作者在2015年开发的全系统模拟器Panda，对嵌入式固件进行动态分析（收集不同的固件snapshot进行模拟执行）；在动态分析中，通过fuzzing来生成足够多的memory-mapped I/O（MMIO）返回值，以便充分遍历中断处理例程代码；然后，IRQDebloat利用differential slicing技术（在2011年IEEE S&P论文中提及），从多次相关动态执行的trace中，识别出中断处理例程，最后开展二进制代码重构：

![](../Images/ec47ba1a69107623b3fcc08324a4ea89.png)

  

  

作者对大量不同的嵌入式系统进行了分析，对其中使用的IRQ handlers也进行了相关的统计：  

  

![](../Images/454914f260ff27012937ff51bebb166e.png)

  

![](../Images/d9a64793ded60246c0e03c6d16213cc5.png)

  

通过构建相关的ground truth，作者得以在后续的fuzzing中确定是否能充分触发这些handler。作者的分析表明，所有这些handler中，只有两个特殊的、被系统屏蔽的handler无法被fuzzing触发，其它的都可以在合理时间内被动态执行覆盖到  

  

![](../Images/c5dbb85de706eca01f22dd2dc7959e8c.png)

  

进一步，通过测试IRQDebloat的代码瘦身，作者发现，仅有Timer和inter-processor interrupt（IPI）相关中断请求是非常关键的，其余的handler均可进行精简

  

![](../Images/7a4a531a60a38f514f200afafaf634a7.png)

  

通过IRQDebloat的处理，作者发现很多已知CVE相关的攻击可以完全被屏蔽：

![](../Images/dd2eb2a2542ddfe974e58da25a0d4df1.png)
