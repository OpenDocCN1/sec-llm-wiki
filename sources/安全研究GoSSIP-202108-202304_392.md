# G.O.S.S.I.P 学术论文推荐 2022-01-05 Deplmpact

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=Mzg5ODUxMzg0Ng==&mid=2247488417&idx=1&sn=073095dfaaf8552842acdb8130bc8417&chksm=c0603d78f717b46e326a24a380fed4612291dc8edffcb421195cfafd1ef0dfdca667205b17ca&scene=126&sessionid=1681404216#rd](http://mp.weixin.qq.com/s?__biz=Mzg5ODUxMzg0Ng==&mid=2247488417&idx=1&sn=073095dfaaf8552842acdb8130bc8417&chksm=c0603d78f717b46e326a24a380fed4612291dc8edffcb421195cfafd1ef0dfdca667205b17ca&scene=126&sessionid=1681404216#rd)

2022年的第二篇论文推荐是来自[凯斯西储大学RISE Lab](http://mp.weixin.qq.com/s?__biz=Mzg5ODUxMzg0Ng==&mid=2247485053&idx=1&sn=90f26a427f70b501c69a847f4994a7d7&chksm=c06028a4f717a1b21422492292b2986bb29da4a2b20ea719b4efcfcd49f16ab70f4adaac2723&scene=21#wechat_redirect)投稿的关于攻击检测的最新工作***Back-Propagating System Dependency Impact for Attack Investigation***，目前该工作已经被USENIX Security 2022录用。

  

![](../Images/dab96a023bdac8634ab3a9e5d2df34fa.png)

目前互联网的完全形式变得日益严峻， 许多公司和政府机构成为了黑客的攻击目标。这些攻击通常涉及到多个漏洞的利用， 具有时间跨度长，步骤多等特点，对攻击检测与调查提出了新的挑战。目前的攻击检测与调查方法多是基于内核系统调用的图模型， 并在此基础上做进一步的因果分析（Causality Analysis). 但这种分析通常需要付出大量的人力劳动才能获得攻击相关的过程信息，这是由于由系统调用信息产生的图规模通常十分巨大。

  

![](../Images/46b095d68859ebe9eb60d386dde383f3.png)

  

以上图为例，图的节点代表着进程， 文件，IP 地址， 边则代表着不同的系统内核调用，例如send, write,read 等等, 此图包含约20万个节点，3百万条边， 深色部分表示攻击相关的部分，称为crtitical edge (关键边)。关键边只有12条，仅仅只占图的一小部分。

  

为了解决这个问题，在本文中，团队作者提出了DepImact。该工具可以有效的检测出攻击相关的过程信息和涉及到的系统对象, 并且不依赖与提预收集的数据或者模型。

  

![](../Images/3795597932c783b39e9b876786e1d794.png)

  

DepImpact的工作流程可以分为**三个阶段**：

**第一阶段**，根据检测到的系统异常事件和系统调用日志产生相应的图。 

**第二阶段**，根据输入的可疑事件 (Point-of-Interest event), DepImpact 会根据可疑事件发生的时间，数据流， 以及一些图特征，等计算图中所有边的数据特征。为了最大化攻击相关部分和不相关边的权值区别，DepImpact 会基于边聚类的结果，进行LDA运算（Linear Discriminant Analysi），计算得到最佳投影， 并依据此将不同特征值融合为图中边的权值。 

**第三阶段**，受PageRank的启发， DepImact 依据权值信息迭代更新 图中所有节点对于POI事件的dependency score。待迭代数值稳定后，DepImpact 会依据这个dependency score 对于图中只有出边没有入边的节点进行排序。依据排序结果，DepImact 会选取排位靠前的进程，文件， 网络节点进行前向分析 （forward causality analysis）。前向分析结果和由POI event 开始的后向分析结果产生的交集是DepImpact的最终输出，其中包含了攻击相关的节点和边。团队使用了广泛的攻击数据来测试DepImpact在攻击调查方面的表现，其中包括DARPA TC的公共数据， 数据集总共包括了高达1.5亿个系统调用数据。

  

![](../Images/21aa46f4cffba9b2248c3108f23369ef.png)

  

实验结果表明。相较于原始图平均包含1百万条边的规模，经过DepImpact的处理，最终图只包含数百条边，规模缩小4000多倍， 并且保留了攻击相关的部分在最终输出中。

  

下面作者用一个实验中用的攻击Shellshock来阐述DepImpact生产攻击相关部分（critical component）的流程。此攻击涉及到了多台机器和不同的POI event, 具体的调查过程如下。

  

![](../Images/5468ab67fd25635e4cfbaef123bbc073.png)

  

对于host 1, 由于发现了可疑文件（password.tar.bz2）， 因此用此文件作为DepImpact的输入，在经过DepImpact 相关分析后，网络通信节点host2->host1 为攻击相关节点，从此节点出发的前向分析和原始图的交集为攻击的相关部分（critical component）如图中最左侧所示，由此实现了对图尺寸的缩小。因为发现了代表host1与host2的通信节点， 又在host2上以此通信节点作为DepImpact输入，发现了可疑脚本（crackpassword.sh）的下载, 并且此图上再一次出现了host1 与 host2的通信节点， 在host1上以此通信节点作为poi 输入， 发现了同样恶意脚本的下载。通过DepImpact 的分析， 可以重建具体攻击流程如下，攻击者首先渗透了host1 并下载恶意脚本crack\_password.sh, 并通过scp 将此恶意脚本发送至host2， 并且执行， 在收集完用户信息后，将此信息发送回host1，经压缩后上传回attacker. 至此，DepImpact 完成了一个对于涉及到不同机器， 不同POI event的复杂攻击的调查分析。
