# G.O.S.S.I.P 学术论文推荐 2022-01-04 VPDroid

今天给大家推荐的来自ICSE 2021的一篇关于Android app自动登录功能安全性的文章——"App’s Auto-Login Function Security Testing via Android OS-Level Virtualization"。

![](../Images/d0a4e026a66fb8442741ffb9749f300c.png)

如今，许多Android app都支持自动登录功能，即用户在完成一次登录验证之后，每次启动app无需重新输入登录凭证即可登入账户。此类自动登录认证功能通常是通过存储在用户手机上的**凭证数据**和**设备一致性**检测来实现的。例如，微信app会将登录凭据信息和连接信息存放在 "/data/data/MicroMsg/" 目录下，以实现自动登录功能；如果将该目录下的所有数据复制到另一台手机时，由于微信app检测手机环境，仍然不会登录成功。  

![](../Images/2fc38bf3a06344c738469abfa92e697d.png)

本文作者指出这种自动登录的功能可用于实现数据克隆攻击。在此类攻击中，攻击者能够通过三种途径获得受害者登陆凭据数据：  

*   受害者设备已被root，攻击者可以通过物理访问受害者设备或利用恶意app窃取凭据数据
    
*   受害者设备没有被root，攻击者可以通过手机克隆app的漏洞来实现数据窃取
    
*   如果攻击目的是实现订阅欺诈（subscription fraud），攻击者对受害者设备有完全控制权，则可以使用手机制造商的手机克隆app来复制数据
    

作者从Google Play、华为应用市场、小米应用市场获取了234个下载量超过100万的app。作者首先进行简单的数据克隆测试，发现经过直接的数据复制之后，234个app中有131个app可以直接登入（表2）。

![](../Images/705446b62d4207701087fb099c53b2b6.png)

无法成功登录的app中，一部分是由于检测到了设备环境的变化，作者利用设备属性编辑工具XxsqManager，通过API hooking来编辑设备属性，并再次进行数据克隆攻击；103个app中，有17个app能够成功登入（表3）。对于剩余86个app，作者认为这些app会检测到API hooking机制的存在，例如会检测到包名、native方法名、共享对象中的可疑信息。针对此，作者实现了VPDroid，具备更好的透明性和属性可编辑性，能用来实现对剩余的全部86个app的数据克隆攻击。

![](../Images/27a42ba6eb4e444c63eb0de21aac8af8.png)

VPDroid系统是基于Cells虚拟化系统实现的，其中对Cells的改进集中在两个方面：  

*   实现了用户级设备虚拟化，来提供更好的透明性
    

*   针对在ServiceManager中注册过Binder object的服务，采取**Binder Service Sharing**。具体而言，作者修改了Linux Kernel中的Binder driver，为VP创建了专属的Binder driver数据结构，其中包含一个handler，指向Host的context\_mgr\_node，进而关联到ServiceManager中的相关服务。
    

![](../Images/0bc6f9cd4d9a397f2a938f37b610c83e.png)

*   针对未在ServiceManager中注册过的匿名服务，采取**Device Namespace Proxy**。
    

![](../Images/19251b6fbdbef37cf02c0e7c2ddd380f.png)

*   允许使用者自定义VP设备属性
    

![](../Images/e68add7fb7d9f291989e1a668ca563fa.png)

作者对VPDroid的性能以及数据克隆攻击可行性进行了评估，针对全部的234个app，VPDroid均能完成数据克隆攻击。
