2021年的倒数第二天给大家推荐的是来自ACSAC 2021的一篇关于工业控制系统模糊测试的论文——"ICS³Fuzzer: A Framework for Discovering Protocol Implementation Bugs in ICS Supervisory Software by Fuzzing"。

![](../Images/2c0e79c1765163efdd924606c54c9260.png)

工业控制系统（ICS）通常由三层组成：1）Field Instrument Control Layer由系统传感器和执行器组成；2）Process Control Layer由专用设备（PLC/RTU）来实时控制；3）Supervisory Control Layer由多个工作站组成，提供设备实时监控。

![](../Images/858faf4b8ae8f2f845bbd8a3afc61156.png)

一个典型的ICS交互过程如图4所示，管理者首先需要点击connect按钮来开启监控软件和PLC之间的TCP连接，之后点击download按钮来完成下载程序到PLC的操作。作者发现监控软件在不同的交互状态下有不同的代码执行行为，例如点击connect之前download按钮为灰色（不可点击）。如果攻击者能够发现利用监控软件与PLC之间通信交互过程的实现缺陷，将会对整个ICS系统的安全性造成威胁。

![](../Images/8d156b1866b5cb2f7dc02517d8d307f9.png)

![](../Images/3f86fd3c2603ac0311290136e6bd6b20.png)

本文提出了一个ICS监控软件自动化模糊测试框架——ICS³Fuzzer，其实现主要包含两个阶段：  

**（1）预处理阶段**：分析给定监控软件的功能和私有协议。  

*   功能分析：ICS³Fuzzer实现了guiAutolits，通过识别GUI句柄、操控GUI空间以及UI操作的执行，来启动相关的ICS功能。
    
*   私有协议分析：ICS通常会实现私有协议来完成通信，ICS³Fuzzer在这一步解析监控软件与PLC设备之间交互过程所使用的私有协议。
    

*   Inferring Protocol Format：作者利用已有工具Netzob来对私有协议格式进行解析。
    
*   Obtaining State-Space：在监控软件中，一个会话通常涉及多种输入状态，需要能够区分不同的输入状态来提高模糊测试效率。传统的方法是通过简单的比较消息之间的相似性来区分输入状态，但并不精准。由于不同的执行流通常会生成不同的消息，并且即使消息中的微小差异也会有十分不同的执行流，因此本文作者通过记录不同输入状态的执行流来区分不同的输入状态，以实现筛除重复相似的输入状态。
    
*   Device Emulation：为了降低成本，作者模拟了PLC设备的响应消息来实现自动化的状态切换。作者观察到同一设备同一功能产生的网络流量十分相似，但仍有细微差异（动态字段），因此ICS³Fuzzer首先通过比较实际通信流量之间的差异来获得动态字段，之后自动查找和修改相关动态字段来模拟PLC响应。  
    

**（2）Fuzzing阶段**

*   状态选择：作者为每个输入状态的相关属性分配一个权重，以此来决定有意义的模糊状态。权重分配基于三个假设：
    

*   网络通信越深入（顺序靠后），存在漏洞的可能性越大
    
*   消息被转发至监控软件中，越多新的基本块被触发，存在漏洞的可能性越大
    
*   越复杂的输入，存在漏洞的可能性越大
    

*   输入生成：ICS³Fuzzer利用获得的协议格式生成变异输入。
    
*   数据输送：ICS³Fuzzer利用一种基于代理的方式来自动化的向监控软件提供数据，如图7所示。
    
*   崩溃监控：ICS³Fuzzer监控Windows事件日志来捕获崩溃。
    

![](../Images/ba5822d6cb44365bd39520673b776ade.png)

作者实现了ICS³Fuzzer原型，并使用ICS³Fuzzer对四款ICS监控软件进行评估。ICS³Fuzzer一共发现了13个内存破坏漏洞，会有40种产品会受到影响。
