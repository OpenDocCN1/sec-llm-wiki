G.O.S.S.I.P 学术论文推荐 2021-12-28 RapidPatch

二进制代码的热补丁（hotpatch）是安全防护领域的一个热门研究课题，G.O.S.S.I.P 在2017年ICSME会议上发表的论文Embroidery: Patching Vulnerable Binary Code of Fragmentized Android Devices就讨论了如何针对厂商已经不再更新的Android设备开展二进制代码层面的（内核及系统框架）漏洞修复。今天我们要介绍的这篇USENIX Security 2022论文则将关注点聚焦在嵌入式设备上，提出了一种新型的固件二进制代码快速修复机制

作者指出，尽管Linux内核之类的系统很早以前就开始考虑热修复补丁，并已经存在如KProbe和Ksplice等机制，但是在嵌入式设备特别是real time OS（RTOS）上，目前比较新的研究工作是NDSS 2021会议论文HERA: Hotpatching of Embedded Real-time Applications中提及的HERA系统。不过，在碎片化极其严重的嵌入式生态环境中，HERA的适用性存在很大不足，例如对Xtensa、AVR和RISC-V等架构支持性不够，同时还需要厂商配合提供源码的情况下才能生成binary patch等。因此，本文提出了RapidPatch框架，试图一举解决前序工作的不足之处

RapidPatch框架同以前的一些工作相比，其中一个很大的特色是它使用了非常fancy的Extended Berkeley Packet Filter (eBPF) 技术，关于eBPF的细节可参考eBPF Documentation，大家可以把它想象成是一个代码解释器（想象一下很多嵌入式系统中现在会集成Lua来实现灵活的可编程运行）

有了强大的eBPF加持，RapidPatch的工作流程就很清晰了：开发者只需要为特定的漏洞开发C代码的补丁，然后相应地生成eBPF字节码补丁，再将其应用到有问题的固件上（这一步还是要通过设备厂商来执行更新，当然也需要固件本身支持RapidPatch），完成实时快速的热修复。

RapidPatch生成的patch分为两种，一种是filter patch，顾名思义就是对input进行过滤和净化的patch；另一种是code replace patch，直接替换有问题的代码

RapidPatch主打性能和全面性两张王牌：既能支持快速高效的热修复，同时支持大量的操作系统和架构（而且不需要为不同的架构去逐一适配）
