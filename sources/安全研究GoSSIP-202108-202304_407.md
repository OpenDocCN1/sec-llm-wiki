今天给大家推荐的是来自ASE 2021的一篇论文，作者研究了安卓系统中Native Framework API权限问题

![](../Images/bbf3919d3f221399414be2d37a30350c.png)

在这篇文章中，作者的关注点落在了Android中的Native Framework API，设计并开发了静态分析工具PSGen，通过静态分析Android Framework和Android Kernel，将Native Framework API与调用该API所需的权限相关联，从而构建了一套权限规范（permission specification）。

作者首先指出，目前大量的安卓app通过native code来实现功能。例如，作者发现从第三方应用市场下载到的超过266,000个app中，约有82%的app包含native code。作者进而指出，现有的有关安卓系统中权限规范的研究大多针对Java Framework API，而不去关注Native Framework API。同时，Google提供的文档中也缺乏对Native Framework API权限的相关说明。例如，下图对比了Google官方文档中对camera服务的Java Framework API和Native Framework API的说明。这两个API均可以被调用来打开摄像头设备，对其的调用也均需要CAMERA权限，但是对Java Framework API的说明中列出了所需权限，而对Native Framework API的说明中则缺少相关信息。

![](../Images/518aba91ddfb959e825e539d53a239b2.png)

因此，作者所要实现的目标就是，构建一个分析工具，来自动生成Native Framework API的权限规范。作者首先将Native Framework API分为三类，划分的依据是app进程与service进程或者kernel交互的方式。

第一类Native Framework API会在内部调用service的Binder local interface，而app进程通过调用该Native Framework API来请求服务。例如下图中展示的ACameraManager\_openCamera，就是一个这样的API，该API位于libcamera2ndk.so库中，app可以调用该API来请求camera服务，打开相机。

![](../Images/af952ba7b3bda3f38a6ca629ac3040d1.png)

第二类Native Framework API是用于获取service的Binder proxy的API，而app进程通过调用这些Native Framework API来获取service的Binder proxy，进而调用Binder proxy的transact函数来请求service。其过程如下图所示。

![](../Images/af49b38cc950c9e62089dca04c924199.png)

第三类Native Framework API会在内部执行system call，而app进程通过调用这些API来与kernel进行交互。这类API中的代表是socket。socket会通过syscall函数来执行\_\_NR\_socket系统调用，该系统调用最终被kernel中的sys\_socket这个handler处理，如下图所示。

![](../Images/6d1ec80cb0bdad5556666e0222af770d.png)

作者设计的权限规范生成工具名为`PSGen`，通过静态分析Android Framework和Android Kernel来构建Native Framework API的权限规范。以下图（Fig.2）为例：首先，PSGen识别在validateConnectLocked 中执行的权限检查（第9行）。然后，PSGen会找到camera服务的调用受权限限制的接口（即第5、6行的connectDevice接口），并将其与被检查的CAMERA权限相关联。随后，PSGen找到从ACameraManager_openCamera这个API到connectDevice这个接口的调用路径，并进一步将CAMERA权限与ACameraManager_openCamera这个API相关联。

![](../Images/f6bf8e683a4ceea3547cd3b5cd6a5820.png)
