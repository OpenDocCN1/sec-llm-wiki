今天为大家推荐的论文是来自浙江大学NesaLab投稿的，关于IoT内核漏洞挖掘论文CPscan: Detecting Bugs Caused by Code Pruning in IoT Kernels，该工作已经被CCS 2021录用。



为了降低研发时间和成本，物联网厂商倾向于通过定制 Linux 内核来构建IoT 内核。在代码定制化过程中，代码修剪十分普遍。然而IoT 内核缺乏长期有效的维护，此外，由于Linux内核固有的复杂性，物联网厂商可能会在修剪过程中错误地删除必要的安全操作。相关安全操作的删除会导致多种内核错误，例如内存泄漏和空指针引用。然而，检测IoT 内核中由代码修剪引起的安全错误很困难。具体来说，(1)代码定制化后，程序结构的变化使得精确定位被删除的安全操作 (deleted security operations，𝐷𝑆𝑂) 变得困难，以及 (2) 推断 𝐷𝑆𝑂 的安全影响并非易事，因为它需要复杂的语义理解。



在本文中，团队提出了 CPscan，该工具可自动检测IoT 内核中由代码修剪引起的错误。首先，通过使用一种新的基于图的匹配方法，CPscan迭代地进行结构感知的基本块匹配，准确有效地识别物联网内核中被删除的安全操作。在图匹配过程中，只进行一对一匹配（一个基本块对一个基本块的匹配）可能会漏掉很多基本块对，造成较高的误报和漏报率。因此，为了保证图匹配的精度，我们考虑一对一匹配和一对多匹配（一个基本块对多个基本块的匹配）。一对一匹配的主要思想是，当最大公共子图为空时，我们使用包含安全操作的基本块作为种子基本块来引导初始快速基本块匹配，原因是包含相同安全操作的基本块更有可能被匹配。在最大公共子图更新后，我们利用最大公共子图来指导已经匹配的基本块对的邻居节点的匹配——如果两个基本块指向或来自相同匹配的基本块，则它们很可能相似。通过这种方式，CPscan可以准确有效地识别函数对中大部分的一对一匹配。在一对多匹配中，对于一个与N个基本块相似的基本块，我们首先将N个相似的基本块按照它们的CFG顺序链接起来，构造一个新的基本块，然后对新构建的基本块进行一对一的匹配，以确认此一对多匹配的正确性。如果一对一匹配的相似度低于我们定义的阈值，CPscan会将N个相似的基本块重新排序，并再次将它们链接到一个新的基本块以重复一对一匹配。如果 N 个基本块的所有排列的一对一匹配失败，则丢弃该匹配。

其次，CPscan通过比较与安全操作相关的安全关键变量的有界使用链（变量在可能受影响的代码段中的位置和使用方式）来推断被删除的安全操作产生的安全影响。具体来说，如果相关安全关键变量的有界使用链在安全操作删除前后保持不变，则 CPscan会将安全操作的删除报告为漏洞。这是因为安全关键变量的未更改使用意味着IoT内核中可能同样需要该安全操作，删除它可能会影响代码安全。团队对三种类型的安全操作（安全检查、变量初始化和资源释放）进行了检测，对10 个物联网供应商的 28 个物联网内核进行了实验。实验结果表明，CPscan能够识别IoT内核中3193个被删除的安全操作。此外，CPscan能够以较低的误报率识别 114 个新内核漏洞。
