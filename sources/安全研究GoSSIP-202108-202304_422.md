之前我们为大家推荐了由香港中文大学张克环研究组、[加州大学尔湾分校李洲研究组](http://mp.weixin.qq.com/s?__biz=MzA5MzQ1MDI2MA==&mid=2456040870&idx=1&sn=d95659831b914eb344d0c265a45a698a&chksm=87cd2cddb0baa5cb650fc66139ccc63355035cc852172a75b4a6cd9c3d8b290648150574f9bf&scene=21#wechat_redirect)、[山东大学刁文瑞研究组](http://mp.weixin.qq.com/s?__biz=Mzg5ODUxMzg0Ng==&mid=2247485473&idx=1&sn=360d2f24855bf4f8c6c7e0fad5b22198&chksm=c06026f8f717afee02970217562520ebb109021bd82421d34b405987d5286b3f738dba6564bb&scene=21#wechat_redirect)发表在今年CCS上关于[Android模拟器（Android emulator）安全性分析](http://mp.weixin.qq.com/s?__biz=Mzg5ODUxMzg0Ng==&mid=2247487821&idx=1&sn=16f82600829c8607981fc830a525cef0&chksm=c0603f94f717b682c396250ef6416712fc98a67dad8ced1bf4130cbe4e12d0cf99cdc026d245&scene=21#wechat_redirect)的最新研究，Android on PC: On the Security of End-user Android Emulators，我们今天特地邀请到这篇论文的一作来为大家进一步解读这篇工作的亮点👏

  

![](../Images/c5361f5dcf7c0f83f73c6efa67a28d46.png)

  

作为主流的移动系统，安卓同时也以模拟器的形式被移植到了PC平台，方便用户在桌面系统运行手机app。安卓模拟器（Android Emulator）主要用于以下两种用户场景：面向安卓开发者和面向终端用户（end-user）。前者比如Android Studio内置的模拟器，主要用于app的开发测试；而后者适用于普通用户如游戏玩家等，可以增强用户的体验，因而此类模拟器中可能存在大量的用户隐私信息，例如游戏账号与凭证，应用商店账号与凭证，用户浏览记录等。这篇文章主要对面向终端用户的Android emulator进行了安全分析，首次揭露了这类平台中存在的共同安全问题。如下表统计，此类模拟器已经有着广泛的使用。  

  

![](../Images/8009da5936d3ed7ef4e41e8d5fe77a46.png)

  

**「模拟器特征与典型架构」**  

典型的模拟器主界面如下图所示：

![](../Images/973e417621dd907f1415c06315719808.png)

除了显示Android屏幕部分，模拟器提供了许多有用的功能与配置选项，分布在侧边栏或者导航栏中。例如，除了在emulator内置应用商店安装app，用户也可以安装保存在host OS的APK文件；通过键盘模拟Android屏幕上的点击操作；back/home/截屏功能键等。然而这些功能的触发是发生在host侧的模拟器UI上，需要某种通信机制传递到Android OS中才能真正实现对应的功能。通过对主流模拟器的逆向分析，作者总结出了典型的模拟器架构模型，如下图所示：

  

![](../Images/607abfdc5d80aeeb4002901c8bd79702.png)

  

其中，Android系统运行在Virtual Machine进程中（VMCore），host侧主UI进程（WinShell）可以通过host-guest communication channel 和其进行通信交互。这类channel包括虚拟机提供的服务比如VirtualBox的shared folders，configurations；以及模拟器自己定制的TCP/UDP连接或virtual device通道。Android系统中通常会有一些privileged daemons （如图中HostService进程）来接受并处理host的命令和数据，这些进程也可能继续通过Android内部IPC channels传递给其他进程来处理。如果上述channels没有得到充分的保护，那么attacker就可以利用与其关联的一些敏感服务来绕过Android的安全模型对用户进行攻击。 

  

**「攻击与后果」**

作者总结了模拟器主要的特性并标注出其中六种安全敏感的功能与服务，如下图所示。

  

![](../Images/957d7bb7a0f58a3bead23db67250013e.png)

通过固件比对，VirtualBox配置与日志文件检查，网络与文件访问监控，静态逆向，动态抓包、重放与注入等方法，作者分析了模拟器中用户输入、APP侧载安装、导航栏管理、ADB等高风险功能的实现，并构造了对应的attack：

*   Input Spoofing：伪造用户输入法/触摸/键盘输入
    
*   Keylogger：监听用户输入（通过passive sniffing或active MITM）
    
*   Installation Hijacking：劫持app安装，实现钓鱼攻击等（通过直接命令注入或race condition attack）
    
*   Tab Session Hijacking：劫持导航栏的打开/切换app行为，实现钓鱼攻击等
    
*   ADB/Shell Abusing：利用ADB或其他privileged daemon提权（如获得root权限）
