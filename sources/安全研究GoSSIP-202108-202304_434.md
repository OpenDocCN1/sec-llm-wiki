# G.O.S.S.I.P 学术论文推荐 2021-11-12

今天给大家推荐一篇Usenix Security 2022上的与fuzz相关的工作——MORPHUZZ: Bending (Input) Space to Fuzz Virtual Devices。文章的作者设计了MORPHUZZ工具，其利用hypervisor结合覆盖引导的fuzz技术来查找虚拟设备实现中的bug，并且MORPHUZZ工具不需要有初始种子输入。

  

![](../Images/f5dc11e65479bafae75742731b343dcf.png)

  

MORPHUZZ工具弥补了现有fuzz工具的不足，消除了fuzz工具在实现了复杂I/O协议的虚拟设备上的使用障碍。MORPHUZZ工具设计的两个核心原则是重塑输入空间以适应I/O内存布局的动态变化，以及针对任意的DMA活动进行优化。MORPHUZZ工具将PIO域和MMIO域隔离开，以此确保每个产生PIO/MMIO交互可以成功触发虚拟设备代码。除此之外，其利用hypervisor的DMA api透明地生成能够满足复杂语义依赖的输入策略。下图展示了MORPHUZZ工具的大致流程。

  

  

![](../Images/650ae6d8c1673b82cd67351d8675d6a9.png)

  

为了评估MORPHUZZ工具的性能，论文的作者从多个角度进行了衡量。相关的测试与比较数据如文末图片所示。

  

实验运行在Debian 10系统的虚拟机上，其硬件条件为小主机(16核Xeon CPU与128GB内存)与大主机(28核Xeon CPU与384GB内存)。每个虚拟机的配置为双核加上4GB内存，其中运行的QEMU版本为5.0，bhyve版本为12.1（为了与先前工作进行对比选取了相同版本）。

  

1）发现bug数量：MORPHUZZ工具成功找到了110个bug。其中完全覆盖了Nyx工具所找到的44个bug(其中16个QEMU相关的bug以及28个bhyve相关的bug)，并发现了66个新的bug(其中61个QEMU相关以及5个bhyve相关)。

  

2）工具实现的通用性和扩展性：除了对x86/x86-64架构的设备进行模糊测试，MORPHUZZ工具还找到了5个ARM设备上的bug，其中包括了所有面向云的ARM QEMU虚拟机中都存在的UAF漏洞。（考虑到先前工作无法针对ARM架构进行检测，因此这里发现的bug没有计入上述110个bug中）。由此可以说明，MORPHUZZ工具具有较好的跨架构扩展性和通用性。

  

3）代码覆盖效率：从文末图片的结果中可以看出MORPHUZZ工具的代码覆盖率比先前工作高出很多，最多增加了53.89%的覆盖率。在总共33个虚拟设备实现的测试中，平局代码覆盖率达到了81%。

  

4）隔离策略的选择对性能的影响：论文的作者还对MORPHUZZ工具做了其他设定（除了隔离策略的设定）来研究隔离策略对性能的影响，发现程序的稳定性出现了下降，不如加入隔离策略好。
