今天的论文推荐我们给大家介绍一篇由南方科大张殷乾老师的学生作为一作发表的Usenix Security 2021论文，主要针对AMD的Secure Encrypted Virtualization (SEV) 进行侧信道安全分析

![](../Images/b81771b4ea8165886f501f76c648c5ff.png)

  

本文作者提出了名为CipherLeaks的攻击，该攻击主要利用了AMD的SEV设计问题，实现了密文侧信道攻击。高权限的攻击者(hypervisor)可以推断出虚拟机客户端的执行状态，甚至可以恢复出明文数据。此攻击也成功撬开了常量时间密码算法实现防护的大门。该攻击的影响范围涉及到SEV的各个包含此设计问题的版本，除了SEV-Encrypted State (SEV-ES)存在此漏洞之外，最新的SEV-Secure Nested Paging (SEV-SNP)也不能幸免。

  

CipherLeaks攻击针对了SEV内存加密模块的实现弱点，主要利用的是SEV机制中 VM Save Area (VMSA) 的信息泄露。VMSA用于VMEXIT阶段，存储当前虚拟机的一些寄存器状态信息，是一个加密的内存模块。其内容样例如下图所示：

![](../Images/f68cffcb3e85cacc2c8056d6ad5a24f4.png)

  

然而VMSA使用了一个非常不安全的加密机制，出现了类似ECB加密模式攻击这种问题，针对此设计问题，本文主要将重心放在对VMSA密文的检测上，并且构造了两类攻击原语：执行状态推断 (execution state inference)和明文恢复 (plaintext recovery)。执行状态推断用于定位目标函数在执行过程中的物理地址，并推断出一个进程中真正执行的函数是什么。攻击样例如下图所示，当hypervisor可以获取到虚拟机上正在运行的代码之时（下图a），可以在callq之前使代码发生错误，然后与正确状态的NPF (nested page fault) 进行比较，由此可以得到某个callq时的寄存器状态改变信息。

  

![](../Images/ec2819f62cf850b2b48085a468929f57.png)

  

明文恢复可以将某些密文块的明文恢复。由于hypervisor具有读取VMSA的权限，即具有IOIO\_PROT的操作权限，该操作可以帮助hypervisor在处理NPF的时候记录已知明文的寄存器密文，进而可以建立明文密文字典。hypervisor可以收集到的所有明文范围如下：

![](../Images/41269da9765e07f036940d6c5da4e121.png)

  

  

作者利用CipherLeaks攻击，针对最新OpenSSL库中的RSA和ECDSA (两个算法均为常量时间实现) 均获取了私钥信息。在作者的实验环境中（AMD EPYC 7251处理器，虚拟机设置了SEV-ES-enabled，虚拟机环境还包含一个虚拟CPU, 4 GB DRAM和30 GB存储容量)，利用CipherLeak攻击方法针对上述两个算法各偷取10次私钥信息，结果表明此攻击方法以100%的正确率泄露出了私钥信息。其中获取2048-bit的RSA私钥的平均时间为0.0490秒，获取ECDSA私钥信息的平均时间为0.0033秒。

  

最后作者还分别从软硬件的角度，提出了针对CipherLeaks攻击的对策。其中软件角度的措施不能很好的解决问题，或者依旧存在漏洞。硬件角度的防御措施比较可行，其包括以下两点：

  

\- 禁止hypervisor读取虚拟机内存。

\- 通过硬件操作产生随机数，在密文计算的过程中加入随机化操作，防止相同地址的数据加密后得到相同密文
