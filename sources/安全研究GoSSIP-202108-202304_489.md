九月的第二天为大家推荐的论文是来自约翰斯霍普金斯大学[曹寅志](http://mp.weixin.qq.com/s?__biz=MzA5MzQ1MDI2MA==&mid=2456041267&idx=1&sn=a5dbe0834e29267f6249757376cd7bc8&chksm=87cd2e48b0baa75e26ea4adb16ecd4443756923859593d9a26b41cd9c67c53b7e24ad7259b7f&scene=21#wechat_redirect)研究组投稿的，目前已经发表在软工顶会ESEC/FSE上的论文***Detecting Node.js Prototype Pollution Vulnerabilities via Object Lookup Analysis***。

  

![](../Images/f38bcad7da48fa1742521b26cdb395bc.png)

  

JavaScript作为一个稳定且灵活度高的语言，被广泛应用于诸如前端开发或者后台Node.js开发等各种应用场景中。同时，许多JavaScript的特性为开发者提供了很高的开发自由度。在这其中，原型链就是一种很具代表性的语言特性。在JavaScript中，一个对象可以通过原型链来继承该对象的原型的属性。同时，JavaScript允许开发者通过原型链对某个对象的原型属性进行修改，从而方便的定义某个原型的属性。

  

与此同时，这个灵活的原型链特性也带来了一个严重的安全漏 -- 原型链污染。在2018年，由Olivier Arteau等人发现攻击者可以通过赋予某些变量特殊的值，从而进行原型链回溯来攻击有漏洞的代码，进一步重新定义某些JavaScript内置的属性。例如在代码obj\[a\]\[b\]=c中，如果攻击者可以控制a，b和c的数值，a，b和c可以被分别赋值为”\_\_proto\_\_”，”toString”以及 “hack”。自此以后，JavaScript的内置属性”Object.prototype.toString”就会被改写为”hack”。在改写之后，所有原型为Object的对象的”toString”属性都会被识别为”hack”。此类攻击可能造成诸如拒绝服务，远程代码执行等严重后果。

  

目前原型链污染漏洞的检测工具并不多。Arteau等人尝试通过赋予特殊用户输入，然后观察运行结果的动态方法来进行漏洞检测。虽然此类方法可以以较低的误报率检测该漏洞，但是它的代码覆盖率偏低，从而导致许多漏洞不能被检测到。同时动态检测的方式需要安装整套的测试环境，为测试过程增加了难度。在静态分析工具方面，现存的原型链污染检测工具仅仅通过在AST和控制流图中匹配特征模式来进行检测。这种检测的误报率和准确率都很低。

  

本文提出了一种基于在对象属性图（Object Property Graph）中寻找源头簇（source cluster）和目标簇（sink cluster）匹配的原型链污染漏洞检测的解决方案。在此基础上，作者通过5843行Python以及3150行JavaScript实现了一个开源框架（ObjLupAnsys）来在生成对象属性图同时进行原型链污染检测。最后，在评估阶段，作者在现有的NPM数据库中发现了61个存在0-day原型链污染漏洞的包，同时发现了7个由于使用了有漏洞的包而出现漏洞的应用。

  

ObjLupAnsys的主要过程如下：

1.  分析文件依赖关系，生成AST；
    
2.  通过AST和控制流图来进行摘要解析（abstract interpretation），同时使用约束分析器来分析约束条件，从而选择正确的路径，推进污染标记，同时生成对象属性图；
    
3.  在摘要解析生成对象属性图的过程中寻找源头簇和目标簇，尝试进行匹配。一旦匹配成功则生成漏洞报告。
    

  

![](../Images/4342e3dc3ff2be6c5595682a1a228917.png)

  

在摘要解析过程中，ObjLupAnsys会将AST，控制流图，数据流图，对象节点以及引用节点联系在一起。通过在对象属性图体现不同对象和属性之间的关系，来寻找可能的源头簇和目标簇的映射关系，从而分析可能存在的原型链污染漏洞。举例说明，在paypal-adaptive这个包中，作者简化过后的漏洞代码如下图：

在该示例Figure 1中，如果按照Exploit部分中的代码运行，作者生成的部分对象属性图如Figure 2所示。在此过程中，函数”merge”会被调用两次。在第一次调用开始时，变量a和变量defaultConfig指向同一个对象节点。变量b和变量config指向同一节点。在第5行时，由于p是b的一部分，而b（config）可以被攻击者控制，所以p也可以被攻击者控制。此时在Figure 2中，可以被控制的变量b就会被以\*标识。此时merge函数会被第二次调用。在第二次调用过程中，程序会进入第7行。此时p仍然可以被攻击者控制，所以在Figure 2中以\*标识。如果攻击者在第一次merge函数调用时将p赋值”\_\_proto\_\_”，在第二次调用时对p赋值”toString”。那么defaultConfig\[“\_\_proto\_\_”\]\[“toString”\]就会在第7行被攻击者赋值。此时源头簇就是如Figure 2所示的config相关的属性查找使用的节点，目标簇就是最终被复写的内置节点。如果程序试图在赋值过程中，将一个\*对象赋值给一个可能指向JavaScript内置属性的引用上，就会出现如Figure 2所示的目标簇和源头簇映射成功的情况。在映射成功时，攻击者可以通过赋予受控制节点特殊数值的方式，将某个值赋值给JavaScript内置属性。此时也就表明这里可能存在一个原型链污染漏洞。
