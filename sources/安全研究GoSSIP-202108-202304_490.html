开学第一天为大家推荐的论文是来自印第安纳大学邢璐祎研究组与廖晓静研究组共同投稿的，目前已经发表在USENIX Security 2021上的工作Understanding Malicious Cross-library Data Harvesting on Android。



现如今，移动应用app 广泛集成了第三方库（例如，广告分析，智能化推送 或者第三方登陆相关的库）。这些第三方库不但为 app 开发者提供了便捷，也丰富了app的功能。但是于此同时，也为用户的安全隐私带来了风险。以前的研究表明一些恶意的library会通过运行它的app或者app的服务器或云存储中偷偷地从设备收集私人用户数据（例如，IMEI、GPS位置、电话号码、MAC地址、SIM卡ID、Android ID等）。但是，是否这些恶意的 library 还会从其他渠道收集用户数据、危害用户隐私安全尚未被完全研究。


在作者的研究中，发现了一种以前从未报道过的第三方 library 偷用户隐私数据的恶意行为，它针对其他也被集成在app中的SDK。这种SDK往往携带用户敏感的隐私数据。例如，Facebook 的SDK 被广泛的应用于单点登录，它管理着用户的姓名、生日、去过的地点、社交、健康信息，甚至他关注的政治团体等信息。这些数据可能会暴露给集成Facebook SDK的同一应用程序的恶意第三方库 Library（在本文中，术语“SDK”和“library”总是指第三方库，由除应用程序供应商或操作系统供应商以外的供应商开发；此外，为了便于区分，我们用“SDK”指代受害者库，将“library”作为通用术语指代第三方库）。


图1展示了这样一个恶意库，它首先检查Facebook SDK在其所在的移动应用程序中是否存在，如果存在，则调用Facebook SDK API以获取用户的 Facebook access token进而获取Facebook 用户数据，最后在把这些数据发送给自己的服务器。由于恶意第三方 library和受害的SDK都存在于同一应用程序中，这种调用是没有任何障碍的。鉴于Facebook登录SDK被广泛部署（在Google Play 上超过16%的应用程序中），此类数据泄漏的风险是巨大的。作者将此攻击称为Cross Library Data Harvesting（XLDH）。


图1


为了进一步了解这种恶意行为对用户隐私以及社会的影响，作者开发了一种新的自动化方法，称为XFinder，用于识别集成在Google Play上真实应用程序中的恶意第三方Library。首先作者先从可能受害的SDK的 term of use 文档（ToS，也称为使用条款、条款和条件）中提取受限数据以及在收集以及分享的时候的使用的条件。这些条款描述了受限数据如何与其他库共享或被其他库收集。作者自动从SDK供应商发布的服务条款中提取这些策略，然后分析每个集成库的代码，以确定它是否在违反这些策略的情况下对SDK的数据进行了任何访问。

如图2所示，整个方法分为三个部分：Data PolicyAnalyzer(DPA), Meta-DB Constructor, and Cross-library Analyzer(XLA)

  • Data Policy Analyzer(DPA) 以可能受害的SDK的ToS 文档作为输入，输出SDK的数据共享策略。

  • Meta-DB Constructor 收集返回这些受限数据项的API，用于后续程序分析。

  • XLA检查应用程序的反编译代码，以查找由Meta-DB返回敏感的API。然后确定是否该API被其他library调用。然后在对返回的数据做数据流分析，确定是否被传走。

接下来，作者用一个真实的例子来解释一下XFinder 是如何工作的：


具体来说，XFinder 检查了一个应用程序 “ColumnsGembira”（com.frzgame.columns。这个app 同时集成了一个XLDH 恶意的library 叫做 Mobiburn 和受害的 SDK 叫做 Facebook。在分析应用程序时，XLA首先扫描所有函数调用以查找跨库API调用。这里的跨库调用是指caller 和 callee 分别属于不同的第三方库。例如，mobiburn 这个library 中有一个函数 class com.mobiburn.e.hinmobiburn 调用 Facebook 的库中的函数 com.facebook.AccessToken.getToken（）。如下图a所示。XLA然后查询Meta数据库以确定函数的返回值为Facebook用户的access token，它是一个受限数据。接着XLA使用taint analysis 去跟踪数据流。如下图b 最后我们发现该access token 在 函数 com.mobiburn.e.h.getFbProfile（）用于获取用户的Facebook档案数据（ID、姓名、性别、电子邮件、区域设置、链接等）。最后包含access token在内的所有数据都被发送到了mobiburn服务器。


之后XFinder检查这种数据收集是否违反Facebook ToS中指定的数据共享策略。更具体地说，鉴于Facebook的ToS中的“keep private your secret key and access tokens”声明，DPA自动提取了数据共享策略（access token， condition：null），这表明访问的access token是受限数据项，不允许被收集和分享。因此，Mobiburn 违反了Facebook SDK的数据共享策略，因此，XFinder 检测出 Mobiburn是一个XLDH库。


接着作者用XFinder 去扫描了130万个GooglePlay应用程序中，结果显示XLDH对用户的隐私安全有着严重的威胁。更具体地说，作者发现了42个不同的XLDH库，它们在未经用户同意的情况从第三方SDK获取数据。这些库已经被超过1900个应用程序中集成，总下载量达90亿次。收集的数据高度敏感，包括access token、个人资料照片和朋友列表。 


作者把检测结果发给了受害的SDK的vendor, 比如Facebook，Twitter，Google 等，他们都肯定了作者的发现并承认了这种风险对用户隐私数据威胁极大。其中Facebook还起诉了两家发布XLDH的公司。Facebook，Twitter，Google 分别获得了$30,000, $560, $5000的奖励😎。
