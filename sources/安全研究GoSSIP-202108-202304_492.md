### 如何用程序分析的技术证明神经网络没有后门

SIG-程序分析技术沙龙的第一个talk由来自新加坡管理大学的计算机系教授孙军 (https://sunjun.site) 带来，孙老师的研究方向为形式化方法，软件工程，安全等。

在此次talk中，孙老师与我们分享了如何用程序分析的技术证明神经网络没有后门。传统的神经网络是一个相对特殊的程序，只不过程序的架构比较特殊。神经网络的程序中同样会存在问题。传统的软件可能会生成错误的结果，神经网络系统也一样，传统的软件中会存在后门，神经网络中也可以植入后门，传统的软件可能会泄露个人信息，神经网络中攻击者可以直接偷取整个AI模型。传统的软件必须经过测试、验证，神经网络系统也如此。针对于神经网络的后门问题，在这个问题中首先给定一个神经网络N，一组图片X，一个目标T，和一个trigger shape，问题定义为证明对于X中任意的x，不存在一个后门trigger trg，能够导出N(x+trg) = T。首先通过抽象解释处理每一个函数，比如将RELU函数改用成一个线性函数。RELU函数的定义是RELU(x) = if(x>=0){x}else{0}，如果在这里使用两个范围来线性规划RELU函数成一个线性函数的话，减小符号执行在RELU函数上的低效，改用成线性函数之后，可以使用linear solver来求解。接下来对问题的范围进行了详细的规范。首先定义后门攻击的成功率为Pr，可以扩展为给定K个随机图片，存在后门攻击的可能性不于Pr^K，也就是给定K个随机图像，不存在后门攻击的可能性不多于1-Pr^K。从另一个方向讲，给定K个随机图像，不存在后门攻击的概率大于1-Pr^K，也就是存在后门攻击的可能性不大于Pr^K，从而可以推导出有Pr的概率不存在后门攻击。

接下来就是K，在K选取较大值还是较小值的比较过程中，需要权衡的是程序分析时间和准确度之间的取舍。最终的测试是在MINST数据集上面进行，使用FFNN神经网络，这种分析方法取得了很优秀的结果。然而孙老师在报告中同时提出了另外一个挑战，如何验证semantic后门的缺失，比如一个神经网络可能会将所有绿色的车识别成为是青蛙，那么如何让程序知道绿色的车并不是青蛙？

### 软件2.0 时代的程序分析

张昕老师 (https://xinpl.github.io) 来自北京大学，这次的分享结合了他在MIT做博后和Gatech读博期间的工作成果。

近些年软件开发以及软件分析已经从软件1.0时代走入了软件2.0时代。在软件1.0时期程序的制造主体是程序员，更多的使用的是程序分析的方法，而在软件2.0时期以数据为主体，由机器学习进行程序设计。在软件2.0时代需要考虑的因素有可解释性，公平性，效率。针对现有程序分析的设计方式，有以下优点：能准确表达设计者的意图，可解释，提供严格的正确性保证。但是同时也存在一些缺点。无法处理不确定性，问题没有精确解，速度和精度的取舍。误报是程序分析的痛点。在Christakis& Bird 的 What Developers Want and Need from Program Analysis: An Empirical Study中提到，许多用户会忽视掉程序分析的结果，因为程序分析会提供大量的误报。张老师的研究中采取了基于逻辑+概率进行分析的方法，这样一来既保留了程序分析的优点，又加入了概率的优点。张老师在2018年NIPS上发表的Interpreting Neural Network Judgements via Minimal, Stable and Symbolic Corrections（https://arxiv.org/pdf/1802.07384.pdf）中，在程序给出分析之后用户可以进行同意和否认的选择，并且通过对这个选择进行学习。结果表明程序通过学习5%的用户反馈，消除了70%的错误报告。体现了程序分析结合了概率之后的有效性。

### 面向千万行代码的高精度静态分析系统

左志强老师 (https://z-zhiqiang.github.io) 来自南京大学，他的报告涉及在大规模程序代码上的高精度分析。左老师提到目前很多应用的代码在千万行的级别，比如Linux内核代码，一些浏览器的代码，其他应用比如mysql的代码量。所以对于这些千万行代码的系统，如何在尽可能保证准确性的时候，处理好程序分析的能力。

左老师在本次talk中介绍了他们在PLDI 2021上发表的论文Chianina: A system for flow and context sensitive analyses（http://web.cs.ucla.edu/~harryxu/papers/chianina-pldi21.pdf）。Chianina可以实现可扩展性和高效，因为内置了并行计算，GPU加速，分布式处理，并且无需内核支持。同时便于应用，面向开发者只需要处理一些界面。除此之外，还支持多种语言。在Chianina中，应用了三种漏洞的分析，分别是Pointer/alias, Null-value flow analysis with alias tracking, instruction cache analysis。Chianina的特点是使用了图分析的技术，从而实现可扩展的上下文敏感和流敏感的分析。

  

### 安全密码程序设计语言以及形式化验证

宋富老师(http://faculty.sist.shanghaitech.edu.cn/faculty/songfu/)来自于上海科技大学，他的研究领域是程序分析，形式化验证，软件安全与AI安全。在本次talk中，他给我们带来了安全密码程序设计语言以及形式化验证。现如今密码算法安全性评估方法有无条件安全，计算安全，可证明安全。密码算法的实现有软件程序或硬件芯片。密码程序面临很多的安全问题，在这里面宋老师对密码程序的功耗侧信道攻击进行了介绍。掩码是防御密码程序功耗侧信道攻击的一种有效方案，但是实现安全的掩码程序是一项艰巨而易错的工作，需要形式化验证方法保障密码程序掩码实现的正确性，从而避免功耗侧信道攻击，宋老师介绍了一些在此问题上取得的进展，包括基于精化的验证方法学，组合概率分布类型推导，基于GPU的模型计数约束求解算法。

基于精化的验证方法来自于宋富教授和博士生高鹏飞发表于2019年的ACM TOSEM的Verifying and Quantifying Side-channel Resistance of Masked Software Implementations（https://dl.acm.org/doi/10.1145/3330392），在这篇文章中类型系统包括RUD, SID, NPM, UKD。对于给定的密码程序，首先通过类型推导系统自动推理程序中间计算过程的概率分布类型；在大部分情况下，可以通过概率分布类型证明密码程序侧信道安全性。当类型推导系统无法证明密码程序部分中间计算过程侧信道安全时，采用模型计数技术进行验证，并将验证结果反馈给类型推导系统，精化类型推导过程。此方法能够在验证速度和精确度上都有显著提高。

2020年博士生高鹏飞和宋富教授发表在TOSEM上的A Hybrid Approach to Formal Verification of Higher-Order Masked Arithmetic Programs（http://faculty.sist.shanghaitech.edu.cn/faculty/songfu/publications/TOSEM20.pdf）针对密码程序侧信道高阶安全性验证时出现的组合爆炸问题和模型计数约束求解的可扩展问题，提出了一种基于分治的验证方法来解决组合爆炸问题和基于GPU并行计算的模型计数约束求解方法，同时开创性地提出了基于图同构的验证方法，组合概率分布类型推导通过避免大部分函数调用的内联

2020年IEEE TSE的文章Formal Verification of Masking Countermeasures for Arithmetic Programs（https://ieeexplore.ieee.org/document/9139284）中将基于精化的方法扩展到对算术程序的证明，同时创新地提出了可组合类型推导系统。该类型推导系统通过避免大部分函数调用的内联，大大提高了验证效率，完成包括AES，DES在内的十几个密码程序的自动化验证。

### 基于软件分析的智能化开发新型服务及技术介绍

来自华为云软件分析Lab的技术专家/Team Leader 梁广泰(https://www.linkedin.com/in/guangtai-liang-a162b625/)为我们带来了企业中的一些研究介绍。首先在各大企业中代码的缺陷分析均有研究，比如Amazon的code guru，Microsoft的Azure中有相应的检查规范，阿里云的codeup，依托PMD和sonar插件完成合规检查。腾讯云的coding可以进行代码代码扫描。同时，在开源社区中也有一些治理规范。Github在被Microsoft收购之后，github中的dependabot可以识别组件并且进行漏洞预警。腾讯云的wepack可以进行制品扫描。

华为云中应用的codecheck是本次介绍的主体。codecheck结合华为系列编程规范，构建3级检查+3层运营的检查与修复体系多方位多角度的支撑（IDE插件、门禁级检查、版本级检查）。除此之外，梁博士还对其他的一些研究进行了介绍，DiKTat：lightweight static analysis for Kotlin，使用到PSI的结构。是一个Kotlin语言的编码规范，可以被用在CI/CD过程中的检测和自动修复代码当中。在github上有diKTat（https://github.com/cqfn/diKTat）的开源代码。

### 关于IR在程序分析和优化中应用的一些思考

最后是来自南京大学的计算机系博士生李彬的分享——关于IR在程序分析和优化中应用的一些思考。IR是intermediate representation。IR是程序分析和优化的基础，根据安全检查的场景和IR的特点可以选择在不同的IR层次进行分析。比如对于C/C++安全规范检查，在AST，AST/CFG，LLVM IR，混合AST/CFG & LLVM IR 都有相关检查工具。其中规则场景分为结构化规则场景，数据流规则场景，信息流规则场景，配置规则场景。现代语言普遍AST和LLVM IR之间设计一个high level IR，用于Language specific的优化，数据流检查-例如definitive initialization，从高层抽象IR渐进降低到底层IR，MLIR/eDSL可以降低DSL的实现难度。MLIR是Multi-Level IR，是llvm项目的额一部分，通过多层IR实现DSL可以应用在通用编程语言比如Flang IR(Fortran)，机器学习（TensorFlow/ONNX/XLA...），硬件设计(CIRCT)，量子编程（QCOR），computational chemistry(COMET) 等多个方面。
