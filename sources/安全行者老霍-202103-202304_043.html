CASB 、CWPP、 CSPM、 CNAPP的区别

2021年3月23日   Tyson Supasatit

写在前面：把这几个概念梳理一下，最后应该只剩下CASB和CNAPP。CASB是云接入安全，CNAPP是云自身的工作负载安全、合规、安全态势等。

 

       随着企业将工作负载转移到云上，保护云环境已成为当务之急。

       Gartner预测，2021年全球公共云支出将增长18.4%，达到3049亿美元。这家市场研究公司预计，IT支出的比例将加速向云转移，预计到2024年，云将占全球企业IT支出市场的14.2%，高于2020年的9.1%。

       随着企业将更多的IT支出转移到云服务，他们正面临更多的监管、数据泄露，以及对其云应用的攻击激增。

       为了应对这些挑战，他们需要获得软件即服务(SaaS)、平台即服务(PaaS)和基础设施即服务(IaaS)云的可见性和安全性。有一些工具可以帮助组织为其云环境提供安全性。下面，我们将从较高层面分析正在被越来越多采用的四个选项。


云访问安全代理（CASB ，Cloud Access Security Broker）

       云访问安全代理(CASB)本质上是云服务的防火墙。它提供了一个安全策略加强网关，以确保用户的操作得到授权，并符合公司的安全策略。

       CASB可以识别组织使用的所有云服务，包括影子IT/未经批准或未托管的SaaS和PaaS产品，并在必要时发出警报。它支持云使用跟踪、报告和日志记录，评估影子IT带来的风险，以及事件监控。

       CASB拥有满足监管合规的审计和报告工具，包括云存储数据。这些工具提供用户身份验证、授权和策略强制，例如移动和加密文件、更改权限和过滤消息。

       威胁保护是CASB可以帮助组织的另一个领域。CASB保护授权用户和应用的云服务，并提供反钓鱼、帐户接管、URL过滤、恶意软件检测和沙箱保护。

       在数据安全方面，CASB可以监控对数据的访问，并通过提供细粒度访问控制来加强以数据为中心的安全策略，例如仅通过指定的设备或平台访问云服务。它还提供基于策略的加密。


云工作负载保护平台（CWPP，Cloud Workload Protection Platform）

       云工作负载保护平台（CWPP ，Cloud Workload Protection Platform)为所有类型的工作负载提供了以工作负载为中心的安全保护解决方案，包括物理服务器、虚拟机(VM)、容器和无服务器工作负载。CWPP为本地和云环境提供了具有可视化和安全功能的仪表盘。

 

       根据Gartner的说法，CWPP包含8个控制层。按重要性排序，这些功能包括:

1.      加固、配置、漏洞管理，包括软件上线前的漏洞扫描

2.      网络防火墙，可视化和微隔离

3.      系统完整性保证

4.      应用程序控制和允许列表

5.      漏洞阻止和内存保护

6.      服务器工作负载EDR、行为监控以及威胁检测和响应

7.      基于主机的入侵防御，漏洞屏蔽

8.      恶意软件扫描

       CWPP提供了许多好处，包括能够在CI/CD流程的早期识别漏洞，更快地检测漏洞和主动威胁，以及在响应事件时具有更大的上下文解析和调查能力。CWPP解决方案将观察到的活动对应到MITRE ATT&CK企业矩阵，为分析人员和调查人员提供更多的背景材料，并帮助他们了解事件的严重性。

       CWPP可以统一管理多个不同的云供应商，同时保护工作负载连贯性。CSPM（Cloud Security Posture Management，云安全态势管理）是另一个由Gartner提出的概念，表示能够识别云误配置问题以及合规风险的安全工具。CSPM帮助企业持续监测云基础设施，识别在实现安全策略时出现的缺口。

       CWPP处理数据平面，对工作负载有更深入的理解。

　　CWPP能确保正在执行特权管理，会通过一个数据平面代理分析工作负载。代理会在数据平面上提供正在发生事情的可视化能力：

　　• 发现每个用户在运行哪些程序——在哪个许可等级。

　　• 确保没有任意代码、邮件、或者网站客户端在数据平面运行。

　　• 扫描漏洞。


云安全态势管理（CSPM ，Cloud Security Posture Management)

       云工作负载保护平台从内部保护工作负载，而云安全态势管理（CSPM）则通过评估云平台控制平面的安全与合规配置，从外部保护工作负载。

       为了实现这一点，云安全态势管理提供了一组工具，支持合规监控、集成DevOps流程、事件响应、风险评估和风险可视化。

       云安全态势管理解决方案在组织的整个云资产中识别未知或较高的风险，包括用于计算、存储、身份和访问等云服务。它提供持续的合规监控、阻止配置漂移和安全操作中心调查。

       云安全态势管理将失败定位在其根源上，聚焦于组织的云配置。CSPM之前被称为云基础设施安全态势评估(Cloud Infrastructure Security Posture Assessment)，它的定义是为了响应组织对正确配置公共云Iaas、PaaS服务和修复云风险的日益增长的需求。CSPM使用自动化来识别和修复云基础设施中的漏洞，并以其风险可视化和评估、事件响应、合规监控和DevOps集成功能而闻名。值得注意的是，CSPM能够针对混合云、多云和容器环境统一应用云安全的最佳实践。


为什么会出现错误配置? 

       由于云环境的动态特性、连接资源的数量以及API驱动的集成方法，很容易发生错误配置。基于云的服务包括许多活动部件，当与缺乏主动可视化结合在一起时，会降低组织发现和解决配置错误的能力。

       对云中的存储桶或容器偶然批准公共访问权是一种常见的错误配置，它会带来相当大的风险。就像没有上锁的房子一样，敞开的存储桶很容易被发现的人攻击。


       

       组织应该创建策略来定义云基础设施的理想状态或配置；他们可以使用云安全态势管理（CSPM）产品来监控这些策略。它使企业能够检测和解决影响其云环境的配置问题，互联网安全中心(CIS)的云服务商基准（CIS Benchmark）和MITRE ATT&CK云矩阵对这些问题做了描述。

       云安全态势管理（CSPM）工具自动检查云环境是否合规和违反安全规定，并提供自动化步骤来纠正它们。使用云安全态势管理（CSPM）工具，组织可以意识到其环境的新风险，防范入侵，并构建一组统一的云配置。

       CSPM的关键能力是什么?

  1. 自动检测和修复

  2. 对不同云配置和服务，维护最佳实践清单的能力

  3. 对安全控制框架或监管标准，对应本身的配置状态和连接

  4. 存储桶监控、加密和账户权限的错误配置和合规风险

       随着组织尽职调查的范围不断扩大，及新的网络犯罪事件的复杂化，拥有强大的防御姿态，能够以必要的速度检测和响应是一项只有云安全态势管理（CSPM）已经证明可以交付的任务。


云原生应用保护平台（CNAPP， Cloud-Native Application Protection Platform）

       结合云工作负载保护平台（CWPP）和云安全态势管理（CSPM）的功能，云原生应用程序保护平台(CNAPP)，一个由Gartner创造的术语，可以扫描开发中的工作负载和配置，并在运行时保护它们。

       保护云原生应用程序涉及一组持续的流程，重点是识别、评估、确定优先级并适应云原生应用程序、基础设施和配置中的风险。

       云原生应用程序需要一种身份和实体管理的系统方法，并包含最小特权或零信任、安全态势。保证开发人员和用户身份管理的网络健康必须成为战略的一部分。

       云原生应用保护平台（CNAPP）工具为SecOps和DevOps团队提供统一的可视化，一组响应威胁和保护云原生应用的功能，以及自动化修复漏洞和错误配置。

       云原生应用保护平台（CNAPP）会根据风险，识别所有端点、网络上的工作负载、数据和基础设施，并对其进行优先级排序。它可以防止配置漂移，并提供虚拟机、容器和无服务器环境的漏洞评估。

       使用CNAPP，组织可以建立基于零信任的策略，观察行为，消除误报，通过加强良好的行为实现规模化。它通过将云原生威胁映射到MITRE ATT&CK企业和云矩阵，为安全运营中心赋能。

       对同一个团队使用单独的云工作负载保护平台（CWPP）和云安全态势管理（CSPM）工具意味着不必要的开销和对员工的额外培训。有理由认为，这些方案将合并为元原生应用保护平台（CNAPP）解决方案。

　　在数据平面上检查误配置和漏洞，可以帮助企业在开发流程更早期——在应用和服务进入生产环境前，识别安全风险。这可以让组织在软件开发生命周期进行安全左移。

       只看数据平面还不够，还需要注意控制平面

　　CSPM方案通过评估云平台的控制平面，确定配置是否安全合规，来保护来自外部的工作负载。这些解决方案基于一系列定义好的最佳实践以及已知风险，检查并比较现有的云环境。在追求云优先策略的企业，可以使用CSPM将一些最佳实践延展到混合云以及多云环境之中。

　　随着CWPP带来的安全扫描将安全在开发阶段中进行了左移（包括扫描开源漏洞、库、可执行漏洞、依赖性、硬编码加密凭证、以及恶意软件），扫描云配置发现其他风险同样重要。


Kubernetes也是一个控制平面

　　云原生技术，比如微服务、容器和Kubernetes，能帮助组织在云原生架构建立并运行可扩展的应用。由于Kubernetes基于现实标准的容器编排，CSPM也需要能够包含一个新概念：KSPM（Kubernetes安全态势管理，Kubernetes Security Posture Management）。


CWPP+CSPM（包括KSPM）=CNAPP

　　这两类工具也在逐渐聚合，形成CNAPP（Cloud Native Application Protection Platform，云原生应用保安平台）。CNAPP将CWPP和CSPM中可用的管控合到一起，使团队更容易管理云安全。


你的最佳选择是什么?

       组织选择哪些工具取决于它的优先级。如果它主要关心的是控制企业云的使用，那么云访问安全代理（CASB）可能是最好的选择。

       如果组织的优先级是保护云上的工作负载并加强应用程序安全性，那么云工作负载保护平台（CWPP）可能是更好的选择。组织应该评估其当前的工作负载安全解决方案是否能够应对其目前使用的云服务。例如，如果它正在使用容器，其工作负载安全产品应该能够检查容器的安全风险。

       如果公司最迫切的需要是遵守云配置最佳实践，那么云安全态势管理（CSPM）很可能是最佳解决方案。CSPM工具使用云提供商的应用程序编程接口来自动化实现安全基准测试和审计检查，使您能够避免客户数据暴露在互联网上。

       在选择正确的平台时，组织应该清楚地定义其云安全需求，并与各个参与方及业务主管就这些需求进行沟通。
