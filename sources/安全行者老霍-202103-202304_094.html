现代应用程序的设计和持续采用的DevSecOps正在扩大着AST的市场范围。安全和风险管理的领导者们在软件交付生命周期中，通过无缝集成和自动化实现AST，满足更紧迫的工期和测试更复杂应用程序的需求。

 

战略规划假设

       到2023年，通过暴露的API而不是用户接口，基于Web的应用将有更多的攻击平面，从2020年的50%增长到90%。

      到2022年，API滥用，将从很少采用变成最频繁使用的攻击向量，导致企业web应用的数据泄露。


市场定义/描述

        Gartner 定义应用安全测试市场由买家、和能够提供分析及测试应用程序安全漏洞的产品和服务的卖家组成。     

       分成三种主要的AST技术：

•   静态AST（SAST）技术分析一个应用的源代码，字节码或者二进制代码，找出安全漏洞，一般在软件生命周期的编程或者是测试环节。

•  动态AST（DAST）技术在测试或运营阶段，分析处于动态、运行时状态的应用。模仿针对应用的攻击（典型基于web应用、服务），分析应用的反应，判断是否存在漏洞。

•   交互式AST(IAST)同时结合静态应用安全测试技术和动态应用安全测试技术，在测试运行环境中，安装代理软件（java 虚拟机或.NET CLR插桩），观察软件运行情况或者攻击，发现漏洞。

    软件成分分析（SCA）被用来识别在应用中的开源软件和第三方软件成分，发现已知的安全漏洞。

    应用安全测试能够作为工具或以服务订阅的方式来交付，许多厂商同时提供两种选择，满足企业对产品或者服务的需求。

在过去的三年内，Gartner已经看到了客户要求额外的服务和工具，去覆盖他们的AST要求，包括新的开发方法和武器，今年，我们决定增加这些趋势，扩展应用安全测试的范围：

•   基础设施即代码（Infrastructure as Code，Iac）测试。Gartner定义Iac为软件定义计算（SDC）、网络和存储基础设施即代码的生成、提供，配置。IaC支持中心围绕着传统上与软件开发相关的过程和规程的应用来管理IT基础设施。Iac也经常被称为可编程基础设施（programmable infrastructure，PI），虽然PI也能包括云原生自动化的其他方面，包括容器和不可改架构（immutable infrastructure）。

•  容器安全。容器安全是包括安全流程、测试、和linux基于容器环境的控制的应用程序，理想上包括对K8s的支持。在开发中，综合性的容器安全从风险/容器内容可信，敏感信息管理和K8s配置评估开始，应该被扩展到运行时容器威胁保护和访问控制中。

•  模糊（Fuzz）测试。模糊测试是把经过仔细设计的垃圾数据发送到目标系统，保证他们正常地降级或正确地管理坏数据。例如，对API测试，测试人员将本来希望把数字作为调用的参数，换成文本字符。模糊测试也叫作“不确定性”测试，已经成为把渗透测试中常用的工具引入到AST中一个常用的方法。

•API 测试。API已经变成了现代应用的一个重要部分（例如单页应用，single page application）。但传统的AST工具集，对此支持的不是很好。因此API变成一个重要的安全顾虑，安全支持必须持续跟上时代发展。

•   云原生支持。随着开发越来越向云转移，开发人员的安全工具也需要跟进。我们查看对云原生环境的支持，仅仅在公有云中，把安全工具作为集成开发环境（IDE）的一部分，例如亚马逊Web服务（AWS），微软Azure，谷歌云平台（GCP）。

        本篇2021 魔力象限关注传统AST厂商的产品，他们作为工具或“作为服务”的产品功能和成熟度，以及他们保护由某些现代应用部署关注所带来的攻击平面的某些部分的能力。

        Gartner已经观察到AST市场进化的主要驱动力，来自于需要支持企业级DevOps。客户要求提供高保证、高价值发现、而且不能拖累开发的产品。客户希望产品尽早地适用开发流程，测试常常由开发人员驱动，而不是安全专家。因此，在整个软件开发生命周期（SDLC）中，能够以越来越自动化的方式，集成快速和精准的测试，这个市场评估的重点更多地放在了买家的需求上。


数据源：Gartner 2021年5月

 

厂商优势和不足

 

Checkmarx

        Checkmarx是魔力象限中的领导者。在厂商的产品组合中，动态分析一直得到忽视，仅可作为托管服务提供。公司在许多用户场景中都很有竞争力，但在DevSecOps和云原生环境中，或者说优先考虑SAST时，表现得最好。

        Checkmarx在全球开展业务，美国，欧洲，以色列和新加坡有办事处。

        Checkmarx产品中，最新增加的是一个基础设施即代码扫描工具，公司已经把其作为开源项目发布，KICS（保证基础设施即代码安全  Keeping Infrastructure as Code Secure）支持Terraform、Kubernetes、Docker、AWS CloudFormation 、Ansible 环境，提供超过1000个检查项目，可搜索漏洞和错误配置。

优势

  • CxSCA可作为一个独立的方案提供，虽然它一直受益于和SAST集成，实现可利用路径探测功能。这个功能也被其他厂商添加，在开源软件包升级和修复的优先级排序中提供帮助。

  • CxIAST，一个被动的IAST工具，帮助识别代码中的漏洞和发现API。提供数据流图形化展示，突出显示跨微服务环境中控制和数据路径。这是一个特别的功能，在AST产品中还很少见。帮助开发人员更好（译者：从这里可以看出，AST工具未来一个重要的方向是帮助开发人员可视化代码执行过程）了解在什么地方花费更多的修复精力。

  • Checkmarx 有很强的开发者支持功能，提供跨环境的漏洞评估和修复指南。由开发者培训工具CxCodebashing产品，提供辅助。

不足

  • 虽然把自己定位于混合方案提供商（本地和云）,Checkmarx注意到很多用户忽视了其强大的SaaS产品功能，公司表示在2021年，它计划扩大对SaaS的支持。

  • DAST只能以托管服务方式提供，并且依赖于其他厂商工具。缺少对工具方向上的控制和潜在合作关系中断的可能性，在DAST为主要需求时，Checkmarx价值不大。

  • 客户提到了高成本，许多厂商中越来越普遍的问题。Checkmarx已经开始简化软件许可，大多数产品和用户数挂钩，而CxIAST 和DAST托管服务都基于应用程序/项目。

 

Contrast Security

 

        Contrast Security是魔力象限中的挑战者。以其被动IAST为大家所知，被动IAST 不依赖利用主动扫描生成的攻击来发现漏洞，它使用计划好的非安全测试来实现，例如质量保证。

        Contrast Security 总部在美国，也在EMEA和亚太地区销售。平台由IAST（Contrast Assess），SCA(Contrast OSS)，RASP（Contrast Protect）组成。Contrast Assess包括Contrast OSS，可自动执行SCA。最近，Contrast Security收购CloudEssence 扩展了云原生的测试能力。和NowSecure在移动AST上，达成合作关系。也扩展了语言覆盖范围，使它的TeamServer产品部署在容器中，实现漏洞优先级排序功能。

       Contrast很适合以开发者为中心，寻找插入自动化的、持续安全测试方法的组织。

优势

  • Contrast Assess是使用最广泛的IAST方案之一，持续在Gartner关注的每个IAST 短名单里竞争。Contrast提供最广泛的语言覆盖，包括Java，.NET Framework，.NET Core，Node.JS，RUBY，Python和Golang。

  • Gartner 客户反馈指出，对没有安全测试专家的开发团队，Contrast Security帮助嵌入AST，因为代理软件在正常应用测试时，识别出漏洞。客户也建议厂家被动IAST的方法，误报率很低。

  • Contrast Security 将来自无服务器云函数代码的上下文，（如AWS Lambda），和函数使用服务的配置相关联，决定是否服务配置比最低权限更宽松。

不足

  • Contrast 只提供IAST和SCA方案，当前不提供单机的SAST和DAST工具或服务

  • 尽管Contrast Security提供和IDE集成，在编码时发现和修复漏洞，并不像其他厂商那样，提供单机“拼写检查”SAST套件。

  • Contrast Security 只插桩，测试应用程序后端，因此并不测试Web或移动app客户端代码，也不识别前端代码漏洞，如DOM-based XSS。

 

Data Theorem

 

        Data Theorem是魔力象限中远见者。解决了云原生和容器化应用的核心能力，包括云原生的开发、API和单页应用（single-page application）的安全。因此也适合关注这些应用程序的组织。

        Data Theorem提供API，基础设施即代码测试和移动应用测试，可以提供数据流可见性。也提供一个高度自动化和持续的合规。厂商通过分析引擎（Analyzer Engine），提供SAST/DAST和IAST，使用它的Web Secure，Mobile Secure和API Secure产品的结果，生成一个强大的应用、API和数据流视图。

        虽然Data Theorem提供传统的SAST/DAST/IAST产品，如果客户仅仅想要这些工具，也许本报告中测评的其他厂商能够服务得更好。

优势

  • Data Theorem的安装包括一个自动化发现阶段，会检查所有的API，web调用，和其他信号，来决定你攻击平面的范围，同专业的安全研究者和黑客所用的方法类似。非常容易使用，能帮助安全专家和开发人员，把一套复杂的应用和服务集中起来。

  • Data Theorem 监视和修复云错误配置，这允许云原生应用通过自动化撤销有害变更，防止配置漂移和意外事件。

  • Data Theorem使用Web Secure（这是他的一个产品），运行一个无代理的动态运行时分析，对单页应用（SPA）有一个全面的支持，提供黑客工具箱用于测试重要应用。

不足

  • 同其他厂商相比，Data Theorem支持SCA，但比其他AST厂商提供的产品水平低，也没有开发支持这个产品的合作伙伴。

  • Data Theorem 没有像许多AST领域领导者和挑战者那样，开发出对SAST和DAST核心工具支持的开发者教育，例如，没有内置于编辑器的课程，IDE插件，或安全linter

  • 目前支持在Amazon和Google上的应用开发，Data Theorem还处在对微软Azure Marketplace和阿里巴巴（第一次看到对国内应用支持）支持的早期阶段，虽然它希望在今年晚些时候更好地支持他们。

 

GitHub

 

         GitHub是魔力象限中的利基者。这个公司提供AST的新方法事例，测试工具是底层开发环境的一部分。GitHub在开发基础设施中的地位，使GitHub用户可以紧密的集成，容易地使用测试工具。

        GitHub主要重心在SAST和SCA，虽然也可以提供集成其他类型的测试。特定功能的可用性和成本根据服务水平不同而有变化，公共代码库包括许多安全功能，可以免费试用。代码扫描和更复杂的SCA功能只有商用GitHub企业用户才能获得，作为高级安全服务的一部分，按用户收费。

优势

  • 和GitHub Action及GitHub源代码库得紧密集成是其核心优势，也是方案中最具有吸引力的部分。组织可以在整个组织或者只是项目级别使用检查功能，当代码提交或者拉取的时候，自动执行分析。

  • 开发人员支持很好，尽管限于在GitHub本身上下文环境工作的开发人员（提供Visual Studio IDE插件）。拉取时，结果在GitHub内部界面，安全标签上展示，点击就可以显示漏洞的细节。例如，漏洞原因、代码路径、后果、相关的CVE、代码中问题的修复建议，或者和特定开源软件包相关的问题，使用自动化地拉取，去修复开源软件缺陷（当有修复包时）。

  • 潜在客户对GitHub熟悉度，加上安全功能的紧密集成，使之成为依赖底层代码库组织的有吸引力方案。

不足

  • GitHub 对语言支持有限。主要的功能还是代码分析（使用一种语义/变量分析）和SCA。对更常见的语言提供支持—C variants，Java，JavaScript，TypeScript，Python，Go。但如果一个组织有多个不同产品，会要求可替换的，补充工具。

  • 公司依赖合作伙伴，支持几种能力的市场空间在本报告有总结。和平台的集成及表现，对受支持的合作伙伴很强大，尽管根据选择，一些工具可能需要额外的费用。动态扫描和交互式扫描，以及移动应用安全测试功能还无法提供。

  • 对IDE集成的支持仅限于Visual Studio Code 插件，产品的重点还是原生GitHub平台，虽然，对GitHub用户来说是一个优势，但对不使用平台的用户，或者只是将其用于部分业务的用户也是一个劣势。

 

GitLab

 

        GitLab是魔力象限中的挑战者。提供AST作为他更广泛的DevOps平台中的一部分。GitLab提供AST 作为其ultimate/gold 层一部分。在自己的工作流中，结合了专有的开源扫描工具，提供SAST和DAST功能。也提供SCA依赖扫描功能，GitLab的安全产品包括敏感信息管理，开源扫描功能具有容器扫描，许可证违规发现。

        在过去的一年，GitLab收购了Peach Tech，得到了它的插桩技术，收购Fuzzit，得到碰撞分析技术。也增加了移动AST，集成移动安全框架（MobSF）到平台中，还有API和覆盖率指导的模糊测试能力。也增加了对离线环境和漏洞管理的支持。GitLab和IBM达成伙伴关系，在IBM CLOUD Paks中提供GitLab Ultimate。

        GitLab对使用它的平台做持续交付、需要使用安全应用开发工作流的组织非常适合。

优势

  • GitLab AST产品。包括SAST，敏感信息检测，依赖扫描，包含在Ultimate/Gold 层里，价格可预测且透明。而且，SAST和敏感信息检测也是免费版本功能的一部分

  • GitLab的AST产品包括敏感信息管理功能，扫描代码库内容，识别不应该未受保护的写在代码中授权凭证和其他敏感信息。

  • 提供容器的漏洞扫描，对部署在Docker容器和k8s中的都可以。模糊测试由于其提供的自动化能力，细粒度，功能容易使用，对专业水平要求不高。

不足

  • GitLab的SAST缺少很多成熟产品具有的功能，涵盖语言有限，仪表盘缺少粒度和更成熟工具的定制化。SAST产品缺少如快速修复推荐和实时拼写检查等功能。

  • GitLab当前不提供IAST功能，虽然最近收购了Peach Tech，具有插桩技术。

  • GitLab对不同的语言和框架，使用不同的工具，许多都是开源的，虽然它对他们的开发和维护做了积极的贡献。例如，DAST产品就是OWASP的开源ZAP工具，移动产品由MobSF组成。

 

HCL Software

 

        HCL Softwares 是象限里的领导者，对有多种开发风格的组织非常合适。

        HCL Appscan提供一个混合的部署选择，包括在本地，SaaS，和混合模式。本地产品包括Appscan for SAST，AppScan Standard for DAST，Appscan Enterprise for DAST and IAST。服务模式提供的产品都归属Appscan on Cloud 品牌，包括SAST，DAST，IAST，SCA支持。

        对于基础设施即代码扫描，HCL Appscan检查Docker 和k8s的YAML配置，和运行Docker 镜像的命令行脚本。Appscan作为厂商SAST集成一部分，对开发人员很容易使用，不需要离开他们的工作流。

        HCL有大量的API测试，提供CodeSweep，AppScan的社区版本，直接插入Visual Studio ，执行全功能Appscan产品的许多功能。

优势

  • Appscan 智能发现分析（IFA）有助于提高准确性，确定漏洞“最佳修复”的位置。这是开发团队常见的功能，也是Gartner Peer Insight on AST 2020报告中，最常见的得到认可的亮点。

  • Appscan 在DAST上有一个很好的声誉，在整个产品集中共享同样的基本技术。基于桌面的Appscan Standard 是一个定制化的产品，特别适合人工评估。增量扫描允许更快的扫描，一个“基于动作”的浏览器记录技术，能够测试复杂的工作流和提高对单页应用（SPA）的深入了解.

  • 自从去年，APPSCAN 的IAST功能从DAST功能分离出来，是一个在DevOps团队中越来越受欢迎的被动IAST方法，2020年中期发布，得到普遍好评。

不足

  • Gartner 客户提到HCL技术支持团队对更复杂的用例提供指导时，使用相对长的时间。

  • HCL对Appscan在布局和定制化方面对用户界面做了改进，但客户仍然提到这是一个相对弱点。

  • HCL产品集整体的报价模式仍然很复杂，被客户认为是一个弱点而反复提及（价格复杂性很常见，但不是厂商中普遍的抱怨）。

 

Invicti

 

        Invicti是魔力象限中的利基者。公司有两个著名的品牌，Acunetix，Netsparker。对DAST有基本需求的组织对Invicti很有兴趣。

         除了在交互式分析和模糊测试上之外，产品设置上，功能都很类似。本次报告的时候，只在Acunetix Premium提供这些功能。

        Invicti在美国、马耳他和土耳其都有办公室，直接或通过分销商提供销售和支持，在多个区域都得到了很好的认可。

优势

  • Acunetix和Netsparker都是得到用户非常认可的品牌，在整个用户体验中，都强于竞争对手。在Gartner Peer Insight报告中，Acunetix略好于Netsparker。

  • 提供多个方法，允许测试人员对于没有变更的代码扫描，浪费最少的时间。当URL哈希值改变，对URL实现增量扫描。而且，工具支持再测试选项，主要关注上一次扫描发现的问题，只测试证明修复的部分。

  • Netsparker对指定范围的IP地址提供持续扫描，发现异常和遗忘的网站，虽然不唯一，该功能对努力和开发及业务单元活动保证一致的安全团队很有帮助。

不足

  • Invicti产品最适合对DAST有重度要求的组织。不支持SAST、容器扫描、基础设施即代码扫描、移动或关键业务评估能力。Acunetix IAST 方案，支持PHP，.NET，Java，定位发现漏洞的代码位置，通知DAST扫描器。（主动插桩的IAST产品）

  • 提供和SDLC的广泛集成。虽然开发人员的支持是混合的。提供很宽范围的支持，包括问题跟踪、项目管理、持续集成（CI）服务器，生产和通讯工具、特权访问管理方案（主要用于认证），但没有和IDE集成，虽然开发人员通过缺陷清单集成，或CI工具访问发现的信息。

  • 缺陷清单，例如Jira，提供基本的信息，但更细节的数据需要开发人员点击回到Netsparker控制台，类似地，在开发工具链内，能够生成一个管理层的报告，和控制台生成的PDF和HTML报告类似，但了解更多的细节，还需要访问控制台。

 

Micro Focus

 

        Micro Focus是象限中领导者。它的Fortify产品提供综合性的AST，支持多数语言，及定制化和集成选项。

        Micro Focus总部在英国，是IT产品和服务的全球提供商。在全球都有销售。在北美，EMEA，中美洲市场非常强势。Fortify提供Static Code Analyzer （SAST），Webinspect（DAST &IAST），软件安全中心（控制台），Fortify Audit Workbench（AWB）。通过和Sonatype的集成，Fortify提供SCA功能，Fortify提供AST作为产品，也可以使用Fortify on Demand，提供云服务。

        在2020年，Fortify引入ScanCentral，其CloudScan框架的进化，以中心管理的方式在本地运行扫描，Fortify也和Secure Code Warrior 达成合作伙伴关系，给开发人员提供安全开发培训。

        Fortify对很多种类的用户都很合适，特别适合有多个复杂项目，多个编码风格和经验类型的大企业。

优势

  • Micro Focus具有最完整的AST方案，几种AST技术的能力都很强。在AST的新领域，也都有很好的功能。

  • Fortify Security Assistant 是一个在IDE内运行的实时安全检查器。但并不可能取代全面的SAST扫描，可以提供一个轻量级自动化检查，检查开发人员编码时的的安全错误

  • Micro Focus扩展了它的Fortify Audit Assistant功能，允许团队很大的灵活性，可以使用人工审查，人工智能（AI）对问题的预测，或者选择“自动预测”，允许完全的带内自动分类，有助于减少误报。

不足

  • Fortify因其结果的深度和精确性而著称，满足使用上下文分析的企业用户需求。然而，寻求增量改善，不是很成熟的组织，常常因其复杂性和大量的未过滤结果而面临经验上的挑战。

  • Fortify不提供单机运行的IAST、单机的模糊测试，只提供主动IAST，意味着要和DAST结合使用。

  • Gartner客户报告称，尽管Fortify努力提供灵活的软件许可和报价模式，报价还是很复杂，价格很高。

 

Onapsis

 

        Onapsis是魔力象限中的利基者。一家英国公司，在美国，德国，阿根廷都有分支机构。Onapsis特别关注关键业务应用，在重视这个市场全球公司及客户中，得到了很好的名声。

        Onapsis持续地显示出其对专业开发框架、开发者需求和这些应用所执行的开发环境的深入理解，例如SAP Business Application Studio in Cloud Foundry。

        Onapsis产品集包括2019年收购的Virtual Forge，SAP代码安全领域的著名玩家，得到开发人员强大的技术支持。

        Onapsis 适合关键业务现代化项目，如S/4HANA转换和云迁移。新的功能包括和CI/CD工具（SAP ChaRM）集成，漏洞代码自动化更正，改进的数据和控制流逻辑。

优势

  • Onapsis 提供在Cloud Foundry环境中，和容器环境（SAP Business Application Studio）的集成。

  • 它的数据流和跟踪选项，对监控金融行业、人力资源管理、供应链管理和其他应用中的合规风险非常有用。

  • Onapsis 增加了他的开发人员支持选项，提供一个自动的修复功能，允许开发人员验证安全修复。

不足

  • 其他支持如ABAP和Apex语言的大型厂商，也在进入AST市场，然而这些新的厂商并没有在特定的环境（如SAP）中工作的能力，虽然那可以随着时间而改变。

  • Onapsis 很满意对SAP和Oracle广泛的支持，但和他们自己的产品存在竞争性关系（SAP的Code Vulnerability Analyzer）。

  • 由于重点放在对SAP和Oracle支持的应用上，测试也集中于这些框架，导致和大的、传统的AST环境集成很有挑战。Onapsis计划在2021年，扩展对其他的关键业务应用的支持。

 

Rapid7

 

        Rapid7是魔力象限中的远见者，公司以其动态扫描和漏洞管理闻名，正在激进地扩充产品组合，在方向上做出改变。

        SCA 通过和Snyk新的伙伴关系得到支持，2020年四月下旬，公司宣布收购了DivvyCloud，一家云安全态势管理厂商，实现了基础设施即代码扫描的功能。

        Rapid7 总部在美国，主要在北美和EMEA地区销售，亚太地区不是很多，所有的产品都通过SaaS模式提供，大多数产品也能作为本地方案提供                           （除了InsightVM，tCell）。

优势

  • Rapid7在DAST方面持续享有好名声，特别支持深入定制的人工评估，测试可以交互式的进行，允许对参数的操作，帮助排错和验证修复。

  • 收购DivvyCloud和AIcide帮助公司向更加现代化的应用安全需求转变，希望对云原生的应用提供更多的支持。

  • Rapid7在产品易用性，报告和支持方面得到用户的一致好评。例如给开发人员提供修复建议、描述和错误信息、攻击重放，帮助开发人员理解、修复和重新测试漏洞。

不足

  • Rapid7快速扩充产品。意味着中短期内，面临着管理多个产品和集成各种技术的复杂任务。Gartner确实注意到了一些用户关于复杂性的怨言。寻求使用公司扩展能力的买家，应该保证他们仔细检查和了解公司计划集成产品路线图和时间表。

  • Rapid7缺少原生的静态分析方案，目前，公司使用合作伙伴Checkmarx的产品，去服务有需求的客户，而且，有前景的买家应该保证他们理解和合作伙伴集成路线图及前景。

  • 虽然测试结果非常详细，Rapid7工具一直缺少和IDE的直接集成，促使开发人员切换到InsightAppsec 仪表盘（或者浏览器插件）去检查数据和支持信息。


 Snyk


       Snyk是魔力象限中的远见者。Snyk是一家知名的SCA厂商，利用对开发人员环境知识广泛的了解，使用一种开发人员友好的方法，扩展到AST。

        总部在美国，Snyk在北美，欧洲和以色列都有分支机构和小型虚拟办公，AST产品包括SCA产品，由Snyk Open Source和Snyk Container，以及SAST由Snyk Code和Snyk 基础设施即代码组成。

        去年，Snyk收购了SAST厂商Deepcode.ai，它提供一个机器学习方法扫描解释代码，厂商也细化了支持，如对不安全的K8s和Terraform 配置的修复建议。还在IDE中增加了实时的反馈。

        Snyk适合需要以开发者为中心的SCA和SAST的方案，能够扫描应用和基础设施即代码。

优势

  • Snyk设想应用和基础设施层，越来越模糊在一起。开发和运行时阶段也是如此，这个远景及其产品，符合Gartner所发现的、企业在数字化转型时的经验。

  • Snyk的云原生AST 能力非常成熟和细粒度，厂商提供识别漏洞的详细信息，和自动化的修复建议。Snyk也检查，漏洞是否在代码内部真的可复现，这样好确定修复优先级。

  • 厂商的AST产品价格可预测，价格可公开提供给多大150个开发商。Snyk提供所有产品的免费版，包括对开源项目的无限使用。

不足

  • Snyk有一个相对较新的AST产品，虽然在SCA领域很有名，但在Gartner用户中，没有多少了解Snyk还提供AST产品。Gartner主要把Snyk看做和SCA及CWPP（云工作负载保护平台）领域的玩家竞争。

  • Snyk的产品不像其他传统的AST厂商那么完整。例如，对IOS应用不提供SAST，缺少IAST、模糊测试，和自己的DAST产品，和Rapid7合作提供DAST产品。Snyk也不支持关键业务应用，如SAP，Salesforce，以及其他CRM、ERP应用。

  • 使用传统开发方法的企业，如瀑布式开发，或者主要购买产品供安全人员使用，而不是开发人员，也许会发现Snyk没有提供他们要求的安全和功能。

 

Synopsys

 

        新思是魔力象限中的领导者。总部在美国，新思一直在做战略性的收购，来定义和扩展安全SDLC工具的产品组合。最近的收购是2020年1月收购Tinfoil Security，增加了重要的API测试功能，在魔力象限其他玩家能够看到的功能（六月份，刚刚收购了Code Dx，Code Dx是一家应用安全风险管理解决方案提供商，可自动识别软件漏洞、更早发现漏洞，并进行优先排序和修复，收购后，新思科技成为首家提供全流程应用安全工具和服务的公司）。

        新思在其IAST产品Seeker中，增加了微服务分析的功能。给用户提供一个组件间数据流的可视化界面，这能够帮助识别潜在的不安全的数据流问题。厂商新的智能编排方案，可以集成到CI/CD管道中，使用策略即代码，基于代码变更的重要性和应用的风险概况，横跨多个产品和工具，包括第三方工具，自动地协调安全测试活动。这是业界推荐的做法，从第三方工具中加入数据，是向前的迈出的重要一步。

        新思对有着复杂，多团队开发，使用多种开发方法（敏捷，DevOps）的企业非常合适。

优势

  • 新思已经把自己的产品都容器化，作为一系列可编排的微服务（智能编排），允许在DevSecOps（代码拉取，构建事件）流程中由事件触发扫描。这允许开发人员在促进流程成熟时，有很高程度的灵活性和向前兼容性。

  • 新思的Code Sight插件，非常适合DevOps商店，实现建议和自动修复，修复验证。不管经验水平如何，对大多数开发团队都很适用。

  • 新思在Seeker IAST中，引入一个新的微服务分析功能，提供图形化视图，可以查看基于微服务的应用数据流，开发人员和安全人员都可以使用。

不足

  • Gartner客户反馈指出，取决于工具和当前的数据流，和当前软件开发实践的初始集成和持续维护，可能会非常复杂

  • 从中小企业的反馈指出，尽管对厂商解决方案的兴趣，价格常常超出预算，新思的销售流程也很复杂，客户在过程中不是很顺利

  • 智能编排是一个好想法，但当前仍然是早期阶段，导致一个从Synopsys Polaris和智能编排混合的报告。

 

Veracode

 

        Veracode是魔力象限的领导厂商，公司的产品在好几个用户场景中都表现地非常好。包括传统的开发方法和DevOps，由于缺少基础设施即代码扫描和容器扫描，所以在云原生环境中表现一般。

        Veracode已经增加了在DevSecOps中的投资，平台现在支持一种管道方法，在整个开发生命周期中，优化扫描时间。Veracode也扩展了和开发者生态系统的集成，包括AWS CodeStar、GitHub Action的支持、GitHub安全控制台反馈、GitLab问题和管道的反馈。

        Veracode在全球都有销售，通过扩展的经销商渠道支持，在好几个区域都有办公室。

优势

  • 公司的DAST产品由单机的Veracode discovery 服务补充，扫描客户的边界，发现以前未知的web应用。

  • 除了常见的开源漏洞数据源，Veracode的SCA产品通过一个基于自然语言处理的机器学习引擎，主动的发现开源库中的漏洞。这个扫描工作从代码提交分析到检查日志、缺陷报告和其他数据源。

  • Veracode在开发人员支持的方面表现很好，基于IDE的按需扫描，快速返回结果，直接返回到IDE，完善的修复指南随时可以，特别独一无二的是，Veracode在代码中标记安全最佳实践，提供有帮助的加固。用户能从Veracode Appsec 顾问得到一对一的咨询，在了解结果方面得到帮助。公司在2020早期年，还引入Veracode Security Lab，给开发人员提供交互式培训。

不足

  • 虽然在支持DevOps环境方面，Veracode已经做出了明显的改善，一些方面还需要额外的注意。公司没有支持基础设施即代码扫描，容器扫描也仅限于Docker，通过SCA产品交付，范围仅限于开源软件漏洞。Veracode没有单机的API 测试产品，虽然可以通过DAST来提供这个功能。

  • 在客户咨询时，Veracode客户注意到了高定价，特别是续费时。

  • 虽然Veracode把自己定位于全球厂商，有数量不多的区域分支机构，靠不断扩大的分销商支持。大多数公司的业务集中在北美。

 

WhiteHat Security

 

    WhiteHat Security是魔力象限中的挑战者。是市场中可靠玩家。能够适用很多开发类型和应用。WhiteHat 提供完整的AST工具，包括SAST，DAST，SCA和移动AST—API发现和测试，web应用的基础设施即代码测试和模糊测试。WhiteHat 的产在质量和易用性方面，有一个很稳定的水平，人工辅助的误报减少也很受客户喜欢。Sentinel 平台主要是DAST（应用运行时漏洞发现和测试）。WhiteHat现在从SAST产品中提供SCA功能。

    厂商一直持续完善它的获得专利的直接修复能力，修复建议自动化地推荐给开发人员。WhiteHat的产品基于服务，虽然厂商提供一个虚拟机设备共本地扫描，但结果送回到云里去验证、关联，包含在仪表盘和报告中。

    WhiteHat非常适合开始及正在促进他们安全SDLC成熟的客户。

优势

  • WhiteHat在Gartner用户中，作为一个DAST即服务的提供商，有着很好的声誉，应该被寻找AST SaaS平台的厂家所考虑。WhiteHat提供智能直达（Intelligence Directed）的DAST产品，持续的沿着DAST的道路发展，为了和DevSecOps、原生的API测试，云原生环境集成。

  • 在一个高价格HE 高复杂性著称的市场。WhiteHat提供相对简单的清楚的报价，对项目做预算变成一个相对简单的事情

  • WhiteHat Sentinel Dynamic提供持续，保证上线网站安全的DAST，实现自动化检测和评估，对新发现的漏洞报警，因此作为上线应用保护和早期报警。

不足

  • WhiteHat不提供IAST方案，也不是一个传统IAST工具，ID DAST 提供类似的功能

  • WhiteHat战略集中在使用运行时安全技术（如DAST），作为安全SDLC的核心工具，然而，市场看起来向支持容器和现代开发风格的新技术转变得非常快。

  • 客户报告说，扫描速度没有他们期望的那么快，WhiteHat的图形界面和报告工具需要一些改进，WhiteHat正在通过持续的开发，解决这个问题。

入围和淘汰标准

对于Gartner客户，魔力象限和关键能力研究识别、分析市场上与之紧密相关的厂商和产品。缺省上限为20个厂家，也会根据要求调整。入围的标准，代表了分析者认为对此研究有必要的特定属性。下面是2020年11月21日的标准：

  • 市场参与：

  • 提供专门的AST方案（产品，服务，或者两者兼有），至少涵盖以下四种AST功能中的两种：SCA，SAST，DAST，IAST，细节见市场定义/描述部分。

  • 至少提供这些额外能力的一种，基础设施即代码测试，容器测试，模糊测试，API测试，或者在云原生环境中的使用，如AWS，Azure，GCS。

  • 市场追踪

  • 在过去的四个季度，AST收入至少为2500万美元,包括2000万美元在北美/欧洲，中东和非洲（除掉专业的服务收入）。

  • 和Gartner客户相关的技术能力

  • 提供可重复、持续的、基于订阅方式的参与模式（如果厂商提供AST即服务），主要使用自己的测试工具，实现测试能力。技术能力必须包括：侧重点在安全测试，识别软件安全漏洞，根据OWASP和其他常见漏洞定义的报告模板。通过插件、API、命令行集成CI/CD工具（如Jenkins），和缺陷跟踪工具，（如Jira）。对开发人员在漏洞修复方面的指导。

  • SAST 产品/服务

  • 支持常见的开发语言（Java，C#，PHP，JavaScript）

  • 至少支持Eclipse，Visual Studio IDE，intelliJ IDEA插件

  • DAST产品/服务

  • 提供单机运行的AST方案，具有专门的web应用层动态扫描能力

  • 支持web 脚本编写和自动化工具，如Selenium

  • IAST产品/服务

  • 支持Java，.NET 应用

  • SCA产品/服务

  • 扫描常见的恶意软件能力

  • 扫描过期的漏洞库能力

  • 容器

  • 集成应用注册和容器注册的能力

  • 扫描开源成分中已知的漏洞，并和CVE关联

  • 基础设施即代码支持

  • 在部署之前做静态测试

  • 监控运行环境中的安全违规

  • 容器支持

  • 扫描容器中的开源漏洞

  • 在代码payload中，发现常见漏洞

  • 模糊测试

  • 自动化，持续的模糊测试

  • 支持C，C#，Java，Golang

  • API 测试

  • 测试对API暴力和访问

  • 测试API滥用和凭证填充

  • 云原生支持

  • 支持主要的公有云（Azure，AWS，GCP）

和Gartner客户有关的业务支持能力

  • 有电话、电子邮件、web客户支持。必须提供联系方式、门户网站、技术文档、使用英文的客户支持（或者客户所在地的官方语言）。

出局标准

   在此次报告中，如果一个厂家功能受限于下，将被排除：

  • 只支持移动平台、单一平台/编程语言

  • 提供服务，但并不是以可重复，预定义订阅为基础。—例如，提供定制咨询应用测试服务、协议渗透测试、专业服务

  • 提供网络漏洞扫描，但不提供单机AST能力，或只提供有限的web应用层动态扫描

  • 只提供协议测试，模糊测试方案，调试器，内存分析器，攻击生成器。

  • 主要提供运行时安全防护

  • 聚焦应用代码质量和完整性测试方案，或有限AST 能力的基本安全测试方案

开源软件考虑

        魔力象限用来评估在市场上商业产品，销售执行、远景、营销和产品支持，不包括评估开源软件、或重度依赖开源工具，和开源工具打包的的厂商产品。

其他玩家

        好几个厂家，属于AST领域，或者和AST有重叠，但没有被包含在这个报告里面。这个厂家当前并不符合我们的入围标准，但他们或者提供了AST功能，或满足了特定的AST需求及场景。

        这些厂家产品范围从咨询和专业服务，到相关方案范畴，包括：

  • 关键业务应用安全

  • 应用安全编排和关联（ASOC）

  •  应用安全要求和威胁管理（ASRTM）

  • Crowdsource安全测试平台（CSSTPs）

  • 只有API安全方案

  • 只有容器安全方案

 

评估标准（魔力象限横轴和纵轴的解释）

         这是如何评估组织和产品的标准，评估标准和权重告诉你支持Gartner市场观点的特定的属性和他们的相对重要性，也会用来评估在这个报告中的厂家。

执行能力（纵轴）

• 产品或服务：这个标准评估服务/竞争于指定市场的核心产品和服务。包括当前的产品和服务能力、质量、功能集、技巧等。可以自主开发，也可以OEM/合作伙伴。在市场定义/描述中定义和在子标准中已经详细说明。这个标准特别评估当前核心的AST产品/服务能力，质量和精确度，功能设置。效率和质量，集成到SDLC中也被评估。

•整体可行性：包括整体的财务健康，业务单元的财务和实际运行情况，评估组织持续提供产品及服务和持续投资的可能性，在厂家所有产品中的定位，我们也看对AST产品的重视程度、增长、估计的市场份额、客户基础等。

•销售执行/报价：这个标准看组织所有售前活动的能力，提供支持的架构。包括交易管理、报价、谈判、售前支持、整个销售渠道的有效性。

我们考察厂家面对简单或复杂项目时，如何在报价和技术支持上，体现他们的能力。评估包括客户对销售支持、报价、谈判的反馈。

•市场反应能力/记录：这个标准评估反应能力、改变方向的能力，随着机会发展、友商的行为变化、客户需求进化、市场动态的演变，灵活调整并实现竞争胜利。也考虑厂商对市场需求变化的反应历史。评估厂商更多的应用安全能力，符合企业的功能要求，当市场有新的要求，交付创新功能的历史记录。

•市场执行：这个标准，评估厂商为了影响市场而传递给市场的一些信息，包括清晰度、质量、创新性、程序效率等。推动品牌、提高产品意识、在客户头脑中建立一个主动的形象。通过宣传促销、领导地位、社交媒体、推荐、销售活动等、实现对客户心智的占领，我们评估了厂家在安全专家心中的的声誉和名誉。

•客户体验：我们考察了使客户达到预期结果的产品、服务和程序。特别包括质量供应商/买家互动、技术支持、客户支持。也包括附带工具、客户支持程序、用户组、服务水平协议等等。

•运营：这个标准评估组织完成目标和承诺的能力。包括组织结构的质量、技巧、经验、程序、系统，以及其他能有助于组织运作的更有效和高效的因素。

 

前瞻性（横轴）

•    市场理解：这个指理解客户需求，并将之转变成产品和服务的能力。厂商听取和理解客户需求，展示了对市场清晰远景，根据他们增加的远景，能够塑造、增强市场的改变。包括厂商理解买家需求，把他们转变成有效和有用的AST产品及服务。还要考察厂商在这个市场的关键能力，我们评估其重要性的意识为：

  • 和SDLC集成。（包括新兴的，更灵活的方法）

  • 第三方和开源组件的评估

  • 工具的易用性，和企业架构及流程的集成

  • 如何把这个意识转变成AST的产品和服务

• 销售策略：使用合适的网络，有效的策略来销售产品。包括直接或间接销售、市场营销、服务、沟通。此外，寻找能够扩展市场范围和深度、技术、服务、厂商的客户基础、专业性的合作伙伴。特别是看一个厂商如何通过方案展示给市场，并能够实现销售。例如，借助于合作伙伴和分销商，安全报告，互联网渠道等。

•市场营销策略：我们寻找有差异化的、信息清晰、持续的内部交流。在外部，通过社交媒体、广告、客户程序和定位描述来表达，也需要考虑企业符合新兴市场需求的知名度和可信度。

•产品策略：我们寻找产品开发和交付的方法，其强调市场的差异性、功能、方法符合当前和未来的需求。特别的是，我们看到了AST提供的产品和服务，其范围和模块化能如何满足不同客户的需求，和不同的测试程序的成熟度水平。我们评估厂商开发和交付的方案，和竞争对手的差异性，如何独特的解决关键用户的需求，软件如何集成相关的、非AST的功能，提高整体的应用安全。

•商业模式：评估设计、逻辑、实现持续成功的业务主张。

•垂直/行业战略：我们评估了直接资源（销售，产品，开发）的战略，符合细分市场和垂直市场特定需求的技巧和产品。

•创新：我们寻找直接、相关的、互补和协同的资源布局，利用专业知识或资本，来实现投资，巩固、防御或先发制人的目的。特别是，我们评估厂家如何创新去解决新兴的客户需求，如支持DevOps测试，API安全测试，无服务器的，微服务架构。我们也评估使安全测试更精确的开发方法。我们重视IAST领域的创新，但容器、培训、和开发者当前所使用的软件开发方法集成同样重要。

•地理战略：这个标准评估厂商对直接资源、技巧、具体满足本土之外地理区域的客户特定需求的战略，直接或者通过合作伙伴、渠道、和子公司，适合当地市场的方式。我们评估全球范围内的可用性和支持，包括使用本地语言对工具、控制台、客户服务的支持。

 

象限描述

领导者

在AST市场的领导者，证明着AST产品和服务的广度和深度。领导者典型地提供成熟的，有声誉的SAST/DAST/IAST/SCA产品，通过一个清晰的，规划好的路径支持现代开发人员增长的需要，来证明自己的远见。领导者在他们的方案中，提供对API 测试，基础设施即代码，模糊测试，容器支持，云原生开发支持。领导者也应该给组织提供用来测试的AST即服务和本地运行的交付模型，或一个企业级的报告框架，支持多个用户、组和角色，理想上通过一个单一管理控制台实现。领导者应该能够支持移动应用的测试，在他们提供的核心AST 技术上，展示强大的执行力。尽管在某些领域比较擅长，领导者应该提供一个强大的市场占有率、增长率和客户留存率完整的平台。

挑战者

    在魔力象限中的挑战者，是具有持续执行力的厂商，常常在特定领域占有优势（例如SAST，DAST，IAST），或关注单一交付模型（例如，只提供AST即服务）。此外，和领导者对比，他们还证明了在特定关注领域，显著的竞争性能力，也用客户群整体规模和增长，证明了他们的增长势头。

远见者

    魔力象限中的远见者，具有强烈的远景，满足不断变化的市场需求。包括提供创新能力，更好的推动DevOps，和SDLC集成或识别漏洞。远见者也许不如挑战者及领导者具有持续的执行力。

利基者

利基者提供满足特定用户可行的、可依靠的方案，当考虑到买家在寻找让他们满意的、解决特别业务和技术场景、最好的、最合适的方案时，利基者表现的很好。利基者也许解决了整个市场的一个子集需求。当企业的关注点是某个重要的功能，或特定的厂商经验，或当他们已经和厂商建立了关系，会倾向于挑选利基者系。利基者一般关注一个特定类型的AST技术，或交付模型，或指定的地理区域。

 

背景

   

        2021年应用安全测试魔力象限欢迎您。今年最显著的变化之一是厂商入围标准的扩充，从仅仅提供传统的AST工具（SAST/DAST/IAST/SCA）到包括API测试，移动安全测试，容器，基础设施即代码，其他解决云和现代应用的更宽广的视角。这反映了安全和开发团队对新工具的使用，本身也是对Gartner客户正在使用的开发类型多样性的一种反应，以及采用DevOps。新冠病毒已经加速了我们再过去三到四年一直遵循的趋势。在2020年，Gartner看到了一个明显的在容器安全和云原生应用问询的增加，对比2019年，提高了50%，而整个应用安全问询提高了20%。

        其他常见的问询围绕着价格，对过高报价的埋怨和担心都超过了以往。市场趋势是竞争更激烈。这样的怨言会提醒厂家重新考虑价格，保证竞争力。在这期间，买家应该准备激烈的谈判，对不同意的条款和条件提出警报，对大多数，仅仅基于用户的报价模型会提供一个价值和成本的最佳平衡，也会避免负责的，难以管理的报价方式。

        开发类型和进化，是设置2021年AST魔力象限上下文的一个好方法。看看这个市场和我们的客户，我们通常看到三类团队在使用AST：

  • 安全开发早期阶段：这是目前为止AST产品最大的客户。几乎是其他两类加起来的两倍。在这个阶段的团队正在从把渗透测试作为主要的安全开发控制手段开始转变到使用标准的AST工具集，常常是SAST和SCA。他们在寻找可重复的，降低的风险开发，他们能迭代使用来建立，进而改善他们的流程。这些团队的大多数都是中小规模的企业，通常每年的收入在2亿美元以下。

  • 安全开发中间阶段：下一个最大的使用团体已经建立了基本的流程，从基于关键性指标向基于风险的指标迈进。在这个阶段的团队，常常拥有了全部或者大多数基本工具，希望在整个流程和安全姿态中寻求增量的改进。他们希望增加模糊测试，威胁建模，代码签名，应用安全编排和关联（ASOC），API测试。常常中间阶段的团队在探索某种程度的云原生和微服务开发（常常采用K8s或Docker的形式），也有单页应用模式（SPA），但这还不是他们主要的交付成果。在2020年，这个团队加速采用这些技术。

  • 高级安全开发：高级团队的特点是全部或大多数应用都采用基于容器和云原生开发。他们关注基础设施即代码，单页应用（API管理），CWPP和类似的工具来保护他们的应用。在这个团队内，常常分成两个小团体，其中比较小的团体是从中间阶段转移到高级阶段，特点是有很好实践的安全开发实践，对安全工具的使用非常自信。另一个团体是稍微大一些，是从云中诞生的开发团队，有一个快速的，灵活的开发风格，但还不习惯保护开发，这些团队正在从DevOps向DevSecOps转移。除了上述提到的工具，第二个团体常常需要培训，教练等方式，把安全带进这个团队（可看把安全集成到DevSecOps工具链）

        2021年的AST魔力象限已经扩展到包括这些类型的每一类工具，包含安全开发的真正整体的视角。

市场概况

市场进化

        自从我们去年的魔力象限，应用安全测试（AST）市场已经持续目睹了重大的，根本性的变化，并大大增加了市场的规模和范围。此外，当前的厂商面对着新的竞争压力，随着很多传统上与AST无关的厂商进入到市场。其他结构性的变化包括持续采用新的应用形式因素（例如，容器化。对        API更大的依赖，移动和云原生），要求新的测试和安全能力。我们也已经观察到购买中心的持续移动，预算，开发人员和工程团队每天对他们开发的代码安全承担更大的责任，特别是在很多成熟的组织中，这些改变反映在魔力象限入围厂家的选择上，以及他们提供的功能。

        因为新冠疫情，Gartner 最初预测在2020年，AST支出将温和的、暂时地走弱。基于公司结果和其他调查数据，这个放缓并没有发生。事实上，在数字化关注的提高，（数字化常常都是由软件支持）在应用安全工具，刺激了更多的兴趣和花费。许多厂商报告了收入的增加，同比20%到30%的增长。

        市场的本质已经变化，传统上我们通过静态，动态和交互式AST工具来看待这个市场。虽然这些工具仍然是应用安全程序的主要力量，但也加入了很多其他的工具，包括软件成分分析，移动测试，关键业务（SAP ，Salesforce）应用测试，API测试，容器扫描，基础设施即代码扫描，在应用和云安全之间的界线开始模糊了。

市场空间

        考虑到所有这些因素，Gartner 估计在这个扩张的AST市场，2020年终端用户在这方面的支出，全球范围内达到22亿美元。我们将2021年增长率预测提高到了的18%，2021年达到26亿美元。地理上，市场还是以北美为中心，占到四分之三的份额。随着时间，我们估计其他区域的消费，主要是欧洲和澳大利亚，其他东南亚国家，会占到一半的销量。这些更新会体现在Gartner 的预测分析：全球信息安全和风险管理，2021年第二季度发布。

        在几种情况下，厂商尝试提高价格推动更强的需求。至少在短期，确实尝到了甜头，在接下来的三年，我们希望看到巨大的市场力将推动价格下降。就像已经观察到的情况，传统的厂商，面对来自大的云和网络安全公司和开源工具的低价格新的竞争压力。虽然价格下降，我们估计需求增长和更宽的市场渗透将支持积极的增长目标。

合并和收购

        在市场内的合并和收购，加强了去年趋势的加速，非传统的竞争者在AST领域继续深耕。首先开始于应用开发厂商GitLab，收购工具，扩充其AST功能。在2020年，GitLab在收购Peach Tech和Fuzzit的基础上，  在6月份宣布，扩充了动态和模糊测试能力。同时，GitHub在2019年收购了Semmle（静态代码扫描）,和Dependabot（软件成分分析）。

        网络和云安全厂商也在收购，扩充他们的业务，进入DevOps的开发元素。2021年2月，Palo Alto网络继续收购活动，宣告花费1.56亿美元收购Bridgecrew，Bridgecrew优势在基础架构即代码安全工具，并创建了开源产品checkov基础设施即代码扫描器。这个收购基于以往的收购，容器安全厂商Twistlock（2019年7月，四亿美元），无服务器应用安全公司PureSec（2019年6月，金额未披露）。思科也进军这个市场，2020年10月收购K8s安全专家Portshift，我们希望看到像这样的厂商变化，再加上容器化和云原生应用的普及，将显著地提高传统AST平台厂商的竞争压力。

         当前的市场活动非常活跃：

  • 2021年1月，Rapid7收购了kubernetes 安全专家AIcide。早在2020年5月，收购Divvycloud，对云原生应用提供多种安全合规能力，包括扩充到基础设施及代码扫描。

  • IAST和运行时自我防护（RASP）专家，Contrast Security扩充了产品范围，2020年11月，收购初创公司，CloudEssence增加了云原生应用安全支持。

  • 2020年9月，Snyk收购Deepcode，一个基于AI（语义分析）代码检查工具，在10月，以Snyk Code的名字重新发布。

  • Sonarsource，它的Sonarqube 代码质量分析工具有时被用来做安全测试，在2020年5月，收购了高级安全专家RIPS Technologies，关注   PHP，Java，Node.JS安全测试。

  • 行业老牌厂商，Checkmarx ，在4月，被私募公司hellman&friedman以11.15亿美元估值，从私募公司Insight Partners手中收购。

结论

        AST市场还远远没有平息硝烟，比以前提供了更大，更多种机会。参与者必须考虑到更广泛的成熟度和功能需求，准备面对来自新季度的竞争。当评估工具选项时，买家要扩大考虑到的厂家范围，同时了解增加竞争和需求对定价的可能影响，避免锁定在当前的价格水平。
