为什么读这个报告

        在对静态应用安全测试厂商进行的28个标准的测试中，我们挑选出来12个表现最优秀的厂商—CAST, Checkmarx，GitHub，GitLab，HCL Software，Micro Focus，Parasoft，Perforce Software，SonarSource，Synopsys，Veracode，和WhiteHat Security。对他们进行研究、分析和打分，这个报告介绍了每个产品是如何测试的，帮助安全专家根据他们的需求，选择合适自己的产品。

关键要点

    • Forrester揭示了一个市场，在这个市场中Veracode，新思，Checkmarx，Micro Focus是领导者；HCL Software，CAST是卓越表现者；GitHub，Parasoft，GitLab，Perforce Software，SonarSource 是竞争者；WhiteHat Security 是挑战者。

   • 开发者赋能，新架构支持，精确性是关键差异点。随着开发速度持续加快，团队拥抱新的开发方法。不管在哪里，通过什么方式构建应用，把安全构建到SDLC中的SAST方案，都将起到引领的作用。提供和CI/CD管道深入集成的厂商，快速扩展到保护新的架构，如容器，API，和架构即代码；持续改善性能和提高精确度，把他们自己定位为能够取悦安全和开发人员不可缺少的参与者。

下一代的SAST方案聚焦于开发者赋能

        静态应用安全测试工具最初是为安全专家设计的，忽视了开发人员的需求。因此，开发人员被误报率搞得很受打击。缺少应用上下文，被强迫从日常的工作流中移出，这种挫败感和分歧阻碍了使用。高兴的是，SAST的厂商们，已经改变了他们的认识，把开发人员作为应用安全流程中的关键一环。2020年，web应用安全攻击是外部攻击的首要原因，只要SAST持续和开发人员的工作流保持一致，在SDLC早期，帮助安全专家对应用安全弱点进行排序和解决问题，SAST会一直是解决自有代码漏洞的重要工具。

作为这些趋势的结果，SAST的客户们一直在寻找提供如下功能的供货商：

  • 拥抱开发者角色

SAST的方案必须融入到开发人员的工作当中，允许开发人员使用他们熟知的工具，工作得更有效率。寻找现成可用SAST方案，通过和常用的IDE、构建工具、代码库集成，服务整个CI/CD管道。此外，寻找提供具有可操作性、附有代码例子的修复指南；通过开发人员的工具集，得到桌面可用的交互式培训。

  • 比传统的代码定义更进一层

公司不仅仅使用传统的编程语言，如C++，Java，或更新的语言如Swift和Kotlin来构建应用。API已经变成一个通用的应用构建块，全民参与的开发者已经开始用低代码平台来构建应用，开发人员正在使用架构即代码来定义云配置。当你公司的代码定义扩展了，当开发人员来自于传统的开发组织外部，需要SAST工具能够扫描新类型的“代码”的漏洞。

  • 快速交付精确的结果

虽然SAST已经具备了很多新的特性，低误报率和短的扫描时间仍是基本的要求。许多客户仍然把精确性和性能作为挑战。对给定的应用结构和架构，误报率和性能指标之上，需要如何调整以实现买来即用，如何优化扫描性能仍是客户不断询问的问题。

评测总结

        Forrester Wave 评测领导者，卓越表现者，竞争者，挑战者。只是市场头部厂商的评测，并不代表整个厂商面貌。在其他两篇文档中，您会发现这个市场的更多信息。“Now Tech: Static Application Security Testing, Q3 2020” 和“The Forrester Tech TideTM: Application Security, Q4 2020” 

        我们希望这次评测只是一个起点，鼓励客户使用基于excel的厂商比较工具，利用标准权重的方法来查看产品评测结果。


厂商产品

在这次评测中，共选取了12家厂商，CAST, Checkmarx, GitHub, GitLab, HCL Software, Micro Focus, Parasoft, Perforce Software, SonarSource, Synopsys, Veracode, and WhiteHat Security。

厂商资料

    我们的分析，揭示了每个厂商的优点和不足。

领导者

  • Veracode 投资于开发人员体验

Veracode提供一个完全的SaaS版本，包括三个不同水平的扫描：IDE扫描（适用于单个开发人员），管道扫描（当代码加入管道中开始扫描），策略扫描（上线前检查）。Veracode近来发布安全实验室社区版，包括免费的安全开发培训模块，和一个付费的企业版，虽然这两个版本都无法直接集成到当前的SAST工具，最近Veracode已经更新了报价模式，简化购买流程。

优先级排序是一个优势，Veracode根据风险和修复容易程度，以图形化展示代码缺陷，在市场上没有对手。近几年来，Veracode已经努力变成更加开发者友好—一个重要的举措，考虑到许多客户参考其他厂商，指出Veracode以前在开发人员方面关注的不足。考虑开发人员体验，Veracode自己的客户反馈对修复指南能力评价很高，但在开发人员工作流和API上面临挑战。客户反馈称赞了Veracode高级专属支持—“关系确实很亲密”—对所有的业务单元整合平台。公司寻找企业级的SAST工具，Veracode仍然是首选。

  • 新思提供精确性，深度IDE集成，但定价引发质疑

新思的SAST方案，提供了一系列预发布扫描工具，使用Coverity实现SAST方案。通过新思北极星平台，可以在本地和通过SaaS提供Coverity，包含在内的Codesight IDE插件，在开发人员的IDE环境中，提供实时的扫描，内置修复指南，集成包括SAST和SCA功能（同时使用新思这两个产品的客户）的报告。购买新思电子学习的客户—并不属于Coverity的附件—能够得到和上下文代码相关的培训链接，来作为修复建议的部分参考。新思还引入了智能编排，一个策略即代码的模块，使用客户自定义的风险特征决定何时，何种测试是必要的。

客户反馈对Coverity的低误报率、灵活的报告和客户支持称赞有加。一个反馈评价，如果Coverity扫描标识了一个问题，“开发团队普遍的反应是它很精确，我们要看一下”。一个大的缺点是费用—即使他们对产品很满意，客户质疑是否报价和产品的收益相当。而且，虽然对微任务和小规模的应用程序，产品表现令人开心，但对大规模的单体应用扫描时间过长让人不是很满意。新思对于寻找强大的SAST方案，作为整体AST平台的一部分的客户很适合。

  • Checkmarx的CxSAST扩展了新的开发方法，但报告功能不强。

CxSAST通过Checkmarx的AppSec Accelerator，具有本地或托管服务的功能。Checkmarx集成了培训功能，叫作Codebashing，集成到CxSAST的修复指南中—这个功能得到所有用户的称赞。CxSAST已经投入资源支持新的开发方法，包括扫描OWASP Top 10 API问题，支持Salesforce的VisualForce和Lightning框架。

Checkmarx自带规则集是个优势，用户能够使用CxQL语言，根据定制的规则来扩充他们。CheckLmarx能够和大量的源代码控制和构建工具来集成，客户在开发过程的关键阶段，可以起用webhook加强代码扫描。风险排名和工作流修改是劣势，定制能力有限。客户调研，很渴望提供产品反馈—他们认为CxSAST在扫描性能上和支持语言上排名很高，强调了厂商关系的优势。调研也埋怨了报告功能的有限—特别是关键指标的缺失—一个客户说道“用户界面缺少想要的功能”。拥抱现代开发方法的客户，将会从Checkmarx对API的支持和CI/CD工具深度集成中获益良多。

  • Micro Focus使用第三方集成来丰富用户体验

Micro Focus Fortify可以部署在本地，也可以通过Fortify on Demand（FoD）提供SaaS模块。Fod方案可以完全自动化生成扫描结果，或通过安全专家人工检查来增强。Micro Focus提供一个安全工具套装，包括动态安全测试-Micro Focus WebInspect—能结合到Fortify里面，实现统一报告和分析，此外，Micro Focus支持好几个第三方安全工具解释器插件，允许发现结果显示在仪表盘上Fortify结果的旁边，Micro Focus 为所有的Fortify用户打造了培训平台，SecureCodeWarrior，提供一个前后关联的，游戏化的学习体验。

Fortify提供强大的语言支持和IDE集成，实时的发现缺陷。一些关键功能来自于第三方集成，如和SecureCodeWarrior集成支持开发修复指南、解释器插件导入第三方工具扫描数据。增强的领域包括风险排名，仅限于一个非定制的五星排名系统，和工作流修改。Micro Focus 客户调查称赞了其强大的API和易用性，虽然这些要求更好的说明文档和ServiceNow的原生集成，如果客户通过原厂或第三方工具，对SAST结果寻找额外的关联说明，应该考虑Fortify。

卓越表现者

  • HCL扩宽了支持语言，但修复指南不足

自从2019年HCL从IBM收购了应用安全的产品集，就一直努力把AppScan Source和AppScan on Cloud（ASoC）融合成一个单一引擎的统一方案。HCL客户可以选择本地，云或混合应用安全部署模式。HCL也发布了CodeSweep—AppScan 的社区版本，2020年，HCL支持了更多的语言，包括现代语言如Groovy，Go，Kotlin，Swift。在它“自带编程语言”的框架下，对还没有支持的新的特定语言，客户可以编写规则和修复建议。

虽然HCL提供语言和API相关的文章帮助修复，客户反馈HCL的修复指南排名很低，把它描述成“不足的”，“对没有经验的开发者帮助不大”。整体看来，HCL的客户反馈对关键功能很不满意，包括性能、漏报率、报告功能。反馈非常称赞业务关系，感觉到HCL会和客户工作在一起来解决功能问题。客户寻找一个灵活的部署模型和宽泛的语言支持，可以考虑HCL AppScan。

  • CAST提供架构水平的分析，但缺少SDLC集成

CAST应用智能平台（AIP）和CAST镜像不仅仅分析源代码，钻研数据结构，代码组件和依赖关系。CAST独特的功能是架构蓝图，基于CAST镜像扫描，以交互性的视角深入到应用细节内部。CAST客户，通过CAST或合作伙伴，能够在本地或托管服务的形式，部署CAST应用智能平台（AIP）和CAST镜像。

在我们评测的厂商中，CAST AIP有最全面的现成可用的规则集，涵盖行业标准、编码标准、移动应用。一个主要的缺点是缺乏和开发工具及CI/CD工具集成。AIP无法和IDE集成，只能够和Jira集成。客户对CAST的服务和支持团队反馈很热情，特别说明“CAST的工程团队非常有帮助，提供多种形式的支持”。他们也提到即使开发人员和架构师离开了团队，架构蓝图能够帮助保存积累知识。客户反馈希望看到研发团队前进中更多的创新。如果一个组织，希望扫描方案能够在系统级水平分析代码和架构，应该考虑CAST应用智能平台（AIP）和CAST镜像。

竞争者

  • GitHub视野开阔，但缺乏报告和语言支持等基本功能

GitHub在2019年，收购了Semmle和它的CodeQL分析引擎，获得了SAST方案。去年，公司把CodeQL集成到GitHub体验中，变成Advanced Security的一部分，对所有GitHub开源用户免费，商业用户可以按照每个用户的报价模式获得。GitHub集成了好几个本次报告中提到的竞争伙伴的产品，因此，GitHub的用户能够通过其他的SAST工具来加强CodeQL使用。GitHub的社区聚焦方法，也通过用户贡献定制的CodeQL查询来展示它自己，在GitHub提供的产品之外，保证更多的规则和语言支持。

当GitHub讨论它的远景时，社区元素也来到了前台—作为一个开源代码库的领导者，它认为内置的SAST让软件供应链更安全不可缺少。这个远景有潜力改变游戏，但今天的事实，GitHub承认，对于SAST市场，它还是一个新手，必须补齐功能。一个主要的弱点是报告，只限于一个单人的，无法定制的PDF文档，包括每次扫描的细节。用户反馈同意报告功能需要增强，但他们很满意SAST工具集成到GitHub中的易用性，不使用GitHub的客户，对CodeQL集成可以忽略，然而，完全使用GitHub作为开发的客户将会从CodeQL提供的SAST功能获益良多。

  • Parasoft 定制报告能力突出，但修复指南需要注意

Parasoft来自于代码质量领域，把安全作为一个质量问题来看待。Parasoft SAST开始静态分析C/C++，C#，Java，然后增加了其他安全和合规功能，扩展了支持语言、过程智能和追踪能力。扩展的语言支持是一系列的开源代码分析工具，能够把结果导入Parasoft，但Parasoft不维护他们，客户可以在本地和云中部署Parasoft。

本次报告汇总的许多厂商都在增强报告功能，Parasoft现成可用的可定制的报告功能表现优异，客户能够基于Parasoft提供的模板生成他们自己的仪表盘，或定制一个空的仪表盘，增加Parasoft提供和定制的小工具。可定制的风险评分也是一个优势，调查的客户对Parasoft的精确性排名很高，很喜欢这个新的仪表盘。修复指南收到的评级毁誉参半，有的人埋怨代码用例意义不大，偶尔还有错误现象。如果用户想解决web和嵌入式应用问题，能够提供开发人员，安全部门和管理层的报告，Parasoft是一个好的选择。

  • GitLab符合开发人员需求，但在SAST关键功能上缺乏竞争力

过去的几年中，GitLab投入巨资，把安全功能集成到GitLab的使用体验中，对于部署在生产环境中的应用，GitLab给单个开发人员提供功能分支扫描，给安全专家提供缺省分支扫描。SAST扫描对所有GitLab客户都可用，核心/免费用户都能从GitLab中运行SAST扫描，金牌/精华用户可以访问安全仪表盘，集成工作流。按每用户报价，扫描次数不限，扫描的应用数不限。调查用户看到了CI/CD集成的价值和开发人员的关注点，但当谈到其他功能，观点就褒贬不一。扫描性能和缺乏可用的调谐功能是痛点。一个调查用户描述GitLab作为一个低成本，操作效率高，高可用的方案，虽然不是最好的，但也足够好。问题是是否几年内仍会如此。GitLab的近期产品路线图包括补齐短板，像更多的支持语言、报告功能改善、定制规则集，但几年中计划完成的功能，和其他厂商的正在提供的功能类似。GitLab继续激进的在安全上投资，其优势是提供一个和其开发环境无缝集成的SAST方案。完整使用GitLab作为开发环境的客户，将想要调查是否SAST方案满足他们的需求。

  • Perforce Software的klocwork是功能安全和合规性最佳选择

2019年，Perforce收购了Rogue Wave，把klocwork SAST方案融合进它自己自动测试、代码管理、应用管理、敏捷管理方案系列产品中。Klocwork 聚焦在合规和产品功能安全，满足汽车行业，医疗，航空航天，制造业等打造关键应用客户的需求。重点在于深度而不是广度，只支持四种编程语言—C ，C++ ，C#，Java。紧盯新兴的安全标准如PCI DSS，CERT。对汽车产业软件可靠性协会（MISRA）的支持是其产品路线图上的主要部分。

Klocwork可以和很多IDE集成，帮助开发人员实时的指出问题。然而，它和其他工具的集成非常有限—甚至和其自己的敏捷管理工具，Helix ALM，要求客户写python脚本才能集成。从对Perforce的调查中，Forrester 收到有限的反馈，客户很难说清使用Perforce的细节。对关键功能的反馈，如精确性、性能、自带的规则集都很满意，但对Perforce在有限的时间内，开发新功能，修复缺陷的能力很难说清。打造关键应用，合规要求高的行业，会认可Perforce高度专注标准和功能安全的优势。

  • SonarSource的SonarQube是针对开发人员的方案

SonarSource来自于代码质量领域。在SonarQube中增加了SAST功能，但也关注质量、可靠性和技术负债。2020年5月，公司扩展了安全投资，收购了德国SAST厂商RIPS Technologies，SonarSource估计200000公司使用SonarQube的开源社区版本—商业开发和企业版本增加了数据流分析、OWASP安全报告、产品系列管理。在它发布的信息和战略中，SonarSource把开发人员作为其核心客户，强调开发人员获取的可操作数据和实施反馈的重要性。

开发人员优先的口号，遇到了SonarQube的一些功能缺陷。今天，SonarQube只支持Java，C#，PHP，Python语言，不提供和Jira工具的原生集成。亮点是定制规则，能通过查询语言或用户界面来生成。客户调查认为SonarQube是一个很好的开发工具，但管理企业级的项目会遇到挑战。例如，报告对开发人员发现和理解缺陷非常有帮助，但对了解整个企业范围的状况则用处不大。一个客户评价SonarQube说“缺少在企业中需要的灵活性”。寻找开发工具，也能做一些安全扫描的客户，会考虑SonarQube—大规模的开源使用意味着许多开发者非常熟悉它。

挑战者

  • WhiteHat Security 提供半托管的SAST方案

WhiteHat的Sentinel Source是WhiteHat Sentinel SaaS 平台的一部分，SaaS平台也包括DAST，SCA。对客户体验起到关键作用的是威胁研究团队，对不同的缺陷，生成和维护规则并指定了专属分数。用户可以通过平台、IDE、构建工具，关于安全代码实践和漏洞问题，直接向威胁研究团队询问，从反馈中得到对他们特定的修复努力的支持。注意，客户不能自己生成规则，必须向威胁研究团队提出要求。

WhiteHat只能得到有限的客户反馈—那些调查称赞了Sentinel的精确，但声明他们依靠WhiteHat的人工交互来消除误报。客户也在寻找对新语言的支持，如Kotlin，Swift。WhiteHat售后支持得到高分，主要来自于客户对威胁研究团队的依赖。对寻找半托管方案，希望放弃一些控制和敏捷，换取第三方支持的客户，WhiteHat是一个很好的选择。

测评概述
