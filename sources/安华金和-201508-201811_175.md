# 当银行催账走向互联网共享模式

近几年间，共享经济的模式正在迅速向各领域渗透，作为一种业务创新的流行趋势，互联网+共享的模式得到越来越多企业和部门的青睐。一时间，各类共享平台如雨后春笋般层出不穷，互联网催收平台的出现正是这种创新模式的又一衍生物。

![](../Images/f618c4831a96c24533aba8c581e38bf7.png)

**互联网创新的美好愿望是否经得起考验**

  

互联网催收模式今年发展迅速，平台试图通过云计算、大数据和智能化清收策略，解决不良资产清收的最后一公里难题。因为催收不是银行的强项，出于对用户数据安全的考虑，一直以来银行多会选择有律师资质的大公司进行催收合作，但随着银行业开始试水互联网催收模式，将信用卡欠款的催收与转让业务外包，信用卡用户的隐私数据不再隐私。

**层层转包引发数据泄露隐患 谁来担责？**

  

有记者发现，使用一个虚假身份信息便可在催收平台成功注册成为催客，轻易获取完整字段的欠款人信息，及其家人或朋友的详细个人信息。银行信用卡逾期用户和亲人的信息相当于在互联网上公之于众，如此高敏感度的隐私数据也面临在层层转包中被轻易泄露，商业创新的表象下，暗涌的是巨大的数据泄露风险。 

一位相关机构高管表示：“转包行为本身没什么问题，但银行对本身的数据安全负责，就要间接对使用他数据的供应商负责。银行对供应商的选择，针对信息安全（数据来源、传输、存储）应该有一套规则，选择时应按这个规则来选择厂商，所以问题不在转包，在于银行选择的厂商是否具备足够的信息安全规格与技术来确保信息安全。”

**数据流转、共享场景下如何保证安全**

  

事实上，除了银行，政府、运营商、企业等各行业都面临互联网模式的业务整合与转变，跨部门、跨单位、跨行业的数据流转与共享场景越来越普遍，数据的价值在使用中提升，但其中各环节可能发生的数据泄露风险任何一方都不能免责。

不同于传统的数据安全防护多是抵御外部攻击的应用边界防护，对于数据大集中和共享场景下的安全需要针对整个数据产生、使用、集中、共享及外发各个环节中的安全保护，需要形成整体的全面安全策略，这也是目前越来越多的政府与大型企业启动数据安全治理工作的原因。

**以数据的安全使用为目的进行安全治理**

  

不同于传统安全主要防外的理念，数据安全治理主要面向内部或准内部人员，以这些人员行为的安全管控为主要对象；以数据分级分类为基础，以信息合理、安全流动为目标；以信息使用过程的安全管理和技术支撑为手段；将安全产品技术和流程管理深度整合，形成真正可落地的整体数据安全建设规划。

这里的技术手段支撑需要区分考虑数据的不同类别、敏感级别，以及在各个使用和共享状态下，不同访问者、使用者和管理者的身份和权限使用不同的数据安全技术提供安全保障。

**数据安全状况评估**

通过数据资产梳理技术对数据资产的分布情况，包括敏感数据的存储分布、敏感数据的系统访问状况、敏感数据的批量访问状况、敏感数据的访问风险；

通过数据库漏洞扫描技术实现对数据库安全漏洞和脆弱点等的安全检查。

**数据访问行为管控**

通过数据运维审批和管控技术、数据库防火墙技术、数据库加密和脱敏技术实现敏感数据的访问控制安全。

通过数据水印技术实现数据泄露后的泄漏源定位，有效追责。

**数据访问稽核**

通过数据审计技术实现数据安全稽核，保障数据治理的策略和规范被有效执行和落地，保障能够快速发现潜在的风险和行为。

  

回到文章开头的互联网催收模式中来，在数据外发共享的过程中，面临泄露风险的数据是由银行向用户采集、管理并分发，层层转包后可能出现的数据泄露责任银行与互联网平台都无法推脱。数据的所有者永远是用户自己，那么如何在享受数据共享和流转带来的红利时，实现数据的安全使用，是所有掌握用户数据的部门和机构需要共同思考的问题。
