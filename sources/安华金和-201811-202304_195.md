# 视图分享 | Web应用的网络数据安全防护

近年来，面向公众提供服务的动态网站应用与日俱增，人们在日常工作、生活中常常需要使用大量的Web应用，比如通过电脑和手机登录网上银行、开展远程办公、查询个人社保信息等操作。而对大型企业而言，其分支机构遍布各地，企业内部也需要通过互联网实现信息共享、协同办公、业务流转等信息化管理任务。某些企业的数据库甚至直接安装在对外提供Web服务的计算机上，一旦Web服务器被黑客攻入，企业数据库中的敏感信息很可能被黑客恶意访问、泄露、篡改和破坏。**因此，Web应用的网络数据安全防护无疑是个很重要的课题。**

![](../Images/3322edd2906a289eeb835930d86cc917.png)

  

Web应用访问过程  

  

![](../Images/6a529ba3a93ec3962987bc161d6bf18e.png)

  

Web用户在笔记本上使用浏览器输入网址访问Web服务器，即B/S架构（浏览器/服务器模式）；Web用户在笔记本上使用已安装好的软件应用程序通过互联网访问Web服务器，即C/S架构（客户端/服务器模式）。以上两种模式各有利弊，但通常在互联网上使用的是http协议（超文本传输协议）或https协议（带SSL的http加密协议，安全性更高）。此外，当前人们广泛且频繁使用的移动互联网，则是通过手机app或手机浏览器访问Web应用服务器。

  

伴随公有云的高速普及发展，多数Web应用服务器已部署在阿里云、腾讯云等云服务器之上；当然，也有很多重要的单位是部署在自建IDC机房中的。大型Web应用可能有多台Web服务器，前面常部署Web负载均衡以满足海量网民的并发访问需求，另有一些Web服务器则以存放和展示静态网页为主。当调用动态网页程序时，会访问Web应用服务器，常采用的开发架构有J2EE、.Net Framework等，使用PHP程序框架的也越来越多，有时候还会出现存放使用Java或C#编程的中间件服务器，最终形成SQL语句访问数据库服务器。

  

**了解一个Web应用的大致执行过程，是做好网络数据安全防护的前提和基础。**

  

网络防火墙

  

![](../Images/fef8629d1e3529c1a3c4cb8174034a00.png)

  

互联网和内网之间需要部署网络防火墙。网络防火墙产品主要基于**“源IP+源端口+目的IP+目的端口+协议类型”**进行访问控制，无法对协议的内容进行解析和控制；然而，应用需要访问数据库，因此数据库的通讯端口总是开放的，这就使得网络防火墙对数据库网络通讯无法提供安全防护支撑。

  

行业标准OSI参考模型将网络通信过程分为7个不同层次，分别是：**应用层、表示层、会话层、传输层、网络层、数据链路层、物理层**。网络防火墙主要负责1~4层的网络安全，是内外网隔离必备的防护设备。

  

IDS/IPS

  

IDS/IPS（入侵侦测系统/入侵防护系统）产品相较网络防火墙要更进一步，已开始尝试对应用层的通讯协议进行解析，但仅限于标准通讯协议，如：**FTP、邮件、LDAP、Telnet**等，只能对一些针对标准协议的攻击行为进行防范，而对于数据库非标准化且复杂度高的通讯协议，当前市场上主流的IDS/IPS产品尚未实现对数据库通讯协议的有效解析和防护。

  

WAF

![](../Images/20d63d8bd54ebb7162874d1886fe6ea0.png)WAF（Web Application Firewall 网站应用防火墙），串联部署在Web应用服务器之前，可通过对http协议中的内容进行分析，实现对攻击的防御。通过WAF可以实现对部分SQL注入行为的阻止，但WAF对于复杂的SQL注入和攻击行为却无能为力——**大约有150多种方法可以绕开WAF实现对Web应用服务器的攻击，其中：在Web应用服务器上，利用应用数据库账户攻击数据库服务器是当前刷库的主要手段之一。**

  

堡垒机

  

![](../Images/8e0dda0d2bddddf3833c814635e9c683.png)

  

堡垒机主要针对来自内部的主机、网络、数据库的运维安全风险问题，可将运维人员对主机设备及数据库的维护集中到堡垒机上完成，进行统一的认证、授权和审计。但是，**堡垒机也存在“无法对图形化工具的操作进行控制，只能通过录屏的方式进行录像记录”等安全防护短板。**

  

数据库防火墙

![](../Images/a4d9b9573de0411639be2426104f81c5.png)数据库防火墙产品需串联部署在数据库服务器之前，是基于数据库访问协议分析与控制技术的网络数据库安全防护系统：能够基于主动防御机制，实现对数据库的访问行为控制、危险操作阻断、可疑行为审计；同时，提供SQL注入禁止与数据库虚拟补丁包等功能——**通过虚拟补丁，数据库系统不用升级、打补丁，也可完成对主要数据库漏洞的安全防护。**

  

数据库审计

  

![](../Images/1e7cb2d7644dd489d8ae13b296612518.png)

  

数据库审计通过交换机镜像流量旁路部署，因其对客户现有业务环境并不会产生影响，所以在银行、电力、医院等对业务连续性及并发性能等要求极高的单位，数据库审计产品成为首选。此外，由于堡垒机只能针对运维操作进行管控，而数据库审计却能在运维侧和应用侧同时发挥作用，也令其成为诸多与数据库相关安全建设的必选产品。

  

近年来，国内外先后曝出多起与Web应用及API相关的重大数据安全事件。当前，通信、金融、交通等诸多领域的大型客户，愈发关注Web应用是否存在敏感数据经由API接口等方式泄露的风险以及对应的防护措施，而该领域也尚属安全厂商们的一个短板。本文中介绍的每项安全防护设备及对应措施，在整套安全防护体系建设中都有不可或缺的价值和作用，它们互为补全，共同保障Web应用网络数据的使用安全！
