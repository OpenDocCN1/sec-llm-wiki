在上一章中，我们做了 iOS 平台的概览，并介绍了 iOS 应用程序的结构。在本章中，我们将介绍可用于测试 iOS 应用程序的安全漏洞的基本过程和技术。这些基本过程是后续各章概述的测试用例的基础。


iOS 测试环境搭建


主机设备


尽管可以使用 Linux 或 Windows 机器进行测试，但是你会发现在这些平台上很多任务难以或者无法达成。 此外，Xcode 开发环境和 iOS SDK 仅适用于 macOS。 这意味着你肯定更想要在 macOS 上进行源代码分析和调试（黑盒测试也更加容易）。

 

以下是最基本的 iOS 应用测试环境要求：

 

  • 理想情况下，具有管理员权限的 macOS 电脑。
  • 允许客户端到客户端通信的 Wi-Fi 网络。
  • 至少一台越狱的 iOS 设备（特定的 iOS 版本）。
  • Burp Suite 或其他请求代理工具。


配置 Xcode 和命令行工具


Xcode 是 macOS 上的集成开发环境（IDE），其中包含用于开发 macOS、iOS、watchOS 和 tvOS 上的软件的一系列工具。 你可以从 Apple 官方网站免费下载 Xcode。 Xcode 提供了与 iOS 设备进行交互的不同工具和功能，这在渗透测试（例如分析日志或应用的旁载）期间会有所帮助。

 

所有开发工具已经包含在Xcode 中，但在终端中不可用。 为了使它们在系统范围内可用，建议安装命令行工具包。 在测试 iOS 应用程序时，这将非常方便，因为您稍后将使用的某些工具（例如，objection）也依赖于此软件包的可用性。 您可以从 Apple 官方网站下载它，也可以直接从终端安装它：


$ xcode-select --install


测试设备


获取 iOS 设备的 UDID


UDID 是由 40 位字母和数字组成的唯一序列，用于标识 iOS 设备。由于 iTunes 在 Catalina 中不再可用，在 MacOS Catalina 以后可以在 Finder 中找到 iOS 设备的 UDID。只需在 Finder 中选择连接的 iOS 设备，然后单击iOS 设备名称下的信息即可。除了 UDID，还可以找到序列号、IMEI 和其他有用的信息。


在 Catalina 之前的 macOS 版本中，可以通过 iTunes 找到 iOS 设备的 UDID，方法是选择设备，然后在摘要标签中单击“序列号”。单击此按钮时，将遍历 iOS 设备的不同元数据，包括其 UDID。

通过 USB 连接设备时，还可以通过 macOS 上的各种命令行工具获取 UDID：

  • 使用 I/O Registry Explorer 工具 ioreg：

    $ ioreg -p IOUSB -l | grep "USB Serial"
    |         "USB Serial Number" = "9e8ada44246cee813e2f8c1407520bf2f84849ec"


  • 使用  ideviceinstaller（Linux 上也可用）

$ brew install ideviceinstaller
$ idevice_id -l
316f01bd160932d2bf2f95f1f142bc29b1c62dbc

  • 使用 system_profiler

    $ system_profiler SPUSBDataType | sed -n -e '/iPad/,/Serial/p;/iPhone/,/Serial/p;/iPod/,/Serial/p' | grep "Serial Number:"
    2019-09-08 10:18:03.920 system_profiler[13251:1050356] SPUSBDevice: IOCreatePlugInInterfaceForService failed 0xe00002be
                Serial Number: 64655621de6ef5e56a874d63f1e1bdd14f7103b1


  • 使用 instrument

$ instruments -s devices


在真实设备上测试（越狱）


最好有一部越狱的 iPhone 或 iPad 来进行测试。 越狱后的设备允许 root 访问和工具安装，从而使安全测试过程更加简单。 如果还没有越狱设备，则可以使用本章后面介绍的方法解决，但要准备好接受更艰难的体验。


在 iOS 模拟器上测试


与 Android 模拟器完全模拟真实 Android 设备的硬件不同，iOS SDK 模拟器提供了 iOS 设备的上层模拟。 最重要的是，仿真器二进制文件被编译为 x86 代码而不是 ARM 代码。 模拟器上无法运行为真实设备编译的应用程序，意味着无法使用模拟器进行黑盒测试和逆向工程。


在虚拟机上测试


Corellium 是唯一公开可用的 iOS 虚拟机。 它是单用户许可证模型的企业 SaaS 解决方案，并且不提供任何试用许可证。


获取特权访问


通常将 iOS 越狱与 Android 的 root 做对比，但过程实际上是完全不同的。为了解释差异，我们将首先回顾 Android 上 “root” 和 “刷机” 的概念。

    • root：这通常涉及在系统上安装二进制文件 su 或用已 root 的自定义 ROM 替换整个系统。只要 bootloader 是可访问的，就不需要利用漏洞来获得 root 访问权限。

    • 刷自定义 ROM：解锁 bootloader 后，就可以替换设备上正在运行的操作系统。bootloader 可能需要利用漏洞才能解锁。


在 iOS 设备上，无法刷自定义 ROM，因为 iOS bootloader 仅允许引导和刷入 Apple 签名的镜像。这就是为什么未通过 Apple 签名的官方 iOS 镜像也无法安装的原因，并且这使得仅在以前的 iOS 版本仍被认证的情况下才可能进行 iOS 降级。


越狱的目的是禁用 iOS 保护（尤其是 Apple 的代码签名机制），以便可以在设备上运行任意未签名的代码。 “越狱”一词通俗地说是自动禁用校验过程的多合一工具。


Cydia 是由 Jay Freeman（又名“ saurik”）为越狱设备开发的替代应用程序商店。它提供了图形用户界面和高级打包工具（APT）。你可以通过 Cydia 轻松访问许多“未经许可”的应用程序包。大多数越狱都会自动安装 Cydia。


iOS 11 越狱引入了 Sileo，这是针对 iOS 设备的新越狱应用程序商店。 iOS 12 的越狱 Chimera 也依赖 Sileo 作为软件包管理器。


为给定版本的 iOS 开发越狱并不容易。 作为安全测试人员，很希望使用公开可用的越狱工具。 尽管如此，我们还是建议你研究用于越狱各种版本的 iOS 的技术，你将遇到许多有趣的漏洞，并了解许多有关 OS 内部的知识。 例如，适用于 iOS 9.x 的 Pangu9 至少利用了五个漏洞，其中包括内核的 use-after-free 漏洞（CVE-2015-6794）和“照片”应用程序中的任意文件系统访问漏洞（CVE-2015-7037）。


 由于越狱会停用某些 iOS 的默认安全机制。 一些应用会尝试检测运行它们的 iOS 设备是否已越狱。但是，有几种方法可以解决这些检测问题，我们将在“Reverse Engineering and Tampering on iOS”和“Testing Anti-Reversing Defenses on iOS”章节中介绍它们。


越狱的好处


个人用户经常会越狱设备来调整 iOS 系统的外观，添加新功能以及从非官方应用程序商店安装第三方应用程序。 对于安全测试人员来说，越狱 iOS 设备会带来更多好处。 它们包括但不限于以下内容：

 

  • 文件系统的 root 访问权限。
  • 可以执行未经 Apple 签名的应用程序（包括许多安全工具）。
  • 不受限制的调试和动态分析。
  • 访问 Objective-C 或 Swift 运行时。

越狱的类型


  • Tethered 越狱，设备重启后不会保留，因此重新越狱需要每次重启都将设备连接到电脑。如果未连接电脑，则设备可能根本不会重启。
  • Semi-tethered 越狱，如果要使越狱重新生效，必须每次重启时将设备连接到电脑。该设备还可以自行启动进入非越狱模式。
  • Semi-untethered 越狱，允许设备自行启动，但是用于禁用代码签名的内核补丁（或用户域修改）不会自动启用。 用户必须通过打开一个应用程序或访问一个网站来重新越狱设备（不需要连接到计算机，因此是 untethered）。
  • Untethered 越狱，对于个人用户而言，Untethered 越狱是最流行的选择，因为仅需应用一次，此后该设备将被永久越狱。

注意事项


越狱 iOS 设备变得越来越复杂，因为 Apple 不断加固系统并修补可利用的漏洞。越狱已成为一个非常时间敏感的过程，因为苹果公司在发布修复程序后相对较快地停止对那些易受攻击的版本进行签名（除非越狱得益于基于硬件的漏洞，例如影响 iPhone 4 和 iPad 1 的 bootROM 的 limera1n 漏洞）。也就是说一旦 Apple 停止对固件进行签名，便无法降级到特定的 iOS 版本。


如果你有一台用于安全测试的越狱设备，请保持原样，除非 100％ 确信在升级到最新的 iOS 版本后可以将其重新越狱。考虑准备一个（或多个）备用设备（更新到每个主要的 iOS 版本），并等待公开的越狱。公开发布越狱程序后，Apple 通常会很快发布补丁程序，因此只有几天的时间（如果它仍由 Apple 签署）降级到受影响的 iOS 版本并应用越狱程序。

iOS  升级基于挑战-应答流程（因此产生了所谓的 SHSH Blob）。仅当对挑战的响应由 Apple 签署时，设备才允许安装操作系统。这就是研究人员所说的“签名窗口”，这就是为什么你不能简单地存储下载的 OTA 固件包并将其加载到设备上的原因。 iOS 小版本升级期间，Apple 可能会同时签署两个版本（最新版本和前一个 iOS 版本）。这是唯一可以降级 iOS 设备的情况。您可以检查当前的签名窗口并从 IPSW Downloads 网站下载 OTA 固件。

使用哪种越狱工具


不同的 iOS 版本需要不同的越狱技术。确定你的 iOS 版本是否可以使用公开越狱。提防假冒工具和间谍软件，它们通常藏在与越狱组/作者的名称相似的域名后面。

越狱的 Pangu 1.3.0 适用于运行 iOS 9.0 的 64 位设备。 如果你的设备运行的 iOS 版本没有越狱功能，则在你降级或升级到目标可越狱的 iOS 版本（通过IPSW 下载或 iOS 更新机制）后，仍然可以越狱该设备。 但是，如果所需的 iOS 版本不再由Apple 签名，就没有办法这样做了。

iOS 越狱场景发展太快了，很难提供实时的最新说明。 但是，我们可以为你列出一些目前可靠的资源。

  • Can I Jailbreak?（https://canijailbreak.com/）
  • The iPhone Wiki（https://www.theiphonewiki.com/）
  • Redmond Pie（https://www.redmondpie.com/）
  • Reddit Jailbreak（https://www.reddit.com/r/jailbreak/）
 
请注意，对设备所做的任何修改均需你自担风险。通常情况下，越狱是安全的，但事情可能会出错，并且最终可能会使设备变砖。你需要为损坏自担风险。

推荐工具 - iOS 设备


可以使用 Cydia 安装越狱设备上的许多工具，Cydia 是 iOS 设备的非官方 AppStore，它可让你管理软件仓库。在 Cydia 中，你可以导航到Sources-> Edit，然后单击左上角的 Add，来添加（如果默认情况下没有）以下代码仓库：

  • http://apt.thebigboss.org/repofiles/cydia/: BigBoss 是最流行的仓库之一，它有丰富的安装包，比如 BigBoss Recommended Tools。
  • https://cydia.akemi.ai/: 添加 "Karen's Repo" 仓库来获取 AppSync。
  • https://build.frida.re: 通过添加这个仓库到 Cydia 来安装 Frida。
  • http://mobiletools.mwrinfosecurity.com/cydia/: The Needle agent, 也有它自己的仓库，需要添加。它也可以通过以下仓库来获取 https://github.com/fsecurelabs/needle-agent。
  • https://repo.chariz.io: 在 iOS 11上管理越狱很有用。
  • https://apt.bingner.com/: Elucubratus 是另一个拥有一些不错的工具的仓库，当你使用 Unc0ver 在 iOS 12 上安装 Cydia 时，将安装该仓库。
  • https://coolstar.org/publicrepo/: 对于 Needle，应该考虑添加 Coolstar     仓库，以便安装 Darwin CC Tools。
 
如果你使用的是 Sileo App Store，请记住，Sileo 兼容层在 Cydia 和 Sileo 之间共享你的源。但是，Cydia 无法删除在 Sileo 中添加的源，同时 Sileo 也无法删除在 Cydia 中添加的源。 当你尝试删除源时，请记住这一点。


在添加完上面所有建议的仓库后，可以从 Cydia 安装以下有用的软件包并开始使用：

  • adv-cmds: 高级的命令行工具，包含了如 finger、fingerd、last、lsvfs、md 和 ps 等工具。
  • AppList: 允许开发人员查询已安装应用程序的列表，并基于该列表提供首选项窗格。
  • Apt: 高级软件包工具，你可以使用它来管理已安装的软件包，类似于 DPKG，但是更友好。这使你可以从 Cydia 仓库安装、卸载、升级和降级软件包。来自 Elucubratus。
  • AppSync Unified: 允许你同步和安装未签名的 iOS 应用程序。
  • BigBoss Recommended Tools: 安装了许多有用的命令行工具以进行安全测试，包括 iOS 缺少的标准 Unix 实用程序，包括 wget、unrar、less 和     sqlite3 客户端。
  • Class-dump: 一种命令行工具，用于检查存储在  Mach-O 文件中的Objective-C 运行时信息，并可以通过类接口生成头文件。
  • Class-dump-Z:一种命令行工具，用于检查存储在 Mach-O 文件中的Swift 运行时信息，并可以通过类接口生成头文件。 Cydia 无法使用此功能，因此请参考安装步骤以使 class-dump-z 在你的 iOS 设备上运行。
  • Clutch: 用于解密应用程序可执行文件。
  • Cycript: 是一种内联，优化的 Cycript-to-JavaScript 编译器和即时模式控制台环境，可以将其注入正在运行的进程中（与  Substrate 相关）。
  • Cydia Substrate: 通过动态应用程序操纵或内省，使第三方 iOS 附加组件开发更加轻松的一个平台。
  • cURL: 是众所周知的 http 客户端，可用于将软件包更快地下载到设备。例如，当你需要在设备上安装不同版本的  Frida-server 时，会很有用。
  • Darwin CC Tools: 从 Coolstar 仓库中安装 Darwin CC Tools，作为对 Needle 的依赖。
  • IPA Installer Console: 用于从命令行安装 IPA 应用程序包的工具。安装后，     installipa 和 ipainstaller 命令都可用，两者作用相同。
  • Frida: 可用于动态检测的应用程序。请注意，Frida 随着时间的推移更改了其     API 的实现，这意味着某些脚本可能仅适用于 Frida-server 的特定版本（这也迫使你在 macOS 上更新/降级其版本）。建议运行通过 APT 或 Cydia 安装的 Frida Server。之后，可以按照此 Github issue 的说明进行升级/降级。（https://github.com/AloneMonkey/frida-ios-dump/issues/65#issuecomment-490790602）
  • Grep: 用来过滤文本行的方便工具。
  • Gzip: 知名的 ZIP 软件。
  • Needle-Agent: Needle 框架的一部分，需要安装在iOS设备上。
  • Open for iOS 11: 启用 Needle Agent 功能所需的工具。
  • PreferenceLoader: 基于 Sbustrate 的实用程序，允许开发人员将条目添加到“设置”应用程序，类似于 App Store 应用程序使用的 SettingsBundle。
  • SOcket CAT: 可用于连接套接字以读取和写入消息的实用程序。 如果你想在 iOS 12 设备上跟踪系统日志，它可能会派上用场。

除 Cydia 以外，还有其他几种可用的开源工具应被安装，例如 Introspy。
除了 Cydia 之外，你还可以使用 ssh 进入 iOS 设备，并且可以直接通过 apt-get 安装软件包，例如安装 adv-cmds：
$ apt-get update
$ apt-get install adv-cmds


iDevice USB 的小注意事项


在 iOS 11.4.1 及之后由于 USB 受限模式的引入， iOS 设备处于锁定状态 1 小时后，你将无法再进行数据连接，除非再次解锁。


推荐工具 - 主机


为了分析 iOS 应用，你应该在主机上安装以下工具。在整个指南中，我们将使用它们。请注意，其中很多将需要 macOS 才能运行，因此在测试 iOS 应用程序时，通常建议使用 macOS 电脑。


Burp Suite


Burp Suite 是一个拦截代理，可用于分析应用程序和与其通信的 API 之间的流量。如何在 iOS 环境中进行设置，请参阅下面“设置拦截代理”的部分。


Frida


Frida 是一个免费的开源动态代码注入工具包，可让你在 native 应用程序中执行 JavaScript 片段。它已在常规测试指南的“篡改和逆向工程”一章中介绍过。Frida 将在以下几个部分和章节中使用。


Frida 支持通过 ObjC API 与 Objective-C 运行时进行交互。你可以 hook 或调用进程中及 native libraries 中的 Ojective-C 和 native 方法。你的 JavaScript 代码段具有对内存的完全访问权限，例如读取和/或写入任何结构化数据。


以下是 Frida API 提供的一些功能，这些功能是 iOS 相关的或专有的：

 

  • 实例化 Objective-C 对象并调用静态和非静态类方法（ObjC API）。
  • 跟踪 Objective-C 方法调用和/或替换其实现（Interceptor API）。
  • 通过扫描堆枚举特定类的活动实例（ObjC API）。
  • 扫描进程内存中是否出现字符串（Memory API）。
  • 拦截 native 函数调用以在函数入口和出口运行自己的代码（Interceptor API）。
在iOS上，你还可以从安装 Frida 时所提供的内置工具中受益，其中包括 Frida CLI（frida）、frida-ps、frida-ls-devices 和 frida-trace等。
iOS 上有一项值得关注的 frida-trace 功能：使用 -m 标志和通配符来跟踪 Objective-C API。例如，可以简单运行以下命令来跟踪名称中包括“ HTTP”并属于名称以“NSURL”开头的任何类的所有方法：
$ frida-trace -U YourApp -m "*[NSURL* *HTTP*]"
可以通过 https://www.frida.re/docs/examples/ios/ 快速入门。

Frida-ios-dump


Frida-ios-dump 允许您从 iOS 设备提取解密的 IPA。请参阅“使用 Frida-ios-dump” 一节以获取有关如何使用它的详细说明。


IDB


IDB 是一个开源工具，可简化 iOS 应用安全评估和研究的一些常见任务。 https://www.idbtool.com/installation/ 文档中提供了IDB的安装说明。


单击 IDB 中的“Connect to USB/SSH device”按钮，然后在启动 IDB 终端中键入 SSH 密码即可使用。 现在，您可以单击“Select App...”，选择要分析的应用程序并获取该应用程序的元信息。 现在，你可以进行二进制分析，查看本地存储并检查 IPC 了。


请记住，选择应用程序后，IDB 可能会不稳定并崩溃。


ios-deploy


使用 ios-deploy，你可以从命令行安装和调试 iOS 应用，而无需使用 Xcode。可以通过 brew 在 macOS 上安装它：

$ brew install ios-deploy


有关用法，请参阅下面的“ ios-deploy”部分，该部分是“安装应用”的一部分。


iFunBox


iFunBox 是支持 iOS 使用的文件和应用程序管理工具。 


可以在 http://www.i-funbox.com/en_download.html 下载。它具有多种功能，例如应用程序安装，无需越狱即可访问应用程序沙箱等。


Keychain-dumper

移动安全框架 - MobSF


MobSF 是一种自动化的多合一移动应用程序渗透测试框架，该框架还支持 iOS IPA 文件。使用 MobSF 的最简单方法是通过 Docker。

$ docker pull opensecurity/mobile-security-framework-mobsf
$ docker run -it -p 8000:8000 opensecurity/mobile-security-framework-mobsf:latest


或通过运行以下命令在主机上本地安装并启动它：

# Setup
git clone https://github.com/MobSF/Mobile-Security-Framework-MobSF.git
cd Mobile-Security-Framework-MobSF
./setup.sh # For Linux and Mac
setup.bat # For Windows

# Installation process
./run.sh # For Linux and Mac
run.bat # For Windows

通过在 macOS 主机上本地运行它，你将获得稍微更好的类转储输出。


启动并运行 MobSF 后，您可以通过浏览器访问 http://127.0.0.1:8000 打开它。 只需将要分析的 IPA 拖到上传区域，MobSF 将开始工作。


在完成 MobSF 的分析之后，你将获得一页的所有已执行测试的概述。 该页面分为多个部分，在应用程序的受攻击面上提供了一些初步提示。

会展示以下内容：

  • 应用程序及其二进制文件的基本信息。
  • 有一些选项:
    • 查看 Info.plist 文件。
    • 查看应用二进制文件中的字符串。
    • 如果应用使用 Objective-C 写的，可以下载 class-dump；如果是用      Swift 写的，就没有办法获取 class-dump。
  • 列出从 Info.plist 中提取的可能对获悉应用使用权限有用的提示性字符串。
  • 将列出不符合 App Transport Security（ATS）配置的情况。
  • 简单的二进制分析，显示是否启用了二进制安全功能，或者例如二进制文件是否使用了禁止的 API。
  • 列出应用程序二进制文件使用的库，以及解压后的 IPA 中所有文件的列表。

与 Android 不同，MobSF 不为 iOS 应用程序提供任何动态分析的功能。

更多信息请参考 https://github.com/MobSF/Mobile-Security-Framework-MobSF/wiki/1.-Documentation 。

Objection


Objection 提供重打包工具，你可以用这个工具很简单的将 Frida gadget 注入到应用中。这样，你就可以通过旁载重新打包的应用程序将其部署到非越狱设备，并按照上一节中的说明与应用程序进行交互。


同时，Objection 还提供了 REPL，它允许你与应用程序进行交互，从而能够执行应用程序可以执行的任何操作。可以在项目的主页上找到 Objection 功能的完整列表，这里列出了一些有趣的功能：

  • 重打包应用以加入 Frida gadget
  • 为常见方法禁用 SSL pinning
  • 访问应用程序存储来上传或下载文件
  • 执行自定义的 Frida 脚本
  • Dump the Keychain
  • 读 plist 文件
 
通过使用 Objection 的 REPL 中的命令，可以轻松完成所有这些任务以及其他任务。例如，可以通过运行以下命令获取应用程序中使用的类、类的方法或有关应用程序包的信息：
OWASP.iGoat-Swift on (iPhone: 12.0) [usb] # ios hooking list classes
OWASP.iGoat-Swift on (iPhone: 12.0) [usb] # ios hooking list class_methods <ClassName>
OWASP.iGoat-Swift on (iPhone: 12.0) [usb] # ios bundles list_bundles

在非越狱设备上执行高级动态分析的能力是使 Objection 变得异常有用的功能之一。因为不是总能够越狱最新版本 iOS 的，或者应用程序可能具有先进的越狱检测机制。此外，随附的 Frida 脚本使快速分析应用程序或解决基本安全控制变得非常容易。


最后，如果你正在使用越狱设备，则 Objection 可以直接连接到正在运行的 Frida 服务端，来使用 Frida 的所有功能，而无需重打包应用程序。


安装 Objection


可以按照  Objection's Wiki（https://github.com/sensepost/objection/wiki/Installation） 中所述通过 pip 安装 Objection。

$ pip3 install objection


如果你的设备已越狱，则现在可以与该设备上运行的任何应用程序进行交互，并且可以跳到下面的“使用 Objection”部分。


但是，如果要在非越狱设备上进行测试，则首先需要在应用程序中包含 Frida gadget。 Objection Wiki（https://github.com/sensepost/objection/wiki/Patching-iOS-Applications）详细描述了所需的步骤，在进行了正确的准备后，你将可以通过调用 Objection 命令来 patch IPA：

$ objection patchipa --source my-app.ipa --codesign-signature 0C2E8200Dxxxx


最后，该应用程序需要旁载并在启用调试通信的情况下运行。 可以在 Objection Wiki （https://github.com/sensepost/objection/wiki/Running-Patched-iOS-Applications）上找到详细的步骤，但是对于 macOS 用户，可以使用 ios-deploy 轻松完成此步骤：

$ ios-deploy --bundle Payload/my-app.app -W -d


使用 Objection


要成功运行 Objection 取决于你是否已 patch 了 IPA 或使用的是运行 Frida server 的越狱设备。对于运行 patch 了的 IPA，Objection 会自动找到所有连接的设备并搜索监听的 frida gadget。但是，在使用 frida-server 时，你需要明确告诉 frida-server 要分析哪个应用程序。

# Connecting to a patched IPA
$ objection explore

# Using frida-ps to get the correct application name
$ frida-ps -Ua | grep -i Telegram
983  Telegram

# Connecting to the Telegram app through Frida-server
$ objection --gadget="Telegram" explore


进入 Objection REPL 后，你可以执行任何可用的命令。以下是一些最有用的命令的概述：

# Show the different storage locations belonging to the app
$ env

# Disable popular ssl pinning methods
$ ios sslpinning disable

# Dump the Keychain
$ ios keychain dump

# Dump the Keychain, including access modifiers. The result will be written to the host in myfile.json
$ ios keychain dump --json <myfile.json>

# Show the content of a plist file
$ ios plist cat <myfile.plist>


有关使用 Objection REPL 的更多信息，请参见异议Wiki（https://github.com/sensepost/objection/wiki/Using-objection）。


Passionfruit


Passionfruit 是一个 iOS 应用程序黑盒评估工具，它使用 iOS 设备上的 Frida server，并通过基于 Vue.js 的 GUI 可视化标准应用程序数据。它可以使用 npm 安装。

借助 Passionfruit，可以浏览有关 iOS 应用程序的各种信息。选择 iOS 应用后，你可以执行许多任务，例如：

  • 获取二进制文件的信息
