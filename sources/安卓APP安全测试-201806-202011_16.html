本文主要翻译自 《OWASP Mobile Security Testing Guide》中的Local Authentication on Android 章节，介绍安卓本地身份认证的相关安全知识。


1. 简介 


安卓系统在本地身份认证期间，应用程序会通过对比设备本地存储的凭据对用户进行身份验证。 换句话说，用户通过验证本地存储的有效 PIN、密码或指纹来解锁 app 或某些内部功能。 本地身份验证经常被用来恢复与远程服务的现有会话或作为保护某些关键功能而增加的认证手段。  


2. 测试生物认证


  • 概述

Android Marshmallow（6.0）引入了指纹认证的 API。通过 FingerprintManager 类提供对指纹硬件的访问。 应用程序可以通过实例化 FingerprintManager 类并调用其 authenticate() 方法来请求指纹身份验证。 调用者注册回调方法以处理认证过程的可能结果（即成功、失败或错误）。值得注意的是，此方法并不能强有力地证明实际进行了指纹验证，比如说， 攻击者可以 patch 身份验证步骤，或者可以通过进程注入的方式来调用“成功”的回调方法。 


通过将指纹 API 与 Android KeyGenerator 类结合使用，可以实现更好的安全性。 使用此方法时，对称密钥存储在密钥库中，并使用用户的指纹“解锁”。 例如，要启用用户对远程服务的访问，会创建一个 AES 密钥，用于加密用户 PIN 或身份验证令牌。 通过在创建密钥时调用 setUserAuthenticationRequired(true)，可确保用户必须重新进行身份验证才能使用。 然后可以将加密的认证凭证直接保存到设备上的本地存储（例如，SharedPreferences）。 此设计是一种相对安全的方法，可确保用户实际输入授权指纹。 但请注意，此设计要求应用程序在加密操作期间将对称密钥保存在内存中，可能会将其暴露给能在运行时访问应用程序内存的攻击者。 


更安全的选择是使用非对称加密。 此处，移动应用程序在密钥库中创建非对称密钥对，并将公钥传到后端服务器。 然后，使用私钥对稍后的数据交互进行签名，并由服务器使用公钥进行验证。 这样做的好处是可以使用 Keystore API 对数据交互进行签名，而无需从 Keystore 中提取私钥。 因此，攻击者无法从内存转储或注入来获取密钥。


  • 静态检查


首先搜索 FingerprintManager.authenticate() 调用。 传递给此方法的第一个参数应该是CryptoObject 实例，这个实例是 FingerprintManager 支持的加密对象的包装类。 如果参数设置为 null，则表示指纹授权纯粹受事件限制，可能会产生安全问题。


可以通过查找初始化密码包装的密钥的创建来回溯到 CryptoObject。需要验证两点：一是在创建 KeyGenParameterSpec 对象期间调用 setUserAuthenticationRequired（true），二是使用 KeyGenerator 类创建密钥（请参阅下面的代码示例）。


一定要去验证身份校验逻辑是否正确。一个好的身份验证，远程服务端必须要求客户端提供从密钥库中检索到的密钥、从密钥派生的值或使用客户端私钥签名的值（请参见上文）。


安全地实施指纹认证需要遵循一些简单的原则，首先检查该类型的认证是否可用。最基本的，设备必须运行在 Android 6.0 或更高版本（API 23+）。还必须验证其他四个先决条件：

  • 指纹硬件可用

FingerprintManager fingerprintManager = (FingerprintManager)
                    context.getSystemService(Context.FINGERPRINT_SERVICE);
fingerprintManager.isHardwareDetected();

  • 用户要设置了锁屏保护

 KeyguardManager keyguardManager = (KeyguardManager) context.getSystemService(Context.KEYGUARD_SERVICE);
 keyguardManager.isKeyguardSecure();

  • 至少要录入了一个指纹

fingerprintManager.hasEnrolledFingerprints();

  • 应用需要有权限去请求用户指纹

context.checkSelfPermission(Manifest.permission.USE_FINGERPRINT) == PermissionResult.PERMISSION_GRANTED;

如果以上的任何一个失败了，就不应该提供指纹认证了。

重要的是要记住并非每个 Android 设备都提供硬件支持的密钥存储。 要确认密钥是否位于安全硬件（如可信执行环境（TEE）或安全元件（SE））内，可以通过 KeyInfo 类来验证。

SecretKeyFactory factory = SecretKeyFactory.getInstance(getEncryptionKey().getAlgorithm(), ANDROID_KEYSTORE);
KeyInfo secetkeyInfo = (KeyInfo) factory.getKeySpec(yourencryptionkeyhere, KeyInfo.class);
secetkeyInfo.isInsideSecureHardware();

在特定的系统上，也可以强制必须通过硬件来进行生物识别认证。可以通用以下方法检查：

keyInfo.isUserAuthenticationRequirementEnforcedBySecureHardware()

  • 使用对称密钥时进行指纹身份验证


当使用 KeyGenerator 类创建新的 AES 密钥时，可以通过在 KeyGenParameterSpec.Builder 中添加 setUserAuthenticationRequired(true)，来要求进行指纹认证。


generator = KeyGenerator.getInstance(KeyProperties.KEY_ALGORITHM_AES, KEYSTORE);      
generator.init(new KeyGenParameterSpec.Builder (KEY_ALIAS,

    .setBlockModes(KeyProperties.BLOCK_MODE_CBC)           
    .setEncryptionPaddings(KeyProperties.ENCRYPTION_PADDING_PKCS7)           
    .setUserAuthenticationRequired(true)           
    .build()     
); ‍     
generator.generateKey();

要使用受保护的密钥执行加密或解密，请创建一个 Cipher 对象并使用密钥别名对其进行初始化。

SecretKey keyspec = (SecretKey)keyStore.getKey(KEY_ALIAS, null);      
if (mode == Cipher.ENCRYPT_MODE) {
         cipher.init(mode, keyspec);

请记住，新密钥必须首先通过 FingerprintManager 进行身份验证后才能使用。 具体做法是将 Cipher 对象包装到 FingerprintManager.CryptoObject 中，该对象在被识别之前传递给FingerprintManager.authenticate()。

cryptoObject = new FingerprintManager.CryptoObject(cipher);
fingerprintManager.authenticate(cryptoObject, new CancellationSignal(), 0, this, null);

认证成功时会调用回调方法 onAuthenticationSucceeded(FingerprintManager.AuthenticationResult result) ，此时可以从返回结果中获取认证的  CryptoObject 对象。

public void authenticationSucceeded(FingerprintManager.AuthenticationResult result) {
    cipher = result.getCryptoObject().getCipher();

    (... do something with the authenticated cipher object ...)
}

  • 使用非对称密钥时进行指纹身份验证


首先使用 KeyPairGenerator 类来生产一个签名密钥，将公钥上传到服务器。然后就可以在客户端对传输的数据进行签名，在服务端来验证签名。https://android-developers.googleblog.com/2015/10/new-in-android-samples-authenticating.html 中有使用指纹 API 对远程服务器进行身份验证的详细示例。


生成密钥对：

KeyPairGenerator.getInstance(KeyProperties.KEY_ALGORITHM_EC, "AndroidKeyStore");
keyPairGenerator.initialize(new KeyGenParameterSpec.Builder(MY_KEY,
                KeyProperties.PURPOSE_SIGN)
                .setDigests(KeyProperties.DIGEST_SHA256)
                .setAlgorithmParameterSpec(new ECGenParameterSpec("secp256r1"))
                .setUserAuthenticationRequired(true)
                .build());
keyPairGenerator.generateKeyPair();

要使用密钥进行签名，你需要实例化一个 CryptoObject 对象，并使用 FingerprintManager 对其进行验证。

Signature.getInstance("SHA256withECDSA");
KeyStore keyStore = KeyStore.getInstance("AndroidKeyStore");
keyStore.load(null);
PrivateKey key = (PrivateKey) keyStore.getKey(MY_KEY, null);
signature.initSign(key);
CryptoObject cryptObject = new FingerprintManager.CryptoObject(signature);

CancellationSignal cancellationSignal = new CancellationSignal();
FingerprintManager fingerprintManager =
        context.getSystemService(FingerprintManager.class);
fingerprintManager.authenticate(cryptoObject, cancellationSignal, 0, this, null);

可以通过如下代码对字节数组 inputBytes 进行签名。

Signature signature = cryptoObject.getSignature();
signature.update(inputBytes);
byte[] signed = signature.sign();

  • 注意在签名数据中需要加入随机数 nonce，否则攻击者可以进行重放攻击。

  • 使用 challenge-response 协议。

  • 其他安全特性


Android Nougat（API 24）在 KeyGenParameterSpec.Builder 中增加了 setInvalidatedByBiometricEnrollment（boolean invalidateKey）方法。 当 invalidateKey 值设置为 “true”（默认值）时，对于指纹身份验证有效的密钥在注册新指纹时会被设置为无效。 这可以防止攻击者获取密钥，即使他们能够注册其他指纹也不行。


  • 动态分析


可以通过 patch 应用或者动态注入的方式来绕过指纹认证。 例如，你可以使用 Frida 直接调用onAuthenticationSucceeded 回调方法。 （如果能够成功绕过验证，则说明验证机制不够健壮。）
