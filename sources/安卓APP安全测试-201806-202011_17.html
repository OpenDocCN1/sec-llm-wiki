前言


WebView 是 Android 系统定义的一个的控件，其继承自 AbsoluteLayout，相当于一个微型的浏览器，可以用来显示网页、执行 JavaScript 等。


本文将介绍 WebView 的基础知识，和使用不当会造成的安全隐患，以及如何发现及缓解这些安全隐患。


注：本文中使用到的 web 应用为 github 中的 clone-1.0.jar（springboot应用）。


1. WebView 的基本用法


1.1 简单使用


下面是一个最简单的用法，创建 WebView 并加载网页。


WebView webview = new WebView(this);
setContentView(webview);
webview.loadUrl("https://www.baidu.com");

当然，你也可以自己写一个类继承自 WebView。

WebView 有以下方法可以用来加载网页：

loadUrl(String url)
loadUrl(String url, Map<String, String> additionalHttpHeaders)
loadData(String data, String mimeType, String encoding)
loadDataWithBaseURL(String baseUrl, String data, String mimeType, String encoding, String historyUrl)

loadData 示例如下：

String html = "<h1> 安卓 APP 安全测试</h3>";
webview.loadData(html, "text/html", "UTF-8");


1.2 常用设置 


WebView 默认是无法加载 JS 脚本的，可以通过以下设置来开启此功能。

WebView webview = new WebView(this);
WebSettings webSettings = webView.getSettings();
webSettings.setJavaScriptEnabled(true);

还有一些常用的配置如下：

// 是否允许 WebView 通过 file 协议加载网页，默认值为 true。
// 示例： webview.loadUrl("file:///sdcard/1.html")
webSettings.setAllowFileAccess(true);

// 设置是否允许运行在 file 协议上下文中的 Javascript 读取其他的
// 通过 file 协议访问文件的内容。
// 这个设置在 JELLY_BEAN（API LEVEL 16）以前的版本默认为 true，
// 在 JELLY_BEAN 及以后的版本中默认为 false。
webSettings.setAllowFileAccessFromFileURLs(true);

// 设置是否允许运行在 file 协议上下文中的 Javascript 访问其他的源，
// 包括其他的文件和 http，https 等其他的源。
// 这个设置在 JELLY_BEAN（API LEVEL 16）以前的版本默认为 true，
// 在 JELLY_BEAN 及以后的版本中默认为 false。
// 如果此设置为 true，则setAllowFileAccessFromFileURLs(false)不起做用。
webSettings.setAllowUniversalAccessFromFileURLs(true);

// WebViewClient 主要辅助 WebView 执行处理各种响应请求事件，
// 如果不设置，网页会跳转到默认浏览器打开。
webView.setWebViewClient(new WebViewClient());
 
 // WebChromeClient 主要辅助 WebView 处理 JS 的对话框等
 // 如果不设置，将无法弹出对话框等。
webView.setWebChromeClient(new WebChromeClient());

2.3 安全建议


  • 若不需要运行 JS 脚本，设置 webSettings.setJavaScriptEnabled(true);

  • 对传入 web 的数据进行过滤或编码，防止 xss；

  • 对暴露给 web 的 java 对象方法进行严格检查；

  • 对 WebViewClient 的 shouldOverrideUrlLoading() 方法进行检查；

  • 对 WebChromeClient 的 onJsAlert()、onJsConfirm()、onJsPrompt() 进行检查


3. 应用克隆问题


应用克隆漏洞主要是指通过跨域读取应用的本地沙盒数据（/data/data/packagename下的文件），从而实现在其他手机上重现应用的状态的问题。


其若要攻击成功，需具备以下几个条件：

  • 开启了 file 域的跨域访问

    即设置了以下属性

webSettings.setAllowFileAccess(true);
以下两个设置了至少一个
webSettings.setAllowFileAccessFromFileURLs(true);
webSettings.setAllowUniversalAccessFromFileURLs(true);

  • 攻击者可以让应用加载指定的网页文件

  • 应用本身的鉴权机制允许不同环境下登录。比如有的应用会检测登录环境的设备信息、网络环境等，如果有变化就需要重新登录。这种场景下应用克隆就难以实现，只能够窃取用户的本地沙盒数据。
