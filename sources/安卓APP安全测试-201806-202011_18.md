## 

1\. 漏洞简介

  

ZipperDown 漏洞主要是指应用在解压压缩包的时候，如果处理不当会导致路径穿越，进一步可能会覆盖应用本地文件的一类漏洞。其具有通用性，在安卓、IOS、Web等多种应用中都可能存在。本文以安卓为例进行说明。

  

## 

2\. 漏洞代码示例

## 

  

*   **关键 API**
    

```
// java.util.zip.ZipInputStream#getNextEntry()

 **getNextEntry()**

java.util.zip.ZipEntry#getName() 

**getName()** { return name; }
```

*   **    漏洞位置**
    

在 vuls 应用中有以下的功能，其会下载某个 zip 文件，解压后保存到应用的 cache 目录。

  

![](../Images/be549453ffcba0e23c201134985ee4b4.png)

*   ## **关键代码**
    

  

```
String url = "http://www.example.com/test.zip

"; @Override 

@Override

**String entryName = zipEntry.getName(); **

**String fileName = dstPath + File.separator + entryName;**

 
```

  

在上面红色加粗的代码中，直接将获取的压缩文件中的文件名进行拼接。正常情况下，zip 文件中文件名为 a.txt，其会被下载到 /data/data/ddns.android.vuls/cache/a.txt。如果攻击者构造一个 ../files/token.txt 的文件名，则拼接后的文件名为 /data/data/ddns.android.vuls/cache/../files/token.txt，其会覆盖本地的 token.txt 文件。

  

## 

3\. 检测方法

  

*   **构造测试文件**
    

  

这里我打算去覆盖掉 /data/data/ddns.android.vuls/files/token.txt，于是需要构造一个包含 ../files/token.txt 文件的 zip 包。步骤如下：

  

1.  先创建好 token.txt，内容为 “this is a fake token by zipperdown!”。
    
2.  将 token.txt 压缩为 token.zip。
    
3.  使用 7-Zip 打开文件，并修改文件名。
    

![](../Images/9000dd177908d9f70375b9b2fbbc9852.png)

  

*   **中间人攻击**
    
      
    

原请求为  http://www.example.com/test.zip，于是将上一步构造的 token.zip 重命名为 test.zip，并在当前目录下执行命令 python -m SimpleHTTPServer。这样就在 8000 端口开了一个 http 服务。

  

设置手机的代理为 burp，并做如下配置：

![](../Images/dde68e0ba5efb877701041ac929de145.png)

  

这样，当请求 http://www.example.com/test.zip 的时候，会自动跳转到请求 http://127.0.0.1:8000/test.zip。

## 

4\. 漏洞修复

  

1、使用 https 并且对证书进行正确校验，防止中间人攻击。

2、获取文件名的时候判断是否包含 “../”。
