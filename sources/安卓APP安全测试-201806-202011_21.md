## 前言

  

WebView 是 Android 系统定义的一个的控件，其继承自 AbsoluteLayout，相当于一个微型的浏览器，可以用来显示网页、执行 JavaScript 等。  

  

本文将介绍 WebView 的基础知识，和使用不当会造成的安全隐患，以及如何发现及缓解这些安全隐患。

  

注：本文中使用到的 web 应用为 github 中的 clone-1.0.jar（springboot应用）。

2\. 原生应用与 H5 交互的安全问题

  

原生应用是指开发的安卓应用，H5 是指通过 WebView 加载的 web 应用。很多情况下原生应用与 web 之间需要进行交互，在交互的过程中，如果处理不当会造成各种安全问题，比如信息泄露，XSS、越权等。

## **2.3 安全建议**

  

*   若不需要运行 JS 脚本，设置 webSettings.setJavaScriptEnabled(false;
    
*   对传入 web 的数据进行过滤或编码，防止 xss；
    
*   对暴露给 web 的 java 对象方法进行严格检查；
    
*   对 WebViewClient 的 shouldOverrideUrlLoading() 方法进行检查；
    
*   对 WebChromeClient 的 onJsAlert()、onJsConfirm()、onJsPrompt() 进行检查

3\. 应用克隆问题

  

应用克隆漏洞主要是指通过跨域读取应用的本地沙盒数据（/data/data/packagename下的文件），从而实现在其他手机上重现应用的状态的问题。

  

其若要攻击成功，需具备以下几个条件：

*   开启了 file 域的跨域访问
    
    即设置了以下属性
    

```
webSettings.setAllowFileAccess(true
);
true);
true);
```

*   攻击者可以让应用加载指定的网页文件
    
*   应用本身的鉴权机制允许不同环境下登录。比如有的应用会检测登录环境的设备信息、网络环境等，如果有变化就需要重新登录。这种场景下应用克隆就难以实现，只能够窃取用户的本地沙盒数据。

4\. 通信安全问题

  

很多时候，开发人员为了测试方便，经常会采用重写 WebViewClient 的 onReceivedSslError 方法来忽略 SSL/TLS 的错误。典型代码如下：

  

![](../Images/a454c93beb112f35634bd726a8af624b.png)

  

此时，访问网络会忽略证书错误，从而面临中间人攻击的威胁。

  

**安全建议**

  

*   不要忽略SSL/TLS 的错误。
    
*   在安全要求高的场景下进行 SSL pinning 或者双向校验。
