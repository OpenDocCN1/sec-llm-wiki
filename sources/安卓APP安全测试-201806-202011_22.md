## 前言

  

Content Provider 是 Android 定义的四大组件之一，其核心功能是提供应用间的统一的数据访问方式，当然也可以用于应用内的数据封装。  

  

本文将介绍 Content Provider 的基础知识，和使用不当会造成的安全隐患，以及如何发现及缓解这些安全隐患。

*   **URI**
    

URI 是英文 Uniform Resource Identifier 的缩写，即统一资源识别符，简单的说它的作用就是用来识别或者标识资源名称用的一串字符串。

  

其基本形式如下（中括号中可以省略）：

\[scheme:\]\[//authority\]\[/path\]\[?query\]\[#fragment\] 

  

在 android 中，除了scheme、authority是必须要有的，其它的几个path、query、fragment，它们每一个可以选择性的要或不要，但顺序不能变。

  

以下是一个典型的 Content Provider URI：

content://ddns.vuls.AccountProvider/account/1?name=jack

scheme： 固定为 content

authority： 为 ddns.vuls.AccountProvider ，指定了特定 provider

path： 为 /account/1 ，account 指定了表名，1 指定了哪条记录

query：为 name=jack，即请求参数

*   Uri：
    

public static Uri parse(String uriString) 将 uri 字符串解析成 Uri 对象

public abstract String getPath() 获取 path 信息

public String getQueryParameter(String key) 获取请求参数

  

*   ContentUris : 解析uri的工具类
    

long parseId(Uri contentUri) 解析uri, 得到其中的id

Uri withAppendedId(Uri contentUri, long id)  添加id到指定的uri中

  

*   UriMatcher : 用于匹配Uri的容器
    

void addURI(Stringauthority, String path, intcode) 添加一个合法的URI

int match(Uri uri) 匹配指定的uri, 返回匹配码

2\. 常见安全问题

  

Content Provider 用于应用间数据和文件访问，使用不当会造成敏感信息泄露、SQL注入、任意文件读写等安全问题。这里会举几个典型的案例。

1、反编译 apk 文件，在 AndroidManifest.xml 中查找显示设置了 android:exported="true" Content Provider。

  

2、使用 drozer 工具。

3\. 安全建议

###   

*   判断 Content Provider 是否真的有必要导出，如果无必要，则设置为非导出。
    
*   如果 Content Provider 必须导出，则可以通过添加权限的方式，缩小暴露范围。
    

比如我们在 vuls app 中定义了一个权限，

![](../Images/f985b880f5b2074c8870b16904795fe2.png)

在调用 Content Provider 的时候，要求拥有此权限。

![](../Images/f2e4def77da4ae03197d8a118b0a7804.png)

  

android:protectionLevel 这个属性的值用来表示该权限所对应的风险等级。分类如下：  

*   "dangerous": 这一等级通常会被分配给那些需要访问用户的敏感数据或系统配置数据的 app。用来限制任何可能对用户造成危险的功能或数据的访问。当安装应用的时候，会提示用户授权。
    
*   "normal":这一等级用来表示，需要访问不会引发安全风险的数据或服务的权限。当安全应用的时候，不会提示用户授权。
    
*   "signature":这一等级表示如果之前已经又一个用与该 app 一样的证书签名的 app 获得这一权限。
    
*   "signatureOrSystem":这一等级表示相同的证书签名或者系统应用获得这一权限。
    
    **对于敏感数据一般要求 signature 或 signatureOrSystem 等级。**
    

  

*   对有敏感数据的 path 进行权限控制。
    

![](../Images/8cb1ca8f2878a7bf3812ceabd8e4271a.png)

要**特别注意**对于一个path 要同时限制有 “/” 的和没有 “/” 的，即上面例子中，还要限制 “/account/” 路径的权限。

  

*   对于任意文件读取，要对文件名称合法性做校验，即将参数进行 url 解码后判断是否包含 “../” 等特殊字符。
