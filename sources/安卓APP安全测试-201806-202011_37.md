**四、反编译apk文件**

 

目前有很多款的反编译工具，比如老牌的smali、Apktool等。作为新手，我推荐大家使用开源工具jadx，地址https://github.com/skylot/jadx。你可以去官方的git下载，也可以使用我编译好的（https://github.com/AndroidAppSec/resources）。 

使用jadx打开Sieve.apk，如下图：

  

![](../Images/14f3bd7c495fed37086d26f1f5ac6abe.png)

目录结构跟之前的压缩包文件中的结构是不是很像。其中 Source code 就是由 classes.dex 中反编译回来的源代码，Resources 里面是资源文件。jadx支持全文搜索和交叉引用，在阅读代码时候很方便，可以自行体验一下。

  

**五、重要文件及目录介绍**

 

**1、AndroidManifest.xml**

 

先看一下反编译之后的文件内容。

  

![](../Images/c84d10ed073cd73765cd50575024bbbc.png)

manifest 标签：文件的根标签，package 属性定义了包名。

uses-permission  标签：声明了安卓应用运行时需要的权限，这里有android.permission.READ\_EXTERNAL\_STORAGE（读外部存储）、android.permission.WRITE\_EXTERNAL\_STORAGE（写外部存储）、android.permission.INTERNET（互联网权限）。注意要点，安卓应用不应该申请超出自己功能需要的权限，尤其是电话、短信等涉及到用户敏感信息的权限，以免遭受质疑。

permission 标签：定义了应用自身的一些权限，这些权限可以用来限制访问某些应用的组件，比如 sieve 定义了权限如下：

![](../Images/75b01c7a3dc2d1c9d15f9fd291c06669.png)

在 DBContentProvider 中就要求有这个权限才能访问：

![](../Images/78c7832102510d16b86e756f3d99f3fd.png)

潜在风险： 权限滥用。其 android:protectionLevel 属性有四个等级：normal、dangerous、signature、signatureOrSystem。不同等级申请权限的要求不一样，如设置不合理会造成权限滥用。（后续会详细介绍）

application 标签： 整个应用的声明，其会定义应用的整体属性，在其子标签中会定义 android 的组件（activity、service、receiver、provider 等）。

潜在风险：

debuggable 属性：默认值为false，如果为true就允许应用被动态调试。

allowBackup 属性：默认值为true，如果为true就允许使用adb来备份和还原应用数据。

四大组件：拒绝服务、权限绕过、组件暴露、权限提升、数据泄露、sql 注入等等。（后续会详细说明）

  

**2、res 目录**

此目录下是应用的一些资源文件，包括页面布局文件、应用图标、菜单等等。可以重点关注一下布局文件，方便理解安卓应用的使用界面，如下图：

![](../Images/46f4e995b81fd09e2812aa91f21ae855.png)

  

**3、resources.arsc**

同样是应用的资源文件，其中包含了app使用到的一些字符串资源，在逆向分析时候经常会用到。

![](../Images/ff7504c72d0ee9fa53a72d6092e48593.png)

  

**4、lib 目录**

里面包含了 app 使用到的原生库文件，扩展名为so。越来越多的应用将核心逻辑放入 so 文件中，来提高运行效率增加破解难度。

  

![](../Images/7c538e3d28bbc72c1a44357f806a549a.png)
