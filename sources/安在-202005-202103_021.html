话题一

对于企业“零信任”落地，有什么实践和思考？


观点1：我觉得零信任现在被炒的有点过热了，基本达到了炒作巅峰，我已经有些逆反了，估计是时候坠入绝望之谷了。毕竟在很多领域零信任的成本都有些太高了，一定要多想想再迈入，不可人云亦云。脚踏实地，认真做事才是王道。


观点2：零信任的问题是这个架构和定义包容性很大，就像一个方向，而不是单一技术。从身份、sdp、微分段等的实施，其实就算没有这个概念都是会做的，就像云上微服务、dfw细颗粒度管理、illumio等微分段技术都可以加个“零信任和XX”的来做输出，身份认证上的联合认证、身份和授权系统分离、fid管理（如Cyberark等）这类都一样。所以，不放零信任，或许都好写，一放零信任，感觉逼格都不够，因为单一技术敢叫零信任的只有销售。


观点3：国内的安全文化本身就是构建在不信任的基础上的，只是以往陷于技术主导能力，管理和治理能力的限制而不能很好落实，变成一刀切，反而欧美在方向上是有转变的。其实像准入+sso+iam+代理+微服务token等构建的纵深防御基本架构，也可以说借鉴零信任思路，如service mash这类的，还有API网关和安全平台的，都可以算吧。我觉得只要题目是“零信任和”、“零信任思路下的…”，都没有问题。


观点4：提几个疑问，可以对照下：1. sso接管所有应用了吗？ldap还在用有细颗粒度要求了吗，如应用自身的session控制？Cyberark的aim接入完成了吗，对于老系统无法改造的有做前置系统转接吗，dual control还是可以的吗？API都open了，那API治理和数据标准化做了吗，建了统一API安全平台了吗，带缓存，mfa，session控制和安全检测的那种？B2Bservice下，payload加密落实了吗？等等。


观点5：如Biz->CDN secure->external API gw->internal API gw->Security gw这层，内部网关也可以是反向代理，应用的微服务接入安全网关完成认证，应用通过网关调微服务，网关验证，如jwt等。这个模式是目前可落地的应用层零信任的方案，也比较成熟。抛开传统遗留系统，新生应用采用该模式，安全收益比较高。


观点6：因为市场上所有零信任产品都是假的，零信任讲究的是无招胜有招，是软件开发人员自己搞安全，每个环节都丝丝入扣，让黑客无懈可击。根本不需要任何安全产品的防护了，真的练到那个境界，安全公司全都得倒闭。


观点7：我不认同上述观点，你理解的是绝对化的零信任，安全公司能做是将大量需要开发人员做的事情集中到自己的产品里，让系统、架构尽可能的少动。不然所有事情都开发人员自己做，那还要WAF这些安全产品干啥？对现在的零信任，开发人员其实更关注无界远程办公，安全由安全专业人员搞定。


观点8：零信任落地要协调的资源多，现阶段的投入产出比也看不出来，难以得到高层重视，感觉不熟悉的人做着做着就会做回VPN的老路了…



厂商建议



1: 零信任是有成熟度的，安全和业务需要平衡，企业的零信任之旅是需要分阶段进行的。2: 零信任是一个理念和方法论，是用来解决安全问题的，目前做零信任的厂家不少，但其实背后解决的安全问题是不一样的，企业需要先回答自己需要解决什么样的安全问题。3：甲方有甲方的擅长，乙方有乙方的擅长，在选择零信任相关产品时候一定要关注开放性，能否把甲方的能力利用起来，如何让甲方在之上搭建更大的防御体系，让能力回到甲方手里。4: 大部分零信任相关产品是逻辑串联在网络中的，企业在选择零信任的时候需要关注稳定性和性能。
——虎符网络
“零信任没有银弹。”零信任之旅不是一夜之间的旅程，这是一个多年的旅程，得花点时间才能到那里。除了购买零信任安全产品，还需要组织内部自上而下的努力才能实现这个战略目标。
——启明星辰
零信任概念的兴起对于安全厂商是新的浪潮，零信任落地时要根据业务系统建设阶段、人员和设备管理情况、现有网络环境、企业网络安全威胁、现有安全机制、预算情况、安全团队人员能力等因素综合考虑。需要有专门的安全团队和人员牵头和推进实施（懂技术），制定零信任的安全目标，终极目标和阶段性目标（懂规划），梳理现有网络环境，明确范围，制定实施方案（懂流程）。推动零信任落地需要新的技术和大环境支撑。
——木链科技


话题二

DLP怎样做才能性价比高又实用？


观点1：虚拟安全办公桌面阔以了解一下。不同行业、企业可能差别挺大的。主流的大概就天空卫士、IPGuard、McAfee、联软，华为有自研的桌面管理。如果是针对办公场景的数据防泄漏，确实还有其他解决方案可以考虑。DLP、云桌面、安全桌面都有。看你的问题背后，到底想解决什么问题。


观点2：我最近也在选型这个产品。复杂，不能100%，但有比没有好，尽力争取控制到可接受风险范围内。前期测试过奇安信的，联软的，IPG的，都有些问题，最近准备测试虚拟安全桌面，听上去像比较全面的解决方案。主要是看需求，要做到什么程度，有哪些渠道，范围，都会左右产品选型。全知的理念非常好，但也有适用场景，产品实现还不错，还在逐步完善中。如果你主要是对文档的管控，就不要看全知了，亿赛通搞文档管控。


观点3：DLP两种比较有代表解决方案，一种倾向于加密，如ipguard，文档落地全加密；一种倾向于通道管控，forcepoint/赛门铁克，两种方案都有弊端，加密的，利用wps云文档可绕过/mac支持性一般；通道管控，社交软件类，难管控，更新不及时。云桌面，桌面虚拟化也是一种方案，类似通道管控。虚拟桌面成本高，期望值不要太高。


观点4：通道管控+PC标装+桌管控制，对于一般非金融公司来说，解决方案偏重。为DLP去做虚拟桌面有点不合需求，虽然也可以一定程度实现。我倒比较偏向虚拟安全桌面，环境内全管控，脱离环境无效，不过还需要测试以后才能确定效果。需要考虑应用场景是文本文档，还是包含音视频图文，结合现有办公场景来。


观点5：目前了解到的是安全桌面内号称的功能比较强大，但实际效果如何还得看真实测试结果。我们CISO说DLP太复杂，没有用，单独上桌面虚拟化那确实算不上一种好的方案。DLP还涉及一个层面，就是数据分类分级，如果没有明确这块，也会给选择产品造成困扰。



厂商建议


首先要将敏感信息定义准确，充分理解监管要求、业务特性的前提下准确定义敏感信息，必要时可借助外部资源辅助完成。建议在DLP中使用可以采用分层制定安全策略，划分数据等级、明确人员权限，建立人员与数据使用的交叉权限关系，并以审计为主配合规章制度来逐渐养成员工对于数据安全的意识，定期开展摸底资产驻留排查及告知，让数据使用者明确数据价值。
——启明星辰

话题三

企业在做DLP时，应该如何平衡用户个人隐私？


观点1：先在意识层面做好宣传吧，比如明确告诉员工公司电脑只能用于办公使用，严禁用于处理个人事务，因为公司会对办公电脑做必要的审计；在公司的一些地方进行公示，明确表示公司电脑上存储的信息属公司所有，绝不可擅自存储携带；再不行就直接禁止使用个人电脑。


观点2：怎么说呢，开发和安全是对立的，很难协调，比如我们经常会听到有人说“公司这么做（监控）是侵犯隐私”。我倒是想问问了，你用的都已经是公司资产的办公电脑了，是因为工作需要提供给你使用的，那你拿着公司资产就应该做工作的事吧？你凭什么要做与工作无关的所谓“隐私”的事呢？既然你自己愿意把私人事务放到上面来处理，那就别说什么隐私了，而且如果因此泄了密，公司还得追究你的责任。


观点3：不过话说回来，现在公司电脑上其实都允许装微信，那么微信上的信息有公司的也有私人的。假设有些信息比如生活照，通过公司电脑的微信泄露了，那该怎么办呢？


观点4：对不起，企业微信才是企业官方认可的通讯工具，微信即使不禁止也只是员工自愿安装使用的，出了问题自己负责，如果泄露公司机密还要被追责。


观点5：我认为终端录屏、即时消息监控肯定是不允许的，因为这些严重侵犯了员工隐私，我相信除了安全部门，其他人是不会同意。所以我建议，如果一定要严格管理和平衡的话，就安装一个虚拟桌面吧，不管做什么都有记录，也不用通知录屏了。



厂商建议


应尽量避免单项敏感数据审查技术单独使用，DLP应采用关键字对、多关键字、正则表达式、数据指纹等进行敏感信息检测技术进行组合检测并设定合理阈值，提升敏感信息检测的准确度来避免误报个人隐私信息，并精细化管控通道范围设定，必要时可禁止个人性质较强的通讯工具及通道的使用。
——启明星辰
用户个人隐私应当属于企业隐私数据安全的一部分，对需展示的个人信息采取去标识化处理等措施，降低个人信息在展示环节的泄露风险，防止内部非授权人员及个人信息主体之外的其他人员未经授权获取个人信息。
——木链科技



话题四
对于业务网和办公网两张网的态势感知部署有什么好的建议？是各自一套，还是共用一套？


观点1：我觉得一套是可以的，因为分开各做成两套的话，如果上面的管理平台被黑，有可能影响到下面的两张网。同时两个平台流量不一样，如果分开两套的话，还得分别进行流量分析，还需要解决两套平台的统一管理问题。


观点2：我不这么认为。因为两边环境完全不一样，没办法用一套规则来管理，误报率肯定极高，所以我建议分开。针对统一管理的问题，我们可以把两套平台当做数据采集和初步处理的引擎，上面再用一个统一的分析和处置平台。


观点3：我也认为两套好。至于流量分析，逻辑都是数据采集-分析，如果没有响应，直接走单向数据就好了。探针和分析各放一边，做了简单分析处理后，把告警和关联的原始数据往统一的平台发，统一做分析就是了。比如办公的检测规则和生产的检测规则就是两套，但是关联分析和处置可以统一到一起。



厂商建议


我们建议部署一套全面覆盖办公网和业务网。主要是从两个方面考虑：一是态势感知平台定位为客户的安全大脑，是一个检测、预警、响应处置的大数据安全分析平台。其以网络侧全流量分析和主机侧监测与响应处置为核心，结合威胁情报、行为分析建模、UEBA、图关联分析、机器学习、大数据关联分析、可视化等技术，对全网网络空间实现全网业务可视化、威胁可视化、攻击与可疑流量可视化等，帮助客户在高级威胁入侵之后，损失发生之前及时发现威胁；二是企业网络空间是一个整体，办公网和业务网之间不是孤立的，从实践中看比如勒索病毒的传播、业务系统被入侵攻击等威胁经常以办公网终端电脑为跳板，因此，只有办公网和业务网的安全要素数据统一接入一套态势平台进行全面分析，才能更好的避免“追踪不下去，找不到源头”难题。
——安全狗
不同网络环境数据的采集，可在边缘端通过探针获取数据，再统一发送到中央处理服务器做大数据的分析和响应；获取可利用数据的成本大大降低，采集到的海量异构的数据在数据分析过程中造成误报、漏报的概率大大降低。
——木链科技
