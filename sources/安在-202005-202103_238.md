# 译文｜11种主要的云安全威胁

越来越多的数据和应用正在向云转移，这带来了独特的信息安全挑战。

  

云计算继续改变组织使用、存储和共享数据、应用程序和工作负载的方式。同时也带来了一系列新的安全威胁和挑战。由于有如此多的数据进入云——特别是进入公共云服务——这些资源成为了恶意行为者的天然目标。

  

![](../Images/56fee8f722c5ecc9c9ee9a42ea9a3bc4.png)

  

Gartner公司副总裁兼云安全主管Jay Heiser说:“公共云的使用量正在迅速增长，这不可避免地导致了潜在危险的大量敏感内容的出现。”

  

与许多人的想法相反，保护云中企业数据的主要责任不是服务提供商，而是云客户。Heiser说:“我们正处于云安全的过渡时期，关注点正从供应商转向客户。”“企业逐渐认识到，花大量时间试图弄清楚某个特定云服务提供商是否‘安全’，实际上是没有回报的。”

  

为了使组织对云安全问题有最新的了解，以便他们可以就云采用策略做出有根据的决策，云安全联盟(CSA)发布了最新版本的《云计算的十一种头号威胁》报告。该报告于9月发布，列出了2019年发生的主要云威胁。

  

该报告反映了CSA社区的安全专家对云计算中最重要的安全问题的共识。尽管在云计算中存在许多安全问题，CSA说，这个列表主要关注11个与云计算的共享、按需特性相关的问题。

  

为了确定最重要的问题，CSA对行业专家进行了一次调查，以汇编关于云计算中最大安全问题的专业意见。以下是最重要的云安全问题(根据调查结果的严重性排序):

  

**1\. ****数据泄露**

数据泄露的威胁仍是去年调查中排名第一的问题。原因很简单，违规行为可能造成巨大的声誉和财务损失，它们可能会导致知识产权(IP)的损失和重大法律责任。

  

**CSA关于数据泄露威胁的主要结论包括:**

*   攻击者需要数据，因此企业需要定义其数据的价值及其损失的影响。
    
*   谁有权访问数据是保护数据的关键问题。
    
*   可通过internet访问的数据最容易被错误配置或利用。
    
*   加密可以保护数据，但需要在性能和用户体验方面进行权衡。
    
*   企业需要将云服务提供商考虑在内的健壮的、经过测试的事件响应计划。
    

  

**2\. ****错误的配置和不适当的变更控制**

这对CSA列表来说是一个新的威胁，考虑到许多企业意外地通过云暴露数据的例子，这并不奇怪。例如，CSA引用了Exactis事件，在该事件中，由于错误配置，供应商留下了一个Elasticsearch数据库，其中包含2.3亿美国消费者的个人数据。同样具有破坏性的是，由于备份服务器配置不当，一级机器人暴露了100多家制造公司的IP。

  

根据CSA的说法，公司需要担心的不仅仅是数据的丢失，还有为了破坏业务而对资源的删除或修改。报告将大多数配置错误归咎于糟糕的变更控制实践。

  

**CSA关于错误配置和不适当的变更控制的关键结论包括:**

*   基于云的资源的复杂性使得它们难以配置。
    
*   不要期望传统的控制和改变管理方法在云计算中是有效的。
    
*   使用自动化和技术持续地扫描配置错误的资源。
    

  

**3.****缺乏云安全架构和策略**

这个问题和云计算一样古老。最小化将系统和数据迁移到云中所需的时间的愿望通常优先于安全性。因此，该公司可以使用非针对其设计的安全性基础架构和策略在云中运营。这一现象出现在2020年的榜单上，表明越来越多的公司意识到了这一问题。

  

**CSA关于云安全架构和策略缺乏的主要意见包括:**

*   安全体系结构需要与业务目标保持一致。
    
*   开发和实施一个安全架构框架。
    
*   保持最新的威胁模型。
    
*   部署持续监视功能。
    

  

**4.****身份、凭据、访问和密钥管理不足**

列表中的另一个新威胁是对数据、系统和物理资源(如服务器机房和建筑物)的访问管理和控制不足。该报告指出，云计算要求企业改变与身份和访问管理(IAM)相关的实践。

  

**根据该报告，不这样做的后果可能导致下列安全事件和破坏:**

*   保护不当的凭证
    
*   缺少加密密钥、密码和证书的自动旋转
    
*   缺乏可伸缩性
    
*   未能使用多因素身份验证
    
*   没有使用强密码
    

  

**CSA关于身份、证书、访问和密钥管理不足的主要意见包括:**

*   安全帐户，包括使用双因素身份验证。
    
*   对云用户和身份使用严格的身份和访问控制——特别是限制根帐户的使用。
    
*   根据业务需求和最低权限原则隔离帐户、虚拟私有云和身份组。
    
*   采用程序性的、集中的方法来旋转键。
    
*   删除未使用的凭证和访问特权。
    

  

**5\. ****账户劫持**

账户劫持仍然是今年第五大云威胁。随着网络钓鱼尝试变得更加有效和有针对性，攻击者获得访问高度特权帐户的风险非常大。网络钓鱼并不是攻击者获得证书的唯一途径。他们也可以通过危及云服务本身，通过其他方式窃取来获取。

  

一旦攻击者可以使用合法帐户进入系统，他们可以造成大量破坏，包括盗窃或破坏重要数据，中断服务交付，或金融欺诈。CSA建议对用户进行帐户被劫持的危险和迹象相关的教育，以将风险降到最低。

  

**CSA关于帐户劫持的关键要点包括:**

*   不要只在账户凭证被盗时重置密码。解决根本原因。
    
*   深度防御和强大的IAM控制是最好的防守。
    

  

**6\. ****内部威胁**

来自可信赖的内部人员的威胁在云计算中和在内部系统中一样严重。内部人员可以是现任或前任雇员、承包商或值得信赖的商业伙伴——任何不需要突破公司防御系统才能进入公司系统的人。

  

内部人士不需要有恶意的破坏意图，他们可能无意中使数据和系统处于危险之中。CSA援引了波耐蒙研究所（Ponemon Institute）的《2018年内部威胁成本研究》，该研究指出，64%被报道的内部事件是由于员工或承包商的疏忽。这些疏忽可能包括云服务器配置不当、在个人设备上存储敏感数据，或者成为钓鱼邮件的受害者。

  

**CSA关于内部威胁的主要结论包括:**

*   对员工进行适当的培训和教育，以保护数据和系统。让教育成为持续的过程。
    
*   定期审计和修复错误配置的云服务器。
    
*   限制对关键系统的访问。
    

  

**7\. ****不安全的接口和****API**

从去年的第三名跌至第七名，不安全的接口和API是常见的攻击载体，Facebook知道这一点。2018年，该社交媒体的服务遭遇了一次入侵，影响了5000多万个账户，这是该服务引入的一个漏洞造成的。特别是当与用户界面相关联时，API漏洞可以为攻击者提供一条清晰的路径来窃取用户或员工凭证。

  

CSA报告说，组织需要理解API和用户界面通常是系统中最容易暴露的部分，它鼓励通过设计方法来构建它们的安全性。

  

**CSA关于不安全接口和API的主要结论包括:**

*   采用良好的API实践，比如监督库存、测试、审计和异常活动保护等项目。
    
*   保护API密钥并避免重用。
    
*   考虑一个开放的API框架，比如开放云计算接口(OCCI)或云基础设施管理接口(CIMI)。
    

  

**8\. ****控制面薄弱**

控制平面包含数据复制、迁移和存储的过程。CSA表示，如果负责这些流程的人不能完全控制数据基础设施的逻辑、安全和验证，那么控制面就会很弱。控制的涉众需要了解安全配置、数据如何流动以及体系结构的盲点或弱点。如果不这样做，可能会导致数据泄漏、数据不可用或数据损坏。

  

**CSA对于弱控制平面的主要结论包括:**

*   确保云服务提供商提供履行法律和法定义务所需的安全控制。
    
*   执行尽职调查，以确保云服务提供商拥有足够的控制平面。
    

  

**9\. ****元结构和应用结构失败**

云服务提供商的元结构保存关于如何保护其系统的安全信息，并通过API调用公开这些信息。CSA将元结构称为云服务提供商/客户的“分界线”或“水线”。“这些API帮助客户检测未经授权的访问，但也包含高度敏感的信息，如日志或审计系统数据。

  

这条水线也是一个潜在的故障点，可能使攻击者能够访问数据或破坏云客户。糟糕的API实现通常是造成漏洞的原因。CSA指出，例如，不成熟的云服务提供商可能不知道如何正确地为其客户提供API。

  

另一方面，客户可能不了解如何正确地运行云应用程序。当它们连接不是为云环境设计的应用程序时，尤其如此。

  

**CSA关于元结构和应用结构故障的关键结论包括:**

*   确保云服务提供商提供可见性并公开缓解措施。
    
*   在云本地设计中实现适当的特性和控件。
    
*   确保云服务提供商进行渗透测试并向客户提供发现。
    

  

**10\. ****有限的云使用能见度  
  
**

安全专业人员经常抱怨云环境使他们对检测和防止恶意活动所需的大量数据视而不见。CSA将这种有限的使用可见性挑战分为两类:未经批准的应用程序使用和批准的应用程序滥用。

  

未经批准的应用程序本质上是影子IT应用程序，雇员在未经允许或IT或安全支持的情况下使用。任何不符合公司安全指导原则的应用程序都代表着安全团队可能没有意识到的风险。

  

被批准的应用程序滥用可能是授权人员使用已批准的应用程序，或者外部威胁行为人使用偷来的证书。CSA报告称，安全团队需要能够通过检测异常行为来区分有效用户和无效用户。

  

**关于有限的云使用可见性，CSA的主要结论包括:**

*   自上而下地开发与人员、流程和技术相关的云可见性工作。
    
*   在全公司范围内对已接受的云使用政策和执行进行强制性培训。
    
*   让云安全架构师或第三方风险管理人员查看所有未经批准的云服务。
    
*   投资云访问安全代理(CASB)或软件定义网关(SDG)来分析出站活动。
    
*   投资一个Web应用程序防火墙来分析入站连接。
    
*   在整个组织中实施零信任模型。
    

  

**11\. ****滥用和恶意使用云服务**

攻击者越来越多地使用合法的云服务来支持他们的活动。例如，他们可能使用云服务在GitHub等网站上托管伪装的恶意软件，发起DDoS攻击，分发钓鱼邮件，挖掘数字货币，执行自动点击欺诈，或实施暴力攻击以窃取凭证。

  

CSA表示，云服务提供商应采取适当措施，防止和检测支付工具欺诈或云服务滥用。对于云提供商来说，有一个适当的事件响应框架来应对滥用并允许客户报告滥用也是很重要的。

  

**关于云服务的滥用和误用，CSA的主要结论包括:**

*   监控员工对云的滥用。
    
*   使用云数据丢失预防(DLP)解决方案来监控和停止数据泄露。
