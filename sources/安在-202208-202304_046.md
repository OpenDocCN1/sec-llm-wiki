# 全世界84%的代码库至少存在1个开源漏洞

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzU5ODgzNTExOQ==&mid=2247585413&idx=2&sn=58a9d75dd321b0909953e0b4fc992f23&chksm=febde445c9ca6d53e3f6c83c2f48a864fcdd05ad2387634dd82dd691d8078aa5044a507fcd26&scene=126&sessionid=1681310555#rd](http://mp.weixin.qq.com/s?__biz=MzU5ODgzNTExOQ==&mid=2247585413&idx=2&sn=58a9d75dd321b0909953e0b4fc992f23&chksm=febde445c9ca6d53e3f6c83c2f48a864fcdd05ad2387634dd82dd691d8078aa5044a507fcd26&scene=126&sessionid=1681310555#rd)

软件供应链安全问题一直在被业界所讨论，在几乎所有软件都包含开源代码的时候，应用安全公司Synopsys的研究人员发现84%的商业和专有代码库中至少存在一个已知的漏洞。此外，Synopsys研究人员分析的所有代码库中，有48%包含高危漏洞。这些漏洞要么多次被使用，要么已经被分类为远程代码执行漏洞。

  

该漏洞数据以及开源许可证合规信息可以在Synopsys发布的2023年开源安全和风险分析（OSSRA）报告查看，该报告由Synopsys的网络安全研究中心（CyRC）整理。（https://www.synopsys.com/content/dam/synopsys/sig-assets/reports/rep-ossra-2023.pdf）

  

![](../Images/16a4312c14db1979864ec032c60442df.png)

  

  
  

**0****1****开源漏洞数量正在增加**  

OSSRA报告称，相比2021年，2022年代码审计得出的已知的开源漏洞数量增加了4%。值得注意的是，OSSRA分析目标包括各行业代码库的绝大部分。换句话说，任何行业的软件在应用开源代码时都有可能存在漏洞。

航天、航空、汽车、运输和物流行业的绝大多数公司的代码库都包含一些开源代码，其中开源代码占总代码的73%。除此之外，63%的代码（开源和专有）包含被归类为高危漏洞，即CVSS安全风险值分为7分或更高的漏洞。在能源和清洁技术领域，78%的代码是开源的，69%包含高危漏洞。

![](../Images/5dde447e70076d0a0d2385537109d651.png)

报告表示，尽管这些公司的代码库在漏洞占比方面高于其他行业，但并不代表着其他行业没有这些高危漏洞，和上述行业相比，其他行业的高危漏洞占比程度较小，但并非没有。

**0****2****开源采用率跃升**  

根据OSSRA的报告，在过去五年中，开源代码在所有垂直行业的代码库中所占的比例都有所上升。

例如，在2018年至2022年间，在线教育行业的代码库中，开源代码比例增长了163%；航空、航天、汽车、运输和物流业占97%；制造业和机器人领域占74%。报告认为，在线教育的开源代码增长可以归咎于疫情，疫情推动了在线教育的发展，而软件是在线教育的基础。

**0****3****高危漏洞增多**  

与此同时，所有行业的高危脆弱性都有所增加。例如，航空、航天、汽车、运输和物流公司的高危漏洞在5年内增加了232%。Synopsys公司认为，这些行业中使用的大部分软件和硬件都在封闭系统中运行，这虽然可以降低漏洞利用的可能性，但也可能导致漏洞修补不及时。

自2018年以来，物联网相关代码库中的高风险漏洞已跃升130%。研究人员认为，当考虑到物联网设备正在逐渐推广，这种风险让人格外担忧。尤其是与生活许多方面相关联起来的物联网设备，漏洞的存在可能会影响到更多人的日常生活。

**0****4****未应用可用的修补措施**  

在研究人员审计的包括风险评估在内的1481个基于代码的系统中，91%包含过时版本的开源组件，这意味着很多可使用的更新和补丁并未及时应用。当然，带来这一结果的可能是开发人员认为更新或使用补丁后的风险超过了旧版本的风险。

另外，研究人员认为，缺乏时间和资源也可能是导致未及时应用补丁的原因。报告认为，由于许多开发或安全团队已经达到了构建和测试新代码工作的极限，除了最关键的问题外，更新现有软件的优先级可能会降低。此外，报告认为DevSecOps团队可能不知道何时有更新版本的开源组件可用。

![](../Images/19b54d3b95fe397c90d6f7a676d5469d.png)

  

**0****5****SBOM有助于维护代码质量和合规性**  

  

该报告建议，为了避免漏洞被利用，同时保持开源代码的更新，组织可以考虑使用软件材料清单（SBOM）。一个全面的SBOM会列出了应用程序中的所有开源组件以及许可证、版本和修补程序状态等等。报告补充道，开源组件的SBOM使组织能够快速确定有风险的组件，并确定补救的优先级。
