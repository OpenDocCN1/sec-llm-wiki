# 安全措施和合规有冲突怎么办？

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzU5ODgzNTExOQ==&mid=2247565784&idx=1&sn=2afa904bf17b60be8ecdec049d153f5b&chksm=febdab18c9ca220e6ad16a336a147fa3e191aa8686f5c210279868633e596bc67435f8665ddb&scene=126&sessionid=1681310579#rd](http://mp.weixin.qq.com/s?__biz=MzU5ODgzNTExOQ==&mid=2247565784&idx=1&sn=2afa904bf17b60be8ecdec049d153f5b&chksm=febdab18c9ca220e6ad16a336a147fa3e191aa8686f5c210279868633e596bc67435f8665ddb&scene=126&sessionid=1681310579#rd)

**![](../Images/ec03a52bc4c05aea2c6e258462f5c0df.png)**

  

  

在网络安全趋于成熟的今天，安全与合规正越来越多地在高度交叉、融合，这与国际网络空间安全战略以及国家网络安全法律频繁出台密切相关。因此，企业在做安全规划时，其中一个重要的驱动便是合规驱动。是否符合网络安全法？是否符合数据安全法？是否符合个人信息保护法等，如不满足安全监管要求，业务就无法放心大胆地开展。

  

另一方面，无论是从security by design还是audit的角度来说，整个发展的过程中，合规始终是贯穿首尾的框架和主线，所以企业需要在这个基础和框架里去保证安全的正确实施，同时合规还具有调整和矫正的作用，比如使用合规成熟度模型来衡量企业的风险评分，或使用这些模型策略来捕捉不断变化的风险，当然还可以用这些模型来帮助 IT 负责人，以他们所能理解的风险和业务语言向高层管理人员报告。

  

可以说，每一个安全的domain和安全的lifecycle的过程，都是相辅相成、相互依靠的。随着合规不断地演绎和引进，安全便是在此过程中会发生不断地迭代，并磨合出最佳实践，这是安全和合规之间主要的关联。那不禁要问，如果当下所适用的安全措施不符合合规要求怎么办？答案是：改变它，并尽可能地使它保持合规。

  

正如国外安全专家建议的那样，当安全人员发现了某个安全措施，并觉得此措施能给公司的安全带来改善时，明智的做法是先确定这措施是否合规，或者判断其是否可以成为企业合规模板可接受的例外，不然盲目地落实措施会给企业带来无法想象的后果。

  

![](../Images/72b8c25b19de477307070eafe7444e08.png)

  

从现实来看，许多安全人员为具有多项合规要求的公司工作，显而易见，所处的公司规模越大、国际化程度越高，所需遵循的合规、法规就越多，比如欧盟的通用数据保护条例 (GDPR)、美国健康保险流通与责任法案 (HIPAA)、支付卡行业数据安全标准 (PCI DSS)、美国国家标准与技术研究院 (NIST) 的指南、联邦信息安全管理法案 (FISMA) 和互联网安全中心 (CIS) 控制等，包括我国的《个人信息保护法》、《数据安全法》、《网络安全法》。

  

这些法规包含了各种建议和具体实施内容，企业需要在更改网络防御之前查看这些条例，以确保自己的合规性。接下去就简单介绍几种需要注意的安全措施。

  

  

**关于Windows 更新**  

  

通过这几年我们在网络中观测到的变化，一些事件的处理可能会出乎安全从业者的意料，比如“该如何处理Windows的更新”，由于一些组件的更新不再由Windows软件更新服务（WSUS）所控制，而相关法规又没有提示相应的更新方式，所以该如何处理这事成了不小的麻烦。

旧规定是很明确的：不允许所更新的系统不受控制。正如Server 2012 R2部分所述：“不受控制的更新可能会给系统带来问题，比如从外部获取的更新组件可能会在不经意间泄露敏感信息，因此可选组件安装或修复必须从内部获取来源。”

为此，国外安全专家建议企业别再使用WSUS，他们认为可以将计算机设置为从internet获取.Net 3.5组件。“将计算机配置->管理模板->系统->策略值配置中的‘为可选组件安装和组件修复指定’设置为已启用，并选择‘从不尝试从Windows Update下载有效负载’。”

那么在安装和部署.NET 3.5时，可以让服务器独立连接到Windows update进行服务吗？答案是：视情况而定。对于某些公司来说，比如金融业，他们大多是强监管，可能会被要求遵守严格的合规模板。而其他公司可以根据需求和安全态势适当的“请求例外”。

另一方面，甚至连Windows Server 2019也要求别再使用更现代化的更新功能。一个典型的例子是，Server 2019不允许网络中的其他设备可以搜索更新被称为“传递优化的对等更新技术”。“Windows Update可以从其他来源获取更新，而不仅仅是在Microsoft。除Microsoft外，还可以从本地网络和Internet上的PC获取更新并将其发送到PC，这是Windows Update可信过程的一部分。但是为了最大限度减少外部暴露，必须防止系统会从Internet上获取更新。”

  

![](../Images/4f16d6d8c2d58f83c279e4ad27959ea1.png)

为确保系统没有此设置，国家安全专家建议，可将计算机配置>>管理模板>>Windows组件>>交付优化中下载模式的策略值改为“启用”。

  

**在 Microsoft Azure 中修补虚拟机**  

  

即使是使用Azure之类的技术，企业也必须遵守合规性要求，例如，Azure 中的虚拟机必须与补丁保持同步。国外安全专家建议使用Azure安全中心查看 Windows 和 Linux 虚拟机的状态，或者使用第三方补丁软件使系统保持最新。

而说到补丁，国内几乎所有的条例都规定企业要给全部系统及时地打上重要和关键的补丁，但实际操作中连打全补丁的企业都是凤毛麟角，就更别说“及时打全补丁”的了。

同样，完全修复的服务器也近乎为零。每个人都觉得服务器已经完全修复了，但实际上修复的只是那些打上了全部微软补丁的服务器，甚至部分服务器连微软补丁打没打全都不一定。而即便操作系统补丁都打上了，服务器管理软件却仍然是过时的。有些底层视频编码器堪称老旧，有些服务器管理工具年代久远，这些所谓的过时、老旧、年代久远，都意味着它们包含了那些公开已知的漏洞，也就是说系统可随时被远程控制。

每次面对合规审计时，只告诉审计员99%的漏洞都给补上了，而且还能拿出报告加以证明。但没告诉审计员的是，未修复的那1%的漏洞正是最有可能被恶意黑客给利用的，避重就轻是大部分企业在面对合规时所采用的策略，即合规报告中宣称已完全修复，但实际上漏洞一直都在。

![](../Images/a748849ffaac2978a991cad0b5d7b91e.png)

  

在此建议，切不可为了合规而逃避安全，也不可为了安全而无视合规，虽然现阶段每家公司对安全部门甚至整个IT部门的资源投入都有限，但作为企业的守门员，还是尽可能地要完善策略和机制，争取不让企业陷入威胁和罚款。

  

**关于新技术平台**  

  

国外安全专家表示，企业在推出新技术平台之前需要对其进行审查和批准。以 Microsoft 用于管理和控制工作站的新平台 Intune 为例，CIS 有一个用于部署 Intune 的审核模板，要审查的项目范围是从设置到身份验证。

关于新技术平台，当下的趋势是这样，由于现代网络安全环境中最普遍的挑战之一是工具供应商过多，所以如何将这些工具结合起来成了当前比较热门的发展方向。除了相关的技术外，可以看到所有工具供应商都有自己的数据和体系，他们通常会采用自己的本地模式或数据格式，因此，当安全团队需要集成、实施和管理的网络安全工具变得越来越多，所涉及的“数据合规”问题也就会越来越多，安全从业人员必须花时间识别这些数据，审查综合技术平台所包含的这些工具是否合规。

在这样的问题上，亚马逊网络服务（AWS）认为，数据转型时代所带来的数据合规，使越来越多的安全从业人员疲于应对各种安全工具所带来的专有数据格式和输出，鉴于该行业已经面临了巨大的劳动力挑战、倦怠和资源不足，亚马逊网络服务（AWS）发布了开放网络安全架构框架（OCSF）项目，此项目通过对安全产品模式、格式进行标准化，可使更多的安全工具相互融合，包括这些工具所带来的合规问题都能一并解决，这样安全从业人员就可以花更多时间去解决真正意义上的威胁风险。

  

**关于密码**  

  

一些密码设置可能会给密码管理带来更多的问题。正如Tenable 审核页面指出的那样，服务器模板和 Intune 中建议将密码使用期限设置为 60 天或更短。然而最近的研究表明，如果多因素身份验证与更好的身份验证技术（如Windows Hello或其他生物特征选项）一起使用，密码到期时间可以设置为高于60天，甚至可能完全禁用。安全人员需要对某些“法规遵从性模板”请求一定的例外项，因为我们的目标总是让企业更安全。

另一方面，安全风险显然不是二元的，但合规是。合规就是只准回答“是或否”的一系列二元问题。你做没做过某某事项？所要求的事项达标了吗？这些问题可以说没给创新思维或更强大的安全留下太多空间。举个例子，大多数合规规定要求至少8个字符的复杂密码，即便20个字符的非复杂密码无疑更难破解也更容易使用，但在大多数公司里你却不能这么设。

![](../Images/368679a60b87c6d55134e43a60207262.png)

  

另一个例子，合规会要求设置用户账户锁定策略：密码输入错误次数达到预设阈值即锁定账户。但如果已经要求了足够长的密码，那其实无需账户锁定策略风险也不会太高。

增加密码默认强度不能免除账户锁定策略的要求。但某些情况下，账户锁定策略反而会增加拒绝服务事件的风险。密码猜解蠕虫往往会尝试100个随机密码，极有可能导致目标用户账户被锁定。黑客也可以对在线门户网站发起密码猜解攻击，令网站用户无法登录。这些是需要企业在合规、安全和用户服务中一并衡量的。

  

**监管和指导资源**  

  

在国外，互联网安全中心网站要求企业在提供电子邮件地址和公司信息后，允许企业下载指南，范围从苹果设备到思科设备，从防火墙到打印机都有。因此国外安全专家建议，除了下载指南之外，安全人员还可以注册加入基准社区，以便提问并参与讨论。通常在这些基准社区中，能找到志同道合的参与者可帮助安全人员完成合规项目。

对标致国内，其实我们也可以设置更多这样的社区，将安全人员统一起来共同完成合规要求。而安在新媒体的发展道路就是以“社区”、“群体”为目标，希望更多的CSO、CISO、安全从业人员能够团结起来，一同对抗风险和威胁。

  

**国内安全专家的建议**  

  

对于安全措施和合规之间的冲突，国内安全专家如此建议。

**隐私保护工作从业者王振东**表示自己曾遇到过这样的问题，但由于事件牵扯公司隐秘，所以并不能完全告知。但他建议一旦遇到这样的问题，首先是找到上级协调沟通并且达成一致。王振东相信安全和合规的目标实际上是相同的，不会有核心冲突，或者说不会有无法解决的冲突，大多问题只是没有沟通清楚罢了。

“我是直接从研发转型为合规的，没有经历过安全这一步，但是因为我也长期关注和研究安全的一些领域（比如SDLC、安全意识培养、渗透测试等），如果要对安全和合规说些什么，那就是希望安全从业人员要避免过分看重自己的观点，要和法务、IT、人力资源等多方配合，服务好业务，为公司带来1+1+1+1+1＞5的收益。”

**而某集团安全专家梁龙亭认为**，近来大家遇到的冲突大多集中表现在隐私合规问题上，特别是一些To C企业，在对外提供应用服务时，会比往常增加更多收集使用个人信息弹窗提示的设计。从法律合规视角来看，每款应用内包含的不同业务都需要根据不同业务场景单独设计隐私政策及弹窗提示，10个业务场景就需要10个隐私政策和弹窗提示，这无疑给用户体验和应用提供商带来了巨大挑战，应用提供商没有主动整改的积极性，终端用户似乎对此也怨声载道。

为此，梁龙亭建议：

1，向高级管理层宣传法律法规，形成自上而下的沟通机制，获得高管资源支持。

2，项目立项，成立项目组，明确分工。

3，周会跟进项目进展。

4，每个重要节点请律师指正。

5，最后，根据实际变化持续更新隐私政策。

面对笔者所提：“您作为安全人员最想对‘合规’说些什么？”梁龙亭回答：“合规工作为企业守住了法律法规底线，是企业内部的‘监管部门’，所以我希望合规人员能眼观六路耳听八方，及时捕捉到法律法规变化，并与公司各部门协力合作，同舟共济。不建议合规人员只提出问题，不带来建议；合规人员不是只提出问题，更要能够有解决问题的能力，尽管问题最终并非由合规人员来解决，但是这个提出解决方案的能力是必需具备的，因为，合规人员在公司虽然具有一定独立性，但毕竟不是真正的‘监管部门’。”

**某科技公司安全部经理Softgirl**也经历过同样的状况，鉴于项目比较敏感，不方便明说。但她指出，对企业来说合规是底线，也就是必须遵守的准则，因此如果遇到和合规起冲突的措施，那就该取消该安全措施的实施。

“对‘合规’我并没有什么想过多表达的，但可以明确的是，合规对任何一家企业来说都是很重要的基线，甚至安全也是合规的一部分。一般合规可能包括法律合规、行业合规、内控合规、安全合规等。作为安全从业者，我们要做好安全合规的要求和基线，以此来做好安全防御，为安全打好基础。”

**某软件公司信息安全管理总负责人胡燕**对此表示赞同，她认为面对这种情况，需要征求公司高管意见，协商改进措施和规定要求，然后结合合规要求和公司实际情况对安全措施进行修补。

“至于对‘合规’有啥看法，我认为，作为安全从业人员，合规与安全均需要分门别类，当合规与安全冲突时，需要定位问题根本原因，不能水火不容，也不能迁就某一方，合规如果出现不适用的情况，也需要明确并完善。与其因为任何原因而裁剪出‘不适用’的安全控制，不如再细化真正可用性高的方法和规定，进而在不妨碍公司业务运营能力的情况下实现所有实际上可行的控制。”

另一方面，**某大型IT服务外包集团安全负责人朱诚表示，**在他的工作经历中，也遇到过和合规起冲突的安全措施。他为此举了个例子：“‘隐私’是个比较大的范畴，当然‘隐私’的管理也属于合规管理，因此公司在对员工做上网行为管理的监控时，势必会看到一些‘隐私’，哪怕是办公环境里的电脑和网络。所以我觉得正确的处理方法可以是将起冲突的管理措施告诉大家，在受监督的情况下进行安全管理措施。简单的说就是把‘安全管理权力关进笼子里、放在阳光下’。”

朱诚认为，“安全”和“合规”从来都不是对立面，宽泛意义上来说“安全”、“合规”就是一个“大安全管理”的观念，完全是可以成为一家人的，朱诚公司就是这样设立成了“安全合规部”，安全主管信息泄露风险，合规主管商业行为规范。安全和合规，两者权力相互制约，两者功能又相互配合，从另外一方面来说，配合好了就是“相得益彰”，配合不好就是“相互掣肘”。所以朱诚希望我们安全业界和合规业界，都能站在战略层面去考虑这件事情，只有相互配合，才能实现1+1>2！

  

**补充**  

合规妨碍安全的理由还有很多，比如大量时间精力浪费在满足略有不同的多个合规要求上，或者某些指南过于详细，而其他规定又过于宽泛。合规最大的问题就在于，没有跟进真正应该减小的底层网络安全风险。不得不说，没尊崇真正的安全实现真是件令人悲伤的事，而当合规与安全冲突时，只要安全能偶尔胜出，情况都会好许多。

最后想说，对几乎所有成规模的公司而言，合规都是一项必要的任务，安全人员的目标是在选择正确的合规手段和采用可为公司带来更多安全性的新技术之间找到平衡。
