一

项目简介


RuoYi 是一个 Java EE 企业级快速开发平台，基于经典技术组合（Spring Boot、Apache Shiro、MyBatis、Thymeleaf、Bootstrap），内置模块如：部门管理、角色用户、菜单及按钮授权、数据权限、系统参数、日志管理、通知公告等。在线定时任务配置；支持集群，支持多数据源，支持分布式事务。

01

主要特性


  • 完全响应式布局（支持电脑、平板、手机等所有主流设备）；

  • 强大的一键生成功能（包括控制器、模型、视图、菜单等）；

  • 支持多数据源，简单配置即可实现切换；

  • 支持按钮及数据权限，可自定义部门数据权限；

  • 对常用js插件进行二次封装，使js代码变得简洁，更加易维护；

  • 完善的XSS防范及脚本过滤，彻底杜绝XSS攻击；

  • Maven多项目依赖，模块及插件分项目，尽量松耦合，方便模块升级、增减模块；

  • 国际化支持，服务端及客户端支持；

  • 完善的日志记录体系简单注解即可实现；

  • 支持服务监控，数据监控，缓存监控功能。

02

内置功能


  • 用户管理：用户是系统操作者，该功能主要完成系统用户配置。

  • 部门管理：配置系统组织机构（公司、部门、小组），树结构展现支持数据权限。

  • 岗位管理：配置系统用户所属担任职务。

  • 菜单管理：配置系统菜单，操作权限，按钮权限标识等。

  • 角色管理：角色菜单权限分配、设置角色按机构进行数据范围权限划分。

  • 字典管理：对系统中经常使用的一些较为固定的数据进行维护。

  • 参数管理：对系统动态配置常用参数。

  • 通知公告：系统通知公告信息发布维护。

  • 操作日志：系统正常操作日志记录和查询；系统异常信息日志记录和查询。

  • 登录日志：系统登录日志记录查询包含登录异常。

  • 在线用户：当前系统中活跃用户状态监控。

  • 定时任务：在线（添加、修改、删除)任务调度包含执行结果日志。

  • 代码生成：前后端代码的生成（java、html、xml、sql)支持CRUD下载 。

  • 系统接口：根据业务代码自动生成相关的api接口文档。

  • 服务监控：监视当前系统CPU、内存、磁盘、堆栈等相关信息。

  • 缓存监控：对系统的缓存查询，查看、清理等操作。

  • 在线构建器：拖动表单元素生成相应的HTML代码。

  • 连接池监视：监视当期系统数据库连接池状态，可进行分析SQL找出系统性能瓶颈。

shiro反序列化漏洞


若依管理系统使用了Apache Shiro，Shiro 提供了记住我（RememberMe）的功能，下次访问时无需再登录即可访问。系统将密钥硬编码在代码里，且在官方文档中并没有强调修改该密钥，导致框架使用者大多数都使用了默认密钥。


攻击者可以构造一个恶意的对象，并且对其序列化、AES加密、base64编码后，作为cookie的rememberMe字段发送。Shiro将rememberMe进行解密并且反序列化，最终造成反序列化漏洞，进而在目标机器上执行任意命令。


漏洞验证

查看pom.xml文件，可知该系统使用的shiro版本为1.6.0。

查看ruoyi-admin下的application.yml，可发现默认密钥为：

zSyK5Kp6PZAAjlT+eeNMlg==


在Shiro1.4.2版本后，Shiro的加密模式由AES-CBC更换为 AES-GCM。本地搭建的shiro版本为1.6.0，则勾选GCM加密，使用工具利用成功。


修复建议

该漏洞存在的主要原因是框架使用者大多数都使用了默认密钥，导致漏洞产生。我们需要将修改默认密钥或采用随机生成密钥的方式替换默认密钥。具体方法如下：


将以下代码直接拷贝到main方法里运行即可生成一个Base64唯一字符串，并将生成的新密钥替换默认密钥，注意妥善保管密钥，防止泄漏。

01

SQL注入漏洞


Mybatis提供了 “#”和 ”$” 两种符号进行传参。

#{} 在预处理时，会把参数部分用一个占位符 ? 替代，其中 value 表示接受输入参数的名称。

${} 表示使用拼接字符串，将接受到参数的内容不加任何修饰符拼接在 SQL 中，使用${}拼接 SQL语句，将引起 SQL 注入问题。


漏洞验证

在xml文件中搜索 ${ ，发现 SysDeptMapper.xml 和 SysRoleMapper.xml 有存在SQL注入的地方。


第一处-dataScope

点击进入 SysRoleMapper.xml ，注入点在第58行，使用 $ 直接拼接了参数。点击左侧箭头快速跳转到DAO层（IDEA中需要安装Free Mybatis plugin插件）。

看看谁调用了这个方法，键盘按住Ctrl加鼠标左键，点击selectRoleList。

跳转到SysRoleServiceImpl的实现层。

进入 SysRoleServiceImpl 后，再回溯到 SysRoleService ，可使用左侧快速跳转按钮。


键盘按住Ctrl加鼠标左键，点击 selectRoleList ，回溯到 Controller 层，最终发现是 SysRoleController 调用了这个方法。

通过Controller层，我们可以知道，漏洞为 /system/role/list 接口。进入/system/role/页面，点击搜索按钮，使用BurpSuite抓包。

任意文件读取/下载漏洞


网站由于业务需求，往往需要提供文件查看或文件下载功能，但若对用户查看或下载的文件不做限制，则恶意用户就能够查看或下载任意敏感文件。


任意文件下载漏洞，正常的利用手段是下载服务器文件，如脚本代码，服务器配置或者是系统配置等等。可以利用../来逐层猜测路径。


漏洞验证

查看配置文件，可知默认文件路径为D:/ruoyi/uploadPath。

在目录D:/ruoyi/创建一个1.txt文件。


使用BurpSuite抓包，修改数据包为以下内容（记得修改Cookie）。

GET /common/download/resource?resource=/profile/../1.txt HTTP/1.1Host: 127.0.0.1User-Agent: Mozilla/5.0 (Windows NT 10.0; WOW64; rv:52.0) Gecko/20100101 Firefox/52.0Accept: text/html,application/xhtml+xml,application/xml;q=0.9,*/*;q=0.8Accept-Language: zh-CN,zh;q=0.8,en-US;q=0.5,en;q=0.3Accept-Encoding: gzip, deflateCookie: JSESSIONID=fa4b3bdd-e507-462a-a155-a2adf4842470;DNT: 1Connection: closeUpgrade-Insecure-Requests: 1
