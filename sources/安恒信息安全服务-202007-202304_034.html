前置知识

缓冲区溢出是指程序向缓冲区中写入的数据超过了缓冲区的大小，从而导致数据覆盖到缓冲区之外的内存。这种情况下，攻击者可能会利用这种溢出来执行恶意代码，从而导致系统崩溃或者被远程控制。

“代码段”存储了用户程序的所有可执行代码，在程序正常执行的情况下，程序计数器（PC 指针）只会在代码段和操作系统地址空间（内核态）内寻址。“数据段”内则存储了用户程序的全局变量、文字池等。


“栈”空间存储了用户程序的函数栈帧（包括参数、局部数据等），实现函数调用机制，它的数据增长方向是低地址方向。“堆”空间存储了程序运行时动态申请的内存数据等，数据增长方向是高地址方向。


除了代码段和受操作系统保护的数据区域，其他的内存区域都可能作为缓冲区，因此缓冲区溢出的位置可能在数据段，也可能在堆、栈段。


如果程序的代码有软件漏洞，恶意程序就会“教唆”程序计数器从上述缓冲区内取址，并执行恶意程序提供的数据代码。下文将会对栈溢出的攻击方式进行简单分析。



函数栈帧

函数栈帧是一种用于在调用函数时存储函数相关信息的数据结构。每当一个函数被调用时，系统都会为该函数创建一个新的函数栈帧并把它放到栈的顶部。函数栈帧包含以下信息：

· 函数的返回地址：指向下一条要执行的指令的地址，用于在函数执行完后返回调用者。

· 函数的参数：传递给函数的参数值。

· 函数的局部变量：函数内部使用的变量。


当函数执行完后，系统会把函数栈帧弹出栈，并接着执行下一条指令。

函数栈帧在程序调试、函数调用和内存管理等方面都很重要。它们可以帮助我们了解函数调用的过程，以及函数的参数和局部变量的使用情况。


如下图所示，我们定义了一个简单的函数 function，它接受一个整形参数，做一次乘法操作并返回。当调用 function(0)时，arg 参数记录了值 0 入栈，并将 call function 指令下一条指令的地址 0x00bd16f0 保存到栈内，然后跳转到 function 函数内部执行（每个函数定义都会有函数头和函数尾代码，如图绿框表示）。

因为函数内需要用 ebp 保存函数栈帧基址，因此先保存 ebp 原来的值到栈内，然后将栈指针 esp 内容保存到 ebp。函数返回前需要做相反的操作——将 esp 指针恢复，并弹出 ebp。这样，在函数内正常情况下，无论怎样使用栈都不会使栈失去平衡。

之所以会有缓冲区溢出的可能，主要是因为栈空间内保存了函数的返回地址。该地址保存了函数调用结束后后续执行的指令的位置，对于计算机安全来说，该信息是很敏感的。如果有人恶意修改了该返回地址，并使其指向了一个新的代码位置，程序就能从其它位置继续执行。


栈溢出基本原理

栈溢出指的是在执行函数时函数栈的大小超过了系统预先设定的限制，从而导致数据覆盖到栈之外的内存。这种情况下，攻击者可能会利用这种溢出来执行恶意代码，从而导致系统崩溃或者被远程控制。


举个例子：
#include <stdio.h>
void recurse(int n) {    int array[10000];    printf("recurse called with n = %d\n", n);    recurse(n + 1);}
int main() {    recurse(0);    return 0;}

这段代码中有一个函数 recurse，它会递归调用自身。为了模拟大量数据占用栈空间，我们在函数中声明了一个大小为 10000 的数组。


当我们运行这段代码时，它会打印出如下输出：

recurse called with n = 0recurse called with n = 1recurse called with n = 2


这些输出会一直重复下去，直到堆栈溢出。当堆栈溢出时，程序会崩溃并退出。


下面用一个通俗易懂的例子来解释：

想象你在做一个游戏，在游戏中你有一个背包，用来装物品。但是背包容量有限，最多只能装下 1000 个物品。现在你在游戏中捡到了一个神奇的物品，使你的背包增加了一个格子。你拿着这个神奇的物品又去捡了一个神奇的物品，再次增加了一个格子。你一直重复这个过程，直到你的背包格子数量超过了最大限制，就像这样：

背包容量: 1000 背包格子数: 1000你捡到了一个神奇的物品，增加了一个格子，背包格子数变为 1001你捡到了另一个神奇的物品，增加了一个格子，背包格子数变为 1002……

背包格子数一直增加，直到超过了最大限制。此时，就会发生栈溢出。

类比到计算机程序中，堆栈就相当于你的背包，函数调用就相当于你捡到了神奇的物品。如果函数调用层级过多，就会导致堆栈溢出。



堆溢出

堆溢出是指程序在申请内存时，申请的内存超过了最大限制。堆溢出的原理是，程序中的某个变量向系统申请内存，但是系统没有足够的空闲内存来分配，导致程序崩溃。


下面是一个示例：


#include <stdio.h>#include <stdlib.h>
int main() {    while (1) {        int *array = malloc(1000000000 * sizeof(int));        if (array == NULL) {            perror("malloc failed");            exit(1);        }        printf("Allocated 1 billion integers\n");    }    return 0;}

这段代码中，我们使用 malloc 函数在循环中不断申请内存。每次申请 1 百亿个 int 类型的内存。如果申请成功，就会输出 "Allocated 1 billion integers"。当你运行这段代码时，它会不断申请内存，直到申请失败。此时，就会发生堆溢出。堆溢出可能导致计算机系统错误或者程序异常退出。


想象你在玩一个电脑游戏，游戏中有一个敌人可以放置障碍物。你的目标是消灭这个敌人。你的武器有一个弹药上限，最多只能装载 1000 发子弹。但是敌人的障碍物可以无限生成，就像这样：

弹药上限: 1000 当前弹药数: 1000你开火，弹药数减少 1 发，变为 999你开火，弹药数减少 1 发，变为 998……


一直开火，弹药数一直减少，直到为负数。此时，就会发生堆溢出。

类比到计算机程序中，堆就相当于你的弹药库，内存申请就相当于你开火。如果你一直申请内存，但是没有足够的空闲内存来分配，就会发生堆溢出。



防范方法

栈溢出：

1. 使用非递归实现：递归函数会导致函数调用层级增加，容易导致栈溢出。可以使用循环或者迭代来替代递归实现，避免栈溢出。

2. 使用尾递归优化：尾递归是一种特殊的递归形式，它不会导致函数调用层级增加，因此不容易导致栈溢出。可以使用尾递归优化来替代普通递归实现，从而避免栈溢出。

3. 增大堆栈空间：可以使用编译器选项或者系统调用来增大堆栈的最大空间，从而避免栈溢出。但是要注意，增大堆栈空间会增加程序的内存占用，因此应该根据需要合理调整堆栈空间的大小。

4. 检查函数调用层级：可以在程序中添加代码来检查函数调用的层级，如果层级过多就可以触发警报或者直接退出程序，从而避免栈溢出。

5. 使用安全的编程语言：有些编程语言，比如 Python，内置了垃圾回收机制，可以自动回收内存，避免堆溢出和栈溢出的问题。使用这种安全的编程语言，可以大大减少安全隐患。


堆溢出

1. 合理设置内存限制：可以在程序中设置内存限制，避免程序申请过多的内存。

2. 使用安全的编程语言：理由与栈溢出类似。

3. 调整堆的初始大小：可以使用编译器选项或者系统调用来调整堆的初始大小，从而避免堆溢出。但是要注意，调整堆的初始大小会增加程序的内存占用，因此应该根据需要合理调整堆的大小。

4. 及时释放内存：在程序中使用内存完毕后，应该及时调用 free或者相应的内存释放函数，释放不再使用的内存。这可以避免内存泄露，同时也可以防止堆溢出。

5. 使用内存池：内存池是一种优化内存使用的技术，它可以避免频繁调用内存分配函数，提高程序效率。同时，内存池也可以有效防止堆溢出。

6. 使用安全的库函数：有些库函数，比如 strcpy_s 和 strncpy_s，是安全的字符串拷贝函数。它们可以避免缓冲区溢出，从而有效防止堆溢出。
