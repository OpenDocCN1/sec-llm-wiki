**一、前置知识**

  

MVC模式是当前主流的Web应用开发模式之一，即模型(Model )－视图(View )－控制器(Controller)。通过实现Model-View-Controller模式能够很好地将数据、业务与展现进行分离。

  

Spring MVC是一个用于构建Web应用程序的Java框架，遵循着MVC的模式设计思想。

  

实现MVC模式的Web应用，会对外表现出前后端分离的特征。在挖掘利用这类前后端分离的系统的RCE漏洞时，会发现大部分的Web应用系统都对用户访问进行了一定的权限控制措施（如URL控制、Cookie控制、Session控制等），一定条件上限制了RCE漏洞的利用。

  

这种情况下通过挖掘权限绕过漏洞，组合发现的RCE漏洞，就极有可能突破权限限制实现无条件RCE。因为权限控制方案的不同实现方案，因此权限绕过漏洞的挖掘也存在不同的观察角度。

  

本文主要是讲述常规Java Web开发情景下，由于对来源客户端请求URI的处理存在缺陷导致的URI权限绕过漏洞及防范。

  

**二、getRequestURI()带来的安全隐患**

  

getRequestURI()是Java Web request对象中用于处理请求URL的一个方法，该方法返回的是一个字符串，内容为整个访问的url的path内容，不带有query参数；当使用getRequestURI()作为URI处理函数，并且不使用Shiro等权限控制框架时，极有可能存在URL权限绕过漏洞。

  

Java Web开发中，如果不使用Shiro等框架进行权限控制，通常会使用Filter方案来进行URL鉴权。本部分将通过主流的Spring boot项目与Filter过滤方案来演示该方案下可能存在的权限绕过漏洞。

  

1.新建一个Spring boot项目，实现一个Filter 接口，使用@WebFilter注解urlPatterns=”/\*”拦截所有的请求，将访问/inter/路径开头的接口请求转发到/failed路由，禁止访问/inter/下的接口，其中Filter接口中定义了三个方法：

**init：**用于初始化Filter，在程序启动时被调用。  

**doFilter：**在客户端请求时被调用，该方法中还定义了Filter的主要处理逻辑，同时还负责将请求传递给下一个Filter。

**destroy：**在 Web 程序关闭时调用该方法，用于释放资源。

## 

由于开发对获取URL路径的函数getRequestURI()不熟悉，使用它进行鉴权比较，导致容易出现权限绕过的风险。

2、使用成熟的权限控制框架进行鉴权（如Spring Security）。

3、减少使用类似startsWith()、endsWith()进行判断字符路径。

4、对相关接口访问进行标准化处理，剔除不相关的元素，例如../,分隔符(;)后的内容等。

  

同样，开发常用的开发框架Spring配置xml，通常会对静态文件进行放权（不鉴权），这个也是容易导致出现权限绕过的点。这些都是开发日常上的疏忽导致的安全风险隐患。
