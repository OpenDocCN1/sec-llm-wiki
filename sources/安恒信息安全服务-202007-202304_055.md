**四、枚举LDAP树**

![](../Images/65f857053698af489e84cebce9a8c382.png)

  

在拿到密码之后，我们就可以通过这个凭据去枚举 LDAP 树（也就是 LDAP 文件目录结构），使用\`ldapsearch\`来完成，但如果你和我一样不了解\`LDAP\`的基本概念，可以先简单学习下：

**LDAP（Lightweight Directory Access Protocol）：**

即轻量级目录访问协议，是一个访问在线目录服务的协议，这些目录上可以存储各种类型的数据，是 Windows AD 域中最重要的协议之一，LDAP 服务器与 LDAP 应用共同构成了域控。另外，LDAP 的链接是这样的形式：ldap://servername/DN。

  

**DN（Distinguished Name）：**

可区别名称，其实就像域名一样，是一个唯一的可标记字符串，标记了 LDAP 协议上资源存放的位置，由 CN / OU / DC 组成。

  

**CN（Common Name）：**

通用名称，即用户名 / 服务器名。

  

**OU（Organizational Unit）：**

组织单元，即组织机构所属部门。

  

**DC（Domain Component）：**

域名组成部分。

**八、攻击流程总结**

![](../Images/65f857053698af489e84cebce9a8c382.png)

  

这台机器涉及到的知识点有点多，难度中等，风格偏\`CTF\`，突破点出现在了一些比较奇怪的地方，但算是很好玩的一次过程。

  

在端口扫描之后，首先是通过\`SMB\`探测得到敏感文件泄露，对敏感文件使用\`dnSpy\`反编译得到源码，在源码中发现\`LDAP\`链接中的\`password\`硬编码，拿到密码后使用\`ldapsearch\`枚举\`LDAP\`树通过\`WinRM\`拿到初始\`shell\`。

  

然后是提权，使用\`BloodHound\`进行分析，发现可以进行基于资源的约束委派，通过\`Powermad\`在域中创建一个新的对象\`FAKEPC\`，并设置\`DC\`的属性\`msDS-AllowedToActOnBehalfOfOtherIdentity\`，将\`FAKEPC\`的\`SPN\`添加进去，使其开启基于资源的约束委派；然后使用\`Rubeus\`生成\`FAKEPC\`的\`hash\`，用\`impacket\`系列的\`getST\`模拟\`DC\`上的\`Administrator\`用户请求自身的服务，最终拿到\`Administrator\`的\`TGT\`票据即\`Administrator.ccahe\`，将其导入到内容中，使用\`smbexec\`进行\`PTT\`攻击，最终成功通过\`wimexec\`登录系统拿下最高权限。

**九、加固建议**

![](../Images/65f857053698af489e84cebce9a8c382.png)

*   禁止使用共享的 AD 域账户，防止攻击者通过 SMB 共享探测内网敏感信息。
    
*   禁止在软件中对凭据进行硬编码。
    
*   禁止在 AD 域账户的属性中泄露密码。
    
*   禁止启动匿名访问的文件共享。
    
*   禁止普通用户向 AD 域中添加新的计算机对象或用户。
    
*   防火墙配置白名单IP，不向外开放88 / 135 / 139 / 389 / 445等端口，防止敏感信息泄露。
    
*   如非必要，请禁用WinRM，或使用防火墙策略对非白名单IP进行拦截。
    
*   开启杀软等反病毒软件或 EDR 设备，拦截黑客工具的上传与执行，防止攻击者的提权或横向行为。
    
*   加装 APT 设备，监测域内可疑流量以及主机用户敏感行为。
    
*   加装日志审计设备，开启 Windows 日志功能，在入侵发生后可以及时溯源。
