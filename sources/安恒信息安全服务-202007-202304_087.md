**前言**

  

我们都知道，编写的Java程序需要编译成\`.class\`文件，\`.class\`文件中描述了类的各种信息，但最终都需要加载到JVM虚拟机之后才能运行和使用。

  

**ClassLoader**

  

**ClassLoader的作用**

  

ClassLoader的主要作用就是加载Java类文件（class文件）。ClassLoader负责将Class的字节码形式转化为内存形式的Class对象，而这些字节码可以是来自磁盘文件的\`\*.class\`，也可以是来自\`jar\`包的\`\*.class\`，也可以是来自远程服务器提供的字节码。

  

因为有很多字节码加密及时就是依靠定制 ClassLoader来实现的，先使用工具对字节码文件进行加密，运行时使用定制的ClassLoader解密文件再加载这些解密后的字节码。并且每个Class对象内部都有一个ClassLoader字段来标识自己是由哪个ClassLoader加载的。

  

**ClassLoader加载方式**

  

一切的Java类都必须经过JVM加载后才能运行，但在JVM启动时，并不会一次性加载所有的class，而是选择动态加载，这样做的目的是为了防止一次性加载过多，导致内存压力增大。同时在程序运行的过程中也会遇到很多新类，此时就需要调用ClassLoader来加载这些新类，当加载完成之后就会将Class对象存在ClassLoader里面，这样再次遇到时就不用重新加载。

  

**三个重要的ClassLoader**

  

在JVM类加载器中最顶层的是\`Bootstrap ClassLoader（启动类加载器）\`、\`Extension ClassLoader（扩展类加载器）\`和\`App ClassLoader（系统类加载器）\`。

  

\`AppClassLoader\`是默认的类加载器，如果类加载时我们不指定类加载器的情况下，默认会使用\`AppClassLoader\`加载类。

  

ClassLoader类的核心方法有如下五个：

loadClass（加载指定的Java类）  

findClass（查找指定的Java类）

findLoadedClass（查找JVM已经加载过的类）

defineClass（定义一个Java类）

resolveClass（链接指定的Java类）

  

**Bootstrap ClassLoader**

  

**Bootstrap ClassLoader启动类加载器**

  

主要用于加载JDK核心类库，C++语言实现的，加载时的搜索路径是由\`sun.boot.class.path\`所指定的。

  

比如：\`%JRE\_HOME%\\jre\\lib\`下的\`rt.jar、resources.jar、charsets.jar\`等。

  

写一个测试Demo：

*   
*   
*   
*   
*   
*   
*   
*   

```
//Bootstrap ClassLoaderSystem.out.println(String.class.getClassLoader()); //输出null//获取扫描路径String paths =System.getProperty("sun.boot.class.path");String[] arr = paths.split(";");for (String path : arr){      System.out.println(path);}
```

运行结果如下：

![](../Images/dbca31a57a6e08f05424bbd5a8a6e6ad.png)

  

第一行输出了\`null\`，输出null就代表\`String\`类被\`Bootstrap ClassLoader\`加载，为什么会输出\`null\`呢？  

  

因为\`Bootstrap ClassLoader\`是C++语言实现的，是JVM的一部分并不是Java类库中的某个类，既然不是一个类就没办法在Java中指定一个引用指向它，所以获取被\`Bootstrap ClassLoader\`类加载器所加载的类的\`ClassLoader\`时候都会返回\`null\`。

  

通过输出的结果发现扫描路径都是在\`%JRE\_HOME%\\jre\\lib\\\`下。

  

另外还有三个配置：

Xbootclasspath:路径指定的路径会完全去掉jdk核心的搜索路径不可用。  

Xbootclasspath/a:路径指定的路径会在jdk核心类后搜索可用。

Xbootclasspath/p:路径指定的路径会在jdk核心类前搜索可用，不建议。

**Extension ClassLoader**

  

**Extension ClassLoader扩展类加载器**

  

扩展类加载器，加载 \`-Djava.ext.dirs\`选项指定的\*\*目录\*\*，比如：\`%JRE\_HOME%\\jre\\lib\\ext\`目录下的jar包和class文件。

  

注：如果配置自定义路径，会覆盖默认路径。

  

写一个测试Demo：

*   
*   
*   
*   
*   
*   
*   
*   

```
//Extension ClassLoaderSystem.out.println(DNSNameService.class.getClassLoader());//获取扫描路径String paths =System.getProperty("java.ext.dirs");String[] arr = paths.split(";");for (String path : arr){      System.out.println(path);}
```

** App ClassLoader**

  

**App ClassLoader系统类加载器**

  

它的搜索路径是由\`java.class.path(CLASSPATH)\`来指定，主要用来加载程序中的类文件，也就是自己编写的文件，及引用第三方库。

  

写一个测试Demo：

*   
*   
*   
*   
*   
*   
*   
*   

```
System.out.println(Demo.class.getClassLoader());System.out.println(Demo.class.getClassLoader().getParent());//获取扫描路径String paths =System.getProperty("java.class.path");String[] arr = paths.split(";");for (String path : arr){     System.out.println(path);}
```
