**四、**FastJson渗透总结****

  

1、反序列化创建的两种利用方式：一种基于rmi，一种基于ldap。  
2、RMI是一种行为，是指java远程方法调用。  
3、JNDI是一个接口，在这个接口下面会有很多种目录系统服务的实现，通过名称等去找到相关的对象，并把它下载到客户端来。  
4、ldap指轻量级目录访问协议。

  

存在java版本限制

基于rmi的利用方式：适用于jdk版本：JDK 6u132,JDK 7u131,JDK 8u21之前。在jdk8u122的时候，加入了反序列化白名单的机制，关闭了rmi远程加载代码。

  
基于ldap的利用方式：适用jdk版本：JDK 11.0.1、8u191、7u201、6u211之前。在jdk 8u191更新中，Oracle对LDAP向量设置了相同的限制，并发布了CVE-2018-3149，关闭了JNDI远程类加载。

  
可以看到ldap的利用范围要比rmi要大，实现情况下推荐使用ldap方法利用。

  

**1、fastjson 1.2.24 反序列化导致任意命令执行漏洞（CVE-2017-18349)**

  

**1、漏洞介绍**

  

1）漏洞原理

  

fastjson在解析json的过程中，支持使用autoType来实例化某一个具体的类，并调用该类set\\get方法来访问属性。通过查找代码中相关的方法，即可构造出一些恶意利用链。

  

通俗理解就是：漏洞是利用fastjson autotype在处理json对象的时候，未对@tyep字段进行安全验证，攻击者可以传入危险类，并调用危险类连接远程rmi主机，通过其中的恶意类执行代码，攻击者通过这种方式可以实现远程代码执行漏洞利用，获取服务器敏感信息，甚至可以利用此漏洞进一步对服务i去数据进行修改、增加、删除等操作，对服务器造成间距大影响。

**3、Fastjson 1.2.47远程命令执行漏洞**

  

**1、漏洞简介**

  

1）漏洞原理

Fastjson是阿里巴巴公司开源的一款json解析器，其性能优越，被广泛应用于各大厂商的java项目中。fastjson于1.2.24版本后增加反序列化白名单，而在1.2.48之前的版本中，攻击者可以利用特殊构造的json字符串绕过白名单检测，成功执行任意命令。

  

2）影响版本

Fastjson < 1.2.47

**1、fastjosn <= 1.2.24漏洞**

  

fastjson通过函数parse 或者parseObject 来完成字符串的反序列化操作，并且可以通过 @type 来指定反序化的类型。Fastjson V1.2.24可以通过 JdbcRowSetImpl 来实现来实现 JNDI 注入。

*   
*   
*   
*   
*   

```
{  "@type":"com.sun.rowset.JdbcRowSetImpl",  "dataSourceName":"ldap://localhost:1389/test",   "autoCommit":true}
```

\*左右滑动查看更多

  

在fastjson v1.2.25推出了AutoType机制，在 DefaultJSONParser 函数中增加了 checkAutoType 检查。checkAutoType 检查通过黑白名单实现的。在此之后的漏洞fastjson反序列化漏洞，基本上都是通过绕过AutoType机制，来实现漏洞利用的。
