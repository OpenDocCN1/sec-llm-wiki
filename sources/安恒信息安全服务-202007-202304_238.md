# 九维团队-红队(突破) | Vulhub DC系列渗透记录

本次将使用**kali**作为攻击机来进行对此靶机的攻击：

  

![](../Images/d658f535f4597dd450d78d8a80a3bace.png)

  

根据靶机**MAC**地址，找到IP地址。然后老规矩，上**nmap**看开启的端口及服务。

  

![](../Images/d30f7d292d259c5a9814291384e6a1cb.png)

  

看到**80端口**直接就去网站上看一下。

  

![](../Images/ecfb43a5b8f8b5e95444a5a5dba9417d.png)

  

发现是一个普普通通的登录框，为此我们尝试过**弱口令、万能密码**等手段均失败了，**F12**看一下前端源码。

  

![](../Images/56d0cd3b1749b0949026f047e710c20a.png)

  

发现这个网站是使用**Drupal 7**搭建的。

  

![](../Images/093c9a8155ceef2ccf7ab9c8902a1fbc.png)

  

上**MSF：**

  

![](../Images/0319a98adb1e3cce90799246e07f6350.png)

  

有选择符合版本并且最新的一个。一般来说，毕竟**越新越不容易被及时修复。**

  

![](../Images/724b9133cd46db9dbf7b2580fe2517d8.png)

  

可以看到只需提供一个**RHOSTS参数**即可。

  

![](../Images/2adc2aea505519ef3299854842e23319.png)

  

利用成功。发现**没有光标**，可通过用**py反弹一个shell**。

  

![](../Images/a397f4096b1e59c9abf806b2ba64720b.png)

  

发现了**flag1（这个靶机的目标是获取五个flag，并拿到root权限）**，意思大概是说注意这个CMS的config文件。继续百度，配置文件的位置。

  

![](../Images/abae2d0f19f18ea9b328d863bd0136c1.png)

  

打开文件：

  

![](../Images/47011ae556df2553d30ca84b7fd5016d.png)

  

![](../Images/2120c827577bde52f38514a3abe0cd4b.png)

  

发现了**flag2**，数据库的账号，密码，名称，类型等信息，这个**flag的意思是不建议使用字典爆破，尝试登陆数据库来发掘有用信息**。所以，首先登陆mysql。

  

![](../Images/a05b48b09113589f785225f6a9378134.png)

  

有一个**users表**很惹人注意，一般情况下，存放的是**用户信息**，来看一下有哪些字段，然后根据字段筛选一下。

  

![](../Images/02de29d5cb01fb51e58d981b50050d3f.png)

  

本以为这么简单就拿到权限，结束任务了，结果发现**密文不可逆，解密不出来**。**既然无法解密当前的密码，那么可以换一种思路：尝试替换当前的密码。**

  

![](../Images/16b17e922bdf8e3fa5e2eecaf8437267.png)

  

百度提供了方法，可以尝试一下。

  

![](../Images/db07405c2e402f557faf35a29085c729.png)

  

此时**admin**的密码已被替换为**123456。**再回到一开始的**web界面**登陆框中尝试登录。

  

![](../Images/58321178e0869c058bff989ea5054e61.png)

  

登录之后，发现了**flag3**，大意是让我们去**shadow**里面找东西。**而shadow和passwd最主要的区别就是，只有root权限才可以看shadow里面的东西。**所以可以说是在暗示我们进行**提权**。可以看到**flag3**里面**find**是大写的，好像在提示我们用**Find**来进行提权。

  

![](../Images/1b516a717388ab44305da17ae4a8d151.png)

  

查找**SUID**命令可执行文件。

  

![](../Images/5477d85cb7417e94c38ca43ca4bb32f7.png)

  

我们发现两个用户很显眼，一个是**flag4**，一个是**root**。Linux下万物皆文件，在**home**目录下用户的名字就是文件名字，先去看一下**flag4**的。

  

![](../Images/2a11585ff66d92486716dd81d7aff5ff.png)

  

flag4就是让我们**读取root下的最后一个flag**。

  

![](../Images/ca1042c64f9c63788921705f3fdc6eba.png)

  

最后和之前提权的步骤类似，在新建的文件夹下面操作即可。

  

![](../Images/8604aa1de015fd76b205184b8cd7f567.png)  
  
**防护和加固建议**  
  

‍‍‍‍‍‍1.Drupal历史上爆过多个漏洞，建议定期关注官方安全公告，安全公告网站（https://www.drupal.org/security），同时针对Web的漏洞攻击，建议部署WAF产品拦截攻击。

  
‍‍2.建议root用户远程登录系统，操作系统在上线前做安全基线扫描和必要的安全加固配置，同时针对主机环境部署EDR解决方案，及时发现、告警、或拦截主机上的攻击行为。‍

‍‍

  
3.数据库端口做访问控制，只允许指定源IP访问，同时针对数据库访问进行操作事件审核、可疑查询审核等，确及时发现数据库访问异常。‍‍‍‍‍
