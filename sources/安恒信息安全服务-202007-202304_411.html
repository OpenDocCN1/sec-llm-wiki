摘要

数据泄露的成本与检测到泄露的时间息息相关，也和消除它所消耗的时间有关。根据波尼蒙研究所的一项研究，2019年发现数据泄露的时间成本平均为206天（Ponemon Institute，2019）。减少检测时间范围对于减少消除违规的总体时间表以及与之相关的成本至关重要。随着攻击者不断创造新的方式对企业组织进行破坏，预防性安全措施是必不可少，但还远远不够。企业组织不应该仅仅假设自己会受到危害，而应该假设自己已经受到危害，这样才能对安全防护足够重视。


找到并消除这些已经存在的攻击行为可能很困难。为了发现现有的攻击行为，组织需要进行威胁狩猎，以发现攻击者是否存在于现有检测技术以前未发现的环境中（Gunter & Seitz，2018）。本文着眼于PowerShell工具索伦之眼的视角，该工具可用于识别威胁指标（IOC）以及用于Windows环境中使用数据堆栈进行异常检测的威胁狩猎。它在两种情况下都测试了其检测IOC的能力，一种是在模拟攻击中，另一种是在引入恶意软件之后。


1、引言

检测、遏制和消除事件所花费的时间直接影响其财务成本。根据IBM和波尼蒙研究所进行的一项研究，2019年识别泄露的平均时间为206天，其中包含73天的时间来进行遏制，从发现到根除共计279天，平均成本为3.92百万美元(Ponemon Institute，2019）。与2018年平均生命周期为266天相比增加了4.9％。这表明，尽管防御能力和技术在进步，但对手的战术和程序也在进步。


最近的活动表明随着攻击者不断发展。在针对终端安全产品的领先提供商Mandiant的2018年10月至2019年9月的时间范围内的研究中，研究人员研究了成千上万个由186个独特家族组成的恶意软件样本。在这些恶意家族中，有41%的恶意软件样本之前从未被研究小组发现。此外，有46％的样本带有后门程序，而70％的样本则作为可移植的可执行文件引入（FireEye，2020）。即使恶意软件避免了最初的检测，它也需要在系统上进行更改以建立持久性，并经常留下文件和其他证据。如果分析人员知道要查找的内容，则可以检测到这些文件和更改，并帮助识别恶意活动。


为了帮助组织识别、评估、监视和应对网络威胁，他们可以参与网络威胁信息共享。威胁信息是“可以帮助组织保护自身免受威胁或检测行为者活动的任何信息（Johnson，Badger，Waltermire，Snyder和＆Skorupka，2016年）。威胁信息包括但不限于战术、技术和程序（TTP）、安全告警、威胁情报报告和妥协指标（IOC）。共享威胁信息有很多好处，可以让企业组织在遭受攻击前做好防御准备。


IOC是入侵后取证的的指标，表明潜在的妥协或至少是可疑活动（Mertens，2018年）为更高级的威胁狩猎奠定了基础。它们可以包括任意数量的指示符，例如：IP地址、端口、DNS查询、服务、进程、文件、启动项等等。通过在威胁信息共享平台中共享这些IOC，


组织可以查询其网络以查找过去已经发生或当前正在发生的潜在危害。允许识别，遏制和消除这些折中办法，将有助于减少平均时间范围和破坏成本。


数据库和IOC提要中有成千上万的指标，但是并不是所有指标都一样，有些指标在面对攻击时比其他指标更有价值（Bianco，2013年）。根据戴维·比安科（David Bianco）的痛苦金字塔，诸如哈希值、IP地址和域名之类的指标很容易被攻击者更改，从而使其价值不及其他指标。因工具和TTP的更改，也就更具挑战性，更难识别。金字塔防御者的作战能力越高，对手越难避免被发现。一旦进入了TTP级别，攻击者就必须学习新的行为并重塑或者直接放弃；这是组织应努力实现的水平（Bianco，2013年）。


图1 痛苦金字塔(Bianco，2013)

火眼已发布了有关几个高级持久威胁（APT）组的报告，重点介绍了他们观察到的指标，其中包括文件哈希和IP以及工具和TTP。关于APT 41- Double Dragon的最新报告列出了71个易于检测的IOC以及对其使用的TTP的深入研究（FireEye，2019）。随着组织的威胁狩猎工作日趋成熟，其重点从金字塔的底部转移到顶部。但是，如果无法识别低级别的指标，将无法在更高级别上进行操作。


在SANS研究所的威胁狩猎报告中，确定了四个级别的威胁狩猎金字塔。IOC构成前两个层次，首先是前面讨论过的一般 IOC，其次是精选 IOC，这是根据环境量身定制的指标。


图2 SANS 威胁猎杀成熟度金字塔(Fuchs，2020)


金字塔的第三层，异常检测，取决于识别环境中的异常活动。但是，要使组织识别异常，他们必须首先能够确定正常现象并具有基准配置。基准不仅包括软件，还包括服务，启动程序，正在运行的进程等等。在单个工作站上检测到新的应用程序可能会引起关注，同样，发现新的启动项或服务也应进一步分析。异常不能保证攻击者的存在。但是，基线之外的任何异常都需要考虑和适当分析。


收集确定环境中正常情况和异常情况所需的数据可能是一个挑战。OSQuery可作为参考选项，“是一个将操作系统公开为高性能数据库的框架(OSQuery n.d.)。”它是一个强大的工具，可以提供有价值的分析。然而，为了在整个企业中释放 OSQuery的真正潜力，它需要与其他系统(如安全信息和事件管理(Security Information and Event Management，SIEM)系统)相结合，并且将数据转换为可操作的情报可能是复杂的(Picotte，2018年)。


另一个选择，索伦之眼是基于PowerShell的工具，旨在提供对Windows环境的洞察，以识别异常并搜索IOC。它易于使用且易于定制化，允许组织根据需要对其进行调整，并寻找对他们最有帮助的数据。它通过从客户终端收集多个数据并集体分析结果来工作。这个工具可以在个案基础上使用，也可以每天运行，创建数据历史记录，以更好地识别新的异常活动。这项研究将评估该工具的有效性，以确定在模拟攻击活动期间以及在测试环境中引入未知恶意软件样本后所做的更改。


2、研究方法

这项研究将测试这些工具的有效性，以揭示潜在的改变，这可能表明恶意软件的存在或正在进行或已完成的攻击活动。模拟攻击将包括初始执行、建立持久性、横向移动以及命令和控制点。在完成整个攻击过程后，工具将对比攻击后的结果与攻击前的结果，以确定是否有恶意行为发生。

测试环境包括以下内容：

· 三个Windows 10客户端工作站

· 一个Windows Server 2019（域控制器和文件服务器）

·一台带有Metasploit的Kali Linux计算机


这项研究的重点是确定潜在的IOC，而不是绕过安全控制点。因此，在测试期间，诸如 Windows Defender 和 Windows 防火墙之类的控件将被禁用。最初的危害发生在一个域管理员帐户下，模拟一个管理员从一个被入侵的网站下载并安装一个 Portable Executable 文件。


由于恶意软件样本的行为是未知的，对未知的、活动的恶意软件的第二次测试将提供一个盲测。

最后阶段与攻击本身无关。相反，使用该工具通过搜索已发现的 IOC 来识别以前未检测到的危害。能够搜索以前的事件，有利于保持结果历史记录，使新确定的指标能够通过以往的结果进行审查，有可能发现以前未发现的事件。


2.2恶意软件样本

测试的第二部分将有效的恶意软件引入到单个工作站的环境中。然后，使用恶意软件识别工具确定其有效存在。使用的恶意软件样本来自http://www.tekdefense.com，并且采取了适当的措施来确保恶意软件不会离开测试环境。这个测试模拟了恶意软件路过式下载; 在测试开始时恶意软件的行为是未知的。


2.3索伦之眼工具概述

索伦之眼是一个由三个 PowerShell 脚本组成，用于收集和分析来自 Windows 系统的数据。使用该工具有两种主要方式。第一种方法是让它每天运行，创建一个记录，将最近的发现与以前的结果进行比较，通过识别新的活动来搜索异常。另一种方法是，通过搜索 IOC 和使用数据叠加来识别异常，将其部署为一次性能力，从整个企业收集数据，以帮助遏制和消除特定事件。这项研究将试图通过比较以前的结果以及数据叠加来识别环境中的一次性变化。


该工具收集的数据集属于下面列表中的类。这些类都保存在单独的 CSV 文件中，稍后进行总结，以便进行增强的查询。PowerShell 的功能允许根据需要调整查询，以满足组织的需要，并且只收集相关数据。并非所有类别都是为了查找威胁而设计的，而更多的是为了进行遵从性检查，比如安装了 Windows 更新。

2.3.1收集脚本

该脚本在每个端点上运行，以收集上面提到的数据点。它使用 Windows 管理规范和注册表查询来收集大部分数据并保存到指定的共享目录中。理想情况下，此脚本使用计划任务或其他自动化方式每天运行，以提供用查找新添加内容的结果历史记录。txt文件在所有三个脚本之间共享变量，避免了单独编辑它们的需要，并确保了一致性。


2.3.2摘要脚本

在所有系统都运行了收集脚本之后，将运行汇总脚本。这个脚本有三个函数; 首先，它总结收集脚本所收集的结果，并将它们组合到 Summary CSV 文件中。第二个功能是将最近的结果与最近的以前的结果进行比较，将所有新的发现输出到 excel 表格中以便于分析。第三个功能是进行维护，根据 variables.txt 文件中指定的时间框架删除单个系统数据和汇总数据。


摘要文件保存的时间越长，搜索过去调查结果和找到以前遗漏的指标的能力就越强。此历史记录还可以帮助识别正常行为，如正在运行的进程或已建立的网络连接。索伦之眼可以结合多天的结果来识别不寻常的活动，比如显示过去七天内运行的所有进程，或者显示过去30天内检测到的新本地帐户。


2.3.3用户界面脚本

用户界面脚本正是索伦之眼的关键，用于查询收集的数据，以便使用一系列菜单和预定义的查询进行进一步分析。菜单和查询方法允许对 PowerShell 脚本知之甚少的人有效地使用该工具。相比之下，那些掌握 PowerShell 脚本编制知识的人可以轻松地添加其他查询以获得他们想要的结果。图5显示了这个脚本的主菜单，以及本地管理员帐户子菜单，可以通过从主菜单中输入“1”来访问它。


图5索伦之眼主菜单和本地管理员帐户菜单


随着数据保存在 CSV 文件中，还有许多其他的选项可以访问数据，比如额外的 PowerShell 脚本或者 Microsoft Excel 之类的程序。但是，根据要处理的数据量，有些查询可能需要相当长的时间来处理。例如，在包含2,400个工作站的环境中搜索过去30天的所有网络连接可能需要一个多小时，而将查询限制为最新的结果则需要几分钟。执行查询的系统的可用资源也极大地影响了时效。默认情况下，结果显示在交互式网格视图表中。这些结果可以进一步过滤和排序，或复制到另一个应用程序，如 Excel。
