# 通过机器学习应对SDLC

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzAwMDgyNTQzMQ==&mid=2247485204&idx=1&sn=951c20b3e539f7acddbb287d231a22f0&chksm=9ae2462cad95cf3a8492868ad93130f1444bd1f128921db464a624fb728489c6fd9758b57445&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzAwMDgyNTQzMQ==&mid=2247485204&idx=1&sn=951c20b3e539f7acddbb287d231a22f0&chksm=9ae2462cad95cf3a8492868ad93130f1444bd1f128921db464a624fb728489c6fd9758b57445&scene=27#wechat_redirect)

企业的数字化转型继续表明，相对性和竞争力与开发和利用软件的能力直接相关。作为微软的首席执行官， Satya Nadella常说：“每个公司现在都是软件公司。”

  

软件缺陷会导致意外数据泄漏，破坏或危害公共安全或环境，这不仅代价高昂，而且可能对公司的未来构成威胁。因此，软件及其背后的开发过程的完整性和安全性已成为每个组织成功的重要组成部分。这是企业CISO与DevOps领导者越来越多地合作，并警惕地更新安全开发生命周期（SDLC）流程以采用新的机器学习（ML）方法的主要原因。

  

自动化的应用程序安全测试是现代SDLC的关键组成部分，可以相对容易和低成本的发现许多错误和潜在的安全漏洞。应用程序安全测试包含广泛的互补技术和工具，例如静态应用程序安全测试（SAST），动态应用程序安全测试（DAST），交互式应用程序安全测试（IAST）和运行时应用程序自我保护（RASP）。当前的最佳实践安全建议是使用多样化工具，从字母拼写方式到机械地标记错误和漏洞，以减轻未解决的漏洞对生产系统造成的影响。

  

这种方法带来的麻烦后果是，识别出的软件缺陷数量众多，开发团队有能力证实缺陷的风险（以及随后的优先级），于是很多组织通过漏洞悬赏计划项目对漏洞研究人员提交的研究报告进行分类及清单。在这方面做的更成熟的比如，SDLC机制运转良好的企业也要对应用程序安全性测试工作流程中产生的错误进行自动分类和优先级排序，微软47,000名开发人员每月会产生近30,000个漏洞。

  

为了更高效且大规模标记漏洞并确定其优先级，新的机器学习方法是正在推进应用的方式，其结果也让人振奋。以微软为例，大数据专家开发了一种流程和机器学习模型，可以以99％的正确率区分安全性和非安全性漏洞，并以97％的准确率识别关键的高优先级安全性漏洞。

  

对于自动化应用程序安全测试设备和SDLC流程之外的缺陷漏洞（例如客户或研究人员报告的错误），在通过提交的丰富内容来训练机器学习分类器系统时，不同困难可能包括带有密码的报告，个人身份信息（PII），或其他类型的敏感数据。最近的出版物“仅基于报告标题和繁杂的数据识别安全漏洞报告”指出，即使保留机密信息并且仅使用错误报告的标题，经过适当培训的机器学习分类器也可以非常准确。

  

企业CISO应及时了解该领域的创新。据Coralogix称，普通开发人员每千行代码会创建70个错误，而修复一个错误所花的时间比编写一行代码要长30倍。

  

通过从越来越多的由自动应用程序测试工具和客户报告的缺陷所产生的大量漏洞中正确识别安全漏洞，企业可以适当地确定其开发团队的修复工作的优先级，并进一步降低对其组织，客户和合作伙伴的应用程序风险。

  

尽管在培训机器学习分类器系统以分类安全性漏洞和改进现代SDLC中封装的流程方面正在进行大量研究和创新，但是要组织购买现成的集成解决方案还需要一段时间。

  

企业CISO和DevOps安全领导者们应该对新的研究材料以及最新技术保持警觉，并督促其自动化的应用软件测试工具供应商改进其解决方案，以智能地、准确地标记安全漏洞，而不是当做日常琐事去执行。
