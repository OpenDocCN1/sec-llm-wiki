# 捍卫你的预算：如何证明网络安全投资的投资回报率

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzAwMDgyNTQzMQ==&mid=2247485059&idx=1&sn=bc2c22668516aa37545ffbf4acda7b46&chksm=9ae247bbad95cead4f14074cda60a7ce1fd07d5f5afc371129603152e3e6ef0e7194bfa77089&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzAwMDgyNTQzMQ==&mid=2247485059&idx=1&sn=bc2c22668516aa37545ffbf4acda7b46&chksm=9ae247bbad95cead4f14074cda60a7ce1fd07d5f5afc371129603152e3e6ef0e7194bfa77089&scene=27#wechat_redirect)

对于那些从事网络安全工作的人来说，毫无疑问，“投资回报率”（ROI：Return on Investment）无疑是一个尴尬的话题。我们使用的解决方案有回报，但通常只有在恶意软件攻击期间或阻止数据泄露后才能看到。

 

像测试降落伞或评估新的安全带一样，进行现场演示以显示解决方案的功能对于任何安全专业人员来说都不是一件容易的事。

  

以往证明安全投资的投资回报还不是一个可轻易解决的问题。在我们已经进入的远程办公这个新时代之前，我们主要靠传统纸媒或新闻网页的头条新闻获取到最新有关漏洞、恶意软件及勒索软件的信息，利用这些信息促使企业部署并拥有了一定程度的针对性防护能力。

  

*   **谁参与进来？**
    

  

领导层仍然必须以安全至上的心态为导向，但预算仍在不断复审和收紧。在远程办公常态化之前确实如此，但现在更是如此，因为我们很快将需要对工作场所进行升级防护。

  

CISO和CTO制定安全项目决策，定期开会并讨论如何平衡风险和分配预算，而风险通常具有足够的额外权重以获得批准。这正在改变；安全仍然是必不可少的，但是企业现在希望在整个公司的不同级别来评估和应用风险。例如，拥有托管产品数据表的面向公众的Web服务器所需要的安全性比托管即将发布的产品版本的开发人员代码的服务器要少。

  

CISO和CIO之间的伙伴关系对于确保将正确级别的网络安全应用于业务至关重要。对于CISO而言，这仍然意味着不同的想法。仅显示保护统计信息或可以阻止的网络钓鱼电子邮件的数量还不够。企业领导者不仅想知道安全性如何使他们保持安全，还想知道如何使他们的业务效率更高。

  

*   **答案显而易见**
    

  

安全需要成为一种可衡量的，以结果为导向的可交付成果，而不仅仅是在防止违规行为之后得到证明的东西。为了实现这一目标，不仅需要评估安全信息。需要使用来自设备、网络和外部源的数据将安全交付物改进为能够证明业务价值并因此证明ROI的内容。

  

幸运的是，在某些方面我们可以集中精力实现对安全性ROI的更通畅的观察。尽管没有完美的解决方案来应对这一挑战，但如果将风险与后果结合起来，则可以更轻松地建立业务对话来支持未来的投资。

  

开发投资回报率模型需要花费时间-笔者建议是着重于一个简单的安全项目，当证明成功时，该项目将为企业带来高价值。证明有可能获得回报，将有助于团队为更复杂的解决方案开发模型。

  

*   **通过安全意识展示投资回报率**
    

  

防范意识对于任何组织都至关重要，因为勒索软件、数据盗窃及其他攻击恰恰是利用了脆弱的防范意识。商业电子邮件泄露（BEC）呈上升趋势，据报告显示，仅在美国，2019年网络犯罪损失就可能造成高达50％的损失。

  

值得注意的是，安全软件不能总是阻止BEC。这种攻击形式更灵活且目标更强，这意味着更多的攻击者将成功找到通往用户收件箱的途径。根据JAMA Network Open的2019年报告，平均仍有35％的用户仍会单击网络钓鱼链接。

  

这些统计数据不言而喻–安全意识培训应该成为任何安全计划的组成部分，并可以减少未来的BEC风险。但是，我们如何为安全支出辩护呢？

  

进行渗透测试，针对企业内部用户以企业电子邮件进行渗透测试，让他们单击可能包含恶意软件的链接。

  

对于每1,000个用户，大约35％的用户将单击链接。这看似很高，但是公司用户通常会在工作中受到防护，这会使他们更容易受到攻击。

  

通过这个测试，最终成功诱骗了350个用户。如果这是一个真实的广告系列，那么这些用户可能会使企业为每次点击支付的损失高达75,000美元。每位用户仅需花费几美元，定期进行的在线安全意识培训就非常值得。

  

培训是一个简单的例子。可以开发体现ROI的其他IT项目包括端点安全，如引入加密技术或更好地保护Wi-Fi身份验证。

  

笔者的建议是在每个人都更好地理解安全ROI流程之前，避免进行更复杂的项目，例如防火墙升级。仅提供技术指标或可交付成果，会使安全团队难以清楚地传达业务价值，从而导致项目搁置甚至完全取消。

  

*   **ROI秘籍**
    

  

简而言之，这个可以实现。但是这全取决于业务风险偏好，并建立了足够的数字来证明其成熟度，可以为将来提供帮助。以下是提高安全性ROI的建议：

  

在指标的定义要达成一致，关注基于风险安全性KPI，便于提供可用于开发项目ROI的数据。

  

了解企业如何应对风险。每项新变更都可能带来新的威胁，因此需要明确的信息来平衡风险与创新速度和客户体验之间的平衡。

  

风险不仅仅是安全团队，而更是业务的责任， 确保有针对不同业务负责人的安全KPI，而不仅仅是CISO或CIO。

  

上面的观点并不详尽，而是一个很好的起点。另一个关键问题是，在整个企业中建立安全性KPI意味着企业领导者都将全力投资于对任何项目做出最佳决策。

  

虽然建立和了解用于安全性的ROI似乎具有挑战性，但成功之路始于小而明确的项目。不要期望100％的准确性-随着更多数据改善模型，随着时间的推移，准确性会随着时间的推移而变化，这反过来又提供了向企业展示安全性ROI的能力。
