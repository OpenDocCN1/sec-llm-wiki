GitHub作为全球最大最受欢迎的社交编程及代码托管网站，每天被成千上万的人使用着，然而由于部分研发人员安全意识薄弱，未经公司许可将敏感源代码上传到Github，使企业大量信息泄露，最终使企业蒙受巨大损失。为了保护公司代码安全，宜人贷安全部在进行安全培训的同时，研发了属于自己的安全工具——Gitscan巡检。




Github巡检主要根据关键字对Github的公共代码库进行搜索，并且支持白名单、定时任务、邮件通知等。该工具虽然功能简单，但是“五脏俱全”，囊括了进程守护、任务调度、反向代理等多项服务和功能，真正的小而全，在运行中做到了真正的高效和自动化。

其中Gunicorn作为运行Flask的容器，Supervisor作为Gunicorn的进程守护，则用于容器运行过程中意外终止之后的自动重启。而对于apscheduler用于定时任务启动爬虫进行爬取，同时支持Linux的cron触发器。爬虫在爬取完成后会将相关结果发送到相关配置邮箱中，支持白名单过滤、时间过滤等，并最后将结果存入数据库之中。


在网络操作（访问、爬虫等）的过程中，我们加入了协程框架Gevent，从而使得爬虫在爬取过程中更加高效，采用倒序+正序排列的爬取方式尽可能保证最大数量的爬取。同时在配置到服务器之中的采用的是Nginx的反向代理。


多线程爬虫模块工作流程如下：

首先会获取代理IP池并检测IP是否可用，加入到可用代理IP池供爬取调用，在爬取的过程中采用了自动控制速度，当检测到Github Response Code 为429时会通过降低速度以及切换IP等重试方法，保证爬取到每个URL请求，通过BeautifulSoup进行解析，判断是否做入库更新操作。


项目上线之后第一天的项目是最多的，高达几百个，但已处理过的项目如果没有更新，是不会再次进行爬取的，因此后期会逐渐稳定在几个左右。所以每天泡茶等待的时候，只花要再花5分钟的时间就可以搞定。


技术进阶


项目在这之后其实基本完成了，但是今天我们不从成本和收益的角度，而单单从技术的角度来看，这工具能不能更自动化一些。

答案是可以的！以下为小编的一些后续的思考，之后有时间可能会加上这些功能吧。


方式一：根据函数命名规范


众所周知，为了代码的可维护性，各个公司都会有一套自己的命名规范。那么以此为切入点，我们可以把公司自己的函数命名规范存入到数据库之中，之后在爬取之后，把Github代码之中的函数提取出来和公司的函数命名规范进行比对（机器学习算法在这里就比较好用了）。通过设置一个阈值范围，快速筛选出来高风险项目。


方式二：特征过滤


有的公司可能没有函数命名规范相关的文档，那怎么办？好办，那么我们的目标就要改改，争取去掉根本没用的项目。大家知道GitHub鱼龙混杂，什么项目都有，那么我们优先去掉肯定不是的项目也是可以大大减少我们的工作量。比如一些爬虫类、域名收集类的项目很容易可以靠一些简单规则去除的。


方式三：混合式


方式一+方式二，两者结合起来。奏是这样！
