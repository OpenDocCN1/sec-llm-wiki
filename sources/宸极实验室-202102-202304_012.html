0x00 前言

在之前的攻防演练中遇到过几次SOAP注入的场景，本文将搭建环境对该漏洞进行简单的分析学习。

0x01 Web Service 简介

在学习SOAP注入之前，先来介绍一下Web Service，Web Service是一个平台独立的、低耦合的、自包含的、基于可编程的Web的应用程序，可使用开放的XML（标准通用标记语言下的一个子集）标准来描述、发布、发现、协调和配置这些应用程序，用于开发分布式的交互操作的应用程序。Web Service是一种远程调用技术，实质就是一个程序向外界暴露出了一个可通过Web调用的API，如果对传入的参数不做限制就有可能导致SQL注入等漏洞的产生。

Web Service有三要素，分别为soap，wsdl和uddl。

  • uddl用于提供发布和查询Web Service方法；

  • wsdl是Web Service服务描述语言，用于web服务说明，它是一个xml文档，用于说明一组soap消息如何访问接口；

  • soap是一种简单的基于 XML的协议，它使应用程序通过HTTP来交换信息，用于分布式环境的基于信息交换的同行协议，描述传递信息的格式和规范，它可以用于连接web服务和客户端之间的接口，是一个可以在不同操作系统上运行的不同语言编写的程序之间的传输通信协议，格式为XML。

0x02 SOAP版本区分

SOAP协议分为SOAP 1.1和SOAP 1.2两个版本，主要区别如下。

2.1 请求头不同

SOAP 1.1存在SOAPAction的请求头
SOAP 1.2不存在SOAPAction的请求头

SOAP1.1的请求头：

POST /WSShakespeare.asmx HTTP/1.1Host: www.xxx.comContent-Type: text/xml; charset=utf-8Content-Length: lengthSOAPAction: "http://xmlme.com/WebServices/GetSpeech"
SOAP1.2的请求头：
POST /WSShakespeare.asmx HTTP/1.1Host: www.xxx.comContent-Type: application/soap+xml; charset=utf-8Content-Length: length
2.2 命名空间不同
SOAP1.1的命令空间：
xmlns:soap=“http://schemas.xmlsoap.org/soap/envelope/“

SOAP1.2的命令空间：

xmlns:soap="http://www.w3.org/2003/05/soap-envelope“
2.3 请求方式不同
SOAP1.1为content-Type:text/xm;charset=UTF-8
SOAP1.2为content-Type:application/soap+xml;charset=UTF-8
0x03 SOAP SQL 注入
3.1 注入原理
SOAP SQL注入就是攻击者修改发送的SOAP消息参数，达到发起SQL注入的效果，在服务提供端，SOAP信息被解析，参数在访问数据库前没有被检测，导致执行SQL语句，造成SQL注入。
3.2 靶场环境测试
靶场下载地址：https://www.vulnhub.com/entry/csharp-vulnsoap,135/
环境默认使用桥接模式进行连接，直接访问虚拟机的ip地址即可访问到漏洞环境。
该靶场有4个功能点，AddUser为添加用户ListUsers为列举用户，GetUser为获取用户，DeleteUser为删除用户。
发现在GetUser功能处username处为string此处传入为字符串，可能存在注入漏洞。
也可以通过查看wsdl去分析。
查看GetUser的操作活动发现，GetUserHttpGetIn意思是获取用户的输入。
下面使用简单的测试payload进行测试是否存在注入漏洞。
'or 1=1 ---qqq'or 1=2 ---qqq
📢📢由于下班回到家，网络环境发生了变化，靶场ip发生改变。
访问http://192.168.0.103/Vulnerable.asmx?wsdl并使用burp抓取数据包，右击选择使用WSDL插件（该插件BAPP Store里直接安装）。
复制并保存请求数据包为txt格式，利用sqlmap测试，可成功利用注入获取数据。
3.3 漏洞挖掘
通常而言通过搜索特定后缀去找webservice地址，asmx是webservice服务程序的后缀名，可以使用google语法搜索，
inurl:asmx?wsdlinurl:.php?wsdl inurl:.ashx?wsdl
通过去查找webservice的服务描述的xml文档来找寻可能的注入点。
由于真实环境的wsdl内的信息过于繁杂，我们可以借助工具SoapUI进行简单分析，判断是否存在注入点。
SoapUI：https://www.soapui.org/downloads/latest-release/
