0x00 前言

之前分享过一篇 SMC 动态代码加密技术的文章。在那篇文章里，作者实现了一种方法，设置了一个特定代码段，然后将整个特定代码段进行加密操作，从而实现了该项技术，但是这种技术，缺点就是，设置的代码段容易被破解者重点关注，从而轻易的识别出程序使用 SMC 技术。

这篇文章再分享一种 SMC 动态代码加密技术的实现方式。

0x01 函数体加密

既然设立一个特殊代码段会被轻易识别出，那么我们是不是可以不使用对代码段加密的方式，取而代之使用对整个函数进行加密的方式呢？

对整个函数体进行加密的方式，需要解决的问题其实就是，函数体从哪里开始以及函数体在哪里结束。一旦我们获取到上述两个地址，我们就可以实现加密和解密运行操作。

在 C/C++ 语言中有一个特性，即函数名代表函数的开始地址，所以根据函数名即可得到函数体在内存中的位置，剩下的问题就是怎么确定函数的结束地址，也就是要找到函数体的最后一条指令的地址。但是目前为止没有很好的方法可以 100% 完美获取到函数体最后一条指令地址，但是我们可以得到于该函数体相邻的下一个函数体的起始位置，从而计算出两个函数开始地址的一个差值，这个差值就可大致认为是函数代码块的大小。

这个差值就可大致认为是函数代码块的大小。但是这种方式存在不完美性，即任何一款编译器都无法保证两个 C/C++ 代码相邻的函数在最终生成的机器代码中也是相邻的。还有就是这种方式对函数体代码约束较多，比如函数体中最好不使用 longjmp() 之类的控制跳转的函数。也尽量不使用 switch...case 语句，因为该语句会让编译器产生机器代码不连续的情况。

虽然对函数体加密的方式会产生上述不完美的现象，但是如果我们避免使用上述结构体，可以避免出现问题，所以该种方式也被大量采用。

下面使用一个简单的实例代码看一看具体效果，使用 VS2019 编译一个项目，然后设置一个简单的 +1 输出的函数 Xorprint ，后面紧跟设置一个空的函数体。

void NullFun1(){    char tmp[] = "++++++++++++++++";    for (int i = 0; i < 10; i++)    {        printf("%c", (int)tmp[i]);    }}
void Xorprint(){    char tmp[] = "GdkknVnqkc";    for (int i = 0; i < 10; i++)    {        printf("%c", (int)tmp[i] + 1);    }}
void NullFun2(){    char tmp[] = "---------------";    for (int i = 0; i < 10; i++)    {        printf("%c", (int)tmp[i]);    }}
我们将上述代码编译一下，看一下汇编指令是否是连续的。
如果不做任何设置，直接使用 VS2019 进行编译，肯定不行，但是经过作者两天的学习（别问为啥学这么久，毕竟我要做项目...）发现可以通过链接器优化选项，使用 /ORDER 指定函数编译顺序。
最终编译出的文件成功按照想要顺序排序了。
解决了这个问题，接下来就是获取 Xorprint 函数体大小。
int nFuncSize = ((char *)NullFun2 - (char *)Xorprint);
编译运行一下试试看。
使用反编译软件看一下实际的函数大小，发现是正确的，这就解决了计算函数体大小的问题。
这样我们所有的问题都已经解决了，函数体开始地址，函数体大小全部得到，接下来就是自身在运行时先对该段代码进行自解密然后运行即可。
int main(){    int nFuncSize = ((char*)NullFun2 - (char*)Xorprint);    char* pFuncAddr = (char*)Xorprint;    for (int i = 0; i < nFuncSize; i++)    {        *(pFuncAddr + i) = *(pFuncAddr + i) ^ 0x21;    }    Xorprint();    return 0;}
抱歉报错了，什么原因导致的呢，后来我在动态调试的时候发现，产生了两个错误，第一个原因 VS debug 版本会产生很多调试代码，在某处调试代码处出现了崩溃现象，具体因为什么我没研究，转成 Release 模式把这个错误过了。第二个原因是不是忘了上篇文章说的，因为涉及自更改代码，所以必须要对段内容有写权限？所以赋予 .text 段可写属性即可。
#pragma comment(linker, "/SECTION:.text,ERW")
至此，我们已经通过修改函数体的方式将 SMC技术 实现了，这种方式不会产生可疑代码段，具有相对较好隐蔽性。
可能有的读者会问，那我们怎么去把加密之后的函数体内容放进去呢，因为只有加密后的函数体在运行时进行自解密才是正确逻辑。
这里笔者是将未加密的函数体编译出来之后，把原本内容拷贝出来之后，使用工具将 hex 数据转换之后再替换进去源程序进行实现的。当然大家可以写另外一个程序，用来对源程序进行加密。笔者偷个懒（其实是因为已经超过文章提交deadline了，能省就省了吧）。
