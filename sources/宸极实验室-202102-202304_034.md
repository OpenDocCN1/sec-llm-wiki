## 0x00 前言

`Yii2` 是一个高性能，基于组件的开源 `PHP` 框架，用于快速开发现代 `Web` 应用程序。与其他 `PHP` 框架类似，`Yii2` 实现了 `MVC (Model-View-Controller)` 设计模式并基于该模式组织代码。

由于其花样繁多的反序列化漏洞，近年来常见于各大`CTF`比赛和攻防演练中。

`Yii Framework 2` 在`2020年9月14日`发布的更新日志中公布了一个反序列化远程命令执行漏洞，编号为`CVE-2020-15148`。学习之旅，就从这里开始。

![](../Images/c7069b7a3cfd72c56c38ca4362fc22eb.png)

## 0x01 前期准备

`Yii2` 是基于`MVC`架构的 `PHP` 框架，所以要学习它的反序列化漏洞，需要对`PHP`基础、反序列化基础、类与对象以及命名空间的概念有所了解。

## 0x02 漏洞分析及复现

分析反序列化漏洞时，需要找到漏洞起点，可以从官方的更新日志中找到线索。  
*https://github.com/yiisoft/yii2/blob/master/framework/CHANGELOG.md*

从该日志中可以发现，`CVE-2020-15148`漏洞的影响文件是`yii2/db/BatchQueryResult.php`。

![](../Images/bd9c1fdd52228ceae1263a45f8bd8723.png)

之后我们可以从`github`的`commit`中找到对应日期的版本，进行对比分析。

![](../Images/7d059e9dc9a945ca132da9d7a4fcd9cd.png)

选择`tag`是`2.0.38`之后，可发现：

![](../Images/07b09d3def2fc4a69ac59368c6262da4.png)

*https://github.com/yiisoft/yii2/commit/9abccb96d7c5ddb569f92d1a748f50ee9b3e2b99?diff=split*

在该版本的更新中，在`yii\db\BatchQueryResult`类中添加了一个`__wakeup()`魔术方法，禁止了该类的反序列化，这无疑也佐证了我们的判断。

![](../Images/84faf57c0df6d5fdc88a2fdaef9e4687.png)

所以，漏洞分析的起点，就从`yii\db\BatchQueryResult`开始。

当然，在开始之前，需要先简单列一下常见的魔术方法。

| 魔术方法 || 触发条件 |
| --- | --- |
| `__wakeup()` || 使用`unserialize`时触发，常用于反序列化漏洞的起点，优先级高于`__destruct()` |
| --- | --- |
| `__sleep()` || 使用`serialize`时触发 |
| `__construct()` || 对象被创建时触发 |
| `__destruct()` || 对象被销毁时触发，常用于反序列化漏洞的起点 |
| `__call()` || 在对象上下文中调用不可访问的方法时触发 |
| `__get()` || 用于从不可访问的属性读取数据 |
| `__set()` || 用于将数据写入不可访问的属性 |
| `__toString()` || 把类当作字符串使用时触发 |
| `__invoke()` || 当脚本尝试将对象调用为函数时触发 |

最常见的反序列化起点无非就是`__destruct()`或`__wakeup()`，其他的魔术方法作为构成`POP`链的一环。了解这些之后，我们开始正式分析漏洞。

![](../Images/e12f1956333f4723045ca2a094e8f37e.png)

首先打开文件，`/vendor/yiisoft/yii2/db/BatchQueryResult.php`，删除多余的代码和注释后，如下：

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   

```
<?phpnamespace yii\db;
use yii\base\BaseObject;
class BatchQueryResult extends BaseObject implements \Iterator{
    private $_dataReader;
    public function __destruct(){        $this->reset();    }
    public function reset(){        if ($this->_dataReader !== null) {            $this->_dataReader->close();        }    }
```

在经过反序列化时，通过`__destruct`魔术方法，触发了自身的`reset`方法，此时`_dataReader`变量是可控的。`reset`方法进行调用了`_dataReader`的`close`方法。

这时候会有两种情况：

1.`_dataReader`对象没有`close`方法，于是触发`__call()`魔术方法，从`__call()`方法触发其他危险函数。

2.`_dataReader`对象存在`close`方法，于是触发`close`方法，从`close`方法触发其他危险函数。

这里的危险函数是泛指一切类似于`call_user_func`之类的可直接或间接执行命令的函数。从这里，就可以分出两条`POP`链，我们先从第一种情况开始说起。

### POP1

首先寻找含有`__call()`魔术方法的类，通过工具搜索关键字`function __call(`，共找到`14`个文件。

![](../Images/0c1db67655278490c50c5fb2b61b6dcc.png)

由于`close`方法没有传递参数，所以`__call()`魔术方法也没有传递参数，所以危险函数的参数，需要从类的本身寻找。接下来需要从这些`__call()`魔术方法中，寻找符合要求的类。

在排除掉大部分无函数执行的类之后，初步筛选了`5` 个类。

*   
*   
*   
*

```
/vendor/fzaninotto/faker/src/Faker/UniqueGenerator.php/vendor/fzaninotto/faker/src/Faker/Generator.php/vendor/fzaninotto/faker/src/Faker/ValidGenerator.php/vendor/guzzlehttp/psr7/src/StreamDecoratorTrait.php/vendor/yiisoft/yii2/base/Component.php
```

继续深入筛选发现，`Component.php`的函数参数不可控；`StreamDecoratorTrait.php`使用`trait`定义，无法被实例化；但是在`ValidGenerator.php`中发现`call_user_func_array(array($this->generator, $name), $arguments);`代码，通过代码进行简单测试。

*   
*   
*   
*   
*   
*

```
<?php
$generator='aaa';$name='';$arguments=[];
call_user_func_array(array($generator, $name), $arguments);
```

运行之后发现存在警告：  
`Warning: call_user_func_array() expects parameter 1 to be a valid callback, class 'aaa' not found in C:\Users\87563\Desktop\2.php on line 7`。  

根据警告信息去检索了`call_user_func_array`的官方说明，根据：  
*https://www.php.net/manual/zh/function.call-user-func-array.php  
https://www.php.net/manual/zh/language.types.callable.php*

发现，`call_user_func_array`和`call_user_func`函数中的`$callback`参数支持已实例化的对象作为数组传递，一个已实例化的 `object` 的方法被作为 `array` 传递，下标 `0` 包含该 `object`，下标 `1` 包含方法名。

也就是说，我们可以通过执行`class`中的方法，例如：

*   
*   
*   
*   
*   
*   
*   

```
<?php
$generator=new Test();$name='test_func';$arguments=[];
call_user_func_array(array($generator, $name), $arguments);
```

这样就可以执行`Test`类中的`test_func`函数。

但在`ValidGenerator.php`中，`class`不可控，方法不可控，`UniqueGenerator.php`也同样如此，于是排除掉。

最终，只剩下了`Generator.php`，进行深入分析，代码审计。在删除掉多余代码后，简单改变一下代码顺序，就变成了：

`__call()`魔术方法会调用自身的`format`方法，`format`方法又会调用`call_user_func_array`，然后会触发`getFormatter`方法进行一个简单的判断。因为我们是通过`BatchQueryResult.php`中`$this->_dataReader->close();`来触发的`__call()`，所以这时候`$formatter`的值是`close`，判断逻辑是如果存在`$this->formatters['close']`，那么就返回它的值。

简单来说就是，可以通过控制`$this->formatters['close']`，来选择调用不同的函数，当然必需是无参数的函数，例如`phpinfo()`。

`getIsActive()`的返回值与`session`有关，经测试，当开启`session`时，返回值为`True`，所以只要是正常网页访问，就永远为`True`:
