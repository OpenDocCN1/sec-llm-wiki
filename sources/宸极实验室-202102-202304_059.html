介绍：由一道 CTF 题目学习 Windows 画图程序 mspaint.exe 内存取证。

0x00 前言

目前CTF中常见的内存取证题目，一般取证的范围是落地的文件、浏览器的历史记录、命令行执行历史记录、注册表等，很少有见过针对正在运行的画图程序进行取证的，那么应该如何对正在运行且并未保存成文件的图像进行恢复呢？

0x01 对进程进行提取

之前的比赛题目因为太大了，已经被我删掉了，我重新制作了一份内存，我们来进行取证的样例演示。

环境：win10X64

首先我们用Volatility对这个win10的内存进行加载。

这里需要大家注意一点的是，如果大家对win10较新版本的系统进行取证的话，需要下载较新的的profile才能进行完整的加载，否则使用imageinfo很有可能检测不出来系统的版本或者会有部分插件无法使用的情况发生。

0x02 恢复图像

画图程序在windows内存中的图像是以原始图像数据的形式存在的，所以我们要加载原始的图像数据，就要使用到一款工具叫做GIMP。

GIMP（名称由GNU Image Manipulation Program的首字母组成，意为"GNU图像处理程序"）是一个自由及开放源代码的位图图像编辑器，用于图像照片润饰及编辑、自由绘图、调整大小、裁剪、照片蒙太奇、转换图像格式以及其他专业任务。

我是在ubuntu里打开的，如果电脑里没有的话，可以使用命令进行安装：
sudo apt install gimp gimp-help-en -y

然后我们将dmp文件的后缀改成.data，使用GIMP进行加载。

  • 调整三个属性：height当调整到合适的值时，它不必改变。确定一个width通常常见的显示分辨率，然后不断调整displacement使其可见，也就是镜像中的系统界面。

接下来就需要我们不断地去尝试一个适合的长宽高度来完整的显示图片。
当宽度为4096，高度为1024的时候，可以看到界面上出现了文字的样式。

至此，我们得到了我们原始在画图上画出的文字，将原始的图像恢复完成了。

0x03 总结

利用GIMP对内存中原始的图像数据进行恢复其实并不难，重要的就是如何能识别出原始的图像数据并用正确的方式去打开它。
