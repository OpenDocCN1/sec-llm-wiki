0x00 欢迎光临

Cknife是一款开源的WebShell管理工具，2015年12月首发，由Java语言编写而成，可以连接至Java、 PHP、ASP和ASP.NET等服务器。

作者是两名来自MS509Team的安全研究人员——Chora & MelodyZX。

在当时的网络环境，各种版本的菜刀满天飞，由于初学者的鉴别能力有限，经常会下载到含有后门的版本。

于是，Cknife应运而生，并且风靡一时。

作为菜刀的跨平台替代版，Cknife拥有菜刀的绝大部分功能，并且符合用户的使用习惯。

但由于各种各样的原因，Cknife后来被蚁剑以及冰蝎等工具所替代。

在之前，有很多大佬公开过基于菜刀的Jsp一句话木马，缺点就是体积比较大。

并且菜刀的流量特征早就被摸透了，所以相比较而言，大家更喜欢冰蝎等工具。

而故事，就要从这里开始讲起。

0x01 凉菜

在某天午后，驻场同事在安全设备的日志中，发现了疑似WebShell的文件admin.jspx。

由于文件比较复杂，于是发到了实验室进行分析。

在修改完几处语法bug之后，证实该文件确实是WebShell，但是与常见的Jsp_WebShell不太一样。

首先，他的基本逻辑与菜刀的Jsp_WebShell逻辑一致，关键代码如下：

简略分析之后，可以大致理解该WebShell的整体流程。

从POST的body中获取到加密后的参数和值，之后通过解密解码，解析成正常菜刀的指令，之后将指令执行结果加密编码，返回。

虽然走通了流程，但是令人苦恼的是，并没有一款现成的工具可以支持这种操作。

于是，萌生了魔改开源工具的想法。

0x02 热菜

魔改的目标首选就是Cknife。

首先代码量小，其次，它与菜刀的贴合度最高。

魔改的最终目的是，在数据传输的过程中，添加AES加解密的流程，

使指令进行加密后再发送，获取到的结果解密后再显示。

首先在util中，添加了AES类，用于后续的加解密，代码不再赘述。

之后，需要简单修改指令命名。

这一部分的原因是，Cknife的指令并不与菜刀完全一致。

例如：

菜刀：password=A&Z0=UTF-8password=M&Z0=UTF-8&Z1=-c/bin/sh&Z2=xxx
Cknife:password=1&action=A&code=UTF-8password=1&action=M&code=UTF-8&Z1=-c/bin/sh&Z2=xxx

而WebShell的指令方式是菜刀版本的。

所以需要简单的修改Cknife的指令格式。

  public static String makeParams(String... args) {        String params = "";        if (args.length == 2) {            params = Safe.PASS + "=" + args[0] + "&" + Safe.CODE + "="                    + args[1];        } else if (args.length == 3) {            params = Safe.PASS + "=" + args[0] + "&" + Safe.CODE + "="                    + args[1] + "&" + Safe.PARAM1 + "=" + args[2];        } else if (args.length == 4) {            params = Safe.PASS + "=" + args[0] + "&" + Safe.CODE + "="                    + args[1] + "&" + Safe.PARAM1 + "=" + args[2] + "&"                    + Safe.PARAM2 + "=" + args[3];        }        return params;    }

这之后还需要解决的问题是编码问题。

Cknife本身没有加密传输，所以它的指令在传输前需要进行URL编码。

所以这里需要去掉URL编码的过程。
