介绍：有趣的RDP利用方式。

0x00 前言

在很多组织的网络架构部署中，为了减少风险限制其他端口接入，通常会在军事隔离区的计算机设备中只开启3389端口，运维人员通过远程桌面进行网络维护。

针对这种受限制的网络设备，接下来介绍两种思路，供大家参考。

1、我们可以利用RDP反向攻击，让运维主机上线；

2、利用RDP搭建Socks5代理隧道。

0x01 挂载盘符反向攻击

1.1 原理

Windows远程桌面客户端mstsc有一个盘符挂载选项，如果勾选了该选项，会开启磁盘共享功能，相当于将你本地磁盘在远程主机上共享，类似于SMB文件传输命令那样将位于远程主机上的文件复制到客户端主机上。

RDPInception攻击：通过相应的设置，在客户端连接远程主机的一瞬间，将远程主机上早已准备好的木马程序复制到客户端主机的启动项中，那么当客户端主机下一次启动时便会执行该木马程序，客户端主机便可以成功上线。

1.2 限制条件

客户端的mstsc.exe必须要开启驱动器C盘共享，但是默认情况下mstsc.exe是会不开启磁盘共享功能的。

1.3 基本操作

在客户端进行远程连接目标机器的时候，在客户端的【选项】-【本地资源】-【详细信息】处选择磁盘共享。

当客户端进行远程登录后，在远程连接目标机器的网络环境中，会发现一个名为tsclient的主机。

我们可以运行命令 dir \\tsclient\c 列出连接远程主机的客户端C盘目录；还可以将远程主机上的文件复制到连接远程主机客户端的C盘中 copy file \\tsclient\c，如下图所示。

1.4 构建简单网络环境上线CS

根据上面的网络结构，假定黑客利用某个漏洞成功拿下win7-1 web server服务器。

我们在被控的win7-1 web server服务器的启动项中写入一个.bat脚本，当某个运维客户端(win7-2)通过远程桌面连接到这个远程主机时，在登录之后会立即执行这个启动项中的run.bat脚本。

0x02 剪贴板窃取

2.1 原理

在使用mstsc进行远程桌面的时候，会启动一个叫rdpclip.exe的进程，这个进程的作用是同步服务端与客户端的剪贴板。如果直接结束该进程，那么在服务端上将某些数据拷贝到客户端上时，就会发现剪贴板失效，无法复制。

由于启动该进程时，会自动同步剪切板内容，因此当目标机器与其他机器使用mstsc建立RDP远程连接时，就可以通过读取rdpclip.exe进程数据，进行剪贴板窃取，以尽可能地获取更多的信息。

该进程是后台运行的，如果管理员同时用远程桌面登录多台服务器，在其中的某一个服务器上进行复制拷贝操作时，会将数据同步到所有服务器的rdpclip.exe进程。

文件从服务器复制到客户端，完整流程如下图所示：

（1）在服务器上，"复制"操作会创建格式为 "CF_HDROP" 的剪贴板数据。
（2） 在客户端计算机中执行「粘贴」时，将触发一系列事件。
（3） 要求服务器上的 rdpclip.exe 进程提供剪贴板的内容，并将其转换为 FileGroupDescriptor(Fgd)剪贴板格式。
（4）使用 HdropToFgdConverter::AddItemToFgd() 函数，将文件的元数据添加到描述符中。
（5） 完成后，将 Fgd Blob 发送到服务器上的 RDP 服务。
（6） 服务器只是将其包装并将其发送给客户端。
（7） 客户端将其解包并将其存储在自己的剪贴板中。
（8） 「粘贴」事件将发送到当前窗口（例如，explorer.exe）。
（9） 处理事件并从剪贴板读取数据。
（10） 通过 RDP 连接接收文件的内容。

0x03 剪贴板劫持（CVE-2019-0887）

3.1 漏洞原理

利用剪切板目录穿越进行恶意文件传输。
向rdpclip进程中注入dll，hook几个关键函数，对Hdrop数据进行修改，在客户端复制的时候触发，路径可以自定义，实现目录穿越进行文件传输。

3.2 限制条件

（1）需要开启mstsc的剪切板功能；

（2）受害者进行粘贴复制操作；

（3）需要开机自启动操作。
