## 1、 前言

由于谷歌旗下的 `Pixel` 系列手机因其开放性以及对自家安卓系统的兼容非常好，所以很多移动安全人员都喜欢用该系列的手机作为测试机，进行日常应用测试及脱壳分析等工作，本文为刚接触移动安全的朋友提供一份靠谱的基础环境构建指南系列之篇Ⅱ-基础抓包环境。

日常工作中，无论是渗透还是`APP`测试，都会涉及到抓取`APP`数据包的需求，如手机不做任何处理，则只能抓取到`HTTP`的请数据包，`HTTPS`的无能为力，由于`Android 7.0`之后引入的新机制，会出现安装了证书也无法抓包的情况，本文将在上篇文章搭建的环境上进行基础抓包环境的搭建。

### 2.1 Magisk 模块安装

由于安卓系统从 7.0 版本开始，系统不再信任用户证书，导致之前的抓包配置方法失效，所以需要一个模块来解决此问题，让安卓系统继续信任我们添加的证书，这样才可以抓到包。当然这里有个小技巧，可以通过修改 `AndroidManifest.xml` 文件，修改`networkSecurityConfig`配置，从而接受用户证书，但这只能对修改过的应用程序有效，这部分内容在正文最后一节，感兴趣的可以自行尝试，这里还是让`Magisk`来解决此问题。

模块项目地址：*https://github.com/NVISOsecurity/MagiskTrustUserCerts*

模块下载链接：https://github.com/NVISOsecurity/MagiskTrustUserCerts/releases/download/v0.4.1/AlwaysTrustUserCerts.zip

模块作者提供的安装说明：

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   

```
1. Install Magisk.2. Zip files `zip -r AlwaysTrustUserCerts.zip ./*` or download zip from releases.3. Install in Magisk.4. Install client certificates through normal flow.5. The installed user certificates can now be found in the system store.
Adding certificatesInstall the certificate as a user certificate and restart the device.
Removing certificatesRemove the certificate from the user store through the settings, and restart the device.
```

接下来按照说明，将压缩包传入手机：

*   
*   

```
# 使用 adb 将压缩包传入手机中adb push AlwaysTrustUserCerts.zip /sdcard/Download/
```

打开`Magisk`应用，切换到模块管理功能页，点击从本地安装。

![](../Images/4d6daf70dc820cc9dffe92c526d04d2e.png)

选择刚刚上传到手机中的压缩包`AlwaysTrustUserCerts.zip`。

![](../Images/f07bc03a6a93bbe1d1be3f442c9af686.png)

安装完成后如下所示，点击重启按钮，重启完成之后即可生效。

![](../Images/82fd7268cadbabd95fcd3fdf7a8cd5c0.png)

### 2.2 BurpSuite 配置监听

接下来打开`BurpSuite`，选择`Proxy`->`Options`标签页：

![](../Images/9b1cafc638d13fbd11ee6137bf32789c.png)

点击`Add`按钮，添加一个监听，端口填写无固定要求，与后续设置代理时保持一致即可，地址选择电脑与手机所在的同一个局域网地址，点击`OK`按钮保存。

![](../Images/d72aedc1d91d701aede6103227fbe74a.png)

监听添加完成后，操作正确的话`Listeners`列表中应该多了一个地址，如下所示：

![](../Images/692e1cc36255c4e8313cae5eb0635223.png)

### 2.3 BurpSuite 证书安装至 Android

监听添加完成后，手机打开浏览器输入刚才在`BurpSuite`中选择的地址及端口，如下所示。

![](../Images/ce59b09988d65579e45fa71cd5ee17e1.png)

点击右上角`CA Certificate`下载文件，完成后至文件管理器将文件重命名为`.cer`后缀。

![](../Images/d642ce720f744f9c4c9faaa1fabe8a9e.png)

打开手机`设置`->`安全`->`加密与凭据`->`安装证书`->`CA证书`->`仍然安装`，选择到下载目录中刚刚重命名的`.cer`文件，安装完成后返回上一级菜单，点击`信任的凭据`->`用户`，查看安装结果。

![](../Images/899264cd2fad5e438801266ff1da4175.png)

重启设备后，查看系统级证书中是否出现用户证书。

![](../Images/10181ecaa1a366557775ba0a8fe9d034.png)

*   


![](../Images/29cf43fa559ea87d0b6a231fe3fa3a2d.png)

点击`无线网络`，选择当前的无线网络，进入该网络的设置页面，设置代理为手动，填入地址及端口，类型选择`HTTP`类型。

行动选择`本地代理链全部`，应用选择需要抓包的应用，之后点击右上角保存按钮。

![](../Images/427351a10e44a2b662daf7b3336c34cb.png)

返回到主界面，左滑回到日志界面中，点击最下方的按钮打开开关。

![](../Images/629a148714627a3fc2a7ce7e8e33db03.png)

第一次使用会弹出一个提示，点击确定即可。

![](../Images/39b11b05b2dd01d346df337d3a7d9861.png)

确认已清空`WLAN`中的代理设置。

打开目标应用程序，查看`BurpSuite`数据包记录。

### 2.6 小技巧 - networkSecurityConfig

这个小技巧了解即可，由于用起来不是很方便，推荐在环境受限的情况时可以尝试一下，所以这里简单记录一下过程，不作详细描述了，感兴趣朋友可以自行尝试。

首先需要将目标程序从手机中提取出来，解包目标应用程序。

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   

```
# 列出系统中安装的应用列表# 如已有 apk 文件，可以跳过此步骤，直接解包目标应用程序pm list package
# 找到目标应用的包名，使用 -f 参数获取路径。pm list package -f xxx
# 复制路径，新开一个终端，将应用复制到电脑中。adb pull /data/app/com.xxx-xxxxxxxxx==/base.apk
# 解包目标应用程序apktool d -f base.apk
```

解包后可以看到`AndroidManifest.xml`文件，`AndroidManifest.xml`的官方释义是应用清单，每个应用程序的根目录必要有此文件，且文件名必须保持一致，其中记录了应用程序的各项信息，如应用需要使用的权限、各个组件的导出及权限信息等。

接下来需要编辑`AndroidManifest.xml`这个文件，定位到其中的`application`标签，添加如下内容：

*   
*   
*   
*   
*   

```
# 添加如下内容android:debuggable="true" android:networkSecurityConfig="@xml/network_security_config"
# 添加后的格式大致如下<application android:debuggable="true" android:networkSecurityConfig="@xml/network_security_config" android:allowBackup="true" android:icon="@drawable/ic_launcher" android:label="@string/app_name" android:theme="@style/AppTheme" >
```

添加的`android:debuggable="true"`表示开启应用调试功能，方便测试应用一并添加，如本身有这个属性，只需要将`false`调整为`true`。

`android:networkSecurityConfig`是主角，它是`Android 7.0`安全方面引入的新功能，允许用户可以在不修改应用本身代码的情况下，对网络安全配置文件进行自定义管理。

通过网络安全配置文件(`res/xml/network_security_config.xml`)可以实现多个功能，如：

配置自定义`CA`，假设要连接到使用自签名`SSL`证书的主机，或者连接到其`SSL`证书由信任的非公共`CA`（如公司的内部 `CA`）颁发的主机。

*   
*   
*   
*   
*   
*   
*   
*   
*   

```
<?xml version="1.0" encoding="utf-8"?><network-security-config>    <domain-config>        <domain includeSubdomains="true">example.com</domain>        <trust-anchors>            <certificates src="@raw/my_ca"/>        </trust-anchors>    </domain-config></network-security-config>
```

限制可信`CA`集，如果应用并不一定想要信任系统信任的所有`CA`，则可以自行指定，即缩减要信任的`CA`集。这样可防止应用信任由任何其他`CA`颁发的欺诈性证书。

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   

```
<?xml version="1.0" encoding="utf-8"?><network-security-config>    <domain-config>        <domain includeSubdomains="true">secure.example.com</domain>        <domain includeSubdomains="true">cdn.example.com</domain>        <trust-anchors>            <certificates src="@raw/trusted_roots"/>        </trust-anchors>    </domain-config></network-security-config>
```

信任其他`CA`，应用可能需要信任系统不信任的其他`CA`，应用可以通过为一个配置指定多个证书源来实现此目的。

*   
*   
*   
*   
*   
*   
*   
*   
*   

```
<?xml version="1.0" encoding="utf-8"?><network-security-config>    <base-config>        <trust-anchors>            <certificates src="@raw/extracas"/>            <certificates src="system"/>        </trust-anchors>    </base-config></network-security-config>
```

配置用于调试的`CA`，调试通过`HTTPS`连接的应用时，可能需要连接到没有为生产服务器提供`SSL`证书的本地开发服务器。为了支持此操作，而又不对应用的代码进行任何修改，可以通过使用 `debug-overrides` 指定仅在`android:debuggable`为 `true` 时才可信的仅调试`CA`。通常，`IDE`和构建工具会自动为非发布`build`设置此标记。

*   
*   
*   
*   
*   
*   
*   
*   

```
<?xml version="1.0" encoding="utf-8"?><network-security-config>    <debug-overrides>        <trust-anchors>            <certificates src="@raw/debug_cas"/>        </trust-anchors>    </debug-overrides></network-security-config>
```

选择停用明文流量，应用可能需要确保所有与`secure.example.com`的连接始终通过`HTTPS`完成，以防止来自恶意网络的敏感流量。

*   
*   
*   
*   
*   
*   

```
<?xml version="1.0" encoding="utf-8"?><network-security-config>    <domain-config cleartextTrafficPermitted="false">        <domain includeSubdomains="true">secure.example.com</domain>    </domain-config></network-security-config>
```

回归正题，此处需要让应用程序信任用户域证书，配置文件`res/xml/network_security_config.xml`的内容如下：

*   
*   
*   
*   
*   
*   
*   
*   

```
<?xml version="1.0" encoding="utf-8"?><network-security-config>    <debug-overrides>        <trust-anchors>            <certificates src="user"/>        </trust-anchors>    </debug-overrides></network-security-config>
```

修改完后，重新打包应用并签名。

*   
*   
*   
*   
*   

```
# 重新打包应用apktool b base
# 签名java -jar signapk.jar key.x509.pem key.pk8 1.apk 1_Signed.apk
```

将应用安装回手机，再次配置抓包即可。
