首先我们先了解一下几个方法和类。

`Runtime`类

*   
*   
*   

```
 Runtime类封装了运行时的环境。每个 Java 应用程序都有一个 Runtime 类实例，使应用程序能够与其运行的环境相连接。一般不能实例化一个Runtime对象，应用程序也不能创建自己的 Runtime 类实例，但可以通过 getRuntime 方法获取当前Runtime运行时对象的引用。一旦得到了一个当前的Runtime对象的引用，就可以调用Runtime对象的方法去控制Java虚拟机的状态和行为。
```

上面的意思解释一下就是：

*   
*   
*   
*   
*   

```
一般我们通过Runtime.getRuntime方法来获取Runtime类的实例，进而调用其对象的方法。然后其中包括一个方法exec(String command)       在单独的进程中执行指定的字符串命令。我们看到这个exec方法的形参是String类型的。
```

`getClass`方法：

*   
*   
*   

```
假如存在一个person类,同时存在一个person类的对象p,p.getClass()获得是一个object.person。即一个class类型的对象。就比如string name，string是类型，name是对象，那么p.getClass()结果可以解读为class等同于string，p等同于name所以只有一个类的实例才能存在getclass方法。
```

`getMethod`方法:

*   
*   
*   
*   

```
Method Class.getMethod(String name, Class<?>... parameterTypes)的作用是获得对象所声明的公开方法我们看到getMethod的形参第一个是String,第二个形参在java里可以看做一个class数组，即可以写成Class[]parameterTypes形式所以我们在赋值的时候，第一个参数是String类型，第二个参数是class数组。同时呢,在调用的时候，第一个参数是方法名，第二个参数是该方法的参数类型
```

Object invoke(Object obj, Object... args)method.invoke(Object obj, Object... args)的作用是执行method方法如果method方法是一个静态方法，obj参数可以写成null

## 0x04 反射机制调用反射机制函数实现Runtime实例

上面分析了三个利用的方法,发现我们还是没有解决一个问题：我们不能直接`input`输入`Runtime.getRuntime()`。

但是我们有`InvokerTransformer`,`ConstantTransformer`,`ChainedTransformer`类都实现了`Serializable`接口，而且有任意的反射机制，所以我们可以通过反射机制来反射`class`类的`getMethod`方法，然后再调用`Runtime`类的`getRuntime`方法。

我们仿照`InvokerTransformer.transformer`方法可以这么实现：

![](../Images/6236e44d07cd74d4b8b0ecaf582d1626.png)

然后我们来讲讲为什么这么写，刚开始看的时候，其实很懵，参数为啥是这样的？

*   
*   
*   
*   
*   
*   
*   

```
首先：我们的input的值为Runtime.class，一般讲反射的时候都会讲到[类名].class来获取类对象的方法,那么Runtime.class获取类对象，cls=Runtime.class.getClass=java.lang.Class然后：我们的目标是从Class中获取getMethod方法，使用getMethod方法来获取，而String.class,Class[].class是getMethod方法定义形参类型，字符串和Class数组。即method=java.lang.Class.getMethod(java.lang.String,java.lang.Class[]) 最后：Runtime.class调用java.lang.Class.getMethod方法，参数是String.class和new Class[0]，参数和getMethod的对应起来，要不然会报错注意：这里是Runtime.class调用了getMethod方法获得了getRuntime方法
```

然后我们转换成使用`InvokerTransformer`类的形式。

*   
*   
*   
*   
*   

```
InvokerTransformer invokerTransformer = new InvokerTransformer(                "getMethod",new Class[]{String.class,Class[].class},new Object[]{"getRuntime",new Class[0]}                );Object ceshi = invokerTransformer.transform(Runtime.class);System.out.println(ceshi);
```

这里对参数添加`new Class`和`new Object`是因为`InvokerTransformer`的初始化的参数的格式是`class[]`和`Object[]`。

我们再加入`ConstantTransformer`类：

*   
*   
*   
*   
*   
*   
*   

```
InvokerTransformer invokerTransformer = new InvokerTransformer(                "getMethod",new Class[]{String.class,Class[].class},new Object[]{"getRuntime",new Class[0]}                );ConstantTransformer cls = new ConstantTransformer(Runtime.class);Object transform = cls.transform(null);Object ceshi = invokerTransformer.transform(transform);System.out.println(ceshi);
```

最后再加入`ChainedTransformer`类：

*   
*   
*   
*   
*   
*   
*   

```
Transformer[] transformers = new Transformer[]{                new ConstantTransformer(Runtime.class),                new InvokerTransformer("getMethod",new Class[]{String.class,Class[].class},new Object[]{"getRuntime",new Class[0]}),        };Transformer chain = new ChainedTransformer(transformers);Object ceshi = chain.transform(null);System.out.println(ceshi);
```

获取到`Runtime`的`getRuntime`，按照之前执行代码的逻辑可以加执行`exec`的代码，运行一下却发现报错了。

![](../Images/59938f42999714369d28cf1f28f1c2f2.png)

报错说没有在`java.lang.reflect.Method`找到`exec`方法，我们的本意是通过`Runtime.getRuntime`获得`Runtime`的实例，然后在`Runtime`类里找`exec`方法。为何偏了呢？其实这里我们在前面就分析了，在传入`exec`方法之前，只是`Runtime.class`调用了`getMethod`方法获取了`getRuntime`方法，但是我们没有执行`getRuntime`方法，就没有获得`Runtime`的实例。如何执行方法呢，反射中，通过`getMethod`等方法获取方法，通过`invoke`执行方法。执行`getRuntime`方法，`invoke`需要传入`getRuntime`的类对象和相应函数的参数。一般反射是通过类似这种的形式来简单执行`Person`的`study`方法。

*   
*   
*   
*   

```
Class c = Class.forName("test.reflect.Person");//创建Class对象Object m = c.newInstance();//创建类实例对象Method method = c.getDeclaredMethod("study", String.class);//获取reflectMethod方法method.invoke(m,"大家");//调用实例对象方法
```

我们对照一下就发现我们在之前只是获得了`Runtime.getRutime`，对应的上述代码的`method`，我们还需要执行该方法，需要达到这样的效果：`getRuntime.invoke(Runtime.getRuntime())`

那么我们尝试在代码上执行`invoke`，但是`transformer`为`Object`类型，没有`invoke`方法，这该怎么解决呢?

是不是感觉这个问题有点似曾相识，前面我们解决的是`java.lang.class`没有`getRuntime`方法，我们通过反射调用`getMethod`方法来获得`getRuntime`,这里我们通过可以`getMethod`方法来获得`invoke`方法。

```
首先:input为public static java.lang.Runtime java.lang.Runtime.getRuntime(),即getRuntime方法cls=getRuntime方法.getClass()=java.lang.reflect.Method,getRuntime方法的是Method类(方法当然是Method类，这里容易误解成是Runtime的类对象，其实是方法的类对象)然后:method=java.lang.reflect.Method.getMethod("invoke",Object.class,Object[].class)=public java.lang.Object java.lang.reflect.Method.invoke,即invoke方法这里的要获取invoke方法,invoke方法定义：public Object invoke(Object obj, Object... args)所以参数类似是Object.class,Object[].class最后:method.invoke(input,args)=invoke方法.invoke(input,args)两个invoke该怎么解读呢最简单的method.invoke(input,args)实现的是input去执行method方法，给method方法传参是args，所以这里是getRuntime去执行invoke方法,给invoke传的参数是args，那么就变成了getRuntime.invoke(args)即input.invoke(args)是getRuntime方法被调用而对于getRuntime.invoke(Object obj, Object... args)方法,下面的参数的构造涉及了invoke参数的特性：对于method.invoke(obj，args)，如果method是一个静态方法,那么其第一个参数可以写作null,getRuntime是一个静态方法，所以这里可以所属类可以写成null。而getRuntime参数是无参数的方法，所以其参数也可以写成null,对应invoke方法的形式,就对应的是null,new Object[0]。
```
