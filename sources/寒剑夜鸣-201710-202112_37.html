大家好，我是Alex。今天教大家windows下使用netsh实现端口转发！

目标IP：192.168.1.200

跳板机IP：192.168.1.199（1.200的远程管理机）

攻击机IP：192.168.1.19


IP 192.168.1.200开启了远程桌面连接以及3389端口，但在防火墙做了策略只能通过管理机（192.168.1.199）访问，如下图

192.168.1.19无法访问192.168.1.200远程连接

IP 192.168.1.19可以远程管理机（192.168.1.199）


那么好，我们就通过远程管理机使用netsh命令来新建一条端口转发规则，使得攻击机可远程管理机本地转发后的端口来连接目标机器


在管理机中（192.168.1.199）使用如下命令，将本地端口443转发至192.168.1.200的3389端口

netsh interface portproxy add v4tov4 listenport=443 listenaddress=0.0.0.0 connectaddress=192.168.1.200 connectport=3389


PS：删除转发规则 ，add改为delete

可使用命令netsh interface portproxy show all来查看所有已建转发规则，

注意：防火墙例外443端口！

这样攻击机就可以直接连接目标远程桌面了

那么为什么ssh一关闭，程序就不再运行了？

以下原文链接：https://www.jianshu.com/p/9d4270a284cb

答：元凶：SIGHUP 信号

让我们来看看为什么关掉窗口/断开连接会使得正在运行的程序死掉。

在Linux/Unix中，有这样几个概念：

进程组（process group）：一个或多个进程的集合，每一个进程组有唯一一个进程组ID，即进程组长进程的ID。

会话期（session）：一个或多个进程组的集合，有唯一一个会话期首进程（session leader）。会话期ID为首进程的ID。

会话期可以有一个单独的控制终端（controlling terminal）。与控制终端连接的会话期首进程叫做控制进程（controlling process）。当前与终端交互的进程称为前台进程组。其余进程组称为后台进程组。

根据POSIX.1定义：

挂断信号（SIGHUP）默认的动作是终止程序。

当终端接口检测到网络连接断开，将挂断信号发送给控制进程（会话期首进程）。

如果会话期首进程终止，则该信号发送到该会话期前台进程组。

一个进程退出导致一个孤儿进程组中产生时，如果任意一个孤儿进程组进程处于STOP状态，发送SIGHUP和SIGCONT信号到该进程组中所有进程。（关于孤儿进程参照：http://blog.csdn.net/hmsiwtv/article/details/7901711 ）

结论：因此当网络断开或终端窗口关闭后，也就是SSH断开以后，控制进程收到SIGHUP信号退出，会导致该会话期内其他进程退出。

简而言之：就是ssh 打开以后，bash等都是他的子程序，一旦ssh关闭，系统将所有相关进程杀掉！！导致一旦ssh关闭，执行中的任务就取消了
