# Nginx文件名逻辑漏洞（CVE-2013-4547）

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzIwMzU0NDY5OA==&mid=2247488070&idx=1&sn=1861a3c0565b81c9a11bf21788d8115e&chksm=96cc9353a1bb1a452dbc9269e3f5f3e476caded85eabb4cb13e7b50a168304e15a83a7b96bc6&scene=126&sessionid=1681669480#rd](http://mp.weixin.qq.com/s?__biz=MzIwMzU0NDY5OA==&mid=2247488070&idx=1&sn=1861a3c0565b81c9a11bf21788d8115e&chksm=96cc9353a1bb1a452dbc9269e3f5f3e476caded85eabb4cb13e7b50a168304e15a83a7b96bc6&scene=126&sessionid=1681669480#rd)

1

●

漏洞影响版本

  

Nginx 0.8.41 ~ 1.4.3 / 1.5.0 ~ 1.5.7

 

2

●

漏洞原理

  
这个漏洞形成的主要原因是错误地解析了请求的URI，错误地获取到用户请求的文件名，导致出现**权限绕过**、**代码执行**的连带影响，其和代码执行没有太大关系。举个例子，比如，Nginx匹配到.php结尾的请求，就发送给fastcgi进行解析，常见的写法如下：

*   
*   
*   
*   
*   
*   
*   

```
location ~ \.php$ {    include        fastcgi_params;    fastcgi_pass   127.0.0.1:9000;    fastcgi_index  index.php;    fastcgi_param  SCRIPT_FILENAME  /var/www/html$fastcgi_script_name;    fastcgi_param  DOCUMENT_ROOT /var/www/html;}
```

如上，只有.php后缀的文件才会被发送给fastcgi解析。而存在CVE-2013-4547的情况下，我们请求1.gif\[0x20\]\[0x00\].php，这个URI可以匹配上正则.php$，可以进入这个Location块；但进入后，Nginx却错误地认为请求的文件是1.gif\[0x20\]，就设置其为**SCRIPT\_FILENAME**的值发送给fastcgi。fastcgi根据SCRIPT\_FILENAME的值进行解析，最后造成了解析漏洞。所以，我们只需要上传一个空格结尾的文件，即可使PHP解析之。

 

3

●

存在漏洞的必要条件

  
（1）cgi.fix\_pathinfo的配置需要关闭。如果cgi.fix\_pathinfo被开启，将会先去判断文件是否存在。而不会直接去匹配location块进而被发送到fastcgi程序。（2）没有高版本php的"security.limit\_extensions"限制高版本存在security.limit\_extensions = .php的配置，那么将只会把后缀为.php的文件当作是合法的php文件，进而我们的jpg空格文件将会被判定为不合法。进而不会被去当作php解析。
