20.网页木马

漏洞描述
经过渗透测试发现了目标站点存在webshell，攻击者可直接爆破口令使用木马，非常低成本的进行恶意操作。
修复建议
1.确认并删除木马文件，并进行本地文件漏洞扫描来排查是否还存在有其他木马。
2.发现并及时修复已存在的漏洞。
3.通过查看日志和服务器杀毒等安全排查，确保服务器未被留下后门

21.备份文件泄露

漏洞描述
网站备份文件、敏感信息文件存放在某个网站目录下，攻击者可以通过文件扫描等方法发现并下载该备份文件，从而导致网站敏感信息泄露。
修复建议
1.不在网站目录下存放网站备份的文件或者敏感信息的文件。
2.如需存放该类文件，可以将文件名命名为难以猜解的无规则字符串。

22.敏感信息泄露

漏洞描述

在页面中或者返回的响应包里面泄露了敏感信息，通过这些信息，给攻击者渗透提供了非常多有用的信息。
修复建议
1.如果是探针或者测试页面等无用的程序建议删除，或者修改成难以猜解的名字。
2.不影响业务或功能的情况下删除或禁止访问泄露敏感信息页面。
3.在服务器端对相关的敏感信息进行模糊化处理。
4.对服务器端返回的数据进行严格的检查，满足查询数据与页面显示数据一致。

23.短信/邮件轰炸

漏洞描述

由于没有对短信或者邮件发送的次数进行限制，导致可无限次发送短信或者是邮件给用户，造成短信邮件轰炸，进一步可能被大量用户投诉，因此影响公司声誉。
修复建议
在服务器端限制发送短信或者邮件的频率，例如同一个账号1分钟只能发送1次短信或邮件，一天内只能发送3次。

24.phpinfo信息泄露

漏洞描述
在Web站点的某些测试页面上可能会使用到PHP的phpinfo()函数，能输出服务器的关键信息，从而造成服务器信息泄露，为攻击提供有利的信息。
修复建议
1.彻底删除phpinfo 函数。
2.若文件没用可直接删除。 

25.IIS短文件名泄露漏洞

漏洞描述
Internet Information Services是由微软公司提供的基于运行Microsoft Windows的互联网基本服务。Microsoft IIS在实现上存在着文件枚举漏洞，攻击者可以利用此漏洞枚举网络服务器根目录中的文件。
存在危害：攻击者可以利用“~”字符猜解或者遍历服务器中的文件名，以此对IIS服务器中的.Net Framework进行拒绝服务攻击。
攻击者可以通过该漏洞来尝试获取网站服务器文件的文件名，从而达到获取更多信息来入侵服务器的目的。

26.应用程序错误信息泄露

漏洞描述
攻击者可通过特殊的攻击向量，使web服务器出现500、403等相关的错误，导致信息泄漏如绝对路径、源代码、webserver版本、sql语句等敏感信息，恶意攻击者便很有可能利用这些信息实施进一步的攻击。
修复建议
1.自定义错误页面或者使用统一的错误页面提示。

27.Apache Tomcat默认文件

漏洞描述
Apache Tomcat默认样例文件没有删除或者限制访问，可能存在cookie、session伪造，进行后台登录操作
修复建议
1.删除样例文件
2.限制文件访问权限

28.Crossdomain.xml配置不当

漏洞描述
网站根目录下的 crossdomain.xml 文件指明了远程Flash 是否可以加载当前网站的资源（图片、网页内容、Flash等）。如果这里配置不当，可能导致遭受跨站请求伪造（CSRF）攻击。
修复建议
对于不需要从外部加载资源的网站，在 crossdomain.xml 文件中更改allow-access-from的domain属性为域名白名单即可。

29.目标服务器启用了不安全HTTP方法

漏洞描述

目标服务器启用了不安全的传输方法，如TRACE、PUT、MOVE、DELETE等，这些方法表示可能在服务器上使用了 WebDAV，dav方法允许客户端操纵服务器上的文件，如上传、删除、修改相关文件等危险操作，所以，如果没有合理配置dav，有可能允许未授权的用户对其进行利用，修改服务器上的文件。
修复建议
1.关闭不安全的传输方法，只开启GET、POST方法。
2.如果服务器不使用 WebDAV 可直接禁用，或为允许webdav的目录配置严格的访问权限，如认证需要的用户名、密码以及认证方法。

30.weblogic SSRF服务器请求伪造

漏洞描述

目标存在weblogic SSRF服务器请求伪造漏洞。WebLogic是用于集成、开发、部署和管理大型分布式Web应用、网络应用和数据库应用的Java应用服务器。SSRF(Server-Side Request Forgery:服务器端请求伪造) 是一种由攻击者构造形成由服务端发起请求的一个安全漏洞。在一般情况下，SSRF攻击的目标是从外网无法访问的内部系统，（正是因为它是由服务端发起的，所以它能够请求到与它相连而与外网隔离的内部系统）。Weblogic中间件默认带有“UDDI 目录浏览器”且为未授权访问，通过该应用，可进行无回显SSRF请求。攻击者便可以利用该漏洞对很多企业内网进行大规模扫描，了解内网结构，并可能结合内网漏洞直接获取服务器权限。
修复建议
1.若不影响业务则可以删除uddiexplorer文件夹
2.限制uddiexplorer应用只能内网访问

31.Apache Struts2远程代码执行漏洞（S2-019）

漏洞描述
Apache Struts2的“Dynamic MethodInvocation”机制是默认开启的，仅提醒用户如果可能的情况下关闭此机制，如果未关闭此机制将会导致远程代码执行漏洞，远程攻击者可以利用此漏洞在受影响应用上下文中执行任意代码。
修复建议
1.目前厂商已经发布了升级补丁来修复这个安全问题，请到厂商的主页下载。
2.或者是手工设置struts.xml文件
<constantname="struts.enable.DynamicMethodInvocation"value="false"/>

32.Apache Struts2远程代码执行漏洞（S2-037）

漏洞描述
Apache Struts2在使用REST插件时，攻击者可以通过绕过动态方法执行的限制，来调用恶意表达式执行远程代码。
修复建议
建议用户到官方获取最新补丁或者最新版本程序。

33.Apache Struts DevMode远程代码执行漏洞

漏洞描述

为了方便开发人员调试程序，Struts2提供了一个devMode模式，便于查看日志以及程序错误等信息。当Struts2中的devMode模式设置为true时，意味着存在严重远程代码执行漏洞。如果WebService 启动权限为最高权限时，可远程执行任意命令，包括关机、删除服务器上所有文件、建立新用户等等。
修复建议
建议用户到官方网站获取最新补丁或者最新版本程序。
或者将struts.properties中的devMode设置为false，或是在struts.xml中添加如下代码：<constant name="struts.devMode"value="false"/>。

34.Apache Struts2远程代码执行漏洞（S2-045）

漏洞描述
Apache Struts2的Jakarta Multipartparser插件存在着远程代码执行漏洞，漏洞编号为CVE-2017-5638。攻击者在使用该插件上传文件的时候，可以修改HTTP请求头中的Content-Type值来触发该漏洞，导致远程执行代码。
修复建议
检测方式如下：查看web目录下/WEB-INF/lib/目录下struts-core.x.x.jar ，如果这个版本在Struts2.3.5 到 Struts2.3.31 及 Struts2.5 到 Struts2.5.10之间则存在着漏洞。
1.建议用户到官方网站获取最新补丁或者最新版本程序。
2.版本更新至Strusts2.3.32或者Strusts2.5.10.1，或使用第三方的防护设备进行防护。
3.临时解决方案：删除commons-fileupload-x.x.x.jar文件（会使上传功能不可用）。
4.修改WEB-INF/classes目录下的配置
　　在WEB-INF/classes目录下的struts.xml中的struts 标签下添加
<constantname=”struts.custom.i18n.resources”value=”global”/>；
　　在WEB-INF/classes/目录下添加global.properties，文件内容如下:
struts.messages.upload.error.InvalidContentTypeException=1

35.Apache Struts2远程代码执行漏洞（S2-033）

漏洞描述
Apache Struts2在开启动态方法时调用（DynamicMethod Invocation）的情况下，攻击者可以使用REST插件调用恶意表达式可远程执行代码。
修复建议
1.用户可以到官方获取最新补丁或者最新版本程序。
2.或者在允许的情况下通过禁用动态方法调用（Dynamic Method Invocation），修改Struts2的配置文件struts.xml，将struts.enable.DynamicMethodInvocation设置为“false”。

36.redis相关漏洞修复

漏洞描述
redis默认没有口令可能会未授权访问造成信息泄露，若redis为高权限账户运行，可能导致服务器权限丢失等。
安全建议
1、禁用一些高危命令
　　常见如：flushdb，flushall，config，keys 等
2、以低权限运行 Redis 服务
3、为 Redis 添加密码验证
4、禁止外网访问 Redis
5、保证 authorized_keys 文件的安全
