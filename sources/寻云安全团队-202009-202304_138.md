## 0x02 v2rayN 结合 Burpsuite

翻墙的时候，系统的代理已经设置成为了`SSRPort`，可是我们总是需要测试一些被墙的网站的，那应该怎么设置代理？这个时候把Burpsuite抓包的代理设置成SSR的代理那是愚蠢至极的做法！**因为这种愚蠢至极的做法我尝试过，在开启SSR的时候是无法在Burpsuite代理选中使用的！**

**User options ->Connections -> Upstream Proxy Servers**![](../Images/7f61e40f204816114109babbecb3add4.png)点击左侧的`Add`，弹出`Add upstream proxy rule`窗口，一共有八个设置项，我们只需要填充前四个即可。![](../Images/3aacd464d00874398599e28e37abc821.png)

##### **`Add upstream proxy rule:`**

*   Destination host : \*
*   Proxy host : 127.0.0.1
*   Proxy port : **v2rayN代理端口**
*   Authentication type : **None**![](../Images/a525d7630b1a0f1bf07f9d711593ed49.png)完成之后Burpsuite就可以开始抓被墙的网站的数据包了，这属于`Bug Bounty Tip`范畴吗？

## 0x03 通过忘记密码的用户枚举

用户枚举可以通过忘记密码功能实现，在密码找回处我随便输入密码，可是它并没有显示发送邮件，而是提示该邮件没有注册。这个提示方便我们进行爆破收集该网站的用户的邮箱信息，方便红队打点为后期社工做准备。有些厂商收这类漏洞，在不重复的前提一般是`100$-150$`这个范围的赏金。我来演示一遍！

**厂商:`Imgur @HackerOne`**![](../Images/f864f2328159a02bd020a6ffe23a4df3.png)按照步骤来，我们找到找回密码处然后随便输入任何邮箱。![](../Images/006f64942ec3d7366655828dc9bcfbf2.png)

![](../Images/9725a9341dc88cdd1b47ad2def66b3d1.png)**提示:未找到该用户名或电子邮件。** 是的，我们挖掘到了这类漏洞，可是`Imgur`并不收取这类漏洞于是报告被忽略了！后来我在`Hackerone`找到其中一个厂商也存在此类漏洞，但是重复了可它给我通过了可是没有任何赏金。

我的报告是这样写的:![](../Images/ca9611058677559b4db41ece20f3d8ae.png)

```


Vulnerability:-then
 intercept request by burp suitin

 response you will get That username or email was not found."if that mail address exists in our system, then we will send password reset link."

' emails. / Information Disclosure.
```

在`BugV`虽然重复了，但是厂商给了我五积分，可我不知道能用来干嘛![](../Images/98d0a14f7e1f195a30ab04d0ff3b4020.png)

## 0x04 Open redirect

当 Web 应用程序接受不受信任的输入时，可能会发生未经验证的重定向和转发，这可能导致 Web 应用程序将请求重定向到不受信任的输入中包含的 URL。通过修改恶意站点的不受信任的 URL 输入，攻击者可能成功发起网络钓鱼诈骗并窃取用户凭据！这是我从`@Owasp`复制来的关于重定向的解释。

**分享一个Bug Bounty Tip:**

```
Google Dork:site:example.com inurl:redir | inurl: URL | inurl:redirect | inurl:redirect | inurl:redirect | inurl:return
 | inurl:src=http | inurl:r=http
```

这个`Dork语句`能够有效且快速帮我们找到相关`Open redirect`漏洞！

**厂商:`Semrush @HackerOne`**

使用`Burpsuite`进行`Fuzz`，字典在Github上面能够找到需要师傅们收集的非常有用信息，能够帮助你快速的找到目标漏洞。![](../Images/4a18d8f7faff6fc21aac2bd245d280c0.png)当我看见这些英文我就知道有戏！继续Fuzz，尝试找出相对于的参数，没过多久我通过Burpsuite发现了它,![](../Images/5d2bb90b991cbafbb81b10bcc6de7080.png)是否能够跳转，我尝试输入:`http://www.baidu.com`发现成功跳转，我开始查看厂商公开的漏洞看看有没有重复。查找才知道这个洞两年前被大佬提交过，真的很想问厂商为什么不修复，白给了我一个希望！

HackerOne报告:`https://hackerone.com/reports/311330`

这类漏洞如果能搭配XSS证明危害，赏金一般是`100$-500$`这个范围![](../Images/8f04c508fec463e1a19f2ebef93c92ca.png)

## 0x05 SQLi in Harvard Subdomain

哈佛大学的子域名`*.med.harvard.edu`用Google Hacking语法可以找到很多SQLi，我拿其中一个来举例子

使用`ffuf`或者`Dirserch`对目录进行了FUZZ，发现了在第一级目录有这样一个PHP文件`availability.php`![](../Images/c416d42bece88630a2b87f5fe296475a.png)发现上面提示我们缺少`users`参数，我们来填充。![](../Images/e7d3cdeab7bbf579d5981be879e260cb.png)和前面一样我们需要补充参数，之后也是如此！于是我补充了几个参数后得到了一个网页！![](../Images/2f763e8e3ba3bdaae2bf88b198ada840.png)我在`Day`参数的值加了个`'`提示报错，我们用Sqlmap来跑就可以得到结果的![](../Images/ea912eb193d865ad125131d57f176632.png)

![](../Images/e56c5c4b603cb3066c5a2c69713682b9.png)可惜的是这个域名并没有赏金平台可以收取，所以我们提示了校方并让他们修复漏洞，我的朋友`@noob3xploiter`将这个漏洞写了一篇文章发布在了Medium平台上。
