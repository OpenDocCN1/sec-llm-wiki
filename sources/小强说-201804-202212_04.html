一、前言


OCA（The Open Cybersecurity Alliance 开放网络安全联盟），根据其2021年4月在Linkedin上发布的公告称，其将承接IACD（Integrated Adaptive Cyber Defense，集成的自适应防护）成果转化的工作，并称其首要任务是增加和改善网络安全产品之间的互操作性。这是自2019年IACD项目公开信息停更以来，最让人兴奋的消息。由于OCA项目涉及的内容和参与的企业成员较多，且一直在变化，计划通过撰写系列文章对其整体情况和详细技术内容进行介绍。

 

从本文开始，将对OCA中涉及的具体项目和规范内容进行详细介绍，STIX Shifter项目是为了解决跨厂商、跨产品之间数据协同，实现跨网络、文件和日志域的复杂查询和分析。


二、STIX Shifter基本情况


在介绍STIX Shifter之前，需要先介绍一下STIX，STIX（Structured Threat Information Expression，结构化威胁信息表达）是一种语言描述和序列化的格式，组织可以用来描述和交换网络威胁情报（CTI）。STIX使用对象和关系来进行描述，并使用JSON格式进行存储，以提高机器可读性【1】。

 

STIX提供了一种一致的、机器可读的方式来实现威胁分析、自动威胁信息交换、自动检测和响应等业务的协作开展（详细了解STIX的变化和演进见文章“从STIX2.1看安全智能归来”）。


STIX 1.x的实体和关系结构如图所示。


STIX Shifter是OCA发起的开源Python项目，目的是支持OCA框架的落地和业务开展。STIX Shifter允许软件通过STIX Patterning连接到包含数据存储库的产品，并以STIX Observations的形式返回结果。这样，在数据留在原地的前提下，允许软件连接和查询存放数据库的产品。

 

STIX Shifter通过规范化数据集和存储库，在使用原生APIs时增加使用价值，进而构建全面的双边连接，达到：

 

1）快速查询多个产品，生成统一结果；

 

2）使用跨越网络、文件和日志域的复杂查询进行扩展；

 

3）作为开源项目的一部分提供相应产品的连接器。

三、STIX Patterning


很多人通常认为Indicator指示器只有IP、域名、Hash和URL等内容，但是STIX 2 Patterning也是STIX Indicator指示器的一部分，它实现STIX匹配信息的功能，这部分内容经常容易被忽略【3】，STIX Patterning支持多条件的、多类型实体的复杂逻辑匹配。




STIX Patterning的示例如下：

 

[url:value = 'http://www.testaddress.com'] OR [ipv4-addr:value = '192.168.122.84']

 

STIX Shifter支持以STIX 2 Patterning作为输入，并“查找”与存储网络安全数据的各种产品中的模式相匹配的数据，这类产品包括：SIEM、终端管理系统、威胁情报平台、编排平台、网络控制点、数据湖等。

 

为了屏蔽不同来源安全数据内容差异，STIX Patterning支持转换输出为STIX 2 Observation格式。这里面涉及到对单个可观测数据的描述，即STIX Cyber-observable实体（SCO），以及相应的匹配逻辑。

 

STIX Cyber-observable实体（SCO）即之前的CybOX规范，在STIX 2.0中已经将CybOX进行了合并【4】。

 

在STIX Cyber-observable实体（SCO）中对Artifact、AS、邮件、文件、域名、注册表、MAC、互斥体、流量、进程、软件、用户账户、Window注册表、证书等内容进行了较为详细的定义和描述。



常用的STIX Cyber-observable实体（SCO）属性有created、modified、first_observed、last_observed、number_observed等。

 

STIX Observation的示例如下：

 

{  "id": "observed-data--cf2c58dc-200e-49e0-b6f7-e1997cccf707",  "type": "observed-data",  "created_by_ref": "identity--3532c56d-ea72-48be-a2ad-1a53f4c9c6d8",  "objects": {    "0": {      "type": "network-traffic",      "src_port": 567,      "dst_port": 102,      "src_ref": "1",      "dst_ref": "2"    },    "1": {      "type": "ipv4-addr",      "value": "192.168.122.84"    },    "2": {      "type": "ipv4-addr",      "value": "127.0.0.1"    },    "3": {      "type": "url",      "value": "www.testaddress.com"    }  }}

STIX Shifter希望通过STIX Patterning和STIX Observation来克服构建跨平台安全分析所面临的跨域数据的清洗和规范化等问题。

 

值得注意的是，听起来，STIX Patterning与SIGMA项目存在一定的相似性，依照SIGMA的Slogan，“Sigma is for log files what Snort is for network traffic and YARA is for files（Sigma对于日志文件的作用，就像Snort对于网络流量，以及YARA对于文件）”【5】。但STIX Patterning的目标是包含全部的三个基本安全数据源类型：网络、日志和文件，并允许创建跨域的复杂查询和分析，实现跨SIEM、端点、网络和文件级别的复杂模式搜索。




四、STIX Shifter Connector


Connector是STIX Shifter项目库中的一个功能模块，其主要实现接口：

 

（1）数据源查询和结果集转换；

 

（2）数据源通信。

 

Translation转换函数和Transmission传输函数的组合允许单个STIX Pattern为每个支持的数据源生成本地查询。每次查询后会将结果转换为STIX对象，并允许将不同源的查询数据结果进行汇总和统一描述。

 

通过Connector映射文件可以定义每个Connector支持STIX对象和属性，目前STIX Shifter已为多个安全厂商的多款安全产品提供Connector支持，如下图所示。

STIX Shifter开源项目的详细程序结构如下图所示：



可以看到，STIX Shifter提供了多个功能函数：

 

（1）Translate转换，不同的数据源可能使用不同的查询语言和逻辑，该命令将STIX Patterns转换为数据源查询，并将JSON格式的数据源结果转换为绑定的STIX Observation对象，STIX对象格式结构如图所示。



（2）Transmit传输，该命令允许STIX Shifter连接到存储网络安全数据的产品，连接和身份验证凭证被传输到数据源API，STIX Shifter可以调用ping数据源、查询、删除查询、检查查询状态和获取查询结果等操作。

 

（3）Execute执行，该命令提供了一种方法来测试完整的STIX Shifter流程：通过CLI命令行接口来执行命令。


5.1 Translate转换


第一个场景：将STIX Pattern转换为本地数据源查询。

 

输入如下（STIX 2 Pattern）：

 

# STIX Pattern:"[url:value = 'http://www.testaddress.com'] OR [ipv4-addr:value = '192.168.122.84']"
 

输出（本地数据源查询）：

 

# Translated Query (using SQL as an example):"SELECT * FROM tableName WHERE (Url = 'http://www.testaddress.com') OR ((SourceIpV4 = '192.168.122.84' OR DestinationIpV4 = '192.168.122.84'))"
 

在终端命令行下，导航到Python3环境，Translate转换查询格式如下：

 

stix-shifter translate <MODULE NAME> query "<STIX IDENTITY OBJECT>" "<STIX PATTERN>" "<OPTIONS>"

 

或者可以从源代码运行CLI命令，在终端中导航到STIX Shifter根目录，查询格式如下：

 

python main.py translate <MODULE NAME> query "<STIX IDENTITY OBJECT>" "<STIX PATTERN>" "<OPTIONS>"

 

其中模块名指的是STIX Shifter中包含Connector代码文件夹的名称，其中STIX identity对象仅在将数据源结果转换为STIX时使用，因此可以作为空对象传递给查询转换调用。

 

以Qradar Connector为例：

 

python main.py translate qradar query "{}" "[url:value = 'http://www.testaddress.com'] OR [ipv4-addr:value = '192.168.122.84']"

 

第二个场景是将JSON数据源查询结果转换为可观察对象的STIX bundle。

 

输入：JSON数据源查询结果。

 

# Datasource results (in JSON format):[    {        "SourcePort": 567,        "DestinationPort": 102,        "SourceIpV4": "192.168.122.84",        "DestinationIpV4": "127.0.0.1",        "Url": "www.testaddress.com"    }]
 

输出：可观察对象的STIX bundle。

 

# STIX Observables{    "type": "bundle",    "id": "bundle--2042a6e9-7f34-4a03-a745-502e358594c3",    "objects": [        {            "type": "identity",            "id": "identity--3532c56d-ea72-48be-a2ad-1a53f4c9c6d8",            "name": "YourDataSource",            "identity_class": "events"        },        {            "id": "observed-data--cf2c58dc-200e-49e0-b6f7-e1997cccf707",            "type": "observed-data",            "created_by_ref": "identity--3532c56d-ea72-48be-a2ad-1a53f4c9c6d8",            "objects": {                "0": {                    "type": "network-traffic",                    "src_port": 567,                    "dst_port": 102,                    "src_ref": "1",                    "dst_ref": "2"                },                "1": {                    "type": "ipv4-addr",                    "value": "192.168.122.84"                },                "2": {                    "type": "ipv4-addr",                    "value": "127.0.0.1"                },                "3": {                    "type": "url",                    "value": "www.testaddress.com"                }            }        }    ]}

第三类场景是CLI命令

 

在终端命令行下，导航到Python3环境，Translation查询结果格式如下：

 

stix-shifter translate <MODULE NAME> result '<STIX IDENTITY OBJECT>' '<LIST OF JSON RESULTS>'

 

或者可以从源代码运行CLI命令，在终端中导航到STIX Shifter根目录，查询格式如下：

 

python main.py translate <MODULE NAME> result '<STIX IDENTITY OBJECT>' '<LIST OF JSON RESULTS>'

 

其中模块名指的是STIX Shifter中包含Connector代码文件夹的名称，其中STIX identity对象仅在将数据源结果转换为STIX时使用，因此可以作为空对象传递给查询转换调用。

 

以Qradar Connector为例：

 

python main.py translate qradar results \'{"type": "identity", "id": "identity--3532c56d-ea72-48be-a2ad-1a53f4c9c6d3", "name": "QRadar", "identity_class": "events"}' \'[{"sourceip": "192.0.2.0", "filename": "someFile.exe", "sourceport": "0123", "username": "root"}]' --stix-validator
 

最后的--stix-validator标志将对返回的STIX对象进行验证，以确保返回结果符合STIX2标准。或者可以以选项字典'{ "stix_validator": true }'传入。

 

第四类场景是使用输入文件对结果进行转换

 

创建一个JSON文件，其中包含要转换的结果。可以使用标准输入在结果转换调用中使用该文件。

 

results.json文件内容如下所示：

 

[    {        "starttime": "1563892019916",        "endtime": "1563892019916",        "sourceip": "9.21.122.127",        "sourceport": "100",        "identityip": "0.0.0.0",        "destinationip": "127.0.0.1",        "destinationport": "800",        "username": "admin",        "protocol": "tcp"    }]
 

运行命令如下：

 

python main.py translate qradar results '{"type": "identity","id": "identity--f431f809-377b-45e0-aa1c-6a4751cae5ff","name": "QRadar","identity_class": "system"}' '' < /path/to/file/results.json


5.2 Transmit传输


在该命令中，首先介绍的是连接和配置对象。

 

STIX Shifter期望在transmission传输调用期间传入连接和配置对象，连接对象包含要连接的数据源主机地址和端口，以及可选的服务器名称指示器（SNI）和自签名证书。

 

其中，连接对象包含连接到特定数据源所需的信息，其中host和port字段是必需字段：

 

{    "host": <Host URL or IP address>,    "port": <Port>,    "sni": <Server name indicator>,    "selfSignedCert": <false or Certificate>,    "cert": <Certificate (if required)>,    "resultSizeLimit": <Results limit to come back from the data source query>,    "timeRange": <Default query time range in minutes>,    "options": {<Any required options specific to the particular data source>}}
 

配置对象包含的auth键值存储数据源的身份验证信息，在身份验证中存储的密钥和值取决于数据源的身份验证要求。

 

{    "auth": {        "username": <Username>,        "password": <Password>    }}

{    "auth": {        "tenant": <Tenant>,        "clientId": <Client ID>,        "clientSecret": <Client Secret>    }}

{    "auth": {        "SEC": <SEC Token>    }}

{    "auth": {        "token": <Security Token>    }}

{    "auth": {        "accountId": <Account ID>,        "apiKey": <API Key>    }}

然后介绍的是Transmit传输函数。

 

该函数提供了几个功能：ping、query、status（对于异步数据源）、results、delete（如果数据源支持）和is_async。

 

每个Transmit传输函数都接受公共参数：模块名、连接对象和配置对象。模块是指STIX Shifter中包含连接器代码的文件夹名称。每个CLI命令都可以在STIX Shifter根目录下的终端运行。

 

任何失败的Transmit传输函数调用都将以一下格式返回错误：

 

{'success': False, 'error': <Error message reported by API>, 'code': <Error code>}

其中，ping命令是使用数据源API来进行ping连接，其CLI命令如下：

 

stix-shifter transmit <MODULE NAME> '<CONNECTION OBJECT>' '<CONFIGURATION OBJECT>' ping


输出：

 

{'success': True}

 

query命令是使用数据源API向连接提交查询，其CLI命令如下：

 

stix-shifter transmit <MODULE NAME> '<CONNECTION OBJECT>' '<CONFIGURATION OBJECT>' query <NATIVE DATA SOURCE QUERY>


输出：

 

{'success': True, 'search_id': <SEARCH ID>}


异步数据源通常会返回由API响应提供的搜索ID。如果API没有返回搜索id，如同步数据源，那么搜索id将在传输模块中定义。

 

status命令是使用数据源API查找基于查询调用返回的search_id，这只适用于异步数据源，在执行查询调用后不会立即返回结果，其CLI命令如下：

 

stix-shifter transmit <MODULE NAME> '<CONNECTION OBJECT>' '<CONFIGURATION OBJECT>' status <SEARCH ID>

 

输出：

 

{'success': True, 'status': <STATUS>, 'progress': <QUERY PERCENTAGE COMPLETE>}


状态可以是：COMPLETED, ERROR, CANCELLED, TIMEOUT 或 RUNNING。根据数据源的不同，进度可能返回小于100，同时仍显示“已完成”的状态。

 

results命令是使用数据源API，根据搜索ID、偏移量和长度获取返回结果，其CLI命令如下：

 

stix-shifter transmit <MODULE NAME> '<CONNECTION OBJECT>' '<CONFIGURATION OBJECT>' results <SEARCH ID> <OFFSET> <LENGTH>

 

输出：

 

{'success': True, 'data': [<QUERY RESULTS>]}


OFFSET和LENGTH控制在查询结果中返回哪些数据页和行。

 

result_stix命令是使用数据源API根据搜索ID、偏移量和长度获取查询结果，并转换为STIX bundle对象，其CLI命令如下：

 

stix-shifter transmit <MODULE NAME> '<CONNECTION OBJECT>' '<CONFIGURATION OBJECT>' results_stix <SEARCH ID> <OFFSET> <LENGTH> '<STIX IDENTITY OBJECT>'


输出STIX bundle对象。

 

OFFSET和LENGTH控制在查询结果中返回哪些数据页和行。

 

is_async命令是检查数据源连接是否异步，其CLI命令如下：

 

stix-shifter transmit <MODULE NAME> '<CONNECTION OBJECT>' '<CONFIGURATION OBJECT>' is_async


输出True或False。

 

5.3 Execute执行


execute命令测试translation-transmission流的所有步骤，包括：

 

（1）STIX pattern 被转换为一个或多个本地数据源查询列表（使用 translate query调用）；

 

（2）通过translate query调用，列表中的每个translate query被发送到数据源中；

 

（3）如果数据源是异步的，则transmit status调用每个查询，否则流转到下一步；

 

（4）transmit result调用每个查询（使用第（2）步中返回的查询ID）。如果返回数据，则生成JSON对象添加到列表中；

 

（5）JSON结果列表被转换为带有translate query调用的STIX bundle对象，其中包含STIX identity对象和observed-data对象。

 

其CLI命令如下：

 

stix-shifter execute <TRANSMISSION MODULE NAME> <TRANSLATION MODULE NAME> '<STIX IDENTITY OBJECT>' '<CONNECTION OBJECT>' '<CONFIGURATION OBJECT>' '<STIX PATTERN>'


命令中可以添加选项--debug，以查看更多日志，如下：

 

stix-shifter execute <TRANSMISSION MODULE NAME> <TRANSLATION MODULE NAME> '<STIX IDENTITY OBJECT>' '<CONNECTION OBJECT>' '<CONFIGURATION OBJECT>' '<STIX PATTERN>' --debug

 

此外，也可以更改最大返回结果数，通过添加--results选项，该选项在CLI命令末尾补充整数，以显示返回搜索结果中的最大数量（默认为10）。

 

stix-shifter execute <TRANSMISSION MODULE NAME> <TRANSLATION MODULE NAME> '<STIX IDENTITY OBJECT>' '<CONNECTION OBJECT>' '<CONFIGURATION OBJECT>' '<STIX PATTERN>' --results 50


另外，还可以将CLI命令将输出的STIX结果定向到一个JSON文件中，如下：

 

stix-shifter execute <TRANSMISSION MODULE NAME> <TRANSLATION MODULE NAME> '<STIX IDENTITY OBJECT>' '<CONNECTION OBJECT>' '<CONFIGURATION OBJECT>' '<STIX PATTERN>' > results.json


5.4 Modules 模块


modules命令将返回现有连接器的JSON，以及查询转换中使用的定制语言，其CLI命令如下：

 

python main.py modules


返回：

 

{    "qradar": {        "flows": {            "language": "stix",            "default": true        },        "events": {            "language": "stix",            "default": true        },        "aql": {            "language": "aql",            "default": false        }    },    "security_advisor": {        "default": {            "language": "stix",            "default": true        }    },    ...}

在上述示例中，QRadar连接器可以使用三种定制语言：flows, events 和aql，当使用Security Advisor时，连接器只使用一种定制语言。大多数定制语言都会使用STIX，因为它们将STIX pattern转换为本地查询。

 

最后输出STIX bundle对象。


五、总结


STIX Shifter通过规范化数据集和存储库，在使用原生APIs时增加使用价值，进而构建全面的双边连接，实现跨网络、文件和日志域的复杂查询和分析。
