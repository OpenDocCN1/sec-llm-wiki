这个程序在linux机器上是没有执行成功.

$ qemu-arm -L /usr/arm-linux-gnueabihf/ ./count./count: Invalid ELF image for this architecture

我们直接打远程就好.


程序的逻辑 是 通过 srand(time(0)) 生成 一个随机数 进行3 次 "%100"处理，并同时将3次  " %100"后的值进行 相加，然后我们输入一个数值，结果要与 它相等。

而 0x400920函数 是一个后门函数，

__int64 sub_400920(){  return system("/bin/sh");}

如果要执行它，需要满足  v8 == 0x12235612，而从read(0LL, &v7, 0x6ELL) 这 我们可向v7栈地址处起，最多可输入 0x6E字节数据，

而从ida 中 我们可得到 v7 距离v8的距离是  0xDC-0x78==0x64.

  __int64 v7; // [xsp+78h] [xbp+78h]  int v8; // [xsp+DCh] [xbp+DCh]

即

我们可构造payload： 'a'*0x64+p64(0x12235612)

从而实现 v8=0x12235612 ，满足if 条件，执行后门函数sub_400920(),拿到shell。

环境安装

arm结构的程序时不可以直接在linux系统上运行的。

我们首先得需要安装下相关环境.

首先我们安装环境.

sudo apt install qemu-usersudo apt install g{cc,++}-arm-linux-gnueabihfsudo apt install gdb-multiarch
ubuntu16.04测试成功.

ubuntu18.04测试成功.

ubuntu20.04 报错了.//相关依赖问题，暂时不着急.后面再解决吧.

安装默认装到/usr/中了.

运行程序.

$ qemu-arm -L /usr/arm-linux-gnueabihf/ ./chall

easyarm那题,libc_base加载地址是0xff7c5000,当然这是本地的.远程就不一定了.

除了通过leak远程libc的方式之外,还可以采用爆破0xff后面的三位去爆破,直接获得shell.


16*16*16=4096次.

其实一般说0xff后面的值远程应该是<=7的,所以2048的次数甚至更少就可以getshell.
