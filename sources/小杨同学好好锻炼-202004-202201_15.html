前言

当打远程的时候，常会遇到远程libc版本本本地不同，导致调试起来很头疼，

而glibc-all-in-one和patchelf工具是个很得力的助手。

glibc-all-in-one下载

sudo git clone https://github.com/matrix1001/glibc-all-in-one.gitcd glibc-all-in-one/

iscc2021pwn2

修改elf程序的动态链接库。

比如说 iscc2021的pwn2.它远程的libc是2.27.但是可以double的版本。而自己的系统是更新后的，没办法double free。这个时候就需要更换动态链接库。

下载对应动态链接库:

$ sudo ./download 2.27-3ubuntu1_amd64


复制一份做对比。

$ cp isccpwn2 isccpwn2_backup

将供调试用的dbg解压到/home/ymt/glibc-all-in-one/libs/2.27-3ubuntu1_amd64/.debug中。//使得gdb调试的时候可以使用bin 和heap命令。

命令：~/glibc-all-in-one/debs$ extract libc6-dbg_2.27-3ubuntu1_amd64.deb /home/ymt/glibc-all-in-one/libs/2.27-3ubuntu1_amd64/.debug
Keywords for file libc6-dbg_2.27-3ubuntu1_amd64.deb:mimetype - application/x-debian-packageembedded filename - debian-binaryembedded filename - control.tar.xzembedded filename - data.tar.xzmimetype - application/vnd.debian.binary-packageformat - arKeywords for file /home/ymt/glibc-all-in-one/libs/2.27-3ubuntu1_amd64/.debug:

然后利用patchelf工具修改elf程序所需的动态链接库

$ patchelf --set-interpreter /home/ymt/glibc-all-in-one/libs/2.27-3ubuntu1_amd64/ld-2.27.so ./isccpwn2$ patchelf --replace-needed libc.so.6 /home/ymt/glibc-all-in-one/libs/2.27-3ubuntu1_amd64/libc-2.27.so ./isccpwn2

看vmmap发现下载的动态链接库是加载成功了，
