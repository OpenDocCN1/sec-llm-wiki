pwn3_letter

这题没有开启任何保护。

我们将它放入ida

int __cdecl main(int argc, const char **argv, const char **envp)
{
 char buf[16]; // [rsp+0h] [rbp-10h] BYREF

 init(argc, argv, envp);
 write(1, "In old days, the letter is asked to be short.\n", 0x2EuLL);
 write(1, "how much character do you want to send?\n", 0x28uLL);
 read(0, buf, 0x10uLL);
 LODWORD(length) = atoi(buf);     //整形溢出
 if ( (int)length > 15 )
{
   write(1, "sorry, too long.\n", 0x11uLL);
}
 else
{
   read(0, buf, (unsigned int)length);   //栈溢出
   write(1, "hope the letter can be sent safely.\n", 0x24uLL);
}
 return 0;
}

我们可以很容易看出这里存在整形溢出和栈溢出漏洞，又因为没有开启NX保护，所以我们可以 写一个shellcode即可。

但这里还需要注意的一点就是 这个程序禁用了 一些系统函数。

我们发现我们不可以 system("/bin/sh") 去getshell ，而只能使用orw去读取flag。

所以我们的思路可以是这样，首先输入一个负数，让它经过atoi函数转化后 以0x00007fff ffffffff 的形式存放在buf里面，然后取它的低双字部分(对应后面的8个16进制)，使它是 jmp rsp对应的地址。

但这里可能会有人疑问，我们如何取确认该输入怎样的负数才能达到要求，我是首先写一个exp：

shellcode = '''
jmp rsp
'''
asm(shellcode)

然后就可以在gdb种看到

即jmp rsp 汇编指令在计算机中是以 0xe4ff 形式存在的。

我们这样 0xffff ffff -0xe4ff +1 =  4294908673。可是如果我们输入-4294908673的话，在程序代码的第十行 if ( (int)length > 15 ) 就会满足if条件了。为了我们得到的  (int)length <15. 我们在这样操作。0xffff ffff -0xf000 e4ff +1 =  268376833.即我们输入 -268376833。这样的话，它经过atoi函数转化后是 RAX  0xffffffff f000e4ff。而我们length又只取它后面的双字(对应8个16进制) 即f000e4ff。然后它作为有符号整数与15作比较。最前面的f化成二进制是 0b1111最前面代表负数所以肯定小于15.不满足if条件，所以会继续向下执行。read(0,buf,0xf000e4ff)，存在栈溢出。

后面就是正常思路了。

然后我们构造payload ：'a'*0x18+p64(0x60108C)+asm(shellcode))

这里的shellcode 是我们自己构造的orw（open read write）的系统调用汇编指令。

可以看出 0xe4ff 已经成功转化成 jmp rsp 汇编指令了。

分析

这题含有栈溢出漏洞和格式化字符串漏洞，按我们的正常的思路第一步是可以通过格式化字符串漏洞去leak出 libc地址的，然后就可以拿到onegadget的真实地址，进而再通过栈溢出去将它覆盖掉返回地址拿到shell。不过这题只有一次输入机会，那么这里其实还考察了绕过pie的其中一种方式 低字节覆盖。开启pie后 程序的最低 12 bit(对应3个16进制)是不变的，当覆盖最低的 1 个字节(2个16进制)，就回返回到其它相近的地址，后面步骤就是正常的思路步骤了。

正常的话是会返回到0x55905cb941bf这里的

然后我们观察下start地址，main地址以及vuln地址，发现如果覆盖一字节是可以覆盖main以及vuln地址的，这里我们选择返回到vuln地址。
