# 2019小米IoT安全峰会-王书魁《AIoT自动化评估探索与实践》

此次大会的第四个重磅议题来自小米安全技术负责人-王书魁，他给大家带来的议题是《AIoT 自动化评估探索和实践》。

![](../Images/1f0ecd0a7295e40aa86467a549f712d8.png)**AIoT 自动化评估探索和实践**

![](../Images/44120055019f226a81b1e0f9efcfbdb1.png)

今天的分享主要讲四个部分：第一个讲历程，即这几年小米AIoT安全是怎么发展的，第二个讲原因，为什么要做AIoT自动化评估，第三讲探索，最后是实践，我们是怎么做AIoT自动化评估的。

最初小米并不专注于做IoT，我们主要做手机、路由器、电视等硬件产品，虽然安全人员规模不是很大，但能够覆盖到每一个产品，保障其安全和隐私。之后随着小米不断发展，产品越来越多，IoT平台也在不断壮大，接入了更多的智能产品。因此，我们也对安全人员做了相应增加，通过建立标准的评估体系做到保障每一个产品的安全及隐私。

但之后这个平台规模变得更大，接入了数量庞大、品类众多的产品，整个平台共有2000多款产品。这么多的产品、这么大的平台，我们该如何保证它的安全？仅有标准化体系是远远不够的，我们研发了现在的AIoT自动化评估系统，用以保障整个平台中产品的安全和隐私。目前通过AIoT自动化评估覆盖的小米自有和生态链产品共有500多款。

![](../Images/aadfc6b0eaeb85f35d53122ac3fe3868.png)

那么我们为什么要做自动化评估？第一，我们评估的自有品牌和生态链产品有500多款，平台上还有大量的第三方产品，产品很多，人很少，且每个产品的功能迭代都是非常快的，如果单靠人力的方式很难解决问题。第二，整个评估面会越来越多，最开始我们聚焦在安全方面，随着公司业务以及整个社会在不断发展，我们需要把很多精力同时关注到隐私方面，现在政策、技术不断更新，供应链不断增长，这些因素都要求着我们要多方面地做好安全和隐私评估。第三，现在很多IoT产品除了正常功能外会有一些低频的操作，比如打点和数据统计，如果仅是短期的评估，是不太容易发现这些功能的存在，可能会有一些潜在风险，我们需要通过持续的评估来发现其中存在的安全和隐私风险。第四，评估周期长，IoT评估涉及的技术面很多，难度也相应比传统的web技术高一些，那么每做一款产品的评估周期是相对长的，我们需要有能力来缩短评估周期，降低评估成本。以上这些原因都推动了我们去做AIoT自动化评估。

那小米安全团队在AIoT自动化评估上具体做了哪些探索？

![](../Images/243f3769ef98066a55ef7110a85e2925.png)

首先我们来看看AIoT产品的典型应用场景，物联网设备首先接入到本地的网络，进而连入互联网云端，通过移动设备和云端的联动能够对物联网设备进行交互。物联网设备、移动设备、云端三个方面是通过通讯网络连到一起做互联互通，在这种典型场景下会存在什么样的威胁，我们可以通过如下四个方面做威胁分析。第一物联网设备，硬件、系统、组件、服务都可能面临很多安全的风险和隐私风险。第二移动端也会面临类似的风险。第三云端，这个层面比较偏传统，这里不做过多的阐述。最后是通讯层面，你用了什么协议，是不是有加密的，是不是有认证和校验，都会面临风险。其实还有一个层面就是隐私方面，我们需要评估产品是否涉及到隐私数据，这些隐私数据是否满足合规的需求。

![](../Images/7cfa5b91d1f4b8cadb2e54d19e3bf134.png)

通过前面的威胁分析，我们就能够明确AIoT自动化评估系统的功能需求，首先是自动化评估系统最基本的要求是要有自动化的能力，在这个层面细分成五个：评估简单、一键操作、具备7×24小时长期的监控评估能力以应对低频的风险需求、具备智能报告生成的能力以及深度学习的能力。

其次是安全评估，除了传统的资产识别、端口扫描、漏洞扫描、流量分析，包括对加密流量分析的能力，因为IoT很多用了自己的私有协议，大部分是通过加密的方式来做。还有基线检查、链路劫持、Fuzz，APK扫描。

第三个是隐私评估，因为不同的国家或者不同地区的政策不一样，我们需要有针对不同国家和地区制定不同的隐私评估策略，之后还需要对这些数据做分析，分析这些数据是否满足我们的隐私合规需求。因为小米很多产品以及手机会销往全球海外很多地区，如果每个地区都去安排人力在当地做评估这个成本很大，所以我们需要具备在同一个地区，比如在北京可以评估销往全球产品能力。隐私这块，除了既定规则之外，我们还需要知道哪些规则或者哪些数据会有潜在的风险，因此，需要具备一些AI方面的能力，帮助我们发现潜在的危险和风险。

第四是网络模拟，我们要支撑跨区域的隐私评估，也就是网络模拟需要能够模拟不同国家的网络，满足我们在一个地区就能够评估全球的产品需求。同时还需要能够模拟网络带宽、延迟、丢包率等，协助业务进行功能测试。

  

![](../Images/5a631c1b320a5e69e2031c3d6dbbfbde.png)

回到这个图，刚才讲到它的典型场景以及它面临的威胁，还讲了AIoT自动化评估需要具备什么样的功能，那我们怎么构建这个评估模型呢？我们分成了三个方面去构建整个自动化评估模型，第一个是我们的本地网络，因为大部分IoT产品都是首先通过WiFi等进一步接入到互联网中，我们可以在这个关键节点上做自动化评估的事情。因为小米有路由器，我们基于路由器做路由引擎，它能够实现流量采集、流量分析、流量劫持，还可以做端口和漏洞的扫描。我们还需要评估不同地区的产品，可以在路由器上实现区域代理的能力以及网络模拟功能。其实我们还可以建立网络隧道实时下发评估策略，并且可以很轻易的更新策略来满足不断变化的评估需求。  

第二方面是手机端，有很多产品是通过手机端接入到整个互联网的。同时手机端也可以做IoT产品的控制，所以在手机端上我们可以做比如流量的采集、分析和劫持，包括漏洞检测、区域代理、网络模拟等等功能。

第三方面是云端，为了做更多的事情还需要具备云端的引擎。通过云端引擎我们能够对APK以及固件进行扫描，要具备静态、动态的分析能力，来发现这些APK文件和固件中是否存在安全的隐患或者隐私的风险。我们还可以把流量搜集到云端，对流量进行详细的分析。云端还可以做区域代理的网络搭建，策略的下发。同时，网络层也可以做隧道去满足刚才说的动态更新策略的需求。此外，通过网络隧道，还可以做漏洞扫描。

![](../Images/b47d4195c65c16c3cedeba2840556515.png)

这是我们通过探索需求所构建的模型，小米本身有手机和路由器产品，我们能够很轻易的把手机和路由器变成评估引擎就可以满足刚才说的IoT自动化测试的需求。

![](../Images/6639e7b81aa0f2ad609389e7113ed966.png)  

这个是我们关于MiEye产品的整体架构。最底层是待评估设备或者文件，设备包括IoT产品、手机和电视等，文件包括APK和固件。之上一层是刚才提到的两个评估引擎，一个是路由器，一个是手机，我们可以通过这两个评估引擎做端口扫描、网络抓包、网络模拟等等。在之上是和云端对接的API层。最上层是云端，它能做的事情更多一些。我们通过Web管理台管理整个MiEye的平台。

刚才主要讲了架构，我们抽几个点具体讲解一下。

![](../Images/8afa5854d10a91e13056a5ea30c9183a.png)

第一个加密流量分析，大部分产品的通讯都已经进行了加密，但是我们要怎么分析加密流量的数据？第一个做证书的劫持，很早就有相关的技术实现这个能力，我们可以直接用，但是还需要做到智能劫持。一个IoT产品如果需要访问互联网，如果不断地做劫持会影响整个产品的正常功能使用，测试人员在使用时就会出现问题，所以我们在劫持失败的时候跳过劫持，这样就不会影响正常功能的使用。如果正常的劫持手段无法使用，我们可以把证书植入到待评估的设备中，通过证书去TLS还原。还有不少产品有自有或者私有的协议，我们对协议进行分析，通过技术手段获取加密的流量，进一步可以对流量进行分析，以及做漏洞扫描等。

![](../Images/b018c5990940004fb9d2a3cfb44dd844.png)

第二个多国节点，我们在不同的地区部署网络结点，这样就可以通过我们的平台一键让待评估设备接入到我们销往这个国家的网络，通过这种方式满足评估的需求。

最后一个是要实现复杂的网络环境模拟，有的IoT设备对网络的实时性要求比较高，不是所有的网络环境的带宽都特别充足的，我们的设备需要应对复杂的网络环境，来避免对正常的功能产生影响。我们可以通过MiEye系统模拟很复杂的网络环境，在 Linux 下通过 Netem+TC 就可以满足这块的需求。

![](../Images/e1e5c06bae4c73e4fd334b546d1a5ceb.png)

这是我们在目前整个系统所实现的功能列表，目前大部分功能都已经实现，还有部分功能在研发和优化中。
