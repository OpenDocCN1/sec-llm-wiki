# 漏洞复现 | MongoDB未授权访问

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=Mzg3MTY3NzUwMQ==&mid=2247483917&idx=1&sn=c8f6a42613a32e0a9b366a8943b51e1a&chksm=cefba95ff98c2049f7a3a799116cea5c3599c2ada240c74b1a1ffbb29d1eed5d1017d19b27d0&scene=126&sessionid=1681655051#rd](http://mp.weixin.qq.com/s?__biz=Mzg3MTY3NzUwMQ==&mid=2247483917&idx=1&sn=c8f6a42613a32e0a9b366a8943b51e1a&chksm=cefba95ff98c2049f7a3a799116cea5c3599c2ada240c74b1a1ffbb29d1eed5d1017d19b27d0&scene=126&sessionid=1681655051#rd)

  
  

漏洞简介

**开启MongoDB服务时不添加任何参数，默认是没有权限验证的**，登陆的用户可以通过默认端口无需密码直接远程访问数据库，并进行增删改查操作。

#### 漏洞成因

在刚安装完毕的时候MongoDB都默认有一个admin数据库,此时admin数据库是空的,没有记录权限相关的信息！**当admin.system.users一个用户都没有时，即使mongod启动时添加了—auth参数,如果没有在admin数据库中添加用户,此时不进行任何认证还是可以做任何操作**(不管是否是以—auth  参数启动),直到在admin.system.users中添加了一个用户。**加固的核心是只有在admin.system.users中添加用户之后，mongodb的认证,授权服务才能生效。**

#### 环境搭建

这里用docker进行搭建，首先再docker里搜索MongoDB的镜像，命令如下：

```
docker  search MongoDB
```

结果如下图：

![](../Images/fa04261ae84f5651ec670c01f0696127.png)

拉取镜像：

```
docker pull mongo
```

![](../Images/d0c91b81941cdd6d7e1aa25ef5e1d77e.png)

 创建一个新的容器并运行一个命令:

```
docker run -d -p 27017:27017 --name mongodb mongo
```

![](../Images/6aa4279b06c579558b027a8d178a050f.png)

#### 本机未授权连接测试

这里使用 NoSQLBooster，官方下载地址为：

https://nosqlbooster.com/downloads

下载好后尝试连接

![](../Images/009cedf8df67abe1ba0e78ac7680a81e.png)

发现连接失败=-=。

![](../Images/46ff216292fb301b9956641df121fe3a.png)

猜测是防火墙原因，关掉测试机防火墙，命令如下：

```
systemctl stop firewalld
```

连接成功！

![](../Images/330d22cb59b998f7cca91a8b3b77a925.png)

#### 安全建议

为MongoDB添加认证：MongoDB启动时添加--auth参数、**为MongoDB添加用户**。
