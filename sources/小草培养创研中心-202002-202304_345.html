canary保护

在程序加了 canary 保护之后，如果我们读取的 buffer 覆盖了对应的值时，程序就会报错，而一般来说我们并不会关心报错信息。而 stack smash 技巧则就是利用打印这一信息的程序来得到我们想要的内容。这是因为在程序启动 canary 保护之后，如果发现 canary 被修改的话，程序就会执行 __stack_chk_fail 函数来打印 argv[0] 指针所指向的字符串，正常情况下，这个指针指向了程序名。其代码如下

void attribute ((noreturn)) __stack_chk_fail (void)
{
__fortify_fail ("stack smashing detected");
}
void attribute ((noreturn)) internal_function __fortify_fail (const char msg)
{
/ The loop is added only to keep gcc happy.  /
while (1)
__libc_message (2, "* %s : %s terminated\n",
msg, __libc_argv[0] ?: "");
}

stack smash泄露canary在较高的glibc版本不存在如（glibc-2.31），在较低的glibc版本存在，如（glibc-2.24），

pwntools

Cyclic Pattern

Cyclic pattern是一个很强大的功能，大概意思就是，使用pwntools生成一个pattern，pattern就是指一个字符串，可以通过其中的一部分数据去定位到他在一个字符串中的位置。

在我们完成栈溢出题目的时候，使用pattern可以大大的减少计算溢出点的时间。

用法：

cyclic(0x100) # 生成一个0x100大小的pattern，即一个特殊的字符串
cyclic_find(0x61616161) # 找到该数据在pattern中的位置（或者是cyclic -l 0x61616161 ）
cyclic_find('aaaa') # 查找位置也可以使用字符串去定位

设置context

example：

context(os='linux', arch='amd64', log_level='debug')

arch:amd64/i386

log_level设置日志输出的等级为debug，这句话在调试的时候一般会设置，这样pwntools会将完整的io过程都打印下来，使得调试更加方便，可以避免在完成CTF题目时出现一些和IO相关的错误。

生成Shellcode

最好先设置context，如果没声明平则

shellcraft.i386.linux.sh()   #32位
shellcraft.amd64.linux.sh()  #64位
print(shellcraft.sh())       # 打印出shellcode

使用asm()函数进行汇编

print(asm(shellcraft.sh())) # 打印出汇编后的shellcode

pwntools目前的asm实现还有一些缺陷，比如不能支持相对跳转等等，只可以进行简单的汇编操作。如果需要更复杂一些的汇编功能，可以使用keystone-engine项目。

ELF操作

>>> e = ELF('/bin/cat')
>>> print hex(e.address)  # 文件装载的基地址
0x400000
>>> print hex(e.symbols['write']) # 函数地址,symbols,got,plt均是列表
0x401680
>>> print hex(e.got['write']) # GOT表的地址
0x60b070
>>> print hex(e.plt['write']) # PLT的地址
0x401680
>>> print hex(e.search('/bin/sh').next())# 字符串/bin/sh的地址字符串加（）

使用monkeyhex可以不用hex()

指定动态链接库版本

LD_PRELOAD命令可以指定动态库的加载，也就是说，可以指定glibc版本

比如我要运行a.out文件，指定它链接2.24版本的libc：

LD_PRELOAD=libc-2.24.so ./a.out

如果要使用gdb调试可以使用以下方法：

gdb your_program
(gdb) set environment LD_PRELOAD ./yourso.so
(gdb) start
