templates.equals(templatesImpl)调用的时候会获取Templates类中的所有方法，再通过遍历触发TemplatesImpl.getOutputProperties()。

现在就得想办法让templates.equals(templatesImpl)语句能够执行。在HashMap的put方法中存在key.equals(k)语句，如果key为templates对象，k为templatesImpl对象，则正好触发我们构造的调用链。

public V put(K key, V value) {    if (key == null)        return putForNullKey(value);    int hash = hash(key);    int i = indexFor(hash, table.length);    for (Entry<K,V> e = table[i]; e != null; e = e.next) {        Object k;        if (e.hash == hash && ((k = e.key) == key || key.equals(k))) {            V oldValue = e.value;            e.value = value;            e.recordAccess(this);            return oldValue;        }    }
    modCount++;    addEntry(hash, key, value, i);    return null;}

经过分析可知，k为上一个存入的变量，key为本次存入的变量。

但是想要执行key.equals(k)仍然需要满足以下几点：

  1. key与k的hash计算值要相等，满足前面的表达式才会进入后面的逻辑与

  2. 同时k与key的值不能相等，程序才能执行逻辑或后面的代码。

  3. 其中key的对象为templates，k的对象为templatesImpl。

所以HashMap对象如下创建：

    HashMap hashmap = new HashMap();    hashmap.put(templatesImpl, "templatesImpl");    hashmap.put(templates, "templates");

总结出需要的因素，开始一步步bypass。

k的对象是templatesImpl，该类是没有重写hashCode()，所以跟进发现其实是调用了JDK的hashCode()。

而key的对象是templates，也就是之前动态代理类AnnotationInvocationHandler，该类在调用invoke的时候用switch分支判断hashCode方法

返回hashCodeImpl方法

方法中用迭代器遍历memberValues变量，其中memberValueHashCode方法判断传入的类是否为数组，不为数组将调用hashCode()

这里补充一下JDK7u21的一个bug，“f5a5a608”字符串的hashCode返回值是0。

按照计算来看

127 * ((String)var3.getKey()).hashCode()

上述公式的计算结果为0

memberValueHashCode(var3.getValue())

而当var3.getValue()的值为templatesImpl的时候，其值也为0

从而达到两次put的hash值都为0


LinkedHashSet

由于需要通过反序列化触发漏洞的调用，所以需要在readObject方法里面有调用put()，HashSet中就有符合条件的readObject()，HashSet 的 readObject 反序列化方法中会循环往 map 对象中 put 值。所以我们创建的 LinkedHashSet 对象时，首先写入 templatesImpl 对象，然后写入 templates。LinkedHashSet能保证值加入的顺序。

最终调用链如下：

LinkedHashSet.readObject()  LinkedHashSet.add()    ...      TemplatesImpl.hashCode() (X)  LinkedHashSet.add()    ...      Proxy(Templates).equals()        AnnotationInvocationHandler.invoke()          AnnotationInvocationHandler.equalsImpl()            Method.invoke()              ...                TemplatesImpl.getOutputProperties()                  TemplatesImpl.newTransformer()                    TemplatesImpl.getTransletInstance()                      TemplatesImpl.defineTransletClasses()                        ClassLoader.defineClass()                        Class.newInstance()                          ...                            MaliciousClass.<clinit>()                              ...                                Runtime.exec()

阅读payload朋友们可以看到在创建恶意代码的之前有：

    HashMap map = new HashMap();    map.put(zeroHashCodeStr, "foo");

并在set.add之后有

map.put(zeroHashCodeStr, templates); // swap in real object

如果提前就将真实对象put进map，将会提前满足e.hash == hash的条件，从而提前触发调用链，引发异常。
