01 CAS简介

—

单点登录（Single Sign On , 简称 SSO ）是目前比较流行的服务于企业业务整合的解决方案之一， SSO 使得在多个应用系统中，用户只需要登录一次就可以访问所有相互信任的应用系统。CAS(Central Authentication Service)是一款不错的针对 Web 应用的单点登录框架，本文介绍了 CAS 的原理、协议、在 Tomcat 中的配置和使用，对于采用 CAS 实现轻量级单点登录解决方案的入门读者具有一定指导作用。

CAS 介绍

CAS 是 Yale 大学发起的一个开源项目，旨在为 Web 应用系统提供一种可靠的单点登录方法，CAS 在 2004 年 12 月正式成为 JA-SIG 的一个项目。CAS 具有以下特点：


  1. 开源的企业级单点登录解决方案。
  2. CAS Server 为需要独立部署的 Web 应用。
  3. CAS Client 支持非常多的客户端(这里指单点登录系统中的各个 Web 应用)，包括 Java, .Net, PHP, Perl, Apache, uPortal, Ruby 等。



02 从GitHub上下载项目并编译

—


CAS GitHub地址：https://github.com/apereo/cas-overlay-template/tree/4.1

由于需要clone的是4.1的分支，所以需要在克隆的时候加上-b参数

$ git clone -b 4.1 https://github.com/apereo/cas-overlay-template

下载后在pom.xml中更改cas的版本

<cas.version>4.1.5</cas.version>

更改完后利用目录中进行编译


03 搭建远程Debug环境

—


这里我就IDEA来debug远程Tomcat上的cas war包

首先需要更改main\webapp\WEB-INF\spring-configuration\propertyFileConfigurer.xml配置文件

将上述配置项更改成cas.properties文件的绝对路径地址

然后在IDEA中编译war包

将war包中的项目以工程的方式导入进去，并在Tomcat的catalina.bat文件中添加一行命令监听5555端口

set CATALINA_OPTS="-agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=5555"

在IDEA中配置Remote服务

然后启动Tomcat，在以debug方式启动Remote服务，显示：

Connected to the target VM, address: 'localhost:5555', transport: 'socket'

便是启动成功了。


04 漏洞分析

—

先来看项目的web.xml文件

/login路径匹配的servlet是名为cas的映射器

这里借助Freebuf中的一图

在SpringMVC中选择DispatcherServlet作为前端控制器

跟进流程找到DispatcherServlet.service方法，发现其中调用了this.doDispatch

而在doDispatch方法中调用了handler

经过debug后可以发现跟进了org.jasig.cas.web.flow.SelectiveFlowHandlerAdapter

当然也可以通过cas-servlet.xml文件中的p:supportedFlowId属性来定位handler

请求Dispatcher路径

发现SelectiveFlowHandlerAdapter继承了FlowHandlerAdapter类，继续跟进FlowHandlerAdapter.handle方法。

getFlowExecutionKey(request)程序执行到121行的此处会从request对象中取出execution参数中的值，随后将其赋值给flowExecutionKey并在125行带入resumeExecution方法中执行

跟进后发现到达了org.springframework.webflow.executor.FlowExecutorImpl.resumeExecution()

在91行使用parseFlowExecutionKey方法解析了execution参数的值

大致就是通过split分成两个值

在程序的第96行处调用了getFlowExecution(key)

跟进后发现在其58行处调用了this.transcoder.decode(encoded)进行解密

其调用了org.jasig.spring.webflow.plugin.EncryptedTranscoder.decode()方法。

触发反序列化的地方就在99行处的readObject()

但在序列化之前，程序调用了this.cipherBean.decrypt()进行解密，并通过GZIPInputStream初始化数据流赋值给in变量。最终导致readObject触发反序列化漏洞。


05 漏洞复现

—

编写一个加密过程，同时利用ysoserial来生成序列化

将payload复制并替换burp中的execution参数内容，同时经过url特殊字符编码后

弹出calc.exe

如果想构造有回显的payload：

org.springframework.webflow.context.ExternalContextHolder.getExternalContext()方法可以获取到上下文关联信息，然后通过getNativeRequest()方法获取request对象通过getNativeResponse()方法获取response对象。同时提及到org.springframework.cglib.core.ReflectUtils.defineClass().newInstance();加载payload。
