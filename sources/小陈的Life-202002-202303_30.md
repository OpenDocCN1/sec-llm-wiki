01漏洞描述

—

  

Apache Dubbo支持多种协议,官方推荐使用Dubbo协议.Apache Dubbo HTTP协议中的一个反序列化漏洞（CVE-2019-17564）,该漏洞的主要原因在于当Apache Dubbo启用HTTP协议之后，Apache Dubbo对消息体处理不当导致不安全反序列化，当项目包中存在可用的gadgets时即可导致远程代码执行.

  

  

  

02影响范围

—

  

2.7.0 <= Apache Dubbo <= 2.7.4.1

2.6.0 <= Apache Dubbo <= 2.6.7

Apache Dubbo = 2.5.x

04漏洞分析

—

一、找到数据包处理类  

程序会在第29行通过spring的bean创建服务  

![](../Images/73bf1c34547289bd243e29b087a70e96.png)

ClassPathXmlApplicationContext读取xml配置会在org.springframework.context.event.SimpleApplicationEventMulticaster类的doInvokeListener方法中调用dubbo的org.apache.dubbo.config.spring.extension.onApplicationEvent方法

![](../Images/1147d792e516683430466357b1bbbfae.png)

经过很长一段debug发现dubbo创建了org.apache.dubbo.remoting.http.tomcat.TomcatHttpServer对象

![](../Images/b44e6794601ffb7b7eef3ca226453371.png)

所绑定的Servlet类是org.apache.dubbo.remoting.http.servlet.DispatcherServlet

在该Servlet类中有个service方法，用来捕获数据包的。类似于HttpServlet的service一样。在代码的43行，程序调用了handler.handle(request, response);

![](../Images/8085e56543fc69d4619e08e5699574a7.png)

跟进之后跳转到org.apache.dubbo.rpc.protocol.http.HttpProtocol

![](../Images/f37ac09efdd9fd60453fc12a8fec70cb.png)

这里会判断数据包的方法是否用POST提交的  

并继续跟入177行的skeleton.handleRequest(request, response)

![](../Images/4f35e4b70171aadc867a05f8871d33db.png)

在第29行中调用了readRemoteInvocation，继续往下跟踪到了42行

![](../Images/9b58899baeefaec4933aa3c4749235e6.png)

在42行的this.createObjectInputStream方法创建了序列化，并返回了request.getInputStream()内容。再传递至46行的this.doReadRemoteInvocation(ois)跟进看看。跳转至org.springframework.remoting.httpinvoker.HttpInvokerServiceExporter

![](../Images/0543beb0d5a9af9377024447c12f22bd.png)

直接调用了对象的readObject()反序列化，造成RCE。  

![](../Images/f081444ca5850727478fa6988f2b50d8.png)
