**0x00 前言**

分享一个内网渗透中从服务器打到个人机的思路：

  

当你拿到内网某应用服务器和数据库的权限时，可整理数据库中用户表的用户登陆ip，用户名和密码，并利用这些信息去扫这些ip的3389端口并尝试密码复用进行登陆。  

![](../Images/2918c4126bcc7f8e28af61f29afa6a6f.png)

  

即使3389端口没开，收集目标员工的密码信息也会对接下来的渗透过程有所帮助。

  

这个思路的难点在于数据库中的密码怎么解密，本文将分享几个**根据已有内网应用权限获取目标管理员明文密码**的方案。

  

**0x01 直接解密**

自2011年csdn被拖库事件发生后，很少有系统会以明文方式存放用户密码了，目前流行的方案是使用不可逆的md5等哈希算法去处理存放用户密码，确保数据库权限丢失后也能保证密码的安全。

  

但不可逆只是相对算法原理而言的，哈希算法的运算规则是固定的，我们通过**暴力穷举**主动加密明文去匹配密文的方式(跑彩虹表)是可以实现"破解"的效果的。

  

破解哈希有个很好用的在线工具cmd5.com，不过大部分解密需要收费，如果不想花钱的话也可以试试somd5.com。

![](../Images/c8e0c40d239c8a4cd7cff9956a7570f4.png)

  

实战中发现有些系统会仅采用des等**对称加密**算法去处理密码，我们拿到服务器即可根据源码逆向出算法和key（通常难度不会很高，主要是耐心），这时数据库中的密文就形同虚设了。  

  

**0x02 日志抓取**

内网中dev、test环境的应用**debug级别**通常设的很高，日志记录也会比较详细，数据库中的密码解不开时可以去应用日志翻翻，搜索关键词password或key有概率直接搜到明文密码。

**0x03 tcpdump**

相信大家都使用burp扫到过”高危漏洞“——密码明文传输，以前当安服做漏扫的时候可以拿这个水一篇报告(雾)。不过一直不理解这个漏洞高危在哪里，直到发现了**tcpdump**这个工具。  

  

tcpdump是linux上抓取主机通信流量的工具(类似于wireshark)，如果密码是明文传输的则可以直接被抓取到，以下是简单的两条使用示例。  

*   
*   
*   
*   

```
# 抓取与某ip地址通信的流量包，保存到/tmptcpdump host 192.168.1.1 -vv -w /tmp/test.cap# 抓取某端口通信的流量包，保存到/tmptcpdump port 8080 -vv -w /tmp/test.cap
```

  

运行效果如下图，注意控制抓取时间，不然生成的流量包会很大。

![](../Images/6180a9d59bd3b230002fdb90ea43e267.png)

  

可以用**xxd加grep匹配**去筛选流量包中的密码，不过因为二进制文件的换行比较随机，有些条目会匹配不到。

（比如在passw和ord之间换行就会导致password匹配不到）  

![](../Images/d0a8d4baec6624382aca08ff06ea0a61.png)

  

比较靠谱的是把流量包下载回来用wireshark人工分析，因为对wireshark和tcpdump都不太熟，目前没有找到能只抓取关键流量或快速定位流量包里关键字段的方法，望各位师傅指点。
