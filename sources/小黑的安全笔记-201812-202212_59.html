0X00 前言

最近做的项目已经快到尾声了，目标使用的数据库是PostgreSQL。之前没有接触过这个数据库于是恶补了一下，这里分享一下我的收获。


0x01 搭建PostgreSQL

搞安全有一项基本能力要求，就是能复现各种奇奇怪怪的环境到本地来进行测试。而搭建环境这个工作，虽然有各种靶场或docker可以一键启动，但我还是喜欢手动的搭建一遍，这样对环境理解的会更深刻，并可能发现一些运维容易忽视的点。


PostgreSQL数据库搭建步骤如下：


1、进入官网下载页面选择对应操作系统

https://www.postgresql.org/download/


2、选好操作系统后下滑选择pgsql版本和系统架构

我这里选择的是和目标一致的版本。选好后就会出现下图灰色的部分——官方给出的安装命令。


3、一条一条照着输入就好了，下载安装启动一条龙。


4、ps aux和netstat -antp命令查看进程和网络信息，发现pgsql相关进程。


0x02连接PostgreSQL

1、pgsql安装后会创建一个postgresql系统用户，cat  /etc/passwd命令可见，su命令切换到该用户。


2、直接输入psql命令，即可进入数据库命令行。\help查看帮助。


3、\q退出数据库，exit返回到之前的用户。

为降低学习成本，我跳过了学习命令行的使用方法，打算直接用navicat远程连接管理。


4、不过之前netstat -antp看到，PostgreSQL安装好默认只允许本地ip连接，需要修改配置文件放开这个限制。


5、之前用ps aux查看进程信息，获取到pgsql的data目录。


6、进入该目录，编辑pg_hba.conf文件


7、在最下面添加host all all 0.0.0.0/0 trust一行，可允许任意ip地址无需密码连接！


8、然后修改postgresql.conf文件，将listen_addresses的值修改为‘*’，并去掉前面的注释。


9、sudo systemctl restart postgresql-9.6 命令重启数据库使配置生效，再次查看网络信息发现已经允许所有ip访问了。


10、最后别忘记添加防火墙规则放行端口，如果是云主机还要配置相对应的安全组。

firewall-cmd --zone=public --add-port=5432/tcp --permanent

firewall-cmd --reload


11、使用Navicat新建PostgreSQL连接，直接输入ip地址并使用默认用户即可，无需输入密码。


12、连接成功


0x03 基本使用方法

1、组织架构：库-模式-表

PostgreSQL和mysql数据库的组织架构有一个区别，数据库和表之间多了一个东西叫做模式。如下图所示，test是数据库，下面的moshi是数据库的一个模式，模式下面才是表tabletest。表下的行列和mysql一样。


2、收集基本信息：

select version();   //查询数据库版本

select current_database();   //查看当前数据库

select user;   //查看当前用户


3、收集用户信息

select * from pg_user; //查看所有用户

select * from information_schema.table_privileges; //查看用户拥有的权限


4、收集表信息

select * from pg_tables; //查看所有表（含隐藏的系统表）

select * from information_schema.columns where table_schema='库名' and table_name ='表名';//查看某个表所有字段


0x04 设置密码

pg_hba.conf中设置认证方式为trust即可免输密码，但这样很不安全，所以这里记录一下pgsql设置密码的方式。


1、安装PostgreSQL数据库后自动创建一个postgres用户作为数据库的管理员，同时创建同名linux系统用户，密码随机。要修改密码，首先以postgres系统用户登陆数据库：

sudo -u postgres psql


2、ALTER USER postgres WITH PASSWORD ‘postgres’;  //修改数据库用户密码

\q //退出数据库客户端


3、passwd postgres //修改系统用户密码


4、创建普通数据库用户

CREATE USER 用户名 WITH PASSWORD '密码' CREATEDB;

GRANT ALL PRIVILEGES ON DATABASE 数据库名 to 用户名;


0x05 拖库

1、pg_dump是类似于mysqldump一样的导出数据库的工具，一般来说安装PostgreSQL服务端后自带客户端含psql、pg_dump等工具。无需特意去安装。


2、特殊情况需单独安装pgsql客户端，下面给出了centos系统的安装命令。

# yum install https://download.postgresql.org/pub/repos/yum/reporpms/EL-7-x86_64/pgdg-redhat-repo-latest.noarch.rpm

# yum install postgresql96


客户端和服务端的版本尽量对应，否则可能连接失败。有时候大版本号对应了，小版本号不对应也不行，这时候可以考虑换个大版本号试试：比如yum install postgresql10安装的客户端版本为10.5，但是服务端是10.8，这时候有概率连接失败，单独下载编译10.8版本客户端是一个解决方案，但是很麻烦，这时候就可以试试yum install postgresql11或yum install postgresql9，有几率连接成功（实际环境中遇到过）。



3、一个坑：本机复现需要修改pg_hba.conf，将这一行注释掉，然后重启服务


4、pg_dump具体使用命令

导出特定的表的数据：

pg_dump -h 主机 -U 用户名 -t "模式名.\"表名\"" 库名 -f 导出文件名

导出特定模式中所有数据：

pg_dump -h 主机 -U 用户名 -n 模式名 库名 -f 导出文件名

导出特定库中所有的数据：

pg_dump -h 主机 -U 用户名 -d 库名 -f 导出文件名


5、如何免密码使用pg_dump

使用场景：数据库过大，需要配合nohup启用后台进程去拖，这时候不方便输入密码。

（1）在当前用户家目录下新建.pgpass文件，权限设置为600

（2）内容为：

hostname:port:database:username:password

（3）运行pg_dump，当匹配到填写的hostname，port(不填默认为5432)，database和username四项正确时，即可不填写password，会自动从.pgpass文件中读取。
