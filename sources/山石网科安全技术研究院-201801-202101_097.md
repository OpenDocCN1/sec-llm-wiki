## ******漏洞背景******  

  

以色列JSOF研究人员在Treck公司开发的广泛使用的底层TCP / IP软件库中发现了一系列0day漏洞。

这19个漏洞（名为Ripple20）影响亿万个设备（或更多）。

其中包含多个远程执行代码漏洞。

攻击者可能会在嵌入式设备中隐藏恶意代码。

其中一个漏洞可能允许从外部进入网络边界。

这只是潜在风险的一小部分。

  

Ripple20涉及了来自广泛领域的关键物联网设备，涉及了众多供应商。受影响的供应商范围从一人的精品店到财富500强跨国公司，包括惠普，施耐德电气，英特尔，罗克韦尔自动化，卡特彼勒，百特，以及许多其他可能在医疗，运输，工业控制方面受到影响的主要国际供应商，企业，能源（石油/天然气），电信，零售和商业以及其他行业。

## ******漏洞描述******  

Ripple20是在Treck TCP / IP堆栈上发现的19个漏洞的集合。Ripple20漏洞中有四个被评为严重，CVSS得分超过9，并且启用了远程执行代码。严重漏洞之一是DNS协议中的漏洞，并且可能由老练的攻击者通过互联网（甚至在未连接到互联网的设备上）从网络边界外部通过互联网利用。

  

将在 BlackHat USA 2020 发布的第二份白皮书将详细介绍在Schneider Electric APC UPS设备上利用DNS漏洞 CVE-2020-11901。 其他15个漏洞的严重性程度不同，CVSS评分从3.1到8.2不等，其影响范围从拒绝服务到潜在的远程执行代码。

  

据我们所知，Ripple20是迄今为止在Treck中报告的唯一漏洞，除了过去引用的一些通用逻辑漏洞与许多堆栈实现有关，这些漏洞通常与RFC错误解释或与不建议使用的RFC有关。

  

由于供应链的影响，Ripple20漏洞在其广泛的影响和影响方面都是独特的，并且这些漏洞使攻击者可以绕过NAT和防火墙并控制未检测到的设备，而无需用户交互。这是由于漏洞位于底层TCP / IP堆栈中，并且对于许多漏洞而言，发送的数据包与有效数据包非常相似，或者在某些情况下是完全有效的数据包。这样可以使攻击作为合法流量通过。

  

*   CVE-2020-11896：可以通过将多个格式错误的IPv4数据包发送到支持IPv4隧道的设备来触发此漏洞。它会影响使用特定配置运行Treck的所有设备，可以实现稳定的远程代码执行
    
*   CVE\-2020\-11897：可以通过向设备发送多个格式错误的IPv6数据包来触发此漏洞。它会影响任何运行旧版支持IPv6的Treck的设备，先前已进行了修复。它可能潜在地允许稳定的远程代码执行
    
*   CVE\-2020\-11901：可以通过回答设备发出的单个DNS请求来触发此漏洞。它会影响任何运行支持DNS且支持Treck的设备
    
*   CVE\-2020\-11898：处理未经授权的网络攻击者发送的数据包时，IPv4 / ICMPv4组件中的长度参数不一致（CWE-130）处理不当。可能暴露敏感信息（CWE-200）
    
*   CVE\-2020\-11900：处理网络攻击者发送的数据包时，IPv4隧道组件中可能存在双重释放（CWE-415）。释放后引用（CWE-416）漏洞
    
*   CVE\-2020\-11902：处理未经授权的网络攻击者发送的数据包时，IPv6OverIPv4隧道组件中的输入验证不正确（CWE-20）。 可能存在越界读取（CWE-125）
    
*   CVE\-2020\-11904：处理未经授权的网络攻击者发送的数据包时，内存分配组件中可能存在整数溢出（CWE-190）和可能的越界写（CWE-787）
    
*   CVE\-2020\-11899：处理未经授权的网络攻击者发送的数据包时，IPv6组件中的输入验证不正确（CWE-20）。可能的越界读取（CWE-125）和可能的拒绝服务。 
    
*   CVE-2020-11904：处理未经授权的网络攻击者发送的数据包时，DHCP组件中可能存在越界读取（CWE-125），可能暴露敏感信息（CWE-200）
    
*   CVE-2020-11905：处理未经授权的网络攻击者发送的数据包时，DHCPv6组件中可能存在越界读取（CWE-125）。可能暴露敏感信息（CWE-200）
    
*   CVE-2020-11906：未经授权用户发送的数据包中的以太网链路层组件中的输入验证不正确（CWE-20），整数下溢（CWE-191）
    
*   CVE-2020-11907：TCP组件中的长度参数不一致（CWE-130）处理不当，来自未经授权的网络攻击者发送数据包时会发生整数下溢（CWE-191） 
    
*   CVE-2020-11909：处理未经授权的网络攻击者发送的数据包时，IPv4组件中的输入验证不正确（CWE\-20），以及整数下溢（CWE-191）
    
*   CVE-2020-11910：处理未经授权的网络攻击者发送的数据包时，ICMPv4组件中的输入验证不正确（CWE-20）；可能的越界读取（CWE-125）
    
*   CVE-2020-11911：处理未经授权的网络攻击者发送的数据包时，ICMPv4组件中的访问控制（CWE-284）不正确。 关键资源的权限分配不正确（CWE-732）
    
*   CVE-2020-11912：处理未经授权的网络攻击者发送的数据包时，TCP组件中的输入验证不正确（CWE-20）；可能越界读取（CWE-125）
    
*   CVE-2020-11913：处理未经授权的网络攻击者发送的数据包时，IPv6组件中的输入验证不正确（CWE-20）；可能越界读取（CWE-125）
    
*   CVE-2020-11914：处理未经授权的网络攻击者发送的数据包时，ARP组件中的输入验证不正确（CWE-20）；可能越界读取（CWE-125）
    
*   CVE-2020-11908：处理未经授权的网络攻击者发送的数据包时，DHCP组件中的Null终止（CWE-170）不正确，可能暴露敏感信息（CWE-200）
    

## ******漏洞危害******

关于Ripple20的有趣之处在于其影响的不可思议的程度，被供应链因素放大了。软件库的广泛传播（及其内部漏洞）是供应链“涟漪效应”的自然结果。 单个易受攻击的组件虽然本身可能相对较小，但可以向外扩散以影响广泛的行业，应用程序，公司和人员，引起涟漪荡漾不断。

  

## ******解决方案******  

1.  所有组织在部署防御措施之前都必须进行全面的风险评估。
    
2.  首先以被动“警报”模式部署防御措施。
    
3.  **设备供应商的缓解措施：**
    

1.  确定是否使用了易受攻击的Treck堆栈
    
2.  联系Treck了解风险
    
3.  更新到最新的Treck堆栈版本（6.0.1.67或更高版本）
    
4.  如果无法更新，请考虑禁用易受攻击的功能
    

5.  ### **针对运营商和网络用户（基于CERT / CC和CISA ICS-CERT建议）：**
    

1.  ### 
    
    第一个也是最好的缓解措施是将所有设备更新为补丁程序版本。
    
2.  如果无法更新设备，建议执行以下步骤：
    

1.  最小化嵌入式和关键设备的网络暴露，将暴露程度保持在最低水平，并确保除非绝对必要，否则无法从Internet访问设备。
    
2.  将OT网络和设备隔离在防火墙后，并将其与业务网络隔离。
    
3.  仅启用安全的远程访问方法。
    

4.  阻止异常IP流量。
    
5.  通过深度数据包检查来阻止网络攻击，以降低Treck嵌入式启用TCP / IP的设备的风险。
