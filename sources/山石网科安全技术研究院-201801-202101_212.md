## ******事件来源******  

近日，山石网科安全应急响应中心（HSCERT）监测到大量Sodinokibi勒索病毒的攻击事件，我们对Sodinokibi勒索病毒样本进行了跟踪分析，Sodin最早出现在2019年上半年，它通过Oracle Weblogic漏洞进行分发攻击，并对MSP提供商进行攻击。在详细分析中，**我们发现它还利用CVE-2018-8453漏洞来提升Windows中的权限（这在勒索软件中很少见）**，并使用合法的处理器功能来规避安全解决方案。

  

  

## ****样本分析****

Sodinokibi勒索软件首次出现是在2019年5月28日的推特上，当时还伴随着RDP攻击，

这是Sodinokibi勒索软件的第一个版本，但是这些制作者有长期的勒索病毒开发经验。

**我们还发现了它与GandCrab的相似之处**，GandCrab ransomware于今年6月初停止更新，Sodinokibi勒索软件填补GandCrab留下的空缺。

**RDP攻击**

Sodinokibi在内存中生成ECC密钥对后，公钥存储在pk\_key值内部的recfg regisry密钥中我们将其称为dk\_key(私钥)和pk\_key(公钥)，:

```

```

 

此时，调用Sub\_13597B函数生成sk\_key数据结构:

pBuff\_sk\_key = Sub\_13597B (key\_pubblica\_json, key\_privata, size IN, size out)

Sub\_13597B的目的是加密sk\_key数据结构中生成的私钥。

  

Sub\_13597B函数有4个输入参数:

```
key_pubblica_json: 
```

  

Sub\_13597B函数执行以下步骤:

分配一个0x58字节的缓冲区，并将私钥(dk\_key)“key\_privata”从偏移量0x4复制到缓冲区中

计算一对新的ECC密钥，一个私有密钥(dk\_new)和一个公共密钥(pk\_new)

计算dk\_new\*pk -> shared\_key\_new(其中pk是json配置部分中的公钥)，结果是SHA-3的“hashato”

计算一个16字节的随机数——> random\_16，它将被用作IV(初始化向量forAES)

通过IV初始化向量和SHA-3 (shared\_key\_new)通过AES-256 CTR将从0分配到0x24的缓冲区加密

将公钥pk\_new复制到偏移0x24处分配的缓冲区中

将随机数random\_16复制到偏移0x44处分配的缓冲区中

计算从0分配到0x24的缓冲区的CRC32，并将结果保存在偏移量0x54处

Sub\_13597B函数返回指向缓冲区的指针，该缓冲区在sk\_key数据结构中分配给0x58字节。

为了解密sk\_key，攻击者使用一个秘密密钥，即只有他们知道的私钥dk。私钥dk是存储在json配置中的公钥pk的对称密钥。

公钥pk\_new以未加密的方式放在sk\_key结构中。

计算值为:dk \* pk\_new = shared\_key\_new

  

shared\_key\_new与:dk\_new\*pk相同。

私钥(dk\_key)是通过SHA-3 (shared\_key\_new)和偏移0x44上的随机数(IV)用AES-256 CTR加密的。

通过SHA-3 (shared\_key\_new)和得到的随机数dk\_key，用AES-256将缓冲区从0x4解密到0x24。

现在可以执行相同的过程解密0\_key，在本例中使用主私钥(只有Sodinokibi的作者知道)来获得dk\_key。
