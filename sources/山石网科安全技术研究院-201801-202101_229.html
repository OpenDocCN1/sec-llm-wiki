漏洞描述

近日，RedHat官方发布公告，研究人员在Linux内核处理TCP网络时发现了三个重大漏洞。最严重的一个漏洞允许远程攻击者在受影响软件的系统中触发漏洞造成内核崩溃，从而影响系统的可用性。

三个漏洞的CVE编号为CVE-2019-11477（高危）、CVE-2019-11478和CVE-2019-11479。

前两个漏洞与选择性确认（SACK）数据包和最大段大小（MSS）有关，第三个仅与最大段大小（MSS）有关。


漏洞分析

TCP选择性确认（SACK）机制

数据接收方可以通知发送方已成功接受的所有段。这允许发送方重新传输从其已知集中丢失的段。当禁用TCP SACK时，需要更大的重传集来重新传输完整的数据流。

最大段大小（MSS）

是在分组的TCP报头中设置的参数，其指定重构的TCP段中包含的数据总量。
由于数据包在跨不同路由传输时可能会被碎片化，因此主机必须将MSS指定为等于主机可以处理的最大IP数据报有效负载大小。非常大的MSS大小会导致数据包在到达目的地的路上被碎片化，而较小的数据包可以确保较少的碎片但最终会导致未使用的开销。

操作系统和传输类型可以默认为指定的MSS大小。具有特权访问权限的攻击者可以在数据包中创建具有精心设计的MSS选项的原始数据包，来进行攻击。

TCP是面向连接的协议

当双方希望通过TCP连接进行通信时，他们通过交换信息建立连接，例如请求发起（SYN）连接，初始序列号，确认号，通过此连接使用的最大段大小（MSS），权限发送和处理选择性确认（SACK）等。此连接建立过程称为3次握手。

TCP通过称为Segment的单元发送和接收用户数据。一个TCP段包括TCP报头，选项和用户数据的。



每个TCP段具有序列号（SEQ）和确认号（ACK）。

这些SEQ和ACK号用于跟踪接收器成功接收哪些段。ACK号表示接收器的下一个预期段。

示例：上面的用户'A'通过13个100字节的段发送1千字节的数据，13是因为每个段具有20字节的TCP头。在接收端，用户'B'接收段1,2,4,6,8-13，段3,5和7丢失，不会被用户'B'接收。

通过使用ACK号码，用户'B'将指示它正在期望段号3，用户'A'读取为用户'B'接收到2之后没有段，并且用户'A'将重新发送全部即使用户'B'成功接收到第4,6和8-13段，从3开始的段也是如此。用户'B'无法向用户'A'表明。这会导致网络的低效使用。

选择性确认：SACK

为了克服上述问题，选择性确认（SACK）机制由RFC-2018设计和定义。通过选择性确认（SACK），上面的用户'B'使用其TCP选项字段向用户'A'通知它已成功接收的所有段（1,2,4,6,8-13），因此用户'A'需要仅重传段3,5和7，从而大大节省了网络带宽并避免了进一步的拥塞。

CVE-2019-11477 SACK Panic
套接字缓冲区（SKB）是Linux TCP / IP实现中使用的最核心的数据结构。它是缓冲区的链接列表，用于保存网络数据包。这样的列表可以充当传输队列，接收队列，SACK'd队列，重传队列等.SKB可以将分组数据保存成片段。Linux SKB最多可以容纳17个片段。

linux / include / linux / skbuff.h 
定义MAX_SKB_FRAGS（65536 / PAGE_SIZE + 1）=> 17

每个片段在x86（PowerPC上为64KB）的数据中最多可容纳32KB。当数据包将被发送时，它被放置在发送队列中，它的详细信息保存在控制缓冲区结构中

其中，' tcp_gso_segs '和' tcp_gso_size '字段用于告知设备驱动程序有关分段卸载的信息。

当Segmentation offload打开并且SACK机制也被启用时，由于数据包丢失和某些数据包的选择性重传，SKB可能最终持有多个数据包，由' tcp_gso_segs ' 计数。列表中的多个这样的SKB被合并为一个以有效地处理不同的SACK块。它涉及将数据从一个SKB移动到列表中的另一个SKB。在此数据移动期间，SKB结构可以达到其最大限制为17个片段，并且' tcp_gso_segs '参数可以溢出并触发下面的BUG_ON（）调用，从而导致所述内核崩溃问题。

tcp_skb_pcount_add（prev，pcount）; 
BUG_ON（tcp_skb_pcount（skb）<pcount）; <= SACK panic 
tcp_skb_pcount_add（skb，-pcount）;

}

远程用户可以通过将TCP连接的最大段大小（MSS）设置为48字节的最低限制并发送一系列特制的SACK数据包来触发此问题。最低MSS每段仅留下8字节数据，因此增加了发送所有数据所需的TCP段数。
