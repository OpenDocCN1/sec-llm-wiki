# 安全访问服务边缘（SASE）技术应用白皮书

在2021年度的网络安全行业的热点名词中，安全访问服务边缘（Secure AccessService Edge ，简称SASE）绝对是热点之一，自2019年Gartner发布《The Future of Network Security Isin the Cloud（网络安全的未来在云端）》，SASE的概念被提出，迅速成为国内外各大安全厂商和创业公司的关注重点，纷纷阐述各自对SASE的理解，并推出相关方案或产品进行试水。在短短一年多的时间里，SASE从概念诞生到炙手可热，关注度和热度持续上升，但在发展过程中也存在了诸多乱象。

基于此，本白皮书立足国内网络安全产业的发展现状，从客观技术视角阐述对SASE的理解，澄清相关概念，介绍SASE的特征和优势，总体架构及核心技术，从产业发展的角度，提出SASE适用的场景及部署路径建议，并对SASE发展成熟度提供评估参考，旨在将SASE从混乱的概念炒作阶段，逐步牵引至良性发展的轨道，从而使SASE概念真正落地和规范化发展，推动SASE的标准化进程。  

  

**1 背景**

由于企业网络云化发展趋势和新冠疫情等因素的影响，企业内大量数据和应用都搬迁到了云上，尤其是大型企业，分支流量急速增大和访问路径变化使得分支用户的体验变得难以忍受。软件定义广域网（Software Defined Wide AreaNetwork，SD-WAN）技术在提升分支访问总部、云端的体验的同时，也带来了一系列的运维问题和分支安全需求。采购SD-WAN技术的同时还需要采购互联网线路，运维责任不明晰。分支直连公网应用，面临错综复杂的网络环境和应用关系，需要对应用进行针对性的识别、管理和调度，同时要采购额外的安全设备，配备对应的安全功能，如：安全Web网关（Secure Web Gateway，SWG）、入侵检测系统（Intrusion Prevention System，IPS）等。大量的分支安全需求反而促使安全功能云化趋势的兴起。

云计算和边缘化趋势让越来越多的企业计划更改其网络接入和网络安全架构，各种孤立的安全产品和解决方案难以解决企业的实际需求，同时，由于现实因素导致远程办公的兴起，让传统的VPN系统不堪重负，因此安全服务商和云服务商面临将网络接入和安全能力进行融合的挑战。

为了应对这一挑战，Gartner在2019年提出安全访问服务边缘（SASE）架构。

 

**2 定义**

**2.1 Gartner定义的SASE**

Gartner在《The Future of Network Security Isin the Cloud（网络安全的未来在云端）》中，将SASE定义为一种基于实体的身份、实时上下文、企业安全/合规策略，以及在整个会话中持续评估风险/信任的服务。其中，实体的身份可与人员、人员组（分支办公室）、设备、应用、服务、物联网系统或边缘计算场地相关联。

在Gartner的定义里，SASE是一种基于零信任模型、通过SD-WAN整合了各种云原生的安全功能（包含SWG、IPS等）的管理型服务，从而满足企业在数字化转型过程中的动态安全访问需求。其本质是网络和安全的综合云化。  

  

**2.2 Forrester定义的ZTE**

曾在2010年推出零信任（Zero Trust）安全理念的Forrester公司，在2021年1月提出了零信任边缘（Zero Trust Edge，ZTE）模型，将SASE纳入到零信任框架中。

Forrester在《Introducing The Zero Trust EdgeModel For Security And Network Services（将安全带到零信任边缘）》报告中认为，ZTE模型与SASE模型是相似的，但ZTE模型重点侧重于零信任，将零信任和边缘安全融为一体，而SASE模型侧重点是通过SD-WAN进行网络和安全的同步。

因此，ZTE与SASE在实施路径上存在差异，SASE强调网络和安全紧耦合，网络和安全同步，因此要求单一供应商提供全套SASE产品；ZTE强调网络和安全解耦，零信任先行，网络重构滞后，可以由多个供应商集成，先解决战术性“远程访问”问题，最后再解决困难的“网络重构”问题。  

  

**2.3 我们的观点**

SASE与ZTE是由业界两大知名咨询公司提出的安全模型，殊途同归，目的都是提升“边缘安全”的地位。

而我们认为在云化时代，传统堆叠安全硬件设备方式将无法满足企业数字化发展和业务上云后的安全需求，软件化和服务化是未来网络安全的发展趋势，当前网络安全市场“重产品，轻服务”的局面也将逐步改变，企业将更多采用托管的安全服务取代自建安全设施。

SASE是通过将网络接入和安全能力融合，统一在云端平台管理和交付，将安全执行点部署在离用户更近的边缘节点，克服了分散集成和地理位置约束解决方案的成本、复杂性和刚性，从而实现安全能力的服务化和企业安全服务的托管。

 

**3 特征**

**3.1 身份驱动**

在SASE中，安全访问决策以连接源的用户实体身份为中心，决定网络互联的服务质量、访问权限级别、路由选择、应用的安全风险。所有这些都由与每个网络连接相关联的身份所驱动，身份是访问决策的中心，只需要专注于身份管理和对应的安全风险策略，无需考虑设备或地理位置，从而降低运营开销。SASE采用最低权限策略，执行严格的访问控制，能够根据相关属性控制与资源的交互，包括应用访问、用户和组身份以及被访问数据的敏感性。  

  

**3.2 云原生架构**

SASE的部署是基于云原生架构，因此具备云原生的弹性、自适应性、自恢复能力和自维护功能，基于微服务架构，具备按需扩展的能力。通过客户成本分摊，最大程度地节省成本并提供最大效率的平台，在方便地适应新兴业务需求的同时实现服务的快速扩展。  

  

**3.3 近源部署**

5G技术的规模应用，加速了分布式边缘计算的需求，近源部署可以提供低延迟以类似于访问本地存储的用户体验，通过SASE 为整个组织的资源——数据中心、分支机构、云资源以及移动和远程用户创建一个网络，将SD-WAN和安全能力集成到云计算服务中，从而保证简化的WAN部署、提高效率和安全性，并为每个应用程序提供适当的带宽，也就是说，无论最终用户需要什么资源，以及自身和资源位于何处，都具有相同的访问体验和安全防护能力。  

  

**3.4 分布互联**

为确保所有网络和安全功能随处可用，并向全部边缘提供尽可能好的用户体验，SASE将安全能力下沉至云边缘节点，组织的分支机构/营业网点需要就近选择安全防护节点接入，这就要SASE实现分布互联。因此，SASE必须扩展自身覆盖面，向组织边缘交付低延迟服务。

最终，SASE 架构的目标是要能够更容易地实现安全的云环境。SASE 提供了一种摒弃传统方法的设计哲学，抛弃了将SD-WAN 设备、防火墙、IPS 设备和各种其他网络及安全解决方案拼凑到一起的做法，以一个统一的覆盖全网的SD-WAN 服务和安全服务代替了难以管理的技术大杂烩。

 

**4 优势**

**4.1 融合管控**

在单个框架中进行网络接入管理和网络安全管理是SASE的一大优势，这实现了接入和安全的融合管控。

IT管理人员可以通过基于云的管理平台集中设置策略，并在靠近终端用户的分布式POP点上实施策略，在需要时也可以在本地决策点进行部署。同时可以对网络和安全数据集中管理，进行整体行为分析，发现在孤立系统中不明显的威胁和异常。这些分析可以作为基于云的服务提供，并且能包含更新的威胁数据和其他外部情报。相应地，SASE云服务对新的威胁或攻击载体的适应能够集中完成，立即影响所有企业和所有边缘，而不需要部署或激活这些新增功能。  

  

**4.2 降低成本**

将SASE用于从分布式云服务交付聚合的企业网络和安全服务，能克服分散集成和地理位置约束的解决方案的成本问题。

SASE采用没有特定硬件依赖关系的云原生架构，可多租户模式部署，并能快速实例化，实现服务的快速扩展，SASE还减少了企业跟供应商之间不必要的交流，减少了分支机构和其他远程位置所需的硬件数量和终端用户设备上的代理数量，降低成本。企业更新功能时不需要受到硬件容量和更新硬件的限制，节省迭代成本。  

  

**4.3 灵活部署**

由于SASE使用灵活的广域网接入技术，采用SASE的企业可以比传统的多协议标签交换（Multi-Protocol Label Switching，MPLS）服务在更短的时间内以更低的成本交付响应更快、更可预测的应用程序，只需几分钟就可以部署站点，同时可以利用一切可用的数据服务搭建，例如MPLS、专用互联网接入（Dedicated Internet Access，DIA）、宽频或无线网络。

利用云基础架构的SASE服务可以灵活部署多种安全服务，例如威胁预防、Web过滤、沙箱、DNS安全、数据防泄漏和下一代防火墙策略。无需接触企业网络就可以进行网络和安全部署，这使企业可以迅速采用新功能，提高网络和安全服务部署的敏捷性和简便性。  

  

**4.4 性能优化**

SASE供应商通过部署POP点提供延时优化的路由，这对于延时敏感的业务非常关键。同时，借助云基础架构，用户能在服务部署的任何位置轻松连接到资源所在的位置，访问应用程序、互联网和公司数据。

使用SASE的企业安全专业人员可以专注于理解业务、法规和应用的访问需求，并将这些需求映射到SASE功能，而不是陷入到基础设施的常规配置任务中。SASE服务商可以给应用程序提供不同质量的服务，使每一个应用获得所需的带宽和网络响应能力。使用SASE可以减少企业IT员工部署、监视、维护等相关杂务，以便执行更高级别的任务。

 

**4.5 提升安全**

SASE最大的优点是将众多不同的网络服务融合和统一到一个针对边缘环境和独立用户的代理结构中，而传统方法往往需要多个供应商和服务来实现相同的控制，管理复杂且缺乏互操作性。SASE旨在通过基于云的安全服务的集中策略控制来降低传统方法的复杂性和缺乏互操作性，从而提高安全性。当出现新的威胁时，供应商会提供如何防御这些威胁的解决方案，不需要企业采购新的硬件。

SASE服务将使企业的合作伙伴和承包商可以安全地访问其应用、服务、API和数据，而无需担心暴露传统架构中的VPN和DMZ带来的大量风险。

 

**5 架构**

**5.1 总体架构**

SASE是云、网、边、端、安协同与融合的架构，将网络能力与安全能力相融合，能够适应多种IT环境，并利用多种设备和服务拓展SASE服务边缘，从而实现网络就近接入和降低延时，并支持安全防护能力的实时敏捷和弹性伸缩的要求。

SASE体系架构主要由接入端和云端两部分构成，其中SASE接入端包含客户端、用户侧网关等，负责将流量从物理、云和设备边缘驱动到SASE云端处理。SASE云端作为网络和安全功能的聚合器，使用一个单通道的流量处理引擎来有效地应用优化和安全检查，并为所有流量提供前后关联，SASE云端包含SASE节点、SASE云和SASE控制中心。  

  

**5.2 SASE接入端**

SASE接入侧设备需要满足办公场景“多样化”的业务需求，能够支撑移动办公、远程办公、总部/分支机构协同办公的场景。

*   对于公司机构（包含总部及分支机构），可以采用专用的SASE硬件接入客户端设备，利用该设备通过Internet实现就近加密接入SASE云端，从而获得更加智能、更加可靠、更加安全的云体验。
    
*   对于员工出差、移动办公、远程办公等通过个人电脑方式的接入场景，可以通过SASE客户端软件、浏览器SASE插件等方式，实现用户认证和边缘接入。
    
*   对于采用手机的移动办公场景需求，可以采用安装手机版本的SASE客户端软件的方式，实现用户认证和边缘接入。
    

 

**5.3 SASE云端**

SASE云端包含SASE节点、SASE云和SASE控制中心。

*   SASE节点：把网络和安全整合到一个平台中，将访问技术栈压进方便管理的连接网络，进行统一管理。SASE使用私有数据中心、公共云或托管设施作为SASE接入点，形成了SASE架构的服务边缘。而各个分公司和分支则通过客户终端设备作为SASE接入点连接到网络。
    
*   SASE云：集中部署的安全能力池，在容器云技术架构下，SASE云可以是一个存储、管理安全能力应用镜像的镜像仓库。通过集中云化部署的方式，实现安全能力的资源化、服务化和目录化，从而具备按需快速开通和调用能力。SASE云也可以向不同的SASE接入点侧输出可调用的安全能力，通过安全能力资源共建共享，节约化建设运营。安全能力可通过容器等方式下放部署在接入点。
    
*   SASE控制中心：SASE控制中心是对SASE网络的进行统一管理的平台，能够对SASE云、安全能力池、SASE接入点、安全能力运行状态等进行统一管理和运维。SASE控制中心能够适用不同场景、不同业务的云用户，提供多场景、个性化安全能力服务；实现对集中化安全能力池和SASE接入点安全能力组件区的集中调度管理；标准API接口与各安全组件对接，实现安全能力的统一配置、编排和使用。SASE将允许从控制台进行任意位置的安全、网络能力和策略分发，支持人工智能自动化创建策略、支持API自动化以及与现有流程、工具的集成。根据不同的部署方式，控制中心可以托管在公共云中、私有云中或本地。
    

 

**6 核心技术**

**6.1 网络接入能力**

网络接入能力作为SASE的核心功能之一，主要包括SD-WAN、零信任网络访问（Zero trust network access，ZTNA）、内容分发网络（Content Delivery Network，CDN）等相关技术，其中以SD-WAN和零信任当前应用最为广泛。  

  

**1、SD-WAN**

SD-WAN是SASE平台的关键组件，它将分支位置和数据中心链接到SASE云服务。SASE的理念就是借助SD-WAN搭建起来的虚拟化架构去集中化，将核心能力附加到边缘，使数据处理和安全能力都在边缘并行，以满足当前和未来云上和移动业务的动态需要。

SASE使用私有数据中心、公共云或托管设施作为POP点。这些POP点形成了SASE体系结构的服务边缘。此外，这些POP点通常位于公共云中，或者靠近公共云网关，以实现对云资源的低延迟安全访问，无论哪个节点都有足够的资源来满足用户的请求。同时，SASE软件可以确定流量到达其端点时使用的最佳路径。与SD-WAN以数据中心为中心的架构不同，SASE采用的是分布式架构。  

  

**2、零信任网络访问ZTNA**

零信任就是默认系统环境不可信，并以“永不信任、持续验证”的理念，兼顾安全和体验的方式，实现资源的可信任访问。零信任的信任关系源自于对所有参与对象和行为的动态验证。核心原则包含最小权限原则、持续动态访问控制和授权。

零信任架构核心分为控制平面和数据平面。控制平面的策略引擎负责信任评估，控制引擎为策略控制点，数据平面的安全代理作为策略执行点。除了核心组件，也包含内部和外部信任源，用于收集并分析参与对象和其行为的安全信息，为信任评估提供依据。  

  

**6.2 网络安全能力**

网络安全能力是SASE的另外一个核心功能，也是安全能力服务化的具体体现，主要包括防火墙即服务FWaaS、安全Web网关SWG、云访问安全代理CASB等。  

  

**1、防火墙即服务FWaaS**

“防火墙即服务（Firewall as a Service，FWaaS）”是一种将防火墙作为SASE平台组件从而提供安全防护服务的概念。它使企业更轻松地管理网络安全，设置统一策略，及时发现异常并快速进行响应。FWaaS不是物理设备，也不是托管在组织的本地环境。与其他“即服务”类别类似（如软件即服务或平台即服务），FWaaS也是在云环境中运行，并可以通过互联网进行访问。  

  

**2、安全Web网关SWG**

基于云的安全Web网关（SWG）的主要作用就是确保员工和设备在任何时间任何地点都能安全地连接到互联网以及保护企业拥有和管理的应用程序，企业可以通过集中管理、在全球范围内部署策略，保护企业和员工免受恶意软件、勒索软件、钓鱼攻击、数据泄漏等风险。由于采用云服务的形式，安全Web 网关无需部署硬件或虚拟设备，无需回传流量即可为Web流量提供保护，允许直接连接到互联网，从而降低了MPLS、VPN等网络成本。

基于云的安全Web网关通过集成企业应用隐藏、多因素认证（Multi-FactorAuthentication，MFA）、统一应用门户和单点登录、恶意软件检测、文件沙箱和动态威胁情报、SSL解密、应用和内容过滤以及数据泄漏防护等功能，可以记录和检查所有的Web流量，从而获得最佳的控制和保护。  

  

**3、云访问安全代理CASB**

云访问安全代理（Cloud Access Security Broker，CSAB）是基于云原生应运而生的产品和服务，它是云安全战略的基本元素，帮助安全和风险管理领导者发现云服务并评估云风险，识别和保护敏感信息，检测和缓解威胁，并建立有效的云治理和法规遵从性。

CASB特别设计用于保护和控制对存储在其他人系统中的数据的访问，它提供了不同的、特定于云的功能，这些功能通常不是传统安全产品的功能。

Gartner将云访问安全代理市场定义为解决云服务使用过程安全漏洞问题的产品和服务。CASB为多云管理提供了一个中心，用于跨多个云服务并发地执行策略和治理，以及对来自企业内外的用户活动和敏感数据（包括云到云访问）的精确可见性和控制。CASB相当于一个超级网关，融合了多种类型的安全策略执行点。在这个超级网关上，能够进行认证、单点登录、授权、凭据映射、设备建模、数据安全（内容检测、加密、混淆）、日志管理、告警，甚至恶意代码检测和防护。

 

**7 场景**

SASE架构将安全控制的实施环节下放到距离用户和应用最近的地方，对网络能力和网络安全能力进行耦合，方便企业更快捷地应对内外部环境变化。以下为部分更应率先接入SASE架构的应用场景。  

  

**7.1 零信任第一步**

零信任提供了一种全面而灵活的方法来保护IT基础架构、应用程序和数据。将基于“零信任”策略的安全性应用于用户交互时，企业可以减少其网络攻击面。接入侧终端经过身份验证，仅能有限地访问他们被授权使用的应用程序、数据和资源。“零信任”的安全决策在云中定义和管理，在端点实施，核心数据可分散存储在多地。访问策略可以根据IT资源、会话数据、身份验证和许多其他因素在访问边缘做出安全决策。由于缺少基础的网络架构，企业从现有的物理网络上改造“零信任”会花费巨大成本，“零信任”的其他功能实际难以落地。  

  

**7.2 多分支接入**

对于有多个分支机构的大中型企业，由于地理位置分散，分支机构无法通过内网直接访问到总部，安全保护较弱。传统的总部-分支安全模式不适用于当下的企业内外部环境，分支机构独立采购安全设备并使用MPLS专线进行通信的模式成本高、使用体验差；分支机构和总部统一进行网络和安全建设，对设备性能要求高，成本高，分支网络、安全策略变化需要经由总部进行处理，运维复杂。

SASE架构通过在分支机构出口部署SD-WAN 设备将上网流量引流到SASE服务边缘接入节点，按需开通安全模块，统一实现分支上网安全、组网和集中管理功能，无需购买传统安全设备。使用统一安全管理平台，可实现多分支集中管理，多分支流量可视，分支安全事件分析统一展示，提供实时告警推送。对企业终端上网行为进行管理，对上网流量进行监控与分析，保障企业信息安全。同时对终端侧进行安全威胁检测与响应，提供基于零信任的内网应用资源接入，通过身份认证、权限控制等模块，确保企业员工、合作伙伴在全球任何地方都能更安全、更隐私地访问业务。

实现轻资产、简运维、统一管理的目标，节省采购设备成本，减轻运维压力，统一管理多分支安全。  

  

**7.3 远程接入**

传统的企业外部接入都是经由总部数据中心将员工连接到互联网，并在企业内网放置应用。但是，随着应用程序迁移到云的趋势不断上升，以及新冠疫情等外部因素促使企业推进居家办公模式，使得通过传统的VPN连接总部数据中心的解决方案不再满足当前企业的远程接入需求。员工居家办公、合作伙伴远程接入内网，终端环境不可控，存在安全风险；VPN不能最小化访问权限，无法触及云上业务；终端多种环境接入入口不统一等。

基于SASE 架构的远程接入，不需要对终端进行复杂安全部署，只需部署轻量级引流插件，将流量引流到SASE云平台的边缘接入节点，即可体验远程访问内部应用。

SASE云平台对所有员工都支持下发认证策略，只有通过认证的员工才能访问内部应用。无论企业的内部应用部署在私有云、共有云还是本地的数据中心，都由SASE云平台统一管理；企业整体的内部应用访问权限完全托管到SASE平台管理，保证内部应用按需访问，降低入侵、数据泄露的可能性。同时可实现内部应用访问活动可视化，如发现越权访问，立即调整访问权限，保证内部应用的安全。

实现保护企业内部应用的目标，减轻远程访问复杂度，基于实体身份进行权限管理，并通过云平台集中管理内部应用。

 

**7.4 资产隐藏**

近年来，我国云计算开始进入高速发展阶段，其中SaaS领域已经发展成为云计算最大的细分领域，由于SaaS应用的便捷和高效的特性，越来越多的中小企业从传统的软硬件部署方式转向使用SaaS应用办公，其中不乏财务、人力资源、OA等核心系统，有效提升企业工作效率。

SaaS安全访问及数据外泄安全一直是中小企业关注的重点，但是由于SaaS服务已经摆脱地域和网络环境的限制，传统的硬件安全产品部署方式已经不再有效，同时传统的安全设备价格昂贵、未能服务化交付。业务系统SaaS化以后，网络缺少安全边界，用户可以通过办公电脑，个人笔记本，任何终端访问业务系统，一旦账号密码被泄露，黑客或者竞争对手可以直接访问平台获取数据，内部员工更是随意拿到相关数据。

SASE的应用可将企业内部应用全部收敛起来，无需暴露外部访问地址，员工只有通过SASE的接入节点才能访问到自身权限允许的应用，保证内部应用在简单高效访问的同时又不会暴露在外，实现更安全、更隐私、更稳定的访问体验。

无论企业的内部应用部署在私有云、公有云还是本地的数据中心，都会收纳到SASE云平台统一管理，可以做到轻资产、高效访问等优点。  

  

**8 部署**

**8.1 部署路径**

SASE的部署主要包括网络接入能力的部署和网络安全能力的部署，网络接入能力可以根据业务发展需求变化而变化，网络安全能力的部署可以根据接入边缘的变化及安全需求的变化进行弹性扩展。

从部署路径上，可以依据企业规模及应用场景而定。对于具备较强IT基础和管理能力的中大型企业可以选择私有化部署的SASE服务，根据企业需求选择SASE服务的广度和深度，将企业已经部署和商用的网络接入能力和网络安全能力，通过合理规划，逐步迁移至SASE服务中。对于IT基础和运维较为薄弱的中小微企业可以选择公有化部署的SASE服务，通过租赁服务的方式应用，避免过大的投资。  

  

**8.2 影响部署的因素  
**

  

**1、观念的转变**

传统的安全建设和运维思路是建立安全边界，通过防火墙等硬件设备划分安全域，通过IPS/IDS等设备进行流量审计。而随着安全边界越来越模糊，企业不可能无限制的增加安全设备，传统通过堆叠安全设备的方式无法满足日趋复杂的安全形式，SASE通过云化方式提供相应的接入和安全服务，在一个框架下实现网络接入和网络安全的管理，企业可按需开通相应服务。  

  

**2、低估SASE的复杂度**

虽然SASE的核心功能是网络接入和网络安全的融合，但不是简单的技术栈的叠加，要真正发挥SASE的价值，需要从更高的角度统筹SASE的建设和部署。

针对私有化部署SASE的企业，要确保网络运维和安全管理是一个团队。

针对已经具备网络接入能力或者网络安全能力，需要做好迁移建设规划，特别是具有多个不同供应商的情况下，需要关注供应商的能力是否可以满足迁移需求。

关注数据流量的走向和变化，数据流量的可见性是安全能力的重要基础之一，缺乏数据上下文，可能导致无法判断内容的敏感性或者是恶意，需要合理规划网络接入的流量引流至安全能力资源池。

 

**9 展望**

  

**1、SASE的标准化进程**

自Gartner2019年定义了SASE，国内外安全和网络供应商以及相关机构就开始持续推进针对SASE的标准研究。

国际上，城域以太网论坛（Metro Ethernet Forum，MEF）一直关注软件定义网络和安全基础服务的标准创建，MEF在2020年发布《MEF SASE服务框架》白皮书，概述了基于现有SD-WAN安全性和自动化以及其他标准化工作的SASE标准服务框架，通过在融合的网络和安全框架以及相关的SASE服务上达成共识，使供应商专注于提供通用的核心功能，并在此之外构建自己的创新能力。此外，MEF还启动了SASE服务和属性（MEFW117）项目。

在国内，中国通信标准化协会（China Communications Standards Association，CCSA）已经全面开展《基于安全访问服务边缘（SASE）网络总体技术要求》、《安全访问服务边缘技术指南》等相关标准的研究。

云安全联盟大中华区（CSA GCR）也正式成立了SASE工作组，开展基于中国安全环境的SASE实践落地研究。  

  

**2、SASE的成熟度**

由于缺乏SASE相关的标准，因此当前业界SASE的发展是自由和无序的发展状态，是一个市场自发的行为，容易造成参差不齐的状态，一些供应商提供基于云的安全服务，但是以牺牲SD-WAN的性能为代价，一些拥有成熟SD-WAN产品的供应商，提供的安全能力有限。为更好的推进SASE的发展，可以从以下几点评估SASE服务：

*   全面的网络和安全能力组合：SASE产品是否能够提供企业需求的网络接入能力和网络安全能力，所提供的哪些能力对企业最重要。
    
*   远程接入访问能力：SASE产品是否能支持众多使用移动设备的外出员工。能否提供统一的远程访问架构提升员工远程访问体验、简化远程办公流程并方便管理。
    
*   连接并保护人员和设备：SASE产品是否能保证企业各种接入设备的安全性，并能整合其物联网安全功能。
    
*   SASE的生态系统：SASE供应商是否拥有足够强大的技术合作伙伴体系来简化、合并网络、安全和管理方面的能力。
    
*   长期愿景和生存能力：SASE供应商要有长期愿景，能够快速灵活地适应新的市场需求、有能力进行创新和收购来满足产品更新的技术需求、具有敏锐的洞察力将新技术整合到SASE架构中。
    
*   使用场景：企业应当归纳总结应用场景、优先事项，将需求与对应SASE功能联系起来。  
    

  

**3、SASE的展望**

企业数字化转型和业务上云是SASE的重要驱动力。企业的数据中心不再是用户与设备访问需求的中心，大量SaaS 等基于云计算服务的部署，以及新兴的边缘计算平台，颠覆了传统的网络和应用架构模式，使企业网络架构出现“内外翻转”的现象。与此同时，数字化转型需要随时随地访问位于云端的应用和服务，传统的网络和网络安全体系架构无法满足数字业务的动态安全访问需求。

采用SASE架构，企业边界不再是一个位置；而是一组动态创建的、基于策略的安全访问服务边缘。SASE的本质是基于身份认证的整合网络和安全的边缘融合服务，是典型的云网安融合的新兴产品。

SASE将极大的改变产业业态，第一，促使网络厂商和安全厂商的融合；第二，是云网运营商向云网安运营商的转型，安全将成为刚需，无处不在；第三，专业安全厂商研发重点从设备研发转向VNF的研发和专业服务，其销售渠道主要依赖于云网运营商；第四，企业安全从业者能力要求大大降低，工作重心从设备采购配置向安全服务订阅管理转移。
