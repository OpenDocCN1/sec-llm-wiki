## syscall

### 分析

首先看一下题目开启的保护，开启了PIE与NX保护

![](../Images/09e89a201566e5182a6cd5f8abf79194.png "屏幕截图.png")

接着看一下程序的功能，程序提供了三个功能

*   `Encrypt`功能会输出`TQL`且多次测试发现只会输出这个字符串，目测没有太实际的作用
    
*   `DeCrypt`功能会接受我们的输入，且输入后的字符串会被加密然后输出
    
*   `ExIt`功能则会直接退出程序
    

![](../Images/d64f5da7c7b7bf6d8bb6db354d04f402.png "屏幕截图.png")

接着用`IDA`进行分析

#### main函数

程序通过`get_choice`函数接受我们输入的序号，接着实现相应的功能

```
nt \_\_cdecl \_\_noreturn main(int argc, const char \*\*argv, const char \*\*envp)
{
  int v3; // \[rsp+Ch\] \[rbp-4h\]
  while ( 1 )
  {
    menu();
    v3 \= get\_choice(\*(\_QWORD \*)&argc, argv);
    switch ( v3 )
    {
      case 1:
        decrypt();
        break;
      case 2:
        argv \= 0LL;
        \*(\_QWORD \*)&argc \= 60LL;
        syscall\_safe(60LL, 0LL, 0LL, 0LL);
        break;
      case 0:
        encrypt();
        break;
    }
  }
}
```

#### get\_choice函数

程序没有用往常惯用的`read`函数进行输入而是改用`syscall_safe`的自定义函数进行输入，结合题目的名称`syscall`并且`syscall_safe`的第一个参数为`0`可以想到该函数应该是调用了系统调用进行输入。

```
int get\_choice()
{
  char s\[32\]; // \[rsp+0h\] \[rbp-30h\] BYREF
  \_\_int64 v2; // \[rsp+20h\] \[rbp-10h\]
  char \*v3; // \[rsp+28h\] \[rbp-8h\]
  memset(s, 0, sizeof(s)); //初始化栈变量
  v3 \= s;
  v2 \= 0x20LL;
  syscall\_safe(0LL, 0LL, s, 0x20LL);//猜测接受我们的输入
  return atoi(s); //我们的输入保存到s中，使用atoi函数进行字符串到整形的转换
}
```

#### syscall\_safe函数

与猜测的一样，程序使用了`syscall`的系统调用,`x86-64`是通过`syscall`进行调用的而`x86-32`则是使用`int 0x80`,可以看出了该函数接受了4个参数`a1`、`a2`、`a3`、`a4`，通过该函数的汇编可以发现`a1`、`a2`、`a3`、`a4`分别会赋值给`rax`寄存器、`rdi=rcx`寄存器、`rsi`寄存器、`rdx`寄存器，即参数`a1`为系统调用号、`a2`为系统调用的第一个参数、`a3`为系统调用的第三个参数、`a4`为系统调用的第四个参数，但是这里对系统调用的参数分别做了小部分的限制，当`a1`为0或者1时即调用`read`函数或者`write`函数时(因为`read`函数与`write`函数的系统调用号分别为0与1,具体的系统调用可以查看系统调用表)，`a3`的值不能为0且`a4`的值不能大于`0x100`

*   read(`a2`,`a3`,`a4`)
    

*   `a2`代表文件描述符
    
*   `a3`代表输入缓冲区
    
*   `a4`代表长度
    
*   write函数同理
    

即`a3`值不能为空，即输入的缓冲区不能是地址0，因为这是无效地址，且输入输出的大小不能大于`0x100`到此就已经分析完该程序最核心的函数了，即输入输出函数都是通过系统调用实现的，倘若可以控制`a1`,`a2`,`a3`,`a4`参数即可完成任意函数的调用。如果不满足条件`v5`值会被设置成60，而`v5`与`a1`指向的值是一致的,60则是为`exit`的系统调用，即不满足要求会直接退出程序

```
\_\_int64 \_\_fastcall syscall\_safe(\_\_int64 a1, \_\_int64 a2, \_\_int64 a3, \_\_int64 a4)
{
  unsigned int v5; // \[rsp+18h\] \[rbp-18h\]
  v5 \= a1;
  if ( a1 \>= 0 && a1 <= 0x14C )
  {
    if ( (!a1 || a1 \== 1) && (!a3 || a4 \> 0x100) )
      v5 \= 60;
  }
  else
  {
    v5 \= 60;
  }
  \_\_asm { syscall; LINUX \- }
  return v5;
}
```

#### decrypt

`decrypt`函数是整个程序的关键，也是漏洞所在的地方。首先程序通过`syscall_safe`进行打印输出`context:`接着再次调用`syscall_wrapper`，并且`v3`作为参数传入

*   `v3[0]` = 0 = `a1`
    
*   `v3[1]` = 0 = `a2`
    
*   `v3[2]` = s = `a3`
    
*   `v3[3]` = 0x100 = `a4`
    

即调用了`read(0,s,0x100)`，往字符组`s`读入0x100字节的字符而漏洞点在于字符组`s`与数组`v2`的距离为`0x90 = rbp-0x50 -(rbp-0x140)`，数组`v2`又作为`syscall_wrapper`参数进行系统调用

```
s ----------> rbp-0x140
.....     ^ 
.....     |   距
.....     |   离
.....     |   0x90
.....     V
v2 ---------> rbp-0x50
```

由于输入的大小限制在`0x100`因此只能覆盖`v2[0]`与`v2[1]`因此能够覆盖系统调用号与第一个参数

```
\_\_int64 decrypt()
{
  char s\[240\]; // \[rsp+0h\] \[rbp-140h\] BYREF
  \_\_int64 v2\[4\]; // \[rsp+F0h\] \[rbp-50h\] BYREF
  \_\_int64 v3\[5\]; // \[rsp+110h\] \[rbp-30h\] BYREF
  int i; // \[rsp+138h\] \[rbp-8h\]
  int v5; // \[rsp+13Ch\] \[rbp-4h\]
  memset(s, 0, 0x100uLL);
  v2\[0\] \= 1LL;
  v2\[1\] \= 1LL;
  v2\[2\] \= (\_\_int64)s;
  v3\[0\] \= 0LL;
  v3\[1\] \= 0LL;
  v3\[2\] \= (\_\_int64)s;
  v3\[3\] \= 0x100LL;
  v3\[4\] \= (\_\_int64)"context:";
  syscall\_safe(1LL, 1LL, (\_\_int64)"context:", 8LL); //调用write函数打印
  syscall\_wrapper(v3);  //将v3数组作为参数传入
  v5 \= strlen(s); //计算输入的长度
  if ( v5 \> 0x100 ) //长度不能大于0x100
    v5 \= 0x100;
  for ( i \= 0; i < v5; ++i ) //放射加密
    s\[i\] \= 0xA7 \* (s\[i\] \- 0x23);
  s\[v5 \- 1\] \= 0;
  v2\[3\] \= strlen(s);//计算加密后的长度
  return syscall\_wrapper(v2); //将v2数组作为参数传入
}
```

### 漏洞利用

从分析可知，可以利用的条件有

*   `rax`寄存器==系统调用号(可控)
    
*   `rdi`寄存器 == 第一个参数值(可控)
    
*   `rsi`寄存器 == 第二个参数值(输入的缓冲区地址)
    
*   `rdx`寄存器 == 输入的长度(可控)
    

系统调用的利用，大都是通过

```
open("./flag","r") //利用open调用打开flag文件进行rw回显
execve("/bin/sh",0,0) //获取shell权限
```

题目开启了`PIE`保护，并且输入缓冲区每次在使用前都进行了清空操作，因此不能利用栈上残留数据进行地址的泄露，因此需要利用其他的系统调用

```
memset(s, 0, 0x100uLL);
```

**可利用的系统调用**

除了`open`与`execve`还存在类似的系统调用`oepnat`与`execveat`

**execveat**

*   当`filename`为空且`flags`为`AT_EMPTY_PATH`时，文件描述符`dirfd`指定的文件将被指向
    

**openat**

*   当`filename`为绝对路径,则`dfd`被忽略
    
*   当`filename`为相对路径则相对于`dfd`所指定的目录进行引用
    
*   当`filename`为相对路径且`dirfd`为`AT_FDCWD`则相对于当前目录引用
    

利用`execveat`和`openat`可以将`filename`参数修改为第二个参数，并且在程序中第二个参数为输入缓冲区的地址。还需要注意一个问题是，通常情况下`/bin/sh`文件为只读权限而`flags`取值为

*   `O_RDONLY`(只读) 对应数值为0
    
*   `O_WRONLY`(只写)对应数值为1
    
*   `O_RDWRD`(读写)对应数值为2
    

因此`flags&(O_WRONLY | O_RDWRD) == flags&3 == 0`则需要构造

```
openat(任意值,'//bin/sh',strlen('//bin/sh'));
/\*
由于/bin/sh的长度为7，此时7&3!=0
而//bin/sh的长度为8，此时8&3 == 0
\*/
```

接着配合`execveat`即可拿到`shell`权限

execveat(3,"",0,0,AT\_EMPTY\_PATH);
