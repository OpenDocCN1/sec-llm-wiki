frp介绍

frp是一个专注于内网穿透的高性能的反向代理应用，支持TCP、UDP、HTTP、HTTPS等多种协议。可以将内网服务以安全、便捷的方式通过具有公网IP节点的中转暴露到公网。

为什么使用 frp？

通过在具有公网IP的节点上部署frp服务端，可以轻松地将内网服务穿透到公网，同时提供诸多专业的功能特性，这包括：

  • 客户端服务端通信支持 TCP、KCP以及Websocket等多种协议。

  • 采用TCP连接流式复用，在单个连接间承载更多请求，节省连接建立时间。

  • 代理组间的负载均衡。

  • 端口复用，多个服务通过同一个服务端端口暴露。

  • 多个原生支持的客户端插件（静态文件查看，HTTP、SOCK5代理等），便于独立使用frp客户端完成某些工作。

  • 高度扩展性的服务端插件系统，方便结合自身需求进行功能扩展。

  • 服务端和客户端UI页面。

应用场景

  1. 内网搭建的服务，可将服务映射到公网ip的某个端口上，便于共享资源。

  2. 实施渗透测试时，可将无法直接访问的内网环境or服务映射出来，便于测试。

frp安装和使用
frp服务端(vps)：
  1. 项目releases页面下载对应的压缩包 https://github.com/fatedier/frp/releases/download/v0.35.0/frp_0.35.0_linux_amd64.tar.gz
  2. 解压缩之后修改frps.ini文件内容
[common]
bind_port = 7000
token = passtest
bind_port表示服务端端口，token表示认证密码(尽量复杂一点)。
  1. 服务端启动：./frps -c frps.ini
  2. frps服务化
cat >> /lib/systemd/system/frps.service <<EOF
[Unit]
Description=fraps service
After=network.target syslog.target
Wants=network.target

[Service]
Type=simple
ExecStart=/root/frp_0.35.0_linux_amd64/frps -c /root/frp_0.35.0_linux_amd64/frps.ini #此处按实际情况修改

[Install]
WantedBy=multi-user.target
EOF

systemctl start frps
systemctl enable frps

从以上可以看出只有端口10022访问失败，那么为什么会失败呢？
我们是在10.0.0.66这台机器上安装了虚拟机，再在虚拟机上通过docker安装了frp的客户端，当我们通过vps的10022端口请求内网的127.0.0.1的22端口时，相当于请求了该docker容器自身的22端口，而不是192.168.11.11这台机器的22端口，这样做在一定程度上提高了安全性同时也更容易理解frp的原理。另外直接在机器上用命令开启客户端的方式更常用一点。
实际上当我们通过服务端端口访问内网某个ip的时候，请求的发送路径是从人这个客户端请求到vps某端口然后再到frp客户端再到frp客户端所在系统再到目的ip和对应的端口,也就是client(people)->vps:port->frp client->system of frp client->destination server这样一个流程。
