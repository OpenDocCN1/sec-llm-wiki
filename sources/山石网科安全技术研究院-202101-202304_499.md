# **漏洞信息**

Oracle System PAM组件缓冲区溢出漏洞（CVE-2020-14871）\[1\]受影响的版本：     Oracle Solaris 11Oracle Solaris10Oracle Solaris 9（已不支持，2014年已终止）安全建议：

1.  升级系统，安装相应补丁。需要从Oracle官方手动下载。
2.  如果无法进行升级建议修改sshd\_config文件，并将ChallengeResponseAuthentication和KbdInteractiveAuthentication选项配置为no。这将限制UNC1945和其他人试图利用的当前攻击媒介，但是可能还有其他方法可以触发利用。此缓解措施应仅在升级可行之前临时应用。

  

# **背景**

2018年底，FireEye子公司Mandiant的FLARE AdvancedPractices团队，在追踪UNC1945团体的活动时发现该团体在一台Oracle Solaris操作系统上安装了一个被称为SLAPSTICK的后门，用以捕获连接详细信息和身份凭证。转眼间到了2020年中旬，Mandiant观察到UNC1945团体在Oracle Solaris9服务器上部署了称为EVILSUN的远程利用工具。\[2\]通过分析发现该工具利用Oracle Solaris Pluggable Authentication Module (可插拔身份验证模块，简称PAM)的基于堆栈的缓冲区溢出漏洞获取最高系统权限。FLARE小组的进攻性特遣队（OffensiveTask Force）分析了此漏洞以确定其工作方式，并在不同版本的Solaris系统上重现了漏洞，然后将其报告给Oracle。这是一个存在已久的zero-day漏洞。根据2020年4月在黑市网站上的帖子，“Oracle Solaris SSHD远程根攻击”的价格约为3,000美元。更有消息称，早在2015年Hacking Team泄露的邮件表明2014就有组织可以出售SunSSHD的漏洞按月收费。

# **漏洞分析**

PAM是动态身份验证组件，从1997年开始，它就已作为Solaris 2.6的一部分集成到Solaris中。该漏洞的CVSSv3评分为10.0，这是最高的评分。在发布时，此漏洞的Tenable VPR分数也为10.0。pam\_framework.c文件中的parse\_user\_name（）函数，“username” 缓冲区是一个由PAM\_MAX\_RESP\_SIZE（pam\_appl.h）定义的512字节数组，该数组在函数开始时在堆栈上声明。当执行通过PAM的身份验证时，此缓冲区用于保存提供给parse\_user\_name（）函数的用户名。“ user\_input”参数在第658行进行while循环处理，该循环将跳过任何已识别的空格或制表符，并且在662行将user\_input自变量的每个字节写入固定大小的用户名缓冲区。存在此漏洞是因为此函数不检查用户名堆栈数组的边界，因此可以通过向该函数提供一个长度大于512字节的user\_input参数来写越过缓冲区的边界。这是一个经典的“stack-smashing”示例，它使攻击者可以破坏堆栈帧，覆盖重要的变量，例如当前执行函数用作返回地址的指针。现在我们已经了解了漏洞的详细信息，我们可以通过使用parse\_user\_name（）函数查找代码来确定触发问题的方法。

在配置中启用了“keyboard-interactive”身份验证的SunSSH上使用时（除非更改，否则为标准默认设置），SunSSH将利用“authtok\_get”PAM模块提示输入用户名和密码。PAM模块将使用pam\_sm\_authenticate（）提供的用户名，该用户名将调用pam\_get\_user（）并最终将我们的用户名直接提供给parse\_user\_name（）函数。Solaris 11.1中，用户名在到达易受攻击的代码路径之前被截断，以防止通过SunSSH发生溢出。要触发PAM身份验证提示，我们可以使用空的用户名连接SSH，在要求提供用户名时在传递一个大于512字节的用户名，从而导致堆栈帧被破坏，并且远程SunSSH进程将在目标上进行core dump。下面显示了使用标准OpenSSH客户端触发此问题的示例。
