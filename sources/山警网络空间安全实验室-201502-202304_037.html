2021级 甲小由|基于pe文件结构的几个实验

实验一

目标

在文件运行之前，增加一个弹窗

具体步骤

1.用lpe查看程序基本信息

numberofsection:4 右侧section按钮可以查看4个部分的详细信息

再section table中右键，可以add new section,

voffset为虚拟地址的开端，flag非连续代表不同模式 节属性，右键可以修改

此次，我修改vsize 0=>1000 Rsize 0 = >200 （具体为啥？？？）flag用不到的去掉（也可不去）

名称 虚拟地址 虚拟地址长度 文件中的位置 文件中的地址长度 标志

运行，第一次报错，改变后实际内存没有变大。添加新节后，大小应该是原大小+新节大小

2.解决内存大小统一问题

利用c32修改文件大小，图中大小单位为字节 在文件末位填充0x200(512)个0.

记录最后一行地址：00031ff0,下一行的开头地址应该就是：上图所示的roffset的值：32000

换算技巧如下，ffh=255 100h=256 200h=512

插入512个数字即可

且在lpe中pe editor中sizeofimage（镜像基址）修改大小为原大小+新节大小=36000 或者理解为：sizeofimage=voffset+vsize

之后，用c32修改的实际文件大小和lordpe修改出的文件头大小相等

也比之前的大小大出1kb

3.最后，利用od进行修改

①记录入口点s，通过观察可见，在lordpe中所示entrypoint（入口偏移地址）+imagebase（基址）=入口点

②（lordpe）修改入口点为新节起始地址，再用od打开即可从新入口点进入。由此，做出以下推断，lordpe只是将pe头数据可视化，并不能自动适配。系统执行文件也是在pe头识别开始地址

③写入代码

选中一行 ctrl+g? 跟进至此行开始写入hex字符串，记录此行地址，以备后面调用参数使用。然后移动至16进制窗口，空格开始写入字符串。记录字符串地址x,y(符合messageboxa的参数)（p.s.修改之后，虽然上方将16进制数识别为代码，但是不会执行）

push 0  //004182ec
push x
push y
push 0
call MessageBoxA

修改之后，右键

保存

ok

实验二

前言

可执行文件加载时，先将文件加载到内存，是文件从磁盘映射到内存。

目的

比较内存和磁盘中文件的差异。

步骤

首先用RadASM写一程序

代码如下
.386
.model flat,stdcall
option casemap:none

include windows.inc
include kernel32.inc
include user32.inc
includelib kernel32.lib
includelib user32.lib

   .data
szCaption db  '申卫华同志',0
szText    db  'happy father·s day',0

   .code
start: 
   push 0
   lea eax,szCaption
   push eax
   lea eax,szText
   push eax
   push 0
   call MessageBox
   push 0
   call ExitProcess
   
  end start
分别用winhex打开磁盘和内存中的test.exe

注意，运行起来的程序才能在ram中被找到。

比较

总结一下，不同点有下

  1. 基址不同：磁盘基址为0x0,而内存基址为0x400000.
  2. 相同内容的十六进制不同。
  3. 相同数据间间隔不同。

详细介绍pe文件的各部分

注意：大部分16进制分析软件，将程序的16进制数据依据ascii码表翻译出。

PE头

定义程序部分各类数据的位置

大体上，程序可分为以下部分

指令
只读数据
数据（可读可写）
DOS头（IMAGE DOS HEADER）

是为了兼容以前的dos系统而设的

在dos系统中指令和数据混合起来，成线性排列

结构如下：
typedef struct_IMAGE_DOS_HEADER{
  WORD e_magic;   //大小为2btye=4个16进制数  地址为0x0  ASCII：MZ  EXE标识
..........
  LONG e_lfanew;  //大小为4btye=8个16进制数  地址0x3c 真PE头偏移地址在此处以小端序的方式储存
}IMAGE_DOS_HEADER;  *PIMAGE_DOS_HEADER

最后4个字节表明：真的pe头地址为：00 00 00 0b

判断是否为一个pe文件，0x0为MZ 追踪 LONG e_lfanew到的PE头为50 45 00 00

文件中只保留DOS头，并进行编译
放进ida
public start
start proc near  //文件开头
push    cs
pop     ds   
//cs为指令段 ds为数据段。这两条指令将这两段统一，意为dos系统在内存中线性执行代码  
assue ds:seg000
mov     dx, 0Eh
mov     ah, 9
int     21h             ; DOS - PRINT STRING
                        ; DS:DX -> string terminated by "$"
mov     ax, 4C01h
int     21h             ; DOS - 2+ - QUIT WITH EXIT CODE (EXIT)
start endp              ; AL = exit code

int 21h

iNT 21H叫系统功能调用，也就是系统功能调用接口。

其中，dx中储存数据，ax中储存指令，int 21h 使其执行

ax中为操作代码（编号），不同编号对应于BIOS中预先存储的程序段，可完成不同功能.

mox ax , 4c01h
int 21h // 4c01h是exit的操作码，这段指令结束程序

mov dx, 0eh
mov ah, 9
int 21h //0eh=A  9号操作码为print  这段指令为  print（“A”）
