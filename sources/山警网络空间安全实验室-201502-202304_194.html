「sudoer配置文件错误」

有的时候，普通用户经常要执行某个命令，管理员会通过配置/etc/sudoers文件来实现普通用户某个命令权限的提升，但是如果一旦是给了用户写入的root权限，比如vi，就可以通过vi来提权

cd /etc/sudoers
chmod u+w /etc/shudoers
vi /etc/sudoers
看到这里
# User privilege specification
root    ALL=(ALL:ALL) ALL

第一个ALL：用户 ALL:ALL：指以谁的身份去执行，root就行了

最后一个ALL：指所有的命令，如/bin/ls

在文件中写入guest=(root) /bin/ls

su guest
ls /root

你会发现可以查询了

「🚩」.user.ini漏洞

❞

PHP官方介绍里的user.ini文件：

自 PHP 5.3.0 起，PHP 支持基于每个目录的 .htaccess 风格的 INI 文件。此类文件仅被 CGI／FastCGI SAPI 处理。此功能使得 PECL 的 htscanner 扩展作废。如果使用 Apache，则用 .htaccess 文件有同样效果。

除了主 php.ini 之外，PHP 还会在每个目录下扫描 INI 文件，从被执行的 PHP 文件所在目录开始一直上升到 web 根目录（[$_SERVER['DOCUMENT_ROOT'] 所指定的）。如果被执行的 PHP 文件在 web 根目录之外，则只扫描该目录。

在 .user.ini 风格的 INI 文件中只有具有 PHP_INI_PERDIR 和 PHP_INI_USER 模式的 INI 设置可被识别。

两个新的 INI 指令，user_ini.filename 和 user_ini.cache_ttl 控制着用户 INI 文件的使用。

user_ini.filename 设定了 PHP 会在每个目录下搜寻的文件名；如果设定为空字符串则 PHP 不会搜寻。默认值是 .user.ini。

user_ini.cache_ttl 控制着重新读取用户 INI 文件的间隔时间。默认是 300 秒（5 分钟）。

所以，.user.ini实际上就是一个可以由用户“自定义”的php.ini，我们能够自定义的设置是模式为“PHP_INI_PERDIR 、 PHP_INI_USER”的设置。

php.ini中有两项：

auto_prepend_file 在页面顶部加载文件

auto_append_file 在页面底部加载文件

类似于在文件前调用了require()函数。使用方法很简单，直接写在.user.ini中，例如：

auto_prepend_file=01.gif

这里01.gif是要包含的文件。所以，就可以借助.user.ini让所有php文件都“自动”包含某个文件

做题时的使用方法：某网站限制不允许上传.php文件，便可以上传一个.user.ini，再上传一个图片马，包含起来进行getshell。不过前提是含有.user.ini的文件夹下需要有正常的php文件，否则也不能包含了。

xss漏洞简介

xss：跨网站脚本攻击（区别于css 层叠样式表），主要形式就是将恶意代码植入网页，当用户访问此网页时，恶意代码将得到执行，从而达到攻击的目的。

xss的危害：通过这些恶意代码，攻击者可以获取用户的cookies，以及获取用户的其他敏感信息，接下来可以利用这些信息进行攻击其他服务器或植入木马等具有危害性的行为。

xss的类别

  1. 「反射型xss攻击」

「此类xss攻击不会储存在服务器端，一般用于构建恶意网页，引诱客户访问此网页以达到攻击的目的：」

「测试代码」

<?php
if (isset($_GET['name'])) {
       $name=$_GET['name'];
       echo "<h1> Hello ".$name."<h1>";
}else{
       exit();
}
?>

这是个最简单的测试代码，没有对用户的输入做任何过滤。

这时候我们可以在URL中构造?name=以下为本地测试结果：

由于本人很菜，所以写不了高大上的恶意攻击脚本，只写了一个js的弹窗语句，狗头保命！

2.存储型xss攻击

顾名思义，与反射型攻击不同，此类型攻击将恶意代码直接储存在服务器端，一般手段是通过留言板等输入表单植入，如果服务器端对用户的输入过滤不够严格则易发生存储型xss攻击。

比如这里，url并没有问题，但是依旧弹出了1，原因就是恶意代码储存在服务器端，并不会在url中显示，所以论迷惑性存储型要高于反射型，因为用户并不能通过url察觉异常。

3.DOM型xss攻击

这种类型的攻击可以称为较为高级的xss了，因为它正是利用了开发者的安全防护护措施，在反射型xss中，漏洞的原因是对用户的输入不做过滤，而DOM正是利用了对用户输入的防护，举一个栗子：如果服务器端将输入的参数编码后再存储到数据库中，那么DOM攻击便类似于解码，将参数再次转变为实体字符。（以上理解来自一个很菜的弟弟，如有出错欢迎斧正！）

接下来谈谈CSRF跨站请求伪造

CSRF通常与xss联合使用，相互配合

通俗的解释一下就是服务器分不清浏览器发出的请求与用户的请求，也就是说如果浏览器访问了恶意网址，那么浏览器就会“背着你”向服务器发送一些请求。

那么如何检测CSRF呢

  • 去掉token参数尝试能否请求成功
  • 去掉referer尝试能否请求成功
  • 是否可以用GET 代替 POST

如果上述三项都存在，那么就存在CSRF，而现在大部分网站的防护措施便是增加验证机制

  • referer验证
  • token验证
  • 验证码，图片验证

其中防范等级依次递增

Sqlmap工具几种基本用法详解

1.主要功能：

一个用来做sql注入攻击的工具。

扫描、发现、利用给定的url的sql注入漏洞，内置许多绕过插件。

❝

注意：需要python2才能运行，python3不可

❞

sqlmap工具压缩包官方下载地址:http://sqlmap.org/

2.支持的数据库：

mysql、oracle、sql server、access、DB2、sqlite、postgresql、Firebird、sybase、sap maxDB。

3.采用5种注入技术：


[1]基于布尔的盲注：根据返回页面判断条件真假

[2]基于时间的盲注：使用条件语句查看时间延迟语句是否执行（页面返回时间是否增加）

[3]基于报错注入：返回错误信息，或将注入语句的结果返回页面中

[4]联合查询注入：在允许使用union的情况下注入

[5]堆查询注入：同时执行多条语句注入

4.用法
