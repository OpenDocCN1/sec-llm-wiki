栈挟持&栈迁移

前言：

在我们只能够控制ebp的情况下，我们怎么才能够控制eip去拿到我们的shell？

我们可以使用栈迁移的方法去控制

原理：

在我们执行玩函数的时候

会有如下指令：

1leave;
2ret;

实际上这两个汇编指令的实际意义是这样的：

1leave  == mov esp,ebp;
2pop ebp;
3ret   == pop eip 
4#弹出栈顶数据给eip寄存器

我们看到了eip寄存器，我们知道之后程序会继续执行eip寄存器中存储地址指向的指令

所以，如果我们可以劫持eip的话，我们就可以劫持程序流，去执行我们想要执行的指令

当然，原理只是原理，原理与实践总是差距很大，那么我就来拿一道题来详细说明一下

例题：ciscn_2019_es_2

分析：

1、32位程序，开了NX保护（堆栈不可执行）

2、看程序可以发现存在两次写入以及printf

3、我们发现有个hack函数。但是溢出后发现并不能获取flag（就是一个打印‘flag’的函数）

4、因此我们可以写入shell

5、但同时，我们发现我们能输入的字符数量不多，就是说无法达到我们构造rop链的要求

6、因此我们可以利用栈迁移来进行getshell

我先来说一下模板：

一、如果我们只想将空间在本函数的栈空间上扩展的话

1payload = 'a' * 4 or 8 + ret（想要执行的函数）+offset+leave_ret + 参数1+参数2......

解释一下：

1、第一部分取决于程序是32位还是64位地址

2、只是想在本地栈空间操作，所以第一部分的数据只是为了pop ebp

3.第二部分为我们pop eip的操作

4.offset为了将我们的leave指令覆盖如本栈的ret地址处，另外也可以作为根据我们想执行函数的rop链或者参数

5.参数1，参数2可以是我们想执行函数的参数，也可以没有

二、

如果想转移到其他位置，例如bss段的话

可以将ebp的地址覆盖为bss段的某一地址

我们以32位程序为例

1payload = offset + bss的某一地址（覆盖的ebp）+ read_add(覆盖的ret) + leave_add(read函数的返回地址) + 参数1，参数2，参数3

1.这里的话如果bss段是可写可执行的，那么我们就可以通过read函数去进行对bss处的写入，read内容：

（0，bss某一地址，长度）

2.若还想继续迁移的话，此时我们的ebp指针已经指向的是bss的某一地址，因此我们我们可以根据上一个payload

重新进行迁移，当然，若果空间充足，可以尽情执行rop链

思路：

1.本题目的printf函数会泄露ebp地址

1.我们先使用printf泄露我们的ebp

2.ebp即为我们的栈地址，可以通过调试获取esp相对于栈地址的偏移，从而获取esp的地址

3.构造payload，因为题目中有system，所以不用泄露libc地址

4.直接栈向前迁移，然后调用system使用我们写入的/bin/sh参数即可
