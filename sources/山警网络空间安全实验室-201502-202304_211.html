web1

题目开始就放源码

<?phperror_reporting(0);require 'flag.php';$value = $_GET['value'];$password = $_GET['password'];$username = '';for ($i = 0; $i < count($value); ++$i) {    if ($value[$i] > 32 && $value[$i] < 127) unset($value);    else $username .= chr($value[$i]);    if ($username == 'w3lc0me_To_ISCC2019' && intval($password) < 2333 && intval($password + 1) > 2333) {        echo 'Hello '.$username.'!', '', PHP_EOL;        echo $flag, '<hr>';    }}highlight_file(__FILE__);

代码审计第8行题目给出了提示，count($value)提示我们应该传入一个value数组，并且value值在chr()之后拼接成为’w3lc0me_To_ISCC2019’ ，并且value[]的ascii码不能在32到127之间，这些都是我们需要绕过的地方。

写个两行代码，获取w3lc0me_To_ISCC2019的ASCII码：

array = map(ord, 'w3lc0me_To_ISCC2019')print(list(array))[49, 53, 116, 104, 95, 72, 97, 99, 107, 105, 110, 103, 67, 97, 109, 112]

发现这些数都在32-127 之间，都会被unset($value) ！！！

查看PHP Maunal中有关于chr()函数的使用笔记：

Note that if the number is higher than 256, it will return the number mod 256.

For example :

chr(321)=A because A=65(256)

就是说，如果一个数大于256，就会自动取mod256后再把结果传进函数。奈斯，马上构建函数修改：

array = map(ord, 'w3lc0me_To_ISCC2019')def plus(x):    return x+256result = map(plus, array)print (list(result))[375, 307, 364, 355, 304, 365, 357, 351, 340, 367, 351, 329, 339, 323, 323, 306, 304, 305, 313]

总结：绕过这些限制需要几个小trick 

1. chr函数在转换时会自动取模256,所以我们只需要在原本ascii码基础上+256即可 

2. intval()在处理16进制时存在问题,但强制转换时时正常的

绕过验证码：很多验证码是先带着cookie访问某个文件然后登陆时再判断该cookie的验证码是否正确

或者对于一些混淆不明显的验证码，可以直接识别出验证码然后进行爆破

这道题把cookie和验证码去掉进行爆破即可：

web3

主页是登陆页面

注册一个账号登陆发现可以更改密码

联想到sql-labs中LESS-24中的二次注入猜测是通过sql注入改变admin的密码

尝试注册admin'or 1#然后登陆更改密码为123，再登陆admin，密码为123，成功得到flag

估计后台更改密码处用的就是简单地拼接语句，列名，表名皆为臆测：

update users set password='$_POST["password"]' where username='$_POST["username"]';

如果我们username传入admin'or 1#，password传入123，查询语句就会变为：

update users set password='123' where username='admin'or 1#';
