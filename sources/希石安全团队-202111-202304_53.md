```
<?phpnamespace Home\Controller;use Think\Controller;class IndexController extends Controller {    public function index(){        $data['user_login'] = array('eq','admin');        $value = M('users')->where($data)->order(I('order'))->find();        var_dump($value);    }}

## payload

```
?order=id and updatexml(1,concat(0x7,user(),0x7e),1)

## **0x02 漏洞分析**

不妨在`$value`处下断点，然后跟进到I方法，第一个问题还是`think_filter` 方法未过滤`updatexml`

![](../Images/bb383b7fd9ba5ea1f6d193b38004fb32.png)

由于可控处位于order处，所以不必关注`where`相关的处理，不妨一直跟进到`find`方法，可以看到其会执行`select`方法

![](../Images/05dfd3e73bc7181cb1bb0a753295c3c8.png)

不妨跟进去继续分析，可以看到会执行`buildSelectSql` 方法

![](../Images/d65553b345c74ff0fe5f17397f6a6fc0.png)

很熟悉的步骤，跟进去，其会执行`parseSql`方法

![](../Images/8a52a777ded280e352b096e3fc2f1389.png)

跟进去继续分析，这里很明显，问题应该会出在`parseOrder`方法

![](../Images/8184f8f118a219c74423099e084ea2d6.png)

跟进到`parseOrder`方法，继续分析，可以看到如果`$order`的值不为数组，则order by 和参数值直接拼接造成注入

![](../Images/b983d9830e20883af159233926c9ed75.png)
