0x02 漏洞分析

不妨在I方法处下断点跟进，其参数会被htmlspecialchars方法进行过滤，然后被think_filter 方法过滤，可以看到此处未对"bind"进行过滤

随后进入where方法，由于参数为数组且$parse 为空，所以此处参数也直接赋予$this->options['where']

然后就会进入save方法，在这里会进入_parseOptions 方法

不妨跟进去继续分析，由于传入的参数为数组，且有两个值，因此不满足is_scalar($val)的条件，所以将不会被_parseType方法进行强转

然后，将进入update方法

跟进去进行分析，其会执行parseWhere方法

不妨继续跟进去，发现其会执行parseWhereItem 方法

跟进去分析，发现当$exp为'bind'时，$key的值和id[1]的值将会拼接为$key=:$id[1]的形式

然后将进入到execute方法

不妨跟进去继续分析，发现strtr方法会将:0 替换为外部传入的字符，即参数user的值

因此冒号将被替换掉，我们的语句将被拼接为如下形式


UPDATE `catfish_users` SET `user_login`='' WHERE `id` = '' and (updatexml(1,concat(0x7e,user(),0x7e),1))
