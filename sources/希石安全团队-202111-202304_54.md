## 0x02 漏洞分析

不妨在`I`方法处下断点跟进，其参数会被`htmlspecialchars`方法进行过滤，然后被`think_filter` 方法过滤，可以看到此处未对"bind"进行过滤

![](../Images/e2082af4b68d41d539923048846d3274.png)

随后进入`where`方法，由于参数为数组且`$parse` 为空，所以此处参数也直接赋予`$this->options['where']`

![](../Images/7e3cc7eada4e285d4050556c3661359b.png)

然后就会进入`save`方法，在这里会进入`_parseOptions` 方法

![](../Images/31006d9f7da514b54b2e376ff6379267.png)

不妨跟进去继续分析，由于传入的参数为数组，且有两个值，因此不满足`is_scalar($val)`的条件，所以将不会被`_parseType`方法进行强转

![](../Images/826831b618ab3433d0eab7c980efe02a.png)

然后，将进入`update`方法

![](../Images/110825748e689e0a9fff984971e70864.png)

跟进去进行分析，其会执行`parseWhere`方法

![](../Images/66a8a67ccd81f3415adb598005e1c21a.png)

不妨继续跟进去，发现其会执行`parseWhereItem` 方法

![](../Images/406d873ee3f4afc9270403dbd2acec0b.png)

跟进去分析，发现当`$exp`为'bind'时，$key的值和id[1]的值将会拼接为`$key=:$id[1]`的形式![](../Images/e513db94605afed48b316828209ba89a.png)

然后将进入到`execute`方法

![](../Images/00b84179696175fa6ca186abf2d48dcf.png)

不妨跟进去继续分析，发现strtr方法会将`:0` 替换为外部传入的字符，即参数`user`的值

![](../Images/7485311630be3c363b4cfcecc7998ed9.png)

因此冒号将被替换掉，我们的语句将被拼接为如下形式

  

```
UPDATE \`catfish\_users\` SET \`user\_login\`='' WHERE \`id\` = '' and (updatexml(1,concat(0x7e,user(),0x7e),1))
```
