0x01 wher注入

Demo

<?phpnamespace Home\Controller;use Think\Controller;class IndexController extends Controller {    public function index(){        $data =M('users')->find(I('GET.id'));        var_dump($data);    }}

payload

?id[where]=1 and 1=updatexml(1,concat(0x7e,database(),0x7e),1)


0x02 漏洞分析

在I方法处下断点，将payload传入，然后跟进分析，

发现该方法首先会取出数组id里面的值，赋予$data

然后使用htmlspecialchars方法对其进行了过滤

随后使用think_filter方法进行了过滤

进去看一下，发现没有过滤updatexml

继续往下跟，跟进到了find方法，由于传入的值为数组，所以$options将直接被_parseOptions方法处理，跟进看看

由于传入的$options为数组，所以和$this->options进行了合并

然后，由于不满足is_array($options['where'])的条件，所以将不会被_parseType方法进行强转

随后将进行select查询

其并没有再进行任何过滤

因此我们的语句最终被拼接为以下形式

SELECT * FROM `catfish_users` WHERE 1 and 1=updatexml(1,concat(0x7e,database(),0x7e),1)LIMIT 1

最终效果如下

所以形成该漏洞的原因如下：

  1. think_filter方法中，黑名单过滤不严

  2. find方法中，$thins->options参数可被传入的参数污染


0x03 修复方法

1.使用数组传参

<?phpnamespace Home\Controller;use Think\Controller;class IndexController extends Controller {    public function index(){        $map['id'] = I('GET.id');        $data =M('users')->where($map)->find();        var_dump($data);    }}

2.升级至3.2.4

官方将$options与$this->options区别开来，以避免参数污染，从而防止了该方法的注入。
