**0x01 前言  
**

应用有时需要调用一些执行系统命令的函数，如PHP中的`system`、`exec`、`shell_exec`、`passthru`、`popen`、`proc_popen`等，当用户能控制这些函数中的参数时，就可以将恶意系统命令拼接到正常命令中，从而造成命令执行攻击，这就是命令执行漏洞。

  

**0x02 漏洞原因**  

*   应用没有对用户的输入做严格的检查过滤，导致用户输入的参数或恶意代码被当成命令来执行。
    
*   Web服务器没有过滤危险函数导致命令执行漏洞攻击成功。
    

  

**0x03 漏洞危害**

1.继承web服务程序的权限去执行系统命令或写文件。

2.反弹shell，获取目标服务器的权限。

3.进一步内网渗透

  

**0x04 远程命令执行**

在PHP中，又是需要调用一些执行命令的函数，如果存在一个使用这些函数且未对可被用户可控的参数进行检查过滤的界面，那么这个页面就可能存在远程命令执行漏洞。

1.eval()和assert()函数例：

*   
*   

```
<?php @eval($_POST['cmd']); ?><?php @assert($_POST['cmd']) ?>
```

注意：eval()函数传入的参数必须为PHP代码，即要以分号结尾；assert()函数是直接将传入的参数当成PHP代码执行，不需要以分号结尾。**2.****preg\_replace()函数**preg\_replace('正则规则','替换字符','目标字符')例：

*   
*   
*   

```
<?php    prge_replace('/test/e',$_POST["cmd"],"just test");?>
```

原理：PCRE修饰符：preg\_replace()在进行对替换字符串的后向引用替换之后，将替换后的字符串作为php代码执行（eval函数方式）,并使用执行结果最为实际参与替换的字符串。

**3.****array\_map()函数**

将用户自定义函数作用到数组中的每个值上，并返回用户自定义函数作用后的带有新值得数组。例：

*   
*   
*   
*   
*   
*   
*   

```
<?php    $func=$_GET['func];    $cmd=$_POST['cmd'];    $array[0]=$cmd;    $new_array=array_map($func,$array);    echo $new_array;?>
```

```


cmd1|cmd2：无论cmd1是否执行成功，cmd2将被执行
```
