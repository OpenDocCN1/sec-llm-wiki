# S2-062漏洞原理分析

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzIzODAwMTYxNQ==&mid=2652142452&idx=1&sn=f682bb48510b36243f29813f9fc8c5f6&chksm=f320d7d4c4575ec27ee173ed4be2870e4bf6cfe7d62991059578926442d5c898a25602c7887e&scene=126&sessionid=1681380582#rd](http://mp.weixin.qq.com/s?__biz=MzIzODAwMTYxNQ==&mid=2652142452&idx=1&sn=f682bb48510b36243f29813f9fc8c5f6&chksm=f320d7d4c4575ec27ee173ed4be2870e4bf6cfe7d62991059578926442d5c898a25602c7887e&scene=126&sessionid=1681380582#rd)

S2-062漏洞形成的原因是struts在处理标签的name属性时，将用户输入当作表达式进行二次解释，导致OGNL表达式注入。  
 和S2-061/S2-059类似，不过S2-061和S2-059是ID属性导致的，S2-061是对S2-059修复黑名单的绕过。 下面我们先回顾一下前两个漏洞：  

#### ****\>\>\>\> ******S2-059**

  
影响版本：Struts 2.0.0 - Struts 2.5.20 漏洞原理： 漏洞代码样例：<s:a id="%{id}">SimpleTest</s:a> 输入为id=%{8\*8}，标签解析由org.apache.struts2.views.jsp.ComponentTagSupport#doStartTag()方法开始；第一次OGNL解析在populateParams()方法中，第二次在start()方法中。 ![](../Images/5901109f0476d7aa47cdf9b5489e269b.png)  
省略部分调用栈，populateParams()方法经过多层调用进入AbstractUITag#populateParams()方法中，其调用uiBean.setId(this.id)。 ![](../Images/d58c05100bdfe67b12694fe3e2e9c03b.png)  
该方法继续调用了findString(id)，并且将返回值赋给了this.id。  ![](../Images/635dd451923e24573565b4706c622f29.png)  
省略部分调用栈，findString()最终调用了OgnlTextParser#evaluate()方法，其去掉%{}，var=id，并调用evaluator.evaluate()去解析。 ![](../Images/e6fc9254f25d00bf546ba3be3857eba7.png)  
evaluator.evaluate(var)解析返回了id的值%{8\*8}，最终这个值被返回给上层调用，赋给了this.id。   
![](../Images/91f51525e0801f68772a638f2e06b799.png)  
再看下第二次OGNL解析，start()方法调用了evaluateParams()。 ![](../Images/c9ff6fa125c53bfef13cde5681f08673.png)  
UIBean#evaluateParams()继续调用其populateComponentHtmlId()。 ![](../Images/c2bcc5ff528246b0d3b7795dad46a3f0.png)  
UIBean#populateComponentHtmlId()调用this.findStringIfAltSyntax()方法。 ![](../Images/9baf716ecac869ee67e64c20ca24466f.png)  
AltSyntax设置是默认开启的，所以在Component#findStringIfAltSyntax()会继续调用this.findString(expr);expr=%{8\*8}。 ![](../Images/6cc540cad33d39cd1eb25a4bdecb7fdc.png)  
同样findString()最终会进入OgnlTextParser#evaluate()方法中，evaluator.evaluate(8\*8)得到了64。  
![](../Images/85c203ec83f65d81e94404db72f4c983.png)  
Payload：包含两部分，其构造原理，可参考**S2-059/S2-061 Payload分析**。（https://zhuanlan.zhihu.com/p/351720183）

#### ****\>\>\>\> ******S2-062**

  
影响版本：Struts 2.0.0 - Struts 2.5.29 漏洞原理： 漏洞代码样例：<s:label id="test" name="%{payload}" /> 输入为payload=8\*8时，completeExpressionIfAltSyntax(name)返回的是%{8\*8}，赋值给expr； 而recursion(name)返回为false，从而进入else分支，仍然调用了findValue(expr);
