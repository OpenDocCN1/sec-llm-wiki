（反）序列化最主要的用处就是在传递和保存对象的时候，保证对象的完整性和可传递性。给我们传递对象提供了一种简单的方法。serialize()将一个对象转换成一个字符串，unserialize()将字符串还原为一个对象。

反序列化中的符号：

O   对象a   数组i   代表int，数字s   代表string，字符串d   代表小数或科学计数

example：

<?php  class Test{    public $a = "test";    public $b = 123456;    public $c = 1e2;    public $d = 0.123456;  }  $a = new Test();  $b = Array($a);  echo serialize($b);  ?>   结果：a:1:{  i:0;O:4:"Test":4:{    s:1:"a";s:4:"test";    s:1:"b";i:123456;    s:1:"c";d:100;    s:1:"d";d:0.123456;}

PHP中魔术方法的定义是把以两个下划线__开头的方法称为魔术方法，常见的如下：

__construct:在创建对象时候初始化对象，一般用于对变量赋初值。__destruct:和构造函数相反，当对象所在函数调用完毕后执行。__toString:当对象被当做一个字符串使用时调用。__sleep:序列化对象之前就调用此方法(其返回需要一个数组)__wakeup:反序列化恢复对象之前调用该方法__call:当调用对象中不存在的方法会自动调用该方法。__get:从不可访问的属性中读取数据会触发__isset():在不可访问的属性上调用isset()或empty()触发__unset():在不可访问的属性上使用unset()时触发__invoke():将对象调用为函数时触发更多请查看PHP手册：https://www.php.net/manual/zh/language.oop5.magic.php
example：
<?phpclass Test{  public $a = "test";  public $b = 123456;  public $c = 1e2;  public $d = 0.123456;  private $e = "over";
  public function __construct($str="test"){        $this->a = $str;        echo "__construct!!";    }    public function __get($key){        echo "__get!!!";    }    public function __wakeup(){        echo "__wakeup!!";    }}$a = new Test();$d = new Test($a->$e);$c = serialize($d);unserialize($c);?>
页面显示结果：__construct!!__get!!!__construct!!__wakeup!!
结果分析：1、首先$a创建对象时候初始化对象触发第一个__construct，打印第一个__construct!!。2、$a->$e作为参数传入$d的__construct，可是因为$a->$e是private属性，所以会触发__get，打印get!!!。3、$d创建对象时候初始化对象时候触发__construct，打印第二个_construct!!。4、$c反序列化恢复对象之前触发__wakeup，打印__wakeup!!。

粗略查看源码，分析发现存在三个类Modifier、Show和Test。首先寻找反序列化的关键点，可以看到Modifier类中append函数中的include，文件包含漏洞，我们可以使用伪协议读取flag.php中注释中的内容，这里存在魔术方法__invoke()，当php脚本尝试将对象调用为函数时触发，所以这里需要将Modifier类调用为函数。Modifier类代码如下：
class Modifier {    protected  $var;    public function append($value){        include($value);    }    public function __invoke(){        $this->append($this->var);    }}
继续查看Show类，这有三个魔法方法：__toString() 把类当作字符串使用时触发，调用str属性里的source。__wakeup()使用反序列化函数时触发。过滤了source属性里的一些字符串，过滤了部分伪协议读取，但是还是有未过滤的伪协议可以读取flag.php中的内容（感觉这里的过滤并没有起作用，后面笔者试了一下，发现file协议也能使用，但是不能读取flag.php源码）。而且这里的__construct()方法可以触发__toString() 方法，当$this->source为对象时就能触发。Show类代码如下：
class Show{    public $source;    public $str;    public function __construct($file='index.php'){        $this->source = $file;        echo 'Welcome to '.$this->source."<br>";    }    public function __toString(){        return $this->str->source;    }
    public function __wakeup(){        if(preg_match("/gopher|http|file|ftp|https|dict|\.\./i", $this->source)) {            echo "hacker";            $this->source = "index.php";        }    }}

继续查看Test类，这里有两个魔法方法：不过__construct()在这没用到，__get() 是当从不可访问的属性中读取数据会触发，会返回$function作为函数调用。Test类代码如下：

class Test{    public $p;    public function __construct(){        $this->p = array();    }
    public function __get($key){        $function = $this->p;        return $function();    }}

构造POP链：

至此，流程都处理得差不多了，可以开始构造pop链了。首先反序列化函数，触发Show类中的__construct()方法，__construct()方法做字符串处理，触发__tosring()方法，如果将str实例化为Test类，因为Test类不含source属性，所以触发__get()方法，将$function(也就是Test类中的$this->p)实例化为Modifier类，即可触发其中__invoke()方法，最终调用文件包含函数，读取flag.php。
