【简历攻略】谙熟求职技巧，让你的简历不再石沉大海！So easy

又快到一年招聘季，就业大学生和再就业者四处奔波参加面试的日子又来了！工作好不好找，简历很重要，简历不仅仅是履历，它的重要作用是展示能力！

就拿阿里巴巴来说，在阿里常年招聘中，筛过各式各样的简历，每到招聘季，筛简历和面试过程非常耗精力。当然，想要招到非常优秀的人才，需要花些时间，另一方面，除了那些不合格的简历之外，还有好多简历写的语焉不详，在面试时不得不反复确认，同时为了兼顾应聘者感受，又要很职业得跟他做一些互动，往往这部分会大量筛掉一些人，去糙取精。所以为了提高应聘者的简历（面试）的通过率，一位资深HR在这里列几点建议，告诉大家如何写一份优秀的前端开发工程师简历，当然对于一般的就职者来说，也非常有指导意义！

1

自荐简历一定要署名

招聘季的招聘信息发出去后，HR的邮箱会收到大量简历，邮件标题和附件基本上都是不署名的。简历评估+电面之后，并不会把每个简历都写完整评价录入系统，特别是一些拿不准的简历，想要再次确认再翻出来看，看到这些简历的时候，从邮件列表中看到的往往是这样的：
      此时，早已不记得哪个邮件放的是谁的简历，再挨个儿去翻附件（有的是PDF格式，有的是Word格式，有的是HTML，有的是zip，有的是一个网址，有的干脆把简历粘贴在邮件正文……）去确认当初写的评价，这很耗时，而且效率奇低。即使最后翻到要找的简历，也已经大大减分了。所以，如果发送自荐简历的话，一定要在邮件标题，简历附件文件名上写清楚，你叫什么名字，应聘什么岗位，建议层级（初级、资深、专家）等等，仅此一项就可以大大提高你的简历通过率了！

2

务必要有word 或 pdf 文件的简历

现在大部分人简历直接挂在网上，这种简历HR处理起来很费劲。阿里内部的招聘系统支持 word 和 pdf 格式支持的最好，简历被录入系统时，上传完附件后好多字段直接就被系统读出来了，HTML 格式的简历支持的最差。而且一页 HTML 简历源码能表现的东西实在有限，毕竟阿里这类的大公司现在不招初级（P5及以下）前端了，所以 word 和 pdf 格式的载体足够了，你要多花精力放在简历内容上。

3

简历要表现出亮点，最好有作品

前端技术现在也分化的厉害，不严格划分的话，有 Node.js、H5、Hybrid、架构和业务研发等方向，每个分支的难度、技术基线都类似（比如达到资深所消耗的时间都差不多），所以全栈通才固然好，每个方向都深入有点太强人所难，但至少要在某一个方向非常精钻非常深入。所以简历里要重点标出这个长处。实际上九成的简历里的“技能”部分几乎都是一样的，都是把前端用到的技术罗列一遍，毫无意义的占据简历中的黄金地段。

所以，既然全栈不易，不如把自己最擅长的那个语言或技术高亮加粗出来，面试的时候面试官就直接绕过其他非重点的部分，专从这个“高亮加粗”部分来做一些技术探底了，以此来引导面试官来问你擅长的部分，更有利于你扬长避短。

那么技术探底一般怎么做呢？

看作品！

如果擅长 Node，就看看 NPM 上提交的模块，install 下来演示下，讲讲核心代码。如果是一个组件，就直接看 Demo，讲设计封装思路。如果是一套脚手架工具，直接画架构图，讲原理和适用场景。如果是项目，那就展示下你作为项目经理发布的产品！

作品不仅仅是这些，也可以是技术专利、设计方案、成功的带人案例、成功的团建案例等，只要内容充实接地气，脉略（可以是代码，也可以是一件事）清晰，展示的过程中两眼放光唾沫星子乱飞，有这个感觉就对了。所以，简历里要适当带有这些储备好的作品，等到面试的时候狂秀一下。

4

突出重点，展示能力

现在招一个能干活的人不难，难的是招一个能解决问题的人。特别是像阿里这种业务性的研发，既要从业务方那儿领需求，又要警惕需求陷阱，准确识别出刚性需求，出方案，推执行，发布结果。所以，应对这每个环节所需的技能，最好要在简历里有所表现。

具体说就是描述每个项目时，不仅要有背景、过程，还要有你为这个项目带来的结果。比如这样描述项目：

我做了 XX 项目重构，用了 XX 技术方案，克服了 XX 的困难，最终让 XX 这类需求变更为可以短平快的被消化，极速研发、快速上线、且数据采集也做到了标准化，研发成本大大降低，数据积累增长迅速，比如 XX ，最后在 XX 产品线中开始推广。

在面试时，这种描述很容易引出有针对性的话题来聊，也正因为简历里有这些铺垫，可以节省大量的面聊时间，更快做出判断。


      相比之下，这种描述就不好：

XX 项目前端研发，用了 AngluarJS，整个项目独立完成，包括整个Boss 系统的受理收费、商品零售、小灵通短信群发、有线电视代收费、营业员/营业点结账等模块。 

这段描述只传达出一个信息，就是你用过 AngularJS。至于当初面临多少种技术选型，如何做取舍选择了AngluarJS，这些系统模块之间如何基于AngularJS 进行耦合，有没有涉及前端架构，AngularJS 用的有多深，项目成员分工怎样，如何并行研发？遇到过哪些你认为有价值的问题，并针对此提出应对方案，是代码解决还是组织解决？这个过程要靠面试的时候问答大半天才能搞清楚，问不出来的，基本也就跳过了。要是简历里表达出来，脑子里很嘹喨，面聊也不会很拖沓，能力评价自然会很高。

再补充一个，有好多人有写博客写总结的习惯，这个习惯非常好，如果某个总结能和简历里做的项目结合起来，就更好了。

5

全绿的 Github 提交记录

简历里附上 Github（Github是一个代码托管平台和开发者社区，开发者可以在Github上创建自己的开源项目并与其他开发者协作编码。），最好提交记录那里泛绿的厉害，如果进到 Github 首页就想点开项目列表，找项目去读，如果看到有那种长时间维护的、自述文件写得清楚的、一本正经的写上“转载注明出处”的，基本上抓起电话就开聊了，结果通常不会差。

6

其他关注和不关注

关注：

每次换工作的离职原因，可量化的工作成果，能代表你最高水平的项目要写详细，标红加粗下划线，在简历中强调出来。

不关注：

证书、四六级、了解的编程语言（如果不精通就不要写）、你不擅长什么、个人简介。

7

典型问题

技术探底的问题肯定会问一些，此外面试每个人多会问：

1. 哪个项目让你最满意、代表你的最高水平？如何做的？

2. 让你印象最深刻的一个（技术）难点，害的你搞了很久，最后怎么解的，有什么心得？

3. 你做的时间最久的一个项目（或产品），你看到这个项目有哪些问题，你能做什么？

4. 你能给我们团队或者产品带来什么？

另外附上一些前段开发的知识点，希望会有帮助：

1、DOM结构 —— 两个节点之间可能存在哪些关系以及如何在节点之间任意移动。

2、DOM操作 ——如何添加、移除、移动、复制、创建和查找节点等。

3、事件 —— 如何使用事件，以及IE和标准DOM事件模型之间存在的差别。

4、XMLHttpRequest —— 这是什么、怎样完整地执行一次GET请求、怎样检测错误。

5、严格模式与混杂模式 —— 如何触发这两种模式，区分它们有何意义。

6、盒模型 —— 外边距、内边距和边框之间的关系，及IE8以下版本的浏览器中的盒模型。

7、块级元素与行内元素 —— 怎么用CSS控制它们、以及如何合理的使用它们。

8、浮动元素 ——怎么使用它们、它们有什么问题以及怎么解决这些问题。

9、HTML与XHTML ——二者有什么区别，你觉得应该使用哪一个并说出理由。

10、JSON —— 作用、用途、设计结构。

这些问题不是硬性的，主要看平时是不是除了技术还琢磨点别的，特别是在阿里好多业务单元产品基本形态成型的基础上，要做试错、创新、提效、求精、找方向，这种情况下，只具备（完成刚性需求的）技术能力已经远不够了，而更需要辩证的执行。


展示一份相对完善的简历，有需要参考的尽管拿去！
