# **1.对于之前的文章《[HVV之是蜜罐又不是蜜罐](http://mp.weixin.qq.com/s?__biz=MzU2NDgzOTQzNw==&mid=2247486592&idx=1&sn=353e2fb60b359dcd470c5ca510ca5ec7&chksm=fc4599e2cb3210f4bf7be6f5d757d59c0d2fbfcb7baec2d663f65b43b753c8676622fdbec6bf&scene=21#wechat_redirect)》内容进行延伸。**

**2.和之前的文章一样，通过nginx反向代理到freebuf实现高交互蜜罐，这次也一样，但是这次需要把nginx部署到docker里面，目的是为了和宿主机隔离，就算nginx有漏洞，被打穿了，也不至于影响到宿主机。**

# **3.配置如下，docker只映射80端口出来，docker里面的nginx反向代理到**

# **www.freebuf.com。**

**4.效果如下。**

![](../Images/eb736c75fffe2c6bdd5a8098ccbe16c1.png)

**5.但是我们如何知道有人攻击蜜罐呢？目前采用的架构是Suricata+ELK。**

  

**6.Suricata部署到宿主机,对于机器进行流量采集和规则检测，我这里监听eth0网卡的流量。**

![](../Images/3b93ae4107eeb5875752a7571e61e84d.png)

  

**7.Suricata目前启用的规则是emerging-scan.rules。**

![](../Images/183dabff7c1f23f610adf11d14c84117.png)

![](../Images/d725614bf4d14a3b53bd07c59b3d3a19.png)

  

**8.触发规则之后,产生的攻击告警会写进fast.log。**

![](../Images/7bd0f5bb0adaf8a20b6c794d2fcb7ceb.png)

  

**9.我这里为了方便,使用别人已经打包好Logstash+Elasticsearch+kibana的镜像。**

![](../Images/f2b9c6ce5ac1a05744cf15d1726c1731.png)

  

**10.启动的时候,把宿主机的Suricata日志目录映射到容器内的/mnt/目录。**

![](../Images/19cfffcd1e4b9aeb9728d8559d6bcab5.png)

  

**11.然后配置Logstash,把fast.log产生的告警发送给Elasticsearch进行存储,然后使用kibana进行数据的展示。**

![](../Images/6f9ee85e53ba514a3bfc78ae1be08ff6.png)

**12.然后模拟攻击者对端口进行扫描。**

![](../Images/0d3149537d5e88a0f78dc994a178ba10.png)

  

**13.这样就可以检测到,攻击者对蜜罐进行端口扫描。**

![](../Images/307e56047dfd1abfa88e1aee68805383.png)
