RDP 是勒索软件最流行的攻击媒介，并且近几年一直都是。根据 Unit 42 在2020年针对1000多起数据泄露事件的调研发现，在一半的勒索软件部署中，最初的攻击媒介都是 RDP。关于 RDP 及攻击者如何利用 RDP 实施攻击、使用团伙与防御方法，这篇文章说得比较清楚，希望对你有帮助。

  

RDP，即 Remote Desktop Protocol，也就是远程桌面协议，是微软开发的一种网络通信协议，也是远程控制系统最流行的通信协议之一。它可以用于大多数 Windows 操作系统，通过提供图形用户界面，允许用户远程访问服务器或其他计算机。通过 RDP，远程服务器的显示内容会传输到客户端计算机，远程服务器能够通过客户端的键盘或鼠标等输入设备进行操作。这样一来，不用坐在电脑面前，就能操作电脑。

 

不过，这样一个非常给力的工具，却也被攻击者利用，成为发起攻击的工具。原因在于，通过 RDP 这种远程访问工具作为攻击入口，非常高效。攻击者只需获得正确的凭据，就能访问到企业的网络。而且通常情况下，攻击者不仅是利用 RDP 直接暴露的服务器，在获得访问权限后，还会继续转移到企业其他系统，进入企业的常规网络流量。根据报告指出，被窃取的系统访问凭据会被公布在暗网上进行售卖，利润丰厚。

  

  

**01****RDP 是如何工作的**  

**RDP 是一个双向通信协议，通过这个协议它能实现两种效果**：一是将服务器的屏幕输出传输到客户端；另外则是将键盘和鼠标的输入内容，从客户端传输到服务器，整个过程是非对称的，原因在于大多数的数据都是从服务器到客户端，而客户端返回数据很少。而在建立通信之前，客户端和服务器端必须经历多个阶段：

  

*   客户端开始连接，与服务器就使用设置（如屏幕分辨率）、支持功能与许可证信息达成一致；
    
*   之后就 RDP 安全类型达成一致，然后从标准模式（基于 RC4）与增强模式（RDP 依赖 TLS 或 CredSSP 等其他协议）两种支持的模式中进行选择；
*   最后，就通道数量达成一致。所谓通道即是单独的数据流，每个数据流有自己的 ID，从而构成远程桌面协议。这些通道可重定向对文件系统的访问，或者启用客户端与服务器之间的粘贴板共享。

  

  

**02****谁在利用 RDP**

☞** BlueKeep**

2019年研究人员在上述通道中发现了一个非常关键的漏洞，叫做 BlueKeep。利用该漏洞（CVE-2019-0708）可导致远程执行随机代码，无需用户执行任何操作。最重要的是，它无需有效凭证。这些结合起来，可能导致蠕虫和恶意软件，在有漏洞的系统间进行自我传播。最典型的，就是几年前出现的 Wanncry 恶意软件。BlueKeep 的显著特点是，它可以连接到较老的 Windows 系统，并让微软系统通过奇怪的步骤，为微软不再支持的系统版本制作新的补丁。  

☞** DejaBlue**

2019年8月，研究人员公布了 DejaBlue。不过这不是一个漏洞，而是一系列类似于 BlueKeep 的漏洞，允许攻击者在没有任何形式身份验证的情况下，劫持易受攻击的系统。不过与 BlueKeep 不同的是，DejaBlue 的漏洞位于较新版本的 Windows 中。

  

☞** 无需利用漏洞**

还有一种情况，就是攻击者无需滥用漏洞，只要简单地利用配置错误就能进行攻击，RDP 安全中一些常见的风险包括：

*   弱用户登录凭据；
*   未对 RDP 登录服务器进行记录或监控，此类系统可供攻击者随意尝试暴力攻击或者密码喷洒攻击；
*   未经网络过滤公开暴露的系统。
    

  

☞** 利用 RDP 攻击的 APT 组织**

经常使用 RDP 进行攻击的组织包括：

*   FIN6、FIN7 等组织，利用 RDP 进行横向移动；
*   FLIPSIDE 等组织，利用 RDP 主要进行信息窃取。例如，Ngrok 就是一个合法的反向代理，可以通过对 RDP 中的流量隧道化来窃取受害者数据；
*   WannaCry 恶意软件，能够在现有的远程桌面会话中，执行恶意软件。这种针对会话进行窃取，通常也被称为 RDP 劫持。

  

  
**03****如何更安全地使用 RDP**  

虽然在利用 RDP 的过程中，存在很多安全风险，但 RDP 依旧为我们带来了巨大的便利。我们需要做的，就是通过多方面的考量来保护远程桌面服务器，包括但不限于：

*   **确保系统及时更新。**不必多说，对于关键的远程访问服务尤其重要；
*   **使用 VPN（虚拟专用网络****）**。当 RDP 对在线访问开放时，可能会出现严重的安全问题。利用 VPN，用户可以从外部安全地访问公司网络，不会将系统暴露；
*   **限制通过防火墙访问**。在 Windows 10 上，可以使用 Windows 防火墙限制 RDP 访问特定的 IP 地址或连接到远程桌面连接的多个 IP 地址；
*   **阻止多次失败的登录尝试**。短时间内登录失败次数过多大多属于暴力破解。Windows 中的本地安全策略可以用来确定用户登录 RDP 访问时可以尝试多少次。如果检测到多次失败的登录尝试，一些保护类软件会自动警告管理员；
*   **限制远程访问权限**。虽然默认情况下允许所有管理员帐户使用 RDP，但并不是所有用户的实际工作都需要远程访问。因此，企业应该坚持最低权限原则，限制需要访问 RDP 的员工；
*   **修改 RDP 监听端口**。恶意攻击者通过在互联网上搜索关注 TCP 3389 (标准 RDP 端口)的计算机，找出潜在的受害者。企业可以通过 Windows 注册表更改这个监控端口来“隐藏”易受攻击的连接，但这种方法不能防止 RDP 攻击。因此，它只能作为一项额外的预防措施；
*   **使用 RD 网关**。通过配置 RD 网关服务器，可以简化安全 RDP 提供与安全管理；
*   **使用多层身份验证**。虽然最强的密码也可能被破解，但双因素身份验证（2FA）至少多提供了一层保护，用户必须使用至少两种类型的身份验证（例如，一次性代码或生物特征证明）才能登录到RDP 会话。
*   **强密码管理**。大多数基于 RDP 的攻击都是破解了弱密码。所以企业必须为所有 RDP 客户端和服务器强制执行强密码。这些强密码需要从长度、独特性与随机性进行设置；
*   **通过监控和取证**。无论你的 RDP 设置得多么安全，总会有攻击者抓到机会进行利用。这时需要通过日志记录和监控进行分析当前的情况。通常来说，RDP 取证文件的重要来源包括：➜ 命令 quser、qwinsta 和 qprocess，能够提供有关 RDP 用户、会话和进程的信息；➜ Microsoft-Windows-Terminal-Services-RemoteConnectionManager 和 Windows-TerminalServices-LocalSessionManager，能够展示客户端网络连接以及 RDP会话的起止；➜ Microsoft-Windows-Security-Auditing，包括认证尝试成功或失败的事件。

  

近两年随着远程办工越来越多，具备开放 RDP 端口的服务器不断增加，为企业带去价值的同时，为攻击者 RDP 攻击提供了机会。对于企业而言，只有积极的防御，实施足够的防御措施，才能确保足够的安全。
