*   SQL Server服务端配置加密：该方案跟https 一样在TCP协议上套接TLS 加密传输，这种方式会强制所有的客户端都使用TLS加密，一般安全建设足够到胃的企业都应该启用TLS加密，需要在服务端配置证书，加密后的流量我们只能看到TLS 流量，不会再看到TDS协议交互内容；
*   客户端加密：这种方式就是客户端来决定是否对数据加密传输，只有设置了加密策略的那条流传输的数据才会进行加密，其他没有设置加密的连接都是明文传输，像我们常用的“Navicat工具”，就会通过这种方式来对认证信息进行加密传输，但其他交互都是明文传输。

## **3、日志分析**

##   

## 关于MSSQL的日志分析，bypass师傅的应急文章里面其实也有提到，SSMS工具的使用就不做过多解释，基本有手就行～

##   

*   ## SQL Server日志：SQLServer本身的日志有事物日志和信息日志两种，事物日志是数据库操作相关的记录，我们重点分析信息日志；
    
*   Windows系统事件日志：作为一个Windows开启和管理的服务程序，Windwos系统自带的Application和system日志会对 MSSQL 的启动、关闭、异常、登录等信息进行记录。  
    

**（1）SQLServer 日志分析**SQLServer日志（认证、错误日志）存储路径：C:\\Program Files\\Microsoft SQL Server\\MSSQL13.MSSQLSERVER\\MSSQL\\Log在应急时我们一般只需关注“ERRORLOG”和“log.trc”就够了，前者记录了 SQLServer认证及一些敏感操作触发的相关信息，直接以文本形式或着SSMS 的日志查看器浏览即可，后者记录了详细的认证及报错等关键信息，需要用SQLServer的对象查看工具来打开。Tips：“ERRORLOG\*”在 SQLServer 启动时就会生成，默认只保留7份errorlog文件，按照时间顺序，依次用文件扩名 1,2,3,...,6表示，每重启一次服务，文件扩展名都会加一，最早的那份会被删除，建议上机后第一时间备份这里的日志文件。![](../Images/fa493ccc315742c11bec5e51c4be9917.png)SQL Server默认只记录报错和登录失败记录，强烈建议开启登录成功审计，需要在安全性设置中勾选。![](../Images/fcfaba61c145783eb2d8d8335c001a85.png)在应急过程中，我们通过客户服务器上安装的SSMS工具自带的日志查看器可以更高效的分析errorlog日志，该工具支持查看SQLServer日志、作业历史记录、维护计划、SQL Server 代理等多种日志类型，还支持筛选和导出，功能与系统的事件查看器基本一致。![](../Images/2b6e7531b4dacbd65d2f08a9b13d2146.png)在分析SQLServer日志时，我们一般只需要关注以下几个日志ID就能解决我们的大部分问题了，同时，这些ID也与系统事件日志中的ID保持一致。![](../Images/ec39c0d438eb05eab12f96e7264f6838.png)
