# 系统补丁管理规范

系统补丁管理是为了规范系统补丁的跟踪、分析、测试、安装和检查流程，落实系统补丁安全管理工作，保障系统安全稳定运行，降低由于系统未及时更新补丁所带来的安全隐患。

**▼▼系统补丁定义：**

系统补丁（以下简称“补丁”）是指系统厂商为用于修复其产品缺陷而专门发布的程序包。

**************系统补丁管理原则**************

系统补丁的管理工作应落实以下三个原则：

****▼▼**及时性原则**对于必要的系统补丁的发布和安装流程，必须及时准确，把系统漏洞所造成的潜在威胁降到最低。****▼▼**严密性原则**补丁的测试和分发过程需要制定严密的计划，在保障安全的同时不影响生产和应用系统的正常运行。****▼▼**持续性原则**补丁管理工作是一个长期持续性的工作，信息安全管理人员应时刻跟踪厂商的补丁公告和安全公司的安全公告。

**************补丁跟踪和分析**************

信息安全岗位人员应根据系统的重要等级，有针对性地跟踪系统所需要的补丁和需要采取的措施。

根据IT系统重要程度，对系统补丁跟踪周期定义如下：

*   核心业务系统、重要业务系统、重要基础系统补丁跟踪周期为1个月；
    
*   一般业务系统、一般基础系统补丁跟踪周期为3个月。

信息的来源分为以下三类：

*   软件厂商：软件厂商是补丁的主要来源，每一次安全补丁的发布，一般都会在其网站上发布通告；
    
*   安全机构：官方安全机构会对一些影响特别大的安全事件进行通告；
    
*   安全组织和安全公司：一般会通过其网站发布最新的安全补丁通告，公告的特点是发布快速、内容详细、解决方案全面，并且可知是否已经或者可以被利用。

**************补丁测试和安装**************

各系统管理管理人员应分析系统漏洞等级，根据系统补丁修补时间及修补方式要求进行系统漏洞修补。

系统管理岗位人员应确保从系统厂商的官方途径获取补丁程序，推荐直接从厂商网站上下载，如果补丁支持校验，必须进行安全校验，以验证补丁的可靠性，防止补丁被恶意用户篡改。

******▼▼****系统补丁测试**

补丁测试的过程要考虑测试的广泛性和针对性，应根据实际情况首先考虑在测试环境或准生产环境中进行，没有测试环境或准生产环境的，则先在生产环境的备机进行测试，以便判断该补丁对关键应用的影响。

系统管理岗位人员在完成补丁测试后，应对补丁的测试情况做出总结，编制《系统补丁修复测试报告》，测试报告应详细总结测试过程及结果。

如果在测试中发现问题，要做详细的分析，以判断发生问题的原因，并及时处理。如果暂时无法解决问题，则需记录下发生该问题的环境，并进行重复验证。如果确实是该环境和补丁发生冲突，则立即反馈给厂商，寻求厂商支持。

******▼▼****系统补丁安装**系统管理岗位人员完成补丁测试后，如果未发现问题，则要根据漏洞威胁的紧急程度汇同相关岗位和技术人员，共同制定补丁分发计划，并根据系统变更管理相关要求进行补丁安装。如系统漏洞威胁程度为紧急，可口头进行补丁修补审批，并且在修补补丁时按系统紧急变更管理相关规定执行。在系统安装系统补丁前，系统管理岗位人员应事先做好系统和数据的备份工作，以便在补丁安装失败后可以尽快恢复系统。系统管理岗位人员在完成系统补丁的修补后，应判断系统补丁安装的有效性。

**************补丁疑难解决和检查**************

系统管理岗位人员对于补丁测试过程中出现的问题，应进行总结形成知识库并发布，以帮助公司内部解决同类问题。  

对于因兼容性原因，暂时无法进行补丁升级的，系统管理岗位人员应寻求厂商技术支持。如因特殊原因无法对威胁等级为紧急、严重的漏洞进行修补，系统管理岗位人员应会同信息安全岗位人员及其他信息技术人员制定补偿性控制措施，以防止由于系统漏洞对系统造成的损害。信息安全管理岗位人员在系统补丁修补完成后进行相关检查，及时确认补丁的安装情况。
