什么是审计？ 

审计就是检查、审查、核查，你可以理解为交警平时做的事就是审计。

每年的审车也是审计。

如果你的行为触碰了，审计员，预先规定好，的规则和条律，那么你对应的地方就存在漏洞 和 你在未来使用过程当中，可能存在的风险和威胁。

这就是审计。

闯红灯，因为闯红灯有可能造成交通事故，人员的伤亡 和 交通的堵塞，所以如果你开车闯红灯了，被交警叔叔看到，那么你的行为对于 安全来说，这是就存在风险和威胁的，那么这就是一种漏洞。


交警每天站岗在哪里，就如同你每天去公司在做人工审计。人不是万能的，也有忽略没有及时发现和抓到的违法行为，那么这些行为漏洞也就错过了。


那么监控就可以随时抓拍和掌控 非法/不安全的行为，只要我想要掌握情况，那么我只需要去看一下监控给我的数据就可以了，这就是工具审计。

额外的知识补充和拓展：

往往这些风险和威胁，无论是对使用者（用户），还是创造者（企业）来说，都是足以致命的。

试想一下，你用的手机，电脑在生产出来，没有经过检查和审查环节，你有没有可能会被炸死啊？


但是我们这里说的是代码审计，和开发相关，往往这些漏洞，会泄露用户的敏感信息，会被信息贩子低价贩卖，给他们实施诈骗，和其他的违法行为，提供便利，甚至用户会收到各种骚扰，多的也不说了，最直接的一点，由于用户的密码习惯，几乎多张银行卡，和社交账号的密码，70%的人都是一样的。如果你的密码被别人窃取，你可以试想一下会发生那些情况。


那么对于企业和APP和各种网站来说，威胁更为巨大，今天我们就先入门，后面再慢慢深入讨论





代码审计是什么？正式版



通过审计应用程序的源码来发现潜在的漏洞和安全隐患，

同时可以覆盖黑盒测试中忽略/未能完成的点，是一种比较可靠且安全的挖掘漏洞的方法。

通常可以对类似ASP、.NET、PHP、JAVA等编程语言进行审计。



可以控制的变量，一切输入都是有害的，


变量达到又利用价值的函数【危险函数】，一切函数的变量都是有害的。

代码是一个二傻子，人们叫他做什么他们就会做什么，如果我们发现，他在执行一些操作的时候，有可能存在漏洞，那么我就可以去下达，去执行一些别命令，比如，把你主人家的密码告诉我是多少等等等。


再比如：一场宴会只允许穿蓝色衣服的人进场。

那么我是不是，只需要披上蓝色的衣服就可以进场了呢？

但是并没有限制，是男人还是女人，是好人还是坏人，是中国人还是外国人，是大人还是小孩，是少数名族还是汉族，是四肢健全还是有所残缺。

这就是典型的校验机制不完整，存在缺陷。

就因为我穿蓝色的衣服，你就信任我，我就进去了，我要是一个劫匪，整场宴会包括主人都会收到我的威胁和伤害。

参加宴会的普通用户，被我拿到账号密码个人家庭住址敏感信息都是小事。

关键的事，我可以通过宴会的晋升机制，再满足条件之后，摇身一变成为这场宴会的第二个主人。


所以，一款产品，尤其是网络产品，拼夕夕、某宝、某猫，在上线之前，为了避免以上所述的威胁，代码审计就显得格外的重要了。

又因为，PHP至今流行，JAVA框架好用，所以，才有了PHP 审计，JAVA审计的岗位和职责。

          1、数据流追踪法         2、敏感参数回溯法


          3、定向功能审计法      4、通读全文跟踪法



1、数据流追踪法 




2、敏感参数回溯法

                    优点：耗费时间短、定向审计、精准打击

                    缺点：对全程序把控程度把控低、积累经验较少

                大多数漏洞的产生是因为函数的使用不当导致的。

      我们只要找到这样的一些使用不当的函数，就可以快速挖掘想要的漏洞。

Seay法师源代码审计系统，

        主要是利用正则匹配一些高危函数、关键函数以及敏感关键字。

                然后，我们就可以分析判断敏感函数的上下文，追踪参数源头。

                       尝试控制可控的参数变量。





 3、定向功能审计法


登录、注册、留言、查询、上传、更新、充值、密码修改、重置….

                   定向功能分析法主要是根据程序的业务逻辑来说审计的。
                   首先是用浏览器逐个访问浏览，看看这套程序有那些功能。
                    根据相关功能，大概推测可能存在那些漏洞。
                    找到具体的功能模块，主要审计此模块。






4、通读全文跟踪法

优点：

            有利于代码审计的经验积累

            能更深入的挖掘一些难以发现的漏洞、

            对全程序的把控程度较高、覆盖逻辑漏洞


缺点：

            时间耗费太长 太长----长，投入≠产出





个人推荐：优先使用敏感参数回溯法和定向功能审计法

                 敏感参数回溯法配上一个审计工具，你的工作就可以顺利开展了

                 工具RIPS：https://sourceforge.net/projects/rips-scanner/

                 工具Seay：https://github.com/f1tz/cnseay

                如果时间比较多，且不着急或者工作中大型项目：用全文通读法






通用流程 

1-了解目录结构和相关函数的作用


了解文件目录后，就从index.php文件入手

    Index.php 一般是整个程序的入口，

        通过index文件可以知道程序的架构、运行流程、包含那些配置文件包含那些过滤文件以及包含那些安全过滤文件，了解程序的业务逻辑。

入口又分为：

                单入口居多（用MVC框架写的）

                多入口

       其次，从入口文件找到包含的全局文件，常见的全局文件包括全局功能，全局变量，或者是一些类等等...

比如某些cms会写一个形如global.func.php的文件，里面存放的是全局函数。


而全局函数通常可以分为以下几类：

    参数过滤函数、文件操作函数、字符转换函数、异常处理函数


配置文件：

        类似config、conf的文件，通常保存一些关于数据库的信息。


过滤功能文件：

    通过详读 公共函数文件 和 安全过滤文件 等。

    可以清晰的掌握用户输入的数据，那些被过滤，那些没有过滤，从哪里开始过滤，通过什么方法过滤，

      我们能否绕过过滤。过滤的方法时替换还是正则？

      有没有GPC处理？

      有没有用函数处理（addslasher()、htmlspecialchars()）

判断是否使用框架:TP5

PHP.ini配置文件对审计的影响：

1、Register Globals = Off  默认值预设为 Off（下面写的都是基本默认的）设定为 On 时，程序可以接收来自服务器的各种环境变量，包括表单提交的变量,容易产生变量覆盖（视情况，但是全局变量关掉会很麻烦）2、display_errors = On 错误等级决定是否可能泄露绝对路径（视情况，错误全关影响调试） E_ALL 最高级别，展示所有错误信息，审计时最好打开，网站上线时关闭3、short_open_tag = On 默认可用短标签 短标签有可能可以帮助我们渗透时免查、免杀；这个设置可以将<?php?>缩写为<??>;<?echo缩写为<?= 4、safe_mode = Off 默认关闭  安全模式，PHP 用来限制文档的存取、限制环境变量的存取，限制system()等函数执行 以及敏感文件的读取5、safe_mode_exec_dir = /var/www/html  这个目录下才可以执行（高版本PHP已废弃）6、disable_classes =      disable_functions = opendir,readdir,scandir,fopen,unlink   禁用某些类、函数 在php.ini设置7、file_uploads = on upload_max_filesize = 8M 设置上传及最大上传文件大小 8、upload_tmp_dir = 文件上传临时目录 Linux是/tmp windows是C:\Windows\Temp9、open_basedir = .:/tmp/  用户访问目录限制  默认不配置是空的 一般都是只能访问网站目录  此配置可有效防止PHP木马跨站运行；Linux使用:分隔    windows使用;分隔
10、magic quotes  魔术引号（宽字节注入大家不会陌生）   magic_quotes_gpc = On   5.4.0移除   虽然移除，但是这个功能很可能被开发者自定义使用11、open_base_dir 禁止使用目录以外的文件操作，有效的消除文件包含12、expose_php  设为 Off ,这样 php 不会在 http 文件头中泄露信息13、allow_url_fopen = On  一直都是开启的  可以远程打开url文件，但是这个选项不是执行远程文件的14、allow_url_include = Off 是否允许远程文件包含（PHP5.2以后默认关闭此功能）允许include、include_once等文件包含函数执行远程文件，所以这个选项比较重要，如果打开远程包含一句话木马就比较可怕了；关于远程文件包含推荐先知社区的伪协议文件包含文章
15、log_errors = On  记录错误日志得就带上吧 其他：16、session.cookie_httponly = ON 时，客户端脚本(JavaScript等)无法访问该 cookie，打开该指令可以有效预防通过 XSS 攻击劫持会话ID17、session.cookie_domain 是否只包含本域，如果是父域，则其他子域能够获取本域的cookies18、如果使用 HTTPS，那么应该设置 session.cookie_secure=ON，确保使用 HTTPS 来传输 cookies
