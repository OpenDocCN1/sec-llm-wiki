2、区域&区域传输

1. 什么是DNS区域

DNS服务器托管区域。DNS区域是DNS服务器提供的域名空间的一部分。例如，example.com及其所有子域(*.example.com)都可以是一个区域。

2. 什么是区域传输

DNS是一项关键服务。如果某个区域的DNS服务器无法正常工作，并且缓存的信息已过期，则所有服务（Web，邮件等）都无法访问该域。因此，每个区域至少应具有两个DNS服务器。对于更关键的区域，可能会有更多。

区域可能很大，可能需要频繁更改。如果您分别在每个服务器上手动编辑区域数据，这将花费大量时间，并且很可能会出现错误。这就是为什么需要DNS区域传输的原因。

您可以对DNS区域传输使用不同的机制，但最简单的机制是AXFR（从技术上讲，AXFR是指DNS区域传输期间使用的协议）。这是客户端发起的请求。因此，您可以在主DNS服务器上编辑信息，然后使用辅助DNS服务器中的AXFR下载整个区域。

3. AXFR

Authoritative Transfer的缩写，是DNS服务器之间用来传送域内完整数据库的协议。

具体可见RFC5936

https://tools.ietf.org/html/rfc5936


3、DNS区域传输漏洞修复

AXFR不提供身份验证，因此任何客户端都可以向DNS服务器请求整个区域的副本。这意味着，除非采用某种保护措施，否则攻击者可以获得一个域的所有主机的列表。

最简单的办法就是给AXFR加白名单。

#vi /etc/named.conf acl trusted-nameservers {192.168.0.10; //ns2 192.168.1.20; //ns3 }; zone zonetransfer.me { type master; file "zones/zonetransfer.me"; allow-transfer { trusted-nameservers; };};

4、工作中常见域名解析相关名词释义

作为一个安全行业的PPT从业人员，在我的日常工作中只有和SRE（Site Reliability Engineer）打交道的时候会用上DNS的一些基本概念。

我把我碰见过的写在下面，给各位同样是PPT从业人员做个参考。

1.泛解析

是指利用 “ * ” 来做子域名，实现所有的子域名都指向同一个IP地址（记录值）。例如域名 dns-example.com，设置泛解析 *.dns-example.com ，则该域名下所有的子域名（如 a.dns-example.com，b.dns-example.com，c.dns-example.com等）都将指向与 *.dns-example.com 相同的IP地址。

2.CNAME

Canonical Name，别名，比如aa.bj.example.com指向www.example.com，是主站的别名，一般CDN用来让用户找到离自己最近的解析。

3.TLD

TLD 的全称是 Top Level Domain，顶级域名，它是一个因特网域名的最后部分，也就是任何域名的最后一个点后面的字母组成的部分，比如.com, .net

4.NS

Name Server，本区域的“名称服务器”，负责本地域内主机的 DNS 解析。例如:

$dig +short ns 163.comns1.nease.net.ns5.nease.net.ns8.166.com.ns4.nease.net.ns2.166.com.ns3.nease.net.ns6.nease.net.


这些NS服务器可以解析针对*.163.com的解析请求。


5.A记录

A (Address) 记录是用来指定主机名（或域名）对应的IP地址记录，比如：

email.zonetransfer.me.  7200  IN  A  74.125.206.26
