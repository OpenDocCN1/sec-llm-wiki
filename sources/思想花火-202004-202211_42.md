前两天收到合作方反馈过来的一个小漏洞：HOST头攻击。

大致意思就是在HTTP request里将HOST字段里我们的域名改成了baidu.com，然后我们的Nginx给重定向到百度首页了。

  

![](../Images/15363337ae309072053943293fee31fc.png)

  

收到漏洞报告后，我仔细看了两遍这种骚操作，左想右想，觉得也没啥呀，如果在HOST里夹带恶意代码并且运行了才算高危啊，在全链路https的环境下篡改HOST搞一个重定向钓鱼到底有啥用？  

  

自己不是很确信，就拿这个问题去请教我们天天挖洞的哥哥们。小哥哥第一感觉和我一样，这个洞没啥用。接着又说：*既然HOST改成了baidu.com，那这个response应该是百度的Nginx返回的啊，和我们没关系。*  

  

我沉默了一下，然后说，*这个response肯定我们的Nginx返回的啊，他只是篡改了HTTP HEADER啊。*

  

小哥哥沉默了三秒钟，马上就认同了我的说法。于是，我们尝试对这个问题进行复现，可惜又幸运的是复现不成功。

  

这个事情运用了两个知识点，有时候是技术面试的时候会问到的。  

1.  在浏览器地址栏输入了网址打开网页的网络协议工作过程
    
2.  HOST头攻击的预防  
    

  

**1、浏览器打开网页的网络协议工作过程**  

1.  域名解析，浏览器获得网站IP地址  
    
2.  TCP三次握手，建立连接  
    
3.  发送HTTP请求  
    
4.  接受服务端响应和网页内容
    
5.  TCP四次握手断开连接  
    

这个时候就看出来了，篡改HOST根本不会影响HTTP请求数据包的路由。

  

**2、HOST头攻击的预防**  

预防措施当然是在HTTP服务上增加HOST校验了。  

Nginx的配置  

修改nginx.conf，重启Nginx服务

*   
*   
*   
*   
*   
*   
*   
*   

```
// server_name就是你的域名，当HOST校验失败时，返回403错误。server {       listen 8888 default;       server_name _;       location / {            return 403;       }       }
```

其他HTTP服务的配置也都差不多。
