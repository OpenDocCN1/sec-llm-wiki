1.中信银行因13项违规被罚2223.6677万元，信息安全引重视

银保监会官网8月9日发布一项行政处罚信息公开表，中信银行(行情601998,诊股)因13项违法违规事实被没收违法所得33.6677万元，罚款2190万元，合计2223.6677万元。13项违规项中，其中有三项是关于信息系统安全存在重大漏洞，且曾发生过重要信息系统运营中断事件。

截图来自中国银行保险监督管理委员会-行政处罚页面

以下为13项违法违规事实：

违规违法事实

1.未按规定提供报表且逾期未改正；

2. 错报、漏报银行业监管统计资料；
3. 未向监管部门报告重要信息系统运营中断事件；
4. 信息系统控制存在较大安全漏洞，未做到有效的安全控制；
5. 未按企业划型标准将多家企业划分为小微型企业，报送监管数据不真实；
6. 向关系人发放信用贷款、向关系人发放担保贷款的条件优于其他借款人同类贷款条件；
7. 重大关联交易未按规定审查审批且未向监管部门报告；
8. 贷后管理不到位导致贷款资金被挪用；
9. 以流动资金贷款名义发放房地产开发贷款；
10. 未将房地产企业贷款计入房地产开发贷款科目；
11. 投资同一家银行机构同期非保本理财产品采用风险权重不一致；
12. 购买非保本理财产品签订可提前赎回协议，未准确计量风险加权资产；
13. 未按规定计提资产支持证券业务的风险加权资产。

行政处罚依据：《银行业监管统计管理暂行办法》（中国银监会令 2004年第6号）第八条、第三十六条，《流动资金贷款管理暂行办法》（中国银行(行情601988,诊股)会令 2010年第1号）第九条、第三十九条，《商业银行与内部人和股东关联交易管理办法》（中国银监会令 2004年第3号）第二十二条、第二十五条、第四十二条、第四十四条，《商业银行资本管理办法（试行）》（中国银监会令2012年第1号）第一百七十八条、附件9第二条，《中华人民共和国商业银行法》第四十条、第七十四条，《中华人民共和国银行业监督管理法》第二十一条、第四十六条、第四十七条的规定和相关内控管理和业务审慎经营规则。

HTTP/2 拒绝服务攻击漏洞预警 

2019年08月13日晚,Netflix 安全团队联合Google，CERT / CC向互联网披露了 HTTP/2 协议在被各个中间件服务实现过程中出现的 DDoS(分布式-拒绝服务攻击)漏洞的问题。

HTTP/2(在RFCs 7540和7541中定义)代表了与HTTP/1.1的区别以及产生的重大变化。有几种新的功能，包括报头压缩和来自多个流的数据的多路复用，这使得它对用户群体具有吸引力。我们发现的许多攻击向量(今天已经修复)都是一个关键点的变体:一个恶意客户端要求服务器做一些产生响应的行为，但是客户端拒绝读取响应。这将考验服务器的队列管理代码。根据服务器处理队列的方式，客户端可以在处理请求时强制它消耗多余的内存和CPU。Nginx 已确认受到影响并已针对此次漏洞情况发布更新nginx security advisories其他的中间件服务尚无明确的响应和修复。

英特尔更新NUC固件以修补高危漏洞

近日英特尔发布了针对多个NUC套件型号的固件更新，以修补可能被利用得到权限提升，导致拒绝服务（DoS）条件或信息泄露的高危漏洞。

NUC套件不是英特尔要求此更新的唯一小型计算机。计算卡和计算在BIOS运行，同样受到错误的影响。

跟踪为CVE-2019-11140，该漏洞的严重性得分为7.5分（满分10分），这是由于验证不充分。

如果攻击者具有特权用户权限的本地访问权限，则可以进行利用; 不过，对于技术能力强的攻击者来说，并不是一件非常难实现的事情。

受CVE-2019-11140影响的英特尔产品的完整列表包括以下型号：

Intel NUC套件NUC7i7DNx 

Intel NUC套件NUC7i5DNx 

Intel NUC套件NUC7i3DNx 

Intel Compute Stick STK2MV64CC 

Intel计算卡CD1IV128MK

该公司今天修复的另一个高风险漏洞是Windows的Processor Identification Utility，用于检索已安装CPU的规格。它可以显示有关图形，芯片组和处理器支持的技术的详细信息。

该错误标识为CVE-2019-11163，严重性评分为8.2。尽管稍微严重一些，但本地访问对于利用是必要的，其效果与利用NUC BIOS中的错误相同。根据该因特尔公告说明，漏洞利用点来自“硬件抽象驱动程序中的访问控制不足”，并且它存在于6.1.0731之前的软件版本中。

英特尔基于Web的RAID管理软件中发现了一个信息泄露漏洞。计算出的严重性为中等（6.8），但未经身份验证的攻击者可以在网络上利用它。

名为KNOB蓝牙漏洞允许攻击者操纵蓝牙连接

目前已经公开了一种名为“KNOB”的新蓝牙漏洞，其允许攻击者更容易强制使用配对期间的加密密钥来监视或操纵在两个配对设备之间传输的数据。

ICASI成员（如微软，苹果，英特尔，思科和亚马逊）披露，一项名为“KNOB”的新漏洞已被披露，影响蓝牙BR / EDR设备，也称为Bluetooth Classic，使用规范版本1.0 - 5.1。

此漏洞已经标记为CVE ID CVE-2019-9506，并允许攻击者减少用于建立连接的加密密钥的长度。在某些情况下，攻击者可以将加密密钥的长度减少到单个八位字节。

“研究人员发现，这个漏洞在进行漏洞攻击时，攻击设备与用于设置加密的BR / EDR两个装置之间是一样的，从而减少所使用的加密密钥的长度连接上的程序干扰”。“此外，由于并非所有蓝牙规范都要求最小加密密钥长度，因此某些供应商可能已开发出蓝牙产品，其中BR / EDR连接上使用的加密密钥的长度可由攻击设备设置为一个八位字节。“

密钥长度的减少将使攻击者更容易暴力破解配对设备使用的加密密钥以相互通信。

一旦攻击者知道密钥，他们就可以监视和操纵设备之间发送的数据。这包括潜在的注入命令，监视击键和其他类型的行为。

ICASI不知道恶意使用此攻击或正在创建任何设备来发起此类攻击。

这个漏洞是由新加坡SUTD的Daniele Antonioli，德国CISPA的Nils Ole Tippenhauer博士和英国牛津大学的Kasper Rasmussen教授发现的，他们将在USINEX安全研讨会上展示这项研究。他们还将于2019年8月14日发布一篇题为“ KNOB破碎：在蓝牙BR / EDR的加密密钥协商中利用 ”的论文。利用此漏洞并非易事，因为它需要具备特定条件。

这包括：

  • 两种设备都需要蓝牙BR / EDR。

  • 攻击者在建立连接时需要在设备的范围内。

“攻击设备需要拦截，操纵和重新传输两个设备之间的密钥长度协商消息，同时还阻止来自两者的传输，所有这些都在一个狭窄的时间窗口内完成。”

缩短加密密钥，然后强制破解解密密钥。每次设备配对时，攻击者都需要重复此攻击。要解决此漏洞，需更新蓝牙规范，以建议BR / EDR连接的最小加密密钥长度为7个八位字节

微软今天发布了一个名为“ CVE-2019-9506 |蓝牙漏洞的加密密钥协商 ”的更新，它将通过强制实施“默认的7个字节的最小密钥长度来确保密钥协商不会使加密变得无足轻重 ”来缓解此漏洞。

安全漏洞导致Suprema Biostar2 百万指纹数据曝光

据悉，研究人员在Suprema的系统中发现了一个安全漏洞，使之能够访问超过100万人的身份验证数据。英国《卫报》指出，这些数据包括了指纹/面部识别数据、未加密的用户名和密码、甚至员工的个人信息。

以色列研究人员Noam Rotem、Ran Locar与vpnmentor一起寻找到了Suprema的安全漏洞，并且获得了Biostar 2数据库的访问权限。在获得访问权限后，安全研究人员发现该数据库缺乏应有的保护，且大多数据处于未加密的存储状态，很容易访问到总量超过2780万条（23GB+）的记录。

除了敏感信息，安全研究人员还能够轻松监控存储的生物识别数据的实际使用情况。比如实时查看哪个用户通过特定的安全门进入任何设施，甚至查看到管理员账户的密码。

金融服务机构和客户的头号威胁：94%的攻击都来源于此

       94％观察到的金融服务攻击来自四种方法之一：SQL注入（SQLi），本地文件包含（LFI），跨站点脚本执行（XSS）和OGNL Java注入。Akamai 2019年互联网安全金融服务攻击经济报告的数据显示，在所有受到网络钓鱼区域影响的机构中，有50％都来自金融服务行业。

       此外，数据显示，在18个月内，攻击者发起了高达35亿次攻击尝试，不仅利用网络钓鱼，还利用了凭证填充攻击，这使金融服务客户的个人数据和银行信息面临风险。
