> **5G安全漏洞允许MiTM，有针对性的攻击**

> 拉斯维加斯 - 5G商用网络正在开始推出，有一些激动人心的实例展出，如自动化汽车和节点具有10年电池寿命的智能传感器网络。值得注意的是，设备身份验证，流量加密，设备ID和凭据的隐私保护以及弹性和完整性的也有很大的改进。
> 
> 5G的许多安全协议和算法都是从之前的4G标准中移植出来的，研究人员发现它仍可以允许设备指纹识别用于目标攻击以及中间人（MiTM）攻击的可能性。5G网络架构由基站（宏或小小区，取决于应用）组成，其与4G小区塔一样覆盖特定区域。这些基站连接到移动边缘云，移动边缘云又连接到核心网络。为了连接到运营商网络，5G设备向基站发送大量信息，基站将其传递到链路上，以便最终注册和认证到核心网络。
> 
> ![](../Images/b2bdc16b58a4d3b15346e44117f3d4a9.png)
> 
> 设备内部的组件根据设备的用途提供不同的功能，据柏林技术大学和Kaitiaki实验室的研究生Altaf Shaik说，这些信息会被发送到基站。它包括诸如是否启用语音呼叫，SMS能力，车辆到车辆通信（V2V）支持，正在使用的频段，设备类别（其中有20个，对应于设备的处理能力）之类的内容和无线电要求，例如设备是否需要无线电接入网络（RAN）来使用MIMO来提高吞吐速度。
> 
> 在Black Hat 2019召开的名为“ 5G网络中的新漏洞”的会议上，与合作伙伴，SINTEF Digital的Ravishankar Borgaonkar进行了研究，Shaik指出，在5G中，与4G一样，设备功能信息被发送到基地在将任何安全性分层到连接之前的站。无线安全性包括从端点到基站的流量加密; 但由于设备功能在开始之前传输，因此它们以纯文本形式显示。根据Shaik的说法，这可以实现三种攻击：移动网络映射（MNmap）、投标，和窄带物联网（NB IoT）设备上的电池消耗。
> 
> “这是一个问题，一个从4G移植的根本问题，”Shaik说。“但是在5G中，有更多的用例和更多功能可以确切地定义它是什么类型的设备，使得定位变得更加容易。”
>

> **KDE LINUX桌面可能会在没有打开**
> 
> **恶意软件的情况下被黑客攻击**
> 
> 如果您在Linux操作系统上运行KDE桌面环境，则需要格外小心，避免下载任何“.desktop”或“.directory”文件一段时间。
> 
> 一名网络安全研究人员在KDE软件框架中披露了一个未修补的零日漏洞，该漏洞可能允许恶意制作的.desktop和.directory文件在用户的计算机上静默运行任意代码，甚至不需要受害者实际打开它。
> 
> ![](../Images/9670e4759c7eeaccf77fe6c3ba758012.png)
> 
> KDE Plasma是Linux用户最流行的基于窗口小部件的桌面环境之一，是许多Linux发行版的默认桌面环境，如Manjaro，openSUSE，Kubuntu和PCLinuxOS。

> **微软将于8月13日默认禁用VBScript**
> 
> 在8月13日的下一个微软补丁周二，微软将在Internet Explorer for Windows 7,8和8.1中默认禁用VBScript。这是微软从2017年开始最终在Internet Explorer中禁用VBScript的计划的一部分。
> 
> 2017年，微软宣布他们将在Internet Explorer中禁用VBScript以获得更安全的体验。这样做是为了防止脚本语言被滥用来下载恶意软件或执行其他不需要的行为。
> 
> “在随后的Windows版本和未来的更新中，我们打算在Internet Explorer 11中为Internet区域和受限制的站点区域中的网站默认禁用VBScript执行。启用，禁用或提示在Internet Explorer 11中执行VBScript的设置将通过注册表或通过组策略在每个站点安全区域保持可配置的时间有限。我们将在此处发布未来的更新，以便在Internet Explorer 11中更改VBScript执行的默认设置。”
> 
> 随着即将推出的更新，旧的操作系统现在正在轮流禁用它。
> 
> 这并不意味着VBScript完全消失。仍然需要它的组织可以通过注册表或组策略再次启用它。
> 
> 但最终，预计微软最终会杀掉VBScript而不是保留一种脚本语言，从而打开太多安全漏洞。
>

> **应用在第三方持续集成和部署GitHub Action即将上线**
> 
> 微软社交代码商GitHub周四表示，其自动化系统GitHub Actions将通过第三方持续集成和持续部署工具发挥出色，这两种工具在其IT阶段以 CI/CD为人所知。
> 
> 将于今年10月份出现在测试版中，预计今年11月13日全面上市。它对公共GitHub存储库是免费的，但它可能会受到加密以及GitHub的服务条款和社区准则下规定的其他不良行为的限制。
> 
> ![](../Images/15d9df401e818c4dddc90ba3794f6fab.png)
> 
> GitHub Actions和CI/CD都是自动执行软件开发任务的方法。正如所料，Acions擅长与GitHub交互， CI / CD是独立工具，如Jenkins和Travis，既没有受到追捧，也没有内置支持特定于平台的事件。GitHub宣布，Actions现在对这些外部工具以及自定义脚本和安装提供了更广泛的支持，并将其与GitHub服务紧密集成。
> 
> “GitHub Actions可以插入软件生命周期的任何部分，并与开发人员今天使用的许多CI / CD工具集成，”GitHub产品设计高级主管Max Schoening在给The Register的电子邮件中说。“它支持任何语言，任何平台和任何云。”
> 
> “GitHub Actions可以构建，测试和部署应用程序，也可以使用它来自动执行开发人员工作流程中常见的其他任务：分类和管理问题，自动发布版本，与您的用户群进行协作等等，”GitHub首席执行官说。Nat Friedman在一篇博文中。“可以在GitHub上的开发人员生命周期中的事件上触发动作工作流程。”
> 
> 我们可以看到的是，与CI / CD相比，Actions可以实现更广泛的自动化任务，CI / CD通常用于自动执行代码编译，验证，测试，构建和部署。操作在YAML（.yml）文件中声明（不推荐使用 HCL语法），并且可以与GitHub API或其他公共API端点进行交互。
> 
> 工作流中的项目在GitHub托管的虚拟机或Docker容器中执行，工作流中的每个作业都可以在自己的虚拟环境中隔离，这使得调试比尝试识别CI / CD中的问题更简单在单个环境中执行所有操作的脚本。
> 
> 动作仍然有一些粗糙的地方，比如对缓存的有限支持（这有助于加快CI / CD任务），缺乏对来自分叉的拉取请求的支持，以及潜在的安全问题。但是，在GitHub的客户中，并没有太多的抱怨。
> 
> 例如：飞利浦的高级软件工程师Jeroen Knoops说：“GitHub Actions使团队能够定义高度先进的管道而不会失去对简单性的关注。” “它将管道的强大功能作为代码，矩阵构建和预定义环境集中在一个地方.GitHub Actions可以通过可重复使用的步骤构建和共享工作流，并提供构建下一代CI / CD管道所需的功能。”
> 
> 那些没有预先选择说好话的人对GitHub对CI / CD市场的兴趣听起来更加警惕。正如CI / CD供应商CircleCI的首席执行官吉姆·罗斯（Jim Rose）将其发送给通过电子邮件发送给The Register的声明，“GitHub已承诺将\[其\]平台保持向所有合作伙伴开放，但时间会证明使用的体验。
> 
> 目前已有4000万开发人员使用GitHub，这种规模产生的重力限制了较小竞争对手的移动。
> 
> 虽然Actions仍然处于测试阶段，但也意味着潜在的用户必须请求入场 - 还有一个额外的动机要求：获得该服务的beta访问权限的人也可以获得一张通过GitHub Package Registry的门票。
