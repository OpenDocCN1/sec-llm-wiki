链接劫持 | 如何利用过期的链接


 内容主要是分享赏金猎人的一些经验


每次目标链接到过期的域或页面时，就会存在过期的链接劫持（BLH）。过期链接劫持有两种形式，反射形式和存储形式。这个问题已经被无数次利用，但是令人惊讶的是，很少有研究人员在漏洞赏金计划中寻找过期的链接。



这篇文章为你提供有关目标链接到过期时间点时可能出现的各种问题的基本概述。

存储的链接劫持

当公司删除其社交媒体帐户时，他们可能会忘记从网站中删除链接。攻击者可以使用该用户名在社交媒体平台上创建帐户，并假冒公司。

外部JS文件劫持

如果目标具有外部JS文件，并且该域/页面已过期，则可以声明它，然后基本上已经有了存储XSS。

假设example.edu在example.com上托管了一个外部JS文件，而example.com已过期。

<!DOCTYPE html><html><head>  <meta charset="utf-8">  <meta name="viewport" content="width=device-width">  <title>Broken Link Hijacking</title></head><body>  <script src="//example.com/script.js"></script></body></html>
现在可以接管example.com，并可以控制example.edu上的JS文件。

信息泄漏

劫持缺少rel="noopener noreferrer"属性的链接可能会将信息泄漏到攻击者控制的页面。[1]

此外，有可能公司链接到过期的分析页面。如果攻击者可以劫持该过期页面，则他们可以监视流量并可能收集有关目标用户具有价值的信息。有人曾经在Gratipay的程序中找到其中一个：
https ://hackerone.com/reports/111078 。

内容劫持

攻击者可以通过接管过期的域/页面来劫持页面的内容。一个很好的例子可以在@ MisterCh0c的博客文章看到“我如何劫持Katy Perry，Shakira在内的顶级名人推文……”。


断开的链接劫持

你以为自己，已经反射了XSS，但是无法突破href或src属性时知道这种感觉吗？
如果链接是CDN或文件托管服务，则可以构造一个恶意链接并将该文件托管在服务上。这些都是非常少见的，但是绝对要记住，以防将来你遇到此问题。

示例场景

http://example.edu/?version=1.0.0返回cdn.example上托管的JS文件的特定版本。

<!-- http://example.edu/?version=1.0.0 --><!DOCTYPE html><html><head>  <meta charset="utf-8">  <meta name="viewport" content="width=device-width">  <title>Broken Link Hijacking</title></head><body>  <script src="//cdn.example/1.0.0/script.js"></script></body></html>
cdn.example允许我们添加项目并托管恶意JS文件。
<!-- http://example.edu/?link=maliciouspath --><!DOCTYPE html><html><head>  <meta charset="utf-8">  <meta name="viewport" content="width=device-width">  <title>Broken Link Hijacking</title></head><body>  <script src="//cdn.example/maliciouspath/script.js"></script></body></html>

工具类

过期链接检查器

过期链接检查器将爬网目标并查找过期的链接。每当我使用此工具时，我都喜欢运行：
$ blc -rof --filter-level 3 https://example.com/
过一段时间后，我经常发现自己将其调整为类似这样的形式，以防止误报：
$ blc -rfoi --exclude linkedin.com --exclude youtube.com --filter-level 3 https://example.com/

链接：https：//github.com/stevenvachon/broken-link-checker
