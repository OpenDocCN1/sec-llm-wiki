迫于...迫于师兄的鸡腿的诱惑，有了这篇简单的关于 StreamDump 这个小工具的简单介绍！

这是在小组里使用的一个小工具，根据 TCP 流的四元组来将每个 TCP 重新组装还原，并分别保存成一个单独的 pcap 文件。是不是很简单？是的，但是就是这么简单的东西，目前还没有发现有比较现成的工具来实现。为了运行效率和编译方便，程序使用 Golang 来实现。

程序的几个特点：

  1. 支持 BPF 过滤规则，可根据需求来进行自定义过滤

  2. 支持捕获双向数据流，保存的文件根据四元组来进行命名：IP[Port]-IP[Port].pcap，在保存双向数据流的情况下，以捕获到的第一个 packet 中的四元组参数进行命名

  3. 不仅支持从网卡中实时捕获流量，还支持从 pcap 文件中读取分析，过滤出自己需要的单个的流文件

功能虽然不多，但是却可以做很多的事情！即使用 Python 来重新写一个脚本并不难，但是，为什么要再重新造轮子呢？！！特别当需要解析一个 10GiB、20GiB 或者更大的 pcap 文件的时候，使用 Python 来解析相对而言效率是十分低下的！

分拆出来的 TCP 流有什么用？如果你需要对某个特定的流，或者某组特定的流进行分析，我想这个工具对你一定十分有用，会让你节省很多时间！


废话少说，下面简单说说如何使用这个小工具：

编译

编译就十分轻松了，go 自带了编译工具，只需要将包里的依赖取回本地，直接编译就可以了

>go get github.com/google/gopacket
>go build -o streamdump streamdump.go

用例

Usage: streamdump [-hv] [-i interface]
Options:
  -b    Capture bidirectional data flow
  -d string
        The domain name of the packet to be captured
  -f string
        BPF filter rules for pcap (default "tcp")
  -h    print this help message and exit
  -i string
        Interface to get packets from (default "en0")
  -l int
        SnapLen for pcap packet capture (default 1600)
  -promisc
        Set promiscuous mode (default true)
  -r string
        Filename to read from, overrides -i
  -s string
        Filepath to save pcap files (default "./pcap_s")
  -v    Logs every packet in great detail

程序会将两分钟内没有数据传输的连接视为无效

  1. 从默认网卡(en0)捕获 baidu.com 对应 ip 以及 443 端口的 tcp 流量：

    命令：./streamdump -f 'tcp and port 443' -s './stream/' -d 'www.baidu.com'

    程序会主动查询www.baidu.com这个域名对应的 ip，并根据过滤条件进行过滤，将符合这个过滤条件的 TCP 流保存下来，如图：

  2. 从 pcap 文件中过滤出单个 TCP 流量:

    命令:./streamdump -r './file.pcap' -f 'tcp' -s './stream/'

  3. 还有很多自定义的组合，需要大家自己动手操作了！比如使用-b选项进行双向数据保存！
