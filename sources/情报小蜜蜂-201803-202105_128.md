前言

    为避免后期优化数据库遇到一系列幺蛾子问题，数据库的优化，在准备使用数据库时就应该考虑到（切记）。本文基于最近做的项目，特写此篇文章作为以后维护mysql数据库的参考。

正文

    在建立mysql数据库之前，需要先回答这几个问题：

    1） 入库内容是否包含中文字符？如是，建议使用mysql5.7 以上版本，其InnoDB和MyIASM存储引擎支持中文分词及中文全文索引。

    2） 建表时，一是选择正确的字段类型，如时间字段，最好用时间戳表示；二是哪些字段要建索引，建单索引，组合索引还是全文索引；

首先，来看看mysql的基本操作。

**二、索引相关**

1）索引类型

    根据字段的属性不同，可建立不同的索引，包括主键索引，唯一索引，普通索引，组合索引，全文索引。用得较多的是普通索引，组合索引可看成是多个普通索引组合到一起，依据的是最左前缀匹配原则，也即是组合字段中靠最左的字段最先匹配。全文索引，当字段存储内容较多时使用，用到了分词技术和匹配算法来对长文本加快检索。

2）索引的建立，查询和删除

    a. 查看索引

    mysql> show index from tblname;

![](../Images/ce2f1e7632404ae43a1952bf479210e7.png)

    b. 建表后删除索引

    drop index index\_name on table\_name;

![](../Images/b96b2aa7097973babb66db704b5fcebf.png)

     c. 建表后添加索引

    alter table table\_name add index index\_name(column\_list);

![](../Images/180a5d517645057847a1b6dfa7a59e8a.png)

3） 中文全文索引建立

    a. 建立英文全文索引

    alter table table\_name add fulltext index idex\_name(column\_list)

    b.建立中文全文索引

    建立中文全文索引，需要用到ngram插件，建索引的命令为：

    alter table  table\_name add fulltext index index\_name(column1, column2) **with parser ngram;**     

    c. 全文索引查询语句

    select \* from table\_name where match(column1, column2) against('关键字'); 

**三、mysql查询语句性能分析**

1） 采用explain命令查看，在查询命令前加explain，如：

    explain select \* from msg where msg\_text like "baby";

![](../Images/bcfcd8ded0eae6820af60c0e12ed70f8.png)    明显可以看到，这条语句只遍历了1行数据，说明用到了索引，再看一例：

    explain select \* from msg where keyword like "baby";

![](../Images/bab40cdb22a12424a22eca72bfbceab7.png)

    可以看到，由于keyword字段没有建立索引，遍历了全表的的数据，这样明显会拖慢查询速度。  

    2）开启mysql内置的慢查询功能

    在mysql的配置文件，windows为my.ini， 在\[mysqld\]item下，加入这三条语句；

    slow\_query\_log = 1       #开启慢查询日志功能

    long\_query\_time = 5     #查询超过该时间，则记录到日志中

    slow\_query\_log\_file = "ms-slow.log"   #日志的文件名，存在默认路径下

    保存配置，重启mysql即生效

    测试，在mysql命令行中，输入：select sleep（11）；

![](../Images/4a9b133e84db98499c939c230ed9ecbd.png)

    大于5s的查询都会记录进该日志中，就很容易判断是哪条查询的查询时间慢。  

    3） 直接看查询语句所花的时间

    直接命令查询语句，记得加限定条数，免得打印太多的信息，如：

    select \* from msg where msg\_text like "baby"  limit 1;

![](../Images/b90654a3834c8ba738f1bb582e973ab6.png)

    为0.00秒；这是建了索引的例子，又如：  

    select \* from msg where keyword like "baby"  limit 1;

![](../Images/31e6f881fb83f8760c66dc082760e0ee.png)

    为0.04秒，这是未建索引的例子。

**四、优化mysql的查询方法**

     不要以为建了索引就万事大吉，还有很多的坑在里面

    1） like模糊查询

    对建了索引的字段进行模糊查询，加了通配符和不加通配符的效果

    不加通配符，如：explain select \* from msg where msg\_text like "baby" ;

![](../Images/10c73e070db91e88910e3c54524d66a9.png)

    只遍历了一行数据，加了通配符，如：explain select \* from msg where msg\_text like "%baby" ;

![](../Images/14c2df11abd928e178ad7e461c9bfe88.png)

    遍历全表，索引失效了。对这种模糊查询，只有采用建立全文索引才能解决。

    2） or 连接词的使用

    对都建了索引的字段用or，可能也会出现遍历全表的情况；可以用union 命令来解决；

   3） order by 语句使用

    慎用order by，会极大第影响查询速度；

![](../Images/22a64f9588bc3f12da375d7d3fc10323.png)

![](../Images/5f0241d3ba2e8ff36b2fc5e1a02dccfa.png)

    感受下，这是某条查询语句中，加上order by 和 去掉order  by的效果，性能相差几百倍。如一定要用order by，可参考order by语句优化。  

    4）group by

    同样慎用，如一定要用，可对group by的字段加一些限定条件。

    5）join 语句

    切记，用来join的字段，类型要一致，而且要建索引。

  

**总结**

    mysql是一款很棒的数据库，但如对它的一些特性不了解，粗暴使用，会极大降低它的性能。因此，在做每次查询时，首先检查下查询语句的性能，如性能可接受，再进行开发工作。本文希望给开发人员一点启发。
