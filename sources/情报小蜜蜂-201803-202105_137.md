# 基于流量周期性和遥测分析的SCADA系统入侵检测

1、简介

         SCADA网络使用的工业协议都是很久之前设计的，当时系统与任何其他网络在物理上是隔离的，这导致这些协议中的基本安全服务的需求不足。然而越来越多SCADA系统连上网络的趋势已经导致内部网络更多地受到更广泛的网络攻击。针对SCADA系统分为四类：侦察，响应注入，命令注入和拒绝服务。

通过研究典型的SCADA系统的周期性和网络流量模式，提出一个名为PT-IDS的入侵检测系统。首先，根据SCADA网络的周期性特征，设计了一个周期性分类模块并且将其分为四类，此外为了有效检测响应注入攻击，又设计了一个辅助模块来分析网络遥测模式。两个模块同时工作，以提高入侵检测的准备行。并且根据结果生成警报，并且根据警报所匹配的严重性给予警报报告。通过纯净正常的数据包训练后，形成模型，通过仿真的攻击检验，证明了PT-IDS的有效性。

2、系统总览

PT-IDS由五个模块组成分别是：过滤器，令牌生成器，周期性分析仪，遥测分析仪，监视器。如下图所示：

流量经过过滤器，将Modbus/TCP的流量过滤出来，然后通过令牌生成器生成令牌流量，并且通过周期性分析器和遥测分析器将正常的数据训练的结果交给监视器，然后监视器使用这些结果来进行入侵检测。

3、各部分详解

 1）过滤器：主要使用进行流量的筛选，通过监听Modbus/TCP协议的默认端口502来获取Modbus/TCP的流量。

         2）令牌生成器：从筛选、过滤后的流量中提取必要的信息，用来做后续分析。包括时间戳和令牌，时间戳为形成pcap文件时的相对帧时间，令牌为根据通信协议和消息类型选择的查询五元组（transaction ID, Session ID, Unit ID, Function code, Payload）。其中transaction ID是查询和响应相匹配。即响应的令牌只有（transaction ID）。

3）周期分析器:多线程的请求可能导致输出数据包的混乱，相同请求的时间间隔大致相等，并且求得这些时间间隔然后组成一个时间间隔序列。设P^(mean)和p^(SD )分别为所有时间间隔序列的平均值和标准差。设置一个p^(SD)^ 的阈值θ用来判别请求的周期性，可以根据时间间隔序列将查询分为四类周期性：串行周期（时间间隔大致相同，p^(SD )<θ）；并行周期（时间间隔不同，但是子序列可以分成串行周期，如时间间隔序列△Tq（Q）\={40m，20m，40m，20m}）；可疑非周期（观察的序列不充分时为可疑非周期），非周期性（不能分为前面类型，则为非周期的）。

周期分析器通过GPT算法训练一定量的正常的流量后得到的结构构建了PeriodChart，生成PeriodChart后，会将其转发给监控器进行入侵检测。监控器可以根据PeriodChart来防御侦察、命令注入攻击和拒绝服务攻击。PeriodChart分为三个字段，type:这个字段是主要字段，它保存着查询类型的记录，下标表示不同的查询。time：如果序列为串行的周期，那么该字段仅包含最后一个元素的时间戳；如果是并行周期，则该字段由每个子序列的最后一个元素的时间戳组成；如果序列元素数量小于4，为可疑非周期，则该字段为序列中每个元素的时间戳；如果不是周期性的，则字段为空。range：这个字段为正常数据的区间范围，对于可疑非周期性和非周期性为空，加入查询序列元素间的时间间隔为\[a, b\]，则pRange为\[a-p^(SD ), b+p^(SD )\]。如此便能通过time和range字段来识别出序列究竟为哪个周期性。

GPT算法如图所示输入的为混合多个查询序列Q和p^(SD) 的阈值θ，通过令牌器生成每一个独立的请求序列，并计算每个请求序列的P^(mean)和p^(SD) ，如果独立的请求序列中的元素数量小于4，则序列为可疑非周期；如果请求序列的p^(SD) <θ，则为串行周期的；若请求序列能被划分为2个或者3个子序列，且每个子序列都为串行周期的话，则为并行周期；如果查询序列中有元素与P^(mean) 的差值大于3θ的话，则为异常数据，如果异常数据大于1%的话则为非周期性的，否则可能时拥堵造成的筛选出异常值并重新分类。

![](../Images/cf0e41d28cd0aa121ae7feecd64384bc.png)

4）遥测分析器：用来防御响应注入攻击，RT为与匹配请求的响应时间，TC是所观察到的响应时间筛选出关于σ的时间跨度，σ为TC的参数值，取值范围为\[0%,10%\]，TC范围内为正常，TE为扩展的可接受范围，TE的定义公式为：TE=\[a-min(a/2,φ.(b-a)),b+φ(b-a)\],φ为TE的范围标度，在TE范围外则为异常，识其为恶意数据包。如果不在TC内而在TE内则为可疑，并且都会输出警报。

另外计算了平均丢包率（APLR）和平均重传率（ARR）。APLR分为APLRc（客户端）和APLRs（服务器），可以确定检测的机场APLR发生在网络的哪一侧。APLRmax定义如下：APLRmax=min(max(0.1%,APLR),1%)。ARRmax也有一样的定义，选择0.1%阈值为了避免零丢包/重传率，而且APLR/ARR的值应该不大于1%。经过计算后遥测分析仪将会构建一个5元组（session ID，TC，TE，APLRmax，ARRmax）名叫TelemetryChart，并将其传输到监视器以便入侵检测。

5）监视器：通过接收遥测分析仪和周期分析仪训练模型所得到的TelemetryChart和PeriodChart来进行入侵检测。

       监视器由三个部分组成，遥测监视器，周期监视器和报警器。如图所示：

![](../Images/1c9e60a929ef9386e072749ed01d4dad.png)

先将令牌生成器生成的令牌流放在遥测监视器中检查，如果是查询流量，则将其传递给周期监视器进行分析。遥测监视器和周期监视器都会根据得到的结果将警报传递给警报器，然后警报器会生成严重性信息的警报报告。

遥测监视器:遥测监视器的流程如图所示，其中八角形的是生成的警告。

![](../Images/8bebdc5650498f20312d08b4046a03b9.png)

当令牌流进入遥测监视器时，会检查其session ID看是否为新的会话；接着会检测丢包率和重传率，丢包率和重传率高于TelemetryChart的训练结果会报警，并且丢包率可以判断究竟是服务器高丢包率或是客户端高丢包率，或者两者都是。然后判断此流量是响应还是请求，如果为请求则将其令牌流和请求流量都将传递给周期监视器进行入侵检测。如果是响应，则计算响应时间，如果在TE外，则发出响应异常的警报，如果在TC外而又在TE内，则发出可疑响应的警报，如果在TC内，则是为良性的响应。

周期性监视器：其工作流程如下图所示，八角形为生成的警告。

![](../Images/17698a5a4670d30df330ebafda1070a6.png)

周期性监视器首先会确认请求是不是已知请求，否则发出警报，然后会判断请求类型，从若为串行周期或者并行周期，则会看时间间隔，如果时间间隔没在指定的时间间隔内时，就会报警长间隔或者段间隔。否则将PeriodChart中time更新为当前查询的时间。如果是可疑非周期的，如果观察请求的总数达到阈值，则重新分类。否则等待请求数超过阈值时再重新分类。

警报器：遥测监控器可疑产生8种警告，而周期性监控器可以产生4种警告。根据警告的组合，可以的到警告的严重性。警报分为严重、高、中、和低。输出的报告还匹配的紧急级别，使管理员能够更直观地做出决策。

4、实验部分

本文最后一章，为了评估PT-IDS，首先捕获数据集的头2个小时作为训练集，此训练集需要清洁，没有受到任何攻击的正常数据。时间间隔阈值θ设置为0.2，从而获得的不同周期性的样本如下图：

![](../Images/1879dba0655b172d7017b6aea6272599.png)

    在检测阶段，监视器使用训练阶段产生的PeriodChart和TelemetryChart来检查每一个输入分组，为了达到总体最优，作者选择了σ为6%，φ为5，这样漏报率只有0.37%，而误报率只有0.72%，这些都与非周期性数据有关。大多数漏报是攻击者伪造非周期性请求查询PLC时产生的，而非周期性请求的RT超出TC范围则产生误报。

5、结论

    本文主要提出的算法比以前的研究更有效率。特别是能够处理周期性数据和并行周期性数据，主要是能够有效的检测到拒绝服务和响应注入攻击，这是以前的文章没能实现过的。对于SCADA系统的入侵检测充分利用了流量的周期性特征，并建立模型，这是需要借鉴和学习的。
