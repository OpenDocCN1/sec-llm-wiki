**“****简介” **

由于modbus/TCP协议是用于HMI和PLC之间的通信协议，而且协议本身存在很多安全威胁，所以在modbus网络上建立入侵检测系统是很有必要的。本文的研究是基于在上位机和PLC之间的通信流量是高度周期的前提下的。为每个HMI和PLC信道之间建立DFA模型，对在正常流量中出现的偏差标记为异常。

  

**“****结构” **

文章先分析Modbus/tcp协议的具体内容。再构造DFA模型，然后检测数据集最后得出结论。

  

**“****模型介绍”**

DFA，即确定有限状态机。典型的DFA模型是由五元组信息来表示：(Q,∑,δ,q\_0,F)。其中Q是有限状态的集合,∑代表的是一系列输入符号的集合，q\_0是开始状态，其中q\_0∈Q,δ是状态转移函数，用函数映射：δ:Q×∑→Q,F是终止状态，这篇论文不考虑终止状态。

DFA模型，简单来说是由一个起始状态q\_0经过某个事件的触发得到下一个状态的过程。其中q\_0是被定义为在捕获到的周期流量数据中第一个发出的请求状态。以下列表中显示的是DFA模型中符号更多表示方法的描述。

  

|       S\_i || 表示的是在DFA模型中的第i个状态。例如S\_1是DFA的第一个状态 |
| --- | --- |
|      s\_ii || 表示的是导致S\_i状态的输入符号 |
|       q\_i || 表示的是在序列中第i个请求 |
|         Q\_i || 表示的是在接受到q\_i之后的状态 |
|       r\_i || 表示的是在序列中第i个应答，与q\_i对应 |
|          R\_i || 表示的是接受r\_i之后的状态 |

在DFA模型中∑表示的是一系列能够引发状态发生变化的输入符号的集合，即上文提到能够引起状态变化的“事件”。（在文中被定义为请求和响应消息的集合，即∑={Query,Response}。在modbus/tcp的协议中把如下字段定义为∑中的符号（共33位）：1位的Q/R,8位的功能码，16位的参数号，8位的Count字段。本文的∑中的输入符号分为两类，已知和未知的。已知是能够在DFA模型学习阶段被观察得到的，未知的就是不能够匹配DFA状态或者在学习期间没有观察到的。

在DFA模型状态转移函数δ是通过原始的状态和输入符号来匹配正确的状态从而实现预测行为。本文把当前的状态定义为S\_i,把接收到的输入符号定义为s\_ii。在输入s\_ii导致S\_i状态转为下一个状态S\_i+1有4种类型：

|       类型 ||                 发生条件 |
| --- | --- |
|      正常 || 在周期序列中的输入已知的符号导致下一个状态 |
|     未知 || 是由于输入了未知的符号 |
|     重传 || 已知的输入和之前的输入相同 |
|     丢失 || 已知的输入符号s\_j 出现了偏差 |

由于DFA模型的输入符号由请求和响应两种数据的modbus协议字段组成，对于整个模型来说，出现未知的转移类型情况，输入符号如果是未知的请求字段，表明或者是人为的操作行为，或者是模型的构建不合适。输入符号如果是未知的响应字段，一般表明的是有错误的功能码。对于两种类的未知输入符号，该论文都把它的状态转移到第一个状态，并且标记为异常。下图DFA表示的是有两个Query的modbus 流量模型：

**“****模型构建”**

构建模型的前提条件是所有的的通信流量都是正常的,不受攻击的。这篇论文采用的方法是先构造一个最小的DFA模型，再用迭代法逐步建立。

**第一步，捕获固定数量的数据包，这个数量用Learning\_Window\_Size来表示。并且需要检查在数据包中Query和Response是不是一一对应。**

**第二步，分离信道。把PLC和HMI的IP地址相同的数据分为一个信道。**

**第三步，对数据包按照一个固定的时间帧来分割成多个小的数据包。构成候选模式。**

**第四步，迭代。首先把迭代的模式长度设置为2，用Pattern\_Length来表示（即一个Query和Response），用这个模式长度构造DFA模型，用DFA模型去验证捕获的Validation\_Window\_Size长度的待测数据集。**

**第五步，计算“丢失”，“重传”，“未知”转移类型的个数，然后计算P=正常转移类型的个数/总数。其中总数是等于“丢失”个数+“重传”个数+“未知”个数+“正常”个数。如果P是低于阈值T，那么就表明Pattern\_Length是太小了，需要加2，然后开始一个新的迭代，如果Pattern\_Length超过Learning\_Window\_Size，模型构建失败。**

要注意的是，本篇论文对于阈值T的自动设置给出了讨论。这里先解释一下两个名词，一个是周期性模式长度，即文章中的pattern  length 和候选模式长度，即candidate length。周期性模式长度是在一个周期内出现Query和Response的个数。候选模式长度就是把捕获到的数据分割成多个数据包，其中每个数据包中Query和Respons消息的个数。设置阈值T的目的是能够使得在迭代模型的时候找到合适的值，停止迭代。这篇文章中目的是使得模型自动设置阈值。文中定义周期模式长度为k,候选模式长度为n和一个待测数据集的长度Ｖ。根据先前的方法构建DFA模型。得到P的值。如下所示（各个取值的具体条件文中已给出）

  

|   P值 ||  条件 |
| --- | --- |
|    n/k ||  n≤k |
|      1 ||   n=i\*K       |
| i\*k-1/i\*k    ||  i\*k+1<=n<=i\*k+(k-1) |

文中提出，为了使得当n=k时，模型迭代能给停止。设置T=k/(k-1),当ｋ≤ｎ时，Ｐ逐渐增加的，n增加，当ｎ＝ｋ-１,Ｔ＝n/(n+1),使得Ｐ>Ｔ，迭代刚好结束。

衡量DFA模型的标准是通过两个参数：Pattern\_Length和“重传”“丢失”和“未知”的比率。其中Pattern\_Length是代表能使DFA模型的P大于阈值的最小整数，因为P大于阈值的时候，迭代停止。“重传”“丢失”“未知”的比率，这些在正常流量数据下都是很低的。DFA是把转移状态为“未知”作为异常来处理。而且根据前面文章指出“未知”的输入符号导致的下一个状态有可能是“丢失”，也有可能是“重传”。所以这三个状态都是有关联的。下图就是展现三者之间的联系的图。其中“未知”转移状态的比例是0.93%。文中指出，从横坐标来看，97.7%的时间，整个系统都是正常的。而且出现“未知”状态和“重传”“丢失”状态的时间帧是一样的。这是三者之间的联系。（这里只是展示数据集#1的某个PLC的三种状态的统计图，而且具体的数据集#1出现的异常原因，也就是“未知”状态的原因会在文中给出）

**“****结论”**

总结这篇文章，主要值得学习的地方就是构建DFA模型的方法，文章的模型不仅仅可以用于Modbus协议，也可以用于其他协议，比如S7协议等。但需要注意的是∑的值，会因为协议不同，取值协议的字段也会不同。另外。要强调一点的是，整个DFA模型都是在流量高度周期的前提下建立的。
