怎么样才算是精通 Python？


今天在知乎偶遇这个问题，看了看其他人的回答，于是随手回答了下：


-----------------

一群没精通过 Python 的人来回答什么是「精通 Python」……

精通=精+通，搞定下面两点：

1. 精于「Python 魔法」，能做到那种很多时候信手拈来、触类旁通；能做到出了棘手 Bug，能顺利调试解决；至于 Pyhonic，那是基本要求

2. 通于「创造想创造的东西」，而不是熟读 Python 源码，然而对于如何创造却一脸茫然

Python 创造面向的细分领域无数种，你要精通哪一种？这才是应该正视的根本。比如：精通爬虫:-)

-----------------

题外话下，这里提到的「Python 爬虫」，过两天我分享一道 Python 爬虫题出来，如果你搞好，那么欢迎你进入爬虫的世界。


这个道理很浅显，对吧？你学一门编程语言，目的是什么？不是为了创造？为什么我们要学软件工程各种思想，为什么我们要了解产品设计，为什么我们要掌握黑客技术，不都是为了创造？打破规则，做了破坏，不也是为了创造？你的目的仅仅是为了破坏？如果没实力，破坏你也做不好。有想法的坏人把破坏也当做了创造。


明白这样的目的，你再来重新审视下「何为精通」。


恐怕你的简历不会再罗列你精通 Python、Java、SQL、C、C++、C# 等等等，你应该会罗列你创造了什么什么。


这个社会很现实，纸上得来终觉浅，即使「满腹经纶」，也没法立足于社会。你什么都懂，你考试很牛逼，然而并没什么卵用，你精通考试罢了，你不精通创造。


何为精通？


现在看来，这只是个非常装逼的词，装逼到一些半吊子喜欢挂在嘴边，而一些高手却不敢说精通两字，另一些高手只是偶尔得瑟两下，然后洗洗睡了。
