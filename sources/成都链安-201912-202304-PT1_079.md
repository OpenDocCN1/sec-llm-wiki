# ****#攻击过程****

  

本次攻击以

0x05d65e0adddc5d9ccfe6cd65be4a7899ebcb6e5ec7a39787971bcc3d6ba73996为例进行阐述，攻击流程图如下：

  

![](../Images/1e900a010a37e2362830990593f119a7.png)

  

1.攻击者**通过闪电贷借出1000个WETH和20个NFT(DOODLE代币)，质押id为720、5251和7425的NFT**；

  

![](../Images/f6a6f880b4a29824783c232504c8342e.png)

  

2.通过步骤1中的质押，**借出12.15个WETH**；

  

![](../Images/e36077416bf2315376fb9f0274fee6fa.png)

  

3.攻击者**调用withdrawERC721函数提取出id为720和5251的NFT**；

![](../Images/4ae0328dc64bb7c3f2ff17a504ce2c8e.png)

4.步骤3过**程中会调用Ntoken合约burn函数，其内部会调用safeTransferFrom函数把NFT发送给攻击者合约，并回调攻击者合约的onERC721Received函数；**

  

![](../Images/bb5961f0953756d6e2170fce52718d32.png)  

![](../Images/0adafa2840d32112d903ae1bc5f4c61f.png)

  

5.攻击者**在攻击合约的onERC721Received函数中重入 Pool合约的liquidationERC721函数对id为7425的NFT进行清算；**

![](../Images/2fa6fdb97ac90ca01be82672ccdf2af8.png)

6.在此清算的过程中，**会调用了\_burnCollateralNTokens函数销毁攻击者合约的凭证币以及归还抵押的NFT，所以又一次调用了safeTransferFrom函数触发攻击者合约的onERC721Received函数**；

  

![](../Images/54037afc9215a558110a1c11ba87e319.png)

  

7.攻击者**再次重入，将闪电贷借来的20个NFT全部质押；**

  

![](../Images/aaba10600dc4425873f8145f2450ac73.png)

**8.借出81个WETH后回到liquidationERC721函数中，将攻击者的借贷状态设置为false**；

  

![](../Images/587d0b83c22968c7a96951a8fcf646ca.png)

**9.****已经将攻击者的借贷状态设置为false，即把用户的借贷状态改为未借贷，所以可成功提取。**

  

  

# ****#漏洞分析****

  

本次攻击的主要原因在于**提取质押品时销毁凭证NFT的相关函数以及清算后NFT转账函数可触发外部合约的回调，构成重入漏洞；并且在用户质押品被清算后会更新用户的借贷状态，导致了攻击者可利用重入进行质押借贷后进行清算，使得该用户的借贷状态被设置为无借贷，可顺利提取出质押的NFT。**

  

  

# ****#资金追踪****

  

截止发文时，攻击者攻击获利的425.5ETH已经全部进入Tornado.Cash。

  

  

# ****#总结****

  

针对本次事件，成都链安安全团队建议：

1.在关键函数中做好防重入措施。

2.项目上线前，建议选择专业的安全审计公司进行全面的安全审计，规避安全风险。
