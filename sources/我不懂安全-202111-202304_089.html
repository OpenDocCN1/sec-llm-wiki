基线检查概述

基线检查功能针对服务器操作系统、数据库、软件和容器的配置进行安全检测，并提供检测结果说明和加固建议。基线检查功能可以帮您进行系统安全加固，降低入侵风险并满足安全合规要求。

什么是基线


基线指操作系统、数据库及中间件的安全实践及合规检查的配置红线，包括弱口令、账号权限、身份鉴别、密码策略、访问控制、安全审计和入侵防范等安全配置检查。

1、高确保不允许使用未列出的文件扩展名 | 服务配置

描述

FileExtensions请求筛选器允许管理员定义其Web服务器将允许和不允许的特定扩展。属性allowUnlisted将覆盖所有未明确允许或拒绝的文件扩展名。通常，永远不要提供.config，.bat，.exe等扩展名。AllowExtensions和DenyExtensions选项与UrlScan等效。建议在最大可能的全局级别上禁止所有扩展，仅允许必要的扩展。除了必要的文件扩展名之外，禁止所有其他文件扩展名可以极大地减少应用程序和服务器的攻击面。

检查提示

--

加固建议

可以使用IIS管理器GUI，在命令行窗口中使用AppCmd.exe命令和/或直接编辑配置文件来为服务器，网站或应用程序设置allowUnlisted请求筛选器。要使用IIS管理器GUI在服务器级别进行配置：1.打开Internet信息服务（IIS）管理器 2.在“连接”窗格中，选择服务器 3.在“主页”窗格中，双击“请求过滤” 4.单击“操作”窗格中的“编辑功能设置...”。5.在常规部分下，取消选中允许未列出的文件扩展名 若要使用AppCmd.exe命令设置此请求筛选器，请在提升的命令提示符处运行以下命令：

%systemroot%\system32\inetsrv\appcmd set config /section:requestfiltering /fileExtensions.allowunlisted:false

2、高确保为会话状态配置了“ httpcookie”模式 | 服务配置

描述

会话cookie将会话信息与该会话的客户端信息相关联，该信息可以是用户连接到站点的持续时间。Cookie与客户端和服务器之间的所有请求一起在HTTP标头中传递。会话信息也可以存储在URL中。但是，以这种方式存储会话信息具有安全隐患，可能会打开攻击向量，例如会话劫持。一种用于防止会话劫持攻击的有效方法是强制Web应用程序使用cookie来存储会话令牌。这可以通过将sessionState节点的cookieless属性设置为UseCookies或False来实现，这将反过来使会话状态数据不包含在URI中。建议将会话状态配置为UseCookies。正确配置的Cookie可以防止ASP.NET将会话信息移至URL，从而有助于减轻攻击风险，例如会话劫持尝试；在URI中移动会话信息会导致会话ID显示在代理日志中，并且客户端脚本可通过document.location对其进行访问。

检查提示

--

加固建议

通过使用IIS管理器GUI，在命令行窗口中使用AppCmd.exe命令，直接编辑配置文件或编写WMI脚本，可以将SessionState设置为UseCookies。执行以下操作，以在IIS管理器GUI中将sessionState节点的cookieless属性设置为UseCookies：

1.打开IIS管理器GUI并浏览所需的服务器，站点或应用程序
2.在“功能视图”中，找到并双击“会话状态”图标
3.在Cookie设置部分中，从模式下拉菜单中选择使用Cookie
4.在“动作”窗格中，单击“应用”

若要使用AppCmd.exe在服务器级别配置sessionState，该命令应如下所示：

%systemroot%\system32\inetsrv\appcmd set config /commit:WEBROOT /section:sessionState /cookieless:UseCookies /cookieName:ASP.NET_SessionID /timeout:20

如果以上两种方式都没有生效，可直接修改配置文件，配置文件为网站根目录下的配置文件web.config，在这个配置文件中<configuration>这个节点下添加一下这个节点

<system.web>
<sessionState cookieless="UseCookies" mode="StateServer" />
</system.web>

3、高确保“debug”已关闭 | 服务配置


描述

开发人员经常在活跃的ASP.NET开发期间启用调试模式，以使他们不必在每次对资源处理程序进行更改时都连续清除其浏览器缓存。问题可能是由于将其保留为“ on”或设置为“ true”。编译调试输出将显示给最终用户，从而使恶意人员可以获得有关应用程序的详细信息。由于machine.config配置文件中的<deployment retail =“ true” />会覆盖所有调试设置，因此这是一种深度防御建议。建议仍然关闭调试。将<compilation debug>设置为false可确保在实时应用程序使用期间不会无意间显示详细的错误信息，从而减轻了应用程序信息泄漏到不道德的人手中的风险。

检查提示

--

加固建议

要使用UI进行此更改，请执行以下操作：1.打开IIS管理器并浏览所需的服务器，站点或应用程序 2.在“功能视图”中，双击“ .NET编译” 3.在“ .NET编译”页上的“行为”部分，确保“调试”字段设置为False。4.完成后，在“操作”窗格中单击“应用”。

4、高确保将“目录浏览”设置为禁用 | 服务配置


描述

目录浏览允许根据Web客户端的请求显示目录的内容。如果为Internet Information Services中的目录启用了目录浏览，则当满足以下两个条件时，用户将收到一个列出目录内容的页面：1. URL中未请求特定文件 2.在IIS中禁用了默认文档功能，或者如果启用了默认文档功能，则IIS无法在目录中找到与IIS默认文档列表中指定的名称匹配的文件。建议禁用目录浏览。确保禁用目录浏览可能会减少泄露敏感内容的可能性，这些敏感内容可通过IIS意外访问。

检查提示

--

加固建议

可以使用UI，运行appcmd.exe命令，直接编辑配置文件或编写WMI脚本来设置目录浏览。要使用appcmd.exe命令在服务器级别禁用目录浏览：

%systemroot%\system32\inetsrv\appcmd set config /section:directoryBrowse /enabled:false

5、高确保将'notListedIsapisAllowed'设置为false | 服务配置

描述

notListedIsapisAllowed属性是服务器级设置，位于ApplicationHost.config文件中<security>下<system.webServer>部分的<isapiCgiRestriction>元素。该元素确保恶意用户无法将未经授权的ISAPI二进制文件复制到Web服务器，然后再运行它们。建议将notListedIsapisAllowed设置为false。将此属性限制为false有助于防止潜在的恶意ISAPI扩展运行

检查提示

--

加固建议

若要使用IIS管理器将notListedIsapisAllowed属性设置为false：1.以管理员身份打开IIS管理器 2.在左侧的“连接”窗格中，选择要配置的服务器 3.在“功能视图”中，选择“ ISAPI和CGI限制”；在“操作”窗格中，选择“打开功能” 4.在“操作”窗格中，选择“编辑功能设置” 5.在“编辑ISAPI和CGI限制设置”对话框中，清除“允许未指定的ISAPI模块”复选框（如果已选中） 6.点击确定 若要使用AppCmd.exe命令设置此请求筛选器，请在提升的命令提示符处运行以下命令：

%systemroot%\system32\inetsrv\appcmd.exe set config -section:system.webServer/security/isapiCgiRestriction /notListedIsapisAllowed:false

6、高确保未授予处理程序写入和脚本/执行权限 | 服务配置

描述

开发人员经常在活跃的ASP.NET开发期间启用调试模式，以使他们不必在每次对资源处理程序进行更改时都连续清除其浏览器缓存。问题可能是由于将其保留为“ on”或设置为“ true”。编译调试输出将显示给最终用户，从而使恶意人员可以获得有关应用程序的详细信息。由于machine.config配置文件中的<deployment retail =“ true” />会覆盖所有调试设置，因此这是一种深度防御建议。建议仍然关闭调试。将<compilation debug>设置为false可确保在实时应用程序使用期间不会无意间显示详细的错误信息，从而减轻了应用程序信息泄漏到不道德的人手中的风险。

检查提示

--

加固建议

存在脚本或执行时，ApplicationHost.config（服务器范围）或web.config（站点或应用程序）的<handlers>部分中的accessPolicy属性一定不能具有Write。要解决Web服务器的此问题，必须手动编辑服务器的ApplicationHost.config文件的<handlers>部分中的属性。要使用记事本编辑ApplicationHost.config文件，请执行以下步骤：1.以管理员身份打开记事本 2.在％systemroot％\system32\inetsrv\config中打开ApplicationHost.config文件。3.编辑<handlers>部分的accessPolicy属性，确认在存在Script或Execute时不存在Write。若要使用AppCmd.exe命令设置此请求筛选器，请在提升的命令提示符处运行以下命令：

%systemroot%\system32\inetsrv\appcmd set config /section:handlers /accessPolicy:Read,Script

7、高确保启用日志功能 | 服务配置


描述

IIS引入了一种新的日志记录方法。管理员现在可以将日志记录信息发送到Windows事件跟踪（ETW）IIS将日志信息刷新到磁盘，因此在IIS之前，管理员无权访问实时日志记录信息。基于文本的日志文件也可能难以处理且耗时。通过启用ETW，管理员可以使用标准查询工具查看实时日志记录信息。

检查提示

--

加固建议

点击开始->管理工具->Internet Information Services (IIS)管理器在iis设置模块点击日志，在右侧点击开启，且在日志事件目标中勾选日志文件和ETW事件选项（如果配置了多个站点，则每个站点都需要进行配置，且应用程序池的上层目录也需要配置

8、高确保不使用默认的IIS Web日志位置 | 服务配置


描述

IIS将在每个请求上记录相对详细的信息。这些日志通常是安全响应中首先要查看的项目，并且可能是最有价值的。恶意用户已经意识到这一点，并且通常会尝试删除其活动的证据。因此，建议将IIS日志文件的默认位置更改为受限制的非系统驱动器。将IIS日志记录移至受限制的非系统驱动器将有助于减轻在系统驱动器发生故障时恶意更改，删除或丢失日志的风险。

检查提示

--

加固建议

点击开始->管理工具->Internet Information Services (IIS)管理器在iis设置模块点击日志,在目录选项点击浏览选择新的日志目录，点击右侧应用。或者使用Appcmd管理工具进行操作

%systemroot%\system32\inetsrv\appcmd set config -section:sites -siteDefaults.logfile.directory:"<log_path>"
