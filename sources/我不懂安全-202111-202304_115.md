上一章我们介绍了adb shell的一些较为常见的用法，有读者朋友问我，如果是真实手机，应该如何使用adb shell命令，如何使用pc主机和手机adb 联动呢？

  

想要实现pc主机和手机端的adb联动其实不难，只需要pc主机安装adb工具即可，手机单独安装adb工具可单独使用

  

大家公众号回复  "adb工具"，即可得到下载链接及密码，pc端解压即可直接在命令行模式下使用，无需安装，手机adb安装后可单独使用

  

adb工具解压后应包含如下图四个文件

![](../Images/f8acb7a8044fafa968c12d4e1516732c.png)

  

手机安装成功后可单独使用，大家自行研究即可，使用方式这里不做过多介绍

  

这里介绍一种简单的方式，使电脑端adb控制手机，只需将手机数据线连接至电脑，并开启调试模式即可

  

而后进入电脑adb所在文件夹，打开命令行窗口

adb devices     查看当前连接状态  

![](../Images/a146a48e5402f354db073eb28b1c8305.png)

  

使用adb shell命令可直接进入到手机adb模式

![](../Images/4771f59d5cdd7b51afe61bf98f77b836.png)

  

使用su命令可切换至管理员模式  

  

  

至此，使用电脑控制手机adb到此结束

  

先来简单的介绍一下 so 文件

Android中的so文件就是ELF文件，so文件中涵盖很多的信息，比如头部信息、section头信息、program程序端头信息 等等

  

读取so文件信息我推荐大家使用kali进行读取，因为不需要自己去配环境，实际上linux系统都可以去读取。

  

readelf -h xxx.so    查看so文件的头部信息

![](../Images/e51535e233039cc794b5f5dfc224256d.png)

readelf -S xxx.so    查看so文件的Section头信息

![](../Images/4c76767e8d840dd751e032a8f60e583a.png)

readelf -l xxx.so   查看so文件程序段头信息（Program）  

![](../Images/6d0d1248509828ae43bdc0eda650df22.png)

readelf -a xxx.so   查看so文件全部内容

![](../Images/a3f49dff10cf2b2c7ee4220b024cc7cf.png)

由于此内容太多，所以直接将之输出到txt文件内了

  

这里开始步入正题，既然是逆向，那第一步还是回归到解包脱壳

  

脱壳先不讲，在这里先介绍解包的两种简单的方法

  

反编译apk--------apktool工具

  

apktool工具大家可以自行下载，也可以在公众号 \*\*say\_ohno\*\*  回复 apktool即可获取下载链接  
  
基础命令：

java -jar apktool\_2.6.0.jar d  -f xxx.apk -o 输出文件夹名字

![](../Images/49118cf282a0fc808a7189068cdb1782.png)

这里反编译出来的是smail源码，eclipse是不能直接看的，本来是有一条命令可以将反编译出来的源码后缀直接成为.java的，但是似乎人家早在上一个版本就移除了这个功能，大家可以自己试一下，推荐大家使用ide工具查看

![](../Images/4cfa17d39a71c13d7cfcfbb57a618184.png)

  

java -jar apktool\_2.6.0.jar d  -d xxx.apk -o 输出文件夹名字

![](../Images/5758d267c84c50625a9fe3ad4568d0c1.png)

  

这一步是为了反编译得到源码，而后方便后续在AndroidManifest.xml文件中添加debuggable信息，以便开启动态调试功能，或阅读源码。

  

使用apktool反编译的好处在于，AndroidManifest.xml 在未做代码混淆的情况下是可以直接阅读并修改的

  

![](../Images/238076e9b20ac1d23e6c51ce01e94663.png)

  

解压

第二种方式，直接将apk安装包当做压缩包进行解压，这种处理方式虽然也能获取到AndroidManifest.xml文件，但是这里的AndroidManifest.xml文件却是乱码，不能直接使用的，而且解压出来的classes.dex文件需要配合其他工具进行二次编译才能获取源码

  

![](../Images/d30cd7cd38787d7a450c14a0d440b2d4.png)

打开AndroidManifest.xml，里面是乱的

![](../Images/02912e388a95d0a98f277ef6fc6c0fcb.png)

  

借助dex2.jar 进行二次编译 dex源码，使其变为 .jar格式代码，而后使用 jd-gui工具或ide工具进行阅读

  

dex2jar.bat  classes.dex  classes.dex文件路径  

![](../Images/0deaea5a81ce375271cc41d0d36a32d0.png)

![](../Images/15474da642397fe8c69d1f807128b2a3.png)

  

此时可以查看代码

  

dex2jar 工具可自行下载，或前往公众号，回复 "dex2jar"即可获取工具下载地址  

  

此时修改结束之后，进行回编译，使其重新生成apk

  

java -jar apktool\_2.6.0.jar b -d jst -o xxxdebug.apk      回编译成apk,注意要有apktool.yam文件  

  

![](../Images/85bbbb029426ec613391aa7d42b79262.png)

![](../Images/5abf4873f2bd18945851b70d6bbbdce5.png)

  

此时生成的调试版本apk不能直接安装，因为没有证书没有签名，在apk中，未签名的apk是不允许直接安装的

  

java -jar signapk.jar  testkey.x509.pem  testkey.pk8 xxxdebug.apk  xxx.sign.apk

  

![](../Images/90e14281d1e5f9db12f1d1c14e749f3c.png)

  

此时生成的apk可以安装，若是安装后依然可以正常使用，那么就属于有高风险，因为未做证书、签名校验，没有去抵抗反编译是一件很危险的事儿。  

  

获取签名证书工具，请在公众号回复"证书签名工具"，即可获取下载链接
