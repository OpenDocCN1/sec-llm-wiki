一、前言

话不多说，先上图

很有意思的“特性”，今天我们来揭秘为什么js会这样解析。。。


二、先来看看parseInt

parseInt()是一个内置的 JavaScript 函数，可以从数字字符串中解析整数。例如，让我们从数字字符串中解析整数'100'：

const number = parseInt('100');number; // 100

正如预期的那样，'100'被解析为 integer 100。

parseInt(numericalString, radix)还接受第二个参数：数字字符串参数所在的基数。radix 参数允许解析来自不同数字基数的整数，最常见的是 2、8、10 和 16。

让我们parseInt()来解析一个以 2 为底的数字字符串：

const number = parseInt('100', 2);number; // 4

parseInt('100', 2)解析'100'为以 2 为基数的整数：因此它返回4（十进制）。


三、parseInt的神秘行为

parseInt(numericalString)总是将其第一个参数转换为字符串（如果它不是字符串），然后将该数字字符串解析为整数值。

这就是为什么您可以（但不应该！）使用parseInt()来提取浮点数的整数部分：

parseInt(0.5);      // => 0parseInt(0.05);     // => 0parseInt(0.005);    // => 0parseInt(0.0005);   // => 0parseInt(0.00005);  // => 0parseInt(0.000005); // => 0

提取浮点数的整数部分，如0.5,0.05等，结果为0. 这按预期工作。

提取整数部分0.0000005怎么样？

parseInt(0.0000005); // => 5

parseInt()将浮点数解析为0.0000005... 5有趣且有点出乎意料...

为什么parseInt(0.0000005)会有如此神秘的行为？


四、揭开神秘面纱

让我们再看看parseInt(numericalString)的第一个参数做了什么：如果它不是字符串，则将其转换为字符串，然后进行解析，并返回解析后的整数。

这可能是第一个线索。

让我们尝试手动将浮点数转换为字符串表示：

String(0.5);      // => '0.5'String(0.05);     // => '0.05'String(0.005);    // => '0.005'String(0.0005);   // => '0.0005'String(0.00005);  // => '0.00005'String(0.000005); // => '0.000005'String(0.0000005); // => '5e-7'

显式转换为字符串的String(0.0000005)行为与其他浮点数不同：它是指数符号的字符串表示！

这是第二个——也是一个重要的线索！

当指数表示法被解析为整数时，您会得到数字5：

parseInt(0.0000005); // => 5// same asparseInt(5e-7);      // => 5// same asparseInt('5e-7');    // => 5

parseInt('5e-7')只解析了第一个数字'5'，跳过了'e-7'。

谜团已揭开！因为parseInt()会在遇到第一个非数字字符停止解析，所以会产生这种情况。

附带说明一下，为了安全地提取浮点数的整数部分，我推荐Math.floor()函数：

Math.floor(0.5);      // => 0Math.floor(0.05);     // => 0Math.floor(0.005);    // => 0Math.floor(0.0005);   // => 0Math.floor(0.00005);  // => 0Math.floor(0.000005); // => 0Math.floor(0.0000005); // => 0

五、结论

parseInt() 是将数字字符串解析为整数的函数。

尝试提取浮点数的整数部分时必须小心使用parseInt()。

转换为字符串的小于1e-6的浮点数（例如0.0000005与 5e-7相同）将以指数符号写入。这就是为什么使用如此小的浮点数parseInt()会导致意想不到的结果：指数表示法只有字符e前的数字会被解析。
