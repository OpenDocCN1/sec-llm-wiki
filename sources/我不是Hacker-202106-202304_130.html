C

1、exec家族 

        因为exec系列函数并不创建任何新进程，所以前后的进程ID没有发生任何改变，exec所做的就是替换当前进程的正文段、数据、堆和栈段。exec系列函数包括：

int execl(const char* pathname, const char* arg0, ...);     // end with NULL
int execv(const char* pathname, char* const argv[]);        // end with NULL
int execle(const char* pathname, const char* arg0, ...);    // end with NULL and char* const envp[]
int execve(const char* pathname, char* const argv[], char* const envp);  // exec系列函数中唯一的系统调用(其它的只是库函数，最终都要调用execve)
int execlp(const char* filename, const char* arg0, ...);    // end with NULL
int execvp(const char* filename, char* const argv[]);       // end with NULL

        这6个exec函数的参数很难记忆。函数名中的字符会给我们一些帮助：字母p表示该函数取filename作为参数，并且用PATH环境变量寻找可执行文件；字母l表示该函数取一个参数表，它与字母v互斥；字母v表示该函数取一个argv[]矢量；最后，字母e表示该函数取envp[]数组，而不使用当前环境。上面6个函数中只有execve是内核的系统调用，其它的5个只是库函数，最终都要调用该系统调用，它们之间的关系如下图：


        Demo：

// 程序名：execl
#include<stdlib.h>
main(){
    execl("cat /etc/passwd");
}

        初始进程链： 
                execl(124)_bash(123)_sshd(122)_system(1) 
        运行后进程链： 
                cat(124)_bash(123)_sshd(122)_system(1) 

        注：进程链中_bash(123)_sshd(122)_system(1)为行文方便而取的固定后缀（后同），代表ssh登陆后在bash中执行程序。

        扩展资料：execve后，系统执行ELF的完整调用链大致长这个样子： 
        execve -> do_execve -> do_execveat_common -> exec_binprm -> search_binary_handler -> fs/binfmt_elf.c:load_binary -> … -> _start

2、system函数
        看实现源码可以知道，该函数会依次调用fork、execl、waitpid。而且execl会先用/bin/sh去做事情，如下： 
        execl("/bin/sh", "sh", "-c", cmdstring, (char *)0); 
        所以，下面代码的进程链就可以知道了。

// 程序名：tsystem
#include<stdlib.h>
main(){
    system("cat /etc/passwd");
}

        进程链： 
                cat(126)_dash(125)_tsystem(124)_bash(123)_sshd(122)_system(1)

3、popen  
        与system表现一致，在Linux上源码表现如下： 
        execl(SHELL, "sh", "-c", cmdstring, (char *) 0); 
        所以，进程链中，会继续保留dash这一层： 
        cat(126)_dash(125)_tpopen(124)_bash(123)_sshd(122)_system(1)

4、posix_spawn 
        a、与system()和exec()不同的是，它会返回子进程的pid，你可以用waitpid()来等待。 
        b、和fork()/vfork()不同的是，在使用时不需要去思考哪一片代码是要被子进程执行，哪一片代码要被父进程执行。同样避免了vfork()一样的问题。 

        执行原理上，类似fork后execve。Demo：

// 程序名：posix_spawn
#include <stdlib.h>
#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <spawn.h>
#include <sys/wait.h>

extern char **environ;

void run_cmd()
{
  pid_t pid;
  char  *argv[] = {"cat", "/etc/passwd", NULL};
  int status;
status = posix_spawn(&pid, "/bin/cat", NULL, NULL, argv, environ);
  if (status == 0) {
    do {
      if (waitpid(pid, &status, 0) != -1) {
         printf("Child status %d\n", WEXITSTATUS(status));
      } else {
        perror("waitpid");
        exit(1);
      }
    } while (!WIFEXITED(status) && !WIFSIGNALED(status));
  } else {
      printf("posix_spawn: %s\n", strerror(status));
  }
}

void main(int argc, char* argv[])
{
run_cmd();
  return;
}

        Demo跑完得到进程链如下： 
        cat(125)_posix_spawn(124)_bash(123)_sshd(122)_system(1)


总结         

        综上，Linux拉起子进程的形成的进程链分三种情况： 
       1、直接调用exec家族函数，将子进程替换为主进程。

       进程链：cat(124)_bash(123)_sshd(122)_system(1) 

       2、fork后调用exec。

       进程链：cat(125)_fork(124)_bash(123)_sshd(122)_system(1) 

       3、fork后exec家族带/bin/sh参数。

      进程链：cat(126)_dash(125)_fork(124)_bash(123)_sshd(122)_system(1)





PHP

1、exec/system/passthru/popen/shell_exec 

        php调用子进程方法如下：

<?php echo exec('cat /etc/passwd'); ?>
<?php system('cat /etc/passwd'); ?>
<?php passthru('cat /etc/passwd'); ?>
<?php popen('cat /etc/passwd', 'r'); ?>
<?php shell_exec('cat /etc/passwd'); ?>

        先看这些内置函数的实现，exec/system/passthru定义如下：

PHP_FUNCTION(exec)
{
    php_exec_ex(INTERNAL_FUNCTION_PARAM_PASSTHRU, 0);
}
PHP_FUNCTION(system)
{
    php_exec_ex(INTERNAL_FUNCTION_PARAM_PASSTHRU, 1);
}
PHP_FUNCTION(passthru)
{
    php_exec_ex(INTERNAL_FUNCTION_PARAM_PASSTHRU, 3);
}

     可知实现均为调用php_exec_ex，传入不同Mode值；而popen/shell_exec则是直接调用VCWD_POPEN来完成命令执行的。

      先跟进php_exec_ex发现是调用 php_exec函数，之后在php_exec中再调用VCWD_POPEN。

      所以，得到exec/system/passthru/popen/shell_exec，最终实现均为调用VCWD_POPEN实现。

      再来看VCWD_POPEN的定义： 
#define VCWD_POPEN(command, type) virtual_popen(command, type)

        在vitual_popen中，可以找到具体实现函数为：popen(command_line, type) 
        对应C中对popen的解释，知道进程链中会起dash。

        所以，直接php执行，进程链如下： 

cat(126)_dash(125)_php7.2(124)_bash(123)_sshd(122)_system(1) 

        nginx+php-fpm环境下访问，进程链如下： 

cat(9681)_dash(9680)_php-fpm7.0(9520)_php-fpm7.0(9515)_systemd(1) 

        apache + php环境下访问，进程链如下： 

cat(13259)_dash(13258)_apache2(12936)_apache2(12870)_systemd(1)

2、pcntl_exec 

        跟进到函数实现，可以发现，它是直接调用的execve(path, argv, envp)，结合第一节中对exec家族的了解，可以知道直接调用，会代替父进程。所以，使用上，一般还有个pcntl_fork配套。 

        Demo如下：

<?php
    $cmd = "/bin/cat";
    $args = array("/etc/passwd");
    pcntl_exec($cmd, $args);
?>

        php直接执行可用，进程链： 
        刚开始： php(124)_bash(123)_sshd(122)_system(1) 
        运行后： cat(124)_bash(123)_sshd(122)_system(1) 
        而使用php -S启动服务时，父进程会直接被kill掉。

        但nginx+php-fpm、apache+php下使用，需要pcntl模块，且默认在disable_function里。

        而且，apache、php-fpm服务下，会单独起子进程跟进当前请求，所以，并不会干掉整个服务，而是单纯的脱离了父进程，变成一个从system出来的进程。可以达到一个脱离父进程的效果。

3、proc_open 
        8.0版本源码实现如下：

child = fork();
...
if (argv) {
    execvp(command, argv);
} else {
    if (env.envarray) {
        execle("/bin/sh", "sh", "-c", command, NULL, env.envarray);
    } else {
        execl("/bin/sh", "sh", "-c", command, NULL);
    }
}

        使用proc_open起进程会区分有无参数，在有参数时，将直接由父进程拉起子进程。

        而8.0以下版本实现如下：

child = fork();
...
if (env.envarray) {
    execle("/bin/sh", "sh", "-c", command, NULL, env.envarray);
} else {
    execl("/bin/sh", "sh", "-c", command, NULL);
}

        Demo：

<?php
    $proc=proc_open("cat /etc/passwd",
    array(
    array("pipe","r"),
    array("pipe","w"),
    array("pipe","w")
    ),
    $pipes);
    print stream_get_contents($pipes[1]);
?>

        php直接运行： 
cat(126)_dash(125)_php7.0(124)_bash(123)_sshd(122)_system(1)

        apache+php： 
cat(16877)_dash(16874)_apache2(16192)_apache2(16186)_systemd(1)

        nginx + php-fpm: 
cat(17377)_dash(17366)_php-fpm7.0(15785)_php-fpm7.0(15778)_systemd(1)

结论

         1、php8之前，进程链基本全是: cat(126)_dash(125)_php(124)_bash(123)_sshd(122)_system(1)。

        2、php8之后，也只有在proc_open函数中，会在无参数时直接拉起进程。进程链：cat(125)_php(124)_bash(123)_sshd(122)_system(1)，其余情况与php8之前一致。不过proc_open一般在disable_function里。 

        3、pcntl_exec能达到一些脱离父进程的效果，不过这个在apache等服务中大概率需要编译模块。且默认在disable_function里。

        跟进execve_with_shell_fallback，在调用execve出错的时候，会进一步调用execve_as_traditional_shell_script，否则就是execve或者execvp来处理。

void
execve_with_shell_fallback(int mode, const char *file,
const char *argv[],
const char *const envp[])
{
    if (mode == MODE_CLONE || mode == MODE_VFORK) {
        /* shared address space; be very careful. */
        execve(file, (char **) argv, (char **) envp);
    if (errno == ENOEXEC)
        execve_as_traditional_shell_script(file, argv, envp);
    } else {
        /* unshared address space; we can mutate environ. */
        environ = (char **) envp;
        execvp(file, (char **) argv);
    }
}

        而在execve_as_traditional_shell_script中，则是在进程链中增加/bin/sh。

void
execve_as_traditional_shell_script(const char *file,
                                   const char *argv[],
                                   const char *const envp[])
{
    ...
    argv[0] = "/bin/sh";
    argv[1] = file;
    execve(argv[0], (char **) argv, (char **) envp);
    ...
}

        综上，在java拉起进程过程中，getRuntime最终也会走到ProcessBuild，进而调用底层c代码。Linux下进程链情况下会是：cat(125)_java(124)_bash(123)_sshd(122)_system(1)。 

        只有在拉起失败的情况下，才会再尝试用execve_as_traditional_shell_script增加一层/bin/sh -c来拉起子进程。

Python

3.8.0

1、subprocess模块

        Popen函数调用链是：_init --> _execute_child --> _posix_spawn --> os.posix_spawn --> py_posix_spawn --> posix_spawn。

os.system实现如下：

static long
os_system_impl(PyObject *module, PyObject *command)
{
    long result;
    const char *bytes = PyBytes_AsString(command);
    if (PySys_Audit("os.system", "(O)", command) < 0) {
        return -1;
}
Py_BEGIN_ALLOW_THREADS
result = system(bytes);
Py_END_ALLOW_THREADS
    return result;
}

        其余的os族实现，也基本是直接调用系统库。如os.execl –> execl。

2.7.5

        Popen函数调用链是：_init --> _execute_child --> os.execvp(e) --> os._execvpe --> execv(e)。 
OS模块：

os.execl ==> execv
os.execle ==>  execve
os.execlp ==>  os.execvp ==> os._execvpe ==> execv(e)

        如果存在fork，且存在execv而不存在spawnv，则：spawnl系列，均为fork后exec。

        os.system实现如下：

static PyObject *
riscos_system(PyObject *self, PyObject *args)
{
    char *command;
    if (!PyArg_ParseTuple(args, "s:system", &command)) return NULL;
    return PyInt_FromLong(system(command));
}

综上： 
        os.system进程链会有dash；popen在默认参数下没有dash；os.exec系列在没有fork的情况下，替换父进程；os.spawn默认参数下无dash。


结论

1、Linux下PHP在拉起的子进程时，默认参数下，会借助/bin/sh -c，进程链中会有dash。 
2、Linux下Java在拉起的子进程时，默认参数下，会直接执行，只有当执行失败的时候，才会调execve在参数中增加/bin/sh -c再次尝试。 
3、Linux下Nodejs在拉起子进程时，是否包含dash由传入函数的参数决定。
4、Linux下python在拉起子进程时，默认参数下，只有os.system会在进程链中包含dash。
