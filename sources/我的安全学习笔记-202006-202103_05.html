       曾有一天，在朋友圈看到有大佬发一个通用的应用层抓包的Frida脚本-【Github搜索 r0capture】。于是在中午午休的时候，抽时间体验了下。这个是基于frida_ssl_logger改进而来的，frida_ssl_logger 抓https包的原理就是hook了 SSL_write，SSL_read等，在HTTPS协议中对明文数据读写的地方。

frida_ssl_logger  和 r0capture 可以满足查看HTTPS请求数据包的需求，也可以导出生成 pcap包，可以用wireshark 查看，和导出RAW格式的请求包。但是始终没有直接使用Burp抓包这样更爽的体验～

测试效果时抓到了Soul的登录包，我这使用系统证书的手机表示不服，于是使用之前配置的手机进行Burp抓包测试。这一测试就遇到和解决了之前没有弄过的双向证书情况，故这里做一下笔记，以便以后参考。

抓Soul的注册/登录包，我先使用了【系统证书的抓包法】，【Frida SSL unpinning法】，最后导入了APP里面的客户端证书才解决。

如何导入系统证书：

前置条件：手机root + BL解锁【可以adb remount】或者使用模拟器也可以【Mumu模拟器测试有效】

1. 配置burp代理，访问http://burp/ 下载证书

2. 执行2条命令

openssl x509 -inform DER -outform PEM -in cacert.der -out cacert.pemopenssl x509 -subject_hash_old -in cacert.pem （得到一个hash 比如：9a5ca275）

3. push 到手机

mv cacert.pem 9a5ca275.0adb remountadb push 9a5ba575.0 /system/etc/security/cacerts/

如果遇到adb shell之后 用su命令可以获取root权限， 但是在adb push的时候，就没有权限。这种可以这样解决

adb shell su -c "mount -o rw,remount /system”

然后再push上去即可

导入自定义CA根证书：

这是为了bypass 一些APP把Burpsuite的证书给拉黑时，导致安装burp证书后也无法抓https包的情况。【虽然好像还没有遇到过案例，麻烦一点安装一下总是好的】，可以参考这篇文章的操作记录。

https://blog.nviso.eu/2018/01/31/using-a-custom-root-ca-with-burp-for-inspecting-android-n-traffic/

我是Mac，需要用到openssl的配置文件，/System/Library/OpenSSL/openssl.cnf ，大致过程如下：

openssl req -x509 -days 730 -nodes -newkey rsa:2048 -outform der -keyout server.key -out ca.der -extensions v3_ca -config openssl.cnf

第一项输入：BE

从第二项开始全部输入：NVISO CA

openssl rsa -in server.key -inform pem -out server.key.der -outform deropenssl pkcs8 -topk8 -in server.key.der -inform der -out server.key.pkcs8.der -outform der -nocrypt

安装CA证书：

经过上面操作会生成自己的CA证书，这里就像上面的操作一样 把ca.de安装为系统证书。

导入自定义的CA证书到Burp中：

打开burp - proxy -options , 点击import/export按钮: 点击Import 导入DER格式证书，然后导入证书文件(ca.cer 和server.key.pkcs8.der)

下载Burp证书，安装为系统证书（很关键，因为安装了自定义证书，需要重新操作一下上面的导出http://burp/证书安装到手机和电脑中）

Frida SSL Unpinning法

https://github.com/coffeehb/FridaHook/tree/master/HTTPS%E6%8A%93%E5%8C%85%E7%9B%B8%E5%85%B3

使用方法也很简单，开启Frida 一键Hook大法。

启动Frida-Serveradb forward tcp:27042 tcp:27042adb forward tcp:27043 tcp:27043adb shell /data/local/tmp/frida-server -Dpython frida_attach.py hooks.js cn.soulapp.android

上面一顿操作后，可以抓95%以上的APP的https包了，哪这里到底遇到了什么问题？？问题如下图所示：

https的包到是一个不漏的抓到了，但是关键请求 返回400. Title提示“400 No required SSL certificate was sent”，客户端使用了不是预期的SSL证书发出的请求。


服务端校验了客户端的SSL证书是否为自己要求使用的， 这里我们Burp的证书，自定义的证书都是不允许的。这终于让我遇到了双向SSL校验场景了，下面将记录如何解决这个问题的。

打开微信搜索一下“双向证书”，找到了曾经看过的一篇文章。于是理清了解决思路：


解决步骤：

        1、导出目标应用APK文件

        2、解压找到P12证书文件

        3、找到证书导入密码

        4、导入P12证书文件到burp中

        5、对应的cer证书，安装到Mac中，并设置信任

第一步，导出APK：

adb shell pm path cn.soulapp.android 找到apkpackage:/data/app/cn.soulapp.android-36w1gAfCIfIm0wYyRmJPqw==/base.apkadb pull /data/app/cn.soulapp.android-36w1gAfCIfIm0wYyRmJPqw==/base.apk . 下载到本地

第二步，解压找到P12证书文件

mv base.apk base.zipunzip base.zip -d base

到资源目录文件夹assets下找到证书-assets/client.cer 和 client.p12


第三步，找到证书导入密码

使用了这个Frida脚本，可以轻松得到密码:  }%2R+\OSsjpP!w%X

https://raw.githubusercontent.com/m0bilesecurity/Frida-Mobile-Scripts/master/Android/tracer_keystore.jsHook命令：frida -U -l tracer_keystore.js -f cn.soulapp.android


第四步，导入P12证书，安装cer证书并信任

点击client.cer安装


打开Burp —— User Options ——Client SSL  Certificates —— Add ——Host设置前面返回400的地址，证书类型选 PKCS#12 

然后点Next, 然后证书文件选择 P12文件，密码就是上面得到的。


点击下一步，可以看到导入成功了～


重新再来抓包看看，效果如下：


设置Host为* ，全部都可以抓包和解包了。成功bypass。


到此，顺利完成双向证书场景下的Burp抓包需求～笔记也就到此为止了，希望对读者有所帮助～
