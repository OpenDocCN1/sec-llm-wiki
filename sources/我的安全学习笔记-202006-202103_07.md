【一】背景、

这两天在整理Sonar的官方提供的JAVA类扫描规则时，看到了下面这样的一条漏洞规则java:S3749。

## 不安全的代码示例：

*   
*   
*   
*   
*   
*   
*   
*   
*   
*

```
@Controllerpublic class HelloWorld {  private String name = null;  @RequestMapping("/greet", method = GET)  public String greet(String greetee) {    if (greetee != null) {      this.name = greetee;    }    return "Hello " + this.name;  // if greetee is null, you see the previous user's data  }}
```

该规则原名为：Members of Spring components should be injected

spring组件的成员应注入，单例注入非静态成员共享会产生风险

看到这里是有一点懵的吧，下面用一个demo来进行理解。

【二】基础知识、

    在SpringMVC中，控制器Controller负责处理由DispatcherServlet分发的请求，它把用户请求的数据经过业务处理层处理之后封装成一个Model，然后再把该Model返回给对应的View进行展示。在SpringMVC中提供了一个非常简单的定义Controller的方法，你无需继承特定的类或实现特定的接口，只需使用@Controller标记一个类是Controller，然后使用@RequestMapping和@RequestParam等一些注解用以定义URL请求和Controller方法之间的映射，这样的Controller就能被外界访问到。此外Controller不会直接依赖于HttpServletRequet和HttpServletResponse等HttpServlet对象。

*   SpringMVC的controller默认是单例的，单例模式是Spring的官方推荐用法，其优势就是：在高并发下能极大节省资源，提高服务抗压能力。因为单例模式无论多少用户同时访问，不用每次都new实例。
    
*   单例模式下容易出现的问题就是controller中定义很多的属性，那么单例肯定会出现竞争访问，不同用户共享数据变量就带来了安全风险。
    

  

【三】复现单例模式的安全问题、

   下面是定义的一个/hello处理接口，接受GET请求。

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   

```
@Controllerpublic class HelloController{    private String Key = null;    @ResponseBody    @RequestMapping(value="/hello",method = RequestMethod.GET)   public String printHello(String greetee) {        if (greetee != null) {            this.Key = greetee;        }      System.out.println("hello " + this.Key);      return "hello" + this.Key;   }
```

这短短几行代码无法还原真实业务场景，我这里是想提醒大家注意它存在的漏洞风险。当你做代码审计时候，看到上面的定义的Controller和接口，你知道有什么漏洞吗？？

这是一种默认的单例模式实现的Controller，根据前面的基础知识，如果两个用户：

黑客A访问：http://192.168.0.7:8080/hello

用户B访问：http://192.168.0.7:8080/hello

他们的请求处理都是同一个实例中完成的，这个实例里的变量是共享的，也就是这里A 和 B 访问的Key是同一个。

那么就有如下的情况：如果黑客访问链接：http://192.168.0.7:8080/hello?greetee=hacker2020 后，这个共同的实例中, 成员变量Key就被设置成功了 hacker2020,

那么用户A访问http://192.168.0.7:8080/hello的时候，就会读取到这个被黑客A篡改的数据。

可能这不像一个安全问题，但是下面这样就不一样了。下面这是不是就更像一个安全漏洞了呢？？

![](../Images/a818d42e467b9e14113784dbd28591b5.png)

这里要说明的单例模式下共享变量是不安全的，为了避免这种问题可以有如下的办法。

1、不要在controller中定义和使用成员变量。

2、万一必须要定义一个非静态成员变量时候，则通过注解@Scope(“prototype”)，将其设置为多例模式。【多例模式是线程安全的】

3、在Controller中使用ThreadLocal变量

哪么上面的代码，在自定义的HelloController添加一个注解@Scope("prototype”)后，就变成了多例模式。

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   

```
@Controller@Scope("prototype")public class HelloController{    private String Key = null;    @ResponseBody    @RequestMapping(value="/hello",method = RequestMethod.GET)   public String printHello(String greetee) {        if (greetee != null) {            this.Key = greetee;        }      System.out.println("hello " + this.Key);      return "hello" + this.Key;   }
```

再次测试发现已经不存在上面的数据互相影响的问题了。
