下载回来的复现项目如下，作者提供了一个Dubbo的生产者和 恶意的消费者，消费者已经内置marshalsec的攻击Hessian协议的gadget.



生产者DubboModules

打开IDEA -> Import Project -> 找到DubboModules 打开，完成项目导入，其为Maven项目。

  • JDK使用gadget能打的版本吧。这个项目需要JDK8的，所以这里以著名的1.8u20来运行。


导入后IDEA会自动识别pom.xml的依赖，开始下载依赖的jar包。

  • 需要注意生产者的provider.xml配置文件里面关于dubbo协议监听端口和zookeeper的配置


  • 到此是其实是可以开始Run了，我这里有点问题，修改了Provider文件的下面代码，指定Spring加载配置文件的方式。

ClassPathXmlApplicationContext context = new ClassPathXmlApplicationContext("classpath:/*.xml") ;


  • 到Zookeeper里面查看，已经成功注册了生产者，等待消费者使用。



消费者dubboconsumer


通用打开IDEA -> Import Project -> 找到dubboconsumer 打开，完成项目导入，也是Maven项目，JDK也选择1.8u20.

经过踩坑，我这里需要修改Consumer的代码如下：

ClassPathXmlApplicationContext context = new ClassPathXmlApplicationContext("file:/Users/CFHB/SRCVulns/VulnsHub/DubboCVE/dubbo-poc/dubboconsumer/resources/consumer.xml") ;

  • 这里指定了恶意LDAP服务地址，以及使用file指定Spring加载的配置文件


IDEA完成环境的自动导入后，就可以运行了。但是这里还需要把恶意的LDAP服务跑起来。
