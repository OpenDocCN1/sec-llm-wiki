前言

![](../Images/c0877f2fb27df7b2ded81ceac3bd27c6.png)

  

本次测试选取了十二个项目做参考，其中由于部分项目原因没有安装上手，大部分均进行了安装使用。总体来说，推荐xray，命令行界面数据处理较快，准确率也较高，挺适合后台扫描。其次是goby，图形界面。功能以及准确性都可以，最大的缺点就是处理慢占用性能，比较时候资产收集，内网扫描。然后xray和goby的poc和exp编写都比较容易上手，简单的poc看一下规则就可以编写。

还有几个其他框架也还不错，一个是pocassist（就是官方给到的poc误报太高了，或者扫不出来）。一个是ARL，这个用于资产扫描，资产收集挺不错，漏洞扫描就差了些。还有一个是biu未开源的框架，但是可以申请测试一个月，根据官方提供的数据感觉挺不错的。

官网直接下载可执行程序，除了免费版，还有一个红队版；但是没什么必要，授权一个月一个月的给，直接用免费版也一样

还有一个是插件模块，这个也挺好用的，但是对电脑性能有要求，性能差了装上也打不开

  

![](../Images/dac99c373e798680783a1ffa8e413b72.png)

  

综合对比了一下，这个算目前开放工具里面好用的了，但实际扫描公网差了点效果。但是在内网是真的不错。内网goby一开，超级弱口令一开就可以撸几把了，坐等验证、报告。

工具包含扫描模块，poc管理模块以及插件模块；poc可以自定义，而且编写也不难。

![](../Images/99d51e57d303a73e197571edd7c7130e.png)

  

poc和exp的编写也就不多说了，和xray一样，提取规则就行。后续有时间再详细补充吧。

编写的时候有个注意事项，goby检测条件，它代表着goby识别到某种资产，才会使用此poc进行验证，所以要根据右边问号的提示尽量的精确识别出资产，才能保证poc在使用的时候确实被触发

1、安装

安装有两个方法，

一个是下载项目解压，使用命令python38 cli.py -h

![](../Images/71ec0d9d2796aa1adc5f5e6ef4b1a752.png)

  

一个是使用pip命令安装（pip3 install pocsuite3），这个有个好处就是不用打开对应目录文件，可以全局调用

![](../Images/6eb2b6b2b07217b477400a6e6172585e.png)

  

使用感受：

结合了知道创宇自家的几大产品，zoomeye和seebug，以及调用傻蛋接口。本地poc就目录里面的那些，相对来说很少。poc的来源于你自己seebug账号提交的poc，比如我这里的账号由于木有提交，直接no poc。

  

![](../Images/e4933f3f4d9e7506efeac90ddcca8bef.png)

  

使用可以一对一，一对多。这里有个设计没搞懂，参数-r是指定poc的，也就是扫描什么漏洞自己指定，不指定就报错。看了一下参数好些也没有看到全poc扫描，按照使用习惯来说，这个就有点懵逼。我何不自己写一个py来用，为啥要用这个框架，都是命令行。不过轮子还是挺好，以后可以往云端渗透想，把工具放到云上，需要直接调用就完了

![](../Images/12e91b32b6d7af199af62be83958ca61.png)
