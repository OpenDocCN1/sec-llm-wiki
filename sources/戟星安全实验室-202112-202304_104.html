本系列文章是内网渗透学习相关的学习笔记，主要是突破内网边界进入DMZ区和办公区之后信息相关姿势（主要核心生产网我也没怎么进去过/狗头），结合hw行动中的内网渗透经验，分享相关技术文章。

0x01 内网基础


  • 工作组（Work Group）

为了避免网络混乱，局域网中多台计算机按照不同的功能、部门等分成不同的组就称为工作组（Work Group）。由于企业内网计算机的命名多半和职位员工信息等有关，可以利用工作组中的所有计算机名来定位测试运维人员或IT部门管理相关的计算机地址，其内网权限相对较大，可以获取到更多信息。


  • 域（Domain）

hw中突破网络边界拿到服务器权限之后，会遇到普通内网和域环境两种情况，普通内网就是简单用了工作组，或者计算机数量很少的中小型企业。而域环境可以理解为升级版的工作组，其安全管理机制更加严格，必须以合法的身份登陆域。我们通常会看看ipconfig中的比如DNS服务器信息（域环境中DNS服务器和域控制器通常在同一个计算机上，因此DNS服务器存在多半是存在域环境的）、执行几个域环境命令等来判断内网环境。

  • 域控制器（Domain Controller）

一般情况下我们称之为DC，也就是大家熟悉的域控。它是域中一台类似管理服务器的计算器。域控负责域内所有连入的计算器和用户的验证工作，其中存在域内的账户、密码、属于这个域的计算机等信息构成的数据库。由于域内所有用来验证身份的账号的密码散列值都保存在域控中，所以，我在北京联通域控等你/狗头。

  • 活动目录（Active Directory）

活动目录，一般称为AD，是指域环境中提供目录服务的组件。按照专业的说法，目录服务是指帮助用户快速、准确的从目录中找到其所需的信息的服务。如果将企业的内网看成一本字典，那么内网的资源就是字典的内容，活动目录就是字典的索引。其存储网络中的所有资源快捷方式。要实现域环境，就是要安装AD，内网中AD在哪一个计算机上，那么该计算机就变成DC。

0x02 内网信息收集


  • 本机信息收集

由于不清楚内网的逻辑结构，我们突破内网边界之后是一片黑暗的。通过对当前所在机器的信息搜集，话说渗透测试就是信息收集的体现不是，我们需要知道：
我是谁：对当前机器角色的判断，是普通web服务器、文件管理器、代理服务器还是DNS服务器什么的，具有什么主机权限，是否需要考虑提权。
这是哪：通过对网内的信息收集，大概有一个相关网络的拓扑结构，方便横向移动和拿下重要目标站点。
我在哪：判断当前机器所在区域是DMZ区、办公区还是核心区，有一个相对性的大致思路。
本机信息收集包括操作系统、权限、内网ip地址段、端口、服务、补丁、共享、密码、杀软等。如果目标机器所在为域环境，由于其系统、补丁、软件等具有批量安装的特性，可以了解整个域的信息。
 
查询网络配置信息
ipconfig /all 
查看IP（需要dns搜索列表，可能是域地址，如果是域名可以nslookup以确定域控服务器IP


查询操作系统及软件信息
Systeminfo | findstr /B /C:”OS 名称” /C:”OS 版本”
如果是英文版系统，中文换成英文即可，但是国内我遇到的基本都是中文的


查看安装的软件、版本、路径等
wmic product get name,version


查询本机服务信息
wmic service list brief


查询进程列表
tasklist
查看当前进程列表和进程用户，可判断杀软、邮件、vpn或其他相关可利用点，主要是看杀毒软件和相关防护。附录会罗列常见杀软的进程


查看计划任务
schtasks /query /fo LIST /v

实战中计划任务自己一般用来反弹shell、权限维持等，利用巧妙效果很好



查询用户列表
net user   查看所有用户，判断自己新建用户是否成功query user 查看当前在线用户，避免远程登陆3389时恰好管理员在线



查看端口列表
netstat -ano

查找重要的端口如3389，3306等一些服务或者接口制定渗透计划



查看补丁信息
systeminfo
关于Windows提权中就详细介绍过，利用相关补丁信息进行提权，此外还需要注意系统版本、位数等，选择合适的exp。内网中关注补丁更新频率，制定合适的权限维持和后渗透计划，避免明天shell就被更新补丁而没了


查询防火墙配置
Netsh firewall set opmode disable               win server 2003 及之前Netsh advfirewall set allprofiles state off     win server 2003之后Netsh firewall show config                      查看防火墙配置


远程连接3389
如果系统未配置过远程桌面服务，第一次开启时还需要添加防火墙规则，允许 3389 端口
netshadvfirewall firewall add rule name="Remote Desktop" protocol=TCPdir=in localport=3389 action=allow

在 Windows Server2003 中开启 3389 端口
wmic RDTOGGLE WHERE ServerName='%COMPUTERNAME%' callSetAllowTSConnections 1

WindowsServer 2008和2012中开启3389端口
wmic /namespace:\\root\cimv2\terminalservices path win32_terminalservicesetting where (__CLASS !="") call setallowtsconnections 1wmic /namespace:\\root\cimv2\terminalservices path win32_tsgeneralsetting where (TerminalName='RDP-Tcp') call setuserauthenticationrequired 1REG ADD "HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server" /v fDenyTSConnections /t REG_DWORD /d 00000000 /

保存的远程登陆凭证
cmdkey /list

  • 基本域命令

查询域管理员用户
net group “domain admins” /domain

查询域用户
net user /domain

查询域名称
net view/domain

查询域内计算机
net view/domain:XX

查询域控制器
net time/domain

查询所有域控制器
dsquery server例：dsquery server-domain super.com | dsget server -dnsname -site


查询域内计算机
dsquery computer例：（搜索域内名称以”admin”开头的10台机器）dsquery computer domainroot -name admin* -limit 10


查询域用户

dsquery user例：（搜索域内以”admin”开头的10个用户）dsquery user domainroot -name admin* -limit 10


查询域内联系
dsquery contact例：(搜索域内以admin开头的10个联系人)dsquery contact domainroot -name admin* -limit 10

查询域内子网
dsquery subnet

查询域内用户组
dsquery group例：搜索在DC=SUPER,DC=COM 雨中的所有组dsquery group dc=super,dc=com |more

查询域内组织单位
dsquery ou

查询域内站点
dsquery site例：（搜索域中所有站点的名称）dsquery site -ordn

  • 添加用户


  • windows

添加用户之前一般会查看当前管理员在线状态和有哪些用户存在，本机信息收集里面有相关的介绍。

添加admin1/adM1n@!23#用户，并添加到管理员组
net user admin1 adM1n@!23 /add & net localgroup administrators admin1 /add

删除用户
net user admin1 /del
之后选择合适的时间段开启3389，远程登陆操作查看更加方便。注意3389开启的一些防火墙配置前面有介绍。关于新建影子用户、修改注册表新建隐藏用户等，后续会在权限维持系列给出具体的操作和注意事项。

  • Linux


chpasswd方式

useradd guest;echo 'guest:123456'|chpasswd


useradd -p 方法

useradd -p `openssl passwd 123456` guest


echo -e 方法

useradd test;echo -e "123456n123456n" |passwd test


删除用户

userdel -r guest


条件允许的话，直接上fscan、goby等工具扫描。
