0x01 签名验证





使用mumu模拟器，签名验签，数字签名检测。

C:\Program Files\Java\jdk-11.0.9\bin\jarsigner.exe -verify test.apk -verbose


检测签名的 CN 及其他字段是否正确标识客户端程序的来源和发布者身份，当输出结果为“jar 已验证”时，表示签名正常。



只有在使用直接客户的证书签名时，才认为安全。Debug 证书、第三方（如

开发方）证书等等均认为风险。




0x02 解包打包





apktool工具的使用，不多说,打包 apktool b ./test/ （不指定输出路径，会写到temp文件夹下）



解包apktool.jar d C:\test.apk（apk文件的绝对路径）





0x03 加固识别





主观判断，压缩软件打开apk，一看有多个dex文件，如果dex特别小，几乎肯定有加固，dex大小不同一般是没有；如果只有一个dex文件而且特别大，大概率没有加固。



工具识别：ApkScan-PKID查壳工具（识别不了腾讯云加固的）



apkscan-pkid-v2.0

https://github.com/moyuwa/apkscan-pkid-v2.0.git


基于apkscan-pkid规则编写的python版本，添加了腾讯云加固的识别。



反编译看包，apktool解包后，通过manifest文件获取到内部包名com.btg.customer



去smali代码文件夹找这个包代码（一般在第一个，因为mainactivity）


可以看到应用代码就一个文件，只有4kb，明显不对劲，这就是加固了的，如果还不放心可以打开smali代码查看。



没有activity组件代码，主函数是代理app注册，存在常见的代码释放，反编译

把 apk 当成 zip 并解压，得到 classes.dex 文件（有时可能不止一个 dex 文件，但文件名大多类似）



使用 dex2jar 执行如下命令：dex2jar.bat classes.dex 文件路径得到 classes.dex.jar，然后使用 jd-gui 打开 jar 文件，即可得到 JAVA 代码。或者直接使用工具查看。





0x04 Activity组件导出




模拟器安装drozer，连接mumu模拟器，确认adb可发现设备。



模拟器安装drozer.apk并开启服务。



本机安装python版drozer，pip2 install drozer 有问题可看这个解决。

https://blog.csdn.net/u014101410/article/details/117693031


drozer连接，执行adb命令转发模拟器服务端口到本机。



执行命令连接drozer console connect。



执行list命令能查看到drozer模块表示成功，如果list结果为空，就切换到drozer的安装路径下再次连接C:\Python27\Scripts。



drozer操作，令查看应用程序包列表，执行run app.package.list命令查看应用程序包，中文乱码没解决的了。



或者使用-f参数进行搜索。



查看包内组件，执行命令 run app.activity.info -a com.btg.customer查看包内组件。



测试组件导出（调用），执行命令run app.activity.start --component 包名 组件路径。 

run app.activity.start --component com.btg.customer com.btg.customer.wxapi.WXEntryActivity



查看调用是否成功，这个apk只有主界面和wxapi是自定义的，即便调用成功也无风险，这里就判断无漏洞。

查找APP是否存在漏洞，如果想测试更详细可执行命令查找APP是否存在漏洞

run app.package.attacksurface 安装包名称。





0x05 dump dex





没有加固的apk就不要做这个操作！！！！！！

FRIDA-DEXDump，安装FRIDA-DEXDump

这里使用FRIDA-DEXDump这个工具

https://github.com/hluwa/FRIDA-DEXDump



或者执行pip3 install frida-dexdump直接安装工具（可能有frida安装问题，没深入）



单独安装frida，frida可能需要单独安装

执行pip3 install -r requirements.txt安装依赖库（frida库可能需要挂代理安装）



安装frida-tools，工具不需要这个，安装主要是为了自己使用方便，执行pip install frida-tools。



模拟器启动frida-server，在https://github.com/frida/frida的releases中选择模拟器对应的server版本。

https://github.com/frida/frida



使用adb上传到模拟器文件夹，添加权限后执行



如果不能连接就进行端口转发


adb forward tcp:27042 tcp:27042

adb forward tcp:27043 tcp:27043


dump app dex，将adb添加到环境变量，在模拟器中将应用窗口置顶（显示界面），命令执行python3 main.py(如果是pip安装就执行frida-dexdump)从内存导出它的全部dex文件，如果报连接错误是因为adb没发现mumu模拟器的端口，手动配置一下，如果报服务错误，则是模拟器没有启动frida-sever或者adb没连接。




处理dex，将dex按大小排序，删除特别小的那两个，因为加固后的app是通过启动器加载的。


将剩下的dex重命名后，添加到压缩包内（不添加部分反编译工具不识别classes2.dex）


GDA,http://www.gda.wiki:9090/，看雪大佬写的，也是一个app反编译工具，360会报毒（火绒没有），不放心可以在虚拟机运行。

打开后第一步是切换语言。



apkfile模块，可看包名、加固、和证书信息，其它模块和其他反编译工具差不多。




dump dex，打开设备查看当前运行的app包列表。



双击选择包查看资源，一般只看ref和dex两个项。



选中右键转存储数据，注意命名覆盖，保存字节大的dex就行





关于专业版


直接下载专业版打开，会提示激活，不激活无法使用，但是它有个很蛋疼的bug，原因是注册激活采用的定时检测。



先运行免费版，再去运行专业版，虽然同样提示激活，但是可直接关闭激活窗口，打开apk文件


这时可使用代码分析、漏洞扫描一些功能了，但是30秒后同样会提示激活，关闭了就会退出，算是可以白嫖一部分功能吧。

简单便捷的工具，但是没有反反调试处理。
