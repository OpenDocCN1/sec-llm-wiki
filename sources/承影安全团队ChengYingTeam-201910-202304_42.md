## 关键代码

### 关键代码1：id验证

*   

```
`return !preg_match("/[^0-9,]+/", $ids);`
```

如果 `$ids` 中包含一个或多个0-9和逗号时，`preg_match` 返回值为0（**\[^\]为正则匹配的非**），因此， `!preg_match("/[^0-9,]+/", $ids)` 的返回值对应为1。只要 `$ids` 中出现非[0-9和逗号]以外的其他字符时，则验证失败。

### 关键代码2：敏感词过滤

为了避免敏感字符插入导致一些安全问题，OA会对匹配到的敏感字符使用空白字符串进行替换后再进行后续处理。

*   
*   

```
`$farr = array("/<(\/?)(script|i?frame|style|html|body|title|link|meta|object|\?|\%)([^>]*?)>/isU", "/(<[^>]*)on[a-zA-Z]+\s*=([^>]*>)/isU", "/select\b|insert\b|update\b|delete\b|drop\b|;|\"|\'|\/\*|\*|\.\.\/|\.\/|and|or|into|alert|substr|exp|if|else|dump/is");``$str = preg_replace($farr, "", $str);`
```

  
**分析**一：数组中的第一个正则表达式：

*   

```
`/<(\/?)(script|i?frame|style|html|body|title|link|meta|object|\?|\%)([^>]*?)>/isU`
```

能够匹配到 `<script>` ， `</script>`， `<iframe>` ，`<frame>` 等，而 `([^>]*?)` 主要针对 `<` 到 `>` 标签之间的一些内容（ `?` 代表 `[^>]*` 为可选内容，而*则对应代表 `[^>]` 可以出现0个或多个），比如 `<script src="http://111.com">` ，这类数据显然能够被这一正则表达式匹配到。最后还有三个正则表达式选项：`isU`

  

•`i` 选项：不区分(ignore)大小写，很显然，这是为了避免攻击者使用诸如 `<sCriPt>` 这类标签绕过检测；•`s` 选项：s模式中的圆点元字符（.）支持匹配所有的字符，包括换行符；•`U` 选项：不会重复匹配，按我理解就是为了节省处理时间，因为只要匹配到了，就可以不用管后面内容了。

  

**分析二**：数组中的第二个正则表达式：

*   

```
`/(<[^>]*)on[a-zA-Z]+\s*=([^>]*>)/isU`
```

这个正则表达式显然能够匹配诸如 `<svg onclick=alert(1)>` 这类的恶意数据，也可以匹配 `<svg onclickmm=alert(1)>` 这类有攻击意图但在前端未必会造成危害的语句。**分析三**：数组中的第三个正则表达式：

*   

```
`/select\b|insert\b|update\b|delete\b|drop\b|;|\"|\'|\/\*|\*|\.\.\/|\.\/|and|or|into|alert|substr|exp|if|else|dump/is`
```

这个正则表达式，重点关注的就是SQL语句，显然 `select` ，`insert`，`update`，`delete`，`drop`，`;`，`"`，`'`，`/*`，`*`，`../`，`./`，`;` 这类敏感字符都会被过滤掉。•b选项：b 选项匹配这样的位置：它的前一个字符和后一个字符不全是(一个是,一个不是或不存在) \\w针对b选项，可以给一些例子，例如：`select7894 from (select1(sleep(5)))mqdx` 就不能被匹配到，原因就是因为\b的存在，由于7在select右侧\w所以不能匹配成功，但是 `select7894 from (select(sleep(5)))mqdx` 就能被匹配成功，因为`select(sleep(5))`的出现，`(` 在`select`的右侧，导致`select\b` 被匹配成功。
