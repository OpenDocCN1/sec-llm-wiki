## 0x00  Apache Shiro 简介

Apache Shiro 是比较重要的 Java 安全框架之一，集认证、授权、密码加密、会话管理等安全措施于一体。本文主要分析的是有关 Shiro 版本号 <= 1.2.4 反序列化问题。当然，版本号并不是问题，存在问题的是代码本身。  

## 0x01  rememberMe 利用链分析

根据官方漏洞描述 https://issues.apache.org/jira/browse/SHIRO-550 ，我们可以大概了解，问题出现在 rememberMe 这个点，所以可以通过动态调试，具体跟一下 Shiro 处理 rememberMe 的流程。  

因为我们并未进行登录操作，而是直接发送了一个带有 rememberMe 的 Cookie 请求给测试站点。于是，我们可以在文件 `org.apache.shiro.mgt.DefaultSecurityManager.class` 中的 `resolvePrincipals` 方法处打个断点，看其如何一步步处理 rememberMe 。  

![](../Images/ead262be40ee62580ddc73a717aefffc.png)

跟进 `getRememberedIdentity` 方法：  

![](../Images/d053448e7891f2162209b63728cc811d.png)

跟进 `getRememberedPrincipals` 方法：  

  

![](../Images/b32603e9a236fd5d5584a1ba5b99ccad.png)

跟进 `getRememberedSerializedIdentity` 方法，在这个方法里，主要就是将 rememberMe 的值进行 Base64 解码。

![](../Images/7683e1f3a5b0beb3b24b35cc62bb26e8.png)

首先根据 http 请求，读取 Cookie 中的 name 和 value，如下图所示：

![](../Images/c4927625481c145590d1e664da65f405.png)

接着如果获取到的 Value 不为空的话，先确定 base64 的 Padding 部分，就可以直接进行 Base64 解码，最后返回解码后的字节数组 decoded 。

然后就跳回上述 `getRememberedPrincipals` 方法中，继续跟进 `convertBytesToPrincipals` 方法，可以从函数名先大略看一下，就是将解码的字节数组进行一次解密，然后再进行一次反序列化。  

  

![](../Images/47fd5b6aed6cfe2b98b7df943bd3ab1a.png)

跟进 `decrypt` 方法：  

  

![](../Images/7c07ba0a853289ea3ebf4a2b7204e867.png)

根据 `getCihperService` 方法，可以得到当前的加解密操作为 `AesCipherService`，然后跟进 `getDecryptionCipherKey` 方法去寻找密钥 Key，当然，经过分析会发现，这个 Key 以 base64 的形式硬编码在文件`AbstractRememberMeManager.class` 里，如下图所示：  

  

![](../Images/7500967ccd68d088e2e4f56eb60a507f.png)

拿到 Key 之后，继续跟进对应  `AesCipherService` 的 `cipherService.decrypt` 方法，进行 AES 解密操作，然后可以发现初始化向量 iv 就是字节数组的前 16 个字节，如下图所示：  

![](../Images/acde621b72f144611b9d99d970af6b2e.png)

继续单步调试，就可以看到 AES 的填充模式为 CBC ：

![](../Images/1385975ec1885407768aae80682c49e3.png)

解密之后的数据，就会看到我们熟悉的 Java 序列化头 `rO0AB...` ，如下图：  

![](../Images/833d88b6cdb86b6b961e04b79b4e11d0.png)

最后跟进 deserialize 方法，最终会执行到更加熟悉的 readObject 方法，如下图：

![](../Images/339dfe2aa4243cf81af44b825489dd4b.png)

那么简单梳理一下，Shiro 整个处理 rememberMe 的流程就是：  

读取 Cookie 中的 rememberMe ---> Base64 解码成字节数组 ---> AES 解密 ---> readObject 反序列化成对象  

在最重要的 AES 解密环节中，已知的是 iv 和 填充模式 CBC ， 如果我们能够得到硬编码的密钥 `Key` ，那么我们就可以构造一个恶意的序列化对象，经过 AES 加密，再进行一次 base64 编码，放入 cookie 中的 rememberMe ，发送请求即可。

## 0x02  漏洞复现

### 0x00  环境搭建

如果只是简单地漏洞复现，可以使用 docker 镜像，如下：  

*   
*   

```
docker pull medicean/vulapps:s_shiro_1docker run -d -p 80:8080 medicean/vulapps:s_shiro_1
```

环境开启后，可直接在 `localhost:80` 进行漏洞测试。  

如果想要本地搭建环境进行调试的话，可以根据以下步骤，先获取 shiro 1.2.4 版本的源码：

```
git clone https://github.com/apache/shiro.gitgit checkout shiro-root-1.2.4cd ./shiro/samples/web
```

然后需要在文件 `pom.xml` 中设置和添加以下两项，以完美复现漏洞：  

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*

```
...    <dependencies>        <dependency>            <groupId>javax.servlet</groupId>            <artifactId>jstl</artifactId>            <!--  这里需要将 jstl 设置为1.2，是为了能解析 jsp 文件 -->            <version>1.2</version>             <scope>runtime</scope>        </dependency>...        <dependency>            <!--  这里添加存在漏洞的组件 -->            <groupId>org.apache.commons</groupId>            <artifactId>commons-collections4</artifactId>            <version>4.0</version>        </dependency>
```

当然，因为 shiro 1.2.4 版本需要 jdk 1.6 来进行编译。所以还需要修改 maven 下的文件 `toolchains.xml` ，如下：


之后将经过 maven 编译生成的 war 包放入 tomcat 下的 webapps 目录 ，启动 tomcat 就可以访问漏洞环境了。

### 0x01  利用工具 ysoserial

在这个漏洞复现过程中，我们需要使用一个专门用来生成 java 反序列化 payload 的工具—— ysoserial 。对应到这个漏洞，我们需要使用 CommonsCollections2 生成的 payload，这也是前面漏洞环境搭建要添加 `commons-collections4.4.0` 依赖组件的原因。当然，有关这个漏洞与 ysoserial 工具利用的一些疑惑，在文章中 https://www.secpulse.com/archives/73655.html 中都有很好的解释，包括在低版本下反弹 shell 的方法，orange 大佬的博客也有说明。

在网上大多数的文章中，最后都可以通过 Dnslog 外带信息对漏洞进行判定，最终通过反弹 shell 拿到权限。但是在真实环境中，可能会有各种各样的情况。于是笔者的师父提出了一个比较苛刻的前提：假设目标无法外联网络，该如何 getshell 呢？当然，首先能够想到的就是通过系统命令将 Web 路径写到我们能够访问的 web 目录下，进而根据路径信息写 shell 拿权限。但是，因为目标操作系统未知，导致我们必须执行不同的操作系统的命令才能进行判定。这样无疑增加了很多操作。

### 0x03  修复建议

虽说官方建议是将版本升级到 1.2.4 之后，但是正如文章 https://blog.csdn.net/jiangbb8686/article/details/100158480 所碰到的实际情况，在其他整合了 shiro 的开源框架中，错误代码的复用依然会导致问题发生。所以这里的修复建议有如下三条：

1.  将 shiro 升级到最新版本；
    
2.  检测代码中是否含有问题代码，如有发现，请尽快删除；
    
3.  保证你的 key 在任何开源平台都搜索不到，确保其唯一性。
    

当然根据最新消息，只要拥有一个合法的登录账号，这个漏洞可以通杀几乎所有版本。
