# 脏牛漏洞临时解决方案（开源）

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzU4NDgxMjI5NA==&mid=2247483971&idx=1&sn=863bb2d27d33d6220cd40aff3123df66&chksm=fd95502acae2d93cbf116204eaf594cac200ae0d4636b531b59cc8b92cbf5dbf2dddf3620a42&scene=126&sessionid=1681408075#rd](http://mp.weixin.qq.com/s?__biz=MzU4NDgxMjI5NA==&mid=2247483971&idx=1&sn=863bb2d27d33d6220cd40aff3123df66&chksm=fd95502acae2d93cbf116204eaf594cac200ae0d4636b531b59cc8b92cbf5dbf2dddf3620a42&scene=126&sessionid=1681408075#rd)

上周五爆出这个CVE-2016-5195 脏牛漏洞时候，安全团队正在旅游，周一赶紧测试了该漏洞，发现的确影响线上的centos服务器，利用网上公布的exp可以提权成功。因为线上服务器需要保持业务连续性，尽可能不重启，之前长亭科技提供了一种免重启的热修补补丁解决方案，实际运维线上部署还是有一些不便，需要安装几百M文件，包括一些内核debuginfo文件等，如果线上机器多的话.....于是我们自己开发了一种更简单的解决方法，可以达到同样效果，防护原理一样，体积小很多，只要把对应内核版本的编译后模块拷贝到机器加载，对于线上机器多的话方便很多。

  

**使用方法：**

模块下载：https://github.com/Safe3/clean-cow

编译模块：make x64

安装模块：insmod cow.ko

卸载模块：rmmod cow.ko

  

**漏洞原因：**

Linux 内核内存子系统的 COW 机制在处理内存写入时存在竞争，导致只读内存页可能被篡改。

Linux 之父 Linus Torvalds 在 commit 19be0ea 中修复了这个漏洞并留言

```

```

**漏洞影响：**

低权限用户可以利用该漏洞写入对自身只读的内存页（包括可写文件系统上对该用户只读的文件）并**提权至**** root**

该漏洞影响所有目前运行 Linux 系统的设备，包括但不限于运行 Linux 系统的服务器、Docker 容器服务、使用 Linux 操作系统的路由器、Android 手机/平板、搭载了 Android 系统的电视机/机顶盒等。

**漏洞修复：**

目前已知修复了该漏洞的常见发行版和修复的内核版本如下： 

1\. Ubuntu 12.04 LTS (3.2.0-113.155) 

2\. Ubuntu 14.04 LTS (3.13.0-100.147) 

3\. Ubuntu 16.04 LTS (4.4.0-45.66) 

4\. Ubuntu 16.10 (4.8.0-26.28) 

5\. Debian wheezy (3.2.82-1) 

6\. Debian jessie (3.16.36-1+deb8u2) 

7\. Debian sid (4.7.8-1)

**CentOS / Red Hat 系列操作系统尚未发布修复（截至发稿时）**

需要注意的是 Debian/Ubuntu 系统必须在 `/etc/apt/sources.list` 中开启 `-security` 后缀的源才能收到更新。由于各镜像更新软件包存在一定的延迟（一般为数小时），为了及时得到更新，建议默认从官方镜像获取安全更新
