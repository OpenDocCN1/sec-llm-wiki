什么是模板

* * *

  

模板的作用是最简单的代码减少代码的冗余量，比如张三发了篇文章，背景要花花绿绿的，页面上要有小动物跑来跑去；

  

李四看到了，也要弄一样的；

  

从这个例子可以清晰的看出，两篇文章的视觉效果是一样的，只是文章内容有区别，如果两篇文章都单独写了上述效果的代码，`张三的文章+视觉效果1，李四的文章+视觉效果1`,那么就造成了代码冗余。

  

为了解决这种问题，可以先写一个模板，当选择这个模板后，文章经过模板的处理就可以达到这个效果，这样就减少了代码的冗余量。

  

![](../Images/f070c6df6297200cd525133f704996a1.png)  
很多cms使用的M都是`MVC`架构，用户的请求发送到控制器(`C`)，控制器根据请求的不同发给不同的模型(`M`)，模型处理完成之后，由视图(`v`)进行显示。

  

在视图这一部分存在着大量的模板，根据需求渲染着来自不同模型的数据。

除了这些cms之外，也存在很多模板引擎提供相关的服务，需要注意的是：

模板引擎不属于特定技术领域，它是跨领域跨平台的概念，在Asp下有模板引擎，在PHP下也有模板引擎，在C#下也有，甚至JavaScript、WinForm开发都会用到模板引擎技术。  

  

比如`FreeMarker`和`Velocity`是Java常用的模模板；

在PHP下有`Smarty`，`Twig`和`Blade` 等；

python的有`Jinja2`、`django`，`tornado`；

凡是使用模板的地方都可能会出现 SSTI 的问题。  

  

#### 什么是模板注入

* * *

  

其实和xss有点类似，xss是把用户输入的语句当成HTML语句执行，`SSTI`是`用户输入的数据`被模板引擎当成`模板内容`进行处理，从而导致的各种问题，比如代码执行等。  

举个例子，这个页面的功能是将用户输入的名字前加个`hello`显示出来，比如输入`test`,输出`hello test`。  
![](../Images/232f528f058c2dc27e46560d7c6afaf9.png)  

这时我们输入的内容是属于前文所说的模板中的`数据`，经过模板`"hello", "$变量"`，得到结果`hello test`

  
但是如果我们输入的数据被当成模板的一部分内，比如我们输入`{{1+1}}`，这时候结果就变成了`2`.

  
![](../Images/b8221a1a65c63003c575bf591d06ade4.png)  
这是因为我们输入的内容，被当成了模板的一部分，例如`"hello","1+1"`，结果就变成了`hello 2`

####   

#### 产生原因

* * *

  

漏洞的本质就是对输入输出的控制不够严谨，再加上中间出点小问题，那么漏洞就来了。  
以`twig`举例，根据twig给出的文档：

```
1.  `require_once '/path/to/vendor/autoload.php';`
    
2.  `$loader =newTwig_Loader_Array(array(`
    
3.  `'index'=>'Hello {{ name }}!',//模板名字是 index,作用是输出hello和传给name的值`
    
4.  `));`
    
5.  `$twig =newTwig_Environment($loader);`
    
6.  `echo $twig->render('index', array('name'=>'Fabien'));//加载模板 index`
    
```

Twig使用一个加载器loader(Twig\_Loader\_Array)来定位模板，以及一个环境变量environment(Twig\_Environment)来存储配置信息。

其中，render() 方法通过其第一个参数载入模板，并通过第二个参数中的变量来渲染模板。

  
根据官方文档和xvwa写了个小的靶场，使用模板`twig`,测试靶场见附件。

```
1.  `$result_0 = $twig->render($name);// 将用户输入作为模版内容的一部分`
    
2.  `$result_1 = $twig->render("{{name}}", array("name"=> $name));// 将用户输入作为模版变量的值`
    
3.  `echo "Hello $result_0<br>";`
    
4.  `echo "Hello $result_1";`
    
```

  

正常的写法`$twig->render("{{name}}", array("name" => $name))`,这时候是将用户输入的内容`{{1+1}}`当作模板变量的值,这样就会原样输出

  

如果开发因为一些原因写成`$result_0 = $twig->render($name)`,就会把用户的输入当成模板的一部分，就会被解析。

  
以thinkphp举例，其中有个函数`display`，是由于处理模板的函数(很多cms中用于展示模板的函数都叫这个名)，

```
1.  `/**`
    
2.  ` * 渲染模板内容`
    
3.  ` * @access public`
    
4.  ` * @param string $content 模板内容`
    
5.  ` * @param array $data 模板变量`
    
6.  ` * @return void`
    
7.  ` */`
    
8.  `publicfunction display($content, $data =[])`
    
9.  `{`
    
10.  ` $this->content = $content;`
     
11.  
     
12.  ` extract($data, EXTR_OVERWRITE);`
     
13.  `eval('?>'. $this->content);`
     
14.  `}`
     
```

和上面的很相似，只要控制了`$data`的值，同样可以造成模板注入值得传入可以参考`assign`

```
1.  `/**`
    
2.  ` * 模板变量赋值`
    
3.  ` * @access public`
    
4.  ` * @param mixed $name`
    
5.  ` * @param mixed $value`
    
6.  ` * @return void`
    
7.  ` */`
    
8.  `publicfunction assign($name, $value ='')`
    
9.  `{`
    
10.  `if(is_array($name)){`
     
11.  ` $this->data = array_merge($this->data, $name);`
     
12.  `}else{`
     
13.  ` $this->data[$name]= $value;`
     
14.  `}`
     
15.  `}`
     
```

#### 寻找

* * *

  

凡是使用模板的网站，基本都会存在`SSTI`，只是能否控制其传参而已。

其实仔细看看`SSTI`的原理，有时候也可以使用`XSS`作为辅助判断。  
![](../Images/698fdf9e9a749fee18456d451990a8df.png)  
有输入，有输出，尝试构造`<script>alert(1)</script>`  
![](../Images/5ea188dbc1b30e32d15a98ea97a3c157.png)  
当然，这只是一种辅助，更多的是使用模板引擎的特性，如下图，绿色表示成功，红色表示失败。

比如在疑似的地方输入`${7*7}`,如果有结果(49)

继续输入`a{*comment*}b`,成功则是`smarty引擎`，以此类推。

有些时候不同的模板引擎对同一输入`{{7*'7'}}`都有结果

但是在`twig`中结果是49，在`jinja2`中是`7777777`。

![](../Images/5462ad976952bc74e11779d7c9e3b4a5.png)  
比如在这个实列靶场中，输入`{{1+1}}`会被执行输出结果`2`一样，通过这种方式去探测。
