1、什么是HttpOnly？

根据微软开发者网络所述，HttpOnly是一个包含在Set-Cookie HTTP响应头中的附加属性。在Cookie中使用HttpOnly属性可以防止XSS脚本获取DOM中的Cookie，而在HTTP协议中使用和获取Cookie是没有任何问题的，当然这依赖浏览器的特性，目前几乎所有浏览器都支持这一特性。

下面的这个例子显示了在HTTP响应头中使用HttpOnly的语法：

Set-Cookie: <name>=<value>[;<Max-Age>=<age>]

[; expires=<date>][;domain=<domain_name>]

[; path=<some_path>][; secure][;HttpOnly]

如果HTTP响应头中包含HttpOnly属性，那么Cookie不会被客户端脚本(前提是浏览器支持HttpOnly属性)访问;即使站点存在XSS漏洞，用户访问了这个包含XSS漏洞的链接，浏览器也不会泄露Cookie给第三方。如果一个浏览器不支持HttpOnly，并且一个网站试图设置HttpOnly属性，那么HttpOnly属性会被浏览器忽略从而创建一个脚本可以访问的Cookie;其后果是你的sessioncookie会被恶意脚本窃取或者修改。

2、使用HttpOnly可以消除大部分的XSS攻击

据统计XSS攻击的主要目标是窃取session cookie。如果服务器在创建Cookie的时候使用HttpOnly属性，那么客户端脚本就不能访问session cookie。如果一个支持HttpOnly的浏览器检测到cookie中包含HttpOnly属性，客户端脚本试图去读取cookie，浏览器会返回一个空的字符串。这样就可以阻止恶意XSS代码将session cookie发送到攻击者的网站。

3、使用python、php设置HttpOnly属性

3.1、使用python(Cherrypy)代码设置HttpOnly属性

在Cherrypysession中使用HttpOnly属相仅仅需要在配置文件中加入下面一行

tools.sessions.httponly = True

如果你使用ssl加密cookie防止中间人劫持攻击，那么在配置文件中加入下面一行

tools.sessions.secure = True

3.2、使用php设置HttpOnly属性

php自5.2.0以后支持设置HttpOnly属性。对于php管理的sessioncookie，可以在php.ini中加入如下配置来设置该属性

session.cookie_httponly = True

或通过session_set_cookie_params函数设置该属性

void session_set_cookie_params ( int$lifetime [, string $path [, string $domain [, bool $secure= false [, bool $httponly= false ]]]] )

或通过setcookie()函数设置该属性

bool setcookie ( string $name [, string $value [, int $expire= 0 [, string $path [, string $domain [, bool $secure= false [, bool $httponly=false ]]]]]] )

4、WAF(即web应用防火墙)

如果修改代码不可行，那么可以使用WAF加HttpOnly属性到session cookies中。

5、支持HttpOnly属性的浏览器

通过这个网站（http://www.browserscope.org/）可以查看支持HttpOnly属性的浏览器。

6、总结

HttpOnly cookie可以防止XSS代码获取敏感数据，有效抵御大部分XSS攻击。但是HttpOnly并不是万能的，首先它并不能解决所有的XSS问题，仍然不能抵制一些有耐心的黑客的攻击，甚至一些基于XSS的proxy也出现了，但是已经可以提高攻击的门槛了，起码XSS攻击不是每个脚本小子都能完成的了，而且其他的那些攻击手法因为一些环境和技术的限制，并不像Cookie窃取这种手法一样通用。
