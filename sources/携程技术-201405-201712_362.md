# Make Spark Sparkling

当今大数据最火的新贵是谁？非Spark莫属！Spark有多火？引用Hadoop之父Doug Cutting的一句话——“Use of MapReduce engine for Big Data projects will decline, replacedby Apache Spark”。如果你还不知道Spark是什么, 那么你需要去补补课了！

 

![](../Images/f890ccd53ac884a95922fa38e334371e.png)

 

经过一个多月的精心准备，1月10日，由携程主办Intel合办的上海第二次Spark Meetup在携程福泉路总部一楼会议室举行。活动当天的火爆现场让组织活动的携程的小伙伴们异常震惊！原定的80个名额，在开放注册时就被一抢而光。由于同学们纷纷要求再开放更多的名额，经过紧急协商，我们又新增了20个名额，然而，新增名额再度被哄抢，座位远远供不应求！最终有超过200名Spark爱好者参加了此次Spark Meetup！这对准备茶歇的同事也是一个挑战，他们不得不到周边超市进行紧急采购，补齐所有与会人员的餐点。

 

200多名参会嘉宾来自华东各地的知名公司、高校和组织机构。其中包括eBay，cloudera，Agoda，百度，唯品会，爱奇艺，新浪，饿了么，IBM，爱立信，中科院，中国电信，中国联通，盛大，大众点评，惠普，华为，亚信，蘑菇街，理财机构，软通动力，Delphi CTC，marinsoftware，NWAP，bocom，lufax，上海仁维，GBI，lewa 等30几家公司。还有不少来自同济，交大，浙大，浙江理工，华中科大，东南大学，上海理工，哈工大的学生，我们惊喜地发现：在学生群体里，接触Spark的人也很多！

![](../Images/7ee84d35373fe304611431aa7c1e46fb.png)

![](../Images/bfc8430631a60a2c84cb40d3ce7dda3d.png)

 

作为Spark上海区Meetup的组织者之一，Intel亚太研发有限公司技术总监段建刚和Grace团队一起来到了现场。Grace首先介绍了Spark Meetup的情况，并邀请更多的小伙伴加入到Spark社区，并预祝本次Spark Meetup圆满举办。Grace还带来了为本次Spark Meetup定制的T恤。

 

![](../Images/e7359aa1601904c2493bcd8a6a322b3e.png)

作为本次Spark Meetup的主办方，携程技术运营中心大数据平台高级经理李亚峰做了开场演讲，开启了本次Spark Meetup的技术盛宴。李亚峰首先介绍了大数据平台在携程的使用情况，也讲到大数据平台在携程的应用，以及携程大数据平台是如何保证整个技术中心10X增速的设想。作为中国第一的在线旅游供应商，携程不断在技术上进行投资。业务的持续增长需要源源不断的技术支撑。技术研发中心就像一台巨大的发动机，孜孜不倦地提供创新的资源。大数据平台每天处理20T的增量数据，2w+MapReduce job，上亿的HBase实时数据请求，并通过数据挖掘、机器学习技术，挖掘海量数据背后的价值。此外，李亚峰介绍了大数据平台定制化的HUE组件，HBase自动化运维工具，并重点介绍了Spark在携程大数据平台的使用情况，阶段性成就以及未来的发展计划。最后，李亚峰也代表携程大数据团队向有志之士们发出邀请。

 

![](../Images/6a7328d0ade7a41ec7ffc2e580d34275.png)

随后，四位演讲嘉宾为我们带来了精彩绝伦的演讲。

 

来自携程大数据团队的刘钰帆做了《Spark Core源码解读及扩展》的分享，主要介绍了Spark Core的架构，并且重点陈述了Spark Core的四个核心组件，最后以Spark Streaming为例，介绍了Spark Core 的扩展。刘钰帆用浅显易懂的动画解释了Spark Core源码的运行原理，其中用数可乐的例子解释Spark的Aggregator，更是让Intel团队的Grace吃了一惊。Grace评价到，“用数可乐代替WordCount，有创意；用动画解释源码运行原理，很聪明”。刘钰帆同学是一名“90后”，13年毕业加入携程，现已成长为可以运维携程Spark平台的技术工程师，同时负责HBase集群以及其他运维相关的工作，他的快速成长和携程的工程师文化氛围是分不开的。

 

![](../Images/204e20d7e4baab11c3ebec7fe90bd091.png)

 

接着，来自淘宝的余根茂做了《SparkStreaming 场景下两类倾斜问题的研究》的分享。余根茂分享了Spark在淘宝的实践，讲到了不同场境下，Spark streaming的性能会表现出CPU倾斜和数据倾斜两种情况。CPU倾斜和数据倾斜会影响整个集群的计算性能。余根茂在演讲中，讲述了整个问题的产生背景，以及相应的处理方法。这是生产中的实际使用经验，可以在以后的使用中引以为戒，避免类似的问题。很多同学也在会后同余根茂进行了深入的交流。

 

![](../Images/e9cefb9cedab1e2a4b44c3935be51577.png)

 

在茶歇时间，小编遇到了eBay麒麟项目的co-founder 韩卿（luke han）。麒麟是中国第一个被接入Apache孵化器的开源项目，他的出现，再一次印证了Spark Meetup的影响力！茶歇还有发礼物环节，不仅有Intel为本次Spark Meetp准备的50件T恤，还有携程准备的精美礼品。

![](../Images/3e76359f255081c29b427296b02b9830.png)

![](../Images/ebaf7a3b496a8227e973f632c7aca2fc.png)

茶歇过后，是Paypal同事戴云晶的演讲——《基于SPARKHBASE的数据平台实践》，他的演讲围绕着Paypal的大数据系统展开，讲到了Paypal对Spark的定制化开发。Spark是一个通用的系统，的确需要很多定制化开发才能接入公司现有的系统。这方面，携程也做了许多工作。

 

![](../Images/989200ab33ffeb8cee635ba2b4a87b09.png)

![](../Images/49691591d4209fa287330fb56fc7ea6d.png)

会议的最后，是来自英特尔的邵赛赛的演讲《SQL on Spark Streaming》。赛赛是Spark的源码贡献者，有着2年多的Spark开发经验，在Spark社群人气很高。他的演讲，主要介绍了Intel正在开发的一个项目——在SparkStreaming上定义SQL。这是一个非常新颖的概念，因为streaming是不间断的数据，如果不间断，那么SQL的操作将如何定义数据集并返回结果？赛赛解答了这个问题，并且进一步讲了Spark SQL on Streaming 领域特定语言的一些设计思路以及设计中遇到的问题，以及Intel团队在这方面的开发进度与后续的开发计划。随后的Q&A环节发问异常热烈，这可是难得的面对面源码贡献者的机会！

Spark作为平台的优势如今已十分明显，Spark平台上的来第三方工具也越来越多。作为国内比较早使用Spark的公司，携程不断同业界保持对话，并且积极参与社区分享。作为大中华区最大的Spark开发团队，Intel的Grace团队不断向社区贡献源码，积极响应社区与国内开发者的需求。此次携程主办Intel合办的Spark Meetup，不仅展示了携程在Spark技术上的阶段性成就，也表明了携程对业界的开放态度，以及对未来Spark社区发展的信心。相信在2015年，Spark能够被运用在携程的更多业务线中。让技术拥抱未来，让10倍增速无后顾之忧。
