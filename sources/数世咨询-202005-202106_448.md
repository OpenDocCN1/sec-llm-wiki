# “谷歌分析”成攻击者窃取支付信息的跳板

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzkxNzA3MTgyNg==&mid=2247484571&idx=1&sn=88a8c3b71c5a9e46a029d1c66f5e5fc2&chksm=c1477626f630ff30e7513b61544298956008b7906720dfeb2876412531173e7160d68e0528c5&scene=126&sessionid=1681323460#rd](http://mp.weixin.qq.com/s?__biz=MzkxNzA3MTgyNg==&mid=2247484571&idx=1&sn=88a8c3b71c5a9e46a029d1c66f5e5fc2&chksm=c1477626f630ff30e7513b61544298956008b7906720dfeb2876412531173e7160d68e0528c5&scene=126&sessionid=1681323460#rd)

研究者近日发现，黑客们正在利用谷歌分析的服务，隐匿地从被病毒感染的电商网站上过滤出信用卡信息。根据PerimeterX、卡巴斯基和Sansec三家机构各自的独立报告，攻击者将数据窃取代码注入到被攻击网站，同时加上他们自身账号在谷歌分析生成的追踪代码，从而在网站的站点安全策略在最高级的情况下，依然能过滤出用户输入的支付信息。卡巴斯基的报告中提到：“攻击者将恶意代码注入站点，收集所有用户输入的数据并通过谷歌分析进行传送。最终，攻击者可以通过他们的谷歌分析账户获得被窃取的数据。”卡巴斯基表示，他们已经在欧洲、南美、北美发现了超过20家受影响网站，销售领域涉及数字设备、化妆品、食品和零配件。**绕过内容安全策略**该攻击利用了许多电商网站使用谷歌的网站分析服务追踪访客情况，从而这些网站会将相关域名放入他们的内容安全策略（content security policy, CSP）白名单中。![](../Images/e86f162cdef198750ab462d06eca401b.png)CSP是一个附加的安全手段，用于检测和环节跨站点脚本攻击的威胁以及其他代码注入攻击。该安全功能允许网站管理员定义一系列能通过网站浏览器和特定URL进行交互的域名，从而防止执行不被信任的代码。![](../Images/1d50350a52734e35021d23901b4e4b28.png)“这个攻击的源头在于CSP规则系统的颗粒状不够。”PerimeterX的研究VP，Amir Shaked如此说到，“识别并阻止这类恶意JavaScript的请求，需要高级可视化解决方案，从而检测到敏感信息的接入以及外漏。”攻击者想通过这种方式获得数据，只需要一小片JavaScript代码，收集凭证信息和支付信息，以及一些谷歌分析用于识别站点上不同行为的参数。一般而言，管理员会将“\*.google-analytics.com”写入CSP中，允许来自google-analytics.com所有相关站点的服务收集数据。同时，卡巴斯基表示，该攻击不需要从外部资源下载新的代码就可以完成攻击。如果要让攻击更隐秘，攻击者需要确定来访者浏览器上的开发者模式是否被启用，然后只在检查结果是“否”的情况下实施攻击。**三月开始的“新型”攻击**而在另一份荷兰公司Sansec的报告中，显示自3月17日开始，有一种类似的攻击，使用在谷歌Firebase上运行的JavaScript代码，对数个电商进行攻击。攻击者创建了一个临时的iFrame用于载入攻击者控制的谷歌分析账号，从而增加隐秘性。在支付表格中输入的信用卡信息会被加密，然后发送到账号的控制台处并进行解密，在这些大规模利用谷歌分析的攻击中，CSP之类的防御手段在攻击者通过事先被开白名单的域名截取敏感信息中，毫无办法。![](../Images/fba3f662eff73847a1c7db8cd8893b96.png)Shaked表示，一种可行的解决方法是使用适应性URL，将ID作为URL的一部分，或者限制子域名（比如不使用“\*”）加强CSP规则，限制数据流出到其他账户上。而另一种颗粒化的解决方案，是加强CSP能力，将XHR代理作为CSP标准的一部分：这么做可以在客户端建立起一个WAF能力，从而限制哪些区域的数据是可以被传输的。不过从顾客角度来看，基本没什么能进行防御的方式。在线上购物的时候启用开发者模式，会有一些帮助。剩下的，就需要时刻注意自己是否有未经许可的购物行为或者身份窃取迹象。*关键词：网站安全；*
