# 32种针对硬件与固件的攻击

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzkxNzA3MTgyNg==&mid=2247484578&idx=1&sn=e3224eefefd45cf0bebf91fe21ab7d5b&chksm=c147761ff630ff094a27f3a7b24bf5465c3e518d6bef349a0e63e726aa51049dfb4158f671fd&scene=126&sessionid=1681323460#rd](http://mp.weixin.qq.com/s?__biz=MzkxNzA3MTgyNg==&mid=2247484578&idx=1&sn=e3224eefefd45cf0bebf91fe21ab7d5b&chksm=c147761ff630ff094a27f3a7b24bf5465c3e518d6bef349a0e63e726aa51049dfb4158f671fd&scene=126&sessionid=1681323460#rd)

![](../Images/3106dc8f9938866cdf79ac4029b690b2.png)2018年1月，全球计算机行业因为Meltdown以及Spectre这两个在处理器中存在的新型漏洞而受到威胁。这两个漏洞直接打破了分离内核以及用户内存的OS安全边界。这两个漏洞基于了现代CPU的预测执行功能，而缓解这两个漏洞带来的影响则需要有史以来最大的补丁计划，范围涉及CPU制造商、设备制造商以及操作系统供应商。Meltdown和Spectre绝不是最早的硬件漏洞，但它们确实引起安全研究者开始注意这种类型的漏洞。从那时开始，许多学术界与私人领域的研究者，都开始研究CPU以及其他硬件组件的低阶运行情况，以发现更多的问题。一些硬件漏洞只能通过发布新一代的组件进行修复，而有一些能通过固件修复。这两种方法都并非是直接进行补丁，因此硬件漏洞会在被发现后的很长一段时间里产生影响。以下是一些需要注意的硬件相关漏洞，有在Meltdown之前被发现的，也有之后被发现的：**CPU侧的边信道攻击****Spectre变种1：CVE-2017-5753**CVE-2017-5753又以绕过边际检查被熟知，攻击可以通过该漏洞对现代CPU的分支预测功能进行利用，以CPU缓存为边信道，从其他处理器的内存中获取信息。该漏洞不仅能能让攻击者从一个处理器中获取其他处理器内存中的敏感信息，还可以绕过用户和内核之间的特权边界。该漏洞影响了英特尔、IBM、以及部分ARM的CPU。**Spectre变种2：CVE-2017-5715**Spectre变种2和变种1有同样的影响，但是利用的技术不同。变种2通过分支目标注入进行。变种2的减缓方式需要升级受影响的CPU微代码：一种方式是通过BIOS/UEFI升级，另一种方式是让操作系统每次重启的时候进行修复。**Meltdown变种3：CVE-2017-5754**CVE-2017-5754也被称为恶意数据缓存加载（Rogue Data Cache Load, RDCL）或者CPU预测执行漏洞变种3。Meltdown利用了现代英特尔CPU的乱序执行能力，该能力允许用户进程越过安全边界读取受保护的内核记忆。该漏洞的修复只需要升级操作系统，并且执行更严格的内核隔离策略即可。**Meltdown-GP：CVE-2018-3640**Meltdown的另一个变种，又称变种3a。该变种利用预测读取系统注册表达成边信道信息泄露。因为这个原因，它也被称为系统寄存器恶意读取（Rogue System Register Read, RSRE）。解决该漏洞需要微代码升级。**Meltdown-NM：CVE-2018-3665**该漏洞是与Meltdown相关的预测执行漏洞，也被称为LazyFP，能被用于泄露浮点单元的状态。浮点单元状态存有密码运行过程中的敏感信息。该漏洞能通过在操作系统层面加强浮点单元的运算内容交换进行缓解。**Spectre-NG：CVE-2018-3639**该漏洞也被称为Spectre变种4，或者预测存储绕过（Speculative Store Bypass, SSB）。该Spectre变种可以导致在内存写入地址确定前进行内存读取，从而泄露跨进程信息。缓解手段同时需要微代码以及操作系统升级。**Spectre-PHT：CVE-2018-3693**该Spectre变种又称为Spectre1.1，通过预测存储形成预测缓冲区溢出。利用该漏洞能绕过一些上述提到的对Spectre系列的缓解手段，修复该漏洞需要升级操作系统。**Spectre-RW**该变种又被称为Spectre 1.2，通过预测存储覆写只读数据和代码指针。该变种能被利用对软件沙盒进行攻击。缓解方式需要升级操作系统。**Foreshadow-OS：CVE-2018-3620**该漏洞又被称为L1 Terrmial Fault。Foreshadow是针对英特尔CPU的预测执行攻击漏洞，可以从处理器的L1数据存储中提取信息。由于虚拟化的CPU用同一个L1存储，该漏洞对虚拟机影响巨大。攻击者可以利用这个漏洞从操作系统（system manage mode, SMM）或者系统管理模式中提取信息。**Foreshadow-VMM：CVE-2018-3646**该Foreshadow变种能让虚拟机中的访客操作系统有可能读取其他访客虚拟机中的敏感内存信息，或者进行自我监视。**Foreshadow-SGX：CVE-2018-3615**该Foreshadow变种能让攻击者读取英特尔SGX中的内存数据。SGX原本是英特尔CPU中的可信执行环境，让开发者即使在操作系统沦陷后，能够安全存储并执行代码。**Meltdown-PK与Meldown-BND**这两个Meltdown的变种在2018年11月在一次更大规模的攻击中被研究人员发现。Meltdown-PK影响了英特尔的CPU，而Meltdown-BND影响了英特尔和AMD。**Spectre-PHT-CA-OP、Spectre-PHT-CA-IP、和Spectre-PHT-SA-OP**这三个Spectre的变种利用了CPU的模式历史表功能。它们和Meltdown-PK以及Meltdown-BND在同一时间被同一个团队披露。**Spectre-BTB-SA-IP以及Spectre-BTB-SA-OP**这两个Spectre的变种利用了分支目标缓冲。它们于2018年11月被发现Meltdown-PK与Meltdown-BND的团队披露。该团队同时表示：“大部分防御手段，包括那些已经部署了的手段，都无法完全防御住所有变种。”**Fallout：CVE-2018-12126**Fallout也被成为微架构存储缓冲数据采样（microarchitectural store buffer data sampling, MSBDS）。该漏洞的影响与Meltdown类似，都能越过安全边界，从受保护的记忆存储区域泄露敏感信息。这是针对英特尔的微架构数据采样（microarchitectural data sampling, MDS）CPU产生的新一类边信道攻击。该漏洞同时影响操作系统以及监视器，缓解手段需要CPU微代码升级。**RIDL：CVE-2018-12127以及CVE-2018-12130**两个针对MDS中微架构负载数据端口采样（microarchitectural load port data sampling, MLPDS）以及微架构填充缓冲区数据采样（microarchitectural fill buffer data sampling, MFBDS）进行攻击。和Fallout一样，缓解手段需要CPU微代码升级。**Zombieload：CVE-2019-11091**MDS攻击的第四种变体，又被称为微架构数据采样无缓冲内存（microarchitectural data sampling uncacheable memory, MDSUM）。和Fallout以及RIDL一样，该漏洞也会泄露内核以及监视层内存中的敏感数据。**Starbleed**Starbleed是在由Xilinx制造的现场可编程门阵列（field-programmable gate arrays, FPGAs）中比特流加密进程中存在的设计问题。和CPU预先设计好服务于大部分计算目的方式不同，FPGA是完全由顾客进行逻辑编程的集成电路。FPGA往往被设置成执行某种特定任务，从而比使用目的广泛的CPU效率更高。FPGA被广泛应用于任务为核心，或者安全为核心的领域，比如航天、金融与军队中。由客户载入到FPGA的配置文件被称为比特流，而像Xilinx这些制造商加入了加密以及比特流验证机制，从而让客户能够保护自己的知识产权，以及其他他们FPGA中可能存在的秘密。德国的一个研究团队发现在Xilinx7系列与 Virtex-6的FPGA中的比特流安全机制存在设计缺陷，会被攻击者利用解密比特流并进行修改。要实现Starbleed攻击，攻击者需要先接入FPGA的硬件配置界面，这就代表了攻击者能够从物理上接触到设备。然而，部分FPGA通过分离的微控制器进行编写以及再编写，从而代表了它们会被连到网上。在这个情况下，攻击者可以远程进行攻击。该设计缺陷由于存在于硅片中，因此无法通过补丁修复，只能在后一代的Xilinx芯片中被纠正。该公司已经在相关论文被发布前被通知这个漏洞，并且已经向客户发出了建议，**针对DRAM记忆的Rowhammer攻击****Rowhammer**Rowhammer是一种物理变化，但是却会影响安全性，该变化在SDRAM芯片中发生，当同一物理排的内存单元被连续极多次读取的时候，会导致该单元的电子泄露到临近排中，改变这些排中单元的数值。这种情况被称为比特翻转，产生原因可能是因为现代SDRAM，尤其是DDR3和DDR4中增多的单元密度。尽管Rowhammer的影响已经被公布了很久，谷歌Project Zero团队的成员却是第一个在2015年证明该问题有安全隐患，并且发布了基于该漏洞的两个特权提升攻击。**Rowhammer.js**Rowhammer.js是通过JavaScript进行的Rowhammer攻击，从而证明了该攻击可以通过一个恶意网站页面，用浏览器远程进行。浏览器厂商已经针对该攻击采取了缓解措施。**Drammer：CVE-2016-6728**Drammer是在2016年出现的针对安卓设备的Rowhammer类型攻击。在那之前，移动设备中的内存芯片都被认为不受Rowhammer影响。**Flip Feng Shui**该Rowhammer类型攻击针对虚拟机，通过一个恶意访客虚拟机翻转物理内存，从而影响另一台虚拟机。研究者通过破解目标虚拟机的OpenSSH公钥认证演示了这种攻击。**ECCploit**ECCploit攻击显示了Rowhammer类型的攻击甚至可以绕过纠错码（error-correcting code, ECC）对SDRAM芯片进行攻击。该类型内存被用于服务器，曾一度被认为不受Rowhammer影响。**Throwhammer**Throwhammer是Rowhammer的另一种变体，在网络上通过远程直接数据存取（remote direct memory access，RDMA）进行攻击。**RAMBleed**RAMBleed是第一个不仅能改变内存单元数据，更能进行窃取的Rowhammer变体。早先的Rowhammer攻击通过比特翻转攻击内存完整性，从而造成提权和其他状况。然而，RAMBleed通过该漏洞以及一个边信道，从而最终从邻近的内存单元中提取信息。从这个角度上来看，它的影响和Meltdown以及Spectre相似。**其他影响深远的固件漏洞****BlueBorne**BlueBorn是一系列于2017年被披露的蓝牙漏洞，影响了包括Linux、安卓、Windows和macOS在内的系统。据估计，其影响设备超过50亿。对于计算机而言，可以简单通过操作系统升级就可以修复；带有蓝牙功能的智能手表、电视机、医疗设备、车载娱乐系统、可穿戴设备和其他物联网设备则需要固件升级。研究人员估计在2018年，依然有超过20亿设备存在该漏洞。**KRACK**KRACK又被称为密钥重装攻击，于2016年被披露，通过利用WPA2的一个漏洞进行攻击。由于该漏洞存在于标准本身，所有基于WP2的设备都受到影响。修复需要固件升级，因此时至今日，依然有大量设备无法被修复。**BadUSB**该攻击于2014年被展现，通过重编写随插随用USB设备中的微控制器从而模仿诸如键盘之类的其他设备，并且利用这些USB控制计算机或者窃取数据。现在依然有许多随插随用USB设备受到影响。**Thunderstrike与Thunderstrike 2**这两个攻击利用苹果Macbook固件中存在的漏洞，在恶意设备连接到雷电接口的时候安装固件恶意软件。Thunderstrike 2还可以攻击新连接的雷点接口设备，产生蠕虫病毒的效果。**Thunderclap**今年新发现的基于雷点端口的攻击，可以在相关设备上执行特权代码。**ROCA**ROCA攻击针对由Infineon Technologies制造的可信平台模组（Trusted Platform Modules，TPMs）以及安全元素（Secure Elements，SEs）。这些TPM与SE被用于上亿商业电脑、服务器、硬件认证通证，以及包括国家身份证在内的多种智能卡。该漏洞导致由这些组件生成的RSA密钥更容易被因数分解。研究者估计复原单个由这些设备生成的2048位RSA密钥大约要花费20,000美元，而1024位密钥大约在40美元。**英特尔管理引擎 **英特尔管理引擎（Intel Management Engine, ME）是一个在许多英特尔CPU中专门的协处理器以及子系统，用于传输层协议使用带外数据管理任务。Intel ME在自己的轻量操作系统上运行，和用户安装的操作系统完全隔开，因此经常被安全社群认为是一个后门。过去几年中经常有严重的漏洞在Intel ME中被发现，而修复这些漏洞需要从计算机制造商处安装固件升级。这意味着许多时间久远，不再得到支持的系统很可能无法获得这些升级。*关键词：物理安全；边信道；*
