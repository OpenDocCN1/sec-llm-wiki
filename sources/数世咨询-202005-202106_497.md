# 什么是配置飘移？

企业里部署的系统都应该配置恰当的安全策略，同时还要对这些策略进行持续的监测。因为随着时间的变化，出于业务变动或是系统升级等原因，配置策略是在不断变化的。这种变化称之为“配置飘移”(Configuration Drift)。配置飘移往往会给企业带来巨大的安全风险。话虽这样说，但所有的运维人员都面临同一个问题，配置策略不易，维护策略更难。下面是配置飘移的几个场景案例：**第一个案例：新开端口**在业务软件上实现一个新的功能，经常需要新开一个通信端口。这时业务部门或IT人员直接在服务器和防火墙上打开端口，以使新功能能够正常运行。如果安全人员对这些操作一无所知，等到了安全审计的时候，审计人员就会置疑这个端口的打开原因，打开时间，以及为什么没有被安全策略允许的记录等，而安全人员则会花费大量的时间去回溯。事情过去的时间越长，追溯起来就会越费力。**第二个案例：权限提升**应用开发人员往往需要反复登入某个服务器，而这个时候检查凭证就会相当耗时——尤其在交付日期临近的时候。如果开发人员有管理员凭证，就可能会把“用户”分组添加到多个权限类别中。毕竟，这些权限并不是覆盖全域名的，只是某个服务器而已——这似乎看上去不是什么大事。但事实上，即使像这样对某个服务器的改动，也会对组织带来巨大风险。用户在进行改动的时候可能是在改动控制之下的，但是如果无法对用户具体改动的内容进行认证，安全团队在人工审计前就对这些改动无从得知。**第三个案例：云端存储**由于之前发生的大量数据泄露事件，亚马逊升级了它的存储接入策略。所有新的存储空间会默认阻断所有公开接入行为。保持这个默认设置意味着：

*   新添加的存储空间或者对象将默认是私有的，所有对现有存储空间和对象的新公开ACL会被限制 。
    
*   所有允许公开接入存储空间和对象的ACL会被无视。
    
*   所有公共或者跨账号进行接入存储空间或者接入点时，即使有允许接入的策略，依然会被阻断。
    

这是一个非常安全的措施，但是会影响IT运维，因此阻断设置可能会被关闭。这可能会在存储空间创建的时候就被关闭，或者管理员之后手动关闭——然后忘得一干二净。

安全配置和最佳实践始终存在，甚至可能被初始化设置了。但从安全层面来看，时刻监控是否存在配置飘移同样重要。三种主要维护系统配置的方式一般而言，维护系统配置的方式有三种；组织根据自身安全管理能力成熟度会进行不同的选择。第一种方式时候手动监控系统配置。这种方式相当耗时，因此无法频繁完成。系统往往在被检测到受到攻击或者进行升级前，都不会进行检查。部分系统可能会因为审计需求而进行审计。一般这种模式下，组织会尽力减少审计包含的系统数量。一个审计员往往会要求在有限的环境里，查看一部分设备来验证合规性。除非被检查到的部分发现了不合规情况，否则不会有进一步的措施，![](../Images/66e13a357fac52afa0372e5f5a0a6a6b.png) Figure A   
第二种方式是使用扫描。相比第一种方式而言，扫描不会有太多耗时或者冗长的问题，但依然需要一定程度的交互：包括为扫描工具创建管理员凭证、对扫描进行时间规划并实行、根据结果采取措施等等。一般这些事情每个月或者每个季度，赶在审计前进行一次。这种方式依然是对合规范围内的系统进行。非合规区域的系统仍然会被遗留，只在问题发生或者需要升级的时候进行检查。CIS关键安全控制中建议所有系统都应该进行安全配置，因此所有系统中的任何配置都应该在发生变化时被监控。![](../Images/18aad2124f58d495690782c779639e35.png) Figure B 第三种方式是最成熟的，将所有系统系统几乎以实时的方式进行监控。这种方式需要系统被一个轻量化的探针进行监控，同时探针不需要任何凭证进行登录，也不需要开启OS审计选项。探针要在所有系统中被部署，可以通过内嵌在镜像中，或者集成在其他自动化工具中。只要探针被开启，当发生不合规的变化时，修复流程就能被启动：可以自动化形成事故单、发送邮件、或者通过SIEM工具对SOC进行告警。![](../Images/9756d81b1600f0f1cf77c07c0c0985e5.png) Figure C   
CIS也对如何评估监控的有效性进行了推荐：

1.  业务系统中有多少比例的系统当下没有按照组织通过的配置标准进行安全配置？
    
2.  业务系统中有多少比例的系统没有受到组织技术配置管理应用的强制管理？
    
3.  业务系统中有多少比例的系统没有最新的操作系统软件安全补丁？
    
4.  业务系统中有多少比例的系统没有最新的商业软件安全补丁？
    
5.  业务系统中有多少比例的系统没有被文件完整性评估软件保护？
    
6.  有多少比例的未授权或者未记录的改动会引发安全问题？
    

在这些指标确立后，基于持续化改善流程，安全团队和业务团队就应该合作提高被监控系统的比例，并当配置飘移发生时进行修复。将配置飘移压在一个最低档能有效地确保业务系统的安全状态，从而直接改善组织的安全态势。
