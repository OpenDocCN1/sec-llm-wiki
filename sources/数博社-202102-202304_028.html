API 不安全每年造成数十亿美元的损失

Imperva, Inc. 的一项新研究揭示了易受攻击或不安全的 API 的全球成本不断上升。根据 Imperva 的数据，对近 117,000 起网络安全事件的分析估计，API 不安全每年会导致 41-750 亿美元的损失。


由 Marsh McLennan 网络风险分析中心进行的 量化 API 不安全成本 研究发现，在统计上，较大的组织更有可能发生更高比例的 API 相关事件。事实上，收入至少为 1000 亿美元的企业遇到 API 不安全的可能性是中小型企业的 3-4 倍。数据表明，随着这些成熟的组织加速数字化转型，大公司特别容易受到与暴露或未受保护的 API 相关的安全风险的影响。 


API 是无形的结缔组织，使应用程序能够共享数据以改善最终用户体验和结果。企业使用的 API 数量正在快速增长；近一半的企业在 内部或公开部署了 50-500个，而有些企业拥有超过一千个活动 API。 


许多 API 直接连接到存储敏感数据的后端数据库。因此，黑客越来越多地将 API 作为通往底层基础设施的途径，以窃取敏感信息。如今，每 13 起网络事件中就有多达 1 起可归因于 API 不安全。随着生产中的 API 数量成倍增加，预计这一数字将在未来几年增长。 


该研究还发现了行业之间的巨大差异。IT、专业服务和零售最有可能遭受与 API 相关的安全事件：

在国家层面，所有报告的 API 相关事件中有 57% 发生在美国，是下一个国家英国的 9 倍多。鉴于美国企业在数字化方面更加成熟，许多企业依赖于复杂的软件供应链和广泛的 API 生态系统。这两个因素都增加了 API 相关安全事件的可能性。 


提高 API 安全性的建议：

  • 识别和分类流经每个 API 的数据：可见性对于理解每个 API 的完整架构以及识别和分类流经它的数据以便评估风险至关重要。 

  • 自动发现：API 的生成速度快且经常修改，这使它们成为许多组织的盲点。通过自动化，组织可以消除流氓或影子 API。此外，通过自动化 API 清单，安全团队将了解开发人员何时在生产中修改 API。

  • 启用 API 治理：API 治理模型对于高度监管行业的组织至关重要。这只有在可见性超出 API 端点并进入底层有效负载的情况下才有可能，因此可以充分保护敏感数据。
