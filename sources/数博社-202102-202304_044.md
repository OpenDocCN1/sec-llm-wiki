# NIST 更新软件供应链风险管理指南

'一个可以带你从爬行到走路到跑步的综合工具'

![](../Images/69e640d198268a328ec01a79918215c5.png)

  

Infosec 专家对美国国家标准与技术研究院 (NIST) 对其网络安全供应链风险管理指南 (C-SCRM) 的全面改革表示欢迎。

为响应拜登总统于 2021 年 5 月签署的一项行政命令，修订后的 C-SCRM 文件为识别、评估和解决整个供应链中的网络安全风险提供了建议。

该出版物——“系统和组织的网络安全供应链风险管理实践”(PDF)——敦促硬件、软件和数字服务的收购方和最终用户对数字产品组件的来源和安全性进行尽职调查。

“如果您的机构或组织尚未开始使用 \[C-SCRM\]，这是一个全面的工具，可以带您从爬行到步行到跑步，并且可以帮助您立即这样做，”NIST 的联合创始人 Jon Boyens 说该出版物的作者，在新闻稿。

### '基础最佳实践'

攻击者越来越多地瞄准数字供应链，因为他们可以通过毒化或利用广泛使用的组件中的弱点来危害多个设备、应用程序或组织，其中 2020 SolarWinds 攻击是迄今为止最具破坏性的例子。

软件供应链安全专家 Sonatype 的现场首席技术官 Ilkka Turunen 告诉The Daily Swig：“随着下一代供应链攻击的增加，C-SCRM 指南正式确定了大大小小的组织中的许多已知做法。

“它描述了基本的最佳实践——如生成 SBOM \[软件材料清单\]——以及维持有效供应链安全实践所需的持续活动。

他继续说：“这个知识纲要传授了如何防御未来的 log4Shell 问题和其他下一代威胁。现在是组织投资自动化这些流程的时候了。”

Synopsys 网络安全研究中心的首席安全策略师 Tim Mackey 表示，该文件涵盖的远不止 SBOM 对开源组件的价值。

“软件从多个来源进入组织，包括开源和API使用，”他告诉The Daily Swig。

“软件运营商，无论该软件本质上是纯粹的开源软件还是专有开发的结果，都有效地接受了与使用该软件相关的商业风险。

“降低软件风险首先要了解组织如何使用托管和非托管软件，并逐步降低这些风险——不仅在供应商层面，而且随着每个新软件版本和变化的持续进行。”

### 持续存在的问题

API 安全专家 Cequence Security 最近对关键的 Log4Shell 漏洞的持续存在敲响了警钟，该漏洞是六个月前在几乎无处不在的日志记录实用程序 Apache Log4j中发现的。

Cequence Security 的常驻黑客 Jason Kent 说，该问题被该公司称为“LoNg4j”，“说明了现代企业 IT 基础设施是如何相互连接的，以及这个数字供应链如何远远超出已知的应用程序”。

修改后的 NIST 指南目前仅以 PDF 文档的形式提供，但作者表示，他们还打算发布一个更加用户友好、可点击的 Web 版本以及针对 C-SCRM 新手的组织的快速入门指南。
