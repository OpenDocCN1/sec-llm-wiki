API 攻击在过去 12 个月中增加了 681%

原文：http://mp.weixin.qq.com/s?__biz=MzkyMDIxMjU2MA==&mid=2247487241&idx=1&sn=6fbbafd880ea21d49f70c7f777467da3&chksm=c1970a36f6e08320a8e72b88de49d4e97b32dbe166bd2b70d56d4121bbc29f4ad19f25b02395&scene=126&sessionid=1681312615#rd

Salt Security发布了Salt Labs 2022年第一季度API安全状况报告。这份半年度报告发现，95%的受访组织在过去12个月内经历过API安全事件。研究表明，34%的受访者（他们都在运行生产API）缺乏任何类型的API安全策略。这种缺乏防御给企业带来了巨大的商业风险，其形式是业务创新放缓、消费者信心受损以及现代化工作中断。

API 安全状况报告取材于 Salt SaaS 云平台的调查响应和经验数据的组合。被其平台阻止的针对 Salt 客户的尝试攻击急剧增长 - 恶意 API 流量增加了 681%，而整体 API 流量增加了 321%。可以理解的是，62%的受访者承认，由于API安全问题，新应用程序的推出速度放慢了。

 “为了在今天蓬勃发展，每家公司都必须是一家软件公司，而API是其应用程序创新的核心。数字企业已成为我们现代经济的领导者，同时，它们已成为不良行为者的主要目标，“Salt Security联合创始人兼首席执行官Roey Eliyahu说。“我们看到API攻击逐年显着加速。更令人担忧的是，API使用和攻击的增长速度继续超过企业的准备和防御速度。组织必须投入时间和精力来了解 API 攻击形势以及保护其最重要资产所需的关键功能。

由于几乎每个受访者（95%）都在其生产API中发现了API安全事件，因此迫切需要设计一个强大的API安全策略。Salt客户的攻击频率也越来越高，12%的客户平均每月遭受500多次攻击。 

“API提供了一个有吸引力的攻击媒介，尽管组织在将API发布到生产环境之前尽最大努力验证API，”Salt Security技术布道者Michael Isbitski说。“鉴于传统的安全和API管理平台无法抵御针对API独特业务逻辑的复杂攻击，因此攻击者继续取得成功，使企业面临风险也就不足为奇了。 

安全问题在 API 策略方面的担忧中名列前茅，占 40%

调查受访者对公司的API程序有各种担忧，40%的受访者认为安全性是他们的主要担忧。在生产前安全方面的投资不足占据了首位，为22%，另有18%的受访者担心该计划没有充分解决运行时或生产安全问题。在充实需求和文档方面的投资不足是19%的受访者的主要担忧。 

大多数企业对 API 攻击毫无准备

高度宣传的安全事件和安全专业人员要求实施API安全保护，但不足以推动大多数组织采用有效的API安全策略。在调查受访者中，34%的人没有制定战略，略多于四分之一（27%）的人只有基本战略。只有11%的公司拥有包括专用API测试和保护在内的高级策略。 

调查结果还支持这样一种观点，即预算和技能差距是缺乏准备的原因之一。缺乏专业知识或资源（35%）和预算限制（20%）是实施最佳API安全策略的最大障碍。 

过度依赖“左移”实践继续使企业失望

由于运行时保护是有效 API 保护的基础，并且 95% 的受访者在去年经历过 API 安全事件，因此 API 安全性的“左移”策略被证明是不够的。随着 IT 团队继续在 API 安全性的“所有权”上存在分歧，这个问题被放大了。超过一半的受访者表示，主要责任在于开发人员，DevOps或DevSecOps。只有31%的受访者将API安全的责任交给AppSec或InfoSec团队。 

WAF 和 API 网关继续错过 API 攻击

对传统安全和 API 管理工具（如 Web 应用程序防火墙 （WAF） 和 API 网关）的依赖使许多组织产生了虚假的安全感。去年，95% 的受访者经历过 API 安全事件，55% 的受访者依赖来自网关的警报，37% 的受访者使用 WAF 来识别攻击者，这一事实表明了能力上的差距。依赖日志文件分析（45%）来确保API安全性同样是无效的 - 当日志文件被解析时，攻击者早已失去了他们想要的有价值的数据和有效载荷。 

阻止 API 攻击仍然是 API 安全平台的首要标准

连续第三次，越来越多的受访者（42%）认为阻止API攻击是他们在API安全平台中寻求的最重要功能。确定哪些 API 公开个人身份信息 （PII） 和敏感数据紧随其后 （41%）。随着时间的推移，强化API的能力排在第三位（38%），满足合规性或法规要求排在第四位（36%）。

API 安全状态报告中的其他发现：

  • “僵尸”或过时API的风险是API安全问题的首要问题，43%的受访者认为这是他们最担心的问题。客户接管排在第二位，22%的人将这种风险视为他们最关心的问题。

  • API更改呈上升趋势 - 9%的受访者每天更新API，31%的受访者每周更新一次，24%的受访者每月更新一次。

  • Salt 客户群中 94% 的攻击都是针对经过身份验证的 API 进行的。

  • 86%的受访者缺乏信心，不知道哪些API暴露了敏感数据。

  • 85%的受访者指出，他们目前的工具在阻止API攻击方面无效。

  • 83%的受访者对其API库存缺乏充分的信心。 

API 安全性正在改善安全团队的工作方式

尽管组织在谁应该对API安全负责的看法上存在很大差异，但安全和DevOps团队之间的协作和共享输入正在增加。超过三分之一的受访者（34%）表示，由于解决了API安全问题，安全团队与DevOps的合作更多，另有30%的受访者表示DevOps寻求安全团队的意见来制定API指南。另有25%的组织正在将安全工程师嵌入到DevOps团队中以应对挑战。调查还发现，越来越多的安全团队正在强调OWASP API前10大威胁列表 - 本报告中的61%与六个月前的50%相比，这是改善整个组织API安全实践的积极变化。 

《2022 年第 1 季度 API 安全现状报告》由 Salt Security 研究部门 Salt Labs 的研究人员编制，利用来自 250 多名安全、应用和 DevOps 高管和专业人员的调查数据，以及通过 Salt Security API 保护平台获得的 Salt Security 客户的匿名和汇总经验数据。
