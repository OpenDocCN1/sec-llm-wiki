从 DNS 重新绑定中保存私有网络

在专用网络中，Web 服务与外部在线世界保持隔离。尽管如此，网络犯罪分子仍然可以通过一种称为 DNS 重新绑定的技术滥用基于 Web 的控制台来破坏内部网络。它是一种在受害者浏览器上启动后将内部 Web 应用程序的攻击面暴露给恶意网站的方法。

要了解私有网络是如何被渗透的，让我们了解 DNS 重新绑定在现代浏览器（例如 Chrome 和 Firefox）上的工作原理。

DNS 重新绑定如何工作？

流行的浏览器采用同源策略，其中各种资源（如 JavaScript、图像和 CSS）从同一服务器加载以运行 Web 应用程序。但是，已经发现攻击者可以使用 DNS 重新绑定来绕过这一点并允许跨域请求。

  • 该策略使用 URI 方案、端口和主机名的组合来发现请求的不同来源（例如，与其自身或其他服务器相同的服务器）。在这些组件中，浏览器使用主机名来标识 Internet 上的不同服务器。但是，主机名不绑定到网络设备，而是由 DNS 解析为 IP 地址。 

  • IP 地址是静态或动态分配给设备的。由于域所有者可以完全控制 DNS 记录，因此他们可以将主机名解析为任意 IP 地址。DNS 重新绑定滥用了此特权。

  • 在受害者的 Web 浏览器从攻击者的服务器加载恶意负载后，攻击者可以将其主机名与重定向到目标服务器的内部 IP 地址重新绑定。

专网渗透

根据 Palo Alto Networks 的 Unit 42 的研究人员的说法，首先是用社会工程策略（例如网络钓鱼电子邮件和域名抢注）欺骗受害者打开恶意网站。

  • 在受害者的浏览器上启动恶意站点后，攻击者会在发起 DNS 重新绑定攻击之前寻找私有 IP 地址和端口来托管易受攻击的服务。

  • 开放端口提供有关暴露在 IP 地址后面的 Web 应用程序的详细信息。此外，使用 WebRTC 方法，恶意网站可以扫描本地网络内的开放 Web 服务。

  • 定位目标服务后，攻击者的网站可以在 iframe 内发起 DNS 重新绑定攻击。 

  • 第一个请求从恶意主机名获取重新绑定负载。此攻击脚本继续触发对主机名的重复解析，直到它重新绑定到目标 IP 地址。然后 iframe 可以在受害者不知情的情况下与内部服务持续通信。

在现实世界的攻击中使用

该DNS重新绑定攻击可以利用受害者的浏览器作为代理攻击面扩大到专用网络，通过通过POC攻击研究人员所证实。

  • 它已被用于实际渗透称为 Singularity 的开源 DNS 重新绑定平台。

  • 研究人员在模拟环境中启动了 Singularity 的 RCE 有效载荷。他们用它来定位 Rails 框架，其中 PUT API 允许用户在服务器上运行任意系统命令。 

  • 任何使用此 API 的 Web 应用程序都需要在运行时生成新的令牌，并且在不读取服务器响应的情况下不可能猜测有效的 API 端点。

  • 但是，在执行 DNS 绑定后，Singularity RCE 负载可以获得令牌，并使用它来重建任何所需的 URL。

许多解决方法

目前在实践中有几种保护方法——基于浏览器的 DNS 固定方法；基于DNS的使用DNS缓存软件；基于服务器的缓解措施在私有服务上实施 HTTPS 通信；实时 DNS 重新绑定检测。

尾注

DNS重新绑定技术是一个严重的威胁。Web 浏览器供应商、Web 应用程序所有者和 DNS 解析器需要应用适当的保护策略来确保针对此类威胁的安全性。
