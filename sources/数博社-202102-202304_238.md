# OWASP 网络防御矩阵

OWASP® 基金会致力于通过其社区主导的开源软件项目来提高软件的安全性，其中包括 OWASP Cyber Defense Matrix，该项目最初旨在帮助组织整个网络安全供应商市场的安全技术。它们解决了一些仍然存在的混淆，因为网络安全社区不使用一致的术语，供应商使用基于流行术语的市场语言。

  

想象一下，走进一家杂货店购买感恩节晚餐，但看到的不是漂亮、有序的过道，而是杂货店中间的一大堆食物。找到做晚餐所需的原料将非常困难，因为没有组织系统可以帮助您了解事物的位置。这种混乱使您很难找到您需要的东西并比较竞争产品。

![](../Images/86aff757d5cd8f5c37aa43c3ce7171c7.png)

网络安全供应商市场就像这个杂乱无章的杂货店。通过查看任何主要安全会议的供应商大厅，可以看到这一断言的证据。供应商兜售商品时发出的刺耳声音、供应商市场结构令人困惑的语言以及缺乏任何组织结构（从大到小）都无助于买家了解他们需要什么或在哪里可以找到它。

![](../Images/7ede1663ebfd503087ad623ae42ff0ae.png)

由于网络安全社区没有使用一致的术语来描述我们的需求，因此对许多供应商产品的实际用途存在很多混淆。我们被过度使用的时髦行话轰炸，而不是清楚地阐明产品的功能，这些行话通常让我们怀疑该产品是否真的可以解决我们的任何问题。一些安全团队甚至根据行话进行组织。我们需要停止让营销宣传来支配我们的术语，而不是忽视那些实际上告诉我们某事做什么的更平淡的描述。

  

网络防御矩阵通过逻辑结构帮助我们了解我们需要组织的内容，以便当我们进入安全供应商市场时，我们可以快速辨别哪些产品解决了哪些问题，并了解给定产品的核心功能是什么。此外，网络防御矩阵提供了一种机制，可确保我们拥有涵盖整个选项范围的能力，以帮助保护我们的环境。

![](../Images/9d22a9c71ab00208e7f5d87159306c74.png)

虽然网络防御矩阵最初是为了帮助组织安全技术而创建的，但已经发现了许多其他用例来帮助构建、管理和运行安全程序。该网站将捕获这些用例及其实施，以帮助安全从业人员完善他们的安全计划。

# 网络防御矩阵的结构

网络防御矩阵的基本结构从两个维度开始。

第一个维度捕获了 NIST 网络安全框架的五个操作功能：

| 识别 || 保护 || 探测 || 回应 || 恢复 |
| --- | --- | --- | --- | --- |

识别 (ID)：清点资产和漏洞、测量攻击面、确定优先级、确定正常情况的基线、威胁建模、风险评估

保护(PR)：预防或限制影响、修补、包含、隔离、强化、管理访问、漏洞缓解

检测 (DE) ：发现事件、触发异常、寻找入侵、安全分析

响应(RS) ：对事件采取行动，消除入侵，评估损害，法医重建

恢复(RC)：恢复正常运营、恢复服务、记录经验教训、恢复能力

  

**第二个维度捕获了我们试图保护的五个资产类别：**

| 设备 |
| --- |
| 应用 |
| --- |
| 网络 |
| 数据 |
| 用户 |

设备：工作站、服务器、手机、平板电脑、存储、网络设备、物联网基础设施等。

应用：设备上的软件、交互和应用程序流

网络：设备和应用程序之间的连接和流量流动、通信路径

数据：左侧的资源处于静止、传输中或使用中的内容

用户：使用左边所列资源的人

**当这两个维度放入网格中时，我们会得到一个 5×5 的矩阵，我们称之为“网络防御矩阵”。**

![](../Images/a5bedc7e51dd3a186c553edf21db4da5.png)

这个矩阵还有一个更重要的部分。在网格的底部，我们展示了一个连续体，它描述了在我们通过 NIST 网络安全框架的五个操作功能时对技术、人员和流程的依赖程度。技术在识别和保护方面发挥着更大的作用。随着我们转向检测、响应和恢复，我们对技术的依赖减少了，而我们对人的依赖增加了。在所有五个运营职能中，对 PROCESS 的依赖程度始终如一。这种连续性有助于我们了解在尝试应对网络安全挑战时，我们在对人员、流程和技术的依赖方面可能存在哪些不平衡。
