几乎每个应用程序都使用应用程序编程接口 (API)。不过，从安全的角度来看，API 也存在一些常见问题。Gartner预测 API 滥用将是 2022 年最常见的攻击类型。那么，API 究竟面临哪些问题？数据安全捍卫者可以做些什么呢？ 

## **普遍的 API 风险**

2019 年，OWASP列出了 10 个需要注意的 Web 应用程序数据安全风险。这些包括： 

*   **数据暴露**：当开发人员公开其对象的所有属性而不考虑这些项目的私密性时，就会出现这种类型的威胁。因此，在向用户显示任何内容之前，由客户端执行数据过滤。
    
*   **安全配置错误**：这些数据安全漏洞有多种形式，包括错误配置的 HTTP 标头、包含敏感信息的错误消息和暴露的云存储。通常，它们是不安全的默认配置的产物。
    
*   **注入**：在这种情况下，命令或查询将不受信任的数据发送给解释器。攻击者可以使用这些类型的缺陷来欺骗解释器运行涉及敏感数据的恶意代码或命令。
    
*   **日志记录和监控不足**：这两种数据安全风险都可以为攻击者提供隐藏在其网络中不被注意的机会。从那里，威胁行为者可以确定网络范围，转移到关键业务资产并窃取数据。
    

## **数据安全风险对业务的影响**

涉及 API 的问题不仅仅阻碍了企业推出新应用程序的计划。如果确实发生了攻击，它们也会花费时间和资源。

这种情况在 2020 年发生了很多次。正如Salt Security所指出的那样，91% 的受访者的雇主在这一年中至少遇到过一个 API 问题。在这些受访者中，超过一半 (56%) 在此期间每月发生超过 55 起与 API 相关的数据安全事件。与此同时，22% 的人每月处理多达 200 次攻击。

新的一年的开始也没有结束这些 API 问题。以下是 2021 年前六个月成为头条新闻的几起 API 事件：

*   今年 2 月，研究人员发现他们研究的所有30 个医疗保健应用程序都面临 API 攻击的风险。他们还了解到，这些应用程序使 2300 万用户面临潜在威胁。
    
*   主要征信机构之一使用的 API 工具暴露了几乎每个美国人的信用评分。该工具使某人能够仅使用公共信息通过信用局进行信用检查。
    
*   另一个 API 问题涉及一家流行的固定自行车制造商。一位研究人员发现，他们可以向公司的 API 发出未经身份验证的用户帐户数据请求。这一弱点使研究人员能够访问其他自行车车主的信息。
    

## **如何提高 API 数据安全性 **

上面讨论的案例强调了企业和机构未来保护其 API 的必要性。他们可以做到这一点的方法之一是始终使用 SSL 和 TLS 证书。将有效证书与 API 结合使用有助于通过加密保护数据交换。这将使防御者能够保护应用程序免受旨在暴露用户信息的中间人攻击。

之后，优化防火墙。这些对于帮助控制由 API 启用的信息流至关重要。撤销任何对应用程序需求过于宽松的数据安全规则。这可能需要首先查看防火墙规则和网络对象，以了解特定企业或机构的 API 使用情况。

最后，企业和机构需要对其客户实施适当的身份验证和授权。他们可以考虑使用协议来限制第三方应用程序对 API 的访问。这样做可以帮助防止太多方访问和共享太多内容。

## **不要忘记您的 API**

API 的安全模型没有跟上越来越无边界的现代网络。这些框架未能发现涉及其 API 的漏洞。因此，如上所述的 API 漏洞正变得越来越普遍。

通过密切关注 API，企业和机构可以开始正规化他们的 API 数据安全工作。通过这样做，他们可以与越来越多的 API 攻击的威胁形势保持同步。
