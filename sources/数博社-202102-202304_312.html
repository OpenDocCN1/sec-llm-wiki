1、俄罗斯间谍黑客在野外利用的12个安全漏洞



消息来源：https://thehackernews.com/2021/05/top-11-security-flaws-russian-spy.html?&web_view=true

根据英国和美国情报机构周五联合发布的新咨询报告，隶属于俄罗斯外国情报局（SVR）的网络特工已改变其战术，以响应先前公开的攻击方法披露。

这些措施包括部署名为Sliver的开源工具，以维护他们对受害受害者的访问权限，并利用Microsoft Exchange服务器中的ProxyLogon缺陷进行开发后的活动。

上个月将与SVR相关的参与者公开归因于SolarWinds供应链攻击的。例如高级持久威胁29（APT29），Dukes，CozyBear和Yttrium。技术报告中详细介绍了SVR的APT29组用作渗透美国和外国实体的初始访问点的五个漏洞。

  • CVE-2018-13379 -Fortinet FortiGate VPN

  • CVE-2019-9670 -Synacor Zimbra协作套件

  • CVE-2019-11510-脉冲安全脉冲连接安全VPN

  • CVE-2019-19781 -Citrix应用程序交付控制器和网关

  • CVE-2020-4006 -VMware Workspace ONE访问

NCSC说：“ SVR的目标组织符合俄罗斯外国情报利益，包括政府，智囊团，政策和能源目标，以及更多有时间限制的目标，例如2020年的COVID-19疫苗目标。”

随后在4月26日发布了单独的指南，该指南进一步阐明了该组织用于组织入侵，计数密码喷射，利用针对虚拟专用网络设备的零日漏洞（例如CVE-2019-19781）的技术。网络访问，并部署一种名为WELLMESS的Golang恶意软件，以掠夺参与COVID-19疫苗开发的多个组织的知识产权。

根据NCSC的说法，现在又添加了七个漏洞，同时注意到APT29可能会“迅速地”武器化最近发布的公共漏洞，这些漏洞可能使他们能够初步访问其目标。

  • CVE-2019-2725 -Oracle WebLogic服务器

  • CVE-2019-7609 -Kibana

  • CVE-2020-5902 -F5大IP

  • CVE-2020-14882 -Oracle WebLogic Server

  • CVE-2021-21972 -VMware vSphere

  • CVE-2021-26855 -Microsoft Exchange Server


2、10个APT组织在网络攻击中利用MS Exchange相关漏洞



消息来源：https://cybernews.com/security/10-apt-groups-that-joined-the-ms-exchange-exploitation-party/?&web_view=true



在公司发布补丁之前，至少有五个高级威胁参与者（APT）正在利用Microsoft Exchange服务器。微软宣布存在漏洞后，至少有五家其他APT加入了该组织，并且网络攻击的企图激增。

3月2日，Microsoft检测到多个0天漏洞被用来攻击Microsoft Exchange Server的本地版本。

ESET的研究表明近期多个Exchange相关漏洞被至少10个APT组利用。

  • CVE-2021-26855 Exchange SSRF漏洞中，攻击者可直接构造恶意请求，以Exchange server的身份发起任意HTTP请求，扫描内网，并且可获取Exchange用户信息。该漏洞利用无需身份认证。

  • 在 CVE-2021-26857 Unified Messaging service 反序列化漏洞中，攻击者可构造恶意请求，触发反序列化漏洞，从而执行任意代码。成功利用该漏洞需要Exchange administrator权限，或需要配合其他漏洞。

  • CVE-2021-26858 / CVE-2021-27065 Exchange 任意文件写入漏洞中，攻击者可结合CVE-2021-26855 SSRF漏洞，或提供正确的administrator凭证，构造恶意请求，在系统上写入任意文件。

APT是由国家资助的黑客组织，它们从事间谍活动和破坏攻击，以窃取敏感数据并削弱对手的基础设施和防御系统。现在，他们的业务被视为对政府机构和私人组织的最大威胁。

ESET研究人员Matthieu Faou表示：“仅在补丁发布后，利用攻击的数量就增加了，并且在接下来的几天中相当高。”


3、谷歌修补总共19个影响Web浏览器的漏洞



消息来源：https://www.securityweek.com/google-patches-19-vulnerabilities-chrome-90-update?&web_view=true

谷歌2021年5月11日宣布了另一套针对Chrome的补丁程序，以解决总共19个影响Web浏览器的漏洞。

最新的Chrome版本-90.0.4430.212 –适用于Windows，Mac和Linux用户。浏览器的Android和iOS变体也进行了更新。

在此版本中解决的19个安全漏洞中，外部研究人员报告了15个漏洞，包括13个被认为具有高严重性的漏洞和2个级别为中等严重性的漏洞。

受这些问题影响的Chrome组件包括Web应用安装，脱机，媒体Feed，Aura，标签组，通知，V8，自动填充，文件API，历史记录，阅读器模式，付款和标签栏。

像往常一样，在将修补程序交付给大多数用户之前，该公司不会共享有关已解决错误的完整详细信息。Google在其通报中未提及在实时攻击中利用的任何这些漏洞。

但是，在过去的几个月中，这家互联网搜索巨头发布了一些针对浏览器中零日漏洞的补丁程序。

3月份，Google发布了紧急修复程序以解决CVE-2021-21193的问题，该漏洞已被发布为零日漏洞。

4月，该公司发布了CVE-2021-21206和CVE-2021-21220（在Chrome 89中）和CVE-2021-21224（Chrome 90）的补丁。

4月份，在将补丁交付给Chrome和Edge用户之前，发布了针对Chromium漏洞（在V8 JavaScript引擎中）的概念验证（PoC）漏洞。4月下旬，Google修复了V8中的另一个严重错误。

4、研究员发现“核弹级”Wi-Fi安全漏洞FragAttacks



消息来源：https://mp.weixin.qq.com/s/dTBUWQucWaRuN3Jq1bB9RA

近日，纽约大学阿布扎比分校的安全研究员Mathy Vanhoef发现了一种堪称“核弹级”的Wi-Fi安全漏洞——FragAttacks（破片和聚合攻击），该漏洞存在于1997年Wi-Fi技术诞生以来的所有Wi-Fi设备（包括计算机、智能手机、园区网络、家庭路由器、智能家居设备、智能汽车、物联网等等）。

FragAttack是一组漏洞，其中三个影响大多数WiFi设备，属于Wi-Fi 802.11标准帧聚合和帧分段功能中的设计缺陷，而其他漏洞是Wi-Fi产品中的编程错误。

与Wi-Fi设计缺陷相关的FragAttacks CVE漏洞包括：


  • CVE-2020-24588：聚合攻击（接受非SPP A-MSDU帧）；


  • CVE-2020-24587：混合密钥攻击（重组使用不同密钥加密的片段）；


  • CVE-2020-24586：片段缓存攻击（（重新）连接到网络时不从内存中清除片段）。


Wi-Fi实现漏洞被分配了以下CVE：


  • CVE-2020-26145：接受纯文本广播片段作为完整帧（在加密网络中）；


  • CVE-2020-26144：接受以EtherType EAPOL（在加密网络中）以RFC1042标头开头的纯文本A-MSDU帧；


  • CVE-2020-26140：在受保护的网络中接受纯文本数据帧；


  • CVE-2020-26143：在受保护的网络中接受分段的纯文本数据帧。


Vanhoef发现的其他实现漏洞还包括：


  • CVE-2020-26139：即使发件人尚未通过身份验证，也要转发EAPOL帧（应仅影响AP）；


  • CVE-2020-26146：重新组合具有非连续数据包编号的加密片段；


  • CVE-2020-26147：重新组合混合的加密/纯文本片段；


  • CVE-2020-26142：将片段帧作为完整帧进行处理；


  • CVE-2020-26141：不验证分段帧的TKIP MIC。



5、高通芯片高危漏洞影响全球40%手机



消息来源：https://mp.weixin.qq.com/s/ZHuoKRYCRqzzczSC0PZEgQ

近日，高通公司的移动调制解调器MSM芯片（包括最新的支持5G的版本）中发现了一个高危安全漏洞（CVE-2020-11292），攻击者可以利用该漏洞获取手机用户的短信、通话记录、监听对话甚至远程解锁SIM卡！更可怕的是，该漏洞的利用无法被常规系统安全功能检测到。

高通MSM芯片包含2G、3G、4G和5G功能的一系列片上系统（SoC），全部都存在该高危漏洞。目前全球约40%的手机都使用了MSM芯片，其中包括三星、谷歌、LG、OnePlus和小米在内的多家手机供应商的产品。

根据Check Point研究人员的说法，“如果该漏洞被利用，攻击者将能使用安卓操作系统本身作为向手机中注入恶意和隐藏式代码的入口点”，CPR还详细说明了事件的时间表。研究人员在2020年10月中旬发现了该漏洞，高通确认了该漏洞，编号为CVE-2020-11292。并在CPR通知该公司一周后的10月15日将其归类为“高评级漏洞”。

该安全漏洞甚至还可使攻击者解锁移动设备的用户识别模块（SIM），后者存储着用户的网络身份验证信息和联系人信息。

高通公司（Qualcomm）于12月修复了该漏洞，距离该漏洞向公众披露了几个月。

6、NAME：WRECK DNS漏洞影响超过1亿台物联网设备



消息来源：https://www.bleepingcomputer.com/news/security/name-wreck-dns-vulnerabilities-affect-over-100-million-devices

安全研究人员2021年4月披露了九个漏洞，这些漏洞影响在至少1亿个设备上运行的流行TCP / IP网络通信堆栈中的域名系统协议的实现。

这些缺陷可以统称为NAME：WRECK，可以利用这些缺陷使受影响的设备脱机或对其进行控制。

在从高性能服务器和网络设备到监视和控制工业设备的操作技术（OT）系统等广泛产品上运行的广泛TCP / IP堆栈中发现了这些漏洞。

四个TCP / IP堆栈中的问题

NAME：WRECK的发现是物联网企业安全公司Forescout和以色列安全研究小组JSOF的共同努力，并影响以下TCP / IP堆栈中的DNS实现：

  • FreeBSD（脆弱版本：12.1）-BSD系列中最流行的操作系统之一

  • IPnet（易受攻击的版本：VxWorks 6.6）-由Interpeak最初开发，现在由WindRiver维护，并由VxWorks实时操作系统（RTOS）使用

  • NetX（漏洞版本：6.0.1）-是ThreadX RTOS的一部分，现在是Microsoft维护的一个开源项目，名称为Azure RTOS NetX

  • Nucleus NET（漏洞版本：4.3）-由西门子业务Mentor Graphics维护的Nucleus RTOS的一部分，用于医疗，工业，消费类，航空航天和物联网设备

根据Forescout的说法，在假设但可行的情况下，威胁参与者可以利用NAME：WRECK漏洞通过窃取敏感数据，修改或使设备脱机以对制造行业中的政府或企业服务器，医疗机构，零售商或公司造成重大损害。

NAME：WRECK漏洞

安全报告重点介绍了每个NAME：WRECK漏洞（以及受影响的堆栈，描述和CVSS评分）。读者还可以查看完整的报告以了解更多详细信息。

  1. 严重的RCE CVE-2016-20009（IPnet）：DNS客户端在消息解压缩功能上基于堆栈的溢出导致潜在的RCE（CVSS评分9.8）。

  2. 严重的RCE CVE-2020-15795（Nucleus NET）：DNS域名标签解析功能无法正确验证DNS响应中的名称（CVSS评分8.1）。

  3. 严重的RCE CVE-2020-27009（Nucleus NET）：DNS域名记录解压缩功能无法正确验证指针偏移值（CVSS评分8.1）。

  4. 高DoS CVE-2020-7461（FreeBSD）：在dhclient（8）中的DHCP数据包中解析选项119数据时，由于边界错误而存在漏洞（CVSS评分7.8）。

  5. 中级DoS CVE-2020-27736（Nucleus NET）：DNS域名标签解析功能无法正确验证DNS响应中的名称（CVSS评分6.5）。

  6. 中级DoS CVE-2020-27737（Nucleus NET）：DNS响应解析功能无法正确验证记录的各种长度和计数（CVSS评分6.5）。

  7. 中级DoS CVE-2020-27738（Nucleus NET）：DNS域名记录解压缩功能无法正确验证指针偏移值（CVSS评分6.5）。

  8. 中度DNS缓存中毒CVE-2021-25677（Nucleus NET）：DNS客户端不能正确随机化DNS事务ID（TXID）和UDP端口号，从而使攻击者能够进行DNS缓存中毒/欺骗攻击（CVSS评分5.3）。

  9. NetX的中等DoS（没有可用的CVE）：影响DNS解析器组件中的多个功能（CVSS评分6.5）。

这三个严重漏洞和一个高严重性漏洞（CVE-2020-7461）可能会导致远程执行代码（RCE）。其余中等严重性漏洞可能导致拒绝服务（DoS）或DNS缓存中毒。

研究人员分析了上述TCP / IP堆栈中的DNS实现，着眼于协议的消息压缩功能。

DNS响应数据包多次包含相同域名或一部分域名的情况并不少见，因此存在一种压缩机制来减小DNS消息的大小。

在多播DNS（mDNS），DHCP客户端和IPv6路由器通告中，不仅存在DNS解析器，而且还从该编码中受益。

Forescout在今天的一份报告中解释说，尽管某些协议并未正式支持压缩，但该功能还存在于许多实现中。发生这种情况是“由于代码重用或对规范的特定理解。”

研究人员指出，实施压缩机制一直是一项艰巨的任务，特别是自2000年以来发现了十多个漏洞。

必须注意的是，并非所有NAME：WRECK都可以被利用来获得相同的结果。其中最严重的潜在影响是远程执行代码，最高严重性得分被计算为9.8（满分10分）。

如上表所示，并非所有漏洞都与消息压缩有关。这些例外是研究的副产品，可以与其他例外联系起来以扩大攻击的影响。

另一个例外是CVE-2016-20009。 该漏洞最初 由Exodus Intelligence于2016年发现，但并未获得跟踪号。尽管该产品不再维护（报废），但今天仍在使用。

Forescout要求Wind River申请CVE，但该公司已经几个月没有采取任何行动。因此，该公司向Exodus Intelligence提出了同样的要求，并且该漏洞在2021年1月收到了一个标识符。

利用单个漏洞的攻击者可能无法取得很大的成就，但通过将它们组合在一起，可能会造成严重破坏。

例如，他们可以利用一种缺陷将任意数据写入易受攻击的设备的敏感内存位置，将另一种缺陷注入到数据包中，然后将第三个缺陷传递给目标。

Forescout的报告深入探讨了有关技术利用的技术细节，该技术可利用 公司在开放源代码TCP /中发现的NAME：WRECK漏洞以及AMNESIA：33集合中的错误，利用这些漏洞如何导致成功的远程执行代码攻击 IP堆栈。

该公司还讨论了多个实现问题，这些问题在DNS消息解析器中不断重复，称为反模式，这是NAME：WRECK漏洞的原因：

-缺少TXID验证，随机TXID和源UDP端口不足

-缺乏域名字符验证

-缺少标签和名称长度验证

-缺少NULL终止验证

-缺少记录计数字段验证

-缺乏域名压缩指针和偏移量验证

NAME：WRECK的修补程序可用于 FreeBSD，Nucleus NET和 NetX，如果这些修补程序涉及到受影响的产品，则可以消除此问题。

因此，现在由设备供应商来将更正应用于仍可以更新的产品。但是，由于存在多个障碍，因此该过程的成功率不太可能达到100％。

首先，操作员需要确定在受影响的设备上运行的TCP / IP堆栈。这并非总是一件容易的事，因为有时甚至设备供应商也不知道。

另一个障碍是应用补丁，在许多情况下，由于没有集中管理，因此需要手动安装该补丁。除此之外，关键设备无法在更新过程中脱机，并且很清楚为什么实际上不可能达到100％的补丁率。
