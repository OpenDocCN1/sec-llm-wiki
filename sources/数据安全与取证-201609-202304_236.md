▍**什么是“包”？**

  

**“包”指的是数据包，即网路通信中的流量，是通信传输中的数据单位。**

  

换种说法，数据包其实是**某个信息被划分后形成的多个数据块**，这些划分后的数据包会在一个或多个网络的不同路径中传输，最后根据一定的规则在到达目的地后重新组合为这个信息，这就是网络传递信息的过程。

  

可以说，**上网的过程就是数据包交换的过程**。当你打开网页浏览时，你也就向一个网站发送了多个数据包，网站在接收到你的数据包后，会返给你其网页的数据包；若你对网站有进一步浏览的的需求，你的电脑就会继续发送数据包，然后再接收到网站发回的数据包，这样来回就形成了上网的交换过程。

  

▍**什么是“抓包”？**

知道了什么是数据包，“抓包”理解起来就容易了。  

  

**抓包（packet capture）就是将网络传输发送与接收的数据包进行截获、重发、编辑、转存等操作。**

  

▍**为什么我们能够“抓包”？**

前面说过，上网过程就是一个交换数据包的过程。但是我们作为发送和接收方的同时，**但是我们的数据包在和我们交换的同时，还会经过许多中继站（交换机、路由器等），有许多数据包会流经他们然后去向别处**，类似于快递的中转站。正因如此，网络才能够互相流通传达信息；也恰恰是因为这个原因，我们也可以截取到别人的数据包进行分析查看。  

  

▍**WireShark抓包演示**

  

虽然知道了数据包的含义，但它对我们来说依旧是个抽象的概念。因此，我们希望能“看见”这些数据包，这就是抓包软件的作用了。

  

**抓包软件能够将网络通信中的数据包截取后，以16进制的形式可视化展现和分析。**

  

接下来我们以Wireshark抓包软件为例，介绍数据包及其抓取内容。

这里涉及到**OSI模型(Open System Interconnection，开放系统互联)**的知识，也称为**七层协议**，它定义了一种分层体系结构，在其中的每一层定义了针对不同通信级别的协议。1到7层分别是：**物理层、数据链路层、网络层、传输层、会话层、表示层、应用层**。OSI模型在逻辑上可分为两个部分：低层的1至3层关注的是原始数据的传输；高层的4至7层关注的是网络下的应用程序。

  

在第三个框即图1中的状态栏，表示的是选中的数据包的内容，以16进制的形式呈现。

![](../Images/8bfc838c609f2eb0a8de25ab7380fbc8.png)

图5 状态栏

状态栏中16进制的字符串记录的就是数据包中的文件内容，每一段的含义软件都已经翻译好，你只需要点击相应字段就能查看。

  

网络时刻在传达大量信息，抓包经常就动辄成千上万条，此时我们需要用到过滤器，根据一定条件筛选所截取到的数据包。

![](../Images/8c08b69830c7a50cbb5238b8af4ccb77.png)

图6 过滤器

图例输入的筛选条件是http协议，你可以看到，筛选后的列表中显示的都是协议为http的数据包。

  

点击筛选框旁边的表达式，会有一个自定义筛选表达式的窗口。

![](../Images/e6c0294ab96ee939808b96b2a4146fb8.png)

图7 过滤表达式

其实过滤器有两种，一种是捕捉过滤器，一种是显示过滤器。

  

**捕捉过滤器（CaptureFilters）：**需要在开始捕捉前设置，用于决定将什么样的信息记录在捕捉结果中。

  

**显示过滤器（DisplayFilters）：**在捕捉结果中进行详细精确的查找，可以在得到捕捉结果后随意修改。两种过滤器使用的语法是完全不同的。

  

▍**捕捉过滤器的语法如图**

![](../Images/354041c828fc573faf7c000367ea8f1e.png)

图8：捕捉过滤器语法

**Protocol（协议）**

可能的值: ether, fddi, ip, arp, rarp, decnet, lat, sca, moprc, mopdl, tcp and udp.如果没有特别指明是什么协议，则默认使用所有支持的协议。

  

**Direction（方向）**

可能的值: src, dst, src and dst, src or dst如果没有特别指明来源或目的地，则默认使用 “src or dst” 作为关键字。

例如，”host 10.2.2.2″与”src or dst host 10.2.2.2″是一样的。

  

**Host(s)**

可能的值： net, port, host, portrange.如果没有指定此值，则默认使用”host”关键字。

例如，”src 10.1.1.1″与”src host 10.1.1.1″相同。

  

**Logical Operations（逻辑运算）**

可能的值：not, and, or.否(“not”)具有最高的优先级。或(“or”)和与(“and”)具有相同的优先级，运算时从左至右进行。

例如，“not tcp port 3128 and tcp port 23″与”(not tcp port 3128) and tcp port 23″相同。“not tcp port 3128 and tcp port 23″与”not (tcp port 3128 and tcp port 23)”不同。

  

**解读例子：**

例1：tcp dst port 3128  //捕捉目的TCP端口为3128的封包。

例2：ip src host 10.1.1.1  //捕捉来源IP地址为10.1.1.1的封包。

  

▍**显示过滤器的语法如图**

![](../Images/64cd715065cb242d867bcc5f260e499f.png)

图9：显示过滤器语法  

**解读例子：**

例1: snmp || dns || icmp //显示SNMP或DNS或ICMP封包。 

例2: ip.addr == 10.1.1.1  //显示来源或目的IP地址为10.1.1.1的封包。

例3: ip.src != 10.1.2.3 or ip.dst != 10.4.5.6  //显示来源不为10.1.2.3或者目的不为10.4.5.6的封包。

换句话说，显示的封包将会为：“来源IP：除了10.1.2.3以外任意；目的IP：任意”以及“来源IP：任意；目的IP：除了10.4.5.6以外任意”。

▍**实际操练**

  

接下来，小编给您录了一组动图，给你示例**通过抓包来分析某网站安全性**。

  

我们找了某人力资源网站，填写需要的个人信息后注册，但是在注册之前我们启动了WireShark，所以已经开始抓包了。

  

![](../Images/0b62c4091b1cd0459969389b34c48ef3.png)

  

可以看到，我在该网站所提交的数据中，通过抓包后发现，**除了账号密码是有MD5算法加密的，其余个人信息如姓名、手机号、身份证号等等均是明文**，甚至连我填的密保问题的答案“Wendy”、“Levin”、“Sprite”都能直接看到，因此拿到账号密码也只是多个步骤而已。

  

也就是说，**任何能够抓取到该过程数据包的人，都都能够轻而易举拿到在该网站注册过的个人信息**，由此可以判断该网站的安全性较差。
