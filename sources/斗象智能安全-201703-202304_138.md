# Osprey鱼鹰开源漏洞检测框架Docker使用指南

自9月23日，斗象科技 TCC团队（斗象能力中心Tophant Competence Center）在FreeTalk 2017深圳站宣布正式开源CRS漏洞检测框架——Osprey(鱼鹰)已经过去一个多月。在对鱼鹰做迭代升级的同时，为便于大家安装和使用鱼鹰，TCC为鱼鹰添加了完整的Docker支持。包含Docker使用的最新鱼鹰代码已经同步到GitHub。

通过Docker使用鱼鹰，省去了手动安装各种环境与依赖的过程，利用Docker-compose可快速搭建完整的鱼鹰框架，包含基础的命令行使用工具和交互式Console接口以及可扩展的Web API接口。1准备工作

安装Docker以及Docker-compose，具体安装步骤请参考以下官方文档操作：

Install Docker：https://docs.docker.com/engine/installation/

Install Compose：https://docs.docker.com/compose/install/

Docker-compose可通过pip直接安装。安装成功之后，确保docker和docker-compose命令可用。![](../Images/0fdf00884d3d1bcb9467b7ac41e22f8a.png)

![](../Images/2b087555a1d97444050f7d1c981aa087.png)

拉取最新版本的Osprey Git代码：

git clone： https://github.com/TophantTechnology/osprey.git

或者在已有项目中更新代码：git pull

2编译使用Docker环境

1、进入鱼鹰项目中的docker目录：cd docker

2、通过compose编译启动Osprey项目环境：

docker-compose build

docker-compose up

up命令的启动过程中，会自动拉取Osprey项目所需的三个docker镜像，分别是mongo:latest、rabbitmq:latest以及tophant/osprey:latest，最后一个就是打包好的osprey镜像。

（拉取镜像的过程受网络带宽影响，可能会因网络问题断开或耗时较久，请耐心等待，或使用其他国内的docker源。）

3、当镜像下载完毕之后，Osprey项目相关的服务将会自动启动，通过终端Compose的输出可以发现mongodb、rabbitmq服务已经启动，osprey作为worker启动（终端的输出信息默认输出到前台，通过docker-compose up –d使项目后台运行）。

 此时用浏览器访问5000端口，可以看到osprey-web首页的指示信息，安装部署成功

![](../Images/e5ece58f667d23458f32988cc456173b.png)

4、利用Osprey的Web API接口下发任务和获取任务结果，可以使用curl工具，或者通过Firefox浏览器的HackBar工具测试。

curl http://127.0.0.1:5000/api/start -d '{"task\_id": "TASK\_ID", "vid": "vb\_ID", "target": "http://x.com/"}'

curl http://127.0.0.1:5000/api/result -d '{"task\_id": "TASK\_ID"}'

通过docker ps命令看到三个相关服务容器正在运行

![](../Images/cb1309fb2c07f5860d13b39703c3bf5e.png)可以进入osprey容器进行操作：docker exec –it docker-osprey\_1 bash

接下来便可以在osprey容器内使用鱼鹰的命令行工具和Console接口了

![](../Images/677ed193c64b538ee6156f15ddd26111.png)

3Osprey镜像单独使用

当然，如果仅仅想使用osprey来写PoC和验证漏洞，不需要使用Web API接口，也可以不使用Compose构建完整的项目环境，只拉取osprey的镜像来启动单独的容器使用。

拉取osprey的镜像：docker pull tophant/osprey:latest

利用osprey镜像启动并进入容器：docker run –it –v pocs:/opt/osprey/pocs tophant/osprey bash

**注：** –v pocs:/opt/osprey/pocs tophant/osprey选项是将宿主机上存放PoC的目录挂载进osprey容器内，供容器内的osprey调用使用，因此具体的PoC目录应视实际情况指定。
