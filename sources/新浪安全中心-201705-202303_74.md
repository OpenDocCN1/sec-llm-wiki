# Redis未授权访问

写这个小段子算是给自己也给大家提个醒吧，老漏洞不管再老，只要存在那就还是核弹，不一定什么时候就会引爆然后把公司炸飞。

         Redis是一个开源的使用ANSI C语言编写、支持网络、可基于内存亦可持久化的日志型、Key-Value数据库，并提供多种语言的API。

Redis 未授权访问是一直存在的问题，但Redis作者放弃了解决未授权访问导致的安全问题，Redis 安全模型的观念是: “请不要将Redis暴露在公开网络中, 因为让不受信任的客户接触到Redis是非常危险的” 。

Redis默认的监听端口是6379，如果在配置Redis的时候，端口开放在了0.0.0.0上，而防护设备和防火墙也没有做相应限制，就会导致其他机器也可以访问该端口，要是也没有设置连接密码，就会造成Redis未授权访问。下面就是一改变了端口的未授权Redis，改了端口还是被人扫出来了吧，你还能藏得起来？

有人说了，谁还会那么傻，连个密码都不设就敢往公网上放。年轻人我跟你讲，世事无绝对啊。年轻的开发，习惯使用默认配置的网络管理员，有些为了业务需求的同事，甚至可能在自己服务器上搭建环境来玩的编程爱好者，都可能干出这种事情。不信你去shodan或者zoomeye搜一下6379端口试试~

那么这个未授权访问的利用方法是谁公布的呢？Redis的作者Antirez……是不是很无语，人家都已经放弃修复了，告诉你们这玩意儿不要放公网……

这个漏洞的危害可以分成两个方向，一个是数据方向，一个是系统方向。

数据方向就是Redis本身就是数据库，存储的有数据。

系统方向的话，需要结合Redis本身的权限来确定了，如果Redis是以Root权限启动的，那其本身据有的写权限功能就足够攻击者使用了，写脚本写shell写定时，删文件删数据删用户，扫办公扫内网扫机房。现在网上有的比较多的是写ssh的authorized\_keys，写crontab文件反弹shell的也有一些，具体的利用方法这里就不再重复了，有兴趣可以自己去搜一下，太多了。

这种漏洞就是大家常说的，成本低，操作简单，易传播，易学习但风险无限高的梦幻漏洞。那么这么好的漏洞到哪里才能找到呢？请大家自行发现，并且发现后不要利用其从事违法犯罪活动，《网络安全法》可是刚刚开始实施~

关于这种漏洞的修复建议：

*   给Redis配置上授权访问密码
    

通过命令就可以进行密码配置：

redis127.0.0.1:6379\[1\]> config set requirepass my\_redis  
OK  
redis 127.0.0.1:6379\[1\]> config get requirepass  
1) "requirepass"  
2) "my\_redis"

当然要是愿意登陆上服务器去改也可以：

         修改Redis目录下的redis.conf文件

         #requirepass foobared这一行，去掉#号，foobared修改为自己想用的密码然后重启。

*   限制IP访问Redis
    

进入redis.conf文件，找到bind。

去掉#，bind127.0.0.1 192.168.1.10

这表示可以访问redis的IP，多个IP用空格隔开。

*   以较低权限运行Redis
    

可以禁用该帐号的登录权限，限制数据写入等。

*   尽量不要把Redis暴露在公网
