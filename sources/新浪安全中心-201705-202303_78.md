东西和知识都比较老了，但在做安全检查的时候，依然会发现有些开发人员在使用rsync的时候，或者因为安全意识薄弱，或者因为单纯图省事儿，直接使用默认配置，结果导致严重的安全问题。

rsync是类unix系统下的数据镜像备份工具——remote sync。一款快速增量备份工具，实现远程同步功能的软件，能同步更新两处计算机的文件及目录。在同步文件时，可以保持源文件的权限、时间、软硬链接等附加信息。

rsync的默认配置文件是/etc/rsyncd.conf（需要注意的是，rsync安装完成后并不会生成这个配置文件，需要自己去etc下边创建一个配置文件，这里是官方配置文件模版，https://rsync.samba.org/ftp/rsync/rsyncd.conf.html），默认监听端口为873，两种认证方式分别是rsync-daemon及ssh。具体rsync的使用方法这里就不赘述了，说说具体的安全漏洞吧。

首先就是大名鼎鼎的rsync未授权访问了，rsync默认是允许匿名访问的，且rsync进程默认以root权限启动，加上rsync可保持源文件的权限。叮咚，简单的一行命令，上传下载无所不能，比找web漏洞容易多了好么。

命令：rsync \*.\*.\*.\*::

![](../Images/b89e969b7c4c79c03c13cb9761447ce2.png)

  

在本地将shell提升权限，然后通过命令上传。

提升权限：chmod a+s shell.php

上传：rsync –avz shell.php \*.\*.\*.\*::www

安全配置方法有两种，一种是不允许匿名访问，这是针对上面的漏洞的，还有一种是限定IP访问。

先说不允许匿名访问，在rsyncd.conf中，添加以下命令：

auth users = rsync  #多个用户用，分隔

secrets file = /etc/rsyncd.secrets

/etc/rsyncd.secrets为密码文件，格式为user:password。并且权限必须是600，不是600的话会提示auth failed on module out。

另一个种安全配置为限定IP访问，这个比较简单，在配置文件中加入以下命令。

hosts allow = \*.\*.\*.\* #限定的可访问IP

当然，本人依然推荐两种方法一起用，安全这种东西，再怎么小心也不为过。

最后提一个更老的东西吧，rsync远程命令执行漏洞，影响版本在2.3.3到3之间，具体的命令如下：

rsync -e./script.sh localhost:/tmp--server ./

有兴趣的同学可以到https://bugzilla.redhat.com/show\_bug.cgi?id=877279去看看研究一下，说不定会有收获。遇到这种版本问题，就像所有的系统漏洞、组件漏洞一样，五个字，升级大法好。
