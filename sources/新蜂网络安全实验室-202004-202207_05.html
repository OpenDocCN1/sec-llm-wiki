基于memcached的反射型ddos攻击是多年前的一种攻击形式。对该攻击方式进行复现，是为了更深入地了解反射型攻击的相关技术。
 

一、攻击原理

（一）什么是反射型DDOS攻击

反射型DDOS是发送大量带有被害者IP地址的请求给存在漏洞的服务器，服务器对被害者IP地址做出大量回应，形成拒绝服务攻击。CLOUDFLARE的这张图很好的解释了反射型DDOS攻击的过程：
 

（二）UDP反射放大攻击需要满足的基本条件

1、攻击者需要能伪造IP，并发送大量伪造IP的请求给反射服务器。
2、反射服务器，上面需要运行着容易放大反射攻击的服务。
3、反射服务器的响应包最好远远大于请求包。
4、反射服务器对应的协议或服务在互联网上有一定的使用量。

（三）为什么Memcached可用于反射型DDOS

而Memcached提供的基于UDP协议的服务正好满足上诉的UDP反射放大攻击的各种条件：
1、从协议看，Memcached支持UDP。
2、Memcached大部分是作为企业应用的组件，往往具有很高的上传带宽。
3、Memcached不需要认证就可以随意交互。
3、很多用户编译安装时，错误的监听了0.0.0.0，且未设置iptables或云安全组，这使得攻击者可以自由访问这些服务，从而进行UDP反射攻击。
在攻击事件中，攻击者发送大量带有被害者IP地址的UDP数据包给Memcached服务器，服务器对伪造的IP地址源做出大量回应(Memcached系统支持最大键值单数据对1M存储)，形成分布式拒绝服务攻击。

（四）各类反射攻击的放大倍数

可以看出，利用Memcached发起的反射型攻击的放大倍数是最高的。

二、Memcached反射型攻击流程

第一步，收集存在漏洞的memcached服务器

扫描端口和服务，获取不需要认证的Memcached主机。
 

第二步，上传指定数据到远程服务器Memcached上

使用set命令，可将value(数据值)存储在指定的key(键)中。如果set的key已经存在，该命令可以更新该key所对应的原来的数据，也就是实现更新的作用。
set 命令的基本语法格式如下：
set keyflags exptime bytes [noreply]
value
参数说明如下：
key：键值 key-value 结构中的 key，用于查找缓存值。
flags：可以包括键值对的整型参数，客户机使用它存储关于键值对的额外信息 。
exptime：在缓存中保存键值对的时间长度（以秒为单位，0 表示永远）
bytes：在缓存中存储的字节数
noreply（可选）：该参数告知服务器不需要返回数据
value：存储的值（始终位于第二行）

例子：
set runoob 0 900 9  //输入key：runoob，过期时间设置为900秒，字节数为9
memcached  //输入值：memcached，服务器返回STORED
get runoob  //输入get命令，查看runoob的值，服务器返回key的值，并以END结尾

第三步，攻击者请求获取数据

攻击者将自身IP伪造成攻击的目标IP地址，向Memcached服务器发送请求，读取在Memcached中存储的数据。
get命令用于获取存储在key(键)中的value(数据值)，如果key不存在，则返回空。
 
例子：
在下面的例子中，使用runoob作为key，过期时间设置为900秒，字节数为9
set runoob 0 900 9  //输入key：runoob
memcached  //输入runoob的值
get runoob  //查看runoob的值
 

第四步，memcached向被攻击者发送攻击者请求的数据

Memcached在收到攻击者的请求后，将请求的结果发送给伪造的源地址，也就是被攻击者的IP。由于放大倍数巨大，造成拒绝服务。
