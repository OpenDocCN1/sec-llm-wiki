一、操作目的和应用场景

ubuntu 1804系统使用AppArmor对容器实施强制访问控制。

二、平台及工具版本

操作系统：ubuntu 1804
软件：docker-ce 18

三、操作步骤

（一）安装AppArmor

1、 在线安装

apt install apparmor-utils apparmor-profiles apparmor-profiles-extra
apparmor-utils是一组用户空间的命令行实用工具，用于管理AppArmor。后两者是一些预先配置的配置文件，这些配置文件一般来说是比较完善的，但是也需要根据实际需要进行修改。
 

2、 查看AppArmor是否已被启用

aa-enabled



（二）禁用/启用AppArmor

1、 禁用AppArmor

(1) 关闭/禁用服务

sudo systemctl stop apparmor
sudo systemctl disable apparmor
 
ubuntu 16之前的系统：
sudo invoke-rc.d apparmor stop
sudo update-rc.d -f apparmor remove
 

(2) 在内核中禁用AppArmor

vi /etc/default/grub  //编辑配置文件，加入下面的行
* 'apparmor=0'  //禁用AppArmor
或者
* 'security=""'  //禁用LSM
或者
* 'security="selinux"'  //启用selinux
保存退出。
 

2、 重新启用AppArmor

安装AppArmor后，AppArmor是默认自动启动的。如果按照前面的方式禁用了AppArmor，则可使用下面的命令重新启用AppArmor。
确认在/etc/default/grub文件中没有禁用AppArmor。
确认安装了apparmor软件包。
systemctl enable apparmor
systemctl start apparmor
 
ubuntu 16之前的系统启动apparmor：
sudo invoke-rc.d apparmor start
sudo update-rc.d apparmor start 37 S .
//重新加载全部配置文件
sudo service apparmor reload
 

（三）管理AppArmor的配置文件

1、 配置文件的路径

AppArmor通过配置文件来管理各个程序的权限。配置文件的文件名通常是其控制的程序的完整路径名（比如/etc/apparmor.d/usr.sbin.nginx是控制Nginx的配置文件）。生效的配置文件的位置是/etc/apparmor.d，而一些可选的配置文件夹位于 /usr/share/apparmor/profiles目录。
使用下面的命令，通过软链接将配置文件链接到/etc/apparmor.d，从而启用配置。
ln -s /usr/share/apparmor/extra-profiles/usr.sbin.sshd /etc/apparmor.d
 

5、 配置文件的状态

(1) 配置文件的三种状态

在AppArmor中，每一个配置文件都有三种状态（模式）：enforce、complain以及disable。分别使用aa-enforce <程序名>, aa-complain <程序名> 以及aa-disable <程序名>来切换程序配置文件的状态。
enforce：强制模式，这种模式下，所有没有被授权的行为都会被禁止并且记录。
complain：抱怨模式，此时未授权行为会被放行，但是也会被记录。
disable：此时对应配置文件不加载，没有对程序行为进行限制。
 

(2) 查看AppArmor所有配置文件的状态

aa-status

省略一部分输出

输出显示装载了多少个配置文件，有哪些配置文件分别处于强制模式、抱怨模式和禁用状态。输出还显示有多少进程有配置文件，其中哪些处于强制模式/抱怨模式，以及哪些未指定模式。
 

(3) 将配置文件切换到抱怨模式

sudo aa-complain /bin/ping
 

(4) 将配置文件切换到强制模式

sudo aa-enforce /bin/ping
 

(5) 禁用配置文件

sudo ln -s /etc/apparmor.d/bin.ping /etc/apparmor.d/disable/
sudo apparmor_parser -R /etc/apparmor.d/bin.ping
 

3、 配置文件的格式

下面我们来看一个典型的配置文件：/etc/apparmor.d/usr.sbin.nginx ：
# Last Modified: Thu May 21 22:05:25 2020
#include <tunables/global>
 
/usr/sbin/nginx {
  #include <abstractions/apache2-common>
  #include <abstractions/base>
 
  capability dac_override,
  capability setgid,
  capability setuid,
 
  deny /srv/private/** rw,
  /etc/nginx/** r,
  /srv/www/** r,
  /var/lib/nginx/ rw,
  /var/log/nginx/* w,
  /var/www/html r,
  /etc/group r,
  /etc/nginx/cert.d/* r,
  /etc/nginx/conf.d/* r,
  /etc/nsswitch.conf r,
  /etc/passwd r,
  /etc/ssl/openssl.cnf r,
  /run/nginx.pid rw,
  /usr/lib/nginx/** m,
  /usr/share/nginx/modules-available/* r,
  /var/lib/nginx/** rw,
}
 
解读：
#include指令可以用于包含其他的配置文件和预定义规则，便于实现规则的架构化。
capability指令用于授权一系列特殊权限，比如在这个例子里就授权了dac_override （修改DAC列表）、suid和guid权限。
network指令对于网络的报文和地址绑定进行限制。（比如 network raw）
对文件系统进行限制，可指定文件和目录的读写权限。规则是 ：
[audit] [deny] filename rights，即是否开启审计、禁止、文件名以及对应的权限。下面是文件系统限制的具体说明：
Ø audit：表示开启审计
Ø deny：表示对匹配该条规则的行为直接禁止
Ø filename：可以使用 * 和 ** 通配符， * 表示目录下的所有文件，而 ** 则进行了递归。filename还可以使用一些预定义的变量，比如 @{HOME} 和 @{PROC} 等。
Ø AppArmor对读写权限进行了进一步细化，包括了：‘r’ (r), ‘w’ (write), ’m' (memory map as executable), ‘k’ (file locking), and ‘l’ (creation hard links) 等等。
 
4、 配置文件的加载/禁用

(1) 禁用某个配置文件

sudo ln -s /etc/apparmor.d/bin.ping /etc/apparmor.d/disable/
sudo apparmor_parser -R /etc/apparmor.d/bin.ping
-R, --remove
 

(1) 启用某个配置文件

profile在默认情况下都是被启用的（被装载到内核并应用到进程）。
sudo rm /etc/apparmor.d/disable/bin.ping
sudo apparmor_parser -r -W /etc/apparmor.d/bin.ping
-r, --replace
-W, --write-cache
 

5、 修改配置文件

配置文件文件都在/etc/apparmor.d目录中。它们都是简单的文本文件，可使用文本编辑器或者aa-logprof进行编辑。
可以在/etc/apparmor.d/tunables/目录实施某些自定义操作。例如定义别名等。


在更新配置文件的时候主要使用正确的操作。例如下面的情况：
不要使用：
  /home/*/ r,
要使用：
  @{HOME}/ r,
更新配置文件之后，一定要重新加载它：
sudo apparmor_parser -r -W /etc/apparmor.d/bin.ping
 

6、 创建新的配置文件

首先使用aa-autodep命令为指定程序生成一个初始化的配置文件。
aa-autodep ifconfig


第二步，使用aa-complain命令将这个配置文件指定为抱怨模式，这时候会记录所有需要授权的行为。
aa-complain ifconfig


第三步，使用了ifconfog命令一段时间后，使用aa-logprof确认允许的操作。aa-logprof会读取日志中所有操作，然后逐条询问之后是否允许这样的操作。（A 运行，D 不允许， I 忽略，G 改用通配符，N 修改规则）。然后把你的回应写入到对应的配置文件中去，从而形成了符合你需求的配置文件。


回答aa-logprof提出的问题，aa-logprof随后将你的选择写入配置文件。
 
cat /etc/apparmor.d/sbin.ifconfig  //查看配置文件


aa-logprof命令的回答都被加入到了配置文件。
 
第四步，可以直接修改规则配置文件。
vi /etc/apparmor.d/sbin.ifconfig
 
第五步，测试一段时间且规则没有问题后，可以使用aa-enforce开启 enforce模式。
aa-enforce /etc/apparmor.d/sbin.ifconfig

 
最后查看apparmor状态：


可以看到，/sbin/ifconfig已经处于强制模式了。
 

（四）为docker容器创建配置文件

1、 默认的配置文件

在不为容器指定AppArmor配置文件的情况下，默认使用docker自带的配置文件，名为docker-default。
 

2、 使用自定义配置文件

(1) 创建配置文件

现在我们为nginx容器创建下面的配置文件：
//创建用于保存容器配置文件的目录
mkdir /etc/apparmor.d/containers  && cd /etc/apparmor.d/containers
//创建并编辑配置文件
vi docker-nginx  //编辑文件，加入下面的内容
#include <tunables/global>
 
profile docker-nginx flags=(attach_disconnected,mediate_deleted) {
  #include <abstractions/base>
 
  network inet tcp,
  network inet udp,
  network inet icmp,
 
  deny network raw,
  deny network packet,
 
  file,
  umount,
 
  deny /bin/** wl,
  deny /boot/** wl,
  deny /dev/** wl,
  deny /etc/** wl,
  deny /home/** wl,
  deny /lib/** wl,
  deny /lib64/** wl,
  deny /media/** wl,
  deny /mnt/** wl,
  deny /opt/** wl,
  deny /proc/** wl,
  deny /root/** wl,
  deny /sbin/** wl,
  deny /srv/** wl,
  deny /tmp/** wl,
  deny /sys/** wl,
  deny /usr/** wl,
 
  audit /** w,
 
  /var/run/nginx.pid w,
 
  /usr/sbin/nginx ix,
 
  deny /bin/dash mrwklx,
  deny /bin/sh mrwklx,
  deny /usr/bin/top mrwklx,
 
  capability chown,
  capability dac_override,
  capability setuid,
  capability setgid,
  capability net_bind_service,
 
  deny @{PROC}/* w,   # deny write for all files directly in /proc (not in a subdir)
  # deny write to files not in /proc/<number>/** or /proc/sys/**
  deny @{PROC}/{[^1-9],[^1-9][^0-9],[^1-9s][^0-9y][^0-9s],[^1-9][^0-9][^0-9][^0-9]*}/** w,
  deny @{PROC}/sys/[^k]** w,  # deny /proc/sys except /proc/sys/k* (effectively /proc/sys/kernel)
  deny @{PROC}/sys/kernel/{?,??,[^s][^h][^m]**} w,  # deny everything except shm* in /proc/sys/kernel/
  deny @{PROC}/sysrq-trigger rwklx,
  deny @{PROC}/mem rwklx,
  deny @{PROC}/kmem rwklx,
  deny @{PROC}/kcore rwklx,
 
  deny mount,
 
  deny /sys/[^f]*/** wklx,
  deny /sys/f[^s]*/** wklx,
  deny /sys/fs/[^c]*/** wklx,
  deny /sys/fs/c[^g]*/** wklx,
  deny /sys/fs/cg[^r]*/** wklx,
  deny /sys/firmware/** rwklx,
  deny /sys/kernel/security/** rwklx,
}
保存退出。
可以看到，在配置文件中有如下的指令：
deny /bin/dash mrwklx,
deny /bin/sh mrwklx,
禁止访问/bin/dash和/bin/sh。下面我们做个测试，看这两个程序还能不能运行。
 

(6) 测试配置文件的效果

//启用配置文件
sudo apparmor_parser -r -W /etc/apparmor.d/containers/docker-nginx
 
//启动容器并加载指定的AppArmor配置文件
docker run --security-opt "apparmor=docker-nginx" -p 80:80 -d --name apparmor-nginx nginx

//进入nginx容器中
docker container exec -it apparmor-nginx bash

//执行测试


拒绝访问sh和dash，但是bash可以运行，说明配置文件生效了。
