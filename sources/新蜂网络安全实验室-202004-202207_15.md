## （三）**管理****AppArmor****的配置文件**

### 1、 **配置文件的路径**

AppArmor通过配置文件来管理各个程序的权限。配置文件的文件名通常是其控制的程序的完整路径名（比如/etc/apparmor.d/usr.sbin.nginx是控制Nginx的配置文件）。生效的配置文件的位置是/etc/apparmor.d，而一些可选的配置文件夹位于 /usr/share/apparmor/profiles目录。使用下面的命令，通过软链接将配置文件链接到/etc/apparmor.d，从而启用配置。ln -s /usr/share/apparmor/extra-profiles/usr.sbin.sshd /etc/apparmor.d 

### 5、 **配置文件的状态**

#### (1) **配置文件的三种状态**

在AppArmor中，每一个配置文件都有三种状态（模式）：enforce、complain以及disable。分别使用aa-enforce <程序名>, aa-complain <程序名> 以及aa-disable <程序名>来切换程序配置文件的状态。enforce：强制模式，这种模式下，所有没有被授权的行为都会被禁止并且记录。complain：抱怨模式，此时未授权行为会被放行，但是也会被记录。disable：此时对应配置文件不加载，没有对程序行为进行限制。 

#### (2) **查看AppArmor所有配置文件的状态**

### 3、 **配置文件的格式**

下面我们来看一个典型的配置文件：/etc/apparmor.d/usr.sbin.nginx ：  
\# Last Modified: Thu May 21 22:05:25 2020#include <tunables/global> /usr/sbin/nginx {  #include <abstractions/apache2-common>  #include <abstractions/base>   capability dac\_override,  capability setgid,  capability setuid,   deny /srv/private/\*\* rw,  /etc/nginx/\*\* r,  /srv/www/\*\* r,  /var/lib/nginx/ rw,  /var/log/nginx/\* w,  /var/www/html r,  /etc/group r,  /etc/nginx/cert.d/\* r,  /etc/nginx/conf.d/\* r,  /etc/nsswitch.conf r,  /etc/passwd r,  /etc/ssl/openssl.cnf r,  /run/nginx.pid rw,  /usr/lib/nginx/\*\* m,  /usr/share/nginx/modules-available/\* r,  /var/lib/nginx/\*\* rw,} 解读：#include指令可以用于包含其他的配置文件和预定义规则，便于实现规则的架构化。capability指令用于授权一系列特殊权限，比如在这个例子里就授权了dac\_override （修改DAC列表）、suid和guid权限。network指令对于网络的报文和地址绑定进行限制。（比如 network raw）对文件系统进行限制，可指定文件和目录的读写权限。规则是 ：\[audit\] \[deny\] filename rights，即是否开启审计、禁止、文件名以及对应的权限。下面是文件系统限制的具体说明：Ø audit：表示开启审计Ø deny：表示对匹配该条规则的行为直接禁止Ø filename：可以使用 \* 和 \*\* 通配符， \* 表示目录下的所有文件，而 \*\* 则进行了递归。filename还可以使用一些预定义的变量，比如 @{HOME} 和 @{PROC} 等。Ø AppArmor对读写权限进行了进一步细化，包括了：‘r’ (r), ‘w’ (write), ’m' (memory map as executable), ‘k’ (file locking), and ‘l’ (creation hard links) 等等。 4、 **配置文件的加载****/****禁用**

### 6、 **创建新的****配置文件**

首先使用aa-autodep命令为指定程序生成一个初始化的配置文件。aa-autodep ifconfig

第二步，使用aa-complain命令将这个配置文件指定为抱怨模式，这时候会记录所有需要授权的行为。aa-complain ifconfig  
![](../Images/39e9bde7ec59b58e258e0125800ad6ad.png)  
第三步，使用了ifconfog命令一段时间后，使用aa-logprof确认允许的操作。aa-logprof会读取日志中所有操作，然后逐条询问之后是否允许这样的操作。（A 运行，D 不允许， I 忽略，G 改用通配符，N 修改规则）。然后把你的回应写入到对应的配置文件中去，从而形成了符合你需求的配置文件。

![](../Images/d5b8306a85f8c4226fe899c14f07298d.png)  
aa-logprof命令的回答都被加入到了配置文件。 第四步，可以直接修改规则配置文件。vi /etc/apparmor.d/sbin.ifconfig 第五步，测试一段时间且规则没有问题后，可以使用aa-enforce开启 enforce模式。aa-enforce /etc/apparmor.d/sbin.ifconfig

## （四）**为docker容器创建配置文件**

### 1、 **默认的配置文件**

在不为容器指定AppArmor配置文件的情况下，默认使用docker自带的配置文件，名为docker-default。 

### 2、 **使用自定义配置文件**

#### (1) **创建配置文件**

现在我们为nginx容器创建下面的配置文件：//创建用于保存容器配置文件的目录mkdir /etc/apparmor.d/containers  && cd /etc/apparmor.d/containers//创建并编辑配置文件vi docker-nginx  //编辑文件，加入下面的内容#include <tunables/global> profile docker-nginx flags=(attach\_disconnected,mediate\_deleted) {  #include <abstractions/base>   network inet tcp,  network inet udp,  network inet icmp,   deny network raw,  deny network packet,   file,  umount,   deny /bin/\*\* wl,  deny /boot/\*\* wl,  deny /dev/\*\* wl,  deny /etc/\*\* wl,  deny /home/\*\* wl,  deny /lib/\*\* wl,  deny /lib64/\*\* wl,  deny /media/\*\* wl,  deny /mnt/\*\* wl,  deny /opt/\*\* wl,  deny /proc/\*\* wl,  deny /root/\*\* wl,  deny /sbin/\*\* wl,  deny /srv/\*\* wl,  deny /tmp/\*\* wl,  deny /sys/\*\* wl,  deny /usr/\*\* wl,   audit /\*\* w,   /var/run/nginx.pid w,   /usr/sbin/nginx ix,   deny /bin/dash mrwklx,  deny /bin/sh mrwklx,  deny /usr/bin/top mrwklx,   capability chown,  capability dac\_override,  capability setuid,  capability setgid,  capability net\_bind\_service,   deny @{PROC}/\* w,   # deny write for all files directly in /proc (not in a subdir)  # deny write to files not in /proc/<number>/\*\* or /proc/sys/\*\*  deny @{PROC}/{\[^1-9\],\[^1-9\]\[^0-9\],\[^1-9s\]\[^0-9y\]\[^0-9s\],\[^1-9\]\[^0-9\]\[^0-9\]\[^0-9\]\*}/\*\* w,  deny @{PROC}/sys/\[^k\]\*\* w,  # deny /proc/sys except /proc/sys/k\* (effectively /proc/sys/kernel)  deny @{PROC}/sys/kernel/{?,??,\[^s\]\[^h\]\[^m\]\*\*} w,  # deny everything except shm\* in /proc/sys/kernel/  deny @{PROC}/sysrq-trigger rwklx,  deny @{PROC}/mem rwklx,  deny @{PROC}/kmem rwklx,  deny @{PROC}/kcore rwklx,   deny mount,   deny /sys/\[^f\]\*/\*\* wklx,  deny /sys/f\[^s\]\*/\*\* wklx,  deny /sys/fs/\[^c\]\*/\*\* wklx,  deny /sys/fs/c\[^g\]\*/\*\* wklx,  deny /sys/fs/cg\[^r\]\*/\*\* wklx,  deny /sys/firmware/\*\* rwklx,  deny /sys/kernel/security/\*\* rwklx,}保存退出。可以看到，在配置文件中有如下的指令：deny /bin/dash mrwklx,deny /bin/sh mrwklx,禁止访问/bin/dash和/bin/sh。下面我们做个测试，看这两个程序还能不能运行。
