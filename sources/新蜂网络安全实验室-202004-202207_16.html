（一）概述

在这个例子中，容器启动时通过--privileged=true指定其拥有特权，并通过--pid=host将宿主机的PID名称空间映射到容器中。
特权状态的容器具有cap_sys_ptrace的capability，容器中运行的进程作为容器的子进程也拥有这个capability。具有cap_sys_ptrace能力的进程可以获取其它进程的系统调用，恶意程序可以利用cap_sys_ptrace将代码注入其它进程的地址空间并执行。
由于指定了启动参数--pid=host，因此容器中可以访问宿主机的进程，那么容器中的恶意程序即可将自身代码注入到宿主机的进程中，从而在宿主机中执行操作。这样就形成了容器逃逸。

容器所在宿主机（虚拟机）：debian，192.168.242.135
攻击者机器（虚拟机）：debian，192.168.242.137
测试环境下载地址：https://sourceforge.net/projects/defcon-26-container-security/
 

（二）过程

1、 理解docker的PID名称空间

PID namespace使宿主机和各个容器各有自己的PID名称空间，互不冲突。由于容器有自己的PID名称空间，使得容器在迁移到新的宿主机后PID还可以保持不变。
举例来说，当我们运行一个nginx容器，nginx进程在容器内的PID总是1，但在主机上的PID是不同的。
//创建容器
docker run --rm --name=samplewebapp1 -d nginx:alpine
//宿主机查看nginx进程
ps aux | grep nginx
//进入samplewebapp1容器
docker exec -it samplewebapp1 sh
//容器内查看nginx进程
ps aux | grep nginx

 
可以看到，nginx进程在宿主机中的PID为4394，但是在容器中的PID为1和31。
 
//创建另一个容器
docker run --rm --name=samplewebapp2 -d nginx:alpine
//宿主机查看nginx进程
ps aux | grep nginx
//进入samplewebapp1容器
docker exec -it samplewebapp2 sh
//容器内查看nginx进程
ps aux | grep nginx


可以看到，不同容器中nginx进程的PID相同，都是1和31，但是并不冲突。这就是PID名称空间的隔离效果。
 
可以将宿主机的PID名称空间或者其它容器的PID名称空间映射到容器中。
//创建容器，并将宿主机的PID名称空间映射到容器中
docker run --pid=host --rm --name=samplewebapp3 -d nginx:alpine
//进入容器
docker exec -it samplewebapp3 sh
//查看进程列表
ps aux


看到的是宿主机的进程列表。通过这种方式，容器中的监控软件可以对宿主机中的进程进行监控。
 
//创建新的容器，并将其它容器的PID名称空间映射到本容器
docker run --pid=container:samplewebapp1 --rm --name=samplewebapp4 -d nginx:alpine  
docker exec -it samplewebapp4 sh
ps aux  //查看进程列表


可以看到，两个容器的PID名称空间叠加在一起，也并没有冲突。这样就为容器之间进程的访问提供了途径。
 

2、 容器逃逸的例子

docker run --rm -it --privileged=true --pid=host --name sysmon sysmon /bin/bash


容器启动后，在容器中可以看到宿主机的进程列表。
