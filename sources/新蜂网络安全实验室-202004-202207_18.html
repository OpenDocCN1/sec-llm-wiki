一、操作目的和应用场景

docker 1.13启用selinux实施强制访问控制。

 

二、平台及工具版本

操作系统：CentOS 7

软件：docker 1.13

 

三、操作步骤

（一）docker启用selinux防护

步骤一，在操作系统层面启用selinux

vi /etc/selinux/config  //编辑selinux的配置文件，设置

SELINUX=enabled

SELINUXTYPE=targeted

保存退出。

reboot  //重启服务器

 

步骤二，查看docker的安全选项

docker info | grep -A 3 "Security Options"  //查看宿主机支持的docker安全选项



可以看到，docker当前是支持selinux的。注意，在操作系统没有启用selinux的情况下，docker的安全选项中是看不到selinux的。

 

步骤三，在docker服务中启用selinux

docker 1.13版本默认启用了selinux。

在/etc/sysconfig/docker文件中的OPTIONS中指定了--selinux-enabled：



ps aux | grep docker | grep selinux  //确认docker进程是否含有selinux选项



可以看到，docker进程的选项中带有--selinux-enabled，也就是说，启用了selinux。

 

（二） 容器的安全标签

//启动测试用的容器

docker run --rm -d --name ubuntu-1 ubuntu:latest /bin/sleep 1000

//查看容器的安全标签

docker inspect ubuntu-1 | grep "Label"



容器被赋予了多个标签。

 

//再启动一个容器

docker run --rm -d --name ubuntu-2 ubuntu:latest /bin/sleep 1000

//查看容器的安全标签

docker inspect ubuntu-2 | grep "Label"

 

可以看到，这两个容器各有两个安全标签，分别是MountLabel和ProcessLabel。MountLabel的type都被设置为svirt_sandbox_file_t，ProcessLabel的type都被设置为svirt_lxc_net_t。安全标签的最后一个字段是Category，对于不同容器来说是不同的（SELinux的MCS隔离机制）。正是因为Category字段不同，所以两个不同容器中的进程无法访问对方创建的资源。

MountLabel标签中的svirt_sandbox_file_t类型限制容器对文件系统的访问。如果文件被标记为svirt_sandbox_file_t，那么所有容器都可以访问这个文件。

Process标签中的svirt_lxc_net_t类型用于进程之间的防护。该类型将容器与宿主机隔离开，并产生一个唯一的多类别安全标签，以防止容器进程访问其它容器中的进程和内容。

 

（三）在docker中禁用selinux

一些情况下，为了解决容器的某些问题，可能需要禁用selinux。

第一种方式：在操作系统层面禁用selinux

vi /etc/selinux/config  //编辑配置文件

SELINUX=disabled



保存退出。重启计算机。

包括docker在内，整个操作系统都失去了selinux的保护。

 

第二种方式，在docker服务中禁用selinux

在操作系统启动selinux的情况下，在docker服务的选项中禁用selinux。

vi /etc/sysconfig/docker  //编辑配置文件，设置

--selinux-enabled=false



保存退出

systemctl restart docker  //重启docker服务

 

//查看服务进程的选项

ps aux | grep docker | grep selinux



可以看到，服务进程的参数中带有--selinux-enabled=false

 

//启动容器

docker run --rm -d --name ubuntu-1 ubuntu:latest /bin/sleep 1000

docker run --rm -d --name ubuntu-2 ubuntu:latest /bin/sleep 1000

//查看容器的安全标签



在docker服务中禁用selinux防护之后，所有的容器都受到影响。安全标签被请空了，这样不同的docker容器可以相互访问资源。如果一个容器失陷，则其它容器也会受到攻击。

 

第三种方式，针对特定的docker容器禁用selinux

在操作系统和docker服务中都启用了selinux的情况下，针对特定的容器禁用selinux。

//以禁用selinux的方式启动容器

docker run --rm -d --security-opt label:disable --name ubuntu-1 ubuntu:latest /bin/sleep 1000

//正常方式启动另一个容器

docker run --rm -d --name ubuntu-2 ubuntu:latest /bin/sleep 1000

//查看容器的安全标签



可以看到，禁用selinux的方式启动的容器，其ProcessLabel的内容是空的。

2、 数据卷无法设置为只允许某一个容器访问

解决的思路是，启动容器时为数据卷目录重新打上容器的标签，以只允许本容器访问。

//第一个容器为数据卷目录重新打标签

docker run --rm -d -it /test1:/test1:Z --name ubuntu-1 ubuntu:latest /bin/bash


 

可以看到，数据卷目录以及在其中所创建文件的安全标签中包含ubuntu-1容器的的catagory。


//第二个容器使用默认的标签

docker run --rm -it -v /test1:/test1 --name ubuntu-2 ubuntu:latest /bin/bash



由于标签不匹配，ubuntu-2容器虽然挂载了数据卷目录/test1，但是无法访问该目录。数据卷目录只能被ubuntu-1容器访问。
