# 一、**操作目的和应用场景**

## （一）**目的**

docker 1.13通过seccomp限制容器执行不安全的系统调用。 

## （二）**简介**

### 1、 **什么是seccomp**

seccomp的全称为secure computing mode，是linux kernel从2.6.23版本开始所支持的一种安全机制。在Linux系统里，默认情况下，所有的系统调用（syscall）直接暴露给用户态程序。但用户态程序并不一定需要执行所有的系统调用，而且恶意程序还可能通过系统调用对系统造成破坏。所以，我们通过seccomp对允许进程使用的系统调用进行限制，以减小系统的受攻击面。 

### 2、 **seccomp支持的模式**

seccomp支持两种模式：SECCOMP\_MODE\_STRICT和SECCOMP\_MODE\_FILTER。在SECCOMP\_MODE\_STRICT模式下，进程不能使用read(2)、write(2)、\_exit(2)和sigreturn(2)以外的其他系统调用。在SECCOMP\_MODE\_FILTER模式下，可以利用Berkeley Packet Filter配置哪些系统调用及它们的参数可以被进程使用。 

### 3、 **seccomp的例子**

#### (1) **不使用seccomp进行编码**

//安装gccyum install gcc //创建源码文件touch simple\_syscall.cvi simple\_syscall.c  //编辑代码，加入下面的内容#include <stdio.h>int main(void){         char \* filename = "/bin/sh";         char \* argv\[\] = {"/bin/sh",NULL};         char \* envp\[\] = {NULL};         write(1,"i will give you a shell\\n",24);         syscall(59,filename,argv,envp);  //execve         return 0;}保存退出 //编译gcc -g simple\_syscall.c -o simple\_syscall //执行./simple\_syscall  
![](../Images/3c0d37f1749ee93b09ac964c4d61d174.png)  
得到了shell，说明可以执行execve系统调用。  
 

#### (2) **使用seccomp进行编码**

//安装seccompyum install libseccomp libseccomp-devel seccomp touch simple\_syscall\_seccomp.cvi simple\_syscall\_seccomp.c  //编辑代码，加入下面的内容#include<unistd.h>#include<seccomp.h>#include<sys/syscall.h> int main(){scmp\_filter\_ctx ctx;ctx = seccomp\_init(SCMP\_ACT\_ALLOW);  //初始化过滤状态为允许所有系统调用seccomp\_rule\_add(ctx, SCMP\_ACT\_KILL, SCMP\_SYS(execve), 0);  //添加被限制的系统调用seccomp\_load(ctx);  char \* filename = "/bin/sh";char \* argv\[\] = { "/bin/sh", NULL };char \* envp\[\] = { NULL };write(1,"i will give you a shell\\n",24);syscall(59, filename, argv, envp);return 0;}保存退出。多了seccomp的四行代码，禁止进程执行execve。 //编译gcc -g simple\_syscall\_seccomp.c -o simple\_syscall\_seccomp -lseccomp //运行./simple\_syscall\_seccomp  
![](../Images/eb8e3b724ab6841ec07edd6f8280e726.png)  
提示错误的系统调用，程序终止，无法得到shell。通过上面的例子可以了解到，seccomp机制可以禁止进程访问特定的系统调用。  

# 二、**操作步骤**

## （一）**查看对****seccomp****的支持**

### 1、 **查看内核对****seccomp的支持**

cat /boot/config-\`uname -r\` | grep CONFIG\_SECCOMP=  
![](../Images/3023291bd9205a02420fc485e4a3055a.png)  
CentOS 7系统是支持seccomp功能的。 

### 2、 **查看****docker****支持的****安全选项**

docker info | grep -A 3 "Security Options"  
![](../Images/312ca7469eff1c37cb1f1a081482a54d.png)  
docker支持的安全选项中包括seccomp。 

## （二）**在docker服务和容器中使用seccomp**

### 方法1、 **在docker服务配置文件中指定seccomp**

docker服务默认是启用seccomp功能的，查看docker的服务配置文件：cat /usr/lib/systemd/system/docker.service | less在ExecStart指令中，docker守护进程启动的时候指定了--seccomp-profile=/etc/docker/seccomp.json  
![](../Images/039db1b8767536aef248763a1cd56e9c.png)  
从服务配置文件中可以看到，默认情况下，使用/etc/docker/seccomp.json文件作为seccomp的配置文件。该文件定义了允许容器进程执行的系统调用。  
![](../Images/bc6f308edbe838dcd1ae0c573a659b37.png)  
实际上，该配置文件是白名单，默认情况下阻止访问所有的系统调用，然后将特定的系统调用列入白名单。  

### 方法2、 **在启动容器时指定seccomp选项**

docker服务默认以seccomp方式启动，如果在启动容器的时候不指定seccomp选项，则容器进程也使用与docker服务相同的seccomp设置。若要让容器进程使用与服务不同的seccomp设置，须在启动容器时指定seccomp选项。 

#### (1) **以指定自定义seccomp配置文件的方式启动容器**

docker run --rm -it --security-opt seccomp=/path/to/seccomp.json ubuntu:latest /bin/bash  

#### (2) **以不使用seccomp机制的方式启动容器**

docker run --rm -it --security-opt seccomp=unconfined ubuntu:latest /bin/bash
