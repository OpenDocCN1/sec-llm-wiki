大家好，我是彭瑞。最近我在研究内网渗透，想在公众号中为大家分享一些相关的技术。这篇文档主要是讲通过reGeorg搭建socks代理，进而实现内网穿透的方法。

网上内网渗透的文章很多，现在也出版了一些书籍涉及到内网渗透的内容。但是我希望通过我的文章，通过自己的实际研究，最大程度地把技术讲清楚。

reGeorg是reDuh的升级版，它利用webshell建立socks代理以实现内网穿透。作为跳板机的web服务器使用的语言可以是aspx、php或jsp中的一种。

  

那么什么是socks？

![](../Images/50abc36f87e31cb3cb63a6a408e250ef.png)

wikipedia是这样解释的：“SOCKS是一种网络传输协议，主要用于客户端与外网服务器之间通讯的中间传递。SOCKS是"SOCKetS"的缩写。当防火墙后的客户端要访问外部的服务器时，就跟SOCKS代理服务器连接。这个代理服务器控制客户端访问外网的资格，允许的话，就将客户端的请求发往外部的服务器。SOCKS工作在比HTTP代理更低的层次：SOCKS使用握手协议来通知代理软件其客户端试图进行的SOCKS连接，然后尽可能透明地进行操作，而常规代理可能会解释和重写报头。”（不要看百度百科上的解释，你懂的）

从上面的描述可以看出，socks代理是转发数据的一种机制，并且其工作透明，不会重写报头，也就是说，不会修改端口号、确认号以及数据等内容。这样代理两端的通信内容可以最大程度地保持原样，好处一是连接的速度快，二是通信的类型和内容不会受到局限。

对于网络渗透来说，攻击者无法直接连接到防火墙后的内网主机。但是如果存在这样一台机器，它与攻击者之间是连通的，与内网主机之间也是连通的，那么如果能在这台机器上安装socks代理服务，就可以通过代理服务将攻击者的任意请求转发给内网机，从而实现攻击者对内网机不受限制的访问。

## （二）**使用**

### **1、攻击场景**

攻击者（192.168.1.5）位于外网，无法访问目标网络内部的主机。但是攻击者可以访问目标网络中对外提供服务的web服务器（192.168.1.11），这台web服务器拥有内网IP地址（192.168.56.112），可以访问内网机器。于是攻击者以这台web服务器为跳板，攻击内网机器（192.168.56.101）。

![](../Images/525f729656808227c1e3184bcfc5ff51.png)

  

### **2、攻击方法**

(1）上传webshell

攻击过程开始。首先将reGeorg软件包中的tunnel.jsp部署在跳板机（web服务器）上（实际工作中一般是利用上传/SQL注入等漏洞，最好修改webshell的名字以增强隐蔽性）。

jspstudy的网站发布目录为C:\\jspstudy\\WWW，复制到这个目录中即可。

测试一下，攻击者用浏览器访问webshell：

![](../Images/1d7fbf09bed793c277dbae3cf80f861d.png)

webshell的回应为“All seems fine.”，视其为工作正常。

 

（2）攻击者本地运行客户端程序，连接web服务器上的webshell。同时在本地启动socks服务，监听本地的8080端口。

python reGeorgSocksProxy.py -p 8080 \-u http://192.168.1.11/tunnel.jsp

![](../Images/00722db9c3128dd149bd16264b973516.png)

工作正常。这样就在本机和跳板机192.168.1.11之间建立了隧道。

 

（3）攻击者本地运行全局代理

如果攻击者使用的是linux系统，可使用proxychains作为全局代理（是的，它也是个socks代理，加上reGeorg就是两层socks代理了）。以proxychains为例，说明全局代理的用法：

apt install proxychains  //安装proxychains  

vi /etc/proxychains.conf  //配置proxychains

将最后一行的socks4注释掉，添加下面的行，端口为reGeorg的socks服务监听的8080：

socks5  127.0.0.1 8080

保存退出

 

（4）访问内网主机

proxychains telnet 192.168.56.101  //连接内网主机的telnet服务。

![](../Images/ab17975e47cd4a8850097a23bb1e4f72.png)

可以成功连接到192.168.56.101的telnet服务，但是数据包的源地址是攻击者还是跳板机呢？

在内网机上抓包：

tcpdump -i eth0 port 23 -n

![](../Images/0e1a96242983b6770bb0152e09b60e5f.png)

可以看到，telnet连接的源地址是跳板机的内网地址192.168.56.112。这说明攻击者已经将跳板机做成了中转站，可以在内网中访问了。

由此我们可以这样解释内网穿透的实现过程：攻击者发出的telnet请求首先会被proxychains发送给本地的8080端口，reGeorg的socks服务会将其转发到http隧道的另一端—跳板机（web服务器）的外网口地址，跳板机再将数据包从其内网口传出，并将数据包的源地址改为跳板机的内网口IP地址。这样，攻击者的请求从跳板机的内网口发出，内网目标的回应也会被传输到跳板机的内网口，之后跳板机再将目标的回应通过http隧道返回给攻击者，从而形成完整的回路。由于跳板机的内网口IP地址作为目标IP在内网是可路由的，因此可访问内网中所有路由可达的目标。这样就实现了所谓的内网穿透。

  

proxychains nmap 192.168.56.101  //nmap扫描内网机器端口，但是可能速度较慢。

![](../Images/6976d0514dd4f40aecffe964c2995a17.png)

  

proxychains ftp 192.168.56.101  //访问内网的ftp服务也是成功的

![](../Images/8cb3e4706aeaa479989ab58edc9055a3.png)

  

## （三）**总结**

使用reGeorg，只要目标网络存在web漏洞，我们就可以通过上传webshell进入企业内网，这还是非常实用的。但是在我的测试中，reGeorg出现了一些问题，一是它对php的支持不好，二是metasploit的某些功能无法正常实现。
