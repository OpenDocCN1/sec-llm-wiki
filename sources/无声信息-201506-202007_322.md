‍‍‍**1****‍ **‍背景与应用场景‍‍

‍‍**·****1.1 ****防火墙限制**‍

  

在做渗透时，假设你拿到了服务器的管理员权限，已经可以通过SSH在服务器上远程执行各种命令。

  

此时你发现该服务器上开着各种服务，如：Web服务，MySQL数据库服务之类的，想远程看这些东西的你却发现该服务器只允许通过22端口访问，其他端口的请求通通被防火墙过滤了。*（此处的防火墙当然不是指该服务器上的iptables啦，不然管理员权限吃素啊！）*

  

**· 1.2 其他场景**

  

在VPS上搭建SS做代理的时候，有一阵被GFW干扰的很严重，常用的端口都被阻断了，但是80端口却还可以用。

  

那么问题来了，能不能在保持VPS上搭建的网站正常运行的情况下，还能让SS使用80端口？虽然可以把Apache监听的端口改成8080之类的，但是别人以前访问我的网址是http://www.xxx.com，现在要变成http://www.xxx.com:8080（*违和感太重！*），那么现在就需要HTTP服务和SS服务能同时使用80端口，并且对外提供服务。

  

当然，还有必须同时使用同一个地址+协议+端口的情况。

  

怎么解决以上2个场景的问题？

  

有人说，加个网卡啊，2个IP地址不就行了，这样肯定是可以的，但是心有余而条件不足，这个时候就可以***“端口复用”***了。

  

在Windows XP以及更早的Windows版本上，使用“端口复用”**技术几乎没有限制**，低级权限的用户可以重绑定在高级权限的用户使用端口上。

  

**    如下表所示：**

  

![](../Images/162fad08ae4e7f94c49ea6fcfb66eafa.png)

  

可以看到，不管先绑定端口的程序是默认选项，还是加了SO\_REUSEADDR选项，只要后绑定的程序设置了SO\_REUSEADDR，就能端口复用成功。

  

正是因为如此，微软在Windows Server 2003之后增强了“端口复用”这方面的安全性。

  

**    如下表所示：**

  

![](../Images/9d3db3ef978474f73f0fd58e40868fc5.png)

  

Linux上对“端口复用”的处理类似Windows Server2003及更新版本Windows的处理方式。  

看来，“端口复用”也不好用啊，况且也至多能解决场景2的问题。

  

那么，我们需要一个**能够根据请求数据包内容/协议特征来选择服务的工具**，**一个代理不同协议的服务**，我将它命名为：***multiplexer***，一方面因为multiplexer有多工器，复用器的意思，另外在Github上看到类似的项目，也被命名为xxx-multiplexer。

  

  

  

**2** 原理与实现流程

  

既然TCP multiplexer实际上是一个反向代理服务器，那么它首先要作为一个Server端，供远程的用户Client连接，并对其提供服务；其次它需要作为Client端，转发用户的请求到最终的服务（如HTTP，SSH，MySQL等）上，并返回结果。

  

![](../Images/ec00cb0347db66979bfd8a12edb55ee4.png)

  

如上图所示，客户端通过某一端口，能够同时HTTP、SOCKS5等服务，TCP multiplexer通过解析客户端的数据包/请求，根据规则来选择相应的服务；“服务器A/B”的意思是TCP multiplexer服务可以和Apache Service、SOCKS5 Service放在同一台主机上，也可以放在不同的机器上。

  

学过网络编程的童鞋都知道，TCP网络编程中***编写服务器端的步骤是：***

a)创建/初始化套接字：socket

b)绑定套接字：bind

c)监听套接字：listen

d)接受连接请求：accept

e)接收/发送数据：recv/send

f)关闭套接字：close

***编写客户端的步骤是：***  

a) 创建/初始化套接字：socket

b) 连接远程服务器：connect

c) 接收/发送数据：recv/send

d) 关闭套接字：close

  

TCP multiplexer为了提高效率，接收到连接请求，就新建一个线程来处理；为了解析客户端的请求，选择相应的服务，提供了csv模版，修改csv文件，即可定制协议/服务复用规则，如：

  

![](../Images/85bfa2d246d838c8e6472b706d9f871b.png)

*表1 协议选择规则表*

  

其中name可随意填写，只是作为用户的备注标记；pattern是符合正则表达式的规则，remote\_addr和remote\_port是当客户端请求匹配规则时候，需要选择的服务。每个连接在进行规则匹配的时候，按从上到下顺序开始，匹配到之后，就用该规则，后面的规则就不生效。

  

详细的代码在：https://github.com/qiaofei32/tcp-multiplexer

  

  

  

3 如何定制规则

‍

  

**3‍.1 示例1-HTTP**

  

HTTP协议不多说了，大家都知道HTTP基于TCP协议，由三部分组成：请求行、消息报头、请求正文，典型的请求如：

  

GET https://www.baidu.com/ HTTP/1.1

Host: www.baidu.com

Connection: keep-alive

Accept: text/html ,\*/\*;q=0.8

Upgrade-Insecure-Requests: 1

User-Agent: Mozilla/5.0 Chrome/50.0.2661.102 Safari/537.36

Accept-Encoding: gzip, deflate, sdch, br

Accept-Language: zh-CN,zh;q=0.8,ja;q=0.6,zh-TW;q=0.4,be;q=0.2,en;q=0.2

…..(略)

  

  

那么HTTP协议第一个TCP请求的数据包是以GET/POST之类的请求的开始的，那么规则就是：” ^GET”或者” ^POST”之类的，如表1的“HTTP”规则。当然也可以使用HTTP的Header部分，如表1的“HTTP2”规则。

  

**3.2 示例2-SSH**

对其他协议如SSH协议，如果不清楚协议的构成和特征，可以使用抓包工具去分析。比如为了分析SSH协议特征，打开抓到的数据包，如图：

 

![](../Images/de45459d4d1913ee6fc79d806c41bc71.png)

  

输入条件过滤一下，或者肉眼慢慢找一下：

  

![](../Images/abc1b6f2adf6c09365753091b2b32ae8.png)

  

发现SSH协议的第一个客户端请求的特征为：SSH-2.0-SecureCRT\_7.2.1 (x64 build 443)

  

![](../Images/0adf8d59a003fd30ff04dd715cd63832.png)

  

经过查阅资料，SSH协议建立连接时，客户端第一个请求的格式为：“SSH－<主协议版本号>.<次协议版本号>－<软件版本号>”，这与上述的特征“SSH-2.0-SecureCRT\_7.2.1 (x64 build 443)”是一致的。那么，可以使用“^SSH”来建立SSH服务的规则。

该TCP multiplexer服务运行在IP地址为：192.168.1.219的ubuntu上，开启HTTP服务，如果没有装Apache之类的Web服务，用python一句话就可以：

python -m SimpleHTTPServer 80‍

  

![](../Images/9c4129ffe3fe63aa156bb7bc9185388b.png)

![](../Images/18bb666ae9d3a141206c11ce762312c4.png)

  

开启TCP复用器，监听9000端口，然后通过浏览器访问：

  

![](../Images/f5afedf10d0e60affa2569c2ea835e3d.png)

  

已经可以通过9000端口访问80端口的HTTP服务了。通过复用器的日志信息也可以看到连接请求：  

  

![](../Images/9428dccc3c87c38ca2ecfbb548e2a210.png)

  

接着试试能不能通过9000端口访问22端口的SSH服务，先查看本机的IP地址（192.168.1.254）：

  

![](../Images/2f4cbe37f9c29617e6208c4ab7f0b310.png)

![](../Images/188f5c52b5c8697e391b8159daaeddfc.png)

  

multiplexer的输出信息也能看到SSH的连接请求：

  

![](../Images/9857cbf83fd7fc6d2b202774bfe718aa.png)
