**Crypto\_TryHash**  
  

审计题目代码，题目给出了一个feistel结构的加密算法，密钥长度为8字节。用随机生成的密钥对flag进行了加密。攻击者可以提供一段明文让服务器用同样的密钥进行加密。

密钥长度为8字节，直接爆破的复杂度为2^64,是不太现实的。

本题密码算法的设计漏洞其实在于其轮函数f的设计。具体来说其轮函数具有较差的差分性质。

*   
*   
*

```
def g(self,v1,v2,x):      value = (v1+v2+x)%256      value = ((value<<3) | (value>>5)) &0xff      return value    def f(self,value):      v1,v2 = unpack('>2B',pack('>H',value))      v2 = self.g(v1,v2,1)      v1 = self.g(v1,v2,0)      value = unpack('>H',pack('>2B',v1,v2))      return value[0]  
```

具体来说，通过数学推导，我们可以发现，对于f来说，当其两个输入的差分为0x8080时，其输出差分100%是0x400。根据这一差分性质，我们可以对该加密算法进行差分分析攻击。差分分析的具体原理可以参考这个blog http://www.theamazingking.com/crypto-feal.php

我们以对最后一轮加密（即第3轮）进行攻击为例，介绍攻击的流程。

我们构造两个特殊的输入 (L0，R0)和 （L0',R0'）其中 L0 = L0‘， R0 = R0’^0x8080,让服务器加密，得到加密结果 (L3,R3),(L3',R3').通过对该加密算法的推导，我们可以得到关于第3轮轮函数f的运算关系。

*   
*   
*   

```
f(round3_key^L0)  = out1      f(round3_key^L0') = out2     out1^out2 = R0^L0^R0'^L0'^0x400  
```

其中，只有round3\_key是未知的，其他参数都是已知的。round3\_key的大小为2个字节，完全可以通过爆破来得到正确的解。这样我们就把对于整个key的求解，拆分到对于轮密钥的求解，爆破复杂度从 2^64降低到了 2^16

需要注意的是对于一组明密文对，可能有多个符合关系的解，我们可以同时对多组明密文对进行求解，来过滤掉错误的解。

依次类推，可以用相似的方法得到第1，2，3轮的轮密钥。有了这三轮的轮密钥后，可以通过逆运算很块的求解出第0轮的密钥，最终恢复出整个密钥。

核心漏洞点在sub\_12C1函数中，在读取数据的时候会在缓冲区的末尾添加一个\\x00，是一个经典的 off-by-null 漏洞。

**protocol**  
  

程序保护全开。

程序主要是一个基于protobuf实现的文件系统，主要的功能包括login/logout/open/read/write/access/delete。核心的漏洞点在于，access可以移动文件读写指针但没有越界检查，因此可以实现堆上的越界读写。每个功能在使用是均有检查token是否正确（需要通过逆向确定token变异方式来bypass）。文件系统的每个fd通过链表形式来维护，最多可以申请16个fd。

首先可以通过逆向函数sub\_c3a，可以推测protobuf的格式为：

message msg

{

optional uint32 opcode;optional string operand(最大0x500长度);optional string token(最大0x20长度)

}

其中Opcode的取值范围为1-7，分别代表Login, Logout, Open, Read, Write, Access, Delete。程序在login后会自动生成32位随机token，token的每个字符均为'a'-'z'，每次使用一个功能时，token会进行简单的变异，即token每位加一（如'a'->'b', 'z'->'a')。

具体的漏洞利用思路为：首先login，随后申请多个fd并释放，得到0x30的tcache与fastbin，随后通过分配一个大的chunk将fastbin放入smallbin中得到libc地址残留。通过Access配合Read/Write，实现堆上的越界读写。泄露完libc地址后可以修改tcache的fd完成get shell。

需要注意的是，本题实现的protobuf parser中，并不会检查字符是否为printable，即可以填充地址类信息。（但python的protobuf lib会检查，可以想办法把这个检查去掉或序列化后再填充unprintable数据）

首先，程序通过一个类似vm的解析逻辑来判断触发的菜单选项，主要包括create/show/edit/delete。

struct NoteBook {
