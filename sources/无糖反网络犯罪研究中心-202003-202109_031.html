一、寻 EIP: 32位汇编方法

    首先介绍使用 x86 Assembly (32位)指令定位 EIP 的方法。有两种方法，根据您可能面临的情况和限制，它们都是有用的。这两种方法都可以达到发现 EIP 的目的。我将详细介绍的第一个方法比第二个稍微小一个字节。这两种方法实现了完全相同的目标，即在 EAX 寄存器中存储 EIP 值。这两种方法都是空(0x00)字节。您会使用一个而不是另一个的原因归结为您可能遇到的大小或字符限制。


1、方法1: 使用 FPU 指令

这个方法首先利用x87浮点运算器寄存器来获得EIP的值。下面的基本汇编代码将EIP的值存储在EAX寄存器中。

[SECTION .text]

BITS 32

global _start

_start:
    fldz
    fnstenv [esp-0x0C]
    pop eax
    add al, 0x07

为了激活 FPU 寄存器，执行fldz指令。该指令将常量值 + 0.0推送到FPU寄存器堆栈(ST (0))。在此过程中，初始化FPU 寄存器，并将EIP的当前值存储在FPU指令指针偏移量(FIP)寄存器中。图1详细说明了FPU寄存器的结构。

图1:内存中的保护模式 x87 FPU 状态映像，32位格式


下一条指令将FPU寄存器存储在指定的地址。因为EIP值使用fnstenv指令存储在FIP寄存器中，偏移量为0x0C。指定ESP-0x0C的目标，以便将FIP值存储在当前的ESP地址。接下来，该值从堆栈中弹出并存储在EAX寄存器中。由于从EIP存储在FPU的FIP寄存器到它被弹出到EAX之间已经执行了几个字节的指令，所以有必要调整这个值来表示EIP 的当前值,0x07被添加到AL寄存器中。使用AL寄存器可以避免使用NULL字节。

测法2：替代-使用减法

建议使用EAX寄存器的减法而不是add al指令来避免在某些情况下失败，我添加了这种替代方法。正如他正确指出的那样，问题是通过添加到AL寄存器，如果添加会导致进位，那么EAX可能会指向错误的位置。例如，如果AL寄存器包含大于或等于0xF9 的任何内容，向其添加0x07将导致进位 1 被丢弃。例如，如果EAX包含0x001234F9并且我们添加0x07到AL寄存器(0xF9)，结果值将是0x00123400而不是我们需要的0x00123500。


为了克服这个问题并避免空字节，可以从EAX中减去一个负值。基本算术，减去一个负值结果相加。简单但有效。修正后的代码如下，避免了NULL字节，

global _start

_start:
    fldz
    fnstenv [esp-0x0C]
    pop eax
    sub eax, -0x07

2、方法2: 使用跳转和调用

第二种方法只比第一种方法长一个字节。为了获得EIP，这个方法使用一系列跳转和调用，导致EIP的值存储在EAX中。

[SECTION .text]

BITS 32

global _start

_start:
    jmp label2
    label1:
        jmp getEIP
    label2:
        call label1
    getEIP:
        pop eax

在上面的代码中，执行跳转到label2，这是一个调用 label1的调用指令。当一个调用被执行时，返回地址，下一条指令的地址，被推送到堆栈。然后执行跳转到getEIP，它将返回地址弹出到EAX。

二、寻RIP: 64位汇编方法

1、方法1: 使用 FPU 指令

使用FPU指令可以工作，因为指令在x64 Assembly下仍然有效。首先，查明如果对在32位模式下运行时使用的指令不进行或者进行半进制修改会发生什么。为此，我启动了x64dbg 并执行notepad.exe并运行它，直到点击EntryPoint。使用Assemble命令，我手动插入了32位指令来代替前几条指令。这样做的结果可以在图4中看到。这里要注意的是：首先，出现在fnstenv指令的前面的67:，67h前缀是地址大小覆盖前缀。这似乎是必要的，因为我使用的是ESP而不是RSP。第二，我不能使用POP EAX指令，我必须使用POP RAX。

图4: 使用 FPU 指令查找 RIP，尝试1

运行这个序列会导致部分成功。(参见图5)当执行加法时，rax指向 RIP之前的指令。这是因为有必要使用67h地址前缀。这很容易通过简单地添加0x08而不是0x07来进行补偿。

图5: 使用 FPU 指令查找 RIP，尝试1结果

编写

现在已经证明可以使用FPU寄存器检索RIP的值。对我来说，下一步是看看是否有可能编写一些汇编代码，以便复制在调试器中手动输入命令所得到的结果。经过一些调整之后，我得到了下面这段代码:

[SECTION .text]

BITS 64

global _start

_start:
    fldz
    fnstenv [rsp-0x0C]
    pop rax
    add rax, 0x07

当使用Nasm编译时，上面的代码会生成如图6所示的指令。为了测试这些指令，我在使用x64dbg打开的64位进程的第一个指令上进行了二进制粘贴。如您所见，现在在add rax，0x07指令中有一个新的48h前缀是一个REX前缀，它允许一条指令寻址一个8位寄存器。汇编程序可以通过这种方式删除NULL 字节。此外，由于地址大小前缀是不需要的fnstenv时，使用RSP而不是ESP，增加0x07字节的RAX应该导致RAX包含的RIP 地址。

2、方法2: 使用跳转和调用

3、方法3: 加载 RIP 的有效地址

在获得了前两种使用64位的方法之后，我想看看是否还有更好的方法。在搜索过程中，我偶然发现一篇文章，其中详细介绍了Rapid7在Metasploit实现的一种使用LEA指令获取 RIP 的方法。在一些尝试和错误之后，通过使用Nasm命令行开关，我得到了下面的代码，它将复制Metasploit使用的方法:

[SECTION .text]

BITS 64

default rel

global _start

_start:
    lea rax, [_start]

当使用以下标志与 Nasm 混合时，得到的代码是空字节无关的，长度只有7字节。-O0标志告诉Nasm不要执行优化。如果不使用此标志，则生成的操作码将包含NULL值。你可以自己尝试一下，看看它是如何工作的:

nasm -O0 method3.asm -o method3.bin

代码和结果可以在图8中看到。

图8: 用加载有效地址(LEA)指令查找 RIP，最终

三、结论

已经详细介绍了根据目标架构查找EIP或RAX的几种方法。如果您希望执行与您的shellcode交互的其他操作，那么动态获取这些值很重要。由于ASLR无法动态查找EIP/RIP，因此无法解码、复制或以其他方式修改您的代码。
