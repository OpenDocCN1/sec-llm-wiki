## **Executable Header**

任何 ELF 文件都以一个可执行头开始。它包含了关于 ELF 文件的类型的信息，这些偏移设置为不同的头部。如果你看看评论，一切都是不言自明的。在这个例子中，我使用了32位结构。对于 x86\_64，尺寸可能会改变，变数命名原则将以“ Elf64\_”开头。

```


#define EI\_NIDENT (16)
```

![](../Images/1282f51a2a4c0e9f1a926ab40245298b.png)

  

如：要计算整个二进制文件的大小，我们可以使用下面的计算：

```
size = e\_shoff + (e\_shnum \* e\_shentsize)即：size = Start of section headers + (Number of section headers \* Size of section headers)
size = 145256 + (30\*64) = 147176
如你所见，我们的计算是正确的。![](../Images/61f9fdf467a08c2a869855abf2577c23.png)
```

## **Program Headers**

```


typedef struct {
```

这些头文件描述了对加载二进制文件非常重要的二进制文件段，这些信息对于内核将段从磁盘映射到内存非常有用。结构的成员是不言自明的。

  

## **Section Headers**

```


typedef struct {
```

这些头包含二进制文件段的信息，它为指引了文件大小、链接定位和正确调试。这些头文件对于二进制文件的执行流并不重要，因为他们只是依赖这些头来定位符号信息。  

  

## **Sections**

### **.bss Section：**此部分包含程序未初始化的全局数据。

### **.data Section：**此部分包含程序的已初始化的全局变量。

### **.rodata Section：**此部分包含只读数据，例如所用程序的字符串。

### **.text Section：**本节包含程序的实际代码，逻辑流程。
