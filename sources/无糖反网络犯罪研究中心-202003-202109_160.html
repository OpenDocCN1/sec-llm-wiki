    下一篇将介绍个PE的插入技术，这里先作个铺垫，熟悉并回忆一下以前的基础知识。


    我们来看看最简单的PE Header，以一个16位的 MS-DOS 可执行文件Stub为例。


这是详细的 MS-DOS 头。


#define IMAGE_DOS_SIGNATURE               0x5A4D          // MZ

#define IMAGE_NT_SIGNATURE                  0x00004550  // PE00

typedef struct _IMAGE_DOS_HEADER {      // DOS .EXE header

    WORD   e_magic;              // Magic number

    WORD   e_cblp;                 // Bytes on last page of file

    WORD   e_cp;                    // Pages in file

    WORD   e_crlc;                  // Relocations

    WORD   e_cparhdr;           // Size of header in paragraphs

    WORD   e_minalloc;          // Minimum extra paragraphs needed

    WORD   e_maxalloc;          // Maximum extra paragraphs needed

    WORD   e_ss;                     // Initial (relative) SS value

    WORD   e_sp;                     // Initial SP value

    WORD   e_csum;                // Checksum

    WORD   e_ip;                      // Initial IP value

    WORD   e_cs;                      // Initial (relative) CS value

    WORD   e_lfarlc;                  // File address of relocation table

    WORD   e_ovno;                  // Overlay number

    WORD   e_res[4];                 // Reserved words

    WORD   e_oemid;                // OEM identifier (for e_oeminfo)

    WORD   e_oeminfo;             // OEM information; e_oemid specific

    WORD   e_res2[10];              // Reserved words

    LONG   e_lfanew;                 // File address of new exe header

  } IMAGE_DOS_HEADER, *PIMAGE_DOS_HEADER;


    每个 PE 文件都以一个 MS-DOS 可执行文件开始，该文件以IMAGE_dos_signature 开始。ASCII 表示为0x5a4d，即 MZ。字母“ MZ”代表 Mark Zbikowski，他是 MS-DOS 的原始架构师之一，也是 MS-DOS 可执行格式的设计者。


    在上面的图片中，0x3c是IMAGE_dos_header的e_lfanew成员。此地址指向新的 EXE 标头，即 _image_nt_headers。在本例中，e_lfanew 包含0x00000120，它指向结构 IMAGE_nt_headers 的开头,包含IMAGE_nt_Signature的签名。经过实验，Windows加载程序只关心 e_magic和e_lfanew，成员来自 IMAGE_dos_header，因为 DOS 头的其余成员被 MS-DOS 用来执行Stub。



    在任何32位/64位 PE 文件中，都会看到一个很小的 MS-DOS Stub。从偏移量0x40到0x7f 是这个64字节的Stub。让我们移除带有Stub的 MS-DOS头并反汇编代码。

在 DOS下运行此程序，会报提示；

如果我们查看 DOS 头，可以在调试器中看到这些值，这证明只需要MS-DOS 头就可以执行它的Stub,但是正如我之前提到的，e_magic 和e_lfanew 对于 Windows 加载器来说非常重要。

从上图中可以看到初始堆栈指针0x00B8的值 e_sp 和初始指令指针0x0000的值 e_ip。我们解码的16位汇编代码可以看到将执行和打印该文本。

我们来写一段简单的程序，C语言如下：


#include <stdio.h>

int main() {

  size_t i = 0;

  while (i++<5) puts("@OsandaMalith");

  return 0;

}

下面的代码是16位 MASM。这将是我们的 MS-DOS Stub程序。

dosseg

ifndef ??Version

option m510

endif

 

.model small

.8086

.stack 0400h

 

.data

    message db '@OsandaMalith',0Dh,0dh,0Ah

    len = $ - message

.code

Main proc

    mov ax, @data

    mov ds, ax              

    mov es, ax            

    lea bp, message

 

    mov cx, len

    mov bl, 2

    

    xor dx, dx

    push dx

 

.repeat

    push cx                 

; Save CX (needed for Int 10h/AH=13h below)

    mov ah, 03h            

; VIDEO - GET CURSOR POSITION AND SIZE

    xor bh, bh              

; Page 0

    int 10h                

; Call Video-BIOS => DX is current cursor position

    pop cx    

    

    mov ah, 13h            

; VIDEO - WRITE STRING (AT and later,EGA)

    mov al, 1              

; Mode 1: move cursor

    xor bh, bh             

 ; Page 0

    int 10h      

    pop dx

    inc dx

    push dx

.until dx == 5

    mov  ax, 4C01h          

    int  21h

Main endp

end Main


编译和链接，

ml /c /Fo hello.obj hello.asmseglink hello.obj, stub.exe,nul,,nul

我们可以告诉链接器在使用“/stub”参数链接时使用我们的 stub程序。

link hello.obj /stub:stub.exe

如果您检查 PE 头，您可以在 IMAGE_dos_stub 部分看到我们新创建的存根程序。

最后，如果我们在 MS-DOS 中运行64位 PE，我们应该可以很好地看到新创建的Stub程序正在执行。
