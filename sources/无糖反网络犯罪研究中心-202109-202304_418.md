**一、原理介绍**

从Windows 8.1（和 Server 2012 R2）开始，Microsoft引入了一项称为LSA保护的功能。此功能基于Protected Process Light (PPL) 技术，该技术是一种纵深防御安全功能，旨在“防止非管理性非PPL进程通过开放访问或篡改PPL进程中的代码和数据”。

  

我注意到有一个常见的误解，即LSA保护可以防止利用SeDebug或管理权限从内存中提取凭据材料的攻击，例如Mimikatz。LSA保护不能防止这些攻击，充其量只是使它们稍微困难一些，因为需要执行额外的步骤。

  

要绕过LSA保护，您有几个选择：

1.  删除RunAsPPL注册表项并重新启动（可能是最糟糕的方法，因为您将丢失内存中的任何凭据）；
    
2.  通过修补EPROCESS内核结构禁用LSASS进程上的PPL标志；
    
3.  直接读取LSASS进程内存内容，而不是使用开放进程函数。
    

后两种方法需要读写内核内存的能力。实现这一点的最简单方法是通过加载驱动程序，尽管您可以创建自己的驱动程序，但我决定利用MSI Afterburner中的RTCore64.sys驱动程序。我选择这个驱动程序是因为它经过签名并且允许读写任意内存，感谢 MSI。

  

我决定实施第二种方法，因为删除PPL标志允许使用已经建立的工具（如Mimikatz）从LSASS转储凭证材料。为此，我们需要找到LSASS EPROCESS结构的地址并将5个值修补：SignatureLevel、SectionSignatureLevel、Type、Audit 和 Signer为零。

  

该EnumDeviceDrivers函数可用于泄漏内核基地址。这可用于定位指向系统进程的EPROCESS结构的PsInitialSystemProcess。由于内核将进程存储在链表中，因此可以使用EPROCESS结构的 ActiveProcessLinks成员来迭代链表并找到LSASS。

  
如果我们查看EPROCESS结构（参见下图），我们可以看到我们需要修补的5个字段都按惯例对齐成连续的4个字节。这让我们可以在单个4字节写入中修补EPROCESS结构，如下所示：  
WriteMemoryPrimitive(Device,4,CurrentProcessAddress+SignatureLevelOffset, 0x00);

![](../Images/6bf297fa0ade09799035956800ad2716.png)

  

现在PPL已被移除，所有传统的转储LSASS方法都可以使用，例如MimiKatz、MiniDumpWriteDump API调用等。

  

# **二、使用和演示**

1.  运行PPLKiller.exe /installDriver安装驱动程序；
    
2.  进行攻击，PPLKiller.exe /disableLSAProtection；
    
3.  清理: PPLKiller.exe /uninstallDriver。

 \[/disablePPL <PID>\]

 \[/disableLSAProtection\]

 \[/makeSYSTEM <PID>\]

 \[/makeSYSTEMcmd\]

 \[/installDriver\]

 \[/uninstallDriver\]
