**一、正文**

    在网络攻击者和网络防御者之间永恒的猫捉老鼠追逐中，防御者可以执行的关键活动之一是分析恶意软件以提取IOC并确定恶意软件实际做了什么在一个系统上。

  

    当恶意软件在Windows系统上运行时，它需要以某种方式与该系统进行交互。最常见的方法之一是使用Windows API，其中众所周知的API调用此类VirtualAllocateEx，WriteProcessMemory、CreateRemoteThread允许恶意软件将一些恶意代码注入进程，然后运行该代码。

  

    出于这个原因，在调试恶意软件时，您会看到人们做的第一件事就是在这些众所周知的API调用和任何其他可用于执行恶意操作的API调用上设置断点。

  

    类似地，EDR等防御性软件通常会监视这些API调用，例如通过挂钩它们，以便在调用它们时首先绕道进入EDR代码，在那里可以分析参数和行为，然后允许API调用继续。

  

    攻击者试图通过“降低”并使用内部或未记录的 API 调用(例如RtlCreateUserThread)来规避这一点NtAllocateVirtualMemory，但现在这些反过来也受到严密审查。

  

    最新的一种方法是尽可能地靠近内核，并直接使用系统调用，但首先我们应该大概了解系统调用实际上是什么。

  

## **二、系统调用**

(请注意，以下内容适用于 64 位 Windows 上的 64 位可执行文件。虽然类似，但 32 位应用程序与 32 位 Windows 和 WOW64 上的工作方式略有不同。)

* * *

  

    如上所述，Windows 操作系统 (OS) 具有多个抽象层，以便允许开发人员在内部获得一些许可，以便在不破坏任何使用其 API 的程序的情况下更改 Windows 内部的工作方式。

  

    例如，Microsoft 为Windows API提供了关于msdn鼓励希望与操作系统交互的开发人员使用哪些（例如CreateThread在kernel32.dll中，不出所料，它会创建一个运行某些代码的线程）。这些 API 调用本身可能会利用其他较低级别的内部或未记录的 API 调用，例如RtlCreateUserThread（在ntdll.dll 中），以提供抽象层并包装可能更改或依赖于平台的代码等。

  

    最终，这些 API 调用中的大多数都需要进行一些需要由 Windows内核处理的更改（例如任何使用硬件的东西，如读写磁盘）。“内核空间”受到高度保护，用户态代码无法更改或调用内核函数，除非使用系统调用。

![](../Images/da0733391d05f47fd46e1602d2d4dcf5.png)

这些系统调用发生在ntdll.dll（或用于图形调用的 Win32k）中的函数中，并以Nt或Zw为前缀，例如NtCreateThread。这些是实际执行系统调用的函数，以受控方式将执行从用户空间转移到内核。因此，例如，当应用程序调用时，CreateRemoteThread实际流程如下所示：  

![](../Images/b9399351c66dea28fd440d9028e6c5b3.png)

那么系统调用是什么样的呢？本质上，系统调用只是将预先确定的数字（系统调用号）移动到rax寄存器中，然后调用syscall指令，如下所示：

![](../Images/1aa6ffb473c392933e5c599df1935666.png)

ntdll.dll 中的 NtCreateThread 进行系统调用

  

    然后将执行交给内核，内核在系统服务调度表(SSDT) 中查找此系统调用编号的相关函数，然后调用它。

  

## **三、使用系统调用**

    现在，作为开发人员使用系统调用是有风险的，因为系统调用号是 Windows 内部的，并且可以（并且确实）随着任何更新而改变。因此，如果您编写直接使用 syscall 指令的代码，您可能会在一分钟内编写工作代码，然后在下一分钟编写损坏的代码。

  

    然而，对于攻击者来说，它们提供了一个极好的机会来隐藏他们的踪迹，方法是在尽可能低的用户级级别与操作系统交互，绕过 API 层周围的任何控制或检测，并使逆向工程师的生活变得更加困难，因为他们的二进制文件不会为他们正在执行的活动提供任何通常的导入。同样，通常断点时动态逆向工程恶意软件上VirtualProtect，VirtualAlloc，WriteProcessMemory等都是无用的，因为这些API调用并不实际调用。

  

    为了强调这一点，编写了一个简单的示例程序，它使用系统调用将一些良性的“消息框”shellcode 执行到目标进程中。

  

    该程序使用流行的 Syswhispers2  项目来完成所有繁重的工作。Syswhispers2 维护一个跨 Windows 版本和更新的已知系统调用号的查找表，并rax在调用syscall指令执行操作之前在运行时用适当的值填充寄存器。

  

    这些函数以其“真实”对应物命名，以便于开发，但请不要误会 - 这些不是真正的函数ntdll.dll。

    那么现在问题的关键是，使用系统调用的恶意软件在显微镜下是什么样的，我们需要知道什么来寻找？

  

    如果我们在 CFF Explorer 中检查我们的示例二进制文件，我们可以看到，正如预期的那样，它不会导入任何常见的可疑 API 调用，类似于使用动态 API 解析。

## **六、概括**

    使用系统调用是攻击者可以使用的一种复杂技术，它需要一些额外的工作，但允许恶意软件通过系统调用接口直接与内核交互来绕过 API 钩子、断点和检测。

  

    如果您怀疑系统调用的使用，那么知道要查找的内容非常有用，并且将这些知识放在口袋里可以帮助您避免与使用此技术的恶意软件发生冲突。我们已经了解了系统调用是什么， 以及一些帮助定位和调试它们在 64 位 Windows 可执行文件中所做的事情的方法。
