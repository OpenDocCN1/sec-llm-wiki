Tenet 是一个IDA Pro插件，用于探索执行跟踪。它是2021插件大赛的第一名。此插件的目标是针对给定的二进制文件导航执行跟踪。

  

![](../Images/fd5fbea50f52231361589a98b7b2ad9b.png)

  

# 安装

# 放置在/plugins目录下。

# 用法

正确安装后，反汇编程序中将出现一个新菜单项。这可用于将外部收集的执行跟踪加载到 Tenet 中。

![](../Images/0b6baacb2139e375ff58b1329501e1c8.png)

  

## 双向勘探

在使用 Tenet 时，插件将“绘制”轨迹以指示从您在活动执行跟踪中的当前位置向前（蓝色）和向后（红色）执行的流程。

![](../Images/093b0354e26b9d1b0ca0332412009991.png)

要`step`向前或向后通过时间，您只需将*鼠标悬停在*反汇编器右侧*的时间轴*上*滚动*即可。要`step over`调用函数，请`SHIFT`在滚动时按住。

  

## 跟踪时间线

跟踪时间线将停靠在反汇编器的右侧。此小部件用于可视化跟踪时间轴上的不同类型的事件并执行如上所述的基本导航。

![](../Images/c61f4737584e532f11a45c70d00d8f6f.png)

  

通过*在时间轴上单击并拖动*，可以放大执行跟踪的特定部分。此操作可以重复任意次以达到所需的粒度。

## 执行断点

双击寄存器窗口中的指令指针会将其突出显示为红色，显示指令在跟踪时间线上执行的所有位置。

![](../Images/c8a1b6d4d89cf619ae3ef4c20434fc5c.png)

要在执行之间跳转，请*在悬停突出显示的指令指针 的同时向上或向下滚动*。

此外，您可以*右键单击反汇编列表*并选择基于导航的菜单条目之一，以快速寻找感兴趣的指令的执行。

![](../Images/e4b0582aa519d559e759376e80f0c370.png)

IDA 的本机`F2`热键还可用于在任意指令上设置断点。

## 内存断点

通过双击堆栈或内存视图中的一个字节，您将立即看到对该地址的所有读/写，并在整个跟踪时间线上可视化。黄色表示内存*读取*，蓝色表示内存*写入*。

![](../Images/2734f367dc570dd296366d944406b692.png)

可以使用为执行断点描述的相同技术来导航内存断点。双击一个字节，并*在悬停所选字节的**同时滚动*以查找其每个访问的跟踪。

如果您有特定的导航操作，则*右键单击*感兴趣*的字节*将为您提供在内存读取/写入/访问之间寻找的选项。

![](../Images/ca9652d9fb5631ab939d942c6251c52d.png)

要将内存视图导航到任意地址，请单击内存视图并点击`G`以输入地址或数据库符号以查找视图。

## 区域断点

通过突出显示内存块并双击它来设置访问断点，可以在整个内存区域设置内存断点。

![](../Images/8a53b67a272f14176c277adfc280d705.png)

与普通内存断点一样，悬停区域和*滚动*可用于在对选定内存区域进行的访问之间进行遍历。

## 注册寻求

在逆向工程中，经常会遇到这样的情况：*“哪个指令将此寄存器设置为其当前值？”*

使用 Tenet，您可以通过单击向后查找该指令。

![](../Images/833f7c20cba9703eb9730a6f2c58c0b0.png)

向后查找是迄今为止在寄存器更改之间导航的最常见方向……但为了灵巧，您还可以使用寄存器右侧的蓝色箭头向前查找下一个寄存器分配。

## 时间戳外壳

提供了一个简单的“shell”来导航到跟踪中的特定时间戳。将时间戳粘贴（或键入...）带或不带逗号的 shell 就足够了。

![](../Images/961fe90d2507e45d5d491585c78f3869.png)

  

  

使用感叹号，您还可以在跟踪中寻找指定的“百分比”。进入`!100`将寻找轨迹中的最后`!50`一条指令，在轨迹中将寻找大约 50% 的路径。`!last`将寻找可在反汇编程序中查看的最后一条可导航指令。

## 主题

Tenet 附带两个默认主题——“浅色”主题和“深色”主题。根据反汇编程序当前使用的颜色，Tenet 将尝试选择看起来最合适的主题。

![](../Images/3ae8ac7c23988f72b04c1789697882e7.png)

主题文件作为简单的 JSON 存储在磁盘上，并且是高度可配置的。如果您对默认主题或颜色不满意，您可以创建自己的主题并将它们放在用户主题目录中。

Tenet 会记住您的主题偏好，以备将来加载和使用。

# 常问问题

#### 问：如何使用 Tenet 记录执行跟踪？

*   *A: Tenet 是一个跟踪阅读器，而不是一个跟踪记录器。您必须使用动态二进制检测框架（或其他相关技术）来生成兼容的执行跟踪。有关现有跟踪器或如何实现自己的跟踪器的更多信息，请参阅跟踪自述文件。*
    

#### 问：Tenet 支持加载哪些跟踪架构？

*   *A：只有 x86 和 AMD64，但代码库几乎完全与架构无关。*
    

#### 问：Tenet 可以加载/导航多大的跟踪文件？

*   *A: Tenet 的 trace reader 是纯 python 的，它是作为 MVP 编写的。无法保证超过 1000 万条指令的跟踪将合理导航，直到本机后端替换它。*
    

#### 问：我加载了一个执行跟踪，现在有一个“.tt”文件。它是什么？

*   *答：当 Tenet 加载给定的文本跟踪时，它会将跟踪解析、索引和压缩为更高性能的格式。在后续加载中，Tenet 将尝试加载“.tt”文件，该文件的加载时间比加载原始文本跟踪所需的时间短。*
    

#### 问：插件崩溃/抛出错误/显示错误跟踪信息，我该怎么办？

*   *答：如果您遇到可以重现的问题或不准确之处，请针对此存储库提交问题并上传示例跟踪 + 可执行文件。*
    

#### 问：我的跟踪中的内存正在更改，但没有写入该区域。这是bug吗！？

*   *答：您的日志文件可能未捕获所有内存写入。例如，用户模式 DBI 通常不会获得外部写入进程内存的内存回调。这在从文件或套接字读取时最常见——它是内核将内存写入您指定的用户模式缓冲区，使事件对传统检测不可见。*
    

*   Microsoft TTD 通常表现出相同的行为，如果不为系统调用建模就很难解决。
