**F5的BIG-IP安全套件存在RCE漏洞**

  

近期，F5的BIG-IP负载平衡和安全套件受到远程代码执行（RCE）漏洞的影响。iControl REST API存在漏洞，允许远程访问平台配置，攻击者不需要任何身份验证便可获得公开端点/mgmt/tm/util/bash的访问权。

![](../Images/fa7e2e681dfe04ef79bc82f7db1d973c.png)

  

该漏洞的CVSS评分为9.8，编号为CVE-2022-1388。F5已修复该问题，建议用户立即为系统打补丁，建议受影响系统的用户阻止该API端点或限制对其使用的端口的访问。

  

根据Shodan和Censys的搜索，多达16,000个带有管理接口的BIG-IP系统暴露在公共互联网上。Stack报告称，BIG-IP平台的用户包括亚马逊、谷歌云、华为、微软、韩国电信等电信公司。

这是一个极其严重的API2：2019——失效的认证——始终确保暴露的API具备充分认证，以防止匿名访问。

  

  

**API安全成熟度模型**

  

API 安全已成为现代企业关注的前沿问题。但是，有一系列 API 安全实现，并不是所有的都是有效的。很多时候，API 只采用 HTTP 基本身份验证、API 密钥或基于令牌的身份验证，而忽略了一个主要问题：身份。为了防止漏洞并获得效率优势，全面的身份关注对于全面发展的 API 至关重要。为此，Curity创建了一个四级的API安全成熟度模型，组织可借其评估当前的成熟度，并完善安全的路线图。

  

![](../Images/c73e87524cbcd5197417edf4bf3cfd12.png)

  

**每个阶段的关键要素如下：**

**• 0级：**API密钥和基本身份验证：这是最基本的级别，而且——不幸的是——使用最广泛，特别是在传统系统中，身份验证是通过Basic Auth进行的，或者将API密钥插入头文件或主体文件中。

• **1级：**基于令牌的身份验证：在这个级别，使用令牌交换机制来基于令牌识别客户机。尽管在0级上有所改进，但是仍缺乏限制客户行为的指示，仅通过持有令牌来验证身份。

•** 2级：**基于令牌的授权：现代API通常使用OAuth2来增强安全程度，允许对资源进行基于作用域的授权。然而，提高安全成熟度是以增加复杂性为代价的。

• **3级：**使用声明的集中式信任：是最安全的级别，使用一个基于声明的强模型，该模型通常基于jwt，通常为完整性签名。建议使用标准协议，如OAuth和OpenID Connect。 

  

**重点：高度成熟的API只信任极少的资源。**

  

**强化谷歌云平台实现**

  

云平台的灵活性和先进特性推动了创新，因此日渐受到开发人员的喜爱。不幸的是，现代云平台极其复杂，容易出现错误配置。

  

![](../Images/99dbf1dd2b047951800253e53b0616eb.png)

Mitiga的安全研究团队发布了一篇技术博客文章，描述了通过“命令和控制”接管谷歌云平台（GCP）的场景。GCP的安全团队审查了细节，并给研究人员发了一些奖金，但没有将该场景归类为漏洞。

  

研究人员发现，GCP控制平面暴露了VM计算模块上的一个API端点getSerialPortOutput()。研究人员认为，通过向这个API发送任意数据，攻击者可以使用该API向受影响的虚拟机发送“命令和控制”数据。尽管某些API调用需要提升特权，但getSerialPortOutput()的访问只需非常基本的权限。GCP安全团队建议，如无必要，应该使用VPC服务控制删除对该API的访问。

  

**研究人员就加固云系统提供了以下建议：**

**• **避免使用内置角色，应用最小特权原则。

• 评估是否需要危险的功能，如果不需要就关闭它。

• 只允许通过标准的、安全的方式访问，如SSH和RDP。

• 尽量以最低权限级别运行应用程序和服务。

  

**通常建议注意隐藏的复杂性和潜在的不安全默认配置。**
