**Facebook数据泄露**

  

近期，最严重的数据泄露事件就是Facebook泄露了5.3亿的用户信息，然而Facebook却在官方的声明中轻描淡写，说这些数据早在2019年就被通过Facebook API的方式抓取了，而不是通过数据库访问以及其他直接的黑客攻击。

攻击者利用的漏洞存在于Facebook创建的根据手机中的通讯录来发现好友的API中。Facebook想要帮助用户更容易地找到他们社交网络上的好友，所以Facebook程序通过API把用户的通讯录进行上传，并获取与上传电话号匹配的用户个人资料。

这种办法听起来非常棒，而且对用户十分友好，但正如常常会发生的，让事情变得简单也会降低安全性。攻击者通过生成庞大的电话库，并提交给API来利用这一功能。毕竟电话号码只是遵循一定语法的一系列数字：国家代码，区号和七位数，遍历他们并不困难。

这种方式让攻击者可以抓取用户的数据库并收集大量详细的个人信息，这绝对是不该发生的，并且应该可以预见的。现在，随着这些泄露数据的公开，5.3亿用户（包括扎克伯格本人）的姓名，Facebook ID, 电话号码，邮件等信息都被曝光在了公众下。

  

**这次泄漏事件造成的影响**

▪ Facebook的立场是，如果是使用API来进行数据收集，就不是黑客攻击，毫无意义。然而对于攻击者来说，API实际是一种攻击媒介，并且是当前主流的攻击媒介之一，黑客攻击就是黑客攻击，无论是哪种方式。

▪ 尽管一些数据是公开的，比如名字，但这些大型数据集的公开信息与其他详细信息结合可用于各种网络钓鱼和社会工程攻击。还有报告表示有些数据库还包含了点赞数量。这也加剧了这次数据泄露事件的严重程度：骗子掌握的信息越多，骗局就越容易让人上当

▪ 无论用户隐私如何设置，这个电话匹配功能都有效。即使设置不共享电话号码，或者仅用于多重身份验证，API仍会公开该电话号码的用户信息。这是对用户隐私的严重侵犯。

▪ 报告显示，Facebook多年来一直收到有关该漏洞的报告，却直到2019年才进行修复

  

**吸取的教训**

▪ API是主要的攻击面之一。

▪ 一旦公共信息整合成大型数据集，公共信息也可能变得危险。毕竟，信息就是力量：更多的信息，更多的力量。我们不能因为疏忽而让这些信息落入坏人之手。

▪ APIs 不应该允许访问用户界面共享以外的数据。

▪ 批量操作极其危险。不仅要限制调用 API 的速率，还要限制它们可以返回的数据量。

▪ API 需要在设计时就被保护起来，如果只在漏洞被利用后去修复问题的话会造成灾难性后果。

▪ 监控，警报和及时的响应漏洞报告也是很好的缓解措施。

  

**Clubhouse数据泄露**

  

clubhouse也有类似的泄露问题，130万的用户数据被泄露，事后声明也和Facebook很像。

就像我们上面讨论的，API 用于检索信息这一事实不会以任何方式改变影响（和供应商责任）。

  

**影响和Facebook很像**

▪ 如上所述，用户数据的大型数据集是有问题的，会帮助网络钓鱼和其他社会工程学攻击。

▪ 数据包含指向其他社交网络中用户个人资料的链接。对于某些用户来说，这意味着他们的私人Twitter和 Instagram帐户已被暴露。

▪Clubhouse使检索数据变得容易，因为用户ID是连续整数。因此，API可用于检索有关用户1号、2号、3号等的信息，这让枚举用户信息变得更加简单。

  

**吸取的教训**

▪永远不要用连续的ID，只是使用 GUID 的一个简单步骤就会让攻击更加困难，并且不允许他们去迭代用户信息或资源记录。
