01

前言

Windows进行安全更新后，会发布若干补丁，如果想要进行漏洞研究，或者写出Nday的exp，就要对补丁修改前后的内容进行比较。那么如何定位修改的内容就是关键点了。

02

知识提要 

● MSU文件


Windows 更新独立安装程序使用 Windows 更新代理 API 来安装了更新程序包。更新软件包具有文件扩展名为.msu。


.msu文件中包含以下内容。

内容

说明

Windows Update元数据

反馈

一个或多个.cab 文件

每个.cab 文件代表一个更新

.xml 文件

该.xml 文件介绍了.msu 更新软件包。当您使用程序包管理器工具 (Pkgmgr.exe) 执行更新的无人值守安装时，Wusa.exe会使用该.xml 文件

属性文件


此文件包含 Wusa.exe 使用的字符串属性。例如，此文件包含 Microsoft 知识库中相应的文章相关文章的标题



一个msu文件可以通过如下方式进行展开，并提取.cab(此次更新的内容)


1
mkdir msu
2
expand -F:* [补丁名称].msu [path]/msu
3
expand -F:* [path]/msu/*.cab [path]/msu

03

获取漏洞信息 

正所谓“工欲善其事，必先利其器”，前期的准备是不可少的。首先到搜索引擎上去搜索该编号，包括但不仅限于：

  • https://msrc.microsoft.com/update-guide/vulnerability（Windows官方安全更新）

  • https://cve.mitre.org/

  • 各大安全咨询平台


主要提炼的信息为：

  • 该漏洞与什么服务有关

  • 该漏洞的影响范围

  • 补丁是否已经发布


就拿知名度比较广的CVE-2019-0708举例子，

漏洞概要如下：


//From https://msrc.microsoft.com/update-guide/vulnerability/CVE-2019-0708 微软官方漏洞补丁更新
Executive Summary
A remote code execution vulnerability exists in Remote Desktop Services – formerly known as Terminal Services –
when an unauthenticated attacker connects to the target system using RDP and sends specially crafted requests.
This vulnerability is pre-authentication and requires no user interaction.
An attacker who successfully exploited this vulnerability could execute arbitrary code on the target system.
An attacker could then install programs; view, change, or delete data; or create new accounts with full user rights.

大意为：当未经身份验证的攻击者使用RDP连接目标系统，并构造特定请求就可以在目标系统上执行任意代码，此漏洞是预认证，不需要用户交互。


从中可以提取的主要信息为：“该服务与RDP服务相关”。


然后从补丁列表以及各大资讯平台可以得知，

影响范围如下：


  • Windows 7

  • Windows Server 2008 R2

  • Windows Server 2008

  • Windows 2003

  • Windows XP

那么信息收集的第一步已经完成，第二步就是定位漏洞的相关文件。

04

定位漏洞文件 

下载补丁.msu文件后，将.cab文件进行解压之后的文件还是非常的多，那么如何进一步筛选呢？就需要我们提前准备好的“利器”--信息。


接着来说CVE-2019-0708，我们了解到其漏洞和RDP服务相关，如果我们定位到RDP服务的相关进程，并查看所调用的驱动和模块文件，就能再一次缩小范围。


先说定位进程，关于这个漏洞有两种方法：


    1.通过相关知识可以知道RDP服务是监听在3389端口上的，所以可以通过查看是哪个进程监听的3389端口




    2.因为Windows的相关服务都是通过svchost.exe进行启动，可以通过ProcessExplorer对所有svchost.exe进程的Service以及CommandLine进行遍历，从而找到和RDP相关的。



定位进程之后，需要找到该进程在进行rdp认证的过程中所调用的函数过程。


这里可以用ProcessMoniter来监控进程的网络行为所调用的函数过程。


网络传输的事件非常多，如何继续定位呢？这个时候需要用的另外一个漏洞描述：此漏洞为预认证，不需要用户交互，那么我们尝试在rdp连接上pc后，不进行密码验证，查看他的网络传输行为。



然后点开进行查看，可以看到图如下：



然后做个苦力活，把每个文件都在已经展开的补丁文件里面进行搜索，可以得到的是，只有内核驱动文件termdd.sys文件进行了修改。所以我们可以把目光放在termdd.sys文件上。


05

定位文件内漏洞点 

对两个termdd.sys文件使用Bindiff进行比较，可以发现 IcaBindVirtualChannels函数的Similarity不同，判断其进行了更改，后面即为逻辑内容，继续进行研究即可。



06

总结

如何定位漏洞的关键点已经结束，对于不同的漏洞，具体细节上会有很大的出入，但是总体的思路是不变的，在研究一个没有人研究过的漏洞之前，需要各种信息收集来从补丁文件定位到漏洞点。


07

附录 

bat脚本如下:


1
@echo off
2
mkdir msu
3
for %%i in (*.msu) do (expand -F:* %%i %cd%\msu)
4
cd msu
5
mkdir cab
6
for %%i in (windows*.cab) do (expand -F:* %%i %cd%\cab)
7
pause
