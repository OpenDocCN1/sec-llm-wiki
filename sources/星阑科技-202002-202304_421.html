任意文件读取漏洞过滤绕过


    通过扫描我们发现，该网站使用的是phpstudy（没有后门），还存在着一个phpmyadmin 页面，利用该页面可以操作数据库。但是，在这之前，我们需要获取数据库的连接账号密码。此处，利用任用文件读取漏洞，获取有两种可行方案。

    一种是尝试读取名为database.php的数据库配置文件;另外一种是尝试读取mysql的user.MYD的数据文件，从中恢复出root的账号密码。phpstudy默认的user.MYD的存储位置为：
phpStudy\PHPTutorial\MySQL\data\mysql\user.MYD
    读取后的内容如下：


    加密的方式是mysql5，但是，相关的密码hash无法解出。于是，我们尝试读取数据关键配置文件database.php。这时，却出现了一个很奇怪的问题：同目录下的其他php文件都能正常读取，但是唯独该文件读取的时候返回为空。（一般是因为该文件不存在）而直接在web上访问时，database.php返回为200。如果文件不存在，web访问时应该会报错；而如果读取时，文件权限不够，那么web访问时，权限也会存在问题，从而引发报错。由此可见，产生该问题的原因可能是存在一些WAF的过滤。


    WAF的过滤一般在CDN层或者代码层实现。通过参考前期的自动化信息收集工具产生的文档，我们并没有发现相关网站存在CDN。于是，借助任意文件读取的漏洞，我们可以检验代码上的WAF的具体实现。


    最终我们在thinkphp的入口文件index.php上，发现他引入了一个名为360scan.php的文件。该php的内容大致如下：
if($str){	if (get_magic_quotes_gpc()){
		$str = str_replace("\\\"", "&quot;",$str);
		$str = str_replace("\\''", "&#039;",$str);
	}else{
		$str = addslashes($str);
		$str = str_replace("\"", "&quot;",$str);
		$str = str_replace("'", "&#039;",$str);
	}
	$str=RemoveXSS($str);
	$str=RemoveWJ($str);
	}
    在 RemoveXSS函数中，file=database.php中的base会被修改为ba&lt;x&gt;se，因此之前在使用任意文件读取的攻击载荷进行攻击时，读取的文件不是database.php，而是databa&lt;x&gt;se.php，该文件不存在，因此返回为空。如果仅仅是过滤base，我们可以利用windows环境下的php通配符进行绕过。例如此处我们想要读取的是database.php，我们可以写成data>或者data<的形式，通过通配符，我们可以在不写完整文件名的情况下读取到该database.php。遗憾的是，<以及>都会被RemoveXSS转义。
 
    此外，我们注意到在RemoveXSS之后，还有一个RemoveWJ函数，我们可以利用该函数，绕过对base的过滤。在检查该函数后，我们发现，他会将%0d过滤为空，也就是会将传参中的所有%0d去除掉。因此，我们可以将原先传参中的database.php改写为databa%0dse.php，这样子一来，经过两个函数的过滤之后，我们最终可以成功读取到database.php。

第三种getshell方式：
thinkphp assign函数文件包含漏洞
    在审计代码时，我们发现了愚蠢的开发对于php函数的错误用法，该错误用法可以导致一定版本范围内的tp版本出现任意文件包含漏洞。存在漏洞的代码如下:
if(input('param.id')){
    $id = input('param.id');
    $data = Db::name('config')->where('id',$id)->find();    $this->assign($data);
}return $this->fetch();

   具体的漏洞分析，请参考如下文章，此处不再赘述：

https://mochazz.github.io/2019/04/04/ThinkPHP5漏洞分析之文件包含7/#漏洞分析

    在此，只要能够完全控制$data中的内容，并控制其中cacheFile字段，我们即可以包含cacheFile字段指定的文件。例如，当

$data['cacheFile']='/etc/passwd'


    那么我们即可在fetch渲染时，实现对/etc/passwd的文件包含。此处 $data 字段来自于数据表config的结果，因此我们只要在config中添加一个cacheFile字段，并将其内容指向我们要包含的文件，即可实现任意文件包含。因为我们已经控制了数据库，所以这个操作便可以行云流水地完成。
