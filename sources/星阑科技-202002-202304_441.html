1. WebAssembly & Web-Browser CVEs




WebAssenmbly （简称 wasm ）是一种 Web 上新型可移植的二进制指令集，且节省大小速度高效。它同时由四种浏览器（ Chrome ,  Edge ,  Firefox  and WebKit ）的开发人员研制，目前在桌面/移动端的主流浏览器中默认开启，运行在各自浏览器的 Javascript 引擎上，例如 V8 。


在 caniuse.com  [1] 上可以看到，2020 年一月时，已经有 88% 的互联网用户可在浏览器上运行 wasm ：



在不同 Javascript 引擎上添加这么一种新的二进制指令格式往往需要十分大型的代码开发，对安全研究人员来说，也同时预示着一种新型的攻击面。研究人员已经发现了一些 Webassembly API 的安全问题，例如 Natalie Silvanovich (@natashenka)  [2] 在 V8、WebKit 和 Firefox 上的发现以及 @fluoroacetate  [3] 在闭源小米 Mi6 浏览器上发现的  CVE-2019-6743  [4]


其它 WebAssembly 浏览器的 CVE 可参考：


  •  The Problems and Promise of WebAssembly by natashenka – blogpost [5] ， slides  [6]  

  •   A collection of JavaScript engine CVEs with PoCs – github  [7]

  •  Apple Safari Wasm Section Exploit CVE 2018-04-16 by MWR-labs – write-up  [8]





2. WebAssembly JavaScript APIs





WebAssembly JavaScript APIs 有多个函数和 WebAssembly 对象构造函数（用来创建和实例化 wasm 模块）组成，例如：


  • WebAssembly.instantiate()  [9] 函数.

  • WebAssembly.compile()  [10] 函数.

  • WebAssembly.validate()  [11] 函数.

  • WebAssembly.Global()  [12] 对象.

  • WebAssembly.Module()  [13] 对象.

  • WebAssembly.Instance()  [14] 对象.

  • WebAssembly.Memory()  [15] 对象.

  • WebAssembly.Table()  [16] 对象.

这些 API 是我们 Fuzz 的主要目标，因为它们设计过好几个 CVE 且在每个浏览器/Javascript 引擎实现中都很常见。关于这些 API 与使用方法可以参考：


  • WebAssembly by Mozilla MDN [17]

  • WebAssembly Web API by W3C [18]

  • Understanding the JS API [19]





3. 使用 Dharma/Domato 创建符合 WebAssembly APIs 语法的用例





Dharma [20] 是一个基于生成的上下文无关语法 fuzzer ，由 Christoph Diehl  [21]（Mozilla Security team） 在2015年开发。该工具可根据给定的语法描述创建语法文件（像Javascript 或 HTML ），概念与 Google Project Zero  Ivan Fratric [22] 开发的 Domato [23] 类似。


个人更喜欢 Dharma ，但这两者的应用互相转换应该不难。



其中工作量最大的地方在，需要读懂所有 API 的介绍与细节才能创建合法的 wasm 对象和函数调用。关于 Dharma 语法的具体使用，可以查阅此处：https://github.com/MozillaSecurity/dharma#dharma-grammar-cheatsheet 。当 Dharma 配置好后，使用该命令生成测试用例：


dharma -grammars dharma/wasm.dg -count 100 -format js -seed 1337 -storage output_folder


输出文件夹就会包含多个类似文件：



这里开源了 WebAssembly 语法文件：


https://github.com/pventuzelo/fuzzing_browsers_wasm_js。

4. JavaScript engines built with ASan (Chrome/V8)





这篇文章只针对了 Chrome/V8 因为它可以节省大量时间在编译、调试上。AddressSanitizer [29] (ASan) 是一个基于编译器插桩 （LLVM） 的内存错误检测功能，被用来检测多种漏洞（像 UaF，HBoF 等）


使用 Chrome/V8 的理由如下：


  • Google 提供了带 AddressSanitizer 编译好的 Chrome 可执行文件

  • 其中一个可执行文件是 d8 [30] ,V8 自带的开发者命令行工具。

  • 通过 d8 可激活开发者 WebAssembly 功能，例如 anyref，threads，simd 等。

  • 编译好的版本是最新的且用 Google gsutil tool [31] 和以下命令方便下载


gsutil cp $(gsutil ls "gs://chromium-browser-asan/linux-release/asan-linux-release-*.zip" | tail -1) .


如果想编译其它带 ASan 的 Javascript 引擎，可参考：


  • Building WebKit/JSC with ASan [32]

  • Firefox/Spidermonkey ASan builds + compilation intructions [33]

  • V8 build tests with ASan [34]





5. Fuzzing & monitoring – 简单的方式




最后一步便是将 JS 文件发送给 d8 。一个简单的方式是用一个小脚本

（https://github.com/pventuzelo/fuzzing_browsers_wasm_js/blob/master/fuzzing_d8_asan.sh），它会不断循环并且：


  •  把每个 Dharma 生成的 js 文件输入 d8

  •  追踪程序执行的返回结果

  •  如果返回结果不是 0 就把测试用例存起来


这种方法很简单且没经过优化，如果不想写脚本，也有更简单的办法，就是使用 honggfuzz [35] 接受并执行测试用例。



Honggfuzz [36] 很容易且很好用，由 Google 的 Robert Swiecki [37] 开发。在Honggfuzz [38] 的 dry-run 模式下，所有测试用例会在不同线程下执行，监控 crash 并保存，即只需执行一下命令：


honggfuzz -t 5 -n 4 -i input_wasm_js/ -- ./d8 ___FILE___


有人已经将 Dharma 直接和 honggfuzz 结合起来了：


https://github.com/Sbouber/honggfuzz-dharma





6.深入&总结




目前我们实现了基于生成的 fuzzer 来 fuzz WebAssembly APIs。上面提到的 Dhrama只针对 WebAssembly API ，如果想针对其它 Javascript 特性（Array，UIntArray，Number 等）需要再优化，同时，还需要另一个文件生成器来创建合法的WebAssembly bytecode ，同时还需要使用 WebAssembly.Module() [39] 构造函数保存在数组里。
