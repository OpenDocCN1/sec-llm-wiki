RSAC 的 Early Stage Expo，主要是为新兴厂商所设置的产品和演示展区，在大型公司产品不断趋近于成熟和稳定的同时，新兴厂商的创新点往往可以给我们很多不一样的思路和视角。今天我们前方记者 —— 星阑科技CEO王郁和其他CEO深入探讨以后，向我们发来了四种产品的新鲜解读，同时也继续给我们带来了最后一个“网络安全故事”，接下来，我们就一起去看看吧~
产品报告



PlexTrac



Purple  Teaming 平台，使得 Red Team 和 Blue Team 可以通过一个 Web 端平台进行高效的协作，完成从发现到修补威胁的合作流程，同时可以以一种多方合作的全局视角，揭示企业目前所面临的安全威胁情况。 
 
该平台也与市场上的多种安全工具进行了整合，可以从 Nessus、Nexpose 等多种异构数据源中自动获取信息，除此，还可以以集成化的方式，直观展示扫描器等安全评估工具的漏洞输出，并提供各种有效信息和流程控制机制来修复漏洞。
 
对于 Redteam 而言，PlexTrac 可以进行漏洞信息的整合，辅助信息收集、风险评估和渗透测试；而对于 Blueteam 而言，PlexTrac 可以进行 Implement Control、安全监控和应急响应等。
 
当然，本系统本身并不具备安全评估能力，仍需要依靠人工或者其他安全工具进行漏洞的探测和输出。此产品主要解决企业内部各团队及使用中关于安全评估工具的信息孤岛问题，打通从自动化巡检、人工验证、漏洞修复的整体流程，并提供整体的威胁视图，其中一些类似于许多大型厂商所使用的漏洞工单系统，可有效降低安全团队之间的沟通成本，实现较好的协作。

Polyverse



Polyverse 的主要思路是向操作系统引入多态化的内容，从多个系统角度中引入多样性和独特性，进而防范软件漏洞被攻击者利用。


目前该产品主要面向Linux操作系统, 包括 Red Hat ,  Alpine , CentOS , Fedora , Ubuntu , SUSE 和 Debian 等发行版，polyverse 在软件安装时，会向软件包中引入随机变化，使得不同用户在安装相同软件时，获得了不同软件包（引入随机信息，但并不会影响软件包功能）。
 
攻击者在发起对软件的漏洞利用时，攻击者通常需要知道软件的 layout ，如路径、内存地址信息等，使用标准源的时候，大家软件的 layout 也基本是一致的，但在使用 polyverse 会改变多种软件信息，因此当不寻常的位置被触发时，就会引起相关的检测和告警。其实现方法主要是通过特制的编译器，对源上的软件进行重新编译和打包，从而引入软件包的 unique layout 。
 
polyverse 的使用方法也相对较为简单，只要在你自己的操作系统上，使用他们的源，进行软件包的安装即可，据称可以达相当低的 overhead 。
 
其实 polyverse 的思路属于 proactive detection , 即在漏洞利用成功前进行告警，这样可以相对有效的解决检测滞后所造成的的潜在风险损失。但是，由于软件包本身的异构性，在解决安全问题的同时，同样可能会引入一些兼容性及运行稳定性的相关风险，整体的风险收益方面可能仍需要更加谨慎的进行考虑。

SmartPhone Triage -- BlockChain Security



SmartPhone Triage主要能够方便地通过手机等移动设备，借助区块链技术实现数字认证(主要应用于法务、HR、安全认证等领域)，他们主要拥有三种技术，分别为：


  1. 电子邮件真伪验证系统，寄送者在寄信时的邮件画面截图，邮件内容，以及寄件人，收件人，附件档名等信息 Hash 上传区块链保存，收信者在收信后，验证该信件 Hash 与原信件是否一致。

  1. 基于区块链技术的合约签核验证系统，通过将和约签署后的 Hash 上传至区块链永久保存，简化签署时的复杂流程，完成具有不可否认性的合约签署流程。

  1. 网页数字数据防伪机制,提供了应用于网页端的技术。将数据的指纹进行加密转换与验证，在产生数据前，首先侦测是否能启用变更替换数据或网页源码的相关功能，进而要求重启浏览器，避免画面遭到篡改。

 
在区块链技术方面，主要使用 Postchain 这一架构，Postchain 是 BlockChain 2.0 的新技术架构，使用这一架构不需要重新学习底层的区块链技术。凡是具有 SQL 能力的工程师，都能开发区块链应用，同时还能够降低开发难度，同时 Postchain 不仅能将 Rich Data 存储在每个节点，也能够整合数据库，提高数据处理效率，并利用数据库的身份限制，资料加密等功能，让所生成的完全透明的账本，更适合私有区块链。Postchain 使用 PBFT 共识法，只要三分之二节点正常运行，即可达成共识，即便一个节点同步失败，仍能从其他节点检索丢失的资料，重新同步，而且运算速度能够达到 160 - 500 交易每秒。
 
其中涉及的相关技术都属于区块链的常见利用场景，从数字认证的角度结与区块链相结合，确实是一个切入点，也可能是区块链实际落地的一个方向；虽然从技术和易用性角度上可行，但是在实际应用中尚存在法律效应认证等方面不明确性的问题。

ermetic



在 IaaS/PaaS 环境下，身份验证和数据安全机制经常因为复杂的资产环境、未执行标准的DevOps 流程等原因而难以得到保证。在复杂的云环境下，可能同时存在数百种角色和规则，由于开发和运维团队对代码和配置的快速更新，都给管理工作带来了极大的挑战。
 

在传统云环境下，为了构建精确的 risk graph ，需要明确：


  1. 哪些人，和哪些机器，需要访问什么资源？谁来授权？

  2. 哪些人，和哪些机器，现在正在访问那些资源？

  3. 哪些访问是被允许的？

  4. 对于违例行为，是否有监控和反馈的机制？


在资产和角色较为复杂的情况下，仅仅明确以上问题可能就需要花费极大的管理成本，并且为了减少攻击面，云上资源通常还需要进行策略和行为分析，以及可疑行为的自动化监测。

 
针对上述问题，ermetic 通过对身份、权限的透明可视化，来辅助云上管理策略的制定和自动化的执行，并提供高级分析来保证业务正常运行的同时，来减少攻击面。主要具备以下特点：
 
可视化: 能够对人员、账号、角色、权限、数据、计算资源、管理策略进行可视化。
分析：在保证业务连续性的前提下，分析访问策略、权限控制和操作风险。
强制策略：在定义数据访问策略和数据敏感性的前提下，执行强制的访问控制，杜绝 excessive access。
异常检测：针对敏感数据的异常行为的检测。
自动化：生成保证业务运行和安全性的访问控制策略，同时可以进行访问违例的检测。
 
在目前复杂系统管理中，依据最小权限原则通常很难得到完全落地，经常会出现为了方便操作而给予相关人员过高权限的情况，进而导致权限控制松动，造成敏感数据泄漏。ermetic 本质上是对于当前的管理视图进行了更高级的封装，从而在管理人员视角上升维，降低了管理成本。管理人员需要的，不仅仅是对已有权限和资产的简单罗列，而需要更好的组织和更清晰的表达，这一点或许值得所有资产、权限管理类的产品学习。


主题演讲


Nowhere toHide: How HW Telemetry and ML Can Make Life Tough for Exploits



本次的演讲者为英特尔的Zhang Zheng和Rahul Ghosh，主要带来了硬件遥感 (telemetry) 是如何进行exploit 的检测。


会议首先介绍了一下对于 Malware 检测机制的演进，从文件、内存、行为的检测逐步演化到基于 AI 的检测，以及基于硬件的检测；同时攻击者也会使用 AI 进行辅助，目标也逐渐从 PC 和 server 扩展到云和 IoT 。



关于硬件遥感 (telemetry)，其实现基础主要是基于，现代处理器可以通过芯片上的单元来监控 microarchitectural 事件。



从 microarchitectural 事件角度，Exploit / 恶意软件和正常软件所产生的事件序列具备较大差别（尤其是在执行哈希计算、加密、堆喷射、缓存操纵时），因此可以作为 telemetry 签名来用于检测。


但是由于 PMU 事件数量众多，如何选择事件来作为其相应的特征，是一个需要解决的问题；目前较好的方法是使用基于 IG 的事件筛选方式（类似于 TF-IDF 中使用 IG 来进行选择），并从中选择能够作为特征的 event ，不过通常这种时间的 IG 值都较高。




选择合适的时间后，我们可以按照以下的方法计算概率值来作为相应的特征。
 


获取特征后，按照 ML 的常见模式，我们可以使用 Feature Map 来观察其低维映射，确认当前的数据在分布理论上是否具备模型可分性，可以看到，由于正负样本之间存在明显的分布边界，因此容易使用模型进行检测。

由于 PMU Driver 可以运行在硬件上，也可以通过 VMM 和底层做交互，因此 PMU 检测方法在裸机和无客户系统的虚拟机上都可以很好的运行。



在现场演示了一个 demo ，可以看到，在右侧的恶意程序执行后，左侧的检测系统能够很快的给出告警。


此外，在事件的取样中，可以引入更多数据，如 IP 指针、Flag 、寄存器、交互内存数据、TSC 值等，都可以被用作特征。LBR 也可以拿来利用。


此次会议主要介绍了基于硬件事件取样并结合 AI 的 Exploit/Malware 检测方法，在当前检测规避主要集中于在 Loader 、混淆等技术方案时，通过更底层的 CPU 事件进行检测确实能够拓展防守方的战略视野，即尽可能找到攻击方的透明点，这种思想在RASP中也有所体现。此外，我们也可以从中看到攻防双方在 AI 技术和硬件基础设施方向都有不断发展的趋势。
