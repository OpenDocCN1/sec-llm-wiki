## babyqmk

搜索字符串发现qmk\_firmware，搜索得知是一个开源键盘固件。

![](../Images/8d027e52a09d9c9f334297f87072dd2f.png)

搜索字符串，找到输出`Combo 1!`的位置。查看qmk手册得知Combo激活时会回调`process_combo_event`函数。

![](../Images/5772c7f38602cdde6909c52022ab7b85.png)

Combo的按键信息存放在`key_combos`中，找到`key_combos`结构体的位置，根据keycode得到对应的按键，得知输入`CHUNQIU`会激活Combo_1，输入`GAME`会激活Combo_2。

![](../Images/1d81776df79b01bd79e07c89322757a2.png)

通过process\_combo\_event函数得知，不同Combo激活会激活不同Layer。Layer信息存放在keymaps中，提取每个Layer的数据并格式化。观察得知共有3个Layer，每个Layer只有0-9A-Z按键的keycode不同，且Layer2中0-9位置上的按键继承了上一层Layer的keycode。

![](../Images/d88a374891a25e2fa402fbb28ff31f80.png)

找到输出OK!的位置。查看qmk手册得知qmk会在按键按下或抬起时回调`process_record_user`。这个函数会根据当前的Layer对keycode进行不同的变换，然后根据变换后的值按下KeyTable中对应的按键。

![](../Images/b78dabfab00c8dae7eecf04bf4e3dc97.png)

根据输出的结果求出变换前的keycode，然后根据不同的Layer将keycode映射回原来的按键就可以得到flag。

搜索报错可发现是特征值`UPX!`被抹去导致的（packers - Decoding the UPX ELF header file - Reverse Engineering Stack Exchange(https://reverseengineering.stackexchange.com/questions/3335/decoding-the-upx-elf-header-file)）。

查看UPX壳源码可知（也可以自己打包几个elf看看），unpack时会依次在三个地方检查`UPX_MAGIC_LE32`（即`"UPX!"`）：

① 在倒数第36字节偏移处检查，如果特征值不符就会转入`throwNotPacked()`异常抛出函数，打印`not packed by UPX`；

② l\_info在Program Header后面，由`readelf`可以看到应该在第字节偏移处开始。

![](../Images/8ef658b3a8257d38358998eda97cfeb6.png)

而l\_info的结构如下：

```
    __packed_struct(l_info)     // 12-byte trailer in header for loader

unsigned char
 l_version;unsigned char

 l_format;
```

显然`UPX!`应该在l_info的第4字节偏移处，即整个文件的字节偏移处。如果这里的特征值不符就会转入`throwCantUnpack()`异常抛出函数，打印`l_info corrupted`；

③ 在倒数第46字节偏移处检查，如果特征值不符就会转入`throwCompressedDataViolation()`异常抛出函数，打印`Exception: compressed data violation`；
