### 02 bug环节

在比赛运维期间，依旧出现了喜闻乐见的玩bug系列。![](../Images/2ecd7ad3a671f125d386a25f9b9d1084.png)

之前大晚上写合约，代码写的迷迷糊糊，导致 sendGift 合约代码给写成了transfer。然后在很多次测试中居然还没发现这个bug，简直离谱了...

好吧，正确的代码是应该是如下方法：

```


    function sendGift(address payable addr_,uint256 amount_) public onlyPlayer{
```

本来这个是可以触发一个漏洞点的，但是最后发现，很多人玩游戏居然不涨coins。仔细检查后发现是这个问题，简直想吐血。

因为在比赛中，如果贸然中止合约而创建一条新的合约，明显会对比赛产生比较大的影响。所以在比赛中仅仅是修改了交互时调用合约的逻辑，本来的接口走向是 `前端 saveMoney -> 后端 saveMoney -> API sendGift -> contract sendGift`，经过思考之后，决定将API调用的方法改成 `payToUser`，这样在前端看起来逻辑是正常的，只不过本来是合约主动印发coins变成了由owner被动发coins...，不管怎么说，反正暂时问题是解决了～ 

什么？你问如果owner的coins发完了怎么办？hhh，owner可以自己印发哒。![](../Images/2d4c27e5143f2933b528b2f423d84b5b.png)

  

### 03 coins重放攻击

言归正传，我们可以把目光聚焦在coins的发送上，coins是根据我们游戏中获取的金币数量决定的，所以每次游戏之后，应该会有一个请求跟后端代码进行交互，发送当前回合获取的coins数量。所以，我们可以使用chrome分析网络请求。![](../Images/6620acd7c0385a524afecb2cff7bcb19.png)

![](../Images/dea54d457b75128abdf6e51a28fbc7e6.png)

查找一下发送请求的代码，不难在levelState.js中发现它的身影。![](../Images/48509b748e8a8d77cf5a28d948552a99.png)从图中可以看出，代码使用jq的post方法，将 coins 发送到 /saveMoney 接口。

既然我们知道了coins的发送方法，那么我们可以尝试着使用bp或者别的工具抓包重放，便可以让coins很快的增加了～

但是有的同学发现了，修改coins之后，发现服务器返回了一个failed的问题，然后以为是存在什么验证逻辑，就没继续测试了。其实这里只是一个很简单的判断，仅仅是判断了每次请求中coins的数量是不是大于200，如果大于200，那么就返回failed，否则的话，就正常往合约中发送数据。![](../Images/a1a76c01c250bc4381509629b5402143.png)

  

### 04 合约的分析

我们从web页面中可以获取到的信息基本就是这么多，接下来得开始合约的分析了。

从web页面中可以获取到合约的地址，其实不从web页面，从我们自己的metamask中也可以看到合约的地址，是 0xA658070ae2b6701570C7eF04ac5765a825A37013。![](../Images/8e953376f8263a1a3d9817de4ff2938e.png)跟踪进入之后，发现合约是一个共享的状态，所有选手都可以在合约上进行自己的操作。

![](../Images/f00f77e7c8954bfaa7d6926faa5ce989.png)

同时还没有开放源代码，我们只能使用在线分析工具来进行分析。

![](../Images/049863bdb95757f4fd14a2b5a413f150.png)

以太坊合约代码分析工具网址是：https://ethervm.io/decompile/ ，我们可以输入以太坊 上的合约地址，便可以获取合约的evm汇编代码(https://ethervm.io/decompile/rinkeby/0xa658070ae2b6701570c7ef04ac5765a825a37013)。

### 06 任意用户地址余额转移

其实再看合约，会发现很多 0xd8c07fb3 方法。![](../Images/b3f8038c067100654872dc330682abca.png)点进去看下，发现传输的data内容如下：![](../Images/3118d18d7bd37db3c31218c5a35e6cf6.png)这个最终的结果是，前面76d用户的coins减少了40,000。后面 336 的coins则增加了这么多。

我们可以往上看看，最开始我们就说，合约的创建者是 0x76d19a6b01d2a3...(https://rinkeby.etherscan.io/address/0x76d19a6b01d2a33d66222f255357003dd7e3c613) , 那么这个方法应该就是直接从owner中分出来金币给选手账户。分析汇编代码，发现此处也是很有问题的，可以造成任意用户地址coins转账，危险程度非常高～![](../Images/851bccf8f4229ece9f9badfbbd1408e3.png)有兴趣的同学可以自己尝试构造一下攻击代码，将owner里面的小钱钱都转走哈～
