作为巅峰极客连续四年的技术支持团队，和紫金山实验室的合作伙伴，在本次比赛中我们通过mimic-game题目模拟了紫金山实验室的拟态仿真技术，正常用户访问的服务其实是在三个不同的异构体程序中互相切换，但是全程没有任何感知。


题目中C语言编写的程序存在一个严重的栈缓冲区攻击问题，但是当有人攻击时，却发现并没有办法成功利用，这是为什么呢？因为与之交互的时候并非只有C语言程序，还有两个伴随程序（go和python）也参与了正常交互，中间的裁决程序会对数据交互进行裁决分析，判定三个程序的输出是否一致，从而阻止了进一步攻击的可能。


类似于生物界的拟态防御，在网络空间防御领域中，使用拟态技术可极大的提升黑客攻击的难度。希望通过这道题，可以让极客青年们更好的了解拟态防御原理和拟态技术，对线下决赛的拟态挑战环节和未来工作中活学活用会有更多帮助。




 mimic-game 


mimic-game 日常非预期，然后经过一番考虑，出了一个pro版本，最后发现没有师傅做出来，(T_T)


先说一下非预期解法吧，首先拿到附件，解压后发现给出了很多的文件，

其实主要关注的只有obs，mimic32这两个程序了，毕竟go、py虽然有漏洞，但是不是这么简单能够挖出来的对吧~


检查一下obs程序，发现是一个简单的裁决器，每次nc交互的时候，会随机分配一个go或者是python程序作为伴随程序，如果发现跟我们的32位C语言的ELF程序输出不一致，就会退出。




因为程序每次都会加载mimic32程序，所以如果想要稳定利用的话，应该是必须要使用这个程序的漏洞进行攻击的。所以我们继续看看这个mimic32到底是什么东东。



main 函数还是比较简单的，首先使用time(0)作为种子初始化随机数生成器。然后就是一个菜单部分，只有1选项是有用的，2选项是空的，3是直接退出程序。


跟进guess函数查看一下，整体逻辑也是比较简单的，就是可以输入一个动物名称，然后对比动物是不是跟程序随机算出来的一样，如果一样，就输出Good，否则显示动物的名称。



这里很容易注意到 input 变量，它的定义是一个 0x20 的字符串空间，存放在栈上，但是在我们输入的时候是可以输入 80 也就是 0x50 长度的字符，这很明显可以造成栈溢出漏洞，程序也没有开启canary保护，很nice。



那么这里就可以用栈溢出来操作了，但是具体要使用栈溢出来做什么呢？要知道，程序这里的输入输出都是被obs接管了的，不存在任何的泄露地址的可能，所以考虑能不能利用stderr做一些文章，毕竟obs中没有对stderr做检测的。


那这里就有至少两种方法去操作了：


第一种就是栈迁移，劫持rbp到bss区域，然后控制返回地址为read函数，这样就可以在bss区域写入我们构造好的rop链，执行ORW方法，将读取到的flag字符串放到标准错误流中。


第二种就比较直接，使用ret2dl_resolve方法去攻击，重新解析一个system函数到一块可写的位置，最后调用这个system函数，执行命令cat flag >&2就可以了，新版本的pwntools对这个漏洞的利用提供了非常简单的方法，具体的可以参考一下官方文档。


在比赛中，也看到了有不少选手想使用反弹shell的方法来操作，但是很可惜都失败了，因为一开始就想到这种解法，但是过于简单了，就把docker访问外网的权限给ban了，2333。




mimic-game-pro


上述两种攻击方法都是基于标准错误流开启的情况下实现的，那么有没有方法可以做到，在关闭标准错误流的时候，也能成功利用呢？


这里也就是mimic-game-pro题目的利用方法，也是这个题目刚开始设计时候想要考察的知识点。


我们继续看看pro版本的程序有什么变化，使用ida检查一下，发现只是添加了两行代码，分别对obs、mimic32两个程序，均添加了一行 close(2) 的操作。这样的话，我们就没办法利用错误流来获取flag了。




现在，请大家思考一下，在32位程序中，如果开启了aslr，那么我们想要猜测出libc中的system地址，概率是多少呢？第一位是0x7f固定，后面1.5位固定，那么就是 1/4096 ？其实不是的，我们可以编写代码试试。


#include "stdio.h"
#include "stdlib.h"
int main(){
    void *p = puts;
    puts("Hello world");
    system("whoami");
    printf("puts addr -> %p\n",(void *)**(unsigned int**)(p+2));
    p = system;
    printf("system addr -> %p\n",(void *)**(unsigned int**)(p+2));
}



仔细观察，我们发现了什么？没错，可以看到中间的3位中，后面两位是不断变化的，但是第一位不是5就是6，非常稳定。所以就可以把概率直接缩小到 1/512。有了这样一个小的概率，那么其实我们就可以做很多有意思的事情了。

那么我们接着就可以使用shell命令来盲打flag。



如果我们猜错了flag，那么就会输出fail，进而导致裁决器退出，所以可以根据io是否还存在来判断我们的猜测是否正确。
