解题思路

在IndexController中可以看到代码

public function hello($name = 'ThinkPHP5')
{
    $file = input('get.file');
    $res = file_get_contents($file);
    file_put_contents($file,$res);
    return 'hello,' . $name;
}

file_get_contents 的参数作为 file_put_contents 的文件名，结果作为写入的内容。如果要控制文件内容，需要使用伪协议请求外部文件，但是文件名会不符合要求。
因此需要使用 php://filter 将thinkphp5的log文件转换成phar格式的文件，再使用 file_get_contents 触发phar反序列化。

  1. 清空log文件内容
    /index.php/index/index/hello?file=php://filter/read=convert.iconv.utf-8.utf-16be|convert.quoted-printable-encode|convert.iconv.utf-16be.utf-8|convert.base64-decode/resource=/var/www/html/runtime/log/202105/19.log，不同的日期log文件名不同。

  2. 触发error log，将convert.quoted-printable-encode编码的phar payload写入log文件中，X-REAL-HOST 请求头会覆盖log文件中的host。反序列化链参考N1CTF2019:https://github.com/Smi1eSEC/My-CTF-Challenge/tree/master/N1CTF2019/sql_manage

由于这里调用了file_get_contents()，且其中的参数可控，所以这里可以通过phar://协议去触发phar反序列化。

审计一下看看原来的链子可以用不，发现好像没啥变化。

于是构造rce链子生成序列化字符串，并没有发现这条链子有什么问题，应该就是老的利用链和新的反序列化方式，显然就是file_get_contents触发phar发序列化。问题是这里必须是一个文件，emmmmm，然后主办方给了暗示说 log。日志文件怎么去搞？

想起了最近复现的一个比较火的漏洞 Laravel Debug mode RCE（CVE-2021-3129），通过 log文件去写phar。

贴一个链接：https://xz.aliyun.com/t/9030#toc-4

作者在文章中提出了使用php://filter中的convert.base64-decode过滤器的特性，将log清空。

最终通过这样的方式去清空log

  • 使用convert.iconv.utf-8.utf-16be(UTF-8 -> UTF-16BE)

  • 使用convert.quoted-printable-encode(打印所有不可见字符)

  • 使用convert.iconv.utf-16be.utf-8(UTF-16BE -> UTF-8)

  • 这时候再使用convert.base64-decode过滤器就可以成功清空了

php://filter/write=convert.iconv.utf-8.utf-16be|convert.quoted-printableencode|convert.iconv.utf-16be.utf-8|convert.base64-decode/resource=php://filter/write=convert.iconv.utf-8.utf-16be|convert.quotedprintable-encode|convert.iconv.utf-16be.utf-8|convert.base64-decode/resource=/var/www/html/runtime/log/202105/29.log

    req.session.monster = req.session.monster.slice(1);
    his.push("你赢了耶！");
  } else {
    his.push("你输了，刷新以重新开始");
    req.session.init = false;
  }
  req.session.history = req.session.history.concat(his);
  res.send({message: his.join("\n")});
});
