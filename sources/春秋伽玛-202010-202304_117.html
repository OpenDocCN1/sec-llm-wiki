随着比特币、狗狗币等虚拟币交易的火爆，其背后也藏着巨大的安全风险。在大起大落的行情下，如有不慎，投入的资金就可能尽数水漂。春秋GAME专家组以此为背景，设置了一道Misc题目[GameContract]，构建了一个股票交易所场景，模拟了交易中用户自己资金的变化情况，同时还在发行ChunQiuGame Coin(简称CQGC)的合约中增加后门函数，方便合约所有者进行随意增发代币，提供给选手去审计发现。本题从多个角度考察了选手对智能合约漏洞的利用，希望能有更多的选手将目光转向区块链安全。




出题前的基本构思

1. 每个选手可以根据token在CQGC（ChunQiuGame Coin）合约上创建自己的账户
2. 服务器存在一个web页面，展示虚拟股票的信息，选手可以自行买入卖出

80端口web页面功能

  • 查询当前所有股票价格，数据从redis中获取

  • 当账户余额低于一定数值之后，可以申请低保（空投 10$，最多申请 3 次

  • 可以自由买卖股票，卖出时有3%手续费


3. 监听脚本。用于检查合约用户，发现payforflag事件后，从内存数据中取出对应地址的email，然后再去发送邮件


合约的一些设定


1. 合约保存所有用户的账户余额，假定货币单位为$

2. 允许自由转账，但是转账需要扣除 20% 手续费（a -> b 100$，a扣除 100$，b 收到 80$） （ 出题人忘记写了

3. 合约使用ERC20代币作为流通手段

4. 合约中存在购买flag 函数，需要消耗 1000$

5. 合约存在挖矿函数，分为简单挖、随心挖、暴富挖，难度不一样，启动挖矿函数，需要缴纳一定的金额(1$

    - 简单挖，5 位0的sha3，奖励 10$ (基本上10s

    - 随心挖，6 位0的sha3，奖励 100$（时间不定，200s ~ 2230s

    - 暴富挖，7 位0的sha3，奖励 999$（时间不定，900s ~ 1.5h

6. 合约存在彩票函数，允许购买彩票

    - 每张彩票 2$

    - 当购买彩票数 >10 && 当前区块高度 - 当前轮彩票开始时区块高度 > 20 后，进行开奖

    - 奖励为当前彩票池的90%，剩下10% + 100$作为奖池剩下资金。初始奖池资金为100$

解法一

把握时机，低买高卖


根据不同股的价格波动，我们可以在价格低点的时候入手，然后涨价之后就卖出。


这里注意的是，千万不要买价格很高的股，因为一点也不划算。


我们以CQG1为例



从图中可以发现，价格最高的时候涨到了800多一股，即使我们从中间，比如400的时候买入，我们初始只有10,0000，能买250个，涨到800后，价格才翻了一倍，卖出去无非收获一倍的资金。跟1000,0000还差得很远。


最好的方法是购买低价的股，比如CQG8，CQG4等，根据不同时间买不同的低价股。




可以看到，如果我们在很低的价格，比如1的时候，全部购买之后，那么它只要涨到2，我们就赚了一倍，只要随便涨到100，我们就翻了100倍，血赚。。。


同时这里还有一个小的逻辑漏洞，出题人只考虑到股票价格不能为负数（不然随便买不就可以了？），但是当时脑子缺了一根弦，没想到0也可以，hhhh。所以可以利用此处的漏洞，在0的时候直接大量购买（反正不花钱），只要它涨了，那就直接卖出去，无本万利啊有木有，解出该题的两支队伍均是使用该方法去获取flag的。也算是一种预期中的非预期解法吧。Orz

解法三

财大气粗法


我们观察源码，发现其中有定义fallback函数，该函数一般是用来转账的时候触发调用的。我们分析代码：


// get flag
function payForFlag() public onlyPlayer{
    _burn(_msgSender(), 10000000); // 扣除余额
    emit getFlag(_msgSender());
}
// fallback
fallback() payable external onlyPlayer{
    // _mint 函数是给合约中自己地址增加余额的，相当于 1eth = 1 CQGC
    _mint(_msgSender(),msg.value/1 ether * 10000); 
}


根据这个函数，我们可以知道，只要我们给合约转1000的eth，就可以成功调用payforflag，这种属于典型的财大气粗法，非土豪人员是无法使用此方法的。(壕：诶，我就是有钱任性～)

// 抽奖，从购买彩票的人中间，伪随机方法抽取一名幸运观众，送出奖池的 90
function lottery() public onlyOwner{
    uint256 len = _tickets.length;
    emit log(_tickets.length,"tickets length");
    emit log(block.number,"block number");
    //require(_tickets.length >= 10 && block.number - _startNumber >= 20, "Not the right time yet");
    // 确认购买彩票的数量达到20个 而且 当前区块的高度比上一次抽奖的高度要高至少20块后，才能开奖
    if(_tickets.length >= 20 && block.number - _startNumber >= 20){
    // 伪随机选取一个幸运数字，（0 ～ len - 1 之间)
        uint8 luckyPlayerNumber = uint8(uint256(keccak256(abi.encodePacked(block.timestamp, block.difficulty)))%len);
        // 奖金
        uint bonus = uint(_prizePool * 9 / 10);
        emit luckyLog(_tickets[luckyPlayerNumber],block.timestamp);
        // 重置奖池，余额 = 之前奖池的 10% + 100 
        _prizePool = uint(_prizePool / 10) + 1000000;
        _mint(_tickets[luckyPlayerNumber],bonus);
        _startNumber = block.number;
        // 删除所有彩票
        delete _tickets;
        // uint8(uint256(keccak256(block.timestamp, block.difficulty))%251);
    }
}

// lottery end ---------------------------------------------------------

 pow解法 


下面是 pow 函数的源码 + 注释


// pow stast
function pow(bytes memory calcStr) public returns(bool){
    // 固定扣除 1,000 
    _burn(_msgSender(),10000);
    // 计算 hash ，salt 为注册的用户 addr
    uint hashNumber_ = uint256(keccak256((abi.encodePacked(_msgSender(),calcStr))));
    // 取 hash 的前8位
    uint headHashNumber_ = hashNumber_ >> 0xf0;
    uint amount_ = 0;
    // 如果该hash已经出现在hash list中了，那么就直接返回 false
    if(!_powHash[hashNumber_]){
        return false;
    }

    // 否则 根据前7位的0的个数，来计算挖矿奖金
    if(headHashNumber_ < 0x10){
    // 前7位都是0，奖金为 999,0000
        amount_ = 9990000;
    }
    else if(headHashNumber_ < 0x100){
    // 6个0，奖金 100,0000
        amount_ = 1000000;
    }
    else if(headHashNumber_ < 0x1000){
    // 5个0，奖金 10,0000
        amount_ = 100000;
    }
    else{
        return false;
    }
    // 发放奖金
    _mint(_msgSender(),amount_);
    // 将hash加入hash list
    _powHash[hashNumber_] = true;
    emit powLog(hashNumber_,calcStr,_msgSender());
    return true;
    //emit log(hashNumber_,"hash number");
    //emit log(hashNumber_>>4*60,"aaa");
}
// pow end ----------------------------------------------------------

pow 函数比较好理解，其实就是通常意义上的挖矿函数，只是这里的挖矿计算比较简单了，只计算7个0的hash头，这个比真实的比特币挖矿难度低了不少，实际上，2009年1月产生的第1000个比特币区块时，需要计算的hash前面为0的个数就已经是8个了（00000000c937983704a73af28acdec37b049d214adbda81d7e2a3dd146f6ed09)，到了目前(2021.05.31)，更是涨到了0000000000000000000d4ff4789a67eb79676e200d5db459ffd951e3054bec0c(https://btc.com/0000000000000000000d4ff4789a67eb79676e200d5db459ffd951e3054bec0c)，前面19个0！！！
