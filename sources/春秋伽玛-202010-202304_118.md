# 01

  

双边协议@1.5

  

**出题人：小蓝蓝 @W&M**

###  设计思路 

1.  题目创设性的将漏洞设计的着眼点放在数据协议上。
    
2.  选手在链接题目时会发现远端传输的都是Base64编码后的数据，且解码后虽然能看到有意义的数据但是会发现有额外数据。
    
3.  题目中定义了专用数据包，格式如下：
    
    | 1bit~8bit || 8bit~16bit |
    | --- | --- |
    | Magic Number || Message Length |
    | --- | --- |
    | Key Length || Content Length |
    | Key(自由长度) || Content(自由长度) |
    
4.  选手在和远端服务器交互时同样需要传输封装后的数据。
    
5.  远端服务器在接收数据后会首先提取0x20字节的首部，依次检查魔数以及字段大小是否合理，随后根据字段大小提示提取Key，最后提取Content并通过Key解密。
    
6.  漏洞埋设点是多个逻辑缺陷综合引发的：
    
7.  由于加密使用了SM4-ECB变异算法，其加密块为32bit，因此将涉及填充，而填充逻辑设计成了越界读。
    
8.  由于Edit函数过度信赖协议的Content Length字段，造成越界写。
    
9.  由于时间原因，本题目使用了泄露Libc即可getshell的思路，未达到预期的堆布局getshell难度，故题目标号使用了1.5。下一个版本将对此部分难度进行增加。
    

###  writeup 

1.  题目开启了全保护。
    
2.  分析主逻辑发现安全。
    
3.  分析逻辑发现在自有协议的实现中，数据封装时存在SM4分组加密，当明密文块不满足分组长度时越界读的情况。
    
4.  分析逻辑发现在自有协议的实现中，数据解封装时存在用户传入的密文包含填充字节时将填充字节越界写的情况。

    ![](../Images/d3e4a9122544cd636afb18abe16dda11.png)

    ![](../Images/b6f4b8ee3bf92bc88993290144881ed1.png)

# 04

  

Safe\_heap

  

**出题人：pzhxbz @Nu1L**  

**设计思路 **

之前闲逛的时候看到了mimalloc(https://github.com/microsoft/mimalloc)，

发现它的secure mode非常有现实程序中堆风水的味道，并且经过简单的测试之后也能大概明白它的分配方式，并不需要完整的逆向其分配机制。所以这个题可能和传统的glibc  pwn思路完全不一致，利用mimalloc的secure mode的随机性，是有可能将能溢出的buffer申请到存放buffer的堆块之前的，并且利用show功能也能去测试覆盖是否成功，而覆盖到存放buffer的堆块之后就有任意地址读写了，和堆管理本身的东西就没有关系了，所以后续利用也不算很难。

**解题思路 **

1.  逆向分析程序，发现程序被混淆，手动patch异常处理的部分即可正常f5.
2.  逆向程序，在获取输入的函数中发现size为0时程序不会补0，可以利用这一点泄露加密使用的key，但是有一定几率会段错误。
3.  在edit函数中发现负数溢出，可以覆盖下一个堆块的内容
4.  编写代码测试未知的堆分配算法，发现有可能申请到数据之前的堆块，从而溢出到数据：
