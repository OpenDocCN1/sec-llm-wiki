0x01 简介
在内网环境中，windows系统不仅覆盖了大多数的个人PC主机系统和部分核心的生产服务器系统系统。Windows后渗透技术结合内网定位技术可以帮助快速的发现主要的特殊资料和内网横向的凭证信息。

0x02 Windows下DPAPI信息获取与利用

2.1 DPAPI介绍

Windows系统自2000版本以后为了对数据进行保护，使用了Data Protection Application Programming Interface（DPAPI）接口对敏感的数据信息进行加密解密。其信息包括IE、Chrome部分浏览器信息、远程桌面身份凭证、Outlook、windows mail等等。在进行内网凭证搜集以及第三方取证的过程中，DPAPI的获取对我们解密相关凭证数据至关重要。
2.2 DPAPI作用流程
DPAPI的加密采用对称加密，密钥文件被称为Master Key File，该密钥文件存储在%appdata%/microsoft/protect/%sid%路径下，加密解密使用64位随机字节码经过用户密码等信息加密后生成。
在DPAPI的作用流程中，应用程序向DPAPI传递明文的信息数据，DPAPI会调用系统API函数RtlGenRandom，该函数将返回64个伪随机生成字节并使用用户密码、安全标识符（SID）和其他16位字节的随机数据（salt）对返回的随机字节进行加密。
加密过后的Master key将获取以GUID(全局唯一标识符)的唯一名称，每个DPAPI Blob将存储该其GUID，该GUID也是masterkey密钥和加密的程序数据内容的链接通道。
数据经过加密后DPAPI将向程序会回送加密后的数据块BLOB，以完成一次加密。

2.3 以Chrome和RDP为例的凭证获取与解密

以被DPAPI保护的Chrome数据和RDP远程连接凭证为例完成后渗透时的非加密凭证收集。按照其加密方法获取BLOB应用数据文件和对应的加密密钥即可进行解密。
Chrome的数据加密文件以sqlite数据格式存储在appdata/local/google/chrome/user data/default/位置下，RDP远程连接凭证则通过注册表和文件进行链接，RDP远程连接将凭证存储在注册表HKEY_CURRENT_USER\Software\Microsoft\Terminal Server Client\Servers位置下，同时将RDP连接的密码以文件的形式保存在AppData\Local\Microsoft\Credentials\目录中。
对DPAPI解密常用的三种方法有：在线获取masterkey解密、lsass进程提取master key解密、利用注册表dpapi system解密master key值。
1.在线获取masterkey解密
对于DPAPI加密的密钥masterkey可以在登陆活动状态下，利用mimikatz的dpapi功能sekurlsa::dpapi在线获取获取其密钥值，再加载BLOB加密的数据利用密钥进行解密：dpapi::cred /in:C:\Users\Administrator\AppData\Local\Microsoft\Credentials\RDP密码文件名 /masterkey:key值。
2.lsass进程提取master key
除了直接在线获取masterkey之外还可以通过转储lsass进程进行解密，转储使用procdump dump导出解析lsass进程块（procdump.exe -accepteula -ma lsass.exe lsass.dmp），同样使用mimikatz进行加载lsass（sekurlsa::minidump lsass.dmp）进程其dpapi的解密模块进行。
3.注册表dpapi system解密
除了在线解密外，在本地用户目录下还存储了加密的Masterkey文件，需要利用注册表中的dpapi system键值进行解密，解密过程可以先存储对应的注册表文件HKLM\SYSTEM SystemBkup.hiv和HKLM\SECURITY SECURITY.hiv，然后解析其注册表内容mimikatz log "lsadump::secrets /system:SystemBkup.hiv /security:SECURITY.hiv"，解密对应的masterkey文件mimikatz "dpapi::masterkey /in:C:\Windows\System32\Microsoft\Protect\S-1-5-18\User\04ece708-132d-4bf0-a647-e3329269a012 /system:cur/hex中的m/u值。
0x03 Windows下部分重点应用凭证搜集
3.1 Teamviewer
在对个人主机的后渗透过程中，Teamviewer的远程控制凭证获取十分常见，Teamviewer使用了基于2048 RSA私钥/公钥交换算法的加密方式和AES (256位)会话加密，该传输技术标准与SSL标准相同，同时远控的密码使用TOTP基于时间的一次性密码算法生成，故我们无法从流量直接获取数据信息或采用直接的逆算法方式解密有关凭证。
在对已控主机的Teamviewer远控凭证分析时发现，利用Teamviewer的内存加载特性，可以有效的获取TOTP码，这一信息获取操作要求转储Teamviewer的进程块，并根据其密码在内存中的hex特征进行提取。
关于密码在内存块中的特征主要通过遍历定位魔术数据起始`[00 88]`与结束`[00 00 00 00 00 00]`或`[00 00 00 20 00 00]`来获取明文密码。
现存工具可以参考https://github.com/vah13/extractTVpasswords进行。

3.2 Navicat

Navicat是由PremiumSoft CyberTech Ltd.为MySQL，MariaDB，Oracle，SQLite，PostgreSQL和Microsoft SQL Server生产的一系列图形数据库管理和开发软件。
在对运维主机的控制下，数据库管理方面常常面临库连接凭证获取的困难，因为Navicate的保护机制，无法直接有效的获取直观可查的明文密码，具体的加密密码存储在windows注册表中。
Navicat使用blowfish算法对密码字符进行加密，加密的过程先使用SHA-1算法生成长160位的密钥，然后利用blowfish算法，因为该算法支持加密一次最长为8字节长度，故需要通过初始化初始向量（IV）然后对明文进行分块加密，加密后的密码块存储在windows的注册表当中，每个存储的加密密码是hex字符串连接。
对于待解密的连接密码根据navicate管理的不同数据库类型，存储在不同的注册表位置，具体位置参考下表：

3.3 Xshell
Xshell的密码加密通常采用RC4流密码进行，但在加密的密钥根据会话版本的不同，生成密钥的算法也不相同。
在对会话文件版本低于5.1的文件中，Xshell使用ASCII编码的“!X@s#h$e%l^l&”结合MD5算法进行RC4密钥生成。
在对于会话文件版本等于5.1或者5.2时使用sha-256进行系统用户的sid加密进行生成。
在版本大于5.2的文件中除了使用sid之外还加入了操作系统用户的名称进行，即“OS SYSTEM ACCOUNT”+“SID”进行。
密码字符在经过上述加密后以Base64字符串的形式存储到会话文件当中。
在对Xshell凭证进行解密时首先明确xshell的绘画凭证session存储在本地文件中，根据软件的版本不同，session文件存储位置如下：

对其进行逆算法解密的方法主要是从从session文件中获取加密的密文即password字段和版本信息version字段进行解密，具体的逆算法解密程序参考https://github.com/HyperSine/how-does-Xmanager-encrypt-password进行实现。

3.4Winscp

Winscp的会话凭证的本地存储主要采用密钥加密方式进行，密钥采用主机名和用户名相拼接的方式进行，故把握winscp的配置存储位置便可对本地凭证进行快速解密。
在Winscp的配置中可选文件存储方式为.ini与注册表形式进行，对注册表形式的存储，信息主要存储在HKEY_CURRENT_USER\\Software\\Martin Prikryl\\WinSCP 2\\Sessions位置下，快速解密工具可参考https://bitbucket.org/knarf/winscppwd/downloads/winscppwd.exe（usage：winscppasswd.exe <主机>  <用户名> <加密密码>）进行。
附部分解密源码（key为用户与主机名拼接）：

3.5 部分主流浏览器
在几个主流浏览器中，浏览器的相关凭证信息，例如：存储的账号密码、已存储的cookie信息等等，通常以sqlite数据库的文件形式在本地存储，在使用时进行载入调用，其中部分信息会存储以加密的BLOB 十六进制数据形式。
在进行凭证获取的过程中，若无加密的信息的文件可以直接通过文件定位来获取数据，部分主流浏览器的文件存储位置如下：
chrome:`C:Users\Administrator\AppData\Local\Google\Chrome\User Data\Default`
firefox:`C:Users\Administrator\AppData\Local\Mozilla\Firefox\Profiles`
IE:`C:Users\Administrator\AppData\Local\Microsoft\Credentials`
在上述目录下找到对应的凭证文件可以使用db browser直接进行信息获取，对存在加密的文件可参考上文的DPAPI的解密方式进行解密获取。

其他陌生应用凭证获取与分析思路

在对陌生的主机应用进行凭证获取利用时主要是参考本地静态文件解密与动态内存分析/流量分析的方式进行。
1.静态文件解密
通过对应用的程序的凭证调用分析可以解密本地的数据文件，在面临本地强加密或者算法因要素缺少而不可逆的情况下往往要考虑动态性的凭证捕获。静态文件的解密如大多数的浏览器数据文件存储调用、Shadowsocks/CCproxy/Nvicate配置解析等，应用程序往往调用或者临时生成缓存凭证文件进行。故此类应用的明文凭证获取思路主要是定位到应用调用的文件，结合应用程序的逆向/开放性源码分析进行解密文件。
2.动态内存分析/流量分析
 在面对部分本地验证不全、加密过程开放性不够明确、逆向困难度较大的应用程序进行凭证获取分析时，往往需要采用动态的方式，例如Bitlocker加载的密钥文件已在本地无法发现，但是其内存加载方式却可直接提取。部分本地远程双因子认证的软件尽管无法直接解密本地的文件，但可以捕获程序运行认证过程的网络交互流量进而进行直接的凭证获取。
0x04 域内信息搜集的技术
内网环境中的域渗透往往主要围绕着域内环境的主机定位和凭证伪造与收集传递进行，故在域内信息搜集方面有效的定位域控制器和获取域内票据的相关信息是信息搜集的一个重点。

4.2 Kerberos的票据信息搜集

Kerberos 是Windows活动目录中使用的客户/服务器认证协议，为通信双方提供双向身份认证。相互认证或请求服务的实体被称为委托人（principal）。参与的中央服务器被称为密钥分发中心（简称KDC）。KDC有两个服务组成：身份验证服务（Authentication Server，简称AS）和票据授予服务（Ticket Granting Server，简称TGS）。在Windows域环境下，身份验证服务和票据授予服务可同时运行在任何可写域控服务器上。
参考工具：https://github.com/nidem/kerberoast、https://github.com/cheetz/PowerTools/tree/master/PowerView。
在Kerberos身份验证流程中主要是将用户密码转换为ntlm哈希结合时间戳使用散列加密，作为身份验证票据（TGT）请求（AS-REQ）中的身份验证器并发送请求给域控制器，域控制器在检查用户信息后创建加密授权票据，因为对票据的伪造可以完成对域名特定服务的访问控制权限突破。
针对Kerberos的渗透工作除了常用的MS14-068之外，还可以通过spn扫描、票务身份伪造与窃取等方法进行。

通常的票据伪造主要是黄金票据伪造和白银票据伪造，金票据的伪造主要依靠伪造TGT来获取kerberos服务权限，而银票据的伪造通过伪造TGS来访问指定服务。

金银票据的伪造主要是结合域内操作系统的账户NTLM hash与kerberos服务认证进行搜集与利用，对账户分析主要是在线提取与lsass转储方式进行。
