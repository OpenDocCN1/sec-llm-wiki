# **2.漏洞分析**

*   genacgi\_main函数是漏洞开始的触发点，通过getenv函数获取“REQUEST\_URI”环境变量的内容，接着对其进行验证，最后进入sub\_40FCE0。
    

![](../Images/87f71ef0aecd40ebd490283b6330bc7f.png)

*   下图是sub\_40FCE0函数的内容，在上图中获得的值，最终通过xmldbc\_ephp函数发送出 去，数据由run.NOTIFY.php进行处理。
    

![](../Images/63402664d566292344ee84b3c5e8dd8c.png)

*   该php调用了GENA\_subscribe\_new函数，并且向里面传递了cgibin中获取到的数据，还 传递了SHELL\_FILE参数。
    

![](../Images/7be52287916f6ab7c98b1a1a7a0dfe30.png)

*   文件gena.php中是函数GENA\_subscribe\_new的实现代码。从代码中我们可以看到该函数并未对shell\_file数据进行操作。但是在最后调用了 GENA\_notify\_init函数传入了shell\_file。接下来在该文件下找到GENA\_notify\_init函。
    

![](../Images/ecc9c5a37b7a2f9523749d569cf39e54.png)

*   接下来在该文件下找到GENA\_notify\_init函数 第一次调用fwrite的时候创建了文件， 第二次调用fwrite的时候使用了"rm -f"命令。
    

![](../Images/3c8fb7b20db3cd9dfc535b7138158e4c.png)

到此为止我们的攻击思路大致已经出来了。我们只需要插入一个反引号包裹的系统命 令，然后注入到shell脚本中即可。
