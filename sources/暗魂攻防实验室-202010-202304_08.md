# 前言

本靶场是一台旨在演示**Linux**特权升级的**7**种最常见方式的机器

目标：通过7种不同的方式获取root权限

默认凭证：(muhammad:nasef)

  

# NO.1 权限配置错误

一些文件只能由root用户去读取，有时权限配置不正确，导致任何人都可以读取该文件。比如/etc/shadow，该文件存储了密码，正常只能由root用户读取写入。

使用本台机器检查/etc/shadow文件权限

```
ls \-al /etc/shadow
\-rw-rw-r-- 1 root shadow 760 2020\-12-03 01:57 /etc/shadow
```

![](../Images/c18751044edc8c43060af731f71fd700.png)

通过文件权限可知，文件所有者有读和写权限，群组也有读和写的权限，其他人有读权限。说明，该文件都可以进行读取，那么就导致所有人都可以读取密码，进行密码破解。

```
cat /etc/shadow
```

# NO.3 suid提权

suid是一种特殊权限，允许任何用户以文件所有者身份去执行文件。

寻找suid权限的可执行文件

```
find / \-perm \-4000 2\> /dev/null
```

![](../Images/a3b70d3fa9252ea958902174237f81e9.png)

发现/home/muhammad/vuln/1/suid文件存在suid权限

![](../Images/1c31c046240b61ef92d1ee4c883b83da.png)

同样跟上面的sudo一样，那么就直接执行。

![](../Images/05d040fdf77b653bac3f534ca9439f04.png)

id查看权限，但不是root，但是whoami是root，说明该shell具有root权限，因为/etc/passwd有读写权限，所以我们可以添加新的用户并且覆盖上去。

首先使用openssl先生成一个密码


# NO.4 计划任务提权

crontab是计划的命令和脚本，它们以特定用户的身份在一定时间间隔内自动运行。如果某个脚本以一定的时间间隔以root身份执行，则我们可以修改此脚本。

我们查看一下计划任务

```
cat /etc/crontab
```

![](../Images/02473509bd86863e2e1f0740d87b1181.png)

```
root /home/muhammad/vuln/4/script.sh
```

看下脚本内容

```
cp /home/muhammad/vuln/4/passwd /etc/passwd
```

![](../Images/10decb5083eb34c0734689460ebd6546.png)

意思是复制passwd文件定时覆盖掉/etc/passwd

那我们就可以修改passwd，跟上面的suid提权差不多了。这里就不详细写了，直接vim，把用户密码添加上去即可

![](../Images/7c02206da16d575c1c466b5670b6aa07.png)

# NO.6 内核漏洞提权

我们可以通过linux的内核漏洞进行提权，首先我们可以使用uname  -r查看内核版本

![](../Images/df4bc257199e0633c59eaeae63722ceb.png)

然后我们可以使用kali中的exploitdb搜索合适的漏洞利用脚本。

```
searchsploit linux 2.6.24
```

![](../Images/2344c11307904e1e72ae1d5366be2e42.png)

这里使用著名的脏牛提权（Dirty COW），脚本是linux/local/40839.c，

```
searchsploit linux/local/40839.c \-m
本条命令就是提取该脚本到当前根目录
```

![](../Images/22ed36b6f7a390580f95ccadd9bfc47b.png)

然后上传该脚本，通过脚本内容可知编译方法为：

```
gcc \-pthread 40839.c \-o anhunsec \-lcrypt
```

![](../Images/dcf2068fd028c30945116522d900d7c9.png)

然后./anhunsec运行，输入新密码

![](../Images/b5ad77191e028269e2b842cfdd032c37.png)

运行成功后切换用户firefart。密码是自己设置的密码

![](../Images/328c3af3839816b5693615f3ea06c662.png)

然后id可以看到是root权限了。

# NO.7 NFS特权提升

当服务器中存在NFS共享，且开启了no\_root\_squash选项时，这时如果客户端使用的是root用户，那么对于共享目录来说，该客户端就有root权限，可以使用它来提升权限。

```
cat /etc/exports
```

![](../Images/f3722f7646f8f6477e95446dacc1d5a5.png)

我们可以发现/home/muhammad是存在共享的，也启用了no\_root\_squash

那么我们就直接挂载目录

```
mount \-t nfs 192.168.1.8:/home/muhammad /mnt
```

![](../Images/04ff59535d55069512260a30b1eb1bb6.png)

对于共享目录来说，挂载的客户端也有root权限。

那么我们就是可以用上述的几种提权方式提权就行。比如计划任务提权中，在passwd添加新用户。

![](../Images/651a5b1ee5c22d73021b20406163daba.png)

并且script.sh加个权限，然后返回靶机去执行它

```
chmod +sx script.sh
```
