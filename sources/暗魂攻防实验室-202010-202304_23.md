# 0x01 信息收集

扫描端口：

```
nmap \-A \-T4 \-Pn \-sS  10.254.2.7
```

![](../Images/f654206d873bfc802ed084032aa1e958.png)

扫描端口后得知只有22端口和3000端口，访问3000端口是个web页面。

![](../Images/07572f17294e2c95e12e822e7b936de7.png)

并且有个登陆页面

![](../Images/c43df04cb8a9cc33e53723efdaf9c6e1.png)

  

# 0x02 web渗透

查看一下源代码，发现很多js代码

![](../Images/c1d725b498f27444571629a3f7038929.png)

在assets/js/app/controllers/home.js文件夹有个api接口

![](../Images/74a40c001bc3e5e031eaf43e5142ee9e.png)

然后直接访问api接口，意外发现有三个uername和md5加密后的password

![](../Images/b7cbcf35acc2dae23244bf5b03f506b5.png)

第一个拿去somd5网站解密后得到密码：spongebob

![](../Images/7a070ee8b9134a1d5150a77d8b5e0010.png)

直接登陆进去，提示只有admin用户可以访问控制面板

![](../Images/ec2cc0b6351de41fecc53a2699fa4f41.png)

回到原点，我们继续查看js的源代码，在assets/js/app/controllers/profile.js文件中发现有个/api/users的接口，我们访问他

![](../Images/63e057fe28b12c8d4878b62d4acb74ed.png)

发现多了一个用户，并且他的is\_admin是true类型，那就说明他是管理员用户

![](../Images/a134ece8501378b16c841cd79b2c408d.png)

同样拿去somd5解密，得到密码：manchester

![](../Images/a623e5e63887ac51c01b800498ea4c56.png)

登陆后发现有个下载按钮，并且是备份的文件

![](../Images/139ad493bf29dc8d00a509ee49f68f5e.png)

文件名为myplace.backup，不知道是啥后缀的文件，我就用记事本查看，发现好多字符串，以CTF思维来讲好像是个base64编码

![](../Images/990e67b62c20cfd3d0cca9e6918bd7be.png)

那么多放在在线解密网站直接崩了。经过网上查询，可以使用kali的base64命令解出来合成一个文件。然后file命令查看一下他输出的是什么文件格式。

```
base64 \-d myplace.backup > myplace
file myplace
```

![](../Images/f0c4573c0706e2ac827c1faecfc78fa3.png)

发现他是zip压缩包格式，我们查看一下有什么。打开后发现还需要密码

![](../Images/62726008dee266eaaeb33cbc95531e45.png)

直接爆破，本次使用kali的fcrackzip工具以及自带的字典爆破。

新版的kali没有自带了，需要安装

```
apt install fcrackzip
```

```
fcrackzip  \-u \-D \-p /usr/share/wordlists/rockyou.txt myplace.zip
```

![](../Images/ed6c22209867c188c478bf7d5b052033.png)

得到密码：magicword

打开后是源码的备份文件，然后在app.js发现有个连接数据库配置文件，找到连接用户名和密码

![](../Images/72dedf7f3d80e413e2b4f276a0c5f45b.png)

尝试22的SSH登陆，ssh mark@10.254.2.7

![](../Images/10c8e0195341795d71b2dbaee90e8899.png)

登陆成功！

  

# 0x03 权限提升

使用sudo -l查看特权文件，可惜没有。我们先使用uname -a查看内核版本

![](../Images/e447be20dfb337efa6bee3c28cd12115.png)

尝试搜下有没有内核提权漏洞

```
searchsploit linux 4.4.0
```

![](../Images/051c2da8cea9719ee7450159f14f1cbd.png)

把exp复制到桌面上

```
searchsploit \-m linux/local/44298.c
```

然后使用scp复制到目标主机上

```
scp 44298.c mark@10.254.2.7:/var/tmp/
```

![](../Images/9b7d9ba957da16cff5493e31965a5a04.png)

使用gcc进行编译exp

```
gcc 44298.c \-o shell
```

![](../Images/d49e9661faeda206d60a7e541da56028.png)

执行shell文件，成功提权至root

![](../Images/6444cca241877f36c10fd840134ee00e.png)

root用户根目录下有个flag：1722e99ca5f353b362556a62bd5e6be0

![](../Images/e4bca921e71a24b69c5909f5c16de71c.png)

第二个flag是tom用户的根目录下：e1156acc3574e04b06908ecf76be91b1

![](../Images/4a85bbc92ddd800fd0a6c1f772e6a631.png)
