如何用C编写和编译Shellcode

原文：http://mp.weixin.qq.com/s?__biz=MzU1Mzk4Mzc5MA==&mid=2247484602&idx=1&sn=5940c3852da99fd15d9f41f4fcb1ca82&chksm=fbebcefbcc9c47edc5dfccc3b8590c9b9a65212d1e849918aaec27749a918c11b285828b994e&scene=27#wechat_redirect


这是一篇速成教程，教你如何用C编写和编译Shellcode,首先打开一个简单的C语言程序（hasherezade之前写的文章中有提供过），该程序会弹出一个消息框，将其手动注入到notepad中的RWX内存中，并对其进行Shellcode和执行。




概述


下面是有关如何用C编写和编译shellcode的简单概述：


  1. 用C编写shellcode

  2. 把C语言代码编译成程序集指令

  3. 清理程序集指令，移除外部依赖项

  4. 把程序集链到二进制文件

  5. 从二进制文件中提取shellcode

  6. 利用代码注入技术，注入/执行shellcode



攻略


注意: 1.本实验用的是Visual Studio 2019。

      2.程序和shellcode用的是x64。




01

准备开发环境



首先，启动Developer Command Prompt for VS 2019，建立开发环境，该环境用于编译和链接本实验中使用的C语言代码：


上述控制台位于此处：


C:\Program Files (x86)\Microsoft Visual Studio\2019\Community\Common7\Tools\VsDevCmd.bat


开始操作：


cmd /k "C:\Program Files (x86)\Microsoft Visual Studio\2019\Community\Common7\Tools\VsDevCmd.bat"





02

生成程序集清单



下面是将要转换为shellcode的程序的两个C语言程序：


  • c-shellcode.cpp– 弹出消息框的程序

  • peb-lookup.h - c-shellcode.cpp需要的头文件，其包含用于解析LoadLibraryA和GetProcAddress地址的函数




现在，我们可以把c-shellcode.cpp里的C语言代码转换成程序集指令：


"C:\Program Files (x86)\Microsoft Visual Studio\2019\Community\VC\Tools\MSVC\14.26.28801\bin\Hostx64\x64\cl.exe" /c /FA /GS- c-shellcode.cpp


编译开关执行以下操作：


  •  /c – 禁止自动调用LINK

  • /FA – 给已有的C语言代码创建一个包含程序集代码的清单文件

  • /GS- - 关闭某些缓冲区超限的检测

03

整理程序集清单



既然C语言代码已经转换成c-shellcode.asm中的程序集，我们需要稍微清理一下文件，这样才能在不出错的情况下把它链到.exe，避免shellcode崩溃。我们需要做到以下三点：


  • 从外部库删除依赖项

  • 对齐堆栈

  • 解决一个简单的语法问题

3.2修复堆栈对齐


把AlignRSP添加到c-shellcode.asm第一个_TEXT段的顶部：


; https://github.com/mattifestation/PIC_Bindshell/blob/master/PIC_Bindshell/AdjustStack.asm
; AlignRSP is a simple call stub that ensures that the stack is 16-byte aligned prior; to calling the entry point of the payload. This is necessary because 64-bit functions; in Windows assume that they were called with 16-byte stack alignment. When amd64; shellcode is executed, you can't be assured that you stack is 16-byte aligned. For example,; if your shellcode lands with 8-byte stack alignment, any call to a Win32 function will likely; crash upon calling any ASM instruction that utilizes XMM registers (which require 16-byte); alignment.
AlignRSP PROC    push rsi ; Preserve RSI since we're stomping on it    mov rsi, rsp ; Save the value of RSP so it can be restored    and rsp, 0FFFFFFFFFFFFFFF0h ; Align RSP to 16 bytes    sub rsp, 020h ; Allocate homing space for ExecutePayload    call main ; Call the entry point of the payload    mov rsp, rsi ; Restore the original value of RSP    pop rsi ; Restore RSI    ret ; Return to callerAlignRSP ENDP
