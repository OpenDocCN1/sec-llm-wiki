**背景**

![](../Images/0706c9ee54cb2ac89da7fab18ad5b949.png)

  

最近，我们发布了一组有关Ivanti Unified Endpoint Manager的通报，其中几个漏洞可用于实现本地权限提升。

  

每当我们在 JUMPSEC发现新的漏洞时，我们会试着编写检测规则。从中我们学到了很多，调整漏洞利用程序和躲避检测是个有趣的过程，同时我们还能试着写出更好的检测规则。

  

自然，有了正确的识别特征，就可以检测到未来的漏洞利用程序。在历史数据上运行这一程序，可以得知是不是已经有人发现这一漏洞并加以利用。

  

我们十分享受这一过程，并深知这对客户而言很有价值，同时也希望能发现更多漏洞，这就是为什么我们努力分享一些有关Ivanti通报的细节。

  

  

  

![](../Images/3a8830dbd76b7f47b3a1d08f1365d446.png)

**介绍**

  

  

由于构成操作系统的组件数量众多，具有本地访问权限的攻击者能通过众多方式发起恶意攻击，即使他们只有低权限。也就是说需要付出更大的努力来监控可疑行为和检测攻击。

  

根据最近影响 Ivanti Unified Endpoint Manager的漏洞，我们希望简要说明如何检测本地特权升级攻击，特别是解决 CVE-2020-13770 和 CVE-2020-13771。

  

你可能已经听说过Sysmon，它是Windows Sysinternals工具套装中的一个便利工具，可以用于跟踪，记录和存储详细的系统事件。然后可以在 Windows 事件查看器中查看这些事件，其通常由 SIEM 软件收集，进行整合分析。

  

在撰写本文时，我们会专门说下Sysmon。

  

  

  

**技术细节**

  

  

在本节中，我们会简要说明漏洞和 Sysmon 配置规则的示例，用于记录漏洞利用，以及它们背后的基本原理，以便其他人能根据自身需要将它们调整到现有配置。这些将作为检测的第一点，而由此生成的事件是恶意攻击的一个可靠指标，它们可以进一步与其他事件关联，以进行更精确的监测。

  

  

  

**CVE-2020-13771 - DLL 搜索命令劫持**

  

  

要利用此漏洞，本地攻击者需要创建恶意 DLL 库，并把其放在文件系统上的特定路径中。此路径完全取决于主机配置；易受攻击的软件依赖 Windows 的DLL 搜索命令的桌面应用程序，来查找和加载 DLL 文件。（如下所述）

  

启用DLL安全搜索模式后：

  

1.从中加载应用程序的目录。

2.系统目录。通常是C:\\Windows\\System32\\或 C:\\Windows\\SysWow64\\，具体取决于操作系统和进程体系结构。

3.16 位系统目录。通常是 C:\\Windows\\System\\

4.Windows 目录。通常是 C：\\Windows

5.进程的当前目录。

6.PATH 环境变量中列出的目录。请注意，这不包括应用路径注册表项指定的每个应用程序路径。计算 DLL 搜索路径时，不会使用“应用路径”键。

  

禁用DLL安全搜索模式：

  

1.从中加载应用程序的目录。

2.系统目录。通常是C:\\Windows\\System32\\或 C:\\Windows\\SysWow64\\，具体取决于操作系统和进程体系结构。

3.16 位系统目录。通常是 C:\\Windows\\System\\

4.Windows 目录。通常是 C：\\Windows

5.进程的当前目录。

6.PATH 环境变量中列出的目录。请注意，这不包括应用路径注册表项指定的每个应用程序路径。计算 DLL 搜索路径时，不会使用“应用路径”键。

  

DLL安全搜索模式本质上是一个默认启用的设置，它将进程的当前目录按搜索顺序排列，以尝试缓解这种类型的漏洞。其值可以在以下注册表项中设置为 1（启用）或 0（禁用）：

  

HKEY\_LOCAL\_MACHINE\\System\\CurrentControlSet\\Control\\Session Manager\\SafeDllSearchMode

  

  

在这两种情况下，以防尚未找到库，操作系统会按其显示的顺序在 PATH 环境变量中的目录里查找 DLL 文件。这个变量需要特别注意，因为很容易出现每个人都可写的目录；此外，许多软件安装者会静默地追加目录到这个变量。

  

如果本地攻击者（或具有任意文件系统写入权限的远程攻击者）能把恶意dll放进其中一个路径，优先于找到合法dll的路径，或者无论优先级如何，如果找不到合法dll，则由易受攻击的进程加载该恶意dll，该进程将在其自己的上下文中执行其 DllMain 函数。

  

回到 Ivanti Unified Endpoint Manager例子中，进程中找不到通报中引用的 DLL 文件，就会给攻击者留下了一些放置恶意dll的可能路径。

  

为了记录漏洞利用程序的利用过程，我们可以指示 Sysmon 去记录 ImageLoad 事件; DLL 文件需要具备进程所查找的精确文件名，否则无法加载该DLL文件，因此文件名是设置筛选器的重要属性。由于合法库通常由软件供应商或发布者签名，因此我们可以根据此条件进行筛选，仅限记录未签名或不受信任的映像。以下规则将使用文件系统中任何位置的这些特定文件名，记录所有未签名/不受信任的dll在任何进程上的加载事件：

```

**CVE-2020-13770 - 命名管道token模拟**

  

  

此漏洞是特权升级技术的另一个典例；事实上，当运行"getsystem"时，meterpreter可以尝试这一方法。当进程打开命名管道对象，而没有显式指定正确的安全属性时，就会出现这一现象。在"dwFlagsandAttributes"参数上调用 CreateFile 时，可以指定这些安全属性；其中，从攻击者的角度来看，以下两个安全属性很有趣：

  

SECURITY\_DELEGATION - 在委托模拟级别模拟客户端。

SECURITY\_IMPERSONATION = 在模拟级别模拟客户端。如果未指定其他标志和SECURITY\_SQOS\_PRESENT，则这就是默认行为。

  

  

第一个属性允许在远程主机上进行模拟，而第二个属性只允许在本地进行模拟。其问题在于：在未指定其他属性时，或者未设置"SECURITY\_SQOS\_PRESENT"标志时，“SECURITY\_IMPERSONATION”是默认值，这容易导致不小心引入此漏洞。

  

在打开具有这两个安全属性之一的命名管道时，服务器有权获取客户端token并在后续访问检查期间使用它的访问权限；如果客户端具有高于服务器的权限，服务器就能有效获取权限提升。任何进程都可以打开一个新的命名管道对象，但同名的对象不存在，尽管模拟进程要求服务器进程保留 SeImpersonate 特权。默认情况下，这分配给服务用户，如"nt authority\\network service"。

  

权限升级过程的另一个要求是，客户端必须先将一些数据写入命名管道，然后才能进行模拟进程。因此，进程可以打开具有不安全的安全属性管道，但无法用来实现 EoP。

  

检测Unified Endpoint Manager上的漏洞利用程序，在标识了发生模拟行为的命名管道后，可以在其名称上筛选管道创建事件。除合法管道服务器外的任何进程都可以追加到用于筛选的规则中。由于管道只能用于 Ivanti 软件，因此这样的配置能有效地避免误报。其他事件可以选择与此处的目标事件关联，例如由创建命名管道的同一进程执行进程创建或文件操作。请注意，可能需要将排除规则编辑到读者的 SQL Server版本。

<Sysmon schemaversion="4.22">    <EventFiltering>        <RuleGroup name="CVE-2020-13770" groupRelation="and">            <PipeEvent onmatch="include">                <!-- Monitor CreatePipe events -->                <EventType condition="is">CreatePipe</EventType>                <!-- Only log these named pipes -->                <PipeName condition="is">\SQLLocal\ldmsdata</PipeName>            </PipeEvent>            <PipeEvent onmatch="exclude">                <!-- Only log if the pipe is not created by these (legitimate) processes -->                <Image condition="is">C:\Program Files\Microsoft SQL Server\MSSQL13.LDMSDATA\MSSQL\Binn\sqlservr.exe</Image>            </PipeEvent>        </RuleGroup>    </EventFiltering></Sysmon>
```
