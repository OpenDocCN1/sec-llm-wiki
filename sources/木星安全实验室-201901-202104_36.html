1. Kerberos协议基础


Kerberos是域内比较重要的协议，通过使用密钥加密为客户端/服务器应用程序提供强身份验证。Kerberos整个认证流程主要为了证明我是我自己。整个Kerberos认证流程大致分为六步，主要有Client Server KDC三个角色，KDC可以抽象为AS TGS两部分，其中AS负责颁发TGT，TGS负责发放访问票据ST。整个认证过程如下图所示：




2. 用户和计算机


在Active Directory中，用户类表示包含了众多属性的一个对象。


Active Directory域中，包含用户账户和计算机账户，计算机类继承于用户类，所以计算机账户也是一个域用户。



3. 服务


服务由Active Directory中的SPN（服务主体名称）标识，该SPN指示服务名称和类，所有者和主机。


服务通常在计算机中作为一种过程执行，通常服务在域用户的上下文中执行，执行权限为该用户的权限。服务主体名称（SPN）是服务实例的唯一标识符，域用户的SPN存储在其ServicePrincipalName属性中。一般来说，添加修改SPN需要具有SeEnabledelegation权限，通常域管理员具有这个权限。



4. 委派


委派允许服务使用客户端本身的特权和权限来模拟客户端用户与第二个服务进行交互，通过委派，应用程序能够访问托管在其他服务器上的资源。


如下图所示，简单来说，服务A代表用户User访问服务B，就是一种典型的委派。




5. 非约束委派


 非约束委派是最"原始"的委派，配置了无约束委派时，对象的userAccountControl属性将更新为包括TRUSTED_FOR_DELEGATION标志,这将允许服务不受限制地模拟用户。当对象通过配置了无限制委托的主机进行身份验证时，该帐户的票据授予票据（TGT）将存储在内存中。这样一来，配置了无限制委派的主机可以在TGT有效期内根据需要模拟为该用户。


一个完整的非约束委派请求过程如下图所示：



查询非约束委派的方法有很多，本质都是ldap查询。


在以下查询开启了非约束委派的主机和用户中，关键匹配规则为

<attribute name>:<matching rule OID>:=<value>


(&(samAccountType=805306369)(userAccountControl:1.2.840.113556.1.4.803:=524288)) //查询开启了非约束委派的主机


(&(samAccountType=805306368)(userAccountControl:1.2.840.113556.1.4.803:=524288)) //查询开启了非约束委派的用户


 

在以上查询非约束委派的示例中，samAccountType属性的805306368标志代表用户对象，805306369标志代表主机对象。1.2.840.113556.1.4.803是匹配规则，代表仅当属性中的所有位均与值匹配时，才找到匹配项。UserAccountControl定义了用户帐户属性，非约束委派(TRUSTED_FOR_DELEGATION)对应的值十六进制为0x80000，十进制为524288，设置了此标志意味着为Kerberos委派信任运行服务的服务帐户，任何此类服务都可以冒充请求该服务的客户端。


LDAP具体语法参考：https://docs.microsoft.com/en-us/windows/win32/adsi/search-filter-syntax


UserAccountControl属性参考：https://docs.microsoft.com/en-us/troubleshoot/windows-server/identity/useraccountcontrol-manipulate-account-properties


我们可以使用C#来编写小工具，实现查询启用了非约束委派的主机和用户，完整代码如下：


using System;using System.DirectoryServices;
namespace DelegationUsersExamples{
    public class Program    {        static void Main(string[] args)        {            GetDelegationUsers();        }
        static void GetDelegationUsers()        {            DirectorySearcher ldaps = null;            SearchResultCollection results;            DirectoryEntry de= new            DirectoryEntry(GetCurrentDomainPath());            ldaps = new DirectorySearcher(de);
            ldaps.Filter = "(&(samAccountType=805306369)(userAccountControl:1.2.840.113556.1.4.803:=524288))";            results = ldaps.FindAll();            foreach (SearchResult sr in results)            {
                Console.WriteLine("开启了非约束委派的主机："+sr.Properties["name"][0].ToString());            }
            ldaps.Filter = "(&(samAccountType=805306368)(userAccountControl:1.2.840.113556.1.4.803:=524288))";            results = ldaps.FindAll();            foreach (SearchResult sr in results)            {                Console.WriteLine("开启了非约束委派的用户：" + sr.Properties["name"][0].ToString());            }
        }        static string GetCurrentDomainPath()        {            DirectoryEntry de = new DirectoryEntry("LDAP://RootDSE");            return ("LDAP://" + de.Properties["defaultNamingContext"][0].ToString());        }    }
}

6. Printer bug


首先，Printer bug更像是微软的一个设计缺陷，并非漏洞。当有一个帐户配置了无约束委派，并且在计算机上运行了Print Spooler服务(域控默认启用)，这样一来，我们就能够以用户的身份获取到发送给具有无约束委派授权的系统的身份验证信息，获取到TGT。


通过Printer bug，可以强制触发域控访问受陷主机，主动获取到域控主机账户的TGT，然后使用非约束委派模拟用户，拿下域控制器。注意，这里我们需要的是一个配置了非约束委派的主机账户，因为SMB服务默认以System权限运行。


触发Printer bug，可以使用Spoolsample。该工具利用Windows打印系统远程协议(MS-RPRN),通过RpcRemoteFindFirstPrinterChangeNotification即可触发响应。函数结构如下：


DWORD RpcRemoteFindFirstPrinterChangeNotification(

   [in] PRINTER_HANDLE hPrinter,

   [in] DWORD fdwFlags,

   [in] DWORD fdwOptions,

   [in, string, unique] wchar_t* pszLocalMachine,

   [in] DWORD dwPrinterLocal,

   [in, range(0,512)] DWORD cbBuffer,

   [in, out, unique, size_is(cbBuffer), disable_consistency_check] 

     BYTE* pBuffer

 );



详细代码可以参考Spoolsample的C++实现，该项目也有C#版本，但是C#版本其实是一个PE加载器，直接加载了C++版本的dll。


具体复现结果如下图所示：

 首先查询到配置了非约束委派的主机MAIN，EXCHANGE。MAIN是域控制器的主机账户，默认开启非约束委派。EXCHANGE是开启了非约束委派的已被攻陷的普通主机。(注：这里并不需要EXCHANGE这样的高权限主机，普通的配置了非约束委派的主机就行)


我们使用Spoolsample触发域控主动访问EXCHANGE，

然后使用PTT注入到内存，即可Dcsync导出整个域的hash





7. 防御建议



1）禁用没有必要的Print Spooler服务


2）取消没有必要的非约束委派功能


3）使用Suricata等网络威胁检测引擎，添加相应规则进行阻止。上文中的Printer bug阻止规则可参考：https://github.com/ptresearch/AttackDetection/blob/master/ThePrinterBug/theprinterbug.rules
