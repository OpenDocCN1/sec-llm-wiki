# 资讯 | 谷歌分析和数据传输：如何使你的分析工具符合GDPR？

2022年2月10日，法国国家信息自由委员会（CNIL）与其欧洲其他执行机构合作，向使用Google Analytics（谷歌分析）非法向美国转移数据的几个组织发布禁止令，正确使用配置可以成为限制个人风险的解决方案。

  

欧盟法院（CJEU）在2020年7月16日的裁决中宣布“隐私护盾”无效，该机制为欧盟和美国之间的个人数据转移提供了框架。而美国立法没有提供足够的保障以应对情报部门获取欧洲居民个人数据的风险。

  

裁决之后，CNIL收到了来自NOYB协会的几项投诉，质疑法国公司使用在美国发布的分析工具Google Analytics。CNIL对这些投诉做出了裁定，认为这些投诉是有效的，并命令有关公司遵守。

  

在这些决定中，CNIL认为，由于使用Google Analytics导致对美国的转移监管不到位。正如CNIL问答中所回顾的，简单执行标准合同条款不足以使Google Analytics符合GDPR的规定。

  

**一、仅简单更改工具的设置是不够的**

  

在这些正式通知之后，许多用户试图确定技术设置和措施，以便在尊重互联网用户隐私的同时保持Google Analytics的使用。

  

但是，仅仅更改IP地址的处理设置并不足以满足欧盟法院的要求，尤其是在这些地址持续转移到美国的情况下。另一个想法是对Google Analytics生成的标识符的“加密”，或者将其替换为网站运营商生成的标识符。然而，由于Google对IP地址的持久处理，几乎没有提供额外的保证来防止数据主体被重新识别。

  

**阻止这些措施解决非欧洲当局访问数据问题的根本问题是个人终端与Google管理的服务器之间通过HTTPS直接联系。**

  

由此产生的请求允许这些服务器获取互联网用户的IP地址以及有关其终端的大量信息。 这些信息实际上可以让用户被重新识别，从而使用Google Analytics访问他或她在所有网站上的浏览。

  

**只有允许中断终端和服务器之间这种联系的解决方案才能解决此问题。**除了Google Analytics之外，这种类型的解决方案还可以使其他分析工具的使用与GDPR数据传输规则相协调。

  

**二、代理可能是一个解决方案**

  

鉴于上述标准，**一种可能的解决方案是使用代理服务器，以避免互联网用户的终端与分析工具（在本例中为Google）的服务器之间的任何直接联系。**但是，必须确保该服务器满足一组标准，以便能够认为此附加措施符合EDPB在2021年6月18日提出的建议。事实上，这样的过程将对应数据导出前假名化的用例。

  

如这些建议所述，**只有当控制者通过彻底分析确定，即时与其他信息交叉核对，假名个人数据也不能归因于已识别或可识别的个人时，才有可能进行此类导出。**

  

因此，除了不能简单地从用户终端向分析工具的服务器发出请求之外，有必要确保传输的所有信息都不会以任何方式允许重新识别该人，即使考虑到当局可能利用大量手段进行这种重新识别。

  

**（一）实现有效代理应采取的必要措施**

  

CNIL认为执行代理的服务器必须应用一套措施来限制传输的数据。原则上是必要的：

  

**• 不向分析工具的服务器传输IP地址。**如果向测量工具的服务器传输位置，则必须由代理服务器执行，并且精度级别必须确保此信息不会重新识别该主体（例如，通过使用地理网确保每个小区的最低互联网用户数量）；

  

**• 由代理服务器取代用户标识符。**为了确保有效的假名化，执行替换的算法应确保足够的冲突级别（即两个不同的标识符在哈希后给出相同结果的概率），并包括一个时变组件（向哈希数据添加一个值，随着时间的推移而演变，对于相同的标识符，哈希结果并不总是相同的）；

  

**• 删除网站上的外部推荐人信息；**

  

**• 删除收集的URL中包含的任何参数**（例如UTMs，但也包括网站内部路由的URL参数）；

  

**• 重新处理可用于生成指纹的信息**，例如用户代理，以删除可能导致重新识别的最稀有配置；

  

**• 没有收集跨网站或持久的标识符**（CRM ID，唯一ID）；

  

**• 删除可能导致重新识别的任何其他数据。**

  

**（二）有足够的代理托管条件**

  

代理服务器的托管条件也必须确保其处理的数据不会被转移到欧盟以外的国家，这些国家提供的保护水平与欧洲经济区内提供的保护水平基本相当。

  

在任何情况下，根据EDPB的建议，将由数据控制者对这一点进行分析，并在他们希望使用这种类型的解决方案时采取必要的措施，以及根据产品的发展情况，核实这些措施的维护情况。
