[核心提示] 三年后，仍在持续「用力」的 YunOS，到底图什么？

2014年，阿里的 YunOS 动作频频。

先是发布了主打生活服务与安全防护功能的 YunOS 3.0，随后联合魅族推出以 YunOS 作为底层的银翼版 MX4，更传出将与中移动合作推出基于 YunOS 的终端产品。

但短短两三年，小米、魅族、一加依靠高质平价的异军突起，而联想、华为更是积极向互联网转型。

依靠杂牌军抢地盘的阿里云手机却一直乏善可陈，陷入一个无法自拔的怪圈：

产品无法获得消费者青睐，销量无法达到预期，合作伙伴频繁更迭，战略一年一个样。

此次 YunOS 3.0 卷土重来，有什么底气可以改变曲高和寡的尴尬局面？在整个阿里战阵中又占据了怎样的位置？

跟厂商做朋友，不再强求当家做主

YunOS 在过去三年与杂牌厂商合作的统一模式：你做硬件，我做系统。

并非阿里巴巴不愿意和高大上的一线手机厂商合作，2012 年阿里云曾经计划与宏碁合作发布预装 YunOS 的智能手机，但很快被 Google 叫停。

原因在于宏碁参与了由 Google 主导的开放手机联盟（Open Handset Alliance），这个联盟成员不仅包括 ARM、MIPS、联发科、英伟达、英特尔、高通、德州仪器这样的芯片厂商，还囊括了三星、索尼、摩托罗拉等几乎所有国际一线手机厂商。

联盟成员的义务中有最重要的一条：不能分裂 Android 生态。

而 YunOS 搭载了名为 lemur 的异化虚拟机，跟 MIUI、Flyme OS 这样的壳系统有本质差异，基本不可能找到靠谱的一线合作伙伴。

而对于真正有追求的厂商而言，同样乐于去构建包括应用商店、云服务、账号系统等自有生态系统，已获得在商业竞争中的优势。在这一点上，他们与喜好包买包办的 YunOS 殊途难归。

在 YunOS 与魅族的合作中，我们看到了更具弹性的合作模式：

只要底层是我的，其它都可以谈。

银翼版 MX4 搭载的 Flyme OS 基于 YunOS 的底层，只是加入了 YunOS 3.0 的生活服务与安全防护功能，除此之外和标准版的 Flyme OS 没有任何区别。

底层交给我，你做手机和交互，我淘宝天猫帮你推帮你卖，卖了钱都是你的，我还能花钱帮你扩大产能，还跟你分享增值服务收入。

利好消息是，正占据市场的新兴中国手机厂商，几乎都身处「开放手机联盟」之外。

更具弹性的置入方式，辅以阿里在电商流量上的倾斜与资本投入，YunOS 对手机厂商是可以尝试的甜心。

从手机上，保卫阿里的安全

YunOS 是一个不标准的安卓系统，并且这种「不标准」由阿里巴巴独家制定，能开发出只支持 YunOS 的应用及专属安全机制。

阿里巴巴是一家业务横跨电子商务、金融支付、消费生活、娱乐互动的「大型」互联网公司，体量与规模决定了它在保护自身业务安全性上的急迫感，从系统底层介入显然是一个好选择。

根据李楠在发布会上所述，市面上所有的 root 破解软件对 YunOS 均无效。

而 YunOS 系统自带的安全体系：

  • 包括对「App 行为判断」的主动行为防御，

  • 系统安全键盘保护淘宝、支付宝等付款动作

  • 防截屏、支付短信保护、防钓鱼网址库

  • 数据加密，以及远程数据擦除。

此外XX安全卫士/助手/管家的内存优化、垃圾清理、骚扰拦截、病毒查杀、权限管理、流量统计等功能，YunOS 全部进行了内置。

从此，不再有被别人卸载和弹窗的风险，不再有关键数据被别人窥探的风险，对于不听话的竞争对手也能可管可控。

YunOS 在手，安全我有。

此外，工信部和科技部的副部长联袂出席 YunOS 发布会，直接印证 YunOS 的努力获得了政府方面的肯定，通过自主知识产权、安全、可管可控的概念，已经获得工信部五星安全认证，并进入中央政府采购名单。

在国家信息安全的大背景下，YunOS 仍然有着可观的契机。

终于有了数据

一直崇尚「大数据」概念的阿里巴巴，但却一直没有能够在系统底层抓取用户行为数据的渠道。

YunOS 正被寄予厚望，期望能够从手机上获得全局的消费与行为数据，包括游戏、消费、娱乐、购物等各种你能够想到的数据，甚至包括开关机时间，在什么时候最喜欢用什么应用。

这也正是 YunOS 一直在寻求除手机之外的合作伙伴，他们与海尔、飞利浦、天敏合作智能电视产品，与明基、酷乐视、山水合作推出智能投影产品，与安防视频监控厂商大华股份推出家居与智慧城市产品。

这些数据结合阿里巴巴自身在消费、支付、金融数据的累计，将会为阿里旗下业务带来协同效应，也能给关键业务决策提供支撑。

目前业内既有底层数据又有上层服务的，只有小米独一家，从硬件、系统、服务一直到电商、智能家居，其中的数据蕴含巨大价值。

阿里巴巴在试图以 YunOS 破局，去打造一个垂直控制的数据生态。

系统层面的 Web App

Cloud Card - 是 YunOS 3.0 主打的一大功能特性，基于云端 App 实现关联服务的联动。

更值得注意的是，Cloud Card 全程都抛弃了安卓系统常用的 Native App 结构，无需安装即可使用，可以看作是 Web App 的 演变。

早年 Web App 在流畅度、稳定性上都有大幅的不足，但诸多缺憾随着硬件性能的提升，第三方开放组件的丰富、HTML 5 标准确立获得改善。

对于消费者而言 App 不重要，他们需要的是服务，所以越便捷越好。对于服务商而言，开发成本低，多平台匹配便捷是难以抵御的诱惑力。

Cloud Card 可以看做是阿里巴巴试图在已经定型的应用市场区块，使用产品形态的 Web App 进行突围，避开与小米、百度 91、豌豆荚的竞争。

而如支付宝此前开放的服务窗、二维码、Wi-Fi、卡券、账户体系、支付、JSAPI 等体系，更可以看作是给 Cloud Card 共享的服务商库。

Cloud Card 是阿里巴巴在 Web App 上的有益尝试，去除 App 这一层的限制，从系统层面满足用户对服务的需求。

结语

三年时间，从当初的「阿里云 OS」变成如今的 YunOS，它仍然充当着阿里巴巴试图深入移动互联网底层的先头组织，并且策略变得愈发灵活与多变。

公司发展阶段的不同，决定了阿里巴巴无法像小米一样从头打造一个垂直管控的移动生态，某种程度上，基于资源、平台的开放策略是被迫的选择。

手机硬件行业的快速变化，特别是「新国产手机厂商」的兴起，给 YunOS 的硬件渗透带来了可能性。

同时，我们也需要看到阿里这家全球第二大市值的互联网公司，试图在 Google Android 之外重新建立生态的高风险。

很多时候，你与行业走在完全相反方向，并且数年固执坚持，很可能受到最终挫败。

坚持撞石头，头破血流难免。但，带来一些变化总是好的。
