# 我们提问了 50 位 CTO，他们都觉得大家对这个职业有误解

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MTMwNDMwODQ0MQ==&mid=2652843320&idx=3&sn=d8385099519b9be89abb1bdf01ab2ab5&chksm=7e6a508e491dd9987b7e9947b60f327ca91bdafaabdc5c5e110d3db0d7eaf51abccf634c27aa&scene=126&sessionid=1681311439#rd](http://mp.weixin.qq.com/s?__biz=MTMwNDMwODQ0MQ==&mid=2652843320&idx=3&sn=d8385099519b9be89abb1bdf01ab2ab5&chksm=7e6a508e491dd9987b7e9947b60f327ca91bdafaabdc5c5e110d3db0d7eaf51abccf634c27aa&scene=126&sessionid=1681311439#rd)

上周我们做了一个小小的问卷调查，想帮助大家更加深入地理解 CTO 这个职业。  

我们发现，大家常常会仅仅因为职业名称而给不同的职业下定义： CTO （首席技术官）就是技术最厉害的，CMO （首席营销官）就是最会包装产品的，运营人员就是维护社交渠道发微信的……

不了解常常会在沟通中产生一些误会，甚至偏见。比如，把工作中的一部分——写代码、Code Review （代码审查）等作为判断 CTO 的标准。

我们觉得，这事儿， CTO 他们自己更有发言权。于是，我们设计了一个问卷调查，截至调查结束，共有 50 位 CTO 参与其中。

鉴于早期定向传播的原因，这 50 位 CTO 基本上来自创业公司。

在这之中有 33.3% 的人认为 CTO 需要每天写代码，大部分人认为这需要视情况而定。比如在创业早期需要，越往后则越少；只有 11.1% 的人给出的结论是没必要。

![](../Images/8de0767dee08c9687706ea5b50a814e9.png)

38.9% 的 CTO 认为  Code Review 是日常工作之一，27.8%  的人认为不是，还有一部分人需要看情况。比如，在没有 VP of Engineering 的时候需要更深入负责项目技术支持，CTO 需要参与到日常前线工作。

![](../Images/3ab8ec333dc6aabd50b771f769e8c0b0.png)

每天和 CTO 沟通最多的人包括 CEO 等其他高管、技术人员。产品经理和运营人员也是他们的沟通对象，但是占比不高。

![](../Images/8eb74bf4944438ae4ab16a1f58012e24.png)

大部分的 CTO 认为他们不是整个公司技术最强的人。

![](../Images/c0b3ce97fa02d0249be32bcc271bdfc3.png)

虽然 CTO 所撰写的博客和公众号很受欢迎，但是在调查中，有将近 70%的 CTO 没有个人公众号。

![](../Images/b2e1935b6c1eb8ef6df7778136bc4702.png)

他们吸引技术人才加入团队的方式也并不完全依靠自己在社交网络平台上的个人影响力。公司人事渠道还是一个重要的招聘手段。

![](../Images/130c3c31ede4ea82f1a1929daad34f94.png)

98% 的 CTO 认为，大家对他们的最大误解就在于，认为 CTO 是整个公司技术最强的，什么都会。  

![](../Images/d4b5a51985efa90651f3a2f267346173.png)

一位 CTO 的回答是：CTO 还扮演着运营管理和推动者的角色，不能简单地定义为技术大拿。

剩下的 2% 认为，外界不了解也包括分不清 CTO 和 VP of Engineering 的职位区别；认为 CTO 可以什么都不用做。

在调查中，我们很好奇 CTO 本身是如何定位自己的，我们给出的多选备选选项有：管理者、协调者、战略师和宣传者。其中，协调者是大家比较有共识的定位。其次是管理者、战略师和宣传者。

![](../Images/1fdd92263c506a9909da666ab442570f.png)

一个 CTO 一天的工作中，所处理的工作有：与技术团队、产品、管理团队沟通并参与讨论、帮助各项目组协调技术需求、任务分解、写代码、参加 Code Review、技术选型、架构设计、风险管理、招聘、团队规划、管理以及培训、个人学习。  

有的 CTO 还要负责打杂、修电脑等事宜。心疼三秒钟。

![](../Images/4250b7d0ec21b9406088154f8e78aad8.png)

尽管要处理的工作很多，但是每个 CTO 对于自己的主要工作职责认识很明确。这些职责抽象点说就是在合适的时间做合适的事情。

具体点而言，出现频次最高的词语分别是：团队、方向、制度。

比如：

> **· **定义工程文化，确保技术层面没有拉下项目进度，招聘和制定公司技术方向。
> 
> **· **提高技术团队的效率、水平，营造技术氛围，让技术人员在各方面都能得到成长。
> 
> **· **决定技术方向与架构，保证船不沉，带领团队进步。
> 
> **· **等等。

尽管要处理的工作会因为公司的发展阶段有所不同，但是把握技术的战略方向、营造好的团队文化却是参与调查的 CTO 一致认可的职责。

最后，感谢参与调查的 CTO 大大们，他们来自：100 offer、秦苍科技、侯斯特网络科技、极客公园、青橙科技、 Strikingly 、喜马拉雅网络科技、又拍云等创业公司。（名称按照首字母先后排序）
