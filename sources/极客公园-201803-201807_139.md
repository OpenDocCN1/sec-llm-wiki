# 微软为何 75 亿美元收购 GitHub ？除了纳德拉的执念，还有什么幕后？

> **Microsoft + GitHub = Empowering Developers？**

  

GitHub 把自己卖给微软了，售价高达 75 亿美元，这是自微软内部框架调整后发生的最大收购交易。作为全世界最负盛名的程序员社区之一，GitHub 在 2015 年最后一次融资时的估值是 20 亿美元。不到三年，身价翻了三倍有余。  

收购发生的前夜，数以万记的程序员们仍然在这里创造、搬运、讨论「代码」；当收购的消息传来，几乎所有业内人士都异口同声的表达：意料之外，情理之中；当极客公园和这些人聊起这则消息，我们发现关于收购的认知焦点存在于有三个关键问题之中。

  

## **为什么「卖身」**？

GitHub 成立于 2008 年，由四个程序员创立，是一个面向开源及私有软件项目的托管平台，也是目前世界上最大的开源社区之一。 除了 git 代码仓库托管及基本的 Web 管理界面以外，GitHub 还提供订阅、讨论组、文本渲染、在线文件编辑器、协作图谱（报表）、代码片段分享（Gist）等功能。

![](../Images/3c20daefe6c59b7261224299fcf869dd.png)

与被戏称为「全球最大同性交友社区」相比，GitHub 其实更像程序员界的「Facebook」。程序员在上面会大量公开开源代码，互相寻求帮助。发展到现在，GitHub 的作用已经不仅是一个程序员交流地，更成为一个猎头挖人平台，普通程序员甚至可以将自己在 GitHub 上的经验写进简历。  

过去十年，GitHub 的发展几乎没有遇到什么阻碍。它拥有一切成功创业故事所具备的特质：创始人在解决自己工作困难时「无意」创造的产品，准确刺中了市场的痛点。凭借着独特的产品调性和一点点运气，GitHub 在十年间打败了几乎所有挑战者，其中甚至包括微软和谷歌的同类开源平台。

从 2011 年开始，主要依靠代码托管的 GitHub 就宣布公司已经开始盈利。到被微软收购前，GitHub 已有超过 2800 万多名使用者，超过 8500 万的代码储存。但顺风顺水背后，GitHub 其实一直存在着一个底层隐患——程序员出身的创始团队在公司管理方面既无经验，也无兴趣。

![](../Images/9e4be86337b8e43a2bab65a2038bab51.png)GitHub 创始人兼 CEO Chris Wanstrath

创办公司和管理公司不同。在成立四年后的 2012 年，日益壮大的 GitHub 才选择接受外部的投资，其中 A 轮融资就拿到了 1 亿美元。然而，拿了投资人的钱就要受投资者「监督」。GitHub 近两年一直受到投资者的诟病，后者指责 GitHub 管理层在招聘员工，建造办公空间时花钱太过大手大脚。2015 年，当时员工不足 600 人的 GitHub 在工资和福利方面的开销达到了 7100 万美元。而从 2016 年 1 月到 10 月，这一数值更是进一步攀升到 1.08 亿美元。  

另外，包括现任 CEO Chris Wanstrath 在内的四位 GitHub 的创始人对管理公司兴趣不大。去年 8 月份，GitHub 的联合创始人兼 CEO Chris Wanstrath 就表示将辞去 GitHub CEO 一职。与做 CEO 相比，他更想做一个改善产品的人，而非公司的管理者。

越来越多外部竞争者的出现使 GitHub 面对的局势变得更糟，其中又以谷歌参与投资的 Gitlab 对 GitHub 造成的威胁最严重。Gitlab 拥有与 Github 类似的功能，能够浏览源代码，管理缺陷和注释，但它比 GitHub 更便宜且专门为大型企业服务。在 2017 年前，Gitlab 已有超过 11 万个客户。这种专为大型企业商业服务的模式正在对 GitHub 的「自由」社区形成冲击。

对于 GitHub 而言，在经历长达接近一年的内部近乎无序发展后，是时候做出一个选择了。外敌当前，是继续无序发展还是出售自己，现任管理层给出的答案是出售，买家选择的是微软。

  

## **为什么是微软？**

微软将接手 GitHub 其实算不上「新」闻，因为在过去几年，类似的消息总是反反复复地出现在各路知情人士的口中。

在漫长的「传闻」里，微软一直都是除了 GitHub 创始团队之外最好的选择之一——没有人比对手更了解自己，即使这个对手曾是手下败将。微软对于 GitHub 的钟情，要和微软现任 CEO 纳德拉联系起来。

![](../Images/5278cbe115a1ff0d7f872e05c8c4942b.png)

在鲍尔默时代，微软对开源软件的态度是排斥的。鲍尔默曾有一句被广为诟病的名言——「开源软件是知识产权的癌症」。可事实上，微软早在 GitHub 诞生的两年前就推出了开源平台 CodePlex  ，但这种以「微软」公司为中心的开源平台，很快就被对开源充满热情，保持平台中立的 GitHub 所冲垮。不过，双方存在的竞争关系，使得微软和 GitHub 的关系算不上如何友好。  

当微软进入纳德拉时代，这种紧张的关系立刻得到了缓和。纳德拉看到了开源背后的广阔市场——用哪家的底层代码就意味着更可能接入哪家服务。从 2014 年开始，微软在 GitHub 大量公布开源代码，其中包括微软.NET 等核心代码；2015 年，微软贡献了 16419 个开源项目，成为 GitHub 上公开代码最多的组织；在今年的 Build 大会上，微软还宣布旗下云业务 Azure 和 GitHub 将开展更密切的合作。

![](../Images/933b3c1a53fb31f212764212d1060a10.png)

收购 GitHub 是微软在 2018 年三月底架构调整后进行的最大收购。收购后的 GitHub 将归属于微软现在两大部门中的「云计算与人工智能平台」。显然，微软希望 GitHub 能帮助其拓展云服务市场。在接受极客公园的采访时，冯大辉也表示「（微软）收购 GitHub 用意在扩大云计算市场份额上，微软云计算市场占比会进一步扩大。长期看，GitHub 的重要性甚至比 LinkedIn 还要大。」  

GitHub 上的代码主要是被程序员使用，但几乎所有程序员都有工作，背后都站着一家家公司。这些程序员在使用哪家的算法框架时，很大程度上就决定了它更适合接入哪家的云服务等后续服务。

对微软来说，GitHub 一定程度上将帮助微软缩小同 Google 在云业务之间的差距。2018 年微软第二季度财报中，Azure 在国际市场已经排名第二，为财报带来的收益增加 98%。但分析师数据显示，微软云业务占市场份额只有 20％，而排名第一的 Google 则高达 62%。

  

## **这****会破坏 GitHub 的独立性吗？**

在 GitHub 将被微软收购消息放出后，GitHub 的主要对手 Gitlab 的用户迅速出现增长。很多程序员在很多社交平台上表达出对微软未来操控 GitHub、盗取用户代码数据，GitHub 将无法像现在一样独立自主发展的担心。

但就极客公园目前从业界了解到的信息来看，这种可能性不大。

![](../Images/74850739c1b937fcd21afd555147783d.png)

一方面，微软在收购公告中指出，未来将让 GitHub 保持独立运营发展；另一方面，从微软的整体规划上来说，为了更好的推动核心业务「云业务」方面，加上之前的 CodePlex 失败案例在前，微软也不会做出这类竭泽而渔的举动。  

链家技术副总裁惠新宸在接受极客公园采访时也表达了相似的看法。他认为，GitHub 的存在更可能和微软的云服务和代码核心提示等服务相结合。微软对开源的态度是非常开放的。「目前链家 PHP 核心开发组中就有一个 Windows 开发组，虽然开发组成员是微软的雇员，但一直非常配合 Windows 下的版本开发升级。」

GitHub 中国区排名第一的用户「代码家」则表示，开源本身是相对去中心的，微软尝试只会只会毁了这个社区。「微软不至于这么傻」，微软更可能借助 GitHub 的数据库来分析 code 或者招募人才。
