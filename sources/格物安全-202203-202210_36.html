类加载漫谈

        Java 的实现依赖于 JVM（Java 虚拟机），Java 代码先通过编译器编译成 .class 类字节文件，再通过ClassLoader读取加载到内存中，而ClassLoader是调用 JVM 中的native方法来创建实例。

        这样说可能十分抽象并且难以理解，我们先搞清楚native，也就是本地方法是什么东西。Java 在底层定义了许多native方法的接口，这些接口都是通过其他编程语言，如C / C++这种适合与底层打交道的语言实现的（为了高性能以及更好地与硬件进行交互）。但并不是说随便一段代码都能实现native方法，无论是什么语言，要实现native方法，都需要遵循一套标准，这套标准就是JNI，即Java Native Interface。

        但是，在这里我们应该有一个疑问，Java 所引以为傲的特性——可移植性，不就是它的运行与硬件、操作系统无关才得以实现的吗？现在你跟我说它底层用了C / C++，那它的可移植性又从何说起呢？别急，JNI标准正是为了解决这一问题而出现的，它能保证任何代码都能工作在 JVM 环境中，以确保代码的可移植性。




Java的反射机制

        反射是 Java 被视为动态语言的关键，它指的是对于任何一个Class类，在运行的时候都可以直接得到这个类的全部成分（获取类的字节码文件对象），包括构造器、成员变量、成员方法，也就是动态调用类中成分的能力。

        通过反射获取类对象的方式有三种，这些方式也叫动态加载，我们会在文章后面介绍：

  • 类名.class

  • 对象.getClass()

  • Class.forname("全类名")

package top.tuzk1.sec;
public class Demo1 {    public static void main(String[] args) throws ClassNotFoundException {        Class cls1 = Test.class;        Class cls2 = Class.forName("top.tuzk1.sec.Test");        Test test = new Test();        Class cls3 = test.getClass();        System.out.println(cls1);        System.out.println(cls2);        System.out.println(cls3);        System.out.println(cls1 == cls2);        System.out.println(cls1 == cls3);    }}

类加载的过程


我们把重点放在类加载的过程，JVM 在进行类加载的过程如下：

  1. 通过一个类的全限定名来获取定义此类的二进制字节流
  2. 将这个字节流所代表的静态存储结构转化为数据区的方法区的运行时数据结构
  3. 在内存中生成一个代表这个类的java.lang.Class对象，作为方法区中这个类的各种数据的访问入口

但是，在第一点中，这个二进制字节流不一定是从.class文件中获取，它可以来自程序在运行中产生的结果，从JAR包、从网络中、运行时计算生成等等。

只是，这里又会有一个问题，类是什么时候加载的呢？

Java 类加载分为动态和静态（显式和隐式），动态加载是通过反射或直接通过 ClassLoader 来加载一个类对象，在运行时需要用到再加载，无需提前编译；而静态则是通过类名.方法名()或new实例化对象，在编译时就加载。静态类在运行程序的时候内存里就已经有了，动态类在程序运行到创建实例的时候内存中才会有。

常见的类的动态加载方式：

// 通过反射加载，默认会初始化被加载类的静态属性和方法Class.forName("com.tuzk1.sec.Hello");
// 通过反射加载，不会初始化被加载类的静态属性和方法Class.forName("com.tuzk1.sec.Hello", false, this.getClass().getClassLoader());
// 通过ClassLoader加载，不会初始化被加载类的静态属性和方法this.getClass().getClassLoader().loadClass("com.tuzk1.sec.Hello");
