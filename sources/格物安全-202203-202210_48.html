基础知识

默认有16个数据库，默认使用第一个，set+num可以切换数据库

dbsize:数据库大小

flushall：清除所有数据库数据

flushdb:清除本数据库数据

select + num:选择操作哪个数据库

redis是基于单线程的，性能瓶颈是机器的内存和网络带宽，和cpu无关

qps：每秒查询率（QPS，Queries-per-second）是对一个特定的查询服务器在规定时间内所处理流量多少的衡量标准。

上下文切换指的是内核（操作系统的核心）在CPU上对进程或者线程进行切换。上下文切换过程中的信息被保存在进程控制块（PCB-Process Control Block）中。PCB又被称作切换帧（SwitchFrame）。上下文切换的信息会一直被保存在CPU的内存中，直到被再次使用。

ttl

当 key 不存在时，返回 -2 。当 key 存在但没有设置剩余生存时间时，返回 -1 。否则，以秒为单位，返回 key 的剩余生存时间。

注意：在 Redis 2.8 以前，当 key 不存在，或者 key 没有设置剩余生存时间时，命令都返回 -1 。

type + key

查看key的数据类型

String（字符串）

append + key + string:追加字符串，如果字符串不存在，就相当于set

STRLEN + KEY:截取字符串长度

incr + key:自动加一

decr + key:自减一

事物

ACID：隔离性、持久性、原子性（要么同时成功、要么同时失败）、一致性

redis事物本质：一组命令的集合

一个事物中的所有命令都会被序列化，在事务执行的过程中，会按照顺序执行

一次性、顺序性、排他性

redis单条命令是保证原子性的，但是事物不保证原子性

redis事物没有隔离级别的概念

redis事物

  • 开启事务（multi）

  • 命令入队

  • 执行事物（exec）

127.0.0.1:6379> MULTI
OK
127.0.0.1:6379> set b 4
QUEUED
127.0.0.1:6379> get b
QUEUED

QUEUED
127.0.0.1:6379> get b

127.0.0.1:6379> EXEC

2) "4"

  • 很悲观，认为什么时候都会出事，都会上锁

乐观锁：

  • 很乐观，认为什么时候都不会出问题，所以不会上锁。更新数据的时候去判断一下，在此期间是否有人修改过这个数据
