# 一个吃货眼中的熔断漏洞

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MjM5NzE0NTIxMg==&mid=2651092548&idx=2&sn=3e27be4eee82f4c9e873c940fe16243a&chksm=bd2ea9578a592041d41241a4a25578c3c07084b5450626bed1ff5992e56ece871981b421580b&scene=126&sessionid=1681369038#rd](http://mp.weixin.qq.com/s?__biz=MjM5NzE0NTIxMg==&mid=2651092548&idx=2&sn=3e27be4eee82f4c9e873c940fe16243a&chksm=bd2ea9578a592041d41241a4a25578c3c07084b5450626bed1ff5992e56ece871981b421580b&scene=126&sessionid=1681369038#rd)

大家好，新年刚过，安全界就出了一个大事，英特尔处理芯片A级漏洞Meltdown（熔毁）和Spectre（幽灵）一举击垮全球计算机设备，掀起轩然大波。

![](../Images/6632d24387f2c8938f445edd36ce005a.png)

各大安全厂商和研究人员倾巢而出，各种原理解读文章扑面而来，然而此次漏洞涉及到CPU硬件架构和操作系统底层原理，普通的非专业人士还是很难理解清楚的。

![](../Images/4ed487fb478c5e7fc1befc46c4f5df17.png)

小编作为一个资深吃货，长期出入各大五星酒店、路边苍蝇店、网红店，在这里用餐饮界的思路来为各位看官分析下英特尔本次漏洞到底是怎么一回事儿。

**首先，看一下餐馆和芯片的共同点：**

**1****、分区**

![](../Images/ea86b4295e93ba8feca7946614edcf11.png)

内核态和用户态是操作系统用来定义应用进程获取资源的两种权限，处于内核态时，CPU可以访问内存的所有数据；处于用户态时，CPU受限的访问内存。这一点就像顾客点餐一样，作为顾客，是不能随意进入后厨直接品尝菜品的，只能在用户区通过服务员向后厨下单；

当一个程序需要从用户态转化为内核态时，就像顾客点了一道菜要到后厨加工一样，有3种方式：

1）系统调用：例如调用sys\_fork()来创建进程，即成功下单，厨子您炒菜去吧；

2）外部中断：例如NOC发出的中断，即客户中途取消下单，这菜有点贵；

3）异常：例如没有找到所需的页表，比如客户点的菜配菜不足了，今天卖太火！

**2、权限**

芯片和餐馆一样，是按区划分访问权限的，就像后厨只允许厨师和服务生进入，顾客是绝不可以进入的。在大一些的餐厅，甚至会严格限制后厨内各位工作人员的工作区域和权限，比如清洗菜品的小工不可以直接接触成品菜。

![](../Images/487f7c45b79f61b1eac7b67bf9cfc2d0.png)

在Intel的X86硬件上有一个核心的机制就是权限，从低到高分别为ring3~ring0，硬件上在执行每条指令时都会对指令所具有的权限做相应的检查，ring0对应为内核态，为最高权限。进程被设计为无法访问内核地址空间，所以当处于ring3的程序进程要访问ring0权限的地址空间时，就会被CPU拒绝。

**3、缓存机制：**

缓存其实就是我们的库存，做实业的最清楚了，每天盘库都很重要，根据库存状态判断该提前采购些什么菜，不然等到顾客已经下单了，发现没有再去买就尴尬了，而且十分影响翻台率。

具体到芯片，因为普通的硬盘或者内存的I/O速度，都无法赶上CPU的计算速度，因此增加了Cache机制来优化CPU读取内存数据的速度。

![](../Images/84171303476df678061a7ab2a5a3d092.png)

现在的CPU中，L1和L2 Cache基本都是内建在CPU内部。CPU 访问某个数据时，首先查询 Cache 是否已缓存该数据。如果有，则返回数据，无需访问内存，称为一次Hit；如果不存在，则需把数据从内存中载入 Cache，最后返回给处理器，称为一次Miss。

由于L1/L2 Cache是on-CPU的，而且Cache的存在本来也是设计给CPU快速读取数据的，因此程序进程是无法直接访问Cache的，其中的数据只会被系统调用指令读取。只有Cache中的数据进入寄存器以后才可以被程序进程访问。

![](../Images/5812854007b2d6982545705fa87113d1.png)

**4、推测执行**

简单说，推测执行就是预先准备好计算结果，当需要这些数据时立即使用。就如餐馆开门营业时，厨房的准备工作是基本就绪的，当顾客进门之后点菜时，厨房的菜大部分是被加工成半成品的，比如土豆切丝、切块，肉丝、肉块都是分类切好摆放的，当顾客进门点菜时，只需要把这些菜品分配使用即可。

以下面这段简单代码为例：

IF A = B THEN

C = C + 1

ELSE

C = C - 1

END IF

正常情况下，本来处于两个逻辑分支中的语句只会被执行其中一个，但是CPU通过推测执行的方式，同时计算了C+1和C-1两个结果，并把数据从内存中加载到缓存中，当A和B的相等判断完后，就可以直接从缓存中取出相应的值，这样有效减少了因为顺序执行带来的等待延迟。推测执行并没有违反用户态永远无法直接访问内核态的原则，因为数据最终必须被载入寄存器才会被访问，而程序直接访问缓存是会被判定为越权异常。

**说完共同点，再来看一下英特尔的漏洞是什么情况？**

我们都知道，餐厅一般有两种收费方式，像麦当劳、肯德基、食堂、快餐店这些地方，一般都是先收费，下单时就付款，但是很多餐厅都是先吃饭后付款的，我之前就遇到很多顾客吃完了之后看服务员不注意就偷偷溜掉，这样就会出现吃霸王餐的情况。

![](../Images/53fdf71b40faae83d2c87ca38170aac9.png)

英特尔本次所遭遇的霸王餐利用的是对缓存数据读取的鉴权过晚，攻击者有效利用了CPU缓存记录了所有对应地址上的数据，并通过侧信道攻击，精确探测内核地址空间边界，从而将内存空间导出得到敏感数据。可以看到，在整个攻击过程中，缓存、预测执行这两个重要机制被利用，侧信道攻击方式也十分隐蔽和巧妙。

**吃完霸王餐的后果是什么呢？**

如果只是碰到一个吃霸王餐的，可能并不影响大局，但是如果一个餐馆碰到10个甚至更多吃霸王餐的，小至亏损，日益累计的结果可能就是破产了。本次漏洞对云基础设施的影响最为深远，由于是硬件层面的漏洞，租户间、应用间、应用和系统间的隔离在硬件层面完全失效。对于个人用户，针对操作系统口令、秘钥、cookie等信息的窃取将是重中之重，攻击者可以读取内存中的敏感数据，甚至能够完整Dump内存镜像。更为恐怖的是，如果“熔断”这种核武器级别的漏洞被用于主权对抗，那么对我国关键基础设施的影响将更为严重。

**附：本次漏洞简要技术分析**

针对英特尔处理器漏洞分别为Meltdown（熔断）和Spectre（幽灵），Meltdown涉及CVE-2017-5753和CVE-2017-5715，而Spectre涉及CVE-2017-5754。

以CVE-2017-5754为例，整个攻击过程大致为：

1）  恶意程序先执行一个系统调用sys\_fork( )创建新进程，此时，CPU的TLB、L1/2/3 Cache中可能会与此次系统调用有关的代码和数据，例如分配的内存地址、内存大小、Offset等。当调用返回后，这些内容并不会立即就被清掉，而是继续待在TLB和Cache中。

2）  恶意程序发出请求访问内核区，由于违反了权限设定，最终当然是访问失败，但是由于CPU的推测执行，这些指令实际上已经被CPU计算， Intel非常激进的不仅将页表条目载入TLB，连对应地址上的数据都被载入了缓存。只是在最后阶段检查ring权限时，发现不匹配导致读取报错，但执行痕迹却留在了缓存中。

3）  恶意程序发出多次请求访问内核区，如果程序尝试访问的内核区恰恰就是刚才所执行的系统调用相关的内容，那么缓存命中，此时会发现这个调用返回的比之前快，这就说明了，该内核区域存放的可能就是sys\_fork相关的代码和数据。通过对整个内核地址区不断尝试，就可以精确探测出内核地址空间的边界。

4）  将内存空间导出，得到敏感数据。

*Tips**：*

*TLB：Translation Lookaside Buffer，是一种CPU快速读取内存位置的方法*

*侧信道攻击：通过对运行结果的观察和推测，进行攻击的一种方法*
