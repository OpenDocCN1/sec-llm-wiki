区块链的安全成长竟然还需搞定它！

最近IT圈讨论的热火朝天的事情中比特币算是一个了，毕竟许多人眼睁睁的看着它从年初的一千多美元飙涨到近两万美元！让一大批很早就了解和接触到比特币的IT人士捶胸顿足，一个个都在高呼错过一次成为土豪的大好机会！

不过随着今年9月份七大部委联合发布的《关于防范代币发行融资风险的公告》一纸通告，国内所有代币平台的交易基本停滞。虽然代币被监管机构叫停，但是这些代币背后的区块链技术却没有受到影响，反倒发展的风生水起，不断有新的区块链创业公司出现，意图在证券市场、支付系统、票据与供应链金融、客户征信与反欺诈等应用场景里谋求大发展。但在享有“互联网之后最具颠覆性的创新技术”之名的区块链技术应用背后，安全问题却成为了不可忽略的重要一环。

单单就区块链技术本身而言，它使用了目前非常主流的加密、签名等方案来确保其安全性，但是再安全的系统也会存在安全问题，下面分几个方面分析区块链可能存在的安全问题。

密钥安全：密码技术是区块链的核心技术之一，保证了区块链不可逆、不可伪造。因此密码技术中秘钥的存储、传输等安全风险在区块链中同样存在。区块链没有第三方，私钥由每个用户各自保管，如若用户用于存储私钥的设备感染了病毒，则可能会导致私钥丢失，一旦私钥丢失用户将失去对自身数据或者资产的控制权。区块链由于去中心化，没有私钥补发与管理机制，因此私钥一旦丢失即无法找回。

隐私保护：区块链的隐私保护也存在安全性风险。一个区块的数据中包含了所有交易记录以及账户身份信息，交易信息在区块链中是公开的，且账户身份信息通过非对称加密算法加密，所有人都可以获取，因此如果交易信息存在一定的敏感性，那么就有可能被“意外”泄漏。另外区块链系统内各节点并非完全匿名，而是通过类似电子邮件地址的地址标识（例如比特币公钥地址）来实现数据传输。虽然地址标识并未直接与真实世界的人物身份相关联，但区块链数据是完全公开透明的，随着各类反匿名身份甄别技术和大数据技术的发展，通过数据整合分析则可能实现部分重点目标的定位和识别。

拒绝服务：很多人一看到区块链去中心化的特点就会觉得区块链在应对拒绝服务方面相比现有的中心化系统会有一定优势，如更加灵活、点对点、多冗余，其中一个节点遭受拒绝服务攻击也不会影响整个系统。然而如果没有适当的机制来协调控制，当一个节点遭受攻击时，虽然不会影响整个系统，但是与该节点连接的用户则无法进行相应的操作。另外，区块链客户端如果存在安全漏洞，同样会存在类似目前移动App一样的拒绝服务问题，类似的事件有以太坊钱包Geth客户端崩溃导致以太币(ETH)交易市场发生临时性恐慌抛售事件和分叉以太坊(ETH)DDoS攻击。

针对技术实现攻击：每一个系统设计实现都会有缺陷，就算设计是安全的，代码实现也会存在一定风险。攻击者可以通过对数字货币钱包应用的代码逆向分析，寻找可利用的漏洞，从而对业务进行攻击。

上面列出了区块链技术会面临的主要安全风险点，不过还需要警惕的是，某些传统安全问题在给区块链业务企业信息系统安全性造成影响的同时，还会由于连锁反应而对其区块链业务系统的正常运行造成干扰。近期，梆梆安全的相关专家们就帮助某做区块链应用的企业客户解决了其业务网站建设过程中遇到的种种安全性问题，有效保障了客户区块链业务的正常运作。

该客户为了增加用户粘性，提升用户的活跃度，计划上线系列面向全球用户的促销活动，由于促销活动涉及到了用户隐私以及用户资金安全，所以对活动网站的安全要求十分高，梆梆安全作为一家专业的安全服务提供商，在收到客户需求之后，迅速组织安全专家帮助客户从安全角度进行技术安全选型（云服务商、操作系统、数据库、中间件、开发语言、安全产品）、风险评估、网站安全体系建设、网站安全开发咨询、网站安全运维体系、网站安全应急响应机制等多个方面的咨询，解决了客户在建设网站时所面临的实际安全问题，使客户能够放心地上线会涉及到用户隐私信息、资金情况的活动页面。避免了由于用户隐私数据泄露，可能会对其区块链应用业务造成的负面影响。

如果您的应用系统部署在了Linux服务器中，为了防止攻击者利用由于开发人员配置不当而出现的安全隐患，您可以通过对以下内容进行设置来提高操作系统的安全性。


Nginx作为一个高性能、轻量级的Web服务器/反向代理服务器，被许多开发者所喜爱，但是开发人员在配置Nginx反向代理的过程中，往往会忽略安全相关配置，如果您也使用了Nginx，那您可以参考下面的代码来对Nginx进行安全的反向代理配置。

events{ 

       worker_connections 10000; 

      }   

http{ 

       upstream myproject{ 

                  server服务器IP地址;   #这里可以添加多个

                  } 

upstream   test{ 

                  server服务器IP地址;   #这里可以添加多个,用于二级目录

                  }

              server { 

                listen 80; 

                              server_name www.xxx.com; #这里替换为实际的网站域名

                                   return 301   https:// www.xxx.com $request_uri;

               } 

location   /attivity {

                     proxy_pass http://test;

        }


        server { 

                listen 443 ssl; 

                              server_name www.xxx.com; #这里替换为实际的网站域名

                location / { 

                     proxy_pass   http://myproject;

                                          proxy_set_header  X-Real-IP    $remote_addr;

proxy_set_header  X-Forwarded-For $proxy_add_x_forwarded_for;

proxy_set_header  Host    $host;

                           }   

               } 

location   /attivity {

                     proxy_pass http://test;

proxy_set_header  X-Real-IP    $remote_addr;

proxy_set_header  X-Forwarded-For $proxy_add_x_forwarded_for;

proxy_set_header  Host    $host;

        }

    } 

上面只列出了部分在Web应用开发过程中会遇到的安全问题，Web应用安全也不是仅通过正确配置就能实现全面保障的，在技术上它还会涉及到操作系统安全、数据库安全、中间件安全、开发安全、DDoS防护、网站攻击防护等不同层面，在管理方面还会涉及安全开发、安全应急响应制度等安全防护需求。

从业务角度来看，大部分区块链企业、新兴科技企业、政府机关等都会使用Web网站来向用户展示公司产品，让用户能够通过Web网站来自助办理各种业务。在这个过程中，根据网站的业务类型，会涉及到用户的个人隐私安全、个人资产安全、企业数据安全、企业信息系统安全等不同层面的安全问题，因此无论是类似提供区块链业务的新技术企业也好还是传统企业也好，凡是通过网站承载公司业务的客户，必须要将网站自身安全防护放在首位。否则，攻击者就可以利用企业对公众提供的Web网站安全缺陷、安全漏洞实施恶意攻击，渗透进入企业内部信息系统，对企业整体业务都造成巨大的负面影响及损失。
