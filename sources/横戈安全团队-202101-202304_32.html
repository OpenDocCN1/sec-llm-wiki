0x03 Janus漏洞利用

1.首先查看是否使用了V2，如果使用了V2则表示漏洞不存在

https://github.com/bihe0832/Android-GetAPKInfo

命令：

java -jar GetApkInfo.jar test.apk

2.然后使用baksmali.jar来将classes.dex解开

将apk变为rar才可将classes.dex拿出来


拿出来

将这个文件拿到F:\janus\Apktool\Bin下

将包解开

命令：

java -jar F:\janus\Apktool\Bin\baksmali.jar -o F:\janus\target classes.dex

在F:\janus\target classes.dex下会将所有的包给解开

3.随意修改一个包中的参数

修改，注意修改的参数，一般改字符串，不然容易使app崩溃

4.将解开的包再打包回去

进入BIN文件中

输入命令

java -jar F:\janus\Apktool\Bin\smali.jar F:\janus\target -o F:\janus\classes.dex

成功之后，会在F:\janus文件夹下生成新的classes.dex

5.重新签名，打包回去，生成新的apk

工具地址（https://github.com/V-E-O/PoC/blob/master/CVE-2017-13156/janus.py）

命令:python janus.py classes.dex test.apk tarfet.apk

将classes.dex和test.apk重新生成一个签名不变的tarfet.apk

6.最后安装进手机,使用360手机助手

7.查看是否可以安装并且运行

思考：发现有很多打包之后运行就会失败，是因为直接把包给放进去了，多了一个资源文件，会崩溃

tarfet.apk的大小=classer.dex+bubei.apk

应该是将原始包中的classer.der给剔除，再加上修改的classer.der包，但是存在一个签名问题。如果直接剔除就会导致软件没有签名

0x05数据备份

当在AndroidManifest.xml文件中未设置android:allowBackup属性值或,设置android:allowBackup="true"时,可对应用程序私有目录下的所有数据进行备份.

1.使用改之理反编译apk

搜索allowBackup=”true”，为true说明是可以备份的

2.在夜神模拟器中下载xxx，并且登录


3.在夜神模拟器打开adb shell

这个备份有手机版本限制，所以我是在夜神模拟器上去做的测试

然后启动xxx，adb shell命令查看包名：

adb shell dumpsys activity top #

找到该app的路径

adb shell pm path com.world.three

导出apk文件，到当前目录下。

 adb pull /data/app/com.world.three-1.apk

 

开始备份

adb backup -nosystem -all -noapk -noshared -f app_live.ab com.world.three

这个需要在模拟器上去点击确认备份

再看XXX就发现已经是登录状态了

危害：现在日益增多的充电宝上如果有这个备份程序，是否会导致一些危害
