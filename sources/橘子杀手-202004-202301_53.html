Linux

向服务器上传/下载文件

方法其实有很多。可以搭建各种服务（HTTP 啦，ftp 啦，sftp 啦，scp 啦，rsync 啦）来传输。甚至直接可以打印出来之后直接复制粘贴（对于二进制文件就不行了，更何况还有文件夹呢）。其实 nc 也可以很方便地进行传输，直接打个洞就可以传数据了： 

下载：

# 服务端：
nc -lv 8888 < flag.txt

# 本地：
nc -v 服务器ip 8888 > flag.txt

上传，尖括号反过来就行：

# 服务端：
nc -lv 8888 > flag.txt

# 本地：
nc -v 服务器ip 8888 < flag.txt

如果服务端没有外网 ip，那么可以把“本地”改为自己的服务器，和反弹 shell 的道理是一样的。

nc 还有一个好处，可以穿过跳板机（虽然大部分跳板机都有文件传输功能），如果用走 ssh 的传输，有跳板机，它自带的文件传输又没法用的话就很难受了。

至于传输文件夹嘛，加个打包就行了：

# 服务端：
tar zcvf - ./flags | nc -lv 8888

# 本地：
nc -v 服务器ip 8888 | tar zxvf -

跳过 alias 与 func

上一期也提到了可以定义一个 alias，这样我们就不需要老是输入一大堆的命令了，别问，问就是懒。但更多的时候我们用来替换自带的命令，比如

alias man="man -M /usr/local/share/man/zh_CN"

这样我的 man 就是中文。但是有时我就是要看英文的 man，这个时候我要执行的是不加任何参数的 man，怎么办呢？在前面加 command 即可：

command man ls

command 可以强制 shell 在执行的程序时候跳过任何函数、内置的 builtins 还有 alias。当然直接指定可执行文件也是不错的选择，不过得先用 whereis 拿到路径，像我这么懒的人肯定是不会用的 。

command 还可以用于打印命令的位置或者是属性：

# macr0phag3 in ~ [18:57:23]
» command -v ls
alias ls='ls --color=auto'

如果你用 zsh 比较多的话，你就会发现 command/type 加上 whereis/which，包装包装差不多就是 where 了，where 是 zsh 的 shell built-in command，可以查找任何命令的位置，包括 alias、func、可执行文件。

当然，如果你知道各种 os 命令注入的技巧，你自然而然就会想到这样肯定也行：

\man
m\an
"man" ls
"m""an" ls

嗯，有点 hack。但是需要注意的是，这些方法只能跳过 alias，没法跳过自定义的函数以及 builtins。至于原理以及 os 命令注入的其他技巧，后面会单发一篇文章，这里就不多说了

然后我们就可以编辑这个命令。当然如果这个命令不是你想要的，那么直接删除后再组织自己想要的命令就好了。编辑完保存退出之后，会立刻执行这个文件里的命令：

shell-to-clipboard

那么如何在 Linux 上使用 pbcopy 和 pbpaste 呢？需要安装 xclip：

sudo apt install xclip
sudo yum install xclip

还需要加个别名：

alias pbcopy='xclip -selection clipboard'
alias pbpaste='xclip -selection clipboard -o'

还有一种就是 xsel，安装完之后，别名设置如下：

alias pbcopy='xsel --clipboard --input'
alias pbpaste='xsel --clipboard --output'

诶嘿嘿，接下来就可以愉快地使用  pbcopy 和 pbpaste 了

这个网站可以解释你输入的 shell 命令，例如 fork 炸弹：:(){ :|:& };:：

全英文的，其实相当于把 man 里的解释链接上了 shell 命令，不过还是很直观的。比如这里我们就知道原来 :(){ :|:& } 是个自定义的函数，名字就叫:，里面就是递归运行它自己，然后 fork 后台运行自己；定义完这个无限递归的函数之后，: 开始执行这个自定义函数。
