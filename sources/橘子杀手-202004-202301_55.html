Linux

当文件名以 - 开头

我们知道，在 shell 里 - 代表参数起始字符，当然也有 --。那如果文件以 - 开头的话，要怎么处理呢？例如文件名为-test-。直接写肯定是不行的：

# macr0phag3 in ~/Downloads [19:05:39]
» ls -test-
ls: invalid option -- 'e'
Try 'ls --help' for more information.

那加上引号呢：

# macr0phag3 in ~/Downloads [19:05:50]
» ls '-test-'
ls: invalid option -- 'e'
Try 'ls --help' for more information.

# macr0phag3 in ~/Downloads [19:06:30]
» ls "-test-"
ls: invalid option -- 'e'
Try 'ls --help' for more information.

很遗憾，也不可以。那转义呢？也是不行的，因为 - 并不是什么特殊字符：

# macr0phag3 in ~/Downloads [19:08:07]
» ls "\-test\-"
ls: cannot access '\-test\-': No such file or directory

解决方法有 2 种：

# macr0phag3 in ~/Downloads [19:08:12]
» ls ./-test-
./-test-

# macr0phag3 in ~/Downloads [19:09:17]
» ls -- ./-test-
./-test-

--啥意思呢？大多数 bash 的内置命令和许多其他命令中都会使用双破折号表示命令选项的结尾，在此之后就仅接受位置参数。

临时使用代理

用 curl 的时候加上代理怎么加呢？尤其是配了 科学♂上网的时候，想让 shell 也能走代理：

# macr0phag3 in ~ [19:55:41]
» export http_proxy=http://127.0.0.1:7890/

# macr0phag3 in ~ [19:55:42]
» export https_proxy=http://127.0.0.1:7890/

# macr0phag3 in ~ [19:55:46]
» curl ip.cip.cc
169.63.141.71

# macr0phag3 in ~ [19:57:07]
» unset http_proxy

# macr0phag3 in ~ [19:57:57]
» unset http_proxy

这样用完之后还得把 http_proxy 和 https_proxy 清空，否则会影响接下来的其他命令。

其实不用这么麻烦：

# macr0phag3 in ~ [19:58:00]
» where proxy
proxy: aliased to http_proxy=http://127.0.0.1:7890/ https_proxy=http://127.0.0.1:7890/

# macr0phag3 in ~ [19:58:15]
» proxy curl ip.cip.cc
169.63.141.71

# macr0phag3 in ~ [19:58:31]
» curl ip.cip.cc
121.68.81.35

这样需要走代理的，前面加上 proxy 即可。是不是和 proxychains 很像？（注：macOS 安装 proxychains 特别麻烦。。。所以想了这个办法）

~ 切换目录

基本上每个用过 Linux 的人都知道 ~ 代表的是当前用户的 home 目录。那如果我想切换到其他用户的 home 目录呢？可以用 ~username还可以用 ~- 切换到上一个目录；而 ~+ 代表的是当前目录：

# macr0phag3 in ~ [19:36:33]
» cd ~/Library/

# macr0phag3 in ~/Library [19:36:41]
» echo ~+
/Users/macr0phag3/Library

# macr0phag3 in ~/Library [19:36:45]
» echo ~-
/Users/macr0phag3

在 ps + grep 的结果中剔除 grep 自身的进程

常用的有 ps aux | grep -v grep | grep 'python'像我这样的懒人，更喜欢用  ps aux | grep '[p]ython'原理就是 [] 代表的是正则的 []，加了中括号之后，grep 的进程就变成了 grep '[p]ython’，这样就不符合解析之后的 grep 了，所以达到了剔除的作用。

:> 是什么意思？

: 在 shell 中代表什么都不做，既然什么都不做了，所以它一定会执行成功（滑稽）。所以嘛，可以用来清空文件：

一键解压文件夹

灵魂拷问：tar、zip 解压参数还记得吗？

懒人如我选择 x：

x () {
    if [ -z "$1" ]
    then
        echo "Usage: extract <path/file_name>.<zip|rar|bz2|gz|tar|tbz2|tgz|Z|7z|xz|ex|tar.bz2|tar.gz|tar.xz>"
        echo "       extract <path/file_name_1.ext> [path/file_name_2.ext] [path/file_name_3.ext]"
    else
        for n in "$@"
        do
            if [ -f "$n" ]
            then
                case "${n%,}" in
                    (*.cbt | *.tar.bz2 | *.tar.gz | *.tar.xz | *.tbz2 | *.tgz | *.txz | *.tar) tar xvf "$n" ;;
                    (*.lzma) unlzma ./"$n" ;;
                    (*.bz2) bunzip2 ./"$n" ;;
                    (*.cbr | *.rar) unrar x -ad ./"$n" ;;
                    (*.gz) gunzip ./"$n" ;;
                    (*.cbz | *.epub | *.zip) unzip ./"$n" ;;
                    (*.z) uncompress ./"$n" ;;
                    (*.7z | *.arj | *.cab | *.cb7 | *.chm | *.deb | *.dmg | *.iso | *.lzh | *.msi | *.pkg | *.rpm | *.udf | *.wim | *.xar) 7z x ./"$n" ;;
                    (*.xz) unxz ./"$n" ;;
                    (*.exe) cabextract ./"$n" ;;
                    (*.cpio) cpio -id < ./"$n" ;;
                    (*.cba | *.ace) unace x ./"$n" ;;
                    (*) echo "extract: '$n' - unknown archive method"
                        return 1 ;;
                esac
            else
                echo "'$n' - file does not exist"
                return 1
            fi
        done
    fi
}

放入 ~/.bashrc 或者 ~/.zshrc 之类的配置，即可用 x 文件名 横扫压缩文件。

将 n 秒转为合适时间单位

from itertools import accumulate
from operator import truediv, mul


def timer_unit(s):
    d = [(i, u) for i, u in zip(accumulate([s, 60, 60, 24, 30, 12], truediv), 'smhDMY') if i >= 1]
    m = [(i, u) for i, u in zip(accumulate([s, *[1000]*2], mul), 's ms us'.split()) if i >= 1]

    return [*d[::-1], *m, (s, 'us')][0]
    # return num, unit

示例：
