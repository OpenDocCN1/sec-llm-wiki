# 记一次利用cs进行内网渗透的过程

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=Mzg5OTY2NjUxMw==&mid=2247507080&idx=1&sn=183626a121e6e1f0f45d7a0a038be353&chksm=c04d5bb6f73ad2a0945793ae23cf8a69bfe3666b515b9247a8a23f95687d6a3cfb2fa10b1068&scene=126&sessionid=1681662779#rd](http://mp.weixin.qq.com/s?__biz=Mzg5OTY2NjUxMw==&mid=2247507080&idx=1&sn=183626a121e6e1f0f45d7a0a038be353&chksm=c04d5bb6f73ad2a0945793ae23cf8a69bfe3666b515b9247a8a23f95687d6a3cfb2fa10b1068&scene=126&sessionid=1681662779#rd)

首先搭建好cs的服务端和客户端连接，下面正式进行渗透

  

##### **环境**

kali:192.168.0.226

域控机：192.168.0.138

成员机：192.168.0.251 192.168.0.141

##### **操作**

###### **cs上线**

1.  首先开启监听cobalt->listeners,host和beacons都为cs服务端的ip地址
    
    ![](../Images/ea0a16fa8a77a0505c3f6541779e63d5.png)
    
2.  生成相应的windows木马，上传到靶机251中执行。
    
    ![](../Images/dd025ced7890ff9655bee2440b75c1c7.png)
    
    选择对应的监听和木马格式
    
    ![](../Images/a5d22e9ae5704319dc82ccca9e5bf6fb.png)
    
    最后将生成的木马传到靶机中，让靶机执行。
    
3.  机器上线成功
    
    ![](../Images/acaa649bbfe4dc641c0ea9e2ac334a7f.png)
    

###### **部分cs命令利用**

```

getsystem
```

获取到内网域相应的信息

###### **存活主机探测和获取凭证**

1.  内网横向探测
    
    获取到一个 cs 的 beacon 后可以目标内网情况和端口开放情况，在 beacon 上右键 -> 目标 -> 选择 net view 或者 port scan：
    
    ![](../Images/96c5f28123ef387709c74bb621647e11.png)
    
    可以在菜单栏中，view视窗的targets选项中查看
    
2.  用 cs 的 hashdump 读内存密码：hashdump，用 mimikatz 读注册表密码：logonpasswords。获取相应账户凭证
    
    或者：
    
    右键->Access->Dump Hashes（需要Administrator权限）
    
    右键->Access->Run Mimikatz
    
    ![](../Images/927c38b61e969862ad4470fa7262446e.png)
    
    可以在凭证栏中查看获取的凭证
    
    ![](../Images/54aa3f74b0ffafb67db0cccfd37eeed4.png)
    
    ![](../Images/db5716b1db7d72143cfb1f711feb9d9e.png)
    
      
    

###### SMB Beacon和psexec传递（msf中的hash传递攻击）

######   

在探测到其他两个内网机器开了445端口的前提下，可以使用SMB beacon获取。相当于在msf里面使用永恒之蓝获取shell。有两种方法

1.  直接派生，新建一个listener，pyload设置为beacon\_smb
    
    ![](../Images/9b67c3caf384d76dcece93fe14e86065.png)
    
    在已有的 Beacon 上右键 Spawn(生成会话 / 派生)，选择创建的 smb beacon 的 listerner：
    
    选择后会反弹一个子会话，在 external 的 ip 后面会有一个链接的小图标：
    
    ![](../Images/dbbd8511e853d6188c5bec430dbe0354.png)
    
      
    
    这就是派生的 SMB Beacon，当前没有连接，可以在主 Beacon 上用 link host 连接它，或者unlink host 断开
    
    ![](../Images/f3ffdf1f94494141a6774cf960e36d5e.png)
    
      
    
    就是说通过之前的beacon为跳板通过SMB去连接新beacon获取权限shell
    
    可以在视图界面查看图形化连接情况
    
    ![](../Images/c3728a27bdb0b78936b9ef69bfb53138.png)
    
      
    
2.  前面横向探测已经获取到内网内的其他 Targets 以及读取到的凭证信息，尝试使用 psexec
    
    模块登录其他主机，右键选择一台非域控主机 ROOT-TVI862UBEH 的 psexec 模块：
    
    ![](../Images/868403bdadbdb53c7097da56458c721a.png)
    
      
    
3.  在弹出的窗口中选择使用 god.org 的 Administrator 的凭证信息，监听器选择之前创建的
    
    smb beacon，会话也选择对应的 smb beacon 的会话：
    
    ![](../Images/ea7e7f0e04f1e8b2418561938ca4737c.png)
    
      
    
4.  成功上线，并返回新的beacon
    
    ![](../Images/2f1f8a47c0af6056961248ca3f0098f3.png)
    
      
    

###### **另一种方式token 窃取**

除了直接使用获取到的 hash 值，也可以直接窃取 GOD\\Administrator 的 token 来登录其

他主机，选择 beacon 右键 -> 目标 -> 进程列表，选择 GOD\\Administrator 的 token 盗取：

![](../Images/3bd472a13e64d47b2f12a5cba2b047e9.png)

找到相应账户的conhost.exe信息，获取其token

![](../Images/136746a8d4997453af0fa0bba7732447.png)

再在之前获取的凭证中选择相应账户，勾选token选项就好了

![](../Images/de44ea9fdb5c7cd05c167c2273812571.png)

**补充;**

###### cs与MSF会话传递

1.  MSF 创建监听自己的 ip 跟端口：
    
    ![](../Images/d33dd48c5b6e456577c348c338168c2b.png)
    
2.  CS 创建监听 listeners，Listeners 的 ip 为 msf 的 ip，端口为 msf 监听的端口（注：如果
    
    msf 是内网下的，则需要把端口映射到公网，或者使用 ngrok 等工具做流量转发）
    
3.  回到 cs 上，选中拿下的计算机会话，右键选中 spawn，然后在弹出来的框中选择刚刚创
    
    建的 listeners 监听器，然后执行。
    
4.  msf收到会话
