对自己学校进行的一次渗透测试，由于深信服过于变态，而且拦截会直接封ip，整个过程有点曲折期间进行了后缀名绕过，jspx命名空间绕过、获取网站根目录、base64五层编码写入shell等操作

## **获取网站接口**

主界面:![](../Images/d02d2cd6939a658c83ba5ab2034be3da.png)上传点:![](../Images/7c949e0c6b438914e5ad645daa13c590.png)由于该应用是内嵌企业微信的套皮Html，所以我们首先用Burp Suite抓包获取接口和cookie![](../Images/0844a4dd56ffcf6578b2ba692213a63d.png)任意文件上传:![](../Images/589f89370ee32a2dda55cc1e3e4a74e5.png)文件名强制命名为code+学号，后缀为最后一次点号出现之后的字母

## **后缀名绕过**

  
代码不限制后缀名，但是waf限制呀！后缀名`jsp`，`jspx`会拦截，但是`jspp`，`jspxx`等不会拦截所以要利用`windows特性`绕过，常规的绕过手法例如`末尾加点号`、`::$DATA`均无法绕过![](../Images/25edfde261282fbb1b1388e073efb834.png)经过fuzz，发现`正斜杠`可以绕过![](../Images/bf43d9cf6853184ff7b230c70fad8c56.png)

## **内容绕过**

  
常见的jsp标记均无法绕过![](../Images/5898bdf4d63b019238e64614e4a0157a.png)![](../Images/c7f623a1a884b71b4d0e024d3d6e7fb3.png)所以我们得绕过`JSP标记`检测，这里参考了`yzddmr6`师傅的两种 **绕过方法**：

*   jspEL表达式绕过
*   jspx命名空间绕过

**第一种是利用`${}`标记**：payload：`${Runtime.getRuntime().exec(request.getParameter("x"))}`但深信服waf过滤了一句话，需要变形绕过鄙人太菜了，不了解相关函数的变形绕过，所以选择第二种写法**第二种是利用命名空间的特性**：参照yzddmr6师傅的图：![](../Images/5642a898e33e52acd3d08cfd95987a8f.png)  
使用自定义的命名空间，替换掉`jsp`的关键字将原本的`<jsp:scriptlet>`替换成`<自定义字符:scriptlet>`这样waf的正则匹配不到`<jsp:scriptlet>`自然就会放行

```
`  <hi xmlns:hi="http://java.sun.com/JSP/Page">`
```

![](../Images/403c76941c5dccb183a9cfa83053824b.png)![](../Images/0ef3e23fbc4e71e5041db60885654572.png)


## **编码或加密绕过waf写入shell**

  
菜鸡的payload：

```
`  <hi xmlns:hi="http://java.sun.com/JSP/Page">`
```

一开始我是用两层base64编码，还是被检测了，经过fuzz发现五层编码即可绕过鄙人太懒了，不想重新造轮子。如果各位师傅有时间的话，遇到这种waf建议用RSA、AES等加密算法绕过![](../Images/4d49d6c3759537741ae803a41733ec0c.png)

深信服的waf算挺强了，而且也足够恶心，检测可疑行为直接封ip，光是fuzz就用掉了快30个ip了学校其他站点有`thinkphp5.0.23 RCE`、`泛微8.0前台sql注入`的漏洞，但都有这个waf，实在没有耐心一个个fuzz
