# 0x00前言

某日在做一个渗透测试项目，但是没有任何收获，这怎么能给领导交差呢？于是只能加班加点进行测试，终于在我大力出奇迹的干法下，拿到了一个shell。

# 0x01 获取备份文件

1、对目标站点进行目录扫描没有什么收获，只有一些403，

![](../Images/386a0afe63c22b2193f5ee13a4e8ec50.png)

但是总感觉这里会有东西，于是我又重新fuzz了一下目录，把目标的公司名缩写加在了目录名中，果然大力出奇迹，获取到了一个备份文件。

![](../Images/0e26849227cc3febc79ebfce8c87ef08.png)

  

2、在备份文件中获取到了许多敏感信息

![](../Images/e1cf91a8f600fc21266e71fc3abb74d1.png)

# 0x02 通过钉钉KEY和SECRET获取敏感信息

1、env的文件中有微信小程序、公众号、QQ、钉钉等IM通讯软件的KEY和SECRET

![](../Images/b3633bd8e797ee233466667262a02631.png)

2、微信的KEY和SECRET都尝试利用了，但都没能获取到token，可能是设置的有IP地址限制，但是钉钉的可以成功利用，利用官方的API 获取accessToken

https://open-dev.dingtalk.com/apiExplorer#/?devType=org&api=oauth2\\\_1.0%23GetAccessToken![](../Images/57920ce296e8628d8db0c560edb19952.png)

然后有了token，能够获取的数据就有很多了，这里只演示一下获取部门列表，根据官方API手册，获取部门列表

![](../Images/59663cbe6773daa9d10d8c97d2b2d1b3.png)

成功获取部门列表信息

![](../Images/56b76d8bb642c177bdbbe863bd5f6eab.png)

# 0x03 微信支付宝支付接口信息泄露

1、在Web.config文件中获取到了微信和支付宝支付的接口信息

![](../Images/6dd3dd65e6ac6582e94c6084675bddbc.png)

2、支付密钥泄漏，就有可能导致攻击者花1元购买了100元的商品。系统进行验证时，会发现签名正确，商户号正确，订单号支付成功，若代码没有验证支付金额与订单是否匹配，将完成攻击者的订单。在许多网站或者App中，曾出现过只验证签名和订单id的情况，没有验证实付金额，因此可以通过这种金额篡改进行攻击。

![](../Images/b5db8da92f4d46e048004fdf0e0040ab.png)

3、并且文件中还泄漏了证书文件

![](../Images/c5d8de984a4d0f6df9a8a95da6e2d2d0.png)

有了证书就可以调用微信支付安全级别较高的接口（如：退款、企业红包、企业付款）

4、这里就没有进行利用（害怕ing）

# 0x04 接口文档泄露导致getshell

1、泄露的文件中还有一个接口文档，在其中查到了一个文件上传的接口

![](../Images/a6193e2645e00d6dca931a47c9d0e793.png)

2、测试后发现该接口是未授权访问并且可以上传webshell

![](../Images/34d72374970380becb819b150be52c42.png)

但是返回的链接直接拼接到url上并不是正确的shell路径，于是本着大力出奇迹的原则，开始爆破webshell的路径，可以先选择一些常用的上传文件的接口路径进行爆破

```
file/fileRealm/file\_manager/file\_upload/fileadmin/fileadmin/\_processed\_/fileadmin/\_temp\_/fileadmin/user\_upload/upload/filedump/filemanager/filerun/fileupload/files/files/cache/files/tmp/logfile/paket-files/profile/profiles/
```

我们发现uploadFile这个路径和其它的不太一样

![](../Images/305108a0b33e8e913ee4d1a95b1e4b42.png)

成功连接shell

![](../Images/834881a466275140ade3d2a04106c343.png)
