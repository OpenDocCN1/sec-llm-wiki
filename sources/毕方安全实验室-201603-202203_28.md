# 多图预警：从安全角度吐槽Uber的产品设计

做为一个安全狗，对类似这种问题会格外感兴趣，不研究研究肯定是睡不好觉的。首先想到是不是存在逻辑、越权之类的漏洞，看了看相关的支付绑定功能，否定了这个想法。

 

后来猜测可能是被攻击者盗号了，以前对几百家公司的产品做过安全测试，一般涉及到RMB消费的产品，都会有二次短信验证或者支付密码验证，使用过Uber的都知道，Uber这款奇葩的产品是没有做二次验证的，打完车会被自动扣款，用户只能收到银行扣款通知。

 

很好奇攻击者是如何消费朋友账号里的钱的，如果知道我朋友账号的密码，叫车消费的时候，朋友肯定会接到司机的电话或者Uber的车已到之类的通知，**但是我朋友反馈说并没有收到任何的短信，只有收到了银行扣款的提示。**

 

接着怀疑应该是朋友的账号资料被修改了，因为朋友用之前注册的账号登录，会提示电话、邮箱无效之类的。正常的产品业务流程，涉及到修改敏感信息的也会有二次短信验证之类的，测试发现通过Uber App修改资料，验证流程如下：

1，要修改账号的电话、邮箱，旧的手机号码会收到一个短信提示，大体内容是账号的电话、邮箱被修改了，如果不是本人修改的，请发邮件到support@uber.com；

2，新修改后的邮箱会收到一个确认邮箱的链接，新修改后的手机会收到一个四位验证码，四位验证码是用来重新登录手机App的时候用的。

![](../Images/5ecabf674628cd55b0f5cf41fbea0f08.png)  
最主要的以上修改敏感信息的操作，居然没有二次验证，居然没有二次验证，居然没有二次验证！这意味着，盗号者能轻易把被盗的账号据为己有，因为邮箱、手机等关键信息都已经被攻击者修改了，再用之前的电话、邮箱登录都会"提示邮箱、手机号码无效“之类的。

 

虽然被攻击者的手机会收到一个短信提示，但是亲测通过邮件申诉24小时之后，并没接到任何的答复或者更改。也就是说，等接到Uber客服的反馈处理，至少需要等24小时，说不定你银行卡里的钱，已经被盗号者消费很多了……

 

以上测试并没有结束，继续测试发现Uber这个产品真是很奇葩啊，我都已经无力吐槽了！

 

因为朋友反馈说他没有接到账号资料被修改的短信提示，继续测试，发现问题出在web端。通过web端修改被攻击者的电话、邮箱信息，被攻击者不会接到任何的提示，不会接到任何提示，不会接到任何提示！

 

因此可以还原事件的过程如下：

1，攻击者盗取了朋友的Uber账号；

2，攻击者网页登录uber，修改了朋友Uber账号的电话、邮箱；

3，攻击者用修改后的账号和密码登录了Uber App；

4，攻击者利用Uber打车，消费了我朋友银行卡中的RMB。

 

Uber产品设计的车费支付是自动扣费，修改敏感信息应该有最基本的二次的短信验证，这样在用户账号被盗号的情况下，才能保证用户资产的安全。并且Web端和APP在相同功能的实现上，居然有大的流程差别，也是让人无法理解的。

 

从安全方面看，以上案例攻击难度是挺大的，测试发现修改资料无任何验证的问题严格意义上讲也不算安全漏洞，不过一旦有登录接口可以撞库，影响就会很严重，意味着黑客一个人可以拥有众多Uber账号，并且可以随时进行打车消费别人账号里的RMB。

 

因为按照我的理解，发现的问题不算安全漏洞，也就没有提交到wooyun，前不久在知乎看了道哥有关渗透测试的回答，吓得我也不敢继续深入测试是否有存在撞库的接口，或许主站就可以撞库呢？而且Uber这个公司居然也不是wooyun的厂商，不知道是不是产品做的“太安全的”的原因！
