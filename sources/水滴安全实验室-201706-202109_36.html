前言

前两天一个比赛的pwn题，此题是在做off-by-null 漏洞相关的利用 ，使用 fastbin attack

通过此题，掌握 off-by-null 漏洞利用的一些处理细节，这里给大家介绍一下我的解题思路。

关于 off-by-null 漏洞原理 以及 fastbin attack 相关的内容，这里就不啰嗦了，在解题中体现。

功能分析

这是一道人员管理题，是一个堆的题，程序提供了五个选项，分别是：

1.add2.edit3.show4.delete5.exit

关键函数分析

add函数

漏洞点在add函数中的read_input函数中

_BYTE *__fastcall read_input(__int64 a1, int size){  _BYTE *result; // rax  int i; // [rsp+1Ch] [rbp-4h]
  for ( i = 0; i <= size; ++i )  {    read(0, (void *)(i + a1), 1uLL);    if ( *(_BYTE *)(i + a1) == '\n' )    {      *(_BYTE *)(i + a1) = 0;      break;    }  }  result = (_BYTE *)(i - 1LL + a1);  *result = 0;    // 最后加上字节”\x00″，造成了offbynull漏洞。  return result;}


edit函数没任何作用

__int64 edit(){  puts("not implement");  return 0LL;}


show 函数：通过对fastbin 的操作，由show泄露 unsorted bin chunk的地址

9.修改malloc_hook为one_gadget，然后add 函数触发malloc劫持__malloc_hook

one_gadget = libc_base + 0x4526Apayload = 'a' * 0x13 + p64(one_gadget)add(0x60, payload)          # 执行触发 malloc劫持__malloc_hook，转而执行 one_gadget


执行之后，我们发现并没有成功获取到shell，如下图：

这是因为当执行one_gadget的时候，执行到call    execve时，lea     rsi, [rsp+30h] 所获取到的栈中的数据不为NULL，也就是 execve 函数调用时，执行 /bin/sh 命令时，命令参数不为NULL，如下图：

因为 [rsp+30h] 对应的栈中数据不为0，所以我们需要采用调栈的方法，达到 rsp+30h 对应的栈数据始终 为0。
