# **测试介绍**

#     在胖虎表哥的办工桌上发现了他的电动车钥匙，在他出去的过程中，我偷偷按下了他的遥控器，并且录制好了信号，在下图可以看到胖虎表哥的车钥匙分别有四个功能，分别是:开锁、上锁、警报、和无钥匙启动(不需要插入钥匙即可开车)

![](../Images/5ea6808a39388c2df694978ae9135517.png)

  

    我是不是可以通过分析一个开锁或者一个关锁的信号，推算出警报和无钥匙启动呢?

    在本文测试中，主要测试的是电动车遥控器，一般频率在315MHz或433MHz。

    那么我们首先了解一下生活中常见的一些频率吧。

**一、生活中常见的频率**

 

1. 发射频率:125KHz 13.56MHz

     典型产品: 门禁刷卡器、公交刷卡器;

2. 发射频率:27MHz、35MHz、40MHz、49MHz、72、MHz

     典型产品: 遥控玩具、无线鼠标、非专业对讲机;

3. 发射频率:315MHz、433MHz、868MHz、915MHz(间断性,周期性产品,遥 控玩具禁止使用 ) 

    典型产品: 遥控开关、无线门铃、防盗设备(汽车或电动车遥控器);

4. 发射频率：88-108MHz

    典型产品：FM发射器；

5. 发射频率:902-928 MHz, 2400-2483.5 MHz, 5725- 5850 MHz

    典型产品：遥控玩具、无线鼠标、蓝牙、WIFI、发射器；

**三、信号录制**

  

    录制信号的话那么就需要知道是在那个频率上的，那么我们就可以利用上面所说的SDR#或者Gqrx来进行测试看遥控器的频率是那个。

    以下是windows环境下测试遥控器的频率:

![](../Images/f73645a6ec695cd4b6119fc4a7ec81af.png)

![](../Images/5b737563f70403cd781be8f19f8cd34d.png)

  

    SDR#调节到315Mhz下看到317MHZ有明显反应，同样在Gqrx上测试也是相同的。

    这样就确定了遥控器的中心频率就可以去录制信号并重放了。

    录制遥控器信号:

hackrf\_transfer –r H2oDoopLab.raw –f 317000000 –s 8000000 –n 40000000

    重放遥控器信号:

hackrf\_transfer –t H2oDoopLab.raw –f 317000000 –s 8000000–a 1 –l 40 –x 47 –R

  录制信号317MHz频率到文件H20DoopLab.raw里 指定采样率8Msps/s采样样本为40M  5乘8=40 则采样时间为5秒 在这五秒的时间内按下遥控器即可。

**四、解码捕获信号**  

 

    我们可以用Audacity来进行信号分析

![](../Images/a62ea2163c2e8875d64f0b5fcd2e91d8.png)

    或者也可以用inspectrum来进行分析

![](../Images/a7f92194d74e8d98c83e0b8f5e9e1fc8.png)

  

    以下是EV1527编码的码位波形图

![](../Images/e21121abd547833a0ce572f5bd16101a.png)

    一帧信号的编码格式为\=>8位同步码+20位内码+4位数据码

    0码, 对应1个高电平+3个低电平

    1码, 对应3个高电平+1个低电平

    同步码, 对应1个高电平+31个低电平

    也就是说

    同步码\=10000000000000000000000000000000

    0码=1000

    1码=1110

    再用inspectrum来进行分析

    Add derived plot\-->Add frequency plot

![](../Images/8defda2321fcb0f9ec2a27c663694ac3.png)

    调整位置能看出大体方波即可，然后选择第二个区域的方波右击添加阈值图。

    这样就会很清楚的看出方波的形状了，再去勾选Enable cursors√

    选择一位内码到下一位内码的宽度 如图所示:

![](../Images/130ebfaa9fa2670d9fe90d8f18b54b4c.png)

    一帧信号的编码格式为\=>8位同步码+20位内码+4位数据码，由此可知一帧信号为32位码组成，那么我们在Symbols里填入32即可，不过这里要注意，划分好之后不要将最后一位码包含在内，因为那一位码是下一帧信号的同步引导码。

    然后右击选择Extract symbols-->Copy to clipboard

![](../Images/f0eb5c85eebe10bea9d4db12d938ce7d.png)

    首先我们得到的是前八位同步码+中间20位内码+后四位数据码 我们要换算出来
