**一、背景**

* * *

    恰逢五月，我们的蜜网系统依然在辛勤耕耘，收集着世界各地活跃的病毒样本，当又一批Mayday家族病毒样本，出现于我们的蜜网视野中时，我们决定要对其认真的剖析一下啦~

    简单介绍下，Backdoor.Linux.Mayday后门病毒（后文简称Mayday），多起DDoS攻击事件的常客，2013年末就已出现，其代码模块封装十分优秀，条理清晰，使其在后续几年里衍生了多个版本，但通信协议等基本框架始终没有变化；与大多数DDoS类样本一样，Mayday的主要攻击类型包括TCP FLOOD、UDP FLOOD、ICMP FLOOD和DNS放大攻击；其在国内的僵尸控制节点分布较多，地理范围较广，具有很强的潜在破坏性，需加以警惕。

**二、行为分析**

* * *

  

    首先看一下程序运行逻辑：

    样本首先会进行初始化工作，初始化主要进行两方面的工作，一个是获取本地的机器信息，另一个是解密主控端的IP和端口。

其中获取本地机器信息为：

1.  系统版本（通过调用uname（））
    
2.  CPU核心数量及其时钟速率（取自/proc/cpuinfo）
    
3.  CPU负载（取自/proc/stat）
    
4.  网络负载（来自/proc/net/dev的带有“eth”前缀的接口的数据）
    

这些信息会初始化，保存到CStatBase对象中，具体初始化信息代码如下图：

之后是解密主控端ip和端口信息并保存到CStatBase对象：

以上两步初始化工作完成之后，会进入样本最核心的代码：CManager::StartNetProcess。该部分主要完成创建线程、组装上线包、上线和接收指令等工作，接下来将对每个核心部分进行具体分析。

1、创建线程

    创建线程，样本会创建两个线程具体的线程入口函数为CThreadHostStatus::ProcessMain和CManager::StartTaskProcess。并且开启数个CThreadAttack::ProcessMain线程。

| 线程函数 || 描述 |
| --- | --- |
| CThreadHostStatus::ProcessMain || 每个1000秒刷新一次cpu和网卡载荷 |
| CManager::StartTaskProcess || 负责管理任务队列 |
| CThreadAttack::ProcessMain || 负责从任务队列读取任务实施DDOS攻击 |

![](../Images/043c6e74b7f69c9e497aacf9aa36c88a.png)

在上述代码中，可以发现在创建线程之前初始化一个CFake对象，这个对象主要记录在DDoS攻击时需要伪造的源IP和端口。CFake会在样本运行的路径下读取fake.cfg文件，fake.cfg文件就是记录DDoS所要伪造的那些IP和端口。

fake.cfg文件的文件格式：

| 行数 || 描述 |
| --- | --- |
| 第一行 || 0或1控制位（0表示停止攻击，1表示攻击） |
| 第二行 || 发动攻击IP的范围（例如： 192.168.0.1:192.168.0.99） |
| 第三行 || 发动攻击的端口范围（例如： 8000:1000） |
| 第四行 || 域名 |

3、接收指令

    接下来主要分析接收主控端指令并解析的过程。样本会先从socket缓存中读取一个int型的数据，这个数据代表指令的主功能号。

![](../Images/a502b49788b00c0f1217d5c25ce33147.png)主要有四个功能：

| 任务号 || 执行函数 |
| --- | --- |
| 1 || ReadTask   攻击任务 |
| 2 || StopTask   停止任务 |
| 3 || ReadFake   读取伪造信息 |
| 4 || SendTaskStatus 向主控端发送状态信息 |

![](../Images/a6428843dfdcb8edf3c067edf73dfd2d.png)

1、ReadTask

    样本会创建一个CCmdMessage对象，并用ReadTask初始化这个对象，其中CCmdMessage第一个DWORD数据为控制信息，表示此项任务是否停止，1代表进行任务，2表示停止任务。

![](../Images/2e097f504fd42be47dccbbb3da6d2ecd.png)

在ReadTask中，样本会读取缓存中一个int型数据，这个数据代表后续数据的大小，并申请一块空间，来读取后续的指令数据。下图为ReadTask接收数据的代码：

![](../Images/b2f98ca764af156b82ee7c650e66d65a.png)

在接收到数据后，需要对这些数据进行解析。这里需要用到一个中转对象CMedia。CMedia将这些数据解析，并初始化为CLoopTask对象。此时CLoopTask对象内保存着进行DDoS的信息。将CLoopTask对象保存到之前创建的CCmdMessage中，到此ReadTask的主要工作完成了。

接下来是接收数据的最后一步，将CCmdMessage通过CThreadSignaledMessageList<CCmdMessage>::MessageSend保存起来。至此1号任务完成，样本会向主控端发送一个状态包，然后等待接收下一条指令。

2、StopTask

    StopTask相对简单，创建一个空的CCmdMessage，并将控制位赋值为2，表示停止任务。

![](../Images/5f78aca64322a6683d4893d4b9939d59.png)

3、ReadFake

    ReadFake和ReadTask的代码差不多，不过ReadFake会将接收到的数据通过CFake::SetFake存储起来。CFake::SetFake会更新fake.cfg文件的内容。

![](../Images/abe7387f40be5106f0458e088f9c74c9.png)

    我们之前也分析了，样本在接收到指令后会保存在CThreadSignaledMessageList中，但是CThreadSignaledMessageList中内容什么时候才会使用呢，肯定很多人对此抱有疑问。还记得我们之前遗留的两个线程吗？没错，CThreadAttack::ProcessMain和CManager::StartTaskProcess会实现接下来任务。

    CManager::StartTaskProcess从CThreadSignaledMessageList中读取一个CCmdMessage，并会判断CCmdMessage的控制位是否为1，为1则会进行下一步的工作；如果为2则代表停止任务。

![](../Images/f9e1b309004823155f9ea79f4c594524.png)

随后调用CThreadAttack::Start来添加任务，CThreadAttack::Start会将CCmdMessage中的CLoopTask对象添加到一个CLoopTask的列表中。

![](../Images/38c4096c0666a64bb12ea77e5de10d08.png)

接下就该CThreadAttack::ProcessMain出场了。CThreadAttack::ProcessMain会先判断CLoopTask的列表是否为空，如果不为空就从中取出来一个。

![](../Images/3a70743e8e9b96b43f28b8ffa9148c50.png)

解析CLoopTask对象内的指令，最终传入到CThreadAttack::PktAtk中。在CThreadAttack::PktAtk会根据不同的CLoopTask的来进行DDOS攻击。

![](../Images/e7816543d2af8ee915caaa63bb6ebdf0.png)

在CThreadAttack::PktAtk有四种DDOS攻击：

  

| 攻击号 || 说明 |
| --- | --- |
| 0x80 || TCP攻击，其中源IP和端口在fake.cfg文件中定义 |
| 0x81 || UDP，IP端口同上 |
| 0x82 || ICMP攻击 |
| 0x83 || DNS攻击，域名随机 |
| 0x84 || DNS攻击，域名在fake.cfg文件中定义 |

**三、后续**  

* * *

  

    如果你的机器不慎感染了Mayday病毒，由于其无进程守护与自启动属性，只需通过kill命令杀死Mayday进程,删除恶意样本并重新启动机器即可，同时建议关闭未应用端口，安装杀毒软件并保持更新。
