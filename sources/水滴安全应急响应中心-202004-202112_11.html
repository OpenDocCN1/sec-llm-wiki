一、目的 

水滴安全应急响应中心(后述简称:SDSRC)致力于解决属于本公司产品或服务中存在的安全漏洞。本则标准描述了SDSRC对于不同类型漏洞的奖励标准，为漏洞发现者及漏洞报告者从事漏洞发现和报告的活动提供指引。


二、适用范围

属于水滴公司及旗下所有开放在互联网的应用系统，包括:

*.shuidihuzhu.com、*.shuidihuzhu.cn、*.sdbao.com、*.shuidichou.cn、*.shuidichou.com、*.baotuitui18.com、*.shuidi-inc.com、*.shuiditech.com

*超出以上范围且确实属于水滴公司业务的漏洞，视漏洞严重、影响程度给分或忽略。

四、限制与指引

SDSRC鼓励安全研究人员积极发现并向我们报告属于我司产品或服务中的安全漏洞，但同时希望您的行为遵循《SDSRC安全测试规范（水滴SRC官网公告页及微信公众号均有公示）》以及以下要求:

1)请您不要在最低验证之外利用任何安全漏洞。

2)请您不要进行网络拒绝服务测试。

3)请您不要进行物理测试、社会工程学测试或任何其他非技术漏洞测试。

4)请不要使用awvs等相关工具进行自动化扫描。

5)请您尽量避免访问任何存储在我司信息系统内的数据，除非访问该数据为验证安全漏洞 存在的必要步骤。如您在本原则允许的测试过程中发现以下信息，请立即停止测试并及时通知我们:

a)个人识别信息;

b)金融信息(信用信息或银行账户号码信息等);

c)企业的财产信息或商业秘密;

6)请您不要在任何情况下泄露漏洞测试过程中所获知的任何数据。

7)在收到我司的明确书面授权之前，请不要公开披露或提供关于我司产品或服务安全漏洞的任何细节信息。如您无法确定能否继续进行测试，请与我们联系。

8)我们反对和谴责一切以漏洞测试为借口，利用安全漏洞进行破坏、损害水滴公司系统及用户的利益的攻击行为，我们保护追究法律责任的权利。

9）所有漏洞禁止传播，尤其是，白帽子之间禁止交流水滴业务漏洞，如有发现，扣除20安全币，情节严重者永久禁封账号

10）通常情况下，每位白帽子的SDSRC账号是其在本网站进行一切活动的唯一身份识别依据，每一个SDSRC平台账户都可以在本网站独立开展活动，但在下列情形下，SDSRC有权对一个白帽子拥有的多个SDSRC账号进行统一处理，包括但不限于：

目前SDSRC平台允许一人拥有多个SDSRC账号，各账户之间互相承担连带责任，但一个SDSRC平台账号仅能对应一人；

一个人仅能享受一个SDSRC平台账号的关于SDSRC平台的活动奖励权利，禁止一人享受其拥有的多个SDSRC账号关于水滴SRC平台的活动奖励。如有发现白帽子通过其拥有的多个SDSRC账号恶意刷积分、刷排名等恶意行为，以获取享受多个SDSRC平台账号关于SDSRC的活动奖励的，SDSRC平台有权对该白帽子以及该白帽子拥有的SDSRC账号进行警告整改、积分清零、禁封账号处理；

在符合法律法规的情况下，如果白帽子需要转让、赠予或让他人继承自己SDSRC平台的账号，SDSRC平台有权要求白帽子提供合格的文件材料并按照SDSRC平台要求的操作流程办理。


五、漏洞提交与处理流程

1. 漏洞提交:

漏洞提交者可以通过 SDSRC平台 (https://security.shuidihuzhu.com) 注册并提交漏洞，也可以发送邮件到security@shuidihuzhu.com，请在邮件主题注明“漏洞提交”，包括但不限于:漏洞的位置及潜在危害，复制该漏洞所需的步骤、脚本、保护解析代码，重现该问题的技术相关信息，可能的解决措施等。为确保信息的机密性，我们希望，当您向我们发送的电子邮件涉及敏感信息时，对该信息进行加密处理。

注：

提交报告时一定要参考报告模板，可有效提高通过率、缩短漏洞审核时间。

2. 漏洞处理流程:

3-7个工作日内完成漏洞的确认、定级、及奖励金额评测。一旦提交的漏洞被确认，漏洞 提交者可以收到相对应的安全币，可用于兑换SDSRC 平台上的所有礼品。

 

 

六、有效漏洞奖励标准 

针对漏洞提交及漏洞确认有效的贡献者，SDSRC 将给予奖励。我们采用安全币作为漏洞奖励单位，按资产的重要性及漏洞影响来计算安全币:

【核心业务】包括:水滴保险、水滴互助、水滴筹

【一般业务】包括:水滴公益

不同的安全漏洞和威胁情报，安全币发放不同(注: 1安全币=5人民币)：

计算公式：安全币=漏洞系数*业务系数+报告质量奖励

【高额奖励攻略】:

漏洞系数，获取权限越高、影响用户越多、泄露信息越严重，系数越高。

业务系数，涉及用户相关的系统如水滴筹、水滴保等，业务系数高于公司内部系统。

报告质量，漏洞复现过程越详细、修复建议越完整可落地，系数越高。

【漏洞额外奖励】:

凡是已经确认的有效漏洞所影响的系统为核心应用且漏洞等级为严重，提交人可向 SRC运营人员申请此奖励，申请后我们会结合业务方建议，对该严重漏洞进行二次综合评定，视情况额外发放价值在10%-30%的安全币。对报告质量高者酌情追加奖励。

核心系统个别漏洞影响较大，可额外获取5000-10000奖金。

【不接受的漏洞范围】:

以下范围的安全漏洞，我们可能会忽略或酌情给予奖励:

1. 对于利用条件异常苛刻或无法利用的安全漏洞。

2. 对于已由其他白帽子或公司内部提前知晓的漏洞。

3. 非指定范围内漏洞将根据实际情况酌情给予奖励或忽略。

4. 不涉及安全的问题。包括但不仅限于产品功能缺陷（如：反馈处无限提交垃圾数据）、网页乱码、样式混乱、静态文件目录遍历、应用兼容性等问题。


七、漏洞评级标准

漏洞严重性分级:

【 严重 】 

1、直接获取系统权限的漏洞。包括但不仅限于利用命令执行、代码执行、植入 Webshell、SQL 注入获取系统权限、缓冲区溢出等各类可以获取系统权限的漏洞。

2、直接导致业务系统拒绝服务的漏洞。包括但不仅限于利用漏洞或业务逻辑漏洞直接导致 系统业务不可用。

3、严重的敏感信息泄漏。包括但不仅限于核心 DB(资金、用户身份、订单) 的 SQL 注 入，可获取大量核心用户的身份信息、订单信息、银行卡信息等接口问题引起的敏感信息泄露。

4、严重的逻辑设计缺陷和流程缺陷。包括但不仅限于通过业务接口批量发送任意伪造消息、 任意账号资金消费、批量修改任意帐号密码漏洞。

【高危】 

1、敏感信息泄漏。包括但不仅限于遍历导致大量敏感数据泄露、非核心 DB SQL 注入、源代码压缩包泄漏、硬编码密码等问题引起的敏感信息泄露。

2、敏感信息越权访问。包括但不仅限于绕过认证直接访问管理后台以修改大量前台敏感信息，或利用后台弱密码、SSRF 获取大量内网敏感信息。

3、直接获取移动客户端权限。包括但不仅限于远程命令执行、任意代码执行。

4、越权敏感操作。包括但不仅限于账号越权修改重要信息、进行订单普通操作、重要业务配置修改等较为重要的越权行为。

5、任意文件读取、删除。

【中危】

1、需交互才能影响用户的漏洞。包括但不仅限于一般页面的存储型XSS、重要操作CSRF。

2、普通越权操作。包括但不仅限于不正确的直接对象引用、越权查看订单信息、越权查看 用户身份信息等。

3、普通信息泄漏。包括但不仅限于客户端明文存储密码、系统路径遍历、Github 密码泄露。

4、普通的逻辑设计缺陷和流程缺陷。 （如：对任意一个用户无限制短信轰炸。）

【低危】 

1、轻微信息泄漏。包括但不仅限于路径信息泄漏、SVN 信息泄漏、异常信息泄露，以及客 户端应用本地 SQL 注入(仅泄漏数据库名称、字段名、cache 内容)、日志打印、配置信息、异常信息等。

2、难以利用但存在安全隐患的漏洞。包括但不仅限于难以利用的 SQL 注入点，客户端密码和银行卡数据明文传输。

3、属于无危害范围但存在特殊影响的漏洞。包括但不限于难以利用的SQL注入点、综合影响较低的CSRF、URL跳转、无回显的SSRF漏洞，有一定影响的爆破，验证码绕过等。

【无危害】 

1、不涉及安全问题的 Bug。包括但不仅限于产品功能缺陷、网页乱码、样式混乱、静态文 件目录遍历、应用兼容性等问题。

2、无法利用的漏洞。无敏感操作的 CSRF(收藏、取消收藏、添加购物车、一般的资料修改 等)、无意义的异常信息泄漏、无意义的源码泄漏、内网 IP 地址/域名泄漏、无敏感信息 的越权访问、401 基础认证钓鱼。

3、不能直接体现漏洞危害危害的。包括但不仅限于未启用域名的邮箱伪造、前端或不涉及跨域的CORS漏洞。

4、不能直接反映漏洞存在的其他问题。包括但不仅限于纯属用户猜测的问题。


八、补充说明及注意事项 

1. 以下情况将不记分:

1) 与水滴公司无关的漏洞;

2) 在漏洞修复之前被公开的漏洞;

3) 网上已公开的漏洞;

4) 同一漏洞，首位报告者计分，其他报告者均不计分;

5) 以测试漏洞为理由，利用漏洞进行损害用户利益、影响业务运作、盗取用户数据等行为 的，将不计分，同时水滴公司保留采取进一步法律行动的权利;

2. 对于同一个 URL，如果多个参数存在类似的漏洞，按一个漏洞积分，不同类型的，按危害程度最大的计分。

3. 第三方产品的漏洞只给第一个提交者计分，不同版本的同一处漏洞视为相同漏洞

4. 同一个漏洞源产生的多个漏洞计算为一个漏洞。例如同一个 JS 引起的多个安全漏洞、同一个发布系统引起的多个页面的安全漏洞、框架导致的整站的安全漏洞、泛域名解析产生的 多个安全漏洞等。

5. 一个报告中提交多个漏洞，以危害级别最高的漏洞计分。

6.提交漏洞时请确认是否会对业务有真正的影响，并提交实际产生危害的证明。
