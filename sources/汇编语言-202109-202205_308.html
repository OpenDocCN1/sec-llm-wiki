日志文件是Windows操作系统中一种特殊的文件，它记录了在Windows操作系统中所发生的一切活动。例如，各种服务的启动、运行、关闭等重要信息。日志文件的大小一般为512 kB，如果文件大小超出这个范围，系统则会报错，并不再记录任何日志。


1. Windows Vista的日志


在Windows Vista的事件查看器中，日志的数目比之前Windows操作系统的日志数目增加。因为除了应用程序、安全、系统这三个传统事件日志以外，还有一些新日志。例如，安装日志（专为应用程序的安装程序而设计）、备份服务的日志WinLogon服务的日志。这些新日志存放在一个专为特定应用程序和服务创建的日志文件夹中。

Windows Vista的日志文件默认存储目录是C盘\systemroot\system32\winevt\logs。每个日志文件包括一个较小的文件头和一系列的数据块，每个数据块又包含整数条的事件记录。其中，文件头包含日志文件的一些基本信息，它常驻内存共占4096 byte，目前只使用前128 byte，其余的保留。在自动维护模式下，一旦日志文件达到最大值，系统会重命名该文件，并以原文件名创建一个新的日志文件新文件中基于日志的编号以原文件中的编号为开始，而基于文件的编号将被清零。只有在清空日志的时候，基于日志的编号才会被清零。

微软在Windows Vista中使用了全新的事件日志系统，该系统是基于XML技术的，但XML要占用大量的CPU和内存资源分析文件格式，并且有许多冗余，这就会占用较多的磁盘空间。为了解决磁盘空间使用效率的问题，微软采用了一种专有的二进制XML编码方式将事件消息从文本形式转换成二进制形式，这个转换有效地减少了占用的存储空间和处理器时间。转换过程分为三个步骤：（1）对XML语言元素进行标记；（2）通过替换机制将内容和结构分离；（3）为重复的XML结构定义模板。

在Windows Vista的日志系统中，对XML消息的频繁读取会消耗较多的资源，因此将一些语言元素转换成“记号”，可有效地节省计算资源和空间资源。这些记号分为两类：一是系统记号，二是应用程序记号。系统记号被硬编码进生成和使用二进制XML文件的程序中，为某个编号和相应的功能提供静态映射。应用程序记号表示的则是应用程序特有的实体。例如，元素名称和属性值、模板等。


2. Windows 7的日志


Windows 7有三个默认的事件日志：一个是安全事件日志，一个是系统事件日志，还有一个是应用程序事件日志。除了这些日志外，还可能会有应用程序安装到服务器上的其他日志，以及用户创建的自定义日志。例如，同Windows Vista系统一样，Windows 7系统也是基于XML技术，采用EVTX 格式的日志文件。

由于Windows 7操作系统的广泛性，可以通过登录、登出事件的实例分析展示事件日志产生某一记录的原因。

从计算机取证的角度来看，登录、登出事件作为用户使用计算机开始活动的起点和终点，是分析用户行为非常重要的环节。通过了解不同的登录方式、不同数据代表的不同含义，帮助调查者在事件日志中发现可疑的攻击行为，并能够根据其判断攻击方式。

在Windows 7系统中，用户成功登录产生的事件ID号为4624，用户登录失败产生的事件ID号为4625，可通过登录错误代码辨识具体失败原因。事件ID号4776是用户尝试登录，进行审核身份凭据产生的审核记录。

下面就Windows 7系统中本地交互式登录方式进行详细分析和说明。

本地交互式登录是最常使用的登录方式，是指用户通过本地键盘输入用户名和密码进行的登录。我们尝试两种不同的登录情况进行实验：正确用户名和密码，正确用户名和错误密码。


（1）正确用户名和密码


当尝试用户登录时，通过本地键盘输入正确的用户名和密码。登录会产生三条日志记录信息，分别为事件ID号为4776的登录审核事件、事件ID号为4648的用户尝试登录事件，以及事件ID号为4624的成功登录事件。


（2）正确用户名和错误密码


使用正确用户名和错误的密码登录时，只会产生事件ID号为4776的登录审核事件和事件ID号为4625的账户登录失败事件。具体信息如图1和图2所示。

图1  登录审核事件


图2  登录失败事件


无论登录成功还是登录失败，日志都会产生事件ID号为4776的登录审核事件这就是计算机试图验证登录用户的凭据。事件ID号为4625的登录失败事件，在用户试图访问的计算机上，当登录请求失败后日志系统记录该事件。


3. Windows 10的日志


由于Windows 8的适用性远不及Windows 10，而且两者在其事件日志上非常相近，故以Windows 10为例，讲述在Windows 10系统上如何查看系统时间篡改痕迹、USB使用记录日志。一般我们可以通过事件查看器查看系统的日志。

（1）系统时间篡改痕迹


系统时间篡改的日志可以在Windows日志中的“安全”块进行查看。在Windows 10系统上手动篡改系统时间得到的系统日志如图3所示。

图3  系统时间更改


由图3可知，该事件的ID为4616。当更改系统时间时会生成此事件。这对于Windows时间服务属正常情况，该服务以系统特权运行，定期更改系统时间。其他系统时间更改则意味着对计算机的破坏。


（2）USB使用记录日志


USB使用记录日志的查看，需要打开计算机中的注册表编辑器，进入路径 HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Enum\USBSTOR所示的位置原因是在Windows系统中，当一个USB移动存储设备插入时，会在注册表中留下痕迹。当移动设备插入计算机时，即插即用管理器PnP（Plug and Play）接受该事件，并且在USB设备的固件中查询有关该设备的描述信息（厂商、型号、序列号等）。当设备被识别后，在注册表中创建一个新的键值，这个新的键值就会存储在上述位置。
