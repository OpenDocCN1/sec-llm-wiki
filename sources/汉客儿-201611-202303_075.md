在Windows上编写命名管道服务器时候，必须能够确保安全。你会遇到一个常见的问题就是抢占命名管道，比如一个低权限的应用程序在真正的服务器之前或作为现有的服务器的新实力创建一个命名的管道服务器的时候。如果服务器用于汇集来自多个客户端的私密数据，云可能会导致信息泄露，如果条件符合设置可能导致提权。

 

有一些编程策略可以减少命名管道抢占的问题，包括将FILE\_FLAG\_FIRST\_PIPE\_INSTANCE标志传递给CreatedNamedPipe，如果管道已经存在会返回错误，以及管道的安全描述也需要适当配置。最近windows新增的管道安全前缀，使得开发一个不易被抢占的命名管道服务器变得更加容易。但是我没有找到任何官方的文档来说明如何使用这个管道安全前缀技术。似乎在WindowsInternals中简要提到了安全管道前缀，但是没有详细说明它是什么或者它如何工作的。所以这篇文章是对弥补文档缺乏做出的努力。

 

首先让我们从如何命名命名管道开始。命名管道被命名管道文件系统（NPFS）驱动导出，该驱动创建*\\Device\\NamedPipe*设备对象。你创建一个新的命名管道实例时候，你可以使用要创建的管道的完整路径调用*CreateNamedPipe*（底层实际上是*NtCreateNamedPipeFile*）。通常以*\\\\.\\pipe\\**PipeName***的格式作为管道路径，其中PipeName是你要分配的名称。在native API层，路径被转换成\\??\\pipe\\PipeName，\\??\\pipe是符号链接，最终解析到路径\\Device\\NamedPipe\\PipeName。

 

即使*\\Device\\NamedPipe*属于文件系统，NPFS也不支持跟目录以外的目录。如果你列出命名管道根目录的内容，你会注意到有些管道名称中有反斜杠（译者注：看着像是目录），但NPFS只是将它们视为名称，如下所示：

 

![](../Images/bd355074fba71693660fe461affbbebf.png)

在代码中，我们可以看到用于创建目录文件的标志被检查。如果请求目录文件，则驱动程序尝试创建或者打开命名管道前缀。我们来尝试创建一个前缀：

![](../Images/2e773d44530fece059cce138bb600be6.png)

嗯，它说它需要权限。我们深入研究一下*NpCreateNamedPipePrefix*，看看我们缺少哪些权限：  

 

*NTSTATUS NpCreateNamedPipePrefix(...){    
 // Blah blah...  
 if(SeSinglePrivilegeCheck(SeExports->SeTcbPrivilege,UserMode)){  
   // Continue...  
 }else{  
   returnSTATUS\_PRIVILEGE\_NOT\_HELD;  
 }

TCB权限只能授予SYSTEM用户，甚至管理员都没有这个权限。虽然作为管理员获取SYSTEM token并不难，更不用说LocalService 或 NetworkService账户。我们先检查一下模拟具有TCB权限的SYSTEM是否可以创建前缀：

![](../Images/e83b456385099e956419beb302b81d7f.png)

我们现在有个叫做*Badgers*的新前缀，所以让我们尝试作为一个普通的用户在该前缀下创建一个新的命名管道，看看是否有用。  

![](../Images/66dd90e964fa41c85bda3e60dd518de7.png)

我们获取到STATUS\_ACCESS\_DENIED的返回值。事实上驱动会在已经注册的最大的前缀中查找，并检查调用者是否有可以访问前缀的安全性。那么*Badgers*前缀的安全描述符是什么？  

![](../Images/ce58199765cb579082f950e2e9a08c5f.png)

看起来只有SYSTEM和Administrators用户组具有访问权限，这是基于原始调用者是SYSTEM创建的。因此，如果我们提供更加宽松的安全描述符，那么它应该允许普通用户创建管道。 

![](../Images/fbfb887918375542e5031041e189762c.png)

另一个问题，我们如何摆脱现有的前缀呢？你只需要关闭所有的前缀句柄，它就会自动消失。  

 

如上述说的，你需要TCB权限才能创建一个新的安全前缀，尤其是对于非管理员服务账户。系统是否已经创建一些前缀？NPFS中没有明显的东西。经过一些查证发现，会话管理器（SMSS）在函数*SmpCreateProtectedPrefixes*中创建了许多已知的前缀。比如：SMSS创建了以下前缀：

 

*\\ProtectedPrefix\\Administrators*

*\\ProtectedPrefix\\LocalService*

*\\ProtectedPrefix\\NetWorkService*

 

这些前缀中每个都具有基于名称账户的DACL，例如：*LocalService*中有一个DACL，它只允许LocalService用户在该前缀下创建命名管道。

 

值得注意的是，前缀的所有者是管理员组，这意味着管理员可以打开前缀并重写DACL，如果你真的想搞砸操作系统：

 

如果你正在写一个新的命名管道服务器并且你希望减少命名管道的抢占，那么可以适当地添加安全前缀阻止其他用户，尤其是低权限用户创建的新的相同名称的管道。如果有人知道关于命名管道安全前缀分析的文档在哪里，请告诉我，因为我认为这是个十分有用且知道的人很少的安全功能。
