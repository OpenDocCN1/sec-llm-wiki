# 概述    

昨天，在看雪群看到个支付宝口令（加密变换过的），莫名其妙得我居然想解开看看，难道是太爱红包，我不这样看自己，我觉得是因为自己太爱技术了，肯定是的。在解密过程中想复杂了，就按自己思路解了半天，结果死活找不到思路（其实很简单），然后就想按自己思路也搞个加密口令红包。然后才知道支付宝红包口令必须是中文或者随机数字，然后回头一看那个口令解出来了。

然后就把自己的加密口令发到群里（几个群），然后大家居然就玩开了，各种加密口令模式出来了，有base64+凯撒加密的，有二进制数据装逼的，还有js的base64+urlencode+uncode变换的，各种…

然后为了体现本公众号是一个技术公众号，我给大家也发了一个支付宝加密口令红包，想看看大家有多少是会在春节为了红包去折腾解密的技术宅的。

由于快一天了，也没人领红包，过期太浪费了，这里就说一下怎么解密的，供大家玩乐。

废话不说了，下面开始正题。

# 解密

其实加密变换思路很简单，xor+倒叙+base64，但是xor有点不一样而已。

下面从解密的角度开始分析。加密口令是`M0M0Q0I4RkUyNzAyOEYzODEwMEMzODgzNDE4OEEwMkYwODgzNDFBOENGQjgwQzMzMEY3QzBGN0NDMTQyNDQ3QzBGN0MwRjdDODE0MjQ0N0MwRUVDOENBRDQxNDI0NDdDMEE2QjlGRUIwMTQyNDQ3QzBFRUNEQjNCQzA0MjQ0N0M4RDZCOUZFQjgwNDI0NDdDOUFERDNGQ0I0MDQyNDQ3QzdDNUIwQjBCNDI0MDdDMDJDRTM4`。

现在按加密顺序倒过来开始分析。

## base64解码

其实看口令应该很容易看出是base64编码过的，随便找个在线base64解码看看就知道了。

```
>>> base64.b64decode('M0M0Q0I4RkUyNzAyOEYzODEwMEMzODgzNDE4OEEwMkYwODgzNDFBOENGQjgwQzMzMEY3QzBGN0NDMTQyNDQ3QzBGN0MwRjdDODE0MjQ0N0MwRUVDOENBRDQxNDI0NDdDMEE2QjlGRUIwMTQyNDQ3QzBFRUNEQjNCQzA0MjQ0N0M4RDZCOUZFQjgwNDI0NDdDOUFERDNGQ0I0MDQyNDQ3QzdDNUIwQjBCNDI0MDdDMDJDRTM4')
'3C4CB8FE27028F38100C38834188A02F088341A8CFB80C330F7C0F7CC142447C0F7C0F7C8142447C0EEC8CAD4142447C0A6B9FEB0142447C0EECDB3BC042447C8D6B9FEB8042447C9ADD3FCB4042447C7C5B0B0B42407C02CE38'
```

解码结果是`3C4CB8FE27028F38100C38834188A02F088341A8CFB80C330F7C0F7CC142447C0F7C0F7C8142447C0EEC8CAD4142447C0A6B9FEB0142447C0EECDB3BC042447C8D6B9FEB8042447C9ADD3FCB4042447C7C5B0B0B42407C02CE38`，这个数据其实也很容易识别和猜想，16进制数据，要么就是字符的各类编码值的变换，要么就是汇编指令（我一开始解别人的就是这个反应，因为他的口令太像汇编指令了）。但是这么长一串，不可能是口令的编码啊，因为支付宝中文口令有6-20字符的限制，那么其实就可以尝试看看是什么汇编代码了。

## 倒序

如果直接贴过去看着不像正常的汇编代码，读不通，那就应该想想这个字符有没有什么其他的变换了，比如倒序，字节取反之类的，我这里就是倒序了一次，现在倒序回来。结果是`83EC20C70424B0B0B5C7C7442404BCF3DDA9C7442408BEF9B6D8C744240CB3BDCEE0C7442410BEF9B6A0C7442414DAC8CEE0C7442418C7F0C7F0C744241CC7F0C7F033C08BFC8A143880F20A88143883C00183F82072EF8BC4C3`。

很明显，分配0x20字节的局部变量区，分多次赋值的一串数据，到`0040125B`看看数据是啥？如下，其实就是变换后的红包口令。

```
0012FF6C  B0 B0 B5 C7 BC F3 DD A9 BE F9 B6 D8 B3 BD CE E0  鞍登俭荸均敦辰梧
```

继续执行，下面就是0x20字节的数据和0xA异或，执行完后返回数据给eax，很完整的一个函数。

执行完也就看到局部变量（`0012FF6C`）中保存最后的结果了，就是原始的支付宝红包口令了。

为了不直接给大家偷懒的机会，我这里不给出直接结果了，把那段汇编转成C代码吧，给大家一个动手的机会才能领红包，不动手的同学就没法了。

当然如果有非技术同学想要口令，也可以后台回复我，我单独回复口令，或者帮助他们开启技术之路。

C代码如下：

```
char encrypt_code[0x20] = {/*上面得到的加密口令（0012FF6C）*/};
for(int i=0; i<0x20; i++) {
    encrypt_code[i] = encrypt_code[i] ^ 0xA;
}
printf("%s\n", encrypt_code);
```
