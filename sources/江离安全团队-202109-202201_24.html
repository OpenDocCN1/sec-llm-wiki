何为HTTP走私攻击？


HTTP走私攻击是一种协议层的攻击，产生原因是不同服务器之间对http请求的实现方式存在不同，导致后端服务器接收到的请求中可能夹带有走私的http请求，从而产生安全风险。



引言:Keep-Alive和Pipeline


在HTTP1.0之前版本，服务器和客户端每一次http请求都需要建立一次tcp连接，这种设计对于现代web网站来说会比较消耗资源和时间，所以在HTTP1.0之后版本中支持了长连接，在请求头中加入Connection:Keep-Alive即可，意为告诉服务器在这次请求之后tcp连接不要关闭，下次还用这个继续交流（HTTP1.1后默认支持）。

HTTP Pipeline即为http管线化，是一项实现了多个http请求无需等待响应就可以写进一个socket的技术，HTTP1.1开始支持。



引言：Content-Length和Transfer-Encoding



Content-Length和Transfer-Encoding都是HTTP报文中header中的字段，相当于服务器和客户端之间做个约定。Content-Length是告诉服务器本次发送数据body的长度，Transfer-Encoding是告诉服务器使用的传输编码，其中chunked表示输出长度不确定，服务器读取到0\r\n\r\n就认为已经读取到结尾了。





HTTP走私攻击的原理


CL不为0型


当前端代理服务器允许HTTP数据包携带请求体而后端服务器不允许时，可能会产生HTTP走私攻击风险。

GET / HTTP/1.1\r\nHost: example.com\r\nContent-Length: 44\r\n
GET / secret HTTP/1.1\r\nHost: example.com\r\n\r\n

例如发送该HTTP请求，前端代理服务器读到Content-Length(CL)为44，将下面的数据判断为一个完整的包发到后端服务器，后端服务器不对CL做处理，将下面的数据部分判断为又一个HTTP请求包，就造成了HTTP走私。


CL-CL型


RFC7230规定服务器在收到请求包中有两个CL时要返回400错误，当服务器没有严格的按照RFC7230标准实现时会产生HTTP走私风险。

POST / HTTP/1.1\r\nHost: example.com\r\nContent-Length: 4\r\nContent-Length: 3\r\n
a\r\na

例如发送该HTTP请求，假设前端代理服务器根据第一个CL判断长度为4，即a\r\n和下一行的a，后端服务器根据第二个CL处理，此时第二行的a便形成了HTTP走私，可以自行构造进行攻击利用。


CL-TE型


RFC2616规定服务器在同时接收到CL头和TE头时把CL给忽略掉，当前端代理服务器只处理CL头，而后端服务器根据RFC2616忽略掉CL按TE处理时，就会产生HTTP走私攻击风险。


POST / HTTP/1.1\r\nHost: example.com\r\nConnection: keep-alive\r\nContent-Length: 6\r\nTransfer-Encoding: chunked\r\n
0\r\n\r\na

例如发送该HTTP请求，包体中同时存在CL和TE头，前端代理服务器判断CL为6，将0\r\n\r\na看作数据，判断该请求为完整的一次HTTP请求包，后端根据TE为chunked，读取到0\r\n\r\n就当作结束，最后的a便造成了HTTP走私攻击，可以自行构造攻击利用。


TE-CL型


与CL-TE型相对应，如果前端代理服务器遵守RFC2616规定而后端服务器只对CL头处理的话也会造成HTTP走私风险。


POST / HTTP/1.1\r\nHost: example.com\r\nConnection: keep-alive\r\nContent-Length: 3\r\nTransfer-Encoding: chunked\r\n
a\r\nGET /HTTP/1.1\r\n\r\n0\r\n\r\n

例如发送该请求包，前端服务器根据TE的chunked判断7-11行都是HTTP请求携带的数据，判断为这是一个HTTP请求发给后端，后端根据CL为3，读取到a\r\n就认为结束，后面的数据便造成HTTP走私，可以自行构造攻击利用。


TE-TE型


当前端代理服务器和后端服务器都处理TE时，有时可以根据前后端服务器不同来构造一些混淆，从而造成前后端处理的TE不是同一种，产生HTTP走私攻击。


POST / HTTP/1.1\r\nHost: example.com\r\nContent-length: 3\r\nTransfer-Encoding: chunked\r\nTransfer-encoding: cow\r\n
a\r\naPOST / HTTP/1.1\r\n....0\r\n\r\n

例如发送该请求，前端代理服务器根据第一个TE头的chunked读取到最后，判断为一个完整的HTTP数据包，而后端服务器根据第二个TE头，此时后端服务器无法处理时便会又回退到根据CL头判断长度为3，读取完a\r\n就视为结束，于是后面的数据包就形成了HTTP走私，可自行构造攻击利用。
