高质量代码或将是汽车行业的又一个技术制高点

互联汽车在未来汽车产业中将是至关重要的,因为技术将高度集成到车辆的不同方面。因此，软件作者（程序猿）将承受着来自汽车制造商的巨大压力！


汽车正在“网联化”的道路上飞驰,通过网联充分发挥汽车的潜力,并将提供大大改善的安全功能。

网联汽车将能够与附近的车辆"交谈",并随时了解路况,再通过云实时呈现交通数据。据说大多数交通事故都归结于驾驶员开车的方式。事故源于错误的决定和注意力不集中,但随着人口和交通数量的增加,互联汽车将确保我们在路上保持安全。

这是大多数汽车人希冀达到的智能汽车和智慧交通系统的理想状态！然而，事务都具有两面性，网联汽车可以有很“智能”的设想，但是，也有不小的担忧：


1、（网络）安全的担忧

那些把联网汽车带给消费者的公司必须保证他们完全安全,才能获得消费者的信任和钱包。令人担忧的是,虽然依赖互联网的汽车可能会提供大幅改进的仪表板、娱乐系统、刹车、加速、灯光等,但它们可能会被黑客劫持。现实中，我们已经看到了很多这方面的例子。例如宝马修补了其ConnectedDrive服务的一个缺陷,该漏洞允许黑客远程解锁超过200万辆劳斯莱斯、迷你和宝马汽车的车门。特斯拉、克莱斯勒、大众等一众品牌，均发现过系统漏洞，有的甚至由此造成了大面积的召回。


某机构的研究人员通过创建一个虚拟手机网络来证明这一点是如何发生的。他们诱骗附近的汽车连接到它,并展示了他们如何可以拦截通信与宝马的互联驱动器和解锁车门。

虽然宝马已经修补了漏洞,向220万辆受影响的车辆发布了空中软件更新,并在车辆与宝马服务器之间的连接中添加了HTTPS加密,但它表明,互联汽车的（网络）安全性并不是一个小问题。

2、黑客攻击不是唯一的担忧

"我最担心的是应用程序。如果你能使用Android应用程序打开你的空调,喇叭和灯,这意味着其他人也可以,例如黑客,"当然，有的新势力造出来的“网联”汽车，系统“半夜唱歌”就更吓人了！谁也不知道除了“半夜唱歌”之外，还会不会干点别的。

汽车制造商没有意识到,恶作剧是汽车黑客行为的重要动机,而且这还不全是黑客行为。

 数据的完整性非常重要,即使在车辆中也是如此,因为从云中下载了大量信息,例如交通报告和汽车将记录的个人数据,例如个人淘宝账号，网络购物记录等。

网联汽车正在成为巨大的数据源。我们已经知道,在数据保护方面存在问题,例如谁拥有它。如果是汽车制造商,那么这些数据会用来干什么?


3、更高质量的软件代码必不可少

如果汽车在使用的技术方面变得越来越复杂,并最终完全依赖于互联服务,很明显,需要做些什么来使它们更安全,特别是在目前“软件定义汽车”和“传统造车思维”的较量、相互妥协阶段。

但是,为什么会发生上文的这些情况,如何实现这种安全?

像宝马这样的汽车公司都面临被网络犯罪分子利用的风险,因为软件漏洞,并可能助长网络犯罪分子的敲诈或远程汽车盗窃。而且还可能是跨国的网络犯罪行为。

因此，网联汽车需要比“互联网”更高安全级别的软件编写方法。然而,糟糕的编码质量并不总是软件编写者的错。更糟糕的情况是，即使知道如何编写高质量软件的人也并不总是这样做。这可能归结为多种因素,例如雇主要求尽快将软件推向市场的压力（例如很多造车新势力的产品开发周期明显缩短，在物理系统的实验、论证上都压缩时间，何况在“看不见”的软件系统上呢，所以今后再发生在长安街上系统升级等事件，就一点也不“奇怪”了，哈哈）。如果需要更多的时间来编写高质量的代码,那么当出现问题时,软件开发人员将来需要减少一些操作,例如发布修补程序来修复编写软件时忽略的错误。

对于消费者来说 说:"我们需要高质量的软件,因此不需要这么多的补丁。"更新软件时总是有风险的,因为随后可能会影响软件的其他部分。

现实世界里，人们必须不断修补,但持续发布软件和生产这么多补丁并不是一个可持续的长期战略。最糟糕的是,黑客侵入软件,例如互联汽车,不需要受过训练或熟练的编码器,只需要基本技能来执行黑客技术,可能会产生灾难性的后果。

四哥团队在对很多“网联”汽车App应用的APK文件进行安全性研究时，发现日常使用的软件中的漏洞,这些漏洞本应在几年前就已修复,而供应商也已经推出了补丁,但在一些汽车品牌的官方网站上并未进行更新。在看到的漏洞中,80% 实际上不应该存在,因为软件供应商已经发布了针对它们的修复程序。问题是汽车厂商的软件编写者没有采取适当的步骤来确保他们的软件是最新的。

"许多互联网业转攻网联汽车的专业人士认为,测试测试需要由公众来完成。我们是小白。汽车厂商需要对此进行评估,并防止这种情况发生"很多做第三方插件的软件外包公司保持这一观点。

对于汽车制造商来说,首先生产高质量的软件比以后解决错误要便宜得多。例如,汽车软件制造商在发布软件之前需要注意其软件的可信度,如果在内部编写 API 或许会有所帮助。

写在文末：

为了满足越来越丰富的功能安全要求，手写代码已经无法满足汽车的需求，都要采用MBD，通过仿真验证后的控制模型直接生成产品代码。如我们每个使用电脑的人都有的经验，Windows就一直都存在Bug，而汽车软件是“不允许”存在Bug，因为谁也不知道一个Bug造成的后果是不是会仅限于“半夜唱歌”或者只是在“长安街上升级”，而未知的后果很有可能是车辆失控，不按照驾驶员指令进行加速或者刹车等更加严重的后果。

但是,无论互联网的世界怎样，对于汽车来说，没有理由不实现高质量的软件代码,因为在某些领域已经使用了更高安全级别的软件代码。例如军事领域,当然这需要汽车领域的相关方付出更多的努力,并使用正式的方法。不是说每一个软件都需要如此程度的谨慎、安全和代码,但是,我们知道我们可以把车联网相关软件做的更好,所以相关方应该把它付诸实践。而对于一些系统不成熟，无缘无故就宕机、在长安街上“撒娇”等半成品的汽车软件，绝对是不负责任和对生命不尊重的表现。

当然，一些传统的跨国汽车企业在这方面似乎也并没有特别明显的优势，例如基于Windows系统的VW. OS，以Windows如此多的Bug来看，估计是理想很丰满，现实很骨感！Windows宕机了可以重启，而汽车软件发生严重后果，生命就不会给人“重启”的机会！
