# 政府网站综合防护系统攻击事件回溯关键技术研究

**摘   要：**在复杂的网络环境下，威胁系统应用安全的各种攻击越来越多。为了政府部门以及重要企业用户了解自身应用系统的弱点，同时对来自网络的攻击能够采取及时、有效的响应措施，政府网站综合防护系统（以下简称“网防G01”）使用攻击事件来完整描述每一次应用系统被攻击过程。使用事件的描述方法区别于以往使用攻击日志记录报警，使攻击更直观更清晰更可读。介绍攻击事件回溯使用的关键技术点，包括日志获取的关键技术——互动式应用程序安全测试技术，运行时应用程序自我保护技术，内核加固技术，攻击日志分析技术。“网防G01”正是因为能够在攻击的每个步骤都能获取日志，才能把日志串起来连成事件；攻击日志分析算法决定了最后事件呈现的准确性。

 

**关键词：**互动式应用程序安全测试   运行时应用程序自我保护   内核加固   日志分析   事件回溯

  

**一、引言**

随着全球互联网的发展和电子商务的兴起，网站攻击日志的数据量有了大量的增长，每天日志量上亿或者上十亿基本成为了主流，如何从海量日志中提取互相有关联的日志是当前网站攻击日志分析面临的问题之一；随着网络攻击方向和速度的快速发展，网站应用系统使用越来越多的防护手段来防御网络攻击，包括网站应用级入侵防御系统、云安全防御系统、服务器系统防火墙、服务器系统杀毒软件等，由此产生的多种攻击日志无法相互联系是当前网站攻击日志分析面临的问题之二；随着全社会分工的细化，各单位各自运行业务范围内的应用系统，各单位各自防御和分析应用系统面临的网络攻击，无法形成攻击态势预警和分析，是当前网站攻击日志分析面临的问题之三。

总的来说，政府部门和重要企业的应用系统防护通过日志记录系统被攻击的信息，造成日志量大、日志种类多、信息分散。针对一个应用，WEB应用防护系统日志、WEB服务器日志、操作系统防火墙日志、杀毒软件日志文件数量异常庞大，多种日志文件格式并存，无法把日志联系起来，描述完整攻击事件和威胁；无法了解其他应用系统的攻击情况，对网络攻击形成全面的评估分析。

因此把大量复杂的防护日志信息分析成可读性强的威胁攻击事件来促进政府部门和重要企业的应用系统修复高危漏洞；把单一的攻击事件联系起来，让网络安全监管部门评估整体的攻击态势和威胁程度，是当前面临的重要挑战。

“网防G01”在WEB应用系统的多个节点布置探针，收集攻击每一步所产生的日志，日志格式无缝对接，利用数据分析挖掘技术，从海量的日志中抽离并关联，把日志分析成攻击事件，自动回溯攻击过程，清楚直观地展示被拦截的攻击和可能的危害，帮助政府和企业快速定位并修复黑客入侵时利用的风险点。

 

**二、攻击事件回溯关键技术**

  

**（一）攻击事件回溯技术架构**

“网防G01”从网络层，系统层，内核层获取针对应用的每一步攻击痕迹，记录成日志，通过攻击日志分析算法对一次攻击进行提取和关联分析，最终回溯出完整的攻击事件，如图1所示。

 

![](../Images/b09f4d0695a1bef72d5a6b7824d44dab.png)

 

“网防G01”使用互动式应用程序安全测试（IAST）技术获取安全漏洞日志，使用运行时应用程序自我保护（RASP）技术获取网络攻击日志，使用内核加固技术获取操作系统日志，攻击日志分析算法使用网络攻击日志和操作系统日志分析提取事件，使用安全漏洞日志验证攻击事件，以此来减少系统的误报率和漏报率，最终分析出完整的攻击事件路径、危害程度以及防护措施。

“网防G01”正是因为能够在攻击的每个步骤都能获取日志，才能把日志串起来连成事件；攻击日志分析算法决定了最后事件呈现的准确性。

**（二）日志获取关键技术**

1\. 互动式应用程序安全测试（IAST）获取应用安全漏洞日志

互动式应用程序安全测试IAST( Interactive Application Security Test) ，是由美国某公司首先提出的新一代漏洞分析技术\[1\]。该技术通过使用独特设计的上下文内容( Context)关联机制将静态应用程序安全测试(SAST)与动态应用程序安全测试(DAST)技术进行结合。通过这种深度融合交互能力和差异化对比机制，可以在处于运行状态的应用程序中构建一种快速和高度自动化的漏洞分析能力。IAST 集合了静态应用程序安全测试技术SAST与动态应用程序安全测试技术DAST的优点于一体，持续不断地监视并识别应用程序中的漏洞，基于面向方面（Aspect－oriented） 的编程技术使得差异化对比机制可以在运行程序中进行动态安全分析，并且可以从活动的应用程序中提取上下文内容、数据流和控制信息，提供针对运行代码级的实际数据值的访问能力。因此，正是由于获取了这些丰富的信息，差异化对比机制可以比其他现有的安全工具识别更多的异常情况，并达到空前的精确性。通过互动式应用程序安全测试技术IAST，还能确认或排除已侦测到的漏洞是否可能被用来实施攻击，并判断漏洞来源在应用程序代码中的位置。      

“网防G01”，使用交互式扫描（IAST）技术，通过在服务端部署代理程序，收集、监控Web应用程序运行时函数执行、数据传输，并与扫描器端进行实时交互，高效、准确的识别安全缺陷及漏洞，同时可准确确定漏洞所在的代码文件、行数、函数及参数。基本实现流程如图2所示。

2\. 运行时应用程序自我保护（RASP）获取网络攻击日志

运行时应用程序自我保护（Runtime Application Self-protection），是一种应用安全保护技术，它将保护程序像疫苗一样注入到应用程序和应用程序融为一体，能实时检测和阻断安全攻击，使应用程序具备自我保护能力，当应用程序遇到特定漏洞和攻击时不需要人工干预就可以进行自动重新配置应对新的攻击。这意味着，运行时应用程序自我保护模块运行在程序执行期间，使程序能够自我监控和识别有害的输入和行为。运行时应用程序自我保护技术不同于传统的安全技术仅在网络周边或者终端设备上进行保护，它能够让应用程序具备自我保护能力。而实时是运行时应用程序自我保护技术非常重要的特点，因为拥有应用程序的上下文，它不仅可以分析应用程序的行为也可以结合上下文对行为进行分析，而且这些能持续不断的进行分析，一旦发现有攻击行为能立刻进行响应和处理。

“网防G01”将安全保护代码嵌入到运行中的服务器应用程序，在可疑行为进入应用程序时并不拦截，而是先对其进行标记，在输出时再检查是否为危险行为，从而最终实现应用程序自我保护，并尽量减少误报和漏报的概率。这对精确性要求极高的政府部门、重要企事业单位的应用程序保护尤其重要，因为这些应用程序对性能和可用性要求非常高。如图3所示。

“网防G01”使用运行时应用程序自我保护技术，对应用系统的流量、上下文、行为进行持续监控，识别并防御已知、未知威胁。能有效防御并记录SQL注入、命令执行、文件上传、任意文件读写、反序列化、Struts2等基于传统签名方式无法有效防护的应用漏洞攻击，并与互动式应用程序安全测试技术完美集成，提高准确率，减少误判漏判。

3\. 内核加固技术获取系统操作日志

内核加固技术即在操作系统核心设置一个自主可控的安全壳\[2\]，拦截威胁对资源的访问行为，防止某些软件对底层文件的修改、删除，保护操作系统安全\[3\]。

“网防G01”通过内核探针加固操作系统，提高系统自身的安全性和抗攻击能力，保护系统核心文件，如文件防篡改、禁止恶意代码执行、禁止加载没有数字签名的驱动等，通过禁止操作系统中无用的服务，提高系统安全性，同时减低系统资源占用。“网防G01”可对服务器安全配置进行全面、高效的基线检查，包括检查系统弱口令、检查克隆账户、检查计划任务等。如图4所示。

![](../Images/97b5252096ed49e9d2ec962482aa24de.png)

  

“网防G01”使用WEB入侵检测算法，对网络攻击日志和安全漏洞日志进行挖掘分析，检测攻击由WEB页面访问权限到WEB系统权限的过程；使用WEB提权检测算法，对网络攻击日志、系统攻击日志、安全漏洞日志进行挖掘分析，检测攻击由WEB系统权限提升到操作系统权限过程；使用操作系统入侵检测算法，对系统攻击日志、安全漏洞日志进行挖掘分析，检测攻击由操作系统权限进入系统内核权限的过程，最终描述出完整的威胁攻击事件全过程。

2\. 日志分析关键算法

（1）WEB入侵检测算法

属性提取：网络攻击日志中提取攻击属性（如访问频率、访问时间间隔、时间、地理位置及时区、返回字节长度、属性字符分布、属性的出现与缺失、属性字符出现频率、路径、 调用或访问顺序等），应用分类算法（如贝叶斯、决策树、SVM等）进行分类。

用户识别和会话识别：不同的IP地址视为不同用户，相同IP地址不同的客户端类型视为不同用户， 以30分钟为会话时长来识别会话。

学习阶段：使用挖掘关联规则的算法计算属性出现的频率，学习阶段建立正常行为模型，一旦正常行为模型建立好，系统就切换到检测阶段。

检测阶段：从学习阶段切换到检测阶段时，与正常行为进行比较，如果有异常行为则认为是入侵发生。如果发现敏感的关键词（如select，insert，update，<script>，exec） 则认为是 SQL注入或者CSS攻击。

确认阶段：使用安全漏洞日志确认检测到的攻击对应WEB应用程序代码位置。

预期效果：网络攻击日志检测算法能够分析WEB应用层的攻击，给出攻击者IP地址， 给出WEB应用攻击类型。

（2）WEB提权检测算法

日志提取：在网络攻击日志中，查找符合条件｛User-Agent：内容简短、版本陈旧；Referrer：空；URIs：首次出现；客户端行为特征：只访问某一个URI、一天之内同一User-Agent使用多个IP地址｝的访问日志，称为特定网络攻击日志结果集合。

属性提取：网络攻击日志中提取攻击属性（如访问频率、访问时间间隔、时间、地理位置及时区、返回字节长度、属性字符分布、属性的出现与缺失、属性字符出现频率、路径、 调用或访问顺序等），将若干属性作为多维向量的变量，应用聚类算法，找出属于离散点的日志。

主机行为：在系统操作日志中，查找特权用户的操作（如创建用户、重启进程、清除磁盘空间、读取日志等），如果有操作，给出操作时间。

结果提取：在系统操作日志中搜索在上述时间前后的管理员登录记录。如果在此时间范围内，没有管理员登录记录，则在网络攻击日志结果集合中，搜索该时间范围内的访问日志，从日志中提取URI作为算法输出结果 。

确认阶段：使用安全漏洞日志确认检测到的攻击对应WEB应用程序、WEB中间件、操系统漏洞位置。

预期效果：给出WEB提权的文件路径及文件名（即认定该文件为Webshell），疑似攻击者的IP地址或UID。

（3）操作系统入侵检测算法

日志提取：在操作系统日志中提取攻击会话日志，日志属性包括操作主体（包括进程、用户、IP）和操作客体（包括文件、端口、进程、服务、网络共享、磁盘、注册表）。

用户登入登出：从操作日志中检测其登陆操作属性（如登陆次数、登陆频率、登陆时间、登陆时间间隔、登陆用户名、登陆用户密码，登陆是否成功等），使用特征匹配算法，检测特定攻击类型。

内核资源操作：从操作日志中检测所有操作对象，掌握入侵的操作系统内核深度。

确认阶段：使用安全漏洞日志确认检测到的攻击对应操系统漏洞位置。

预期效果：给出攻击方使用的进程，对操作系统访问的文件以及操作系统漏洞位置。

**三、展望**

无论在理论还是实践方面，从日志分析到攻击事件回溯展示，对政府部门和重要企业网站的防护和修复都具有革命性意义。以多维度收集攻击日志、以攻击事件的形式完整展示“网防G01”的防护结果，将是未来的发展趋势。

“网防G01”在攻击事件回溯的基础上，分析所有安装单位被攻击的趋势和危害程度，为网络安全实施态势感知、决策的制定提供有力手段，为保卫国家重要信息系统资源发挥重要功能是“网防G01”发展的下一步方向。
