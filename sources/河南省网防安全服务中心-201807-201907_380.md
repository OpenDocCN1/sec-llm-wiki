**apk文件是安卓APP的安装文件，通过对APK文件的逆向分析可以发现一些安全或其他方面的问题，但目前市面上的APP大多已经使用了各种安全加固服务，加固的目的是出于保护APP源码及防篡改，今天由老师傅给大家简要讲一下如何对这些APK文件进行逆向分析。**![](../Images/a0d94e42560c892bae65b8158b1f8941.png)****

**试验平台：**

windows系统

Java环境

**所需环境：**

Android4.4.2 模拟器

安装xposed框架

 

**工具：**

apktool

jd-gui

dex2jar

FDex2模块

 

**工具的作用：**

apktool：资源文件的获取，可以提取图片文件和布局文件进行查看；

dex2jar：将APK反编译成java源码（classes.dex转化成jar文件）；

jd-gui：查看APK中的classes.dex转化成的jar文件，即java源码文件。

xposed框架配合FDex2模块进行脱壳，比如：360加固、腾讯乐固等。

 

**搭建环境：**

1、安装Android4.4.2 模拟器，安装后确认开启root。

这里推荐**夜神模拟器，**可以直接从官网（https://www.yeshen.com/）下载最新版本进行安装，安装模拟器的过程不再详述。安装之后启动模拟器，并确认开启了root。如下图：

  

![](../Images/2b10b950f9738fc6d20e6d227ce1a7ce.png)

 

2、安装xposed框架及FDex2模块

这两个模块的安装也是很简单的，但要注意的地方是xposed对安卓系统的版本是有要求的，要使用对应的版本。这里使用的是v32版。

 

夜神模拟器安装APK的方法有2种，一种是直接双击APK进行安装，这类需要安装模拟器的时候对APK文件类型进行了关联；第二种是将APK直接拖入到模拟器中进行安装。这些不再详述，我们使用第二种方法，直接将APK文件拖放到模拟器界面上，会自动进行安装。

 

注意安装顺序，FDex2是Xposed的一个模块，所以我们要**先安装Xposed框架**。

 

将Xposed框架APK文件拖放到模拟器，安装成功后如下图：

  

![](../Images/ce8764650cd78a9a1264f6f2d346440f.png)

  

在这里，我们要打开Xposed框架并进行配置，点击“框架”进入框架详情页面，如下图：  

  

![](../Images/7bddf2af6a6cb09c0754b391fdc6dba2.png)

  

点击“·安装/更新”，会出现root权限请求，我们选择“永久记住选择”，点击“允许”，如下图：

  

![](../Images/a787d1b0e78ff918b70cb19c28693214.png)

  

安装成功之后会看到框架里的激活下文的版本号，同时会提示重启，点击“确定”，如下图：  

 

![](../Images/838dfe56a86a344574e24c6e3755864b.png)

  

此时由于模拟器的原因可能不会自动重启，我们关闭模拟器再重新打开即可。

重新打开模拟器后我们要再进入“框架”中查看安装是否成功，如下图：

 

![](../Images/331ec3367db14ab97c6be0f2f61e7098.png)

  

接下来安装脱壳模块FDex2，安装步骤一样，将FDex2拖入到模拟器中安装。如下图：  

 

![](../Images/17b487790ef226d2e986409abc692faf.png)

  

安装成功之后如果想使用是需要先激活模块的。  

我们打开Xposed 框架，进入“模块”，选中FDex2模块即可激活。此时重启一下模拟器。

到此脱壳环境的配置基本完成。

下面我们来具体看下如何操作。

 

**操作方法：**

在这里我们随便找一个安卓的APP测试一下。

 

首先使用apktool对apk文件中的资源文件进行提取，获取AndroidManifest.xml的配置，以及一些其他的配置文件。

 

操作命令如下：

java -jar apktool.jar d-f xxx.apk OutDir

注意：xxx.apk是要反编译的APP的文件，若不加OutDir目录路径会在当前目录输出反编译后的结果。

 

如下图： 

![](../Images/eaa06394624518e182299d4d48f0506d.png)

  

APP的资源文件已经被我们提取出来了如下图，接下来我们提取dex文件并反编译。 

  

![](../Images/8636e521ddf904862e3739683ebca40c.png)

  

提取的方法也有很多种，这里我们可以直接将APP的文件扩展名改成zip进行提取dex文件，  

 

![](../Images/75ba6cf0b860cdc4c3f544a004538315.png)

  

然后我们可以使用dex2jar进行反编译，获取源代码。  

将classeds.dex拷贝到dex2jar目录下，然后按shift点击鼠标右键——在此处打开命令窗口(W)，打开的命令窗口中执行命令：

d2j-dex2jar.bat classes.dex

此时命令执行成功后会在目录下生成一个classes-dex2jar.jar文件，这个就是反编译后的java源文件，如下图：

  

![](../Images/99b347b939dc37f4b08db4ac4477b2bc.png)

  

这个就是反编译后的jar文件，可以使用jd-gui打开查看源码。

运行jd-gui，命令如下：

java -jar jd-gui-1.4.0.jar

我们使用jd-gui打开文件查看一下内容，如下图：  

  

![](../Images/0b889abbe8a9da463535c191871fd5c0.png)

  

可此时我们看到的反编译源码中只有标识为qihoo360的文件，并没有看到app相关的东西，其实这里就是使用了某数字加固才会出现这样的情况，那我们要怎么样才能看到真正的app源码呢？如果APP没有使用类似的加固的话，到了这里就可以看到APP反编译之后的源码了，但这里是使用了加固的我们该怎么做呢？好了，到了这里才正式到了我们这篇文章的重点，不卖关子让我们继续。还记得前面我们准备的模拟器的环境吧，现在就要正式上场了。

  

将我们要测试反编译的APP安装到模拟器中，点击打开我们安装好的FDex2模块，进行设置HOOK目标，点击选择我们要测试反编译的APP名字，此时会弹出输出目录，记住目录的位置，点击OK，如下图：

![](../Images/70d9f1eb7bd7b6175a14319968337010.png)

  

然后去打开APP运行一次之后，我们去输出目录中查看是否有文件输出，如下图。

![](../Images/7fdf85e41196db7943ab8b513247daf4.png)

  

我们将这些dex文件全部拷贝出来，存放到dex2jar目录下，使用dex2jar逐一的进行反编译,执行命令：

d2j-dex2jar.bat com.xxx.app.main1340496.dex

反编译后如下图：

![](../Images/7b5379db3bc2a055f53b6f93972f769f.png)

  

dex2jar.jar后缀的文件就是反编译后的文件，反编译后的代码使用jd-gui打开后就可以看到java源码了，如下图：

![](../Images/fd84860c1c1032e5fb07d75f1e95f29c.png)

  

到这里完成了加壳APP的脱壳反编译，我们可以查看APP反编译后的java源代码了。![](../Images/2df8edd48f14762240892f0374cf8bbb.png)
