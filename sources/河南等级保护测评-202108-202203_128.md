# 五眼联盟发布缓解Log4Shell 和其他与 Log4j 相关的漏洞通告

美国网络安全和基础设施安全局 (CISA)、美国联邦调查局 (FBI)、国家安全局 (NSA)、澳大利亚网络安全中心 (ACSC)、加拿大网络安全中心 (CCCS)、新西兰计算机应急响应小组(CERT NZ)、新西兰国家网络安全中心 (NZ NCSC) 和英国国家网络安全中心 (NCSC-UK) 正在发布此联合网络安全咨询 (CSA)，以提供有关解决 Apache Log4j 软件漏洞的缓解指南库：CVE-2021-44228（称为“Log4Shell”）、CVE-2021-45046和CVE-2021-45105. 复杂的网络威胁行为者正在积极扫描网络，以潜在地利用易受攻击系统中的 Log4Shell、CVE-2021-45046 和 CVE-2021-45105。根据公开报告，Log4Shell 和 CVE-2021-45046 正在被积极利用。

这些步骤包括：

*   识别受 Log4Shell 和其他 Log4j 相关漏洞影响的资产， 
    
*   一旦补丁可用，立即将 Log4j 资产和受影响的产品升级到最新版本，并保持对供应商软件更新的警惕，以及
    
*   启动追捕和事件响应程序以检测可能的 Log4Shell 漏洞利用。 
    

该 CSA 还为具有运营技术 (OT)/工业控制系统 (ICS) 资产的受影响组织提供指导。

Log4j 是一个基于 Java 的日志库，用于各种消费者和企业服务、网站、应用程序和 OT 产品。这些漏洞，尤其是 Log4Shell，非常严重——Apache 在通用漏洞评分系统 (CVSS) 中将 Log4Shell 和 CVE-2021-45046 评为严重，将 CVE-2021-45105 评为高。这些漏洞很可能会在很长一段时间内被利用。CISA、FBI、NSA、ACSC、CCCS、CERT NZ、NZ NCSC 和 NCSC-UK 强烈敦促所有组织应用缓解部分中的建议。 

CISA、FBI、NSA、ACSC、CCCS、CERT NZ、NZ NCSC 和 NCSC-UK 鼓励组织领导人查看 NCSC-UK 的博客文章Log4j 漏洞：董事会应该问什么？，有关 Log4Shell 对其组织的可能影响以及响应建议的信息。

**注意：**这是一个不断发展的情况，正在发现新的漏洞。CISA、FBI、NSA、ACSC、CCCS、CERT NZ、NZ NCSC 和 NCSC-UK 将在我们了解有关此漏洞的更多信息并提供进一步指导时更新此 CSA。

### 技术细节

#### **Log4Shell**

Log4Shell于 2021 年 12 月 10 日披露，是一个远程代码执行 (RCE) 漏洞，影响 Apache 的 Log4j 库，版本 2.0-beta9 到 2.14.1。该漏洞存在于 Java 命名和目录接口 (JNDI) 用于解析变量的操作中。受影响的 Log4j 版本包含 JNDI 功能（例如消息查找替换），这些功能无法抵御攻击者控制的轻量级目录访问协议 (LDAP)、域名系统 (DNS) 和其他 JNDI 相关端点。 

攻击者可以通过向易受攻击的系统提交特制的请求来利用 Log4Shell，导致该系统执行任意代码。该请求允许对手完全控制系统。然后，攻击者可以窃取信息、启动勒索软件或进行其他恶意活动。

#### **CVE-2021-45046**

CVE-2021-45046于 2021 年 12 月 13 日披露，使远程攻击者能够在某些非默认配置中导致 RCE、拒绝服务 (DoS) 条件或其他影响。此漏洞影响从 2.0-beta9 到 2.12.1 和 2.13.0 到 2.15.0 的所有 Log4j 版本。作为回应，Apache 发布了 Log4j 版本 2.16.0（Java 8）。

#### **CVE-2021-45105**

2021 年 12 月 16 日披露的CVE-2021-45105使远程攻击者能够在某些非默认配置中引发 DoS 条件或其他影响。根据 Apache 的说法，当日志配置使用带有上下文查找的非默认模式布局（例如，`$${ctx:loginId}`）时，控制线程上下文映射（MDC）输入数据的攻击者可以制作包含递归查找的恶意输入数据，从而导致a`StackOverflowError`将终止进程。作为回应，Apache 发布了 Log4j 版本 2.17.0（Java 8）。

#### **影响**

Log4Shell 和 CVE-2021-45046（被 Apache 评为严重漏洞）非常严重，因为 Java 在 IT 和 OT 平台上广泛使用，它们很容易被利用，并且应用缓解措施是资源密集型的。Log4Shell 尤其重要，因为它允许恶意行为者在易受攻击的网络上远程运行代码并完全控制系统。 

根据公开报道，Log4Shell 的利用始于 2021 年 12 月 1 日或前后，并且该漏洞的概念验证漏洞已公开可用。联邦调查局观察到有人企图利用和广泛扫描 Log4j 漏洞来访问网络以部署加密挖掘和僵尸网络恶意软件。FBI 评估此漏洞可能被复杂的网络威胁行为者利用，并被纳入正在寻求采用越来越复杂的混淆技术的现有网络犯罪计划。根据公开报告，CVE-2021-45046 也正在被积极利用。 

CISA、FBI、NSA、ACSC、CCCS、CERT NZ、NZ NCSC 和 NCSC-UK 评估这些漏洞的利用，尤其是 Log4Shell，可能会增加并在很长一段时间内持续下去。鉴于漏洞的严重性和可能增加的漏洞利用，CISA、FBI、NSA、ACSC、CCCS、CERT NZ、NZ NCSC 和 NCSC-UK 强烈敦促所有组织应用缓解部分中的建议，以识别、缓解和更新受影响的资产。

有关这些漏洞的更多信息，请参阅Apache Log4j 安全漏洞网页。 

### 缓解措施

#### **供应商**

CISA、FBI、NSA、ACSC、CCCS、CERT NZ、NZ NCSC 和 NCSC-UK 鼓励供应商：

1.  **立即识别、缓解和更新受影响的**使用 Log4j 的**产品**到最新的修补版本。
    

1.  对于使用 Java 8 或更高版本的环境，升级到 Log4j 版本 2.17.0（2021 年 12 月 17 日发布）或更高版本。
    
2.  对于使用 Java 7 的环境，升级到 Log4j 版本 2.12.3（2021 年 12 月 21 日发布）。**注意：** Java 7 目前已停止使用，组织应升级到 Java 8。
    

3.  **将包含这些漏洞的产品告知您的最终用户，**并强烈敦促他们优先考虑软件更新。CISA、FBI、NSA、ACSC、CCCS、CERT NZ、NZ NCSC 和 NCSC-UK 强烈建议供应商采取措施确保软件更新的消息传递给尽可能广泛的受众（例如，避免将相关信息置于付费墙后面）。**注意：** CISA 正在积极维护一个GitHub 页面和存储库，其中包含已知受 Log4Shell 影响的产品的补丁信息。CISA 还通知了可能受到影响的 ICS 供应商，并要求他们确认受 Log4Shell 影响的任何资产并应用可用的缓解措施。

*   从网络中物理移除资产（例如，拔下网络电缆）；

1.  请参阅步骤 3.A.(4) 中列出的利用和检测资源。
    
2.  请注意，有多种方法可以混淆漏洞利用字符串。不要一直依赖一种检测方法来工作。
    

   C. **继续监视Apache Log4j 安全漏洞网页以获取新的更新。注意：**由于这是一个不断发展的情况，并且正在发现 Log4J 中的新漏洞，组织应确保其 Apache Log4j 是最新的。确定您的企业使用的软件并掌握更新，因为这些可能会被其他更新和修复所取代。

   D.  **阻止特定的出站传输控制协议 (TCP) 和用户数据报协议 (UDP) 网络流量。**

1.  **出站 LDAP：**对于大多数网络，LDAP 在内部使用，但很少将 LDAP 请求路由到网络外部。组织应阻止出站 LDAP 或将出站 LDAP 使用许可名单到已知的良好目的地。**注意：**如果没有执行应用层过滤的防火墙，这可能很难在某些端口上检测到。 
    
2.  **远程方法调用 (RMI)：**对于大多数网络，RMI 要么未使用，要么用于内部源。组织应阻止出站 RMI 或使用允许列表将出站 RMI 列入已知良好目的地。
    
3.  **出站 DNS：**使用企业 DNS 解析的组织可以阻止来自已识别 DNS 解析器以外的来源的出站 DNS。至少，阻止来自配置为使用企业 DNS 解析的 Web 应用程序服务器的直接出站 DNS 将降低这些系统的风险。
    

**注意：**由于来自非恶意研究人员和供应商的大量扫描，在此事件期间阻止攻击者 Internet IP 地址很困难。IP 地址的误报率很高。组织应该专注于寻找成功利用的迹象，而不是扫描。

**拥有 OT/ICS 资产的受影响组织**

由于 Apache Log4j 软件库的普遍性以及该库在运营产品中的集成，CISA、FBI、NSA、ACSC、CCCS、CERT NZ、NZ NCSC 和 NCSC-UK 强烈建议 OT 资产所有者和运营商审查其运营架构并根据当前产品警报和建议列举漏洞状态。如果产品没有专门针对漏洞状态的安全公告，请对其进行额外保护。CISA、FBI、NSA、ACSC、CCCS、CERT NZ、NZ NCSC 和 NCSC-UK 敦促修补或部署缓解措施，以降低这些漏洞威胁的风险。 

**注意：** CISA、FBI、NSA、ACSC、CCCS、CERT NZ、NZ NCSC 和 NCSC-UK 建议优先修补 IT 设备，尤其是那些具有互联网连接的设备。受影响的面向互联网的设备以及笔记本电脑、台式机和平板电脑特别容易受到这些漏洞的利用。OT/ICS 设备——如果从 IT 环境中适当地分割出来——不会面向互联网，因此，对这个漏洞的攻击面更小。如果没有足够的网络分段来防止横向移动，则利用 IT 设备可能会影响 OT/ICS 设备。 

CISA、FBI、NSA、ACSC、CCCS、CERT NZ、NZ NCSC 和 NCSC-UK 建议 OT/ICS 资产所有者/运营商考虑以下指南：

1.  **审查运营架构并根据当前产品警报和建议列举漏洞。**如果产品没有专门针对其漏洞状态的安全公告，则建议对这些设备进行额外保护。 
    
2.  **实施上一节中列出的步骤，以识别和隔离**OT/ICS 环境中的**易受攻击的资产**。了解 OT 环境中的哪些类型的产品会受到影响。许多 OT/ICS 特定的产品都包含了 Log4j 库的易受攻击版本。
    
3.  **使用风险知情的决策过程，在**操作可行的情况下尽快**将最新版本的修补程序或补丁**应用于受影响的设备。如果无法应用补丁，则应部署产品制造商或经销商提供的缓解措施。**注意：**作为质量保证，CISA、FBI、NSA、ACSC、CCCS、CERT NZ、NZ NCSC 和 NCSC-UK 建议用户在安装前在反映其生产环境的测试开发环境中测试更新。 
    
4.  **尽量减少所有控制系统设备和/或系统的网络暴露**，并确保它们无法从 Internet 访问。
    
5.  **定位防火墙后面的控制系统网络和远程设备，并将它们**与业务网络**隔离**。
    

当需要远程访问时，请使用安全方法，例如虚拟专用网络 (VPN)，认识到 VPN 可能存在漏洞并应更新到可用的最新版本。还要认识到 VPN 的安全性取决于其连接的设备。 

CISA、FBI、NSA、ACSC、CCCS、CERT NZ、NZ NCSC 和 NCSC-UK 还提醒组织在部署防御措施之前进行适当的影响分析和风险评估。

钢协也提供了部分控制系统的安全建议的做法对上cisa.gov的ICS网页。一些推荐的实践可供阅读和下载，包括使用深度防御策略改善工业控制系统网络安全。

在 cisa.gov上的ICS 网页上，技术信息文件ICS-TIP-12-146-01B--Targeted Cyber Intrusion Detection and Mitigation Strategies中公开了其他缓解指南和推荐做法。

观察到任何可疑恶意活动的组织应遵循其既定的内部程序并考虑立即报告危害。
