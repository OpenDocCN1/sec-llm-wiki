为 IT 系统管理员提供有关如何管理和保护智能手机、平板电脑、笔记本电脑和台式 PC 上的固件的建议

所有现代设备都包含对设备安全功能至关重要的固件。

本文将帮助解如何管理设备上的固件，还提供了有关可以采取哪些步骤来管理任何相关安全风险的建议。

* * *

## 为什么要管理设备固件？

固件通常是执行构成平台的硬件组件的配置和控制的代码。因此，固件通常是设备开机时运行的第一个代码，因此提供了建立系统信任的基础。

固件在设置许多保护设备和操作系统所需的保护方面也发挥着重要作用。这包括配置硬件安全设置、验证启动和移交给操作系统。

尽管固件攻击必须具有高度针对性，但成功的攻击可以提供长期、持续的访问或本质上具有破坏性。结果可能包括数据丢失、系统修改或永久拒绝服务。

* * *

## 固件管理准备

在规划管理制度时，您应该牢记固件管理的几个方面。

### 固件更新

固件更新允许将错误修复、新功能和安全更新应用于设备。因此，它们是使设备保持最新状态的基本要素。

您需要考虑您的组织将如何部署和管理固件更新。手机（包括 Android 和 iOS）通常会在操作系统和软件更新的同时打包和分发固件更新。如果您已经遵循保持设备最新的建议，那么固件更新应该是理所当然的。

在笔记本电脑和 PC 上，对自动固件更新的支持将因设备、制造商和操作系统而异。如果设备不支持将自动更新作为操作系统更新机制的一部分，那么您需要考虑哪些移动设备管理 (MDM)服务或企业工具可用于自动化和分发固件更新。

### 固件设置

设备固件将具有可以修改的设置，以配置整个系统的功能。某些固件设置（例如*安全启动*和*启动路径*）对于设备的安全运行至关重要。其他允许设备的功能控制，例如，启用或禁用麦克风，或管理对外围接口的访问，但仍可被视为安全设置。

在移动电话上，通常不需要单独管理固件设置，而在台式机和笔记本电脑上可能需要。设置可能必须通过本地固件管理控制台、移动设备管理 (MDM) 或自定义企业管理工具进行独立管理。

在所有情况下，修改关键固件和引导设置的能力仅限于管理员，这一点很重要。

### 固件监控  

应该考虑组织使用的设备上可用的固件日志记录和监控功能。

有效的日志记录和监控可以包括信息和事件，例如：

*   固件版本
    
*   修改设备固件设置
    
*   固件更新事件
    
*   设备固件设置的合规性
    
*   开机状态
    
*   开机测量
    

实际上，许多设备对记录这些类型的事件的支持非常有限。

在台式机和笔记本电脑上，支持会有所不同。某些设备可能能够提供有关固件的基本反馈。例如，在 Chromebook 上，移动设备管理可用于强制执行设备报告，其中包括固件和启动状态信息。

也可以使用其他企业管理工具或服务来生成自定义日志。例如，在 Windows 上，可以使用基于代理的管理工具（例如System Center Configuration Manager (SCCM)或Azure 日志分析）来部署和报告自定义设备合规性规则或生成自定义日志。

设备制造商还可以提供可以扩展日志记录功能的单独工具或功能。HP Sure Start就是一个例子。惠普商用笔记本电脑上提供的这种增强型固件保护系统可以为固件相关的安全事件生成额外的 Windows 事件日志。然后可以使用Windows 事件转发或您选择的日志代理将这些日志转发到远程存储，作为设备日志记录和监控过程的一部分。

### 固件弹性

某些设备将支持针对固件代码和关键配置数据的增强保护，以防止攻击或损坏。通常，这些设备将使用单独的硬件支持*的信任根*和密钥存储来提供更强大的固件代码和数据加密验证以及安全恢复。

在移动电话上，在许多情况下，这些保护措施是标准内置的。在台式机和笔记本电脑上，这些类型的增强保护通常取决于制造商、设备和硬件支持。示例包括Windows 上的HP Sure Start和 Intel Boot Guard，以及macOS 上的T2 安全芯片。在选择在您的组织中使用哪些设备时，您可以考虑这些要求。

## 如何管理设备固件

  

您的组织可能会使用不止一种类型的设备，从台式机和笔记本电脑到手机和平板电脑。这些可能涵盖一系列硬件制造商和操作系统。对于这些设备中的每一个，您应该执行以下操作：

*   确定哪些固件管理功能可用于您正在使用的设备和管理基础设施。在选择在您的组织中使用哪些设备时，请记住这一点。
    
*   制定流程以保持设备固件最新，并在可能的情况下实现自动化。检查操作系统的自动更新系统是否也可以更新固件。如果不能，请设置设备制造商专有的自动更新服务（如果有），或使用企业管理工具自动更新固件。
    
*   必要时，启用和配置关键设备安全设置，例如安全启动、允许的启动路径和经过身份验证的更新。您还应该应用组织的设备配置策略所需的任何其他设置，例如启用/禁用麦克风。在可能的情况下，使用您的移动设备管理服务强制执行设备固件设置。如果不支持，则可能需要单独的制造商提供的企业管理工具进行远程管理。作为最后的手段，可能必须通过本地设备管理控制台配置设置。
    
*   限制对本地和远程管理界面的访问。这将有助于防止对设备设置或设备固件进行未经授权的更改。
    
*   在可能的情况下，记录和监控设备固件的状态以及相关的安全事件。在可能的情况下，应首选设备健康证明以验证设备的状态。我们的记录和监测指导提供了可用的平台升的具体建议ogging和监督机制，包括认证服务，在某些情况下可以帮助监控固件的完整性。
    
*   要求其固件具有更高弹性的组织应该更喜欢提供更强的固件代码完整性保护和关键安全设置、危害/篡改检测以及在未经授权的更改或损坏的情况下安全恢复设备固件的能力的设备。在您的组织中选择要使用的设备时，请记住这些因素。
    
*   确保您的用户可以识别可能表明固件被篡改或损坏的设备警告类型。为用户报告事件制定政策。
    

在实施上述建议时，每个平台的流程都不同。我们在下面列出了其中的一些差异，并在相关时提供了一些特定的平台建议。

### 固件更新

在 Android 和 iOS 等设备上，固件更新通常会自动应用，作为更广泛的操作系统更新的一部分。

但是，在运行 Windows 和 Linux 操作系统的 PC 和笔记本电脑上，对自动固件更新的支持会有所不同。为了帮助解决这个问题，我们在下面为这些平台提供了一些具体建议。

### 固件设置

在许多设备上，例如 Android 和 iOS，不需要单独管理设备固件设置。

但是，组织应用关键设备安全设置来强制执行经过验证的启动模式仍然很重要。这可以使用MDM来实现。

在 Windows 和 Linux 设备上，许多固件设置可能必须在操作系统设置之外进行管理。这包括关键的安全设置，例如安全启动和允许的启动路径。对远程管理的支持会有所不同。

我们在下面提供了一些特定于平台的建议。

| 操作系统 || 推荐 |
| --- | --- |
| 安卓 || 应禁用开发人员选项以防止解锁设备引导加载程序和调试功能。 |
| --- | --- |
| 苹果系统 || 应设置 EFI 密码以防止对特定系统上的固件设置进行意外修改。 |
| 操作系统 || 应强制执行验证模式以防止用户将设备切换到开发人员模式。 |
| Linux || 可配置的设备设置因设备类型、型号和制造商而异。至少，它们应该通过设备预启动固件管理控制台进行管理。有关推荐的安全设置的指南，请参阅Linux 平台特定指南的固件部分。 |
| Windows || 可用设置因设备类型、型号和制造商而异。至少，固件设置应通过设备预启动固件管理控制台进行管理。各种选项也可用于远程管理，包括MDM或单独的制造商企业管理工具。有关推荐设置的指南，请参阅我们的Windows 平台特定指南的设备固件部分。作为Windows 硬件兼容性计划的一部分，OEM 应默认启用其中的许多设置。 |
