Ubuntu LTS

本指南最后在 2020 年 4 月 23 日发布的 Ubuntu 20.04 长期支持 (LTS) 版上进行了测试，但它可能与其他版本的 Ubuntu 相关。此版本在公共支持下一直支持到 2025 年，在 2030 年之前作为付费选项提供支持。

一般建议

对于 Ubuntu 设备的企业部署，您应该：

  • 决定您的组织将使用哪些 Ubuntu 设备。应考虑具有 TPM 2.0 和 DMA 保护的 Ubuntu 认证硬件设备。

  • 使用推荐的网络架构之一来启用对企业服务的远程访问。

  • 使用自动化部署和软件配置管理 (SCM) 服务在您的 Ubuntu 设备上配置、监控和实施技术控制。对于小规模部署，通过使用预播种脚本手动预播种安装程序并运行安装后脚本进行部署就足够了。对于中大型部署，请考虑实施预引导执行环境 (PXE)，它会自动在客户端设备上安装 Ubuntu。相同的种子前和安装后脚本可用于使用 SCM 系统注册设备，以确保完全自动化的配置。可以创建签名包以推送安全配置设置和批准的应用程序。这些可以上传到自定义存储库，该存储库可以托管在同一 SCM 服务器上。

  • 配置Ubuntu 的任何日志记录和监控功能。虽然 Ubuntu 没有可用的本地远程擦除功能，但可以使用 SCM 系统（例如Puppet、Chef或Ansible ）实现远程擦除功能。

  • 考虑您是否将在 Ubuntu 上部署防病毒或其他安全软件，因为存在一些试图检测此平台恶意代码的第三方反恶意软件产品。但是，当按照本指南中的建议进行配置时，Ubuntu 本质上提供了一些防止恶意代码运行的保护。此外，在可用的情况下，AppArmor配置文件会限制应用程序对平台的访问。如果需要，可以将其他应用程序配置为使用 AppArmor。最后，Snap 应用程序在受限沙箱中运行。

设备配置

一旦您选择了您的部署方法、架构和应用程序构建，您应该开发一个设备配置，您可以应用该配置来实施您的技术控制。特别是，您应该包括管理以下各项的策略：

  • 使用生物识别技术（如果可用），以及密码和身份验证策略。我们建议您在保护用户帐户时参考我们的密码指南。大多数用户应该拥有没有管理权限的帐户。需要管理权限的用户应使用单独的非特权帐户进行电子邮件和 Web 浏览。建议本地管理员帐户为每台设备设置一个唯一的强密码。

  • 安全启动。Ubuntu 会验证启动过程，但不会验证所有与启动相关的文件是否被篡改。可以通过以下方式获得安全利益：

    • 在不支持传统 BIOS 和传统引导选项的情况下配置 UEFI，并确保启用安全引导

    • 配置 UEFI 管理/设置密码，以便无法更改 UEFI 配置

    • 安装后，禁用从外部媒体启动

    • 配置 GRUB 密码以防止运行时更改 grub2 配置

    • 确保 Ubuntu内核锁定在完整性模式下保持启用状态。通过将保护模式设置为机密模式可以获得进一步的保护，但应该进行进一步的测试以确保这不会中断您组织部署的应用程序的执行

  • 配置 LUKS/dm-crypt 磁盘加密设置以提供全卷加密并防止使用物理攻击提取数据

  • 外部接口保护，例如在锁定时禁用新存储设备的安装

  • 应用程序允许列表。不应允许用户在设备上安装任意应用程序。第三方应用应由管理员授权并通过可信机制部署，例如 Ubuntu Landscape。或者，您可以使用Puppet、Chef或Ansible等工具 来管理设备上的软件安装。可以在安装时配置权限以确保用户无法从他们可以写入的任何磁盘分区执行应用程序。所有应用程序安装都应由管理员执行

  • 自动操作系统和应用程序更新。操作系统安全更新可以配置为自动应用。使用推荐的软件更新设置，当设备开启并完全启动时，应用程序更新会自动安装。默认情况下，Snap 应用程序每天检查更新四次。为了确保安装 Snap 软件包不会对您系统的安全状况带来任何风险，我们建议仅从授权的 Ubuntu 商店和受信任的开发人员处安装 Snap 软件包。此外，Canonical LivePatch 可以配置为在运行时动态修补内核，否则内核更新仅在重新启动时有效

  • VPN软件如strongSwan VPN可以如果使用客户端的虚拟专用网络（VPN）是必需

  • 基于主机的防火墙。应启用并配置防火墙以阻止传入连接。可以根据您的设备使用情况和安全要求定义更细粒度的策略
