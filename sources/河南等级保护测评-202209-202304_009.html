本月，我们将深入研究上传到 PyPI 注册表的一系列被识别为信息窃取者的恶意包，其中一些是我们一直在跟踪的流行 W4SP 窃取者的副本。我们还将探索一个名为reverse-shell的恶意程序包，它是全球恶意软件即服务 (MaaS) 计划的一部分，以及 OpenAI 经历的一次数据泄露事件，导致西方国家首次禁止 ChatGPT。 

从数量上看，3月份我们一共抓到了6933个恶意包。 

我们在 npm 上捕获的一些节点包，例如segment-js-sdk、product-api-ts-axios-sdk和account-api-ts-axios-sdk，在范围12build下发布，包含轻微混淆的代码将环境变量泄露到“pipedream.net”地址的文件build.js 。其他软件包，包括ibd-ui-component-library、fortnox-react、otc-trading-desk、payments-js、f0-content-parser和typeahead-client-logger遵循完全相同的模式。在 PyPI 方面，我们想更深入地研究我们发现的最新信息窃取者：微软助手和反向外壳。 

了解有关恶意软件安全领域的最新消息和见解，以及如何正确保护团队的构建环境免受潜在风险的影响。

W4SP 的模仿者没有休息

在我们对上传到 PyPI 注册表的一系列恶意包进行初步报告后，我们调查并确定为信息窃取木马，之后我们观察到这种趋势在整个 3 月份持续存在。我们谈论的这些软件包是流行的 W4SP 窃取程序的模仿者，这是开源软件供应链的持续风险。

这些类型的软件包令人担忧，因为它们对可能无意中下载和安装它们的开发人员构成严重威胁。鉴于所涉及的潜在危险，我们将它们报告给了 PyPI 团队，他们迅速而熟练地解决了这些问题。尽管如此，我们还是想深入研究并事后分析其中一个恶意软件包，以便更好地了解它们的运作方式。

带着我们的手套和手术器械，让我们更深入地研究一个名为microsoft-helper的包的复杂性，然后我们将检查它的近亲pyezstyle，它只会短暂出现。

通常情况下，不良行为者会在setup.py中添加一行，以便开发人员在运行pip install时部署恶意软件。 

该软件包的名称microsoft-helper可能是不良行为者试图掩饰其恶意性质，其目标可能是将其添加为他们已经拥有的流行软件包的依赖项。然而，作者的名字，由缩写组成，甚至没有试图假装它来自合法作者：

当开发人员无意中执行 payload 时，它会从 URL https[:]//paste[.]bingner[.]com/paste/rg8v8/raw获取包含第二阶段 payload 的远程脚本。在撰写本文时，该 URL 处于活动状态。然而，Discord webhook——与我们分析过的其他模仿者不同，它被移到了代码的顶部——返回一个带有“代码：10015”错误消息的 JSON 文件，表明该 webhook 现在无效或已过时。

所以现在让我们换一个包：几乎重复的pyezstyle。如果我们比较两个第二阶段的有效负载，只有一个区别：Discord webhook URL：https[:]//discord[ . ]com/api/webhooks/1087680971081519124/FAYiwvOu4N_raBxx6JAs9GQHtjLBqJK6yBJXKXlHi5xJ2g3QKtxLQDqe_lysFBYUL 这个没有返回错误消息，通过查看 guild_id ，我们发现该频道是在 2023 年 3 月 21 日创建的。所以这是一个仍然活跃的频道。 

无论如何，就是来自pyezstyle 的它，我们告诉过你它只会短暂出现，所以让我们切换回microsoft-helper。

我们注意到的另一件事是，不良行为者修改了我们最初访问的第二阶段有效载荷。这是一种众所周知的做法：除了使恶意代码不那么明显之外，添加第二阶段有效负载还可以提供更大的灵活性，因为修改代码更容易，而无需从头开始重做所有事情。

在microsoft-helper中，我们见证了名称“Fade Stealer”（本身是 W4SP 窃取程序的山寨版）如何被修改为“EVIL$ Stealer”。在“Satan Stealer”、“ANGEL Stealer”、“Leaf $tealer”、“@skid STEALER”、“Fade Stealer”、“Celestial Stealer”和“Creal Stealer”之后添加到模仿信息窃取者列表中的新名称” 这是副本的副本。 

西班牙小队进入MaaS市场

如果您是仔细阅读 PyPI 注册表的软件开发人员，那么当您偶然发现一个名为reverse-shell的包时，您会三思而后行。当然，你不会故意pip install以攻击技术命名的东西——除非你兼任安全研究员，在那种情况下，我们确信你会在虚拟机的安全范围内寻找. 

那么为什么有人会以如此明显的方式命名恶意包呢？不良行为者通常通过以流行的库或公司名称命名他们的包来隐藏他们的意图，所以当我们的安全研究人员发现这个时，它是令人不安的。这里没有拼写尝试。没有依赖性混淆。也许这些坏演员只是在试水别的东西…… 

当我们查看setup.py时，我们发现了一些更奇怪的东西：西班牙语中类似教程的详细注释。“克隆 GitHub 存储库并执行文件”，“替换为你的 GitHub 存储库的 URL”，“你想要克隆存储库的路径”，等等。看起来我们要么是针对初学者的黑客教程，要么是针对初学者的 MaaS 产品。西班牙语市场。 

属于名为“ NotInfected ”的用户的代码中引用的存储库 URL 不再处于活动状态。但与此代码关联的另一个回购协议目前仍处于活动状态。我们会在适当的时候透露该回购协议的名称，所以请耐心等待。

尽管包reverse-shell乍一看并没有恶意，但它从 GitHub 执行的文件bypass.py以及随后的WindowsDefender.py只不过是恶意的。

在公共存储库上托管恶意文件可以让不良行为者更好地控制它们。它赋予他们删除、升级甚至对有效载荷进行版本控制的能力。 

bypass.py就是这种情况。该代码有一些轻微的混淆，可能是为了逃避静态代码分析工具或只是对开发人员隐藏恶意代码： 

他们将脚本编码为一系列数字，这些数字对应于所述脚本中字符的 ASCII 代码。然后使用.join()方法将这些代码连接在一起。通过简单地更改print的exec方法，突然显示了人类可读的代码：

该代码将函数add_to_startup定义为持久性访问机制：它将应用程序添加到 Windows 注册表，以便它在每次 Windows 启动时自动启动。它还将文件WindowsDefender.py（托管在 NotInfected 的 GitHub 上）添加到 Windows 启动文件夹，并为该文件构建正确的路径。最后，它使用subprocess.run()来执行WindowsDefender.py脚本。

好的，那就是bypass.py中的内容。让我们探索WindowsDefender.py看看它能带我们去哪里。 

通过上述相同的去混淆方法后，静态分析揭示了 Python 代码的恶意。教程部分消失了——这次没有详细的评论——所以这个不应该被他们的 MaaS 客户修改。 

我们在这里处理的是“信息窃取者”：一种旨在泄露敏感信息的恶意软件。它是这样工作的：

get_token () 函数检索存储在各种 Web 浏览器的本地存储中的 Discord 身份验证令牌，并尝试使用主密钥对其进行解密。其他函数，包括get_login_data()、get_web_history()、get_downloads()、get_cookies() 和 get_credit_cards()，在将所有信息发送到 Discord 通道中的 webhook 之前执行其名称所暗示的内容。 

从网络浏览器抓取数据后，代码使用 Python 图像库 (PIL) 中的ImageGrab.grab()函数截取用户桌面的屏幕截图。屏幕截图保存到临时目录并上传到同一个 Discord webhook。

该代码还会检查用户系统上是否安装了 Steam 游戏平台。如果是这样，它会压缩 Steam 安装目录中的配置目录和任何 SSFN 文件（身份验证令牌）。然后将压缩文件上传到 Discord webhook，攻击者将拥有控制 Steam 帐户所需的一切。 

如您所见，它检查了所有复选框以寻找复杂的信息窃取器。在代码中，我们还发现了文本字符串，表明这背后的参与者可能是一个名为 SylexSquad 的组织：

还记得我们之前提到的那个仍然活跃的回购协议吗？它属于 SylexSquad。我们刚刚讨论的两个文件都存放在那里。  

一些 OSINT 研究表明，该组织是 Sellix 平台上一个现已不复存在的黑客市场的幕后黑手，该市场于 2022 年活跃。 

与其他销售信息窃取器的团体一样，他们使用 YouTube 通过快节奏、嘻哈/电子音乐主题的预告视频来宣传他们的产品。在一个名为“DISCORD SYLEXRAT BOT”的机器人中，他们快速透露了一个 MediaFire 页面的 URL，用于下载文件GAutoClicker.zip。当然，我们下载了它——之前我们注意到该文件是从西班牙上传的：

在这次活动的背后，我们发现了三个 Discord 用户，其中两个名为 Syntax：

这是包sintaxisoyyo短暂出现的地方。在其setup.py上没有任何恶意：只是发送到 Discord webhook 的通知带有消息：“¡Alguien ha instalado el paquete reverse_shell！” （有人安装了reverse_shell包）。当然，这不是反向 shell包，所以是的，他们只是在尝试。实验通常很混乱：这个包中有一个名为“syntax”的文件夹，其中包含两个文件：__init__.py和__main__.py。前者的代码经过轻微混淆，结果与WindowsDefender.py相同. 而后者，没有混淆，似乎是另一种产品：一个 Discord 机器人，它在受感染的机器上执行命令并执行操作。所以这是实际的反向 shell。

该恶意软件可以检索 cookie、截取屏幕截图、运行 shell 命令、窃取浏览历史记录，并将所有这些数据发送到攻击者的 Discord 频道。因为这是 MaaS 产品的一部分，一张图片胜过一千字：一旦攻击者收到一条消息，宣布有人已被感染，ASCII 艺术就会打印在 Discord 频道中。

我们在我们的数据中跟踪了sonatype-2023-1534下的这些包，并将它们报告给了 PyPI 团队，PyPI 团队有效地将它们取下。我们将密切关注该小组未来的活动，并不断将任何发现添加到我们的数据中，以便您始终受到保护。

ChatGPT，写一段关于你最近的数据泄露 

我们想通过提及 OpenAI 最近经历的数据泄露来结束这个问题。

名为 Redis 的开源组件中一个未修补的软件错误/漏洞导致其部分订阅者的支付相关信息和用户的聊天查询泄露。OpenAI 确定事件的根本原因是 Redis 中的竞争条件漏洞，Redis 是 PyPI 存储库中可用的流行组件。 

尽管如此，尽管在版本 4.5.3 (CVE-2023-28858) 中发布了初始修复，一些测试人员仍然能够重现该缺陷，使其未被修复并导致分配第二个标识符来跟踪该缺陷（CVE- 2023-28859）。 

这一事件引发了对人工智能监管的争论，导致意大利成为第一个禁止 ChatGPT 的西方国家。它还提醒人们警惕竞争条件漏洞及其被利用的可能性。 

自动防御供应链攻击

上面提到的软件包只是我们工具捕获的大量恶意软件的冰山一角。自 2019 年以来，我们共发现了 115,165 个标记为恶意、可疑或概念验证的软件包。

Sonatype 的系统使用 ML/AI 技术来识别公共存储库中新发布的组件的异常属性。通过我们工具的近乎实时的检测功能提供的数据有助于防止我们的客户无意中使用恶意组件。

如果您想免受软件供应链攻击，请考虑使用Nexus 防火墙自动阻止恶意包到达您的开发版本。
