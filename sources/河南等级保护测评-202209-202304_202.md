# 用于隔离和中介的基元

在1960年代，Multics成为第一个从头开始设计时考虑到安全性的主要操作系统。虽然它从未变得非常流行，但它的许多安全创新仍然可以在当今最流行的操作系统中找到。即使某些功能不是由Multics团队直接发明的，它们集成到单个、工作、面向安全的操作系统设计中仍然是新颖的。Multics提供保护环、虚拟内存、基于分段的保护、支持自由访问控制（DAC）*和*强制访问控制（MAC).事实上，在许多方面，应军方要求添加的Multics中的强制访问控制是Bell-LaPadula安全模型的直接软件实现。最后，Multics确保其许多小型软件组件被强封装，只能通过发生中介的已发布接口访问。

如果这听起来很熟悉，这并不奇怪，因为JeromeSaltzer是Multics团队的领导者之一。可信计算机系统评估标准（TCSEC），更广为人知的是著名的*橙皮书*，描述了评估计算机系统安全性的要求，并且强烈地基于Multics。毫无疑问，Multics非常先进，甚至可能领先于一些现代操作系统，但这也是它的垮台\-系统变得如此之大，如此复杂，以至于至少在某些开发人员中，它可以说违反了心理可接受性原则。沮丧的KenThomson和DennisRitchie决定编写一个新的，更简单的操作系统。作为一个双关语，并与Multics形成对比，他们称之为“Unics”，后来拼写为UNIX。与目前使用的所有主要通用操作系统一样，它依赖于少量核心原语来隔离其不同的安全域。

那么这些主要的隔离原语是什么呢？首先，操作系统必须具有某种方式对用户和安全域进行身份验证，以便它可以决定他们是否可以访问某些资源。要隔离不同的安全域，操作系统还需要支持对对象（如文件）的访问控制。此外，它需要内存保护，以确保一个安全域不能简单地从另一个域的内存中读取数据。最后，它需要一种方法来区分特权代码和非特权代码，以便只有特权代码才能在最低级别配置所需的隔离并保证所有业务的调解。

## 认证和识别

由于身份验证是身份验证，授权和责任CyBOK知识领域的主题，我们将观察到要确定访问权限，操作系统需要对其用户进行身份验证，并且有很多方法可以做到这一点。传统上，只有用户名和密码用于此目的，但现在越来越多的系统使用其他方法（例如智能卡，指纹，虹膜扫描或面部）识别）——代替密码或作为附加因素。多因素身份验证使攻击者更难伪装成合法用户，特别是如果这些因素具有不同的性质，例如，您知道的东西（如密码）、您拥有的东西（如智能卡）和您“是”的东西（生物识别数据，如指纹）。

对于经过身份验证的每个用户，操作系统都会维护一个唯一的用户ID。此外，它还可能保留有关用户的其他信息，例如他们所在的组（例如，学生、教职员工和/或管理员）。同样，大多数操作系统将一些标识附加到代表用户运行的每个进程，并跟踪它们使用的文件的所有权和访问权限。例如，它为每个正在运行的进程提供一个唯一的进程ID，并注册代表其运行的用户的ID（以及用户所在的组）。最后，它跟踪哪个用户拥有正在执行的二进制文件。请注意，*拥有*二进制文件的用户和*运行*二进制文件的用户不必相同。例如，管理员可以创建并拥有其他用户可执行但不能修改的系统程序集合。

顺便说一下，以安全的方式存储凭据至关重要。一些现代操作系统诉诸硬件来保护此类敏感数据。例如，他们可以使用受信任的平台模块（TPM）来确保磁盘加密密钥等凭据以加密方式密封，或者为凭据存储使用单独的VM，以便即使遭到入侵的VM将无法直接访问凭据。

## 访问控制列表

给定这些标识，操作系统可以推理允许哪个用户和哪个进程对特定对象执行哪些操作：访问控制。

当RobertDaley和PeterNeumann首次开发Multics文件系统时，他们为系统中的每个数据块引入了访问控制列表（ACL）。从概念上讲，ACL是一个包含用户和数据块的表，它为每个数据块指定哪些用户具有哪种访问权限。大多数现代操作系统都采用了ACL的某些变体，通常用于文件系统。让我们看一个例子。在基于UNIX的系统上，默认的访问控制非常简单。每个文件都归用户和组所有。此外，每个用户都可以在一个或多个组中。例如，在Linux系统上，用户herbertb分为九个不同的组： 

| herbertb@nordkapp:~$ groups herbertbherbertb : herbertb adm cdrom sudo dip plugdev lpadmin sambashare cybokherbertb@nordkapp:~$ |
| --- |

对于每个文件，少量 权限位指示 拥有用户、拥有组和其他所有人的访问权限 。例如，让我们 看一下Linux上一个名为myscript的文件的ACL：

| herbertb@nordkapp:~/tmp$ getfacl myscript\# file: home/herbertb/tmp/myscript\# owner: herbertb# group: cybokuser::rwxgroup::rwxother::r-x |
| --- |

我们看到myscript由用户herbertb和组cybok拥有。拥有用户和组cybok中的所有用户都有权read、**w**rite和ex执行文件，而所有其他用户可以**r**ead和e**x**执行（但不要写入）。

这些基本的UNIX文件权限非常简单，但现代系统（如Linux和Windows）也允许更广泛的ACL（例如，具有多个用户或组的显式访问权限）。每当有人尝试读取、写入或访问文件时，操作系统都会验证ACL中是否有适当的访问权限。此外，UNIX中的访问控制策略通常是任意的，因为允许拥有用户为其他人设置这些权限。例如，在上面的Linux系统上，用户herbertb可以自己决定使文件myscript可以被所有用户写入（'chmodo+wmyscript'）。

除了DAC之外，Multics还实现了MAC，虽然达到这个阶段需要很长时间，但现在对于许多采用其灵感来自Multics（即当今最流行的操作系统）。Linux甚至提供了一个框架，允许通过所谓的“参考监视器”插入各种访问控制解决方案，这些监视器会审查每次执行安全敏感操作的尝试，实际上存在多个MAC解决方案。最著名的可能是Security-EnhancedLinux（SELinux），这是一组Linux安全补丁，最初由美国国家安全局（NSA）开发，源自FluxAdvanced。安全内核（FLASK）。

SELinux为用户和进程提供了三个字符串的上下文：（用户名、角色、域）。虽然元组已经（正确地）表明SELinux也支持RBAC，但在使用什么和避免什么方面存在显着的灵活性。例如，许多已部署的系统仅对MAC使用域字符串，并将所有用户的用户名和角色设置为相同的值。除了进程之外，文件、网络端口和硬件资源等资源也具有与之关联的SELinux上下文。根据此配置，系统管理员可以定义系统范围的策略，以便对其系统进行访问控制。例如，他们可以简单地定义进程必须对资源执行特定操作（读取、写入、执行、连接）的域，但策略也可能要复杂得多，具有多级安全性和严格执行信息流*类似于*贝尔\-拉帕杜拉、比巴或一些自定义访问控制模型。

SELinux等系统中的强制访问控制围绕由中央管理员设置且不会更改的单个系统范围策略。它们不允许不受信任的进程定义和更新自己的信息控制策略。相比之下，石棉、HiStar和Flume等研究操作系统恰恰提供了分布式信息流控制。换句话说，任何进程都可以创建安全标签并对数据进行分类和解密。
