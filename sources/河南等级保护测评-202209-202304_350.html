跨租户AWS漏洞暴露账户资源

原文：http://mp.weixin.qq.com/s?__biz=Mzg2NjY2MTI3Mg==&mid=2247488412&idx=2&sn=2391d5795d77141f85f1331be47d9219&chksm=ce46356bf931bc7d2b1d12359fb48178d765eb94363e75db6d05b49a87b5e2935e7fb19a3a06&scene=27#wechat_redirect

Amazon Web Services (AWS) 中的跨租户漏洞可能允许攻击者滥用 AWS AppSync 来访问组织账户中的资源。

云安全公司 Datadog Security Labs 解释说，攻击者可以利用 AWS AppSync 服务在其他 AWS 账户中担任身份和访问管理 (IAM) 角色，从而获得对这些账户中资源的访问权限。

AppSync 服务允许开发人员创建GraphQL 和 Pub/Sub API，每个 API 都有一个关联的数据源，以及直接调用 AWS API，创建与 AWS 服务的集成，这需要定义具有 IAM 权限的角色。

已识别的漏洞被描述为“混淆代理问题”，因为它允许权限较低的实体（攻击者）欺骗权限较高的实体（AppSync）代表其执行特定操作。

为防止此类攻击，在创建数据源期间，AWS 会根据 AWS 账户验证角色的唯一标识符，称为亚马逊资源名称 (ARN)。如果它们不匹配，API 会显示错误。

Datadog 安全实验室发现，在验证期间，“API 会接受具有使用混合大小写属性的 JSON 有效负载”。ARN 在serviceRoleArn 参数中传递，如果在不同的外壳中提供，该参数可用于绕过验证过程。

从本质上讲，该机制允许云安全公司“提供不同 AWS 账户中角色的 ARN”。

“通过绕过 ARN 验证，我们能够创建与其他 AWS 账户中的角色相关联的 AppSync 数据源。这将允许攻击者与任何与信任任何账户中的 AWS AppSync 服务的角色关联的资源进行交互，”Datadog 指出。

该公司解释说，该安全缺陷可被用来创建指向其他 AWS 账户中资源的 AppSync API 数据源，本质上是访问这些账户中的数据。

Datadog 已发布针对该漏洞的概念验证 (PoC) 代码，并于 9 月 1 日向 AWS 报告了该问题。补丁已于 9 月6 日推出。

本周，AWS 发布了关于此漏洞的公告，确认它可能被滥用以绕过 AppSync 的跨账户角色使用验证并访问其他客户账户中的资源。

“没有客户受到此问题的影响，也不需要客户采取任何行动。对追溯到服务启动的日志进行了分析，我们最终确定与此问题相关的唯一活动是在研究人员拥有的账户之间进行的。没有其他客户账户受到影响，”AWS 指出。
