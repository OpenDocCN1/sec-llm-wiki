# 攻击者使用 IPFS 进行分布式防弹恶意软件托管

**星际文件系统 (IPFS) 被认为是 web3 的构建块之一，越来越多地用于为恶意软件提供隐藏的防弹托管。**

“多个恶意软件家族目前托管在 IPFS 中，并在恶意软件攻击的初始阶段进行检索，”Cisco Talos 的研究人员说。

![](../Images/ddea8013afe848a15a1b0aa5f9067bf1.png)

IPFS 是一个分布式文件系统，通过内容而不是物理位置来促进访问。目标文件的 URL 是内容的散列，而不是服务器位置的定义。文件被输入系统，然后自动复制到多个节点。用户不知道节点的物理位置，因为文件是通过内容哈希而不是 IP 地址检索的。节点和哈希之间的关系由 IPFS 网关维护——整个目的是创建和维护对互联网内容的合法弹性、去中心化和未经审查的访问。

“虽然这些技术在各种实际应用中具有合法用途，但它们也为攻击者创造了在网络钓鱼和恶意软件分发活动中利用它们的机会，”Talos 在其最新的威胁聚焦中说。

“作为攻击者，”Talos 告诉*SecurityWeek*，“你通常会在你控制的系统上安装 IPFS 客户端。” 这可能是您拥有的计算机、受感染的主机或匿名的虚拟专用服务器。“您将文件发布到 IPFS 网络，并且您可以有效且自动地将本地内容提供给 IPFS 网络中的多个其他节点。”

然后，您可以脱离初始计算机，但该文件仍存在于 IPFS 中的位置，只有 IPFS 网关使用的哈希表知道。保持弹性，没有单点故障，目标不必是 IPFS 的一部分。

对攻击者的吸引力是显而易见的：他们没有与恶意软件存储相关的成本，而且他们的 IPFS“服务器”不能像传统的 IP 恶意软件服务器一样被拆除。

需要明确的是，攻击的过程是不变的。目标仍然需要定向到 IPFS 文件，该文件很可能是恶意软件或网络钓鱼页面。这将继续主要通过恶意链接或武器化附件进行。一个特别精明的用户可以识别电子邮件中的 IPFS URL（它只是看起来是一系列随机字符）并拒绝点击——但我们凭经验知道用户往往不会仔细查看链接，很容易被社会工程学所左右链接周围的上下文。

“目前，”Talos 告诉*SecurityWeek*，“如果你是一个与 web3 没有关联的组织，并且你不处理 NFT，我建议你简单地阻止对所有 IPFS 网关的访问，因为它们有一个维护列表. 这将在很大程度上缓解这种情况。”

但这不是长久之计。随着 web3 的发展和发展，以及 NFT/区块链应用程序在 IPFS 上变得越来越普遍，许多用户不太可能脱离这个过程。 

任何形式的本地或 IPFS 网关阻止恶意文件都将是困难的。虽然可以识别并单独阻止恶意 IPFS URL，但该过程将类似于使用传统签名来阻止恶意软件。攻击者只需要更改文件中的几个字符，就会创建一个新的哈希签名——创建一个新的 IPFS 文件，该文件将重新分配到不同的节点。

Talos 报告描述了研究人员在 IPFS 中发现的几种不同的攻击。一个示例似乎是与 DocuSign 关联的 PDF。如果受害者单击“查看文档”，他或她将被重定向到一个看似 Microsoft 身份验证页面，但实际上是托管在 IPFS 网络上的网络钓鱼页面。收集到的任何数据都会通过 HTTP POST 请求发送到攻击者控制的 Web 服务器，以用于进一步的攻击。

另一个例子是 Agent Tesla 恶意垃圾邮件活动，在整个感染过程中使用 IPFS 最终传递恶意软件负载。 

需要明确的是，使用 IPFS 不需要新的恶意软件。它主要是一种不断发展的托管和交付机制。它为攻击者提供了弹性托管，使防御者即使不是不可能也很难阻止恶意链接。由于防御者更加依赖恶意软件检测和响应，因此对交付的恶意软件的防御保持不变。

由于 IPFS 托管的恶意软件简单、免费且具有弹性的托管功能，攻击者可能会增加其使用率。这是否会导致攻击量急剧增加还有待观察。
