### 花指令

*   #### Wh4t is 花指令
    
    花指令是程序中的无用指令或者垃圾指令，故意干扰各种反汇编静态分析工具，但是程序不受任何影响，缺少了它也能正常运行。加花指令后，IDA Pro等分析工具对程序静态反汇编时，往往会出现错误或者遭到破坏，加大逆向静态分析的难度，从而隐藏自身的程序结构和算法，从而较好的保护自己。
    

  

*   #### Opcode of JMP&CALL
    
    ```
    0BBD:0000   B80000  MOV AX, 0000
    0BBD:0003   EB03    JMP 0008
    0BBD:0005   050100  ADD AX, 0001
    0BBD:0008   40      INC AX
    ```
    
    ```
    0BBD:0000   B80000  MOV AX, 0000
    0BBD:0003   BB0000  MOV BX, 0000
    0BBD:0006   EB03    JMP 0008
    0BBD:0008   050100  ADD AX, 0001
    0BBD:000B   40      INC AX
    ```
    

*   0xE8 call + 4字节偏移地址
    
*   0xE9 jmp + 4字节偏移地址
    
*   0xEB jmp + 2字节偏移地址
    
*   0xFF15 call + 4字节地址
    
*   0xFF25 jmp + 4字节地址
    
*   两个程序中的inc ax指令的偏移地址不同，但是jmp指令所对应的机器码都是EB 03，说明CPU在执行jmp指令的时候并不需要转移目的地址。
    
*   jmp short的机器码形式为EB XX，所指向的地址为当前地址 + 2（指令长度） + XX，其中XX为8位位移，范围为-128~127，用补码表示。
    
*   (near relative)call的机器码形式为E8 XXXXXXXX，例如EIP为00411A39，opcode为E8A7F7FFFF，则此时目标地址为00411A39 + 5 + FFFFF7A7 = (1)004111E5
    
*   Summary
    
*   CPU执行指令的过程
    
    （1）从CS:IP指向内存单元读取指令，读取的指令进入指令缓冲器；
    
    （2）(IP)=(IP)+所读取指令的长度，从而指向下一条指令；
    
    （3）执行指令。转到（1），重复这个过程。
    
      
    

*   #### 花指令作用原理
    
    常用的两种反汇编算法：（1）线性扫描算法：逐行扫描反汇编（2）递归行进算法：按照代码可能的顺序进行反汇编程序下面仅以线性扫描算法和jmp花指令为例讲解反汇编算法是如何受花指令的影响。
    

```
jmp label1
\_emit E8h
label1:
push eax
xor eax,eax
pop eax
```

程序正常执行时很明显不会执行\_emit E8h指令，但是线性反汇编算法在识别时仍然会对E8进行处理。E8对应的汇编指令是CALL指令，于是线性反汇编器在遇到CALL指令的时候会自动读取接下来的4个字节作为要跳转的地址，这四个字节会与E8构成一个完整的CALL指令。在上面的例子中线性反汇编器遇到E8后将会读取后面的四个字节数据，导致四个字节被读入,这四个字节分别是50h、33h、C0h、58h。其中50h就是push eax代表的机器码，33h和C0h一起组成了xor eax,eax,58则是pop eax。CALL与这几个本不应该和CALL拼接的字节拼接之后造成了后续分析的混乱，达到花指令的目的。

#### 几种常见的花指令

*   **简单jmp跳转**
    

```
\_\_asm{
    jmp LAB3L
    \_emit 01h   //junk code，在这种情况下拼接Opcode无法干扰到ida对程序的静态分析
LAB3L:
    add a, 1    //有用的代码
}
```

![](../Images/58c3b4b46cf5a0f130551ca0a5bc7bef.png)

  

* * *

*   **永真条件跳转**
    

```
\_\_asm{
    mov eax, 1
    cmp eax, 0
    jnz LAB3L   //此处一定跳转到LAB3L
    \_emit 0E8h  //junk code,在这种情况下拼接Opcode能够干扰到ida对程序的静态分析
LAB3L:
    add a, 1    //有用的代码
}
```

![](../Images/25297c4e55598b74e2dbdd07d02bebe9.png)

  

* * *

*   **jz和jnz条件跳转**
    

```
\_\_asm{
    jz LAB3L
    jnz LAB3L   //jz和jnz互补，因此一定会满足其中一个而跳转到LAB3L
    \_emit 0E8h  //junk code,在这种情况下拼接Opcode能够干扰到ida对程序的静态分析
LAB3L:
    add a, 1    //有用的代码
}
```

*   **call&ret**
    

```
\_\_asm{
    call LAB3L
    \_emit 0E8h  //junk code，在这种情况下拼接Opcode无法干扰到ida对程序的静态分析
LAB3L:
    add a, 1    //有用的代码
    pop eax     //下面都是junk code
    add eax,11  //此处将返回地址取出后加某个值，来控制ret返回的地址，例子中是到ret的下一条语句 
    push eax
    ret
}
```

*   #### 脚本清除花指令
    

 以本题为例，本题是通过call&return构造花指令，其中对于寄存器ecx的操作均为junk code，而有用的代码则是对于寄存器eax和ebx的操作，因此要将有关寄存器ecx的操作全部nop掉。

  

```
//IDC脚本
#include <idc.idc>
static main(){
    auto addr\_start \=0x00415990;//函数起始地址
    auto addr\_end \= 0x00416048;//函数结束地址
    auto i\=0,j\=0;
    for(i\=addr\_start;i<addr\_end;i++){
        if(Dword(i) \== 0x1E8){
            for(j\=0 ; j<6; j++,i++ ){
                PatchByte(i,0x90);
        }
            i\=i+4;
            for(j\=0 ; j<3; j++,i++ ){
                PatchByte(i,0x90);
        }
            i\=i+10;
            for(j\=0 ; j<3; j++,i++ ){
                PatchByte(i,0x90);
        }
            i\=i+5;
            for(j\=0 ; j<1; j++,i++ ){
                PatchByte(i,0x90);
        }   
            i\=i+3;
            for(j\=0 ; j<2; j++,i++ ){
                PatchByte(i,0x90);
        }     
            i\--;    
    }
}
}
```

#基于匹配的IDC花指令去除脚本以花指令代码

```
\_\_asm {
        \_emit 90h
        call LABEL1
        \_emit 0Eh
        LABEL1 :
        xor ebx, ebx
            pop ecx
            add ecx, 9
            push ecx
            ret
}
```

为例

```
#include<idc.idc>
static patchCode(addr,len)
{
    auto index = 0;
    for(index;index<len;index++)
    {
        PatchByte(addr+index,0x90);
    }
}
static main(){
    auto origAddr = ScreenEA();
    auto startCode = GetFunctionAttr(origAddr,FUNCATTR\_START);
    auto txtEnd = GetFunctionAttr(origAddr,FUNCATTR\_END);
    auto code;
    code=FindBinary(startCode,1,"E8 01 00 00 00 0E 33 DB 59 83 C1 09 51 C3");
    while(code!=-1){
            patchCode(code,0xE);
            Message("OK");
            startCode=startCode+0xE;
            code=FindBinary(startCode,1,"E8 01 00 00 00 0E 33 DB 59 83 C1 09 51 C3");
        }
}
```
