# 浅谈mysql宽松模式下的安全隐患

Mysql 的宽松模式，又叫非严格模式，指的是没有对自身的数据进行严格校验（格式、长度、类型等），在宽松模式下，即使插入不同类型的数据或者超过数据设置的长度，也不会使数据库报错。

查看数据库是否开启宽松模式，可以使用 `select @@GLOBAL.sql_mode;` 来判断，下图就是开启的宽松模式。

![](../Images/a377a06514f25e92e34b19f32e21d529.png)

那么宽松模式有什么隐患呢？

打个比方，如果我们设置了宽松模式，并且设置 `varchar` 长度为 12 的 `username` 字段，我们往里面插入一段数据 `1234567890abc`。

```

insert into users values('1234567890abc','qjntml);
```

![](../Images/424128b6f0e6b521964b3b5db750d560.png)![](../Images/cde94857c56d8eded2f876effdaa453f.png)

可以看到，我们的数据被截断了，只留下了12个字符

```

select username,password from users;
```

![](../Images/a61b190edd284d79c11d54d1388e984d.png)

所以当 mysql 设置了宽松模式，又对后端没有进行严格校验的时候，我们可以利用宽松模式的一些机制来进行漏洞利用。

比如存在一个 `admin` 的管理员用户，我们可以利用宽松模式进行注册，往里面添加空格符号，起初只有一个 `admin` 账号

```

select * from users where username='admin';
```

![](../Images/f770cf4085515818e832a88b69bcf889.png)

我们利用宽松模式，注册一个 `admin`，后面加上空格

```

insert into users values('admin          ','123456');
```

![](../Images/a98854d9f5109868f22de0bdc6560ab9.png)

这时候再使用 `select` 搜索 `admin` 账号，发现出现了两个结果，宽松模式把空格给自动过滤掉了，也就是说，数据库把我们刚注册的账号也认为是 `admin` 账号。

```

select * from users where username='admin';
```

![](../Images/eae876302d1422227ba06b7e926e75e5.png)

而如果后端的登录逻辑如下图所示

![](../Images/fc9de9829e4458eb1dac660c3e7c6881.png)

我们就获得了 `admin` 的权限。
