# 漏洞提交基本原则

> > > 1.  在漏洞挖掘过程中，发现的相关漏洞应严格保密，禁止提交到其它的众测平台或对外发布；禁止利用发现的漏洞实施非法活动；测试过程中发现的所有漏洞都需如实反馈，写进漏洞报告；
> > > 2.  不允许造成或引发业务运营故障，包含但不限于不得发起大量级或高频请求等手段；
> > > 3.  在测试过程中如包含数据获取功能时，包括但不限于SQL注入、用户资料的越权获取等，**「应采取手动测试，且获取的数据量不能超过3条，相关数据也需在报告后尽快删除；」**
> > > 4.  测试命令执行、数据库注入、webshell上传、供应链攻击等可直接威胁内网及数据库安全的漏洞，发现问题后需立马告知涂鸦，**「经授权后才能进行横向移动，未经授权禁止植入后门或者对内网其他主机进行测试；」**
> > > 5.  测试命令执行漏洞时，证明漏洞即可，禁止植入文件或者对内网其他主机进行扫描测试；
> > > 6.  获取网站的权限时，禁止修改代码文件或植入后门等操作。
> > > 7.  活动中如遭遇账号锁定、封停等情况，请自行处理(走正常客诉流程)，测试期间不受理SRC账号封禁处理，测试完毕可统一解封。

**「如有发现以下情况，对应白帽子将会加入黑名单，涂鸦保留有进一步追究法律责任的权力：」**

> > > 1.  恶意利用漏洞故意泄漏涂鸦数据行为；
> > > 2.  利用漏洞恶意删除我司系统文件或数据，故意破坏涂鸦系统行为；
> > > 3.  发现涂鸦漏洞提交到其它的众测平台或对外发布；
> > > 4.  发现漏洞故意不上报涂鸦行为；
> > > 5.  利用发现漏洞实施其它非法活动行为；
> > > 6.  使用DDoS技术等暴力测试对涂鸦系统进行攻击行为；
> > > 7.  任何以漏洞测试为借口，利用安全漏洞进行破坏、损害用户及涂鸦利益的攻击行为。
