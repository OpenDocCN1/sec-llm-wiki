# 【漏洞预警】WebLogic反序列化漏洞CVE-2018-3191

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=Mzg2NjgzNjA5NQ==&mid=2247514220&idx=2&sn=2857991de6b2864b23535cd365982e1b&chksm=ce46337cf931ba6a93e393dd1a016db584cc4bf48812a517643ae59a35c223b3b9359ef3b6a3&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=Mzg2NjgzNjA5NQ==&mid=2247514220&idx=2&sn=2857991de6b2864b23535cd365982e1b&chksm=ce46337cf931ba6a93e393dd1a016db584cc4bf48812a517643ae59a35c223b3b9359ef3b6a3&scene=27#wechat_redirect)

Oracle官方发布了10月份的关键补丁更新CPU（Critical Patch Update）,其中包含一个远程代码执行漏洞，漏洞威胁等级为高危，漏洞对应的CVE编号为CVE-2018-3191。

 

    

**千里百科**

    

WebLogic是美国Oracle公司出品的一个application server，确切的说是一个基于JAVAEE架构的中间件，WebLogic是用于开发、集成、部署和管理大型分布式Web应用、网络应用和数据库应用的Java应用服务器。

 

将Java的动态功能和Java Enterprise标准的安全性引入大型网络应用的开发、集成、部署和管理之中。WebLogic是商业市场上主要的Java（J2EE）应用服务器软件（application server）之一，是世界上第一个成功商业化的J2EE应用服务器，具有可扩展性，快速开发，灵活，可靠性等优势。

 

    

**漏洞描述**

    

此漏洞产生于WebLogic T3服务，所有开放WebLogic控制台端口的应用，均会默认开启T3服务。据统计，在全球范围内对互联网开放WebLogic服务的资产数量多达35,382台，其中归属中国地区的受影响资产数量为10,562台。具体数据如下图：

![](../Images/df4f9b3cfa765e3098aba4206396cb13.png)

WebLogic java反序列化漏洞(CVE-2018-3191)是利用AbstractPlatformTransactionManager类，在JtaTransactionManager中找到java反序列化入口——readObject。在initUserTransactionAndTransactionManager方法中可以找到基于JNDI寻址方法lookupUserTransaction。通过重写readObject，进行java反序列化攻击。实现任意代码执行，并获取目标系统的所有权限。

 

    

**漏洞复现**

    

**触发此漏洞的前提是：**

**1.使用了Oracle WebLogic Server10.3.6.0, 12.2.1.3，12.1.3.0 中的任何一个版本的WebLogic服务。**

**2.对外开放了WebLogic服务端口。**

**3.对外开放T3协议。**

 

基于这三个前提条件，搭建一套WebLogic 10.3.6.0的运行环境。

![](../Images/1a87324ca9fd2c33f222ed60461a3b23.png)

使用深信服云眼检测系统可以发现，此WebLogic环境存在CVE-2018-3191漏洞  

![](../Images/f2361bf4f03ee505e6fe8f787b0e7b58.png)

**临时解决方案**

    

对T3服务进行控制

控制T3服务的方法:

![](../Images/8a36534a0b7a8f309c9fc20d152d76db.png)

在上图这个界面中选择安全-筛选器，在下方出现的界面中找到“连接筛选器”，在里面输入

security.net.ConnectionFilterImpl

然后在连接筛选器规则中输入

127.0.0.1 \* \* allow t3 t3s，0.0.0.0/0 \* \* deny t3 t3s

最后保存并重启服务器即可生效。
