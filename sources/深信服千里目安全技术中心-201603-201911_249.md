**国内使用量最大的CMS**

    

织梦内容管理系统（DedeCMS)是上海卓卓网络科技有限公司出品的一款CMS产品，是国内最知名、使用人数最多的内容管理系统（CMS）之一。DedeCMS基于PHP+MySQL技术开发，支持多种服务器平台，旨在帮助用户解决日益复杂与重要的 Web 内容的创建、维护、发布和应用。

  

从2004年发布第一个版本开始，至今已经发布了五个大版本。DedeCMS以简单、健壮、灵活、开源等几大特点占领了国内CMS的大部份市场，根据全网可被搜索数据统计，目前国内已有超过20余万个站点正在使用DedeCMS或基于DedeCMS核心开发，产品安装量达到95万。根据统计，DedeCMS在政府部门的使用量过千个，在教育行业使用也超过500余个，在商业中的用途也很广泛，超过15W商业用户在使用，具体分布如下图：

![](../Images/5e515804768dc5e7256e99828196d32d.png)

 DedeCMS被如此广泛的应用，必定有它所特有的优势。DedeCMS是一种很灵活的CMS，推出了模块功能，用户可以像安装软件一样，下载相应的模块进行安装，网站就会增加这些特殊的功能。DedeCMS同时为用户提供了方便快捷的用户自定义模型，你可以使用这个功能根据自身需求来创建各式各样的站点。方便、易用、灵活、便捷就成为DedeCMS所具有的标签，但是，DedeCMS的历来的安全性却备受诟病。网络上有很多人说DedeCMS的漏洞多的原因是因为它的用户量高，研究的人多，所以漏洞也自然多起来。这并不是理由，软件的用户量越多，那么漏洞就应该更越少。软件漏洞的产生和利用的门槛很低，最终，这些都需要用户为软件厂商埋下来的安全问题来买单。

  

    

**DedeCMS高危漏洞一览**

    

根据千里目实验室漏洞库的数据统计，DedeCMS历史漏洞总量高达80余个，其中核心版本DedeCMS 5.6版本、DedeCMS 5.7版本漏洞30余个。DedeCMS的高危漏洞数超过十个，并且漏洞的危险性极大，攻击者可以利用这些漏洞进入DedeCMS后台，甚至Getshell。所以，DedeCMS的安全性一直备受广大用户的质疑。

  

经过笔者对DedeCMS高危漏洞的统计以及分析整理，其高危漏洞类型主要有以下几类：**注入类、命令执行类、远程文件包含类**等，其中SQL注入问题是最为严重的一类，其数量超过高危总量的百分之80%以上，接下来笔者将按照漏洞类型来介绍DedeCMS的经典漏洞。

**2.2代码执行漏洞**

代码执行是一种威胁性非常大的漏洞类型，大多数“一锅端”（能够getshell，控制全站）漏洞都是代码执行漏洞。但是DedeCMS的远程代码执行漏洞基本都有一个特点，必须得登录后台。这也与DedeCMS的特点有关，DedeCMS的后台权限极大，官方的开发意识一向是，开发者只要拥有管理员权限，在网站中可以为所欲为。DedeCMS最危险的漏洞也都在后台中隐藏着，所以，DedeCMS的用户，必须得看管好自己的后台权限，一旦陷落，后患无穷。

**2.3远程文件包含漏洞**

DeDeCMS中有一个经典的远程文件包含漏洞，该漏洞利用方式简单，危害性大，但是前提是install文件夹未在网站安装后删除。该漏洞利用需要执行两步，首先进行变量覆盖，然后才能进行远程文件包含，接下来我们来看看这个漏洞。

**远程文件包含漏洞**

 

**1.漏洞原理**

该漏洞利用需要两步，首先是进行变量覆盖，然后进行远程文件包含，首先在install/index.php中：

$insLockfile = dirname(\_\_FILE\_\_).'/install\_lock.txt';

$moduleCacheFile = dirname(\_\_FILE\_\_).'/modules.tmp.inc';

define('DEDEINC',dirname(\_\_FILE\_\_).'/../include');

define('DEDEDATA',dirname(\_\_FILE\_\_).'/../data');

define('DEDEROOT',preg\_replace("#\[\\\\\\\\\\/\]install#", '', dirname(\_\_FILE\_\_)));

header("Content-Type: text/html; charset={$s\_lang}");

require\_once(DEDEROOT.'/install/install.inc.php');

require\_once(DEDEINC.'/zip.class.php');

foreach(Array('\_GET','\_POST','\_COOKIE') as $\_request)

{

    foreach($$\_request as $\_k => $\_v) ${$\_k} = RunMagicQuotes($\_v);

}

require\_once(DEDEINC.'/common.func.php');

 

if(file\_exists($insLockfile))

{

    exit(" 程序已运行安装，如果你确定要重新安装，请先从FTP中删除 install/install\_lock.txt！");

}

其中，代码中标红的代码就是变量覆盖产生的地方，相信大家看着这个代码很眼熟，在之前SQL注入第一个漏洞中我们也看到了类似的这个代码，DedeCMS变量覆盖的“万恶之源”。大致意思是将get,post或者cookie方式传入的值通过foreach以键值对的方式输出，例如在url中输入  ?str=hello,则$\_k的值就是str，$\_v的值就是hello  所以  ${$\_K}就是$str，这里很明显的变量覆盖了。后面的RunMagicQuotes函数在另一个文件中定义的，在这里理解为返回参数内容就好了。

  

只有变量覆盖漏洞暂时还不够，我们看文件中的以下代码：

else if($step==11)

{

    require\_once('../data/admin/config\_update.php');

    $rmurl = $updateHost."dedecms/demodata.{$s\_lang}.txt";

    $sql\_content = file\_get\_contents($rmurl);

    $fp = fopen($install\_demo\_name,'w');

    if(fwrite($fp,$sql\_content))

        echo '  <font color="green">\[√\]</font> 存在(您可以选择安装进行体验)';

    else

        echo '  <font color="red">\[×\]</font> 远程获取失败';

    unset($sql\_content);

    fclose($fp);

    exit();

}

这段代码块引入了 /data/admin/config\_update.php文件，文件内容为：

<?php

/\*\*

 \* 更新服务器，如果有变动，请到 http://bbs.dedecms.com 查询

 \*

 \* @version        $Id: config\_update.php 1 11:36 2011-2-21 tianya $

 \* @package        DedeCMS.Administrator

 \* @license        http://help.dedecms.com/usersguide/license.html

//更新服务器，如果有变动，请到 http://bbs.dedecms.com 查询

$updateHost = 'http://updatenew.dedecms.com/base-v57/';

$linkHost = 'http://flink.dedecms.com/server\_url.php';

这段代码中讲到，可以从远程服务器中获取到最新的配置文件，而远程服务器已经被指定，无法自行构造。但是我们可以通过变量覆盖漏洞删除/data/admin/config\_update.php文件中的内容，然后看这里定义了变量updateHost，继续看标红的代码，$updateHost与"dedecms/demodata.{$s\_lang}.txt"拼接为字符串，并利用file\_get\_contents函数读取demodata.{$s\_lang}.txt文件内容，最后将该文件内容写入到$install\_demo\_name  =  'dedev57demo.txt'文件中，因此我们可以结合上面的变量覆盖漏洞来进行远程文件包含，直接写webshell。由于$updateHost变量是引入进来的所以不能直接进行覆盖，需要先将config\_update.php文件清空再包含。

**总结**

    

以上内容主要介绍了DedeCMS的三类漏洞中的经典漏洞，我们可以看出，这些漏洞的危害性都是极大的，基本都可以Getshell，当然，这些漏洞的危害远不仅仅是Getshell，甚至会引发更严重的安全事件。

  

依稀记得2013年在国内发生了一起大规模的挂马攻击，目标是就是DedeCMS，这个网马利用了DedeCMS的SQL注入漏洞，从而得到管理员账号，破解出密码，查找到后台，进行批量登录，然后在后台批量生成静态html文件，这些文件就是游戏“轩辕传奇”的页面。据监测，有些被这样挂马的网站，居然一次性生成了80,452个页面，甚为壮观。

  

所以安全是信息时代的生命线，安全研究人员分析漏洞的最终目的是如何更好的进行防御。作为一个致力于web安全的安全研究员，PHP类软件的安全是我无法忽视的一个阵地，对于本文中的DedeCMS，笔者经过长时间的分析与总结，为的就是提升这些漏洞的检测能力以及防御能力，最终为用户的WEB安全修上一堵墙。DedeCMS虽然好用，但是安全问题频发，一个漏洞的出现，对于用户来说，那么就意味着自己的资产陷入了危险的境遇之中，所以对漏洞的提前的防御与预知，防范于未然，是很有必要的。

  

攻防的较量从未停止，黑帽子与白帽子间的斗争也越演越烈。在web安全这个战场上，需要持续深入地研究，才能占有主动权。
