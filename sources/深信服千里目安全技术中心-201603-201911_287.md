# 【漏洞预警】Redis服务器拒绝服务漏洞（cve-2018-12453）

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=Mzg2NjgzNjA5NQ==&mid=2247514163&idx=1&sn=7591e659c0fc1760afe9c4279a9cf255&chksm=ce463323f931ba35b7888363b1e262286dd947d3e0b2eb91d0baf7e4b49ab67164c03b29b3b6&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=Mzg2NjgzNjA5NQ==&mid=2247514163&idx=1&sn=7591e659c0fc1760afe9c4279a9cf255&chksm=ce463323f931ba35b7888363b1e262286dd947d3e0b2eb91d0baf7e4b49ab67164c03b29b3b6&scene=27#wechat_redirect)

2018年6月14日，Redis官方发布了最新的Redis 5.0 rc3版本。之前Fakhri Zulkifli在github上发布了Redis-5.0的一个拒绝服务漏洞poc，该漏洞可以让已经登录到Redis数据库的攻击者通过发送多条指令让Redis程序崩溃。

    

**千里百科**

    

Redis是一个开源的使用ANSI C语言编写、支持网络、可基于内存亦可持久化的日志型、Key-Value数据库，并提供多种语言的API。根据月度排行网站DB-Engines.com的数据显示，Redis是最流行的键值对存储数据库。

    

**漏洞描述**

    

当前Github上已经发布了可导致Redis拒绝服务的攻击指令，当攻击者通过远程登录到Redis数据库的开放网络端口时，通过发送XGROUP CREATE等一系列指令可造成Redis数据库崩溃。触发该漏洞的原因在于Redis并没有对XGROUP CREATE 指令的参数进行类型检测，导致其它类型如数字、字符串型的参数会被当做OBJ\_STREAM类型做处理，在处理的过程中访问了未初始化的内存导致程序崩溃。

    

**漏洞复现**

    

本次复现使用了Ubuntu 16.0.4TLS64位环境，从github上下载Redis 5.0 rc1的安装包进行手动编译安装。安装完后启动Redis服务器并监听本地的6379端口，如下图：

![](../Images/c5119707c146c72b5f5098bffd63e5ce.png)

随后通过redis-cli工具登录到6379端口，并查看当前的版本如下：

![](../Images/fa8aa06647b6f91c545bec579929c51f.png)

随后定义一个数字类型的变量，并利用XGROUP CREATE创建基于该变量类型的群组，造成Redis崩溃：

![](../Images/7fc5c428c996156539f9514436660daa.png)

![](../Images/787deb9bfd806807c87e49647bb8c4c8.png)  

而Redis开发团队也很快发布了针对该漏洞的新版本Redis 5.0 rc3,在新版本中添加了对XGROUP CREATE指令的参数类型检查，如下：

![](../Images/de4b3b07d4e38cf1cb8d2445cf1ae879.png)

用户只需下载安装此版本的Redis即可防御此类攻击
