# 公式编辑器漏洞攻击来袭，你打补丁了吗？

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=Mzg2NjgzNjA5NQ==&mid=2247514117&idx=1&sn=926d3517df9e04a5673fb797542ef69c&chksm=ce463315f931ba032e7d4cc8b3dd7fe07fb2354bf2247da68e04751698bfe5174fea9839765f&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=Mzg2NjgzNjA5NQ==&mid=2247514117&idx=1&sn=926d3517df9e04a5673fb797542ef69c&chksm=ce463315f931ba032e7d4cc8b3dd7fe07fb2354bf2247da68e04751698bfe5174fea9839765f&scene=27#wechat_redirect)

近期，深信服EDR安全团队捕获多个利用CVE-2018-0802漏洞进行攻击的最新样本，这批样本是通过利用CVE-2018-0802漏洞执行隐藏在文档中的恶意程序进行攻击的，受攻击用户打开恶意的office文档时，无需交互，就可执行恶意代码。此漏洞与2017年11月微软发布的修复CVE-2017-11882漏洞密切相关，在安装过CVE-2017-11882漏洞补丁的用户将受到CVE-2018-0802漏洞的威胁。

漏洞概述

2017年，微软office公式编辑器被曝出存留时间长达17年之久的高危漏洞CVE-2017-11882，之后微软迅速推出相关的补丁进行修复，但修复之后，从修复补丁中发现了新的漏洞CVE-2018-0802，2018年1月发布了新的安全补丁，其中修补了office漏洞CVE-2018-0802，此漏洞原理与CVE-2017-11882类似，也是由于office公式编辑器组件EQNEDT32.EXE，对字体名的长度没有进行长度检测，导致攻击者可以通过构造畸形的字体名，执行任意代码。 

![](../Images/b9b5b210bc0a3c38a66d6f67fef39ff6.png)

漏洞原理

CVE-2018-0802为CVE-2017-11882的补丁绕过漏洞，类型为栈溢出，根本原因为微软在CVE-2017-11882的漏洞补丁中没有修复另外一处拷贝字体FaceName时的栈溢出。本次漏洞可以在打过CVE-2017-11882补丁的版本上完美利用。

下面我们通过捕获到的一些相关样本，来分析CVE-2018-0802漏洞。拿到样本之后，我们先提取样本里的OLEObject，如下图所示：

![](../Images/567abfa88ffa55146906e72b53b4a0e0.png)

查看样本的RTF文件，可以看到继续使用objupdate字段来使OLE对象的自动更新和加载，如下图所示：

![](../Images/49822384bf4db65505f1114f79e8e479.png)

CVE-2018-0802与CVE-2017-11882漏洞一样，漏洞触发数据都是位于所提取OLE对象的“Equation Native”流内，如下图所示：

![](../Images/e1149b403efce6ec6ad38e2761c2cf1e.png)

因此，我们先了解一下它的大致结构，整个“Equation Native”数据由头结构与后续数据组成。其头结构为：

![](../Images/98f447a027060d5545290c624811cdcb.png)

紧接着头结构的MTEFData内容，MTEFData内容也由MTEF头和MTEF字节流数据组成，MTEF头内容：

![](../Images/bb9f29721ce7da722ed653fc26d23978.png)

MTEF字节流数据包括一系列记录，每一个记录以一个标签位开始，标签位的低4位描述该记录的类型，高四位描述该记录的属性，后续紧跟标签的内容数据，此次发生栈溢出的部分在于字体标签，字体标签结构如下：

![](../Images/540774198652df96bc216eaff0f93630.png)

程序在初始化一个LOGFONT结构体时，未对用户输入的字体名进行长度校验，直接进行copy发生溢出，漏洞函数的代汇编代码如下：

![](../Images/8b298a081ed25603257b42b777606dfa.png)

交叉引用得到LOGFONT结构体指针是由调用sub\_421E39的sub\_421774函数传入，结构体存在于sub\_421774的函数栈上，所以可以导致栈溢出，覆盖返回地址，劫持执行流，如下图所示：

![](../Images/34980b7a5f2803312bf8dee485a540e0.png)

分析sub\_421774函数，它先调用了漏洞函数sub\_421E39去初始化一个LOGFONT结构体，然后调用相关的API传入这个结构体，从系统获取一个字体名称保存到Name。随后，它将获取到的Name和用户提供的lpLogFont作对比，如果不一致则调用sub\_4115A7函数，这个函数会调用CVE-2017-11882的漏洞函数，如果用户之前打过CVE-2017-11882的补丁程序，在执行CVE-2017-11882函数之后，会根据a3指定的条件来继续调用或者不调用自身，而a3为sub\_421774函数的第三个参数，在这里调用自身传入的第三个参数为0，并且传入的lpLogFont为从系统中获取的Name所以不会发生二次溢出且不会再次调用自身函数，所以函数可以正常返回，相关的反汇编代码，如下所示：

![](../Images/9977c3df6ff765a998f9d53f100fdeca.png)

知道了相关的原理之后，后面的工作就是覆盖返回地址以及结构相应的shellcode，执行恶意操作了，构造shellcode的时候通过寻找最近的ret地址，然后成功绕过了CVE-2017-11882补丁的ASLR（地址随机化）的安全保护措施，并攻击成功。

可以看到溢出部分的最后两个字节为25 00，00为终止符，拷贝时遇到00就停止，按照小端地址布局，poc运行时，EIP只会被覆盖低位的2个字节，这样就可以绕过ASLR，执相关的shellcode代码，如下图所示：

![](../Images/9661dd37f41eb49e3d9109bd2fc4cd0d.png)

通过执行shellcode代码，直接调用WinExec，然后执行恶意代码，动态调试测试样本，如下图所示：

![](../Images/4c4fd74b87e6cd92a4d6e83775c19c8d.png)

至此整个利用CVE-2017-11882漏洞补丁进行攻击的CVE-2018-0802文件构造就完成了，当打开该文档后会自动弹出计算器程序，通过我们捕获的相应的样本，该漏洞可利用来执行任意程序，包含各种远控、挖矿、勒索样本等，它利用了rtf文档的一个特性，在打开rtf文档时会将嵌入到文档中的文件自动释放到系统%temp%目录下，捕获到的样本就是利用这个特性在rtf文档中嵌入恶意EXE文件，然后再利用该漏洞去执行释放在%temp%目录下的文件，嵌入到rtf的PE文件如下图所示：

![](../Images/203fdeaa8d9969f72e0c05777d24022d.png)

这样一个具有攻击性的rtf文档就形成了，该文档在被word程序打开后将会由于自身机制释放相关的恶意程序到%temp%目录下，之后由于公式编辑器的漏洞利用了WinExec函数执行了”cmd /c %tmp%\\virus.exe”，实现了最终的攻击行为，如下图所示：

![](../Images/b6aa0de0c12011785f809c494bd67e86.png)

通过这种方式，各大杀毒厂商已经发现大量利用CVE-2017-11882和CVE-2018-0802漏洞来攻击的在野远控类样本，同时这类攻击可利用来执行任意的恶意程序，可能后续会出现相关的勒索，挖矿以及DDOS类样本。

 

 

解决方案

 深信服提醒广大客户，及时安装微软发布的相关补丁，以防止通过CVE-2018-0802漏洞利用进行勒索、挖矿、远控、DDoS等病毒的攻击。

 

1\. 下载微软最新补丁

https://portal.msrc.microsoft.com/en-US/security-guidance/advisory/CVE-2018-0802

![](../Images/34cb37e732d16921a315a51d63e04454.png)

2.  开启Windows自动更新

开启Windows自动更新或者手动更新Windows到最新版本，最新版本已经将此漏洞模块（EQNEDT32.EXE）从Offcie中删除，并不再支持旧版本的公式格式。

![](../Images/a15e1dede43d84e577c723f125d3f60a.png)

3\.  在注册表中取消漏洞模块（EQNEDT32.EXE）的注册

64位操作系统的64位Office、32位操作系统的32位Office：

**Reg add “HKLM\\SOFTWARE\\Microsoft\\Office\\Common\\COMCompatibility\\**

**{0002CE02-0000-0000-C000-000000000046}” /v “Compatibility Flags” /t REG\_DWORD /d 0x400**

 

64位操作系统上的32位Office：

**Reg add “HKLM\\SOFTWARE\\Wow6432Node\\Microsoft\\Office\\Common\\COM Compatibility\\{0002CE02-0000-0000-C000-000000000046}” /v “Compatibility Flags” /t REG\_DWORD /d 0x400**
