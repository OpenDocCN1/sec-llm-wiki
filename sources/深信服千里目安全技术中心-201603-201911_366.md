近日，多个 0DAY 频发，WebLogic 反序列化绕过漏洞重现，CVE-2017-3248 漏洞补丁可绕过利用。Drupal 内容管理系统被曝存在远程代码执行漏洞。

  

漏洞一、Weblogic反序列化漏洞

  

ADLab 发表 WebLogic 反序列化漏洞预警。此漏洞源于今年 1 月 WebLogic 官方发布的 CVE-2017-3248 反序列化漏洞，官方补丁可被绕过所致。

  

关于反序列化漏洞，将追溯到 2016 年全面爆发的高危 JAVA 反序列化漏洞，‍‍序列化就是把对象转换成字节流，便于保存在内存、文件、数据库中；反序列化即逆过程，由字节流还原成对象。Java 中的 ObjectOutputStream 类的  writeObject()  方法可以实现序列化，类 ObjectInputStream 类的 readObject() 方法用于反序列化。下面是将字符串对象先进行序列化，存储到本地文件，然后再通过反序列化进行恢复的样例代码：

![](../Images/2cdfc88e93d30906aceb20b91d7c77bc.png)

问题在于，如果 Java 应用对用户输入，即不可信数据做了反序列化处理，那么攻击者可以通过构造恶意输入，让反序列化产生非预期的对象，非预期的对象在产生过程中就有可能带来任意代码执行。

  

WebLogic 是一款知名的 JAVA 应用。2017 年 1 月，WebLogic 官方发布了编号为 CVE-2017-3248 的反序列化漏洞补丁，该漏洞的修复方式与之前一样，采用黑名单的方式过滤危险的反序列化类，但是这种修复方式很被动，存在被绕过的风险，只要发现可用并且未在黑名单之外的反序列化类，那么之前的防护就会被打破，系统遭受攻击。

  

**漏洞影响**

本次曝出的 WebLogic 反序列化绕过漏洞影响 WebLogic 10.3.6.0, 12.1.3.0,12.2.1.0, 12.2.1.1 多个版本。

  

**安全建议**

WebLogic 官方还未针对本次绕过漏洞发布安全补丁，受影响用户可升级 JDK 版本或升级 WebLogic、删除不需要的页面，清理不安全的第三方库来缓解反序列化漏洞的影响。

  

漏洞二、Drupal远程代码执行漏洞

  

2017 年 6 月 21 日，Drupal 官方发布了一个编号为 CVE-2017- 6920 的漏洞，影响为 Critical。这是 DrupalCore 的 YAML 解析器处理不当所导致的一个远程代码执行漏洞，影响 8.x 的 DrupalCore。

  

攻击者通过序列化一个 GuzzleHttp\\Psr7\\FnStream 类, 将结果写入到文件，序列化后的字符串如图：

 

![](../Images/927fbe79b750d1436d492f6824ef3bf8.png)

随后进一步给字符串加上 !php/object 标签。

 

![](../Images/7db3ff1a87810c8e5c49781de776034a.png)

登录管理员账号，访问如下路径，*http://xxx/admin/config/development/configuration/single/import*，将提前创建好的字符串粘贴到 configuration 处，点击 import 可成功执行 phpinfo 函数，如下图所示。

 

![](../Images/c024caa0820333be43350b7e83b701ca.png)

**安全建议**

最新发布的 Drupal 8.3.4 已经修复了该漏洞，请受影响用户尽快升级系统，湖区方案防护。下载链接：*https://www.drupal.org/SA-CORE-2017-003*

例外，想要利用此漏洞，需要网站获取管理员权限，利用难度非常大。
