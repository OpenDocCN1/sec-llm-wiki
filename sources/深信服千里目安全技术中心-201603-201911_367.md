# 【漏洞预警】Joomla! 3.7.0 Core 曝高危 SQL 注入漏洞

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=Mzg2NjgzNjA5NQ==&mid=2247514088&idx=1&sn=cb533a71b621ece2dd5152040a65b113&chksm=ce463cf8f931b5ee5d84b86dd24098f16679901006e5f3900e98c25bd951075ece9af11243c0&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=Mzg2NjgzNjA5NQ==&mid=2247514088&idx=1&sn=cb533a71b621ece2dd5152040a65b113&chksm=ce463cf8f931b5ee5d84b86dd24098f16679901006e5f3900e98c25bd951075ece9af11243c0&scene=27#wechat_redirect)

Joomla! 被曝出 3.7.0 版本存在高危 SQL 注入漏洞，CVE 编号 CVE-2017-8917。该漏洞出现在 3.7.0 版本新引入的一个组件 “com\_fields”中，此插件无需登录验证，任何人都可以访问。因此，该漏洞极易被攻击者利用，危害极大。

  

千里百科

Joomla! 是一套全球知名的内容管理系统，使用 PHP 语言加上 MySQL 数据库所开发的开源软件系统，适合从个人网站到百货销售类型等各类网站。

  

漏洞详情

Joomla! 3.7.0 Core SQL 注入漏洞出现在 3.7.0 版本新引入的一个组件“com\_fields”，该组件从相同名称的管理端组件继承了一些视图，这样可以缩减大量相同功能的代码，提高代码的复用性

 

![](../Images/072879100d026df61760c758434363f8.png)

从上面的代码片段可以看到，$config\['base\_path'\] 变量的值是 JPATH\_COMPONENT\_ADMINISTRATOR 常量传过去的，这个常量值代表管理员组件目录的本地路径，这样做会造成 Joomla! 从这个路径获取视图 views 和模块 models，要成功的操作需要构造相关参数和值，view 参数的值是 fields ，layout 参数的值是 modal。那么构造的 URL 如下：

![](../Images/09ee374722c55a67b762a6cb4ff6365e.png)

访问此 URL 可以显示这个站点所有自定义字段的列表。

需要注意的是这是唯一的一个管理员视图的组件字段（我们前面说到的 $config\['base\_path'\] 变量这块）。这种情况下，我们可以直接从管理员模型获取数据。具体的漏洞位于：

.MarchModelFields  模型下的  ./administrator/components/com\_fields/models/fields.php 文件中。

最终我们定位到出问题的方法 getListQuery

![](../Images/3a58c6b8de5532ff5167e7c2ec11df02.png)

如果不熟悉 Joomla! 执行 SQL 查询，$query-> order() 真的只是一个方法，其输入将被连接到一个查询的 ORDER BY 语句，这里就是我们要做的最后一件事，将未经检查的用户输入带入到这里，看看会发生什么

![](../Images/a7278d1bd52480bea07f21a69f32c9af.png)

用户输入传入到 list.fullordering，因为 FieldsModelFields 模型从继承 JModelList 类，它同样也包含上面的代码段。你可能会注意到它对内容做了一些验证，然后相应地设置 list.direction 和 list.ordering，但是 list.fullordering 呢？

![](../Images/34dcd4ba3029d087e0798f82bcfcd0bf.png)

在 switch 语句之后，不管它是否生成了一个有效的 list.direction 或者 list.ordering，我们可以利用这行指令通过我们输入的内容来设置我们想要的值。

所以为了利用这个漏洞，攻击者必须做的是为 URL 添加适当的参数，以便注入到 SQL 查询。
