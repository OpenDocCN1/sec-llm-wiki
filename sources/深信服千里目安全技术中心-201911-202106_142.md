# 【漏洞通告】MinIO 服务端请求伪造漏洞

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=Mzg2NjgzNjA5NQ==&mid=2247514686&idx=2&sn=9fe00ffcea9c6c6eeba73bd9904156b6&chksm=ce46312ef931b838e11eebaec21d0036fd4ed457552b90003ef9be1978bae1777e1fb4fdc072&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=Mzg2NjgzNjA5NQ==&mid=2247514686&idx=2&sn=9fe00ffcea9c6c6eeba73bd9904156b6&chksm=ce46312ef931b838e11eebaec21d0036fd4ed457552b90003ef9be1978bae1777e1fb4fdc072&scene=27#wechat_redirect)

**漏洞名称** : MinIO 服务端请求伪造漏洞

**组件名称** : MinIO

**威胁等级** : **高****危**  

**影响范围** : MinIO < RELEASE.2021-01-30T00-20-58Z

**漏洞类型** : 服务端请求伪造

**利用条件** : 1、用户认证：不需要用户认证

2、触发方式：远程

**造成后果** : 在服务器端请求伪造（SSRF）攻击中，攻击者可以利用服务器上的功能来读取或更新内部资源。

  

    

**漏洞分析**

    

  

**1 ****组件****介绍**

MinIO 是一个基于Apache License v2.0开源协议的对象存储服务。它兼容亚马逊S3云存储服务接口，适合于存储大容量非结构化的数据，例如图片、视频、日志文件、备份数据和容器/虚拟机镜像等，而一个对象文件可以是任意大小，从几kb到最大5T不等。

MinIO是一个轻量的服务,可以很简单的和其他应用的结合，类似 NodeJS, Redis 或者 MySQL。

  

**2 漏洞描述**

2021年2月2日，深信服安全团队监测到一则MinIO组件存在服务端伪造请求漏洞的信息，漏洞编号：CVE-2021-21287，漏洞等级：高危。该漏洞是由于MinIO组件中LoginSTS接口逻辑设计不当，导致服务端请求伪造漏洞。攻击者通过精心构造URL来修改对此功能的调用。在服务器端请求伪造攻击中，攻击者可以利用服务器上的功能来读取或更新内部资源，可能结合内网其他服务进行执行任意命令。

  

**3 ****漏洞分析**

MinIO中的LoginSTS接口用于代理AWS STS登录请求，将发送到JsonRPC的请求转化成STS的方式，再转发给本地的9000端口。

![](../Images/f34f5933a231d472326c562e89f44f09.png)

由于MinIO将请求转发本地监听，直接从请求HTTP头部Host中获取本地地址，并将其作为本地转发的URL的IP地址。由于请求头攻击者可控，最终导致服务端请求伪造漏洞。

**影响范围**

    

  

MinIO是一个轻量的服务,可以很简单的和其他应用的结合。可能受漏洞影响的资产广泛分布于世界各地，中国大陆省份中，浙江、北京、广东、上海、山东、江苏、四川等省市占比接近 70%。

  

目前受影响的MinIO版本：

MinIO < RELEASE.2021-01-30T00-20-58Z

  

    

**解决方案**

    

  

**1 ****官方修复建议**

当前官方已发布受影响版本的对应补丁（当前官方已发布最新版本），建议受影响的用户及时更新官方的安全补丁（及时更新升级到最新版本）。链接如下：

https://github.com/minio/minio/releases/tag/RELEASE.2021-01-30T00-20-58Z

  

**2 ****临时修复建议**

部署MinIO的服务器上，配置环境变量MINIO\_BROWSER禁用浏览器前端访问。

*   
*   

```
export MINIO_BROWSER=offminio server /data
```
