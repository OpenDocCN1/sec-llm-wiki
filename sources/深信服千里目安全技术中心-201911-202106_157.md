# 【更新】深信服EDR快速响应支持防护Windows condrv.sys内存损坏漏洞

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=Mzg2NjgzNjA5NQ==&mid=2247514678&idx=1&sn=7186ade6d5a231532d9610763e376541&chksm=ce463126f931b830e51c23547251f4d0d6707b023c24584c7a5048bf96f19a276c9467aed513&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=Mzg2NjgzNjA5NQ==&mid=2247514678&idx=1&sn=7186ade6d5a231532d9610763e376541&chksm=ce463126f931b830e51c23547251f4d0d6707b023c24584c7a5048bf96f19a276c9467aed513&scene=27#wechat_redirect)

近日，深信服安全团队追踪一则Windows 10 condrv.sys存在内存损坏漏洞的信息，漏洞等级为**高危**。该漏洞是由于Windows 10中condrv设备不正确的设置导致异常。

攻击者可利用该漏洞，通过在浏览器的地址栏中打开特定路径或构造恶意快捷方式进行钓鱼攻击，最终导致Windows 10蓝屏崩溃。

 

**该漏洞当前暂无官方解决方案，深信服EDR轻补丁功能快速响应支持免疫该漏洞，EDR用户可升级至V3.2.33版本，开启轻补丁漏洞免疫功能进行一键防护。**

**漏洞名称** : Microsoft Windows condrv.sys内存损坏漏洞

**威胁等级**: 高危  

**影响范围** : Windows 10

**漏洞类型**: 内存损坏

**利用难度** : 简单

  

  

  
  
  
  
  
  
 

**漏洞分析**  

  
  
  
  

**1 漏洞（补丁）分析**

调试查看漏洞堆栈：

![](../Images/1bb2f052aec887a6f43425f5721dca89.png)

  

从堆栈可以看出当打开此路径的时候，进入内核的对象管理器依次解析对象目录，直到解析到\\device\\condrv发现这是个设备对象，且设备对象类型是有ParseProcedure例程的。

故调用设备对象的ParseProcedure，即函数IopPraseDevice。函数内部在处理完请求时尝试去关闭这个文件对象，如下图：

![](../Images/ca3dde82af7639bdacb50bacf18ae623.png)

  

关闭文件对象就会对相应的驱动发送IRP\_MJ\_CLEANUP IRP，驱动为condrv.sys。

蓝屏的直接原因如下：

![](../Images/190e28ad180e3a130c9ce5324c8f42d3.png)

即从IRP中获取文件对象FILE\_OBJECT，然后获取FILE\_OBJECT的FCB即FsContext成员。但此时FsContext为NULL，所以就导致了空指针引用的问题。

![](../Images/591a3919c09dda05bcba99d3c56ae6d3.png)

  

**2 根因分析**

我们可以认为这个文件对象是“非法”的, 那么可能从创建初始化的时候就可能出现问题。

对内核有了解的应该知道，如果要引用设备对象那么必然会对设备对象所在的驱动发送IRP\_MJ\_CREATE。我们找到condrv.sys 使用IDA载入，查看反汇编如下：

![](../Images/7e79033363a6a7cc90df1c38ed9d5131.png)

  

它会循环比较文件名是不是预定义的几个，如果是，则调用预定义的创建回调函数，如下：

![](../Images/723b0793faf48fec03736b13607ebc67.png)

  

Poc里面打开的是kernlcontect所以IRP\_MJ\_CREATE最终会调用函数CdCreateKernelConnection， 查看该函数如下：

![](../Images/14e7d2aec94f361b647d0061a3950811.png)

  

第一个判断是如果先前模式是usermode则返回0xc000022，即拒绝访问；也就是设计之初内核是不允许用户直接使用这个符号链接的。

  

但是问题出就出在这个直接返回拒绝，因为这是在处理IRP。它没有设置IRP的状态码以及调用IoCompleteRequest结束IRP。导致当IRP返回时，其IoStatus.Status为0。（0表示成功）

![](../Images/b6751927c3b8652642f02cb2a91a4b06.png)

  

而在函数IopPraseDevice中是以IoStatus.Status为准,所以IopPraseDevice 错误的认为IoCalldriver是成功的，进而引发后续错误地关闭文件对象从而导致蓝屏。手动测试修改IoStatus.Status为失败值，蓝屏消失。
