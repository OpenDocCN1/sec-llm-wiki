# 【高级持续性威胁追踪】Purple Fox 新变种讲述从钓鱼网站到Rootkit的故事

| 背景介绍

  

Purple Fox，又称“紫狐”，是一个于2018年9月被首次观察到，在2019年曾使用过NSIS（Nullsoft Scriptable Install System）和Rig漏洞利用攻击工具包，后来转而采用PowerShell来实现无文件执行。本次发现的新变种利用了CVE-2020-0674的IE远程代码执行漏洞、CVE-2018-8120和CVE-2020-1054两个Win32k.sys提权漏洞，并且利用了Dll类型的白文件进行新一轮的网络攻击。

![](../Images/19253e07161a432b06cf15468806fbed.png)

  

深信服团队对Purple Fox家族病毒有着持续的追踪和监测。从以往的攻击历史来看，Purple Fox的攻击链正在变长，利用手段复杂多变，但最终都以MSI安装包程序安装成熟的Rootkit驱动程序实现持久化。病毒多次变种连接的C2域名中故意包含“githack”字符串，可见黑客组织在传播恶意软件的同时也在虚张自己的声势。

![](../Images/872b9141a519fb6df3b14389cf4844fa.png)

  

本次发现的Purple Fox病毒挂附网站链接

steep-boat-06f5.qqztw.workers.dev/uoppg.swf，该网站是俄罗斯一家新闻网站，现如今已经被标记为钓鱼网站。网站的目的文件是uoppg.swf是一个flash文件，当用户在安装Flash播放器的情况下访问该链接时会解析恶意的uoppg.swf文件触发IE漏洞CVE-2020-0674，执行JS脚本，并调用Powershell。

## | 脚本执行与漏洞利用

  

![](../Images/b8ebedab47b12ee681edcc036df30904.png)

  

如图所示是Purple Fox的部分攻击过程，可见攻击链风格仍然保持比较长而且复杂的风格。该过程通过IE漏洞远程执行代码启动powershell脚本，并提权释放执行了MSI程序安装包。

![](../Images/7bbbd5ae57bad8ff53b7b8ecadd2de3d.png)

  

首先从网站下载的uoppg.swf文件以标准zlib方式压缩，其中隐藏了JS脚本，该JS脚本采用eval和unescape等常用方法加密，在浏览器中运行解密后可得到另一段被混淆的JS脚本。

![](../Images/f836c21b670dde0c18ec81980ad6976d.png)

  

JS去混淆后发现是上图的一段POC利用html脚本程序，其目的是为了触发IE远程代码执行漏洞CVE-2020-0674，启动主机系统自带的mshta.exe进程。

![](../Images/4324fbb65300e4d24b6874ad5296d4f2.png)

  

Mshta.exe会启动powershell执行base64加密的脚本。对脚本解密后代码如下：

![](../Images/5c4c3e12fe46b91d431ebb4dbdab4b69.png)

  

代码作用是每隔2分钟链接另一网站下载并执行up.php。

![](../Images/a4961c7971b9f58a97ff03d454de87d5.png)

  

如上图，up.php开始一段被红框标记的解密之后发现其实是绕过AMSI的代码：

\[Runtime.InteropServices.Marshal\]::WriteInt32(\[Ref\].Assembly.GetType('System.Management.Automation.amsiUtils').GetField('amsiContext',\[Reflection.BindingFlags\]$(NonPublic,Static).GetValue($null),0x5B9D83E7);

![](../Images/f23b34873831ce719de872cc0cf9765c.png)

  

除此之外，该powershell脚本中创建“Global\\ifqGpTzdTzhMHSOz”互斥体，通过WMI枚举操作系统信息，控制下载后续阶段的payload，并滥用msi.dll安装即将下载的MSI安装包，该安装包包含API接口来安装并执行“紫狐”Rootkit的主组件。

![](../Images/2b70f9e48796f36ebb2d8a39e24ea072.png)

  

而payload2\_up脚本使用了

new-object system.io.compression.deflatestream(\[io.memorystream\] \[system.convert\]::frombase64string(obfusecode,,\[system.io.compression.compressionmode\]::decompress)| foreach-object {new-objectsystem.io.streamreader($\_ ,\[system.text.encoding\]::ascii ) } ).readtoend()方法，从中解密出了2.6M左右的PowerSploit模块，其中包含base64加密的CVE-2018-8120和CVE-2020-1054漏洞利用程序。该工具主要是在当前powershell的用户不是管理员的情况下进行提权的。

![](../Images/fc980f6bf44e185a6fb5568a71e670a2.png)

  

Payload3\_up其实是一个被BASE64加密的MSI程序安装包，从中提取到的Binary.Prereq.dll和Binary.aicustact.dll两者都是Caphyon LTD公司正常签名产品文件。经查询这种利用方式类似于Amavaldo银行木马的攻击方式，Binary.Prereq.dll的别名又叫msi8ad3.tmp，而使用AICustAct.dll目的是用于检查可用的Internet连接，出自于https://www.advancedinstaller.com。

  

  

## | “紫狐”Rootkit释放与安装

  

![](../Images/a483d5536ed327f139724274bfacd4d4.png)

  

上图是MSI安装包执行之后的执行流程。在运行一系列进程之后再次启动了powershell执行命令Start-Sleep -Seconds 900;Restart-Computer -Force，作用是延迟15分钟后强制重启计算机。

![](../Images/5ae98c9c2ef5cd26daa0cf088951c798.png)

  

在AICustAct.dll中发现的大量字符串表明此前说过的大量进程启动的原因是AICustAct.dll在尝试检查可用的Internet连接。

![](../Images/b147a669ba5746be70cfc5f35df226c9.png)

  

病毒样本在C:/Windows目录下释放了.xml和.xlog的伪装文件，实际上分别是32位和64位的dll，真实名字分别是SetupAs64.dll和SetupAs32.dll。其中SetupAs64.dll导出函数dbkFCallWrapperAddr、\_\_dbk\_fcall\_wrapper和Servicemain，而SetupAs32.dll只有导出函数Servicemain。

![](../Images/43060754b18ea164ea536c78bce659dd.png)

  

Dll使用Delphi编译，并带有vmp壳。为了免杀故意填充HEX数据到10M文件大小，在powershell关机重启后，将会删除填充的数据，并组装成为Ms58ABB22CApp.dll。

![](../Images/33df0dc445caf0e588414f5722d1a94e.png)

  

使用X64dbg简单调试该dll，发现会拼接字符串在system32的目录下释放Ms58ABB22CApp.dll。在system32的drivers目录下释放dump\_58ABB22C.sys驱动程序。

![](../Images/96bfdc783b43f4e0fd9ca1463e8bbb5d.png)

  

发现并提取出了C:/Windows/system32目录下隐藏的Ms58ABB22CApp.dll。

![](../Images/a42d1c94275dc70ab08cada482b3bb9a.png)

  

同时在C:/Windows下新建目录AppPatch并释放了隐藏不可见的Rootkit组件。

![](../Images/84af30f6c61cb6a60ffaf92e1c3eb58d.png)

  

该攻击模块会生成日志并且从日志中可以看出与之前Rootkit组件的攻击方式非常相似。相关详细分析可以参考链接https://zhuanlan.zhihu.com/p/44849652

![](../Images/b601c35cf59310c1980a1bc8e09a0253.png)

  

利用Svchost注册表添加自启动项的方式比较独特，恶意Ms58ABB22CApp.dll会随svchost.exe进程启动时以服务形式加载。

![](../Images/67670446d73e525eb82a930c5e0dc052.png)

  

最终Ms58ABB22CApp.dll注入shellcode到svchost.exe中，开启多个线程循环检测当前网络状态，如果网络不通会递增端口缓慢尝试通信。

![](../Images/318c5f337cb3d37650e56c6aa3801c66.png)

![](../Images/588e80583de1c88b10c5607c8f5a3f47.png)

  

相反如果当前网络通信正常，则会以受害主机为平台疯狂爆破多处远端IP地址445端口，同时在局域网内发送ARP请求进行横向爆破。

![](../Images/f119ba95fa0df6be57233f51101fe9bd.png)

  

从svchost.exe中提取到没有vmp壳的dll，发现dll功能比较完善成熟。该dll代码中有混淆，且自定义了字符串解密函数，并通过上图中自定义注册表修改函数sub\_427E88修改注册表禁用安全模式。

![](../Images/4385b2b729d78cf6b5db6eeaea2ea9f3.png)

  

和以往披露不同的是病毒dll还使用了Delphi 的TSMBIOS库获取BIOS等主机硬件信息。该项目是github开源项目，相关链接为https://github.com/RRUZ/tsmbios。

![](../Images/55a73905859f86973228e1f1a9b7a08b.png)

  

此外还会获取物理驱动器信息并与驱动程序通信控制实现持久性后门植入，可见用户一旦感染此类后门想彻底清除是很困难的。

显然“Purple Fox”背后的黑客组织一直在强化自己的Rootkit驱动后门功能，并尝试用多种方式落地安装Rootkit后门。从此次攻击手法来看，黑客组织基本上实现了从点击一下挂马网站链接到植入内核驱动后门的攻击链，用户主机在防御薄弱的情况下可能会被植入严重后门。攻击链虽然很长，但却利用了变化文件哈希的手法来躲避常规静态检测，而且真正的恶意代码只在系统进程内存中展开运行，可见黑客组织的技术也愈来愈成熟。深信服团队会持续关注此类病毒并做后续分析与查杀。
