| 样本概述


深信服安全团队近期捕获到了疑似摩诃草组织（APT-C-09）的攻击样本，原始doc文档通过DDE利用下载了一份签名带有“Bobsoft”字样的Delphi装载器，该装载器最终加载了一款远控木马，但可能由于其网络通信特征与已知远控木马存在一定的相似度，匹配到了多款RAT的标签。经过关联分析，最终确定了加载的远控木马属于Darktrack RAT家族，也同样使用Delphi语言进行编写。


此样本主要起到下载器的作用，利用了Office DDE特性来获取远程攻击载荷并执行，首次上传仅被两款引擎检出，样本在VirusTotal上体现了 其具有良好的免杀效果。


样本名为AIT.doc，MD5为1331b068477e2974894a899c855bfc4b，正文标题为“American Institute in Taiwan (AIT), Director Brent Christensen statement on 823 ceremony”（美国台湾研究所（AIT）所长布伦特·克里斯滕森在823仪式上发表声明）。根据近期发生的事件来看，诱饵文档是对应了2020年8月23日美国台湾学会（AIT）所长首次与中国台湾领导人一起纪念823典礼。红色醒目文字“无法从中船贸易连接更新消息，请允许该文件下载消息”，关联到中国船舶工业贸易公司（CSTC），疑似是针对该公司的诱饵文档。

| 样本行为


AIT.doc（原始样本，下载者）

打开样本属性页，可以看到编写者名为”kim“，文档编写日期为2020/8/24，于近期制作完成并完成投放。


打开样本后会弹出典型的DDE利用弹窗，两次点击“是”后会执行内嵌的恶意DDE代码。


在正文最下方换行符处点击右键-切换域代码，可以显示出未经混淆的DDEAUTO代码，其功能是恶意软件下载器，主要执行如下四个步骤：

  1. 执行cmd命令行调用，使用certutil获取远程可执行文件http://coremailxt5mainjsp.com/ps/sgrm.exe；

  2. 使用attrib命令修改sgrm.exe为隐藏文件；

  3. 使用start命令启动sgrm.exe;

  4. 无论以上命令成功与否，使用taskkill结束cmd进程。


sgrm.exe（远程样本，Delphi加载器）

该样本由delphi编写，伪装成打印机实用程序，实际上算是一层外壳，用于保护里面加密存储的远控木马程序。外壳代码使用了自定义的VEH异常处理程序来构造异常，并对加密代码进行处理，解密后的代码包含了许多对抗沙箱、杀软和分析人员的手段，包括代码加密/乱序、检测虚拟环境、路径、杀软进程、分析工具进程、检测调试等等，最终会使用Process Hollowing技术执行Darktrack RAT。外壳分析如下：


使用pestudio查看其静态信息，发现其使用Delphi语言编写，平均熵值较高，可能采用了代码压缩/加密技巧。Delphi签名包含了字符串“BobSoft Mini Delphi -> BoB / BobSoft”，与2017年FireEye报道过的Delphi Packer如出一辙，但功能和细节上略有出入。


尝试使用Delphi反汇编工具DarkDe4获取汇编代码，发现只有一个表单创建函数，最后会创建一个线程继续执行。


FormCreate中首先使用cpuid获取到CPU信息，并检测是否处于Parallels和Microsoft Hyper-V虚拟环境下。


获取了三个时间相关函数的地址，并创建新线程。


新线程有大量nop指令，用于拖慢分析速度。


首先调用wglCreateContext()创建一个新的线程上下文，GetSystemTime()获取本机格林威治标准时间，若年份大于2018则继续，GetSystemTimeAsFileTime()获取到的是从1601年1月1日到目前经过的纳秒，保存到lpSystemTimeAsFileTime指向的FILETIME结构体。


FileTimeToSystemTime()转换FILETIME格式为SYSTEMTIME格式，返回值非零表示成功，零表示失败，成功则继续，调用两次GetSystemMetrics获取屏幕分辨率。


执行判断，若屏幕分辨率高于800*600，且两次获取到的SYSTEMTIME年份相同则继续。


AddVectoredExceptionHandler()添加VEH异常处理程序，执行函数0x49D060，函数内部仅处理两种异常，异常码0x80000001对应STATUS_GUARD_PAGE_VIOLATION，异常码0xC0000094对应STATUS_INTEGER_DIVIDE_BY_ZERO。


设置完VEH异常处理程序后立即触发了除0异常（0xC0000094）。


可以看到此处分支将0x49D010函数地址拷贝至线程上下文CONTEXT EIP（+0xB8）处。


第一次异常处理完毕后会进入到ntdll领空执行ZwContinue，新的EIP指向了0x49D010函数。


0x49D010函数首先调用VirtualAlloc()申请一块大小为0x11FE3的内存，接着使用0xC3进行填充，最后使用VirtualProtect()将此块内存的保护属性设置为PAGE_READWRITE|PAGE_GUARD，PAGE_GUARD属性会导致该内存区域下一次被访问时抛出一个STATUS_GUARD_PAGE_VIOLATION异常（0x80000001）。


设置完页保护属性后，将ECX的值设为硬编码的0x4B1BB，用于后续的校验；紧接着会jmp跳转到该内存区域触发第二次异常0x80000001，异常抛出后会进入到之前的VEH异常处理程序。


校验原CONTEXT的ECX异或0x28792值是否等于0x63629，若校验相同则去掉其PAGE_GUARD属性。


进入自定义解密函数解压缩并解密代码和数据。


修改CONTEXT EIP，使其指向解压后的代码。


第二次异常0x80000001处理结束，步过ZwContinue则会跳转到新的EIP处执行。


解密后的代码通过段寄存器FS进行递归寻址以获取kernel32基地址ImageBase，寻址流程如下：

FS:[0x30] → _PEB+0xC → _PEB_LDR_DATA + 0xC → _LIST_ENTRY(self) → FIRST(ntdll) → FIRST(kernel32) + 0x18 → kernel32_ImageBase


遍历kernel32导出函数，计算函数名对应的16进制值是否为0x8ABF0222，获取了VirtualAlloc函数并调用，创建一片空内存区域。


接下来重复进行上述寻址操作，新分配的内存用于存储多个关键函数的地址。


Kernel32的函数寻址完毕后，调用LoadLibraryA()加载shell32.dll、user32.dll，继续重复上述寻址操作。


上述寻址完毕后再次调用VirtualAlloc()分配内存区域，大小为0x1000。


通过段寄存器获取ntdll的基地址，继续重复上述寻址操作。

通过user32.CallWindowProcW()调用大小为0x1000的新内存区域的kernel32.GetTickCount()。


调用kernel32.GetModuleFileNameW()获取自身路径。


继续分配内存，大小为0x7FEE0。


遍历进程列表，存放至大小为0x7FEE0的内存区域。


反沙箱分析：判断自身路径名中是否含有“malware”、“sandbox”、“sample”字符串。


反杀软：判断进程列表中是否含有avastsvc.exe + avastui.exe + aswidsagent（AVAST）、avgsvc.exe + avgui.exe（AVG）、avp.exe（Kaspersky）、bdagent.exe + bdwtxag.exe（BitDefender）、dwengine.exe（Dr.Web）、mpcmdrun + msmpeng + nissrv（Windows Defender）。


反调试器、反行为监控：判断进程列表中是否含有procexp64.exe、procmon64.exe、procmon.exe、ollydbg.exe、procexp.exe、windbg.exe。


反调试：通过ZwQueryInformationProcess获取ProcessDebugObjectHandle（0x1E），ProcessDebugFlags（0x1F），多次使用FS段寄存器获取PEB.BeingDebugged，检测调试器是否存在。


若以上反分析检测均通过，则从资源头中装载资源0x4CDE28，分配同等大小0x1AF的内存进行储存。


执行自定义算法解密资源，出现wscript.shell字符串。


调用SHGetFolderPathW()获取开始菜单启动目录（0x7），拼接字符串后可以发现其会将在开始菜单启动目录下创建winhost.vbs。


创建notepad进程，分配进程内存并写入数据，使用注入APC队列的方式向notepad注入代码，以建立基于winhost.vbs的持久化机制。


注入notepad进程的APC代码先尝试删除再创建位于开始菜单启动目录的winhost.vbs，其功能是调用wscript.shell来实现开机启动sgrm.exe。


再次分配内存，加载资源，执行三次，最后异或解密得到一个PE。


创建自身挂起进程（0x4），使用Process Hollowing技术将解密的PE注入到挂起进程并执行。


以上步骤执行成功则结束自身进程，否则重复上述创建傀儡进程的步骤直到成功。


解密的PE（Darktrack RAT，Delphi编写）

通过分析，最终能够确定该PE属于Darktrack家族的远控木马，软件版本为0.21。提取后使用DarkDe4工具进行反汇编，发现并没有任何与窗体/表单绑定的函数，提取的PE样本只支持通过注入的方式进行调用，无法独立运行。


但可以从模块信息和组件列表中观察到样本可能具有的功能，包括但不限于资源管理器、键盘记录等。


发现硬编码的可疑字符串及内网IP信息，可能是RAT内置的测试用默认配置。


设置注册表开机自启。


从资源头查找“CFG”节并加载，里面包含了服务端的配置信息，真正的C2为79.141.168.109:4975。


创建互斥体“021MUTEX021”，保证只有一个实例正在运行。


创建线程进行键盘记录，记录文件名为klog.dat，保存至当前运行目录。


创建Socket连接C2服务器79.141.168.109:4975，连接成功后搜集系统信息，包括用户名、计算机名、系统版本、当前窗口名、系统语言，发送至C2服务器。

| 关联分析


通过资源头中的配置信息格式来看，C2端口位于开头IP位于末尾，连接密钥也保存至端口之后，不难发现此样本实际上属于Darktrack RAT的早先版本。


Darktrack Alien是一个专业且免费的远程解决方案，使用Delphi编码。网上流传的Darktrack RAT版本号为Alien 4.1，与此份样本相比更新了大量的功能。


通过对互斥量“021MUTEX021”的搜索，还发现了早先2018 年3月27日上传的一份样本，版本号和主要功能与此样本保持一致，此可见其服务端生成器早已经被使用。


对于样本使用的Delphi加载器（Bobsoft），从2017年火绒对其进行曝光至今，仍有大量样本使用此加载器来隐藏最终的恶意模块，包括但不限于Formbook、Lokibot、AgentTesla。Bobsoft强大的反分析技巧也随着版本迭代正在不断增强，在如今甚至于未来仍旧给安全软件和分析人员带来很大的挑战。
