# Apache IoTDB 远程代码执行漏洞CVE-2020-1952

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=Mzg2NjgzNjA5NQ==&mid=2247514544&idx=2&sn=6837e11c212f0131947555ff705a0a73&chksm=ce4632a0f931bbb6d7c00fad467cc0b19ed576db2eaaff2f3f5474e2a35a426fe782e5053632&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=Mzg2NjgzNjA5NQ==&mid=2247514544&idx=2&sn=6837e11c212f0131947555ff705a0a73&chksm=ce4632a0f931bbb6d7c00fad467cc0b19ed576db2eaaff2f3f5474e2a35a426fe782e5053632&scene=27#wechat_redirect)

Apache IoTDB 0.9.0-0.9.1版本和0.8.0-0.8.2版本存在远程代码执行漏洞，漏洞是由于上述Apache IoTDB版本默认在31999端口开启RMI服务，并且没有做任何过滤，攻击者利用该漏洞可以导致远程代码执行。

  
  
  
  

**漏洞名称**：Apache IoTDB远程代码执行漏洞CVE-2020-1952

**威胁等级**：高危

**影响范围**：  

Apache IoTDB 0.8.0-0.8.2  

Apache IoTDB 0.9.0-0.9.1

**漏洞类型**：远程代码执行

**利用难度**：简单

  
  
  
  

  

    

**漏洞分析**

      

**1 Apache IoTDB组件介绍**

Apache IoTDB是为时间序列数据设计的集成数据管理引擎。它为用户提供数据收集，存储和分析服务。由于其轻巧的架构，高性能和丰富的功能集以及与Apache Hadoop，Spark和Flink的深度集成，Apache IoTDB可以在物联网工业领域满足海量数据存储，高速数据提取和复杂数据分析的需求。

  

**2 漏洞描述**

Apache IoTDB 0.9.0-0.9.1版本和0.8.0-0.8.2版本存在远程代码执行漏洞，漏洞是由于上述Apache IoTDB版本默认在31999端口开启RMI服务，并且没有做任何过滤，攻击者利用该漏洞可以导致远程代码执行。

  

**3 漏洞分析**

使用Apache IoTDB 0.8.2进行分析，从下图中可以看出默认JMX端口是31999，并且开启了远程连接功能。

![](../Images/07d3d9960f25f3424b755bab9c47ad67.png)

上述信息表明已经存在RCE的可能，如果再能够寻找到一个存在漏洞的jar包就可以对其进行利用。经过寻找发现commons-collection4，如果之前接触过反序列化漏洞，就会想到ysoserial中的gadget。

![](../Images/f918c8da7b21b4275433d54ba7b22c0c.png)

这里使用ysoserial的RMIRegistryExploit类对其进行攻击，可以看一下该类的部分内容。

![](../Images/54938d52e99f4a239b81dd42748bc92c.png)

main方法部分主要是获取ip，端口，命令以及gadget的信息，使用Registry类获取目标主机的远程对象注册表的引用。

![](../Images/3373bd3bc9ac95b224ac8e97b1dc90e4.png)

exploit方法通过使用选取的gadget构造payload，这里我们选择常用的CC链。通过getObject获取CC链生成的handler对象，使用代理类进行封装，利用bind方法绑定构造的remote远程引用，实现反序列化攻击。

  

**4 漏洞复现**

搭建Apache IoTDB 0.8.2漏洞环境，使用上述提到的ysoserial的payload进行攻击，最终执行命令，弹出计算器，效果如图：

**影响范围**

**解决方案  
**

    

  

**1 修复建议**

Apache IoTDB 0.9.2及以后的版本已经防御此漏洞，请受漏洞影响的用户下载最新版本。

  

下载链接：

http://iotdb.apache.org/zh/

  

**2 临时解决方案**

将conf目录下的iotdb-env.bat或者iotdb-env.sh中的 LOCAL\_JMX设置为yes

  

**3 深信服解决方案**

【**深信服下一代防火墙**】可轻松防御此漏洞， 建议部署深信服下一代防火墙的用户更新至最新的安全防护规则，可轻松抵御此高危风险。

  

【**深信服云盾**】已第一时间从云端自动更新防护规则，云盾用户无需操作，即可轻松、快速防御此高危风险。

  

【**深信服安全感知平台**】可检测利用该漏洞的攻击，实时告警，并可联动【深信服下一代防火墙等产品】实现对攻击者ip的封堵。

  

【**深信服安全运营服务**】深信服云端安全专家提供7\*24小时持续的安全运营服务。在漏洞爆发之初，云端安全专家即对客户的网络环境进行漏洞扫描，保障第一时间检查客户的主机是否存在此漏洞。对存在漏洞的用户，检查并更新了客户防护设备的策略，确保客户防护设备可以防御此漏洞风险。
