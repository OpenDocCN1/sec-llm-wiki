# 微软6月份补丁日重点漏洞

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=Mzg2NjgzNjA5NQ==&mid=2247514512&idx=1&sn=a169a3343eec1154561c0bf05a54b89d&chksm=ce463280f931bb966f302f0d9b3b1e83295337ad9ab643a725915b144b5d107cda628249df0e&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=Mzg2NjgzNjA5NQ==&mid=2247514512&idx=1&sn=a169a3343eec1154561c0bf05a54b89d&chksm=ce463280f931bb966f302f0d9b3b1e83295337ad9ab643a725915b144b5d107cda628249df0e&scene=27#wechat_redirect)

2020年6月10日（北京时间），微软发布2020年6月份安全更新，**共发布了129个漏洞的补丁程序，涵盖了Microsoft Windows、Internet Explorer（IE）、Office、Microsoft Edge、Windows Defender等众多组件和软件。128个CVE中共有11个被微软官方标记为Critical，118个被标记为“Importent”**。

  

此外，**在本月的安全补丁中，有23个针对远程代码执行漏洞，5个针对拒绝服务漏洞，70个针对权限提升漏洞以及11个针对信息泄露漏洞。**整体来看，此次补丁日发布的安全补丁基本解决了本月Windows中被发现的漏洞或Bug。

  

需要注意的是，微软在2020年已经连续4个月发布110多个CVE补丁程序，创造同时期发布补丁数量新高。

  

深信服安全研究团队依据漏洞重要性和影响力进行筛选，对下述漏洞做重点说明。

  

    

**漏洞分析**

    

  

  

**1\. CVE-2020-1299**

LNK远程代码执行漏洞。与以往的LNK远程代码执行漏洞一样，用户在处理特制LNK时即可触发漏洞。要利用此漏洞，攻击者可以向用户提供包含恶意的.LNK文件和关联的恶意二进制文件的可移动驱动器或远程共享，当用户在Windows资源管理器或任何其他解析.LNK文件的应用程序中打开此驱动器（或远程共享）时，恶意二进制文件将在目标系统上执行攻击者指定的代码。

  

成功利用该漏洞的攻击者可以在目标系统上以当前用户权限执行任意代码。由于该漏洞影响范围较广，且利用方式简单，因此需要引起重视，不要访问来源不明的驱动器或共享文件。

  

  

**2\. CVE-2020-1300**

Windows 远程代码执行漏洞。该漏洞主要是由于Windows在处理cab格式文件时发生错误导致。.cab文件是Windows系统上的一种压缩文件，可以使用WinRAR或者IE5以上自带的IExpress打开。要利用此漏洞，攻击者需要诱骗目标用户打开特制的.cab文件，或者将.cab文件伪装成打印机驱动程序进行安装来触发漏洞。

  

成功利用此漏洞的攻击者可以实现远程代码执行。此漏洞影响Windows版本众多，且多为国内用户使用的主流系统，用户需提高警惕，不要打开来源不明的.cab文件。

  

  

**3\. CVE-2020-1281**

Windows OLE远程代码执行漏洞。该漏洞主要是因为Windows OLE未能正确处理用户输入导致。OLE是微软开发的一项专有技术，允许嵌入和链接到文档和其他对象，即允许编辑应用程序（Word、Excel等）将文档的一部分导出到另一个编辑应用程序。要利用此漏洞，攻击者需要先特制一个文件，然后诱骗目标用户打开，文件来源可以是web网页或者钓鱼邮件。

  

同样，该漏洞影响范围广泛，需要引起重视，不要下载来源不明的文件或者打开来源不明的邮件。

  

  

**4\. CVE-2020-1301**

Windows SMB远程代码执行漏洞。该漏洞位于SMBv1的驱动中，SMBv2和SMBv3版本不受影响，漏洞触发点位于在处理MS-FSCC协议中的FSCTL\_SIS\_COPTFILE请求时，没有完整验证SI\_COPYFILE结构，导致整数溢出。要利用该漏洞需要先通过SMB用户认证，这提高了漏洞的利用难度。但SMBv1部署在Windows 7- Windows 10的所有版本中，因此漏洞影响范围较广，需要引起重视。

  

成功利用该漏洞的攻击者可以实现在目标主机上执行任意代码。深信服千里目实验室后续将发布针对该漏洞的详细分析文章及解决方案。

  

  

**5\. CVE-2020-1213/1216**

VBScript 远程代码执行漏洞。这两个漏洞都位于IE的VBScript Engine中，但漏洞类型不同。CVE-2020-1213是一个UAF漏洞，CVE-2020-1216是一个类型混淆漏洞，均可以导致远程代码执行。要想利用此漏洞，攻击者采取的主要方式仍然是钓鱼形式，可以构造一个钓鱼网站诱使目标用户进行访问，或者在承载IE呈现引擎的应用程序或Microsoft Office文档中嵌入标记为“初始化安全”的ActiveX控件。

  

漏洞主要影响IE 9和IE 11，相对来说降低了影响范围。为保证不受漏洞影响，应警惕访问一些网站或者打开一些来源不明文件，尽可能降低受攻击风险。

**修复建议**

    

  

**1\. 部分缓解措施：**

**CVE-2020-1301**：

1.使用强密码进行SMB用户认证，避免使用弱密码被破解登录。

  

2.建议关闭SMBv1，SMBv1存在诸多安全问题，如非必要，建议关闭SMBv1，使用SMBv2或更高版本协议进行替代，各Windows系统版本关闭SMBv1的方法可参考微软官方推荐方案：

*https://docs.microsoft.com/zh-cn/windows-server/storage/file-server/troubleshoot/detect-enable-and-disable-smbv1-v2-v3*

  

**2\. 官方更新补丁：**

微软官方已更新受影响软件的安全补丁，用户可根据不同版本系统下载安装对应的安全补丁，安全更新链接如下：*https://portal.msrc.microsoft.com/en-us/security-guidance/advisory/CVE-2020-1299**https://portal.msrc.microsoft.com/en-us/security-guidance/advisory/CVE-2020-1300**https://portal.msrc.microsoft.com/en-us/security-guidance/advisory/CVE-2020-1281**https://portal.msrc.microsoft.com/en-us/security-guidance/advisory/CVE-2020-1301**https://portal.msrc.microsoft.com/en-us/security-guidance/advisory/CVE-2020-1213*
