**漏洞分析**

**组件介绍**

WebLogic是美国Oracle公司出品的一个Application Server，确切地说是一个基于Jave EE架构的中间件，WebLogic是用于开发、集成、部署和管理大型分布式Web应用、网络应用和数据库应用的Java应用服务器。

  

WebLogic将Java的动态功能和Java Enterprise标准的安全性引入大型网络应用的开发、集成、部署和管理之中，是商业市场上主要的Java（J2EE）应用服务器软件（Application Server）之一，是世界上第一个成功商业化的J2EE应用服务器，具有可扩展性、快速开发、灵活、可靠性等优势。

![](../Images/21ebc4929212857f3732ca510f9d4e02.png)

**漏洞描述**

  

2023年1月18日，深信服安全团队监测到一则Oracle WebLogic官方发布安全补丁的通告，共修复了11个WebLogic安全漏洞。

![](../Images/27532231d30d3dcc89de4876b497ad7f.png)![](../Images/467042c12a6da933cdd01ed3b7422637.png)![](../Images/21ebc4929212857f3732ca510f9d4e02.png)

**高危漏洞描述**

  

**Oracle WebLogic Server 远程代码执行漏洞CVE-2022-42920**

该漏洞是由于在Oracle WebLogic Server中使用了存在漏洞的第三方软件“Apache Commons BCEL”，**攻击者通过利用受影响的服务器的多个API发送恶意数据进行攻击，可能会造成Oracle WebLogic Server程序执行攻击控制的字节码，有潜在的远程代码执行可能。**

  

**Oracle WebLogic Server 拒绝服务漏洞CVE-2022-40150**

该漏洞是由于在Oracle WebLogic Server中使用了存在漏洞的第三方软件“Jettison”，**未经身份验证的攻击者通过向受影响的服务器发送恶意的XML或JSON数据进行攻击，可能会造成Oracle WebLogic Server程序崩溃、资源消耗等影响****。**

  

**Oracle WebLogic Server 拒绝服务漏洞CVE-2022-40153**

该漏洞是由于Oracle WebLogic Server 使用了存在漏洞的第三方软件“XStream”，**攻击者可利用该漏洞，构造恶意数据进行攻击导致解析器崩溃，最终可能会导致拒绝服务。**

  

**Oracle WebLogic Server拒绝服务漏洞CVE-2022-25647**

该漏洞是由于Oracle WebLogic Server 中的方法“writeReplace()”可对不受信任的数据进行反序列化，**攻击者可利用该漏洞，构造恶意数据进行攻击，最终可能会导致拒绝服务。**

  

**Oracle WebLogic Server 信息泄露漏洞CVE-2023-21842**

该漏洞是由于Oracle WebLogic Server的Web容器允许未经验证的攻击者通过HTTP访问受影响的服务器，**攻击者可利用该漏洞，未经授权访问关键数据，造成服务器敏感信息泄露。**

  

**Oracle WebLogic Server 信息泄露漏洞CVE-2023-21837**

该漏洞是由于Oracle WebLogic Server 的核心组件允许未经验证的攻击者通过IIOP访问受影响的服务器，**攻击者可利用该漏洞，未经授权访问关键数据，造成服务器敏感信息泄露。**

  

**Oracle WebLogic Server 拒绝服务漏洞CVE-2023-21838**

该漏洞是由于Oracle WebLogic Server 的核心组件允许未经验证的攻击者通过T3或IIOP访问受影响的服务器，未经授权的**攻击者可利用该漏洞，导致Oracle WebLogic Server挂起或频繁重复崩溃（完全DOS）。**

  

**Oracle WebLogic Server 远程代码执行漏洞CVE-2023-21839**

该漏洞是由于Oracle WebLogic Server 的核心组件允许未经验证的攻击者通过T3或IIOP访问受影响的服务器，**攻击者可利用该漏洞，未经授权访问关键数据，造成服务器敏感信息泄露并执行任意代码。**

  

**Oracle WebLogic Server 信息泄露漏洞CVE-2023-21841**

该漏洞是由于Oracle WebLogic Server 的核心组件允许未经验证的攻击者通过T3或IIOP访问受影响的服务器，**攻击者可利用该漏洞，未经授权访问关键数据，造成服务器敏感信息泄露。**

  

**Oracle Coherence 远程代码执行漏洞CVE-2022-23305**

该漏洞是由于Oracle Coherence使用了存在漏洞的第三方软件“Apache Log4j”，**攻击者可利用该漏洞，构造恶意SQL语句进行攻击并执行查询，最终可能会导致远程执行代码。**

  

**Oracle Coherence 反序列化漏洞CVE-2022-45047**

该漏洞是由于Oracle Coherence使用了存在漏洞的第三方软件“Apache Mina SSHD”，**攻击者可利用该漏洞，构造恶意数据进行反序列化攻击并获取私钥，最终可能会导致远程执行代码。**

**解决方案**

![](../Images/21ebc4929212857f3732ca510f9d4e02.png)

**官方修复建议**

当前官方已发布最新版本，建议受影响的用户及时更新升级到最新版本。链接如下：

https://www.oracle.com/securityalerts/cpujan2023.html

![](../Images/21ebc4929212857f3732ca510f9d4e02.png)

**如何检测组件版本**

用户可以通过进入WebLogic安装主目录下的OPatch目录，在此处打开命令行，输入.\\opatch lspatches命令，结果如下：

![](../Images/beeb88dbd45e7e7fa73558a6c71e5eff.png)![](../Images/21ebc4929212857f3732ca510f9d4e02.png)

**打补丁/升级方法:**

**12.2.1.3版本**

**步骤1  更新Opatch补丁升级工具**

进入:

C:\\oracle\\Middleware\\Oracle\_Home\\OPatch目录

执行以下命令：

C:\\oracle\\Middleware\\Oracle\_Home\\OPatch > opatch version

如图，如果不是13.9.4.0.0版本则需要先升级Opatch版本，否则直接进入步骤2

![](../Images/6050b55b7c0446e433f795f873ee784b.png)

**Opatch升级方法：**

  

**1. 删除旧版本Opatch**

进入C:\\oracle\\Middleware\\Oracle\_Home目录，

重命名OPatch、oracle\_common、oui、inventory四个目录

  

**2. 下载并解压安装包**

由于WebLogic在持续更新，请从官网（https://support.oracle.com）下载最新补丁。

  

**3. 安装Opatch**

执行以下命令：

java -jar opatch\_generic.jar -silent oracle\_home=C:\\oracle\\Middleware\\Oracle\_Home

如果出现如下报错，则切换到jdk安装目录的bin目录下重新安装即可

  

![](../Images/80e834718a8d54c0bf4ed5d4a6e46786.png)

**4. 检查安装结果**

OPatch、oracle\_common、oui、inventory四个目录已经重新生成，重新执行命令：

C:\\oracle\\Middleware\\Oracle\_Home\\OPatch > opatch version Opatch版本变为13.9.4

  

**步骤2  下载并解压补丁包**

由于WebLogic在持续更新，请从官网（https://support.oracle.com）下载最新补丁。

  

**步骤3 打补丁前建议阅读README文档**

**步骤4 停止WebLogic服务**

**步骤5 安装补丁**

进入补丁包解压目录，执行以下命令：

C:\\oracle\\Middleware\\Oracle\_Home\\OPatch\\opatch  apply

  

**步骤6 重启WebLogic服务**

重启WebLogic服务，并验证业务是否能够正常使用。

 

注：若补丁导致业务异常，使用如下命令进行回滚：

C:\\oracle\\Middleware\\Oracle\_Home\\OPatch\\opatch  rollback -id  <补丁ID>

  

**其他版本**

其他版本必须先升级到12.2.1.3以上版本，才能打补丁，由于WebLogic属于收费服务，升级方法请联系官方技术支持解决。

![](../Images/21ebc4929212857f3732ca510f9d4e02.png)

**临时修复建议**

  

该临时修复建议存在一定风险，建议用户可根据业务系统特性审慎选择采用临时修复方案：  

  

**1.可通过关闭IIOP协议对此漏洞进行临时防御。操作如下：**

在WebLogic控制台中，选择“服务”->”AdminServer”->”协议”，取消“启用IIOP”的勾选。并重启WebLogic项目，使配置生效。

  

![](../Images/6adc001ccab054ba670983239924b9f4.png)

**2.对T3服务进行控制**

控制T3服务的方法:

  

![](../Images/63710628a18f37f06ea40adbf575a6bb.png)

  

在上图这个WebLogic界面中选择安全-筛选器，在下方出现的界面中找到“连接筛选器”，在里面输入

security.net.ConnectionFilterImpl

然后在连接筛选器规则中输入

127.0.0.1 \* \* allow t3 t3s，0.0.0.0/0 \* \* deny t3 t3s

最后保存并重启服务器即可生效。

![](../Images/21ebc4929212857f3732ca510f9d4e02.png)
