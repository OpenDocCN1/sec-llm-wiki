企业资产视角下的高可利用漏洞


当我们都在讨论“被疫情偷走的两年”时，2021 年的记忆点又真真切切得提醒着我们，2021 已结束，2022 已来临。2021 年是“十四五”规划的开局之年，不可否认“十四五”规划加速了全社会的数字化转型，相应也对数字化转型下的数据安全和数字产业安全提出了更高、更明确的要求。而网络安全中长期未能妥善解决的漏洞管理也将面临更大的挑战。


深信服2021年对企业资产组成进行调研、统计及分析，企业仍旧以定制化业务为主，但相较于2020年定制化业务占比下降，通用组件占比增加。由于黑客利用通用组件漏洞发起攻击成本较低，因此绝大部分黑客倾向于利用通用组件漏洞对系统发起攻击，故本篇报告重点研究对象为通用组件下的高可利用漏洞以及漏洞管理技术的发展曲线。

深信服千里目安全实验室将深信服威胁对抗指挥中心、深信服安全服务及威胁情报相关数据进行概括、总结及分析编写出此份基于深信服漏洞基础数据的《2021年漏洞威胁分析报告》。

2021 漏洞风险预览

深信服针对 2021 年的服务对象资产进行调研、统计、聚合、分析，发现企业资产仍旧以定制化业务为主，但相较于 2020 年的 70.7% 有所减少；相应的通用组件由 2020 年的 29.3% 上升至 35.9%。从攻击角度看，黑客利用通用组件漏洞发起攻击成本较低，故绝大部分黑客更倾向于利用通用组件漏洞对系统发起攻击。

本报告采取随机抽样调查模式，本次抽取样本中包含 200+ 业务系统的上千余个系统弱点，并对其攻击方式进行分析，得出弱点类型分布图，其中占比最高的仍旧是信息泄露、暴力破解和弱口令。

深信服千里目安全实验室自 2016 年正式成立通用组件漏洞研究团队，从 0 到 1，在实验室及真实场景不断探索和调整方向，到如今准确定位并聚焦关键组件，深入分析关键组件相关高可利用漏洞。深信服威胁对抗指挥中心漏洞库中的漏洞数据不断丰富，并根据全球攻击面绘测数据结合漏洞在野利用情况，对漏洞情报进行动态分析及研判，2021 年深信服重点关注组件 200 余个，聚焦漏洞 400 余个。

图 3 深信服聚焦组件漏洞,2021

此外深信服千里目安全实验室秉承着“以黑客视角看安全的理念”，从攻击者角度出发，从前沿攻击技术中窥探攻击者的攻击思路进而推断攻击者钟爱的漏洞方向、跟踪 APT 组织动向捕获 APT 组织的常用漏洞等等。通过对黑客行为进行深入分析、聚类以及抽象逆向推导出黑客重点关注组件，深信服千里目安全实验室漏洞研究团队以组件为单位研究极具威胁的“高可利用漏洞”，赋能深信服安全产品，为客户业务安全保驾护航。

重点关注厂商漏洞回顾

2021 年深信服千里目安全实验室从客户资产出发，全年实时跟踪了 200 余个组件的 400 余个全新漏洞，其中重点投入分析研究了 200 余个。在 2021 年重点关注的漏洞中，深信服千里目安全实验室漏洞研究团队挑选出四个重点关注组件加以总结：

1. VMware vCenter Server


VMware vCenter Server 是美国威睿(VMware)公司的一套服务器和虚拟化管理软件。该软件提供了一个用于管理 VMware vSphere 环境的集中式平台，可自动实施和交付虚拟基础架构。根据全网数据统计，VMware vCenter Server 在全球的使用量将近十万，大部分集中在美国，中国的使用量排在第二位。

图 4 VMware vCenter Server 全球使用量数据统计,2021


在国内的数据统计中，广东、上海、江苏、浙江等省市使用量较高。


图 5 VMware vCenter Server 国内使用量统计,2021

2021 年官方披露了诸多 VMware vCenter Server 的漏洞，涉及远程代码执行、未授权访问、DoS、信息泄漏、权限提升等多种类型，详情见附件 1。

2019 年 VMware vCenter Server 发布的漏洞类型主要集中于信息泄漏；2020 年，只爆出了四个漏洞；2021 年发布的漏洞数量呈爆发式增长，并且出现 CVE-2021-21972、CVE-2021-21985、CVE-2021-22005 三个严重漏洞。CVE-2021-21972 存在于vCenter对于上传压缩文件的处理上；CVE-2021-21985 问题出现在 Bean 对象的反射调用中；CVE-2021-22005 可以被看作是两个漏洞，一个是存在于 CEIP（用户体验计划）的日志写入，另一个则是存在于 analytics 服务对于 manifest 数据的处理上，最终会调用 Velocity 对数据中的表达式进行处理。从这三个严重漏洞造成的原因上也可以看出，作为大型管理平台，VMware vCenter Server的漏洞并不局限于某一服务或某一漏洞类型。随着越来越多安全研究员关注 vCenter 漏洞，并且 vCenter 走向 7.0 版本增加了更多的服务，预计2022年，VMware vCenter Server漏洞数量仍会有一定提升。


2. XStream


XStream 是 Java 类库，用来将对象序列化成 XML(JSON)或反序列化为对象。XStream 在运行时使用 Java 反射机制对要进行序列化的对象树的结构进行探索，并不需要对对象作出修改。XStream 可以序列化内部字段，包括私 private 和 final 字段，并且支持非公开类以及内部类。

XStream 作为 Java 开发基础类库，应用在各个框架，中间件，Web 应用中，其中包括 Struts2,Spirng,Weblogic 等组件。根据全网数据统计，应用 XStream 的常用软件在全球的使用量将近十万，大部分集中在中国和美国，中国的使用量排在第一位，具体如下图所示：

图6 应用 XStream 的常用软件全球使用量数据统计图,2021

在国内的数据统计中，广东、北京、上海、浙江、江苏等省市使用量较高。

图7 应用 XStream 的常用软件国内使用量数据统计图,2021

2021 年官方披露了 26 个 XStream 的漏洞，其中 7 个严重级别的漏洞，18 个高危级别的漏洞。漏洞类型涉及任意代码执行、拒绝服务、任意文件删除、服务端请求伪造等多种类型，详情见附件2。

XStream 漏洞主要集中在 2021 年期间(2021年之前的XStream漏洞数量为 8 个)。2021 年发布的漏洞数量呈爆发式增长(总计 26 个漏洞)，并且出现较多的危害性较高的任意代码执行漏洞。由于 XStream 1.4.17 版本及之前，针对反序列化漏洞采用的是黑名单防御机制，此防御机制存在较大的绕过风险，这也是 XStream 在 2021 年频频出现漏洞的原因之一。在 XStream 1.4.18 版本中，XStream 采用了白名单防御机制，此防御机制的安全效果较高，绕过风险较低，但是存在一定的软件兼容性问题。如果官方持续使用并维护此防御机制，预计 2022 年，XStream 漏洞将大幅度降低。


3. F5 BIG-IP


F5 BIG-IP 是美国 F5 公司的一款集成了网络流量管理、应用程序安全管理、负载均衡等功能的应用交付平台，在该平台可自定义集成多个软件模块。

根据深信服空间绘测的数据，截止目前为止，互联网上的 F5 BIG-IP 约有 110000+ 个，其中大部分分布在美国，其次是中国，第三是日本。国内分户主要集中在广东、北京、上海等地，分布图如下：

2021年官方披露了诸多 F5 BIG-IP 的漏洞，详见附件 3，其中大部分是漏洞都需要进过身份认证之后才可以使用，少部分可以绕过权限认证达到 RCE，如 CVE-2021-22986 利用前后端的认证缺陷绕过了身份认证并通过 /mgmt/tm/util/bash 直接执行命令。

在最近几年中，F5 BIG-IP 的漏洞逐年递增，最近三年中每年披露的漏洞甚至高达上百个，2021严重级别的漏洞也出现了不少，对攻击者而言利用价值高的漏洞主要是在未经身份认证的远程代码执行漏洞，目前F5 BIG-IP的漏洞趋势也是从之前的破坏系统的可用性逐渐往获取服务器权限上过渡。

4. Google Chrome


Google Chrome 是由 Google 开发的免费网页浏览器。根据 netmarketshare 统计的数据，截止 2020 年 10 月，桌面浏览器 Chrome 的市场占有率为 69.28% 。远超第二名的 Edge 的 7.75%。而在移动端，Chrome 的市场占有率也达到了 63.71%，占据了浏览器市场绝对重要的地位。

2021 年 Google 官方披露并修复了了 18 个高危漏洞，详见附件 4，其中大部分是沙箱内远程代码执行漏洞，少部分可以进行沙箱逃逸提升标签页的权限，部分因漏洞利用代码被公开对老版本Chrome用户造成较大安全威胁。

回顾 2021 年 Chrome 披露的漏洞，v8 类型混淆类的占比比较大，v8 内对象是依赖原型而不是依赖类，每个对象有不同的属性从而有不同的“形状”，这个“形状”通过“map”来描述，当漏洞得到越界写入的能力时，可以覆盖一个对象的类型为另一个对象，这样可以任意操作对象和数组达到任意地址读写的能力，最终造成远程代码执行，尤其是v8以及Blink。预计2021年之后，Chrome漏洞的爆发依然不会减少，仍是一个值得重点关注的组件。

Microsoft MSHTML 远程代码执行漏洞

2021 年 9 月微软官方发布安全更新，其中包含 Microsoft MSHTML 组件存在远程代码执行漏洞的信息，漏洞编号：CVE-2021-40444，漏洞威胁等级：高危。该漏洞是由于组件自身缺陷而引起的，攻击者可利用该漏洞，通过构造恶意的Office文档发送给被攻击方，最终导致远程代码执行。

影响范围

微软 ActiveX 控件是微软公司的 COM 架构下单产物。其在 Windows 操作系统中应用广泛，Windows 中的 Office 套件，IE 浏览器等产品中有广泛应用。通过 ActiveX 控件可以与微软的 MSHTML 组件进行交互，从而引起安全问题。Windows 作为全球安装用户量最大的操作系统，使用范围遍及世界各地，涉及用户量多，导致该漏洞的危害等级较高。

03

SonarQube API未授权访问漏洞

SonarQube 是一款代码质量审计和管理分析平台，2020 年官方披露了 SonarQube API 未授权访问漏洞，漏洞编号：CVE-2020-27986，漏洞威胁等级：高危。SonarQube 系统在默认配置下，会将通过审计的源代码上传至 SonarQube 平台。SonarQube 某接口存在信息泄露漏洞，攻击者利用该漏洞可以获取部分敏感信息。

影响范围

目前受影响的 SonarQube 版本：

SonarQube < 8.6

关联事件

2021 深信服安全团队监测到境外黑客组织 AgainstTheWest（以下简称 ATW）针对托管在外网的 SonarQube 平台进行了定向攻击，窃取我国重要单位源代码，并在境外论坛上进行出售。

通过深度分析，我国有不少 SonarQube 平台服务器存在一定的安全隐患并直接暴露在互联网上，ATW 黑客组织就利用 SonarQube 存在的安全问题，针对托管在外网的 SonarQube 平台进行了定向攻击，导致相关单位失陷造成源码泄露。

在分析 ATW 入侵事件中发现，其可通过 SonarQube 平台的未授权访问漏洞来进行入侵。SonarQube 系统在默认配置下，会将通过审计的源代码上传至 SonarQube 平台。由于 SonarQube 缺少对 API 接口访问的鉴权控制，攻击者利用该漏洞，可在未授权的情况下通过访问上述 API 接口，获取 SonarQube 平台上的程序源代码，构成项目源代码数据泄露风险。

解决方案

登录 SonarQube 系统，在 Administation -> Security -> Force user authentication 设置开启。


另外，除未授权访问漏洞外，分析中还发现攻击者可通过 SonarQube 平台的信息泄露漏洞，以及弱口令爆破的方式实施入侵，获取该部分 SonarQube 平台上的项目源代码。

托管于外网的 SonarQube 平台的服务器有大量 IP 地址位于我国，黑客可利用上述方法均可能导致相关单位失陷，从而发生供应链攻击。对于已经部署 SonarQube 平台的客户，建议如下：

1、 建议客户及时升级 SonarQube 平台至最新版本；

2、 修改 SonarQube 平台的默认配置，包括修改默认账号名、密码、端口号(9000)，并且禁止使用弱口令；

3、 审计托管在 SonarQube 的项目源码，若源码包含数据库配置信息、内部系统的账号密码、内部 API 接口等敏感信息，应及时通知相关人员进行更改；

4、 禁止 SonarQube 平台的外网访问权限，如若必须开放外网访问，将 SonarQube 平台放置于防火墙等边界安全设备保护范围内，并且定期排查是否存在未授权访问的异常记录。

04

Apache Log4j2 远程代码执行漏洞

2021 年 12 月，官方发布  Apache Log4j2 组件存在远程代码执行漏洞的信息漏洞编号：CVE-2021-44228。漏洞威胁等级：严重。该漏洞是由于 Apache Log4j2 某些功能存在递归解析功能，攻击者可利用该漏洞在未授权的情况下，构造恶意数据进行远程代码执行攻击，最终获取服务器最高权限。

2021 年 12 月 10 日，Apache Log4j2 官方针对此漏洞发布的 2.15.0-rc1 版本存在绕过，官方再次发布 2.15.0-rc2 版本以解决绕过问题。

影响范围

Apache Log4j2 广泛地应用在中间件、开发框架、Web 应用中。漏洞危害性高，涉及用户量较大，导致漏洞影响力巨大。目前受影响的 Apache Log4j2 版本：

2.0.0 ≤ Apache Log4j ≤ 2.15.0-rc1
关联事件

2021 年深信服陆续捕获到恶意黑客组织利用 Apache Log4j2 远程代码执行漏洞进行恶意攻击的多起安全事件，深信服安全专家分析后发现该漏洞被广泛应用于勒索、挖矿、僵尸网络上。多起案例显示，攻击者利用该漏洞可致受害系统从瘫痪、业务中断到重要数据被加密、系统长期被监控。下列四个案例摘取自深信服安全技术团队捕获、整理的公开案例，但网络空间中利用 Apache Log4j2 远程代码执行漏洞攻击的事件绝不止于此。


事件一：比利时国防部遭不明攻击者攻击

比利时国防部发言人奥利维尔·塞维林 (Olivier Séverin) 当地时间 2021 年 12 月 20 日对比利时《标准报》说，国防部发现其计算机网络受到不明攻击者的成功攻击，该部已采取措施隔离受影响的网络区域。并且证实这次攻击是成功利用了 log4j2 的漏洞。

发言人表示部分计算机网络无法使用，处于瘫痪状态。如，邮件系统已经停机数日。计算机攻击是在上周才发现的，也是 Log4j2 软件安全漏洞披露之后发生的。目前尚不清楚谁是此次攻击事件的幕后黑手。

事件二：利用 Log4j2 漏洞传播新型挖矿病毒

2021 年 12 月 15 日。深信服捕获到专门针对某 OA 系统的利用 CVE-2021-44228 漏洞进行传播的挖矿病毒。深信服安全专家命名为 WhiteLotusMiner。目前 WhiteLotusMiner 通过 Log4j2 远程代码执行漏洞下发挖矿脚本，深信服安全团队捕获 3 种样本，分别对应 Windows 和 Linux 系统。

从漏洞利用方式和捕获的样本可知，攻击目的明确，攻击目标选择针对性强，但此挖矿病毒攻击手法简单，攻击过程没有考虑检测规避，说明了攻击者本身水平不高，由于 Aache Log4j2 远程代码执行漏洞(CVE-2021-44228)广泛存在各类组件中，且漏洞利用难度较低，容易与其他已知的各类攻击形式相结合，对攻击者攻击技术水平要求不高，因此低水平攻击者也能发起有针对性的高危攻击。预计未来一段时间内，此类低水平的攻击者，利用该漏洞的攻击事件仍会持续增加。

事件三：利用 Log4j2 漏洞传播新型挖矿病毒

2021 年 12 月 13 日。深信服捕获到勒索病毒 Tellyouthepass 最新变种已经开始使用CVE-2021-44228 漏洞专门针对某 OA 系统对 Windows 和 Linux 双平台进行攻击。

一旦被勒索，没有作者私钥的情况下，被病毒加密后文件无法解密。根据其历史版本，该家族有使用永恒之蓝漏洞(MS17-010)进行内网传播，危害极大，建议受 CVE-2021-44228 立即修复。

事件四：Conti 团伙已武器化 Log4Shell 并建立完整的攻击链

Palo Alto Networks 曾称 Conti 为目前已知活跃的数十个勒索软件组织中“最无情的组织”之一。2021 年 12 月 18 日，安全公司 Advanced Intelligence 称总部位于俄罗斯的 Conti 成为首个将 Log4j2 武器化的专业级勒索运营团伙，现已拥有完整的攻击链。

AdvIntel 研究人员指出，存在 Log4Shell 漏洞的服务器已成为攻击者攻击的靶点，据调查 Log4j2 远程代码执行漏洞正在被更多恶意团伙利用。常言道：“如果有一天发现了一个漏洞使用在 APT 攻击中，那么不久它就会被勒索软件武器化”。

从弱点管理到攻击面管理

基于“十三五”打下的良好基础，2021 年“十四五”开局，伴随着业务数字化转型、云基础设置转型、Sass 转型、物联网发展以及 IT 和运营体系的融合、远程办公等，网络安全的重要性也大幅提升。而目前网络安全市场碎片化现象突出，在弱点管理方面甚至产生了在安全技术趋于成熟、安全产品飞速更新换代的大前提下，安全产品对安全运营（用户）的技能要求越来越高、安全运营对弱点的处置越来越繁琐的前提下，安全效果还得不到提升的怪相。因此网络安全产品如何完成点、线、面、体的跨越显示至关重要。

1. 弱点评估


弱点评估(Vulnerability Assessment)是一个成熟且市场预期较高的技术，也是当下主流的安全实践。在网络攻防场景中，攻击者不断地发现弱点并执行攻击，也就要求防御方在攻击者利用弱点前，发现并对弱点进行处置。因此防御方必须主动采取策略发现、评估、管理弱点。传统的弱点评估(VA)包含资产发现、资产优先级排序、弱点扫描、扫描结果分析和修补以及持续运营六个步骤。

针对通用组件漏洞，最常用最有效的识别方式还是弱点扫描，弱点扫描器包括网络扫描、主机扫描、数据库扫描等不同种类。是指基于弱点数据库，通过扫描等手段对指定的远程或者本地计算机系统的安全脆弱性进行检测，发现可利用弱点的一种安全检测（渗透攻击）行为。因此扫描效果极大程度上取决于弱点扫描产品的弱点数据库。

弱点评估是指在弱点识别的基础上对弱点的威胁等级、被利用的可能性等进行评估的过程。弱点评估的方法很多，最常见的是通过 CVSS 评分划分漏洞威胁等级，但由于 CVSS 评分更大程度上体现的是弱点技术严重性，因此在弱点管理中单一的采取此种评分方式是不合理的。

随着弱点评估技术发展以及用户对弱点评估期待值的增加，弱点评估工具正在从识别弱点的工具逐步转向成主动评估、管理和报告弱点风险的工具，弱点评估工具也逐渐与弱点优先级排序技术(VPT)结合，实现点到线的提升。

2. 弱点管理

弱点管理(Vulnerability Management)是信息安全操作的基础部分，一般认为的弱点管理框架包含治理、发现、评估、处理、监控和报告五个部分，分为：弱点识别、弱点评估、弱点处置、弱点报告四个步骤。

弱点处置的方法主要是风险缓解和风险接受，对企业而言，最直接的风险缓解方案即是漏洞修复，打补丁，而当漏洞修复成本过高时，存在无法直接打补丁的情况，也可选择降低风险和接受风险。

弱点管理是一个一直都未被妥善处理的老问题。相较于大部分弱点集中在操作系统、中间件、业务应用等方面的传统互联网时代，在 5G 技术、人工智能、大数据、边缘计算、云计算等新 IT 技术迅速发展的当下，弱点数量成倍增加，弱点辐射范围急剧扩张的场景。在此种场景下，传统弱点管理的不足将会被放大。

（1）传统弱点管理在面对大批量的弱点时，显得力不从心。弱点处置往往按照弱点技术严重性的顺序进行处置、修复，而不是弱点或者缺陷实际带来的风险大小，从而导致安全运营人员耗费了大量的精力，却无法保证安全效果。

2. 弱点管理关注的传统IT资产已远不能满足当下需求。弱点管理关注的往往是服务器、网络设备、数据库、业务应用等传统认知的IT资产，随着数字化推进，云端资产、容器、IOT设备以及最容易被忽视的安全设备和影子资产都应该加入被关注的行列。

3. 基于风险的弱点管理

弱点优先排序技术(Vulnerability Prioritization Technology)是针对基于风险的弱点管理(Risk-Based approach to Vulnerability Management)中的一次微创新。随着新 IT 技术迅速发展，容器、移动互联网、IOT 谁被等广泛应用，弱点影响的范围也随之扩大。另一方面从 CNVD 近 5 年来收录的漏洞数量显示，收录漏洞总量最少的 2018 年，全年收录漏洞 13964 个，而总量最多的 2020 年全年收录漏洞数量突破两万，高达 20255 个，面对如此庞大的漏洞数量，传统的弱点评估往往按照弱点技术严重性进行评估，安全运营人员也同样按照弱点技术严重性由高危到低危的顺序进行修复。然而，在每年新发现的近两万个漏洞中，即使安全团队修补了所有高危和严重漏洞，也不过只修复了 24% 的可利用漏洞，也就意味着，安全运营人员有 76% 的时间浪费在短期内几乎不会对系统产生风险的漏洞上。更可怕的是，有 44% 的短期可被利用的漏洞从技术严重性方面被评为中低风险，而中低风险的漏洞也及有可能被安全运营所忽略。因此弱点从来都不能等同相待。

基于上述问题，Gartner 在 2020 年 9 月提出了基于风险的弱点管理(RBVM),基于风险的弱点管理(RBVM)技术包含弱点评估、弱点优先排序、弱点补充控制三个阶段，其中重要的创新就是弱点优先排序(VPT)。在安全运营中，想修复所有的弱点是不可能的，弱点优先排序是采用某些方法和流程，动态的将需要修复的弱点进行优先排序和流程优化，提高修复效率，以达到用最少的时间实现最好的效果。在 2021 年 7 月 Gartner 发布的“Hype Cycle for Security Operations, 2021”中指出，处于膨胀阶段的弱点优先排序(VPT)是最具期待性的新兴技术，距离被市场普遍认可及产品成熟约 2-3 年时间。Gartner 建议，利用弱点优先级技术（VPT）解决方案，实施基于风险的弱点管理办法(RBVM)，将弱点结果带到统一平台进行优先级排序及处理（例如修复），从而提高安全运营效率

4. 新兴概念基于风险的弱点管理

资产一直是网络空间中备受关注的话题，常言道：“你无法保护你看不见的东西”，资产也如是。实战攻防中的首要步骤是攻击面分析与暴露面收敛。攻击方试图通过信息收集获取目标可用的信息，将各攻击点连接汇成攻击面，攻击面越广意味着发现潜在漏洞的可能性越大，攻击成功的概率也就越高。相应地，防守方关注自身的暴露面，分析自身可能存在的安全风险，然后通过安全方案最小化暴露面，以此降低安全风险。随着数字化的推进，网络资产组成发生变化，资产发现和管理也面临着巨大挑战，在面对影子资产、物联网过时的软件、未知开源软件、第三方供应商的资产时，数字资产发现困难、弱点发现和分级困难以及弱点处置困难等问题也随之产生。因此网络防护的任务不应该仅仅是实施工具和分析的组合，识别和保护不断扩大的威胁媒介更是避免成为攻击对象和攻击跳板的关键因素。2021 年 7 月 Gartner 发布的“Hype Cycle for Security Operations, 2021”中提出了两个全新概念——外部攻击面管理(External Attack Surface Management)和网络资产攻击面管理(Cyber Asset Attack Surface Management)。

处于技术萌芽期外部资产攻击面管理(EASM）是发现面向互联网的企业资产和系统及相关弱点而部署的流程、技术和管理服务。包含服务器、凭证、公共云服务器的错误配置和可能会被攻击者利用的第三方合作伙伴的软件代码漏洞。外部资产攻击面管理可以帮助识别未知资产，并提供例如系统、云服务和应用程序等对攻击者可用和可见的信息。

同样处于萌芽期的网络资产攻击面管理(CAASM)专注帮助安全运营人员解决持续的资产可见性和弱点挑战。使企业能够通过与现有工具的 API 集成识别内外部资产，查询综合数据，确定弱点范围与安全控制的差距，并进行修复。网络资产攻击面管理能够通过整体环境的安全控制、安全态势和资产风险的修复和资产修复和处置来改善基本的安全状况。部署网络资产攻击面管理(CAASM)的企业可以对自身系统和手动收集过程的依赖，并通过手动或自动化流程来修复弱点。此外这些可以直观地看到安全工具的覆盖情况，并纠正修复陈旧或缺失数据的原始记录系统。
