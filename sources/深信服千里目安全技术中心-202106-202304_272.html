事件背景






近期深信服安全蓝军高级威胁研究团队捕获到 SideWinder 的恶意文件，经过分析后发现 SideWinder 在2022年1月3号至1月13号之间假冒“巴基斯坦政府内阁秘书处，内阁部门国家电信和信息技术安全委员会”的身份发布《网络安全公告 - Apple 针对网络攻击的威胁通知》公告对巴基斯坦进行钓鱼攻击。


事件发现过程：13号在外部 hunting 发现符合 SideWinder 下载 url 特征的 docx 文件，但是 url 已经失效了。14号捕获到 SideWinder 最新的rtf文件，虽然在外部 hunting 时该文件并没有与13号发现的 docx 产生关联，但是经过分析后发现其使用的域名和该 docx 使用的域名是一致的，可以确定这个 rtf 是 docx下载的远程模板。而且该rtf释放的 1.a 中的 js 代码重写了一个字符串加密方式，对字符串进行加减取余的方式进行多层封装，这是不同于2021年使用异或加密+自定义 base64 的加密方法。以及js脚本中反射加载的 App.dll 增加了使用下载的数据前32位字节循环异或解密后续内容的过程。虽然后续文件的下载 url 也是失效了，但已经足够说明这是一起 SideWinder 的攻击事件了。

恶意文档分析





13号在外部hunting发现符合SideWinder下载url特征的docx文件，但是url已经失效了。文件内容如下。




文档假冒“巴基斯坦政府内阁秘书处，内阁部门国家电信和信息技术安全委员会”的身份发布《网络安全公告 - Apple 针对网络攻击的威胁通知》公告，使用远程模板注入技术，文档打开时会使用url：https[:]//cabinet-gov-pk.ministry-pk.net/14300/1/1273/2/0/0/0/m/files-68ebf815/file.rtf下载file.rtf并加载。




rft文件分析




14号捕获到 SideWinder 最新的 rtf，虽然在外部 hunting 时该文件并没有与13号发现的 docx 产生关联，但是经过分析后发现其使用的域名和该 docx 使用的域名是一致的，可以确定这个 rtf 是 docx 下载的远程模板。


文件中包含两个关键结构：

一个 Package 结构，文件打开时会向 %temp% 路径下释放 1.a 文件。



一个 Equation.3 结构，用于 CVE-2017-11882 的漏洞利用。



漏洞利用执行的 shellcode，通过异或解密出一段 js 脚本，并将这段字符串通过 GetCommandLine 覆盖原有内容。



通过设置全0参数触发 RunHtmlApplication 中使用 GetCommandLine 获取字符串并解析并执行 1.a 中保存的 js 脚本。此 shellcode 与2021年使用的并无太大变化。






1.a文件分析




1.a 文件依旧是 js 脚本，不过更改了字符串的加密方式。

这次使用的加密方式，对字符串进行加减取余的方式进行多层封装。


key 的值总共有13，15，24，12，79。脚本中使用“||”这个逻辑或运算，每个方法相互嵌套，但是 key 的值都是为最开始执行“||”运算的结果。



其中后面的4个方法中的tostring方法使用eval执行了一段加密字符串，该字符串是由字符串反转函数，字符串步长反转函数，进一步封装得到的。

反向加载的App.dll 分析






前半部分代码不变，依旧是检查在上一步 js 代码中获取到的安全软件信息是否包含“aspers”，“avast”和“avg”。只要匹配到其中任意一个，就会使用WMI打开 mshta 进程执行打开诱饵文档的脚本。这一块打开文档的代码在这次攻击时不会执行的。



另一块

代码发生了变化，对下载的内容进行异或解密才进行反射加载。



密钥是下载数据的前32字节，与SideWinder常用文件加密方式一致。相比于2021年9月份的App.dll的添加“MZ”这个PE头魔术字符，更加稳健。

总结




作为2022年的首次攻击，SideWinder 使用了新字符串加密方式，使得 1.a 这个文件的特征有了非常大的改变，短期内有较好的免杀效果。以及给传输的数据进行加密，补足了最后一块数据的加密，至此 SideWinder 攻击过程中除远程模板注入之外的下载数据都是加密的，整体风格更加稳健了。
