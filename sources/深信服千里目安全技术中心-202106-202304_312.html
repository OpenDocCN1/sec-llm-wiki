概述

近日，深信服高级威胁团队在云端日常威胁猎捕工作中持续监控 Apache log4j2 远程代码执行漏洞（CVE-2021-44228）利用情况。前不久已经监控发现许多已知的黑产组织，如 H2Miner、Mirai、Muhstik、Z0Miner 等，已将此漏洞利用融入攻击链中。本次新捕获的是 Windows 和 Linux 双平台下，攻击路径具有一定特点，专门针对某 OA 系统的 Log4shell 漏洞传播的挖矿病毒。深信服安全专家命名为 WhiteLotusMiner。

WhiteLotusMiner挖矿病毒

通过云端防护日志监测，发现新型挖矿病毒，因其样本字符串特征，从而命名为 WhiteLotusMiner。此挖矿病毒针对多个目标的相同OA系统的接口，发起 Log4j2 漏洞攻击，执行命令后下载挖矿脚本并执行。

恶意的 LDAP 服务器，收到受害者请求后，返回专门利用 Tomcat 特性，绕过 jdk 高版本的 JNDI 注入限制的恶意代码，其代码解码 base64 字符串后拼接到 strs 参数，strs最终为要执行的系统命令。受害者接收到恶意代码后本地加载 cmd 或 bash 执行系统命令。

Base64 解码后的 payload，通过系统命令下载远程挖矿脚本并执行：

目前 WhiteLotusMiner 通过 Log4j2 漏洞下发挖矿脚本，捕获3种样本，分别对应Windows 和 Linux 系统。

Windows 版本挖矿脚本，通过创建一个新目录作为信号量，判断机器是否已经感染，若未感染，则进入 C:\ProgramData 目录下，从恶意服务器下载最新的 xmrig-6.16.2-gcc-win64 挖矿程序和 7z.exe 解压 xmrig 后执行挖矿程序。


Linux 版本挖矿脚本，通过创建新的 White_lotus 空目录作为信号量，判断机器是否已经感染，若未感染，则列出所有进程号，如果发现已经感染 xmrig 进程，则杀掉已有的xmrig 挖矿进程，再进入 tmp 目录，删除可能已经存在的 xmrig-6.16.2 文件目录，最后通过 xmrig Github 地址下载最新的 xmrig-6.16.2-linux-x64 挖矿程序后执行。

总结

WhiteLotusMiner 其特点是只针对某知名 OA 系统的 Log4j2 漏洞利用，来传播挖矿病毒。从漏洞利用方式和捕获的样本可知，攻击目的明确，攻击目标选择针对性强，目标都使用相同的某知名 OA 系统，漏洞利用的 payload 也是专门利用 Tomcat 特性，绕过 jdk 高版本的 JNDI 注入限制。

攻击手法简单，攻击过程没有考虑检测规避，不同目标受到相同IP地址发送的Log4j2漏洞利用的攻击包。漏洞利用和脚本执行并没有做到动静态检测规避。其3种payload指向同一台恶意服务器，并且恶意类/代码与挖矿脚本是在相同服务器上下发。执行挖矿程序的命令参数是使用 Monero Mining Pool 矿池的默认配置选项。

这些也说明了攻击者本身水平不高，但是因为 Aache Log4j2 远程代码执行漏洞（CVE-2021-44228）广泛存在各类组件中，且漏洞利用难度较低，容易与其他已知的各类攻击形式相结合，导致不需要很高的技术水平就能发起针对性的高危攻击。

预计未来一段时间内，此类低水平的攻击者，利用该漏洞的攻击事件仍会持续增加。
