0x01 什么是shellcode

在计算机安全中，shellcode这么词常常被提及，在一些缓冲区溢出利用的过程中，向目标程序发送一段十六进制的机器码就可以获得该机器的shell，shellcode从名字来看它是一段能getshell的代码，广义上的shellcode的作用并不只是getshell，它的功能可以是弹出一个信息框，也可以是修改某个寄存器或内存地址等等。

# 0x02 如何编写一段shellcode

注：本文shellcode运行环境为windows x86

一段能被称为shellcode的代码它应该具有以下特点:

1.能够独立执行，不依赖其他库函数

2.尽可能的短

3.尽量避免机器码中出现字节0

以上三个特点也是编写shellcode的守则

先从第一个开始讲起，要满足第一个特点，我们需要做到以下几点：

1.所以变量必须以局部变量的形式声明，不能使用全局变量

因为无论是在windows还是Linux的文件格式中，数据段和代码段默认都是两个不同的区段，虽然可以通过#pragram 向链接器说明将数据段与代码段合并，但由于执行shellcode时的时候的位置常常都是难以预测的，没有必要特意去获取全局变量的地址来增加代码量。

## 在shellcode中调用系统API

在编写代码的时候我们常需要用到系统API，在编写shellcode的时候也是，根据shellcode的特点，调用API的方式与常规有所不同，一个API的调用需要需要获取到API所在的地址，这里需要了解一个结构体：PEB

### PEB

PEB全称ProcessEnvironmentBlock，进程环境块，它位于TEB(线程环境块)的+0x30偏移的位置

在32位程序中 fs:\[0\]所指向的是TEB的第一个成员，那么fs:\[0x30\]指向的就是PEB

### 导出表

一个exe或dll想提供自己的函数供别人调用，需要有个地方来说明哪些函数是可供别人调用的，描述这些信息的地方叫导出表，导出表位于数据目录的第0项。

函数导出的方式有两种，一种是按名字导出，一种是按序号导出。

它的结构如下：

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   

```
typedef struct _IMAGE_EXPORT_DIRECTORY {    DWORD   Characteristics;    DWORD   TimeDateStamp;    WORD    MajorVersion;    WORD    MinorVersion;    DWORD   Name;    DWORD   Base;    DWORD   NumberOfFunctions;    DWORD   NumberOfNames;    DWORD   AddressOfFunctions;     // RVA from base of image    DWORD   AddressOfNames;         // RVA from base of image    DWORD   AddressOfNameOrdinals;  // RVA from base of image} IMAGE_EXPORT_DIRECTORY, *PIMAGE_EXPORT_DIRECTORY;
```

这里比较关键的几个成员

Name：函数所在模块的名称

Base：函数序号的基数，查找索引时候需要加上这个base

NumberOfFunctions：所有导出函数的数量

NumberOfNames：按名字导出函数的数量

AddressOfFunctions：指向一个数组，其中包含了所有导出函数的地址

AddressOfNames：指向一个数组，其中包含了以名称导出的函数的函数名

AddressOfNameOrdinals：指向一个数组，成员数与AddressOfNames相同，保存了按名称导出函数在AddressOfFunctions指向的数组中的索引

![](../Images/47afd91c07b08efab9f7969c80e75494.png)

如上图所示，AddressOfNames指向了一个数组，数组中保存的是以名字导出的函数的函数名

如果函数以名称导出，先在AddressOfNames中找到对应的名字，比如Function2，他在AddressOfNames中是第1项，然后从AddressOfNameOrdinals中取出第1项的值，也就是1，表示函数入口保存在AddressOfFunctions这个数组中下标为1的项，由此可取出Function2函数的地址

如果函数是以序号导出的，那么查找的时候直接用序号减去Base，得到的值就是函数在AddressOfFunctions中的下标

# 0x04 缩短shellcode的长度

我们编写出来的shellcode是要求越短越好的，那么如何缩短shellcode的长度呢

之前我们提到dll的初始化顺序，第二个初始化的可能是kernel32.dll也可能是kernelbase.dll这个取决于程序所运行的操作系统版本，如果我们能确定运行的操作系统，那么就不需要像我上面写的代码一样对dll名称进行一个个比对，只要用下面几行汇编代码就可以取到kernel32.dll的基址(前提是kernel32.dll是第二个初始化的)

*   
*   
*   
*   
*   

```
mov eax,fs:[0x30]//取出PEBmov eax,[eax+0xc]//取出Ldr地址mov eax,[eax+0x1c]//取出InInitializationOrderLinksmov eax,[eax]//取出第二个dllmov eax,[eax+0x8]//取出dllbase
```

当我们要使用很多API的时候就要在局部变量里存储很多API的名称，这会使得shellcode长度增加，

对应的解决方案是对API名称取hash值，当比对API的时候不再比对字符串而是比较hash值，一个API的名称可能会超过十个字节，而一个hash值固定只占用4个字节，当使用大量API值时，就能有效缩短shellcode的长度

这里分享一个取hash的算法

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   

```
DWORD GetHash(char *fun_name){    DWORD digest = 0;    while (*fun_name)    {        digest = ((digest << 25) | (digest >> 7));        digest += *fun_name;        fun_name++;    }    return digest;}
```

这里可能存在疑惑，不是说不能调用其他函数吗？那这个函数怎么调用

在汇编中使用call调用一个函数是采用的是相对寻址

![](../Images/ec9bd1d47d2c363e92925e3724d4a192.png)

例如这个call 操作码E8后面跟着的操作数是66F1FFFF

这里的计算公式是 call的操作数 = 目标地址 - call下一行地址

对应图中情况也就是 00741037 - 00741ED1 =FFFF F166 转为小端存储也就是(66 F1 FF FF)

也就是说只要GetHash函数与shellcode函数的相对位置固定 这个call的机器码就是固定的，那么我们就能正常调用到这个call

# 0x05 避免字节0的出现

在shellcode的使用场景中，很多情况下是作为程序的输入传入的，很多的输入都是以字节0结尾的，如果在shellcode中出现了字节0，很可能导致shellcode被截断，无法实现原定的功能

这里提供一下几点解决方法：

1.对于一些清零操作使用xor函数

例如：

*   
*   
*   

```
00A3178C      B8 00000000   mov     eax, 0x0替换为：00A31791      33C0          xor     eax, eax
```

2.操作数中出现0尽量用加减乘除和移位操作来进行等价替换

例如：

*   
*   
*   
*   

```
00A31770      B8 11110000   mov     eax, 0x1111替换为：00A31775      B8 11111111   mov     eax, 0x1111111100A3177A      C1E8 10       shr     eax, 0x10
```

3.对shellcode进行加密，执行时解密

对shellcode加密算法可以采用最简单的异或，也可以使用base64等不会出现字节0的算法，总之让shellcode中的字节0消失即可。

# 0x06 取出shellcode所在eip

emmm最后再给大家分享下如何取出shellcode所在的eip，这个问题解决方法很简单，面试某南极厂的时候被问道，当时脑子抽了，说我写shellcode的时候没有用到。。。

当我们call一个地址的时候会将返回地址压入堆栈中，前面也提到call是相对寻址，如果call后面跟着是四个字节的0，也就是说call的目标地址就是call所在地址的下一行，我们只要在下一行 进行一个pop操作就能取出返回地址，并且保持堆栈平衡

*   
*   
*   

```
00A31770      E8 00000000   call    00A3177500A31775      58            pop     eax//eax = 00A31775
```
