## **0x00 前言**  

我们都知道，在PHP的类中存在“魔术方法”的概念，在对象初始化时会调用类中的\_\_construct方法，在对象销毁时我们应该关注\_\_destruct方法，当序列化字符串被unserialize函数调用时会调用到\_\_wakeup方法....

可以看到魔术方法对PHP代码审计有着极大的重要性，其实当代码审计遇上魔术方法时，笔者认为最大的核心也只是代码运行的流程。

在文中的Serializable接口研究部分，笔者发现两种比较好玩的姿势，它可以绕过PHP全版本的\_\_wakeup魔术方法以及绕过preg\_match('/^O:\\d+/',$data)。

可以联想到代码的运行流程对我们代码审计工程来说，是多么重要，那么笔者在这里简单介绍一下，PHP预定义接口。

## **0x01 预定义接口简介**

预定义接口实现后会获得一些特有的功能。例如：我们想要得到一个对象的name属性（$obj->name），但是我们想通过数组的形式访问对象（$obj\[name\]），我们就可以通过预定义接口来完成。

预定义接口技术被广泛应用于大型框架中。

当然PHP的预定义接口不止一个，笔者在此记录一下代码审计中常见的预定义接口。

## **0x02 预定义接口案例**

### Traversable（遍历）

Traversable接口的功能为：检测一个类是否可以使用 foreach 进行遍历的接口。但是 Traversable是不可以被直接实现的，例如：

> class Person implements Traversable {}

如果我们直接进行implements实现，那么PHP会抛出异常，如图：

![](../Images/8bc4d0db197dd28c902b80c4766487dd.png)

那么该如何使用这个接口呢？

如果php使用foreach遍历对象，那么php会遍历该对象的成员属性以及成员属性的值，并且我们判断该对象是否属于Traversable的实例，例如：

> <?php
> 
> class Person {
> 
> public $name = 'Yahoo';
> 
> public $age = '18';
> 
> }
> 
> $person = (new Person());
> 
> foreach($person as $key => $value){
> 
> echo $key . '->' . $value . '<br>';
> 
> }
> 
> var\_dump($person instanceof Traversable);

运行结果：

![](../Images/5048bb5969c8435f6e0ee6a55dcda757.png)

### 一、Iterator（简称：迭代器）接口：

当我们将Person类实现Iterator接口时，Person类属于Traversable的实例，例如：

> <?php
> 
> class Person implements Iterator {
> 
> public $key;
> 
> public $data = \[
> 
> 'Yahoo',
> 
> 'Helen',
> 
> 'Laza',
> 
> 'Along'
> 
> \];
> 
> public function key(){
> 
> return $this -> key;
> 
> }
> 
> public function current(){
> 
> return $this -> data \[ $this -> key \];
> 
> }
> 
> public function next(){
> 
> ++$this -> key;
> 
> }
> 
> public function rewind(){
> 
> $this -> key = 0;
> 
> }
> 
> public function valid(){
> 
> return isset($this -> data\[ $this -> key\]);
> 
> }
> 
> }
> 
> $person = (new Person());
> 
> foreach($person as $key => $value){
> 
> echo $key . '->' . $value . '<br>';
> 
> }
> 
> var\_dump($person instanceof Traversable);

运行结果：

![](../Images/d6ddb00ac304cde5810cfd3f60272280.png)

此时我们Person对象的遍历方式已经发生改变，并且Person类已经是Traversable类的实例。

Iterator接口的执行流程为：“遍历的第一次调用 rewind 方法来初始 key 属性的值，然后调用 valid 方法来判断当前的某个键值是否真正存在，如果存在则调用 current 方法来得到当前的键值，然后使用 key 方法来得到当前的键，最后使用 next 方法来进行自动增长。”

那么当我们代码审计时，更需要关注Iterator接口的current方法以及key方法来判断目标场景遍历返回的数据。

### 二、IteratorAggregate（简称：聚合式迭代器）接口：

该接口并没有Iterator接口那么麻烦，只需要定义一个getIterator方法就可以完成对象的遍历了，例如：

> <?php
> 
> class Person implements IteratorAggregate {
> 
> public $datas = \[0 => '张三', 1 => '李四'\];
> 
> public function getIterator()
> 
> {
> 
> echo 'getIterator...<br>';
> 
> return new ArrayIterator($this -> datas);
> 
> }
> 
> }
> 
> foreach((new Person) as $key => $value){
> 
> echo $key . '->' . $value . '<br>';
> 
> }

运行结果：

![](../Images/95ae08c6c6ddf5f5115052fb3270e475.png)

可以从图中看到，foreach时直接调用了Person类的getIterator方法，而foreach的规则则被定义为PHP给予我们的ArrayIterator对象，同时当前Person类所实例化下来的对象也是Traversable的实例。

下面是FilesystemIterator对象的使用，如图：

![](../Images/f97a8f9a0f88d5aabf859b3b91f14fdd.png)

可以看到这样定义与类是没有什么关系了，就是遍历出当前文件夹下的文件。

### ArrayAccess（像数组一样访问）

这个接口可以让对象像数组一样访问，当然这种写法在很多框架中是常见的，例如：

> <?php
> 
> class Person implements ArrayAccess {
> 
> public $datas = \[
> 
> 'name'  =>  '张三',
> 
> 'age'   =>  '13'
> 
> \];
> 
> public function offsetExists($offset)
> 
> {
> 
> echo 'offsetExists...<br>';
> 
> return isset($this -> datas\[$offset\]);
> 
> }
> 
> public function offsetGet($offset)
> 
> {
> 
> echo 'offsetGet...<br>';
> 
> return $this -> datas\[$offset\];
> 
> }
> 
> public function offsetSet($offset, $value)
> 
> {
> 
> echo 'offsetSet...<br>';
> 
> $this -> datas\[$offset\] = $value;
> 
> }
> 
> public function offsetUnset($offset)
> 
> {
> 
> echo 'offsetUnset...<br>';
> 
> unset($this -> datas\[$offset\]);
> 
> }
> 
> }
> 
> $obj = new Person();
> 
> echo $obj\['name'\];

运行结果：

![](../Images/c011ba065cf99b42c04dcf343539180f.png)

### Serializable（序列化&反序列化规则）

当我们对一个对象使用serialize函数时，会返回序列化串，当然这是我们大家都知道的，那么当某个类实现了Serializable接口时，serialize与unserialize的规则就会被重写，当然，规则被重写后，将不会调用\_\_wakeup以及\_\_destruct方法。例如：

> <?php
> 
> class Person implements Serializable {
> 
> public $data = '张三';
> 
> public function serialize(){
> 
> echo 'Person类的serialize方法被调用...<br>';
> 
> return serialize($this -> data);
> 
> }
> 
> public function unserialize($data){
> 
> echo 'Person类的unserialize方法被调用...<br>';
> 
> $this -> data = unserialize($data);
> 
> }
> 
> public function \_\_wakeup(){
> 
> echo 'wakeup...';
> 
> }
> 
> public function \_\_sleep(){
> 
> echo 'sleep...';
> 
> }
> 
> }
> 
> $obj = new Person();
> 
> $p1 = serialize($obj);
> 
> echo $p1 . '<br>';
> 
> $p2 = unserialize($p1);
> 
> var\_dump($p2);

运行结果：

![](../Images/570089302c9e357de871a33da82efed4.png)

我们可以看到，serialize还是首先使用原生的serialize方法，第二次则调用到了Person类的serialize方法，将Person类中的serialize方法的返回结果保存为“s:6:"张三";”，并且将它生成为“C:类名长度:类名:serialize字符长度:{s:6:"张三";}”字符串，这里也没有调用\_\_sleep方法。

在unserialize中的调用顺序也是如此，逆推回去即可得到Person类的实例化对象，只是这里并没有调用\_\_wakeup方法。

### preg\_match('/^O:\\d+/',$data)绕过思路

那么我们可以发现，一个对象的字符串第一个字符是“O”，在这里第一个字符的字符串则变为了“C”，那么我们通过C指令是否可以生成一个对象出来呢？我们编写如下代码进行测试：

> <?php
> 
> class Person {
> 
> public function sayHello(){
> 
> echo 'Hi~';
> 
> }
> 
> }
> 
> $obj = unserialize('C:6:"Person":0:{}');
> 
> $obj -> sayHello();

运行结果：

![](../Images/ede6bb1dc5fc6e829c55c1e9095d96a3.png)

从图中我们可以看到，通过C是可以进行反序列化的，即使当前的Person类并没有继承Serializable。那么这样的姿势也巧妙的实例化了Person对象，只是没有任何属性而已。

### \_\_wakeup绕过思路

我们刚刚说了，如果我们实现了Serializable，那么该类反序列化时，则不会进入\_\_wakeup方法，那么如果类中并没有实现Serializable，但是我们却使用了开头为“C”的序列化串进行了反序列化操作，还会不会进入进入到\_\_wakeup方法呢？我们编写代码来进行测试：

> <?php
> 
> class Person {
> 
> public function \_\_wakeup(){
> 
> echo 'Person Wakeup...';
> 
> }
> 
> public function \_\_destruct(){
> 
> echo 'Person Destruct...';
> 
> }
> 
> }
> 
> $obj = unserialize('C:6:"Person":0:{}');

运行结果：

![](../Images/f5231c8b1574b4be66f1a1e519179558.png)

可以看到，并没有进入到\_\_wakeup方法，那么我们可以通过此特性来编写一道CTF题，如：

> <?php
> 
> class Person {
> 
> public $code;
> 
> public function \_\_wakeup(){
> 
> $this -> code = 'echo "NONONON";';
> 
> }
> 
> public function \_\_destruct(){
> 
> if(!$this -> code){
> 
> $this -> code = $\_REQUEST\['code'\];
> 
> }
> 
> eval($this->code);
> 
> }
> 
> }
> 
> $obj = unserialize($\_GET\['data'\]);

如果我们不知道环境情况下，可能首先想到的是CVE-2016-7124，但是目前是PHP8.0的环境，所以这里我们可以使用C指令来绕过wakeup的限制，构造Payload：?data=C:6:"Person":0:{}&code=phpinfo();

运行结果如下：

![](../Images/3a15d5f7b8006c1a9dc5f3b346e23a00.png)

成功逃逸了wakeup方法的限制。
