ICMP加密隧道笔记

ICMP隧道兴起

互联网刚刚普及的时候，上网费贵得要死，不小心上个网就能让一个穷学生倾家荡产！后来有人研究出了一种技术。虽然网络断了(并非拨号无法获得IP的，而是有IP的)，但是可以ping通IP，于是就开始用ICMP隧道访问转发自己的一台放置在公网的代理，利用代理中转访问公网，实现免费上网(网速慢)

技术原理

首先就是ICMP了

ICMP全称Internet Control Message Protocol，中文名为因特网控制报文协议，它和IP一样工作在网络层 其主要作用是 主机探测 路由维护 路由选择 流量控制

网络本身是不可靠的，在网络传输过程中，可能会发生许多突发事件并导致数据传输失败。网络层的IP协议是一个无连接的协议，它不会处理网络层传输中的故障，而位于网络层的ICMP协议却恰好弥补了IP的缺限，它使用IP协议进行信息传递，向数据包中的源端节点提供发生在网络层的错误信息反馈。

ICMP提供多种类型的消息为源端节点提供网络层的故障信息反馈，它的报文类型可以归纳为以下5个大类：

  • 诊断报文(类型8，代码0；类型0，代码0)；
  • 目的不可达报文(类型3，代码0-15)
  • 重定向报文(类型5，代码0-4)
  • 超时报文(类型11，代码0-1)
  • 信息报文(类型12-18)

说白了，就是检测网路状况，确保连线准确 其通过不同的类别(Type)与代码(Code)识别不同的连线状况。

下面是ICMP的校验算法

unsigned short cal_chksum(unsigned short *addr,int len)
{       int nleft=len;
        int sum=0;
        unsigned short *w=addr;
        unsigned short answer=0;
 
/*把ICMP报头二进制数据以2字节为单位累加起来*/
        while(nleft>1)
        {       sum+=*w++;
                nleft-=2;
        }   
        /*若ICMP报头为奇数个字节，会剩下最后一字节。把最后一个字节视为一个2字节数据的高字节
                                ，这个2字节数据的低字节为0，继续累加*/
        if( nleft==1)
        {       *(unsigned char *)(&answer)=*(unsigned char *)w;
                sum+=answer;
        }   
 
 /*校验和是以16位为单位进行求和计算的，sum是32位的，sum&0xffff是低16位，sum>>16是右移16位，
            取到的是高16位，相加就是高16位和低16位的和。*/
    sum=(sum>>16)+(sum&0xffff);
 
     /*这一步是有可能上面加的时候有进位到高16位的，再把高16位加进来。*/  
    sum+=(sum>>16);
 
    /*上一步肯定不会再有进位了，即使上面sum高16位非0也不要紧，此处sum只能把低字节数赋值给answer，因为answer为16位*/  
    answer=~sum;
 
     return answer;

ICMP的隧道技术原理

由于ICMP报文自身可以携带数据，而且ICMP报文是由系统内核处理的，不占用任何端口，因此具有很高的隐蔽性。

通常ICMP隧道技术采用ICMP的ICMP_ECHO和ICMP_ECHOREPLY两种报文，把数据隐藏在ICMP数据包包头的选项域中，利用ping命令建立隐蔽通道。

利用ICMP的请求和应答数据包，伪造Ping命令的数据包形式，实现绕过防火墙和入侵检测系统的阻拦。

ICMP隧道就是将Data(不清楚往下看)换成我们自己的数据，替换后还要满足其他的规则

参考:https://www.rfc-editor.org/rfc/inline-errata/rfc792.html

利用ICMP隧道进行文件传输

https://github.com/NotSoSecure/icmp_tunnel_ex_filtrate 一个用python写的利用ICMP隧道传输

ntds.dit 的提取与散列值导出 https://www.jianshu.com/p/2796e2ad61d5 这里就打个比方

我得到了目标机的hive文件 需要将其送到本机进行离线破解 可以将hive文件以ICMP数据包的形式从目标机上发送到本机，然后用UI个数据包捕获工具 捕获所有的请求ping流量

首先将hive转换成base64 将这个base64文本文件分割成小块 使用分割后的块创建一个ICMP隧道 让其跟我们的服务器具有相同的序列号 在本机捕获流量 然后删除所有包含ping请求的数据  在本机对文件进行base64解码

大致流程如下：

  • Windows 自带certutil 用它将hive文件进行base64编码    如果是Linux可使用自带的base64
  • 在本机启动tcpdump或wireshark等捕获所有的ICMP数据包
  • 通过可构造ICMP数据包的工具对本机发送ICMP数据包:hping3、自写脚本 如python
  • 对收到的ICMP包提取data数据段内容，进行拼接，重新进行base64解码，得到源文件
