# 某次红蓝对抗之Solr-RCE实战绕过 | 干货

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzkxNDAyNTY2NA==&mid=2247492526&idx=2&sn=538bc1564255ec393ad87330ec8775d7&chksm=c1761e01f6019717cea9db8a08825dccbc526bcdd8f48afce233715775ec67f1c2db9f3bbc95&scene=126&sessionid=1681407986#rd](http://mp.weixin.qq.com/s?__biz=MzkxNDAyNTY2NA==&mid=2247492526&idx=2&sn=538bc1564255ec393ad87330ec8775d7&chksm=c1761e01f6019717cea9db8a08825dccbc526bcdd8f48afce233715775ec67f1c2db9f3bbc95&scene=126&sessionid=1681407986#rd)

**0x01 前言**

在某次红蓝对抗过程中，要结束的时候突然发现了扫描器爆出了Solr-RCE-CVE-2019-0192漏洞。

  

但是进行测试过程中发现存在各种各样的问题。

![](../Images/2d986ef521662bc6bc669afb3aba3500.png)

  

**0x02 绕过1**

进行测试，发现目标只可以执行单命令，返回字段比较少的命令。  

*   
*   

```
whoamiipconfig
```

![](../Images/006e465a5d1783a8a447ed0f7ca66291.png)  

执行dir，无法执行。

![](../Images/06ac38a70e9d889e8377a30087e92603.png)

  
**注：**想着直接执行ps直接上线就好了，各种尝试之后，后知后觉发现对方不出网

  

**0x03 写Webshell**

发现目标不出网的时候，只有写webshell这一条路子可以走了。但是目标只能执行个别命令还无法解决。

![](../Images/42d43c618e23ba4345e58bbab5fb93d7.png)

  

dir无法执行，陷入了沉思，加入单双引号也不行。根据以前的内网经验是不是系统无法默认调用到dir.exe。  
那么 cmd /c dir是不是可以。![](../Images/afbec75f0948913563b4128318796618.png)

  

惊奇的发现，可以完美的执行命令。通过dir找到目录进行写马尝试。  
但是发现目标路由规则写死了，无法直接访问到.jsp的文件。![](../Images/f1aa00287ff87b48cbecb301295f244e.png)

  

刚开始以为是根目录的问题，发现不止根目录，常用的css/js和img下面的也不行。![](../Images/e42d21c46d6e7bc3adfa6590c023b337.png)

  

后续在webshell中看到，翻文件看到了有类似路由机制的验证

![](../Images/d34bb201694ff19b118cc5bfcd2b806e.png)

  

**0x04 言归正传**

在执行rce的时候，找到了solr的目录，发现这里的.jsp是没有这个验证的。  

![](../Images/c5aaeb538dc61ea11e060f700d148e01.png)  
利用命令执行进行找到该位置，进行写文件。问题来了。echo 写入一直无法写入。。![](../Images/766f3e9a5c62056fe2a960b8e8ce9d55.png)

  

**问题解决：**把这里的特殊字符进行编码后即可成功写入。  
又遇到一个问题，jsp的马子都有%号，这里不论怎么做 %就是写不进去。差点放弃，找不到不带%的马子。

  

**0x05 柳暗花明**

但是想到了上午利用过的Certutil可以进行编码解码，这样就没有特殊字符了。

![](../Images/34cb48d6c77367e8549ec66c382f9c1f.png)

  

完全没问题，刚开始一点一点追加，发现下面的会写进去两行![](../Images/efb9a4216bd3867ef490f36d5e9e4b47.png)

  

看了一下就最后有一个+号，没有特殊字符，全部直接写进去。![](../Images/5d0cde6c55a39fdd1bbcfa335f7c4954.png)

  

然后decode进行解码,完美。![](../Images/15b52853b5330f906a857a30ccd0719a.png)![](../Images/931041f0331643c5a86bd74199c28402.png)

  

访问但是是500，不过确很开心，因为确实写上来。![](../Images/d5a2ddb788d2cef5fe2c2b4c1d646b61.png)

  

接下来解决为啥500就可以了，type 123.jsp查看一下。![](../Images/cea549d42455d0ddfb02b5d99ad07140.png)

  

发现最后decode的时候，少了一个\>，本地测试，是没有这个问题的。可能是目标一次性字符长度的问题。  
这里很简单了，追加一下就可以了。![](../Images/1e21dcdaa1ef4542a8e912d95339b88b.png)

  

连接成功![](../Images/6633be4a772e8a8b8790940f1c0eb695.png)
