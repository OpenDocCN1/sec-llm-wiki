# 记一次利用cs进行内网渗透的过程

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzkxNDAyNTY2NA==&mid=2247491779&idx=1&sn=c95aca98bfc290079a742d46c0196ce6&chksm=c1761d6cf601947a0182b95701e37757e579ae863e177d5da7c3d1be36751edd28138c0fead5&scene=126&sessionid=1681407991#rd](http://mp.weixin.qq.com/s?__biz=MzkxNDAyNTY2NA==&mid=2247491779&idx=1&sn=c95aca98bfc290079a742d46c0196ce6&chksm=c1761d6cf601947a0182b95701e37757e579ae863e177d5da7c3d1be36751edd28138c0fead5&scene=126&sessionid=1681407991#rd)

首先搭建好cs的服务端和客户端连接，下面正式进行渗透  

  

  

##### **环境**

kali:192.168.0.226

域控机：192.168.0.138

成员机：192.168.0.251 192.168.0.141

##### **操作**

###### **cs上线**

1.  首先开启监听cobalt->listeners,host和beacons都为cs服务端的ip地址
    
    ![](../Images/4dcc24a024e783fd75977145272b78fb.png)
    
2.  生成相应的windows木马，上传到靶机251中执行。
    
    ![](../Images/9f6633bfdcb61aed42a50b44912b639f.png)
    
    选择对应的监听和木马格式
    
    ![](../Images/fdc36d1bb99b48326730568db24283b2.png)
    
    最后将生成的木马传到靶机中，让靶机执行。
    
3.  机器上线成功
    
    ![](../Images/c3a69b936fec93417926e74f87b4efaf.png)
    

###### **部分cs命令利用**

```

getsystem
```

获取到内网域相应的信息

###### **存活主机探测和获取凭证**

1.  内网横向探测
    
    获取到一个 cs 的 beacon 后可以目标内网情况和端口开放情况，在 beacon 上右键 -> 目标 -> 选择 net view 或者 port scan：
    
    ![](../Images/3967185c674586aa708218c866f27c93.png)
    
    可以在菜单栏中，view视窗的targets选项中查看
    
2.  用 cs 的 hashdump 读内存密码：hashdump，用 mimikatz 读注册表密码：logonpasswords。获取相应账户凭证
    
    或者：
    
    右键->Access->Dump Hashes（需要Administrator权限）
    
    右键->Access->Run Mimikatz
    
    ![](../Images/3c83285d3ef4e698caedd3ca350d8332.png)
    
    可以在凭证栏中查看获取的凭证
    
    ![](../Images/38837298528c81559fc4f5299d50d9e7.png)
    
    ![](../Images/5b620d66510819b30fcf6273465b23af.png)
    
      
    

###### SMB Beacon和psexec传递（msf中的hash传递攻击）

######   

在探测到其他两个内网机器开了445端口的前提下，可以使用SMB beacon获取。相当于在msf里面使用永恒之蓝获取shell。有两种方法

1.  直接派生，新建一个listener，pyload设置为beacon\_smb
    
    ![](../Images/9f1aefe291313d6df41111f106bcf2f6.png)
    
    在已有的 Beacon 上右键 Spawn(生成会话 / 派生)，选择创建的 smb beacon 的 listerner：
    
    选择后会反弹一个子会话，在 external 的 ip 后面会有一个链接的小图标：
    
    ![](../Images/b53b70381c32b10f4d25c43415a26c6a.png)
    
      
    
    这就是派生的 SMB Beacon，当前没有连接，可以在主 Beacon 上用 link host 连接它，或者unlink host 断开
    
    ![](../Images/5d7d55b9e96e75b73d834924e74456a1.png)
    
      
    
    就是说通过之前的beacon为跳板通过SMB去连接新beacon获取权限shell
    
    可以在视图界面查看图形化连接情况
    
    ![](../Images/d66621a105c1cdf1b39c17d45b2ad43e.png)
    
      
    
2.  前面横向探测已经获取到内网内的其他 Targets 以及读取到的凭证信息，尝试使用 psexec
    
    模块登录其他主机，右键选择一台非域控主机 ROOT-TVI862UBEH 的 psexec 模块：
    
    ![](../Images/2dac1c3cdce583bc4bc91ea6e8638245.png)
    
      
    
3.  在弹出的窗口中选择使用 god.org 的 Administrator 的凭证信息，监听器选择之前创建的
    
    smb beacon，会话也选择对应的 smb beacon 的会话：
    
    ![](../Images/1c20306e938c37723e80e98c5f926966.png)
    
      
    
4.  成功上线，并返回新的beacon
    
    ![](../Images/0123c24ec2e730581981f7fd314c7cde.png)
    
      
    

###### **另一种方式token 窃取**

除了直接使用获取到的 hash 值，也可以直接窃取 GOD\\Administrator 的 token 来登录其

他主机，选择 beacon 右键 -> 目标 -> 进程列表，选择 GOD\\Administrator 的 token 盗取：

![](../Images/28b7c9b7c4f1f14c3ff55897d2605f76.png)

找到相应账户的conhost.exe信息，获取其token

![](../Images/5d73b7063ab384f3ab5be11129e76249.png)

再在之前获取的凭证中选择相应账户，勾选token选项就好了

![](../Images/477c1a2c60d8c935318e56fe6406e374.png)

**补充;**

###### cs与MSF会话传递

1.  MSF 创建监听自己的 ip 跟端口：
    
    ![](../Images/e2bf7798c3910d5cde885f33eaa1fb9a.png)
    
2.  CS 创建监听 listeners，Listeners 的 ip 为 msf 的 ip，端口为 msf 监听的端口（注：如果
    
    msf 是内网下的，则需要把端口映射到公网，或者使用 ngrok 等工具做流量转发）
    
3.  回到 cs 上，选中拿下的计算机会话，右键选中 spawn，然后在弹出来的框中选择刚刚创
    
    建的 listeners 监听器，然后执行。
    
4.  msf收到会话
