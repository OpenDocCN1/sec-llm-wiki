![](../Images/0c75ccd25b6342210c8bc9f76327f435.png)

  
定位过去，一套加解密算法都写好了放在这  

![](../Images/0bd413c659d7270ab30bb39b1ff83588.png)

  
放到浏览器console里面调试，果然没错

![](../Images/3dfe74511c2cd0276fbf71e9a50cfa39.png)

![](../Images/4609ce6c6f68c154d5afb5db65936e3f.png)至此已经可以判断该登录点就是一个注入了，可是返回结果始终都是“用户名或密码错”即使用了`' or '1'='1`  

![](../Images/a17c659d24187146d628a08ab9f7e06e.png)根据返回结果推测，后端的登录处的逻辑代码可能是这样的

```






userInfo = 'select * from userinfo where username = <userName>';
```

通过Union注入构造万能密码，是可以造成任意用户登陆的，测试过程如下  
先使用`order by`测试，得知字段的数量为9个，构造`payload`

```



# 由于目标服务器带有过滤，所以这里简单的bypass一下
```

# 注意这里passWord我修改成了123，用来测试Union构造的万能密码是否可行

在绕过后，发现程序出现了异常

![](../Images/4e100b259fe189bc813390d53fc1dda2.png)

仔细观察返回的数据，其中有username（用户名）、staffId（职工号）、email（邮箱）、staffName（姓名）、tel（手机号）、mobile（手机号），然而这些数据都是我刚刚自己随便构造的，这里应该需要一个真实的用户信息，供后续的登录流程使用  

![](../Images/c1d408058683f7bb754cbeda7e1fe64e.png)

好在，还是有一个地方能获取真实的用户信息的  
App还有一个忘记密码的功能（通常这里可以爆破用户名）  

![](../Images/d59e3a11391a41b7a7759f28de77d95f.png)

利用忘记密码的功能可以判断用户名是否存在，这里随便跑了一下字典，就出来好多用户名

![](../Images/c1ffdb94df900534c075ef45ccbcc93b.png)

  

![](../Images/82aa230600543f3b2aec0faa5d01c383.png)

自然而然地利用这些用户名使用短信验证码登录  

![](../Images/dc5f26b9e7101384ade382fdc96b057c.png)

获取验证码，然后解密数据包，惊奇的发现返回了用户基本信息  

![](../Images/aac4744fe8797cb8442d801b48ca0568.png)
