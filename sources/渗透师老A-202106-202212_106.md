# 一次某大学sql注入到getshell

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=Mzg5NzU1MzM5Mw==&mid=2247510081&idx=1&sn=2e54e2a19a9b43c5a9f0e53ff38a1c9f&chksm=c072eedff70567c91b1b25598c89e39bfcd2b61bc45c5d9afad5bb9eba22f4f5137a25019f79&scene=126&sessionid=1681656378#rd](http://mp.weixin.qq.com/s?__biz=Mzg5NzU1MzM5Mw==&mid=2247510081&idx=1&sn=2e54e2a19a9b43c5a9f0e53ff38a1c9f&chksm=c072eedff70567c91b1b25598c89e39bfcd2b61bc45c5d9afad5bb9eba22f4f5137a25019f79&scene=126&sessionid=1681656378#rd)

目标是一大学，在一次挖洞过程中遇到个sql注入，尝试进一步利用扩大危害，漏洞已报送平台进行了修复

#### sql注入getshell失败

在id处连续加两个单引号都报错，经过探测发现是数字型的注入且过滤了空格，这里可以用/\*\*/代替

![](../Images/d79c21088426f0c90562bde1d702dd41.png)

![](../Images/c56b5294c984066726ac51967528be04.png)  

于是直接上sqlmap  

  

```
python sqlmap.py \-u url \--batch \--tamper\=space2comment.py –dbs

```

  

![](../Images/e011381ad7b3a0e07bc4d0331334fde9.png)

  
发现是dba权限：  

```
python sqlmap.py \-u url \--batch \--tamper\=space2comment.py \--is\-dba

```

![](../Images/6db9f18967df68fef24b65b64f00323f.png)

试了很多方法找web路径

  
最后注意到操作系统是FreeBSD

  
无意中看到这个  

  

![](../Images/9db4ae867fa29357f2e91713d404d9ca.png)

  

char(47)就是’/’，立马想到可以通过这个遍历目录、找路径  

  

![](../Images/4571b18c77fdcec8e89bff8f3f7bea19.png)

  
通过从根目录开始逐层遍历，最终找到网站根目录：  

![](../Images/c77b0eb61eef6a1cc505abd0f931fb2c.png)

  
写入shell失败，转换成16进制规避单引号还是不行

但是这个注入可以读取服务器上的任意敏感文件（包括非web目录），危害巨大  

#### 从其它点继续尝试

读取sql注入处代码，发现并没有代码层面的过滤，explode() 函数把字符串打散为数组，这里以空格为分隔，取数组的第一个，变相地过滤了空格，把空格换成内联注释就能注入  

  

![](../Images/b09a94b91e68883e785d045f5dd34cb0.png)

  
根据泄露的数据库账号、密码尝试连接3306端口失败，估计绑定了本地ip  
继续遍历目录，发现了mysql的登陆界面  

![](../Images/b87a4ef0bdb8b9f1b60b4955f10283ea.png)

登录之后却是空白界面，读取处理登录逻辑的代码发现登陆成功直接设置session但不跳转，登陆后直接访问首页就行

  
查一下secure\_file\_priv，发现是空值，并没有限制  

  

![](../Images/cf8963e0ff9c07f51158f7b557eb3788.png)

  

尝试利用日志写入webshell，发现没有权限设置日志路径  

  

![](../Images/34e8ad72efa7a00bc0be65075e0727b7.png)

![](../Images/defa641e5e55dfb2fe758c40a70b76ce.png)

  

找到了网站后台  

![](../Images/554aeaedb0ba883dcb5f3836b4b08dab.png)

  

数据库里面查到的账号和密码hash值

  
在线网站解密hash值得到明文

  
登录失败，读取一下源码  

  

![](../Images/693ee1556e86a9744b28e305b61272bd.png)

![](../Images/1568240bfad4f583efde8d7d37ad9701.png)

  
发现是加了盐的，于是加盐再解密得到正确密码

成功登陆后在人員資料管理新增处发现一个上传照片的地方  

![](../Images/bb07e5deb673a0b6666cc74022e1b232.png)

  

但是只能上传图片文件  

  

![](../Images/1089375a15bf45d79753a20568038a0d.png)

  

上传成功之后，突然想到了sql写shell失败是不是因为目录权限问题，网站限制了除上传目录外其它目录都不可写？  

  

于是尝试写入shell  

  

![](../Images/26836bcd161172b76e001d261915b633.png)

成功，果然是目录写权限问题  

  

![](../Images/b8e7526baaf43b5d037d5f0ddf735844.png)

  
发现蚁剑连不上，估计waf拦截了流量。

  

看了一下蚁剑的流量加密，蚁剑流量有一个重要特征就是User-Agent为antSword/版本，另外使用了编码器的话还要将解码函数发过去，所以解码函数这里也是一个特征，需要自定义编码器和解码器。

  
修改antSword-master/modules/request.js和antSword-master/modules/update.js两个文件的User-Agent后成功连接，waf仅仅拦截了UA这一明显特征  

  

![](../Images/9f1869bedd43abe22b29c4ec0d808c53.png)

  

反弹shell失败，nc是基于tcp/udp协议的，所以可能的原因有：反弹的命令不存在、禁止出站IP、禁止tcp协议出站端口

  
确认sh存在：  

  

![](../Images/12f954a5caa866630a097fae4e38c76c.png)

  

出站端口为访问外网，查询网络连接发现54454端口可以出站  

  

![](../Images/633aaa147de6d61b727ae92c25a46455.png)

  

于是监听54454端口后成功反弹shell  

  

![](../Images/e05a29cc3ebdcd2bb9042e9967de6da9.png)

  

提权失败。

  

服务器内核版本过高，无法利用内核漏洞提权，尝试计划任务、环境变量、和suid提权发现没有可以利用的地方，sudo提权也不行，第三方服务中udf提权发现插件目录不可写，几个文件权限也配置正常，也没有发现其它敏感信息泄露
