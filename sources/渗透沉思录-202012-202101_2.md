# 0x01 一个WordPress

目标是xx组织的一个宣传网站 mubiao.net，经过信息收集得知是一个云托管的WordPress，装了Wordfence安全防护插件，许多页面都被限制访问，这就让渗透WordPress那些常规的手法都已经不适用了。

![](../Images/ae7ef30364a68baf00b75a20cb5309b4.png "null")

# 0x02 尝试找真实IP

那就换个思路找真实IP日一下旁站，发现目标挂了CloudFlare CDN，历史dns解析记录中有个N月份的真实IP，不过host绑定试了下发现已经不是现在网站的真实ip了。

谷歌搜了下网站域名，找到了pastebin.com的剪贴板链接，标题为“近期因为xxx封禁的网址”，关联出了一个mubiao.com网站，访问发现该域名确实已经被封禁，查了下com域名的dns记录，也没有发现什么可疑ip。

又尝试通过各大搜索引擎，搜索关键词、网页特征、标题、icohash、证书均无果。抱着最后的一丝希望，拿着子域的ip去和主域做host碰撞，结果还是没出来....

![](../Images/61dc9a890f284e96a6a8ab89c182e0bb.png "null")

就简单一说比较重要的部分，还有一些都挺常规的尝试就不提了，随便找篇bypass CDN的文章描述的方法就挺全。

# 0x03 服务商迂回攻击

一般这种云托管的网站程序都会有cPanel控制面板，还有WebMail、WHM登录口，对应开放的端口也就那几个，简单扫一下就能出来。顺带提一下这种登录口尝试爆破成功的几率几乎为0，一是密码一般都是随机生成的，二是有的还会限制访问次数。我这里扫描端口主要是想看看有没有什么类似mysql的端口可以爆破一下，然而并没有。访问cPanel控制台的时候，发现了一点不一样的东西。

![](../Images/293b356fbf38eb3bbb0c8719b4c35d4c.png "null")

登陆表单下面有一个快速聊天窗口，点击直接跳到了服务商的客服对话窗口了，想起来查Whois的时候，mubiao.net的网址注册服务商也是这个fuwushang.com，该网站也提供WordPress托管服务，看来很有可能就是网站和域名一块搬到这个服务商来了。

## 客服聊天【第一轮】

```
我：hello，我这个mubiao.net网站的注册邮箱忘了，可不可以帮我查一下。客服：请提供下您的用户名我：忘了客服：抱歉我不能给您解决问题，如需解决请提交工单。我：......
```

第一轮宣布失败，掌握的信息实在太有限了，尝试在服务商网站注册个账号，尽量走一遍所有的业务点，顺便测一下供应商的漏洞。注册的时候发现，在工单系统注册的账号，并不能去登录服务商的主网站，这样看来工单系统的用户和主站用户不是同一个数据表【记住这里，很重要！】

测功能的时候，鬼使神差的想着，要不把目标域名当用户名和密码登录试下，于是在主站登录界面上账号密码都填的 mubiao ，发现弹出来的界面不是账号密码错误，居然是一个邮箱的二次认证码，显示为 `m*****@*******m`，很明显账号密码是对的，只是现在问题要过二次认证，手动测试发现有错误次数和重试时间限制，只好从客服下手。

简单分析一下，对应各星号位数：

`m*****@********m`

可以初步推测邮箱是这样的。

`mubiao@*****.com`

## 客服聊天【第二轮】

```
我：hello，我这个mubiao.net网站的注册邮箱忘了，可不可以帮我查一下。客服：请提供您的用户名我：用户名是 mubiao客服：请稍等几分钟我：我记得邮箱是大概是mubiao@*****.com，但是我忘记了我的注册地址是什么，因为我有许多名称相同但网址的不同的邮箱。客服：请您提供您注册时填写的地址信息我：我忘了，当时注册时地址填的是虚假的客服：感谢您的诚实客服：但是根据目前您的提供的信息，我无权为您操作我：......
```

第二轮再次失败，回想着之前测过的东西，主站用户和工单系统用户不是同一张表，那会不会只有主站有二次认证，工单系统没有二次认证，而且之前注册工单系统发现个人信息哪里是可以直接看到完整明文邮箱的。
