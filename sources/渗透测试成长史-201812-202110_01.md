# **远程命令执行漏洞（RCE）**

**![](../Images/5f656752cf6a2e41f8fc007a63f31ee0.png)**

## 一、**介绍：**

RCE漏洞，可以让攻击者直接向后台服务器远程注入操作系统命令或者代码，从而控制后台系统。

**远程系统命令执行**

一般出现这种漏洞，是因为应用系统从设计上需要给用户提供指定的远程命令操作的接口。比如我们常见的路由器、防火墙、入侵检测等设备的web管理界面上，一般会给用户提供一个ping操作的web界面，用户从web界面输入目标IP，提交后，后台会对该IP地址进行一次ping测试，并返回测试结果。而设计者在完成该功能时，没有做严格的安全控制，则可能会导致攻击者通过该接口提交“意想不到”的命令，从而让后台进行执行，从而控制整个后台服务器

现在很多的甲方企业都开始实施自动化运维,大量的系统操作会通过"自动化运维平台"进行操作。在这种平台上往往会出现远程系统命令执行的漏洞。

应用程序中有时需要调用执行系统命令的函数，比如，在PHP中，使用system、exec、shell\_exec等函数可以执行系统命令。当黑客可以控制这些函数的参数时，就可以将恶意的系统命令拼接到正常命令中，从而造成命令执行漏洞。

 

**远程代码执行**

同样的道理,因为需求设计,后台有时候也会把用户的输入作为代码的一部分进行执行,也就造成了远程代码执行漏洞。不管是使用了代码执行的函数,还是使用了不安全的反序列化等等。

因此，如果需要给前端用户提供操作类的API接口，一定需要对接口输入的内容进行严格的判断，比如实施严格的白名单策略会是一个比较好的方法。

## 二、**常用的管道符：**

windows:”|”、”||”、”&”、”&&”.

linux:”;”、”|”、”||”、”&”、”&&”.

|：表示直接执行后面的命令；

||：表示如果前面的命令出错，则执行后面的命令；

&：前面的语句为假则执行后面的语句，前面的语句可真可假；

&&：前面的语句只能为真；

；：执行完前面的语句再执行后面的。

 

## **三：DVWA：**

### 1、**LOW：**

查看源代码：

<?php

if( isset( $\_POST\[ 'Submit' \]  ) ) {

    $target = $\_REQUEST\[ 'ip' \];

    if( stristr( php\_uname( 's' ), 'Windows NT' ) ) {

        $cmd = shell\_exec( 'ping  ' . $target );

    }

    else {

        $cmd = shell\_exec( 'ping  -c 4 ' . $target );

    }

    echo "<pre>{$cmd}</pre>";

}

?>

可以看到，接收了用户的输入IP地址之后根据windows的不同系统构造不同的ping命令。对用户输入的IP地址没有进行任何过滤，存在命令执行漏洞。

### 2、**MEDIUM：**

查看源代码：

<?php

if( isset( $\_POST\[ 'Submit' \]  ) ) {

    $target = $\_REQUEST\[ 'ip' \];

    // 管道字符代替为null

    $substitutions = array(

        '&&' => '',

        ';'  => '',

    );

    $target = str\_replace( array\_keys( $substitutions ), $substitutions, $target );

        $cmd = shell\_exec( 'ping  ' . $target );

## **四：修复建议：**

①　尽量不使用命令执行函数；

②　客户端提交的变量在进入执行函数之前要做好过滤；

③　使用动态函数之前，确保使用使用的函数是指定的函数之一。

④　对PHP而言，不能完全控制的函数最好不要使用。
