前言

CVE 2022-0847是Max Kellerman在Linux Kernel 5.8版之后才发现的权限提升漏洞，该漏洞允许覆盖任意只读文件中的数据，或者更简单地说，允许非权限进程在特权或者 root进程中注入代码，从而提升权限

漏洞发现的过程

这里重新说明一下Max Kellerman在提到的导致发现此漏洞的问题一系列发现的陈述

当用户在提供访问日志zip文件后，Max Kellerman分享了十六进制转储的通用文件：

81 d6 94 39 81 05 b0 ed e9 c0 fd 0700 00 ff ff03 009c 12 0b f5f7 4a 00 00

00 00 ff ff：同步刷新字节

03 00: 清空“final”块

9c 12 0b f5: 压缩文件的CRC

f7 4a 00 00：十进制文件长度 = 19191 字节

但是，损坏的文件显示以下十六进制转储：

81 d6 94 39 81 05 b0 ed e9 c0 fd 0700 00 ff ff03 0050 4b 01 021e 03 14 00

50 4b 01 02：50 4b表示“PK”的ASCII     01 02表示中心目录文件头的代码

1e 03 14 00：以十进制表示的文件长度更改为 1.3Mb  

如所见，CRC 已更改为表示字母“PK”，它是 *.zip 文件的标头和中央目录文件标头。1e 03 等于 30 (UNIX v3.0) 并且 14 00 是需要提取的版本（转换为 ASCII 20 或 v2.0）

只考虑了 8 个字节，其余字节被截断。

结果表明，发生损坏的原因是管道错误导致的。您可以看到，当连接一个月内的每日日志时，它会执行以下操作：

第 1 天 + 第 2 天 + .... + 第 31 天

当所有31天日志都连接起来时，它就变成了一个 ZIP 文件。因此，在第 31 天时，创建了 filename.zip。在连接最后一天的日志时，会发生管道错误，该错误会用 ZIP 标头覆盖 CRC。

一些常用术语和定义

  • 页（page)：由 CPU 管理的最小内存单元。单位大小 4 KB。如果一个进程请求内存，CPU 会分配多个页面给由“页面缓存”管理的进程。管道使用页面引用来实现内存切换

  • 管道(pipe)：两个系统进程之间的连接，这样一个进程的标准输出成为另一个进程的标准输入。它是一种单向通信方法。

echo “abc” | cat > /dev/null

在上面的例子中，echo是STDOUT，cat接受“abc”作为STDIN。管道中的这些输入由文件描述符处理。“|” 也称为管道运算符。

  • 文件描述符（FD）：唯一标识进程的打开文件的整数。它的范围从 0 到 10230 to 10230 => 预留给STDIN1 =>  预留给STDOUT2 => STDERR  

     to 1023 => 可自定义

因此，管道变为：

FD[1] [WRITE end]（管道输出）<= FD[0] [READ end]（管道输入）   FD[1] [WRITE end] (pipe output) <= FD[0] [READ end] (pipe input)

  • Splice：splice() 在两个文件描述符之间移动数据，而无需在内核地址空间和用户地址空间之间进行复制。它将最多 len 字节的数据从文件描述符 fd_in 传输到文件描述符 fd_out中，其中一个文件描述符必须引用管道。

      格式：splice(FD0, offset FD0, FD1, offset FD1, length, flags);

因此，通过在 FD1 中提供写入文件并从 FD0 读取，splice 可以写入文件。

  • Write函数：C 语言中的 write() 可以帮助用户写入任何文件，当使用 splice 时，write() 也可以为管道提供输入。

格式：splice(FD0, offset FD0, FD1, offset FD1, length, flags);

漏洞发现与模拟

Max Kellerman在 通过损坏的访问日志中发现是由管道错误导致的，错误的数据被写入到 zip 文件，并模拟以下情况：

步骤1：打开一个文件“foo”，并在文件中写入“AAAAA”。伪代码如下：

int main()

{

for(;;) write(1, "AAAAA", 5);

}

步骤2：在偏移量 0 处创建一个管道，在 WRITE 端通向 foo.txt

步骤3：将另一个字符串“BBBBB”拼接并写入到此管道

步骤4:页面缓存被覆盖

步骤2到4的伪代码如下：

int main()

{

for(;;)

{

splice(0,0,1,0,2,0);

write(1,"BBBBB",5);

}

发现：即使第二个进程没有写入文件foo的权限，字符串“BBBBB”也会同样被写入到文件foo。

导致此问题的原因：函数 PIPE_BUF_FLAG_CAN_MERGE 缺少标志初始化。

通过将PIPE_BUF_FLAG_CAN_MERGE注入页面缓存引用，只需将新数据写入以特殊方式准备的管道，就可以覆盖页面缓存中的数据

漏洞利用

如果你已经了解了管道漏洞的发现和模拟，那么利用就很容易理解了。到目前为止，我们已经了解了如何通过管道提供输入来写入文件会导致任意文件写入。因此，利用如下：

  • 创建管道  

  • 用任意数据填充管道（在所有环目中设置 PIPE_BUF_FLAG_CAN_MERGE 标志）

  • 清空管道

  • 将目标文件（以只读模式打开）中的数据从目标偏移之前的位置拼接到管道中

  • 将任意数据写入到管道。现在将覆盖页面缓存，因为设置了PIPE_BUF_FLAG_CAN_MERGE

它之所以有效，是因为页面缓存始终可由内核写入，而写入管道从不检查任何权限。
