这个漏洞本身不能登录Apple账号，但在第三方站点使用过Apple登录过的第三方账号，通过Sign in with Apple其中的漏洞 来接管第三方账号成为可能


何为 Sign in with Apple？

苹果的Sign in with Apple 类似Oauth2.0

举几个Sign in with Apple例子：Dropbox、Spotify、Airbnb、Giphy等等，第三方站点都可以使用Apple 账号登录


Sign in with Apple技术细节

下图展示了Sign in with Apple 登录、创建验证的工作原理

在第二步授权时，Apple 为用户提供了一个选项，是否与第三方应用程序共享 Apple 电子邮件 ID

如果用户决定 隐藏电子邮件 ID，Apple 会自动生成一个虚拟的电子邮件 ID

根据用户选择，成功授权后，Apple 会创建一个包含此电子邮件 ID 的 JWT，然后第三方程序使用该 ID 登录用户


解码后的 JWT 如下：

{  "iss": "https://appleid.apple.com",  "aud": "com.XXXX.weblogin",  "exp": 158XXXXXXX,  "iat": 158XXXXXXX,  "sub": "XXXX.XXXXX.XXXX",  "c_hash": "FJXwx9EHQqXXXXXXXX",  "email": "contact@bhavukjain.com", // or "XXXXX@privaterelay.appleid.com"  "email_verified": "true",  "auth_time": 158XXXXXXX,  "nonce_supported": true}

漏洞发现

@ Bhavuk Jain 发现通过某个接口，可以向 Apple 来请求任何电子邮件 ID 的JWT，并使用 Apple 的公钥验证这些JWT令牌的签名时，并显示为有效

POST /XXXX/XXXX HTTP/1.1Host: appleid.apple.com
{"email":"contact@bhavukjain.com"}

Apple 为这个电子邮件 ID 生成了一个有效的 JWT (id_token)，因为这个JWT有效，所以可以用于去第三方站点认证并登录

响应

{  "authorization" : {    "id_token" : "eyJraWQiOiJlWGF1bm1MIiwiYWxnIjoiUlMyNTYifQ.XXXXX.XXXXX",    "grant_code" : "XXX.0.nzr.XXXX",    "scope" : [ "name", "email" ]  },  "authorizedData" : {    "userId" : "XXX.XXXXX.XXXX"  },  "consentRequired" : false}

漏洞的影响非常严重，因为它可能允许完全接管第三方帐户

许多平台已经集成Sign in with Apple，举几个Sign in with Apple例子——Dropbox、Spotify、Airbnb、Giphy（现在被 Facebook 收购）。这些应用程序可能很容易被完全帐户接管。
