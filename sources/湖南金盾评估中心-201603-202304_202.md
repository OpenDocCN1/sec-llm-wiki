## 0x00 Introduction

`CyberChef`是一个简单，直观的`Web`应用程序，用于在`Web`浏览器中执行各种“网络”操作。这些操作包括简单的编码（如`XOR`或`Base64`），更复杂的加密（如`AES`，`DES`和`Blowfish`），创建二进制和十六进制转储，数据的压缩和解压缩，计算哈希和校验和，`IPv6`和`X.509`解析，更改字符编码等等。

源代码：Github，在线版：Online，由于这是个纯前端项目，也可下载源码到本地，直接双击根目录下的`CyberChef.html`在浏览器中访问。

界面如下图，左侧是支持的操作类型，中间的`Recipe`为操作步骤，可以直接拖放左侧的操作到`Recipe`区域，右侧为输入与输出区。话不多说，直接通过案例来演示。

![](../Images/9bd155cc952cfdc75ffbbcb83ff779f9.png)

## 0x01 Case 1  

在某安卓APP的测试过程中，输入用户名`admin`和密码`P@ssw0rd`后，抓到的登录请求包如下：

```
POST /mobile/user/login.action HTTP/1.1
Connection: close
Content-Type: application/x-www-form-urlencoded
User-Agent: Dalvik/2.1.0 (Linux; U; Android \*; MI \* MIUI/\*.\*.\*)
Host: \*.\*.\*.\*
Accept-Encoding: gzip, deflate
Content-Length: 129

password=6hwEcIeoG9ZrTbL1oVg5qh%2Fnn%2F6SML7YQ2cdAFYYRzY%3D&clientType=Android&version=2.6.0&mac=ZL4Rd5yaWlaQcrVvR&username=admin
```

可以发现`password`字段经过某种加密后进行了`base64`编码，响应包如下：

```
HTTP/1.1 200 OK
Server: nginx
Date: Thu, 13 Feb 2020 03:09:28 GMT
Content-Type: text/html;charset=utf-8
Connection: close
Vary: Accept-Encoding
Content-Language: zh-CN
Set-Cookie: Secure
Content-Length: 124

oAhGYYS4WcF9QqD/rQMosjC5qyfc4GH5T9L0z9YKGqkakVmKyDkyhQ8ztYXnWCvZXkCzFlSVNn1d
```

这里`response body`也经过了加密处理，猜测其加密方式与`password`字段类似。通过对APP进行逆向，发现登录接口：

![](../Images/add6d8fb82d93d1806643dbdc1a08ff7.png)

加密函数在`DX_AESUtil`类的`encrypt`方法, 查看代码：  

![](../Images/977ab0204ffbc662e2669005d2cebbc2.png)

加密用的`key`, `iv`和加密方式都定义在`DesKeyUtil`类中，继续追溯`DesKeyUtil`类：  

![](../Images/54ac4a84d92484eb2cde0a673977926b.png)

`System.loadLibrary`说明`DesKeyUtil`类定义在`lib`目录下的`so`文件中，找到`lib\armeabi-v7a\libDesKeyUtil.so`文件，使用`IDA`加载`libDesKeyUtil.so`文件，很容易就找到想要的值。  

*   `AesKey: 6sdf09d89348eiu`
    

![](../Images/a4233fbf5bfe8d31392312970cf141fa.png)

*   `AesIV: sh34d9rtj49fjf3d`
    

![](../Images/ab364c17e0e41062c8fc7bf071108916.png)

*   `CipherMode: AES/CFB/NoPadding`
    

![](../Images/fff6545fec9bdd49a5979afd322a654b.png)

尝试对响应包进行解密，在`CyberChef`的`Recipe`中先后拖选`From Base64`, `AES Decrypt`, 输入`key: 6sdf09d89348eiu`, `iv: sh34d9rtj49fjf3d`, 选择加密`Mode`为`CFB`, 由于解密后有中文，再加一项`Decode text`，选择`UTF-8`, 成功解密`response body`得到`密码错误`, 这样任何一个请求的响应都能成功解密。  

![](../Images/df2b7c03deeeec6f4bf10799712eef03.png)

修改用户名为随机字符串，得到响应为:  

```
HTTP/1.1 200 OK
Server: nginx
Date: Thu, 13 Feb 2020 05:30:00 GMT
Content-Type: text/html;charset=utf-8
Connection: close
Vary: Accept-Encoding
Content-Language: zh-CN
Set-Cookie: Secure
Content-Length: 96

oAhGYYS4WcF9QqD/rA8osrVA0FIWgGnQ8LWzq7C+ANVUXKHt3GtlUiHA+gO/s5eVM3YFHTb2YjBY3MgnpfpOrP9zLyGHtcCp
```

解密后为`用户不存在或被删除`，说明此接口可以帮助猜解系统有效用户名。

![](../Images/f5c5251e07b54e222dbd01056ccf2a4b.png)

另外从逆向的接口代码，发现密码是先`MD5`再`AES`的，我们可以用此规则借助`CyberChef`生成对应的弱口令字典对登录接口进行爆破。  

![](../Images/23d228129395203b96e54eca5e633f3f.png)

## 0x02 Case 2

在另一个安卓APP的测试过程中，解包`apk`文件后里面有4个`dex`格式文件，但是通过`jadx`逆向`apk`时得到的代码量少得可怜。

![](../Images/089c819f8ccdf56fee1a2629bcd719f9.png)

并且使用`file`命令查看这几个`dex`文件属性时，只有`classes.dex`被识别为`Dalvik dex file`, 其他`dex`文件无法识别文件类型。猜测这几个`dex`文件被加密，并在`apk`运行时解密为真正的`dex`文件加载到内存中运行。  

![](../Images/12e8a3652847134e22fc8f5e04a2dd83.png)

由于`classes.dex`仅有`10KB`大小，代码量少，直接逆向找到如下代码，很容易看出功能为解密主目录下文件名不为`classes.dex`的其他`dex`格式文件。  

![](../Images/2e3d67dfc87542c3761fa07e04705120.png)

解密函数是`a`类中的`a`方法，下面就更容易了，查看该方法：  

![](../Images/c563cf73d371bfef2b8d994e76ae6fed.png)

加密类型`AES/ECB/PKCS5Padding`, 密钥`cnm*************gsn`, 直接在`CyberChef`进行相应设置，以`s_classes3.dex`为例，在`Input`右侧中使用`Open file as input`, 选择`s_classes3.dex`. 看到`Output`中熟悉的文件头`dex.035`, 说明猜想是正确的。  

![](../Images/aea9d77f1274d170b91cf010993a95f0.png)

在`Output`右侧选择`Save output to file`, 保存解密结果到本地, 即可得到正确的`dex`文件，从而可以继续愉快地逆向了。  

![](../Images/fecc087f90eee81bd3d29ee019de3df3.png)
