# 针对中东工业领域的新APT组织（WildPressure）

这是一个新的APT组织，拥有新的恶意软件，并且未链接到任何其他以前的APT攻击操作。  

  

根据卡巴斯基的报告称，它们发现了一个新的，从未见过的黑客组织，该组织目前针对中东工业部门。

卡巴斯基将这个组织命名为**WildPressure**，并将其描述为APT（高级持续性威胁），该术语通常用来描述由国家发起的黑客攻击活动。

该组织的主要武器是卡巴斯基（Kaspersky）命名为**Milum**的新C ++后门木马，它使**WildPressure**操作员可以完全控制受感染的主机。

**Milum****木马分析**  

该恶意软件使用JSON格式进行配置数据，并通过HTTP作为C2通信协议。在HTTPPOST请求中的加密通信中，研究人员发现了几个有趣的字段。其中一个显示了恶意软件版本-1.0.1。这样的版本号表示开发的早期阶段。其他领域表明，至少存在非C++版本的计划。

唯一实现的加密是RC4算法，为不同的受害者提供了不同的64字节密钥。此外，外发人员还很好地将RTTI数据保存在文件中。

![](../Images/da23fc220534b11328f43e686e819d04.png)

上述所有C++木马都被编译为独立的PE文件，最初名为Milum 46\_Win32.exe。在恶意软件中的C++类名中使用了‘Milum’这个词，所以以它的名字命名了这个木马。

另一个显著的特点是恶意软件输出了大量的zlib压缩函数，比如zlibVersion()、giate()或exate()。这种压缩是C2通信所必需的，但实际上，在独立应用程序的情况下，不需要导出它们。

JSON配置字段不仅限于版本和编程语言；活动运算符还使用示例中的目标ID。其中，我们发现了HatLandM 30和HatLandid3--这两个我们都不熟悉。下表提供了具有相似PE头编译时间戳但目标ID不同的Milum示例：

卡巴斯基没有逐一描述所有配置字段，而是将它们集中在一个表中，其中包含了这个恶意软件家族的所有主要特征：

  

| 编程语言 || C++带有STL函数，主要用于解析JSON数据和异常处理。 |
| --- | --- |
| 配置数据 || PE资源中的Base 64编码的JSON数据。包括超时、C2 URL和通信键，包括RC4 64字节键. |
| 网络协议 || 特洛伊木马通过使用gzip、base 64编码和RC4加密的HTTPPOST请求传输压缩的JSON数据。 |
| 信标数据 || 加密的JSON包含恶意软件版本“1.0.1”、Epoch时间戳和客户端ID。它还具有特定的字段，如“vt”和“ext”，它们对应于编程语言“c++”和文件扩展名“exe”。如果我们的假设是正确的，这意味着非C++木马版本可能是计划的，如果还没有实现。 |
| 持久力 || HKCU自动运行系统注册表项运行和RunOnce。 |
| 加密 || 所使用的通信加密是RC4，其64字节密钥存储在配置数据中。 |
| 压缩 || 对于压缩，特洛伊木马使用嵌入的gzip代码。出于某种原因，gzip函数是从PE导出的，尽管示例是独立的可执行文件，而不是DLL。 |

此应用程序以不可见工具栏窗口的形式存在。主要恶意函数在单独的线程中实现。Milum对其配置数据进行解码，除了超时之外，它还将获取用于RC4加密的参数“clientid”和“crypt\_key”。  

![](../Images/ef9e8aff3f9bd82d195447eb7144cd74.png)

  

下表描述了不同的配置参数：

  

| **配置参数** || **参数特征** |
| --- | --- |
| 短路 || C2通信工作周期之间的暂停(毫秒) |
| 客户id || 唯一的ASCII目标名称 |
| 加密密钥 || 基于JSON的C2通信的Rc4加密密钥 |
| 继电器-url || 发送HTTPPOST信标和获取命令的完整URL |
| 继电器.键 || 每个C2与之通信的唯一ASCII键 |

  

运算符可以使用键(“b”或“B”)作为第一个参数，使用文件名作为第二个参数来运行特洛伊木马。在这种情况下，Milum将删除作为参数发送的文件。然后，特洛伊木马将创建C：\\ProgramData\\Micapp\\Windows\\目录，并解析其配置数据以形成信标发送到C2。  

为了发送信标，Milum使用HTTPPOST请求，其中包含三个参数，如下表所示。

| **信标参数** || **参数值** |
| --- | --- |
| MD || Clientid from config，具有前缀01011和随机5个字符的asci后缀。 |
| NK || 键从配置到与C2通信，每个服务器不同 |
| 瓦尔 || 压缩、加密和编码命令JSON数据 |

前两个参数是从配置数据中提取的。第三种是加密的，经过解密、解压缩、解码和美化后，如下所示：

![](../Images/0460f31460ad1a7104405a88a18c071b.png)

这里有几个领域值得一提。除了C++之外，我们还提到了不同的编程语言：“vt”似乎引用了一种编程语言，“ext”指的是文件扩展名。如果攻击者有几个用不同语言编写的特洛伊木马来使用相同的控制服务器，我们就能想到保留这些木马的唯一原因。

关于“命令”字段，在分析时控制服务器是不可访问的，因此我们没有来自它们的命令。但是，我们分析了Milum代码中的命令处理程序，如下所述：

卡巴斯基专家说，他们首先在2019年8月发现了感染了Milum的计算机，但后来发现过去感染的迹象可以追溯到2019年5月31日。  

对Milum代码的分析还证实，Milum是在两个月前（即2019年3月）进行编译的，这解释了卡巴斯基为何无法接收较早的感染。

### 没有与其他任何操作共享的代码或受害者

此外，相同的分析还表明，Milum由相对较新的代码组成，与任何其他APT操作没有交集或相似之处。

卡巴斯基威胁引擎（KTAE）检测到该木马与已知的活动没有任何代码相似性。

莱格佐说：“我们还没有看到任何目标交叉路口。” “实际上，我们在一个国家中仅发现了三个几乎独特的样本。”

卡巴斯基分享的截图显示，那个国家是伊朗，显示伊朗的IP地址连接到其研究人员于2019年9月成功潜入的Milum命令与控制（C＆C）服务器。

Milum在2019年3月的两个月前进行了编译，威胁参与者使用了租用的OVH和Netzbetrieb虚拟专用服务器（VPS），并使用了通过代理匿名服务在Domains中注册的域。

  

在2019年9月，卡巴斯基的研究人员潜入APT小组（upiserversys1212 \[.\] com）使用的C2域之一。绝大多数的访问者IP都来自中东，特别是来自伊朗，而其余的是网络扫描仪，TOR出口节点或VPN连接。

  

![](../Images/af2b50349da5346db5bba87c462dc8ff.png)

  

过去，这不是APT小组第一次针对伊朗。迄今为止，Stuxnet事件仍是历史上最臭名昭著的黑客事件之一，这是美国和以色列进行的旨在破坏伊朗核能力的联合行动。

总体而言，过去一年来，中东的网络间谍活动也相当活跃。从伊朗黑客工具的泄漏到新的破坏性数据擦除恶意软件的部署，该地区总有事情在发生，在许多事件中，攻击都针对当地的工业部门，尤其是石油和天然气领域。
