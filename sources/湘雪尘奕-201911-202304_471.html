0x00 Meta Keywords


Meta设置对Suricata的检查没有影响；它们对Suricata告警事件的方式确实有影响。

01

message

描述信息

关键字 msg 提供了有关规则签名和告警事件的文本信息。
msg的格式是：
msg: "some description";
例如：
msg:"ATTACK-RESPONSES 403 Forbidden";
msg:"ET EXPLOIT SMB-DS DCERPC PnP bind attempt";
为了继续上一章的例子，这是关键字在实际规则中的作用：

drop tcp $HOME_NET any -> $EXTERNAL_NET any (msg:”ET TROJAN Likely Bot Nick in IRC (USA +..)”; flow:established,to_server; flowbits:isset,is_proto_irc; content:”NICK “; pcre:”/NICK .*USA.*[0-9]{3,}/i”; reference:url,doc.emergingthreats.net/2008124; classtype:trojan-activity; sid:2008124; rev:2;)


提示

约定使签名的第一部分大写并显示签名的类别。这也是约定，msg成为签名中的第一个关键字。

注意

msg中必须转义以下字符： ; \ "

 

02

signature ID

规则签名ID

关键字sid为每个签名提供了自己的ID。此ID用数字表示。sid的格式是：
sid:123;
规则签名中的sid示例：

drop tcp $HOME_NET any -> $EXTERNAL_NET any (msg:”ET TROJAN Likely Bot Nick in IRC (USA +..)”; flow:established,to_server; flowbits:isset,is_proto_irc; content:”NICK “; pcre:”/NICK .*USA.*[0-9]{3,}/i”; reference:url,doc.emergingthreats.net/2008124; classtype:trojan-activity; sid:2008124; rev:2;)

提示

按照惯例，签名sid被提供为签名的最后一个关键字（或者倒数第二rev）。

03

revision

修订版本

sid关键字几乎每一次都伴随rev。rev代表着签名的版本。如果签名被修改，rev的数量将由签名编写者增加。rev的格式是：
rev ：123 ;
签名中的修改示例：

drop tcp $HOME_NET any -> $EXTERNAL_NET any (msg:”ET TROJAN Likely Bot Nick in IRC (USA +..)”; flow:established,to_server; flowbits:isset,is_proto_irc; content:”NICK “; pcre:”/NICK .*USA.*[0-9]{3,}/i”; reference:url,doc.emergingthreats.net/2008124; classtype:trojan-activity; sid:2008124; rev:2;)


提示

这是sid在rev之前出现的惯例，并且它们都是所有关键字中的最后一个。

04

group ID

组ID

gid关键字可用于为不同的签名组提供另一个id值（如在sid中）。Suricata默认使用gid 1.可以修改它。通常情况下它会被改变，改变它没有技术含义。您只能在报警中注意到它。
fast.log告警中的gid示例。在[1: 2008124: 2]部分，1是gid（2008124是sid和 2 rev）。

drop tcp $HOME_NET any -> $EXTERNAL_NET any (msg:”ET TROJAN Likely Bot Nick in IRC (USA +..)”; flow:established,to_server; flowbits:isset,is_proto_irc; content:”NICK “; pcre:”/NICK .*USA.*[0-9]{3,}/i”; reference:url,doc.emergingthreats.net/2008124; classtype:trojan-activity; sid:2008124; gid:1;)


05

classtype

分类类型

class关键字提供有关规则和告警分类的信息。它由一个简短的名字，一个长名字和一个优先级组成。它可以说明一个规则是仅仅是信息性的还是关于黑客等等。对于每一个classtype，classification.config具有将在规则中使用的优先级。
示例类型定义：
config classification: web-application-attack,Web Application Attack,1
config classification: not-suspicious,Not Suspicious Traffic,3
现在，当我们在配置中定义了这个时，我们可以在规则中使用这些类型。具有classtype web-application-attack的规则将被分配优先级为1，并且告警将包含“Web Application Attack”：

CLASSTYPE

警报

优先

web-application-attack

Web Application Attack

1

not-suspicious

Not Suspicious Traffic

3 

我们继续的例子也有一个类型，这是一个木马活动：

drop tcp $HOME_NET any -> $EXTERNAL_NET any (msg:”ET TROJAN Likely Bot Nick in IRC (USA +..)”; flow:established,to_server; flowbits:isset,is_proto_irc; content:”NICK “; pcre:”/NICK .*USA.*[0-9]{3,}/i”; reference:url,doc.emergingthreats.net/2008124; classtype:trojan-activity; sid:2008124; rev:2;)

提示

这是一个约定，classtype在sid和rev之前以及其他关键字之后。

06

refernce

参考

可以找到引用关键字指向签名试图解决的签名和问题信息的地方。引用关键字可以在签名中多次出现。此关键字适用于签名人员和分析人员，他们调查签名匹配的原因。它有以下格式：
reference: type, reference
对www.info.com的典型引用是：
reference: url, www.info.com
但是，也有几个系统可以作为参考。一个众所周知的例子是CVE数据库，它为漏洞分配数字。为了防止你一次又一次地输入相同的URL，你可以使用这样的东西：
reference: cve, CVE-2014-1234
这将引用http://cve.mitre.org/cgi-bin/cvename.cgi?name=CVE-2014-1234。所有的参考类型都在reference.config配置文件中定义。
我们继续的例子也有一个参考：


drop tcp $HOME_NET any -> $EXTERNAL_NET any (msg:”ET TROJAN Likely Bot Nick in IRC (USA +..)”; flow:established,to_server; flowbits:isset,is_proto_irc; content:”NICK “; pcre:”/NICK .*USA.*[0-9]{3,}/i”; reference:url,doc.emergingthreats.net/2008124;classtype:trojan-activity; sid:2008124; rev:2;)


07

priority

优先级

优先级关键字带有一个强制数字值，其范围可以从1到255.数字1到4是最常用的。首先检查具有较高优先级的签名。最高优先级是1.通常签名已经通过类型的优先级。这可以用关键字优先级来推翻。优先的格式是：
priority:1;


08

metadata

meta数据


meta关键字允许将额外的非功能性信息添加到签名中。虽然格式是自由格式，但建议您坚持使用键值对，因为Suricata可以在预警中包含这些格式。格式是：
metadata: key value;
metadata: key value, key value;


09

target

目标


target关键字允许规则编写者指定警报的哪一侧是攻击的目标。如果指定，则会增强警报事件以包含有关源和目标的信息。
格式是：
target:[src_ip|dest_ip]
如果值为src_ip，则生成的事件（JSON中的src_ip字段）中的源IP是攻击的目标。如果target设置为dest_ip，则目标是生成事件中的目标IP。
更多内容请查看Suricata YAML配置文件中动作顺序的介绍。
