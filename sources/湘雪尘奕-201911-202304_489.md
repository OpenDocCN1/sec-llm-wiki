**0x00 MelSoft 简介**

![](../Images/4aebcc140e8243a69ef7d30a9ac838ed.png)

  

  

三菱MelSoft通信协议是三菱内部协议，一般用于支持三菱协议的产品通讯。比如三菱的编程软件，三菱的触摸屏等。本内容是根据FX5U-32MT/ES设备进行的协议逆向。故而有一些偏差或者错误还请谅解。本内容所逆向是基于主端设备（PC）所发起的命令。而从端设备（PLC）的响应数据，除非有必要的情况下，才进行分析。三菱的MelSoft通信协议与其MelSec通信协议有些相似之处，也有不同的地方。如果想详细了解三菱的私有MelSoft通信协议，还请提前查看MelSec协议内容，该内容可从网络上直接获取。也可以通过三菱的官方网站进行查找下载。欧姆龙全球制造用于工业和制造业的机器。FINS用于通过网络控制其中一些机器。FINS以太网协议基于OSI模型：

| **OSI layer** || **Protocol** |
| --- | --- |
| 7 Application Layer || MelSoft |
| 6 Presentation Layer |
| 5 Session Layer |
| 4 Transport Layer || UDP |
| 3 Network Layer || IP |
| 2 Data Link Layer || Ethernet |
| 1 Physical Layer || Ethernet |

其中，第1-4层会由计算机自己完成（底层驱动程序），关于这些神马的定义，大家可以上网查一下；第5～7层，FINS，这一层和用户数据相关，对PLC数据的读取报文在这里完成。

**帧结构**

MELSOFT数据帧结构分类两类，一类这里暂时称为短帧，一类称为长帧短帧顾名思义，就是数据包很短。它的作用管理会话，涉及到会话的发起、重置、绑定和确认等内容。长帧顾名思义，就是数据包内容比较多。它的作用管理数据传输，涉及到含功能码、数据、参数的等内容。**短帧**：短帧的数据结构如下所示：![](../Images/f9a929f58dd1d14c3e32953715155357.png)

MelSoft 短帧部分

  

MELSOFT 短帧部分包含了3个信息：协议标识符，预留及命令组成。如图2所示：MELSOFT 短帧的结构为：l  0：Protocol ID，协议ID，通常为0x5a；l  1：Fram Type，帧类型：u  0x00：会话管理u  0x01：数据传输l  2：Reserved，预留，通常为0x00 0x00；l  3：Type，数据帧类型，一般有以下值：u  0x00：data trans 数据传输u  0x01：Connect Requst 连接请求数据帧u  0x11：Binding Session 绑定会话；u  0x22：Reset Session 重置会话；u  0xFF：Confirmation session 确认会话举个例子，如图4所示：

MelSoft 长帧部分

  

MELSOFT 长帧部分分为MELSOFT Header、MELSOFT Commands 和 MELSOFT Data三种结构类型。如图3所示。MELSOFT Header具体内容如下：l  0：Protocol ID，协议ID，通常为0x57；l  1：Fram Type，帧类型：u  0x00：会话管理u  0x01：数据传输l  2～18：目前这40多位的内容一直没有变化，暂时不分析了。l  19～20：后续数据长度，地位在前，高位在后，例如数据长度为1003（后续982与前面21个长度之和），则0xD6 0x03。l  21～45：目前这40多位的内容一直没有变化，暂时不分析了。MELSOFT Commands 具体内容如下：l  46～47：Command：l  48：Command ParaMELSOFT Data 具体内容：l  49～：数据。举个例子，如图5所示；

MelSoft Forced

Forced功能码可以强制设置或者强制重置位。也可以强制设置状态及释放状态。在恢复强制状态前，程序将无法继续执行。其命令结构如下图所示。
