认证介绍




        CEH(Certificated Ethical Hacker)被业界称之为道德骇客（正派黑客）认证，是由国际电子商务顾问委员会（EC-Council）提供的网络安全认证。911事件发生后，该机构创始人发现了美国安全机构缺乏能够利用网络工具和资源来阻止网络攻击能力的这个商机，成立了EC-Council， 提供信息安全培训和认证计划。该计划的CEH认证得到了包括美国国防部在内的政府机构的认可。

      EC-Council提供一系列的安全认证，除了今天介绍的CEH外，还有CEH Practical，实操考核，提供虚拟机环境。通过CEH后，进阶链路上还包括如下两个认证，大家取得CEH认证后可以继续深入学习：

EC-Council安全分析师（EC-Council Certified Security Analyst，ECSA）
特许入侵测试员（Licensed Penetration Tester，LPT）



报名流程




1、在线（https://cert.eccouncil.org/Exam-Eligibility-Form.html）填写申请表，初审通过后会收到官方邮件通知；
2、按照邮件要求提供正式申请表、身份证明、个人简历以及缴纳$100申请费（https://store.eccouncil.org/）的订单证明；
3、正式审核通过后，会再次收到邮件，在线（地址同上）购买考试券$1099，报名约考。
另外，AppStore有CEHv9和CEHv10的题库收费版app，许多通过了考试的前辈推荐使用。



考试大纲




       考试包括125道英文选择题，给了4h的作答时间。官方不提供具体的最低及格分数，但网传答对70%合格。考试大纲包括7个模块（新版可能已有变动但变动不会太多），各自的权重占比可参考下图。其中最后两个部分，法律法规和道德是通俗意义上的“送分题”，只要稍微熟悉一下涉及的法规，再根据常识判断即可。


内容架构





CEHv9共有19个章节，可划分为三大部分

 分别是基础知识、攻击步骤和攻击手段


/第一部分 /


第一部分(chapter1-3)涉及了大量的安全基础知识，需要我们平时的学习和积累。基础知识又可以分为两类，流程类和技术类。流程类包括事件响应的策略和步骤、业务连续性计划的制定、调查取证证据链路的形成、法律法规的介绍等；技术类包括网络的拓扑结构、OSI七层模型、TCP三次握手、各类网络设备（路由器交换机防火墙IDS、IPS）、几大操作系统（Win、Linux、Mac OS、Android）在安全方面天然的优势劣势、不同的备份策略、以及加密相关（对称、非对称、PKI公钥机制、消息摘要）。这一块的内容和CISSP等其他安全类的各大认证有很大的重叠。


/第二部分 /


  第二部分（chapter4-7）按照黑客攻击步骤成文，也是我们从事渗透测试的范本。它包括这样几个阶段。

Footprinting-踩点、信息收集

 为了后续能够发动更加精准的攻击，必须尽可能多地收集信息。这里介绍了各类信息收集的方法和工具，例如google hacking、时光机等，并提到有时候，从竞争对手处获取目标信息可能是更为便捷的方式，因为“敌人往往是最了解你的人”。

Scanning-扫描

 扫描通常是为了确定目标有哪些资产，有什么价值。通过端口扫描、网络扫描和脆弱性扫描，探知哪些端口是开启的，拿到服务器操作系统及组件的指纹信息，绘制目标网络架构拓扑图。这里介绍了一个非常重要的工具nmap，该工具的使用方法、参数设置是CEH的重要考点之一。

   Enumeration-枚举

 在渗透测试中，我们很少把枚举环节单独提出作为一个攻击步骤，一般都融入在系统攻击中。Enumeration主要指的是我们枚举系统用户、组的信息，以及其他一些初步攻击系统的行为，例如从收集到的邮箱信息拆出可能的用户名和域名，获取中间件的默认密码、尝试通过字典去做目录遍历，攻击SNMP和SMTP协议等。也是从这个步骤开始，攻击行为有了被指控的危险。作为道德骇客，一定要与委托方签订合同明确职责。

System hacking-系统攻击

 正式开始对系统的攻击，这个步骤中包括获得系统权限、提权、抹除痕迹和留下后门等内容。除了介绍各种攻击手段外，这一章还花较大的篇幅介绍了多种获取密码的手段。可以通过密码字典、暴力破解外，可以利用网络流量嗅探的方式，也可以使用键盘记录器、间谍软件直接获取，针对hash也能建立彩虹表，离线碰撞出密码，当然，社会工程永远是一个可能的选择。


/ 第三部分 /


了解攻击步骤后，开始介绍第三部分(chapter8-19)的内容：各种攻击手段。这一部分内容繁多，包括恶意软件、嗅探、社会工程、拒绝服务、进程劫持、WEB安全、SQL注入、WiFI和Bluetooth攻击、移动设备安全、防护设备绕过、物理安全、云技术等。如果你从事的是渗透测试工作，那么对这一块内容应该早已有所了解，特别是其中的进程劫持、SQL注入、WEB安全等章节，内容基本上覆盖了平时工作中遇到的全部漏洞类型。包括SSL弱算法系列漏洞、Banner信息泄露、错误页面泄露这些低危漏洞也都有所涉及。



知识要点




下面为大家介绍一些学习过程中印象较为深刻的知识点。

/ HackerClasses（黑客分类） /

Black hats：黑帽子
White hats：白帽子
Gray hats：灰帽子，与黑白帽子相对应，在不同的时段表现出不同的行为特征
Suicide hackers：不计后果，不担心踪迹被发现
Script Kiddies：脚本小子，多利用网上现成的脚本或工具，对攻击原理理解不深
Cyber Terrorists：恐怖分子，攻击电网、红绿灯
State Sponsored Hackers：国家队
Hacktivist：“黑客主义”，重在宣扬理念和表达自己的观点，类似Anonymous那种

/ 法律法规 /

作为道德骇客，保证自己的行为没有违反法律的前提是，要懂得当地的法律法规。由于CEH是基于美国机构的，我们需要了解一些US法律法规。

1.1986 U.S. Computer Fraud and Abuse Act
该法案明确了联邦计算机犯罪中欺诈和滥用罪的定义，消除法律模糊性，扫除对计算机犯罪起诉的障碍。
2.1996—U.S. Kennedy-Kassebaum Health Insuranceand Portability Accountability Act (HIPAA)
该法案强调对个人健康信息的隐私保护，HIPPA requiresemployer's standard national numbers to identify them on standard transactions.
3.2002—Sarbanes–Oxley Act (SOX or SarBox) 萨班斯法案
萨班斯法案相当有名，着力于上市公司的财务审计
4.2002—Federal Information Security ManagementAct (FISMA) 联邦信息安全管理法案
该法案致力于保护联邦政府的数据安全

/ LM Hash /

早期SMB协议在网络上传输明文口令。后来出现"LAN ManagerChallenge/Response" 验证机制，简称LM，它是如此简单以至很容易被破解。微软提出了WindowsNT挑战/响 应验证机制，称之为NTLM。现在已经有了更新的NTLMv2以及Kerberos验证体系。

LM HASH生成规则如下：

1.  用户的密码被限制为最多14个字符。

2.  用户的密码转换为大写。

3.  密码转换为16进制字符串，不足14字节将会用0来在后面补全。

4.  密码的16进制字符串被分成两个7byte部分。每部分转换成比特流，并且长度为56bit，长度不足使用0在左边补齐长度，再分7bit为一组末尾加0，组成新的编码。

5.  上步骤得到的8byte二组，分别作为DESkey为"KGS!@#$%"（魔术字符串）进行加密。

6.  将二组DES加密后的编码拼接，得到最终LMHASH值。

参考它的生成规则，我们可以看出它的加密方式并不安全，字符长度被限制、又不区分大小写，算法简单，很容易被枚举。

/ 防火墙的类型 /

包过滤防火墙：检查IP数据包的源地址、目的地址、端口号、协议等因素，在网络层对数据包进行分析和过滤
电路级网关防火墙：监视两主机建立连接时的握手信息，如SYN、ACK和序列号是否合乎逻辑，判定该会话请求是否合法。工作在会话层
应用层防火墙：工作在应用层，可以根据协议判断
状态检测防火墙：抽取数据包与应用状态有关的信息，发现连接的参数有变化时，连接就会被终止。

需要了解各种防火墙工作在OSI七层模型的哪一层，是通过数据包的哪些特征来实现过滤的。

/社会工程 /

“There is no patch for human stupidity.”

人是许多组织的薄弱环节，攻击者利用人的天性达到目的。在社会工程中，攻击者往往扮演两种角色：求助者和权威者。前者利用注入技术支持、前台的好意得到信息，后者则假装自己是内部人士，利用全职和他人的敬畏得到信息。

/ 拒绝服务 /

除了常见的攻击类型，例如SYN flood、teardrop等外，还涉及到栈溢出和堆溢出的知识，如果对汇编语言有基础的话会更容易理解。众多编程语言中，C语言是最容易导致栈溢出问题的。

/工具的使用 /

CEH十分关注各类工具的使用，特别是Win平台黑客工具，需要掌握常见工具的作用领域和使用方法。常见的考察方式包括给出某个场景，询问在这个场景下用什么工具最合适；或者给出某个工具的执行结果，询问使用的命令参数是什么等。
