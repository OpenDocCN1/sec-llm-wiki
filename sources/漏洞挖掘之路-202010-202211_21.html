Metasploit Framework简介

    目前最流行的、最强大、最具扩展性的渗透测试平台软件

    2003年由HD More发布第一版，2007年用ruby语言重写。

    MSF默认集成于Kali Linux之中，使用postgresql数据库存储数据，早期版本需要先启动数据库再启动msf。

项目地址

https://windows.metasploit.com/

https://github.com/rapid7/metasploit-framework/wiki/Nightly-Installers

版本对比

模  块 

01

Exploits

    利用系统漏洞进行攻击的动作，此模块对应每一个具体漏洞的攻击方法（主动、被动）

02

Payload

    成功exploit之后，真正在目标系统执行的代码或命令。

    Shellcode或系统命令


Payload在msf中的默认路径：

/usr/share/metasploit-framework/modules/payloads/



默认有三种Payload:

single:all-in-one。完整的payload，这些payload都是一体化的，不需要依赖外部的库和包。

stager:目标计算机内存有限时，先传输一个较小的payload用于连接

stages:利用stager建立的连接下载的后续payload

staget/stages都有多种类型，适用于不同场景


    shellcode是payload的一种，由于其建立正向/反向shell而得名

03

Auxiliary

    执行信息收集、枚举、指纹探测、扫描等功能的辅助模块（没有payload的exploit模块）

04

Encoders

    对payload进行加密，躲避AntiVirus检查的模块

05

Nops

    提高payload稳定性及维持大小。在渗透攻击构造恶意数据缓冲区时，常常要在真正要执行的Shellcode之前添加一段空指令区， 这样当触发渗透攻击后跳转执行ShellCode时，有一个较大的安全着陆区，从而避免受到内存 地址随机化、返回地址计算偏差等原因造成的ShellCode执行失败，提高渗透攻击的可靠性。

06

post

    后期渗透模块。在取得目标系统远程控制权后，进行一系列的后渗透攻击动作，如获取敏感信息、跳板攻击等操作

基本  使用 

注：MSF中不区分大小写

msfupdate


更新MSF


msfconsole


启动控制台

msfconsole

参数：

msfconsole -q

安静的方式启动，启动的时候不显示banner信息

msfconsole -h

查看帮助信息

msfconsole -r

资源文件

msfconsole -v

查看版本信息


help或？


查看帮助信息

help vulns

? vulns


exit


退出msfconsole控制台

exit


set


设置参数

    比如要设置渗透的主机IP、payload等。我们可以用show missing查看没有设置的参数

set rhosts 192.168.1.1

set target 34

set payloads windows/shell/reverse_tcp


setg


设置全局变量，避免每个模块都要输入相同的参数，退出当前会话后就失效

setg rhosts 192.168.1.1


unset


取消设置参数

unset rhosts


unsetg


取消设置的全局变量

unsetg rhosts


save


当设置的参数在下一次启动的时候不会生效时，可以用save保存配置到/root/.msf4/config，如果想删除可直接删除/root/.msf4/config 配置文件。

save /root/.msf4/config


check


检查是否存在漏洞（大部分漏洞利用模块下不支持check）


back


退回msfconsole界面


use


search找到模块后，用use使用模块

use exploit/windows/smb/ms08_067_netapi

    用use使用一个模块后，可以使用show options查看我们需要配置的选项，使用show targgets选择目标主机系统、使用show payloads选择payload、使用show advanced查看高级参数、使用show evasion查看用来做混淆、逃避的模块。

run/exploit


执行

run

exploit

exploit -j        #在后台执行监听端口


session


查看建立的连接（shell、meterpreter session、VNC）

session -i id 可以进入一个session交互

session -i 2  进入id为2的session


creds


查看扫描出来的密码信息

creds


vulns


查看扫描出来的漏洞信息

vulns


loot


查看获取到的hash

loot


load


加载插件

load openvas

调用openvas插件，连接外部openvas扫描器

load nessus

调用nessus插件，连接外部openvas扫描器


unload


卸载插件

unload openvas 

unload nessus


loadpath


指定路径加载其他模块，调用自己开发自己编写的漏洞利用模块


route


通过指定session路由流量，添加一条路由，比如发往某个子网的流量都经过攻陷的机器路由转发。


edit


编辑脚本文件


msfconsole

banner


查看banner


color


颜色信息

color false 关闭颜色变化

color true  启动颜色变化

color auto 自动变化


connect

connect


可以理解成MSF中的nc命令

connect -h     #查看帮助信息

connect [options]

connect 192.168.1.1 80


show

显示当前模块下的信息



show all查看所有模块下的信息

show exploits查看exploits模块下的具体信息

show auxiliary 查看auxiliary模块下的具体信息

show payloads查看payloads模块下的具体信息

show auxiliary/exploits/payloads/encoders/nops


search

搜索模块


简单搜索

search ms10-046

查看帮助信息

search -h

搜索关键词

search [keywords]

search name:mysql

search type:exploit

搜索路径

search path:

搜索平台

search platform:aix

search platform:linux

搜索cve

search cve:2022

搜素作者

search author:aaron


show

显示


显示具体配置选项

show options

查看适用目标系统

show targets

查看适用于当前模块下的payloads

show payloads

查看高级参数

show advanced

查看混淆躲避

show evasion

查看没设置的必要参数

show missing


msfdb

用来管理MSF的数据库的命令


启动msf数据库

msfdb start

停止msf数据库

msfdb stop

查看数据库端口是否启动成功

netstat -pantu | grep 5432

查看连接数据库是否成功

    没有数据库的状态下msf可以使用，有了数据库msf更理想的使用状态，有数据库的话可以将渗透过程中获取的一些信息保存下来。

db_status

指定配置文件连接数据库

db_connect

db_connect -h        #查看帮助信息，内含多种连接数据库方式

db_connect  -y /usr/share/metasploit-framework/config/database.yml#使用配置文件连接数据库

    默认msf数据库配置文件在 /usr/share/metasploit-framework/config/database.yml


集成在msf下的nmap扫描命令，扫描出来的结果会自动保存到msf数据库里

可使用nmap里的参数

db_nmap 192.168.1.104  #对目标主机进行扫描

db_nmap -A 192.168.1.104

数据库删除

db_remove

保存数据库

db_save

从当前数据库断开

db_disconnect

数据库导入

db_import

db_import /root/nmap.xml

数据库导出

db_export

db_export -f 文件格式 文件路径

db_export -f xml /root/msfbak.xml

例：将nmap导出的数据库导入到msf中

nmap -A 192.168.1.1 -oX nmap.xml

db_import/root/nmap.xml

将所有模块信息缓存到数据库中，提高数据库检索效率

db_rebuild_cache


hosts

查看当前数据库里保存的信息


hosts -h 查看帮助信息

hosts 192.168.1.104查看具体ip地址的信息

hosts -u查看扫描时开启状态的ip

hosts -c查看指定列的信息

hosts -c address,os_flavor

hosts -S windows搜索windows系统的信息

hosts -S 121搜索包含121的信息

hosts -S 192.168搜索包含192.168的信息


services

查看端口开放信息


services -S 445搜索端口，其他地方有445的话也会搜出来

services -p 445查看开放端口 445只搜开放端口445

services -h 查看帮助信息

services -c 查看指定列信息

created_at|info|name|port|proto|state|updated_at

services -c info,name,port,state

services -p 1-200查看指定范围内端口信息
