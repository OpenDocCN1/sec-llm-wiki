# Apache Struts2 S2-045漏洞原理剖析

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzA5NzQ0Mjc5NA==&mid=2649749366&idx=1&sn=3065184bbbc8b04f085016a9807de419&chksm=88bb99f3bfcc10e5edd0527f18b54976326bea56b1127d2ec9263ec273d8a164a8e22f4baa09&scene=126&sessionid=1681309257#rd](http://mp.weixin.qq.com/s?__biz=MzA5NzQ0Mjc5NA==&mid=2649749366&idx=1&sn=3065184bbbc8b04f085016a9807de419&chksm=88bb99f3bfcc10e5edd0527f18b54976326bea56b1127d2ec9263ec273d8a164a8e22f4baa09&scene=126&sessionid=1681309257#rd)

**1\. 漏洞概述**

官方公告：

> Problem :It is possible to perform a RCE attack with a malicious Content-Type value. If the Content-Type value isn't valid an exception is thrown which is then used to display an error message to a user.改漏洞是利用构造Content-Type出发报错并来实现的任意代码执行。

官方公告中还提到了Jakarta这个Struts2默认的上传组件。

> If you are using Jakarta based file upload Multipart parser, upgrade to Apache Struts version 2.3.32 or 2.5.10.1. You can also switch to a different implementation of the Multipart parser.

官方公告网址：https://cwiki.apache.org/confluence/display/WW/S2-045

**2.Content-Type中“multipart/form-data”的猫腻**

触发该漏洞构造的Content-Type头部必须要存在“multipart/form-data”这个部分，原因是Strus2并没有自己的上传请求解析器，Struts2会调用其他解析器，将HTTP请求中的表单域解析出来。

而默认的解析器就是Jakarta。

![](../Images/836569e34ff5856d681404442456d23d.png)而只有Content-Type头部存在“multipart/form-data”才会将HTTP请求交给Jakarta解析。我们来看一下这部分的源代码，位置在Dispatcher类中：

![](../Images/e091d54664277dc4eed659e3ab53f961.png)

这里可以看见判断了Content-Type中是否存在multipart/form-data，存在则交给MultipartRequest类处理，MultipartRequest主要是是对文件上传进行的处理。而Dispatcher(调度员)类主要是做一些初始化的操作，加载一些配置文件：

![](../Images/310f47bb163b8ed2b6176c30aa6d3478.png)

其次Dispatcher也会将上层(PrepareOperations)传来的HttpServletRequest对象进行分类。

即图二中的if else，在这里请求就分为了两种，文件上传请求和其他请求，文件上传请求则需要进行“包装”成为MultiPartRequestWrapper对象，MultiPartRequestWrapper对象中主要有三个属性：![](../Images/96c63bc1a0644bf069e9625407c477cd.png)主要是存放错误信息(errors)和文件信息(multi)以及一些国际化(Locale)的东西，其中MultiPartRequest类是这次045的主角JakartaMultiPartRequest类的基类，主要是一些文件的基本属性：

![](../Images/ac53f09ef6700ff00b34830b93fa792a.png)

我们回到图二中可以看到：

![](../Images/8c8f162c819f70b6508c5697f82a33e5.png)

而getMultiPartRequest()方法正是读取了默认配置的Jakarta类来实例化：

![](../Images/cf0a6e8f8db30752eb05538813f2d19c.png)![](../Images/0b815069b9ca1162a1b5b3de79f1be93.png)

**3.漏洞原因分析**

接上文，当MultiPartRequestWrapper试图解析请求时：

![](../Images/7a2ca24fba7d766e5041f71e860a3f5d.png)

调用了JakartaMultiPartRequest的parse方法：

![](../Images/d453a53e178b9c0e5e633e82eeffedc7.png)

该方法调用了该类中的processUpload()方法，processUpload()方法会调用该类中的parseRequest()来分析请求，在parseRequest()中会createRequestContext()创建一个新的上下文，以供Jakarta来上传文件：

![](../Images/39d220709d9526ab7efd8e0b032ec1c6.png)

这里的getContentType()方法报错：

![](../Images/21176a944f803368ee48764474f914b8.png)

明显构造的“有毒”的代码不满足startsWith("multipart/")，抛出异常回到到parse()方法中：

![](../Images/71fde47b45bdb33fc3a032add158d8b6.png)

然后buildErrorMessage()方法又调用了LocalizedTextUtil类中的findText方法。

![](../Images/ddc69470fbbb55f4ee3abbfef5f98531.png)

然后在findText(Class aClass, String aTextName, Locale locale, String defaultMessage, Object\[\] args) 中解析了Content-Type中的OGNL并且放入了valueStack中：

![](../Images/638759fb682f77de414841b0afd2431b.png)

然后在将valueStack一起传递到findText(Class aClass, String aTextName, Locale locale, String defaultMessage, Object\[\] args,ValueStack valueStack)中：

![](../Images/02c208d60fd9c4cb050deafb55dfe222.png)

在findText()中将expression(包含POC)扔给translateVariables()函数解析：

![](../Images/966e87205b1f66d29d72db87004ed8f2.png)

执行了构造在Content-Type中的OGNL指令，哪怕devMode关闭状态报错依然会抛出给攻击者。

**4.修复措施**

1.受影响用户可升级版本至Apache Struts 2.3.32 或 Apache Struts 2.5.10.1以消除漏洞影响。

2.修改default.properties中的struts.multipart.parser为cos或pell(需相应包支持)。

3.参考官方版本修复方式:

2.5.10.1：[https://github.com/apache/struts/commit/b06dd50af2a3319dd896bf5c2f4972d2b772cf2b](https://github.com/apache/struts/commit/b06dd50af2a3319dd896bf5c2f4972d2b772cf2b)

2.3.32：[https://github.com/apache/struts/commit/352306493971e7d5a756d61780d57a76eb1f519a](https://github.com/apache/struts/commit/352306493971e7d5a756d61780d57a76eb1f519a)
