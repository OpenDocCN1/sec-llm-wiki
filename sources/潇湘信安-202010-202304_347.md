**0x01 前言**

本文源于实战场景，以下所有测试均基于Fastadmin前台模版getshell漏洞环境。  
  

**环境：**

```
Win10 Phpstudy 2018  PHP-7.0.12 NTS+ApacheFastadmin V1.2.0.20210125_full ThinkPHP 5.0.24Fastadmin默认配置 (不开启app_debug和app_trace)
```

  

**0x02 正文**

我们知道在Thinkphp5没有开启app\_debug的时候，能够写入日志文件的信息很少而且只有触发报错的时候才会写入部分日志信息，如下：  
![](../Images/2667bc4805d32714a820927b7ec9e169.png)  
而直接用url传入php代码，空格会被urlencode。![](../Images/658cd4dea6d2bf19317e5d18a7759ed2.png)  
观察日志信息，与及分析代码，可控有蓝色框的请求IP地址，红色圆圈的请求方法，与及后面的host和请求uri，对应代码：![](../Images/9e1b88f798750f13ea41818b9f9c6b98.png)  
一个个分析一下，ip可以用X-Forwarded-For等，但最后都过滤了。![](../Images/f012a473600bc2ac05150abf8ccd32f1.png)  
**method：**![](../Images/8598c7330ce668a3c9e675bd97ea22f0.png)  
**host：**![](../Images/4aac5d76b6bffe1eaca37763b1317eda.png)  
**uri：**![](../Images/5eb920da888db81165600586a662233f.png)  
可以发现可用的选择还挺多的，method可以用X-HTTP-METHOD-OVERRIDE头，host可以用X-REAL-HOST，uri可以用：X-REWRITE-URL。

*   
*   
*   

```
X-REAL-HOST: <?php phpinfo();?>X-REWRITE-URL: <?php phpinfo();?>X-HTTP-METHOD-OVERRIDE: <?php phpinfo();?>
```

  

**一一对应：**

![](../Images/05a744d40fff40cc7c347b612d15fd17.png)![](../Images/f8607f92933d60e7c70700b85a6bb7f3.png)  
有一点需要注意，看上图，用method头会换成大写，PHP马写进去之后解析可能会出问题，所以建议还是用host和url的两个头  
**实战场景：**Fastadmin普通用户可以登陆，有模版渲染漏洞，没有开app\_debug，无法修改头像，用模版渲染日志文件getshell![](../Images/2b6796d0012cad968202149ea310fb50.png)![](../Images/348089faca5130b9f0c94e55f647afe7.png)![](../Images/4fc29467335028bd79ee61c6050dd51f.png)  

**0x03 总结**

遇到类似的场景时，基于tp5的文件包含、模板渲染写入PHP代码时可尝试用上述的请求头。
