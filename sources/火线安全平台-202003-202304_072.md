**测试范围**

  

  

好大夫互联网侧所有资产，包括但不限于域名、ip、app、小程序等。

如果多个地方存在同样的漏洞，建议打包处理，否则会进行降价处理至降为0。

边缘业务或者新上线的用户量极小的或者旧系统只有很少量的存量数据的业务，漏洞等级会进行降级处理。

同一个组件存在的漏洞导致的问题，通过升级可以解决的问题，只会收录此组件的第一个漏洞。

**漏洞定级**

  

  

**1、严重漏洞：**

*   直接获取基础架构系统权限包括但不限于：核心业务操作系统、核心业务数据库等； 
    
*   直接获取 Web 服务器权限，包括但不限于：远程命令执行、上传并执行 Webshell等； 
    
*   严重的业务逻辑缺陷，可导致：大量用户经济损失，订单及支付系统业务逻辑绕过等；
    
*    严重的程序设计缺陷，可导致：大量用户敏感信息泄露，公司内部核心数据泄露等。
    

**2、高危漏洞：**  

*   越权访问重要应用系统，包括但不仅限于绕过认证直接访问管理后台，后台系统密码泄露等；
    
*   影响一定范围用户账号或资金安全，包括但不限于：非核心 DB SQL 注入，可导致用户账号安全的应用系统漏洞或业务逻辑缺陷等；
    
*   重要业务系统源代码、涉及大量敏感信息的可利用的密钥或涉及大量敏感信息未鉴权的API 的泄露。
    

**3、中危漏洞：**  

*   需用户交互且在主流浏览器中才能产生影响的漏洞，包括但不仅限于针对重要系统的存储型 XSS等；
    
*   普通越权操作，包括但不仅限于不正确的直接对象引用，身份数据篡改等；
    
*    少量的用户敏感信息泄露，包括但不限于：个别用户订单或身份信息泄露等； 
    
*   不涉及资金、订单和用户敏感信息的普通逻辑设计缺陷和业务流程缺陷；
    
*   一定量的非重要系统的普通代码泄露。
    

**4、低危漏洞：**  

*   包括但不限于反射型XSS、非关键业务的存储型XSS等；
    
*   低敏感度信息泄漏；
    
*   公司内部普通数据泄露，如：包括但不仅限于SVN 信息泄漏、配置信息等；
    
*   根据设备、系统、软件或框架的官方告警正在修复的漏洞；
    
*   短信轰炸。
    

  

  

**注意事项**

  

  

1、在需要输入的地方加上**安全测试**或者**测试**字样；

2、由于医疗行业特殊性，请各位白帽提交数据时需注意避免提交医疗纠纷敏感词汇，严禁发布故意诋毁、抹黑相关的不良内容；

3、测试红线：避免无意义的重复性扫描。
