在最初的测试中，Python-agent 未能成功检测出 XSS 漏洞。经团队检查发现，是因为 Django 模板的 hook 规则不完整，导致污点链路断裂。在经过修复后，Python-agent 已经可以成功检测出 XSS 漏洞。  
![](../Images/10cec77fbfd2cd23ac8bf10f1d8b678d.png)  
![](../Images/ac45321e33597b9107021d0d3afa84d9.png)  
另一个 Django 路由里变量的 XSS 漏洞在最初测试中未能检测出的原因在于，路由参数没有 hook 以及路由参数的获取与普通方法获取参数并不相同，另外该靶场还手动使用了 `urllib.parse.unqoute`。在对以上问题增加相应的 hook 规则以及对返回值的 hash 值进行处理后，Python-agent 已可以正常检出。  
注意：对于 Django 需要使用 uwsgi 方式启动，使用 `python manage.py ...` 启动时部分模块 import 可能会早于 hook，会出现部分 hook 点拿不到的情况，影响检出成功率，后续会继续研究解决方案。

![](../Images/bc70c32a70a4fa8168cba743aabe2ea6.png)

测试靶场3

vulpy

  

> Github 地址：https://github.com/fportantier/vulpy
> 
> 框架：Flask

  
通过查看靶场源代码，发现存在存储型 XSS 漏洞，但 Python-agent 目前尚不支持检出；SQL 执行语句使用的是 sqlite3，Python-agent 可以检出。  

经测试， /user/chpasswd、/user/login 存在 SQL 注入，测试过程中只是正常操作，未发送 SQL 注入 payload。

  
![](../Images/b78ae9f4f655b67c9312157e03748548.png)  
正常的输入账号密码进行登录操作，洞态 IAST 检测逻辑依据的是程序执行过程中梳理的调用链，入参是否可控，能否触达危险函数，以下为 SQL 注入过程中的污点调用链，精确到每一行的代码及程序运行过程中当时的变量内容。  
![](../Images/61120fb544b025d2214fbefa0d96d955.png)  
同样的检测逻辑，修改账户密码，经验证，存在 SQL 注入。  
![](../Images/a9fb23db1379e528ea33ebd848864706.png)

**关于洞态 IAST**

洞态 IAST 是全球首个开源 IAST 产品，于2021年9月1日正式开源发布。洞态 IAST 专注于 DevSecOps，具备高检出率、低误报率、无脏数据的特点，帮助企业在应用上线前发现并解决安全风险。自开源发布以来，洞态 IAST 备受开源社区人员和企业的关注，包括工商银行、去哪儿、知乎、同程旅行、轻松筹等在内的上百家企业都已成为洞态用户。官网地址：http://dongtai.io![](../Images/055828956332f480057a66c15fd3c0dc.png)![](../Images/27a0a2b982f2d264792243f58b9d5e16.png)
