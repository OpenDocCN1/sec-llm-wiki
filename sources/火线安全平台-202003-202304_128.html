洞态 IAST 专注于 DevOps，致力于打造成为 DevSecOps 流程中的自动化安全检测利器。为了更好的将洞态 IAST 用于 DevOps 流程中，洞态项目所有服务的发布均采用 DevOps 流程，并在逐步构建完善的“单元测试用例”与“接口自动化测试流程”。目前，洞态 IAST 也用于自身的服务中，检测安全风险。本文的所有内容均来自 DongTai-Agent-Java 的产品发布流程。



01

需求初现


自动化必将代替重复性的人工测试

DongTai-Java-Agent 开源后，一直保持两周一次的上线频率。随着项目的功能越来越复杂、参与开发的用户越来越多，Agent 在上线前，必须对其进行回归测试，确保产品的兼容性、性能、漏洞检出率和误报率与预期一致。
但是，一个仅有11天时限的开发周期却需要处理包括：功能开发、Bug修复、接口联调、兼容性测试、性能测试、漏洞检出率/误报率测试、靶场回归测试等在内的数项任务。功能开发的时间与测试的时间严重不协调，重复性的人工测试占据了迭代周期中大部分的时间。
经过反思，我们发现：比起重复的进行人工测试，我们更需要一种自动化的方法来保证漏洞检测效果、性能测试结果、产品兼容性结果等，避免花费大量的精力在重复性的人工测试工作中，从而有效提高开发人员的效率。

02

降本增效


优化 DongTai-Agent-Java 的 DevOps 流程

引入洞态 IAST 前，DongTai-Agent-Java 的上线流程：
由于每次上线都需要进行一轮完整的测试，所以一开始我们做了如下自动化流程：

  • 搭建所有的中间件运行环境，开发 shell 脚本用于自动化测试，满足中间件的兼容性要求

  • 搭建已知的漏洞靶场环境，开发对应的自动化流量触发脚本或录制流量进行重放

  • 分析漏洞检测的结果，观察是否存在误报/漏报的问题

上述流程减少了一定的人工时间成本，但每次测试的结果，依然需要人工统计并出具结果报告，偶尔还需要人工进行不同版本之间的数据对比，确保 Agent 检测结果的一致性。

04

最佳实践


DongTai-Agent-Java 如何集成到 DevOps 流程并进行版本控制


Java Agent 在 GitHub Action 及 DevOps 流程中的建议启动命令：java -javaagent:/path/to/agent.jar -Dproject.create=true -Dproject.name=WebGoat -Dproject.version=8.2 -Dresponse.length=1000 -Diast.server.mode=local -jar app.jar


需求： 在每次提交代码时，自动将靶场的测试数据存入特定的项目、特定的版本中，方便直接根据项目及版本进行数据的对比分析。
配置参数：

  • 自动创建项目：

    -Dproject.create=true

  • 指定项目名称：

    -Dproject.name=openrasp-vulns

  • 指定项目版本：

    -Dproject.version=${{ github.event_name }}-${{ github.run_number }}

拥抱社区，共同发展

洞态 IAST 在融入 DevOps 流程的过程中，存在着诸多应用场景和用户需求。作为一款开源的 IAST 产品，我们始终与用户站在同一战线，及时满足社区用户的需求与建议。大家在内部的 DevOps 流程中落地实践过程中，遇到的所有问题、需求和建议，都可通过 “GitHub 提交 Issue、Discussion” 或  “微信群” 进行反馈。



关于洞态 IAST 

洞态 IAST 是全球首个开源 IAST 产品，于2021年9月1日正式开源发布。洞态 IAST 专注于 DevSecOps，具备高检出率、低误报率、无脏数据的特点，帮助企业在应用上线前发现并解决安全风险。自开源发布以来，洞态 IAST 备受开源社区人员和企业的关注，包括工商银行、去哪儿、知乎、同程旅行、轻松筹等在内的上百家企业都已成为洞态用户。
