前言

Foreword

近期有洞态 IAST 社区的用户反馈了 WebGoat 靶场 sql 注入漏洞无法检出的问题，本篇文章希望通过记录洞态研发人员解决该问题并提升洞态的检测能力的过程，让社区用户了解洞态 IAST 自定义规则与漏洞检出的原理，为洞态开源社区贡献更多漏洞检测规则。



 问题 

为什么此前 WebGoat 靶场测试的 sql 注入检出率是100%，但实际检出率却不是？
上面的疑惑来自于洞态 IAST 产品负责人 owefsad。由于此前洞态内部测试 WebGoat 靶场的 sql 注入的结果为100%，因此本次社区反馈的问题让内部的研发人员产生比较大的疑问。将此前的测试记录对比之后，以 WebGoat 含有 sql 注入漏洞的接口—— /SqlInjection/assignment5a 为例，进行复查。
在本次复查中，Github Issue 为洞态团队提供了很大帮助。
根据 Issue：HXSecurity/DongTai/#270（https://github.com/HXSecurity/DongTai/issues/270），洞态研发人员得知了洞态 IAST 版本、WebGoat 版本、运行环境等因素，据此复现漏洞未检出时的运行环境。也希望社区用户今后在使用洞态 IAST 出现 bug ，在洞态 github 仓库提交 Issue 时，附上相关环境。洞态的研发人员便可以花费最短的时间去修复，给用户提供更好的体验。
测试结果：未检出该 sql 注入漏洞

通过观察两者的区别，发现调用链在传播方法—— StringConcatHelper.newString() 处出现断链。查看 WebGoat 8.2.2 的源代码，会发现这里依然在调用 StringConcatHelper.newString() 方法。由此，洞态研发人员产生 “为什么这里的 StringConcatHelper.newString() 方法没有被 HOOK 到？”的疑问。
JDK 版本更新，内部某些旧的 API 也会更新。
经过 Debug 源码进行排查，发现问题所在：因为 WebGoat 8.2.2 使用的是 JDK 16，某些内部的 API 进行了改变，以上述方法——StringConcatHelper.newString() 为例，JDK 9 与 JDK 16 的方法参数发生了改变：
// JDK 9    /**     * Instantiates the String with given buffer and coder     * @param buf           buffer to use     * @param indexCoder    remaining index (should be zero) and coder     * @return String       resulting string     */    static String newString(byte[] buf, long indexCoder) {        // Use the private, non-copying constructor (unsafe!)        if (indexCoder == LATIN1) {            return new String(buf, String.LATIN1);        } else if (indexCoder == UTF16) {            return new String(buf, String.UTF16);        } else {            throw new InternalError("Storage is not completely initialized, " + (int)indexCoder + " bytes left");        }    }// JDK 16    /**     * Instantiates the String with given buffer and coder     * @param buf           buffer to use     * @param indexCoder    remaining index (should be zero) and coder     * @return String       resulting string     */    static String newString(byte[] buf, long indexCoder) {        // Use the private, non-copying constructor (unsafe!)        if (indexCoder == LATIN1) {            return new String(buf, String.LATIN1);        } else if (indexCoder == UTF16) {            return new String(buf, String.UTF16);        } else {            throw new InternalError("Storage is not completely initialized, " + (int)indexCoder + " bytes left");        }    }
通过观察，可以发现在⽅法的参数发⽣改变后，洞态的⾃定义规则库⾥并没有该规则，导致没有 HOOK 到该⽅法。定位到问题后，添加该处规则就可以检测到漏洞了！




解决方法

洞态 IDEA 插件快速添加自定义规则
IDEA 查看 JDK 16 的源代码，使用洞态 IDEA 插件的“添加 HOOK 规则”，快速添加自定义规则。
可以看到插件自动生成了方法参数，不需要手动填写
提交之后，显示规则已经添加至云端。
