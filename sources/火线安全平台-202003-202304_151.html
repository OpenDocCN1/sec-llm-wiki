关注我们

近日有用户向仓库提交pr时发现出现了push失败的问题，提示权限不足的问题，经过排查，原来是因为github修改了push验证协议导致。这边给出相应的解决方案。


git强制进行token验证



github规定2021年8月13日以后需要token验证，好多小伙伴在push自己代码的时候都会遇到这样的问题



因为github考虑到了安全性问题，因此必须要进行token验证才可以提交代码。


这样一来安全性大大提升了，但是好多朋友还没有配置过token。这篇文章将会教大家如何从零开始配置自己的token。


生成ssh公钥



首先我们需要检擦一下自己本机的global配置，我们可以输入如下指令：


git config --global --list

你这时候将会得到在本机的配置信息。


如果显示的 user.name 或者 user.email 配置为空的话 则需要进行如下命令行配置自己本机的global信息：

git config --global user.name "你的用户名"git config --global user.email "你的邮箱"

邮箱切记一定要和github的邮箱一致，否则pr等操作可能在被pr的仓库无法记录你的pr信息，即使pr的代码被采纳也无法进入项目贡献者名单。


配置过后我们可以运行命令来生成公钥了。


ssh-keygen -t rsa -C "你的邮箱"


后面会让你进行几个设置，我这边给大家粗略翻译一下，如果没有特殊需求，一路回车设置为默认即可。


  1. 确认秘钥的保存路径，建议默认；

  2. 如果上一步置顶的保存路径下已经有秘钥文件，则需要确认是否覆盖；

  3. 创建密码；

  4. 确认密码


这时候 我们如果没有设置过路径 则直接切换到 ~/.ssh 文件夹然后即可看到 id_rsa 和 id_rsa.pub 两个文件。


我们运行

cat id_rsa.pub

将内容复制出来，进行下一步，ssh配置


ssh配置



进入我们的github，从右上角头像进入settings



然后从左侧列表选择SSH and GPG keys 选项卡


点击右上角的 new SSH key



输入title（你对于这个key的描述）和ssh（刚才cat的那段内容）



然后点击 Add SSH key 即可完成添加


https方式clone的项目修改为ssh模式



我们只需要书写一行命令即可

git remote set-url origin git@github:你的用户名/你的仓库名.git

其他方案



如果不使用ssh进行验证，大家还可以选择自行生成Personal access tokens的模式进行


同样也是settings下，选择Developer settings,再选择Personal access tokens 选项卡，点击右上角的 Generate new token



选择完你需要的功能然后点击创建即可获得一个token，这里token一定要记得保存，因为它只能够生成一次


然后我们可以把token配置进入开发工具



或者清理掉windows下或者macOS下的原始凭据


然后在我们push的时候就会提示我们输入token，把刚才的token加进去就可以了。
