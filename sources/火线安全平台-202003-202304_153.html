你是否也会有这样的困惑：
  • 一个系统有上百个接口，怎么快速判断哪些接口被测试过?
  • 这个业务系统已经「按要求」测试过很多遍了，为什么白帽子还能找到存在漏洞的接口？
  • 这个接口已经让研发部门「下线」了，为什么还能被访问到？
  • QA同学「按照文档」测试的接口为什么与真实上线的接口数量不一致?

随着DevOps流程的普及，应用的研发、集成和交付的效率有了极大的提升，同时也带来了很多新的问题,比如：
研发人员需要梳理出刚维护项目的所有API接口，快速了解项目；
测试人员需要了解即将上线的接口，确保每个接口都经过了测试；
安全人员需要了解系统中是否存在正常功能覆盖不到的API接口，是否依然存在让研发强制下线的API接口等等；

综上，研发、测试、安全团队都需要有一款便捷的API接口梳理工具，用于确保线上应用的稳定性与安全性.

对于安全团队来说，待上线的应用系统数量变得越来越多，面对大量的待上线系统，我们往往会把重心放在系统的安全测试中，确保业务系统可以安全的上线，却没有足够的时间来排查系统里可能存在的隐藏接口与老旧接口，而真正被攻击、被外部发现的安全风险中，相当一部分都来自于这类接口。
那么让我们一起了解一下如何用洞态IAST实现Java Spring项目中隐藏接口、老旧接口的梳理.

01 如何接入

我们使用演示环境：https://demo.iast.io 来进行演示，实际使用时，大家请使用本地化部署的洞态或SaaS版本 https://iast.io

步骤一：下载洞态的Java探针

访问Add Agent页面 ，下载探针到需要部署探针的服务所在机器的磁盘上

步骤二：启动 Spring 服务，配置 Java 探针

以 Sentinel 为例，启动项目，项目地址：https://github.com/alibaba/Sentinel

配置JVM参数，启动项目，并指定项目名称：

java -javaagent:/tmp/agent.jar -Dproject.name=Sentinel -jar app.jar
