本次Elkeid Team开源的 Yara Scanner 插件是使用yara规则对/proc的exe和敏感目录下的文件进行周期扫描，也可以使用fanotify监控敏感目录文件变动，来主动检测恶意或可疑文件（UPX/挖矿二进制/挖矿脚本/可疑脚本文件/...）的插件。


插件地址：

https://github.com/bytedance/Elkeid/blob/main/agent/scanner


1.插件整体架构

该插件有三种扫描任务：Cronjob定时任务，Fanotify目录文件监控，SingleTask临时扫描任务。他们会将需要扫描的文件path以及任务类型发送到channel中，当Scanner从channel中消费到扫描任务后，会使用yara进行扫描。


2.功能&配置说明

2.1 Cronjob定时任务

周期扫描proc下的进程exe文件，和配置中的目录，并根据最大递归深度扫描子目录文件

config.rs可配置项:

SCAN_DIR_CONFIG : 扫描目录，以及递归深度
SCAN_DIR_FILTER : 过滤目录，按照前缀匹配过滤扫描白名单
LOAD_MMAP_MAX_SIZE : 扫描的文件的最大文件大小，跳过大文件
WAIT_INTERVAL_DAILY : 周期扫描每轮的间隔时间
WAIT_INTERVAL_DIR_SCAN : 周期扫描目录下每个文件的间隔时间
WAIT_INTERVAL_PROC_SCAN : 周期扫描proc每个进程exe的间隔时间


2.2 Fanotify 目录文件监控

使用 Fanotify 监控配置目录下的文件变更，当触发 fanotify事件时，发送扫描任务

fmonitor.rs可配置项:

DEFAULT_MASK : Fanotify事件mask(https://man7.org/linux/man-pages/man2/fanotify_mark.2.html)
SCAN_DIR_CONFIG : 监控目录目录(与周期扫描配置的一级目录相同)


2.3 SingleTask单个扫描任务

通过AC-Manager(https://github.com/bytedance/Elkeid/tree/main/server)对Agent插件下发扫描任务(https://documenter.getpostman.com/view/9865152/TzCTZ5Do#fed76842-448f-4d8a-acdc-dab5eccd5371)，并返回扫描结果，下面为任务示例。

{
    "tag": "test_all",
    "id_list": [
        "33623333-3365-4905-b417-331e183333ff"
    ],
    "data": {
        "task": {
            "name": "scanner",
            "data": "{\"content\":\"/home/root/bin.elf\"}"
        }
    }
}


2.4 Clean Buffer

channel 端设置了超时时间，超时后，会drop扫描器以及文件buffer区，直到接收到新的扫描任务后，重新初始化相关缓存和扫描器main.rs中可修改超时时间:

thread::spawn(move || loop {
        let mut _timeout = 300;
        mworker.work(Duration::from_secs(_timeout));
    });


3.返回数据说明

如果存在检出数据，会将告警数据发送到Elkeid Server。

3.1 数据示例

"data_type": "6001",
"exe_hash": "1bd5eb9964a03fa097764493431cf8914dae99f094ffdd09a0b2ae135af79817",
"create_at": "1619084646",
"motify_at": "1619084646",
"timestamp": "1619192201",
"exe": "/root/test/xmrig",
"data": "",
"agent_id": "33623333-3365-4905-b417-331e183333ff",
"types": "miner_stratum_elf"

3.2 通用字段

timestamp : 命中时间
types : 命中yara规则
exe : 命中对象文件目录
exe_hash : 命中对象文件 sha256sum
exe_size : 命中对象文件大小 (byte)
data : 命中对象脚本文件内容 (小于规则配置大小)
create_at : 命中对象文件创建时间
motify_at : 命中对象文件最后内容修改时间

3.3 文件命中(cronjob 目录扫描)

data_type : 6001

3.4 进程exe命中(cronjob proc扫描)

data_type : 6002
pid : 进程ID
ppid : 父进程ID
pgid : 进程组ID
tgid : 线程组ID
argv : cmdline
comm : 进程名
sessionid : session id
uid : 用户ID
pns : 进程namespace

3.5 单个扫描任务结果(SingleTask)

data_type : 6003
error : 如果扫描过程报错则字段非空
token : 任务token

3.6 文件监控命中(Fanotify 监控扫描)

data_type : 6004
pid : 触发 fanotify监控的进程ID

4.Yara 规则示例

本次开源重点在于开放了Yara检测能力，同时也开放了部分检测规则用于示例，配置在 config.rs 的 RULES_SET 变量中。规则示例：

  • UPX二进制

  • 挖矿二进制/脚本

  • 可疑脚本

更多 Yara规则可参考:

  • https://github.com/godaddy/yara-rules

  • https://github.com/Yara-Rules/rules

  • https://github.com/fireeye/red_team_tool_countermeasures

  • https://github.com/x64dbg/yarasigs


5.性能表现

插件目前处于灰度阶段，已在2W左右业务机器上运行1个月以上时间，根据扫描的默认参数，可以保证在插件工作的同时，不会占用过多的系统CPU/内存资源，不会对业务机器/进程造成影响。

注：Yara规则，扫描白名单过滤器，扫描配置等需要根据业务实际情况不断进行调整。
