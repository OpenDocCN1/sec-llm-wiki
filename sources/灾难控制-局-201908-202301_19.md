### 1.3 Connect Hook 数据详解

Common 字段在上期 Execve Hook 数据详解中已经有介绍，可以移步查看。

#### connect\_type

无意义字段，为了兼容老版本存在的字段，后续会移除该字段。

#### sa\_family

表示协议族，仅采集`AF_INET(2)`或`AF_INET6(10)`的数据，即该字段仅可能是`AF_INET(2)`或者`AF_INET6(10)`

可以参考：

https://elixir.bootlin.com/linux/v4.19.193/source/include/linux/socket.h#L160

#### dip

connect destination ip

#### dport

connect destination port

(注：如果是 Linux ping 通常会是1025)

#### sip

connect source ip

#### sport

connect source port

#### res

connect syscall return value

可以参考：

https://man7.org/linux/man-pages/man2/connect.2.html

### 3.1 DNS Hook 介绍

DNS Hook 使用 Hook `udp_recvmsg/udpv6_recvmsg` 实现的，在目前开源版本默认关闭，原因是在非常极端的情况下会有一定的性能开销(压测性能损耗单CPU 10%)，下个版本会优化，并默认开启。

  

### 3.2 DNS Hook 数据格式

Elkeid Driver 输出到 pipe 内的 DNS 数据的格式为`common data` + `dns data`，dns data 如下：

![](../Images/f4e08b6e620d0aec6e7296a62b570528.png)

###   

### 3.3 DNS Hook 数据详解

DNS Hook 仅会采集请求A记录的响应的部分信息

#### query

请求的域名信息

#### sa\_family

表示当前请求的socket的表示协议族

#### dip

表示当前请求的socket的destination ip，通常为DNS Server

#### dport

表示当前请求的socket的destination port，通常为53或5353

#### sip

表示当前请求的socket的source ip

#### sport

表示当前请求的socket的source port

#### qr

Query/Response，当前版本总是为1

#### opcode

Operation Code

![](../Images/e5cd2c5cfc13ab91dcddc10e7f50efe9.png)

一般情况下为0

#### rcode

Return code
