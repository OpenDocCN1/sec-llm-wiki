本文关注 Golang 中的函数在可执行文件中的构成形式，并分析两种 Go 函数 Hook 的实现。

  

**How Go Compiled Source Code**

Golang 提供了多个 Go 编译器：\[gccgo\](https://github.com/golang/gofrontend) 和 gc( "Go compiler", 不是垃圾回收GC），gc 也就是默认提供的编译器，gccgo 使用 CPP 编写了 GCC 的前端（当然也会存在 GoLLVM)。

  

gc 的一些历史：\[Go 1.5 Release Notes\](https://golang.org/doc/go1.5)

  

本文中将会使用 gc，gc 的源码在 \`src/cmd/compile/internal/gc\` 。这里要注意的是在 \`src/go/\*\` 下同时存在诸如：\`go/parser\` 和 \`go/types\` 等与编译器没有关联的 package, 而 gofmt 等处理 Go 源码的工具会使用这些pacakge。

  

通过 \`src/cmd/compile/README.md\` 中的介绍，gc 在编译源码时的过程中共有4个步骤：

1\. Parsing

2\. Type-checking and AST transformations

3\. Generic SSA

4\. Generating machine code

**Go 函数 Hook 的实现**

**Monkey Patch**

Monkey Patch 的实现 \[bouk/monkey」(https://github.com/bouk/monkey), 作者通过分析 Go 编译后的汇编指令发现，在运行时可以通过计算原函数地址后，将要替代的函数的函数体指令覆写为跳转到 Hook 函数的地址，以达到 Hook 的效果。

patch的内容在：\[链接\](https://github.com/bouk/monkey/blob/b118a17387657e860bb85a0f3dafd15cad03c266/monkey\_amd64.go#L15)

覆写的代码在：\[链接\](https://github.com/bouk/monkey/blob/b118a17387657e860bb85a0f3dafd15cad03c266/replace\_unix.go#L23)

通过实现\`monkey.PatchGuard\` \[链接\](https://github.com/bouk/monkey/blob/b118a17387657e860bb85a0f3dafd15cad03c266/monkey.go#L37)， 可以做到在 Hook 函数内使用原函数。

**Gohook**

Gohook 的实现 \[brahma-adshonor/gohook\](https://github.com/brahma-adshonor/gohook)，通过作者在\[文章\](https://www.cnblogs.com/catch/p/10973611.html)里的描述，“gohook 则通过把目标函数绝对地址压到栈上，再执行 ret 指令实现跳转”，代码生成：\[链接\](https://github.com/brahma-adshonor/gohook/blob/4dfde2738c748d3f9c7a7889c90c927b3f7af4f1/arch\_util.go#L743)，这里会有判断，如果\`|from-to| < 2G\` 则使用\`relaive jump\`, 直接 \`jmp\` 到Hook函数。

\`jmp func\_b\` 5 bytes 会插入到被Hook函数的入口，并且通过\`Trampoline\`的方式回到原函数。下图说明了原理：
