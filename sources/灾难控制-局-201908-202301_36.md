#### 2.增加部分Rootkit检测功能

这部分功能主要参考了 **Tyton**:https://nbulischeck.github.io/tyton/ 项目实现，主要针对的是Linux Kernel Module型的Rootkit，目前移植的检测项有：

*   Syscall/Interrupt Descriptor Table Hooking
    
    通过遍历Syscall Table和Interrupts Table来检测是否存在不在预期内的内存地址
    
    Kernel memory map in x86\_64：
    
    ![](../Images/7f2e62be59a3ae91a2c63deb9fa8fb5a.png)
    
    告警数据样例：
    
      
    
    ![](../Images/8a68272a38dbf2f92642bb57a54e7497.png)
    
*   Hidden Modules
    
    通过遍历`module_kset`和`find_module(kobj->mod->name))`进行对比，来检测尝试隐藏自己的LKM。
    
    Kset-Kobject relationship:
    
    ![](../Images/b67a665a1bb77d0b519fbf9e14353dd6.png)  
    
    告警数据样例：
    
      
    
    ![](../Images/26ae2ade7aaed123b7ea411ac2a4ccf6.png)
    
*   Process File Operations Hooking
    
    通过检测`/proc` 的`f_op`的`iterate`或者`readdir`来检测是否有指向某个LKM。
    
    告警数据样例：
    
      
    
    ![](../Images/4e21b374f9269a18d0b591784a50f4dd.png)
    

目前RootKit检测能力覆盖尚不全面，后续会逐步增加。且需要注意的是目前仅支持Kernel >= 3.10，默认15分钟检测一次。

#### 3.增加Cred变更检测

该功能通过Hook各位Hack最喜欢用的**commit\_creds**来实现的，为了避免无意义告警过多，目前仅在**UID非0通过commit\_creds后UID变为0，且comm不为：sudo/su/sshd**的前提下产生告警。
