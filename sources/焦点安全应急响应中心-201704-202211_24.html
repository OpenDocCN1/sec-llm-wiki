引语

‍‍‍XSS是Web应用程序中常见的漏洞类型之一，也经常位居于 OWASP top 10 榜单。攻击者可以在网页中嵌入客户端脚本，当用户使用浏览器浏览网页时，脚本就会在用户的浏览器上执行，从而达到攻击者的目的。
现在很多网站管理员通过过滤用户输入内容、根据上下文转换输出数据、正确使用 DOM、强制执行跨源资源共享（CORS）策略以及其他的安全策略来规避XSS漏洞。但基于正则表达式的字符串检测仍是目前广泛使用的技术。目前很多Web应用防火墙（WAF）就是利用正则表达式对XSS进行防御。
固然有WAF的加持，绕过正则过滤也不是不可实现的，本文章将以最近学习的一个CVE漏洞入手，对XSS绕过正则过滤做一个思考分析。



    

jQuery 简介

jQuery 于2006年1月由 John Resig 发布，是一个快速、简洁的 JavaScript 框架。它封装 JavaScript 常用的功能代码，提供一种简便的 JavaScript 设计模式，用来优化HTML文档操作、事件处理、动画设计和Ajax交互。
jQuery 的核心特性可以总结为：具有独特的链式语法和短小清晰的多功能接口；具有高效灵活的CSS选择器，并且可对CSS选择器进行扩展；拥有便捷的插件扩展机制和丰富的插件。jQuery 兼容各种主流浏览器，如：IE6.0+、FF1.5+、Safari2.0+、Opera9.0+等。

漏洞原理



导致上述问题的关键是，在html()方法中，作为参数传递的HTML字符串将传递到 $ .htmlPrefilter() 方法中。这个方法用于替换自闭合标签，如将<tagname /> 替换为 <tagname ></tagname>，3.x之前使用的正则是：

rxhtmlTag =/<(?!area|br|col|embed|hr|img|input|link|meta|param)(([\w:-]+)[^>]*)\/>/gi[...]htmlPrefilter: function( html ){return html.replace(rxhtmlTag, "<$1></$2>" );}

3.x之后使用的正则稍作改变：

rxhtmlTag =/<(?!area|br|col|embed|hr|img|input|link|meta|param)(([a-z][^\/\0>\x20\t\r\n\f]*)[^>]*)\/>/gi

这就引出了环境里的PoC2（仅适用于jQuery3.x），这里的XSS payload是作为属性出现，所以可以绕过规则：

<img alt="<x" title="/><img src=xonerror=alert(1)>

该PoC使用 html() 方法执行后发现变为：

<img alt="<x" title="/></x”><imgsrc=x onerror=alert(1)>

该正则会将x"识别为标签并新增</x”>闭合标签，从而达到XSS的效果：

针对上述漏洞原理，jQuery Team 进行了修复，修复手段为将 $.htmlPrefilter() 方法替换为标识函数，因此传递的HTML字符串现在不再经过 htmlPrefilter 函数处理，从而成功修复了漏洞。

但仍有手段可以绕过，CVE-2020-11023 就是针对 CVE-2020-11022 的绕过：绕过使用的是另一个特性，某些特殊的标签在经过 html() 方法处理时，会由于HTML的特性或浏览器的bug而使得这些标签被移除。

option 就是这些特殊标签之一，我们知道 option 元素通过位于 select 元素内部来构造一个选择列表，但如果没有 select 元素，option 会被移除。为了解决这个bug，如果传入参数的第一个元素为 option，jQuery 会新增<select multiple='multiple’>和</select>。

所以我们提交PoC3：

<option><style></option></select><imgsrc=x onerror=alert(123456)></style>

经过处理会变为：

<select multiple='multiple'><option><style></option></select><imgsrc=x onerror=alert(123456)></style></select>

根据HTML从前往后解析的顺序，会先解析一个<select>标签，且<select>不允许将大部分HTML标签包裹其中，导致<style>被忽略，而后识别<img>标签从而XSS。



    

经验分享

当今WAF虽然阻拦了很多XSS漏洞，但毕竟是机器，不能结合实际情况来识别标签，XSS的分量已然不容小觑。从文中CVE可以看出，甲方安全团队需要针对给定的上下文环境，确定各种不同的 payload 结构以达到最优的防御效果，有效地规避XSS漏洞。同时，应该结合各种实例完善WAF规则，逐步减少XSS存在的数量，防止黑客操作JS或利用Cookie对公司进行攻击。
