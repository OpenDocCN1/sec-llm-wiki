**引语**  
  

‍‍‍XSS是Web应用程序中常见的漏洞类型之一，也经常位居于 OWASP top 10 榜单。攻击者可以在网页中嵌入客户端脚本，当用户使用浏览器浏览网页时，脚本就会在用户的浏览器上执行，从而达到攻击者的目的。现在很多网站管理员通过过滤用户输入内容、根据上下文转换输出数据、正确使用 DOM、强制执行跨源资源共享（CORS）策略以及其他的安全策略来规避XSS漏洞。但基于正则表达式的字符串检测仍是目前广泛使用的技术。目前很多Web应用防火墙（WAF）就是利用正则表达式对XSS进行防御。固然有WAF的加持，绕过正则过滤也不是不可实现的，本文章将以最近学习的一个CVE漏洞入手，对XSS绕过正则过滤做一个思考分析。

  

  

**jQuery 简介**  
  

jQuery 于2006年1月由 John Resig 发布，是一个快速、简洁的 JavaScript 框架。它封装 JavaScript 常用的功能代码，提供一种简便的 JavaScript 设计模式，用来优化HTML文档操作、事件处理、动画设计和Ajax交互。jQuery 的核心特性可以总结为：具有独特的链式语法和短小清晰的多功能接口；具有高效灵活的CSS选择器，并且可对CSS选择器进行扩展；拥有便捷的插件扩展机制和丰富的插件。jQuery 兼容各种主流浏览器，如：IE6.0+、FF1.5+、Safari2.0+、Opera9.0+等。

**漏洞分析——CVE-2020-11022/11023**  
  

  
  
  
漏洞背景  

  

针对本次分析的CVE，我们首先了解一下它的背景，在NVD中是这么描述的：大于或等于1.2且小于3.5.0的 jQuery 版本中，即使执行了消毒（sanitize）处理，仍会将来自不受信任来源的 HTML 传递给 jQuery 的DOM操作方法，即 html()、.append() 等，从而导致XSS。![](../Images/c55236b2bb30f2d51fa557530f5058db.png)与此次 jQuery 漏洞联系比较紧密的是 html() 方法，此方法返回或设置被选元素的内容 (inner HTML)，可用于设置所有选定元素的内容。在此引用一个简单的例子：![](../Images/268a2d5841434308578e16b9c932c46d.png)在此处定义一个点击事件，会对所有的p元素进行匹配，并将它修改为相同的内容。由此我们展开对CVE的分析理解。

但仍有手段可以绕过，CVE-2020-11023 就是针对 CVE-2020-11022 的绕过：绕过使用的是另一个特性，某些特殊的标签在经过 html() 方法处理时，会由于HTML的特性或浏览器的bug而使得这些标签被移除。

**经验分享**  
  

当今WAF虽然阻拦了很多XSS漏洞，但毕竟是机器，不能结合实际情况来识别标签，XSS的分量已然不容小觑。从文中CVE可以看出，甲方安全团队需要针对给定的上下文环境，确定各种不同的 payload 结构以达到最优的防御效果，有效地规避XSS漏洞。同时，应该结合各种实例完善WAF规则，逐步减少XSS存在的数量，防止黑客操作JS或利用Cookie对公司进行攻击。
