Debug端口开放存在被攻击的风险，这个系列我们介绍 Node.js、Headless Chrome 、Java、Golang 、Flask、Django六类语言或框架中的debug端口漏洞检测和攻击方式。本篇介绍Golang 、Flask、Django三类远程调试器的攻击面和检测方式，Node.js、Headless Chrome 、Java请看上一篇分享介绍。

Golang


Delve是Go编程语言的调试器。对于远程调试，Delve使用JSON-RPC协议（通常在端口2345上）

编写测试代码:

package main
import (
    "os/exec"
    "fmt"
    "log"
)
func main() {
    cmd := exec.Command("ls","-l")
    out, err := cmd.CombinedOutput()
    if err != nil {
        log.Fatalf("cmd.Run() failed with %s\n", err)
    }
    fmt.Printf("combined out:\n%s\n", string(out))
}

开启本地调试golang程序：

dlv debug test.go                                              

开启远程调试golang程序：

dlv --listen=:2345 --headless --api-version=2 debug test.go

为了在"API模式"下运行Delve，使用--headless标志进行调用，这会以非交互方式启动调试器，侦听指定地址。使用--accept-multiclient可以多个客户端连接。

Delve当前支持其API的两个版本。默认情况下使用APIv1，选择APIv2的话要使用--api-version=2命令行参数。

dlv connect ip:port连接debug服务器，help查看命令，call命令可以调用当前程序import的函数，如果导入了"os/exec"包，那么就可以call "os/exec".Command来执行系统命令。

先通过b main.mian为main函数打个断点，c执行到main函数，n执行下一步

命令执行到定义cmd的时候，执行call cmd="os/exec".Command("ls" ,os.Args)，再执行call cmd.CombinedOutput()，返回标准输出和标准错误，返回结果如下，其中~r0（ASCII码）就是命令的结果：

这样做的前提是程序import os/exec。

关于检测，Delve公开了JSON-RPC API接口。JSON-RPC接口通过套接字而不是HTTP服务。可以发送请求获取远程服务器信息，根据响应的数据进行判断。

请求和返回的格式都是json格式，方法名称RPCServer，所有方法都可以在这个网站中查看https://pkg.go.dev/github.com/go-delve/delve/service/rpc2#RPCServer

请求格式：

{ "method":"方法名", "params":["参数数组"], "id":方法ID}

如果想要在函数上或者在某行设置断点，第一步将FindLocation使用Scope = api.EvalScope{ GoroutineID: -1, Frame: 0}，调用方法Loc = "main.main"或者行数Loc ="10"。JSON-RPC请求数据包应如下所示：

{"method":"RPCServer.FindLocation","params":[{"Scope":{"Gorout
ineID":-1,"Frame":0},"Loc":"10"}],"id":1}

响应数据包将如下所示：

{"id":1,"result":{"Locations":[{"pc":5152114,"file":"/root/go/
src/test/test.go","line":10,"function":{"name":"main.main",
"value":5152064,"type":0,"goType":0,"optimized":false},"pcs":
[5152114]}]},"error":null}
可以看见当前断点在第10行
还可以通过State返回当前调试器状态，请求数据包如下：
{"method":"RPCServer.State","params":[{"NonBlocking":true}],
"id":2}
响应数据包将如下所示：
{"id":2,"result":{"State":{"Running":false,"Recording":false,"CoreDumping":false,
"currentThread":{"id":69743,"pc":5152114,"file":"/root/go/src/test/test.go","line":10,
"function":{"name":"main.main","value":5152064,"type":0,"goType":0,"optimized":false},…
检测脚本大致如下：
sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
sock.connect((ip, int(port)))
payload = '{"method":"RPCServer.SetApiVersion","params":
[{"APIVersion":2}],"id":0}'
sock.send(payload)
resp = sock.recv(1024)
if '{"id":0,"result":{},"error":null}' in resp:
    print（"[*] golang delve debugger open")
sock.close()
pprof：
pprof是go的性能分析的工具，可以用来监测进程的运行数据，用于监控程序的性能，对内存使用和CPU使用的情况信息进行分析。官方提供了两个包：runtime/pprof和net/http/pprof，前者用于普通代码的性能分析，后者用于web服务器的性能分析。
本文引入包_"net/http/pprof"，然后就可以在浏览器中使用http://localhost:port/debug/pprof/直接看到当前web服务的状态，包括CPU占用情况和内存使用情况等
编写测试代码:
启动一个端口（和正常提供业务服务的端口不同）监听 pprof 请求：
package main
import (
       "fmt"
       "log"
       "net/http"
       _ "net/http/pprof"
)
func main() {
       http.HandleFunc("/", func(w http.ResponseWriter,
r *http.Request) {
              fmt.Fprintf(w, "Hello World!")
       })
       log.Fatal(http.ListenAndServe(":8081", nil))
}

启动服务后，直接在浏览器访问：

http://ip:8081/debug/pprof/

可以直接点击上面的链接，进入子页面，可以查看相关的汇总信息。

还可以先后台采集一段时间的数据后（默认从当前开始收集30s的cpu使用情况），直接使用如下命令，不需要通过点击浏览器上的链接就能进入命令行交互模式：

go tool pprof http://x.x.x.x:8081/debug/pprof/profile

造成的风险：函数名称和文件路径会显示出来，数据可能会泄露业务敏感信息Web服务器的流量等，分析会降低性能，为DoS攻击提供载体。

关于检测，可以通过访问http://ip:8081/debug/pprof/响应的数据来判断是否有/debug/pprof/指纹：

urlstr = url + '/debug/pprof/'
re = requests.get(urlstr)
patternStr = '<title>/debug/pprof/'
if re.status_code == 200:
    if re.text.find(patternStr) != -1:
        print("[*] pprof exist")
Flask


Flask是一个用Python编写的Web应用程序框架


写一个简单的基于Flask的Web应用，开启调试模式debug=True：

from flask import Flask
app = Flask(__name__)
@app.route("/")
def test():
    return testparam
if __name__ == "__main__":
app.run(host="0.0.0.0", port=80, debug=True)

代码是存在错误的，testparam没有定义，先执行起来。



当访问网站的时候执行test()函数，会出现500错误，进入debug页面



这个时候发现，后端控制台显示访问了这几个路径，说明进入debug页面的时候访问了，那么这可以作为检测脚本的一个方式。


访问"/?__debugger__=yes&cmd=resource&f=debugger.js"的页面如下，我们可以根据返回的字符串来判断debug


大致代码如下：

def verity(url):
    path = '/?__debugger__=yes&cmd=resource&f=debugger.js'
    str = 'if we are in console mode, show the console.'
    res = requests.get(url+path)
    text = res.text
    if text.find(str) != -1:
        print("[*] flask debug exist")

重要的是debug页面点击console图标可获得debug权限，包含Python交互式shell，如果没有开启pin码进行校验，可直接获取python交互式shell进行命令执行，但是想进入shell一般都需要PIN码：


经过分析生成的PIN码，需要知道六个参数：

1.  username：当前主机的用户名

2.  modname：'flask.app'

3.  getattr(app, "name",app.class.name)：一般默认 flask.app 为'Flask'

4.  getattr(mod, "file",None)：flask目录下的一个app.py的绝对路径,可在报错页面看到

5.  str(uuid.getnode())：网卡MAC地址的十进制值

6.  get_machine_id()：系统id，在linux系统下的存储位置为/etc/machine-id

一般需要通过任意文件读取漏洞读取到生成pin码的第5,6个参数。

Django


使用命令django-admin startproject djangoprogram创建好django的项目之后，设置：debug=True（默认值是True），还需要正确的设置ALLOWED_HOSTS列表，代表可以服务的主机名或域名。


在旧的Django版本中，如果DEBUG=True，ALLOWED_HOSTS没有被检查。在Django 1.10.3，1.9.11和1.8.16版本中改变，以防止DNS重新绑定攻击。

运行服务器命令如下：

python manage.py runserver ip:port

访问ip， debug页面可以看见所有的路径

当遇到错误时会泄漏代码片段和项目的完整路径，可以进一步分析

当DEBUG设为True，且ALLOWED_HOSTS为空时，会使用['localhost', '127.0.0.1', '[::1]']来验证Host头。请求头的host不在ALLOWED_HOSTS列表中时，会返回DisallowedHost，抓包看一看：

那么检测的脚本就可以通过修改host根据返回之中的"DisallowedHost at"来判断

headers = {
    'Host': 'SomeInvalidHost',
}
re = requests.get(url, headers=headers)
patternStr = '<title>DisallowedHost'
if re.status_code == 400:
    if re.text.find(patternStr) != -1:
        print("[*] django debug exist")
