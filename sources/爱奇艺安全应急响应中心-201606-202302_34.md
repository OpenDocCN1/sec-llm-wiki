**pprof****：**

pprof是go的性能分析的工具，可以用来监测进程的运行数据，用于监控程序的性能，对内存使用和CPU使用的情况信息进行分析。官方提供了两个包：runtime/pprof和net/http/pprof，前者用于普通代码的性能分析，后者用于web服务器的性能分析。

本文引入包\_"net/http/pprof"，然后就可以在浏览器中使用http://localhost:port/debug/pprof/直接看到当前web服务的状态，包括CPU占用情况和内存使用情况等

启动服务后，直接在浏览器访问： 

http://ip:8081/debug/pprof/

![](../Images/92744c6cf9d2b3fd6c0deb61fc86fbe1.png)

可以直接点击上面的链接，进入子页面，可以查看相关的汇总信息。

还可以先后台采集一段时间的数据后（默认从当前开始收集30s的cpu使用情况），直接使用如下命令，不需要通过点击浏览器上的链接就能进入命令行交互模式：

![](../Images/72864931700dfb5aa01fdd44e3095e9c.png)

经过分析生成的PIN码，需要知道六个参数：

1.  username：当前主机的用户名

2.  modname：'flask.app'

3.  getattr(app, "name",app.class.name)：一般默认 flask.app 为'Flask'

4.  getattr(mod, "file",None)：flask目录下的一个app.py的绝对路径,可在报错页面看到

5.  str(uuid.getnode())：网卡MAC地址的十进制值

6.  get\_machine\_id()：系统id，在linux系统下的存储位置为/etc/machine-id

一般需要通过任意文件读取漏洞读取到生成pin码的第5,6个参数。

**Django**  
  

使用命令django-admin startproject djangoprogram创建好django的项目之后，设置：**debug=True****（**默认值是True），还需要正确的设置ALLOWED\_HOSTS列表，代表可以服务的主机名或域名。  

  

在旧的Django版本中，如果DEBUG=True，ALLOWED\_HOSTS没有被检查。在Django 1.10.3，1.9.11和1.8.16版本中改变，以防止DNS重新绑定攻击。

运行服务器命令如下：

```
python manage.py runserver ip:port
```

![](../Images/9082e3f7294396b383ba3ab764cc2ccf.png)

访问ip， debug页面可以看见所有的路径

![](../Images/7b36d373ea83e2338367b4cd5d2ef3a3.png)

当遇到错误时会泄漏代码片段和项目的完整路径，可以进一步分析

![](../Images/3068b222a87feab75a471b7337cd737d.png)

当DEBUG设为True，且ALLOWED\_HOSTS为空时，会使用\['localhost', '127.0.0.1', '\[::1\]'\]来验证Host头。请求头的host不在ALLOWED\_HOSTS列表中时，会返回DisallowedHost，抓包看一看：

![](../Images/21a2623e47983f8da141074b32485830.png)

那么检测的脚本就可以通过修改host根据返回之中的"DisallowedHost at"来判断
