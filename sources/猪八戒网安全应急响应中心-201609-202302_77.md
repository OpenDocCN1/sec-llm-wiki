> > 2、SQL注入
> > 
> > **成因:**
> > 
> >  所谓SQL注入，就是通过把SQL命令插入到Web表单提交或输入域名或页面请求的查询字符串，最终达到欺骗服务器执行恶意的SQL命令。
> > 
> > **案例：**
> > 
> >  搜狐焦点主站存在SQL注入
> > 
> > ![](../Images/3f2122e6645e606de1a041177b9c668d.png "1479711307822740.png")
> > 
> > ![](../Images/70faec858cec9fa2fc595efff6339f25.png "1479711315351165.png")
> > 
> > **防御策略：**
> > 
> >  Mybatis安全配置
> > 
> > Mybatis某sql语句的xml配置
> > 
> > ![](../Images/ddbe90467b2a2780d274b89fb193b3d1.png "1479711395382880.png")
> > 
> > 预编译后的sql，使用占位符?，这样数据库在执行sql时，传入的数据只会作为参数替换占位符
> > 
> > ![](../Images/0239007d749e9ca5129fc7f6cd9727d7.png "1479711437595907.png")
> > 
> > Mybatis安全配置为何可以规避sql注入?
> > 
> > Mybatis框架底层使用了JDBC组件中的preparedstatement类（预编译语句）
> > 
> > a.提升系统性能：一次编译多次执行
> > 
> > b.提升系统安全性：使用预编译语句，传入的任何内容就不会和原来的语句发生任何匹配的关系，也就是说不会影响原有语句的逻辑

> > 3、上传类
> > 
> > **成因:**
> > 
> >  文件上传漏洞是指用户上传了一个可执行的脚本文件，并通过此脚本文件获得了执行服务器端命令的能力。
> > 
> > **案例：**
> > 
> >  中国移动某站Struts2命令执行（已getshell）
> > 
> > ![](../Images/01acc06a61d2773dce5e4cb7acea1535.png "1479717539223668.png")
> > 
> > ![](../Images/fadcce47e802cf746373eda6d6ec8f80.png "1479717548471040.png")
> > 
> > **防御策略：**
> > 
> >  1、使用FastDFS存储
> > 
> > 采用FastDFS对资源文件进行管理，功能包含文件存储、文件同步、文件访问（文件上传、文件下载）等，解决了大容量存储和负载均衡的问题，同时也规避了恶意脚本上传执行的风险。

> > > > 4、CSRF
> > > > 
> > > > **成因:**
> > > > 
> > > >  该漏洞是多窗口浏览器带来的，攻击者通过浏览器中共享的cookie伪造恶意请求，通过伪造身份提交恶意请求至服务器来进行攻击。
> > > > 
> > > > **案例：**
> > > > 
> > > > 中国移动某站Struts2命令执行（已getshell）
> > > > 
> > > > 某站点更改密码存在CSRF漏洞

> > > >

> > > > 
> > > > **防御策略：**
> > > > 
> > > >  csrf防御组件
> > > > 
> > > > 通过过滤器来防范CSRF。用户通过浏览器第一次请求服务器时，把token写入cookie中。业务请求时携带随机Token，filter来比较随机Token是否一致。
