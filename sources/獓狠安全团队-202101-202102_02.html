一、Windows 启动目录：

Windows 启动目录分为，用户启动目录，与系统启动目录。

用户启动目录是登录特定用户的时候才会启动。

系统启动目录是所有登录该计算机的用户都会启动。

1、用户启动目录(普通用户权限即可)：

C:\Users\{username}\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup

2、系统启动目录(需要管理员权限)：

C:\ProgramData\Microsoft\Windows\Start Menu\Programs\StartUp

如果通过 move 的方式向系统启动目录的写入需要进行提权，才可写入

move c:\xxx.exe "C:\ProgramData\Microsoft\Windows\Start Menu\Programs\StartUp\xxx.exe"

二、Windows 服务注册：

(需要本地管理组权限，实战不推荐使用)

通过在注册表中注册恶意服务并设置为自启动的方式来进行持久化。

1、CMD 通过 sc 进行注册：

理论上说是可行的，但是我这个服务起不来，就很迷，而且创建的可以在服务里看到，所以就当多了解点

需要注意SC 命令需要等号后面接空格在加参数
命令详解：sc create 服务名 binpath= "命令" start= "auto" obj= "objectname"

sc create test binpath= "cmd.exe /k C:\xxx.exe" start="auto" obj="LocalSystem"

sc start test #立即启动服务

2、PowerShell 通过New-service 创建：

New-service -Name "服务名" -BinaryPathName "执行的命令" -Description "" -StartupType Automatic

sc start test2

三、Registry Run Keys（注册表注册键）：

1、Run 注册键 ：

（1）、HKCU:

计算机\HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run

我们通常安装的软件，其开机自启动都会放在该注册表下。如图

添加键值只需要普通用户权限

reg add "HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run" /v qf_test /t REG_SZ /d "C:\WINDOWS\system32\notepad.exe"

（2）、HKLM:

计算机\HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows\CurrentVersion\Run

有效负载将在每次系统启动时执行，与使用系统身份验证的用户无关。

添加键值需要管理员权限

reg add "HKEY_LOCAL_MACHINE\Software\Microsoft\Windows\CurrentVersion\Run" /v qf_test1 /t REG_SZ /d "C:\WINDOWS\system32\notepad.exe"

2、Userinit 注册键：

Userinit 位于

计算机\HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon

以下是微软对于该注册键的说明：

指定用户登录时Winlogon运行的程序。默认情况下，Winlogon运行Userinit.exe，后者运行登录脚本，重新建立网络连接，然后启动Windows用户界面Explorer.exe。

您可以更改此条目的值以添加或删除程序。例如，要在Windows资源管理器用户界面启动之前运行程序，请在该条目的值中用该程序的名称替换Userinit.exe，然后在该程序中包含说明以启动Userinit.exe。如果您脱机工作且未使用登录脚本，则可能还需要用Explorer.exe代替Userinit.exe。

Userinit注册键是可以通过逗号分割多个应用程序，并且执行的程序还可以带参数（也就意味着，可以利用 powershell 实现无文件后门持久化）。需要注意的是，修改 Userinit 必须要管理员权限才可。

（1）、通过 Reg 修改注册表 ：

reg add "HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon" /v Userinit /t REG_SZ /d "C:\Windows\system32\userinit.exe,cmd.exe" /f

（2）、通过 PowerShell 修改注册表：

Set-ItemProperty "HKLM:\SOFTWARE\Microsoft\WINDOWS NT\CurrentVersion\Winlogon" -name Userinit -value "C:\Windows\system32\userinit.exe,cmd.exe /c calc.exe"

3、LogonScript 注册键(普通用户权限)：

UserInitMprLogonScript 注册键位于 "计算机\HKEY_CURRENT_USER\Environment"下，大多数系统，注册表中都不会包含这一项。我们只需要创建该键即可。reg 或 powershell 都可以完成。

reg add "HKEY_CURRENT_USER\Environment" /v UserInitMprLogonScript /t REG_SZ /d "c:\users\susu\desktop\1.bat" /f

New-ItemProperty "HKCU:\Environment" UserInitMprLogonScript -value "c:\users\susu\desktop\1.bat" -propertyType string | Out-Null

注销登录就可以发现文件成功被写入，并且需要注意的是，LogonScript 的启动优先级较高，甚至优于某些杀软启动。(测试中bat会弹窗)

4、Load 注册键(普通用户权限)

Load 注册键位于 “计算机\HKEY_CURRENT_USER\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Windows” 下。通常该键也是不存在的，但是也可以通过添加 load 键值的方式，使其生效。

reg add "HKEY_CURRENT_USER\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Windows" /v load /t REG_SZ /d "c:\users\susu\desktop\1.bat" /f

New-ItemProperty "HKCU:\Software\Microsoft\Windows NT\CurrentVersion\Windows" load -value "c:\users\susu\desktop\1.bat" -propertyType string | Out-Null

5、Explore\run 注册键(管理员权限)：

Explore\run 位于 HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Policies\Explorer 与 HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\Explorer  下, 这两个注册表项需要提权才能进行修改。

reg add "HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Policies\Explorer\run" /v twin /t REG_SZ /d "lala.exe" /f

WIN 10进行测试的时候，发现通过这种方式创建的持久化，会触发 explorer 的错误，只有关闭掉该错误提示，才会进行后续动作

win7、win2008 R2、win2012 R2 、win2016均无explorer 报错，正常执行测试的bat，但是测试2012(这台是域控)时发现管理员权限会“报错：拒绝访问”，我认为可能是在域控底下的机子会被访问控制

(这里如果不对的话，还请师傅们指正，修改)

图左：2012，域hack.lab，图右：2012 R2

而单纯使用 PowerShell 进行创建的话，(大部分只有Policies) 则先需要创建 run 注册表项，然后在创建健值。

New-Item "HKCU:\HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Policies\Explorer\run"

New-ItemProperty "HKCU:\HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Policies\Explorer\run" run_shell -value "c:\users\susu\desktop\4.bat" -propertyType string | Out-Null

6、Command Processor\AutoRun 注册键（管理员）：

注册键位于HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Command Processor 启动时间先于用户登录。在完全重启计算机时会运行。

New-ItemProperty "HKLM:\HKEY_LOCAL_MACHINE\Software\Microsoft\Command Processor" AutoRun -value "c:\users\susu\desktop\5.bat" -propertyType string | Out-Null

并且是以system权限启动

7、Winlogon\taskman 注册键(管理员)：

HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon

其实HKCU底下也有该目录，但是测试只有HKLM注册表下的taskman才生效

New-ItemProperty "HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon" taskman -value "c:\users\susu\desktop\4.bat" -propertyType string | Out-Null

8、Windows NT\CurrentVersion\Windows\run 注册键(普通用户)：

Windows\run 注册键位于 HKCU:\Software\Microsoft\Windows NT\CurrentVersion\Windows 下 HKLM 下的该键则不会生效。并且该键值是需要用户登录桌面后才会启动，且是当前用户权限。

New-ItemProperty "HKCU:\Software\Microsoft\Windows NT\CurrentVersion\Windows" run -value "c:\users\susu\desktop\2.exe" -propertyType string | Out-Null

9、Windows NT\CurrentVersion\Windows\load 注册键：

位于 HKCU:\Software\Microsoft\Windows NT\CurrentVersion\Windows 下和 Windows\run 一样，只有 HKCU 下的该键才生效。

New-ItemProperty "HKCU:\Software\Microsoft\Windows NT\CurrentVersion\Windows" load -value "c:\users\susu\desktop\3.exe" -propertyType string | Out-Null

四、计划任务（管理员）：

win7及之前：at ，XP不需要管理员权限(XP无powershell)

不能将任务在前台执行，只会打开一个后台进程

win8之后：schtasks

系统启动时执行
schtasks /create /tn PentestLab /tr "需要运行的程序或执行的命令" /sc onstart /ru System

schtasks /create /tn PentestLab /tr "需要运行的程序或执行的命令" /sc onidle /i 30

schtasks /create /tn PentestLab /tr "需要运行的程序或执行的命令" /sc onlogon /ru System

schtasks /create /tn Updater /tr notepad.exe /sc hourly /mo 1
