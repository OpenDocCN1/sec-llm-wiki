# **AWS事件为行业敲醒警钟，交易所系统的安全稳定至关重要**

今日，因亚马逊旗下Amazon Web Services (AWS)缓存系统出现问题，导致众多交易所交易出现交易和充提币业务异常。意外发生后，BHEX提币业务也受到了相应影响。但是系统自动在分钟级自动完成了应急预案切换，即刻恢复了正常服务。针对这一事件，BHEX创始人兼CEO巨建华指出，“对于金融系统而言，可用性是非常核心的技术指标。数字货币行业尚处于发展早期，很多交易所的技术架构都比较原始，无法抵御意外情况的发生。在搭建BHEX交易系统之初我们就树立了一个目标：整套系统要做到99.99%的高可用性。BHEX交易所的底层架构充分考虑到了各种极端情况，在持久化、缓存服务、名称服务等基础设施方面，都引入了高可用的支持，以应对类似于今天这样的意外情况。随着行业发展加速，相信会有更多用户会意识到，安全稳定的交易所系统的重要性。”  

# **本次AWS故障主要受影响区域是日本东****京周****边**

据慢雾消息，针对刚刚突发的“AWS故障影响数字货币交易所”事件，本次AWS故障主要受影响区域是日本东京周边，如果是AWS云数据库产品(RDS)故障，在没处理好的情况下，确实有可能出现各种怪异bug，包括价格异动。用户可点击“查看详情”，查看可见AWS全球服务状态链接。  

# **伦敦商事法院在对一起加密货币黑客案件的临时判决中将比特币视为“财产”**

据雅虎财经消息，近期，伦敦商事法院（London’s Commercial Court）在对一起加密货币黑客案件的临时判决中将比特币视为“财产”。Alphabit的首席执行官Liam Robertson声称他上个月被骗了价值100万美元的比特币。伦敦商事法院发布了一项资产保全令，命令交易所CoinBase暂时冻结被盗资金，法院在对这起加密货币黑客案件的临时判决中将比特币视为“财产”。虽然这只是临时的判决，仍需要批准，但是这对加密货币资产“财产”化具有重要意义。  

# **SnapEx将对遭恶意流量攻击事件中受到影响用户全额补偿**

据官方消息，8月22日20:00，SnapEx平台遭到了不明黑客恶意流量饱和攻击，造成平台短暂的无法访问。期间用户体验访问受限，但后台订单数据正常，用户账户里的资金没有受到损失。经紧急修复，该恶意流量在21:15被成功阻挡。目前系统正常运行。对此，SnapEx将启用“SnapEx平台赔付基金”，按照故障期间最大可能的盈利，对本次订单受到影响的用户进行赔付。  

# **莫斯科区块链投票系统在使用前被发现存在严重漏洞**

据Cnbeta消息，法国安全研究人员Pierrick Gaudry发现计划在下个月使用的莫斯科区块链投票系统存在严重漏洞，能根据公钥计算出私钥。该私钥和公钥被用于在选举中的加密用户投票。莫斯科信息技术部门承诺将解决该问题，该部门发言人承认256x3的私钥长度不够安全，他们计划将密钥长度改为1024位。但1024位显然还是太弱，Gaudry认为密钥长度至少应该2048 位。  

# **Cryptopia清算人Grant Thornton：****该交易所未使用个人加密钱包**

据Bitcoinist报道，被盗交易所Cryptopia清算人Grant Thornton周三在其网站上发布声明称，Cryptopia没有使用个人加密钱包，而是将客户资金汇集到混合的加密货币钱包中。因此，清算人在确定客户持有的金额方面面临困难。此外，Grant Thornton表示，其必须手动协调合并的钱包数据与客户数据信息。一位相关专家表示：“我们正在努力协调90多万客户的账户，其中许多客户拥有多种加密资产，还有数百万笔交易和400多种不同的加密资产。这些数据必须逐一协调。据此前消息，在今年1月份遭黑客入侵损失1600万美元后，新西兰加密资产交易所Cryptopia目前已申请美国破产保护。8月21日，Cryptopia在其推特上发布了关于用户资产和平台将在此基础上采取的步骤的声明。声明表示，他们已经成功获取了存储在亚利桑那州数据中心的数据，这使平台能够识别交易所客户持有的加密货币资产，他们已经开始将资金转移到在1月份黑客入侵之后创建的“安全的非黑客环境”钱包中，并称这是为了预防再次遭遇攻击，因为2019年1月黑客攻击的源头目前还没有确定。
