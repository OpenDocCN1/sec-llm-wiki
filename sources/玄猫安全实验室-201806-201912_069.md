**前言**

![](../Images/181348dd129bcdd303db711537d81e74.png)

2019年1月15号，Grin主网正式上线，1月16号凌晨00:01:27主网第一个区块成功被挖出，一瞬间，"Grin"在圈里爆红，各路大V,各大交易所纷纷谈论，以至于从来没听过"Grin"这个词的各路吃瓜群众一刹那被"完全隐私货币","比特币2.0",甚至一张"笑脸"给刷屏。那究竟"Grin"是什么呢？  

  

**何为Grin**

![](../Images/181348dd129bcdd303db711537d81e74.png)

![](../Images/8df66ea50e41bae0e11da3c225fe053b.png)  

  

Grin的Logo:眼睛中"M-W"正是代表着是基于mimblewimble协议的区块链，而mimblewimble则出自哈利波特里的一句咒语，意为无声无息咒。

###   

### 先看看官方怎么说  

官方中的介绍仅仅是简短的几个单词:

  

The private and lightweight mimblewimble blockchain.

  

其中最重要的三个单词:private、lightweight、 mimblewimble。众所周知比特币就是数字加密货币，看到官方的介绍不禁会想：难道比特币不private(隐私)吗，lightweight和mimblewimble又是什么东西呢？简单来说，Grin就说以高匿性(private)，高扩展性(lightweight)为主要特点的区块链，而mimblewimble则是Grin底层的一种零知识证明协议，提供非常好的可扩展性、隐私和可替代性。  

###   

### **有何不同？**

  

private，一个朴实无华的单词诠释了整个"Grin"的核心，但是刚刚也讲到比特币不也是加密的吗，那为什么"Grin"可以如此淡定的以这个单词作为自己的亮点呢?下面我们来看看

**一次比特币交易**

![](../Images/552c159bbac7193ec262198ed3537346.png)

  

**一次Grin交易**

![](../Images/d544d190186bd20afdb98324bf7d0885.png)  

  

比特币和Grin都是基于UTXO体系的货币，但是从比特币交易图中我们可以很清晰的看到币的发送者是谁，接受者又是谁，交易的金额也是清清楚楚的展示在全球网络中，而对比Grin，看到的仅仅是一连串的字符且毫无规律可言。这就是Grin可以如此淡定以private来作为自己亮点之一的原因：没有地址！没有金额！甚至是输入和输出都是分开展示，一点关联都没有，有的只是赤裸裸的一串串看不懂的字符而已。  

###   

### **独特之处**

  

lightweight是Grin的第二个代言词，得益于底层的mimblewimble协议，Grin可以通过交易聚合（transaction aggregation）与核销（cut-through)来大大减少区块链的大小。 区块大小与交易量相适配，历史交易仅保留约100字节的交易核（transaction kernel）, 相比其它区块链节省了大量空间。

  

截至2019.1.18，比特币有超过370M交易量，平均按500字节估算，在区块中存放这些交易数据大约需要185GB。 比特币现在的UTXO数量是60M多一点。如果放在Grin，只有UTXO需要存放，平均按800字节估算，那么在Grin只需要48GB，大约是比特币的26%。 比特币地址现在在用的有500K左右，历史峰值的时候有1M。 Grin鼓励核销和合并UTXO（交易输入个数是按负值计算交易费的），从设计机制上也保证了用户完全没有必要去维护很多个UTXO，那么按照每个地址平均10个UTXO来估算，如果达到比特币的用户规模，Grin顶多只需要5M个UTXO就够了。

  

所以估算结果现在就变成了：4GB，大约是比特币的2.16%。

  

### **为何可以如此魔幻？**

毋庸置疑，mimblewimble协议是该项目背后莫大的功臣，并且Grin在协议之上又填补了许多协议缺失的东西,两两结合，方产生爆炸的化学反应，达到的效果如同该咒语一般魔幻。那么下面我们就来看看mimblewimble协议是如何达到如此神奇的效果的。

  

**mimblewimble协议**

![](../Images/181348dd129bcdd303db711537d81e74.png)

  

首先，一个数字加密货币无论如何最基本的要求必须达到以下两点  

1.  交易金额守恒，即我给了你1块钱，你收到的必须是1块钱，不会凭空乱造多了一些或者少了一些
    
2.  货币归属权明确,即我只能使用属于自己的钱，别人也不可以从我口袋里面拿去几块钱去消费
    
3.  而比特币通过暴露了三个信息以达到以上的两个目的:
    
4.  发送方地址
    
5.  接收方地址
    
6.  交易金额
    

  

通过暴露发送方的地址以验证交易签名，明确了货币归属权，而接收方地址和交易金额则明确指示了货币的交易流向，达到交易金额的守恒。而mimblewimble协议为了达到以上两个目的，又不将任何信息显性的暴露出来，主要利用了以下两点

  

1.  0和验证。 输出总和减去输入总是等于零，证明交易没有凭空创造新的资金，而且不会显示实际金额。
    
2.  拥有私钥即拥有交易输出的所有权。但在MimbleWimble中，证明一个所有者拥有这些私钥并不是通过直接签署交易来实现的。通过特殊的签名方式来避免交易方的地址暴露。
    

  

这种交易方式，我们称之为机密交易

**4\. 交易过程**

  

首先我们来看以下实际使用Grin时是如何转账给别人的，这里使用的方式是文件转账

  

（1）发送者(A)创建一个交易文件

```
grin wallet send -m file -d my\_grin\_transaction.tx 3
```

此时我们创建了一个文件名为my\_grin\_transaction.tx的文件并且标识这次转账的金额为3

  

（2）将这个交易文件发送给接收者(B)，你可以通过邮件，微信，QQ...等等方式进行传输

  

（3）接受者(B)收到这个文件后导入自己的钱包

```
grin wallet receive -i my\_grin\_transaction.tx
```

执行完之后会产生一个my\_grin\_transaction.tx.response的文件并发送回给发送方(A)

  

（4）发送者(A)收到response文件后把这个交易广播到区块链网络中

```
grin wallet finalize -i my\_grin\_transaction.tx.response
```

  

（5）至此，交易完成。看起来Grin的交易非常的麻烦，不像比特币或者其他货币那样非常的方便，这是机密性带来的不便。

其中ro2 是Alice选择的私钥，只有她自己知道，而ro1是我自己选择的私钥，只有我自己才知道。 现在交易开始

  

1.  双方确认交易金额。我在生成.tx文件时，指定我所交易的金额为2，当Alice收到我的文件时，交易双方就确认了这次交易的金额
    
2.  而我在发送发件时,一起附上28 - ro1这个值(为什么是这个值?因为这个值即不会暴露我自己找零回来的交易输出的私钥值，又证明了我具有28这个私钥值(拥有输入币的所属权))
    
3.  Alice收到这些信息后，自己选择一个ro2的值，但是这个值并不等于28 - ro1(为了避免上面我知道Alice输出私钥)，并使用ro1+ro2-28(`excess value`)进行签名，所以实际上得到的交易是这样的(mimblewimble中实际的交易)
    

  

ro1\*G + 1\*H + ro2\*G + 2\*H - 28\*G + 3\*H = (ro1 + ro2 - 28)\*G + 0\*H

只需通过验证excess\_value的签名即可以完成验证交易金额是否守恒以及验证并分配货币归属权的问题

  

如果金额不守恒，那么得到的结果就是(ro1 + ro2 - 28)G + nH ，即不是G上的公钥，验证失败

ro1(找零输出)只有我自己知道，ro2(Alice的输出)只有Alice自己知道，解决了货币归属权的问题

 4.  交易构造完成，广播交易

 5.  因此，MimbleWimble交易包括以下内容：

*   一组输入，参考和花费一组以前的输出。
    
*   一组新的输出包括：
    

*   一个值和一个致盲因子（r它只是一个新的私钥）在曲线上相乘并相加为r×G + v×H.
    
*   范围证明(Range Proofs)显示v是非负的
    

*   明确的交易费用。
    
*   一个签名，通过采取excess value（所有输出加费用之和减去输入）并将其用作私钥来计算
    

  

### **核销(Cut-through)**

  

机密交易揭开了Grin官网中特点之一private的神秘面纱，那么还有一个特点lightweight是如何实现的呢?那就是——核销。这项技术不仅极大的提高了Grin的扩展性，还进一步提高了隐私性。

  

![](../Images/b5733825a6238b8476a19ca13566d018.png)

  

  

将上面的交易进行简化，我们可以得到以下一条式子

  

```


ro1\*G + 1\*H + ro2\*G + 2\*H - 28\*G + 3\*H = (ro1 + ro2 - 28)\*G + 0\*H
```

  

这称之为交易聚合，并且同样适用于区块多个交易之中(因为区块只是一系列聚合的交易输入、交易输出和交易核)，因此在一个区块中假如有三个交易如下

  

```


I1(x1) --- O1
```

  

在一个区块内，可能会存在一个交易的输出是另外一个交易的输入，如上面所示区块中的O2和O3，因此可以将一个区块内的交易进行核销变成如下的形式

  

```

```

  

O2和O3都作为中间的输入而省略掉(核销)，那么一个区块的结构就变成了如下

*   块头。
    
*   核销（cut-through） 后剩余的输入列表。
    
*   核销（cut-through） 后剩余的输出列表。
    
*   每个交易的交易核(transaction kernels)包含：
    

*   从所有commitments总和中获得的公钥r \* G。
    
*   使用excess value生成的签名。
    
*   挖矿费用 (fee)。
    

其中每一笔输入输出的交易结构都被删除了，提高扩展性的同时又增加了私密性。这时我们可以回头看看Grin的交易图，交易的输入和输出是分开展示就是源于此。
