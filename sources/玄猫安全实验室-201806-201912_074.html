关注并标星区块安全

更全面更深刻了解区块链安全

随着区块链技术的快速发展，加密数字货币进入人们的视野，据不完全统计在2018年数字资产钱包用户达到了三千多万，各大厂商为了抢先占领市场，开发出各种各样的数字货币钱包。目前市面上的数字货币钱包仍不时被爆出存在漏洞，本文就对热钱包部分功能做一些安全分析。 


钱包安全有哪些


在开发钱包时，开发人员对于钱包的安全了解不多，有可能无意间写出或配置出安全漏洞，针对APP钱包的一些功能会出现什么样的安全问题，我将从下图中的几个问题点来进行讨论。


1. 创建钱包安全

创建钱包时一般钱包会创建自己的账户，然后用创建的账户的密码来加密私钥等操作。在这个过程中攻击者一般关注的是创建钱包的随机数生成、助记词的保存和私钥存储·。


（1）随机数生成

若知道加密算法和种子，是有可能预测出接下来的随机数序列，因为具有一定的可预测性，在密码学中我们称为伪随机数。相同，在钱包中若使用了伪随机数对攻击者来说还是能够推测出正确的随机数列。在区块链技术中也有被随机数攻击的案列，比如EOS伪随机数漏洞。目前各种代码语言都有了安全的随机数写法，比如Java语言的SecureRandom库生成安全的随机数。


（2） 助记词主要涉及保存安全及长度。创建钱包后会生成助记词，目前开发助记词使用的代码是默认是生成12个助记词，若减少助记词的数量有可能助记词的被攻击者暴力破解。在保存助记词上钱包助记词不能被复制和截屏，目前手机图片一般会被第三方软件同步备份，手机丢失等问题，虚拟货币匿名性强，若丢失含有助记词的图片资产会受到严重的威胁。


（3）私钥存储会被种子信息加密并存储在Keystore文件中，Keystore文件的安全非常重要，攻击者若得到Keystore文件可以通过暴力破解的方式获得你的私钥，这就对种子信息的长度和复杂度有一定的要求了。


2. 本地数据存储安全

数字钱包的助记词、私钥、keystore等敏感信息在终端上目录的访问控制权限、存储形式和加密方式都需要去做一些严格的设计，防止攻击者通过系统或其他第三方软件的安全能够控制被害人的手机，然后可以获取到数字钱包的一些敏感信息文件。比如某安全公司大佬通过root权限，获得助记词的加密数据进行逆向获得助记词。玄猫科技安全研究下载一些开源的钱包进行分析，发现部分钱包敏感信息文件明文存储，即使不是明文存储加密方式也是写在程序中，可破解，对于敏感信息的文件目录也是存储方式也是有一定的规律性。如下图某IOS开源钱包敏感信息的存储路径。


3. 数据备份安全 

Android手机在Android API Level 8及其以上Android系统提供了为应用程序数据的备份和恢复功能，若allowBackup属性值为true则可通过adb backup和adb restore来进行对应用数据的备份和恢复，若敏感数据被备份出来则对钱包用户的资产存在一定的威胁。


4. 业务逻辑安全

业务逻辑安全主要是交易安全和钱包其他功能逻辑权限。交易安全主要在交易签名的逻辑安全，交易过程中交易金额和交易地址能否任意更改和PIN码的安全。其他逻辑安全按照特定的业务防止钱包被数据被越权或篡改。


5. 钱包APP加固

对于Android APP的加固一般是加壳，用源APK与壳程序Apk通过加密算法进行合并形成新的Dex，最后替换壳程序中的Dex得到新的APK，防止安全人员对APK进行反编译。


IOS APP一般使用以下方式进行加固：

（1）字符串混淆

（2）类名、方法名混淆

（3）程序结构混淆加密

（4）反调试、反注入等一些主动保护策略。添加上述这些方式能大大增加IOS APP被人破解的难度。


6. 通信安全

在通讯领域主要防范是通信是否是明文传输和中间人攻击。通信过程中尽量加密传输。正确配置HTTPS协议，防止因配置错误引起漏洞，对于HTTPS协议的中间人攻击漏洞主要由以下几种方式产生：

（1）没有对SSL协议进行校验

（2）没有对域名进行校验

（3）证书颁发机构被攻击，导致私钥泄露等。


在开发的过程中尽量避免

黑盒测试过程中，安全测试人员主要测试输入输出，检查输入什么，输出什么，输出的内容怎样利用。在开发过程中，不要信任客户的输入，一切的输入均不可信，做好过滤。关注好行业安全动态，当数字钱包有新的漏洞爆出来，检查自己所开发的数字钱包是否也存在相同的漏洞，若有及时修复更新。
