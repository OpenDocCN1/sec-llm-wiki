  区块链浏览器

区块链浏览器有很多种，我们这里选择 Blockexplorer 作为示例。

访问 ： https://blockexplorer.com

通过在框中输入交易哈希、公钥地址、区块哈希等便可以搜索到相应信息。


  分析交易信息

访问 ：

https://blockexplorer.com/tx/57309a5cf004fd4746ab508deb0093a5181fb93ead1fbf0b0ebf375b2e817fb6

如图，这个表格告诉我们：


  • Size ： 交易的字节大小。在这里为 3873 个字节。一个区块的容量大概为 1MB，说明能够容纳大概 258 个这样的交易信息。而新区块一般是每 10 分钟产生一次，那么我们就能知道，比特币的协议能处理的交易信息为每秒2-3个。远远小于 Visa 等每秒几千个。

  • Free rate : 用户支付的用于交易的费用，以便广播之，到比特币网络，并被确认。 0.001305959204750839 BTC / kB (1 kB = 1000 bytes) 说明了这个交易花费了 0.00505798 或 $22.2 在当前的区块上。而当前区块的价格是 $4368.

  • Received Time : 区块被链接收时间

  • Mined Time : 区块打包时间

  • Included in block : 所在区块

上表的左边包含输入地址，右边包含目标地址。不知道哪个地址到哪个地址的数量，只知道总数和分布情况。在最右边，有一个标识 S 或 U。S 代表 spent ，而 U 代表 unspent 。Unspnet 说明钱还在地址中，没有花费掉。


最底下我们可以看到不同的区块属性。

  • FEE : 发起交易花费的费用。

  • CONFIRMATIONS : 目前多少个区块被确认。

  • BTC : 在这一笔交易中转移的比特币总数。由于交易的发起者是交换的形式，因此金额通常会稍微大一些。在上面的例子中，以 22.20 美元费用支付了167,312.42 美元的交易，0.0001326859，比 100% 多一点。


分析区块信息

访问 ：

https://blockexplorer.com/block/000000000000000000d5c0a8280170283a776e2029e4c0ef9c3022ba8ee8f5f6

从 Summary 里，我们可以读到以下信息：


  • Number of transactions : 表明此区块中总共的交易数量。此处为 2712 个。

  • Height : 区块序列号

  • Timestamp : 时间戳

  • Block reward : 给矿工的打包奖励

  • Mined by : 打包的矿工 ID 。一些个人、小企业、政府机关，会倾向于保持匿名，所以这个位置有时是空的。

  • Merkle Root : Merkle 根，本区块所有的交易信息的哈希，以及他们的序号。Merkle 根用于验证块的内容，而不是交易本身。

  • Next block 或 Previous block : 下一个区块、上一个区块

  • Difficulty : Difficulty 是找到这个区块的有效哈希值的数学值。为了保持每10分钟的平均速度，在开采新区块时，每一个新的区块都比上一个更难开采。有时候，难度会降低，比如一些矿工离开了矿井网络。

  • Bits : 位是 Difficulty 的十六进制表示。每个块以比特的形式存储其困难的压缩形式，用此算法计算。

  • Size : Size 表示块的总大小。在本例中，我们处理的是 991124，或者小于 1 兆字节 : 0.991MB。这几乎是一个完整的区块。一个区块不必达到100%的开采能力。事实上，空块可以在网络极度不活跃的时候被挖掘出来。无论网络需求如何，矿工们从不停止。

  • Version : Version 是一组数字，矿机软件使用这些数字向网络的其余部分发出信号，表明它打算对网络进行某些更新。

  • Nonce : Nonce 是向交易、数据、Merkle根和其他信息的组合中添加的随机数，以便使 PoW 算法得到与难度匹配的哈希。最终的目标是得到一个比这个难度小的哈希，通常由哈希中的前导零数表示。一旦计算出了这样的散列，nonce就被认为是解决方案，并被用作网络中其他节点(矿工)的确认机制，这些节点(矿工)随后确认此区块确实有效。


分析地址

我们来查看地址：

1ArB3Sn8kNt236fh1CHcvYaEz7RnnV9qq7

我们可以看到这个地址总共转移了 12.4 BTC : 其中接收到 7.37 BTC，通过 28 个交易发送了 5.03 BTC 。剩余的 2.34 BTC 正在写入中。


这个地址的所有者正努力使金额保持四舍五入，目标是0.5比特币。他们频繁地使用相同的更改地址 : 1cbk5dasbc3zzdslc2nbq9kyxjfvq5wgz。此地址也是前面讨论的交易中的两个输出地址之一。因此，我们可以得出这样的结论:这是我们的用户用来继续参与网络的地址，而其他的地址可能是他们的客户或熟人。


如果我们检查一下地址是在哪里得到资金的，我们会注意到它经常从多个输入(multi-inputs)中接收，并且多输出(multi-outputs)，这通常意味着它是一个交换(exchange)或一个滚筒(tumbler)——一个用来“洗(launder)”比特币的服务。它将每个人的 BTC 放入一个公共池中，并将其发送到新的地址，这样在这个多向交易(multi-directional)之后就没有人知道谁是谁了。


如果我们检查上面提到的变更地址，我们会发现在它的 95 个生命周期交易中有 33.44 BTC 的流量，有单个和多个输入和输出。假设这个交易的两端都有多输入和多输出，那么很可能我们要处理的不是一个滚筒(tumbler)，就是一个交换(exchange)，或者是一条正在使用多地址钱包的鲸鱼。

总结

一开始阅读区块链数据可能会让人感到困惑，但是一旦您知道了每一位数据的含义，一切就都就位了。有了这些新知识，再加上本文中介绍的有关比特币匿名性的技术，您可以轻松地通过区块链跟踪用户或地址，并记录他们的所有交易。在一些公开的地址上试试——在论坛或者像Steemit这样的平台上，人们喜欢请求捐赠的地方。
