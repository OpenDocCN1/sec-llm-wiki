# 漏洞预警|大量交易所TradingView组件存在DOM型XSS漏洞

据相关消息通知，Trading View组件存在xss漏洞，玄猫安全实验室紧急对该漏洞进行跟进，针对网络上的大量交易所进行漏洞统计，做出如下安全报告。

  

**TradingView介绍**

![](../Images/dee7b1485b9ea2a22cfb0e45c5860105.png)

TradingView是一个开源免费的K线图分析工具，有完善的API，能把K线展示最流行的JS库，被广泛运用到股票、期货、指数、外汇和比特币交易系统中常用的第三方组件。

**漏洞描述**

本次漏洞出现为DOM型XSS。漏洞在Trading View绘制K线时会加载一个本地可控参数的JS，攻击者根据这个可控参数注入并执行任意JS恶意代码，造成反射型跨站脚本攻击。常见的漏洞利用方式是利用反射型跨站脚本盗取用户登陆信息，借此信息来登陆用户账号，导致用户的财产被盗。

![](../Images/eb7191c3d2e92159da3ef59c3188d01c.png)

  

**漏洞覆盖情况**

近日，随着漏洞细节的披露，玄猫区块链安全实验室对本漏洞进行深入剖析，并监测目前全球范围内使用此组件的交易所安全情况，结果如下图所示：

![](../Images/db5d17daed3c5387881c53630466d05b.png)

  

![](../Images/0a32cbd41d040f9a5a754fd475b79212.png)

  

通过图表可以分析出该次TradingView 0Day 影响范围较广，存在漏洞厂商比例高达33%，其中A类厂商占23.85%，B类厂商占35.76%。建议各大厂商尽快进行漏洞检查并修复。

  

**漏洞修复与建议**

临时修改方案：

（1）检查TradingView 库 bundles 目录 library 开头的 js 文件中是否含有getScript(urlParams.indicatorsFile)如果存在，临时可以把代码改为：getScript("")。

（2）配置HttpOnly提升Cookie安全性，防止登录信息被盗窃。
