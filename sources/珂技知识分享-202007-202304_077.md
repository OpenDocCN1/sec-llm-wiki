mybatis的$符号产生的SQL注入问题都是老生常谈了，一般常见于必须拼接的地方，比如order by like tablename等地方。所以源码解压出来直接全局搜【.xml】文件和【${】内容。  

![](../Images/d0287273ae6a99955bf784e7648e03ef.png)

打开第一个SysUserMapper.xml，找到第一个注入点${params.dataScope}。

![](../Images/ee06f07691eb5b151c45254bf0ed79d2.png)

如何触发这处SQL注入呢？注意它这个传参是带点的，我们不知道带点的该怎么传，但注意标记的params.endTime，待会儿还会看到它。

  

一种方法是根据名字selectUserList直接在前端界面上找对应的前端入口，userlist肯定是用户管理。

![](../Images/70a39ade512228ab665a70f0ef5f2e6b.png)

burp抓包后发现

![](../Images/10784383ea52e2f9711c60be2401fb17.png)  

看到了params.endTime，没看到params.dataScope，不过已经知道怎么构造了，params\[dataScope\]=a就行。

![](../Images/9ca1f33f9fc79309731bf8cc06984916.png)

这是拼接在where后面的，最后也没有换行orderby需要闭合，因此联合报错都可以注。

  

还有的时候前端功能太多了找不到入口，或者前端压根没有入口，我们就要去找controller里这个方法具体如何触发。搜【.java】文件【selectUserList】内容。

![](../Images/dd2ae33711775ed2fca7ce62897e2326.png)

SysUserController.java代码如下

```
    @RequiresPermissions("system:user:list")    @PostMapping("/list")    @ResponseBody    public TableDataInfo list(SysUser user)    {        startPage();        List<SysUser> list = userService.selectUserList(user);        return getDataTable(list);    }
```

就知道是/system/user/list了。

除此之外，export也调用了selectUserList。

*

```
    @Log(title = "用户管理", businessType = BusinessType.EXPORT)    @RequiresPermissions("system:user:export")    @PostMapping("/export")    @ResponseBody    public AjaxResult export(SysUser user)    {        List<SysUser> list = userService.selectUserList(user);        ExcelUtil<SysUser> util = new ExcelUtil<SysUser>(SysUser.class);        return util.exportExcel(list, "用户数据");    }
```

因此两处SQL注入的接口就找到了

POST /system/user/list

params\[dataScope\]=and 1=1

  

POST /system/user/export

params\[dataScope\]=and 1=1

  

其他xml中还有多处${params.dataScope}产生的SQL注入，都在后管，这处功能大概是方便开发提供更多的过滤条件，但造成了SQL注入。
