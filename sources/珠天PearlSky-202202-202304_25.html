先写一个接口，命名为StudyClassInterface.java，里面就一个执行命令的方法

public interface StudyClassInterface {
    public String execCmd(String cmd);
}

再写一个java文件，命名为StudyClass.java

    /**
     * 
     * @param cmd 系统命令
     * @return
     */
    @Override
    public String execCmd(String cmd) {
        Process process = null;
        try {
            process = new ProcessBuilder("cmd.exe","/c",cmd).start();
        } catch (IOException ex) {

        }

            throw new RuntimeException(ex);
        }

为了更好的理解class文件结构，分别定义了各种成员变量以及对应的getter/setter方法还有一个打印变量信息的printField方法和一个执行系统命令的execCmd方法，还有一个主函数，执行系统命令然后返回结果

将StudyClassInterface.java和StudyClass.java放在同一目录，使用编译命令javac -g StudyClass.java编译成class文件，-g指定在生成的class文件中包含所有调试信息（行号、变量、源文件）


命令行

使用javap -c -l -v StudyClass.class命令查看反编译的class文件

  • -c：进行反编译

  • -l：输出行号和本地变量表

  • -v：更详细的信息


反编译显示出来很多内容，大部分都是指令，这里显示的内容和class文件是有点不同的，主要是方便我们查看

前四行：

  1. 指定反编译文件

  2. 上次修改时间和文件大小

  3. MD5校验和

  4. 从哪个文件编译而来

第五行到第九行：

  1. 哪个类，实现的哪个接口

  2. 次版本

  3. 主版本

  4. 访问权限修饰符

  5. 常量池（重要）

常量池完了之后，进入方法区

第一个方法是构造函数，然后构造函数的第二行是描述符，描述了函数参数和返回值，第三行依旧是访问权限修饰符，第四行是代码区，代码区又包指令和行号表，以及本地变量表


其他方法同样是这个结构，有些方法可能会多一个异常表，比如execCmd方法里有个异常表

而且此方法还多了一个栈映射表，是JDK1.6 之后引入的一个JVM特性，主要用于提高 JVM 在加载类时对局部变量表中的类型验证效率

class文件遵循以下结构

ClassFile {
    u4             magic; 
    u2             minor_version;
    u2             major_version;
    u2             constant_pool_count;
    cp_info        constant_pool[constant_pool_count-1];
    u2             access_flags;
    u2             this_class;
    u2             super_class;
    u2             interfaces_count;
    u2             interfaces[interfaces_count];
    u2             fields_count;
    field_info     fields[fields_count];
    u2             methods_count;
    method_info    methods[methods_count];
    u2             attributes_count;
    attribute_info attributes[attributes_count];
}

u1，u2，u4，分别代表无符号1个字节，2个字节和4个字节

magic

第一个属性是magic，魔数

魔数用来标识这是个class文件，拥有固定的值CAFEBABE，占用4个字节

minor_version和major_version

第二个第三个属性分别代表次要版本和主要版本

minor_version和major_version共同决定class文件的版本

major_version的值对应如下java版本

支持那列举个例子来说，比如用java8编译java文件，生成的class文件的major_version是52，但是他向前兼容，所以java8支持major_version45到52的

constant_pool_count

常量池数量，值为下一个属性constant_pool的数量+1

constant_pool[constant_pool_count-1];

constant_pool是一个数组，他是一个cp_info类型，表示引用的各种字符串常量、类和接口名称、字段名称和其他常量

cp_info {
    u1 tag;
    u1 info[];
}

他根据tag的值分为不同的类型


cp_info类型的info属性不固定，根据不同tag分为不同的属性

比如：

CONSTANT_Methodref拥有class_index（方法所属类的索引）和name_and_type_index（方法的名称和描述符）

而CONSTANT_Class_info拥有name_index（类名索引）

而这个索引其实指向的是constant_pool数组的某某项

比如，我们随便挑一个

这个是个CONSTANT_Class_info类型，而他的属性name_index的值为164，也就是常量池数组的164项，constant_pool[163]，因为数组从0开始

他指向的是CONSTANT_Utf8类型，值存在bytes属性中，也就是StudyClassInterface字符串

不同类型对应的cp_info结构体不同，具体参照https://docs.oracle.com/javase/specs/jvms/se15/html/jvms-4.html#jvms-4.4

access_flags

access_flags代表类的访问权限修饰符


这里的值为0x21，也就是ACC_SUPER和ACC_PUBLIC的组合

this_class

他的值指向常量池数组当中的CONSTANT_Class_info类型，代表了这个class文件代表的类或接口


然后去找constant_pool[15]

这里的name_index指向CONSTANT_Utf8类型，

super_class

super_class代表父类，值不可能为0，值为0说明是Object类，值代表常量池数组的索引-1

interfaces_count

代表实现的接口数

interfaces[interfaces_count]

代表实现的接口，占用两个字节，索引指向的是CONSTANT_Class_info类型

fields_count

字段数量

fields[fields_count]

然后又是一个field_info结构体，该这个fields数组仅包括由此类或接口声明的那些字段，它不包括从父类或父类实现的接口继承的字段。

field_info {
    u2             access_flags;
    u2             name_index;
    u2             descriptor_index;
    u2             attributes_count;
    attribute_info attributes[attributes_count];
}

前两个属性说过，直接看第三个属性descriptor_index（描述符索引，描述符代表字段的类型），class文件不同于在java文件中用int,String来代表类型等，编译后的int其实用I来表示，double用D来表示

第四个属性attributes_count代表属性数量，如果为0，就不会有下一个attributes属性

第五个属性attributes是一个attribute_info结构体

attribute_info {
    u2 attribute_name_index;
    u4 attribute_length;
    u1 info[attribute_length];
}

第一个是属性名索引，属性名索引指向CONSTANT_Utf8类型，下表为各种属性名

第二个是属性的长度，第三个不固定，不同属性名此处对应的属性不一样，如同constant_pool数组一样，也就是不同的属性名不同的attribute_info结构体

比如：ConstantValue的attribute_info结构体为

attribute_info {
    u2 attribute_name_index;
    u4 attribute_length;
    u2 constantvalue_index;
}

Code的attribute_info结构体为：

attribute_info {
    u2 attribute_name_index;
    u4 attribute_length;
    u2 max_stack;
    u2 max_locals;
    u4 code_length;
    u1 code[code_length];
    u2 exception_table_length;
    {   u2 start_pc;
        u2 end_pc;
        u2 handler_pc;
        u2 catch_type;
    } exception_table[exception_table_length];
    u2 attributes_count;
    attribute_info attributes[attributes_count];
}

methods_count

方法数量

methods[methods_count]

一个method_info结构体代表一个方法

method_info {
    u2             access_flags;
    u2             name_index;
    u2             descriptor_index;
    u2             attributes_count;
    attribute_info attributes[attributes_count];
}

 跟field_info差不多，随便找一个看看

access_flags如果不是ACC_ABSTRACT和ACC_NATIVE的话，那会在Code类型的attribute_info结构体中的code属性提供java虚拟机指令

下面提供了一份jvm指令集，图中的LineNumberTable行数表

记录了虚拟机指令对应java源文件的第几行，比如start_pc是虚拟机指令的开始地址，他对应java源文件第十二行（line_number）的语句

然后是本地变量表，记述了在方法中的各种变量，比如方法参数，在方法中新创建的变量

本地变量表中存的第一个元素，应该是方法的第一个参数，也就是this指针（static方法除外）

attributes_count;

属性数，代表class文件的属性

attribute_info attributes[attributes_count]

最后这个attribute_info属性的类型是SourceFile

SourceFile_attribute {
    u2 attribute_name_index;
    u4 attribute_length;
    u2 sourcefile_index;
}

光看名字也知道啥意思了吧，sourcefile_index指向CONSTANT_Utf8类型，值是字符串StudyClass.java

    u2 number_of_exceptions;
    u2 exception_index_table[number_of_exceptions];
}

number_of_exceptions表示异常索引表的数量，下面就是异常索引表

可以看到从字节码分析，StringBuffer底层用的是StringBuilder处理，循环跳转用goto语句，本地变量表存储着每一个变量，存储对应变量前置为null（占位符），本地变量表搭配栈完成运算，相比原生的机器指令还是比较容易看的，封装了多层的汇编指令，看懂JVM指令也是ASM操作的重要基础。
