Phar简介

Phar 是英文 PHP Archive 的缩写。根据官方的介绍

What is phar? Phar archives are best characterized as a convenient way to group several files into a single file. As such, a phar archive provides a way to distribute a complete PHP application in a single file and run it from that file without the need to extract it to disk. Additionally, phar archives can be executed by PHP as easily as any other file, both on the commandline and from a web server. Phar is kind of like a thumb drive for PHP applications.

phar文件就是将多个文件组合成一个文件，方便分发与安装，类似java的jar包。

Phar的文件结构

All Phar archives contain three to four sections:

  1. a stub
  2. a manifest describing the contents
  3. the file contents
  4. [optional] a signature for verifying Phar integrity (phar file format only)

一个phar文件至少包含三部分内容：

  • a stub：php通过此标志识别为phar文件，格式为xxx<?php xxx; __HALT_COMPILER();?>，其中xxx的内容不限，但必须以__HALT_COMPILER();?>结尾

  • manifest：这部分放每个被压缩文件的权限属性等信息，用户自定义的Meta-data信息以序列化的形式存储，这个是漏洞利用的核心部分。

    Global Phar manifest format

    Size in bytesDescription
    4 bytesLength of manifest in bytes (1 MB limit)
    4 bytesNumber of files in the Phar
    2 bytesAPI version of the Phar manifest (currently 1.0.0)
    4 bytesGlobal Phar bitmapped flags
    4 bytesLength of Phar alias
    ??Phar alias (length based on previous)
    4 bytesLength of Phar metadata (0 for none)
    ??Serialized Phar Meta-data, stored in serialize() format
    at least 24 * number of entries bytesentries for each file

  • file contents：被压缩的文件的内容

  • signature：签名，可选部分，用于完整性检测

    Signature format

    Length in bytesDescription
    varyingThe actual signature, 20 bytes for an SHA1 signature, 16 bytes for an MD5 signature, 32 bytes for an SHA256 signature, and 64 bytes for an SHA512 signature. The length of an OPENSSL signature depends on the size of the private key.
    4 bytesSignature flags. 0x0001 is used to define an MD5 signature, 0x0002 is used to define an SHA1 signature, 0x0003 is used to define an SHA256 signature, and 0x0004 is used to define an SHA512 signature. The SHA256 and SHA512 signature support is available as of API version 1.1.0. 0x0010 is used to define an OPENSSL signature, what is available as of API version 1.1.1, if OpenSSL is available.
    4 bytesMagic GBMB used to define the presence of a signature.

Phar的创建

需要注意的是，php的配置文件 php.ini 中 phar.readonly 选项默认是不开启的，需要把前面的逗号删除，并把选项的值设置为 off，否则无法生成 phar 文件。

KaliLinux中php配置文件在: /etc/php/8.1/cli/php.ini

其他Linux可以使用命令:sudo find / -name "php.ini"查找

<?php
/*
这一部分是我们要存入manifest的数据
*/
class Test {public $data;}
$test = new Test();
$test -> data = 'Hello World!'; 

/*
这一部分是如何创建phar文件
*/
$phar = new Phar("test.phar"); //后缀名必须为phar，生成的phar包名字为test
$phar->startBuffering(); // 开始缓冲phar写操作，根据官方文档，使用此方法在创建或者修改包含大量文件的phar存档时性能显著提升

$phar->setStub("<?php __HALT_COMPILER(); ?>"); //设置stub
$phar->setMetadata($test); //将自定义的meta-data存入manifest

// public Phar::addFromString(string $localname, string $contents): void
// $content 指定的字符串内容被添加到 phar 档案中。 文件将会以 $localname 为路径保存到档案中
// 因为这部分不是我们所要利用的地方，两个参数内容可以随便写，但是这部分必须要有
$phar->addFromString("test.txt", "test");// 添加要压缩的文件

$phar->stopBuffering(); //结束缓冲phar写操作
?>

执行后当前文件夹会出现一个名为 test.phar 的文件。

使用UTF-8编码形式打开这个文件，会发现我们存入 manifest 的数据变成了

O:4:"Test":1:{s:4:"data";s:12:"Hello World!";}

Phar反序列化漏洞

利用原理

phar文件通过序列化的形式存储用户自定义的Meta-data信息，通过伪协议phar://解析phar文件时，必会将Meta-data信息进行反序列化。

利用条件

  1. 能上传自定义的phar文件
  2. 有文件操作函数
  3. 文件操作函数的参数可控，且其参数没有过滤phar、:、/字符
  4. 有可用的魔术方法作为跳板

如果服务器检测上传的文件类型，我们可以通过设置 phar 文件的 stub 时添加符合要求的文件头绕过检测。由于 php 主要通过__HALT_COMPILER();?>识别 phar文件，前面的内容是可以修改的，添加其他文件头并不影响 php 识别 phar 文件。

$phar -> setStub('GIF89a <?php __HALT_COMPILER();?>'); // 例如GIF89a为gif的文件头

在 Linux 使用 file 命令查看新的 phar 文件

$ file test.phar
test.phar: GIF image data, version 89a, 16188 x 26736

    }
}

首先把不存在函数名存入变量funcs中，下一段

foreach ($this->files as $file) { $this->results[$file->name()][$func] = $file->$func(); }

遍历files变量，使得files变量中的所有 File对象 都调用这个FileList对象不存在函数，调用结果存到resulst变量中。

给出调用后变量funcs和变量results的结构以助于理解

魔术方法__destruct()，这个魔术方法在FileList对象销毁时自动调用。

POP链构造

代码审计的时候，我们已经构造了部分链：

user.__destruct() => file.close() => file_get_contents()

令User对象的成员变量db为File对象，可以触发上面的链，虽然已经后台已经读取到了flag，但是此时触发并没有回显，依然得不到flag。

回顾FileList类，成员变量files存的是变量path指定路径下文件的 File对象。

成员变量funcs存的是FileList对象调用本身不存在的函数的名字。

成员变量results是个二维数组，存的是成员变量files中所有File对象调用了这个不存在函数的结果。

魔术方法__call() 会把FileList对象调用本身不存在的函数的名字存入成员变量funcs，并迭代成员变量files，使用此数组中每一个Files对象调用此FileList类不存在的函数，并把结果存在成员变量results中。

魔术方法__destruct()会打印一段html标签，这段html标签里面含有成员变量funcs和成员变量results所有的内容。

此时令User对象的成员变量db为FileList对象，FileList对象的成员变量files中有flag所在文件的File对象，则在User对象销毁时调用close()方法，这个方法FileList对象没有，去调用FileList对象的魔术方法__call()，此时将会把flag读入成员变量results，最后结果会在FileList对象销毁时打印出来，我们就可以获得flag。

完整的POP链：

user.__destruct() => user.db.close() => filelist.__call() => flagfile.close() => file_get_contents()

构造Phar文件

先来构造exp，从POP链中得知，要令User对象的成员变量db为FileList对象，FileList对象的成员变量files中要有flag所在文件的File对象，因此得到exp

<?php
class User {
    public $db;
}

    public $filename;

class FileList {
    private $files;

执行后当前文件夹会出现一个名为 test.phar 的文件。

获取FLAG

在网盘上传，并使用burp抓包修改 Content-Type 为 image/png ，会发现多了个test.png的文件

点击删除用burp抓包，修改filename的值为 phar://test.png ，即可在回显中发现flag。

需要注意的是，点击下载用burp抓包修改 filename 值访问此phar文件无法获得flag，因为 download.php 的源码中有一句

ini_set("open_basedir", getcwd() . ":/etc:/tmp");

限定了能访问的目录，flag.txt文件在根目录下面，无法读取。

而 删除 操作向 delete.php 页面post发送filename，delete.php 源码中并没有限定访问的目录，所以可以读取flag.txt文件并获得flag。
