代码审计

pkshow类

class pkshow 
{  
    function echo_name()     
    {          
        return "very safe^.^";      
    }  
} 

这个类非常的简单，只有一个 echo_name() 函数，这个函数返回一个字符串 。

acp类

class acp 
{   
    protected $cinder;  
    public $neutron;
    public $nova;
    function __construct() 
    {      
        $this->cinder = new pkshow;
    }  
    function __toString()      
    {          
        if (isset($this->cinder))  
            return $this->cinder->echo_name();      
    }  
} 

这个类有三个变量，分别是cinder、neutron、nova，以及两个魔法函数__construct()、__toString()。

acp类实例化的时候，会自动调用魔法函数__construct()，即实例化时会给变量cinder赋值，其值为pkshow对象。

acp对象被强制转换为字符串时，会自动调用魔法函数__toString()，这个函数首先判断变量cinder是否设置，如果设置并且非NULL则调用变量cinder的echo_name()函数。（acp对象实例化时已经给变量cinder赋了个pkshow对象。pkshow对象有echo_name()函数。）

ace类

class ace
{    
    public $filename;     
    public $openstack;
    public $docker; 
    function echo_name()
    {   
        $this->openstack = unserialize($this->docker);
        $this->openstack->neutron = $heat;
        if($this->openstack->neutron === $this->openstack->nova)
        {
        $file = "./{$this->filename}";
            if (file_get_contents($file))         
            {              
                return file_get_contents($file); 
            }  
            else 
            { 
                return "keystone lost~"; 
            }    
        }
    }  
} 

这个类有三个变量，分别是filename、openstack、docker，以及函数echo_name()。

在函数echo_name()中，通过

$this->openstack = unserialize($this->docker);

可以猜测变量docker的值是一个序列化后的值，变量openstack的值是变量docker反序列的结果。下一句

$this->openstack->neutron = $heat;

变量heat的值是未知的，它将赋给变量openstack的成员变量neutron。下一段

if($this->openstack->neutron === $this->openstack->nova)
{
    $file = "./{$this->filename}";
    if (file_get_contents($file))
    {              
      return file_get_contents($file); 
    }
    else
    {
        return "keystone lost~";
    }
}

将会判断openstack的成员变量neutron和成员变量nova的值，如果其值和类型都相等，则会使用变量filename拼接成一个路径相关字符串，调用file_get_contents()函数获取名为filename变量指定的文件的内容。

至此，代码审计完成得差不多了。

POP链的构造

从代码的最前面发现

include 'flag.php';

flag 应该就是在flag.php文件里面，只要获取到flag.php的内容，我们就可以获得flag。

通过代码审计我们发现 ace类的函数echo_name()调用了file_get_contents()函数，只要ace类的成员变量filename为flag.php就可以得到flag！

想要代码运行到

return file_get_contents($file);

就必须要绕过这个判断语句

if($this->openstack->neutron === $this->openstack->nova)

绕过这个判断语句有两种方式，第一种就是两边都为NULL，在php中null === null返回的结果是true，第二种就是令的两边的值是相等的，但是我们不知道变量heat的值，想要判断的结果相等，只需要openstack的成员变量neutron引用成员变量nova就好了。

继续往上分析，进入这一段代码的前提是调用了ace对象的echo_name()函数。给出的代码中调用了echo_name()函数的就是acp类的魔法函数__toString()，我们只需要使acp对象的cinder变量的值为ace的对象即可。

现在我们可以得出POP链为

acp -> __toString() ==> ace -> echo_name() ==> file_get_contents($file)

payload构造

第一种绕过方式

"null === null"

想要令的openstack的成员变量neutron和nova的值都为NULL，只需要令openstack为NULL即可。我们来验证一下

<?php
$openstack = null;
if($openstack->neutron === $openstack->nova)
{
 echo "Yes";
}
else{
    echo "No";
}
?>

运行以上代码，其输出的结果是Yes。根据

$this->openstack = unserialize($this->docker);

unserialize()函数接受的是一个字符串，docker变量由于没有初始化，传入unserialize()函数得到的返回结果是布尔类型false，所以$openstack->neutron与$openstack->nova的结果都是NULL。验证代码

<?php
$docker;
$openstack = unserialize($docker);
var_dump($openstack); // 结果为bool(false)
var_dump($openstack->neutron);// 结果为NULL
var_dump($openstack->nova);// 结果为NULL
?>

第二种绕过方式

变量neutron引用变量nova

如果判断那个语句修改成

if(($this->openstack->neutron === $this->openstack->nova) and ($this->openstack->neutron != null) and ($this->openstack->nova != null))

那第一种方式就无法绕过了，我们可以使用第二种绕过方式。变量heat的值是未知的，想要判断时的结果为true，只需要使得变量neutron引用变量nova，这两个变量都指向同一个值，判断时自然会相等。

    public $nova;

    function echo_name()

        $this->openstack = unserialize($this->docker);
