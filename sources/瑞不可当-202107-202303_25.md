# CVE-2021-4034 PolicyKit本地权限提升漏洞

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzkzODI1NjMyNQ==&mid=2247483763&idx=2&sn=a3bb666fe6594d853207aec26cb371fc&chksm=c283b3d9f5f43acfb01ecc3ef39ebef3ae3ff6eb789195f8667c2e619a9952ac2303198257af&scene=126&sessionid=1681665292#rd](http://mp.weixin.qq.com/s?__biz=MzkzODI1NjMyNQ==&mid=2247483763&idx=2&sn=a3bb666fe6594d853207aec26cb371fc&chksm=c283b3d9f5f43acfb01ecc3ef39ebef3ae3ff6eb789195f8667c2e619a9952ac2303198257af&scene=126&sessionid=1681665292#rd)

**【漏洞描述】**

        pkexec 应用程序是一个 setuid 工具，旨在允许非特权用户根据预定义的策略以特权用户身份运行命令，是sudo的替代方案。 1月25日，研究人员公开披露了在 polkit 的 pkexec 中发现的一个权限提升漏洞（CVE-2021-4034 ，也称PwnKit)，它存在于所有主流的 Linux 发行版的默认配置中。

      polkit 的 pkexec 实用程序中存在一个本地权限提升漏洞。当前版本的 pkexec 无法正确处理调用参数计数，并最终尝试将环境变量作为命令执行。攻击者可以通过控制环境变量来利用这一点，从而诱导 pkexec 执行任意代码。利用成功后，会导致本地特权升级，非特权用户获得管理员权限。

  

**【漏洞评级】**  

CVE-2021-4034 PolicyKit本地权限提升漏洞    高危（7.8）

  

**【影响版本】**

**【漏洞成因】**

漏洞出在pkexec命令上。pkexec 的 main() 函数的开头处理命令行参数（第 534-568 行），如果传入的路径不是绝对路径，那么就会在 PATH 环境变量的目录中搜索要执行的程序。

![](../Images/ca16cde50bf7f42dc35b87b284f07cf6.png)

如果命令行参数 argc 的数量为 0——这意味着如果我们传递给 execve() 的参数列表 argv 为空，即 {NULL}——那么 argv\[0\] 为 NULL。这是参数列表的终止符。所以：

*    在第 534 行，整数 n 永久设置为 1；
    
*    在第 610 行，从 argv\[1\] 越界读取指针路径；
    
*    在第 639 行，指针 s 被越界写入 argv\[1\]。
    

调用新的execve()函数后，新程序的堆栈如下所示：

![](../Images/3b221bfa1b9f2d8494effb020fbd0582.png)

因为 argv 和 envp 指针在内存中是连续的，如果 argc 为 0，那么越界 argv\[1\] 实际上是 envp\[0\]，指向我们的第一个环境变量“value”的指针。

1.   在第610行，将要执行的程序的路径从argv\[1\]（即envp\[0\]）中越界读取，并指向“value”；
    
2.   在第 632 行，这个路径“value”被传递给 g\_find\_program\_in\_path()（因为“value”不是以斜线开头，在第 629 行）；
    
3.   然后，g\_find\_program\_in\_path() 在我们的 PATH 环境变量的目录中搜索一个名为“value”的可执行文件；
    
4.   如果找到这样的可执行文件，则将其完整路径返回给 pkexec 的 main() 函数（在第 632 行）；
    
5.   最后，在第 639 行，这个完整路径被越界写入 argv\[1\]（即 envp\[0\]），从而覆盖了我们的第一个环境变量。
    

由此，内存安全问题变成了一个逻辑问题。这种越界写入允许我们将“不安全”的环境变量重新引入 pkexec 的环境。这些“不安全”变量通常在调用 main() 函数之前从 SUID 程序的环境中删除。pkexec 具有 suid，在执行入口程序之前不安全的环境变量都会被过滤一遍；由于这个漏洞的存在，这个过滤措施可以直接绕过。  

**【修复建议】**  

参考漏洞影响范围，及时升级到安全版本。
