0x01 基本概念

【概念介绍】

安全应急响应中心（SRC, Security Response Center），是企业用于对外接收来自用户发现并报告的产品缺陷的站点。一般起着对外发布企业突发安全事件处理动态，作为企业与热心用户以及安全研究人员沟通反馈的平台以及对外发布企业信息安全团队研究成果的重要作用。

【实现方式】

目前安全应急响应中心的实现方式有以下两种：
漏洞报告平台：漏洞报告平台是指由独立的第三方公司或机构成立综合性的“安全应急响应中心”。国内补天平台、漏洞盒子平台，以及据此衍生的Sobug众测平台等均属于该模式。外部报告者注册对应漏洞报告平台选择对应的厂商进行报送，接着该第三方机构会发送邮件提示相关厂商确认处理。这种方法的缺陷十分明显。厂商的历史漏洞信息完全暴露给第三方机构，报告中涉及的企业内部大量敏感信息因此外泄丧失私密性。
SRC模式：xSRC模式是指：企业自己分配工程师开发属于自身的安全应急响应中心，制定自己的漏洞收集和披露计划。目前包括Google、Microsoft以及腾讯、阿里巴巴、百度等，均成立了自己的安全应急响应中心，对外收集并处理安全研究员报送的漏洞报告。使用这种模式，企业在漏洞的收集和披露过程中完全掌控了主动性，拥有良好的私密性和可定制性。
以上就是SRC的基本概念，那么如何进行漏洞的挖掘呢？以下内容对漏洞挖掘的流程进行了简单的介绍。

0x03 了解业务

在一次渗透的过程当中，最为重要的就是进行信息收集，这是一切后续的基础。然而大型企业的各类信息繁杂，是一个庞大的信息体。想要进行渗透挖掘漏洞，首先要对公司的整个架构有基础的了解。
以公司的业务为主线，了解目标下的各类子公司、分公司的各类业务甚至于第三方厂商的信息，了解业务内容、业务资产以及业务应用；以渗透测试的思维收集目标信息，主要包括但不局限于域名、ip范围、开源社区关于公司的代码、员工信息等。
要想对目标公司有较为透彻的了解以及认识，需要比较长的时间，因此只要选择一两个目标公司进行漏洞的挖掘。与此同时，因为对核心业务的技术不了解，很难直接挖掘存在哪些漏洞，但是可以利用逻辑问题挖掘核心业务的漏洞；边缘的业务因为大家对其重视程度不及核心业务，往往存在较多的问题安全问题。
其中，业务安全最容易出现问题的环节：
非普通用户拥有的权限：商家、合作方。我们可以尝试获取商家、合作方以及签约作者等人的账户，以他们的权限进行渗透测试。
新上线业务：新上线的业务往往会被认为存在漏洞的概率较低，然而事实恰恰相反。新上线的业务可能存在测试时间较短、未经过众测等原因，大大增加了漏洞存在的可能性。

0x03 信息收集

信息收集主要包括以下六方面：

  • User List: username、password、mobile、mail、

  • Domain List：二级、三级、备案、whois、第三方业务资产

  • IP List：外网ip、内网ip、C段ip、办公网ip、端口

  • Web List：中间件、CMS、数据库、基础服务

  • Mail List：user mail、业务mail、公用mail

  • work os：oa、jenkins、wiki、vpn、sso、后台等

以下为部分信息收集的方法介绍：

【子域名收集】

因为厂商会在规则中划定测试的业务以及域名，因此可以直接进行子域名的收集。

  • 基于SSL证书查询：cengsys.io、crt.sh

  • 第三方网站接口查询:riskiq、shodan、findsubdomains、censys.io、dnsdb.io

  • Github、DNS解析记录、子域名枚举等

  • 爆破：sublist3r、subdomainsBurte、subfinder、layer子域名挖掘机等

  • 在线查询站点：云系资产、Virustotal、Dnsdumpster、Threatcrowd

【路径扫描】

目录爆破+路径扫描：msf中的brute_dirs、dir_listing、dir_scanner

dirsearch、burpsuite、dirb

【IP段收集】

通过AS号或者IP所属网络名称进行反查，获取厂商拥有的IP段。

【端口扫描】

python调用masscan全端口扫描+nmap端口服务识别

0x04 漏洞挖掘

常见的漏洞有以下6种：

【注入漏洞】SQL注入、命令注入、表达式/代码注入、SSRF网络注入

【信息泄露】配置文件、测试文件、备份文件、接口暴露、心脏滴血

【逻辑漏洞】穷举遍历、水平越权、垂直越权、流程乱序、数据篡改、未授权访问

【二进制漏洞】缓冲区溢出、堆/栈溢出、内存泄漏

【前端漏洞】XSS、CSRF、ClickJacking

【其他】拒绝服务、暴力破解

提升危害

挖到漏洞后不建议直接提交，而是思考如何才能扩大战果，比如挖到XSS后，思考能不能拿到cookie？如果不能退一步可不可以找一个csrf将漏洞变成XSRF以此形成蠕虫？在测试机器通过弱口令进去后能不能Getshell，拿到shell后进行审计又是十几个高危。在对只有登录框界面进行测试时一定要多注意子目录以及接口。IP打开后403、404不要忽略，先扫目录，扫完了在说，往往高危会存在与许多低微的并发利用。

0x05 漏洞报告

漏洞挖掘完成后还需向SRC平台提交漏洞报告，具体格式如下：

【漏洞标题】漏洞影响域名和范围、涉及参数、漏洞类型等

【漏洞描述】包含漏洞涉及的 url、参数、应用版本等

【复现过程】按照逻辑对漏洞复现顺序进行详细描述，若使用工具复现漏洞，应提供工具名称

【修复建议】建议提供可执行的修复建议，可以提供代码级的修复建议，也可以提供防护策略

0x06 Some tips

最后是一些简单小技巧，能够提高挖洞效率的同时也能够提高挖洞的几率。

【巧用搜索引擎】关注页面内容、关注目录、敏感关键字搜索

【关注企业动态】微信公众号、小程序、app、应用程序

【其他】github搜索、漏洞回挖、假性社工
