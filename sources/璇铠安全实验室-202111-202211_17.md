Gerapy是一款基于Scrapy、Scrapyd、Django和Vue.js的分布式爬虫管理框架。最近在准备毕设的一些材料，涉及到爬虫，在GitHub上面找相关爬虫的开源项目，恰巧看到了Gerapy，就下过来准备用用看，看看是不是有能够学习的一些地方。结果在几个公众号的推文里看到了有关Gerapy远程命令执行的漏洞，刚好是要搭建环境的，顺手就来分析复现一下子。

**环境搭建****FOLLOW****CLOSELY**![](../Images/7a0033f9aa55b9bb3e346a9c83f41c77.png)

项目地址，选择合适的版本进行下载，下载之后解压，命令行进入到文件路径，运行以下命令进行安装，说是安装，其实是对所需要的一些第三方库等的下载

python setup.py install

  

![](../Images/5370361ad99907848186a15781f07e1c.png)

在完成之后进入到gerapy的文件路径下

gerapy init  gerapy进行初始化

gerapy migrate  数据库初始化

再完成所有的初始化之后，由于此时数据库基本上为空，缺少后台超管的账号，需要用命令行进行创建

gerapy createsuperuser

username email（可不填） password

再完成所有的操作之后就可以启动gerapy了，由于未进行主机等配置，所以显示错误为正常情况，其他的相关设置和使用等自行百度

gerapy runserver 127.0.0.1:4444   #（可自行修改端口）

![](../Images/678d6818bfba479752ed06795072eade.png)

**漏洞分析****FOLLOW****CLOSELY**![](../Images/7a0033f9aa55b9bb3e346a9c83f41c77.png)

根据360漏洞云文章中提到的该漏洞源于程序没有正确清理通过project\_clone端点传递给Popen的输入，全局去搜索整个项目的源代码进行漏洞点的定位，定位到\`gerapy/server/core/views.py\`文件中的project\_clone方法

![](../Images/444a0211b99079ebe1d8fed94982d61a.png)

下面来进行一下该函数的分析

首先在调用该函数的时候，会先对请求方法进行判断，如果是POST方法就会接着往下，调用json库的loads，这里稍微提一下这个方法，最近也是在做一个文档自动输出平台，就用到了这个方法

json.loads(s, \*, encoding=None, cls=None, object\_hook=None, parse\_float=None, parse\_int=None, parse\_constant=None, object\_pairs\_hook=None, \*\*kw)

s: 将s（包含JSON文档的str，bytes或bytearray实例）反序列化为Python对象。

encoding: 指定一个编码的格式

也就是说会对请求体中的json数据进行反序列化为python的对象，然后赋值给这里的data；接着获取反序列化处理之后键名为address的value值，根据后面的判断应该获取的是请求的URL地址，不是http的直接抛出异常；之后会对address进行校验不以.git结束就会进行拼接

之后对address直接拼接入了cmd包括target，并且直接俄将cmd传入了popen，可以直接进行系统命令的执行，只要address或者target一个可控，就能够执行我们的恶意命令，这里address完全可控

接着回溯调用了project\_clone方法的路由

\`server/core/urls.py#26\`

![](../Images/386c387ec96e3b9e9fb36e4f6288a6b1.png)

在project\_clone方法的前面还有如下两行代码，重点是后面的，会对请求头中的Authorization进行校验，也就是说必须是授权的用户，且请求带有唯一凭证才可以

@api\_view(\['POST'\])

@permission\_classes(\[IsAuthenticated\])
