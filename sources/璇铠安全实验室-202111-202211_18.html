apache shenyu网关前身Soul 网关经过 Apache Incubator 投票，正式步入 Apache 基金会孵化器。随后，Soul 网关项目将改名为 ShenYu。apache shenyu是一款高性能,跨语言,多协议的API网关。在初步了解了这个开源项目之后，只能说项目负责人yyds。

项目解析
FOLLOW
CLOSELY

前几天去做应急了，上去看了那边的设备，看那个请求包的数据，看上去是再正常不过的一个GET请求，但是很奇怪的是响应包居然返回了后台敏感数据，开始挺不理解的，但还是先按着应急流程走吧

对攻击源IP进行了溯源，微步情报上显示是恶意IP，并且显示有100个左右的攻击画像，攻击了挺多的目标的，确认是攻击者无疑了，就是没有别的多余的信息，没办法进行很好的溯源。

接着去百度搜索了一下相关的攻击请求路径，发现是有关于apache shenyu Admin身份认证绕过的漏洞， 起因是JWT的错误使用允许攻击者绕过身份验证，攻击者可通过该漏洞直接进入系统后台

知道了是什么漏洞之后就是去找了一下poc，尝试去复现一下，但是发现了一个问题，公开的poc全都是直接访问`/dashboardUser`路由就能够获得泄露的信息，但是并没有打成功，提示如下

{"code":600,"message":"token is error"}

回过头看捕获的数据包，结合漏洞爆出的JWT问题，猜测应该是header头中`X-Access-Token`字段值的问题。

最后也是协助一起进行了官方发布新版本的迭代，此次应急也算是结束了，腾出点时间来看看漏洞成因。

漏洞分析
FOLLOW
CLOSELY

访问`/dashboardUser`，根据IDEA运行日志报错来跟代码

`org/apache/shenyu/admin/shiro/bean/StatelessAuthFilter.java`

这里的`HEAD_TOKEN=X-Access-Token`,调用了`HttpServletRequest`接口中的`getHeader`方法，来获取http请求中传入的`X-Access-Token`字段值，并且判断为空就会在日志中抛出错误；后面会实例化StatelessToken类，并且会调用ServletRequest封装请求信息和ServletResponse封装响应信息来获取请求响应信息；后面会获取请求头中的Token信息来进行登录校验，错误就会抛出响应的异常信息

`org/apache/shenyu/admin/shiro/bean/StatelessToken.java`，该类中的方法就是返回获取到的Token值

分析完这两个类还是没有找到漏洞点，直接全局来搜索`dashboardUser`，定位到了下面的类文件

`org/apache/shenyu/admin/model/vo/LoginDashboardUserVO.java`

这里的调式点有一个setToken方法，应该是初始化Token值，结合调用的`JwtUtils`类中的`generateToken`方法，传入方法的变量值是获取到的登录用户名，跟进

public static String generateToken(final String userName) {

        try {

            return JWT.create().withClaim("userName", userName).withExpiresAt(new Date()).sign(generateAlgorithm());

        } catch (IllegalArgumentException | JWTCreationException e) {

            log.error("JWTToken generate fail ", e);

        }

        return StringUtils.EMPTY_STRING;

    }

上面这段代码会生成JWT，可以看到生成规则是username+new Date(),也就是登录用户名加上当前的时间戳，是生成对应的JWT的加密内容，要想自己来生成需要知道key值，这里经过搜索发现key值是写死的常量值

有了以上的信息，也就能够自行伪造JWT来获取Token值，那么Token验证那里就能够通过了

从`DashboardUserController`类的测试文件中可以看到再通过Token校验之后再访问该路径，就能够获取到泄露的账号信息了
