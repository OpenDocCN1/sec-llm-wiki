01
数据库介绍

现如今，⼤部分数据库可以分为关系型数据库和⾮关系型数据库（也被叫做NoSQL数据库）两类，关系型数据库的代表包括Mysql，Oracle，MSSQL，Sqlite等，⾮关系型数据库包括Redis（后续课程），MongoDB等

对于⼤部分的WEB⽹站，后端都会存在有⼀个数据库，在这个数据库中通常存放的是⽤户的个⼈信息数据，如账号，密码等，及⼀些⽹站资料的数据，如⽹站图⽚，⽹站配置信息等。

WEB⽹站可以通过开发语⾔的⼀些连接函数与数据库进⾏连接，并可以对数据库的数据进⾏增，删，改，查等操作，我们也可以⼿动对数据库进⾏⼀些操作。

这⾥的数据库操作的程序语句就叫SQL语句。

02
SQL注⼊原理

结构化查询语⾔(Structured Query Language)简称SQL，结构化查询语⾔是⼀种数据库查询和程序设计语⾔，⽤于存取数据以及查询、更新和管理关系数据库系统；

sql 语句就是对数据库进⾏操作的⼀种语⾔。


⼀个常⻅的进⾏数据库查询的操作语句

select * from user_table where username= "⽤户输⼊的账号" and password = "⽤户
输⼊的密码";

上述语句通常会⽤在登录的时候，语句可以根据⽤户输⼊的账号和密码对数据库进⾏查询，根据返回的  结果来判断该账号和密码是否存在于数据库中可以看出在这个语句中，⽤户的输⼊会被直接组合到原有的数据库操作语句中，⽐如⽤户输⼊的账号密码是admin/admin，那么这个语句就是

select * from user_table where username = "admin" and password = "admin";

正常情况下，这个操作不会出现特殊的问题，但是有攻击者就想到了能否在将sql本身的⼀些语句当作⽤户的账号和密码拼接到语句中呢，⽐如在密码处输⼊123" or 1=1 -- ，那么语句会变成

select * from user_table where username = "admin" and password = "123" or
1=1 -- ";

我们可以发现，就算输⼊了很奇怪的密码，但是整个语句似乎还是有逻辑的，我们来着重分析⼀下输⼊的密码组合到语句⾥变成了什么

username = "admin" and password = "123" or 1=1 -- ";

⾸先是123"，这个输⼊会导致password原语句⾃带的第⼀个双引号被我⼿动输⼊的双引号闭合

然后是or、1=1，这个就很简单是⼀个逻辑，不管你输⼊的是123还是321还是错误的或者正确的密码，因为后⾯1=1恒成⽴，再加上or条件，所以整个式⼦都是恒为真，也就是说不管他真正的密码是多么复杂，我都可以通过这个来绕过

最后是--，在SQL语句中，--后⾯相当于注释符，也就是后⾯的东⻄都变成了注释，也就是⽆效了，那     么就完美的将⾃带的最后⼀个引号给注释掉了，使得整个语句不会报错，那么⼀次简单的SQL注⼊就完成了，它的功能就是绕过登录，实现万能密码SQL注⼊是发⽣于应⽤程序层与数据库层的安全漏洞。简⽽⾔之，是在输⼊的字符串之中注⼊SQL指     令，在设计不良的程序当中忽略了字符检查，那么这些注⼊进去的恶意指令就会被数据库服务器误认为是正常的SQL指令⽽运⾏，因此遭到破坏或是⼊侵。

1、联合查询注⼊

最快捷的⽅法，通过联合查询获取到所有想要的数据，前提是请求返回后能输出SQL执⾏后查询到的内容联合查询是将两个查询的结果合并输出，如下图

所以使⽤联合查询注⼊的前提是需要知道⽬标站点返回的SQL查询结果的位置和查询的字段数⼀般我们使⽤order by *来判断⽬标的查询字段数，我们让*从1开始递增，直到出现报错，就可以判断出⽬标的查询字段数，如下图

然后我们就可以根据⽬标输出的字段位置进⾏联合查询注⼊获取⽬标数据库信息

http://127.0.0.1/view?id=1 UNION SELECT SCHEMA_NAME FROM INFORMATION_SCHEMA.SCHEMATA



2、堆叠注⼊

即能够执⾏多条查询语句，⾮常危险，因为这意味着能够对数据库直接做更新操作。

堆叠注⼊的局限性在于并不是每⼀个环境下都可以执⾏，可能受到API或者数据库引擎不⽀持的限制。

http://127.0.0.1/view?id=1;update t1 set content = 'aaaaaaaaa'

3、报错注⼊

如果⻚⾯能够输出SQL报错信息，则可以从报错信息中获得想要的信息。报错注⼊常⽤函数

1. extravalue

extractvalue(xmlfrag, xpath_expr) xml_frag：XML标记⽚段
xpath_expr：XPath表达式

它返回CDATA第⼀个⽂本节点的text（），该节点是XPath表达式匹配的元素的⼦元素。第⼀个参数可以传⼊⽬标xml⽂档，第⼆个参数是⽤Xpath路径法表示的查找路径

例如：

http://localhost/sqli/Less-1/?id=1%27and(select%20extractvalue(1,concat(%27~%27，(select%20database()))))--+

2. updatexml

updatexml(xml_target, xpath_expr, new_xml) xml_target：需要操作的xml⽚段
xpath_expr：需要更新的xml路径(Xpath格式)
new_xml：更新后的内容


此函数⽤来更新选定XML⽚段的内容，将XML标记的给定⽚段的单个部分替换为xml_target 新的XML⽚段new_xml ，然后返回更改的XML。

xml_target替换的部分与xpath_expr ⽤户提供的XPath表达式匹配。

如果未xpath_expr找到表达式匹配，或者找到多个匹配项，则该函数返回原始xml_targetXML⽚段。和上⾯的extravalut⼀样，我们利⽤中间这个参数的xpath报错

例如：

http://localhost/sqli/Less-1/? id=1%27and(select%20updatexml(1,concat(%27~%27,(select%20database())),1))-
-+

3. floor 报错语句

4.时间盲注

⻚⾯不会返回错误信息，不会输出UNION注⼊所查出来的泄露的信息。这时就需要采⽤基于时间  的注⼊了，即判断请求响应的时间，但该类型注⼊获取信息的速度⾮常慢。

时间盲注的⽅法除了sleep外，还有

1. 笛卡尔积

2. Benchmark函数

3. get_lock对会话加锁

总体原理都是为了产⽣延时，因此可能还有许多其他⽅法可以使⽤通常时间盲注我们使⽤sqlmap或者⾃⼰写python脚本进⾏攻击

http://localhost/sqli/Less-8/?id=1%27and%20if(ascii(substr(database(),1,1))=115,sleep(5),1)--+

5、布尔盲注

通过判断⻚⾯返回情况获得想要的信息。如果⻚⾯在返回值为真和返回值为假时返回⻚⾯的内容不相同，那么我们就可以尝试使⽤布尔盲注

http://localhost/sqli/Less-8/?id=1%27and%20database()=%27security%27--+

6、宽字节注⼊

宽字节注⼊原理

GBK编码，字符占⽤两字节

ASCII编码，字符占⽤⼀字节

PHP中存在转义函数，会向⼀些符号前添加转义符号“\”，但是执⾏添加的“\”是ASCII编码，MYSQL默认字符集是GBK等宽字节字符集。

⾸先，我们对注⼊点需要有⼀定的敏感性，尤其是url中带有id，uid之类的参数时，就可以进⾏尝试

1. 可以尝试在查询参数后⾯加单引号，如果会报错，那么很有可能存在sql注⼊

3. 如果是字符型参数，可以⽤and '1'='1和and '1'='2来做判断

SQL注⼊的⼀些BYPASS

关键词过滤

对关键词，如select，union等的过滤，可以尝试⽤⼤⼩写或双写进⾏绕过，也可以使⽤内联注释，如UN/**/ION这种⽅式，内联注释适⽤于MYSQL数据库

空格过滤

对于空格的过滤，可以⽤/**/注释，或者⼀些特殊编码字符，如%0a,%20,%09,%00等也可以尝试⽤括号进⾏绕过，如下⾯的语句

select(user())from dual where(1=1)and(2=2)

单引号过滤

如果⽬标使⽤了addslash等函数进⾏转义，可以⽤宽字节注⼊进⾏尝试。前提要求数据库使⽤GBK编码

⼤⼩于号过滤

如果在使⽤时间等盲注时，过滤了⼤⼩于号，可以⽤函数来绕过

● greatest(n1, n2, n3…):返回n中的最⼤值
● least(n1,n2,n3…):返回n中的最⼩值
● strcmp(str1,str2):若所有的字符串均相同，则返回STRCMP()，若根据当前分类次序，第⼀个参数⼩于第⼆个，则返回 -1，其它情况返回 1
● in关键字
● between a and b:范围在a-b之间

特定函数过滤

可能⽬标站点会过滤⼀些危险函数，如sleep等，我们可以尝试⽤⼀些同效果函数进⾏替换

1. sleep()函数可以⽤benchmark()函数替换，都能达到延时效果
2. ascii()–>hex()、bin()，替代之后再使⽤对应的进制转string即可
3. group_concat()–>concat_ws()
4. substr(),substring(),mid()可以相互取代, 取⼦串的函数还有left(),right()
5. version() --> @@version、datadir–>@@datadir
6. ord()–>ascii():这两个函数在处理英⽂时效果⼀样，但是处理中⽂等时不⼀致

UDF提权

UDF提权的⼤致思路如下

1. 将含有cmd函数的DLL⽂件写⼊指定⽂件夹下
2. 基于第⼀步的DLL⽂件创建⾃定义函数
3. 基于第⼆步得到的⾃定义函数调⽤相应的函数，传⼊参数，执⾏系统命令（权限为system）利⽤的条件
● Mysql版本⼤于5.1：DLL⽂件必须放置在MYSQL安装⽬录下的lib\plugin⽬录下
● Mysql版本⼤于5.0⼩于5.1：在Windows2003下DLL⽂件放置于C:\windows\system32；在windows2000下DLL⽂件放置于C:\winnt\system32
● Mysql版本⼩于5.0：DLL⽂件可任意放置在MYSQL数据库⽤户具有创建和删除函数的权限，DLL⽂件有写⼊指定⽬录的权限

利⽤的原理：MOF⽂件每隔5秒就会执⾏，且执⾏命令时的权限为系统权限，如果通过MYSQL将MOF

⽂件替换，那么系统就会每隔5秒执⾏MOF⽂件，MOF⽂件中存在⼀段VBS脚本，因此控制VBS脚本内容变成让系统执⾏命令，进⽽提权

CLOSELY
01
预编译

预编译是防御SQL注⼊的最好⽅法，预编译的原理是sql注⼊只对sql语句的准备(编译)过程有破坏作⽤，

⽽预编译已经准备好了,执⾏阶段只是把输⼊串作为数据处理，⽽不再对sql语句进⾏解析,准备,因此也就避免了sql注⼊问题

02
 关键词过滤

可以使⽤正则等⼀些⽅法对特定关键词做检查，如果检测到不合法语句则进⾏报错返回

03
对数据库权限进⾏限制

对于数据库⽤户权限进⾏限制，防⽌如果真的存在SQL注⼊，也不会导致服务器失陷

04
对特定数据加密

对于⽤户密码这类敏感数据，可以使⽤hash或者加盐，使得攻击者⽆法直接利⽤数据进⾏进⼀步的攻击
