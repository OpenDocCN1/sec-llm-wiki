漏洞原理  

其7.0.3之前的版本中，对于digest和form两种认证方式，如果用户传入的密码为null（也就是没有传递密码参数），appweb将因为一个逻辑错误导致直接认证成功，并返回session。添加Set-Cookie到HTTP 头信息和用户名后,就可以绕过认证。

但是必须知道用户名，这个就显现出此漏洞的局限性了。

  
![](../Images/aac75e68f16f46b07169f32353b9fc35.png)  
影响版本  
  

Appweb 7.0.2以及之前的版本

  

![](../Images/aac75e68f16f46b07169f32353b9fc35.png)  
漏洞复现  

  

开启靶机

```


cd vulhub/appweb/CVE-2018-8715
```

![](../Images/0646f1cacf28455c627359f5f2f662a7.png)

  

访问目标：（http://your-ip:8080）看到一个登录页面![](../Images/4c8d7123fd6337e067769823fe74f782.png)

  

尝试登录用户名admin进行抓包

返回状态码为200，获取HTTP 头信息中的Set-Cookie：

```
\-http-session-=1::http.session::0444fdd35616140a355027102b2ac805
```

![](../Images/bd6099fd65f044a14649aca2389c223b.png)

  

再通过发送POST请求，添加Set-Cookie到HTTP 头信息和用户名后，发送数据包，尝试登录。

登录成功，成功绕过了密码验认证。

![](../Images/7270c7f21e6c926016fb6e2eff99b49b.png)

```
docker-compose down -v
```
