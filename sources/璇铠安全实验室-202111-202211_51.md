**1**

ActiveMQ的web控制台分三个应用，admin、api和fileserver，其中admin是管理员页面，api是接口，fileserver是储存文件的接口；admin和api都需要登录后才能使用，fileserver无需登录。

fileserver是一个RESTful API接口，我们可以通过GET、PUT、DELETE等HTTP请求对其中存储的文件进行读写操作，其设计目的是为了弥补消息队列操作不能传输、存储二进制文件的缺陷，但后来发现：

**2**![](../Images/27c6397b8514be47123f6617bcba820f.png)  
  
**3**影响版本  
**3**

Apache ActiveMQ 5.12.0之前的5.x版本

ActiveMQ在5.12.x~5.13.x版本中，已经默认关闭了fileserver这个应用（你可以在conf/jetty.xml中开启之）；在5.14.0版本以后，彻底删除了fileserver应用。

**5**漏洞复现  
  
准备阶段  
首先我们进入文件开启靶场

```

cd vulhub/activemq/CVE-2016-3088
```

![](../Images/b4827cf2258f2cf94dc73411babaa233.png)

  
信息收集  
使用nmap工具进行对网站服务的端口扫描

`nmap -sS -T5 -n -p- 192.168.9.151`

![](../Images/401a4428c2bd817d62744fc8f3b5e39f.png)

能看到拥有（8161和61616）2个端口，ActiveMQ的web界面端口就是8161，而他的工作端口是61616

  
漏洞利用  
警告测试次漏洞需要登录账号

警告测试次漏洞需要登录账号才能进行成功复现默认密码是admin/admin，访问url 获取他的绝对路径

http://192.168.9.151:8161/admin/test/systemProperties.jsp

![](../Images/e918e83d1c6a9c2bf0029ba261b1e00e.png)

我们进行bp抓包,并且修改请求头，使用PUT方法进行上传

```


PUT /fileserver/cs.txt HTTP/1.1
```

出现204即代表上传成功

![](../Images/3b4912018109379be7683beeb519d31d.png)

验证一下http://192.168.9.151:8161/fileserver/cs.txt

![](../Images/2cdb4d4a23a05616950b3de713ed2906.png)

接下来使用MOVE，进行变成jsp一句话木马，这边建议重新上传一下webshell

```


PUT /fileserver/shell.txt HTTP/1.1
```

能看到成功上传但是现在没办法被解析，我们需要将txt变成jsp

![](../Images/60f7c8e60fca554075a73cc5432e0eff.png)

使用MOVE进行修改文件后缀名

```


MOVE /fileserver/shell.txt HTTP/1.1
```

就成功的命令执行了http://192.168.9.151:8161/api/shell.jsp?cmd=whoami

![](../Images/d3b82b1d66b9bc0c8b57cc42d9cd2c70.png)

  
附加内容  
我们可以使用反弹shell，来拿去倒服务器的权限**PUT头**  
PUT头

```


PUT /fileserver/1.txt HTTP/1.1
```

**MOVE头**  
MOVE头

```


MOVE /fileserver/1.txt HTTP/1.1
```
