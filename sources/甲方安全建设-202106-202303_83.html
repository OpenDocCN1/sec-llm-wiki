探索 Windows UAC 绕过：技术和检测策略

前言

恶意软件通常需要机器上的完全管理权限才能执行更有影响力的操作，例如添加防病毒排除、加密安全文件或将代码注入有趣的系统进程。即使目标用户具有管理权限，用户帐户控制(UAC) 的流行也意味着恶意应用程序通常会默认为中等完整性，从而阻止对具有更高完整性级别的资源的写入访问。要绕过此限制，攻击者将需要一种无需用户交互（无UAC 提示）静默提升完整性级别的方法。这种技术被称为用户帐户控制绕过并且依赖于各种原语和条件，其中大部分基于搭载提升的 Windows 功能。

在这篇博文中，我们将查看一组 UAC 绕过，调查它们所依赖的一些关键原语，并探索检测机会。

注册表项操作¶

操作注册表项的目的是将提升程序的执行流程重定向到受控命令。被滥用最多的键值与特定扩展的 shell 打开命令（取决于目标程序）或windir/systemroot 环境变量操作有关：

  • HKCU\\Software\\Classes\<targeted_extension>\\shell\\open\command（默认或 DelegateExecute 值）
  • HKCU\\Environment\\windir
  • HKCU\\Environment\\systemroot

例如，当fodhelper恶意软件将（允许提升而不需要 UAC 提示的 Windows 二进制文件）作为中等完整性进程启动时，Windows 会自动fodhelper从中等完整性进程提升到高完整性进程。高完整性fodhelper然后尝试ms-settings使用其默认处理程序打开文件。由于medium-integrity恶意软件已经劫持了这个处理程序，提升的fodhelper人将执行攻击者选择的命令作为高完整性进程。

DLL劫持¶

DLL 劫持方法通常包括查找丢失的 DLL（通常是丢失的依赖项）或通过将恶意 DLL 加载到提升的进程中来赢得 DLL 文件写入竞赛。如果 UAC 已启用但未设置为**Always Notify，**则恶意软件可以执行提升的IFileOperation（无 UAC 提示）来创建/复制/重命名或将 DLL 文件移动到受信任的路径（即System32），然后触发提升的程序加载恶意 DLL 而不是预期的。

IFileOperation 由dllhost.exe(COM Surrogate) 执行，process.command_line包含 classId { 3AD05575-8857-4850-9277-11B85BDB8E09}。

我们可以使用以下EQL 关联来链接任何文件操作，dllhost.exe然后将非 Microsoft 签名的 DLL 加载到以系统完整性运行的进程中：
