# 探索 Windows UAC 绕过：技术和检测策略

## 前言 

恶意软件通常需要机器上的完全管理权限才能执行更有影响力的操作，例如添加防病毒排除、加密安全文件或将代码注入有趣的系统进程。即使目标用户具有管理权限，用户帐户控制(UAC) 的流行也意味着恶意应用程序通常会默认为中等完整性，从而阻止对具有更高完整性级别的资源的写入访问。要绕过此限制，攻击者将需要一种无需用户交互（无UAC 提示）静默提升完整性级别的方法。这种技术被称为用户帐户控制绕过并且依赖于各种原语和条件，其中大部分基于搭载提升的 Windows 功能。

`cscript.exe`以 Medium 身份运行并`cmd.exe`通过 UAC 绕过生成具有高完整性的实例的示例：

![](../Images/d605353bb91f8f7844977c967af566e3.png)

大多数 UAC 验证逻辑是在应用程序信息 (AppInfo) 服务中实现的。可以在此处找到有关海拔条件和不同检查的精彩入门。

在这篇博文中，我们将查看一组 UAC 绕过，调查它们所依赖的一些关键原语，并探索检测机会。

## UAC 绕过方法¶

## 注册表项操作¶ 

操作注册表项的目的是将提升程序的执行流程重定向到受控命令。被滥用最多的键值与特定扩展的 shell 打开命令（取决于目标程序）或`windir/systemroot` 环境变量操作有关：

*   `HKCU\\Software\\Classes\<targeted_extension>\\shell\\open\command`（默认或 DelegateExecute 值）
*   `HKCU\\Environment\\windir`
*   `HKCU\\Environment\\systemroot`

例如，当`fodhelper`恶意软件将（允许提升而不需要 UAC 提示的 Windows 二进制文件）作为中等完整性进程启动时，Windows 会自动`fodhelper`从中等完整性进程提升到高完整性进程。高完整性`fodhelper`然后尝试`ms-settings`使用其默认处理程序打开文件。由于`medium-integrity`恶意软件已经劫持了这个处理程序，提升的`fodhelper`人将执行攻击者选择的命令作为高完整性进程。

## DLL劫持¶ 

DLL 劫持方法通常包括查找丢失的 DLL（通常是丢失的依赖项）或通过将恶意 DLL 加载到提升的进程中来赢得 DLL 文件写入竞赛。如果 UAC 已启用但未设置为\*\*Always Notify，\*\*则恶意软件可以执行提升的IFileOperation（无 UAC 提示）来创建/复制/重命名或将 DLL 文件移动到受信任的路径（即`System32`），然后触发提升的程序加载恶意 DLL 而不是预期的。

IFileOperation 由`dllhost.exe`(COM Surrogate) 执行，`process.command_line`包含 classId { `3AD05575-8857-4850-9277-11B85BDB8E09`}。

## 检测规避¶ 

hFireF0X在这篇博文中讨论了许多不限于 UAC 绕过的规避技术，例如重命名文件夹或注册表项、注册表符号链接以基于特定文件路径/注册表项更改或不同的关联来破坏检测逻辑同一过程的事件。尽管大多数恶意软件家族都不会费心修改和调整这些技术，但考虑到这些规避机会是提高弹性的必要条件。

## 结论¶ 

通过专注于攻击性技术的关键构建块来设计检测比试图涵盖无穷无尽的实现和潜在的规避调整更具成本效益。在这篇文章中，我们介绍了用于 UAC 绕过的主要方法以及如何检测它们，以及使用令牌安全属性丰富流程执行事件如何使我们能够创建更广泛的检测逻辑，以匹配未知的绕过。

除了本博文中重点介绍的更广泛的检测之外，Elastic Endpoint Security还附带 26 种针对 UAC 绕过的预构建端点行为保护。
