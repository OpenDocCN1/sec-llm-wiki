在意大利的一个黑客聚会上，描述了一个有关手机取证的挑战过程，手机型号是“Jolla White 16GB JP-1301”，操作系统是“Sailfish 2.0.1.11”，设备之前已经过两次出厂重置，内部存储没有加密，但是设置了5位的数字PIN码，而且没有开启开发者模式。整个取证过程可谓是曲折有趣，这里进行简要摘编和分析。

**获取**

手机没有开启安卓提供的“ADB”服务，只能看到通过MTP协议提供的大容量存储，这种情况下只能对已有的文件进行逻辑备份，由于之前的重置操作，这部分数据的价值很小。

尝试使用 UFED4PC 和 Magnet Acquire 获取都失败了，这些工具甚至不能检测到手机。

在外部逻辑访问不成功的情况下，就应该掌握手机的更多细节，所以对这个手机进行了完全的拆解，直至看到主板的细节。首先可以看到的是处理器不是采用常见的高通4核，而是一个定制的MTK芯片：芯片上的编码在网上查不到任何信息。

![](../Images/0a516c5e6a88d987f7363d1b861c3fb8.png)  

其次可以看到的是主板上有很多测试点。从某些方面来看这是有利的地方，但是不利的地方是很难找到 JTAG 的接入点。

![](../Images/12a9d95a3e6c5bcd7e17c3573e6855fd.png)  

采用MTK芯片的通常方法连接，移除电池连接USB接口也没有任何成功的迹象。

采用网上找到的一个方法：

*   移除电池
    
*   在按住降低音量按键的同时插入电池
    
*   在按住降低音量按键的同时打开电源直到手机出现震动
    
*   放开电源和降低音量按键
    
*   系统进入恢复模式
    

在此模式下进行连接时，设备显示为一个新的USB设备，名称为“Generic RNDIS device”。在 Windows 10 中不能正确的加载驱动，在手工安装驱动后，设备被识别为一个网卡。

将手机接入到 Linux 操作系统，设备立刻被识别为USB网卡。在激活网卡后，可以发现手机运行了 DHCP 服务，计算机获得了一个IP地址。

手机只开放了23端口的终端服务。在登录之后（不需要认证），就获得了 root 权限。

首先运行 mount 命令检查文件系统，我们发现系统的主要分区没有加载，设备 (/dev/mmcblk0) 通过 GPT 模式划分了 28 个分区。

这个恢复状态的Linux系统已经足够使用了，具备用来获取手机物理内存的 “dd” 和 “netcat” 命令，因而最简便的方法就是利用现有的网络连接获取手机物理内存。

这个过程需要在计算机端使用 netcat 侦听，大致过程如下：

*   计算机中： nc -lvp 8888 | dd of=/path/to/destination/image.raw
    
*   手机中： dd if=/dev/mmcblk0 conv=noerror,sync | nc \[ip of the PC interface\] 8888
    

整个获取过程用了3个小时左右，得到了手机的物理内存，大小为16G，现在可以进行分析啦。

**分析**

首先需要检测的是分区情况，使用 X-Ways 打开分区镜像，可以解析 GPT 分区模式得到28个分区，胜利似乎不远了。

但是采用 UFED Physical Analyzer 分析镜像却没有成功：无论是采用预定义的模式，或者单独配置插件来提取镜像中的信息都失败了。最好的结果是采用“通用MTK模式”，PA 似乎找到了一些邮件和删除的信息，但是我们发现这些都是误命中 。

随后开始用 X-Ways 来分析分区，我们发现有两个大的分区，一个是24分区（Linux Swap，500M），另外一个是28分区（13.5G）。不幸的是我们遇到另外一个问题：分区采用最新的 BTRFS 文件系统，目前 X-Ways 和 UFED PA 都不支持。FTK Imager 和 Autopsy 不支持，Encase 和 FTK 也没有结果，没有一个主流的取证工具支持 BTRFS 文件系统，但是 Linux 支持!

所以两组人分别开始尝试不同的方法：有人在 Linux 下加载文件系统，然后将所有的数据文件打包导出，另外的人通过原始数据镜像扫描来进行分析。

第一组人成功获得了 Tar 文件，并开始用 X-Ways 进行分析。和我们估计的类似，设备上的当前文件并没有什么有用的数据，因为在开始之前经过了两次出厂重置。

所以第二组人的工作就很重要了。原始数据中有什么？首先采用 X-Ways 和 PhoteRec 进行恢复，然后再使用 Internet Evidence Finder (IEF) 和 Bulk Extractor (BE) 扫描结构化信息。

经过了几秒钟之后，X-Ways 提取出一些和医学站点有关的浏览器缓存图片，随后 IEF 和 BE 也找到了一些采用 Google 搜索特定医疗的关键词。X-Ways 和 PhoteRec 都恢复了一些 SQLite 数据库 (X-Ways 569, PhotoRec 600+)。其中有 Cookie 数据库，使得我们可以了解这些图片的来源，同时可以确定搜索和网站访问操作的时间。

我们又恢复出 GPS 应用的屏幕截图，也许是系统内置的应用，从截图中可以了解机主的部分行踪。最后我们提取出 EML 格式的邮件：邮件中可以得到使用人的姓名、地址等信息。

使用邮件中邮箱作为关键词搜索，找到了400个命中：对结果的详细分析又得到 200 个邮件信息，其中仅有部分信息被覆盖了，邮件中具有更详细的机主个人和工作的信息。
