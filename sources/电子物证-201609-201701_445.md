# 信息隐藏技术

在日常生活中我们所使用的钞票为了防伪，就使用了信息隐藏技术，如在紫外线的照射下可以看到一些在平常不可见的标志。在程序中，一般要隐藏版权信息、特定标识和关键代码等信息，而这些一般可以利用加解密的算法来在程序中实现。

 

一、文本信息隐藏

一般在一个软件中会有很多得文字内容，他们又用来做程序交互提示的，但是还有一些是表示软件的版权信息的文字。一般这些文字在软件分发后，不希望被别人修改。为了这个目的，就要对这些敏感文字进行隐藏处理，以防止这些信息被轻易的修改（一般如果不做处理的话，这些信息在文件中是以明文得方式存在的，可以通过十六进制工具轻易的进行修改）。

       在共享软件中的处理中，一般会有对某一些条件的检查判断（如时间，运行次数等），然后给出一些表示是试用、过期等提示的文字，这些信息如果不进行处理，在文件中同样以明文的方式存在的。破解者在静态反汇编时，通常都会首先找这些信息，然后根据显示信息的相关性，查找判断点，从而对软件进行破解。

现在假设有如下的逻辑：

| if condition  then  showmessage(0, ‘You see me!’, ‘You see  me!’, 0); |
| --- |

编译后的程序用W32Dasm反汇编得到如下的形式：

| :00401110  85C0                    test eax, eax         ; 判断:00401112  755B                    jne 0040116F:00401114 50                      push eax\* Possible  StringData Ref from Data Obj ->"You see me!":00401115  6838504000              push 00405038\* Possible  StringData Ref from Data Obj ->"You see me!":0040111A  6838504000              push 00405038:0040111F  50                      push eax\* Reference  To: USER32.MessageBoxA, Ord:01BEh:00401120  FF15A0404000            Call dword ptr  \[004040A0\] |
| --- |

在对该段代码进行破解时，很容易由静态的反汇编文本中对文本“You see me!”的引用，快速定位到condition的判断位置，将条件转移条件改掉，从而不显示该文字。前面所示代码中可以将401112处的代码755B改为**EB5B**（如果是对某个功能的限制，则就取消了对该限制的判断），或直接将文字内容改掉，显示其他内容。

同样逻辑，我们首先将文字内容做了隐藏变化，然后在程序中使用到该文字的地方首先对文字内容进行还原，在使用如下：

| if condition  then  showmessage(0, decodestr(szText),  decodestr(szText), 0); |
| --- |

这样对编译后的程序再进行反汇编后，我们可以得到如下形式的表示：

| :00401110  85C0                    test eax, eax         ; 判断:00401112  755B                    jne 0040116F:00401114 50                      push eax\* Possible  StringData Ref from Data Obj ->"Tbx-":00401115  6838504000              push 00405038\* Possible  StringData Ref from Data Obj ->" Tbx-":0040111A  6838504000              push 00405038:0040111F  50                      push eax\* Reference  To: USER32.MessageBoxA, Ord:01BEh:00401120  FF15A0404000            Call dword ptr  \[004040A0\] |
| --- |

这样就不能通过对明码文字的引用快速定位到条件判断出了，延长静态分析的时间，也在一定程度上也起了防止了软件破解的作用。

二、处理过程

隐藏数据，也就是要做保护的数据，如软件的名称，软件的制作者等信息，试用版提示信息等。对隐藏数据的处理可以有两种方法，一种为事前处理，一种为事后处理。

 

1\. 事前处理

在编译程序前就将程序中的某些数据以某种方式做成隐藏数据，然后将其一代码的方式写到程序中，进行编译。

假设我们的数据隐藏算法是按字节与13进行xor运算，则在前面的“You see me!”，在其代码处理前后的表示如下：

处理前

| Pascal中：const  sText : String = ‘You see me!’;C 中：  char \*szText = “You see me!”;ASM中：  szText DB ‘You see me!’ |
| --- |

处理后：

| Pascal中：const  szText: String =  #84#98#120#45#126#104#104#45#96#104#44;C 中：  char szText\[11\] = (84,98,120,45,126,104,104,45,96,104,44);ASM中：  szText    db 84,98,120,45,126,104,104,45,96,104,44; |
| --- |

其算法在pascal中可以像如下

| function  DecodeStr(const sText: String; XorValue: Byte): String;var      I : Integer;begin      Result := sText;      for I := 1 to Length(Result) do    // Iterate      begin           Result\[I\] := Char(Ord(sText\[i\]) xor  XorValue);      end;     // forend; |
| --- |

 因为要经常进行这样的文字信息的隐藏预处理，可以将这个功能做成一个简单的工具程序，供以后只要将要隐藏的文字填入，就可以得到隐藏后的代码表示。

2\. 事后处理

在程序中对首先要将隐藏信息进行还原，然后才能使用，要不然给用户看到的就是乱码了。还原算法一般是和隐藏处理的算法是对应的。

对信息隐藏的算法可以使用密码学中的各种对称算法，对数据进行加密解密。

  

三、总结

对一些关键数据进行了隐藏处理后，在一定程度上可以增加静态反编译的破解难度。如将“软件已经过期，请购买”，“软件为试用版，你还剩下12天可以使用”等数据进行隐藏处理，就可以有效防止那些利用静态反汇编，根据这些信息快速找到程序判断点进行快速破解。

而如果对关键代码进行了隐藏，则可以在一定程度上防止静态反汇编分析，因为该代码在静态时，是经过加密的，反汇编出的结果并不是实际在运行中执行的代码，也在一定程度上可以防止程序被打破解补丁，因为代码数据只有在执行该代码之前才被还原，其他时刻仍然是处于加密状态，这就需要破解者具有很强的破解功底，才能够对软件程序打补丁。

当然信息隐藏的处理也不是就这样几种，有很多种方法可以对信息进行隐藏，例如可以将信息进行隐藏处理后存放在外部的某个文件中，在使用时再从文件中读入信息还原后使用，也可以将信息隐藏在另外一个信息中等等。

对信息隐藏的算法可以使用密码学中的各种对称算法，对数据进行加密解密。

如果将信息隐藏技术配合其他技术，如花指令，反跟踪等，将会大大加大软件破解的难度。
