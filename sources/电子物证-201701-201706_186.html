在一些安全事件的调查取证过程中，经常需要通过恢复删除的文件来还原事实真相。黑客在入侵系统后，往往会采取一些措施清除攻击过程中留下的痕迹，主要是通过删除文件或清除特定信息。黑客攻击过程中可能会人为删除一些工具及其生成的文件，删除文件的方式可能是恶意程序内置自销毁、也可以是人为删除或者是杀毒软件检测后自动删除。

已删除文件并不总是可以恢复，恢复的可能性取决于几个因素：文件删除的方式、系统活动/数据重写到磁盘的概率、磁盘硬件（磁盘大小、磁盘类型 (如固态硬盘SSD)）。如文件无法恢复，文件的元数据信息也仍然可能被记录在其它Windows痕迹之中，可以通过Windows的相关痕迹信息来获得更多线索。

一

文件创建的痕迹

1. NTFS文件系统元数据文件-$MFT

NTFS文件系统中最重要的一个内部文件（元文件）是$MFT，该文件看起来很昂贵吗(都带有$美元符号）? 这是一个NTFS元数据文件，除该文件外，还有$LogFile, $UsnJrnl, $I30等。当一个文件创建时，在该文件中也会相应生成一条$MFT记录，文件数据内容本身存在于$MFT 的$DATA 属性之中。

如文件比较小 (<700字节), 文件内容将直接存在$MFT记录之中（常称为“常驻数据” )，恶意程序的配置小文件或输出文件可能就是这种常驻文件。当文件删除时，其对应的$MFT记录将会被标记为“不活动(inactive)”或可回收(free)。在这部分磁盘空间重新利用之前，文件元数据是可以恢复的。

2. NTFS文件系统元数据文件- $UsnJrnl

$UsnJrnl记录了文件系统的变化（出于维护系统可靠性目的），该元数据文件从Vista及以上版本开始支持。  Usn Journal日志记录包括了文件/文件夹名, 相应的$MFT项, 更新序列编号(USN), 时间戳, 原因标记等。常见的原因标记，如文件创建时，将设置“USN_REASON_FILE_CREATE” 标记，文件删除时，将设置 “USN_REASON_FILE_DELETE” 标记，完整的原因标记说明参考: https://msdn.microsoft.com/en-us/library/aa365722.aspx。$UsnJrnl通常不会被覆盖, 但日志记录可以从未分配空间挖掘恢复或卷影复制(VSC)中提取。

以下通过一个案例来说明该文件的作用。涉案人员使用微软SysInternals工具集中的SDelete进行数据的覆盖操作，用AAAA.AAA~ZZZZ.ZZZ覆盖文件名，覆盖文件内容可能无法恢复，但仍然可以通过注册表中搜索Eula许可协议接受的键值信息，如NTUSER.DAT\Software\Sysinternals\Sdelete，用正则表达式([A-Za-z])\1{2}(~[0-9]\.|\.)([A-Za-z])\1{2}搜索相关痕迹信息。 此外，可以提取出$UsnJrnl文件，可通过第三方工具（UsnJrnl2Csv）来解析数据，解析后有约395,000行，125 个唯一的 “Reason” 代码. 该案例中，我们聚焦在三种情况，Reason为DATA_OVERWRITE, FILE_CREATE, RENAME_NEW_NAME


通过USN Journal日志，取证人员可以清楚地了解发生了什么，黑客做了哪些操作，从而了解事实的真相。

3. NTFS文件系统元数据文件- $Logfile

NTFS使用$Logfile记录文件创建等操作，$Logfile记录信息的历史数据不如$UsnJrnl多，但是有更为详细的信息。最多只能保存32,000条记录, 超过后将重新开始并覆盖原有记录，它跟踪记录文件系统的创建、更新、重命名等，不记录文件自身数据的特有变化。

二

文件访问的痕迹 

1. 最近使用的应用(CCM_RecentlyUsedApps)

最近使用的应用(CCM_RecentlyUsedApps): 记录执行过的软件，生成使用统计信息。

该痕迹信息存储位置:

  • Vista以上操作系统: C:\WINDOWS\system32\wbem\Repository\OBJECTS.DATA

  • Windows XP操作系统: C:\WINDOWS\system32\wbem\Repository\FS\OBJECTS.DATA

  • SQL数据库：C:\Windows\CCM\InventoryStore.sdf

字段属性有Company Name，File Name，File Description，File Version，Last Used Time，Last User Name，Original File Name ，Product Name，Launch Count，多数正常文件有PE头部元数据信息，如果某些程序文件没有，就有可能是异常文件。要如何解析这些数据呢？  可以使用python-cim来解析数据，详细信息可进一步访问https://github.com/fireeye/flare-wmi/blob/master/python-cim/samples/

show_CCM_RecentlyUsedApps.py。 

2.   应用程序兼容缓存(Application Compatibility Cache)

Windows 查找AppCompatCache （即ShimCache）判断模块是否需要应用程序兼容处理。缓存数据跟踪程序相关信息取决于操作系统，通常包括文件路径(file path), 大小(size), 最后修改时间(last modified time), 最后执行时间(last execution time)以及文件创建时间  (适用于Vista以上操作系统）。应用程序兼容缓存的注册表键信息HKLM\SYSTEM\CurrentControlSet\Control\Session Manager的AppCompatibility或AppCompatCache\AppCompatCache。

可借助第三方工具来进行数据解析，如ShimCache Parser或Shimcachemem Volatility插件。下载地址如下：

https://github.com/mandiant/ShimCacheParser

https://github.com/fireeye/Volatility- Plugins/tree/master/shimcachemem

3.   预读文件(Windows Prefetch)

预读文件(Prefetch)保存最后执行的128个程序文件（默认）。记录最后运行日期、路径以及执行次数，文件创建日期可能就是文件第一次运行的时间。Windows Server服务器默认没有Prefetch预读文件。它跟踪记录程序执行时前10秒加载的文件，可能包含关联库文件、输入及输出文件。可以使用第三方工具，如PoorBillionaire编写的Windows Prefetch Parser工具（https://github.com/PoorBillionaire/Windows-Prefetch-Parser）

三

 结束语  

除了以上介绍的相关Windows痕迹信息，还有更多的痕迹及分析方法，可以找到文件在操作系统中的生成、运行及访问记录，从而了解还原事实真相。因此，安全人员或取证人员在对安全事件进行调查时，需不断学习新的知识，多参加专业培训课程（如电子取证、应急响应处置课程），参加讲座及学习Webinar，对于新兴的技术、操作系统的各种痕迹进行研究，此外还需学会换位思考，以攻击者的思维来思考，才能做到游刃有余。
