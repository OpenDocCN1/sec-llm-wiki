介绍

这篇文章和我之前的文章相比有些变化，我之前的文章大多数都是关于镜像制作以及镜像分析相关的。制作镜像需要满足三要素：  

*   设备和计算机之间的数据连接
    
*   漏洞
    
*   镜像命令
    

如果无法ROOT或不想ROOT设备，该怎么处理呢？这是实际存在的情况。只要你会使用ADB命令对手机进行操作，其实还是有其他办法从设备中获取一些有用数据的。本文就介绍一些简单的办法。

确定设备已经ROOT过

  

安卓取证过程中一中情况是设备可以被ROOT，但用户却不知道。这完全是有可能的，不过可以通过ADB shell来判断。以下是一些基础知识：  

*   系统分区，挂载点为“/system”,是只读的
    

普通用户无法修改此分区的任何数据，除非在ROOT状态下

*   Root文件——su——一般可以在系统分区找到
    
*   如果设备已经ROOT，那么证据一般在系统分区下可以找到
    

使用ADB shell连接设备，通过cd命令进入/system，然后执行“ls -al”命令。“ls”命令的“-l”参数会得到包含最后修改时间的/system下所有文件和目录的列表，“-a”参数会显示所有隐藏的文件，所以不至于遗漏某些内容。下面是在我的Nexus 5上执行上述命令得到的结果：

shell@hammerhead:/ $ cd /system

shell@hammerhead:/system $ ls -al

drwxr-xr-x root     root              1970-11-15 06:44 app

drwxr-xr-x root     shell             1970-11-15 06:44 bin

正如上面的时间戳所显示的，大部分目录的最后修改日期是2015-04-17，这是我最后一次刷机的时间。我们也可以发现一些比较奇怪的情况，有两个目录更新时间是两个月后的2015-06-25。这是什么情况呢？我们一起来看看。

通过cd命令进入etc目录，再次执行“ls -al”命令。

shell@hammerhead:/system $ cd etc

shell@hammerhead:/system/etc $ ls -al

\-rw-r--r-- root     root            2 1970-11-15 06:44 .installed\_su\_daemon

\-rw-r--r-- root     root         1472 2015-04-17 13:34 DxHDCP.cfg

\-rw-r--r-- root     root       277097 2015-04-17 13:34 NOTICE.html.gz

(A bunch more files ....)

\-rw-r--r-- root     root           38 2015-06-25 22:10 resolv.conf

(A bunch more files ....)

drwxr-xr-x root     root              2015-04-17 13:34 updatecmds

drwxr-xr-x root     root              2015-04-17 13:34 wifi

shell@hammerhead:/system/etc $ 

我们会发现resolv.conf文件只有读写权限而没有执行权限，最后修改日期为2015-06-25。这究竟是个什么文件？是否值得注意呢？  

我还注意到这个文件仅有38字节，于是用“cat”命令查看。

shell@hammerhead:/system/etc $ cat resolv.conf                                 

nameserver 8.8.4.4

nameserver 8.8.8.8

shell@hammerhead:/system/etc $ 

文件内容很简单，至于“8.8.4.4”的含义，请直接谷歌查询。  

一方面，这个文件仅仅描述了使用google DNS，并没有特别的意义；另一方面，为什么这个文件会有这样的修改时间？如果没忘记的话,resolv.conf文件和/system/xbin目录的修改时间是相同的。让我们切换到该目录并使用“ls -al”命令看看。

shell@hammerhead:/system/etc $ cd ../xbin

shell@hammerhead:/system/xbin $ ls -al

lrwxrwxrwx root     root              2015-06-25 22:10 \[ -> /system/xbin/busybox

lrwxrwxrwx root     root              2015-06-25 22:10 \[\[ -> /system/xbin/busybox

lrwxrwxrwx root     root              2015-06-25 22:10 acpid -> /system/xbin/busybox

.....

\-rwxr-xr-x root     root      1095836 2015-06-25 22:10 busybox

.....

\-rwxr-xr-x root     root        75364 1970-11-15 06:44 su

\-rwxr-xr-x root     root        75364 1970-11-15 06:44 sugote

\-rwxr-xr-x root     root       157412 1970-11-15 06:44 sugote-mksh

.....

lrwxrwxrwx root     root              2015-06-25 22:10 zcat -> /system/xbin/busybox

lrwxrwxrwx root     root              2015-06-25 22:10 zcip -> /system/xbin/busybox

shell@hammerhead:/system/xbin $  

上面这些意味着什么呢？意味着我在美国东部时间2015-06-25 22:20在我设备上安装了busybox。Busybox在/xbin目录创建了逻辑链接指向自己，并且修改了/system/etc/resolv.conf使之指向谷歌。  

此外，通过su文件这条记录，可以看到我在1970年11月15日root掉了我的设备。

1970年？无论是设备还是我，那时候还没有出生呢！那时候Google不存在，蜂窝网络也不存在，那时候的计算机还是用纸片打孔作为输入，那时候喇叭裤正流行！

其实，我是在2015年6月份ROOT我的设备的。由于我是通过recovery模式ROOT的，这种情况下没有启用Android时钟，所以全部活动都显示为发生在1970年。这些也可以在/system/etc/.installed\_su\_daemon文件上得到体现，该文件的最后修改时间也是1970年。

简单地总结一下，如果你担心你的手机可能已经被ROOT或破解，可以尝试在/system下执行“ls -al”命令来检查是否有修改时间异常的文件或目录。另外，请检查 /system/xbin/su是否存在。

一些提醒：

*   系统时间很容易被修改
    

聪明的攻击者会把时间改过来，类似上面的简单分析就发现不了了。

*   su文件可能并不叫“su”，而且可能存在于“/system/xbin”路径下
    

该文件可能存在于其他位置，有其他名称。总之只要有合适的权限，该文件可以放置在任何有执行权限的位置。

查看安装了哪些应用以及是否有不熟悉的应用

可能我们在手机上安装了某些应用并且记得自己安装过，也有可能我们安装了某些应用但忘记录已经安装。  

但如果某人把他的魔爪伸向你的手机并悄悄地安装了一些东西呢？我们看到过一些关于手机间谍软件的的文章，我们也看过在一些电影中，坏人得到了好人的手机并在其中安装了东西从而让坏人可以监听好人的一举一动。实际上，Android开发者模式就可以被利用来让这种应用运行。

如果你怀疑有人在监听你的手机怎么办？如果你的手机曾经root过，很有可能被人顺便留了些小“礼物”——安装了某个应用。这很可能是隐藏的，但是可以通过简单的命令行命令让其现身。

我将会介绍一种获取用户安装的应用清单简单快速的方法和另一种获取设备上安装的应用的详细信息的方法。

快速的方法是，使用ADB shell连接手机，执行下面命令：

pm list packages -3

“pm”命令代表“package manager”，顾名思义，该命令可以管理设备上的应用包或APP。上面命令会显示所有第三方应用，或者用户安装的应用。下面是我的手机执行的结果：

shell@hammerhead:/ $ pm list packages -3

package:stericson.busybox

package:com.redfin.android

package:com.weather.Weather

... a bunch more third party apps ...

package:com.google.android.apps.chromecast.app

package:com.lookout

package:com.fandango

package:com.hp.android.printservice

shell@hammerhead:/ $ 

如果应用清单中有任何你不认识的，可能你需要留意一下了。我个人能认出上面的所有已安装的应用。  

现在假设你想查看某个具体的应用。我们可以使用dumpsys命令，该命令可以访问各种类型的系统日志。例如，我们来看一下WatchESPN这个应用。

我执行了下面命令：

dumpsys package air.WatchESPN

你还可以输入下面命令：

dumpsys package

同样会得到一个类似的设备上已安装应用的清单。建议将这些信息导出到一个文件，方法如下。

adb shell dumpsys package > dumpsyspackage.txt

你的计算机上将会得到一个名为dumpsyspackage.txt的文件，里面有手机上所有应用的列表。  

列表中的WatchESPN应用引起了我的兴趣，想逆向该应用。那么我可以在非ROOT权限下导出该应用。下面是将一个应用导出到计算机本地的方法：

adb pull /data/app/air.WatchESPN-2/base.apk

根据上文的输出内容，应用的路径为 /data/app/air.WatchESPN-2/，我正好知道Android 5中应用在对应目录下的文件名为“base.apk”。上面命令会将该文件导出到本地计算机。  

继续讨论dumpsys命令。

Dumpsys有意思的地方

我在上面说过，dumpsys命令可以访问系统日志，该命令可以告诉我们除应用列表外的更多信息。  

如果你想获取所有的系统日志，可以使用上面导出应用日志到单个文件类似的命令。执行下面命令，然后去享受一杯饮料吧，因为执行时间有点长。

adb shell dumpsys > dumpsys.txt

得到的dumpsys.txt文件体积比较大，也没有什么条理，不好完整地展示。所以我们换用一种查看方式。ADB shell连接设备并执行下面命令：

dumpsys -l

那么我可以获得关于我正连接着的WiFi、使用情况等信息，你也可以对其他服做类似操作，比如对蓝牙信息感兴趣？我想你现在已经应该知道怎么操作了。

Dumpsys是一个不错的工具，但只对正在运行着的设备有效，对于镜像无能为力。镜像仅仅是一个文件，是死的，而设备是“活”的。

**总结**

*   存在一些办法从一个正在运行的Android设备上获取到有用信息，即使没有ROOT权限或无法获取到镜像。  
    
*   检查系统分区中文件的时间戳，是检查设备是否被破解的方法，不过记住时间戳是可以被伪造的。
    
*   Dumpsys是一个有用的工具。
    
*   可以使用dumpsys来了解设备上安装的应用程序，使用adb pull命令可以导出某个应用然后进行分析。
