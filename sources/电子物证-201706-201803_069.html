2016年6月14日，苹果公司在WWDC上正式宣布了全新的文件格式——Apple  File System（简称APFS），即“苹果文件系统”。从2017年的macOS High Sierra首先启用APFS文件系统后，用户是更加放心了，但取证人员更头疼了。


APFS的诞生

APFS是一个64位文件系统，单个分区支持9百亿亿文件，为取代苹果延用了30多年之久的HFS+文件系统而生，加入了很多现代文件系统应有的新功能特性。


在此之前，苹果的所有设备几乎都是基于HFS文件系统，但实际上由于设备的特性不同，因此采用的文件系统有多种，如macOS上的HFS、HFS+和HFS+J，而iPhone、Apple Watch的HFS+和HFS+ Per-File Crypto。此外，存储管理又有Fusion Drive和CoreStorage等等，相当繁杂混乱。


所以，苹果公司为改变现状，就设计出了功能更先进、更齐全的APFS，成为苹果设备中统一的文件系统。


APFS的特点

APFS作为苹果公司新的“扛把子”，该文件系统具备了一些新的优点。


  1. 动态存储：在不用重新分区的情况下，分区大小可以动态调整；

  2. 克隆：快速、高效地在同个卷宗上复制文件，且不须占用额外存储空间。对数据的修改将写入其他位置，未修改的块可继续共享使用。

  3. 快照：创建特定时间点、文件系统只读实例的快照；

  4. 磁盘加密：三种卷加密模型——不加密、单密钥加密、多密钥加密（即每个文件使用单独的密钥加密，元数据再使用另一个密钥加密）。

  5. 数据完整性：为确保数据完整性，APFS 对元数据采用校验和技术；

  6. 崩溃防护：使用“全新元数据记录、指向新记录、释放旧记录”的逻辑，而非覆盖现有记录，从而避免更新期间崩溃导致的记录损坏。


APFS的“容器”概念

苹果文件系统最令人惊叹的地方，就在于其动态存储特性。首先，我们来理解一下「容器」(container)的概念。


对照磁盘工具，我们可以看到物理磁盘之下，首先是一个「APFS容器」，其下才是APFS逻辑卷，这些「卷」是放在「APFS容器里面的」。


APFS格式的磁盘就是单个容器，多个分区共享容器的空余容量。


举个例子，如果在一个1000GB的APFS格式磁盘上，有一个A分区和一个B分区。


目前A和B分区各占300G和400G，但两者都可以任意用整个「容器」剩余的300GB空间。A和B分区可以不设固定分区大小，这样在A或B分区中，即使再存储一个大至300GB的文件都没问题。


我们都知道，一直以来，传统的文件系统都是通过固定的分区来管理文件的。我们之所以能迅速定位某个文件，很大程度上都依赖于记录固定位置的分区表。

（戳👉……复习文件系统知识）


现在APFS文件系统中磁盘分区的存储大小、位置都能在「容器」内自由膨胀，APFS的分区表有多强大，可想而知！



从前，系统盘如果爆了就必须格了重新分区，但现在完全不用操心这个问题了。APFS文件系统的空间共享（Space Sharing）的概念，让我们脱离了固定位置、固定大小的限制，可谓是真正的随心所欲。


随心所欲也意味着，如果你不喜欢共享，

还是可以给某个分区设置大小界定的。



APFS的分析方法

目前针对APFS的分析资料并不多，其原理只有苹果知道。但作为取证人员，我们不能对APFS束手无策，直接分析不行，那就利用多种工具对案件的数据进行分析，取长补短，得到尽可能多的分析结果。


对于APFS文件系统的分析，最好的方法就是苹果系统直接直接挂载分析（配合软只读工具），这样无需任何取证分析工具即可直接查看macOS系统中的各类文件，或利用Recon for macOS对各种App数据库进行解析。


但是，国内大多数取证分析人员习惯使用Windows系统及Windows系统下的取证工具，而目前能够完全支持APFS文件系统的取证工具并不多。


因此，本文给各位简单地介绍目前各种可以用于分析APFS磁盘镜像的方法和工具。


1、可以识别APFS文件系统的工具


Paragon 公司提供了一个在Windows下免费挂载APFS 卷的工具「APFS for Windows」。


如果在Windows操作系统下需要读取被格式化为APFS文件系统的硬盘、SSD、闪存，则可以安装这个工具，直接连接磁盘即可以只读方式读取数据。

APFS for Windows下载地址：

http://dl.paragon-software.com/free/apfswin_preview.msi


镜像文件被挂载成功后，APFS for Windows可以显示盘符为E：状态只读。


E：中显示出APFS文件系统下所有目录和文件



2、磁盘加载工具


因为案件中的数据主要是磁盘镜像，可能是DMG、DD、E01等格式，那么为了使镜像可以被加载起来，并被Windows所识别，取证人员可以使用2017年CCFC峰会中，讲师Mark Spencer所提供该公司的免费工具「 Arsenal Image Mounter」。


但是，利用Arsenal Image Mounter加载APFS镜像时，一定需要将扇区大小修改为4096字节。


注：请同时安装.Net Framework

Arsenal Image Mounter2.4.26版本下载地址：https://arsenalrecon.com/weapons/download/ArsenalImageMounter_2.4.26_Beta.zip


此时，用户可以用第三方取证工具对APFS文件系统进行分析，例如Encase、FTK。本例中，使用X-Ways Forensics 以逻辑磁盘形式加载分析APFS分区。



3、Windows系统下只读工具


利用Transmac 12.1 试用版（59美元），也可以在Windows系统下只读方式打开APFS卷，并可以直接读取DMG格式磁盘镜像，查看镜像中的文件。


Transmac 12.1 下载地址：http://www.acutesystems.com/tmac/tmsetup.zip


4、直接分析APFS镜像的工具

天宇宁达最新发布的法证通3.19版本，增加了对APFS文件系统的直接解析功能。无需第三方工具辅助，即可直接读取DMG、DD、E01、VMDK等格式的磁盘镜像，对APFS文件系统下的数据直接分析。


而处理苹果计算机数据的最佳平台毫无疑问是macOS，特别是对于苹果特有的Keynote、Pages、Numbers等文件内容查看和搜索、过滤都非常的方便。


结合法证通自动解析macOS系统信息、浏览器历史记录、电子邮件等APP数据库的功能，建议在实际分析过程中，用法证通和macOS协同分析。


如下图，这是郭老师的“苹果计算机+虚拟机+法证通+XWays Forensics”分析环境。


最后还有一点要注意：

Sumuri公司的Steve Whalen提示，对APFS文件系统进行磁盘镜像时，一定要对物理磁盘（disk0）进行镜像。即便需要对FileVault加密卷解密，也是要在镜像完成之后再进行，不要先解密再镜像。


所以要在此强调，进行证据获取时，一定要做完整的物理镜像，保证所有容器下的分区数据完整。
