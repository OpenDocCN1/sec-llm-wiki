# 【“清空回收站”后......】仍然可以找到证据！

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzAwNDcwMDgzMA==&mid=2651037001&idx=1&sn=6d440b552b564905947997163a1ccaae&chksm=80d0d2b8b7a75baedb914461007cad22d93b737b861205f9fe35f82507c488efcc5832700fbc&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzAwNDcwMDgzMA==&mid=2651037001&idx=1&sn=6d440b552b564905947997163a1ccaae&chksm=80d0d2b8b7a75baedb914461007cad22d93b737b861205f9fe35f82507c488efcc5832700fbc&scene=27#wechat_redirect)

  

当我们需要对计算机进行磁盘取证时往往会发现，该台电脑之前的操作人员已经将敏感文件删除进入回收站，并清空回收站或从回收站中彻底删除了这些文件，而这些文件很可能包含了重要的取证信息。

![](../Images/77b549d420780696f8f85052008ce7d0.png)

从原理上，删除只是在文件上作了删除标记，而真正的文件内容仍保存在磁盘的数据区中，并未得以删除。要等到以后的数据写入，把此数据区覆盖掉，这样才算是彻底把原来的数据删除。因此只要将整个磁盘进行分析，就有可能将已经彻底删除的文件恢复。

2准备工作  

目标系统：Win7SP1x86

1、首先我们在 D 盘创建几个小图片、小视频、小文档： 

`image.jpg、video.mov、text.txt、document.docx、image_d.jpg、video_d.mov、text_d.txt、document_d.docx。`

2、右键删除

`image_d.jpg、video_d.mov、text_d.txt、document_d.docx，`

之后 "清空回收站"。

![](../Images/7cca9de8b8039ea7d638390e864de3a8.png)  

# 

3创建磁盘镜像  

在进行磁盘取证时，为了尽量减少目标主机文件系统的变动，我们可以使用离线方式进行磁盘取证，将目标主机的磁盘创建镜像，放在移动磁盘中存储。

3.1在 Kali 下创建磁盘镜像  

### 3.3.1 启动到Live模式下

1、首先启动进入取证模式；

![](../Images/6d19f536d95fce7bb48c7ec7c880fba7.png)

2、接入移动硬盘，fdisk -l 确定移动硬盘的设备名为/dev/sdb1；

![](../Images/17fc91a256ce13dda75203a362022913.png)

3、挂载移动硬盘。

cd /mnt 

mkdir udisk 

mount /dev/sdb1 /mnt/udisk 

![](../Images/4301a3f947b96c27a64e9ec57389f7a7.png)

### 3.1.2 使用Guymager

![](../Images/214cdcf5bdbefe616a0885c7c9252dce.png)

1、在目标硬盘上右键 Acquire image， 

设置相关信息、保存路径、文件名，开始获取磁盘镜像。 

下面的hash校验我勾掉了，是为了让速度更快一些。 

![](../Images/dcb3bfd1b116558303d8f36be81092eb.png)

2、Start开始后，需要一段时间，由磁盘容量、速度与电脑性能决定。 

![](../Images/30cfa2977dda2e18a7bed992504525de.png)

3、镜像制作完成。 

![](../Images/987e02d18ddcec75bfef4ffee8c49d47.png)

![](../Images/a9d6901355ff7f8fe6afb51623cc973d.png)

全磁盘镜像文件大小共4.7GB。

![](../Images/ba0effe96f84660fc3a4270e736bc036.png)

磁盘实际使用大小是这样的。

![](../Images/40949572f849703c7148403c10771b1e.png)

### 3.1.3 使用dd

1、fdisk -l 判断目标磁盘编号：

#if=指定需要制作映像设备，-of=指定保存的位置。

2、dd if=/dev/sda

of=/mnt/udisk/Forensic/dd/sda 

![](../Images/159f9627059e4a9f487cfb8984954886.png)

dd速度非常慢，且在备份过程中没有任何进度提示，直接放弃换用增强版dd------dc3dd。

### 3.1.4 使用dc3dd

dc3dd和dd参数使用是一样的，它们一样是完整备份，对备份盘容量需求比较大，这里只备份sda3（D盘），可以看到备份了约6GB大小。 

![](../Images/3859d8e265ce586baae0faee687ba2b3.png)

最终D盘分区镜像大小5.81GB。

![](../Images/0d575c2597af95a28ceb04d55eef738a.png)

  

3.2在 Windows 下创建磁盘镜像  

在Windows下也最好使用Live系统如WindowsPE启动盘进行取证，但是由于这里没有现成的包含取证工具的启动盘，因此直接在系统里操作。取证工具、创建的磁盘镜像文件，都放在虚拟机的共享磁盘上，尽可能避免改变目标文件系统。

### 3.2.1 使用X-Ways Forensics 

这个工具就是Winhex的取证加强版，因此界面几乎都一样。 

1、工具栏选择Create Disk Image。

![](../Images/1723e6ffab032da94585f318cac74f53.png)

2、直接给整个磁盘创建镜像，创建分区镜像可以选择上边的。 

![](../Images/e0ea73749bb7a72fb098039ee40d30bf.png)

3、选择好存储路径后点OK开始。

![](../Images/da5e2a7b44827f8b1787685e9fca5f96.png)

4、开始创建镜像，镜像备份的速度比dd真是快的太多了。 

![](../Images/ba12576ca79604044c6f2bf7c3b382b8.png)

全盘备份5.8GB，要比guymager备份的文件容量多1GB，这个结果可能是受到了在线备份镜像的影响。 

![](../Images/4dab8c704dbd3c4f092ff595920b75a0.png)

### 3.2.2 使用AccessData FTK Imager 

由于我找到的这个版本不支持32位系统，因此只能使用它在另外一台x64虚拟机做一个创建镜像的演示。（D盘环境存在相同的文件读写删除操作） 

![](../Images/a6d9084ec9762e5a7738e60c9e15c960.png)

1、同样在工具栏选择Create Disk Image。

![](../Images/8805f1e3da97af0822c564a1185d91ce.png)

2、选择整个磁盘或分区，这里准备备份一个分区D盘。 

![](../Images/3ceae3fb8cb7edabdd59313a05ac3c55.png)

![](../Images/9d6831cead3cbb7ca78ef01f8e7e5228.png)

3、选择备份类型，这里不建议用Raw，那样就跟dd一样创建一个和磁盘大小一样的镜像，无视实际使用空间大小。 

![](../Images/a70f371df0da2764c39aa432dfe2e87e.png)

4、按需填写证据信息。

![](../Images/8403f61759a5d755c960d8b8afef716c.png)

5、选择存储位置，之后开始创建镜像。

![](../Images/acaf699e53fe06969bfa3b27f48e955a.png)

![](../Images/2ce3fccdd2807a20979bd7d821882ad4.png)

D盘镜像大小21.6MB（如果使用RAW格式，将会是10GB）。

![](../Images/8551e002bd55b9f4232e4a49891301cc.png)

4分析磁盘镜像  
4.1使用 X-Ways Forensics 分析证据  

相较于FTK，X-Ways拥有更完善的案件、证据管理模式，可以保存案件后续再接着分析。

1、创建案件。

![](../Images/fbe8d5824f76b13362fdc75b77c0c66c.png)

2、导入证据。

可以导入各类证据，这里选择镜像。

![](../Images/5acca22558f99faccab09297ff3ea2a0.png)

3、导入前面创建的4个镜像（包含两个全磁盘镜像、1个x86虚拟机的D盘、1个x64虚拟机的D盘）。

![](../Images/c368dc02c452b1007b582344767d819e.png)

4、查看D盘里的文件 。

可以正常显示图片，但是这里没有看到被删除的文件（被删除的文件显示为半透明）。 

![](../Images/cf600db69e5496a50a2c39b3bc00eaf1.png)

5、寻找被删除的文件。

由于删除时，是先del进入回收站，然后清空的，因此被删除的文件会在回收站的路径中。 

![](../Images/47f61d05e93eb65e4f8ef01747957125.png)

6、可以将镜像中有需要的文件恢复出来进一步分析。

![](../Images/7203331967308df96cacdc7244d02a1c.png)

  

4.2使用 AccessData FTK Imager 分析证据  

1、添加证据。

![](../Images/428ad86dff36855a9606eae12e02f7c4.png)

2、选择镜像文件，之后选择位置即可。

![](../Images/793e0b0cf1ae4b3e64561d2279132d85.png)

3、将4个镜像全部载入，这里不支持重命名。

![](../Images/97e58599cb387bc5483a5fd47b5a0ce9.png)

4、分析文件。

FTK同样可以直接预览txt、jpg 

![](../Images/773525447fffaac5137924bb05a31e31.png)

5、寻找被删除的文件。

同样到回收站目录下寻找被清空的文件，这里是使用红叉表示其被删除了。 

![](../Images/217f50024ee7b939a12a9fabc725352e.png)

6、导出文件。

FTK同样可以导出镜像内的文件。

![](../Images/73e7fcaa922c2319552c49ce3923a4a7.png)

5快速提取镜像内的文件  

使用 foremost 提取磁盘映像里的文件。 

`foremost -t all -i sda3`

```
\-i 指定镜像文件
\-t 指定文件类型
all 是所有支持的类型，具体支持的类型查看man。
```

![](../Images/d3d662da406e31282f827d995adbad4c.png)
