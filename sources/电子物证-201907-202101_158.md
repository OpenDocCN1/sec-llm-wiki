在移动设备数据提取以及设备密码破解的过程中，我们经常会遇到一些专业名词，例如9008模式、recovery模式、fastboot模式等，我们在理解该模式的时候经常会一头雾水，接下来，boy带着大家一起来了解一些Android芯片平台的各种模式以及相应的工作原理，并且利用该模式来进行全盘数据提取以及设备密码破解。** 1.Adb调试**adb的全称为Android Debug Bridge，主要作用是用于调试Android设备。我们能用adb模式干啥呢？Adb清除设备锁屏密码、adb重启以及重启进指定的设备模式、adb启动某APP、adb提取或者备份APP数据、adb......如果要查看adb支持的命令，可以在cmd窗口输入adb help即可查阅。我们如何利用adb来进行移动设备的密码破解以及逻辑数据提取、逻辑镜像、物理镜像呢？如果我们的设备具有su权限的情况下，我们可以使用adb以及相关的组件进行物理镜像提取以及逻辑镜像的提取。在我们尚未获得root权限或者su权限时，我们可以利用adb的backup命令进行数据备份，但是在许多APP中，已经禁止backup命令的实现，所以我们可以借助adb pull的方式，将sdcard中的用户数据资源进行导出到PC端，APP数据以系统自带的备份工具进行数据备份。   
**2.Fastboot模式**Fastboot模式在Android平台中，属于比较底层的一种模式，fastboot主要是对image镜像进行烧录、信息读取等。在该模式中，我们通常用于烧录第三方的recovery.img镜像。在该模式下，支持解锁bl（解锁fastboot烧录权限，俗称解锁bl或者解锁bootloader）。Fastboot与bootloader的关系，其实很多人都不明白，有点混了，boy对该模式的理解，是这样子滴：bootloader是开机第一启动的分区程序，bootloader会对设备状态进行判断，如果设备正常运行，则引导进入系统，如果设备接收到指令（如按音量上下键进入recovery或者fastboot模式时），bootloader会引导进入机主操作的模式中。在bootloader模式中，支持fastboot烧录协议，所以很多人称为fastboot模式或者bootloader模式，在本质上，两者都是同个程序运行的。只不过在不同情况下，程序执行的功能不一样。Android平台通用解锁bootloader命令如下：Fastboot root的方式运行。并且recovery模式支持解密全盘加密数据。在如今的Android项目平台，recovery模式具备了基础的Linux环境，可以实现一些基础的shell指令。我们可以通过修改官方recovery的方式，来使移动设备在该模式下具有root权限，并且实现对设备锁屏密码的清除、以及数据的提取。我们要如何借助Recovery来实现对设备的密码重置以及数据提取呢?首先，我们需要对该设备进行第三方recovery的适配（基于TWRP开源项目，是出色的第三方Recovery开源项目，该项目提供基础的Android运行环境，甚至可以运行jar格式的程序）我们借助移植或者编译twrp的方式，将所需要进行操作的设备，进行Recovery.img的适配。在完成适配后，我们将搭载TWRP的recovery.img，载入到移动设备中（以串口模式或者fastboot烧录模式将image镜像进行替换），并且在开机的时候，强制进入recovery模式，在进入recovery模式后，我们可以使用adb调试检测设备是否挂载（TWRP默认以adb root方式运行），检测完成后，可以使用adb shell的rm命令，将设备锁屏密码从/data/system/中，进行永久删除。命令如下：Adb shell rm -rf /data/system/gatekeeper.password.keyAdb shell rm -rf /data/system/gatekeeper.pattern.keyAdb shell rm -rf /data/system/locksettings.dbAdb shell rm -rf /data/system/locksettings.db-shmAdb shell rm -rf /data/system/locksettings.db-wal以上命令通用Android2.0-Android9.0在完成删除后，即可执行adb reboot重启设备，在重启后，即可发现设备密码已消失，我们即可进行数据提取以及分析。那我们要如何在第三方Recovery下进行数据提取呢？其实很简单，在Recovery下，我们可以先检测？userdata这个用户数据分区是否正常挂载（adb shell ls /data/data）因为用户的APP数据存储在/data/data路径下，如果数据正常挂载，我们可以使用adb pull的方式，将已挂载的数据，进行导出文件数据（adb pull /data/data），数据将被导出到PC端的adb组件的位置，也可以自定义保存路径。如果担心在pull的过程中，担心影响或者损坏文件，我们可以以tar压缩的形式，将数据从/data/data中，进行压缩后pull出来，命令如下：Adb devicesAdb shell tar -zcvf /sdcard/data.tar  
高通9008串口模式是属于芯片级串口数据读写。如果我们在经过CPU的授权通讯后，我们可以通过该桥接模式，对存储芯片（emmc或者ufs）进行有效的全盘读写。大概原理如下：我们利用串口通讯协议（firehose协议）向CPU发送firehose引导文件验证，如果CPU验证通过后，我们即可获得读写存储芯片的能力，可以借助软件，将移动设备中的全盘分区进行镜像转存到PC端。我们可以利用该模式，对没有进行数据加密的机型，进行有效的物理镜像提取。在市面上，Qualcomm平台提供了QFIL工具进行全盘数据读写的管理。后续我们将对QFIL工具进行有效的教学指导。下图为firehose协议通讯存储芯片的大致流程。![](../Images/aedf4d4913f5d8e02a0caf83c1a6e2fb.png)**5.高通9006串口模式**高通9006模式主要存在于早期的高通芯片平台，时间点为2014年以前的大部分高通设备手机，高通9006模式的特点在于进入该模式后，CPU自动将存储芯片以磁盘形式直接挂在于电脑。在该模式下，我们可以以非常友好的方式，进行设备全盘数据的管理、读写等。我们利用该模式，可以使用winhex以及其他能够加载磁盘的工具，进行有效的数据挂载。当数据挂载完成后，我们可以利用该模式，进行物理镜像提取、逻辑数据提取、设备密码重置等。   
介绍完以上的Android平台的模式，其实boy介绍的只是Android平台中的一部分，我们能够利用这些模式，可以进行有效的数据恢复、数据提取以及设备密码破解。如果我们能够熟练掌握以上模式的功能以及操作，我们基本上能够应对大部分早期的Android设备手机。以上内容来自十年以来对Android设备的学习以及操作，如果前辈们阅读到该文章后需要进行技术指点，麻烦前辈们请不吝赐教！
