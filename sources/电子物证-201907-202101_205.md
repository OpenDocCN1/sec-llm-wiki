密码可能是最古老的身份验证方法。尽管密码似乎有些过时了，但密码仍然是当今数字时代最受欢迎的身份验证方法。与其他身份验证机制相比，它们具有许多明显的好处。它们可以根据需要变得复杂或易于记忆。它们可以易于使用并且可以同时固定（如果使用正确）。

一个普通人必须记住的密码数量呈指数增长。早在2017年，普通家庭用户就不得不应对近20个密码（大概是唯一的密码）。一个普通的企业员工必须应付191个密码。密码无处不在。甚至您的手机也具有多个密码。说到Apple iPhone，它可能需要多达四个（半个）密码才能使您前进。为了使事情变得更加复杂，四个半密码是彼此紧密相关的。让我们列出它们：

*   屏幕锁定密码（这是您的iPhone密码）
    
*   iCloud密码（这是您的Apple帐户密码）
    
*   iTunes备份密码（保护计算机上的备份）
    
*   屏幕时间密码（保护您的设备和帐户，可以保护对上述密码的更改）
    
*   一次性验证码（如果您的帐户使用双向验证，则为“半个密码”）
    

在本文中，我们将概述如何使用这些密码以及它们如何相互关联。默认设置是什么以及它们如何影响您的隐私和安全。我们将告诉您如何使用一个密码重设另一个密码。我们还将介绍密码策略，并描述如果您尝试强行使用被遗忘的密码会发生什么情况。

**0x00.屏幕锁定密码**

这是最重要和最深刻的密码。这是大多数用户设置新iPhone时设置的密码。默认情况下，屏幕锁定密码的长度为6位数字。如果您努力尝试，仍然可以选择使用“旧模式”的 4位数字PIN，或者，如果您认为有隐藏的地方，则可以选择自定义字母数字密码。从技术上讲，您无需密码即可设置设备，但选择此项将限制您访问某些iPhone功能（如Apple Pay）的能力。没有屏幕锁定密码，您将无法将网站密码，消息和运行状况数据同步到iCloud。

**如果您忘记了屏幕锁定密码**

如果您是普通用户，则将无法解锁iPhone。但是，您可以重置iPhone，从而消除密码和所有数据。（确保在iCloud和/或计算机上有备份。）成功重置iPhone后，绝对需要使用**iCloud****密码**进行设置。（看到了吧？这是第一个关系。）

*   您可以擦除设备以重置屏幕锁定密码。但是，您需要输入**iCloud****密码**才能稍后重新激活设备。
    
*   如果您在执法部门工作，可以访问某些非常受限制的软件或服务且设备兼容，则可以攻击屏幕锁定密码。即使那样，也可能存在多个问题，而且即使不是大多数设备，也有许多设备可能无法在合理的时间内解锁。
    

**如果您知道屏幕锁定密码**

如果您知道屏幕锁定密码，则可以执行以下所有操作：

*   即使在冷启动后也可以解锁设备
    
*   连接到USB附件（解锁设备会禁用USB限制）
    
*   将设备与新计算机配对并进行新的本地备份
    
*   更改**iCloud****密码**和受信任的电话号码（仅适用于**2FA****帐户**；不需要一次性2FA密码）
    
*   重置（删除）**iTunes****备份密码**（如果未设置“**屏幕时间****”****密码**）
    
*   iOS 13：更改或设置新的iTunes备份密码
    
*   更新iOS
    
*   将设备重置为出厂设置
    
*   查看保存在钥匙串中的密码
    
*   从iCloud访问某些类型的数据（需要**iCloud****密码**和**一次性** **2FA****密码**）。这包括iCloud钥匙串，运行状况数据，已同步的消息，屏幕时间数据
    
*   执行物理分析。如果设备屏幕锁定密码已知，并且安装应用程序没有“屏幕时间”限制，则可以使用iOS     Forensic Toolkit越狱设备，提取文件系统并解密钥匙串。通过物理提取获得的钥匙串将包含**屏幕锁定密码**和**iCloud****密码**等。
    

****其他情况（****The ifs and buts****）****

*   仅当用户未对Apple帐户更改设置屏幕时间限制时，才能更改iCloud密码（如果您知道**屏幕时间密码**，则可以将其关闭；还有其他关系）
    
*   如果用户具有“ **屏幕时间****”****密码**，则需要（除了**屏幕锁定密码之外**）以重置**iTunes****备份密码。**
    
*   设置或更改密码后，设备将尝试连接到iCloud（确认iPhone密码）。这是将设备添加到“信任的圈子”所必需的。否则，将禁用iCloud钥匙串并中断受保护数据类别（运行状况，消息，屏幕时间）的同步。

**0x01.iCloud****密码**

如果您使用的是iCloud，则始终设置此密码。如果您曾经从App Store下载过一个应用程序，则您还将这个密码作为Apple ID密码。很难想象一个拥有iPhone却没有Apple ID / iCloud密码的人。

Apple对密码复杂性执行某些最低要求；本文介绍的所有其他类型的密码通常都比较简单。除了密码复杂性外，不允许用户设置与以前使用的Apple ID / iCloud密码匹配的Apple ID / iCloud密码。

Apple ID / iCloud密码的目的是保护对用户在线帐户（例如其iCloud数据，包括iCloud照片和备份）的访问，并保护iPhone免受盗窃。iCloud密码是极为可靠的出厂重置保护系统的一部分，该系统使iPhone盗窃的吸引力大大降低。

该密码（以及2FA帐户的第二个身份验证因素）限制了访问iCloud数据的能力。即使您知道Apple ID / iCloud密码，也可能不足以访问某些类型的数据。例如，访问iCloud钥匙串，iCloud消息，运行状况和屏幕时间数据，您还需要设备**屏幕锁定密码**。

无需密码即可访问iCloud吗？是的，至少对于某些数据而言；阅读访问iCloud中有和没有在2019年密码以获取更多信息。

**如果您忘记了****iCloud****密码**

如果您忘记了iCloud密码怎么办？苹果对此主题有详尽的文章：如果您忘记了Apple ID密码。您可以直接从设备上重置iCloud密码（如果您知道设备**屏幕锁定密码** 并且该帐户使用**两因素身份验证**）。此外，您可以从多种来源中提取iCloud密码，例如使用Internet Password Breaker（Windows）提取Web浏览器中的密码，使用Password Digger提取 macOS钥匙串的信息，或使用Phone Breaker提取加密设备备份数据（如果又知道**iTunes****备份密码**）。

如果您忘记了iCloud密码，则可以选择：

*   从您的Apple设备重置（需要**屏幕锁定密码**，必须启用**两因素身份验证**，但不要求输入2FA代码）
    
*   从其他人的Apple设备重置（需要**屏幕锁定密码**，必须启用**两因素身份验证**，**一次**需要**2FA****代码**）
    
*   通过Web浏览器重置（使用或不使用2FA的帐户的操作步骤不同；对于2FA帐户，您将需要输入**一次发**短信形式的**2FA****代码**到您**信任的电话号码中**）。
    

**如果您知道****iCloud****密码**

如果您知道iCloud密码，则可以执行以下所有操作：

*   如果您忘记了其**屏幕锁定密码，**则可以重新访问自己的设备：通过恢复模式重置设备，然后在设置过程中出现提示时输入**iCloud****密码**
    
*   授权App Store购买（如果未为购买启用生物特征识别）
    
*   授权应用更新（如果出现提示，这似乎是随机的）
    
*   登录到App Store（对于具有**两要素身份验证**帐户的帐户，需要**一次性****2FA****代码**）
    
*   从iCloud提取某些类型的数据（没有两因素身份验证的帐户）
    
*   从iCloud中提取更多数据（**两因素身份验证**帐户，需要**一次性****2FA****代码**）
    
*   从iCloud提取更多数据（例如iCloud钥匙串，iCloud消息，运行状况和屏幕时间）（**两要素身份验证**帐户，需要**一次性****2FA****代码，**需要设备**屏幕锁定密码**）
    
*   禁用iCloud锁定，关闭“查找我的iPhone”，执行恢复出厂设置
    
*   登录您的Apple帐户（对于具有**两要素身份验证**帐户的帐户，需要**一次性****2FA****代码**）
    
*   通过“ 查找我”远程定位，锁定或擦除设备（即使对于2FA帐户，也不需要一次性2FA代码）
    
*   更改您的Apple ID / iCloud密码
    
*   在Apple设备上登录以使其受信任（对于具有**两要素身份验证**帐户的帐户，需要**一次性****2FA****代码**）
    

**其他情况（****The ifs and buts****）**

*   仅当用户未对Apple帐户更改设置屏幕时间限制时，才能更改iCloud密码（如果您知道**屏幕时间密码，**可以将其关闭）
    
*   如果您的Apple帐户使用**两因素身份验证**，则**iCloud****密码几乎毫无意义**。如果您可以使用第二个身份验证因子（受信任的iPhone，受信任的电话号码/     SIM卡），则可以**轻松更改****iCloud****密码**。但是，如果您仍然知道iCloud密码，但无法访问第二个身份验证因素，则将无法访问您的帐户。恢复您的Apple ID的过程非常漫长而复杂，但结果无法保证。在我们执行的测试中，在没有访问第二个因素的情况下恢复2FA帐户时，成功几率接近50-50。也许这（而不是第二个因素）应该成为Apple密码的一半？
    

**0x02.iTunes****备份密码**

该密码是可选的，默认情况下未设置。

显而易见的是，您将需要此密码才能从备份中还原设备。如果您的原始设备没有数据，而只有备份文件，则需要使用一系列智能攻击和蛮力攻击（例如，使用Elcomsoft分布式密码恢复）来破坏密码。由于防护能力很强，这些攻击效率不是很高。期望在合理的时间内仅恢复简短的密码。

但是，如果您有权访问iOS设备本身，则可以在进行新备份之前*重置*备份密码。此功能在iOS 11和所有较新版本的iOS中可用。您需要**设备屏幕锁定密码**来**重置****iTunes****备份密码**。如果配置了“ **屏幕时间****”****密码**，则会阻止您执行此操作，因此，除了屏幕锁定密码外，您还需要“屏幕时间”密码才能重置iTunes备份密码。

如果设备运行的是iOS 13，则还需要输入设备**屏幕锁定密码**以设置或更改备份密码。

**如果您忘记了****iTunes****备份密码**

*   如果您拥有原始的iOS设备，则可以尝试重置iTunes备份密码（iOS     11及更高版本）。为此，您需要设备**屏幕锁定密码**。另外，如果设置了“屏幕时间”密码，则还需要“ **屏幕时间****”****密码**。
    
*   如果只有备份文件，并且备份受未知的iTunes备份密码保护，则需要强行使用该密码（这可能非常慢）。您可以使用GPU辅助和/或分布式攻击，或者选择执行字典攻击而不是蛮力攻击来加快恢复速度。
    
*   您还可以使用iCloud备份来分析/还原设备。您将需要**iCloud****密码**和**2FA****代码**才能还原/下载云备份。但是，如果将iCloud备份还原到*新*设备（或使用Elcomsoft     Phone Breaker下载），则钥匙串将丢失；所有保存的密码都将消失。
    
*   如果“ **帐户更改****”**限制设置为**“****不允许****”****，**则“屏幕时间”密码可能会阻止您重置iCloud密码。
    

**如果您知道****iTunes****备份密码**

如果您知道iTunes备份密码（并且具有备份文件），则可以执行以下所有操作：

*   恢复原始或新的iOS设备（包括钥匙串密码）
    
*   分析备份并获取“ **屏幕时间****”****密码**（仅限iOS     12）或“限制”密码（iOS的较早版本）。
    
*   分析备份并从钥匙串中获取密码（可能包含或可能不包含用户的**Apple     ID / iCloud****密码**）\*
    

**其他情况（****The ifs and buts****）**

*   分析本地备份时，**iCloud****密码**可能可用或不可用。如果用户从Safari浏览器登录其Apple帐户，也可以获取该密码。\*
    
*   如果iOS 13设备产生了“ **屏幕时间****”****密码，**则无法从本地备份获取“ **屏幕时间****”****密码**。

**0x03.屏幕时间密码**

屏幕时间是iOS 12中出现的一项最新功能。可以使用或不使用密码来启用屏幕时间。如果您选择使用密码，则密码始终由四位数字组成。

如果设置了“屏幕时间”密码，它将阻止更改“屏幕时间”设置中指定的任何限制。另外，“屏幕时间”密码可防止用户重置设备设置。反过来，这意味着如果您不知道屏幕时间密码，您将无法重置备份密码。

此外，用户可以配置安装应用程序的限制。在这种情况下，“屏幕时间”密码将阻止安装新应用的功能，这意味着您可能无法安装越狱程序。越狱通常允许提取设备的全部内容，包括完整的钥匙串（其中包括**iTunes****备份密码**，**屏幕时间密码**和**Apple ID / iCloud****密码**）。

**如果您忘记了屏幕时间密码**

*   您将无法关闭屏幕时间，禁用或绕过限制
    
*   您将无法打开“跨设备共享”功能，如果要从iCloud获取“屏幕时间”密码，则需要此功能
    
*   iOS 12：通过分析受密码保护的备份（需要**iTunes****备份密码**）来恢复“屏幕时间”密码。
    
*   iOS 12和13：从iCloud提取屏幕时间密码（需要以下三个条件：**iCloud****密码**，**2FA****代码**，设备**屏幕锁定密码**）
    

**如果您知道屏幕时间密码**

*   您可以删除单个“屏幕时间”限制，关闭“屏幕时间”或仅禁用“屏幕时间”密码
    
*   如果您知道设备**屏幕锁定密码**，则可以重设**iTunes****备份密码**
    

**其他情况（****The ifs and buts****）**

*   iOS 12：您需要受密码保护的备份才能提取“屏幕时间”密码。如果未指定备份密码，则需要设置新的备份密码。
    
*   iOS 13：“屏幕时间”密码在iTunes备份中不可用。请改用云提取。
    
*   如果已启用“ **跨设备共享** ”功能，则只能从iCloud中提取“屏幕时间”密码。如果不是，则没有有效的“屏幕时间”密码，您将无法激活它。
    
*   如果您知道**的****iCloud****密码**，有**2FA****代码**，并知道**锁屏密码**或**系统密码**的**至少一个**参加“分享跨设备”设备的功能，您将能够提取所有屏幕时间密码，所有设备参与在分享中。
    

**0x04.两因素认证码**

说到Web服务，密码保护绝对不足以保护帐户安全。Celebgate是一个很好的例子，它迫使Apple加快了两因素身份验证的工作。如今，我们坚信必须使用第二个因素保护iCloud帐户。苹果公司的双重身份验证实现非常好。一旦有人尝试访问其帐户，所有者就会在所有注册的设备上立即收到推送通知。可以离线生成2FA代码或通过短信接收它们。

但是，在Apple实施2FA的情况下，与没有两因素身份验证的设备相比，设备本身的安全性可能会降低。因此，我们将2FA代码视为半密码。

在现实世界中，Apple十分强调两因素身份验证。您**必须**对您的Apple帐户中有双因素认证，如果你想要的任何的以下特点：

*   能够在iCloud中同步密码（iCloud钥匙串）
    
*   通过iCloud同步运行状况，消息和屏幕时间
    
*   重置忘记的Apple     ID / iCloud密码的功能
    

如果您忘记了Apple ID / iCloud密码，则只要可以访问受信任的设备（该设备被视为您的第二个身份验证因素），就可以随时将其重置。但是，如果您失去对所有受信任设备和受信任电话号码的访问权限（实际上失去了对两因素身份验证的访问权限），那么您将被锁定在Apple ID / iCloud帐户之外。恢复您的Apple ID的过程非常漫长而复杂，但结果无法保证。在我们执行的测试中，在没有访问第二个因素的情况下恢复2FA帐户时，成功几率接近50-50。所有这些使您的第二身份验证因素远比iCloud密码重要。

**如果您无法访问第二个身份验证因素**

*   即使您知道iCloud密码，您也将被锁定在Apple ID / iCloud帐户之外
    
*   您也许可以恢复对Apple帐户的访问。该过程复杂而漫长，并且无法保证结果
    
*   尝试不失去对第二个身份验证因素的访问权限
    

**如果您有权使用第二个身份验证因素**

*   如果您可以访问受信任的设备（该设备被视为您的第二身份验证因素），则可以轻松重置您的**Apple     ID / iCloud****密码。**

**0x05.密码政策**

四个密码在长度和复杂度上有不同的策略。：

*   **屏幕锁定密码**：无明确政策；可以选择4位，**6****位**（默认），自定义数字或可变长度的字母数字。苹果维护着最常见密码的数据库；如果您尝试选择其中之一，则会受到警告（但仍然可以使用它）。
    
*   **iCloud****密码**：至少必须包含8个字符；必须至少包含一个小写字母，一个大写字母和一位数字。
    
*   **iTunes****备份密码**：无政策。
    
*   **屏幕时间密码**：正好4位数字
    

**0x06.如果您尝试暴力验证**

如果您忘记了密码，则可能会尝试尝试一些您认为合适的密码。如果您这样做，将会发生以下情况：

*   **屏幕锁定密码**：逐渐增加延迟，然后永久锁定设备（由于USB受限模式而导致“连接到iTunes”死锁），或者，如果用户指定“ 10次尝试后擦除”设置，则尝试10次后擦除为出厂设置。
    
*   **iCloud****密码**：临时帐户锁定。此外，如果在从iCloud提取iCloud钥匙串，运行状况，消息或屏幕时间数据时尝试强行使用设备**屏幕锁定密码**，则仅需尝试10次，所有这些类别都将被擦除。
    
*   **iTunes****备份密码**：无限制。蛮力离开！
    
*   **屏幕时间密码**：逐渐增加的延迟；尝试10次后，两次尝试之间将延迟一小时。
    

**0x07.****结论**
