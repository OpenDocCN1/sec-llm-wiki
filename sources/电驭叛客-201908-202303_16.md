**Google 云安全概述**

**https://cloud.google.com/blog/topics/developers-practitioners/google-cloud-security-overview**

  

说到云安全，包括基础设施、网络、数据、应用程序和身份访问与管理。还包括安全运营、治理、风险、合规管理等流程。

  

在云上构建应用程序的最佳方式是责任共担。

  

![](../Images/9a6016afbbf8eab8f08bb784aeda3195.png)

  

  

**责任共担，命运共担**

  

云安全需要协作，并且通常在共享责任模型上运行，其中云提供商负责底层云基础设施的安全，而用户负责保护部署在云上的应用程序。

  

提供了的应用程序和业务实施所需的安全控制所需的灵活性和控制力。可以限制对敏感数据和项目的访问，或有选择地部署公共应用程序。

  

在 Google Cloud，我们努力超越这种共享责任模型的基础，建立基于Shared Fate的运营模型。

  

共同的命运是为客户准备一个安全的登陆区，在他们那里指导他们，对他们可以配置的安全控制保持清晰和透明，提供护栏，并帮助他们进行网络保险。这是为了帮助确保客户拥有强大的安全态势，包括设计安全的服务、安全的默认设置以及我们提供的一组丰富的最佳实践、模板、蓝图、文档和专业服务。

  

![](../Images/8b81fe73e2918515f554a38c049299f9.png)

  

  

**基础设施安全**

  

云提供商负责提供基础设施安全，包括整个信息处理生命周期的安全，包括硬件基础设施、服务部署、存储服务、用户身份、互联网通信以及操作和设备安全。

  

![](../Images/4972fd4cfc1cf3acdbcd6165e1d1c154.png)

  

  

**网络安全**

  

网络安全部分由云提供商负责，部分由您负责。供应商致力于确保流量安全和加密，以及与公共互联网上其他服务的通信安全。它们还提供针对网络攻击的强大基线保护。

  

用户负责定义和实施应用程序边界、在团队和组织之间分割项目、管理员工的远程访问以及实施额外的 DoS 防御。 

  

  

**应用安全**

  

在云上构建应用程序或 API 时，用户负责应用程序的安全性，包括扫描和测试。采用以下做法： 

  

*   根据用户的身份验证和授权允许和拒绝流量。 
    
*   使用或实施服务来阻止机器人和欺诈性用户访问您的网站。 
    

  

用户可以使用 Web 应用程序和 API 保护 (WAAP) 解决方案保护面向 Internet 的应用程序免受攻击。

  

![](../Images/5a335562b262dfe2e9bb7504de950414.png)

  

  

**软件供应链安全**

  

保护软件需要建立、验证和维护信任链，以通过在整个软件开发和部署过程中生成和检查的证明来建立代码的出处或来源跟踪。

  

软件工件的开源 SLSA供应链级别是供应链完整性的端到端框架，可以逐步采用该框架来提高安全水位。 

  

在 Google 中，Cloud Binary Authorization 服务通过 SDLC 流程不同步骤的证明和策略检查来建立、验证和维护信任链。 

  

![](../Images/fb393259348179e5c05870cabf3d2cc3.png)

  

  

**数据安全**

  

数据安全是用户和云提供商之间的共同责任。

  

云提供商提供了一些内置在基础架构中的功能，例如静态和传输中的数据加密。

  

客户负责应用程序的数据安全。这包括密钥和秘密管理、查找敏感数据、实施控制、防止泄露和数据丢失等功能。 

  

![](../Images/cdf571c0837f294d87331257efd0715a.png)

  

  

**身份和访问管理**

  

安全的管理用户生命周期和应用程序访问，包括用户身份验证和这些用户对适当服务的授权。 

  

![](../Images/422b8f7553b5e8436bf111e379164225.png)

  

  

  

一旦通过身份验证，Cloud IAM通过提供细粒度的访问控制和集中管理云资源的可见性来提供授权——“谁可以在 Google Cloud 上做什么和在哪里做”。

  

IAM 策略管理对 Google Cloud 资源的访问控制，而 IAM 角色有助于设置细粒度的权限。 

  

![](../Images/264300dd60b32875e94e6f9fcf079844.png)

  

BeyondCorp Enterprise采用零信任模型来访问应用程序和资源。

  

除非它们符合每个资源访问策略中规定的所有规则和条件，否则任何人都无法访问相关资源：

  

![](../Images/5e147e9f1ac1b8181f25bce1d266c5a8.png)

  

  

**端点安全**

端点安全对于保护用户和访问至关重要。您需要确保应用补丁、防止入侵和管理用户设备，包括定义哪些设备可以访问您的应用程序或项目中的哪些资源的策略。 

  

**安全监控和运营**

  

从安全运营 (SecOps) 的角度来看，需要检测、响应和修复云中的威胁。

  

![](../Images/7f599b14090dbbd4f1616e5d7c645a33.png)

  

**治理、风险和合规**

  

包括了解安全风险、定义和执行策略、通过获得认证来证明合规性并保持良好的安全态势。
