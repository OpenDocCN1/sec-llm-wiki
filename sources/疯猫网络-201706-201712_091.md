前言  

  

在分析`shellcode`时，静态分析或者使用`scdbg`模拟分析都不够准确，如果转换成`exe`文件那么就可以用`debugger`或者`IDA`分析，会方便很多。

  

  

![](../Images/98760d82f1edad15f9b842569f9b0e21.png)

  

## 样本分析

这里以`CVE-2013-3346   `的样本为例，使用`peepdf`分析样本:

  

> ```
> $ python peepdf.py -i -f ~/Downloads/sample.pdf                                                                                                                                                
> ```

  

其中`Objects with JS code (1): [3]`可知对象3是一段`js`代码:

  

> ```
> PPDF> object 
> ```

  

这里要把从`Q=~[]`开始的加密代码拷贝到文件中。

这里的代码是用`jjencode`加密过的，使用`peepdf`自带的解密工具可以还原出`js`代码:

  

> ```
> PPDF> js_jjdecode file /Users/seviezhou/Downloads/sample.js $> jsdecode
> 
> PPDF> js_analyse variable jsdecode $> shellcode
> 
> PPDF> show jsdecode
> 
> var shellcode = unescape(
> ```

`js`代码主要是`shellcode`的布置和堆喷射还有`rop`的构造，这里的`shellcode`利用`CVE-2013-5065`绕过了沙箱。将`shellcode`提取出来使用`scdbg`分析得到如下结果:

一开始分析就会陷入一个死循环，然后尝试改变`eip`得到了一些`api`的调用。

## 转换shellcode为exe

还是看不出什么，这里我们把`shellcode`转换成`exe`文件来分析，首先我尝试了`shellcode2exe.py`，可转换结果并不是一个合法的`exe`文件，这里讲一个通用的方法，这里要用到`yasm.exe`和`golink.exe`，下载地址:

  

yasm-1.3.0-win64.exe

yasm-1.3.0-win32.exe

golink

下载对应位数的`yasm`和`golink`，分别重命名为`yasm.exe`和`golink.exe`。

然后用`winhex`等十六进制编辑器把`shellcode`保存为`shellcode.bin`:

  

> ```
> $ hexdump shellcode.bin
> ```

  

然后新建一个文件`shellcode.asm`，内容如下:

  

> ```
> $ cat shellcode.asm
> 
> Global 
> ```

  

最后把`yasm.exe`、`golink.exe`、`shellcode.asm`、`shellcode.bin`放在同一个目录下，以32位系统为例，依次执行如下命令:

  

> ```
> yasm.exe -f win32 -o shellcode.obj shellcode.
> ```

然后就可以分析`shellcode`了，当然也可以放到`IDA`中分析。

## 总结

当分析`shellcode`时，可以结合多种方法分析，静态或者动态，才能更好的分析代码的行为，这时能够转换成可执行文件分析就是很好的方法。
