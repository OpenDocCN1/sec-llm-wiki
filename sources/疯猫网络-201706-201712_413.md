# VMware Horizon的macOS客户端代码注入漏洞分析

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzIyMzE5NTQ3Ng==&mid=2650588224&idx=2&sn=1c4acd9f9d140681622405b8e152bf3d&chksm=f0299c7bc75e156de7274dddfd3fa9c28c76963cc37ca4d7f8f96924d57b3b8a284d65192d8f&scene=126&sessionid=1681370466#rd](http://mp.weixin.qq.com/s?__biz=MzIyMzE5NTQ3Ng==&mid=2650588224&idx=2&sn=1c4acd9f9d140681622405b8e152bf3d&chksm=f0299c7bc75e156de7274dddfd3fa9c28c76963cc37ca4d7f8f96924d57b3b8a284d65192d8f&scene=126&sessionid=1681370466#rd)

![](../Images/bd12d37e5b6d2b5b81389d88a9cef40a.png)

**本文我们将探讨如何通过VMware Horizon macOS客户端版本4.4.0 (5164329)中存在的代码注入漏洞获取本地root权限。在此文发布前我们已确认漏洞在最新版本中已被修复，该漏洞是在学习了解“Open VMware View Client Services” SUID机制后发现的。**

  

![](../Images/fae802ec806d8c0fc72405482da9c7ba.png)

该漏洞存在于Horizon内部的远程USB服务，且仅在键入管理凭证启动服务之后才能利用  

  

![](../Images/232159be79fe14ec8560dc06b5d02f84.png)

  

为了进一步研究，使用到Fireeye最新发布的Monitor.app应用程序，该程序主要用于macOS上的进程监听(procmon) 

  

![](../Images/777cc2199a05e6e813e4e5e783e7e55a.png)

从Monitor.app捕获到的结果，可以清楚得知services.sh被包装在Open VMware View Client Services之中。这样脚本文件的SUID位被忽略也就说得通了（参考Allow setuid on shell scripts）。

  

在仔细观察该脚本文件之后，辨识出如下截图中代码高亮部分或许就是代码注入漏洞的起点。尽管我对./vmware-usbarbitrator的内部工作原理不了解，但这些代码深深的吸引了大家的目光。作为一个非管理员用户，能够设置环境变量

  

VMWARE\_VIEW\_USBARBITRATOR\_LOG\_OPTIONS的内容（在之后的一个SUID执行脚本中会用到）

![](../Images/665c77b3a9b4217655223ae7f7d66955.png)

在仔细阅读命令行参数选项说明后，非常肯定我们是能够通过–kext参数加载一个自定义内核扩展。  

![](../Images/0febdf993543973d9f72cb1ece4fe7f7.png)

但接下来我们将面临2个问题：

  

> *   内核扩展仅在root : wheel权限下加载
>     
> *   此外，KEXTs必须有苹果公司的签名
>     

  

经过一系列思考，我们决定忽略第二个问题。因此，禁用了SIP

![](../Images/818072a41e480593963e2154840989ef.png)

接下来我们就着重关注第一个问题。为了成功加载一个内核扩展，该二进制文件必属于root : wheel。然而，对于一个普通用户来说，是无法在本地文件上设置该文件系统权限的。幸运的是，在这之前有花时间去了解Tools On Air文件系统的输入输出原理，所以清楚的知道我们只需利用NFS便能达到目的。NFS允许服务指定文件系统权限，即使是由一个普通用户进行挂载。知道的其他本地或者远程文件系统从某种程度上来讲，都会忽略root用户所属文件权限。我们的下一个动作即是引用一个远程文件夹随身携带的Kali Linux以利用NFS。

![](../Images/891f793374dc29e0288355296623590e.png)

使用Finder的“连接到服务器”功能进行挂载

![](../Images/b6a167107f55084998932f1911a2e8ed.png)

接着创建一个简单的KEXT

![](../Images/338f44970d484cef09e7aa9916698a90.png)

之后更新Info.plist文件以满足我们的需求（新增一个IOKitPersonalities字典），已经准备好了！

![](../Images/3959f291f21fb37d6c4c789ba9b4aae0.png)

通过将KEXT复制到NFS服务器，之后进行权限调整以满足root:wheel，至此我们便能够愉快的开始真正的利用了。

![](../Images/e860d67920463b504effdf4a8d885d3e.png)

  

在我们之前创建的KEXT中简单设置VMWARE\_VIEW\_USBARBITRATOR\_LOG\_OPTIONS环境变量，然后运行Open VMware View Client Services。现在能够成功加载了。

![](../Images/320337d902841df4570b8586806ee690.png)

## 解决方案

过滤或者清除环境变量VMWARE\_VIEW\_USBARBITRATOR\_LOG\_OPTIONS以及VMWARE\_VIEW\_USBD\_LOG\_OPTIONS

  

![](../Images/e8c1330a4ae95198ebdb17e4f3bb4cbb.png)
