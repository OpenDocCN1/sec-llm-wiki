# 前端JS攻击  

本节中的攻击旨在帮助您了解 JavaScript 在浏览器中的使用方式以及如何对其进行操作。攻击可以通过仅分析网络流量来执行，但这不是重点，而且可能会更难。

  
本节中的措施帮助您了解如何在浏览器中使用 JavaScript 以及如何取消进行攻击，通过分析网络流量来实现，这不是本章节的重点，而且可能要阻止进一步的推进。显然，这不是那么简单，每个级别工具不同的保护机制JavaScript的包含在网页必须分析然后被操纵绕过保护。

  
只需提交单词“成功”即可攻击成功，显然这并不是那么容易。一般语言都实现了不同的保护机制，页面中包含的 JavaScript 必须经过分析，然后才能绕过保护。

  

这里用DVWA的靶场来作为例子。

# 高的

高和中很相似，生成的令牌值的逻辑在另外的js文件中。和中不同的是，这里的JS代码是经过了重新的，就很明显，肯定不了解。  
访问`http://127.0.0.1/bachang/dvwa/vulnerabilities/javascript/source/high.js`，分类看外观。到经过混淆的JS代码：

![](../Images/521c897c031cfa9bcc6caec6e6619912.png)

  

那么这里就要用到JS解混淆的工具了大家可以到这里的github里下载项目：https://github.com/mindedsecurity/JStillery;也可以用基于这个JStillery的在线JS解混淆的工具：http://tool.yuanrenxue.com/deobfuscator。它所提供的功能是：把重制后的JS代码成我们可以看懂的JS代码。如图所示，我们复制再转后的JS代码就粘贴到里，点击尝试解重，然后成功了：

  

![](../Images/8bb56ae99b4792f464f2c4c52334076f.png)

  

解重后的JS代码代码如下：

```
var a = [
```

有个关键的部分是这里：

  

![](../Images/12f32e9959837c5826b0e914148e5682.png)

  

这里生成token的步骤是：

1、执行token\_part\_1("ABCD", 44)  
2、执行token\_part\_2("XX")(原始是延迟300ms的那个)  
3、点击按钮的token\_part\_3  
因为token\_part\_2(执行"XX") 有300执行时候执行了，所以token\_part\_1("ABCD", 44) 会被先，而token\_part\_3()则是和按钮的点击事件一起。  
所以我们在输入框成功后，再到输入输入中输入token\_part\_1("ABCD", 44)和token\_part\_2("XX")这两个函数就可以了，最后点击提交就执行token\_part\_3()。
