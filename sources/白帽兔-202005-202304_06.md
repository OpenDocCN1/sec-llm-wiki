**前言**

Nacos属于阿里巴巴的一个开源的项目,通过一组简单的特性集,Nacos能够帮助用户实现服务动态发现、服务配置、服务元数据及流量管理。

  

Nacos历史版本存在命令执行漏洞。

  

**漏洞影响范围**

  
![](../Images/fe6bfd679de6bc4f2989b72714412784.png)

版本：

2.2.x

2.1.x

2.0.x

1.5.x

  

**漏洞复现**

  
![](../Images/fe6bfd679de6bc4f2989b72714412784.png)

1.  首先启动一个nacos，服务访问地址为`http://127.0.0.1:8848`
    
2.  在nacos添加dataId为'test-server'，其余为默认的配置，内容如下:
    

```


server:
```

3.  启动一个使用了spring-cloud-starter-alibaba-nacos-config的服务，它的bootstrap.yml配置如下：
    

```









spring:
```

可以发现，服务在12345端口启动了

4.编写java文件（EvilScript.java）

```










































































import java.util.List;
```

5.编译java文件，并打包成jar

```




javac EvilScript.java
```

6.把得到的EvilScript.jar放到http可以下载到的地方，例如：

```

http://127.0.0.1:80/EvilScript.jar
```

7.  使用nacos的认证绕过漏洞`https://github.com/alibaba/nacos/issues/4593`创建账号，去修改dataId为test-server的yaml配置文件
    

```




server:
```

8.  此时可以看到，test-server这个服务会通过`http://127.0.0.1:80/EvilScript.jar`加载恶意jar并执行，导致服务端命令执行，创建了`/tmp/pwn`文件
