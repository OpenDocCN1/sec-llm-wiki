**旨在分享思路，不是分享exp然后批量getshell。**

  

首先渗透的起因是这样的。那时候我闲着无聊看看补天的主页，发现有人提交了XX公司XX漏洞，奖金RMBXX元（具体记不太清了）。

  

然后我就想去捡捡漏。。。貌似大家都喜欢这样？

  

百度搜索了一下那公司的名字，找到了他们公司的官网。

  

![](../Images/c0e60c31237a40ef4d5afc8f60da6ce5.png)

  

一下还看不出是什么CMS，一般这种公司展示的网站都是用CMS做的，不会自己找程序员写新的。

  

大多都是dede。

  

拿到这个站后，先看看他的URL。

  

![](../Images/35643d13bb6dc98c79ab41c6c6cac03b.png)

  

  

/news/index.php?c=show&id=xx  

  

他这里是比较普通的一个URL，也看不出什么，顺手测试下sql注入，发现不存在。。要是存在就没有下文了。

  

然后又简单看了看几个别的页面，没什么特殊的地方，功能也很少，就是展示下公司新闻。

  

这种情况就得掏出扫描器扫一下目录文件了。

  

扫了下，发现存在member目录。

  

![](../Images/df2d777a5abf9a534396d8a632d396f2.png)

  

  

然后思路就多了一条了。先注册试试。

  

网站也没有关闭注册，顺利注册登录。

  

![](../Images/e71a38150485abec17b2ab072e5bac5c.png)

  

登录后直接跳转到了主页，于是再访问member目录，成功进入会员中心。  

  

但是蛋疼得发现所有的功能都还不可用，是待审核会员，需要等待审核。。。

  

![](../Images/957039e3a061a0bc14de310497740652.png)

  

然后扫描器还扫到一个adminkey.php，访问发现是一个后台登陆页面，测了下注入也不行。

  

![](../Images/b2d336ba54c96898ef5c55543ee801fb.png)

  

  

到目前为止，虽然我没有挖到漏洞，但是废话了很多，顺带发现了一些信息。

  

这个网站是使用的XXCMS，然后根据后台页面的提示，这个CMS是XXX公司开发的。

  

貌似首页下面也有写技术支持：XXXX。

  

那么就有思路了，去下载这个CMS来审计一下看看有没有什么漏洞好利用的。

  

百度他们公司名字，发现没有提供这个CMS的下载，百度这个CMS，发现没有一点关于这个CMS的信息，全是其他杂七杂八的东西。

  

然后就想到这个可能不是一个开源的CMS。

  

那么思路就得变通一下，去寻找使用这个CMS的网站，找脆弱的拿到这个CMS的源码。

  

**那么具体怎么找呢？**

  

找这个网站上比较特别的地方，去搜，最好不要使用百度了，谷歌搜的更全。通过搜索:

  

"技术支持:XXXX"

inurl:/news/index.php?c=show&id=

采集到了一些应该是使用这个CMS的网站。

  

**然后又怎么快速获取源码呢？**

  

批量扫备份。我这里是只扫备份文件，很快就真找到了一个。

  

运气不错，如果没有找到的话，得费点功夫弄旁站什么的了，你们懂我的意思吧？

  

  

![](../Images/a0f5ab2484294c782170182e230c44e3.png)

  

下载备份文件：http://www.xxxxxx.com/wwwroot.rar，解压，打开工具开始审计。

  

  

![](../Images/6d220d328837143309e789c83fd68da7.png)

  

先看index.php里写的什么鬼东西。（实际上我当时直接就上法师工具自动审计，快速搜漏洞点的。

  

这里为了写的更明白点，就先假装是看index.php吧。

  

一般比较熟悉后，想快速定位漏洞，直接找敏感函数回溯就可以了。）

  

![](../Images/457489a8efd1fff3cf670e34320119a6.png)

  

看了index.php，马上知道这个CMS是使用了CI框架。

  

怎么知道的？看代码结构啊。

  

看不太懂？看第39行注释你总得懂了吧。  

  

然后就去看他的一些控制器的代码

  

![](../Images/034a905ff9fe35bea347eb8e19142c7c.png)

  

为什么这么做？  

  

这就是，不解释审计。

  

  

![](../Images/074af81a191e617287e3d4ba7e644d6f.png)

  

  

然后开始不解释审计：

  

读api.php

  

![](../Images/f63b9ea45e6a14627d4224c5e5d03333.png)

  

  

直接看公开的方法。

  

一路往下看。构造函数什么也没做，第二个方法调用了一个api\_template方法。

  

sublime快捷键ctrl+shift+f 搜索定位到定义处。

  

  

![](../Images/93a3bdcf35aa778aa8c0154deb5dbcaa.png)

  

好了，不用看了，不存在什么高危漏洞。

  

回到api.php，继续读下一个方法。

  

![](../Images/339a37c752f43f7e0fa2a72f60267ca7.png)

  

hits方法这里把获取到的内容强制转换成了整数型，不能注入。

  

desktop方法看注释就不用看了，跳过。

  

  

![](../Images/b2b570631a409277770c25d27e27ec9b.png)

  

  

test方法没用，不过当作这个CMS的指纹挺不错。

  

data方法先是判断get\['auth'\]是否等于SYS\_KEY常量。

  

这个常量我们可以先搜下看看是多少。

  

![](../Images/77e0731d0d69a895acb732403025e533.png)

  

这个常量就是 这个CMS的名字，应该不会 是随机生成的，也就是存在默认值。

  

接着data方法第121行，获取的get\['param'\]传入了list\_tag方法，搜索跟入。

  

![](../Images/e5ee2b347cc5eec38797a2c4bd7e9c65.png)

  

定义了几个数组，然后用空格分隔传入的参数，也就是get\['param'\]，放入到$params中。

  

那么现在这个$params就是可以控制的。

  

接着426行，foreach遍历它。接续看。

  

  

![](../Images/6d032aa9062e18f226815cc5d4d3c150.png)

  

用 ‘=’ 分割数组中的元素，放入到$var,$val变量。

  

然后经过一系列的判断，$var当作key，$val当作value赋值到$system或者$param或者$where。

  

那么现在这三个变量都是可以控制的了。

  

然后是替换掉$system\['order'\]中的非法字符。

  

再就进入switch语句。

  

![](../Images/f70e4d28f58602d0304783becbd6e149.png)

  

当$system\['action'\]是等于cache的时候：

  

把$param\['name'\]用 '.' 分割放到$\_name 和 $\_param变量里面。

  

然后把$\_name 和 $system\['site'\]传入\_cache\_var方法，跟进去看下吧。

  

![](../Images/7b70994b99161a28b43f324fcfdc5574.png)

  

如果$\_name等于某些值，就返回一些固定的值。

  

否则返回$\_name和$system\['site'\]传入ci->get\_cache方法的返回值。

  

然后回到list\_tag方法。

  

![](../Images/876335254b5127aecd68e68796de51ef.png)

  

判断$cache是否为空，是的话就会返回。如果想执行到后面的代码的话，就得让\_cache\_var方法返回值不是空。

  

前面分析了，如果$\_name等于某些值，\_cache\_var就会返回一些固定值。

  

接着，492行，$\_param传入\_get\_var方法，返回值就带入了eval函数。

  

如果\_get\_var的返回值可控的话，我们就可以通过控制$\_param变量来注入任意的php代码去执行。

  

跟入\_get\_var。

  

![](../Images/753f33d3e9f9efd738b54a6228967c60.png)

  

用 '.' 分隔了$param放到$array中，然后遍历$array，对$var进行简单判断，直接拼接到$string变量，然后返回$string。

  

这里可以发现，返回值$string我们还是可以控制部分，插入恶意php代码。

  

然后再一层层回溯上去，构建出POC去验证：

  

![](../Images/73dc9ec28610806de1ccb1744ef01e59.png)

  

  

成功执行phpinfo().然后我就拿到了目标站的权限。

  

这个漏洞至今还没有修复，所以我也不方便把这个CMS的名字说出来，全程打马了。
