碰到了一个对外宣传是否安全的站点，但实际测试下来并不安全。不过在这次获取权限的过程中还是有点曲折，记录下来并分享给大家。

**整个测试过程均在授权的情况下完成，漏洞详细已经提交并通告相关知情。**

****过程****

**1\. 进入**

https://xxx.edu.cn/a/login，使用弱口令进行登陆

  

### **2\. 寻找上传点**

进来后找到一处文件上传的地方进行测试

![](../Images/585a47eae5b42b69c0ab82fecb03c871.png)

  

前端对上传的文件类型做了初步校验，这里我们上传一个空文本后抓包

![](../Images/76d17f374bedb5e978fbf5770800fb37.png)

  

发现路径可以被操控，而且返回了绝对路径。

![](../Images/8fc2ada85fc88c728c44fb473f76960d.png)

  

尝试访问后发现不能被解析只能下载。

![](../Images/3409b44b4cb750967aedd7e1a03108de.png)

  

再次寻找上传点，发现有头像上传的地方。这种上传点一般都能被解析。

![](../Images/0ca282479d0af0f6d70854a010810af9.png)

  

上传正常图片

![](../Images/3d22379d8434bff587b6a71fe185d340.png)

  

返回了上传成功的提示，但没发现返回的地址。

![](../Images/df6e33bb3f8679ddd76f2be67ebdad24.png)

  

而后在个人资料出发现了图片地址

![](../Images/21a776907f293057a5b68f71bb840070.png)

  

我们再次尝试构造请求报文重发，这里直接将后缀改成 jsp 上传成功

![](../Images/54d5bfa8f10e62db0c7f3a32262203ca.png)

  

刷新个人信息，找到访问链接。发现仍然是只能下载。

![](../Images/fc5859904d7634171173113a96b35d14.png)

  

### **3\. 突破口**

![](../Images/e871e12b9ca98fe9d34050aee4be7f7e.png)

  

我在 Cookie 中发现 jeeplus 的字眼，尝试搜索 getshell 方法

![](../Images/eb300e4e014722f6c6e9b6caab6becdf.png)

  

发现早已有前辈做过代码审计。

  

#### **1）SQL注入**


  

更具已有的 poc 进行尝试 sqlmap 跑起来，\*号的地方是注入点。

![](../Images/8f2d9f3c8e9903e124c4707c60485828.png)

  

通过 sqlmap 跑出来是 oracle 数据库。尝试一些查询和提权无果放弃。注意，oracle 注入的 sql shell 只能做查询语句。

![](../Images/c026d9837e6abb4e254f5c7892b1746f.png)

  

#### **2）文件管理**

直接访问 https://xxx.edu.cn/a/sys/file 就能越权进入到文件管理页面

![](../Images/534d438027a02b66bea776d824e9cff3.png)

  

这个目录下面的文件都只能下载，我们对这里的文件上传、删除、下载都做了测试。

  

##### **a. 任意文件读取**

下载接口可以返回文件内容，存在任意文件读取。

![](../Images/3512306ffb83840372830a07082dbcde.png)

![](../Images/3bef65a8aa38de2784fd71703ab1d4aa.png)

  

##### **b.任意文件删除**

这里甚至可以直接删除文件夹

![](../Images/56963939e240e19be2c8d86dfac6bff5.png)![](../Images/85255e79dfacd71e9bc7729a0ad132ab.png)  

##### **c. 任意文件上传**

![](../Images/d130f39732b5135ee18d1865548b31d1.png)![](../Images/29b713f1bccf0497be8ffdf88294ea8d.png)

  

这里可以自定义上传路径，如果路径不存在则创建目录并上传。

  

#### **3）尝试上传文件到可解析目录**

我第一时间想到上传到 static 目录，因为这个目录是可以被直接访问的。

![](../Images/7aa7ab5b8bc3250b08199460905c89db.png)

  

然后尝试访问仍然是 404。

![](../Images/e1f59fc451692614652c9c7e3ef9bd0b.png)

  

这里就是我没有找到真确的路径。想去官网直接下载源码，点击下载后回要求注册，注册之后也没有发现哪里有下载源码的地方。

![](../Images/46359ba7306483d36897df784ed3243d.png)

  

没办法就去凌风云网盘搜了一下，发现存在历史的版本，我感觉差异应该不会那么大。

![](../Images/62300b5808fae3aa0c39dd35cec74b08.png)

  

挑了一个比较大文件的下载，解压后可以查看目录结构。

![](../Images/cf37fff92d28a002f73c5fe3c36ba74a.png)

  

看到有存放配置文件的地方，我想看看能不能通过读取配置来找到绝对路径。

![](../Images/88cb9aefa20a34607528ed59af764422.png)

  

结果还是路径不对。一番尝试后无果，突然想起来站点的目录还没扫过，直接 dirsearch 来一波。

![](../Images/75debd96360b04e76b03153864482dcb.png)

  

当我看到扫出来 web.xml 这些配置文件我就知道有戏了。

![](../Images/f16b6ba892f38b5890452e26867650d2.png)

  

在 web.xml 中没有发现东西，但是在 conf/server.xml 发现了站点的另一个路径，我觉得这就是前端访问的路径。

![](../Images/5656b642f2121a9730963a4c1f6decba.png)

  

通过任意文件接口尝试构造路径 C:\\tomcat\\webapps\\xxxx\\WEB-INF\\web.xml 发现有内容返回说明我找对了路径，然后发现了 404.jsp 存放的路径，对比我们之前拿到的源码发现我们成功找对了路径——上传文件到 webpage 这个目录绝对能解析。

![](../Images/f735365d56c51f362e856c3d794615c0.png)

  

尝试直接上传 webshell。

![](../Images/e6a20481da2ab92a9f27a890c1cd6913.png)

  

发现文件真实存在，但是没有返回东西，我用任意文件读取查看。

![](../Images/b60aa838f6671b588e475264173c6219.png)  

#### **4）免杀绕过WD检测**

发现可能存在waf，但我后面对waf做了识别发现是 apache generic，这个不至于拦截我传的。再用 nmap 对机器做识别发现是 window10，让我想起了被 windows Defender支配的恐惧，不过这里我们找个命令免杀马子上传即可，找了一番之后用了以前 hw 碰到的一个马子。

  

https://github.com/LandGrey/webshell-detect-bypass/blob/master/webshell/jsp/Runtime-reflect-cmd.jsp

![](../Images/363d567b2f823ede716d2ae127789d8a.png)

  

#### **5）上线 CS**

成功上传并执行命令，原本想通过 powershell 上线，但是尝试过不同的命令包括免杀命令都不行。

代理出来之后进入桌面，发现果然开启了 WD

![](../Images/1924c8aef928312b47541fda960b4453.png)

  

上机之后才知道，原来管理员把上传文件夹路径放到F盘，主体是C盘，估计就是怕内存不够吧。

![](../Images/e39cbd74724216002b70c1485d51c20b.png)

****总结****

碰到没有思路的站点就做好信息收集扩大攻击面。指纹识别、端口扫描、路径扫描都是老生常谈的了，这次还结合了公网网盘信息泄露的点，不然我还得继续猜路径。还有一点需要注意的是，测试的前提是**取得相关授权**。
