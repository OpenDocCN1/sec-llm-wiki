目标是一大学，在一次挖洞过程中遇到个sql注入，尝试进一步利用扩大危害，漏洞已报送平台进行了修复

#### sql注入getshell失败

在id处连续加两个单引号都报错，经过探测发现是数字型的注入且过滤了空格，这里可以用/\*\*/代替

![](../Images/f459008cadee00cb804fafdeabb7913a.png)

![](../Images/396a5c7e0af34306d06e36d9b3ba94e3.png)  

于是直接上sqlmap  

  

```
python sqlmap.py \-u url \--batch \--tamper\=space2comment.py –dbs

```

  

![](../Images/50c043c077616c28317e1f63b1e5832f.png)

  
发现是dba权限：  

```
python sqlmap.py \-u url \--batch \--tamper\=space2comment.py \--is\-dba

```

![](../Images/8bbaea9ccd41645f7d417067a7eab864.png)

试了很多方法找web路径

  
最后注意到操作系统是FreeBSD

  
无意中看到这个  

  

![](../Images/19624c4c5f03c184a4874cdfc65fc46b.png)

  

char(47)就是’/’，立马想到可以通过这个遍历目录、找路径  

  

![](../Images/a70eaeae64245cc4ebed4a84d0c5ed00.png)

  
通过从根目录开始逐层遍历，最终找到网站根目录：  

![](../Images/98b6ae6eac9dde77a69335dea334f3bf.png)

  
写入shell失败，转换成16进制规避单引号还是不行

但是这个注入可以读取服务器上的任意敏感文件（包括非web目录），危害巨大  

#### 从其它点继续尝试

读取sql注入处代码，发现并没有代码层面的过滤，explode() 函数把字符串打散为数组，这里以空格为分隔，取数组的第一个，变相地过滤了空格，把空格换成内联注释就能注入  

  

![](../Images/8c22f9d241960629f1e4301cf6721e6b.png)

  
根据泄露的数据库账号、密码尝试连接3306端口失败，估计绑定了本地ip  
继续遍历目录，发现了mysql的登陆界面  

![](../Images/75dc980ef4c6584958fbbdf83ba995ba.png)

登录之后却是空白界面，读取处理登录逻辑的代码发现登陆成功直接设置session但不跳转，登陆后直接访问首页就行

  
查一下secure\_file\_priv，发现是空值，并没有限制  

  

![](../Images/a135e0871be984d4f10e0f105f24c2cb.png)

  

尝试利用日志写入webshell，发现没有权限设置日志路径  

  

![](../Images/4a4c24254eccd5faa1bc4ff010630867.png)

![](../Images/1d7d06735e698f4a84c487d989731ff0.png)

  

找到了网站后台  

![](../Images/84c6dd972ece108e9e9ec35810d84b14.png)

  

数据库里面查到的账号和密码hash值

  
在线网站解密hash值得到明文

  
登录失败，读取一下源码  

  

![](../Images/07365981bedb70caa89248d112eb2f37.png)

![](../Images/b55d0096c3a3cd19913c7340a8b94ee0.png)

  
发现是加了盐的，于是加盐再解密得到正确密码

成功登陆后在人員資料管理新增处发现一个上传照片的地方  

![](../Images/7ec900895f30da86bc3cfc1fba59dbee.png)

  

但是只能上传图片文件  

  

![](../Images/97bcd8d5ea46d60da4891611ca247c19.png)

  

上传成功之后，突然想到了sql写shell失败是不是因为目录权限问题，网站限制了除上传目录外其它目录都不可写？  

  

于是尝试写入shell  

  

![](../Images/5f0c2202125263b4cece255366e53854.png)

成功，果然是目录写权限问题  

  

![](../Images/ebbcd81f01a12e3eb8147d72dfdc9ac4.png)

  
发现蚁剑连不上，估计waf拦截了流量。

  

看了一下蚁剑的流量加密，蚁剑流量有一个重要特征就是User-Agent为antSword/版本，另外使用了编码器的话还要将解码函数发过去，所以解码函数这里也是一个特征，需要自定义编码器和解码器。

  
修改antSword-master/modules/request.js和antSword-master/modules/update.js两个文件的User-Agent后成功连接，waf仅仅拦截了UA这一明显特征  

  

![](../Images/766e32408988c2849a506ad78ff29e6a.png)

  

反弹shell失败，nc是基于tcp/udp协议的，所以可能的原因有：反弹的命令不存在、禁止出站IP、禁止tcp协议出站端口

  
确认sh存在：  

  

![](../Images/e1e6963c45dbe2b8f0e58ccede909be9.png)

  

出站端口为访问外网，查询网络连接发现54454端口可以出站  

  

![](../Images/bd06836a97849b8a9afcee8e63591d87.png)

  

于是监听54454端口后成功反弹shell  

  

![](../Images/321dea6733f0050dcb7c8127796664b0.png)

  

提权失败。

  

服务器内核版本过高，无法利用内核漏洞提权，尝试计划任务、环境变量、和suid提权发现没有可以利用的地方，sudo提权也不行，第三方服务中udf提权发现插件目录不可写，几个文件权限也配置正常，也没有发现其它敏感信息泄露
