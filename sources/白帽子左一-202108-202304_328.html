随着WAF产品从

Dismap定位是一种资产发现和识别工具。

可快速识别web/tcp/udp等协议和指纹信息，定位资产类型，适用于内外网。

协助红队人员快速定位潜在风险资产信息，协助蓝队人员发现疑似易碎资产

Dismap拥有完整的指纹规则库，目前包括tcp/udp/tls协议指纹和4500+条web指纹规则，可以识别favicon、body、header等。规则库介绍位于RuleLab

扫描结果可以直接发送到vulmap（>=0.8）进行漏洞扫描。0.3版本改变了文本结果，增加了json文件结果，vulmap将支持>=1.0的链接


Run

Dismap 是适用于 Linux、MacOS 和 Windows 的二进制文件。去Release下载对应版本运行：

# Linux 或 MacOS zhzyker@debian: ~ $ chmod +x dismap-0.3-linux-amd64zhzyker@debian: ~ $ ./dismap-0.3-linux-amd64 -h
# Windows C: \U sers \z hzyker \D esktop > dismap-0.3-windows-amd64.exe -h

规则实验室


整个规则库是一个结构体，位于rule.go的 粗略格式：

规则：Name: name  /* 定义规则名称 */ Type: header | 身体| ico   /* 支持识别类型，header，body，ico可以是任意逻辑组合，ico是单独请求favicon.ico并计算MD5*/ Mode: and | or  /* 类型判断逻辑 */ Rule InBody: str   /* 指定响应正文中存在哪个str */ InHeader: str   /* 指定响应Header中存在哪个str */ InIcoMd5: str_md5   /* favicon.ico的MD5 * /网址：请求方法：GET | POST   /* 自定义请求方式，目前支持GET和POST */ ReqPath: str   /* 自定义请求web路径 */ ReqHeader: [] str   /* 自定义Http请求的header */ ReqBody : str   /* 自定义请求的body POST 请求 */

示例 1：
字符是否<flink-root></flink-root>存在于响应正文中
{ "Apahce Flink" , "body" , "" , InStr { "(<flink-root></flink-root>)" , "" , "" }, ReqHttp { "" , "" , nil , "" }},

示例 2：
自定义请求路径/myportal/control/main，判断自定义请求结果中是否有header字符和body字符
可以发现都支持正则表达式
{ "Apache OFBiz" , "body|header" , "or" , InStr { "(Apache OFBiz|apache.ofbiz)" , "(Set-Cookie: OFBiz.Visitor=(.*))" , "" }, ReqHttp { "GET" , "/myportal/control/main" , nil , "" }},

header、body、ico的逻辑关系可以随意组合，但不能重复组合：

Can: "body|header|ico", "or"or "body|header|ico", "or|and"or "body|ico", "and"Can't:"body|body", "or"不允许按类型指定重复组合，但可以通过InBody判断字符来实现："body", "", InStr{"(str1|str2)"
