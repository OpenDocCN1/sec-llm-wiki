Vulstudy是一个综合了当前比较多的漏洞靶场的docker整合环境，安装与搭建方便，不用自己再一个一个安装与搭建了，当然自己一步步搭建还是最好的，这样可以熟悉docker，linux和网站搭建的综合知识了。今天在这里记录一下，该环境搭建步骤。

一、升级centos7内核

由于最新的docker要求的linux内核的版本比centos7默认的内核版本高。需要升级linux内核。centos7.x默认内核版本为3.10.0-xxx。当前最新的linux内核为5.6.4

查看当前和可升级版本：

# yum list kernel

升级小版本：

#yum update kernel -y

重启并检查：

#reboot

#uname -r


升级大版本：
载入公钥：
#rpm --import https://www.elrepo.org/RPM-GPG-KEY-elrepo.org

升级安装ELRepo

#rpm -Uvh http://www.elrepo.org/elrepo-release-7.0-3.el7.elrepo.noarch.rpm

载入elrepo-kernel元数据：

#yum --disablerepo=\*--enablerepo=elrepo-kernel repolist

查看可用的rpm内核包：
# yum --disablerepo=\* --enablerepo=elrepo-kernel list kernel*

说明：

lt：long term support，长期支持版本；

ml：mainline，主线版本；

安装最新版本的kernel

#yum --disablerepo=\*--enablerepo=elrepo-kernel install kernel-ml.x86_64  -y

删除旧版本工具包：

#yum removekernel-tools-libs.x86_64 kernel-tools.x86_64 -y

安装新版本工具包：

#yum --disablerepo=\*--enablerepo=elrepo-kernel install kernel-ml-tools.x86_64  -y

查看内核插入顺序：
# awk -F \' '$1=="menuentry " {print i++ " : " $2}'/etc/grub2.cfg

说明：默认新内核是从头插入，默认启动顺序也是从0开始（当前顺序还未生效）

其中文件/etc/grub2.cfg 和 /boot/grub2/grub.cfg 内容一致。

查看当前实际启动顺序

# grub2-editenv list

设置默认启动

# grub2-set-default 0  //0代表当前第一行，也就是上面的5.6.4版本那一行内容

# grub2-editenv list

重启并检查

#reboot

#uname -r

二、安装docker和docker-compose

#yum update -y

卸载旧版本（如果安装过旧版本的话）

#yum remove dockerdocker-common docker-selinux docker-engine docer-io docker-compose

安装依赖软件包

yum-util 提供 yum-config-manager 功能， 另外两个是 devicemapper 驱动依赖

#yum install -y yum-utilsdevice-mapper-persistent-data lvm2

设置yum源

#yum-config-manager--add-repo https://download.docker.com/linux/centos/docker-ce.repo

查看所有仓库中所有docker 版本，并选择特定版本安装

#yum list docker-ce--showduplicates | sort -r

安装docker，这里不指定版本，会自动安装你的内核可以使用的最新的docker的版本。

#yum install  -y docker-ce docker-ce-cli containerd.io

设置开机启动并启动服务

#systemctl enable docker &&systemctl start docker

安装额外依赖包

#yum install epel-release

安装pip并升级pip到最新版本

#yum install -ypython-pip

#pip install --upgradepip

安装docker-compose

#pip installdocker-compose

Pip安装的过程中有时候会出现错误，可以按照以下错误及解决办法进行解决。

第一次报错(sudo pip install docker-compose时)

ERROR: jsonschema 3.2.0 has requirementsix>=1.11.0, but you'll have six 1.9.0 which is incompatible.

解决方法

sudo pip install six --user -U

第二次报错(sudo pip install docker-compose时)

ERROR: Cannot uninstall 'subprocess32'. It is adistutils installed project and thus we cannot accurately determine which>files belong to it which would lead to only a partial uninstall.

解决方法

# 搜索subprocess32-3.2.6-py2.7.egg-info文件

sudo find / -name *subpro*.egg-info

# 删除

rm -rf/usr/lib64/python2.7/site-packages/subprocess32-3.2.6-py2.7.egg-info

第三次报错(sudo pip install subprocess32 -U时)

configure: error: no acceptable C compilerfound in $PATH

解决方法

sudo yum install -y  gcc

第四次报错(sudo pip install subprocess32 -U时)

error: command 'gcc' failed with exit status 1

解决方法

# 安装openssl-devel

sudo yum install gcc libffi-devel python-developenssl-devel -y

第五次报错(sudo pip install docker-compose时)

RROR: Cannot uninstall 'requests'. It is adistutils installed project and thus we cannot accurately determine which files>belong to it which would lead to only a partial uninstall.

解决方法

# 搜索requests-2.6.0-py2.7.egg-info文件

sudo find / -name *requests*.egg-info

# 删除

   rm -rf/usr/lib/python2.7/site-packages/requests-2.6.0-py2.7.egg-info

三、安装漏洞靶场

下载github上docker文件

git clone https://github.com/c0ny1/vulstudy.git

单独运行一个漏洞靶场

cd vulstudy/DVWA

docker-compose up -d #启动容器

docker-compose stop #停止容器

同时运行所有漏洞平台


   cd vulstudy

   docker-compose up -d #启动容器

   docker-compose stop #停止容器

第一次启动容器后，会经过漫长的等待，直到出现如下提示时，访问linux的IP，就会看到vulstudy的页面了。

注意：拉取docker到本地时，要保证磁盘空间足够大。特别是使用虚拟机搭建的同学。上面的命令都是使用的root用户，如果你使用的非root用户执行命令，请自行在命令前添加sudo 命令
