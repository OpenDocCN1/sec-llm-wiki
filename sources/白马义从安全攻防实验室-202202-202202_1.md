## 证书和 HTTPS 流量

在审查可疑网络活动时，我们经常遇到加密流量。因为大多数网站都使用安全超文本传输协议 (HTTPS) 协议。但与大多数网站一样，各种类型的恶意软件也使用 HTTPS。从恶意软件活动中查看 pcaps 时，了解感染后流量中包含的内容非常有帮助。

可以使用基于文本的日志进行解密，该日志包含最初记录 pcap 时捕获的加密密钥数据。使用此密钥日志文件，我们可以解密 pcap 中的 HTTPS 活动并查看其内容。

HTTPS 本质上是一个包含 HTTP 流量的加密通信隧道。这些隧道首先使用安全套接字层 (SSL) 作为加密协议。今天，大多数 HTTPS 流量使用传输层安全性 (TLS)。

### HTTPS数字证书

要了解 Dridex 感染活动，我们还应该了解用于 HTTPS 流量的数字证书。

数字证书用于 HTTPS 流量的 SSL/TLS 加密。使用 HTTPS 查看网站时，Web 服务器会将证书发送到客户端的 Web 浏览器。此数字证书中的数据用于建立 HTTPS 连接。证书包含网站的公钥并确认网站的身份。

不同的证书颁发机构(CA) 可以为各种网站颁发数字证书。证书出售给商业网站的企业，而Let's Encrypt等一些证书颁发机构免费提供证书。

可以从 Wireshark 中的 HTTPS 流量中查看证书信息。我们将重点关注以下两个部分：

*   有关 CA 的颁发者数据。
*   关于网站的主题数据。

颁发者数据显示颁发数字证书的 CA。主题数据验证网站的身份。图 8 显示了如何从www.paloaltonetworks.com查找 HTTPS 流量的证书颁发者和主题数据。

## Dridex感染活动的流量分析

Dridex 感染流量由两部分组成：

*   初始感染活动。
*   感染后 C2 流量。

当受害者从电子邮件链接下载恶意文件时，就会发生初始感染活动。初始感染活动还包括加载 Dridex 安装程序的恶意文件。在某些情况下，您可能没有初始下载，因为恶意文件是电子邮件的附件。在其他情况下，您可能看不到加载 Dridex 安装程序，因为初始文件本身就是一个安装程序。在许多情况下，此活动通过 HTTPS 进行，因此我们不会看到任何 URL，而只会看到一个域名。

## 总结

这三个示例应该可以很好地了解 Dridex HTTPS C2 流量的证书颁发者数据是什么样的。这些模式与许多其他恶意软件系列不同，但它们有点类似于来自 HTTPS C2 Qakbot网络流量的证书颁发者数据。但是，对于 Qakbot，stateOrProvinceName始终是两个字母的值，并且LocalityName由随机字符组成。使用 Dridex，stateOrProvinceName由随机字符组成，LocalityName是用于countryName的任何国家的首都。

本文介绍了如何从具有 Dridex 网络流量的 pcap 中识别 Dridex 活动。我们审查三次 Dridex 感染 pcap，发现来自感染后 C2 流量的证书颁发者数据有相似之处。证书颁发者数据是识别 Dridex 感染的关键，因为这些模式似乎是 Dridex 独有的。
