背景

Spring-security-oauth2是spring提供的用于授权服务的组件，官方在5月8日更新了2.3.3，而这个版本修复了一个新的RCE（CVE-2018-1260），某些官方默认注解使用Spel表达式解析用户输入可能会导致远程命令执行。

  

  

  

  

**1**

  

**漏洞触发**

  

搭建spring-security-oauth2测试demo，然后访问localhost:8080/oauth/authorize?client\_id=&response\_type=&redirect\_uri=&scope=payload

可以在eclipse中发现：

![](../Images/5596bbdb2f8df2d4347e0991a89c30fe.png)

成功弹出三次计算器！

  

  

**2**  

  

**补丁分析**

通过beyond-compare对比2.3.3和2.3.2可以发现，官方删除了org/springframework/security/oauth2/provider/spelView.java:

![](../Images/2111e30d24b50ce6e56f04194bc0f4f9.png)

  

spelView.java中的构造函数SpelView中引入了spel表达式：

  

private final SpelExpressionParser parser = newSpelExpressionParser();

        publicSpelView(String template) {

                          this.template= template;

                          this.prefix= new RandomValueStringGenerator().generate() + "{";

                          this.context.addPropertyAccessor(newMapAccessor());

                          this.resolver= new PlaceholderResolver() {

                                            publicString resolvePlaceholder(String name) {

                                                              Expression expression = parser.parseExpression(name);

                                                              Objectvalue = expression.getValue(context);

                                                              returnvalue == null ? null : value.toString();

                                            }

                          };

        }

  

代码中直接调用SpelExpressionParser.parseExpression()函数解析name，反向查找调用spelView()地方，可以发现：

![](../Images/6dd894b11084236d6d15b0f77d5aca5e.png)

  

 官方注解/oauth/confirm\_access中向SpelView中传入了参数template，而template则调用createTemplate函数产生，继续跟进：

   

![](../Images/e9d03f18aa854987459b4b90d58a18f2.png)

在createTemplate中，首先检测model中是否包含scope和request中获取属性scopes是否为空，调试发现scopes的值为{scope.${Tpayload}=false}，然后会调用createScopes函数，继续跟进：

 

![](../Images/36530b5f7e4c20752ec8a18a079b5145.png)

TEMPLATE和SCOPE为官方设定模板：

![](../Images/1c6c639b4c887ceec612eb2dd9ff05c2.png)

  

使用用户输入scope替换掉官方scope，最终template被传入spelVIew构造函数中，name字段被当作spel表达式解析执行，因此最终会解析三次，弹出三次计算器。

漏洞执行链为：

![](../Images/aa50f2c6fa7a0bbe77516b13456c5dd4.png)

  

  

    注：本漏洞触发要求服务器为权限认证服务器，且使用官方默认confirm\_access，同时未指定scope。

  

**3**  

  

**修复建议**

  

官方建议2.3.x更新到2.3.3，2.2.x更新到2.2.2，2.1.x更新到2.1.2，2.0.x更新到2.0.15。在官方更新中，删除了SpelVIew（简单粗暴），同时修改了org\\springframework\\security\\oauth2\\provider\\endpoint\\WhitelabelApprovalEndpoint.java文件中的大部分函数实现，将模板解析彻底修改为动态页面解析，从而避免模板注入：

![](../Images/73861c066ef127dc1aac807af233983c.png)

因此开发者如果不希望进行版本更新，也可以直接自定义/oauth/confirm\_access注解，可以效仿官方补丁动态解析页面内容，而不是用模板解析。
