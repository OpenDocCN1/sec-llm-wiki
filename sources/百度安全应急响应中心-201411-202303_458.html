一、敏感信息泄漏

1.1 Web服务器列目录漏洞

假设你使用的是apache服务器，那么你有两种方法补上这个漏洞，第一种方法是

<Directory "/home/work/kr/kr">Options Indexes FollowSymLinksAllowOverride NoneOrder allow,denydeny from all</Directory>

这种方法的思路是阻止所有人对目录的遍历。

第二种方法是：

<Directory "/home/work/kr/kr ">Options -Indexes -MultiViews FollowSymLinksAllowOverride NoneOrder allow,denyAllow from all</Directory>

-Indexes 表示阻止列目录，-MultiViews表示禁止隐含的模式匹配（比如将index自动转成index.html）


1.2 敏感文件信息泄漏

什么才算是敏感信息？凡是泄漏之后可能会对网站的正常运营造成风险，或者可能造成网站和网站用户的切身利益受到损害的信息，都算是敏感信息。比如log文件、配置文件、数据库文件或者其他代码文件，都是敏感信息，授权访问的范围一定要严格遵循最小权限原则。因为一旦被一些不良居心的用户恶意利用，可能反推出程序逻辑，甚至是用户密码。

作为网站的经营者，你可能会觉得这有些不可思议，但在黑客和白帽子的眼里，这是基本的常识。比如log文件中可能包含用户名信息，黑客就省去了猜用户名这一步。

那么如何修补这个漏洞呢？和上面一条的配置方法差不多，只要deny all，就行了。

举个例子，假设你使用的是nginx，PHP的Yii框架（并且你使用了默认的目录结构），那么你需要将protected目录禁止访问（里面包含代码和日志）。

location~/protected{denyall;}

总之，任何后端代码文件、日志、配置、以及任何泄漏之后可能给网站和网站用户带来损失的内容，都要严格保密，不能被泄漏。能够被他人获取到的敏感信息越少，网站就越安全。


现在的框架，大多会建立public目录，将服务器的根目录配置在这里，就不存在这个问题。


以下的安全问题和这个如出一辙：

  1. 敏感文件信息泄漏

  2. 日志文件信息泄漏

  3. htaccess文件信息泄漏

  4. 备份文件信息泄漏

  5. phpinfo文件信息泄漏

  6. SVN版本控制信息泄漏

  7. CGI文件泄漏

  8. .DS_Store敏感文件信息泄漏

  9. git文件敏感信息泄漏

  10. 数据库文件信息泄漏

对于网站的安全问题，你给它几分关心，它就有几分安全。

第4条和第7条。很多人都喜欢用版本管理工具部署代码，这无可厚非，可是不要忘记把.svn 和 .git文件的权限关掉。要知道这里面可是有网站的整个源码。一旦黑客获取了这些源代码，黑掉你的网站就真的是小菜一碟了。

很多人不明白第6条这个问题的严重性。.DS_Store是mac系统里面用来做当前文件夹预览的数据库文件。里面可能含有文本文件前几十行，其严重性几乎和直接暴露代码差不多。


1.3 服务器异常信息泄漏

我们经常会看到 Java或者.Net的暴站信息，这种信息也是敏感信息（比如会暴露部署位置等等）。请配置对应的框架，使之隐藏相关报错。但是在日志中请记录下来，以便日后分析。

以下问题都是这个方面的问题。

  1. SQL Server异常信息泄漏

  2. thinkphp框架异常信息泄漏

  3. struts框架异常信息泄漏

  4. ci框架异常信息泄漏


其中thinkphp算是大家很常用的框架了，解决方案如下：

如果不想让用户看到具体的错误信息，可以设置关闭错误信息的显示并设置统一的错误提示信息，例如：

'SHOW_ERROR_MSG' =>false,'ERROR_MESSAGE' =>'发生错误！'

其他的框架请自行搜索解决方案。


1.4 请升级！

有些是因为漏洞引发的安全事件，是因为网站漏洞没有及时打补丁所导致的，比如：

  1. fckeditor敏感文件

  2. Struts命令执行漏洞

如果怕兼容问题，大版本可以不升级，但是小版本请尽快升级。与已知有漏洞的版本相比，未知漏洞的版本可以防住更多的黑客。


1.5 apache服务器统计信息泄漏

通过请求/server-status可获取关于Apache服务器配置的敏感信息。

如果黑客知道你的服务器版本，会对他的攻击有帮助吗？

当然有！如果黑客知道你的Apache < 1.3.24, 2.0.* < 2.0.34 并且是windows版，那么他试试DOS批文件可以执行任意命令漏洞。

所以要使得黑客不能访问相关信息，必须将统计信息关掉（也就上将下面这行注释掉）

LoadModule status_module modules/mod_status.so

除此之外，最好关掉版本信息。也就是在http返回头中的版本信息

Nginx

修改nginx配置文件nginx.conf中的server_tokens为off。

Apache

修改httpd.conf

ServerSignature Off
ServerTokens ProductOnly

此外，PHP也能暴露自己的版本，比如http://www.snnu.edu.cn/?=PHPE9568F34-D428-11d2-A769-00AA001ACF42中就可以看到PHP的logo，这可以用来判断大致的版本，当然，主要是能用来判断是否使用了PHP。想要关闭它很简单，你可以在php.ini中配置即可：

expose_php = Off # 也能关掉 X-Powered-By 标记

一般而言，通过隐藏的手段提高安全性的做法被认为是作用不大。但某些情况下，尽可能多地增加一份安全性都是值得的。

三、文件包含漏洞

这种漏洞，是因为PHP（或者其他脚本语言）在动态执行（include）文件时，没有很好的检查文件名，黑客可以利用这个来执行恶意文件。

那么怎样来避免呢？答案是：最好不要动态拼接文件名，如需拼接，要仔细检查代码，不要给黑客留机会。

如果你不是开发者，那么只要升级自己的网站到最新版本就行了。
