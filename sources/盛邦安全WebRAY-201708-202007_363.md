2018年9月26日，WebRAY安全研究中心在针对不同客户的Web应用进行安全监测时，发现有安全人员放出EXP表示Joomla多组件存在SQL注入漏洞，经检测，大量用户受到该类漏洞的影响。

  

经过分析，发现Joomla多组件存在SQL注入漏洞，通过把SQL命令插入到Web表单提交或输入域名或页面请求的查询字符串,最终达到欺骗服务器执行恶意的SQL命令。

**1、漏洞概述**

  

漏洞简述：2018年9月25日，PHP平台发布了漏洞编号分别为CVE-2018-17394、CVE-2018-17380、CVE-2018-17397、CVE-2018-17376、CVE-2018-17383、CVE-2018-17384、CVE-2018-17385、CVE-2018-17382、CVE-2018-17377、CVE-2018-17378、CVE-2018-17375、CVE-2018-17379的安全漏洞，漏洞危害程度为高等（higher）。SQL注入攻击是攻击者通过在应用程序中预先定义好的查询语句结尾加上额外的SQL语句元素，欺骗数据库服务器执行非授权的任意查询。会导致网页被篡改、数据被篡改、核心数据被窃取、数据库所在服务器被攻击变成傀儡主机等后果。

  

**2、漏洞基本信息**

  

**产生原因**

未对用户输入进行严格过滤

**影响范围**

Joomla Component Timetable Schedule 3.6.8

Joomla Component Article Factory Manager 4.3.9

Joomla Component AlphaIndex Dictionaries 1.0

Joomla Component Reverse Auction Factory 4.3.8

Joomla Component Collection Factory 4.1.9

Joomla Component Swap Factory 2.2.1

Joomla Component eXtroForms 2.1.5

Joomla Component Jobs Factory 2.0.4

Joomla Component Questions 1.4.3

Joomla Component Penny Auction Factory 2.0.4

Joomla Component Music Collection 3.0.3

Joomla Component Raffle Factory 3.5.2

Joomla Component Dutch Auction Factory 2.0.2

Joomla Component Responsive Portfolio 1.6.1

**漏洞ID**

CVE-2018-17394、CVE-2018-17380

CVE-2018-17397、CVE-2018-17376

CVE-2018-17383、CVE-2018-17384

CVE-2018-17385、CVE-2018-17382

CVE-2018-17377、CVE-2018-17378

CVE-2018-17375、CVE-2018-17379

  

**3、漏洞等级**

  

WebRAY安全研究中心风险评级：高危

  

**4、修复建议**

  

1.在网页代码中需要对用户输入的数据进行严格过滤。

2.进行组件的升级。

3.不要使用管理员权限的数据库连接，为每个应用使用单独的权限有限的数据库连接。

4.不要把机密信息直接存放，将密码和敏感的信息进行加密处理。

5.应用的异常信息应该给出尽可能少的提示，最好使用自定义的错误信息对原始错误信息进行包装。
