# 兵临城下丨红蓝日记⑤：“软柿子”不一定好捏

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzAwNTAxMjUwNw==&mid=2650266461&idx=1&sn=6da5ae82d1b2c751e44bf0a8a3175cb4&chksm=83205629b457df3f0ced8ff77206e49c27841c42702fafd677b32fb12c9e4419dbabd491bbac&scene=126&sessionid=1681374541#rd](http://mp.weixin.qq.com/s?__biz=MzAwNTAxMjUwNw==&mid=2650266461&idx=1&sn=6da5ae82d1b2c751e44bf0a8a3175cb4&chksm=83205629b457df3f0ced8ff77206e49c27841c42702fafd677b32fb12c9e4419dbabd491bbac&scene=126&sessionid=1681374541#rd)

兵法曰：“知己知彼，百战不殆”，网络安全攻防演习中，有人想要“知己”，盘点自身网络资产“家底”，排查安全漏洞和风险，防患于未然；有人更想要“知彼”，从看似杂乱无章的信息中抓取到蛛丝马迹，找到一击即中的方法。

  
  

**小红日记**

  
  
  

**3月18日 星期四，小雨转多云**

  
  
![](../Images/68f6f4a942872e47f53f8e1df581b17e.png)

  

攻防演练的第一天，拿到目标后我从众多的目标中找出一个看上去像是软柿子的目标，通过收集企业组织架构和whois反查域名加ICP备案反查域名等方式找到了很多目标的一级域名，然后开始收集子域名资产，经过一波CDN探测判断后发现大部分资产都存在CDN，难搞啊！但是通过域名证书查询到了一些可直接访问的IP资产，拿去扫了下C段，发现目标有一个ThinkPHP的站点。  
  
![](../Images/e697cf9ec2cdbe08ed56d3736dc4dd32.png)  
访问一下，url输入个不存在的路径，让它报错

  

![](../Images/e4bc570d48a284108585381bfd05ebad.png)

目标的版本为ThinkPHP-5.0.22，5.x的，我记得有RCE漏洞啊？直接上神器扫一下，发现漏洞确实存在。  
![](../Images/70746cb4f249ea6e97ada0bf0189678b.png)

![](../Images/c6ae6ebe437a394a245a81fd1d353426.png)

  

然后传个webshell，方便操作嘿嘿……

  

![](../Images/395a1212999330f27f274e1ee88cb6ce.png)

  

但是发现总是上传不上去，那怎么办呢？直接反弹个shell回来。

  

![](../Images/e6513f873c46d1ed22e997dad09929b7.png)

  
反弹shell还是不舒服，上传文件费劲，还是下载个webshell，为了方便内网移动我再上传的C&C马来做权限维持和横向，用shellcode分离免杀上传个加载器上去。

  

![](../Images/a0bee8f82eec6cda8879d6e62255e255.png)

  

![](../Images/531ab30d3164652c4d6716f76398dfa3.png)

  

先运行下mimikatz知道了本机的明文密码

  

![](../Images/99ad97b0b24491eb75da9d83f24d54dd.png)

  

然后看下C段有哪些存活主机

  

![](../Images/5b4ba8007cf65d8690dcbc46ee6f8a18.png)

  

扫描完后转到target视图

  

![](../Images/001855526e02d0cc9e5dc3c3685e2c00.png)

  

发现117这台机器开了个SSH服务，是台Linux，用nmaps探测下全端口看下还有哪些服务

  

![](../Images/ce08204e14f1bef029a9c502986ca905.png)

  

把刚才得到的明文密码加入弱口令字典跑一波SSH和MySQL弱口令，但是并没有什么结果……今天也算是个开门红了，删除上传的111.bat和加载器及Webshell跑路了，明天继续。

（加载器把C&C马注入到了资源管理器中，只要目标服务器不关机，权限就不会掉）

  
  
  

**小蓝日记**

  
  
  

**3月18日 星期四，小雨转多云**

  
  
![](../Images/e8575186870e642def68cc68429b7fd6.png)

  

今天是攻防演练第一天，先给内网上个低交互蜜罐，防止被打进来都不知道。

  

![](../Images/07d03421d138f3517693942ac8375a99.png)

  

修改下默认配置，登录看看

  

![](../Images/04126a0254debb1b7b550680a78c1bc9.png)

  

N的小时之后，看下我的蜜罐有没有情况，吓一跳居然有很多上钩的（攻击者进内网了）

  

![](../Images/c879ba024fa5831c8ca123512e84d1e7.png)

  

上钩一堆MySQL蜜罐，应该是攻击者在进行弱口令扫描，看这个IP是我们的外部Web服务器，赶紧登上这台服务器，中间件是nginx，把Web日志access.log下载下来分析。

  

![](../Images/a484285fbb9fb517626e1498646defc3.png)

  

发现这个IP（模拟攻击者IP)访问了nb.php这个文件，但是我们网站根目录下没这个文件，猜测这就是攻击者的Webshell，但是已经被删除了……再接着往上翻日志，看攻击者怎么进来的。

  

![](../Images/6094eed5845c631854980d19a3597a68.png)

  

![](../Images/fa2d9d9663fda86088ffd9253cc6545a.png)

  

重点在这里，nb.php是这个时候创建的，逆向推理发现攻击者是先把111.txt改名为111.bat，然后运行了111.bat，然后就出现了nb.php这个文件。再接着向上翻看日志，发现了下边这条日志：

  

![](../Images/495fcb0190a45fb4a85cea790a269da7.png)

  

用powershell 从攻击者的VPS下载了一个脚本输出到了111.txt中，百度搜了下这个脚本的名字发现是个powershell反弹shell的脚本，所以攻击者应该是先反弹了shell再写了nb.php这个webshell。  
  
审计系统日志点击“开始→运行”，输入eventvwr，打开系统日志，使用事件ID-4624过滤最近12小时登录成功的事件。

  

| **事件ID** || **说明** |
| --- | --- |
| 4624 || 登录成功 |
| 4625 || 登录失败 |
| 4634 || 注销成功 |
| 4647 || 用户启动的注销 |
| 4672 || 使用超级用户（如管理员）进行登录 |
| 4720 || 创建用户 |

  

发现了攻击者的登录日志，截图取证：

  

![](../Images/72ac1080aa730348cfd067361e7bc74d.png)

  

溯源攻击者，去威胁情报平台查询一下这个IP

  

![](../Images/73844931493f48163eba67dce415f77e.png)

  

发现这是一台恶意的VPS云主机，不是代理IP，而是攻击者真实的IP。去这个云主机的运营商网站通过密码找回功能溯源攻击者。

  

![](../Images/10c963a361df1ec408bcdb815576248b.png)

  

![](../Images/6b0d2752e2aeccd21d78f412ec7d5a08.png)

可以得到一个中间4位打码的手机号码。  

  

  

  

**经验总结**

  
  
  
  

  

1、首先知道部署低交互蜜罐作为最后的防线，这点值得表扬；  

2、但自身资产梳理不完善，导致被轻易打入内网；

3、可惜没有发现攻击者留下做权限维持的C&C马。

网络安全攻防就如同打仗，任何一个微小的细节都可能决定最终的成败。所谓千里之堤毁于蚁穴，我们平时的网络安全工作可能看起来很细碎繁琐，都是一些不起眼的“小事”，但往往巨大的风险就隐藏在这些被忽视的小问题中。所以，做好每个环节的防护，清楚地感知自己的安全状态和潜在风险，才能在真正的“风暴”来临时经得住考验。
