由在 VM 里安装 Windows Server 2003 Enterprise 时安装 vm tools 导致的蓝屏牵出的内核 bug 分析。


环境：VMware Workstation 12 Pro 12.5.2 build-4638234，其中 vmhgfs.sys 文件版本为10.0.0.0 


虚拟机系统：Windows Server 2003 Enterprise，其中 nt 的文件版本为 5.2.3790.0 


前天用 VM 安装 win server 2003 时，在安装 vm tools 时发生蓝屏，很是郁闷，而在之前安装 win server 2003 sp1 和 win server 2003 sp2 时安装 vm tools 时都没有发生蓝屏，好奇心驱使我找到蓝屏原因和解决蓝屏的办法，过程简述如下： 


安装 win server 2003 时，由于 VM 在进行简易安装，它会自动进行安装 vm tools，过了一会儿出现一个错误提示：没找到 tpvmmon.dll，我并没有理睬这个错误，而是继续安装vm tools，没过多久就出现蓝屏，多次重复还是蓝屏，于是就下定决心深入分析一下。正常启动后，由于没能成功安装 vm tools，导致不能全屏，也不能直接在主机和虚拟机之间拖拽文件，很别扭，这时想到了 windbg 这个好伙伴（毕竟自己接触内核开发也有一年多的时间），通过调试来一探究竟。

从以上的信息可以看出，蓝屏的原因是在 vmhgfs 中调用 MmGetSystemRoutineAddress 函数时导致的蓝屏，查 MSDN 可知：


MmGetSystemRoutineAddress 函数类似于 r3 的 GetProcAddress，不过只能得到 nt 和 hal 这两个内核模块的导出函数的地址。


执行 dtnt!_UNICODE_STRING 0xf78a6440 ，发现 vmhgfs 是 想 得 到CcGetFileObjectFromSectionPtrsRef 这个函数的地址，通过查 MSDN 可知，这个函数是在 Windows Vista 及 以 后 os 的 nt 中 才 有 的 导 出 函 数 。 


用 IDA 逆 向 nt 可 知 ，MmGetSystemRoutineAddress 会从 PsLoadedModuleList 这个全局变量里找到已经加载的内核模块链表，从中找到 nt 和 hal 的基地址；


然后可以发现 MmGetSystemRoutineAddress 其实调用了 MiFindExportedRoutineByName 函数获取导出函数地址，该函数第一个参数为内核模块的基地址，第二个参数类型为 PANSI_STRING，由 RtlUnicodeStringToAnsiString 转换MmGetSystemRoutineAddress 的类型为 PUNICODE_STRING 而 来 ；


MiFindExportedRoutineByName 函数先定位到 PE 文件的导出表，从而利用折半查找去获得想要获取的导出函数的地址，而蓝屏原因正好就出在这个折半查找的实现里。


从这个函数的实现可以侧面证明 nt 以及 hal 的导出表里导出函数名是有序排列的，从我查看 hal 导出表的情况来看是按升序排列的。折半查找的原理：必须要求待查表为有序表。首先，假设表中元素是按升序排列，将表中间位置记录的关键字与查找关键字比较，如果两者相等，则查找成功；否则利用中间位置记录将表分成前、后两个子表，如果中间位置记录的关键字大于查找关键字，则进一步查找前一子表，否则进一步查找后一子表。重复以上过程，直到找到满足条件的记录，使查找成功，或直到子表不存在为止，此时查找不成功。


从图 2 和图 3 可以看出，是在 hal模块中寻找导出函数地址时引发的蓝屏。

从 图 7 可 知 hal 模块所有导出函数 名 中最小的是 "ExAcquireFastMutex" ， 因此”CcGetFileObjectFromSectionPtrsRef”字符串小于所有 hal 模块导出函数名，这就是发现直到蓝屏时，都会走到图 6 中红框里（也就是走到前面折半查找原理中提到的查找前一子表的分支里）的原因，而此时 cmp 指令的第二个操作数仍然是 0，此时重点来了，jnb 指令为无符号跳转，因此 jnb 跳转的条件恒为真，这就导致循环一直不停地进行下去，直到访问内存错误而导致蓝屏。


解决蓝屏的办法为：在调试器中将无符号跳转的 jnb(jae)指令改为有符号跳转的 jnl (jge)指令，让其成功安装好 vm tools，把 vmhgfs.sys 驱动对应的服务启动类型设置为 3 或者 4，或者按照下面对 vmhgfs.sys 文件打补丁的方式解决（32 位系统，没有 DSE，很好办。）： 


重新启动再次调试，先执行 sxe ld: vmhgfs，当系统加载 vnhgfs.sys 时中断到 windbg 后，再执行 ub vmhgfs+0x610b，得到 vmhgfs.sys 里调用 MmGetSystemRoutineAddress 时 call 指令的地址 vmhgfs+0x6109，并对该指令地址下断点，如图 8 所示： 

图 8 


到这里，解决蓝屏的方法已经出现，那就是对 vmhgfs.sys 驱动文件打静态补丁，找到 vmhgfs+0x6108 对应的文件偏移，把偏移处的前 3 个字节 0x50 0xff 0xd7 改为 0x33 0xc00x90（对应 xor eax,eax;nop），然后替换原始的 vmhgfs.sys，经试验，蓝屏问题可以被解决。
