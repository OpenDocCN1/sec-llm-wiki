看雪版主&评委 netwind 点评

本题通过父进程调试子进程的方式进行，起到干扰破解者的作用。子进程和父进程之间通过 INT3 异常事件进行交互，主进程会对子进程的一些指令和数据进行了剥离，这样使得破解者不能轻易地 dump 子进程。父进程对用户输入的 sn 进行了变形得到 sn1，再将 sn1 交给子进程得到 sn2，再回到父进程校验 sn2，满足算法就由父进程弹框显示成功。先 dump 出子进程里的算法相关代码并修复，再分析出主进程里对 sn 进行的加密算法就可以破解此题。


作者简介

驿站过客，科锐 22 期毕业学员

 

设计思路

利用调试器调试另外被调试进程，在被调试进程申请空间，把算法写到该空间上运行

故意制造了 int3 断点，让调试器得到控制权，把算法中原本的加法变减法。

在最后一次断点异常的时候验证值是否正确。

 

破解思路

1、把注入被调试进程那段代码 dump 出来；


2、找到调试进程处理断点异常的函数，分析函数在处理断点异常的时候动了什么手脚；


3、把 dump 出来的代码修复好，再加上在输入密码后的那次运算，结果就出来了。


下面选择了分析者 brichfire 的详细分析

1、流程分析

分析得到程序的工作流程如下图

 

                                           

发现验证程序使用双进程，通过 scanf 获取输入，参数 %21s 最多获取 21 个字符，然后将输入载入 sub_401060 函数进行运算，得到一串 21 字符的密文，接下来将密文写入子进程，此外还往子进程写入了其它数据，可能包括一些程序代码，子进程执行相关代码对密文进行第二次加密，之后父进程读取子进程运算结果，进行校验匹配。

2、发现致命缺陷

双进程的使用给分析带来了不小的挑战，而且子进程的加密运算并不明朗，当输入的验证码不正确时其并不会触发加密运算，然而此题有个致命的缺陷，就是对输入进行编码加密的函数sub_401060，该函数的有效输入其实只有第一个字符，后续的内存区域会被第一个字符的一序列运算输出覆盖。流程图中已用红色标注出来，可能是作者实现时的失误。既然只需要一个字符，那么就可以穷举了，大小写字母和数字总共62个字符，试出来结果是字符‘k’。

3、抽丝剥解

虽然得出了验证码，但对其原理还不清晰，往下继续分析。


静态分析发现 Broiler.exe 就是一个无限循环的Sleep，其奥秘其实还在父进程 CrackMe。

起初输入的验证码不正确，发现WriteProcessMemory 和 ReadProcessMemory 的数据是一致的，去求解满足条件的输入发现无解。后来输入正确验证码才发现这两者不一致，子进程内进行了另外的运算。


是什么因素主导了这个运算过程呢？为何有些输入写入和读出内存的内容是一样的，而有些是不一样的? 后续的分析发现其实是因为对于某些输入字符，加密输出结果是与输入一致的，而并非没有进行运算。


A、首先是布局第二次加密运算的代码和输入数据


父进程调用了 5 次 WriteProcessMemory 布局代码。

5 次跨进程写入的内存地址如下所示，地址仅是一次测试的地址，是可变的，本分析报告以此为例。

第一次往 0x150000 地址写入了 21 个第一次加密后的字符；


第二次往 0x160000 地址写入 1 字节，是 push 指令操作码；


第三次往 0x160001 地址写入 4 字节，是内容是第一次写入地址的值，即 0x150000, 与上述构成一条 push 0x150000 指令，看来是将第一次加密后的字符串地址作为参数传递了；

第四次往 0x160005 地址写入 308 个字节，内容是一堆可执行指令，用来对数据进行第二次加密运算。

第五次是子进程触发 int 3 中断后触发的，计数器统计发现第一次进入了本流程，而第二次则会走另外的分支，WriteProcessMemory往0x1600d1 地址写入 2 个字节，内容除了 nop 指令的机器码，将 int 3 指令替换成了 nop 指令外，还将原本 0x1600d2 处的加法指令改成了减法。

B、接下来是执行第二次加密的代码

从执行记录来看，监测到的用户态指令序列中，0x160000位置指令的前一条指令是父进程的指令。可见这段代码不是子进程自己引导启动，需要父进程进行控制。

找出父进程控制启动这段代码的位置，如下所示，写入完毕后设置子进程 ConText.Eip 到这段代码，之后父进程的主线程进入 system(“pause”) 的等待状态。


子进程 sleep 结束唤醒后，执行 0x160000 位置的代码进行第 2 次加密运算函数，加密过程中会触发第一次 int 3 中断，父进程有一个线程专门接受子进程的异常，该线程判断异常类型为0x80000003，检测计数器次数，进入第 5 次的WriteProcessMemory，原本的int 3指令在循环里，被改成了 nop，因此加密过程中不会再产生int 3中断，子进程恢复后继续执行，完成第二次加密运算，等到加密完成后结尾的代码产生第二次 int 3 中断，父进程接收到信号，根据计数器走了另一个处理分支，读取 0x150000 位置的 21 个字符与预设验证码匹配，成功就弹出窗口。

 

子进程的加密函数通过反汇编机器码得到汇编指令，再逆向出算法代码如下，各个字节是相互独立的，其中的 key[28] 从抠出来的代码里只能发现前 27 个，第 28 个 0xff 需要动态调试过程中获取。


void encInChild(unsigned char     input2[21])

{

       unsigned     char key[28]={

              0x8c,0x4c,0x96,0x5b,0x2a,0x3f,0xb6,0x5b,0x2a,0x11,0xb1,0x15,0xac,0xc3,

              0x53,0xb6,0x2a,0x3f,0xb2,0xfc,0x69,0x10,0xbf,0xfd,0xb6,0x5b,0x3f,0xff

       };     // 前27个静态分析获得，第28个动态虚拟化调试获得

       int     len = 21;

       int     i = 0;

       int     v3, v6, v9,v10;

       int     A12, A24;

       unsigned     char *pA20, *pA16, *pA8, *pA4, *v5;

       unsigned     char *input = input2;

       do{

              A12     = 0;   pA20 = key;  pA16 = key;

              do{

                     pA4     = pA16;   A24 = 0;  pA8 = pA20;

                     do{

                            v5     = pA4; v6 = 0;

                            do{

                                   if(     input[i] == pA8[v6] )

                                   {//有些输入始终无法成立，因此存在输入输出一致的情况

                     //                   __asm int 3 会被改成nop

                                          v9     = v5[0] * (pA8[v6] - (input[i] ^ key[A12 +     3*(A24+v6)]));

                     // 此处的减法是WriteProcessMemory导致，原始代码得到的是加法

                                          input[i]     = v9 & 0xff;

                                   }

                                   v6++;     v5 += 9;

                            }while(v6     < 4);

                            A24     += 3;

                            pA8     = pA8 + 3;

                            pA4++;

                     }while(A24     < 6);

                     A12     += 1;

                     pA16     += 3;

                     pA20     += 9;

              }while(A12     < 3);

              len--;       i++;

       }while(len     > 0 );

       // __asm int3  //原程序中触发第二次中断，穷举过程中不需要

}

得出可能的几种情况，只要输入字符第一轮编码输出的结果是下列情况中的一种就能满足校验条件。各个字符相互独立，可组合出多种情况，只要输入满足其中一种即可。


第一次加密编码函数


void sub_401060_encode(unsigned     char* input)

{

       int     i = 0;

       unsigned     int v2 = input[0];

       unsigned     char v3;

       char     temp;

       do{

              v3     = (input[0]>>2) ^ ((v2 & 0xff00)>>8);

              temp     = input[0];

              input[i]     = v3;

              v2     = 0x22fc*(v2>>2) + 5478 * (v2 + v3);

              input[i]     = input[i] ^ 0x41;

              i++;

       }while(i     < 21);

       return;

}
