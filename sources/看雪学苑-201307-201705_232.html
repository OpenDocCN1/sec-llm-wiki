运作原理

CrackMe 的运行步骤是这样的:


①   普通的输入 -> ②检测输入正确性 -> ③弹窗提示结果

根据设计依据的指导，一个CrackMe的破解关键在于第②步，但第②步往往不容易找到，而第③步往往是和第二步连在一起的，第③步如果没有经过特殊处理往往是很容易就找到的，因此通过第③步就可以定位到第②步。

所以，这个CrackMe主要就是对后两步进行了特殊处理。


基本处理:

1.   在获取文本时,并不是通过正经的获取窗口文本来获取(例如GetWindowText,GetDlgItemText等等)，而是使用GetPixel这个API来获取，通过这个 API 来获取控件上的字体像素点，再把常用的字母，数字等字体的像素点阵保存起来，最后通过循环比较像素点阵来找到对应的字符。这样一来就不能直接找到字符串了, 但是 GetPixel 这个 API 还是太明显。

2.   提示成功使用 MessageBox 这个 API 来完成，传入这个 API 的字符串是事先加密过的，因此，直接搜索是搜索不出来的，但是，MessageBox 一旦被调用，就可以通过堆栈回溯找到调用点。


升级处理:

在上述的处理基础上, 又分别将 GetBoundsRect 和 GetDlgItemInt 给 HOOK 住。HOOK 住这两个API之后，GetPixel 和 MessageBox 就不显眼了，通过一定的处理，调用 GetBoundsRect 的时候就转到 GetPixel，在调用 GetDlgItemInt 的时候就转到 MessageBoxW。


原理如下:

程序本身是要通过 GetPixel 来获取到像素点的, 但是，现在将 GetBoundsRect 函数 HOOK 到一个自定义转发函数，在自定义转发函数中判断是否是需要调用 GetPixel，如果是就在函数内部调用GetPixel，否则调用原函数 .MessageBox 函数的处理同理, 但是在 MessageBox 调用之前，我会保存当前函数的栈底地址, 在自定义转发函数中调用 MessageBox 之后，我会将自定义转发函数的栈底替换掉，返回的时候，就不会返回到调用 MessageBox 调用的地方了，而是直接返回到上一层函数中。至于为什么要选 GetBoundsRect和 GetDlgItemInt 这两个 API 来做 HOOK，是因为这两个 API 的形参，返回值和真正需要调用的API 很相像，而且在我的代码中不常用。

UINT GetBoundsRect(HDC,   LPRECT, UINT);

   

中间函数=>

   

COLORREF GetPixel(HDC, int,   int);

   

Int GetDlgItemInt(HWND,int,BOOL*,BOOL);

   

中间函数=>

   

Int MessageBoxW(HWND,LPCWSTR,LPCWSTR,UINT)
