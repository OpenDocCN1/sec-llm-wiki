题目设计的非常新颖，作者的题目引入了 windows 下的 shim 安全技术。Shim 的执行依赖兼容性数据库（sdb）文件，sdb 文件是由一系列 tag 以及 tag 对应的值组成。只有攻击者写入正确的 tag 信息才能创建匹配 CrackMe 程序的 sdb 文件。另外本题对注册码进行了哈夫曼编码，以输出的哈夫曼编码去写入 sdb。本题破解的入手点在于研究 sdb 文件的创建过程，要分析程序写入 sdb 文件的 tag 并找到相对应正确的值，才能突破此题。  

  

出题者简介

  

**hyabcd**，一名爱好 Windows 攻防的大四学生

  

设计思路

  

本题比较新颖的地方应该是把 Windows 下的安全技术 shim 与 Crackme 结合。Shim 是一种通过读取兼容性数据库获取匹配信息，对指定程序进行兼容性修复的技术，由于 shim 技术中包含有 dll 注入，提权等功能，因此可被恶意程序利用作为攻击手段。本题使用的就是 shim 里的 dll注入功能，将目录下的 CrackMe.dll 注入到 CrackMe 程序中，并重新运行 CrackMe 程序，弹出“注册成功”的对话框。

  

Shim 的执行依赖兼容性数据库（sdb）文件，本题的目的就是让攻击者创建一个可以执行 shim 的 sdb 文件。sdb 文件是由一系列 tag 以及 tag对应的值组成，这些 tag 表示的含义包括但不限于需要执行兼容性修复的文件名，文件版本，产品名称，执行的 shim 功能等等，详见https://msdn.microsoft.com/en-us/library/bb432182.aspx。

  

本题更像是一道填空题，对于一些不影响结果的 tag 值已经在程序中写入，而需要攻击者写入的 tag 包括字符形式的文件版本，产品名称，公司名称，二进制形式的文件版本，时间对应的tagid以及程序的系统版本（x86或x64）。除此之外，攻击者还必须写入注入 dll 对应的 shim 名称—“InjectDll”。只有攻击者写入正确的信息才能创建匹配 CrackMe 程序的 sdb 文件，并成功注入dll。

  

本题中 sdb 文件的创建及写入参照微软的 shim工具 Application Compatibility Toolkit。通过逆向该工具创建 sdb 文件的过程即可了解 sdb 文件的创建。

  

当然，如果直接拿输入的注册码去写入 sdb 文件就太直白了，本题对注册码做了些许处理，对注册码进行哈夫曼编码，以输出的哈夫曼编码去写入 sdb。这里有个彩蛋，当时输出哈夫曼编码的时候从下标 1 开始输出。所以就忽略了第一位注册码，不过因为前面第一位注册码固定了，所以，没有影响。除了哈夫曼编码，在一些写入sdb 文件的地方还有一些小处理，不过都比较简单。

  

破解方法

  

本题破解的入手点在于 sdb 文件的创建，只要知道程序写入 sdb 文件的哪几个 tag 就可以找到相对应正确的值。对于字符形式的文件版本，产品名称，公司名称，可以直接右键-属性，在详细信息里就能找到，二进制文件版本只是对字符形式的文件版本求其每一级的二进制即可，时间对应的 tagid 是 0x5001，由于是32位程序，所以程序系统版本为1，最后一一对应得到一串哈夫曼，对其进行逆变换，满足程序定义的格式即可得到注册码前半部分，最后就是 “InjectDll”，“I” 和 “D”已经固定，补充其他位置即可，进行-5转换，作为注册码后半部分即可得到注册码。
