# 开了挂的勒索软件：Cryptowall 2.0

这篇文章由 Andrea Allievi 与 Earl Carter 共同所写，翻译 by 银雁冰 。

勒索软件对用户数据的劫持，其变种版本加密用户的数据，使得数据再也无法使用，直到支付赎金后获得加密密钥（才能解密文件）。 Cryptowall 2.0 使用洋葱网络（TOR）来混淆与 C&C 端的通道。释放器使用多种利用技术去获取初始权限，并且结合反虚拟机技术与反调试技术去阻碍其被沙箱识别出来。释放器和下载的 Cryptowall 程序事实上结合了多级加密。关于这个恶意样本最有趣的一点是，它具备直接通过自己的 32 位释放器去运行 64 位代码的能力。在 Windows 32-bit on Windows 64-bit WOW64）环境下，它确实能将处理器执行上下文从 32 位切换到 64 位。

# **初始的入侵**

  

Cryptowall2.0能够通过多种攻击因素进行传播，包括email附件，恶意pdf文档甚至多种多样的利用套件（Exploitkits）。在我们分析的这个样本中，释放器使用了CVE-2013- 3660，一个win32k提权漏洞，来完成基于x86机器上初始权限的提升。这个利用工作在从Vista开始的32位操作系统上。释放器甚至包含一个64位的DLL，它可以被用来触发所有AMD64 Windows系统中的漏洞利用。  

在确保通过反虚拟机和反调试检测后，Cryptowall恶意代码被解密，并且安装到系统上。 一旦系统被感染，用户就会看到与图1类似的一则消息。

# **构造未加密的Cryptowall程序**

  

为了构造没有加密的Cryptowall2.0代码，释放器1经过多个阶段的解密。主释放器是一 个C++MFC应用程序。第一阶段的加密代码位于MFC的事件处理例程“CMainFrame::OnCreate”中。这个例程构建了第一阶段的解密代码（位于RVA+0xF3F0处） 并且简单地调用它。

  

第一阶段的解密代码打开原始释放的PE，从里面读取大块的代码（第二阶段所需）并且解密。最后，它将执行过程传递给位于额外缓冲区中的第二阶段。

  

第二阶段是代码加密的最后一层。它构造一个简单的导入表（IAT），并且执行多种特性。这里面最重要的是反虚拟机检查。反虚拟机代码相当简单：

 图2：Cryptowall简单的反虚拟机检查

  

如果没有虚拟机被检测到，另一个“释放器”被以挂起状态派生出来。“ZwUnmapViewOfSection”API被用来映射原始的PE缓冲区。一个新的内存块被分配，而且一个新的PE（提取并解密自“.data”节）被拷贝到它的预加载地址。然后使用下面新的上下文来唤醒新进程的主线程，接着原始进程退出：

*   EAX寄存器被设置为新PE的加载入口地址（entry pointaddress）；
    
*   EBX寄存器被设置为一个仍不知道的值：7ffd8008；
    
     
    

**安装Cryptowall到系统**

  

假“explorer”进程中的“VirusExplorerMain”例程构造（译者注：上述过程之后，一个新的explorer.exe进程被初始PE启动）构造IAT表并且将Cryptowall安装到受害者的系统上。第一阶段是去创建一个基于计算机MD5值的名字的可执行文件。这个可执行文件被拷贝到%APPDATA%环境变量所代表的本地文件夹

（C:\\Users\\<Username>\\AppData\\Roaming）。

为了达到可持续的目的，自启动注册表值被写入这些地方：

*   HKCU\\Software\\Microsoft\\Windows\\CurrentVersion\\Run
    
*   HKCU\\Software\\Microsoft\\Windows\\CurrentVersion\\RunOnce
    

注意：RunOnce值前面会带一个星号，这样即使在安全模式下进程也可以启动。

  

同一个恶意程序也会被拷贝到开始菜单栏的“Startup”文件夹下。假explorer进程的最后任务是禁止系统保护，下列命令行会被调用然后被执行：

*   vssadmin.exeDelete Shadows /All /Quiet（译者注：删除卷影副本）
    
*   bcdedit.exe /set{default} recoveryenabledNo（译者注：禁止开机时的启动修复）
    
*   bcdedit.exe /set{default} bootstatuspolicy ignoreallfailures（译者注：禁止开机启动时的错误恢复）
    

 

下列服务也会被禁止：Security  Center, Windows  Defender, Windows  Update,BackgroundIntelligent Transfer Service,ERSvc, Windows ErrorReportingService。

  

最后，初始被释放的文件执行退出，并且文件被删除。现在，Cryptowall的PE实体被注入到一个假的“Svchost”进程（Svchost的启动过程和刚才那个假explorer一样）。感染在新的Svchost进程中继续进行。

  

“VirusSvchostMain”函数（RVA：0x418C70）是主感染例程。它构造有害的IAT（导入函数来自下列模块：ntdll,kernel32,advapi32,user32,wininet,ole32,gdi32），它会检查安装过程是否已经完成，并且创建一个主Cryptowall事件。（译者注：事实上，如果另一个Cryptowall发现这个事件已经存在，则不会继续运行）。然后创建Cryptowall线程并尝试从 下列URLs之一下载用来与服务控制端通信的洋葱网络客户端。

 

![](../Images/6e69f74e0384557523d45c03ffa32d82.png)  

如果成功下载了更新文件，它会立即执行。下载的文件是一个用同一简单算法加密3次的可执行文件。在解密后，一个干净的PE被提取出来并且执行。这个PE文件显得尤其特别，因为所有常见的头部（DOS头，NT头，IAT，EAT，…）它都缺失。它的IAT和“.data”节位于另一块大的内存缓冲区。解密代码会处理正确的链接和重定位。

  

事实上，这个干净的PE就是洋葱网络通信模块。它执行一个完全的洋葱网络客户端，用来与C&C控制端进行通信。我们分析的这个样本使用的洋葱网络URLs如下：

*   crptarv4hcu24ijv.onion
    
*   crptbfoi5i54ubez.onion
    
*   crptcj7wd4oaafdl.onion
    

 

使用PE里硬编码的IP地址，恶意程序通过一个443或9090端口的加密SSL连接连接到洋葱网络服务端。在成功建立连接之后，它开始使用一个定制化的域名生成算法（DGA）生成Cryptowall的域名。这个算法位于（offset+0x2E9F处）。

 ![](../Images/f89e7f7d9614820d405c76be3a12aec7.png)  

图3：洋葱网络客户端的DGA算法

 

如果加密连接进行顺利，与CryptowallC&C控制端的通信就会进行；否则主线程会睡眠一段随机的秒数，然后再用一个新生成的服务名重新尝试连接。

  

Cryptowall2.0建立的众多SSL连接中的每个连接都使用证书中一个随机的服务器名称。然而，客户端证书共享一个可以用来检测是否有客户端离线的例程（一个就足够了）。一旦安装，Cryptowall2.0就会创建很多很多的请求。

  

Cryptowall2.0会使用“CetExternalIpAddr”函数去尝试获取当前操作系统所在网络的外 网IP地址。它通过与以下地址交互来实现上述目的：

*   http://wtfismyip.com/text
    
*   http://ip-addr.es
    
*   http://myexternalip.com/raw
    
*   http://curlmyip.com
    

 

它以wtfismyip.com开始，一旦第一个成功回应收到就立即停止。在大多数情况下，这意味着它访问完wtfismyip.com后就会停止（既然它是列表中的第一个）。尽管这是一个相 当常见的请求，但在企业网络里面这不应该是一个非常常见的行为，所以这一点可被看做这个恶意软件的网络行为特征。

  

我们分析的这个样本的另一个有趣的地方是，在它的32位主执行程序中包含一些64位的代码（和一个利用DLL）。尽管主模块运行在32位模式下，它有能力执行它所需要的任 何64位函数。它通过执行一个直接的处理器执行上下文切换来完成这个过程。代码先将两个32位值压到栈上：64位函数的目标偏移（只有低32位），和一个64位选择子。

  

push <32Bit Selector>

push <32Bit LowDWORD address>

retf

 

它最终执行一个FARRET（操作码0xCB）。正如《Intel开发人员指令手册》里面讲的 那样，这类操作码执行一个“FarReturn”：返回到位于不同于当前代码段的另一个段的调用例程。为了返回到32位模式，代码会执行上述过程的逆过程：

  

call $+5                                                    ;这会往栈里面压入64位返回地址

mov dwordptr\[esp+4\],<32BitSelector>;与push (32位值)一样

mov dwordptr\[esp\],<32Bit Address>     ;在AMD64模式下所有值都是8个字节

retf

 

这种64位代码和32位朱执行程序的混用甚至给IDA的反汇编增加了难度。图4显示了一个Windows7/864位全局表述符表（GDT）的dump：

![](../Images/bfe884597c003fccd23a82e796a19c6f.png)  

 正如读者所能看到的那样，0x20描述符和0x30描述符是Ring3层代码段用来描述整个用户模式地址空间的，一个给32位，另一个给64位。Cryptowall给这两个段描述符使用合适的选择子，并在它的执行过程中，在这两种执行模式下进行切换。

**总结**

对于电脑用户，勒索软件是一个正在增长的威胁。变种还继续在功能和逃避能力上进行 进化。仅仅将这些样本在沙箱中运行会变得越来越难，使得分析越来越复杂和深入，需要持续性的研究来更新规则和特征，以同这些持续性的攻击做斗争。

  

辨识和停止这些复杂的新变种需要一种分层的安全方法。打破攻击链中的任何一步都可以成功预防攻击。因此，阻断初始的钓鱼邮件，阻断同已知恶意内容的网络连接，和停止恶意代码的进程活动，都是同勒索软件进行斗争和组织它劫持并占有你的数据的关键。
