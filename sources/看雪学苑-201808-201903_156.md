# 手动分析VMP加密的x64驱动导入表

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MjM5NTc2MDYxMw==&mid=2458293453&idx=1&sn=2610ea019989e53b674fe321e9d91196&chksm=b181a44786f62d51b52868dc04a4144e9ca729f07fc98f212a86c99efb535051c3a888763476&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MjM5NTc2MDYxMw==&mid=2458293453&idx=1&sn=2610ea019989e53b674fe321e9d91196&chksm=b181a44786f62d51b52868dc04a4144e9ca729f07fc98f212a86c99efb535051c3a888763476&scene=27#wechat_redirect)

**VMProtect**是当前最强大的虚拟机保护软件之一，它适用于Windows平台本地编译的目标程序，支持EXE、DLL、SYS。

  

VMProtect是由俄罗斯人PolyTech开发的，是一个利用伪指令虚拟机的保护软件。经过VMProtect处理的软件，分析难度大大增加。越来越多的软件优先考虑使用VMProtect来保护自己的产品。另外，经过虚拟机的处理，代码执行效率将会降低，因此，一些对效率要求比较高的代码不适合用VMProtect来处理。

![](../Images/86351853896fafbab2055b6718f649e2.png)

  

VMP保护的导入表会把FF 25 offset (call qword ptr\[rip+offset\])修改为E8 call。

![](../Images/c55aa2b81d614189b2cc24e5c5b16d32.png)

  

![](../Images/08d9b0dc56d678562b29ce07dc87c96a.png)  

  

跟进去可以看到先保存了rdi，后面rdi会用于堆栈平衡以及修正返回地址。

![](../Images/0c708377d5df544990f6e9515a955ac9.png)  

  

然后返回地址也就是+BE081  int  3那一行的地址被保存到rdi。

![](../Images/c13daaf713cc01f8a53c6db702bc09e9.png)  

  

![](../Images/01a96d0e63b7c620ecb3cd7cda3a150c.png)  

  

![](../Images/19af437a431957273c11bfc52e2e0c66.png)  

  

rdi被加一之后又填充回返回地址，也就是让返回地址跳过int 3指向正确的BE082 test eax,  eax那一行。

![](../Images/1abf63a7a001047a0d0086fe3cdef610.png)  

  

![](../Images/60850217e3389fa6166f19d37c2c9a9f.png)  

  

![](../Images/23f69a3473e3c8738b63dc417d25a322.png)  

  

这几步相当于解密导入函数地址，从\[imagebase+37DF6+14B606\] + 3DDC1A68处取出函数地址放入\[rsp\]中。

  

我们用模拟器验证一下。

```

```

  

![](../Images/dcdbb62863d492b58337f4afadec27b2.png)  

  

![](../Images/e9a5377229411af85f3999619b791864.png)  

  

最后一步retn直接飞向\[rsp\]也就是刚才计算出的API地址并让最开始push rdi 减少的rsp恢复。

  

按照这个思路稍加修改甚至可以实现一键脱vmp壳，只要用脚本定位所有api call的地址，修复导入表。
