# CryptoWall勒索病毒分析

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MjM5NTc2MDYxMw==&mid=2458296533&idx=1&sn=88cea2926d11902d5e382c9edea1204e&chksm=b181905f86f61949bc9f3c665da07a623bd2db2ee4a9c8ba1f0aa1bf822c55e79cca6a724c06&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MjM5NTc2MDYxMw==&mid=2458296533&idx=1&sn=88cea2926d11902d5e382c9edea1204e&chksm=b181905f86f61949bc9f3c665da07a623bd2db2ee4a9c8ba1f0aa1bf822c55e79cca6a724c06&scene=27#wechat_redirect)

前几天给的样本，分析完之后，感觉还是比较经典的，且网上并没有相关分析，所以跟大家分析一下我的思路

  

用PEID查看，并没有加壳，但是竟然有附加数据

  

![](../Images/f532af3d1affec64a9119ca6c175d1dd.png)

  

用LoadPe查看导入表信息，明显很奇怪

  

![](../Images/c02d80f40d82cc058f7261db21c34899.png)  

  

用火绒剑分析进行行为分析，发现创建了一个跟自己同名的子进程

  

![](../Images/f3285498debc371b3485465a0a5b1a80.png)

  

载入Od,在这个call里程序就跑飞了

  

![](../Images/b0885acda93cadfcbef7262c68fc2d03.png)

  

跟踪进入，一脸懵\*

  

![](../Images/c01debe159c68a4423aef439698f01dd.png)

  

全都是这样的代码，既然创建了进程，于是直接下API断点

CreateProcessW  CreateProcessA

  

![](../Images/f8cafe7a0a08f89745e611be8b55ece6.png)  

  

栈回溯发现地址很小，明显是申请的堆空间，且这个进程是被挂起来的，经验告诉我，既然是挂起，肯定是要修改OEP,活者是写入一段shellcode等操作

继续下 WriteProcessMemory断点

  

![](../Images/cb4f130ff81edec5bb6454c5fec4113c.png)

  

  

和我想的不太一样，虽然写入了内存，但是发现是把所有的区段都给改了，包括PE头，多次写入，不用想这块内存肯定我们真实的病毒程序

  

经过分析这块内存是利用VirtualAlloc申请出来的，把内存中的数据复制过来并解密，然后写入挂起的线程

  

直接把这块内存dump出来

  

![](../Images/49a1c525a4de149c4b5442e2c23c50eb.png)  

![](../Images/60c99f8208da008e7bac99eaf3f5c477.png)

  

经过测试，dump出来的程序确实真正的病毒程序

下面开始分析病毒的行为

  

用火绒剑过滤的时候发现病毒会复制到

C:\\Users\\用户名\\Documents\\yfqgbh.exe

名字是六位数的随机字母

在CopyFileW上下断

  

![](../Images/470c3396f6132b537f43914609150043.png)  

  

栈回溯发现下面有创建新的进程，这个进程就是我们复制过去的病毒，往上看的话肯定是判断

  

![](../Images/14080b4036866b36f1740b6a21d55607.png)

  

往上走，发现有拼接字符串，下F2断，重新跑起来

  

![](../Images/ab7c56ad5b574a0a17fd5769c1f3066d.png)

  

发现在获取目得的路径

  

![](../Images/6040fb2bf91da5774c21db9cf62b8d3d.png)

  

然后打开这个位置的病毒，很显然，这个位置并没有我们的程序，所以GetLastError会返回错误代码2

  

![](../Images/fd6204d98cb57823d92dac73c8066fd9.png)

  

![](../Images/7ce27ce8aed4eaad7e361fa66195c202.png)

  

这样我们的跳转实现不了（实现不了则会复制文件到目标目录）为了分析方面我直接把这个jnz改成jmp分析

单步往下跟踪

发现先创建了一个互斥体，防止多开

  

![](../Images/97e5b6c33ae6916703c0d89490671ced.png)

  

到这里我们可以先用IDA静态分析，配合OD动态验证我们的猜想

  

![](../Images/9213563c43e739b9d5450600925f8ca1.png)

![](../Images/56f8b44297d41ce2a4db0bde72f5cca2.png)

  

在IDA里我们可以看到，在获取系统版本之后，下面有几个call

  

第一个call跟进去之后,发现明显是在提权

  

![](../Images/54c0153e6c54a06964449a9d478c2dc0.png)

  

第二个call，发现看不到什么，回到OD，继续单步

  

![](../Images/fbb079a957926e1ca24fad487f6e29d3.png)  

  

发现返回值是CreateThread

  

![](../Images/bdc584729d7fc572aea9253d70af495b.png)

  

继续单步，发现创建了一个线程，回调函数地址是我们传进来的参数a1

  

![](../Images/dc8d30e106962f715ccab153a5428a88.png)

  

IDA反编译查看该线程的源码，发现是在枚举进程

  

![](../Images/28bd737c6bac75e03814ffb1e742b9cb.png)

  

经过动态分析这个线程

  

![](../Images/2d4231b051f81275508e1547bfb003af.png)

  

0217FF40   0217FF48  UNICODE "<"

0217FF44   00000000

0217FF48   0000003C

0217FF4C   00000040

0217FF50   00000000

0217FF54   005A3038  UNICODE "runas"

0217FF58   005A33E8  UNICODE "vssadmin.exe"

0217FF5C   005A3410  UNICODE " Delete Shadows /All /Quiet "

  

静默删除 影子 ？不知道是下要干什么

  

分析完线程，回到主函数，继续单步发现创建了很多线程，因为文章篇幅，我们直接以找到感染函数和加密函数 为目的分析（毕竟是勒索病毒，分析重点）

  

单步跟踪发现，有个设置线程优先级的，想象一下，把这个线程设置成了空闲状态

  

![](../Images/ee270e02d91c471e93e2c1c1681a6324.png)  

  

该线程回调函数地址地址为0x401710,IDA中跟随到该函数，发现里面在递归遍历磁盘，既然都遍历了，碰到合适的肯定要加密一下嘛，

进入递归函数，目录是肯定不会加密的，所以里面必不少的就是判断，目录，后缀名为我们需要加密的程序…等

  

![](../Images/004c737f0b512c4beaeff45ba48ef471.png)

![](../Images/9e7bf37d4e324699565712473893f2c9.png)  

  

![](../Images/3e7b16ece130ad8ffbea495f6028aaf1.png)

  

设置属性，读取到内存，又写入，很有可能是在加密，在该函数位置下断

00401C85    E8 46000000    CALL <dump.sub\_401CD0>   ; 感染函数

  

![](../Images/c7a1a3c5280b4b2e671adcdad5ceea21.png)

  

加密函数肯定是要加密我们的文本的，我在C:\\backup放入一个txt文本

跑起来程序，发现这个位置确实放了我们的文件，F9运行

  

![](../Images/d0179386a32b6835f61dd1f6692f6a20.png)

  

断到读取我们放入的文本时，继续单步跟进

  

![](../Images/2a7e4c84f5afdb2ad45ddc3420ea0338.png)

  

发现要CreateFileW我们的文本了

  

![](../Images/df9eb4501157b8564c3de5f192d5ca30.png)

  

读取到内存

  

![](../Images/2e6b91f8959ebd2e375343690c825ba3.png)

  

先读取128个字节，并判断开头处是否为空，如果是则是已经加密过的，如果不是则会申请一段堆空间 

  

![](../Images/d5a869bdd4aaed1ef0965c25d9e4bb63.png)

  

把读取的内容放到这个空间

  

![](../Images/35e101b3dfe0bd3bdce0a4a4f2aec2eb.png)

  

往下单步跟踪发现又申请了一段堆空间，然后有两个可以函数，经过测试

  

![](../Images/2ecd586c3a17faa87f24c9fa742d5e9d.png)

  

这个位置的call是加密函数

00401FAE   E8 FD1A0000    CALL <dump.sub\_403AB0>

  

![](../Images/28428b40b398dcdfdd7a77e919b5c6c5.png)

  

最后就是设置文件指针，然后写入加密后的文本了

  

![](../Images/66c6549e495343fa24a364b594add853.png)

  

IDA里面还是比较清晰的

  

![](../Images/1afafe6e7239777b5e7e1aeef04339f6.png)

  

以下为加密函数

  

![](../Images/acdf6def7371766ea9e04d48b2d20e5d.png)

  

如果这个加密是可逆的，那么我们就可以恢复原始文件了。弹出来的框框显示的是RSA-4096不可逆，有兴趣的可以研究

根据这个样本的特征我推测是CryptoWall勒索病毒，具体版本就不知道了
