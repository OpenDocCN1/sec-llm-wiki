# .NetReactor 3.6——体验另类的脱壳法

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MjM5NTc2MDYxMw==&mid=2458295726&idx=1&sn=cd9315ef4497e4b6a5d4f21d802ef368&chksm=b181ad2486f62432351519f56bd50756cf58e6a93ec09914a176f1a55db6ffaa54521e4647d7&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MjM5NTc2MDYxMw==&mid=2458295726&idx=1&sn=cd9315ef4497e4b6a5d4f21d802ef368&chksm=b181ad2486f62432351519f56bd50756cf58e6a93ec09914a176f1a55db6ffaa54521e4647d7&scene=27#wechat_redirect)

  

## 前言

  

最近一直在看脱壳的相关资料，看到了Tuts4you社区脱壳脚本的教程，这个壳我感觉很不错挺有意思的，于是打算将内容整理下分享出来。  

  

  

## 查壳

  

![](../Images/1d6f18e3d539f7f9ef81455ce9bb0fbd.png)  

 

这个壳是.NetReactor 3.6.0.0的版本。根据作者的介绍，这个壳只是一个包装器，它包装目标程序，然后将其全部解包到内存中执行。但是这是一种不安全的方法，因为有人可以将内存中的目标程序转储回文件并完全恢复程序集。这个壳的重点在于转储之后的修复，需要对PE文件有一定的了解。

  

  

## 脱壳

  

接下来直接载入OD，F9让程序运行起来。

![](../Images/3a689ed57cfeafccd99bf273797a017f.png)

 

接着调出内存窗口，为了锁定目标程序被解压的位置，因为这个crackme实际上也是作者写的，所以选择通过搜索关键字符串的方法，搜索Crackme。

![](../Images/7fefa0e072faa842e964aec8b85b641d.png)

 

![](../Images/e7ec0baf195997654703dfb0c4b09260.png)

 

搜索到关键字符串之后向上滚动，查找PE文件，如果找到了说明这里就是目标文件解压缩的地方。

![](../Images/12f4db7df52053edf04d5b2e7340622c.png)

 

经过搜索和寻找，我们在第六次搜索结果中找到了要找的PE文件。

![](../Images/654f220aa4201c4216d469ccb6f23fb8.png)

 

接着右键->备份->保存数据到文件。

![](../Images/6a4838c1cf8f3b25f2f62c69b2f81a33.png)

 

选择保存类型为任何文件，并修改后缀名为exe。

![](../Images/ae10daf2e914f8c6ef7eb971f1bfb331.png)

 

接着测试运行一下，弹出一个错误框，无法在电脑上运行。这很正常，因为直接dump下来的文件在PE头总是会出现问题。因为我是在本机上跑的，如果是W7的话应该是显示不是有效的W32程序。

  

  

## 修复目标程序

  

接下来用CFF Explorer这款PE工具来修复一下目标程序。

![](../Images/d26f5d61eb2696f9c54a814b7a77245e.png)

 

载入目标程序，点击Header部分，错误提示为Out of memory。

![](../Images/9903c61ebabb0013cdf88bca39d36c76.png)

 

接下来进入到Driectory部分，修复MetaData Header的错误。我们需要修复这个错误的RVA和Size，Size明显是错的，太小了。

![](../Images/7083ea25127b4f89d3820558107f0961.png)

 

接着来到Address Converter部分，点击这个放大镜，查找字符串BSJB。至于为什么搜索这么一串字符串，作者给出的解释是这个字符串的Offset就是要修复的Meta Data的Offset。（我也是一脸蒙蔽，这解释有点太勉强了吧）

![](../Images/38d33fa381131a30c94754e478c12d2e.png)

 

接着点击查找，找到了0x9400这个地址，那么Meta Data的Offset就是0x9400。

![](../Images/e0987f8b7f53466f865343bbf10af9aa.png)

 

接着把9400输入到Offset中，会自动计算出我们要的RVA是0xA400。

![](../Images/da05390a04d46c535d27ba6855d9b386.png)

 

回到Directoy部分，将正确的RVA填入。至于Size我们可以根据一个公式计算得出：

  

MetaDataSize=Import Directory RVA-MetaDataRVA,Import Directory RVA的值如下图：

![](../Images/5f8f8111f29d0e81d240d8d897113552.png)

 

最后算出Size为0x194C。

![](../Images/4ca39e2fb2d55f12c4ec161d8cc85757.png)

 

接着修改回正确的RVA，然后点击保存。

![](../Images/58081a9aea0db330a2aaf5eacb19ab80.png)  

  

接着再次双击测试运行，还是无法运行。这里作者的原话是根据我之前的经验，我应该是忘记修改文件头属性了。

 

不得不感叹大神的经验就是强大。好吧，继续修复。

![](../Images/8f086fc8a3dbf7b2bb0557aa42bd9242.png)

 

点击文件头 找到Characteristics，双击。

![](../Images/61e9b15e2b728bb1ad3fb939f5cf9b3a.png)

 

属性显示这是一个DLL，难怪会报错。把勾去掉，再次保存。

![](../Images/e40019512238d6aa4c4c41b8a0146e5e.png)

 

OK，程序完美运行，这个壳也算是脱完了。
