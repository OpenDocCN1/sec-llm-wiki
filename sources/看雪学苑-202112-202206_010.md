# **详细分析及实现**

  

首先创建了一个名为"avoid repeat open"的互斥体，保证程序的单例执行。![](../Images/e138a13df798675b2090b0ba91e11c42.png)然后开始创建窗口，并初始化D3D设备。![](../Images/c00686dc63e40e3bee38c10ea4338ce7.png)

![](../Images/5144f29c18254c606d65d7709376baec.png)

随后开始动态获取ZwAllocateVirtualMemory和ZwFreeVirtualMem的函数地址。

![](../Images/5184fe3ae10336f89d9b6ed356ec9001.png)

调用ZwAllocateVirtualMemory申请一段可执行内存后，开始将两段shellcode写入。

![](../Images/af763828170a84f5f92286aed8c53ba8.png)

紧接着可以看到通过调用GetTickCount来判断运行时间是否超过4秒，若超过4秒则清空shellcode，即绘制消失。

![](../Images/d3c1617ad0c41ebe01c661ca94ba7825.png)

shellcode的入口为D3D的一些shader初始化。![](../Images/94c8ded977bbf51a0c35092dc570b6c7.png)

![](../Images/3d86fc62711ad94a9c9ac53721d19f16.png)

动态编译shader完毕后开始执行虚拟机。![](../Images/aa46e61af16e807de304ddf50ac26c8a.png)

![](../Images/7ad4375922f40afebfc5f7f166073abb.png)

  
简单分析了之后，可知每个分支作用如下：  
  

| 指令 || 作用 |
| --- | --- |
| 0 || 寄存器相加。eg：v1+=v2 |
| 1 || 两数相减。eg：v1-=v2 |
| 2 || 寄存器赋值。eg：v1=v2 |
| 3 || 立即数赋值。eg：v1=999 |
| 4 || 计算key。 |
| 5 || 绘制黄色小方块 |
| 6 || 绘制青色小方块 |
| 7 || 函数返回 |

  
由于绘制青色方块正常，黄色方块不正常，故猜测黄色方块数据存在污染。进一步分析DrawFillRect函数，得知前四个参数中，第一第二个为坐标数据，第三第四个为Key。  
并且在捕获绘制青色方块的数据时发现，第三和第四个参数在参与运算时结果始终为0，反之，黄色方块不为0。

![](../Images/bd8d37c36ccf1f34a08880258eb419f9.png)

将指令集扣下后使用C++进行模拟流程，并输出操作流程。![](../Images/0247e91ae454f00b98c5657557371ef8.png)![](../Images/cb9c9a7f956e90d24f47676cc08b4581.png)经过对比，发现黄色方块在计算Decryp之后，将Table\[6\]与Table\[7\]的值进行了互换。直接通过判断互换流程将其修改为Table\[3\] = Table\[1\]禁止互换。

![](../Images/968ba8a88f41b5cc33d6867caa9fa505.png)

![](../Images/e197945df708369710a9a4e7b08aed8b.png)

修改后发现仍然没有绘制黄色小方块，通过代码调试发现绘制时，Table\[4\]为负数，而Table\[4\] = (Table\[0\] – Table\[1\]) = 0x32 – 0x3E8。![](../Images/6b26d156079af849ab1f52e57bfb2632.png)怀疑0x3E8为故意使坐标计算为负数，故将0x3E8修改为0x0后，黄色小方块显示。![](../Images/8003ca70392a904aefb37ee422b49c2d.png)同理，第二个黄色方块的由于没有Key互换，但是对0x1F4计算，将0x1F4修改为0，后方块显示。![](../Images/44647531a36e1e4dbfa8c737cfc52def.png)经过手动修改后，发现存在0x3E8和0x1F4数据对黄色方块的坐标进行污染，将其修改0，并且禁止key互换后，旗帜显示。

![](../Images/39a47c4b1e130ac2abcdb6f13415b9f6.png)

![](../Images/1adcb32b88a587f46d4edc0195f5802d.png)
