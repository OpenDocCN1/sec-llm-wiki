三

  

**分析**

  
刚开始是想直接去分析lighttpd的。随手登陆了一下，看了下包。

> 我个人浅薄的经验，不要单纯去无目的的分析某个应用，我之前犯过这种错误，太容易对着一个程序漫无目的的乱逛，希望你没有这种情况。

  
这里明显可以看到调用了cgi文件，之前看文件的时候看到了这个东西的。 ![](../Images/fcdc29e92e1e7f371069189b1eff36e8.png) 可以去分析下这个文件。

*   
*   
*   
*   
*   

```
ghidra open！！！ Link 死大头！！！ search "action"！！！
```

  
![](../Images/e6a0ded970cc0c2e7e6f0f119c0e9a33.png)  
action=login，交叉引用，看一下。 ![](../Images/c2fb67f6ddf305b2353ef11b3ecc5662.png)   
说实话，ghidra的这个伪代码看着老奇怪了，这里是判断了登陆还是升级。 ![](../Images/6511ecbd8c8d1453a76c35755bb48e80.png) if下面，这里判断flag=1，最后的逻辑是将字符串格式化到acStack4456中。 ![](../Images/034b0d68797ceb87c75add7a0e7a7ca7.png) 再往下这个地方我刚开始比较懵了，因为websGetVar程序查找表变量var,相当于获取参数。所以这里并没有往下看，而是换了个思路点。 这里知道了他是对登陆做了个判断。 去查找登陆的请求参数。![](../Images/e082ee2b0d8b0aa7e4c4a577bb1bd19f.png)![](../Images/06aeabaa2dd31436bf3b5124365b63e1.png) 发现了这么个地方，根据登陆的包。![](../Images/75f16a5186c4c0a846c3bbcc04ac1332.png)发现他返回了一串地址。并且主动访问了这串地址。![](../Images/dc97deb78e0a4819218e106627ed7c5d.png)所以这个地方是判断密码的地方。本来想试试正确密码，来分析下，结果密码怎么都不对。 这里解释下，因为我没有设备，是直接在官网下载的固件，所以这个密码怎么都不对，我怀疑是固件模拟的问题，就没有往下追究。 他主动访问了formloginAuth.htm，在www/文件夹下并没有这个文件，所以去找下lighttpd文件分析下。

*   
*   
*   
*   

```
ghidra open！！！ Link 死大头！！！ search "formLoginAuth"！！！
```

  
![](../Images/ef9e5f9e43ee405c432beac84444aaf8.png)  
跟进from\_Login函数： ![](../Images/59d0637db6e920baa898eaf9dd7e054f.png) 这里就发现了参数处理。![](../Images/eaec4881a04ee465c77c5c5490bda5b1.png) 判断几个参数做了什么，userName是空的先不看，goURL是某个html文件，盲猜他是的从哪来的，action是要做什么。 所以现在要看一下authCode。 如果authCode不等于0，iVar2就等于整形的authCode的值。 往下分析： ![](../Images/305b3ff99afb1b8d62b0c4702e400d2b.png) 这里改成1之后直接，跳过了这个判断。 但是只吧这个改为1之后还是返回到登陆界面。 ![](../Images/f87ec27b2fc0989dc25f7c1343211a57.png) 这里pcVar2=1，导致跳过了设置pcVar2 = home.html。 所以我猜测goUrl参数不是从哪来，而是从哪去。 最后发现果然是哦。 其实在ghidra反编译的时候，好多地方不太习惯，很多地方靠函数名和字符串硬猜。
