系统被入侵后，日志会记录下黑客是如何入侵的，入侵后进行了哪些操作，这为管理员判断系统异常，服务器运行状况等提供了分析依据，因此保证日志的完整性对入侵事件的分析以及后续修补漏洞，都有着极大的帮助。

不法黑客“消尸灭迹”

通常情况下，我们会将日志在本机保存两份。一份正常，一份藏在系统较深的目录中。但是，不管藏得多深，终究都是在本机上。但凡有点经验的黑客，就会找到这些日志一并清除，以此来掩盖自己的犯罪证据。

安全专家自有高招

独立的日志服务

针对上述问题，创宇安全专家建议使用独立的日志服务。建立独立的日志服务器，通过对服务进行配置，将日志输出到日志服务器上，而不是保存在本地。这样便大大减少了日志被删除的可能性。

当网络架构不大时，完全可以使用独立的日志服务器这种方案，配置简单、省时省力、安全性尚可，配合 goaccess 这样小巧的工具进行分析，是一个不错的解决方案。

而无法配置使用远程日志服务器的客户，可以使用rsync等工具将日志同步到远程服务器。

集中式日志系统

当每天日志量庞大时，独立的日志服务器就只能做到保存日志，并不能对其进行有效的分析。此时，独立的日志服务就不适用了。网络较大，人员充足的情况下，建议需要使用集中式日志系统，这种方式不仅可以保护日志，还能有效分析，做到：

收集－能够采集多种来源的日志数据

传输－能够稳定地把日志数据传输到中央系统

存储－能够存储日志数据

分析－可以支持 UI 分析

警告－能够提供错误报告监控机制

例如：

（1）Elasticsearch

Elasticsearch 是一个实时的分布式搜索和分析引擎，它可以用于全文搜索，结构化搜索以及分析。它是一个建立在全文搜索引擎 Apache Lucene 基础上的搜索引擎，使用 Java 语言编写。主要特点是实时分析、分布式实时文件存储，并将每一个字段都编入索引，所有的对象全部是文档。具有高可用性，易扩展，支持集群（Cluster）、分片和复制（Shards 和 Replicas）接口友好，支持 JSON。 

（2）Logstash 

Logstash是一个具有实时渠道能力的数据收集引擎。使用 JRuby 语言编写。主要特点是几乎可以访问任何数据，可以和多种外部应用结合。支持弹性扩展。

（3）Kibana

Kibana 是一款基于 Apache 开源协议，使用 JavaScript 语言编写，为 Elasticsearch 提供分析和可视化的 Web 平台。

ELK 三款软件之间互相配合使用，完美衔接，高效地满足了很多场合的应用，并且被很多用户所采纳，诸如路透社，脸书（Facebook）StackOverFlow 等等。

系统被入侵，多数原因并不是系统本身的漏洞，而是系统上所运行的服务。运行的服务越少，被黑的可能性就越低，当日志服务器上仅运行一个日志服务或者 rsync 服务，那么这台服务器被黑的概率就很低，保障了日志的完整性。同时也为运行其他服务的系统腾出了更多的空间。总之，日志作为“电脑监控”而存在，它的价值是不言而喻的。
