# java 反序列化-开篇

简介  

**java 序列化**

`java序列化`（Serializable）是指把java对象转为字节序列的过程，便于保存在内存、文件、数据库中。`ObjectiOutputStream`类的`writerObject()`方法可以实现序列化。

**java 反序列化**

`java反序列化`(Deserializable)是指把字节序列恢复为java对象的过程，`ObjectInputStream`类的`readObjetion()`方法用于反序列化。

**Serializable 接口**

Serializable接口是一个标记接口，没有方法或字段，一旦实现了此接口，就标志该类的对象是可序列化的。

**序列化的目的**

序列化是为了让java对象脱离java运行环境的一种手段，可以实现`网络传输（RMI RPC）`，`对象持久化存储`。

## 漏洞基本原理

这里我参考了深入理解Java反序列化漏洞里的代码，先来了解一下序列化和反序列化

```
public class test{
    public static void main(String args\[\])throws Exception{
          //定义obj对象
        String obj\="hello world!";
          //创建一个包含对象进行反序列化信息的”object”数据文件
        FileOutputStream fos\=new FileOutputStream("object");
        ObjectOutputStream os\=new ObjectOutputStream(fos);
          //writeObject()方法将obj对象写入object文件
        os.writeObject(obj);
        os.close();
          //从文件中反序列化obj对象
        FileInputStream fis\=new FileInputStream("object");
        ObjectInputStream ois\=new ObjectInputStream(fis);
          //恢复对象
        String obj2\=(String)ois.readObject();
        System.out.print(obj2);
        ois.close();
    }
}
```

通过上面的代码，`ObjectiOutputStream`类的`writerObject()`方法可以实现序列化，`ObjectInputStream`类的`readObjetion()`方法用于反序列化。将String的对象obj1 序列化写入object文件，然后在从文件中反序列化得到对象。

```
public class test{
    public static void main(String args\[\]) throws Exception{
        //定义myObj对象
        MyObject myObj \= new MyObject();
        myObj.name \= "hi";

        FileOutputStream fos \= new FileOutputStream("object");

        os.writeObject(myObj);

        ObjectInputStream ois \= new ObjectInputStream(fis);
        //恢复对象
        MyObject objectFromDisk \= (MyObject)ois.readObject();
        System.out.println(objectFromDisk.name);
        ois.close();
    }
}
class MyObject implements Serializable{
    public String name;
    //重写readObject()方法
    private void readObject(java.io.ObjectInputStream in) throws IOException, ClassNotFoundException{
        //执行默认的readObject()方法
        in.defaultReadObject();
        //执行打开计算器程序命令
        Runtime.getRuntime().exec("open Calculator");
    }
}
```

## 序列化的条件

可以注意到Myobject 类实现了`Serializable`接口，并重写了`readObject()`函数，**要注意到只有实现了Serializable接口的类的对象是可以被序列化的**。实现`java.io.Serializable`的接口的类才可被反序列化而且所有属性必须是可序列化的(用transient关键字修饰的属性除外，不参与序列化过程)，上面代码的`readObject()`执行了`Runtime.getRuntime().exec("open Calculator")`，而 readObject() 方法的作用正是从一个源输入流中读取字节序列，再把它们反序列化为一个对象，并将其返回，readObject() 是可以重写的，可以定制反序列化的一些行为。

一个类的对象要想序列化，必须满足两个条件：

*   该类必须实现`java.io.Serializable`接口
    
*   该类的所有属性必须是可序列化的。如果有一个属性不是可序列化的，则该属性必须注明是短暂的
    

## 注意事项

这些注意事项， 在后面的文章中都会提及，这里做个了解

*   必须实现Serializable接口或Externalizable接口的类才能进行序列化
    
*   transient和static修饰符修饰的成员变量不会参与序列化和反序列化
    
*   反序列化对象和序列化前的对象的全类名和serialVersionUID必须一致
    
*   在目标类中添加私有的writeObject和readObject方法可以覆盖默认的序列化和反序列化方法
    
*   在目标类中添加私有的readResolve可以最终修改反序列化回来的对象，可用于单例模式防止序列化导致生成第二个对象的问题
    

## 漏洞成因

思考一下 为什么会出现反序列化漏洞？

作为用户，可控的点是HTTP请求的参数，当与服务器进行交互的接口存在反序列化功能，或可以通过接口实现Java反射来调用任意函数时， 就可以从使用者变成管理者，将恶意的代码，通过反序列化来执行系统命令。

总结一下：

*   输入反序列化的数据可控
    
*   暴露或间接暴露的反序列化API 如 开源的三方库，RMI 仓库
    
*   以及自定义协议，用来接收与发送原始的java对象

## 知识点

**java中extends与implements的区别**

Extends 可以理解为全盘继承了父类的功能。

implements 可以理解为为这个类附加一些额外的功能；interface 定义一些方法,并没有实现,需要 implements 来实现才可用。

extend 可以继承一个接口,但仍是一个接口,也需要 implements 之后才可用。

对于 class 而言，Extends 用于(单)继承一个类（class），而 implements 用于实现一个接口(interface)。

**RMI**

Java 远程方法调用，是一种用于实现远程过程的调用的应用程序编程接口。常见的两种接口实现为 JRMP(Java Remote Message Protocol ，Java 远程消息交换协议)以及 CORBA。在RMI中传输的数据一定是序列化的。

**JNIDI**

JNDI (Java Naming and Directory Interface) Java 命名与目录接口，是一个应用程序设计的 API，为开发人员提供了查找和访问各种命名和目录服务的通用、统一的接口。

JNDI 支持的服务主要有以下几种：DNS、LDAP、 CORBA 对象服务、RMI 等。

**JMX**

JMX 是一套标准的代理和服务，用户可以在任何 Java 应用程序中使用这些代理和服务实现管理,中间件软件 WebLogic 的管理页面就是基于 JMX 开发的，而 JBoss 则整个系统都基于 JMX 构架。

**HTTP**

多平台之间的通信，管理等
