回过头把Android的基础都复习了下，这里对apk的文件结构和打包流程记个笔记。

## APK文件结构

Apk 可以使用解压工具打开，下面是一个简单的apk文件结构，通常apk还有assets目录，用来存放静态资源文件  

![](../Images/55d847210572c25318a04769c04a636b.png)  

|   **文件或目录**   ||   **作用**   |
| --- | --- |
|   assets   ||   存放静态资源文件，不会被编译   |
| --- | --- |
|   lib   ||   .so文件（C/C++）   |
|   META-INF   ||   存放着apk的签名信息   |
|   res   ||   存放应用程序的资源文件   |
|   resources.arsc   ||   包含了已被编译好的资源的二进制格式文件   |
|   classes.dex   ||   运行在Dalvik虚拟机上的可执行文件   |
|   AndroidManifest.xml   ||   全局配置文件   |

## APK 打包流程图  

那apk为什么是这样的文件结构，通过他的打包流程图，就可以详细的了解  
![](../Images/7e5c370dd55a370cc4c38b37cc994f1f.png)

这里根据功能和处理方式将APK打包分为7个步骤

**1\. 打包资源文件，生成R.java**

使用aapt(Android资源打包工具) 来打包资源文件，生成R.java,resources.arsc(可以理解为资源索引表) 和res文件（二进制和非二进制res/raw和pic保持原样）

R.java会自动收录当前应用中所有的资源，并根据这些资源建立对应的ID，包括：布局资源、控件资源、String资源、Drawable资源等。我们可以简单的把R.java理解成是当前Android应用的资源字典。请求时通过R.id.filename即可

resources.arsc 可以理解为资源索引表，通过一样的ID，根据不同的配置(例如分辨率)索引到最佳的资源显示在UI中

**2.处理aidl文件，生成相应的Java文件**

AIDL （Android Interface Definition Language）是Android接口定义语言，Android提供的IPC （Inter Process Communication，进程间通信）的一种独特实现，实现进程间通讯，通过aidl工具解析接口定义文件然后生成相应的.java代码接口供程序使用

**3\. 编译项目源代码，生成class文件**

将项目中的R.java,Application Source Code 和Java 接口文件通过Java 编辑器(Javac) 编译成.class 文件，生成的.class文件,生成的class文件位于工程的bin/classes 目录下

apk通常在这一步对代码进行混淆编译，防止代码被盗用。

**4\. 转换所有的class文件，生成classes.dex文件**

在Android系统中Dalvik虚拟机的可执行文件为Dex格式，通过dx 工具将.class文件转换成classes.dex文件。

> dx --dex --output = C:\\Users\\Desktop\\classes.dex C:\\Users\\Desktop\\ceshi

所有的三方库和.class 文件都会被转换为.dex文件，dx工具在转换过程中还压缩常量池，消除冗余信息等作用、

**5\. 打包生成APK文件**

apkbuilder脚本工具将前面所有的文件，包括classes.dex、resources.arsc、res文件夹，其他资源，AndroidManifest.xml打包成apk文件

**6.对apk文件进行签名**

到这一步，已经形成了Release版本了，在某些模拟器上就可以直接安装未签名的app，但Android系统要求apk必须使用签名的apk，否则不能正常使用，在安装的过程中会检测META-INF文件夹的内容来校验APK完整性

对APK签名有两种签名keystore，一种是用于调试的debug，这是Android Studio默认的，另一个是发布正式版本的release签名，这个需要开发者自己配置

**7\. 对签名后的APK文件进行对齐处理**

使用工具zipalign对APK 进行对齐处理

Zipalign是一个android平台整理APK文件的工具，他对apk中未压缩的数据进行4字节对齐，可以提高硬件打开加载速度，这样通过内存映射访问apk文件的速度会更快，对齐的作用是减少运行时内存的使用。
