# 只是Work还不够，更重要的是Think

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzAxOTc0NzExNg==&mid=2665514113&idx=1&sn=5ec8b014afb2992c75d39c9cb51df1d8&chksm=80d67cc2b7a1f5d402cc9a227f68c96087efad43d9a6176e5cb0c548493a4f3e6f33dbb7a9f3&scene=126&sessionid=1681664463#rd](http://mp.weixin.qq.com/s?__biz=MzAxOTc0NzExNg==&mid=2665514113&idx=1&sn=5ec8b014afb2992c75d39c9cb51df1d8&chksm=80d67cc2b7a1f5d402cc9a227f68c96087efad43d9a6176e5cb0c548493a4f3e6f33dbb7a9f3&scene=126&sessionid=1681664463#rd)

今天无意中看到一条新闻：IBM第三季度营收为191.53亿美元， 销售额连续22个季度下滑，看来老东家还在艰难地转型之中。

回想起我在IBM的经历，让我感触比较深的一点就是 **Think **的文化。 

也许你用过IBM的笔记本电脑ThinkPad， 甚至用过IBM的台式机ThinkCentre。 你也许会想过：为什么叫做Think呢？   

（题外话： IBM的PC业务早在2004年已经被联想收购，现在PC的Think品牌属于联想，很多人认为ThinkPad T43以后的笔记本都不是纯正的ThinkPad了![](../Images/66cfae8d3a37fe1ee018a29bb5b282cb.png)）

Think其实就是鼓励创新， 不Think怎么可能创新呢？

很多公司都会提倡创新，在会议上、在文件中把创新提得震天响，但更多的是一些口号，标语，真正能把创新落到实处的公司却不多。  

因为创新这个词确实有点“虚”，对于普通员工来说，我怎么做才是创新？ 发表论文？申请专利？ 那也不是我的工作啊，我手头的工作还忙不过来呢，创新什么啊？！  

在IBM, 创新已经成为绩效考核，升职加薪的一部分了，每年在做年度计划的时候，要在个人绩效承诺中庄重地写上：我今年要publish x 个idea,  file x 个patent 。 

稍微解释下，“publish” 是说你的idea还达不到专利的要求，但是呢我们要把发布它，别的公司也不能就这个idea申请专利了，自然也不能收我们的“保护费”了，这是个防御性措施。所以publish 相对容易， "file"才是真正的申请专利成功，比较难。 

既然做出了庄重的承诺，年底总结的时候是要算账的，直接和加薪关联，所以得打起12分的精神去想各种idea了。 一个人绞尽脑汁也想不出来？不用怕，可以组成互帮互助的小组，大家一起头脑风暴。一个组内想法太单一？ 可以形成跨组织、跨部门的小组， 不同专业的人在一起好好“激荡”一下。 

诸位可以想象一下这个场景，IBM有几十万员工，每个人都这么干，得有多少新想法，新点子冒出来啊！ 

我看了下资料，IBM 2016年在美国获得了8088项专利，连续24年高居榜首！ 据说IBM单单是专利授权费用每年就有20亿美金的利润！ 非常可观。 

但是作为一个普通的程序员，很难像科学家那样天马行空地去创造出东西出来，即使是是从自己的工作中挖掘，提炼，找出对某个问题的新的、更有效的解决方法，想搞出一个专利的难度还是挺大的，专利只属于少数人。

对于大部分人来讲，没法成功申请专利怎么办？ 难道就没法升职加薪了吗？其实也不是，这里所说的创新，它的范围要比专利大得多。  

例如你发现了自己做的系统中需要手工执行的地方太多，开发了一个工具把他们给自动化了；你发现测试数据不好准备，写了一个脚本来帮忙，或者你引入了一种新的开发方式，新的技术...... 只要是能够提升效率，提高质量，改善流程的方式方法都算。  

只是有个限制，那就是**业务导向**，你的“创新”必须得围绕着业务来，给业务带来价值。 如果你说：老板，Go语言很火，我想学Go语言， 我们用Go 语言重写系统吧！  这是不行的。  

这种创新的氛围在公司是一个非常好的文化，它会引领着大家不断地改善、提高现有系统和流程，走向优秀和卓越。

就这一点而言，也是值得各公司借鉴学习的，不能够只是拿着鞭子赶着程序员快点做完！ 更重要的是要让程序员思考，让程序员Think。不能只看到眼前利益，要看得长远一些，这样无论是对公司还是个人都有莫大的好处。

对于个人来讲，如果所在的是一个主要由业务驱动的公司，天天实现业务是非常无聊的一件事情，很容易就变成熟手，就做烦了。如果你不让程序员想办法做点新鲜事，提升自己的能力（也顺便帮助公司），程序员是很容易跑路的。  

但是很多公司想做到这一点何其难也 ！ 活这么多，加班都干不完，你想Think，还是老老实实地Work吧。

回到IBM这个话题，我认为只要它能保持Think的文化，并且坚决贯彻执行下去，依托IBM深厚的底蕴，蓝色巨人的转型是一定能够成功的。

（完）
