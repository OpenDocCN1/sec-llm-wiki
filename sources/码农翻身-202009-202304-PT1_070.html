很想去一趟拉斯维加斯

我这个人吧，看到一个技术特别喜欢追根溯源，看看它是如何诞生的，解决了什么问题，一路走来发生了什么事情，这样就会有个整体的把握。


但是这样做有个坏处，相当于广度优先搜索，搜着搜着就会走入一个让我更感兴趣的岔路，忘记了主干，一条岔道走到黑。 


最近有个朋友向我咨询数据仓库的事情，我第一个反应就是 Amazon Redshift，毕竟是业界领先的云数据仓库嘛。 


Redshift 这个名称有个有趣的传说：Oracle 的数据库产品非常厉害，并且图标logo啥的都喜欢用大红色，所以想要 Shift Oracle to Amazon，就相当于Shift Red to Amazon， 于是就Redshift，不知道是真是假。


接着我就找 Redshift 的技术资料和发展历史，Redshift 从一个 MPP(无共享架构关系数据库）起家，成为数据仓库解决方案，在亚马逊云科技 re:Invent 2012年大会上正式宣布，成为完全托管的、PB 级的云数据仓库服务。


2015年 Amazon Redshift 已经成为亚马逊云科技历史上增长最快的产品，后来又相继推出联邦查询Amazon Redshift Spectrum，无服务器部署选项Amazon Redshift Serverless，可以分析 EB 级数据和复杂查询，奠定了数据仓库领导者的地位。


在这个过程中我经常看到一个词：re:Invent。因为 Amazon Redshift 很多新产品都是在re:Invent 上率先发布的。


作为敏感的程序员，第一反应可能是：re:Invent ? 重新发明轮子 ？


好奇心引发我走入了岔路口，不搜不知道，一搜吓一跳，这 re:Invent 哪里是什么技术大会，它简直就是一个大 Party 嘛。


先看看这举办地，著名赌城拉斯维加斯：



亚马逊的CTO，Dr. Werner Vogels 是个狂热的音乐迷，所以在 re:Invent 大会的压轴环节就是一场大型音乐会，经常有大牌摇滚乐队和音乐人被邀请在 re:Play 上演出，白天聊完了，晚上嗨起来吧！



除了这些，还可以感受速度和激情，黑客马拉松、电影之夜，乒乓球擂台赛、吉尼斯认证世界级的 Tatonka（鸡翅比赛）、复古街机、激光逃生室、无人机障碍训练场、攀岩墙、躲避球、弹跳城堡。 


总之，在这个大 Party 中每个人都能找到自己感兴趣的玩意儿。




你肯定要问了，这么多活动，得多少人参加啊？ 


2012年推出 Amazon Redshift 的第一届亚马逊云科技 re:Invent 大会有几千人参加，所有会议都可以在一个叫做威尼斯人的酒店搞定。


随后几年，人数不断攀升，最近这两年人数最高达到了6万多人，需要拉斯维加斯的六七家酒店才能容纳下！这还不包括音乐节的场地。 


拉斯维加斯每一个酒店都非常的大，商场赌场，各种游乐设施，住宿等结为一体，完全不是国人传统概念上的那种“酒店”。一个需要六七家酒店才能去覆盖得住的商业活动，是一个几乎无法想象的一个规模。


由于场地众多，需要频繁转移，有人甚至整理了参加 亚马逊云科技 re:Invent 的攻略，包括：


  • 提前几周买一双新跑鞋.....


  • 对拉斯维加斯不熟的话，事先一定要了解下街道，特别是会议场地......


  • 为手机、电脑准备足够的充电宝，数据线......


  • 准备些消食的药物，因为你会吃很多平时不吃的东西，会比平时喝更多的酒.....


......


做好这些准备，目的就是为了充分地参加自己感兴趣的技术活动。


因为 re:Invent 的技术活动实在太多了！


就拿2019年来说，有4个 keynote，还有3000多个技术演讲，一个人在四五天时间内，无论如何也是听不完的，只有选择好场次，规划好路线去参加有限的分享。


这些技术讲座有讲商业的，架构的，深入某个技术的，还有亲自动手练习的......满足 CTO、架构师、程序员等各个层次的需求，所以挑选适合自己的非常重要。


当然，所有的讲座视频都会被放到亚马逊云科技 Youtube 频道上，可以事后反复观看。 


我自己也看了不少视频，发现亚马逊云科技 re:Invent 有两个特点：


1. 特别关注用户的需求


一般的技术大会，主要就是讲自家的产品有多厉害，能解决什么问题，营销味道很足。 


而 re:Invent 上是倒过来的，它的分享一般是客户有什么问题，我们经过总结、提炼、沉淀，今年又推出了新的云服务，它具备什么样的特点，能解决什么问题。


这种问题驱动/需求驱动，拿案例来讲的方式很吸引人。


我个人也很喜欢，因为我自己写技术文章也喜欢先讲 why，而不是 how。


我印象最深的一个案例是2012年美国“好奇号”火星车降落火星的故事，当时 NASA 要对全球直播好奇号穿过火星大气层下降，并在火星上着陆的最后 7 分钟的情况。由于观看流量的不可预见性，NASA 根本没有视频流直播的基础设施。 


NASA 后来使用亚马逊云科技的流式处理来处理好奇号的图像和视频，仅用两三周时间就搭建了一个可以根据流量扩展，弹性十足的直播设施，全球公众都可以访问其 NASA，观看直播。


这样技术和案例的结合实在太酷了。


2. 特别喜欢讲解底层技术的实现原理


比如作为亚马逊 CTO，Werner Vogels竟然在 keynote 上花了很多时间大谈 Quorum 机制。Quorum 是一种种保证数据冗余和最终一致性的投票算法，不知道台下那些非技术人员有如何感想，毕竟太枯燥了。



但是，通过深入讲解底层原理，系统架构，最佳实践，让大家了解到亚马逊云科技底层是怎么做的，技术人员听完后，可以迅速到亚马逊云科技平台上做实践和验证（会议有很多动手操作的 session）。


这种非常踏实的感觉，从而获取大家的信任。


站在科技的最前沿领域，有趣有料，这可能是亚马逊云科技 re:Invent 能吸引如此多人员参会的重要原因。


围绕着 re:Invent，还有很多有趣的创作，例如 A Cloud Guru 公司还会对亚马逊云科技 re:Invent 会推出哪些服务做一些开玩笑似的预测，也从侧面说明了 re:Invent 的火热程度。


简单总结一下吧，re:Invent 是全球云计算引领者——亚马逊云科技举办的年度盛会，也是全球云计算领域全面而盛大的行业峰会。每年的亚马逊云科技 re:Invent 都会发布一系列引领未来的创新技术和服务，邀请全球各个行业、各种规模的客户以及亚马逊云科技合作伙伴分享最新的商业创新实践、因而成为了云计算行业的风向标，吸引着全世界开发者和用户的广泛关注和参与。


今年的大会依然是在拉斯维加斯，从11月28号到12月2号，一共五天，说实话，很想亲身去拉斯维加斯去体验一番，但是在疫情之下，这种想法也只能无奈放下，还好亚马逊云科技 re:Invent 开通了线上的会议，到时候在虚拟的会议中感受感受吧！
