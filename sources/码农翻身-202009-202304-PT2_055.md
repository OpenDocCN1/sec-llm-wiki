# 漫画 | 干掉session，爽死了！

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzAxOTc0NzExNg==&mid=2665523882&idx=1&sn=f79802e21df83adfbbe2209efc323b61&chksm=80d652e9b7a1dbffc9599aecd1599af32175ea8d07495a820e8f5ffda67de97575283c7b329a&scene=126&sessionid=1681664155#rd](http://mp.weixin.qq.com/s?__biz=MzAxOTc0NzExNg==&mid=2665523882&idx=1&sn=f79802e21df83adfbbe2209efc323b61&chksm=80d652e9b7a1dbffc9599aecd1599af32175ea8d07495a820e8f5ffda67de97575283c7b329a&scene=126&sessionid=1681664155#rd)

  

三十年前，我找了一份好工作，生活很悠闲。

  

![](../Images/262a549d75e1643aa555479cfb8fc03e.png)

  

没错，我就是个HTTP服务器，我的创造者们对我很好， 他们制定的HTTP协议超级简单， 就是请求<--->响应。

  

我特别喜欢HTTP协议的**无状态**：

  

![](../Images/eda06dd397a6c584395ab374863983fd.png)

  

无状态是由业务决定的，30年前的Web 基本上就是文档的浏览而已， 既然是浏览，我作为一个服务器， 为什么要记住谁在一段时间里都浏览了什么文档呢？

  

可是好日子没持续多久，交互式的Web迅速兴起，论坛、购物、聊天等网站都要求我记住一个人的登录状态。

  

![](../Images/a08d4e10a592f465d8be97a65abe962e.png)

  

我没有办法，只好给每个登录的人造一个箱子，把每个应用想放的东西放进去

  

![](../Images/54c764b5fd3647cb73376a478a587c8d.png)

这个叫session的办法能区分开登录的用户，大家都很高兴。

  

可是，每个浏览器只需要保存自己的session id，而我需要保存所有人的session id ！ 如果访问我的人多了， 就得有成千上万，甚至几十万个。

![](../Images/a6a581c5f4bb54001fc2e9e2b60f0692.png)

  

有些不着调的家伙还疯狂地往箱子里塞东西！

居然把庞大的购物车都放到session中。

  

![](../Images/52b2d8d4c10e5eba272e9e2d7b97d5e3.png)

  

这对我来说是一个巨大的开销 ，我不得不建了一座新房子

  

![](../Images/73b045c7d212cad4cb18fad81b6bdad2.png)

  

很快，麻烦来了

  

![](../Images/80a15935d6b66e49e217a5e5387f389e.png)

  

这样的事情越来越多，没办法，我只好做session的复制

  

![](../Images/be71d145048db6c13e01201b22d64f4a.png)

  

后来，我遇到了一个叫做Redis的家伙，让我集中存储到他那里。

  

![](../Images/9b9d46ecdc93ce91a1e530d152e8e918.png)

  

Redis的新方案虽然不错，但是增加了单点失败的可能性， 要是那个Redis的机器挂了，  所有人都得重新登录一遍， 估计得被人骂死。

  

我也尝试把这个单点的机器也搞出集群，增加可靠性， 但不管如何， 这小小的session 对我来说是一个沉重的负担。

  

![](../Images/f9e7ee304db5bc25b65326eaa2f2fb13.png)

  

但是让客户端去保留状态信息，有很大的安全漏洞，那些不怀好意的人可能伪造箱子。

  

![](../Images/846658a226b17a75d26cb4bbbead90d8.png)

  

关键点是验证，我得给这个箱子增加一点信息，证明是我创建的。

  

该怎么实现呢？Https这家伙给我支了一个招：

  

![](../Images/7bb915c2dea220b3d499dc6a924d384f.png)

  

然后在把这个签名和之前的数据放到一起，形成一个叫Token 的东西。

  

![](../Images/529b62459b90d932690173182e7b6ba5.png)

  

我在服务器端不保存Token，当客户端把token发过来的时候，我再用同样的算法做一个验证就行了。

  

![](../Images/b56b74de191956248b7a5c1c94f36c80.png)

  

如果相同， 我就知道这个人已经登录过了，并且可以直接取到他的user id。  

  

如果不相同， 数据部分肯定被人篡改过，那我就不客气了。

  

![](../Images/5e81292d3121350a13a6087452e2bf9b.png)

  

从此以后，我再也不用维护那众多的箱子了，我又回到了最初的美好时光：无状态。

  

验证token增加了一点儿计算的开销，不过[CPU阿甘](http://mp.weixin.qq.com/s?__biz=MzAxOTc0NzExNg==&mid=2665513017&idx=1&sn=5550ee714abd36d0b580713f673e670b&chksm=80d6787ab7a1f16c39e1258d046b199c06a4dcc95dc192ff2f285be04f616a9ab891d6b3f7d9&scene=21#wechat_redirect)那傻小子跑得飞快，这点儿计算对他来说不算什么。

  

![](../Images/8490224eef3987136b9f4d8afe4929f8.png)

  

不过，所有的事情都是双刃剑。

token很快就遇到了问题

  

![](../Images/86057e1c78df3d0a0d9587100ce26a09.png)

  

过了一会儿，这个家伙又过来找我了

  

![](../Images/262e87770846067123640f78fc58fda5.png)

  

有了有效期，我就可以检查这个token是否过期了。

  

可是这小子很执拗，非要立即退出，非要在服务器端让Token立刻失效，有效期不行，气死我了。

  

被逼急了，我只好在墙上记了一个黑名单

  

![](../Images/a8f1914a9c7eb82c30592faeb4bc1bcc.png)

![](../Images/89955af1915ab99d4ba32d12c4685454.png)

  

看来，想在服务器端干掉session，干掉状态，几乎不可能啊！
