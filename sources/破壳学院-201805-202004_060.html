个人背景

Li，本科，电子信息工程专业，毕业一年半，有javascript、php、python 语言基础，目前自学Web 安全中。

笔记内容如下

一、溯源的目的

溯源的目的更多的是清理已经植入服务器的各种病毒，然后找到入侵的源头，也就是黑客是通过什么漏洞入侵服务器的，课程总结的是服务器被入侵挖矿溯源的经历。


二、溯源的过程

1.查看服务器的进程情况

输入 top 命令，再按大写 P ，根据CPU利用率来看看进程：

看到有一个进程的 CPU 占用率到达 99.7%。


2.再查看端口连接信息

终端输入 netstat -anpt

 看到有一个IP 为 158.69.133.20:3333 明显不是我们自己的异常 IP


3.查询IP信息

用IP查询地理位置（http://www.ipip.net/ip.html）

可以看到这是一个国外的 IP。


再到威胁情报平台查询 IP 信息

(比如：http://x.threatbook.cn/ip/158.69.133.20)

 可以看到这是一个矿池情报。可以确定服务器被入侵了，被植入了挖矿程序。

 

4.查看该进程的具体信息，并 kill 掉它

kill 掉，为了防止恶意进程占用大部分的 CPU 资源，导致排查过程缓慢。


5.其次,进入 var/temp 目录,可以看到相关文件

     

6.提取文件的 md5值，并检验

再到 https://www.virustotal.com/ 查询，可以看到这里有60款软件，有20款都对它报毒,这是一个挖矿程序。如下图所示：


7.查找日志和 history 看看是否有 wget、curl等下载行为。

从经验来看，这种挖矿程序，一般都是通过bash脚本进行执行，然后下载进行启动，可以通过查找日志和 history 看看是否有 wget、curl等下载行为。

上图可以很明显看到有 wget 行为。


8.下载脚本分析行为。

由于下载地址还没有失效，可以直接下载脚本分析行为

  • 除了 /var/tmp 目录下的文件，其他文件已自删除

  • 脚本中还修改了 crontab任务


清理的方式：直接删除 /var/tmp 目录下的恶意文件

同时，根据脚本的分析和 syslog 中看到脚本是通过 crontab 任务中 root 账户下载执行的，那么我们直接查看 /var/spool/crontabs/root 文件。

     

可以看到系统的 crontabs 任务已被修改了，加入了一些其他任务，我们把这些任务清理掉就可以了，可以看到任务的内容有 REDIS0006字样，我们可以排查到，这是Redis存在未授权访问的问题。修复方法：对应修复 Redis 的配置问题关闭外网访问，增加密码验证。妈妈再也不用担心我被黑了。


总结一下，这是一个比较顺利的溯源过程，通过前一个步骤、或者历史痕迹查到或猜测到黑客的相关操作，甚至可以获得脚本进行行为分析，但是在实际的溯源过程中，黑客会删除日志、清理相关痕迹、相关链接会失效。先学到这里了，嘿嘿，本次课程主要是建立大家对溯源的概念和认知。
