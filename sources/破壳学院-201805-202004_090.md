**2018.08.06（周二），漏洞分享和漏洞经验**

  

相信很多小伙伴学习了前面的课程之后，对于安全也有了一定的了解，今晚就由我来给大家讲解一下我们应该如何去学习这些漏洞以及利用哪些方法去学习我们的 web 漏洞！  

  

在讲漏洞学习之前，我先给大家分享一下安全从业人员的日常工作！  

  

![](../Images/da850dc6b2964b5a6fbe2745f8eddcb2.png)

  

一般我们都是通过公司单位去接各种各样的安全测试项目。我们到达客户现场之后，都会跟客户确认我们需要测试的范围，测试的时间，测试的内容，测试的地点。因为我们的目的跟黑客不同，黑客是奔着破坏和利益的方向去的，而我们是为了提高技术，也是为了帮助客户解决安全问题的。所以一旦我们确定了测试范围，时间，内容和地点。我们才会开始工作。在测试的过程中，我们通常都是会去检查和尝试网站的每个功能，比如说：

  

**我们看到了输入框或者表单，都会习惯性地想到了 XSS 了。看到了上传的功能，我们就会联想到文件上传漏洞。看到 URL 后面带有传输的参数，我们就会想到SQL注入，XSS，命令、代码执行，或者是文件包含漏洞等。**  

  

![](../Images/dec289a742cebe78d3e3035741d1566c.png)

  

因为每个网站的功能都大同小异，要么就是进行了某些参数与数据库的交互，要么就是输入提交表单，要么就是上传，要么就是中间件漏洞等等。  

  

所以我们一开始学习漏洞的时候，只需要大概清楚漏洞的原理，最重要的是要学会，看到这个功能我能联想到什么类型的漏洞！当然这个要靠你的细心了，因为很多时候，你测试不出来并不代表这个网站不存在这个漏洞，而是你利用的方式不对！比如说，我插入了 XSS 的测试 payload ，但是却始终弹不出来，可能是浏览器问题，可能是标签被过滤了，也可能是其他情况。所以我们教给大家的是一些常见的测试方法和测试语句。在日常渗透测试的过程中，最终还是要靠你的耐心和仔细了。而且最最重要的是，我们要学会使用百度和 Google 。很多漏洞我们都会在课程给大家进行详细地讲解。所以各位小伙伴们也一定要认真地跟紧我们的学习进度！  

  

****![](../Images/83c55f04273bc1bceaf97fa1edd2e584.png)****

  

接着给大家分享一下我们经常使用的测试环境和测试工具了。  

  

我们渗透测试中，最常用的几种系统就是：windows7，kali，centos 和 MAC 了，最常用的工具有：burpsuite，sqlmap，中国菜刀，子域名挖掘机等，最常用的扫描器有：nmap,nessus,AWVS,Appscan 等。   

  

以上说的这些，都是在测试我们网站的时候，最常用的工具了，特别是 burpsuite ，可以配合很多种工具来进行使用。而且在后面的课程，我们也会不断地给大家补充这些工具的安装和使用办法。  

  

接着我给大家分享一下 PT 老师日常的渗透流程和思路：  

  

PT 老师接到一个网站之后，第一步就是会去仔细地点击网站的每个功能，每个链接。在脑海中形成大致的框架；  

  

第二步就会收集该网站的信息，包括：使用的操作系统，使用的数据库，使用的中间件，网站的子域名，该网站是不是由某种 CMS 进行二次开发，网站的后台管理系统；  

  

第三步，对 web 应用成的功能进行逐步的测试，比如说：输入框，上传功能等；（ XSS , SQL, 文件上传，命令执行，代码执行，CSRF 等）  

  

第四步，查看该网站是否存在逻辑漏洞；（垂直越权，平行越权，短信轰炸，任意用户注册，任意用户登陆，未授权访问等）  

  

第五步，查看网站是否存在弱口令，比如说：网站后台，数据库，tomcat 管理后台等。（FTP 弱口令，Mysql 弱口令，sqlserver 弱口令，tomcat 弱口令，windows 密码爆破，linux 密码爆破等）  

  

第六步，对以上收集到的信息进行综合分析，对每个功能进行抓包分析，每个参数进行测试，看是否存在隐藏的漏洞！（ SQL 盲注等）  

  

第七步，整理漏洞信息出漏洞报告！

以上就是PT老师日常渗透的流程以及思路！  

  

**2018.08.09（周四），日常渗透测试中常见的 XSS 问题**  

  

鉴于很多同学在完成 XSS 作业的时候遇到很多问题，今晚呢，PT 老师给各位小伙伴分享一些在日常渗透测试中常见的 XSS 问题，我们会从作业中抽几道题来讲。后面的题目就要依靠小伙伴们自己去完成啦！

  

在讲解作业之前，我们先要巩固一下 XSS 的知识点！

  
我们只需要知道反射型 XSS 和储存型 XSS 即可，因为 DOM 型的 XSS 在现在的网站都是很少出现的，而且利用方式复制，利用点低。所以我们 DOM 型的 XSS 了解即可！

  

![](../Images/d82645a7db50d5b2bfcb23e9f0a54afe.png)

  
所谓反射型 XSS 就是非持久型 XSS ，可以理解为一次性使用的 XSS ，即使通过 URL 直接传输我们的跨站脚本攻击代码，并不会每次点开就会触发。一般这种 xss 可以用来盗取 cookie 。在前面的课程我们已经明白 cookie 的作用了。所以我们只要盗取到被害者的网站 cookie ，接下来我们只需要找到网站响应的登陆后台或者登陆框即可直接绕过验证机制，进入被害者网站的后台或者用户中心了！一般在后台和用户中心都会有上传和数据库备份的功能，所以黑客们就可以尝试上传各种 webshell ，获取到我们网站相对应的权限，进而可以导致我们的服务器被攻击者控制！

  

![](../Images/ff0a35ed69c990c8a85bb00163b357b1.png)

  

但是我们一般情况下都不会直接去利用 XSS 进行攻击，在进行安全测试的时候，我们只需要让网站弹出框或者在网站内插入恶意的攻击代码即可！ 

  

接下来我们讲一下储存型 XSS ，储存型 XSS 就是将攻击代码直接通过网站放到我们的数据库里面，这样的代码攻击是持久型的。只要我们每次点开被攻击的网页，就会相对应地弹出我们熟悉的框框，或者在网站上插入相对应的 iframe 等等。

  

![](../Images/461a816c363c17c3736a3bb1bdd2dba9.png)

  

因此储存型 XSS 的危害是比较大的，它可以造成蠕虫攻击，可以在网站上挂马，可以在网页上留下煽动社会的非法言语，甚至可以记录我们的键盘操作。

  

一般在外网，储存型 XSS 的漏洞是比较少的，但不代表没有，所以小伙伴想深入学习储存型 XSS 的话，我们就可以搭建靶场，比如说：DVWA ,也可以在漏洞平台查找已经出现过这种漏洞的 CMS 系统进行搭建，然后按照网络上的教程进行操作！

  

所以小伙伴们在学习 XSS 的时候，不需要太急于担心怎么利用 XSS 进行攻击，你应该想办法如何让网站弹出或者获取到你想要的资源！在找 XSS 漏洞的时候，我们可以使用谷歌语法：inurl:'Product.asp?BigClassName 来找存在有输入框的网站进行练习，但小伙伴一定要尽量找小的网站哦！

  

接下来我们给大家讲解一下挖掘 XSS 漏洞的基本思路：

  

1.我们看到网站存在输入框或者文本框的时候，我们就会用基本的语句：

  

<script>alert('xss')</script> 或者 <img src=1 onerror=alert(1)> 来插入进行测试，插入之前，我们可以打开我们浏览器的 F12 审查元素进行观看，观看我们插入之前和插入之后网站源代码发生了哪种变化，或者观察网站的 URL ，看看 URL 是否传送了我们插入的攻击代码，插入之后，网站是否对我们的攻击代码进行了过滤或者编码呢？

  

2.确认网站是否过滤了我们插入的攻击代码之后，我们针对我们被过滤的标签进行 URL 编码或者其他操作，这里我们会给大家附上一些常用的 XSS 测试语句！

  

3.如果我们的标签被过滤了，比如说：script 被过滤了，我们是否可以这样考虑，我们将 script 进行 url 编码，或者利用大小写 Script 等等

  

4.尝试使用键盘触发的 XSS 代码进行测试，比如说用 oninput 进行键盘触发。
