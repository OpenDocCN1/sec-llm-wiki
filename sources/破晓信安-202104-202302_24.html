交易支付

描述

1.支付过程中可修改支付金额。

2.没有对购买商品数量进行限制

3.支付过程中对购买商品编号进行篡改

检测方法

1.利用burpsuite工具，对支付页面进行抓包，修改支付的金额。

2.利用burpsuite工具，对支付页面进行抓包，修改购买的数量，查看价格是否改变。

3.利用burpsuite工具，对支付页面进行抓包，修改商品编号，查看价格。

防御

1.对于传递重要的参数信息应当加密隐藏

2.传递多个参数之间应当检测数据的一致性

密码修改与找回

描述

利用漏洞修改、找回他人帐号密码，甚至修改、找回管理员的密码。

检测方法

1.利用抓该包工具，修改要修改用户的ID，达到修改其他ID用户的密码目的。

2.短信验证码可以重复使用，攻击者就可以修改用户的密码。短信验证码未与用户绑定，攻击者可以利用其他用户的包来修改本用户的密码。

3.未验证旧密码是否正确

3.短信验证码未验证是否与用户绑定手机关系

防御

1.每次调用用户数据时必须检验当前登陆用户是否有权限调用

2.验证旧密码

3.短信验证码要验证是否为用户绑定手机所接收。

越权

描述

越权分为垂直越权和水平越权。

同级别为水平，反之为垂直。

检测方法

1.修改用户ID

2.登陆时，用不同的手机号接码并登陆其他手机号账户。

防御

增加验证

短信炸弹

描述

短信轰炸攻击时常见的一种攻击，攻击者通过网站页面中所提供的发送短信验证码的功能处，通过对其发送数据包的获取后，进行重放，如果服务器短信平台未做校验的情况时，系统会一直去发送短信，这样就造成了短信轰炸的漏洞。

检测方法

利用burp或者其它抓包截断工具，抓取发送验证码的数据包，并且进行重放攻击，查看手机是否在短时间内连续收到10条以上短信，如果收到大量短信，则说明存在该漏洞。

防御

合理配置后台短信服务器的功能

验证码绕过

描述

验证码可被绕过，执行暴力破解等操作。

检测方法

1.手机验证码，抓包查看返回包是否存在验证码。

2.其他手机号接收的验证码是否可以进行登陆等操作。

3.验证码是否长期有效，对账户进行爆破。

防御

1.增加验证

2.验证码设置时效性。

状态码修改

描述

登陆或者其他的过程修改状态码即可绕过。

检测方法

1.修改HTTP状态码，如302修改为200是否可登录成功等.

2.身份登陆成功时code:0，登陆失败为1，将失败修改为0查看是否登陆成功。

防御

对控制身份的数据包要做好严格限制。

未授权访问

常见分类

Redis 未授权访问漏洞
MongoDB 未授权访问漏洞
Jenkins 未授权访问漏洞
Memcached 未授权访问漏洞
JBOSS 未授权访问漏洞
VNC 未授权访问漏洞
Docker 未授权访问漏洞
ZooKeeper 未授权访问漏洞
Rsync 未授权访问漏洞
Atlassian Crowd 未授权访问漏洞
CouchDB 未授权访问漏洞
Elasticsearch 未授权访问漏洞
Hadoop 未授权访问漏洞
Jupyter Notebook 未授权访问漏洞
Apache ActiveMQ 未授权访问

原理

未授权访问漏洞，是在攻击者没有获取到登录权限或未授权的情况下，或者不需要输入密码，即可通过直接输入网站控制台主页面地址，或者不允许查看的链接便可进行访问，同时进行操作。

测试方法

一、通过对登录后的页面进行抓包，将抓取到的功能链接，在其他浏览器进行打开。

二、也可以通过web扫描工具进行扫描，爬虫得到相关地址链接，进行直接访问，如果未进行跳转到登录页面，则可判断为存在未授权访问漏洞。

三、登陆以后，可利用新的浏览器访问登陆后的每一个功能链接。

防御

在系统中，加入用户身份认证机制或者tonken验证，防止可被直接通过连接就可访问到用户的功能进行操作，简而言之，一定对系统重要功能点增加权限控制，对用户操作进行合法性验证

多点认证缺陷

描述

系统允许多点认证。

检测方法

1.在浏览器A中使用测试账号登录系统；

2.同时在浏览器B中使用同一个账号登录系统；

3.若在多个浏览器中均可登录同一各账号，说明存在多点认证缺陷。

4.攻击者在获取到其他用户的账号密码后，可利用该缺陷在用户已登录且未知的情况下进行登录，操作用户账户。

防御

议在不影响业务的前提下，关键业务系统应禁止多点认证。当同一账号在其他地方登录时已登录的账号应退出会话，并提示用户账户在其他地区登录，可能存在账号被盗风险。

会话重用

描述

用户退出系统后，服务器端Session未失效，攻击者可利用此Session向服务器继续发送服务请求。

检测方法

通过客户端提供的注销功能退出客户端登录，利用登录时的会话再次向服务器发出操作请求，判断服务器是否返回操作结果。攻击者通过网络嗅探或者钓鱼攻击窃取用户的Session信息，在用户注销系统后，如服务器端未直接清理此Session，则攻击者仍可利用窃取到的Session成功访问系统直到Session过期。

防御

用户退出系统后，服务器端应清空此用户的Session信息。

jsonp跨域请求

描述

当某网站通过 JSONP 的方式来传递用户认证后的敏感信息时，攻击者通过构造恶意的 JSONP 调用页面，诱导被攻击者访问来达到截取用户敏感信息的目的。

检测方法

一个典型的 JSON劫持攻击代码：

<script> function test(v){   alert(v.username); } </script> <script src="http://www.xxx.com/?o=sso&m=info&func=test"></script>

当被攻击者在登陆www.xxx.com网站的情况下访问了该网页时，那么用户的隐私数据（如用户名，邮箱等）可能被攻击者劫持。

攻击者可利用该漏洞结合社会工程学，诱导用户点击某个精心构造的页面，从而达到窃取用户敏感信息的目的。

防御

严格安全的实现CSRF方式调用JSON文件：限制Referer、部署一次性Token等。
