靶机介绍

脚本可以参考刚才所提及的房间里面有，或者是这位大佬的Github脚本 https://github.com/hum4nG0D/OSCP_Bufferovrflw_Prep。本次的脚本编写也是融合了这两位大佬的脚本算是一个造轮子的过程。

02

信息收集


还是需要先用nmap进行信息收集这次开了21端口可匿名登录，3389和一个奇怪的9999端口。

命令:nmap -sS -sV -sC -v -p- -T4 -Pn ip
























ftp ip连接以后可以看到有个文件夹叫chatserver，里面有个.exe的文件。
























如果想传输过来的话首先需要输入binary进行二进制模式，为了保证文件无任何乱码或者是BUG，执行文件需要在二进制模式下传输。
























这里在ftp输入binary进入二进制模式，然后使用GET下载下来。
























这里我把程序拖入到window10虚拟机中，可以看到程序正常运行。


03

分析程序


程序运行以后会在虚拟机开放9999端口,可以在kali上使用nc连接一波。这里先看看程序的一个流程。首先有个欢迎标语然后让你输入一个用户名，输入完用户名以后再写条信息。系统会输出当前时间然后变成复读机重复你说的话再次让你输入信息。
























这里我先用python模拟一下我的行为。当然还未能实现循环回复功能。
























这里看看运行效果，除了不能实现循环意外基本上模仿成功。


04

寻找缓冲区溢出点


通过刚才测试大概发现有两个输入点，一个是一开始的输入名字另外一个是写信息那里。由于这里有两个输入点先不直接上模糊测试，先看看哪里可能存在溢出点。
























这里先在kali下准备好3000个字符串作为测试

命令:python

Print(‘A’ * 3000)
























开始测试，现在输入用户名里面丢3000个字符串进去发现可以继续执行下一步输入信息。那么继续在写信息这里丢3000个字符串瞬间卡住进行不到下一步。
























Windows10虚拟机下用Immunity Debugger发现程序已经停住不动了。可以确认写信息这里有缓冲区溢出点。
























重新运行chatserver以后在输入框输入这条语句后续用mona联动方便点。


05

编写脚本


首先需要kali下的/usr/share/Metasploit-framework/tools/pattern_create.rb 脚本帮我们创造出字符串字符出来-l 指定输出多少个字符串。这里还是3000个字符串
























然后丢到第二个脚本里面。把刚复制好的字符串丢到string1变量里面。
























可以成功执行。
























回到windows虚拟机上。正常情况下下进入暂停状态。然后在输入框输入!mona findmsp -distance 3000可以看到有条语句提示EIP contains normal pattern xxx offset 2012。2012就是这个程序能承受的极限。
























如果想确定2012是不是程序的极限，可以用这个新的脚本更改IP，offset数值，和retn变量为BBBB去验证。
























成功运行。
























这里打开回虚拟机Immuntiy Debugger进入暂停状态。EIP显示的是42424242即16进制的BBBB























下一步就是寻找坏字符串看看哪个坏字符串会影响后面shellcode的编译当然\x00必是坏字符串。先在Immuntiy Debugger输入!mona bytearray -b “\x00”通知这是个坏字符串。
























检查坏字符串的话我们需要从\x01到\xff逐一遍历。
























把所有字符串贴到新脚本bad变量里面。
























重新运行以后使用!mona compare -f C:\mona\chatserver\bytearray.bin -a ESP地址 语句发现居然没有坏字符串运气挺好的。
























到倒数第二步了，找完坏字符串需要找跳跃点。为后续准备在输入框输入!mona jmp -r esp -cpb "\x00“有以下跳跃点。随便选一个即可。这里我选择头顶的。
























使用msfvenom生成shellcode,这里先使用本地IP测试。本地测试如果没问题那靶机也应该没问题。
























这里用最后一个脚本，填上IP，端口，offset数值，和刚才jmp反过来的地址。最后payload填上刚才msfvenom的shellcode。
























最后我直接改为靶机IP地址可以成功接收反弹shell,权限也很高。
