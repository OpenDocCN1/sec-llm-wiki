# 0x01:Fuzz测试

这里先解释一下Fuzz测试，你可以理解为啥都往里丢测试。由于我们现在进行的是缓冲区溢出测试，重点在溢出。有点像把水倒入杯子里面，观察倒多少水才能溢出来。而我们通过这个模糊测试可以大概判断出这个程序的极限可以接收多少数据。

![](../Images/a3340836213e4c82661634201ab0caf0.png)

  

  

这里先把github上的第一个脚本01-fuzz.py稍微改装一下，红点指的地方即为需要更改或稍微添加的地方。

![](../Images/b5b762a466b210e7674e8abc6ed7aa32.png)

![](../Images/a3340836213e4c82661634201ab0caf0.png)

  

然后直接python运行，FUZZ测试后发现程序大概在接收2100 bytes左右崩了

![](../Images/a3340836213e4c82661634201ab0caf0.png)

# **0x02:精准定位**

虽然我们大概知道程序崩溃点大概在2000-2100左右但还没确定一个精准的位置。所以下一步就是要确认程序崩溃的位置在哪。首先我们需要借助kali自带的pattern\_create.rb脚本创造很多很多字符串

![](../Images/d9dc63b51d20c8a0f8497c5bb0c0d6ee.png)

![](../Images/a3340836213e4c82661634201ab0caf0.png)

  

  
  

这里建议用网页所提供的脚本然后复制粘贴到buffer这个变量里面下面就稍微改改IP地址之类的。重新运行程序一次。

![](../Images/c8836f606e8efd87bb038710fd14e206.png)

![](../Images/a3340836213e4c82661634201ab0caf0.png)

  

  
  

然后再Windows上运行!mona findmsp -distance 3000(这个数字是可以更改的根据前面你生成的字符串数量)。可以看到有个EIP contains normal pattern 0x6f43396e (offset 1978)的字样。(EIP寄存器存储着CPU要读取指令的地方尽头只到了1978这个位置说明极限可能在这里)。

![](../Images/cc6fa7f1a0741cf4fa492ff0d29478a3.png)

![](../Images/a3340836213e4c82661634201ab0caf0.png)

  

  
  

如果想验证一波极限是否在这里的话可以在刚才的脚本里面设置一个返回值。比如说4个B

![](../Images/d3a3d42d77f6e7c18f4868c6dc9d1c0f.png)

![](../Images/a3340836213e4c82661634201ab0caf0.png)

  

  
  

此时稍微更新一波脚本把offset变量的值设为1978 retn可以设置为BBBB或者其它也可重新运行一次脚本

![](../Images/1d135f5c3a327e755ba1dc099f16befe.png)

![](../Images/a3340836213e4c82661634201ab0caf0.png)

  

  
  

可以看到此时的EIP已经覆盖变成42424242了(16进制下的BBBB)

# **0x03:寻找坏字符串**

现在我们已经找到一个程序崩溃可以覆盖掉的点了。接下来是寻找坏字符串。由于我们后期是通过写shellcode进程序把它弄崩溃以后获得一个反弹权限。但有些shellcode程序会不认可，这会导致我们的shellcode写入失败。常见的坏字符串有\\x00(空字节), \\x0A(空格), \\x0D(回车),\\xFF(换页)。但这并不是固定的，每个程序的坏字符串都有可能不一样，不过\\x00应该是上黑名单首页的。

![](../Images/a3340836213e4c82661634201ab0caf0.png)

  

  
  

这里可以用网页所提供的py脚本生成字符串，然后丢到程序里慢慢排查有哪些字符串是坏字符串

![](../Images/4f1de36323b70cb161a5161f9d29cf0b.png)

![](../Images/a3340836213e4c82661634201ab0caf0.png)

  

  
  

这里把py生成的字符串贴到bad变量里面稍微更改下IP地址就可

![](../Images/5d102ff474501852227b245aa9ff7fc1.png)

![](../Images/a3340836213e4c82661634201ab0caf0.png)

  

  
  

回到windows被攻击机这里找一波ESP的地址然后用!mona compare -f C:\\mona\\oscp\\bytearray.bin -a ESP地址

![](../Images/31cb61c57f1189355bcc9afa33ac67a7.png)

![](../Images/a3340836213e4c82661634201ab0caf0.png)

  

  
  

这里会弹出一个对话框，嫌疑目标是6个。并不代表着6个全都是坏的有可能是其中某些坏了连累了后面的。00就可以自动忽略了系统也提示了Bytes omitted from input 00

![](../Images/a8820f51dee663e4195a630136ad27be.png)

![](../Images/a3340836213e4c82661634201ab0caf0.png)

  

  
  

这里其实就是排错法了。把07在脚本里面删了，坏字符串这里07还在上榜，08没了

![](../Images/9a3df1735f77d89f3e0db13dda999a61.png)

![](../Images/a3340836213e4c82661634201ab0caf0.png)

  

  

把08从脚本里面删了，07还在坏字符串榜上，08也上榜了，07是内鬼坏字符串。

这里更新一波生成的字符串去除那四大天王。

# **0x04:寻找跳跃点**

然后我们就要找波跳跃点，用这条mona指令, -cpb是用来识别错误字符

!mona jmp -r esp -cpb “\\x00”

![](../Images/a3340836213e4c82661634201ab0caf0.png)

  

  
  

这条命令可以查找所有的jmp esp指令，这些指令的地址不会包含任何指定的badchar。

  

输入完以后我选择最头顶的0x625011af

![](../Images/4cc8a5468457c94c2c6f0292d82ec5d4.png)

![](../Images/a3340836213e4c82661634201ab0caf0.png)

  

  
  

这里就可以把该地址写到retn这个变量里，不过要注意要反着来写而且要加\\x

![](../Images/15ea65b29510402f608d9b8f337e7eba.png)
