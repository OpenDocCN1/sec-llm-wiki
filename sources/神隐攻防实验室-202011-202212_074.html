0x01:缓冲区

先说一下缓冲区的概念，由于计算机程序经常需要从网络、文件等不同来源读取一些数据。所以程序会经常分配一段有限的空间让数据储存起来。而这段内存空间就是缓冲区。

       比如说现在有个简单的C程序例子要求我们输入一个名字然后打印Hello+输入的名字。这个应该难不倒大家。比如说现在我输入makabaka, makabaka 这个词会先储存到缓冲区(内存空间)中直到程序执行printf 输出结果命令的时候，程序会从缓冲区中找回刚才存放的用户名数据 makabaka 然后输出结果”Hello makabaka”

例子:


#include <stdio.h>int main () {//定义主函数   char username[20];//指定变量名的地方以及分配20个字符空间
   printf("Enter your name: ");//输出信息   scanf("%s", username);//接收输入的参数
   printf("Hello %s\n", username);//输出结果      return(0);}

0x02:应用程序内存，堆栈和内存空间

这里引入一个新的词。堆栈是一个内存缓冲区，用于存放程序的功能和局部变量。

下面的图是一个应用程序内存结构图。
    (Application memory = 程序内存；
    heap=堆
    dynamic memory = 动态内存
    stack=栈
    Function Calls = calls函数
    local variables = 局部变量
    global variables = 全局变量
    base code = 基础代码)


  1. 首先程序由源代码构成(code)，它们是程序的主要指令来源。然后就有了存储全局变量的缓冲区（static /global）。局部变量和全局变量的区别在于局部变量仅限于某个函数。它是在某个函数已经定义好的只能在该函数中调用，而全局变量可以在主函数中定义也可在函数外部定义。此类变量无限制。

  2.  之后去到堆栈(stack)这里，这里也是缓冲区溢出发生的地方同时也是存储本地变量和函数调用的地方。最后就是堆(heap)这里是一个动态内存分配的地方。

0x03:缓冲区发生溢出的原因

前面介绍了一些基础知识现在开始进入正题。缓冲区溢出发生在输入的数据长度超过缓冲区容量时。同时程序会把数据写入分配到缓冲区之外，有可能覆盖用于保存程序所用数据的内存其它部分进而使程序崩溃。这里还是用回第一个C程序作为例子在return前加入printf("Program exited normanlly");观察程序是否可以正常回显。

      


#include <stdio.h>
int main () {   char username[20];
   printf("Enter your name: ");   scanf("%s", username);
   printf("Hello %s\n", username);   printf("Program exited normanlly");   return(0);}



首先用gcc编译一波然后执行我们还是输入makabaka可以看到有提示Program exit normanlly表示程序正常退出，然而当我们尝试输入n个b以后程序执行失败。同时没有显示Program exit normanlly这段提示词只显示有个segmentation fault。由于我们输入了太多个b，多余的bbb超出了20个字符缓冲区容量并覆盖了其它数据(这里指打印程序正常退出那段”)。这也导致了系统提示segmentation fault,因为程序坏了。

0x05:缓冲区溢出的危害

当某些二进制文件或程序设置成setuid二进制时很容易被人攻击。Setuid可以理解为任何用户执行这个文件时都会以root的权限运行，如果你找到溢出点把它给弄崩溃，那么你的权限很有可能直接从普通用户直接提权成为root。
