# **0x00:基础知识**  

在讲解如何利用该漏洞之前需要简单介绍一下文件上传漏洞。文件上传漏洞可能是攻击者伪装成正常用户登录网站以后尝试在上传功能点上传恶意的脚本。由于网站开发可能未对上传文件做出文件后缀限制保护，导致攻击者上传了一个与网站脚本语言相同的恶意代码动态脚本到服务器上。上传成功后，攻击者访问该文件利用菜刀，蚁剑，weevely进行连接,尝试接管低级shell。从而进一步影响网站安全。

攻击者为了偷懒多半会使用一句话木马。毕竟只用几行代码就搞定一个木马的制作大部分人还是会选择偷懒的。同时杀伤力也很强大，当把木马上传成功后可以在本地借助工具从而获得服务器权限。常见的一句话木马有以下:

php:  @eval($\_POST\['cmd'\]); ?>

asp: <% eval=""> 或 <%>

aspx: <%@ page="" language="Jscript"> <%eval(request.item\["cmd"\],"unsafe");%>

此外也可借用工具生成常见的一句话木马。这里推荐kali下的weevely,语法如下

![](../Images/db5f1aaa5e4b93b2b0637762fc1feee2.png)

  

当然weevely的缺点就是只能生成php马。所以我们还需要一波中国蚁剑

![](../Images/84d64371a964c2a6c8ec3107a755e1dd.png)

  

接下来借用暗月大佬的靶场讲解常见的十个文件上传漏洞场景

# **0x01:未作任何限制的文件上传**

第一种场景为上传点未作任何限制即可以上传任意文件想上传啥就上传啥。这种情况比较少见了。大部分网站开始有点安全意识了可能会做出一点限制。先看一下第一个场景，先正常的选择一张图片

![](../Images/92e7012e03b0666c84475a1acdf19346.png)

  

然后点击submit,返回一个存放地址

![](../Images/9f5392cf185c3cd71d411ecfc455c4ef.png)

  

那我们可以跟过去，可以正常访问

![](../Images/ccdb0428831ed07dc56f81ebe9dbacef.png)

  

那么尝试使用一个刚用weevely 生成好的php马传上去以后连接。当出现weevely 或输入一些命令函数可执行成功的时候代表拿到一个第权限的shell了。

![](../Images/e6a45ea9bc65bdb4365f2984ec336886.png)

  

# **0x02:客户端JS验证绕过**

第二种情况是在前端有一点点的JavaScript检查措施，比如我现在还是上传一个hello.php木马上去，直接弹窗说该文件类型不允许上传。

![](../Images/3175737ed69c93e5673666fc5a77f7b9.png)

  

先不要着急,按F12查看波源代码，此时在<< span="">script>里面出现了一个check.js

![](../Images/e8d4fb4741c363a8a54b675d2cf4ab6f.png)

  

跟过去一看，发现是检查内容只允许上传.jpg,.gif,.bmp。其它类型的文件果断反弹该文件类型不允许上传。那么我们的方法有两种，最简单粗暴的就是在浏览器中把JS代码给删了，或者是我们先给木马改成.jpg格式在上传的过程中偷包把它改回为.php上传回去。

![](../Images/fd53a477b5d69ba77570696af2762c4a.png)

  

那么首先在kali下用mv帮我们的木马改成.jpg格式

![](../Images/f664c5ebbd565c467828a825642530b6.png)

  

随后使用抓包技术在上传的时候把.jpg改回.php模式点击Forwarded

![](../Images/f556a8d841a560f9cf091fef5f4a6c29.png)

  

很快啊它显示出路径就是代表上传成功了。

![](../Images/d382b941d5312d2d044fda6bfb39d2a9.png)

  

我们用回weevely连输入部分命令可执行成功。

![](../Images/4db5aadd050f5729b370a561c3275855.png)

  

# **0x03:黑白名单绕过**

一些网站的安全意识可能还不错，把文件后缀名限制的死死的.php必不可能被上传，但是网站开发可能会对后缀名没有过滤全导致有漏网之鱼。所以最快的方法就是暴力穷举看看有哪些漏网之鱼可以上传成功

当然头铁的话可以去试一下不过必被禁止

![](../Images/78e1ec2bc1a8ff5eeb44c73d01b72733.png)

  

那么我们需要搜寻波常见的后缀名，为了捡漏多点漏网之鱼我们可以把后缀名转换成大写，或者是首字母大写增加概率。

![](../Images/5e05d2015fb2d250ed277a68b86176b1.png)

  

正常上传一个文件用Burp抓包发到Intruder那里，对后缀名进行穷举

![](../Images/691d59041ba8263f02d8c6c393b36285.png)

  

Payload选择刚才准备好的常见后缀名

![](../Images/726a167aaa1068b25e6a26f46602ac12.png)

  

开始start attack,可以根据最长的length判断是否成功，点到response拉到最下面发现返回文件路径可以确定.asp,大小写皆可上传

![](../Images/dc693714210392a876efcc9936a9c136.png)

  

由于我们的weevely只能支持php马所以我们需要先制作一个.asp的马

![](../Images/b098738444592d210dec496c12964ca3.png)

  

然后使用中国蚁剑进行连接。

![](../Images/7a089269d45136dd9c11309ec50af785.png)

# **0x04:content-type检测绕过**

第四种情况是content-type的检测绕过,首先先正常的上传可以看到有一个content-Type:image/jpeg点击放包

![](../Images/aa20a21edf62c7de629d8dd479510780.png)

  

可正常上传

![](../Images/7912f2bcafdd6931ca6f578ac7caaf2c.png)

  

这次换成.php的一句话木马此时发现content-Type变为了 application/octet-stream

![](../Images/99a12d329486626477fc99f61bdbc5be.png)

  

结果是当然上传不了。。。。

![](../Images/99a12d329486626477fc99f61bdbc5be.png)

  

此时再次重新上传一次把content-Type改为跟.jpg一样的 image/jpeg点击Forwarded啪的一下就上传成功了。

![](../Images/9cbe2954c050d10c2c13d49e61347c41.png)

  

由于上面的图片马出了点问题稍微改了一下，用新的。

![](../Images/e943f38405cf28aebdba4770e29e5580.png)

  

此时使用蚁剑测试了一波显示连接正常。

# **0x05:文件头检测绕过**

最后一种文件头检测绕过需要多观察一波。比如说正常的上传1.jpg文件

![](../Images/65210e6ca0ecabbed5e74ebd3e71fe42.png)

  

结果发现正常的.jpg文件也不支持了。

![](../Images/2da67b7134fc22430c205e0d0560e504.png)

  

只能换成1.gif格式

![](../Images/6c36cc7cfaed45f75c0c2e4e92cd9cb4.png)

  

啪的一下就上传成功了。

![](../Images/e08106b1fd0aa42f4b05065b6a660576.png)

  

  

也可以用之前的方法改content-type和客户端js绕过方法试一下但都凉了。这里可以用到Linux的strings来查看一波里面的格式。.jpg多是以JFIF为开头而.gif是以GIF89a开始。

![](../Images/e99bc0b17dc8202198d23a9d34adcd9a.png)

  

  

那么我们可以用GIF89a图片文件欺骗绕过的方法。简单的来讲就是文件上传功能点可能只会对文件头一开始的那部分做检测。那么这里可能只需要一开头有GIF89a就行了。其它危害内容不care。

![](../Images/c070847029bfa380aa0d7c1a74738a7e.png)
