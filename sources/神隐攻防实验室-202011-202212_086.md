# **如何找到反序列化漏**

  **无论是白盒测试还是黑盒测试找到反序列化漏洞还是比较简单的。**首先我们需要观察一下传递到网站的所有数据。并尝试识别任何看起来像序列化数据的内容。假如我们知道不同语言序列化的格式使用则相对容易辨识出来。**下面会讲一下PHP和JAVA序列化的例子。**一旦你找到序列化的数据尝试看看能不能控制它们。

# **`Java序列化格式`**

**Java是用二进制作为序列化的。**由于是用二进制所以比较难读取数据。但是如果你知道一些明显的迹象，仍然可以识别序列化数据。

      不如Java序列化对象始终以相同的字节做为开头，**这些字节在16进制是 ac和ed而Base64是ro0。**

      **任何实现接口java.io.Serializable的类都可以进行序列化和反序列化。**假如可以代码审计网站源码的话，注意有没有readObject()函数。它可以用来从inputStream读取和反序列化数据。

# **更改数据类型**

前面已经讲了如何更改序列化对象来实现漏洞的，这里再讲一下如何利用数据类型实现漏洞。由于PHP的逻辑在比较不同的数据类型时,通常会用到**\==**比较一波，而这种特别容易受到操控进行攻击。比如整数和字符串进行比较的时候,PHP会尝试把字符串转为整数。这也意味着5==”5”计算结果为True。这种情况也适用于数字开头的任何字母数字字符串。在这种情况下,PHP将根据数字有效地将整个字符串转为整数值。字符串的剩余部分将会被完全忽略。**因此5==”某物中的5”将会被认为5==5。**这里其实翻译的时候是有点问题。原文为5==something of 5，这里的something可以理解为具体的一个数字。就强行拆解了。比较整数0的字符串的时候,这变得更加奇怪:

  

*   

```

```

  

  

为什么这句话没问题?因为没有数字,所以字符串中的数字为0。PHP会把整个字符串视为0。考虑到整个松散的比较方式和反序列化对象中的用户可控数据一起使用的情况，这可能会导致危险的逻辑缺陷。

看看以下代码:

  

*   
*   
*   
*   

```
$login = unserialize($_COOKIE)if ($login['password'] == $password) {// log in successfully}
```

  

假设攻击者可以修改了password属性,使其包含整数0而不是预期的密码字符串。**只要存储的密码不是不是以数字开头，这个条件永远判断为True,从而启用身份验证绕过。**要注意的是,因为反序列化可保留数据类型。如果代码直接从请求中获取了密码,则0会转为字符串。并且条件评估为False。要注意的是,在修改任何序列化对象格式的数据类型时,也要注意更新序列化当中的长度，布尔值等等。否则序列化对象会被破坏并且不会执行反序列化。
