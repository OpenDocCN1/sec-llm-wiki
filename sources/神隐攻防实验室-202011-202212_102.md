# **0x00:靶机介绍**

这次的靶机是Netmon,难度应该不会太难还是有很多人做出来的。

![](../Images/d55836369839341b4e224ac9c5561368.png)

  

# 0x01:探测靶机

这里得到IP(10.10.10.152)，以后为了更好的获取信息还是决定用Nmap进行扫描,这里主要开了,21端口(可匿名登录),80(HTTP服务,即正常网页,还有135,139,445,其它大的端口暂时忽略。命令:nmap -A -sS -sV -v -p- 10.10.10.152

![](../Images/da1a80d592387304ee29fa4614e20e39.png)

  

访问波80端口，可以正常访问，是个表单页面。

![](../Images/a64fd9cec12b3d69430c5019465d2e09.png)

  

# **0x02:拜访21端口**

在刚才通过nmap扫描的时候我们知道21端口是允许匿名登录(Anonymous FTP login allowed),这里就直接ftp + IP登录，用户名即Anonymous,成功登录。

![](../Images/44b80263eb1ce5e4c7a821c1cd87cc31.png)

  

这里发现ls,和dir均可以使用，接下来就是到处浏览了，先dir(列出点前文件)一波以后进入到User目录，再爬到Public里面发现了一个user.txt，使用get下载下来。

![](../Images/4f30b31c1409882caf557048419b6b99.png)

  

Emmm好吧，user的flag好像挺简单的。

![](../Images/6531385e42b9268eba99fc5d19eead43.png)

  

# **0x03:集中火力输出80端口**

这里回到80端口观察一波，首先这是一个登录框页面，所以可能存在POST注入可以使用波sqlmap自己跑一下，同时这个页面设计的挺好看的可能是个CMS可以把PRTG network monitor关键词提取出来，拿到网上搜索一下。

![](../Images/a64fd9cec12b3d69430c5019465d2e09.png)

  

这里我先让sqlmap自己动起来先。

![](../Images/50c1eb98f854939c47536660ef9ab4d5.png)

  

这里跑了一会以后sqlmap还是倒了，只能上网查了一下搜到相关CVE，CVE-2018-9276，操作系统命令注入漏洞，然而需要一个账号登录进去才行。。。。 

![](../Images/74f96d307e8eff3efde5d7aebdba182d.png)

  

那么回到原点，这是一个监控系统，只要不是独家的就可以把它当做一个CMS看待，这样的话必然有一个配置文件或者是默认账号这里在必应找到一个讲配置文件存放地方的链接:https://kb.paessler.com/en/topic/463-how-and-where-does-prtg-store-its-data#:~:text=All%20system%20settings%20%28except%20license%20keys%20and%20Enterprise,installed%20previously%29.%2032-Bit%20Systems%3A%20PRTG%209%20or%20later%3A

![](../Images/3cf4017dc2995379f911dd1ff8b8ac81.png)

  

# **0x04:二次拜访21端口**

爬回去看nmap扫描到的信息，这是台windows Server 2008 R2的服务器应该是对应的第一个存放位置，然后我又想起ftp端口是有windows目录存放的可能要爬回ftp端口了。

![](../Images/44b80263eb1ce5e4c7a821c1cd87cc31.png)

  

这里回到ftp端口这次换成dir -a (类似ls -la)，有一个ProgramData,对应刚才链接里面存放的地方那我们就开始cd不断跟进了。

![](../Images/8885e2f78d8496b621ec4c3f531c8935.png)

一直跟进到PRTG Network Monitor里面发现了3个 Configuration,这里选择用get 下载.dat和.bak

![](../Images/05b5ccbd15e173ae18276f2f365b4af3.png)

  

下载完之后打开.bat emmm只能说包含的信息实在太多了这里我慢慢用搜索功能搜索关键字提取信息服务器版本: PRTG Network Monitor 18.1.37.13946最后一次登录的用户名:prtgadmin

![](../Images/e621ceeb76367f118416c5822d9adb25.png)

  

密码有可能是这两个其中的一个

![](../Images/0694db3628407bafafc878864604725c.png)

  

然而让我裂开的是我在.bat搜索了password半天，结果我在旁边的old.bak里面发现有个明文输出密码形式。。。

![](../Images/f133c2b77024ac50312eeff0d9fac879.png)

  

你以为得到的密码就是对的嘛?错了还得恶心你一下，观察一波，.bak是18年的而.dat是19年的也就是说这个密码是过时的，由于CMS的默认账号密码是为懒人设计的只需要把最后一位改为9就行了。。。

![](../Images/05b5ccbd15e173ae18276f2f365b4af3.png)

  

成功登录

![](../Images/e8abd4b47ff6b103f3640556f0d9d703.png)

  

# **0x05:不讲武德直接拿flag**

我们可以刚才的链接，来搞破坏

![](../Images/74f96d307e8eff3efde5d7aebdba182d.png)

  

由于花了一下午复现都没成功，没办法我只能出阴招了，登录成功以后点击setup,然后再点Notification

![](../Images/3d62057445a4cbc390154b6b6f3dcff5.png)

  

点击右边的Add new notification

![](../Images/cea1622fe0719ec284b3ca00692254d9.png)

  
给Notificaiton取个名字啥都行

![](../Images/347ab5a9af9ab6d7946cd073f9a35594.png)

  

  

然后拉到下面点击Execute Program, 在Program File 选择Demon exe notification -outfile.ps1然后在Parameter输入:`test.txt; Copy-item "C:/Users/Administrator/Desktop/root.txt" -Destination "C:/Users/Public/root.txt"(``这里解释一下``CVE-2018-9276``在P``arameter``这里存在命令执行漏洞,可以从这里g``etshell,``然而我的脚本死活运行不了，只能换种方法把r``oot``的flag偷出来，我们需要猜到r``oot``的flag位置，可以通过ftp端口那里在/``users``下有2个目录分别是A``dministrator``和public，只能猜还有个d``esktop``目录下才包含flag，我们可以通过c``opy``命令把它拷贝到p``ublic``目录下来进行读取)`

![](../Images/30769118e68f3041d51eaf75afaefcc7.png)

  

写完以后再回到上面的Notification Summarization点第一个选项，点击save保存

![](../Images/ed3366adf2c7030650a7354a70e7ed6c.png)

  

之后回跳转到一个新页面，最后点下test1(shiyan失败了)再点击蓝色的小铃铛会弹出就行了

![](../Images/5edf99dde2563512d2580db2af185c14.png)

  

最后成功得到flag

![](../Images/12341f466e8c9cee0555f4a0f0299ce5.png)
