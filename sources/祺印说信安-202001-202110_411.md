# Windows编解码器库漏洞允许远程执行代码

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzA5MzU5MzQzMA==&mid=2652086858&idx=1&sn=856e30adec9a9bbcd4cc7e91e3e348df&chksm=8bbc8873bccb0165dfda91ddacb061612484e2e86923634a908f2e0d8a4339bd72066c3c7d5b&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzA5MzU5MzQzMA==&mid=2652086858&idx=1&sn=856e30adec9a9bbcd4cc7e91e3e348df&chksm=8bbc8873bccb0165dfda91ddacb061612484e2e86923634a908f2e0d8a4339bd72066c3c7d5b&scene=27#wechat_redirect)

微软周二发布公告详细介绍了解决Windows编解码器库中的两个远程执行代码漏洞。

  

这两个漏洞与受影响的Windows组件处理内存中对象的方式有关，并且都具有7.3的CVSS评分。

  

利用CVE-2020-1425可以使攻击者用于进一步破坏系统的数据，针对第二个安全问题发布的公告中CVE-2020-1457，Microsoft指出成功利用该漏洞将导致任意代码执行。这些漏洞在处理特制图像文件时触发。

  

![](../Images/c17cbea032a66f31b309f8202285279b.png)

  

Microsoft没有提供有关攻击者可能利用该漏洞的攻击媒介的具体详细信息，但针对类似漏洞的攻击通常涉及诱使用户打开制作的恶意文件。为了解决安全问题，Microsoft更正了Windows Codecs库的内存中对象处理。

  

漏洞影响32位、64位和基于ARM64的系统以及Windows Server 2019和Windows Server 1709版，Windows 10版本1709、1803、1809、1903、1909和2004 1903和2004（服务器核心安装）。

  

微软已为系统发布为系统发布漏洞补丁程序，补丁程序将通过Microsoft Store自动推送到客户机器，客户也可以使用Microsoft Store App检查更新。
