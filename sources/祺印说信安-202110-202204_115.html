2022 年 2 月 25 日

2022 年 2 月 24 日，赛门铁克企业‍报告‍称，与 HermeticWiper 恶意软件一起部署了一个名为 PartyTicket 的勒索软件。IBM Security X-Force 获得了 PartyTicket 勒索软件的样本，并提供了技术分析、危害指标和检测。


2022 年 2 月 23 日，开源情报来源开始报告在属于乌克兰组织的系统上执行的擦除恶意软件（一种旨在永久破坏目标数据的破坏性恶意软件系列）的检测。IBM Security X-Force 获得了一个名为 HermeticWiper 的擦除器样本。它使用良性分区管理器驱动程序（empntdrv.sys的副本）执行其擦除功能，破坏所有可用物理驱动器的主引导记录 (MBR)、分区和文件系统（FAT 或 NTFS）。

这不是 X-Force 分析的第一个针对乌克兰组织的擦除器恶意软件。2022 年 1 月，X-Force 分析了WhisperGate 恶意软件，没有发现 WhisperGate 和 HermeticWiper 之间有任何代码重叠。

本文将详细介绍 IBM Security X-Force 对 HermeticWiper 恶意软件的洞察、样本的技术分析以及入侵指标 (IoC)，以帮助组织保护自己免受这种恶意软件的侵害。

为什么这很重要

今年 1 月，X-Force 分析了WhisperG‍ate 恶意软件。HermeticWIper 是过去两个月中观察到的第二个新发现的破坏性恶意软件系列，针对乌克兰的组织，据报道还有东欧其他国家。WhisperGate 和 HermeticWiper 之间没有发现代码重叠。

这些新的破坏性恶意软件家族的部署和发现速度是前所未有的，进一步凸显了组织需要拥有超越基于签名的防御的积极和明智的防御策略。

随着地区的军事冲突不断发展，鉴于 WhisperGate 和 HermeticWiper 的破坏性能力， 该区域目标地区内的关键基础设施组织应该加强防御。这些组织应专注于为可能破坏或加密数据或以其他方式显着影响运营的潜在攻击做好准备。

破坏性网络攻击可能会继续用于支持混合作战的民用目标，网络攻击很可能会随着持续冲突的范围而继续升级和扩大。应该指出的是，越来越多的针对与乌克兰及其盟友相关的私营企业和实体的破坏性能力可能会通过对区域商业造成更高的威胁来改变网络安全环境。

分析细节

本节包含对提交的样本执行的分析结果。典型的分析包括行为分析和静态分析。

行为分析描述了执行期间在系统上观察到的恶意软件行为。行为分析通常包括在系统上执行的操作，例如文件删除、持久性、流程执行的细节和任何 C2 通信。应该注意的是，行为分析可能无法捕获所有值得注意的恶意软件行为，因为某些功能只能由恶意软件在特定条件下执行。

静态分析是对恶意软件技术分析的更深入研究。静态分析通常包括有关功能、样本中的混淆或打包、恶意软件使用的加密、配置信息或其他值得注意的技术细节的更多详细信息。

行为分析

执行后，HermeticWiper 立即调整其进程令牌权限并启用SeBackupPrivilege。这为恶意软件提供了对任何文件的读取访问控制，而不管访问控制列表 (ACL) 中指定了什么。

然后会检查系统的操作系统版本，以了解它将使用哪个版本的良性分区管理驱动程序（EaseUS 分区管理器：epmntdrv.sys）。驱动程序最初是 Microsoft 压缩的（SZDD 压缩）并嵌入其名为 RCDATA 的资源中。

对于 Windows XP：

  • x86 – 使用 DRV_XP_X86

  • x64 – 使用 DRV_XPX64

对于 Windows 7 及更高版本：

  • x86 – 使用 DRV_X86

  • x64 – 使用 DRV_X64

在验证它将使用什么版本后，将 SZDD 压缩的良性分区管理驱动程序放在以下目录中：

%WINDIR%\system32\driver\<random_2chars>dr
Example: C:\Windows\system32\Drivers\vfdr

然后继续解压缩并添加“ .sys ”作为文件扩展名。

Example: C:\Windows\system32\Drivers\vfdr.sys

然后再次调整其进程令牌权限以启用SeLoadDriverPrivilege。这个令牌使 HermeticWiper 进程有能力加载和卸载设备驱动程序。

接下来，通过修改以下注册表项来禁用故障转储：

HKLM\SYSTEM\CurrentControlSet\Control\CrashControl
CrashDumpEnabled = 0

请注意，故障转储是包含系统意外停止原因信息的内存转储。禁用此选项后，将阻止系统创建任何转储，从而成功覆盖其轨迹。

如果启用，它还会禁用卷影服务 (vss)，并禁用所有 HKEY_USERS 注册表中的ShowCompColor和ShowInfoTip ：

HKEY_USERS\<ID>\Software\Microsoft\Windows\CurrentVersion\Explorer\Advanced
ShowCompColor = 0
ShowInfoTip = 0

ShowCompColor选项以彩色显示压缩和加密的 NTFS 文件，而ShowInfoTip显示文件夹和桌面项目的弹出式描述。

HermeticWiper 然后继续使用诸如OpenSCManagerW()、OpenServiceW()、CreateServiceW()和StartServiceW()等 Windows API 添加和加载创建的驱动程序作为服务。

例子：

这会在注册表中创建一个服务条目：

HKLM\SYSTEM\CurrentControlSet\services\<random_2chars>dr

一旦良性驱动程序服务启动并加载到系统中，就会通过删除 %WINDIR%\system32\drivers 中创建的驱动程序并删除注册表中创建的服务来再次掩盖其踪迹。

HermeticWiper 通过循环 0-100 枚举最多 100 个物理驱动器的范围。使用现在加载到系统中的良性分区管理器来破坏系统中存在的每个物理驱动器的所有主引导记录 (MBR)。

但并不止于此，还会破坏所有可用的分区，甚至支持 FAT 和 NTFS 文件系统。对于 NTFS，还会破坏保存有关文件的所有信息的主文件表 (MFT)，以确保数据不可恢复。

一旦所有磁盘都损坏，系统应该会导致崩溃，但为了以防万一，HermeticWiper 创建了一个故障安全睡眠线程，触发系统关闭以强制重启目标系统。

服务：

PartyTicket分析

被称为 PartyTicket 的勒索软件样本是 Golang 编译的勒索软件，据信与针对乌克兰组织的 HermeticWiper 恶意软件一起分发。

PartyTicket 勒索软件不包括任何权限升级，并将在当前用户的上下文中执行，意味着如果使用非特权账户执行，则需要更高特权的文件夹和文件将不会被加密。

PartyTicket 将“ .[ vote2024forjb@protonmail.com ].encryptedJB ”作为文件扩展名添加到它加密的所有文件中，同时使用 RSA 和 AES 来加密目标文件。

对勒索软件的初步静态分析揭示代码中引用的“Biden”和“Whitehouse”。

执行后，PartyTicket 勒索软件通过检查从 A: 到 Z: 的所有可用驱动器并遍历所有目录（包含“Windows”和“程序文件”的目录除外）来构建要加密的文件列表。

在遍历目录结构时，勒索软件会枚举包含以下扩展名的文件的目标列表：

.acl, .avi, .bat, .bmp, .cab, .cfg, .chm, .cmd, .com, .crt, .css, .dat, .dip, .dll, .doc, .dot, .exe, .gif, .htm, .ico, .iso, .jpg, .mp3, .msi, .odt, .one, .ova, .pdf, .png, .ppt, .pub, .rar, .rtf, .sfx, .sql, .txt, .url, .vdi, .vsd, .wma, .wmv, .wtv, .xls, .xml, .xps, .zip, .docx, .epub, .html, .jpeg, .pptx, .xlsx, .pgsql, .contact, inc

请注意，.exe包含在要加密的目标文件中，表明勒索软件随后会自行加密。

创建目标列表后，勒索软件将为目标列表中的每个文件创建一个具有通用唯一标识符 (UUID) 名称的自身副本。副本作为原始 PartyTicket 进程的子进程以 30 秒超时执行，每个进程负责加密目标文件列表中的文件。

示例 PartyTicket 子流程执行生命周期：

C:\Windows\system32\cmd.exe cmd /c copy <PartyTicket.exe> b6771851-a968-11eb-9f9f-000c29fc4fde.exe
b6771851-a968-11eb-9f9f-000c29fc4fde.exe.exe <target_file_to_encrypt>
timeout /t 30 && C:\Windows\system32\cmd.exe /C del <UUID>.exe

目前，建议组织对本报告中列出的文件系统、注册表和 Windows 服务指标实施检测，并利用提供的 Yara 规则扫描文件。此外，全球企业应寻求对其各自的网络、供应链、第三方以及位于或服务于区域内机构的合作伙伴关系建立健全的洞察力。还建议组织开放相关信息共享实体之间的通信线路，以确保接收和交换可操作的指标。

除了与妥协指标相关的响应措施外， 建议组织考虑以下主动措施：

  • 阻止所有 B2B VPN 上的高风险协议

  • 在所有出口点实施网络流量监控

  • 制定应急计划以断开 B2B VPN，尤其是那些高风险的 VPN

  • 防止加载未知的驱动程序文件
