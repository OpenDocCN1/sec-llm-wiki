微软2022年1月份于周二补丁日针对 98个漏洞发布安全补丁

原文：http://mp.weixin.qq.com/s?__biz=MzA5MzU5MzQzMA==&mid=2652091768&idx=1&sn=e958488e1061a0ccaecac12982165c71&chksm=8bbc9f41bccb1657e52fbedcb4d2c2afa833dd57aa3e4cf0179eb7defc3791d9de6187711de0&scene=27#wechat_redirect

本次是微软2022年第一期漏洞修复，微软2022 年的第一组更新涵盖了其软件生态系统中 98 个安全漏洞，微软敦促客户优先修补所谓的关键“可蠕虫化”漏洞。
这些补丁涵盖了微软一系列产品组合，包括 Microsoft Windows 和 Windows 组件、Exchange Server、Microsoft Office 和 Office 组件、SharePoint Server、.NET Framework、Microsoft Dynamics、开源软件、Windows Hyper-V、Windows Defender、和 Windows 远程桌面协议 (RDP)。
其中CVE-2022-21907（CVSS 评分：9.8），是一个根植于 HTTP 协议栈的远程代码执行漏洞。在大多数情况下，未经身份验证的攻击者可以利用 HTTP 协议栈 (http.sys) 将特制数据包发送到目标服务器以处理数据包。


来自俄罗斯安全研究员米哈伊尔·梅德韦杰夫发现并报告了这个可蠕虫化的漏洞，意味着不需要用户交互来触发和传播感染。当然，大家想到可蠕虫化可能会想到震网病毒、永恒之蓝（想哭病毒）等。Virsec 首席架构师 Danny Kim 表示，尽管微软提供了官方补丁，但这个 CVE 再次提醒我们，软件功能允许攻击者滥用功能进行恶意行为。
作为补丁星期二更新的一部分，微软还解决了六个零日漏洞，其中两个是与开源库 curl 和 libarchive 相关的第三方修复的集成。
  • CVE-2021-22947（CVSS 评分：N/A）——开源 curl 远程代码执行漏洞
  • CVE-2021-36976（CVSS 评分：N/A）——开源 libarchive 远程代码执行漏洞
  • CVE-2022-21836（CVSS 分数：7.8）– Windows 证书欺骗漏洞
  • CVE-2022-21839（CVSS 评分：6.1）——Windows 事件跟踪任意访问控制列表拒绝服务漏洞
  • CVE-2022-21874（CVSS 分数：7.8）——Windows 安全中心 API 远程代码执行漏洞
  • CVE-2022-21919（CVSS 评分：7.0）– Windows 用户配置文件服务特权提升漏洞
另一个严重漏洞涉及Windows Internet 密钥交换 ( IKE ) 版本 2 中的远程代码执行漏洞（ CVE-2022-21849 ，CVSS 评分：9.8） ，微软表示远程攻击者可能将其武器化为触发多个漏洞而不正在被认证。

最重要的是，该补丁还修复了一些影响 Exchange Server、Microsoft Office ( CVE-2022-21840 )、SharePoint Server、RDP 和 Windows 弹性文件系统的远程代码执行漏洞以及 Active Directory 域中的权限提升漏洞服务、Windows 帐户控制、Windows 清理管理器和 Windows Kerberos 等。

Exchange Server中发现的三个漏洞（CVE-2022-21846、CVE-2022-21855和CVE-2022-21969，CVSS 分数：9.0）必须立即应用补丁来应对针对这些弱点的潜在现实世界攻击。美国国家安全局 (NSA) 已确认标记 CVE-2022-21846。

另外，一月份，Adobe 发布了 5 个补丁，解决了 Acrobat 和 Reader、Illustrator、Adobe Bridge、InCopy 和 InDesign 中的 41 个 CVE。如果用户打开特制的 PDF，其中最严重的可能导致远程代码执行 (RCE)。美国人认为，其中一些漏洞在我国去年天府杯上进行了成功演示，因此在未来的某个地方看到这些漏洞在野外使用也就不足为奇了。InCopy的更新修复了三个严重级别的 RCE 错误和一个重要级别的权限提升。InDesign的补丁更正了两个可能导致代码执行的严重分级越界 (OOB) 写入错误以及适度的 Use-After-Free 权限升级。Adobe Bridge的修复涵盖了六个错误，但只有一个 OOB 写入被列为关键。其他是特权升级和内存泄漏的混合。最后，Illustrator的补丁涵盖了两个 OOB 读取错误——这两个错误都不能用于代码执行。
