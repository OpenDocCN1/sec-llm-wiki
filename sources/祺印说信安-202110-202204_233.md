# 网络安全知识体系1.1风险管理和治理（五）风险评估与管理方法（下）

风险管理国际标准ISO/IEC 27005包含与NIST指南类似的活动（见图6）。它包括一个建立背景阶段，其主要目的是实现NIST准备阶段和IRGC预评估阶段的成果。风险评估阶段是多层次的，包括识别、评估和评估阶段。这与IRGC 的评估和特征描述阶段一致。ISO 27005 也有风险沟通和风险监控和审查阶段，广泛涉及NIST沟通和维护阶段的目标，以及IRGC 的跨领域沟通、背景和参与阶段。ISO /IEC 27005 有额外的元素来明确捕获风险管理决策过程，但它没有规定如何实施它们。包括与沟通和审查相关的治疗和接受阶段，抓住了一些基本的管理方面，提供治疗或接受的选择作为评估过程的一部分。

![](../Images/236331d0ef87771f07cd8e0a8fc36ac2.png)

  

ISO /IEC 27005 方法的这一方面类似于NIST的风险响应要素SP800-39 风险管理指南，其中风险应对选项包括接受、避免、缓解或共享/转移。这种比较得出的结论是，虽然风险评估阶段的风险评估方法可能不同（取决于所分析的系统类型和研究范围），但准备、沟通和持续监控阶段是广泛使用的国际准则中的必备条件，以及围绕风险承受能力的重要决定。ISO /IEC 27005 的规范性不如NIST，因此提供了在整个过程中包含一系列评估和管理方法的选项。

可以在中找到常用的组件驱动的网络风险管理框架列表。该列表还包括简要说明、它们如何工作的概述、应该使用它的人以及成本和先决条件的指示。虽然不希望在此处重现整个列表，但我们提供了一个概述以供比较。

l ISO /IEC 27005:2018 是一套国际标准的信息风险管理指南。它没有规定具体的风险评估技术，但确实有一个组件驱动的重点，并要求具体说明漏洞、威胁和影响。

l NIST SP800-30/39 是美国政府首选的风险评估/管理方法，是美国政府机构强制执行的。他们有很强的监管重点，这可能与美国以外的国家无关，但他们有一套明确的指导步骤来支持从建立背景到风险容忍度的整个风险评估和管理过程，以及有效的控制，包括确定影响的可能性。它们是免费提供的，并且符合ISO标准（不是免费的，但成本低）。

l 信息安全论坛（ISF）制定了IRAM 2风险管理方法，该方法采用多个阶段，利用脆弱性、威胁和影响措施识别、评估和处理风险。它提供给ISF的（付费）成员，需要信息风险管理专业知识才能有效地使用它，这可能需要额外的成本。

l FAIR最初由Jones开发，随后与OpenGroup合作开发为OpenFAIR，提出了风险因素的分类法和组合风险因素的框架。威胁面可以被认为是非常广泛的，并且明确关注损失事件频率、威胁能力、控制强度和损失幅度。它还将财务损失因素分为多个级别，并支持情景模型来构建可比较的损失概况。。

l Octave Allegro 面向运营风险和安全实践，而不是技术。定性风险评估与组织目标相关联。真实场景用于通过威胁和影响分析来识别风险。然后优先考虑风险并计划缓解。该方法专为研讨会式风险评估而设计，可以在内部执行，可能比顾问主导的风险评估成本更低。

l STRIDE 是一种面向故障的威胁建模方法，专注于六个核心领域：欺骗（伪造身份）、篡改（未经授权的修改）、否认（拒绝行为）、信息泄露（数据泄漏）、拒绝服务（减速）或禁用系统）和特权提升（对系统进行未经授权的控制）。该方法考虑了威胁目标（包括攻击者可能会做什么）、缓解策略和缓解技术。威胁可以考虑针对系统中同一威胁目标的多次交互，可以包括人员、流程和技术。Shostack 在他的书中将 STRIDE 作为四阶段框架的一部分：对系统建模，发现威胁，解决威胁，验证。当然，威胁建模不能保证可以预测所有故障，但如果时间和资源允许，迭代过程支持对不断演变的威胁进行持续评估。

l **攻击树** 根据攻击者（根节点）的目标制定总体目标，并开发与导致成功入侵系统组件的操作相关的子节点。像 STRIDE 一样，攻击树需要迭代，不断考虑修剪树并检查完整性。常见漏洞和暴露( CVE )和开放 Web应用程序安全项目(OWASP)等攻击库可用于增强对不断演变的威胁和攻击的内部知识。

可以在英国国家网络安全中心中找到常用的系统驱动的网络风险管理方法列表。下面我们提供一个概述，并根据每种方法的核心重点确定可以作为差异化因素的属性。这些都集中在系统级风险上，因此，根据组织的规模，可能需要大量的人力资源工作。这些方法的主要目标是捕捉系统的交互和相互依赖的方面，因此需要与流程所有者进行广泛的接触，并寻找具有子系统知识的“合适的”人员。

l  **系统理论事故模型和过程( STAMP****)**是麻省理工学院开发的一组用于对事故和危险的因果关系建模的方法。最初将安全作为一个动态控制问题，包括直接和间接因果关系，它也被应用于网络安全（例如 STPA-Sec），并关注风险的社会技术方面。该方法使用带有控制器和通过驱动和反馈链接的受控过程的反馈回路。它基于系统思维，包括：识别系统目的、不可接受的损失、危害和约束；分层控制结构的开发；不安全控制动作的识别；以及导致这些不安全控制行为的因果情景分析。这可以由时间线或事件序列来补充。

***优势***：因果关系有助于识别子系统相互作用中出现的风险。

l  **开放组架构框架****( TOGAF****)**是一种企业架构标准，支持组件驱动和系统驱动的风险管理方法。在此上下文中，企业的概念包括构成企业整个基础设施和治理活动的所有业务活动和能力、信息和技术。如果这扩展到合作伙伴、供应商和客户，以及内部业务部门，那么该模型也可以包含这方面的内容。TOGAF 中的风险评估 基于结合效果和频率标签的定性方法来产生整体影响评估。然后将风险评估和缓解工作表作为治理人工制品进行维护。

***优势***：与企业的结构化架构表示相关联。

l **依赖建模Open Group **还以自上而下的方法为面向目标的风险建模开发了开放依赖模型( O-DM ) 框架 \[ 46\]。这种方法首先询问“系统或企业的总体目标是什么？” （例如，持续的制造操作），然后提出进一步的问题“这个目标取决于什么才能成功？” （例如，运转中的机器、操作人员、材料供应）。然后该方法迭代问题，直到创建依赖关系树。目标是抽象的，因此不依赖于实际流程，并允许开发企业、其供应商和客户的连接主义视图。最近的工作开发了工具来支持在车间环境中捕获依赖关系并将定量概率应用于目标，支持贝叶斯分析和建模级联故障。

***优势***：捕捉位于实际业务流程之上并与实际业务流程相关联的抽象目标之间的相互依赖关系。

l **SABSA ****是另一种基于架构的方法。**它包括四个阶段。第一阶段确定与实现目标相关的风险，以便确定缓解计划。然后将输出输入到设计阶段，以确定安全管理流程及其使用方式。第三阶段由运营团队实施、部署和测试管理流程。什末阶段与管理和测量有关，它收集安全信息并向治理利益相关者报告。该方法是通过分解不同架构层的业务流程来制定的，从高级功能（上下文和概念）到逻辑和物理方面、技术组件和活动。以自上而下的方法在每一层解决风险，通过所有层的活动来管理风险，并从上到下过滤安全要求，以确保始终考虑网络风险。贯穿所有层面，重点关注资产（什么）、动机（为什么）、过程（如何）、人员（谁）、位置（地点）和时间（时间）。

***优势***：与业务模型相关的矩阵结构分层方法（可以位于TOGAF 中）。
