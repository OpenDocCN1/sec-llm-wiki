微软：攻击者越来越多地使用 IIS 扩展作为服务器后门

微软警告说，在 Exchange 服务器上用作后门的恶意 Internet 信息服务 (IIS) 扩展会有所增加。
了解 IIS 扩展

IIS 是一种灵活的通用 Web 服务器，多年来一直是 Windows 平台的核心部分。作为用于托管网站、服务和应用程序的易于管理、模块化和可扩展的平台，IIS 为众多组织提供关键业务逻辑。IIS 的模块化架构允许用户根据自己的需要扩展和定制 Web 服务器。这些扩展可以采用本机 (C/C++) 和托管 (C#、VB.NET) 代码结构的形式，后者是我们在这篇博文中的重点。扩展可以进一步分类为模块和处理程序。

IIS 管道是由 ASP.NET 运行时启动以处理请求的一系列可扩展对象。IIS 模块和处理程序是 .NET 组件，它们充当管道中的主要可扩展点。每个请求在由单个 IIS 处理程序处理之前由多个 IIS 模块处理。就像一组构建块一样，添加了模块和处理程序来为目标应用程序提供所需的功能。此外，可以配置处理程序以响应请求中的特定属性，例如 URL、文件扩展名和 HTTP 方法。例如，Aspnet_isapi.dll是一个用于常见.aspx扩展的预配置 IIS 处理程序。

微软指出，虽然 IIS 扩展不像 Web Shell 那样常用于针对服务器的攻击，但它们提供了一种持久的持久性机制，因为它们隐藏在目标环境的深处。

与 Web shell 相比，IIS 扩展的检测率也相对较低，并且更难检测，因为它们与合法模块非常相似并且行为相似：它们部署在相同的目录中并且具有相同的代码结构。

微软方面解释说：“在大多数情况下，实际的后门逻辑是最小的，如果不更广泛地了解合法 IIS 扩展的工作原理，就不能将其视为恶意，这也使得确定感染源变得困难。”

攻击者通常利用托管应用程序中的关键漏洞进行初始访问，然后部署 Web shell。后来，他们安装了一个 IIS 后门，用于对服务器的持久访问。

在目标应用程序注册后，后门会监控传入和传出的请求，同时还为运行远程命令和后台凭证转储提供支持。

微软同时指出：“我们预计攻击者将继续越来越多地利用 IIS 后门。”

这家科技巨头表示，在 2022 年 1 月至 2022 年 5 月期间，发现针对 Exchange 服务器的威胁参与者使用 IIS 后门与其他自定义 IIS 模块配合使用。

在初始访问之后，攻击者将执行诸如侦察、凭证转储和建立远程访问通道等操作。

接下来，看到他们安装了一个自定义 IIS 后门，该后门可以执行 Exchange 管理操作，包括枚举邮箱并将其导出以进行渗透。

攻击者使用命令行连接工具 plink.exe 进行远程访问，使用开源项目 PowerShDLL 进行远程命令执行，并启用 WDigest 注册表设置以强制将明文密码保留在内存中。

在过去的一年里，微软观察到至少四种类型的 IIS 后门，包括基于 IIS 模块的 Web Shell 版本、开源项目、IIS 处理程序和凭据窃取程序——用于监控网络流量和转储中的登录模式的模块加密形式的凭据。

为了免受 IIS 后门的影响，建议组织及时部署软件更新，使用安全解决方案，审查高权限组，应用最小权限原则，优先警报，并定期检查配置文件和 bin 文件夹。
