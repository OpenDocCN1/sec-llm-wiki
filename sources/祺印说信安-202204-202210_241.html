安全专家警告与数据泄露和丢失相关的两个主要客户端风险

据thehackernews一篇文章称，两个客户端风险主导着数据丢失和数据泄露的问题：在网站和 Web 应用程序上不正确地放置跟踪器，以及从 NPM 等第三方存储库中提取的恶意客户端代码。

客户端安全研究人员发现，放置不当的跟踪器虽然不是故意恶意的，但在合规/监管问题（如 HIPAA 或 PCI DSS 4.0）方面是一个日益严重的问题，并且具有明显且重要的隐私影响。为了突出追踪器放错位置的风险，The Markup（一家非营利性新闻机构）最近的一项研究调查了《新闻周刊》在美国排名前 100 的医院。他们在三分之一的医院网站上发现了一个 Facebook 追踪器，每当用户点击“安排预约”按钮时，该追踪器就会向 Facebook 发送高度个人化的医疗保健数据。数据不一定是匿名的，因为数据连接到 IP 地址，IP 地址和约会信息都会发送到 Facebook。

记者和客户端安全研究人员并不是唯一关注数据隐私问题的人。上周，FTC 宣布了打击科技公司不当或非法使用和共享高度敏感数据的计划。FTC 表示，他们还计划针对有关数据匿名化的虚假声明。该政府机构指出，敏感的健康信息与科技公司使用的隐蔽数据安全做法相结合是非常成问题的，大多数客户对他们的数据如何收集、收集哪些数据、如何使用或它是如何受到保护的。

安全行业一再证明，通过组合多个数据集以创建最终用户身份的清晰图像，重新识别匿名数据是多么容易。

除了放置不当的网络跟踪器外，客户端安全研究人员还警告说，与从第三方存储库（如 NPM）提取的 JavaScript 代码相关的风险。最近的研究发现，包含混淆和恶意 JavaScript 的包管理器被用于从网站和 Web 应用程序中收集敏感信息。使用 NPM 等来源，恶意威胁参与者通过JavaScript 软件供应链攻击以组织为目标，使用流氓组件将用户在包含此恶意代码的网站上输入的数据泄露到表单中。

客户端安全研究人员建议了几种方法来识别和减轻这两个主要风险。客户端攻击面监控是最全面和最全面的，可以保护最终用户和企业免受 Magecart、e-skimming、跨站点脚本和 JavaScript 注入攻击导致的数据盗窃风险。其他工具，如 Web 应用程序防火墙 (WAF)，可以保护客户端攻击面的某些方面，但无法保护动态网页上发生的活动。内容安全策略 (CSP) 是另一个很好的客户端安全工具，但 CSP 很麻烦。手动代码审查以识别 CSP 的问题可能意味着需要花费数小时（或数天）时间来搜索数千行 Web 应用程序脚本。

安全专业人员还可以探索包含威胁情报、访问洞察力（哪些资产正在访问哪些数据）和隐私（任何数据不恰当地共享给外部资源）的客户端攻击面映射解决方案。

客户端攻击面监控解决方案是一种相对较新的网络安全技术，可以自动发现公司的所有网络资产并报告其数据访问。这些解决方案使用无头浏览器来浏览网站和 Web 应用程序页面中包含的所有 JavaScript。他们从最终用户的角度收集有关扫描网站如何工作的实时信息。

客户端攻击面监控解决方案中的一个关键技术组件是合成用户，在威胁检测爬行期间部署，以与真人在动态网页上进行交互的方式进行交互。这些合成用户可以完成各种活动，包括点击活动链接、提交表单、解决验证码和输入财务信息。记录和监控综合用户交互，然后对每个页面进行行为分析和逻辑注入，以收集难以手动收集的信息，包括表单数据、第三方脚本可以访问的数据、部署的跟踪器及其活动，以及跨国界传输数据的任何表格或第三方脚本。

解决方案还应该能够通过使用允许列表和阻止列表以及通过扫描后信息分析来实现在识别或客户端映射过程中发现的任何问题，以获得综合情报，以保护 Web 应用程序免受损害。

具有客户端专业知识的安全专家强烈建议金融服务、媒体/娱乐、电子商务、医疗保健和技术/SaaS 等行业的组织，这些组织拥有多个前端 Web 应用程序，以了解客户端安全性以及如何使用客户端- 侧面风险可能会影响他们的业务。
