什么是数据目录？数据目录是以表格、文件、报告等形式存在于公司各种源系统中的所有数据资产的系统列表。它很像时尚目录。但它没有详细说明泳衣或鞋子，而是从公司的 ERP、人力资源、财务和电子商务系统（以及社交媒体源）中获取信息。该目录还显示了所有数据实体的位置。数据目录包含有关每条数据的大量关键信息，例如数据的配置文件（有关数据的统计信息或信息摘要）、沿袭（数据的生成方式）以及其他人对此的评价。该目录是数据分析师、数据管理员、数据科学家和其他人查找和了解相关数据集 以建立洞察力、发现趋势并为公司确定新产品的首选地点。

## 构建数据目录的分步过程

### Step1：访问所有数据库的元数据

构建数据目录的第一步是收集数据的元数据。数据目录使用元数据来识别数据表、文件和数据库。目录爬取公司的数据库并将元数据（不是实际数据）带到数据目录中。一些数据目录对它们可以爬取的数据库类型有限制。椭圆边缘没有。它可以爬行：数据管理平台

*   关系数据库 - Oracle、SQL Server、MySQL、DB2 等。
*   数据仓库 - Teradata、Vertica 等。
*   对象存储
*   云平台 - Google Big Query、MS Azure Data Lake、AWS – Athena 和 Red Shift
*   非关系/NoSQL 数据库 - Cassandra、MongoDB
*   Hadoop 发行版

分析和商业智能平台

*   现代商业智能平台，如 Tableau、Qlik、Power BI、Sisense 等
*   分析应用

自定义应用程序  

### Step2：构建数据字典

第二步是构建数据字典或将现有的字典上传到数据目录中。数据字典包含每个表或文件及其所有元数据实体的描述和 Wiki。员工可以通过基于 Web 的软件或使用 Excel 电子表格协作创建数据字典。

### 第 3 步：分析以查看数据统计信息

下一步是分析数据，以帮助数据消费者快速查看和理解数据。这些配置文件是解释数据的信息摘要。例如，数据库的配置文件通常包括表数、文件数、行数等。对于表，配置文件可能包括列描述、列中的最高值、列的空计数、不同计数、最大值、最小值等等。

### 第 4 步：标记数据之间的关系

标记关系是下一个重要步骤。通过这一步，数据消费者可以跨多个数据库发现相关数据。例如，分析师可能需要整合的客户信息。通过数据目录，她发现五个不同系统中的五个文件都有客户数据。随着OvalEdge 数据目录在 IT 的帮助下，您可以拥有一个实验区，您可以在其中加入所有数据并对其进行清理。然后使用整合的客户数据来实现您的业务目标。

#### 标记关系的多种方式

可以通过多种方式在数据之间识别和标记数据关系：

1.  通过人类知识
2.  高级算法可以找出连接。例如，在列名称“供应商”下的表中，有一个实体“亚马逊”。在另一个表中，对于列 V1，还有一个实体“亚马逊”。该算法将找出这些表之间存在关系。
3.  从查询中收集情报——一些开发人员从经验中了解不同数据集之间的联系。可以检查他们的查询日志，然后对其进行解析以标记关系。

### 第 5 步：建立血统

标记关系后，数据目录会构建沿袭。数据沿袭的可视化表示有助于跟踪从源到目的地的数据。它解释了数据流中涉及的不同过程。因此，它使分析师能够将错误追溯到分析中的根本原因。通常，ETL（Extract、Transfer、Load）工具用于从源数据库中提取数据、转换和清洗数据并将其加载到目标数据库中。数据目录解析这些工具以创建沿袭。一些可以解析的 ETL 工具是——

1.  SQL 解析
2.  奥特里克斯
3.  信息学
4.  塔伦德

### 第 6 步：组织数据

在表格/文件中，数据以技术格式排列，而不是以对业务用户最有意义的方式排列。因此，我们需要在数据资产上进行人工协作，以便业务用户能够发现、访问和信任它们。以下是我们可以安排数据以便于发现的一些技术 -

1.  标记
2.  按使用量组织
3.  按特定用户使用情况进行组织
4.  通过自动化——有时当有大量数据时，可以使用高级算法来组织数据。

## 使目录易于访问

对于数据消费者的高使用率，Web 应用程序、移动应用程序、Android 和 IOS 应用程序应该可以轻松访问数据目录。应该具有聊天功能。

## 确保适当的安全和治理

由于数据目录包含所有数据，因此保护最敏感文件的护栏至关重要。数据目录应具有以下功能，以确保只有右眼才能看到数据 -

1.  基于角色的安全性
2.  谁在什么时间访问什么数据的信息
3.  审计
4.  加密

## 建立数据目录的预计时间

构建数据目录所需的时间取决于要编目的数据库的数量。抓取和分析可以在一两天内完成。上传现有数据字典，构建沿袭，在数据库的利益相关者的帮助下，可以在一周内完成数据库的标记关系。如果一个组织必须对十个数据库进行编目，则可能需要四到五周的时间。一家大公司可以在大约三个月内建立其数据目录。一家中型公司可以在两到四个星期内建成一个。数据目录是当今数据驱动型组织所需的新型动态和敏捷工具。它们可作为您所有数据需求的单一参考来源。需要 IT 专家用户和大量手动管理的静态元数据存储库已成为过去。
