# **概述**  

本文档描述了 Computing Services 制定的指导方针，以确保安全使用具有管理员或特权访问权限的 Windows 操作系统账户。

## **适用于**

具有管理员或特权访问权限的任何计算机、设备或应用程序上的 Windows 操作系统账户。

## **指南的目的**

Carnegie Mellon Computing Policy为使用计算、电话和信息资源制定了一般政策。本指南的目的是建立可接受的实践来支持适用于 Windows 管理员账户 的策略。

此外，本指南的目的是介绍有效的做法，旨在减少入侵者访问特权账户的机会，减少不需要和/或恶意软件的秘密安装的发生，提高共享时特权账户的安全性和可管理性在工作组内，并根据最小权限原则限制特权账户的使用。 

## **定义/说明**

所有 Microsoft Windows 系统都有一个本地管理员账户，通常称为“管理员”。此账户具有提升的特权（超级用户）访问权限，因此，恶意攻击者通常使用它来尝试破坏系统。如果您访问 Internet 站点或打开电子邮件附件，您可能会损坏您的计算机，因为可能会部署恶意代码，这些代码将在您的计算机上下载并执行。如果您在本地计算机上以管理员或同等身份登录，恶意代码可以重新格式化您的硬盘驱动器，删除您的文件，并创建一个具有管理权限的新用户账户以供恶意使用。

对于大多数目的（例如，日常用户活动），管理员账户不需要执行手头的任务。

最小权限原则 – 规定所有用户都应使用具有完成当前任务所需的绝对最低权限的用户账户登录。

## **指南声明**  

**采取的步骤：**

1\.  立即更改任何 Windows 系统默认附带的“管理员”账户密码。密码应符合批准的密码准则。

2\.  在创建具有管理员权限的新账户时，请避免使用标识分配权限级别的账户名称，例如“\_admin”、“super\_user”、“sysadmin”等。

3\.  将最小权限原则应用于所有账户。因此，对于不需要管理员权限的正常日常计算使用，请仅登录具有“有限”权限的账户。

4\.  限制谁有权访问具有管理员权限的账户。如果允许访问，请将访问范围限制为仅授权计算机。 

5\.  审核所有管理员登录/注销事件、失败的登录尝试并查看事件日志以了解管理员账户上的意外密码更改。及时调查意外或不寻常的发现。

6\.  不要在脚本文件（或任何未加密的文件）中包含账户名和密码。例如，在Windows 系统上，使用“RunAs”命令启动系统脚本。

7\.  考虑从已知的安全机器远程更改管理员密码，以避免在受感染的计算机上出现“键盘记录器”的可能性。

8\.  考虑禁用 SAM 枚举。SAM 枚举是列出给定机器上所有账户名和 SID 的能力。要禁用 SAM 枚举，请编辑单个计算机的本地 GPO 或编辑联网计算机的域 GPO 之一。

## **用户责任和程序**

最终用户应与部门管理员讨论管理员权限的实施。用户应遵守本文档中指出的和/或部门管理员规定的所有政策和程序。如果最终用户没有部门管理员，请联系帮助中心。
