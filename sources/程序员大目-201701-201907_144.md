## 踩坑了

最近团队微调，我被调整到另一个小团队。前两天接了个新需求，于是我依然使用MySQL workbench EER建模，结果好不容易建模完成了，却被告知这个项目用的数据库是PostgreSQL！

于是就面临如下几种选择：

*   重新找个支持导出PostgreSQL DDL语句的建模软件，再弄一遍。据我所知，macOS平台里没啥好的数据建模软件…
    
*   PowerDesigner用不了（除非装虚拟机，或者Wine）；
    
*   Navicat太难用了（居然有人说Navicat是最好的数据库客户端，我只能给一个大写的服，在我看来，这货连IDEA自带数据库管理都比不上……这观点可能有点偏激，但现状是我做个查询，Navicat把查询按钮藏得很深）；
    
*   IDEA宣布会开发类似功能，但一直没有动静；
    
*   开源的PDMan，体验挺不错，但也得连个数据库控制版本。
    
*   依然用MySQL workbench导出DDL，然后自己将MySQL DDL转换成PostgreSQL DDL。
    

我选择了自己转换SQL语句。

## 自己开发工具

考虑到我的诉求其实非常简单，只是个DDL语句转换而已，自己开发一个也不难。而且之前研读Mybatis通用Mapper源码时，知道Java世界里有个 `jsqlparser` 的工具。

花了10分钟简单了解了下 `jsqlparser` 后，就开撸开发工具了……花了20分钟，初版写完了，然后和该项目的同事又花了20分钟验证了下，最终确定了如下的版本。代码贴出来：

加依赖：

```
1.  ` <dependency>`
    
2.  `    <groupId>com.github.jsqlparser</groupId>`
    
3.  `    <artifactId>jsqlparser</artifactId>`
    
4.  `    <version>1.2</version>`
    
5.  `</dependency>`
    
```

写代码：

```
1.  `public class MysqlDdl2PgDdlUtil {`
    
2.  `    public static void main(String[] args) throws IOException, JSQLParserException {`
    
3.  `        // 你的MySQL DDL路径`
    
4.  `        String mysqlDDLPath = "/Users/reno/Downloads/mysql.sql";`
    
5.  `        String dDLs = FileUtils.readFileToString(new File(mysqlDDLPath));`
    
6.  
    
7.  `        System.out.println(dDLs);`
    
8.  `        System.out.println("++++++++++开始转换SQL语句+++++++++++++");`
    
9.  
    
10.  `        Statements statements = CCJSqlParserUtil.parseStatements(dDLs);`
     
11.  
     
12.  `        statements.getStatements()`
     
13.  `                .stream()`
     
14.  `                .map(statement -> (CreateTable) statement).forEach(ct -> {`
     
15.  `            Table table = ct.getTable();`
     
16.  `            List<ColumnDefinition> columnDefinitions = ct.getColumnDefinitions();`
     
17.  `            List<String> comments = new ArrayList<>();`
     
18.  `            List<ColumnDefinition> collect = columnDefinitions.stream()`
     
19.  `                    .peek(columnDefinition -> {`
     
20.  `                        List<String> columnSpecStrings = columnDefinition.getColumnSpecStrings();`
     
21.  
     
22.  `                        int commentIndex = getCommentIndex(columnSpecStrings);`
     
23.  
     
24.  `                        if (commentIndex != -1) {`
     
25.  `                            int commentStringIndex = commentIndex + 1;`
     
26.  `                            String commentString = columnSpecStrings.get(commentStringIndex);`
     
27.  
     
28.  `                            String commentSql = genCommentSql(table.toString(), columnDefinition.getColumnName(), commentString);`
     
29.  `                            comments.add(commentSql);`
     
30.  `                            columnSpecStrings.remove(commentStringIndex);`
     
31.  `                            columnSpecStrings.remove(commentIndex);`
     
32.  `                        }`
     
33.  `                        columnDefinition.setColumnSpecStrings(columnSpecStrings);`
     
34.  `                    }).collect(Collectors.toList());`
     
35.  `            ct.setColumnDefinitions(collect);`
     
36.  `            String createSQL = ct.toString()`
     
37.  ``                    .replaceAll("`", "\"")``
     
38.  `                    .replaceAll("BIGINT UNIQUE NOT NULL AUTO_INCREMENT", "BIGSERIAL PRIMARY KEY")`
     
39.  `                    .replaceAll("BIGINT NULL AUTO_INCREMENT", "BIGSERIAL PRIMARY KEY")`
     
40.  `                    .replaceAll("BIGINT NOT NULL AUTO_INCREMENT", "BIGSERIAL PRIMARY KEY")`
     
41.  `                    .replaceAll("INT NOT NULL AUTO_INCREMENT", "BIGSERIAL PRIMARY KEY")`
     
42.  `                    .replaceAll("INT NULL AUTO_INCREMENT", "BIGSERIAL PRIMARY KEY")`
     
43.  `                    .replaceAll("IF NOT EXISTS", "")`
     
44.  `                    .replaceAll("TINYINT", "SMALLINT")`
     
45.  `                    .replaceAll("DATETIME", "TIMESTAMP")`
     
46.  `                    .replaceAll(", PRIMARY KEY \\(\"id\"\\)", "");`
     
47.  
     
48.  `            // 如果存在表注释`
     
49.  `            if (createSQL.contains("COMMENT")) {`
     
50.  `                createSQL = createSQL.substring(0, createSQL.indexOf("COMMENT"));`
     
51.  `            }`
     
52.  `            System.out.println(createSQL + ";");`
     
53.  
     
54.  ``            comments.forEach(t -> System.out.println(t.replaceAll("`", "\"") + ";"));``
     
55.  `        });`
     
56.  `    }`
     
57.  
     
58.  `    /**`
     
59.  `     * 获得注释的下标`
     
60.  `     *`
     
61.  `     * @param columnSpecStrings columnSpecStrings`
     
62.  `     * @return 下标`
     
63.  `     */`
     
64.  `    private static int getCommentIndex(List<String> columnSpecStrings) {`
     
65.  `        for (int i = 0; i < columnSpecStrings.size(); i++) {`
     
66.  `            if ("COMMENT".equalsIgnoreCase(columnSpecStrings.get(i))) {`
     
67.  `                return i;`
     
68.  `            }`
     
69.  `        }`
     
70.  `        return -1;`
     
71.  `    }`
     
72.  
     
73.  `    /**`
     
74.  `     * 生成COMMENT语句`
     
75.  `     *`
     
76.  `     * @param table        表名`
     
77.  `     * @param column       字段名`
     
78.  `     * @param commentValue 描述文字`
     
79.  `     * @return COMMENT语句`
     
80.  `     */`
     
81.  `    private static String genCommentSql(String table, String column, String commentValue) {`
     
82.  `        return String.format("COMMENT ON COLUMN %s.%s IS %s", table, column, commentValue);`
     
83.  `    }`
     
84.  `}`
     
```

如代码所示，目前是借助 `jsqlparser` 的SQL解析能力配合字符串替换的方式生成PostgreSQL的。

## 不足

目前工具代码比较屎，如果想要改进，应该是要让工具理解MySQL DDL的词法，然后构建成例如Table、Column、Comment、Constraint、Index等对象例如：

```
1.  `class Table {`
    
2.  `    private String name;`
    
3.  `    private Column column;`
    
4.  `}`
    
5.  `class Column {`
    
6.  `    private String name;`
    
7.  `    private String type;`
    
8.  `    // 约束，例如非空等`
    
9.  `    private Set<Constraint> constraints;`
    
10.  `    // 索引`
     
11.  `    private Index index;`
     
12.  `}`
     
13.  `class Index {`
     
14.  `    private String name;`
     
15.  `    private String type;`
     
16.  `}`
     
17.  `enum Constraint {`
     
18.  `    NOT_NULL,...;`
     
19.  `}`
     
```

然后抽象一个方言枚举，并为不同的方言制作一个DDL Generator Handler，然后根据不同的方言生成不同数据库平台的DDL语句。

为什么不改进？因为没有时间，工具是为工作服务的，目前能达到我的目的，就没动力修改了，未来有需求再改进吧。
