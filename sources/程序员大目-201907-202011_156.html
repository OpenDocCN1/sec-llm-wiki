上周，一位朋友在后台留言，参加了某厂的面试时杯具了，有点想不明白：“我的单体应用把公司服务的稳稳当当，面试官却跟我说，你是应聘里第一个还在用单体的。难道不会微服务就不值钱了？”

其实，微服务之所以成为软件开发行业的主流趋势，是因为快速变化的市场需求场景驱动的。这也是为什么目前绝大部分互联网企业都已经或正在进行微服务转型的原因。虽然使用微服务并不意味着必须抛弃当下成熟的单体架构。但问题是当业务规模达到大厂级别时，只会单体架构只能被企业淘汰掉。

而不少初学者并没有找到好的方法，往往没有搞清楚设计理念和原则就开始重复造轮子，常常有以下误区：
把系统拆成多个服务，用rest api 互相调用，但是读同一个数据库，就算微服务吗？
一会学会儿Spring boot，一会学会儿 Netflix，但每次学习时总是被配置、流程等问题搞得想吐。
对于小公司，本来用户量并发量就不够，硬把项目微服务化。

总之，微服务之所以难掌握，首先是没有一个有效的方法，大家都是摸着石头过河。再一个就是没有相应的业务场景。那么作为技术人，应该如何正确走上微服务转型的道路呢？
