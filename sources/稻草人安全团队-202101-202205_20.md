# 0x02 基于ARP的活跃设备发现

**ARP——地址解析协议**，主要用在局域网中。

所有设备在互联网通信时使用的是IP地址，在局域网通信时使用硬件地址（MAC地址），网络设备在局域网中不能使用IP地址进行通信，但能正常工作就是依靠ARP协议，在知道IP地址时去发现MAC地址。

比如我们所在的设备IP地址为**192.168.1.1**，目标设备IP为**192.168.1.2**，同一网络中还有**192.168.1.3**和**192.168.1.4**，4台设备使用一台交换机通过MAC地址进行通信。

![](../Images/16df14d66896f68224600a6b66fca53e.png)

知道IP地址去获得MAC地址的过程如下：  

•我们的设备（192.168.1.1）向局域网广播包含目标设备IP的ARP请求包•其他三台设备接到ARP请求包，比较自己的IP是否和目标IP相同•（假如目标是192.168.1.2）**192.168.1.2**发送有自己MAC地址的ARP响应包给**192.168.1.1**，其他设备不做出回应•**192.168.1.1**收到ARP响应包，将MAC地址存入ARP表•下次通信时，**192.168.1.1**查询ARP表，找到对应MAC地址发送

当目标设备和我们处于同一局域网时，利用ARP扫描速度最快，而且没有任何安全机制会阻止这个过程，那么接下来我们使用Python的Scapy模块模拟一个ARP请求包，来实现对目标的ARP扫描


# 0x03 基于ICMP的活跃设备发现

**ICMP——互联网控制报文协议**，位于TCP/IP中的**网络层**，在设备、路由之间传递信息。

ICMP和ARP原理相似，但是他提供四种报文：

•响应请求或应答•时间戳请求或应答•地址掩码请求或应答•路由器询问请求或应答

但是在实际应用中，后三种报文的成功率很低，所以我们使用第一种查询报文，Ping命令就是响应请求或应答的一种应用，经常用来测试与目标设备之间的连通性。

整个过程如下：

•向目标设备发送ICMP请求数据包•如果目标处于活跃状态，正常情况下会回应一个ICMP应答数据包，否则就处于非活跃状态，不会给出任何回应

需要注意的是，很多网络安全设备或机制会屏蔽ICMP，导致目标处于活跃状态但我们也收不到回应，接下来我们使用Python的Scapy模块模拟一个ICMP请求数据包：

如果收到了ICMP响应包，就说明设备存活，如果没有就说明设备不在线或有相应的安全机制。

完整的脚本如下：

*


# 0x04 基于TCP的活跃设备发现

**TCP——传输控制协议**，位于传输层，特点是**三次握手协议建立连接**：

•客户端发送SYN数据包给服务端，进入SYN\_SEND状态•服务端收到SYN数据包，回应一个SYN+ACK数据包，进入SYN\_RECV状态•客户端收到SYN+ACK数据包，回应一个ACK数据包，进入ESTABLISHED状态，成功建立连接，开始传输数据

![](../Images/d7561a7a4afab5ef0d69f8960119bece.png)

传输层出现了端口这一概念，各种服务通过 “ **IP+端口号** ” 来区分，那么我们检测一台设备的某个端口是活跃的，就可以判断设备存活，如果设备存活，即使端口关闭，也会回应一个拒绝连接的**RST**数据包，也就是说，只要我们收到**任何回应**，就可以判断目标为存活。


# 0x05 基于UDP的活跃设备发现

**UDP——用户数据报协议**，和TCP一样用于处理数据包，处于传输层，但是没有三次握手。利用UDP进行扫描的过程如下：

•向目标设备发送UDP数据包•当目标设备活跃，端口正常，返回一个ICMP数据包•当目标设备活跃，端口关闭，返回一个ICMP数据包，内容为**unreachable**•当目标设备不活跃，我们收不到任何回应

# 0x06 基于TCP全开的端口扫描

如果目标端口是开放的，那么收到SYN数据包后会返回一个SYN+ACK数据包，然后设备回应一个ACK数据包建立连接，如果端口是关闭的，就会返回一个RST数据包，中断TCP连接。

当然还有一种情况，设备发出SYN数据包，没有收到任何回应，可能是目标设备处于非活跃状态，也可能是网络安全设备屏蔽了SYN数据包。

我们使用Python的Scapy模块来模拟一个SYN数据包，使用sr1()函数发送出去，在TCP数据包中的flags设置为S表明这是一个SYN数据包

*   
*   

```
pkt=IP(dst=dst_ip)/TCP(sport=src_port,dport=dst_port,flags="S")resp=sr1(pkt,timeout=10)
```

接下来跟据收到应答来判断目标端口状态：

•如果resp为空，就是没收到应答，该端口关闭或有安全策略•如果数据包是SYN+ACK，说明端口开放，就可以发送一个ACK数据包完成三次握手建立连接•如果数据包是RST，说明端口关闭

完整的脚本如下：

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   

```
from scapy.all import *from scapy.layers.inet import IP, TCP
dst_ip="192.168.1.1"src_port=RandShort()dst_port=80pkt=IP(dst=dst_ip)/TCP(sport=src_port,flags="S")resp=sr1(pkt,timeout=1)if(str(type(resp))=="<class 'NoneType'>"):    print("端口%s是关闭的" %(dst_port))elif (resp.haslayer(TCP)):    if(resp.getlayer(TCP).flags==0x12):        seq1=resp.ack        ack1=resp.seq+1        pkt_rst=IP(dst=dst_ip)/TCP(sport=src_port,dport=dst_port,seq=seq1,ack=ack1,flags=0x10)        send(pkt_rst)        print("端口%s是开放的" %(dst_port))    elif(resp.getlayer(TCP).flags==0x14):        print("端口%s是关闭的" %(dst_port))
```

# 0x07 基于TCP半开的端口扫描

基于TCP全开的端口扫描存在一些问题，比如可能会被日志记录下来，而且第三次握手是没有用的，所以可以去除这一步，因为没有建立完整的TCP连接，所以称为半开，过程如下：

•发送SYN数据包•如果端口开放，返回SYN+ACK数据包，然后设备回应一个RST数据包断开连接

完整的脚本如下：

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   

```
from scapy.all import *from scapy.layers.inet import IP, TCP
dst_ip="192.168.1.1"src_port=RandShort()dst_port=80pkt=IP(dst=dst_ip)/TCP(sport=src_port,flags="S")resp=sr1(pkt,timeout=1)if(str(type(resp))=="<class 'NoneType'>"):    print("端口%s是关闭的" %(dst_port))elif (resp.haslayer(TCP)):    if(resp.getlayer(TCP).flags==0x12):        print("端口%s是开放的" %(dst_port))    elif(resp.getlayer(TCP).flags==0x14):        print("端口%s是关闭的" %(dst_port))

```

除了TCP全开、TCP半开，还有TCP FIN、TCP ACK等扫描方式，都是采用了TCP协议的工作原理。
