1、堆块结构和malloc分配机制介绍

在C中的动态分配一般使用malloc，其在glibc中的实现是基于dlmalloc的ptmalloc。基本思路是将堆上的内存区域划分为多个chunk，在分配和回收内存时，对chunk进行相应操作。下面看一下关于chunk的定义

/*  This struct declaration is misleading (but accurate and necessary).  It declares a "view" into memory allowing access to necessary  fields at known offsets from a given base. See explanation below.*/struct malloc_chunk {


  INTERNAL_SIZE_T      prev_size;  /* Size of previous chunk (if free).  */
  INTERNAL_SIZE_T      size;       /* Size in bytes, including overhead. */


  struct malloc_chunk* fd;         /* double links -- used only if free. */
  struct malloc_chunk* bk;


  /* Only used for large blocks: pointer to next larger size.  */
  struct malloc_chunk* fd_nextsize; /* double links -- used only if free. */
  struct malloc_chunk* bk_nextsize;};

这里简单介绍一下关于chunk的结构，将其分为分配情况下的和空闲情况下的。

当chunk在使用状态时，它的下一个chunk的prev_size字段无效，所以下一个chunk的该部分区域可以被当前chunk使用。即chunk的空间复用。下图为已分配情况下的结构：

空闲的chunk被记录在链表中（可能在循环双链表，也可能单向链表，在介绍fastbin时再详细说明）。下图是空闲情况下的结构:

这里第一排中的prev_size、size和p为chunk的header；fd、bk和data是用户申请的空间。

「prev_size」 是一个整数，如果当前chunk的前一个物理相邻的chunk未被使用(前一个是指地址较低的)，则prev_size表示前一个chunk的大小，否则，该字段可以用来存储物理相邻的前一个chunk的数据；

「size」 表示当前chunk的大小(chunk的大小包含header)。chunk大小是2 * SIZE_SZ( 32 位系统中，SIZE_SZ 是 4；64 位系统中，SIZE_SZ 是 8)的整数倍。若申请内存大小不满足，则会自动填充为2 * SIZE_SZ的整数倍。该字段从左到右3 bits分别表示:

  • NON_MAIN_ARENA，记录当前 chunk 是否不属于主线程，1 表示不属于，0 表示属于。
  • IS_MAPPED，记录当前 chunk 是否是由 mmap 分配的。
  • PREV_INUSE，记录前一个的 chunk 块是否被分配。一般来说，堆中第一个被分配的内存块的 size 字段的 P 位都会被设置为 1，以便于防止访问前面的非法内存。当一个 chunk 的 size 的 P 位为 0 时，我们能通过 prev_size 字段来获取上一个 chunk 的大小以及地址。这也方便进行空闲 chunk 之间的合并。

「fd和bk指针」

若当前chunk处于分配状态时，从fd字段开始是用户数据；

当chunk为空闲时，会被添加到对应的空闲管理链表中， 通过fd和bk指针，可以方便chunk链表将空闲的chunk块进行管理。其含义为:

  • fd 表示下一个未被使用的chunk的地址;

  • bk 表示上一个未被使用的chunk的地址。

「fd_nextsize和bk_nextsize」

在chunk空闲时使用，一般用于较大chunk(large chunk)

fd_nextsize 指向前一个与当前 chunk 大小不同的第一个空闲块，不包含 bin 的头指针；bk_nextsize 指向后一个与当前 chunk 大小不同的第一个空闲块，不包含 bin 的头指针。空闲的large chunk在fd的遍历顺序中，按照由大到小排列，以提高遍历效率。

接下来是关于malloc的分配机制。

#define request2size(req)

2、fast bin介绍

事实上，当用户释放掉chunk时，chunk并不会马上还给系统，ptmalloc会根据chunk的大小和使用状态统一管理heap和mmap映射区域中的空闲chunk。当chunk再一次被申请时，ptmalloc分配器会尝试在空闲chunk中选择一块合适的给用户，以比表面频繁的系统调用，降低内存分配的开销。

根据chunk的大小和使用状态，可以将chunk初步分为4类：fast bins，small bins，large bins 和unsorted bins。其中fast bins比较特殊，是由单向链表链接，在其他bins中，相似大小的chunk都由双向链表链接起来。因为全部介绍起来内容太多，而且除了fast bins以外，其他的bins还没有做详细了解，所以这里就着重介绍fast bins，以后再慢慢更新其他的相关内容。

很多程序会经常申请以及释放一些很小的内存块。如果将这些较小的chunk释放以后发现存在与之相邻的空闲的chunk并将它们合并，那么下一次再申请相应大小的chunk时，就又需要再一次进行分割，很明显，这样的效率很低。因此ptmalloc中专门设计了fast bin，以减少这种重复的操作。对应变量为malloc state中的fastbinsY

/*   Fastbins


    An array of lists holding recently freed small chunks.  Fastbins    are not doubly linked.  It is faster to single-link them, and    since chunks are never removed from the middles of these lists,    double linking is not necessary. Also, unlike regular bins, they    are not even processed in FIFO order (they use faster LIFO) since    ordering doesn't much matter in the transient contexts in which    fastbins are normally used.


    Chunks in fastbins keep their inuse bit set, so they cannot    be consolidated with other free chunks. malloc_consolidate    releases all chunks in fastbins and consolidates them with    other free chunks. */


    typedef struct malloc_chunk *mfastbinptr;

/*    This is in malloc_state.   
         /* Fastbins */
    mfastbinptr fastbinsY[ NFASTBINS ];
*/

如之前介绍的，glibc对fastbin中的每个bin采用了单向链表进行组织，且每个bin采取LIFO(后进先出)策略，最近释放的chunk会更早地被分配，这会更适合于局部性。

默认情况下(32位为例），fastbin中默认支持的最大chunk的数据空间大小为64字节。但是其可以支持的chunk的数据空间最大为80字节。同时fatsbin最多可以支持的bin的个数为10个，从数据空间为8字节开始，一直到80字节(不包含prev_size和size字段的大小)，

需要特别注意的是，fastbin范围的chunk的inuse始终被置为1。因此它们不会和其他bin中（samllbin、largebin和unsortedbin）被释放的chunk合并。

但是当释放的 chunk 与该 chunk 相邻的空闲 chunk 合并后的大小大于FASTBIN_CONSOLIDATION_THRESHOLD（65536）时，内存碎片可能比较多了，就需要把 fast bins 中的 chunk 都进行合并，以减少内存碎片对系统的影响。

malloc_consolidate 函数可以将 fastbin中所有能和其它 chunk 合并的 chunk 合并在一起。

3、fastbin attack分类和介绍

fastbin attack表示一类漏洞的攻击方法，其主要是针对fastbin机制的漏洞进行攻击。此类攻击的前提是：

  1. 存在堆溢出、UAF等能控制chunk内容的漏洞。
  2. 漏洞发生于fastbin类型的chunk中

针对fastbin attack，可以做如下分类：

  1. Fastbin Double Free
  2. House of Spirit
  3. Alloc to Stack
  4. Aribitrary Alloc

1和2主要侧重于利用free函数释放真的chunk或伪造的chunk，然后再次申请chunk进行攻击，本文着重讲解的也是Fastbin Double Free的利用；后面两种侧重于故意修改fd指针，直接利用malloc申请指定位置chunk进行攻击，这两个了解的不多，就多做介绍了。下面实际操作一下：

int main(void)
{
    void *chunk1,*chunk2,*chunk3;
    chunk1=malloc(0x30);
    chunk2=malloc(0x30);
    chunk3=malloc(0x30);
    free(chunk1);
    free(chunk2);
    free(chunk3);
    return 0;
}

4、fastbin利用实例之一 —— Double Free

Fastbin Double Free是指fastbin的chunk可以被多次释放，因此可以在fastbin链表中存在多次。这样导致的后果是多次分配可以从fastbin链表中取出。这样导致的后果是多次分配可以从fastbin链表中取出同一个堆块，相当于多个指针指向同一个堆块，结合堆块的数据内容(data字段)可以实现类似于类型混淆(type confused)的效果

在CTF比赛中，一般存在下次特征的题目就可以利用Double Free：

  1. fastbin的堆块被释放后下一个chunk的pre_inuse位没有清空

  2. fastbin在执行free的时候仅验证了main_arena直接指向的块，即链表指针头部的块。对于链表后面的块没有验证。

漏洞利用：
对于printnote函数中的

(*(void (__cdecl **)(void *))ptr[v1])(ptr[v1]);//打印content内容

当调用printnote函数时，会调用结构体中的第一个地址指向的函数，其参数为结构体本身。我们可以溢出覆盖掉一个之前申请过的结构体，将结构体的第一个函数地址修改为system的地址， system的参数即为结构体本身，也就是本来puts函数的位置被system函数给替换掉了。

「tips」: 用"||sh"或者";sh"可以实现system的参数截断

根据之前介绍的malloc分配机制，我们可以申请两个长度>12的note(以申请32字节为例)，这时候堆内：

16->40->16->40

很明显，这些chunk都在fastbin当中，当这些chunk被free后再次申请时，对chunk的分配遵循LIFO原则。从后向前第一个满足的chunk便是第一个chunk(第三个chunk覆盖为结构体)

「即」：note的文本内容会修改原本0号chunk

如果将结构体中的 * content内容修改为got.plt中的一个地址，那么针对第0号chunk调用printnote就会打印出函数加载后的真实地址，之后就是常规的leak到libc的基址，计算出system函数地址。

再继续修改一次结构体数据为system的地址，重新利用printnote来调用修改后机构体中地址对应的system函数，从而获取shell。
