# 1、堆块结构和malloc分配机制介绍

在C中的动态分配一般使用`malloc`，其在glibc中的实现是基于`dlmalloc`的`ptmalloc`。基本思路是将堆上的内存区域划分为多个chunk，在分配和回收内存时，对chunk进行相应操作。下面看一下关于chunk的定义

```
/*  This struct declaration is misleading (but accurate and necessary).  It declares a "view" into memory allowing access to necessary  fields at known offsets from a given base. See explanation below.*/struct malloc_chunk {

/* Size of previous chunk (if free).  */
/* Size in bytes, including overhead. */

struct malloc_chunk* fd;         /* double links -- used only if free. */
struct malloc_chunk* bk;

/* Only used for large blocks: pointer to next larger size.  */
struct malloc_chunk* fd_nextsize; /* double links -- used only if free. */
struct malloc_chunk* bk_nextsize;
};
```

这里简单介绍一下关于chunk的结构，将其分为分配情况下的和空闲情况下的。

当chunk在使用状态时，它的下一个chunk的`prev_size`字段无效，所以下一个chunk的该部分区域可以被当前chunk使用。即chunk的空间复用。下图为已分配情况下的结构：

![](../Images/b86bdc0c785f0cafa34916ed6e22306d.png)

空闲的chunk被记录在链表中（可能在循环双链表，也可能单向链表，在介绍`fastbin`时再详细说明）。下图是空闲情况下的结构:

![](../Images/82e271e757aec4ff3d654c10ba043741.png)

这里第一排中的`prev_size`、`size`和`p`为`chunk`的`header`；`fd`、`bk`和`data`是用户申请的空间。

**「prev\_size」** 是一个整数，如果当前chunk的前一个物理相邻的chunk未被使用(前一个是指地址较低的)，则`prev_size`表示前一个chunk的大小，否则，该字段可以用来存储物理相邻的前一个chunk的数据；

**「size」** 表示当前chunk的大小(chunk的大小包含header)。chunk大小是`2 * SIZE_SZ`( 32 位系统中，`SIZE_SZ` 是 4；64 位系统中，`SIZE_SZ` 是 8)的整数倍。若申请内存大小不满足，则会自动填充为`2 * SIZE_SZ`的整数倍。该字段从左到右`3 bits`分别表示:

*   `NON_MAIN_ARENA`，记录当前 chunk 是否不属于主线程，1 表示不属于，0 表示属于。
*   `IS_MAPPED`，记录当前 chunk 是否是由 mmap 分配的。
*   `PREV_INUSE`，记录前一个的 chunk 块是否被分配。一般来说，堆中第一个被分配的内存块的 size 字段的 P 位都会被设置为 1，以便于防止访问前面的非法内存。当一个 chunk 的 size 的 P 位为 0 时，我们能通过 prev_size 字段来获取上一个 chunk 的大小以及地址。这也方便进行空闲 chunk 之间的合并。

**「fd和bk指针」**

若当前chunk处于分配状态时，从fd字段开始是用户数据；

当chunk为空闲时，会被添加到对应的空闲管理链表中， 通过`fd`和`bk`指针，可以方便chunk链表将空闲的chunk块进行管理。其含义为:

*   fd 表示下一个未被使用的chunk的地址;
    
*   bk 表示上一个未被使用的chunk的地址。
    

**「fd\_nextsize和bk\_nextsize」**

在chunk空闲时使用，一般用于较大chunk(large chunk)

`fd_nextsize` 指向前一个与当前 chunk 大小不同的第一个空闲块，不包含 bin 的头指针；`bk_nextsize` 指向后一个与当前 chunk 大小不同的第一个空闲块，不包含 bin 的头指针。空闲的large chunk在fd的遍历顺序中，按照由大到小排列，以提高遍历效率。

# 2、fast bin介绍

事实上，当用户释放掉chunk时，chunk并不会马上还给系统，ptmalloc会根据chunk的大小和使用状态统一管理`heap`和`mmap`映射区域中的空闲chunk。当chunk再一次被申请时，`ptmalloc`分配器会尝试在空闲chunk中选择一块合适的给用户，以比表面频繁的系统调用，降低内存分配的开销。

根据chunk的大小和使用状态，可以将chunk初步分为4类：`fast bins`，`small bins`，`large bins` 和`unsorted bins`。其中`fast bins`比较特殊，是由单向链表链接，在其他`bins`中，相似大小的chunk都由双向链表链接起来。因为全部介绍起来内容太多，而且除了`fast bins`以外，其他的`bins`还没有做详细了解，所以这里就着重介绍`fast bins`，以后再慢慢更新其他的相关内容。

很多程序会经常申请以及释放一些很小的内存块。如果将这些较小的chunk释放以后发现存在与之相邻的空闲的chunk并将它们合并，那么下一次再申请相应大小的chunk时，就又需要再一次进行分割，很明显，这样的效率很低。因此`ptmalloc`中专门设计了`fast bin`，以减少这种重复的操作。对应变量为`malloc state`中的`fastbinsY`

```


/*   Fastbinsin FIFO order (they use faster LIFO) since    ordering doesn

't much matter in the transient contexts in which    fastbins are normally used.
```

如之前介绍的，`glibc`对`fastbin`中的每个`bin`采用了单向链表进行组织，且每个bin采取LIFO(后进先出)策略，最近释放的chunk会更早地被分配，这会更适合于局部性。

默认情况下(32位为例），`fastbin`中默认支持的最大chunk的数据空间大小为`64`字节。但是其可以支持的chunk的数据空间最大为`80`字节。同时`fatsbin`最多可以支持的bin的个数为10个，从数据空间为8字节开始，一直到80字节(不包含`prev_size`和`size`字段的大小)，

# 3、fastbin attack分类和介绍

fastbin attack表示一类漏洞的攻击方法，其主要是针对fastbin机制的漏洞进行攻击。此类攻击的前提是：

1.  存在堆溢出、UAF等能控制chunk内容的漏洞。
2.  漏洞发生于fastbin类型的chunk中

针对fastbin attack，可以做如下分类：

1.  Fastbin Double Free
2.  House of Spirit
3.  Alloc to Stack
4.  Aribitrary Alloc

1和2主要侧重于利用`free`函数释放真的chunk或伪造的chunk，然后再次申请chunk进行攻击，本文着重讲解的也是`Fastbin Double Free`的利用；后面两种侧重于故意修改fd指针，直接利用`malloc`申请指定位置chunk进行攻击，这两个了解的不多，就多做介绍了。下面实际操作一下：

# 4、fastbin利用实例之一 —— Double Free

`Fastbin Double Free`是指`fastbin`的chunk可以被多次释放，因此可以在`fastbin`链表中存在多次。这样导致的后果是多次分配可以从`fastbin`链表中取出。这样导致的后果是多次分配可以从`fastbin`链表中取出同一个堆块，相当于多个指针指向同一个堆块，结合堆块的数据内容(`data`字段)可以实现类似于类型混淆(`type confused`)的效果

在CTF比赛中，一般存在下次特征的题目就可以利用`Double Free`：

1.  fastbin的堆块被释放后下一个chunk的pre\_inuse位没有清空
    
2.  fastbin在执行free的时候仅验证了main\_arena直接指向的块，即链表指针头部的块。对于链表后面的块没有验证。
