美创科技为了更好地进行入侵检测和防御，参照各种安全威胁框架和自身的实践与思考，提出了基于入侵生命周期的攻击管理模型，作为美创新一代安全架构的三大支柱之一。

  

入侵生命周期v1.0把入侵过程划分为7个阶段：探索发现、入侵和感染、探索感知、传播、持久化、攻击和利用、恢复。入侵生命周期v1.0同样以ATT&CK作为基本战术知识库，匹配到不同的入侵阶段。需要注意的是，并非所有的入侵都会经历这7个阶段，也没有绝对的线性次序。  
**1）探索发现**在这个阶段中，攻击者会先锁定攻击对象，然后利用某些技术手段，尽可能多地获取目标暴露出来的信息，如通过端口扫描、指纹探测等方式，发现敏感端口及版本信息，进而寻找攻击点，为下一步入侵做准备。  
**2）入侵和感染**在这个阶段，攻击者会根据“探索发现”阶段所发现的重要信息，来对目标暴露出的攻击面进行攻击尝试，在“探索发现”阶段收集到的信息越多，攻击对象所暴露的攻击面也就越多，攻击更易成功。  
**3）探索感知**攻击者在成功进入系统内部后，由于是首次进入所以会出现对内部环境不熟悉的情况，这时攻击者的动作一般会是对当前所处环境进行探索，摸清内部大致的网络结构，常常伴随着被入侵本机的敏感信息收集以及对内网大量的端口进行扫描，后续根据攻击者的目的进行下一步操作。  
**4）传播**在此阶段，攻击者根据上一阶段在内网探索感知收集到的信息，选择特定的攻击手法。如若发现内部是域环境，攻击者可能会尝试先攻破域控服务器，再传播其他机器。若是工作组环境，可能会利用收集到的端口和服务信息，选择特定漏洞进行批量扫描攻击，来尽可能多地继续获得其他计算机的控制权。  
**5）持久化**攻击者在对资产进行恶意操作后，为了能够减少再次连接的攻击成本，方便下次进入，会进行“留后门”的操作，常见的后门如：建立计划任务，定时连接远程服务器；设置开机启动程序，在每次开机时触发执行特定恶意程序；新建系统管理员账号等。这样便于攻击者下次快速登录并控制该系统。  
**6）攻击和利用**攻击者在此阶段便会开始对目标资产进行恶意操作，按照攻击者意愿，对能利用的数据进行窃取、利用；对操作系统、敏感文件进行破坏、删除。所有的防御手段都应该极力阻止攻击者进行到这一阶段。  
**7）恢复**攻击者在执行所有的攻击操作时，往往会在系统上留下大量的行为日志，因此在这一阶段，攻击者会对记录自身痕迹的所有日志进行处理，或删除或混淆，从而消灭证据，逃避追踪。

容器技术是一种有效的将单个操作系统的资源划分到孤立的组中，以便更好的在孤立的组之间平衡有冲突的资源使用需求的技术，目前使用容器技术来进行应用的部署已经越来越普及，如Docker、Kubernetes等。  

  

从攻击者的角度来分析，当目标组织使用了容器技术部署应用时，如果配置不当就会产生安全漏洞，攻击者可以通过容器漏洞获取容器内的应用敏感信息，从而进一步获得容器的控制权，甚至可以逃逸到宿主机获得宿主机的控制权。  

  

根据攻击者的入侵流程和操作手段，利用容器和资源发现进行攻击在入侵过程的成功入侵之后，可以帮助攻击者发现更多的资源信息，从入侵生命周期角度分析，远程服务会话劫持攻击可作用于探索感知阶段。在探索感知阶段，攻击者通过探测容器api、执行容器命令、读取容器配置文件等操作，获取组织内部更多的攻击面。  

  

从攻击行为链条的上下文来看，针对容器和资源发现攻击的行为链条输入输出如下：  

  

**输入：**docker命令、Kubernetes命令、docker api接口、Kubernetes api接口

**  
输出：**容器内敏感信息、容器控制权、宿主机控制权  

  

根据不同攻击思路，攻击者利用容器和资源发现进行攻击的手法通常有3种：  

  

**1.  通过远程接口获取容器资源信息  
**

  

Docker 提供了用于与 Docker 守护进程交互的 API（称为 Docker Engine API），Docker 守护进程接收来自Docker Engine API的请求并处理，Docker daemon默认监听在2375端口且允许未鉴权访问。  
  
使用命令docker -H tcp://ip:2375 ps(docker命令)接口即可获取dcoker信息。  
  
![](../Images/5f0d00c8a234fd22e79981b0611e77f2.png)  
Kubernetes 控制面 的核心是 API 服务器。API 服务器负责提供 HTTP API，以供用户、集群中的不同部分和集群外部组件相互通信。Kubernetes API可以查询和操纵 Kubernetes API 中对象（例如：Pod、Namespace、ConfigMap和 Event）的状态。  
  
在默认情况下，Kubernetes API Server提供6443、8080两个HTTP端口。  
  
直接使用浏览器访问http://ip:6443即可获取KubernetesAPI Server信息。  
  
![](../Images/ed245a30ecc53279b4498e8fa79c58f8.png)  
直接使用浏览器访问http://ip:8080即可获取KubernetesAPI Server信息。  
  
![](../Images/3f16e4b4408679a8f38c4a587226cf71.png)  
对于Kubernetes集群来说，每一个Node节点都有一个kubelet服务，kubelet监听了10250，10248，10255等端口。  
  
当这些端口允许未授权访问时，使用http协议并使用/pods接口即可获取集群的详细信息。  
  
![](../Images/66a95bbb1e2ce602908c003a99959c3a.png)  
  
在Kubernetes中默认使用了etcd数据库，其默认监听了2379等端口。当Kubernetes配置不当导致etcd的端口暴露且允许未授权访问时，访问http://ip:2379/v2/keys/?recursive=true即可获取敏感数据。  
  
![](../Images/59f2bc2638f3d201d8789caa682661f7.png)  
dashboard是Kubernetes官方推出的控制Kubernetes的图形化界面，当配置不当时允许攻击者跳过认证步骤控制Kubernetes集群。  
  
![](../Images/e57d0bf2732b4adaece57e8ab303e170.png)  
![](../Images/2528e3273ce614462a46b77005b4915e.png)

当攻击者取得应用服务器的控制权限后，可能会搜集服务器上的容器配置信息，从而可以控制更多的容器；如果获得的权限是在容器内，则会进行信息收集寻找漏洞进行容器逃逸。~/.kube/config目录，包含Kubernetes集群的配置信息。
