简介


如果我们使用过apache或者nginx来部署发布过应用系统，那么可能就会用到一个配置--禁止ip访问。这个配置可以让访问者直接访问应用系统ip时返回403错误，只有访问ip绑定的域名才能得到正确的返回结果。


很多时候访问目标ip资产响应多为：401、403、404、500，但是用域名请求却能返回正常的业务系统，因为这大多数都是需要绑定host才能正常请求访问的，那么我们就可以通过收集到的目标的内网域名和目标资产的IP段组合起来，以IP段+域名的形式进行捆绑碰撞。如果原本访问相应为401、403、404、500的ip在和某个内网域名匹配访问返回200、301等正常响应时，就证明存在HOST碰撞漏洞。



HOST碰撞攻击模拟环境演示


首先需要安装nginx

apt-get install nginx



安装依赖包

apt-get install openssl libssl-dev libpcre3 libpcre3-dev zlib1g-dev
其中pcre包的作用是是让 Nginx 支持 Rewrite 功能。


使用命令service nginx start启动nginx服务

启动后使用service nginx status查看nginx服务是否正常启动



浏览器访问ip的80端口，出现以下界面时证明nginx已部署成功


wget·http://archive.apache.org/dist/tomcat/tomcat-7/v7.0.75/bin/apache-tomcat-7.0.75.tar.gz

下载apache



使用tar -zxvf apache-tomcat-7.0.75.tar.gz命令解压

cd /apache-tomcat-7.0.75/bin



./startup.sh启动tomcat
如果未安装java的话可以使用apt-get install openjdk-8-jre-headless命令进行安装


浏览器访问ip的8080端口，出现以下界面时证明apache已部署成功



配置nginx

vim /etc/nginx/nginx.conf

添加以下配置

server {

listen 80 default_server;

server_name _;

return 400;

}

server {

listen 80;

server_name www.hzmctest.com;

location / {

proxy_pass http://192.168.150.25:8080;

proxy_redirect off;

proxy_set_header Host $host:$server_port;

proxy_set_header X-Real-IP $remote_addr;

proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

root html;

index index.html index.htm;

}

access_log logs/hzmctest.com.log;

}


以上配置的意思是当直接访问ip的80端口时，返回400，如果访问www.hzmctest.com域名，则会转发到http://192.168.150.25:8080/也就是tomcat上。


通过service nginx restart重启nginx让配置生效，接下来使用浏览器直接访问http://192.168.150.25/，发现返回400错误。


当我们使用burpsuite抓取访问http://192.168.150.25/的请求包，然后将请求头中的Host字段修改为www.hzmctest.com时，发现返回包中返回了tomcat页面的数据。


真实环境Host碰撞攻击流程：

1.确定目标单位IP段，通过端口扫描等筛选出返回状态码为400、403、401、404、500的IP资产；

2.收集目标单位子域名，筛选出指向内网ip的子域名；
3.通过批量碰撞工具，如Hosts_scan，https://github.com/fofapro/Hosts_scan，对收集的ip和域名进行匹配，找出可以正常访问的ip和域名组合。
