简介

  

如果我们使用过apache或者nginx来部署发布过应用系统，那么可能就会用到一个配置--禁止ip访问。这个配置可以让访问者直接访问应用系统ip时返回403错误，只有访问ip绑定的域名才能得到正确的返回结果。

  

很多时候访问目标ip资产响应多为：401、403、404、500，但是用域名请求却能返回正常的业务系统，因为这大多数都是需要绑定host才能正常请求访问的，那么我们就可以通过收集到的目标的内网域名和目标资产的IP段组合起来，以IP段+域名的形式进行捆绑碰撞。如果原本访问相应为401、403、404、500的ip在和某个内网域名匹配访问返回200、301等正常响应时，就证明存在HOST碰撞漏洞。

配置nginx

vim /etc/nginx/nginx.conf

添加以下配置

server {

listen 80 default\_server;

server\_name \_;

return 400;

}

server {

listen 80;

server\_name www.hzmctest.com;

location / {

proxy\_pass http://192.168.150.25:8080;

proxy\_redirect off;

proxy\_set\_header Host $host:$server\_port;

proxy\_set\_header X-Real-IP $remote\_addr;

proxy\_set\_header X-Forwarded-For $proxy\_add\_x\_forwarded\_for;

root html;

index index.html index.htm;

}

access\_log logs/hzmctest.com.log;

}

![](../Images/9c659dd377f230deb68fc5ae3ec1199a.png)

  
以上配置的意思是当直接访问ip的80端口时，返回400，如果访问www.hzmctest.com域名，则会转发到http://192.168.150.25:8080/也就是tomcat上。

  

通过service nginx restart重启nginx让配置生效，接下来使用浏览器直接访问http://192.168.150.25/，发现返回400错误。  
  

![](../Images/cb594ea4022db920bffe22ba94b04ba3.png)

当我们使用burpsuite抓取访问http://192.168.150.25/的请求包，然后将请求头中的Host字段修改为www.hzmctest.com时，发现返回包中返回了tomcat页面的数据。  

![](../Images/79a2548e65d46a139152e0f7ac4de0fa.png)

  
**真实环境Host碰撞攻击流程：**

1.确定目标单位IP段，通过端口扫描等筛选出返回状态码为400、403、401、404、500的IP资产；

2.收集目标单位子域名，筛选出指向内网ip的子域名；3.通过批量碰撞工具，如Hosts\_scan，https://github.com/fofapro/Hosts\_scan，对收集的ip和域名进行匹配，找出可以正常访问的ip和域名组合。
