cobalt strike去特征化方法（一）

原文：http://mp.weixin.qq.com/s?__biz=MzI0NDgxMzgxNA==&mid=2247489155&idx=1&sn=395a2ad88f4fed1b9c6d683deaa3ecad&chksm=e9594c1ade2ec50c615fa75c72d9068539ee715332ec8f7deabdc44a413e89403f298fd2dea2&scene=126&sessionid=1681405454#rd
Cobalt Strike是一款商业化的渗透测试利器，由著名的攻防专业团队StrategicCyber开发。该工具被广泛应用于渗透测试项目中，在提高政府和企业网络设施安全性上起到了重要的作用。

同时，随着网络空间的红蓝对抗不断发展，该框架成为对手模拟和红队行动中最为流行的一款软件。但由于该框架具备团队协作攻击、流量防检测、防安全软件查杀等优势，因而也被大量黑客组织用于真实的高危害性的攻击。在近些年的攻防演练中，该工具多被攻击队所使用，因此也被防御方重点检测，下面介绍几种去除cobalt strike本身特征的方法。


01
修改默认端口


服务器默认启动时，cs运行在50050端口。



修改teamserver文件，修改默认端口为10080





02
修改默认证书


根据上图中的截图，我们可以看到cs默认的证书签发者具有相关特征，因此可以通过修改默认的证书，去除该特征。




commonName=MajorCobaltStrike/organizationName=cobaltstrike/stateOrProvinceName=Cyberspace/countryName=Earth


使用keytool重签一个伪造的证书,keytool是一个装好jdk就会有的java证书管理工具，输入命令keytool -list -v -keystore cobaltstrike.store -storepass 123456 就会详细列出证书各条目信息



删除原来的cobaltstrike.store文件，创建新证书


keytool-keystore cobaltstrike.store -storepass 123456 -keypass 123456 -genkey -keyalgRSA -alias microsoft.com -dname "CN=Microsoft Windows, OU=MOPR, O=MicrosoftCorporation, L=Redmond, ST=Washington, C=US"



导入新证书


keytool-importkeystore -srckeystore cobaltstrike.store -destkeystorecobaltstrike.store -deststoretype pkcs12




此时重新启动cs，可以看到证书都已经替换成我们新生成的，没有cs相关特征。




03
修改https上线证书


虽然上面我们修改了CS服务器监听的证书，但这个证书是用于10080主控端的证书，当我们通过cs开启监听，使用https的bacon时，https的证书同样具有一定的特征。


这里我们以beacon-https开启监听进行演示



生成执行器进行执行时，查看流量



可以看到该证书并不是我们在第二步中生成的证书，为cs默认的证书，且具有一定的固定特征，在流量检测层面可能存在特征，无法正常上线，因此还需要对该证书进行修改。

 

三：https证书修改


通过let’s encrypt申请一个免费证书并打包为keystore，替换cs自带的证书


下面的域名需要替换成自己注册的，且可解析


apt installcertbot

certbot certonly--standalone -d update.domain.com


将证书打包并生成store文件


openssl pkcs12-export -in /etc/letsencrypt/live/update.domain.com/fullchain.pem -inkey/etc/letsencrypt/live/update.domain.com/privkey.pem -out update.domain.com.p12-name update.domain.com -passout pass:123456

keytool-importkeystore -deststorepass 123456 -destkeypass 123456 -destkeystoreupdate.domain.com.store -srckeystore update.domain.com.p12 -srcstoretype PKCS12-srcstorepass 123456 -alias update.domain.com


利用malleable C2profile来引入自己申请的证书，Malleable C2允许我们通过一个简单的配置文件来改变beacon与C2通信时的流量特征与行为，是cobalt strike的一项功能。


https://github.com/rsmudge/Malleable-C2-Profiles


根据你自己选择的profile来在相应的profile文件下面追加证书认证


https-certificate{

             set keystore"update.domain.com.store";

           set password "123456";

}'


通过c2lint进行配置文件有效性检查

./c2lintxxx.profile



最后通过nobup./teamserver IP password amazon.profile &启动后抓上线包，则证书就是自己申请的了。


通过以上方式大致可以将cs本身的特征去除，但在实际的攻防中，在投递payload,beacon监听、会话回连等过程中，都有可能使C2服务器暴露。目前识别CS的还有JA3/S或者JARM方式，主要是通过Java版本、Web服务器、TLS版本等多因素TLS握手包生成指纹，通过这种方式，可以生成相应jdk版本下的cs 指纹，虽然会存在一定的误报。


如使用jarm生成jarm指纹（Jarm: https://github.com/salesforce/jarm）

首先通过fofa查找cobalt strike服务器




对这些服务器生成jarm指纹，均为

07d14d16d21d21d00042d41d00041d47e4e0ae17960b2a5b4fd6107fbb0926，这些jarm就可以做为识别cobalt strike的指纹

 


以上的几种方式是目前常见的几种修改cobalt strike特征的方式，为了避免C2服务器的暴露，还有各种隐藏C2服务器IP的方法，如端口转发、CDN等，将在下一期进行介绍。
