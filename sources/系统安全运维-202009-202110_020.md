# 记一次阿里云木马排查过程

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=Mzk0NjE0NDc5OQ==&mid=2247492036&idx=2&sn=1ce640eeb563ad2db5c06e27c0131e9f&chksm=c30832b4f47fbba26b972b37453f5fc90d2491851f750d13f8c1465c629e79009f5ed4bf932e&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=Mzk0NjE0NDc5OQ==&mid=2247492036&idx=2&sn=1ce640eeb563ad2db5c06e27c0131e9f&chksm=c30832b4f47fbba26b972b37453f5fc90d2491851f750d13f8c1465c629e79009f5ed4bf932e&scene=27#wechat_redirect)

问题描述  

接到阿里云报警邮件，说是一台ECS有恶意进程。查看阿里云的安全详情，发现有恶意进程(云查杀)-自变异木马：  
![](../Images/f25e5ea621ef1f1e4c04706b7caa7331.png)  
登录到服务器上检查/bin目录，发现该文件确实不对，大小变成的1.1M，类似的还有netstat。如下图：  
![](../Images/6b2298f529e9a2a5288f91b5697d6823.png)  
正常ubuntu系统下的ps才96K，netstat大小为117K，上述命令文件被恶意窜改了。

# 检查

根据手动分析的结果发现，有多处系统文件被感染。通过lastlog等命令查看系统登录及操作，并未发现有被入侵的痕迹。  
分析启动项，发现多出了如下文件：


两个文件都是软链接：

![](../Images/3bd625f336d45592f473f0e765647685.png)

可以明确感染文件不止一处，所以需要通过软件进行全盘扫描。linux下比较常见的杀毒工具是clamav，于是决定安装扫描全盘。

总结

本文记录了一次简单的木马排查过程，供安全小白参考，毕竟现在很多后端都没有安全方面的经验。本文处理比较简单，但基本上能解决掉木马问题。这也提醒了广大后端程序员，服务器安全还是得引起重视。  
有一些遗留问题，至此仍不清楚服务器是如何感染的。没有发现其他非法登录的情况，猜测有可能是使用了一些nodejs非官方库导致的。至于这些木马是干什么的，出于时间考虑，也没有做进一步分析。
