# 真实环境中的渗透思路

**背景**

  

授权测试XX工程公司内部OA系统

主要业务：监理，工程造价等

  

## **正文**

  

接入内部网络，拿到网址后使用nmap扫描服务器信息

nmap -O  目标

  

![](../Images/f578160a2316929569131c8be7922d5c.png)

开启了不少端口，扫描结果服务器可能为win7或windows sever 2012，开启了445端口，试试永恒之蓝是否能直接拿下

msfconsole

use exploit/windows/smb/ms17\_010\_eternalblue

set rhost 目标IP

exploit

![](../Images/e9fcead5c874156ce7a497ba5fa1af88.png)

  

没成功，意料之中。

  

尝试3306端口爆破mysql口令。  

  

mysql -h 目标ip

  

![](../Images/9c7df65c06839e349d9fc53506a452a8.png)

  

拒绝了我们的连接，不过在这里曝出了服务器名，现在尝试查看80端口的web服务，web才是我们的主要目标。  

  

登录页

![](../Images/5effc51e6e3512419376a95a6c2d519c.png)

这里未做验证码控制，说明可能允许爆破，打开purb进行抓包，查看信息  

  

![](../Images/8227d5175e4fc18f7411dc52c43db0e3.png)

密码未进行加密，手动尝试了几个弱口令没有提示异常，

  

选择OA系统成功率高的字典开始枚举

  

且把从浏览器收集到的公司暴露在外面的员工姓名加入字典  

  

![](../Images/a6bc98e119b1bdc4db0e3ffb4c8eb86f.png)

枚举途中查看网站指纹，下图为wappalyzer插件  

![](../Images/99727dca5a9202cec12f1b4ad7690e06.png)

  

可以看到网站使用thinkphp框架，中间件为APache 2.4.4

  

thinkphp不同版本具有远程代码执行漏洞，信息泄露、文件包含、SQL注入漏洞

  

尝试利用文件包含漏洞途中thinkphp报错

![](../Images/aaf9264d8e838f34e3f58fa92494a7ed.png)

虽然没利用成功，但是这里曝出了网站路径和thinkphp具体版本  

  

知道具体版本后尝试使用thinkphp3.2.3经典漏洞信息泄露查看日志文件

  

<domain>/Application/Runtime/Logs/Home/19\_07\_022.log

![](../Images/210e628966edf8f5255e3386584dab13.png)

成功查看到日志文件，包含了历史登录的所有用户名、密码和一些其他信息，数据量巨大，没来得及慢慢看。

这个漏洞详细利用方式介绍：https://newsn.net/say/thinkphp-bug-log.html  

这里使用泄露的用户名密码登录系统

![](../Images/cd83041babf6eac2c1161697b93ef45c.png)

进入系统后从项目信息中获取到公司内部结构，然后从日志信息中获取权限更高的用户密码  

![](../Images/7213d83a9725b7c1fe93996b93d7cc9b.png)

登录到高权限账户后发现待我处理模块中可以上传合同文件  

![](../Images/b0a404f2c0d5f8aa07db15cef29b5fd4.png)

thinkphp框架中规定了各类函数的安全引用方法

  

尝试过程中发现XSS已经做了转译处理，SQL注入也已预编译，防护均OK

  

但是上传功能配合APache 2.4.4的解析漏洞可能绕过thinkphp规定的安全策略，

  

开始从上传点入手  

  

下载部分网站图片等文件作为上传测试，乱输入一个后缀无法上传，

  

说明为白名单，测试结果仅允许JPG，PNG，docx，xlsx后缀上传

  

![](../Images/7be8fdd7fdc42383c26f60b168b38bc7.png)

  

这里花费了很多功夫，发现安全策略检查了MIME，检查了后缀，检查了文件内容，

且上传后会二次渲染并重新随机命名文件

  

安全策略还是很全面的，单配合解析漏洞无法利用  

  

![](../Images/869876e35310047ad95a9b55644d2b59.png)

但工作表的上传可能带来另一个危险漏洞，如果上传的合同文件带有Office宏病毒，当工作人员下载查看文件的时候可能被控制主机  

![](../Images/7970f70097ffc8a4f649a48233208962.png)

  

上传点进行到这里结束，寻找其他漏洞  

  

这时我们想起之前的信息泄露，目录文件为wamp，wamp server为开发者的集成环境

  

推测服务器环境使用此环境搭建，且wamp默认安装了phpmyadmin进行mysql管理，尝试访问phpmyadmin

![](../Images/f74b0999f97dffd75626341cbca52771.png)

  

这里显示无权限访问phpmyadmin界面  

![](../Images/e0e0e08e80ef2248b69707c383efab61.png)

  

这里修改IP尝试访问，最终在58网段成功访问phpmyadmin界面  

![](../Images/2f9d19b326cc637d30697da7c400a6b9.png)

对之前的泄露的口令进行口令组合尝试密码枚举

  

成功登录枚举出root密码，密码为小写字母加数字加特殊字符方式，进入数据库  

  

![](../Images/629d5c68f87d6c501ae9e3141474918c.png)

  

数据在系统里已经呈现七七八八了，尝试写入shell获得系统权限  

select ‘内容’ into outfile ‘这里的绝对路径thinkphp报错已经告诉我们，

  

并且日志文件泄露，mysql日志文件同样记录有绝对路径’

  

![](../Images/b8c5706b27a737bb06d448f8cbbe0e3a.png)

  

成功执行，访问地址

![](../Images/9c148d035a2426f222cf76e90671a190.png)

  

接下来写入一句话，写入一句话的时候遇到点问题

  

执行后访问无这个文件，推测可能装了杀毒，写入免杀脚本成功连接

  

![](../Images/7e4956aef9ef1a5578f09be1d045c036.png)
