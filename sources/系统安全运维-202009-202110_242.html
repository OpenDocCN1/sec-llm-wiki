前言

2020年某网行动期间，深夜难眠，回想起今天waf上一大堆误报和几无几几的替换，甲方爸爸提供的两荤一素已经换成了白粥榨菜，农夫已经换成了怡宝，猪肉换成榨菜，或许我们是时长一个月实习生的身份，已经彻底暴露了，明天不知道是不是只能吃开水泡面了。唉，明天又要穿上白衬衫，继续假装自己是5年工作经验的安全专家，今晚终于认清现实，活捉红队0day依然是我们遥不可及的梦。

生而为人，我很抱歉。

突然叮咚一声，服务器酱提示CS有人上线了，之前的悲伤已经烟消云散，CS上号一看，是一台红队机器，有人踩了蜜罐哈哈。做好权限维持以后就开始翻他的文件（坏笑）。在这个人的冰蝎里发现了多个shell，其中有两个webshell的路径比较特别，引起了我的注意，从而进行了一波分析，虽然我无法活捉红队的0day，但是经过努力，成功分析出了一个1day。

分析

这两个webshell是这样的
http://xxx.xxx.xxx.xxx/ResourcePic/MQ==.ASPX 
http://xxx.xxx.xxx.xxx/fileManager/UploadFile/CoursePic/485b1b71-8035-44c1- 9ceb-637cd68eda19.ASPX

：这两个站点，发现都是PowerCreator CMS这一框架，如果排除是通过弱密码进入的后台，在后台上传getshell等可能外，应该是使用任意文件上传扩展进行攻击的。

在互联网上进行了一通搜索，并没有发现这个CMS的任意文件上传有效载荷，但是在CNVD中发现了关于这个CMS的突破描述



CNVD-2017-07290，漏洞描述：PowerCreator CMS存在任何文件上传漏洞，该漏洞源于CMS编辑器未对文件上传做任何校验，允许攻击者利用扩展上传任意格式文件，获得服务器控制权。

CNVD-2019-43598，漏洞描述：PowerCreator CMS存在文件上传漏洞，攻击者可利用该入侵获取网站服务器控制权

注意到CNVD-2017-07290是CMS编辑器插件的漏洞，而CNVD-2019-43598是CMS本身的漏洞，厂商均未提供修复方案，那么看来，是通杀全部系统了

编辑器任意文件上传

根据描述，是编辑器的漏洞，查看原始码发现该CMS采用了kindeditor编辑器，该编辑器存在任何文件上传拆分

因为这个是烂大街的东西，关于对kindeditor编辑器任何文件上传的分析文章网上一搜一大堆，因此这里就略了。另外反复复现发现，只能传txt和html，不能传aspx，很鸡肋。

根据上面的分析，实际上突破的关键点就是上传接口未授权访问可以直接进行上传操作，存在一个Content-Type为图片/ jpeg的判断，另外需要注意的是传递一个资源ID变量才能成功进入到上传逻辑。

直接访问，没传递rid变量，回显参数错误，因此上传接口前面没有任何校正，可以直接进行文件上传操作

给rid变量赋一个值，也即任意使用get方法或post方法传递ResourceID变量，但是由于不存在文件上传操作，报文类型不符合multipart / form-data规范，因此返回-1

那么只要本地构造一个上传表单，在上传的时候将Content-Type改成图片/ jpeg，就可以进行任意文件上传，上传过后文件命中会是ResourceID变量的值进行base64编码+上传文件的扩展名

本地构造表单

< form  action = “ http://xxx.xxx.xxx.xxx/upload/UploadResourcePic.ashx?ResourceID=1”  enctype = “ multipart / form-data” 方法= “ POST” > 
<输入 类型= “ file” 类= “ file1” 名称= “ file1”  /> 
<按钮 类型= “提交”  class = “ but1” >上传</ button > 
</ form >

改一个Content-Type为image / jpeg，即可成功getshell
