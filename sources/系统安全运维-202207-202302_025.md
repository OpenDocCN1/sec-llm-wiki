# CobaltStrike -- 流量分析

一、 http-staging流量分析(1)stage 下载stager 可执行文件 artifact.exe 运行后会有一个 payload 下载过程，使用 http 协议从指定服务器下载 stage 。![](../Images/eba7eefccc6d3be9f6024e376c37991e.png)  
其中 http 请求路径不唯一，但都符合一个 checksum8 规则，即：路径的 ascii 之和与 256 取余计算值等于 92 。\#  /Yle2、/cKTZ、/wQPD  
![](../Images/0b9a4fea09af87d9d19c31cadeb603f5.png)而下载的文件约 211kb，解析后可以看到回连地址、加密字段、公钥等配置信息。  
![](../Images/a41a5d5fac4dcf3d568f7050afa01581.png)  
(2)beacon 上线随后 beacon 按设置的频率以 get 方法向 c2 服务器发起心跳请求，通过 cookie 携带靶机信息。  
![](../Images/ca63fa6d7eb21e2bd274e8990e49482f.png)此时 client 界面可以看见目标机器上线：  
![](../Images/cee0b9003997419aebd0478811a0d445.png)  
(3)命令下发c2 服务器如果有任务下发，则放入 http 心跳请求返回包中。![](../Images/d3e41b57fac834be438c9814f58b17b4.png)  
当前下发的命令：whoami  
![](../Images/39b92bbc7017d137a48f58f4bf917e0c.png)  
(4)结果回传beacon 端处理完成后，通过 post 方法回传数据。  
![](../Images/0f2ea477b400a367e114a01ba89661ec.png)注：https-beacon 在 http-beacon 的基础上加入了 tls 层对流量加密，其他过程相似。![](../Images/bd77c5f37ab18f732e962b9af81eb1d5.png)  
二、dns-stagless流量分析![](../Images/3f210066c885a560fa0ecce34b61b646.png)(1)beacon 上线与 staging 阶段不同，stagless 不需要额外加载 stage，运行 dns-beacon.exe后，beacon 端发起一个A记录查询，查询内容为16进制字符串地址，表示靶机信标已上线，c2 服务器收到请求后回复 0.0.0.0 表示确认消息。  
![](../Images/e1d41b4029670a0f00f2ac5adb54a54f.png)此时，在客户端可以看见一个不同于 http(s)上线的黑框记录。  
![](../Images/44b87ec34ab25984553988748cb7ce45.png)(2)beacon 激活客户端控制台输入 checkin 或其他指令激活窗口，dns-beacon服务器支持A、TXT、AAAA三种方式下发payload，激活后默认使用TXT记录，流量中表现为 0.0.0.243，除此之外还可以通过 mode 指令切换为A、AAAA 记录，流量中表现为 0.0.0.241、0.0.0.245，随后 beacon 端发起以 www 为首的A记录请求，向 c2 服务器传递靶机基础信息。  
![](../Images/b78a0adc387103ad36fb566da6f1e2f3.png)(3)命令下发beacon 准备接收 c2 任务，先发送以 api 开头的A记录请求告知 c2 服务器可以开始下发任务，即图中的 0.0.0.243-TXT 方式，随后发起以 api 开头的 TXT 记录请求等待 c2 服务器返回数据。  
![](../Images/97840d1704fec6439060f5f78dfeb681.png)  
(4)结果回传beacon 端执行完命令后，再向 c2 服务器发起以 post 开头的A记录查询回传执行结果。![](../Images/122879268dfd0f8b22b6363fc708ac3f.png)
