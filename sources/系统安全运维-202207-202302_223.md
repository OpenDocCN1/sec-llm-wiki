# 记一次对某站点详细的渗透测试

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=Mzk0NjE0NDc5OQ==&mid=2247511446&idx=2&sn=4f08386d7617e169871ef956ab756a4d&chksm=c3087ee6f47ff7f0cab4ac224d945c3fa8233ca60bee54626e8dccb55aa9bc55e9cc7bd7520f&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=Mzk0NjE0NDc5OQ==&mid=2247511446&idx=2&sn=4f08386d7617e169871ef956ab756a4d&chksm=c3087ee6f47ff7f0cab4ac224d945c3fa8233ca60bee54626e8dccb55aa9bc55e9cc7bd7520f&scene=27#wechat_redirect)

**0x01 前言**最近在尝试冲刺排名，恰好本次渗透中的东西可以拿来做一些分享，希望可以给大家提供一些思路，有什么不对不足的地方，希望各位师傅斧正，本文所涉及的漏洞均已提交至src平台  
**0x02 ****任意用户注册**像这种注册页面没有验证码的，果断抓包尝试无限绑定任意电话号码和邮箱注册  
![](../Images/e2f82655ae787dc6b7b63da7aaa98f42.png)  
![](../Images/6e6bf2c1e323be3bf9d60d62e7c53e48.png)  
![](../Images/5b08a48dfcd269cca80c50a99a93ca3b.png)![](../Images/bb71992dff1fac506ce08149e2db7c1d.png)  
验证之后成功注册并登录两个账户，果然可以批量注册，登陆，送上手的低危成功吃到  
**0x03 ****任意用户密码重置**登陆账户，进入修改资料界面，仔细观察，修改密码居然不用填旧密码？  
![](../Images/e9d6142677d73abbcd0e7417126c0d2f.png)  
果断抓包，这里的逻辑是用自己的用户名找回密码，在最后修改密码的时候抓包，改成其他用户名  
![](../Images/d3cd1cca8b921bdf21d8af6dff2bee55.png)  
![](../Images/94a8ad31d6b562a3c83d0dbc5fd8ea3f.png)  
验证一下，成功更改另一用户密码登录，ok，又是一个低危+，(其实可以看到这里第一个和第二个漏洞都不难，因为是业务逻辑类型，这类型的漏洞其实只要我们细心，就一定能挖到的)  
**0x04 ****水平越权+存储xss组合拳**上面在找到任意密码重置后，便可以发现这个页面存在非常简单的越权漏洞，原理同上，他的逻辑是通过username参数来查询更改后端的数据。但是既然已经找到任意密码重置了，单单一个水平越权确实没什么看点了，但是没关系，虽然咱们菜，但是咱们能坚持，够细心  
继续对资料修改处进行测试，发现下面有一自我介绍处，自我介绍这个功能一般来说长度和特殊字符限制比较少，因为这属于业务需要，所以测试的时候遇到了就不能忽略，  
![](../Images/a69642a6af0c8140ab80eacaeb7b327a.png)  
果然这里有一存储型xss漏洞，抓包改payload，然后登陆另一账户进入修改资料页面验证成功  
![](../Images/832ecafbaf790bdbb521d7d27eb14d30.png)  
![](../Images/a54f324fde355065e865f923e84ea3f0.png)  
备注:其实这里也可以用存储型+csrf组合拳哦，不过我个人认为越权+存储型更实用(当然要是用img标签打csrf也很实用啦)  
**0x05**** sql注入**问题出该网站一信息查看处，看到url处存在?id=1![](../Images/eec123af6684c94de0d922ca491a1010.png)  
多用几个payload找到更多信息，  
首先是发现存在waf，

*   

```
`payload1:www.xxx.com/xxx/?id=1+and+select`
```

![](../Images/5d548ace89f6491a8da0095e024a0624.png)然后是存在报错信息，  

*   

```
`payload2:www.xxx.com/xxx/?id=abcd`
```

虽然access数据库不支持报错注入，但是后面我们会利用是否报错来进行一个盲注![](../Images/9cd162d6c4684d0dbee3b7130d08abbb.png)  
于是手注一直尝试，找到了他这里的语句结构，非常难受，access数据库除了不能报错，也不能利用注释，但是别放弃,  

*   

```
`payload3:www.xxx.com/xxx/?id=1+and+exists(`
```

  
![](../Images/93d33122cbe6e3d882427348db089489.png)  
基于此语句结构去构造payload，虽然有waf但是可以绕过，具体绕过手法我想在后面的文章做详细汇总  
这里说一下其中有一个逻辑，select后面不能直接跟任何占位空字符(%0d,%0a,%0c,%20,' ')，这个应该是他在后端自己又加的正则，用select(xxx)可以绕过这个逻辑  

*   

```
`最终的payload:www.xxx.com/xxx/?id=1+and+exists(查询数据的语句)`
```

绕过waf后可以通过盲注暴力猜解数据,可以看到admin表不存在，会给到错误信息回显，而另一个表是存在的，则正常回显![](../Images/7ddb4278f21b8c3a249cca0556f6a671.png)  
![](../Images/504dba45ecc1248bf3a9c60e409e9d4a.png)成功猜解出一表名，点到为止，拿下高危
