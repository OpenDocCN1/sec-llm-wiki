卡巴斯基在线防护API容易被网站滥用

原文：http://mp.weixin.qq.com/s?__biz=Mzg3MjI1MDU4OA==&mid=2247486781&idx=1&sn=e617a25b69450c2d1047e3d10ebdc0cf&chksm=cef3608ef984e9986d25a2fec99d0b842b6e91613c05672489e5f6c1b6f88e9e6dde6d12ce05&scene=27#wechat_redirect


卡巴斯基软件中的漏洞使内部API易于被网站管理员滥用，并且迄今为止，尝试进行修补均已失败。 



周一，软件开发人员弗拉基米尔·帕兰特（Wladimir Palant）记录了这一传奇故事，该传奇故事始于他开始调查软件（例如Kaspersky Internet Security 2019）中包含的Kaspersky Web Protection功能。在线保护功能包括扫描搜索结果以清除潜在的恶意链接，广告拦截，和跟踪预防。 


去年12月，开发人员在Web保护功能中发现了一系列漏洞和安全问题，任何网站都可以启用该功能。


Web Protection需要能够与主Kaspersky应用程序进行通信，并启用“秘密”签名值（该值在理论上是Web域不知道的），以确保安全通信。但是，据Palant称，存在安全漏洞，网站可以“非常容易地”获得此密钥，并“允许它们建立与Kaspersky应用程序的连接并像Web Protection一样发送命令”。


Chrome和Firefox扩展使用本机消息传递来检索签名，而Internet Explorer读取脚本注入。如果没有浏览器扩展，卡巴斯基将直接将其脚本注入到网页中，这是笔记的第一个漏洞CVE-2019-15685，它是通过滥用URL Advisor和框架来提取签名而出现的。


开发人员说：“网站可以利用此漏洞来静默禁用广告拦截和跟踪保护功能。” “他们还可以做很多事情，但影响并不那么明显。”


在报告了该漏洞之后，卡巴斯基于2019年7月通过阻止访问2020产品中的网站某些功能来开发了修复程序。但是，仍然可以接受其他命令，例如将adblocker上的网站列入白名单（CVE-2019-15686）。由于补丁失败，也出现了一个新问题。网站能够访问用户系统数据，包括PC上卡巴斯基安装的唯一标识符（CVE-2019-15687）。 


“当我尝试新的Kaspersky Internet Security 2020时，从注入的脚本中提取秘密仍然是微不足道的，而主要的挑战是使概念验证代码适应API调用约定的更改，” Palant说。“坦率地说，我不能怪卡巴斯基开发人员甚至没有尝试-我认为在他们无法控制的环境中保护自己的脚本是一个失败的原因。”


这种无意引入的数据泄漏还没有结束。Palant表示，该补丁程序还引入了一个新漏洞，该漏洞可用于触发防病毒程序崩溃，从而使系统容易受到损害，跟踪代码为CVE-2019-15686。

 

然后，网络安全公司尝试进行另一项修复，以解决数据泄漏并“主要”修复崩溃问题。网站不再可能导致崩溃，但浏览器扩展或本地应用程序可能会崩溃。 


已经开发了一个新的补丁程序，并将在11月28日发布，但是使用后备脚本注入方法而不是仅仅依靠浏览器扩展，对于真正解决问题，开发人员并不抱有希望。 


该开发人员说：“也许卡巴斯基是如此依赖直接注入到网页中的脚本，因为这些脚本被认为是其产品的独特功能，即使用户拒绝安装扩展程序，它也能够胜任。” “但是该功能也恰恰是安全隐患，而且似乎无法弥补。”


“但是，一件事不会改变：网站仍然可以向Kaspersky应用程序发送命令。它们可以触发那里的所有功能是否无害？我不会打赌。”


更新：卡巴斯基发言人告诉外媒：


“卡巴斯基在其产品和Google Chrome浏览器产品扩展中的网络保护组件中已修复安全问题。这些安全问题已通过补丁2019 I，J和2020 E，F修复，这些补丁已通过自动更新过程分发给用户。 


可能需要重新启动才能应用这些更新。 


该公司还建议用户确保已安装并启用Web浏览器的Kaspersky保护扩展。有关已解决问题的详细信息，请访问卡巴斯基网站。”
