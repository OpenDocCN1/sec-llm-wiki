赛门铁克企业版现权限提升漏洞已紧急修复


Symantec修复了一个本地特权升级安全漏洞，该漏洞影响了14.2 RU2之前的所有Symantec Endpoint Protection软件版本，并允许攻击者提升受感染设备的特权并使用SYSTEM特权执行恶意代码。



Symantec Endpoint Protection是一套安全解决方案，包括针对台式计算机和服务器计算机的入侵防护，防火墙，数据丢失防护和反恶意软件功能。


不是向安全供应商报告的第一个LPE错误

这不是SafeBreach Labs安全研究员Peleg Hadar今年向安全供应商报告的第一个本地特权升级安全问题，该人还发现了Symantec Endpoint Protection LPE。 


趋势科技，Check Point Software，Bitdefender，Avast和McAfee修复了安全漏洞（跟踪为CVE-2019-14684，CVE-2019-8461，CVE-2019-15295，CVE-2019-17449，CVE-2019-17093，和CVE-2019-3648）在收到研究者的披露报告后，用户将通过安全应用内建的自动更新功能接收更新。


赛门铁克修复了特权升级漏洞

现已将Symantec Endpoint Protection LPE Bug跟踪为  CVE-2019-12758，  要求潜在的攻击者具有管理员权限才能成功将此问题利用到Hadar。


虽然这种脆弱性的威胁等级不是立即显而易见的，这样的错误通常额定具有中等和高严重性CVSS 3.x的基础分数[ 1，  2 ]。


黑客在渗透目标计算机以提升权限以进一步损害设备并建立持久性之后，将DLL搜索顺序劫持问题（例如多阶段攻击）滥用为这种攻击。


成功利用后，可以将其用于“通过将任意未签名的DLL加载到由Symantec签名并作为NT AUTHORITY \ SYSTEM运行的进程中，绕过Symantec的自我防御机制并实现防御逃避，持久性和特权提升，” 哈达尔说。


赛门铁克在2019年10月22日发布的Symantec Endpoint Protection 14.2 RU2 版本中解决了LPE漏洞：

从CWD加载任意无符号DLL

Hadar说CVE-2019-12758是由于安全解决方案尝试从其当前工作目录（CWD）而不是DLL的实际位置加载DLL以及不验证DLL是否使用数字证书签名引起的。


研究人员发现，作为NT AUTHORITY \ SYSTEM签名进程运行的Symantec SepMasterService服务试图从其CWD（而不是其实际位置）的CWD中导入SysWow64文件夹中的C：\ Windows \ SysWow64 \ Wbem目录中的DSPARSE.dll。。


通过利用此错误，可以将一个未经签名的任意DLL加载到SepMasterService进程中（如果已在系统上具有管理员权限），从而绕过Symantec Endpoint Protection的自卫机制。


Hadar作为概念验证（Poc）演示的一部分，在SysWow64 \ Wbem文件夹中植入了一个未签名的32位代理DLL，然后将其加载并在Symantec Corporation签名为NT的进程中执行AUTHORITY \ SYSTEM，正如预期的那样规避了Symantec Endpoint Protection的自卫机制。



概念验证（SafeBreach实验室）


Hadar指出：“该漏洞使攻击者能够在Symantec签名的过程中加载和执行恶意有效载荷。”


“攻击者可能会出于不同目的（例如执行和逃避）滥用此功能，例如：应用程序白名单绕过。防病毒软件可能不会检测到攻击者的二进制文件，因为它试图在不对其进行任何验证的情况下尝试加载它。”


利用运行Symantec Endpoint Protection漏洞版本的计算机上的CVE-2019-12758错误，还可以使攻击者有可能在每次将Symantec服务加载到系统上时加载并启动恶意代码，从而获得持久性系统重启之间。


Hadar报告的末尾提供了有关如何发现LPE缺陷，对其根本原因的全面分析以及完整披露时间表的更多信息。

McAfee家用防病毒全系现权限提升漏洞，已紧急修复

McAfee防病毒软件中的一个漏洞，它可能使攻击者升级特权并以SYSTEM特权执行代码。



SafeBreach的安全专家发现了McAfee防病毒软件中的漏洞，跟踪为CVE-2019-3648，该漏洞可能允许具有管理员特权的攻击者升级特权并以SYSTEM特权执行代码。


该漏洞会影响McAfee Total Protection（MTP），McAfee Anti-Virus Plus（AVP）和McAfee Internet Security（MIS）所有版本包括 16.0.R22。



在CVE-2019-3648漏洞可以被攻击者利用来加载未签名的DLL到多个服务运行作为NT AUTHORITY \ SYSTEM。


“这个该漏洞可能已被用来绕过McAfee的自我防御机制；通过将任意未签名的DLL加载到以NT AUTHORITY \ SYSTEM运行的多个服务中来实现防御逃避和持久性。”阅读SafeBreach发布的分析。 


“该软件的多个部分作为Windows服务运行，以“ NT AUTHORITY \ SYSTEM”执行，为其提供了非常强大的权限。”“可以利用此漏洞在多个McAfee服务的上下文中实现任意代码执行，从而获得访问权限具有NT AUTHORITY \ SYSTEM级别的特权。

专家发现，McAfee软件的多种服务试图从路径c：\ Windows \ System32 \ wbem \ wbemcomn.dll加载一个库，因为该库位于System32而不是System32 \ Wbem文件夹中，所以找不到该库。


攻击者可以放置恶意软件 dll文件名为wbemcomn.dll在 的 wbem 文件夹并执行它。专家解释说，有可能绕过防病毒软件的自防御机制，因为防病毒软件无法验证电子签名 DLL文件。


研究人员通过从原始wbemcomn.dll DLL文件中编译一个代理DLL（未签名）来测试此缺陷，该文件写有加载进程的名称，执行该进程的用户名以及DLL文件的名称。然后专家将其植入C：\ Windows \ System32 \ Wbem，然后重新启动计算机：


“我们能够加载任意DLL并在由McAfee，LLC签名为NT AUTHORITY \ SYSTEM的多个进程中执行代码，从而绕过了程序的自卫机制。”专家继续说道。


专家分别于8月和11月12日向McAfee报告了该漏洞 麦卡菲发布了安全公告，并发布了补丁程序来解决此问题。McAfee确认它不知道该漏洞可用于野外攻击。


安全突破在其他厂商的其他安全解决方案中发现了类似的问题，包括趋势科技，Check Point，Bitdefender，  AVG和Avast。
