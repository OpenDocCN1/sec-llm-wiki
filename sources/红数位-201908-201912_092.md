# 微软敦促用户修补易受BlueKeep攻击的系统，这仅仅是开始，最坏的在后头

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=Mzg3MjI1MDU4OA==&mid=2247486555&idx=2&sn=49dce16abaa1d94609bdd3403de44739&chksm=cef361e8f984e8fede4dd41b2cc1261976093a6d32b9eb334571d8dc1a3d3964ae71e73caf46&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=Mzg3MjI1MDU4OA==&mid=2247486555&idx=2&sn=49dce16abaa1d94609bdd3403de44739&chksm=cef361e8f984e8fede4dd41b2cc1261976093a6d32b9eb334571d8dc1a3d3964ae71e73caf46&scene=27#wechat_redirect)

****![](../Images/533414f6c4ac61ba1231567613f86972.png)****

**微软在发现BlueKeep漏洞利用尝试激增后，紧急呼吁用户修补过时的Windows系统。**

  

![](../Images/ff3ac51474067ded5cf85568f25daaed.png)  

**点击阅读：**[**全球首个BlueKeep大规模黑客攻击来袭！**](http://mp.weixin.qq.com/s?__biz=Mzg3MjI1MDU4OA==&mid=2247486369&idx=1&sn=1f506128095cd42a127c11430ae1e7cd&chksm=cef36612f984ef04c7b6f114e114a4744001ae5077da15678aff62037573358c735588870197&scene=21#wechat_redirect)  

  

**微软Defender ATP研究小组在博客中说：****“微软的安全信号表明与RDP相关的崩溃增加了，这很可能与在某些易受攻击的机器上使用不稳定的BlueKeep Metasploit模块有关。****”**

  

据研究人员称，安全研究员凯文·博蒙特（Kevin Beaumont）在本月初报告的BlueKeep攻击与9月首次发现的硬币挖掘运动有关，该运动使用相同的命令和控制服务器对易受攻击的系统进行攻击。

  

![](../Images/43989cbec6b3172f596a56455e512fc3.png)

  

在 11月3日发布的帖子中，博蒙特报道说，他创建用来检测BlueKeep漏洞的发展的“全球蜜罐网络”已经崩溃。

  

博蒙特说，第一次崩溃事故发生在10月23日，然后所有剩余的蜜罐（澳大利亚除外）也崩溃。

  

另一名安全研究人员Marcus Hutchins（也称为MalwareTech）也证实了BlueKeep漏洞正在遭受攻击。

  

**微软安全研究人员与Beaumont和Hutchins合作调查了这些崩溃，并发现它们是由BlueKeep漏洞利用模块引起的。**

  

微软表示，已在9月初为BlueKeep Metasploit模块部署了行为检测系统。该公司注意到，从9月6日开始，RDP服务崩溃每天从10个增加到100个。从10月9日开始，内存损坏崩溃也出现了类似的高峰。

  

*   自Metasploit模块发布以来，从2019年9月6日开始，RDP服务的崩溃从每天的10起增加到每天100起
    
*   从2019年10月9日开始，内存损坏崩溃的增加也类似
    
*   从2019年10月23日开始，外部研究人员蜜罐崩溃
    

  

  

![](../Images/3452eb1ef10d8d76ed9b7d5839d79272.png)

  

BlueKeep是一个可蠕虫的远程执行代码漏洞，影响Windows XP，Windows 7，Windows Server 2003，Windows Vista，Windows Server 2008和Windows Server 2008 R2。索引为CVE-2019-0708，此漏洞是预身份验证，这意味着它不需要用户交互。

  

![](../Images/024cf2da0e43391351815d9c9d4d9238.png)

遭遇此次影响的地理分布

  

由于它是蠕虫病毒，因此它可以使利用此漏洞的任何恶意软件都能从一个易受攻击的系统传播到另一个易受攻击的系统，而无需用户交互。

  

这些攻击很可能是通过对具有脆弱的，面向Internet的RDP服务的计算机进行端口扫描而发起的。攻击者找到此类计算机后，便使用BlueKeep Metasploit模块运行PowerShell脚本，该脚本最终下载并启动了其他一些编码的PowerShell脚本。

  

![](../Images/6c3214ebf021e73adf5361ce606c182a.png)

最初尝试利用BlueKeep的技术和组件

  

主要使用内存转储来拼凑PowerShell脚本的行为。在外部研究人员博客中还讨论了以下脚本活动：

1.  初始脚本通过端口443从位于法国某处的攻击者控制的远程服务器（5.135.199.19）下载了另一个编码的PowerShell脚本。
    
2.  后续脚本下载并启动了一系列其他三到四个编码的PowerShell脚本。
    
3.  最终脚本最终从托管在英国的另一台由攻击者控制的服务器（109.176.117.11）下载了硬币采矿机的有效负载。
    
4.  除了下载有效载荷外，最终脚本还创建了计划任务以确保硬币开采者保持持久状态。
    

  

![](../Images/44abbb57dd8428927255504220c2c5ce.png)

攻击中使用的PowerShell脚本的内存转储

  

最终脚本将挖矿恶意软件保存为以下文件：

C：\\ Windows \\ System32 \\ spool \\ svchost.exe

  

挖矿恶意软件以5.100.251.106的价格连接到以色列的指挥与控制基础设施。在早期活动中部署的其他未利用BlueKeep的挖矿恶意软件也已连接到该IP地址。

  

与BlueKeep相关的风险迫使Microsoft于5月14日发布了Windows XP的补丁程序，这是多年以来的首次。尽管如此，近百万的Windows系统仍然容易受到BlueKeep截至5月2019年。

  

![](../Images/bd2a38079d0bab7c2999e41f7747b575.png)

  

本月初发起的攻击并未部署任何可感染蠕虫的恶意软件。相反，威胁行动者一次扫描了网络中易受攻击的计算机并攻击了未修补的系统。他们首先部署了BlueKeep漏洞，然后部署了挖矿恶意软件。

  

**根据微软的说法：****这仅仅是开始，最坏的时刻还没有到来。**

**安全信号和取证分析表明，BlueKeep Metasploit模块在某些情况下会导致崩溃，但是我们不能轻视可能会导致更有效攻击的增强功能。****此外，尽管在撰写本文时，还没有其他涉及勒索软件或其他类型恶意软件的经过验证的攻击，但BlueKeep漏洞可能会被用来提供比挖矿恶意软件更有影响力和破坏力的有效载荷（比如勒索等）。**

  

研究人员警告说，攻击者最终将改善他们的攻击，并将使用BlueKeep漏洞提供比硬币矿工更具破坏性的有效载荷。

  

**微软表示，“只要系统未打补丁，BlueKeep将继续构成威胁”，并且“总体安全状况不会受到控制”。**

  

**“由于BlueKeep可以被利用而不会留下明显痕迹，因此客户还应该彻底检查可能已经被感染或受到破坏的系统。****”**

**BLUEKEEP摘要**

由于今年有大量与BlueKeep相关的报道，因此以下是您需要了解的摘要：

  

*   BlueKeep是CVE-2019-0708的昵称，CVE-2019-0708是Microsoft RDP（远程桌面协议）服务中的漏洞。
    
*   BlueKeep仅影响：Windows 7，Windows Server 2008 R2，Windows Server 2008。
    
*   修补程序自2019年5月中旬起可用。请参阅Microsoft官方通报。
    
*   在发布补丁程序的同一天，Microsoft发表了一篇博客文章，警告说BlueKeep具有可感染性。
    
*   微软在5月底发布了第二条警告，要求组织需要补丁BlueKeep，两周后。
    
*   在美国国家安全局的美国国土安全部，德国BSI网络安全代理，澳大利亚网络安全中心，与英国的国家网络安全中心都各自触发警报，试图让企业修补过时的电脑舰队。
    
*   整个夏天，许多安全研究人员和网络安全公司开发了完全有效的BlueKeep漏洞；但是，没有人意识到该漏洞利用有多么危险，并担心恶意软件作者可能会滥用该代码，因此没有人发布该代码。
    
*   7月，一家美国公司开始向其客户出售私有BlueKeep漏洞，以便他们可以测试其系统是否易受攻击。
    
*   9月，Metasploit渗透测试框架的开发人员发布了第一个公开的BlueKeep概念验证漏洞。
    
*   10月下旬，恶意软件作者开始在实际活动中使用此BlueKeep Metasploit模块。Microsoft 在此处有一篇有关此恶意软件活动的文章。
    
*   根据BinaryEdge的说法，大约有700,000个Internet连接的Windows系统容易受到BlueKeep的攻击，并且尚未收到补丁。
