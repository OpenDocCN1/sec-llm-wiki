# 新Microsoft NTLM缺陷可能允许完整域破坏

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=Mzg3MjI1MDU4OA==&mid=2247485525&idx=3&sn=c96545fdc96c09da93b49c5bfc410618&chksm=cef365e6f984ecf076098d20edd54afb868eb97c7221b5a8e59e02def0f138a457f1d24de9cc&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=Mzg3MjI1MDU4OA==&mid=2247485525&idx=3&sn=c96545fdc96c09da93b49c5bfc410618&chksm=cef365e6f984ecf076098d20edd54afb868eb97c7221b5a8e59e02def0f138a457f1d24de9cc&scene=27#wechat_redirect)

  

微软的NTLM身份验证协议中的两个安全漏洞使攻击者可以绕过MIC（消息完整性代码）保护并降级NTLM安全功能，从而导致整个域受到损害。

  

![](../Images/7c83aa2c18f9dcfefe85de8bb3617ff4.png)

  

微软在Preempt披露后于昨日发布的星期二补丁更新中修复了这两个NTLM漏洞并发布了安全公告。

  

抢先公司的研究人员  Yaron Zinar和Marina Simakov发现，攻击者可以利用这些漏洞作为NTLM中继攻击的一部分，**在某些情况下，这些漏洞可能“导致网络的整个域受损”，并且所有具有默认配置的Active Directory客户都被暴露出来。**

  

Windows NT（新技术）LAN Manager（NTLM）身份验证协议用于客户端/服务器身份验证目的，以对远程用户进行身份验证，并在应用程序协议要求时提供会话安全性。

  

NTLM已被Kerberos取代，Kerberos现在是Windows 2000之上所有Windows版本的域连接设备的默认身份验证协议。

  

“尽管Kerberos在大多数组织中是更普遍的身份验证协议，但NTLM仍处于启用状态，因此被攻击者滥用以利用我们上面描述的漏洞，” Preempt通报补充道。

  

**篡改漏洞会影响所有受支持的Windows版本**

Preempt的研究团队能够发现可能被潜在攻击者滥用的缺陷，从而规避了Microsoft提供的NTLM中继缓解措施。

  

微软在添加消息完整性代码（MIC）字段以阻止攻击者篡改NTLM消息时，Preempt的研究人员发现绕过  NTLM身份验证，攻击者可以“修改NTLM消息流中的任何字段，包括签名要求”。

  

“这种旁路使攻击者可以将已经成功协商签名的身份验证尝试中继到另一台服务器，同时诱使服务器完全忽略签名要求。”

  

导致这种绕过的NTLM篡改漏洞被跟踪为  CVE-2019-1166  （被Preempt 称为Drop The MIC 2），并且如上所述，由Microsoft昨天于10月的周二补丁程序中进行了修补。

  

![](../Images/0350e7fa6ed5457662e160fb2ba42d88.png)

NTLM中继基本流程

  

CVE-2019-1166影响所有受支持的Windows版本，所有不执行签名的服务器都容易受到利用它的攻击。

  

微软的通报说：“当中间人攻击者能够成功绕过NTLM MIC（消息完整性检查）保护时，Microsoft Windows中便存在一个篡改漏洞。” “成功利用此漏洞的攻击者可以获得降级NTLM安全功能的能力。”

  

**第二个缺陷影响发送LMv2响应的客户端**

Preempt发现的第二个缺陷还规避了针对NTLM中继攻击以及其他NTLM中继缓解措施的MIC保护，包括但不限于“某些身份验证发送给LMv2的旧NTLM客户端的增强型身份验证（EPA）和目标SPN验证”回应。”

  

Windows NTLM安全功能绕过漏洞的漏洞跟踪为CVE-2019-1338  ，与第一个漏洞一样，由Microsoft作为本月补丁星期二的一部分进行了修补。

  

它 会影响Windows 7 SP1，Windows 2008和Windows 2008 R2设备，并且可以用于使威胁攻击者“使用NTLM中继成功认证诸如OWA和ADFS之类的关键服务器并窃取有价值的用户数据的攻击”。

  

微软的安全公告说：“当客户端同时发送LMv2响应时，中间人攻击者能够成功绕过NTLMv2保护，则Microsoft Windows中存在一个安全功能旁路漏洞。” 

  

“成功利用此漏洞的攻击者可以获得降级NTLM安全功能的能力。”

  

**具有默认配置的AD客户容易受到攻击**

要利用CVE-2019-1166，潜在的攻击者将需要篡改NTLM交换，而尝试将CVE-2019-1338作为其攻击一部分的攻击者则需要能够修改NTLM流量交换。

  

Preempt研究人员补充说：“所有具有默认配置的Active Directory客户都容易受到此类攻击。”

  

“此外，不阻止LM响应并让客户端仍发送这些默认响应的组织容易受到针对这些客户端的有针对性的攻击，从而绕过其他NTLM保护”

  

Preempt的分析中提供了有关这两个NTLM缺陷的更多技术细节和背景信息。

  

**以前的NTLM缺陷和保护**

这不是Preempt首次发现NTLM漏洞，它具有两个由三个逻辑缺陷组成的漏洞，并且允许攻击者在运行 Microsoft修复的Windows版本的计算机上运行远程代码并进行身份验证，这是6月Patch Tuesday安全更新的一部分。

  

此前，Preempt披露了当时影响所有受支持Windows版本的另一个漏洞，该漏洞  由Microsoft在2017年7月补丁星期二修复  ，并使攻击者能够在本地网络的域控制器（DC）上创建管理员帐户。

  

Preempt的研究团队提供以下建议，以保护受这些漏洞影响的设备的网络：

  

*   强制实施NTLM缓解措施。为了完全免受NTLM中继攻击，您需要在所有相关服务器上启用服务器签名和EPA。
    
*   补丁！确保您的系统受到最新安全更新的完全保护。
    
*   应用高级的NTLM中继检测和预防技术，类似于Preempt在我们的Black Hat 2019演讲中公开的技术（可在此处找到免费的Encore演示文稿）。
    
*   一些NTLM客户端使用较弱的NTLM变体（例如，不发送MIC）。这使您的网络更容易受到NTLM中继的攻击。监视网络中的NTLM通信，并尝试限制不安全的NTLM通信。
    
*   摆脱发送LM响应的客户端，并设置GPO网络安全性：LAN Manager身份验证级别以拒绝LM响应。
    
*   不建议一般使用NTLM，因为它会引起一些安全问题：NTLM中继，暴力破解和其他漏洞。您可以在此处阅读有关NTLM的一般风险  。根据经验：请尝试尽可能减少网络中的NTLM使用。
    

  

Preempt的首席技术官兼联合创始人Roman Blachman在6月表示： “即使NTLM Relay是一种旧技术，企业也无法完全消除对该协议的使用，因为它将破坏许多应用程序。”

  

因此，它仍然对企业构成重大风险，尤其是不断发现新的漏洞时。”
