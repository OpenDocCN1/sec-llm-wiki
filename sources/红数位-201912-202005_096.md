# 微软Exchange：355000台服务器缺少重要补丁

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=Mzg3MjI1MDU4OA==&mid=2247488375&idx=4&sn=39dc230891749f6d51fa03d3e40689ff&chksm=cef37ec4f984f7d2cd2943d38e072cc9f79d20124ca1abd8b54f3f981647a5a04521b19f14c4&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=Mzg3MjI1MDU4OA==&mid=2247488375&idx=4&sn=39dc230891749f6d51fa03d3e40689ff&chksm=cef37ec4f984f7d2cd2943d38e072cc9f79d20124ca1abd8b54f3f981647a5a04521b19f14c4&scene=27#wechat_redirect)

位于波士顿的Rapid7 Labs的高级经理汤姆·塞勒斯（Tom Sellers）在博客中写道：“截至3月24日，有超过35万台Exchange服务器公开了具有此漏洞的软件版本。”

  

![](../Images/51eaea9851f19c8293d0aaa0bfe7e726.png)

  

他说，该漏洞可能使远程攻击者“将所有被盗的Exchange用户帐户变成一个完整的系统威胁”。“在许多实现中，这可以用来完全破坏整个Exchange环境-包括所有电子邮件-甚至可能破坏所有Active Directory”（请参阅：为什么黑客滥用Active Directory）。

  

![](../Images/fe3650b96e449c70fda1f5eb308253d8.png)

  

Microsoft通过2月11日针对所有受支持的Microsoft Exchange版本发布的安全更新解决了名为CVE-2020-0688的远程执行代码漏洞。该公司表示，至少到那时，该漏洞似乎并不是针对性的。该漏洞是由匿名研究人员通过趋势科技的“零日行动计划”报告给Microsoft的。

  

微软在其安全警报中说：“当服务器在安装时未能正确创建唯一密钥时，Microsoft Exchange Server中将存在一个远程执行代码漏洞。” “验证密钥的知识使具有邮箱的经过身份验证的用户可以传递要由Web应用程序反序列化的任意对象，该Web应用程序以SYSTEM身份运行。此安全更新通过更正Microsoft Exchange在安装过程中创建密钥的方式来解决该漏洞。”

  

**安全更新包括补丁**

为了修复此缺陷，Microsoft推出了针对四个基本版本的Exchange的安全更新：

  

*   Exchange Server 2010 Service Pack 3更新汇总30；
    
*   Exchange Server 2013累积更新23；
    
*   Exchange Server 2016累积更新14;
    
*   Exchange Server 2016累积更新15;
    
*   Exchange Server 2019累积更新3;
    
*   Exchange Server 2019累积更新4。
    

  

但是，根据Rapid7内部互联网扫描项目Project Sonar进行的一项调查，这些服务器中的绝大多数仍未打补丁（请参阅：COVID-19是否正在推动不安全的远程连接激增？）。

  

卖家说：“ 3月24日，我们使用Sonar项目对互联网进行了公开调查，以了解面向公众的Exchange Outlook Web App-OWA-服务。” “我们发现，在我们观察到的433,464台Exchange服务器中，至少有357,629台（82.5％）是易受攻击的。”

  

随后，卖方提出警告，由于Microsoft对Exchange 2010的修复未更新可见的构建信息，因此可能会减少35,000台服务器的漏洞，这意味着仅扫描无法确定Exchange 2010系统是否已更新。相反，组织将需要手动验证每个此类系统都有更新。卖家表示，他们应该对所有Exchange 2013及更高版本的系统执行相同的操作，并指出仅内部版本号应指示相关更新是否到位。

  

**检查是否妥协**

Rapid7还建议所有使用Exchange搜索的组织查找由于此漏洞而受到危害的任何迹象。

  

卖家说：“我们在Windows事件日志和IIS \[Internet Information Services\]中用左日志构件测试的漏洞利用代码会在已打补丁的服务器和未打补丁的服务器上记录日志，”卖方指出，日志错误消息还将命名受感染的用户帐户。

  

![](../Images/65bcff4b864d961a958b54d54919c19f.png)

Rapid7的汤姆·塞勒斯（Tom Sellers）表示：“您将在日志条目的末尾看到被盗用的帐户名的用户名。”

  

由于攻击要求成功的有效Exchange用户帐户才能成功，因此“在这些利用尝试中看到的任何用户帐户都应被视为受到威胁”，Sellers说。

  

**但是等等，还有更多**

不幸的是，“声纳计划”扫描显示出比缺少CVE-2020-0688修补程序更为广泛的问题。值得注意的是，Rapid7研究人员发现31,000台Exchange 2012服务器在线，自2012年以来没有更新，还有800台从未更新的Exchange 2010服务器。它还看到了10,371台Exchange 2007服务器。

  

塞勒斯说：“除了缺少多次更新的大量服务器外，还有数量众多的Exchange 2007和2010服务器。”塞勒斯说，尽管他指出Exchange 2007并不容易受到CVE-2020-0688的攻击。即便如此，不受支持的操作系统很久以前就停止接收安全更新，而现在却存在大量可供攻击者利用的严重缺陷。他说：“ Exchange 2007在大约三年前的2017年4月11日过渡到'支持终止'状态。” 该日期之后没有提供安全更新，错误修复，时区更新等。”

  

Exchange 2010计划于1月14日终止支持，尽管现在已推迟至2020年10月13日。“卖家中有超过166,000台服务器已连接到Internet，” Sellers说。“这是数量惊人的企业级邮件系统，几个月后将不被支持。”
