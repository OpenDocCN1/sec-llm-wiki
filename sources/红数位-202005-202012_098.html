微软已在10月的补丁星期二版本中发布大量安全修复程序，其中11个被Microsoft评为“危急”（包括最新的Adobe Flash安全更新）。



在修补的漏洞中，虽然不是零日漏洞，但有两个漏洞危急程度明显高于其他漏洞：CVE-2020-16898和CVE-2020-16899，CSVV分数：9.8。


这些漏洞是由Windows TCP / IP驱动程序中的错误引起的，可以追溯到2013年Windows中修复的“ Ping of Death”（死亡之PING）漏洞。它们使精心制作的攻击数据包可以让系统拒绝服务并可能执行远程代码。


微软其实已经在 2013 年修复过该漏洞。

当时受影响操作系统：

  • Windows Vista

  • Windows 7

  • Windows 8

  • Windows Server 2008

  • Windows Server 2008 R2

  • Windows Server 2012

  • Windows RT

不受影响的操作系统

  • Windows XP Service Pack 3

  • Windows XP Professional x64 Edition Service Pack 2

  • Windows Server 2003 Service Pack 2

  • Windows Server 2003 x64 Edition Service Pack 2

  • Windows Server 2003 SP2


 然而由于未知的原因，2020 版的 Windows 10 系统竟然又躺枪了。

  • Windows 10版本1809（用于基于x64的系统）

据悉，该漏洞的核心，Tcpip.sys中包含驱动程序解析ICMP消息时的逻辑错误，可以使用包含递归DNS服务器（RDNSS）选项的精心制作的IPv6路由器广告包来远程触发。RDNSS选项通常包含一个或多个递归DNS服务器的IPv6地址列表。 


此外该漏洞利用涉及特制的 IPv6 路由广播封包，在让驱动程序的数据处理能力过载的情况下，即可导致缓冲区溢出或蓝屏死机。

庆幸的是，微软已经在 Windows 10 2020 十月更新中修复了这一问题。此外还有临时解决方案，比如完全禁用 IPv6 通讯协议。


📌临时修补建议：

可以禁用IMCPv6 RDNSS来缓解风险，使用以下PowerShell命令禁用ICMPv6 RDNSS，以防止攻击者利用此漏洞。此解决方法仅适用于Windows 1709及更高版本。

netsh int ipv6 set int *INTERFACENUMBER* rabaseddnsconfig=disable


进行更改后无需重新启动。

可以使用以下PowerShell命令禁用上述解决方法。

netsh int ipv6 set int *INTERFACENUMBER* rabaseddnsconfig=enable


虽然该漏洞还可被用于远程代码执行（RCE），但 Sophos 测试表明，其并没有前述的拒绝服务（DoS）攻击那样容易得逞。


恶意软件会利用该漏洞，相对轻松地对 Windows 安全系统进行欺骗。对于普通用户来说，还请记得及时更新 —— 但愿这批补丁不会又引入新的 bug 。
