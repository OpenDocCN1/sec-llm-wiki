黑客可以利用Microsoft Windows DNS服务器中已经存在了17年的一个严重漏洞来获取Domain Administrator特权，并破坏其背后的整个企业基础结构。



该漏洞收到了跟踪标识符CVE-2020-1350和名称SIGRed。这是一个远程代码执行，会影响Windows Server 2003到2019版，并获得最高严重等级，得分10分。


它具有蠕虫功能，这意味着利用漏洞可以自动传播到网络上易受攻击的计算机，而无需用户干预。此特征使它与服务器消息块（SMB）中的EternalBlue和远程桌面协议（RDP）中的BlueKeep处于同一风险类别。


DNS软件包格式错误

域名系统（DNS）是Internet的电话簿，使客户端可以连接到服务器以访问资源。它是一种将域名映射到IP地址以启用与正确服务器的连接的模型。


该模型是分层的和分散的，因此，如果DNS服务器将阶梯式转发给它没有答案的查询。在层次结构的顶部是13台具有所有信息的根DNS服务器。


Check Point的研究人员发现了Microsoft DNS实施中的一个缺陷，当服务器解析传入的查询或对转发请求的响应时，可以利用该缺陷。


他们发现整数溢出导致“ dns.exe！SigWireRead”中基于堆的缓冲区溢出，该函数为SIG查询解析响应类型。


“总而言之，通过发送包含大（大于64KB）SIG记录的DNS响应，我们可以在一个小的分配缓冲区上引起大约64KB的基于堆的受控缓冲区溢出” – Check Point


在今天的技术博客中，研究人员详细说明了他们如何通过使用足够大的SIG响应来响应目标查询中的一个来触发该错误，从而利用目标DNS服务器中的漏洞。


为了使目标Windows DNS服务器解析其计算机上的响应，研究人员进行了以下操作：


  1. 配置我们域的（deadbeef.fun）NS记录以指向我们的恶意DNS服务器（ns1.41414141.club）

  2. 查询受害者Windows DNS服务器以获取deadbeef.fun的NS记录

  3. 受害DNS尚不知道此查询的答案，将查询转发到其上方的DNS服务器（8.8.8.8）

  4. 权威服务器（8.8.8.8）知道答案，并回答deadbeef.fun的NameServer为ns1.41414141.club

  5. 受害者Windows DNS服务器处理并缓存此响应

  6. 下次我们查询deadbeef.fun的子域时，目标Windows DNS服务器还将查询ns1.41414141.club的响应，因为它是该域的NameServer。


研究人员发现，利用SIGRed的威胁参与者不必与目标DNS服务器位于同一网络上，因为DNS数据可以通过Windows DNS支持的TCP连接进行传输。


这样，目标服务器将数据打包为HTTP有效负载，也会将其解析为DNS查询。


Check Point指出，由于Windows DNS服务器支持“连接重用”和“管道传输”，因此攻击者可以通过TCP连接启动多个查询，而不必等待答复。


这些功能允许将带有二进制数据的HTTP POST请求发送到服务器，该请求在POST数据中具有另一个DNS查询，需要分别进行处理。


即使在诸如Internet Explorer和Microsoft Edge之类的浏览器中，这也是可能的，该浏览器允许对DNS使用的端口53的请求。Google Chrome和Mozilla Firefox不允许对此端口进行HTTP请求。

漏洞存在17年

该漏洞已在Microsoft代码中存在17年以上。如果研究人员发现了这种情况，Check Point漏洞研究小组负责人Omri Herscovici说，假设其他参与者也已经发现它并不难。


“ DNS服务器漏洞是一个关键问题。大多数时候，它使攻击者离破坏整个组织仅一英寸之遥。这些漏洞类型中只有极少数已经发布”-Omri Herscovici


对于大小型组织而言，这足以激励他们优先考虑应用Microsoft今天为SIGRed 发布的补丁。


对于目前无法应用补丁的用户，Microsoft建议修改注册表以缓解此问题。更改将在重新启动DNS服务后生效：


HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\DNS\Parameters 

DWORD = TcpReceivePacketSize 

Value = 0xFF00


应用补丁程序后，管理员应通过删除值TcpReceivePacketSize及其数据将更改恢复到原始状态。
