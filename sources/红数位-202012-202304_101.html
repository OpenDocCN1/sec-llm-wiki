微软警告这两洞可以轻松接管整个域

原文：http://mp.weixin.qq.com/s?__biz=Mzg3MjI1MDU4OA==&mid=2247498648&idx=2&sn=5f2bbbe129b7d79e170f0671e1b90325&chksm=cef0962bf9871f3deeed46cab6b57046fae391156e373ecd69589cad0c682fa3ae0df0580395&scene=27#wechat_redirect

微软今天警告客户修补两个“Windows Active Directory域服务权限提升漏洞”，当这些漏洞结合在一起时，攻击者可以轻松接管整个Windows域。



微软在2021年11月的星期二补丁日发布了安全更新，以解决两个安全漏洞(编号CVE-2021-42287和CVE-2021-42278，由Catalyst IT的Andrew Bartlett报告)。


12月12日，在Twitter和GitHub上共享了一个可以利用这些漏洞的概念验证 (PoC) 工具之后，微软警告立即修补这两个漏洞——这两个漏洞都允许攻击者冒充域控制器。“当结合这两个漏洞时，攻击者可以在没有应用这些新更新的Active Directory 环境中创建到域管理员用户的直接路径，”微软在今天发布的公告中解释道。


“一旦攻击者危害域中的普通用户，这种升级攻击允许攻击者轻松地将他们的权限提升为域管理员的权限。一如既往，我们强烈建议尽快在域控制器上部署最新补丁。”


微软都下场警告了，肯定这坑不是一般的大，不仅只会有Poc，应该已经检测到攻击了。


敦促 Windows 管理员使用以下知识库文章中详述的步骤和信息更新易受攻击的设备：KB5008102、KB5008380、KB5008602：


  • https://support.microsoft.com/en-us/topic/kb5008102-active-directory-security-accounts-manager-hardening-changes-cve-2021-42278-5975b463-4c95-45e1-831a-d120004e258e

  • https://support.microsoft.com/en-us/topic/kb5008380-authentication-updates-cve-2021-42287-9dafac11-e0d0-4cb8-959a-143bd0201041

  • https://support.microsoft.com/en-us/topic/november-14-2021-kb5008602-os-build-17763-2305-out-of-band-8583a8a3-ebed-4829-b285-356fb5aaacd7

如何检测漏洞利用迹象


Microsoft还分享了有关检测环境中的漏洞利用迹象和使用Defender for Identity高级搜索查询来识别潜在受损服务器的详细指南，该查询可查找异常设备名称更改。


分步指南要求你做的操作：


1.sAMAccountName更改基于事件4662。请确保在域控制器上启用它以捕获此类活动。在此处了解有关如何操作的更多信息：

https://docs.microsoft.com/en-us/defender-for-identity/configure-windows-event-collection#configure-object-auditing

2.打开Microsoft 365 Defender并导航到Advanced Hunting。

复制以下查询（也可在 Microsoft 365 Defender GitHub高级狩猎查询中找到）：

IdentityDirectoryEvents| where Timestamp > ago(1d)| where ActionType == "SAM Account Name changed"| extend FROMSAM = parse_json(AdditionalFields)['FROM SAM Account Name']| extend TOSAM = parse_json(AdditionalFields)['TO SAM Account Name']| where (FROMSAM has "$" and TOSAM !has "$")        or TOSAM in ("DC1", "DC2", "DC3", "DC4") // DC Names in the org| project Timestamp, Application, ActionType, TargetDeviceName, FROMSAM, TOSAM, ReportId, AdditionalFields

4.用域控制器的命名约定替换标记区域。

5.运行查询并分析包含受影响设备的结果。如果这些机器是新创建的，您可以使用Windows 事件 4741来查找这些机器的创建者。

6.我们建议调查这些受感染的计算机并确定它们没有被武器化。


“我们的研究团队继续努力创造更多的方法来检测这些漏洞，无论是通过查询还是开箱即用的检测，”微软最后补充道。
