## 0x01 概述

`Jackson-databind`的作用简单来说就是就是将json转换成对象。

## 0x02 漏洞分析

从payload来看，应该也是和

`org.springframework.context.support.FileSystemXmlApplicationContext`这个有关系。

```json
{
```

在这个地方下一个断点

`org/springframework/context/support/FileSystemXmlApplicationContext.class`

![](../Images/70e0dfdef9ff38e40140411337ca666c.png)

通过`idea`可以通过`diagrams`的`Show Diagram Popup`查看类与接口之间的继承关系。

![](../Images/f87b4cd1275bc246bb268661a7dbc98c.png)

在`beanFactory`中有`getBean`的构造方法

![](../Images/11b6cd9de49ee6c80787a1f781aac904.png)

而实际`getBean`的构造方法是在`AbstractBeanFactory`类中调用。

![](../Images/5cd5fbcdb9f218237abe67752a686fc3.png)

我们试着在`AbstractBeanFactory`类中的`getBean`方法下个断点也就是说程序通过一系列的`json`反序列化，以及反射机制进入到了`getBean`方法，并且获取到了这个name为`pb`的方法。

![](../Images/c1b3bf53868b174f85ee9effdaea2bad.png)

在`org.springframework.beans.factory.support.BeanDefinitionValueResolver#resolveValueIfNecessary`这里下断点，我看到经过`evaluate`处理之后`valueObject`等于我们要执行的`calc.exe`。

![](../Images/e37f0e30250fc0b103a98f11bf1180b0.png)

这里看一下`evaluate`方法的实现。

![](../Images/7e0ccd439b1fda4a0aef28c2e353e46f.png)

然后会继续解析`#{ pb.start() }`进，对`#{ pb.start() }`进行spel操作。

![](../Images/770f8d72d68a2daa5cd1c6d76401bc16.png)

当解析完`pb.start`操作后就会命令执行。

## 0x03 后话

回过头看一下发现`Weblogic-CVE-2019-2725`使用的`FileSystemXmlApplicationContext`和`CVE-2017-17485`使用的`FileSystemXmlApplicationContext`相比缺少了一步表达式解析，也就是

```java
Object valueObject = 
```

![](../Images/598250d323da94c6cde4298d6975279b.png)![](../Images/e37f0e30250fc0b103a98f11bf1180b0.png)

那我试试看，调整一下payload，当然也是可以的。

![](../Images/a323c5d43ac13c16240e0e5b3e89103d.png)

也就是说实际上`CVE-2017-17485`所用到的`spring`版本为`5.0.2`，它足够高，支持`spel`表达式的方法来初始化`bean`对象，而`Weblogic-CVE-2019-2725`所用到的`spring`版本过低，无法支持`spel`表达式，所以它需要通过指定`init-method`的方法来初始化`bean`对象。
