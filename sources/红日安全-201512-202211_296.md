# 0x01PHP漏洞产生的原因

PHP的漏洞有很大一部分是来自于程序员本身的经验不足，当然和服务器的配置有关，但那属于系统安全范畴了，今天我想主要谈谈关于PHP代码审计和漏洞挖掘的一些思路和理解。  
PHP的漏洞发掘，其实就是web的渗透测试，和客户端的fuzzing测试一样，web的渗透测试也可以使用类似的技术，web fuzzing，即基于web的动态扫描。  
这类软件国内外有很多，如WVS，Lan Guard，rips等。这类扫描器的共同特点都是基于蜘蛛引擎对我们给出的URL地址进行遍历搜索，对得到的URL和参数进行记录，然后使用本地或者web端的script脚本攻击语句进行攻击测试。  
WVS使用本地的脚本攻击数据库对这些参数进行交叉替换和填充，构造出新的URL，然后用GET或者POST的方式向服务器发出请求，并对返回的结果进行 正则判断。如是否出现:” You have an error in your SQL syntax”等字样。如果出现，则记录下来，说明这个脚本页面”可能”存在漏洞。  

![](../Images/cef42876a5b713600186b14b353b4749.png)

*   Wvs把攻击模块分成了很多模块：
    

*   Blind\_SQL\_Injection
    
*   AcuSensor
    
*   CSRF
    
*   Directory\_And\_File\_Check
    
*   File\_Upload
    
*   GHDB(Google黑客数据库)
    
*   Sql\_Injection
    
*   Weak\_Password
    
*   XSS
    

每种攻击测试方式都对应着一类scripts，里面包含了攻击语句。  
WVS查找的漏洞提示分两种，一种是启发式测试，就是作者说的“可能”。另外一种是带（verify）字样的，如果看到这个字样就恭喜你了，这是一个被证 实的漏洞。小编就曾经利用这个方法发掘过漏洞，效果不错。另外作者说的使用sqlmap进行测试，小编这里不太推荐。对于漏洞挖掘来说，最好使用手工注入 的方式来测试漏洞是否存在，毕竟现在只是挖掘漏洞，还不是在利用漏洞。我相信很多人都遇到过手工能测试成功。  

![](../Images/7d8d47b817c0d4ccb881377d6e4d5a7a.png)

Rips（基于对静态脚本的检测）的基本上会检查两种类型的变量，一种是关于`mysql_query()`，它认为一切输入的变量都是有害的，所有会格外注意这些输入的变量，会去判断它是否被过滤，如果没有过滤则会导致一写漏洞出现。  
对用户传输过来的数据进行跟踪，如`$_GET[]、$_POST[]、$_COOKIE`等进行检测。  
用户输入的一切数据都有害”，大部分的注入漏洞，包括二次注入，究其原因都是因为对用户的输入数据没有做好过滤，RIPS对这些敏感数据进行跟踪，并判 断其在进入敏感函数(`mysql_query()`)之前有没有对其进行有效处理(addslashes())来判断这条数据流是否存在漏洞。  
PHP源码中寻找以下变量：  
`$_SERVER`  
`$_SERVER` $\_SERVER是预定义服务器变量的一种，所有$\_SERVER开头的都是预定义服务变量\_SERVER开头的都是预定义服务变量  
`$_GET` $\_GET 变量用于收集来自 method=”get” 的表单中的值\_POST`预定义的 $_POST 变量用于收集来自 method="post" 的表单中的值`$_COOKIE`$_COOKIE -- $HTTP_COOKIE_VARS [已弃用]— HTTP Cookies说明 通过HTTP Cookies 方式传递给当前脚本的变量的数组`

`$_REQUEST` PHP $\_REQUEST 用于收集HTML表单提交的数据。`$_FILES` PHP编程语言中的常见的$\_FILES系统函数用法有：`$_FILES['myFile']['name']` 显示客户端文件的原名称 `$_ENV` PHP中的$\_ENV是一个包含服务器端环境变量的数组。。
