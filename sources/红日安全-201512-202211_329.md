执行BeautifulSoup  
在BeautifulSoup库最常用的对象是，BeautifulSoup对象。让我们来看看运行中的BeautifulSoup对象，修改在本章开始时发现的例子：  
from urllib.request import urlopen  
from bs4 import BeautifulSoup  
html = urlopen("http://www.pythonscraping.com/pages/page1.html")  
bsObj = BeautifulSoup(html.read())  
print(bsObj.h1)  
输出是：  
<h1>An Interesting Title</h1>  
在之前的例子，我们导入urlopen库并调用HTML.read()以获得页面的HTML内容。这个HTML内容，然后转化成一个beautifulsoup对象，具有以下结构：  
html → <html><head>...</head><body>...</body></html>  
— head → <head><title>A Useful Page<title></head>  
   — title → <title>A Useful Page</title>  
— body → <body><h1>An Int...</h1><div>Lorem ip...</div></body>  
    — h1 → <h1>An Interesting Title</h1>  
    — div → <div>Lorem Ipsum dolor...</div>  
  
注意从页面我们提取的<h1>标签，嵌套两层深入到我们beautifulsoup对象结构（HTML→body→H1）。然而，当我们真正把它从对象中取出，我们直接称之为H1标签：   
bsobj.h1   
    事实上，以下任何一个函数调用都会产生相同的输出：   
bsObj.html.body.h1  
bsObj.body.h1  
bsObj.html.h1  
我们希望这个beautifulsoup的小尝试让你认识到这个库的力量和简洁。几乎所有的信息都可以从任何HTML（或XML）文件提取，只要它有一些在其周围或附近的标签。在3章中，我们将更深入地研究一些更复杂的beautifulsoup函数调用，以及看看正则表达式，并研究如何在BeautifulSoup中使用正则表达式从网站提取信息。   
连接可靠性  
网络是混乱的。数据格式正确，网站关闭，关闭标签丢失。web scraper最令人沮丧的经验之一是，在scraper运行过程中休眠，以为第二天所有数据都会在你的数据库中，却发现，你停止看屏幕不就之后，由于scraper遇到了一些意想不到的数据格式的错误，停止执行。在这样的情况下，你可能会试图诅咒创建网站的开发人员（和奇怪的格式化数据），但你真的应该责怪的是你自己，因为你没有在第一时间预测到异常！  
  
让我们看一看我们的scraper的第一行，在导入语句后，并弄清楚如何处理这个可能会抛出的异常：  
html = urlopen("http://www.pythonscraping.com/pages/page1.html")  
  
在这一行有两个主要出错的可能：  
•在服务器上找不到这个页面（或者在检索服务器上有一定的错误）  
•在第一种情况下，服务器没有被找到，一个HTTP错误将返回。这个HTTP错误可能是“404找不到页面，“500内部服务器错误”等，在所有这些情况下，函数urlopen将抛出通用的异常“HTTPError”，我们可以用下面的方法处理这个异常  
try:  
html = urlopen("http://www.pythonscraping.com/pages/page1.html")  
except HTTPError as e:  
print(e)  
#return null, break, or do some other "Plan B"  
else:  
#program continues. Note: If you return or break in the  
#exception catch, you do not need to use the "else" statement  
  
如果一个HTTP错误代码返回，程序现在打印错误，没有执行else语句下的其他程序。  
如果服务器没有被发现（如果说，http://www.pythonscraping.com关闭，或网址打错了），urlopen返回空对象。此对象类似于其他编程语言中的空值。我们可以看看返回的HTML是否为空：  
if html is None:  
print("URL is not found")  
else:  
#program continues  
当然，如果页面从服务器上成功检索，页面上的内容仍然不太可能是我们所期望的。每次你访问一个beautifulsoup对象标签，添加一个检查以确保标签实际上存在是聪明的。如果你试图访问一个不存在的标签，BeautifulSoup将返回一个空对象。问题是，试图访问一个空对象标签本身会导致AttributeError异常被抛出。下面一行（在nonexistenttag是合成标签，不是一个真正的beautifulsoup函数的名称）：   
print(bsObj.nonExistentTag)  
返回一个空对象。这个对象是完全合理的处理和检查。问题是如果你不检查它，而是继续尝试在空对象上调用一些其他函数，如下面所述：  
print(bsObj.nonExistentTag.someTag)  
它将返回异常：  
AttributeError: 'NoneType' object has no attribute 'someTag'  
如何才能防范这两种情况？最简单的方法是显式检查这两种情况：   
try:  
badContent = bsObj.nonExistingTag.anotherTag  
except AttributeError as e:  
print("Tag was not found")  
else:  
if badContent == None:  
print ("Tag was not found")  
else:  
print(badContent)  
这种对每一个错误的检查和处理似乎是费力的，但它很容易就改写了这个代码，使它更容易写（but it’s easy to add a little reorganization to this code to make it less difficult to write ）（而且，更重要的是，更容易读）。这个代码，例如，是我们相同的scraper以一个稍微不同的方式写的：   
from urllib.request import urlopen  
from urllib.error import HTTPError  
from bs4 import BeautifulSoup  
def getTitle(url):  
try:  
html = urlopen(url)  
except HTTPError as e:  
return None  
try:  
bsObj = BeautifulSoup(html.read())  
title = bsObj.body.h1  
except AttributeError as e:  
return None  
return title  
title = getTitle("http://www.pythonscraping.com/pages/page1.html")  
if title == None:  
print("Title could not be found")  
else:  
print(title)  
在这个例子中，我们创建一个函数getTitle，这返回网页的标题，如果有一些信息检索问题，则返回一个空对象。在getTitl里，我们检查HTTPError，如前面的例子，并将BeautifulSoup的两行封装在一个try语句（and also encapsulate two of the BeautifulSoup lines inside one try statement. ）。一个AttributeError可能从这些行抛出（如果服务器不存在，HTML将会是空对象，和HTML.read()抛出出一个AttributeError）。事实上，我们可以，包含我们希望的尽可能多的行到一个try语句，或调用另一个函数，可以在任何时候抛出AttributeError。  
写scraper时，考虑你的代码的整体格局来处理异常并保证其可读性很重要。您还可能希望重重用代码。具有通用功能，如getsitehtml和getTitle （完全彻底的异常处理）便于快速可靠地scrape网络。

The BeautifulSoup library was named after a Lewis Carroll poem of the same name in Alice’s Adventures in Wonderland. In the story, this poem is sung by a character called the Mock Turtle (itself a pun on the popular Victorian dish Mock Turtle Soup made not of turtle but of cow).

Like its Wonderland namesake, BeautifulSoup tries to make sense of the nonsensical;it helps format and organize the messy web by fixing bad HTML and presenting us with easily-traversible Python objects representing XML structures.

BeautifulSoup库被命名为刘易斯卡罗尔诗（Lewis Carroll poem），与爱丽丝梦游仙境里一样的名字。在这个故事中，这首诗是由模拟海龟（Mock Turtle）唱的。（Mock Turtle这是一个很受欢迎的维多利亚菜的双关语，它不是乌龟，而是牛的汤）。

与仙境同名，beautifulsoup尝试使荒谬的变得有意义；BeautifulSoup通过修复坏的的HTML，并向我们呈现容易traversible 代表XML结构的Python对象，来格式化和组织混乱的网络 。
