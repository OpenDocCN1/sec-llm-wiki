# 前言

# Brute Ratel C4是类似于Cobalt Strike的商业红队框架，每年的License收费为$2500，首个版本Brute Ratel C4 v0.2 (Prometheus)于2021年2月9日发布，截至发稿最新发布版本v1.1(Stoffel's Escape)与2022年7月20日发布，相比与Cobalt Strike的知名度BRc4显然要低调的多，但是BRc4使用的技术和功能却丝毫不亚于CS，本次分析的样本使用的最终payload就是BRc4框架。

# 恶意代码分析

恶意样本是个iso文件，双击挂载iso，一共有5个文件，除了`Roshan-Bandara_CV_Dialog`这个快捷方式之外其他的文件都是隐藏文件（我开启了显示隐藏文件所以这里全部显示了）  
![](../Images/b1bdb16ad6fd8e565969cc09d0a8c5eb.png)  
我们查看Roshan-Bandara\_CV\_Dialog快捷方式指向的目标`%windir%/system32/cmd.exe /c start OneDriveUpdater.exe`，主要就是调用cmd命令执行了隐藏文件OneDriveUpdater.exe，`cmd.exe /c`命令指定执行完后会自动关闭控制台窗口  
![](../Images/a75a6010ca32370df6dc24257a799766.png)  
我们接着看这个快捷方式的图标文件，发现其图标文件指向`%ProgramFiles%\Microsoft Office\root\Office16\WINWORD.EXE`，由于本机没有装Office 2016所以此快捷方式的图标就无法显示，由此可见此次攻击样本十分有针对性  
![](../Images/3ba07f151bef5a107d14acf28fa89e29.png)  
其中的vresion.dll和OneDriveUpdater.exe为白文件都有Microsoft的有效数字签名  
![](../Images/0dfdd2fc5873875a8968ed8164e47c5c.png)  
其中的version.dll链接器版本14.29是使用1929 (Visual Studio 2019 Version 16.10 + 16.11)编译的64位DLL，可以看到编译时间戳为`2022-5-17 16:35:50`  
![](../Images/12e498534f4e4c92e53a2f363821a950.png)  
version.dll和vresion.dll的导出函数完全相同  
![](../Images/f948c85386d61e82d818e386f0f473d5.png)  
OneDrive.Update是一个被加密的二进制文件，猜测可能是shellcode或者pe文件  
![](../Images/8551db23139947415229c62b7fe177f0.png)  
使用ida64打开OneDriveUpdater.exe分析，我们可以看到OneDriveUpdater.exe一共调用了version.dll中的3个导出函数  
![](../Images/ea97c85d3c9dac20938d751d3d80163b.png)  
接下来我们使用ida64分析version.dll，查看version.dll的导出函数时发现并没有相关的实现，而是使用了导出函数转发技术将函数转发到白文件vresion.dll的实现  
![](../Images/796d0c859bde238c18e5e7a2e2545ea9.png)

## stage0：version.dll代码分析

接下来我们分析version.dll的DllMain函数，只调用了一个sub\_180002090函数  
![](../Images/967b5f6d375efed050b49d0cfd521aca.png)  
sub\_180002090函数使用了WTSEnumerateProcessesA函数枚举进程  
![](../Images/66d424f31ab82313165cf9a20fbaaffd.png)  
循环查找`RuntimeBroker.exe`进程  
![](../Images/4be3f3934ced34962041bd4f4bab7454.png)  
读取加密文件`OneDrive.Update`到内存  
![](../Images/671912a81adf98d55b335fa5872e15a3.png)  
控制台窗口打印字符串`"Please wait..."`  
![](../Images/573e5f4d6decd75099eeede47d1255e3.png)  
先调用了`NtDelayExecution`函数休眠了几秒，接着调用`NtOpenProcess`函数以`PROCESS_ALLACCESS`权限打开`RuntimeBroker.exe`进程  
![](../Images/70bfaec638cd51d1fd01c01c0b455bfc.png)  
此样本的NtOpenProcess函数实现，这些汇编代码特征让我想到了SysWhispers3项目  
![](../Images/fe45d62bae766247e8d35c4b4d5d4320.png)  
这是我使用SysWhispers3项目生成的NtOpenProcesss的syscall调用，发现除了SysWhispers3使用函数Hash方式之外汇编代码特征完全一致，可以判断此样本使用了SysWhispers3项目  
![](../Images/1f33079b0f254e378f2e10812a165895.png)  
接下来我们详细分析下首先`SW3_GetSyscallEGG_180001D20`函数参数为`ntop`  
![](../Images/001a3d7248a5daa15d7c06b653e0b528.png)  
主要逻辑是通过`gs:[60]`获取PEB，然后通过偏移找到`PEB->Ldr->InMemoryOrderModuleList`链表，并通过访问`LDR_DATA_TABLE_ENTRY->FullDllName`字段使用_stricmp函数判断找到ntdll.dll  
![](../Images/c9636c72f19f9fb6da25bc5aa59d8557.png)  
接下来通过解析ntdll.dll的PE结构获取导出函数  
![](../Images/95a8a803ad9a93e7cf8ebc3a143ebbe4.png)  
第一个导出函数名称  
![](../Images/e7ee699521b50d6a2d4bd60977cf96e6.png)  
memcmp函数对比直到找到导出函数NtOpenProcess  
![](../Images/371121a9f78789f8e84a9127d69d73a6.png)  
最终获取到导出函数地址  
![](../Images/dc8445099976c4551129edfe93f28ed4.png)  
接下来通过搜索函数NtOpenProcess的OPCODE特征找到syscall（0F05）的地址（EGG）  
![](../Images/4415c324268ccff0906ec4a618bc5cc4.png)  
接下来分析`SW3_GetSyscallNumber_180002000`函数，主要逻辑还是通过OPCODE特征搜索找到syscall id，关于syscall id对应的函数在不同windows版本下不同可以在j00ru的博客查询  
![](../Images/63e7a30f81369ccec1faf3062a9790c5.png)  
此时RAX为NtOpenProcess函数的syscall id：26，r15为syscall的地址  
![](../Images/1a54b75d4846e6786c20bc2a71516b90.png)  
通过syscall调用NtOpenProcess函数  
![](../Images/ce2829c9ca3af07f92250869605771a3.png)  
接下来使用硬编码的xor密钥`jikoewarfkmzsdlhfnuiwaejrpaw`解密`OneDrive.Update`，解密大小为0x493E0  
![](../Images/738c0153a1078708a7878f62a447e816.png)  
调用了`NtCreateSection`函数创建`0x493E0`大小的`PAGE_EXECUTE_READWRITE`内存权限，`SECTION_MAP_READ | SECTION_MAP_WRITE | SECTION_MAP_EXECUTE`访问属性的section  
![](../Images/8e0bad18be04709aaea603b9e6763d6a.png)  
接着调用`NtMapViewOfSection`函数将section映射到本进程虚拟内存  
![](../Images/742fff4db79886156995337695e81515.png)  
并调用`NtMapViewOfSection`函数将section映射到`RuntimeBroker.exe`进程虚拟内存  
![](../Images/4c1c14c1b173e04d4517d6035de6234b.png)  
使用memmove函数将解密后的shellcode复制到本进程section共享内存空间，此时section内存会同步映射到远程进程`RuntimeBroker.exe`进程虚拟内存  
![](../Images/e77494df8ca639e2e9b7a41a43faa104.png)  
然后调用NtCreateThreadEx函数在RuntimeBroker.exe进程中创建远程线程执行注入的shellcode  
![](../Images/8430a5f3f7738780bf24e5c1c47ef5e8.png)  
我们使用processhack工具查看`RuntimeBroker.exe`进程内存可以看到shellcode已经注入成功  
![](../Images/54181e9075083366334ea59df2373946.png)

## stage1：OneDrive.Update代码分析

为了方便调试我将stage0解密后的shellcode从内存中dump下来并使用自写的shellcode loader加载调试分析，shellcode开头有巨量的`mov`和`push`执行的组合，通过压入栈中的数据可以判断大致是在初始化数据和函数调用要用到的参数等等  
![](../Images/b7e753a4d356562d95435178fdc86cc3.png)在偏移0x43750处才开始主要逻辑  
![](../Images/4f9f0e1e470b8498695fa0dd59cfa5be.png)可以看到刚刚压入栈中的众多数据包含了一个PE文件并且此PE文件的Dos头的MZSignature（0x5A4D）被抹除防止EDR进行内存扫描查杀，通过访问0x3C位置AddressOfNewExeHeader开始解析此PE文件  
![](../Images/fbce3f2a4612b7d38abb792409dc9139.png)最终获取导出函数的RVA：0x92E0  
![](../Images/9a01203d5d88d9b844fc9b7d4f11ebf6.png)接下来的逻辑还是熟悉的通过`PEB-Ldr->InMemoryOrderModuleList`获取ntdll.dll的基址  
![](../Images/7c1a9c5ca40d9abcf3051df806afd1b4.png)然后调用FindHashFunAddress\_5137AE函数通过函数Hash获取对应函数的地址  
![](../Images/e8432f68f6ae7d27a12432295732a84d.png)通过解析ntdll.dll的PE结构获取导出函数名称表  
![](../Images/fb4643e56d27605f575855ae7a4ee921.png)并对导出函数名进行ror13 Hash然后对比目标函数Hash直到找到需要的函数  
![](../Images/9399891e6b2a6a7eb77710ca01aff1f3.png)  
获取到需要的导出函数地址后会调用CheckFuninlineHook\_51375B函数进行检查  
![](../Images/e01715ca53ca59254f5af8e379ee77eb.png)首先检查函数头是否被下了int3软件断点（0xCC），然后通过检测OPCODE编码E9（jmp）判断函数是否被EDR给inlineHook，如果函数正常则通过偏移获取函数的syscall id  
![](../Images/d1ae5101e70171097c2b1c88cc8f1fa7.png)接着将参数压栈，通过syscall调用`ZwAllocateVirtualMemory`申请`PAGE_READWRITE`权限的内存  
![](../Images/43b068d51bb3d5efdd7dbb05fdc68b15.png)接着又申请了一块内存`PAGE_READWRITE`权限的内存  
![](../Images/ed32c1429c1c17f1ed51010aaaf6b25e.png)申请完内存后调用了CopyPeToAllocAddress\_513815函数  
![](../Images/63ed661dedf68af0d6094c236b99a07b.png)此函数将栈中的PE文件（0x3240）大小的内容以每次QWORD大小复制到申请的虚拟内存中  
![](../Images/0fedd5c57972772b83e02b3c701c77c7.png)PE文件复制完成  
![](../Images/480eb08d5a77ea8cae4cfd7ec6c185b1.png)接着调用 MemSetPeMemoryFeatures\_513805函数将内存中PE文件Dos头除了AddressOfNewExeHeader字段以外的内存置0，防止EDR扫描内存查杀  
![](../Images/b2a5b1741fb611e48f67d5ba4ca7e363.png)又调用了MemSetPeMemoryFeatures\_513805函数将内存中PE文件DosStub部分的内存置0  
![](../Images/4b66fb2f2972700929c388c1daa21494.png)接着调用CopyBase64ToAllocAddress\_513820函数  
![](../Images/5cc3ad08784c7c6067141505d972fdb3.png)将0x148字节大小的Base64编码数据复制到申请的第二块虚拟内存中  
![](../Images/57f85580f95c76f77afa51cf6ef6484b.png)复制完内存后还是通过调用FindHashFunAddress\_5137AE函数通过函数Hash获取ZwProtectVirtualMemory函数地址  
![](../Images/2c0de301e8bdf21a31cc0474be9aa333.png)调用ZwProtectVirtualMemory将存放PE文件那块内存属性改为`PAGE_EXECUTE_READ`属性  
![](../Images/0bcd527de796b635df67712b24aa1c47.png)获取了ZwCreateThreadEx的syscall id  
![](../Images/d89ba7150d76bcaed76252f8341a2b9b.png)调用ZwCreateThreadEx执行的函数为函数开头获取的导出函数  
![](../Images/f161bbbbc9beb11ebefeb10f7c9b6bb0.png)调用ZwWaitForSingleObject函数等待线程执行完毕![](../Images/567533b6ed0e981014b33d820e699e4d.png)**文章来源于：https://www.freebuf.com/articles/system/341336.html**
