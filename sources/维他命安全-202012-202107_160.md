# Hello勒索软件分析

### **摘要**

今年1月，我们发现了一种使用.hello作为扩展名的新勒索软件，它可能是通过SharePoint服务器的漏洞进入系统的。

![](../Images/a1934670d23fe82c8e10c5ff18ae9d5d.png)

这似乎是一个新的勒索软件家族，被称为Hello勒索软件，又名WickrMe，这是以用于联系网络罪犯的聊天应用程序命名的。以前的变种被观察到使用.hemming和. strike扩展名，但不包括网络犯罪分子的WickrMe用户句柄，相比之下，带有.hello扩展名的较新版本的赎金票据现在带有WickrMe联系信息。  

![](../Images/0bda7fda63ce0c7359e0edebb275bad9.png)

图1.没有WickrMe详细信息且没有索要赎金的赎金票据  

 

![](../Images/96766834aace972f28495b1dae1d6977.png)

图2.带有WickrMe用户名和需求的赎金票据的更新版本

该勒索软件通过利用Microsoft SharePoint漏洞CVE-2019-0604进入目标系统。为了启动Payload，攻击者滥用Cobalt Strike beacon（信标）来启动勒索软件。

根据我们对这个变种的监测，自从它在三个月前出现后，我们还观察到China Chopper （中国菜刀）Web shell的更新，这可能是为了规避已知样本的检测。

 

  

### **CVE-2019-0604和China Chopper**

正如其他人所记录的那样，CVE-2019-0604被攻击者滥用于系统的初始访问。但是，我们的分析还显示，攻击者在利用该漏洞进行入侵后，部署了China Chopper Web Shell（趋势科技检测为Backdoor.ASP.WEBSHELL.SMYAAIAS）以执行PowerShell命令，该命令随后又下载了Cobalt Strike信标，这将导致目标系统感染勒索软件的Payload。

我们之前观察到CVE-2019-0604漏洞导致被安装China Chopper Web Shell的模式，而Hello勒索软件的攻击者似乎正在重新利用2019年的方法进行攻击。但是，我们发现这个变种使用web shell的任意代码执行来部署Cobalt Strike，最终导致感染勒索软件。

通过观察暗网，我们发现一个论坛免费提供了该漏洞的利用程序。考虑到它的可用性，我们没有发现强烈的迹象表明正在寻找它或将其用于勒索软件部署的人。

 

 

### **Hello勒索软****件的例程**

![](../Images/ae7f6eb8adf8c899097d0e2ade04fd3c.png)

图3\. Hello勒索软件的攻击链

 

当参数“{Malware file path}\\{Malware Name}.exe e{UUID} {BTC}”不满足某些条件时，该攻击将停止执行，其中：

*   e是硬编码的检查功能，它是第一个参数。
    
*   UUID应该是系统中存在的具有XML格式的RSA公钥文件。否则，它将不会继续其预期的加密例程。
    
*   BTC是要支付的金额，如赎金说明中所示。
    

 

![](../Images/80f70048c8814a4db155f718192d455c.png)

图4.检查当前用户是否具有管理员权限，如果不是，例程将自行终止。

 

![](../Images/7614d3d524e5cb14a581fe878813037b.png)

图5.在系统中查找格式化的RSA公钥

 

管理员权利升级的过程中受到Enigma 3.90的保护，Enigma 3.90是一个合法的软件，主要用于保护可执行文件。值得注意的是，这个例程所使用的版本已经过期近10年了，但日期表明似乎不是这样。虽然我们不知道网络犯罪分子使用的是合法版本还是破解版，但我们发现该软件可以保护程序不受分析和逆向工程的影响。

![](../Images/0d634c121fb93765a60da7bb6dd4d001.png)

图6.使用合法软件的旧版本来保护管理员权限升级的过程  

 

经过检查，当例程发现当前用户有管理权限时，它就会搜索具有特定扩展名的文件和文件夹，以收集它将要加密的文件。它还会搜索allowlisted目录，以避免对它们进行加密。

![](../Images/395c499bd3e0ccc76629bd7cc25988e8.png)

图10. AES初始化功能

 

我们注意到，该恶意软件避免对以下文件夹加密文件，以免影响系统和恶意软件的执行：

%Windows%\\

%All Users Profile%\\

%System Root%\\$recycle bin\\

%System Root%\\Common Files\\

%System Root%\\windowspowershell\\

 

它将扩展名.hello附加到被加密的文件中，并投放以下赎金说明：

%public%\\Desktop\\Readme!!!.txt

%Desktop%\\Readme!!!.txt

 

![](../Images/9eea3fee3dd690eb1dbedbd7864df884.png)

图11.将扩展名附加到加密文件

 

![](../Images/987997b6540e96f059d0f6c9c2252735.png)

这个恶意软件背后的网络犯罪分子确保通过删除备份驱动器和卷影副本来禁止恢复文件。我们发现，该例程包括执行以下命令：

"%System%\\vssadmin.exe"delete shadows /all – Deletes shadow copy

"powershell.exe"Dismount-DiskImage "{Found filepath.vhd}" – Dismounts virtual drives

 

![](../Images/772f143302fe890d7c4800936e656357.png)

图13.删除卷影副本并卸载虚拟驱动器

 

它还会删除文件名中带有\*backup\*字符串的文件，包括文件名后缀为\*.bak、\*.bk、\*.vbk、\*.vbm和\*.vhd等虚拟驱动器中的备份文件。

![](../Images/3d3515ac5682540c1b983ee904cbe6ac.png)

图14. 删除备份文件  

 

此外，如果恶意软件发现特定的备份和数据库进程，则勒索软件例程会在搜索过程中终止服务，以确保也对它们进行加密。如果数据库应用程序仍在运行，那这些数据库文件将处于“in use”状态，无法进行加密访问：

mssql

sql

postgresql

oracle

mysql

veeam

backup

 

![](../Images/6318fc1ef6afc7e46f4921e9f70aec05.png)

图15.终止服务  

 

我们还注意到，即使系统中存在勒索信息，勒索软件例程也不会继续执行其加密例程。这可能是执行不当或缺少某些组件造成的。

 

 

### **China Chopper Web Shell更新**

此外，我们注意到，之前观察到的China Chopper Web Shell样本与网络犯罪分子在这次攻击中使用的样本之间存在细微差别。

![](../Images/b0de22fa6686db26493b5b3db12af02e.png)

  

图16. 以前的攻击（顶部）和最近感染的更新版本（底部）中的China ChopperWeb Shell脚本版本的比较

 

我们认为，这个修改后的版本可能是为了规避目前对China Chopper Web Shell样本的检测。虽然脚本格式改变了，但其用途仍然相同，以便攻击者能够在受影响的系统上执行任意shell命令。

 

 

### **结论**

微软在2019年发布了CVE-2019-0604的咨询，并修复了这个漏洞。自2020年首次被用于攻击之后，该漏洞不断被攻击者滥用。已经观察到将漏洞利用程序和ChinaChopper Web Shell一起使用的攻击模式，这引发了以下问题：这两种工具的组合是否表明使用它们的网络犯罪分子有一定的访问权限，或是否有更多的人参与并能够从几个人手中购买访问权限。还值得注意的是，两年后，该漏洞的持续滥用暗示大量的公司仍未修补这个漏洞。

此外，在线扫描后，发现更多受害者的相同赎金票据样本，尤其是是内容相同但电子邮件地址不同的样本。随着原始感染开始到受害者向网络罪犯发送电子邮件的时间越长，赎金的要求也会增加。根据我们的监测，虽然发送了电子邮件，但我们并未观察到网络犯罪分子的回应。

勒索软件感染仍然是对用户和企业运营的严重威胁。以下是减轻这种威胁的一些最佳做法：

*   避免打开未验证的电子邮件或单击其嵌入式链接，因为它们会启动勒索软件的安装过程。
    
*   使用3-2-1规则备份重要文件：以两种不同的文件格式创建三个备份副本，其中一个备份位于单独的位置。
    
*   定期更新软件、程序和应用程序，以确保应用程序是最新的，以保护系统免受漏洞利用。
    
*   使用跨层威胁检测和响应系统，该系统能够监视已知、未知和隐藏的威胁和攻击。无论环境如何，都可以保护新的和现有的工作负载，以确保数据安全，同时又不影响操作和性能。
