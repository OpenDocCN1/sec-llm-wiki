UNC2891攻击活动的分析

Mandiant 分析了UNC2891 和UNC1945使用的技术、恶意软件和应用，发现它们之间存在很多重叠，但 Mandiant 尚未确定它们是同一团伙。

  • UNC2891 的攻击活动似乎是出于经济动机，可能跨越数年，在此期间该团伙基本上未被发现。

  • UNC2891 擅长于 Unix 和 Linux 环境，主要使用TINYSHELL 和 SLAPSTICK 后门针对基于 Oracle Solaris 的系统。

  • Mandiant 观察到 UNC2891 使用 OPSEC 运行，并利用公开和私人恶意软件、实用程序和脚本来删除痕迹并阻碍响应工作。

  • Mandiant 发现了一个新的用于 Oracle Solaris 系统的 rootkit，UNC2891 利用其藏身于目标网络中，命名为 CAKETAP。

  • CAKETAP 的一种变体可控制通过目标自动柜员机 (ATM) 网络的消息。据悉，这是一场规模更大的行动的一部分，该行动利用这些信息在多家银行进行未经授权的现金提取。

SLAPSTICK 和 TINYSHELL 后门

与过去的 UNC1945 的攻击一样， UNC2891 使用基于可插拔身份验证模块 (PAM) 的后门，追踪为 SLAPSTICK，以窃取凭据，并提供对目标网络的后门访问。SLAPSTICK 通过硬编码的magical password提供对目标系统的持久后门访问，它还将身份验证尝试和相应的密码记录在加密的日志文件中。虽然这极大地帮助 UNC2891 进行凭证收集和横向移动，但也为 Mandiant 事件响应提供了有价值的信息。尽管 SLAPSTICK 日志文件经常打上时间戳，但 Mandiant 能够通过使用后门提供的magical password对其进行解码并追踪一些横向移动活动。

图 1：样本SLAPSTICK 解码日志

除了 SLAPSTICK，UNC2891 还经常使用公开的TINYSHELL 后门的自定义变体。UNC2891的TINYSHELL 后门利用了一个外部加密的配置文件和一些具有额外功能的变种，例如通过具有基本身份验证的 HTTP 代理进行通信的功能。根据该团伙对基于 Unix 和 Linux 的系统的熟悉程度，UNC2891 经常使用伪装成合法服务的值命名和配置他们的 TINYSHELL 后门，例如 systemd (SYSTEMD)、名称服务缓存守护进程 (NCSD)、和 Linux at daemon (ATD)。

根据配置分析，UNC2891 在一个多跳结构中配置了 TINYSHELL 后门，该结构利用多个被感染的内部服务器进行命令和控制。在一个案例中，Mandiant 发现攻击者将不同的 TINYSHELL 变体链接在一起，以获得对具有网络限制的网段内的服务器的远程访问。

为了隐藏他们的 TINYSHELL 连接网络，UNC2891 安装并配置了一个 rootkit，以从网络连接相关的 API 中过滤掉这些连接。UNC2891 配置了带有 TINYSHELL 后门的远程访问系统，这些后门使用动态 DNS 域作为其外部C2通道。这些域是为单个主机创建的，并且不会被多次使用，子域有时与被感染设备的主机名相似。Mandiant无法收集这些动态DNS域的被动DNS数据，这表明当需要访问网络时，UNC2891可能在短时间内启用了IP解析。在一个被攻击目标中，这些TINYSHELL后门被配置为在端口53和443上使用TCP执行通信，这可能是一种绕过出站网络保护、混入现有流量并逃避检测的机制。

STEELHOUND、STEELCORGI 和环境变量

UNC2891 经常使用STEELCORGI 内存中的 dropper，它通过从运行时获得的环境变量的值中派生 ChaCha20 密钥来解密其嵌入的payload。在许多情况下，Mandiant 无法恢复所需的环境变量来解密嵌入式payload。然而，在能够解密的样本中，UNC2891 部署了一个常用的工具包的不同版本，该工具包似乎是以 SUN4ME 的名义开发的。SUN4ME 包含用于网络侦察、主机枚举、利用已知漏洞、日志清楚、文件操作的工具以及常用shell 实用程序。

Mandiant 发现此次UNC2891 利用了一个类似的内存dropper，它也使用环境变量来解密其嵌入的payload，但依赖于 RC4 加密，研究人员将其命名为 STEELHOUND。除了充当嵌入式payload的dropper之外，STEELHOUND 还能够通过加密目标二进制文件来加密新的payload，并将其连同自身副本和文件结尾配置一起写入磁盘。


WINGHOOK 和 WINGCRACK

在这些调查过程中，Mandiant 还发现了一系列键盘记录恶意软件，并将其命名为 WINGHOOK 和 WINGCRACK。

  • WINGHOOK 是基于 Linux 和 Unix 的操作系统的键盘记录程序。它被打包为一个共享库（SO 文件），并hook了两个常用函数read和fgets用于处理用户输入。捕获的数据以编码格式存储在目录/var/tmp/中，文件名以.zmanDw 开头。

  • WINGCRACK 是一个实用程序，可以解码和显示包含来自 WINGHOOK 的编码键盘记录数据的文件内容。恶意软件开发者将这些编码文件称为“schwing”文件。


检测到的其它程序

Mandiant 之前检测到 UNC1945 在入侵过程中使用了大量的公开和私有工具，UNC2891 也是如此。Mandiant 发现了 UNC2891 所利用的其它程序：

  • BINBASH 是一个简单的 ELF 实用程序，它将组 ID 和用户ID 设置为“root”或指定值后执行 shell。BINBASH 似乎是源代码的编译。

  • WIPERIGHT 是一个 ELF 实用程序，可清除基于 Linux 和 Unix 的系统上的特定日志条目。它可以删除 lastlog、utmp/utmpx、wtmp/wtmpx 和 pacct 日志中与给定用户关联的条目。它似乎起源于可用的源代码。

  • MIGLOGCLEANER 是另一个 ELF 实用程序，可在基于 Linux 和 Unix 的系统上清楚日志或从日志中删除某些字符串。它在 GitHub 上公开可用。

UNC2891 经常使用uuencoding 方案来编码和解码文件，例如恶意软件二进制文件或包含大量主机枚举脚本输出的文件，这在攻击者中不常见。攻击者通常利用简单的 Perl 打包脚本来执行 uuencoding 和 uudecoding 功能。


CAKETAP

CAKETAP 是一个内核模块 rootkit，UNC2891 将其部署在运行 Oracle Solaris 的服务器上。CAKETAP 可以隐藏网络连接、进程和文件。在初始化期间，它会从加载的模块列表中删除自己，并使用先前加载的模块更新last_module_id以隐藏其存在。

函数ipcl_get_next_conn中安装了一个hook，以及ip模块中的几个函数。这使 CAKETAP 能够过滤掉与攻击者配置的 IP 地址或端口（本地或远程）匹配的所有连接。

识别在 Solaris 系统上运行的 CAKETAP 的一种方法是检查是否存在该hook。下面显示了一个示例命令，可识别hook的ipcl_get_next_conn函数（注意：mdb命令可能需要系统上的特殊权限）：

root@solaris:~# echo'ipcl_get_next_conn::dis -n 0 ; ::quit' | mdb -k

在一个安全的SPARC Solaris系统中，输出如下所示:

ipcl_get_next_conn:save %sp, -0xb0, %sp

hook函数将以sethi指令开始，如下所示（常量0x11971c00将根据 CAKETAP 的加载位置而变化）：

ipcl_get_next_conn:sethi %hi(0x11971c00), %g1

额外的hook被安装到mkdirat（makedirectory at）和getdents64（getdirectory entries）系统调用中。CAKETAP 使用mkdirat hook从包含signal字符串的路径接收命令。命令包括配置网络过滤器、显示或更新其配置以及取消隐藏。getdents64 hook使CAKETAP隐藏文件系统上包含秘密signal字符串的文件或目录。表 4 包含 CAKETAP  hook的signal字符串。

CAKETAP 未经授权的交易

来自一个被攻击的 ATM 交换机服务器的内存取证显示，CAKETAP 的一种变体具有额外的网络hook功能，可以拦截与卡和密码验证相关的消息。有证据表明，这种 CAKETAP 变体被用于使用虚假银行执行未经授权交易。

此 CAKETAP 变体针对发往支付硬件安全模块 (HSM) 的消息。这个额外的网络hook执行了几个功能：

1、处理银行卡验证消息：

CAKETAP 更改了某些传出消息的模式，以禁用银行卡验证。这导致 HSM 未执行正确的银行卡验证，而是生成了有效的响应。虚假的银行卡使用自定义算法生成验证消息，该算法使用主帐号 (PAN) 和其它参数作为 CAKETAP 的“marker”。CAKETAP 会检查传出的消息，如果它与算法匹配，CAKETAP 就会识别出这张银行卡是虚假的，并将PAN存储在内存中，以便在接下来的步骤中使用。

2、 重放 PIN 验证消息：

CAKETAP 会检查符合特定条件的传出 PIN 验证消息，并识别出带有反映虚假银行卡的主帐号 (PAN) 的消息。如果消息不是针对虚假银行卡的，它会在内部保存消息并不加修改地发送，以免中断合法的 ATM PIN 验证。但是，如果是针对虚假银行卡的，CAKETAP 会用以前保存的消息中的数据替换消息内容。这实际上是一种重放攻击，导致虚假银行卡绕过 PIN 验证。

根据 Mandiant 的调查结果，CAKETAP 是 UNC2891 更大行动的一部分，已成功地使用虚假的性银行卡从多家银行的 ATM 进行未经授权的现金提取。


结论

UNC2891 保持高水平的 OPSEC， 并采用多种技术来绕过检测。攻击者利用他们的技术和经验来充分利用 Unix和 Linux 环境中经常出现的可问题。Mandiant 预计 UNC2891 将继续利用这一点，并针对运行这些操作系统的重要任务系统执行类似的攻击以谋取利益。

虽然在UNC2891和UNC1945之间存在部分重叠，但将这些攻击归结为一个团伙还不够确凿。例如，UNC2891和UNC1945活动的重要部分可能是由一个团伙执行，该团伙是多个攻击团伙的公共资源，这可以解释入侵目标的差异——例如，一个常见的恶意软件开发者或一个攻击合作伙伴。无论如何，Mandiant公布这些这些信息是为了提高对诈骗活动的认识，并帮助维护者揭露更多的UNC2891活动。
