      Daxin 以 Windows 内核驱动程序的形式出现。这篇博客详细地介绍了驱动程序初始化、网络、密钥交换和后门功能，此系列的第二部分将分析恶意软件的通信和网络功能。

此分析基于 Backdoor.Daxin 样本（SHA256：ea3d773438c04274545d26cc19a33f9f1dbbff2a518e4302addc1279f9950cef）。根据收集到的信息表明，该样本已于 2021 年 11 月攻击了两个组织。


初始化程序

研究人员分析的 Daxin 样本似乎是用标准的 VMProtect packer封装的。许多早期的样本在 VMProtect 之上添加了一个额外的外部包装层。该外部打包程序是为驱动程序定制的，甚至在最终 payload 中也使用了相同的加密算法。研究人员认为，攻击者之所以决定删除自定义打包程序，是因为与最新的Windows版本存在兼容问题。

每当驱动程序启动时，打包程序添加的代码会解密并解压最终的payload，然后将控制权传递给解压 payload 的入口。此时，恶意代码在内核内存中可见，尽管有一些混淆。

大部分 payload 初始化代码都与 Windows 内核的网络堆栈有关。这包括识别一些未导出的结构和连接WindowsTCP/IP 堆栈。

Daxin通过修改TCP/IP 协议的每个预先存在的NDIS_OPEN_BLOCK来hook网络驱动程序接口规范 (NDIS) 层，其中ReceiveNetBufferLists和ProtSendNetBufferListsComplete处理程序被替换为自己的处理程序。对于每一个NDIS_OPEN_BLOCKs，相关的NDIS_M_DRIVER_BLOCK也可以通过替换现有的SendNetBufferListsHandler来修改。当SendNetBufferListsHandler不存在时，通过替换NextSendNetBufferListsHandler来修改相应的NDIS_MINIPORT_BLOCK。

为了识别 TCP/IP 协议的所有NDIS_OPEN_BLOCK，驱动程序依赖于调用NdisRegisterProtocol()来创建并返回未导出的ndisProtocolList的新的头部。然后它遍历每个NDIS_PROTOCOL_BLOCK 的ndisProtocolList ，将每个访问的NDIS_PROTOCOL_BLOCK结构的 Name 属性与字符串“TCPIP”进行比较。匹配结构的OpenQueue字段指向要 hook 的NDIS_OPEN_BLOCK列表。这种技术是已知的，但是 Daxin hook 的处理程序略有不同。这些调整并非Daxin独有，而是由 Windows 网络架构的架构变化导致的。

为了识别相关的NDIS_M_DRIVER_BLOCKs和NDIS_MINIPORT_BLOCKs，驱动程序分析“ndis.sys”机器代码来定位未导出的ndisFindMiniportOnGlobalList()和ndisMiniDriverList。然后从先前标识的NDIS_OPEN_BLOCKs开始获得相关的NDIS_MINIPORT_BLOCKs，其中每个样本的RootDeviceName作为参数传递给ndisFindMiniportOnGlobalList()调用，该调用返回要hook的结构。最后，为了定位相关的NDIS_M_DRIVER_BLOCKs，驱动程序遍历 ndisMiniDriverList检查MiniportQueue已识别NDIS_MINIPORT_BLOCKs的每个项目的列表。

注册伪造协议时，Daxin 调用 NdisRegisterProtocol() API 传递带有硬编码名称属性“NDISXRPT”的ProtocolCharacteristics参数。

由于NDIS_OPEN_BLOCK结构的布局在不同的 Windows 版本之间会发生变化，因此Daxin需要确定要使用的正确偏移量。首先，它根据一组明确给出NDIS_OPEN_BLOCK偏移量的硬编码值检查NtBuildNumber（如图 2）。

图 2：Daxin 对照一组硬编码值检查NtBuildNumber

Daxin代码库中硬编码的最新 Windows 内部版本号是 17763。它对应于 Windows Server 2019 和 Windows 10 版本 1809 (Redstone 5)。当 Windows 版本无法识别时，Daxin会尝试使用另一种方法来确定 NDIS_OPEN_BLOCK 偏移量。

然后 Daxin收集所有 NDIS 结构的详细信息进行hook，以及相关网络接口的信息。最后，对于每个网络接口，它都会用自己的处理程序替换原始处理程序。

网络

ReceiveNetBufferListshook和SendNetBufferListsHandler（或NextSendNetBufferListsHandler ）hook都实现了检查网络数据包的逻辑，然后在将剩余的数据包传递给原始处理程序之前劫持一些数据包。ProtSendNetBufferListsComplete hook 完成 Daxin发起的所有发送操作，例如NET_BUFFER_LIST 结构在调用原始处理程序之前被删除和释放。

 在详细描述 hooks 的实现之前，首先分析在Daxin中观察到的几个样本。

在第一个场景中，ReceiveNetBufferLists hook 检查某些 TCP 数据包的数据部分是否有预定义的模式。然后在调用原始ReceiveNetBufferLists处理程序之前从NetBufferLists中删除任何匹配的 TCP 数据包。同时，对于每个被删除的 TCP 数据包，恶意驱动程序都会发送两个新数据包。第一个数据包是发送到原始目的地的欺骗性 RST TCP 数据包，因此其接收者将 TCP 连接标记为关闭。第二个数据包是发送到原始源的 ACK TCP 数据包。从那时起，恶意驱动程序依靠ReceiveNetBufferListshook来维护与原始源的TCP连接，从而劫持相关的网络数据包，如图 4 所示。

图 4. ReceiveNetBufferLists  hook检查 TCP 数据包是否存在预定义模式

在生成网络流量时， Daxin使用自己的代码伪造网络数据包，绕过合法的 Windows TCP/IP 堆栈。为了说明这一点，研究人员重新配置了 WindowsTCP/IP 堆栈以使用非标准生存时间 (TTL)。由于Daxin不重视更新后的参数，因此其流量在图 4 所示的 Wireshark 捕获中显示出来。

Wireshark 捕获到的 TCP 重传是由于内核调试器的脚本减慢了驱动程序的响应。否则不会预期重传。研究人员决定激活这些脚本来分析驱动程序的内部工作，可以从捕获的Wireshark中识别各个数据包，如图 5 所示。

图 5. 通过捕获单个数据包分析 Daxin的内部工作原理

在另一种情景下， Daxin发起一个新的 TCP 连接，并在 TCP 会话的整个生命周期内维护它。该恶意软件依赖ReceiveNetBufferLists hook来劫持与此连接相关的所有网络数据包。被劫持的数据包不会到达合法的 Windows TCP/IP 驱动程序。

在最后一个场景中， Daxin使用 UDP 协议发送 DNS 请求。响应UDP 数据包被ReceiveNetBufferLists hook劫持，DNS 响应被恶意驱动程序解析。研究人员在分析与C2连接相关的配置选项时使用了此功能。

所描述的场景表明 Daxin 实现了自己的 TCP/IP 堆栈。这一点在进一步对驱动程序的逆向工程中得到了证实，其中确定了实现IPv4、TCP和UDP的数据结构和子例程。

 Daxin安装的NDIS hook的主要目的是允许其恶意 TCP/IP 堆栈与同一台设备上的合法 Windows TCP/IP 堆栈共存。当满足某些条件时，hook还允许它劫持预先存在的 TCP 连接。

ReceiveNetBufferListshook 检查NDIS_NBL_FLAGS_IS_LOOPBACK_PACKET标志的NetBufferLists参数头部的NET_BUFFER_LIST结构的NblFlags成员。只要设置了该标志，hook就会将网络数据传递给原始的ReceiveNetBufferLists处理程序，而不进行其他处理。否则，它调用一个辅助子例程，传递NET_BUFFER_LISTs的NetBufferLists链表。helper 子例程将原始的 net_buffer_list 链表划分为两条链：一条是允许数据包被合法堆栈进一步处理的链，另一条是要丢弃劫持到的数据包的链。然后 hook 将允许的数据包链传递给原始的ReceiveNetBufferLists处理程序。接下来，如果NDIS_RECEIVE_FLAGS_RESOURCES标志未在其ReceiveFlags参数中设置，则 hook 使用NdisReturnNetBufferLists()释放被劫持数据包链的所有权。

SendNetBufferListsHandlerhook 检查 NET_BUFFER_LIST 结构的NdisPoolHandle成员（作为其NetBufferList参数传递）是否对应于 Daxin自己创建的用于发送恶意流量的池。如果是，hook 只是将网络数据传递给原始的SendNetBufferListsHandler而不进行其他处理。否则，它调用ReceiveNetBufferListshook 使用的相同 helper 程序子例程，以将其NetBufferList参数分成两个链。然后它将允许的数据包链传递给原始的SendNetBufferListsHandler。最后，被劫持的数据包链使用NdisMSendNetBufferListsComplete()或ProtSendNetBufferListsComplete处理程序。

两个 hook 使用的辅助子例程遍历NET_BUFFER_LIST的原始链表，从每个访问的 NET_BUFFER_LIST 结构中提取网络数据包，并为每个提取的数据包调用恶意数据包过滤器。数据包过滤器对访问的NET_BUFFER_LIST结构中的第一个数据包返回的判断确定该结构是否应允许合法堆栈进一步处理或被丢弃。

数据包过滤器是Daxin网络功能的核心，因为它控制将提取的数据包分派到Daxin的各个子模块，每个子模块实现不同的功能。过滤器返回“ accept ”或“drop“，以指示相关数据包是否应该到达合法的 TCP/IP 堆栈。它的运作方式如下：

1、检查数据包是否与来自恶意隧道的数据流相关。如果有，它会捕获数据包并通过加密通道转发给攻击者，然后返回“drop”。
2、检查以太网源 MAC 地址和目标 MAC 地址是否相等。如果是，它会返回“accept”。
3、从ReceiveNetBufferLists hook 调用它的情况下，会检查以太网源MAC 地址是否对应于本地机器的任何网络接口。如果是这样，它会返回“accept”。
4、对于 TCP over IPv4 数据包，它会跟踪活跃 TCP 连接的某些参数，以供将来 TCP 劫持逻辑使用（如果需要）。
5、对于非 IPv4 数据包或从ReceiveNetBufferLists hook 调用时，它会调用Daxin数据包处理程序列表中的每个处理程序，并在第一个声明数据包所有权的处理程序上停止。每当Daxin的处理程序声明对 IPv4 数据包的所有权时，过滤器都会返回“drop”。
这些Daxin数据包处理程序由恶意 TCP/IP 堆栈根据需要动态注册和注销，从而最大限度地减少开销。此外，对于 TCP，处理程序列表由服务器端口（支持 TCP 服务器侦听新连接）或客户端和服务器端口的组合（支持 TCP 会话）存储。在调用处理程序之前解析数据包，解析器逻辑将支持的协议组合为 ARP、IPv4 上的 UDP 和 IPv4 上的 TCP。
6、如果从ReceiveNetBufferLists hook 调用 TCP over IPv4 数据包，它会检查数据包中的 TCP 数据：

  以字符串“POST”开头并包含字符串“756981520337”，中间没有任何换行符“\r\n”

  以字节序列 0x10 0x99 0x10 开始，并且至少有 8 个字节长

  以字节序列 0x10 0x99 0x11 开始，至少有 8 个字节长

当找到匹配项时，它会触发劫持相关TCP连接并返回“drop”。需要注意的是，这些检查并不局限于 TCP 会话的开始，因此有可能在交换任意数量的数据后触发劫持。这可以用来在与托管在目标上的服务器的对话结束时，开始与恶意驱动程序通信。

最后，ProtSendNetBufferListsCompletehook 遍历作为其第二个参数传递的NET_BUFFER_LIST结构的列表，检查访问的NET_BUFFER_LIST结构的NdisPoolHandle成员是否与恶意驱动自己创建的用于发送恶意流量的池相对应。然后在列表中删除匹配的结构，并在验证Flags成员后重新分配。Hook 将修改后的列表传递给原始的ProtSendNetBufferListsComplete处理程序。


密钥交换

每当 Daxin劫持TCP 连接时，它都会检查接收到的数据中是否有特定消息。预期的消息启动自定义密钥交换，其中双方遵循互补步骤。在讨论这个密钥交换协议时，研究人员将使用术语“initiator”来指代发送初始消息的一方。另一个将被称为“target”。

首先， Daxin为每个被劫持的 TCP 连接启动目标端协议。此外，它可以配置为连接到远程 TCP 服务器，在该服务器上进行特定的握手，然后启动目标端协议。最后，可以指示 Daxin连接到远程 TCP 服务器，在该服务器上启动发起端协议。

后门功能

成功的密钥交换会建立一个加密通信通道， Daxin使用这个通道来交换各种信息。一些消息指示恶意软件执行各种操作，例如在目标上启动任意进程。其它的则传输这些操作的结果，例如由启动的进程生成的输出。Daxin识别的操作集比较紧凑，最基本的操作是读写任意文件。

Daxin还可以执行任意的EXE和DLL二进制文件。对于 EXE 文件， Daxin启动一个新的用户模式进程。启动进程的标准输入和输出被重定向，使得远程攻击者可以交互地发送输入和接收输出。当命令执行一个 DLL 文件时，Daxin将注入到一个预先存在的“svchost.exe”进程中。

 Daxin为攻击者在目标中安装的所有附加组件提供了专用的通信机制。所有兼容的组件都可以打开一个由 Daxin创建的“\\.\Tcp4”设备来注册自己进行通信，它可以选择分配一个 32 位的服务标识符，以将自己与同一台计算机上可能处于活动状态的其它服务区分开来。然后Daxin转发远程攻击者和注册服务之间的任何匹配通信。

接下来，远程攻击者可以检查和更新后门配置。配置实现为键值结构，以加密形式存储在 Windows 注册表中以保持持久性。

还有一些专用消息封装了要通过本地网络适配器传输的原始网络数据包。然后恶意驱动程序捕获所有响应数据包并将其转发给远程攻击者。远程攻击者可以与目标网络上的所有服务器建立通信，从而为远程攻击者创建一个隧道与感兴趣的服务器进行交互。

最后，可以使用一条特殊消息在多个恶意节点之间建立新的连接，其中节点列表包含在单个命令中。对于每个节点，该消息提供建立通信所需的详细信息，特别是节点 IP 地址、其 TCP 端口号以及在自定义密钥交换期间使用的凭据。Daxin收到此消息后，会从列表中选择下一个节点。然后它使用其恶意 TCP/IP 堆栈连接到所选条目中列出的 TCP 服务器。建立连接后， Daxin启动发起端协议。在另一端计算机上，如果感染了 Daxin，initiator流量会导致 TCP 连接被劫持，如前所述。随后是自定义密钥交换以建立新的加密通信通道。之后，连接驱动程序通过这个新通道发送原始消息的更新副本，其中要使用的下一个节点的位置将递增。然后对列表中的剩余节点重复该过程。

在上述过程中创建的TCP连接，以及接收到原始连接设置指令的连接，随后将用于后续通信。当中间节点接收到消息时，它可以执行所请求的操作，或者沿着连接路径转发消息。对于某些操作，执行操作的节点由路径上的位置决定。在其它情况下，操作指令总是转发到最后一个节点。最后，某些操作总是只由第一个节点执行。

这种创建多跳连接的方法值得注意。攻击者在目标网络中通过多个跃点来绕过防火墙或更好地融入正常的网络流量，这种情况并不少见。当使用其它恶意软件时，这常涉及多个步骤，其中每次跳转都需要一个单独的操作。然而，在分析的样本中，攻击者将这些操作合并到一个操作中。这可能表明， Daxin针对受到良好保护的网络以及攻击者需要定期重新连接到目标网络的情况进行了优化

使用劫持的 TCP 连接进行后门通信的功能也很重要。当利用严格控制的网络、严格的防火墙规则或防御者监控网络异常时，可能需要这种功能。在被攻击的设备上，所有恶意网络连接都会绕过 Windows TCP/IP 堆栈，这可以提供某种程度的隐蔽性。攻击者投入大量精力使用支持 TCP 连接劫持的恶意 TCP/IP 堆栈来实现这些功能。

网络隧道的实现（恶意驱动程序在远程攻击者和目标网络之间直接传递数据包）展示了攻击者如何在不牺牲性能的情况下尝试最小化其足迹。


后门演示

为了演示 Daxin的后门功能，研究人员准备了一个实验来说明上一节中描述的内容。实验使用四个独立的网络和五台计算机。有些机器有两个网络接口来与不同的网络通信，但是所有的数据包转发功能都被禁用了。每台机器运行的各种网络服务只能从它的邻域到达。

图 6. 说明Daxin后门功能的测试设置

在设置中，攻击者可以与“Alice-PC”通信，而攻击者无法直接访问所有其它计算机。这模拟了一个假想的目标的网络，其中担任不同角色的计算机具有非常有限的连接。“Alice-PC”可以表示可以从 Internet 访问的 DMZ 服务，但其它计算机都是隔离的。

用Daxin感染了所有配置的机器，只有网络深处的一台没被感染。接下来，基于对恶意驱动逆向工程中获得的恶意通信协议的理解，研究人员实现了一个粗略的客户端，用来与运行在“Alice-PC”上的Daxin后门进行交互。使用此客户端指示“Alice-PC”上的后门通过两个中间节点“Bob-PC”和“Charlie-PC”创建与“Dave-PC”的通信通道。连接已成功建立，研究人员能够与所有被感染的计算机进行交互。最后，可以通过“Dave-PC”使用这个恶意网络隧道与“Clean-PC”上的合法服务进行通信。
