# 对公有云中数百个公开服务的攻击分析

### **执行摘要**

云环境中因为错误配置导致的最常见的安全问题是将服务以不安全的状态暴露在互联网上。这些服务在互联网上可以被发现，并可能对同一基础架构中的云工作负载构成重大风险。众所周知，REvil和Mespinoza等臭名昭著的勒索团伙利用暴露的服务来获得对受害者环境的初始访问。因此，Unit 42 研究人员通过利用部署在全球的320个节点的蜜罐基础设施进行观察，以更好地了解针对公共云中的服务的攻击。

![](../Images/2bdfc3c14d7ba7ae4e69b5f7dbe824d3.png)

我们在这 320 个蜜罐基础设施上部署了远程桌面协议（RDP）、安全shell协议（SSH）、服务器信息块（SMB）和Postgres数据库的多个实例，其中80%的蜜罐在24小时内被攻破，所有的蜜罐在一周内被入侵。一些引人注目的发现是：  

*   SSH是受攻击最多的应用程序。攻击者和入侵事件的数量远远高于其他三种应用。
    
*   受攻击最多的SSH蜜罐在一天内被攻击了169次。
    
*   平均而言，每个SSH蜜罐每天被攻击26次。
    
*   一个威胁者在30秒内破坏了我们全球80个Postgres蜜罐中的96%。
    
*   85%的攻击者IP只在一天内被观察到。这个数字表明，基于三层IP的防火墙是无效的，因为攻击者很少重复使用相同的IP来发动攻击。今天创建的恶意IP列表很可能明天就会过时。
    

漏洞管理的速度通常以天或月为单位。攻击者可以在几分钟内找到并破坏我们的蜜罐，这一事实令人震惊。这项研究证明了在不安全状态下公开服务的风险。结果重申了迅速缓解和修复安全问题的重要性。当配置错误或易受攻击的服务暴露于Internet时，攻击者只需几分钟即可发现并破坏该服务，因此安全修复的时间非常有限，这个时机不容错过。

Prisma Cloud可以在整个应用生命周期中识别和防止漏洞和错误配置，同时优先考虑云原生环境的风险。VM系列防火墙可以帮助检测和抵御虚拟化环境中的恶意活动。

 

 

### **方法**

2021年7月至8月，Unit 42研究人员在北美（NA）、亚太地区（APAC）和欧洲（EU）部署了320个蜜罐。本研究分析了在这些蜜罐基础设施中观察到的攻击的日期、频率和来源。

四种类型的应用程序，SSH、Samba、Postgres和RDP，被均匀地部署在整个蜜罐基础设施中。我们故意配置了一些使用弱凭据的帐户，如admin:admin,guest:guest, administrator:password，这些帐户在沙箱环境中授予应用程序的有限访问权限。当检测到入侵事件时，即当威胁者通过其中一个凭证成功进行身份验证并获得对应用程序的访问权限时，蜜罐将被重置并重新部署。

为了分析阻止网络扫描流量的有效性，我们阻止了蜜罐子集上的已知扫描器IP列表。防火墙策略根据观察到的网络扫描流量每天更新一次。根据应用程序和天数，每个防火墙策略可能会阻止600-3000个已知的扫描器IP地址。

所有蜜罐的日志都聚合在一个Elasticsearch集群中。控制器服务器持续监控日志并检查每个蜜罐的运行状况。如果检测到入侵事件或虚拟机没有响应，控制器将重新部署虚拟机和应用程序。图1展示了蜜罐基础设施的体系结构。

### **攻击模式**

图2-5分析了攻击的时间、频率和来源。我们将“首次入侵时间”定义为一个应用程序在首次遭到破坏之前处于完整状态的时间。图2显示了320个蜜罐的平均首次入侵时间（以分钟为单位）。首次入侵时间基本上是攻击者在互联网上发现并破坏一项新服务所需的时间。它也类似于IT管理员在被攻击前对暴露的服务的安全警报做出反应的时间。

首次入侵时间因应用而异。一般来说，它与针对该应用的攻击者数量成反比（图4）。当攻击者的数量增加时，该应用的首次入侵时间就会减少。

![](../Images/2160b24bd74148f314008aff82d9ce17.png)

图2. 从蜜罐部署到其首次入侵事件之间的时间  

 

“平均入侵间隔”是指目标应用程序的两个连续入侵事件之间的平均时间。图3显示了30天内每个蜜罐应用的平均入侵间隔。

互联网上一个易受攻击的服务通常会被多个不同的攻击者多次破坏。为了争夺受害者的资源，攻击者通常试图清除其他网络犯罪团伙（如Rocke、TeamTNT）留下的恶意软件或后门。出于这个原因，平均入侵间隔类似于攻击者在另一个攻击者出现之前可以在破坏系统上拥有的时间，与首次入侵时间一样，应用程序的平均入侵间隔与针对该应用程序的攻击者数量成反比。

![](../Images/626f9628fe71ec7fffe425f3cb17d597.png)

图3. 一个应用程序的两个连续入侵事件之间的平均时间  

 

图4显示了30天内在每个蜜罐上观察到的唯一攻击者IP地址的平均数量。该数字也表示每个蜜罐被攻破的次数。请注意，这不是在全球范围内观察到的攻击者IP的数量。由于大多数攻击者IP只到达我们蜜罐的一小部分，因此全球观察到的攻击者IP的数量要高得多。在我们的实验中，只有18%的攻击者IP到达一个以上的蜜罐。

![](../Images/eefb8acef50f6405e843734eb0515ce3.png)

图 4. 30 天内在蜜罐上观察到的唯一攻击者 IP 的平均数量  

 

图5显示了在不同日期里重复观察到的攻击者IP地址的百分比。在本研究涉及的30天内，85%的攻击者IP只在一天内被观察到。这个数字表明，基于三层IP的防火墙是无效的，因为攻击者很少重复使用相同的IP来发动攻击。今天创建的恶意IP列表很可能明天就会过时。

### **防火墙的有效性**

之前对网络扫描活动的调查发现每天有超过70万个扫描器IP。我们很好奇，主动阻断网络扫描流量是否可以防止攻击者发现蜜罐并减少攻击次数。为了测试这个假设，我们创建了一个由48个蜜罐组成的实验组，并应用防火墙策略来阻止来自已知网络扫描器的IP。防火墙策略阻止了过去30天内每天扫描特定应用程序的IP。图6比较了对照组（无防火墙）和实验组（有防火墙）之间在每个蜜罐上观察到的攻击数量。我们没有发现两组之间的显著差异，这意味着阻止已知的扫描器IP对缓解攻击是无效的。

![](../Images/d4524cd15f9d4c11b1cfcac8b5d93913.png)

图6. 在有防火墙和无防火墙的每个蜜罐上观察到的唯一攻击者IP的平均数量  

 

 

### **区域影响**

我们也很好奇部署在不同地理位置的服务是否会受到不同的攻击。图7比较了在不同地区观察到的每个蜜罐的攻击数量。对于部署在不同地区的Samba、Postgres和RDP蜜罐来说，没有明显区别。然而，我们发现，不同地区针对SSH蜜罐的攻击集中度差异很大：部署在亚太地区的SSH蜜罐的攻击数量比部署在北美的高50%，比欧盟的高263%。这些数字与攻击来源之间也存在着有趣的关联性，如图8所示。50%的攻击者IP地址来自亚太地区，20%的来自北美，只有不到10%来自欧盟。这表明，位于亚太地区的SSH服务比其他地区的服务更容易受到攻击。

### **结论**

这项研究强调了这种错误配置的风险和严重性。当一个脆弱的服务暴露在互联网上，攻击者可以在短短几分钟内找到并攻击它。由于这些面向互联网的服务大多与其他一些云负载相连，任何被破坏的服务都有可能导致云被破坏。

但是，这种类型的错误配置并不难用云原生方法来预防和补救。系统管理员可以采取如下的一些措施：

*   创建防护以防止特权端口被打开。例如，使用AWS服务控制策略或Azure防火墙管理。
    
*   创建审计规则，监测所有开放的端口和暴露的服务。例如，使用AWS配置、Checkov或云安全态势管理工具。
    
*   创建自动响应和补救规则，自动修复错误配置。例如，考虑AWS Security Hub或Prisma Cloud AutomatedRemediation。
    
*   在应用程序前面部署下一代防火墙，如VM系列或WAF来阻止恶意流量。
