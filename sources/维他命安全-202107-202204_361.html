0x00 风险概述

2021年9月14日，微软发布了9月份的安全更新，修复了开放管理基础结构 (OMI) 软件代理中的4个安全漏洞，这些漏洞统称为OMIGOD。目前已经发现了僵尸网络Mirai利用OMIGOD 漏洞的攻击活动。

 

0x01 攻击详情

开放管理基础设施（OMI）是一个开源的基于网络的企业管理（WBEM）实现，用于管理Linux和UNIX系统。一些Azure虚拟机（VM）管理扩展使用这个框架来协调Linux虚拟机的配置管理和日志收集。

这4个漏洞是在微软静默安装在超过一半的 Azure 实例上OMI软件代理中发现的，OMI代理以root权限运行。攻击者可以利用它们远程执行代码或提升 Azure 上运行的易受攻击的 Linux 虚拟机的权限。这些漏洞非常容易被利用，它们影响了数以千计的 Azure 客户和数百万个端点。OMIGOD漏洞包括：

  • CVE-2021-38647：未经身份验证（root权限）的远程代码执行（CVSS评分：9.8）

  • CVE-2021-38648：权限提升漏洞（CVSS评分：7.8）

  • CVE-2021-38645：权限提升漏洞（CVSS评分：7.8）

  • CVE-2021-38649：权限提升漏洞（CVSS评分：7.0）

其中，最严重的漏洞为CVE-2021-38647，该漏洞的攻击复杂度较低，在单个数据包中，攻击者只需删除身份验证头即可成为远程计算机上的root用户。攻击者也可以利用这个漏洞获得对目标 Azure 环境的初始访问，然后进行横向移动。

研究人员表示，攻击者正在互联网上扫描超过110台服务器暴露的Azure Linux虚拟机，这些虚拟机容易受到CVE-2021-38647漏洞的攻击。目前OMIGOD漏洞正在被积极利用来投放僵尸网络和加密挖矿恶意软件，如僵尸网络Mirai。

 

0x02 风险等级

高危。

攻击者可以利用这些漏洞远程执行任意代码并升级到root权限。

 

0x03 影响范围

OMI 版本 < v1.6.8-1

 

0x04 安全建议

微软已在OMI 版本 1.6.8-1中修复了这些漏洞，建议受影响用户手动升级其 OMI 实例。此外，OMI实例在5985、5986、1270端口进行监听的用户应该限制对这些端口的网络访问，以防护远程代码执行漏洞（CVE-2021-38647）。

微软已于2021年9月16日发布了OMI 漏洞的附加指南，并建议客户在更新可用时为云和本地部署更新易受攻击的扩展，具体影响范围和更新时间表请参考微软官方发布的更新指南。

通用安全建议

  • 定期更新软件、程序和应用程序，确保应用程序是最新的，以保护系统免受漏洞利用。

  • 加强系统和网络的访问控制，修改防火墙策略，关闭非必要的应用端口或服务，减少将危险服务（如SSH、RDP等）暴露到公网，以减少攻击面。

  • 预防0day漏洞和恶意软件，安全产品实时更新最新规则或相关防护指标。

  • 加强系统用户和权限管理，启用多因素认证机制和最小权限原则，用户和软件权限应保持在最低限度；启用强密码策略并设置为定期修改。

  • 使用最新、全面的威胁情报信息，监控网络和安全事件，以快速响应攻击。
