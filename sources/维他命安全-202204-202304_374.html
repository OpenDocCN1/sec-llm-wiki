摘要

Unit 42 发现了 Zloader 和 BazarLoader 样本可绕过沙盒，文章将详细介绍 API Hammering 在这类恶意软件中的实现。API Hammering 涉及使用大量的Windows API 调用，作为延长休眠的一种形式，以绕过沙盒中的检测。

沙盒是一种流行的技术，用于检测样本是否是恶意的。沙盒可用来分析二进制文件在受控环境中执行时的行为。在利用有限的计算资源分析大量的二进制文件时，沙盒须处理许多问题。恶意软件有时会滥用这些问题，在执行恶意程序之前在沙盒中休眠，以隐藏其真实意图。


常见的恶意软件休眠方式

最常见的恶意软件休眠方式是简单地调用Windows API 函数 Sleep。常见的一种更隐蔽的方式是Ping Sleep 技术，即恶意软件不断向一个 IP 地址发送ICMP 网络数据包（ping），并循环进行。发送和接收这种无用的ping 信息需要一定的时间，因此恶意软件间接地进行了休眠。然而，这些方法都很容易被发现。


API Hammering

API Hammering 是一种已知的沙盒绕过技术，恶意软件开发者有时会使用它来绕过沙盒分析。研究人员近期发现 Zloader（多种类型恶意软件的 dropper）和后门 BazarLoader 使用了新的 API Hammering 实现来保持隐蔽性。

API Hammering 包含大量垃圾 Windows API 函数调用。这些调用的执行时间延迟了恶意软件的真正恶意程序的执行。这使恶意软件可以在沙盒分析过程中间接休眠。


BazarLoader 中的 API Hammering

BazarLoader的一个较早的变体使用固定数量（1550）的 printf 函数调用来超时恶意软件分析。在分析较新版本的 BazarLoader 时，研究人员发现了一个更复杂的 API Hammering 的实现。

下面的反编译过程显示了这个新变体是如何在 BazarLoader 样本中实现的。它利用了一个具有随机计数的巨大循环，反复访问 Windows中的随机注册表项列表。

图 1. BazarLoader 中的 API Hammering 循环

为了生成随机循环计数和注册表项列表，该样本从System32 目录中读取符合定义大小的第一个文件。然后对该文件进行编码（参见图 2）以删除其大部分空字节。然后根据该文件中第一个空字节的偏移量计算随机计数。随机注册表项列表是从编码文件中的固定长度块生成的。

图 2. 在 BazarLoader 中对选定文件进行编码

对于不同的 Windows 版本（Windows 7和8 等）和不同的应用更新，System32目录中也有不同的文件。这会导致 BazarLoader 在不同机器上执行时，使用的循环计数和注册表项列表不同。

API Hammering 函数位于 BazarLoader 样本的打包程序中（参见图 3）。它延迟了payload 解包过程以绕过检测。如果不完成解包过程，BazarLoader 样本似乎只是在访问随机注册表项，这种行为也可以在许多合法的软件中看到。

图 3. API Hammering 延迟 BazarLoader 中的解包过程


Zloader 中的 API Hammering

BazarLoader样本依赖循环来执行 API Hammering，而 Zloader 使用了一种不同的方法。它不需要巨大的循环，而是使用了 4 个大型函数，其中包含对多个较小函数的嵌套调用（参见图 4）。

图 4. ZLoader 中负责 API Hammering 的大型函数之一

每个小程序内部都有4个与文件 I/O 相关的 API 函数调用。这些函数是GetFileAttributesW、ReadFile、CreateFileW和WriteFile（参见图 5）。

图 5. ZLoader 中负责 API Hammering 的小函数之一

通过使用调试器，研究人员计算出对4个文件 I/O 函数的调用次数（参见图6）。大型和小型函数总共生成超过一百万个函数调用，而无需使用 BazarLoader 中看到的单个大型循环。
