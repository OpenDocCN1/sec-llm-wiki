Google Chrome V8引擎远程代码执行漏洞是由于源代码中异常类型误写造成，攻击者可利用此漏洞执行任意代码，目前厂商已经发布了相应的升级补丁，补丁可直接到厂商主页下载。此次漏洞涉及面比较大，绿盟科技启动应急响应，10小时完成漏洞分析、报告输出、检测工具及产品升级。

综述
Google Chrome V8引擎3.20至4.2版本中存在远程代码执行漏洞，该漏洞是由于源代码中“observe_accept_invalid”异常类型被误写为“observe_invalid_accept”所致。攻击者可利用该漏洞造成kMessages关键对象信息泄露，执行任意代码。基于Android 4.4.4至5.1版本系统的WebView控件开发的手机APP均可能受上述漏洞影响。

漏洞分析
V8是一个Google开发的开源高性能JavaScript引擎，内置机制是将底层native的对象或代码暴露给上层JavaScript代码，供其访问调用，从而提高效率。本次BadKernel漏洞，存在于ConvertAcceptListToTypeMap函数。该函数代码见以下地址：
该函数代码见以下地址：
http://androidxref.com/5.0.0_r2/xref/external/chromium_org/v8/src/object-observe.js#ConvertAcceptListToTypeMap


该漏洞产生的具体原因及利用步骤如下：
1.JavaScript代码调用对象的observe方法——Object.observe()。
2. Object.observe方法调用native层绑定的NativeObjectObserve函数。

FormatMessage函数的type参数的最终来源是MakeTpyeError()函数的“observe_accept_invalid”参数，然而它并不存在，从而导致内存越界访问，造成信息泄露。因此，攻击者可以通过精巧的内存控制，借助此漏洞调用对象的observe方法实现信息泄露，进而实现任意代码执行。

防护方案
1.受影响的厂商，尽快升级V8版本至4.2以上版本。
2.对于暂时因各种原因无法升级的厂商，将messages.js文件中定义的observe_invalid_accept修改为observe_accept_invalid，并重新编译V8至自身APP内，推送APP升级。

什么是Google Chrome V8引擎?
Google V8 JavaScript Engine是美国谷歌（Google）公司为Chrome浏览器开发的一套开源JavaScript引擎。V8会将JavaScript代码编译成机器码执行，而非以字节码或是解释程序执行，以此提升性能。除此之外，V8引擎还使用了如内联缓存（inline caching）等方法来提高性能。基于以上特性，V8执行JavaScript代码的效率可以媲美二进制程序。
影响的版本
 ●  Google Chrome JavaScript V8 引擎 3.20-4.2。
 ●  Android 4.4.4-5.1上使用WebView控件所开发的APP。
不受影响的版本
●  Google Chrome JavaScript V8引擎 > 4.2。
