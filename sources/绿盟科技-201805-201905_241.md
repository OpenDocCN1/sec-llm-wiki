# 实战 | 如何利用态势感知平台挑战挖矿蠕虫

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MjM5ODYyMTM4MA==&mid=2650394021&idx=1&sn=fdec983c7afcb9b53e32ebace7a5b7bb&chksm=beca940e89bd1d1899aae0d02c46b4ef8960ff41e77fe85f2249f0fcb86fccc265bf05f725f0&scene=126&sessionid=1681372495#rd](http://mp.weixin.qq.com/s?__biz=MjM5ODYyMTM4MA==&mid=2650394021&idx=1&sn=fdec983c7afcb9b53e32ebace7a5b7bb&chksm=beca940e89bd1d1899aae0d02c46b4ef8960ff41e77fe85f2249f0fcb86fccc265bf05f725f0&scene=126&sessionid=1681372495#rd)

**WannaMine**是一种挖矿蠕虫，利用NSA泄漏的EternalBlue（“永恒之蓝”）漏洞进行传播，黑客以此建立挖矿僵尸网络。其危害与其兄弟WannaCry的“即时爆发”的方式不同，WannaMine会长期潜伏于系统，比WannaCry更隐蔽，伺机感染其它终端，最终导致终端性能下降、甚至网络拥塞，直至业务不能正常运行。

怎么发现网内主机、服务器被WannaMine感染了呢？今天，绿盟君就跟大家分享一个能源行业实例，一起定位挖矿蠕虫。

  

事件背景

  

某能源集团（以下简称Z集团），内部主机接近6W台，服务器300台，海内外分支机构众多，网络安全技术防御体系包含防火墙、抗DDoS、入侵防御系统、WAF、日志审计系统等若干设备。

 

另部署有绿盟科技态势感知平台，三台绿盟僵木蠕探针以及其它探针若干。

 

Z集团于2017年底要求全网客户端、服务器更新MS17-010补丁，以预防WannaCry家族的入侵。

  

事件分析

**感知阶段**

  

*   某日，Z集团管理员在绿盟态势感知大屏中发现风险指数突发性增高。
    

![](../Images/dbfd99d45c3b441ab4b839eee3010568.png)

  

*   通过观察，发现页面左下角攻击链中，最危险的三个阶段都存在告警。
    

![](../Images/a99cf3eb2301fe12ac5dee5ec9f92203.png)

  

*   管理员脑中马上亮起红灯，机敏地意识到可能发生安全事件，于是在平台中进一步分析，默认搜索条件下一眼就发现了两个显眼的攻击阶段。
    

![](../Images/6da7428d23603ef00b3a3807090f17d9.png)

  

*   点击图标“安装工具”，向下钻取，查看合并后的日志，就可以发现“挖矿蠕虫的行为”。
    

![](../Images/293a5688825af355acb0747f252e37ca.png)

  

*   Z集团管理员此时已确认安全事件，但感觉信息还是不够详细。继续向下钻取到原始看看……经过向下钻取，WannaMine安全事件在网络层面的攻击行径已经很清晰了，内网存在主机向DNS服务器请求C&C域名地址，以此建立挖矿程序链接。
    

![](../Images/bb0ff0b9197adfea023b97b084b9a21e.png)

![](../Images/a1f44cb521e0619d31a13c8b86da4038.png)

  

*   从平台感知到搞清楚安全事件流向只用了 **2 分钟！！！**
    

  

**定位分析阶段**

  

*   管理员向上级报告了该事件，并联系绿盟技术专家到现场定位分析。技术专家经过现场排查，内部的这台主机，除了外联C&C域名的行为，还对全网进行445端口的漫扫描行为，试图以此横向感染内网其它主机。（以下为探针抓包的数据）
    

  

![](../Images/188a65d6d03a291ef79911e7881030ee.png)

  

*   经过绿盟专家的排查，内网两台主机确诊感染WannaMine病毒，由于两台主机并无关键数据，在绿盟专家的配合下，完成了后续处置恢复工作。
    

  

事件总结

  

◆ 被感染主机均没更新MS17-010补丁，445端口没有使用，却处于开放状态；

◆ 网络安全管理制度没有落实到位，导致管理终端数量庞大时，网络安全的重要决策全网推动效率较低；

◆ 部署了众多各类的安全设备，并不代表网络安全已健全。

  

值得庆幸的是，Z集团部署了绿盟科技态势感知平台，并且拥有一位警觉爱技术的安全运维管理员；

  

关键点：在**“人 + 平台 + 设备”**的化学反应下，及时发现并妥善的处理了一起安全事件。

  

**安全建议总结**

1、及时更新系统和中间件的补丁。

2、关闭终端、服务器上不必要的端口。

3、建立健全网络安全管理制度。

4、热情邀请热衷技术的安全运维人员。

5、最重要的：搭建一套**绿盟态势感知平台**，它可以：

     ◆ 提供大屏展示，全方位风险直观展示；

     ◆ 以大数据平台分析为基础，通过攻击链展示需关注的安全事件，一眼望穿威胁；

     ◆ 对安全日志归并，以大数据结构存储，大大减少管理员对海量日志分析的成本；

     ◆ 结合安全情报，提高安全事件研判准确度。
