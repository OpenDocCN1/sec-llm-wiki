# WordPress ≤ 4.9.6任意文件删除漏洞

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MjM5ODYyMTM4MA==&mid=2650392391&idx=2&sn=b0c202753880c838defc316ada198f25&chksm=beca9eec89bd17fafbe24efa229e6f6820f58b52ef4dd35289f037f4b0bfc6b47991d1c5d278&scene=126&sessionid=1681372515#rd](http://mp.weixin.qq.com/s?__biz=MjM5ODYyMTM4MA==&mid=2650392391&idx=2&sn=b0c202753880c838defc316ada198f25&chksm=beca9eec89bd17fafbe24efa229e6f6820f58b52ef4dd35289f037f4b0bfc6b47991d1c5d278&scene=126&sessionid=1681372515#rd)

综述

近日，国外安全研究组织rips团队发布了一篇WordPress任意文件删除到代码执行的漏洞文章，文章中指出攻击者可以利用此漏洞删除任意文件，比如删除WordPress建站配置文件wp-config.php，通过删除此文件可导致界面进入网站安装页面，通过重装网站后进入管理员后台即可获取网站shell从而控制WordPress网站，故该漏洞的危害很大。唯一缺陷就是需要攻击者拥有操作多媒体文件的功能，一般作者权限就可以触发漏洞。

攻击难度：中

危害程度：高

影响版本： ≤4.9.6

什么是WordPress？

WordPress是一个以PHP和MySQL为平台的自由开源的博客软件和内容管理系统。WordPress具有插件架构和模板系统。Alexa排行前100万的网站中有超过16.7%的网站使用WordPress，根据w3tech的资料显示，约有30％的网站在使用它。WordPress是目前因特网上最流行的博客系统。

技术分析

在文件/wp-admin/posts.php中，当编辑附件时有如下代码：

![](../Images/127cc2c6bea702931db8204f48d222ae.png)![](../Images/08d1f5a6b58902a1377b9e463959c214.png)

通过wp\_get\_attachment\_metadata函数获取当前post\_id对应内容的metadata信息，也就是数据库表wp\_postmeta中的信息，然后给metadata信息中添加一个thumb的内容，这个thumb的内容通过POST直接传递，没有经过处理，最后更新metadata的信息。然后在删除媒体内容时，有如下代码：

![](../Images/37c050767fb51c04eece4b42d58cf453.png)![](../Images/08d1f5a6b58902a1377b9e463959c214.png)

当前用户有删除内容的权限时，调用了wp\_delete\_attachment函数，这里的post\_type默认就是attachment。

![](../Images/73b6f0a81377a9e04c9467cb79888db4.png)![](../Images/08d1f5a6b58902a1377b9e463959c214.png)

然后跟进wp\_delete\_attachment函数，在文件/wp-includes/post.php中跟进次函数：

![](../Images/3719a2b5b506a24c4ae2510d15582ec9.png)![](../Images/08d1f5a6b58902a1377b9e463959c214.png)

通过wp\_get\_attachment\_metadata函数获取post\_id对应内容的metadata信息，然后当thumb不为空时，到最后unlink文件：

![](../Images/09ed9231f98581b2d0fd226b4ade1650.png)![](../Images/08d1f5a6b58902a1377b9e463959c214.png)

从meta\[‘thumb’\]到thumbfile，再从thumbfile进入unlink函数，没有对文件进行过滤处理，导致直接删除文件。

**通过上面的分析，我们首先通过修改媒体文件，给thumb赋值为你想删除的文件，然后再删除此媒体文件，既可以删除任意文件。**

漏洞验证

首先我们注册一个author的作者权限用户，登陆后添加媒体文件，再编辑文件并且找到修改图像时的wpnonce值。

![](../Images/973aa1367c6d1d6fa58dc97bfb832725.png)![](../Images/08d1f5a6b58902a1377b9e463959c214.png)

然后发送修改图像的请求，这里我们在网站根目录下新建了一个111111文件，然后修改要删除的文件为111111：

![](../Images/3a0c3f8cec0324788ba7f223125fa3bc.png)![](../Images/08d1f5a6b58902a1377b9e463959c214.png)

此时已经修改图像，并且图像的metadata中thumb的内容就是../../../../111111文件路径。然后我们在删除该文件，首先找到删除文件时的wpnonce：

![](../Images/0abfb00085060a3aeaf4770e57539517.png)![](../Images/08d1f5a6b58902a1377b9e463959c214.png)

最后直接发送删除请求：

http://localhost/wordpress-4.7.4/wp-admin/post.php?post=12&action=delete&\_wpnonce=d85e71ffa9

同下断点可以看到这里删除的具体文件：

![](../Images/988228f7f53500c4e03156cce32c1b9a.png)![](../Images/08d1f5a6b58902a1377b9e463959c214.png)

最后成功删除我们新建的111111文件。那么删除wp-config.php文件同理。

防护方案

目前官方没有提供修复方案，这里给出临时修复方案。在/wp-admin/post.php中，当修改图像文件时，在wp\_update\_attachment\_metadata更新metadata时对传入的thumb文件进行处理，如图：
