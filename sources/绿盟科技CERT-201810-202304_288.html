 危害等级：高，影响范围广，PoC已在野公布，攻击者利用此漏洞可以root权限执行任意命令。
 版本：1.0
1

漏洞概述


2月11日，安全研究人员在oss-security邮件列表披露了runC容器逃逸漏洞的详细情况，根据OpenWall规定，EXP将于2019年2月18日公开。但绿盟科技安全服务团队监测发现，此漏洞PoC已于Github上公开。目前官方已发布针对此漏洞的补丁，请部署有云平台、容器应用的企业尽快部署防护措施。

runC默认运行于Docker、containerd, Podman, and CRI-O等容器，应用范围广。其是根据OCI (Open Container Initiative)标准，生成和运行容器的命令行接口(CLI)工具，可不通过docker引擎，直接运行容器。该漏洞（CVE-2019-5736）允许恶意容器覆盖宿主机上的 runC 文件，从而在宿主机上以root 权限执行恶意代码。


参考链接：

https://www.openwall.com/lists/oss-security/2019/02/11/2

2影响范围

该漏洞的利用存在限制条件，当满足下列任一条件时，攻击者可能以root权限执行任意命令：

(1) 用户使用已被攻击者控制的恶意镜像创建新容器；

(2) 攻击者具有docker容器的写入权限，可使用docker exec执行命令。


受影响产品：

  • runC  <= 1.0.rx6

  • Docker  < 18.09.2

  • Apache Mesos

  • LXC

3解决方案

为缓解该漏洞，建议用户使用经过审查且来源可信的容器镜像。同时建议使用基于runC 技术的开发者尽快采取防护措施，对此漏洞进行修复。

  • runC github 修复链接：

https://github.com/opencontainers/runc/commit/0a8e4117e7f715d5fbeef398405813ce8e88558b

  • LXC补丁更新参考链接：

https://github.com/lxc/lxc/commit/6400238d08cdf1ca20d49bafb85f4e224348bf9d

  • Docker 最新版本18.09.2 中已修复了该漏洞，建议升级到最新版本。

https://github.com/docker/docker-ce/releases/tag/v18.09.2
