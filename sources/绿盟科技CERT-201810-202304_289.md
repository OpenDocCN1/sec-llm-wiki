**1**

**漏洞概述**

  

近日，安全研究员公布了Microsoft Exchange 任意用户伪造漏洞（CVE-2018-8581）的新利用方式，危害更大，可导致攻击者获取域服务管理控制权限，进而获得域服务中的所有账户信息。目前该研究员已将此利用方式的PoC及细节公布，且微软尚未对此漏洞发布安全补丁，相关用户可参考本文的临时防护方案进行有效防护。

2**影响范围**

**受影响版本：**

*   Microsoft Exchange Server 2010
    
*   Microsoft Exchange Server 2013
    
*   Microsoft Exchange Server 2016
    
*   Microsoft Exchange Server 2019
    

  

3**漏洞排查**

**3.1 注册表排查**

用户可判断是否存在以下注册表项HKEY\_LOCAL\_MACHINE\\SYSTEM\\CurrentControlSet\\Control\\Lsa\\DisableLoopbackCheck，若存在且键值为1，则说明存在风险。

**![](../Images/839c49e4650fd358b6ab6b57e563287e.png)**

注：注册表项HKEY\_LOCAL\_MACHINE\\SYSTEM\\CurrentControlSet\\Control\\Lsa\\DisableLoopbackCheck为身份验证环回检查，当其设置为1时，表示该项被禁用。

  

4**漏洞防护**

经分析，安全研究员Dirk-jan在博客上公开的漏洞利用细节中，利用了多种缺陷进行组合，将用户提升为域控权限，但是提权成功需要同时满足以下3个条件：

*   目标账号在Exchange系统中拥有较高的权限，即在Exchange Windows permissions(EWP)安全组中或继承该组权限。
    
*   NTLM认证可被中继攻击。
    
*   Exchange存在 CVE-2018-8581 SSRF漏洞。
    

目前微软还未对此漏洞发布相关的安全补丁，作者在文中也给出了缓解措施，绿盟科技建议，使用Microsoft Exchange Server的企业参考如下措施对此攻击进行临时防护。

  

**4.1 删除Exchange账户高权限**

*   删除Exchange对Domain对象所具有的不必要的高权限。
    

用户可到下列链接中下载高危权限移除脚本，该脚本会检查WriteDacl权限，并移除该权限。在Powershell控制台执行此脚本可完成此项防护措施。

https://github.com/gdedrouas/Exchange-AD-Privesc/blob/master/DomainObject/Fix-DomainObjectDACL.ps1 

注意：

进行权限变更可能会影响正常业务，请用户进行评估后再进行操作。

经绿盟科技分析，此脚本移除权限操作，无植入后门、远程控制以及数据窃取行为；

  

**4.2 NTLM中继安全认证**

    通过设置Microsoft Exchange Server的NTLM中继安全认证，可阻断CVE\-2018-8581漏洞击杀链，通过实施如下任一方案，即可在NTLM认证方面实现漏洞利用的防护，但是也请读者认真阅读相关措施可能造成的问题。

  

**方法一：启用LDAP签名并启用LDAP通道绑定**

通过启用LDAP签名和通道绑定，来避免中继到LDAP及LDAPS协议上(https://support.microsoft.com/en-us/help/4034879/how-to-add-the-ldapenforcechannelbinding-registry-entry)。

注意： 在域控上启用该设置之前，客户端必须先安装 CVE-2017-8563安全更新，否则可能出现兼容性问题。

启用LdapEnforceChannelBinding注册表项，具体操作步骤如下：

1、 键入“Windows”+“R”，输入“regedit”打开注册表编辑器。

2、 进入下列路径：

Active Directory 域服务(AD DS)控制器注册表路径：

HKEY\_LOCAL\_MACHINE\\System\\CurrentControlSet\\Services\\NTDS\\Parameters

ActiveDirectory轻量目录服务(ADLDS)服务器注册表路径：

HKEY\_LOCAL\_MACHINE\\SYSTEM\\CurrentControlSet\\Services\\<LDS instance name>\\Parameters

3、 找到LdapEnforceChannelBinding项，将其设置为2，无需重启即可生效。

注：

*   dword值：0表示已禁用。不执行通道绑定验证。这是所有尚未更新的服务器的默认行为。
    
*   dword值：1表示支持时启用。在已更新为支持信道绑定令牌(CBT)的Windows版本上运行的所有客户端必须向服务器提供信道绑定信息。运行未更新以支持CBT的Windows版本的客户端不必这样做。这是一个允许应用程序兼容性的中间选项。
    
*   dword值：2表示始终启用。所有客户端必须提供信道绑定信息。服务器拒绝所有不提供信道绑定信息的身份验证请求。
    

**![](../Images/3100cc1a7e653babc6a30837339ef812.png)**

  

**方法二：设置Exchange服务器访问控制**

通过防火墙屏蔽Exchange服务器对无关主机的访问，设置可访问服务器白名单。

  

**方法三：在IIS中的Exchange端点上启用身份认证的扩展保护**

通过验证NTLM身份认证中的通道绑定参数，将NTLM身份验证与TLS连接联系起来，阻止中继到Exchange Web服务。详情可参考https://msdn.microsoft.com/enus/library/dd767318%28v=vs.90%29.aspx（请注意：不是Exchange后端端点，这将破坏Exchange）。

  

**方法四：在Exchange服务器上启用SMB签名**

通过启用SMB签名，防止对SMB的跨协议中继攻击。

注意：启用SMB签名会对所有的SMB数据包进行签名校验，会导致网络性能降低10%-15%，建议在网络性能支持的情况下开启。

配置SMB签名，具体操作步骤如下：

1、 键入“Windows”+“R”，输入“regedit”打开注册表编辑器。

2、 进入下列路径：

*   配置服务器SMB签名注册表路径
    

HKEY\_LOCAL\_MACHIME\\System\\CurrentControlSet\\Services\\LanManServer\\Paramete

*   配置工作站SMB签名注册表路径
    

HKEY\_LOCAL\_MACHIME\\System\\CurrentControlSet\\Services\\Rdr\\Paramete

3、 在编辑菜单上单击新建->DWORD值。

4、 添加以下两个值：

| Value Name: EnableSecuritySignatureData Type: REG\_DWORDData: 0 (disable), 1 (enable)    NOTE: The default is 0   (disable)  
Name: RequireSecuritySignatureType: REG\_DWORDValue: 0 (disable), 1 (enable)    NOTE: The default is 0   (disable) |
| --- |

5、  单击确定，退出注册表编辑器，关闭并重新启动服务器。

![](../Images/55e2627d1c44b01c4cf073d1680ce9c2.png)

  

**4.3  删除DisableLoopbackCheck注册表项**

*   用户可通过删除注册表项DisableLoopbackCheck来实现对该漏洞的防护，具体操作方法如下：
    

以管理员权限打开命令提示符并执行如下命令：

| reg delete“HKEY\_LOCAL\_MACHINE\\SYSTEM\\CurrentControlSet\\Control\\Lsa”   /v “DisableLoopbackCheck” /f |
| --- |

  

删除后无需重启系统或Exchange Server，即可生效。同时公告指出，Exchange更新后将不再默认启用该注册表项，也请用户及时关注官方的更新情况。

另：为确保服务稳定运行，用户可在执行上述注册表项删除命令前对注册表进行备份，具体步骤如下：

1、 键入“Windows”+“R”，输入“regedit”打开注册表编辑器。

2、 点击“文件”->“导出”，将注册文件进行备份保存。

![](../Images/738101a686432ec6bc6c612379e0520d.png)

  

  

5**攻击手段简析**

Exchange允许任何用户构造所需URL推送订阅（Push Subscription），服务器将尝试向构造的URL发送通知。由于Exchange使用CredentialCache.DefaultCredentials实现连接，而在Exchange Web Server（EWS）中，CredentialCache.DefaultCredentials在NT AUTHORITY\\SYSTEM上运行，因此导致Exchange Server泄露NTLM hash给攻击者。

  

**5.1  NTML容易受中继攻击**

NTML 受中继攻击是多年以来一直存在的问题，NTML 身份验证封装在其他协议中，如 HTTP、SMB 等，无论上层协议如何，NTML 身份验证请求都是相同的，攻击者可以截取这些身份验证请求，并在其他协议中使用。如下图所示（图片来源：https://www.fox-it.com），攻击者骗取了用户的 NTML 身份验证请求，发送给服务器端，完成自身身份的验证。

![](../Images/23805feed269f8a345a8df58a686961c.png)

  

**5.2 Exchange存在SSRF漏洞（CVE-2018-8581）**

Exchange 存在 SSRF漏洞，通过PushSubscription功能，可以实现通过 HTTP对任意 URL 的身份认证。该漏洞已经分析过，这里就不详细描述。此次提权主要利用该漏洞发起主动的 NTML 身份认证以骗取 NTML 身份验证凭据。

![](../Images/aeaef5ab97ecb577ba3dae530d02e792.png)

  

**5.3 Exchange在系统中拥有较高权限**

该漏洞可以利用成功的第三点要素就是 Exchange 在系统中具有较高权限。在安装 Exchange时会创建 Organization Management 安全组，该组具有更改 Exchange 配置的权限，组成员具有更改组成员和其他 Exchange 安全组的权限。例如 Exchange Trusted Subsystem 安全组，Exchange Trusted Subsystem 也是 Exchange Windows Permissions 安全组的成员。

![](../Images/faa30ca8653c1a2b23b82ead3c356eb8.png)

Exchange Windows Permissions 安全组默认具有修改权限：

![](../Images/b9277b5c6aac2b05777cf2415543986d.png)

  

**5.4 漏洞复现过程**

首先使用ntlmrelayx.py脚本开启NTLM 中继监听，尝试使用liuruo账户进行提权：

![](../Images/5e0e5eb5064dc58c1ca693d9febd2cae.png)

       接下来使用 privexchange.py工具利用 CVE-2018-8581漏洞让Exchange 服务器对监听主机发起 NTLM 身份验证：

![](../Images/00493c073a725ebc1e4f4880038240e4.png)

监听主机监听到服务器对本地的 NTLM 身份认证请求，获取到 NTLM身份凭据，并使用该凭据更改安全组配置及 DACL，获取 Replication-Get-Changes-ALL 权限。

![](../Images/32884b3f32de5b083b1310420c602ba3.png)

最后，利用liuruo 账户，直接进行 Dcsync 操作，获取域内所有主机NTLM HASH，这就意味着获取到域的管理权：

![](../Images/c35a2d705917f4c69525ca3f5597d81a.png)
