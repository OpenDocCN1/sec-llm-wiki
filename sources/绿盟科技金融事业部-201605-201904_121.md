# 关于金融数据安全管理的一些探讨

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzI2NDI5MTg4MA==&mid=2247485676&idx=1&sn=78e165967aff9f00a8e013d796f3dd37&chksm=eaaf9babddd812bd6af86c16a06074e63f055df1064b9552ffbd7a2d53213752571711f92c2e&scene=126&sessionid=1681322718#rd](http://mp.weixin.qq.com/s?__biz=MzI2NDI5MTg4MA==&mid=2247485676&idx=1&sn=78e165967aff9f00a8e013d796f3dd37&chksm=eaaf9babddd812bd6af86c16a06074e63f055df1064b9552ffbd7a2d53213752571711f92c2e&scene=126&sessionid=1681322718#rd)

最早提出“大数据”时代到来的是全球知名咨询公司麦肯锡，从2012年起，大数据（big data）一词越来越多地被提及，从硅谷到北京，该话题愈演愈烈。毫无争议，金融业数据无疑是大数据领域中最重要之一，当我们在利用金融大数据分析和挖掘获取商业价值的同时，黑客已经悄无声息介入攻击，使得数据安全一直是各金融企业和学术界非常关注的研究方向。

行为学家Dan Ariely曾说过有关大数据的一段话，同样适用于金融行业的大数据，“Big Data is like teenage sex: Everyone talks about it, nobody really knows how to do it, everyone thinks everyone else is doing it, so everyone claims they are doing it too”。借用知乎用户翻译: 大数据之谓也，若未弱冠而行周公之礼。人人语之，无人晓之。假人人为之，以己为之矣。借用Dan Ariely的话，其实可以映射出目前金融行业的一些现状问题，大家都在对金融数据安全纷纷侃侃而谈，但没谁真正知道该怎么去做，甚至在前几年，有人枕大数据之席文，夜以继日的研究金融行业数据安全，但行业里的解决方案依然是门可罗雀。

好在近几年，随着我国在信息安全领域重视的推动下，我国《信息安全技术-网络安全等级保护基本要求》即将进入了2.0时代，且融入了大数据及平台和应用的相应等级标准要求，在不久的将来会和大家见面。本文就金融行业数据安全方面，结合我国对大数据相关安全标准和数据全生命周期管理的维度，对金融数据安全管理技术和安全管理规范方面进行探讨和研究。

1

**金融数据价值**

近年来，我国在金融科技的快速发展下，金融业数据迅速膨胀并呈现出几何级数的增长态势，其带来的商业价值不言而喻。如BAT对金融大数据应用领域非常丰富，其横亘支付、贷款、理财、保险、证券、银行、征信、基金、众筹等各个领域，简单举个Alibaba集团在上述各方面的应用。

![](../Images/fe2d64a5481bfd88cce31e949159ad9d.png)

那么，金融数据有哪些价值呢？

**金融数据价值**

**描述**

精准营销

精准营销，基于用户行为数据去预测其偏好和兴趣，继而推荐合适的金融产品，相比传统的短信群发模式，先进了不少倍，这个大家都容易理解。帮助企业以较低的成本和较好的体验，实现精准营销，提升业务收入。

大数据风控

大数据风控主要用于预测信用风险、识别欺诈风险两方面，在金融领域的应用最成熟，目前已经在业界逐步普及。以美国主流的个人信用评分工具FICO公司开发的信用分为例，通过应用大数据来预测并验证消费者信用评分，比如P2P风控，你可以在审批授信过程中获取客户的数据，再比如网络借贷数据、还贷数据、地理位置、社交媒体数据、流水信息等等，目的也只有一个，服务于其信用体系。而欺诈风险的防控，本质上也是通过对历史欺诈行为的分析，不断梳理完善风险特征库，比如异地登录、非常用设备登录等行为，都是一种风险信号，建立一系列的风险规则判定集，预测用户行为背后的欺诈概率。

征信收集

征信收集方面，由于个人信用数据存在多多少少的缺失，大数据征信是基于用户在互联网上的社交行为、消费行为、搜索行为等产生的海量数据，其价值并没有被充分挖掘。个人征信在大数据的采集和信息挖掘上面仍有很大的想象空间。例如：阿里的芝麻信用打通了用户的身份特质，行为偏好，人脉关系，信用历史，履约能力等各类信息。

用户画像

用户画像在金融大数据中较为常见的，其实用性很高。通常金融服务机构通过对客户需求和消费能力，以及客户信用额度的分析上，去寻找潜在的目标客户，帮助金融机构对其所拥有的用户数据进行数据挖掘，构建出用户画像，从而挖掘业务机会。

Decide

（决策支持）

基于大数据和人工智能技术的决策树模型将会有效帮助金融行业分析信用风险，为业务决策提供有力支持。

客户管理

依据大数据分析，银行业，保险业，证券业相关金融领域的公司，可以帮助其客户分析金融市场产品投资，快速推出行业报告和市场趋势报告，协助其赚取超额利润等，提高其客户的满意度。

总之，金融行业的客户信息、资产信息、信用信息、交易信息等数据经过有效采集和整理，将成为具有很高价值的数据信息。

2

**金融行业数据安全现状**

大数据时代的到来，在越来越多的行业和产业中扮演着重要的角色。大数据已经成为与物质资产和人力资本同样重要的基础生产要素。大家首先来感受下我们国家对数据安全的重视程度。

![](../Images/6a2cc405d6ddafa3381eb19a8f0d9c06.png)

再来感受下金融行业的数据安全方面的现状如下：

1、2017年4月25日，中共中央政治局就维护国家金融安全进行第四十次集体学习，习近平总书记在主持学习时强调，金融是国家重要的核心竞争力，金融安全是国家安全的重要组成部分，是经济平稳健康发展的重要基础。

2、国家已经将金融行业定位到“国之重器”的高度，将金融安全从技术层面提升到了战略层面。随着金融行业地位的提升，整个行业的信息安全也变得更加重要，随之而来的挑战也更加严峻。

3、近年，大规模数据泄露事件激增，根据一份来自Identity Theft Resource Center和CyberScout的报告显示，2017年前11个月，数据泄露事件继续猛增，数量增加到1202起，这比2016年全年的1093起多出了10%。作为网络安全重点行业之一，金融因其行业特殊性一直是网络犯罪的主要目标，金融数据变成不法分子觊觎的重点对象。

4、金融科技安全现状和安全趋势值得关注：

•金融业务大幅云化，金融行业约60%的机构使用了各类云服务；

•金融行业机构对安全事件处置时间滞后，20%的安全事件处置时间超过一周；

•金融机构业务流程欠缺，只有32.9%采用了SDL开发；

•信息安全不可忽视，71.3%的企业计划增加安全预算投入，但只有21%的企业打算扩招安全团队。

5、金融行业的数据具有极高的价值和丰富的交易渠道，已经形成了暗潮汹涌的成熟黑产链条，为了在这条利益链条上分一杯羹，外部黑客不惜串通内部员工利用各种途径窃取数据，金融黑产的繁华热闹一直令金融行业的CIO们顶着巨大的压力。

6、2018年3月16日，银监会起草发布了《银行业金融机构数据治理指引（征求意见稿）》，《指引》共包括七章五十五条，旨在引导银行业金融机构加强数据治理，充分发挥数据价值。

通过上述介绍，不难看出，如今金融数据安全已经成为了大数据安全的重中之重。

3

**金融行业数据特性**

金融行业的数据，由于其本身具有较强的敏感性，其除了具有大数据的4V1C特点：Volume （大量）、 Variety （多样）、 Value （高价值）、Velocity （高速）、Complexity（复杂）外，还具备了以下的特性。

**特性**

**说明**

虚拟性

金融数据没有物质实体形态，一般以隐性的方式存在。

共享性

金融数据中有很大一部分是有共享性的，这些金融数据（如征信数据等），这些数据可以在同一时间不同地点由不同的主体（银行、保险、证券等）同时使用。

难以量化

金融数据通常都具有极大的价值，例如学术研究价值、市场监管价值、投资行情预测价值等，但是这些价值难以进行量化。

风险性

越是价值高的东西，越容易被盯上，金融数据目前无疑是黑产界非常盛行的买卖物质，同时金融数据的风险性还体现在其研发风险和收益风险方面。

那么，基于以上特点，在金融机构的业务开展过程中，需要建立建全完备的可落地的数据安全管理规范和制度，同时也需要具备强有力的且成熟的安全技术手段来保障其金融数据的安全性和业务连续性。

**金融数据安全技术**

从上一章节介绍的有关金融数据全生命周期的阶段出发，部分阶段涉及到了金融数据相关的安全技术，建议金融机构在数据生命周期阶段中，关注或采用如下安全技术，以满足一定标准要求。  

**周期阶段**

**数据安全技术应用场景**

数据采集

身份认证技术：金融机构对数据的采集者，需要有严格的身份认证，身份认证技术主要依赖于CA数字证书，故在该阶段需要关注数据采集是否可确保其最小访问原则，从而建立一个安全的数据采集环境。

数据传输

1、传输协议：在金融数据传输过程中，通常采用   SSL（Secure   Sockets Layer安全套接层，通常见到的HTTPS就是在HTTP层加入了SSL层）、TLS（Transport   Layer Security，TLS）的协议进行传输，必要时采用VPN（Virtual private network，虚拟专用网络）隧道传输，以保证数据信道的安全性。  
  2、加密技术：加密技术必不可少，其分为对称加密技术和非对称加密技术。对称加密技术又称单钥密码体制，其加密密钥和解密密钥相同，常用算法DES（Data Encryption   Standard，即数据加密标准，通常密钥长度为56位）、AES（Advanced   Encryption Standard，即高级加密标准，通常密钥长度为128、192、256位）。AES的安全性要高于DES；而非对称加密算法需要两个密钥来进行加密和解密，加密密钥和解密密钥不同，一个公开，称为公钥；一个保密，称为私钥，常用算法有RSA（RSA算法是第一个能同时用于加密和数字签名的算法），ECC（Elliptic Curves Cryptography，椭圆曲线密码编码学）。

3、数字签名技术：又称公钥数字签名、电子签章，是一种类似写在纸上的普通的物理签名，但是使用了公钥加密领域的技术实现，用于鉴别数字信息的方法。一套数字签名通常定义两种互补的运算，一个用于签名，另一个用于验证。金融数据安全中，利用较多的数据签名技术包括Hash函数/MD5/SHA系/RSA数字签名/ECC数字签名等。

数据存储

1、数据存储方式：结构化存储和非结构化存储。金融数据中，结构化存储技术常见有: Oracle、MySQL、DB2等。非结构化数据是数据结构不规则或不完整，没有预定义的数据模型，不方便用数据库二维逻辑表来表现的数据。包括所有格式的办公文档、文本、图片、XML、HTML、各类报表、图像和音频/视频信息等等，非结构化存储的技术依托于分布式文件系统，如AFS、HDFS、GFS等。

2、存储加密技术：参考上述数据传输中加密技术。

数据处理

1、数据加工技术：对金融数据中杂乱无序的数据根据需要进行排序、筛选、有条件透视等操作。

2、数据加解密技术：通过加密算法，将需要处理的金融数据明文先加密后，然后再处理，可有效防止数据处理过程中，中间状态数据造成的泄漏。

3、数据脱敏技术：通过一定的脱敏算法，对所有隐私数据信息使用固定字符串方式替换或者部分替换进行脱敏，如客户全称、证件号码、地址信息、电话、邮件、密码等脱敏处理。

数据交换

1、身份认证技术：详见数据采集身份认证技术。

2、传输协议：详见数据传输中传输协议技术说明。

3、传输数据加密技术：详见数据传输中传输数据加密技术说明

数据销毁

1、软销毁技术：软销毁又称逻辑销毁,即通过数据覆盖等软件方法进行数据销毁或者数据擦除，主要是将数据文件在存储介质上的二进制数据，强制全部写成0或1，来实现数据在存储介质上的销毁。

2、硬销毁技术硬销毁是将存储介质进行物理上的粉碎和破坏，来实现数据的安全销毁。硬销毁需要借助存储介质粉碎机进行销毁工作。

**金融数据安全规范**

金融机构在其数据治理的安全管理中，可以从以下几个方面建设：

● 需建立合理的组织架构并对人员管理，角色管理和人员培训方面做出要求；

● 结合自身发展战略和监管要求等，制定其数据安全战略，策略与规程、金融数据资产和系统资产、数据供应链，元数据等方面明确其安全管理目标、制度、流程、原则和范围；

● 基于《商业银行信息科技风险管理指引》业务连续性要求以及《商业银行业务连续性监管指引》要求和金融机构内部总体的应急预案下制定数据专项应急预案；

● 另外需要参考GDPR和个人信息安全规范等标准，制定金融机构中涉及数据跨境传输、个人信息、重要数据保护和密码支持等合规性管理制度。

除上述相关管理层面的建设外，金融数据的安全管理规范也需从全生命周期管理的维度出发，从数据收集、传输、存储、处理、交换、销毁方面制定安全规范，以满足金融行业数据的合规和各方面要求。以下为在各阶段所需规范的领域：
