# Apache Struts2 远程代码执行漏洞（S2-052） 防护方案

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzI2NDI5MTg4MA==&mid=2247484692&idx=1&sn=398ca08923241d592ece7a4acb63b5b2&chksm=eaaf9653ddd81f45d5d63a00e2ef8a472bd5a8b9b042cb198db2a6b3847205b824f22e9f6d40&scene=126&sessionid=1681322783#rd](http://mp.weixin.qq.com/s?__biz=MzI2NDI5MTg4MA==&mid=2247484692&idx=1&sn=398ca08923241d592ece7a4acb63b5b2&chksm=eaaf9653ddd81f45d5d63a00e2ef8a472bd5a8b9b042cb198db2a6b3847205b824f22e9f6d40&scene=126&sessionid=1681322783#rd)

**综述**

2017年9月5日，Apache Struts发布最新的安全公告，Apache Struts 2.5.x的REST插件存在远程代码执行的高危漏洞，漏洞编号为CVE-2017-9805（S2-052）。漏洞的成因是由于使用XStreamHandler反序列化XStream实例的时候没有任何类型过滤导致远程代码执行。   

> 相关链接如下：
> 
> **https://struts.apache.org/docs/s2-052.html**
> 
> **https://cwiki.apache.org/confluence/display/WW/S2-052**

 

**漏洞影响**

**受影响的版本：**

*   **Struts 2.1.2 - Struts 2.3.33**  
    
*   **Struts 2.5 - Struts 2.5.12**
    

**不受影响的版本：**

*   ****Struts** **2.3.34** or **Struts** **2.5.13****

**注意：**

新版本使用的默认限制策略会导致REST的一些函数停止工作，会对一些业务造成影响，建议使用以下新的接口：

org.apache.struts2.rest.handler.AllowedClasses

org.apache.struts2.rest.handler.AllowedClassNames

org.apache.struts2.rest.handler.XStreamPermissionProvider

**绿盟科技建议**由于漏洞本身特性，绿盟科技已经通过使用过滤器和产品规则升级对已知攻击方法进行了有效防护，但仍然可能存在其他绕过目前防护变形攻击方式，因此建议尽快进行升级struts2框架，彻底消除安全隐患。

  

   **绿盟科技临时修护方案**

如果应用系统暂时无法升级Struts框架，可以采用禁用XML请求的方式临时防护攻击。添加XML过滤器，将所有的contentType为“application/xml”的请求全部过滤。该方案会导致所有contentType为application/xml的请求失效。

**过滤器防护：**

      添加xml过滤器，将所有的contentType为“application/xml”的请求全部过滤。该方案会导致所有contentType为application/xml的请求失效，为暂时性的防护方案。
