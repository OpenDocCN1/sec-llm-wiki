# 漏洞研究新进展 ：Towards Efficient Heap Overflow Discovery

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzA4ODYzMjU0NQ==&mid=2652307305&idx=1&sn=c7e8593890e2dcf57206bca3cada852b&chksm=8bc562e7bcb2ebf12807ad3cc8e9c8ea6ebaf26de4671ad684ba15aaa93a350af3e748190118&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzA4ODYzMjU0NQ==&mid=2652307305&idx=1&sn=c7e8593890e2dcf57206bca3cada852b&chksm=8bc562e7bcb2ebf12807ad3cc8e9c8ea6ebaf26de4671ad684ba15aaa93a350af3e748190118&scene=27#wechat_redirect)

　　内存破坏漏洞是众多攻击（包括APT攻击等）的根源。众所周知的栈溢出漏洞是一类经典的内存破坏漏洞，但是随着DEP、ASLR、Stack Canary、CFG等安全机制在系统中的大范围应用，以及编译器提供的安全检查的默认开启，传统的栈溢出漏洞越来越少见。近几年来，堆相关的漏洞，如堆溢出，逐渐取代栈溢出成为最流行的漏洞类型之一。根据微软2013年的报告\[1\]，针对Windows7的攻击中，25%利用的是堆溢出漏洞。由于发现漏洞既是攻击者攻击的前提，也是防御者修补或者防御的基础。因而如何快速、准确的发掘堆溢出漏洞，一直是攻防双方关注的重点问题。

　　

　　传统的漏洞挖掘，主要基于模糊测试等手段进行。但由于软件自身的复杂性、堆溢出漏洞触发条件的复杂性，以路径覆盖率为导向的模糊测试技术及其他技术（如AddressSanitizer），在挖掘堆溢出漏洞方面有所欠缺。这些技术严重依赖于输入样本去执行有漏洞的程序路径及触发漏洞本身，同时可能遗漏同一路径多个漏洞中的若干个。

　　

　　中国科学院软件研究所软件智能分析协同创新团队，针对这一问题展开了长期研究工作。提出了一个新的基于执行路径离线分析的方案，并构建了一套原型系统HOTracer。该方案通过对代表性的程序动态执行路径进行离线深入分析，深度挖掘路径中可能存在的堆溢出漏洞。具体而言，通过对执行路径中堆相关的操作即分配、释放及访问进行识别，并关联相关的堆分配/访问操作（即分配和访问同一堆对象）；同时跟踪输入对堆操作的影响，对堆溢出漏洞进行建模，找出潜在漏洞；进而构造样本验证潜在的漏洞。其具体工作流程如图1所示。

　　图1 HOTracer总体框架

　　

　　HOTracer具有以下特点：1）漏洞挖掘过程避免了盲目尝试，通过关联相关的堆访问操作，聚焦潜在的漏洞位置，并针对性地发掘漏洞，效率更高；2）挖掘过程不需要输入样本动态触发程序异常，通过离线分析保证了对路径的分析深度和全面性。比如在实验过程中，我们在对Word软件的已知漏洞CVE-2014-1761执行路径深入分析之后，在同一条路径上又发现了另外一个未知的堆溢出漏洞，影响所有版本的Word软件。

　　

　　基于该系统，我们对Word、iTunes、RealPlayer、QQPlayer等常用软件进行了分析，共发现未知漏洞47个，具体统计数据如图2所示。相关漏洞已通报给相关厂商，部分已经得到修复，并获得CVE编号。腾讯公司对我们的发现给予了奖励。

　　目前相关结果已经形成论文\[2\]，并被USENIX Security 2017录用。USENIX Security Symposium是网络与系统安全领域四大顶级会议之一，其2017年共收到稿件522篇，录用85篇，录取比率16.28%。该论文全体作者都是中国科学院软件研究所软件智能分析协同创新团队成员，包括XiangkunJia，Chao Zhang，Purui Su，Yi Yang，Huafeng Huang，Dengguo Feng。其中苏璞睿老师是中国科学院软件研究所软件研究员，协同创新团队的负责人；张超老师是清华大学副教授，协同创新团队的客座研究员。该成果是协同创新团队协作的最新成果。
