二、INDX Entry

结论说完了，再补充扩展一下。有位大神提醒我，上一篇写的与文件时间有关的属性还不全。windows时间规则实验1：修改文件名

我们尝试用Ftk Imager来分析文件，出现了一组4个新的时间戳：INDX Entry  Date  Created/Modified/Accessed/Changed

那么这些时间戳又来自哪里呢？答案就是INDX Entry就来自索引属性。除了用winhex、FTK Imager等分析文件系统，还可以用010editor结合模板来学习和查看文件系统很直观和方便。010editor提供了大量的二进制文件解析模板，

找到关于Drives的部分，下载相应的.bt模板文件。Drive.bt模板可以解析逻辑和物理驱动器，包括MBR, FAT12, FAT16, FAT32, exFAT, HFS, NTFS和扩展分区，确实是非常强大了。

                           

NTFS的MFT由一个个表项构成，每一个表项是一个文件记录，大小一般为1KB(两个扇区，也就是图中的400h)，记录着卷中每一个目录和文件的信息，每个文件记录的结构都是固定的，由文件记录头和若干属性构成。

MFT的第五项是卷的根目录的文件记录，也就是 $Root项。

MFT表中的$ROOT(名字是.)目录的0X90索引根属性，存放着该目录下的子目录和子文件的索引项；当某个目录下的内容比较多，0X90属性无法完全存放时，0XA0属性会指向一个索引区域，这个索引区域包含了该目录下所有剩余内容的索引项。

因为这个例子里面我们的根目录比较大，90属性放不下，就会通过A0属性INDEX_ALLOCATION来指向一个索引区域。

                           

索引区域的地址显示的很明显，就在第36簇，也就是36*8=288扇区。

我们跳转到288扇区看一下是什么


刚好就是根目录索引的记录项了。这和010editor模板显示的NTFS_FILE_INDEX完全一致。通过根目录的文件记录的90属性和A0属性，可以定位根目录下所有内容的索引项，而这些索引项又指向了它自己的文件记录项(MFT中的一项)，该文件记录的90和A0属性又指向了它的子目录的索引项。逻辑上看，这就成了一棵树的样子。

NTFS将INDX记录放置在B +树中，其中的键是文件名。B +树是一种数据结构，其中任意记录由可排序的键值（例如数字或字符串）组成。树中的每个节点可能具有许多分支，这些分支通向其他节点。查找与键值关联的数据归结为遍历节点，并使用键值来决定采用哪个分支。

B +节点的大小是NTFS文件系统规定的，通常为4096字节。这意味着INDX分配属性的大小将始终是4096字节的倍数。在节点内，INDX记录连续排列，相邻记录之间没有空格。由于通常记录少于节点的全部容量，因此最后一个INDX记录与B +树节点的末尾之间通常存在空闲空间。在INDX操作过程中，Microsoft Windows NTFS驱动程序不会重写整个B +树节点。而是，驱动程序仅修改在删除记录之后按字母数字顺序找到的活动INDX记录的地址。因此，Windows不会将闲置空间清零，可能会从该区域恢复INDX记录的旧记录。

INDEX_ALLOCATION属性（A0）属性它有个名字叫$I30

                           

所以FTK imager等软件专门把它叫做$I30文件，而xways等软件并没有专门列出来。其实$I30文件对应的就是INDEX_ALLOCATION的非常驻索引记录。可以注意一下，小文件夹在Ftk imager解析的时候并没有出现$I30文件，原因就是90属性够用，当多放点文件进去的时候再用FTK imager分析，I30文件就出现。

三、$30文件解析

$I30文件的解析还是挺有价值的，一是可以依据INDX文件作为时间戳的来源来开发活动时间线。二是文件空闲空间可能会有一些残留数据。

可以用这个脚本来进行解析https://github.com/williballenthin/INDXParse，脚本用python2.7编写，可以把解析结果导出成csv文件。

工具介绍：

INDX文件是Windows NTFS文件系统的特性。它们可以被看作是B+树中的节点，其中每个目录都有一个INDX文件。INDX文件包含一个目录中每个文件的记录。记录至少包含以下信息:-文件名-文件的物理大小-文件的逻辑大小-修改的时间戳-访问的时间戳-更改的时间戳-创建的时间戳

INDX文件取证调查员感兴趣的原因有很多。首先，研究者可以使用INDX文件作为时间戳的来源来开发活动时间线。其次，这些文件有很大的空闲空间。通过仔细的解析，调查员可以从这些数据块中恢复旧的或删除的记录。换句话说，即使一个文件已经被删除，调查员也可以显示它的存在。INDX文件通常不能从Windows操作系统中访问。像FTK Imager这样的取证工具可以允许用户通过访问原始硬盘来提取文件。FTK将INDX文件命名为“$I30”。像Sleuthkit这样的工具可以从取证图像中提取目录条目。INDXParse只能分析静态镜像。

使用步骤：

首先用FTK imager等工具提取出$I30文件，然后运行脚本

python INDXParse.py -c -d $I30 > INDX.csv

表示将$30文件分析结果存到同目录下的INDX.csv文件中。

要注意，脚本显示中文有问题，需要经过一点修改。在脚本开头加上：

#coding=utf-8

import sys

reload(sys)

import csv

sys.setdefaultencoding('gbk')

然后在提取中文文件名的位置改为：e,e.filename().encode("gbk", "replace")（此处特别感谢李大神）
