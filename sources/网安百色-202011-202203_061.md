# 谷歌警告称，超过 35,000 个 Java 包受 Log4j 漏洞影响

Google 在 Maven 中央存储库中发现了 35,000 多个受 Apache Log4j 库缺陷影响的 Java 包。

![](../Images/dc7beca989940543aa4bc11800678edd.png)

谷歌开源团队扫描了 Maven 中央 Java 包存储库，发现 35,863 个包（总数的 8%）正在使用易受 Log4Shell 漏洞和 CVE-2021-45046 RCE 攻击的 Apache Log4j 库版本。

  

“超过 35,000 个 Java 包，占 Maven 中央存储库（最重要的 Java 包存储库）的 8% 以上，受到最近披露的 log4j 漏洞（1、2）的影响，并在整个软件行业产生了广泛的影响。”阅读谷歌发布的报告。“就存储库影响而言，8% 是巨大的。”

  

Google 专家使用 Open Source Insights（一个用于确定开源依赖项的项目）来评估 Maven 中央存储库中所有工件的所有版本。

  

专家指出，直接依赖项约占受影响包的 7,000 个，大部分受影响的工件与间接依赖项有关。

  

“漏洞在依赖链中越深，修复它所需的步骤就越多。下图显示了受影响的 log4j 包（核心或 api）首次出现在消费者依赖图中的深度的直方图。”阅读“对于超过 80% 的软件包，漏洞深度不止一个级别，其中大多数影响了五个级别（并且一些多达九个级别）。这些包将需要在树的所有部分进行修复，从开始首先从最深的依赖开始。”

  

但自从漏洞被披露以来，所有易受攻击的软件包中有 13% 已被修复（4,620）。

  

在整个生态系统中修复此漏洞需要多长时间？

  

回答这个问题并不容易，专家们分析了修复影响 Maven 包的关键公告中报告的缺陷所花费的时间，并确定只有 48% 的受漏洞影响的工件已得到修复。

  

尽管最近几天急于修复 Log4J，但整个过程可能需要数年时间。

“作为我们调查的一部分，我们汇总了 500 个受影响软件包的列表，其中一些软件包的传递使用率最高。如果您是维护人员或帮助修补工作的用户，优先考虑这些软件包可以最大限度地提高您的影响并疏通更多社区.我们鼓励开源社区通过启用自动依赖更新和添加安全缓解措施来继续加强这些包的安全性。”谷歌总结道。
