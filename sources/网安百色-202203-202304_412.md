# 未修补的 DNS 相关漏洞影响各种 IoT 设备

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzI0NzE4ODk1Mw==&mid=2652091715&idx=2&sn=bb5a1fe009d5d1a10e85028a132dc7ea&chksm=f254c9f5c52340e379caf499df4c4b6344f3b53149b9a46cfce595284e4d0b74c62a412ceebf&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzI0NzE4ODk1Mw==&mid=2652091715&idx=2&sn=bb5a1fe009d5d1a10e85028a132dc7ea&chksm=f254c9f5c52340e379caf499df4c4b6344f3b53149b9a46cfce595284e4d0b74c62a412ceebf&scene=27#wechat_redirect)

    网络安全研究人员披露了一个未修补的安全漏洞，该漏洞可能对物联网产品构成严重风险。该问题最初于2021年9月报告，影响了两个流行的C库uClibc和uClibc-ng的域名系统（DNS）实现，这两个库用于开发嵌入式Linux系统。

    众所周知，uClibc被Linksys，Netgear和Axis等主要供应商以及嵌入式Gentoo等Linux发行版使用，可能会使数百万物联网设备面临安全威胁。“该漏洞是由库生成的DNS请求中包含的交易ID的可预测性引起的，这可能允许攻击者对目标设备进行DNS中毒攻击。

![](../Images/30fba5c596910692478aa128c3053e3e.png)

    DNS 中毒（也称为 DNS 欺骗）是破坏 DNS 解析程序缓存（为其提供与域名关联的 IP 地址）的技术，目的是将用户重定向到恶意网站。uClibc 和 uClibc-ng 中的漏洞是为每个 DNS 查找分配了一个可预测的事务 ID 及其静态使用源端口 53 的结果，从而有效地破坏了源端口随机化保护。

    成功利用该漏洞可以允许攻击者执行中间人（MitM）攻击并破坏DNS缓存，从而有效地将互联网流量重新路由到其控制的服务器。Nozomi Networks警告说，如果将操作系统配置为使用固定或可预测的源端口，则可以以可靠的方式轻松利用该漏洞。

    研究人员说：“攻击者可以窃取和/或操纵用户传输的信息，并对这些设备进行其他攻击以完全破坏它们。”
