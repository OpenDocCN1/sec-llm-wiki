一、什么是Python供应链攻击

向python公共仓库或私有仓库投递精心构造包名且包含恶意代码的python库，在setup.py文件中植入，则安装时会执行恶意代码，在__init__.py或其它文件中植入，则导入、使用库时会执行恶意代码。

二、攻击方式有哪些

python供应链攻击有很多种方式，可以广撒网，当海王，也可以目标专一，精准打击。

1.企业内部私有包抢注


企业内部拥有私有化部署的python仓库，以及内部开发的python库。如果内部python库的名字泄露，攻击者就可以通过在官方仓库注册私有库，对目标企业进行定向攻击。




中招场景





（1）公司员工直接使用pip install internal_package_name的方式从pypi.org安装私有库；

（2）公司员工已配置默认从私有仓库安装，但使用--extra-index-url参数指定额外的仓库。这种情况下pip会同时查找私有库和额外指定的仓库，选择高版本进行安装。

2. 开源项目名称抢注


开源python项目没有及时在官方仓库注册发布项目对应的python包，被攻击者抢先注册。




中招场景





用户安装开源python项目


公开案例：cupy

cupy是一个非常流行的大数据工具库，github star数5k+。cupy每个版本都会发布一个带有版本号的python库，但是cupy-cuda112的python包在官方发布之前，就已经被抢注了。假如cupy-cuda112中包含恶意代码，将会有大量用户中招。
https://github.com/cupy/cupy/issues/4787


3. python库名错误拼写packagename typo


利用用户安装python库时可能输错库名的现象，生成并抢注这些包名




中招场景





（1）用户手动输入pip install xxxx安装python包，比如常见的requests库，结果误输入成request。

（2）python项目批量安装依赖包的方式pip install -r requirements.txt，误输入成pip install requirements.txt，就变成安装名为requirements.txt的python包。（注：目前官方已经禁止上传注册名称类似requirements的包）。

实践案例：批量注册“拼写错误”的python包


前面实践过了精准攻击，这次再来实践下“海王”攻击 ;

 

（1）常用包名收集
想批量进行注册，首先要收集大家常用的包名，这里采用了两种方式去收集。

  • 搜索引擎推荐搜索搜索框输入pip install，搜索引擎就会给你推荐常用的包通过遍历a-z首字母，获取推荐结果，提取python包名

  • HIDS收集pip install命令收集服务器上执行过的pip install命令，提取python包名

 

（2）typo包名生成

有了python包名，该怎么生成“错误拼写”？

这里用了在线Keyword Typo Generator工具：http://tools.seobook.com/spelling/keywords-typos.cgi ，

选择两种类型：缺少某个字母，字母顺序错误。

 

（3）包描述收集

最近上传的包会显示在pypi.org主页上，如果批量上传，而且包描述文字都相同，可能会引起别人的注意。
所以写了个爬虫爬取已有包的描述信息，用于随机填充到要生成的包中，防止批量上传时，pypi.org首页出现大量描述相同的包。

 

（4）信息收集
收集安装“拼写错误”包的人 IP地址、操作系统、用户名三项信息。

 

（5）批量生成包
这次需要生成大量的包，只能自动化，于是就创建了一个包模板，所有的包都基于这个模板生成。
模板目录结构如下：

4. 常见用错的包名


一些知名python包和实际安装的名称不一致




中招场景





比如opencv，导入代码为import cv2，可能就有人尝试pip install opencv或者pip install cv2，实际安装时的包名为opencv-python

beautifulsoup，导入包的代码为import bs4,实际安装包名为beautifulsoup4。

比如注册js、java等其它语言的库

三、官方缓解机制

  1. 检测空包，并删除；

  2. 禁止注册python内置包名；

  3. 禁止注册requirements类似包；

  4. 第三方检测恶意包，并通知官方，官方会将包名加入黑名单，禁止上传包被上传后，世界各地的官方镜像仓库会进行同步，会出现官方仓库将恶意包删除后，镜像仓库仍然存在恶意包的情况。

四、如何防御和检测

  1. 基于内部包名检测官方仓库是否存在相同或相似包名，对于命中包进行分析；

  2. 从正规仓库进行安装，遵循官方包安装文档，检查是否存在输入错误；

  3. 统一使用内部源，发生供应链攻击时，可以迅速删除恶意包，切断传播；

  4. 内部源从官方同步时，沙箱实时检测；

  5. 监测pip进程的网络连接行为。
