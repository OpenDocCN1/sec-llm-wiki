# 常见场景

*   账号登录处
    
*   账号注册处
    
*   密码重置处
    
*   邮箱绑定/修改处
    
*   手机修改/绑定处
    
*   免费试用/活动领取/独特功能/反馈/留言处
    
*   略
    

# 漏洞场景

常见场景，诸如用户注册处、密码找回处，此类功能会存在邮箱验证，也就是说系统会向用户邮箱发送验证邮件，我们可在此处抓包重放，然后到邮箱处查看是否收到了多条邮件。  
![](../Images/8f5b606d6336836b70c107fdeaf902d1.png)

  

  

  

一般来说，此类功能多数会存在频控、验证码等限制，如下面场景：

在正常情况下，发送15条邮件为上限，先前测试用了4条

![](../Images/47bdf5b41a592873d602435f54acfdf8.png)

  

  

  

这里虽然存在限制，但是一个账户可以发送15条邮件，那么只需要换一个账户又可发送15次，此处无其它验证，也可导致大规模的邮箱轰炸。

![](../Images/61958e95f7c21a0d0d70aeb0da02fcdf.png)

  

  

  

但是为了最大化漏洞效果，需要进一步绕过限制

常见的绕过方法：

*   修改IP绕过
    
*   更改cookie绕过（类似场景）
    
*   利用大小写绕过（下面例子）
    
*   利用不同账号绕过（上面例子）
    
*   利用空格绕过限制（短信场景可尝试+号或者+86绕过）
    
*   略
    

经过测试，发现利用大小写可绕过邮箱轰炸限制，随便修改一个字母为大写

![](../Images/177f7453da4cf6fa378d445820a7f8a0.png)

  

  

  

查看邮箱可以发现绕过了限制，现在可以发送到28条，再尝试下是否能发送更多邮件

![](../Images/e96e55352b47ecd282c13b29272137a0.png)

  

  

  

采用intrude重放数据包，现在为234条邮件，到此，成功绕过了限制，扩大了漏洞危害

![](../Images/f7a15ff2b7927a7203ab8e72d041f0a8.png)

  

  

  

注：遇到这类需要重复发包的场景，可以在intrude模块里选择（Null payloads）或者标记User-Agent字段及其它不受影响的字段进行重复发包，如：

![](../Images/261f3afe58dea9066aad13d35fe19465.png)

  

  

  

# 小结

很多时候，在挖掘此类漏洞时，或多或少会遇到各种各样的限制或阻碍，诸如像验证码、频控等；当遇到这类限制时，我们应该冷静下来，从多个方面去思考绕过方式，还是那句话，在挖掘漏洞时，除了技术，还需要灵活的思维和技巧。
