# 【杂志精彩内容推荐】巧用VLAN定位故障

**【导读】在运营商城域网规划和维护中，VLAN起着很重要的作用。不同接入网设备之间可以通过不同的外层VLAN来区分；同一设备不同端口之间也可以通过不同的VLAN划分。这样划分的好处是通过AAA服务器和LCBMS管理系统绑定用户账号，可以减小盗号风险。本文通过灵活使用VLAN技术，为我们介绍了QinQ（也称Stacked VLAN或Double VLAN）的操作应用。**

  

城域网企业用户大致分为两类：一类是互联网专线企业用户，即运营商分配给用户IP地址、子网掩码、网关、DNS主备用地址，以及常用单层VLAN，例如500—699。另外一类是普通ADSL企业用户，运营商分配给用户宽带账号和密码，常用内层VLAN，例如1101—3000。在宽带城域网维护中，常常会遇到机房内存在多台宽带设备，如何快速定位故障用户属于哪台设备，成为一个棘手问题。为此，我们可以巧用VLAN技术来实现故障的定位。

企业用户投诉宽带拨号错误：678，宽带拨号使用PPPoE协议，用户侧ADSL猫与DSLAM设备之间建立PVC通道，而BRAS（宽带远程接入服务器）终止来自DSLAM设备的VLAN信息，如果ADSL猫与BRAS之间通信正常，则AAA服务器将验证用户账号和密码，验证通过后，用户就可以上网了。引起错误：678的主要原因包括：一是用户电脑与ADSL猫相连的端口错插到IPTV端口；二是ADSL猫发生故障；再有就是ADSL猫上联的线路故障；最后，也可能是ADSL猫上联的DSLAM设备层面故障。其中，DSLAM设备层面故障包括：宽带端口、上联网线、上联光纤收发器、光纤收发器对应的光功率、远端光纤收发器对应的卡和卡相连的网线、8908交换机端口、8908交换机端口与卡之间协商模式等。

装维工程师更换宽带端口和ADSL猫，并确认线路是好的，用户电脑网线位置正确，但仍旧出现错误：678的提示。由此，我们判断问题出在DSLAM设备层面。

图1 网络拓扑图

用户所在机房有两台宽带设备，分别为5100 DSLAM和9806H，网络结构如图1所示。我们无法判断归属哪台设备，只有通过逐级查询，才能定位故障设备。且用户宽带账号为589mtz1847，登录互联网综合业务计费和管理系统（LCBMS管理系统）→业务管理→DSL接入业务受理→信息查询。我们在用户账号一栏中输入589mtz1847，看到信息如下：

nasip=X.X.X.X

||

nasportid=slot=4

subslot=2

port=4

VLANid=1112

VLANid2=303

||

其中，“VLANid2”为Qin Q VLAN，我们查看规划表，发现303对应设备为5100 DSLAM，即外层VLAN。并且5100 DSLAM与8908交换机之间通过网线转光纤收发器互联。我们登录8908交换机，在Config模式下输入命令“show VLAN id 303”，可以看到303对应的端口为：fei\_2/48。再输入命令“show interface fei\_2/48”，显示：fei\_2/48 is down，line protocol is down。接着，我们通过输入命令“show run interface fei\_2/48”查看到无Shutdown，且强制全双工模式，端口处于开启状态。重新插拔网线，端口灯闪烁，判断该端口无问题。随机拔掉网线，光纤收发器卡上TXSPD灯闪，闪烁表示百兆模式，没有插网线，TXSPD指示灯应该熄灭。由此，我们通过VLAN技术的应用，判断该卡出现异常。更换卡后，在8908中输入“show interface fei\_2/48”结果显示正常，用户反映业务恢复正常。
