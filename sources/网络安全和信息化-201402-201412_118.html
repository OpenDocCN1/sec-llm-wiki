【导读】作为单位的网络管理员，日常工作中要经常维护一些重要的网络设备，对于核心的设备肯定是要专人管理，但是对于接入层的设备，应该允许基层的工作人员对其进行日常的维护操作。对此，本文详细讲解了定义访问OLT用户权限等级的实操方法，一起来学习下吧。


单位开通了县公司教育网专线业务以后，每个县公司机房都放置了一台OLT设备，为了让县公司的同事尽快的熟悉该设备，进行一些诸如Ping、查看当前设备、查看ONU的在线情况等操作，以达到简化工程排除流程，缩短排除故障的目的。下面以某品牌的OLT为例讲一下配置的步骤。

首先需要说明的是该款OLT共有16个命令行级别，即0—15，其中0—4为参观级，我们可以执行网络诊断工具命令Ping、Clear和查看历史记录命令等；5—10为监控级，可以执行用于系统维护命令，诸如Show一类的命令；11—14级为配置级，可以执行用于配置VLAN、IP和路由等各类业务命令；最高级15级，命名为管理级，用于系统基本运行命令。结合我们刚才遇到的问题，就可以按照这个等级进行设置了。例如初学者可以让他们Ping一下链路状态，查看一下历史命令，那就把级别定到参观级别。对于有更高要求的可以把级别定义到监控级别，使用一些Show命令查看设备各项状态指标。定义级别可以根据实际情况而定，下面就介绍一下具体的配置方法。

例如我们定义一个用户名为“test”密码也为“test”，级别为参观级，进行如下配置：

User name test password test

//创建登录用户名和密码均为test

User name test privilege 4

//配置登录用户名的级别和权限为4即参观级别。

这样使用用户名和密码均为test的用户登录到该设备只有使用一些Ping或者Clear的命令，不能做其它的操作。

使用该用户名登录OLT后，若执行了比4级别较高的命令，例如“show running config”时则会提示“You Need higher priority!”，意思是不能对此进行操作，需要较高级别的权限。

其它等级的命令配置与上面的操作类似。通过级别的划分，可以让不同的用户拥有不同的权限。那么较低级的用户是否能享有较高级别用户的个别权限呢？通过实践验证是可以的，下面就这方面的操作。

实现这个需求的关键点在于对用户级别权限的细化处理。首先我们需要建立一个命令集，然后将15级内的个别或者一部分命令包含进去，然后再进行应用，具体命令如下。

Command-set r1

//创建命令集r1

Command create

//添加“创建VLAN”权限

User name test1 password test1

//创建用户test1

User name test1 pri 10

//定义用户级别为10 级

User test1 allow-exeset r1

// 配置用户test1 在命令集ric1的权限

这样就设置成功了，可以通过命令“show user detail”查看用户级别和命令集使用情况。要想查看刚才配置的命令集r1的中详细信息可以使用“show command-set detail r1”来查看。但是需要注意的是在命令集中增加命令时，即使仅需要添加一条命令，也必须完整输入命令，如果要批量添加命令，则可以输入这些命令中相同的部分。

上面和大家介绍了如何定义用户的级别，以及每个级别对应的权限，然后又更深层次的介绍了用户权限级别的细化处理，如何让较低级别的用户享有较高级别用户的配置权限。这样就可以满足不同用户在各自实际情况下的使用。如果大家单位来了新人，对于刚开始接触网络设备的工作人员，可以使用这个办法来定义他们的权限，既熟悉了设备操作方法，又在最大程度上减少了误操作带来的网络故障。按照这个思路，对于其它的网络设备也可以设置不同操作权限的用户，达到规范网络管理的目的。
