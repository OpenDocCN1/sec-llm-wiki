【实用文章】故障诊断：排除Windows域控复制错误

【导读】我们在工作中经常会遇到一些Windows Server域控制器的复制错误，如果此时没有正确处理，会导致Windows AD域的灾难发生。本人最近遇到两起此类故障，使用Windows自带命令得到解决。


故障一


1.故障现象

原有备份生产域中，一台Windows Server 2003 R2域控服务器使用年限较长，一直没有进行巡检，最近发现网卡故障已有较长时间显示为断开连接。报修更换主板网卡后，发现该备份域控已长时间没有与主域控进行复制，已报如下错误：

“此计算机与命名的源计算机上一次复制的时间间隔太长。与此源的复制间隔时间已超过 tombstone生存时间。与此源的复制已停止。”


2.故障解决

此时信息提示解决方法“如果源DC和目标DC都是Windows Server 2003 DC，则安装包含在安装CD中的支持工具。若要查看要删除但实际上不执行删除操作的对象，请运行“repadmin /removelingeringobjects <源 DC> <目标 DC DSA GUID> <NC> /ADVISORY_MODE”。源DS上的事件日志将枚举所有延迟对象。若要从源域控制器删除延迟对象，请运行“repadmin removelingeringobjects <源 DC> <目标 DC DSA GUID> <NC>”。或者“强制降级或重新安装断开连接的DC。”

此类解决方法要么过于复杂，要么操作有一定难度。在查阅相关资料后发现，可以直接修改注册表后重具体键值如下：在HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\NTDS\Parameters中点击右键，增加DWord值命名为：“Allow Replication With Divergent and Corrupt Partner”，设置键值为1。重启域控后等待几分钟，可以在事件日志中查看到域控复制已正常。此时故障已排除。


故障二

现有生产域为Windows Server 2008 R2，最近在做域控的迁移工作，将一台备份域从物理机迁移至虚拟机中。虚拟备域控已搭建完毕，需要将物理机中域控进行删除。在删除过程中，网络管理员重启了所连交换机，导致域控删除异常发出报错信息。


1.故障现象

重启后，发现不能正常降级，备份域控已无法连接到主域中，无法使用命令DCpromo进行正常的域控降级为普通服务器，提示无法连接其他域控无法删除域信息。在“AD域用用户和计算机”的操作主机各操作主机选项卡中，已无法找到相应的主机显示错误主机。

如果强行在“AD域用用户和计算机”删除域控主机，会导致在NTDS中的不少域控信息键值无法全部清空，各域控主机中会提示相应的域控复制错误信息，如以后以相同服务器主机名加入会报错。


2.解决方法

使用Windows Server自带命令repadmin /showrepl以确定是否存在复制问题，如确定有问题无法正常进行域控制器之间的复制，可以通过以顾问模式运行命令repadmin /remove lingeringobjects来实现域控制器之间的复制。如果操作系统是Windows Server 2003，需要安装Windows Server 2003支持工具“\Support\Tools\Suptools.msi”。

使用该命令后，域控制之间的复制恢复了正常，操作主机中找到了主域控，可以使用DCpromo正常降级故障排除。


经验总结

在发生此类故障时，大家还是要小心谨慎，对域控主机的操作要三思而后行，尽可能不要强制删除和手动修改NTDS键值，域控主机也要经常巡检。以上方法对出现微软事件Id：2402、1988故障有一定的参考价值。
