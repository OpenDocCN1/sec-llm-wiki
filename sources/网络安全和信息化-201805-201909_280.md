# 安全基线与校园网络安全管理

> **网络安全问题溯源**

  

据有关资料统计，网络安全事件中约有80%源自计算机终端问题。终端已成为新的安全边界，终端安全问题已成为全球计算机用户所面临的新挑战。而由于各业务系统使用的开发技术及建立的时间不同，缺乏统一的安全标准和配置规范，使服务器的管理存在安全隐患。信息系统、设备自身配置的脆弱性，是安全事件发生的重要原因之一。

  

安全需要在安全风险和成本付出之间进行平衡，而安全基线就是这个平衡点。不满足系统最基本的安全需求, 也就无法承受由此带来的安全风险, 而非基本安全需求的满足同样会带来超额安全成本的付出, 所以构造信息系统安全基线己经成为系统安全工程的首要步骤, 同时也是进行安全评估、解决信息系统安全性问题的先决条件。

  

> **安全基线的提出与实施**

  

安全基线（Secruity Baseline）是最基本的安全要求，好比是安全“木桶理论”的最短板，对于一个信息系统来说是最小安全保证，即该信息系统最需要满足的基本安全要求。安全基线由安全配置的概念逐渐演变进化而来，源于微软公司早期为美国空军建议的Windows XP 和Windows Vista操作系统安全配置方案，即标准桌面配置方案（Standard Desktop Configuration，SDC）。2007年，美国政府启动联邦桌面核心配置项目（FDCC，Federal Desktop Core Configuration），建立桌面系统（Windows XP、Windows vista等）相关安全基线要求规范，并通过自动化的工具进行基线检查，并明确规定，所有使用Windows操作系统的计算机，必须符合FDCC的配置要求。

  

FDCC 作为联邦政府所有桌面计算机的安全配置标准，已经成为美国国家网络安全综合计划（CNCI）的重要组成部分。FDCC的提出为终端安全提供了可参考的标准，具有指导意义。通过实施 FDCC，美国在整个桌面系统中提高一致性，从而起到简化部署和简化网络管理和工具的复杂性的作用；减小了标准用户的管理权限，增强了桌面系统安全性。通过标准化又降低了运维成本，减少了信息技术支持人员数量，缩短系统更新的测试和安装时间。安全配置的统一化和标准化，有利于信息安全策略的整体部署和提高防范措施的实施效率。

  

除美国政府机构强制使用的安全基线之外，微软的安全基线方案约有15 种，涵盖 5 类不同的微软产品：

  

1）WindowsXP SP3、Windows Vista SP2、Windows 7 SP1、Windows 8；

  

2）WindowsServer 2003 SP2、Windows Server 2008 R2 SP1、Windows Server 2008 SP2、Windows Server 2012；

  

3）Office2007 SP2、Office 2010 SP1；

  

4）IE8、IE 9、IE 11；

  

5）Exchange Server 2007 SP3、Exchange Server 2010 SP2。

  

OWASP 基金会的开放式Web应用程序安全项目目标是推动全球软件安全的革新与发展，其安全基线子项目进行了多种操作系统、网络设备、应用软件、数据库、移动设备的安全配置的研究，形成了一系列的安全基线、安全检查清单、安全加固指导等技术资料及工具。具体包括15种操作系统安全基线、4种虚拟软件安全基线，12种中间件、应用软件安全基线、6种数据库安全基线、4种网络设备安全基线、3种移动设备安全基线。

  

我国国家信息中心于2008年提出了“政务终端安全核心配置”(CGDCC) ，最终目标是实现全国政府办公网络终端安全防护系统的统一规划、统一管理，并为政务终端提供统一的安全策略配置、检测的补丁分发、实时的安全状态监测等终端安全护理服务。对网络安全要求较高的金融行业、通信运营商也纷纷采取了全方位的网络安全管理措施，包括发布相关的安全基线规范，用以构建最基本的安全防范壁垒与手段。

  

完整的安全基线内容主要由系统存在的安全漏洞、系统配置的脆弱性、系统状态的监控三方面必须满足的最低要求组成。

  

1、安全漏洞：漏洞通常是由于软件或协议等系统自身存在缺陷引起的安全风险，如系统登录漏洞、拒绝服务漏洞、缓冲区溢出、信息泄漏、蠕虫后门、恶意代码执行等，反映了系统自身的安全脆弱性；

  

2、安全配置：通常都是由于人为的疏忽造成，主要包括了账号、口令、授权、日志、IP协议等方面的配置要求，配置不当导致系统存在安全风险；

  

3、系统状态：包含系统端口状态、进程、账号、服务以及重要文件的变化。这些信息反映了系统当前所处环境的动态安全状况，存在的安全隐患将威胁系统运行安全。

  

安全基线通过安全合规管理机制判断用户的应用环境安全是否达标，提供一个信息系统所需的最基本的安全保证。FDCC基于NVD、NCP等内容进行基线安全核查。NVD（National Vulnerability Database，国家漏洞数据库）为自动化漏洞管理、安全评估和合规性检查提供数据支撑，包含安全核查名单、与安全相关的软件漏洞、配置错误以及量化影响等。NVD数据库针对数据库中的漏洞等提出了一整套核查名单（Checklist），划归到NCP（National Checklist Program）计划中。

  

> **安全基线应用于校园网络安全管理**

  

随着校园网络信息化的快速发展，网络基础设施、网络信息服务设施、信息应用系统、用户接入终端数量和规模都在不断扩张，使网络安全管理工作量陡增，需要增加网络安全设备和专业技术人员，管理成本逐步上升。如何实现增强管理力度、提高管理效率已成为高校面临的重要问题。而安全基线标准的建立，可强化管理依据，规范管理方法。

  

因此，全面构建网络信息安全基线标准体系，形成长效安全检查机制，是保障校园网络信息安全的基础措施。根据校园网等保定级的情况对服务器、应用系统、数据库及网络设备等分类建立标准安全配置规范，形成校园网安全基线，并制定针对不同系统设备的详细检查项目和核查方法，开展横向的安全评估和管理。

安全基线标准的制定可参考微软以及金融、通信行业的相关安全基线规范，还应结合网络安全等级保护对物理安全、网络安全、主机安全、应用安全、数据安全的技术与管理要求，详细编写基线内容说明，并配套设置操作具体步骤和合规性检查的依据。

  

具体来说，安全基线标准内容应包括：安全基线名称、基线编号、基线说明、设置操作步骤、符合性判定依据及备注六项内容（见图1）。以Windows操作系统配置安全基线标准为例，总体包含的内容主要有：账户管理、认证授权（系统账户控制、密码安全策略、操作授权）；日志配置操作（日志审核内容、日志文件大小）；IP协议安全配置（SYN、ICMP、SNMP攻击保护，IP路由控制，碎片攻击保护）；其他安全功能要求（共享访问权限、恶意代码与病毒防护、终端服务管理、网络访问授权、启动项、系统服务管理）；系统更新（补丁更新）。

  

*图1 安全基线标准内容样例*

| 安全基线名称 || 操作系统缺省账户安全基线要求项 |
| --- | --- |
| 安全基线编号 || SBL-Windows-V01-02-01-01 |
| 安全基线说明 || 对于管理员帐号，要求更改缺省帐户名称；禁用guest（来宾）帐号。 |
| 设置操作步骤 || 进入“控制面板-> 管理工具-> 计算机管理” ，在“系统工具->本地用户和组”：缺省帐户Administrator －>重命名Guest  帐号-> 属性->勾选“账户已禁用” |
| 基线符合性判定依据 || 缺省账户Administrator名称已更改。Guest 帐号已停用。 |
| 备注 || 应删除或锁定与系统运行、维护等工作无关的账户。 |

 

安全基线的检查工具种类比较多，有商业化的工具设备，开源的工具软件以及根据具体使用需要开发的检测脚本程序、自动化扫描程序等。

  

微软基线安全分析器（MBSA）是微软公司为IT专业人员设计的一个简单易用的免费工具，可以检测Windows系统常见的安全性错误配置和遗漏的安全更新，改善安全管理流程。
