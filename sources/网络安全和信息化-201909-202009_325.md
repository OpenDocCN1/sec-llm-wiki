# Windows Server 2008官方支持结束，企业如何应对？

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MjM5MzMwMDU5NQ==&mid=2649141931&idx=1&sn=7ef673a19f17c86d736c1de74f03b30e&chksm=be8b3bb789fcb2a1a9552c607bab762162aedcd0ee5b48588bb5dd504ef8e04cbb1aec0ddbfe&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MjM5MzMwMDU5NQ==&mid=2649141931&idx=1&sn=7ef673a19f17c86d736c1de74f03b30e&chksm=be8b3bb789fcb2a1a9552c607bab762162aedcd0ee5b48588bb5dd504ef8e04cbb1aec0ddbfe&scene=27#wechat_redirect)

微软建议将Server 2008工作负载迁移到Azure云服务上，与此同时，企业应为Windows Server 2016或2019部署升级其应用程序。

  

![](../Images/8cd9ac6b2725d269d453e099514c9be7.png)

  

本周的 “补丁星期二”标志着Windows 7和Windows Server 2008（以及2008 R2）的生产线结束。除非您购买了昂贵的扩展服务许可证，否则不会为这两个旧的操作系统发布任何修复程序。

  

在Windows 7方面，微软在积极地（也许是过于频繁地）升级程序来部署Windows 10这一方面做得很好。根据StatCounter的数据，Windows 10现在占全球Windows桌面市场份额的65％，而Windows 7下降到27％。

  

但是，尽管Windows 7受到很多关注，但Server 2008实际上在某些方面，其生命周期和关键里程碑更为重要。在去年7月的Inspire展会上，微软高管在接受云存储提供商和微软合作伙伴Carbonite的采访时表示，现在60%安装了Windows Server的用户正在运行Server 2008，大概有2400万个实例。

  

“有很多客户坚持使用Server 2008，”研究咨询公司AVOA的分析师Tim Crawford表示， “这一人群可以分成两类：第一类，需要使用WS2008的一些特定功能；第二类，使用应用程序的版本仅与WS2008兼容。升级通常说起来容易做起来难。特别是当使用的应用程序已经成一种习惯并相互关联的时候。”

  

Server 2008是基于Windows Vista代码库，这也是可以单独放弃它的原因。但是Windows Server 2016和Windows Server 2019是部署在Windows 10上的，所以对OS生态系统严重依赖。由于这种内部结构的不同，因此，Server 2016和Server 2019很难移动。

  

“我的一些同事仍在使用Windows Server 2008，他们了解支持EOL的后果。但是大多数人都有各种不能够迁移应用程序的缘由，比如应用程序兼容性、位置等，对于这种情况他们也很困惑。” Crawford表示。

  

对于那些难以移动的应用程序，Crawford建议尽可能多地与系统进行隔离，从而保护这些程序。同时要制定迁移计划，让重要的应用程序尽可能快地迁移走。

  

微软提供并推荐了使用Azure迁移，因此Server 2008应用程序在升级至Server 2019可兼容的版本后，可以放到Azure中运行，再在企业内部署。

  

迁移应该是企业首要的工作，因为如果您正在运行Server 2008，那么相配套的硬件至少已使用了八年，甚至已经使用了十二年。从技术上讲，这是很古老的。即使没有其他问题，未来硬件也可能发生故障。

  

令管理员们头疼的一个问题是不能将Server 2008直接迁移到2016或2019版。您必须升级到Server 2012作为中间步骤。所以，您最好是能想办法将应用程序一次性迁移到2019版，而不要浪费时间在系统上迁移两次。

  

微软已经为Server 2008用户提供了相关资源，包括迁移向导，帮助用户顺利迁移到Azure上。
