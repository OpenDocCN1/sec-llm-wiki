# 警惕API风险，即使再完美的API也可能被滥用

在 API（应用编程接口） 安全领域，“攻击”和“漏洞”可谓是常用词。如今针对API的威胁呈现出爆炸式增长的趋势。  

 

Akamai公司统计数据显示，在针对金融服务业发起的撞库攻击中，高达75%的攻击直接以API为目标。Salt Security公司的一份报告发现，其客户遭遇的API攻击流量在过去一年中增长了681%，与此同时，整体API流量增长了321%。相对于传统Web应用，攻击API的成本更低、价值更高。Gartner 也表示，到 2022 年， API将成为最常见的在线攻击媒介。

 

实际上，即使是非常成熟的 API 用户也面临最紧迫的形势。业界现有的 API 安全框架和指南在很大程度上没有很好地解决安全问题。例如当前API授权认证体系已经比较完善，但是在授权之后访问的控制相对薄弱。

**并非所有的API攻击都会利用漏洞**

传统的应用程序安全漏洞，例如在OWASP API Top 10中逐项列出的漏洞，其被定义为API在实现、部署或配置中的缺陷。软件开发生命周期 （SDLC）已经非常关注扫描代码和运行动态分析，以便及早发现API漏洞。

 

常见的攻击是通过漏洞利用的方式进行，但如果攻击者使用的是合法凭据，那么即使是设计完美的 API 也可能存在被滥用的可能。

 

API被设计的目的是将核心业务逻辑和敏感数据暴露给外部连接。许多成功的攻击通过隐藏在合法授权流量中，从而绕开了针对API安全的检测，这是API攻击难以被发现的一个非常重要的原因。

 

如今，API滥用是风险最高的攻击，这些攻击的危害远远超出了漏洞利用。API 滥用可能包括：

 

*   出于恶意原因以未经允许的方式使用API。在这一情况下，API是按设计要求使用的，但被错误的人或出于错误的原因所使用，例如数据抓取。
    
*   利用应用程序逻辑中的漏洞。这些API滥用行为存在于特定业务，并且在许多情况下，并没有通过众所周知的OWASP框架解决。
    

  

API滥用问题值得API开发人员和产品经理反思，为什么这些API功能没有按原有被创建时的路径发展，以致于被攻击者利用。

 

**API滥用问题有多大？**

API滥用是一个非常严重的问题。有些企业可能会认为他们的API已经过漏洞评估，是安全的，但这一想法是片面的。也有些企业会认为已经部署了API网关或WAF来保护API。但即使API程序编写得“完美无缺”，它们也可能以一些意想不到的方式被滥用，从而暴露企业的核心业务功能和数据。

 

整体来看，API所面临的风险包括：凭据失陷、越权访问、数据篡改、违规爬取、数据泄露等诸多安全风险。

 

2018 年震惊世界的 Facebook数据泄露事件从某些方面反映出API安全的某些缺陷，包括技术或管理方面。该事件中，Cambridge Analytica (CA) 利用 Facebook 的开放 API 收集了有关至少 8700 万用户的大量数据，就通过使用 Facebook 测验应用程序实现的，该应用程序利用了允许第三方应用程序收集有关测验者的各类个人隐私信息。

 

这一事件并不涉及利用Facebook API 基础设施中的程序漏洞，但最终造成API被滥用。

 

**对企业的影响**

随着企业越来越多地通过 API 将其宝贵的数字资产提供给合作伙伴及用户，发生API滥用的情况也在大大增加。例如我们现在每天使用的网上交易、财务应用和服务，API在其中发挥了重要的作用。开发的每个API都是企业业务的一个窗口，都存在API被滥用的可能。

 

除了用户隐私风险外，API滥用问题还可能对企业业务产生毁灭性影响。几乎所有行业都存在类似的风险，因为我们日常的B2C和B2B的商务活动大部分都是通过API在线进行的。

 

**应对API滥用问题**

现有的最佳实践和资源（如 OWASP API Top 10）为安全专业人员提供了解决路线图。但企业需要将消除API基础设施漏洞视为起点，而不是唯一点，更不是终点。制定阻止API滥用的安全策略将是赢得API安全的有效方式。

**从API攻击的本质入手**

在其他安全领域，有两种不同类型的框架：

  

*   发现、记录和修复漏洞的系统方法（例如MITRE CVE）。
    
*   建立已知攻击技术的知识库（例如MITRE ATT&CK）。
    

  

在API安全领域，OWASP API Top 10提供了一个着手点。但要将列表中的每个广泛漏洞类型分解为API团队重点关注的细分领域，还有更多工作要做。可以说，OWASP API Top 10是主动应对API基础设施漏洞的绝佳蓝图。

**大幅增加分析API数据量**

许多早期的API安全工作都集中在监控单个API调用，或者充其量是短期会话活动。但这对于现在来说已远远不够。对单个请求或会话的评估，无法真正理解正常或非法滥用行为及其背景。许多合法的业务流程发生在几分钟、几小时乃至几天的时间范围内，而许多攻击也是如此。因此，API监控和分析方法必须得到改进，以分析涵盖这些延长时间段的数据集。

 

盲点是许多API安全的另一个致命弱点。API监控和分析不能仅限于安全团队所明确的应用程序，而且还要包含那些平时不被注意的API，即影子API，以防止被攻击者趁机而入。

 

为应对以上短板，云计算是一个有效且关键的因素。云提供了从最广泛的来源（包括 API 网关、网络设备、微服务编排解决方案和云提供商）收集详细数据所需可扩展的存储，还提供了对这些数据集执行现代行为分析和AI所需的计算能力。当然，也应辩证地看待云API场景，其中的安全问题同样也不可忽视。

**使用AI创建安全工具**

以攻击者视角思考安全问题，进而改善防护弱点，是一个很有效的方法，但很多时候执行起来也是很困难的。大量的人类智能和自动化正被用于各种攻击中，包括API攻击和滥用。企业能做的是为发现、检测和缓解API威胁带来更多资源和创造力。

 

AI是其中的关键。即使是安全专家也永远无法预测攻击者会使用哪种API攻击方式。但企业可以为API的使用和活动设置正常基准。接下来，可以通过AI来更好地了解使用API的实体，监测其行为是否合规。毕竟传统的应用安全方法并不是为了查看API滥用而构建的。
