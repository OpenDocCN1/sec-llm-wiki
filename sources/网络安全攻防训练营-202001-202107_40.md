简单记录：*是ctfshow里的web入门的题，记几个知识点。*  

## web19

题目描述：密钥什么的，就不要放在前端了 打开题目是登录框，第一想法是去尝试了万能密码。但是没有成功。然后才回过头看题目描述是前端有密钥。所以就看源代码。![](../Images/9707d6d098012a879296969a756ccb66.png)上面是加密方法，百度发现是前端AES加密。它会将用户输入的密码字符串进行加密。两种可行方法，第一种是解密，先百度，然后这样这样，再那样那样就解出来了。(没有使用这种)。第二种是抓包修改，绕过前端验证。将密钥修改为 `$p`的字符串。发包得到flag![](../Images/f7173698a2a69d55667fe8b6d416a5f3.png)

## web 7、8

题目描述：版本控制很重要，但不要部署到生产环境更重要。版本信息部署到生产环境，两道题分别考察git泄露和svn泄露。这是简单的题，不用工具。CTFHUB的技能树也有几个这样的题，是需要用到工具的，用时参考—https://blog.csdn.net/qq\_45836474/article/details/107767955#t3

## web9

vim编辑器使用的扩展知识。当我们在使用vim编辑的时候，vim会在被编辑文件同一目录下，创建一个名为filename.swp的文件，记录我们的动作。编辑文件时，非正常退出编辑，就会生成一个这样的文件。再次执行编辑命令就会发现，![](../Images/f9905a0efb59c4e94a9780d599443859.png)而且每次打开都是这样的，这个文件是个隐藏文件，使用 `ls-all`可以看到![](../Images/577e85dc6d7506a0d6a72a0c7fd63471.png)

## web11

域名隐藏信息，解析记录的txt中有隐藏信息。![](../Images/3853dc60490d2569f952439144d6100c.png)

## web13

在源码中发现PDF，![](../Images/39c6633fcaac6e32c6561bc72de501ce.png)访问能看到登录地址，管理员账号密码

## web14(标记)

题目描述：有时候源码里面就能不经意间泄露重要(editor)的信息,默认配置害死人 提示这么明显了，打开直接看源码了，里面找editor关键字。![](../Images/780d6e0e12c4bee08db658d458789237.png)摸索一阵，发现editor中有东西![](../Images/94ae19c21ed9c321ee7d6b5c20e02017.png)然后点击第二行倒数第十个图标，![](../Images/5c7f72cdac2f516e91909c7db7af9e3a.png)可以遍历到所有目录，找一遍，在 `/tmp/html/nothinghere/fl000g.txt`发现了这个文件。访问 `nothinghere/fl000g.txt`得到flag

## api调用(XXE)

一开始没有管题目，看到题，就尝试了命令执行，但是返回的是这样的。![](../Images/88019513ab31df527fa0947b262d285b.png)这里回显不管写什么命令，都是在后面补上own，所以命令执行可能无从下手，所以就有看看题目了。api调用是没了解过的，然后呢就有些懵，源码没有信息，也不知道改从哪里下手，做题web题，没有头绪就抓个包看看。然后发现![](../Images/d7a271e58817bc88a9134a6814f88f0c.png)有点奇怪，还是直接burp抓包看看。![](../Images/f28e2b45bb1a2930be02574b766324a4.png)看起来好像XXE的样子。跟之前打的靶场挺像的，就回头查了查博客，果然很相似，所以就使用现成的payload进行读取文件。先尝试有回显的

```
6.  
    
7.  `<user><username>&hacker;</username><password>m0re</password></user>`
    
```

## hello\_misc

每次做一道misc题都是满满的脑洞。奇怪的知识又增加了。看这个，一张图片，一个压缩包。压缩包加密，里面放的关于flag的压缩包，根据经验，一般是先分析图片，然后再进行压缩包解密。不过起初没办法的时候，都进行尝试了，暴力破解等手段。不过没有线索。正确思路应该是这样的，首先010editor查看。发现了有个out.txt![](../Images/7886776df9fcdf2d04b11452a1aaaaa1.png)然后选择分离图片，得到了压缩包![](../Images/f5e6887c36697e1797f2455056ce66c2.png)查看没有伪加密，也不是弱口令(暴力破解需要一年以上) 所以必定是在图片中还有压缩包的密码，看图片的样子，很像是平时做题的时候RGB隐写时显示的样子，使用stegsolve进行解题，![](../Images/851f15669d77d8c0aa047c402000a104.png)红色最低位，一张图片，将其保存为png图片。看到了内容![](../Images/a87172a09ee4ed1757f2576c68d3d645.png)压缩包密码也有了 `!@#$%67*()-+`文件里就是这样的一堆数字，看着挺熟悉的，之前见过、![](../Images/efe701390e9b6becdaa786a6df86ba8d.png)与之类似的题—\[SWPU2019\]Network然后就使用脚本，进行批量转换，贴个大佬的脚本

```
1.  `with open('out.txt') as a_file:`
    
2.  `    content = [x.strip() for x in a_file.readlines()]`
    
3.  `bins = []`
    
4.  `for i in content:`
    
5.  `    bins.append(bin(int(i))[2:].zfill(8)[:2])`
    
6.  `stringBins = ''.join(bins)`
    
7.  `num = 0`
    
8.  `flag = ''`
    
9.  `for i in range(int(len(stringBins)/8)):`
    
10.  `    flag+=chr(int(stringBins[num:num+8],2))`
     
11.  `    num+=8`
     
12.  
     
13.  `print(flag)`
     
```

![](../Images/f67d40c2fe17dc5989bf1e8e2749f669.png)得到了rar压缩包的密码，套路是没有什么变化的。解压得到fffflag.zip，但是解压拿到的是一堆文件，所以先使用file命令查看一下这个压缩包的文件类型。发现是word文档。![](../Images/a96f030a34279044c0efceb2da13f912.png)改下后缀，查看文档。![](../Images/fbf5543963bba5565902d50184afda96.png)复制到记事本中看![](../Images/855cb9af38e976d06ef510ca8414a432.png)看了wp，是base64编码，这个还真的看不出来、菜。![](../Images/3a1fa76052b586dad0c45c4d8db161db.png)然后看0和1的分布![](../Images/479bf07d64839c2ed218072fe2d32982.png)所以flag是 `He1Lo_mi5c~`

## swp

题目来源：BUUCTF\[ACTF新生赛2020\]swp 下载得到tar压缩包，所以在kali中进行解题。![](../Images/f700918d3bdb95ca647d1de990d61244.png)最后得到一个流量包，打开wireshark分析查看，随手翻了一下，看到有http请求。于是尝试导出http对象，看到好多文件，还看到了 `hint.html`和一个压缩包。于是先导出来再说。![](../Images/75dd69875fa243a7f4393c0c0bb2c48d.png)压缩包加密了，所以再拉到windows中打开， 对了，还有hint，先查看hint，![](../Images/b39c03becc749ccac0a7fce4eb5156c6.png)不需要密码，说明压缩包要么是简单爆破得到，要么是伪加密。打开却看到是这样的。![](../Images/4ff8b21eb6df942c28c3b673aae5fef9.png)明白了为什么不用密码了，直接打开flag.swp文件就可以了。就能找到flag![](../Images/0cffd8c2387313d16d0bd9a022d7b3ae.png)swp文件在linux系统中是隐藏文件，是看不到的，但是在windows系统中是可以看到的，这里直接用记事本打开就可以。扩展：一般隐藏文件使用 `ls`命令查看![](../Images/08d1785fc9b7b221abdcfb4b4cac637d.png)
