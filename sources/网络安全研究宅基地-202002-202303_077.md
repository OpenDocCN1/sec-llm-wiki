## 前言

Windows TCP/IP 处理程序运行在 内核层 驱动文件名为 TCPIP.sys

该漏洞主要为 TCP/IP 堆栈处理 0x19 递归DNS服务器选项时对长度字段为偶数的ICMPv6的IPv6路由广播数据包时,处理逻辑存在漏洞 因此可以绕过安全检查 导致堆栈溢出 通过”精心”构造的代码可以在目标主机上执行任意代码

本文专注漏洞分析 篇幅原因所以并不过多描述 IPv6 协议等细节 详情请自行查询RFC文档等

IDA 静态分析:

其中 该函数存在两个 Switch 循环 第一个 Switch 循环为验证 Packet结构是否正确的 读取 长度 以及 Type进行验证 此处是导致漏洞的主要成因

如果Length是偶数 设置为 4 则 第一次验证完成后 会读取 偏移 +32 字节的内容,

![](../Images/a323561f8b1eed7353187e273f30d69e.png)

  

也就是说 他将我们特殊设置的 DNS 地址 当成了 第二个IPv6 Options的属性 我们只需要设置一个合理的属性 即可绕过他的安全检测 实现调用列表里的任意功能

```
1.  `case 0x19:`
    
2.  `        if ( *(_BYTE *)(v12 + 0x194) < 0 && (RDNSS_Header_Length < 0x18u)`
    
3.  `          *v8 = 0x19;`
    
4.  `        break;`
    
```

我们只需要设置报文让 Length \* 8 > 0x18 即可

“\\x03\\xcc\\xb2\\xb3\\xb4\\xb5\\xb6\\xb7\\x19\\xCC\\x00\\x00\\xbc\\xbd\\xbe\\xbf”

此处笔者设置为 0xCC 为下面 栈溢出埋下伏笔

![](../Images/257d75adf3e0949a5c6af6f9a4980ffa.png)

接着通过实现功能的 Switch 循环 我们调用到了 TcpIP!Ipv6pUpdateRDNSS 函数,该函数在计算 IPv6 DNS Server 地址时 会使用我们精心设计的 Length 经过错误的计算 让Address字段中的 DNS Server地址 的数量存在偏差 使得 NdisGetDataBuffer 函数中 NET\_BUFFER 结构 偏移不正确,导致读取了错误的内存

此处Length设置为 0x04 根据该算法 得出的值为 0x01 也就是说 他认为只存在一组DNS Server 地址 下面循环只处理一次

tcpip!Ipv6pUpdateRDNSS

此处 DataOffSet +=8 指向 RDNSS\_Option.Address
