漏洞信息：https://cwiki.apache.org/confluence/display/WW/S2-016

在struts2中，DefaultActionMapper 类支持以 action:、redirect:、redirectAction: 作为导航或是重定向前缀，但是这些前缀后面同时可以跟OGNL表达式，由于struts2没有对这些前缀做过滤，可以执行任意OGNL表达式。

漏洞复现

影响范围

Struts 2.0.0 - 2.3.15

漏洞分析

在使用 struts2 的时候要在 web.xml 中配置一个过滤器，来拦截用户发起的请求，并进行一些预处理，根据配置文件把请求分配给对应的 action 。FilterDispatcher 是早期struts2的过滤器， StrutsPrepareAndExecuteFilter 自2.1.3开始就替代了FilterDispatcher 。

当服务器启动时会调用 StrutsPrepareAndExecuteFilte.init() 来进行一些初始化，当有请求发送到服务器时，StrutsPrepareAndExecuteFilte 的 doFilter() 方法被调用进行 ActionContext 创建、 request 的封装等操作，并将请求信息转发给 ActionMapper，由 ActionMapper 检测这个信息是否需要Struts2进行处理，ActionMapper 会返回一个存储有 Action 配置信息的 ActionMapping 对象给 StrutsPrepareAndExecuteFilte。

漏洞出现在 org.apache.struts2.dispatcher.mapper.DefaultActionMapper 类中，它是 ActionMapper 的实现类。在 StrutsPrepareAndExecuteFilter.doFilter 方法中下断点，跟进 this.prepare.findActionMapping 方法。

首先从 request 对象中获取 mapping 对象，看是否存在，不存在就创建 ActionMapper 对象，并调用其 getMapping 方法。

获得请求的uri，删除uri ; 后面的字符串，删除 .action 或者 .do 扩展名，this.parseNameAndNamespace(uri, mapping, configManager); 从uri中分离得到请求的 action 名、命名空间，并set给 mapping 对象，然后跟进用于处理特殊参数的方法 this.handleSpecialParameters(request, mapping);

获取url中的参数，迭代处理所有参数名，其中 ParameterAction parameterAction = (ParameterAction)this.prefixTrie.get(key); 会根据不同的特殊参数名前缀返回对应的 ParameterAction 对象，然后 parameterAction.execute(key, mapping); 会调用对应的 execute 方法处理。

DefaultActionMapper 的构造函数针对不同的特殊参数名前缀put了对应的 execute 处理函数。这里我们调用的是 redirect: 对应的 execute 函数。

  1. public DefaultActionMapper() {
  2.     this.prefixTrie = new PrefixTrie() {
  3.         {
  4.             this.put("method:", new ParameterAction() {
  5.                 public void execute(String key, ActionMapping mapping) {
  6.                     if (DefaultActionMapper.this.allowDynamicMethodCalls) {
  7.                         mapping.setMethod(key.substring("method:".length()));
  8.                     }

  10.                 }
  11.             });
  12.             this.put("action:", new ParameterAction() {
  13.                 public void execute(String key, ActionMapping mapping) {
  14.                     String name = key.substring("action:".length());
  15.                     if (DefaultActionMapper.this.allowDynamicMethodCalls) {
  16.                         int bang = name.indexOf(33);
  17.                         if (bang != -1) {
  18.                             String method = name.substring(bang + 1);
  19.                             mapping.setMethod(method);
  20.                             name = name.substring(0, bang);
  21.                         }
  22.                     }

  24.                     mapping.setName(name);
  25.                 }
  26.             });
  27.             this.put("redirect:", new ParameterAction() {
  28.                 public void execute(String key, ActionMapping mapping) {
  29.                     ServletRedirectResult redirect = new ServletRedirectResult();
  30.                     DefaultActionMapper.this.container.inject(redirect);
  31.                     redirect.setLocation(key.substring("redirect:".length()));
  32.                     mapping.setResult(redirect);
  33.                 }
  34.             });
  35.             this.put("redirectAction:", new ParameterAction() {
  36.                 public void execute(String key, ActionMapping mapping) {
  37.                     String location = key.substring("redirectAction:".length());
  38.                     ServletRedirectResult redirect = new ServletRedirectResult();
  39.                     DefaultActionMapper.this.container.inject(redirect);
  40.                     String extension = DefaultActionMapper.this.getDefaultExtension();
  41.                     if (extension != null && extension.length() > 0) {
  42.                         location = location + "." + extension;
  43.                     }

  45.                     redirect.setLocation(location);
  46.                     mapping.setResult(redirect);
  47.                 }
  48.             });
  49.         }
  50.     };
  51. }

可以看到这里会创建一个 ServletRedirectResult 对象，然后把我们的参数设置为其 Location 属性，并set给mapping 对象的 result 属性，这里类似S2-012中的配置

<result name="redirect" type="redirect">/index.jsp?redirect=${redirect}</result>

之后还是和 S2-012 的流程一样，在计算重定向值 this.lastFinalLocation 时，会调用 TextParseUtil.translateVariables 对我们上面赋值的 Location 属性中的 ${}、%{} 进行 OGNL 表达式解析，从而造成任意代码执行。

漏洞修复

删除了 DefaultActionMapper 中对特殊参数名前缀 redirect: 和 redirectAction 的处理，只留下了 action: 和method: 两种无害的写法。由于在修复 S2-015 时对添加了正则 allowedActionNames 对 ActionName 进行过滤，因此使用 DefaultActionMapper.this.cleanupActionName(name) 对参数名前缀 action: 进行修复，该方法会使用 allowedActionNames 对 ActionName 进行正则过滤。
