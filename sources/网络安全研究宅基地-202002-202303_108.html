漏洞信息：https://cwiki.apache.org/confluence/display/WW/S2-012

如果在配置 Action 中的 Result 时使用了重定向类型，并且还使用 ${param_name} 作为重定向变量，当触发 redirect 类型返回时，Struts2 使用 ${param_name} 获取其值，在这个过程中会对 name 参数的值执行 OGNL 表达式解析，从而可以插入任意 OGNL 表达式导致任意代码执行。

例如

  1. <package name="S2-012" extends="struts-default">
  2.     <action name="user" class="com.demo.action.UserAction">
  3.         <result name="redirect" type="redirect">/index.jsp?name=${name}</result>
  4.         <result name="input">/index.jsp</result>
  5.         <result name="success">/index.jsp</result>
  6.     </action>
  7. </package>

漏洞复现

影响范围

Struts 2.0.0-2.3.14.

漏洞分析

根据漏洞描述可以知道漏洞点在执行完 action 之后，这个时候 action 之前的所有 Interceptor 已经执行完了，直接跟进 DefaultActionInvocation.executeResult 方法。


executeResult 方法只是用于执行 Result 类的实例，即是执行 Result 类的 execute 方法。Result 用于对 action 类实例执行之后结果的处理，也就是处理网页。


this.createResult(); 会根据 action 返回值获取对应的 result 标签配置，然后传入 this.objectFactory.buildResult


buildResult 用来生成对应的 Result 实现类， 这里是 org.apache.struts2.dispatcher.ServletRedirectResult，并把对应 result 标签的值 /index.jsp?name=${name} 设置给 ServletRedirectResult 类的 location 属性，然后返回 ServletRedirectResult。



然后继续跟进 this.result.execute(this); ，此时的 result 就是 ServletRedirectResult。


它会调用父类 StrutsResultSupport 的 execute 方法，继续跟进。此时会调用 this.conditionalParse() 计算重定向的值，这时候又看到了熟悉的 TextParseUtil.translateVariables


然后依次调用了下面这两个方法，一个是设置 openChars ，也就是待解析的 ognl 表达式的开头字符 %{}、${}，另一个是设置循环解析次数1次。

  1. public static String translateVariables(String expression, ValueStack stack, TextParseUtil.ParsedValueEvaluator evaluator) {
  2.       return translateVariables(new char[]{'$', '%'}, expression, stack, String.class, evaluator).toString();
  3. }

  5. public static Object translateVariables(char[] openChars, String expression, ValueStack stack, Class asType, TextParseUtil.ParsedValueEvaluator evaluator) {
  6.           return translateVariables(openChars, expression, stack, asType, evaluator, 1);
  7. }

然后就是和S2-001一样的过程，不过需要注意的是S2-001修复递归解析的方式就是加了一个 int maxLoopCount 参数限制循环解析次数，这里传入的我们的 maxLoopCount 为1，而我们的payload储存在 OgnlValeStack root区域的 name 属性中，此时解析的是 ${name}，想要执行我们的payload需要循环解析两次，第一次获取我们的payload %{..} ，第二次解析执行。

这里能够执行两次是因为它传入了 new char[]{'$', '%'} ，导致for循环可以执行两次，判断解析次数的break跳出的只是while循环，因此还会继续执行第二次for循环。

另外这里有一个 pos 参数在S2-001的修复方式中没有提到，他是用来获取 expression 表达式的开始位置，比如如果解析完了 %{password} 的值，下一次解析是从 %{password} 后面开始。在S2-001的修复中它被放在了for循环里，导致第二次for循环时 pos 的值会被重置为0，从而又从头开始解析。


最后依然是在 while 循环的 stack.findValue 中执行我们的payload。


漏洞修复

解析重定向的变量值时，把 pos 变量放到了最外层循环的外面，防止对结果进行二次表达式解析。
