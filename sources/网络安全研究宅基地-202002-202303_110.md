### 漏洞分析  

对HTTP来说，每个事件都是一个字符串。但是，在Struts类中，你可以具有任意数据类型的属性。Struts2中默认有一个类型转换器，可以帮助我们完成大部分的自动转换操作。例如你的Action类中有一个integer属性，你不需要执行任何操作，Struts会自动将请求参数转换为integer属性。

而拦截器 `ConversionErrorInterceptor` 用于处理类型转换错误。例如某个action存在属性 `private Integer age = null;`，如果我们提交一个非数字的字符串，就会产生类型转换错误，交给拦截器 `ConversionErrorInterceptor` 进行处理。

在 `com.opensymphony.xwork2.interceptor.ConversionErrorInterceptor` 的 `intercept` 方法中下断点。

![](../Images/553e48b6ddd5cc77c23552e02d4eca0e.png)

出现了类型转换错误的属性名和值赋值给了Map对象 `conversionErrors`。然后生成迭代对象 `i$` 并对其进行遍历。遍历过程中把属性名赋值给 `propertyName` ，属性值赋值给 `value` 。最终执行到 `fakie.put(propertyName, this.getOverrideExpr(invocation, value));`，跟进 `getOverrideExpr` 方法。

![](../Images/413370c0c0b4f33dce3d53de9b887d8f.png)

这里把 `value` 值入栈然后前后拼接了单引号赋值给 `var4`，最后出栈并返回 `var4`。这里可以知道为什么payload前后要拼接单引号。

此时的 `fakie`

![](../Images/3912fe5d84c2675f2222070c196e2eb4.png)

然后会调用 `OgnlValueStack` 的 `setExprOverrides` 方法，将Map对象 `fakie` 赋值给 `overrides` 属性。

![](../Images/91ba15b854fd0e4c7e6f1c1104405c42.png)

```
1.  `public void setExprOverrides(Map<Object, Object> overrides) {`
    
2.  `    if (this.overrides == null) {`
    
3.  `          this.overrides = overrides;`
    
4.  `    } else {`
    
5.  `          this.overrides.putAll(overrides);`
    
6.  `    }`
    
7.  `}`
    
```

拦截器执行完以后会对jsp标签进行解析，然后就还是S2-001的那一套流程，与S2-001不同的是S2-001需要利用 `%{}` 进行递归解析，而S2-005利用的是 `OgnlValueStack` 在 `findValue` 时会先在自己的 `overrides` 属性中寻找是否有对应key的键值对，如果有会直接覆盖掉我们想要在 `OgnlValueStack` 的 `CompoundRoot` 区域中寻找的属性值。

![](../Images/defb3b1861edc906eec5d22a66f408c1.png)

在这里当解析到 `<s:textfield name="age" label="age" />` 时，会从`OgnlValueStack` 的 `overrides` 属性中寻找key为 `age` 的键值对，值就是我们一开始传入的 `ognl` 表达式，最后该表达式会覆盖掉传入的 `age` 解析并返回。(因为Struts2的版本不同，代码有一些变动，但是功能是差不多的)

### 配置了 Validation 并不是该漏洞的产生的原因

与S2-001一样，表单验证错误 `Validation` 并不是该漏洞的产生的原因，表单验证错误只是为了让页面不进行跳转从而让我们能够对age属性进行覆盖。表单验证错误只是该漏洞的常见利用场景，该漏洞的产生原因应该是在类型转换出错时，拦截器 `ConversionErrorInterceptor` 会把我们提交的表单值组成键值对传入 `OgnlValueStack` 的 `overrides` 属性中，而键值由于使用的是 `'+键值+'` 这种拼接的形式，我们可以在键值前后构造单引号逃逸出来，从而在之后解析jsp标签的替换过程中进行任意 `ognl` 表达式解析。

### 漏洞修复

对类型转换出错的 `value` 值进行 `escape` 转义处理。
