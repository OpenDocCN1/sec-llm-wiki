## 概述

下列提及的所有的类均为实现了java.io.Serializable接口的类，只有实现了java.io.Serializable接口才能序列化对应的对象。

## 要求

需要了解java Proxy，java反射相关知识技能点。

## 任意class加载

com.bea.core.repackaged.springframework.beans.factory.support.DisposableBeanAdapter类中存在一个private void invokeCustomDestroyMethod()方法。如下图所示：

![](../Images/ebf72795e53179e898e62ae9ccdb92a3.png)

  

其中this.bean对象为Object类型、this.destoryMethodName为String类型。如下图所示：

![](../Images/5cf661e0794d1f3e4d8777cf9ed94d6a.png)

  

通过反序列化可以控制上述两个属性值、在上述两个属性值可控的情况下就可以控制反射的方法、以及反射的对象this.bean就可以触发序列化对象的任意无参方法。

  

例如最为常见的反序列化利用链中的com.sun.org.apache.xalan.internal.xsltc.trax.TemplatesImpl

可以通过控制bean属性为该实现类，destoryMethodName为getTransletInstance那就可以触发com.sun.org.apache.xalan.internal.xsltc.trax.TemplatesImpl中的Classloader加载任意的class。

## 如何触发任意方法调用

com.bea.core.repackaged.springframework.beans.factory.support.DisposableBeanAdapter类的public void destroy()中当destoryMethodName不为destroy的时候即可触发private void invokeCustomDestroyMethod()方法

如下图所示 

![](../Images/a7fe0f7f64cdcb05c84de90982202c18.png)

  

要触发任意方法调用必须触发com.bea.core.repackaged.springframework.beans.factory.support.DisposableBeanAdapter的public void destroy()方法。通过大量的代码翻阅之后发现com.bea.core.repackaged.springframework.aop.framework.JdkDynamicAopProxy的public Object invoke(Object proxy, Method method, Object\[\] args)方法在异常捕获的finally代码块中会调用targetSource.releaseTarget(target)去释放target对象。如下图所示：

![](../Images/2de4a6ddb56138a70dc5ef1a33dfd786.png)

 

targetSource可以通过advised对象来获取，advised是通过初始化JdkDynamicAopProxy的时候设置的是可控对象,com.bea.core.repackaged.springframework.aop.TargetSource

接口如下：

![](../Images/dc600cd3c93c318dee516b570d458443.png)

  

com.bea.core.repackaged.springframework.aop.target.PrototypeTargetSource类是com.bea.core.repackaged.springframework.aop.TargetSource的接口实现类之一如下图

![](../Images/1e2a419415d10cb1125b177619c3f8ac.png)

   

releaseTarget方法调用了destroyPrototypeInstance方法,继续跟进destroyPrototypeInstance方法如下图所示:

![](../Images/60a2baac8a841354eca61e04f9dfd440.png)

 在该类中即可触发com.bea.core.repackaged.springframework.beans.factory.support.DisposableBeanAdapter的destory方法。

## 触发条件

**第一个条件:targetSource.isStatic的返回值为false**

需要触发targetSource的releaseTarget方法必须满足targetSource的isStatic方法返回false

![](../Images/0cbb16ba7eb6b6d875d77379edf9de1b.png)

 

com.bea.core.repackaged.springframework.aop.target.PrototypeTargetSource类作为com.bea.core.repackaged.springframework.aop.target.AbstractBeanFactoryBasedTargetSource的实现类 刚好满足该条件。

![](../Images/71ad4f0c5668e8169d1a51a331811dab.png)

并且com.bea.core.repackaged.springframework.aop.target.PrototypeTargetSource的releaseTarget方法刚好能触发父类com.bea.core.repackaged.springframework.aop.target.AbstractPrototypeBasedTargetSource的destroyPrototypeInstance方法实现最终调用com.bea.core.repackaged.springframework.beans.factory.support.DisposableBeanAdapter的destory方法实现任意class加载。

  

**第二个条件:targetSource.realeaseTarget(target)方法中的target参数的控制**

com.bea.core.repackaged.springframework.aop.framework.JdkDynamicAopProxy的public Object invoke(Object proxy, Method method, Object\[\] args)方法中定义了target的来源，是通过targetsource获取的。如下图

![](../Images/6abe0040ee697632433ceee0ba3f301b.png)

 

跟进com.bea.core.repackaged.springframework.aop.target.PrototypeTargetSource查看其getTarget的方法是否可控？

![](../Images/7d08a928ec0b9bd4e7889aa04761c902.png)

![](../Images/cc4d7cfcd730e98002a0e5cc53520285.png)

  

可以发现最后是调用beanFactory的getbean来获取的，但是这里只能控制targetBeanName不能控制获取到的整个target对象。所以该类不能全部满足我们的需求继续寻找其他类

最后选择了com.bea.core.repackaged.springframework.aop.target.SingletonTargetSource

该类能完整的控制需要的target对象

![](../Images/10e98ddbde2a26f50199476709ea9633.png)

   

但是该类的releaseTarget方法并不能触发destroyPrototypeInstance实现任意class加载。所以需要有种方式能实现既能调用com.bea.core.repackaged.springframework.aop.target.SingletonTargetSource的getTarget方法又能调用com.bea.core.repackaged.springframework.aop.target.PrototypeTargetSource的releaseTarget方法。

  

通过搜索发现com.sun.corba.se.spi.orbutil.proxy.CompositeInvocationHandlerImpl

类能满足该种需求,它可以根据代理方法的不同声明类实现选择不同的代理类来处理，如下图

![](../Images/e6b20460c43fbca6299cf4ada8275298.png)

  

那么我们就可以通过注册两个不同的接口实现该种功能

1、因为我们需要调用releaseTarget方法所以我们需要构造com.bea.core.repackaged.springframework.aop.TargetSource接口的代理类来代理releaseTarget调用。

2、因为我们需要调用getTarget方法所以需要找到一个能代理getTarget的接口，com.bea.core.repackaged.springframework.validation.BindingResult刚好能满足该需求。

![](../Images/38b87c0c042c9ccafb37b8afde14ab7b.png)

  

这样我们通过构造该两种接口的实现类实现基于不同同一个类代理不同的方法的功能。

  

但是在调用com.bea.core.repackaged.springframework.validation.BindingResult的getTarget方法的时候跟proxy对象无法兼容，因为需要满足TargetSouce接口的调用的话proxy就必须是TargetSouce的子类，所以只能想办法通过实现代理com.bea.core.repackaged.springframework.validation.BindingResult的getTarget方法来实现控制代理方法。找到了weblogic.ejb.container.internal.RemoteBusinessIntfProxy类来实现该功能。如果代理方法的方法名跟返回值相同的话就可以调用另一个对象来调用该代理方法

![](../Images/9aabb423a0c2eaba06f2f9fe4ec081b4.png)

这样就可以利用com.bea.core.repackaged.springframework.validation.BindingResult的getTarget方法来调用获取com.bea.core.repackaged.springframework.aop.target.SingletonTargetSource的getTarget方法。实现target对象的可控。
