S2-005漏洞的起源源于S2-003(受影响版本: 低于Struts 2.0.12)，struts2会将http的每个参数名解析为OGNL语句执行(可理解为java代码)。OGNL表达式通过#来访问struts的对象，struts框架通过过滤#字符防止安全问题，然而通过unicode编码(u0023)或8进制(43)即绕过了安全限制，对于S2-003漏洞，官方通过增加安全配置(禁止静态方法调用和类方法执行等)来修补，但是安全配置被绕过再次导致了漏洞，攻击者可以利用OGNL表达式将这些选项打开，S2-003的修补方案把自己上了一个锁，但是把锁钥匙给插在了锁头上。—— 《白帽子讲Web安全》

漏洞复现

tomcat7 及以后的版本会严格按照 RFC 3986规范进行访问解析，而 RFC 3986规范定义了Url中只允许包含英文字母 a-zA-Z、数字0-9、-_.~4个特殊字符以及所有保留字符(RFC3986中指定了以下字符为保留字符：! * ’ ( ) ; : @ & = + $ , / ? # [ ])

本地测试时，发现也不能使用[ ]，因此如果url中要使用下列字符，需要进行url编码，否则会返回400状态码。

  1. ^[]{}\|"<>`

Struts 2.0.0 - Struts 2.1.8.1

OGNL Expression Evaluation

浅析OGNL表达式求值

如果你在任意对象后面紧接着一个带括号的OGNL表达式，而中间没有使用.符号连接，那么OGNL将会试着把第一个表达式的计算结果当作一个新的表达式再去计算，并且把带括号表达式的计算结果作为本次计算的root对象。第一个表达式的计算结果可以是任意对象；如果它是一个AST树，OGNL就会认为这是一个表达式的解析形态，然后直接解释它；否则，OGNL会拿到这个对象的字符串值，然后去解释通过解析这个字符串得到的AST树。

(one)(two)

它将会把one当作一个OGNL表达式去计算，然后把它的结果当作另一个以two为根对象的OGNL表达式再一次计算。所以，如果one的返回内容能被解析为AST树，那么这些内容将会被当作OGNL语句被计算。

常见payload有以下三种形式

(aaa)(bbb)=true

(aaa=true)(bbb)(ccc)

(ccc)((aaa=true)(bbb))

例如在 ('\43_memberAccess.allowStaticMethodAccess')(a) 中， 第一个表达式的计算结果是一个字符串，绕过了特殊字符检测，生成AST树后被解码为正常的 #_memberAccess["allowStaticMethodAccess"] 字符串，在第一次计算时拿到的是该字符串，然后尝试对它解析得到AST树，再次计算，导致内部实际payload被执行。

漏洞分析

漏洞代码在拦截器 ParametersInterceptor 中，我们首先简单了解一下 Struts2 中的拦截器。

Struts2 拦截器是 Struts2 中一个很重要的功能，本质是代理模式。当一个请求到达服务端时，首先在MVC模式下会执行 Action 来响应这个请求，而拦截器是在 执行 Action 前后被调用的一个对象（Class）。Struts2 会查找配置文件，并根据其配置实例化相对应的拦截器对象，然后串成一个列表，最后一个一个地调用列表中的拦截器。

拦截器的执行职责有三种选择

  1. 中止整个执行，直接返回一个字符串作为 resultCode，return "toLogin"

  2. 通过递归调用负责调用堆栈中下一个 Interceptor 的执行， invocation.invoke();

  3. 如果在堆栈内已经不存在任何的 Interceptor，调用 Action。

这里直接使用 S2-001 测试的源码环境。

Struts2.xml

  1. <?xml version="1.0" encoding="UTF-8" ?>
  2. <!DOCTYPE struts PUBLIC
  3.         "-//Apache Software Foundation//DTD Struts Configuration 2.0//EN"
  4.         "http://struts.apache.org/dtds/struts-2.0.dtd">
  5. <struts>
  6.     <package name="S2-001" extends="struts-default">

  8.             <result name="success">welcome.jsp</result>
  9.             <result name="error">index.jsp</result>

package 节点是整个配置的核心部分。每个 package从语义上讲，其实代表了每一个独立的模块。在这个模块中，你可以定义隶属于这个模块的行为方式，而与其他的模块没有关系。通过使用 extends，你可以指定本 package 继承另外一个 package 的所有的配置。

通常情况下，我们使用 struts-default 作为 package 的基础。struts-default.xml 文件是 Struts2 框架默认加载的配置文件。它定义 Struts2 一些核心的 bean 和拦截器。其路径为struts2-core-2.0.1.jar!/struts-default.xml。

其中就包含着拦截器 ParametersInterceptor。

S2-003

因为 S2-005 是对 S2-003 的绕过，所以我们先来分析S2-003。

在 com.opensymphony.xwork2.interceptor.ParametersInterceptor 中的 intercept 方法中下端点。

ParametersInterceptor 拦截器其主要功能是把 ActionContext 中的请求参数设置到 ValueStack 中。

在 getValueStack 并设置请求参数之前，执行了 OgnlContextState.setDenyMethodExecution(contextMap, true); 来禁止 OGNL 表达式中方法的执行。因此我们的poc中需要使用 ('#context[\'xwork.MethodAccessor.denyMethodExecution\']=false')(bla)(bla) 将 denyMethodExecution 设置为false。

跟进this.setParameters(action, stack, parameters);。

action 即 LoginAction 实例对象。stack 即 OgnlValueStack，它是 ValueStack 的实现类。parameters 即 LoginAction 的请求参数。

通过迭代 parameters 将参数名和 value 添加进 OgnlValueStack。

在获取参数名 name 之后有一个 this.acceptableName(name)操作

  1. protected boolean acceptableName(String name) {
  2.         return name.indexOf(61) == -1 && name.indexOf(44) == -1 && name.indexOf(35) == -1 && name.indexOf(58) == -1;
  3. }

如果 name 中含有 =,#: 会返回false，并且不会将此参数添加进 OgnlValueStack ，继续获取下一个参数名。
高版本中改为了正则 [\\p{Graph}&&[^,#:=]]*，允许除了 ^,#:= 以外的所有可见字符，空格属于不可见字符，因此高版本中空格也要进行unicode编码或者8进制编码。
因此我们的url中参数名不能出现上述字符，这里使用unicode编码(\u0023)或8进制(\43)来绕过，原理就是 parseExpression 方法在解析 OGNL 表达式的时候，会调用 ognl.JavaCharStream 的 readChar 方法进行处理。当读取到 \ 并且其后面如果是 u 则会做进一步处理。

继续跟进 stack.setValue(name,value)

  1. public void setValue(String expr, Object value) {
  2.       this.setValue(expr, value, this.isDevModeEnabled());
  3. }

setValue 最终会去执行 OGNL 表达式，这里的 expr 实际上就是我们请求 Action 的参数名。因此我们最终可以通过控制请求参数名来执行 OGNL 表达式 。
