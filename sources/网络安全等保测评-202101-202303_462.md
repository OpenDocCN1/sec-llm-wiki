背景  

当前市场上网络请求抓包工具有很多，常用的有：Charles、Fiddler、Burpsuite、WireShark、mitmproxy等。如果从市场使用率来讲，特别是对于Windows用户来说，Fiddler抓包使用人群占比最多。

由于Fiddler基于.NET开发，Mac系统用户显然无法使用，为了解决Mac下使用Fiddler的问题，早在2016年Telerik官方出过一款名为Fiddler for OS X Beta 1尝试来解决这类问题, 但这款工具必须通过Mono才可以在Mac上使用。并且在Mac上使用是非常不稳定, 有非常多的问题。Mac用户的绝大多数选择都是Charles，Charles基于JAVA开发，功能十分强大，是Mac的平台的首推抓包工具，但该软件是收费软件，使得软件的使用受到一定限制。

基于以上背景，2018年Telerik官方推出了跨平台版本Fiddller Everywhere, 给Mac、Linux用户更多的选择

# 简介

我们引用官方的一段描述

Fiddler Everywhere is a web debugging proxy for any browser, any application, any process. Log and inspect all HTTP(S) traffic between your computer and the Internet, mock requests, and diagnose network issues. Fiddler Everywhere is available for macOS, Windows, and Linux.”

简而言之，**Fiddler Everywhere**是可以运行在任何浏览器，任何系统、跨平台的一款Web调试代理工具*。*它可以抓取和记录客户机和Internet之间的所有HTTP（S）通信，用于检查网络通信，甚至可以编辑请求用于调试。在我们熟知以上功能外，它还额外支持类似Postman的Mock请求能力。我们甚至可以将它理解为精简版的Fiddler + Postman组合体。更重要的是它提供免费版本，并且支持Windows、Mac和Linux。

# 主页面

![](../Images/d354b68764e622d017bd8df86749c3ab.png)

主界面主要分为以下几个区域：

*    Sessions – 本机保存的会话请求记录，可以单个，也可以是当前对话抓取的所有记录
    
*    Requests – 类似Postman，保存了所有请求。可以随时手工执行发起请求
    
*   Live Traffic – 通信拦截区域，展示所有客户端通过fiddler代理发出的请求
    
*    Composer – 请求执行区域
    
*   Inspector – 请求信息展示区，展示了请求及返回的具体内容
    
*   Auto Responder – 自动返回处理规则区，可以根据匹配条件自定义返回数据
    

# 代理配置

1.点击配置按钮，打开配置页到Connections选项卡

![](../Images/f89586032690315264a5212f760bc086.png)

在这里可以配置Fiddler的监听端口，如8866

2.浏览器将代理设为Fiddler

2.1 IE&Edge和Safari请参照系统配置进行配置

*   Edge: https://jingyan.baidu.com/article/22a299b5ce28a89e19376a07.html
    
*   Safari: https://support.apple.com/zh-cn/guide/safari/ibrw1053/mac
    

2.2 Firefox及Chrome用户可以直接使用系统代理配置，但推荐使用代理切换插件SwitchyOmega 具体安装步骤请参考

https://github.com/FelisCatus/SwitchyOmega/releases

2.3 代理设置

代理主机：Fiddler所运行的主机，如是本机则127.0.0.1

代理端口：如上配置的fiddler服务端口，如8866

# 拦截请求筛选及处理

1.筛选拦截主页面各字段提供筛选功能，可以筛选特定的请求

![](../Images/c666523fb1a1a1e49a061fc3449da491.png)

2. 处理右键点击请求弹出如下菜单

![](../Images/8ab685100bd8e14b047b20ad85cd4f39.png)

*   Edit in Composer – 自动跳转到Composer页面，实现对请求的修改及重新发送
    
*   Save – 保存请求记录
    
*   Share – 分享请求给其他Fiddler用户
    
*   Export – 导出请求
    
*   Remove – 移除当前拦截的请求
    
*   Comment – 加备注
    
*   Mark – 进行标记方便识别
    
*   Replay – 重发选择的请求
    
*   Select – 选择器，可以选中子节点、父节点等
    
*   Copy – 拷贝当前选择的请求
    
*   Add New Rule – 基于该请求创建返回值规则（类似mock功能）
    

# 请求修改及重发

从拦截器中筛选到需修改的请求，右键\->Edit in Composer即可进入Composer页面

![](../Images/fe5c7b48de9cdbca98a120d076af9eb4.png)

可以修改参数后点击Execute重新发起请求并查看结果

也可以在修改后点击SAVE将该请求保存到主页面左侧Requests(类似Postman)

![](../Images/845307976c2247196e9fa38e6b55c068.png)

![](../Images/2dba8deb6ffc586c82f204d7577e6278.png)

Composer的页面风格和Postman十分相似。

# 免费版的限制

![](../Images/bd88b03d733b7a1babb427f419ca0b0f.png)

免费版主要有以下限制

可在线保存的sessions最大5个

可保存的Requests最大5个

可设置的Mock Rule最大5个

# 小结

Fiddler Everywhere仍在不断迭代中，目前整体的功能比较简洁`，`简单来说，**它融合了****Fiddler****\+ Postman**** 的基础功能**，并且提供了Charles之外的另一种跨平台抓包解决方案，同时提供免费版也大大降低了使用门槛。
