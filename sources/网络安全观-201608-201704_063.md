# LOCKet打造国内领先CASB服务（2017-02-21）

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzIxNzUxNzA2NQ==&mid=2247484167&idx=3&sn=13065be90f55da3f860dfb3d74a3cc33&chksm=97f9de61a08e577724ee12971d266426da51b9d30b2f218823b420371c2ee47a306630b2c13f&scene=126&sessionid=1681323843#rd](http://mp.weixin.qq.com/s?__biz=MzIxNzUxNzA2NQ==&mid=2247484167&idx=3&sn=13065be90f55da3f860dfb3d74a3cc33&chksm=97f9de61a08e577724ee12971d266426da51b9d30b2f218823b420371c2ee47a306630b2c13f&scene=126&sessionid=1681323843#rd)

齐鲁晚报02月21日讯：近日，国内第三方数据安全团队LOCKet，正在打造中国领先的CASB（Cloud Access Security Broker，云访问安全代理）服务。CASB，作为国外云安全领域的最新 “大热门”，将传统安全技术服务集约化，帮助企业对外减小云数据泄露风险，对内统一管理各项云服务使用情况，让客户对原本飘忽不定的“云”更具掌控力。  

  

展开来说，CASB这个概念，最早是由Gartner在2012年正式提出，其最主要的四大核心功能是：可视化、合规性、数据安全和威胁防护。

  

那么，LOCKet所要打造的CASB 服务具体是怎么样的？LOCKet现有的 GATEWAY安全网关已初具CASB雏形，但各项功能还需丰富，比如覆盖更多、更广的国内SaaS服务；比如数据安全模块，还应增加DLP、凭证化等安全技术；再或是LOCKet的可视化服务，现在主要针对密钥使用情况追踪，后续关键数据仍是密文，企业客户可自行选择部分用户行为、设备进行追踪。

  

LOCKet在此前的发布会上宣布将推出LOCKet 2.0产品，其中的LOCKet MIND 将通过深度学习形式，为企业客户标识哪些为敏感信息，预警哪些存在异常等，将会是更加智能、更懂人性的可视化服务。

  

LOCKet的CASB服务将拥有强大的用户行为分析能力，能让企业清楚了解云中数据走向，对于异常行为及时发出警报，让云中的一切变得可视、可控。另一方面，一些传统安全防护的“硬技术”仍将保留在其中，有效防止云中数据丢失、泄漏。

  

据了解，LOCKet是国内鲜有的第三方云安全团队，主要解决人与云之间的信任问题，此前完成了千万元Pre-A融资，LOCKet目前的安全服务适用于 SaaS、PaaS、IaaS 各个云计算场景，主要合作伙伴包括阿里云、红圈营销、众安保险、每刻报销、大华集团等。

  

大华集团作为LOCKet的企业客户代表，其副总裁魏美钟曾如此评价LOCKet：“LOCKet，让我们对报销云平台的安全有了信心。LOCKet 模式对中国SaaS 的普及有重要意义，在信用体系不强的社会里，第三方安全加密服务让用户的安全担心消除。”

  

放眼看CASB国外的发展历程，它自萌芽以来，就吸引了大量资本，各种高价收购的案例频现。2015年，Bluecoat高价收购两家CASB企业——Perspecsys和Elastica（2.8亿美元）。2016年6月，Cisco以2.93亿美金收购CloudLock。

  

CASB的发展未来，无疑是一片蓝海。据Gartner 最新“全球CASB市场预测报告”，到2020年，85%的大型企业都会选择为他们的云服务配置CASB服务，尽管如今只有不到5%的比例。

  

目前在国内，市面上基本还没有成形的CASB服务。客观来看，以国内现有云技术的发展速度，云安全需求的日益扩大将是必然。CASB服务在传统安全防护的基础上，让云中的一切变得透明，将数据主权真正归还给客户所有，帮助云服务更加健康地发展。

**革命性的安全体验**

开发者 “零”开发成本，可快速接入。直接接入厂商原服务，客户不需下载、安装、注册。只有经过 LOCKet 认证的设备，才可以进行解密操作。支持加密搜索。

LOCKet 与众安保险合作推出数据安全责任险。众安保险承保 LOCKet 安全承诺和技术实现，最高理赔 1000 万元。

支持 AES-GCM 256 位加密，比支付宝网络传输加密级别还高。

RSA 多重加密密钥，据维基百科介绍目前还没有可靠的攻击 RSA 算法的方式。

  

**高性能的加解密服务**

单实例支撑 10000+TPS、每秒 10万+ 加解密请求。

支持横向扩展，支持 HTTP、UDP 等多种通信协议。

加密数据存储和密钥管理分离。

**二、产品问答**

  

1、LOCKet 解决的问题？

以独立第三方的视角，提供数据安全方案，解决用户对云的不信任矛盾，做到“我的数据我做主”。

2、产品是什么形态？网关是硬件还是软件？部署是否有要求？

LOCKet GATEWAY 以 SaaS 服务形态交付，不需要独立硬件支持。可选择部署在开发者自身服务的负载均衡之前或者之后。

3、加解密程序可以自行研发，为什么要用 LOCKet 呢？

第一，加密不仅仅是加密算法的问题，而是同时涉及到整体安全体系架构、密钥管理、身份验证等方方面面。对于非专注于安全领域的开发者而言，具有不小的挑战；第二，LOCKet 提供的是独立第三方的安全解决方案，只有第三方立场才能解决用户对服务的不信任问题；第三，LOCKet 在加密之外提供了全面的数据安全服务，包括但不限于合规性支持、安全可视化、数据审计、风险报警等。

4、LOCKet 是加密非结构化数据还是结构化数据？

同时支持结构化数据和非结构化数据加密。

5、加密是否需要硬件？

LOCKet GATEWAY 无需加密硬件支撑，作为普通软件服务使用即可，没有硬件采购、管理成本。

6、LOCKet GATEWAY 与 HTTPS 的区别？

SSL/TLS 或者叫作大家更熟悉的 HTTPS，是通过加密手段保护数据由客户端发送到服务端之间的传输链路层安全，数据经过 HTTPS 到达服务端后依然是明文状态，无法保证客户数据云上的隐私安全。LOCKet GATEWAY 在数据到达云端后，会对其进行及时的加密处理，从而确保客户数据始终是以密文的形式存在云端。

**三、加解密原理相关问题**

  

1、采用什么加密算法？强度如何？

不同的节点采用不同的算法，字段级别的加密以 AES256 为主。同时支持特殊行业的合规性要求加密算法，如国密等。

2、加密怎么实现？是全部加密吗？解密是怎么实现的？

LOCKet 同时支持字段级别加密和文件加密，开发者只需在 LOCKet 开发者平台配置相应策略即可。解密无需配置策略，由 LOCKet GATEWAY 在完成身份验证后，自动进行解密。

3、加密之后手机验证是否会受影响？

SaaS 服务发送手机验证码功能，依赖第三方短信服务，开发者只需使用 LOCKet GATEWAY 来代理短信验证码服务请求即可，即使使用密文的手机号码，LOCKet GATEWAY 也能支持自动解密后转发请求。

4、加密后调试系统如何？

LOCKet GATEWAY 支持 DEBUG 模式，并包含大量的日志，可帮助开发者快速定位问题。

5、加密后数据是否变长？不同数据的碰撞怎么办？

经过 LOCKet 加密后的数据，我们将在密文的基础上增添文件头或数据头，加密后的数据将在一定程度上变长。LOCKet 安全体系内，数据加密时采用随机的密钥和初始化向量，产生的密文也都不同。对于用户敏感信息不可逆存储， 采用 PBKDF2 算法迭代加密数据尽可能降低碰撞产生的可能，在摘要算法的选择上，我们优先使用 SHA256 等算法。

6、如果数据加密了，还能搜索吗？

目前通过分词加密方式予以支持。

7、目前GATEWAY主要支持哪些协议？

HTTP、HTTPS，后续会陆续支持其它协议如 RPC、WebService、WebSocket 等。

8、目前合作的 SaaS 可以单独部署 GATEWAY？

支持本地部署。

9、密文落库，统计查询工作会不会受影响？

可以查询，都是密文。数字加密后无法在数据库层面进行统计计算，需要业务逻辑层进行处理，因此不推荐加密数字等信息。

10、加密哪些信息？是数字金额？例如涉及工资、销售业绩的统计等？

建议加密和用户身份相关的真实敏感信息。不建议对数字信息进行加密。

11、用户使用时，现有数据明文状态，历史数据加密是如何处理的？

LOCKet 支持数据刷新，合作伙伴可选着在上线前或者上线后统一刷成密文。

12、加密后对 PDF、WORD 预览是否会有影响 ？

加密不影响应用上层业务。
