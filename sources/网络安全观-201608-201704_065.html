第一章 摘要


近年来,云访问安全代理(Cloud Access Security Broker ,以下简称 CASB)市场随着云服务的发展急速扩张。Gartner 预测,到 2020 年,95% 的云安全故障可归因于客户本身;截止 2016 年,只有不到 5% 的大型企业选择为它们的云服务配置 CASB 服务,但到 2020 年,这个比例将提升至 85%。


第二章 背景


如今,初创公司和小规模企业多数依赖众多便捷的公有 SaaS 服务,来快速组建公司和团队,支撑、辅助企业内部的正常运转,如 CRM、ERP、HR、OA、财务、文件协同等 SaaS 服务。


SaaS 市场的发展,伴随着用户对其安全性、隐私性及合规性的担忧,对云的可控性提出了严苛且紧迫的挑战。


2.1 Shadow IT


SaaS 服务相比于传统的软件服务,具有极强的易用性,往往注册即可用,省去了繁杂的安装、部署、license、个性化配置等阶段。基于这样的背景,许多企业的业务部门、员工可轻易地选择不经过 IT 部门的帮助,直接获取所需的云服务,这种趋势被称为“Shadow IT”。它推动了云服务应用的增长,但企业本身则开始面临较大的云安全风险。


2.2 BYOD


SaaS 服务的勃发、移动互联网的兴盛、智能设备的普及,都为移动办公提供了肥沃的土壤,企业员工越来越多的将自己的设备(智能手机、手提电脑、平板电脑)作为完成工作的平台和媒介(Bring Your Own Device),企业已难以面向员工强制固定的设备进行办公。企业失去了对办公设备的控制和监管,也就失去了对企业数据资产的控制,企业依赖云服务,却又愈加的担忧起云服务的安全。


2.3 云信任矛盾


云计算拥有里程碑式的历史地位,但它却并不是某种新技术的产品载体,更多的是理念和方式的一次跃变。人们受益于云计算的诸多优势,本质还在于通过云计算将自身纳入了一个更为广泛的协作关系网络中来。通过协作,外包自身核心业务非相关的部分给第三方(云平台、其它第三方服务),使自己更为专注。因为专注所以高效,因为高效所以降低机会成本。


在计算的世界里,协作意味着数据的交换,数据的交换必然导致数据主体自主权的削弱,当主权面临挑战,协作双方的信任危机也就不可避免地被催生了出来。


传统企业已经开始越来越多地将公有云视为节约成本或者增加自有数据中心容量的理想解决方案。然而,企业目前在选择公有云时主要关注的还是安全性问题。


第三章 CASB 定义


CASB (Cloud Access Security Broker)作为云服务安全访问代理, 帮助组织填补了云服务安全方面的缺失。CASB 有别于传统安全技术,例如 Web 应用程序防火墙(WAF),安全 Web 网关 (SWG)和企业防火墙。CASB 更理解云服务用户的痛点所在：这仍是您的数据，但它并不存储在您所能控制的系统中。CASB 为混合云服务用户或设备,提供一致的配置策略,通过细颗粒度的可视化方式来掌控用户行为。


CASB 目前主要适用于企业 SaaS 服务,例如企业文件同步和共享(EFSS)、CRM、HR、ERP、服务台及办公软件,也在逐步覆盖企业社交网络,以及主流 IaaS 、PaaS 服务。此外,某些 CASB 厂商还支持在企业应用的前端进行部署,从而将这些应用程序放在统一的云服务管理框架下。


第四章 CASB 核心功能


Gartner 认为 CASB 主要由以下四个核心功能组成。


4.1 可视化 (Visibility)


帮助组织了解其内部在使用哪些云服务,何时何地谁使用了哪项云服务。领先的 CASB 厂商会对各项云服务进行信任评级(基于云服务商安全能力、合规性等),来将云服务商的“安全性可视化”, 从而转化为用户对云的“信任感”。


4.2 合规性 (Compliance)


让云数据更加合规、合法地存储,帮助识别各项云服务使用情况,以及特定云服务存在的安全风险。组织需要 CASB 满足内外部合规性要求,并充分向其展示,谁何时何地在哪儿,由于什么,使用了某项云服务。此外,CASB 还能对云访问权限进行控制。


4.3 数据安全 (Data Security)


强制执行数据中心安全策略,通过对访问权限进行控制,对用户敏感信息、越权访问行为进行追踪等,来降低安全风险。有些 CASB 产品还针对数据字段或文件提供加密、凭证化、目录编排等功能。密钥支持私有化存储管理。


此外,CASB 还拥有数据防泄漏(DLP)功能,支持通过 CASB 产品部署,或经由 ICPA 完成本地网络部署。部分 CASB 产品还拥有数据审计防护中心(Data-centric audit and protection, DCAP),当然如今一些传统 DACP 厂商也在逐步覆盖云服务场景。


4.4 威胁防护 (Threat Protection)


通过提供合适的访问权限控制,来控制云端设备、用户及应用的进出情况。比如,用户行为分析功能 (UEBA)能帮助分析异常用户操作,快速发现威胁信息,自动识别恶意软件。某些 CASB 厂商拥有专业的数据分析团队,基于云服务或针对云服务的各种攻击类型。


CASB 技术通过虚拟或实体设备,部署于 SaaS 应用程序、本地服务或混合云。目前 SaaS 环境下的 CASB 方案较其他两种方案,更具普适性,更受客户青睐。而 CASB 本地部署形式,能满足客户监控本地数据权限的特定需求。


第五章 CASB 服务形式


CASB 服务作为云服务的入口,主要以两种形态予以构建:


  • 流量代理服务 (Proxy、GATEWAY)

    代理客户端到云端的所有流量,在将流量转发到云服务后端之前进行安全保护。


  • 接口服务 (API)

    考虑到各个云服务功能的差异性(有时差异巨大)，往往很难通过构建统一的流量代理服务来覆盖所有的云服务。因此，CASB 厂商通常往往借助于特定云服务的开放性，利用其开放 的 API 来针对性的搭建安全服务。

从长远来看，云服务提供给终端用户的 API 接口服务,若能在服务广度、深度、可用性及性能上更为成熟，就能避免代理 (Proxy、Gateway) 截流量的情况。然而，现在云服务商的 API 服务成熟度水平参差不齐。Gartner 预计未来 2-3 年，即使不在行业合规性标准的推动下，如云安全联盟提出的开放 API 接口宪章(详见: https://cloudsecurityalliance.org/document/open-api- charter/)，领先的云应用或云服务商也将大幅度开发他们的 API 服务，API 接口未来将更好地支持安全服务。较小的 SaaS 厂商可能不会选择开发关于可视化控制相关的 AIP 服务,因此代理 (Proxy)的需求未来不可能完全消失。


5.1 流量代理


5.1.1 反向代理 (Reverse Proxy)


以代理服务器来接受 internet 上的连接请求,然后将请求转发给内部网络上的服务器,并将从服务器上得到的结果返回给 internet 上请求连接的客户端,此时代理服务器对外就表现为一个反向代理服务器。


这种形式无需任何终端配置，在终端用户与 SaaS 服务(使用证书加密的移动本机应用除外)之间接入 CASB 服务。密钥、加密方案策略支持本地化管理,可完全隔离于 CASB 厂商与云服务商之外。您也可以通过托管反向代理,来间接访问到 CASB 或是 CSP 云端密钥管理系统。


5.1.2 正向代理(Forward proxy)


位于客户端和原始服务器(origin server)之间的服务器,为了从原始服务器取得内容, 客户端向代理发送一个请求并指定目标(原始服务器),然后代理向原始服务器转交请求并将获得的内容返回给客户端。客户端才能使用正向代理。


支持云服务或是本地化部署。一些 CASB 厂商还支持在终端设备上部署软件代理服务,或是在企业文件移动端管理系统(EMM)上配置文件,来强制使用诸如 DNS 和自动配置代理(PAC)之类的服务。从终端用户角度出发，流量被强制导入CASB，是最具侵入性的方案。


某些 CASB 代理商会提供加密服务,通常使用非对称加密技术,在终端或通过 VPN,对密钥进行分离管理,也可以使用自签或是第三方数字证书(self-signed digital certificate),或是由企业来管理密钥使用方案。


5.2 接口模式(API mode)


CASB 被授予 SaaS 服务 API 接口的访问权限,可直接使用 SaaS 本身的功能。该模式让组织可以使用更多的功能,例如日志监测、安全策略可视化、云服务或应用中静止数据的安全检测。该模式下,密钥管理支持本地化或托管两种形式。


API 模式是一个双赢的选择,不论从 CASB 角度,或是 SaaS 服务的数据保护层面,由 SaaS 厂商 (例如 Salesforce Shield)提供加密/凭证化功能,而密钥掌握在用户手里。但是在这种情况下, SaaS 服务商仍有访问密钥的途径,并且数据在应用程序内是明文。如果该 SaaS 服务由另一个 CSP (如 Amazon,Microsoft)托管,在 IaaS 厂商的内存中可见,这可能没那么满足数据存储或合规性要求。


第六章 企业集成


CASB 能与企业原有安全基础设施部分的关键节点集成,防止企业安全“孤岛化”,具体包括身份及访问管理(IAM)和 IDaaS 服务,会重复利用原有 DLP 云安全策略。本地密钥管理系统也将与 CASB 的安全信息和事件管理台(SIEM)集成在一起。此外,CASB 还支持部分原有安全流程,如事件响应性与合规性。CASB 本身还将提供企业能自动集成的 API 服务,以便将其与其他企业管理工具整合。


第七章 CASB 交叉技术


CASB 在其它领域的技术解决方案基础上,研究出了全新功能,开辟了安全技术新领域,比如访问权限控制、凭证化、加密、数据防丢失(DLP)以及数据分析功能。CASB 中提供的 DLP 和 UEBA(用户行为分析系统)服务功能，比不上市面上顶尖 DLP 和UEBA 厂商,但对许多组织来说，足够满足它们的需求。


此外,企业无法将 SaaS 应用与本地环境下的数据进行完全隔离。因此,市场急需基于数据安全管理流程,建立全企业全数据安全策略分析和控制方案。


第八章 CASB 市场现状


CASB 市场自 2012 年萌芽以来发展迅速。尽管许多厂商仍是创业公司,但由于资本市场青睐,整个 CASB 市场快速成熟。尤其在欧美、英国等国家,由于整个 SaaS 行业的快速且相对规范的发展,激发了 CASB 的快速发展,如下罗列了国外主要的 CASB 厂商列表。
