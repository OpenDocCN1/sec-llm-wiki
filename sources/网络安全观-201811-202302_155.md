API 网关功能在Gartner调研报告中，有一部分很重要的功能是API转换功能：

![](../Images/8e8b8736e81fb30be73d1b61b986171a.png)

API网关在转换方面的功能，结合实际生产的需求，整理转换功能主要包含

  

  
  
  
  
  
**1.通信协议的转换**  

  

![](../Images/4ae4aff11d7d554c6d4683b383c49f91.png)

客户端使用的通信协议和API服务器使用的通信协议不一致，可以通过API Gateway将客户端通信协议转换为API服务器所使用的协议，以满足客户端的访问需求，通常可以看到的转换路径是HTTPS转为HTTP，该功能是F5 BIG-IP的标准功能，F5使用非开源OpenSSL实现TLS协议，避免OpenSSL本身的实现漏洞

![](../Images/e2c7a8c214eb4f5f81515a9c32f6f6bf.png)

从V12版本开始，F5 BIG-IP支持HTTP2协议，支持客户端到F5运行HTTP2，后端API服务器使用HTTP，从V14版本开始，支持前端后端HTTP2的全代理模式，如API服务器使用HTTP2实现异步单连接多请求的高性能模式，通过F5 API Gateway，可以完全无缝接入。

![](../Images/cbb38bae92759cb51d3c8dc01c4f57fb.png)

  

  

  
  
  
  
  
**2.认证协议的转换**  

  

API中大量使用JWT以及Oauth bearer类型认证，而API服务器则多种多样，新式API服务器对JWT以及Oauth兼容性较好，而未直接支持JWT/Oauth2的服务器，其原生有可能已经支持HTTP Basic Auth/HTTPS证书，为将这部分API服务器纳入统一的API全生命周期管理，提供统一的API入口和对外展现，需要实现认证协议的转换，在生产环境可以看到一些认证的转换路径包括

  

| CLIENT SIDE || SERVER SIDE |
| --- | --- |
| JWT || HTTP Basic-》AD |
| SSL Certificate || JWT |
| HTTP Basic || JWT |

F5 API Gateway可抽取客户端API请求中的关键认证信息，包括：

1.  SSL客户端证书信息，如Issue，Common Name等
2.  JWK Token 解密后信息，如Audience，Issuer
3.  HTTP Basic 认证中的User和PassWord

  

将上述信息进行转换，发起sideband的认证请求到外部IdP，或者重新封装认证信息，转换为服务器端可识别的认证格式，降低客户端的升级成本和API服务器的兼容成本。

  

  
  
  
  
  
**3.通信内容格式的转换**  

  

通信内容格式的转换在API领域是更常见的场景，生产中常见的内容格式转换场景有：

| CLIENT SIDE || SERVER SIDE |
| --- | --- |
| JSON || XML |
| XML || JSON |
| HTTP URL Parameter || JSON |
| HTTP JSON || SOCKET（特定格式） |

  
F5 API Gateway工作在全代理模式下，对数据具备截获，修改，重定向转发等高级协议处理能力，其数据处理的流程为：

  

![](../Images/54dae582b2d51a64f8f1734aee87d2ad.png)

  

于此同时，F5内置多种数据格式解析命令：

可以将客户端APP发起请求的内容参数抽取后转换成其他格式，还可以使用NODEJS对转换功能进行扩展。

  

以下是通过F5，将HTTP请求中URL内的参数变量，转换为json格式，通过sideband的模式发送给API服务器，并将API服务器的返回内容转发给客户端的代码。在整个过程中，F5 API将HTTP方法从GET转换为POST，同时将uri数据进行了格式转换。

  

**iRule 代码：**

when HTTP\_REQUEST  {

  

    set name \[URI::query \[HTTP::uri\] "name"\]

    set title \[URI::query \[HTTP::uri\] "title"\]

   

    set ilx\_handle \[ILX::init "ilx\_pl" "ilx\_ext"\]

    if {\[catch {ILX::call $ilx\_handle "httpRequest" $name $title} result\]} {

        log local0.error "Client - \[IP::client\_addr\], ILX failure: $result"

        HTTP::respond 400 content "<html>There has been an error.</html>"

        return

    }

    HTTP::respond 200 content $result

   

}

![](../Images/089f78fd963fb75813cec25541702f1f.png)**小结**  

F5 API Gateway具备通信协议和通信内容的转换能力，满足API服务器到客户端的格式转换适配需求，在通信协议的转换中可以使用F5 BIG-IP内置的协议适配，在内容转换功能中，F5 API Gateway可做为一个使用TCL和NodeJS语言的二次开发的平台，使用内置对各种数据格式的解析的TCL方法以及JS方法，可以快速实现对内容格式的转换，实现广泛的API服务多协议适配场景。
