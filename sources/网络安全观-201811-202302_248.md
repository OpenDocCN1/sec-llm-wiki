# 从企业架构角度说一下：中台

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzIxNzUxNzA2NQ==&mid=2247492059&idx=1&sn=a9d674f72f78fb0c7b18fd563f8202fa&chksm=97fa3cbda08db5ab8e0f011ed2df7354e35237a2abe2a7d90bda2e76b6b488eb1b662de72551&scene=126&sessionid=1681323706#rd](http://mp.weixin.qq.com/s?__biz=MzIxNzUxNzA2NQ==&mid=2247492059&idx=1&sn=a9d674f72f78fb0c7b18fd563f8202fa&chksm=97fa3cbda08db5ab8e0f011ed2df7354e35237a2abe2a7d90bda2e76b6b488eb1b662de72551&scene=126&sessionid=1681323706#rd)

企业架构系列

> 这两年给阿里做了几期企业架构培训，和一些人员也有一些交流，他们也希望我说一下中台和企业架构的关系。中台出现是个好现象，但学习者应该从企业架构开始学起......

今年国内有个好现象，那就是“中台”变得越来越热，培训的也越来越多。学习中台的人员普遍是被市场和环境影响，不知道这个词或不了解如何去做，好像就要落伍了一样。但现实是，“中台”还没有达成一个或几个相对确定的定义，培训也只是一家之词。

  

找我做中台培训的基本也都比较急于求成。培训对于我们来说其实比较容易，做多少培训拿多少钱，可以不用管落地，而我做了多年企业架构，深知里面水有多深，所以我回绝了所有关于中台的培训。

![](../Images/c4d42fd2e2fad0003630922a5951e7e7.png)

  

对于“中台“在国内的兴起，我是非常支持和肯定的态度，因为这毕竟是来自我们国内自己的一大概念，开始也衍生了不同的方法论和工具，这对IT发展来说是有积极的作用。我在2017年写过一篇文章《[从技术角度杂说一下：中台](http://mp.weixin.qq.com/s?__biz=MjM5MDk2MTIwMA==&mid=2247487321&idx=1&sn=295e550d0c3fb182837abae5728de0c8&chksm=a6bd940691ca1d102a5a7e6dc8d104f2f387e7959e41a75885b4de573af59982d387a9fee6cf&scene=21#wechat_redirect)》，讲到中台背后的本质其实都是可以在现有的框架或方法中找到来源，今天准备从企业架构角度来说一下中台。

  

在[BangEA实践公开课](http://mp.weixin.qq.com/s?__biz=MjM5MDk2MTIwMA==&mid=2247490923&idx=1&sn=09a95b41944ec3dfe7729c5825fc6d0c&chksm=a6bd863491ca0f2285e026e3d93a9569781587a96817e006a9b345258d3631930466238d08a1&scene=21#wechat_redirect)中，我常和大家用下面这张图厘清一下架构实践的发展。

![](../Images/af8660c38c73c5fa19a7797da10d38fe.png)

  

要区分架构，A到B点是一个重要变化点，首先需要划分为项目级和企业级。中台是从企业IT复用和业务敏捷创新角度去看的，这和企业架构概念一样，都是属于企业级的。

  

谈到企业级，我们在《[企业级产品研发管理体系的构建](http://mp.weixin.qq.com/s?__biz=MjM5MDk2MTIwMA==&mid=2247490959&idx=1&sn=93d6bcf022bb874e336561d1af4f4f78&chksm=a6bd86d091ca0fc63d6b5220e8ee0cfecfbe22a50bb12c568a03365bfb0659023410af69f0c8&scene=21#wechat_redirect)》中学习到IPD其实就是从组织角度去考虑技术复用的[](http://mp.weixin.qq.com/s?__biz=MjM5MDk2MTIwMA==&mid=2247490959&idx=1&sn=93d6bcf022bb874e336561d1af4f4f78&chksm=a6bd86d091ca0fc63d6b5220e8ee0cfecfbe22a50bb12c568a03365bfb0659023410af69f0c8&scene=21#wechat_redirect)

![](../Images/590b8a695ed20272d8e902699146ca37.png)

在线上课程中，我们对每部分都有单独课时进行介绍，例如平台开发又有自己的流程和具体方法，其中技术开发又有自己的流程和具体方法。

![](../Images/1596f362ba757e33dec47faf987fc0af.png)

技术和平台开发，其实就是业务和技术的下层，这个中台出现的根源是有共同之处的，所以如果你了解组织级产品管理体系，你就知道中台研发管理可能会涉及哪些内容。

  

再回到架构实践成熟度这张图，B到C点是另一个重要点，也就从企业级IT到企业级业务的关注转变  

![](../Images/af8660c38c73c5fa19a7797da10d38fe.png)

IT的建设是为了满足业务的发展，中台的建设离不开业务。而我了解到，很多中台建设部门其实还是纯IT人员，他们其实不具备业务视角，也没有业务人员参与，这样的中台我不知道建设之后能起到多大作用。这样的中台建设会带来哪些问题？大家可能会说，中台是个新事物，如何规避这些风险呢？

  

其实，中台建设从某种角度来说，它就是企业架构实施的一个过程。企业架构作为企业级信息化规划和建设建设，从上世纪开始就已经存在，它已经有了相对成熟的体系和方法，也明确了要解决的问题。例如我们在BangEA实践课程中会讲到40个字，这些内容也是中台建设无法回避的障碍。

![](../Images/4556789d752611d45d1e1062fa036ba8.png)

除了中台，数字化转型也是一个热词。我们看看下图，企业架构在规划层，起到了承上启下的作用，为战略和实施架构了一个很好的桥梁，去解决上面提到的40个字。

![](../Images/1db4d9d69c6fb0b45f70647c068b2d6b.png)

中台是一个跨越规划和实施层的事务，它有企业级的架构和项目级的实施，在企业级架构部分用到的方法和可能遇到的问题，其实在企业架构中都早已总结，包括企业架构治理也都早已提出，以避免失败。  

  

企业架构方法也有很多，例如TOGAF、Zachman、BangEA等

![](../Images/7f2b65ce76c66c466792113cb41bcef8.png)

  

虽然具体内容不一样，但有一个共同的认识，那就是架构被归为四大领域：业务架构、数据架构、应用架构和技术架构。

![](../Images/4ba347489159d01fdd691badcc840208.png)

  

真正的中台建设离不开这四个架构领域，也就是说你如果做中台，你就要学习企业架构中这四个架构领域的最佳实践，而不能还是把它当做项目级的IT设计和编码工作了。

![](../Images/c5405deff2ad995f9722852a0d2dcd17.png)

![](../Images/013dc03e1b2716dfaf8956011d5adbee.png)

![](../Images/3f544a542ea991225537953a7c766f91.png)

  

如果有了这样的认识，你就会发现要学的东西其实还有很多。

![](../Images/eaef109197b6e061849c440816feec1f.png)

  

而上面这些内容在现在普遍的中台培训中都不会提到，大家关注的更多的还是技术层面的技术实现。这些技术的架构和实现在中台建设过程中很重要，但中台建设失败的来源是多方面的，而且更多的失败显而易见的不是来自于技术，而这些在中台建设中并没有受到重视。而这些在企业架构领域中早就帮助大家总结梳理了企业级建设框架，我们完全没有必要一定要自己从头走多遍再吸取经验。

  

既然提到中台，我们来看一下阿里巴巴数据中台的一张图：

![](../Images/d8c8773673e99c2a0640eb0e922cddd2.png)

“数据中台”是阿里提出的，出现的背景是阿里的生态系中淘宝、天猫、蚂蚁金服、盒马生鲜等业务，这些板块每天都会产生着大量有价值的数据，要在不同业务群间做到数据的互联互通，对数据价值进行最大化挖掘，所以需要整合各业务群的数据建立集团层面的“数据中台”，统一管理和应用数据。

  

大部分人学习中台看到的图基本上都是类似上面的样子，这种图示意很好，但对于架构师来说远远不够，这也导致后来者学习起来有很大挑战，看完也不知道该如何建设？那我们该如何去进行中台建设呢？上面那张图在企业架构没有完全对应的模型图，如果从企业架构角度来看，这张图包括的元素包括企业架构应用架构和技术架构领域，以及一些管理元素。做项目级架构我们会建模，如果要做企业级的架构，也一定要建模，这样画出来的架构图就是有理有据，而不只是示意图了。

![](../Images/7bcc3da05d57416772c9bb06a28f09ad.png)

  

关于数据中台，我在第三期七嘴八舌中有介绍，感兴趣也可以去听一下：

![](../Images/55f23612b3599ff5e26786e1b0ce72e3.png)

如果你们也准备去构建中台，我建议架构师还是从学习上世纪就有的企业架构开始，去系统的了解企业级架构是什么、为什么要建设，以及如何去建设，相信通过企业架构的建设可以让你更全面整体的了解中台是什么，对中台建设有合理预期，也知道在你自己的企业该如何去推动。

  

今天只是简单说一下企业架构和中台，首先是大家需要从项目级和企业级区分开中台与以往IT建设的不同，其次是在企业级角度下重视IT和业务的融合，不只是业务参与，甚至是业务主导。

![](../Images/5833a3fd7a9597dbde33aec4ab5b520f.png)
