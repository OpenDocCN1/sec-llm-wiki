**“****第七篇：****F5/NGINX与云原生之API优先”**

  

  

API是现代应用架构中的关键组件。广义上来说任何对资源组件进行抽象并形成规范化合约即为API。数据中心中的各种产品、服务器提供API，这是产品自身能力抽象的产品API。服务化开发下，各个模块同样提供API来实现服务间的调用，在微服务场景下，API则是单元服务对外暴露的标准方式。通过API对资源调用的抽象，在加速使用者效率的同时降低了外部复杂变化需求对开发者的干扰。同时越来越多的企业将API作为独立产品来管理，组建独立的包含API产品经理，API架构师，API开发者，API布道师的API产品团队，构建API的理念从单纯的项目思想转变为产品思想，通过不断吸取API使用者的意见来改进和迭代API产品，将API转化为能够为企业带来商业价值的数字经济，例如Netflix 50%的收入来自API。

不同形态的API具有不同的上下文意义，它可能是一个企业的重要商业模型的表现，也可能是企业重要业务产品的接入形态，在技术形态上API具有一定的通用性，首先来看看API gateway的类：

  

API gateway类型  

  

API gateway一般是作为系统边界存在，例如银行业务系统中的前置机其实就是一种API gateway，它对系统进行安全隔离，对服务进行抽象，同时还要负责认证、报文转换、访问控制等非业务性功能。现代API gateway得益于移动APP的飞速发展、企业对外部服务能力的进一步开放以及IoT的发展。总的来说API gateway从功能上主要分为：

![](../Images/3de3b0c8ca600e2efc3a45c53d44a64b.png)**Web/Mobile App网关**

这类网关主要为了分离前后端，由于企业可能存在多种形态的客户端应用，比如浏览器、iOS客户端、安卓客户端、通用Java客户端、机顶盒客户端等，相同的内容服务需要对这些不同形态的客户端进行适配乃至定制和优化，如果将这些非业务功能代码全部放到核心服务程序中，将对开发人员带来较大工作困扰及难度，通过将这些功能分离到前端API实现不同形态客户端的统一接入和转换，可使核心服务开发只需关注在业务逻辑上，复杂的终端形态适配可以统一由API gateway进行。  

![](../Images/3de3b0c8ca600e2efc3a45c53d44a64b.png)**Partner 开放API网关**

此类API主要是企业将自身服务提供给合作伙伴使用，比如API银行，支付网关接口等属于此类API，从安全域角度讲，此类API的一个重要功能就是隔离外部网络，增强企业网络安全性，除业务功能外，这样的API往往会增加验证、鉴权、访问参数控制、DDOS等诸多安全功能。

![](../Images/3de3b0c8ca600e2efc3a45c53d44a64b.png)**IoT智能设备网关**

随着智能设备，5G的发展，物联网将迎来新一轮的流量爆发，智能穿戴、家庭智能产品、智能汽车、工业传感器将频繁发送海量数据。智能设备的API主要负责数据的安全传输，专有协议如MQTT的接入与转换到内网进行数据处理，并能够支撑海量高并发数据。高性能、高吞吐、高安全是此类API的重要关注。

  

API gateway作用价值  

  

无论哪种形态的API gateway，其作用与价值主要表现在以下几个方面： 

![](../Images/3de3b0c8ca600e2efc3a45c53d44a64b.png)**隔离**

隔离是对企业系统安全的一种保护，由于API是在边界提供给企业组织之间或企业外部进行访问的，因此保证企业系统不受有威胁的访问是API的首要作用。API网关首先应能够保护业务系统免受意料之外的访问，这包含不正确或不规范的访问请求，恶意探测，DDOS攻击等，因此API网关自身在建设上需要考虑这些能力，无论是自主开发或是通过在API网关前部署专业的API保护设备。

![](../Images/3de3b0c8ca600e2efc3a45c53d44a64b.png)**解耦**

服务的提供者往往希望服务具有始终稳定的服务提供能力，因此往往不希望受到太多的外部功能需求的干扰，但是业务的快速发展决定了业务访问方的需求是多变的，因此通过在服务提供方与服务访问方之间设置一个中间层，通过该层封装不同的业务访问请求并按照统一的服务提供方要求进行转化并访问。通过这样一个中间层，将两个完全不同诉求的双方有效的调和起来，实现解耦。

![](../Images/3de3b0c8ca600e2efc3a45c53d44a64b.png)**插件**

从位置与形态上看，API gateway类似proxy的角色，除了负责请求的接收、路由、响应外，还可以执行诸如流量控制、日志获取可视化、安全控制等。同时由于业务可能快速变化，如果核心业务功能无法在某些方面快速实现需求，API gateway可通过插件化的设计实现自定义功能的扩展，例如通过对请求的改写，内容控制，多样化验证接入等能力，可以通过快速开发插件或通过F5这样具备接入与内容控制能力的设备来快速达到目的以适应业务灵活多变的需求。

  

API gateway的架构设计  

  

API gateway在系统架构上主要需从以下角度考量：

![](../Images/3de3b0c8ca600e2efc3a45c53d44a64b.png)**安全防护**

API  gateway应充分考量安全方面的处理，这包含DDOS防御，XML/JSON等内容防护，协议安全，认证、授权，SSL加解密等。尽管很多功能可以通过软件开发实现，但这些功能完全可以通过在API gateway前部署专业的API安全设备或模块来进行，这使得API gateway自身可以更加专注在对外能力的提供上。同时，由于API gateway本身就是一种聚合式的统一入口，即便是现代分布式架构，对外的API依旧表现在统一的入口上，因此在API  gateway前部署高性能高安全的硬件类设备并不违背现代分布式架构的理念。

![](../Images/3de3b0c8ca600e2efc3a45c53d44a64b.png)**流量控制**

流量控制表现在对连接或请求的控制上，避免突发请求造成API gateway服务能力的下降或不可用，这包含API的并发请求数，单位时间调用数，连接限制能力，TCP 队列能力以及TCP连接复用能力等方面。甚至在极端情况下对API能力的主动熔断与降级。

![](../Images/3de3b0c8ca600e2efc3a45c53d44a64b.png)**访问控制**

访问控制是对请求参数的控制，例如对XML或 Json Schema的校验，对请求URI中的参数细粒度控制能力，确保有害请求无法影响业务系统。本质上这类似于WAF产品所提供的保护能力。

![](../Images/3de3b0c8ca600e2efc3a45c53d44a64b.png)**监控跟踪**

实时提供对API的监控，包括：请求数，调用方式，响应时间，失败率等，并将这些数据集中高性能采集，实现可视化报表并基于智能学习等方式建立访问行为、基线数据。

![](../Images/3de3b0c8ca600e2efc3a45c53d44a64b.png)**高可用**

API gateway本身应具备高可用能力，避免局部实例或服务器故障对业务的影响，在加入新的gateway时应能够做到慢启动，确保gateway可以提供业务能力后方可接入请求；而在变更或下线gateway时候又应做到优雅下线，避免已经存在的请求被强行中断。

![](../Images/3de3b0c8ca600e2efc3a45c53d44a64b.png)**高性能/高弹性**

API gateway本身应具备横向和纵向的扩容能力，以保证无论是有状态还是无状态gateway都能拥有最佳的扩容方式，一般来说API gateway都以集群形态出现并在前端通过负载均衡类设备提供水平扩展能力。

  

API生命周期管理  

  

![](../Images/52ac77f6322565515eff66fb3a9e8331.png)

API的生命周期管理主要包含以下几个方面：

![](../Images/3de3b0c8ca600e2efc3a45c53d44a64b.png)**API的定义与发布**

实现对API的资源定义、URL格式定义、集中化策略、版本化处理等高级功能。

![](../Images/3de3b0c8ca600e2efc3a45c53d44a64b.png)**API 开发者门户**

为API的消费者提供注册，反馈，API接口文档查询，范例介绍等功能实现消费者自服务，为消费者提供统一的dashaboard展现调用统计、性能、计费等。

![](../Images/3de3b0c8ca600e2efc3a45c53d44a64b.png)**API安全**

API是企业的商业价值所在，是产品的重要访问方式，通过提供诸如JWT,OIDC,SAML,Oauth等验证能力保护API，使用TLS保护传输安全，限流，限制机器人对API的访问等安全手段保护API。

![](../Images/3de3b0c8ca600e2efc3a45c53d44a64b.png)**API监控**

API是外部外部调用应用正常运行的基础，因此需要监控API性能数据，5xx等失败调用统计，保证API高可用来确保API处于良性运行状态。

![](../Images/3de3b0c8ca600e2efc3a45c53d44a64b.png)**API分析**

API作为企业的重要产品，通过可视化洞察分析消费者使用行为、调用频率、消费趋势，产生用户消费报告等为运营提供更多metric数据进行商业分析，为迭代更好的API产品提供反馈信息。

![](../Images/3de3b0c8ca600e2efc3a45c53d44a64b.png)**API商业化**

通过提供自服务化的注册、计费、支付等方式方便消费者进行消费，提供更棒的消费体验来增加API的商业收入。

  

F5/Nginx与API gateway  

  

API gateway所强调和拥有的能力与F5 BIGIP应用交付控制器以及Nginx有着重叠，比如API gateway的水平扩展依赖于负载均衡机制，安全防护可在LB基础上集成A.WAF模块实现API方面的深度内容防护，这包含通过智能学习参数行为并进行控制、机器学习实现基于行为的DDOS防御、对XML,JSON进行深度内容识别和检查。可通过TCP queue，基于连接或URI请求速率限制来保护API gateway，通过slow start、优雅下线等功能保证业务的连续性。F5 BIGIP可通过类似DPDK技术实现请求日志高速发送到kafka等消息队列中实现日志的统一输出，并可以在metric中直接提供请求方法、调用的URI及参数乃至Post内容、错误响应状态、API调用延迟等数据。F5 Access接入管理模块则可实现诸如SAML,OAut,JWT验证能力，通过高性能的TLS offload实现数据加密。

![](../Images/e43892bb6bab5f80a5356e572fc45dbb.png)

Nginx以更加灵活的软件形态融入服务作为API服务网关实现API的定义发布，带外策略管理、验证、安全防护、监控分析等能力。

在API访问接入上可采用F5硬件设备提供统一高可靠接入，并实现总入口连接限制、HTTP/JSON/XML安全控制、基于设备指纹的BOT防御管理，API监控，在具体API前端采用Nginx实现各个API的资源定义与发布，版本化处理，高级访问策略控制，更细粒度的API安全，在端到端的监控与可视化分析上可采用F5/Nginx统一控制器实现集中数据遥感与展现并可将API的访问统计数据统一输出到企业API业务分析平台进行商业化分析。

在API数字经济时代，API产品需要不断的快速迭代以适应市场，因此API的开发是典型的敏捷开发模型，这要求围绕API的开发、发布、管理都要能够适应CI/CD，F5/Nginx通过提供诸如Declarative Onboarding接口，声明式配置AS3接口，Jenkins，Ansible集成，Nginx Controller RestAPI等丰富多样的CI/CD工具集帮助实现快速发布与部署。
