简介


实现应用交付与安全设备部署和配置管理自动化势在必行。在 2017 年 IDG FutureScape 报告中，自动化和多云管理被列为到 2021 年将影响企业的关键措施。[1] 自动化支持以可扩展、可靠和集成的方式部署应用所需的基础安全、优化和可用性服务，并且让它们的交付成为编排式构建、测试和部署工作流的一部分，这些工作流正在成为应用部署的主要模式。

 

即使像添加新的虚拟服务器或池成员等基础任务的简单自动化也能够为应用所有者或其他自动化系统提供自助服务功能，支持将更多时间用于构建全新自动化工具等更重要的工作。

 

当企业开始采用多个云平台提供IT 服务时，自动化会变得更加重要。如果您想把服务部署到具有不同平台特征的多个位置，自动化可帮助您降低不断升高的运营开销，并减少由于不熟悉新平台所造成的错误。

 

但我们应该如何实现自动化及对哪些环节实施自动化？由于具有不同的操作模式、界面和语言，自动化软件可在单个设备层运行，也可作为更复杂的多系统工具使用。基础设施即服务（IaaS）云平台全部都提供自己的本地工具部署虚拟基础设施和服务。此外，F5 提供广泛的界面和编排选项。尽管广泛的工具和选项可以让您采用最适合企业的方法实现自动化，但选择合适的工具可能是一件艰巨的任务，另外复杂性和工具激增的风险是真实存在的。

 

在本白皮书中，我们将概述实现F5 BIG-IP设备（物理和虚拟设备）部署、管理和配置自动化的方法，以及关于如何选择适合路径的一些建议。



自动化：主要考虑因素

 

自动化的范围

自动化涵盖了各种活动。它的一端是使用 Bash、TMSH、Python 或其他语言编写和开发的简单脚本，这些脚本可在本地运行以加快手动配置活动的速度。另一端是一个完整的“基础设施即代码”系统，它整合源代码管理、工作流编排器和（潜在的）多种自动化工具，以创建一个基础设施配置由存储库内包含的文本文件定义并由它修改的系统。在这两种极端情况之间，许多不同选项可帮助您管理 BIG-IP 平台的部署和配置。



可变与不可变

大多数当前的BIG-IP 部署都可视为是可变的，这意味着它们的配置可能会随着时间而变化。这是因为 BIG-IP 平台在多数情况下用作为多个应用提供服务的多租户设备。随着新应用部署或现有应用扩展或需要额外的服务，BIG-IP 的配置将相应地更新。这种部署方法使基础设施团队能够管理一组集中化基础设施，通过一个共同平台为应用提供服务。

 

但是，有时候BIG-IP 平台作为独立应用堆栈的一部分部署，特定 BIG-IP 的服务与特定应用或服务绑定。在这种情况下，我们可将 BIG-IP 配置视为不可变；也就是说，配置在启动时安装或者作为软件映像的一部分安装，在 BIG-IP 实例生命周期期间不会改变。通过更改软件映像或启动代理脚本内容然后重新部署，配置变更就会生效。这种模式通常被称为“推倒重来（nuke and pave）”。尽管总体上不是很常用，可支持按应用实例部署的全新 BIG-IP 许可模式、增强的许可工具以及像 F5 云库（一套 Node.js 脚本和库，可帮助您将BIG-IP 添加到云中）这样的工具正在让这种部署模式成为一种可行选项，非常适合其应用需要紧密关联但又彼此分离的代码和基础设施堆栈的企业。



声明式与命令式

对于自动化界面如何呈现给消费者，存在两种概念模式。最常见的“第一轮”自动化模式偏向于命令式模式。在命令式自动化模式中，自动化消费者通常需要了解自己想要实现的目标以及实现目标的明确步骤（通常利用API 调用）。这通常会给消费者造成负担，他们需要费时了解高级服务的配置详情，同时还会增加复杂性，需要将服务与自动化工具相集成。这类似于想要吃三明治还要具体说明做三明治的每个所需步骤，而不是只提出想吃三明治的想法，具体怎么做自然有三明治制作者操心。

 

相反，使用声明式界面时，消费者（人或机器）只需提出要求，服务便可快速创建完成。它并不要求消费者具备所有所需步骤的详细知识，因为自动化目标使用预配置工作流或服务模板基于要求的结果创建配置。尽管声明式界面的初始设置稍微复杂一点，但是一旦构建了合适的服务模板，操作就会大大简化，因此这种复杂性也就不值一提。总体而言，这让它成为构建自动化系统的首选机制。

 

直接或通过管理工具

您需要考虑的另一个决定是，自动化API 调用请求应该直接从第三方工具发送至需要修改的设备，还是通过额外的管理工具发送至这类设备。相比直接连接到托管实体，管理工具可以抽象化和简化操作并可提供额外的控制和记录层。但是，您需要支持该工具，以确保在需要快速进行更改的能力时管理层高度可用。



API、启动代理还是 CLI？

BIG-IP 设备通常通过 REST API 实现自动化，后者可通过成文样板呈现大多数 BIG-IP 功能。F5 提供的 Ansible 等自动化工具模块大量使用了REST API。除了提供预设置、命令式界面，REST API 调用可用于启动 F5 iApp 模板，在这里，配置 iApp 服务的值作为 API 调用中的 JSON 有效负载传递。新增的 iControl LX 功能也能够创建一个可通过单个API 调用执行多步骤操作的用户定义的API 端点。


实现 BIG-IP 配置自动化的另一种常见方法是使用启动代理，它在启动时运行并能够提取外部信息来配置 BIG-IP 平台。启动代理通常用于执行初始配置以增加设备，能够从GitHub 等第三方站点或您自己的存储库中提取额外的脚本和配置文件。启动代理还可用于完整地配置 BIG-IP 平台，尤其是如果您选择固定的按应用配置。

 

最常用的启动配置是 cloud-init，它在所有 BIG-IP VE 映像中启用（Microsoft Azure 除外），但是最适合用在AWS 和OpenStack 部署中。除了 cloud-init 外，F5 还提供一系列云启动库帮助在启动时配置 BIG-IP。

 

如果您选择在启动后使用启动代理配置平台，请注意使用外部资源时可能出现的管理故障，尤其是当实例作为扩展活动的一部分启动时。如果外部资源不可用，系统将会如何表现呢？是否会为了满足需求创建额外的僵尸设备？

 

在一些情况下，自动化系统能够以用户身份运行，执行 CLI 命令。尽管这偶尔能够解决 API 调用可能无法解决的一些问题，但总体而言，支持困难以及解决方案的脆弱性使该方法成为不得已情况下的最后选择。

 

模板和手册

模板和手册可创建自动化部署和构建具备一定标准化水平的基础设施。合适的标准化水平可让您的基础设施更强大和更可靠。精心创建的模板可提供声明式界面，请求实体（用户或机器）只需知道所需的属性，不需要了解实施详情。通过模板严格部署并仅通过更正模板进行补救能够提高服务质量，帮助立刻修复问题，通过新模板重新部署服务。

 

平台集成

平台集成工具将 BIG-IP 服务的配置与私有云或容器管理系统等计算平台相结合。各种平台和实施的机制各不相同，但总体可分为三种模式：


1

将 F5 服务替换到现有平台构造中

在该模式中，F5 服务使用现有的平台构造插入，比如将 F5 服务用作 OpenShift Container Platform Router 或将 F5 服务与 OpenStack Load Balancing as a Service（LBaaS）系统一起使用。使用这些机制需要对操作程序进行一点修改，因为平台本地接口用于配置服务，并且提供的驱动程序和其他软件将平台配置指令无缝转化为F5 配置。但需要记住的是，只有通过平台本地接口获得的功能才能够轻松部署。


2

订阅平台事件

另一种常见集成方法是用软件模块（比如ContainerConnectorforKubernetes和 ContainerConnectorforMesos）订阅平台内的事件，然后根据事件修改配置。您可以标记需要服务的应用，然后配置连接器软件监控带有所需标记的事件，从而选中要部署的事件和服务。


3

集成平台管理工具

很多私有云平台拥有专为自动化设计的管理系统。例如，VMware拥有几个管理和集成工具，包括 vRealize Orchestrator（vRO），里面有一个用于 BIG-IP 配置的第三方插件。再比如面向 OpenStackHEAT 模板系统的插件。


 

服务发现

虽然不是完整的自动化解决方案，服务发现却是一种集成 BIG-IP 配置和环境中变更的简单、有效的方式。服务发现通过 API 定期轮询云系统以检索资源列表，然后相应地修改 BIG-IP 配置。这在资源被配置成自动扩展群组的环境中尤为有用，因为扩展后端计算资源需要负载均衡器了解新的资源。服务发现组件与面向 AWS 和 Azure 的 F5 云自动扩展解决方案一起提供。

编排和工作流工具注释

上述工具和集成代表了部署和配置BIG-IP 平台以提供应用可用性、安全性和扩展服务的自动化方法。这些服务尽管必不可少，但只是组成完整堆栈应用部署的一部分。协调、可靠地创建具有服务器、数据、编译应用代码和基础设施的完整应用堆栈不能仅依靠简单的自动化工具。


您需要带有相关工作流以及与大量自动化系统集成的更高级编排工具。这些工具最常用于持续集成/持续交付（CI/CD） 工作实践中，对于所有实际实施而言，自动化都是必须的。尽管存在大量编排工具，Jenkins 可能是最常用的工具，里面提供了示例工作流，展示了如何使用 Jenkins、F5 和Ansible 解决方案将 F5 基础设施即代码功能整合到 CI/CD 工作流中。但总体而言，编排工具将使用其中一种配置自动化工具进行修改以部署服务。

 

许可

BIG-IP 平台需要许可才能运行，因此在关键的自动化路径中包含许可很重要。在多变的环境中，为了测试和开发目的可能需要快速扩展或缩小或者创建BIG-IP 虚拟设备，这时候就应该仔细考虑许可模式。

 

在公有云中，一种途径是使用BIG-IP 的按需计费计费版本（通过云市场提供）。按需计费实例将采用自助许可，云提供商会按照随用随付模式或者承诺使用时间收取费用。

 

另一个选择是使用通过订阅（或永久）购买的可重复使用许可池以及F5 BIG-IQ 许可管理器，后者可支持您通过池分配和撤销许可。

 

您可以通过启动代理和API 调用实现许可步骤自动化，这需要对 F5 许可服务器的出站互联网访问（即使是云平台中的实用程序许可也是这样）。



使用什么，何时使用？


企业情况不同，选择合适自动化和编排工具的难易程度也不一样。如果您已经采用了面向其他组件的工具或方法并且只需要将 BIG-IP 集成到系统，那么选择就会很简单。即使没有集成到特定工具，丰富的 iControlREST API 以及iControlLX 功能和 cloud-init会让 BIG-IP 集成到现有自动化工具的操作变得相对简单（尤其是如果结合了 iApp 模板使用的话，这些模板可用于借助单个API 调用创建复杂的配置）。

 

但是，如果您是从头开始，那么事情会更复杂一点。正如选择任何其他解决方案一样，首先应该先了解您的需求。尽管本白皮书不能指导您生成需求列表，但我们提供了一系列问题和建议，帮助您进行评估。



自动化模式：


声明式模式会更易于您的编排消费者使用。消费者只需要知道自己想要什么，而不需要了解实现目标的所有程序化步骤。



潜在平台和环境：


此时我们似乎需要假设容器和各种云平台将成为应用基础设施的关键组成部分，并做好相应规划。


技能：

 

您是否已经掌握了一些基础技术的技能？请记住，您所在部门可能没有这些技能，但公司层面会有。如果是这样的话，最好选择使用贵公司已采用语言的工具。



可支持性：

 

只构建您能够支持的系统。这看起来可能显而易见，但成功的关键是选择您可以在企业内应付的复杂程度，以便您最大限度地发挥自动化优势，同时不会产生额外的运营开销。



F5 私有云解决方案包

 

F5 私有云解决方案包可帮助轻松获取所需的技术和服务，以在大量私有云环境中提供F5 应用。解决方案包将软件、硬件和专业服务捆绑到一起，可为大量私有云平台创建一个经过验证的交钥匙解决方案。使用私有云解决方案包能够为您提供一个部署范例，然后将其复制到其他平台中，创建一个跨多种环境的更加统一和一致的应用交付与安全服务集合。



总结

 

IT 自动化水平的提高势在必行。采用战略方法提供关键的应用交付与安全服务可确保您企业部署的应用始终安全、可用。自动化还可帮助您降低运营开销，尤其是当采用多个平台和公有云时。

 

选择合适的自动化系统具有一定挑战性，需要紧密协作，并通盘考虑技能、系统的可支持性等各种因素。无论您选择哪一种解决方案，BIG-IP 平台和 F5 专业知识都可帮助您轻松提供应用所依赖的企业级服务，无论应用部署在哪里。
