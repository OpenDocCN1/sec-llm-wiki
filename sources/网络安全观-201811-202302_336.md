Cloud Native ADC是什么  

  

在以企业为中心的数据中心场景下，基于传统数据中心应用发布需求的ADC产品越来越不能够适应当前以应用为中心的发展趋势，云原生应用的发展要求应用交付产品具有更加灵活的多云部署能力、富有弹性的架构、能够更好的融入CI/CD pipeline中，以及拥有更高性价比。传统ADC产品的生态在数据中心运维；Cloud Native ADC生态则更加面向DevOps，帮助企业实现更加弹性和敏捷的应用交付，Cloud Native ADC一般来说应具备以下特征：

*   产品本身基于云原生思想开发，遵从12要素(The Twelve-Factor App)指导
    
*   独立的控制平面与数据平面，具备弹性扩缩容服务能力
    
*   微服务化设计思想，各服务组件相互独立，服务间以gRPC等形式实现服务调用
    
*   平台无关性，能够在任意公有云、私有云、混合云间无缝迁移，且保证一致性
    
*   API 优先，提供声明式的API服务接口，具备配置幂等性，与CI/CD pipeline紧密结合实现代码即架构
    
*   轻量级快速部署，基于容器并具备组件服务编排能力，能快速启动服务
    
*   基于策略的流量管理能力
    
*   以每应用为中心的集中可视化洞察
    
*   以每应用为单位的弹性应用安全保护
    
*   统一日志收集与管理

Nginx - Cloud Native ADC  

  

![](../Images/3de3b0c8ca600e2efc3a45c53d44a64b.png)**开源Nginx**  

Nginx作为知名web server及反向代理服务软件，运行在近4亿网站上，世界Top 1000网站中有50%的网站采用Nginx，同时Nginx也是大量开源或商业软件的底层基础。无论是大型互联网公司还是金融企业都大量部署着Nginx。Nginx的非阻塞模块化设计使其拥有高并发高性能稳定的特点，Nginx社区充满活力，让Nginx拥有大量的第三方模块。

Nginx具有轻量、软件化特点，非常适用于进行大规模部署，无论是在本地数据中心还是在多云环境下，都有着良好的适应性及扩展性。Nginx也是kubernetes中默认的Ingress Controller。

![](../Images/4db7b9b9cbb52c29aa79a003274a95c9.png)

Nginx Plus是基于开源Nginx进行增强的企业级产品，本身支持API接口，可通过Nginx Controller进行配置管理、软件自身及应用性能集中可视化监控与分析，其中动态管理无需通过手动修改配置文件和重启。Nginx Plus拥有应用层健康检查、更丰富的LB算法、WAF以及API gateway功能。Javascript模块支持对访问进行动态处理，同时支持Lua脚本语言。

  

![](../Images/3de3b0c8ca600e2efc3a45c53d44a64b.png)**Nginx Plus API管理**  

  

围绕企业API生命周期管理对API进行定义，发布，安全，监控，流量策略等方面管理, API管理详见后文“API优先”章节。

  

![](../Images/3de3b0c8ca600e2efc3a45c53d44a64b.png)**Nginx unit**  

  

一款多语言支持的动态应用服务器，支持Go, Node.js, Perl, PHP, Python, and Ruby，支持API接口动态配置管理，Nginx unit的多语言框架为为service mesh提供了应用服务器基础，帮助企业安全高速跨语言互联各个微服务。

  

![](../Images/3de3b0c8ca600e2efc3a45c53d44a64b.png)**Nginx微服务模型**  

Nginx推荐三种微服务模型，帮助企业解决不同阶段微服务化需求：

**Proxy模型：**使用Nginx或Nginx Plus作为外部代理处理南北向流量，对于服务之间的东西流量通过与服务注册配合，使得东西流量走外部代理服务器，使服务获得Nginx Plus的诸多特性与能力，同时这支持Nginx作为API gateway部署。这与在外部使用BIG-IP解决方案类似。此访问只适合小型服务或尚处在微服务改造前期的场景。

**Router-mesh模型：**在Proxy模型基础上，在微服务内运行Nginx/Plus容器实例集群，并通过与服务注册/发现配合，通过与编排平台接口协调将服务之间的访问流量导向到Nginx上实现Hub式通讯。此模型适合中等规模，或已经实现了Proxy模型并希望进一步增强微服务能力的场景。

**Fabric 模型：**这是一种类似Sidecar的模型，通过为每个服务实例运行一个sidecar容器实现服务间代理通信。

关于以上三种模型，详细可参考Nginx Microservices Reference Architecture(MRA)

  
F5与Nginx  

弥合开发与运营鸿沟，实现从代码到客户的统一交付。F5收购Nginx后，帮助客户实现了业务路径前后统一应用策略交付，互补两者不同优势，进一步增强L4/L7分离架构的交付能力，实现统一监控、全路径应用可视化与洞察，开发运维（DevOps）将进一步得到融合与增强。F5硬件交付控制器帮助交付更高性能，更加安全，更加复杂的应用; Nginx则以轻量级形态与简洁易用的功能实现应用侧更加灵活方便的交付，无论是多云环境还是PaaS平台。统一应用交付控制中心帮助企业简化从代码的开发到数据中心的运维发布流程，并实现统一的数据管控，真正实现统一应用交付。
