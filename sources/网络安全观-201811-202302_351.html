“第三篇：F5/NGINX与云原生之拥抱DevOps”


DevOps从字面上来看是Dev（开发人员）+Ops（运维人员）结合，实际上，它是一组过程、方法与系统的统称，其概念从2009年首次提出发展到现在，内容非常丰富，包括组织文化、自动化、精益、反馈和分享等诸多方面。首先，组织架构、企业文化与理念等，需要自上而下设计，用于促进开发部门、运维部门和质量保障部门之间的沟通、协作与整合，简单而言组织形式类似于系统分层设计。其次，自动化是指所有的操作都不需要人工参与，全部依赖系统自动完成，比如持续交付过程必须自动化才有可能完成快速迭代。再次，DevOps的出现，是为了按时交付软件产品和服务，开发部门和运维部门必须紧密合作实现缩短产品从开发到部署的周期。DevOps强调的是高效组织团队之间如何通过自动化的工具协作和沟通来完成软件的生命周期管理，从而更快、更频繁地交付更稳定的软件。

F5

如上所示，DevOps包含了多个部门之间的协调工作，软件产品需要经历开发、测试、生产运维多个阶段，那么在这样一个价值流的传动过程中，F5是如何来适应这样一个过程，以及采用了哪些技术来实现自动化。


统一TMOS


F5提供了统一的软件系统（TMOS），无论是公/私有云中运行的虚拟化版本，还是硬件设备上运行的版本，都提供了相同的TMOS系统，在界面、功能、特性上完全一致，这可以保证无论是在开发、测试还是生产环境，都可以拥有一致的架构与配置，从而确保拥有一致性的F5环境与配置。开发人员可以在本地开发环境安装使用低吞吐量或Lab license VE产品，保证在开发人员的本地模拟架构中即拥有F5. 测试部门则可以利用VE或测试环境的硬件F5实现与生产一致的环境配置并进行测试。


自动化Onboarding


在开发测试环境搭建过程中，会随时根据需要自动化的拉起一台F5 VE，根据DevOps理念，系统的onbarding过程需要能够自动化，避免人工干预。为此F5根据不同环境提供了多种onboarding方法，Vmwware下的vRO, Opensack环境的heat部署模板，AWS下提供CFT模板，Azure下供ARM模板，V13版本后还提供了Cloud-init开发包帮助用户通过Terraform，Ansible等自动化工具实现代码即架构的声明式定义。F5 Declarative onboarding支持通过申明式接口进行设备的激活、基本网络配置等。

自动化License


为了满足敏捷的开发部署环境，在开发、测试、运维的任何一个环节，都有可能需要自动化的拉起与配置一台F5，因此需要保证本地自动化的license管理。为此F5提供了多种灵活的License模型，例如License Pool，企业License（ELA）等，借助BIG-IQ自动化的实现VE与设备的License激活与吊销。


接口与自动化工具链


自动化配置、部署是DevOps中具体的技术要求，唯有完全实现自动化，才能完全发挥DevOps对业务的促进作用。


RESTful API

F5/Nginx Plus提供Ansible、Puppet、Chef、Terraform等自动化工具的模块集成，帮助更好的实现自动化集成工作。其中Ansible提供官方F5 support支持。


Yaml支持

在容器化编排平台（k8s等）提供平台支持原生声明式（YAML）配置能力。无论是F5 BIG-IP还是Nginx都与容器云平台的深度集成。


公/私有云集成

在Openstack环境中提供Heat模板实现业务自动化部署。在ACI环境下提供Device package。
在Azure，AWS等公有云环境下提供Cloud template，支持公有云下应用的自动化部署。

开发者通用库

Python SDK为开发者提供了如何通过REST API接口进行F5配置通用开发库。


CRD能力

iControlLX是F5控制平面的扩展的底层基础，通过提供iControlLX使得用户可以开发自定义的API接口能力，满足用户在Devops Pipeline中的定制化需求。
RESTful API 则可通过定义调用脚本提供原生API资源之外的Custom Resource Definition 能力，诸如对BIND、连接控制等接口能力。

IaC能力

F5已提供Application Service3（AS3）帮助用户更灵活实现架构即代码（IaC）的声明式业务配置，使用相同的JSON文件获得幂等的业务配置。AS3帮助抽象复杂的配置对象定义，使得开发人员无需掌握过多的domain expertise即可集成F5到Devops pipeline当中，并可以实现更加灵活的基于版本控制。例如开发人员可以借助自定义开发的模块实现基于Github webhook接口进行自动化配置管理，配置管理完全Github化。

Nginx的配置管理则是原生IaC思想，文本配置文件可以以版本化方式管理，也可以通过crossplane实现文本与json的相互转化从而更好的实现代码管理。


RBAC/应用模板/iApp


DevOps中很重要的一点是强调部门间的协作，在实际场景中，一个业务的发布需涉及到多种环境与技术，例如网络、系统、中间件、应用、安全等，这些技术或产品可能分属不同的部门来管理，各个部门具有不同的利益诉求，应用开发部门希望更快捷的应用部署而无需关心底层网络，而网络部门则希望应用在进行部署时能够遵循既定的网络规范与策略，由于部门利益或技术壁垒使得这些诉求变成了潜在的矛盾冲突，因此需要通过技术形态来调和这些问题，F5 BIG-IQ提供基于角色的访问控制（RBAC）进行细粒度的权限划分，并容许网络管理员定义应用配置模板，应用部署人员在部署应用时只需使用确定的模板，填写简单的应用信息即可，与网络环境强相关的配置已被网络管理员通过模板的方式进行了标准化和对应用部门的屏蔽，这实现了不同利益诉求部门的矛盾调和。同时，这些应用模板可以理解为应用编排代码并存放在如Github等系统中，融入CI/CD自动化流程，从而通过工具、脚本实现存放、提取、部署等动作。
