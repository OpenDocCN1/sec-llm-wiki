# **一、传统网络架构的问题**

在当前的技术体系下，数据在网络中的转发，是网络设备通过标准化的协议进行信息传递，各自计算，最终得出一个最优的下一跳网络设备节点，如此循环，直到将数据转发到目标服务器。这使得每台设备维护着各自的信息，一旦发生网络故障，很有可能导致全网设备的信息需要重新计算。

在传统数据中心网络环境下，通过“烟囱”式的网络架构，不利于业务的快速部署、敏捷上线。究其原因，是因为区域较多，网络设备类型及数量多，在变更时需要按照一定的顺序去对设备进行配置。

随着应用技术的发展，云计算，容器，微服务等技术的运用，传统以南北向为主的网络流量逐步转向以东西向流量为主，这对数据中心计算资源提出了资源池化的要求。而传统的网络架构由于技术上的限制，无法满足大规模计算资源池的部署，造成业务对计算资源的需求无法满足。这样，数据中心的主要矛盾逐步变成业务的增长对计算资源的需求和网络技术限制之间的矛盾。

以上场景分别从数据中心网络的内因和外因分别描述了传统数据中心网络所面临的问题。试想，如果有一个平台能够做到网络状态信息的统一收集，设备配置的统一下发，这势必能够提高网络效率。同时，统一化管理也打破了传统网络区域的划分，从技术上解决了大规模计算资源池部署的限制。

数据中心网络设备的多厂商、多种类、多型号、多系统，导致网络设备硬件、网络功能和网络资源之间的强耦合，若想实现网络的统一管理平台，首先需要进行硬件与功能和资源的解耦，实现的方式就是虚拟化。网络技术中有三种方式的虚拟化，分别是设备虚拟化、网络虚拟化和网络功能虚拟化，不同的虚拟化方式应对的是数据中心不同类型的部署场景，下面对这些虚拟化方式进行逐个介绍。

# **二、网络设备虚拟化**

网络设备虚拟化，顾名思义，就是将物理设备的资源在逻辑上再分配的过程，有“一虚多”和“多虚一”两种方式。在“一虚多”模式下，是将单台物理设备逻辑上划分为多台设备的过程，以实现设备资源最大化的利用。目前我们使用最多的网络设备虚拟化主要有VLAN（虚拟局域网）、VRF（虚拟路由转发）等技术。 “多虚一”模式主要是将多台网络设备通过堆叠，FHRP（首跳冗余协议）实现的虚拟化,在网络中将多台（通常是2台）设备看作1台设备。

设备层面的虚拟化技术是虚拟化的初级阶段，也是向网络虚拟化、资源池化的必经阶段。  

# **三、网络虚拟化**

现在网络有个比较流行的技术叫“大二层”，所谓“大二层”，就是在逻辑上将所有的ToR（柜顶）交换机全互联，在逻辑上来看，整个数据中心就像一个大的交换机，所有的计算资源都连接到这个交换机的接口上。很明显，“大二层”整合了数据中心内部的网络交换机资源，为实现网络资源的统一管理迈出了第一步。

数据中心网络的“大二层”就是统一交换机的控制平面，实现交换机的控制平面与转发平面进行逻辑上的分离，是更高阶的网络交换机“多虚一”的虚拟化模式，实现这个模式有多种方式，下面逐一进行分析：

    1.  传统二层结构。使用VLAN隔离，无控制平面。每台设备上都会有大量的VLAN，设备上还会存有大量服务器的MAC（媒体访问控制）地址， ARP（地址解析协议）广播全网泛洪，会占用大量带宽，造成数据中心内部网络的瓶颈。

    2.  MAC in IP（网际协议）。目前主流的技术实现方式。使用vxlan（虚拟扩展局域网）协议+BGP（边界网关协议） EVPN（二层私有网络）技术来统一网络设备的控制平面。这种方式克服了传统二层结构几乎所有的问题，但是涉及传统的IGP（内部网关协议）和BGP路由协议，以及VRF之间和VRF内部VNI（vxlan网络标识）的联通方式比较复杂，在初期上线时工作量较大，后期维护的成本也较高。另外，还涉及不同厂商间vxlan兼容性问题较多，结合实际情况，需对设备部署进行统一规划。

    3.  商用SDN（软件定义网络）。目前主流的企业网络解决方案。MAC in IP的方式为网络提供了统一的控制平面，SDN控制器的出现则优化了这种部署方式。通过SDN控制器进行配置下发，设备状态的监控和信息收集功能，实现网络交换机的快速部署、统一监控和管理。但SDN控制器与网络设备是强耦合的，不同厂商由于使用南向控制协议的不同而不兼容。

    4.  开源SDN。目前公有云主流的网络解决方案。开源SDN控制器只能对开源虚拟交换机（OVS）进行统一管理，通过云平台对SDN控制器进行应用编排，将OVS所需的转发信息下发到OVS上，实现整个网络的虚拟化。但虚拟交换机在性能方面是瓶颈，虽然目前可通过硬件加速技术来提升性能，但是在虚机数量、虚机迁移等方面有较大的弱势，所以大规模部署时需要很强的二次开发能力来消除这些瓶颈。

    5.  转发平面的控制。目前主要通过开源方式实现，对转发数据的设备进行控制，通过编程，使转发设备按需提供所要的网络功能。目前还没有商用，但应是公有云底层网络架构的发展方向。

实现网络“大二层”的过程，就是数据中心交换机虚拟化、集中化的过程，通过网络虚拟化，将整个数据中心网络交换机转发平面作为Underlay网络；将数据中心交换机进行了控制平面的整合，通过对交换机控制平面的统一管理，按需分配，实现数据中心的Overlay网络。

通过上面的介绍，假定我们已经实现交换机的网络虚拟化，下面来看看数据中心内部状态化设备的虚拟化方式。状态化设备通常指负载均衡、防火墙等设备，以主/备方式部署，当主设备故障时，备用设备可以自动接管，而不会造成流量中断。

当随着技术的发展，以微服务为例，应用被拆分成了多个功能、多个层级的服务组件，这些组件部署在数据中心的计算资源池中，这时，负载均衡设备的应考虑池化部署，将“大二层”环境中的多台负载均衡设备部署在同一个集群中，集群中的设备为不同的服务提供负载均衡服务，对于所有的业务都部署成一主多备的冗余模式，且保证设备的状态都是同步的，即使多台设备同时出现问题，通常其他的设备都能够自动接管。这样，设备仅以“服务”的形式对外提供负载均衡功能，应用无需知道负载均衡的功能部署在了哪台设备上，因为所有的网络都是通的。由于负载均衡的实现方式和交换机不一样，目前暂时没有统一控制平面的技术，仍然使用配置-同步的方式对设备进行管理，而且集群技术在厂商之间不能兼容。

# **四、网络功能虚拟化（NFV）**

通过虚拟化技术，将网络节点的功能，通过软件的方式实现，不再局限于硬件架构。也就是说，从服务器上安装了实现网络功能的软件（通常是操作系统），就可以把服务器作为网络设备来使用。目前各网络厂商推出的网络设备的虚拟化版本，如VMware的NSX，F5的BigIP VE都属于这个范畴。

在云计算多租户环境下，硬件负载均衡虽然可以使用资源池的方式进行部署，但单台设备仍不可避免的承载着多个租户的服务，容易发生资源抢占,且横向扩展性差，因为一个集群内的设备数量是有限的。如果使用NFV技术，则可以实现租户负载均衡设备的按需弹性部署和回收，而且租户的设备专用，不会发生资源抢占的现象。

针对数据中心防火墙设备的部署，需要考虑三种情况：

    1.  数据中心出口处，作用是数据中心网络与外界网络之间的安全隔离。

    2.  数据中心内部各区域，作用是数据中心各区域的网络之间的安全隔离。

    3.  数据中心各区域内部网络，即“大二层”网络内部的安全隔离。

对于1和2，仍采用传统的硬件设备，主备部署方式即可。对于3，“大二层”网络环境中，采用了分布式网关的技术，传统的防火墙部署方式无法有效的对网络流量进行安全检查，因为流量根本不会通过防火墙。

为避免这种安全隐患，可以采用NFV技术，将防火墙的部署位置后移到宿主机上，在每台虚拟机前端部署一个防火墙，用来对出入这台虚拟机的流量进行安全检查。所有的虚拟防火墙都可以进行统一的管理，监控和威胁感知。

# **五、综述**

通过这段时间不断的学习和交流，逐渐理顺了当前主流网络技术的原理，以及适用的场景。限于篇幅原因，仅介绍了数据中心内部网络，上面只对中的技术进行了简单的趋势分析和部署场景的介绍。对于技术点也进行了浅尝辄止的介绍。

    数据中心网络是云环境下的一个模块。对于数据中心网络互联，广域网技术，网络与云平台其他组件的联动，这又属于新的领域，但是这个也是我们必须和将要思考的。
