**概  述**

Moto是一种自2011年最早出现的蠕虫病毒，至今仍很活跃。360终端安全实验室持续接到用户反馈网络中此类蠕虫的感染情况，我们对用户现场提取的样本做了深入分析，由于在野版本众多，细节功能各异，本次分析的样本为Moto 1.58版本。

  

通过分析发现该病毒具有关机回写能力，在一定条件下会删除自身以及相关注册表服务项，以躲避人工或杀软的检测。其主要通过弱口令暴力破解RDP 3389端口进行传播，主要危害是接受远程指令、下载运行其他恶意可执行程序从而成为一个受控主机。

  

**病毒影响范围**

根据360网络安全研究院的数据，Moto感染量总体趋势比较平稳，每天感染终端数量约在万级。以下是最近30天 Moto 蠕虫的感染趋势图：  

![](../Images/0e1d8af68d62595a06317e3285fccd43.png)

  

**病毒落地传播过程**

病毒通过RDP弱口令爆破传播，当爆破成功后将开始进行传播，以下是传播过程：

1、  创建一个RDP 共享临时盘 \\\\tsclient\\a

2、  释放病毒自身 Loader至 \\\\tsclient\\a\\a.dll

3、  释放以下注册表文件至 \\\\tsclient\\a\\r.reg

注册表内容如下：

![](../Images/3c3a783531c11c3e263a7b9727cb1af3.png)

  

以上注册表是为了保证随后rundll32以管理员权限运行。

4、  将病毒母体Payload拷贝至 \\\\tsclient\\a\\moto

5、  发起RDP会话并指定以下命令行作为会话Shell：regedit /s \\\\tsclient\\a\\r.reg

6、  发起RDP会话并指定以下命令行作为会话Shell：rundll32 \\\\tsclient\\a\\a.dll

以上步骤在攻击机上执行。

 

以下是落地过程，这些步骤在目标机上执行：

1.执行RDP会话指定的Shell命令：regedit /s\\\\tsclient\\a\\r.reg

2.执行RDP会话指定的Shell命令：rundll32 \\\\tsclient\\a\\a.dll

当此命令得以执行后，读取\\\\tsclient\\a\\moto 文件，获得母体Payload数据；

3.将母体Payload 数据写入HKLM\\SYSTEM\\WPA\\md注册键；

4\. 释放Loader至%windir%\\clb.dll

5.通过向 Windows 任务栏发送消息调用“运行”对话框（见后面分析），最终执行regedit 后加载clb.dll ，创建病毒svchost服务；

  

 当svchost服务建立后，至此病毒得以成功着陆稳定运行。

![](../Images/af1c07c22cb93533319fb7a3eabfaf02.png)

Moto传播流程

**通过系统进程svchost服务加载**

病毒以共享进程svchost服务形式运行，该服务加载病毒的Loader，继而由该Loader发起病毒的执行。

  

Loader加载路径在32位和64位系统上有所不同：

32位系统加载文件位于以下路径：“%windir%\\Offline Web Pages\\cache.txt”

64位系统的加载路径是：“%windir%\\temp\\ntshrui.dll”

  

下图是64位系统服务配置项（服务名不固定，由病毒根据一定逻辑筛选，且32位系统上该注册配置项在加载后会自动删除，直到关机时才将服务配置写回）：

![](../Images/bd50aebf2cc1ed3dcb2b61fba96bd38f.png)

  

实际上64位系统上的ntshrui.dll是由 cache.txt在系统重启时重命名而来：

![](../Images/6be8a107448fa7a99e8791403eb6f196.png)

  

**隐藏于Windows目录“Offline Web Pages”**

病毒的Loader文件伪装成 Web 缓存文件存放在以下路径：

“%windir%\\Offline Web Pages\\cache.txt”

在XP/2003上，该路径在资源管理器上是看不到的内容的（可以通过 DIR 命令进行查看）：

![](../Images/d47bd9137505c10e42b93d6427fe7c51.png)

  

不过这种隐藏方式在Windows7以上系统无效。

**病毒Payload藏匿于注册表中**

病毒的Payload固定存储在以下注册表中：

![](../Images/d6f0f6745a299b2eaf39a359a3aab587.png)

md键值为Payload键，该键值在病毒落地时填写。其他注册项是病毒的配置项目。md键值在病毒启动时会被Loader读取解密，解密的恶意代码不落地只在内存中运行，同时在检测到Regedit 或360安全产品主窗口句柄后会删除自身，在一定程度上可以达到无文件运行效果。

**病毒主要危害**

通过分析我们可看到，Moto蠕虫病毒最终目的就是控制受害主机，使其沦为病毒传播者手中的黑产，为今后的进一步的非法利用做准备。此外，Moto 由于大量扫描网络3389 端口也会占用不少网络带宽，严重时甚至会造成网络拥堵进而影响业务和办公。

  

**总结及安全建议**

*   弱口令是Moto的首要利用传播方式，因此建议必须避免使用弱口令。近来许多网络攻击方式就是利用弱口令，包括危害非常大的勒索病毒其主要入侵方式就是如此（人工入侵服务器投毒勒索尤其严重）。
    

  

*   关闭不用的端口，比如3389等高危端口，即使要用，也建议更改默认端口。对于直接或间接暴露在外网的 RDP 端口，我们强烈建议关闭外网访问权限，采用双因子VPN接入内网后访问服务器。
    

  

*   安装一款成熟的杀毒软件也是必不可少的。360天擎针对Moto病毒进行了深度优化，即使病毒隐身，也可通过扫描内存发现其踪迹，从而将之杀绝。
