1. 前言

安全工程师：接口需要验证参数中的URL是否是内部域名。开发工程师：好的，没问题。

如果不使用已经写好的安全框架，真正让开发去添加一个URL白名单，我相信不少人会出现不同程度的安全问题。

2. 可造成的漏洞

和URL有关系的漏洞，我们可以联想到包括但不局限于下面的漏洞

  • CSRF

  • Json Hijack

  • SSRF

  • URL跳转

3. Bypass Poc及实际案例

先来看下应该如何安全验证：

  • 取一级域名

  • 判断一级域名是否在白名单里

但是，在实际的甲方安全中，很多开发者会犯以下的一些错误。

3.1 endsWith

取出一级域名，再使用endsWith判断是否在白名单列表

Bypass Poc:

bypassmogujie.com

案例：某旅行APP做referer校验的时候，全站存在referer校验bypass问题，导致全站存在Json Hijack等漏洞，可以拿到某旅行APP的开房记录等信息。目前漏洞已经修复。

绕过的poc

Referer: https://www.mogujiexxtrip.com/mytrip/

3.2 contains

取出一级域名，判断一级域名在白名单列表里使用contains判断

Bypass Poc:

mogujie.com.bypass.com
bypassmogujie.com

3.3 startsWith

取出一级域名，判断一级域名在白名单列表里使用startsWith判断

Bypass Poc:

mogujie.combypass

这种域名后缀虽然不存在，造成无法利用。但是在实际的测试中，确实发现某大公司是以这样的方式写的代码。所以说，如果没有规范，什么样的逻辑代码都能写出来。

3.4 正则表达式

用正则表达式去匹配URL中是否存在www.mogujie.com字符串

Bypass Poc:

www.mogujie.com.bypass.com

还有的URL接口验证是否是图片链接，但是验证的方式居然是用正则匹配是否以类似.800*600.结尾。Bypass Poc:

www.mogujie.com/_4528x2020.php

用正则判断host是否是域名Bypass Poc:

10.10.10.10.xip.io

案例：腾讯某域名诊断功能存在SSRF（目前该漏洞已经修复）。该功能验证逻辑，首先判断host是否是域名。

所以我们可以利用xip.io进行Bypass。

4. 安全代码

针对URL白名单，写了一份java的安全代码。逻辑很简单：

  • 取一级域名

  • 判断一级域名是否在白名单里。

方法调用：

String[] urlwhitelist = {"mogujie.com", "meilishuo.com"};
if (!UrlSecCheck(url, urlwhitelist)) {
    return;
}

方法代码：

需要先添加guava库（目的是获取一级域名）

<dependency>
    <groupId>com.google.guava</groupId>
    <artifactId>guava</artifactId>
    <version>21.0</version>
</dependency>
public static Boolean UrlSecCheck(String url, String[] urlwhitelist) {
    try {
        URL u = new URL(url);
        // 只允许http和https的协议
        if (!u.getProtocol().startsWith("http") && !u.getProtocol().startsWith("https")) {
            return  false;
        }
        // 获取域名，并转为小写
        String host = u.getHost().toLowerCase();
        // 获取一级域名
        String rootDomain = InternetDomainName.from(host).topPrivateDomain().toString();

        for (String whiteurl: urlwhitelist){
            if (rootDomain.equals(whiteurl)) {
                return true;
            }
        }
        return false;

    } catch (Exception e) {
        return false;
    }
}
