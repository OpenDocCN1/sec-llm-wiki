前言

02

Deeplink协议介绍

由于该漏洞利用了Deeplink协议，因此我们先来了解一下什么是DeepLink协议。

Deeplink，即深度链接技术，是指在App、短信、广告里点击链接，能直接跳转到目标App具体位置的技术。深度链接打破了短信、网站与App间的壁垒，成为实现网站与App相互跳转的桥梁。开发者不仅可以通过Deeplink实现网站到App互相跳转，也可以实现从多个平台（QQ、微信、微博、Twitter、Facebook、短信、各大浏览器等）到App内指定页的跳转。Deeplink的应用场景众多，可用于App社交分享、App 沉默唤醒、App广告引流等场景。

5.系统如何处理Deeplink协议

当点击的链接或编程请求调用 Web URI intent时，Android 系统根据App manifest.xml文件中声明的Action 、Category 、 Scheme去匹配，按顺序尝试以下每个操作直到请求成功：

a.打开可以处理 URI 的用户首选App (如果已指定处理该scheme的App）。

b.打开唯一可以处理 URI 的可用App。

c.如果多个App注册了相同的scheme，允许用户从对话框中选择使用哪一个App打开。

3.3 Deeplink漏洞验证

1.经过前面的分析，我们发现存在如下安全问题：

a.通过传入外部可控的URL参数，可使App跳转到任意网址，导致任意URL跳转漏洞。

b.App会从本地Cookie中获取参数值拼接到外部URL中，可造成Cookie数据泄露。

为了保证App从本地Cookie中能正常获取到数据，需要先登录App，登录后来验证一下这两个问题。

04

总结

该漏洞是一个Deeplink协议任意URL跳转漏洞，且跳转URL时传入了Cookie数据，导致可以被攻击者跳转到恶意网址窃取Cookie，攻击效果相当于XSS窃取Cookie攻击。总体来说该漏洞还是比较容易理解的。

对于开发者而言，为了避免产生此类漏洞应在开发时注意以下几点：

a.当需要从外部数据中获取URL时，如果URL来源是确定的，则建议使用域名白名单进行校验，防止加载恶意网址。

b.禁止在Deeplink跳转URL时携带身份认证数据，例如：Cookie、token等。

c.如果业务功能需要WebView使用File协议，则应考虑黑名单或白名单来控制访问的文件路径，防止产生File跨域漏洞读取敏感文件。

d.对于导出组件应仔细评估业务需求是否必须导出，对于不需要导出的组件设置为不导出；如果业务功能上需要导出，建议考虑增加权限来限制只被具有权限的应用调用。注意：增加权限时，需要业务上调用方App同步增加权限声明，否则会导致无法与该组件交互。
