Passwords Managers 101

Password managers are tools that help us to generate secure passwords (long and complex) and store it safely, in the cloud or locally, behind one strong password, one example of this tool is KeePass. This tool will help us to never forget a password, fulfil password security policies and prevent us from re-use password (The most common and critical habit related to security issues). 


The most important concept behind of this password managers is like in the lord of the rings, “One rig to rule them all”, You should use a strong password (A.K.A master password) to secure all the other passwords. If by any mean your master password is not strong, all the password manager concept fails, and your information and accounts can be compromised.

CVE-2023-24055

This vulnerability allows one attacker to export (get) all the passwords stored in the database, that means the attacker can obtain all the password, obtaining direct access to your account if you don’t use any other countermeasure.

 

This vulnerability will be considered high risk because of the impact, but his difficulty execution and prerequisites will make this value go to medium.


The process is simple, the attacker will inject a trigger in the configuration file, that will export in a predefined location the already opened password database, in plain text, then save this file; the next step is wait for the victim to use the tool.


图表 3 Attack Process


When the victim starts to use KeePass, after put his master password, the tool will execute the configuration file, encountering the malicious trigger, exporting in plain text the password database, later, the attacker just have to exfiltrate the loot in his preferred or convenient way XD. 


This attack is also an stealth attack, because the process of export the password database is made in the background, the victim don’t need to consent or accept any popup, also will not be warn or see any sign of the attack.


The key parameter in the vulnerability is the next trigger “D5prW87VRr65NO2xP5RIIg==:” that is the responsible for export the active database. 


图表 4 Exploit code snip


Maybe some of you are thinking, are this triggers and actions legal? The answer is: these actions and triggers are legal functions, are created to help to perform actions to his users or automate part of the work. In this case, the security researcher find a way to abuse this functionality, this is one of reasons of why, KeePass developers are disputing this vulnerability, because they think is more and abuse of a functionality than a vulnerability itself. 


If you want to know more about triggers and actions, you can check KeePass documentation in the link :

What to do next

· To prevent incidents as consequence of a password leak, you can use other technologies like Fido, Latch or any technology that implement second factor authentication. Even if one attacker has your password, can’t do too much with it, because don’t have the other part of the key.

· If you use KeePass, update it or move to other fork like KeePassXC, these don’t allow the use of triggers.

· If you think you are already compromised, you can check your configuration file for the next specific triggers:

If you found it, the most responsible thing you can do is:


1.Contact your Incident response to capture evidence of the penetration for further investigation.

2.Delete your operative system and install one new, you are already pwned!

3.In your fresh installed O.S. install a non-vulnerable password manager

4.Create new passwords for all your accounts, don’t forget to activate any extra countermeasure (Fido, latch yubikey……..).
