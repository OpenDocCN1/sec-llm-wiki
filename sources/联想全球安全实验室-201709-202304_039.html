HTTPs 越来越普及，我们都知道 HTTPs 通信更安全，为什么 HTTPs 比 HTTP 更安全呢？数字证书在这里起到了什么作用呢？数字签名又是什么？


正式介绍 TLS/SSL 证书前，需要先简单了解下背景知识，举一个通信中常用的 Alice 和 Bob 的例子来说明。



通信和加密


  • 明文通信

图 1  明文通信

Alice 和 Bob 是一对好朋友，Alice 给 Bob 写信，信在传递过程中经过的人都能查看信的内容，信没有加密很容易泄漏。


  • 对称加密通信

图 2  对称加密通信

于是 Alice 想到要用密文给 Bob 写信，以防信件被偷看。Alice 跟 Bob 约定一个密钥，Bob 需要用密钥才能解开信件，看到真实的内容。这里的不安全之处在于 Alice 和 Bob 都需要保存密钥，一旦任何一人丢失密钥，双方通信便不再保密。


  • 非对称加密通信

图 3  对称加密通信

Alice 想到了用两把钥匙解决这个问题，称为公钥和私钥，私钥由 Alice 自己保存不透露给别人，公钥给 Bob。Bob 拿到公钥后可用公钥加密信的内容，Alice 使用私钥解密，Alice 也可用私钥加密信件，Bob 使用公钥解密。


这里 Alice 只需要保存好私钥即可，降低了私钥泄漏的可能。


意外的情况出现了，Hacker 想窃取 Bob 写的信，于是伪造了一对密钥，并偷偷把 Bob 手里的公钥换成伪造的公钥，Bob 再用公钥加密信件时，Hacker 便可用伪造的私钥解密信件。这里的问题在于 Bob 无法确认手里的公钥来自 Alice。


  • 非对称加密 + 数字证书

图 4  申请数字证书

Alice 和 Bob 于是想到找一个可信的第三方给 Alice 的公钥作证，证明这个公钥属于 Alice。可信第三方用自己的私钥，对 Alice 的公钥和一些相关信息一起加密，生成一个文件"数字证书"（Digital Certificate）。


Alice 再给 Bob 写信的同时附带第三方签发的数字证书，Bob 信任这个第三方，也信任第三方作出的证明，Bob 解开证明看到 Alice 的个人信息，确信公钥属于 Alice，双方就可以愉快地通信了。


总结上述故事背景涉及到的知识点：

加密

加密是将明文信息改变为难以读取的密文内容，使之不可读。只有经由解密过程，才能将密文还原为正常可读的内容。加密算法分为对称加密和非对称加密。


对称加密

对称加密是指双方持有相同的密钥进行通信，常见的对称加密算法有DES、3DES、AES等。


非对称加密

非对称加密，又称为公开密钥加密。非对称加密中，加密的密钥和解密的密钥是不同的，也就是说有两把密钥，一个是公钥 (public key)，另一个是私钥 (private key)。

• 公钥是对外开放，私钥是自己保存。

• 公钥加密的数据，只能用私钥解密。

• 私钥加密的数据，只能用公钥解密。

常见非对称加密算法有 RSA、DSA、ECC 等。


数字证书

通过上面的介绍对数字证书有个概念，Transport Layer Security (TLS) 证书，也被称为 SSL 证书，SSL 是 TLS 的前身，本文中统称 TLS/SSL 证书。TLS/SSL 证书通常安装在 Web 服务器如 Tomcat、IIS、Nginx 上，用来给客户端浏览器校验服务端身份，确保传输数据是加密处理的，且没有被篡改。


CA 机构

CA 机构， Certificate Authority (CA) 是负责验证实体（例如网站，电子邮件地址，公司或个人）的身份，为其颁发数字证书的机构，目前世界上主要的 CA 机构有这些 IdenTrust，DigiCert，Sectigo (Comodo Cybersecurity)，Let's Encrypt，GoDaddy。


数字签名

CA 机构用私钥加密证书得到的密文实际上就是数字签名，要验证这个签名是否正确，只能用私钥持有者的公钥进行解密验证。使用数字签名的目的是为了确认某个信息确实是由某个发送方发送的，任何人都不可能伪造消息，并且，发送方也不能抵赖。在实际应用的时候，签名实际上并不是针对原始消息，而是针对原始消息的哈希进行签名。

TLS/SSL 证书的安全问题

现行 CA 和证书体系是否能保证通信安全呢？通常情况下 TLS/SSL 证书可以保证通信安全，但仍有几种攻击方式：

1. 机器被攻击

如果黑客攻击了某台主机，并在主机上安装了恶意的根证书，黑客就可以窃取用户通信数据。渗透测试时安装 Burp 根证书来抓取 HTTPs 数据包就是基于这个原理。

2. CA 机构被攻击

CA 机构是证书信任的基础，证书信任的前提就是 CA 机构是公认的可信第三方，然而一旦 CA 机构被攻击，CA 机构证书的私钥泄漏，那么该 CA 证书签发的所有证书将不可信。数字证书服务商 DigiNotar 就发生过私钥泄漏导致公司破产的事故。

3. 伪造证书

证书校验不严格，导致中间人攻击。比如绕过 SSL Pinning 就是利用了证书校验不严格。

4. 不安全的加密算法

比如 RSA 密文填充攻击 (Padding Oracle attack) 。
