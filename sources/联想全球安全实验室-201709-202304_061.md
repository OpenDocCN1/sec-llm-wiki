# 固件文件研究之文件系统提取及重打包

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzU1ODk1MzI1NQ==&mid=2247484984&idx=1&sn=c18001c362632a9ab3b440ac3ab9410d&chksm=fc1fe070cb686966bba94afbb7bedebf6564ad72a9a348e44e33d253d26a5dabd07d8b8a50da&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzU1ODk1MzI1NQ==&mid=2247484984&idx=1&sn=c18001c362632a9ab3b440ac3ab9410d&chksm=fc1fe070cb686966bba94afbb7bedebf6564ad72a9a348e44e33d253d26a5dabd07d8b8a50da&scene=27#wechat_redirect)

在研究分析智能摄像头和路由器等设备相关漏洞时，很多同学常常对于基于linux的固件格式有点不解，对于固件获取和文件系统提取更是难以理解，有时还很难拿到设备shell。因此，这篇文章以智能摄像头为例，教大家一些常用的分析思路和方法，对于固件文件格式组成，以及如何从固件中提取文件系统进行阐述，并以智能摄像头为例说明一下在有复杂验证情况下，应当如何对固件进行重打包来获取shell。  

**一．固件文件格式**

在进行固件文件漏洞分析及固件修改时，首先需要对固件文件组成有所了解。一般基于linux的固件文件由头部和数据部分组成。

**1. 头部信息**

在固件文件的头部信息中记录了整个固件文件的结构、文件数据的存储方式、文件类型、长度及一些辅助信息等。以一个固件头部为例，前28字节数据如下：

![](../Images/0d1898f34e49558551a8dab266a530cf.png)

头部数据分析可知。

*   magic=0x48445230 代表固件magic number
*   len=0x17A000 代表文件长度
*   crc32=0x1F181132 代表32位CRC校验码
*   flag\_version=0x00100000 表示标志和版本
*   offset\[0\]=0x001C 代表第一数据部分从28字节开始
*   offset\[1\]=0x08D8 代表第二数据部分从2264字节开始
*   offset\[2\]=0x07E400 代表第三数据部分从517120字节开始
    

**2. 数据部分**

在固件文件的数据部分，由引导加载、内核、文件系统等部分组成。uImage作为引导加载的uboot专用映像文件，它在内核镜像之前加上一个长度为64字节的ulmage header，存储整个镜像的概括信息区域，包括固件文件大小、crc校验值、固件镜像文件的一些基本属性等。而uboot类似于bootloader，作为设备固件中的引导加载程序，一般存在于flash memory中开头的部分，研究内核和文件系统的加载或烧录需要对这一部分进行研究，如下图为引导加载程序的启动过程。

![](../Images/c48ebe9342bd5149b0a0c7a3aba81906.png)

文件系统作为操作系统的重要组成部分，是操作运行的基础。如果对固件文件进行逆向分析或者漏洞挖掘，那么就需要对文件系统中的二进制和脚本进行研究。不同设备使用的文件系统格式不尽相同，根文件系统会被打包成当前设备使用的文件系统格式，然后组装到固件文件中。常见的固件文件系统类型有squashfs、ubifs、romfs、rootfs、jffs2、yaffs2、cramfs、initramfs2a等。

以基于linux固件中常见的squashfs文件系统为例，其作为只读格式的文件系统，以Linux内核源码补丁的形式发布。当系统启动后，会将文件系统保存在一个压缩过的文件中，该文件可以使用换回的形式挂载并对其中的文件进行访问，当进程需要某些文件时，仅将对应部分的压缩文件进行解压。squashfs文件系统常用的压缩格式有GZIP、LZMA、LZO、XZ(LZMA2)等。

以智能摄像头和路由器为例，主要对其固件文件中的文件系统进行逆向分析研究，比如后台验证方式设置是否合适，是否存在命令注入攻击点，是否明文存储了一些敏感信息，是否开启了不必要的端口等漏洞。

**二．提取文件系统及重打包**

了解了固件文件的组成，接下来需要从测试设备中获取基于linux的固件文件，再从固件文件中把文件系统提取出来，逆向分析文件系统。而提取文件系统存在的难点之一在于不同的操作系统使用的文件系统不同，另外文件系统使用的压缩算法也有差异，甚至有的文件系统会使用非标准的压缩算法打包文件系统，因此，大家必须知道文件系统的类型及压缩算法等。

**1. 设备固件获取**

在进行漏洞分析时获取IoT设备固件常见的三种方式：

*   从厂商提供的更新网站下载
    
*   通过串口等硬件接入，从设备的flash中读取
    
*   通过拆卸相关存储芯片，利用编程器读取

**2. 手动提取文件系统**

**判断文件类型  **

通常我们使用file命令来识别文件类型，file命令是从给定文件的首字节开始，按照既定格式进行模式匹配，但是这意味着不能识别文件系统magic签名，所以需要使用下面的方法进一步分析：

1.  “strings | grep"检索文件系统magic签名头
2.  “hexdump | grep" 检索magic签名偏移
3.  “dd | file" 确定magic签名偏移处的文件类型

文件系统magic签名头是指一个文件系统中包含的一串可识别字符，有了这串字符，表明该文件可能包含某个文件系统。当然，如果要确定是否包含某文件系统，还需要检索签名处地址偏移的一段数据类型。

**检索magic签名并确认文件类型**

文件系统头部特征是根据每一种文件系统开头的几字节提炼出来的。以cramfs和squashfs文件系统为例，其头部特征如下：

*   cramfs——文件系统头部特征字符为"0x28cd3d45"
    
*   squashfs——文件系统头部特征较多，大致分为sqsh、hsqs、qshs、shsq、hsqt、tqsh、sqlz这7种
    

检查是否存在cramfs文件系统，当无法判断是大端格式还是小端格式时，需要进行二次搜索：

*   
*   

```
strings firmware.bin | grep `python -c 'print "\x28\xcd\x3d\x45"'`strings firmware.bin | grep `python -c 'print "\x45\x3d\xcd\x28"'`
```

以squashfs文件系统为例，发现"hsqs"的magic签名头后，需要进一步确定是不是squashfs文件系统以及收集一些基本信息。从检测出签名头的偏移地址开始dump出一段数据（一般squashfs文件系统的头部校验不会超过100字节），再利用file命令确认文件类型（可以利用-m参数加载自定义magic签名文件，得到更详细的输出信息），可以得到文件系统的基本信息，如下图为squashfs文件头部特征的识别：  

![](../Images/77e2405afb32ab4ad89e7d624c12795a.png)

知道了偏移地址和文件大小，可以利用dd命令复制该数据块，从而手动提取出文件系统。

当然，还可以利用一些自动化工具对固件文件进行更好的研究分析。

**3. ****自动化工具提取**

除了上述手动提取方法之外，还可以采用Binwalk、Firmware-mod-kit工具自动执行前面的所有操作，借助自动化工具，只需要一条命令就可以从固件二进制镜像中提取出文件系统，原理与上述手动提取方法原理类似，均是使用magic字节以及首部特征字符串检测文件系统以及其他组件的偏移。在下面的URL链接中可以查看Binwalk所能识别的文件系统类型：

https://github.com/devttys0/binwalk/blob/62e9caa164305a18d7d1f037ab27d14ac933d3cf/src/binwalk/magic/filesystems

从git-hub上拉取相关代码并安装相应依赖，即可在本地使用。Binwalk和Firmware-mod-ki的URL链接如下：

https://github.com/devttys0/binwalk.githttps://github.com/mirror/firmware-mod-kit.git

**4. 固件重打包**

当拿到文件系统之后，通常都需要拿到设备的shell来配合进行逆向研究。然而，在无法顺利通过设备验证或者文件系统无法修改时，则需要考虑对固件进行重打包，来顺利完成逆向分析研究。

固件重打包一般可以分为两步，解包和合包。

解包时，针对文件系统，若binwalk里添加如下图所示的设置，利用-e参数可以自动对提取出的相应文件系统进行解压，得到文件目录。

![](../Images/a1e86c44d18b5439b13a1ccf39a2a1d1.png)

在得到文件目录后，可以按照需求修改文件，比如删除/etc/shadow下的密码，在初始化进程里添加telnet等，方便漏洞测试研究。

合包时，需要注意以相同的压缩算法和参数对文件系统进行打包，且当前目录结构不变，文件名不变等，同时需要注意MTD分区大小，如果与原来分区相比变小则需填充字节使其大小不变，如果溢出则需重新计算crc值及更改相关偏移地址。

以某智能摄像头为例，在无法通过暴力破解密码拿到shell，同时telnet未开启的情况下，需要考虑对固件进行重打包。用热风枪吹落电路板上flash芯片，利用编程器读取固件，如图。

![](../Images/3734ea4a56217e9e1a1e41ff8b49b511.png)

利用binwalk对固件进行信息提取，如图。可以知道使用的是squashfs文件系统，压缩算法为XZ，blocksize为131072个字节等信息。

![](../Images/bc29561809e73f59640ba9e36af4289f.png)

接下来根据串口输出日志，查看固件分区地址偏移，如图。

![](../Images/1f07c9b4e689f07fa85e2bc9f38177ff.png)

从图中可以看出需要修改的部分位于为rootfs：0x0000001c0000 ~0x000000440000之间，按rootfs分区开始地址和结束地址，使用dd命令将固件分为三部分。然后解包文件系统，在/etc/shadow下直接删除密码，在/init.d/rcS下添加开启telnet指令，完成修改。

![](../Images/dbc9c52af0bd187d3be134077440f1cd.png)

![](../Images/1b736465b5c4d6e28137a9ac2486dd9a.png)

接下来是对修改后的文件进行打包，针对squashfs文件系统，考虑使用squashfs-tools工具进行打包，压缩方法与块大小的参数指定需要与原来一样，如图。

![](../Images/cd4e1b8cb3b1598c30fdb0070ab080dd.png)

查看打包前和打包后文件大小，发现打包后文件变小，因此不需要考虑修改分区表，只需要填充0xff字段满足分区表地址偏移大小。

![](../Images/077c0e2ae4bb5a5ebd6c93e4647f3833.png)

对于修改后的squashfs文件系统，需要填充0xff字节来满足原先的偏移地址，将其大小填充到0x000000440000-0x0000001C0000大小，即0x000000440000-0x0000001C0000-2460916=160524个0xff字节。

在补齐squashfs文件系统ff字节后，直接使用cat拼接各部分即可，如图所示。

![](../Images/0a751326e8e87f79e6969f36193a90bd.png)

打包好固件（pack\_firmware.bin）之后，同样使用编程器刷回flash中，至此，摄像头固件重打包工作完成。

**三．结语**

通过了解固件文件组成和文件系统的特点，可以将固件文件分为多个部分，并从中将文件系统提取出来，再配合固件文件重打包手段，拿到shell或编入相应文件，以配合固件文件的研究分析。想要逆向分析研究固件文件，以上是对固件的必要理解和处理，但是仅是第一步，还需要对固件文件中二进制文件或脚本进行深入了解分析，在此分享一些常用于固件分析的工具和一些常见固件漏洞的突破口。

**Linux自带工具**

*   file 用来检测是否是有效的文件和文件类型
    
*   xxd 会生成给定文件或者输入的十六进制格式
    
*   hexdump 16进制查看工具
    
*   strings 展示输入文件中可识别的字符串
    
*   dd 用于复制文件并对原文件的内容进行转换和格式化处理
    
*   lzma 解压lzma文件
    
*   grep文本搜索工具
    
*   unsquashfs 用于解压squashfs的文件格式
    

**第三方工具**

*   binwalk（分析固件的自动化脚本）
    
*   IDA（二进制分析工具）
    
*   ghidra (二进制分析工具)
    
*   firmware-mod-kit （打包固件的自动化脚本）
    
*   Firmwalker（自动化分析固件漏洞的突破口）
    
*   Firmware Analysis Comparison Toolkit（自动化漏洞分析工具）
    

**搜寻固件漏洞一些突破口**

*   搜索etc/shadow和etc/passwd
    
*   搜索etc/ssl目录
    
*   搜索与SSL相关的文件，例如.pem、.crt等
    
*   搜索配置文件
    
*   搜索脚本文件
    
*   搜索.bin文件
    
*   搜索诸如admin，password，remote，AWS key等关键字
    
*   搜索物联网设备上使用的通用Web应用程序
    
*   搜索常见的二进制文件，例如ssh，tftp，dropbear等
    
*   搜索一些不安全的C函数，例如strcmp
    
*   搜索可能存在的XSS，CSRF，XXE，命令注入等攻击点
    
*   搜索URL，电子邮箱地址，IP地址
