**一．Docker简介**

Docker是一种操作系统层面的虚拟化技术，基于Linux内核，使用Go语言进行开发实现。

虚拟化的传统方式是在硬件层面实现虚拟化，需要额外的虚拟机管理应用和虚拟机操作系统层。然而Docker是轻量级的虚拟化，在当前操作系统上直接使用即可。 

对于一个主机部署的Docker容器，其实可以简单理解为iOS中APP的沙盒。

随着Docker技术的广泛运用，Docker逃逸也由然而生，即突破容器限制，访问或者控制宿主机的攻击方式，如最新的Docker容器逃逸漏洞(CVE-2020-15257)。

Docker的官方文档，列出了部分Docker的历史安全问题。

https://docs.docker.com/engine/security/non-events/

  

**二．Docker的攻击和防御**

只有了解攻击Docker的方式才能更好的进行防御。所以首先了解一下什么场景会存在安全风险，以及Docker逃逸的方式。**可能存在安全风险的场景：**

*   一些能够管理后台、具有开启主机资源功能的服务，如能够创建新的Docker或者虚拟机的后台服务。
    
*   web后台及web服务本身就是Docker容器。例如，Docker部署的jupyter，confluence等。
    
*   通过主机漏洞或能对目标的主机资源进行访问，例如端口的未授权访问。如果发现是Docker后，可进一步攻击利用。

**常见的攻击方式：**首先判断是否为容器，如查看cgroup组，查看环境变量，查看挂载硬盘等。在确定为容器后，可通过三个方向进行测试攻击。

**1\. 宿主机内核漏洞**

因为 Docker 与宿主机共用一个内核，所以当内核存在提权等漏洞时，可发生逃逸，如Dirty COW漏洞(CVE-2016-5195)。

该漏洞比较早，但仍然具有参考意义，如果恰好有内核Nday漏洞曝出，但未及时升级linux内核，也有被攻击利用的风险。修复方案：及时关注最新漏洞消息，对有漏洞的Linux版本进升级。**2\. Docker自身漏洞**(1) Docker容器逃逸漏洞（CVE-2020-15257）Docker的引擎是由Docker Client、Docker daemon、Containerd以及run共同负责创建和运行的。Docker 对容器的管理和操作基本都是通过 Containerd 完成的，该漏洞是利用Containerd 在操作 runC时创建相应进程并生成一个抽象 socket，此socket 存在于宿主机的 /proc/net/unix中。当 Docker 容器内部共享宿主机的网络时，便可通过加载该 socket，来控制 Docker 容器，引发逃逸。目前已经有成熟可用的开源工具针对该漏洞进行安全测试。https://github.com/Xyntax/CDK/修复方案：漏洞影响版本为<= 1.3.7、1.4.0、1.4.1的版本，已在1.3.9、1.4.3版本中修复漏洞。需要注意的是，修复升级后应重启容器内的服务以确保生效。

(2) Docker cp命令漏洞（CVE-2019-14271）

Docker cp命令实现中存在的一个安全问题，攻击者可以利用该漏洞实现容器逃逸。修复方案：目前Docker已经发布了补丁。

(3) Docker逃逸漏洞（CVE-2019-5736）

漏洞点在于runC，通过调用runC可以完成容器的创建，运行，销毁等操作。攻击者可利用漏洞重写宿主机上的runC 二进制文件，以root身份执行命令。

该漏洞需要管理员执行exec才能触发，可能Docker会崩溃，且成功利用的关键是需要go编译上传exp，并且重新进入Docker才能触发。Poc：https://github.com/Frichetten/CVE-2019-5736-PoC修复方案：受影响的版本为 Docker <18.09.2版本  runC <=1.0-rc6版本。可通过升级Docker及runC版本修复漏洞。**3．错误配置**(1) 端口暴露在公网通过暴露的Docker API端口创建新的容器进行挖矿，如门罗币挖矿。例如访问  http://x.x.x.x:2375/containers/json![](../Images/08d19c63c77403752002ba286472a86f.png)Docker API用于外部访问的端口是4243，可能利用未授权安装DDoS僵尸和其他工具、脚本来确保僵尸主机能够在系统重启后自动启动。(2) 权限配置错误Docker 默认情况下会关闭大多数capability，若开启了某些特权 capability，可发生逃逸。如开启了特权容器，可直接挂载物理硬盘，访问宿主机文件等。**三．Docker的安全基线**最后，关于如何制定Docker的安全基线，可以参考以下方向。1\. 主机方面

*   时刻关注最新的漏洞发布，及时更新内核并升级系统
    
*   SELiux/AppArmor/GRSEC控制文件访问权限
    
*   Capability（权限划分）
    
*   限定系统调用
    
*   禁止将容器的命名空间与宿主机进程命名空间共享
    
*   用户权限为root的Docker相关文件的权限应该为644或者更低权限
    
*   对Docker守护进程、相关文件和目录进行审计
    
*   定期清理不必要的容器
    

2\. 网络方面

*   对端口进行限制，只开启和使用必要端口
    
*   通过iptables等设定规则实现禁止或允许容器之间网络流量
    

3\. 镜像方面

*   创建本地安全镜像仓库服务器
    
*   并通过安全通道下载可信镜像文件
    
*   镜像仓库客户端使用证书认证，对下载的镜像进行检查
    

4\. 其他设置

*   安全审计，日志收集及安全检测
    
*   监控Docker容器状态，确保最低权限及最少资源
    
*   使用堡垒机等安全设备对云主机及容器进行管理
