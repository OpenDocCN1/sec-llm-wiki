## **0x04 JTAG状态机**

在介绍JTAGulator识别JTAG引脚的原理之前，需要先介绍一下JTAG状态机的相关知识。

支持JTAG规范的芯片会在器件内部定义一个TAP（Test Access Port）并规定TAP状态机的行为，通过专用的测试工具进行内部节点测试。下图为TAP状态机，状态机一共有16个状态，在TCK的上升沿时，TMS可以改变状态机的状态。

![](../Images/cf29cd84b7c11ebdb96500ae84b8a7b9.png)

图1  TAP状态机

从状态机中可以看到，在任意状态下，TMS持续5个TCK，状态机就一定会回到复位，即Test-Logic-Reset状态，所以管脚上的复位（TRST）确实不是必须的，某些IoT厂商为了禁止调试，会在出厂的时候，将TRST上拉，使TAP状态机始终处于复位状态。正常情况下，从Test-Logic-Reset状态出发，就可以控制状态机进入任意一个状态了。

例如，使状态机进入“Shift-IR”状态，就可以用以下代码实现：

*   
*   
*   
*   
*   
*   
*   
*   
*   

```
// first sync everybody to the test-logic-reset state    for(i=0; i<5; i++) JTAG_clock(TMS);// now that everybody is in a known and identical state, we can move together to another state    // let's go to Shift-IR    JTAG_clock(0);    JTAG_clock(TMS);    JTAG_clock(TMS);    JTAG_clock(0);    JTAG_clock(0);
```

当状态机进入Shift-IR状态后，就可以使用TDO、TDI进行传输指令了，同样的，也可以使状态机进入Shift-DR状态，TDO、TDI也可以进行数据的传输。

下图为JTAG指令的示意图，可以看到，指令寄存器和TAP状态机共同决定JTAG的操作。TAP分为DR和IR两部分，其中DR为DataRegister(数据寄存器)，DR通常由3个寄存器组成：边界扫描寄存器（BSR，Boundary Scan Register）、BYPASS寄存器和IDCODE寄存器。

边界扫描寄存器：主要的数据寄存器，用于通过I/O引脚传输数据。

BYPASS寄存器：该寄存器只有1位，用于设备测试，具体的功能后面会结合BYPASS指令详细介绍。

![](../Images/a400dcaad4b82adfda4636235ca9aa58.png)图2  JTAG指令示意图

IDCODE寄存器：该寄存器存有设备ID、版本号等出厂信息，可以使用IDCODE指令读取该寄存器里的信息。

IR为Instruction Register（指令寄存器），该寄存器内存放指令，TAP状态机根据指令去处理接收到的数据，下面我们会详细介绍JTAG支持的一些基本指令。

  

**0x05 JTAG Boundary-ScanCommand**

JTAG支持一些基本指令，这些指令可以写入到IR中执行，例如：

*   BYPASS：该指令用BYPASS寄存器来连接TDI和TDO，BYPASS寄存器只有1位，即TDI输入的数据会在1个周期延迟后通过TDO输出，该指令常用于检测在JTAG下挂了多少个CPU。
*   EXTEST：该指令将TDI、TDO连接到BSR（边界扫描寄存器）。在该指令下，设备引脚的状态通过状态机中“Capture-DR”状态进行采集，并将新的状态值通过状态机中“Shift-DR”传入BSR中，并通过“Update-DR”状态将新值更新到设备引脚上。
*   SAMPLE/PRELOAD：该指令将TDI、TDO连接到边界扫描寄存器。在该指令下，可以通过数据扫描的方式访问BSR并对其输入输出的数据进行采样。该指令也可以用在EXTEST指令前向BSR写入测试数据。
*   IDCODE ：该指令将TDI、TDO连接到IDCODE寄存器，可以通过该指令读取IDCODE。

  

关于如何执行这些指令，我们从JTAG指令示意图中可以看到，一个完整的命令，需要同时用到IR和DR。我们以BYPASS命令为例，想要执行BYPASS命令，首先要到IR中，输入BYPASS的命令，然后再到BYPASS寄存器中，执行相关命令。所以，每一个JTAG指令，都是由一个通过IR访问的指令和一个可以访问的DR构成。而由于JTAG是单向的（固定从TDI输入,TDO输出），所以每一个DR都是单向的，即，要么只读，要么只写。

下图是某芯片支持的JTAG Boundary-ScanCommand 列表，从这个表中可以看到 BYPASS的指令是111111，即0x3F。回顾之前的操作，要执行BYPASS命令，首先需要对IR进行操作，输入0x3F这个指令。然后，再通过TAP状态机转移到DR寄存器，通过TDI不断写入数据，抓取TDO的输出即可。

![](../Images/ac06ca13ec7928c662ba0e36c0667d85.png)

图3 某芯片JTAG指令集

以下代码实现借助BYPASS命令来确定挂载在JTAG下CPU的个数：

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   

```
// go to reset statefor(i=0; i<5; i++) JTAG_clock(TMS);// go to Shift-IRJTAG_clock(0);JTAG_clock(TMS);JTAG_clock(TMS);JTAG_clock(0);JTAG_clock(0);// Send plenty of ones into the IR registers// That makes sure all devices are in BYPASS!for(i=0; i<999; i++) JTAG_clock(1);JTAG_clock(1 | TMS);  // last bit needs to have TMS active, to exitshift-IR// we are in Exit1-IR, go to Shift-DRJTAG_clock(TMS);JTAG_clock(TMS);JTAG_clock(0);JTAG_clock(0);// Send plenty of zeros into the DR registersto flush themfor(i=0; i<1000; i++) JTAG_clock(0);// now send ones until we receive one backfor(i=0; i<1000; i++) if(JTAG_clock(1))break;nbDevices = i;printf("There are %d device(s) in theJTAG chain\n", nbDevices);
```

同样的，如果想要执行IDCODE命令去读取设备的ID，操作方法与执行BYPASS命令的方法步骤是类似的。

不同的芯片支持的JTAG指令集略有不同，可以通过查看Datasheet或者BSDL文件查找。

上面介绍了JTAG支持的一些指令集，并演示了执行BYPASS指令的过程。正确的操作可以执行这些指令，反过来，我们可以利用某些指令的功能去识别JTAG的引脚，这也是JTAGulator进行JTAG引脚识别的根据。

  

**0x06 JTAG引脚识别原理**

JTAGulator识别JTAG引脚的原理就是根据BYPASS指令和IDCODE指令的特性，BYPASS指令下，TDO会输出TDI输入的值；IDCODE指令下，可以读取IDCODE寄存器的值。具体的操作方法为，先假设一个引脚顺序，然后去执行指令，如果指令执行成功（TDO有输出值），那么这个引脚顺序就是对的，如果执行不成功，就换下一种引脚顺序，利用穷举法，不断的去尝试不同的引脚顺序，直至能够成功执行指令。

下图是JTAGulator的ID\_SCAN功能函数，该函数主要部分是嵌套的repeat（相当于for循环）去不断的执行IDCODE命令，直到被测设备能够输出数据。

![](../Images/7b74c99c3c571b6c6e01114eb967886c.png)图4  JTAGulator源码截图 

另外，JTAGulator并不是首款识别JTAG引脚的设备，它也是参考了JTAGenum，有兴趣的小伙伴可以去了解一下，这也是一款开源的硬件。

  

**0x07 JTAGulator操作流程**

首先，我们用万用表测量出JTAG接口中的VCC和GND，最后剩下4个引脚无法确定，将其连接到JTAGulator，将JTAGulator通过串口连接到电脑，波特率115200，以下是JTAGulator支持的命令：

*   
*   
*   
*   
*   
*   
*   
*   

```
Target Interfaces:J JTAG/IEEE 1149.1U UART/Asynchronous SerialG GPIOGeneral Commands:V Set target I/O voltage (1.2V to3.3V)I Display version informationH Display available commands
```

输入V，设置被测设备的I/O电压为3.3V（根据被测设备实际I/O电压设置），然后输入J，进入JTAG接口模式，支持以下命令，

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   

```
JTAG Commands:I Identify JTAG pinout (IDCODEScan)B Identify JTAG pinout (BYPASSScan)D Get Device ID(s)T Test BYPASS (TDI to TDO)Y Instruction/Data Register (IR/DR)discoveryX Transfer instruction/dataC Set JTAG clock speedGeneral Commands:V Set target I/O voltage (1.2V to3.3V)H Display available commandsM Return to main menu
```

我们使用IDCODE扫描的方式进行JTAG引脚识别。如下图，输入I，按照提示操作，等待扫描完成，就可以得到JTAG各个引脚的顺序。从操作过程中可以看到，我们将4个引脚连接在JTAGulator上，所以就会有共24种可能的引脚顺序，这也符合我们前面介绍的识别原理。

完成JTAG引脚识别之后，我们就可以按照这个引脚定义读取IDCODE，也可以使用AttifyBadge读取固件了。
