**PartI  About Security Architecture Design**

Before we talk about security architecture design, we should first have a glimpse at architecture,architecture describe the basic functions or components of a product, and the organization of these primary elements. Architecture focus on the accomplishment of a function and its deployment.

Security architecture design focus on the security requirement, goals ofthe software application from a security perspective – ensuring mistakes and weaknesses are identified early on, before they propagate into vulnerabilities.We should consider security at the beginning of system design, try to consider possible future security requirements, void security as an after-thought - makesure products are secured from the ground up.

 

**PartII  Architecture Design basic Requiremen**t

There are six primary security services defined in the Open System Interconnection Reference modal, it could be the basic security requirements of a product.These requirements are confidentiality,integrity,availiable,authentication,nonrepudiation and access control. confidentiality, integrity, available short for CIA, is necessary of every product, confidentiality requires the data to be processed, stored and transmitted securely. Integrity means we should provides security mechanism ensure the data orsystem t is a complete whole,not being tampered.available requires the product runs properly without interruption. accessto protected information must be restricted to people who are authorized to access the information. Access control is generally considered in three steps:identification, authentication, and authorization.

**PartIII  Architecture Design Principles**

There are ten design principle we should consider in product design, the first one is minimum attack surface, that means the more complex a product is, the more likely a security issue will occur.

Ø  p1  Minimum Attack Surface

Ø  P2  Default Security

Ø  P3  Least Privilege

Ø  P4  Defense in Depth

Ø  P5  Failure Security

Ø  P6  Distrust third-party Systems or Components

Ø  P7  Business isolation

Ø  P8  Open Design

Ø  P9  Simplify System Design

Ø  P10 Use whitelists

 

**PartIV Architecture Design Security Review Approach**

The goal of an architecture and Design review is to assess the architecture, design, requirements and goals of the software application from a security perspective – ensuring mistakes and weaknesses are identified early on, before they propagate into vulnerabilities.

Analyse the architecture and design of application from a security perspective. Examine deployment, infrastructure and the approach taken across each tier of application.

1.  Deployment and infrastructure.deployment environment and the associated security policies
