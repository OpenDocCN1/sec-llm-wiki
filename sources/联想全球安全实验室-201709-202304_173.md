**一、摘要**

物联网设备固件获取有很多方法，本文介绍其中一种，通过设备固件正常的升级过程，获取设备的固件。

**二、原理**

![](../Images/2ad6f9b8271b2e87a5c21554c5947fff.png)

通过iptables规则，将IoT设备访问互联网云端的数据转发到本地的监听代理端口，如下可以将设备访问互联网的80、443端口的数据转发到Burpsuite。

iptables -t nat -A PREROUTING -i $wInf -p tcp --dport 80 -j REDIRECT--to-ports 9999

iptables -t nat -A PREROUTING -i $wInf -p tcp --dport 443 -jREDIRECT --to-ports 9999

同时使用wireshark抓包工具对网络流量进行嗅探，获取Burpsuite不能截断的流量数据，如FTP。

通过IoT-Security Proxy抓取设备升级过程，即使设备通过静默升级的方式来升级固件，也可以被工具截断，比单独使用抓包工具更方便，而且可以用来进行设备降级测试。

**2****、****FTP**  

某家庭报警器在升级过程中使用了FTP协议，我们使用IoT-Security Proxy将网关访问云端端口的数据重定向到Burpsuite端口。如下所示为代理规则，可以看到访问云端FTP（21）端口的规则有数据包命中：

![](../Images/bfa4f38a658a21558b03ad39288b3516.png)

这时候在wireshark上可以看到设备访问云端FTP的数据，此时因为访问云端21端口的数据被重定向到了Burpeuite端口，这个时候升级并不会成功。如下所示，可以看到设备升级之前使用DNS解析了升级服务器地址，然后向升级服务器的21端口发起了请求。

![](../Images/51ca86837b4fa699723ceaae28b04af2.png)

去掉iptables规则后，再次进行升级，通过wireshark抓包可以看到设备通过FTP升级的过程，其中包含了FTP服务器的用户名、密码等信息。![](../Images/dcd99c251ecaa076b285ba6524e606f2.png)
