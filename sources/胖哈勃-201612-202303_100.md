## 分析

题目是一个猜硬币正反面的游戏，每猜一次 0/1 后可以得知猜得是否正确。连续猜对 50 次可以得到 flag，错误一次则连接断开。随机猜测成功的概率是2^-50，所以靠暴力穷举不可能成功。我们可以看到，题目使用密码学安全的随机数生成 0/1 的信息并且存入变量 coin，然后根据这个 coin 来从 msg1 和 msg2 中选择一条信息，其中 msg1 和 msg2 是代表硬币正反面的 Head 和 Tail 两个英文单词后面添加了随机字节。然后，这个信息会被 pycrypto 库的 ElGamal 加密算法进行非对称加密，我们可以得到加密后的密文。加密的公钥是写死的，只有私钥才能解密，我们并没有私钥。我们想要成功猜对 50 次硬币，就要从 ElGamal 加密的密文中区分出来明文是以 Head 开头的 msg1 还是以 Tail 开头的 msg2。可以分辨这两种情况，意味着这种加密算法不满足 Semantic security（语义安全）。ElGamal 算法的 Semantic security 只有它所使用的群 G 满足 Decisional Diffie–Hellman assumption 才行（可以参见维基百科的 ElGamal encryption 词条），但是 pycrypto 的实现中，群 G 只是 mod 整数的乘法群，所以不满足。这样，我们可以用通过计算勒让德符号来分辨密文对应哪一条明文。勒让德符号的意义是，判断一个数在 mod p 的意义下，是否为另一个数的平方。如果是，勒让德符号就是 1，否则是 -1，这里不需要考虑勒让德符号为 0 的特殊情况。勒让德符号的计算非常简单，请参见解题代码中的 `legendre` 函数。参考 pycrypto 的源代码（https://github.com/dlitz/pycrypto/blob/master/lib/Crypto/PublicKey/ElGamal.py#L332），我们得到的 tuple（a 和 b）分别由以下公式计算而来（都是 mod p 意义下）：![](../Images/79b6915dca85228835dc957b9eba51f3.png)勒让德符号有积性，也就是说两个数乘积的勒让德符号是它们勒让德符号的乘积。g 是生成元，勒让德符号是 -1。当 a 的勒让德符号是 1 时，我们可以肯定 k 是偶数，此时y^k勒让德符号是 1。当 y 的勒让德符号是 1 时，y^k的勒让德符号也肯定是偶数。这两种情况任意一种成立时，m 的勒让德符号和 b 相同。当 a 和 y 的勒让德符号都是 -1 时，m 的勒让德符号和 b 相反。所以我们可以根据 b 的勒让德符号判断 m 的勒让德符号。但要注意，两个 msg 的勒让德符号可能相同，此时无法分辨。即使勒让德符号不同，我们也无法猜出哪一个是 1 哪一个是 -1。由于每次题目运行时 msg 后面的随机字节是不同的，所以当我们失败时可以重新连接题目重试直到成功。根据概率，试几次之内就基本可以成功。

# BabyOT 题解

## 题目详情

```
#!/usr/bin/env -S python3 -u

import os
import string
from Crypto.PublicKey import RSA
from Crypto.Util.number import bytes\_to\_long
from random import SystemRandom

def getkey():
    if os.path.isfile("key.pem"):
        with open("key.pem", "rb") as f:
            key = RSA.importKey(f.read())
    else:
        key = RSA.generate(2048)
        with open("key.pem", "wb") as f:
            f.write(key.exportKey("PEM"))
    return key

def random\_str(n):
    return "".join(\[random.choice(string.ascii\_letters) for \_ in range(n)\])

if \_\_name\_\_ == "\_\_main\_\_":
    random = SystemRandom()

    key = getkey()

    print(key.n)
    print(key.e)

    while True:
        msg0 = bytes\_to\_long(random\_str(2048 // 8 \- 1).encode())
        msg1 = bytes\_to\_long(random\_str(2048 // 8 \- 1).encode())

        x0 = random.randrange(key.n)
        x1 = random.randrange(key.n)

        print(x0)
        print(x1)

        v = int(input())
        print((msg0 + pow(v \- x0, key.d, key.n)) % key.n)
        print((msg1 + pow(v \- x1, key.d, key.n)) % key.n)

        guess0 = int(input())
        guess1 = int(input())
        if guess0 == msg0:
            print("You are on the half way of success, work harder!")
            if guess1 == msg1:
                print(open('flag').read())
                exit()

```

## 分析

题目代码模拟了 1-2 Oblivious transfer 协议的过程。Oblivious transfer（OT）协议是现代密码学中的一个协议，它可以做到发送者向接收者发送多条信息中的某一条。接收者可以选择接收多条消息中的哪一条，但只能得到一条消息，同时，发送者无从得知接收者选择的是哪一条。1-2 Oblivious transfer 协议就是从两条消息中选择一条的协议。一种可行的方法如下：![](../Images/963487c9f7a1f3d5e045b6d6bc258563.png)这个协议可以保证：

1.  Bob 只能得到 m0 和 m1（即代码中的 msg0 和 msg1）中的一个。
2.  Alice 不知道 Bob 获取了哪一个。

本题服务器充当了 Alice 的角色，只考察上面两个性质中第一个性质的攻击，如果同时答对 m0 和 m1 即可获得 flag。解题选手作为 Bob，通过 OT 协议的正常执行即可拿到 m0 和 m1 其中一个，也就是达到服务器输出 "You are on the half way of success, work harder!" 的条件，但这远远不够。（这句话其实是在骗人的）仔细分析题目代码，可以发现图中协议每次执行重新生成 RSA key，但题中重复使用了 RSA key，这就给了我们攻击协议的机会。正常执行协议获得 m0 后，为了得到 m1，选手需要解出 k1。为此，选手需要保持第一个连接不断，同时发起新的连接，并使用精心构造的 v，让新连接中的 k1' 和第一个连接的 k1 保持相同。可以很容易算出，满足这样条件的 v 就是 x0-x1+x0'。这样重复多次之后，选手可以拿到多个 k1' + m1' 的结果，其中 k1' 一直保持不变，而 m1' 不断随机变化，每次都是随机生成的。我们注意到，由于 m1' 仅由大小写字母构成，是所有可能字节的子集，所以我们可以由这种不均匀的分布来求解出 k1 可能的范围。这个求解的过程需要考虑 m1' 和 k1 相同位置字节相加时的进位。下面解题代码中求解的逻辑是，初始认为 k1 所有的字节都有 256 种可能（candidates）。每次得到新的 k1 + m1' 时，根据 m1' 每个字节可能的范围，把 k1 中每个字节不可能的情况去除掉。当 k1 所有的情况数（即每个字节可能的情况数）小于一个比较小的阈值时，开始对 k1 进行穷举。实践上，通过大约 300 条消息，就可以把 k1 的范围缩小到可以穷举的程度。这个穷举的过程不是必要的，可以一直获取新的数据直到 k1 的所有字节都完全确定，但穷举可以有效降低交互的次数。这个求解过程如果不想手写，也可以使用 z3 等求解器来实现，这里就不讲了。除此之外，第一条连接中发送的 v，其实可以是任取的，反正我们可以用相同的方法解出 m0 和 m1，但没必要这样做。把 v 取成 x0 与 x1 的平均值，也可以让我们只解密一个数就可以恢复 m0 和 m1。这道题一个有趣的点在于，你必须要同时向服务器发起两条连接，才可以成功攻击协议。**作为出题人，我想通过这道题告诉大家，现实中有很多的安全协议，从网站的鉴权与授权，到手机与基站的通信，都被发现过类似的缺陷。即，协议的单次执行和反复执行都是没有安全问题的，使得协议看起来完美无缺。但如果协议的多个 session 同时进行，甚至一个人在不同 session 中充当不同角色，就可能存在严重的安全漏洞。**

## 解题脚本

解题脚本的运行环境为 Python 3，需要安装 pwntools 和 pycrypto，安装命令为 `python3 -m pip install --upgrade git+https://github.com/Gallopsled/pwntools.git@dev` 和 `python3 -m pip install pycrypto`

from Crypto.Util.number import long\_to\_bytes, bytes\_to\_long
import string
from itertools import product

\# context.log\_level = 'debug'

port = 10001

    candidates = \[set(range(256)) for i in range(length)\]
    charmin = ord(min(string.ascii\_letters))
    charmax = ord(max(string.ascii\_letters))

    e = int(r1.recvline())

        x1 = int(r1.recvline())
        r1.sendline(str((x0 + c) % n))
        m0 = int(r1.recvline())
        m1 = int(r1.recvline())
        r1.sendline("0")
        r1.sendline("0")

        b = long\_to\_bytes(m0, length)\[::\-1\]
        for i in range(length):
            if i == 0:
                carrymin = 0
                carrymax = 0
            else:
                if min(candidates\[i \- 1\]) + charmin \>\= 256:
                    carrymin = 1
                else:
                    carrymin = 0
                if max(candidates\[i \- 1\]) + charmax < 256:
                    carrymax = 0
                else:
                    carrymax = 1

            if i == length \- 1:
                start = b\[i\] \- carrymax
                end = b\[i\] \- carrymin
            else:

                end = b\[i\] \- charmin \- carrymin

    x0 = int(r0.recvline())

    r0.sendline(str(x0))
    m0 = int(r0.recvline())
    m1 = int(r0.recvline())

    r0.sendline(str((m1 \- dec(x0 \- x1)) % n))
