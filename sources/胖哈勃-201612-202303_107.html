1. 测试waf


因为最初题目没有给出代码，所以探测waf成为了关键。
题目本身给了两个参数，一个为v代表表名，一个i代表id，两个参数都可以拿来测waf，只是因为触发waf返回空所以变的有点不太好测试，下面是测试方法。

参数v：输入不存在的表名时会返回no such table，触发waf时返回空。利用这一点可以测试waf。

参数i：首先我们需要测试他是否可以注入，通常情况下int型参数的过滤是强制转换为int，比如我们输入1abc最终会变为1

虽然题目没有直接强制转换，但sql本身也存在弱类型，当输入1abc，也会被强制转换为1

所以我们输入1=1返回1，输入1=2返回1，输入1^1返回1，就可以说明i被强制转换为int了。

之后我们输入1-，1#，1'，1=''，1;%00等都返回为空，则说明这些用于闭合符号或者注释的方法被过滤了。

所以参数i无法注入。

2. desc注入


确定i无法注入后，我们看看v，我们可以从报错放回信息no such table中，得出v是一个表名。关于表名的注入，我们很容易就能查到desc注入，且能发现表名注入的关键在反引号`，但这里除了反引号之外还有一个坑点，就是不知道mysql的链接方式。

通常情况下mysql的注释方式有#，/*，--+，;%00这几种。但是php在使用pdo的情况下，使用单独的;也可以截断sql，还可以执行这样的sql语句，而不报错。

post
v=character`;
使sql变为
desc `character`;`                    //通过
SELECT * FROM  acg_character`; where id =    //虽然反引号没有闭合但是语句依然执行了
现在测出`;可以注入出效果之后就比较容易了。


3. pdo注入


当使用php的pdo连接mysql时，默认会支持堆叠。但是因为waf过滤大部分可以用的关键字，关键点就变成了怎么进行堆叠注入。
通常情况，堆叠注入的流程是
   set @s='select 123';prepare x from @s;execute x;
下面列举几种定义变量的方式
   set @s='123';
   select '123' into @s;
   select @s:='123';
   do @s:='123';
可以看到:=是一个可以定义变量的方法，根据官方文档，还可以这样用
   select user from mysql.user where @s:='123'='123'
这样就绕过了set的限制，其他的限制可以使用16进制的方法来表示。
