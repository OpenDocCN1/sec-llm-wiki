**1\. Linux perf event简介**

Perf 是Linux下用来进行软件性能分析的工具。通过它，应用程序可以利用 PMU，tracepoint 和内核中的特殊计数器来进行性能统计。它不但可以分析指定应用程序的性能问题 (per thread)，也可以用来分析内核的性能问题，当然也可以同时分析应用代码和内核，从而全面理解应用程序中的性能瓶颈。

![](../Images/b212e5df750583c2b5eb649e4076ed99.png)

如上图所示，Linux Perf Events可以分为以下几类：

1)   硬件事件 Hardware Events: CPU 性能检测计数器；

2)   软件事件 Software Events: 利用kernel counters低层次的events，例如CPU迁移,minor faults, major faults；

3)   内核追踪事件 Kernel Tracepoint Events: 有些内核态的tracepoint被硬件编码到内核中的一些地方；

4)   用户态静态追踪事件 User Statically-Defined Tracing (USDT): 用户态程序中的静态tracepoint；

5)   动态追踪 Dynamic Tracing: 利用kprobe和uprobe在任意位置创建event；

6)   TimedProfiling: 可以间隔一段时间时间进行快照。

在抓取perf event前，可以设置一个过滤器，按指定的条件过滤要抓取的事件。本文所述内存泄露，就发生在设置过滤器过程中，涉及到的perf\_event\_parse\_addr\_filter函数中。

**2.perf\_event\_parse\_addr\_filter内存泄露分析**

perf\_event\_parse\_addr\_filter函数主要功能是解析过滤字符串，然后转换成事件过滤时用到的各种结构体、链表。函数调用栈：  

*   
*   
*   
*   
*   

```
perf_event_parse_addr_filter(perf_event *,char *, list_head *) : int       perf_event_set_addr_filter(perf_event*, char *) : int              perf_event_set_filter(perf_event*, void *) : int                     _perf_ioctl(perf_event*, unsigned int, unsigned long int) : long int                            perf_ioctl(file*, unsigned int, unsigned long int) : long int
```

  

可以通过调用ioctl函数，设置PERF\_EVENT\_IOC\_SET\_FILTER触发。

访问以下链接，可以查看Linux 内核5.9.3的perf\_event\_parse\_addr\_filter的代码

https://git.kernel.org/pub/scm/linux/kernel/git/stable/linux.git/tree/kernel/events/core.c?h=v5.9.3#n9991  

*   
*   
*   

```
9991       static int9992       perf_event_parse_addr_filter(struct perf_event *event, char *fstr,9993                         struct list_head *filters)
```

  

第二个参数char \*fstr，就是应用层传递过来的过滤字符串。

*   
*   
*   
*   
*   
*   
*   

```
10002 orig = fstr = kstrdup(fstr, GFP_KERNEL);10003 if (!fstr)10004 return -ENOMEM;1000510006 while ((start = strsep(&fstr, ",\n")) != NULL) {...............................................................................................................................................10024 token = match_token(start, if_tokens, args);
```

  

这个字符串首先调用kstrdup函数，复制一份后，再以逗号（,）或者换行符（\\n）作分隔符，被分隔成多个小字符串，每个小字符串按以下模式匹配：  

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   

```
static const match_table_t if_tokens = {       {IF_ACT_FILTER,"filter" },       {IF_ACT_START,       "start" },       {IF_ACT_STOP,         "stop" },       {IF_SRC_FILE,           "%u/%u@%s"},       {IF_SRC_KERNEL,    "%u/%u" },       {IF_SRC_FILEADDR,"%u@%s" },       {IF_SRC_KERNELADDR,"%u" },       {IF_ACT_NONE,       NULL },};
```

1)   没有百分号（%）的，字符串必须全部相同，例如：filter可以匹配得到IF\_ACT\_FILTER，filter1、filter\_8这些就没法匹配了

2)   有百分号（%）的，%u匹配数字，%s匹配字符串，例如：1234/5678@ABCD可以匹配得到IF\_SRC\_FILE，1234/5678可以匹配得到IF\_SRC\_KERNEL

在匹配完成后，按得到的token分别处理。

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   

```
10042 case IF_SRC_FILE:...............................................................................................................................................10058  if (token == IF_SRC_FILE || token == IF_SRC_FILEADDR) {10059   int fpos = token == IF_SRC_FILE ? 2 : 1;1006010061   filename = match_strdup(&args[fpos]);10062   if (!filename) {10063    ret = -ENOMEM;10064    goto fail;10065   }10066   }
```

  

在处理IF\_SRC\_FILE时，1234/5678@ABCD再次被分隔成3个小字符串：1234、5678、ABCD，存储在args中。在10061行，调用match\_strdup函数把ABCD复制一份后，赋给了filename。  

*   
*   
*   

```
10089  if (filter->action == PERF_ADDR_FILTER_ACTION_FILTER &&10090      !filter->size)10091   goto fail;
```

  

如果同时满足这两个条件的话，意味着当前处理的filter是非法的，直接跳转到fail分支处理，整个过滤字符串都不再继续处理，

*   
*   
*   
*   
*   

```
10142 fail:10143 free_filters_list(filters);10144 kfree(orig);1014510146 return ret;
```

  

在fail分支里面，可以看到，释放filters、释放掉orig后，就直接返回了。而在10061行复制得到的filename却没有做任何处理，这样就造成了内核内存泄露。

通过不断调用perf\_event\_parse\_addr\_filter函数，系统内存将持续消耗，无法得到释放，最终结果将是整个系统失去响应，只能重新启动。
