# 利用 Airflow 快速搭建企业安全运营自动化平台

**1\. 安全运营自动化**

企业的各类安全设备每天都会产生大量的告警和安全事件，安全运营人员在处理这些安全告警和事件的过程中，一方面，需要手工去对安全事件进行信息富化，搜集更多的关于告警、资产、威胁情报的相关信息，以进行调查和确认；另一方面，需要对一些低威胁的、明显未成功，或者并不关注的告警进行初步过滤。

在这个过程中，安全运营人员往往会进行大量的重复性工作，需要耗费大量的时间和精力进行各类查询和分析判断。本文旨在讨论通过一种开源的工作流引擎，Airflow，快速搭建企业的安全运营自动化平台（SOA），减少运营工作中的重复工作，提高安全运营的效率。同时，通过将安全运营的流程固化为剧本，可以帮助运营团队进行安全运营的经验的沉淀和积累。

![](../Images/23545684b25951d62b212e6823a358d3.png)

  

**2. 工作流引擎 Airflow**

Airflow 是一款开源的工作流引擎，自带 Web 界面， 以非常灵活的方式来支持数据的 ETL 过程，并且可以自动调度任务执行，同时也支持多种插件拓展各种对数据的处理和操作方式。

![](../Images/956964fc8471a389a6e8c239cc06f9ee.png)

  

Airflow 的部署可以参考网上的其他教程，在部署之后可以通过 Python 脚本来自定义剧本。Airflow 中的剧本都是 DAG （ 有向无环图 ），因此在 AIrflow 中是不支持循环的。一个 DAG 包含多个 Operator， 每个 Operator 中可以执行命令、进行数据处理、查询数据等操作。一个基础的 Airflow 剧本如下：

  

![](../Images/b5cfba0abd71b7d977ba8879e637d699.png)

  

在这个剧本中，定义了 t1、t2、t3 共 3 个节点，t1 节点指向 t2 和 t3 节点。在 Airflow 中可以通过 “>>“ 来定义节点之间的执行指向关系。通过定义 BashOperator 来定义执行的 bash 操作。

在实际使用中，每个 Airflow 工作流作为一个剧本，处理一条或一类告警。将日常的安全运营过程中常用的数据查询、调查操作，例如查询以指定 IP 相关的近 10 分钟内的所有告警，或者查询指定 IP 的所有 SQL 注入事件等等，将这些常用的操作编写成通用的 Operator，在剧本中通过传入不同的参数，进行灵活的配置以实现各种调查剧本。

  

**3\. 利用插件自定义操作**

在安全运营工作中，有非常多的操作是 Airflow 自身没有的，在这种情况下我们可以通过 Airflow 的插件功能，将自己常用但 Airflow 不支持的操作写成插件，后续就可以直接调用。通过 AirflowPlugin 提供的接口，用户可以直接编写插件。关于接口提供的具体功能，可以查询官方文档。自定义插件放置到 $AIRFLOW\_HOME/plugins 目录下，即可自动加载使用。

![](../Images/c2cb2a7c2b022236c6bd2ef06ab44584.png)

  

**4\. 剧本**

通过 Python 脚本，将一系列的常用调查和判断编排成剧本，一方面可以帮助安全运营人员进行信息富化，安全运营人员不再需要自己去手动查询和搜集信息，直接根据剧本运行结果进行调查分析；另一方面，安全运营人员可以利用工作流操作实现一些过滤规则，过滤掉大量的不需要关注的告警和事件，排除干扰信息，只需要将精力集中在过滤剩下的少量无法判定的告警上。

  

![](../Images/1e6cddf6b5b495150fee698698f16ccb.png)

  

**5\. 腾讯SOC SOAR**

腾讯安全运营中心（SOC）内置了 SOAR 平台，内置支持多种场景的安全剧本，同时支持多种安全设备的联动。当前已经支持下列 4 类场景的多种剧本：

*   告警准确性调优和确认
    
*   调查情报聚合  
    
*   告警分诊和主动通知
    
*   自动化响应
    

  

![](../Images/6070c38b34549ac7a2304b532b95100a.png)

  

安全运营人员也可以使用 SOAR 平台提供的编排界面，使用系统支持的 100 余种常用调查操作，进行快速灵活的剧本制定，制定符合自身安全运营工作的剧本。
