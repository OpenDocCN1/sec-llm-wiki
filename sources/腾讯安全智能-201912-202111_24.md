**导语** 基于Spark的SOC ML检测平台是为企业安全运营人员打造的一站式机器学习检测服务平台，为用户提供从数据预处理、特征转换、特征提取、模型训练、模型预测、异常结果可视化到用户实时反馈的全流程可配置（无需编写代码）可直接运用于生产环境的智能威胁检测服务。**本篇主要介绍基于SOC机器学习检测框架的行为分析建模的一个场景http隐蔽通信检测。**

  

**一、SOC机器学习检测框架及行为分析建模简述**

企业里的威胁检测主要针对细分安全场景进行检测，场景多且不同企业关注场景可能不同。我们针对于企业威胁检测的特点构建了统一的SOC机器学习检测框架，框架的目的有两个: **一是支撑SOC内置场景检测，丰富UEBA模块，增强SOC安全检测能力。二是提供客户自定义场景功能，以满足客户自定义场景发现未知威胁的能力。**

**行为分析异常检测：**

针对企业环境下一些复杂的场景，通过单维时间序列或者几条规则没法达到检测效果的场景，我们提出使用具有可解释性的行为分析建模方法。**一方面模型能自动通过多维特征共同影响检测结果，另一方面可通过可解释性解释结果的异常原因**。

  

**二、HTTP隐蔽通信及检测方案**

很多APT恶意软件通常会依赖于基于http的C&C隐蔽通道进行通信，因为一方面大多数企业允许浏览web，另一方面正常的web浏览行为会产生大量的请求。基于http进行通信的恶意软件较容易把通信行为隐藏在大量的web 请求中。目前大多的安全设备采用根据恶意软件特点去识别恶意通信例如：基于签名的方式等等，但是这种方法很容易被攻击者绕过。

  

**本文提出了一种基于图过滤+同类异常检测+历史异常检测的方式检测基于http的隐蔽通信**，本方法不基于已知恶意软件的特点，主要基于企业内网真实的正常数据建模，先通过图构建过滤掉正常的浏览行为，再通过同类对比和历史对比的方式检测异常通信。

  

**业界对比：**

  

**目前检测http可疑通信的主要方法：**

**基于签名检测：**基于签名检测主要是通过分析已知的恶意软件样本的通信方式，比如：请求头中包含某类字符等等，直接匹配检测。这种方式很容易被攻击者绕过。没法发现未知的恶意软件通信。

**1\. 流量数据预处理：**

对原始http流量分析过滤掉大部分正常流量。

  

1）过滤到内对内流量，只保留内对外流量。

  

2）过滤掉高频业务流量: 对企业内网服务器请求的url数量统计排序，过滤掉top 3 的url流量数据。

  

3）构建访问图，识别正常访问行为

  

![](../Images/725b96f4e19abf578198ffb3a78df728.png)

  

a. 将http 数据聚成不同的簇

  

对每台服务器，根据User-Agent 将http 数据聚成不同的簇，相同的UA 在同一簇。

  

b.构建图，给每个簇打类型标签

  

将簇的类型分为两种：backgroud和brower。

  

Background : http 流量不是由用户直接产生的,例如反病毒软件更新查询。这些应用一般在通信过程中都有固定的模式。

  

Brower: 流量器访问产生的http流量。

  

当一个用户访问了一个网站，浏览器会产生一个web页的请求，一旦html页面被下载，浏览器会产生额外的http请求去提取额外的信息，比如图片，脚本，CSS等等。这是浏览器所特有的，可以区分出backgroud和brower。

  

我们可以通过http之间的请求关系构建refer 图，Refer 图构建过程如下：

  

对每一个content-type 为html, javascript,css 或者flash 的请求头，我们把它当做head 节点。一个head节点可产生其他请求，一旦我们识别出一个簇中所有的head节点，我们把他们链接到又他们产生的子节点上，这样一个refer图生成。如果一个节点的referer或者origin域匹配head节点的host值，那么就拉一条边把这两个节点连接起来。将refer图中相关节点标识为browser。

  

而未被连接到refer图的簇，被标识backgroud，用于后续进一步分析。

  

**2.特征提取**

  

提取五类特征：

  

人为访问行为特征：是否有cookie；是否有http\_ref；server 是否常见；user agent 是否常见；host url 是否常见等等。

  

http requests长度特征：request长度；URL长度；URL参数长度；header长度；请求body长度等等。

  

http requests结构特征：URL参数名平均长度；URL参数值的平均长度；header名的平均长度；header值的凭据你长度等等。

  

http 请求的熵特征。

  

http请求时间相关特征：上一分钟请求数；上一分钟外发字节数等等。

  

**3.算法**

我们从两个思路检测异常，两种思路的检测结果进行ensemble，得到最终的结果。

  

**基于历史的行为异常检测**：对每个src\_ip检测，基于一周的特征数据训练训练正常的http访问模型。针对每个src\_ip新的一个小时的数据进行预测是否有异常。

  

**基于同类的行为异常检测**：在一个小时内，基于同类hosts的特征数据训练正常的http访问模型。检测异常的ua行为。

  

**异常检测算法**：maha\_svd, 孤立森林等，以maha\_svd为例。

  

![](../Images/41410bba121e69a35cc703a7184ea84d.png)

  

**算法流程如下：**

\*  获取N天的流量数据，提取检测场景相关的特征,构成正常流量矩阵

\*  去噪：通过RPCA 过滤噪声数据

\*  通过SVD矩阵分解计算马氏距离

\*  基于马氏距离归一化打异常分值（0-100）

\*  基于z-score 输出重要特征集

  

**4\. 策略**

模型结果ensemble

基于同类的异常检测和基于历史的异常检测的结果取交集

UA白名单

常见的正常UA过滤

静态策略

例如：上一分钟请求数大于threshold等等。

  

**5.归一化**

将结果进行归一化，既是拉取原始数据，统一可视化数据。将归一化后的数据写回到ES，kafka，mysql等，以便产品展示。
