开发工程师的生涯中总是要经历几次Code Review的洗礼
他二哥刚就职时，第一次提交上线代码CR，
几十行的代码提交了十几次才通过。

修改了一夜后，终于得到了一个“LGTM“评论

这真是二哥一段难忘的回忆

（LGTM=Looks Good to Me）


他二哥的同事们也分享了不少在

Code Review的难忘经历

一起来看看这些不同等级的“名场面”吧



其实CR是非常必要的一个环节，

仔细进行CR可以在开发阶段发现大部分问题，

好的代码风格和设计也需要通过CR展现出来。

前期 CR 可以发现很多不足和问题，

慢慢提高了代码质量，要改的 Bug 就少了。


最后温馨提醒一下，

CR别人的时候至少给一条正面评价，

欲扬先抑or先抑后扬都可以，

都是对提升团队融洽度极好的。

各位大佬还有哪些难忘或者有趣的经历

一起在评论区分享吧！
