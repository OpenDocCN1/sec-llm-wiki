# 关于安全情报能力和应用的一些思考

网络威胁情报（Cyber threat intelligence，CTI）一直是网络安全中的一个火热的话题的，从google trends的数据来看，一直是处于上升的一个态势：

![](../Images/af65b49beeb127920f2788067e06b08b.png)

笔者从2014年接触到威胁情报到现在，8年有余。犹记得当初那段时间，安全威胁情报还是个时髦的名词，圈里张口闭口都是威胁情报，还出现了各种包装成威胁情报的产品、安全威胁情报为主议题的安全大会，好不火热。不过近几年，随着其他新概念的不断出现，安全威胁情报的热度下降了不少。但是，这并非因为大家抛弃了威胁情报这个概念，相反，各安全厂商已经从吹嘘概念到踏踏实实地在把威胁情报的能力落地，把威胁情报作为安全产品能力的基座来进行打造。

  
因此，本文就以笔者自身对威胁情报的一些理解和思考，来谈谈甲方企业在安全建设中，到底需要怎么样的威胁情报，威胁情报能帮助甲方如何更高效地进行安全运营工作。

  

**01**

**从威胁情报到安全情报**

  

既然谈威胁情报，我们先从威胁情报的定义开始。对于威胁情报，并没有一个标准的定义，每个人，每个安全厂商，应该都有自己的理解和定义。但是，目前普遍被大众接受的，或者认可的，是Gartner在2014的《安全威胁情报服务市场指南》（Market Guide for Security Threat Intelligence Service）中提出的一个定义：

威胁情报是一种基于证据的知识，包括了情境、机制、指标、影响和操作建议。威胁情报描述了现存的、或者是即将出现针对资产的威胁或危险，并可以用于通知主体针对相关威胁或危险采取某种响应。

  

事实上，威胁情报的概念和定义，是针对传统的IT系统的威胁的。但目前的攻击者进行网络攻击活动，为了避免被发现，也并非完全从IT系统展开的。比如，为了获取攻击入口，可能针对该企业的供应商等第三方来攻击，窃取相关的账号；也可能从暗网等地方购买企业关联的账号信息；亦或是买通企业员工，利用职务便利来泄露信息（如Lapsus$勒索团伙入侵微软）。又如，攻击者会注册一些跟所要攻击目标类似的网址，建立钓鱼网站，来搜集相关的信息。而国家间的网络攻击活动，甚至会派出相关的间谍，去目标企业门口发放传单、投递含有颜色小视频的U盘等。如，破坏伊朗核设施（浓缩铀的离心机），使得伊朗核发展足足倒退了2年的"震网"病毒，根据相关人士透露，最初始的攻击就是荷兰情报机构招募的一名伊朗间谍帮助美国和以色列在伊朗纳坦兹核离心机上安装了"震网"病毒。

  

因此，我们需要把情报的概念扩充到第三方情报（供应链），品牌情报，攻击者情报，甚至跟地缘政治相关的情报等等。传统的威胁情报已经很难涵盖这些内容。因此，Recorded Future在《The Security Intelligence Handbook》Third Edition（安全情报指南第三版）中，提出了安全情报的概念，用以涵盖包括传统威胁情报在内的所有安全相关的情报。

![](../Images/bc035e59545caf8281dd4b17b0f977e4.png)

  

**02**

**我们需要怎么样的情报？**

那么，我们到底需要怎么样的情报呢？我们首先从军事上的一些案例来理解下。  
比如，场景一：某国家安全机关获取到一个情报：某恐怖组织将针对某地的市中心发起恐怖袭击活动。

![](../Images/875c0c1ae8643ee5262a20cc16a76172.png)

那么作为国家安全机关，你需要得到什么样的具体情报呢？  

*   首先，谁？这些恐怖的身份信息是什么，有什么特征。不然怎么去进行抓捕？
*   其次，为什么？为什么判断他们是恐怖分子？有什么依据吗？会不会误抓好人？虽然特殊时候，可以"格杀勿论"，但是大部分的时候，还是需要谨慎；
*   再次，怎样？这些恐怖分子将何时，何地，通过怎么样的方式发动恐怖活动？人肉炸弹，还是手持AK47？还是有其他的方式？否则，执法机关贸然地出动，可能会全军覆没；
*   再次，原因？这些恐怖分子的背景是什么，为什么要发起这次恐怖活动？不知道原委，很难彻底化解"仇恨"。有第一次就会有第二次，永远活在恐怖当中？
*   最后，更多？怎么找出更多的恐怖分子呢？情报里的人员信息已经足够了么？有什么更多的策略和特征可以把可疑人物都筛选出来进行调查？

  
  
场景二：目前俄乌战争如火如荼，那么，虽然我们国家没有参与其中，但是，我们依然需要从战争中获得一些情报以及启示。  

![](../Images/7723f85a00650c144d267caab9e950a0.png)

那么国家相关部门，需要得到哪些情报呢？

*   首先，战术。我们需要观察和了解俄乌双方使用的攻击的战术和作战策略是什么？
    
*   其次，武器。俄乌双方都使用了哪些武器？杀伤力怎么样？
    
*   再次，防御。如果跟我军开战，我军能抵挡住么？我军该怎么提前做好防御措施？
    
*   再次，反攻。双方是否存在弱点？使我军可以反攻，或者主动出击？
    
*   最后，舆情。需要观察俄乌战争中，国际上的舆情是怎么样的？相关国家的制裁手段有哪些？反制裁的手段又有哪些？为万一某天台海的冲突提前做好准备。  
    

  

说完了军事中的情报，那么网络安全中，甲方企业需要什么样的情报？

![](../Images/26b65336c9bc72bdc72355fe557e6c2d.png)

根据这个问题，我们可以通过SANS针对网络威胁情报进行的调查报告来发现一些端倪：调查一：你的企业是否生产或使用威胁情报？该问题来自2021年SANS的网络威胁情报报告。

![](../Images/ec851264dcef2e41af6939b99bfd69ce.png)

从调查结果来看，到2021年，有85%的企业已经在使用或者生产威胁情报，而剩余15%的企业虽然还未，但也已经有计划要生产或者使用了。无计划的已经完全清0。可能正是因为这个原因，2022的报告中并未再次做这个问题的调查。  
  
调查二：企业收集情报的类型有哪些？调查结果为：  

![](../Images/0ff22cf5d856ca3e2e66174ffb8fbbc0.png)

可以看出，外部来源，如新闻和媒体报道的，跟情报供应商提供的情报是最主要的情报收集来源。自建的数据来源相对偏少，如从内部IDS、防火墙、终端等安全系统收集的安全数据的比重为57.8%，蜜罐的仅为25.3%。调查三：哪些类型的威胁情报对您的运营最有用？![](../Images/d64f459918a43a1c611ff77f556c0202.png)

从调查结果来看，当前最有用的情报是攻击中使用的恶意软件的详细信息、攻击者使用的漏洞信息以及攻击者趋势的信息。而未来一年，

所在行业和地区的攻击组织的详细信息将会成为对运营最有用的信息。其次为攻击中的归属信息。而目前一些情报厂商提供的基础IOCs等信息，在调查中认为有用的比重并不高，当前的比重为73.1%，而1年后的比重将下降到40.3%。

  

**03**

**安全情报的分类**

根据上面对我们需要需要怎么样的安全情报的思考，我们可以针对安全情报进行一下分类。目前比较认可的分类是战术情报、运营情报、战略情报。但是笔者认为，从实际甲方需要的情报，或者甲方不同人群的需要或者操作来看，安全情报可以分类为两类：可运营的安全情报、战略级的安全威胁。

![](../Images/6ee0d93986df47e9d07231e58e724596.png)

*   可运营的安全情报：主要对象是安全运营的人员，用于相关安全设备或者安全运营人员可以实际进行操作或者指导进行操作的情报。该分类的情报，更多的是实际所遇到的一些威胁信息。1）用于安全设备进行检测拦截的IOCs。该情报需要直接联动设备进行封禁，因此需要非常的精准，否则会引起误报；其次，IOCs由于变化太快，因此需要更有效的B（Behivor）IOCs。2）对（B）IOC进行分级分类。不同等级的威胁信息，处理的手段不一样。比如设备封禁完就完事了么？是否还需要针对拦截信息，进行进一步的研判或者应急响应？笔者认为，扫描类的情报，封禁就完事了（不过也不一定），而失陷类的情报，需要进行一定的应急响应。因此，如果安排应急和调查的优先级，分级分类的信息就尤为重要。3）丰富的上下文信息和判断依据。厂商提供的IOC情报真的准确么？这些IOC的情报的判断依据是什么？这些情报的信息越丰富越好，用于运营人员进行研判和操作；4）行动方案。甲方的安全运营人员，遇到一次攻击活动，受限于对全局的了解或者技能所限，可能对分析经验和处理经验相对欠缺。这时候，就非常需要情报厂商可以针对某家族或者某组织的攻击活动，给出相应的行动方案。比如面对某家族的攻击时，该如何进行攻击缓解？植入木马后的清除方案又是什么？该怎么进行加固以防止下一次再被入侵？除了手动的方案外，是否有一些专杀工具？或者联动各个安全设备进行快速处置？是否有SOAR、IACD的剧本或者实例？5）主动进行威胁狩猎。需要有些针对威胁狩猎的规则，可以进行前置或者事后的调查。6）传感器的遥测。遥感器，如终端Agent采集的数据是否能满足于检测这次威胁？若不能，需要补充怎么样的数据源？7）漏洞情报。漏洞情报有主动防御的部分，也有实际需要操作的部分，因此有些分类，把漏洞情报划为战略情报中。不管如何分类，漏洞情报需要指导甲方进行漏洞的修补以及漏洞的优先级排序。事实上，STIX2.1和信息安全技术网络安全威胁信息格式规范（GB/T 36643-2018）也已经包含了上述的一些信息和思想：  
    
    ![](../Images/caf776206a53b475c4a9658cf9fa29d3.png)
    
      
    
    ![](../Images/358b78fbd6b38c95f8ddc0221d1dd81a.png)
    
*   战略级的威胁情报：主要对象是企业的CISO或者相应的安全负责人。用于布局或者指导企业的安全建设方向。1）攻击活动和攻击趋势：需要了解目前哪些家族的攻击活动比较活跃，哪些组织又针对哪些行业进行了攻击活动？如是一家金融企业的安全负责人，必然关心是否有同类型的金融企业遭遇了对应的APT攻击。如果被某APT组织攻击了，需要思考如果对我们企业进行攻击，我们能防御住么？如果不能，需要做怎么样的加固策略？亦或是更改安全架构？2）品牌情报：重要的安全事件是会影响公司当前的形象的，甚至带来更多的经济损失，如影响重大的宕机事故，或者信息泄露，可能会影响整个公司的运作或者上市公司的股价，从而造成重大的经济损失。因此越来越多的企业来关注自身品牌的情报，包括是否存在数据泄露、是否有人在暗网或者tg中售卖相应的数据信息？是否存在仿冒的域名或者钓鱼网站？3）供应链情报：如上述所说，目前的攻击活动，可能并非直接从攻击目标入手，可能会从该企业的上下游供应链进行入手。因此供应链的相关情报也至关重要。比如是否有对应的供应链企业被攻击，供应链中的组件或者系统是否存在弱点？4）情报服务：严格来说不属于战略级情报。情报服务是情报厂商根据所掌握的情报信息，对企业进行的一些额外的服务，如资产的探测、攻击面的检测、暴露信息和权限、API的探测等。用于企业收敛资产和权限。

  
可以看到，从运营级的安全情报到战略级的安全情报，也是针对企业一次从被动防御到主动防御的过程。  
总而言之，不管情报如何分类，安全情报需要覆盖攻击的预防、检测、调查、响应的OODA循环的各个阶段。下面有一张图可以说明（来源：http://correlatedsecurity.com/why-cyber-threat-intelligence-informed-security-operations-is-important/）：

**安全情报的相关实践**

一、基础情报的信息和分类如某个设备有下面的告警，安全运营人员是不是会很懵逼？无从下手？  

![](../Images/1cf30fc667152c25dba55ea46ca2a491.png)

那么如果加上目的ip的对应的国家或地区信息呢？是不是会更直观？

![](../Images/6024026ff507d2de51fb8d9529b1e107.png)

但是够了么？运营人员这样就能很好的研判了么？依然不够。那如果加上情报的对应方向呢？

![](../Images/ff44701509cc3d3f6c1e36b48800ffec.png)

是否可以碰撞出一些了？比如是探测类的，但是又标注了出站类的情报，是否就存在误报了呢？如果方向是一致的，那么出站类的情报是失陷类的，是不是响应的优先级就更高了呢？  
那么，这样足够了呢？如果加上情报的归属信息呢？  

![](../Images/827e9d8f2315421114b8ba01566d83f0.png)

这样是不是就更加明确了。可以针对探测类或者失陷类，以及对应的家族和组织信息，进行更好的研判。除了更好的帮助分析人员进行威胁的研判外，分类分级的情报信息和标签还能指导运行人员进行下一步动作的优先级选择。一般情况下，甲方的安全设备或者soc/siem等平台每天都会有海量的告警，所有告警都跟踪和响应么？这显然不现实，极少有企业有人力和资源来支撑所有告警都来跟踪，分析，调查和响应一遍。因此分类分级信息就尤为重要了。比如通常情况下，APT和勒索病毒是优先级最高的，其他的后门等失陷类其次，广告流氓软件类再次，探测扫描类的就相对靠后了。当然不同的等级处理流程也不一样，探测类的拦截加情报库基本完事，失陷类的要去评估失陷多少主机，造成多少影响和损失，是否有数据泄露等。  
此外，引申出来的问题是，如这种研判类或者聚合类的情报平台，需要提供怎么样的信息呢？哪些信息才是对运营人员最迫切需要的？  
聚合类的平台，一般包含三种信息：  
1、本身的信息，如针对文件，包含文件的hash、路径、文件名、文件大小、节表、导入导出表等等文件本身的基础信息；2、关联信息：比如ip，反查的域名，访问样本信息等；  
3、情报信息：危害、家族、组织等因此，最重要的是情报相关的信息。需要一目了然的让运营人员知道相关查询东西的危害、归属信息，以及判断依据，解决方案等。笔者认为，对你一条指标，最重要的是危害跟作用，其次才是家族，组织等归属信息。现在的情报有点把这些混为一谈。比如查一个ip，给的信息是海莲花，不了解的人员，鬼知道海莲花是什么，有什么危害？直接了当的告诉用户是后门的c&c，相信绝大部分从业者都知道是怎么回事，然后才会去关注是哪个家族的后门，属于什么组织。因此，笔者认为的情报效果图应该为：

二、进行威胁狩猎的规则对于甲方安全运营团队来说，威胁狩猎是个重要的事项，但也需要很多的安全技能。  
对于狩猎来说，主要分为三个阶段：数据采集、威胁狩猎、狩猎结果。

*   数据采集：需要对企业内使用的安全设备进行数据的采集，包括EPP/EDR、IPS/IDS/NTA/NDR、邮件网关、准入系统、行为管理等。有了数据，才可以进行下一步的狩猎工作。至于采集什么样的数据，情报提供厂商需要对每种威胁源提供对应的要进行遥测的数据源。也可以甲方企业自己指定采集规则；
*   威胁狩猎：进行威胁狩猎的方式包括基于数据的狩猎（如异常的流量、非正常的文件流向等）、基于情报的狩猎（根据基础(B)iocs情报等）、基于TTPs的狩猎（依托于MITRE ATT&CK等）、基于实体的狩猎（针对高风险机器的定向狩猎）、混合狩猎（包含上述各种方式）。
*   狩猎结果：包括威胁的发现、事件的调查、应急响应等。  
    
    ![](../Images/227013efd9dd99e1888fbae48027aa98.png)

但是这里的问题是，企业真的需要知道所有的漏洞信息么？一方面，很多应用在国内根本不流向也不会使用，这些应用的漏洞信息没太大价值；另一方面，很多漏洞可能没有利用，或者很难被利用。这些也不是甲方需要高优先级关注的。当然针对能力或者精力有余的团队，所有漏洞都打也没什么问题。但现实是，企业在修补补丁的时候，存在很多的限制，无论是精力还是环境限制。因此这里需要情报厂商推送情报的时候，附带情报的危害程度等信息。  
每年被爆出的漏洞非常多，如每年的漏洞数量统计（来源：IBM X-Force Threat Intelligence Index 2022）：

但是根据调查，事实上仅有八分之一的漏洞存在利用。而一般出现在野攻击的时间约2周到3个月，如果超过这个时间还没出现，说明攻击者不屑于用这个漏洞，或者有更好用的可以替代的漏洞方案，或者说是利用难度非常大。事实上，很多企业在判断漏洞的严重性的时候，是基于CVSS分数的。但笔者认为这没太大价值，仅供参考。  
举个例子，2017年曾出现一个lnk漏洞CVE-2017-8464，这是一个被CVSS3.0判断为8.8的高危漏洞：

当时刚出现的时候，绝大部分厂商包括笔者都认为会是一个王炸漏洞，会被大量APT组织使用。因为漏洞确实好用，"看一眼"无需操作就能中招。但是实际攻击中，虽然也有一些APT组织使用，但远没达到当时的预期，该漏洞的使用并没有想象中的那么多。

**05**

**总结**

安全情报作为安全产品最重要的底层能力是至关重要的。当然安全厂商的引擎也要针对情报来进行一些改革。比如，某些安全厂商的引擎，只支持文件查杀，只针对单一的行为进行检测，因此需要改造成基于TTPs的综合检测；Agent需要具备检测ATT&CK的能力等。  
此外，单独的情报产品和服务，对甲方来说同样有用。但是甲方需要的不仅仅是IOCs形式的基础情报，更多的是可以指导甲方进行预防、检测、调查、处置、应急响应等的综合性的情报能力。目前来看，能提供这些综合能力的厂商是少之又少。  
当然本文只是笔者自己对情报的一些思考，里面难免存在一些考虑不周全或者错误的地方。希望同行朋友可以指正和交流，一起为国内的情报生态和能力而努力！
