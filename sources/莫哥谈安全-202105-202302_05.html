一、Data Source更新

二、新增的技术点（ATT&CK for Enterprise）

1、新增的技术

  • T1619：Cloud Storage Object Discovery（云存储对象发现）

    该技术为攻击者可能会枚举云存储基础设施中的对象。识别可用的存储服务（即云基础设施发现）后，攻击者可以访问存储在云基础设施中的内容/对象。

  • T1615：Group Policy Discovery（组策略发现）

    攻击者可能会收集有关组策略设置的信息，以确定权限提升的路径、域内应用的安全措施，以及发现域对象中可被操纵或用于融入环境的模式。

  • T1620：Reflective Code Loading（反射代码加载）

    攻击者可能会反射性地将代码加载到进程中，以隐藏恶意payload的执行。



2、新增的子技术

  • T1547.015：Boot or Logon Autostart Execution：Login Items（启动或登录自动启动执行：登录项）

    该技术使得攻击者可能会添加登录项以在用户登录时执行以获得持久性或升级权限。登录项是用户登录时自动启动的应用程序、文档、文件夹或服务器连接。

  • T1213.003：Data from Information Repositories: Code Repositories（来自信息库的数据：代码库）

    攻击者可能会利用代码存储库来收集有价值的信息。一旦攻击者获得对受害者网络或私有代码存储库的访问权限，他们可能会收集敏感信息，例如专有源代码或软件源代码中包含的凭据。获得软件源代码的访问权限可能允许攻击者开发漏洞利用，而凭据可以使用有效帐户提供对其他资源的访问权限。

  • T1564.008：Hide Artifacts: Email Hiding Rules（隐藏工件：电子邮件隐藏规则）

    攻击者可能会使用电子邮件规则将入站电子邮件隐藏在受感染用户的邮箱中。攻击者可能会利用受感染用户邮箱中的电子邮件规则来删除和/或将电子邮件移动到不太显眼的文件夹中。攻击者可能会这样做以隐藏安全警报、C2 通信或对从受感染帐户发送的内部鱼叉式网络钓鱼电子邮件的响应。


  • T1564.009：Hide Artifacts: Resource Forking（隐藏工件：资源分支）

    攻击者可以使用资源分叉来隐藏可能直接存储在文件中的恶意数据。攻击者可以使用附加的资源分叉在指定的偏移处执行内容，然后将其移动到可执行位置然后调用。资源分叉内容也可能被混淆/加密，直到执行。


  • T1562.009：Impair Defenses: Safe Mode Boot（削弱防御：安全模式启动）

    攻击者可能会滥用安全模式来禁用可能无法启动受限的端点防御。通过修改引导配置数据 (BCD) 存储（管理引导应用程序设置的文件），可以在下次重新引导后强制主机进入安全模式。攻击者还可以通过修改相关注册表值将其恶意应用程序添加到以安全模式启动的最小服务列表中。恶意组件对象模型(COM) 对象也可以在安全模式下注册和加载。


  • T1562.010：Impair Defenses: Downgrade Attack（削弱防御：降级攻击）

    攻击者可能会降级或使用可能过时、易受攻击和/或不支持更新的安全控制（例如日志记录）的系统功能版本。

  • T1036.007：Masquerading: Double File Extension（伪装：双文件扩展名）

    攻击者可能会滥用文件名中的双扩展名作为伪装真实文件类型的手段。文件名可能包含一个次要文件类型扩展名，它可能只显示第一个扩展名，例如，一个名为的可执行文件附件Evil.txt.exe可能会显示Evil.txt给用户。然后，用户可能会将其视为良性文本文件并打开它，从而无意中执行了隐藏的恶意软件。

  • T1027.006：Obfuscated Files or Information: HTML Smuggling（混淆的文件或信息：HTML 走私）

    攻击者可能会通过将恶意payload隐藏在看似良性的 HTML 文件中来走私数据和文件，使其通绕过内容过滤器。滥用 JavaScript Blob 和/或 HTML5 下载属性，通过 HTML 走私 向受害者提供有效payload。

  • T1505.004：Server Software Component: IIS Components（服务器软件组件：IIS 组件）

    攻击者可能会安装在 Internet 信息服务 (IIS) Web 服务器上运行的恶意组件以建立持久性。攻击者可能会安装恶意 ISAPI 扩展和过滤器来观察和/或修改流量，在受感染的机器上执行命令，或代理命令和控制流量。攻击者还可能安装恶意 IIS 模块来观察和/或修改流量。


  • T1218.014：Signed Binary Proxy Execution: MMC（签名二进制代理执行：MMC）

    攻击者可能会滥用 mmc.exe 来代理恶意 .msc 文件的执行。攻击者还可能滥用 MMC 来执行恶意的 .msc 文件。

    如：mmc.exe -Embedding C:\path\to\test.msc

  • T1218.013：Signed Binary Proxy Execution: Mavinject（签名二进制代理执行：Mavinject）

    攻击者可能会滥用 mavinject.exe 来代理恶意代码的执行。Mavinject.exe 是 Microsoft Application Virtualization Injector，Windows应用程序。

  • T1614.001：System Location Discovery: System Language Discovery（系统位置发现：系统语言发现）

    攻击者可能会尝试收集有关受害者系统语言的信息，以推断该主机的地理位置。

四、软件和组织

本次更新，对软件和组织也进行了不少的更新。

更新的软件包括：Clop、LiteDuke、Stuxnet、TRITON等。

更新前的软件数为585，更新后为638.


更新的组织包括：TeamTNT、Transparent Tribe等，也对一些组织进行了修改，包括APT32、Fin7、Kimsuky、TA505等。

更新前的组织数为122，更新后为129。


五、缓解措施

增加的新的缓解措施为：M1057：Data Loss Prevention（DLP，数据丢失防护）



六、总结

整体而言，此次更新的力度不算太大，除了Data Source单独的成项外，其他的技术、组织、软件、缓解的更新都没有伤筋动骨。这也基本符合年初发布的ATT&CK 2021的路线图的规划（https://medium.com/mitre-attack/att-ck-2021-roadmap-68bab3886fa2）。
