## 随着技术的发展，JavaScript 模块化已经成为很重要的开发方式。2009年 node.js的诞生，并在服务器端采用模块化开发的方法，就推进了前端的模块化开发的发展。

  

## **为什么要做 javascript 模块化**

* * *

  

随着项目的迭代更新，网页的业务逻辑越来越复杂，javascript 代码越来越多，这必然会影响到维护和性能的成本；加上开发人员的流动，多人开发也会带来一系列的问题。

  

> *   **命名冲突**
>     
> 
>   
> 
> 这是多人开发不得不面对的一个问题，每个人都自己定义方法名，变量名，很容易就造成命名冲突。很多程序员也都为此苦恼，想要命名一个合适的并且没有被占用的名字，却常常纠结一番。
> 
>   
> 
> *   **文件依赖**
>     
> 
>   
> 
> 也许你现在已经抽取出了公共方法，或者提取出了通用组件，避开了大量重复造轮子的任务。但问题也来了，组件之间如果存在着依赖关系，就必须先引入依赖文件。项目简单还可以人工完成依赖，当项目越来越复杂，复杂的文件依赖会让人抓狂。如果还在使用 script 标签来引入各种依赖文件，开发效率会很低。

  

**两个模块定义规范：AMD 和 CMD**

* * *

  

> *   **AMD(Asynchronous Module Definition) - 异步模块定义规范。**
>     
>       
>     
>     AMD 规范定义的模块和模块依赖都会被异步加载，这也和浏览器异步加载模块的环境刚好适应。
>     
>       
>     
> *   **CMD(Common Module Definition) - 通用模块定义规范。**
>
