**挑战1 透明的修改 HTTP 请求**

本题目主要考察了 golang http 标准包的熟悉程度，涉及到在 golang 中一个 HTTP 请求是怎么样发起的。题目要求实现一个简单的数据校验功能，对请求 body 做 md5 计算，然后把结果转为十六进制添加到请求 header 中，头部名称为 X-Md5。也就是在 HTTP 请求 header 中添加一个 X-Md5: <hex md5 of body> 键值对，如果body为空那么就不填。

在 Golang HTTP 请求会使用到 http.Client，它内部实际上是创建出一个 http.Request，再用 http.RoundTripper.RoundTrip 来做真实的请求。RoundTrip 内部才是真实的数据传输相关的操作。但 http.RoundTripper 实际上是一个 interface，只有一个方法 RoundTrip(\*Request) (\*Response, error)。所以如果想实现题目需求，只需要实现 http.RoundTripper 接口，并在具体实现中完成 MD5 哈希的计算并设置头部就可以满足题目要求了。

参考代码如下：

> package md5transport
> 
> import (
> 
>     "bytes"
> 
>     "crypto/md5"
> 
>     "encoding/hex"
> 
>     "io/ioutil"
> 
>     "net/http"
> 
> )
> 
>   
> 
> type Transport struct {
> 
>     http.RoundTripper
> 
> }
> 
>   
> 
> func NewTransport(transport http.RoundTripper) http.RoundTripper {
> 
>     return &Transport{transport}
> 
> }
> 
>   
> 
> func (t \*Transport) RoundTrip(req \*http.Request) (\*http.Response, error) {
> 
>   
> 
>     // do something
> 
>     if req.Body == nil {
> 
>         return t.RoundTripper.RoundTrip(req)
> 
>     }
> 
>   
> 
>     b, err := ioutil.ReadAll(req.Body)
> 
>     req.Body.Close()
> 
>     if err != nil {
> 
>         return nil, err
> 
>     }
> 
>   
> 
>     if len(b) ==0 {
> 
>        return t.RoundTripper.RoundTrip(req)
> 
>     }
> 
>   
> 
>     m := md5.Sum(b)
> 
>     req.Header.Set("X-Md5", hex.EncodeToString(m\[:\]))
> 
>   
> 
>     // 由于 ioutil.ReadAll 方法会读取到 EOF，所以需要重置 Body
> 
>     req.Body = ioutil.NopCloser(bytes.NewBuffer(b))
> 
>   
> 
>     return t.RoundTripper.RoundTrip(req)
> 
> }

上面代码中，通过 ioutil.ReadAll 直接读取 req.Body, 后面又进行了重新赋值操作。另一种方法是通过通过 req.GetBody 直接返回 req.Body 的复制。

**挑战2 缓存请求执行结果**

第二道题目的要求是基于 github.com/golang/groupcache/singleflight 包实现支持过期时间的缓存系统。这道题目考察以下知识点：

*   并发访问的控制；
    
*   判断缓存值是否过期;
    

对于第二点非常容易实现，只需要每一个缓存值附加一个生成时间，在访问该值时判断时间差是否超过预设的生存时间即可。

由于要求是实现一个键值缓存系统，所以可以基于 Golang 内置的 map 类型实现。但由于 map 默认不是并发安全的（在 golang 1.9 中可以使用 sync.Map ），所以想到使用 sync.RWMutex 读写锁控制并发访问。第一版代码如下：

> package cacheflight
> 
>   
> 
> import (
> 
>     "sync"
> 
>     "time"
> 
>   
> 
>     "github.com/golang/groupcache/singleflight"
> 
> )
> 
>   
> 
> type cacheResult struct {
> 
>     data  interface{}
> 
>     ctime time.Time
> 
> }
> 
>   
> 
> // Group is a ttl cache
> 
> type Group struct {
> 
>     cacheExpiration time.Duration
> 
>     sfg             \*singleflight.Group
> 
>     cache           map\[string\]cacheResult
> 
>     lock            sync.RWMutex
> 
> }
> 
>   
> 
> // NewGroup return ttl cache
> 
> func NewGroup(cacheExpiration time.Duration) (group \*Group) {
> 
>   
> 
>     // do something
> 
>     group = &Group{
> 
>         sfg:             &singleflight.Group{},
> 
>         cache:           make(map\[string\]cacheResult),
> 
>         cacheExpiration: cacheExpiration,
> 
>     }
> 
>     return
> 
> }
> 
>   
> 
> // Do cache
> 
> func (g \*Group) Do(key string, fn func() (interface{}, error)) (ret interface{}, err error) {
> 
>   
> 
>    // map 的并发访问控制
> 
>     g.lock.RLock()
> 
>     result, ok := g.cache\[key\]
> 
>     g.lock.RUnlock()
> 
>   
> 
>     if !ok || result.ctime.Add(g.cacheExpiration).Before(time.Now()) {
> 
>   
> 
>         return g.do(key, fn)
> 
>     }
> 
>     return result.data, nil
> 
> }
> 
>   
> 
> func (g \*Group) do(key string, fn func() (interface{}, error)) (ret interface{}, err error) {
> 
>   
> 
>     return g.sfg.Do(key, func() (interface{}, error) {
> 
>         ret, err = fn()
> 
>         if err != nil {
> 
>             return ret, nil
> 
>         }
> 
>   
> 
>         result := cacheResult{
> 
>             data:  ret,
> 
>             // 缓存值生成时间
> 
>             ctime: time.Now(),
> 
>         }
> 
>         g.lock.Lock()
> 
>         g.cache\[key\] = result
> 
>         g.lock.Unlock()
> 
>   
> 
>         return ret, nil
> 
>     })
> 
> }

但是根据挑战提供的测试用例，上面代码有一定得几率测试失败。可以通过 for i in $(seq 100); go test -race; done; 执行测试发现该问题。仔细阅读测试用例代码，发现测试用例要求在并发访问中每一个 key 的真正执行体 fn 只执行一次，而以上的代码不满足该要求。可以引入 channel 解决该问题，如果发现有其他 goroutine 在执行 fn 时则等待，改善后的正确代码如下：

> package cacheflight
> 
>   
> 
> import (
> 
>     "sync"
> 
>     "time"
> 
>   
> 
>     "github.com/golang/groupcache/singleflight"
> 
> )
> 
>   
> 
> type cacheResult struct {
> 
>     data  interface{}
> 
>     ctime time.Time
> 
>     // 保证在并发访问时 key 对应的 fn 只执行一次
> 
>     doing chan bool
> 
> }
> 
>   
> 
> type Group struct {
> 
>     cacheExpiration time.Duration
> 
>     sfg             \*singleflight.Group
> 
>     cache           map\[string\]cacheResult
> 
>     lock            sync.RWMutex
> 
> }
> 
>   
> 
> func NewGroup(cacheExpiration time.Duration) (group \*Group) {
> 
>   
> 
>     // do something
> 
>     group = &Group{
> 
>         sfg:             &singleflight.Group{},
> 
>         cache:           make(map\[string\]cacheResult),
> 
>         cacheExpiration: cacheExpiration,
> 
>     }
> 
>     return
> 
> }
> 
>   
> 
> func (g \*Group) Do(key string, fn func() (interface{}, error)) (ret interface{}, err error) {
> 
>   
> 
>     // do something
> 
>     return g.do(key, fn)
> 
> }
> 
>   
> 
> func (g \*Group) do(key string, fn func() (interface{}, error)) (ret interface{}, err error) {
> 
>   
> 
>     return g.sfg.Do(key, func() (interface{}, error) {
> 
>   
> 
>         g.lock.Lock()
> 
>         result, ok := g.cache\[key\]
> 
>         if result.doing != nil {
> 
>             g.lock.Unlock()
> 
>             // 等待 fn 执行完成
> 
>             <-result.doing
> 
>             return g.do(key, fn)
> 
>         } else if !ok || result.ctime.Add(g.cacheExpiration).Before(time.Now()) {
> 
>             var doing = make(chan bool)
> 
>             result.doing = doing
> 
>             g.cache\[key\] = result
> 
>             // fn 执行完成后关闭 channel，使其他等待的 goroutine 能及时响应
> 
>             defer func() {
> 
>                 close(doing)
> 
>             }()
> 
>         } else {
> 
>             g.lock.Unlock()
> 
>             return result.data, nil
> 
>         }
> 
>         g.lock.Unlock()
> 
>   
> 
>      // 不同 key 的 fn 能做到并发执行
> 
>         ret, err = fn()
> 
>         if err != nil {
> 
>             return ret, nil
> 
>         }
> 
>   
> 
>         result = cacheResult{
> 
>             data:  ret,
> 
>             ctime: time.Now(),
> 
>         }
> 
>         g.lock.Lock()
> 
>         g.cache\[key\] = result
> 
>         g.lock.Unlock()
> 
>   
> 
>         return ret, nil
> 
>     })
> 
> }

上面代码中，goroutine 通过 <-result.doing 等待 fn 完成执行，这样就保证了并发时每个 key 对应的 fn 只会执行一次。也确保了不同 key 的 fn 能够并发执行。

**挑战3 实现 json 注释解析器**

本挑战要求实现一个 json 解析器，该解析器支持通过使用 # 进行单行注释，具体要求如下：

*   支持 # 作为 json 的注释字符，字符以及之后的都是注释；
    
*   当 # 出现在一对 " 之间的时候，# 不作为特殊字符；
    
*   当 " 是字符串内容时候，是用 \\" 来表示的，然后 \\ 是用 \\\\ 来表示的。
    

Golang 官方包 encoding/json 已经实现了标准的 json 解析器，不难想到可以基于该解析器实现注释功能。题目要求实现单行注释，所以只需要处理 json 文版的每一行，将注释文本全部剔除后，直接将处理后的文本交给 encoding/json包处理就行了。

完整的实现代码如下：

> package jsonex
> 
>   
> 
> import (
> 
>     "bytes"
> 
>     "encoding/json"
> 
> )
> 
>   
> 
> func Unmarshal(data \[\]byte, ret interface{}) error {
> 
>   
> 
>     lines := bytes.Split(data, \[\]byte{'\\n'})
> 
>     var trimed \[\]\[\]byte
> 
>     for \_, line := range lines {
> 
>         trimed = append(trimed, trimCommentsLine(line))
> 
>     }
> 
>     data = bytes.Join(trimed, \[\]byte{'\\n'})
> 
>   
> 
>     return json.Unmarshal(data, ret)
> 
> }
> 
>   
> 
> func trimCommentsLine(line \[\]byte) \[\]byte {
> 
>   
> 
>     var newLine \[\]byte
> 
>     var i, quoteCount int
> 
>     lastIdx := len(line) - 1
> 
>     for i = 0; i <= lastIdx; i++ {
> 
>         if line\[i\] == '\\\\' {
> 
>             if i != lastIdx && (line\[i+1\] == '\\\\' || line\[i+1\] == '"') {
> 
>                 newLine = append(newLine, line\[i\], line\[i+1\])
> 
>                 i++
> 
>                 continue
> 
>             }
> 
>         }
> 
>   
> 
>         if line\[i\] == '"' {
> 
>             quoteCount++
> 
>         }
> 
>   
> 
>         if line\[i\] == '#' {
> 
>            // # 属于真正的 json 内容
> 
>             if quoteCount%2 == 0 {
> 
>                 break
> 
>             }
> 
>         }
> 
>   
> 
>         newLine = append(newLine, line\[i\])
> 
>     }
> 
>   
> 
>     return newLine
> 
> }
