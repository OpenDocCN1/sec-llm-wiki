运维真的完了么？

聪明的你一定知道，上面只是一个玩笑。未来运维会不会消失，让我们看看运维到底是什么就明白了：

产品部署，功能，逻辑是否完整，运行质量，稳定性，时间范围内可用性等等，这是整个开发流程中重要的一环，不是未来短期内能够被替代掉的。DevOps 也好，SRE也好，只是实现方式不同。


运维并不是在消亡，而是在合并、进化。老派的，旧一代的运维，只关注操作系统层面的东西，已经远远不够了；会不会被替代，取决于你是什么样的运维。

运维的未来是要使开发者能够通过工具、自动化和流程实现自助服务，并使他们能够通过最小的运维干预来部署并运行服务。每个角色都应该朝着脱离它们的工作实现自动化的方向而努力。

对于从业8年以上的资深运维来说，他们刚开始做运维的时候更多的是接触机房、机架、主机、交换机、防火墙等硬件设备。然后对接业务运维后，一般通过 Shell、Python 等脚本来辅助工作。等到业界提出 DevOps 的时候，他们往往已经专注于团队管理、容量规划、架构调优、运维服务质量等高级范畴。


未来好的运维应该是运维基础+运维思维+开发能力三者结合；把自己当成一个真正的程序员，以程序员的评价标准来要求自己。Google工程师们对SRE（Site Reliability Engineer）的解释是：


SRE is fundamentally doing work that has historically been done by an operations team, but using engineers with software expertise, and banking on the fact that these engineers are inherently both predisposed to, and have the ability to, substitute automation for human labor.   


最重要的是have the ability to, substitute automation for human labor.   通过工具、自动化和流程，来节省人力。运维是一种需要技能面比较广的工种，大家普遍都是处于技术面广但不深的状态，在未来，你必须要有某一方面非常深入。


说到底，运维失业、消亡是一个被夸大的事实。这只是某个工种演变的过程罢了，这个过程是缓慢进行的，不是一夜就发生的，比如传统行业的QA一样。按照人工智能的论调，多数人未来都要失业呢！
