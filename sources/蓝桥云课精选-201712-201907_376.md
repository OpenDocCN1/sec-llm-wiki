## 一、实验介绍

### 1.1 实验内容

本次课程讲的是在实验楼的在线环境中，如何使用 `Github` 去管理在在线环境中使用的代码、配置、资源等实验相关文件，怎样去添加、同步和下拉在远程仓库中的实验文件，以此来维持自身的实验进度。

### 1.2 实验知识点

*   `SSH` 公私钥的基本使用
    
*   `Github` 的基本使用
    
*   `Git` 工具的基本使用
    

### 1.3 实验环境

*   git: `Git` 管理工具
    
*   ssh-keygen：`SSH` 公私钥管理工具
    
*   xfce终端
    

### 1.4 适合人群

本课程难度为简单，属于基础级别课程，适合具有 `Bash` 命令行基础的用户。

### 2.2 SSH 公私钥的使用

讲解如何使用 `ssh-keygen` 生成公私钥

#### 2.2.1 创建密钥

首先在终端敲入，如果一路一直按回车下去，会把密钥文件放置在默认路径，也就是`~/.ssh/` 路径下，并且会创建一套空密码验证的密钥文件，反之则每一次匹对公私钥都需要再手动输入一次密码，所以这里为了方便使用，建议一路回车下去就行

```

$ ssh-keygen
```

输入密钥文件保存路径，建议默认路径，按回车跳过![](../Images/772213f7d1697b92d9221d585e887ecd.png)

要求输入密码，建议回车使用空密码方便以后的每次连接![](../Images/4c8186f80085d04f2b33bb50a019a0a8.png)

到选择存放密钥文件的路径下查看，我这里使用的使默认路径，所以使 `~/.ssh/`路径下，可以看到生成了两个密钥文件，后缀为 `.pub` 的就是公钥文件，另一个没有后缀的就是私钥文件，可以看到密钥文件创建完毕![](../Images/86afa76c20b3d2dde65c469f14fe2c7b.png)

#### 2.2.2 关联公钥到 Github 账号下

首先复制公钥文件中的内容，也就是 `ssh-rsa` 开头到 `用户名@主机名` 这段字符串![](../Images/46caf4d91593de8aa001ce4ea9afc8ce.png)

然后回到 `Github`, 点击右上角头像的下拉按钮，选择 `Settings`![](../Images/587816c042dd5ab0ed954f0578fc9d39.png)

然后在 `Settings` 页面中选择左边菜单里的 `SSH and GPG keys`，然后点击右上角的 `New SSH key` 按钮，填写 `Title` 和 `Key`，然后点击 `Add SSH key` 按钮提交![](../Images/c0405e24a7aa161f8f6cb8e20a89c6e7.png)

通过返回的页面可以看到公钥与 `Github` 已经关联完毕![](../Images/9b81b17f88a6e7127ebe6a637c6c3556.png)

### 2.3 安装配置 Git 工具

介绍如何安装与简单的配置 `Git` 工具

#### 2.3.1 安装

首先在终端下面敲入 `git --version`， 如果正确回显版本号，则说明已经安装好，如果没有则在终端敲入下面这条命令进行安装

### 3.2 添加实验文件到索引库

#### 3.2.1 添加／修改

要把一个文件添加或者更新内容到本地索引中，可以使用 `git add` 命令，命令的用法是 `git add <文件名|路径名>`，具体步骤如下

创建一个新的 `txt` 文件，文件的内容就写“这是一个新的文件”![](../Images/7d3195b878d91b7065158c402e987d4d.png)

将这个文件移动到仓库下，并用 `git add` 命令添加到本地索引库中![](../Images/d9975c291a237e14960fd17906aacf7f.png)

#### 3.2.2 删除

要把仓库里的文件删除掉，可以使用 `git rm` 命令，用法是 `git rm [-rf] <文件名|路径>`，具体步骤如下

这里我们可以用一开始就存在的 `README.md` 文件来做实验，我们敲入 `git rm README.md`，然后可以发现文件已经删除了![](../Images/f9d432c145e4a2b8e553a8de16be1b34.png)

#### 3.2.3 撤销

要把仓库里的改动撤销回克隆下来的状态（注意，如果改动之后执行了提交就无法再撤销，只能从远程仓库重新克隆一份到本地），可以使用 `git reset` 命令，具体步骤如下

比如我们要把刚才删除的 `README.md` 文件给还原回来，就可以在仓库目录下，敲入 `git reset --hard HEAD` 来回退![](../Images/fd6ef5642b371cf31d68cccd3eb1b28a.png)

`cat` 一下，可以发现文件已经恢复了![](../Images/10ef74cf645ef11feb3bddae0bad26cf.png)

### 3.3 提交仓库的改动

在仓库的每一次改动操作之后，推送同步到远程仓库之前，都需要对这一次或这一批次的操作做提交，命令为 `git commit`，用法是 `git commit -m "你的提交备注"`，只有做好提交动作，才可以开始推送改动到远程仓库同步

因为我之前已经撤销了仓库的改动，这里就重新创建一个新的文件，内容就写“测试”两个字，然后提交改动![](../Images/42081375b9b6179a0f821b1bc2ff7e27.png)

### 3.4 推送改动到远程仓库中

当我们提交了仓库的改动后，就可以开始推送改动的内容到远程仓库了，可以使用`git push` 命令来推送，用法是 `git push [-u] origin <分支名>`，分支名默认是 master 具体步骤如下

第一次推送改动可以使用 `-u` 参数，使用之后会绑定你这一次的仓库分支名，这样的话下一次推送就不需要加上分支名了，如图，使用之后回提示已经绑定好分支，而且因为我们是 `HTTPS` 协议方式来克隆的仓库，所以每一次同步操作都需要输入用户名和密码![](../Images/e7e2f6021875f9f6275a54a5d794db00.png)

然后我们到远程仓库去看一下，可以发现这个文件已经推送上来了，并且对应的行会显示之前提交操作的备注![](../Images/bbf3ddabc12ba1388c6c9bf908459389.png)

### 3.5 在新的实验环境中同步之前的实验文件

之前的步骤我们已经同步好远程仓库了，现在我们把在线环境不保存并关闭，然后重新打开实验，理所当然的之前的实验文件都已经不存在了

然后我们依旧去自己的远程仓库地址，把仓库克隆到本地，可以看到之前实验的文件都在![](../Images/93e95f236bf34d239885c20d02b7060e.png)

### 3.6 在本地个人计算机中同步在线环境中的进度

为了方便我们离开在线环境之后在个人机器上做实验，我们可以在最开始的个人机器的本地仓库中同步远程仓库的更新下来

#### 3.6.1 查看仓库改动

首先我们可以通过 `git fetch` 命令查看有哪一些新改动，用法是在仓库目录下敲入 `git fetch origin`![](../Images/17b947299ece572bf72fc2ba829d45d6.png)

#### 3.6.2 下拉仓库同步

确认好更新的内容后，下一步就是把更新给同步到本地仓库中了，通过 `git pull`命令来实现，具体用法是 `git pull origin <分支名>`，分支名默认是 master，再查看一下目录，可以看到已经同步好了![](../Images/8804227183b5bb21967566704e3fd204.png)
