## 哈希指针

![](../Images/2537e07161b64d7d2e3b4e7738bfdd4b.png)首先我们要介绍第一个概念：**哈希指针。**一般来说，一个普通指针可以告诉你数据存储的位置， 哈希指针除了能够告诉你数据存储的位置，它**还存储了对应数据的哈希值，能告诉你对应数据是否被篡改过。**

## 区块链

![](../Images/be84ae6609debfd2e51bcf84094ca98c.png)**区块链其实就是一个将普通指针换成哈希指针的链表**，所以每个区块不仅包含了上一个区块的地址，还包括了上一个区块的哈希值 。（抄三遍，期末必考，装逼一百分 ![](../Images/66dc8cdb0a38d8c5fe16803df159a33a.png)）我们下面来看一看一个由 python 实现的简化版区块链:

18.  `return sha.hexdigest()`

![](../Images/19c171fb1bad0335d3f9155d14a66aca.png)在区块链中，如果我们假设一个区块被篡改了：![](../Images/fcc00de1ba5b7e12f1a5bb6cbfd9c08c.png)那么如果我们对这个区块的数据计算哈希值， 就会跟后面一个区块中存储的哈希值对不上 ，此时就会发生验证问题 。如果要掩盖这个问题，就必须再把后面一个区块的哈希值给改掉，一直改到最近的一个区块。有一个特殊的哈希指针指向最近的区块，由于这个哈希指针无法被黑客篡改，所以黑客没有办法通过篡改区块的方式对区块链进行攻击。

## 默克尔树

其实所有带有指针的数据结构都可以把普通指针换为哈希指针，例如我们可以把二叉树的指针也换成哈希指针，然后就可以得到默克尔树 。默克尔树底部的树叶是我们的交易数据，而每一个父节点是两个子节点哈希值之和的哈希值。![](../Images/e0605b70cab631b699552499b9908139.png)我们可以通过一个简化版的 python 程序来领略一下默克尔树

```
1.  `from hashlib import sha256 as sha`
    
2.  
    
3.  `def chunks(l, n):`
    
4.  `"""Yield successive n-sized chunks from l."""`
    
5.  `for i in range(0, len(l), n):`
    
6.  `yield l[i:i + n]`
    
7.  
    
8.  `def m_tree(transactions):`
    
9.  `"""Takes an array of transactions and computes a Merkle root"""`
    
10.  `sub_t= []`
     
11.  `for i in chunks(transactions,2):`
     
12.  `if len(i) == 2:`
     
13.  `            hash = sha(str(i[0]+i[1])).hexdigest()`
     
14.  `else:`
     
15.  `            hash = sha(str(i[0]+i[0])).hexdigest()`
     
16.  `sub_t.append(hash)`
     
17.  `printsub_t`

```

![](../Images/227785a12d0261193028ba32b42bd5b3.png)树这种数据结构为我们快速验证一个交易是否存在提供了便利，在比特币中我们为每个交易存储了一个默克尔路径，比如我们要验证 K 这个交易，我们只用存储下图中蓝色的哈希值就能把根节点给重建出来 ，验证是否存在这笔交易。而不需要整棵树的数据，这大大节约了空间和时间，在比特币的 SPV 轻钱包认证中默克尔树起到非常重要的作用。![](../Images/f0a632633f84c3aaf84372aa095b7f8d.png)

## 区块链结构

最后我们可以来看一看在真实的比特币系统中交易是怎样被存储的。![](../Images/5d9ecfc6a2732c5865360a93be0a133f.png)通过上图我们可以看到在真实的比特币系统中，外层是一个区块链，而每个区块内部则是用一个默克尔树来存储交易。外层的区块链保证了结构的简单 ，为后面将要介绍的挖矿与共识打下了基础，而默克尔树则为快速验证交易提供了基础。读者可以尝试写一些代码，把区块链和默克尔树的知识结合起来，构建一个比特币系统区块链结构的原型。
