如果论起近两年特别火热的技术，Flutter 算是其中的佼佼者了。作为一门横空出世的跨平台技术，Google 对 Flutter 可是给予了厚望。


不论从迭代的速度还是给与的曝光度来看，这都是一门面向未来的技术栈，它融合了近些年优秀的语言设计思路，优雅而简洁，高效而实用，很适合大多数开发者和在校学生学习。



在了解 Flutter 前，我们需要提前了解跨平台框架。它按照原理来划分，可以分为以下三类：


1、H5+ 原生（代表为 Cordova、Ionic、微信小程序）

混合应用的优点是动态内容是 H5，web 技术栈，社区及资源丰富，而缺点是性能不太好，对于一些复杂的用户界面或动画，WebView 不堪重负。


2、JavaScript 开发+原生渲染 （代表为 React Native、Weex、快应用）

优点：

  • 使用 Web 技术栈，社区资源丰富、上手很快、开发成本相对较低；

  • 采用原生渲染，性能比 H5 要高很多；

  • 支持热更新，可以满足动态化的要求。


不足：

  • 页面渲染时 JavaScript 需要与原生通信，在有些场景下比如拖动可能会因为通信过于频繁而导致不流畅；

  • JavaScript 作为脚本语言，运行时需要 JIT，执行效率与 AOT 代码之间存在一些差距；

  • 由于渲染依赖原生控件，不同平台的控件需要单独维护，当系统更新时，严重依赖于社区可能会导致开发滞后，对于需要定制化的功能，需要投入一定的成本来开发。

3、自绘 UI+原生（Flutter）

自绘 UI 是指另起炉灶创造出一个新平台，所有的开发基于这个平台。开发者无需关注原生平台，专注在这个平台进行开发即可。


官方会处理这个平台与原生的所有互操作与绘制问题，在此基础上解决跨平台与卡顿的问题。


Google 推出的 Flutter 就是基于这种理念开发出来的。


  • 从 Github 和 Stackoverflow 的趋势来看，活跃用户在飞速增长，开发过程中遇到的很多问题都能在 Github 的 issue 和 Stackoverflow 中找到答案；


  • 从 Flutter 近年来的更新速度与支持上，Google 投入了大量的资源，致力于打造一个强力的跨平台方案，不是一个玩票性质的项目；


  • 从开发效率来看，热重载技术的应用在开发中极大的提高了效率，流畅的开发体验让开发者感觉极为舒适。


（Flutter 框架图）


Flutter Framework

这是一个纯 Dart 实现的 SDK，它实现了一套基础库，底下两层（Foundation 和 Animation、Painting、Gestures）在 Google 的一些介绍视频中被合并为一个 dart UI 层，其对应的是 Flutter 中的 dart:ui 包，它是 Flutter 引擎暴露的底层 UI 库，提供动画、手势及绘制能力。


Rendering

Rendering 层是一个抽象的布局层，它依赖于 dart UI 层。这层会构建一个 UI 树，系统会侦测 UI 树是否有变化。


如果发生了变化，会计算出有变化的那一部分，然后更新 UI 树，然后将 UI 树绘制到屏幕上，这个绘制过程就有点类似于 React 中的虚拟 DOM。


Rendering 层可以说是 Flutter UI 框架最核心的部分，它除了要确定每个 UI 元素的位置、大小之外还要对他们进行坐标变换、绘制。


Widgets

Widgets 层是 Flutter 提供的一套基础组件库，在基础组件库之上，Flutter 还提供了 Material 和 Cupertino 两种视觉风格的组件库。


而我们日常在 Flutter 开发中大多数场景，只是和这两层打交道。


Flutter Engine

这是一个纯 C++ 实现的 SDK，其中包括了 Skia 引擎、Dart 运行时、文字排版引擎等。在代码调用 dart:ui 库时，调用最终会进入到 Engine 层，实现真正的绘制逻辑。

  • 操作系统：Linux（64 位）；

  • 磁盘空间：600MB（不包含安装 IDE 和其他工具的空间）；
