你知道计算机中如果生成随机数吗？你知道为什么叫伪随机数吗？你能预测下一个随机数的值吗？


本实验将带你进入研究随机数的大门。


Java 中实现伪随机数

在 Java 中，JDK 的 java.util 包下提供了 Random 类，可以通过创建 Random 的对象来产生随机数，随机生成的内容包括布尔型、整数和浮点数等。


其基本代码如下：


import java.util.Random;
public class GuessRandom {    public static void main(String[] args) {           Random rd = new Random();           rd.setSeed(50000);           //以上两句等同于   Random rd = new Random(50000);            System.out.println("第一次值："+ rd.nextInt());            System.out.println("第二次值："+ rd.nextInt());            System.out.println("第三次值："+ rd.nextInt());            System.out.println("第四次值："+ rd.nextInt());            System.out.println("第五次值："+ rd.nextInt());      }}

此代码不管你执行多少次，它的执行结果必然如下所示:


第一次值：1291210300第二次值：381359965第三次值：980106025第四次值：-1975868224第五次值：1145442612

这说明这不是一个真正意义上的随机数。其结果的产生依赖于种子，一旦种子确定了那就之后所有的随机数都是固定的。


其它诸如 Math 类的随机数生成方法或其它语言的随机数生产原理都相同，这也就是为什么称之为伪随机数的原因。


也就是说，在计算机世界没有真正意义上的随机数。


下面以 Java 的 Random 为例，让我们一窥究竟。


Random 类源码追踪

下列代码源自Java 中 Random 类，首先从 Random 的无参构造方法开始：


 /**     * Creates a new random number generator. This constructor sets     * the seed of the random number generator to a value very likely     * to be distinct from any other invocation of this constructor.     */    public Random() {        this(seedUniquifier() ^ System.nanoTime());    }

从源码的默认构造中可以看出如果创建对象时没有提供种子，则会根据系统时间生成一个种子（不存在没有种子的随机数），下面是带参构造：


 /**     * Creates a new random number generator using a single {@code long} seed.     * The seed is the initial value of the internal state of the pseudorandom     * number generator which is maintained by method {@link #next}.     */    public Random(long seed) {        if (getClass() == Random.class)            this.seed = new AtomicLong(initialScramble(seed));        else {            // subclass might have overriden setSeed            this.seed = new AtomicLong();            setSeed(seed);        }    }


从源码的带参构造中可以看出如果创建对象时提供种子，会调用 initialScramble() 方法生成下一个种子。


 private static long initialScramble(long seed) {        return (seed ^ multiplier) & mask;  }

在 initialScramble 方法中出现的值，种子（seed）是变量，multiplier 和 mask 是常量，它们的运算结果会成为下一个种子。


这就是为什么说第一个种子一旦确定，下一个种子也就确定了的原因。


接下来我们来看 nextInt() 方法：


  /**     * Returns the next pseudorandom, uniformly distributed {@code int}     * value from this random number generator's sequence. The general     * contract of {@code nextInt} is that one {@code int} value is     * pseudorandomly generated and returned. All 2<sup>32</sup> possible     * {@code int} values are produced with (approximately) equal probability.     */    public int nextInt() {        return next(32);    }

在 nextInt() 中调用了 next() ,传递的值固定为 32 ，继续观察 next() :


    /**     * Generates the next pseudorandom number. Subclasses should     * override this, as this is used by all other methods.     */    protected int next(int bits) {        long oldseed, nextseed;        AtomicLong seed = this.seed;        do {            oldseed = seed.get();            nextseed = (oldseed * multiplier + addend) & mask;        } while (!seed.compareAndSet(oldseed, nextseed));        return (int)(nextseed >>> (48 - bits));    }

在 next() 方法中，获取当前的种子 oldseed ，并通过 (oldseed * multiplier + addend) & mask 生成下一个种子 nextseed，在 compareAndSet() 中，将当前种子 seed 的值修改成下一个种子 nextseed，等待下一次的运算。 


这里出现的 addend 也是一个常量。这里的下一个种子向右有符号位移动 （48-32=16）位后的结果转成 int 返回。


代码观察到这里就清晰地看明白了，只要第一步的种子是确定的，后续根据事先设定的算法和参数进行运算，其运行的所有结果都是确定的，都是可预测的。


预测第 N 次的结果

下面根据源码，我们来预测第六次，第七次……的执行结果，编写代码如下：


import java.util.Random; public class GuessRandom {   //从源码中获取的常量值    private static final long multiplier = 0x5DEECE66DL;    private static final long addend = 0xBL;    private static final long mask = (1L << 48) - 1;
     public static void main(String[] args) {            Random rd = new Random();            rd.setSeed(50000);            //以上两句等同于   Random rd = new Random(50000);            //使用相同的种子获取第6次的结果            getGuessByNum(50000,6);
            System.out.println("第一次值："+ rd.nextInt());            System.out.println("第二次值："+ rd.nextInt());            System.out.println("第三次值："+ rd.nextInt());            System.out.println("第四次值："+ rd.nextInt());            System.out.println("第五次值："+ rd.nextInt());              System.out.println("第六次值："+ rd.nextInt());        }        //获取伪随机数的值        public static int getInt(long oldseed) {            long  nextseed = (oldseed * multiplier + addend) & mask;            return (int)(nextseed >>> 16);        }        //获取当前种子值        public static long getSeed(long oldseed){            return (oldseed ^ multiplier) & mask;        }        //获取下一个种子值        public static long getNextSeed(long seed){            return (seed * multiplier + addend) & mask;        }        // 获取指定次数的随机数    public static int getGuessByNum(long seed,int num){        long old =getSeed(seed);        int result=0;        for(int i=0;i<num;i++) {            long next =getNextSeed(old);            result = getInt(old);            old=next;        }        System.out.println("预测第"+num+"次:"+result);        return result;    }
}

动手试试吧！结果如下：

预测第6次:-166393144第一次值：1291210300第二次值：381359965第三次值：980106025第四次值：-1975868224第五次值：1145442612第六次值：-166393144
如法炮制其它指定范围的方法，一样可以预测随机数的值，比如 nextInt(int bound) 方法。

随机数不随机，咋整？嗯，只要种子不告诉别人，他就预测不了。

那它是否可被逆运算呢？

假定我知道第六次的值和第五次的值，我能否推算出第四次的值？如果能，那我最终是否就获取到了你的最初种子呢？怎么样才可以生成真正的随机数呢？

如何生成真正的随机数
伪随机数的缺点是根据其算法是完全可预测的。此外，所有伪随机数的序列最终都会重复。

这个问题困扰了一代计算机专家和科学家。

最终的结论，在现有的体系中，单纯依靠计算机本身（如算法）不足以产生真正意义上的随机数，与伪随机数生成器相比，真随机数生成器产生随机数会更慢、更复杂。

因为它们必须依赖现实世界，或通过使用外部设备采集外部信息，比如你敲击键盘的速度、你的网速、你的 IP、经纬度、你的个人作息、天气信息、当前时间、宇宙射线等等，以现实世界的随机信息纳入到系统结合计算机算法实现。

因此真随机数与其说是生成的，不如说是采样的。

所以与随机相关的计算机信息，比如密钥越来越长，越来越复杂。
