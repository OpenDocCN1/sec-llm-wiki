## **循环依赖**

什么是循环依赖？简单来说，就是 N 个类中出现了循环嵌套的引用，**你中有我，我中有你**。

  

![](../Images/68a0a4f9b97ffd02d17b5bf939ce19db.png)

  

以下代码示例就清晰的描绘了这一景像。

  

*   
*   
*   
*   
*   
*   
*   
*   
*   
*   
*   

```
public  class A{     public A(){        new B();    }}
public class  B{     public B(){        new A();    }}
```

  

循环依赖的后果就是创建 A 对象或 B 对象时很快就会**内存溢出**，程序崩溃就是循环依赖导致的后果。

  

你可能会问怎么可能会有这样的代码出现。确实直接构造依赖的方式极及少见，但其实在一个项目中，极有可能会因为业务场景的设定出现间接循环依赖这样不可避免设定。

  

比如，在设计学生和课程的多对多关系的实体类时，有可能就会有需求设计出双向关联：

  

*   
*   
*   
*   
*   
*   
*   
*   
*   

```
public  class Student{      // 一个学生有多个课程     List<Course> courses=new ArrayList<Course>();}
public class  Course{     // 一个课程有多个学生     List<Student> students=new ArrayList<Student>();}
```

  

从根本上说，直接或间接的循环依赖是**代码质量低下**的表现。

  

因此在开发中经常有要求，非必要不得建立双向关联，即使处理再得当，它也是**隐患**。但事实上间接的循环依赖因其隐蔽性在代码中是比较常见的问题。

  

## **Spring 中的循环依赖处理**

既然循环依赖是不能避免的会发生，那 Spring 会如何解决循环依赖的问题呢？

  

要明白 Spring 如何解决循环依赖，还得从 Sping 的 Bean 的创建说起，Spring 中 Bean 的**生成基本步骤**如下：‍

  

1.首先根据 class 信息获取构造方法

2.根据构造方法，反射创建对象（原始对象）

3.反射填充原始对象中的属性（依赖注入）

4.如果原始对象中的某个方法被 AOP 了，那么则需要根据原始对象生成一个代理对象

5.把最终生成的代理对象放入单例池（源码中叫做 singletonObjects）中，下次 getBean 时就直接从单例池拿，即可在这里重点是第三步的依赖注入，在进行注入的时候有可能发生什么事情？

  

假设在创建 A 类对象时，A 类中存在一个 B 类的属性 b，所以，当 A 类生成了一个原始对象之后，就会去给属性 b 去赋值。

  

如果此时 Spring 容器中存在对应的 Bean，那么直接拿来赋值给属性 b ；如果不存在，则需要生成一个 B 对应的 Bean，然后再赋值给属性 b 。

  

此时，如果 B 类中存在一个A类的属性 a，那么在创建 B 的Bean的过程中就出现了循环依赖。

  

在 Spring 中，通过**缓存机制**帮开发者解决了部分循环依赖的问题。

## **Spring Boot 的循环依赖配置**

从 Spring Boot 2.6 开始， 源码(SpringApplication.java)中提供了 allowCircularReferences 属性，该值用于设定是否允许循环依赖。默认情况下该值为 false，即不允许。

  

现在就启动环境验证一下吧! 环境中已经提供了基础内容，包括 A 类和 B 类，在 A 中依赖 B， 在 B 中依赖 A。

  

*   
*   

```
cd /home/project/demomvn spring-boot:run
```

  

默认不允许循环依赖下的启动结果如图所示：

  

![](../Images/25e76d3320632c7e02a7144b317cb667.png)

  

修改 spring.main.allow-circular-references 的值为 true 后的启动结果即正常：

  

![](../Images/32f4212e5da554e0f08a4a8bf1cacec6.png)

  

你可以修改 Spring Boot 的版本进行验证。

  

## **总结**

在相当长的一段时间内，**Spring 默认允许循环依赖**，纵容了大批低质量的代码产生，现在终于向循环依赖说不。

  

虽然还允许通过配置文件的方式允许循环依赖，还可以通过@Lazy 注解懒加载的方式绕过，但这已经向开发者发出明确的信号，请不要再写循环依赖的代码了！
