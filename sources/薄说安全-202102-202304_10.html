将一个AI算法模型部署到嵌入式系统中，能够上板运行跑起来，实现如目标检测、分类等等算法，整个开发过程需要AI开发工具链的支持，本篇以地平线open explorer工具链为例，谈谈AI开发在上板前开发所使用的一系列工具链。


  1. 浮点模型准备：

浮点模型来源于公开的各类深度学习训练框架，使用最多的DL训练框架有：


DL框架链接
TensorFlowGoogle用于机器学习和高性能数值计算的开源AI框架，它是一个Python库，调用C++来构建和执行数据流。它支持多种分类和回归算法，支持深度学习和神经网络。TensorFlow的一个最大的优点是它的简化和抽象，保持了代码的精炼和开发的效率。www.tensorflow.org
Scikit-learn

Scikit-learn是一个开源的，可商业用的AI库，也是一个Python库，它支持监督和无监督机器学习，具体有分类、回归、聚类、降维、模型选择和预处理。scikit-learn建立在NumPY，matplotlib和SciPy库之上。

scikit-learn定位为“简单有效的数据挖掘和数据分析工具，可以轻松访问，并在各种环境中重复使用。

www.scikit-learn.org/stable
Caffe
Caffe是一个深度学习框架，它考虑了表达式、速度和模块化。它由伯克利人工智能研究（BAIR）和社区贡献者开发。灵活的架构鼓励应用和创新，代码可扩展促进主动开发，速度使Caffe适合研究实验和行业部署。caffe.berkeleyvision.org
Keras

Keras是一个高层次的神经网络API，可以在TensorFlow，Microsoft Cognitive Toolkit或Theano上运行。这个Python DL库有助于快速实验，并声称“能够以尽可能少的延迟从想法转化为结果,是进行良好研究的关键。”

Keras 不是端到端的机器学习框架，而是作为用户友好、易于扩展的接口运行，支持模块化和完全表现力。独立模块（如神经层、损失函数等）可以组合在一起，几乎没有限制，并且新模块很容易添加。

借助一致且简单的 API，可以最大限度地减少常见用例中的用户操作。它可以在CPU或GPU中运行。

www.keras.io
Microsoft Cognitive Toolkit

Microsoft Cognitive Toolkit 以前称为 Microsoft CNTK，是一个开源深度学习库，旨在支持强大的商业级数据集和算法。

借助 Skype、Cortana 和 Bing 等知名客户端，Microsoft Cognitive Toolkit 提供了从单个 CPU 到 GPU 再到多台计算机的高效可扩展性，而不会牺牲质量程度的速度和准确性。

Microsoft Cognitive Toolkit 支持 C++、Python、C# 和 BrainScript。

docs.microsoft.com/en-us/cognitive-toolkit/
PyTorch

PyTorch是一个开源的机器学习Python库，主要由Facebook的AI研究小组开发。

PyTorch支持CPU和GPU计算，并在研究和生产中提供可扩展的分布式训练和性能优化。 它的两个高级功能包括具有GPU加速的tensor计算（类似于NumPy）和taped based autodiff 系统构建的深度神经网络。

www.pytorch.org
Torch

与PyTorch类似，Torch是一个类似于NumPy的Tensor库，也支持GPU。与PyTorch不同，Torch被包装在LuaJIT中，具有底层的C/CUDA实现。

作为一个科学计算框架，Torch 在构建算法时优先考虑速度、灵活性和简单性。通过流行的神经网络和优化库，Torch为用户提供了易于使用的库，同时可以灵活地实现复杂的神经网络拓扑。

www.torch.ch
MXNet
开源DL框架，用于训练及部署深度神经网络，具有可扩展性、允许快速训练模型，支持灵活的编程模型和多种语言。
mxnet.apache.org

基于公开DL框架训练得到的浮点模型是模型转换工具的输入，以上框架中，Caffe导出的caffemodel是直接支持的；PyTorch、TensorFlow和MXNet是通过转到ONNX实现间接支持。

ONNX是一种针对机器学习所设计的开发式文件格式，用于存储训练好的模型。它使得不同的DL框架可以使用相同格式存储模型数据，便于主流DL框架之间的模型迁移。

2. 模型验证

模型在嵌入式平台能够高效运行，模型中所使用的算子需要符合平台的算子约束。以地平线平台为例，在《supported_op_list_and_restrictions_release》中给出了每个算子具体的参数约束。

Caffe算子约束（示例）

为了避免人工逐条核对的麻烦，地平线提供了hb_mapper_checker工具用于验证模型所使用算子的支持情况。hb_mapper_checker工具检查结果中每行都代表一个模型节点的check情况，每行含Node、ON、Subgraph和Type四列， 分别为节点名称、执行节点计算的硬件、节点所属子图和节点映射到的地平线内部实现名称。

3. 模型转换
模型量化转换是深度神经网络的性能优化技术， 前面准备的浮点模型训练框架得到的模型一般都是float32，这种模型部署在嵌入式平台上，平台的存储空间和总线带宽无法匹配，因此通过降低权重和激活的精度来减小存储和计算量， 转换为定点模型，如int8 。
地平线的模型量化转换，包括模型解析、模型结构优化、参数定点化、模型指令编译与优化，最后生成能在嵌入式平台部署的模型。
模型量化生成的quantized_model.onnx模型计算精度由float32转换为了int8，最后通过平台模型编译器，将量化模型转换为平台支持的计算指令和数据，这时生成的是bin模型，是模型转换的最终产出结果。

4. 模型精度分析

基于校准数据实现浮点模型到定点模型转换的后量化方式，将会存在一定的精度损失，需要分析转换后的模型精度损失在可接受的范围内。根据地平线精度调优用户手册的建议：

精度有较明显损失（损失大于4%）：这种问题往往是由于yaml配置不当，校验数据集不均衡等导致的，可以从pipeline、模型转换设置和一致性。

精度损失较小（1.5%~3%）：排除以上问题导致的精度较大偏差后，如果仍然出现精度有小幅度损失，往往是由于模型自身的敏感性导致，可以使用厂商提供的精度调优工具进行调优。

如果通过上述分析，并没有发现任何配置上的问题，但是精度仍不能满足要求，则可能是PTQ（即：Post-training Quantization，后量化训练）本身的限制。这时候可以改用QAT（即Quantization Aware Training，量化感知训练）的方式来对模型进行量化。

5. 模型性能分析

模型性能分析分为开发机工具评估和上板实测性能评估两个步骤。在开发机上，地平线使用hb_perf工具对模型转换的bin文件作为输入，可以直接得到上板预期功能，评估的整体指标有：

  • Model Name——模型名称。

  • Model Latency(ms)——模型整体单帧计算耗时(单位为ms)。

  • Model DDR Occupation(Mb per frame)——模型运行的整体内存占用情况(单位为Mb/frame)。

  • Loaded Bytes per Frame——模型运行每帧读取数据量。

  • Stored Bytes per Frame——模型运行每帧存储数据量

除整体指标外，还有模型子图的细化指标：

  • Model Subgraph Name——子图名称。

  • Model Subgraph Calculation Load (OPpf)——子图的单帧计算量。

  • Model Subgraph DDR Occupation(Mbpf)——子图的单帧读写数据量（单位为MB）。

  • Model Subgraph Latency(ms)——子图的单帧计算耗时（单位为ms）

在开发板上，地平线使用hrt_model_exec_perf作为评估工具，用于评测模型的推理性能，对模型实际运行的真实性能得到了解。


以上是嵌入式AI开发中模型准备、验证、量化转换、模型评估的基本过程，把整个工具链跑通是AI开发的基础，相比于传统软件开发工具，可以看出AI开发过程中的调试、目标代码生成、测试的差异性，同时，相比于传统软件集成编译环境的友好程度，AI开发工具链上手不是那么容易，需要一定的学习成本。
