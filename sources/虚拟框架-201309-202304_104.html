一次更新引发的血案

四天前我发布了太极 5.2.1 版本，万万没想到，这次更新简直就是个灾难。。


5.2.1 版本除了更新对 Android Q Beta4的支持之外，最最重要的改进是提升性能。在太极加载模块的过程中，有一个执行比较频繁的操作是相对耗时的，在 5.2.1 以前的版本，我的 MIX 2S上执行一次这个操作第一次大约需要 40ms，后续发生 JIT 之后大约需要10ms，5.2.1 版本更新之后这个操作最多需要 2ms；整体来说性能提升应该是非常明显的。这个性能的提升功劳归功于  C++。以前这部分操作使用 Java 编写，在大量频繁创建小对象的场景，Java是不适合的，即使有ART上的 JIT 加持也被 C++  甩了十几条大街。


然而不幸的是，大量的太极用户莫名其妙翻车了。为了解决这个 BUG，这个周末我奋战了两天，拉着一大堆用户帮我测试bug，最后不得已还自己刷了好几次机，终于在半个小时前的十二点半把问题解决，终于可以睡个好觉了。


本来打我打算回滚这次变更的，不用 C++反正也够用，何必在这纠结呢？但是这意味着我好不容易重构带来的性能提升成为泡影，偏偏俺比较倔，就这个bug 干到底了。


起初我以为是我的 C++ 代码有问题，找几个用户测试之后发现并非如此。后来发现貌似小米官改包很容易出问题，以为碰到了系统的坑，刷了星空和LittleTurtle的包发现还是没问题，而且奇怪的是有用户跟我一样是 MIX 2S，一样的包我就没问题他就卡米；虽然用户很耐心地帮我一起查日志，但是我自己复现不了的话，解决起来实在是效率很低。经过一天半的反复测试，我们终于得到了一个必现的路径：太极 5.2.1 + 官改9.6.27 + 核心破解 = 100% 卡米。（感谢机智的 @uiLoaiP 给出关键的一步）


问题能必现之后就比较容易解决了。在经过一下午的排查之后，发现竟然是原来的代码有 BUG，但是使用 Java 写的话触发gc会降低这个bug的出现概率。


瞎扯了一堆，新版本 5.2.2 已经发布，修复了 5.2.1 版本的问题，关注公众号直接回复 最新版即可。


最后，郑重地给大家道个歉，这次翻车是我的锅。但愿这次翻车没有对你的生活造成困扰。（尤记得上次某同学去法院出证之前刷机使得手机变砖导致没法出示照片。。）
