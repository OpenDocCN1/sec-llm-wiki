       部署Cobalt Strike的VPS上经常出现告警，提示存在aaa9恶意文件，强迫关停VPS甚至永久关闭。以下针对Cobalt Strike aaa9文件进行详细分析。

一、搜索Cobalt Strike服务器

首先不得不提起JARM这款指纹识别工具。它基于远程服务器的TLS配置（例如TLS版本或TLS扩展）生成指纹，而无需考虑证书。在识别某些工具使用的自定义Web服务器非常有用，Cobalt Strike就是其中之一。https://github.com/salesforce/jarm

这是Cobalt Strike JARM签名：

07d14d16d21d21d07c42d41d00041d24a458a375eef0c576d23a7bab9a9fb1
JARM已经添加到Shodan，BinaryEdge和SecurityTrails中，Shodan上添加了索引ssl.jarm的功能，因此很容易找到在野Cobalt Strike服务器。


Shodan使用此JARM指纹Cobalt Strike服务器发现了5623个IP，主要是在Amazon和Digital Ocean上。如果将端口限制为443，则将获得3423个IP。说明大部分的Cobalt Strike服务器都在443端口。

使用JARM工具对第一个IP进行探测，发现Cobalt Strike在443端口上运行：
$ python jarm.py 78.152.61.71Domain: 78.152.61.71Resolved IP: 78.152.61.71JARM: 07d14d16d21d21d07c42d41d00041d24a458a375eef0c576d23a7bab9a9fb1
（此JARM签名实际上是Java Web服务器的签名，并且特定于JAVA 11堆栈，因此它包括与Cobalt Strike不相关的其他工具（例如Burp Suite），并且不包括使用不同Java版本的CobaltStrike。

二、获取Cobalt Strike的payloads

Cobalt Strike使用称为checksum8的算法使用url的校验和来提供32b或64b版本的有效负载（与metasploit服务器相同）。Cobalt Strike的反编译代码已在GitHub或其他地方发布了几次，它提供了有关此校验和的信息：
public static long checksum8(String text) {    if (text.length() < 4) {        return 0L;    }    text = text.replace("/", "");    long sum = 0L;    for (int x = 0; x < text.length(); x++) {        sum += text.charAt(x);    }
    return sum % 256L;}
public static boolean isStager(String uri) {    return (checksum8(uri) == 92L);}
public static boolean isStagerX64(String uri) {    return (checksum8(uri) == 93L && uri.matches("/[A-Za-z0-9]{4}"));}
可以通过暴力破解算法来找到相匹配的值：
from itertools import productimport string
def checksum8(strr):    j = 0    if len(strr) < 4:        return 0    strr = strr.replace("/", "")    for c in strr:        j += ord(c)    return j % 256

三、解密Cobalt Strike信标

服务器返回的文件实际上不是PE文件：
$ file *aaa9:     dataaab9:     data
在执行Cobalt Strike漏洞利用期间，它将下载此信标并直接在内存中运行。因此，此文件是一小段数据，在开头包含shellcode，该shellcode解码并执行信标。
可以使用miasm绘制此shellcode：


第一个JMP在加密密钥和加密信标之前直接进行请求。调用返回到Shellcode，下一个POP EDX获得密钥的地址。其中代码loc_f获取EBX中的密钥，EAX中是有效负载的长度，并将其存储在堆栈上最终信标的地址中。循环loc_1d进入信标，然后用密钥对其进行异或。
可以在python中实现，关键是找到基址。loc_47是紧接密钥、长度和加密有效负载之前的调用地址，因此基址是0x47 + 5（调用指令的长度）。基址随有效负载的不同而变化，但是可以通过搜索最后一个调用指令找到它。
import struct
def xor(a, b):    return bytearray([a[0]^b[0], a[1]^b[1], a[2]^b[2], a[3]^b[3]])
with open("aaa9", "rb") as f:    data = f.read()
ba = 0x4ckey = data[ba:ba+4]print("Key : {}".format(key))size = struct.unpack("I", xor(key, data[ba+4:ba+8]))[0]print("Size : {}".format(size))

with open("a.out", "wb+") as f:    f.write(res)
得到一个PE文件：

3c9a06b2477694919b1c77d3288984cb793a47dd328ef39e15132cd0cfb593ab。

直接在此能看到PE文件，因为它是由上一次调用直接执行的。诀窍在于，实际上将PE文件修改为一个有效的PE文件，并且可以直接直接执行（Cobalt Strike称为无级有效负载）。在这里看到正在执行的MZ标头：


修改DOS标头，使其包含跳至二进制文件中地址0x8157的有效指令。此地址是导出_ReflectiveLoader@4函数的地址，该函数基于RefelctiveDLLInection软件，负责在调用入口点之前再现一个简单的PE加载器以加载和映射导入函数。

（请注意，这仅在Cobalt Strike中是可选的，许多Cobalt Strike有效负载不具有PE文件格式，而是直接类似于Shellcode格式的有效负载）。

四、提取配置

Cobalt Strike配置在有效负载中进行了加密，并根据Cobalt Strike版本使用不同的密钥（0x23或0x69）。解码后，配置以type-length-value格式存储：

  • 一个简短的表示数据密钥的列表（可以在Cobalt Strike源代码中找到该列表）

  • 两个短字节代表数据类型（Int，Short，String等）及其长度

  • 数据本身

要找到配置的起始地址，我们可以查找第一个密钥的编码值，即1（DNS / SSL），1（Short），2（2个字节），并ihihik使用密钥0x69或././.,使用键0x23。

通常会为许多不同的样本找到相同的配置，因为CS使用了特定的配置文件，这些配置文件实际上是CS信标的配置，可以通过配置文件轻松共享。例如，Ocean Lotus使用模仿Google Safebrowsing url的公共配置文件。该存储库列出了不同的APT或网络犯罪组使用的配置文件。
配置中一个值叫签名，它是证书文件生成的值。由于它是客户特有的，因此可用于将多个CobaltStrike实例枢轴连接在一起（就像Trickbot所做的那样。因此，许多CobaltStrike的破解版本都禁用了此签名。该签名在技术上与Cobalt Strike客户id相关联，因此可以将此ID上报给Cobalt Strike并为使用付费证书的客户标识，但是很少有APT组拥有有效的CS证书。
