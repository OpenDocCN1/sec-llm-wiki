## 三、解密Cobalt Strike信标

服务器返回的文件实际上不是PE文件：

*   
*   
*   

```
$ file *aaa9:     dataaab9:     data
```

在执行Cobalt Strike漏洞利用期间，它将下载此信标并直接在内存中运行。因此，此文件是一小段数据，在开头包含shellcode，该shellcode解码并执行信标。可以使用miasm绘制此shellcode：  

![](../Images/169915907e4277a4407d573a5c1ca409.png)  

第一个JMP在加密密钥和加密信标之前直接进行请求。调用返回到Shellcode，下一个POP EDX获得密钥的地址。其中代码loc\_f获取EBX中的密钥，EAX中是有效负载的长度，并将其存储在堆栈上最终信标的地址中。循环loc\_1d进入信标，然后用密钥对其进行异或。可以在python中实现，关键是找到基址。loc\_47是紧接密钥、长度和加密有效负载之前的调用地址，因此基址是0x47 + 5（调用指令的长度）。基址随有效负载的不同而变化，但是可以通过搜索最后一个调用指令找到它。

直接在此能看到PE文件，因为它是由上一次调用直接执行的。诀窍在于，实际上将PE文件修改为一个有效的PE文件，并且可以直接直接执行（Cobalt Strike称为无级有效负载）。在这里看到正在执行的MZ标头：

修改DOS标头，使其包含跳至二进制文件中地址0x8157的有效指令。此地址是导出\_ReflectiveLoader@4函数的地址，该函数基于RefelctiveDLLInection软件，负责在调用入口点之前再现一个简单的PE加载器以加载和映射导入函数。

（请注意，这仅在Cobalt Strike中是可选的，许多Cobalt Strike有效负载不具有PE文件格式，而是直接类似于Shellcode格式的有效负载）。  

## 四、提取配置

Cobalt Strike配置在有效负载中进行了加密，并根据Cobalt Strike版本使用不同的密钥（0x23或0x69）。解码后，配置以type-length-value格式存储：

*   一个简短的表示数据密钥的列表（可以在Cobalt Strike源代码中找到该列表）
    
*   两个短字节代表数据类型（Int，Short，String等）及其长度
    
*   数据本身
    

要找到配置的起始地址，我们可以查找第一个密钥的编码值，即1（DNS / SSL），1（Short），2（2个字节），并ihihik使用密钥0x69或././.,使用键0x23。然后，我们可以解码信标的配置：

通常会为许多不同的样本找到相同的配置，因为CS使用了特定的配置文件，这些配置文件实际上是CS信标的配置，可以通过配置文件轻松共享。例如，Ocean Lotus使用模仿Google Safebrowsing url的公共配置文件。该存储库列出了不同的APT或网络犯罪组使用的配置文件。配置中一个值叫签名，它是证书文件生成的值。由于它是客户特有的，因此可用于将多个CobaltStrike实例枢轴连接在一起（就像Trickbot所做的那样。因此，许多CobaltStrike的破解版本都禁用了此签名。该签名在技术上与Cobalt Strike客户id相关联，因此可以将此ID上报给Cobalt Strike并为使用付费证书的客户标识，但是很少有APT组拥有有效的CS证书。
