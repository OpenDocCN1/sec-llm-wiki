**0x01**

 什么是shellcode

我们⻅到的shellcode是这样的

![](../Images/33f0b60477bfcefd391eb1901f23ba89.png)

简单来说，shellcode就是⼀段可以获取权限的代码。复杂点说，shellcode是⼀段通过中断程序执⾏改写寄存器值⽽**获取权限（系统调用）**的机器码。

 **分解⼀下这段话：**

1.  shellcode 获取权限 （结果）
    
2.  中断程序执⾏改写寄存器的值（功能实现过程）
    

**不同位数的程序实现shellcode的⽅式不同 **

 linux 32位 ：init0x80 中断实现execve系统调⽤

 linux 64位 ：syscall 中断实现execve系统调⽤

  

**0x02**

shellcode实现分步来看

0x021 系统调⽤过程

⾸先我们来认识⼀下 int 0x80 (Intel CPU)程序为什么会执⾏我们所设定的系统调⽤呢？

程序在执⾏的过程中会有两种状态，⽤户态(User Mode) 和内核态(Kernel Mode)，⽽这两种状态的关系是怎么样的呢？我们拿⼀张图来说明。

![](../Images/a1dbbfc6cb5d7440e74248fde19474de.png)

名词解释：

System call Invocation in Application program : 在应⽤程序中调⽤系统调⽤ 

Wrapper routine In libc standard Library ：在libc标准库中封装例程 

System call handler ：系统调⽤处理程序 

System call Service routine ：系统调⽤服务例程

  

如上图，系统调⽤执⾏的流程如下： 

1.  应⽤程序代码调⽤系统调⽤(xyz)，该函数是⼀个包装系统调⽤的 库函数；
    
2.  库函数 ( xyz )负责准备向内核传递的参数，并触发软中断(int 0x80) 以切换到内核；
    
3.  CPU被软中断打断后，执行中断处理函数,即系统调⽤处理函数 (system\_call)；
    
4.  系统调⽤处理函数调⽤系统调⽤服务例程(sys\_xyz)，真正开始处理该系统调⽤；
    
      
    

那么系统调⽤是如何区分系统调用函数的呢？

是通过**系统调⽤号**来区分的，不同位数的操作系统的**系统调⽤号**不同。系统调⽤号⼀般通过**eax寄存器**传递，⽤户进程传递**系统调⽤号**给**系统调用处理函数**以调⽤**系统调⽤**。 

  

查看系统调⽤号

linux下32位系统调⽤号：

cat/usr/include/asm/unistd\_32.h 

linux下64位系统调⽤号：

cat/usr/include/asm/unistd\_64.h

0x022 shellcode载⼊

（init 0x80 中断实现execve过程）

execve函数说明

![](../Images/0232ffeeda9a9f9903ff18376a7c3069.png)

通过上⾯来看我们需要传递4个参数【调⽤号、fifilename、argv\[\]、envp\[\]】来实现execve系统调⽤ 

       ebx, ecx, edx分别代表第１,２,３个参数  

参数设置

系统调⽤号为11，放在eax中

fifilename 为’/bin/sh/’放在ebx中 

argv\[\] 不需要向程序传参，所以ecx设置为0

envp\[\] 没有新环境变量，所以edx设置为 0

将参数传递给系统调⽤处理函数即可
