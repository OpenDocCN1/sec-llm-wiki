背景





网络靶场其实除了传统的N个功能外还可以做一些其他事情！我们利用火天系列靶场可以进行模拟器级别的设备配置，包括交换机、路由器、各类应用设备和安全设备等，本期文章就给大家带来在靶场中配置Cisco ISE身份认证系统！


本实验中使用 Cisco ISE身份认证服务器开启 radius 服务实现对有线接入用户的802.1x认证为例。802.1X认证是网络接入控制方案，是一种基于端口的网络接入控制协议，即在局域网接入设备的端口上对所接入的用户设备进行认证，以便用户设备控制对网络资源的访问。


此场景可适用于企业内网安全接入的身份认证，实现对有线网络接入用户的访问控制。当前主流的对终端进行安全上网认证服务有TACAS 和 RADIUS，基于开启 radius 服务开启 dot1x 认证和 mab 认证是目前最常见的认证方式，通过 ISE 其配置原理都大致相同。





802.1X系统介绍




802.1X 系统中包括三个实体:客户端、设备端和认证服务器。


 

1） 客户端是请求接入局域网的用户终端设备，它由局域网中的设备端对其进行认证。客户端上必须安装支持802.1X认证的客户端软件。


2） 设备端是局域网中控制客户端接入的网络设备，位于客户端和认证服务器之间，为客户端提供接入局域网的端口（物理端口或逻辑端口），并通过与服务器的交互来对所连接的客户端进行认证。


3） 认证服务器用于对客户端进行认证、授权和审计，通常为RADIUS服务器。认证服务器根据设备端发送来的客户端认证信息来验证客户端的合法性，并将验证结果通知给设备端，由设备端决定是否允许客户端接入。




802.1X 的认证过程 



    客户端主动发起认证→设备端将客户端发送的用户名信息封装在radius报文中发送给认证服务器进行处理→radius服务器收到设备端转发的用户名信息后，将该信息与数据库中的用户名列表中对比，找到该用户名对应的密码信息，用随机生成的一个MD5 Challenge对密码进行加密处理，同时将此MD5 Challenge发送给设备端。设备端将RADIUS服务器发送的MD5 Challenge转发给客户端。之后客户端用该Challenge对密码部分进行加密处理，并以相同方法转发给RADIUS服务器，RADIUS服务器将收到的已加密的密码信息和本地经过加密运算后的密码信息进行对比，如果相同，则认为该用户为合法用户并向设备端发送认证通过报文。设备收到认证通过报文后向客户端发送认证成功帧（EAP-Success），并将端口改为授权状态，允许用户通过端口访问网络。



实验准备



实验拓扑




认证前域：用户认证未通过时可以访问的区域，如radius服务器

认证后域：用户认证通过时可以访问的区域，如业务服务器、网关、边界路由器、防火墙等等。


实验需求


1.采用802.1x的认证方式对终端设备做接入认证。

2.认证通过后。终端设备可以访问ISE服务器和业务服务器。




实验步骤



交换机(设备端)基础网络配置



创建VLAN 100，200，300


按照VLAN规划，将接口加入对应的VLAN




配置ISE，业务服务器，终端IP地址


ISE中端口gi 1默认关闭，需要no shut





配置交换机上的vlanif接口，保证网络通畅


Switch(config)#int vlan 100

Switch(config-if)#ip address 192.168.100.154 255.255.255.0 //ISE设备使用的网关IP

Switch(config-if)#no shutdown

Switch(config)#int vlan 200

Switch(config-if)#ip address 192.168.102.154255.255.255.0 //业务服务器使用的网关IP

Switch(config-if)#no shutdown

Switch(config)#int vlan 100

Switch(config-if)#ip address 192.168.1.154 255.255.255.0 //终端设备使用的网关IP

Switch(config-if)#no shutdown



cisco ISE web界面配置



ISE启用设备管理，关闭密码策略




添加网络设备




创建用户组与用户，将用户加入到相应的组中





部署AAA（基于RADIUS）


认证策略可以不用配置，因为有一个default策略




做授权策略（Radius对授权支持的不是很好，只能进行权限等级的授权，不支持对命令行的授权）首先要去创建授权策略配置文件（就是一个模板，待会我们用来进行调用）





填入shell:priv-lvl=15

模板创建好后，这个授权并没有生效，因为我们还没有调用这个模板，我们需要去创建一个授权策略然后进行调用，针对特定的用户组来进行生效






选择组名identityGroup：name






交换机开启Radius服务



交换机定义802.1x使用Radius服务器认证




指定Radius服务器地址和验证


(密钥认证服务器端口号：1812，计费服务器IP地址：计费服务器端口号：1813)




创建Radius服务器组，将Radius服务器加入到组中。


switch (config)#aaa group server radius ISE-Radius

switch(config-sg-radius)#server name ISE


向Radius服务器发送相关属性提供相关参数：（防止AAA异常，以及802.1X异常）


switch (config)#radius-server vsa send authentication

switch (config)#radius-server vsa send accounting

switch (config)#radius-server attribute 6 on-for-login-auth

switch (config)#radius-server attribute 8 include-in-access-req

switch (config)#radius-server attribute 25 access-request include


先给Console和Enable留个后门（console，enable认证不受AAA管辖）


switch (config)#aaa authentication login NOISE line none


（命名式方法列表，优先使用line线下密码进行认证，如果没配线下密码就none不进行认证）


switch (config)#aaa authentication enable default enable none


（enable密码，优先使用配置的enable密码进行认证，如果没配置enable密码，就none不进行认证）

在line下进行调用，因为命名式的方法列表需要手工进行调用


switch (config)#line con 0

switch (config-line)#login authentication NOISE


给vty接口下的服务启用认证（telnet、ssh）


switch (config)#aaa authentication login ISE group ISE-Radius local-case


可以在上用命令来测试与AAA服务器是否能正常进行认证、授权


switch #test aaa group ISE-Radius ISE Zbnsec@123 legacy//传统方式



test aaa group ISE-Radius ISE Zbnsec@123 new-code //新型方式




测试都没问题的话，我们就可以在接口下正式启用AAA了！




结果验证





未经过认证终端不允许访问业务服务器




switch(config)#line vty 0 4
switch (config-line)#login authentication ISE
switch (config-line)#authorization dot1x ISE
switch (config-line)#transport input all



已经过认证的终端可以访问业务服务器
