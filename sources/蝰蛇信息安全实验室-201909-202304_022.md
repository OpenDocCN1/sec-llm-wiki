# 2\. 原理概述

RCE漏洞，即Remote Command/Code Execute，意为“远程命令或代码执行”，它可以让攻击者直接向后台服务器远程注入操作系统命令或者代码，从而控制后台系统。

## 2.1 命令执行

当应用需要调用一些外部程序去处理内容的情况下，就会用到一些执行系统命令的函数，如PHP中的`system，exec，shell_exec`等。当用户可以控制命令执行函数中的参数时，就可注入恶意系统命令到正常命令中，从而造成命令执行攻击。

一般出现这种漏洞，是因为应用系统从设计上需要给用户提供指定的远程命令操作的接口，比如我们常见的路由器、防火墙、入侵检测等设备的web管理界面上一般会给用户提供一个ping操作的web界面，用户从web界面输入目标IP，提交后，后台会对该IP地址进行一次ping测试，并返回测试结果。而如果设计者在完成该功能时，没有做严格的安全控制，则可能会导致攻击者通过该接口提交“意想不到”的命令，从而让后台执行，进而控制整个后台服务器。

这种漏洞的危害性很大，攻击者常会利用它继承Web服务程序的权限，去读写文件或反弹shell，成为进一步内网渗透的跳板。以下为该漏洞的PHP源码示例：

```
<?php
'Content-Type: text/html; charset=GB2312'
);// 出现乱码在最顶上加入这样一行代码，改成“GB2312”即可
'x'
];echo system($code); //echo回显

?>

```

在以上示例中，使用了`system()`作为漏洞的执行函数，除此以外，PHP中常用的执行系统函数有：`exec()、popen() passthru() shell_exec()`。在远程命令漏洞执行的利用中，要注意Linux和Windows的命令区别，不能混用。

## 2.2 代码执行

应用程序在调用一些能够将字符串转换为代码的函数（如PHP中的eval）时，没有考虑用户是否控制这个字符串，就会造成代码执行漏洞。这种漏洞很难通过黑盒查找，大部分都是根据源代码判断代码执行漏洞。

几种常用语言，都有将字符串转化成代码去执行的相关函数，如：

*   PHP：eval、assert
    
*   Javascript：eval
    
*   Vbscript: Execute、Eval
    
*   Python：exec
    
*   Java：Java中没有类似php中eval 函数这种直接可以将字符串转化为代码执行的函数，但是有反射机制，并且有各种基于反射机制的表达式引擎，如：OGNL、SpEL、MVEL等，这些都能造成代码执行漏洞
    

该漏洞的利用方式一般有以下几种，

*   直接获取shell：一句话木马：`?code=@eval($_POST[1])`使用菜刀连接，密码为1；
*   获取当前文件绝对路径：`__FILE__`是php预定义常量，其含义为当前文件的路径，参数：`?code=print(__FILE__)`；
*   读文件：我们可以利用file\_get\_contents()函数读取服务器任意文件，前提是知道目标文件路径和读取权限。参数：`?code=val_dump(file_get_contents("c:\windows\system32\driver\etc\hosts"))`
*   写文件：可以利用file\_put\_contents()函数写入文件，前提是知道可写目录。参数：`?code=val_dump(file_put_contents($_POST[1],$_POST[2]))`。借助第三方工具通过POST提交参数`1=shell.php&2=<?php phpinfo()?>`，会在当前目录下创建shell.php的文件，文件中的代码为`<?php phpinfo()?>`

以下为该漏洞的PHP源码示例：

```
<?php
'x'
];eval
($code);//eval 把（括号里的）字符串当成php代码执行

//访问：http://127.0.0.12/test.php?x=phpinfo();
//对应代码解释
//$code=phpinfo();
//eval($code);
?>

```

## 3.2 代码分析（白盒）

```
<?php
eval(gzinflate(base64_decode(&40
pNzshXSFCJD3INDHUNDolOjE2wtlawt+MCAA==&)));?>

```

当看见`eval()`函数，就要注意这里是否有代码执行漏洞。由于这里有加密数据的存在，手工辨别比较麻烦，所以可以先运行一遍，根据回显结果做一个初步判断。在运行之前，要修改一下代码，因为`eval()`不会显示回显信息，此外，`base64_decode()`函数的参数应该是一个单引号围起来的字符串，所以符号也要修改，代码经整理后如下：

```
<?php
echo gzinflate(base64_decode('40pNzshXSFCJD3INDHUNDolOjE2wtlawt+MCAA=='
));//echo 起到输出作用
?>

```

![](../Images/ab4d37a937260e4c8fb199a0b6045d25.png)

image

对代码稍作整理，即可将源代码精简为如下形式：

```
<?php
eval(echo `$_REQUEST[a]`;; ?>
)
```

这段代码的大意就是，eval()后面执行了echo()，这里的值固定，所以这里没有代码执行漏洞；而后面的echo()与反引号的搭配，出现了一个命令执行漏洞。关于这段代码，需要说明一下echo与反引号：

> ❝
> 
> **「反引号：」** 主要是用在内部还要嵌套引用一条命令时使用，现在可以直接用代替，例如(ls -la  .)"\`。
> 
> **「单引号：」** 单引号的原则是不管里面的内容是什么都原样输出，不能识别通配符、变量、命令等。
> 
> **「双引号：」** 双引号就比单引号人性化一点，可以识别变量和特殊转义符，进行一步翻译再输出，同时这里再强调一下在shell脚本中使用双引号必须结合$、/和\`这三个来申明变量、引入特殊符号和加上命令，这样才可以直接被编译器识别的。echo使用时若只输出字符串，可以不加双引号。
> 
> ❞

通过一个简单的ping命令即可验证猜想：`127.0.0.1/test/RCE.php?a=ping 127.0.0.1`。

# 4\. 防御

## 4.1 防御措施

*   **「不执行外部的应用程序或命令 ：」** 尽量使用自定义函数或函数库实现外部应用程序或命令的功能。在执行system、eval等命令执行功能的函数前，要先确定参数内容。
*   **「使用escapeshellarg函数处理相关参数：」** Escapeshellarg函数会将任何引起参数或命令结束的字符进行转义，如单引号"'"会被转义为"\\’"，双引号“””会被转义为"""，分号";"会被转义为";"，这样escapeshellarg会将参数内容限制在一对单引号或双引号里面，转义参数中所包含的单引号或双引号，使其无法对当前执行进行截断，实现防范命令注入攻击的目的。
*   **「使用`safe_mode_exec_dir`执行可执行的文件路径：」** 将php.ini文件中的safe\_mode设置为On，然后将允许执行的文件放入一个目录中，并使用safe\_mode\_exec\_dir指定这个可执行的文件路径。这样，在需要执行相应的外部程序时，程序必须在safe\_mode\_exec\_dir指定的目录中才会允许执行，否则执行将失败。

## 4.2 临时修补

以上的方案主要适用于项目的构建阶段，如果在项目已经运行时出现了相关漏洞，就很难修补。现在的项目大多利用各种框架开发，修复漏洞极为困难，所以主要的修补方案还是等待框架发行方的更新或补丁，在更新或补丁到来之前，只能采取一些临时修补措施提高漏洞利用的门槛，以达到减少攻击的目的。

临时修补没有统一的方案，主要还是依照一些防御原则入手，比如过滤特殊字符、禁用某些功能、组件等等。上文提到的s2-045漏洞被曝出之后，官方推出了对应的版本更新，但是在那之前，安全人员也提出了如下两种修补方案：

*   方式1：修改struts2组件中的default.properties文件，将struts.multipart.parser的值由jakarta更改为pell；
*   方式2：通过WAF等过滤方式对Content-Type中入侵的关键字：DEFAULT\_MEMBER\_ACCESS做过滤。
