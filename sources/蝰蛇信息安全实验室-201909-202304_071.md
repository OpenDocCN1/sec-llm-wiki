XSS漏洞知识点

## 1.1 跨站脚本漏洞

**1.1.1概述**

XSS漏洞全称为“跨站脚本漏洞”，一直被评估为Web漏洞中**危害较大的漏洞**，在OWASP TOP10的排名中一 直属于**前三的江湖地位**。这是一种发生在Web前端的漏洞，所以其危害的对象也主要是前端用户。

XSS漏洞可以用来进行钓鱼攻击、钓鱼攻击、前端js挖矿、用户cookie获取。甚至可以结合浏览器自身的漏洞对用户主机进行远程控制等。

**1.1.2跨站脚本漏洞常见类型**

XSS漏洞分**三种类型**，其*危害等级*如下：存储型＞反射型>DOM型

**反射型**：交互的数据一般不会被存在在数据库里面，一次性，所见即所得，一般出现在查询类页面等。

**存储型**：交互的数据会被存在在数据库里面，永久性存储，一般出现在留言板，注册等页面。

**DOM型**：不与后台服务器产生数据交互，是一种通过DOM操作前端代码输出的时候产生的问题，一次性也属于反射型。

**1.1.3 XSS漏洞形成原因**

形成XSS漏洞的主要原因是**程序对输入和输出的控制不够严格**，导致"精心构造"的脚本输入后,在输到前端时被浏览器当作有效代码解析执行从而产生危害。

**1.1.4 跨站脚本漏洞测试流程**

测试流程共四步：

1.  找表单
2.  测试特殊字符
3.  定位分析代码
4.  提交构造代码

TIPS :

一般查询接口容易出现反射型XSS ,留言板容易出现存储型XSS ；

由于后台可能存在过滤措施，构造的script可能会被过滤掉,而无法生效,或者环境限制了执行（浏览器）；

通过变化不同的script,尝试绕过后台过滤机制。

一般来说，我们把用于攻击的代码叫做payload.

## 2.1 Stage #1

  

![](../Images/ff2b44068d48f1e7d7f15a60e2665bb1.png)

Notes (for all stages):NEVER DO ANY ATTACKS EXCEPT XSS.DO NOT USE ANY AUTOMATED SCANNER (AppScan, WebInspect, WVS, ...)Some stages may fit only IE**翻译：**注意事项(所有阶段):不要做任何攻击，除了XSS不要使用任何自动扫描器(AppScan, WebInspect, WVS，…)有些阶段可能只适合IE  
What you have to do: Inject the following JavaScript command: alert(document.domain)**翻译：**  
你需要做的是:注入以下JavaScript命令:alert(document.domain)

  

这里的`alert(document.domain)`可以等效于上文1.2.2中的`alert(1)`。alert是js中的输出函数，以弹框形式输出，可以用C语言中的print函数来理解。  

我们查看这一关的提示（hint）：very simple...（非常简单）

根据1.1.4中的步骤，我们找到一个输入点，也就是这里的唯一输入框，我们一般把这个输入框叫做“表单”。

  

第二步，我们输入一些特殊字符：" ' <>?& 这是为了检验这些字符是否被做了特殊处理。

![](../Images/8f22825c6675cf7de2137a04e577aff9.png)

第三步，我们查看两个地方的代码，按下f12键或者fn+f12键（这是查看网页源代码的方式）

*   
*   
*   

```
<input type="text" name="p1" size="60" value=""><hr> No results for <b>"" " <>?&"</b>
```

这里是我们选中的两处的代码。这个地方都使用了我们输入的字符串，代码显示，这里没有对我们的字符串进行任何过滤措施，也就是说，这两个地方都非常容易被攻击。在这里，我们遵循由易到难的原则，对第二处（第三行代码，较易）进行攻击，第一处（第一行代码，稍难）将在稍后专门讲解。

由于我们输入的代码没有过滤，所以最简单的payload就是1.1.2中的`<script>alert(1)</script>`，但是由于此题有要求，所以略作修改，最后结果为`<script>alert(document.domain)</script>`

## 2.2 Stage#2 

  

![](../Images/382b2288b595c730a8d0f532db014022.png)

查看这一关的提示（Hint）：close the current tag and add SCRIPT tag...（闭合当前标签并添加SCRIPT标签…)

![](../Images/3fc31c154e9deb356ffba9dd80f8f55f.png)![](../Images/a205edd634b28bbeb4b9a85f92b4433f.png)

这一题与上一题第一处（第一行代码）的攻击方式相同。

用四步方法进行测试：第一步，找到输入点。

![](../Images/e05ea2712d37f21ce9c30d94e79c6321.png)

图中箭头所指表单即为输入点。

第二步，输入特殊字符。在这里，我们输入特殊字符串：'<>?& 查看源代码如下：

![](../Images/2091220d659f57eae42f295c1b4f2e71.png)![](../Images/c8c57a578f58da832c744e9bbdb010a1.png)

*   
*   

```

<input type="text" name="p1" size="50" value="'<>?&amp;">
```

从`value="'<>?&";`语句中可以看出，我们输入的字符串没有被过滤，可以使用js代码进行攻击。  
  

但是有一个问题：如果我们的技术代码被放在input标签里，将不会被识别，也就是说无法执行。

![](../Images/5457a06700c393b89ecb4c5ead7a2ffe.png)

在这里，我们要扩展一下，html标签内的技术代码会被当做**实体字符**处理。有关实体字符的详细信息会在之后适当的时候介绍。

所以，为了使我们的代码能够被执行，我们需要提前闭合input标签。payload如下：`"<script>alert(document.domain)</script>"`

闭合前后对比：

`<input type="text" name="p1" size="50" value="'<>?&">`

`<input type="text" name="p1" size="50" value="`<script> alert(document.domain)</script>">

根据对比可知，input标签被提前闭合，所以js代码可以被执行。

![](../Images/6c354e46c4b4646c4a85b8d7ffa1771c.png)

当然，这题还有别的解决方案，但受限于读者的基础，我们暂不做过多介绍，会在以后的文章中一一道来。
