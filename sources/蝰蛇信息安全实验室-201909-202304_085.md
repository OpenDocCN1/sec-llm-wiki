unlink是linux合并堆的一个机制，当我们的堆释放后不在fastbin(glibc版本<2.27时，没有tcache bin)和tachebin时，当有tcache bin时0x420一下大小的堆块释放后都会进入tcache bin,直到对应size的大小被填满（也就是7个chunk)。

如果填满，然后0x90以下大小的堆会被放入fastbin，以上的会先被放入fastbin,而大于的会被放入unsortbin，当两个unsortbin相邻的时候会发生合并，这个合并机制是可以利用的。

  

  

**unsort bin chunk的结构**

struct chunk

{

\_\_int64 pre\_size; 只有前一个堆是释放的才有这个size

\_\_int64 size,；当前堆块大小，因为堆16字节对其，所以第三位被用作标志，分别是前一个堆是否释放，当前堆块是不是mmap的，是否属于主线程

chunk \* fd;   双向链表，所有unsortbin会链成一个双向链表

chunk \* bk;

}

  

  

  
  
  

当我们malloc（0x20）时，实际上堆块大小是0x30，因为要加上pre\_size和size,fd bk指针在我们使用时是没用用的，只有被释放的时候才有用，所以也在我们申请下来的内存中，所以我们分配下来的内存实际上是指向fd结构的。

  

当两个堆块合并时，会将其中一个堆块从链表取下，也就是

chunk->fd->bk = p->bk

chunk->bk->fd = chunk->fd

  

我们如果能控制fd和bk指针，就能在任意地址处写一个任意值，为了防止这个事情，glibc库会做一个chunk->fd->bk == chunk 和chunk->bk->fd == chunk的检查，但我们知道，一般程序会有一个地址用来保存chunk值，如果我们知道这个地址p，就可以将伪造的fd设为p – 0x18 ,bk设为p – 0x10,这样就能通过chunk->fd->bk == chunk 和chunk->bk->fd == chunk的检查，然后我们的p就会被设为p – 0x18的地址，此时我们如果我们可以读写p，就可以控制p，而p刚好指向的是保存的堆块，我们就可以改写堆块地址，造成任意地址读写，在程序没有开启pie保护（地址随机化时）。这个利用是非常方便的。

解释一下代码

  

uint64\_t \* chunk0\_ptr = (uint64\_t\*) malloc(malloc\_size); //chunk0

uint64\_t \*chunk1\_ptr  = (uint64\_t\*) malloc(malloc\_size); //chunk1

  

分配两个0x90的堆块,此时堆块释放后会进入unsort bin

  

chunk0\_ptr\[2\] = (uint64\_t) &chunk0\_ptr-(sizeof(uint64\_t)\*3);

chunk0\_ptr\[3\] = (uint64\_t) &chunk0\_ptr-(sizeof(uint64\_t)\*2);

  

伪造fd,bk指针

  

  
![](../Images/4f8fced75a47820ef27f20242765de9d.png)

  

  

0x603000地址处就是我们的chunk1,0x603090地址处就是chunk2

0x603020 地址处就是我们伪造的fd,bk

  

uint64\_t \*chunk1\_hdr = chunk1\_ptr - header\_size;

此时chunk1\_hdr指向我们的chunk1 pre\_ize字节

chunk1\_hdr\[0\] = malloc\_size;

伪造 chunk1的pre\_size字节,当合并时系统会通过chunk1 – pre\_size找到我们伪造的chunk

chunk1\_hdr\[1\] &= ~1;

将chunk1 size的最低位置零，chunk1 size的最低位为零时，标识前一堆块是释放的，我们让它认为我们的伪造堆块是释放的。

free(chunk1\_ptr)

释放chunk1，然后他会和我们伪造的堆块合并，通过chunk->fd->bk = p->bk

chunk->bk->fd = chunk->fd

chunk1\_ptr 变为chunk1\_ptr – 0x18,这里没有构造伪造chunk的pre\_size和size,实际利用中，还是构造一下比较好，要不然下次malloc很可能会报错，构造pre\_size为0，size为0x81就好(0x80 的大小加上最低的标志位)

**代码解析**

因为chunk1\_ptr为 chunk1\_ptr – 0x18,所以要chunk0\_ptr\[3\] = (uint64\_t) victim\_string;，也就是偏移0x18位才能重设chunk值，指针类型值为8位大小，3 \* 8就是0x18了，chunk1\_ptr就指向了victim\_string，我们可以通过chunk1 控制victin\_string,也可以改写其他地方，构成了一个任意地址读写。
