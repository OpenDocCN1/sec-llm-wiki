# 干货 | 内网渗透—NTLM中继攻击

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzAxODg1MDMwOQ==&mid=2247485156&idx=1&sn=23bde8ae59b14d3e4beafbae3d2a33e6&chksm=9bceb18eacb93898c35e6722316a582f9a45fb5e109e9962065b4b0f11c2d43880963a57f29e&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzAxODg1MDMwOQ==&mid=2247485156&idx=1&sn=23bde8ae59b14d3e4beafbae3d2a33e6&chksm=9bceb18eacb93898c35e6722316a582f9a45fb5e109e9962065b4b0f11c2d43880963a57f29e&scene=27#wechat_redirect)

5月12日WannaCry造成的全球网络风暴是利用了Windows SMB的漏洞。

SMB相关的漏洞，在内网渗透中，经常会用到，如HASH传递攻击以及NTLM中继攻击。 

  

下面我们来分析一下NTLM中继攻击是如何执行的。

关于NTLM中继攻击，大多数文章都会提到NTLMv1/v2和Net-NTLMv1/v2，那么这两者分别是什么？  

  

NTLM哈希值储存在SAM数据库中和域控制器的NTDS.dit数据库中。如下所示： 

    ![](../Images/1fbccd66d07ef99069531b7139327344.png)

跟大多数人所想的不一样，LM哈希值是冒号前面的字符串，NT哈希值是冒号后面的字符串。NTLM哈希值会伴随Windows Vista和Windows Server 2008系统启动，默认情况下，只有NT哈希值会被存储。Net-NTLM哈希值被用来进行网络识别（由challenge/response算法衍生出来，依托于用户的NT哈希值）以下是一个Net-NTLMv2哈希值的例子：

    ![](../Images/1a88d988e340220932dbc1c8bd02f1c8.png)

  

  

**< 从渗透测试的角度来看 >**

*   可以利用NTLM哈希值进行“哈希传递”攻击
    
*   无法利用Net-NTLM哈希值来进行“哈希传递”攻击
    

从任何Windows系统的SAM数据库、域控制器的NTDS.dit数据库中可以得到NTLM哈希值，也可以利用Mimikatz工具来获取NTLM哈希值。一些完善的工具可以用来获取NT哈希值（比如Mimikatz），当然也可以利用NT哈希值来进行哈希传递攻击。

  

  

**< 利用Responder或Inveigh工具可以获取Net-NTLMv1/v2哈希值，那么利用当前Windows环境中的Net-NTLM哈希值能做些什么呢 ? >**

自从MS08-068漏洞修复之后无法再将Net-NTLM哈希值传回到获得这个哈希值的同一台机器上，除非进行跨协议转发，但是该哈希值仍然可以通过中继转发给另外一台机器。利用Responder结合其他中继工具可以进行自动化的拦截并且对哈希值进行中继转发。**唯一的一个不足之处就是**，在这之前需要在进行转发操作的机器上禁用SMB签名。但是除了个别的例外，所有的Windows操作系统都默认关闭了SMB签名。

**整个过程可以概括为如下三点：**

  

**1.** 通过多播/广播协议，利用Responder工具来对验证信息（Net-NTLM哈希值）进行截取。

  

**2.** 关闭Responder的SMB和HTTP服务，并且运行ntlmrelayx.py脚本，将验证哈希值发送到ntlmrelayx.py脚本的SMB和HTTP服务。

  

**3.** ntlmrelayx.py工具将获取这些哈希值，并将它们发送到目标列表中。如果中继操作执行成功它将触发通知命令。

SMB中继攻击依然是很有威胁性的。禁用SMB签名结合多播/广播协议可以让攻击者对验证信息进行无缝拦截，并将它们转发到其他机器。结合上述方法再借助DeathStar这样的工具，攻击者将很轻易获取windows的域管理权限。
