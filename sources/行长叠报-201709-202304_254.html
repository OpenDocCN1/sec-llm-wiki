前言


最近有位安全研究人员挖掘出了Python中一个非常隐蔽且特别的功能——代码也可作为软件包本身安装过程的一部分来执行。


科普：Python语言允许用户安装其包含在程序中的功能包来扩展其功能，并在执行程序时，按规则运行程序包中的代码。



演示过程


研究人员就此演示了一种攻击方法，方法采用了Python模块中的“setup.py”文件，使其能在安装软件包时执行代码运行。通过这种方法攻击者可以将恶意代码放进可以root的程序包里——当然也不是所有程序包都需要root权限。


为了验证观点，该研究人员创建了一个命名为owned的POC安装文件来详细说明情况：


以下代码显示了“pip install”运行时如何调用自定义“PostInstallCommand”类。

  from setuptools import setup

  from setuptools.command.install import install

 

  class PostInstallCommand(install):

        def run(self):

           # Insert code here

           install.run(self)

 

  setup(

         ...

         cmdclass={

                  'install': PostInstallCommand,

         },

         ...

  )



安装文件默许恶意软件暗中部署


Python模块通常使用名为“pip”的安装包管理器进行安装，由pip启动“setup.py”文件，一般情况下大家都不会注意到这个文件，因为它的作用仅限于帮用户给计算机添加模块。所以相对于其他部分来说，我们分析配置文件的可能性更小，黑客往往也会选择在这些地方做手脚。


给应用程序提供功能和服务的Python包的代码可能永远不会执行，因为程序大部分情况下不会用到这个部分，但是当黑客们把恶意代码放进“setup.py”之后，它就会默许程序进行安装并忽略恶意软件。



官方Python存储库中的恶意模块


恶意库在包存储库里并不少见，2017年就有安全人员在PyPi里发现了起码10个恶意库。


注：PyPi是Python的官方第三方商店


通常恶意代码开发人员会给他们的库命名跟合法模块雷同的名字并上传以诱导用户进行下载。


从结果来看，这个攻击方式也是非常有效的，用户基本上不会在第一时间察觉到包的真伪，也不会费心去查看代码。


而从平台层面来说，上传恶意内容也是可行的，因为平台缺少必要的安全检查环节。



POC


我们来回顾一下这回出现的情况：


首先下载存储库：

$ git clone https://github.com/mschwager/0wned.git


开始安装包：

$ sudo python -m pip install 0wned/

$ cat /0wned

Created '/0wned' with user 'root' at 1536011622


在pip安装过程中owned可以成功写入根目录，这证实了owned可以作为root用户或管理员用户执行任何操作。


为避免这种情况，我们应该用--user标志设置本地权限：

$ python -m pip install --user 0wned/
$ cat ~/0wned
Created '/home/tempuser/0wned' with user 'tempuser' at 1536011624

详细说明 ：https://github.com/mschwager/0wned



结论


本次事件的研究人员建议大家对自己系统上的Python模块要保持一定程度的警惕，尤其是当涉及到敏感权限操作时。


若使用--user标志设置本地权限，并用HashCheck模式安装软件包，保证一定程度的安全性。同时在平台上选择功能包时也要更加仔细地检查，确保名字和自己想找的模块一模一样，避免出现李逵、李鬼的乌龙。
