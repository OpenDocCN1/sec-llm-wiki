前言


怎么让普罗大众心甘情愿地献出自己的电脑控制权，交由自己使用？


暴力破解太粗鲁了，不适合优雅的黑客们。于是他们想到通过其他手段搞事情——只要你日常使用Office程序，不管是Word、PPT还是Excel什么的，黑客都能在不知不觉中进入你的电脑，获取你的权限。


相比于利用Office漏洞，黑客们更愿意向目标发送带有恶意程序（宏）的Office文档，因为这个方式成本更低，而且操作更简单，此之谓社会工程学。听起来像是一个社会学名词，实际上在黑客术语里你也能频繁地听到这个词。


基于微软已推出的各种针对Office恶意程序的安全措施，本文会向各位介绍一些能够有效诱导目标运行Office中恶意程序的方法，当然相对来说，这两种方法都需要用户进行一定程度上的参与，没有办法像更早之前一样，“点击就送”。



Shell.Explorer.1


Shell.Explorer.1 OLE对象（CLSID {EAB22AC3-30C1-11CF-A7EB-0000C05BAE0B}）常用于嵌入式Windows资源管理器或嵌入式Internet Explorer。我们可以将这个OLE对象嵌入Office文档中，并作为持久对象保存在相应的文档中。


对于持久化的Shell.Explorer.1对象来说，会使用一种专有格式，并且我们可以在偏移量76（0x4C）处可以看到一个熟悉的结构，位于该偏移处的结构看起来好像是ShellLink结构[MS-SHLLINK]。


在初始化Shell.Exporer.1对象时，ShellLink结构将被解析为常规LNK文件。该对象会从ShellLink获取ID列表，并使用它来导航到提供的文件、文件夹或网站。


图1：ShellLink结构的ID列表传递给CWebBrowserOC :: BrowseObject（） 



  • 嵌入式资源管理器


在提供文件夹路径时，该对象的行为类似于Windows资源管理器。利用它不仅可以浏览文件和文件夹，还可以通过双击来执行文件。由此攻击者可能会使用这个功能来嵌入资源管理器，以便于打开包含可执行文件的远程共享。如果通过某种手段说服目标用户打开包含恶意代码的文件，黑客就可以通过远程共享运行可执行代码。


不过这种攻击手法实际上来说很难实现。首先，OLE对象需要单击才能激活，其次用户需要双击OLE对象才能实际获得可用的资源管理器视图，最后用户还需要双击资源管理器视图中的文件才可以。


图2：使用嵌入式Windows资源管理器浏览本地计算机 



  • Internet Explorer


当Shell.Explorer.1用于嵌入式Internet Explorer时，事情会变得更有趣。除了可以在文档中嵌入Web浏览器之外，它还能用来浏览本地计算机上的文件，以及浏览远程位置（共享文件夹和网站）上的文件。当然如果没有用户交互的话，这些都是不可能的。


此外，单击激活也适用于该模式，单击该对象将触发Internet Explorer的文件下载功能，这意味着将向用户显示“文件下载”对话框。如果用户单击“运行”或“打开”按钮的话，就会执行相应的文件。


图3：单击嵌入的Internet Explorer对象后显示的“文件下载”对话框 


不过，某些文件类型，如exe文件会触发另一个警告对话框。但是通过使用其他可执行文件类型，可以轻松绕过该对话框，例如Matt发现的SettingContent-ms文件（其他文件格式也可以）就可以达到这个目的。


图4：某些文件类型将触发另一个警告对话框 


由于该控件禁用了IE的保护模式，而该模式会阻止显示其他对话框，例如UAC对话框。因此，只需要两次单击就可以运行恶意代码，即第一次单击用以激活，然后点击运行/打开按钮即可。Shell.Explorer.1对象也是绕过Office 2016/365中文件扩展名黑名单的一个很好的方法，因为Shell.Explorer.1没有位于相应的黑名单中。

Microsoft Forms 2.0 HTML控件


Microsoft Froms 2.0对象库提供了很多可以在Office文档中使用的“HTML”Active X控件，这些控件标记为对初始化是安全的，并且不要求用户为嵌入它们的文档启用Active X。此外这些控件的存储格式也比Shell.Explorer.1对象要简单得多。从本质上来说，这些控件是由对象的CLSID和HTML片段（UTF-16编码）组成的。此外这些HTML片段的格式也没有严格的要求，因为对象只会搜索它支持的属性。其中由两个对象支持action属性，并且该属性可接收URL。这两个对象分别是：


  • Forms.HTML：Image.1（CLSID {5512D112-5CC6-11CF-8D67-00AA00BDCE1D}）


  • Forms.HTML：Submitbutton.1（CLSID {5512D110-5CC6-11CF-8D67-00AA00BDCE1D}） 


当单击设置了action属性的嵌入对象时，就会打开定义的URL。对于常规URL来说，会在默认浏览器中打开，但对于文件URL（包括共享文件）来说将直接打开。这时会显示一个警告框，该对话框与其他警告框略有不同，如图所示，这个警告框对于所有文件类型来说都是相同的。


图6：从HTML控件打开文件URL时的警告对话框 


“Forms.HTML:Image.1”可以接受一个src，可用于配置文档中显示的图像。由此我们可以使用图像来伪装对象，例如将其伪装成嵌入式文档来诱使受害目标来点击它。


值得注意的是，当Office文档包含Web标记时，就会显示另外一个警告框，指出它是从Internet下载的。由于这个对话框更加显眼，所以从黑客的角度来看，这项技术不太实用。


图7：从Internet下载文档时显示的警告对话框

受保护的视图模式


如上所述，文档中可能会含有指示该文件是从Internet下载而来的Web标记（MOTW）。如果存在该标记，文档将在受保护的视图中打开。在这种模式下，将禁用文档中存在的任何嵌入式对象。除非攻击者利用了可以绕过受保护视图的漏洞，否则的话，则需要额外的社会工程技巧来欺骗用户单击“启用编辑”按钮。


图9：从受保护的视图中打开从Internet下载的文档 



  • 防御措施


防御者应该密切关注含有下列对象的文档：


  • Shell.Explorer.1 / {EAB22AC3-30C1-11CF-A7EB-0000C05BAE0B}


  • Forms.HTML:Image.1 / {5512D112-5CC6-11CF-8D67-00AA00BDCE1D}


  • Forms.HTML:Submitbutton.1 / {5512D110-5CC6-11CF-8D67-00AA00BDCE1D}


对于Shell.Explorer.1对象来说，可以从该对象中提取LNK文件并检索ID列表，从而找出单击对象时所打开的内容。我们的GitHub页面上的.NET类库ShellLink可用于从LNK文件中读取ID列表。通常来说，LNK文件是从持久化的Shell.Explorer.1对象的偏移量76处开始的。


HTML Forms对象更容易解析，因为它们是带有16字节GUID的UTF-16编码的HTML片段。防御者应该知道，在Office文档中存储对象的方法有许多种。例如，ActiveX控件也可以嵌入为PersistPropertyBag对象，其中对象的属性设置在XML文件中（例如，activeX1.xml）。



尾声


对于受害者这方，微软推出了同时也在持续更新各类针对社会工程学的安全手段和补丁。上文所说的“受保护的视图模式”就是其中一个方法，另外Pakcer文件扩展名黑名单也能够阻止位于黑名单中的文件类型被用户不经意间运行。


虽然这些既有的防御手段并不能非常有效地保护你的电脑，黑客还是能够通过各种手段达成其社会工程学攻击，但至少在一定程度上减少了攻击的数量。


在此还是建议大家平时使用电脑时要保持必要的安全意识，不要随意接收来历不明的文件，包括Office程序，压缩包，exe等，如不可避免，一定要及时对重要数据做好备份工作，并部署好合适的杀毒软件、防火墙，虽未必能防，总归是聊胜于无。
