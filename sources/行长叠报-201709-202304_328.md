**前言**

  

3月份，研究人员无意中在Windows中发现了一个漏洞，该漏洞允许任何进程访问和修改页面表项。

  

本文重在技术分享，旨在探讨如何针对此类漏洞制定漏洞利用。  

  

**分页基本面**

  

为了理解此漏洞的工作原理，我们首先需要介绍一下在x86/x64体系结构中分页工作的一些基本原理。

  

众所周知，x64操作系统上的虚拟地址通常如下所示：

![](../Images/c6c2999d493dd313134803df67a98403.png)

  

其实，虚拟地址不仅仅是指向RAM中任意位置的指针，它实际上由许多字段组成，这些字段在将虚拟地址转换为物理地址时具有特定的用途。

  

我们先把上面的虚拟内存地址转换成二进制：

![](../Images/7129abd7fbb99b0587cb1a87bfb16db5.png)

  

从左到右，前16位对我们来说没有实际意义，它们只是设置为镜像虚拟地址的第48位。

  

从48位偏移量开始：

  

> *   前九位000001111（十进制15）是PML4表中的偏移量。
>     
> *   接下来的9位111111111（十进制511）是PDPT表中的偏移量。
>     
> *   接下来的9位111111111（十进制511）是PD表中的偏移量。
>     
> *   接下来的9位111010110（十进制为470）是PT表中的偏移量。
>     
> *   最后，12位000000000001（十进制中的1）是内存页面的偏移量。
>     

  

那么PML4，PDPT，PD和PT都是些什么呢？

  

**PML4，PDPT，PD和PT**

  

在x64体系结构中，将虚拟地址转换为物理地址是使用CR3寄存器指向的一组分页表完成的：

  

> *   PML4 - 页面地图4级
>     
> *   PDPT - 页面目录指针表
>     
> *   PD - 页面目录
>     
> *   PT - 页表
>     

  

每个表格负责提供数据存储位置的物理地址以及与此存储位置相关的标志。

  

例如，页表中的条目可以负责提供指向查找链中的下一个表的指针，用于在内存页上设置NX位，或者确保内核内存不能被运行在OS。

  

简单来说，上面的虚拟地址查找将如下所示：

![](../Images/cdad650e36520a7105d76e2d828725e9.png)

  

在这里，我们看到这些表都是由每个条目完成，这些条目提供指向下一个表的指针，最终条目指向存储数据的内存中的物理地址。

  

正如想象的那样，操作系统上的每个进程存储和管理页表会很麻烦，操作系统开发人员用来缓解这一过程的一个技巧，便是称为“自参考页表”的技术。

  

**自引用页表**

  

简单来说，自参照页表通过利用引用自身的PML4表中的字段来工作。例如，如果我们在PML4表中创建一个索引处的新条目0x100，并且该条目指向PML4表的物理地址，那么我们就有所谓的“自参考条目”。

  

那么为什么会有人这样做呢？这实际上给了我们一组虚拟地址，我们可以在虚拟地址空间中引用和修改任何页表。

  

例如，如果我们想要为我们的过程修改PML4表，我们可以简单地引用虚拟地址0x804020100000，该虚拟地址转换为：

  

> *   PML4索引0x100 - PML4的物理地址
>     
> *   PDPT索引0x100 - 同样是PML4的物理地址
>     
> *   PD索引0x100 - 同样是PML4的物理地址
>     
> *   PT索引0x100 - 再次...... PML4的物理地址
>     

  

它最终会返回PML4的内存。

**错误**

  

了解完基础知识，我们开始把注意力转到漏洞。

  

如果我们将2018-02安全更新应用于Windows 7 x64或Server 2008 R2 x64，会发现PML4条目0x1e8已更新。

  

在实验室实例中，PML4的输入0x1e8与此类似：

![](../Images/aac0f80d3b15c23b92861295c514b741.png)

  

在这里，我们应该注意的是这个页表项的第三位。它允许从用户模式访问内存页面，而不是访问被限制在内核。

  

更糟糕的是，PML4条目0x1e8用作Windows 7和Server 2008 R2 x64中的自参考条目，这意味着任何用户模式进程都被授予查看和修改PML4页表的权限。

  

通过修改这个顶级页表，我们实际上能够查看修改系统上的所有物理内存。

  

**利用**

  

为了利用这个缺陷并实现特权升级，我们将使用一些步骤来实现我们的利用：

  

> *   创建一组新的页表，这将允许访问任何物理内存地址。
>     
> *   创建一组可用于\_EPROCESS在内核内存中搜索结构的签名。
>     
> *   查找\_EPROCESS我们正在执行的进程以及系统进程的内存地址。
>     
> *   将我们正在执行的程序的标记替换为System的标记，将我们提升至NT AUTHORITY\\System。
>
