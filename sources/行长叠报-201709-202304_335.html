今天和大家聊聊一个黑掉网站的骚操作。


安全专家Scott最近接触到一家被恶意入侵的公司。他详细描述了取证的经过，并在最后提出了一些针对这类事件的解决方法。


当然，小编最看重中的还是，其中的骚操作。


背景


Scott 的客户最近注册了新域名，他们在 VPS 上设置了网站空间，并使用 WordPress 安装脚本安装最新版本的 WordPress。可能是觉得有了新域名，应该庆祝一下，于是他们花了一周去花天酒地。如果顺利的话，他们只要在旅行归来之后输入数据库凭证即可完成 WordPress 安装。


当他们旅行归来之后，访问网站，准备输入数据库凭证的时候，他们收到了浏览器警告。充分的诠释了什么叫“不作死就不会死”！


忽略警告并进入站点，页面上显示着 “Rooted Syntax” 标志。


分析


通过搜索 “Rooted Syntax”，Scott 进入了一个黑客组织的 Facebook 页面，上面显示了遭到他们破坏的各个网站的详细信息。


Scott 的第一个任务是，通过 SSH 进入被黑网站的服务器，查看 WordPress 的根目录。他立即注意到一些通常不会在新装的 WordPress 目录下的数据内容。


以下是一些奇怪文件和目录：


  • Doc_file

  • Mailweb.zip

  • webmail

  • wso.php


这些文件除了不是标准文件，它们的添加时间也有问题。WordPress 是在3月20日安装完成的，但是 wso.php 文件的安装时间显然是在3月20日之后。


Scott 将文档根目录移到了另一个位置，以便进一步分析，并为该网站安装了一个新的静态 HTML 来保存页面。


打开 wp-config.php 文件，寻找线索。


骚操作来了！在查看时发现，黑客组织通过输入自己的 MySQL 凭证，来完成Scott 客户的 WordPress 安装，安装成功之后，WordPress 会使用黑客组织服务器上的 MySQL 进行登录验证。


使用上图 MySQL 凭证，能够在黑客主机上运行 SQL 查询来获取信息。Scott 跑了 SHOW TABLES，它展示了2,310个表格，考虑到每个 WordPress 实例默认使用12个表格，大约有192个 WordPress 网站被入侵了。


运行SQL select option_value from jhmxeoptions where option_name='recently_edited'\G 来查看管理员最近编辑了哪些文件。

结论


从这个特定案例了解到，黑客可以通过扫描新注册域名上的网站，尝试查看 WordPress 设置是否已完成。如果没有完成，他们就会通过输入他们自己的MySQL账号信息来接管网站。


解决方案


建议：


  • 不要让 WordPress 处于半安装状态 - 即使它处于新登记和/或未公开的域名。

  • 确保管理员用户不能将文件写入服务器。

    通过后台禁用直接文件编辑，请在 wp-config.php 文件中设置以下内容：

    define('DISALLOW_FILE_EDIT', true);
