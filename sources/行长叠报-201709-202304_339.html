前言

随着科技的进步，企业网络安全显得尤为重要，硬实力的公司和相关软件也越来越受到青睐，嗯，此处可以算漏洞银行硬广一条，给小编加鸡腿。


今天漏洞的来源，就是企业密码应用程序——CyberArk企业密码保险柜，该应用程序旨在保护和控制特权帐户的访问凭证。


CyberArk密码保险柜所使用的身份验证，是由序列化的.NET对象组成的令牌。问题就出在这里，攻击者通过操纵令牌，能够在服务器上获得未经验证的远程代码执行。

漏洞细节

产品：CyberArk密码保险柜

受影响的版本：低于9.9.5的版本

修复版本：9.9.5、9.10、10.2版本

漏洞类型：远程执行代码

安全风险：高

供应商网址：https://www.cyberark.com/

供应商状态：已发布修复版本

咨询网址：https：//www.redteam-pentesting.de/advisories/rt-sa-2017-014

咨询状态：已发布CVE：CVE-2018-9843CVE 

URL：https://cve.mitre.org/cgi-bin/cvename.cgi?name=CVE-2018-9843


CyberArk密码保险柜为网站凭据提供安全存储，此外，它还提供了一个REST API编程，该API在URL中可用于类似以下内容：


https://10.0.0.6/PasswordVault/WebServices/


该API使用不同的方法提供多个端点。API提供的大多数方法需要事先验证。因此，用户的API调用必须包含身份验证令牌的一个HTTP授权。标记可以通过的API方法。


研究人员对此令牌的分析表明，它包含该类型的base64编码的、序列化的.NET对象“CyberArk.Services.Web.SessionIdentifiers”。它由四个组成字符串属性，保存有关用户会话的信息。该序列化数据的完整性并不受保护。


因此，攻击者可以将任意.NET对象发送到授权的API。通过利用某些小工具，如ysoserial.net，在上下文中执行任意代码。

解决方法

1. 在route/ PasswordVault / WebServices上禁用对API的任何访问。


2. 将CyberArk密码保险柜升级到9.9.5或更高版本。

安全风险

此漏洞的风险被评为高。攻击者可以访问PrivateArk Vault Web Access ，REST API可以在服务器上执行任意代码。


攻击者可以获得系统具有的访问Web应用程序的特权，进而利用恶意程序获得帐户和凭据。另外，攻击者也可以从中转向Web服务器直接攻击保险柜。
