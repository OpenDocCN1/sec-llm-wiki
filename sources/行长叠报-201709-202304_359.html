前言


Sofacy网络间谍小组，又被称作APT28，从2008年就开始活跃于网络，是一个使用俄语的黑客组织，其攻击目标主要为全球的军事和政府机构。


最近，他们又发起了一场针对世界各地外交部的攻击运动。而且，这个运动似乎有两个并行的尝试，每个尝试都使用完全不同的工具集来进行攻击。


攻击细节



2018年2月初，研究人员发现了两个针对涉外政府机构的攻击活动，虽然两次活动的攻击者并不在同一个区域，一个位于欧洲，另一个位于北美，但其受害者和受害组织几乎完全一致。


攻击者最初是利用钓鱼电子邮件作为攻击媒介，以2018年2月即将举行的国防事件作为主题，并把自己的发件人地址修改为<events@ihsmarkit.com>，这个地址来自Jane’s。


Jane’s by IHS Markit是一家知名的信息和分析供应商，通常与国防和政府部门合作。通过对电子邮件标题数据的分析，研究人员发现发件人地址根本不是来自Jane’s by IHS Markit。


钓鱼邮件中的文本声称，附件是与目标组织相关的事件日历，并包含相关问题的操作说明。

攻击活动中使用的钓鱼网页邮件

 

附件本身是一个包含恶意宏脚本的Microsoft Excel XLS文档。该文档将自己标记为标准的宏文档，在受害者启用宏之前，其文本处于隐藏状态。


攻击者将文本字体颜色修改为白色，使其看起来必须启用宏才能访问内容，从而诱导受害者启用宏，事实上，即使不启用宏，所有内容都可以被受害者访问。一旦受害者启用宏，将出现以下代码：

ActiveSheet.Range(“a1:c54”).Font.Color = vbBlack


代码将指定单元格范围内的字体颜色更改为黑色，并将内容呈现给用户。仔细检查会发现，文档中存在几个异常点。


下图显示了文档最初的外观以及在宏运行时的变化。

运行宏之前和之后的投递文档

 

投递文档


宏获取第2227行到2248行、170列中的单元格的内容，以此获得base64编码的有效载荷，如下图所示：

投递文档显示base64编码的有效载荷

 

宏将字符串BEGIN CERTIFICATE到base64编码的有效载荷的开头，并在数据的末尾加上END CERTIFICATE。然后，该宏使用具有.txt扩展名的随机文件名，并将此数据写入C：\ Programdata文件夹中的文本文件。


之后，宏使用命令certutil -decode来解码此文本文件的内容，并将解码的内容传输到C：\ Programdata文件夹中带有.exe扩展名的随机文件中。宏休眠两秒钟后，执行刚刚删除的可执行文件。


刚刚删除的可执行文件是一个加载器木马，它负责安装和运行攻击的有效载荷。我们对这个加载器木马程序进行了更详细的分析，详见附录。执行后，加载程序将使用自定义算法解密嵌入的有效载荷（DLL），解压并将其保存到以下文件中：

%LOCALAPPDATA%\cdnver.dll


然后，加载程序将创建批处理文件：

%LOCALAPPDATA%\cdnver.bat


它将写入以下内容:

start rundll32.exe “C:\Users\user\AppData\Local\cdnver.dll”,#1


加载器木马使用这个批处理文件来运行嵌入式DLL载荷，加载器会将此批处理文件的路径写入以下注册表项，该注册表项在每次用户登录系统时都会运行批处理文件：

HKCU\Environment\UserInitMprLogonScript


由加载器可执行文件安装的cdnver.dll有效载荷是SofacyCarberp有效载荷的变体，Sofacy经常使用该有效载荷。


总体而言，SofacyCarberp通过收集系统信息并将其发送到C2服务器进行初始侦察，然后再将工具下载到系统。SofacyCarberp这种变体使用以下域作为其C2服务器：

cdnverify[.]net


这次袭击中发送的加载程序和SofacyCarberp样本相对于过去分析的样本，有了用于解析API函数的新哈希算法，并可以查找正在运行的浏览器进程并进行注入，以及对邮件的附件中详细解释的C2通信机制的更改。


开源投递文档生成器


据研究人员猜测，Sofacy可能使用了一个名为Luckystrike的开源工具来生成交付文档和用于此次攻击的宏。


Luckystrike于2016年9月在DerbyCon 6上发布，它是一种基于Microsoft PowerShell的工具，通过用户将宏添加到Excel或Word文档，以此执行嵌入式有效内容，进而生成恶意投递文档。


为了证实上述猜测，研究人员用Luckystrike生成了一个恶意Excel文件，并将其宏与Sofacy投递文档中找到的宏进行了比较。


对比后发现，除了随机函数名称和Luckystrike工具为每个有效载荷生成的随机单元格值之外，宏之间只有一个区别：即“certutil -decode”命令中的“.txt”和“.exe”文件的路径。Sofacy文档使用“C：\ Programdata \”作为路径，而Luckystrike文档使用存储在Application.UserLibraryPath环境变量中的路径。


下图显示了两者的区别，左边是LuckyStrike宏，右边是Sofacy宏，除了文件路径和宏中随机生成的值之外，其他所有内容都完全相同：

Luckystrike生成的文档中的宏（左）和Sofacy的投递文档（右）

 

捕捉攻击间的共同点


通过研究，新兴的安全攻击通常是先前观察到的行为规则或关系的一些组合，诸如重用WHOIS构件、IP，甚至域名主题的格式也是常用的，并且他们经常将攻击分组到特定的活动中。


在这种前提下，研究人员观察到Sofacy组织注册了新域名，然后设置了默认登录页面，并在一年中重复使用它们。


特别的是，地址866-593-54352、403-965-2341或522 Clematis，3000种序列被屡次发现：

 cdnverify.net域的默认登录页面


 hotfixmsupload.com域的默认登录页面

 

Hotfixmsupload[.]com被反复识别为Sofacy C2域名。在这种情况下，域名cdnverify[.]于2018年1月30日被注册，并且仅在两天后，攻击者使用此域名作为C2发起了攻击。


结论


在深入研究之后，Sofacy不再是神秘的攻击者。研究人员已经有了他们的文档记录，并且了解了他们的许多攻击方法。


当然，如果他们继续坚持攻击行动，并继续使用与过去类似的工具，他们的攻击仍有可能取得成功，数据的应用仍然具有挑战性。


Palo Alto Networks的客户可以通过以下方式免受这次威胁的侵害：


1. WildFire用malicious verdicts检测所有SofacyCarberp有效载荷。

2. AutoFocus的客户可以使用Sofacy、SofacyMacro和SofacyCarberp来跟踪侵害工具。

3. 阻止Sofacy交付文档和SofacyCarberp载荷的陷阱。

加载器木马


由宏下载到系统的有效载荷是一个可执行文件，负责为系统安装和执行动态链接库（DLL）。


加载程序有几个编码功能。例如，在执行时，加载器尝试加载api-ms-win-core-synch-l1-2-0.dll，该DLL是Windows 10平台应用程序的一部分。


通常，开发人员不会直接链接到此文件，而是可以访问基础API的WindowsApp.lib。loader包含了对Windows API函数包装的定义，它们不能直接调用，因为它们在所有操作系统上都不被支持。


执行后，加载程序将使用自定义算法解密嵌入的有效载荷（DLL），然后使用RtlDecompressBuffer API 对其进行解压缩。此API通常用于Windows驱动程序，并且参数记录在MSDN上。它所使用的压缩算法是具有最大压缩级别的LZNT1。


有效载荷使用0x3950BE2CD37B2C7CCBF8开始的10字节XOR密钥进行解密。数据一旦解密，就被传递给解压例程。有效载荷位于文件偏移处的加载器中，即位于0x19880 - 0x1F23C，大小为0x59BD。使用以下Python脚本进行解密和解压：


加载器将下列文件放入％LOCALAPPDATA％文件路径中：


  • Cdnver.dll

  • Cdnver.bat


为了避免Windows资源管理器的检测，文件属性被设置为隐藏。启动可执行文件的用户的路径是％LOCALAPPDATA％，即C:\Users\user\AppData\Local，其中包含了用户的登录帐户。


为了执行DLL，加载器首先检查正在执行的进程的完整性级别，如果它没有必要的权限，加载器将枚举系统的进程以搜索explorer.exe。枚举过程最有可能被执行，因为它通常以管理员权限运行。


加载器将尝试使用explorer.exe的权限通过CreateProcessAsUser执行DLL 。如果执行加载器的用户具有足够的权限，则可以跳过此步骤。使用Windows rundll32.exe程序处理执行，并调用DLL。


示例：

start rundll32.exe “C:\Users\user\AppData\Local\cdnver.dll”,#1


加载器将使用以下值将注册表项UserInitMprLogonScript添加到HKCU\Environment：

C:\Users\user\AppData\Local\cdnver.bat


此条目会导致在用户登录时执行批处理文件操作。批处理文件包含以下信息：

start rundll32.exe “C:\Users\user\AppData\Local\cdnver.dll”,#1

注入浏览器


该木马将使用相同的散列算法进行API解析，用来查找在系统上运行的浏览器进程，以便将代码注入浏览器，并与其C2服务器进行通信。


为了能成功实现注入，木马调用ZwQuerySystemInformation函数，并且需要与SystemProcessInformation关联的数据。


结果是得到一个名为SYSTEM_PROCESS_INFORMATION的结构，木马将访问字段ImageName（偏移量0x3c）中的Unicode字符串。


然后，木马以ASCII格式将此Unicode字符串转换为哈希算法，查找以下内容：


  • 0xCDCB4E50 - iexplore.exe

  • 0x70297938 - firefox.exe

  • 0x723F0158 - chrome.exe


该木马尝试将代码注入这些浏览器以执行其C2通信。如果要通过远程进程中的注入代码执行C2通信，注入的代码会传输到C2服务器，并将响应保存到名为SNFIRNW的内存映射文件中。


该木马在该映射文件中使用自定义通信协议，但是在较高级别上，木马将不断地在映射的SNFIRNW文件内查找数据，并且处理数据方式与C2服务器通信时使用的处理方式相同。


指挥和控制通信


除了能够通过注入Web浏览器的代码与C2服务器进行通信外，木马还可以在自己的进程中执行相同的通信过程。C2通信使用HTTPS协议，并专门设置以下标志用来允许无效证书的操作：

SECURITY_FLAG_IGNORE_CERT_DATE_INVALID|SECURITY_FLAG_IGNORE_CERT_CN_INVALID|SECURITY_FLAG_IGNORE_UNKNOWN_CA|SECURITY_FLAG_IGNORE_REVOCATION

字符串中参数的值，特别是WrLqG1kMJXpgID1rODM=，它是base64编码的密文，解密为字符串UihklEpz4V，该字符串在木马中被硬编码。用于加密URL中数据的算法，它与以前的SofacyCarberp样本中使用的算法相同。


确定系统具有Internet访问权后，该木马将收集详细的系统信息并将其发送到C2服务器。所收集的信息包括基于存储卷序列号（id字段）的唯一标识符、正在运行的进程列表、网络接口卡信息、存储设备名称（磁盘字段）、木马的构建标识符（构建字段，具体为0x9104f000） ，最后还有系统的屏幕截图（img字段）。


该木马具有屏幕截图功能，因为木马的代码不是使用Windows API进行屏幕截图，而是模拟用户按下屏幕截图键（PrtscSysRq）在键盘上保存屏幕截图到剪贴板。


然后，木马访问剪贴板中的数据并将其转换为JPG图像以包含在此HTTP请求中。所有这些数据都经过加密、base64编码，并通过HTTP POST发送到C2服务器，用来获得与初始互联网连接检查类似的URL。

使用系统信息从SofacyCarberp到C2服务器的HTTP POST

 

SofacyCarberp木马程序解析C2服务器对数据请求的响应，木马程序将使用该数据下载辅助有效载荷到系统。木马在响应数据中查找标记 [file]、[/file]、[settings]、[/settings]之间的部分。


但是，此特定变体还包含另一个标签为[shell]和[/shell]的部分。木马解析这些部分的特定字段，并指示木马要进行的操作，包括木马将保存下载文件的位置，木马如何运行次要有效负载以及木马应与哪个C2位置通信。


以下字段由木马解析：


  • FileName: Specified filename

  • PathToSave: Path to specified file

  • Execute: Create a process with the specified file

  • Delete: Delete the specified file

  • LoadLib: Load the specified DLL into the current process

  • ReadFile: Reads a specified the file

  • Rundll: Runs the specified DLL with a specified exported function

  • IP: Set C2 location

  • shell: Run additional code in a newly created thread


shell字段中指定的shell部分中的数据是为raw汇编的base64编码数据。我们可以根据木马使用base64解码数据来推测和创建本地线程，这也表明所提供的数据可以是任何与位置无关的代码或shellcode。
