背景

AsusWRT是华硕中端和高端路由器使用的操作系统，它基于Linux系统，却具有平滑的Web UI，适合在资源受限的路由器上运行。


然而，由于一些编码错误，LAN中未经认证的攻击者有可能以root权限在路由器上执行远程代码。

 

由于漏洞的及时披露，目前问题已经得到解决。


技术细节


1

漏洞：HTTP服务器身份验证绕过

漏洞编号：CVE-2018-5999

攻击向量：远程

限制：无（容易被未经认证的攻击者利用）

受影响的版本： v3.0.0.4.380.7743，可能会影响v3.0.0.4.384.10007之前的所有版本

 

AsusWRT HTTP服务器在handle_request()上存在缺陷，允许未经身份验证的用户对某些操作执行POST请求。


在AsusWRT_source/router/httpd/httpd.c中：

{

...

      handler->auth(auth_userid, auth_passwd, auth_realm);

      auth_result = auth_check(auth_realm, authorization, url, file, cookies, fromapp);

 

      if (auth_result != 0)                                            <--- auth fails

      {

           if(strcasecmp(method, "post") == 0){

                 if (handler->input) {

                      handler->input(file, conn_fp, cl, boundary);    <--- but POST request is still processed

                 }

                 send_login_page(fromapp, auth_result, NULL, NULL, 0);

           }

           //if(!fromapp) http_logout(login_ip_tmp, cookies);

           return;

      }

...

}


这可以与其他漏洞结合起来实现远程代码执行。


2

漏洞：未经授权的配置更改（NVRAM值设置）

漏洞编号：CVE-2018-6000

攻击向量：远程

限制：无（容易被未经认证的攻击者利用）

受影响的版本：v3.0.0.4.380.7743，可能会影响v3.0.0.4.384.10007之前的所有版本

 

通过滥用漏洞CVE-2018-5999并将其发布到vpnupload.cgi，我们可以在HTTP服务器代码中调用do_vpnupload_post()。服务器代码中有一个漏洞，允许攻击者直接设置NVRAM配置。


在AsusWRT_source/router/httpd/web.c中：

do_vpnupload_post(char *url, FILE *stream, int len, char *boundary)

{

...

      if (!strncasecmp(post_buf, "Content-Disposition:", 20)) {

           if(strstr(post_buf, "name=\"file\""))

                 break;

           else if(strstr(post_buf, "name=\"")) {

                 offset = strlen(post_buf);

                 fgets(post_buf+offset, MIN(len + 1, sizeof(post_buf)-offset), stream);

                 len -= strlen(post_buf) - offset;

                 offset = strlen(post_buf);

                 fgets(post_buf+offset, MIN(len + 1, sizeof(post_buf)-offset), stream);

                 len -= strlen(post_buf) - offset;

                 p = post_buf;

                 p = strstr(name, "\"");

                 strcpy(p++, "\0");

                 value = strstr(p, "\r\n\r\n") + 4;

                 p = strstr(value, "\r");

                 nvram_set(name, value);

           }

      }

...

}


这些NVRAM值包含非常重要的配置变量，例如管理员密码，它可以让通过身份验证或未经身份验证的攻击者以这种方式进行设置。

 

一旦完成，代码执行就很容易实现。一种方法是使用新密码登录Web界面，启用SSH，重启路由器并通过SSH登录。

 

更好的选择是滥用infosvr，这是一个在端口9999上运行的UDP守护进程。守护进程有一个特殊的模式，以root权限执行数据包中接收到的一个命令。这个特殊的模式只有在ateCommand_flag被设置为1的情况下才能启用，一般只发生在工厂测试或质量检测中。

 

但是，我们可以使用上述的VPN配置上传技术，将ateCommand_flag设置为1，然后发送PKT_SYSCMD到infosvr。守护进程将从数据包中读取一个命令并以root权限执行它，实现我们的命令执行而无需更改任何密码。

 

（注意：infosvr用于在未设置ateCommand_flag的情况下，执行未经身份验证的命令，进而发现CVE-2014-9583漏洞；2015年初华硕已修复此问题）。


数据包结构（来自AsusWRT_source/router/shared/iboxcom.h）：

- Header

  typedef struct iboxPKTEx

  {

    BYTE       ServiceID;

    BYTE       PacketType;

    WORD          OpCode;

    DWORD            Info; // Or Transaction ID

    BYTE       MacAddress[6];

    BYTE       Password[32];   //NULL terminated string, string length:1~31, cannot be NULL string

  } ibox_comm_pkt_hdr_ex;

 

- Body

  typedef struct iboxPKTCmd

  {

    WORD          len;

    BYTE       cmd[420];      <--- command goes here

  } PKT_SYSCMD;          // total 422 bytes
