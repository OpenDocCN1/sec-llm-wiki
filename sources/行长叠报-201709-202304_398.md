**Purple Rain**

  

为什么叫这个名字？

**随机生成**

  
  

  

Purple Rain攻击的灵感来源于PRINCE（可传性无限链式元素）攻击和随机规则生成，网上有两篇很好的文章，我建议大家可以看一下：

  

Matt Weir关于PRINCEPROCESSOR及其功能的文章：

https://github.com/evilmog/evilmog/wiki/Hashcat-Raking---generated2.rule

  

@evilmog写的有关“raking”（随机密码候选生成）技术的书面报告：

https://github.com/evilmog/evilmog/wiki/Hashcat-Raking---generated2.rule

  

与此同时，建立你自己的环境，以使用hashcat 中的随机规则生成结果。

  

简而言之，PRINCE可以根据输入的字典集，通过随机组合产生输入词链表。加上Hashcat的随机规则生成选项\-g，可以增强PRINCE密码候选生成结果。

  

**选择字典**

  

你可以通过两种方法为Purple Rain攻击选择输入词典：目标词表或通用词表。

  

如果你已经根据你的目标创建了自定义字典，那么你可以从“目标”字典开始。如果没有，那么你可以继续使用像rockyou.txt数据集一样好的“通用”字典。  

  

我不建议你使用一个非常大的字典，比如使用PRINCE（500 MB+）。你可以直接使用最常用的1000万个密码集（只有3.8MB），也可以参考**weakpass.com**，根据实际需要选择合适的词典。

  

最后，先把shuffle命令shuf发送到你的字典上，再将其传送到PRINCEprocessor上。这种方式将确保你每次开始Purple Rain攻击时，PRINCEprocessor不会创建相同的词链。

  

你只需多次尝试以下命令并比较输出便可明白我在说什么：

**pp64.bin --pw-min=8 < dict.txt | head -20**

**shuf dict.txt | pp64.bin --pw-min=8 | head -20**

  

当选择规则的时候，我建议先从Hashcat包含的dive.rule开始。这至少将已知的密码变化与PRINCEprocessor随机生成的密码候选组合在一起，而且由于dive.rule按概率顺序排序，所以你可能很快就能获得密码（幸运女神眷顾![](../Images/932079e201072fa4b33f608d49dfa161.png)）。

  

接下来，你要设置规则数为50000-1000000的Hashcat随机规则生成选项。我会建议你每次使用300000个，这在命令行中是\-g 300000。

  

注意，你尝试生成的随机规则集越大，Hashcat启动的时间就越长，因为Hashcat每次都在动态生成这些规则。

  

**命令结构**

  

让我们来谈谈完整的Purple Rain攻击命令结构：

**shuf dict.txt | pp64.bin --pw-min = 8 | hashcat -a 0 -m #type -w 4 -O hashes.txt -g 300000**

  

shuf：在进入PRINCEPROCESSOR之前，随机化我们的字典

dict.txt：你选择的字典文件

pp64.bin： Hashcat的 PRINCEPROCESSOR 工具

\--pw-min = 8：命令PRINCE生成最小长度为8的字符密码

hashcat -a 0：直接启动Hashcat以获取stdin输入

\-m #type：指定哈希模式编号，例如-m 1000是NTLM

\-w 4：命令Hashcat使用最高的工作负载设置

hashes.txt：你的文件包含的待破解哈希

\-g 300000：命令Hashcat生成300,000个随机规则

  

我们建议限制运行时间为1到24小时，然后重新启动相同的攻击。

  

收集成功的随机规则：

**\--debug-mode = 1 --debug-file = success\_purplerain.rules**

  

**高级命令语法**

  

你是否想随机选择你的字典？那么指向你的字典：

**ls dict / | sort -R | shuf'dict /'\`tail -1\` | pp64.bin --pw-min = 8 | hashcat -a 0 -m #type -w 4 -O hashes.txt -g 300000**

  

想要在多个词典中随机化以增加多样性？

**cat dict1.txt dict2.txt | shuf | pp64.bin --pw-min = 8 | hashcat -a 0 -m #type -w 4 -O hashes.txt -g 300000**

  

**高级选项**

  

在PRINCEprocessor中，我们可以使用**\--elem-cnt-min**和**\--elem-cnt-max**选项，从输入字典中增加词链的数量。

 

在Hashcat随机生成规则中，我们可以使用**\--generate-rules-func-min**和**\--generate-rules-func-max选项**，增加或减少规则函数的数量。

  

**运行测试**

  

这里有一些简单的步骤来运行一个简易的Purple Rain攻击测试。

 

首先让我们随机化，从rockyou字典中取出前三万个密码：

**shuf rockyou.txt | head -30000 > test\_rockyou.txt**

 

然后，我们将test\_rockyou.txt文件进行md5编码（这将需要时间）：

**while read line; do echo -n $line | md5sum; done < test\_rockyou.txt | awk -F " " '{print$1}' > hashes.txt**

  

接下来我们将创建一个小字典来运行我们的新测试哈希：

**hashcat -a 3 -i？a？a --stdout >> test\_dict.txt**

 

另外，我们从网上抓取谷歌最常用的20,000个英语单词字典并添加它：

**cat google-20k.txt >> test\_dict.txt**

 

现在先用dive.rule运行Purple Rain攻击1小时：

**shuf test\_dict.txt | pp64.bin | hashcat -a 0 -m 0 -w 4 -O hashes.txt -r dive.rule**

 

你可以看到它在Hashcat中生成的候选密码。

 

现在我们将让Purple Rain攻击以20万随机生成的规则运行8小时：

**shuf test\_dict.txt | pp64.bin | hashcat -a 0 -m 0 -w 4 -O hashes.txt -g 200000**

  

通过8小时的运行时间，你可以了解到这种方法不需要过多人工参与，可以持续、自主完成攻击过程。你会看到你根本无法想到的一些密码组合。请记住一点：不确定的输出结果是你最好的朋友。
