CVE-2017-17562，一个存在于所有低于3.6.5 GoAhead Web服务器版本中的远程代码执行漏洞。


该漏洞是初始化使用不受信用的HTTP请求参数的CGI脚本环境的结果，并且会影响所有启用了动态链接可执行文件（CGI脚本）的CGI支持的用户。这种行为与glibc动态链接器结合使用时，可能会被使用特殊变量LD_PRELOAD的远程代码执行滥用。

该漏洞在cgiHandler函数中，该函数通过为新进程的envp参数分配一个指针数组，然后使用从HTTP请求参数中获取的键值对来初始化该漏洞。最后，launchCgi函数被称为fork和execve的CGI脚本。


除了REMOTE_HOST和HTTP_AUTHORIZATION外，所有其他参数都无需过滤。这允许攻击者控制新CGI进程的任意环境变量。

ELF动态链接器


读取goahead二进制文件的ELF头，我们可以看到它是一个64位动态链接的可执行文件。程序解释器在该INTERP部分中有具体说明并指向/lib64/ld-linux-x86-64.so.2（这是动态链接器）。


读取ELF标题


动态链接器是第一个在动态链接的可执行文件中运行的代码，负责链接和加载共享对象并解析符号。为了得到goahead二进制加载的所有共享对象的列表，我们可以将一个特殊的环境变量LD_TRACE_LOADED_OBJECTS设置为1。

特殊的环境变量


动态链接器是第一个执行新进程的代码，如果读取man 8 ld.so，会发现有特殊的环境变量可以修改默认行为。该dl_main函数本质上是动态链接器的主要入口点。


glibc / elf / rtld.c：dl_main


此函数做的第一件事就是调用process_envvars。


glibc / elf / rtld.c：process_envvars


我们可以看到链接器正在解析envp数组，并且如果找到特殊的变量名称，就会执行不同的代码路径。


glibc / elf / rtld.c：dl_main


在dl_main中，如果preloadlist不为空，则调用handle_ld_preload函数。


glibc / elf / rtld.c：handle_ld_preload


handle_ld_preload函数将解析preloadlist，并将其值视为要加载的共享对象列表。


综上所述，利用goahead，我们可以注入任意的环境变量，我们可以滥用glibc处理特殊情况的事实，比如LD_PRELOAD不同地加载任意的共享对象，而这些对象甚至不在二进制文件中。

launchCgi方法实际上是将stdin文件描述符指向包含POST请求的请求主体的临时文件。这意味着将会有一个包含用户提供数据的磁盘上的文件，并且可以通过类似LD_PRELOAD =/tmp/ cgi-XXXXXX的语句来引用。


goahead / src / cgi.c：launchCgi


Linux procfs文件系统有一个很好的符号链接，我们可以用来引用stdin描述符，它指向我们的临时文件。这可以通过将LD_PRELOAD指向/ proc/ self/fd/0，也可以使用/ dev/ stdin。


linux / fs / proc / self.c


如果我们把所有这些信息放在一起，我们可以通过发送包含一个malcious共享对象的POST请求来可靠地利用漏洞，该对象包含一个在加载时要调用的构造函数。我们还指定包含一个HTTP参数?LD_PRELOAD=/proc/self/fd/ 0，该文件将指向包含攻击者有效负载的磁盘上的临时文件。

总结


这个漏洞是一个有趣的案例，研究如何远程利用LD_PRELOAD，并对GoAhead web服务器的所有版本进行测试。该构造本身可能存在于其他服务中。可能只使用开发字符串并在没有实际审计任何代码的情况下进行盲操作。


尽管CGI处理代码在web服务器的所有版本中保持相对稳定(这使它成为理想的目标)，但是在其他模块中，多年来出现了大量的代码转换。有可能存在其他有趣的漏洞。
