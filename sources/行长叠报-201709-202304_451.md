# 记一次艰难的渗透测试

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzAxODg1MDMwOQ==&mid=2247486914&idx=1&sn=b6c5e870d52884cd7aadec6d5d96f5ff&chksm=9bcebaa8acb933be9522520ac8360acd8d4a8002ba5347743457837f9b7d70606294e5efd152&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzAxODg1MDMwOQ==&mid=2247486914&idx=1&sn=b6c5e870d52884cd7aadec6d5d96f5ff&chksm=9bcebaa8acb933be9522520ac8360acd8d4a8002ba5347743457837f9b7d70606294e5efd152&scene=27#wechat_redirect)

**The Beginning**  

这一切的一切

  

都要从一个过时的Oracle电子商务套件实例说起

  

传说此套件有许多公开漏洞

  

其中就包括绕过身份验证和Blind XXE漏洞

在访客用户可以绕过的EBS版本中浏览OA.jsp文件，可以dump出调试信息。

  

http://targethost/OA\_HTML/OA.jsp

  

这会导致以下错误：

  

You have encountered an unexpected error

  

此时我获得一个有效会话，允许我作为访客用户查看登录表单中的调试信息。

  

可以得到如下调试信息：

  

1、主机操作系统

2、安装应用程序(EBS)的路径

3、后端数据库

  

在操作系统、应用程序路径和数据库架构的支持下，我可以绕过身份验证并得到一些信息。

遍历EBS实例，我发现了另一个包含Blind XXE漏洞的端点。

  

Blind XXE是一个有趣的漏洞，因为我最初的想法是，它只是一些端口扫描和文件识别。经过一些研究，可以通过blind XXE来从/etc/hosts文件中获取另一个端点。由于这个端点在一个内部IP上，所以不能通过互联网访问。然而通过XXE有可能读取用户的.bash\_history文件，在这个文件中我发现内部IP指向一个域名。对这个域名进行DNS查找时，我发现了一个互联网IP！

  

现在回到程序来确认范围，果然，范围涵盖了域\*.example.com。

  

它出乎我原来的预料，尤其是在发现它的内部主机名是ExperimentDB-92Hn192的情况下，外部领域完全没有提及DB。外部主机名是my.example.com。

  

我发现，这个域名的主机有一个未知的仪表盘正在运行，默认显示访客登录。有一个参数guest，它的值为1，我试图把这个参数改为0，但并没有什么用。

  

在此之后，我试图模糊测试其他参数，然后发现tabl = default。经过几次的测试后，我发现这个参数是从某种形式的数据库加载信息。

经过测试，发现了一些通用的SQL字符串，并确定数据库是Microsoft SQL（mssql）。

![](../Images/1fcfd7662d5786c2c226c8ecdf181f6d.png)

有了这些信息，我开始尝试使用手动SQLi来识别版本：

  

'+AND+SELECT+@@version+--

  

返回使用的版本为：

  

Microsoft SQL Server 2005—9.00

  

测试后我发现几乎所有SQL查询都被使用。我确定这个版本支持xp\_cmdshell，但是在运行基本命令时没有返回任何命令。

  

这让我觉得，这里无法使用SQL注入进行有效攻击。

![](../Images/bc80e50c339a9c1d18cc0780db870278.png)

  

通过SQL注入，我可以重新启用xp\_cmdshell：

  

'+AND+EXEC+sp\_configure+'show advanced options',+1

  

'+AND+RECONFIGURE

  

'+AND+EXEC+sp\_configure+'xp\_cmdshell'，+1

  

'+AND+RECONFIGURE

  

执行这四个查询使我能够运行xp\_cmdshell查询！为了证明我已经执行了命令，我发起了查询：

  

'+AND+EXEC+master.dbo.xp\_cmdshell+'net users'

  

这表明系统上有两个用户，Administrator & Guest，现在我可以确认：

  

1、DB实例没有一个单独用户，这意味着它可能运行为admin

2、这里可以执行命令

  

然而，它只证明了对系统的读取权限.所以我在C盘上创建了一个临时文件，以显示写入文件是可能的。

  

'+AND+EXEC+master.dbo.xp\_cmdshell+'echo 1 > C:\\Zephr.txt'

  

这似乎是成功的，因为没有发现错误信息。在进行了列目录的操作后，我确认已经取得了读取和写入的权限，文件也已经创建成功。

  

我可以通过如下代码删除文件：

  

+AND+EXEC+master.dbo.xp\_cmdshell+'rm C:\\Zephr.txt'

  

接着进行列目录操作，我发现该文件已经删除。利用这四个漏洞我们最终得到了命令执行。

1、Auth bypass -> Blind XXE

2、Blind XXE -> Information Disclosure -> SQL Injection

3、SQL Injection -> Command Execution -> RWX Permissions as Administrator

  

**认证绕过+ XXE +信息泄露+ SQLi = RCE**
