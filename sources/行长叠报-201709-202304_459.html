PHP对象实例化

本节主要介绍将PHP对象实例化漏洞转变为Blind XXE攻击漏洞。


RIPS自动识别的对象实例化漏洞可以跨多个文件和类。注入点位于该功能中，用于在商店后台预览产品流。

最后，关键点是用$className指定类型的ReflectionClass来实例化对象。使用用户控制输入的newInstanceArgs()方法，可以指定构造函数的参数。ReflectionClass是PHP 5中引入的反射API的一部分。它允许检索在执行期间给定点可访问的所有类的信息（可用方法，等待参数等）。newInstanceArgs()是用给定的参数创建一个类的实例。据此，我们可以实例化任意对象。


Blind XXE

我们来看看如何利用这样的漏洞。


攻击者将参数发送到dPreviewAction()方法，从而实例化任意对象。当对象反序列化时，调用的不是__wakeup()魔术方法，而是__construct()魔术方法。检查注入的虚拟对象的生命周期显示，其方法中的以下方法被调用：

1. __construct()
2. __call() if method getName() not available. Else getName()
3. __destruct()


所以剩下要做的是找到一个在运行时可用的类，其中上述方法之一以有利的方式实现。遗憾的是，我们在Shopware代码库中找不到任何这样的类。


但是，在运行时也可以使用PHP内置类。在这种情况下，可以实例化对象的一个有趣的类是SimpleXMLElement。这个类是大多数PHP安装中可用的PHP SimpleXML扩展的一部分。当实例化SimpleXMLElement对象时，传递给其构造函数的数据被解析为XML。这可以用于启动XML外部实体(XXE)攻击。SimpleXMLElement的构造函数的签名如下所示：

SimpleXMLElement::__construct ( string $data [, int $options = 0 [, bool $data_is_url = false [, string $ns = "" [, bool $is_prefix = false ]]]] )


下面的XML和DTD示例显示了如何滥用它来读取目标系统上Web服务器权限允许访问的任何文件。

首先，对象实例化漏洞被用来实例化一个带有适当参数的SimpleXMLElement对象。参数$ options必须设置为LIBXML_NOENT，以激活用于工作的XXE所需的实体替换。参数$ data_is_url设置为true，$ data指向攻击者xxe.xml文件。当XML文件被注入的SimpleXMLElement对象解析时，它从文件系统读取/ etc/ passwd文件，并将其内容base64发送回攻击者web服务器。

最后，攻击者可以通过查看他的web服务器的日志文件和base64解码获得的日志来读取所需文件的内容。
