**ATM机原理**  

首先，我们简单的介绍一下ATM机的工作原理。

 

我们可以把ATM机看做一个由计算机控制的保险箱。这个保险箱有两个装置：一个是用于取出的分配器，一个是用于存放的纸币接收器。控制ATM的计算机通过一个独立网络与银行卡进程服务相连接。

 

在一台ATM机的制造、安装和操作过程中，会有很多人参与。这些人都可以使用手中的权限找出系统漏洞，盗取ATM里的现金。例如：

 

**内部人员**

*   软件开发人员：在程序中创建后门
    
*   ATM承包商：将加密密钥交给黑客
    
*   服务工程师：伪造硬件和软件组件，恶意使用密钥
    
*   现金押运人员：直接偷取装着现金的保险箱
    

 

**外部人员**

*   银行客户：在纸币上涂胶，先存钱再取钱，将钱顺出来
    
*   无专业知识的攻击者：窃取ATM，袭击押运员，利用社会工程学
    
*   装备先进的攻击者：物理破坏ATM，控制现金槽，取得ATM内部权限
    
*   影响ATM本地网络的攻击者：黑盒子攻击，银行卡克隆，访问ATM中的PC
    
*   远程影响ATM网络的攻击者：通过本地网络进行未经授权的访问，安装恶意软件，利用软件和操作系统的漏洞
    

 

本文主要介绍如何利用ATM内置PC上的软件漏洞，在最高级别的执行环境中执行代码。

  

 

**ATM中ISS的详细信息**

 

安全运行ATM机的前提是系统的完整性。为了防止任何无关代码在ATM上运行，信息安全系统（ISS）会阻止任何修改系统或添加外部组件的行为，这些行为包括：

  

*   软件：可执行文件，软件安装包，脚本
    
*   硬件：USB存储器， CD/DVD
    

 

但依然有很多方法可以将恶意软件上传到ATM内置PC中，这其中包括本地访问和远程访问。

 

**本地访问：**

*   利用摄像头或在电缆打孔，连接USB的总线。
    
*   复制服务密钥，插入闪存驱动器，或者利用无线键盘插头可以在不被察觉的情况下打开ATM机身。
    

  

**远程访问：**

*   从银行通过远程桌面上传恶意软件
    
*   利用监控和管理设备服务中的漏洞
    

![](../Images/ff7a8518307ed439e9166d5e7405bdc9.png)

  

此外，访问控制同样重要。对设备、进程、文件系统、注册表对象和其他元素的访问由系统控制。

  

正常情况下，黑客在攻击的初始阶段拥有的权限很少。即便可以绕过上述的控制，仍需提权才能访问关键资源，例如分配器。

**KESS功能概述**

*   应用程序启动控制——控制系统中运行的代码
    

 

KESS采用“默认拒绝”策略：禁止所有未明确允许的内容。

该系统分为两个模式：

  

*   内核模式：KESS驱动程序保持运行
    
*   用户模式：KESS服务进程在用户和系统进程之间运行

当系统请求过滤端口时会调用creat\_module\_list函数。该函数生成一个模块列表，这些模块从查询参数加载到进程的地址空间中。

  

然后将缓冲区发送回KESS服务进程来扫描这些模块。在这里我们需要密切注意ExAllocatePoolWithTag分配器的调用，该分配器对之前的sz参数进行特定计算。

  

  

**函数的逻辑如下：**

 

1、通过访问InMemoryOrderModuleList链表，并计算module\_list模块所需的内存量（sz变量）。包含模块路径的字符串，字符串大小，模块的地址和大小，一些常量将被复制到该链表。

 

2、将0x1008的«reserve»添加到sz的结果中。

 

3、调用ExAllocatePoolWithTag，并请求分配sz + 0x1000 的大小。

  

4、对module\_list链表进行循环，每个模块对应的数据添加到分配缓存中。然后将缓冲区中的偏移量与sz值进行比较，以防止溢出。

 

5、在缓冲区中添加8个零；它的指针和大小被返回。

 

**这种缓冲区大小的计算有可能导致整数溢出。可以采取如下措施：**

 

1、生成InMemoryOrderModuleList\_fake链表，在第一个循环中，计算的字符串长度和剩余系数等于0xffffdff8；

  

2、将其放在PEB中；

  

3、调用函数进行列表审核；

  

4、在操作算法的第2步(2)中，函数将被赋值为sz + = 0x1008(sz = 0xFFFFDFF + 0x1008 = = 0xFFFFF000)；

  

5、为了调用ExAllocatepoolwithtag，Sz\_arg = sz + 0x1000(Sz\_arg = 0xFFFFF000 + 0x1000 = = 0)的大小参数将被分配一个zero-size缓冲区；

  

6、将来自In Memory Order Module List\_fake的数据复制到此缓冲区中，直到偏移值为> sz（sz == 0xFFFFF000），即远远大于分配的零字节数。

 

我们可以为任何sz的值自由构建一个InMemoryOrderModuleList\_fake。在0xFFFFDFF8 <= sz <0xFFFFEFF8 的范围内，我们可以分配大小为0到0x1000字节的缓冲区并溢出。

**分页池**

 

为了将我们控制的对象放置在溢出的缓冲区中，我们将尝试创建所需的内核内存状态。我们需要了解，易受攻击的的缓冲区被分配在一个分页池中。由于以下原因，这有点不方便：

 

*   当在非分页池中分配重写回调时，我们可以使用这些对象快速获得控制。
    
*   分页池数量很少，它们由分配器进行切换以平衡负载。
    

 

  

**填充**

 

通过连接调试器并检查PoolDescriptor，ListHeads列表的分页池，一个注意到在KESS内存扫描时，在Windows启动后，有一些分配大小尚未涉及到密集的系统初始化过程。

  

例如，通过分配0x400字节块，我们可以假设在我们的工作中，相同的块不会被分配和释放，从而在喷雾器中产生错误，并危及开发的可靠性。你可以通过创建命名对象(如事件)来在分页池中分配这些块。对象名称字符串由WCHAR字符组成，然后被放到与KESS驱动程序使用的一个池中，以创建模块列表。

  

我们可以设置易受攻击的缓冲区的大小和具有事件名称的字符串的大小，以使它们进入同一个PoolDescriptor。同时还需要在几个分页池中分配一个块数组。

 

实验表明，在开发周期中逐个创建对象会导致相同的池被重用，以存储对象的名称字符串，而在一个易受攻击的驱动函数中调用分配器，一个块可能在系统中的多个池中的任何一个池中返回未预测的结果。

  

在我们的开发中，每创建1000个对象后，我们添加了一个小的延迟，而这一次通常足以切换分配器中的池索引。所有的池子都被填满。

 

我们将销毁之前创建的一些对象。选定区域中未使用的块会返回到PoolDescriptor.ListHeads列表，然后等待KESS驱动程序分配。

 

  

**使用溢出**

 

这部分的开发和架构体系的关系较大，我们将使用Windows 7x32作为目标系统。

 

我们将在下一个块中覆盖Poolindex。当块被释放时，该值被采用为PoolDescriptor的索引，将被添加到释放块的相应ListHead中。PoolDescriptor包含PendingFrees列表，即等待被添加到ListHeads的块。

 

首先，ExFreePoolWithTag在其自身内部调用ExDeferredFreePool来释放PendingFrees：合并空闲的相邻块并将它们附加到对应大小的ListHead中。

  

然后，控制从ExDeferredFreePool返回到ExFreePoolWithTag，此函数释放的块被添加到PendingFrees。

 

当PoolIndex被重写的值高于系统创建的池（在我们的例子中为5）时，对ExDeferredFreePool的调用将采用数组中的NULL值 —未初始化的地址，在创建池时添加PoolDescriptor的地址。ExDeferredFreePool将必须取消引用NULL并根据其算法使用PendingFrees和该无效地址结构的其他成员进行工作。

 

在Windows 7中，必须取消引用NULL指针。使用NtAllocateVirtualMemory系统API，我们可以选择页面，从NULL开始，使得该区域的内存适合阅读和写入。在这些页面上，我们会仔细地为所有成员建立一个适合值的假PoolDescriptor，以使ExDeferredFreePool准确的工作。

 

ExDeferredFreePool将使用我们的假PoolDesciptor通过PendingFrees列表。它将从列表中获取一个块，检查它和相邻块的头，并将块的地址插入到我们的池的相应ListHead中。这就是整个行动的关键目标。要将一个项目添加到链接列表中，ExDeferredFreePool中的代码将使用存储在我们的描述符中的指针，并根据指针（从Pendingfrees中释放块的地址）从我们的描述符中写入一个值。

**细微之处：**
