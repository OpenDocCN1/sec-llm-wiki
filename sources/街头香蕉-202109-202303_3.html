CVE-2021-41773

当然肯定是CVE-2021-41773占头条了，漏洞在v2.4.50版本中进行了修复，并且只影响该版本。从Apache官方声明来看，攻击者可以使用路径遍历攻击将URL映射到预期文档根以外的文件。如果文档根目录以外的文件不受require all denied保护，则攻击者可以访问这些文件。

cs脚本

项目:https://github.com/mgeeky/cobalt-arsenal

几个有点意思的脚本演示

parse-error-codes.cna 输出错误代码的含义

beacon> ls C:\gdgsdfgdf   // 使用前[*] Tasked beacon to list files in C:\gdgsdfgdf[+] host called home, sent: 30 bytes[-] could not open C:\gdgsdfgdf\*: 3beacon> ls C:\gdgsdfgdf  // 使用后[*] Tasked beacon to list files in C:\gdgsdfgdf[+] host called home, sent: 30 bytes[-] could not open C:\gdgsdfgdf\*: 3. Parsed error code:    3 - ERROR_PATH_NOT_FOUND

smart-autoppid.cna 大概就是一个伪造ppid的脚本

beacon> autoppid svchost.exe[*] Tasked Beacon to find unprivileged svchost.exe running as 16474 and make it the PPID.[+] Future post-ex jobs will be spawned with fake PPID set to:    svchost.exe      8292      x64      xxxxxxx\xxxx      1[*] Tasked beacon to spoof 8292 as parent processbeacon> shell whoami[*] Tasked beacon to run: whoami[+] received output:xxxxxxx\xxxx

这样监控执行whoami的父进程为伪造的8292进程




如果是正常使用的话，可以看到执行whoami的父进程就是cs的当前进程





stomp-dll-info.py 这个和上面uuid使用了相同的技术点Module Stomping

vCenter SAML Login Tool

项目:https://github.com/horizon3ai/vcenter_saml_login

非常的牛逼，利用之前vcenter文件上传的漏洞，然后通过一顿操作，获取到web端的cookie,实现登录web端的目的。

首先要获取data.mdb

  • Linux:

    /storage/db/vmware-vmdir/data.mdb

  • Windows

    C:\ProgramData\VMware\vCenterServer\data\vmdird\data.mdb

笔者也试了一个。运气比较差，没有成功。看代码他判断替换cookie之后的302，这里报错那就是确实登录不了。手工试了下替换生成的cookie，也是登录不了的。不是代码问题。
