**代码审计**

根据数据包的路径(/func/upload/uploadImages)直接搜索路由，成功找到上传函数

![](../Images/2763d96fef0c8c30007ababe31a5df4a.png)

首先会对db的值进行判断，根据db的值来决定上传文件的保存方式

![](../Images/f9b3ce3a0f40da2d445f9fba72c22742.png)

初始上传的时候，db=1，而if的GlobalConstant.FILE\_UPLOADER\_SAVE\_FILE=0，故直接进入到else if

![](../Images/1676288a1fd4f831933322a4781393e2.png)

![](../Images/a3cee0c1f22bda0a5611ee80e2f3f340.png)

新的文件名 = 上传时间 + 10位随机数 + 原始上传文件的后缀名

*   
*   
*   

```
String extend = FileUtils.getExtend(fileName);// 获取文件扩展名String noextfilename = DateUtils.getDataString(DateUtils.SDF_YYYYMMDDHHMMSS) + StringUtil.random(10);//自定义文件名称String myfilename= noextfilename+"."+extend;//自定义文件名称
```

![](../Images/239d4676710f1bcf9d1155e451aa6baa.png)

文件存储在数据库中，并将文件名通过map保存，最后返回在数据包中

![](../Images/409c57c57b438f463aafbefcf85c9924.png)

![](../Images/d0d5a0fe2259d3ef34d780ca2b0da392.png)

![](../Images/88c196b733b3e2eeb29b99ff01f7556e.png)

db可控，在上传的时候，将db=1改为db=0，进入到if

![](../Images/b951f9d2d960a96c0b95996003005a0e.png)

会创建新的上传目录，新的目录 = Web根目录 + upload + 上传时间（年月日），若不存在则进行新建

*   
*   
*   
*   
*   
*   

```
String realPath = request.getSession().getServletContext().getRealPath("/") + "/upload/" + strYYYYMMDD + "/";// 文件的硬盘真实路径String path = "upload/" + strYYYYMMDD + "/";File file = new File(realPath);    if (!file.exists()) {    file.mkdirs();// 创建根目录}
```

![](../Images/1fdcaba226c579b6bf2602b78e79e685.png)

新的文件名的命名方式跟else if基本一致，在获取文件的后缀名的时候，并未进行检查和过滤，直接进行拼接，从而造成了文件上传漏洞
