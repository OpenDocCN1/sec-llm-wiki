CodeStubAssembler

V8 内置函数用CodeStubAssembler写法介绍 - 知乎 (zhihu.com)

先了解一个概念，bulitin，在写StarCTF2019 OOB的时候，我们其实也可以发现，对oob函数的定义是BUILTIN(kArray){}这样子的，这个实际上就是声明了我们定义的是一个builtin函数，这种函数最大的特点是它是在v8中被定义的，但是给JS提供了访问接口，其实也就是所谓的VM在runtime时的可执行代码块，就是编译进v8的可执行代码段

CodeStubAssembler这个东西就是一种可以用来实现builtins的方法，如下

在上面的例子中，通过TFJ(MathIs42）来建立一个到JS的链接，也就是在JS里声明了一个MathIs42函数

然后通过TF_BUILTIN宏来创建这个函数的实现

Node* const context = Parameter(Descriptor::kContext);  Node* const x = Parameter(Descriptor::kX);  Node* const number = CallBuiltin(Builtins::kToNumber, context, x);  Label if_issmi(this), if_isheapnumber(this), out(this);    Branch(TaggedIsSmi(number), &if_issmi, &if_isheapnumber);    BIND(&if_issmi);  {    var_result.Bind(SelectBooleanConstant(SmiEqual(number, SmiConstant(42))));    Goto(&out);  }    BIND(&if_isheapnumber);  {    // ToNumber can only return either a Smi or a heap number. TF_BUILTIN就是一个宏，可以在当前环境下为一个CodeStubAssembler创建一个子类，这里就是在Math下创建的子类，因为对于v8来说，Math模块是一个高性能模块，为了更快的运行速度，v8使用了Assembler即汇编（并不是汇编）来实现它，重点关注声明的三个Label，这个玩意和汇编中的label还真是一个意思，CodeStubAssembler实现了一个很神奇的操作，我们看上面的三个BIND，这个是用来绑定标签的，比如说


BIND(&label) {    Return(Float64Constant(64))}

那么当执行到

GOTO(&label)

对的时候，代码逻辑就会跑到label上，也就会开始运行Return，这就是v8实现的一个伪汇编，语言描述是C++，但是作为JS的虚拟机来说，也不是不能接收这种汇编语法，好了现在我们来详细分析一下上面的代码

Branch(TaggedIsSmi(number), &if_issmi, &if_isheapnumber);

若number是一个Smi类型的数，就跳转到if_issmi处执行，否则进入isheapnumber

然后看看smi

BIND(&if_issmi);  {    var_result.Bind(SelectBooleanConstant(SmiEqual(number, SmiConstant(42))));    Goto(&out);  }

为返回结果绑定上一个Boolean值，它的值为number和42的对比，相同则为True，否则为False

再看看另一个分支，执行完了以后跑到out

BIND(&if_isheapnumber);  {    // ToNumber can only return either a Smi or a heap number. Just to make sure    // we add an assertion here that verifies number is actually a heap number.    CSA_ASSERT(this, IsHeapNumber(number));    // Heap numbers wrap a floating point value. We need to explicitly extract    // this value, perform a floating point comparison, and again bind    // var_result based on the outcome.    Node* const value = LoadHeapNumberValue(number);    Node* const is_42 = Float64Equal(value, Float64Constant(42));    var_result.Bind(SelectBooleanConstant(is_42));    Goto(&out);  }

首先一个ASSERT确保这是一个HeapNumber，然后加载它的值，再与42做对比，完事了进out

out就很简单了，直接return返回值，总而言之言而总之，这样就创建了一个汇编一样的机制，它的执行效率是很快的，最后一步是注册安装这个函数

PoC源码分析

从上面的分析中，我们已经大概知道了v8是怎么操作Array.from了，有一个临时变量index用于记录迭代次数，也是新数组下标，结束时length为新数组长度，随后重置新数组的长度为length，开发者认为因为在迭代的过程中，每迭代一次，数组里都会被push一个新的元素，因此，不可能出现迭代次数小于新数组的长度这种情况，因此没有判断小于的情况，直接修改了length的值

ok，现在的问题出在新数组上，我们可以控制recevier，从而可以控制新数组 ，如果我们直接令新数组为原本的数组呢？从而在迭代的过程中，我们就可以手动修改数组的length，在迭代退出之前，修改length，此时，新数组等于原数组，长度被修改为0，但是因为在迭代次的时候会记录迭代次数，在迭代的最后，会修改length为迭代次数，数组已经被修改为length=0，数据已经被释放，这样一改，使得length变回迭代次数，length变得很长，从而造成数组越界读写，可以发现整个PoC链都是非常精妙的
