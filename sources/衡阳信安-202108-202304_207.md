# Laravel 9.1.8 POP 链1

## 漏洞描述

```
Laravel 9.1.8, when processing attacker-controlled data for deserialization, allows Remote Code Execution via an unserialize pop chain in __destruct in Illuminate\Broadcasting\PendingBroadcast.php and dispatch($command) in Illuminate\Bus\QueueingDispatcher.php.
```

  

![](../Images/ae83e49a89216224dae63e1b1798335c.png)

## 漏洞分析

根据漏洞信息的描述，跟踪`src/Illuminate/Broadcasting/PendingBroadcast.php`中的`__destruct`方法，可以看到这里的`$this->events`和`$this->event`可控的，寻找可用的`dispatch`方法。

  

![](../Images/3ad5d35410877673dbe1dfa36dfc57a7.png)

![](../Images/85f7a451fbd7f4fe1ee61f7c38e677ff.png)

  

这里跟踪`src/Illuminate/Bus/Dispatcher.php`中的`dispatch`方法，这里`$command`和`$this->queueResolver`均是可控的。

  

![](../Images/a1ae30d38de87b9fd6d06c4f24c47c18.png)

跟进`dispatchToQueue`方法，`$command`和`$this->queueResolver`均是可控的，不难采用的`call_user_func`方法可以利用该方法中来进行执行命令的利用。

![](../Images/5bd95cf473d6c173abeb59356669a2ed.png)

现在需要解决的就是命令的语句，通过上面的语句，`$connection = $command->connection ?? null;`这里可以实现执行命令`src/Illuminate/Broadcasting/BroadcastEvent.php`中的命令来实现控制`$connection`的目的。
