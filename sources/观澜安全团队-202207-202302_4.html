介绍

AMSI（Antimalware Scan Interface），即反恶意软件扫描接口，在windows 10和 windows server 2016上默认安装并启用。顾名思义，他的工作就是扫描、检测和阻止。windows 10和windows server2016中AMSI默认杀软就是Windows Defender。

主要用于可运行脚本语言中的恶意代码检测，如：powershell和VBS等，当amsi检测到恶意程序时，会和反病毒软件进行通信（一般是defender，国内目前没有杀软用）微软鼓励脚本解析引擎都使用该接口，但amsi从逻辑上存在一些漏洞，因此目前主要为defender使用。

amsi检测方式

当脚本进行解密并将脚本提交给脚本引擎时，应用程序可以调用 Windows AMSI API 来请求对内容进行扫描。这样，就可以在决定继续执行之前安全地确定脚本是否是恶意的。

下图为AMSI机制实现逻辑：

  • 首先由上图可知，最终我们需要调AmsiScanBuffer函数或者AmsiScanString函数，这里以Poweshell为例，对一个普通的Powershell进行Attach，并对amsiScanbuffer函数进行Hook，查看其调用栈。
  • 查看到调用堆栈中存在amsi.amsiScanbuffer函数调用，并查看到存在.net库调用，通过逆向查看.net的库文件翻找到amsiScanbuffer的调用位置
  • 可以看到，amsiScanbuffer为外部引入的库函数，无法直接在dnspy看到逻辑，调用函数为System.Management.Automation.AmsiUtils.ScanContent，我们找到ScanContent函数的位置，其为.net框架的一部分，因此是可以查看到代码的。
  • 通过分析System.Management.Automation.AmsiUtils.ScanContent函数，观察到判断若amsi全局变量AmsiUtils.amsiInitFailed也就是没有amsi.dll存在时，会直接通过检查，若为False，则会进行amsiScanBuffer，就会触发RPC将内容发送给杀软进行检测，是为了要兼容没有amsi的机器。

绕过思路

综上所述，PowerShell使用的是.net框架的System.Management.Automation.AmsiUtils.ScanContent调用 AmsiScanBuffer函数，然后RPC调用杀软的检测模块。

  • 思路1:基于Powershell的强大功能，我们可以通过inline Hook AmsiScanBuffer函数对Powershell内存中的AmsiScanBuffer函数进行修改。

  • 思路2:基于Powershell的反射方式，修改内存中的.net对象属性AmsiUtils.amsiInitFailed为Ture即可。

inline Hook Amsi函数

对amsiScanBuffer函数进行Hook，具体思路是通过ps脚本获取amsi.dll句柄，从中获取amsiScanBuffer函数位置，然后将函数内容修改为直接return，就可以防止amsiScanBuffer函数将恶意代码发送给杀软。

项目分析

总体免杀原理为：通过powershell的反射功能调用.net对象，修改对象属性，让对象的AmsiUtils.amsiInitFailed配置为true，使本powershell进程走入NotDetect逻辑返回，并对字符串进行加密后调用。
