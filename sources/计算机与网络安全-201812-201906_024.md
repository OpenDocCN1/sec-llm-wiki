**一、架构选择**

  

常规的安全产品可能是一个杀毒软件、一个[IDS](http://mp.weixin.qq.com/s?__biz=MjM5OTk4MDE2MA==&mid=2655123686&idx=2&sn=23c35bb4d7c1b0414f175ae821ddc950&chksm=bc8665098bf1ec1f63b16681546b1ab596a1350b753f6e7f6c28fde6d0085fe3c15d04977d9e&scene=21#wechat_redirect)、一个WAF，这能解决一个单点安全问题，但如果没有全局的信息汇聚与分析，很难实现对全局态势的感知。

  

[云计算](http://mp.weixin.qq.com/s?__biz=MjM5OTk4MDE2MA==&mid=2655129406&idx=3&sn=83a9a82717306dd30435caf358542d3f&chksm=bc8592d18bf21bc7511d53a4676fd1fb053751a75f0bb0343db152b0f90c39a0ea71e00176aa&scene=21#wechat_redirect)与[云安全](http://mp.weixin.qq.com/s?__biz=MjM5OTk4MDE2MA==&mid=2655123535&idx=2&sn=9630c9bd1587696c83059cb877fa3553&chksm=bc8665a08bf1ecb6416c3496c4415b3b46fabb8e7ee93033ec4e03354bafc43bf81ec19cc718&scene=21#wechat_redirect)是常被提起的概念，在大型网络中，因应用[服务器](http://mp.weixin.qq.com/s?__biz=MjM5OTk4MDE2MA==&mid=2655128495&idx=3&sn=c1bf8a28be100a23ba990869e705ee2a&chksm=bc8596408bf21f5663ebe52e53d2e062f5a7f2149c642a2a9332c17b864f7a5f8758253d7e3f&scene=21#wechat_redirect)对于性能消耗较为敏感，很多复杂的安全分析逻辑不易被业务部门接受，部署于主机和网络上的设备只被限制在实现提取数据功能。分析与计算在后端也就是所谓的云端来实现。

  

采集与计算的分离带来了诸多优点：

  

● 假设（几乎是必然出现）单点系统被[黑客](http://mp.weixin.qq.com/s?__biz=MjM5OTk4MDE2MA==&mid=2655127259&idx=3&sn=c82f59076adf4123590301c9577f3c59&chksm=bc859b348bf21222ef281bc9aebb654a06582273fd7d9eb73ab84b56adbf383f74305efe3c3c&scene=21#wechat_redirect)攻陷，安全策略不易被[逆向](http://mp.weixin.qq.com/s?__biz=MjM5OTk4MDE2MA==&mid=2655126321&idx=3&sn=67729f13740b44858c4eb03f8b43fa47&chksm=bc859ede8bf217c8ecd2086c433e118e518b0caeb5a3a91e5a1380370f185c5049c56d76afc8&scene=21#wechat_redirect)与窃取，避免因策略失窃带来的，对手针对性研究绕过手法；

  

● 可快速更新检测策略，减少对各子节点和探测设备的变更，避免干扰业务系统的稳定；

  

● 原始数据的短时存储，便于对事件演变过程的重现，方便追溯审计，以及预研新检测逻辑的验证。

**1、感知能力**

  

通常SOC系统会收集各种日志，各种NIDS\\HIDS都有数据采集功能。尽可能多的采集数据对于入侵分析是很有帮助的。

  

但我们面对入侵事件时，常常面临两种尴尬局面：

  

**数据很少。**仅有部分系统\\应用默认日志。如侦探破案一般，发现入侵事件最重要的是有证据。通常系统默认的日志等数据无法满足入侵事件分析需求，必须开发专门的探测器。先需要梳理场景对抗需求，搞清楚检测某类攻击所需数据类别与纬度，并将此作为数据采集系统的开发需求，过程如图2所示。

![](../Images/145c56db93bd98712f191efb0a01da7a.png)

图2  数据需求

**数据很多。**大型网络中各类数据很多，甚至多至无法记录。数据并非越多越好，特别是大型网络的海量数据，如全部汇集存储是难以支撑的。且大量的噪音数据也只会带来硬件与人力成本的增加。真正流入最后存储与分析系统的数据，必然是经过精简与格式化之后的，如图3所示。

![](../Images/1591f0cc0686b920c859a2e0ba706930.png)

**2、数据分析**

  

有了数据不等于有检测能力，首先第一个问题就是如何理解您获得的数据，这就是数据格式化。

  

定义格式化数据需做以下工作：

  

● 分析规则决定数据纬度。

● 关联逻辑定义字段扩展。

  

有了格式化好的数据，就实现了数据自动化分析的第一步，接下来才是分析引擎与规则建设。

**三、分析能力**

  

但凡有一点[渗透](http://mp.weixin.qq.com/s?__biz=MjM5OTk4MDE2MA==&mid=2655127440&idx=2&sn=c223aa7241748e66d4ec2490bbe3018e&chksm=bc859a7f8bf213690ae817fe10cf9b5e3a794f74c7650f5fb229284933de86f2f735d6b0bc2c&scene=21#wechat_redirect)经验的人，对于无论是杀毒软件还是WAF\\IDS系统都知道使用各种逃避检测的手段。现在我们面对的是有一定反检测能力的攻击者，特别是高级APT攻击通常较为隐蔽，不易触发单点的安全策略和检测，需要更多纬度和大视角的[数据分析](http://mp.weixin.qq.com/s?__biz=MjM5OTk4MDE2MA==&mid=2655130350&idx=3&sn=9164f5b5a6b1b3e413689caac8c2babb&chksm=bc858f018bf206171a3cc1e08e1b4f85cee39996daf49ae024369447f252ca2bfe533d7faaa7&scene=21#wechat_redirect)。

  

传统安全产品单纯依靠特征库的检测模式，效果已大打折扣。[黑客](http://mp.weixin.qq.com/s?__biz=MjM5OTk4MDE2MA==&mid=2655127290&idx=3&sn=04aaac7d1e20fd446929032cb45b6b38&chksm=bc859b158bf212032e5e2121f6066cd1ec171afc141be62e32ad671879a403ade7b3435495bb&scene=21#wechat_redirect)工具千变万化，攻击手法层出不穷，但他们的目的不变，行为是殊途同归的。所以，在原有特征检测技术之外，用行为模型能更好地检测入侵，我们提出以下检测模型。

**四、实战演示**

  

下面我们通过对一个确切的攻击场景实现检测能力来实践前面的思路。

  

**1、场景分析**

  

在[黑客](http://mp.weixin.qq.com/s?__biz=MjM5OTk4MDE2MA==&mid=2655127259&idx=3&sn=c82f59076adf4123590301c9577f3c59&chksm=bc859b348bf21222ef281bc9aebb654a06582273fd7d9eb73ab84b56adbf383f74305efe3c3c&scene=21#wechat_redirect)入侵过程中，通常有一个环节，就是通过[漏洞](http://mp.weixin.qq.com/s?__biz=MjM5OTk4MDE2MA==&mid=2655127021&idx=3&sn=451c93a621ba2ced4a5ca0e1e63f43c1&chksm=bc8598028bf21114cebd8e7f27e0cf15b764fdef35358d8c62edc03d681d72382568fbadb991&scene=21#wechat_redirect)对自身拥有的权限进行提升，简称[提权](http://mp.weixin.qq.com/s?__biz=MjM5OTk4MDE2MA==&mid=2655128175&idx=3&sn=975f28c1998f4152017482bbeb02db46&chksm=bc8597808bf21e96406c80a6d97b081106b5336cba30cbb00a139ec975059584f99cbc850bad&scene=21#wechat_redirect)。常见的[提权](http://mp.weixin.qq.com/s?__biz=MjM5OTk4MDE2MA==&mid=2655128175&idx=3&sn=975f28c1998f4152017482bbeb02db46&chksm=bc8597808bf21e96406c80a6d97b081106b5336cba30cbb00a139ec975059584f99cbc850bad&scene=21#wechat_redirect)手法是，发现系统存在的[漏洞](http://mp.weixin.qq.com/s?__biz=MjM5OTk4MDE2MA==&mid=2655127021&idx=3&sn=451c93a621ba2ced4a5ca0e1e63f43c1&chksm=bc8598028bf21114cebd8e7f27e0cf15b764fdef35358d8c62edc03d681d72382568fbadb991&scene=21#wechat_redirect)，执行[漏洞](http://mp.weixin.qq.com/s?__biz=MjM5OTk4MDE2MA==&mid=2655127021&idx=3&sn=451c93a621ba2ced4a5ca0e1e63f43c1&chksm=bc8598028bf21114cebd8e7f27e0cf15b764fdef35358d8c62edc03d681d72382568fbadb991&scene=21#wechat_redirect)利用程序，exp利用[漏洞](http://mp.weixin.qq.com/s?__biz=MjM5OTk4MDE2MA==&mid=2655127021&idx=3&sn=451c93a621ba2ced4a5ca0e1e63f43c1&chksm=bc8598028bf21114cebd8e7f27e0cf15b764fdef35358d8c62edc03d681d72382568fbadb991&scene=21#wechat_redirect)获取一个高权限的[shell](http://mp.weixin.qq.com/s?__biz=MjM5OTk4MDE2MA==&mid=2655127748&idx=3&sn=c1a3d178c1155c7613708f4f6384eb64&chksm=bc85952b8bf21c3d2d44139d072702367155b51c86221ea83618a580515205fc6dd139e1496c&scene=21#wechat_redirect)，如图8所示。

**2、检测思路**

  

通过前面的分析和测试，我们会发现一个[提权](http://mp.weixin.qq.com/s?__biz=MjM5OTk4MDE2MA==&mid=2655128175&idx=3&sn=975f28c1998f4152017482bbeb02db46&chksm=bc8597808bf21e96406c80a6d97b081106b5336cba30cbb00a139ec975059584f99cbc850bad&scene=21#wechat_redirect)攻击中的特点，那就是exploit工具自身在执行时是低权限，而得到的[shell](http://mp.weixin.qq.com/s?__biz=MjM5OTk4MDE2MA==&mid=2655127748&idx=3&sn=c1a3d178c1155c7613708f4f6384eb64&chksm=bc85952b8bf21c3d2d44139d072702367155b51c86221ea83618a580515205fc6dd139e1496c&scene=21#wechat_redirect)是高权限。

  

有了对场景的清晰认识，检测逻辑也就很清楚了：

  

某个高权限（system？uid=0？）进程（bash？cmd.exe？）的父进程为低权限，则告警。

**3、系统实现**

  

数据采集需求：我们有了场景有了规则，可以考虑采集那些数据以及数据纬度了。在这个场景中，规则分析至少需要用到几个必备的进程数据纬度：进程权限、进程ID、父进程ID。

  

规则逻辑如下：

  

{

"dsc":"Local Privilege Escalation",

"cache":{

uid>0

},

"rule":{

ip=cache.ip,

ppid=cache.ip.pid

uid=0

}

}

  

以上检测规则基本上能满足多数[提权](http://mp.weixin.qq.com/s?__biz=MjM5OTk4MDE2MA==&mid=2655128175&idx=3&sn=975f28c1998f4152017482bbeb02db46&chksm=bc8597808bf21e96406c80a6d97b081106b5336cba30cbb00a139ec975059584f99cbc850bad&scene=21#wechat_redirect)场景，但实际运用中还有一些细节需要自己去思考完善，例如：

  

● 同样满足父进程权限低，子进程权限高的正常场景有哪些，如何去除误报？

  

● 数据关联分析中，分析流程向前追溯还是向后追溯更易实现，更符合自己分析系统的架构？

  

● [提权](http://mp.weixin.qq.com/s?__biz=MjM5OTk4MDE2MA==&mid=2655128175&idx=3&sn=975f28c1998f4152017482bbeb02db46&chksm=bc8597808bf21e96406c80a6d97b081106b5336cba30cbb00a139ec975059584f99cbc850bad&scene=21#wechat_redirect)攻击除了上述提到的场景，还有哪些？

  

我们可以看到，从行为描述很容易刻画攻击场景，从而实现检测，纵使攻击手法千变万化，而关键路径是不易改变的。通过行为模型实现检测能力，避免了各自[漏洞](http://mp.weixin.qq.com/s?__biz=MjM5OTk4MDE2MA==&mid=2655127021&idx=3&sn=451c93a621ba2ced4a5ca0e1e63f43c1&chksm=bc8598028bf21114cebd8e7f27e0cf15b764fdef35358d8c62edc03d681d72382568fbadb991&scene=21#wechat_redirect)技术细节差异带来的规则库冗余（且影响安全系统性能），也避免因检测规则过分针对细节（特征库\\[漏洞](http://mp.weixin.qq.com/s?__biz=MjM5OTk4MDE2MA==&mid=2655127021&idx=3&sn=451c93a621ba2ced4a5ca0e1e63f43c1&chksm=bc8598028bf21114cebd8e7f27e0cf15b764fdef35358d8c62edc03d681d72382568fbadb991&scene=21#wechat_redirect)库）可能导致的被绕过。

  

以上是在实际入侵对抗实践中，根据公司网络自身环境，外部威胁特点不断总结出来一些浅显经验。总的归纳为：入侵事件数据化、[入侵检测](http://mp.weixin.qq.com/s?__biz=MjM5OTk4MDE2MA==&mid=2655127637&idx=3&sn=eb354c81aeee91431416469bf645d668&chksm=bc8595ba8bf21cac3017017560467081303be6de1228d4bfe211760a4c38031bd63229927ab9&scene=21#wechat_redirect)模型化、事件分析平台化。

  

在针对不同网络环境、安全威胁形势、对抗要求，还须结合自身情况做不少优化和变化。前述无论是架构还是[数据分析](http://mp.weixin.qq.com/s?__biz=MjM5OTk4MDE2MA==&mid=2655130350&idx=3&sn=9164f5b5a6b1b3e413689caac8c2babb&chksm=bc858f018bf206171a3cc1e08e1b4f85cee39996daf49ae024369447f252ca2bfe533d7faaa7&scene=21#wechat_redirect)模型，是在现有网络海量数据、业务环境苛刻、外部威胁多变的情况下一种较为经济易行的[入侵检测](http://mp.weixin.qq.com/s?__biz=MjM5OTk4MDE2MA==&mid=2655127637&idx=3&sn=eb354c81aeee91431416469bf645d668&chksm=bc8595ba8bf21cac3017017560467081303be6de1228d4bfe211760a4c38031bd63229927ab9&scene=21#wechat_redirect)思路。
