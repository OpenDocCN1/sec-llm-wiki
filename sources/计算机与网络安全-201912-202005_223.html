Microsoft Windows系统是最常见的一种操作系统。随着计算机硬件和软件的不断升级，微软的Windows也在不断升级，从架构的16位、32位再到64位，系统版本从最初的Windows 1.0到现在已经发展到Windows 10。目前，对于一些服务器来说，通常使用Windows 2000/2003/2008操作系统，如果是普通用户，通常会使用Windows XP/7/8/10。但是在这些操作系统中存在各种漏洞，如果用户没有及时修复这些漏洞，渗透测试者就可能会利用存在的漏洞实施渗透攻击。本文介绍Windows系统中的漏洞利用渗透实例。


1、Microsoft Windows远程溢出漏洞——CVE-2012-0002


Microsoft Windows是一款流行的操作系统。CVE-2012-0002漏洞源于没有正确处理内存中的数据包。远程攻击者可通过发送特制RDP报文，来访问未初始化或未删除的对象来触发此漏洞。成功利用该漏洞后，可以在目标系统上执行任意代码，并以管理员权限安装程序，查看、更改、删除数据，或创建新账户。受该漏洞影响的系统如下：


Microsoft Windows XP；

Microsoft Windows Vista；

Microsoft Windows Server 2008；

Microsoft Windows Server 2003；

Microsoft Windows 7。


演示在Windows XP SP1上利用该漏洞实施渗透攻击。其中，目标主机的IP地址为192.168.1.106。具体操作步骤如下：


1）使用search命令搜索CVE-2012-0002漏洞的完整路径。执行命令如下：


msf5 > search CVE-2012-0002

auxiliary/scanner/rdp/ms12_020_check normal Yes MS12-020 Microsoft Remote Desktop Checker


从输出的信息中可以看到，已搜索到两个可用于利用该漏洞的攻击模块。其中，第一个攻击模块可使目标造成拒绝服务攻击，第二个漏洞仅用于扫描检测。所以，这里选择第一个攻击模块实施渗透攻击。


2）选择渗透攻击模块，并查看该模块的配置选项参数。具体如下：


msf5 > use auxiliary/dos/windows/rdp/ms12_020_maxchannelids

3）为dos/windows/rdp/ms12_020_maxchannelids模块配置选项参数。执行命令如下：

2、MS11-003（CVE-2001-0036）漏洞


MS11-003（CVE-2001-0036）漏洞利用Internet Explorer（包括IE6、IE7、IE8）对CSS的解析存在的一个问题，使任何访问包含非法CSS的页面导致IE崩溃重启。也就是说，当用户浏览一个特制的网页或者加载了一个非法的CSS的网页时，渗透测试者便可以获得与本地用户相同的用户权限。下面介绍利用MS11-003漏洞实施渗透攻击的方法。

4、IE浏览器的激光漏洞利用

5、浏览器自动攻击模块


在Metasploit中提供了一个浏览器自动攻击模块browser_autopwn。当用户访问Web页面时，该模块将自动攻击目标主机的浏览器。在实施渗透攻击之前，broswer_autopwn模块能够检测到用户使用的浏览器类型。也就是说，该模块只针对IE浏览器攻击。然后，broswer_autopwn将根据浏览器的检测结果，自行部署最合适的exploit。下面介绍利用broswer_autopwn模块实施浏览器自动攻击的方法。

6、利用AdobeReader漏洞——CVE-2010-1240


Adobe Acrobat和Reader都是美国Adobe公司开发的非常流行的PDF文件阅读器。基于Windows和Mac OS X的Adobe Reader和Acrobat 9.3.3之前版本的9.X版本，8.2.3之前的8.X版本不能限制Launch File警告对话框中文本域中的内容。远程攻击者可利用该漏洞欺骗用户执行PDF文档中的任意本地程序。下面介绍利用AdobeReader漏洞实施渗透攻击的方法。


实施PDF文件攻击。具体操作步骤如下：

7、扫描配置不当的Microsoft SQL Server


配置不当的Microsoft SQL Server（MS SQL）通常是进入目标系统的第一个后门。实际上，很多系统管理员甚至不知道它们的工作站上安装有MS SQL服务器软件，因为它们经常作为其他常用软件（如Microsoft Visual Studio）安装的先决条件被自动地安装在系统上。在这些情况下安装的MS SQL服务器软件通常没有实际的用处，也很少安装补丁程序，甚至从未进行过配置，因此存在可利用的漏洞。


安装MS SQL后，默认监听在TCP端口1433上或使用随机动态的TCP端口。如果在随机的TCP端口上进行MS SQL监听，只需要简单地对UDP端口1433进行查询，便能获取这个随机的TCP端口号。当然，Metasploit中有一个模块mssql_ping可以实现该操作。


下面演示使用mssql_ping实施扫描方法。具体操作步骤如下：


1）搜索mssql_ping模块的完整路径，具体如下：


msf5 > search mssql_ping

Matching Modules

================

Name              Disclosure Date         Rank   Check   Description

--------         ---------------         -----  -----   ---------------

auxiliary/scanner/mssql/mssql_ping     normal  Yes    MSSQL Ping Utility


2）选择mssql_ping模块，并查看该模块的选项参数，具体如下：


msf5 > use auxiliary/scanner/mssql/mssql_ping

msf5 auxiliary(mssql_ping) > show options

Module options (auxiliary/scanner/mssql/mssql_ping):

Name        Current Setting    Required      Description

--------   ---------------    ---------     -------------

PASSWORD   no   The password for the specified username

RHOSTS    yes   The target address range or CIDR identifier

THREADS    1   yes   The number of concurrent threads

USERNAME    sa   no  The username to authenticate as

USE_WINDOWS_AUTHENT  false   yes  Use windows authentification (requires DOMAIN option set)


3）配置选项参数，具体如下：


msf5 auxiliary(mssql_ping) > set RHOSTS 192.168.1.103

RHOSTS => 192.168.1.103

msf5 auxiliary(mssql_ping) > set THREADS 255

THREADS => 255


由于mssql_ping使用UDP协议，在对大规模的子网进行扫描时，它的速度可能会很慢，这是因为要处理超时的问题。所以，这里通过设置线程为255来提高扫描速度。接下来即可实施扫描。


4）启动扫描。执行命令如下：


msf5 auxiliary(mssql_ping) > run
