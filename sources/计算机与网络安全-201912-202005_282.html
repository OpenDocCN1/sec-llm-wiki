Metasploit默认已经提供了大量的模块。但是，对于一些漏洞，可能没有对应的渗透攻击模块。这时，可以自己创建或者从第三方获取，并将其导入Metasploit中使用。


1、创建自己的模块


作为一名渗透测试者，会频繁地遇到需要攻击某些应用程序，然而在Metasploit中却没有相应渗透攻击模块的情况。这时候，可以尝试自己来发掘这些应用程序中的漏洞，并为它们编写属于自己的渗透代码。


（1）分析模块的结构


在Metasploit中，所有模块都是使用Ruby语言编写的。而很多用户可能都不会编程语言，不过也不用担心，可以直接使用已有的一些模块作为模板，然后对模板文件进行稍微修改即可成为自己的模块。这里最主要的是，如果要编写自己的模块，则需要对Metasploit中模块脚本的结构有一个清晰的认识。下面以克里斯·盖茨（Chris Gates）编写的一个辅助模块（foursquare）为例，对其进行一个详细的分析。这里先查看该模块的实际脚本代码，并分解各个代码模块。


##

# This file is part of the Metasploit Framework and may be subject to

# redistribution and commercial restrictions. Please see the Metasploit

# Framework web site for more information on licensing and terms of use.

# http://metasploit.com/framework/

##


以上为一些注释信息，是对该模块文件的一个描述。接下来，就是代码的实际内容了：


require 'msf/core'

class Metasploit3 < Msf::Auxiliary   #导入了辅助模块分类

# Exploit mixins should be called first

include Msf::Exploit::Remote::HttpClient  #启用了HTTP客户端功能

include Msf::Auxiliary::Report


以上最前面两行代码表示导入了辅助模块分类，然后在脚本中启用了Metasploit框架内的HTTP客户端功能。


def initialize #初始化构造函数

super(           #定义模块的描述信息

'Name'            => 'Foursquare Location Poster',   #名称

be by venue id',   #描述

[ 'URL', 'http://groups.google.com/group/foursquare-api' ],

['URL','http://www.mikekey.com/im-a-foursquare-cheater/'],

]

[

以上代码主要包括两部分。第一部分是在初始化构造函数中，定义了关于本模块的一些描述信息。在MSF终端中输入info命令时，这些信息会显示出来。第二部分主要对模块运行时要用到的多个参数进行了定义，并在这里定义它们是否为必填参数。所有的代码都非常简单，它们的功能也很明确。但是还没有接触到模块的逻辑流程部分。下面进行深入介绍。


def run  #调用run函数

begin

user = datastore['USERNAME']

pass = datastore['PASSWORD']

venid = datastore['VENUEID']

user_pass = Rex::Text.encode_base64(user + ":" + pass)

decode = Rex::Text.decode_base64(user_pass)

postrequest = "twitter=1\n" #add facebook=1 if you want facebook

print_status("Base64 Encoded User/Pass: #{user_pass}") #debug

print_status("Base64 Decoded User/Pass: #{decode}") #debug

res = send_request_cgi({        #使用send_request_cgi方法创建对象

'uri'     => "/v1/checkin?vid=#{venid}",

'version'    => "1.1",

'method'  => 'POST',

'data'   => postrequest,

'headers' =>

{

'Authorization' => "Basic #{user_pass}",

'Proxy-Connection' =>  "Keep-Alive",

}

}, 25)


以上是该脚本中实际的逻辑流程部分，也就是当run函数被调用后发生的一些列事情。首先将输入的参数传递到局部变量中，同时定义一些其他的对象。然后使用send_request_cgi方法创建一个对象。这个方法是由lib/msf/core/exploit/http.rb导入脚本中的。该方法定义了它的功能描述是“连接到服务器，创建一个请求，发送请求，最后读取服务器返回的信息”。如本例所示，使用这个方法需要多个参数，它会连接到实际的远程服务器上。创建该对象后，将服务器返回的信息显示出来。对应的代码如下：


print_status("#{res}") #this outputs entire response, could

probably do without this but its nice to see whats going on

end


如果执行过程中发生错误。以下是对错误处理的逻辑判断。


rescue ::Rex::ConnectionRefused, ::Rex::HostUnreachable, ::Rex::

ConnectionTimeout

rescue ::Timeout::Error, ::Errno::EPIPE =>e

puts e.message

end

end


以上是对错误处理的逻辑判断，它将错误信息报告给使用者。代码中的逻辑非常简单，实际上是将Metasploit框架所提供的各种功能拼接起来。这个例子很好地展示了Metasploit框架的强大功能，使用这个框架进行开发时，只需要关注为了达到目标所需的各种信息，而不必关心如何进行错误处理，如何管理网络连接，等等。

（2）创建并使用自己的模块


当对Metasploit模块的结构有一个清晰的认识后，也就可以尝试着编写自己的模块了。可以直接在网上找一些模块作为模板文件进行编写，如GitHub。或者，直接复制Metasploit默认的模块作为模板文件。


当创建好自己的模块后，将该块存放在Metasploit用户的辅助模块目录下，以便能够在Metasploit环境中使用它。其中，Metasploit默认将用户的模块位置设置为/root/.msf4/modules。不同操作系统msf版本不同，则该文件夹的名称也不同。在一些系统中，可能是/root/.msf、/root/.msf3、/root/.msf4等。此时，可以根据模块的功能，创建一个完整路径来保存该模块。下面以foursquare模块为例，演示它的使用。下载获取foursquare模块的脚本文件。然后，创建模块存放位置。如下所示：


root@kali:~# cd /root/.msf4/modules/

root@kali:~/.msf4/modules# mkdir -p auxiliary/admin/random


接下来，将下载的模块文件复制到auxiliary/admin/random目录中。如下所示：


root@kali:~/.msf4/modules# cp /root/foursquare.rb /root/.msf4/modules/

auxiliary/admin/random/


接下来，重新启动Metasploit即可加载自己创建的模块。在使用该模块之前，如果不记得该模块的完整路径，则可以先使用search命令进行查找。如下所示：


msf5 > search foursquare  #搜索模块的完整路径

从输出的信息中可以看到，foursquare模块的完整路径为auxiliary/admin/random/foursquare。此时，即可使用该模块了。代码如下：


msf5 > use auxiliary/admin/random/foursquare #使用模块

以上操作显示，先使用use命令选择该模块，然后使用info命令查看了模块的详细信息。接下来，根据信息中提供的参数列表，对该模块进行配置。配置完成后，即可实施渗透攻击。


2、导入第三方模块


一些网站提供了可以直接实施渗透攻击的模块，下载后并导入Metasploit中即可使用。在渗透测试代码库网站（http://www.exploit-db.com/）中，提供了大量渗透攻击模块。如果用户通过漏洞扫描获取到漏洞信息，即可在该网站查找对应的攻击模块。然后，使用该模块对目标实施攻击。


（1）导入第三方模块


导入第三方模块。以导入渗透攻击模块（exploit）为例，介绍其实现方法。具体操作步骤如下：


1）确定下当前系统中的渗透攻击模块个数，代码如下：

with Metasploit Pro -- Learn more on http://rapid7.com/metasploit

+ -- --=[ 2 evasion                                       ]

+ -- --=[ ** This is Metasploit 5 development branch **   ]

msf5 >


从输出的信息中可以看到，当前系统中有1851个渗透攻击模块。接下来，从渗透测试代码库网站中获取第三方模块，并将其导入Metasploit中。


2）在浏览器中访问http://www.exploit-db.com/网站，即可看到大量的渗透攻击模块，如图1所示。

图1  第三方的渗透攻击模块


3）从该界面可以看到，该网站提供了一些渗透攻击模块，并且都进行了分类。另外，该网站还提供了搜索功能。如果知道漏洞的CVE编号，可以直接在该网站搜索对应的攻击模块。而且，该网站还提供有高级搜索功能，可以通过漏洞作者、操作系统平台、攻击类型、端口等进行搜索。单击右上角的Search按钮，即可切换到搜索界面，如图2所示。

图2  搜索攻击模块


4）从该界面可以看到漏洞搜索框，默认没有显示高级搜索选项框。用户通过单击Advanced search命令，显示高级选项搜索框。例如，搜索作者为Metasploit，目标系统平台为Windows的攻击模块，如图3所示。

图3  搜索作者为Metasploit的攻击模块


5）在该界面的搜索选项框中输入对应的条件后，勾选“进行人机身份验证”前面的复选框。然后，单击SEARCH按钮，即可显示对应的搜索结果，如图4所示。

图4  搜索结果


6）从该界面显示的结果中，可以看到已成功搜索到所有的Windows平台，并且是metasploit作者的攻击模块。例如，这里选择下载并导入MS15-100攻击模块。先找到MS15-100攻击模块，然后单击（下载）按钮，并选择保存位置，即可成功获取该攻击模块。该模块成功下载后，是一个名为38195.rb的Ruby文件，具体如下：


root@kali:~# cd /root/下载

root@kali:~/下载# ls

38195.rb


从输出的信息中，可以看到下载的渗透攻击模块。接下来，将该文件复制到Metasploit对应的模块位置，即/root/.msf4/modules。


7）Metasploit默认用户的模块位置是/root/.msf4/。在该目录下有一个modules文件：


root@kali:~/下载# cd /root/.msf4/

root@kali:~/.msf4# ls

history  local  logos  logs  loot  modules  plugins


从以上输出信息中，可以看到有一个名为modules的目录。此时，用户进入modules目录中，同样可以安照模块的分类创建对应的文件夹，用来保存不同类型的模块。本例中将导入一个渗透攻击模块，所以这里将创建名为exploits的文件夹。


root@kali:~/.msf4# cd modules/

root@kali:~/.msf4/modules# mkdir exploits


执行以上命令后，将不会有任何信息输出。此时，使用cd命令切换到该文件夹中。接下来，可以使用mkdir再创建其他文件夹，用来保存该渗透攻击模块。之所以创建多个文件夹，也是为了方便记忆或查找模块的位置。


root@kali:~/.msf4/modules# cd exploits/

root@kali:~/.msf4/modules/exploits# mkdir -p windows/local


成功创建一个模块保存位置后，即可将下载的模块复制到该目录中了。


8）将下载的模块复制到新建的文件夹中。执行命令如下：


root@kali:~/.msf4/modules/exploits/windows# cd local/

root@kali:~/.msf4/modules/exploits/windows/local# cp /root/下载/38195.rb

/root/.msf4/modules/exploits/windows/local/

root@kali:~/.msf4/modules/exploits/windows/local# ls

38195.rb


从输出的信息中可以看到，渗透攻击模块文件38195.rb已成功复制到新建的位置。


9）重新启动Metasploit，即可发现新增加了一个渗透攻击模块。具体如下：

从以上显示的信息中可以看到，exploits类模块由原来的1851变为了1852。由此可以说明，模块已成功导入。

3、动态加载模块


动态加载模块是指根据需要，临时加载指定的模块。这样可以避免永久性大量加载第三方模块，造成Metasploit启动缓慢等问题。在MSF终端，提供了一些命令，用来动态加载模块。下面介绍使用这些命令动态加载模块的方法。


（1）指定加载路径


loadpath命令用来从一个路径中搜索并加载第三方模块。其中，指定的模块类型可以是exploits（漏洞利用）、encoders（编码器）、payloads（有效载荷）等。该命令的语法格式如下：


loadpath [模块路径]


指定从/home/secret/modules路径中搜索并加载模块。执行命令如下：


msf5 > loadpath /home/secret/modules

Loaded 0 modules:


看到以上输出信息，说明已从用户指定的路径中搜索模块了，但是没有找到可加载的模块。


（2）加载模块


load命令用于从Metasploit的模块目录中加载一个模块。如果用户没有指定绝对路径，则首先查找用户的模块目录~/.msf4/plugins，然后查找框架的主模块目录/usr/share/metasploit-framework/plugins。其中，语法格式如下所示：


load [var=val var=val ...]


使用load命令加载模块。执行命令如下：


msf5 > load pcap_log

[*] PcapLog plugin loaded.

[*] Successfully loaded plugin: pcap_log


从输出的信息中可以看到，已成功加载了pcap_log模块。


（3）卸载模块


unload命令用来卸载前面加载的模块或删除任何扩展命令。其中，语法格式如下：


unload [模块名]


卸载pcap_log模块。执行命令如下：


msf5 > unload pcap_log

Unloading plugin pcap_log...unloaded.


从输出的信息中可以看出，pcap_log模块已被卸载。
