1 AUTOSAR安全—整体方法


汽车行业正面临着一场巨大的变革，这给互联和自动驾驶环境中的车辆 E/E 架构带来了根本性的变化。设计正在从许多特定于应用程序的 ECU 转向少数具有捆绑功能的高性能域控制器。这种技术工程趋势要求整合汽车网络安全并改变 AUTOSAR 架构。

2 从 AUTOSAR Classic 到 AUTOSAR Adaptive

AUTOSAR Classic 是大多数车辆平台的标准中间件，满足实时操作系统和功能安全的典型要求。多年来，它一直在不断发展，并提供了一系列用于安全车载通信或密钥和证书管理的安全工具。然而，车载计算机或域控制器将塑造未来的 E/E 架构作为中央应用程序，在高度自动化甚至全自动驾驶和 V2X 通信中，车辆将成为一个以软件为主导的系统。这需要集成更多比过去更加广泛和多样化的应用程序。与 AUTOSAR Classic 不同，AUTOSAR Adaptive 基于与 LINUX 相关的操作系统，应用程序使用“AUTOSAR Runtime for Adaptive Applications”，简称 ARA。此外，自适应平台提供管理程序预配置分区，使不同供应商独立开发的不同 ASIL 类别的软件组件能够集成到车载计算机中并在其上安全运行。AUTOSAR Adaptive 与其面向服务的架构和额外的功能（如细粒度的无线更新）相一致，还整合了额外的措施并为汽车安全设定了新的标准。

3 AUTOSAR 中的安全模块

AUTOSAR 结合了各种 IT 安全应用程序，例如，用于保护车载通信和保护机密数据。

加密堆栈：在 Classic 和 Adaptive 版本中，对安全相关应用程序所需的加密原语、密钥和证书的访问都是通过 AUTOSAR 特定的加密堆栈进行的。应用程序随后仅访问提供的接口，独立于它们各自的加密实现，并保持可移植到不同的 ECU。

安全通信：AUTOSAR 确保通信是安全的——包括车辆内部和外部（例如后端、诊断测试设备）。由于车内应用和总线系统广泛，它同时支持多种协议：SecOC、TLS和IPsec。作为 AUTOSAR Classic 的专用协议，SecOC 专门保护 CAN 通信。另一方面，TLS 和 IPsec 变得越来越重要。这两种标准都支持真实和保密的通信。AUTOSAR Classic 和 Adaptive 都包含 TLS，而 IPsec 仅在 AUTOSAR Adaptive 中可用。

身份和访问管理：通常不建议授予所有应用程序访问车辆网络有限系统资源的权限，例如持久性存储器、传输路径或密钥。因此，AUTOSAR 身份和访问管理模块确保只有经过授权的应用程序才能访问某些资源。身份和访问管理仅在 AUTOSAR Adaptive 中可用。

安全诊断：在车辆网络中记录与安全相关的事件（未经授权的访问、安全通道设置失败等）非常重要，以便随后对其进行评估和调试。AUTOSAR 支持在安全存储器中记录 IT 安全事件。它还使用 UDS 安全访问和身份验证来监控对这些数据的授权访问。

4 超越 AUTOSAR 的集成汽车安全

AUTOSAR Classic 和 Adaptive 为保护车辆软件和数据免受操纵和未经授权的访问提供了重要的模块。但是，对于车联网的端到端保护以及在互联环境中对车辆的全面保护，还需要额外的措施。

最重要的措施是必须为所有安全关键应用程序实施的硬件支持的信任锚。在现代车辆架构中，硬件安全模块 (HSM) 被选择用于此角色。HSM 在物理上封装了密钥材料，并且可以将加密密钥与各种（可能不可信的）应用程序分开存储和管理。此外，随着车辆变得越来越互联，需要在车辆（IDS，汽车防火墙）和后端的取证中实施具有协调组件的综合入侵检测和预防系统（IDPS），包括启动对整个车队的固件无线 (FOTA) 安全更新形式的响应。

此外，上述措施要求ECU在生产过程中配备加密密钥集。车辆制造商的密钥材料必须通过合适的密钥管理系统 (KMS) 在生产现场注入。

图 2. 集成汽车安全，包括 ECU 生产和安全后端

作为互联和自动驾驶趋势的一部分，与安全相关的车载功能不可避免地会增加。成熟的安全措施以及高安全级别的车载架构平台将有助于解决这些技术挑战。此外，原始设备制造商需要有一个安全的车辆工程流程/系统，以建立基于高连接性的新商业模式。这明确要求进一步开发 AUTOSAR Adaptive 以集成安全应用程序，同时继续使用 AUTOSAR Classic 进行传统开发。
