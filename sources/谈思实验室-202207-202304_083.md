# 1 自适应平台架构中的集群更新

这是我想在这里讨论的第一个问题。让我们看下图：

![](../Images/4524c36ff4b61ef25a7e55d98bb5321f.png)左侧的 AP Architect 可能是将于 2020 年 11 月 27 日发布的新 AP Architect。同时，右侧描述了最新 AUTOSAR Release (R19-11) 中的 AP Architect。该图说明了 2个事情。

## 1.1 ara::diag 服务（诊断）更新

第一个是将ara::diag 服务（诊断）从Platform Foundation Cluster（也称为“ API ”）移动到Platform Service Cluster（也称为“ Service ”）

Platform Foundation Cluster是“基于库”的设计。Platform Service Cluster平台服务是“基于服务”的设计。

## 1.2 信号到服务映射和自动驾驶接口

本次更新的最后一项是新增2个属于平台服务的功能集群：信号到服务映射和自动驾驶接口

### 让我们讨论一下信号到服务映射服务:

您可能知道 AUTOSAR Classic Platform (CP) 是“基于信号”的设计，而 AUTOSAR Adaptive Platform (AP) 是“基于服务”的设计。在AP和CP同时存在的情况下，需要解决集成系统中AP和CP之间的转换问题。

从以前的版本开始，它在 CP 的分层软件体系结构和相关规范（例如 Com Stack 规范）中得到了仔细考虑。注意：在AP中的每次版本更新是要考虑AUTOSAR整体系统设计。

# 2  车载应用商店概念

如今，随着使用移动设备的普及，我们可以看到技术的发展不仅取决于“大商业公司”，而且取决于“个人”成员。Symbian 和 Window Mobiles 由于缺乏流行的社区【应用商店】在时代的洪流中落伍了。带有 App Store 的 iOS 和带有 GooglePlay的 Android 的超快速增长是技术社区实力的重要证明,也许很多人都曾想过汽车的“应用程序商店”。想象一下，你坐在自动驾驶汽车上长途旅行（10-12小时），那时候你应该做什么？玩一些游戏，听音乐，看电影等等。个人笔记本电脑或手机完全可以支持这些活动。但是你认为你可以用你的车做什么？

另外，我在汽车社区看到很多人都有自己的私家车。他们想为他们的汽车做一些“改装”。这不像“修改”游戏或 PC 那样容易。我们需要更多地考虑安全性，因为汽车是一个与周围环境交互密切的产品。

也许 AUTOSAR 会在他们的架构中部署这个想法。AUTOSAR Introduction 用一张幻灯片来描述它。
