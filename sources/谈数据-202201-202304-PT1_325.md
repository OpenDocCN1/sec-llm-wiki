# 企业并购期间，产品主数据该怎么管？

并购 (M&A) 的目标和期望几乎总是相同的：削减成本、提高效率、缩短价值实现时间、自动化手动流程、增强商业智能等。最终，并购应该为股东提供价值，谁期望快速获胜。  

然而，并购失败的案例却比比皆是，如微软和诺基亚、谷歌和摩托罗拉、以及时代华纳和美国在线等等。

为什么合并如此频繁地失败，或者至少不像预期的那样容易成功？对并购的高期望似乎与威胁其成功的陷阱成正比。

有几个挑战。Richard Kestenbaum 在他的《福布斯》文章《企业收购失败的原因以及如何避免它》中提到文化是最重要的：“当你收购一家公司并改变文化时，你就是在与公司成功的原因展开战争。”

并购还可能增加员工对裁员的恐惧并带来系统和流程上的差异。本文重点讲一下在企业并购期间产品主数据管理的挑战。 

**01  CIO的职责**

企业并购期间的数据管理对 CIO 或 IT 领导者来说是一个挑战。他们必须管理双倍的信息系统架构并将产品数据合并到一个产品分类系统中。

产品数据的合并对于业务的整合是非常重要的，可以帮助企业建立并购后的品牌一致性、更好的客户体验和提升运营效率。

主数据管理系统可以通过内置的数据治理功能帮助合并产品数据，并通过确保干净和一致的产品数据来实现很多改进的业务成果。

CIO全权负责在并购期间成功管理数据。例如，因并购而整合在一起的全新和改良系统可能会带来流程和数据冗余问题，CIO需确保这个统一系统能够达到预期的协同增效作用，从而履行轻松降低某些成本的承诺。

  

CIO应知道并购带来的某些现实问题：当不同的数据系统因并购而被整合在一起时，将会出现机会和问题并存的情况。数据库整合蕴含巨大潜力，但也隐藏着一些伺机吞噬资金和资源的陷阱。

  

系统和数据库整合是很难向利益相关方讲清楚的严峻IT挑战。成功的并购似乎与CIO无关，但如果IT系统整合失败或预算超标，CIO则难辞其咎。

  

当然，两公司合并后可选择作为独立的个体来经营业务，销售不同品牌和类型的产品，这样便能减少数据问题。但是，利益相关方经常希望通过合并产生重大影响，无论是合并之前的老品牌还是合并之后整合而成的品牌，他们希望通过扩张来改变贸易格局。

  

合并意味着处理数据孤岛和异构数据环境，从 IT 的角度来看，产品数据的合并主要存在以下问题：

*   多组分类和产品数据
    
*   不同的ERP系统
    
*   不同的仓库系统有不同的SKU
    
*   传输和维护产品数据的各种不同的应用程序和系统
    
      
    

数据存在于不同的系统和格式中。并购之后，基础设施架构、需要管理和维护的主数据量以及管理和维护成本都将翻倍。这一点不仅适用于产品数据，而且也适用于客户、供应商、员工、位置、资产和营销等其他数据域。

为提高效率、确保并购后的长期业务运营、以及快速获得回报，您必须汇总并整合数据。您有两个选择：合并您的系统或连接您的系统。或者，确切地说，您有三种选择，第三种是合并并且连接系统。

**02 产品****数据两种管理方法**  

**1、合并系统**

很可能，在合并后，您最终会得到大量冗余系统和主数据重复。因此，您需要在淘汰冗余系统之前将相关信息传递到您的主系统中。

**作为跨系统移动数据的一部分，您需要消除不一致性，例如重复和不准确。**

移动后，您将拥有所需的所有数据，而不会产生管理臃肿的基础设施资产的成本。

**2、连接系统**

作为合并系统的替代方案，您也可以选择连接系统。若选择连接系统，您将能够避免在信息的原始位置使用它们，或者首先等待信息进入企业、然后再通过主数据管理(MDM)解决方案传送之后才能使用它们，从而加快信息使用速度。

这种方法可以标准化并融合ERP、CRM及供应链等主数据和应用平台，同时消除重复性和复杂性。

您具体选择哪种方法取决于商业案例和数据模式。某些情况下，同时选择合并和连接系统才是最佳解决方案。

企业在合并之后，必须尽量将两公司的产品数据汇集在一个统一的产品分类系统下。

这对于建立适当的参考及可追溯制度非常重要：来自不同系统的所有产品必须以相同方式进行分类。

  

**03 并购企业做好数据管理的七个步骤**

一般来说，企业并购期间要做好数据管理，需要以下七个步骤：

**第一步：成立数据管理团队**

成立由收购公司的 CIO 或首席数据官 (CDO) 领导的数据团队。该团队应由来自两个组织的人员组成，并且必须具备足够的 IT 和数据问题专业知识，才能看到机遇和威胁。团队还必须有足够的影响力将问题提升到执行级别，因为及时的沟通对于合并的成功至关重要。

然后，数据团队同意数据管理方法的愿景和目标，然后制定数据战略，包括预算和时间表。

**第二步：执行数据管理审计**

数据团队执行包括所有数据利益相关者的审计，以描述当前的数据格局和未来的数据模型。审计是必需的，因为它将让团队了解涉及哪些业务领域和部门，并了解数据模型的复杂性。由于部门被邀请参与，审计还将提供数据合并的多个视角，并有助于项目的支持。审计期间要解决的问题是：

*   产品数据和资产（系统、应用程序、文件）位于何处？
    
*   数据如何遍历这些不同的系统（数据流）？
    
*   谁拥有数据？
    
*   谁管理数据？
    

  

**3、就数据分类系统达成一致**

根据审核结果，数据团队就产品数据分类系统达成一致。分类系统反映了新公司的来源、数据质量、格式和层次结构。

分类系统将形成匹配和链接产品数据的基础，并为如何迁移产品数据提供指导。

**4、选择合适的主数据管理系统**

如果您使用 MDM 系统来识别、链接、获取和同步来自各种内部和外部来源的产品数据，那么管理数据迁移将变得更加容易和快捷。

根据数据模型的复杂性和数据战略的愿景，您可通过以下四种方法之一来实施MDM系统：（PS：[终于有人把主数据的定义、价值和管理模式讲透了！](http://mp.weixin.qq.com/s?__biz=MzkwNTMzMzI4Mg==&mid=2247486110&idx=1&sn=faf51ec01b80882b38d231bd880cd7e0&chksm=c0f815d3f78f9cc507ad78be07a7be2130b340db9708bd5ee21c6b17b187fc96ddf60ae04eb1&scene=21#wechat_redirect)）

**归集模式。**整合数据由遗留系统（ERP、库存管理系统等）所拥有，且在并购期间仍保存在遗留系统中。这种情况下，您可通过MDM系统将这些数据汇聚并整合到所谓的黄金记录中，在这里对数据进行清理与同步。这种方法的优点在于无需中断遗留系统的运行，从而加快数据合并速度。

**集中模式。**如果通过审计发现数据模型存在大量的杂乱无章的产品数据，无法以有意义的方式聚合，则MDM系统可以作为主记录平台来接管工作，然后将数据推送到运营系统（零售商系统、营销应用程序、销售点、数据仓库等）。如果其中一家公司以电子表格的形式管理产品数据，那么，这种集中式的方法将是值得一试的。

**共存模式。**主数据管理构成双向系统的一部分，可确保单一版本的真实性。每当使用新信息更新孤立系统时，主数据管理系统就会更新，反之亦然。无论系统数据是从哪里提取的，它始终是单一版本的事实。与整合方式相比，共存方式在同步和整合数据的同时，允许遗留系统完全可操作。

**注册表模式。**在这种实施方法中，MDM 系统允许组织保持数据隔离，这有助于支持监管要求。这在医疗保健行业尤其常见。

**5、就数据治理程序达成一致**

在并购完成后的整个新组织中，需要实施新的数据治理政策和程序来确保问责制、灌输准确的报告、管理合规性并确保透明度。 

**6、为所有数据的迁移做好规划**

迁移所有的数据乃是并购完成后最难开展的一项任务，需要充分做好准备工作，包括检查硬件、软件和资源的能力。迁移需要数据安全计划以避免数据泄露和恢复计划以恢复之前的状态；最后，迁移还需要制定上线计划，以规定谁在何时应做些什么。最重要的是，迁移需要反复开展测试，直到将错误量减少到可以接受的范围内，因为您不可能做到完全不出错。

**7、使用主数据管理系统进行迁移**

主数据管理系统将在过渡阶段证明其价值。然而，展望未来，MDM将继续成为一个有价值的工具，因为它可以消除重复数据并帮助企业控制如何通过可配置的工作流程创建、更新和批准记录。

您可以使用主数据管理系统来确保供应商数据的有效载入并将主数据分发给所有利益相关者。该组织将继续受益于消除部门和合作伙伴之间的数据障碍。

由主数据管理系统保护的对主数据的牢牢掌握甚至可以通过清晰的审计跟踪和记录历史来更容易地维护法规遵从性和数据治理。

**04 企业兼并时产品数据管理要点**

并购期间的数据管理对 IT 领导层提出了挑战。导致 IT 基础架构翻倍的业务合并将不可避免地加剧任何现有的数据孤岛问题，合并数据也很重要。

主数据管理可以帮助统一产品数据，也可以作为并购后时代的宝贵工具，让您从长期的并购中获益。具体选择哪种类型的主数据管理模式，需要根据企业的实际情况进行选择。
