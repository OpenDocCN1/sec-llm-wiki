最开始用github好像还是把它当记事本来用，讲真，从没系统的学习过git以及github，就知道它是全球最大的同性交友社区，不过前天出了一个漏洞让我发现善用github真的对快速定位到漏洞点有很大帮助。简单看下https://docs.github.com/

可能不全，慢慢积累

一、搜索 Search



就是搜索功能，高级搜索我一般用不到，这里着重了解下搜索语法

1.对于仓库的搜索

关键字 stars、topics、created、pushed、language、org、

配合= >= <= .. 日期限定等

2.NOT 以及 “-”排除特定结果

cats stars:>10 -language:javascript 匹配含有 "cats" 字样、有超过 10 个星号但并非以 JavaScript 编写的仓库。

3.对带有空格的查询使用引号

build label:"bug fix" 匹配具有标签 "bug fix"、含有 "build" 字样的议题。

4.补充一些关键字

lable、author、assignee、is

5.我的一些搜索习惯

直接搜CVE编号，commit编号，漏洞可能出现的类名方法名等欢迎师傅发散思路

还有之前做安服的时候 会加上password user等关键字


二、关于Github的可视化界面




github提供了一些列的可视化图，可以很方便的查看但那个库的活动摘要

项目贡献者、仓库流量、仓库中的更改、仓库内同的增加和删除、仓库的网络、列出仓库的复刻、仓库的依赖项，这里我觉得最有用的一点应该是依赖项了，可以很直观的查看项目中依赖的其它组件


三、安全漏洞模块



一些组件的安全公告，最新漏洞会在此展示


四、查看和比较



参阅：https://docs.github.com/cn/free-pro-team@latest/github/committing-changes-to-your-project/comparing-commits

以在分支、标记、提交和日期之间比较仓库的状态。要比较仓库的不同版本，请在仓库路径中附加 /compare

查看仓库所有commits：https://github.com/apache/flink/commits

后面直接加commit编号即可此次提交修改部分

https://github.com/apache/flink/commit/049a61a578c8ba7ed65eca69eb543be096ecffac

文件history即可查看文件的所有变更历史


五、Issues 及Pull requests



可根据labels来过滤安全相关更新

其实直接在搜索界面就可以直接定位到
