组件概述



1.   关键词

身份认证框架、反序列化、身份认证绕过

2.  概述

需Apache Shiro是一个强大且易用的Java安全框架,能够用于身份验证、授权、加密和会话管理。Shiro拥有易于理解的API,您可以快速、轻松地获得任何应用程序——从最小的移动应用程序到最大的网络和企业应用程序。

Shiro可以做什么？

  •     验证用户身份

  •     用户访问权限控制，比如：1、判断用户是否分配了一定的安全角色。2、判断用户是否被 授予完成某个操作的权限

  •     在非 Web 或 EJB 容器的环境下可以任意使用Session API

  •     可以响应认证、访问控制，或者 Session 生命周期中发生的事件

  •     可将一个或以上用户安全数据源数据组合成一个复合的用户 “view”(视图)

  •     支持单点登录(SSO)功能

  •     支持提供“Remember Me”服务，获取用户关联信息而无需登录

    以上引用于:https://zhuanlan.zhihu.com/p/54176956

    源码技术架构参考: https://www.jianshu.com/p/dc5c49f5101e

3.使用范围及行业分布

  •     由于其易用、全面、一站式安全框架、Web支持、低耦合、等特性，被广泛应用集成于各个应用中，二次开发中大量使用，通用组件，影响面巨大

  •     未找到有效的应用搜索语法

  •     通用组件，全行业均覆盖

1.CVE-2016-4437 (Shiro550)

1)查看issue信息

默认使用 CookieRememberMeManager 来处理Cookie Base64编码 AES编码 反序列化

2)加密过程

org.apache.shiro.mgt.AbstractRememberMeManager#onSuccessfulLogin 处下个断点

token中存储信息

向下跟进，来到了 forgetIdentity:257, CookieRememberMeManager  会调用构造方法this.forgetIdentity处理request和response请求


向cookie中加如了一些内容

因为勾选了rememberme，所以回到onSuccessfulLogin:297, AbstractRememberMeManager，我们会进入到rememberIdentity方法中

跟进去，由于是root用户登录，所以进入嘚是这个rememberIdentity

convertPrincipalsToBytes:360, AbstractRememberMeManager，这个方法会序列化肉焖传入嘚用户名，然后调用encrypt(encrypt:473, AbstractRememberMeManager)加密序列化吼嘚二进制字节 加密方式为AES/CBC/PKCS5Padding，key为DEFAULT_CIPHER_KEY_BYTES 的常量

然后回到rememberIdentity:347, AbstractRememberMeManager，将加密吼嘚二进制字节流交给rememberSerializedIdentity处理

跟进去，这里会有一步是base64加密

3.CVE-2020-11989

A.复现

没登陆情况，访问会直接302

访问pochttp://192.168.33.134:8080/;/shiro/account/  会直接显示信息


B.分析

1)直接进入Shiro的权限校验

是通过判断url匹配来做的，Shiro中对于URL的获取及匹配在org.apache.shiro.web.filter.mgt.PathMatchingFilterChainResolver#getChain

漏洞点处在这里

访问/;/shiro/account/时，获取到的是/ 所以跟进getPathWithinApplication:111, WebUtils 

org.apache.shiro.web.util.WebUtils#getRequestUri 获取到的是/

跟进GetRequestUri方法，步步跟进，发现问题处在decodeAndCleanUriString:234, WebUtils，分号截断了，

回到getPathWithinApplication:113, WebUtils 返回了 /


2)修复

参考链接 https://xz.aliyun.com/t/7964


4.CVE-2020-1957

动态调试参考链接 https://www.freebuf.com/vuls/231909.html

A.复现

/hello/1 访问不到 /hello/1/ 就访问到了

B.分析

1)漏洞函数与CVE-2020-11989相同

漏洞还是PathMatchingFilterChainResolver的getChain函数，其中正则匹配出了问题

2)修复

该修复方式是通过判断requestURI是否以/为结尾，如果以/结尾的话，则去掉尾部的/符号在与URL表达式进行比较

3)修复绕过

绕过payload，/fdsf;/../hello/1，成功绕过

4)再次修复

获取requestURI的方式从request.getRequestUri直接获取的方式更改为获取request的ContextPath，ServletPath，PathInfo，然后再重新拼接而成，当然了，后面还有CVE-2020-11989呢
