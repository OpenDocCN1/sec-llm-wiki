# 技术分享丨rtf恶意样本静态分析

## ![](../Images/cc4c5455866f38118e1a55fee41e76a8.png)

**一. 起源**

![](../Images/f5133e5fee3e5c73993337d84f3fb4df.png)前几天一位推友发布推文一个恶意样本弹框 大概意思是不能在any run 沙箱中运行![](../Images/94f7e182abe8271c65fa4f7acb2d0193.png)结果推友当时就在any run 沙箱上传运行。也是比较有意思的样本![](../Images/e516035b0d2a7e6189043a7bf50fb149.png)  

**二. 样品分析**

![](../Images/f5133e5fee3e5c73993337d84f3fb4df.png)既然这么搞笑，就我们一起来分析这个恶意样本吧  
本文从静态的角度分析样本。首先我们考虑使用010编辑器查看，结果发现为rtf的文件![](../Images/d090c68061b9f8d51fd5f90a2d278030.png)那么我们这里使用oletools 套件中个的rtfobj查看，结果发现它中包含vbs文件  
![](../Images/e791b1dcd65fa27e946ec87aca966371.png)那么我们对其进行dump下来vbs文件![](../Images/2f2639b450cb9f36c7ef4f843fc9bd10.png)  

**三. VBS混淆**

![](../Images/f5133e5fee3e5c73993337d84f3fb4df.png)下面我们来分析vbs的内容，由于代码过于冗长，不便截图，我这里就挑重点讲。  
下图我们可以看到vbs代码中一个红框包含了字符串的内容为powershell，第二个红框也是为powershell的代码，其中vbs对其进行拼接、替换字符串、以及字符串倒序。![](../Images/b88e8573994f28f6ee980c349faf4bbf.png)那么我们重新整理vbs的代码对其进行输出到控制台  
![](../Images/13caf47f6370f16d7db6eaa6ff2027c2.png)这里我们调用cscript 执行我们重新整理好的vbs，结果完整的powershell代码就输出出来了。![](../Images/9f96d7f26784cbe39b50d4d667361e72.png)  

**四. powershell混淆（一）**

![](../Images/f5133e5fee3e5c73993337d84f3fb4df.png)我们可以看到该powershell的内容为混淆，但是我们可以对其进行解码混淆就是，去掉最后面的 I'E'X字符串  
![](../Images/02f7a2bcc037f1dffa35a3e30efb321c.png)那么我们重新整理之后的代码为下图输出后的内容![](../Images/76a3553b4f396fd7f035d193607f33d3.png)下面我们来分析解码混淆后的代码，第一行代码为字符串拼接，为第一个红框注释的内容，为bypass asmi，第二个红框为下载执行base64加密的文件![](../Images/7c98e31cf271e31d2607a4c1a800a135.png)下图为base64的文件  
![](../Images/8273e204283ecab0f7509f20b7d184d9.png)  

**五. powershell混淆（二）**

![](../Images/f5133e5fee3e5c73993337d84f3fb4df.png)我们对其进行解码后，为下图代码  
![](../Images/449be8974e8c51cb5d2636ee2a3e2e7d.png)由于代码过于冗长我们挑几个重点讲解，我们看到下图中的红框1f,8b开头的数据 为gzip![](../Images/b4d3c927729175fffa9e03957bd960a6.png)而下图 4d，5a开头的数据为我们熟悉PE文件  
![](../Images/9cae95442a8b363caf28cadfdb247568.png)下图为分离后的文件![](../Images/073907820b9b2936dfa6dd0c40c37903.png)同时我们也对其进行解压，发现解压后的文件也是exe/dll文件![](../Images/b102352fca595cd5b02be6cd70267630.png)下图为在010编辑器中的内容  
![](../Images/188f73be7f6f135ce1a89df4a8143170.png)下图为在powershell中我们第二个红框的pe文件![](../Images/a9ae64d8496ae1c249f7df7b68436bca.png)所以最终的文件为，一个c#编写的dll，和一个exe文件  
![](../Images/59c680a7b00bbee25e43d724df02aa18.png)![](../Images/ef7f5adbda54f0688179c1cd6927b9d9.png)我没有对其进行下一步的分析，因为也超出本文的含义分析范畴。大体可以猜测为后门文件。  
![](../Images/963b2f7f15f334c690b0c2879fd295bc.png)最后在powershell的代码中我们，调用control.exe运行第二个exe，为bypass applocker的行为方式。![](../Images/0333eba18bbe380e0f78c34f56cd6e03.png)总体来说该powershell代码具体的内容如下：1.bypass asmi2.下载解码执行base64文件3.解码后释放两个后门文件4.bypass applocker
