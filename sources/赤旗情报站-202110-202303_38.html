Sysmon简介


System Monitor （Sysmon）是一款优秀的日志监控工具，后被微软纳入自身体系，常被用于入侵检测。


值得一提的是，作为一款安全人员常用工具，sysmon主页申明自己不提供事件分析能力，也不尝试保护/隐藏自身防止攻击者定向攻击。


因此严格来说把sysmon视为EDR是不严谨的，因为EDR（Endpoint detection and response）中一个重要能力就是响应能力，而原生的sysmon是不具备这点的。


Sysmon目前版本为：13.32


Sysmon目前支持记录26类事件，包括且不局限于：进程创建、文件创建/删除、网络连接、注册表修改、WMI事件、命名管道。具体支持的事件类型见

https://docs.microsoft.com/en-us/sysinternals/downloads/sysmon#events


Sysmon基本使用


Sysmon默认为全量记录，一般使用都会添加一定规则，一是防止影响机器性能，二是噪音较大不利于分析（splunk贵）。

比较优质的sysmon配置文件有下列的仓库，需要注意不同版本sysmon配置文件的兼容问题


https://github.com/SwiftOnSecurity/sysmon-config

https://github.com/olafhartong/sysmon-modular


使用配置文件安装sysmon


sysmon.exe -accepteula -i sysmonconfig-export.xml

更新规则

sysmon.exe -c sysmonconfig-export.xml

Sysmon的卸载

sysmon.exe -u

Sysmon日志路径为：%SystemRoot%\System32\Winevt\Logs\Microsoft-Windows-Sysmon%4Operational.evtx



Sysmon的检测


很明显，攻击者首先要确认的就是是否安装sysmon，除了从外部社工手段获取目标招中标信息、技术文章，获取一台主机权限后还可以从以下几个角度进行检测。


通过进程

Get-Process | Where-Object { $_.ProcessName -eq "Sysmon" }Get-Process | Where-Object { $_.Description -eq "System activity monitor" }




注意：sysmon进程名可以在安装过程修改


通过查询服务

Get-CimInstance win32_service -Filter "Description = 'System Monitor service'"Get-Service | where-object {$_.DisplayName -like "*sysm*"}


通过查询事件日志注册表

ls HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\WINEVT\Channels | Where-Object {$_.name -like "*sysmon*"}



通过查看驱动，sysmon的驱动名为SysmonDrv

fltMC.exe

前面提到过sysmon也是Sysinternals的一部分，所以可以通过查看Sysinternals的注册表确认是否装过sysmon（有些单位可能POC过，所以不能作为现存的依据）

dir  HKCU:\Software\Sysinternals  | Select-Object name



Sysmon的绕过


前面提到过，一般都会使用sysmon配置文件从而降低噪音，所以可以通过查看sysmon配置文件找到白名单程序从而进行绕过日志记录。


查看sysmon的配置文件，在sysmon二进制文件路径执行如下命令

sysmon -c

或者通过powershell，但是只对老版本有效

https://github.com/mattifestation/PSSysmonTools/blob/master/PSSysmonTools/Code/SysmonRuleParser.ps1


查看代码可以看到该工具读取的是HKLM\SYSTEM\CurrentControlSet\Services\SysmonDrv\Parameters\Rules

该脚本在目前的sysmon新版本会直接报错


通过Seatbelt工具也可以查看sysmon相关信息

https://github.com/GhostPack/Seatbelt


查看注释可以发现，seatbelt同样是根据前面提到的SysmonRuleParser.ps1实现的


Seatbelt对高版本sysmon解析效果如下，是做了一定加密的，所以无法正常读取，不过也可以尝试查找落地的sysmon配置文件。


卸载sysmon驱动

fltMC.exe unload SysmonDrv


卸载sysmon驱动后，sysmon仍然会继续运行，但是会丢失一定的日志检测能力，sysmon最后一条日志会是事件ID255


system日志内也会记录事件ID为1的SysmonDrv卸载事件



但是目前的版本dns查询日志似乎没有使用驱动，所以还是会继续正常记录dns日志


小结


即使攻击者进入一个遍布sysmon的环境也不必过于担心，sysmon仅仅是日志记录工具，如果没有良好的安全运营和检测规则，sysmon同样无法发挥价值。


Sysmon的安全风险主要存在于攻击者已经取得管理员权限，这种情况下sysmon基本无法防范攻击，但是已经最大程度的缩小了攻击面。


由于sysmon Windows版没有开源，所以在sysmon本身添加防护措施比较难。蓝队可以考虑在siem平台设置卸载等敏感操作告警规则，以及在机器一段时间没有正常提供sysmon日志后进行探活。
