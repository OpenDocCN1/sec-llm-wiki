十大技术（之一）

  

  

**Windows Command Shell**  

Windows Command Shell 几乎可以调用系统上的任何可执行文件来执行批处理文件和执行任意任务。

* * *

**分析：**为什么攻击者使用 Windows Command Shell？

  
Windows Command Shell 在所有版本的 Windows 中无处不在，不依赖于特定版本的 .NET。  
Windows Command Shell 是攻击者武器库中最简单的工具，它能够调用系统上几乎任何可执行文件来执行其任务。因为 Command Shell 可以执行批处理文件，所以攻击者可以使用它来可靠地重复执行任意任务。  
**攻击者如何使用 Windows Command Shell？**在对 1,000 多个已确认的威胁检测进行审计时，在数百个客户环境中的 4,000 多个独特命令行中被调用超过 6,000 次。  
PowerShell 在 480 多个实例中是 cmd 的子进程。在 30 多个客户环境中看到了 350 多个对唯一批处理文件的引用和 270 个调用 cmd 的唯一计划任务。  
最常见的技术之一是使用 cmd 调用本机命令并将这些命令的输出重定向到本地管理共享上的文件，例如：  

![](../Images/d84954df21a86a8654b844e38c896d06.png)

  
该技术与 Impacket 一致，攻击者使用它来操纵网络协议。在十几个客户环境中观察到近 400 次类似的执行和输出重定向模式。  
  

**新兴的 Windows Command Shell 替换技术**

在 2020 年最后一个季度，观察到 11 次检测到 cmd.exe 替换 utilman.exe 启用身份验证绕过，是该季度唯一频率较高的 Windows Command Shell 检测涉及可疑的红队活动和类似的内部测试工具。  
当如果涉及cmd.exe有什么新奇的东西，那可能是混淆了。2018 年春天，Daniel Bohannon 发布了一份关于 DOS 混淆技术的白皮书和一个名为 Invoke-DOSfucation 的框架，用于创建可用于逃避简单、基于签名的检测并减慢人工分析的混淆 DOS 命令行。在包含 1,000 多个涉及 Windows 命令外壳的检测的数据集中，发现 91 个独特的命令行涉及某种程度的混淆。观察到的最严重混淆的 DOS 命令与此处显示的类似：  

![](../Images/46553ce0ab8215b5d1cb1365375bbb74.png)

  
在 Windows 命令执行过程中，插入符号 (^) 字符是转义字符。当它在特殊字符之前时，例如管道 (|) 字符或文件重定向运算符 (<>)，这些特殊字符将被视为普通字符。当插入符号在非特殊字符之前时，没有什么特别的事情发生；它实际上被忽略了。所以上面的命令变成了：  

![](../Images/f0c2e8e5b488620ba00c6374848450a7.png)

仔细查看这个命令，可以看到它将一个名为 N1 的变量设置为一个包含反向 PowerShell 命令的字符串。有一个 For 循环可以反转这个字符串并执行它。PowerShell 命令创建一个下载底座以下载文件并通过调用 Invoke-Item 来调用它。  
虽然这些混淆命令可能会避开简单的、基于签名的检测，但寻找常用混淆技术的分析（例如插入符号的存在）可以轻松检测到它们。  
分层检测分析也将有所帮助。如果检测错过了混淆的 DOS 命令，则可能会在 PowerShell 下载、对 Invoke-Item 的调用或对异常域的 DNS 查找上触发另一个检测。

**如何通过进程和命令行监控检测？**  
  

Windows 安全事件日志（特别是启用了命令行参数日志记录的进程创建 【ID 4688】事件）将是观察和检测恶意使用 Windows 命令执行的最佳来源。

  
对调用 Windows Command Shell 的基线脚本和进程有很好的理解对于减少噪音和对抗潜在的误报警报至关重要。  

  

关注不常见的执行模式和通常与恶意相关的执行模式，请考虑监控以下内容：

*   执行似乎是 cmd.exe 的进程与包含大量建议使用混淆的字符的命令行一起执行，例如 ^、=、%、! , \[ , ( , ; • 在 cmd.exe 进程的上下文中过度使用 set 和 call 命令
    
*    命令行中出现异常多的多个空格 
    
*   将输出重定向到 localhost 的管理共享：例如 > \\\\ computername\\c$
    
*   执行与其他攻击技术相关的命令（例如调用 regsvr32.exe 或 regasm.exe 加载异常动态链接库）
    
*   调用 reg.exe 修改注册表项以启用或禁用远程桌面等功能或用户访问控制，或将数据写入或读取异常注册表项
    

  

在应用检测逻辑之前，请考虑从命令行中删除以下字符：( " ) ^ 尽管 cmd.exe 本身的功能相当有限，但它有许多可以调用的工具。充分了解这些工具对于检测恶意使用 Windows Command Shell 至关重要。

  

**如何降噪？**

需要注意：

用于检测恶意使用 Windows 命令执行的最佳数据来源——捕获命令行参数的进程创建事件（Windows 安全事件日志中的事件 ID 4688）——也将是误报的主要来源。

  

创建过滤器以对正常使用、异常使用以及可疑或已知恶意使用进行分类，以构建成功的检测管道，不会让分析人员因误报而不知所措。
