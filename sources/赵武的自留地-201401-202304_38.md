# 少儿编程的困惑

    最初只是为了找一个比较好的方式来构建亲子时间，所以我跟果果说带你编程吧。对于男孩子而言，天生的会对机械类的电子类的比较感兴趣。关于亲子时间我理解的是：不是你站在他身边多长时间，而是你们一起共同渡过的时间。所以，我并不认为接送上培训班我在外面等着叫亲子时间，我也不认为我们坐在沙发上你看着手机他玩着游戏叫亲子时间，而是在没有别的事情干扰的情况下你们一起做的事情才叫亲子时间。所以，通常意义上，我认为亲子时间最好不要带手机（除了拍照以外不要用手机）。

    另外，我又认为亲子时间一定要有趣，有趣是针对我们两个人的，不能我有趣他觉得无趣，也不能他觉得有趣我觉得无趣，任何一方觉得无趣都是一种“牺牲”一种被动的“陪伴”或者“施舍”，这种情感并不会充满乐趣因此也就难以持续。一种健康的亲子时间一定是双方都喜欢并且能够共同成长的（家长有时候会成长的更多，因为小朋友靠的是精力，大人们靠的的经验和总结能力）。选来选去，我们沉淀下来共同喜欢的活动有：露营，篮球，滑雪，乒乓球，编程，阅读，爬山，街机。里面我最擅长的就是编程，所以花费我们的时间也是最长的。最近，我正在积极的学习三国杀……

    回到编程上来，在一开始的时候，我并没有预料到会遇到的难度，不是我不懂编程，而是我不懂“教学”。因为站在我的经验角度来看，我会很容易的跳过底层的基础，而这些对一个小学生而言都是属于完全未知的领域。比如数学计算和计算机英语，更重要的是，我们家两个神兽都是特别喜欢蹦跶静不下来坐不住的代表，让他们能够安静的呆上几个小时，还是比较有难度的。不只是如此，在我们家比其他家难度更大，那就是在老大编程的时候，老二会乘机动老大的玩具，老大就会暴跳如雷……

    所以一路下来，我犯过太多的错误，走过很多弯路，最严重的莫过于差点打击他放弃了这条路，尽管他还是喜欢，但是他不想学了。我们让他跟着一位很好的教授学过一段时间，那段时间他还是比较有成就感的，因为他获得的肯定比较多，身边还有一群好朋友可以交流相互嘚瑟。我曾经问他你觉得你们班同学如果来点评你的话，会怎么说你，他想了想，然后说“他们应该会说我体育不错，我的跳绳和跑步在班里都是很好的”，停顿了一下又补充“还有他们应该会觉得我计算机不错，因为每次上信息课老师问的问题我都能很快的回答上来，老师也经常表扬我”。我觉得在他心里播下了一个非常好的种子这一点我深感欣慰，我需要做的事不断地施肥灌溉不断地除草，我怕的是我的一些行为造成的效果是把种子挖了出来，被我一口吞掉了。

    于是我决定带他编程让他上到一个阶段，这次我把假期时间全部留出来，每天3-4个小时雷打不动的按节奏教他，这个过程持续了一个季度。接下来的我发现了一些教学上的问题，非常明显且极为困惑。

最重要的一个问题就是缺少初心。他最初的原动力是认为计算机好玩，带着尝试的心态去“玩一玩”。类似于scratch或者code早期确实好玩，拖动就是编程，简单直接有效。但是那个只是理解逻辑用，真实的编程大多数靠scratch是不行的，比如底层网络协议或者3d 图形等。而且它们甚至不对应编程语言的逻辑。c++作为noip等官方支持，且非常基础实用的编程语言，似乎是非常适合拿来做入门学习的。然而，问题就来了，如果初心是“好玩”，对于他这个还没有感知主动学习乐趣的年龄段来说，为了学习而学习是非常枯燥的，这种枯燥是一种茫然，是一种无趣，是一种任务。即看不到所见即所得的结果，也看不到色彩鲜艳的图形，唯一看到的就是大段代码和鲜红色的错误提示，他对这些错误提示的英文都不认识。所以，为了学而学，跟我们小时候学习课本一样，日复一日。

    我开始想为什么教他编程？因为他喜欢。为什么中间他开始不喜欢？因为很长一段时间没有正向的结果反馈机制。为什么没有正向反馈？哦，我突然想明白了一件事，那就是：初心没有了，目标丢失了。我们把目标定在了“学会”，而不再是“好玩”，其实这两点并不直接冲突，问题在于：我们没有把“学会等于好玩”的逻辑建立起来。比如他的困惑是“我学会了能干什么呢”？我的困惑是“我教会他了能干什么呢”？是去参加比赛？还是到我公司打工？还是创造属于他自己的东西？

    我打心底里面认可的观点是：编程就是做自己想做的东西，编程的输出是一个创造价值的过程。所以是不是为了比赛，或者是为了求职，这些都不是我们现在要去讨论的话题。而我们容易犯的第一个错误就是，给他一堆乐高积木碎片，然后说你来搭建，除非不世出的天才，否则他永远知会简单的往上堆叠。我们一气之下，把他的堆起来高高的积木推翻，骂了一句“你怎么搭了这么个玩意”，完蛋，他的心灵受到了极大的打击。稍微好一点的父母会边鼓掌边说“哇，你真棒，搭的真好”，于是他每天只会往上搭建，你看了很多天以后，会想“我们家孩子应该没有天赋”，于是放弃了。

    我是很后来才想明白这件事的。要想他打好篮球，不是先给他一个球，而是带他到NBA CBA的现场感受那种激动人心的气氛，是带他看电视上在总决赛抢七大战时力王狂澜的球星。编程也是如此，你要指给他看说，你看比尔盖茨编写的windows操作系统改变了世界，乔布斯的苹果改变了世界，你看你最崇拜的notch编写的《我的世界》让所有小朋友都在玩……这些都不难，你会编程了你也都可以。“真的吗？”那一天我看他眼里都是光，“你是说我也可以吗？”。“当然，谁都可以，关键看你学会以后想做什么。你可以做游戏，你可以跟爸爸一样做网络安全的工具，你也可以做一个微信。这取决于你的想法。你学习编程的目的只是为了做你想做的”。

    当找到了这个答案，我们约定了第一步共同先做一个小游戏，用他学习的c++，时间为一年内，这是他目前最能理解的兴趣点。对于我而言压力还是有点大的，我要教他的东西我也没摸过，所以我偷偷地开始学习cocos2d引擎，我也要学游戏编程的逻辑，乘着他还在学数据结构和算法，等他正式准备编游戏的时候，爸爸威武的形象不能垮。

    说到这，我就明显感觉到现有少儿编程材料的问题，你学成了所有，你依然连一个简单的实用的工具都做不出来。是能力不够吗？当然不是。是场景不够，是创意不够。学的是骨架，要做血管和皮肤，总差那么点意思。在现实生活中的程序，一要图形，二要网络，三要产品体验。这些在类似的早期编程书籍并不会提现。诚然，那些只是后期单独学习的一些类库，是否应该放到早期的逻辑训练过程中有待商榷。只是我们一开始就教软件工程，让他们看不到乐趣。为什么不从最小的一个demo开始来要求呢？有可能我是错的，但是我个人的成长过程却是如此。我永远把我想做的先定好，然后把流程步骤列清楚，最后找出需要有但是我还不具备的能力做单独的学习和攻坚。这种学习方法是一种比较务实的迭代成长方法，在《精益创业》这本书中用了MVP（Minimum Viable Product,意思是最轻量级的可行性产品）来形容小步快跑的学习成长模式。换句话说，谁定了一个方向，谁切分了小目标，谁完成了攻坚，这些是区别于创始人和员工的最本质区别。

    这里我稍微有点成人化的意思，我讲了太多的道理，早上跑步的时候跟果果聊天，说你可能觉得我的要求太高了。相比其他的大部分小学生，我相信你的编程能力肯定强了一些，但是你能做出你想要做的东西了吗？你觉得你缺什么呢？你活着是为了证明比别人强一点吗？我相信肯定不是。我们不是为了别人的评价活着的，我们最终还是想通过自己的努力创造一个我们想要创造的东西，这个东西对其他人产生了价值，所以有很多人愿意使用。所以只要我们还没有做出来我们的小目标，就不要跟别人去“嘚瑟”。“乐趣+务实”是我认为他首先需要体会的原动力。我不希望他为了工作编程，我不希望他为了拿名次上好学校而编程，我也不希望他为了炫技而编程，我希望他单纯的是为了实现自己的理想而编程。

    在实际的教学中，我也有一些困惑，比如实际应用与原理的理解。举个例子来说排序算法有很多种，在实际的使用过程我从来不会关心是什么排序算法，几乎任何一门现代化的语言都内嵌了排序的算法实现，比如c++中Arglrithm库就有sort方法，比如golang中有单独的sort包。在实际的工作中，我其实选择了站在巨人的肩膀上，来跳到更高的起点。但是在教学过程中，似乎很看中这些底层的原理。我倒是不认为学习原理有什么问题，但如果说到原理，那么我最大的困惑就是从哪里开始原理的讲解？比如说面向对象的编程语言之前是函数化的编程语言，再次之前是汇编语言，再往前是机器码，再往前是CPU处理器是ALU单元，再往前是逻辑门……所以原理从来开始，到哪结束呢？还是抽空着来说呢？

    再比如，char数组代表在c里面的字符串，对应很多函数，strcpy，strlen，strcat等，这些函数最大的问题在于需要关注动态内存分配与释放，以及要注意各种访问越界的问题。而在c++中，string类都较好的解决了这些问题。但是对于教学，我们到底要不要教他们这些信息，我觉得理解是一定要的，但是如果是我们自己开发产品编码，我觉得实在是没必要用到那些底层方法，相比封装好的类库，这些原始操作代码量更大也更容易出错。简单来说就是数据类型，数据结构，算法要用自我实现的部分，还是用现成的。

    很多问题我也没有答案，所以我比较困惑，我过度思考了他以后的方向。至少现在他还属于连编译报错的意思都看不懂的阶段，连基本库函数名称都记不住的状态。很多朋友问我如何教小朋友编程，实话说我也不知道，可能等到我们家老大未来某一天突然编了一个软件，让大家用起来了，我才能告诉大家这个答案吧。我不知道果果最近是不是感觉到有趣，反正我是觉得挺有意思的，最不济，他做俯卧撑的能力强大了不少（因为我教过他还不清楚的，我会让他做俯卧撑）。期望今年我们的小游戏能够顺利出来。
