#### 分析

Dubbo官方在2.6.10.1开始就引入了一个属性`serialization.security.check`来避免消费者指定Provider的序列化类型，达到恶意的目的

如果我们将属性`serialization.security.check`置为true

直接在启动类设置环境变量：

```
System.setProperty("serialization.security.check", "true");
```

### Kryo协议

#### 分析

Kryo序列化方式是一种相较于其他序列化方式较快的序列化方式，速度更快，更便捷。

我们有了前面分析Hessian协议下的反序列化铺垫后，我们知道我们能够在消费者发送request请求的时候指定特性的序列化方式

比如有这些

![](../Images/364022940badbcf2863001f25cb7f5ea.png "null")

image-20220916195426942.png

在`CodecSupport#getSerializationById`将会通过传入的序号，返回对应的序列化器

如果这时候我们指定了通过Kryo协议进行序列化和反序列化的时候，并且provider存在Kryo对应的包，且会使用对应的InputStream对象处理数据

如果使用的是老版的Kryo组件(version < 5.0.0)存在反序列化漏洞

#### 影响

这里和前面的那个范围是一样的

*   • Dubbo 2.7.0 to 2.7.8
    
*   • Dubbo 2.6.0 to 2.6.9
    
*   • Dubbo all 2.5.x versions (not supported by official team any longer)
