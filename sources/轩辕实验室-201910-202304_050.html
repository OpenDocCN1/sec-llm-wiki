自动驾驶的驾驶决策安全不能定性分析，因此该文章提出了一种定量分析的验证方法（用概率表示），以单车道环形路口作为一个运行实例，通过对统计模型的检验来验证量化的安全特征。
自动驾驶汽车的典型决策过程：通过感知设备、路边站点、中间站等来感知和观测当前的交通环境；根据上一步获取的信息评估其他车辆的行为；再根据当前的交通状况和上一步的评估来决定下一驾驶行为。接下来，就是整个决策模型的抽象建模过程。
定义：SM表示直接坐标系上的实际位置，segment表示道路段，segment中的element表示组成道路的分区，每个都包含了SM中的可访问位置，我们可以通过函数divSeg根据实际位置信息检索出相应的路段（road segment）
定义1（Map）
Segment等定义如图
 

给定segment，它可以被描述为三个不相交子集的并集，cross、critical、normal
Cross是来的方向大于1，去的方向大于等于1的segment  
Critical是segment的子集，表示与Cross相邻的道路段，在进入Cross前要通过Critical
Normal是剩下的道路段
 
定义2（path）
Path是一个有限长度的道路段序列，长度为n，Sn为结束道路段。
path : < Sn >= {Sn | Sn ∈ Segment ∧ (Sn, Sn+1) ∈ Arc ∧ n ∈ N}
 
定义3（route）
定义和path没差别，就是一条特定的path
定义4（traffic snapshot）
交通快照由五个因素构成，TS = (position, speed, acceleration, left, right)
位置由SM（segment中具体的element表示）
速度值由一段控制周期行驶的距离
加速度值是由此控制周期和前一控制周期的速度值得到
左转向灯和右转向灯的状态是由布尔值表示
 
评估信息
基于三点：
1. 当前控制周期接收到的交通信息
2. 从上一个状态继承的本地知识
3. 受控车周围车辆可能的驾驶决策
 
在每个控制周期内，从交通快照获取最新的信息，然后在自己原定的路线中行驶并重复评估过程。
 
定义5（Estimation Structure）
ES = (movDistance, drivingPath, accesPosition, Prob)
movDistance:计算其他车辆一个控制周期内通过的距离，根据位置速度、加速度数据计算
drivingPath：对于每一个c ∈ C 的从当前位置开始的可能的行驶路径
AccesPosition:对于每一个c ∈ C 可能位于的segment，为了减少位置状态，P(Path) 仅考虑于divSeg(accesPosition(c, drivingPath(c), movDistance(c))).结束的那些segment
Prob:用[0，1]表示沿各种行驶路径的可能路段的概率分布（概率之和为1）
 
评估过程的步骤：
1. 明确受控车辆路线中的目标segment
2. 计算受控车辆在一个周期内可以移动多远，根据由当前TS所获得的速度、目标segment、加速度
3. 根据2中的cover distance减少TS中要观测的空间，检查干扰segment的存在，并预测在已经被减少的TS中哪些segment是受控车辆和其他车辆重叠的路线（这里的reduced TS 就是AccesPosition中的reduce）
4. 根据T S中3的相关车辆的不确定交通信息修改概率
5. 根据3中相关车辆可能接近的距离修改概率。
 
无论交通标志和交通规则的限制如何，都以概率的方式对评估得到的信息进行建模，根据以下方面来表示不确定性：
 
·定义：个体机动车的概率分布：{A1, A2,...,An}表示个体决策的所有样本集，他们既完全穷尽又互斥。（因为当机动车行驶到某一segment时其可能的行驶路径和允许的动作是确定的）
 
·基于TS和可接近距离来修改概率
两个例子：
根据TS:左转为TRUE时，左转的概率提升，相应的其他概率下降（总和为1）
根据灯状态：即使突发状态转向灯不开启，也考虑和转向灯开启一样的评估方式（简化模型）
 
·定义：对概率分布的修改：
P(A1) + P(A2) + ... + P(An) := 1
p(A1) + p(A2) + ... + p(An) := 0
p(B1) + p(B2) + ... + p(Bn) := 0
if left(c) = true ∧ right(c) = false →
P(A1), P(A2),...,P(An) := P(A1) + p(A1), P(A2) + p(A2),...,P(An) + p(An)
right(c) = true ∧ left(c) = false →
P(A1), P(A2),...,P(An) := P(A1) + p(B1), P(2) +p(B2),...,P(An) + p(Bn)
对于每一个动作A，灯状态的改变都会导致对该事件的不同的概率影响。
 
模型的验证
    
如何将抽象模型映射到SHA以检查量化的标准？
需要一个状态机模型：M = (Q, q0, A, G, C, T)
Q是当前所有map上车的TS和其相应的ES
q0是TS中的信息
A：从一个segment到另一个segment的动作，每个动作只有满足G才能触发
G:取决于逻辑表达式中指定的空间条件的布尔值，来源于TS和ES
对于受控车辆或其他车，满足g即发动动作，权重w是用于估计其他车的动作的，TS检查是否在目标段、ES评估下一阶段出现的位置，根据这些，检查是否满足条件。
C：时钟集
T：对其他车辆带有权重的动作在自动机中进行建模，每辆c的Q的更改都是要在满足g的条件下发动动作a，并有一个对应的权重w，其中w由prob得到。
 
验证：
准则：1.假设每辆车都遵守交通规则
2.安全性定义为每段时间每个segment都存在唯一车辆
      
验证标准：受控车辆的segment中不存在任何c
 
具体案例
将整个系统看做自动机网络，则可以分为周期自动机、受控车辆自动机、目标段自动机和干扰段自动机，四个自动机的工作流程如下：
周期自动机：发送信号以控制时间、刷新数据
受控车辆自动机：通过广播信道R发送刷新新环境观测的同步信号，然后更新受控段和目标段，然后根据安全约束g来进行下一步动作
目标段：如果目标段存在其他车，使用一个随机函数，把车随机到其它segment中，以保证self在到达目标segment时是安全的。
干扰段：在干扰段的车如果满足某些条件则可以做出对应的行动，根据行动来调整可能性Prob进而调整权重m
