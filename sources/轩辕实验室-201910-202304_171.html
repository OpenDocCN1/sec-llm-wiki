面向车联网的基于推荐的信任模型（Recommendation-Based Trust Model for Vehicle-to-Everything (V2X)）

  • 作者：Aljawharah Alnasser, Hongjian Sun, and Jing Jiang.

  • 收录于：IEEE INTERNET OF THINGS JOURNAL, VOL. 7, NO. 1, JANUARY 2020.

1. 背景介绍

V2X的重要性：

  • 智能交通系统是实现智能城市的关键，而其中最重要的一项技术就是V2X。V2X为道路上各实体提供了统一的连接平台。每个道路实体（行人、汽车、摩托车、基础设施等）都能够通过V2X分享自身的信息。

V2X存在的问题：

  1. 移动节点如何选择拓扑结构经常变化的下一跳；

  2. 道路实体之间的通讯时间开销；

  3. 点对点连接易遭受攻击（包括内部攻击和外部攻击）；

  4. 传统的密码学方法可以解决外部攻击，但是不能抵抗内部攻击；

在车辆通讯网络中，所有的节点的信息都需要发送给核心网络，这些数据可能会通过多跳路由发送给核心网络；其中，中继节点可能就是一个内部攻击者，可能会对网络产生不利影响；因此，需要一个信任模型通过收集邻居节点的行为和信息来检测出内部攻击者。目前，已有的解决方案中，都要求两个节点之间有过通讯记录，才能对其该结点进行判断。然而，在车载网络中，经常会收到来自一个新的节点请求转发的数据包，基于推荐的信任模型能更好的解决这个问题。

目前已有的基于基于推荐的模型：

  1. 选择可信节点作为排头，所有信任值及反馈信息都有RSUs处理；若在没有RSUs的地方，则不能使用该方法；

  2. 基于各节点的信任值，授予其接入网络通讯的权限；该模型中忽略了信任值较低的节点其发送错误推荐的情况；

  3. 基于节点自身意见和收到推荐意见的相似度来做出决策；若该节点对目标节点不能给出意见时，该方法不能使用；

本文提出了一个基于推荐的分布式的信任模型：

  1. 与以往的推荐信任模型不同，本文提出的模型是一个分布式的模型，并且可以处理非持续性恶意行为；

  2. 在推荐过滤节点，基于正面推荐和负面推荐的数量，分别赋予其不同的权重；

  3. 与现有模型进行了比较：在恶意节点占87.5%时，本文的模型丢包率更优；

2. 系统模型

2.1 网络

  • 由n个道路实体（使用节点代替）组成的车辆通讯网络。各节点按照预先规定的路线以随机的速度移动；

  • 所有的交易消息（transaction message）需要送到核心网络（Core Network）进行进一步的处理；

  • 在中继覆盖的场景中，当两个节点中有一个位于当前车辆通讯网络网络覆盖之外，则其建立通讯；

  • 通讯形成了多条路由从而将数据包发送给核心网络；

在该网络中考虑正常和恶意两种节点：

  • 正常节点：实时检测周围的环境，并将数据包发送给核心网络。同时，它也将收到的数据包转发给附近的RSU；

  • 恶意节点：在这篇文章考虑的中继转发场景中，恶意节点可能实施以下两种攻击：

    • 路由攻击：该攻击会影响数据包的转发。例如Blackhole攻击，恶意节点将收到的数据包全部都丢弃掉。Greygole攻击，恶意节点会丢弃部分收到的数据包；

    • 推荐攻击：恶意节点会故意发送错误的推荐建议来破坏其他节点的信任决策；

此外，考虑恶意节点两种不同的行为模式：

  • 稳定的恶意行为模式：恶意节点会持续进行恶意行为；

  • 变化的恶意行为模式：恶意节点基于自己的选择，将正常行为与恶意行为交替进行；

2.2 模型框架

节点每次要发送信息给核心网络时，都要经过以下四个步骤：

  1. 网络覆盖阶段：每个节点都不断检查其与核心网络以及其他节点的连通性；

  2. 通讯阶段：如果源节点可以与核心网络直接相连，那它直接将数据包发送给核心网络。否则，源节点就将其要发送的数据包发送给一个可靠的中继节点；

  3. 信任计算阶段：每个节点都需要计算邻居节点的信任值；

  4. 决策阶段：根据计算结果，进行决策。

总共模拟四种恶意行为攻击：

  1. Blackhole attack：节点将接收到的所有数据包都丢掉

  2. Greyhole attack：节点丢掉收到的部分数据包

  3. Bad-mounting attack：对于正常的节点，给出一个负面的推荐意见

  4. Good-mounting attack：对于恶意的节点，给出一个正面的推荐意见

4.2 结果分析

1、网络性能

在图中，当恶意节点百分比大于或等于87.50%且所有恶意节点都是Blackhole攻击时，丢包率一直在增加，直到在最坏情况下达到约0.4。另一方面，在Greyhole攻击中，丢包率也会随着恶意节点所占比例的增加而增加，但增加的幅度相对较低。


文中将网络吞吐量定义为成功发送到核心网络的数据包与整个网络中产生的所有数据包的比，这好像就等于1-丢包率。

2、Blackhole/Greyhole攻击的检测率

各节点信任值都初始化为0.5。

  • 在Blackhole攻击中，由于节点将所有的数据包都丢掉，所以导致该节点的直接信任值和收到的推荐值都较低，所以在第一个间隔会直接下降到0.08；之后，随着时间的推移，恶意节点的信任值会逐渐降低。

  • 在Greyhloe攻击中，由于恶意节点一开始只丢弃少数的数据包，所以该节点的整体信任值会上升；但是随着时间的推移，收到越来越多关于该结点丢包的信息，其信任值会逐渐下降；由于收到的建议的影响，价值下降。

3、做出正确决策所需最少可信邻居节点数

分析邻居节点给出推荐建议的四种场景下，对于节点i要做出正确的决策，最少需要的邻居节点数目。


两节点之间之前不存在通讯记录：

  • 三角形标记的那条线表示，表示i和j之间目前不存在通讯，i对j的整体信任值都基于其他邻居节点发送来的推荐建议。所以当给出推荐建议的可信邻居节点较少时，i计算得到j的整体信任值也较低，当可信邻居节点占百分比在60%以上，i计算j的整体信任值会高于信任阈值，此时可以做出正确决策；

  • 正方形标记的那条线，表示i和j之间目前存在通讯，i对j的整体信任值基于j的直接通讯信任值和邻居节点发送来的推荐建议，所以受邻居节点的可信度的影响相对上一种情况较小。

两节点之间存在通讯记录：

  • ⚪标记的那条线表示，表示i和j之间目前不存在通讯，i对j的整体信任值基于i对j的以往信任值和其他邻居节点发送来的推荐建议。因此，当可信节点的百分比高于10%时，计算出j的整体信任值高于信任阈值。
