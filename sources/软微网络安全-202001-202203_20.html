解题步骤


  • 知识点一：

    每个在以太坊虚拟机（EVM）中运行的智能合约的状态都在链上永久地存储着。这些值存储在一个巨大的数组中，数组的长度为2^256，下标从零开始且每一个数组能够储存32字节(256个比特)长度的值。并且存储是稀疏的，并没有那么密集。

  • 知识点二：

    定长数组

        虽然规定了长度为5，但是实际上只用了4个，所以就只是用了四个bytes8的空间

  • 变长数组





Storage Address的由来 x=keccak_256(slot) slot是指数组长度存储的位置，此处对应的就是0

import sha3
import binascii
def byte32(i):
   return binascii.unhexlify('%064x'%i) #计算时需要进行填充

a=sha3.keccak_256(byte32(0)).hexdigest()
print(a)
#0x290decd9548b62a8d60345a988386fc84ba6bc95484008f6362f93160ef3e563

此后a[1],a[2]对应偏移1，2个插槽

然后我们在调用add()函数看，发生了什么

第一步改变了数组a的长度

第二步在a[2]后面的一个插槽写入0x66

  1. 在控制台执行await web3.eth.getStorageAt(instance,0)可以看到owner存储在slot 0插槽中，所以我们的思路是通过改变slot 0中的内容来改变owner值，而改变插槽的值的方式在该合约中只能通过改变数组值进行改变

  2. 为顺利进行后续操作，我们需要先给contact赋值为true，故先执行make_contact()函数

  3. 变长数组codex长度存放在slot 1中，故codex的实际内容存储在 keccak256(bytes32(1)) 起始的位置，计算该值

  4. 通过分析我们可以得知，因为总共有 2^256 个 slot ，要修改slot 0 ，假设 codex 实际所在 slot x ，(对于本题来说，数组的 slot是 1 , x=keccak256(bytes32(1))) ，那么当我们修改codex[y],(y=2^256-x+0)时就能修改slot 0 ，从而修改owner的值

  5. 而为实现第4步，要求y的值需要小于codex.length，而此时codex.length =0，但我们可以通过 retract()函数使 length 发生下溢，进而无论y取什么值，都能满足小于codex.length的条件

  6. 先完成步骤5之后，完成步骤4即可通关
