18. MagicNumber

解题步骤

创建合约的过程：

  1. 首先，用户或合约将交易发送到以太网网络。此交易包含数据但没有接收地址，则表明这是一个合约创建，而不是一个常规的发送或调用交易

  2. 其次，EVM 将 Solidity（高级语言）的合约代码编译为 bytecode（底层的机器语言），该 bytecode 直接转换为 opcodes ，在单个调用堆栈中运行

  • 需要注意的是：contract creation的 bytecode 包含两部分：initialization code 和 runtime code

  • 在创建合约期间，EVM 仅执行 initialization code 直到到达堆栈中的第一条 STOP 或 RETURN 指令，在此阶段，合约的 constructor() 会被运行，合约便有地址了

    • 在运行 initialization code 后，只有 runtime code 在堆栈上，然后将这些 opcode拷贝到 memory 并返回到 EVM

  • 最后，EVM 将 runtime code 返回的 opcode 存储在 state storage ，并与新的合约地址相关联，在将来对新合约的调用时，这些 runtime code 将被执行

    • 所以为了解决该题，我们需要initialization opcodes和runtime codes

    • initialization opcodes: 由 EVM 运行创建合约并存储将来要用的 runtime codes

    • runtime codes: 包含所需的实际执行逻辑。对于本题来说，这是应该返回的代码的主要部分，应该 return 42 并且 under 10 opcodes

      先看 runtime codes :

      • 其实在这一部分，只需要return 42;这一操作即可。而这一操作主要由两部分组成。

        • Tip1

          MSTORE：从栈中依次出栈两个值arg0和arg1，并把arg1存放在memory的arg0处

          SSTORE：从栈中依次出栈两个值arg0和arg1，并把arg1存放在storage的arg0处

        • Tip2

          PUSH1：把1个字节的数值放入栈顶

          PUSH2：把2个字节的数值放入栈顶

        1.首先是先将42 这个值存储在内存中，使用mstore(offset,value)将 42 存储在内存中（其中offset是在内存中的存储位置，value是十六进制值，42 的十六进制是 0x2a），如下面代码所示，42（0x2a）这个值将被存在0x40、0x50占据的32字节的地址空间中。

      0x602a     ;PUSH1 0x2a                  value
      0x6040     ;PUSH1 0x40                  offset
      0x52       ;MSTORE

      2. 然后，使用 return(offset, length) 返回 0x2a ，其中offset是值 0x2a 存储的位置，length是值 0x2a 存储所占的大小 0x20 ，一个slot占32字节

      0x6020     ;PUSH1 0x20                  length
      0x6040     ;PUSH1 0x40                  offset
      0xf3       ;RETURN

      所以 runtime codes 应该是 602a60405260206040f3 ，正好 10 opcodes


      再看 initialization codes

      • initialization codes 需要先将 runtime codes 拷贝到内存，然后再将其返回到 EVM 。

        CODECOPY指令，作用是把后续的内容拷贝到覆盖构造函数的内容，这样就做到了智能合约的构造函数只执行了一次。将代码从一个地方复制到另一个地方是 codecopy(destOffset，offset，length) 操作码。destOffset是代码的目标位置，offset是 runtime codes 的当前位置，length是运行时代码的大小，以字节为单位，对于 602a60405260206040f3 就是 10 bytes

      ;copy bytecode to memory
      0x600a     ;PUSH1 0x0a    length(runtime code size)
      0x60??     ;PUSH1 0x??    offset(current position of runtime opcodes)
      0x6000     ;PUSH1 0x00    destOffset(destination memory index 0)
      0x39       ;CODECOPY

      然后，需要将内存中的 runtime codes 返回到 EVM

      ;return code from memory to EVM
      0x600a     ;PUSH1 0x0a                      length
      0x6000     ;PUSH1 0x00                      offset
      0xf3       ;RETURN

      initialization codes 总共占了 0x0c 字节，这表示 runtime codes 从索引 0x0c 开始，所以 ?? 的地方是 0x0c

      所以initialization codes 最后的顺序是 600a600c600039600a6000f3

      综上，opcodes最后的顺序是 0x600a600c600039600a6000f3602a60405260206040f3

      执行步骤是：

      1. 创建10个opcode以内的合约

      2. 在https://rinkeby.etherscan.io/中找到创建合约的交易信息，获取生成合约的地址

      3. 将创建的合约地址存入solver值内即可通关



    解题代码


    1//创建10个opcode以内的合约
    2web3.eth.sendTransaction({ from: player, data: "0x600a600c600039600a6000f3602a60405260206040f3" }); 
    3//将创建的合约地址存入solver值内
    4await contract.setSolver(上一步生成的合约地址)
