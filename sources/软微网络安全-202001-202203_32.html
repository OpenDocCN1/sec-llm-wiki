9. King


题目描述

  • 当选国王，并使后来者无法再成为国王。

  • 题目合约代码如下：

pragma solidity ^0.6.0;

contract King {

  address payable king;
  uint public prize;
  address payable public owner;

  constructor() public payable {
    owner = msg.sender;  
    king = msg.sender;
    prize = msg.value;
  }

  receive() external payable {
    require(msg.value >= prize || msg.sender == owner);
    king.transfer(msg.value);
    king = msg.sender;
    prize = msg.value;
  }

  function _king() public view returns (address payable) {
    return king;
  }
}



解题步骤

  • 突破点是Solidity 中几种转账方式

    • address.transfer()如果异常会转账失败，抛出异常(等价于require(send()))， 回滚状态有gas限制，最大2300，防止重入

    • address.send()如果异常会转账失败，仅会返回false，不会终止执行有gas限制，最大2300，防止重入

    • address.call.value()()如果异常会转账失败，仅会返回false，不会终止执行无gas限制，无法防止重入

  • 三个方法的共同点：addr.transfer(1 ether)、addr.send(1 ether)、addr.call.value(1 ether)的接收方都是addr。

  • 当我们成为 King 后，如果有人出价比我们高，会首先把钱退回给我们，使用的是 transfer ，上面提到当 transfer 调用失败时会回滚状态，那么如果合约在退钱这一步骤一直调用失败的话，那么代码将无法继续向下运行，其他人也就无法成为新的 King，达到攻击效果

  1. 可通过await web3.utils.fromWei(await contract.prize())查看当前最高出价，为1 eth

  2. 部署一个新的合约，创建该合约时给该合约存入余额，合约中对应调用函数出价需大于等于当前最高出价（题为1 eth），且当收到转账时主动抛出错误，使无法完成收钱交易

Tip1：如果交易未成功的话，可以检查下是不是发起交易的gas费供给不足

Tip2：个人习惯在需要存入余额的合约中加入自毁函数，这样当合约代码有误时，还可以将转入合约的钱取回
