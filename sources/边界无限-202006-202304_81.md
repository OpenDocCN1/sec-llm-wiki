# 修复建议｜Log4j2 远程代码执行漏洞

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzAwNzk0NTkxNw==&mid=2247485034&idx=1&sn=fbe2911a209e53ad8cc5733d0aac14b8&chksm=9b772db8ac00a4ae0b937d2577aca825b0b2e9cfc2488c64df688343d8331a20884bfb3e406b&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzAwNzk0NTkxNw==&mid=2247485034&idx=1&sn=fbe2911a209e53ad8cc5733d0aac14b8&chksm=9b772db8ac00a4ae0b937d2577aca825b0b2e9cfc2488c64df688343d8331a20884bfb3e406b&scene=27#wechat_redirect)

     12月10日，边界无限安全攻防团队监测到 Log4j2 远程代码执行漏洞在 log4j-2.15.0-rc1 修复基础上被绕过，通过 Java JNDI 注入漏洞，只要外部用户输入的数据会被日志记录，即可造成远程代码执行。

       鉴于此漏洞危害巨大，利用门槛极低，边界无限安全攻防团队提供多种修复方案。

**修复方案**

**1**

**升级版本**

官方修复代码，目前尚未正式发布：

https://github.com/apache/logging-log4j2/releases/tag/log4j-2.15.0-rc2

  

优点：即下即用。

缺点：如跨过多版本升级可能存在兼容性问题，且不排除会有新的利用绕过。

**2**

**缓解措施**

1\. 添加jvm启动参数

\-Dlog4j2.formatMsgNoLookups=true；

2\. 在应用classpath下添加

log4j2.component.properties 配置文件，文件内容为log4j2.formatMsgNoLookups=true；

3\. JDK使用11.0.1、8u191、7u201、6u211及以上的高版本。  

  

优点：配置方便，缓解漏洞门槛低。

缺点：

1\. 需要重启业务，会导致业务中断。

2\. 可能导致日志输出流程存在异常，且 JDK 跨大版本升级可能导致业务兼容性等问题。

**3**

**产品解决方案**

**靖云甲·云原生安全防护系统**

针对 log4j2 漏洞推出定制化防护开源工具，支持 Java 应用程序在不重启的前提下，加载安全防护模块。

同时，靖云甲检测类型覆盖全面，抛弃了传统防火墙依赖请求特征的检测模式，除了可以抵御 Log4j2 漏洞利用攻击，还可以抵御未知的 Log4j2 JNDI 注入漏洞“变异”利用攻击，全方位保护用户的应用安全。

  

目前已支持 JDK 6-16 版本。

使用前请在测试环境下使用，确认稳定后，方可在生产环境部署。
