前言:众所周知，在护网中，防守方经常部署蜜罐，利用JSONP来获取攻击者的信息。蜜罐让很多攻击方不经意中就中招了，当我们在护网中发现一个蜜罐有没有办法戏耍他，甚至栽赃陷害其他攻击队呢？


1.什么是jsonp

说到jsonp不得不说跨域，跨越可以详见我之前的文章:跨那个域


    JSONP(JSON with Padding)是JSON的一种“使用模式”，可用于解决主流浏览器的跨域数据访问的问题。由于同源策略，一般来说位于 server1.example.com 的网页无法与不是 server1.example.com的服务器沟通，而 HTML 的<script> 元素是一个例外。利用 <script> 元素的这个开放策略，网页可以得到从其他来源动态产生的 JSON 资料，而这种使用模式就是所谓的 JSONP。用 JSONP 抓到的资料并不是 JSON，而是任意的JavaScript，用 JavaScript 直译器执行而不是用 JSON 解析器解析。


2.jsonp举例说明

前面一大段话简而言之就是同源策略是可以通过HTML标签进行绕过的，

直接举例说明(为了不被举报和引起争议，这里没用百度真实的JSONP，真实的可以自己去抓)

蜜罐:a.com百度账号:account.baidu.com


a.com需要请求account.baidu.com的数据。

account.baidu.com数据如下：

{"account": "xroot", "phone": "1xxxxxx","characteristic" : "帅"},{"account": "边界骇客", "phone": "1xxxxxx","characteristic" :"牛逼"},

蜜罐想请求百度账号的数据就在蜜罐网页中插入<script>进行交互：

<script src="http://account.baidu.com/account?Name=xroot"></script>

这样蜜罐就能得到访问者百度账号的数据的数据

parseResponse({"account": "xroot", "phone": "1xxxxxx","characteristic" : "帅"})

3.如何戏耍蜜罐，甚至栽赃其他红队

JSONP的原理前文已经提及了，但是要如何利用呢？不妨大家可以不用先急着看后文，先考虑一下，先放张图让大家乐一乐。

既然是蜜罐的原理是通过JSONP让你带着各大网站的COOKIE请求其他网站，从而获取你的个人信息。为啥我们不伪造各大网站吐一些假的账号信息给蜜罐呢？？？

如何伪造成各大网站呢？方法其实挺多的，最简单的就是改HOSTS文件或者DNS信息。

C:\Windows\System32\drivers\etc\hosts

把百度可以利用的JSONP地址指向我们可以控制的web服务器，这样配合上社工就可以吐任何信息给蜜罐了。

  1. 社工防守人员是谁，然后吐他们leader的account给他们

  2. 社工其他攻击队的攻击人员，挂个代理。疯狂吐他们的个人信息，其他攻击队不承认有用？？？
