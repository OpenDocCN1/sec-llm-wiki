前言：当我们一不小心拿下一台服务器或者个人机，为了扩大战果我们常常会对已有权限的机器进行信息收集，其中有一项就是收集账号密码。Linux因为文件比较单一，直接全盘搜关键字往往就能找到想要的账号密码或者KEY。Windows则不同，windwos往往会把明文密码与当前用户的秘钥进行一次或者多次的加密。

1.Windows惯用加密方式

Windows的惯用加密通常喜欢把明文加密成密文，再把密文根据当前用户的秘钥再进行一次加密，如windows的Security Account Manager (SAM),会把windows的ntlm hash通过syskey进行二次加密存储到sam数据库。这也是为什么把sam文件拿到其他机器进行解密会获得错误的ntlm_hash。

3.在各种情况下抓取密码（以chrome举例）

3.1.current user

这个没啥好说，直接运行脚本或者工具就行了。

3.2.administrator user

当我们获取的是超管用户权限的会话，比如说administrator希望拿到普通用户bob的chrome保存的密码，但是因为我们当前的秘钥是administrator的所以无法获取bob保存的密码，这时候我们就需要降权拿到bob的会话，然后再启动脚本或者工具，就可以抓到那个bob的chrome 密码了。

要获得bob的会话方法有很多，如

3.2.1进程注入

查看bob是否启动了某个进程或者服务，进行进程注入或者服务劫持，从而拿到bob的会话。

3.2.2当我们知道bob明文密码时

因为我们拥有用户名及密码直接spawnas/runas即可，当然你要远程登录也是可以的。

3.3.离线破解密码

离线破解密码必须是超管用户并且知道我们想抓用户的明文密码，我们只要拿到bob用户底下的chrome保存密码的加密文件，及bob用户的主秘钥。就可以把这两个文件拿到其他机子进行离线破解。

主秘钥位置:

%appdata%\Microsoft\Protect\sid(一串ID每个用户不一样)\*.*

Chrome密码加密文件:

%appdata%\Local\Google\Chrome\User Data\Default\Login Data

这里为了方便直接用nrisoft工具集的chromepass.exe
