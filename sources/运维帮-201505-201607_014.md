# 如何用精细化流量运营节省昂贵的带宽成本？

作者介绍：熊亚军，灵犀技术总监，原百度系统部高级项目经理，负责百度IT基础设施监控团队，其带领的团队经历了百度服务器规模迈入几十万量级，网络架构数次演进，对服务器尤其是网络层的监控和运维自动化智能化有丰富的经验。

  

对于IT运维/运营管理者来说，IT成本优化是一项很重要的KPI。

  

随着企业信息业务的不断丰富，数据大集中已经成为IT建设的趋势，在广域网带宽紧张、成本昂贵的情况下，解决带宽与业务之间的矛盾，构建快速、稳定、高质量的传输网络，保障关键业务传输质量，实现链路资源的充分利用，成为企业内部传输网解决方案的重要组成部分。以超级互联网公司而言，业务为了保证用户的访问质量，会将业务部署同时部署在不同的地区，导致许多业务跨地区传输的情况。随着业务的增多以及访问量的加大，公共传输（带宽）资源面临网络质量下降的风险。传输扩容是解决上述情况的最佳手段，但是带来的高昂的带宽成本是许多公司无法承担或认为其收益比低下的情形。

  

本文将给大家介绍在企业内部传输网络架构上，如何通过流量精细化运营提升在固定带宽资源、多业务环境下带宽资源利用率。

  

# **数据集中式管理网络架构带来的问题**

  

对于大数据型的公司，以下是常见的数据集中式网络架构图。从数据源到中央存储/计算中心、从中央存储/计算中心到服务端都需要大量的带宽资源，承载这部分带宽资源的叫做企业内部传输网。从服务端到用户也需要大量的带宽资源，承载这部分资源的叫做公共传输网。企业内部传输网通常都是由企业自身建设并维护管理，这个网络在不同企业的实现会有较大差异。公共传输网是由运营商来建设并维护的，这个网络对不同企业的相对是一致的。

  

![](../Images/08843918f2f4689ffe6b081b28aa9c0b.png)  

  

企业内部传输网通常作为一种共享资源，不同业务线可以同时使用，在有限的带宽资源下，随着业务的传输需求快速增长势必会带来资源竞争的情况，恶性的资源竞争终究导致资源使用过度，网路传输质量下降。在解决资源竞争过程中，通常会有以下几个难题：

1、缺乏统一的带宽预算模型，到底需要多少资源？

2、缺乏统一的带宽监控手段，资源都是谁在用？

3、缺乏统一的成本分摊机制，资源成本都该算在谁的头上？

#   

# **如何应对？精细化流量运营帮您出招！**

  

带宽资源的管理通常可以分为：规划、建设、交付、监控4个阶段，以下是以运营为核心的带宽资源管理生态图。

  

![](../Images/3b53f94f05a7563b2485c3e0df4c4850.png)  

*   规划：确定需要多少资源
    
*   建设：确定资源怎么落实
    
*   交付：确定资源按需分配
    
*   监控：确定资源合理使用
    

  

资源交付完成后，对资源使用的监控是让资源合理使用、缓解资源竞争冲突最重要的一个环节，也是整个带宽资源精细化运营的核心。监控分为监测、控制两个部分，通过精准的监测、智能的调度，可以让资源利用最大化，以下是以带宽为为核心的网络带宽资源管理模型。

  

![](../Images/d1fb0d49573e12c3d5dec6cbc10ad533.png)  

带宽资源管理模型分为：查询、申请、试用、反馈、降速、回收6个部分，各个部分的作用如下：

*   查询：动态收集可用的带宽资源
    
*   申请：实时/提前申请需要的带宽资源
    
*   试用：根据申请按期使用带宽资源
    
*   反馈：记录带宽资源详细的使用情况
    
*   降速：动态应对带宽资源竞争的问题
    
*   回收：带宽资源试用完毕回收再利用

# **流量调度？带宽精细化管理系统架构**

  

  

![](../Images/3f61275055c9085079849af9bb466b46.png)  

  

在以上管理系统中，控制手段可从业务、网络两个维度进行调度控制。  

1、  业务层的调度

  

![](../Images/1e829ccb03e221a51ab914ec18324266.png)  

  

业务层的调度主要针对应用程序进行网络请求的控制，如上图所示，应用程序在需要发起网络任务时，先向TK调度系统进行资源预申请，预申请通过，TK调度系统会向Kylin流量分析系统查看目前可用的网络资源，TK通过控制应用程序的网络请求量（例如对wget类型的网络请求，可以控制wget并发任务的数量或者控制wget的下载速度）。在带宽资源充足的情况下，提高应用程序的网络请求量；反之在带宽资源不足的情况下，降低应用程序的网络请求量。  

  

2、  网络层的调度

  

![](../Images/190291376c26415b66918df3a75fc292.png)  

  

网络层的调度主要针对网络资源本身提供动态的承载能力，如上图所示，某业务需要1条从机房A到机房B的10G专线，可以通过Kylin调度系统往核心网A、机房A、机房B的对应网路设备发出控制指令（例如路由调整），建立起1条从机房A到机房B的专线。业务的资源需求使用完毕，通道Kylin调度系统用类似的方式，撤销专用链路，回收资源。  

  

# **精细化流量调度的策略**

  

传统的带宽管理是面向资源的，一般通过简单的限速策略来解决带宽资源有限和多业务资源竞争的冲突，这种方法一定程度上可以解决传输的拥塞问题，但是针对多元业务差异化的场景，操作起来不够灵活，管控粒度也粗。而一套先进的精细化流量管理生态圈应该是面向业务，在保证业务的多元化以及可靠传输基础之上实现带宽资源的充分利用。接下来，我们来看看在某超级互联网公司，针对精细化流量调度策略的具体实践。

  

宏观上，通过对带宽峰值、谷值和均值使用率的分析，我们可以发现明显的传输特性，即峰值使用率达到90%，其均值使用率一般在50-60%左右，这意味着带宽的真实使用率存在较大的提升空间，通过”削峰填谷”可以实现最大程度的带宽利用率。

  

微观上，我们会将业务划分为在线业务、离线业务、默认业务三大类流量，其中在线业务是指直接与用户进行交互的流量；离线业务是指支撑在线业务的离线集群计算流量，一般是带宽资源的主要使用者，而这部分流量有时效性敏感度低，可调度性强的特性，是流量调度的重点管控目标；默认业务是指内部非在线、离线的其它业务流量。

# **收益评估**

  

通过在某超级互联网公司内部传输网的实践，我们得出了以下收益：

  

首先，高优先级的任务得到保障，带宽上限得到控制，带宽成本得到有效的控制；

  

其次，削峰填谷，在流量高峰期，减少离线业务传输任务，在流量低峰期，则增加离线业务传输，最终提高了整个链路的带宽利用率；

  

最后，针对业务传输任务进行审计，能够快速定位拥塞源，同时对历史用量数据的分析，可以为机房扩容和业务部署优化提供参考。

  

总而言之，企业内部传输网在应对资源竞争的三个问题得到有效的解决：

A、有了统一的带宽预算模型，到底需要多少资源已不是问题；

B、有了统一的带宽监控手段，资源都是谁在用，用来做什么已经了如指掌；

C、有了统一的成本分摊机制，资源成本都该算在谁的头上，账单清楚明白。
