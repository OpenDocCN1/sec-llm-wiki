听说你写的代码跑得贼慢，是手脚不利索，还是又写bug啦~ 在计算机科学中，算法的时间复杂度（Time complexity）是一个函数，它定性描述该算法的运行时间。这是一个代表算法输入值的字符串的长度的函数。  

想必大家都听过下面这么一段话，但要把这个当真理，那恐怕很容易写出效率不高的代码。

![](../Images/8fafbdbd03cce6ee652d57ae123dd353.png)

> 在编程过程中，不同的数据代表着不一样的作用，并且他们的执行效率也会不一样。

## 0x00 大O表示法 

大O符号，又称为渐进符号，是用于描述函数渐近行为的数学符号。更确切地说，它是用另一个函数来描述一个函数数量级的渐近上界。使用这种方式时，时间复杂度可被称为是渐近的，亦即考察输入值大小趋近无穷时的情况。

这里简单通过一张图来说明下他们的关系。

![](../Images/48fd76097e773a5cebdb19abca2225b1.png)

而后我们将逐一介绍`python3`中的常见对容器的操作效率之分。

> 列表应该是我们用到最为频繁的对象类型了

| len(l) || O(1) |
| l.append(5) || O(1) |
| l.pop() || O(1) |
| l.pop(-1) || O(1) |
| l = \[\] || O(1) |
| l.clear() || O(1) |
| l\[a:b\] || O(b-a) |
| l.extend(...) || O(len(...)) |
| list(...) || O(len(...)) |
| l.insert(1) || O(N) |
| l.pop(i) || O(N) |
| l1 == l2 || O(N) |
| l\[a:b\] = ... || O(N) |
| del l\[i\] || O(N) |
| x in/not in l || O(N) |
| l\[:\] || O(N) |
| l.copy() || O(N) |
| l.remove(...) || O(N) |
| min(l)/max(l) || O(N) |
| l.reverse() || O(N) |
| for v in l: || O(N) |
| l.sort() || O(N Log N) |
| k\*l || O(k N) |

## 0x01 Set集合 

> 大部分set操作的时间复杂度都为O(1)

| 案例 || 类型 |
| --- | --- |
| len(s) || O(1) |
| --- | --- |
| s.add(5) || O(1) |
| x in/not in s || O(1) |
| s.remove(..) || O(1) |
| s.discard(..) || O(1) |
| s.pop() || O(1) |
| s.clear() || O(1) |
| s = set() || O(1) |
| set(...) || O(len(...)) |
| s != t || O(len(s)) |
| s <= t || O(len(s)) |
| s >= t || O(len(t)) |
| s | t || O(len(s)+len(t)) |
| s & t || O(len(s)+len(t)) |
| s - t || O(len(s)+len(t)) |
| s ^ t || O(len(s)+len(t)) |
| for v in s: || O(N) |
| s.copy() || O(N) |

相比 `list`中的 `in/not in` 判定方法 , `set`可以更快

> 可以看到大部分的dict操作也是O(1)

| 案例 || 类型 |

| --- | --- |

| len(d) || O(1) |
| del d\[k\] || O(1) |
| d.get(k) || O(1) |
| d.pop(k) || O(1) |
| d.popitem() || O(1) |
| d.clear() || O(1) |

| d = dict() || O(1) |
| d.keys() || O(1) |
| d.values() || O(1) |

| for k in d: || O(N) |

## 0x03 deque双向队列 

> 这个东西有点像list 但显然比list好用多了

| 案例 || 类型 |
| --- | --- |
| dq.copy() || O(n) |
| --- | --- |
| dq.append(5) || O(1) |
| dq.appendleft(1) || O(1) |
| dq.pop() || O(1) |
| dq.popleft() || O(1) |
| dq.extend(k) || O(len(k)) |
| dq.extendleft(k) || O(len(k)) |
| dq.rotate(k) || O(len(k)) |
| dq.remove(1) || O(n) |

`dq.appendleft(1)` 和 `list.insert(0,1)` 的操作类似，都是在首部插入一个元素，但前者的速度比后者的`O(N)`快很多。

当然，类似`item in/not in set(list)`这样的操作并没有多大的意义，在时间复杂度上任然是`O(len(list))`。即便`set`的成员对象判断上为`O(1)`,但把`list`转换为`set`的过程已经是个取决于`list`长度的操作了。
