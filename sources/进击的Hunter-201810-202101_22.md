### 前言

在使用** `trio`**编写并发脚本的过程中，我们不用担心遇到线程过多与进程超标的问题，因为他使用的是单线程，可以在节省资源的同时提供惊人的效率。

今天我们遇到了这样一个**坑**，当并发量过大时，会出现如下错误。

![](../Images/27630cae697b0f833294efa8c2eaa8ac.png)

为啥呢。。这里显示了 `Toomany open files`，也就是打开的文件过多。

经过一番查阅(**Baidu**与**Google**)，我们得到了以下解决手法。

### 查询限制

```
1.  `ulimit -a`
    
```

在输入了如上命令后，我们得到了下图回显，可以看到我们的 `open files` 也就是最大文件描述符打开数被限制在了**1024**

> `unlimited` 代表无限制

```
1.  `# centos 环境下，主要标出本文有用的参数，具体阅读后续。`
    
2.  
    
3.  `core file size          (blocks, -c) 0`
    
4.  `data seg size           (kbytes, -d) unlimited`
    
5.  `scheduling priority             (-e) 0`
    
6.  `file size               (blocks, -f) unlimited`
    
7.  `pending signals                 (-i) 5906`
    
8.  `max locked memory       (kbytes, -l) 64`
    
9.  `max memory size         (kbytes, -m) unlimited`
    
10.  `open files                      (-n) 1024             # 最大文件描述符数`
     
11.  `pipe size            (512 bytes, -p) 8`
     
12.  `POSIX message queues     (bytes, -q) 819200`
     
13.  `real-time priority              (-r) 0`
     
14.  `stack size              (kbytes, -s) 10240`
     
15.  `cpu time               (seconds, -t) unlimited`
     
16.  `max user processes              (-u) 5906             # 最大进程数`
     
17.  `virtual memory          (kbytes, -v) unlimited`
     
18.  `file locks                      (-x) unlimited`
     
```

我们可以通过编辑 `/etc/security/limits.conf` 文件来解锁限制。

> 非root权限下open files最大4096
> 
> 临时修改方式过于鸡肋这里暂不赘述

### 修改配置

在末尾添加的命令格式如下，详见 limits.conf

```
1.  `<domain> <type> <item> <value>`
    
```

*   **domian** 使用者
    

*   `username` 用户名
    
*   `groupname` 用户组
    
*   `*` 通配
    
*   ...
    

*   **type** 限制类型
    

*   `hard` 硬件限制
    
*   `soft` 软件
    
*   `-` 通配
    

*   **item** 配置项
    

*   `core` 限制核心文件大小
    
*   `data` 最大数据大小
    
*   `fsize` 最大文件大小
    
*   `memlock` 最大锁定内存
    
*   `nofile` 最大打开文件描述符数
    
*   `rss`
    
*   `stack` 最大堆栈
    
*   `cpu` 最大CPU时间
    
*   `nproc` 最大进程数
    
*   `as`
    
*   `maxlogins` 指定非root用户的最多登录次数
    
*   `maxsyslogins` 指定非root用户的最多登录总和次数
    
*   `priority`
    
*   `locks` 最大锁数
    
*   `sigpending`
    
*   `msgqueue`
    
*   `nice`
    
*   `rtprio`
    

*   **value** 设置值（ `-1`, `unlimited`, `infinity` 为无限制 ）
    

于是我们打开该文件并在末尾加上如下配置并重新打开终端。

```
1.  `* - nofile 20480`
    
```

### 修改结果

首先我们输出下配置结果

![](../Images/4af49bddf5d45f205479684159731e06.png)

  

并且我们可以通过如下命令来统计**目标进程( `pid`)**所打开的文件描述符总数来进一步验证。

```
1.  `# 单次查询`
    
2.  `lsof -p [pid]|wc -l`
    
3.  
    
4.  
    
5.  `# 循环输出,替换name即可`
    
6.  `for _ in {1..100};do echo $(lsof -p $(ps -ef|grep [name]|grep -v grep|awk '{print $2}')|wc -l);done`
    
```

最后我们运行两者，可以看到，限制已经突破了1024！
