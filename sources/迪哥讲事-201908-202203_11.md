## 背景

今天的这位小哥的名字叫做0xn3va, 目前在hackerone的gitlab的bbp上面排名第18,到目前为止一共提交了8个有效漏洞,看来很“容易”啊,好了，进入正题,下面来简单概要一下这个漏洞:(想要了解gitlab的WebIDE的，可以看看这个视频) 当你在WebIDE的`/-/ide/project/<full_project_path>`路径下打开一个项目时，IdeController会使用以下方法搜索这个项目:

```


  def project  
```

搜索的结果是内部使用`IdeHelper.ide_data`这个函数:

```


module IdeHelper  
```

`'project'`的值被放到`app/views/ide/_show.html.haml`模板中了,由于`IdeController.project`并没有检查`/-/ide/project/<full_project_path>`的权限, 所以私有项目的信息被泄露了;

## 复现步骤

1.以user1的身份登陆;

2.建立并初始化一个私有项目;

3.以user2的身份登陆；

4.跳转至` /-/ide/project/<user1>/<private-project>`这个接口;

5.打开页面来源并通过`data-project=`这个关键字找到项目数据; 注意:第五步可以通过以下操作来完成:`$ curl -b '_gitlab_session=<user2-session>' 'https://gitlab.com/-/ide/project/<user1>/<private-project>/' | grep "data-project=" `看到的界面如下所示:
