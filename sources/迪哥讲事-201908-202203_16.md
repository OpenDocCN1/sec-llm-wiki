## 复现步骤

1.作为受害者，创建一个公共项目.

![](../Images/a6c6730658bcfd8af25473ebb21baaab.png)

2.在此项目上创建一个合并请求;

![](../Images/c21e619ec93766661557efe1745578f7.png)

3.通过GraphQL API资源管理器查找MR的object ID。你测试的时候将fullPath替换为你的。

![](../Images/4c898583e978a8a9af832d3fe8ffaab0.png)

```


{  
```

4.在MR中添加一个Confidential note。我们再次使用GraphQL API。将noteableId替换为您在上一步中获得的id。

![](../Images/98b1d8e78ff2be9c4266f0bc051b90bb.png)

5.通过浏览MR并刷新页面，确认已将Confidential note添加到MR中。

![](../Images/176a32bce4baeeb65c9fc7b4987dfb80.png)

6.测试的时候你可以作为攻击者(同时不是项目的成员)，访问MR并确认一下是无法查看Confidential note的。

![](../Images/db722ec6b0f779e137d26a5bd2161f4a.png)

7.作为攻击者，请浏览受影响的项目`https://gitlab.com/victimuser/projectname.atom`的RSS feed，并确认您可以阅读受害者创建的Confidential note。

![](../Images/154fdfb1f11eea361a1a6119a295d8fc.png)

8.通过curl调用受影响项目的RSS feed，确认你可以作为未经身份验证的用户查看Confidential note。

```


$ curl -s https://gitlab.com/naaytesting2/h1testpublicproject.atom | grep confi  
```
