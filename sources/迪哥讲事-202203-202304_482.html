gitlab漏洞系列-使用未经验证的电子邮件地址绕过Require Code Owner approval机制

背景

vaib25vicky小哥于2021年6月提交了这个漏洞: 当将地址映射到Gitlab用户名时，CODEOWNERS文件允许未经验证的电子邮件地址。如果CODEOWNERS文件包含没有关联Gitlab帐户的电子邮件地址时，那么 攻击者可以将该电子邮件地址添加到他们的帐户中，并成为代码所有者。这允许攻击者绕过受保护分支的“Require Code Owner approval”机制。

相关细节

受保护的分支有这么一条规则: 允许项目所有者限制谁可以推送并合并到分支 其中一条规则是“Require Code Owner approval”;

“Code Owner file”是一个文件，这个文件意味着:在合并请求批准后，代码可以推送到受保护的分支; 这个批准适用于每个人，包括项目的维护者;

Code Owner file语法允许用用户名和电子邮件定义成员: https://docs.gitlab.com/ee/user/project/code_owners.html#the-syntax-of-code-owners-files

* [@]default-codeowner

###  We can also specify "multiple tab or space" separated codeowners:  
* [@]multiple [@]code [@]owners  email_address@owners

###  Rules defined later in the file take precedence over the rules  
*.rb [@]ruby-owner  

创建代码所有者文件(Code Owner file)后，Gitlab将用户名和电子邮件地址映射到Gitlab帐户。然而，电子邮件验证并没有检查，这允许恶意用户可以模拟为有效的不同代码所有者用户，并绕过代码所有者机制：

复现步骤

代码所有者是高级功能，所以你得选择免费试用的模式; 1.跳转至Group > Settings > Billing ,而后开始试用;

2.假设项目名为h1-project

3.增加3个成员- A-main(维护者)，B-dev, C-dev(开发者)

4.添加一个readme 文件

5.添加一个CODEOWNERS文件

*.md [@]A-main  h1-test@dontexist127.com

6.转到项目设置https://gitlab.com/<namespace>/<h1-project>/-/settings/repository 然后编辑你的主保护分支设置，如图所示

绕过Require Code Owner approval机制

代码所有者文件清楚地声明对*.md的更改。Md文件需要得到[@]A-main和h1-test@dontexist127.com批准 在合并和推之前

  • C-dev添加电子邮件h1-test@dontexist127.com到他的帐户，这是一个未经验证的电子邮件

  • B-dev编辑README文件。并创建了一个新的合并请求

  • C-dev进入合并请求页面，现在他可以很容易地批准和合并

将代码以C-dev的形式传递给受保护的分支，而C-dev不是文件的代码所有者
