1

背景描述


远程桌面协议（Remote Desktop Protocol，RDP）是一种由微软公司实现的支持通过图形化界面进行远程连接的多通道协议。与远程桌面协议兼容的客户端可在多种操作系统上运行，大部分的Windows系统已内置其客户端软件，远程桌面协议的服务器端安装在Windows系统中，默认情况下通过监听TCP 3389端口的数据对客户端的请求进行处理。



2019年5月14日，微软官网发布了一批安全更新补丁，其中修复了一个针对远程桌面服务的远程代码执行漏洞（CVE-2019-0708），该漏洞影响了部分旧版本的Windows系统。未经身份验证的攻击者可以通过RDP连接到目标系统并发送特制请求，即可实现在目标系统中执行任意代码。



虽然目前暂未在网上发现该漏洞公开的利用代码，但是由于此漏洞属于预身份验证，整个过程中无需用户交互，这意味着攻击者可以利用该漏洞实现蠕虫式攻击，含有此漏洞利用代码的恶意软件可能会被从受攻击的计算机传播到受影响的计算机，其传播方式与2017年Wannacry恶意软件在全球传播的方式类似。

该漏洞涉及操作系统数量多，影响面广，迪普科技在此提醒广大受影响用户及时防范，及时更新补丁。


2

漏洞描述



远程桌面服务（以前称为终端服务）中存在远程代码执行漏洞，攻击者在未经身份验证的情况下通过RDP向目标系统的远程桌面服务发送经过特殊处理的请求时，即可在目标系统中触发该漏洞，此漏洞无需用户交互便可以在目标系统上执行任意代码。攻击者可以在目标系统安装程序、查看、更改或删除数据，或创建具有完全用户权限的新帐户。

解决方案

1、官方解决方案

目前，微软已经发布针对该漏洞的安全更新补丁，请使用上述受影响的操作系统用户及时更新：

1）  针对Windows XP，Windows 2003系统的补丁：    https://support.microsoft.com/en-us/help/4500705/customer-guidance-for-cve-2019-0708

2）  针对Windows 7，Windows Server 2008 R2，Windows Server 2008系统的补丁：

https://portal.msrc.microsoft.com/en-US/security-guidance/advisory/CVE-2019-0708


2、临时解决方案

1）关闭远程桌面服务，防止非法用户连接。

2）开启网络级别身份验证（NLA），此方案适用于Windows 7, Windows Server 2008,Windows Server 2008 R2。

3）暂时性修改RDP的TCP端口或在主机防火墙中配置阻断，默认端口为3389。

4）使用ACL对RDP的访问来源进行限制。

5）使用RDP网关，网关的功能是安全的将流量从远程客户端传递到本地设备。使用RDP网关可以防止或最小化远程用户访问，并使组织能够更好的控制用户角色，访问权限和身份验证需求。
