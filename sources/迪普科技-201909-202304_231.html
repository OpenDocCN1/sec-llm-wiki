一、背景描述

SSL是Secure Sockets Layer（安全套接字层协议）的缩写，其目标是保证两个应用间通信的保密性和可靠性,可在服务器端和用户端同时实现支持。目前SSL协议已经成为Internet上保密通讯的工业标准。OpenSSL 是用于传输层安全性 (TLS) 和安全套接字层 (SSL) 协议的商业级和功能齐全的工具包。

2021年8月24日，OpenSSL发布了OpenSSL 1.1.1l，该版本修复了一个高危漏洞：CVE-2021-3711，该漏洞影响OpenSSL 1.1.1l之前的所有包含SM2商密算法版本。业界一些基于OpenSSL改造过的商用国密算法版本也可能受该漏洞影响。

由于OpenSSL使用的广泛性，迪普科技建议相关用户及时进行修补更新，做好相关防护措施。


二、严重等级

高危


三、漏洞描述

该漏洞是由于SM2算法EVP_PKEY_decrypt函数存在安全问题。在实际应用中，一般会调用两次这个函数用来解密：第一次调用EVP_PKEY_decrypt时，“out”参数传 NULL，“outlen”参数会返回存放解密结果所需的缓冲区大小，在分配足够的缓冲区后，再次调用 EVP_PKEY_decrypt，这次”out”传递的是第一次调用所分配的缓冲区。

问题存在于返回“outlen”值的sm2_plaintext_size函数中：

*pt_size（即“outlen”） = msg_len - overhead

msg_len指整个加密后的数据长度，overhead = 10 + 2 * field_size+(size_t)md_size，其中overhead的计算受到了SM2公钥加密后的ASN.1数据结构的影响，最终导致了本漏洞的触发。

SM2密文格式（ASN.1）

overhead的计算公式中：10是选择 SM2 密文 ASN.1 编码引入的长度的最小值，2 * field_size表示x、y分量的长度，由于XCoordinate 和 YCoordinate在加密过程中若要满足指定方程，通常都是占位 32 字节的大数，因此在公式中field_size固定为32，md_size是SM2密钥中的一个值，固定为32，所以onerhead在函数中是固定值106（10+2*32+32）。

但实际上由于XCoordinate 和YCoordinate是加密过程中基于随机数计算出的椭圆曲线点的X坐标和Y坐标，存在一定可能性占位小于32字节，当这种情况发生时，真实的 overhead 可能小于106，即实际解密结果占位>（msg_len - 106），此时用固定值106计算出的“outlen”去分配空间，会导致分配的空间小于解密后的结果，在第二次调用EVP_PKEY_decrypt时，“out”所分配的缓冲区大小不足以存放解密结果，导致缓冲区溢出。

注：以OpenSSL 为基础的国密SM2算法会受到该漏洞的影响，而自行实现的国密算法则不会受到该漏洞的影响。


四、影响范围

OpenSSL 1.1.1-1.1.1k

迪普科技全线产品不受该漏洞影响


五、解决方案

// 检测方法

查看系统版本是否在受影响版本内命令：

openssl version


// 官方解决方案

官方目前已发布解决上述漏洞的安全补丁，请及时升级到1.1.1l，官方补丁下载可以参考以下链接：

https://www.openssl.org/source

https://github.com/openssl/openssl/releases/tag/OpenSSL_1_1_1l


// 迪普科技解决方案

迪普科技安全研究院监测到OpenSSL缓冲区溢出漏洞后，迅速采取了应急措施。

1、使用迪普科技“慧眼安全检测平台”检测现网环境中是否存在OpenSSL缓冲区溢出漏洞。

2、迪普科技安全服务团队可协助客户完成现网使用Openssl服务的资产风险评估，针对网络安全入侵事件，提供快速应急响应支撑服务以及专业的安全建设建议。
