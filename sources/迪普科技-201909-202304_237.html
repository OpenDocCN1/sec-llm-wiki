一、背景描述

迪普安全研究院近期收到某局点客户上报：服务器出现高CPU占用现象，排查发现存在进程名为“xmr”和“work64”的特殊进程，疑似挖矿行为。经分析得知，该挖矿家族被命名为WorkMiner，利用SSH爆破进行传播，影响范围广泛。迪普科技提醒相关用户提高警惕，做好相关防护措施。


二、传播途径

通过对WorkMiner的分析发现，该家族采用了SSH爆破的方式来完成传播。通过对函数名的分析发现，WorkMiner中存在一个名为“_home_haha_work_go_sshworm_work”前缀系列的函数，通过名字可以得知这就是SSH爆破的攻击方式。

通过对攻击流量的捕获，进行流量过滤发现了SSH相关攻击包，

并且发现同时针对多个IP的SSH爆破。


三、影响系统

WorkMiner挖矿家族由go语言编写，理论上支持全linux平台挖矿。

四、挖矿复现

1．挖矿样本由Go语言编写，附带相关符号信息，包括系统调用和自定义攻击SSH攻击函数，且配置文件中内置矿池地址。

2．Work64在tmp目录释放挖矿程序和相关配置文件。

3．在/etc/crontab和/var/spool/cron/crontabs/root设置相关计划任务。

4．修改防火墙策略，端口不固定，测试时已出现多个端口。


五、解决方案

// 清理方案

1．清除相关挖矿xmr和work64/work32进程。

2．清除位于/tmp目录下的xmr挖矿文件和相关config.json、auth.sh、和secure.sh等配置文件。

3．清除位于/var/spool/cron/crontabs/root和/etc/crontab中的计划任务。

4．还原/usr/bin/curl1和/usr/bin/wget1为usr/bin/curl和/usr/bin/wget。

// 加固方案

建议将SSH密码设为强密，即长度大于12位以上，包含大小写，数字和特殊符号。不建议设置为连续字符。

// 迪普科技解决方案

迪普科技安全研究院监测到WorkMiner病毒后，迅速采取了应急措施。

1、迪普科技安全服务团队可协助客户排查系统病毒感染情况，评估网络病毒措施有效性，并指导客户进行病毒监测、预警、处置等闭环建设管理。

2、使用迪普科技“网络安全威胁感知大数据平台”或“高级威胁检测系统”检测现网环境中是否存在WorkMiner病毒的感染行为。
