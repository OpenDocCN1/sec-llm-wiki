# 0x3 加密分析

从加密结果可知 无论我们输入的长度多长 都输出固定长度密文

那可以猜测这可能是一个哈希加密

而且输出的密文长度为40 可以猜测这是一个`SHA1`

那先拿到一份py的SHA1实现

> github:https://github.com/alex-a-robinson/SHA1/blob/master/sha1.py

这是SHA1的一个加密流程![](../Images/6d2321d05b39f33e255cd9e784c2e4aa.png)

从中可以知道一个SHA1会经过20+20+20+20=80轮的加密 而且ABCDE贯穿了整个加密 最终得到一个40位的结果

ABCDE对应的就是魔数 每20轮对应的不同的K值 所以要判断这是不是一个SHA1只需要找到这些值就可以了

根据搜索 可以判断这是一个SHA1![](../Images/b73391e5e5bc831c7b7e7497ea483f01.png)

那主动调用加密`123456`和正常的sha1对比发现结果不一致![](../Images/38f1fd4ee61580bb2d9237b0085bc180.png)![](../Images/55a196c6bdfe0631d00d97a980f07e81.png)

那猜测就是有魔改 从这里可知是从`x0`里取出魔数![](../Images/b742f69258c3c40232fb689c26262791.png)

debugger onsole看`x0`![](../Images/442ba1ee59863219b177bc41b91de704.png)

01 23 45 67 →`0x67452301`

89 AB CD EF →`0xefcdab89`

FE DC BA 98 →`0x98badcfe`

7C 1F 4A 5E→`0x5e4a1f7c`

76 54 32 10→`0x10325476`

原本的魔数为`0x67452301`, `0xefcdab89`, `0x98badcfe`, `0x10325476`, `0xc3d2e1f0`

从这里可以看到后俩个魔数被更改了 手动更正魔数运行看结果![](../Images/ea3f76ef5eba445efb582c228b924973.png)

看来不仅仅更改了魔数 存在其他魔改

从前面可知 SHA1存在80轮加密 那我们手动输出80轮加密的每个结果 对比tracecode不就行了

![](../Images/daccef66df55c1e1724f4b0cb3c4feb2.png)

根据对比每轮的结果发现在第16轮的时候开始出现不同![](../Images/b4a3bebe046203e023d197ee31bf4cad.png)

前15轮的K值为`0x5A827999`![](../Images/d8ea7999237be553a2714fa686bffa7d.png)

在第16次循环的时候就将K值提前换成`0x6ED9EBA1`![](../Images/bdc9c06472e29727378c3ccd9b2e8aac.png)

搜索`0x6ED9EBA1`出现4次![](../Images/ee038977f815a1c1d23ae6677da8ab61.png)

验证结果![](../Images/6c6a5e4cf7fbb6996f7ea92ffc048955.png)![](../Images/30f0b1538bbf3d82aa459e3f6d0421ad.png)

按照这个思路接着看第20轮往后到39轮使用的K值为`0x8F1BBCDC`![](../Images/c6d5eaa324ca110aaa3b61a286cb8dfd.png)

第40轮开始又用回K值为`0x5A827999`![](../Images/fba194033759a9c31faaf764dc8c3085.png)根据tracecode可知这区间又出现EOR又AND可知 这里的计算方式和前16轮一致 K值也一致

搜索`0x5A827999`可知一共出现了36次 减去前16轮 所以后面又使用了20轮![](../Images/0b3e183a16aa49db9069e52a0bfccb75.png)

在60到79后跟原代码一致![](../Images/c9967af7997fc853c723308da75c4752.png)

所以算下来一共分为 16+4+20+20+20=80轮

```
if i <= 15

:0x5A827999
elif i <= 19

:0x6ED9EBA1
elif i <= 39

:0x8F1BBCDC
elif i <= 59

:0x5A827999
else

:0xCA62C1D6

```

验证结果发现并不完全一致 到底是哪里的问题![](../Images/9c0b5403580e4e38e5056a2894f7cf1a.png)

根据错误位置 输出`h2` `h3`和`c` `d`的值![](../Images/14e8b5ffb89dc6fe3ba84f5c5814e399.png)

回到tracecode搜索![](../Images/2cce8727266ede93dd13329f89cd6c45.png)![](../Images/9bcd26cd899a1edd81a7b853b36a198a.png)

从这里就可以看到`0xee9397da`与之相加的是`0x5e4a1f7c` 而`0x2ee2fec3`与之相加的是`0x98badcfe`

也就是需要将`c`和`d`的位置互相调换![](../Images/b6d34de9f3756aa64e06c5498174385b.png)

最后拼接得到结果![](../Images/aa1dc871abc4a7a7f63d1673111e6abd.png)
