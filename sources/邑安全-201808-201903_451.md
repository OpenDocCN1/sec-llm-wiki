## 神秘的交易

参考资料：  
https://bbs.pediy.com/thread-151259-1.htm  
https://www.waitalone.cn/security-hardware-usb.html  
下载Saleae Logic 分析软件分析截获的logicdata数据包：

![](../Images/19b46d75086dd1ae8ce9bc9e48cb4f71.png)

clk栏为时钟电平，data栏为数据电平。

每个指令都在时钟高电平时数据下降沿后开始，数据从低位到高位的顺序发送。发送的命令格式为 一个字节指令类型 一个字节地址 一个字节数据，然后时钟高电平数据电平上升沿代表本次命令结束。我们关注的指令类型为0x33，用于校验口令。发送命令格式为  
`0x33 0x01 s1`  
`0x33 0x02 s2`  
`0x33 0x03 s3`  
其中s1 s2 s3拼在一起就是那三个字节的口令了.  
在下图方框部分可以找到校验口令：

![](../Images/cb748066ea968d00695add5200aceef1.png)

放大后三条命令分别为：

![](../Images/7def0d530a8f2c9ceaf5863c0f2a634d.png)

![](../Images/2d02aec30da5fde85374aa392d296632.png)

在时钟电平为高电平时对应的数据电平高低位分别表示1和0，且数据按从低位到高位的顺序发送，因此三调指令分别为：  

0x33 0x01 0x40  
0x33 0x02 0x31  
0x33 0x03 0x10  
因此三个口令为 0x40 0x31 0x10

> flag：SCTF{403110}

## 被动了手脚的数据

题目提示了数据，这里使用了一款工具modbus-cli（https://github.com/tallakt/modbus-cli ）接收modbus协议的数据。用法如下：

![](../Images/0821782041574e46d1e7ba9e28176bcc.png)

这里尝试读取1000字节的数据，由于每次读取数据长度太长会导致timeout，因此每次只读取50字节，写个脚本如下：

```
#!/bin/bashstart\=400001offset\=50for ((i\=$start; i<\=400001+1000; i+=50))  do
    modbus read --modicon 116.62.123.67 $i $offset
    sleep 1done
```

在跑出来的结果中，发现在400300-400331地址间有一段可疑数据：

![](../Images/c1ce2c556803995f7db0868018671b89.png)

把数据提取出来，转hex转ascii：

```
data \= \[21810, 18035, 25671, 22123, 22577, 11092, 26979, 26482, 22117, 18758, 14640, 18761, 30789, 28503, 12912, 28789, 13161, 12151, 26946, 13638, 30073, 26177, 29764, 29293, 11064, 31308, 21879, 27205, 20314, 13876, 26178, 13162\] print len(data) flag\="" for i in range(len(data)):  
    flag+=hex(data\[i\])\[2:\].decode('hex') print flag#U2FsdGVkX1+TicgrVeIF90IIxEoW2ppu3i/wiB5FuyfAtDrm+8zLUwjEOZ64fB3j
```

得到字符串U2FsdGVkX1+TicgrVeIF90IIxEoW2ppu3i/wiB5FuyfAtDrm+8zLUwjEOZ64fB3j，由U2Fsd特征易知是AES加密的密文，使用解密网站，密钥为空，解得flag：

![](../Images/57387e82e985ccf032f011632fac78f7.png)

flag：sctf{S\_y3L\_0v6:M\_0\_dbus}
