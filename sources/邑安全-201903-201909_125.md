简单分析，猜测有价值的信息可能与todo.txt的最后一句话有关：`3. Work on /h3l105`，猜测`/h3l105`可能为目录名称，但当前smb共享目录下并未发现相关信息。

回看端口扫描的信息 ，还开放了80web端口，猜测可能在此处进行利用，首先访问80端口web页面：

果然有东西~

页面上存在这样一句提示语句：`just another wordpress site`，暗示该站点为`wordpress`架构。

显然，我们可以利用工具对`wordpress`进行脆弱点扫描，包括其相关插件的漏洞

首先修改本地Hosts文件：

![](../Images/4ee205398767e93254eff0d0e46772e1.png)

![](../Images/5639f0acdd9f7f3a6e37a5d22ac4aa94.png)

结果显示，相关插件的漏洞包括：本地文件包含、SQL注入。

尝试分析`Mail Masta 1.0`的本地文件包含漏洞：

![](../Images/266447378f501dd700a25904de48a79a.png)

漏洞说明提示，典型的poc可以泄露passwd文件，尝试利用：

![](../Images/b380c0ed55ad24eafdc3a0c84c11f2ab.png)

如图所示，我们通过访问`http://192.168.88.148/h3l105/wp-content/plugins/mail-masta/inc/campaign/count_of_send.php?pl=/etc/passwd`,成功泄露passwd文件。

这也证明了LFI漏洞的可用性

下一步，如何实现由LFI到RCE？网上的参考资料也很多，例如From Local File Inclusion to Code Execution

结合本靶机的具体情况，由于靶机开启了25端口SMTP服务，因此这里通过发送恶意邮件的途径，实现RCE，具体步骤如下：

首先参考协议格式利用telnet发送邮件：

```

```

![](../Images/779147fb74123184e8ccb02fd6d52c7f.png)

成功发送邮件后，访问链接`http://192.168.88.148/h3l105/wp-content/plugins/mail-masta/inc/campaign/count_of_send.php?pl=/var/mail/helios&cmd=ls`，成功执行恶意php：

![](../Images/5d3b399c14d687d4f0b982bb94ab8ec5.png)

下一步，利用该恶意php获取reverse shell：

![](../Images/e2e658ff1a09b07dbb0fa69c39d8c93d.png)

显然当前用户权限较低，尝试提权操作，从本地拉取脚本文件，搜集可利用的提权相关信息：

![](../Images/0888d392b230b68e9cf38ecece93fa6a.png)

发现一可疑文件`/opt/statuscheck`，该文件为64位ELF程序：

![](../Images/2939a059c5f0ed472b2bf12bc35b1532.png)

拉回本地，扔到IDA分析，发现该程序执行了`curl -I http://localhost`

![](../Images/6b416ad1f8f4804bb63c676d23962361.png)

尝试执行该程序，结果如下：

![](../Images/feff50b7ae1809a911a519c0bc923e2b.png)

查看环境变量信息，当前的$PATH存储的curl可执行程序路径为`/usr/bin/curl`

这里容易想到的利用思路是，自行创建一个curl程序，将其路径添加到$PATH环境变量中，则`statuscheck`程序执行时，就劫持了`curl`程序为我们自己的恶意程序

因此在`tmp`目录下创建curl文件`/bin/sh`,此处注意需要修改curl的权限可执行。

将`tmp`路径添加到环境变量，此时再执行curl命令，实际上执行的是`tmp`目录下的文件

![](../Images/d7babc4feddf57790b9440268d2ac2a3.png)

执行`/opt/statuscheck`，成功拿到root权限以及flag:

![](../Images/b75271db9da89e6ede8a13c21bc2b326.png)

 

## 0x02 symfonos2

该靶机的前半部分与symfonos1有相似之处

探测靶机IP：

![](../Images/e04b2ab5c15a6e35aba00e6ed666ff4d.png)

照例扫描靶机开放的端口信息：

![](../Images/1a8d6e12f0afdba7e23a6210caff3023.png)

![](../Images/17522c06e4d3bd5057712258088f0573.png)

将`/anonymous/backups/log.txt`文件拉回本地，查看文件内容发现一用户名信息：`aeolus`

![](../Images/fc8338d070fd622735910d0ffd373d89.png)

到这一步，卡住了一段时间

smb的扫描结果显示并不存在其他共享目录了，猜测该用户名`aeolus`可能不是在此处进行利用

回看端口扫描的结果，其开放了22端口ssh服务，hydra尝试爆破，果然有新发现：

![](../Images/dd8ec76071b48a7fea67f7c7af6d7abb.png)

获得ssh的登录凭证：`aeolus:seagioteamo`

成功ssh登录到靶机：

![](../Images/a46746ca9dca6a691d2e11bb11bf0bd7.png)

ssh连接状态下，命令的执行受到一定约束：

![](../Images/8349e1a43333e95e0814445077cc2ac9.png)

![](../Images/8d8b1499c4650fb6165ea1a613940742.png)

转而利用msfconsole的ssh相关模块登录靶机：

![](../Images/b8de7929da22f5656371ac487bc90a16.png)

![](../Images/7acb6070af440462f6346e3b39ce6910.png)

在检查网络相关信息时，发现可疑之处，靶机一直监听其本机的8080端口，且只允许来自靶机自身的连接

![](../Images/a31b142880c7948a7bf1065aa63350dc.png)

这里自然想到利用端口转发，此处利用portfwd端口转发/重定向工具，其集成到metasploit内，

![](../Images/d75239ea87986341ace2e580950ec4ec.png)

将对本机9001端口的访问映射到靶机的8080端口，web访问本机9001端口如下：

![](../Images/c972cd896324dd230d03f7c2a24514c7.png)

而利用之前的ssh登录凭证`aeolus:seagioteamo`也可登录此web页面：

![](../Images/41feeeb8d235a581398feda794f26d2a.png)

这里直接利用metasploit查找该librenms是否存在可利用漏洞：

![](../Images/e0127f77cafd3271972dcb72b42f9937.png)

果然存在脆弱点，直接利用该模块尝试漏洞利用

注意，由于利用portfwd设置了端口转发，这里RHOSTS和RPORT的参数，需要设置为本机的IP和端口

![](../Images/467dd57cf6d2f9d0d1eb20a20120582a.png)

漏洞利用成功，拿到shell:

![](../Images/c074df0b7ed6250b466b2d2ad770b708.png)

下一步需要进行提权操作

查看当前用户的命令和权限相关信息，发现存在可利用的mysql，将权限提升至root:

## 0x03 matrix\_v3

探测靶机的ip信息：

![](../Images/8311d5d20bc7914e2105e869f8d39d63.png)

IP为：192.168.88.146

nmap扫描靶机端口，找寻可利用信息：

![](../Images/d3c2ed9e69f937108533f78bcbeceaae.png)

发现开发的端口信息：80（http）、6464（ssh）、7331（caldav）

首先访问80端口的web页面如下：

![](../Images/be013aaa50bee78a68a4c40dc6a2a29f.png)

没有可利用信息。尝试对站点进行子目录爆破：

![](../Images/0590ba135337a2b20f4a6fa539a734b2.png)

发现了`assets`和`Matrix`子目录

先访问`assets`页面如下：

![](../Images/0c5059e8101be677373f82bed6bbf711.png)

发现一名为`Matrix_can-show-you-the-door.png`的图片：

![](../Images/867e219b5073deb55a279daf79b65fa4.png)

然而这只阔爱的兔兔好像并没有什么价值

文件的名称给了暗示，信息可能蕴含在名为`Matrix`的目录下

访问页面如下：

![](../Images/c42e0e6542c99f582fb30925cb9f6974.png)

简单浏览了一下目录，发现各目录下又包含众多空目录

猜测：有价值的信息应该包含在某一目录下

利用上述目录构建字典，尝试爆破：

![](../Images/d13137bf4832471fd8f31aed14ebdc35.png)

根据上述结果，发现其`/n/e/o`的目录较为可疑

最终在`/n/e/o/6/4`的目录下，发现了信息：

![](../Images/01aa0e2d1ac0db4c9e28f9faa69ea845.png)

把文件拉回本地，查看信息：

![](../Images/ccdb80ca7aa6294da4cdea7418126201.png)

猜测为某登录凭证，口令经过了hash运算，尝试破解口令如下：

![](../Images/b6635276b4ab0485d802337bb366da50.png)

得到密码为`passwd`

下一步，注意力转向7331端口，访问该端口，要求输入身份验证信息：

![](../Images/b104da1ab4dd8ddfaed03f9f307627c0.png)

输入之前得到的身份凭证信息`admin:passwd`，进入如下页面：

![](../Images/ed8b7f6ce56092110efcacce6c6ec889.png)

没有发现重要线索信息，依然尝试子目录爆破：

![](../Images/eac5ca96c8517731e5a410dab09ead22.png)

发现`data`目录，访问页面如下：

![](../Images/b1447f459907a4dcc6e978d69edc6391.png)

发现一个二进制文件，拉回本地进行分析：

![](../Images/7168af36a36af9f866db517f6c12f63c.png)

扔到ida里，发现如下字符串信息：

![](../Images/9109d05a571c8d3108b4998dae651d7f.png)

猜测仍然为身份凭证信息

至此，只剩下6464端口的ssh没有进行分析利用，因此尝试利用上述得到的身份凭证登录ssh：

![](../Images/402c234f6a712321928432fa75358f56.png)

上图所示，我们得到了一个受限制的bash，即rbash(restriced bash)

在这种情况下，命令的执行将受到多种约束。

因此，利用`-t "bash --noprofile"`来禁止相关的启动脚本，获得一个完整的guest的shell：

![](../Images/9e4a03b2286c722fcc4335698370498f.png)

get it！

查看一下当前用户下相关命令的权限情况：

![](../Images/0af4ffa80f805fd0bc82270de20413b4.png)

发现，当前guest用户可以以trinity用户的权限来执行`/bin/cp`命令

由此想到以下利用思路：可以生成ssh登录凭证，然后利用cp命令将其公钥拷贝至trinity用户目录下，这样guest用户就可以用生成的私钥ssh登录至trinity用户

流程如下：

![](../Images/3c9d0c29a921fab86b6e35340fd2131b.png)

(注：这里需保证公钥文件有足够的权限)

![](../Images/0c4dceb1e30554ffc1cf501bfb35c269.png)

成功登录到trinity用户下，照旧，查看一下当前用户用户下命令的权限情况

![](../Images/e421e1d3267023ffefa35a8558b2aafc.png)

发现可以以root权限执行`/home/trinity/oracle`程序，在`oracle`文件内写入`/bin/bash`命令，然后赋予执行权限，执行~成功拿到root权限。
