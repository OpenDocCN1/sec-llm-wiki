在2018年12月3日，@ L3mOn在Discuz x3.4中披露了一个前端SSRF。通过使用辅助跳转和两个解析问题，可以巧妙地完成SSRF攻击链。

https://www.cnblogs.com/iamstudy/articles/discuz\_x34\_ssrf\_1.html

在与我的合作伙伴@dawu重现的过程中，发现漏洞本身依赖于多个特征，导致剥削环境的各种减少和对某些条件的强依赖性，这大大降低了漏洞的危害。让我们详细分析一下这个漏洞。

# 脆弱性的条件

*   版本<41eb5bb0a3a716f84b0ce4e4feb41e6f25a980a3（补丁链接）
    
*   PHP版本> PHP 5.3
    
*   php-curl <= 7.54
    
*   DZ在端口80上运行
    
*   默认不影响Linux（不是100％确认，Linux的常见测试环境不受影响）
    

# 漏洞再现

## SSRF

首先，漏洞点的位置是：`/source/module/misc/misc_imgcropper.php line 55`。

![](../Images/fce7ec498726a1861808b7aa9e7dc6ad.png)

这里的变量`$prefix`是`/`，剩下的代码是可控的，然后我们进入函数。

`/source/class/class_image.php line 52 Thumb function`

![](../Images/fd3f1f85a1dad6e26d90d1f2137ca99e.png)

然后进入init函数（第118行）

![](../Images/499af9a3ec8339f34b2955acbba9c3db.png)

显然，只要`parse_url`解析主机，就可以通过发送请求`dfsockopen`。

一个常见的伎俩：因为`/`前面会添加，所以源必须以`/`。

```

//baidu.com
```

这样的链接会自动添加协议，如何添加它取决于特定客户端的编写方式。

然后我们跟着`dfsockopen`来`/source/function/function_core.php line 199`。

![](../Images/38bd792da566263477a4a47f7058f0c7.png)

然后到`source/function/function_filesock.php line 31`。

![](../Images/11f129528853686de5d8d9f61de69c12.png)

主代码在红色框中，您可以看到请求的地址是相应的目标`parse_url`。

如前所述，链接的正面是`/`，因此`parse_url`这里是有限的。

![](../Images/a39cd3bd68c6cc78c4e44c8125568f70.png)

由于没有`scheme`，最终卷曲访问的链接是：

```

：//google.com/
```

因此，在前面自动添加协议如下：

```

HTTP：//：//google.com/
```

这里出现了一个非常严重的问题：对于curl，请求空主机的确切位置在哪里？

在Windows中，libcurl的版本：`7.53.0`。

在这里你可以看到我的本地ipv6的ip被请求。

在Linux环境（ubuntu）中，它`7.47.0`就像在屏幕截图中一样。

![](../Images/85aab98a4709d9a37a0677068b26bcb7.png)

在测试了各种常见系统之后，没有卷曲版本在此过程中不会报告错误，我们暂时认为它只会影响Windows的服务器环境。

回到代码条件，我们可以查看以前的条件：

（1）首先我们需要确保`/{}`可控制，并且在`parse_url`操作下有主机。

为了满足这个条件，我们必须首先清楚地了解结果`parse_url`。

在没有协议的情况下，似乎协议或端口（：number）不能出现在参数中，否则第一个段将不会被解析为主机（不知道确切的原因）。

![](../Images/2a3bb9ee2622adccefb117cd8d39f9b7.png)

在这种情况下，我们只需要删除稍后可能出现的HTTP，因为在没有协议的情况下，默认情况下会添加HTTP（通常）。

（2）Curl必须能够将空主机解析为localhost，因此libcurl版本需要低于7.54.0，并且到目前为止它只影响Windows服务器。（欢迎进一步反驳

（3）DZ在端口80上运行

满足所有条件后，我们实际上请求了任意本地目录。

```
HTTP：//：// {可控}

```

但这实际上是无用的，所以我们仍然需要一个任意的网址来跳转，否则如果它只能攻击本地则没有多大意义。

# URL重定向程序滥用

为了能够与之前的要求进行交互，我们需要一个任意的url jump，它是“get”类型，不需要登录。

在注销时，Dz将从referer参数（而不是header参数）获取值，然后输入301跳转，这里唯一的要求是在主机上进行一些验证，让我们看一下代码。

`/source/function/function_core.php:1498`

![](../Images/a0aa18db3af2198492e56b1a461c5027.png)

上面的屏幕截图解释了此代码的主要问题，核心代码以红色框起。

为了让引用者不改变，我们必须使主机只有一个字符，但显然，如果主机只能有一个字符，我们就无法控制任意的url跳转。

因此，我们需要找到一种方法来获取`parse_url`和`curl`解析与同一URL的目标不一致，以便可能实现我们的目标。

```

HTTP：//localhost#@www.baidu.com/
```

`parse_url`将上面的链接解析为`localhost`，并将curl解释为`www.baidu.com`。

让我们捕获一个数据包来查看：

![](../Images/69a8256f50fe0cb59db4398050dc874f.png)

我们成功地绕过了各种限制。
