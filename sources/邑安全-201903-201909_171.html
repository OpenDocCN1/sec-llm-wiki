git简介

Git是一个用于协作改进的软件源代码变更管理系统。它维护文件版本的历史记录。与“检出”最新版本文件的典型客户端 - 服务器CM系统不同，Git是一个分散的CM系统，其中用户拥有整个存储库的本地副本，其中包括所有文件的完整历史记录。Git在速度，数据可靠性以及维护非线性工作流程方面优于SVN。处理本地项目工作区中与本地克隆源相关的文件的用户可以添加，编辑和删除文件，最后提交更改。然后，用户可以通过“推送”或“拉”到其他Git存储库来将这些更改共享到本地存储库。

Sudo Rights Lab设置了权限提升

现在我们将建立具有更高权限的git命令实验室。正如我在上一篇文章中所解释的那样，在相应地获得更高权限之后，许多命令的行为会发生变化，我们将检查git命令，它在接收到sudo权限后会对它产生什么影响，以及我们如何进一步使用它来进行权限提升。

下面的图像可以清楚地理解我创建了一个本地用户（测试），他以root身份拥有所有sudo权限，并且可以作为admin执行所有任务。

添加sudo right open etc / sudoers文件并输入以下用户权限规范。


1

test All=(root) NOPASSWD: /usr/bin/git


利用Sudo权利

现在我们将开始利用sudoer的权限来开发git服务。假设我们得到了受害者机器的会话，这些会话使我们能够通过本地用户访问目标系统，通过它我们可以升级root用户权限。

首先我们将使用ssh连接到目标计算机，因此，键入以下命令以通过本地用户登录进行访问。


1

ssh test@192.168.0.15

然后我们查找“test”用户的sudo权限（如果给出）并发现用户“test”可以在没有密码的情况下以“root”执行git命令。

因此，键入以下命令以生成bash shell：


1

sudo git help config

 

这将调用默认的寻呼机来像人一样读取配置，在这里我们可以注入“！/ bin / sh”并按Enter键为我们执行bash shell。



你得到“ ＃ ”shell意味着我们已经成功升级了root shell，如下图所示。
