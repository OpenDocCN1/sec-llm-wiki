# Apache Bug让普通用户通过脚本获得Root访问权限

Apache httpd 2.4.39中修复了Apache HTTP服务器中具有重要严重性的权限提升漏洞，允许有权编写和运行脚本的用户在Unix系统上获得root权限。  

正如更改日志中详述的那样，跟踪为  CVE-2019-0211，会影响所有Apache HTTP Server版本从2.4.17到2.4.38，并且可以通过记分板操作执行任意代码。


Apache软件基金会和OpenSSL项目创始成员Mark J. Cox在Twitter帖子中解释说，当使用Web服务器运行共享托管实例时，在httpd 2.4.39中修补的CVE-2019-0211安全问题尤其严重，如果某些具有脚本写入权限的用户不受信任。

> Apache HTTP Server 2.4.17 - 2.4.38中的缺陷允许任何允许编写脚本（PHP，CGI，..）的人获得root权限。获得2.4.39 \* now \*特别是如果你有不受信任的脚本作者或运行共享主机（或使用mod\_auth\_digest，由于一个单独的缺陷）  https://t.co/s08XhOzKKW
> 
> \- Mark J Cox（@iamamoose）2019年4月2日

## 在共享托管环境中特别危险

此外，正如Cox进一步详述的那样，服务器上具有有限权限的用户将能够使用脚本提升其权限，从而可以在易受攻击的Apache Web服务器上以root身份运行命令。

> 这是一次攻击是的。为非特权用户提供编写自己的脚本（在共享托管中常见，但在其他环境中也是如此）的能力也很常见，这将使他们能够获得root权限。
> 
> \- Mark J Cox（@iamamoose）2019年4月2日

在Apache HTTP Server 2.4.39版本中修复了另外两个重要的严重性控制绕过安全漏洞，其中一个跟踪为  CVE-2019-0217，  影响了从2.4.0到2.4.38的所有httpd版本，并使用户“拥有有效的凭据”使用另一个用户名进行身份验证，绕过已配置的访问控制限制“因为”在线程服务器中运行时mod\_auth\_digest中存在竞争条件。

跟踪为  CVE-2019-0215的那个  影响Apache 2.4.37和2.4.38安装，它允许客户端“客户端支持后握手身份验证绕过配置的访问控制限制”，因为“使用每个位置时mod\_ssl中的错误使用TLSv1.3验证客户端证书。“

Apache httpd 2.4.39还修补了三个低严重性漏洞，这些漏洞可能导致崩溃，免费读取和规范化不一致问题。

| CVE || 描述 |
| :-: | :-: |
| CVE-2019-0217 || 重要：mod\_auth\_digest访问控制旁路 |
| CVE-2019-0215 || 重要：mod\_ssl访问控制旁路 |
| CVE-2019-0197 || 低：mod\_http2，可能会在后期升级时崩溃 |
| CVE-2019-0196 || low：mod\_http2，字符串比较后的read-after-free |
| CVE-2019-0220 || 低：Apache httpd URL规范化不一致 |

安全工程师Carles Fol于2月22日报告了此漏洞，并在3月7日由Apache提供了响应和补丁。

Fol还提供了有关CVE-2019-0211本地root权限升级漏洞的详细说明，以及有关如何在其个人博客中利用此漏洞的详细说明。
