SQL Injection

处理数据库的主要类之一是Magento\Framework\DB\Adapter\Pdo\Mysql。经过几分钟的审核后，其中一种方法出现了一个有趣的错误prepareSqlCondition。

protected function _prepareQuotedSqlCondition($text, $value, $fieldName) [3]
{
    $sql = $this->quoteInto($text, $value);
    $sql = str_replace('{{fieldName}}', $fieldName, $sql);
    return $sql;

总体而言，该函数建立从SQL字段名称的SQL条件，和表示操作者（一个阵列=，!=，>等等）和一个值。为此，它使用$conditionKeyMap[1] 将给定条件别名映射到模式，并使用[3]替换给定值的引用版本的别名中的每个 ?字符_prepareQuotedSqlCondition()。例如：

<？php 
   $ db - > prepareSqlCondition （'username' ， [ 'regexp'  =>  'my_value' ]）; 
=>  $ conditionKeyMap [ 'regexp' ]  =  “{{fieldName}} REGEXP？” ; 
=>  $ query  =  “username REGEXP'my_value'” ;

然而，当from和to条件[2]结合使用时会出现问题，通常是为了确保字段包含在一个范围内。例如：

<？php 
$ db - > prepareSqlCondition （'price' ， [ 
    'from'  =>  ' 
    100''to '  =>  '1000' 
]）; 
$ query  =  “price> ='100'AND price <='1000'” ;

当存在两个条件（from和to）时，代码首先处理from部分[3]，然后处理另一个[4]，但是此时发生了一个关键错误[5]：生成from的查询被重用于格式化。

因此，由于每个 ?都被给定值替换，如果值中存在问号from，则它将被替换为值的引用版本to。这是一种打破SQL查询并因此引发SQL注入的方法：

<？PHP的
$分贝- > prepareSqlCondition （'价格' ， [ 
    '从'  =>  '？一些值' 
    '到'  =>  '破' 
]）;

   $查询 =  $ DB - > _prepareQuotedSqlCondition （“{{字段名}}> =？” ， '一些价值？' ， '价格' ）
- >  $查询 =  “价格> = '某个值？'” 
＃TO 
   $ query  =  $ db - > _prepareQuotedSqlCondition （$ query  。 “ ， 'price' ）
- >  $ query  =  $ db - > _prepareQuotedSqlCondition （“price> ='some？value'AND {{fieldName}} <=？” ， 'BROKEN' ， 'price' ）

第一次出现的BROKEN是引号外。为了执行有效的SQL注入，我们可以这样做：

<？php 

$ db - > prepareSqlCondition （'price' ， [ 
    'from'  =>  'x？' 
    'to'  =>  'OR 1 = 1  -   - ' 
]）; 
- >  $ query  =  “price> ='x'或1 = 1  -   - ''和价格<='或1 = 1  -   - '”

Codewise，为了避免这个bug，这一行：

$ query = $ this - > _ prepareQuotedSqlCondition（$ query 。$ conditionKeyMap ['to']，$ to ，$ fieldName ）;

本来应该：

$ query = $ query 。$ this - > _ prepareQuotedSqlCondition（$ conditionKeyMap ['to']，$ to ，$ fieldName ）;

这个错误虽然很小，但是非常有影响力：如果我们可以完全控制第二个参数prepareSqlCondition，我们就会注入SQL。令人惊讶的是，自Magento 1.x以来，这段代码已经存在！

修补

SQL注入的补丁是微不足道的：

+ $ query = $ query。$ this  - > _ prepareQuotedSqlCondition（$ conditionKeyMap ['to']，$ to，$ fieldName）;
