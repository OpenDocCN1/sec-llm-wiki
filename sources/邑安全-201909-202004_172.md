# RD Gateway被曝存在严重漏洞，漏洞POC已公开

微软公告了RD Gateway存在远程代码执行漏洞：CVE-2020-0609，CVE-2020-0610。腾讯安全团队目前已分析漏洞成因，该漏洞不需要用户交互，可以在不需要用户干预的情况下远程执行任意代码。目前全球有2万多台RD网关受影响，RD网关一旦被攻破，内网的机器都可能受到威胁。

![](../Images/880ac93c9792043feddb83f23ec0b975.png)

Remote Desktop Gateway服务通常也被称为RD Gateway（RD网关），用户可以通过RD Gateway从公司防火墙外部安全地连接到内部网络资源，RD网关的三个主要目的是：  
  
**1.在最终用户的设备和RD网关服务器之间建立加密的SSL隧道：**为了通过任何RD网关服务器进行连接，RD网关服务器必须安装了最终用户的设备可以识别的证书。在概念的测试和证明中，可以使用自签名证书，但是在任何生产环境中都只能使用来自证书颁发机构的公共信任的证书。  
  
**2.在环境中对用户进行身份验证：**RD网关使用收件箱IIS服务执行身份验证，甚至可以利用RADIUS协议来利用多因素身份验证解决方案，例如Azure MFA。除了创建的默认策略外，您还可以创建其他RD资源授权策略（RD RAP）和RD连接授权策略（RD CAP），以更具体地定义哪些用户应有权访问安全环境中的哪些资源。  
  
**3.在最终用户的设备和指定资源之间来回传递流量：**只要建立连接，RD网关就会继续执行此任务。您可以在RD网关服务器上指定不同的超时属性，以在用户离开设备时维护环境的安全性。影响版本Windows 2012 R2 – Windows Server 2019由于RD网关服务一般面向大型政企事业单位，一旦攻击代码公开，这些主机随时都有可能成为攻击的目标，并且很容易进一步渗透内网造成严重损失。漏洞详情

在实际的业务场景中，为了提升效率，RD Gateway在配置时通常会开启支持UDP+SSL。  

![](../Images/cc3f3511922c3c9fbd400019bdbbebbf.png)

  
漏洞出现在当客户端向服务器发送一个或多个CONNECT\_PKT\_FRAGMENT包以建立连接，服务器没有验证该结构中的数据，导致攻击者可以构造特殊数据以造成服务端的越界读写。  

![](../Images/d43d8a8d746f3bbbf512a9e9741933fd.png)

POC已被上传到GitHub

![](../Images/ba850f0642472c58bbce3052700ab917.png)

该漏洞可以在不需要用户交互、不需要用户干预的情况下远程执行任意代码，请相关人员尽快更新安装补丁

  

缓解措施

1.通过配置企业防火墙，阻断未经安全验证的IP连接RD网关服务的UDP传输端口（默认为3391）  
  
2.可暂时关闭RD网关服务的UDP传输设置(默认3391端口)。
