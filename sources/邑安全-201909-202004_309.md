# 在4种流行的开源VNC软件中发现数十种严重漏洞

VNC系统旨在为一台设备提供对另一台设备的屏幕的远程访问。值得注意的是，该协议的规范不限制操作系统的选择，并允许跨平台的实现。既有针对通用操作系统（GNU / Linux，Windows，Android）的实现，也有针对异国情调的实现。

VNC已成为同类应用中最广泛的系统之一，这在一定程度上要归功于跨平台的实现和开源许可证。确切的安装数量很难估算。根据shodan.io的数据，可以在线使用超过600,000个VNC服务器。如果添加了仅在本地网络上可用的那些设备，则可以放心地假定正在使用的VNC服务器的总数是原来的许多倍（也许是数量级）。

根据我们的数据，VNC积极用于工业自动化系统。我们最近在我们的网站上发布了有关在工业控制系统中使用远程管理工具的文章。据该文章估计，大约32％的工业控制系统计算机上都安装了包括VNC在内的各种远程管理工具（RAT）。在所有案例的18.6％中，RAT包含在ICS软件分发软件包中，并与该软件一起安装。其余81.4％显然是由这些企业的诚实或不太诚实的员工或其承包商安装的。在我们网站上发布的一篇文章中，我们描述了我们分析过的攻击，攻击者在其中安装并使用了远程管理工具。重要的是，在某些情况下，攻击者利用远程管理工具中的漏洞作为攻击场景的一部分。

根据我们的估计，大多数ICS供应商都基于VNC而不是任何其他系统为其产品实现远程管理工具。这使对VNC安全性的分析成为我们的首要任务。

在2019年，Windows RDP（远程桌面服务）中的BlueKeep漏洞（CVE-2019-0708）引起了公众的强烈反响。该漏洞使未经授权的攻击者可以在运行RDP服务器的Windows计算机上以SYSTEM特权实现远程代码执行。它影响了操作系统的“初级”版本，例如Windows 7 SP1和Windows 2008 Server SP1和SP2。

Windows中的某些VNC服务器组件被实现为提供对系统的特权访问的服务，这意味着它们本身也具有对系统的高级访问。这是优先研究VNC安全性的另一个原因。

已发现四个流行的开源VNC远程桌面应用程序易受总共37个安全漏洞的攻击，其中许多安全漏洞在过去20年中未被发现，而最严重的漏洞可能使远程攻击者可以破坏目标系统。

VNC（虚拟网络计算）是基于RFB（远程帧缓冲区）的开放源代码图形桌面共享协议，允许用户远程控制另一台计算机，类似于Microsoft的RDP服务。  
VNC系统的实现包括在共享桌面的计算机上运行的“服务器组件”和在将访问共享桌面的计算机上运行的“客户端组件”。  
换一种说法，

有许多免费和商业的VNC应用程序，可与Linux，macOS，Windows和Android等广泛使用的操作系统兼容。  
考虑到目前有600,000多个VNC服务器可以通过Internet远程访问，并且其中近32％连接到工业自动化系统，卡巴斯基的网络安全研究人员审核了四种广泛使用的VNC开源实现，包括：  

*   LibVNC
    
*   UltraVNC
    
*   TightVNC 1.x
    
*   TurboVNC
    

在分析了这些VNC软件之后，研究人员在客户端和服务器软件中总共发现了37个新的内存损坏漏洞：其中22个在UltraVNC中发现，10个在LibVNC中发现，在TightVNC中发现4个，在TurboVNC中只有1个。  

> 卡巴斯基说：“所有错误都与不正确的内存使用情况有关。利用它们只会导致故障和拒绝服务，这是相对有利的结果。” “在更严重的情况下，攻击者可以未经授权访问设备上的信息，或者将恶意软件释放到受害者的系统中。

一些已发现的安全漏洞也可能导致远程代码执行（RCE）攻击，这意味着攻击者可以利用这些漏洞在目标系统上运行任意代码并获得对其的控制。  
  
由于客户端应用程序接收更多数据并包含数据解码组件，开发人员在编程时经常会出错，因此大多数漏洞都会影响这些软件的客户端版本。

另一方面，服务器端相对而言包含一个很小的代码库，几乎没有复杂的功能，从而减少了内存损坏漏洞的可能性。

但是，该团队发现了一些可利用的服务器端错误，包括TurboVNC服务器中的堆栈缓冲区溢出漏洞，该漏洞使在服务器上实现远程代码执行成为可能。  
但是，利用此漏洞需要在建立连接之前将身份验证凭据连接到VNC服务器或控制客户端。  
因此，为了防止利用服务器端漏洞的攻击，建议客户端不要连接到不受信任或未经测试的VNC服务器，并且要求管理员使用唯一的强密码保护其VNC服务器。  
卡巴斯基已向受影响的开发人员报告了该漏洞，所有漏洞均已发布了其受支持产品的补丁程序，但其创建者不再支持的TightVNC 1.x除外。因此，建议用户切换到2.x版本。
