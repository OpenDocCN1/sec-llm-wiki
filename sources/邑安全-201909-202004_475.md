使用以下命令在本地使用Docker启动了Jenkins实例：

```
1.  `docker run -p 8080:8080 -p 50000:50000 jenkins/jenkins:lts-alpine`
    
```

![](../Images/2de25de3f73d9ac9b623db238c3b9a3f.png)  
版本为：Jenkins 2.176.3

git客户端：http://updates.jenkins-ci.org/download/plugins/git-client/2.8.2/git-client.hpi

git插件：http://updates.jenkins-ci.org/download/plugins/git/3.12.0/git.hpi

由于官方已经升级了client为2.8.5，git升级到3.12.1。所以需要手动上传插件，上传完成后如下。

![](../Images/1a6178ff2e85718f1df12d748e67512c.png)新建用户user

![](../Images/147ec743c44fa6ee62fa403998c4c98f.png)为账号配置权限，作者这里没看到给了create权限，如果需要使用普通账号来创建任务测试，则需要给create权限，或者已有任务的情况下来操作已有任务也是可以的，就不用给create权限，此处用create来测试。

![](../Images/b00d33c604d0f1b0ef962744f1c8caf8.png)登陆user用户，可以看到用户界面如此

![](../Images/17973a70f58e489f0488ad6cb70358b6.png)  
如下选择

![](../Images/e6be700741b70624f3088fb5c21de615.png)  
在SCM中选择git执行

![](../Images/148fdd7428fbd79f15b970df70491482.png)查看git-ls-remote文档，从给的参数中可以注意到–upload-pack=。看起来像是执行了某些命令，而漏洞作者也是看到了这个参数的形式而采用了这个参数执行。

https://git-scm.com/docs/git-ls-remote.html

![](../Images/95b447e36ec2c10d4f8f24ab14e537cb.png)  
参数的意义是：在远程主机上指定*git-upload-pack*的完整路径。这允许列出通过SSH访问的存储库中的引用，以及SSH守护程序不使用用户配置的PATH的位置。

如此，执行``--upload-pack="`id`"``

![](../Images/7be8ecdb4792e6423fa49d1282e0b05b.png)  
可以看到命令已经执行。
