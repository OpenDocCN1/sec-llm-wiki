# 用Rust重写Linux内核？Linus Torvalds持观望态度

虽说 Linux 是 C 语言的表率，不过时代在变。将 Rust 编程语言作为 Linux 的系统语言呼声越来越高，也受到了非常多用户的支持。例如在 2020 年的 Linux Plumbers 大会上，开发人员认真考虑了在新的 Linux 内联代码中使用 Rust 语言。近日外媒 ZDNet 就这个话题采访了 Linux 创始人 Linus Torvalds 和 Linux 稳定内核维护者 Greg Kroah-Hartman。![](../Images/ef361f811a43e79777f2ab321d67eb53.png)

  

Torvalds 对 Linux 代码 Rust 化有什么看法？他属于“观望”阵营，他表示：“我对这个项目很感兴趣，但我认为这是那些对 Rust 非常兴奋的人推动的，我想看看它然后在实践中最终如何工作。就个人而言，我暂时不会推动 Rust 化，不过考虑到承诺的优势以及能够避免一些安全隐患，我对它持开放态度。但我也知道，有时承诺并不能实现”。Torvalds 认为：“Rust的首要目标似乎是驱动程序，只是因为在那里你会发现只是很多不同的可能目标，而且你有这些内核的单独部分，它们相当小，而且独立。对某些人来说，这可能不是一个非常有趣的目标，但它是明显的目标。对驱动程序的任何初始试验都只是架构方面的，很多驱动程序只在几个目标架构上相关，所以Rust代码在某些架构上不支持的整个问题就不那么严重了”。Kroah-Hartman 也认为，“驱动程序可能是这样的尝试的第一个地方，因为它们是内核源码中依赖树的'末叶'。它们依赖于核心内核功能，但没有任何东西依赖于它们”。Torvalds 也表示了解部分用户并不喜欢 Rust 在 userspace 上的想法。他表示：“人们抱怨用户空间中的 "Rustification "对于未来任何内核的使用都不是一个好兆头，不过这个有待观察。内核与用户空间项目不同--在某些方面比较困难（我们使用了很多非常奇怪的头文件，这就突破了可以被称为‘C’的边界），但在许多其他方面比较容易（主要是内核相当自足，然后不依赖其他项目来获得最终的二进制文件）”。从Kroah-Hartman所处的位置来看，“这一切都将归结于用C语言编写的内核核心结构和寿命规则之间的交互如何能够映射到Rust结构和寿命规则中，让Rust中的驱动程序能够正确使用它们。这需要想要把这一切勾起来的开发者们做很多细致的工作，我祝他们好运”。因此，虽然你几乎可以肯定不会很快看到Linux从C语言移植到Rust中，但人们对将基于Rust的用户空间程序、驱动程序，以及最终将基于Rust的Linux内核引入Linux操作系统有很大的兴趣和行动。
