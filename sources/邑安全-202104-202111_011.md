# 0x01 前言

查资料的时候，偶然间看到这样一个漏洞，在一个提交表单的地方，插入SQL语句，便可以进行报错注入。看着有点像二次注入，对于这样类型的注入，我个人遇到的还是比较少的，再加上一般这种地方多数会尝试XSS，所以进行了分析，看看漏洞到底是如何产生的。

# 0x04 漏洞分析

1、因为漏洞是sql注入，所以首先可以使用数据库语句监控工具进行监控执行的语句。这里我使用的是seay自带的数据库监控工具。  
![](../Images/7d75e10a9d4f5ef0323c3c53f695bbbb.png)  
2、输入账号密码，点击下断  
![](../Images/4f2e86ae01fdc51831a43b03b6c4de8f.png)  
3、发送sql注入的数据包后，点击更新  
![](../Images/e1d732120a1b155626873dba38399d4d.png)  
4、可以看到是一个插入数据库的语句

```
INSERT INTO lmx_cj(name,mid,content) VALUES('11111111111111111111111','1','1' and updatexml(0,concat(0x7e,database()),1) and '')
```

![](../Images/60218d0cf27af141ee6e5fd4c550fd1b.png)  
5、后面的数据包中可以看到是进行了查询  
![](../Images/971e8f16e36faed6c4ed5694bf9eff8c.png)  
6、这里很明显就是一个插入数据库的功能，将数据插入到lmx\_cj表中，因为updatexml函数导致了报错。查看这个数据表，里面是没有数据的。  
![](../Images/b62a7f3d348c6987d33f2973cd0f33b9.png)  
7、插入正常的字符串，里面成功添加了数据。  
![](../Images/12b64793a676a4ab801414e722b47724.png)  
![](../Images/eb75c37445b4e04dd7944c16f7340b6c.png)  
8、那么下面开始代码分析，从数据包中很明显可以看到访问的路径为**admin.php?&m=Acquisi&a=add**。分析过MVP框架的代码便可以很明显看出一个是对应的文件Acquisi，里面调用了add函数。  
先来查看一下admin.php文件，里面包含了/inc/config.inc.php和/inc/run.inc.php两个文件。  
![](../Images/64c38d482ef7790f58d8cba068a4dd76.png)  
9、分别打开2个文件查看，跟文件名上表示的一样，一个是配置，一个是路由  
![](../Images/4d32ccabb5356748c0b80815071d7503.png)  
![](../Images/35a11c9e24a5c1140c8903d8f0871266.png)  
10、其中有一个地方值得注意一下，action即方法是放在根目录下或者extend/目录下的c文件夹中，同理model即模块是放在m文件夹中。  
![](../Images/a4a6f86302e8cf9ccc148d4e6d5a135d.png)  
然后就是执行问题了，这里可以看到区分了伪静态和单入口，大体意思其实跟tp框架的很像，一者是/模板/方法/参数名/参数值，一者是/?m=模板&a=方法  
![](../Images/f6cf4e2076967113a9c934ab5d357599.png)  
看最后面

```
eval('$action=new '.$m.$extendEnt.'();');
```

这里就是可以定位到漏洞文件所在的地方，很明显传入的m的值为**Acquisi**，所以这个请求对应的类为**AcquisiAction()**  
11、在/c/admin/AcquisiAction.class.php找到了它  
![](../Images/45cc35070e55ed5413a4b63cc0de2ef8.png)  
12、在add方法中可以看到，其实就是检测了是不是有从post请求中传入add，并且在data中的name对应的值不为空。其中存在几个函数分别是d()、p()、add()  
![](../Images/64998621bc3c444857c466f9fad38e6b.png)  
13、定位一下d()方法，使用foreach函数，数组键分别赋值，看前面可以知道fieldCj就是一个name，mid，content的数组；$type这里有一个很重要的(int)类型强制转换，$is\_int为传入的数组mid，并且$v为mid时，将其进行强制转换，也就是post包中传入的mid固定为整型。  
![](../Images/e0542cec96c316c706a55e5feed73b04.png)  
![](../Images/10aa29d3f06c9ba496ae7c0d4ce6a0c4.png)  
14、再看一下p()方法，$type=1，$\_POST传入的数据赋值给$data；因为前面只传入了一个1，所以$pe、$sql、$mysql均为false；下面在代码注释中进行说明。

```






















function p($type=1,$pe=false,$sql=false,$mysql=false){
```

![](../Images/019585ef5b63f04718822739798dcfbe.png)  
15、前面对数据处理完之后，调用了这个类的modle中的add()方法

```
$this->model->add($data);
```

所以我们需要在m文件夹中寻找Acquisi的model文件  
![](../Images/87c562ad6323b180a8aa2dfa55046f56.png)  
16、打开一看，第一个函数add就是我们需要的  
![](../Images/9842c31808eb897bc019a294eb5cc99e.png)  
17、右键，选择定位函数（其实使用phpstorm快一点，奈何我这个是虚拟机，没有那个条件装那么大的软件）  
![](../Images/e51ccb09f7bbc67fcdfcacd38edadacd.png)  
18、很幸运，只有一个，不用进行筛选了  
![](../Images/4b4cb71f974e04b01a74241f9ea12f31.png)  
19、调用了一个新函数addDB，从字面上的意思理解是添加到数据库，继续定位函数  
![](../Images/41aacd81b6ae0636d1ca48513e285372.png)  
![](../Images/ceb8740eafb855618cb0085e1652887e.png)  
20、找到函数之后进行分析，首先将数据进行键值分离，然后存入到数组field\[\]和value\[\]中，关于implode()函数的用法，我百度了一下，可以理解为使用逗号将数组中的每个值进行连接。然后，就放入到sql语句中了。  
![](../Images/3b1a0fe9ac1d0e78ee7e16766187c13e.png)  
![](../Images/5bf4023aa985d76215c5c1188ecdfed0.png)  
21、然后是执行query函数，将sql语句直接执行，如果没有返回结果就将错误信息返回。  
![](../Images/05abebdf39ce4d979331e801f8e123aa.png)  
22、总结一下利用链  
首先从admin.php文件 -> 再到/inc/run.inc.php文件 -> 然后调用了传入的m参数值AcquisiAction类 -> AcquisiAction类中的add() -> 对数据经过一些处理，调用了d()、p()函数 -> 调用AcquisiAction类对应的Model中的add方法 -> 调用addModel() -> 调用addDB() -> 在addDB方法中进行了数组的转换就直接放入到sql语句中 ->调用了query()方法，执行了sql语句，然后如果执行结果为空，则将错误打印出来。  

23、分析之后我发现一个有意思的东西，既然没有经过任何过滤，那么是不是存在存储型XSS漏洞呢，试了一下，确实存在。  
![](../Images/4d547ff163ca9dc77167ef9e242c3c46.png)  
两个参数均存在。  
![](../Images/e1d4927a8dc49810a08d3711ba96bef7.png)

# 0x05 总结

分析完一条完整的利用链了，漏洞利用那么简单，但是实际分析确实还是有一点难的，当然如果有PHPstrom可能会好一些，函数之间的跳转会方便点，并且可以通过截断数据进行debug调试，也比这样轻松。但是总的来说还是成功分析完了，这里其实有一些地方的分析还是存在不足之处的，也希望大家体谅小白对代码的熟练度还不够。
