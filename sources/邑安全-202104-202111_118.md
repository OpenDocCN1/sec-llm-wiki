# CVE-2020-14645 - Weblogic漏洞分析与修补之JNDI注入

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzUyMzczNzUyNQ==&mid=2247507639&idx=4&sn=b90c3b77e317b557ee486a9d57012635&chksm=fa3a9e6dcd4d177be12c45d6138f5d3f7abfb42dab8573d575fa74279ce97f56ce8f537aa6e4&scene=126&sessionid=1681375683#rd](http://mp.weixin.qq.com/s?__biz=MzUyMzczNzUyNQ==&mid=2247507639&idx=4&sn=b90c3b77e317b557ee486a9d57012635&chksm=fa3a9e6dcd4d177be12c45d6138f5d3f7abfb42dab8573d575fa74279ce97f56ce8f537aa6e4&scene=126&sessionid=1681375683#rd)

更多全球网络安全资讯尽在邑安全

Oracle七月发布的安全更新中，包含了一个Weblogic的反序列化RCE漏洞，编号CVE-2020-14645，CVS评分9.8。

该漏洞是针对于CVE-2020-2883的补丁绕过，CVE-2020-2883补丁将`MvelExtractor`和`ReflectionExtractor`列入黑名单，因此需要另外寻找一个存在`extract`且方法内存在恶意操作的类即可绕过补丁。

这里找到的是 Weblogic 12.2.1.4.0 Coherence 组件特有的类 `com.tangosol.util.extractor.UniversalExtractor`，因此只能影响 Weblogic 12.2.1.4.x。

## 1）影响范围

Oracle WebLogic Server 12.2.1.4.0

## 3）漏洞分析

在`UniversalExtractor#extract`中，利用了`invoke`调用 `JdbcRowSetImpl#getDatabaseMetaData`方法导致 JDNI 远程动态类加载。`UniversalExtractor` 是 Weblogic 12.2.1.4.0 版本中独有的。

gadget链：

```






- PriorityQueue#readObject 
```

下面就分别解析PriorityQueue、ExtractorComparator、UniversalExtractor、JdbcRowSetImpl这四个类是怎么进行串联产生调用关系的

### 3.1 JdbcRowSetImpl

在`JdbcRowSetImpl`中，调用其`getDatabaseMetaData`方法，会进行`lookup`的操作

![](../Images/eb7ee11e8da932ddc60122eb0c95699b.png)

![](../Images/7b61ee09f7261ec1eb7cbef69efaf5af.png)

可以看到，如果`this.getDataSourceName()`参数可控，则会产生JNDI注入
