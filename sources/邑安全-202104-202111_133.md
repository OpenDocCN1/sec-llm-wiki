# GitHub 在“tar”和 npm CLI 中发现 7 个代码执行漏洞

GitHub 安全团队在 npm CLI 使用的 npm 包“tar”和“@npmcli/arborist”中发现了几个高危漏洞。  

tar包接收平均20万次的下载，而 *arborist* 被下载超过每周30万次。

这些漏洞会影响基于 Windows 和 Unix 的用户，如果不打补丁，攻击者可以利用这些漏洞在安装不受信任的 npm 包的系统上实现任意代码执行。

## 漏洞赏金猎人获得 14,500 美元的 ZIP 单据

今年 7 月至 8 月期间，安全研究人员和漏洞赏金猎人 Robert Chen和Philip Papurt 在开源 Node.js 包*tar* 和*@npmcli/* arborist 中发现了任意代码执行漏洞。

在发现这些漏洞后，研究人员通过 GitHub 的漏洞赏金计划之一私下通知了 npm。

在进一步审查研究人员的报告后，GitHub 安全团队在上述软件包中发现了一些更严重的漏洞，影响了 Windows 和基于 Unix 的系统。

Node.js 包 *tar* 仍然是需要在安装后解压 npm 包的安装程序的核心依赖项。该软件包还被数千个其他开源项目使用，因此每周大约有 20 万次下载。arborist 包是一个核心的依赖则依靠NPM CLI和用于管理 *node\_modules*树。

这些 ZIP 漏洞给开发人员使用 npm CLI 安装不受信任的 npm 包或使用“tar”提取不受信任的包带来了问题。

默认情况下，npm 包作为 . *tar.gz* 或 . *.tgz* 文件是类似 ZIP 的档案，因此需要由安装工具提取。

理想情况下，提取这些档案的工具应该确保档案中的任何恶意路径最终不会覆盖文件系统上的现有文件，尤其是敏感文件。

但是，由于下面列出的漏洞，解压后的 npm 包可能会以运行*npm install* 命令的用户权限覆盖任意文件 ：

“CVE-2021-32804，CVE-2021-37713，CVE-2021-39134，和CVE-2021-39135特别是对故宫CLI安全的影响处理恶意或不信任的NPM包安装时，解释说：” 迈克·汉利，首席GitHub 的安全官。

“其中一些问题可能会导致任意代码执行，即使您使用*\--ignore-scripts*来阻止包生命周期脚本的处理。”

GitHub 安全团队感谢 Chen 和 Papurt 负责任的披露，并授予他们 14,500 美元的奖金，以表彰他们为保护 GitHub 安全所做的努力。

## npm 敦促用户修复漏洞

GitHub 旗下的 npm 也在一条推文中提示开发人员尽快修复这些漏洞：

![](../Images/d144ae38516d1c705ef0baff1b720908.png)

开发者应将*tar* 依赖版本升级到 4.4.19、5.0.11 或 6.1.10，并升级@npmcli/arborist 版本 2.8.2 以修补漏洞。

对于NPM CLI，版本 v6.14.15，  v7.21.0，或更新包含的修补程序。此外，根据 GitHub 的说法，Node.js 版本 12、14 或 16 带有修正的*tar*版本，可以安全地升级。
