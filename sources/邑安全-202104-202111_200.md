## **执行摘要**  

Unit 42 在 Intel CPU 寄存器中发现了一个特定的单个位（陷阱标志），恶意软件通常会滥用该位来逃避沙箱检测。恶意软件可以通过在设置此单个位后监视 CPU 的响应来检测它是在物理机还是虚拟机 (VM) 中执行。沙盒是一种流行的技术，用于检测样本是否为恶意。沙箱分析二进制文件在受控环境中执行时的行为。为了克服在计算资源有限的情况下分析大量二进制文件的挑战，使用虚拟机来构建沙箱。为了逃避检测，恶意软件会尝试确定它是在物理机还是虚拟机中执行。当恶意软件发现它正在虚拟机中执行时，它将终止其执行或提供虚假输出以隐藏其真实意图。一些最常见的规避技术涉及恶意软件对其执行环境进行各种系统检查。例如，恶意软件通常会寻找异常的屏幕分辨率、硬盘和物理内存大小。沙箱可以构建对策，例如在这些检查期间向恶意软件返回虚假信息。该博客记录了恶意软件如何通过 CPU 寄存器中的一个位来检测虚拟机或物理机中 CPU 行为的差异。Palo Alto Networks 客户使用类似的沙箱规避技术与Cortex XDR或具有WildFire和威胁防护安全订阅的下一代防火墙，免受恶意软件系列的侵害。

## **具有单个位的单步模式 — 陷阱标志 (TF)**

为了检测沙箱中虚拟机的使用情况，恶意软件可以在启用陷阱标志后检查 CPU 的行为。

陷阱标志 (TF) 是 Intel x86 CPU 架构的 EFLAGs 寄存器中的第 8 个单比特。如果在单条指令执行前启用 TF，则 CPU 将在指令完成后引发异常（单步模式）。此异常会停止 CPU 执行，以允许异常处理程序检查寄存器和内存位置的内容。在允许代码继续执行之前，CPU 还必须清除 TF。

为了确定是否使用了 VM，恶意软件可以在执行导致 VM 在启用 TF 的情况下退出的特定指令（例如 CPUID、RDTSC、IN）后，检查单步异常是否传递给了正确的 CPU 指令。在 VM 退出期间，管理程序（也称为虚拟机监视器 (VMM)）将模拟它遇到的物理 CPU 的影响。

以下指令序列解释了在物理机中启用 TF 后 CPU 的行为。

![](../Images/a94d0dcc0cfb8716571d003e47bb487e.png)

图 1. 启用 TF 的 CPU 指令。  

前三个指令使能 CPU 的 EFLAGs 寄存器中的 TF 位。RDTSC 在启用 TF 的情况下执行。在物理机中，异常将传递给第一条无操作 (NOP) 指令 ( 0x00401073 )。请注意，在启用 TF 的指令执行后立即在指令上发生异常。

![](../Images/3f89c02e0ddcb047928a4a294b30bfaf.png)

图 2. 在物理机中执行。

在 VM 中执行相同的指令序列会产生不同的效果。在 VM 中，执行 RDTSC 将导致 VM 退出。管理程序将执行其模拟 RDTSC 指令行为的常规任务。但是，对 TF 进行错误模拟的虚拟机管理程序的实现将导致 TF 被忽略，并且代码执行将继续到第一条 NOP 指令。在第一条 NOP 指令的执行过程中，TF 仍处于启用状态，因为 TF 未由虚拟机管理程序处理。这会导致在第二条 NOP 指令 ( 0x00401073 )上发生异常。正确的实现将要求管理程序在模拟导致 VM 退出并清除 TF 的指令后注入调试异常。

![](../Images/2c527e3ff15b9e718e077fdd4111f512.png)

图 3. 在虚拟机中执行。  

作为一种沙箱规避技术，恶意软件除了上述指令序列外，还会使用异常处理程序来检查异常发生在哪条指令上。下一节描述了一个恶意软件家族的真实示例，它利用这种技术来逃避沙箱。

## **真实世界的例子**

Lampion 是一个针对葡萄牙用户的恶意软件家族。Lampion 采用了多个系统检查来逃避沙盒检测。其中一项技术是利用单步模式和 TF，如上一节所述。

Lampion 使用 x86 汇编指令和最少的 Windows API 调用实现了所有系统检查。这使得 Lampion 样本可以在沙箱中隐藏它们的行为。如果恶意软件确定它在 VM 内执行，Lampion 样本将终止。系统检查还与多种反逆向工程技术交织在一起，以躲避人类分析师。

## **恶意软件与沙盒作者**

多年来，恶意软件作者精心设计逃避技术以防止有效分析，而沙盒作者则研究新方法来击败这些逃避，这两者之间一直存在着猫捉老鼠的游戏。

这是促使我们在 Palo Alto Networks 构建我们自己的用于恶意软件分析的自定义虚拟机管理程序的主要驱动因素之一。由于我们可以完全控制软件堆栈，包括虚拟化层，因此我们可以对新出现的威胁做出反应。在这种特殊情况下，一旦我们确定了错误模拟陷阱标志的问题，我们的管理程序团队就能够测试和部署修复程序。此后，对于使用此技术的任何恶意软件样本，此规避问题已得到解决。

Palo Alto Networks 客户使用类似的沙箱规避技术与Cortex XDR或具有WildFire和威胁防护安全订阅的下一代防火墙，进一步保护其免受恶意软件系列的侵害。AutoFocus 客户可以使用Lampion标签跟踪此处讨论的恶意软件。其他类似的依赖于滥用 Intel CPU 指令或寄存器的沙箱规避技术对 WildFire 不起作用。
