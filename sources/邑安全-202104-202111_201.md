# Go、Rust "net "库受关键IP地址验证漏洞影响

Go 和 Rust 语言中常用的“net”库也受到混合格式 IP 地址验证漏洞的影响。  

该错误与*net*如何  将 IP 地址视为十进制有关，即使它们以混合（八进制-十进制）格式提供。

因此，依赖*网络的*应用程序可能容易受到不确定的服务器端请求伪造 (SSRF) 和远程文件包含 (RFI) 漏洞的攻击。 

此前，该缺陷影响 了数以千计的应用程序所依赖的网络掩码库的各种实现 。

后来，名为*ipaddress*的 Python 标准库  也被发现存在漏洞。

## 前导零更改 IP 地址

本周，在DEF CON，安全研究人员*Cheng Xu, Victor Viale, *Sick Codes*, Nick Sahler, Kelly Kaoudis, *opennota**和 John Jackson已披露的一大缺陷关于Go和Rust语言中常用的 "net "库。

该漏洞，通过CVE-2021-29922（生锈）和CVE-2021-29923跟踪（用于Golang）关注如何 *网* 柄混合格式的IP地址，或者更具体地说，当一个十进制IPv4地址中包含前导零。

在 GitHub 上简单搜索“ import net ”就会发现， 仅依赖于*net *库的Go 就有超过 400 万个文件。

IP 地址可以用多种格式表示，包括十六进制和整数，尽管最常见的 IPv4 地址以十进制格式表示。

例如，BleepingComputer 的 IPv4 地址以十进制格式表示为 104.20.59.209，但同样可以用八进制格式表示为 0150.0024.0073.0321。

假设您获得了一个十进制格式的 IP 地址 127.0.0.1，它被广泛理解为本地环回地址或 *localhost。*

如果您要为其添加 0 前缀，应用程序是否仍应将 0127.0.0.1 解析为 127.0.0.1 或其他内容？

在您的网络浏览器中试试这个。在 BleepingComputer 的测试中，在 Chrome 的地址栏中键入 0127.0.0.1/ 会使浏览器将其视为*八进制* 格式的 IP  。

在按下 Enter 或 Return 键时，IP 实际上会更改为其十进制等效值 87.0.0.1，这是大多数应用程序处理此类模糊 IP 地址的方式。 

![](../Images/d0091c87aafebfd00a858d9b66375496.png)

大多数网络浏览器（如 Chrome）会自动补偿混合格式的 IP。 

需要特别注意的是，127.0.0.1 不是公共 IP 地址而是环回地址，但是，它的歧义表示将其更改为公共 IP 地址，从而导致完全不同的主机。

但是，在*网络*库的情况下，任何前导零都将被简单地剥离和丢弃。

根据 IETF 草案 （该草案在正式化为规范之前已过期），如果前缀为“0”，则 IPv4 地址的部分可以解释为八进制。

因此，有关如何解析混合格式 IPv4 地址的规则因应用程序而异。

例如，Go 和 Rust 中的 *net *模块 将 IPv4 地址的*所有*八位字节都视为十进制，如研究人员的报告 \[ 1 , 2 \] 所示。

因此，如果开发人员使用 *net* 来验证 IP 地址是否属于某个范围（例如，根据访问控制列表 (ACL) 解析 IP 列表），则对于基于八进制表示的 IPv4 地址而言，结果可能会出错.

![](../Images/92bd3ad5c7755d0b2ad6b5c783630e95.png)

使用 Rust*网络*模块的PoC 代码 显示混合格式的 IP 被视为十进制

这可能会导致应用程序中出现不确定的服务器端请求伪造 (SSRF) 和远程文件包含 (RFI) 漏洞。

## 多种应用程序和语言受到影响

Go 和 Rust 不是唯一受此错误影响的语言。

这个混合格式的 IP 地址验证错误以前影响了 Python 的 *ipaddress* 库 (CVE-2021-29921)、 网络掩码 实现 (CVE-2021-28918、CVE-2021-29418) 和类似的库。

在大多数情况下，该错误被评为具有高或严重的严重性：

![](../Images/6a22a519b58818668a750d29dd967e89.png)

根据项目维护者的说法，Golang 的 *net *模块将在（测试版）1.17 版中发布补丁 \[ 1 , 2 \]。

*Sick Codes *与 BleepingComputer 分享了一些见解：

“Go 漏洞的影响比 Rust 稍小，因为它只处理 CIDR 块。”

“然而，Kubernetes 挑选修复方法已经足够重要了。” \*\*

“总而言之，由于它们是标准库更改，会影响用该语言本身编写的所有项目，因此他们需要进行大量测试或使补丁变得多余，”  *Sick Codes*在电子邮件采访中告诉 BleepingComputer。

对于 Rust， 正如 BleepingComputer 所确认的那样，*网络*库中已经合并了 一个 修复程序：

![](../Images/54c9b5949cc187620724ae88488e1965.png)

修复推送到 Rust 语言的 网络 模块(GitHub) 

Rust 语言用户应使用包含 此漏洞缓解措施的1.53.0 或更高版本。
