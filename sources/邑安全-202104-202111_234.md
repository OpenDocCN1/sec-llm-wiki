# 一步一步分析勒索软件Darkside（下）

在本文中，我们继续从技术角度为读者深入分析勒索软件Darkside。

**线程活动：sub\_4095AB**

该线程首先会解密以下信息：

![](../Images/02d9af7ddc263be7d18a4b382149b605.png)

Darkside勒索软件的版本也被解密，如下所示：

![](../Images/9cbf6c3d553a03971d7a1c27985a7e16.png)

然后，该软件将解密另一个JSON结构，将用于收集本地机器的数据：

![](../Images/106e197306157a76f495a35cf6389f2c.png)

之后，该进程会检查驱动器的类型，并寻找DRIVE\_REMOVABLE（0x2）、DRIVE\_FIXED（0x3）和DRIVE\_REMOTE（0x4）：

![](../Images/2bc27749e4c447df0b510f09e070055a.png)

GetDiskFreeSpaceExW函数用于检索目标驱动器的信息，如存储容量和可用空间：

![](../Images/0830efb1cd49f6115e96bd24943af566.png)

NtDuplicateToken被用来复制一个现有的令牌，并获得一个新的访问令牌的句柄（0xC = TOKEN\_DUPLICATE | TOKEN\_IMPERSONATE | TOKEN\_QUERY 和 0x2 = TokenImpersonation）： ![](../Images/2fcf30888127e71e868fb88fcc8b92b7.png)

然后，通过调用ZwSetInformationThread例程来修改线程的模拟令牌，如图83所示（0x5 = ThreadImpersonationToken）：

![](../Images/7b7755b99b1dc847b3628fa7bab53e9c.png)

同时，该勒索软件还会检索与当前线程相关的用户名，以及本地机器的NetBIOS名称：

![](../Images/327ba571415dc275c1c8559addffeddc.png)

![](../Images/349c0867ca477e2c55756ebf2abe312b.png)

另外，机器的当前语言是从“LocaleName”值中检索的，如下图所示：

![](../Images/23a2e86807efba23bf9cad96ef08b0dd.png)

NetGetJoinInformation用于获取本地计算机的联接状态信息：

![](../Images/25387eeee4ae4a34cf93db7371fcb4e6.png)

通过查询“ProductName”值可以提取Windows的产品名称，通过查询“ProductID”值可以提取Windows产品ID，具体如下图所示：

![](../Images/76a4cb1d1f5bf7bad758c6f41c6343d0.png)

![](../Images/63b937ef919a9e7173da4abdadedccaa.png)

该恶意软件构造了以下JSON，其中包含要传输给C2服务器的数据：

![](../Images/42c4b01456f38f1ceff63dda33aed155.png)

最终数据如下JSON格式所示：

![](../Images/24db70044364ac49f033b893064ebac7.png)

上面的数据将通过自定义加密算法进行加密：

![](../Images/b9dbeb8a95f9d1d5d7d3a9dd3e25ee99.png)

![](../Images/ef02d4260176895b5342efc155fac69e.png)

加密运算的结果是base64编码的，如下所示：

![](../Images/7a2d35888570209922f620f58f7ca220.png)

 ![](../Images/5054a0e1ea01b8553f0165cdc51ce71d.png)

下面的函数用于生成2个随机的4字节值，这些值将用于网络通信。实际上，该恶意软件是使用诸如RDRAND和RDSEED之类的指令来生成随机数（如果支持的话）的，我们将下文对其进行更深入的解读（它也用于生成Salsa20矩阵）：

 ![](../Images/81a5d05364f142ca23f8fb6f71d1610d.png)

网络请求的参数具有以下结构:random\_number1=base64(encryptionresult)&random\_number2=visit\_uid：

![](../Images/03a2ac9b6aa92d867376dd52defe8beb.png)

InternetOpenW函数是使用恶意软件解密的用户代理作为参数调用的：

![](../Images/d6157e028cf840207dc0876e32db948a.png)

InternetConnectW用于连接到端口443上的一个C2服务器(Baroquetees\[.\]com)：

![](../Images/866c3446ca30f63bb484e69df27f6d75.png)

然后使用HttpPopenRequestW例程创建HTTP请求句柄，如图100所示：

![](../Images/bacbf0019abfc319e202b199e509c8d7.png)

此外，这里还有一个对InternetSetOptionW API的调用，该API用于设置句柄的安全标志(0x1f=INTERNET\_OPTION\_SECURITY\_FLAGS)：

![](../Images/78f7ed1919d34f6eccb7e821aa9b3313.png)

然后，该恶意软件使用HttpSendRequestW将POST请求发送到C2服务器：

![](../Images/fb342aca618f8ac28caeab478c3d4027.png)

![](../Images/857f33671df0d6c1beffab4491ea0419.png)

服务器返回的状态代码可以使用HttpQueryInfoW API进行检索(0x13=HTTP\_QUERY\_STATUS\_CODE):

![](../Images/69dd65e68367ace9bfc1c2208bf214f0.png)

有趣的是，该勒索软件预期的并不是200状态代码，而是500（内部服务器错误）。如果状态代码不是500，它将使用第二个C2服务器Rumahsia\[.\]com，并重复上述所有步骤：

![](../Images/83dfdc613a880d292f24e16fbc764ec3.png)

![](../Images/64f9f9d36002039a1d13eb2865329c44.png)

接下来，我们继续分析主线程。

这个二进制程序将遍历机器上可用的卷，并使用CreateFileW例程来打开它们：

![](../Images/c5ba8eff6476cda3e1f36e54ef0a4731.png)

DeviceIoControl被用来获取关于磁盘分区的类型、大小和性质方面的信息（0x70048 = IOCTL\_DISK\_GET\_PARTITION\_INFO\_EX）：

![](../Images/8ce38bd84f4cb8420fe080bc5102baad.png)

然后，使用CreateThread创建了一个新的线程：

![](../Images/a2d64f0d6e79375bede3922d99b3bd44.png)

**线程活动：sub\_407558**

该线程做的唯一活动是使用GetLogicalDriveStringsW API来检索本地机器上的有效驱动器：

![](../Images/452f2c5b202f7253ddba5118d765c24b.png)

如果卷没有与其相关联的驱动器号，那么该勒索软件就会调用SetVolumeMountPointW API，如下图所示：

![](../Images/a64efbcb90642feb1dcaf4ef9b32d739.png)

该恶意程序的目标位以下类型的驱动器：DRIVE\_REMOVABLE（0x2）、DRIVE\_FIXED（0x3）和DRIVE\_REMOTE（0x4）：

![](../Images/dec4f505313981ad4ca0dd51d04af389.png)

CreateFileMappingW函数被用来创建一个命名的文件映射对象（名称为“Local\\job0-< Process Id>”则意味着该对象是在会话命名空间中创建的）：

![](../Images/44a32b5629d8eba0ccd694ac6dc7a40c.png)

然后，通过调用MapViewOfFile例程(0xF001F=FILE\_MAP\_ALL\_ACCESS)，将文件映射的视图映射到进程的地址空间：

![](../Images/1c9b04cd745f36b93a2f182d36a0fc94.png)

同时，它还会创建名为“local\\\\job0-< process id >-event”的命名事件对象：

![](../Images/1c9b04cd745f36b93a2f182d36a0fc94.png)

该勒索软件利用3个参数启动自己，新进程将执行相应的加密操作：

![](../Images/4d1f87e81d7fc0058b55c29dbb028d84.png)

OpenMutexW用于打开名为“global\\\\t-job0-< process id >”的命名互斥锁（目前不存在）：

![](../Images/783213ac8e6e0b1d8e8f86d7f0e5b530.png)

通过调用OpenEventW API(0x1F0003=EVENT\_ALL\_ACCESS)打开前面创建的事件对象，如图118所示：

![](../Images/30ff0c23006058cbc64240a42ee29637.png)

之后，它将创建一个与文件句柄无关的I/O完成端口，主线程将使用该端口向辅助线程发送待加密的数据：

![](../Images/1f0a4364b00bbedad29964f826ca25d0.png)

使用CreateThread例程创建了两个不同的线程来处理文件的加密任务：

![](../Images/a35eb15df69e301d821985ed424a8900.png)

创建用于赎金说明的README< RansomPseudoValue >.TXT文件，并填充到恶意软件加密的每个目录中：

![](../Images/188ded4b069d43bf6430ab227baa24f3.png)

不过，该进程会避免加密某些特定文件，如下图所示：

![](../Images/12e5864010cd5fc6b12b764e6c91a816.png)

对于扩展名包含在前面解密的文件扩展名列表中的文件，也不会被加密：

![](../Images/c1315d879263efedb313c072cb5eaaff.png)

使用CreateFileW和ReadFile函数打开和读取每个目标文件：

![](../Images/5a059cf22ec66a2dff7556cb163166cd.png)

![](../Images/60fc3685286bffb67b639cf4a1ee7bb0.png)

修改文件扩展名，使其包括< ransompseudovalue >，如下所示：

![](../Images/5f43034bbbca1eed1aa777bcdb287914.png)

同时，还会调用CreateIoCompletionPort函数，将现有的I/O完成端口与FileHandle参数相关联：

![](../Images/a6efd014bdd4d799545643bb15a44545.png)

RSA公开指数和RSA模将用于Salsa20矩阵的加密过程，我们将在后面介绍：

![](../Images/85df6ffe6faf22f2e428e30a650b82a2.png)

该勒索软件会检查处理器是否支持RDRAND和RDSEED指令。如果支持的话，它将使用其中一个指令来生成56个随机字节，并将8个NULL字节添加到生成的缓冲区中。如果这些指令都不支持的话，该恶意软件将使用rdtsc指令生成确定性的时间戳，以用于提供一个64字节的Salsa20矩阵。

![](../Images/6b227e85d3fb5f8671503c8e90ff1ba8.png)

 ![](../Images/13a63b84a28a8370898850ba3d0ee66e.png)

该线程给出了RSA-1024算法的自定义实现（它不依赖于Windows API）。简单说，就是数据d通过公式（d^exponent）%modulus来生成相应的密文。原始模数的计算是使用加法和减法进行的，下面显示的是部分实现代码：

![](../Images/0465faa7965ef185e29a4a899d9a71f2.png)

![](../Images/5be86609b95ac43c79925b6a265cd1f7.png)

Salsa20矩阵使用自定义RSA实现进行加密，如图133所示：

![](../Images/9f8ffced8d46fc6baa47fd04054c53ad.png)

然后，使用一个自定义的“哈希”函数进一步处理上述加密结果，从而生成一个16字节的输出结果：

![](../Images/dcad1dfb10706f5dba71e0837fba0d70.png)

将被加密的文件内容追加到将发送到工作线程的缓冲区中：

![](../Images/a0da1c7326817d54ac522db1984a9ce5.png)

Salsa20矩阵也被添加到缓冲区中，它将被工作线程用来加密文件：

![](../Images/c0b4edbcbd88f840ba66f6807f8cac2c.png)

**线程活动：sub\_405E7C（文件加密）**

文件内容使用自定义的Salsa20实现进行加密，并用密文覆盖缓冲区中的明文：

![](../Images/027cb3ed73c340b2d7ad5f08c6c67e57.png)

下面是自定义实现中的一个代码片段：

![](../Images/2f35f8c266785001dedd529290c624cd.png)

先把加密的内容被写入原来的文件，然后写入加密的Salsa20矩阵和哈希值，如以下图所示：

![](../Images/2f35f8c266785001dedd529290c624cd.png)

![](../Images/400643c95265ae0e9c36d6d415e8abe3.png)

对于这个线程的分析到此结束。下面，我们继续分析主线程。

如果当前目录包含“backup”，那么恶意软件就会将其删除：

![](../Images/4098f70609ce85d2c7bacc6e67c0ea99.png)

主线程通过调用PostQueuedCompletionStatus例程将上述缓冲区（包括要加密的文件内容等）发送给工作线程：

![](../Images/8f46bf5a2c6776a5ea9f3afb8759c695.png)

我们还发现了一个函数，我们认为它是用来传播恶意软件到域控制器的（我们的环境中没有）。它将调用DsGetDcNameW、DsGetDcOpenW和DsGetDcNextW等函数：

 ![](../Images/1cffaee38a2898dc8c44c8b2f54980e9.png)

Darkside使用NetShareEnum API枚举所有网络共享，并通过迄今为止描述的主要加密例程对每个共享进行加密处理：

 ![](../Images/cefbc0908d2e6fc66f1cbe0669f87e9e.png)

**线程活动：sub\_4096A4**

下面的JSON也会被线程解密：

![](../Images/fbf6111d334635a889eb6d9782599c58.png)

该文件通过调用RegCreateKeyExW打开以下注册表项：

![](../Images/2ab89392337acbed56cfe66a2682de9a.png)

通过调用RegQueryValueExW函数检索产品ID：

![](../Images/12a46cddb5958451c719732c61f2f806.png)

计算机GUID是从注册表中提取的，它是表示计算机的唯一标识符：

![](../Images/16c29d2c5fc72e1426ba0c62ed61ae71.png)

![](../Images/033bf1a237a7b41a1a1ccfd8e7e65f0c.png)

加密完成后，该恶意软件会向C2服务器发送加密统计信息，如：受害者ID、uid、加密文件数、加密文件大小、跳过文件数和运行时间。最后的JSON结构如下所示：

![](../Images/64de7ef81128f60c50c128f9ffcb5308.png)

如前所述，缓冲区是用自定义算法加密的，并且是经过base64编码的。发送到C2服务器的请求如下图所示：

![](../Images/33f81895e0cf56abb9f5293ef18fa37c.png)

如果启用了自删除功能，Darkside将使用shellexecutew删除自身：

![](../Images/1b6c12153a42eb6c9e3058d59a319bb9.png)

![](../Images/1b67d7c6800c9ef45c7995c63d9da048.png)

正如我们在分析开始时所指出的那样，这个二进制程序可以用不同的参数运行：

◼1个参数：filename，表示只对指定的文件进行加密

◼2个参数：“-path” directory，表示只对指定的目录进行加密

◼3个参数：“-work”worker0job0-< process id >，这是由初始进程产生的，前面已经讲过了

在处理快捷方式文件（.lnk文件）时，该勒索软件会以不同的方式处理不同的情况。简单来说，它希望从这个链接中提取文件的完整路径。为此，它会使用{000214F9-0000-0000-C000-0000000046}（IShellLinkW接口）的CLSID来调用CoCreateInstance API：

![](../Images/9289df6836e425f89c10254de2c39d31.png)

不幸的是，Scylla在这里无法带来帮助，因为它不能为我们提供相应的方法。我们发现接下来的两个函数调用可以提取文件/目录的路径：

![](../Images/f6282b2f51655efcd6d0ea2ff0b792d5.png)

![](../Images/e9f1de35a914b4ea57b00b90c27278c8.png)
