Apache Tomcat 中的 HTTP 请求走私漏洞自 2015 年就存在

更多全球网络安全资讯尽在邑安全

项目维护者警告说，Apache Tomcat 中的 HTTP 请求走私漏洞“至少自 2015 年以来”就已存在。
Apache Tomcat 是一个开源 Java servlet 容器，由 Apache 软件基金会维护。
在网上发布的发行说明（不安全链接）中，Tomcat 的维护人员透露，该漏洞在该软件的多个版本中被发现。
“在某些情况下，Apache Tomcat 没有正确解析 HTTP 传输编码请求标头，导致在与反向代理一起使用时可能会请求走私，”它写道。
“特别是：如果客户端声明它只接受 HTTP/1.0 响应，Tomcat 会错误地忽略传输编码标头；Tomcat 尊重身份编码；并且 Tomcat 没有确保分块编码（如果存在）是最终编码。”
Apache Tomcat 项目管理委员会成员 Mark Thomas 告诉 The Daily Swig，该漏洞“自
至少 2015 年”。
“它可能在此之前就已经存在，但这是当前支持版本的最早版本，”托马斯说，但补充说，该委员会 - 完全由志愿者组成 - 不会检查较旧的、不受支持的版本。

Tomcat服务器补丁

HTTP 请求走私是一种黑客技术，可用于干扰网站处理从一个或多个用户收到的 HTTP 请求序列的方式。
请求走私漏洞通常很关键，可以让攻击者绕过安全控制，未经授权访问敏感数据，并直接危害其他应用程序用户。
马萨诸塞州波士顿东北大学 NEU SecLab 的研究人员 Bahruz Jabiyev、Steven Sprecher 和 Kaan Onarlioglu 向 Apache 软件基金会报告了该漏洞。
它还没有被分配一个 CVSS 分数。但是，Tomcat 安全团队在“低、中、重要或关键”的范围内将其评为“重要”。
托马斯在 2021 年 5 月 7 日“负责任地”报告了该漏洞。“我们在 5 月 11 日之前私下同意了一个补丁（实际上是一系列三个补丁），”托马斯告诉 The Daily Swig。
Thomas 说，这些补丁于 6 月 8 日公开，尽管公开公告被推迟到 7 月 12 日，因为某些版本在 JSP 处理中包含显着的回归。
受影响版本的用户应更新到 Apache Tomcat 10.0.7 或更高版本、9.0.48 或更高版本或 8.5.68 或更高版本。该问题在 9.0.47 和 8.5.67 中得到修复，“但这些版本的发布投票没有通过”，Thomas 说。
