更多全球网络安全资讯尽在邑安全

Volexity 经常与来自世界各地的老练、积极和装备精良的威胁参与者严重攻击的个人和组织合作。其中一些个人或组织很少或不定期受到攻击，而其他人几乎每周都会看到一连串的攻击。无论攻击频率如何，Volexity 都会保持警惕，寻找新旧威胁，无论它们如何表现。

今年早些时候，Volexity 检测到针对客户的复杂攻击，该客户是多个中国高级持续威胁 (APT) 组织的主要目标。这种特殊的攻击利用零日漏洞来破坏客户的防火墙。Volexity 观察到攻击者实施了一个有趣的 webshell 后门，创建了第二种持久性形式，并最终对客户的员工发起了攻击。这些攻击旨在进一步破坏托管该组织面向公众的网站的云托管 Web 服务器。这种类型的攻击很少见且难以检测。这篇博文旨在分享高度针对性的组织所面临的问题以及防御此类攻击的方法

检测防火墙违规

2022 年 3 月 8 日，通过其网络安全监控服务，Volexity 检测到来自客户的 Sophos 防火墙的异常活动。Volexity 收到了来自其部署的自定义签名的警报，这立即使该设备受到了威胁。这导致了一项取证调查，其中 Volexity 从 Sophos 防火墙获取内存、选择性文件和磁盘映像。对数据的分析导致在防火墙上发现了一个后门，以及可追溯至 2022 年 3 月 5 日的利用证据。Volexity 的调查在发现攻击者使用防火墙进行人为攻击后进一步扩大。中间人（MITM）攻击。攻击者使用从这些 MITM 攻击中收集的数据来破坏防火墙所在网络之外的其他系统。

在 Volexity 的调查之后，Sophos 于 2022 年 3 月 25 日发布了一份公告，描述了 CVE-2022-1040 涵盖的防火墙中的远程代码执行 (RCE) 漏洞（由第三方提交）。Volexity 认为这与调查中利用的漏洞相同，因为客户的防火墙是最新的并且符合远程利用的标准。Volexity 将这些攻击归因于之前以“ DriftingCloud ”的名义向 Volexity 威胁情报客户报告的中国 APT 组织。（注意：本文中的信息在 TIB-20220408 和 TIB-20220429 中可供 Volexity Threat Intelligence 客户使用。）

在这篇博文中，Volexity 将讨论以下内容：

  • 攻击者在成功入侵 Sophos Firewall 后采取的行动

  • 攻击者如何使用通过 MITM 攻击收集的会话 cookie 来破坏防火墙所在网络之外的外部系统

  • 攻击者安装的 Webshell 和恶意软件，以及成功入侵后对外部系统执行的操作

  • 监控网络中类似危害的建议

攻击流程概述如下：

突破防火墙

Volexity 在检测到源自 Sophos Firewall 到其客户网络中的关键系统的可疑流量后，首先发现了入侵活动。很快确定该设备可能受到损害，并立即进行了调查。Volexity 首次收集的内存从设备中，然后收集了完整的磁盘映像以协助其调查。Volexity 怀疑可能涉及 Sophos 防火墙的面向外部的用户门户组件；鉴于它是该网络中唯一暴露在 Internet 上的组件，因此它很可能是一种攻击媒介。因此，Volexity 在开始其他分析任务之前查看了设备的 Web 访问日志。这些日志揭示了针对有效 JSP 文件 (login.jsp) 的重大且重复的可疑访问，如以下示例日志条目所示：
[07/Mar/2022:09:25:58 +0000] <redacted> "POST /userportal/webpages/myaccount/login.jsp HTTP/1.1" 200 - 0 "https:// <redacted>/userportal/jlbed/ fikds4/BQ.jsp" "Mozilla/5.0 (Windows NT 6.1; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/99.0.4844.51 Safari/537.36"
这些请求显示成功的 HTTP 200 状态代码。然而，对“login.jsp”底层代码的检查并没有发现任何异常或修改会导致 Volexity 认为该文件已被后门。应该注意的是，在 Referrer 字段中看到的文件“BQ.jsp”不作为用户门户的一部分存在。
此时，Volexity 实施了一项计划，在设备上设置数据包捕获以拦截入站 Web 请求。Volexity 执行此操作时，攻击者处于活动状态，因此没过多久就捕获了流量并确认此流量异常。

图 1. DriftingCloud 与 Sophos Firewall 上的 webshell 交互
在捕获网络流量之前，Volexity 使用Volexity Surge Collect捕获系统内存。从网络流量中观察到的数据进一步有助于对内存样本的调查。事实证明，网络流量与内存样本分析相结合，可以有效地将攻击者活动的各个方面拼凑在一起。
确定的一项是与向设备的用户门户组件（图 2）发出的可疑请求相邻的大型 base64 字符串的存在，类似于图 1 中看到的那些。

图 2. 内存中的可疑字符串示例
使用相邻的字符串作为枢轴点，Volexity 在防火墙的磁盘上搜索包含与内存中 base64 blob 相邻的字符串类似的文件。在此过程中，Volexity 发现攻击者修改了防火墙的以下合法组件：
/usr/share/webconsole/WEB-INF/classes/cyberoam/sessionmanagement/SessionCheckFilter.class
调查显示攻击者对该文件进行了timestamp，因此其最后修改时间与该目录中的其他文件相同。此 CLASS 文件是 Sophos Firewall 的合法组件。其目的是根据当前 URI 使用正确的参数调用 SessionCheckHelper，从而验证用户是否有有效的会话（如果没有，则指示他们登录）。如果不对防火墙的 Web UI 进行逆向工程，Volexity 会假定当对 Sophos Firewall 门户的任何组件发出任何请求时都会调用此帮助程序。攻击者创建了他们自己的包含恶意逻辑的文件版本。使用ByteCodeViewer对恶意文件进行反编译如图 3 所示。

图 3. 恶意 SessionCheckFilter.class 文件的反编译
总之，添加到 SessionCheckFilter.class 的恶意代码使用了以下工作流程：
  • 检查传入的请求 URI 或“Accept”HTTP 标头是否包含字符串“Applicationssid”；如果失败，请继续使用合法功能。
  • 检查传入请求是否为 POST；如果失败，请继续使用合法功能。
  • 如果两项检查都通过，则使用 base64 和 AES 使用密钥“a918c0e8d8153bfc”解码 POST 正文；这可能是攻击者使用的明文密码的部分（16 个字符）MD5。
  • 解码的结果应该是另一个使用SecureClassLoader加载的 CLASS 文件。
该工作流有效地使用 Webshell 为 Sophos Firewall 设置了后门，该 Webshell 可以通过攻击者选择的任何 URL 进行访问。攻击者试图通过针对“login.jsp”文件的请求访问此 webshell 来进行混入。乍一看，这似乎是一次暴力登录尝试，而不是与后门的交互。日志文件中唯一出现异常的真实元素是引用者值和响应状态代码。CLASS 文件被编译，而不仅仅是文本文件，这使得这样的编辑不像类似的 webshell 案例那样简单。攻击者可能会反编译该类（通过从防火墙或用于测试的本地防火墙检索），然后在重新编译并将其放置在设备上之前在本地创建自己的版本。
Volexity 使用此 webshell 解码了攻击者发出的一些请求，发现攻击者使用的是公开可用的BEHINDER框架。有趣的是，Volexity 认为这与最近通过 CVE-2022-26134对 Confluence 服务器系统进行零日攻击的一个或多个中国 APT 组织所利用的框架相同。

防火墙的其他发现

除了这个 webshell 组件，Volexity 还发现了攻击者在 Sophos 防火墙上执行的其他几项操作，这些操作进一步危害了受害者并确保了持久性。
  • 攻击者在防火墙上创建了 VPN 用户帐户和关联的证书对，以促进合法的远程网络访问。
  • 作为利用 Sophos Firewall 的一部分，攻击者在磁盘上的以下路径写入并执行了一个文件：
    /conf/certificate/pre_install.sh
  • 执行时，“pre_install.sh”文件会运行恶意命令来下载二进制文件，执行它，然后将其从磁盘中删除。在分析时，命令和控制 (C2) 服务器中不存在二进制文件，并且它不存在于内存或磁盘中。该文件似乎不是防火墙的合法组件。

超越防火墙

虽然获得对目标 Sophos Firewall 的访问权限可能是主要目标，但这似乎并不是攻击者的唯一目标。Volexity 发现攻击者利用他们对防火墙的访问权限来修改针对特定目标网站的 DNS 响应，以执行 MITM 攻击。修改后的 DNS 响应是针对属于受害组织的主机名，并为其管理和管理内容。这使攻击者能够从对网站内容管理系统 (CMS) 的管理访问中拦截用户凭据和会话 cookie。Volexity 确定，在多种情况下，攻击者能够使用他们劫持的有效会话 cookie 访问受害组织网站的 CMS 管理页面。

结论

DriftingCloud 是针对五毒相关目标的有效、装备精良且持续存在的威胁参与者。他们能够开发或购买零日漏洞来实现他们的目标，在进入目标网络时使天平向有利于他们的方向倾斜。对于支持目标群体或由目标群体组成的组织来说，拥有适当的网络监控解决方案以便在不可避免地发生妥协时识别它们至关重要。网关设备的入侵是 Volexity 调查的事件的常见根本原因，并且入侵它们通常会使攻击者领先于防御者，这些防御者通常专注于这些设备上不存在的端点和 EDR 解决方案。
Sophos 在其公告中发布了有关缓解此漏洞的建议。具体而言，该咨询指出以下内容：
“Sophos 观察到此漏洞被用于针对主要在南亚地区的一小部分特定组织。我们已直接通知这些组织中的每一个。Sophos 将在我们继续调查时提供更多详细信息。Sophos 无需采取任何行动启用了“允许自动安装修补程序”功能的防火墙客户。启用是默认设置。
为了一般性地识别与所讨论的类似的攻击，Volexity 建议如下：
  • 部署网络安全监控和其他机制来检测和记录来自网关设备的流量。
  • 对于基于 Unix 的网络服务器，请考虑使用auditd以便在发生危害时更轻松地进行调查。
  • 询问外围设备（例如防火墙）供应商他们有哪些能力来检测危害，以及如果发生危害，您可以使用哪些方法来调查危害。一些供应商不允许访问外围设备，这会使对可疑入侵的调查变得复杂。
为了防止这些特定的攻击成功，Volexity 建议如下：
  • 使用此处 列出的 GitHub 上的 YARA 规则来识别可疑的相关活动。
  • 在此处阻止GitHub 上 列出的 IOC 。
