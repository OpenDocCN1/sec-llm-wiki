# 远程性玩具可能会为您的爱情生活增添趣味 - 但骗子也可能从中获得乐趣

CyberNews 的一项调查显示，由于安全功能不佳，Lovense 远程性玩具用户可能面临威胁行为者的风险。

Lovense 吹嘘说，它的远程性爱玩具会增加你的性关系。通过使用无线遥控器，您可以自定义振动并根据您的身体进行调整，或者为房间内甚至数英里外的人带来快乐。

遥控性玩具自 2010 年就出现了。当时，由于智能手机不那么流行，这些玩具由 Skype 控制。随着蓝牙和WiFi的到来，遥控情趣用品市场显着增长。如今，它们由我们手机上的应用程序控制，使用 IP、WebRTC 和蓝牙协议来传输数据。

总部位于香港的 Lovense 是最大的遥控性玩具品牌之一。因此，CyberNews 团队决定测试其设备和接口以检查它们的安全性。

研究人员发现了一些令人担忧的安全实践，包括缺乏混淆、依赖第三方框架和应用程序编程接口 (API) 来交付跨平台应用程序、围绕蓝牙协议的大量公共漏洞、一些可能的拒绝服务 (DoS) 案例，以及据 CyberNews 团队称不应访问的几个访问点。

2017 年，Lovense 客户抱怨该应用程序记录了用户的远程性爱会话。该公司承认存在影响 Android 用户的“小错误”，但坚称没有数据被发送到公司的服务器，而且录音只存在很短的时间。

“用户安全一直是我们的重中之重，这也是 Lovense 投入大量资源参与私人漏洞赏金计划的原因。我们是第一家这样做的性科技公司，”在研究小组将其发现告知制造商后，Lovense 告诉 CyberNews。

该公司表示，它会更新其软件以解决出现的任何问题，并致力于保护用户的隐私和安全。

“我们还与 Internetofdon.gs 和 ESET Research 等网络安全实验室合作，解决漏洞和软件错误，为我们的产品和服务的用户提供安全、可靠和流畅的体验，”它补充说。

## 低于标准的分数

为了开展这项调查，CyberNews 团队使用了市场上最全面的移动应用安全评估框架之一——移动安全框架 (MobSF)——来分析 Lovense Remote Android App 的代码。MobSF 是安全研究人员用来对 Android 应用程序执行静态和动态分析的一组工具的接口。

MobSF 给出了低于平均水平的安全分数——100 分中的 19 分——因为它在 Lovense Remote Android 应用程序中检测到了三个跟踪器。请注意，较低的分数是因为应用程序合法运行所需的许多权限。

它还检测到旧 Android 设备（版本 5.1.1、6.0、6.0.1、7.0、7.1.1、7.1.2 和 8.0）上的 Janus 漏洞、十个危险权限以及允许向所有人发送明文或未加密流量的不安全配置域。

Lovense 指出，Janus 漏洞的范围相当有限：“它只影响使用 Android 原始基于 JAR 的签名方案签名的应用程序，该方案在 2016 年发布的 Android 7.0 中被 Signature Scheme v2 取代。我们在除 Google 之外的常用渠道中使用 v2玩。对于在 Google Play 上发布的包，我们使用 AAB，它不受此影响。”

至于十大“危险权限”，Lovense 表示，所有这些都是启用应用程序功能所必需的。它需要网络和蓝牙连接，以及 Android 6.0 及更高版本的 GPS 权限才能使用蓝牙。未经用户明确同意，该应用不会应用此权限。

仅仅通过拦截来自远程控制链接的流量，CyberNews 的研究人员就设法将 11 个地址与 Lovense 的运营相关联：lovense.com；测试2.loveense.com；apps2.loveense.com；应用程序.loveense.com；测试.loveense.com；c.loveense.com；coll.loveense.com；活动.loveense.com；www.loveense.com；hytto.com；和 126.com。

Lovense 似乎还连接到他们的测试服务器地址——一种通常用于试验网站布局、购物车和会员资格等的方法。但此类地址——仅用于测试且通常用于发送、接收或调用数据的应用程序的端点——不应在网站上线后暴露。

Lovense 指出，它偶尔会通过连接到其测试服务器将一些域留在生产中进行内部测试，但声称“我们的普通用户永远不会使用这些测试域。”

Lovense 使用 Cloudflare Web 应用防火墙 (WAF) 和 IP 代理工具，这意味着恶意行为者仍然难以确定攻击面。

但是，一些地址似乎通过确认他们使用的服务器而泄露了有价值的信息。Cybernews 认为这些接入点——或者至少是关于 IP 地址的信息——应该被完全屏蔽。

大多数用于控制远程设备的 Lovense 前端网站都是基于廉价且相当陈旧的技术构建的，可以追溯到 2016 年左右。它的跨平台应用程序使用 ElectronJS 框架，该框架被认为存在许多公开列出的缺陷。

然而，该公司否认了这种过时的技术可能容易受到网络攻击的担忧。

“Electron 是一个很好的框架，越来越多的组织正在使用——比如 Facebook Messenger、Twitch 和 Microsoft Teams，”它说。“它可能是一个易受攻击的框架，但我们会使其尽可能安全。”

跨平台应用程序还使用 Web 上的控制界面。当用户打开应用程序并连接他们的玩具时，它会生成一个与他们的性伴侣共享的链接。一旦他们打开该链接，他们就会看到一个控制性玩具的用户界面。如上所述，该技术相当陈旧且很少更新，因此可能容易受到攻击。

## 缺乏混淆

Lovense 的跨平台 Windows 和 macOS 运行应用程序使用 JavaScript。来自可执行文件的简单字符串转储揭示了这些应用程序中使用的数百行未混淆（清晰可读）的代码。

请记住，Lovense 为其客户开发此类谨慎的产品，它应该尝试隐藏他们的代码或他们所依赖的第三方的代码。未混淆的代码可能导致逆向工程——威胁参与者或竞争对手解构代码以提取设计信息或用于更多恶意目的。

该公司表示：“除了一些不重要的代码或无法混淆的代码外，我们已经混淆了大部分核心代码。”

## DoS 风险

上面提到的 Lovense 服务器的一些端点设置为长时间超时，这可能会导致对其服务器的 DoS 攻击。但是，Lovense 指出它使用 Cloudflare，并且这些端点无法到达其服务器。

还需要注意的是，由于 Lovense 设备依赖于蓝牙，因此它们容易受到蓝牙 DoS 的影响。如果发生此类攻击，合法用户将无法正确使用他们的性玩具，也无法使用控制它们的应用程序和系统。

## 使用蓝牙控制的性玩具真的安全吗？

蓝牙协议因其易受数据泄露、DoS 和代码执行漏洞的影响而臭名昭著。

2004 年，诺基亚和爱立信承认，他们的一些蓝牙设备很容易通过蓝牙连接未经授权访问无线设备的信息，称为“bluesnarfing”。这意味着攻击者可以读取、修改和复制用户的通讯录和日历而不会留下任何痕迹。

去年，新加坡科技与设计大学 (SUTD) 的研究人员在影响数十亿终端用户设备的商用蓝牙芯片组中发现了一组漏洞，即 BrakTooth。部分漏洞仍未修复。

这项研究的结果令人震惊。发现的漏洞之一甚至设法实现了任意代码执行。因此，我们不禁想知道，使用蓝牙控制的性玩具是否安全？

更重要的是，2017 年，意大利信息安全研究员 Giovanni Mellini 在一篇博客文章中透露，他使用蓝牙低功耗 (BLE) 扫描仪成功破解了 Lovense 对接插头性玩具。

Lovense 承认蓝牙可能不是一个非常安全的协议，但它仍然是实用且常用的。

“例如，\[电动汽车制造商\]特斯拉在其钥匙上使用蓝牙，”洛文斯说。“我们正在尽最大努力使其尽可能安全。基于它的安全性和便利性，我们仍然认为它是情趣用品的不错选择。恶意方需要在用户将其与自己的设备配对的同时处于 Lovense 玩具的蓝牙范围内。

“虽然理论上是可能的，但要让 Lovense 玩具被黑客入侵，需要有一组非常特殊且不太可能发生的情况。万一玩具连接被恶意方拦截，只需手动关闭玩具即可。”

## 结论：Lovense 应该提升其安全性

Lovense 正试图通过在其产品中实施加密技术来提升其安全性。然而，其安全实践的实施和一般监督似乎相当草率。

其所有应用程序缺乏混淆、使用第三方库、API 以及测试服务器的简单枚举表明总体上缺乏对用户隐私的关注。

此外，设备使用的蓝牙协议也不是最安全的选择。针对公司的网络攻击可能导致 DoS、禁用设备或数据泄露。

所有 Lovense 应用程序 - Cam、Remote 和 Connect - 都需要注册，其中存储了用户的电子邮件、用户名和密码。如果攻击者以 Lovense 的服务器为目标，他们很可能会追踪此类敏感信息。
