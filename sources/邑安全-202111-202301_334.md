# Dev 破坏了 NPM 库的“colors”和“faker”

流行的开源库“colors”和“faker”的用户在看到他们的应用程序、使用这些库、打印乱码数据和破坏后都惊呆了。

一些人猜测 NPM 库是否已被破坏，但事实证明还有更多事情要做。

这些库的开发者故意引入了一个无限循环，将 数千个 依赖“颜色”和“伪装”的项目阻塞。 

该*颜色*库收到超过2000万下载量每周上NPM独自拥有近19000项目依靠它。鉴于，*faker* 在 npm 上每周获得超过 280 万次下载，并拥有超过 2,500 名家属。

## 开源革命？

流行的开源 NPM 库“colors”（又名GitHub 上的colours.js ）和“faker”（又名GitHub 上的“faker.js” ）背后的开发人员故意在其中引入了恶作剧的提交，这些提交正在影响依赖这些库的数千个应用程序.

昨天，亚马逊云开发工具包(aws-cdk)等流行开源项目的用户 在看到他们的应用程序在控制台上打印乱码消息时感到震惊。

这些消息包括文本“LIBERTY LIBERTY LIBERTY”，后跟一系列非 ASCII 字符：

最初，用户怀疑这些项目使用的库 'colors' 和 'faker' 受到了破坏 \[ 1 , 2 , 3 \]，类似于coa、rc和ua-parser-js 库去年被恶意行为者劫持的情况。

但事实上，正如 BleepingComputer 所见 ，似乎是*颜色*和*伪造*者背后的开发者故意 提交了造成重大错误的代码。

这位名叫 Marak Squires 的开发人员昨天在版本*v1.4.44-liberty-2 的**colors.js*库中 添加了一个“新的美国国旗模块” ，然后他将其 推送到了 GitHub和 npm。

![](../Images/e3a1fc38f427c6a3758de8539441e8fe.png)

  

  

  

  

'Marak' (GitHub)做出的 colors.js 恶作剧提交

  

  

代码中引入的无限循环将无限期地继续运行；对于任何使用“颜色”的应用程序，在控制台上无休止地打印乱码的非 ASCII 字符序列。

同样，*faker* 的破坏版本“6.6.6”发布到 GitHub 和 npm。

“我们注意到 v1.4.44-liberty-2 版本的颜色中有一个 zalgo 错误，”开发人员嘲笑道。

“请知道我们现在正在努力解决这个问题，很快就会有解决方案。”

Zalgo 文本是指某些出现故障的非 ASCII 字符。

开发人员的这种恶作剧背后的原因似乎是报复——针对大型公司和开源项目的商业消费者，他们广泛依赖免费和社区支持的软件，但据开发人员称，他们不回馈社区。

2020 年 11 月，Marak 曾警告称，他将不再通过“免费工作”来支持大公司，商业实体应考虑分叉项目或以每年“六位数”的工资来补偿开发人员。

“尊敬的，我不再用我的免费工作来支持财富 500 强（和其他小型公司）。没有什么可说的，”开发人员之前写道。

“以此为契机，向我发送一份六位数的年度合同，或者分叉项目并让其他人参与其中。

有趣的是，截至今天，BleepingComputer 注意到“伪造者”GitHub 存储库的README页面也被开发人员修改为引用 Aaron Swartz  ，并指出：“Aaron Swartz 到底发生了什么？”

Swartz 是一位美国程序员、企业家和著名的黑客活动家，他在一场官司之后 自杀了。

为了让所有人都可以免费访问信息，这位黑客主义者从麻省理工学院校园网络上的 JSTOR 数据库下载了数百万篇期刊文章，据称是通过反复轮换他的 IP 和 MAC 地址来绕过 JSTOR 设置的技术块，并麻省理工学院。

在此过程中，Swartz 可能违反了《计算机欺诈和滥用法》并面临刑事指控，最高可判处 35 年监禁。

## 不可思议的蠕虫罐头

马拉克的大胆举动打开了一罐虫子，引起了不同的反应。

开源软件社区的一些成员赞扬了开发人员的行为，而其他人则对此感到震惊。

“显然，‘colors.js’的作者因为没有得到报酬而生气......所以他决定每次加载他的图书馆时都打印美国国旗...... WTF，”一位用户在推特上写道。 

有些被称为 这个实例“又一个OSS开发商去流氓”，而资讯安全专家 *VessOnSecurity*称为行动“不负责任”，指出：

“如果您在使用免费代码时遇到业务问题，请不要发布免费代码。通过破坏您自己广泛使用的东西，您不仅会伤害大企业，还会伤害任何使用它的人。这会训练人们不要更新，'coz stuff可能会破裂。”

据报道，GitHub 已暂停开发者的帐户。而且，这也引起了不同的反应：

NPM 已恢复为 faker.js 包的先前版本，Github 已暂停我对所有公共和私人项目的访问。我有100个项目。#AaronSwartz pic.twitter.com/zFddwn631S

— 马拉克 (@marak) 2022 年 1 月 6 日

“从 \[GitHub\] 删除您自己的代码违反了他们的服务条款？WTF？这是绑架。我们需要开始分散托管免费软件源代码，” 软件工程师 Sergio Gómez回应道。

“永远不知道发生了什么，但我将我所有的项目都托管在 GitLab 私有实例上，只是因为这样的事情发生在我身上。永远不要相信任何互联网服务提供商，”另一位发推文说。

“Marak 做了很多假货和颜色，做了大量的项目，并期望什么都不会发生？” 一位名叫 Piero 的开发人员说。

请注意，Marak 出人意料的举动是在最近引发 Internet 的 Log4j 崩溃之后发生的。

开源库 Log4j 广泛用于各种 Java 应用程序，包括由公司和商业实体开发的应用程序。

但是，在大规模利用 Log4shell 漏洞后不久，随着越来越多的 CVE 被发现，开源库的维护者在假期期间无偿地修补项目。

人们开始担心大型企业如何习惯于“利用”开源；不停地消耗它，但没有给予足够的回报来支持那些通过放弃空闲时间来维持这些关键项目的无偿志愿者。

一些人还批评了追捕 Log4j 维护者的网民和漏洞赏金猎人，他们已经“在缓解措施上夜以继日地工作；修复、文档、CVE、对查询的回复等”。\[ 1，  2，3 \]。

一位 Twitter 用户写道： “对 colour.js/faker.js 作者破坏他们自己的软件包的回应确实说明了有多少企业开发人员认为他们在道德上有权获得开源开发人员的无偿劳动而无需做出任何回报。”

关于OSS 可持续性问题，时间会告诉我们开源软件的未来会怎样。

与此同时，“colors”和“faker”NPM 项目的用户应该确保他们没有使用不安全的版本。降级到较早版本的颜色（例如 1.4.0）和 faker（例如 5.5.3）是一种解决方案。
