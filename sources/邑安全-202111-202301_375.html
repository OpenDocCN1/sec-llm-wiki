五眼联盟发布针对 Log4j 漏洞的“联合咨询和扫描程序”

更多全球网络安全资讯尽在邑安全

来自澳大利亚、加拿大、新西兰、美国和英国的网络安全机构周三发布了一份联合公告，以应对恶意对手广泛利用 Apache Log4j 软件库中的多个漏洞。

“这些漏洞，尤其是 Log4Shell，非常严重，”情报机构在新 指南中表示。“老练的网络威胁行为者正在积极扫描网络，以可能在易受攻击的系统中利用Log4Shell、CVE-2021-45046和CVE-2021-45105。这些漏洞很可能会在很长一段时间内被利用。”

攻击者可以通过向易受攻击的系统提交特制请求来利用 Log4Shell (CVE-2021-44228)，导致该系统执行任意代码。另一方面，CVE-2021-45046 允许在某些非默认配置中远程执行代码，而 CVE-2021-45105 可能被远程攻击者利用来导致拒绝服务 (DoS) 条件。

自从本月这些漏洞被公众知晓以来，未打补丁的服务器已经受到勒索软件组织和民族国家黑客的围攻，他们利用攻击媒介作为渠道来访问网络，以部署 Cobalt Strike 信标、加密矿工和僵尸网络恶意软件。

美国联邦调查局 (FBI) 对这些攻击的评估也提出了一种可能性，即威胁行为者正在将这些缺陷纳入“正在寻求采用越来越复杂的混淆技术的现有网络犯罪计划”。鉴于漏洞的严重性和可能增加的漏洞利用，我们敦促组织尽快识别、缓解和更新受影响的资产。

为此，美国网络安全和基础设施安全局 (CISA) 还发布了一个扫描实用程序，用于识别易受 Log4Shell 漏洞影响的系统，与CERT 协调中心 (CERT/CC) 发布的类似工具相同。

然而，以色列网络安全公司 Rezilion 在本周发布的一项评估中发现，商业扫描工具无法检测环境中 Log4j 库的所有格式，因为这些实例通常深深嵌套在其他代码中，这表明此类实用程序中的“盲点”和静态扫描的局限性。

“最大的挑战在于在生产环境中检测打包软件中的 Log4Shell：Java 文件（例如 Log4j）可以嵌套在其他文件的几层深处——这意味着对文件的浅层搜索不会找到它，”Yotam Rezilion 的漏洞研究负责人 Perkal说。“此外，它们可能以多种不同的格式打包，这对在其他 Java 包中挖掘它们造成了真正的挑战。”

Log4Shell 的公开披露还导致许多技术供应商为包含该缺陷的软件部署补丁。最新发布更新的公司是NVIDIA和HPE，加入了一长串发布安全公告的供应商名单，其中详细说明了受该漏洞影响的产品。

政府采取的最新措施是 Apache 软件基金会 (ASF) 周一发布了 Apache HTTP Server 更新以解决两个缺陷——CVE-2021-44790（CVSS 评分：9.8）和CVE-2021-44224（CVSS 评分：8.2)——前者可以被远程攻击者武器化以执行任意代码并控制受影响的系统。
