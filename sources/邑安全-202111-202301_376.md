# Apple修复了macOS 漏洞，该漏洞可绕过 Gatekeeper 安全功能

Apple 已经解决了 macOS 漏洞，即使在完全修补的系统上，未签名和未公证的基于脚本的应用程序也可以利用该漏洞绕过所有 macOS 安全保护机制。  

如果它们绕过自动公证安全检查（扫描恶意组件和代码签名问题），则允许应用程序通过Gatekeeper启动，这是一种 macOS 安全功能，旨在验证下载的应用程序是否经过公证和开发人员签名。

一旦针对绕过漏洞 ( CVE-2021-30853 )的基于脚本的恶意应用程序在目标系统上启动，攻击者就可以使用它们来下载和部署第二阶段恶意负载。

Apple 已通过 2021 年 9 月发布的安全更新解决了macOS 11.6 中的此漏洞，该更新增加了改进的检查。

## 用shebang绕过看门人

CVE-2021-30853 Gatekeeper 绕过漏洞由 Box Offensive 安全工程师Gordon Long发现并报告给 Apple 。

他发现，即使自动隔离，从 Internet 下载的特制基于脚本的应用程序在启动时也不会显示警报。

“特制”部分需要创建一个应用程序，该应用程序使用以 shebang (!#) 字符开头的脚本，但将行的其余部分留空，这会告诉 Unix shell 运行脚本而不指定 shell 命令解释器。

这会导致 Gatekeeper 绕过，因为 AppleSystemPolicy 内核扩展通常自动调用以执行安全检查（签名和公证）的 syspolicyd 守护进程在启动脚本时不再触发检查，而未指定解释器。

基本上，如果脚本使用了shebang (!#) 但没有明确指定解释器，它将绕过Gatekeeper 安全检查。

![](../Images/686b8da5ce7758b43dfa0d329020645f.png)

“syspolicyd 守护进程将执行各种策略检查并最终阻止不受信任的应用程序的执行，例如那些未签名或未经公证的应用程序，”安全研究员帕特里克沃德尔解释说。

“但是，如果 AppleSystemPolicy kext 决定不需要调用 syspolicyd 守护程序怎么办？那么，这个过程是允许的！如果这个决定是错误的，那么，你有一个可爱的文件隔离、关守和公证旁路。”

正如 Wardle 所揭示的那样，攻击者可以通过诱骗目标打开恶意应用程序来利用此漏洞，该应用程序也可以伪装成外观良好的 PDF 文档。

此类恶意负载可以通过多种方法传送到目标系统上，包括中毒搜索结果、虚假更新以及从链接到盗版软件的站点下载的木马应用程序。

![](../Images/e1421c17ea764fb9a270f39fdcd1c240.png)

## 恶意软件利用的类似漏洞

这并不是 Apple 修复的第一个 macOS 错误，该错误将使威胁行为者能够在完全修补的 Mac 上完全规避操作系统安全机制，例如 Gatekeeper 和 File Quarantine。

4 月，Apple 修补了Shlayer 恶意软件运营商在野外利用的一个零日漏洞，以绕过 macOS 自动安全检查并在受感染的 Mac 上部署额外的有效负载。

正如Jamf Protect 检测团队发现的那样，从 2021 年 1 月开始，Shlayer 威胁参与者开始使用未签名和未经公证的恶意软件攻击 macOS 用户，这些恶意软件利用了零日漏洞（跟踪为CVE-2021-30657）。

微软还在10 月份发现了一个 macOS 漏洞，称为 Shrootless，跟踪为CVE-2021-30892），可用于绕过系统完整性保护 (SIP) 并执行任意操作、将权限提升为 root 并在受感染设备上安装 rootkit。

“恶意应用程序可能能够修改文件系统的受保护部分，”苹果在修补 Shrootless 漏洞后发布的安全公告中表示。
