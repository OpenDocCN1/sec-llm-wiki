## 审计源码，发现漏洞

既然连接不上，那么只能审计一下源码了，先拿工具扫一下。

![](../Images/9b5a111bae004fb60e4f838f4069d5f9.png)

  

经过查看，发现`/application/index/controller/system/SystemUpgradeclient.php`中的`setcopydel`方法可以任意提交参数。

![](../Images/fa841a7cd06626d672139bfef82d0885.png)

可以看到以post方式接收了俩个参数，一个是`id`，一个是`ids`

```
`  if (is_array($post['ids' ])) {foreach ($post['ids'] as  $file) {'public' . DS . 'copyfile'   . $file);if ($post['id' ]) {'public' . DS . 'copyfile' . $post['id' ];// echo $copyFile;exit;    `
```

`ids`是需要数组的，然后拼接路径，传入`$fileservice->del_dir()`方法中。`id`没有类型判断，直接拼接路径传入`$fileservice->del_file()`方法中。那来看看这俩个方法中做了什么事情。`$fileservice->del_dir()`方法是删除目录

![](../Images/c3b33725acefb9f8b5128d34fdee032e.png)

删除目录，看来这是一个任意文件删除漏洞,分析下源码。

```
`  static function del_dir($dirName)  if (!file_exists($dirName)) # 判断文件或目录是否存在，不存在就返回false  return false  ;# 打开一个目录，读取它的内容 while   ($fileName = readdir($dir))'/'  . $fileName;if ($fileName != '.' && $fileName != '..'  )if (is_dir($file))  # 判断是不是目录,是目录就在调用一次本身方法  self  ::del_dir($file);else  # 删除文件  return rmdir($dirName);     # 删除目录    `
```

`$fileservice->del_file()`方法是删除文件

![](../Images/3d8f6a03774d677361c36952113cb8cf.png)

这就没有什么好说的了，判断文件是否存在，然后删除。但是，这是hw啊，这漏洞什么用都没有啊，只能继续找其他漏洞了。  
经过漫长的查找终于在`\application\admin\controller\setting\SystemConfig.php`中的发现了`view_upload`上传的方法。

![](../Images/f59282a882d9accc7a9bb834ba98ff8e.png)

这个方法中，`type`为3的时候是上传文件的，然后传入`Upload::file`方法。

![](../Images/9377ede7ea591c52816246576c080925.png)

  
但是在这个方法中判断了后缀名不能为`php`,但是在win的系统中，可以通过以下的一些方法绕过。

```
`  .php.  `
```

经过尝试，发现使用`1.php::$DATA`这样的方式可以绕过，构造的post数据包为：

```
`  POST /index.php/admin/setting.system_config/view_upload.html HTTP/1.1  403 0 //xxx.com 1  5.0 (Windows NT 6.1; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/76.0.3809.132 Safari/537.36 0.9,image/webp,image/apng,*  /*;q=0.8,application/signed-exchange;v=b3  `
```

  
成功上传文件，但是这个文件上传需要后台登录才能上传，后台之前就已经爆破过了，没有爆破出来账号密码。但是这个程序有`install`文件,根据经验知道程序安装文件都会在安装后创建一个文件，来判断是否已经安装，所以在看看是否和我想的一样。

![](../Images/58ce58972dd34cbc02281ec3e25441de.png)

可以看到确实是生成了一个`install.lock`文件来判断是否安装成功，那么我们可以通过之前的任意文件删除漏洞来删除这个文件让系统进行重装。但是这个删除文件，对系统进行重装，这就得问问裁判组能不能让了啊，经常协商，他们觉得这个程序不重要，在能保证不破坏程序的时候可以做。既然他们说可以了，那么我就小心翼翼的构造一下post包，别真的给程序破坏了。  

## 利用漏洞拿到shell

删除`install.lock`文件的数据包：

```
`  POST /index.php/admin/system.System_Upgradeclient/setcopydel HTTP/1.1  `
```

  

![](../Images/340bfb9b82f32818a0fb5f4e931fe185.png)

返回值是成功的，看来没有问题，那就到重装系统的时候了，为了不对系统的数据造成破坏，我们对系统安装需要连接的mysql放到自己的服务器中。  

![](../Images/db60279b88537cedb59d1dcb34b52282.png)

成功登录后台，然后上传shell，还是之前的那个数据包，没有什么好说的，拿到shell后我用nc反弹一下，查看了系统上都有什么程序，发现这个系统上存在五个程序。

![](../Images/8bf0b9a86cbf7513907d7cf88bd5e8de.png)

既然上来了，那就收集一下信息，然后把流量代理出去扫描一下，结果发现：

![](../Images/1720ae3387e4da4ced4dc48a8d374a73.png)

只是扫描了一下下而已，这个多弱口令，这稳了，通过这些弱口令在来做横向移动，一共拿下了近百台的机器，得了3600分。
