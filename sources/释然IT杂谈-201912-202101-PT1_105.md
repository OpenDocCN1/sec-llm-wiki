# 基于链路聚合提升带宽：winserver2016对接华为S5720交换机

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzIxMTEyOTM2Ng==&mid=2247491243&idx=1&sn=45e3cdf70134d031e0063237f9903f5e&chksm=975b5bd2a02cd2c48a5a40b35b4553895f17503294188b3d31168de2baf90139f96d839a120c&scene=126&sessionid=1681667496#rd](http://mp.weixin.qq.com/s?__biz=MzIxMTEyOTM2Ng==&mid=2247491243&idx=1&sn=45e3cdf70134d031e0063237f9903f5e&chksm=975b5bd2a02cd2c48a5a40b35b4553895f17503294188b3d31168de2baf90139f96d839a120c&scene=126&sessionid=1681667496#rd)

![](../Images/466cf2e323f34e12ae772fa52183a53d.png)

**一、 背景**  

**1、server端**企业中一台server2016利用两块1G网卡组成teaming生成一张2G的虚拟网卡，业务数据在这张带宽为2G的虚拟网卡上运行。这块网卡不仅带宽可以提升1倍，而且可以实现冗余，负载均衡，故障自动切换，保证业务数据不中断，突破网络带宽瓶颈，是文件共享服务器，存储服务器，高并发文件访问服务器的理想选择。这个技术在server 2012以上集成。**2、switch端**交换机端需要支持并配置LACP（(Link Aggregation Control Protocol,链路汇聚控制协议），本次实验使用华为的s5720交换机。

**3、服务器的两块网卡必须接到同一台交换机上。**

**二、网络拓扑图**

![](../Images/48457651d407f3db6ac453d2ba08ef43.png)

**三、配置方式**

**1、Server 2016服务器端**

**1.1**首先命名两张网卡NIC 1和NIC 2分别为100和101，使其处于启用的状态。

![](../Images/2762b445384ab13c1781f94d66a36160.png)

100网卡的速度是1G

![](../Images/6faf0cd264badf518bd2321f007451c2.png)

101网卡的速度是1G

![](../Images/7f40bc46e4a4cf4c034bb03f48916154.png)

**1.2**管理员帐户运行PowerShell,输入以下命令

new-netLbfoteam teamnic -teamingmode switchindependent回车，其中teamnic是组合后虚拟网卡的名称，可以自己定义。按照提示输入成员网卡名称100和101，y(或者直接回车)。

![](../Images/d8a4f73a146655db4bd3d9e755f628cb.png)

**1.3**打开本地服务器, 点击 "(1) 配置此本地服务器"

![](../Images/320544f0aa61f50989b6a021de67094e.png)

1.3.1在本地服务器的属性窗口，看到"NIC组合---已启用",同时看到我们刚才创建的teamnic也是已启用状态.

![](../Images/c2ea11a7d6812141fe389ec560002497.png)

**1.3.2**点击NIC组合中的"已启用"，出现下图

![](../Images/3fb25e9964369a0c021520cf9380dfbe.png)

现在的teamnic的成组模式是交换机独立，负载均衡是动态，这种配置可以实现链路冗余，故障切换，但是在运行时,不能达到网速合并，最大网速是单张网卡速度1G，不能达到组合后的2G。

**1.3.3**点击teamnic,修改

成组模式选择LACP，负载平衡模式选择地址哈希，如下图，点击确定。

![](../Images/edaf4cb7186b25de62d489f7e6632d3a.png)

此时，teamnic的成组模式已经改变为LACP，负载平衡改变为地址哈希，如下图

![](../Images/100f94a235dbbff38d507f7da955b8af.png)

我这里是给teamnic配置完IP地址的截图，如果出现错误，可以在网络配置中配置teamnic（组合后的虚拟网卡）的ip地址。

![](../Images/8c06d5796d40bb95c1cfa785d747e40f.png)

此时，teamnic的网卡速度是2G。

![](../Images/4c1bc48ecda142ea265cbc54e47ce35c.png)

这样在服务器端配置完成，如果出现错误，先不要理会，下面需要在交换机上配置LACP。

**2、交换机端配置**

**登录到S5720交换机，用命令行配置，服务器网卡接入的是交换机的5口和6口。**  

**<hexinin> system-view**

**\[hexinin\] interface eth-trunk 1 # 创建Eth-Trunk1**

**![](../Images/3e8be66b0fd95d3b93b16c17b448f7d6.png)**

**\[hexinin -Eth-Trunk1\] mode lacp # 配置LACP模式**

**![](../Images/5de97c6eba42ec6329e3c59ef5b3f489.png)**

**\[hexinin -Eth-Trunk1\] port link-type access # 配置eth-trunk 1为access模式**

**![](../Images/22f43086afe0f2991ba833d2ebc3bd8f.png)**

**\[hexinin -Eth-Trunk1\] disp this # 显示eth-trunk 1的配置**

**![](../Images/13f76cb703443f2c2f4eaec23d2cd223.png)**

**\[hexinin\] interface g0/0/5 #进入接口5**

**\[hexinin-GigabitEthernet0/0/5\] eth-trunk 1 # 把接口5加入到eth-trunk 1中**

**![](../Images/ddc1bc61961b7454dfb3d59821b6566e.png)**

**\[hexinin\] interface g0/0/6 #进入接口6**

**\[hexinin-GigabitEthernet0/0/6\] eth-trunk 1 # 把接口6加入到eth-trunk 1中**

**![](../Images/cd303868f24f67daa4258d5545edb03c.png)**

**\[hexinin -Eth-Trunk1\] load-balance ? # 查看负载均衡模式**

**![](../Images/d7a6f06e2f5574fd0178221f4a9243a1.png)**

**S5720默认负载均衡模式是src-dst-ip（源目的IP），所以这里不用设置，并且在eth-etrunk1的接口模式下用disp this命令不会显示该平衡模式（load-balance src-dst-mac），由上图还可以知道哦这种平衡是以哈希运算统计,如果其他型号交换机可能是src-dst-mac，需要配置，具体需要测试和咨询供应商。**

**\[****hexinin\] disp eth-trunk 1 # 显示eth-trunk 1的信息**

**![](../Images/7005095e19e8a2dba540745c64ec69c1.png)**

**由上图可以知道，eth-trunk 1是LACP模式，状态是up，成员接口是5和6并且都已经选中，说明配置正确，工作正常。**

  

**四、测试**

此时我们在服务器上测试，从两台不同的PC处copy大文件，一个是5.72G，一个是4.16G，这里的文件必须大，或者参与的PC多，达到相当大的流量，否则测试效果不明显。由下图可以知道网卡速率是1.1G，大于单张网卡的1G，说明链路聚合成功。

![](../Images/bcabdac0542a0aa08b15a5e400eadc92.png)

同时在交换机上查看接口状态（很关键）

\[hexinin\] disp int brief # 显示接口的信息

![](../Images/b12d726a7d6d7525b3b15b0b970bf916.png)

由上图悉知，交换机接口5和接口6的oututi都有流量，说明数据负载到两个接口上，LACP配置成功。
