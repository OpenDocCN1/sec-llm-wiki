EVE相关软件包后台回复“EVE"获取

一、EVE-NG介绍

我们在学习和实践网络技术的时候，很少有采用真的交换机、路由器。所以这时候就需要虚拟的网络设备来搭建虚拟的网络环境，以给我们的学习和实践带来便利。
EVE-NG(Emulated Virtual Environment-NEXT Greneration)下一代仿真虚拟环境是一种新兴的虚拟无缝仿真平台，可以满足当今 IT 世界的需求。在 IT 的世界里为网络工程和信息安全等专业人士提供了无限遐想与实践的机会。
EVE-NG涵盖了Dynamips、IOL、QEMU三大组件。不仅可以模拟各种网络设备比如cisco、juniper、VMware等厂商的设备，而且支持各种windows、ubuntu、centos、macos等主机操作系统。也可以运行zabbix、openstack等监控/云计算操作系统。并且可以和wireshark、VMware协同工作的能力，提升虚拟网络的仿真程度。

二、EVE-NG优缺点

优点：

只需要浏览器即可登录，安装putty，secureCRT等软件即可使用，使用起来十分的轻量级
关闭本地的浏览器时，远端服务器上的实验拓扑不会关闭，随时使用随时连接，很方便

缺点：

各种网络虚拟机的安装很繁琐，需要转格式
原生支持的虚拟机种类和GNS3比相差甚远
三、适用人群

1、网络工程：模拟Cisco、H3C、Huawei、Juniper、Palo Alto、Check Point等厂商的设备；

2、系统工程师：可以模拟Linux、Windows、MacOS等操作系统；

3、虚拟工程师：可以模拟Vmare、Citrix、KVM、QEMU、OpenStack、Docker等虚拟化环境；

4、储存工程师：可以模拟Open-E、Synology存储的操作系统；

5、其他：还可以模拟大量设备来支撑开发环境。

EVE-NG具有如此之多的功能，主要在于其集成了众多的系统与软件。


四、组件介绍

EVE-NG的三大组件包括Dynampis、IOL、QEMU，这三个组件完成了EVE-NG平台上所有设备的虚拟化，是支撑EVE-NG平台的核心。

1、Dynamips：是一个基于虚拟化的技术模拟器，用于运行Cisco路由器真实的操作系统，主要支持Cisco的1700、2600、2691、3600、3725、3745、7200等路由器平台。它能运行标准的IOS镜像，尽管模拟器较陈旧，但至今任然有非常多的人在使用。

2、IOL（Cisco IOS on Linux）是运行在Linux系统上的Cisco IOS，相比Dynamips，IOL能更好的支持二层交换特性，是Cisco路由器和交换机的操作系统，它是模拟Cisco设备的最佳选择之一，但存在不少Bug。建议使用IOL设备模拟Cisco的二层、三层设备。

3、QEMU（Quick Emulation）：是纯软件实现的虚拟化模拟器，几乎可以模拟任何硬件设备。因为 Qemu 是纯软件实现的，所有的指令都要经 Qemu 翻译，所以性能非常低，大多数的做法都是配合 KVM 来完成虚拟化工作，KVM 是硬件辅助的虚拟化技术，主要负责比较繁琐的 CPU 和内存虚拟化，而 Qemu 则负责 I/O 虚拟化，两者合作各自发挥自身的优势，相得益彰。


五、客户端基础软件包

1、SecureCRT

SecureCRT是一款支持SSH（SSH1和SSH2）的终端仿真软件，同时支持Telenet和Rlogin等多种协议，用于连接Windows、UNIX、Linux和VMS的理想工具。

2、Xshell

Xshell是一个强大的安全终端模拟软件，它支持SSH1、SSH2以及Microsoft Windows平台的Telnet协议，对商业收费，对个人和教育用户免费。

3、VNC

VNC（Virtual Network Computing）是虚拟网络计算机的缩写，是一款优秀的远程控制工具软件，是基于UNIX和Linux操作系统的免费开源软件。

4、WireShark

WireShark是一个网络封包分析软件。网络封包分析软件的功能是撷取网络封包，并尽可能显示出最为详细的网络封包资料。Wireshark使用WinPCAP作为接口，直接与网卡进行数据报文交换。

5、VPCS

VPCS（Virtual PC Simulator，虚拟PC模拟器），是EVE-NG唯一一个默认集成的设备，它不是一台传统的PC。它只是一个可以运行在Linux和Windows上的程序，占用CPU和内存极少，它可以支持少量的有关网络方面的命令，主要用于网络测试。它的最大优势是可以使用最小的资源代价模拟PC。


六、EVE-NG的网桥

（1）Bridge：仅作用在EVE-NG的Lab内部，为节点对象互联互通，充当“傻瓜”交换机。

（2）Management（Cloud 0）：桥接到EVE-NG的第1块网卡中，即管理IP桥接的网卡。

（3）Cloud 1：桥接到EVE-NG的第二块网卡。

（4）Cloud 2：桥接到EVE-NG的第三块网卡。
