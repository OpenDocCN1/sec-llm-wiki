**12.1 ****文化问题**

**传统行业：防止信息泄露、防止内部舞弊，侧重控制型****互联网公司：需要频繁访问互联网，重点要考虑办公体验，否则无法落地**

## **1.2   安全域划分**

*   **OA服务器域**
    

1.  **内部经营类**
    
2.  **研发体系**
    
3.  **测试类**
    
4.  **运维类资产管理**
    

*   **桌面环境**
    

1.  **研发类：重度PC用户，网络限制少，但需要防止代码泄露**
    
2.  **运维类：办公和运维分开，运维需要通过堡垒机访问线上服务器区**
    
3.  **市场运营类：中度PC用户，需要一定互联网访问需求，但对限制性安全策略抵触力相对不高**
    
4.  **客服和销售类：轻度PC用户，办公需求单一，接触信息敏感，管理上应严格限制**
    

  

## **12.3   终端管理**

1.  **补丁管理**
    
2.  **组策略**
    
3.  **杀毒软件**
    
4.  **网络准入**：
    

*   **802.1x**
    
*   **基于终端管理软件的C/S模式**
    

**12.4 ****安全网关**

*   **防火墙**
    
*   **UTM、反病毒、邮件网关**
    
*   **堡垒机**
    
*   **行为审计**
    
*   **抗APT、DLP**
    

  

**12.5 ****研发管理**

*   **防泄密**
    

1.  **2台PC：其中一台用于开发，无法直接访问互联网，只能访问另外一台****PC，共享文件夹和剪切板**
    
2.  **通过组策略禁用USB数据传输功能，保留充电和鼠标键盘功能**
    

*   **源代码管理**
    

1.  **统一持续集成和代码托管**
    
2.  **按产品和项目划分权限**
    
3.  **防范开发人员上传代码到GitHub造成代码或密钥等敏感信息泄露**

3.  **入侵检测可统一在服务器端**

## **13.3   KPI**

**类似IT 平衡计分卡评分模型**

1.  **用户满意度**
    

*   **内部用户：高质量的支持，尽可能不降低用户自身工作效率**
    
*   **外部用户：保护用户隐私，不损失用户体验**
    

    2.** IT价值贡献**

*   **花费成本**
    
*   **安全效益，无法很好直接衡量，可看安全指标是否得到持续优化**
    

    3.** IT内部过程**

*   **覆盖率**
    
*   **覆盖深度**
    
*   **检测率/主动止损**
    
*   **TCO/ROI**
    
*   **技术维度指标**
    

    4. **IT学习与革新**

*   **向业界领导厂商学习**
    
*   **应对业务成长的安全能力**
    
*   **应对外部威胁趋势的变化**
    

**13.4 ****外部评价指标**

1.  **攻防能力：安全建设的基础能力**
    
2.  **视野和方法论：安全团队整体产出的瓶颈所在**
    
3.  **工程化能力：单点攻防知识转化为全线防御、纵深防御、自动化的能力**
    
4.  **对业务的影响力：跨组织的沟通能力和推动能力**

# **14      隐私保护**

**隐私保护兴起原因**

*   **互联网公司的兴起，承载了上亿网民数据**
    

**影响业务、品牌、用户流失、触犯法律**

*   **业务角度考虑**
    

1.  **防止盗号**
    
2.  **防止信息过度搜集**
    
3.  **业务遵从隐私保护法**
    
4.  **审计**
    
5.  **法律承诺**
    

**14.1 数据分类**

*   **按敏感程度**
    
*   **按是否结构化**
    
*   **按用户群体**
    

  

**14.2 访问控制**

1.  **用户**
    
2.  **资源**
    
3.  **是否有权限**
    
4.  **有哪些权限**
    
5.  **有效期**
    

**14.3 数据隔离**

1.  **敏感数据与非敏感数据分表分库存储（条件允许分片存储）**
    
2.  **敏感数据集中存储，减少监控成本**
    
3.  **终端设备沙箱隔离**
    
4.  **虚拟化环境采用VPC隔离**
    
5.  **特别敏感需要物理隔离**
    

**14.4 数据加密**

1.  **TDE透明数据加密**
    
2.  **应用级加密**
    
3.  **FPE保留格式加密**
    
4.  **文件/磁盘加密**
    
5.  **噪音混淆**
    

**14.5 密钥管理**

**密钥为加密过程中的单点问题****密钥管理基础设施（KMI）分为2部分：密钥存储和密钥访问授权管理****单一密钥无法支持海量架构，必须为多层级密钥体系****全生命周期管理：创建、激活、禁用、转换、分发、备份、销毁****物理安全：防范云平台、IDC托管方等读取密钥**

## **14.6   安全删除**

**已加密数据：可采用销毁密钥的方式****未加密数据：格式化、重写、消磁等**

## **14.7   匿名化**

**解绑个人隐私和用户行为****不同应用使用不同ID，避免通过多个应用拼图出用户完整偏好**

## **14.8   内容分级**

**对同一个用户的内容进行分级，单一因素认证时，访问权限较低。**  

# **15      业务安全与风控**

## **15.1   对抗原则**

1.  **相对风控而非绝对**
    
2.  **增加黑产成本，而非阻断**
    
3.  **黑产情报收集**
    
4.  **方法比技术更重要**
    
5.  **数据比算法更重要**
    
6.  **勤能补拙（PDCA优化对抗手段）**
    
7.  **忽略性能、用户体验和成本的风控没有意义**
    
8.  **纵深防御**
    
9.  **杀鸡儆猴**
    
10.  **对用户安全教育**
     
11.  **社工库**
     

  

## **15.2   账号安全**

**分为强账号体系和弱账号体系**  

** 1)注册**

*   **验证码：图片、邮件、短信、语音、电话语音**
    
*   **协议可变化：适用于PC客户端**
    
*   **社工库：对比现有用户，提示用户修改密码**
    
*   **根据特征标记灰度，达到一定风险值，提示优惠活动无名额**
    
*   **防止账号枚举**
    

** 2)登录**

*   **风险问题：撞库、暴力破解、盗号登录、非常用设备登录、黑产小号、僵尸号登录**
    
*   **防范：统一登录接口，用户画像（登录地域、IP、可信设备、频率、代理使用习惯）**
    

**3)密保/密码找回：逻辑漏洞**

**  4)多因素认证：付款、密码找回，安装证书等敏感操作**

**  5)多设备登录：同一账号不可在相同平台同时登录（****PC、手机、平板可同时登录）**

**  6)账号共享体系：普通****web只要求一层token，敏感Web需要第二层secure token**

**15.3 电商类**

1.  **恶意下单：侵占库存，使用验证码，未付款超时取消订单，限制下单频率**
    
2.  **黄牛抢单：区分恶意养号，抢购时提示抢购结束**
    
3.  **刷优惠券和奖励：标记账号恶意值（低信誉小优惠），优惠券绑定账号（无法流通交易）**
    
4.  **反价格爬虫：爬虫****IP段，可能不解析JS，缺少正常浏览器正常行为和通信**
    
5.  **反欺诈：注册信息真实性，设备真实性，绑定异常，账号异常，征信数据判断**
    
6.  **信息泄露：撞库，用户信息过度展现，****API滥用，供应链上下游泄露，内鬼**
    
7.  **交易风控：账户安全、客户端安全、证书****PKI，风险评估**
    

  

**15.4 ****广告类**

**点击欺诈，账号标签，用户行为模式分析**

## **15.5   媒体类**

**敏感字过滤，举报功能，人工审核，搜索引擎智能识别**

## **15.6   网游类**

*   **客户端：代码混淆，加密加壳，反调试**
    
*   **网络封包：抗重放**
    
*   **服务端校验：大部分逻辑验证在服务器端，同时校验时钟同步**
    
*   **人机识别：定期弹出验证码，根据地图移动轨迹，鼠标轨迹，物品使用速度**
    
*   **产品内容设计：物品与账号绑定，随时间降低收益，内部经济平衡体系**
    
*   **运营数据监控：监控虚拟装备产出数量，个人成长速度**
    
*   **私服：供应链管理，研发和运营交付信息安全管理**
    

**15.7 云计算**

*   **云厂商角度**
    

**犯罪场所：黄赌毒业务监控，网络攻击发起方监控****肉鸡场：提高安全输出能力，帮助租户解决安全问题**
