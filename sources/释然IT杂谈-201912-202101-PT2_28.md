# **8      入侵感知体系**

## **8.1   主机入侵检测**

### **8.1.1  开源产品OSSEC**

#### **8.1.1.1 特点**

*   **开源**
    
*   **长期维护更新**
    
*   **覆盖主流操作系统**
    
*   **支持云部署**
    
*   **适合中小型网络（服务器小于1W台）**
    
*   **B/S架构**
    
*   **支持二次开发（扫描插件、数据采集、检测规则）**
    

**MIG(Mozilla InvestiGator)**

### **8.1.2  开源分布式取证框架**

**属于事后检测，无法实时入侵检测，可结合OSSEC或OSquery**

*   **文件检测**
    
*   **网络检测**
    
*   **内存检测**
    
*   **漏洞管理**
    
*   **系统审计**
    

**8.1.3 ****OSquery**

**Facebook 开源项目，系统信息可用SQL语句来查询**

**特点：**

*   **本身只获取数据，需要开发日志聚合、云端分析、管理端，才能成为完整的HIDS平台**
    
*   **适合大规模IDC、安全团队有一定开发能力**
    

  

### **8.1.4 自研Linux HIDS系统**

**自研原因：**

*   **商业产品贵，不适合海量环境**
    
*   **商业产品性能无法满足要求**
    
*   **核心业务数据需可控管理**
    
*   **需要和迭代变化快，风险变化快**
    
*   **外部产品无法快速变更应对新漏洞、攻击手法**
    
*   **厂商无法及时响应**
    

  

**8.1.4.1 架构设计**

*   **行业法规需求**
    
*   **基础安全需求**
    
*   **自身业务需求**
    
*   **运维/环境需求**
    
*   **多层级部署，一级基础数据分析和格式化就近部署**
    
*   **容灾备份**
    

  

####   

#### **8.1.4.2 功能模块**

**安全功能、数据传输、管理模块**

**一、安全功能**

*   **基线安全**
    
*   **日志采集**
    
*   **进程信息**
    
*   **网络连接**
    
*   **Webshell**
    
*   **DB审计**
    
      
    

  

**二、数据传输**

**方案**

1.  **syslog转发：优点：实现简单，无法额外开发；缺点：UDP数据波动会丢数据，明文传输。syslog-ng：支持TCP、TLS加密；**
    
2.  **数据直传：适合数据较少，agent几千台量级，如果OSSEC方案；**
    
3.  **数据接收Server：大型互联网需要使用专用数据通道。**
    
      
    

*   **注意数据传输波峰**
    
*   **敏感数据脱敏**
    
*   **数据前后链对账**
    

**三、管理模块**  

*   **健康度监控**
    
*   **自杀机制**
    
*   **部署与更新**
    
*   **自身安全性**
    

  

**8.2 ****检测webshell**

**8.2.1 ****静态检测**

**流程**

1.  **inotify监控**
    
2.  **文件变动**
    
3.  **文件静态扫描**
    
4.  **信息熵对比**
    
5.  **异常业务环境特征分析**
    
6.  **告警**
    

*   **基于黑名单特征字符串、高危函数同时出现：无法应对语法变化**
    
*   **基于信息熵分析：汉字可能影响信息熵**
    
*   **异常业务环境特征：文件属主、生成时间、****inode、上传目录**
    

  

**8.2.2 **** 流量检测**

### 

*   **未修改的webshell**
    

1.  **Webshell名字**
    
2.  **cookie**
    
3.  **POST数据**
    

*   **有修改过的webshell**
    

1.  **访问来源：日常无人访问，仅有少数****IP访问**
    
2.  **历史记录：夜间或其他罕见时间访问，未采用网站统一调用框架代码**
    
3.  **UA：固定的****UA，固定的用户特征访问**
    
4.  **cookie：无网站统一标识**
    
5.  **请求内容：无规范参数，且****POST 数据被加密**
    
6.  **搜索引擎记录：无与网站其他页面的跳转链接，未被搜索引擎爬取**
    

  

**8.3 ****RASP**  

**8.3.1 PHP RASP  
**

**PHP执行时，翻译为opcode，再交由Zend引擎执行，Zend引擎支持扩展，通过Zend扩展实现PHP RASP。****无论PHP代码如何编码混淆，在opcode层都会显形。**

2.  **JVMTI**
    
3.  **Java Agent**
    
4.  **Btrace**
    
5.  **HotCode2**

## **8.4   数据库审计**

### **8.4.1  部署方式**

1.  **旁路型**
    
2.  **主机型**
    
3.  **代理型：最优，适合有数据调用有统一接口的架构使用**
    

**8.4.2 ****攻击检测**

*   **SQL注入**
    

1.  **多个子查询、联合查询且查询系统库表**
    
2.  **可能导致SQL查询失败的语句**
    
3.  **多个联合查询，且子查询非业务所需库表**
    

  

*   **操作违规审计**
    

1.  **账号对应常用DB访问映射**
    
2.  **账户常用的function**
    
3.  **账户+client\_IP与tables的映射**
    
4.  **应用与数据字段的映射**
    
5.  **自然时间+频度与库表映射**
    

  

## **8.5   入侵检测数据分析平台**

### **8.5.1  架构**

**采集与计算分离优点：**

1.  **避免单台服务器被攻击后，安全策略被窃取，攻击者针对性研究绕过手法**
    
2.  **可快速更新检测策略而不影响业务**
    
3.  **原始数据可保存，便于对事件追溯，以及研究新检测策略**
    

  

### **8.5.2功能模块**

1.  **感知能力**
    
2.  **数据分析**
    

*   **单点事件行为分析**
    
*   **上下文事件关联分析**
    
*   **多纬度关联分析**
    

  

**8.6入侵检测数据模型**

1.  **主战场观点**
    
2.  **高维防守**
    
3.  **入侵场景分析提炼策略**
