# 外贸网站之wordpress+woocommerce抗压测试(采集站实战)

近期新冠病毒肆虐，不啦不啦，这种国事岂是我等小民可以议论的，还是我说说我建立的一个新网站吧。最近看到一个国外网站，非常不错，页面数量十万加，关键词也可以，只是SEO做的不行，明明十万级的页面才收录不到3万，那是不是可以采集一下整理到wordpress上，然后抢他的客户？

![](../Images/bfcce38ac993c17a3827e111cc79f791.png)

  

  

说干就干，抄起scrapy就上，mysql应付十万级的数据量还是so easy的，但是在爬取的过程中，由于scrapy需要异步下载图片，在mysql的数据量到3万时，图片才一万多张，明显的被覆盖掉了。由于当时不想恋战，所以每一万网页为一个单元，在程序中控制采集的起始位置与终止位置，完美解决图片下载数量不够的问题；只是跟后期埋了一个坑，后期的项目数量到几百万后，难道还指望一万一万的采集吗？先照顾好眼前再说吧。

![](../Images/7202abc528258fb9b77ac29af8b2b8a8.png)

  

  

几天时间过去，十万页面采集完毕，每一万张图片一个文件夹，每一万条数据一个mysql表，呵呵，前期电梯论坛项目，数据爬取更新问题完美解决：只要在爬虫程序中修改即可。

我的网站采用还是wordpress，但是想把网页全部修改为商品，插件只有woocommerce。安装好插件后，在翻看woocommerce数据库翻了两天，感觉woocommerce的表太乱，直接使用Python操作数据库的话，可能会花费很长的时间。去woocommerce的官网看看，发现woocommerce竟然有API，API地址：https://woocommerce.github.io/woocommerce-rest-api-docs/#introduction，Python连接mysql 然后通过API对商品进行上传，商品图片提前打包上传到服务器即可，图片地址就可以在程序中直接拼接。

由于使用的是woocommerce的API，在Python中每隔一秒钟上传一个商品，不影响网站的正常访问。一万个商品上传大概5-6个小时。那段时间在出差，所以每天晚上睡觉前把程序打开跑。程序跑几天后，谷歌一封邮件：大概意思就是你的商品缺少一些商品信息，想着通过API对商品进行更新；半个月后，商品数量到达10万附近的时候，woocommerce竟然崩溃了。后来不管是如何折腾，重启服务器，重启数据库都不管用。泄气了。（待续）

![](../Images/f69bf354e1abd7d439b8a3efef4c8ad6.png)

  

  

一点感悟吧：

后期scrapy 下载图片的短板必须补上，是否还使用scrapy还是对requests进行封装，这个后边在测试吧；

可以指望wordpress扛起几十万篇文章，但是别想着woocommerce扛起十万的商品。你见过5000个商品的电商店铺，你见过10万商品的店铺吗？个人认为：woocommerce都没有考虑过10万页面。

Wordpress的短板：毕竟我不是学PHP的，毕竟wordpress都已经封装好了，那些功能用不用都在服务器运行，真的不如使用Python的web框架——flask 。Wordpress 对于我而言是一个完整的黑盒，除了直接操作数据库外，什么也做不了。

Mysql 也许暂时没问题，但是当数据量到几千万的时候，还可以吗？还是换成MongoDB吧，也许临时的成本会增加，但是长期而言不算什么
