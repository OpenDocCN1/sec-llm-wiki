前言




随着纳入新基建，区块链技术蓬勃发展产生了大量应用，其中最热门的一个方向当属DeFi去中心化金融。它因提供了从贷款到支付的创新数字金融解决方案而受到称赞。然而伴随着DeFi的火热，DeFi应用所承载的资金量出现了大幅提升。这同时也将大量攻击者的注意力吸引到了这一区块链、智能合约与金融紧密结合的新兴领域。产生了大量攻击事件，造成大量损失。此过程中产生的许多攻击技术手段由于结合了经济学分析，已经逐渐有超出传统安全攻击手法范畴的趋势。作为网络安全的引领者，长亭科技始终紧密关注这一新兴领域。

2020年12月17日，WarpFinance遭到攻击，损失了约 7 Million Dai

2020年12月20日，WarpFinance团队发表文章解释事件。


WarpFinance，作为一个借贷平台，实现了使用LPtoken作为抵押资产进行贷款的功能。在抵押借贷的过程中，WarpFinance需要评估该流动性凭证的价值以确定可以贷出的货币数量。由于WarpFinance对LPtoken的估值算法存在缺陷，导致攻击者可以通过操控池中贵价币的数量，使持有的LPtoken增值，进而可以借出更多的货币。


长亭科技持续关注区块链行业相关安全事件,团队累积近百万行区块链源码安全审计经验。针对此次事件，长亭科技区块链安全团队将分析该漏洞的原理，并叙述攻击流程。

_calculatePriceOfLP函数实现了一个简单的计算。

公式如下:

LPToken_Value_Per_Supply = ( token0_value + token1_value ) * 10 ** 18 / LPToken_TotalSupply


可见，凭证价格计算的方法，就是将流动性凭证两端Token的价值相加作为流动性凭证的总价值。


而后用总价值除以从发行量，便得到了流动性凭证的单价LPToken_Value_Per_Supply。


UniswapLPOracleLib预言机介绍 


在介绍viewPrice函数之前，先简单描述一下UniswapLPOracleLib预言机的原理。


UniswapV2预言机的目的:

  • 在UniswapV1版本中，攻击者可以通过一笔swap交易，使某个token的价格异常波动。

  • 该波动会使其他依赖Uniswap市场的Defi项目错误地估计token价格。

  • 预言机的引入，可以减小攻击者对市场的恶意影响


共有两个涉及预言机的合约：

  • UniswapLPOracleFactory

  • UniswapLPOracleInstance


UniswapLPOracleFactory合约用来创建和管理Oracle实例，每一个Oracle实例都是一个部署好的UniswapLPOracleInstance合约。


两个合约的类关系如下图:


UniswapLPOracleFactory合约有两个关键变量:


LPAssetTracker

  • 该mapping变量 key为 流动性凭证的地址，Value为LPToken两端Token对应的Oracle地址

  • { LPToken_address : [ oracle0, oracle1 ] }


instanceTracker

  • 该mapping变量 key为 Oracle实例的地址， Value为要用Oracle估算价值的那个Token

  • { OracleInstance_address : Token_address}


UniswapLPOracleInstance合约的关键变量如下:


token0 和 token1：


具体哪个是USDC哪个是Token，要比较Token合约地址和USDC合约地址的大小。


这两个token一个是要用Oracle来计算价值的Token，另一个是USDC。


price0Average 和 price1Average:


这两个变量记录的是 一个Token大概值多少USDC 和 一个USDC大概值多少Token


price0CumulativeLast 和 price1CumulativeLast：


  • 这两个变量表示 一个Token大概值多少USDC 在时间上的累积值 和 一个USDC大概值多少Token在时间上的累计值
  • 计算公式为 price0CumulativeLast += ( reserve_token / reserve_USDC ) * timeElapsed

    其中 reserve_token 和 reserve_USDC 为 uniswap币对:USDC-Token中，两个token的分别的存量。

    timeElapsed表示距离上一次累加的时间间隔。


有了以上的数据结构，当我们想获取Token的价格时，就用当前的价格累积值price0Cumulative减去上一次的累积值price0CumulativeLast，再除以两次计算的时间间隔timeElapsed。得到的便是在一段时间内Token的平均价格。


token_price = ( price0Cumulative - price0CumulativeLast ) / timeElapsed


由于该价格是一段时间内的平均值，攻击者仅通过一次交易能对token_price造成的影响变小了。

预言机就是通过如上方法，减小了攻击者能对Uniswap市场造成的恶性影响。

这种利用时间加权来减小token_price波动的方法被称为延时喂价( Delayed price feeds )。


viewPrice函数定义 


接着来看一下viewPrice的实现，这个函数返回的是币对中Token的总价值。


有了上面对Uniswap预言机的介绍，这里就很好理解了。


Token的总价值 = 一段时间内token的平均价格 * token的数量

价值计算方法小结 


通过上文的介绍，我们了解了UniswapLPOracleFactory如何计算流动性凭证的价格：

  1. 通过预言机获取TokenA 和 TokenB 的平均价格

  2. 分别计算当前币对中TokenA 和 TokenB 的价值 ( Amount * Price )

  3. 用TokenA和TokenB的价值之和 除以 流动性凭证的总发行量 得到凭证的价格

漏洞原理分析 


在上述计算模型中，虽然Price A 和 Price B受到预言机保护，很难操作，但是Amount_A和Amount_B仍然可控。攻击者可以通过大额Swap交易来改变Amount_A和Amount_B，从而操作ValuePerLPToken。随着ValuePerLPToken增大，Warp-Finance会认为用户的质押总价值增加了，进而愿意贷给用户更多的Token。

总结




UniswapV2Oracle预言机只能降低攻击者对单个Token价值的影响，无法消减攻击者对TokenPair.reserve存量的影响。使用Token总价值的和来评估流动性凭证的价值，依然会被攻击者操控。该漏洞目前还没有令人满意的修复方案，长亭科技将持续关注Warp-Finance官方动态，跟进项目的修复进程。
