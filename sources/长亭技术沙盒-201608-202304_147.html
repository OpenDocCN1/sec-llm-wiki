     Apache Struts 2 远程代码执行漏洞

（S2-061 / CVE-2020-17530）


Apache Struts 2 是一个基于 MVC 设计模式的 Web 应用框架。其官方在 12 月 8 号发出安全通告，声明对其存在的一个远程代码执行漏洞进行修复：

https://cwiki.apache.org/confluence/display/WW/S2-061


该漏洞编号为 S2-061，CVE 编号为 CVE-2020-17530，由github研究团队的Alvaro Munoz以及来自 Aeye安全研究团队的Masato Anzai报告。


漏洞描述


Apache Struts 2 会对某些标签属性的属性值进行二次表达式解析，因此在某些场景下将可能导致远程代码执行。


根据对比Struts-2.5.25与Struts-2.5.26版本代码差异发现，AbstractUITag.java 文件发生如下变动，未更改版本中会对动态属性值进行OGNL表达式求值，将会导致属性值被二次解析。



Struts标签中除了一些默认属性名之外(如id、url等等)，还可以使用动态属性(属性名任意)，比如如下写法：


<s:a aaa="%{name}">List available Employees</s:a>

如果攻击者能够在请求中控制 name属性值且应用未对其进行检查校验，则攻击者可以直接传入一个 OGNL 表达式，那么最终当标签渲染的时候，name的表达式就会因为二次解析而被执行。



相比于S2-059中特定属性名（id）会造成二次解析问题，用户自定义的动态属性同样也存在该问题。


影响范围


  • Struts 2.0.0 - Struts 2.5.25


解决方案


根据官方公告，最好的解决方法是对每一个标签属性的传入值进行安全校验，并且不应该在除了 value 以外的其他属性值中使用 %{...} 或 ${...} 进行表达式解析。


也可以将 Struts 升级到 2.5.26 版本对此漏洞进行缓解。

产品支持


雷池天然防御，雷池内置语法引擎默认支持检测 OGNL 表达式注入攻击，请确保雷池开启【Java代码注入检测模块】进行检测与拦截。
