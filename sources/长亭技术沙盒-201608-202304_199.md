**Apache Dubbo Provider 反序列化**

**远程代码****执行漏洞**

**（CVE-2020-1948）**

  

6 月 23 日，公开邮件列表披露了一个存在于 Apache Dubbo 中的反序列化远程代码执行漏洞。此漏洞编号为 CVE-2020-1948，由安全研究员 Ruilin 发现并报告给官方。

  

漏洞描述

  
Apache Dubbo 是一款高性能、轻量级的开源 Java RPC 框架，它提供了三大核心能力：面向接口的远程方法调用，智能容错和负载均衡，以及服务自动注册和发现。

Dubbo 的架构设计示意图如下：

![](../Images/130c351f741e442a28056f1622c2f082.png)

各个节点角色说明：  

*   Provider：暴露服务的服务提供方
*   Consumer：调用远程服务的服务消费方
*   Registry：服务注册与发现的注册中心
*   Monitor：统计服务的调用次数和调用时间的监控中心
*   Container：服务运行容器

CVE-2020-1948 漏洞问题出在 Provider 上。由于 Provider 对接收的 RPC 请求处理不当，当攻击者给 Provider 发送精心构造的恶意请求数据包时，将会在服务端触发反序列化漏洞，攻击者从而可执行任意恶意代码，获取系统权限。  

  

默认配置下的 Dubbo Provider 即会受到此漏洞影响。

影响范围

  

*   Dubbo 2.5.x
*   Dubbo 2.7.0 - 2.7.6
*   Dubbo 2.6.0 - 2.6.7
    

解决方案

  

目前官方已发布新版 2.7.7 修复此漏洞，因此建议所有受漏洞影响的 Dubbo 更新至 2.7.7 版本进行漏洞修复。
