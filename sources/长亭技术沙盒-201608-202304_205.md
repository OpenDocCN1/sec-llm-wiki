    ** 关于 Octopus Scanner 恶意软件**

**供应链攻击的风险提示**

  

今年 3 月 9 日的时候，GitHub 安全团队收到来自安全研究者 JJ 的消息，其声称发现 GitHub 上有部分托管的 Java 开源项目仓库中含有恶意软件代码后门，并且这些恶意软件代码很可能是仓库的开发者在不知情的情况下上传的。随后 GitHub 安全事件应急团队对这些项目中包含的恶意软件进行了深入分析，5 月 28 日在博客公布了此恶意软件的利用细节，并将其命名为“ Octopus Scanner ”。

**事件描述**

  

  

Octopus Scanner 是一个针对使用 NetBeans IDE 构建项目的开源软件进行供应链攻击的恶意软件，它会在中招的用户系统上枚举所有的 NetBeans 项目然后植入后门，并尝试进行扩散。

当受害者机器被 Octopus Scanner 感染后，它会首先查看系统上是否有使用 NetBeans IDE 作为开发工具。如果没有使用 NetBeans，则不会采取进一步行动。否则，Octopus Scanner 将通过以下机制继续感染其他 NetBeans 项目：

1.  识别用户的 NetBeans 目录
    
2.  枚举 NetBeans 目录下的所有项目
    
3.  拷贝恶意文件 cache.dat 到 nbproject/cache.dat
    
4.  修改 nbproject/build-impl.xml 文件，来确保每次 NetBeans 项目构建时，恶意代码都会被执行，将项目构建生成出来的所有 JAR 文件全部植入后门
    
5.  后门最终会生成远控木马，进行本地持久化并连接到 C2 服务器，执行由攻击者发送的指令
    

在 GitHub 安全团队的调查过程中，发现至少有 26 个开源项目被植入了 Octopus Scanner 恶意软件后门，不过在 GitHub 发布的报告中并没有提及具体是哪些项目。

  

**排查方法**

  

*   检测是否存在：nbproject/cache.dat 文件，并且通过 file 命令等方式检测其是否为 JAR 文件
    
*   检测 nbproject/build-impl.xml 文件中 pre-jar 和 post-jar 部分是否包含 cache.dat 等关键词
    
*   检测是否存在对 http://ecc.freeddns.org/data.txt 和 http://san.strangled.net/stat 的 HTTP/HTTPS 连接请求、DNS 查询请求
    

  

**类 Unix 系统下：**

*   检测是否存在：$HOME/.local/share/octo 文件
*   检测是否存在：$HOME/.config/autostart/octo.desktop 文件并判断其是否包含执行 Java 操作
*   检测是否存在：$HOME/Library/LaunchAgents/AutoUpdater.dat JAR  文件
*   检测是否存在：$HOME/.local/share/bbauto、$HOME/.config/autostart/none.desktop、$HOME/.config/autostart/.desktop
*   检测是否存在：$HOME/Library/LaunchAgents/SoftwareSync.plist 文件并包含 eln.duckdns.org 关键词

  

**Windows 系统下：**

*   检测是否存在：%TEMP%\\..\\Microsoft\\Cache134.dat 文件
*   检测是否存在名为 LogsProvider、ExplorerSync 的计划任务
*   检测是否存在：%TEMP%\\..\\Microsoft\\ExplorerSync.db 文件
