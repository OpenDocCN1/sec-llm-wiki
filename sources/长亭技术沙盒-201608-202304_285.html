ECShop 2.x-3.x 

远程代码执行漏洞



事件来源


8 月 31 日，ringk3y 在博客上公开了 ECShop 远程代码执行漏洞细节，说明 ECShop 在 2.x 版本中至今仍存在远程代码执行漏洞。但经过我们后续漏洞复现及确认，此漏洞还影响到 ECShop 3.x - 3.6.0 版本。


漏洞描述


ECShop 是一款 B2C 独立网店系统，适合企业及个人快速构建个性化网上商店。系统是基于 PHP 语言及 MySQL 数据库构架开发的跨平台开源程序。


ECShop 在 2017 年及以前的版本中，存在一处 SQL 注入漏洞，通过利用该 SQL 注入漏洞可控制 SQL 查询结果，使其返回注入的恶意数据，并通过进一步利用最终导致任意代码执行漏洞。


通过利用此漏洞，攻击者可在远程且无需账号登录的情况下，仅通过发送一个恶意的 HTTP 请求，即可在服务器上执行任意代码：



影响范围


ECShop 2.x

ECShop 3.x - 3.6.0


其中 ECShop 3.6.0 于 2017-08-18 更新的版本已经对此漏洞进行了修复，而之前尚未更新的 3.6.0 版本仍受此漏洞影响。


解决方案


更新升级使用最新版本的 ECShop 。


作为临时的缓解方案，可以考虑修改 includes/lib_insert.php 文件中的 insert_ads 函数，对 $arr 数组中的变量进行 intval 处理：



即在 insert_ads 函数代码流程开始处加上如下代码：


    $arr['num'] = intval($arr['num']);

    $arr['id'] = intval($arr['id']);


由于此漏洞的利用是由 insert_ads 函数来构造 SQL 注入，然后触发代码注入，故该临时缓解方案能对此远程代码执行漏洞进行防御，但依然可能存在通过其他函数来构造 SQL 注入的问题。因此仍然建议尽快更新升级使用最新版本的 ECShop 。
