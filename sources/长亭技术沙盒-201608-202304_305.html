THINKPHP3.2 SQL注入漏洞



4月14日，ThinkPHP 3.2版本发布了对'think_filter'进行改进的补丁，此次补丁主要针对SQL注入漏洞进行了修补。漏洞主要影响使用了ThinkPHP框架开发、采用'I()'函数获取参数并代入'update'语句（使用诸如save()、update()、setField()）的应用。攻击者可以通过传入恶意参数来获取数据库中的敏感信息或执行恶意SQL语句。


漏洞详情


引发此次漏洞的主要原因是ThinkPHP在处理传入where的数组时，会进行一次检测，如果与内定的一些表达式相匹配，就会执行表达式查询，其最初的目的也是方便开发者做开发。

但攻击者也可以利用这些表达式向SQL语句的where条件中注入恶意向量（有些表达式会将用户可控数据放在单引号之外）。

ThinkPHP本身的I()函数对绝大多数的表达式注入做了处理（在用户注入的表达式名后加空格），使得进行where分析的时候不能匹配到这些表达式。

如果I()传入的是数组，代入think_filter进行处理

但是这个think_filter没有对表达式bind进行处理

在select语句的情况下，由于没有参数绑定，造成:xx直接被拼接到SQL语句，导致SQL语句产生错误。

在update语句的情况下，ThinkPHP对set后的内容进行处理，绑定了参数。

这里:0将指向的是set后的键值，所以可以注入0，从而避开了SQL语句语法错误（在parseWhereItem()里拼接起来是xxx=:0）。

可以直接在后面注入恶意语句。

示例引发漏洞的代码写法

<?php

namespace Home\Controller;

use Think\Controller;

class IndexController extends Controller {

    public function index(){

        $data['name'] = I('u');

        $aa['password'] = "12345";

        $user_info = M('test')->where($data)->save($aa);

        var_dump($user_info);

    }

}

修改functions.php中的think_filter()，增加对bind的处理 (缓解方案)


function think_filter(&$value){

    // TODO 其他安全过滤


    // 过滤查询特殊字符

    if(preg_match('/^(BIND|EXP|NEQ|GT|EGT|LT|ELT|OR|XOR|LIKE|NOTLIKE|NOT BETWEEN|NOTBETWEEN

    |BETWEEN|NOTIN|NOT IN|IN)$/i',$value)){

        $value .= ' ';

    }

}
