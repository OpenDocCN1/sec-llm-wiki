Linux eBPF验证器漏洞导致本地提权

  

  

3月15日，来自澳大利亚的安全研究员Vitaly Nikolenko在Twitter公开了一个可在最新版Ubuntu 16.04实现本地提权的漏洞利用代码，攻击者可利用该代码将普通权限用户提升至root权限。

  

![](../Images/bc3852b5968d7851fadbf50ed82fa9c9.png)

  

经过分析，提权代码中所使用的漏洞是Linux eBPF验证器漏洞（CVE-2017-16995与CVE-2017-16996），最早在2017年12月由Google Project 0的研究人员Jann Horn发现并报告，影响Linux内核版本4.4~4.14。并且在当月，Bruce Leidl在github放出了能在内核版本4.11上实现提权的漏洞利用代码。

  

而近日，Vitaly Nikolenko公开的提权代码能够影响最新版本的Ubuntu 16.04，是因为该发行版使用的Linux内核版本是4.4，也受到漏洞影响，并且在漏洞报告后的3个月内，Ubuntu一直未修复，猜测可能和Jann Horn的最早漏洞报告中未提及漏洞对4.4版本内核的影响有关。

  

漏洞原理

BPF是一种常用的网络包过滤语言，在1992年由劳伦斯伯克利实验室提出，大家最常用的流量抓取和分析软件wireshark、tcpdump就采用了BPF语法。在Linux中也使用了BPF的语法来实现一些安全特性，例如SECCOMP机制可以使用BPF来过滤系统调用。eBPF的全称为extended/enhanced Berkeley Packet Filter，是基于BPF的全新扩展，在Linux中可以用来追踪和调试内核，实现对网络事件、安全事件的过滤。eBPF的使用流程是：  

用户态可以加载一段字节码交给内核

内核会运行一个验证器来确保字节码程序是安全的

然后内核将字节码翻译成本地语言，插入到相应的位置进行过滤

  

  

漏洞就出在内核的验证器当中，验证器在验证字节码对内存访问范围的检查上出现了问题，导致了攻击者可以通过在用户态载入恶意的字节码来实现对内核内存的任意读写。

  

解决方案

  

  彻底修复方案：升级内核，Ubuntu 16.04已提供了内核更新

  

添加proposed源，升级Ubuntu内核

echo "deb http://archive.ubuntu.com/ubuntu/ xenial-proposed main" >>/etc/apt/sources.list && apt update && apt install linux-image-4.4.0-117-generic && reboot

执行以后需要重启

  

值得一提的是，如果从低版本升级到116及更新的版本，会新加入retpoline作为spectre的防护措施，kver magic有改变，使用dkms的用户需要注意使用Ubuntu最新的工具链，不然可能造成某些内核模块无法正常加载。

  

临时解决方案：将内核参数unprivileged\_bpf\_disabled设置为1来禁止低权限用户使用BPF

  

执行命令：

sysctl -w kernel.unprivileged\_bpf\_disabled=1
