2017年4月初，OWASP发布了OWASP Top10 2017的一个候选版本rc1，并开始公开征集意见，正式版预计在7月或8月公布。（点击“阅读原文”可查看完整版OWASP Top 10 2017 rc1报告）

 

众所周知，OWASP – Open Web Application Security Project（开源web应用安全项目）是一个非营利的全球性安全组织，一直致力于提供无偏见、实用、低成本的应用安全方面的工具、信息。


OWASP TOP 10即十大Web应用程序安全问题，这十个问题往往代表着应用安全领域已达成广泛共识的关键问题。这份列表由OWASP项目成员制定，他们是来自世界各地的各路安全专家，因此OWASP TOP 10具有一定的权威性，通常被各大公司和组织用作改进Web应用程序安全性的参考标准。

 

上一个OWASP Top 10的正式版还要追溯到2013年，时隔4年，OWASP TOP 10可能会产生哪些变化呢？





应用程序和API的威胁格局在不断发生着变化。在这种演变中的关键因素是：新技术（包括云，容器和API）的迅速采用、软件开发过程中的加速和自动化方法（例如敏捷开发和DevOps）、第三方库和框架的爆炸式增长以及攻击者技术的提升。这些因素导致应用程序和API变得更难分析，而且完全可以使现有的威胁格局发生质的变化。

 

为了跟上这种变化，OWASP定期更新OWASP Top 10。在2017年的发布版中，他们作出了以下更改：

合并

1.2013年版中A4 – 不安全的直接对象引用（Insecure Direct Object References）与A7 –功能级访问控制缺失（Missing Function Level Access Control）合并成为2017版中的新A4 –失效的访问控制（Broken Access Control）


新增

2.新增A7 – 攻击防护不足（Insufficient Attack Protection）


3.新增A10 – 未受到充分保护的API（Underprotected APIs）


删除

4.删除了2013年版中A10 – 未验证的重定向和转发（Unvalidated Redirects andForwards）


➤  Top 10是围绕主要的风险领域来整理的，不要求严密、不重叠和严格分类。


一直以来，国内外的安全开发人员和企业组织都将OWASP Top 10作为了解应用程序安全的参考指南，Top 10还被众多标准、书籍、工具和相关组织引用，包括MITRE、PCI DSS、DISA、FTC等等。

 

如今OWASPTop 10 2017 rc1发布，新增的风险格外引人注意：2017年，在web应用程序安全领域，存在新风险究竟是怎样的？


我们重点解释新增的2017-A7：


攻击防护不足（Insufficient Attack Protection）是什么？


大多数应用程序和API缺乏检测、防护、响应手动或自动攻击的基本能力。 这里的攻击防护远不止基本输入验证，还包括漏洞攻击的自动检测、记录、响应甚至阻止，还需要应用程序所有者能够快速部署补丁以防止攻击。


如何知道是否存在这个安全问题？


对攻击进行检测、响应和阻止，会使应用程序更难被攻破，但几乎没有任何应用程序或API具有这种保护行为。自定义代码和组件中的关键漏洞也一直在被人发现，但企业组织通常需要几周甚至几个月才能推出新的防御修复方案。

 

有没有部署攻击的检测和响应是很容易判断的：只需尝试手动攻击，或对应用程序运行扫描器。应用程序或API应该能够做到识别攻击，阻止所有可行的攻击，并提供攻击者的细节和攻击特征。

 

否则，如果在发现关键漏洞时无法快速推出虚拟或实际补丁，则会受到攻击。


      面对攻击防护不足的风险，企业该如何应对？

OWASP在报告中提到，如果只针对XSS和SQL注入， 可以使用WAF、RASP和OWASP AppSensor等技术来检测或阻止攻击或虚拟修补漏洞。


然而从防护性能上来讲，传统WAF已经开始遭到质疑。

 

比如：

使用正则防护系统，人工维护规则，维护成本高且易出错。

误报率和漏报率双高，不能发现未知漏洞，无法应对0day攻击。

 

事实上，WAF产品并不一定需要通过不断叠加安全规则来实现防护，它也可以很智能，这就是长亭下一代Web应用防火墙——雷池（SafeLine）。它被内置了一个大脑——基于语义分析的智能威胁识别引擎，不仅能够检测复杂的Web应用攻击，而且能够识别未知的安全威胁和攻击。

 

全面提升安全防护能力的同时，雷池（SafeLine）也将管理人员从复杂的安全规则维护和管理中解脱出来，降低了技术操作人员的工作难度，有效杜绝了因为规则配置和管理不当而导致的安全风险，从根本上解决攻击防护不足的风险。
