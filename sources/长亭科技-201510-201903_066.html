Make HackMD printable ._. Link

Hint: If you are not skilled at black-box testing, you need to figure out how PrintMD is compatible with outdated browsers. Flag is in the filesystem /flag

Hint: Here is a render.js for you.

// render.js

const {Router} = require('express')

const {matchesUA} = require('browserslist-useragent')

const router = Router()

const axios = require('axios')

const md = require('../../plugins/md_srv')


router.post('/render', function (req, res, next) {

  let ret = {}

  ret.ssr = !matchesUA(req.body.ua, {

    browsers: ["last 1 version", "> 1%", "IE 10"],

    _allowHigherVersions: true

  });

  if (ret.ssr) {

    axios(req.body.url).then(r => {

      ret.mdbody = md.render(r.data)

      res.json(ret)

    })

  }

  else {

    ret.mdbody = md.render('# 请稍候…')

    res.json(ret)

  }

});


module.exports = router

PrintMD 可以将 HackMD 文档转换成易于打印的格式，它的一个特性是兼容“过气”浏览器。对比用 IE 8 和 Chrome 访问的结果，可以看到 PrintMD 为了更高的兼容性，对过气浏览器使用了服务端渲染技术。

这些静态文件由 webpack 打包生成，并且不提供用于调试的 sourcemap。是不是感觉非常 real-world？但是借助一些调试手段，还是可以美化一下这些看上去可读性很低的代码：

在 asyncData 这个部分，user-agent 被追加到 ctx.query 里，然后发送给 API ，由 API 来决定用户的浏览器是否旧到需要服务端渲染。

问题出现在 qs.stringify({...ctx.query}) 和 render.js 中的axios(req.body.url) 这两行代码。开发者认为 ctx.query 中的 url 只要能通过 validate 的校验，就一定是安全的。然而 API 在解析参数时由于 express body-parser 的特性，url[xxx]=1 可以被解析成 Object 类型的 {xxx: 1}，这就导致了漏洞的产生。攻击者通过参数污染，可以精心构造出恶意 Object 作为 axios() 的参数。例如，

url[url]=http://ssrf&url[method]=get&url=https://hackmd.io/

传递给 render.js 时，req.body.url 是这样的一个 Object

和 GoogleCTF 2018 bbs 不同的是，这里的场景是服务端渲染，也就是说请求是从服务端发出的。现在我们可以任意构造参数执行 axios() 来实现 SSRF，并且题目告诉我们 flag 在文件系统中。虽然 axios 并不支持 file:// 域，但它支持 UNIX 套接字：
