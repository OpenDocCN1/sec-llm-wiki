# 为什么空密码可以登录你的 Mac?

就在今天（\*昨天）, macOS 被爆出一个重大缺陷：任何人都可以使用管理员账户登陆, 用户名为 root，密码可为空。最早发现并公布复现过程的是 Lemi Orhan Ergin (@lemiorhan)：  

![](../Images/4987695e16c8816317bf5e4f60a915e8.png)

那么, 令人十分好奇的是, 这个问题是因为什么样的 bug 才导致的呢？

  

![](../Images/76fc7402a236ef3f3378fffd9b4569fb.png)0x01

首先，我们观察一下到底发生了什么。当用户/攻击者尝试登陆一个在当前没有被启用的账户的时候，系统将会创建一个新账户使用用户指定的任意内容作为密码，包括空密码，这就是为什么在 UI 触发时需要点击两次：

![](../Images/4704beb3703ce5e9926cdc44109ef818.png)

更深一点来看，当用户尝试授给某个被 *opendirectoryd* handled 账户的时候：  

```

```

一旦收到 mach XPC message, *opendirectoryd *调用 *odm\_RecordVerifyPassword *方法，这个方法之后调用了 *od\_verify\_crypt\_password。odm\_RecordVerifyPassword *方法在 *PlistFile *binary 中被执行。这个 bundle 从 /System/Library/OpenDirectory/Modules/PlistFile.bundle 加载到 *opendirectoryd。*

*odm\_RecordVerifyPassword* 调用了一个未命名的方法 '*sub\_826b*'。这个 subroutine 首先调用了另外一个 helper function，'*sub\_826b*', 来读取 shadowhash(从用户尝试登陆的账户中)。对于一个已经存在的账户来说，这并不成问题。

![](../Images/d3b8376af84aabeeb9a10bfd187546d3.png)

但是对于没有启用的账户来说，这些信息并没有被提供，所以这个函数会 fail。这是很关键的一点。  

```

```

当 shadowhash 不存在的时候，一个 'else' 代码分支被执行了：

![](../Images/afa6ab610f6490eaa89a19bc0ebd09d4.png)

在读取密码之后，它调用了 *od\_verify\_crypt\_password* 来验证密码是否匹配。在这里我们输入了 '*hunter2*'。

![](../Images/e3eec05145a71c47cd80aab61e562c33.png)

如果我们 step over 这个调用，它将返回 al 的值也就是 01...是不是很有趣！

![](../Images/011ea6f35b3dbcde3ca87307912889a1.png)

鉴于一个非零的值被返回了，它讲继续调用其他方法比如 '*sub\_13d00*'。这将带来一个重要的影响：将用户输入的数据作为 shadowhash/securetoken：

![](../Images/2abb659ff772613295f9aa517c140034.png)

我们输入的任意 password 就这么变成了 root password。

  

![](../Images/76fc7402a236ef3f3378fffd9b4569fb.png)0x02

总结一下:  

1.  在未启用的账户(例如 root)中，macOS 将指定用户输入密码作为账户密码；
    
2.  在这个过程中，*od\_verify\_crypt\_password* 返回非零值；
    
3.  之后，用户输入变成账户密码；
    

**很明显, 关键问题就出在了 *od\_verify\_crypt\_password*。**
