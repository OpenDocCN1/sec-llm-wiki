诈骗者用精确的消费信息获取信任，再以不良商品退款为由要求受骗者进行系列操作，包括点击“退款”链接，填写“理赔协议”，扫描二维码等。

是电商，就势必涉及到金钱交易环节。电商平台已经成为别有用心人眼中的奶酪，小红书不过是其中的一块。在其他网站上造成信息泄露的普通漏洞，有了交易信息的加持，就会演化出难以控制的网络诈骗。


电商：谁动了我的奶酪？


风险一般存在于财富和漏洞之间！



建设一个电商在线网站已经十分容易，但实现保证业务的安全运营依旧很难。


“功能”越多，意味着架构越复杂，漏洞存在的可能性就会增加。保“功能”还是选“安全”通常是管理者面临的两难选择。现实中，企业为了抢占市场，往往会将安全置于次要位置。


电商平台为了解决用户不信任的问题，往往会引入第三方交易中介。一方面，这的确帮助网站解决了信任问题，另一方面却带来了更多的安全隐患。第三方中介植入业务链势必会使得业务流程复杂化，进而暴露更多的可攻击弱点，使得平台的安全性受到威胁。


还有一些情况下，为了战胜竞争对手，电商平台通常选择叠加更多的功能以展示丰富的内容，并进行版本的快速迭代。复杂多变的业务逻辑，加上未经深度测试的仓促发布，常见漏洞自然也少不了，如SQL注入、跨站脚本执行等。


至于攻击后果……信息泄露、数据失窃只是跳板，攻击者会利用窃取的资料进行下一步破坏，本次的小红书事件就是一个很好的例子。 

漏洞与攻击，似乎是个哲学问题——没有上锁的箱子激发了人犯罪的欲望。


某知名漏洞平台曾总结过六大常见的业务逻辑漏洞：


1. 欺骗密码找回功能：对于那些仅靠一个验证码就确认用户身份的网站，攻击者可以通过暴力破解验证码，任意重置用户密码；

2. 规避交易限制：攻击者把商品数量设置为负数，就可以因为总价计算为负，让系统自动返钱给自己了；

3. 越权缺陷：通过修改url地址，攻击者可以修改他人数据；

4. cookies和session的问题：对于那些仅依据cookies是否为空或session是否为true就判断用户身份的网站，攻击者只需知道用户ID，然后构造一个cookies或让session值为true就可以绕过认证了。

5. 顺序执行缺陷（强制浏览）：如果开发者意图通过浏览器导航规定用户的访问顺序，那么攻击者也有可能跳过其中的一两个阶段，以逃避支付或验证环节。

6. 时间刷新缺陷：如果网站的刷新间隔基于本地设置，攻击者就可以在控制台将规定时间的关联变量重新设置，大幅度缩短刷新时间。


将以上漏洞应用于对电商平台付款环节的攻击，会产生哪些后果呢？


例如：使用浏览器扩展程序，攻击者就可以阻止HTTP请求，修改请求甚至完全伪造请求。攻击者还可以伪装成为第三方收银中介，通过更改HTTP表单中的返回URL来重复之前订单中的支付信息或拦截第三方收银中介的回复。



电商常见攻击逻辑：SQL注入和价格操控


SQL注入


SQL注入（SQL injection）是指在输入的字符串中插入SQL指令，以欺骗后端数据库把其当作正常指令执行，并由此遭到破坏或入侵。

   

SQL注入时，具体使用何种技术由被攻击的数据库类型确定。例如，Oracle数据库上的SQL注入主要使用UNION关键字完成，并且比MS SQL Server困难得多，而MS SQL Server可以通过使用分号分隔多个查询来执行。在默认配置中，MS SQL服务器以本地系统权限运行，并具有'xp_cmdshell'扩展过程，允许执行操作系统命令。


用SQL注入攻击网站漏洞，攻击者可以获取大量高保密性数据，如信用卡号、交易详情等。2002年2月，美国程序员Jeremiah Jacks发现Guess.com存在SQL注入漏洞，并因此至少获取了200000个用户信用卡信息的访问权。2003年6月，Jeremiah Jacks再次发动攻击，这次他通过PetCo.com的SQL注入缺陷获取了500000个用户信用卡信息的访问权。


从时隔一年的连续偷窃看起来，这件事本身存在取证难、难发现的特点。


价格操控


这是一个多见于线上购物车和支付平台（ payment gateway）的漏洞。通常，用户所选商品的应付总价存储于动态生成的网页的隐藏HTML字段中。当此类信息从用户的浏览器流向Web服务器时，攻击者使用诸如Achilles 的Web应用程序代理，就可以轻而易举地修改金额数目。


如下图：


最终应付价格（currency=RS&amount= 879.00）可以被攻击者操纵为其他数值并发送至与在线商家合作的支付平台（ payment gateway）。


在交易量很大的情况下，价格操纵很容易被忽视，无法得到即使控制。长此以往，重复的价格操纵会使得电商平台无法生存。


第三方软件中也出现了类似的漏洞。例如3D3 ShopFactory购物车，其价格和商品信息存储在客户端Cookie中，因此很容易被攻击者操纵。类似地，Smartwin Technology的Cyber Office购物车2.0则可能会因本地下载订单而受到攻击，并将其重新提交给目标服务器，并将隐藏的表单域修改为任意值。


排查电子商务应用程序中的逻辑漏洞


排查电子商务应用程序中的逻辑漏洞，从以下五点入手：


  1. 订单编号：

    为了绕过付款环节，攻击者可以对收银中介重复展示本平台以前的付款完成信息。如果不验证订单ID，只需未付款订单的总额与先前付款订单的订单总额相符，攻击者就能轻而易举欺骗商家。


  2. 订单总额：

    如果网站缺乏订单总额验证流程，攻击者就可以通过篡改发送给第三方收银中介的待付总额来逃避付款。当然，在这种情况下，攻击者仍然需要向收银员支付部分费用。


  3. 商户ID：

    攻击者可以在第三方收银中介的服务器上设置自己的商户ID，攻击者可以通过向自己的商户ID付款，而逃避付钱给本应收款的商户。


  4. 货币汇率：

    如果收银中介接受多种货币付款，那么攻击者就可以不篡改应付总额，转而篡改货币种类，支付同等数量而价值更少的货币来减少付款。


  5. 暴露的signed token：

    会使原本受信的符号值无法通过安全检查,因为这样一个签名的请求可能被攻击者伪造。
