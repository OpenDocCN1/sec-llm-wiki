**一、漏洞分析**

  

漏洞出在 Struts2 的 MultiPart 解析器中。

先看看补丁的 Diff（点击【阅读原文】查看），可以看到共有三处修复，三处的代码都非常相似，原有代码如下：

修复之后这里的代码变成了：

  

![](../Images/a5ae4cc57ef0af97c60244c660f54f10.png)

  

当 HTTP 请求为 `multipart/form-data` 格式时若解析失败则会调用到 `buildErrorMessage` 方法，并在 `buildErrorMessage` 中调用 `LocalizedTextUtil.findText`。  

patch 修改了 `LocalizedTextUtil.findText` 的调用方式，修复后第四､五个参数发生了变化。  
继续观察 `LocalizedTextUtil.findText`方法，值得注意的是这个方法的文档里提到了这样一句：

> If a message is found, it will also be interpolated. Anything within ${…} will be treated as an OGNL expression and evaluated as such.

看描述，所谓 `message` 中的 ${…} 部分会被当作 OGNL 表达式而执行。  
文档中描述了 `message` 的内容从获得途径：

![](../Images/b456c25942352d5c2017c25bb347d776.png)

  

`getDefaultMessage` 方法的实现如下：

![](../Images/3ddb5e131d8d95fd218ee7808b06d544.png)

![](../Images/8044d3071980f8be9430198c20ac00ec.png)

  

在 `GetDefaultMessage` 方法中调用了 `TextParseUtil.translateVariables` 方法。

![](../Images/338170a7a7978fb59b527a2a5affc1cf.png)

  

`TextParseUtil.translateVariables` 会对 `message` 中的模板变量进行渲染，模板变量以`#{...}`､`${...}`或`%{...}` 的形式存在，大括号中可包含 OGNL 表达式，进而导致这里可以执行任意 OGNL 表达式。

**二、利用方式**

  

通过上述分析可知，当 `Content-Type` 中包含 `multipart/form-data` 字符串但是并不能正确解析 `Content-Type` 时就会引发异常，这时异常信息中包含的 `OGNL` 表达式被解析，导致黑客可以构造恶意请求在 Struts2 服务器上执行任意代码。

  

**三、修复方案**

  

官方已经发布修复补丁：

*   Struts 2.3.5 - Struts 2.3.31 可升级到 Struts 2.3.32
    
*   Struts 2.5 - Struts 2.5.10 可升级到 Struts 2.5.10.1
    

若因为业务原因不能及时升级 Struts2 框架，也可使用长亭雷池 Web 应用防火墙对网站进行保护，长亭科技安全应急响应团队将持续关注漏洞影响后续。
