壹

攻防场景下

蜜罐布防实践

蜜罐可否不依赖探针引流，直接对外服务？

  

蜜罐基础是容器或者虚拟机，直接将其暴露在用户网络中会面临主机层端口冲突、宿主机信息泄露等问题，而通过探针进行一层地址和端口转换后，可实现探针和蜜罐多对多的映射，能够起到更好的伪装欺骗效果。

  

如果蜜罐被攻击者攻破，是否会导致平台失陷？

  

首先需要明确蜜罐被“攻破”的定义，因为蜜罐本身就是要被“攻破”的，这样才会捕获攻击者。我们考虑了攻击者拿下蜜罐后，进一步从蜜罐中逃逸至宿主机的风险，因此在容器和虚拟机上进行了严密的加固、隔离和监测措施。其次，当蜜罐产生告警后，我们需要仔细排查攻击路径，消除风险。

  

蜜罐部署在互联网上有哪些作用和风险？有没有好的部署建议？

  

谛听内置了WebMail、VPN、内容管理系统后台等Web蜜罐，也可以根据客户已有系统制作仿真Web蜜罐，这些蜜罐真实性高，攻击者做信息收集时很难“错过”，在攻防演练前期常会收到不错的效果。由于监管单位会从互联网侧进行资产脆弱性扫描，因此我们发布出去的蜜罐不要存在漏洞和敏感内容，避免不必要的麻烦。部署模式上可以通过NAT地址转换或负载均衡指向探针服务器，将探针服务发布至互联网侧，再关联企业域名信息，当攻击者进行域名爆破、IP段扫描等信息收集时，会采集到蜜罐信息，从而起到欺骗效果。

  

贰

网络攻防演练中的

攻击战术剖析

攻和防是永恒的主题，我们怎么在攻击的过程中保证不留下痕迹给防守方溯源？

  

所谓“雁过留痕”，攻击方在攻击过程是不可能完全不留下任何痕迹的，尤其是目前大部分企业拥有大量的安全设备，我们能做到的就是尽可能的减少被溯源或阻断的可能性。一方面减少在攻击过程中留下特征，做好隐秘和及时清除相关日志；另一方面，尤其是在攻防演练中，可以采取声东击西的方式，比如如果拿下了多个机器，可用一个机器，采取大动作的方式进行攻击，如扫描等，吸引防守方的注意力，与此同时，利用另一个机器进行小动作的真正的攻击，这样被发现的几率就更小。在溯源的时候，也能利用大流量的攻击日志，来掩饰真正的攻击流量。

  

初始探测和建立入口需要的时间这么短吗，如何做到的？

  

入口建立时间的长短，很大程度依赖防守做的多差（笑）。其实虽然有点夸张，但大致如此。在攻防演练中，往往会先对各个目标进行整体浏览，然后先挑最软的柿子捏，所以尤其是刚开始的几个目标很容易建立入口，一方面可能存在比较明显的薄弱点，另一方面极端情况也会酌情使用0day。碰到安全真正做得好的目标时，很长时间找不到入口也是有可能的。

  

目前主机类入侵检测或加固类产品，能准确检测和防护 Webshell和CS远程、powershell脚本？能绕过吗？

  

市面上主流的检测或加固类产品，对于常规Webshell或CS等恶意程序相信还是能做到比较好的检测的，要不然也不至于能流行开来。但与此同时也应该意识到，攻和防往往是“道高一尺魔高一丈”，防护产品还是能绕的，但至少能检测出部分的攻击手法，增加攻击者的攻击成本。

  

攻防演练的信息收集和渗透测试的信息收集有什么不同关注点嘛？

  

对于漏洞这块的信息搜集，两者的区别没那么大，都是寻找目标漏洞，只不过攻防演练更偏向于一些能拿权限或数据相关的信息。但与此同时，攻防演练对于内网相关的信息也会非常关注，毕竟最终是想要拿下目标，而内网的信息将有利于内网的扩展。另外，攻防演练对于人员相关的信息也比较关注，用于社工钓鱼等一些非渗透手段。

  

叁

大型攻防演练中

WAF的调优策略

WAF 和负载均衡器的联动部署模式是怎样的？

  

雷池提供 so 模块在客户的 nginx 上加载，同时部署检测、管理等 WAF 其他服务；请求通过 so 模块转发到检测服务进行检测、控制拦截；用户可以通过管理界面做 WAF 相关配置。

  

WAF 会有海量的噪音，存在大量无意义的扫描器扫描报警，如何筛选出相对有价值的报警呢？每天几十万的量报警人看不过来  

扫描器的日志可能占了无意义告警的绝大部分，所以问题的核心就是将扫描器日志更好的排除出去。方式一：封禁一些扫描器。根据扫描器参数特征、行为特征，结合 IP 信誉,以 JS Challenge 或滑块验证等方式进行识别，并进行拦截或频率限制，从根源上解决问题。方式二：在日志分析过程中对日志进行分类聚合，比如将识别为扫描器攻击的日志滤去，或将产生大量日志的扫描器IP滤去等。

  

WAF 策略需要经常调整么，还是部署后就不用管了  

需要结合业务情况和外部安全态势来看是否需要经常调整，总的来说WAF 策略是需要持续运营才能保持最优的。如果公司业务经常变化，势必会带来一些站点配置的工作及因业务变化引发的误报，这个时候就需要经常性的关注。外部若有新的漏洞爆发或者有新的攻击方式，同样可能进行一些调整。基于语义分析的雷池更具柔性，天然能更好的适配多种业务，同时能一定程度上防御未知攻击，调整的频率低于行业平均水平。

  

WAF 在日常使用中的防护作用有多大，如何处理正常业务被拦截的情况  

作用很大。首先，Web 应用本身更易遭受攻击，因互联网上绝大多数都是 Web 应用，有较高的攻击价值， Web 应用及中间件也更容易爆发新的可能被利用的漏洞。其次， WAF 相比于 IPS/IDS 以及防火墙能够更好的结合业务逻辑，有针对性的防御Web 漏洞，对OWASP TOP 10 的风险进行防护。最后，从侧面看，监管机构对安全的要求中经常提到对 WAF 的要求，金融、互联网、通讯等行业都大量应用了WAF ，这也代表着公众对 WAF 价值的认可。

正常业务被拦截需要结合具体情况进行调优和分析，大多数情况是“正常”业务本身有安全性的风险，这时就需要对业务进行修复或者进行加白处理。

  

请问基于 session，cookie 如何阻挡？因为 session/cookie 很多是动态生成的

  

如果业务系统本身是动态生成的话，可以使用雷池自带的 session 功能。

  

雷池的运维难度对比其他厂家的 WAF 产品，是更简单方便些了吗？

  

a. 从实现上，一些厂家仍是基于规则进行设计和实现，所以需要配置的项就比较多，而雷池的智能语义分析基因让它天然的配置项就比较少。  
b. 从场景上，一些厂家的产品更多面对的是超大型企业极其复杂的业务场景，用通用性产品来满足势必会增加一定的配置复杂度，且这些超大型企业也需要人力来进行维护。对于普通企业来说，遇不到这么多复杂的场景，也没有这么多人力来维护，就显得非常笨重了。

  

碰到0day 的漏洞怎么提高响应速度？

  

雷池会提供及时准确的0day 漏洞信息以及防御功能。其自身的防护技术——智能语义分析也能一定程度防御0day，在部署雷池后，许多0day 漏洞在无需做任何配置修改的情况下就可被准确识别出来。

  

雷池的误报和漏报率怎么样，与同类产品相比的优势在哪里？

  

误报和漏报率会随着测试集的不同有所波动。结合雷池在实际项目中和其他同类产品的竞测，会有更低的误报和漏报，且配置的时间会更短。

  

肆

Webshell 上的

攻防博弈

牧云和雷池关于 Webshell 的防护有什么不同？

  

雷池是流量层面的防护产品，检测通信流量中是否含有与 Webshell 交互相关的特定语义，例如含有自解密执行命令的后端代码等；牧云是主机层面的防护产品，检测的是 Web 应用文件中所隐藏的后门逻辑。雷池必须在实际访问 Webshell 页面时才能发现特征，而牧云不需要。

  

基于数据流的检测方式有什么缺陷？能被绕过吗？

  

基于数据流的静态分析技术是白盒代码审计领域已应用相对成熟的技术，引入到牧云中时，自然也继承了相应的优点和局限。牧云在算法的阈值上做了很多优化调整，并可以和产品整体的其它功能相结合，共同检测、发现 Webshell，达到一个比较令人满意的效果。

  

牧云的 Webshell 检测是对每个文件都进行检测吗，还是要配置网站目录？性能会不会有影响？

  

牧云的 Webshell 检测机制会智能识别 Web 应用运行环境，并在活动环境中扫描 Webshell，因此性能消耗能维持在较低水平。不过为了满足诸如扫描备份环境、离线环境等需求，牧云也提供了手动指定 Web 路径的配置项，使用这些配置项时性能消耗可能会大一些。

  

伍

攻防演练中

漏扫工具以攻助防战术

一条 payload 怎么区分不同的漏洞？

  

洞鉴会根据响应数据的一些特征自动判断出具体是哪个漏洞，如果没有特征，则会调用这类漏洞的通用漏洞模板输出。

  

规则库过多时（达到过万条）会不会影响扫描速率？

  

规则库过多时会对扫描速率有一些影响的，洞鉴针对这种问题做了以下的优化处理：

1.  提升检测速率，从数量级上做提升，本身处理能力可以达到每秒几千的请求。假设原来规则少，每秒只需处理10个请求；后续因为规则增加，每秒需处理上百个请求，那么本身影响是不大的。
    
2.  基于语义、词义、自适应调度等算法，根据指纹智能匹配漏洞检测规则，而不是无脑的全部规则都跑一遍。
    

  

X-Ray 是开源的吗？

  

xray 社区版，是免费版，但不开源；X-ray 企业版是需要付费的（xray 社区版是企业版的一部分核心检测引擎，对应企业版的被动代理扫描策略）

版本区别详情见：https://xray.cool/xray/#/generic/compare

  

如何利用 X-Ray 扫描出来的漏洞？需要自己找 POC 还是工具自带呢？

  

洞鉴（X-Ray）是为了尽可能高效的确认漏洞存在与否，但具体的漏洞利用往往需要再找别的工具。一般洞鉴（X-Ray）非版本匹配插件输出漏洞即为确实存在的漏洞，并且漏洞详情页会提供漏洞存在的位置、请求，只需要再找相关漏洞利用工具尝试利用即可。

HIDS 产品在

重保场景下的应用

HIDS 全称叫什么呢？

  

HIDS 的全称为 Host-based Intrusion Detection System ，是基于主机型的入侵检测系统。

  

公司资产有物理机、公有云主机、虚拟机、容器集群，部署 HIDS 的话，只部署物理机能不能满足安全资产管理，还是说要全部都部署？

  

牧云支持部署到物理机、虚拟机及公有云主机，建议现网环境主机资产全部部署。

  

检测到恶意文件后，是会触发告警还是会进行文件删除类的操作？

  

会触发告警，并且提供解决方案，支持手动隔离/信任恶意文件。
