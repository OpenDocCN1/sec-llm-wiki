现今，诸多安全类产品都宣称理解业务，能够基于业务场景建立业务安全模型，但是业务安全问题类目繁多，对应的安全需求千差万别，不同客户的同类别问题由于业务以及流程的不同，其业务安全问题也大不相同，导致**许多安全产品在理解实际业务过程中困难重重。**  

以典型的**“薅羊毛”**为例，我们来简单分析一下不同业务的区别。

“薅羊毛”行为在**不同业务场景下的具体表现形式：**

1\. 利用不同的账号领取无门槛抵价券

2\. 批量参与抽奖，提高中奖率

3\. 虚假交易刷信用卡，使用积分换取礼品

4\. ……

上述问题中，虽然都是进行薅羊毛，但是**实现的方式千差万别**，第一个是利用多个账号刷取抵价券集中给一个账号使用，造成商家以及平台方的活动亏损；第二是利用活动漏洞或者其他方式批量参与抽奖活动，提高中奖几率，影响活动的公平性，损害其他用户的利益；第三个薅羊毛的问题更为严重，羊毛党利用 POS 机进行虚假交易，通过刷信用卡增加账户积分，再使用获得的积分换取礼品，企业直接蒙受损失。

面对这多样的“薅羊毛”问题，有没有一种**通用的解决方案？**

我们首先需要**思考几个问题：**

1. 不同的业务员**账号体系**是否一样？

2. 不同的业务领取和使用优惠的**流程**是否一样？

3. 如何能够**智能识别**某接口是否可以用来领取“优惠券”？

4. 如何判断一个正常的业务流是否存在**欺诈行为？**

5. ……

面对多样业务安全需求，最重要的环节是**理解企业业务，摸清需求，**才能针对性的回答以上问题，从而制定切实可行的解决方案。

**流量分析对解决业务安全问题至关重要**  

面对定制化安全需求，企业可通过**分析流量**对网站建模，理解业务内容:

·  业务有哪些页面

·  页面接受哪些请求方式

·  页面有哪些参数

·  参数的类型有哪些

·  参数的长度范围

·  ……

结合实际业务场景，分析网站建模结果，进而得出**业务需求：**

·  当前网站上有什么业务

·  业务的支付逻辑是什么样的

·  哪个页面有抽奖活动

·  哪个接口是登录接口

·  整个业务一共有多少个注册接口

·  ......

实现此需求存在**开发成本高、运维成本高、对于业务变更的响应不及时、安全推动落地有难度**等问题，为此安全产品必须通过以下手段来理解业务：

围绕上面的几点思考和「网站建模」功能理解业务的结果，可以发现**「流量分析」的结果尤为重要，直接影响建模的业务贴合性或者之后的一系列行为。**

**WAF更人性化****雷池语义化流量分析引擎**

长亭研发团队认为，要想解决企业实际问题，第一需要**站在用户业务的角度**来进行流量分析；第二需要**更适合用户操作的方式**来构建流量分析逻辑，第三需要**更实时和自由**的流量分析模式。

基于以上考虑，长亭科技雷池（SafeLine）下一代Web应用防火墙提供**开放插件平台**，在获取到完整的 HTTP/HTTPS 的请求后，定制化分析场景流量，让雷池（SafeLine）更加理解业务的企业安全人员，根据自身业务逻辑来完成相关插件的流量分析逻辑，量身打造贴合业务场景的解决方案。

在原有流量处理引擎的基础上，雷池（SafeLine）还增加了**流式流量处理算法**，并升级为**语义化流量分析引擎。**流量分析引擎提供更人性化符合逻辑的插件编写方式——SafeLineQL， 将复杂的实现逻辑以语义化、逻辑化的语言进行查询和统计，满足实时流量统计分析需求，得到查询和统计结果，**亮点功能在于可以根据这些贴合实际业务安全场景的流量分析结果以编程化的方式处理流量。**

SafeLine QL 能干什么，如何提供给用户进行实时流量分析功能？我们结合几个常见案例来说明。

1实际业务问题 

某业务被 CC 攻击了，导致访问非常缓慢，甚至不可用。

**解决思路：**

1. 攻击者的请求集中在运算量大的 API

2. 攻击者的请求频率较高

**解决样例：**

问题转化：服务器响应时间超过 10s 的请求 IP 与 URL

SELECT ip, url\_path  
FROM access\_log  
WHERE TIME > 10

问题转化：一分钟内访问次数最多的 10 个 IP

SELECT ip  
FROM access\_log  
GROUP BY TUMBLE\_WINDOW(TIMESTAMP, 60),  
ORDER BY COUNT(ip) DESC  
LIMIT 10

2实际业务问题 

某业务遭到了暴力破解、撞库攻击。

**解决思路：**

1. 攻击的请求密集在登录接口

2. 登录失败的次数较高

**解决样例:**

问题转化：统计 1 小时发生 1000 次以上登录事件的登录成功率

SELECT ip  
FROM access\_log  
WHERE url\_path = "/login"  
GROUP BY TUMBLE\_WINDOW(TIMESTAMP, 60\*60), status\_code  
ORDER BY COUNT(ip) DESC  
LIMIT 1000

3实际业务问题 

某投票业务，虽然一个账号只能投票一次，但是短时间内依然被刷了很多恶意票。

**解决思路：**

1. 攻击者的请求密集在投票接口

2. 攻击者使用了批量账号来投票

**解决样例：**

问题转化：统计 1 小时使用相同 IP 登录多个用户并投票的情况

SELECT  
  ip, SESSION  
  COUNT(SESSION) ,  
FROM access\_log  
WHERE url\_path = "/vote.php"  
GROUP BY TUMBLE\_WINDOW(TIMESTAMP, 60\*60), ip  
ORDER BY COUNT(SESSION) DESC  
LIMIT 100
