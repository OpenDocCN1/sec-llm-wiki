# 实战案例丨某次红蓝对抗之Solr-RCE实战绕过

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=Mzg4MDY1MzUzNw==&mid=2247494591&idx=2&sn=aecdc57551c803e6ac479bba0bf0ea2e&chksm=cf734e31f804c7276f0242ab55026d69f07f9f12478d3579041c8d3483c0fecc75f89f015a2b&scene=126&sessionid=1681576052#rd](http://mp.weixin.qq.com/s?__biz=Mzg4MDY1MzUzNw==&mid=2247494591&idx=2&sn=aecdc57551c803e6ac479bba0bf0ea2e&chksm=cf734e31f804c7276f0242ab55026d69f07f9f12478d3579041c8d3483c0fecc75f89f015a2b&scene=126&sessionid=1681576052#rd)

![](../Images/a3fa0aec2df7713a75903be1d4ddeb71.png)

  

在某次红蓝对抗过程中，要结束的时候突然发现了扫描器爆出了Solr-RCE-CVE-2019-0192漏洞。

  

但是进行测试过程中发现存在各种各样的问题。

![](../Images/e30cd275634451671ee97c2450372735.png)

  

*01** 绕过1*

进行测试，发现目标只可以执行单命令，返回字段比较少的命令。

*   
*   

```
whoamiipconfig
```

![](../Images/f3c9b675527ebfd238d7540c40743aa4.png)

执行dir，无法执行。

![](../Images/1aa7403aeba43f68ca20f30dfb4752dc.png)

注：想着直接执行ps直接上线就好了，各种尝试之后，后知后觉发现对方不出网

  

*02** 写Webshell*

发现目标不出网的时候，只有写webshell这一条路子可以走了，但是目标只能执行个别命令还无法解决。

![](../Images/512ce41b6c9c00e8fc4576fbb437d540.png)

dir无法执行，陷入了沉思，加入单双引号也不行。根据以前的内网经验是不是系统无法默认调用到dir.exe。

  
那么 cmd /c dir是不是可以。

![](../Images/1768104c634d0d8f49e023ead8f70468.png)

惊奇的发现，可以完美的执行命令。通过dir找到目录进行写马尝试。

  
但是发现目标路由规则写死了，无法直接访问到.jsp的文件。

![](../Images/5b2af53e5bc836926119facd2cc118f3.png)

刚开始以为是根目录的问题，发现不止根目录，常用的css/js和img下面的也不行。

![](../Images/e30ffac31aaf7e89459df990d5a07525.png)

后续在webshell中看到，翻文件看到了有类似路由机制的验证：

![](../Images/a7f01be52bc2af61b0f4443fc7e68a07.png)

  

*03** 言归正传*

在执行rce的时候，找到了solr的目录，发现这里的.jsp是没有这个验证的。

![](../Images/faeffa26d1240288d6ef1eb9f173b472.png)

利用命令执行进行找到该位置，进行写文件。问题来了，echo 写入一直无法写入。

![](../Images/ef706b00d6f494b9b33593243ed8244a.png)

**问题解决：**把这里的特殊字符进行编码后即可成功写入。

  
又遇到一个问题，jsp的马子都有%号，这里不论怎么做 %就是写不进去。差点放弃，找不到不带%的马子。

  

*04** 柳暗花明*

但是想到了上午利用过的Certutil可以进行编码解码，这样就没有特殊字符了。

![](../Images/1cd037cfeaa1ce875524c95212152ce7.png)

完全没问题，刚开始一点一点追加，发现下面的会写进去两行

![](../Images/02aecf984a7e3d642dc595f86f00beab.png)

看了一下就最后有一个+号，没有特殊字符，全部直接写进去。

![](../Images/5d35154513c402023b78831d549e6297.png)

然后decode进行解码,完美。

![](../Images/81c55d35abdcac7e5d22eee9913628e2.png)![](../Images/b235df1f9bf4360e27389904d940a3d2.png)

访问但是是500，不过确很开心，因为确实写上来。

![](../Images/e39a30fdab724ab57d53d5846ca7c53c.png)

接下来解决为啥500就可以了，type 123.jsp查看一下。

![](../Images/7be5a2131c5f218166f98bad79241367.png)

发现最后decode的时候，少了一个\>，本地测试，是没有这个问题的。可能是目标一次性字符长度的问题。

  
这里很简单了，追加一下就可以了。

![](../Images/18a5b8bd4a8593c2a9e7772606bc7236.png)

**连接成功**

![](../Images/1fc9a49b342899dd007187ebd5aa47b5.png)
