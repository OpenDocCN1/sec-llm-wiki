DevSecOps是安全与DevOps深度融合的产物，是安全左移的具体实践。DevSecOps需要一系列工具流程来进行支撑，这些工具可以使用商业版本的工具，也可以使用开源工具。**本文将介绍一下DevSecOps各个关键流程中的可以借鉴使用的开源工具。**首先介绍一下DevSecOps的流程图如图1所示：

  

![](../Images/224abbd55db041d88dcd51372379ee1f.png)

  

图1：DevSecOps标准流程图

  

DevSecOps流程分成以下部分：计划（Plan）、开发（Development）、构建（Build）、测试（Test）、版本发布（Release）、系统上传服务器（Deliver）、系统上线（Deploy）、运营（Operate）、监控（Monitor）和反馈（Feedback）。下面将针对这些部分一一介绍。

**一、计划阶段**

计划阶段的安全活动主要是引入安全需求，作为产品设计人员，应该清楚当前产品涉及的数据分类分级，比如是绝密数据还是普通数据，是个人识别信息还是普通个人数据，该产品会投放什么市场，涉及什么合规要求。这些信息对于后面的信息安全工作非常重要。这里没有涉及太多工具，主要是产品设计人员将这些需求列出来，形成用户故事和用户用例就已经不错了，这里的工作比较粗糙，不会要求特别精细，精细应该是后面的开发设计阶段的事情。

**二、开发阶段**

开发阶段是一个很大的阶段，可以进一步分解为设计阶段与编码阶段两个部分。

**三、设计阶段**

设计阶段，最经典的安全活动就是威胁建模，而最经典的威胁建模理论是微软的STRIDE。 OWASP有个项目叫OWASP Threat Dragon，提供一种工具进行具体的威胁建模工作。OWASP Threat Dragon中文翻译是威胁龙，图标也是一条龙，如图2所示。

![](../Images/6e5e3ec748076f2ea7d4e1411ce7d04e.png)

  

图2: OWASP威胁龙

  

项目的具体链接是：https://owasp.org/www-project-threat-dragon/。威胁龙用于创建威胁建模图，遵循威胁建模宣言与价值观。威胁龙工具支持STRIDE、LINDDUN、CIA三种模型，提供建模图并实施规则引擎以自动生成威胁及其缓解措施。

  

可能有些朋友说STRIDE这个模型太重，威胁龙这个工具太笨重，不满足DevSecOps的敏捷要求。实际上我不是很同意这个观点，工具好不好用，关键看你怎么使用。不过Google的确也提供了另外一种威胁建模的思路，通过问卷的方式进行威胁建模。我过参加OPPO的分享，也看到OPPO使用类似的思路，另外，我在以前的分享中，也有介绍过这个工具，全名叫vsaq，它的github地址是：https://github.com/google/vsaq。

  

VSAQ，全称是供应商安全评估问卷，开始是用于供应商安全评估的，但是可以借鉴用于威胁建模。VSAQ 不是 Google 的官方产品（实验性的或其他的），VSAQ 是一个交互式问卷应用程序。其最初的目的是通过不仅促进信息收集，而且促进以模板形式重新显示收集到的数据来支持安全审查。在谷歌，像这个存储库中的问卷一样，用于评估第三方的安全程序。但是所提供的模板可用于多种目的，包括对您自己的安全程序进行自我评估，或者只是熟悉影响 Web 应用程序安全性的问题。大家如果想立刻试用这个产品，可以访问：https://vsaq-demo.withgoogle.com/。你会看到这样的界面，如图3所示：

**四、开发阶段**

设计完成后，就要进入开发阶段，开发阶段的安全活动主要是静态应用安全扫描（SAST）、开源组件安全扫描（OSA）或者（安全组件扫描）SCA，如果使用了云原生技术，还会有容器镜像安全扫描（Docker Image Scan）等。OWASP有个项目专门列举出各种开源或者免费的工具：https://owasp.org/www-community/Free\_for\_Open\_Source\_Application\_Security\_Tools，大家可以参考和借鉴。

  

**SAST**

首先说一下静态分析安全扫描（SAST）。虽然SAST误报率比较高，漏报率也比较高，但是SAST是DevSecOps中开发安全的基础，如果不做SAST，就会感觉开发安全缺失一个重要的环节。

SAST全称是静态应用安全测试（Static application security test），也称为源代码分析工具（Source code analysis tool）。OWASP有个项目专门描述SAST：https://owasp.org/www-community/Source\_Code\_Analysis\_Tools。

SAST可以帮助分析源代码或代码的编译版本，以发现安全漏洞。SAST有自己的优点和不足。

SAST的优点是：

1.  扩展性好——可以在许多软件上运行，并且可以重复运行（如夜间构建或持续集成）。
    
2.  识别某些众所周知的漏洞，例如：缓冲区溢出、SQL注入漏洞。
    
3.  SAST 工具可以通过文件名、位置、行号甚至受影响的代码片段突出显示有问题的代码，这样的输出可以帮助开发人员定位问题。
    
      
    

SAST的不足有：

1.  很难自动搜索多种类型的安全漏洞，包括：认证问题、访问控制问题、密码的不安全使用问题等
    
2.  当前的 SAST 工具是有限的，只能自动识别相对较小比例的应用程序安全漏洞。
    
3.  大量误报。
    
4.  经常找不到配置问题，因为配置没有在代码中体现出来。
    
5.  难以“证明”已识别的安全问题是实际漏洞。
    
6.  许多 SAST 工具难以分析无法编译的代码。工具通常无法编译代码，除非有：正确的库、编译说明和所有必需的代码。但Checkmarx就发展出不需要进行编译，而只需要进行语法解析的技术。
    

  

OWASP提出了SAST的选择标准，并且列出了一系列开源的SAST工具，大家可以参考上述的OWASP项目。

除了上述的SAST工具外，我还想推荐一个项目CodeQL，Github地址是：https://codeql.github.com/。CodeQL号称使用业界最先进的语义代码分析引擎。CodeQL可以像查询数据一样查询代码；编写查询以查找漏洞的所有变体，从而永远消除这些漏洞。然后分享自建的查询以帮助其他人也这样做。这里感觉借鉴了Checkmarx的CxQL的做法，是否能够有效发现漏洞需要自己编写查询规则，总的来说值得尝试

  ![](../Images/8a54159932691b0f6f72a08944af4078.png)

**OSA**

OSA，我最推荐的是**OWASP Dependency Check**，项目地址是：https://owasp.org/www-project-dependency-check/，Dependency-Check 是一种软件组合分析 (SCA) 工具，该工具试图检测项目依赖项中包含的公开披露的漏洞。该工具通过确定给定依赖项是否存在通用平台枚举 (CPE) 标识符来实现此目的。如果找到，该工具将生成一个链接到相关 CVE 条目的报告。 

![](../Images/8b22c3e98468fa310c0edab16ed0e393.png)

  

Dependency-Check在启动的时候会下载对应CVE的漏洞列表，也就是说Dependency-Check能够找到的漏洞就是CVE列出来的漏洞，如果想支持其他漏洞库，就要自己开发或者使用其他工具。

OWASP除了Dependency-Check，还有一个工具叫Dependency-Track，该工具的OWASP地址是：https://owasp.org/www-project-dependency-track/。

**Dependency-Track 是一个智能组件分析平台**，帮助组织识别和降低软件供应链中的风险。Dependency-Track 通过利用软件物料清单(SBOM)的功能，采用了一种独特且非常有益的方法。这种方法提供了传统软件组合分析 (SCA) 解决方案无法实现的功能。通过SBOM，Dependency-Track可以和多个漏洞情报来源集成，包括：美国国家漏洞数据库(NVD)、NPM库、Sonatype OSS和VulnDB等。理论上，只要符合SBOM标准的漏洞情报库都可以和Dependency-Track集成。

![](../Images/b92d906f493dd98298697aa12b67e02d.png)

  

**容器镜像扫描**

如果使用云原生技术，那么容器技术是不能避免的。容器的运行基于容器镜像，那么容器镜像的安全就是至关重要了。容器镜像安全扫描的开源项目很多，最有名的是Clair，Github地址是：https://github.com/quay/clair。

**Clair 是一个开源项目**，用于对应用程序容器（目前包括OCI和docker）中的漏洞进行静态分析。客户使用 Clair API 为其容器镜像建立索引，然后将其与已知漏洞进行匹配。

![](../Images/9484d74778fb084c28b7fb8bd4ac1937.png)

                               

还有一个项目是Anchore，Github地址是：https://github.com/anchore/anchore-engine。

**Anchore Engine 是一个开源项目**，为容器镜像的检查、分析和认证提供集中式服务。Anchore Engine 作为 Docker 容器映像提供，可以独立运行，也可以在编排平台（例如 Kubernetes、Docker Swarm、Rancher、Amazon ECS 和其他容器编排平台）内运行。

最近，Docker官方直接将容器镜像安全扫描的功能集成到docker里面，直接使用docker scan命令就可以进行扫描，详情请参加文档：https://docs.docker.com/docker-hub/vulnerability-scanning/。

**六、测试阶段**

测试阶段的安全活动主要是IAST和DAST，其中IAST是最近几年兴起的新的安全测试。

**DAST**

DAST全称是动态应用程序安全测试，一般是针对于Web应用程序，所以又叫做Web应用程序漏洞扫描器，DAST一般是一种自动化工具，通常从外部扫描 Web 应用程序，以查找安全漏洞，例如跨站点脚本、SQL 注入、命令注入、路径遍历和不安全的服务器配置。OWASP有个项目叫漏洞扫描工具，项目地址是：https://owasp.org/www-community/Vulnerability\_Scanning\_Tools。该项目列举了大量开源和商业的漏洞扫描工具。如何对DAST的工具的效能做一个有效的评价，可以参考另外一个OWASP项目OWASP Benchmark，项目地址是：https://owasp.org/www-project-benchmark/。

**OWASP有个项目叫做ZAP**，就是一个类似商业软件Burpsuite的漏洞扫描器，项目地址是：https://www.zaproxy.org/，Github地址是：https://github.com/zaproxy/zaproxy。

  ![](../Images/d6891013066658e1a9805ac7cd0b018e.png)

  

除了OWASP的ZAP项目外，我还推荐两个产品：

**一个是Arachni**，Github地址是：https://github.com/Arachni/arachni。

Arachni 是一个功能齐全、模块化、高性能的 Ruby 框架，旨在帮助渗透测试人员和管理员评估 Web 应用程序的安全性。Arachini通过在扫描过程中监控和学习 Web 应用程序的行为来训练自己，并且能够使用多种因素进行元分析，以正确评估结果的可信度并智能识别（或避免）误报。

与其他扫描器不同的是，Arachni考虑了 Web 应用程序的动态特性，可以检测在 Web 应用程序的圈复杂度路径中移动时引起的变化，并能够相应地进行自我调整。通过这种方式，可以无缝处理非人类无法检测到的攻击/输入向量。

   ![](../Images/4be6b88efcceab92da30ffd14bd166d7.png)

**另外一个是nikto**，GitHub地址是：https://github.com/sullo/nikto。Nikto的网站是：https://cirt.net/nikto2。

Nikto 是一个开源 ( GPL ) 网络服务器扫描器，它针对多个项目对网络服务器执行全面测试，包括 6700 多个具有潜在危险的文件/程序，检查 1250 多个服务器的过时版本，以及 270 多个服务器上的版本特定问题。它还会检查服务器配置项目，例如是否存在多个索引文件、HTTP 服务器选项，并将尝试识别已安装的 Web 服务器和软件。扫描项目和插件经常更新，可以自动更新。

  ![](../Images/691c2826b3c1d747461599b6a556713c.png)

**IAST**

IAST全称是交互式应用程序安全测试，补充了传统的自动安全测试 (AST) 工具，例如SAST和DAST。

IAST是一个相当新类型的应用程序的安全工具，重点检测的安全问题，在您的应用程序的代码。它们旨在作为代理在应用程序服务器中运行，通过分析应用程序的流量和执行流程来实时检测安全问题。无需修改应用程序，也无需进行特定的渗透测试活动。

IAST的优点是：

1.  准确性：准确性是 IAST 的主要优势之一，包括能够检测尽可能多的现有风险（低误报率），同时不会将不可利用的点识别为可利用点（低误报率）。
    
2.  在 SDLC 的所有阶段都有用： IAST 工具不限于 SDLC 的特定阶段。
    
3.  与 SDLC 工具和 DevOps 实践的集成。
    
4.  在不影响安全性的情况下加快上市速度：IAST 提供实时漏洞检测和即时反馈。开发人员在运行代码后立即收到安全反馈；无需等待其他扫描过程完成。
    
5.  静态和动态可见性：主要优势之一是应用程序源代码（静态视图）和请求执行视图（动态视图）的可见性。静态和动态视图的结合是上述高精度背后的关键驱动因素之一，以及反馈的可操作性，它提供了风险的源代码文件和行号。

**七、其他阶段**

测试完成后，就可以进行发布，产品发布后就进入运维周期，运维过程中发现问题又会反馈回计划阶段，然后完成一个循环。这里涉及的安全活动有服务器和网络的安全扫描，安全运营等。

服务器和网络的安全扫描是保证服务器没有已知的高危漏洞，这个是一个非常重要的环节。推荐的开源工具有OWASP Nettacker项目，项目地址是https://owasp.org/www-project-nettacker/。

OWASP Nettacker 项目的创建是为了自动化信息收集、漏洞扫描，并在一般情况下帮助渗透测试工作。Nettacker 能够使用各种方法运行各种扫描，并为应用程序和网络生成扫描报告（HTML/TXT/JSON/CSV 格式），包括发现开放端口、服务、错误、漏洞、错误配置、默认凭据、子域、等。Nettacker 可以作为命令行实用程序（包括作为 Docker 容器运行）、API、Web GUI 模式或作为 Maltego 转换运行。

安全运营需要考虑安全运营自动化，这里就会引入SOAR。SOAR全称是安全编排、自动化与响应（Security Orchestration, Automation and Response）。

SOAR 指的是使组织能够收集由安全运营团队监控的输入的技术。例如，来自 SIEM 系统和其他安全技术的警报——可以通过利用人力和机器的力量来执行事件分析和分类——有助于定义、优先考虑和推动标准化的事件响应活动。SOAR 工具允许组织以数字工作流格式定义事件分析和响应程序。

这里有个Github项目讲的比较清楚，项目地址是https://github.com/correlatedsecurity/Awesome-SOAR。在该项目里面，推荐了两个开源产品：

**一个是WALKOFF，**项目地址是https://github.com/nsacyber/WALKOFF。WALKOFF 是Reddit公司推出的一个灵活、易于使用的开源的自动化框架，允许用户集成自己的功能和设备，以减少重复、乏味的任务，减慢运维的速度。

 ![](../Images/36635d47b54a36823180487177eccd5e.png)

**另一个是TheHive，**项目地址是https://thehive-project.org/。TheHive是一个可扩展、开源和免费的安全事件响应平台，与 MISP（恶意软件信息共享平台）紧密集成，旨在让 SOC、CSIRT、CERT 和任何处理需要调查和采取行动的安全事件的信息安全从业者的生活更轻松更便捷。Github地址是https://github.com/TheHive-Project/TheHive。

    ![](../Images/8574e56dff76fcaa0f6bd905037de1cd.png)

安全运营还有两个安全活动可以考虑。

一个是使用WAF保护现有的系统，防止一些通用的注入漏洞攻击。这里推荐有一些开源的WAF，网址如下https://serverguy.com/security/open-source-web-application-firewall/。

**主要推荐一个项目ModSecurity，**项目地址是https://github.com/SpiderLabs/ModSecurity。ModSecurity 是由 Trustwave 的 SpiderLabs 开发的用于 Apache、IIS 和 Nginx 的开源、跨平台 Web 应用程序防火墙 (WAF) 引擎。

  ![](../Images/430a35b467eb04af11474579c1357640.png)

  

OWASP还有一个关联项目是OWASP ModSecurity 核心规则集，项目地址是https://owasp.org/www-project-modsecurity-core-rule-set/。OWASP ModSecurity 核心规则集 (CRS) 是一组通用攻击检测规则，用于ModSecurity或兼容的 Web 应用程序防火墙。CRS 旨在保护 Web 应用程序免受广泛的攻击，包括OWASP 前十名，并将错误警报降至最低。CRS 提供针对许多常见攻击类别的保护，包括 SQL 注入、跨站点脚本、本地文件包含等。

![](../Images/aa6d9ac02977f0aa873e3eeb09d56d64.png)

另外一个是使用RASP去做类似动态补丁的漏洞延缓修复操作。RASP全称是应用运行时自我保护（Runtime Application Self Protection）。

RASP是应用程序运行时出现的技术。当程序开始运行时，RASP通过分析应用程序行为以及此行为的上下文来保护程序免受恶意输入的侵害。RASP持续监控和检测攻击并立即缓解，无需人工干预。

这里推荐的项目是OpenRASP，这个是百度开源的项目。这个项目在前面介绍IAST的时候也介绍过，项目地址是https://rasp.baidu.com/，Github地址是https://github.com/baidu/openrasp。
