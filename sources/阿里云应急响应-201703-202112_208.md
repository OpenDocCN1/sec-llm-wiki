# 【菜鸟腾飞】简单的Getshell和提权

应朋友之邀，纯属友情检测，他给了一个IP(全文IP用此代替xxx.xxx.xxx.xxx)，简单看了一下是一个生活与技术分享的博客，博客风格挺简约的。接下来说重点吧，我一开始看看有没有后台，敏感目录之类的。尝试了几个常见的后台默认地址例如/admin、/manager、/Webadmin等等，发现后台地址为xxx.xxx.xxx.xxx/admin/login.aspx

![](../Images/a7a9d15ebabe2bcf35d2f735e12df9b9.png)

在查看网页源代码也找到后台地址，很多时候页面源代码和js文件有可能存在一些敏感信息，对你接下来的渗透有一定的帮助，有时候多看看页面源代码和js文件还是有好处的。  
![](../Images/43c383b926f92b9b443c6bfb9e509df0.png)

利用网站应用程序中的服务器错误可爆出网站物理路径，过多的报错信息会显会导致网站的安全性下降，解决方法：修改web.config配置关闭远程报错信息会显，Web 应用程序根目录下的“web.config”配置文件中创建一个`<customErrors>` 标记。然后应将此`<customErrors>` 标记的`“mode”`属性设置为`“Off”`，可利用这些报错信息增加下一步渗透的成功性。

![](../Images/f08b02c5d4a628c6f2ce9f371b29e0aa.png)

物理路径信息

尝试了几个常见的弱口令admin/admin,manager/manager,admin/123456,test/test等等，还是未果，用burp爆破一波，弱密码进入了后台。这套程序是*TCMS，*TCMS之前被爆出了好几个漏洞，知道是\*TCMS程序（CMS指纹识别也可以用：云悉指纹）可以在漏洞库找找漏洞利用也是比较快速拿到shell的方法之一。

![](../Images/a8fd39da3d7215fe1820a7006b9572a6.png)

进到后台后果断找上传点，看看能不能直接上传拿到shell，或者添加修改上传类型再上传，直接最暴力的方法。如果没有上传点可以利用后台管理功能写入webshell、利用后台管理向配置文件写webshell、利用后台数据库备份及恢复获得webshell或者利用数据库压缩功能等等其他方式。我下面用了两种方式拿shell。

一．在文件上传设置处那里增加一个asa、ashx和cer上传类型，先测试一下上传功能是否能用，正常的图片是可以上传成功的。asp、php、aspx之类的会被检测，前端也做了验证，添加了上传类型后发现asa/ashx也是上传不了。

![](../Images/25b18c34d76c16c0670dffa31747d237.png)

前端检查文件后缀名

现在我们要做的是绕过上传限制，绕过上传有很多种姿势。可以利用burp抓包改包，先上传一个jpg类型的木马，然后通过burp将其改为asa/ashx后缀名也是无法上传。

![](../Images/dbe9df1e2fb459afb01cbc0b270420d7.png)  
![](../Images/3888a83503e6ea28b97255b416294e40.png)

发现通过burp将后缀名改为cer或者在jpg后缀名加.cer可成功上传拿到shell，一个冷门的文件后缀名绕过了上传限制，应该是黑名单校验，黑名单检测是一般有个专门的blacklist文件，里面会包含常见的危险脚本文件。黑名单未将后缀名cer添加进去，导致上传成功getshell。绕过上传的姿势有很多，例如nMask’s大佬的一篇文章有详细的讲解文件上传漏洞绕过姿势，有客户端绕过、服务端绕过、文件类型、文件头、文件后缀名、配合文件包含漏洞绕过、配合服务器解析漏洞绕过、CMS、编辑器漏洞绕过、配合操作系统文件命名规则绕过、配合其他规则绕过、WAF绕过等等。

![](../Images/6438a67ca398599cb17a231fed508b2a.png)  
![](../Images/e687ee6cedda68e7c9ae0a57d9e26550.png)

![](../Images/1a44871d5a0e96d670f502a655eac293.png)

二．也可以利用后台管理功能写入webshell，这是这次拿shell第二种方法。

在网站管理中心的界面管理中，可以找到站点模板管理的有个模块编辑功能，这个站都是一些伪静态页面，模块中可以看到一个aspx页面对应一个html页面，我们可以在template/main/link.html页面写入一句话木马后点击提交保存此模块，我们就可以获得一句话木马的地址为xxx.xxx.xxx.xxx/xxx/xxx/link.aspx直接拿起菜刀连起来。

![](../Images/c20252506c797f110a09bd0ffbb15fc3.png)  
![](../Images/366ad1a6a9ed696fd130340c15da26f9.png)

getshell之后在cmd执行任何命令都显示拒绝访问，权限居然这么低，这就很尴尬了。

![](../Images/12567e81d731ef3a07cda1ad41fefa13.png)

怎么可能就这样子停下来，接下来就是进行提权，之前做过信息收集知道是aspx的伪静态网站，我直接上传了一个aspx的大马，扫过端口开着1433/3306/3389,服务器有mssql环境，aspx大马的权限比较高，可以查看系统信息systeminfo进行信息收集。

![](../Images/73315c8ed7b5f84a8951e42d93825c1b.png)

百度了一下Microsoft Windows NT 6.3.9600.0 可以判断这台服务器是win2012 r2，用tasklist查看了一下并没有杀软360的存在，在aspx大马也不能执行cmd命令，显示拒绝访问说明了cmd所在的目录不可读，可想而知写入更加不可能了，需要找一个可读可写的目录上传自己的cmd.exe上去，上传的时候不要以exe后缀名上传，后缀是什么都不会影响，最后还是会以exe程序执行，传上去之后发现还是无法执行，我找到了windows powershell程序可以执行命令了，只能执行几个简单的命令，无法添加用户，而且还没有回显。

![](../Images/86491599c97291102f941ddd44f152f1.png)  
![](../Images/fd02c06af0c5d083ecef9b9d909d99c7.png)  
![](../Images/20dac401af92b221042c2d7b90474fb4.png)

只有iis权限，之前看到端口开着1433，mssql环境可以直接利用sa提权，马上去网站目录下找配置文件，在web/blog目录找到了web.Config查看，找到了sa的密码。

![](../Images/8aca53fe61a8352fb13f3c149af00733.png)

在菜刀直接输入sa、密码和数据库名连接到数据库，数据库开启了xp\_cmdshell，用xp\_cmdshell执行cmd命令后发现是系统权限。

![](../Images/32cd903f68b8c0eca3e0b84289fed54a.png)

拿到系统权限马上添加用户和密码连到服务器去，大功告成，友情检测结束。

![](../Images/e720bc4024fd66ff20c5523d23b80bd2.png)
