概述

在上个月我做了一次公益SRC测试，目标站点是一家法国的公司。该公司有一个很普通网站，上面有新闻，联系页面和文档下载等功能。

在测试中，我发现了一个有趣的事情。该站点使用了AJAX请求来加载某些内容，它包含两个参数。

通过这个请求可以获得最新的新闻，并以HTML形式呈现给用户。


远程代码执行

从前面的发现可以大致地了解该网站的运行机制。我可以试着将ajax的端点中的class类参数改为其他内容。

在实现代码执行之前，我先尝试了stdClass和其他的一些类，但都失败了。

我想到了一个新方法，删除class，然后把另一个参数内容替换为phpinfo()。

OK，这是有效的。现在我该考虑如何放大该漏洞的影响？

在PHP中有一个名为system的参数（http://php.net/manual/fr/function.system.php），使用该函数可以执行一些代码并且有结果回显。

system ( string $command [, int &$return_var ] ) : string

聪明的你应该发现了，我还需要别的参数作为命令的内容。经过一段时间的信息收集，我发现某些页面中存在名为args的参数（这并不困难）。

现在我可以（在目标系统）执行任何UNIX命令，我有很多事可以做。我进一步搜寻了一些文件夹，并且查看文件内容。

LDAP服务器

检阅配置文件总是最有趣的，在那里我找到了一些数据库密钥信息。

这是好运还是倒霉？我只发现了一个配置文件，其中包含20个数据库和一台LDAP服务器的登录名和密钥。

但为什么上面会有一台LDAP服务器呢？首先让我来了解了解LDAP服务器。

轻型目录访问协议（英文：Lightweight Directory Access Protocol，缩写：LDAP）是一个开放的，中立的，工业标准的应用协议，通过IP协议提供访问控制和维护分布式信息的目录信息。目录服务在开发内部网和与互联网程序共享用户、系统、网络、服务和应用的过程中占据了重要地位。例如，目录服务可能提供了组织有序的记录集合，通常有层级结构，例如公司电子邮件目录。同理，也可以提供包含了地址和电话号码的电话簿。
源自维基百科：

https://en.wikipedia.org/wiki/Lightweight_Directory_Access_Protocol

为了简单化LDAP地概念，首先得记住它是用户的目录。此目录只允许用户连接一次并且它可以与各种应用和网站链接起来。

有人会问“为什么LDAP凭据信息会出现在配置文件中？”，很简单，因为用户可以自定义更改LDAP访问密钥。

为了在MacOS上连接LDAP服务器，我需要下载LDAP管理软件。我发现只有很少的免费应用可以使用，我使用的是LDAPSoft。

这个LDAP凭据只有读取权限，我无法修改用户的数据。

感谢Wikipedia（维基百科）和LDAP服务器，我发现的安全漏洞影响了大约4000人！

我能控制每个人的：

  • 姓氏与名字

  • 邮件地址

  • 出生年月

  • 电话号码

  • 密码重置（随机数字）

  • 标签RFID的具体信息（MIfare）

  • 开启Windows会话个人目录

员工的个人RFID可以遥控公司的智能设备。因此，我可以购买空白的银行RFID标签，然后输入LDAP服务器上员工的信息，从而冒名（员工）控制智能设备。这种类型的标签并不贵，实现起来非常简单。

虚假短信轰炸

这个公司有一个我从未见过的SMS短信报警系统，当公司的智能设备被入侵或者是发生恐怖袭击时，该系统会发送警报短信给员工。

实际上经过一些搜索后，我已经获得了SMS发送系统的API密钥。

总结

  1. 获取了约4000名员工（或前雇员）的个信息

  2. 访问20个公司数据库

  3. 通过REID控制公司智能设备（未验证）

  4. 获取员工的个人密钥从而实施别的攻击行为

向提交该公司报告后，目前公司已经修复了这个RCE漏洞。
