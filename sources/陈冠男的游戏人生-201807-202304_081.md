# 对 inuse 的 fastbin 进行 extend

  

```
//gcc -g 1.c
int main(void)
{void
 *ptr,*ptr1;malloc(0x10);//分配第一个0x10的chunk
malloc(0x10);//分配第二个0x10的chunk
long long *)((long long)ptr-0x8)=0x41;// 修改第一个块的size域
free
(ptr);malloc(0x30);// 实现 extend，控制了第二个块的内容

;
```

# HITCON Trainging lab13

  

实现了增删改查的功能，index 是从 0 开始的，结构是这样的：

一开始先会申请一个 0x10 的 chunk，用来存放申请的 heap 的大小和指针，然后后面才会申请要申请的 heap 的 chunk

  

![](../Images/f0d3daa435483905db7688a21bbead47.png "image.png")

  

有一个 off by one 的漏洞，heaparray\[a1\] 本来就是存的 size，加上了个 1，可不就是多写了一位

  

![](../Images/51578d6bd8f4fb3cb6be166b92cb5fa6.png "image.png")

  

这是创建的时候的 size

  

![](../Images/34e7a1be51da943ea1053b6390b06153.png "image.png")

  

可以通用来写下一个堆块的 size 字段，伪造 chunk 的大小，然后 overlapping 更改指针

  

free 函数的 got 表项的地址

  

![](../Images/6de2ec3d50754fb3a350c8e173c646ae.png "image.png")

  

通过 off by one 把下一个 chunk 的 size 位给改为 0x41，这里的 heap 申请的是 0x18，多出来的 0x8 会直接用下一个 chunk 的 prev\_size，所以我们才能把下一个的 size 给覆盖掉

  

![](../Images/20ed1c43bb165cd79036b5471c8ea4aa.png "image.png")

  

然后在释放的时候，我们释放了一个 0x40，一个 0x20，那么下一次申请的时候，要先申请 0x20 的结构体，所以会先在 0x603060 那个地方存放结构体，在 0x603070 这里放申请的 heap，而写内容的时候恰好可以把结构体的内容给覆盖掉

  

`p64(0) * 4 + p64(0x30) + p64(heap.got['free'])`

  

![](../Images/343904082014e03788eadb6bca4f68f5.png "image.png")

  

这样，当 show 的时候展示的就是 free 的 got，拿到他以后可以用来计算 libc，另外，因为在刚刚申请的结构体中，内容现在指向的是 free 的 got，所以只要编辑内容就能够直接把 free 的 got 表里改成 system 的地址

  

然后之前我们已经把第 0 个 heap 的内容给改成了 /bin/sh，这时候只要 delete(0) 就能拿到 shell
