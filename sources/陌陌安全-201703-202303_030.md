本文介绍的DNS Response Policy Zone(响应策略区域，以下简称RPZ)技术就可以满足上述需求。

# **1、Response Policy Zones 介绍**

> A response policy zone (RPZ) is a mechanism to introduce a customized policy in Domain Name System servers, so that recursive resolvers return possibly modified results.

维基百科\[1\]解释到，RPZ是一种在DNS服务器上自定义策略的机制，它可以让递归解析返回被修改后的结果。在RPZ官网\[2\]，更是提及到它的另一个名字——DNS Firewall。目前RPZ机制仍作为IETF草案存在\[3\]，但RPZ官网\[2\]显示其已被BIND 9、PowerDNS Recursor 4+等多款DNS软件支持。

# **2、作用**

RPZ的主要作用是用于保护用户免受互联网上已知恶意域名、IP、nameserver等的不良影响。例如：  
  ·  对于已知的恶意域名，RPZ可以拦截用户对它的访问  
  ·  对于已知的恶意IP，RPZ可以拦截指向这些IP的域名解析响应  
  ·  对于已知的恶意nameserver，RPZ可以过滤掉这些恶意NS的解析响应

# **3、原理**

![](../Images/14a11480ba5c785192bbf6ee3dfa9d03.png)

图片引自\[4\]，企业DNS Server可以从本地加载RPZ策略文件，也可以用AXFR/IXFR协议远程同步RPZ策略。RPZ策略Zone相当于在DNS Server中增加了多条策略触发规则，当DNS请求/响应信息满足策略触发条件时，DNS Server将对其管控。

# **4、策略**

## **4.1、管控规则**

RPZ管控规则有6种，以下结论由pdns-recursor 4.1.16实验得出。

### **4.1.1、NXDOMAIN**

![](../Images/8708c0a048da0c2cde88619cf485e34d.png)

### 当RPZ存在一个域名CNAME记录指向根域(.)的话，recursor不会向上游DNS进行查询，直接返回NXDOMAIN，即域名不存在。

### **4.1.2、NODATA**

![](../Images/351e4052f9d266359029a4e2b07141ea.png)

### 当RPZ存在一个域名CNAME记录指向通配符顶级域名，recursor不会向上游DNS进行查询，直接返回NODATA，即空返回。

### **4.1.3、PASSTHRU**

![](../Images/9a74ebec723261c3fa55af716b052130.png)

ok.example.com CNAME记录指向rpz-passthru.，会正常返回查询结果，尽管example.com子域下其他域名会返回NXDOMAIN。

### **4.1.4、DROP**

![](../Images/bdb3fb9682518d870caf99d505a6ff09.png)

当RPZ存在一个域名CNAME指向rpz-drop.，recursor会直接丢弃查询请求，查询客户端无法得到正确响应。

### **4.1.5、TCP-Only**

![](../Images/400ad526ef405a3d3fc2201aaefa11cd.png)

当RPZ存在一个域名CNAME指向rpz-tcp-only.，recursor会引导客户的重新以TCP协议再次发起域名查询。

### **4.1.6、Local Data**

![](../Images/6d76407e61edba1c41c55d353f2a2f97.png)

除了前5种特别的管控规则，RPZ也支持常见的解析记录返回（就像域名解析劫持）。  
需要注意的是，通常情况下通配符\*不可以用在解析目标中，但在RPZ的Local Data管控规则中使用通配符\*会产生后缀追加的特殊效果。

## **4.2、触发条件**

RPZ的触发条件有5中，以下结论由pdns-recursor 4.1.16实验得出。

### **4.2.1、Client IP Address**

![](../Images/17f00ed27d25d8b6613d6352e9832e6b.png)

```
RPZ可以按照DNS请求客户端IP地址进行规则触发判断。RPZ约定IP触发条件需要逆序书写。

```

例如常见IP地址写法为B1.B2.B3.B4/prefix，在RPZ中则记为prefix.B4.B3.B2.B1.rpz-client-ip。  
同时要求原IP prefix掩码后面不可以有0。举例为8.2.0.0.10.rpz-client-ip就不是一个合法的触发条件，原因是10.0.0.2在8位掩码后的面存在非零值。

### **4.2.2、QNAME**

![](../Images/f6f45cfb55784c5c13e26602225e59f7.png)

```
同4.1.1节描述，QNAME触发条件匹配查询域名，同时也支持通配符写法。

```

### **4.2.3、Response IP Address**

```

```

![](../Images/a8ac0bd41042e4ddc2ffd39ae260a222.png)

该触发条件用于匹配未经修改的DNS响应中针对A/AAAA记录的answer段的RDATA内容。IP书写规则遵循4.2.1节描述。  
实验发现，www.baidu.com正常情况下会返回如下记录  

![](../Images/a9366f4d3e34c9911cc6ae960f2fa9e5.png)

按4.2.3节中触发条件，匹配到180.101.49.0/24IP段后，www.baidu.com将会返回NXDOMAIN。  

### **4.2.4、NSDNAME**

![](../Images/6b56d2fed8df158e0deab8848e293e5f.png)

```

该触发条件会匹配DNS资源记录的数据路径中出现的nameserver。
```

需要注意的是，nameserver触发条件不一定会如预期进行，因为DNS Server不总是会以Trace的方式从root NS开始查询。

### **4.2.5、NSIP**

![](../Images/7668aab14084978e0bfdbd6ef33e3dd7.png)

```
如4.2.4中描述，该规则匹配nameserver的IP。IP书写规则遵循4.2.1节描述。

```

# **5、公共资源**

ioc2rpz\[5\]的Available DNS Firewall feeds一节提供了互联网上公开的RPZ策略集。其中不乏有blocklistproject、360DGA等业界知名安全团队维护的策略集。

ioc2rpz称DNS是互联网的控制平面，此言非虚。DNS作为互联网的基础设施，安全性方面理应值得高度关注。也希望RPZ尽早走入RFC规范，成为业界最佳实践之一。
