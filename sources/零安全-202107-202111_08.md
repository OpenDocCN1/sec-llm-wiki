### 0x01 什么是UAF漏洞?

简单的解释就是内存被释放后重引用，下面有一段代码可以帮助你掌握此漏洞的一些要素：

![](../Images/780e7c4379534c4c83aa65b5cbe1a2a3.png)

当我们运行这段代码的时候下断点查看他的执行流程，首先申请到一块内存并将此内存清零：

![](../Images/2b2a03b0363ebfe1cda3a6a0e7d44af5.png)

然后复制N个Hello Word到该内存区域：

![](../Images/561bd85577f692634e91796143709df7.png)

在释放该内存区域，从下图中我们可以看出来释放掉内存区域后除了前8个字节被改变外其余的地址值并未变动：

![](../Images/d7cef96918961c2112248e5faf6cb649.png)

然后再次申请一块同样大小的内存，他们指向同一内存区域

![](../Images/a5261ccdd7cbff5d3e6e1c9ced8bf67f.png)

> 通过实验可以得出程序释放内存后，如果没有将指针置为NULL再次引用可能会出现不可预料的结果，且我们再次申请相同大小的内存大概率还是会申请到同一块内存。

### 0x02 HEVD驱动漏洞复现

HEVD是GITHUB上开源的一个内核漏洞学习的驱动，里面具有大量的漏洞案例，首先逆向该驱动的DriverEntry函数可以得到设备名以及符号链接方便建立IO通讯:

![](../Images/943d78201b8bcfbf7a722b6f9db62e0d.png)

然后是MajorFunction函数,此函数一般用作分发请求，具体是干什么的可以百度不详细解释:

![](../Images/5e230957ad4748f8ad269939c4113846.png)

跟进sub\_444064函数，此函数根据设备码进行分发请求：

![](../Images/bf264f7e66e6ee6df1e6ea317aec26b7.png)

漏洞的触发点在sub\_4464E8函数中：

![](../Images/c0d32dfaecb2edfdc44cd3db96098079.png)

通过交叉引用得到sub\_446236对此全局遍历进行了写入：

![](../Images/293a43c029656dd9165d0086c5532fbf.png)

一直往上追发现sub44635A调用了此函数，也就是设备码222013，所以在调用sub4464E8之前需要先传递设备码222013进行初始化，通过交叉引用发现sub\_446362函数释放了此内存：

![](../Images/f82c3010db4381c46baca7cb3ed1ed40.png)

最后在sub\_44611C可以申请0x58大小内存，并将三环传递过来的地址中的值copy到申请的内存中：

![](../Images/c6e75e21f1504ae70bedbaa3575f205c.png)

这样漏洞利用思路就很清晰了：

1.  通过sub\_446236初始化全局变量
    
2.  通过sub\_446362释放该内存
    
3.  通过sub\_44611C申请同样大小内存并复制三环结构体进零环
    
4.  调用sub\_4464E8执行shellcode

#### 构造shellcode

1.  获取当前进程的EPROCESS
    
2.  获取SYSTEM进程的EPROCESS
    
3.  获取System进程Token
    
4.  替换当前进程token
    

由于我们的Shellcode地址是在三环，所以可以直接使用段寄存器fs获取到KTHREAD结构体，在内核中fs寄存器保存了KPCR结构体，该结构0x124偏移处为该线程的Kthrad指针：

![](../Images/fb58996e0b5721fca5b28ab15a6f0b5d.png)

通过KTHREAD偏移0x50处就是EPROCESS，在网上的结构体中并没有说明但是我们知道就行，EPROCESS+0xB8处是进程链表，我们遍历此链表就可以获取到所有进程：

0x04 构造EXP：

传递设备码0x222013申请内存并初始化全局变量

```
1.  `DeviceIoControl(hDevice, 0x222013, NULL, NULL, NULL, 0, &ret, NULL)`
    
```

传递设备码0x22201B释放内存:

```
1.  `DeviceIoControl(hDevice, 0x22201B, NULL, NULL, NULL, 0, &ret, NULL);`
    
```

传递设备码0x22201F再次申请内存并将R3数据copy到R0中：

```
1.  `DeviceIoControl(hDevice, 0x22201F, struct, 0x60, NULL, 0, &ret, NULL);`
    
```

传递设备码0x222017进行提权:

```
1.  `DeviceIoControl(hDevice, 0x222017, NULL, NULL, NULL, 0, &ret, NULL);`
    
```
