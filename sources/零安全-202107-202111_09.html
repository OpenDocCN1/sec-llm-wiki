0x00 漏洞信息:

漏洞简述:

1.漏洞名称：微软操作系统win32k.sys内核特权等级提升2.漏洞编号：CVE-2008-10843.漏洞类型：计算整形溢出4.漏洞影响：代码执行5.利用难度：简单

组件概述:

win32k.sys是windows操作系统管理用户空间的系统内核管理模块

漏洞利用:

该漏洞主要是由于NtUserfnOUTSTRING函数中的ProbeForWrite函数在执行的时候，把判断是否可以写地址计算整形溢出漏洞为0绕过了检查，导致NullTerminateString向0地址写入2字节任意数据

应用/系统影响:

•Microsoft Windows 2000 Service Pack 4•Windows XP Service Pack 2•Windows XP Professional x64 Edition and Windows XP Professional x64 Edition Service Pack 2•Windows Server 2003 and Windows Server 2003 Service Pack 1 and Windows Server 2003 Service Pack 2•Windows Server 2003 r2 and Windows Server 2003 r2 Service Pack 1 and Windows Server 2003 r2 Service Pack 2•Windows Server 2003 x64 Edition and Windows Server 2003 x64 Edition Service Pack 2•Windows Server 2003 with SP1 for Itanium-based Systems and Windows Server 2003 with SP2 for Itanium based Systems Elevation of Privilege Important None•Windows Vista and Windows Vista Service Pack 1•Windows Vista x64 Edition and Windows Vista x64 Edition Service Pack 1•Windows Server 2008 for 32-bit Systems•Windows Server 2008 for x64-based Systems•Windows Server 2008 for Itanium-based Systems

解决方案：

微软官方针对该漏洞已发布安全更新补丁，补丁地址：

0x02 漏洞分析:

基本信息:

•漏洞文件：win32k.sys•漏洞函数：NullTerminateString(Address, a7);•漏洞参数：Address

详细分析:

静态分析:

分析使用的文件为Windows xp sp2的win32k.sys文件。

首先是一个sendmessage发送过来的消息到NtUserMessageCall，然后通过gapfnMessageCall[MessageTable[wm_msg & 0x1FFFF] & 0x3F]2次取数组到NtUserfnOUTSTRING函数。

那MessageTable[wm_msg & 0x1FFFF] & 0x3F的值就为4，MessageTable[wm_msg & 0x1FFFF]就得为0xd

进入NtUserfnOUTSTRING v7 = (UnicodeString ^ ((a7 << 31) | v11 & 0x7FFFFFFF)) & 0x7FFFFFFF ^ ((a7 << 31) | v11 & 0x7FFFFFFF);//这里就是构造值使得计算结果为0，开源的exploit已经指出UnicodeString为0x80000000，a7为0。ProbeForWrite(Address, v7 & 0x7FFFFFFF, 1u); ProbeForWrite这个函数是判断地址是否可写的，这里v7 & 0x7fffffff值需要为0的话就会直接判断成功

NullTerminateString就是把传入的第一个地址两字节赋值为0
