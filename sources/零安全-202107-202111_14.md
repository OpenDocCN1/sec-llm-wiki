### 0x00 前言

最近都在研究内存马，所以分享些自己的一些看法。内存马常见的就是基于servlet、Filter、Listener以及Agent这几种方式，这里介绍的是基于Agent方式的内存马。同时此方法只适用于tomcat和spring中，webgloc以及jboss需要重新找关键类才能实现。

### 0x01 java agent基础

在java中引入了**java.lang.instrument**这个包，这个包可以帮我们在不影响正常编译的情况下修改字节码。agent修改字节码主要有两种方式：

1.启动时加载agent2.启动后加载agent

java agent和普通的java类有些不同，**他需要在premain与agentmain中选择入口点并在MAINFIEST.MF中定义**。

### 0x03 启动后加载

因为真实环境往往jvm都处于加载状态，而java为了能够在不影响业务的情况下并能修改已加载的类，提供了agentmain方法。

说到agentmain方法这里就必须要介绍Instrumentation接口和VirtualMachine，Instrumentation接口主要是为了拦截已经加载的类，而VirtualMachine主要的作用是在不破坏字节码的情况下对字节码进行修改

![](../Images/ab47f9a4c1b3921be98a1b4eb137d84d.png)

VirtualMachine类的几个主要方法：

1.list():获取jvm加载的类2.attach():通过attach方法传入一个jvm的进程id，连接到jvm3.id()：获取jvm的进程id4.loadAgent():向jvm注册一个代理程序agent，在该agent的代理程序中会得到一个Instrumentation实例，该实例可以 在class加载时改变class的字节码，也可以在class加载后重新加载。在调用Instrumentation实例的方法时，这些方法会使用ClassFileTransformer接口中提供的方法进行处理。5.Detach():解除jvm代理6.displayName():获取jvm加载的类的名字

### 0x07 总结:

基于agent加载内存马的方式的优势：比较其他几种内存马隐蔽性更高些，查杀也相对于更难些，当然也不是查杀不了网上也有相关的查杀分析文章。

基于agent加载内存马的方式的劣势：在虚拟内存不够时通过agent加载的方式容易把网站打崩，同时关键类如果选择不对时也容易打网站打挂。所以在实战时最好可以选择Servlet、Filter这类的内存马，毕竟重在稳妥。
