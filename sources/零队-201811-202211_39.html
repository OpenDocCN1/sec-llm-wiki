不管在红队还是hw的过程中，信息侦测是必不可少的步骤，俗话说不打无准备的仗，如果真的是竞赛开始，才开始进行踩点或者信息侦测，个人觉得这样的效率会大大降低以及会浪费较多的时间，所以在没开打之前，就应该长期监测潜在的目标或者挑选一些价值比较大目标进行监测，其实这思想跟现存的网络测绘团队的想法如出一辙。
说到这里，可能有人会问，现存的测绘引擎它不香吗？香是香，但是我认为这不是我想要的香，就举个例子吧，如果搜索相关的Shiro的站点，想问一下几大搜索引擎能搜出来多少或者质量如何，所以如果能够站在巨人的肩膀上进行相关的操作是不是可以解决这个问题呢？如果将几大引擎的结果都集合一下呢？

此文章只做数据源的相关选择解释，对于搜索的关键词或者字段还需个人进行规划，且前端也需要根据个人爱好自行定制。

提前预测或者提前监测，关键词在提前，所以只要能将各大搜索引擎的爬取结果进行适当的储存即可，对于储存的解决方案本篇文章不做太多的赘述。
对于源数据来说，什么是有价值的呢？比如全网的Weblogic、JBoss、Shiro、Struts2、各种OA、各种中间件再或者使用率较高的容器，只要量级足够大，战时就不会太吃紧。

下面就分享一下我自用的两个解决方案：
需要的条件如下：
一台国外VPS（2TB储存、1G运存）
一个Shodan权限较高的账户

方案一（较为简陋，但是字段较全）

将Shodan上所有国内的扫描结果爬取下来，简单粗暴。
爬取代码如下：

import requestsimport timeimport reimport base64
requests.adapters.DEFAULT_RETRIES = 5

fwrite = open('cn.json','a')
all_search = []

key = "key"

def get_count():  for keywords in all_search:    count_com = 'https://api.shodan.io/shodan/host/count?key='+str(key)+'&query='+str(keywords)    content_url = 'https://api.shodan.io/shodan/host/search?key='+str(key)+'&query='+str(keywords)    try:      r=requests.get(url = count_com)      time.sleep(2)      count = int(r.content.split('"total":')[1].split('}')[0])      page_count = count/100      print page_count      get_content(page=page_count,content_url = content_url)      r.close()    except Exception as e:      time.sleep(60)      pass
def get_content(page,content_url):  if page == 0:    page = page + 2  else:    page = page + 1  for i in range(1,page):    try:      r=requests.get(url = content_url+'&page='+str(i))      time.sleep(2)      encode = base64.b64encode(r.content)      fwrite.write('%s\n'%str(encode))      print '-'*30 + 'Page : '+str(i)+'-'*30      r.close()    except Exception as e:      time.sleep(60)      pass      get_count()# 将需要检索的关键词写入到result.txt文本中。

代码的第46行做了一次base64的加密操作，因为如果不想办法压缩一下，硬盘可能放不下，根据我自测，将所有国内的结果都爬取下来大概耗时22小时左右，使用硬盘大概180GB左右，只要能将结果保存下来，至于入库，各位看官应该都是手到擒来。


方案二（结果较为丰富）

利用开放的数据源，例如Rapid的开放数据源，已经有很多小伙伴问过，我是如何将Rapid那么大的量级的文本进行快速查询的，其实快速真的谈不上，大数据说实话，没有资金支持还是不行的，经过测试，将所有log遍历一遍也就一两个小时即可搞定，并且VPS并不需要高配，毕竟我的VPS只有1G内存。
