# **深育杯-Disk**  

### **难点**

> BitLocker 爆破
> 
> rdp 缓存

### **文件：**

![](../Images/dd4fb5998ec7f117b9e32838303464e0.png)

文件后缀为 vera，是 veracrypt 的加密容器，解密文件需要密码

![](../Images/51e1c5af0bce45a0441d08be493c4974.png)

根据文件名在键盘上画出的轨迹  

![](../Images/f0cd4253a2d4f35323aca2d0c3c7cb15.png)

小写的 pvd 作为密码挂载 veracrypt 到本地  

![](../Images/21c3955f8f71d9f669ae1e1eb7283a89.png)

**查看 `goooood` 的文件头可以知道文件使用 7z 进行压缩**  

![](../Images/d53f006fc80a2ce08d3da22536853bb3.png)

解压后发现是套娃，里面还有一个 goood 文件，再次解压后里面有两个文件  

![](../Images/4ca0254b832d36f1c12df9d98b730c7b.png)

其中 `Microsoft reserved partition.img`是个空文件，使用 HexEditXP 打开后里面什么也没有  

![](../Images/8de23acb88ff8973a7f4430632eeff6e.png)

`Basic data partition.img` 使用 DiskGenius 打开后显示使用 bitlocker 加密

![](../Images/ccb643d069381d86aa0a80eebeac12cc.png)

使用 bitlocker2john 跑出 4 个 hash，一般使用第一个或第二个，第三个和第四个 hashcat 会识别不出来  

`bitlocker2john -i Basic\ data\ partition.img`

![](../Images/cfb7c676de82ef46b2098c8a6aae5253.png)

![](../Images/46861200efc0586316a277d589fe0154.png)

再用 hashcat 爆破 bitlocker 密码，hashcat --help 得到 bitlocker 对应的 hash 类型

![](../Images/51cd304434a428e3da3d4d2f3cb9f5a7.png)

把之前 bitlocker2john 跑出的 hash 保存成 txt 文件，使用经典的 rockyou 字典  

`.\hashcat.exe -m 22100 hash.txt rockyou.txt`

![](../Images/673f890b93b032c70dc9833f8d89bbaf.png)

得到密码 abcd1234，DiskGenius 解锁后在回收站内找到一个体积较大的文件，提取后发现文件使用 7z 压缩  

![](../Images/bc5d0b3cac9c933d4608f08ffb70f50b.png)

解压后得到一个 17.4MB 的 bcache24 文件，为 rdp 缓存文件  

使用 bmc-tools 解密文件，得到 1115 张 bmp 图片

一开始以为是拼图，但由于量是在太大放弃

![](../Images/99a36e15ee6c393a3cb4678b8a8a1438.png)

翻到一张文件的缩略图，不出意外就是 flag  

![](../Images/2da5d52229a9b034ff2a916144b36ad2.png)

继续往下翻找到了两张疑似文件名的图片

![](../Images/88ce78ae786b396578bd6615bc6d8aeb.png)

拼起来后再与上面的缩略图作比较后确认文件名与图片上的内容完全一致  

![](../Images/23f0c9da3b3dc4a97f7e3bf7a94c6e9e.png)

尝试提交提示 flag 错误，base64 解码后提交正确  

  

# **深育杯-bridge**

### **难点**

> lsb 隐写
> 
> idat 数据块

### **文件：**

![](../Images/a872f665a86171c39f3f78e2fbaeca7c.png)

  

经典开局一张图，先用 zsteg 跑一遍，提示有 zlib stream，只不过文件头从 789c 被改成了 879c

![](../Images/2d920f02745bde989fb974bf2f6e63f9.png)

导出 zlib 解压后得到一个 rar 文件  

提示可以去看看 flag1，可是还没找到 flag1，所以先暂时放一边

![](../Images/72e33428610a2284ab28da1aaff0ec7d.png)

用 exiftool 查看图片 exif 信息，发现 Copyright 行有一串 hex 文本  

![](../Images/96814b00dad4f738bb0e21afc6ab23e6.png)

解码后为 `dynamical-geometry` 后面会用到  

用 StegSolve 查看图片，发现 PNG 文件头，前面有空数据导致 zsteg 没识别成功

![](../Images/e6f51614eb6ed022c67a748b78a3295d.png)

导出后手动清理多余的空数据，得到一张图  

![](../Images/9544e868b977188716e80963064798f6.png)

凭借经验，应该是把数据藏在某个通道了，按列查看颜色值，发现蓝色通道出现经典 `504B0304`，妥妥的 zip 文件头，在 StegSolve 勾选蓝色通道，Extract by Column 后导出文件  

![](../Images/8978bd4d3364152787df938abe95a069.png)

得到 zip 文件，解压需要密码  

密码为刚刚在 exif 中得到的 `dynamical-geometry`

解压得到一个 stl 文件，以前做过 3D ，所以一眼认出了这是个模型文件

使用 Windows 自带的 3D 查看器即可打开，得到一半的 flag

![](../Images/b6e6acc21e12d187fcfab3c08bc9f175.png)

根据刚刚的提示，另一个压缩包里的文件应该也是 stl 文件  

同样用 3D 查看器打开，得到剩下的一半 flag

![](../Images/bea570b411338f00c964ca23e86a6a49.png)
