***序列化与反序列化***

序列化是将内存中数据转换成为可存储于硬盘中的字符串形式，目的是方便数据的传输和存储；反序列化则相反，将可传输的字符串再变回内存中的对象。

在php中，通过serialize( )和unserialize( )两个函数来实现序列化和反序列化。  
serialize()执行前会先检查对象中是否存在一个魔术方法\_\_sleep()，如果存在，则会先调用\_\_sleep()方法，然后才执行序列化操作。  
unserialize()会检查对象中是否存在一个魔术方法\_\_wakeup()，如果存在，则会先调用\_\_wakeup 方法。  
这里关系到PHP中常用到的魔术方法：

\_\_construct() 构造函数 在对象创建时被调用

\_\_destruct() 析构函数 在对象销毁时被调用

\_\_wakeup() 在反序列化之后被调用

\_\_sleep() 在序列化之前被调用

\_\_toString() 当一个类被当作字符串对待的时候，会触发这个魔术方法

\_\_get() 用于获取不可访问的私有成员属性值

\_\_set() 用于数据写入不可访问的属性  

产生反序列化漏洞的原因就在于这几个魔术方法来看一个简单的例子：

<?phpclass TEST{    public $test = "test";    function \_\_wakeup(){            echo $this->test;

}

***Typecho反序列化漏洞***

Typecho是一个PHP版本的轻量版博客系统，存在反序列化导致前台getshell的漏洞，通过分析这个漏洞来深入理解PHP反序列化漏洞漏洞的位置发生在install.php

<?php  
   $config = unserialize(base64\_decode(Typecho\_Cookie::get('\_\_typecho\_config')));  
   Typecho\_Cookie::delete('\_\_typecho\_config');  
   $db = new Typecho\_Db($config\['adapter'\], $config\['prefix'\]);  
   $db->addServer($config, Typecho\_Db::READ | Typecho\_Db::WRITE);  
   Typecho\_Db::set($db);  
  
?>  

这里将cookie中的\_\_typecho\_config值取出，base64解密后使用不安全的unserialize函数进行反序列化，这就满足了漏洞发生的第一个条件：存在序列化字符串的输入点。那么我们很容易想到：如果在cookie中的\_\_typecho\_config中构造特定的数据是不是就可以执行任意PHP代码，接下来就是去找一下有什么magic方法可以利用。先全局搜索\_\_construct()、\_\_destruct()、\_\_wakeup()

***CVE-2016-7124 wakeup()绕过漏洞***

原理：反序列化时，如果表示对象属性个数的值大于真实的属性个数时就会跳过\_\_wakeup()的执行我们来看一下序列化后字符串表示的含义

![](../Images/bd280769e4ae1b7ae6000053d8c077ee.png)

<?php  
 class A{    public $target = "test";    function \_\_wakeup(){        $this->target = "wakeup!";  
   }    function \_\_destruct(){  
       $fp = fopen("C:\\phpStudy\\PHPTutorial\\WWW\\haha.php","w");  
       fputs($fp,$this->target);  
       fclose($fp);  
   }  
 }  
 $a = $\_GET\['test'\];  
 $b = unserialize($a);  include(".\\haha.php");?>  

当传入O:1:"A":1:{s:6:"target";s:18:"<?php phpinfo();?>";}，\_\_wakeup()在反序列化时调用，比\_\_destruct()先执行，$target赋值覆盖，所以生成的haha.php里面的内容为test wakeup

![](../Images/e24a8b984b2ebf112f9be37c67cc5c2c.png)

如果我们修改对象个数原来是1我们将其改为2，也就是O:1:"A":2:{s:6:"target";s:18:"<?php phpinfo();?>";}

![](../Images/a39734d11dcfeaab138f927f1d09401b.png)

当传入O:1:"A":1:{s:6:"target";s:18:"";}，对象属性个数的值大于真实的属性个数时就会跳过\_\_wakeup()的执行，成功写入我们构造的内容
