**信息收集**

使用nmap进行深度扫描,发现开放了21和22端口，以及80端口，80端口为wordpress应用，存在wordpress登陆api

```





































































































































Nmap scan report for 10.0.3.4
```

第一个flag  
直接审查网页就能看到

```


curl http://10.0.3.4
```

通过之前扫描出来的robots.txt查看目录  
有两个目录,php目录是403,temporary是304页面的内容是

```

Disallow: /php/
```

通过使用gobuster进行目录枚举，发现出多出来一个weblog目录，访问之后提示this site can't be reached,

```




























./gobuster dir -e -t 50 -u http://10.0.3.4 -w /usr/share/dirb/wordlists/big.txt
```

仔细查看页面后发现被重定向到了一个域名， derpnstink.local尝试添加host访问，发现访问成功，该页面应用为wordpress。

![](../Images/d2912a9e9d160637c292a3eb25b7a59c.png)

使用wpscan进行扫描，之前用nmap扫描的操作扫描出了wordpress的登陆接口，/weblog/wp-login.php，尝试访问http://derpnstink.local/weblog/wp-login.php

![](../Images/ffb5dcae6209906b4ef881d9cd11b1de.png)

尝试使用默认用户名密码admin:admin登录登录成功

![](../Images/ee253e03c393724ac52247469254dfc1.png)

发现这个账号不是管理员账号，尝试使用wpscan进行扫描

![](../Images/43806521023ded045beec9178755022d.png)

```












































































































































































wpscan --enumerate vp --url http://derpnstink.local/ --api-token pvIcEc4yERlNYxFTmVOPgEoijTEa1r8s2gf2K9LxjmU
```

可以看到slideshow-gallery这个插件存在漏洞尝试进行利用,Matching Modules

```






Matching Modules
```

设置参数后尝试利用

```









msf6 exploit(unix/webapp/wp_slideshowgallery_upload) > run
```

尝试读取配置文件wp-config.php,发现Mysql连接密码

![](../Images/1f684210060e0ff1ac2e93a56be0bec5.png)

尝试连接数据库  
访问http://derpnstink.local/php/phpmyadmin  
wp-posts表中存在flag2

![](../Images/32696547e7e1182546bfdbaaa7565ec7.png)

翻找数据库的user表发现了用户unclestinky以及密码

```
$P$BW6NTkFvboVVCHU2R9qmNai1WfHSC41
```

使用john工具进行密码爆破

```

john hash.txt --wordlist=/usr/share/wordlists/rockyou.txt
```

尝试使用unclestinky:wedgie57进行登录，也是flag2

![](../Images/11ba8ef3142ae11934638ec7592afd09.png)

查看本机用户，发现了两个用户

![](../Images/addbe0fd0131c439144795b743ef1bd5.png)

尝试使用之前的密码登录这两个账号，发现stinky登录成功，找到flag3

![](../Images/cb530aa7068cac9f67567a912879e2f0.png)

尝试ftp登录，发现了私钥文件

![](../Images/9eb1297af2077aeae7f4fecc8fd1b83a.png)

把私钥文件移动到kali上通过命令连接,一定要加上-o选项添加上加密类型因为ssh8.8开始ssh-rsa加密类型就不再支持了。

![](../Images/8392796a138f955dc4473da5f2a48ff5.png)

ssh -o PubkeyAcceptedKeyTypes=ssh-rsa -i id\_rsa stinky@xxxxx

讲pacp文件移动到ftp目录下

```
stinky@DeRPnStiNK:~/Documents$ mv derpissues.pcap ~/ftp/files/
```

然后使用ftp把文件传到本地

![](../Images/0e45cb15edb362429f733f8174a0d73f.png)

分析pcap文件，寻找http请求包，找到wp-login登录请求,735长度的报文数据存在账号密码

![](../Images/be3e341f8fd0cb9abbf7ff22d92f7328.png)

```

Form item: "log" = "mrderp"
```

尝试登录，然后使用sudo -l查看当前用户的sudo权限,发现可以使用/binaries/derpy文件执行sudo权限

```






mrderp@DeRPnStiNK:~$ sudo -l
```

创建sh文件并且尝试执行,在root目录下的desktop下发现flag4文件

```












mrderp@DeRPnStiNK:~/binaries$ vi derpy.sh
```
