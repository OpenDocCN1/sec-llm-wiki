# 攻击者仍然需要获得对系统的访问权限并升级到root权限才能运⾏keychaindump。这种⽅法有其⾃身的条件。如前所述，登录后，您的钥匙串默认解锁，并在您使⽤系统时保持解锁状态。这是为了⽅便，这样⽤户就不需要在每次应⽤程序希望访问钥匙串时都输⼊密码。如果⽤户更改了此设置并选择在每次使⽤后锁定钥匙串，则钥匙串转储将不再起作⽤；它依赖于解锁的钥匙串来运⾏。  

# 了解Keychaindump如何从内存中提取密码很重要。此交易中最重要的过程是“安全”过程。Apple将此进程称为授权和加密操作的安全上下⽂守护进程。Apple开发⼈员库对此并没有多说；但是，他们确实告诉我们securityd处理对钥匙串的访问。在他的研究中，Juuso将解密钥匙串所需的密钥称为“万能钥匙”。需要采取许多步骤来获取此密钥，因为它是从⽤户的OSX登录密码派⽣的。如果你想读取钥匙串⽂件，你必须有这个主密钥。可以执⾏以下步骤来获取它。执⾏securityd的堆扫描（keychaindump使⽤vmmap命令执⾏此操作）。可能的主密钥存储在标记为MALLOC\_TINY的区域中。您可以使⽤以下命令⾃⼰查看这些堆的位置：

*   

```
`sudo vmmap <securityd PID> | grep MALLOC_TINY`
```

# 然后Keychaindump将在返回的堆中搜索0x0000000000000018的出现。如果以下8字节值指向当前堆，我们就找到了⼀个潜在的主密钥。从这⾥开始，仍然需要进⾏⼀些反混淆，这可以在源代码中看到，但作为分析师，需要注意的最重要部分是解密此信息的必要数据存储在securityd的进程内存中。这是钥匙串转储输出的示例。

*   

```
`sudo ./keychaindump`
```
