0x01 NoXss介绍

NoXss是一个跨站点脚本漏洞扫描器，支持反射XSS和基于DOM的XSS。它非常快，适合测试数百万个网址。它在BugBounty程序中发现了一些XSS漏洞。

0x02 NoXss特点

  • 快速且适合测试数百万个网址

  • 支持基于Dom的xss（使用 Chrome 或 Phantomjs）和反射xss

  • 现在只使用基于注入位置的8个Payloads（非模糊更准确更快）

  • 异步请求（使用 gevent）和多处理

  • 支持来自Burpsuite 的单个url、文件和流量

  • 基于接口的流量过滤

  • 支持特殊标头(referer,cookie,customized token,eg）

  • 支持通过id快速重新扫描

0x03 NoXss安装

环境

Linux Python2.7 

浏览器：Phantomjs 或 Chrome

安装

  • Ubuntu

apt-get install flex bison phantomjspip install -r requirements.txt

  • Centos

yum install flex bison phantomjspip install -r requirements.txt

  • MacOS

brew install grep findutils flex phantomjspip install -r requirements.txt

如果要扫描使用“--browser=chrome”，则必须手动安装chrome。 您可以使用“--check”来测试安装。

 python start.py --check

0x04 NoXss使用

python start.py --url url --savepython start.py --url url --cookie cookie --browser chrome --save  python start.py --url url --cookie cookie --browser chrome-headless --save  python start.py --file ./url.txt --save  python start.py --burp ./test.xml --save  python start.py --file file --filter

  • 选项‍

--url    //从url扫描--id    //重新扫描由任务ID*.traffic文件--file    //从文本文件中扫描url（如./url.txt）--burp    //扫描 *.xml(base64 编码，如 ./test.xml) 来自 burpsuite 代理--process    //进程数--coroutine    //协程数--cookie    //使用cookie--filter    //过滤器网址--browser    //使用浏览器（chrome、chrome-headless 或 phantomjs）进行扫描，基于 DOM 的 xss 很好，但速度很慢--save    //将结果保存到./result/id.json--clear    //扫描后删除流量文件

  • 如何从 Burpsuite 扫描数据

在 Proxy 中，"Save items" ==> "test.xml" 然后就可以扫描 test.xml 了：

python start.py --burp=./test.xml

  • 如何重新扫描

首先扫描后，./traffic/中会有taskid.traffic和taskid.reflect：

    • taskid.traffic：请求的网络流量（pickled）

    • taskid.reflect：反射结果（pickled），包括反射参数、反射位置、类型等。
      NoXss 将使用这些中间文件重新扫描：

python start.py --id taskid --save

0x05 NoXss是如何工作的？

  • 有效载荷

NoXss 仅使用 8 个有效载荷进行扫描。这些有效载荷基于参数的反射位置。有效载荷更少使其比模糊测试更快。

  • 异步&多进程

NoXss 使用协程是高度并发的。

  • 支持基于dom的xss

越来越多的页面使用 dom 来呈现 html。NoXss 可以使用 Phantomjs（默认）或 chrome 来解析它。

  • 分析文件

有些xss很难扫描。NoXss会在流量/中保存一些文件用于分析，包括：

    • *.traffic（扫描时的流量文件）

    • *.reflect(param 的反射结果)

    • *.redirect(30x 响应)

    • *.error（发生了一些错误，如超时、连接重置等）

    • *.multipart(当请求是multipart-formed时，不容易扫描)
