**隐写类****EXIF信息**查看文件属性/EXIF信息查看器/二进制编辑器  
  
**LSB隐写（最低有效位隐写）**图片是由一个个像素构成的，而每个像素的颜色由RGB(A)三(四)个参数决定（A为透明度，部分图片格式才支持，例如PNG、GIF）。RGBA的范围为0\-255，转换为二进制也就是00000000-11111111**隐写原理**：当改变R、G、B的最后一位时，图片颜色产生的变化肉眼基本无法察觉，所以最后一位可以用来隐藏数据，如果是RGB图片，那么每个像素可以隐藏3位的信息，8个像素就可以隐藏3个字节的信息。

![](../Images/7881da0bb8e835cd374323d8922d980f.png)

**注意**：该隐写对jpg格式的图片无效，jpg是有损压缩，会丢失数据  
**解题工具**：Stegsolve、zsteg等**解题方法**：需要熟练使用Stegsolve、zsteg工具，在实际题目中，可能会出现**各种变形**，例如每个像素的信息不按RGB排列，而是RBG/BGR/BRG/GBR/GRB，解题时都要一一查看。解题时，各种方法都尝试一下小技巧：之前做题遇到过的一个问题，记不太清了，8位BMP的隐写用Stegsolve解不出来，用画图打开，另存为png即可（修改了位深度）

```
import binasciiimport structimport sys
file = input("图片地址：")fr = open(file, 'rb').read()data = bytearray(fr[0x0c:0x1d])print(binascii.b2a_hex(fr[0x1d:0x21]))crc32key = eval('0x' + str(binascii.b2a_hex(fr[0x1d:0x21]))[2:-1])
n = 4096 # 考虑到图片大小，一般情况下4096就够用了for w in range(n):    width = bytearray(struct.pack('>i', w))    for h in range(n):        height = bytearray(struct.pack('>i', h))        for x in range(4):            data[x + 4] = width[x]            data[x + 8] = height[x]        crc32result = binascii.crc32(data) & 0xffffffff        if crc32result == crc32key:            print(width, height)            newpic = bytearray(fr)            for x in range(4):                newpic[x + 16] = width[x]                newpic[x + 20] = height[x]            fw = open(file + '.png', 'wb')            fw.write(newpic)            fw.close            sys.exit()

```

**Jphide隐写**

Jphide是基于最低有效位LSB的JPEG格式图像隐写算法，使用JPEG图像作为载体是因为相比其他图像格式更不容易发现隐藏信息，因为JPEG图像在DCT变换域上进行隐藏比空间域隐藏更难检测，并且鲁棒性更强，同时Blowfish算法有较强的抗统计检测能力。

**解题工具**：

（1）Stegdetect它可以检测到通过**JSteg、JPHide、OutGuess、Invisible Secrets、F5、appendX**和**Camouflage**等这些隐写工具隐藏的信息，并且还具有基于字典暴力破解密码方法提取通过Jphide、outguess和jsteg-shell方式嵌入的隐藏信息。（2）JPHS软件里面主要包含了两个程序JPHIDE和JPSEEK， JPHIDE程序主要是实现将信息文件加密隐藏到JPEG图像功能，而JPSEEK程序主要实现从用JPHIDE程序加密隐藏得到的JPEG图像探测提取信息文件，Windows版本的JPHS里的JPHSWIN程序具有图形化操作界面且具备JPHIDE和JPSEEK的功能。

**明文攻击**  

明文攻击一种攻击模式，指攻击者已知明文、密文及算法，求密钥的过程。

什么时候可以用明文攻击呢，举个例子：一个加密的压缩包，里面有很多文件，都是加密的，但是其中一个文件是已知的（可以通过比较文件的CRC32来判断加密的文件和已知的是不是一样的），这时就可以用明文攻击。

**解题工具**：ARCHPR 4.5.4、AZPR 4.0（为什么还有低版本的呢，因为遇到过一个明文攻击，用4.5.4版本的解不出来，4.0的可以解出来，原因未知，所以两个版本都备着吧hhh）

**ZIP伪加密**

一个zip文件由三部分组成:压缩源文件数据区+压缩源文件目录区+压缩源文件目录结束。

以下资料来源：

https://blog.csdn.net/qq\_26187985/article/details/83654197

**实例：**

![](../Images/3f5595bab020877ab34106c2f2bf8b97.png)

**压缩源文件数据区**： 

50 4B 03 04：这是头文件标记（0x04034b50）14 00：解压文件所需 pkware 版本 00 00：全局方式位标记（有无加密） 头文件标记后2bytes08 00：压缩方式......  
  
  

**压缩源文件目录区**： 

50 4B 01 02：目录中文件文件头标记(0x02014b50) 3F 00：压缩使用的 pkware 版本14 00：解压文件所需 pkware 版本 00 00：全局方式位标记（有无加密，伪加密的关键） 目录文件标记后4bytes08 00：压缩方式 ......  

  

全局方式位标记的四个数字中只有第二个数字对其有影响，其它的不管为何值，都不影响它的加密属性！ 第二个数字为奇数时 –>加密 第二个数字为偶数时 –>未加密

**无加密**

压缩源文件数据区的全局加密应当为00 00（504B0304两个bytes之后）且压缩源文件目录区的全局方式位标记应当为00 00（504B0304四个bytes之后）

**假加密**

压缩源文件数据区的全局加密应当为00 00 且压缩源文件目录区的全局方式位标记应当为09 00

**真加密**

压缩源文件数据区的全局加密应当为09 00且压缩源文件目录区的全局方式位标记应当为09 00
