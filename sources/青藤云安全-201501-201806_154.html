一、网络分割和隔离

Network Segmentation

1、定义

网络分割是企业深度防御中的一项关键战略，在网络安全领域是把计算机网络分为子网络，每个子网络都是一个独立网段。该技术能分割、保护关键的企业数据，限制攻击者在企业网络内部的横向运动。在缩小PCI-DSS等规范审计范围方面也十分有效。


2、必要性

由于企业网是内部相联的，内部网络安全再也不是铁桶一块。一旦攻击者在企业系统中有了立足之地，他们通常就能通过东西流量（横向平移）畅通无阻地入侵其他系统，企业疲于应对。要解决这个问题，就要更加细粒度地控制各个网络间流动的数据，通过网络分割和隔离阻止攻击者的横向平移。内部网络分割虽然并非新观点，但现在终于能得到人们的重视。


3、网络分割的关键要求


1、流量、用户、资产可视化；
如果企业看不到某段网络进出站通讯的流量情况，那访问控制就会成为一句空谈。企业必须清楚想划分的这段网络具体的使用情况。
2、保护出入站通信和资源；
如果不能真正保护某个网段的资源，安全这个首要目标就会落空。简单控制网段间的访问流量还不足够，企业还要具备快速修复威胁的能力。
3、对流量、用户和资产实施细粒度的控制；
企业必须控制所有进出网段的数据，在前两步措施的基础上，企业应该能认识到保护进出网段通信安全的重要性。接下来就要实施细粒度访问控制的通信策略。在了解外部访问网段的通信流量后（步骤1），通过两步实施控制措施：检测控制、预防控制。
4、对所有内部链接设置默认拒绝访问策略；
现在企业已经对流量、用户、资产实现可视化，保护了通信流量，也了解了所有进出网段的数据流量。接下来就要对所有内部链接设置默认拒绝的访问策略，只有这样网段才能真正地从网络中分割出来，作为独立的逻辑单元运行。


Gartner在报告中提出企业要分割网络控制成本、避免厂商一家独大。虽然没有行规清楚说明分割模块的边界，但一般企业会根据功能分割网络：如数据中心、WLAN、应用加速、防火墙、局域网核心、局域网存储等。



二、企业移动管理

Enterprise Mobility Management

1、定义

通过移动信息化管理手段，针对企业移动信息化建设过程中涉及到的企业移动设备、应用、信息等提供管理方案与服务。除此之外，强大的EMM战略还能提供员工移动办公所需的工具来提高工作效率。


2、必要性

Gartner预测企业员工在日常工作中平均使用8-15个移动应用。之前的移动战略只有基础、横向的生产力工具——如邮件、联系人和日历标记，但有关职位特色、关键任务所需的应用程序正在逐渐入驻更多的移动设备。


因此企业需要应用级别的控制方案，交付、使用更多的内容类型。EMM能够让企业确定移动IT是否融合到工作流程中、是否匹配员工的工作目标，并且就如何提高员工在工作场所中使用移动设备的工作效率提出指导策略。


3、核心功能


1、MDM 移动设备管理
包括设备级管理功能和分析，从设备的注册、激活、访问控制、策略配置一直到设备被淘汰的整个过程都可以实现多层次、全方位的管控。MDM现在成为EMM功能组件中的关键部分。
2、MAM 移动应用管理
MAM加快了移动应用程序运行周期的部署和管理。它是MDM向移动应用的延伸，帮助企业将IT策略从设备级延伸到应用级，如邮件安全、日历安全、文件管理软件集成等。MAM还包括认证、标记app为“受管理的”企业应用的功能，为这些app采用管理和安全策略。
3、MCM 移动内容管理
提供对企业文档进行分发、权限设定、安全策略相关的管理。
4、MS 移动安全功能
黑客对移动安全主要有三个攻击目标：数据、身份、可用性。因此企业要加强身份认证，如加密、认证、单点登录等。
 5、MEM 移动邮件管理
安全邮件具有安全邮件网关服务器、安全邮件客户端两个模块。前者与企业邮件系统对接，避免企业的邮件服务器直接暴露于公网，消除信息泄漏的隐患。后者与前者之间采用SSL加密通道访问方式，并对传输的邮件数据内容进行高强度AES的加密。
6、MI&Access 移动互联网和访问
用户现在手里的设备绝不止一台，他们会频繁地使用智能手机、平板和电脑。所以连网并不重要，重要的是连网设备是否有企业授权。MI一般使用数字化认证，但也有其他的认证技术如生物认证和令牌认证。
7、Containment 控制
在这里，"Containment"代表着一整套能加快分离企业和个人数据的能力，包括用户个人信息管理、预先配置公共应用、独立软件开发商提供的移动应用和应用程序扩展。



Gartner认为有些EMM厂商已经开始融合IAM工具，比如开发具备了单点登录等IAM功能。反过来也是如此，一些IDaaS（身份验证即服务）厂商也开始提供基础的EMM功能。


三、云访问安全代理
Cloud Access Security Broker

1、定义

云访问安全代理（Cloud Access Security Broker，CASB）是一种软件工具或服务，存在于企业本地基础架构和云提供商的基础架构中。它可以执行云安全的最佳实践，实施企业的安全策略。CASB能够发现不同云平台上云应用的使用情况，锁定非授权使用行为；并且自动发现风险较高的应用、用户和其他关键风险因子。


2、必要性

（1）企业上云率达到51%，需要减少云应用使用风险。云DLP服务、加密、用户培训、隔离或Legal hold等工作负载是CASB的核心能力。 

（2）保证云上合规性。无论客户属于哪种行业，CASB都能满足企业上云合规要求。 

（3）可视化地管控云支出。

（4）获悉云应用程序使用风险。

（5） 保护云上恶意软件和威胁。CASB可保护用户避免众多恶意软件攻击或免受内部威胁。

（6）虽然企业应用和网络基础架构已经由SaaS厂商保护，但保护这些云应用数据、以及访问用户和设备仍然取决于用户。并且企业的业务单元在逐渐甩开IT部门拥抱云服务，却很少考虑云安全。


所以Gartner预测到2020年，95%的云安全事件都是由客户行为不当而非安全厂商能力不足造成的，而CASB正是为了避免这种情况出现。


3、核心功能


1、可视化、细致管理所有应用。
企业对所有合法与非法应用都要具备可视化和访问控制能力，包括用户在访问哪些数据、使用了什么设备。准确找出平台上的风险数据或风险用户行为。
2、精确有效地保护敏感数据，检查访问、共享方法是否得当。精确保护的措施有：让用户自我修复安全问题、管理员干涉、加密文件层的关键资产。
3、保护企业抵御内部威胁和外部恶意软件、避免高级网络攻击。发现暴露的风险数据、保护企业免受账号入侵。
4、以用户为核心，使用API，考虑未来业务的可拓展性。除了简单部署和可轻松扩展的能力，CASB对终端用户不会产生其他影响。深度集成API能够对部署时的云上静态数据进行回溯性监测，并采取措施。
5、合规性。无论是企业内部管控还是政府授权，执行CASB策略时都要满足合规要求。



一般来说，CASBs会部署在企业的数据中心或云上。也就是说企业可以选择将CASB作为一项服务，也可以托管在物理/虚拟应用程序上。但企业要注意：选择一家CASB厂商既要支持目前业务所需，又要考虑到未来的拓展服务。对安全经理来说，这相当具有挑战性。



云计算、IT商业化、移动化、应用的爆发性增长驱使我们必须使用新兴技术。这些趋势和创新让商业竞争变得更加复杂，同时也提高了我们的生产力，创造了更多国际化的市场机遇。


Gartner分析称在异构环境中持续实施网络分割战略可以有效限制黑客在内网的横向运动、阻止其访问财务和商业资产、减少常规审计规模。

随着BYOD趋势愈演愈烈，企业必须同时处理多个移动设备和多个运行系统，因此要寻找管理移动安全方方面面的解决方案，保护软件、设备、数据和应用。

Gartner预测到2020年，85%的大型企业都会在云服务中使用CASB，减少云应用的使用风险。如果企业有shadow IT，或者安全策略比较散漫，允许业务单元自己获取、管理云资源，CASB就显得尤其重要了。
