# 9步助你完成安全事件响应计划

**摘要：对安全事件来说，未雨绸缪很重要。**

事件响应（Incident Response）规划中，细节很重要。但就算是最成功的IR计划也可能会欠缺某些关键信息，阻碍业务运营快速恢复至正常状态。下面是IR规划者经常忽视但十分重要的9个步骤。

★1、各部门都应做好准备合格的安全领导应该让企业全部人员都参与到IR计划中。CISO可能管理处理威胁的安全团队，但处理泄漏事件的负面影响却需要全体工作人员的参与。

例如，银行处理泄漏事件的影响时，如果需要依法对外公布事件始末，这需要公关部门大力协作。如果黑客对银行的网站展开漏洞利用攻击（如WordPress漏洞），那银行的web开发团队就需要参与IR流程。如果个人数据被泄露，可能需要协同人力部门开展IR工作。当检测到泄露事件时，只有快速通知所有关键人员才能制定出完整的IR计划。

  
2、确认评估方法

一个成功的IR规划会提前规定安全小组处理事件的关键绩效指标（KPIs）。随时间开展进行评估的手段一般有：检测、报告、分类、调查、响应。

从定性方面来说，我们还可以参考误报量、攻击本质（恶意vs非恶意）、检测事件的工具等。

  
3、测试企业要提前考虑各类可能发生的泄露事件。这些事件可以通过团队培训、桌面演习、红蓝军对抗赛等方式提前演练。企业甚至可以模仿泄漏事件，让员工明白当真正的安全事件出现时各自的角色和任务。企业要在准备阶段摸清自己的弱点和风险因素，搞清楚需要密切监测的活动、把安全预算花在刀刃上。每年都要调整IR计划，如果企业发展很快，IR计划要调整地更加频繁。另外，IR计划要合规。  
4、小心看似无碍的警告

一开始威胁监测可能没有问题，跟安全也无关。当IT调查运行缓慢的电脑时，可能会发现设备已经感染恶意病毒，比如钓鱼攻击。那就要在内部检测是否有人点击了可疑链接。

IT专家在调查技术问题时要检查入侵迹象，也要培训用户，在收到含可疑链接的邮件时联系安全人员。另外，IT和安全团队不应忽视用户的怀疑，有时人的第六感真的会检测出泄漏事件。

  
5、创建统一数据库无论企业用什么方法检测威胁，都必须把安全事件整合到一个中心存储库中。一般企业会采用SIEMs，但有时企业无法通过SIEM认识IT整体环境。IR团队有时只能回溯IT环境中的运行情况，但事后诸葛亮的做法很难创建出完整的视角。

创建、维护一个支持持续、广泛可视化的数据库不仅仅是为了满足合规要求，也是为了加快调查和响应速度。

  
6、不要忽视工控系统许多企业设备都在运行工业系统，如炼油厂、制药企业等。但是很多企业可能想不到黑客也会攻击自己，因此并没有密切监测恶意行为。换句话说，除了IT或安全部门之外还应有一个部门在管理工控系统基础设施，如果这些人员缺乏必要的系统监测技术和知识，就会导致安全事件的发生。  
7、控制和补救措施

企业有必要建立一个能够阻止入侵活动的完整控制和补救机制。该机制必须基于安全团队对事件的调查结果基础上，但有时IR计划只依赖于初期检测一星半点的信息。

例如，如果SIEM检测到连接C2服务器的恶意行为，典型的解决方案就是杀进程，封锁防火墙中的IP地址。但如果是持续性的恶意软件，可能电脑重启后会换个进程名称重新载入，去连接其他的服务器。安全小组就陷入了一个检测、控制、消除威胁的死循环。但是如果安全小组能够调查恶意软件的技术和感染媒介，就会开发出一个更好的消除威胁的方案，最后形成一个防御计划。

  
8、计划后期资源要想阻止安全事件再次发生，关键要采取后期行动，但是，由于后续计划可能需要安全预算（如多雇佣几个安全分析师或购买技术，来检测攻击行为），大部分企业都是拒绝的。支出较少的行动一般会给SIEM系统增加新的检测规则。企业可以通过考核KPIs以决定是否要调整后期计划，例如，安全团队可以判断误报率较高的检测规则阻碍了其快速响应安全事件的能力，那就改善检测规则或升级为全新的检测系统。或者在用户报告的安全事件基础上，增加相应的检测规则。  
9、总动员企业要准备好充足的时间和精力来应对数据泄露事件，与阶段1相似，事件响应也不应该只是IT和安全部门的事，而是要全体部门通力合作。只有这样才能更好应对未来的安全事件。
