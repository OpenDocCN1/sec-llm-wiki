虽然写 C 的时候都意识到结构体的传参和指针有所不同，但是改成 js 的时候就很容易迷糊。官方文档写的很清楚：

  

> **STRUCTS & CLASSES BY VALUE**  
>   
> As for structs or classes passed by value, instead of a string provide an array containing the struct’s field types following each other. You may nest these as deep as desired for representing structs inside structs. Note that the returned object is also a NativePointer, and can thus be passed to Interceptor#attach.  
>   
> This must match the struct/class exactly, so if you have a struct with three ints, you must pass \['int', 'int', 'int'\].

  

在 NativeFunction 里使用结构体时，声明参数的类型可以用一个数组表示，里面按顺序列出每个字段的类型。假如一个 stcuct 是三个 int，就可以在 js 里写成 `['int', 'int', 'int']`，支持嵌套声明类型。

  

回到 Cocoa 编程里常见的 CGRect，内部分别是一个 CGPoint 和一个 CGSize 结构，每个结构分别又包含了两个 CGFloat。一共是四个 CGFloat，原点和大小，即一个矩形。

  

以下是在 frida 里调用参数为 CGRect 的实例：

  

*   
*   
*   
*   
*   
*   
*   
*

```
const CGFloat = Process.pointerSize === 8 ? 'double' : 'float';const CGSize = CGPoint = [CGFloat, CGFloat];const CGRect = [CGPoint, CGSize];const strFromRect = new NativeFunction(  Module.findExportByName('Foundation', 'NSStringFromRect'), 'pointer', [CGRect]);const stu = [[10, 10], [640, 480]]; // 初始化
console.log(new ObjC.Object(strFromRect(stru)));// {{10, 10}, {640, 480}}
```

  

无需考虑 Memory.alloc 的大小，也不需要关心编码浮点数到 IEEE754，直接写字面量即可，更不用说具体 ABI 的调用约定了。  

  

虽然以上代码以 Cocoa 的 CGRect 为例，适用于所有 frida 支持的平台的结构体。
