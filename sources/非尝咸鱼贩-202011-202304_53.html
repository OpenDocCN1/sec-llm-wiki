前阵子简单写了几个主流浏览器关闭 JIT 优化的技巧，后台收到留言问怎么关闭沙箱。


Chrome 自然不必说，自带参数可以实现；但是 Safari 并没有提供这样的功能。一般调试的时候也是用没有 sandbox 的 jsc，或者自行编译 WebKit 把沙箱的代码注释掉。


但如果就想要原版的浏览器界面来录小视频，那怎么办？也不是没有办法。


以下提到的一些配置会显著降低系统安全性，请不要在测试环境以外的系统上使用。


思路很简单，使用运行时插桩技术把关键的函数调用屏蔽掉即可。



首先为了魔改系统组件，需要打开上帝模式——关闭 SIP（rootless）保护。


具体步骤不再赘述，有这个需求的读者肯定都知道怎么做。再次强调，请不要在个人电脑上关闭，请仅用于测试环境。


$ csrutil statusSystem Intergrity Protection status: disabled


这个步骤是为了在受保护的应用程序上开启 DYLD_INSERT_LIBRARIES 环境变量。



本文的代码插桩基于 dylib 动态库注入实现。系统默认对 Safari 浏览器各个进程都开启了 Hardened Runtime。如果 dylib 没有官方的数字签名，AMFI 是不会允许加载的。接下来需要关闭 Library Validation。


操作很简单，这个选项由一个 plist 控制：


sudo defaults write /Library/Preferences/com.apple.security.libraryvalidation.plist \    DisableLibraryValidation -bool true


也就是在 /Library/Preferences/com.apple.security.libraryvalidation.plist 这个文件里添加了一个 DisableLibraryValidation 的开关。这个路径需要管理员权限才能修改。amfid 会监听该路径的实时修改，无需注销或重启，马上生效。



准备工作差不多了，接下来开始写代码。


mac 端 Safari 开启沙箱的业务逻辑在 WebKit 的 compileAndApplySandboxSlowCase 函数：


https://github.com/WebKit/WebKit/blob/6520dda9ff25c82a87523c04e7d75ec564dd98eb/Source/WebKit/Shared/mac/AuxiliaryProcessMac.mm#L566


    ALLOW_DEPRECATED_DECLARATIONS_BEGIN    if (sandbox_init_with_parameters(temp.data(), flags, parameters.namedParameterArray(), &errorBuf)) {        ALLOW_DEPRECATED_DECLARATIONS_END        WTFLogAlways("%s: Could not initialize sandbox profile [%s], error '%s'\n", getprogname(), temp.data(), errorBuf);        for (size_t i = 0, count = parameters.count(); i != count; ++i)            WTFLogAlways("%s=%s\n", parameters.name(i), parameters.value(i));        return false;    }


与 iOS 端的浏览器沙箱不同，桌面端渲染器、网络等进程启动时是没有沙箱的，初始化后才会主动调用库函数 sandbox_init_with_parameters。


我们的目的是把这个函数调用跳过。


这里有一个细节问题。WebContent 进程是 Safari 的一个 XPC 服务，我们不能直接用命令行运行，因此不能直接 DYLD_INSERT_LIBRARIES。


mac 针对 XPC 进程的参数传递提供了另一种鲜为人知的方式，就是 __XPC_ 前缀的环境变量。例如给应用程序的主进程传入 __XPC_FOO=bar，该应用程序运行的 XPC 服务就会获得一个 FOO=bar 的环境变量。


所以可以这样启动 Safari：


open -a Safari --env __XPC_DYLD_INSERT_LIBRARIES=/path/to/dylib


之后派生出来的 xpc 服务，包括渲染器、网络等进程都会尝试去加载对应的 dylib。


这个调试功能只有在关闭 SIP 的情况才有效。


开始写代码 hook。



编写 dylib 需要注意计算机的 CPU 架构。M1 系列的是 arm64e，而编译器默认会生成 arm64 的代码。虽然指令集向下兼容，但注入库的时候会报错。记得在编译参数里加入


-target=arm64-apple-darwin -arch=arm64e


Intel 的系统则无需特殊处理，默认就是 x86_64 的。


在 mac 的链接器 dyld 中自带一个插桩功能 DYLD_INTERPOSE


https://opensource.apple.com/source/dyld/dyld-210.2.3/include/mach-o/dyld-interposing.h


/* *  Example: * *  static *  int *  my_open(const char* path, int flags, mode_t mode) *  { *    int value; *    // do stuff before open (including changing the arguments) *    value = open(path, flags, mode); *    // do stuff after open (including changing the return value(s)) *    return value; *  } *  DYLD_INTERPOSE(my_open, open) */
#define DYLD_INTERPOSE(_replacement,_replacee) \   __attribute__((used)) static struct{ const void* replacement; const void* replacee; } _interpose_##_replacee \            __attribute__ ((section ("__DATA,__interpose"))) = { (const void*)(unsigned long)&_replacement, (const void*)(unsigned long)&_replacee };


使用这个宏之后，生成的 MachO 二进制文件会有一个 __DATA,__interpose 的 section。链接器识别到之后将把对应函数名重新绑定到我们提供的函数地址上。iOS 开发者熟悉的 fishhook 库的灵感应该就是从这来的。在这里并不推荐 fishhook，写起来麻烦，而且亲测不支持 M1（没有处理 PAC）。


代码就这么点：


#import <Foundation/Foundation.h>#include <dlfcn.h>
#define DYLD_INTERPOSE(_replacement, _replacee)                                \  __attribute__((used)) static struct {                                        \    const void *replacement;                                                   \    const void *replacee;                                                      \  } _interpose_##_replacee __attribute__((section("__DATA,__interpose"))) = {  \      (const void *)(unsigned long)&_replacement,                              \      (const void *)(unsigned long)&_replacee};
int sandbox_init_with_parameters(const char *profile, uint64_t flags,                                 const char *const parameters[],                                 char **errorbuf);
ssize_t my_sbinit(const char *profile, uint64_t flags,                                 const char *const parameters[],                                 char **errorbuf) {  NSLog(@"disable sandbox");  *errorbuf = NULL;  return 0;}
DYLD_INTERPOSE(my_sbinit, sandbox_init_with_parameters);
