昨天写了篇"因噎废食"的技巧。因为 v8 的 JIT bug 在野利用占了相当比例，不追求性能的话干脆禁用掉一了百了。Chrome 有官方的 bug bounty 计划，而且市场占有率吊打别家，白帽研究的加上野外利用的，在公开的漏洞数量上给人感觉更多。

  

特别是 blink 内核的套壳浏览器，甚至 Electron，经常出现在各种桌面客户端软件上。在一些红蓝对抗的演练中确实也见到有人在用 Chrome 的洞，还是有必要针对性做加固。  

  

[关掉 Chrome 的即时编译优化](http://mp.weixin.qq.com/s?__biz=Mzk0NDE3MTkzNQ==&mid=2247484059&idx=1&sn=486d793745473d72a32a81860be753fc&chksm=c329fc6bf45e757d31530f02eca6f0aa629faf36996a20a72d7fec66dfb34291614ccea3f2ff&scene=21#wechat_redirect)  

  

一不做二不休，干脆试试把 Safari 和 Firefox 的也关了吧。

  

WebKit 上 JIT 的漏洞占比也不低。不过看上去没有像 Chrome 那样有人一言不合在网上扔 1day 完整代码的情况。即使是 macOS 用户，用 Chrome 的人仍然很多。

  

在近几年针对 Firefox 的利用比较少见，大概是因为需要用 0day 打 firefox 的场景基本上都是冲着 tor 浏览器去的，"市场"很小众。在漏洞类型上 JIT 也没有显得很突出。

调试过 WebKit 的读者肯定都知道，桌面版的 Safari 有一个隐藏的 Debug 目录，可以开启各种高级的调试选项（可不是审查元素）。

  

这个选项通过一个 plist 控制，需要通过命令行启用。但由于新版的 macOS 为了隐私控制加强了 TCC 功能，直接访问 Safari 相关配置会提示权限被拒绝，哪怕是 root。

  

首先打开系统设置里的安全和隐私。选择 Privacy（隐私）设置里的 Full Disk Access（完全磁盘访问权限），把终端应用（系统自带，或者 iTerm2，取决于你用哪一个）添加进去并赋予权限。系统会要求输入 sudo 密码或者验证 Touch ID。如果终端已经打开还会提示退出应用以刷新权限。

哪怕是勾选了禁用 JIT，重启 Safari 之后，使用 vmmap 命令查看相关进程，仍然可以找到一个 rwx 的内存区域。我们来给这个 exploit 界知名的函数 JSC::LinkBuffer::linkCode （用来生成即时编译的机器码）下个断点，然后随便访问一些体量比较重的 js 应用，例如 gmail：

调用栈很诚实地显示，JIT 仍然有效。到这一步应该预料到 iOS 会有同样的结果，不过我还是上去实测了一下，确实没起作用。

  

对这件事，WebKit 这帮人自己就很纠结：

  

![](../Images/daebc2139af05cae2f7ea47b3a11cdec.png)

  

https://bugs.webkit.org/show\_bug.cgi?id=191822

  

我大体看了一下，应该是 Launcher/mac/ProcessLauncherMac.mm 的问题。只有在指派了 ProcessLauncher 的 client 委托类，并实现 isJITEnabled 方法返回 false 的情况下才会动态关闭相关的功能。

  

![](../Images/ede94cb412e974408a0962b5f3011888.png)  

  

至于 iOS，系统并没有提供直接修改 plist 的办法，除非通过特定软件获得一个 root shell（你懂的）。曲线救国的方式是通过 iTunes 备份手机数据，然后提取沙盒内的 plist 文件进行编辑，再将修改过的备份文件恢复到手机当中。这种方式存在数据丢失的风险。再说改了也没用。

  

综合考虑在 iOS 上的漏洞利用成本，可能不大会出现类似 Chrome 1day 利用代码被扔到社交网络上，或者大家红蓝演练互相伤害的情况。  

  

![](../Images/c46fd600371d7cb46e0c08a425fe3f07.png)

  

不如直接上 M1 笔记本或者新款手机，软硬件结合大幅提高利用成本。除非是 VIP，基本不用担心被有能耐过最新防护的高级威胁盯上。

  

* * *

  

结论是 WebKit 虽然号称有一个 preference 可以关 JIT，实际上并没起作用。火狐改起来很方便，不过有没有必要关闭就看读者自己的需求了。另外关闭 JIT 可能会导致某些依赖 WASM 的网页出问题。

  

这种破坏式的防御比较激进了。企业网络管理员如果想针对远程攻击做系统性的防护方案，还是多考虑下 EDR 能力的加强。
