关掉 Chrome 的即时编译优化

即时编译（Just-in-time）是现代浏览器为加快 js 执行速度，直接在内存中生成可执行的汇编指令的一种优化手段。在过去的几年里，无论是在野漏洞利用还是各种破解比赛，JIT 相关的浏览器漏洞都占了较大的比重。


具体可以参考 Google Project Zero 整理的一份列表，包括 CVE 编号、影响引擎（组件）和根本原因分析：


https://googleprojectzero.github.io/0days-in-the-wild/rca.html


安全和效率有时候不能兼得。在目前计算机的性能也不差的前提下，关闭浏览器的 JIT 功能可以减少相当一部分攻击面。


Chrome 背后的 js 引擎 v8 在 2019 年就已经推出了 jitless 模式。在 Windows 和 Linux 桌面系统上，快捷方式都是可以添加命令行开关的。直接给 js 引擎传入一个 jitless 标志，可以关闭即时编译优化：


chrome --js-flags="--jitless"


macOS 系统没有简单的修改图标启动参数的功能。当然随时可以用终端输入命令行，但总归更麻烦。


目前 Chrome 最高版本是 94。在 Chrome 93 上新增了三个配置选项：


  • DefaultJavaScriptJitSetting：是否启用 JIT 的全局开关

  • JavaScriptJitAllowedForSites：针对特定网站开启 JIT，可以覆盖全局开关

  • JavaScriptJitBlockedForSites：针对特定网站关闭 JIT




https://chromeenterprise.google/policies/#DefaultJavaScriptJitSetting


这几个选项对 Edge 同样有效。


https://docs.microsoft.com/en-us/DeployEdge/microsoft-edge-policies#defaultjavascriptjitsetting


以第一个全局开关为例。


在 Windows 下，配置可以修改注册表实现：


Software\Policies\Google\Chrome\DefaultJavaScriptJitSetting


而 macOS 下则通过 preference 控制：


DefaultJavaScriptJitSetting


例如我的 mac 系统上，打开终端，输入


defaults write com.google.chrome DefaultJavaScriptJitSetting -int 2


即为全局禁用 JIT。


地址栏输入chrome://policy 页面确认一下，可以看到策略已经被添加进来了：



如果要删除这项设置，在终端中输入：


defaults delete com.google.chrome DefaultJavaScriptJitSetting


以上实例针对个人电脑。


这项功能本身就是针对企业用户设计，IT 管理员可以直接通过下发配置文件来批量修改设置。也就是我们偶尔会见到的"由贵单位管理"提示。如果企业觉得有必要针对 0day 和 1day 部署额外的防护，这个选项不失为一个可以考虑的策略。
