iOS 15 近日推出了正式版，WWDC 预告过的新 Safari 插件系统也正式上线了。iOS 的 Safari 也支持扩展，而扩展可以在 App Store 上安装。今天在网上看到一个有点香的扩展，在这里写一下体验。


iOS 的 Safari 是有远程调试支持的，通过 USB 或者局域网和电脑连接之后，即可在 macOS 端打开完整的 F12 调试功能。笔者之前还发布过一个工具，可以在越狱的设备上全局开启 iOS / mac 的 WebView 调试。


但没有电脑的情况下，iOS 的 Safari 连查看 html 源文件都不支持。


在 iOS MobileSafari 正式支持扩展之前，shortcut 其实已经引入了向浏览器中注入 js 的能力。笔者之前用 Shortcut 自制了查看源文件、下载网页中视频等功能。




新的 Safari 提供了 WebExtensions API 支持，相比 shortcut，能力增强了不止一点：

https://developer.apple.com/documentation/safariservices/safari_web_extensions


注意到地址栏旁边的扩展按钮了吗？





下面进入自来水。提前说明一下，本公众号和这个插件没有任何关系。


这个名为 Web Inspector 的扩展，目前在 Developer Tools 分类热门的第十一位。




这个扩展顾名思义就是提供了 F12 的一小部分功能，而无需打开电脑。


无需多做介绍，一张图就很清晰了：




查看源文件甚至编辑元素都有了。


首先到 AppStore 下载安装，目前是免费应用


https://apps.apple.com/us/app/web-inspector/id1584825745


在地址栏的扩展图标下启用扩展。第一次使用会询问权限，iOS 可以选择允许一天的访问权限。




需要提醒一下，Safari 插件可以访问网页的完整的 DOM 和执行 js，因此页面上所有的信息插件都是可见的。除了指望 App Store 加强应用审核，杜绝恶意插件，作为用户还是尽量不要在敏感的页面，例如涉及支付、财务和个人隐私等系统上使用。


允许权限访问之后就可以使用了。DOM 树前文已经截图过了，不再赘述。亲测发现选择元素功能有 bug，只能高亮元素而不能选中。

在部分网站上 js 控制台有焦点问题，没办法输入完整代码，会跑到网页自带的文本框去。而且这个 js 控制台似乎用的是 eval，如果目标网站开启了 CSP，就会执行失败。Content Security Policy 现在已经是大网站的标配了。

这个功能和原版的 F12 比也是有硬伤的。因为这个面板只能等网页已经开始加载了，点击地址栏的界面才能打开。如果网络请求在插件界面显示出来之前完成，就不会留下任何记录。只能抓到一些 ajax 请求。


Timing 面板记录了资源加载的时间线，只对性能分析有意义。不过一般需要分析性能的都是 Web 开发者自己，不如直接上电脑啦。


最后一个特别有用的面板 Resources 显示了 Local Storage，Cookies 和 Session Storage。此外还把所有的框架、图片、css 和 js 的地址列出来。




一个典型的应用场景就是，instagram 的图片在网页端和 app 上都限制图片保存。当然你仍然可以截图。而在 Resource 面板里，所有图片都会被列出来，直接长按就能保存。
