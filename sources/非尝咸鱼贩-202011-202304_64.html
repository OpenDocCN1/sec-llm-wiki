九月了，之后一些技术可能就不太方便讲了。不如讲讲防御吧。


之前文章 CVE-2021-1748：从客户端 XSS 到弹计算器 介绍了一个 app 层面的远程代码执行。前几天外网上出现了视频，有安全研究员手动复现了文中介绍的问题和技巧，实现了远程代码执行；再加上之前野外被利用的内核漏洞 CVE-2021-1782，实现了 PAC 设备的远程 jailbreakme。


于是有网友询问，如果为了"安全研究"保留低版本设备，能不能通过 tweak 插件的方式修复已知的问题防止被攻击？


针对具体的案例，这个 CVE-2021-1782 可以写插件过滤。


本文不对 tweak 的开发过多赘述，基础知识请参考其他资料或者 iosre 论坛：https://github.com/iosre/iOSAppReverseEngineering；如果没有听说过 tweak 开发，其实到这里可以关掉本文了……



CVE-2021-1782 是 14.4 上修复的，把第一步入口的 XSS 干掉了；后面的各种类型混淆之类留在下一版 14.5 修复，反正没法触发。


这个客户端的 XSS 的根本原因在于把传入的 data URI 当作可信的来源，伪代码大体如下：


- (BOOL)urlIsTrusted:(NSURL*)url{  if ([url.scheme isEqualToString:@"data"]) return YES;  NSString *host = url.host;  NSArray *trusted = [self valueForKey:@"trustedDomains"];  //...


之前的问题有两种 PoC：


itmss:///www.apple.com <- 需要可信域名，例如 apple.com 上的 XSS

itms://[马赛克]?url=data:... <-特定参数下传入 data 即可反射 XSS


第一种不做修复，因为本质上还是服务端的安全漏洞，在客户端加一个 WAF 没有意义；而第二种情况，也就是这个 CVE，只需要针对 data URI 做拒绝访问处理即可。


有人首先会考虑从 MobileSafari 入手，先把 itms 开头的 URL 禁止掉。然而 itms 开头的 URL 有很多，包括一些音乐、播客和 app 安装相关的功能都有依赖，一刀切误伤太大，将导致系统功能缺失。再者 Safari 也不是这个漏洞唯一的入口点，还有 AirDrop。


之前的文章里已经提到，无论哪种方式都会调用到 -[SKUIURL initWithURL:] 方法，在上面加 hook 针对性处理即可。以上两种情况都能拦截到。


改动最小的的方案当然是直接针对 root cause 做修复：


%hook ISURLBag
- (BOOL)urlIsTrusted:(NSURL*)url {  if (![url respondsToSelector:@selector(scheme)]) {    return NO; // 这个检查是防止出现意料之外的类型  }
  if ([url.scheme.lowercaseString isEqualToString:@"data"]) {    return NO; // 尝试在客户端使用 data URI，拒绝  }
  return %orig;}
%end


而根据网上公开的头文件转储，这个方法至少在 iOS 9 就有了，兼容性有保障。


接下来要有选择地编写过滤器，避免补丁被不必要的进程加载影响性能。


THEOS 生成的工程模版里有一个 plist 文件用来过滤插件加载的场景。


{ Filter = { Bundles = ( "com.apple.iTunesStoreUI" ); }; }


如何确定 Bundles 的值？


以上补丁针对的是 ISURLBag 这个类，可以通过两种方法确定其所在的 bundle。


静态在 IDA 里分析可以看到对应的方法在 iTunesStore 模块。直接 SSH 进入 iOS 文件系统，分别在 /System/Library/Frameworks 和 /System/Library/PrivateFrameworks 里查找 iTunesStore.framework。直接读取其 Info.plist 来获取 bundle id。


另一种方法就是直接 frida 附加对应进程。当前版本可以直接获取 Objective C 类所在的模块路径：ObjC.classes.ISURLBag.$moduleName。这个路径去掉最后一个文件名，只保留目录（basename），即 bundle 的路径。然后直接 ObjC.classes.NSBundle.bundleWithPath_('/System/Library/PrivateFrameworks/iTunesStore').bundleIdentifier() + '' 就是 bundle id 了。
