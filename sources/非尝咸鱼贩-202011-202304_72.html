系统版本、大小等信息用 UITableViewLabel 渲染，而更新日志则是一个 UIWebView。说好的 UIWebView 已经不能上架了呢？自己还在用……


接下来以 UIWebView 作为突破口。用 frida-trace 直接跟踪所有相关的方法：

重新进入检查更新的界面，在日志里注意到 loadHTMLString:baseURL: 被调用了。编辑 frida-trace 在 __handlers__ 里自动为这个方法生成的 js，加入调用栈打印：

log('called from:\n' +        Thread.backtrace(this.context, Backtracer.ACCURATE)        .map(DebugSymbol.fromAddress).join('\n') + '\n');


其实这里跟用 lldb 打断点，然后 backtrace 查看调用堆栈没有本质区别。然而实际操作中会发现 debugserver 存在无法正确识别符号的问题，而且 debugserver 每次初始化实在是太慢了。习惯了 frida 之后很多任务比调试器方便很多。

调用栈是一个 NSXPC 方法的回调执行到的。经过反汇编确认定位到这个方法：


-[SUSUISoftwareUpdatePane _titleCellSpecifierForState:]


它调用 -[SUUISoftwareUpdatePane updateDescriptor] 返回一个 SUDescriptor 示例，这个类存储了系统更新的各个字段信息：

这个头文件是网上找的。有很多现成的 iOS 私有头文件转储，直接搜索某个 class 的名字大概率能找到。笔者用的比较多的参考网站是 developer.limneos.net。


当然也可以直接用 Grapefruit 查看 class 的信息，甚至还能当场反汇编



因此至少需要 hook 三个方法：


  • -[SUDescriptor publisher]  出品方

  • -[SUDescriptor humanReadableUpdateName] 系统的名字和版本

  • -[SUDocumentation releaseNotesSummary] 更新日志的 HTML


系统更新服务内部用到了 iOS 的 Assets 框架。这是一个用来分发 OTA 更新的私有库，除了操作系统的升级包之外还有很多动态下发的资源包，例如一些语音合成、词典等五花八门的文件。


iOS 请求更新之后会下载一小部分元数据到如下目录，解压为 [随机 UUID].asset 子目录


/var/MobileSoftwareUpdate/MobileAsset/AssetsV2/com_apple_MobileAsset_SoftwareUpdateDocumentation


asset 里面就是多语言国际化过的许可信息、更新日志等 HTML 文件：

-[SUDocumentation releaseNotesSummary] 方法从 ReadMe.html 中读取一次数据，之后会缓存到内存的一个 NSMutableDictionary 里。为了与原始的更新日志风格一致，可以参考原版的 HTML 文件。


至于这个方法从哪里读取的内容其实不重要，我们只要直接在上层调用把 HTML 返回值替换掉即可。需要注意这个方法的返回值是个 NSData 而不是 NSString。



最后的 frida 脚本代码


const { SUDescriptor, SUDocumentation, NSString } = ObjC.classes
const patches = {  publisher: 'Nokia',  humanReadableUpdateName: 'Symbian OS 2021'}
for (const [method, val] of Object.entries(patches)) {  const str = NSString.stringWithString_(val);  Interceptor.attach(SUDescriptor['- ' + method].implementation, {    onLeave(retVal) {      retVal.replace(str);    }  });}
