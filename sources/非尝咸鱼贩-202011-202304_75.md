# frida 与 iOS lockdown 交互

frida 已经是移动安全不可或缺的框架，就不必多做介绍了。中文的 frida 资料大多集中在环境配置和一些入门 hook 示例，内容大同小异。本文来介绍一个相对冷门的特性，通过 USB 连接后，用 frida 的 API 直接和 iPhone 的 lockdown 服务交互。

  

在 frida 12.7.5 引入了一个叫做 channels 的功能：

  

> **Changes in 12.7.5**  
> Brand new channels API for establishing TCP connections to a tethered iOS or Android device, as well as talking to lockdown services on a tethered iOS device.https://frida.re/news/

  

12.7.20 版本之后针对 iOS 的 lockdown 做了加强，除了 TCP 之外还能直接访问相关系统服务。

  

那么这个 channels 到底是什么东西？

  

* * *

  

先从其他工具说起。  

  

Android 官方的调试器有一个端口转发功能。例如通过 USB 连接手机之后，可以用 adb forward 将设备上的端口转发到电脑上，反之也可以用 reverse 命令把电脑的端口服务转发到手机：

  

adb forward tcp:6100 tcp:7100

adb reverse tcp:3000 tcp:3000

  

这个功能对网络调试有一定作用，譬如可以无需连接 WLAN 便可以让 APP 和测试环境的服务端通信。

  

iOS 官方没有直接提供类似的端口转发功能，但协议是支持的。iTunes 备份数据、Xcode 真机调试，甚至第三方的手机管理工具如 iMazing 等都是利用了 iOS 的 lockdown 服务，对应在 macOS 端的服务是 usbmuxd。

  

usbmuxd^(\[1\]) 提供一个 Unix Socket：/var/run/usbmuxd，无论是 iTunes 还是 Xcode 都可以直接通过访问这个 socket，建立和 iOS 导出到 USB 的服务的连接。Windows 版的 iTunes 安装之后也会提供 lockdown 的访问，不过不是 Unix Socket，而是 TCP 端口 62078。

  

另一方面，iOS 端的进程是 lockdownd（/usr/libexec/lockdownd），用来相应 macOS 端的请求，转发给对应的服务进程，有点类似服务器上的网关。所有通过 USB 暴露的服务都集中配置在一个 plist 文件。之前是 

/System/Library/Lockdown/Services.plist，现在则硬编码写死到 lockdown 文件的 \_\_TEXT.\_\_services 这个 section 里，以免被越狱修改：

  

![](../Images/b7b44487eeda501ff7592b5e18f61741.png)

  

这个 plist 记录了所有允许 USB（lockdown）访问的服务列表的 id、进程路径、启动参数等。几个常用的服务如下：

  

*   com.apple.afc：读写 /private/var/mobile/media 目录下的文件
    
*   com.apple.syslog\_relay：读取系统日志
    
*   com.apple.mobile.installation\_proxy：安装 ipa（如 Xcode 调试包）和枚举、卸载应用  
    

  

扯远了。端口转发在哪里……？

  

官方的 usbmuxd 只提供了 macOS 的支持。有人通过逆向 USB 协议，写了一个跨平台的开源项目 libimobiledevice ^(\[2\])，支持三大主流的桌面操作系统。

  

在其中的 usbmuxd ^(\[3\]) 开源实现里提供了一个命令行工具 iproxy，可以把 iPhone 上的端口转发到计算机上。例如为了安全考虑，现在的越狱工具默认不再监听 0.0.0.0，而是 127.0.0.1。要访问越狱设备的 SSH 端口：

  

iproxy 2222 22

  

接着在电脑上直接访问 localhost:2222 即可登录 SSH（注：checkra1n 越狱默认安装的 SSH 服务是 dropbear，使用的端口为 44）。

  

* * *

  

回到 frida。

  

frida 的 channel 类似 iproxy 和 adb forward 命令，即通过 USB 打开远程设备上的 TCP 端口。如下示例使用 tcp:22，即打开 TCP 22 端口上的 OpenSSH 服务。如果正常工作，将读取到一个表示服务版本号的 banner：

  

*   
*   
*   
*   
*   
*   

```
import fridadev = frida.get_usb_device()channel = dev.open_channel('tcp:22')print(channel.read(1024).decode())
# SSH-2.0-OpenSSH_8.4
```

  

open\_channel 返回一个 IOStream 对象，可读写数据：

  

*   is\_closed 属性：stream 是否已被关闭
    
*   close() 方法：关闭连接
    
*   read(count) 方法：读取最多 count 个字节的数据，返回内容长度可能小于 count
    
*   read\_all(count) 方法：读取最多 count 个字节的数据，在缓冲区没有达到期望长度之前会阻塞
    
*   write(count) 和 write\_all(count) 方法：类似如上两个方法，写数据
    

  

channels 在 frida-node 里同样可用。下面使用两个 pipe 调用就很轻松地实现了一个 iproxy 功能：

```
const frida = require('frida');const net = require('net');
async function main() {  const device = await frida.getUsbDevice();  net.createServer(async (socket) => {    const channel = await device.openChannel('tcp:22');    socket.pipe(channel).pipe(socket);    socket.on('close', () => channel.end())      .on('error', console.error.bind(console));  }).listen(62222);}
main();
```

  

然后试试 ssh -p62222 root@127.1 进入 iPhone 的 shell。再结合 node-ssh2 可以写一个没有过多依赖的 shell 工具。

  

以上提到的 tcp 端口的访问对 Android 和 iOS 都支持。但我个人觉得 Android 上有一些鸡肋，因为 frida-server 自己也需要 adb forward 先转发一个端口或者 socket 才能用……  

  

接下来进入比较有意思的部分。

  

针对 iOS 设备，frida 的 channels 还支持另一种 lockdown 模式的连接。  

  

前面提到 iOS 内置了一些 lockdown 服务，用来实现数据同步、日志读取、应用管理、真机调试等功能。在使用 Xcode 真机调试时，Xcode 会在后台往 iOS 上传一个 Developer Disk Image（开发者镜像），包含一些普通用户用不到的功能，例如 lldb 的 debugserver。

  

这个镜像会在 /Developer 下挂载一个只读的文件系统，在 DDI 里还会额外安装更多的 lockdown 服务：

下面演示一个协议非常简单的截图功能的实现。  

  

在 Xcode 的“设备和模拟器”菜单中打开详情，有一个截图按钮

  

![](../Images/ebc27ee6169535a0f75af333cc8902a0.png)

  

截图对应的服务是 com.apple.mobile.screenshotr，需要挂载开发者镜像才能用。

  

这个服务的消息格式很简单。每条消息是 CoreFoundation 当中的基本数据格式，如字符串、数字、数组和字典等。首先数据会被序列化成 binary plist 格式（做过 iOS 开发对这个很熟悉）的一个数据缓冲。buffer 的长度以 32 位无符号整数保存，先发送，然后紧跟二进制 plist 数据。

  

| 4 字节  
 || 可变长度  
 |
| --- | --- |
| buffer 的长度，大端序，32 位无符号整数  
 || 序列化后的 binary plist buffer  
 |

  

发送和接收都是基于这个格式。

  

lockdown:com.apple.mobile.screenshotr 打开对应的 lockdown 频道，通过 DLMessageVersionExchange 命令交换版本信息；然后发送一条 ScreenShotRequest 命令，在返回的 ScreenShotReply 消息中读取其 ScreenShotData 即为 png 格式的设备全屏截图。

```
import fridaimport structimport plistlib
class Channel(object):    def __init__(self, name='', dev=None):        self.name = name        self.dev = frida.get_usb_device() if dev is None else dev        self.pipe = self.dev.open_channel('lockdown:%s' % name)
        if len(name):            self.version_exchange()            self.dl = True        else:            self.dl = False
    def version_exchange(self):        magic, major, minor = self.read()        assert major >= 300        assert magic == 'DLMessageVersionExchange'        assert minor > -1        self.write(['DLMessageVersionExchange', 'DLVersionsOk', major])
        magic, = self.read()        assert magic == 'DLMessageDeviceReady'
    def send(self, msg):        return self.write(['DLMessageProcessMessage', msg] if self.dl else msg)
    def recv(self):        if self.dl:            magic, msg = self.read()            assert magic == 'DLMessageProcessMessage'            return msg        else:            return self.read()
    def write(self, msg):        buf = plistlib.dumps(msg, fmt=plistlib.FMT_BINARY)        self.pipe.write_all(struct.pack('>I', len(buf)))        self.pipe.write_all(buf)
    def read(self):        size, = struct.unpack('>L', self.pipe.read(4))        response = self.pipe.read_all(size)        return plistlib.loads(response)
    def __enter__(self):        return self
    def __exit__(self, exc_type, exc_value, traceback):        self.close()
    def close(self):        self.pipe.close()
with Channel('com.apple.mobile.screenshotr') as channel:    channel.send({      'MessageType': 'ScreenShotRequest'    })
    response = channel.recv()    assert response['MessageType'] == 'ScreenShotReply'    with open('screenshot.png', 'wb') as fp:        fp.write(response['ScreenShotData'])

```

  

这个技巧已经应用到 Grapefruit 的开发，实现全屏截图和 ideviceinfo 功能。

  

不过老实说，frida 只是提供了一个访问的 lockdown 途径，不如直接用 libimobiledevice 的 Python 绑定。后者封装了常见的服务，不需要手动构造消息。  

  

此外其他语言实现的 lockdown 客户端也值得参考，比如这个 go 语言^(\[4\])的 go-ios：https://github.com/danielpaulus/go-ios

  

值得一提的是部分 lockdown 服务用到了 NSKeyedArchiver 序列化，在 libimobiledevice 里暂时没有直接支持。在没有 Foundation 框架的（非 macOS）系统上，go-ios 提供了跨平台的支持
