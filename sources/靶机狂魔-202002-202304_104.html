老树新开：使用可访问性工具开发任意文件写入

古往今来，众所周知的是替换windows的可访问性辅助工具是绕过远程登录桌面认证执行后门的方法之一。当目标开放3389的时候我们为何不使用某些任意读写工具来达到此目的呢？

引言

当获得3389且没有密码的时候通常网管套路是将硬盘卸下来，装到另一个电脑中并且替换C:\Windows\System32\sethc.exe为cmd.exe。之后重新装回硬盘在欢迎界面时可以触发粘贴键之后以system权限运行cmd了。所以同样的概念也适用于存在任意文件写漏洞的场景，以便以可用的最高特权角色实现命令执行。

Windows Xp中的二进制替换

sethc.exe并不是唯一的可替换的可执行文件，如下列表都可以：

•C:\Windows\System32\sethc.exe•C:\Windows\System32\utilman.exe•C:\Windows\System32\osk.exe•C:\Windows\System32\Magnify.exe•C:\Windows\System32\Narrator.exe•C:\Windows\System32\DisplaySwitch.exe•C:\Windows\System32\AtBroker.exe

我们可以替换任何一个进行提权

Windows 10中的dll劫持

在 Windows 10中，我们可以通过利用屏幕键盘osk.exe这个可执行文件中存在的 DLL 劫持漏洞来实现。特别是当osk.exe被执行后在查找HID.dll库的时候，原始的dll存在于C:\Windows\System32\hid.dll中，而osk.exe首先会在C:\Program Files\Common Files\microsoft shared\ink\HID.dll这个路径中去查找。可想而知~

利用RDP协议

但当上一种方式被修补后：

•Windows Exploitation Tricks: Exploiting Arbitrary File Writes for Local Elevation of Privilege[1]•MS finally fixed the "Diag Hub Collector" exploit on Win 10 1903[2]

那么最近，Clément Labro[3]发现了基于USO服务在Windows 10下的一种新技术。项目地址在这里:https://itm4n.github.io/usodllloader-part1/

但如果我们遇到启用了Network Level Authentication (NLA)[4]的话,他会在加载图形化界面之前预认证。那么接下来的手段分类为2种场景如下：

1.开启了RDP2.启用了NLA，则需要远程桌面用户组成员的有效凭据或等效凭据

未开启NLA

没有任何问题启用屏幕键盘触发

开启了NLA

如果启用了 NLA，我们需要有效的凭据才能到达 RDP 会话中的图形界面 我们可以通过NT AUTHORITY SYSTEM来手动锁定会话去访问登录屏幕，或者通过如下步骤来触发屏幕键盘。

1.Win + R2.osk.exe3.回车4.Ctrl + Alt + Del

一些TIPS

1.使用内置的远程桌面连接客户端连接到本地的RDP服务时，我们需要使用127.0.0.2来作为目标，因为127.0.0.1和localhost被本地客户端自身的硬编码检测阻止掉了。2.如果启用了NLA并且拥有凭据的用户已经完成了桌面的登录，则在强制断开连接之前显示错误消息时。我们仍然可以在system权限下使用Win + U来触发屏幕键盘。

防护与检测

1.保留NLA2.业务允许的情况下可以禁用RDP3.白名单检测或目录监控文中罗列出的可替换的可执行文件
