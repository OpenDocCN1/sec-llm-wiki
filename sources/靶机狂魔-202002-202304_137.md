### 目标情况初步分析

•传统制造业,人员网络安全意识普遍比较薄弱**后续可知,内网绝大部分的windows单机系统都是直接用市面上的乱七八糟的激活工具激活的,可见毫无安全意识可言,估计系统也都是直接ghost的**•外面web虽然看着比较小,但内网规模可能较大,初步看了下,如果从web入手,渗透周期,对人员精力的耗费可能都比较大•所以,决定还是直接用发信的方式来搞,以便能快速获取到目标核心办公网入口,先深入敌后,再从内到外的慢慢迂回进行控制**可能很多情况下都是边界层层防御纵深,但从内到外的渗透往往不堪一击**•上面已提过,由于目标传统制造业,人员整体安全意识可能比较差,所以,对于信的内容要求也不高,前期我也几乎没有做过任何的详细调研准备,就在谷歌上爬了爬目标的文件看了看根据从谷歌上泄露的文件可知,对方的安全部并不叫安全部或者什么技术部,而叫**信息化部**,所以最终就决定直接伪装他们信息化部通过邮件给其他部门下发漏洞补丁**其实就是exe 的木马**另外,不清楚目标邮件服务器是不是做了什么很变态的设置,信一直发不进去,所以,后来没办法,通过搜集目标邮箱,批量尝试单弱口令,很幸运,竟然跑出来了一个,后来就直接拿这邮箱去发木马信了。•在开始正文之前,不妨先来简单分析下国内企业弱口令的规律现状**个人对国内接触的确实比较少,但就已经接触到的经验来看,密码规律大致如下,后期可根据这些规则来写脚本**

> 公司名域名,比如,sanfor,xxxx...之类的+年份+ 666 / 888 / 999+@ / ! 比如: sangfor666, sangfor888 , SangFor666...

> 公司名 + 123 /1234 / 12345 / @123 / @1234 / @12345 比如: sangfor123 , sangfor@123 , SangFor@1234....

> 季节/季度/月份 + 年份 + ! / . 比如: Winter2019! , Spring2019! , June2019 **部分互联网公司爱用这种密码**

> 打印机牌子 + 123 **此为专门针对打印机的弱口令** 比如: HewlettPackard123...

> 把完整域名直接作为网站后台的管理密码

> 员工姓名简拼 + 123/1234/12345/生日日期

> 员工姓名全拼作为登录密码

> 政府单位一般都爱用办公室座机号**这也几乎是针对政府部门的通杀弱口令**

> 针对大学的,一般都是学生学号作为密码的居多**可以直接到谷歌上去爬目标泄露的各种xlsx,doc之类的...** 除此之外,也可以到国内各个漏洞提交平台去看下已被别人爆出的目标密码,然后再根据这些已有的密码来猜测目标的密码设置习惯

> 老外一般偏爱用键盘键位作为密码 等等...

•除此之外,就是一些比较常见的top弱口令,说白点,常用的无非就那五六十个,而且实战也用不了太多,能直接让你挂个大字典在那儿瞎跑的机会其实并不太多,再说那种爆破势必会在目标系统里留下大量的敏感登录日志,不到绝境,非常不建议一上去就那么干

### 首先,是针对那些现已获取本地管理权限的机器维持方法

**加入注册表自启动**

之所以要这样放到注册表中,主要是由于我们后期的操作可能需要有一个正常用户权限的shell,因为有些操作必须在对应的用户权限下才能正常能进行,比如,wmi, schtasks, net use, 截屏,键盘记录,等等... 此处之所以用这种非常老的维持方式,主要还是因为咱们的最终目的只是检测,并非想长期监控,待后期项目全部结束后也方便对方集中清理

*   
*   
*   

```
beacon> shell REG query "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run"beacon> shell REG ADD "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run" /V "SysDebug" /t REG_SZ /F /D "c:\windows\debug\SysDebug.exe"beacon> shell reg delete "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run" /V "SysDebug" /f
```

![](../Images/deb20333d733d6004aeb00eaae7e3e75.png)

**加入高权限计划任务定时执行**

一般情况下,我们弹system权限shell的最快方式就是通过它,这个shell的主要目的是为了暂时性的维稳 (注: **此处所指的维稳并不是我平时说的稳控,计划任务实在太明显),system权限虽然很高,但有时候并不适合我们操作**,比如,上面提到的那些schtasks,net user,wmi之类的,很显然就不适合在system下进行,但某些情况下就很适用,比如,当前机器在域内,而且你也有了当前机器的administrator权限,但你在administrator下是看不到域内的任何东西的,即使当前机器就在域中(没法和dc正常通信),那么此时你就需要想办法先把自己从administrator提到system,之后就能跟DC正常通信了

*   
*   
*   
*   
*   

```
beacon> shell schtasks /create /RL HIGHEST /F /tn "SysDebug" /tr "c:\windows\debug\SysDebug.exe" /sc DAILY /mo 1 /ST 10:05 /RU SYSTEMbeacon> shell schtasks /query | findstr "SysDebug"beacon> shell schtasks /run /tn "SysDebug"beacon> shell schtasks /delete /F /tn "SysDebug"beacon> shell schtasks /tn "SysDebug" /query /fo list /v
```

> 0x03：搜集存放在GPP目录中的各类明文账号密码

共享组策略目录中是域中非常容易出现密码的地方,一些域管理员可能会利用它对域内用户登录时进行一些初始化操作,所以,**基本在每个域渗透中的第一步都会选择赶紧去看看这个地方**,比较幸运的是,我们在此处发现了一个域管平时用来重置域内客户机本地administrator用户密码的bat,bat里直接留了明文密码,也就是说每次指定域用户登陆都会去重置他本地的administrator密码,实在没想到目标域管这么做的用意是什么? 这等于说是直接帮我们留了个后门,由此可见,对方域管的运维水平比较感人,其实看到这儿,明眼人心里估计早都有谱了,说白点,这个域离死已经不太远了
