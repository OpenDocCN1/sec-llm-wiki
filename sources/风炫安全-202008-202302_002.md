# 一 前言  

## 

这几天，一起和同事做一个授权的网站的溯源调查跟踪，并最终拿下服务器，整个过程是比较有意思的，事后我把整个过程脱敏之后写出来供大家一起学习参考。

## 二、探测

接受网址后，首先进行一些踩点摸索，首先看到是一个夺宝拼团类的网站。

![](../Images/3839af09e61668bd2680575f86eb7262.png)

利用谷歌开发者工具看到了这是一个开发语言为PHP的网站，再查看网站源代码之后，查看到网站的路由，基本判定是一种基于Thinkphp的二次开发的网站。可以看到有 `/public/runtime` 这种Web目录，还有网站的路由也是 `index.php?ctl=file&act=upload` ，一般ctl表示控制器， act 表示执行这个控制器中的具体的动作。

### 3.4 payload

上面可以看到我们的缓存内容是一个序列化后的文本，那么我们该如何插入我们的payload的呢？其实就一句话 **利用换行符和注释来突破序列化问题**, 在Http请求中，`%0A%0D`是换行符的编码，我们可以在前后插入换行符来利用。

比如，缓存文件中的内容为：

```
<?php
//00a:1:{s:12:"sina_app_key"}
?>

```

而sina\_app\_key这个文本是我们可控的内容,那我们可以输入

```
%0A%0Dphpinfo();%0A%0D//

```

那么文件中会变成什么样子呢？

```
<?php
//a:1:{s:12:"

//"}
?>

```

![](../Images/501ae71b31c97ee1c1d5e7e9122264e1.png)

可以看到这里的 `phpinfo()` 已经高亮了，说明可以正常解析了。

那么我们的payload就是

```
%0A%0Dphpinfo();%0A%0D//

```

## 五、提权

### 5.1 open\_basedir?

拿到Webshell，第一时间看看有什么文件，但是发现无法跨目录，向上没有权限，宝塔嘛，默认就会设置`open_basedir` ，

![](../Images/df17cabd4ed680bb501830ed96680f79.png)

突破 `open_basedir` 有手就行。

在网站的任意的一个目录下，新建一个 `.user.ini` ，里面内容写上

```

open_basedir=/
```

![](../Images/b6121e676dea602d408ce4c5ad31b6ff.png)

然后把shell复制到这个目录下然后重新连接，突破。**原理是nginx会首先匹配当前目录下是否有.user.ini，如果有优先加载当前目录下的.user.ini。**

![](../Images/4db7fa8a6002b7980face1e5d93d6063.png)

但是翻了下文件，还是没有可利用价值的，还是需要提权。
