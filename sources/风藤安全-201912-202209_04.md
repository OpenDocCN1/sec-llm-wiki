# spring cloud function 最新3.2.3 版本 trick

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzIzMjYzNTQwMA==&mid=2247484293&idx=1&sn=1e7caeadd778fae640a0f339652ef968&chksm=e890aee2dfe727f446398470d5663de97104ca7e3e8676f69e61fb3f2a2b66c7e0f2aca6246b&scene=126&sessionid=1681656984#rd](http://mp.weixin.qq.com/s?__biz=MzIzMjYzNTQwMA==&mid=2247484293&idx=1&sn=1e7caeadd778fae640a0f339652ef968&chksm=e890aee2dfe727f446398470d5663de97104ca7e3e8676f69e61fb3f2a2b66c7e0f2aca6246b&scene=126&sessionid=1681656984#rd)

之前3.0.0.RELEASE <= spring cloud function <=3.2.2 之间的版本存在SPEL注入漏洞，目前官方已经发布了3.2.3版本修复了这个漏洞。

![](../Images/d0207d1ca612e7a8d729e8d5d3c565b9.png)

  

Spring Coud Function 官方在最新版本3.2.3 已经修复了之前的commit为dc5128b 的SPEL注入漏洞，具体代码改动  

![](../Images/449abb8ecca29b8fec2a98a2233d7249.png)

可以看到重载了functionFromExpression方法，通过判断isViaHeader 执行不同的处理过程，如果为真，就用SimpleEvaluationContext处理,否则才用StandardEvaluationContext 处理。

![](../Images/dc53e1d7c90cfedbbd28cd22953aa823.png)

  

在取Header头中的spring.cloud.function.routing-expression是调用了functionFromExpression(StringroutingExpression, Objectinput, booleanisViaHeader)，但是从配置文件中取这个字段的时候还是调用的functionFromExpression(StringroutingExpression, Objectinput)这个方法就是造成SPEL解析命令执行漏洞的关键。

![](../Images/e03331725199cb1cb57420bd5bbbfd72.png)

  

因此理论上只要能够控制functionProperties.getRoutingExpression() 的值应该也能够触发这个漏洞。

进一步看到functionProperties类中的getRoutingExpression()方法

![](../Images/e21de6bb8a9e93141710488528f497fa.png)

  

到这里就非常清晰了，因此只要在配置文件中添加

spring.cloud.function.definition\=functionRouter

spring.cloud.function.routingExpression\=T(java.lang.Runtime).getRuntime().exec("calc")

  

本次还是用[Spring-Cloud-Function SPEL 注入漏洞的一点想法](http://mp.weixin.qq.com/s?__biz=MzIzMjYzNTQwMA==&mid=2247484277&idx=1&sn=ca5e6a0cd02a6d850256804f7cb73e3d&chksm=e890ae12dfe727043e0bc961231989c667ac73f7d1d95612f7dc5ba6183ebad4570242651b1a&scene=21#wechat_redirect) 中的环境，需要将

```
spring-cloud-starter-function-web 版本改成最新3.2.3版本
```
