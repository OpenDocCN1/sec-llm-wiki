Flutter是Google开发的一套全新的跨平台、开源UI框架，帮助开发者通过一套代码库高效构建多平台精美应用，支持移动（iOS、Android系统）、Web、桌面和嵌入式平台。

框架部分完全使用Dart语言实现。

### Flutter的核心是Flutter引擎，它主要是用C ++编写的。它提供Flutter核心API的最小实现，包括图形绘制（通过Skia），文本布局，文件和网络I/O，Dart运行时和编译工具链等。

### Dart 语言

Dart是一种强类型、跨平台的客户端开发语言。具有专门为客户端优化、高生产力、快速高效、可移植（兼容ARM/x86），由Google负责开发和维护，在2011年10启动项目，2017年9月发布第一个2.0-dev版本。

  

**Dart本身提供了三种运行方式：**

1.  使用Dart2js编译成JavaScript代码，运行在常规浏览器中（Dart Web）  
    
2.  使用DartVM直接在命令行中运行Dart代码（DartVM）  
    
3.  AOT方式编译成机器码，例如Flutter App框架（Flutter）
    
      
    

### 0x02  Flutter 运行机制

最近做一款APP做渗透测试，通过简单WIFI代理发现根本没有任何流量导入，APP上界面也没任何报错且功能也不受影响，但发现lib 目录下存在 libflutter.so，毫无疑问这个APP是使用Flutter 框架开发的。由于Flutter APP不会走系统代理，必须要在程序中显式地指定代理服务器地址。类似这种：

*   
*   
*   
*   
*   
*   
*   
*   
*   

```
(dio.httpClientAdapter as DefaultHttpClientAdapter).onHttpClientCreate =      (HttpClient client) {    client.findProxy = (uri) {      //proxy all request to localhost:8888      return "PROXY localhost:8888";    };    client.badCertificateCallback =        (X509Certificate cert, String host, int port) => true;  };  
```

      问题是Flutter 打包好的APP天然就已经加固了，反编译然后添加上述代码十分困难。看看反编译之后的代码结构：com.test.app 只有微信的支付的两个Activity，通过AndroidManifest.xml 知道入口在p140io.flutter.embedding.android.FlutterActivity，当应用启动后，它会加载libflutter.so ，之后任何渲染、输入或事件处理等都会 delegate 给APP。

                    ![](../Images/6a26f8961b05a415948beaf1de9d6821.png "image.png")![](../Images/55f17d62e4f949875abf1332b019428b.png "image.png")

lib 目录下可以找到libflutter.so

![](../Images/a7dc5c9c5a90968c79e1b61f21f63466.png "image.png")  

搜索网上的资源，发现针对Flutter APP  https抓包的实践甚少，大部分是翻译的这篇文章:

https://blog.nviso.eu/2019/08/13/intercepting-traffic-from-android-flutter-applications/

也就是通过使用frida 来hook libflutter.so 里面BoringSSL 证书校验部分逻辑，其实并不需要这么复杂，不过也给作者点个赞，毕竟给了我们一种思路参考。

### 0x03  Flutter 抓包方法

目前，针对Flutter APP抓包除了使用frida hook 外，想到能不能换一种更简便的方式。因此使用了网易的MuMu 模拟器+Proxyman 做了一些尝试最后成功抓到https流量，步骤如下：

**使用proxychains 将Memu模拟器流量强制走Proxyman 代理**

*   
*   
*   
*   
*   
*   
*   

```
[ProxyList]# add proxy here ...# meanwile# defaults set to "tor"#socks4         127.0.0.1 8888#socks5    127.0.0.1 1089http   127.0.0.1  8888
```

然后启动

*   
*   
*   
*   

```
proxychains4  open -a /Applications/NemuPlayer.app[proxychains] config file found: /usr/local/etc/proxychains.conf[proxychains] preloading /usr/local/Cellar/proxychains-ng/4.14/lib/libproxychains4.dylib[proxychains] DLL init: proxychains-ng 4.14
```

之后发现模拟器界面冻结，所有按钮点击失效，网络恢复功能也无效，最后查找原因是因为模拟器本地交互的流量因为启用了"HTTPS Response" ,所以要把IP为127.0.0.1 的https 拦截模式取消。

![](../Images/d3bb45e45578a94f2eebce0ea1852e9f.png "image.png")

这个问题解决之后，当打开测试的flutter APP 后还是不行，Proxyman 报了一个“SSL Handshake Failed" 的错误，说明之前导入到模拟器的Proxyman CA证书不受信任。想到flutter app 是不信任用户证书的，只信任系统证书，所以下一步把Proxyman的CA证书导入的安卓模拟器的系统证书里面（具体步骤百度即可，不再赘述)。

![](../Images/9ff6753fdd73b35dac4704bbd91fb06a.png "image.png")

最后重启模拟器，发现流量都进入到Proxyman 里面了，但都是IP 显示的，后续处理如何定位哪个是测试APP的流量。

![](../Images/473870352adb494727a9a186341ed707.png "image.png")

一种是如果知道域名直接ping 下IP ，然后在这个IP下的任意一个请求右键选择启用“Enable only this domain"

![](../Images/ec97eaff02d90e6e4142938e6321ba13.png "image.png")

如果不知道这个APP请求的后端服务域名，尽量只装这一个APP，其它无关的应用都卸载，多次点击功能，找到NemuHeadless 应用栏里面最新的URL，然后比较IP匹配的域名即可。

![](../Images/4679770d13831328d3a21db11f749d1b.png "image.png")

后续如果修改报文里面的参数或者重放报文，需要把GET请求IP地址替换为相应的域名，否则会出现下面这个错误：

*The certificate for this server is invalid. You might be connecting to a server that is pretending to be “116.xx.x.174” which could put your confidential information at risk. (code=-1202)*
