Gitlab简介


GitLab是一款广泛用于代码版本管理、问题跟踪的软件，又分为GitLabCE（社区版）和GitLabEE（企业版)，尤其在企业级内部应用开发中，更多地是使用了GitLab作为代码仓库，以便于集中规范代码管理、团队协作开发等，在DevOps中也能或多或少看到它的身影。

 此次公开的漏洞编号为：CVE-2020-10977，其中受影响的版本为GitLab EE/CE 8.5 到12.9，漏洞主要产生在项目间移动issue 时存在目录穿越漏洞，导致可任意读取服务器敏感文件。

漏洞原理及复现过程


根据https://gitlab.com/gitlab-org/gitlab/-/issues/212175描述，这个漏洞是赏金猎人William Bowling报告给GitLab团队的，复现漏洞也很简单，只需要3步：

step1:新建两个项目—project1和project2

step2:在其中任意一个项目，例如project1中创建一个新的issue，问题描述输入下方所示代码，然后点击提交

![a](/uploads/11111111111111111111111111111111/../../../../../../../../../../../../../../etc/passwd)


step3:将刚才的issue 移动到另外一个项目中(move issue），例如project2，然后会发现在project2中看到这个issue带了一个附件，名字就为passwd，点击之后下载打开会看到读取的/etc/passwd 内容。

问题是出在UploadsRewriter 中在将issue移动操作时，没有检验文件名，因此可以通过目录穿越复制文件内容携带到目标项目中。Markdown在查找引用时使用了如下的正则表达式：

  MARKDOWN_PATTERN = %r{\!?\[.*?\]\(/uploads/(?<secret>[0-9a-f]{32})/(?<file>.*?)\)}.freeze  

UploadsRewriter在移动issue时，先时查找引用的文件路径是否存在，如果存在就将查找到的文件内容复制到目标项目target_parent中。

 @text.gsub(@pattern) do |markdown|          file = find_file(@source_project, $~[:secret], $~[:file])          break markdown unless file.try(:exists?)
