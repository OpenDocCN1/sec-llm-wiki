今天分享的是国外一位白帽子在Dropbox上发现的一处SSRF漏洞，最终获得Dropbox奖励的4913美刀奖励，以下是这位白帽子挖掘漏洞时的过程自述：


Dropbox计划对我来说非常有趣，因为它有最好的回报和良好的响应时间，所以我选择了在Dropbox Bug Bounty Program的政策中提到的HelloSign上进行搜索。


我开始在app.hellosign.com上搜索主要应用程序，发现具有从Dropbox，GDrive，BOX，OneDrive，EverNote导入文档的功能。此时，我已经想到了SSRF，因此我从Dropbox Import Feature开始，我看到了以下请求：



我将FILE_REFERENCE参数的值更改为我的Burp Collaborator URL，但是我却得到了404报错，此时我以为他们已经提供了😫保护功能，于是我放弃并关闭了我的电脑。


第二天，我怀着新的想法再次登录挖洞，尝试了一下OneDrive功能，我看到了这个请求：


GET /attachment/externalFile?service_type=O&file_reference=MYONEDRIVEFILELINKHERE&file_name=FILENAME.ANYTHING&c=0.8261955039214062 HTTP/1.1Host: app.hellosign.comConnection: closeAccept: application/jsonUser-Agent: Mozilla/5.0 (Macintosh; Intel Mac OS X 10_15_2) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/86.0.4240.111 Safari/537.36X-CSRF-Token: Sec-Fetch-Site: same-originSec-Fetch-Mode: corsSec-Fetch-Dest: emptyReferer: REDACTEDAccept-Encoding: gzip, deflateAccept-Language: en-GB,en-US;q=0.9,en;q=0.8,hi;q=0.7Cookie:REDACTED


可以看到，上面的请求具有SERVICE_TYPE参数值为0，这意味着onedrive使其与第一个来自dropbox且包含D参数的请求不同。现在，file_reference参数值更改为我的协作者链接，幸运的是，这次我执行了ping操作。


之后，HelloSign生成了一个PDF，其中包含我的合作者页面的内容，这一刻我太快乐了。😍


此时我开始获取本地主机内容，起初我检查了他们在Whatismyipaddress s.com上使用的云服务，我发现他们使用的是aws/ec2，所以我尝试获取http://169.254.169.254/latest/，但我却得到了：


404 Not Found


遗憾的是，请求没有通过，然后我尝试了http://127.0.0.1，得到了同样的响应。



现在我有点难过，但是我试着通过黑客攻击寻找更多的方法，发现了这个宝藏报告：https://hackerone.com/reports/247680，其中作者使用了303Redirect to Bypass SSRF Protection(绕过SSRF保护)。


很快我在我的服务器上使用了以下代码：


<?php header('Location: http://169.254.169.254/latest/meta-data/', TRUE, 303); ?>


然后我再次尝试使用服务器重定向链接，最终我得到了AWS Instance（Metadata）的内容😍😍😍


现在我感到非常高兴和震惊，因为我在世界上最大，最好的漏洞赏金计划上发现了完整的SSRF，我能够从AWS元数据中检索所有内容，例如access_keys，tokens等。


最终，在第9天，Dropbox奖励了我4913美刀。



截止目前，这是我的第一个SSRF和最高漏洞赏金。😄
