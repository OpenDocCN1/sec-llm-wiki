# Windows Zerologon漏洞允许攻击者成为域控管理员

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MjM5Mzc4MzUzMQ==&mid=2650254189&idx=1&sn=3639d525c4f58b0086ee545780d1da75&chksm=be92c0e989e549ff5f9296fc7f56ec51352a58adabf4f4e72a7be6b2160351a9be9adbac428a&scene=126&sessionid=1681667019#rd](http://mp.weixin.qq.com/s?__biz=MjM5Mzc4MzUzMQ==&mid=2650254189&idx=1&sn=3639d525c4f58b0086ee545780d1da75&chksm=be92c0e989e549ff5f9296fc7f56ec51352a58adabf4f4e72a7be6b2160351a9be9adbac428a&scene=126&sessionid=1681667019#rd)

研究人员已经发布了Windows Zerologon CVE-2020-1472漏洞的攻击程序，该漏洞可以使攻击者控制Windows域，请及时安装相应补丁！

作为2020年8月补丁星期二安全更新的一部分，Microsoft修复了一个被评级为10/10的严重安全漏洞，称为“ CVE-2020-1472 | Netlogon特权提升漏洞”。

成功利用此漏洞，攻击者可以将其特权提升给域管理员并接管域。

此后，发现此漏洞的网络安全公司Secura发布了该漏洞的详细记录，并将其命名为Zerologon。

## **滥用加密漏洞**

  

当用户登录到域上的Windows设备时，它使用 RPC上的 Netlogon远程协议（MS-NRPC）与域控制器进行通信并验证用户身份。

  

如果用户使用正确的凭据登录，则域控制器会告诉设备允许使用适当的权限进行身份验证。那些使用错误凭证的人显然将无法登录。

  

由于身份验证尝试是敏感的，因此Windows通过安全的加密RPC连接发送身份验证请求。

  

Secura研究人员Tom Tervoort发现，执行身份验证请求时，有可能迫使域控制器退回到未加密的RPC通信。

  

回到非安全的RPC通信之后，Tervoort可能会滥用Netlogon AES-CFB8密码协商算法中的缺陷来尝试欺骗，从而实现成功登录。

  

在Tervoort的测试中，平均需要进行256次尝试才能成功欺骗成功的登录。

这种操作会欺骗设备，使用户以域管理员的身份登录到系统中。

  

![](../Images/dddbadf25480e811eb9ffb456f6f39c0.png)

  

攻击者获得域管理员特权后，他们将获得对域控的完全访问权限，可以更改用户的密码并执行所需的任何命令。  

  

该漏洞的可怕原因在于，攻击者甚至不需要域上的合法凭据，仅通过欺骗响应以实现登录成功。

  

“没有必要等待其他用户尝试登录，相反，攻击者可以自己登录，假装仅支持NTLM并提供一些无效的密码，他们登录的服务会将NTLM握手转发给域控，域控将以否定响应进行回复，然后可以用欺骗性答复（还包含重新计算的会话密钥）代替此消息，指示密码正确，并且，用户也可以尝试登录域管理员组的成员（这意味着他们在目标计算机上也具有管理特权）” Tervoort在他对Zerologon的报告中解释说。

  

当涉及到勒索软件攻击时，此漏洞尤其令人关注，因为它允许在单工作站上立足的攻击者获得Windows域上网络的完全控制权。

  

Tervoort警告说：“当攻击者在内部网络中立足时，此漏洞可能特别危险，因为它既允许特权提升（授予本地管理员），又可以横向移动（在网络上的其他计算机上获得RCE）。”

  

**Zerologon概念验证漏洞发布**

  

自Secura的文章发布以来，许多研究人员已经发布了POC，使用户可以在易受攻击的网络上获得域管理员权限。

  

NCC集团的Rich Warren昨天发布了PoC，使他能够在十秒钟内实现域管理员。

  

![](../Images/16710c51e8ce00e544637fa8b5a4b075.png)

  

研究人员还发布了其他对域控的类似攻击。

  

**修复漏洞**

由于修复Zerologon漏洞可能导致某些设备无法正确进行身份验证，因此微软分两个阶段推出了修复程序。

  

第一阶段已于8月11日以安全更新的形式发布，该更新将阻止Windows Active Directory域控使用不安全的RPC通信。

  

此更新还将记录来自不使用安全RPC通信的非Windows设备的身份验证请求，以使管理员有时间修复设备或将其替换为支持安全RPC的硬件。

  

2021年2月9日，将作为补丁更新的另一部分，微软将发布第二个更新，它将进入强制执行阶段，该阶段要求网络上的所有设备都使用secure-RPC。

  

因此，强烈建议Windows管理员在其Active Directory域控上部署补丁的第一部分，以保护其网络。

  

同时，Secura也发布了一个工具，可以检查域控制器是否容易受到Zerologon（CVE-2020-1472）漏洞的攻击。
