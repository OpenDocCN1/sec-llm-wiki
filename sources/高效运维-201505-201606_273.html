并行分布式框架 Celery 简介

在介绍OWL的Python并发模型之前，有必要先介绍一下Python的分布式框架：Celery，它是一个基于消息传递的异步任务队列，支持任务调度。执行单元称为Task，被一个或多个worker处理，worker使用multiprocessing、Eventlet、Gevent，Task能够被异步（后台）执行也可以被同步（等待完成）执行，Celery在生产服务器每天处理数以万计的Task。

Celery架构优点

  • 分发任务是透明的

  • 在并发worker启动时，对其改变很小

  • 支持同步、异步、周期和计划任务

  • 如果出现了错误，会重新执行任务

注意：不要传递Database/ORM对象

不要传递Database对象（例如一个用户的实例）给任务，因为可能序列化之后的数据已经是过期的数据了，所以最好传递一个user id，然后在任务执行的时候实时的从数据库获取，监控系统的阀值还有相关参数都是实时修改的，报警数值修改了，那么在执行Task的时候相关的报警的数值都会同步更新，做到实时修改报警的阀值，实时生效。

消息传输(Broker)

Broker是Celery中的核心组件，通过Broker可以发送和接受消息，来完成和workers的通信。

Celery 支持多种类型的 Brokers，我们监控系统采用 Mysql 作为 Broker。 Broker提供在不同客户端应用之间通信的方法，客户端应用发送任务，workers执行任务，可以多台带有Broker的机器等待接收消息，然后发送消息给workers，这样就可以做到线性扩容，监控指标的metric增加之后我们只要增加 Broker就能够带来比较好的性能收益。

Worker

Worke是提供任务执行的单元，Worker并发运行在分布式系统的节点中。

Worker支持比较多的工作模式，我们在OWL中使用了协程并发模式：gevent。

简单介绍一下 Python 的协程：
协程的特点在于它是单线程执行，最大的优势就是协程极高的执行效率，因为子程序切换不是线程切换，而是由程序自身控制，因此没有线程切换的开销。和多线程相比，线程数量越多，中间带来的开销就越大，协程的性能优势就越明显。

另外，协程不需要多线程的锁机制，因为只有一个线程，也不存在同时写变量冲突，在协程中控制共享资源不加锁，只需要判断状态就好了，所以执行效率比多线程高很多。

因为协程是一个线程执行，那怎么利用多核CPU呢？
最简单的方法是多进程+协程，既充分利用多核，又充分发挥协程的高效率，可获得极高的性能。

任务结果存储

Task result store存储 Worker执行任务的结果.

一个任务状态就是该任务结束的时候是成功还是失败。在一些统计场合，这很有用，但我们需要知道，任务退出的状态并不是该任务执行的结果，该任务执行的一些结果因为会对程序有影响，通常会被写入数据库，多数都将任务结束的状态存放在数据库，但是存这些真的有必要吗？有可能会影响到你的web服务，所以通常设置CELERY_IGNORE_RESULT=True去丢弃，对于我们的监控系统，因为是异步任务，知道任务执行完成之后的状态没有作用，所以果断丢弃.

实例详解

我们监控系统任务是用设备uuid做标识，一个uuid就表示一台主机，通过定时把任务放到mysql里，worker会实时监测mysql的任务，只要任务放到mysql里，worker就会把任务取走传递到执行任务的方法，执行任务用到Pycurl curlmulti异步的方式.

Pycurl包是一个libcurl的Python接口，它是由C语言编写的，poll轮询和异步非阻塞，通过非阻塞的方式，任务的计算非常实时，有效的保障了我们任务报警的实时性。

任务通过主机uuid获取metric去生成url，通过tsdb去查询所对应的时间数据进行计算，由于查询数据模块和数据计算模块是独立，所以我们必须保存主机metric返回的数据，目前的保存方式是通过文件的方式.

报警策略

监控的主要目的是通过收集数据及时判断出监控的指标所存在的问题。

策略一：固定阀值报警

固定阀值报警是最常见的，就是预设一个固定阀值，和监控指标的当前值做对比，算法如下:

（固定阀值-当前值) > 0 or < 0 or = 0

策略二：浮动报警

浮动报警是为了应对应用指标的可持续变动而设立的，因为固定阀值满足不了它增长的需求（例如业务的高峰期）。一个监控指标的数据可能成几何增长，持续大于固定阀值，这样我们连续收到的报警就没有多大意义，我们需要持续关注监控指标的增长情况，所以浮动阀值应用而生，算法如下:

浮动值 = 当前值 + 浮动阀值

策略三：环比报警

环比是本期统计数据与上期比较，反映本期比上期增长了多少，表明监控指标琢期的发展速度，环比分为日环比、周环比、月环比和年环比，算法如下:

环比率 = (本统数/上期数)/上期数 * 100%
