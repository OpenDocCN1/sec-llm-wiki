Q1：请对比一下SQL Server 的运维与其他数据库、比如MySQL 的运维，有没有什么优势或特别之处？

我自己的感觉是有下面几点：

  1. 基于策略的管理机制(policy Based Management)，里面的资源管理(Resource Governor)能够帮助DBA管理负载和系统资源使用,可以给不同负载设定使用资源的优先级和使用上限，可以保证重要应用不被其他随机请求影响；

  2. 有多种使用方便的图形化管理工具，多种运维任务都提供向导式的用户支持，还可以轻松在上线环境上按照需要抓取语句负载等等；

  3. 对云扩展的支持（数据同步，数据备份到云上等等），提高数据的高可用性；

  4. 和操作系统高度集成，可以完全使用Windows 活动目录的用户安全性,公司策略管理，可以使用OS 的证书对连接传输进行加密，第三方备份工具可以调用OS 的文件shadow copy API 进行数据库备份，使超大型数据库的备份工作变得快捷简单；

  5. 对存储过程和用户自定义函数交互式的debug 功能等

Q2：能否描述一下微软官方对于SQL Server 的产品战略和规划？

SQL Server 的研发主方向非常清晰明了，只有3个：

  1. 关键任务支持 (内存计算) ；

  2. 洞察力 (BI) ；

  3. 云。

受制于停滞不前的CPU时钟，以及越来越便宜的内存价格，内存计算成为MSSQL 的重点。

我这边不讨论列存储技术，因为无论Oracle, SAP Hana 和MSSQL 采用的主要技术差别不大，理论上对查询速度的提升都在100倍左右。

MSSQL 的革新是在OLTP 的内存计算：

  • 内存表的存储引擎完全重写；

  • 传统的Block、Page 的结构不见了；

  • Lock、Latch 的机制在内存表里也消失了。

MSSQL 的内存计算，能够实现事务系统7~30倍的性能提升，而且你也不需要把整个数据库移入内存，而只需灵活地选择那些大负荷的表就可以了。

洞察力（BI）主要包括两个方面：

  1. self-service BI，Power BI 能让那些非IT专业的人员，自己实现商业智能分析， DataZen 能够轻松制作专业报表，并发布到各种平板和智能手机平台；

  2. Advanced Analytics - 微软相信machine learning 是未来的方向，所以MSSQL 会整合R，通过R 来实现基于SQL Server 增强的统计预测能力。

云的支持，不仅仅包括如下：

  • 把一个故障转移的副本放在Azure 云上，就算本地完全失败，负载也能转移到云上的SQL Server;

  • 一个大表，冷数据放在云里，热数据放在本地SQL Server。

事实上整个SQL Server 研发的方式已经发生改变，云优先成为主题。

以后所有的SQL Server 的新功能，会先出现Azure 云上的SQL 数据库，用户反馈不错才会集成到下一版本的SQL Server 上。

还有，云的SQL数据库一个很大竞争力来自于价格，例如：

如果你的数据量少于2GB，事务数又不太高的话，申请一个B级的SQL数据库每月只需要43元，但是却拥有99.99%的高可用，7天内任意点的数据库还原功能（删掉数据库也能还原）。

那么，你还有必要使用昂贵的虚机去安装一个数据库，还要考虑为这个数据库做灾备么 (基本上云平台目前都不支持单个虚机的高可用)？

Q3: 能否列举一下在SQL Server 的管理和维护中遇到的最大的问题？

最大的问题就是对于已经发生过的问题无法追溯，例如：

  1. 数据库曾经发生了高CPU 利用率或者性能下降，如果当时没有收到日志，无法追溯原因。存储过程突然发生重编译带来的性能问题，无法知道重编译的原因。

  2. 用户错误删除了数据，没有简单的办法立刻恢复被误删数据，只能用传统方式通过备份一一恢复。

  3. 没有预先开启audit 的情况下无法查询哪个用户恶意删除数据。

补充：SQL Server 2016 的Query Store 将会解决第一个问题。

Q4: 请以自身经历为基础，描述一下一个SQL Server DBA 的理想职业规划

我个人认为一个优秀的SQL Server DBA 应该不仅仅能保障公司的SQL Server 的高效运行，更应该保持对未来技术趋势良好的愿景和热情。

未来的企业中，会越来越多的出现关系数据库和非结构化数据平台（例如Hadoop）共存的局面。

优秀的DBA 应该有能力整合这两种平台和数据，而不是把自己的能力只限制在SQL Server 中。

还有这一年在市场和企业客户的接触中，我发现越来越多的企业IT支出已经不仅仅是由IT部门负责，而是更倾向于业务/市场部门驱动。

在这种趋势下，优秀的SQL DBA 不仅仅应掌握数据库技术, 更应该了解公司的业务需求和未来发展远景。并利用SQL Server 的高级分析和大数据技术为企业创造价值。
