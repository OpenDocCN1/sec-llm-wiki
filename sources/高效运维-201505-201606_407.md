## 嘉宾介绍

> 彭哲夫，芒果TV平台部核心技术团队负责人。主要负责 Docker 和 Redis Cluster 相关的基础设施开发。前豆瓣App Engine核心主程，前金山快盘核心主程。在系统工程方面经验丰富。彭首席，知识丰富，功底深厚，语言幽默风趣，知乎上、简书上有不少彭首席的精彩大作和回复。

**Q1： Web端是使用什么语言与架构开发?看代码应该是flask吧？**  
A1： 我们用的 Python 和 Flask 开发的。

**Q2：服务端与客户端通信是通过Socket还是其他？**  
A2：客户端是指 Eru 的 API 还是？如果是 Eru 我们走的 HTTP 协议。

**Q3：视频里Redis Cluser创建的时候，创建容器是使用制作好的镜像还是dockerfile?**  
A3：我们不会每次创建，就以 Redis 而言，一次 build，以后每次部署都是直接让 Docker daemon pull image 去部署。

**Q4：目前系统还有瓶颈吗？在哪里？如何应对？**  
A4：现在系统我们没明显的瓶颈了~。

**Q5： “使得 Eru 有了 Container 的组资源控制的能力。” 请问具体是一个什么 组资源 ？**  
A5：就是一组 Pod 的服务器控制能力。

**Q6：一组Pod是多少台物理机？还是说仅仅一台物理机的多个Container？**  
A6：我们一组 Pod 对物理机上限没限制，目前我们测试过模拟 10k 台机器做资源分配，Redis 集群 Pod 现在有 20台左右。

**Q7：“扩容和缩容，我们更加希望是业务方去定制这个组件去做。”，现在有业务这样做的了么，他们实现中遇到了什么问题和挑战？**  
A7：现在 Redis Cluster 就是自己通过数据调用 Eru API 实现的扩容和缩容。实现过程中目前来看是没多大问题的，因为 HTTP 一来是协议简单，二来我们给的都是 Restful 的 API ，比较亲民。

**Q8：新实例启动的时候，进行CPU资源限制，请问是使用—cpuset-cpus还是—cpu-shares？另外你说的碎片核与独立核，是指CPU的线程吧？**  
A8：我们 cpuset 和 cpushare 都用上了，对于这个问题，其实 cgroups 是这样的一个逻辑；假设一个Container 有3个 CPU，其中一个共享核设定了 20% 的使用量， 那么在共享核，我们假设是 0 号核吧，没有其他 Container 绑定的时候，这个 Container可以近似看成绑定了 3个核。

它可以吃满 0 号核 100% 的用量，但是一旦 0 号还让其他4个 Container 绑定后，只要在高峰期，那么它只能最多吃满 20% ，等于就是说对于这个 Container而言，0号核的资源是弹性的，最少能保证 20%。有一篇测试的文章，我给翻一下 https://goldmann.pl/blog/2014/09/11/resource-management-in-docker/ 。

**Q9：Redis容器启动的时候，容器里内核参数overmemory等跟Redis配置相关参数是否修改？如何修改？**  
A9：可以修改，我们实现了一个简单的启动脚本，我们所有的 Container 都是 root 启动，然后通过这个脚本来修改 overmemory 什么鬼的参数，当然这中间我们也做了一些 docker black magic 。具体脚本可以参考 https://github.com/HunanTV/eru-core/blob/master/scripts/launch 。

**Q10：问一下你代码里是把容器里的/proc/sys与宿主机目录/writable-proc/sys绑定，然后修改宿主机的这个目录里对应文件内容吗？**  
A10：不是，Docker 本身对 proc 的mount 是 ro 的，同时proc 的内容实际上在容器中是完全独立的，如果你了解 rust 那么这个解释就很简单了。一个 immutable 的值，mount 这个 writable-proc 实际上类似于给了一个 mutable 的指针，这样使得在容器中修改内核参数成为了可能，而这个参数实际上也是和 host 隔离的。比如你修改 overmemory，那么你看上去修改的是 writable-proc 下的，实际上这时候你 cat /proc 下的这个参数，发现它已经改掉了。所以说这个坑就坑在 Docker 并未给 Container 提供 init 上。

**Q11：使用moosefs作为共享存储，请问mfs的单点故障如何解决的？**  
A11：应用并不强依赖 moosefs，当然从豆瓣的运维经验来看，moosefs 单点问题就1句话解决……重启大法好。

**Q12：容器都有单独的ip还是只有少数几个ip地址公用？如果是多个ip，如何保证Redis Cluster在初始化的时候，不会把主从实例碰巧分配到一台物理机上？**  
A12：macvlan 的好处就在于，IP 随我用，我们现在集群是 /16 的地址，理论上这个子网能覆盖 6w多个 Container。

**Q13：看起来你们改写了Redis trib来实现自动的扩容缩容和对集群的监控等，这个原生的工具有什么问题吗？**  
A13：作为 Python 党，一切 Ruby 实现都是反动派。
