Q&A

Q1：Puppet 就易用性而言，比起 Ansible 这些新工具，有什么不足的地方？
A1：Puppuet 最大的问题在于没有命令执行，也就是向服务器发命令。只有一个很鸡肋的 exec 资源，可以执行命令，但效率很低。为此 Puppetlabs 收购了 Mcollective，来弥补这一不足。

Q2：请方便谈一下你对 Fabric 的理解。
A2：Fabric 也只是命令执行，早在 10 年我们就有使用，但并行性能不行，因此没有采用。

Q3：如果站在今天的角度，抛开你 Puppet 专家的身份，类似运维自动化工具，你推荐哪几个？为什么？
A3：运维自动化工具推荐：Ansible、Zabbix、PowerDNS、GitLab、Redmine、Gods 和 ELK。 利用开源软件是可以快速构建公司的运维体系的，但是否适应公司的长期发展，需要自己根据公司的情况而定。

Q4：什么业务负载的情况下，需要用到 Puppet Agents（集群）？实际用的公司多吗？能否举例？
A4：现在都讲量身定制，运维也要。一般情况下，Web 以及架构复杂的业务、多机房业务需要用到集群模式。例如：大量 Web 并发、CDN。现在公司的业务都有跨机房容灾，所以集群模式用的挺多的。

Q5：Puppet 的周边很丰富，而像 Ansible 感觉更加的简单可依赖，你觉得 Puppet 的前景会怎样？
A5：Puppet 周边丰富，是有很多好处的。比如方便快速构建，并且项目与代码是经过测试的，并非不成熟。不过 Ansible 更灵活，适合小企业直接一套搞定。前景必须无限好。自私地说，也很看好它的发展。新版本运行比以前更快了，依赖也更少了，代码写起来更舒服了。Ansible 和它是把双刃剑，比如：之前要写很多 Require 依赖，新版本只需要按顺序写，减少依赖代码。

Q6：刘大师你好，你提到「Mcollective，又一大神器，基于 MQ 的命令处理，比 Ansible、Salt 更灵活。大企业和传统企业必推荐」。请问 Mcollective，具体而言，怎么比 Ansible、Salt 做到更灵活的？
A6：Mcollective 的灵活性在于，它是一个基于 MQ 的框架，你可以在上面自定义你所需要的编排，并且可以是快速并行处理。缺点就是比较重，不像 Ansible、Salt 轻。我找了一个陈刚很全面的介绍，如下：

MCollective 特点：

  • 能够与小到大型服务器集群交互；

  • 使用广播范式（Broadcast Paradigm）来进行请求分发，所有服务器会同时收到请求，而只有与请求所附带的过滤器匹配的服务器才会去执行这些请求。没有中心数据库来进行同步，网络是唯一的真理。

  • 打破了以往用主机名作为身份验证手段的复杂命名规则。使用每台机器自身提供的丰富的目标数据来定位它们。目标数据来自于：Puppet, Chef, Facter, Ohai 或者自身提供的插件；

  • 使用命令行调用远程代理；

  • 能够写自定义的设备报告；

  • 大量的代理来管理包，服务和其他来自于社区的通用组件；

  • 允许写 SimpleRPC 风格的代理、客户端和使用 Ruby 实现 Web UIs；

  • 外部可插件化（Pluggable）实现本地需求；

  • 中间件系统已有丰富的身份验证和授权模型，利用这些作为控制的第一道防线。

  • 重用中间件来做集群、路由和网络隔离以实现安全和可扩展安装。

Q7：对于创业公司如何快速构建可持续发布环境呢？
A7：现在使用的 PHP，通过 GitLab+Jenkins rsync 发布代码。这块，我有画过一个 Docker的图，不管是 Docker 还是用 Jenkins 都可以。Puppet 我在建行大规模应用了，管理了几千台机器，包括很多小型机，做了很多封装。

之前也画过 Jenkins CI 的图，更偏向于流程图，就是 Jenkins 到节点那一步怎么控制风险。我们现在的 PHP 没有弄这么复杂，直接 Gitlab 用不同的 hook 处理的，和研发约定发布规则。然后不同的 tag 和 ENV，hook 到不同的虚拟机/物理机，目前是放在 Puppet ENV 里处理。游戏这块的 PHP 偏少，所以采用的简单方案。

Q8：刘大师，对于创业公司如何快速构建可持续发布环境？
A8：要看是不是基于云端了，目前很多创业公司都用的云，这块可以利用云端的工具来实现，像 AWS就 提供了很多。国内的话，也有第三方的工具使用。我个人觉得别自己折腾了。如果说非云端，可以利用我刚才说的流程，选自己适合的工具搞定，规模小上 Ansible 好了。

Q9：Salt 适合什么场景？按老师说法适合运行 CMD，Puppet 才适合配置管理。
A9：嗯，我个人是这么推荐的。Ansible/Salt + Puppet 结合，国内这样子的案例挺多。

Q10：Windows 配置管理推荐用哪一个？
A10：Windows 更推荐 Puppet，支持得很好。

Q11：其实一个公司是比较难同时说服 OPS 同时搞几种工具的？
A11：嗯，不要为了工具而上工具，解决你们现在的问题就好了。

Q12：一般监控联动都怎么做的？大致思路是？
答：监控我们的做法时，之前定义好服务器角色与监控模板，在 Puppet 部署完成后，直接 Include Zabbix 即可。

Q13：Puppet 可以在 WinXP 下当软件分发器用吗？我就想能在 WinXP 下用，目前用的 ftp 客户端做客户端程序同步下载，想换成 Puppet，那样可以更高级一些。
A13：Win7 上没有经完全测试，不能保证。官网也这么说明，一般支持 Server 系统，2003、2008、2012。
