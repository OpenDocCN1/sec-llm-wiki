# SRECon亚洲会议的议题是如何产生的？

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzA4Nzg5Nzc5OA==&mid=2651666609&idx=1&sn=aacd912a109b793c2bffa2c962b02141&chksm=8bcbfb18bcbc720ee56314228c506989fc97aa24efce9c6065db5aefccd7b15369ba9f458ecd&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzA4Nzg5Nzc5OA==&mid=2651666609&idx=1&sn=aacd912a109b793c2bffa2c962b02141&chksm=8bcbfb18bcbc720ee56314228c506989fc97aa24efce9c6065db5aefccd7b15369ba9f458ecd&scene=27#wechat_redirect)

![](../Images/20d0c9ea9861afab4d20adbd9b9420a9.png)  

自从 Google 的 SRE 一书面世后，就立即受到了千千万万开发运维人员的追捧，成为了运维攻城狮们标配的圣经。其目前去各大招聘网站去搜一下，BAT、华为，甚至一些传统企业，都在招聘 SRE 工程师。可以说 SRE 工程师是 DevOps 文化的实例化的标志。

![](../Images/72060021702df66d2a5b9d9735391638.png)

SREcon 是 SRE 工程师的世界级会议，从2014年第一次在硅谷举办，一直到现在，已经发展到第四年。该会议由计算机科学领域的知名机构USENIX主办，参会人员来自 Google，Facebook，Twitter, LinkedIn，Dropbox，Netflix，Pivotal，Pinterest，Uber，Twitter 等国际知名科技公司的顶级专家。

一天后该会议的第一次亚洲/澳洲区会议就要在新加坡举行了，这是第一次在亚洲地区举办。本次会议的联合主席是百度和 Dropbox 的大牛担任，笔者有幸成为该次会议的组委会成员（主要任务为担任议题推荐人和议题评审人）。下面为大家介绍本次会议的议题是如何产生出来的。

**首先我们来看下过程时间：**

![](../Images/e6f6ae4f460c21abd108b18247dd73f7.png)

*   2月初的时候开始征集议题
    
*   3月6日是标准议题（45分钟）截止、3月20日闪电议题（20分钟）截止
    
*   3月27日标准议题通知演讲者、4月3日闪电议题通知演讲者
    

那么问题来了，在这20天左右的收集议题完毕到通知演讲者参加的过程中发生了什么，是怎样确认一个议题是否可以参与会议的呢？这个时候评委就要发挥作用了。

![](../Images/bbbc20d24a3f6fc50ea66a3f3d5bbda6.png)

上图就是评分的列表界面，笔者是后来抓的图，在没有确定议题时 SUBMITTER 和 STATUS 两列是没有的，评委们可以看见：

> *   议题题目（如So，you want to be an SRE？）；
>     
> *   议题类型（有 CULTIVATE/RECRUIT/RETAIN、SUCCESSES/PITFALLS、AUTOMATION/MONITORING/DEP、CATALYZING GREATSRE TEAM、DISASTER RECOVERY、EXTENDINGSRE CULTURE、OTHER）；
>     
> *   议题大小（标准、闪电）；
>     
> *   议题提交时间；
>     

**关键步骤来了，点击题目后进入下面的评分页：**

![](../Images/0d67ddb20464e2c84a633945886459cf.png)

![](../Images/5d8967c1c9be538a7e4e75ac25975f50.png)

**通过评分页可以看到几个特点：**

评审内容包括名称、简短描述、完整描述、关键概要、给评委的说明

评委可以打四个分值 0 - Not Acceptable、1 – Satisfactory、2 - Strongly Agree、3 – Excellent

在评审时是看不见投稿者的姓名、公司、职位等相关信息的，只能看到想要演讲的内容的相关说明，这样确保了评审时关注的是内容的价值性，而不会被投稿人的知名度、职位、公司平台等进行干扰；评委可以对议题进行0-3四个分值的打分，最后通过多个评委的打分结果综合得出该议题的总得分。

本次投稿的议题一共有108个，最后会议实际有35个议题，因此只有前三分之一的议题会被录取。可见 SREcon 大会的议题选取经过了公平的严格筛选出来的，因此能在会议上出现的议题都是非常有价值的干货。
