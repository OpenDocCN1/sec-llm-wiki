编者按：根据麦肯锡的一项研究结果，科技公司想要成功，关键所在无外乎两点：标准化和工具赋能。标准本身是最佳实践的集合，有了标准，每一步都离目标更近（而不是偏离），将标准固化在工具里，让人做更有价值的事情。这和 DevOps 标准及 DevOps 持续交付流水线工具平台的核心理念和实践不谋而合。

 

12 月 26 日，2019 运维大会在北京顺利召开。会议由中国信息通信研究院、中国通信标准化协会指导，TC608 云计算标准和开源推进委员会主办，云计算开源产业联盟支持。旨在为进一步推动行业发展，促进运维新技术、新理念时间落地，加强行业内经验分享交流，聚集多领域大咖分享宝贵运维经验。

 

大会隆重发布了 DevOps 标准持续交付部分第六批评估结果。其中，中信银行三个项目顺利通过 DevOps 标准持续交付部分3级评估，获得由中国信息通信研究院（以下简称信通院）开展的《研发运营一体化（ DevOps ）能力成熟度模型》持续交付评估证书。DevOps 标准共分5级，持续交付部分如果能达到 3 级已经是国内领先水准，这代表着中信银行在参评系统的持续交付能力达到国内领先水平。


 

中信银行通过 DevOps 标准持续交付部分的3级评估的项目，分别是：

  • 新版个人移动银行

  • 资产托管清算系统

  • 快捷协作平台


由中国通信标准化协会副秘书长潘峰女士与中国信息通信研究院云计算和大数据研究所所长何宝宏博士共同为中信银行授牌：

 

潘峰女士（右一）、何宝宏博士（左一）为中信银行授牌（左三）▲


 

此次，我们采访了中信银行软件开发中心总经理刘良俊先生，软件开发中心技术平台开发处处长陈海和数据中心技术支持处处长助理伍科松，一起深聊中信银行三个项目参与评估的细节和幕后团队的故事，听他们分享中信银行 DevOps 实践的经验。


-Q&A-


中信银行软件开发中心总经理 刘良俊


Q：请问选择三个项目同时参加评估，是出于一种怎样的考虑？本次贯标对您企业及团队有什么积极影响么？

 

刘：我们本着“以评促建”的初衷参加此次标准评估。在 2019 年初，中信银行正式开展 DevOps 建设和敏捷转型实践，之前就关注了 DevOps 标准，参加评估也是为了更接近行业的最佳实践。本次选择参评的三个项目各有特点：

 

首先是新版个人移动银行，属于渠道端，业务需求非常活跃，此项目对于我们快速交付的要求非常高。第二个是快捷协作平台，支持分行一线业务发展，为分行提供快捷交付、总分协作、共享复用、开放可控的科技服务，代表着一种特殊类型的研发模式。最后是资产托管清算系统，承载托管部清算划款功能，采用的框架是行内统一的开发平台。

 

我们是想通过评估来检验这三类不同的项目，在持续交付方面实践的成熟程度。如果说三个项目都能达到标准，那么在后面全面推广过程中，每一类项目都有一个标杆，都有一个成型的最佳实践案例作为参照。

 

此次是我行第一次参加 DevOps 标准评估，取得了开门红，对于我们的团队具有非常大的激励作用。在过去一年里，作为 DevOps 试点团队，我们尝试用敏捷方法，结合组织级提供的体系和平台支撑进行研发实践。就新版个人移动银行团队举例，是从2016年就开始做敏捷实践的尝试，所以信心更高一些，其他两个团队，基础相对薄弱。通过这样的实践，最重要的是看到思想的转变，很多年轻的同事真正去拥抱这个变化，真正感觉到了敏捷的力量。

 

Q：从您的经验来看，DevOps 标准评估和其他常见标准评估，有什么区别？

 

刘：从 DevOps 标准来讲，更重要的是敏捷研发模式的加速器；当敏捷工作模式成型后，没有 DevOps 体系和工具支撑是跑不起来的，这是我最真实的感受。在内部已经有这样的例子，老的流水线根本满足不了要求，只有新的流水线才能够真正做到持续集成与交付，这是最大的变化。

 

信通院的 DevOps 标准更看重工程实践，解决我们敏捷研发以及传统研发过程中的痛点，解决在业务快速交付过程中的问题。例如现在的资源申请，包括网络、存储资源，都是自助式的，效率跟以前完全不一样，以前大概需要两周左右，现在缩减到一天完成，这是非常大的进步。

 

Q：在 2020 年，对于DevOps 建设有什么规划？

 

刘：今年我们的 DevOps 建设，包括体系和工具平台已经基本成型，内部试点项目是9个，明年会继续扩大。另外今年是在团队级别、项目级别做敏捷实践，明年尝试用一条产品线来实践规模化敏捷。

 

明年的重点工作首先把敏捷和 DevOps 实践在中信内部继续推广，稳中有升；其次是和业务融合，2019 年在零售板块已经尝试了融合式的工作模式，把队伍直接派驻到业务部门。像电子银行建立了13个增长小组，每个小组都面向产品和服务做了一些实践，明年要继续深化，实践组织级敏捷，通过 DevOps 模式的应用，效果会更显著。

 

软件开发中心技术平台开发处处长 陈海


Q：恭喜您三个项目都通过了 DevOps 标准持续交付部分的三级，也表明了这三个项目已经达到了行业的先进水平，现在说一下您此时的感受？

 

陈：首先很感谢信通院对我们的指导和帮助。通过三级评估是我们软件开发中心2019年的重要工作目标，启动评估时，DevOps 平台刚刚搭建起来。所以此次三个项目能够顺利通过评估，要感谢我们项目管理团队、研发团队的付出。此次评估也让我们看到了与业界先进水平的差距，一类是组织级工具的差异，另一类是团队级能力的差距。但是我们通过一步步的改进，正在逐渐把差距缩小。

 

Q：此次通过评估的过程顺利吗？遇到什么困难？如何解决的？


陈：总体来说，本次评测过程是艰辛的，结果是成功的，尤其是参评项目中有像“新版个人移动银行”这样的我行A+类系统，其承载的用户量和技术栈复杂性都是行内系统中排名靠前的。最初模拟评估时评分较低，对团队冲击比较大，但是大家还是有所预期的，更多的还是技术层面上的困难。比如说新版个人移动银行这个项目，由于系统架构没有完全解耦，实际上是一个百人规模的团队。在这样的场景下，原来的配置管理方法还有持续交付方法可能就不适用了，所以也是经过了多轮试验，才寻找到了比较合适的方法，并通过反复沟通大家最终达成了一致。

 

另外，在流水线平台的搭建上，虽然我们的应用系统没有在容器上运行，但是 DevOps 流水线工具，包括项目管理工具、看板工具、持续集成 CI、CD 的工具都是运行在容器上的。我们刚开始预期每日发布 100 次，但到后面在测试环境实际要发布600多次，如果不是借助容器技术，我们不会这样顺利的实现目标。我行容器云平台的能力也在最终评估过程当中得到了认可，甚至个别的能力项达到了四级水平。

 

我们还存在一些差距，尤其是在度量反馈、测试环境管理、测试数据管理方面，这也是未来需要持续提升的地方。我们金融企业有较多的监管和安全的因素要考虑，如何在满足监管的前提下，更好的做好自动化服务，满足业务快速发布的要求，这是我们未来必须要解决的问题。

 

Q：对于 DevOps 今年的实施，您觉得最大的收获是什么？您的下一步计划是？

 

陈：最大的收获是看到了试点项目的研发交付周期缩短，能够更快速的进行业务价值交付。通过测算，试点项目的业务需求交付效率平均提升了 18%，超出了预期。另一方面，团队的士气和信心也得到了明显的提升。

 

通过这次的评估，我们也建立了内部的评估标准。明年也定了一个小目标，所有试点项目的流水线都要达到内部二级的标准要求。

 

明年还要考虑更大规模系统如何做敏捷转型和持续交付。比如核心系统，几百人的项目团队要如何去做敏捷协同和持续集成？比如数据类的项目如何在测试数据、测试环境的准备、持续部署等方面达到更高的要求。这些对我们来说都是新的挑战。

 

Q：那对于 DevOps 发展前景，您怎么看？


陈：DevOps 目标是实现快速、高效、高质量的业务价值交付，同时也重视文化建设和高效能组织建设，这与我们软开中心的定位以及中信银行的企业价值观是高度一致的。在金融科技领域，数字化转型和应用上云的大趋势下，要求企业具备越来越快的IT交付能力和稳定高效的IT服务支撑能力，DevOps，以及未来演进的 AIOPS，都是首当其冲。未来，将会有更多行业从中找到自己关注的特性，各行业都可以通过 DevOps 获得技术革新和组织效能的提升，开展 DevOps 实践将会是众多企业的必然趋势。

 

数据中心技术支持处处长助理 伍科松

 

Q：通过 DevOps 标准评估，给数据中心带来了哪些影响？

 

伍：中信银行数据中心主要负责全行信息系统运行管理的工作，与开发中心一起在信息技术管理部的领导下，一部两中心统一配置资源来实现DevOps转型战略项目的落地，这是成功的关键要素。在 DevOps 的实施过程中，对于数据中心自动化和标准化服务的要求非常高，比如说为了业务价值的快速流动，需要提升基础环境资源交付的效率和质量，评级前我们是以周为单位交付，按照DevOps 的理念，我们通过云服务的标准化和自动化，打通平台壁垒统一规划，简化流程提升效率，将交付周期缩短到了按天和按小时级，让项目团队真正切切的感受到价值。

 

为此，我们对基础资源服务进行了大量优化和改进工作，包括自动化平台的推广和优化，CMDB的治理，通过云平台和PaaS提供相应服务封装，按照基础设施及代码的理念来设计服务，可以在研发平台上直接调用数据中心标准服务，从而加快了资源的交付效率。过程中，涉及到整个数据中心各个部门的参与和协同，从前期准备到落地，在领导的重视和全力投入下，最终能够优化和实现出来，因此数据中心的收获很大。

 

Q：从运维的角度来讲，有哪些明显的提升和改变？

 

伍：首先是思维观念方面的转变。以前按照标准规范和要求去做，现在是整个敏捷文化的推行，运维团队也需要拥抱敏捷，开始往运维开发上思考和转型，总结运维工作当中遇到的问题和挑战，快速响应解决问题和交付价值，为业务赋能，而不是被动等待流程。


其次是技术体系方面的转变。以前开发支撑体系跟运维体系是分开建设的，在 DevOps 文化里面要求去打破，推动全流程自动化的思想深入人心，将运维自动化平台从生产运维端，到开发测试端打通，这样保证了开发和生产配置统一，工具统一，工艺统一，保障部署和发布的高频率和高质量要求。同时，将整个研发的敏捷体系和工艺引入到数据中心的运维开发工作上来，让产品的研发态和运行态实现过程和质量的一致性要求。

 

Q：从数据中心的角度，您认为 2020 年 DevOps 的工作将如何开展？

 

伍：中信银行数据中心团队一直将创建一流数据中心作为自己的使命，2020将会按照DevOps体系的持续交付技术运营规范的要求，更加深入和全面推动的敏捷优化转型，因为把研发效能提升产能扩大之后，下一步就是交付和运维端的敏捷提速。为了适应流水线快速交付要求，首先要持续的将数据中心已有的体系和工具跟 DevOps 流水线做无缝对接，其次就是做数据中心本身的体系和工具能力改造，更为标准，开放和共享，实现软件定义，数字化运营，以更好的适应快速业务价值交付的要求。所以明年要把敏捷基础设施服务变成组织级的通用能力，在今年的基础上进一步提速持续运营能力，坚持按照DevOps的要求和精神深入贯彻下去，让更多的业务需求和项目获得DevOps带来的实实在在的收益。

全球首个 DevOps 标准，即《研发运营一体化（DevOps）能力成熟度模型》，由中国信息通信研究院牵头，联合云计算开源产业联盟、高效运维社区、 DevOps 时代社区、 Google、BATJ、清华大学、南京大学、通信及金融等行业顶尖企事业单位专家共同制定。

 

目前，由中国信息通信研究院主导的 DevOps 标准已在联合国直属标准化组织 ITU-T、中国通信标准化协会（CCSA）正式立项。

 

在此之前，通过中国信通院 DevOps 持续交付能力成熟度评估的企业包括：中国工商银行、中国银行、华泰证券、浙江移动、腾讯、招商银行、广东移动、北京移动、去哪儿网、郑州银行、神州泰岳等。
