**编者按****：**根据麦肯锡的一项研究结果，科技公司想要成功，关键所在无外乎两点：**标准化和工具赋能****。**标准本身是最佳实践的集合，有了标准，每一步都离目标更近（而不是偏离），将标准固化在工具里，让人做更有价值的事情。这和 DevOps 标准及 DevOps 持续交付流水线工具平台的核心理念和实践不谋而合。

 

2019 年 11 月 1 日，GOPS 全球运维大会在上海正式召开。GOPS全球运维大会至今已经举办了13届，是国内第一个也是最大的运维行业大会，也是备受瞩目的千人峰会，面向互联网及金融、通信等传统行业广大运维、开发等技术人员，传播先进技术思想和理念，分享业内最佳实践。

 

此次会议，除主会场外还分为AIOps 场景实践专场、AIOps 行业案例专场、DevOps标准企业案例专场、阿里巴巴专场等，名企专家近70个议题完整覆盖运维全技术领域。

  

特别值得关注的是，**北京移动集中性能管理系统项目顺利通过 DevOps 标准持续交付部分3级评估，**获得由中国信息通信研究院（以下简称信通院）开展的《研发运营一体化（ DevOps ）能力成熟度模型》持续交付评估证书。这代表着北京移动在该系统的持续交付能力达到国内领先水平。

**\- Q & A -**

  

恭喜**北京移动集中性能管理系统项目**顺利通过 DevOps 标准持续交付部分3级评估，为此我们邀请到北京移动网络运行管理中心李欣然副总经理，深度揭秘北京移动 DevOps 能力建设进展与参评背后的故事。

  

**Q：****请介绍一下您和您的企业，以及此次参与评测的项目。**

 

**李欣然：**我来自北京移动网络运行管理中心，北京移动隶属于中国移动通信集团有限公司，中国移动是目前全球网络规模最大、客户数量最多、服务质量和品牌价值领先、市值排名前列的电信运营企业，根据2019年《财富》世界500强排行榜，中国移动位列第56位。

  

此次参与评测的项目是北京移动网络运行管理中心开发的集中性能管理系统项目。集中性能管理系统是网络运维核心系统之一，是基于网络运行数据的综合性能分析平台，通过对网络运行各类数据的集中采集、处理和分析，运用最新的大数据、机器学习等手段实现端到端网络质量监测保障和故障定界定位分析，着力打造六大能力，即面向网络的主动管理能力、面向客户的感知保障能力、面向业务的敏捷支撑能力、面向市场的网业协同能力、面向技术的规划优化能力和面向终端的投放分析能力。

  

在刚刚结束的庆祝中华人民共和国成立70周年阅兵通信保障工作中，该系统作为北京移动应急通信指挥中心的重要核心系统，实现了分钟级网络性能监控和用户感知多维分析，同时基于人工智能技术可以动态实时输出网络优化解决方案，保障网络运行平稳和用户感知最优，可以说，为国庆70周年重大通信保障任务最终圆满顺利完成，实现“零重大网络事故、零重大安全事件、零重要客户投诉”的保障目标，立下了赫赫战功。

 

**Q：****恭喜您通过 DevOps 标准评估，此次贵公司项目通过的是三级，表明达到了国内领先水平，请说一下您此时的感受。**

  

**李欣然：**我非常高兴我们的团队本次通过 DevOps 标准评估，达到持续交付三级能力水平。随着5G时代的到来，在全球数字化转型的大潮下，传统电信运营商也同样需要拥抱业务转型和技术创新，作为运营商中的网络运维部门，参与此次评估工作本身就是我们在O域新网管架构下进行的 DevOps 研运一体化实践和提升，可以说，通过本次评估，巩固和检验了我们的敏捷开发和持续交付能力，面向 DevOps 理念优化了开发运维团队组织架构，DevOps 方法论的核心理念深入到了每一位团队成员的心中，这必将为今后我们网络运维工作进一步实现降本增效、精益生产、敏捷支撑提供坚实的能力保障。

  

感谢信通院组织的 DevOps 成熟度评估，这个评估就像一把尺子，给出了业界领先的技术参考标准，为转型中的我们指明了方向；还要感谢项目组成员为践行信通院 DevOps 标准所付出的努力，后续我们将在 DevOps 理念的指引下，坚持科技引领、软件驱动、持续创新，为企业数字化转型和用户获得感提升做出自己的贡献。

 

**Q：****贵公司是如何决定加入 DevOps 标准评估工作中的？**

  

**李欣然：**5G带来了无限可能，云网融合是我们的发展方向，面对不断涌现的新业务需求，要求我们提供更高效灵活的资源编排调度能力和更稳定持续的网络运维保障能力，因此迫切需要通过 DevOps 理念和方法论提升软件交付速度和交付质量，目前我们的5G基站建设正在如火如荼的进行中，核心网也在进行NFV云化改造，传统的网络运维工具手段已远远无法满足要求，这就要求我们基于 DevOps 快速打造全新的网络技术运营体系。最初衷的想法是想通过对标信通院的成熟度标准来确定我们的开发运营能力到底处在什么水平，在接受评估的过程中找到自身的差距，指导我们的开发运维模式转型。

 

**Q：****通过 DevOps 标准评估对贵团队意味着什么？**

  

**李欣然：**为了达到降本增效的目标，近年来我们一直在进行IT换人、智能运维等方面的实践，通过综合运用大数据、云计算、人工智能等先进技术手段，不断提升网络运营的标准化、智能化水平。本次通过信通院 DevOps 成熟度评估，是对我们现有 DevOps 持续交付能力的证明，也为我们指明了向更高级别 DevOps 成熟度学习的方向，我们还需要向业界先进的科技企业学习，继续努力，深化提升、扩大推广DevOps实践，全力打造基于 DevOps 的网络运维支撑体系新生态。

**Q：****关于 DevOps 标准，您怎么看，对您企业带来了什么帮助？**

  

**李欣然：**我认为主要是在效率、质量和资源使用方面提供了很大帮助，能够帮助我们在有限的资源条件下创造出更大的价值。举个例子，原来我们的系统升级会有一个较长的时间窗口，需要大量的运维人员熬夜部署，效率很低，同时我们原有的业务系统是烟囱式黑盒开发部署模式，质量不可控，风险比较高，通过 DevOps 工具和平台我们实现了自动化开发部署流水线，提升了部署发布效率，通过自动化代码检查和自动化测试，提升了交付质量。另外，我们过去建设一个项目总要先规划出一些资源，这些资源基本上都会给这个项目使用，在项目初期业务量不大的情况下会存在较大的资源浪费。通过 DevOps 标准指导，我们现在可以做到容器化按需自动部署，合理利用计算资源，减少浪费，提升资源使用效率，在部署时间、部署质量和资源使用方面都带来了非常显著的提升。

 

**Q：****对于此次参评的项目，其IT系统有哪些特色，当时是怎么规划和设计的？**

  

**李欣然：**本次参评的集中性能管理系统是通过微服务解耦、容器化部署的 DevOps 最佳实践。北京移动网管系统基于“厚中台、薄应用”原则进行系统分层解耦，拉通底层数据底座，通过数据中台实现数据采集和分析共享，通过技术中台提供GIS、UIUE、AI等通用技术组件服务，通过业务中台发布O域微服务原子能力，如告警衍生和派单等能力，向重点通信保障和性能分析专题等上层应用提供能力化服务。

  

本次参评的 DevOps 平台是基于北京移动网管服务能力创建运营中心，集成了 DevOps 工具链、容器云管理平台、微服务管控平台、全面软件资产管理、能力开放平台相关功能，并进行了深度定制化，比如通过二次开发对Jenkins自动化流水线进行了可视化编辑和运行过程全监控，提供基于云原生架构的一站式软件全生命周期管理。

**Q：****此次通过评测的过程顺利吗？****遇到什么困难？****如何解决的？**

  

**李欣然：**本次评测的准备工作总体还是比较顺利的。在参与评估之前，已经着手进行网管服务能力创建运营中心的实践探索，参与评测的过程也是我们在 DevOps 持续交付部分7个能力子域的平台能力和管理能力持续优化改进的过程。我们根据北京移动自身的IT开发特点量身定做 DevOps 管理体系，并借鉴先进兄弟省份和互联网公司的实践方法，通过整个项目团队的不懈努力、深入研究、持续改进，最终通过 DevOps 成熟度评估。

 

**Q：****关于 DevOps 的发展前景，您怎么看？**

  

**李欣然：**信通院 DevOps 标准体系从大的方面来讲，代表了我国在软件方法论方面的研究成果，而且据我了解也已在联合国直属标准化组织  ITU-T成功立项，逐步成为IT行业的标杆，对于其他各个行业进行数字化转型会起到极大的帮助作用，同时，随着越来越多的公司着手进行 DevOps 实践，相信 DevOps 方法论本身也会不断自我迭代和演进。本次我们通过的仅是持续交付成熟度三级认证，后续我们还将对标先进企业，朝着更高的级别努力，同时还将在技术运营领域进行深入探索和实践，让我们的网络更敏捷、更智能，让我们的用户更信赖、更满意。

全球首个 DevOps 标准，即《研发运营一体化（DevOps）能力成熟度模型》，由中国信息通信研究院牵头，联合云计算开源产业联盟、高效运维社区、 DevOps 时代社区、 Google、BATJ、清华大学、南京大学、通信及金融等行业顶尖企事业单位专家共同制定。

  

目前，由中国信息通信研究院主导的DevOps 标准已在联合国直属标准化组织 ITU-T、中国通信标准化协会（CCSA）正式立项。

  

在此之前，通过中国信通院 DevOps 持续交付能力成熟度评估的企业包括：中国工商银行、中国银行、浙江移动、腾讯、招商银行、广东移动、北京移动、去哪儿网、郑州银行、神州泰岳等。
