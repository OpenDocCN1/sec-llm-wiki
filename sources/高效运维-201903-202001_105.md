**编者按****：**根据麦肯锡的一项研究结果，科技公司想要成功，关键所在无外乎两点：**标准化和工具赋能****。**标准本身是最佳实践的集合，有了标准，每一步都离目标更近（而不是偏离），将标准固化在工具里，让人做更有价值的事情。这和 DevOps 标准及 DevOps 持续交付流水线工具平台的核心理念和实践不谋而合。

 

2019 年 11 月 1 日，GOPS 全球运维大会在上海正式召开。GOPS全球运维大会至今已经举办了13届，是国内第一个也是最大的运维行业大会，也是备受瞩目的千人峰会，面向互联网及金融、通信等传统行业广大运维、开发等技术人员，传播先进技术思想和理念，分享业内最佳实践。

 

此次会议，除主会场外还分为AIOps 场景实践专场、AIOps 行业案例专场、DevOps标准企业案例专场、阿里巴巴专场等，名企专家近70个议题完整覆盖运维全技术领域。

  

特别值得关注的是，** 华泰证券追****风（ CRM 营销 ）项目****和 XTrader 项目顺利通过 De****vOps ****标准持续交付部分3****级评估，**获得由中国信息通信研究院（以下简称信通院）开展的《研发运营一体化（ DevOps ）能力成熟度模型》持续交付评估证书。**De****vOps ****标准**共分5级，持续交付部分如果能达到 3 级已经是国内领先水准，这代表着华泰证券在该系统的持续交付能力达到国内领先水平。

**\- Q&A -**

  

就此次华泰证券通过 **De****vOps ****标准持续交付部分3****级评估**的追风项目，高效运维社区采访到华泰证券客户财富研发中心架构师王可和效能提升专家、华泰证券 DevOps 平台产品经理李青，为我们分享项目评估和背后的故事。  

  

![](../Images/2d6930bd7cef8eb12c4239c0a991910b.png)

华泰证券客户财富研发中心架构师王可（左），华泰证券 DevOps 平台产品经理李青（右）

  

**Q：****两位老师好，首先恭喜此次追风项目顺利通过持续交付 3 级评估，下面请简单介绍一下此次参与评测的项目。**

  

**王可：**本次参评的项目代号叫追风，是我们公司 CRM 体系下一个非常重要的系统，负责提供客户营销相关的业务能力，例如：为我们的运营人员提供营销活动、营销工具的运营管理功能；向“涨乐财富通”等客户端提供营销活动等接口服务。

  

**Q：****恭喜您通过DevOps 标准评估，此次贵公司项目通过的是三级，表明达到了国内领先水平，请说一下您此时的感受。**  

**王可：** 首先非常高兴能够通过此次评级，这是对我们项目组以及公司 DevOps 平台过去工作的一次肯定。但是在参与评级的过程中，我们也发现了自身的一些不足，后续将持续改进。

  

**Q：****贵公司是如何决定加入 DevOps 标准评估工作中的？**

  

**李青：**华泰证券自 2016 年来就已着手推动敏捷转型，在项目运作过程中取得了不错的效果。在敏捷实践过程中，我们发现各个项目在持续构建和持续集成方面各自探索，从组织层面来说存在重复劳动的浪费，并且诸多实践上的不同会引发新的问题，比如度量标准的不统一、执行层面的不到位等。因此我们从 2017 年开始尝试通过 DevOps 进行组织级的流程和工具建设。然而自行摸索的过程中，始终缺乏明确的实践指导。直到我们遇到了 DevOps 标准，发现了一条新的道路。

  

**Q：****通过 DevOps 标准评估对贵团队意味着什么？**

**王可：**此次通过评级对我们的项目团队而言，是一次重要的激励。作为试点团队，项目在过去的一段时间里，在很多方面都是摸着石头过河，走过一些弯路，也遇到了不少挫折。通过这次评级，我们更加坚定了自己的目标，要做到“又快又好的交付价值”，DevOps 这条路是正确的，我们接下来不仅会继续保持，还会加快推进。

  

**Q：****关于 DevOps 标准，您怎么看，对您企业带来了什么帮助？**

  

**李青：**DevOps 是一个非常开放的理念，任何能够提升组织效能的动作、实践、文化都可以纳入这个范畴。这样做使得 DevOps 拥有旺盛的生命力，然而副作用是对初学者非常不友好。DevOps 标准最大的优点之一是能够一目了然的让初学者明确最佳实践的一些有效做法，帮助初学者尽快步入正轨。华泰证券正是在评估过程中，逐步对 DevOps 有了更加清晰透彻的认识，从而碰撞出更多平台功能、项目管理方面的火花，而进一步优化了组织效率。

  

  

**Q：****对于此次参评的项目，其IT系统有哪些特色，当时是怎么规划和设计的?**  

  

**王可：**我们的 IT 角色包括产品经理、Scrum Master、架构师、开发、测试和运维。我们这个项目组很早就开始推行 Scrum 敏捷开发过程，所以团队成员的角色职责，都是参考敏捷和精益方法，并结合我们项目组自身的实际情况来设计的。

  

**Q：****此次通过评测的过程顺利吗？****遇到什么困难？****如何解决的？**

**王可：**从项目层面看，总体来说还是相对比较顺利的，因为我们团队近几年来一直都在坚持推行敏捷，所以在变更管理、发布周期、自动化测试、度量反馈等等一些方面，已经有了一定的基础。但是在参评的过程中，我们还是在CI流水线、配置发布等方面遇到了一些挑战。比如早期我们搭建 CI 流水线的方式相对繁琐，不仅带来大量重复劳动，还容易出问题，后期我们通过调研和总结，摸索出了一套基于 Jenkins Shared Library 的标准化模板的方式，可以大大减轻流水线搭建的工作，并且成功推广至了我们公司大部分的项目。

  
**李青：**从组织层面看，我们借助本次评估，也针对配置管理、环境管理和度量体系建设等方面也进行了查漏补缺，大大完善了已有的管理体系。同时，我们也将标准内容直接应用在了 DevOps 平台的功能设计上，缩短了我们在平台功能上探索的时间。

  

**Q：****关于 DevOps 的发展前景，您怎么看？**

**王可：**我个人非常看好 DevOps 的前景。因为在这个“互联网+”时代，任何企业都在追求“更快更好的响应客户需求”。既要提高交付速度，又要提高交付质量，传统的流程与实践一定会遇到难以逾越的瓶颈，但是DevOps可以帮助企业打通开发、测试和运维之间的壁垒，从理念、流程到工具，为组织和项目提供改进的空间。所以我们也一定会继续推进 DevOps 的研究和落地。

  
**李青：**DevOps 已经发展了数年，如今在各现代行业巨头的身上，基本都能看见它的光环加成。各种报告数据也显示，它在组织建立高效能团队中能够提供巨大帮助。在这个 VUCA 的时代，金融行业受到互联网冲击，IT部门必须在时代冲击下找到自己的新方向。而快速、稳定、安全地交付软件，是技术转型和组织效能提升的关键。通过 DevOps，打造券商的金融科技基础核心竞争力，将是未来能够继续立足于行业前沿的关键。

  

同时高效运维社区也请到华泰证券交易技术研发中心架构师汪海林一起聊聊华泰证券 XTrader 项目的评估的心路历程。

  

![](../Images/ee47d7d29c3fc826a60a96175bb46b10.png)

华泰证券交易技术研发中心架构师汪海林（左），华泰证券 DevOps 平台产品经理李青（右）

  

**Q：****老师您好，首先恭喜此次 XTrader 项目顺利通过持续交付 3 级评估，下面也请两位老师介绍一下参与评测的项目。**

  

**汪海林：**大家好，我是汪海林。我本人任职于华泰证券信息技术部交易技术研发中心，从事交易技术研发中心架构师职位，负责交易系统的设计研发工作。交易技术研发中心负责华泰证券整个交易系统的建设，本次参与 DevOps 评测的 XTrader 项目即是中心自研的交易系统，通过全内存化的设计提供股票的极速交易，供公司自营部门交易使用。

  
**Q：****此次XTrader 项目通过的是三级，表明达到了国内领先水平，请说一下您此时的感受。**  

  

**汪海林：**能通过DevOps我是很开心的，这代表了我们的项目管理流程、研发流程、项目质量、发布管理、上线运维等各方面都已经达到了国内先进水平，同时，在评估过程中，得益于组织的支持，只有整个组织的过程实践达到了评估标准，项目才能达到评估标准。

  

当然在评估过程中，我们也有一些薄弱项以及一些更先进的做法，这也是我们后期需要改进成长的地方。

  
**Q：****通过 DevOps 标准评估对贵团队意味着什么？**

**汪海林**：首先，DevOps是一种文化，文化需要人员的传播，通过DevOps标准评估，意味着团队成员已经高度认可这种文化，而在整个研发交付过程中，对文化的认可也代表着对过程的遵循，在持续集成、持续交付、快速反馈等过程中会有更好的方法论来支撑，对整个软件的交付质量会有很好的提升。

  

**Q：****对于此次参评的项目，其IT系统有哪些特色，当时是怎么规划和设计的？**

**汪海林**：参与此次评测的XTrader系统，是核心交易系统，交易系统和其他的一些一般业务管理系统不同，在证券公司内部有最高的质量等级，在质量、性能、灾备、安全、运维等各方面都有更高的要求。  

  

在项目设计之初，我们对系统的设计、质量都是非常高标准要求，其次希望整个系统对需求的响应是迅速的，所以在公司进行DevOps文化活动实践时，我们交易中心全程参与，以使有更好的流程、工具、数据来度量项目的开发过程。

  

**Q：此次通过评测的过程顺利吗？遇到什么困难？如何解决的？**

**汪海林：**整个评测过程还是很顺利的，因为在部门最近几年大力推进敏捷、DevOps文化过程中，项目组一直在和部门的辅导团队进行合作，相应的研发过程、项目管理流程都已经很成熟了。  

  

**Q：****关于 DevOps 的发展前景，您怎么看？**  
  

**汪海林：**首先，DevOps关注持续集成、持续交付；支持高效交付、缩短开发周期；支持快速反馈、提升软件质量等特点决定了DevOps将出现在更多的行业领域。在当今瞬息万变、信息量巨大的时代，业务的灵活可靠高效是各企业追求的目标，随着DevOps相关概念和技术不断的深入发展，更多行业领域将能找到自己关注的特性。因此DevOps渗入到更多行业是必然趋势，各行业都可以通过DevOps获取技术改进对组织效能的积极影响。

全球首个 DevOps 标准，即《研发运营一体化（DevOps）能力成熟度模型》，由中国信息通信研究院牵头，联合云计算开源产业联盟、高效运维社区、 DevOps 时代社区、 Google、BATJ、清华大学、南京大学、通信及金融等行业顶尖企事业单位专家共同制定。

  

目前，由中国信息通信研究院主导的DevOps 标准已在联合国直属标准化组织 ITU-T、中国通信标准化协会（CCSA）正式立项。

  

在此之前，通过中国信通院 DevOps 持续交付能力成熟度评估的企业包括：中国工商银行、中国银行、浙江移动、腾讯、招商银行、广东移动、北京移动、去哪儿网、郑州银行、神州泰岳等。
