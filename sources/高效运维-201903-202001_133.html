2019年10月18日，由中国信息通信研究院指导，云计算开源产业联盟和开放运维联盟共同发起的企业级 DevOps 赋能（共促）计划二次企业交流会在北京成功举办。


此次与会成员主要来自赋能（共促）计划的参与单位：中国信通院、中国银行、中国工商银行、中国农业银行、招商银行、中信银行、中国电信、东方航空、百度、阿里巴巴、华泰证券、泰康保险、郑州银行、德邦快递、京东数科、中原消费金融、高效运维社区等企业。


企业级 DevOps 赋能（共促）计划二次研讨会在百度科技园顺利召开


本次交流围绕着“企业级 DevOps 平台建设研讨会”这一主题展开交流和讨论。为更好地促进中国企业实现组织级 DevOps 能力，打造一流的、端到端的 DevOps 持续交付流水线平台，提升组织效率与质量，贡献企业自身力量。

首先由中国信通院专家牛晓玲对“企业级 DevOps 赋能（共促）计划”的发起背景进行介绍，该项计划由信通院指导，云计算开源产业联盟和开放运维联盟共同发起，希望能给国内外企业创造更多交流经验的机会，收集优秀案例分享给众多的企业。▼

随后，由高效运维社区雷涛先生重点介绍了企业DevOps供应平台应如何建设，这也是大家在做DevOps转型的时候必须要做的一件事情，最开始企业可能会引入各种各样的供应链，逐渐会转向为各个工具链，工具链分散没有办法做全局的优化，并不好管理，因此会形成工具链的平台。故此次从企业切实需要出发，联合社区的专家形成工具平台的图，供企业参参考。▼

接下来，由百度效率云运营总监金锐先生带来演讲《工程能力永无止境的追求》，给大家分享了百度DevOps 的实践经验。▼

在会上分享重点主要是围绕百度DevOps的实践，以及程能力与DevOps的关系，并从百度软件工程发展、百度工程能力提升之道、对外标准化服务三个方面来着重介绍，为什么百度工程效率部的使命是对工程能力永无止境的追求。

在下午的会议中，由郑州银行技术测试人负责人刘婷，分享城商行核心业务系统的持续交付实践和背后的故事。大概介绍了该系统额项目管理用的开源工具，以及需求和常规的项目管理计划、管理人员、管理测试、管理这些功能，并且可以和很多开源工具做对接，少写公式等益处，并分享了系统的管理流程和部署。▼

在此次活动的互动交流环节，参会专家对关于 DevOps平台建设的提出问题并共同探讨，交流分享经验。

Q：百度公司对流水线定义标准是什么样的？比如说流水线代码构建、测试、部署这些是完成的流水线，我构建完之后不可能有分杈了，但凡分杈的多种测试。
金锐：构建代表代码提交一次，但是流水线触发一次构建之后再触发流水线在这我们没有做严格的限制流水线一定要包括哪些，取决于QA自己设计，有的QA来讲提交之后的流水线就到结果测试做完就行了，但是晚上会再跑又是全新的流水线，不是由代码提交去处理，而是定时处理，同时多个流水线一起处理，所以构建和流水线并不是矛盾的。
Q：很多企业它在设计流水线都会说能不能代码提交直接做到上线，到底怎么样去做？

雷涛：标准上要求你从代码提交到生产要做到这样一个能力，但是在实际的过程当中可以分阶段流水线，一般会建议分三条流水线：第一个提交阶段流水线代码提交就会做大量的检查验证打包，如果没有问题往后去触发。下一阶段叫构建，这个时候会做一些结果测试等等一些集成测试，这个阶段流水线通过之后由于流程管控的需要，可以在这个阶段做人工的卡点，是不是让他去做应急，我们做审批流程可能在后面有一个管理系统或者是项目管理的流程系统做审批，测试负责人或者开发负责人对第二条流水线点确认就会自动的触发第三条流水线。抛去流程管控的原因，基本上可以做到提交就上线，我们在评估的时候也是关注于这个点。

Q：郑州银行该系统的数据库的自动化部署是怎么做的？

刘婷：数据库采用的是商业软件，首先要考虑的是数据库的增量部署，已经部署过的要用清晰状态来标准，和版本是有关系，不同的时间窗口是不一样的，版本和状态要有规；，另外还有执行顺序，目前简单的做法就是在命名上会加12345这样的编号，比如说后面可能是一个文件加一个编号，下面是2点什么会代表不同的文件，不同的版本当中编号是有重复的，但是在同一个版本编号是不能重复的，这是基本的规律。不管是应用版本还是配置，全部是放在上面，一定有一个目录标志它的版本号。

Q：郑州银行该系统平台生产流水线怎么设计的？

刘婷：生产只用自动化部署就可以了，拿的是已经测试好的包，在生产不需要重新定义，重新定义会引入新的风险，然后给它做一个配置文件的替换，然后去做部署。但是这是对后端SQL是可行的，对于移动端是没有办法的，必须重新打包。
Q：郑州银行该系统配置文件是怎么设计的？

刘婷：比如说后面可以跟不同的环境，ABC会写三套配置，同一个文件会写ABC，我们自动化部署也是类似的，比如说PA你就会去选，我们自动化部署平台会选环境，每一套环境要准备一套完整的配置，把那个放到指定的目录下把原来的默认配置给替换掉。

“企业级 DevOps 赋能（共促）计划”的初衷即在于给企业更多交流的机会，促进参与企业 DevOps 能力的提升，通过别人的实践经验解决自己实践中遇到的问题。通过此次活动，参与的企业从中了解到更多的 DevOps 平台的经验，并且通过企业间深入的交流更加了解 DevOps 建设之路该怎样前进。
