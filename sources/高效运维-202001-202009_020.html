陆金所去 Oracle 实践开始于 2018 年年中，历时 18 个月，将全站 90% 的数据库、数千张表从 Oracle 无缝切换至 MySQL。


整个去O过程涉及大几百个子系统，总数据量超过 PB 级，去除的 Oracle 数据库覆盖基金、网贷、信托、资管、银行理财、证 券、保险、主账户等全金融场景，全程使用自动化平台管控和推荐去 Oracle 实践。


陆金所全部的研发和技术运营部门都参与了全站去 Oracle，至少有 500 人以上的开发、测试和运维工程师参与其中。


如果从整个实践过程来看，陆金所去 Oracle 实践有三个比较关键的阶段：

一是通过边缘系统进行方案验证阶段；

二是去”O“自动化工具平台构建和优化阶段；

三是全自动化标准化去”O“落地阶段。


在9月25-26日举办的GOPS全球运维大会·深圳站中，陆金所去 Oracle 实践负责人，陆金所数据库团队负责人王英杰老师将带来主题演讲为您详解幕后故事。


主题：陆金所如何在线更换金融核心场景 Oracle 数据库


简介：本次分享将介绍陆金所如何通过在线更换数据库的方案稳妥和高效的把全站数据库进行去Oracle改造。希望通过本次分享，能够让大家深入了解金融核心系统去Oracle的难点和风险，并给想去Oracle但是不敢落地实施的同学提供真正的实战案例解决思路


王英杰

陆金所数据库团队负责人。


讲师简介：主导和见证了陆金所数据库和大数据平台的建设和演进过程。2018年开始负责陆金所全站去O项目，通过上百次迭代和变更在不做服务降级的情况下，把陆金所所有金融场景数据库在线完成去Oracle化，并打造了一整套去O的方案和工具产品
