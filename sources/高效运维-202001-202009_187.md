# 燃！百信银行通过 DevOps 持续交付标准 3 级评估，相关项目能力达到国内领先水平！

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzA4Nzg5Nzc5OA==&mid=2651685359&idx=5&sn=b66b5ef854dc28cb11067e0198ed5341&chksm=8bcb4246bcbccb50989bda6f0ec3e0e6cd1bf197b5aa60949082cb42da37e3510b2aedb2147f&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzA4Nzg5Nzc5OA==&mid=2651685359&idx=5&sn=b66b5ef854dc28cb11067e0198ed5341&chksm=8bcb4246bcbccb50989bda6f0ec3e0e6cd1bf197b5aa60949082cb42da37e3510b2aedb2147f&scene=27#wechat_redirect)

![](../Images/c2e2259852da561246cb710dae69adcb.png)**编者按：**从各大企业的实践来看，标准化和工具赋能是科技公司成功的关键所在。DevOps 标准及基于标准的 DevOps 持续交付流水线平台，使得企业的软件研发效能飞速提升、更快更灵活应对市场变化，助力IT成为企业的核心竞争力之一。

由云计算开源产业联盟指导、高效运维社区和 DevOps 时代社区联合举办的 GNSEC 2020 全球新一代软件工程线上峰会于 2020 年 6 月 19 日举行，本次峰会线上参会人员超过3000人。峰会专注于全方位的软件工程和技术，致力于定义新一代的软件工程，旨在聚集软件工程行业的专家、学者、从业者，讲述重要的最新研究成果，并分享最前端的实践经验，同时促进产、学、研领域的专家互相交流与合作。

大会隆重发布了 DevOps 标准持续交付部分第七批评估结果。本次发布的参评企业除了百信银行之外，还包括中国农业银行（5个项目）、交行卡中心、浦发总行、招商银行（3个项目）、中国人民保险和泰康保险等。          

百信银行（中信百信银行股份有限公司）本次参评项目为天策信贷中台项目，该项目顺利通过由中国信息通信研究院（以下简称信通院）开展的《研发运营一体化（ DevOps ）能力成熟度模型》持续交付部分 3 级评估。DevOps 标准共分5级，持续交付部分如果能达到 3 级已经是国内领先水准，这代表着百信银行在参评项目的持续交付能力达到国内领先水平。 

此外，百信银行通过 DevOps 标准持续交付部分评估 2 级的项目有：

*   支付前置系统项目
*   客诉系统项目
*   收单项目
*   事件管理平台项目

此次，我们采访了百信银行科技产品部负责人周北春先生，一起深聊百信银行天策信贷中台项目参与评估的细节和幕后团队的故事，分享百信银行 DevOps 实践的经验。![](../Images/eb664b1b6429b5e1b26ec579da2d8bb2.png)

百信银行科技产品部负责人周北春先生

**\-Q&A-****Q：您好，请介绍一下您和您的企业，以及此次参与评估的 5 个项目。****周：**百信银行是由国务院特批、银保监会主导成立的国内首家独立法人直销银行。2017 年由中信银行和百度联合发起设立，通过融合“金融+互联网”基因，探索金融科技与未来银行发展新路径，承载着中国银行业转型发展试验田的使命。在开展金融业务的过程中，百信银行注重科技投入，科技人员占比达到 63%，积极探索互联网、大数据、人工智能等先进技术，累计提交专利申请 70 项，积累了大量的金融科技解决方案，凭借自身在架构、技术领域的先进性，开业一年即获得国家高新技术企业认定。截止 2019 年末，百信银行服务用户数超 3200 万，营业净收入 23.73 亿元，净利润 0.20 亿元，百信银行金融科技创新能力初步得到市场的认可。百信银行本次提交包括“天策信贷中台”、“客诉系统”、“收单系统”、“支付前置”和“事件管理平台”这 5 个项目参加评估。“天策信贷中台”包含客户管理、订单中心、借据管理、代偿代扣、对公管理、合规文件管理、对账文件处理、资金路由等模块，为信贷业务提供中台能力。“客诉系统”是百信银行用于处理用户对百信银行产品及服务投诉的平台，包含工单创建，工单跟踪，统计分析，智能判断等模块。“收单系统”旨在对收单商户的百信账户进行资金管控，解决信息流二清问题，实现一清解决方案。功能输出上，提供进件、下单、结算、提现、分润、对账清算、报表账单等功能。“支付前置”是统一资金处理系统，能够通过配置实现业务系统快速接入，目前提供代扣、代付、行内转账、行内账户资金冻结、解冻和交易对账等功能。“事件管理平台”是监控报警事件的统一管理平台。主要功能包括：统一展示 ZBX、LOG、AIM 告警、事件管理、告警汇聚、告警升级、告警屏蔽、根源分析、故障处置等。

**Q：恭喜您通过 DevOps 标准评估，此次贵公司的天策信贷中台项目通过的是持续交付 3 级，您有什么感****受**？

周：首先很感谢信通院对我们的指导和帮助。全行全面使用 DevOps 是我行 2019 年科技建设重点工作，而参加 DevOps 评估，正是寄希望于能够打造 DevOps 成功实践，树立典型，有效推动全行推广工作。评估开始之初，我行的 DevOps 平台正处于更新换代阶段，能否通过评估是对我行 DevOps 发展目标与成果的一次有效检验。本次项目能够顺利通过评估，一方面要感谢我们参评项目团队、工具研发团队的付出，另一方面也证明了我行对于 DevOps 的当前实践是有效的，进一步验证了我行对其未来规划方向的正确性。于此同时，通过本次评估也让我们接触到业界的主流实践经验，从而认清自身的差距与短板，为以后我行的 DevOps 体系持续优化，提供了方向性的指引。

  

**Q：作为金融行业头部，贵公司是如何决定加入 DevOps 标准评估工作中的？**

**周：**百信银行作为一家互联网银行，既有传统商业银行的金融业务血脉，也有互联网企业追求效率的基因，在筹建之初，就确定了百信银行必须全局敏捷的战略，DevOps 作为全球领先的敏捷工具体系成为我行的第一选择。自17年开始规划 DevOps 工具体系至今，我行始终以 DevOps 理念为指引，以自行设计和自研为主，从我行管理和交付需求出发。在经过两年多的建设后，我行认为需要引入外部机构和行业标准，从而接触到业界的主流实践和建设成果，对我行的建设成果做一个准确的评估，避免出现闭门造车的问题，因此决定加入 DevOps 标准评估工作。

  

**Q：通过 DevOps 标准评估对您企业带来了什么帮助？对贵团队有哪些影响？**

**周：**一个成体系的标准对于一个自行摸索建立的 DevOps 工具体系来说，其指导意义和借鉴价值不言而喻，在准备 DevOps 标准评估过程中，工具研发团队深入学习了标准文档和模拟评估报告，将对标准的理解与专家意见进行分解，逐项落地，这个过程中我行进一步打通了交付流水线，实现了端到端的数据关联，测试环境的自动化供给，提高了研发效率，并且发现了当前规划的不足和隐患。在团队建设上，我行专门成立了一个跨部门的虚拟团队来参与本次评估，在参与评估过程之中，各部门团队携手攻克了一个又一个的难题，团队成员们除了巩固加强了在自身擅长领域的专业性，也对其他领域有了更加深刻的认知，从而进一步强化了我行的组织协同性。如今参与本次评估的成员现在都已成为各部门的核心骨干，成为我行未来进一步培养与扩大 DevOps 团队的坚实基础。

  

**Q：请问您可否详细的介绍一下，通过本次评估有哪些数据指标可以直观的体现项目改进成果？****周：**持续的 DevOps 建设和推广给我行带来一定的提升。其中比较直观的改进就是研发交付周期变短，全行平均需求前置时间，下降幅度超过 73.4%；实现了任何代码提交即自动触发构建流程；通过将质量内建融入流水线，交付质量有所提升，缺陷逃逸率降低了 30%。发布频率加快，投产效能他提升，发布功能服务化供给给开发人员，月均实现 1400+ 次发布，全行发版效能提升 84.3%。![](../Images/12cf80f44c16ce55a7de5a420ca2fdc7.png)

**Q： 对于此次达到3级的项目，其IT系统有哪些特色，当时是怎么规划和设计的？**

**周：**本次通过3级评估的“天策信贷中台”项目，是我行对消费信贷和个人经营贷业务产品系统的重构，该项目目的在于实现主流信贷业务产品的“无码编程”上线、形成支持 1-2 周接入一家流量方的能力，同时业务处理性能和容量可弹性扩展，有效支撑未来业务发展。我行普惠信贷业务刚起步时，使用了单一产品逻辑下的代码和对接标准，尽管在当时看来可直接降低了开发成本、加速了上线流程，是比较成功的设计，但随着业务场景不断丰富，合作伙伴不断增加，我们发现这套这套标准并不适用于所有的B端业务伙伴，在与其他合作方合作上线产品时，普遍需要 6-8 周的代码开发和流程调整的工作量。而随着业务规模的不断扩大，对于产品快速上线能力的需求与日俱增。为了统一标准，适配定制化需求，我行决定用模块化、配置化的方式加速上线开发，天策信贷中台就是基于此痛点来设计开发的，而通过实践证明，这与 DevOps 标准三级的要求高度吻合。

  

**Q：此次通过评估的过程顺利吗？遇到什么困难？如何解决的？**

**周：**对于我们最大的挑战在于日常主线工作和 DevOps 两者的平衡上，在参加 DevOps 评估的过程中，参与人员基本上都是身兼数职。一方面要保证自己的主线工作可以顺利进展，一方面做 DevOps 工具优化，落地改进等工作。因此对于每一个参与其中的团队成员而言，都是一次艰难的考验。但与此同时，大家也都很清楚这是一次难得的锻炼与提升自我能力的机会，因此，每一名参与评估的同事都在通过努力提高工作效率，压缩出 DevOps 工作时间等方式来提高单个人力资源价值，最终顺利完成整个评估。

  

**Q： 一次性参评 5 个项目，是出于怎样的考虑 ？**

**周：**由于百信银行秉承银行金融科技试验田的使命，因此在成立之初就针对科技管理上创新地使用了双线制管理，既设立负责公共基础技术能力建设的IT部门，专注高效的强化IT基本能力，也在业务部门设立负责产品创新的专业 IT 团队，快速响应市场变化。此次参评目的，一方面在于检验我行自建 DevOps 工具体系的成熟度，一方面在于准确评估 DevOps 的全行使用情况，为此我行从各个部门挑选具有代表性的项目，通过一个项目的情况能够一定程度上体现该部门的 DevOps 使用情况，从而判断是否实现了全行全面使用 DevOps 这个目标。

  

**Q：对于 DevOps 今年的实施，您觉得最大的收获是什么？您的下一步计划是？**

**周：**我行本次参加 DevOps 标准评估的5个项目，一个达到 3 级水平，四个达到 2 级水平。从整体结果来看，我行的全面级敏捷战略已取得初步成效，但距离全行3级这样的目标还存在一定的差距。因此在 2020 年的科技规划中，我行将继续优化 DevOps 工具体系，坚定加强全行 DevOps 使用的推广。

  

**Q：对于 DevOps 的发展前景，您怎么看？**

**周：**当前整个社会都在关注企业的数字化转型，尤其是传统企业，其中有外部竞争环境的日益加剧，传统行业的传统模式越来越多受到来自互联网等企业的挑战。而金融业作为与 IT 行业一直保持紧密联系的行业，也在进一步加强自身的数字化能力。我行使用 DevOps 支撑了全行敏捷研发，实现了月均 1400+次的发布，切实提升了研发效能，而在高频发布产品，快速响应市场等方面也表现出了积极的作用，通过实践可知 DevOps 在提升企业整体研发效能方面是非常值得使用和推广的。但另一方面我们也应看到对于某些企业而言，落地 DevOps 目前还是存在一定的困难。DevOps 整个的工具链比较长，涉及到的技术相对比复杂，很多企业没有这个技术能力完成整个链条的整合和落地。总体而言，我们相信随着 DevOps 理念的进一步推广，接受的公司将会逐步增加，DevOps 将成为市场主流，推动企业效率的进一步提高。
