# 燃！宝信软件通过 DevOps 持续交付标准 3 级评估，相关项目能力达到国内领先水平！

**编者按：**从各大企业的实践来看，标准化和工具赋能是科技公司成功的关键所在。DevOps 标准及基于标准的 DevOps 持续交付流水线平台，使得企业的软件研发效能飞速提升、更快更灵活应对市场变化，助力IT成为企业的核心竞争力之一。  

由云计算开源产业联盟指导、高效运维社区和 DevOps 时代社区联合举办的 GNSEC 2020 全球新一代软件工程线上峰会于 2020 年 6 月 19 日举行，本次峰会线上参会人员超过 3000人。峰会专注于全方位的软件工程和技术，致力于定义新一代的软件工程，旨在聚集软件工程行业的专家、学者、从业者，讲述重要的最新研究成果，并分享最前端的实践经验，同时促进产、学、研领域的专家互相交流与合作。

  

大会隆重发布了 DevOps 标准持续交付部分第七批评估结果。本次发布的参评企业除了宝信软件之外，还包括中国农业银行（5个项目）、交行卡中心、浦发总行、招商银行（3个项目）、中国人民保险和泰康保险等。

  

宝信软件（上海宝信软件股份有限公司）本次参评项目为宝武产业链生态圈数据协同运营平台。该项目顺利通过由中国信息通信研究院（以下简称信通院）开展的《研发运营一体化（ DevOps ）能力成熟度模型》持续交付部分 3 级评估。DevOps 标准共分 5 级，持续交付部分如果能达到 3 级已经是国内领先水准，这代表着宝信软件在参评项目的持续交付能力达到国内领先水平。

  

**评测单位：中国信息通信研究院****中国信息通信研究院云计算与大数据研究所所长何宝宏博士公布宝信软件评估结果：**![](../Images/5e8aa96839117c90be24cdca1375628f.png)  

此次，我们采访了宝信软件工业互联网研究院/大数据中心副院长胡兵先生，一起深聊宝信软件宝武产业链生态圈数据协同运营平台项目参与评估的细节和幕后团队的故事，分享宝信软件 DevOps 实践的经验。  

  

**\-Q&A-**![](../Images/1c6eb201be33be3c4a1ad6195d1b843d.png)宝信软件工业互联网研究院/大数据中心副院长胡兵  
  
**Q:  您好，请介绍一下您和您的企业，以及此次参与评估的项目。**  
**胡: ** 宝信软件是中国宝武实际控制、宝钢股份控股的上市软件企业。致力于推动信息化与工业化深度融合、支撑中国制造企业发展方式转变、提升城市智能化水平。近年来，公司顺应IT产业和技术的发展趋势，借助商业模式创新，全面提供工业互联网、云计算、数据中心（IDC）、大数据、智能装备等相关产品和服务，努力成为贯彻推动“工业 4.0”与“中国制造 2025”战略的行业领军企业，成为智慧城市建设与创新的中坚力量。  

本次参与评估的项目是中国宝武生态技术平台（ePlat），为支撑中国宝武智慧钢铁生态圈战略转型，实现开放共享、连接协同、智慧敏捷、创新迭代的平台能力，赋能钢铁生态圈建设，驱动宝武数智化转型。对内打破业务孤岛、融合数据竖井、实现互联互通的数字化运营，对外实现平台化、专业化、服务化的多元化生态，支撑高质量钢铁生态圈的快速发展。而 DevOps 敏态交付的能力，正是支撑钢铁生态圈的重要基础设施之一。

  
**Q:   恭喜您通过 DevOps 标准评估，此次贵公司项目通过的是持续交付 3 级，表明达到了国内领先水平，请说一下您此时的感受。****胡:  **谢谢！很开心，团队共同的目标得以实现，这也是对我们工作的认可。拿到证书的同时，更重要的是通过这个评级过程将标准理解透彻，形成适合我们团队的标准规范，并内化到工具中去，沉淀下来，同时也为将来其他项目组的 DevOps 推广打下良好基础。  
****Q:  ******作为一家工业软件企业，****贵公司是如何决定加入 DevOps 标准评估工作中的？****胡: **业务交付过程涉及到技术架构、流程、组织架构，像我们这样的企业应用，肯定会有很多个性化需求，很难用普适的产品来应对，于是决定在开源的基础上集成、自研。好在我们在技术架构、技术栈方面已经统一，大部分的项目应用都是基于自研开发框架iPlat4j开发的，如何开发一个页面，开发一个微服务，以及更改一项配置，做法和流程是统一的，也就是说已经做到了标准化，我们只是进一步强化了执行标准，并做了自动化。早在2016年的时候，随着微服务架构开始广泛应用，我们的团队尝试封装部署的执行脚本，做了一个简易的自动化部署系统。但随后的很长一段时间，都有些找不到方向。直到2018年开始接触一些在线的相对成熟的 DevOps 产品，尤其是接触到了《研发运营一体化（DevOps）能力成熟度模型》，还参加了一次关于 DevOps 工具标准的讨论，见识了很多互联网大厂在这方面的优秀实践，感觉是叩开了一扇大门走入了一个新的世界。既然有了标准，参与标准评估、“以评促建”显然是加深标准理解和实践落地最高效的途径。  
****Q:  ** 通过 DevOps 标准评估对您企业带来了什么帮助？对贵团队有哪些影响？****胡:  **我们有了方向，知道要做什么，做到什么程度，边界在哪里。首先整个过程锻炼了团队，参与配置管理、持续集成、环境管理、测试、度量等各领域的同学，通过一轮又一轮的找差距和改进，都不同程度加深了对标准的理解，开发团队的深度参与，让大家更能理解 DevOps 实施过程中一些规范形成及技术手段设限的前因后果，知其然且知其所以然。其次逐步在各个环节摸索适合我们的流程规范，并通过工具沉淀下来，为在其他团队的经验复制提供便利。有了这次过级形成的经验和工具平台作为起点，随着推广范围的扩大，应用场景的深度和广度都会进一步提升，团队应对的能力和工具的适配程度都势必会得到加强，从而可以最终提高组织级端对端的业务交付能力。  
****Q:  **请问您可否详细的介绍一下，通过本次评估有哪些数据指标可以直观的体现项目改进成果？****胡:  **原本半年一个版本的交付频率，现在平均每个应用的交付频率达到 4.87 次／月，自动化接口测试覆盖率达到 100%。单元测试行覆盖率达到 85% 以上，有了各种质量门禁的控制，自动化部署成功率达到97%。                  
******Q:  ****此次通过评估的过程中遇到哪些困难？如何解决的？******胡:  ****要让各方都转变一些既有想法，相信 DevOps 的理念及实践效果，从而改变原有的工作方式来提高效率。比如上线审批不用再经过冗长的审批流程，花很长的时间准备一堆的证明文档来证明升级是可靠的，换来半年更新一个版本，而是大胆地提高交付频率，因为系统有各个环节的质量保证，准备了完备的试错机制，让系统在升级出现问题的时候可以安全快速地回退，而不会对在线业务造成负面影响。当然这个过程不能一蹴而就，让大家接受新的理念需要一个过程，机制和工具的完善也需要时间的打磨。

  

******Q:  ****对于 DevOps 今年的实施，下一步计划是什么？ ******胡:  ****对各种实践进行深度探索，俗话说“见过猪跑，也吃过猪肉了”，遇到问题，知道有哪些方式解决方案，可以应对到什么程度，做到心中有数。过级的过程中，对照标准深刻认识到差距，在涉及到的几乎每个环节，都有我们想完善的或大或小的点，DevOps 涵盖的范围广，分支多，我们会根据 DevOps 推广应用的范围和优先级，来逐步完善整个体系和工具平台。在交付模式上，有同时支持敏态业务和稳态业务的需求，并且研究院内产品平台研发类的项目占比较高，也就是一个产品需要同时部署应用在多个项目上，将交付过程天然地分为一次研发和多次部署两段，如何更好地适配这一场景的需求，我们也还有很多事情要做。               
******Q:  **** 对于 DevOps 的发展前景，您怎么看？******胡:  ****DevOps的范畴囊括了一切对开发过程有利的实践，这个定位是非常开放包容的，足以让 DevOps 保持强大的生命力。目前整个 DevOps 的生态体系也发展得很不错，在 DevOps 标准框架下，各家企业频繁交流，在获取营养努力成长后，也会形成自己的一些最佳实践，贡献出来形成反哺，从而促进整个生态进一步良性循环。

**研发运营一体化（DevOps）能力成熟度模型介绍：**

  

全球首个 DevOps 标准，即《研发运营一体化（DevOps）能力成熟度模型》，由中国信息通信研究院牵头，联合云计算开源产业联盟、高效运维社区、 DevOps 时代社区、 Google、BATJ、清华大学、南京大学、通信及金融等行业顶尖企事业单位专家共同制定。

  

目前，由中国信息通信研究院主导的DevOps标准已在联合国直属标准化组织 ITU-T、中国通信标准化协会（CCSA）正式立项。DevOps 标准评估体系主要包括敏捷开发管理、持续交付、技术运营、应用设计、安全及风险管理、系统和工具等部分的评估。            ![](../Images/ab7b39193c42e4efedbb04b7f21ba1bc.png)![](../Images/15d75e1bb1b481715fe0d19f497b00fe.png)![](../Images/b1cba068d9a426a7f566eab65b7c45a2.png)             **DevOps 标准评估相关事宜，请联系：**
