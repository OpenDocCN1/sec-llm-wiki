# 燃！浦发银行通过 DevOps 持续交付标准 3 级评估，相关项目能力达到国内领先水平！

**编者按：**从各大企业的实践来看，标准化和工具赋能是科技公司成功的关键所在。DevOps 标准及基于标准的 DevOps 持续交付流水线平台，使得企业的软件研发效能飞速提升、更快更灵活应对市场变化，助力IT成为企业的核心竞争力之一。

  

由云计算开源产业联盟指导、高效运维社区和 DevOps 时代社区联合举办的 GNSEC 2020 全球新一代软件工程线上峰会于 2020 年 6 月 19 日举行，本次峰会线上参会人员超过3000人。峰会专注于全方位的软件工程和技术，致力于定义新一代的软件工程，旨在聚集软件工程行业的专家、学者、从业者，讲述重要的最新研究成果，并分享最前端的实践经验，同时促进产、学、研领域的专家互相交流与合作。

  

大会隆重发布了 DevOps 标准持续交付部分第七批评估结果。本次发布的参评企业除了浦发银行之外，还包括中国农业银行（5个项目）、交行卡中心、招商银行（3个项目）、中国人民保险和泰康保险等。

  

浦发银行（上海浦东发展银行股份有限公司）本次参评项目为新型互联网贷款产品系统。该项目顺利通过由中国信息通信研究院（以下简称信通院）开展的《研发运营一体化（ DevOps ）能力成熟度模型》持续交付部分 3 级评估。DevOps 标准共分 5 级，持续交付部分如果能达到 3 级已经是国内领先水准，这代表着浦发银行在参评项目的持续交付能力达到国内领先水平。

**Q：浦发银行作为全国第三家通过持续交付 3 级标准评估的股份制银行，您能否谈谈对评估过程及通过评估的感受。**

**万：**很高兴浦发银行能够参加中国通信研究院牵头组织的 DevOps 研发运营一体化能力成熟度模型持续交付部分的评估，我们的项目达到 3 级的水平，这是对浦发银行从传统研发模式向 DevOps 高效研发模式转型过程的肯定。 在转型过程中，通过打造 DevOps 研发能力，打造敏捷的开发模式，在持续交付方面取得明显的改进成果，规范研发过程，加强质量管控，提高自动化的能力。这是一个开始， DevOps 优化是整个云转型工程的核心主线和灵魂。云用的好不好，取决于 DevOps 能力好不好，特别是规模化 DevOps 能力好不好。本次评估，给浦发银行全面组织级 DevOps 持续优化开了一个好头。我们会坚持不懈的走下去。

 

**Q：浦发当初是如何决定加入到评估工作中来的？**

**万：**2019 年初启动 DevOps 转型规划，在规划初期，与具有 DevOps 转型成功经验的企业，以及做 DevOps 赋能企业展开充分的交流。在交流的过程中，我们了解到中国信息通信研究院牵头发布的 DevOps 标准，内容做的严谨，在对于标准不断地学习之后，我们理解 DevOps 标准对于 DevOps 转型有一个比较好的针对性的指导作用。 

另外，浦发总行信息科技部的人员规模在 2800 人左右，接下来的 2-3 年我们会迅速扩招到 5000-10000 人规模级研发和 IT 队伍，这是我们实现数字化转型的重要资源保障。 

我们希望将来借助于组织级敏捷及 DevOps 体系建设，加快我们人才成长的速度，缩短培养周期，使得新进人员通过敏捷团队快速得到能力提升，同时一开始就有新的敏捷文化思维来作为后续研发的团队文化。

主要基于以上两点，我们果断的加入了 DevOps 标准评估的工作中来，希望通过标准评估加快浦发敏捷研发体系的建设。

  

**Q：对于在 2019-2020 年实施 DevOps 的过程中最大收获是什么？下一步的计划有哪些？ **

**万：**通过参与评估的过程，首先从文化观念上，对整体研发敏捷体系有非常大的触动，这是非常重要的一点。第二，通过建立体系化的过程，了解了 DevOps 落地的具体标准和要求，为后续实践提供了标准化的指导，从单个系统、多个系统到规模级系统，我们积累了一些经验，包括把系统之间持续地形成统一的流程，以及打通开发、测试、运维的工具的建立，形成标准。另外，通过改进，我们相关能力有明显提升，有涉及到单个项目的，也有涉及到规模级的过程，从能力的角度讲，既有一定的共性也有一定个性。 第三，我们小组成员通过深度参与评估，对个人定位有更深入的领悟，团队协同工作的能力得到进一步提升。下一步我们会整理归纳一些过程，固化已有成果，把模式快速推广到更多的系统中去，来形成我们面向互联网、面向敏捷，能够持续改进的 DevOps 体系。通过 3 级是我们的起点，后续我们会练好内功，进一步构建规模化、组织级的敏捷工具平台，这样才能使整个研发效率、质量和交付价值得到有机的统一。

**Q：浦发此次参与评估的项目是新型互联网贷款产品系统，请您介绍一下项目以及参评的原因。**

**吕：**参与评估的项目来自是浦发开发服务中心成都分中心，成立两年多的时间，二百多人的规模。除了成都之外，浦发还有上海市本部、成都、武汉、西安、合肥分中心，研发团队对于 DevOps 的研发体系、理念都有非常高的学习热情，接下来的两个推广项目，也将基于成都分中心来开展。此次参评的新型互联网贷款原品系统，是我行的一个分布式的贷款批量处理系统，包含了业务记帐、贷款核算、还款核算、余额核算、计提核算等等功能。 这个项目是我们跟蚂蚁金服合作的一个重要项目，选择此项目参加本次评估，主要是考虑到以下几点： 

第一，这个项目组一共有 25 个人，都是我行自研开发人员，其中以入行两三年的年轻员工居多，大家对这种新的研发模式兴趣和接受度都比较高、比较热情。

第二，我们想通过这个项目的评估来提升整体人员对 DevOps 的熟悉程度和技能。此次通过评估花费了 5 个月的时间，在此期间参与项目的每一个人对于 DevOps 整体研发体系，有了较为深入的理解，从而更加有序、高效地开展了我们的研发工作，大家收益颇深，进步很大。

第三，通过此项目培养的人员即将成为火种，“星星之火，可以燎原”，我们想带动整体的研发项目往 DevOps 研发体系上做转移，这些人员今后也会参与到其他项目中去，把 DevOps 的理念、方法，在其他项目中落地执行。

 

**Q：在本次的贯标过程中，您遇到了哪些让您印象深刻的困难和挑战？**

**吕：**大约是在 2018 年 12月份开始，我们一起探讨 DevOps ，研究技术方向，到2019年，把这个事情作为实际的工作任务开展起来了，参与评估共计 5 个月的时间，在一些方面遇到了困难，也想到了相应解决办法：第一，人员技能的培养，是非常关键的。为了解决人员技能问题，我们从上海调配人员，以及 DevOps 的教练前往成都帮助项目组的人做培训，包括 DevOps 的方法论，同时也安排了架构师搭建了 DevOps 整个流水线。第二，在自动化测试方面，我们遇到一些难点，最终我们把难点克服了，在过程中，我们也深入理解了自动化测试对于提升整体研发效率、研发质量的重要性，前期包括测试案例、测试数据等准备工作，相对来讲比较复杂、繁琐，但通过一系列准备，后续的测试整体效率有了非常大的提升。 第三，关于 DevOps 的度量。流水线上线之后，如何衡量研发效率是否得到提升，提升了多少，研发质量是否得到了提升，质量提升了多少，很多情况都是要通过度量指标来体现。这个在我们以前的研发工作当中，应用较少。此次我们建立了一套信通院的评估标准，DevOps 的度量体系，从项目里面得到了试点，并且上升到组织级，是我们很大的收获。

 

**Q：对于评估中“新增代码的单位测试覆盖率得要大于 80%”等要求，您在去推进单元测试覆盖率的时候，有没有什么困难？ 是如何解决的？**

**吕：**首先按照传统的模式进行的话：先开发，开发完了再做测试。但是很多问题的发现，依赖于后续的 XIT 和 UAT 的测试，这两个测试占用的时间相对来讲是比较长的。但是通过这个测试左移，我们加强了单元测试之后，虽然看下来我们整体上从开发里程碑的角度来看，时间是略有加长的，但是从整体的交付时间来看，我们是缩短的。对于团队人员的疑问，我曾经这样讲：如果说质量提升不了，那么在后续 UAT 的整个测试阶段，反攻率就会增加很多，对于个人的工作量不但没有减少，反而增加，要在前面发现问题。另外，有些要依靠测试人员和业务人员的UAT测试，发现缺陷的概率会有一些值得探讨的地方。相比出现生产问题要承担相应的责任，提前发现和解决是更好的办法。 

由于我们是全行第一个 DevOps 的实践团队，同时我们的队伍非常年轻化，没有历史包袱，接受新鲜理念和事物的能力都比较强，所以我们在没有任何经验的情况下，要去体验、体会、经历的阶段。在工作中，会有一些内容我们当时不理解，但经过一段时间的迭代运作，慢慢就会理解标准是这样设置的原因了。 

   

**Q：您认为，DevOps 与其他标准有什么不同？** 

**吕：**在 2018 年，我们做了CMMI 3级的评估。在2019年，我们整体通过了ISO 20000 的服务管理评估，这两项工作我也都参与其中。此次通过信通院的 DevOps 研发运营一体化成熟度模型持续交付 3 级评估，给我印象最深的地方就是理论和实践的结合，而且是一种非常完美的结合。首先从整体 7 大项，总共 49 个能力项的指标来看的话，既包含方法论，也可以指导相应所得方案如何去开展 DevOps 实践的工作。在评估过程中，评判是否达到了标准，不仅是看文档，也有很多演示的环节，包括自动化的构建、测试、部署及度量。这就要求项目扎扎实实地去落地、执行，而且要有一定的周期、多次的迭代。没有这些过程的话，要想通过评估几乎是不可能的。

  

**Q：此次 3 级的贯标，对于团队和公司有什么样的意义？**

**吕：**能通过 3 级的评估，第一感到非常的荣幸，非常的自豪；第二，实际上我们觉得真正从中得到了很多的收益和启发，包括我们经历的改进点、问题点，都是之后进一步推广的宝贵知识财富。我们整体的研发体系，是向着 DevOps 研发运营一体化的体系去做转型的，此番通过评估不仅仅是为了通过 3 级的评估，或者说尝试新鲜的事物之后浅尝即止。在未来我们会把 DevOps 做为研发转型的方向，通过试点，熟悉体系，接下来我们还有很多的工作要做。比如说：第一，要对全员的 DevOps 技能推出培养方案。第二，我们流水线的平台，接下来要进一步地去做完善。第三，准备在全行的研发当中，推广 DevOps 体系，准备用三年的时间完成将近 200 多个系统  DevOps 体系建设的工作。总而言之，此次评估只是一个起点，接下来我们有大量的工作要做。比如整体的技能培养、体系的建设、整个流水线平台的建设、整体推广的计划推进。这些工作的话，我们都希望今后能一如既往地得到信通院和高效运维社区的帮助和支持。

**研发运营一体化（DevOps）能力成熟度模型介绍：**

  

全球首个 DevOps 标准，即《研发运营一体化（DevOps）能力成熟度模型》，由中国信息通信研究院牵头，联合云计算开源产业联盟、高效运维社区、 DevOps 时代社区、 Google、BATJ、清华大学、南京大学、通信及金融等行业顶尖企事业单位专家共同制定。

  

目前，由中国信息通信研究院主导的DevOps标准已在联合国直属标准化组织 ITU-T、中国通信标准化协会（CCSA）正式立项。DevOps 标准评估体系主要包括敏捷开发管理、持续交付、技术运营、应用设计、安全及风险管理、系统和工具等部分的评估。
