重磅！浦发银行多个项目通过 DevOps 持续交付标准 3 级评估，相关项目能力达到国内领先水平！

编者按：从各大企业的实践来看，标准化和工具赋能是科技公司成功的关键所在。DevOps 标准及基于标准的 DevOps 持续交付流水线平台，使得企业的软件研发效能飞速提升、更快更灵活应对市场变化，助力IT成为企业的核心竞争力之一。

2021 年 3 月 25 日，由中国信息通信研究院指导，云计算开源产业联盟和开放运维联盟共同发起的企业级 DevOps 赋能（共促）计划第五次专题活动——“DevOps体系护航企业数字化转型”成功于线上举办！

会上，中国信息通信研究院隆重发布了 DevOps 标准持续交付第十一批评估结果。上海浦东发展银行股份有限公司（以下简称“浦发银行”）本次参评的 4 个项目均顺利通过由中国信息通信研究院（以下简称信通院）开展的《研发运营一体化（DevOps）能力成熟度模型》持续交付 3 级评估。DevOps标准共分 5 级，持续交付部分如果能达到 3 级已经是国内领先水准，这代表着浦发银行在参评项目的持续交付能力达到国内领先水平。至此，浦发银行已有 5 个项目通过持续交付标准 3 级评估。
此前，浦发银行的新型互联网贷款产品系统项目通过持续交付 3 级评估（相关新闻稿链接详见文末）。
浦发银行本次通过 DevOps 标准持续交付 3 级评估的项目，分别是：

  • 企业级微服务平台项目

  • 现金流分析管理系统项目
  • 资金监管业务系统项目
  • 金融 IC 卡业务系统_ICS 项目

评测单位：中国信息通信研究院

浦发银行本次参评的 4 个项目均顺利通过了中国信息通信研究院开展的《研发运营一体化（ DevOps ）能力成熟度模型》持续交付 3 级评估，这是对浦发银行 DevOps 实践推广从试点阶段到规模化推广过程的肯定。

4 个项目分别来自云转型团队和开发服务中心成都分中心。云转型团队于 2019 年成立，近 200 人的规模；成都研发分中心成立三年左右，800人的规模。本次参评系统分别为企业级微服务平台、现金流分析管理系统、资金监管业务系统和金融 IC卡业务系统。

  • 企业级微服务平台定位于全行企业级应用集成平台；

  • 现金流分析管理系统为浦发手机银行客户提供收支明细查询、便捷记账、多维度的统计等功能；

  • 资金监管业务系统为浦发客户提供资金监管服务；

  • 金融 IC 卡业务系统主要承载金融 IC 卡的开卡、销卡、换卡等卡片管理类业务和银行卡联机消费、余额查询、ATM 取现等交易业务。

浦发银行自 2020 年上半年完成 DevOps 蓝图规划以来，经过近 1 年时间的 DevOps 实施及推广，很多系统研发过程已经采用流水线方式实施，为一次性通过 4 个项目打下坚实基础。此前，浦发银行的新型互联网贷款产品系统通过了持续交付标准 3 级评估。通过总结新型互联网贷款产品系统通过评估的成功经验，固优势、补短板，进一步提升组织级 DevOps 能力，为本次 4 个项目评估提供了组织级能力保障。浦发银行 DevOps 实施的目标之一是各团队 DevOps 功能、实践方面得到统一，一次性通过 4 个项目也拉近了与该目标的距离。

其中在参考新型互联网贷款产品系统之前通过评估的成功经验时，一方面是沿用了其优秀实践；二是改进了之前的不足，最后复用了组织级能力。

  •     首先，4 个项目组搭建了与新型互联网贷款产品系统过程大致相同的CI/CD流水线，保证研发过程可追溯；

  •     其次，4 个项目组都完成了容器化部署改造，提升部署效率及保证环境一致性；

  •     最后，4 个项目组都复用了组织级能力，如质量规约、度量反馈机制、版本管理机制等能力。

在此基础上，浦发银行通过总结经验，推广优势能力项，补足待改进能力项，重点优化薄弱环节，进一步提升持续交付能力。一次性通过4个项目的评估，也说明优化改进取得了不错的效果。
此次通过评估的 4 个项目在投产频率、构建时长、部署频率、单元测试覆盖率等方面效能都有大幅度提升：

本次浦发银行参评的 4 个系统在各个方面都有差异。系统定位方面，既有对客系统，也有企业级集成平台；应用架构方面，既有微服务架构，也有单体架构；开发语言方面，既有Java 语言，也有 C 语言。

此外在参评期间考虑系统的改进方面，浦发银行本着保证各系统 DevOps 实践各环节总体一致性的前提下，针对每个系统自身的架构及开发语言特性，提供差异化的改进方案。比如一致性体现在 DevOps 研发过程、质量控制、自动化能力要求保持一致；差异化体现在选用的工具链、流水线搭建、触发方式、分支策略存在差异。
所以多个项目同时参加 DevOps 标准评估，无疑是增加了评估工作的难度。首先，4 个系统技术栈存在差异，无论是开发语言、应用架构、部署环境均有差异；其次，各系统团队规模存在差异，各系统团队间沟通协作方式有一定差异；最后，选用的工具链存在差异，由于开发语言及部署环境的差异，选用的工具链需匹配系统交付需求。
为了解决上述差异带来的困难，浦发银行从多方面着手进行优化改进。首先是加强 DevOps 平台能力，集成各语言研发过程中需要使用的工具平台；其次是采用敏捷的方式将各系统成员拆成一个个敏捷团队，加强沟通与协作；最后是充分利用容器能力，提供弹性伸缩能力的同时保证部署环境一致性。

DevOps 是一种能力，是人、流程、工具有效结合后达到的交付能力的体现。此次4个项目同时通过 DevOps 标准 3 级评估是对浦发银行组织级 DevOps 能力的认可。
  • 说明浦发银行研发团队能力能达到持续为客户交付价值的要求；
  • 说明浦发银行 DevOps 研发过程能达到可视化、可追溯、可度量的目标；
  • 说明浦发银行工具平台、基础设施具备支撑应用快速交付的能力。
4 个项目在对标改进过程中，研发过程更加规范，质量管控更加严格，自动化能力进一步提升。同时，团队成员在改进过程中得到了很好的锻炼，提升技术能力的同时加深了对 DevOps 理念及文化的认知。

我们都知道持续改进是 DevOps 能力建设的关键一环。浦发银行多个项目参与到 DevOps 标准评估是希望通过持续对标《研发运营一体化（ DevOps ）能力成熟度模型》标准，达到持续改进的效果。标准对于 DevOps 的建设具有很强的指导意义，为企业数字化转型提供了抓手，改进效果得到了领导的高度认可，同时培养了 DevOps 人才，增强团队的能力和信心！

下一步，浦发银行将目标定在提升 DevOps 实践项目组的规范化方面。首先将参加信通院 DevOps 标准评估的改进经验推广到更多的项目组中，形成一套可实施 DevOps 的应用方案；其次着手进一步提升 DevOps 平台能力，通过与浦发金融云平台集成，支撑项目组云原生模式转型。

研发运营一体化（DevOps）能力成熟度模型介绍：
《研发运营一体化（DevOps）能力成熟度模型》系列标准是由中国信息通信研究院牵头，云计算开源产业联盟、高效运维社区、BATJ等顶级互联网公司以及各大金融、通信企业共同制定的国内外首个 DevOps 系列标准，由中国信息通信研究院主导的DevOps标准已由工信部发布并被众多金融、通信和互联网等行业名企纷纷采用并通过评估。
与此同时，DevOps 标准已于2020年7月在联合国直属标准化组织 ITU-T 正式结项，成为全球首个 DevOps 国际标准。DevOps 标准评估体系主要包括敏捷开发管理、持续交付、技术运营、应用设计、安全及风险管理、系统和工具等部分。
