# 燃！中移软件通过 DevOps 持续交付标准 3 级评估，相关项目能力达到国内领先水平！

**编者按：**从各大企业的实践来看，标准化和工具赋能是科技公司成功的关键所在。DevOps 标准及基于标准的 DevOps 持续交付流水线平台，使得企业的软件研发效能飞速提升、更快更灵活应对市场变化，助力 IT 成为企业的核心竞争力之一。

2021 年 3 月 25 日，由中国信息通信研究院指导，云计算开源产业联盟和开放运维联盟共同发起的企业级 DevOps 赋能（共促）计划第五次专题活动——“DevOps体系护航企业数字化转型”成功于线上举办！

**会上，中国信息通信研究院隆重发布了 DevOps 标准持续交付第十一批评估结果。**中移（苏州）软件技术有限公司（以下简称“中移软件”）本次参评项目为中移舆情项目，该项目顺利通过由中国信息通信研究院（以下简称信通院）开展的《研发运营一体化（DevOps）能力成熟度模型》持续交付3级评估。DevOps 标准共分 5 级，持续交付部分如果能达到 3 级已经是国内领先水准，这代表着中移软件在参评项目的持续交付能力达到国内领先水平。**评测单位：中国信息通信研究院**

▲DevOps评估结果公布现场

此次，我们采访了中移（苏州）软件技术有限公司首席科学家钱岭先生， 一同深聊中移软件中移舆情项目参与评估的细节和幕后团队的故事，分享中移软件 DevOps 实践的经验。

中移（苏州）软件技术有限公司首席科学家钱岭

  

  

**Q：您好，请介绍一下您和您的企业，以及此次参与评估的项目。**  

**钱：**我们的企业是中国移动苏州研发中心，也叫中移软件，它最早成立的时候是家软件企业，主要目标是交付项目，在 2019 年的时候我们进行了“云改”，成为了一家运营类企业，运营中国移动的公有云（移动云）。本次参评的项目是我们移动云中的一款产品叫做中移舆情，是一个偏应用的项目，这个项目涉及到从网上采集数据，然后做数据清洗、数据治理、人工智能的分析，最后，以情报的方式交付给用户使用，这是我们参评项目的一些情况。  
**Q：恭喜您通过 DevOps 标准评估，此次贵公司项目通过的是持续交付3级，表明达到了国内领先水平，请说一下您此时的感受。****钱：**应该说是非常激动和高兴的，因为我本人是学质量管理工作的，工作期间又是做质量管理工作，所以对于 CMMI 这个体系比较熟悉，CMMI 体系它实际上一种基于流程以及基于流程运行结果的一个评估，它不太关注过程和工具。DevOps 评估不光关注结果、关注流程，还更关注流程的工具化和系统化，而且还要经过检验，达到可执行、可运行的程度。所以它和传统的 CMMI 的评估有很大的区别，不是提供质量数据就可以了，更多的是提供一套可执行、可用于生产的系统。对于这部分，我们也付出很大的努力，从开始我们认为评估比较容易到后来发现难度有点大，也经历了一些补短板的工作，最终才通过了标准评估，总体很激动。  
**Q：****贵公司是如何决定加入 DevOps 标准评估工作中的？****钱：**原因有两点：一是，我们最初在项目交付的时候，就已经有中移舆情这个产品，那时候这个产品是一个点状的产品，已经采用 DevOps 的部分理念，所以才有底气进行 DevOps 评估。二是，我们公司 19 年“云改”以后，我们移动云产品数量从原先的 39 款到 19 年底大约 70+ 款，再到 2020 年底 200+款，公司内所有产品都变成了运营类产品，产品升级、变更上线以及资费调整、营销等工作的复杂度非常大，我们发现原来我们在点状上做的工作要复制到大的公有云产品上难度很大，所以就要树立一个标杆示范项目，就是用我们的中移舆情这个相对成熟度比较高的运营项目来做标杆项目，参加 DevOps 评估。评估的主要目的是要获取最佳实践，并且证明这个实践对我们工作有帮助，从而推动公司整个所有产品未来的 DevOps 工作开展。 **Q：通过 DevOps 标准评估对您企业带来了什么帮助？对贵团队有哪些影响？****钱：**通过 DevOps 评估，很明确的告诉我们一个方向，就是我们可以实现符合业界最佳实践 DevOps 持续交付三级或者更高级的一个工具链体系、一套流程管理体系以及相关配套的组织架构。这个工作增强了我们的自信心，知道我们可以做到，同时，也可以来把经验推广到整个公司，推广到我们其他项目中，这个帮助对我们来说作用是最大的。另外，对我们的团队来说，他们经历了一次评估的洗礼，他们会更加清晰得认识到自己做得每件事，对他们工作的敏捷性和质量的影响。对我们的其他团队来说，他们有了一个可以学习、参考的一个模板，对于后续的研发管理工作和质量提升工作就打下了很好的基础。  
**Q：****您可否详细的介绍一下，通过本次评估有哪些数据指标可以直观的体现项目改进成果？**![](../Images/a35ee6c69e33b9ebbf50b65b681c3e5c.png)

![](../Images/36390087057eae58bd78744570d7c7f6.png)

**钱：**有上面几项指标：首先，需求交付的周期目前缩短到 11 天，跟我们的其他的同类的产品相比快多了，因为其他产品大概有 60 多天，更长的 141 天的，舆情产品需求交付周期提升，跟我们的 DevOps 改进工作是有很大关系。第二，发布成功率目前也提升到 95% 以上，该指标跟我们其他的产品相比也有很大提升，因为现有一些产品发布往往会有很多的缺陷，即便说是升级完成，第二天还会有一个修 Bug 的过程，根本达不到 95%，在 60%-70% 之间，经过两天以后才能达到可以发布的一个水平。第三，是红灯修复时长 15 分钟以内，从我们评估看的话，我们有能力把其他产品的红灯修复时间缩短到更短的时间里面去；第四，提测流水线执行时长的话只要 7 分钟，但这个不是我们核心改进指标点，其他的产品根据它的产品规模或者复杂性差异，时间差异可能较大，但是有一定优化空间；最后，就是技术债的情况，通过几个月的试运行，把我们原先存量的一些技术债务问题，逐步进行了解决，现在公司内其他有些产品前期的问题比较多，可能需要通过架构优化来解决部分技术债问题，但目前可行性比较小，原因在于每次架构调整都需要通宵割接，工作量比较大。  
 **Q：****对于此次参评的项目，其 IT 系统有哪些特色，当时是怎么规划和设计的？****钱：**这个是我们自己的一套配置管理系统，这个系统集成了很多的工具链，它比较大的一个特征是开放性比较好，能适用于很多场景，可以跟商业化工具、开源工具以及自研工具集成在一起，这个对我们后面的集成以及做二次开发都有很大的帮助。规划方面，这是由于我们是属于类似于互联网这样企业，所以首先想到的工作就是选取咱们业界最佳实践，曾经也考虑过采购一些商业化的 DevOps 工具，包括我们内部团队也有做了一个很好的可以商用的一个 DevOps 系统，评估后都没有采用。后来通过基于主流的开源系统做自研 IT 系统，主要原因是发现我们的企业文化、内部的组织架构、管理流程以及产品的规模是我们调研的所有工具都不支持的，所以必须从我们自己的实际需求出发，然后建立一支研发团队，来完成我们 IT 系统的开发，使它和我们内部的管理体系、组织架构，还有存量的工具链保证兼容、配套使用，这个是我们的一个基本出发点。 **Q：****此次通过评估的过程顺利吗？遇到什么困难？如何解决的？****钱：**评估过程整体上是顺利的，结果是好的。但当中也存在一些困难，我们在准备评估过程当中也发现， DevOps 标准 3 级的评估要求是比较全面和细致的，我们原有的工具能力方面存在一些差距。例如，一些细致的分析工作，包括一些数据的获取、分析，形成分层分级的数据报告，这些是我们原来并不具备的，所以整个过程是一边差距分析、准备评估，一边提升我们 IT 系统的能力，同时也在培养我们相关同事的管理能力。总体来说，过程中还是遇到一些困难的。 **Q：****对于 DevOps 今年的实施，您觉得最大的收获是什么？您的下一步计划是？ ****钱：**我们最大的收获是树立了一个可以推广到公司所有产品以及公司大平台的一个样板；在这个样板基础上，横向扩展可以支持更多的产品，所以对我们的IT系统打磨、DevOps 推广的自信心提升都有很大的意义。下一步工作就是 DevOps 实践的推广，推广到横跨了 12 个中心资源池和 13 个省级资源池还有 2 个合作的省级资源池的移动云上的 200+ 款产品中，目前也正在开展相关的工作，因为这里面还涉及到产品架构改造，然后支撑系统的配套升级；另外，要把 DevOps 做好的话，根据产品的不同情况，也会引入蓝绿发布和灰度发布两种不同的部署发布策略；这些都是我们预计在 2021 年要完成的一些工作。 **Q：****对于 DevOps 的发展前景，您怎么看？****钱：**在我看来， DevOps 是一个比较好用的一个工具，每个企业要根据企业的实际情况来研发相关的 IT 系统，制定相关的流程来开展工作，而不能说一味的是遵循所有规则，比如说互联网企业实现团队一体化是通过事业部的着这种组织架构，这种架构对于实施 DevOps 是可能更加容易一些，但是作为一家从软件企业升级转型而来的企业，我们在这方面并没有完全形成事业部的这种架构，我们的 DevOps 团队实际上不是在一个部门内部的，而是跨了很多条线和领域，类似这种在实施 DevOps 过程中都应该充分考虑到，对于其他参评的单位或者其他准备引入 DevOps 的企业，都应该有充分的考虑。而我们 DevOps 的前景当中也应该加入更多的这种案例，以及一些工作指南，然后来支撑不同组织、不同企业文化的企业都能够享受到 DevOps 带来好处。

**研发运营一体化（DevOps）能力成熟度模型介绍：**《研发运营一体化（DevOps）能力成熟度模型》系列标准是由中国信息通信研究院牵头，云计算开源产业联盟、高效运维社区、BATJ等顶级互联网公司以及各大金融、通信企业共同制定的国内外首个 DevOps 系列标准，由中国信息通信研究院主导的DevOps标准已由工信部发布并被众多金融、通信和互联网等行业名企纷纷采用并通过评估。与此同时，DevOps 标准已于2020年7月在联合国直属标准化组织 ITU-T 正式结项，成为全球首个 DevOps 国际标准。DevOps 标准评估体系主要包括敏捷开发管理、持续交付、技术运营、应用设计、安全及风险管理、系统和工具等部分。![](../Images/c656d5dc0ae9a30269a21e7a55a88029.png)
