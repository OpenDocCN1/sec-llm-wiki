编者按：从各大企业的实践来看，标准化和工具赋能是科技公司成功的关键所在。DevOps 标准及基于标准的 DevOps 持续交付流水线平台，使得企业的软件研发效能飞速提升、更快更灵活应对市场变化，助力IT成为企业的核心竞争力之一。

2021 年 3 月 25 日，由中国信息通信研究院指导，云计算开源产业联盟和开放运维联盟共同发起的企业级 DevOps 赋能（共促）计划第五次专题活动——“DevOps体系护航企业数字化转型”成功于线上举办！

会上，中国信息通信研究院隆重发布了 DevOps 标准持续交付第十一批评估结果。中国移动通信集团江苏有限公司（以下简称“江苏移动”）本次参评项目为阿拉盯行销赋能项目，该项目顺利通过由中国信息通信研究院（以下简称信通院）开展的《研发运营一体化（DevOps）能力成熟度模型》持续交付 3 级评估。DevOps 标准共分 5 级，持续交付部分如果能达到 3 级已经是国内领先水准，这代表着江苏移动在参评项目的持续交付能力达到国内领先水平。
评测单位：中国信息通信研究院

此次，我们采访了江苏移动阿拉盯行销赋能项目团队 ， 一同深聊团队在项目参与评估时的细节和故事，分享江苏移动 DevOps 实践的经验。

-Q&A-
江苏移动阿拉盯行销赋能项目团队

Q：请介绍一下企业以及此次团队参与评估的项目。
A：江苏移动隶属中国移动通信集团公司,是中国移动有限公司在江苏设立的全资子公司。作为江苏省内最大的移动通信运营商，江苏移动近年来致力于 5G 快速发展的同时，在云计算、大数据、DICT 等领域不断突破, 积极推进企业的数智化转型，为个人、家庭及政企用户提供优质服务。
本次参与评估的项目是阿拉盯行销赋能项目，该项目以“小前台+大中台”的思路进行建设，通过构建“实时、精准、高效、共建”的一体化行销平台，打造以服务为中心，业务受理和闭环管理为两翼的渠道运营管理支撑体系，实现数据共享、能力复用、快速响应变化及助力业务创新。

Q：恭喜江苏移动通过 DevOps 标准持续交付3级评估，表明达到了国内领先水平，感受如何？
A：本次能够通过持续交付标准 3 级评估实属不易，首先要感谢信通院对我们的指导和帮助，也感谢集团公司、省公司领导对 DevOps 转型给予的肯定和帮助。阿拉盯项目是江苏移动自主研发构建的移动端渠道支撑运营工具，目前月均业务办理量已达到 120 万笔，业务需求非常活跃，对交付速度有非常高的要求，因此持续交付能力提升具有非常重要的意义。
此次通过标准评估是江苏移动 IT 实施敏捷、精益转型的里程碑，要感谢江苏公司信息技术中心为 DevOps 践行和研发运营一体化建设工作辛勤付出的同事，同时也感谢各方合作伙伴及单位的大力支持。

Q：江苏移动是如何决定加入 DevOps 标准评估工作中的？
A：江苏移动信息技术中心 DevOps 转型工作始于 2018 年，随着公司数智化转型发展，业务驱动创新，对软件交付能力提出了极高的要求，我们从推行 Scrum 敏捷开发模式入手，开展流程优化和构建自动化工具和流程，取得了一些成效；同时我们也看到了与业界先进水平的差距，研发运营一体化（DevOps）能力成熟度模型为软件工程能力全面对标提供了指引和参考，所以我们决定以阿拉盯项目作为参评项目，以度量驱动改进，逐渐缩小平台工具和团队能力上的差距，并将工程实践在组织级进行推广。

Q：通过 DevOps 标准评估对企业带来了什么帮助？对团队有哪些影响？
A：此次通过 DevOps 持续交付标准 3 级评估对于江苏移动意义重大，包括以下三个方面：
首先， DevOps 标准评估助力江苏移动 DevOps 研发运营一体化体系的优化。江苏移动自 2018 年开始，结合运营商研发运维现状，逐步建立了自身特色的 DevOps 体系，并开展了跨团队的产品经理制敏捷开发、灰度发布等一系列流程和工程实践。DevOps 标准评估实现了软件交付生命周期的全覆盖，在深度和广度上具有参考和指导意义，可以帮助我们了解 DevOps 能力现状,并推进 DevOps 转型在通信行业的落地。
其次，DevOps 标准评估助力江苏移动 DevOps 工具平台演进。持续交付需要构建符合企业特点、研发模式的 DevOps 工具链，以助力业务价值的快速释放。江苏移动通过自研创新，构建了贯穿业务全生命周期的 DevOps 平台，为研发团队提供一站式、自助式服务。此次参与持续交付标准评估，与行业先进案例对标，团队得以不断优化和扩展平台能力，通过构建标准化、自动化的 DevOps 工具链，降低研发门槛，助力研发效率和质量的提升。
第三，在实践中提升团队人员能力水平，储备 DevOps 人才。此次参评过程中，江苏移动多名人员参与到DevOps 标准评估工作中，通过开展对外交流、技术沙龙等活动，积累了持续交付的理论和实践经验，提升了专业技能，为推进公司 IT 条线敏捷转型、赋能业务生产提供了中坚力量。
 
Q：团队项目通过本次评估有哪些数据指标可以直观的体现项目改进成果？


A：通过此次 DevOps 持续交付标准 3 级评估，团队在持续交付七个能力子域均获得了显著提升，业务上线周期缩短，能够更快的、高质量的响应业务的变化和需求。如下图所示，可以详细看到参与评估带来的改进：需求交付周期，缩短45%；变更前置时间，缩短50%；变更失败率，降低到5%以内；平均构建时长，缩短到5分钟左右；自动化测试覆盖率提升到100%；上线发布频次，具备按需发布的能力。

Q：对于此次参评的项目，其 IT 系统有哪些特色，当时是怎么规划和设计的？
A：此次参评的项目是“阿拉盯行销赋能项目”，是一款以“全、简、快、固”为理念打造的移动端行销和渠道运营平台，有效的支撑互联网化的融合业务受理。项目采用领域驱动设计方法进行业务架构设计，并采用前、后端分离的微服务系统架构。由于项目的主要用户为江苏移动一线营销人员，业务需求非常活跃，响应及时度要求非常高，因此采用敏捷开发模式，双中心蓝绿部署，支撑需求的快速迭代和发布能力。
 
Q：团队参与评估的过程还顺利吗？遇到哪些困难？如何解决的？
A：总体而言，在此次参与持续交付标准评估的过程中遇到了一些问题和挑战，我们结合专家建议和自身实践，克服了困难，顺利的完成了评估，可以总结为以下几点：
首先，跨团队的协作及沟通成本较高。DevOps 持续交付标准覆盖 7 个能力子域，所涉及的能力子项对应江苏移动的多个团队，包括阿拉盯项目业务开发团队、容器云平台、DevOps 平台等，每个团队的分工和工作模式都有所不同，为提升协作效率，我们组建了跨领域的敏捷团队，共同研读评估标准，统一对持续交付的理解，参照业界先进，实践改进。
第二，持续交付需要有良好的系统架构作为基础支撑。为了更好的支撑业务变化，阿拉盯项目本身不断进行应用架构优化，先后完成了容器化和微服务化的架构改造。通过 DevOps 工具链为每个微服务单独建立 CI\CD 流水线，同时完善质量门禁及自动化测试保障体系，最终实现了云原生架构下微服务独立开发、测试和发布的目标，交付周期大大缩短。
第三，DevOps 人才的培养。虽然江苏移动是较早的开展了 DevOps 转型实践，积累了一些经验，但并未形成可复制的系统方法论，尤其是缺乏相关领域的专家。此次通过持续交付标准评估，团队人员的能力在实践中得到了大幅度提升，顺利通过标准评估，同时也为今后其他项目的转型打下了夯实的基础。

Q：对于江苏移动 DevOps 的实施，团队最大的收获是什么？下一步计划有哪些？
A：最大的收获是实现了阿拉盯项目业务转型指标的提升，能够更快的支撑业务价值交付。目前，“阿拉盯行销赋能项目”需求交付周期显著缩短，极大的增强了转型支撑能力。通过此次标准评估，团队大胆实践并沉淀经验，完善了 DevOps 体系。
下一步计划，将阿拉盯项目团队的成功经验复制推广到更多的项目，尤其是业务支撑领域的复杂系统，在推广的同时保持对各个项目差异化的实践和创新，需进一步打通信息屏障，为更多的产品赋能；第二，进一步提升 DevOps 平台的通用性和扩展性，探索跨团队的敏捷协同及持续集成，进行基础设施即代码等实践，对团队也是新的机遇和挑战。

Q： 对于 DevOps 的发展前景，有哪些看法？
A：DevOps 目标是实现持续、快速、高效、高质量的业务价值交付，同时也重视组织文化建设，通过自动化、精益、反馈和分享等方面的提升，结合理论、实践、工具打造高效能团队，这是效率驱动创新的关键路径，因此选择 DevOps 将会是众多企业的共识。
在数智化、互联网化转型的大趋势下，运营商需要具备越来越快的 IT 交付能力和稳定高效的 IT 服务支撑能力，未来仍需要通过深化 DevOps 实践，进一步修炼内功，获得技术革新和组织效能的提升，从而赋能创新。另一方面，近年来国家对信息安全管理的规范愈加严格，作为通信运营商，在持续交付的同时还需要考虑将 IT 安全防护融入应用到整个生命周期中 ，因此 DevSecOps 也必将成为 DevOps 演进的未来趋势。

研发运营一体化（DevOps）能力成熟度模型介绍：
《研发运营一体化（DevOps）能力成熟度模型》系列标准是由中国信息通信研究院牵头，云计算开源产业联盟、高效运维社区、BATJ等顶级互联网公司以及各大金融、通信企业共同制定的国内外首个 DevOps 系列标准，由中国信息通信研究院主导的DevOps标准已由工信部发布并被众多金融、通信和互联网等行业名企纷纷采用并通过评估。
与此同时，DevOps 标准已于2020年7月在联合国直属标准化组织 ITU-T 正式结项，成为全球首个 DevOps 国际标准。DevOps 标准评估体系主要包括敏捷开发管理、持续交付、技术运营、应用设计、安全及风险管理、系统和工具等部分。
