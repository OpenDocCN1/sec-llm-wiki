# 燃！郑州银行通过 DevOps 技术运营标准评估，相关项目能力达到先进水平

**编者按：**根据麦肯锡的一项研究结果，科技公司想要成功，关键所在无外乎两点：标准化和工具赋能。标准本身是最佳实践的集合，有了标准，每一步都离目标更近（而不是偏离），将标准固化在工具里，让人做更有价值的事情。这和技术运营标准的核心理念不谋而合，旨在体系化的整理技术运营的共性能力模块与实践。

2020年12月23日，为提高企业 IT治理水平，加强行业内经验交流分享，2020 GOLF+ IT新治理领导力论坛在北京召开！本次大会旨在“让IT治理‘融惠’科技创新”，围绕“治效赋能，领航科技新生态”和“ XOPS 聚力，引领运维新风向”两大主题展开。

**大会隆重发布了 DevOps 能力成熟度技术运营第三批评估结果。**郑州银行股份有限公司（以下简称郑州银行）本次参评的核心业务系统项目顺利通过由中国信息通信研究院（以下简称信通院）开展的《研发运营一体化（DevOps）能力成熟度模型》技术运营2级评估，代表着郑州银行在该业务系统的技术运营能力达到国内先进水平。

此前，郑州银行的新版核心业务系统通过了持续交付标准3级评估。

  

  

**评测单位：中国信息通信研究院**

**中国通信标准化协会副理事长兼常务副秘书长代晓慧女士、中国信息通信研究院云计算与大数据研究所所长何宝宏博士共同为企业授牌：**

  

![](../Images/4b0cab00f2fc213adbfa18525aad2c02.png)

▲DevOps评估结果公布现场

  
此次，我们邀请到郑州银行信息科技部总经理贾爱军，郑州银行信息科技部副总经理黄学舟，深聊郑州银行核心业务系统项目通过 DevOps 标准技术运营部分评估的意义，以及背后团队的故事。  
**\- Q&A -**

 

![](../Images/da33386583613a982c8fd2dcecf4adf1.png)

郑州银行信息科技部总经理贾爱军

  

**Q：恭喜您通过 DevOps 标准评估，此次贵公司项目通过的是技术运营 2 级，这在国内是什么样的水平，麻烦您给介绍一下~**

**贾：**郑州银行技术运营工作始终秉承“安全稳定、服务高效、管理规范、持续创新”的理念，坚持以客户为中心，积极拥抱云计算、大数据、人工智能等新兴技术，努力为郑州银行的每一位客户提供更加优质的金融服务和良好的用户体验。

DevOps 技术运营标准为我行技术运营工作在监控管理、事件及变更管理、配置管理等 7 个能力域提供了指导意义，特别是在监控完善、工具整合、数据流转以及组织协同等方面取得了较大程度提升，通过评估核心业务系统顺利通过技术运营 2 级评估。也表明了我行在信息科技方面的实力，希望能为银行业技术运营工作发展有所引领或者给同行业有所借鉴。目前技术运营 2 级代表了国内先进级别水平，从评估结果来看，我行核心业务系统技术运营能力整体已经达到国内先进水平，甚至部分能力域还达到了3级国内领先级的水平。

  

****Q：请您介绍一下此次参与评估的项目。****

****贾：****郑州银行是一家位处中原大地的区域性银行，聚焦“商贸物流银行、中小企业融资专家、精品市民银行”三大特色业务定位。于 2015 年在香港联交所上市，于2018年 9 月在深交所挂牌上市，首开国内城商行 A+H 股上市先河。信息科技部始终贯彻“科技兴行”强力支撑高质量发展的企业方针战略，此次参与评估的项目为我行核心业务系统，是行内最重要的业务系统，为我行客户提供客户管理、存款产品、贷款产品、卡产品以及账务核算等核心功能，该系统日均交易笔数 400 万。

  

  
**Q：关于 DevOps 标准，您怎么看，对您企业带来了什么帮助？**

**贾：**本次核心业务系统通过2级评估，是对近年来我行科技建设成果、科技研发人员能力提升的肯定，标志着我行的技术运营管理水平达到同行先进水平。

DevOps 技术运营的推广，为我行产品快速迭代、业务高质量发展打下了坚实基础，是促进我行数字化转型中团队所必备的能力!

以后我们将以开放，共享的心态，在敏捷开发、安全与风险管理等领域投入更多的资源，共同推动 DevOps 体系在金融行业的建设与推广。

具象说明：通过DevOps技术运营标准引入，首先在监控能力方面，完善了监控体系，实现了监控工具和数据的整合，提升了精准告警能力，也为故障诊断和定位分析打下了基础；其次在应急能力方面，完成了预案场景丰富、预案线上化以及部分预案处置自动化，提升了应急场景处置效率和知识储备能力；最后在客户体验管理能力方面，完成了客户体验数据可视化，实现了体验数据收集，规范了体验优化流程，提升了客户使用感受。通过各领域能力同步提升，促进了我行开发测试运维工作的进一步融合，巩固了业务系统高可用架构，提升了业务连续性，从而保障了业务安全稳定运行。

  
**Q：关于 DevOps ，接下来团队有什么样的计划？**

**贾：**郑州银行通过 DevOps 技术运营能力提升，进一步促进了开发测试运维一体化，明显提高了软件产品的交付质量和持续运营能力，实现了业务可监控、风险可分析、应急有预案、体验有保障、业务高可靠，同时提升了资源使用率、减少了成本投入、降低了潜在运行风险。从本次项目效果看，自动化灾备切换场景处置效率比手工操作提升了 3 倍以上，随着业务交互复杂度提升和设备规模指数级增长，技术运营的优势将更加凸显。

我行已经将 DevOps 建设作为近年来工作的重点之一，在试点成功的基础上，结合专家的改进建议，制定落地方案，进一步补充短板能力，同时加大推广力度，坚持深度和广度齐头并进。除了技术运营能力外，我们也希望能在其他领域如安全与风险管理等有进一步的提升。同时，我们也非常愿意与同行业积极探讨 DevOps 在金融行业落地可行方案，以期共同发展，共同进步。

未来，郑州银行 DevOps 技术运营仍然以客户为中心，持续改进客户体验，围绕“安全稳定、服务高效、管理规范、持续创新”，结合云计算、大数据、人工智能等新兴技术，持续提升技术运营精细化管理水平，为郑州银行业务发展保驾护航。

  

**Q：****关于  DevOps  的发展前景，您怎么看？**

**贾：**DevOps 是一种先进的文化理念，它倡导以客户为中心，这是也企业生存的立足之本。DevOps 还是一个全面的标准体系，横向覆盖了研发运营一体化过程、应用设计、安全与风险、组织结构以及系统和工具等多个方面，纵向到各领域给出了精准的能力项，便于企业对标具体能力点进行改进提升。更值得信赖与称赞的是，DevOps 标准如它倡导的理念一样，也是不断改进的。能接触到并选择这样一个不断学习进步的标准引导我们前进，是一件非常幸运的事情。相信会有更多的企业引入 DevOps 体系，并参与 DevOps 标准的评估。

  

  

![](../Images/bb87c00ec30b1253124cac68cd76de5e.png)

郑州银行信息科技部副总经理黄学舟

  

**Q：贵公司是如何考虑将此项目进行技术运营评估的？**  

**黄：**从行业整体来看，头部科技企业的技术运营工作正在从自动化向智能化转变，郑州银行作为一家力争科技创新的企业，并不满足于当下的科技实力，希望通过 Devops 技术运营评估项目，进一步提升人员、流程和工具的高效协同能力，进而我行数字化转型提供强力科技支撑。

此次选择核心业务系统作为第一个技术运营试点项目，主要是因为核心业务系统作为我行最重要的系统，也是技术运营工作的关键对象，该系统具备全年 7\*24 小时无休的业务连续性，数据丢失零容忍，灵活可扩展高可用架构以及高并发高性能处理时效等严苛的技术运营要求，在此背景下，希望能够通过各领域对标，提升核心业务系统安全、稳定、高效运行的能力；在通过难度选择上，我们考虑到先从难的、硬的骨头下手，切实加强团队 DevOps 技术运营能力建设，提升人员意识、提高工具赋能，为进一步 DevOps 技术运营推广打下坚实基础。同时 2019 年郑州银行参与 DevOps 持续交付评估也是核心业务系统，通过持续交付流水线的建设，明显提升了软件开发的交付效率、交付质量，以此系统延续技术运营工作，不仅具备良好的基础，而且可以深化持续交付和技术运营工作的融合和促进，为我行业务敏捷、数字化转型提供更强力的科技引领和支撑作用。

  

**Q：通过此次 DevOps 标准技术运营部分评估对贵团队意味着什么？具体有哪些改进？**

黄：DevOps 技术运营标准为我行技术运营工作开展指明了方向，通过此项目评估，让我行科技人员加深了认识、激发了灵感、锤炼了工具、弥补了短板，不仅为现有技术运营工作的精细化开展提供了标准参考，同时也明确了未来的努力方向。

郑州银行技术运营工作始终以业务为第一视角，关注客户体验，经过多年的积累和历练，践行“五台一库”建设思路：以监控为基础，以流程为抓手，以自动化为手段，以智能化为辅助，以 CMDB 为数据核心，构建了统一告警平台、统一流程平台、统一自动化平台、统一数据分析平台以及统一展示工作台，实现了配置信息统一管理、事件全生命周期管理、流程高效协同、自动化安全便捷、全视角数据关联及价值挖掘等多方面能力，具备了良好的项目实施基础。此次评估项目团队经过数月的改进提升，不仅验收评估全面达标，而且项目团队在监控管理、事件与变更管理等优势领域深耕细作、不断完善，在成本管理、容量管理等弱势领域吸取经验、弥补短板，实现 7 个能力域全面发展。例如：在事件管理方面，我们通过工具实现预案线上化和自动化，有效的提升了团队对于应急突发事件的高效处置能力；在业务连续性管理方面，研发自动化灾切工具，实现了不同灾切场景下的脚本复用和调度任务灵活配置，进一步提升了灾备切换能力；在用户体验管理方面，运用体验数据埋点实时上报及大数据分析技术，完成日常场景及营销场景下的用户使用体验指标收集，不断优化迭代，改善用户体验。

通过此次评估，团队技术运营能力得到行业的肯定，达到了国内先进级水平，部分能力域优势突出，已达到国内领先水平，也是一次非常重要的鼓舞和激励，促进团队人员继续努力，勇攀高峰。

  
**Q：对于此次参评的项目，其 IT 系统有哪些特色，当时是怎么规划和设计的？**

**黄：**核心业务系统是我行 2018 年 5 月 20 日正式投产的新一代“瘦”核心，具备灵活的产品工厂和定价工厂，产品工厂可实现存贷款产品的快速迭代和特色产品快速发布，为抢占市场先机提供了支撑；定价工厂可实现差异化的利率、费用以及汇率定价，更好的为不同客户群体带来优质的金融服务体验。同时为了提升核心业务系统高可靠运行能力，系统规划时按照微服务架构思想，实现了存款模块、贷款模块、卡模块以及内部服务模块等服务分离，提升了代码复用率以及迭代发版效率；使用数据库读写分离技术，提升了交易处理效率；引入流量控制机制，实现了限流策略等自我保护机制。除此以外还引入了分布式、高可用、负载均衡、数据复制、存储复制等技术保障核心业务系统的业务连续性。

  

**Q：此项目过程中遇到了哪些困难？如何解决的？**

黄：项目顺利通过此次评估归功于项目团队的攻坚克难、不懈努力。我行技术运营团队经过数年的历练和积累，不管在人员意识、工具建设和流程机制上都具备较好的基础，但是项目初期的差距分析还是让我们对自身现状与部分 2 级能力的差距有了更清晰的认识，同时银行企业与互联网企业相比还是有自身行业特点，银行需要监管指引下开展金融服务，因此我们需要结合监管指引和 DevOps 标准指导，制定更适合银行业特点的落地方案。面对这些问题，项目组结合岗位分工，为每个领域指定一名专员牵头负责该领域的方案讨论与迭代改进，制定改进计划，拆解任务项并责任到人，组织讨论落地方案，每日跟踪任务进展和存在问题，通过一系列举措顺利完成了项目验收。

**研发运营一体化（DevOps）能力成熟度模型介绍：**《研发运营一体化（DevOps）能力成熟度模型》系列标准是由中国信息通信研究院牵头，云计算开源产业联盟、高效运维社区、BATJ等顶级互联网公司以及各大金融、通信企业共同制定的国内外首个 DevOps 系列标准，由中国信息通信研究院主导的DevOps标准已在中国通信标准化协会（CCSA）立项在研。与此同时，DevOps 标准已于2020年7月在联合国直属标准化组织 ITU-T 正式结项，成为全球首个 DevOps 国际标准。DevOps 标准评估体系主要包括敏捷开发管理、持续交付、技术运营、应用设计、安全及风险管理、系统和工具等部分。![](../Images/c656d5dc0ae9a30269a21e7a55a88029.png)
