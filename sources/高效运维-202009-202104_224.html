编者按：从各大企业的实践来看，标准化和工具赋能是科技公司成功的关键所在。DevOps 标准及基于标准的 DevOps 持续交付流水线平台，使得企业的软件研发效能飞速提升、更快更灵活应对市场变化，助力IT成为企业的核心竞争力之一。

2020年12月23日，为提高企业IT治理水平，加强行业内经验交流分享，2020 GOLF+ IT新治理领导力论坛在北京召开！本次大会旨在“让IT治理‘融惠’科技创新”，围绕“治效赋能，领航科技新生态”和“ XOPS 聚力，引领运维新风向”两大主题展开。

大会隆重发布了 DevOps 能力成熟度持续交付第十批评估结果。安信证券本次参评项目为用户中心项目 ，该项目顺利通过由中国信息通信研究院（以下简称信通院）开展的《研发运营一体化（DevOps）能力成熟度模型》持续交付3级评估。DevOps标准共分5级，持续交付部分如果能达到3级已经是国内领先水准，这代表着安信证券在参评项目的持续交付能力达到国内领先水平。此项目是安信证券通过持续交付标准3级评估的第二个项目。


此前，安信证券的手机证券交易服务中台项目通过持续交付3级评估（相关新闻稿链接详见文末）。



评测单位：中国信息通信研究院

中国通信标准化协会副理事长兼常务副秘书长代晓慧女士、中国信息通信研究院云计算与大数据研究所所长何宝宏博士共同为企业授牌：


▲DevOps评估结果公布现场


此次，我们采访了安信证券CIO许彦冰女士，一起聊聊安信证券用户中心项目参与评估和幕后的细节故事，分享安信证券的DevOps实践经验。


-Q&A-

安信证券 CIO 许彦冰女士


Q：您好，请介绍一下您和您的企业，以及此次参与评估的项目。

许：大家好，我是许彦冰，目前担任安信证券信息技术总监、兼信息技术中心总经理。安信证券是国家开发投资集团有限公司旗下的证券公司，是一家全牌照综合类券商，多项业务排在行业前列。信息技术中心作为公司数字化转型和金融科技创新的总部直属部门，为公司600多万客户在股票交易、理财投顾等多个金融领域提供完善、可靠的交易IT服务。此次参与评估的用户中心项目定位于互联网业务中台，为安信E账通提供注册、登录、账户绑定、信息修改及查询等功能，推动以用户为中心的账户信息聚合，实现一个账户、一次登录、一站式服务。

Q：恭喜您通过 DevOps 标准评估，此次贵公司项目通过的是持续交付3级，表明达到了国内领先水平，请说一下您此时的感受。

许：很高兴用户中心项目能通过DevOps持续交付 3 级标准评估。该项目是继我司手机证券交易服务中台项目之后，第 2个成功过级的项目。该项目结合自身系统和团队的特点，借鉴上一个项目的优秀实践，查漏补缺，切实提升了系统的持续交付能力，在团队中贯彻了DevOps 理念。评估过程中我们得到了专家的肯定和认可，这不仅是对用户中心项目组持续交付能力的肯定，也是对安信证券DevOps 能力的一个认可。

Q：贵公司是如何决定加入 DevOps 标准评估工作中的？
许：随着业务的持续发展，信息技术中心相应建设和管理的信息系统不断增多，IT团队规模也持续扩张，现在已超 800 人。原来的研发模式是基于项目为单位进行研发和管理，上下游互相依赖和耦合，透明度不足，研发过程通过零散的工具进行支撑，且各团队使用不同的工具，缺少组织级的统一工具平台，各工具之间未能打通和联动，未能形成高效稳定的版本构建和发布。单元测试和自动化测试程度不高，仍以手工测试为主，在研发的后期才参与进来，整个研发过程缺少数据的跟踪和度量，难以满足业务需要快速发布和持续改进优化的要求。此次试点项目是安信证券第二个项目参加 DevOps 标准评估，我们实际上是以参与标准评估之名，行研发转型之实，落实以 DevOps 为基础的敏捷研发体系，为 IT 研发提质增效，并以此作为标杆，号召并带动其他团队深度参与到公司敏捷研发的转型之中。


Q：通过 DevOps 标准评估对您企业带来了什么帮助？对贵团队有哪些影响？
许：金融科技已经成为当今银行、证券和保险等金融行业的大势所趋。为了适应当前移动化、数字化、智能化的时代趋势，证券公司也需要具备互联网公司的快速响应能力，并不断提升研发水平，保障软件产品交付质量，以保障和促进业务的快速发展，为此，我们坚定不移地推行敏捷研发体系。我们从研发组织结构、研发过程、研发平台、研发度量及持续改进机制各维度入手，构建组织级敏捷研发管理体系，逐步形成组织级的敏捷研发能力。在用户中心项目中，涉及的研发流程改造、CICD 流水线的接入，度量数据的持续分析和改进则是安信证券研发管理体系赋能的体现。此次能够顺利通过 DevOps 标准持续交付三级评估，这对于我们意义重大，是安信证券坚定不移从传统研发模式向敏捷研发模式转型的旗帜。

Q：您可否详细的介绍一下，通过本次评估有哪些数据指标可以直观的体现项目改进成果？

许：通过 DevOps 的转型和持续改进，项目组在需求、开发、测试、部署等方案均取得明显的提升。其中一些核心指标上，相关项目的单元测试覆盖率从 50% 提升到 86% 以上，自动化测试比率从 70% 提升到了 92.34%，整个流水线的执行时间在10分钟内可以执行完成，而平均开发交付周期缩短至5.5天，较之原来的动辄数周的交付时长，交付效率得到了很大提升。所有类似这样的数据都在持续的记录跟踪和不断优化，整个 DevOps 成熟度持续提升。


Q：对于此次参评的项目，其IT系统有哪些特色，当时是怎么规划和设计的？

许：本次参评的用户中心项目定位于互联网业务中台，提供安信 e 账通的注册、登录、账户绑定、信息修改及查询等功能，推动以用户为中心的账户信息聚合，实现一个账户、一次登录、一站式服务。用户中心系统组件包括了后端服务，web 服务，前端 H5 页面，和数据库部分，和第一次参评的手机证券交易中台项目相比，多了前端和数据库的部分，因此参评项目改进过程中，流水线也补充了UI自动化测试与数据库变更的能力。最初我们挑选出的三个项目参与 DevOps 持续交付评估，基本上覆盖了所有自研的技术栈，比如第一次参评的手机证券交易服务中台项目主要是基于 Java 技术栈，用户中心相对手机证券交易服务中台多了前端UI和数据库，后面要继续参评的问问小安相对用户中心又多了 Android，iOS 客户端。我们希望通过以上三个项目的评估改进过程，完善工具平台和流水点的能力，覆盖支持所有自研系统的技术栈，为后续推广 DevOps 持续交付覆盖全部自研系统打好基础。


Q：此次通过评估的过程顺利吗？遇到什么困难？如何解决的？

许：在项目推进之初，敏捷实施不够充分，系统建设处于由传统项目形式到敏捷和 DevOps 转型的过渡期，研发过程中的需求管理、开发测试、环境管理、安全检测、部署发布各个阶段没有完全联动起来，整个研发过程的质量依赖于项目经理自身的管理能力，这与 DevOps 提倡打破原有职能组织的限制，强调协作与整体的文化是相悖的。

为了应对这个挑战，我们对整体研发流程进行了全局梳理，从业务需求提出开始，串联需求分析、代码开发、集成测试、环境申请、部署发布各个环节，明确各个节点之间的关系和准入准出条件，新调整及规划了各个环节涉及的不同岗位的工作内容及对应的工具支持，以及相应的制度和规范。

有了清晰连贯的整体流程，我们又组建跨职能的 DevOps 平台团队，为整个研发团队提供 DevOps 整体解决方案，设计和建设持续交付工具链及流水线，提供端到端研发协作平台，为持续交付与持续改进提供平台支撑。

在这个共同努力和协作的过程中，团队也逐渐接受和拥抱 DevOps 整体协同、研发和交付一体化的思维，开始紧密协作，一起基于已有业务基础之上不断优化交付流程，达成清晰一致的目标，问题也逐渐的迎刃而解。



Q：对于 DevOps 今年的实施，您觉得最大的收获是什么？您的下一步计划是？

许：当前，安信证券基于 DevOps 初步建成了研发管理平台，重新梳理了研发过程的全流程，并针对研发过程实施 CICD 自动化流水线，建成度量运营平台。

未来，安信证券将进一步完善敏捷的研发管理体系，主要是在 DevOps 建设上分两条腿走路：

一条腿，持续推广 DevOps 研发管理工具平台：扩大应用系统对接 CICD 自动化流水线的覆盖度，在两到三年之内实现自研系统的全覆盖。同时对研发流程和DevOps平台进行持续优化，实现基于研发的开发者门户，集成和封装所有的研发能力，包括需求、开发、测试、部署、资源申请和开发框架集成能力，实现一套流程，一个门户，一站式服务；

另一条腿，持续度量持续运营：在度量平台中将进一步丰富度量的数据和指标，通过智能化的技术和手段，实现指标和数据的自动化分析，并实时生成优化建议以及任务推送，实现从主动发现到自动分析到主动改进的闭环，形成组织内持续优化和改进的氛围。



Q：对于 DevOps 的发展前景，您怎么看？

许：DevOps 起源于互联网环境，成长于敏捷模式之下，宣导以“快速价值交付”为核心，更关注开发运维一体化，通过软件产品交付过程的IT工具链，打通了持续交付的流水线，相关的团队减少时间消耗，高效协同和快速交付。

金融企业在数字化转型的背景下，IT将从幕后走到台前，业务与IT的融合将成为未来的方向。DevOps 的内涵也必将由狭义的 Dev 和 Ops 的融合，进一步拓展到业务侧 Biz，走向 BizDevOps，企业也将围绕数字化重塑下的价值链的角度，重新审视IT为业务带来的价值。

研发运营一体化（DevOps）能力成熟度模型介绍：
《研发运营一体化（DevOps）能力成熟度模型》系列标准是由中国信息通信研究院牵头，云计算开源产业联盟、高效运维社区、BATJ等顶级互联网公司以及各大金融、通信企业共同制定的国内外首个 DevOps 系列标准，由中国信息通信研究院主导的DevOps标准已在中国通信标准化协会（CCSA）立项在研。
与此同时，DevOps 标准已于 2020 年 7 月在联合国直属标准化组织 ITU-T 正式结项，成为全球首个 DevOps 国际标准。DevOps 标准评估体系主要包括敏捷开发管理、持续交付、技术运营、应用设计、安全及风险管理、系统和工具等部分。
