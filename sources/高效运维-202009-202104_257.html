开放、高效、经济的机器数据分析平台
日前，AnyRobot 在线研讨会以“基于Hub架构纳管Splunk”为主题，对 AnyRobot 产品的开放能力进行了深度解读。
Splunk 在机器数据处理分析领域一直处于领先地位。鉴于数字化转型深入发展、国产化政策要求和企业对技术底层的自主掌控需要，国内的 Splunk 用户逐渐开始采取对Splunk 的替换和纳管方式，以满足安全合规和业务创新发展需求。
某银行实践解读：AnyRobot 纳管 Splunk 实践
强监管和本地化服务的高要求下，某银行一直在国内寻找合适的机器数据平台，可以在保证原有 Splunk 数据采集、分析业务不丢失、不中断的前提下，完成对 Splunk 平台的纳管、切换工作。
几经沟通后，该客户看中了爱数 AnyRobot Hub 架构的开放性和对多源数据、多类数据平台的纳管能力，选择 AnyRobot 对现有 Splunk 平台进行纳管和替换。在这个过程中，用户十分认可 AnyRobot 的分析管理能力，希望基于 AnyRobot，充分释放行内机器数据价值，驱动行内业务的创新发展。
某银行客户在选择 AnyRobot 时的主要关注点：
<1>行内业务系统运行持续稳定运行
爱数 AnyRobot 自研 Agent 代理程序，满足全平台、业务系统的机器数据采集；支持多种数据采集协议和不同的采集策略配置，审计数据采集记录和采集状态，确保全量数据采集和业务稳定运行。

多源数据采集管理


<2>交易系统日志数据解析和脱敏
行内现有业务系统多样，日志数据格式不一，AnyRobot 内置多种数据解析规则，支持鼠标划词解析，可将杂乱的业务系统日志数据信息进行清晰展现，并可将重要数据信息进行脱敏，确保数据安全。
<3>基于SPL的交易数据分析
AnyRobot 平台已支持部分 SPL 命令函数，在进行纳管 Splunk 时，对 Splunk 的SPL命令进行验证，并在数据完全切换后，保障行内业务运维人员的搜索分析需求，提升问题分析处理效率。
<4>现有数据分析和查询业务不中断
AnyRobot Hub 架构可满足客户现有 Splunk 平台内的历史数据、新增数据和现有数据在AnyRobot 平台上进行查询、分析和使用，保障客户原有数据分析业务的稳定进行。

AnyRobot Hub 架构纳管 Splunk


1、Splunk 原有数据采集

在现有 Splunk 平台可继续使用的情况下，保持 Splunk UF 采集数据，然后将数据接入到 AnyRobot 的 Collector Hub，并数据采集过程中增加一个格式处理器，将数据转发至 Splunk 以确保 Splunk 能识别到来自 Hub 的数据格式，同时保障接入的数据 host 字段不变、不影响原有数据处理方式。

2、新增业务系统的机器数据管理
在原有银行业务系统和基础设施层面部署 AnyRobot Agent ，将 Agent 的数据流推送给Collector Hub，传输到 AnyRobot，通过 AnyRobot 进行数据清洗、存储和分析处理。
3、Splunk 原有数据量超出
在不续购、增购 Splunk 平台资源的情况下，避免后续 Splunk 的部分功能不可用，在Collector Hub 上切换部分原有 Splunk 的 UF 数据流到 AnyRobot上，保障原有分析和查询服务不中断。
4、历史数据查询使用
当新的数据接入到 AnyRobot 后，历史数据的查询还需在 Splunk 完成。这时，可使用Calculation Hub，将请求调度给 Splunk，并把接收到的数据返回给 AnyRobot 做统一汇聚计算。
AnyRobot 以开放思维走进机器数据的世界，其Hub架构可实现多源数据连接，整合现有机器数据平台和第三方应用平台，为业务部门和IT管理人员提供统一的机器数据分析平台，满足用户的多样化需求。
