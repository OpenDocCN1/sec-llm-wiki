编者按：从各大企业的实践来看，标准化和工具化是实践组织级 DevOps 的基石，唯有统一标准，并固化到工具中，才能最大程度减少人为失误，减少人力成本，提高开发和运维的效率及质量。

2020 年9月 25 日，由云计算开源产业联盟（OSCAR）指导，由高效运维社区（GreatOPS）和开放运维联盟（OOPSA）联合主办的第十四届 GOPS 全球运维大会在深圳正式召开。GOPS 全球运维大会至今已经举办了 13 届，是国内第一个也是最大的运维行业大会，也是备受瞩目的千人峰会，面向互联网及金融、通信等传统行业广大运维、开发等技术人员，传播先进技术思想和理念，分享业内最佳实践。

大会隆重发布了 DevOps 标准系统和工具部分首批评估结果。平安银行股份有限公司（以下简称“平安银行”）本次参评的 Starlink 开发运维一体化平台项目顺利通过由中国信息通信研究院（以下简称信通院）开展的《研发运营一体化（ DevOps ）能力成熟度模型》系统和工具部分关于构建与持续集成模块的首批评估。代表着平安银行的 DevOps 系统和工具在相关模块达到国内领先水平。


评测单位：中国信息通信研究院

中国信息通信研究院云计算与大数据研究所所长何宝宏博士为平安银行授牌：

此次，我们采访了平安银行科技开发中心首席架构师黄威琪、平安银行科技开发中心 Starlink 产品负责人金艳，一起深聊平安银行 Starlink 开发运维一体化平台项目参与评估的细节和幕后团队的故事，分享平安银行 DevOps 实践的经验。

-Q&A-  


平安银行科技开发中心首席架构师黄威琪

平安银行科技开发中心 Starlink 产品负责人金艳


Q：老师您好，请介绍一下您和您的企业，以及此次参与评估的项目（工具）。
A：你好，我们是平安银行。今年，我行提出“新三年”战略举措：将着力打造“数字银行、生态银行、平台银行”三张名片，夯实转型升级基础，推动发展迈向新台阶。以此战略为目标，我们不断深化推进我行数字化转型实践，建设数字化能力。最近，我们也很荣幸成为首家获得“全球最佳数字化银行”大奖的中资银行。 
Starlink（星链），作为支撑平安银行数字化转型的战略产品。是我行在实践 DevOps、加快组织级敏捷转型的重要抓手。产品设计结合精益思想、敏捷思想，站在全局性、系统性的视角审视我行在研发过程中的一系列问题，提供一套适合我行的流程和协作解决方案。
Starlink 从交付用户价值的角度，通过全流程工具链打通及过程可视化管理，形成从“创意生成→需求设计→开发测试→发布运营→运维监控→需求反馈”完整价值流交付闭环；融入银行 EPG（Engineering Process Group过程改进小组）管理基线、安全 SDLC，实现端到端自动化。同时，我们的产品以用户为中心，从用户视角打造个人工作台。另外，产品也提供全面的精细化度量体系，通过数据来观察每个团队的效能，支持管理决策。
Starlink 适配金融行业特殊性，可以更好地支持组织级 DevOps 转型，面向监管，安全可靠；面向用户，灵活敏捷，快速创新。

Q：恭喜您通过DevOps 标准评估，此次贵公司项目通过的是系统与工具标准，您的感受是怎样的？
A：首先非常感谢信通院的专家对我们的指导和帮助，我们的平台在评估的过程中，专家老师为我们的产品和技术提供了很多的建设性意见；其次我想感谢我们团队的努力工作，从零开始一步一步将我们的规划变成现实；最后特别要感谢行领导及其他团队给予的支持与包容，让我们的产品有成长的空间。
今年 5 月份，工信部信通院正式发布了 DevOps “系统与工具标准”，这是全球首个  DevOps 国际标准，我们一直在关注，也知道这个标准的公信力和含金量。Starlink 产品在我行打磨了一段时间，因此我们足够的信心，前来参与这次工信部信通院举办的首批“系统与工具的标准”及“ DevOps 产品”标准评估。
此次通过 DevOps 标准评估，代表着我们的工具能力和功能得到了认可，产品建设正沿着正确方向在前行，同时，也表明我们的产品在一些方面站在了行业的前列。此次获奖也激励我们，持续迭代优化，保持创新和行业敏锐，把产品建设由点到线、由线到面深化，开放平台服务的能力支撑业务发展。

Q：打造端到端的流程化、一体化的工具链对落地 DevOps 有多重要，您对这个问题怎么看？
A：工具链是实践 DevOps，支持银行数字化转型的重要抓手。只有通过工具，我们才能够有效打通部门间壁垒，构建价值流，将工作可视化、杜绝浪费、识别和改善约束点等等实践落到实处；我们也才能让业务研发团队有规范的方式方法、易用的工具来持续获得用户的反馈，在 DevOps 实践的每一个环节都获得支撑。
所以我们认为工具链是 DevOps 转型实践的起点：通过工具的串接和运用加快研发流程，为业务团队提供高质量的产品，从而实现价值的快速流动和交付。我们希望通过 Starlink，把 DevOps 所倡导的敏捷、价值导向、效能为先、持续学习的研发文化注入到我们研发体系的基因中。

Q：贵单位参与本次系统和工具标准评估，请问企业有哪些考量？有科技输出的规划么？
A：DevOps 已经成为金融科技建设的重要组成部分，大量同业都在引入 DevOps 提升研发、测试、运维效率与质量。
信通院的 DevOps 标准关注组织流程及技术规范，侧重将 CMMI 及 ISO2000 等规定的工程要求进行落地。Starlink 在建设之初，也一直在对标此标准进行建设，我们参与此次评估，也是希望“以评促改，以评促建”。参与 DevOps 标准评估是希望借此找出自己和外界的优势和差距，为平台找一个共同的、可持续的目标，不断迈进。
关于科技输出，这是我们努力的方向。金融银行业的研发体系在对安全、合规方面的要求是不同于互联网的，我们的研发体系在这些方面有一些经验和心得，我们的Starlink 产品设计在安全、合规方面也有着比重相当大的考量。目前我们的Starlink产品已经应用于平安银行十余个不同形态的业务，相信随着我们的使用和探索，我们能够积累更多为银行金融业务研发赋能的经验和能力，为行业提供独特、有价值的研发赋能服务。

Q：通过系统和工具标准评估带给企业和团队哪些变化？
A：很荣幸，我们平安银行是首批通过 DevOps 系统和工具标准评估的企业。通过此次的首批评估，得到中国信通院的外部权威认可，较大地增强了 Starlink 的知名度和美誉度，能够有效提升产品在客户心目中的认知。同时也为我们带了来其他非常积极的影响：一是激励了我们的企业和团队，获得 DevOps 标准的评估代表着我们的能力和价值得到了认可；二是让我们在面对用户时更有信心；三是让我们知道，方向是正确的。让我们可以放开手脚，在正确的方向上持续做正确的事。

Q：您通过本次评估，项目的改进成果体现在哪些方面？
A：此次评估之后，我们对整个平台的运行数据做了一些对比和分析。以支付运营团队为例，在接入 Starlink 平台后，整个流水线构建时长大幅缩短 46%。团队处理需求、交付价值的效率大大提高：需求实现时效（需求开始澄清-开发-测试-投产发布完成）下降至 14.25 天，较上半年 36.2 天大幅缩短 60%。团队各项开发指标也得到了显著提升，首移有效率提升了 6%，自动化测试覆盖率提升了 33.1%，测试缺陷重修率下降了 42.5%。同时，由于研发效率、质量的提升，投产后生产问题工单数量大幅下降了 51.3%。总的来说，Starlink 平台对产品研发效能的促进作用是非常明显的。

Q：对于此次参评的项目规划和设计有哪些特色与不同？
A：Starlink 作为企业级 DevOps 产品，目前已为银行 16 个业务研发团队 8000+ 人员的科技队伍提供服务。
我们通过加快研发流程、打造高质量的、可靠的、安全的产品，从而实现价值的快速流动和交付。
纵向来看，打通了应用全生命周期（从需求、开发、测试、运维、安全等）工具集成。实现跨工具链的自动化。
横向来看，打通产品、架构、开发、运维、安全等部门墙。落地 DevOps 的协作文化。
另一方面我们打造了开放平台，通过汇聚行内工具，沉淀中台能力，优胜劣汰，建立研发工具集的良好生态，激发各业务研发团队进行工具和能力的创新。以此，我们形成高效开放的集成系统。

Q：在系统和工具标准评估过程中的困难与解决办法，可以分享一下吗？
A：Starlink 平台本身也是一个通过敏捷的方法不断迭代完善的产品，参评过程中，我们发现：对标标准中的一些能力，我们在比如兼容性、易用性方面的功能还有所欠缺。需要在正式评估前补足这些能力，以满足评估的需要，所以我们加大了测试，投入了资源来进行完善。
在这里，我们要特别感谢行领导的支持，其他团队的配合，为我们高效完成评估提供了非常大的帮助。

Q：对于 DevOps 工作的开展，下一步计划有几方面？
A：我们深信“好的产品是生长出来，而不是设计出来的”。接下来我们会进行较大规模的推广，让我们的产品能帮助到更多业务团队，深化赋能。在不断支持业务需求的同时，逐步完善优化产品能力，形成可持续、可拓展的正向循环。
在我们的规划里，Starlink 产品须具备“三层能力“：第一层能力，是“标准化/规范化”的产品，包括内嵌全行基线标准，建设开放平台；第二层能力，实现“自动化（AutoOps）”和安全（DevSecOps）,一键触发，高效安全；第三层能力，通过沉淀数据，实现信息共享，提供组织级度量分析能力，通过融入AI技术，实现智能化（AIOps）。
在围绕着三层能力建设的基础上，我们会扩展现有 Starlink 平台，融合 PaaS、IaaS  能力，更好地利用云计算、微服务、容器化能能力，打造开放技术平台，深化研发各个阶段的效能。

Q：对于 DevOps 的未来发展方向，您有何看法？
A：我们平时对 DevOps 相关技术发展是非常关注的，主流企业、研究机构，都是我们关注的目标。在 Gartner 最新的 2020 年“敏捷和 DevOps 成熟度曲线”中，那些预计 5 年以内成熟的技术，大部分是我们重点关注和实践的，5-10 年是我们持续关注的。我们认为，这个报告在一定程度与我们对 DevOps 未来发展方向的判断上是匹配的。

研发运营一体化（DevOps）能力成熟度模型介绍：
《研发运营一体化（DevOps）能力成熟度模型》系列标准是由中国信息通信研究院牵头，云计算开源产业联盟、高效运维社区、BATJ等顶级互联网公司以及各大金融、通信企业共同制定的国内外首个 DevOps 系列标准，由中国信息通信研究院主导的DevOps标准已在中国通信标准化协会（CCSA）立项在研。
与此同时，DevOps 标准已于2020年7月在联合国直属标准化组织 ITU-T 正式结项，成为全球首个 DevOps 国际标准。DevOps 标准评估体系主要包括敏捷开发管理、持续交付、技术运营、应用设计、安全及风险管理、系统和工具等部分。
