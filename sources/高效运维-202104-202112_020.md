**Q：您好，请介绍一下您和您的企业，以及此次参与评估的项目。****万化：**浦发银行（上海浦东发展银行股份有限公司）总行信息科技部规模超 4000 人，参加了信通院组织的第十四、十五批评估，共有 8 个系统参评。参评的系统分别为统一清算平台、缴费及支付系统、行业客户洞察平台、零贷指挥管理平台、零售合规风险监控系统、乐浦社区系统、靠浦薪数字金融服务平台、智慧办公管理系统。其中，统一清算平台是为满足各类中间业务资金清算需要，兼备清算业务管理功能的清算系统。主要有数据核对、清分、资金划拨等功能；缴费及支付系统主要应用于个人中间业务、个人及公司客户的缴费支付业务、第三方代收付业务等业务领域，主要功能有签约管理、对帐管理、批扣管理、联机处理等；行业客户洞察平台为沉淀行业客群洞察能力，形成行业分析的框架和样板，赋能客户经理，提供常态化专业分析，以助浦发拓增量，挖存量。主要功能包含行业趋势洞察、行业竞争分析、行业解决方案、行业新闻资讯、行业数据服务和行业数据管理；零贷指挥管理平台为提升对客户经理队伍营销和外拓方向的穿透指导，提供队伍状态监控模块、KPI目标跟踪、资源配置调度、任务管理调度功能；零售合规风险监控系统基于大数据分析技术，围绕个人、机构、业务等多个维度，提供全行理财合规销售执行情况可视化分析结果，实现总分行穿透式管理；乐浦社区系统旨在通过构建扁平化直通式沟通平台，鼓励员工发声、知识分享、建言献策激发基层活力，促进信息交流和创新交互，提升个人及组织的发展；靠浦薪数字金融服务平台通过平台数据内循环，实现差旅申请、机酒预定、智能发票管理以及报销代发的数据闭环，为中小企业打造一站式圈层生态服务；智慧办公管理系统旨在充分运用数字科技手段，建立行内统一办公入口和平台，以满足日常办公的精细、科学化管理和员工服务要求。该系统全面围绕“智慧”内核，加强制度化工作管理，保障流程运行稳定有序，持续推进服务智能化、可视化和移动化，助力办公效率提升，释放科技研发产能。  
**Q：恭喜通过 DevOps 标准评估，此次贵公司通过持续交付 3 级，表明达到了国内领先水平，您此时的感受如何？******万化******：**很高兴参评的 8 个项目组顺利通过了中国信息通信研究院开展的《研发运营一体化（ DevOps ）能力成熟度模型》持续交付 3 级能力评测，这是对浦发银行 DevOps 实践推广从试点阶段到规模化推广过程的肯定，是浦发银行在战略指引下落地科技敏态转型的一项重要成果，对浦发银行未来敏捷 DevOps 深化转型的推进起到了积极促进作用，特别感谢信通院各位专家在认证评估过程中对我们的帮助和指导。

此前，浦发银行的新型互联网贷款产品系统、金融 IC 卡业务系统、企业级微服务平台、资金监管业务系统、现金流分析管理系统等 5 个系统已通过 3 级能力评测。在此基础上，浦发银行通过持续优化改善研发流程，加快 DevOps 平台建设优化，进一步提升了持续交付能力。

  
**Q：贵公司是如何决定加入 DevOps 标准评估工作中的？********万化******：****信息通信研究院的《研发运营一体化（ DevOps ）能力成熟度模型》是国内统一的 DevOps 标准，内容覆盖全面，持续交付部分包含 7 大项、49 小项，涉及从需求到交付的各个方面。前两次的评估经历对我们 DevOps 实施工作有着很大的帮助，既提高了我们对 DevOps 研发过程的认知，也规范了项目组 DevOps 实践，对于我行 DevOps 转型起到很好的指导作用，因此我们果断地开展了第三次、第四次评估工作。  
**Q：通过 DevOps 标准评估对您企业带来了什么帮助？对贵团队有哪些影响？**********万化******：******通过参加信通院 DevOps 持续交付 3 级能力评估，对浦发银行加速 DevOps 转型起到积极作用。主要表现在以下两个方面：

1）参评项目组通过对标《研发运营一体化（ DevOps ）能力成熟度模型》持续交付3级能力标准，查漏补缺，规范研发团队需求、设计、开发、测试、运维的交付过程，帮助团队实现端到端的持续交付，提高团队的交付效率和交付质量，更好地为业务赋能。

2）浦发银行研发团队在参评过程中逐步形成了协作、共享的 DevOps 文化氛围，也培养了一批 DevOps 工程实践人才。

浦发银行将持续优化完善 DevOps 研发管理体系，持续为客户创造价值。

**Q：对于此次参评的项目，其 IT 系统有哪些特色，当时是怎么规划和设计的？**

**********万化******：********参评的 8 个系统在各个方面都存在差异。在系统定位方面，既有对客系统，也有内部管理系统；应用架构方面，既有微服务架构，也有单体架构；部署方式既有容器部署，也有虚拟机部署。

在改进方面，在保证各系统 DevOps 实践环节总体一致性的前提下，针对每个系统自身的架构及开发语言特性，提供差异化、定制化的改进方案。比如一致性体现在对 DevOps 研发过程、质量控制、自动化能力的要求上保持一致；差异化体现在对工具链、流水线搭建、触发方式、分支策略的选用上存在差异。

  

**Q： 此次通过评估的过程顺利吗？遇到什么困难？如何解决的？************万化******：********这是浦发银行首次 8 个系统参加评测，评估改进的难度较以前有所增加。首先，8 个项目组对于 DevOps 的理解有差异，改进前的现状和技术储备也有好有坏，改进的方向和节奏很难保持一致；其次，8 个系统技术栈、应用架构、部署环境均有差异；最后，由于各系统团队开发语言及部署环境有差异，工具链的选用需匹配系统交付需求，因此所选用的工具链存在差异。为了解决前述差异带来的困难，浦发银行在多个方面进行优化改进。首先，加强 DevOps 平台能力，集成各开发语言研发过程中所需的工具平台；其次，采用敏捷方式，将一个系统团队拆分成多个敏捷团队，加强沟通与协作；最后，利用容器服务提供弹性伸缩能力，同时保证部署环境一致性。

  

**Q：对于 DevOps 今年的实施，您觉得最大的收获是什么？您的下一步计划是？ ************万化******：********DevOps 是数字化转型成功的关键因素，工具赋能、人才支撑和文化是推动 DevOps 转型的核心要素。浦发银行 DevOps 下一阶段的目标包含以下三个方面：1）将参加信通院 DevOps 能力评估的改进经验推广到更多的项目组中，使更多的项目组能够了解信通院的 DevOps 标准，形成一套浦发银行 DevOps 实施标准；2）进一步提升 DevOps 研发平台能力，通过对 DevOps 平台不断优化和推广，加速浦发银行研发团队 DevOps 转型。3）通过推广 DevOps 转型实践，为浦发银行培养更多的 DevOps 技术人才。  
**Q：对于 DevOps 的发展前景，您怎么看？************万化******：********DevOps 通过平台、流程和人的有机整合，以协作、自动化、持续改进、共享文化为指导，旨在建立一种可以快速交付价值并且具有持续改进能力的现代化IT组织。DevOps 是数字化转型成功的关键因素之一，它不仅可以改善软件交付过程，同时也可以持续改善企业内部的工程师文化，提升员工信心，激发员工的活力和价值创造，从而帮助企业在数字化转型浪潮中获得更大的成功。提高研发效率，保证研发质量是研发团队始终追求的目标。DevOps 经过多年的实践，充分证明其具备提高研发效率，保证研发质量的能力。研发团队也逐渐不再讨论是否需要做 DevOps，而是更关注如何做好 DevOps，DevOps 这个名词将等同于研发。

**研发运营一体化（DevOps）能力成熟度模型介绍：**

《研发运营一体化（DevOps）能力成熟度模型》系列标准是由中国信息通信研究院牵头，云计算开源产业联盟、高效运维社区、BATJ等顶级互联网公司以及各大金融、通信企业共同制定的国内外首个 DevOps 系列标准，由中国信息通信研究院主导的DevOps标准已由工信部发布并被众多金融、通信和互联网等行业名企纷纷采用并通过评估。与此同时，DevOps 标准已于2020年7月在联合国直属标准化组织 ITU-T 正式结项，成为全球首个 DevOps 国际标准。DevOps 标准评估体系主要包括敏捷开发管理、持续交付、技术运营、应用设计、安全及风险管理、系统和工具等部分。![](../Images/c656d5dc0ae9a30269a21e7a55a88029.png)
