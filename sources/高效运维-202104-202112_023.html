各大企业的实践及相关数据表明，标准化和工具赋能是企业成功的关键。DevOps 标准及基于标准的 DevOps 持续交付流水线平台，能有效针对企业软件研发提质增效，不仅更快更灵活，也大幅度提高企业核心竞争力！

2021 年 11 月 18 日，由高效运维社区（GreatOPS）和开放运维联盟（OOPSA）、DevOps时代社区联合主办的 GOPS 全球运维大会在上海隆重开幕。全球运维大会是国内第一个运维行业大会，面向互联网及传统行业、广大运维技术人员，旨在传播先进技术思想和理念、分享业内最佳实践。

会上，中国信息通信研究院华东分院院长张雪丽女士隆重发布了 DevOps 标准持续交付第十五批评估结果。交通银行股份有限公司（以下简称“交通银行”）本次参评项目为智慧人资项目和跨境金融项目，两个项目顺利通过由中国信息通信研究院（以下简称“信通院”）开展的《研发运营一体化（DevOps）能力成熟度模型》持续交付 3 级评估。


评估单位：中国信息通信研究院

此次，我们采访了交通银行金融科技部总经理李肇宁先生，一同深聊团队在项目参与评估时的细节和故事，分享交通银行 DevOps 实践的经验。


- Q&A -

交通银行金融科技部总经理 李肇宁

Q：您好，请介绍一下您和您的企业，以及此次参与评估的项目。
李肇宁：我是交通银行金融科技部的总经理李肇宁。首先非常感谢信通院和评审专家对交通银行敏捷和 DevOps 转型成果的肯定。
交通银行是一家有着百年历史的国有金融企业，也是中国首家全国性股份制商业银行。自 2002 年以来，交行的信息化建设历经数据大集中、“531” 工程、“新531”工程等阶段，逐步提升科技赋能业务水平，为集团业务高质量发展注入动力。金融科技工作在深化改革、科技赋能、数据治理、架构转型、风险防控、稳定运行各方面取得成效，并积极运用大数据、云计算、人工智能、区块链等新兴技术开展金融创新，助力业务转型，向线上化、数字化、综合化、开放化、智慧化迈进，有效赋能业务高质量发展。
本次参评有两个项目，一个是跨境金融系统，负责对接各类跨境金融业务，为海关总署，航天电子，深圳采购平台等客户数据进行加签、验签、识别反洗钱以及控制汇款和融资等功能。另一个是智慧人资系统，为全集团员工提供基于 AI 大数据以及移动端的数字化人事管理、薪酬管理、干部管理、教育培训、考勤、绩效等智慧化的人力资源管理平台。

Q：恭喜通过 DevOps 标准评估，此次贵公司两个项目均通过持续交付 3 级，表明达到了国内领先水平，您此时的感受如何？
李肇宁：很高兴能够通过 DevOps 持续交付能力成熟度 3 级评估。这两个项目是总行软件开发中心首批参评项目，也是我们着力打造的 DevOps 持续交付实践的标杆项目。本次对标和评估，交通银行以问题为导向，解决实际难题，以创造价值为原则，找差距抓落实，历经 17 轮迭代，近 10 个月攻坚克难，累计改进组织级平台工具 57 个问题，项目团队 113 个问题，最终顺利通过评估，得到了业界专家对我行敏捷和 DevOps 转型的肯定。

Q：贵公司是如何决定加入 DevOps 标准评估工作中的？

李肇宁：交通银行一直以来都是高度关注业界新技术、新理念的发展动态，积极探索新方法、新实践的落地应用。我行 2019 启动敏捷和 DevOps 建设，2020 年大力推广 DevOps 平台，已应用在超过 200 套系统的研发过程中，2021 年启动 DevOps 标准评估一方面是对标行业先进，学习最佳实践，另一方面，也是借用 DevOps 标准来检验我行敏捷和 DevOps 转型成效。


Q：通过 DevOps 标准评估对您企业带来了什么帮助？对贵团队有哪些影响？
李肇宁：通过 DevOps 标准评估，首先是交通银行项目团队在持续交付能力上的肯定，也表明我们部分项目团队的 DevOps 实践能力达到了业界领先水平。通过 DevOps 标准我们明确了目标和改进方向，在组织层面进行了基于标准的最佳实践比如以端到端交付流水线为核心，打通各项工程活动，为研发人员提供统一的开发测试运维一体化平台，规范研发交付全过程，内嵌质量标准，实现统一的过程管理和监控。在项目层面进行落地并持续改进，形成融合协作的 DevOps 文化，有效支撑我行数字化转型工作，提升了对业务响应能力和 IT 自动化水平及研发效率。同时 DevOps 工具平台也为我行十四五金融科技规划重塑业务流程、建设开放式企业架构、强化科技引领的落地实施提供更快捷更高效的工具支撑。

Q：您可否详细的介绍一下，通过本次评估有哪些改进成果？
李肇宁：通过本次评估，以我行标准软件过程和 DevOps 标准为基础，建立一套顺畅、高质量、可行动的效能度量体系，贯穿需求管理、开发质量、持续集成、持续构建、测试、发布部署等研发全流程共 47 个度量指标项，实现研发数据统一管理和研发端到端数据可视全景视图。各项目团队可持续关注度量结果并进行持续改进，实现效率提升。两个参评项目的主要效果展现在以下几方面：自动构建成功率 90% 以上、日均构建次数 5 次以上、接口测试覆盖率 100%、集成修复时长小于 1 小时、流水线平均时长：5~10 分钟、每个投产批次节省 2 人天。两个项目团队具体工程能力如下：


Q：对于此次参评的项目，其 IT 系统有哪些特色，当时是怎么规划和设计的？

李肇宁：在充分调研同业评级项目情况，本着全面提升，打造标杆的原则，首先在对客业务系统中选取跨境金融项目，该项目采用传统稳态研发管理模式，团队意愿性较高，在行内有一定的影响力和代表性。其次从敏稳双态开发模式项目中选取智慧人资，该项目是我行内部重要的管理系统，采用敏捷研发管理模式，是敏捷标杆示范项目，团队自组织程度较高，已建立测试分层体系和 DevOps 流水线，有一定的先进性和创新性。

在评估过程中通过赛马机制，充分激发两个项目创先争优的活力，比如在数据管理方面跨境金融率先达到 3 级，而在测试管理方面智慧人资率先达到 3 级。在评估完成后期望能以点带面，快速复制过级的两个项目经验，推广到其他系统。

Q： 此次通过评估的过程顺利吗？遇到什么困难？如何解决的？
李肇宁：万事开头难，在我行金科部、开发中心、测试中心、数据中心共同努力下，伴随每轮迭代演进和迭代回顾，逐步缩小与标准的差距，提升各项度量指标，增强团队信心，总结下来过程是艰辛的，结果是成功的，遇到的困难主要有如下两点：

第一是打破部门墙难度较大，跨部门的需求和问题推进缓慢。DevOps 强调开发、测试和运维的融合以及端到端交付价值。借助 DevOps 评估，我行从高层对齐目标、建立联合工作小组，明确分工，责任到人，定期可视化项目进展和按需求开展专项会议解决难点，有效推进评估工作的顺利开展。比如打破部门壁垒，实现从生产端部署数据到开发测试端的闭环反馈，统一测试和生产部署的步骤和工具等跨部门改进工作。

第二是业务和技术融合有待加强。在参评项目里，跨境金融因服务第三方客户以及关联行内的系统较多所以在需求拆分和投产交付比智慧人资难度更高，在标准过级改造中，除持续交付改进工作外，也通过让业务部门深入参与到交付过程、技术部门提前参与需求规划和问题挖掘，业务和技术实现深度融合，共同做好需求分析和版本排期等工作来保障客户需求的及时响应。


Q：对于 DevOps 今年的实施，您觉得最大的收获是什么？您的下一步计划是？ 
李肇宁：最大的收获是看到了两个试点项目的软件质量和研发效率得到显著提升，能够更快速的进行业务价值交付。后续将结合我行实际情况持续和深入地开展优化和实践落地，主要围绕以下方面，首先借助信通院的 DevOps 标准做本地化改造，建立适合交行的 DevOps 标准，其次进一步完善已有 DevOps 工具平台，做好更大范围的推广和落地，提升组织级的 DevOps 能力，最后还将结合我行十四五金融科技规划，建立企业级 DevOps 工具平台，支持全集团总分行研发，实现研发全过程可视化、云上和云下标准化以及自动化持续交付能力。

Q：对于 DevOps 的发展前景，您怎么看？
李肇宁：DevOps 近几年发展迅速，与时俱进，新的管理理念层出不穷，例如最近提出的 DevSecOps、ChatOps、AIOps、AgileOps 等，与当前金融行业的数字化转型深度融合，DevSecOps 将已有的安全合规标准化和自动化落入持续交付中，强化内控合规管理，提供高质量发展基石；AgileOps 从精益需求管理流程、敏捷过程管理和 CICD 工程实践入手，全面提升对用户需求快速响应。未来我们也会继续关注 DevOps 的前沿发展并保持探索和实践，持续推进交通银行 DevOps 建设，将业界最佳实践与交通银行实际工作相结合，进一步打造 DevOps 全流程体系与平台，以高水平金融科技能力赋能业务高质量发展！

研发运营一体化（DevOps）能力成熟度模型介绍：

《研发运营一体化（DevOps）能力成熟度模型》系列标准是由中国信息通信研究院牵头，云计算开源产业联盟、高效运维社区、BATJ等顶级互联网公司以及各大金融、通信企业共同制定的国内外首个 DevOps 系列标准，由中国信息通信研究院主导的DevOps标准已由工信部发布并被众多金融、通信和互联网等行业名企纷纷采用并通过评估。
与此同时，DevOps 标准已于2020年7月在联合国直属标准化组织 ITU-T 正式结项，成为全球首个 DevOps 国际标准。DevOps 标准评估体系主要包括敏捷开发管理、持续交付、技术运营、应用设计、安全及风险管理、系统和工具等部分。
