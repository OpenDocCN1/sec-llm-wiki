**使用 SAP 面临的监控管理****挑战**

![](../Images/d43e91ddc5fa7045e0b737f9e31f0583.png)

  

全球范围内，企业广泛采用SAP作为其重要的IT系统，例如在大中华区，截止2021年第一季度，SAP拥有超过16,000家企业客户。据统计，全球 77% 的业务交易在某种形式上涉及与SAP有关的系统。

  

很多企业的应用系统完全依赖于SAP，通过SAP的功能来为他们的最终客户服务。而更多的公司则利用SAP的定制化功能，在不同的平台上实现他们的业务需求。SAP广泛应用于企业的前端、电子商务平台、后端、物流、研发、制造、供应链、采购等各个领域。

  

然而，被如此广泛使用的SAP，企业对其进行监控管理时却遇到了3大挑战：

1.  无法对SAP实现代码级的监控。
    
2.  难以管理和辨别SAP系统的关键告警。
    
3.  不能将SAP问题与关键业务交易关联起来。
    

SAP的基础组件是 Netweaver 应用服务器，它是用 SAP 专有的编程语言 ABAP 开发的，因此 SAP 的应用服务器无法像基于Java语言或者 .Net语言开发的应用服务器那样支持代码级的性能问题监控。企业运维人员也就无法准确地找到性能问题的根源。

  

SAP内置了一个叫做 Solution Manager 的管理工具，这是个很大的 SAP 生命周期管理工具，它涉及了许多方面，但是在监控SAP，尤其是Netweaver应用服务器上，它只能提供基于静态阈值的告警信息，因此经常导致使用Solution Manager的运维团队陷入告警风暴之中。并且，因为Solution Manager 缺乏代码级的深入监控能力，所以它很难将发现的SAP问题同SAP运行的业务关联起来。

  

此外Solution Manager是专门针对SAP的管理工具，无法管理企业的其它应用系统，也很难与第三方监控管理工具集成。如果企业要同时管理SAP与非SAP环境，则需要多个单独的管理工具，以致形成运维孤岛。

  

上述三大挑战导致目前使用SAP的企业在监控管理上存在以下三种不理想的情况：

1.  企业使用不同的工具监控不同的IT环境，形成完全孤岛式的运维模式，无法正确评估不同的被监控环境之间的相互影响，无法确保业务的稳定运行。  
    
2.  企业使用不同的工具监控不同的IT环境，手动建立不同监控环境之间的关联，不仅消耗大量的人力成本和时间成本，而且由于缺乏工具的辅助，其效果很差，对于解决影响企业业务的性能问题的帮助十分有限。
    
3.  企业完全凭借人力管理整个企业的IT环境，不借助任何工具。这样做也许10年前还是一种选择，但面对处在数字化转型的今天的企业IT环境，其效果很可能还不如上一种模式。
    

  

处于数字化转型的今天，企业面临的一个新的挑战就是IT环境的日益复杂化。云、微服务、持续交付以及SAP自身的不断演化都使得运维的难度不断增大。如果没有统一有效的监控管理手段，则想要实现企业业务的稳定运行就是不可能的任务。

  

SAP支撑着企业的关键业务，但是对SAP进行监控管理却遇到了棘手的挑战。

**考量 SAP 监控管理解决****方案****的三个标准**

![](../Images/d43e91ddc5fa7045e0b737f9e31f0583.png)

  

**01**

**可见性**

  

可见性有两个方面的考量：

  

**1.1在SAP环境中的深度可见性**

是否对 SAP Java平台和SAP ABAP平台均可以实现代码级的监控深度，从代码级的层面构建SAP环境内部的端到到的业务交易性能监控管理。

  

**1.2在整个企业IT环境中的广域可见性**

是否能够在使用SAP的企业内部实现完整的、跨系统的端到端业务交易监控，将业务交易从非SAP环境关联到SAP环境（反之亦然），从而实现对整个企业范围内的端到端的业务交易监控。

  

**02**

**高可用性与优化能力**

  

鉴于SAP对于企业业务的重要性，针对SAP的监控解决方案不应该只是在问题出现后才解决，而是应该利用当前最先进的人工智能深度学习等技术手段，提前预警有可能影响到企业关键业务与用户体验的潜在性能问题。同时需要具备监控解决方案利用性能基线与动态阈值的能力，向企业提供精准的性能告警。通过这些功能特点，帮助企业不断优化SAP的运行性能。

  

**03**

与业务的关联度

  

SAP上运行着重要乃至核心级别的业务交易，同时SAP本身也是一个极为复杂的IT环境，在定位和解决SAP中出现的性能问题时，运维人员往往因为问题的复杂性而搞的一头雾水，并且SAP对业务的重要性也使运维人员感到巨大的压力。将业务内容与SAP发生的问题相关联，可以帮助IT运维人员快速准确地了解IT问题对业务的影响程度，快速准确地定位性能问题的根源。并依据业务内容提出有效的性能问题解决方法。

**主动实时分析 SAP 与非 SAP 环境**

SAP是一个庞大复杂的系统，拥有众多模块，采用手动设置静态阈值的办法对各个模块的运行状态、性能指标进行监控不仅仅耗费大量的精力与成本，而且无法监控到引起SAP性能问题的根源。

  

RPOS则基于整个SAP环境中发生的所有业务交易，对交易涉及的SAP的方方面面的指标进行整体监控，并将零散的性能指标同SAP业务交易运行性能、和用户体验结合起来。

  

在此基础上，RPOS将SAP环境和非SAP环境结合起来，从企业的整体业务系统的角度进行监控管理。借助该服务，运维人员能够快速发现导致用户体验下降的问题，并利用RPOS快速定位问题根源，快速解决问题。

  

RPOS还利用基于人工智能、深度学习等技术的动态基线和动态阈值取代静态阈值。动态基线和动态阈值为企业运维团队带来两大收益：

**第一、可以对性能问题提前发出预警。**

  

比如在假日购物或其他季节性活动、产品发布和其他业务活动时期，PROS 向运维人员预警因为突发性大流量导致的用户体验下降，从而使运维人员提前做出反应，避免突然出现的性能问题给企业带来的收益损失。

  

**第二，减轻运维负担，提高运维效率。**

  

PROS 可以过滤掉无用的误报警告，帮助运维人员摆脱告警风暴的困扰，同时避免关键告警漏报的现象，提升运维工作的效率。

1\. 从监控到的SAP事务中获取的业务数据。

2\. 量化的性能问题及其对业务的影响。

3\. 待解决的性能问题的优先级。

RPOS实时从SAP中获取业务数据，赋予企业运维人员两大重要能力：

  

1、针对关键 SAP 流程（例如从订单再到采购再到付款这样的流程）构建业务流视图，从而更深入地了解企业核心业务的流程。

  

2、通过业务流程健康度指标和全面的SAP环境监控功能，准确定位影响或者潜在影响核心业务的关键性能问题。

  

例如在财务上可能出现这样的关键性能问题：发票创建的过程耗时过长，导致采购业务受到严重影响，采购人员的用户体验也大幅下降，最终致使企业收益受损。

  

RPOS能够帮助企业运维人员准确定位影响核心业务的关键性能问题，从而加速解决性能问题，同时也为业务大数据分析提供了数据来源。
