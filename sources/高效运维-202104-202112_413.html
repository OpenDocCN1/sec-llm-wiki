燃！安信证券通过 DevOps 持续交付标准 3 级评估，相关项目能力达到国内领先水平！

编者按：从各大企业的实践来看，标准化和工具赋能是科技公司成功的关键所在。DevOps 标准及基于标准的 DevOps 持续交付流水线平台，使得企业的软件研发效能飞速提升、更快更灵活应对市场变化，助力IT成为企业的核心竞争力之一。

2021 年 5 月 21 日，由云计算开源产业联盟（OSCAR）指导，由高效运维社区（GreatOPS）和开放运维联盟（OOPSA）联合主办的第十六届 GOPS 全球运维大会在深圳正式召开。GOPS全球运维大会至今已经举办了 15 届，是国内第一个也是最大的运维行业大会，也是备受瞩目的千人峰会，面向互联网及金融、通信等传统行业广大运维、开发等技术人员，传播先进技术思想和理念，分享业内最佳实践。
会上，中国信息通信研究院隆重发布了 DevOps 标准持续交付第十二批评估结果。安信证券股份有限公司（以下简称“安信证券”）本次参评项目为互联网客服平台，该项目顺利通过由中国信息通信研究院（以下简称“信通院”）开展的《研发运营一体化（DevOps）能力成熟度模型》持续交付 3 级评估。DevOps 标准共分 5 级，持续交付部分如果能达到 3 级已经是国内领先水准，这代表着安信证券在参评项目的持续交付能力达到国内领先水平。
此前，安信证券的手机证券交易服务中台项目和用户中心项目已通过持续交付 3 级评估（相关新闻稿链接详见文末）。
评测单位：中国信息通信研究院。
由中国信息通信研究院云计算与大数据研究所所长何宝宏博士为安信证券授牌：

▲DevOps评估结果公布现场

此次，我们采访了安信证券的 CIO 许彦冰女士 ，一同深聊团队在项目参与评估时的细节和故事，分享安信证券 DevOps 实践的经验。

-Q&A-

安信证券 CIO 许彦冰

Q：请介绍一下企业以及此次团队参与评估的项目。

许彦冰：大家好，我是许彦冰，目前担任安信证券信息技术总监、兼信息技术委员会主任。安信证券是国家开发投资集团有限公司旗下的证券公司，是一家全牌照综合类券商，多项业务排在行业前列。信息技术委员会作为公司数字化转型和金融科技创新的总部执行部门，为公司 700 多万客户在股票交易、理财投顾等多个金融领域提供完善、可靠的交易 IT 服务。

此次参评的互联网客服平台项目，是公司打造的 7*24 小时在线服务平台。平台集约全公司分散的服务资源和全体员工碎片化服务时间，联合智能客服系统，为海量客户提供“在线即时问答”服务，随时随地响应客户咨询需求，解答客户投资理财困惑，并以服务持续带动营销，不断提高公司业务市场份额。


Q：恭喜安信证券通过 DevOps 标准持续交付3级评估，表明达到了国内领先水平，感受如何？

许彦冰：对于互联网客服平台项目能通过 DevOps 持续交付 3 级标准评估，我们感到非常开心。该项目是我司第三个成功通过该评估的项目。项目团队在借鉴前两个项目优秀实践的基础上，结合系统自身的技术特点和团队的特点，查漏补缺，在搭建中后台端技术栈持续交付支撑能力之外，补足了当前 APP 端持续交付的能力，切实提升了公司整体 DevOps 持续交付应用能力和管理水平，同时形成了适合安信证券的标准规范，并内化到工具和流程中，为全公司的 DevOps 推广打下良好基础。在评估的过程中，我们再次得到了信通院专家的肯定和认可，这不仅是对互联网客服平台项目组持续交付能力的肯定，也是对安信证券 DevOps 能力的一个认可。


Q：安信证券是如何决定加入 DevOps 标准评估工作中的？
许彦冰：此次互联网客服平台项目是安信证券参加 DevOps 标准评估的第三个试点项目，并与前面两个试点项目的业务类型和技术栈进行互补。在决定加入 DevOps 标准评估之初，由于公司业务持续发展，对应建设和管理的信息系统不断增多，IT 团队规模也持续扩张，IT 团队人数已超过 800 人，原来以项目作为研发和管理单元的模式导致上下游互相依赖和耦合，透明度不足。研发过程通过零散的工具进行支撑，各个项目团队使用不同的工具，缺少组织级的统一工具平台，各工具之间未能打通和联动，未能形成高效稳定的版本构建和发布。
此外，整体的单元测试和自动化测试程度不高，仍以手工测试为主，测试工作和安全检测工作在研发的后期才参与进来，整个研发过程缺少数据的跟踪和度量，难以满足业务需要快速发布和持续改进优化的要求。而这些问题恰恰可以通过 DevOps 推广和落地得到很好的解决。因此，我们持续推进 DevOps 标准评估的工作实际上是想通过持续的行动来宣贯和落实以 DevOps 为核心的敏捷研发体系，通过参与标准评估，切实推行研发转型，达到为 IT 研发提质增效的目的，并以这些试点项目作为标杆，带动其他团队深度参与到公司敏捷研发的转型之中。

Q：通过 DevOps 标准评估对企业带来了什么帮助？对团队有哪些影响？
许彦冰：当前证券行业数字化转型势在必行，证券公司要进一步把握金融科技的机遇，努力夯实数字化转型的技术底座，达到与互联网公司一致的快速响应能力和出色的服务能力，才能应对行业快速发展带来的压力，在数字化转型过程中占据有利的市场位置。为此，我们将坚定不移地推行以 DevOps 为核心的敏捷研发体系，从研发组织结构、研发过程、研发平台、研发度量及持续改进机制各维度入手，构建组织级的敏捷研发能力，助力公司实现数字化转型。
本次互联网客服平台项目通过评估对于我们意义重大。在项目的评估工作过程中，我们查漏补缺，持续打磨完善平台能力，当前安信证券的研发管理平台服务覆盖了 Java、H5、Android、iOS 等技术栈，覆盖自研系统约 90% 的技术栈。通过持续参与 DevOps 标准评估工作，安信证券 DevOps 研发管理平台愈发完善，安信证券的 DevOps 推广也步入全面推广阶段。互联网客服平台、用户中心、手机证券交易服务中台三个试点项目相继通过了DevOps 标准评估是安信证券构建敏捷研发管理体系的关键里程碑，实现了多团队的 DevOps 接入、多技术栈研发服务支持的试点目标，研发团队在过程中得到充分的锻炼，信息系统也得到进一步的完善，为安信证券的敏捷研发管理体系的全面推广奠定了坚实基础。

Q：团队项目通过本次评估有哪些数据指标可以直观的体现项目改进成果？

许彦冰：通过 DevOps 的转型和持续改进，项目组在需求、开发、测试、部署等方面能力均取得明显提升。其中核心指标上，相关项目的单元测试覆盖率从 30% 提升到 75% 以上，自动化测试比率从 40% 提升到了 80%以上，其中自动化测试成功率更是达到 99%，整个流水线的执行时间在 8 分钟内可以执行完成，而在快速迭代的周期中，平均开发交付周期低至 5.7 天，较原来每个版本一个月的交付周期，提升超过70%。类似这样的数据在持续跟踪并不断改进。


Q：对于此次参评的项目，其 IT 系统有哪些特色，当时是怎么规划和设计的？
许彦冰：本次参评的互联网客服平台项目主要目标是集约公司员工服务资源，结合智能客服，为客户提供 7*24 小时的在线咨询服务，解答客户投资理财困惑，并以服务持续带动营销。互联网客服平台模块包括了 IM 服务、后端服务、数据库以及前端的 Android、iOS 和 H5，整体覆盖了当前前端、后端的主流技术栈。较公司之前参评的项目增加了 APP 端的部分，同时补充了 APP 的测试、性能、兼容性、安全等规范。我们挑选出的三个项目参与 DevOps 持续交付评估，基本上覆盖了安信证券所有自研的技术栈，手机证券交易服务中台项目主要是基于 Java 技术栈，用户中心相对手机证券交易服务中台多了前端 UI 和数据库，本次参评的互联网客服平台相对用户中心又多了 H5、Android 和 iOS 客户端。我们希望通过以上三个项目的评估改进过程，完善工具平台和流水线能力，基本覆盖支持所有自研系统的技术栈，为后续推广 DevOps 持续交付覆盖全部自研系统夯实基础。

Q：团队参与评估的过程还顺利吗？遇到哪些困难？如何解决的？
许彦冰：在互联网客服平台之前公司已经积累了两个项目的经验。在工具平台的建设和流水线方面，开发、测试、安全、运维各个阶段和流程方面都已经积累了很多经验。本次互联网客服平台主要是增加了 APP 相关的持续集成和发布过程，APP 的流水线、测试和检测与后台项目有很大区别。为了应对 APP 的流水线接入的挑战，我们对 APP 的编译构建、制品晋级、测试、安全检测等方面和环节进行了整体梳理，并制定了完整的可行性的解决方案，比如 iOS 的代码质量规约、APP 的制品晋级、APP 的测试和安全检测方案等，这些都可以作为组织级的规范，为平台后续的整体推广打好了坚实的基础。整体来说，团队积极拥抱 DevOps 整体协同、研发运维一体化的思维，不断完善平台的工具链和交付流水线，丰富研发过程中的最佳实践。在这个过程中，安信证券自身的研发管理制度和规范也得到进一步的完善。

Q：对于安信证券 DevOps 的实施，团队最大的收获是什么？下一步计划有哪些？

许彦冰：在参与 DevOps 持续交付标准评估工作的过程中，安信证券不断优化 DevOps 研发管理平台，实现了覆盖安信证券研发过程的绝大部分技术栈，包括 Java、iOS、Android、H5 和数据库变更等技术栈的研发过程支撑和管理，并针对研发过程实施 CICD 自动化流水线，不断完善度量运营平台，基于指标和数据的自动化分析并推送问题的改进建议，实现持续度量和持续运营的闭环。

未来，安信证券将进一步完善敏捷的研发管理体系。一方面，安信证券将保持精益求精的匠心，完善 DevOps 研发管理平台、打磨平台和工具并坚定不移地推广 DevOps，为研发团队打造出围绕研发过程的一站式研发支持服务门户，实现一套流程、一个门户、一站式服务；另一方面，我们将在研发流程上进一步标准化、规范化并实现规模化管理，通过结合 CMMI 的标准化要求，赋能敏捷研发过程，以客户价值为驱动，将研发过程向前往业务端延伸，向后与服务运营、业务运营相结合，为客户和业务提供更大价值。

Q： 对于 DevOps 的发展前景，有哪些看法？

许彦冰：DevOps 起源于互联网环境，主要宣导并推动开发和运维团队之间的融合，并以自动化为主要技术手段贯穿团队之间的协同，实现 IT 的高效交付，本质上是采用系统思维的方式解决实际问题。

未来，随着金融企业进一步的开展数字化转型和变革，对于企业来说，业务和 IT 的融合必将成为其数字化生存的关键。在业务即 IT，IT 即业务的数字化背景和转型诉求之下，DevOps 的内涵将持续的扩展并焕发新的活力，其侧重点将从 IT 内部的融合和协作，进一步往前延伸并往后拓展，往前延伸到业务侧，真正实现以客户价值为驱动，往后拓展到运营侧实现自动的持续改进，形成业务、研发、运营的完整闭环。同时，随着容器云平台、人工智能和大数据等的飞速发展，DevOps 的实现方式将更加的一体化和智能化。

研发运营一体化（DevOps）能力成熟度模型介绍：
《研发运营一体化（DevOps）能力成熟度模型》系列标准是由中国信息通信研究院牵头，云计算开源产业联盟、高效运维社区、BATJ等顶级互联网公司以及各大金融、通信企业共同制定的国内外首个 DevOps 系列标准，由中国信息通信研究院主导的DevOps标准已由工信部发布并被众多金融、通信和互联网等行业名企纷纷采用并通过评估。
与此同时，DevOps 标准已于2020年7月在联合国直属标准化组织 ITU-T 正式结项，成为全球首个 DevOps 国际标准。DevOps 标准评估体系主要包括敏捷开发管理、持续交付、技术运营、应用设计、安全及风险管理、系统和工具等部分。
