# SRE 未来发展的 5 种趋势！

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzA4Nzg5Nzc5OA==&mid=2651698518&idx=4&sn=d7918db2a657989aa5c783df6817b9f0&chksm=8bcb76ffbcbcffe9f27cbb9fe22962e3b9df94bd7d1925c55b36b4f3a37760d94c6ace952b89&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzA4Nzg5Nzc5OA==&mid=2651698518&idx=4&sn=d7918db2a657989aa5c783df6817b9f0&chksm=8bcb76ffbcbcffe9f27cbb9fe22962e3b9df94bd7d1925c55b36b4f3a37760d94c6ace952b89&scene=27#wechat_redirect)

最初由 Google 牵头发起的 SRE（站点可靠性工程），极大地引起了人们的兴趣，2021 年，SRE 工程师在许多组织中将继续增长和发展。SRE旨在为应用程序可靠性寻求更明智的责任。SRE 团队设置服务水平指示器，为新功能制定错误预算，并使用诸如应用程序性能监视（APM）之类的工具来可视化性能见解以及其他任务。随着新的数字创新，SRE 迅速成为增加业务产出的关键检查。在SRE发展的几年后，SRE 的发展主要有以下五种方式：

### **1.增加采用**

首先，并非所有公司都接受 SRE 模型。最新研究发现：“……50％的受访者使用SRE模型，由专注于基础架构和工具的专门工程师使用，或者是将全职SRE分配给服务的嵌入式模型。”

### **2.规模更大，种类繁多的 SRE 部门**

许多公司正在经历不断增长的用户需求，因此必须迅速扩展其应用程序网络。同时，寒武纪出现了部署类型的爆炸式增长-系统可以使用各种旧式基础架构，大型机，微服务，云环境和多个云供应商。由于技术堆栈日益复杂，SRE 现在必须涵盖许多领域。因此，SRE 部门可能需要一支更加多元化的领域专家团队。

### **3.将会出现新的测试策略**

SRE部门将引入新的监视和测试方法来保持可靠性。其中之一是混乱工程，它倡导有意破坏应用程序系统的想法。毫无疑问，将出现各种策略来帮助推动用户体验（UX）并确保始终将性能放在首位。

### **4.企业依靠 SRE 减轻风险**

SRE 接受故障并学会管理故障，设计可重复的操作缓解结构。无论是减少平均维修时间（MTTR），对服务水平指示器进行编程，以监视网站加载时间，还是为新功能引入而预测错误预算，都将越来越依赖 SRE 来维持业务稳定性和高性能。**“ SRE的心态是要适应无可指责的环境。” ****5\. SRE 引导 UX**在这种纯数字环境中，“应用程序已成为企业，” 如果该应用程序是业务的核心，则必须监控用户旅程以改进它。SRE监督着一个独特的领域，这也可能产生有价值的业务见解。除了监视正常运行时间以确保 URL 响应时间满足 SLA 之外，SRE还可以跟踪与 UX 相关的见解，例如转换率或购物车放弃率。跟踪此类分析并设置标准基准可以帮助查明影响 UX 的问题。它还可以帮助产品开发设计性能更好的软件。
