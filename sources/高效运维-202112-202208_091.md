# 助力研发效能提升，工行运维转型的“四”大法宝，速速收藏

> 主要从事大型主机核心系统、云平台及分布式技术框架研发环境的运维管理及自动化研究工作，在大型主机核心银行向分布式云架构转型过程中，为应用研发测试提供快捷稳定的环境保障服务。

  
在软件研发生命周期中，研发测试环境是应用代码转化为业务产品价值交付的必经之路，为软件产品部署及测试验证提供必备条件，同时在此阶段的软件产品是不成熟的，而稳定和易用的研发测试环境能够极大提高开发者的工作效率和幸福感。不同于生产环境，研发测试环境具有版本部署频繁、环境需求多、业务测试干扰多、资源配置低等特点，而理想的研发测试环境应该是自由连接、随时可用、互访可控。近几年，中国工商银行软件工行开发中心（以下简称工行开发中心）以“共建、共治、共享”为指导思想，构建“协同、精细、集约、智能”的研发测试环境运维体系，聚焦研发测试环境的稳定和可用，为研发效能提升注入了“新动能”。  

**一、研发测试环境运维特点**

工行开发中心研发测试环境中的应用版本总体上仍然是按月度版本节奏规划，多版本并行开发，同时适应项目敏捷迭代、灵活交付、灵活投产等节奏，工行开发中心针对研发测试不同阶段规划了相适配的应用开发自测环境、集成主测环境、回装验证和投产演练环境；针对不同测试场景或重点项目按需提供了性能测试、账务验证、混沌测试、下主机验证等专项测试环境，同时，应用系统正处于分布式转型阶段，现阶段主机与开放平台双核心并存、应用云与虚拟机环境并用、分布式微服务与传统单机应用相辅，以及服务与服务之间版本和数据一致性要求高等情况，研发测试环境呈现如下特点：

一是应用系统架构复杂、测试场景多样化、环境规模庞大；二是版本部署频繁，版本质量存在结构性差异；三是应用间服务及数据关联强，上下游应用环境相互干扰多，应用服务调用链路长，问题排查困难；四是自动化水平不高，运维效率低。

**二、工行开发中心研发测试环境运维实践**

工行开发中心积极应对行内应用系统架构转型的挑战，在长期的工作实践中，逐步摸索出了一套行之有效的研发测试环境管理办法，聚焦“协同化治理、集约化运维、精细化管理、智能化驱动”等四化建设，逐步打造了高效灵活的研发测试环境运维管理体系，保障了环境的稳定、可用。

![](../Images/eed3c283a0a41279c7f7a253c4f262fe.png)

1.  **强化协同化治理**，构建跨地域、一体化的分布式协同运维组织体系。目前工行开发中心研发部七地十八址，为协调各地研发测试环境管理，确立了共建共治共享的运维理念，强化组织保障，建立运维标准，规范管理流程。包括成立研发测试环境专项提升小组、建立跨研发部的问题解决和协调机制、组建环境动态研究团队、实施智能运维平台化开发等。
    
2.  **深化精细化管理**，加强规范建设和标准实施，保障研发运维有序开展。以流程制度为抓手，规范研发测试环境使用，同时兼顾运维统一性和差异性、稳定性和灵活性。包括实施环境分层和应用分级运维策略、规范环境全生命周期管理、强化环境管理全过程管控（包括变更、质量门禁、权限等），保障研发工作有序开展。在此基础上，强化环境资源的精细化管理，建设环境资源能耗机制，实施低效环境退出，提高资源使用效率。同时建设研发测试环境运行质量和运维效率度量体系，基于价值为导向，指导环境持续改进和提升，强化数据分析，赋能业务科学决策。
    
3.  **实施集约化运维**，做好服务保障，提升研发人员的环境体验。做好环境运维的支持和服务，健全问题反馈机制，打造日常问题提交“一键通”，丰富问题响应渠道，按研发部和部门设立对口运维专业经理，建立“运维管家”机制，始终坚持以“用户有感”为使命，提供优质的运维服务。同时加快问题响应速度，加强问题解决力度，提升用户满意度。
    
4.  **构建自动化智能化的运维驱动体系，提升运维效率**  
    夯实运维管理体系，推动研发测试环境管理从被动式运维向主动式运维转型，搭建环境供给自动化、环境配置标准化、环境运维自动化、环境监控智能化等多维度一体化的环境运维服务平台。同时将“运维人员服务”向“运维能力服务”转变，以自动化运维为基础逐步向智能化、数字化转型，提高运维效率，提供稳定高效的环境支撑，实现与持续交付的协同，赋能研发效能提升。
    

![](../Images/27873bf29a58c7dbf29fe6ccc570e87f.png)

**三、当前面临的挑战**

工行开发中心研发测试环境运维逐步实现了灵活与稳定的统一，但随着工行IT架构转型工作的不断深入，大量核心应用从主机迁移到了分布式架构，系统架构以及应用关联复杂度急剧增加，协作链条加长，同时随着国产化、云原生等新技术推广使用，对运维能力、工具链支撑能力提出了新的挑战。

一是随着工行IT基础架构和运维架构逐步往单元化转型，原来“以应用为核心的运维”逐步向“以业务为核心的运维”转型，运维粒度更加细化，需要建立更加紧密的、灵活的运维专业团队；二是运维体系的底层标准化、全流程自动化建设尚有不足，部分专业内已实现自动化，但在自动化全流程尚未全面打通，存在着“卡壳”环节；三是从原来“集中式架构”向“分布式架构”转型过程中，运维技能变化较大，运维团队运维技术能力需同步提升。

**四、工行开发中心研发测试环境运维提升思路**

随着数字化转型的不断深入，结合业界实践，通过探索研究测试环境运维新模式、加快环境运维数字化转型、完善研发测试环境资源使用机制等措施，进一步提升环境运维效能。

#### 4.1、探索前后端分离的环境运维模式，提升运维集约化水平

目前，工行开发中心以应用为单位将运维人员分散到不同研发部的运维部门，运维团队关注自身应用运维情况，开发测试团队关注自己应用的业务情况。随着工行“以应用为核心的运维”逐步向“以业务为核心的运维”转型，通过研究以业务视角为单位设立环境运维经理，围绕业务运维单元，纵向维持现有的运维组织不变，横向统筹工行开发中心的运维团队，建立以面向业务视角的前后端分离的运维服务模式，前端团队以业务线为视角，负责环境保障（包括环境搭建、环境配置等）、问题处理、服务支持等工作；后端团队以智能化运维为基础，关注自动化的提升、公共类问题的研究解决、运维公共基础研究和建设等，进一步提升运维集约化水平，提高运维运维效能。

#### 4.2、加快研发测试环境运维领域的数字化转型，实现高效协同运维

围绕工行数字化转型的多维布局，通过完善研发测试环境运维服务协同平台、加强运维工具支撑体系建设、构建标准化运维，突破跨机构、跨应用、跨系统的屏障和壁垒，连接内外资源，推动中心运维数字化转型发展。一是在进一步完善研发测试环境运维服务平台，夯实“两个基础”（运维服务和运维数据），形成运维互联互通能力和面向场景的服务支撑能力，全面提升运维自动化水平；二是以实现面向应用服务的高效环境支撑为目标，夯实环境管理的一致性、完整性，持续推进研发、测试、生产等环境支撑标准化建设，设立基础资源、系统配置、应用配置三层模型，将环境配置能力输出标准化、服务化，为工具链的自动化调度提供基础支撑；三是打造贯穿工行开发中心、数据中心、业务研发中心的环境交付及变更流水线，为产品研发、环境运维提供更便捷和一体化的配置服务，强化工具链的全流程支撑能力。

#### 4.3 完善研发测试环境资源管理机制，提升资源使用效能

目前工行开发中心环境分2层6类，按照月度划分，每个月环境将近12套环境，环境的供给和需求存在矛盾，且还在不断扩大，在对环境缺乏成本概念的前提下，环境需求部门都是无限索取资源。后续可以建立对应用的资源使用量、使用效率的成本和效能评价体系，借鉴公有云的管理模式，对CPU/内存/虚机/物理机/网络/电力等资源展现相关计价成本，体现每个部门的实际资源占用情况和成本消耗情况，对需求部门做到相应的警示和参考作用，同时指导后续的资源投放。
