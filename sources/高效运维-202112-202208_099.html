基于 Ansible 实现 MongoDB 的自动化运维

背景

作为公众号的忠实读者，一直以来对各类文风简洁、充满干货的文章深有好感；日前读到《巧用 Ansible 实现 MySQL 备份》的原创，颇有启发。本人并不从事运维工作，但是经常和运维打交道，从交流中也对运维日常略知一二。

目前刚开始接触和学习 MongoDB，对容器技术也稍有了解，原本意图根据文中提到的 Ansible 自带模块实现 MongoDB 的备份运维操作，可惜官方并没有提供预期的功能模块。
在仔细查阅了相关资料后，尝试编写了 Ansible 自定义模块实现 MongoDB 备份功能。

环境准备

参考原创文章，本人也基于 debian11 的官方镜像作为底座和中科大的软件源，构建了自定义镜像，为了便于后期 MongoDB 维护，在镜像构建过程中同时安装 pymongo。Dockerfile 文件定义如下：

FROM debian:latestRUN sed -i 's/deb.debian.org/mirrors.ustc.edu.cn/g' /etc/apt/sources.list \          && apt-get update -y \          && apt-get upgrade -y \          && apt-get install ansible -y \          && apt-get install sshpass -y \          && apt-get install pip -y \          && apt-get autocleanRUN pip3 install pymongoRUN mkdir -p /etc/ansible/CMD ["/bin/bash"]

与 MySQL 类似，MongoDB 的备份需要使用独立的工具实现，好在官网可以直接下载工具包，这里使用的版本为：mongodb-database-tools-debian10-x86_64-100.5.2。

在容器启动后，通过以下命令将 mongodump 工具安装到指定目录：docker cp mongodump ansible:/usr/bin/。

mongodb_dump 自定义模块编写

根据官方文档和其他资料，本人编写了自定义模块，目前仅实现了 dump 备份，后期会视情况进行维护和扩展功能。根据 Ansible 配置，将模块文件安装到 /usr/share/ansible/plugins/modules 目录。

模块核心代码如下：

def handler(module, state, login_host, login_user, login_password, name, target):    cmd = "/usr/bin/mongodump -h %s -u %s -p %s -d %s -o %s -gzip" % (login_host, login_user, login_password, name, target)    ret = subprocess.run(cmd,shell=True,stdout=subprocess.PIPE,stderr=subprocess.PIPE,encoding="utf-8",timeout=3)        if ret.returncode == 0:        result = dict(result = 'success')        module.exit_json(**result)        else:        module.fail_json(msg=ret.stderr)

模块输入定义如下表。

login_host

string

Host running the database.

login_password

string

The password used to  authenticate with.

login_user

string

The username used to  authenticate with.

name

aliases: db

list / elements=string /  required

Name of the  database to dump.

List of databases is provided  with state=dump

state

string

The database  state.

Choices:

dump

playbook 编排和测试

本人准备了用于测试的 playbook 配置文件，对正反两种场景进行验证，均符合预期，结果如下。

playbook：

---- hosts: 127.0.0.1  tasks:    - name: "mongodb dump test"      mongodb_dump:        login_host: 192.168.1.100        login_user: mongoadmin        login_password: ******        name: admin        state: dump        target: /tmp/mongo_{{ ansible_date_time.date }}

总结

在前人的成果之上，本人对 Ansible 自定义模块的编写、部署进行研究，并完成了 MongoDB 的备份测试。Ansible 作为一个开源自动化平台，带给用户丰富的功能和资源，同时模块化的工作原理又兼顾了灵活和扩展性，而开源属性又保证了开放性，可以说是运维转型的首选。

在研究过程中，本人也发现 Ansible 的强大功能还远没有开发出来，如果能用好 Ansible Tower、Ansible galaxy 等资源，势必会帮助企业的IT管理水平更上一层楼。

附：Ansible 原生提供的 MongoDB 模块清单

  • mongodb_balancer module – Manages the MongoDB Sharded Cluster Balancer.
  • mongodb_index module – Creates or drops indexes on MongoDB collections.
  • mongodb_info module – Gather information about MongoDB instance.
  • mongodb_maintenance module – Enables or disables maintenance mode for a secondary member.
  • mongodb_monitoring module – Manages the free monitoring feature.
  • mongodb_oplog module – Resizes the MongoDB oplog.
  • mongodb_parameter module – Change an administrative parameter on a MongoDB server
  • mongodb_replicaset module – Initialises a MongoDB replicaset.
  • mongodb_schema module – Manages MongoDB Document Schema Validators.
  • mongodb_shard module – Add or remove shards from a MongoDB Cluster
  • mongodb_shard_tag module – Manage Shard Tags.
  • mongodb_shard_zone module – Manage Shard Zones.
  • mongodb_shell module – Run commands via the MongoDB shell.
  • mongodb_shutdown module – Cleans up all database resources and then terminates the mongod/mongos process.
  • mongodb_status module – Validates the status of the replicaset.
  • mongodb_stepdown module – Step down the MongoDB node from a PRIMARY state.
  • mongodb_user module – Adds or removes a user from a MongoDB database
