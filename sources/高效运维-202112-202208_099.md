## 背景

作为公众号的忠实读者，一直以来对各类文风简洁、充满干货的文章深有好感；日前读到《[巧用 Ansible 实现 MySQL 备份](https://mp.weixin.qq.com/s?__biz=MzA4Nzg5Nzc5OA==&mid=2651714308&idx=2&sn=6541a682fb35b3eb717c1b2069731686&scene=21#wechat_redirect)》的原创，颇有启发。本人并不从事运维工作，但是经常和运维打交道，从交流中也对运维日常略知一二。

目前刚开始接触和学习 MongoDB，对容器技术也稍有了解，原本意图根据文中提到的 Ansible 自带模块实现 MongoDB 的备份运维操作，可惜官方并没有提供预期的功能模块。在仔细查阅了相关资料后，尝试编写了 Ansible 自定义模块实现 MongoDB 备份功能。

与 MySQL 类似，MongoDB 的备份需要使用独立的工具实现，好在官网可以直接下载工具包，这里使用的版本为：mongodb-database-tools-debian10-x86\_64-100.5.2。

在容器启动后，通过以下命令将 mongodump 工具安装到指定目录：docker cp mongodump ansible:/usr/bin/。

## mongodb\_dump 自定义模块编写

根据官方文档和其他资料，本人编写了自定义模块，目前仅实现了 dump 备份，后期会视情况进行维护和扩展功能。根据 Ansible 配置，将模块文件安装到 /usr/share/ansible/plugins/modules 目录。

模块核心代码如下：

```


*   
*   
*   
*   
*   
*   
*   
*   

```
def handler(module, state, login_host, login_user, login_password, name, target):    cmd = "/usr/bin/mongodump -h %s -u %s -p %s -d %s -o %s -gzip" % (login_host, login_user, login_password, name, target)    ret = subprocess.run(cmd,shell=True,stdout=subprocess.PIPE,stderr=subprocess.PIPE,encoding="utf-8",timeout=3)        if ret.returncode == 0:        result = dict(result = 'success')        module.exit_json(**result)        else:        module.fail_json(msg=ret.stderr)
```


```

模块输入定义如下表。

| login\_hoststring || Host running the database. |
| :-- | :-- |
| login\_passwordstring || The password used to  authenticate with. |
| login\_userstring || The username used to  authenticate with. |
| namealiases: dblist / elements=string /  required || Name of the  database to dump.List of databases is provided  with state=dump |
| statestring || The database  state.Choices:dump |

## 总结

在前人的成果之上，本人对 Ansible 自定义模块的编写、部署进行研究，并完成了 MongoDB 的备份测试。Ansible 作为一个开源自动化平台，带给用户丰富的功能和资源，同时模块化的工作原理又兼顾了灵活和扩展性，而开源属性又保证了开放性，可以说是运维转型的首选。

在研究过程中，本人也发现 Ansible 的强大功能还远没有开发出来，如果能用好 Ansible Tower、Ansible galaxy 等资源，势必会帮助企业的IT管理水平更上一层楼。

## 附：Ansible 原生提供的 MongoDB 模块清单

*   mongodb\_balancer module – Manages the MongoDB Sharded Cluster Balancer.
*   mongodb\_index module – Creates or drops indexes on MongoDB collections.
*   mongodb\_info module – Gather information about MongoDB instance.
*   mongodb\_maintenance module – Enables or disables maintenance mode for a secondary member.
*   mongodb\_monitoring module – Manages the free monitoring feature.
*   mongodb\_oplog module – Resizes the MongoDB oplog.
*   mongodb\_parameter module – Change an administrative parameter on a MongoDB server
*   mongodb\_replicaset module – Initialises a MongoDB replicaset.
*   mongodb\_schema module – Manages MongoDB Document Schema Validators.
*   mongodb\_shard module – Add or remove shards from a MongoDB Cluster
*   mongodb\_shard\_tag module – Manage Shard Tags.
*   mongodb\_shard\_zone module – Manage Shard Zones.
*   mongodb\_shell module – Run commands via the MongoDB shell.
*   mongodb\_shutdown module – Cleans up all database resources and then terminates the mongod/mongos process.
*   mongodb\_status module – Validates the status of the replicaset.
*   mongodb\_stepdown module – Step down the MongoDB node from a PRIMARY state.
*   mongodb\_user module – Adds or removes a user from a MongoDB database
