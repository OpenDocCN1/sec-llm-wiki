国内外大型企业实践表明，标准化和工具赋能是企业成功的关键所在。DevOps 标准及基于标准的 DevOps 持续交付流水线平台和项目实践，可以较大幅度地提质增效，更加安全敏捷地提高企业市场竞争力！“以评促建，以评促改”，以评估为抓手，让DevOps标准更快更好落地，助力企业数字化转型。

  

2022年4月26日，**中国信息通信研究院隆重发布了 DevOps 标准持续交付第十七批评估结果。**

  

中国国际金融股份有限公司（以下简称“中金公司”）本次参评项目为**中金股权激励管理平台（对客）、鲁班数字员工服务平台、中金机构客户服务平台-CICSP和中金公司财富管理业务核心系统AIIS星海平台项目**，四个项目均顺利通过由中国信息通信研究院开展的《研发运营一体化（DevOps）能力成熟度模型》持续交付 3 级评估，相关能力达到国内领先水平。此先，中金公司“天玑DevOps平台”项目于2021年12月通过中国信息通信研究院 DevOps 标准系统和工具相关评估。

  

中金公司也是证券行业首家4个项目一次性通过DevOps标准评估的单位。

  

**评估单位：中国信息通信研究院**

此次，我们采访了中金公司首席信息官（CIO）程龙先生、信息技术部执行总经理叶明登先生和信息技术部副总经理管艳艳女士，一同深聊团队在项目参与评估时的细节和故事，分享中金公司 DevOps 实践的经验。

  

**\- Q&A -**

![](../Images/834b04fe0b40aecb696fd7c6ee4c719a.png "中金公司CIO程龙.jpg")

中金公司CIO 程龙先生  

**Q：您好，请介绍一下您和您的企业，以及此次参与评估的项目。**

**程龙：**中国国际金融股份有限公司成立于 1995 年，是国内首家中外合资的投资银行。中金公司率先将国际经验和中国资本市场经验相结合，完成了众多开创先河的交易。中金公司于 2015 年在香港上市，2017 年与中金财富证券整合，2020 年回归 A 股上市，目前已经成为一家拥有上万员工的上市公司。

  

随着中金公司数字化转型的不断深入，打造一个能够快速响应市场变化的敏捷组织，是中金公司信息技术部持续聚焦的重心。为此，中金公司信息技术部提出“以点带面，以评促改”的策略，提出四个不同业务方向和不同系统特征的项目来参加评估，其中，中金AIIS星海平台是中金公司的财富管理业务核心系统；中金鲁班数字员工服务平台是针对RPA机器人和流程的统一管理系统；中金ESOP平台是股权激励管理平台，为企业提供跨市场、贯穿上市前后、全自动化的ESOP管理系统；中金CICSP机构客户服务平台是以场景和数据相结合，打造机构客户服务生态圈。

  
**Q：恭喜通过 DevOps 标准评估，此次贵公司项目通过了持续交付 3 级评估，表明达到了国内领先水平，请说一下您此时的感受。****程龙：**非常高兴中金公司各个项目通过了本次持续交付3级评估，这代表了中金公司信息技术部从组织级的规范和标准的制订、平台和工具的建设、工程实践的落地，到项目团队的敏捷运作管理、团队协作、需求交付管理等多方面能力得到了全面的提升和完善，达到了一个全新的高度。目前，中金公司信息技术部具备了一整套贴合自身发展，以实现业务价值驱动的自动化IT流程，同时，从需求管理到交付发布，从组织级平台到团队实践，构建真正意义上端到端的研发交付体系。这极大地提升了IT的整体研发效能，并能以此为出发点，通过评估期间积累的大量实践经验，带动整个信息技术部DevOps规模化改进提升的步伐。  
**Q：贵公司是如何决定加入 DevOps 标准评估工作中的？**

**程龙：**数字化转型的关键点之一是IT基础建设的完善和高效化。如果说转型的成功是我们此行目的地的话，那么IT这辆车，在这个旅途中就必须保持够快、够稳、够安全。因此，我们期望可以对标业界专业权威的DevOps持续交付3级标准，要求我们的平台和项目团队去进行持续改进，通过敏捷运作、自动化、工程实践、质量管理等多种手段进行完善和优化，让整个IT组织更快、更稳、更安全。

**Q：****通过 DevOps 标准评估对您企业带来了什么帮助？对贵团队有哪些影响**？****

**叶明登：**从整体来说，对中金公司帮助非常大。首先是证明了中金公司在有限的时间内就具备了DevOps顶级项目交付能力，其次评估的项目在需求交付效率上也得到了实实在在的提升。通过参与评估，我们在中金公司各部门、各团队宣传了DevOps的工具、方法和理念，对没评估团队也起到带动作用，切实起到了以评促学、以评促练、以评促建、以评促改的作用。各未评估的团队也跃跃欲试，希望加入下一批评估项目，这使整个组织在意识和文化方面都发生了巨大的改变。

  

从团队层面来说，经过以评促改，结合敏捷开发模式，团队整体的研发效能得到了明显的提升，研发动作实现了规范化、标准化，从而在确保快速交付业务价值的同时，质量得到了保障。同时，得益于平台工具的逐步完善和优化，端到端的开发过程透明可控，团队开始从传统的手工式开发模式，转变为流水线式的快速交付模式，问题和风险即有即发现，发现即改正，大大降低了交付阶段的风险和调整成本，同时也让团队形成了良好的研发习惯和纪律。

  

**Q：****对于 DevOps 今年的实施，您觉得最大的收获是什么？您的下一步计划是？ **

**叶明登：**通过DevOps一系列管理和工程实践在团队的落地，我们的研发效能明显提升，团队的整体战斗力得到了极大的增强，实现了“更快更好的交付业务价值”的目标，“让业务价值快速流动起来”，这是我们最大的使命，是我们每个IT人追求的目标。建立在这个目标上的所有努力，比如敏捷转型、系统重构、实现各种工程实践及弥补大量的技术债等，每一件单独拿出来，在平时都是一件难以在短时间内攻克的坎，但是我们通过目标一致的努力，通过组织与团队的协同，通过团队内部的互相帮助，在很短的时间内一起把这个事情做成了，这就是我们最大的收获，因此在这里，我们特别感谢组织的高度重视，以及团队的全力付出。

  

另外，通过项目交付的DevOps评估，在去年DevOps工具与系统评估的基础上，工具能力又得到了改进提升，同时也发现了工具系统的一些稳定性问题，促使我们做出了改进，化解了不少风险。另外通过项目评估，参与的员工积累了这方面的能力，后续会把这些员工培养为公司内的DevOps教练。下一步计划基于信通院标准形成中金公司内部的DevOps分级标准，在公司内逐步规模化推广，把DevOps固化为中金公司内嵌的组织能力。

  

**Q：****对于 DevOps 的发展前景，您怎么看？**

**叶明登：**对于DevOps来说，当下虽已成功了一小步，但目光还是要望向未来，目前的四个团队通过评估，只是一个闪光的瞬间，一个宏大旅程的起点，一个可以生根发芽的种子，我们希望通过这四个团队，形成DevOps样板，以点带面，拉动整个组织推进DevOps的规模化进程，从而持续进行研发体系的优化，让我们可以形成“更快、更稳、更安全”的持续改进意识，所以对于我们来说， DevOps理念和实践非常值得我们继续推广，我们相信它对研发质量和效率的巨大提升，也相信DevOps会得到越来越多从业人员的接纳。当然这个提升应该是不断改进的，没有终点，需要通过PDCA循环的理念不断演进和精化。

**Q：****您可否详细的介绍一下，通过本次评估有哪些数据指标可以直观的体现项目改进成果？（需求耗费时长、持续集成响应时间、项目过程缺陷密度、编译构建时长、投产频率等）**

**管艳艳：**通过此次评估，我们通过在多个方面的持续改进，研发效能在多个维度均有了全面的提升，比较明显的是需求耗费时长从此前的1个月左右，缩短至2周以内，甚至一周可多次交付；同时持续集成响应时间从至少耗费半天以上，缩短至最长10分钟以内；构建部署时长从小时级缩短至分钟级；投产频率提升至3倍以上；平均自动构建成功率达到95%以上；平均日构建次数达到20次以上；平均节省成本达到12个人月以上，这样真实的提升，证明了通过全方位的改进，我们的研发团队是可以做到在确保质量的情况下，实现快速交付业务价值的目标的。

**Q：对于此次参评的项目，其IT系统有哪些特色，当时是怎么规划和设计的？**

**管艳艳：**此次参评的四个项目，存在不同的使用客群和业务特点，这也带来了各自不同的技术栈，不同的系统框架设计，不同的架构复杂度，不同的研发管理模式，虽然这样会给参评带来更大的难度。但我们坚持迎难而上，是因为我们希望通过这四个互有差异的系统平台，来摸索出一套广泛通用的端到端研发运维体系，以及总结出中金公司研发团队普遍公认可行的研发规范和标准，同时对平台和工具进行适应性调优，提炼出研发团队使用平台工具的切实可行的操作方法。最后，通过敏捷运作模式贯穿前后，形成具有中金公司特色的敏捷研发模型，打造价值快速流转、高稳定性、高可靠性的优秀样板，给其他的项目和系统作为参照，为后续的规模化敏捷和DevOps推广打下坚实的基础。

  

**Q：****此次通过评估的过程顺利吗？遇到什么困难？如何解决的？**

**管艳艳：**对于我们最大的挑战在于两个方面：一是四个不同特点的项目同时进行评估，不同的业务特点和技术架构，这让制订统一适用的组织级规范标准，以及建立和优化通用性的平台工具困难重重；二是日常主线工作和 DevOps 建设两者的平衡上，团队一边要应对业务的生产压力，另一边要完成DevOps的改进工作，这就是我们常常听到的“在高速行驶中换轮胎，大象在刀尖上跳舞”。

  

这两方面的挑战，对整个组织和单个团队都是一个艰难的考验，但对于中金公司来说，挑战难度大不是问题，畏敌不前才是问题。为了打赢这场攻坚战，在组织层面，信息技术部集中力量，针对评估项优化平台与工具，制定统一规范和标准；在团队层面，宣导团队成员也充分意识到这是一次难得的锻炼与提升自我能力的机会，由团队负责人带头，带动每一名团队成员都努力提高工作效率，同时和业务条线进行协商，平衡业务压力和DevOps工作，减少部分低优先级需求，从而为DevOps的改进让出必要的空间和时间，以一种相对平衡、相对合理的方式，顺利打赢了这场艰难的战役。

**研发运营一体化（DevOps）能力成熟度模型介绍：**  

《研发运营一体化（DevOps）能力成熟度模型》系列标准是由中国信息通信研究院牵头，云计算开源产业联盟、高效运维社区、BATJ等顶级互联网公司以及各大金融、通信企业共同制定的国内外首个 DevOps 系列标准，是最完整、最权威、最具行业指导性的研发运营一体化（DevOps）能力标准之一。由中国信息通信研究院主导的 DevOps 标准已由工信部发布并被众多金融、通信和互联网等行业名企纷纷采用并通过评估。

与此同时，DevOps 标准已于2020年7月在联合国直属标准化组织 ITU-T 正式结项，成为全球首个 DevOps 国际标准。DevOps 标准评估体系主要包括敏捷开发管理、持续交付、技术运营、应用设计、安全及风险管理、系统和工具等部分。
