# 燃！平安银行获信通院研发效能度量工具级『产业推广级』标准评估

12 月 24 日，由中国信息通信研究院主办的“**2021 GOLF+ IT新治理领导力论坛**”隆重开幕，论坛围绕 “治效兼顾，构筑科技治理新生态” 和 “XOPS 创新，领航运维发展新脉络” 两大主题展开，旨在 “**新治理融惠创新，数字化行稳致远**” 。会上产学研各界嘉宾进行了精彩的主题演讲和经验分享，促进了企业间的学习交流和各行业数字化治理持续健康发展。  

**中国信息通信研究院隆重发布了《研发运营一体化（DevOps）通用效能度量模型-系统平台和工具》首批试评估结果**。平安银行股份有限公司（以下简称“平安银行”）的 **Starlink 开发运维一体化平台**参与本次由中国信息通信研究院（以下简称“信通院”）开展的《研发运营一体化（ DevOps ）通用效能度量模型》首批试评估并顺利通过**工具****产业推广级**评估。代表着平安银行的 DevOps 效能度量已经达到国内领先水平。  

**评测单位：中国信息通信研究院**

**中国信息通信研究院云计算与大数据研究所所长何宝宏先生为相关企业授牌：**![](../Images/aac59151d52c4ec04e9c3345373ef9a2.png)

![](../Images/ef70b79286b22b773986d15287393f07.png)

▲评估结果公布现场  

此次，我们采访了平安银行战略发展部总经理袁飞先生、平安银行科技开发中心首席架构师黄威琪先生和科技开发中心 Starlink 产品负责人金艳女士，分享平安银行 DevOps 实践的经验。  

  
**\-Q&A-**  ![](../Images/45c7abe56dcbfb6d7ac0f5cb15a94b43.png)  

平安银行 Starlink-Kepler 团队

**Q：您好，请介绍一下您和您的企业，以及此次参与评估的项目。****A：**您好，平安银行作为一家现代商业银行，深知“科技必须成为银行转型发展的底色”，始终把“科技引领”放在银行发展十二字策略的首位。数字银行、生态银行、平台银行是我们平安银行重点打造的三张名片。一直以来，我们将领先的技术率先应用到平安各综合金融场景之中，实现数字化，智能化的产品和服务创新，以及高效的经营管理。Starlink 是我行统一的 DevOps 平台，串联“创意生成→需求设计→开发测试→发布运营→运维监控→需求反馈”的完整软件价值交付闭环。Kepler 是 Starlink 的效能模块，为 Starlink 提供完备的数据采集、度量定义&规范、度量分析&展现等能力的支持，是 Starlink 为全行提供精细化研发效能管理的重要支持平台。  
**Q：恭喜贵公司项目通过 DevOps 通用效能度量模型评估，表明达到了国内领先水平，请说一下您此时的感受。**

**A：**本次评估是我们参与 DevOps 标准通用效能度量的首批试评估工作。去年，我们先后通过了系统与工具标准以及安全及风险管理两项评估，且均是首批。此次DevOps 通用效能度量标准评估，我们更是获得了“产业推广级”的评估结果。这表明我们 Kepler 的产品建设正沿着正确方向在前行，同时，也表明我们的产品在一些方面站在了行业的前列。此次获奖也激励我们，持续迭代优化，保持创新和行业敏锐，把产品建设由点到线、由线到面深化，继续开放平台服务的能力支撑业务发展。

  
**Q：贵公司是如何决定加入 DevOps 通用效能度量模型评估工作中的？**

****A：****组织越发展，对精细化管理的诉求越来越强，其价值也越高。Starlink 中的 Kepler 效能模块为平安银行整个研发体系提供效能度量和效能精细化管理支持。信通院此次颁布的 DevOps 通用效能度量标准评估涵盖全面，具有指导意义。我们参与此次评估，一方面验证检视我们前期的工作成果，也是希望“以评促改，以评促建”，让我们有机会与其他业内先进案例交流经验。

  
**Q：通过 DevOps 通用效能度量模型评估对您企业带来了什么帮助？对贵团队有哪些影响？**

**A：**通过此次评估，得到中国信通院的权威认可，为我们带了不小的收获：一是激励了我们的企业和团队，获得 DevOps 通用效能度量标准的评估代表着团队能力和平台价值得到了认可；二是帮助我们检视了整个系统、流程、团队，优化现有的不足，让整体能力更上一层；三是树立了业内标杆，建立最佳实践，为效能度量、精细化效能管理在行内的进一步推行有很好的示范作用。

  
**Q：对于此次参评的项目，其 IT 系统有哪些特色，当时是怎么规划和设计的？**

**A：**Starlink 中的 Kepler 效能模块是平安银行研发体系统一的效能管理平台，它为我行研发体系提供着统一的效能度量和管理支持。平台用户群体不仅包括研发体系的成员，更贯穿前后台，为人力、财务、安全合规、决策层以及业务侧提供重要的信息和决策支持。

Kepler 效能模块以创新的产品、架构、指标集设计，解决了我行研发体系数据来源多、多个系统数据不一致、数据抽取困难等数据采集问题，并解决了我行因业务条线多、管理方法差异大、各团队开发模式不同、各组织/角色对数据需求不同而带来的统一数据分析方面的痛点，最终形成全行统一的效能系统。并形成了以端到端数字化大盘、移动端APP、基础数据管理管理数字化、研发数字化、迭代数字化、质量数字化、个人仪表盘、数据中台、人力/项目管理报告等立体化的数据价值输出体系。

  

**Q：此次通过评估的过程顺利吗？遇到什么困难？如何解决的？**

**A：**此次评估时间紧，任务重。在161个测评条目中，我们有一些项目与最高级标准存在一些差距：如对度量场景的支持上以及在可视化仪表盘的能力上。这些能力实际上是已在我们 Kepler 未来的建设规划之内，但遗憾无法在几天的评估过程中补足。

这也激励着我们不满足于现状，始终对齐业界的高标准进行产品建设。这里还要感谢信通院的评估专家们，帮助我们高效检视了我们效能度量系统，为我们后续相关能力建设提供了非常重要的参考意见。

  

**Q：对于DevOps今年的实施，您觉得最大的收获是什么？您的下一步计划是？**

**A：**本年度，平安银行 Starlink 数字化开发运维一体化平台已在平安银行实现 100% 的团队覆盖，全行 99% 的应用基于 Starlink 发版，Kepler 的推广覆盖度也随之基本扩大到全行，平台能力也得到了比较充分的完善。在这个过程中，我们与用户的沟通更为频繁和密切，我们也得到了很多的认可以及可贵的意见和建议，这是我们在今年平台建设中很大的收获。

明年，Starlink 将更加注重提升精细化管理能力，Kepler 将扮演更加重要的角色。我们将更加注重获取研发效能数据，挖掘数据价值，以数据驱动研发效能提升的能力。

  

**Q：对于DevOps的发展前景，您怎么看？****A：**DevOps 作为一套方法论和实践体系，它要解决的问题是不变的，但随着业务场景的变化和新技术的快速演进，不断的有各种新的方法和新的实践被补充进来。对于 DevOps 的发展前景，我们认为，只要它需要解决的问题（价值交付）还在，那么 DevOps 这一套理论就会持续发展下去。而近年来，随着对于 DevOps 研究和实践的不断深入，很多新的技术和方法，值得我们认真研究。如：Kubernetes 与 DevOps 的结合、云原生技术体系、AI 技术在 DevOps 中的使用、基础设施即代码(IaC)、GitOps、DevSecOps 等。

**研发运营一体化（DevOps）通用效能度量模型介绍：**  

《研发运营一体化（DevOps）通用效能度量模型》标准由中国信通院牵头，百度、阿里云、腾讯、中国农业银行、中信银行、民生银行、平安银行、华佑科技、中兴通讯、中国联通软研院、美团、ONES、南方电网、京东科技、华为、亚信、博云、宇信、极狐GitLab、JFrog、ThoughtWorks、融联易云、中软国际、北京燃气、谐云、浩鲸云计算、方云智能等30余家企业单位共同制定。系统平台和工具部分从数据管理、度量分析管理、度量展现管理三个维度作出要求，覆盖敏捷开发场景、持续交付场景、技术运营场景、成本管理场景及组织与人员管理，助力企业整体研发效能提升，为企业在数字化转型浪潮中的研发度量提供重要抓手。整个系统平台和工具部分包含17个模块，164项条目，并根据系统平台及工具满足的能力要求项数量将其分为三个级别：创新突破级（一级）、产业推广级（二级）、卓越引领级（三级），且三级为最高级。是目前业界最完整、最权威、最具行业指导性的研发运营（DevOps）效能度量评估标准。
