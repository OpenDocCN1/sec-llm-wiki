各大企业的实践及相关数据表明，标准化和工具赋能是企业成功的关键。DevOps 标准及基于标准的 DevOps 持续交付流水线平台，能有效针对企业软件研发提质增效，不仅更快更灵活，也大幅度提高企业核心竞争力！12 月 24 日，由中国信息通信研究院主办的“**2021 GOLF+ IT新治理领导力论坛**”隆重开幕，论坛围绕 “治效兼顾，构筑科技治理新生态” 和 “XOPS 创新，领航运维发展新脉络” 两大主题展开，旨在 “**新治理融惠创新，数字化行稳致远**” 。会上产学研各界嘉宾进行了精彩的主题演讲和经验分享，促进了企业间的学习交流和各行业数字化治理持续健康发展。

宁波银行总行金融科技部副总经理 陈卫华  
**Q：您好，请介绍一下您和您的企业，以及此次参与评估的项目。****陈卫华****：**我是宁波银行总行金融科技部副总经理陈卫华。宁波银行是国内首批系统重要性银行之一，长期以来一直非常重视科技赋能，目前共有行员 1000 余人，其中开发人员近 700 名。2020 年我行提出了“ISMART+”智慧银行战略，实施系统化、数字化、智能化的三化发展。

此次参评的场景支付系统是基于我行支付系统群规划，围绕场景全面升级建设的支付中台，主要包括：

**1）**升级支付中台，提高支付服务能力。搭建支付场景、账务、路由、清结算、管理、交换等中心；

**2）**剥离银联支付，助力核心瘦身。将跨行 ATM、柜面通、银联代收付等多个功能模块，分别从核心系统、银联前置剥离至中台，新建银联 POS 收单，实现银联支付通道、风险、数据的统筹管理。

**3）**提高批量转账速度，减少非必要落地交易，提升信用卡清结算工作效率。

  
**Q：恭喜通过 DevOps 标准评估，此次贵公司通过的是持续交付 3 级，表明达到了国内领先水平，请说一下您此时的感受。******陈卫华******：**很高兴场景支付系统能够顺利通过《研发运营一体化（ DevOps ）能力成熟度模型》持续交付 3 级能力评估，非常感谢信通院各位专家在评估过程中的指导与帮助。场景支付系统作为宁波银行首个 DevOps 实践标杆项目，极大地鼓舞了我行 DevOps 能力建设工作，也是一个里程碑式的工作成果。  
**Q：贵公司是如何决定加入 DevOps 标准评估工作中的？**********陈卫华********：****信通院牵头制定的 DevOps 标准对升级组织研发运营能力、提高软件交付质量、度量组织研发运营能力具有重大意义。我行在 2020 年正式启动 DevOps 建设，并且针对平台建设、人员赋能和敏捷转型等做了一系列工作。本次加入标准评估，一方面是希望对已开展的工作进行全面的总结与检验，另一方面是希望通过以评促改的方式，深入理解 DevOps 标准的要求，借鉴国内领先同行的经验，体系化的提升软件交付能力。

  

**Q：通过 DevOps 标准评估对您企业带来了什么帮助？对贵团队有哪些影响？**********陈卫华******：******本次评估实现了在行内树立标杆、打造平台、培养工程教练、打造工程能力要求的目标，为后续行内进行工程能力推广奠定了基础。一方面促进了行内工具平台群整体协同规划和配套改造，形成了真实用户反馈驱动的改进机制；一方面深入理解了 DevOps 并转换成适配我行情况的工程能力指标和实践要求。此外，在评估过程中培养了一组工程教练，在标杆项目中形成了一系列优秀的实践方法和探索经验。对于项目团队来说，初期采用的瀑布研发模式不能有效满足快速交付的要求，因此采用敏捷迭代的方式进行开发，以可测可独立投产的原则对需求进行了细化拆分，并采用了多层级日会、周会机制，通过可视化的方式及时跟进进展、识别问题并分析解决。对于测试人员来说，由于交付周期的缩短而导致的测试时间压缩、大量回归的要求都为测试工作带来很大挑战，而质量门禁的强控保障了进入人工测试前的代码质量，前置的单元、接口等自动化测试在很大程度上能够保证质量，减少人工测试的工作量。对于运维人员来说，通过变更的协同方式的优化、环境基础工具一致的保障、环境和应用（数据库、配置）变更过程的自动化和前序环节的反复验证，基本上避免了环境准备时间过长、测试环境可靠性和生产变更过程可靠性的问题。

**Q：对于此次参评的项目，其 IT 系统有哪些特色，当时是怎么规划和设计的？************陈卫华************：**我们从项目重要性、标杆代表性、历史包袱等方面进行了考量，最终选定了我行的场景支付系统。场景支付系统是依照我行支付系统群规划，围绕场景进行支付中台升级的行内重点项目。场景支付于今年启动今年上线投产，采用微服务架构，涉及 12+ 新建微服务，团队组成约为 15 人。  
**Q： 此次通过评估的过程顺利吗？遇到什么困难？如何解决的？**

******陈卫华******：****我行对于此次评估是非常重视的，并且提前做了大量的准备工作。在启动评估前，我行已经开始开展 DevOps 建设，包括：研发一体化平台（奋进号）的选型落地和全行推广使用；配置管理（持续集成）团队组建、配管体系的搭建和落地、代码库迁移 CI/CD 的实施推广等；参评项目在建设初期就明确了质量目标，进行了单元测试工具的选型和内部培训。接口自动化和 UI 自动化测试方面也已经有了一定的技术积累。

所以我们在开始这个项目时，大家都是很有信心和干劲。但是在项目开展过程中，我们确实也遇到了很多的问题和困难，主要包括以下几点：

**1）****流程适配性：**场景支付属于行内的重大项目，重大项目的管理要求和管控流程都比其他类型的项目要更高、更复杂繁琐、耗时更长，随着项目的推进给项目组带来了比较大的负担，因此后期我们针对场景支付进行了流程适配性的优化，给项目组减负。

**2）****需求粒度粗、传统的研发方式：**由于是重大项目，项目伊始也是完全按照传统瀑布开发模式进行的规划和管理，业务需求颗粒度大交付周期长，按月规划的投产频率。而这种模式在洞察平台中的数据也确实展现出了研发、测试等待时间过长的问题。为了解决这个问题，项目组下了很大的决心采用敏捷实践，重新对需求进行拆分。而在项目中期重新对需求进行细化拆分、协同计划重新安排确实给项目组带来了很大的挑战。

  
**Q：对于 DevOps 今年的实施，您觉得最大的收获是什么？您的下一步计划是？ **

********************陈卫华**********************：**最大的收获是摸索了一组适配我行工程建设的最佳实践，建立了行内标杆 DevOps 项目团队，培养锻炼了一群在各自领域有改造经验、能够理解 DevOps 要求的人员，促进了跨部门组织间的沟通协作并改造建设了一体化的 DevOps 平台。

后续我们会将工程能力的要求和实践经验沉淀为组织的体系规则和指导要求，并以内部对标的方式进行行内整体范围的工程能力摸底。下一步计划我们将在行内进行大范围 DevOps 推广，促进行内研发工程能力的全面提升，推广的方式包括：通过经验分享会、分享文章、展板展示等一系列的方式进行 DevOps 的文化宣传；建立工程教练培养机制，拓展我们的工程教练团队；基于摸底情况识别的薄弱工程能力项、根据优先级逐项分批次的进行能力指导建设。

  

**Q：对于 DevOps 的发展前景，您怎么看？**陈卫华**：**DevOps 是数字化转型的有力抓手，是快速交付业务价值、赋能业务发展的基础保障。DevOps 首先聚焦在持续交付过程，以提高效率减少浪费、促进研发运维融合为目标，这是在科技管理以致企业管理方面是永不会过时的话题。而随着 DevOps 近几年的发展，出现了越来越多好的实践和技术，例如：AIOps、ChatOps，并且也逐步扩展深入到了安全、业务等领域。我们会以我行的实际情况出发，借鉴参考业界的前沿发展在 DevOps 方面进行持续的探索和实践。

**研发运营一体化（DevOps）能力成熟度模型介绍：**  

《研发运营一体化（DevOps）能力成熟度模型》系列标准是由中国信息通信研究院牵头，云计算开源产业联盟、高效运维社区、BATJ等顶级互联网公司以及各大金融、通信企业共同制定的国内外首个 DevOps 系列标准，是最完整、最权威、最具行业指导性的研发运营一体化（DevOps）能力标准之一。由中国信息通信研究院主导的 DevOps 标准已由工信部发布并被众多金融、通信和互联网等行业名企纷纷采用并通过评估。  

与此同时，DevOps 标准已于2020年7月在联合国直属标准化组织 ITU-T 正式结项，成为全球首个 DevOps 国际标准。DevOps 标准评估体系主要包括敏捷开发管理、持续交付、技术运营、应用设计、安全及风险管理、系统和工具等部分。
