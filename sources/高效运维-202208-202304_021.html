国内外大型企业实践表明，标准化和工具赋能是企业成功的关键所在。DevOps 标准及基于标准的 DevOps 持续交付流水线平台和项目实践，可以较大幅度地提质增效，更加安全敏捷地提高企业市场竞争力！“以评促建，以评促改”，以评估为抓手，让 DevOps 标准更快更好落地，助力企业数字化转型。


2023年4月7日，由高效运维社区（GreatOPS）和开放运维联盟（OOPSA）联合主办的第 20 届 GOPS 全球运维大会在深圳正式召开。GOPS 全球运维大会是国内第一个也是最大的运维行业大会，也是备受瞩目的千人峰会，面向互联网及金融、通信等传统行业广大运维、开发等技术人员，传播先进技术思想和理念，分享业内最佳实践。


在本次会议上，中国信息通信研究院隆重公布了 DevOps 系列标准最新批次评估结果。


国泰君安证券股份有限公司（以下简称“国泰君安”）本次参评的项目为“集中营运系统”项目和“君弘君融交易项目”，该项目顺利通过由中国信息通信研究院开展的《研发运营一体化（ DevOps ）能力成熟度模型》技术运营标准 2+ 级评估，代表国泰君安在 DevOps 相关领域能力达到国内领先水平。


目前，国泰君安已通过 DevOps 技术运营标准评估 3 项，是首个一次性2个项目通过 CO2+评估的企业，是通过 CO2+评估最多的企业，也是截至目前全行业通过 CO 评估最多的企业。


评估单位：中国信息通信研究院


2023年4月7日在“2023 GOPS 全球运维大会·深圳站”主会场上，由中国信息通信研究院云计算与大数据研究所副总工程师王蕴韬先生为企业授牌：



此次，我们采访了国泰君安数据中心总经理曾宏祥先生、副总经理毛梦非先生、运维技术支持组总监马辉先生和系统运行组总监邹建东先生，一同深聊团队在项目参与评估时的细节和故事，分享国泰君安 DevOps 实践的经验。

国泰君安

数据中心总经理 曾宏祥


Q

恭喜您通过 DevOps 标准评估，此次贵公司项目通过的是技术运营 2+ 级，达到国内领先水平，麻烦您分享一下此时的感受。

A

曾宏祥：在国泰君安董事长贺青“三个三年三步走”战略路径构想引领下，国泰君安秉持“人人数字化、处处数字化”的理念，进一步聚焦“增长、效率、体验、安全”四大维度，全集团、全领域、全方位地推动建设“SMART 投行”，目标是将公司打造为超级的、基于数据和算法驱动、敏捷和变革的科技投行。将以此为契机，未来我们要建立内部的认证标准，将技术运营标准与内部具体实践相结合，继续围绕“文化、组织、机制、人才”，加快把传统信息技术基础转化为全面数字化经营能力，持续打造面向未来的战略竞争优势，以全面数字化转型引领驱动公司高质量发展。


公司数字化转型初见成效，数字科技的行业领先地位得到进一步巩固，服务实体经济和满足人民群众需求的质量进一步提升，助力行业高质量发展的动力进一步增强。在第二个”三年三步走“的开端之年，国泰君安首席信息官俞枫提出要全面深化数字化转型，实现经营管理模式创新驱动业务模式革新，打造高等级IT基础设施，提前布局金融科技，前瞻布道开放证券生态，一路从行业信息化标杆迈向数字化转型引领者。


作为公司数字化转型的重要环节，国泰君安数据中心坚决贯彻执行全面数字化转型，自主规划智能运维管理体系，通过联合共建的创新方式，积极探索面向金融发展新趋势的一体化智能运维平台建设。国泰君安数据中心的智能运维管理体系，实现了以大数据与算法为基础、以数据治理为手段、以中台技术架构为支撑，集成现有运维工具链，对多样化数据梳理整合，实现数据采集、处理、分析、展示统一的智能运维应用体系。国泰君安数据中心的一体化智能运维平台，实现了对业务系统的全面多维监控、日志分析、调用跟踪、容量管理、算法应用、优化告警等功能，为公司数字化转型和完善用户体验提供了有力的运维保障。


我们感到非常高兴与欣慰的是，在2021年作为行业首家以交易系统通过 DevOps 技术运营 2+ 级的建设成果基础上，历经半年，本次我们两个项目都再次一举通过了技术运营 2+ 级评估。对于信通院专家们给予的认可与鼓励，我们倍感珍惜。



Q

贵公司是如何考虑将此项目进行技术运营评估的？

A

曾宏祥：我们在选取评估项目时，主要围绕核心业务和交易系统两个方面，一方面作为核心业务交易系统其业务安全稳定高效运行的重要性不言而喻；另一方面通过评估可以检验我们对于核心交易系统的技术运营保障能力，并以评促改找到改进和优化的方向和方法，提高效率和质量，降低成本和风险。


集中营运作为我司营运业务的重要承载平台，君弘君融作为我司机构量化交易生态的重要接入系统之一，其业务连续性、系统可靠性与稳定性、用户体验和数字化水平等都是我们团队需要重点保障的内容。相较于其他互联网应用类系统，由于缺少匹配的案例参考，难度更大。通过参加技术运营2+评估，对提升整体技术运营管控过程，贯通和完善技术运营管理的体系，保障业务稳定，达到行业领先水平，意义重大。



Q

您对 DevOps 标准是如何看待的，它给企业带来了哪些帮助？

A

曾宏祥：DevOps 标准作为一种重要的技术实践方法，针对技术运营各个阶段的关键能力项、能力水平都有明确定义和规范要求，能有效帮助我们准确评估研发运营水平的现状和持续改进的努力方向，对全面提升技术运营工作有很好的指导意义。


通过对标技术运营标准，我们能做到心中有数，发现自身的优势与不足，在 CMDB、监控等成熟度较高的能力项基础上，集中精力补齐其他能力短板，以更高质量精细化完善部分能力项建设。


我们相信信通院 DevOps 标准对于其他企业快速理清技术运营建设思路、提升研发运营一体化水平、促进数字化运营能力提升，也会有非常好的引领和指导作用。



国泰君安

数据中心副总经理 毛梦非


Q

关于 DevOps ，接下来团队有什么样的计划？

A

毛梦非：数字化智能运维能力的建设无法一蹴而就，后续我们将继续借鉴 DevOps 技术运营的管理思路与方法，结合实际场景，不断研发新功能，有序提升关键能力域，持续完善国泰君安数字化智能运维平台建设，支撑集团数字化战略快速落地。主要包括以下4点：

1.统一数据底座：通过数据治理持续完善优化平台通、流程通和数据通和能力建设，持续挖掘运维数据价值，为智能运维提供基础有力的数据支撑；

2.自研智能算法：通过产学研结合持续提高自研算法的能力并提高算法的准确性，持续提升智能运维能力，为运维人员发现和处理故障提高有力的工具支撑；

3.挖掘应用场景：通过不断挖掘运维应用场景持续完善成本管理、体验管理等能力建设，补足短板，持续提升IT技术运营价值；

4.整合安全运营：通过优化整合技术运营和安全运营两大领域，结合数据与智能两大能力，为公司数字化转型保驾护航。



Q

关于 DevOps 的发展前景，您怎么看？

A

毛梦非：我们认为 DevOps 的发展前景非常广阔，随着云计算和大数据等技术的快速发展，软件开发和部署过程变得越来越复杂，而 DevOps 正是针对这些挑战提出的一种新型软件开发和运维模式。通过实施 DevOps 流程，可以将软件开发、测试、部署和运营等环节自动化，并加强团队协作，从而提高产品交付速度、质量和稳定性。这对于企业来说是非常有利的竞争优势。我们相信随着时间的推移，越来越多的企业将采用 DevOps，并将其作为提高软件交付效率和质量的重要手段和方法。



国泰君安

数据中心运维技术支持组总监 马辉


Q

请您介绍一下此次参与评估的项目。

A

马辉：此次我们参评的两个项目分别是集中营运和君弘君融交易系统。


集中营运是一个面向公司“全客户、全渠道、全业务”，实现创新模式下基于流程的、可适配异构系统、7×24小时、无纸化的营运业务处理平台，是我司核心业务系统之一。该平台能够有效提升公司整体合规管理水平，进一步落实矩阵式管理。减小分公司的管理半径，有效防范操作风险和道德风险。从根本上解决营业部、网点的资源配置问题，实现业务的跨地域办理。能够紧密贴合互联网时代的客户需求，真正做到线上线下服务的融合。


君弘君融交易系统是一个服务公司高净值客户群体，提供除了基础的委托交易、银证转账、新股申购等功能外，还融合自主研发的算法策略，提供开箱即用的量化工具集，为大客户提供定制化开发服务的机构交易系统，是我司核心交易系统之一。该项目紧紧围绕专业投资者客户的需求，为其提供专业工具辅助交易执行或优化执行效率，打通量化研究到量化实盘的通道，为客户达到决策可量化、交易自动化、风险可管控、监控透明化、能力平台化的量化共建生态目标。



Q

此次通过评估的过程顺利吗？遇到什么困难？如何解决的？

A

马辉：此次评估过程整体较为顺利，虽然在过程中遇到了一些困难，但经过项目组的共同努力，最终保证各项改进任务都如期完成，项目累计梳理完成7个能力域、50+个改进点。


技术运营标准涉及面广，涵盖了监控、配置、容量、连续性和用户体验等多个领域，各领域的成熟度参差不齐、优化工作涉及多个团队，面对以上困难，我们团队进行有效的协同写作，最终不仅达成了通过评估的目标，还完善了自身的技术运营体系。主要包括：

1）上下齐心，目标一致，不仅成立参评专项项目组，各领域都指定了专职人员，绝不止步于评级通过，更重要的是要对该领域内有清晰长远的认知，真正达到以评促改、以评促建的目的；

2）与咨询专家交流探讨，协助梳理改进思路，指定明确详细的改进计划，并针对重点领域提炼长期建设方案；

3）与部门整体的技术运营体系规划有机结合，查漏补缺、补齐短板，持续完善和提升部门技术运营的整体能力。

数据中心系统运行组总监 邹建东


Q

通过此次 DevOps 标准技术运营部分评估对贵团队意味着什么？具体有哪些改进？

A

邹建东：此次参评团队的成员来自各个团队，虽然是临时组建，仅有半年时间改进准备，时间短、任务紧，但是大家还是如期完成目标，这本身就是 Devops 跨职能团队合作文化的一次深刻实践。此外，再次参与技术运营评估，对国泰君安数据中心团队前期探索和投入建设的重点工作进行了更深入的检验，实践表明证实了国泰君安数据中心团队在建设规划与思路上，与信通院倡导的 DevOps 理念和技术运营规范标准，有许多共识之处。同时评估也加深了我们对 Devops 标准的认识与理解，让我们更加清楚地看到我们的优势与不足，对我们后续建设适配公司数字化转型战略的行业领先级智能运维管理体系提供了良好的理论指引和业界优秀实践参考。


本次改进提升主要有两点，一是应用系统高可用架构、持续建设与完善用户体验运营平台，保障应用系统的稳定性与可靠性，为用户提供更好的使用体验；二是优化完善了多个平台的互联互通，形成闭环管理机制，实现精细化运营，持续丰富完善技术运营管理体系。



Q

对于此次参评的项目，其 IT 系统有哪些特色，当时是怎么规划和设计的？

A

邹建东：随着互联网金融的发展，投资者对传统营业部的依赖正越来越弱化，集中营运平台的建设考虑了以下四个方面：

1）实现跨系统的统一登录和统一操作。

2）多渠道受理，形成数据格式统一、内容信息清晰的业务申请记录。

3）技术架构层面引入流程引擎，重构业务流程，实现业务从受理到办理，以及办理各环节之间的自动流程管理。

4）引入协议无纸化办理模式，循序渐进地将纸质协议逐步转变为用电子设备签署的电子协议，大幅降低生产成本和管理成本，并提高客户体验。

在具体技术实现上，业务受理和办理的操作界面由集中作业系统平台统一接管，实现业务人员的一站式登陆操作；同时将受理端和办理段分开，形成了既互联互通，又各自独立，从而构成松耦合的集中营运平台；最后通过集成各个柜台，实现了对各个客户端完全透明，降低了各个客户端适配的开发成本。


国泰君安坚持以客户为中心，持续完善机构客户服务体系，着力打造机构业务完整的交易服务链条，以构建稳定性强、交易速度市场领先、功能完整的量化、极速及程序化交易系统。为解决客户缺少专业辅助型交易工具、缺少实时计算型交易工具、缺少可定制化的交易工具平台、缺少量化实盘交易系统等多项痛点，君弘君融交易系统一站式接入公司所有交易柜台（含普通和极速），业务全面、速度更快，同时也是公司量化交易客户必备的应急逃生通道工具。


此外，君弘君融客户端基于 wpf 技术自主研发，后台技术采用高可用分布式技术框架，后台模块通信使用可靠组播，通过消息保序机制确保所有业务计算节点的强一致性，即支持多个节点同时做相同的业务，主节点故障微秒级别切换备节点，同机房内业务0丢失，所有业务设计天然符合高可用架构。

研发运营一体化（DevOps）能力成熟度模型介绍：

《研发运营一体化（DevOps）能力成熟度模型》系列标准是由中国信息通信研究院牵头，云计算开源产业联盟、高效运维社区、BATJ等顶级互联网公司以及各大金融、通信企业共同制定的国内外首个 DevOps 系列标准，是最完整、最权威、最具行业指导性的研发运营一体化（DevOps）能力标准之一。由中国信息通信研究院主导的 DevOps 标准已由工信部发布并被众多金融、通信和互联网等行业名企纷纷采用并通过评估。

与此同时，DevOps 标准已于2020年7月在联合国直属标准化组织 ITU-T 正式结项，成为全球首个 DevOps 国际标准。研发运营一体化（DevOps）总体架构可划分过程（敏捷开发管理、持续交付、技术运营）、应用设计、安全及风险管理、系统和工具、业务价值管理、合作开发运维、持续测试等。
