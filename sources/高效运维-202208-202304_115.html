农行 DevOps 实践丨农银理财客户份额管理系统 DevOps 建设，助推研发运维一体化能力攀升

2022年12月26日，中国信息通信研究院隆重公布了 DevOps 系列标准最新批次评估结果。
中国农业银行股份有限公司（简称“中国农业银行”）本次共有 9 个系统模块通过中国信息通信研究院《研发运营一体化（ DevOps ）能力成熟度模型》系列标准总计 11 项评估。
其中，中国农业银行研发中心西安研发部参评项目--农银理财客户份额管理系统（FTA）（即“农银理财TA系统灵动产品项目”）顺利通过《研发运营一体化（DevOps）能力成熟度模型》持续交付标准三级评估。

在2023年1月6日举行的“2022 GOLF+IT新治理领导力论坛”主论坛上，中国通信标准化协会副理事长兼秘书长代晓慧女士和中国信息通信研究院云计算与大数据研究所所长何宝宏先生为中国农业银行进行了授牌。




01

农银理财客户份额管理系统 DevOps 持续交付建设

农银理财客户份额管理系统是农银理财子公司负债端核心系统，前端基于UDesk框架开发，后端基于我行自研的太行框架开发，采用两地三中心部署模式，生产环境应用部署、运维及监控告警接入我行自研的一体化生产运维平台，确保应用一键部署、智能运维、全面监控。

在日常工作中建立了一套完整的规范流程：项目经理在接到需求任务后对投产时间进行排期，并进行需求条目化拆分；研发人员根据需求条目拉取特性分支、代码开发、完成单元测试；研发人员提交代码后，通过自动化门禁及人工评审后合并到发布分支；测试准入后配合测试部门进行测试及缺陷修复；创建变更单，按照投产窗口及投产计划开展投产工作；最后开始下一轮迭代工作。

02

DevOps 持续交付实践体会
  • 规范开发，提升质量

在开展 DevOps 建设前，项目的代码版本管理较为混乱，经常会出现不同开发人员提交代码时不小心回退了其他同事的代码、多项目并行开发时开发人员将代码提交到错误的发布分支、缺少单元测试或者代码不规范导致代码质量低下等问题。

DevOps 建设以来，开发人员不能将本地代码直接合并至发布分支，而是需要经过单元测试、代码合规检查、关键代码多人评审等质量门禁才能合并到发布分支，避免问题代码扩散；同时通过在持续集成流水线中内嵌单元测试、代码合规检查、安全扫描、接口自动化测试的质量门禁倒逼代码交付质量提升。
在质量门禁的驱动下，技术债持续下降，自从开展 DevOps 建设以来，接口自动化测试通过率100%、单元测试覆盖率提升59.7%、违例数降低64%、代码重复率保持下降趋势、构建成功率达到90%以上、构建阶段平均时长减少30%。
  • 测试左移，快速对接

在开展 DevOps 建设前，项目流程是先完成所有开发再进行测试，由开发人员需与测试人员对齐需求，手工在测试环境进行应用部署，部署时间与部署频率需双方频繁沟通，这种串行模式常常会导致人员沟通成本高、测试时间紧张、测试不充分，并且随着项目迭代，缺陷被发现和修复的成本会快速增长。

开展 DevOps 建设后，秉持倡导测试左移的思想，测试同事在需求设计与分析阶段介入，有利于开发人员和测试人员在第一时间对齐需求；重构分层策略、将自动化测试纳入流水线，采用自动化测试的方式提升测试效率，测试环境实现一键部署，部署频率时机按需控制，降低了沟通成本，充裕了测试时间，提升了测试质量。

  • 自动部署，高效交付

在开展 DevOps 建设前，多环境部署需要对程序包中环境变量部分代码进行修改，不同环境应用部署需分别打包；生产环境部署需要人工通过was控制台对应用程序进行部署，程序能否正常启动需开发、运维人员通过was控制台实时观测，人力成本及不确定性较高、部署失败常有发生。

开展 DevOps 建设后，实现了应用配置分离，不同环境可以自动识别配置信息，保证开发、测试、版本验证、生产环境程序包均采用单一制品，充分践行所测即所投；开发、测试、版本验证环境制品通过质量门禁把关层层晋级，版本验证环境采用与生产环境相同的部署方式成功部署后才能成功转单到生产环境，目前生产部署成功率达到100%。

本项目能够顺利通过评估得益于项目团队成员的通力合作，在开展 DevOps 建设伊始，项目流程相较于之前变得陌生，团队成员或多或少都有一些疑惑，但是大家都对 DevOps 建设进行了积极配合，遵循规范开发，经过一段时间的实践后，发现在投产前夕不再和之前一样问题百出、手忙脚乱，有一些问题被流水线的质量门禁提前暴露，可以有充足的时间修改，投产的成功率也得到了大幅提升。

此外，农银理财客户份额管理系统作为西安研发部首个参评项目，DevOps 建设也是一个在不断探索的过程中积累经验、持续改进、突破瓶颈的过程。研发中心项目管理办公室也组织了多轮差距分析会议，将建设中的一些宝贵经验与项目团队分享，帮助团队改进问题，补齐能力。在大家齐心协力、紧密协作、共同努力下最终顺利通过了评估。

03

小结

作为我行 DevOps 建设工程试点项目之一，农银理财客户份额管理系统在持续交付能力等方面进行了深入实践，研发、测试、运维自动化能力得到了显著提升。业务、开发和测试协同工作，研发过程快速迭代，端到端全链路交付无缝衔接，产品交付更快捷、项目管理更规范、代码质量和研发效率大幅提升，为部门内其他项目推广 DevOps 奠定基础、积聚力量。

通过 DevOps 持续交付3级评估并不是终点，而是我们持续交付的新起点，在 DevOps 实践道路上，西研的开发、测试同事将一起再接再厉，提高组织内各层级研发运营一体化能力，为我行的数字化转型贡献绵薄之力。

研发运营一体化（DevOps）能力成熟度模型介绍：

《研发运营一体化（DevOps）能力成熟度模型》系列标准是由中国信息通信研究院牵头，云计算开源产业联盟、高效运维社区、BATJ等顶级互联网公司以及各大金融、通信企业共同制定的国内外首个 DevOps 系列标准，是最完整、最权威、最具行业指导性的研发运营一体化（DevOps）能力标准之一。由中国信息通信研究院主导的 DevOps 标准已由工信部发布并被众多金融、通信和互联网等行业名企纷纷采用并通过评估。

与此同时，DevOps 标准已于2020年7月在联合国直属标准化组织 ITU-T 正式结项，成为全球首个 DevOps 国际标准。研发运营一体化（DevOps）总体架构可划分过程（敏捷开发管理、持续交付、技术运营）、应用设计、安全及风险管理、系统和工具、业务价值管理、合作开发运维、持续测试等。
