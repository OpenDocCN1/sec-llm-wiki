国内外大型企业实践表明，标准化和工具赋能是企业成功的关键所在。DevOps 标准及基于标准的 DevOps 持续交付流水线平台和项目实践，可以较大幅度地提质增效，更加安全敏捷地提高企业市场竞争力！“以评促建，以评促改”，以评估为抓手，让 DevOps 标准更快更好落地，助力企业数字化转型。

2022年12月26日，中国信息通信研究院隆重公布了 DevOps 系列标准最新批次评估结果。

招商证券股份有限公司（以下简称“招商证券”）参与评估的项目为新一代核心交易系统项目，该项目顺利通过信通院《研发运营一体化（ DevOps ）能力成熟度模型》技术运营标准 2 级评估，代表招商证券的 DevOps 相关能力达到国内先进水平。

截止目前，招商证券在2022年共通过 5 项中国信通院 DevOps 标准评估，其中包括：通过 DevOps 持续交付标准评估 2 项，通过 DevOps 技术运营标准评估 1 项，通过 DevOps 系统和工具标准的评估 2 项。

评估单位：中国信息通信研究院
2023年1月6日在“2022 GOLF+IT新治理领导力论坛”主论坛上，由中国通信标准化协会副理事长兼秘书长代晓慧女士和中国信息通信研究院云计算与大数据研究所所长何宝宏先生为企业授牌：

此次，我们邀请到招商证券金融科技中心系统运行部总经理何宇先生，深聊招商证券新一代核心交易系统通过 DevOps 标准技术运营部分评估的意义，以及背后团队的故事。


- Q&A -
招商证券金融科技中心
系统运行部总经理 何宇（左六）

Q： 何总好，请您介绍一下此次参与评估的项目。

何宇：招商证券是具有百年历史的招商局集团旗下的证券公司，也是国内拥有证券市场业务全牌照的一流券商。致力于建设“特色鲜明、创新引领、质量第一、贡献卓越的中国最佳投资银行”。公司拥有多层次客户服务渠道，在国内设有259家营业部，同时在香港、英国、韩国、新加坡设有子公司。公司在托管业务竞争中始终保持领先地位，其中私募基金托管产品数量连续八年排名证券行业第一。

近年来我们持续提升安全运营能力，具体发力点如下：1. 落实智能运维2.0规划，提高故障探查能力；2. 持续安全运营建设，构建网络安全体系；3. 建设自动化测试和流量回放能力，保障核心交易质量；4. 建设云原生技术底座，保障资源持续供给；5. 完善应用自动化发布，提升发布效率，降低操作风险。

本次参与技术运营标准评估的项目“新一代核心交易系统”，是证券行业核心交易系统的一次创新与探索，既是业务上的整合，其业务涵盖了集中交易、融资融券、股票期权、订单处理和通用业务等；也是技术上的升级，其技术架构从集中式到分布式，硬件架构从IBM到Intel，操作系统从Unix到Linux、编程语言从C到Java。此外还引入Redis、Zookeeper等大量开源中间件技术。上述的整合与升级无论对于运维人员的技术转型还是运维管理的模式转变来说都是巨大的挑战。目前新一代核心交易系统实现了账户、两融和理财业务的应用服务投产。计划通过本次评估驱动新一代核心交易系统运维能力的完善与提升，为明年集中交易应用服务的顺利投产和稳定运行，打下坚实的基础。 

Q：恭喜您通过 DevOps 标准评估，此次贵公司项目通过的是技术运营 2 级，达到国内先进水平，麻烦您说一下此时的感受。

何宇：很高兴招商证券新一代核心交易系统项目能够顺利通过 DevOps 技术运营 2 级标准评估，这表明我们保障新一代核心交易系统稳定运行的能力进一步得到了提升。随着新一代核心交易系统的逐步投产，运维节点规模从不到百台提升到上千台，运维模式也从登录终端的手工操作转变为借助运维工具实现的大规模自动化运维，对我们的运维人员和运维管理也带来了巨大的挑战。取得 DevOps 技术运营 2 级的评估，是从人员、技术和流程三个方面对招商证券新一代核心交易系统运维能力的全面肯定，也令我们更有信心保障后续集中交易模块的成功投产和稳定运行。

Q：贵公司是如何考虑将此项目进行技术运营评估的？ 

何宇：目前行业内核心交易系统架构还是以集中式为主，存在升级、扩容难，变更影响面广等问题。分布式架构虽然完美地解决了上述问题，但由于存在维护节点多、架构变化大、开源组件掌控能力弱等问题，给运维工作带来了极大的挑战。本次通过技术运营标准评估希望达到以下目的：1. 验证运维能力，从工具、人员和制度等多个维度评估是否满足新一代核心交易系统的运维要求；2. 发现不足，从第三方视角发现当前运维过程中存在的工具和流程问题；3.积极改进，对发现的问题遵照评估老师的建议予以快速解决；4. 推广宣讲，以本次评估辅导过程为契机，帮助运维人员建立运维体系的全局观和方法论。

Q：通过此次 DevOps 标准技术运营部分评估对贵团队意味着什么？具体有哪些改进？ 

何宇：本次参评的“新一代核心交易系统”是证券行业首个分布式核心交易系统，涉及深圳武汉两地的开发、测试、运维人员近百人。上述技术革新和管理规模，给运维带来了巨大的挑战。为此我们参照信通院标准，引入了 DevOps 研发运维一体化的理念，组建虚拟团队，强化沟通协作；建设运维工具平台，提升运维效率；跟踪运维流程的落地质量，控制运行风险。最终通过本次 DevOps 标准技术运营的辅导与评估，我们实现了运维团队自动化与服务化的转型。

在评估初期，由于运维低代码平台、业务全链路分析平台、智能感知平台等运维工具均处于建设阶段，所以在容量成本管理、用户体验管理等领域相对比较薄弱，得分较低。通过对标准的解读和咨询专家的辅导，深圳和武汉两地的项目团队的深度合作，我们加速相关运维工具平台建设和流程制度落地，在最终评估前完成了既定能力域的提升。

Q：对于此次参评的项目，其 IT 系统有哪些特色，当时是怎么规划和设计的？ 

何宇：本次参评的“新一代核心交易系统”，采用分布式微服务架构，具有开源组件多、运维规模大、交易链路复杂等特点。为此我们建设了SEE运维管理平台，与新一代核心交易系统深度整合，管理了上千台微服务节点。使得运维人员无需登录终端，即可完成批量监控、发布等日常运维操作。目前SEE运维管理平台还在增加包括批量发布等一系列的新功能，以优化运维操作体验，提升发布效率，提高监控覆盖率。

针对新一代核心交易系统，交易链路复杂，变更影响分析难的问题，我们从调用链日志、网络流量和Netstat三个数据源提取应用访问关系，并通过CMDB数据丰富，内嵌入变更流程，强化变更评审环节的风险探查能力和事件应急过程中的故障定位能力。

Q：此次通过评估的过程顺利吗？遇到什么困难？如何解决的？

何宇：本次评估过程对招商证券来说是一次迷茫中知不足、知不足而奋进取的持续学习的过程。整个过程中，系统运行部在深圳和武汉两地的多个团队克服疫情的干扰和两地办公的障碍，通力合作完成了本次的评估工作。由于采用了SEE运维一体化工具，整合了监控、自动化、发布等多个完善的运维模块，在监控管理和变更管理等传统能力域得分较高。但在用户体验、成本管理等创新能力域存在不足，主要体现在工具平台方面未完善建设公司级的推广、实施、跟踪等手段。为此，在辅导过程中，我们通过建设虚拟团队的方式，打通不同的部门和团队，合力攻坚将工具、流程、制度实现真正意义的落地。

Q：关于 DevOps 标准，您怎么看，对您企业带来了什么帮助？ 

何宇：本次参评的新一代核心交易系统是公司最重要的对客系统，具有业务功能多、保障等级高、部署节点多等难点。为此，运维通过管理精细化和运维数字化的手段，以ITIL和 DevOps 为理论指导，构建PDCA持续改进流程，以高标准、高要求持续提升运维能力，保障新一代核心交易系统稳定运行。DevOps 标准的落地，为招商证券具象化了“运维数字化”的概念，也为“管理精细化”提供了运维决策所需的数据支撑，对运维来说不仅仅是工具平台的建设，还有制度流程的制定、规范标准的落地、统计数据的分析，这为招商证券更好地服务客户打下坚实的技术基础。

Q：关于 DevOps ，接下来团队有什么样的计划？ 

何宇：结合此次评审老师的意见，接下来我们将进一步完善包括混沌工程、运维大数据、统一API网关在内的智能运维2.0工具体系建设；同时会推动告警事件、变更发布、应急演练、性能容量等关键运维流程的落地跟踪与持续优化工作；最后还计划将新一代核心交易系统的当前能力和最佳实践予以总结，向其它业务系统进行快速推广和复制，推动整个IT的运维能力提升到新的高度，有力保障团队的业务创新与服务稳定。

Q：关于  DevOps  的发展前景，您怎么看？ 

何宇：降低风险、扩大规模、缩减成本、提升效率是运维长期坚持的目标，而 DevOps 就是实现上述目标的重要理论依据。运维标准化和自动化仅仅是我们迈出的第一步，未来我们需要进一步推动运维数字化的转型，具体细化为流程服务化、管理精细化、平台智能化三个方向。我们将以 DevOps 理论指导云原生、工作流程、人员组织的整合，在推动IT数字化转型的同时，进一步推动企业的数字化转型，帮助传统券商拥抱金融科技，提升客户服务质量，助力业务创新迭代。

招商证券新一代核心交易系统项目介绍：

SEE运维控制台：对应用的统一管理，包含部署、升级、应用管控、服务治理；对监控的统一管理，包含基础硬件、网络、系统、组件、数据库、业务指标监控、监控事件跟踪及告警处理、监控数据报表、定制视图、数据全链路看板；对自动化作业的统一管理，包含通过脚本、系统接口等实现对运维过程的自动化处理，根据需要个性编排流程等。

两融业务调用链视图：可直观看到两融业务的调用链关系视图，APP端业务的关键API的具体指标信息，辅助故障预警和运维决策。

业务全链路分析：覆盖核心交易链路，方便开发、测试和运维人员快速了解生产环境业务流向，建立用户全旅程视图，提供应用的来源分析和去向分析服务，实现对用户行为的体验指标监控。

业务链路拓扑平台：开发负责人在提交变更流程时，可直观查询变更所涉及系统在生产环境的真实访问关联关系，维度包括业务、模块和IP，可按时间查询增量或全量，满足变更影响性分析的要求。

全业务链监控平台：对于采集到的交易追踪的数据，通过业务展示的需要去自由组合这些数据，从而进行可视化的展示，例如业务报表的展示。

用户体验优化：通过智能感知系统每日执行用例，对业务指标进行实时监控，从而进行用户端业务的感知与实时观测。

研发运营一体化（DevOps）能力成熟度模型介绍：
《研发运营一体化（DevOps）能力成熟度模型》系列标准是由中国信息通信研究院牵头，云计算开源产业联盟、高效运维社区、BATJ等顶级互联网公司以及各大金融、通信企业共同制定的国内外首个 DevOps 系列标准，是最完整、最权威、最具行业指导性的研发运营一体化（DevOps）能力标准之一。由中国信息通信研究院主导的 DevOps 标准已由工信部发布并被众多金融、通信和互联网等行业名企纷纷采用并通过评估。

与此同时，DevOps 标准已于2020年7月在联合国直属标准化组织 ITU-T 正式结项，成为全球首个 DevOps 国际标准。研发运营一体化（DevOps）总体架构可划分过程（敏捷开发管理、持续交付、技术运营）、应用设计、安全及风险管理、系统和工具、业务价值管理、合作开发运维、持续测试等。
