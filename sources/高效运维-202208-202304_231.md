# 燃！中国农业银行通过 DevOps 应用设计标准 3 级评估，相关能力达到国内领先水平

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzA4Nzg5Nzc5OA==&mid=2651727633&idx=2&sn=29836a5e9ffe9a67ea1c5a2dfc211d1c&chksm=8bc8e4b8bcbf6daec4ddd92b0b0a64b808e0a93a0d9c01dda4ccd16e6db828b073f10e47f1ce&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzA4Nzg5Nzc5OA==&mid=2651727633&idx=2&sn=29836a5e9ffe9a67ea1c5a2dfc211d1c&chksm=8bc8e4b8bcbf6daec4ddd92b0b0a64b808e0a93a0d9c01dda4ccd16e6db828b073f10e47f1ce&scene=27#wechat_redirect)

![](../Images/44035b760cd72527796e69c9434a707f.png)国内外大型企业实践表明，标准化和工具赋能是企业成功的关键所在。DevOps 标准及基于标准的 DevOps 持续交付流水线平台和项目实践，可以较大幅度地提质增效，更加安全敏捷地提高企业市场竞争力！“以评促建，以评促改”，以评估为抓手，让 DevOps 标准更快更好落地，助力企业数字化转型。**2022年12月26日，中国信息通信研究院隆重公布了 DevOps 系列标准及 AIOps 系列标准最新批次评估****结果**。

中国农业银行股份有限公司（简称“**中国农业银行**”）参与评估的项目为**分布式核心客户信息上云项目**，该项目顺利通过**中国信息通信研究院《研发运营一体化（ DevOps ）能力成熟度模型》应用设计标准3级评估**，代表中国农业银行的 DevOps 相关能力达到国内领先水平。

中国农业银行是全国首家也是目前唯一一家通过 DevOps 应用设计标准3级评估的企业。目前，中国农业银行总共通过 17 项中国信通院 DevOps 标准评估，其中通过 DevOps 持续交付标准评估 12 项，通过 DevOps 应用设计标准评估 1 项，通过 DevOps 安全及风险管理标准评估 4 项。**本批次评估将于2023年1月6日中国信通院主办的 “2022 GOLF+ IT新治理领导力论坛”上正式举行授牌仪式。**

此次，我们采访了中国农业银行研发中心副总工程师闫晓林女士，中国农业银行研发中心应用开发一部专家刘国兴先生，一同深聊团队在项目参与评估时的细节和故事，分享中国农业银行 DevOps 实践的经验。

**\- Q&A - **

![](../Images/421eb92db2bd9d6b21f4c9e1856b2366.png)

中国农业银行研发中心副总工程师 闫晓林

**Q：您好，请介绍一下您和您的企业，以及此次参与评估的项目**

**闫晓林**：中国农业银行是一家国有大型上市银行，致力于建设经营特色明显、服务高效便捷、功能齐全协同、价值创造能力突出的国际一流商业银行集团，为全球逾8亿客户提供高效稳健的金融交易服务。农业银行深入践行数字化转型，秉持“守正创新、安全可控、普惠民生、开放共赢”原则，不断完善技术创新体系。

此次参与评估的分布式客户信息项目，对全行客户信息进行统一管理，为总分行提供一致的、实时的客户信息访问服务。项目采用了微服务架构实现不同功能模块的解耦及服务自治，构建了单元化多活容灾体系支撑系统业务连续性保障和应急处置能力，可提供灵活丰富的客户信息服务，有力支撑了农行业务的快速发展。

**Q：恭喜您通过 DevOps 标准评估，此次贵公司项目通过的是应用设计标准评估，表明达到了国内领先水平，请说一下您此时的感受。****闫晓林：**很高兴分布式客户信息项目通过应用设计评级标准评估，这是我行首个通过该评估的项目，也是业界首例。

DevOps 应用设计标准是研发运营一体化（DevOps）能力成熟度模型中的一部分，是对应用软件的技术架构成熟度评估的标准。标准包括可扩展性、可伸缩性、可测试性、可观测性、可用性及安全性6个能力子域，关注应用软件技术架构为了支撑敏捷开发管理、持续交付、技术运营、安全及风险管理等能力域目标实现所需要具备的关键能力要求。

我行积极布局 DevOps 应用实践，实现了项目需求、开发、测试、部署和运营的协调统一，通过组织级协作和平台层面的支撑，不断探索应用设计的优化，在保证业务连续稳定的前提下，快速交付高质量的软件和服务，灵活应对快速变化的业务需求和市场环境。评估过程中我们得到了专家的肯定和认可，这不仅是对核心系统客户信息模块应用设计能力的肯定，也是对农行 DevOps 能力在应用设计方向实践成果的认可。

**Q：贵公司是如何决定加入 DevOps 标准评估工作中的？**

**闫晓林**：中国信息通信研究院 DevOps 标准体系覆盖了软件价值交付端到端的全过程，其核心目标是快速交付、高质量的交付，它不仅仅是软件工程层面的变革，也是企业文化及管理流程的变革。DevOps 理念与我行数字化转型过程中的需要和诉求深度契合，从2020年起，我行通过了信通院的 DevOps 持续交付三级评估，代表着我行的持续交付能力已达到国内领先水平。本次聚焦应用设计能力评估，选取了行内代表性项目参加业界首评，希望通过这次机会，验证我行 DevOps 应用设计能力建设成果，并以此次评估为契机，持续提升企业级的 DevOps 应用设计能力。**Q：通过 DevOps 标准评估对您企业带来了什么帮助？对贵团队有哪些影响？****闫晓林**：DevOps 应用设计标准聚焦应用设计能力成熟度评估，为研发团队提供了参考的标准和度量的依据。DevOps应用设计部分的测评，涉及35个能力项，考察点近200项，作为首家参评的企业，在较短时间内深入解读标准、查漏补缺，整个参评过程是对我行应用设计能力的一次全面、细致的梳理。通过本次评测，项目团队收获了专业的知识和实践指导，参评项目在应用设计的可扩展性、可伸缩性、可测试性、可观测性、可用性、安全性等各领域都对标业界先进水平要求进行了系统性的检验,有助于准确定位我行当前 DevOps 应用设计相关能力所处成熟度阶段，系统性分析差距所在，更好地驱动应用设计能力向更高成熟度提升，以此提高应用开发效率、交付能力和运营能力，促进业务增长。同时，通过此次业界首评，我们也希望树立DevOps应用设计实践在国内落地的行业标杆，引领行业发展。

**Q：对于此次参评的项目，其IT系统有哪些特色，当时是怎么规划和设计的？**

**闫晓林**：此次参评的项目是分布式核心客户信息系统，作为银行核心系统的基础应用模块，是全行对客服务的基础设施。分布式核心系统在建设之初就进行了广泛深入的顶层架构设计预研，最终明确了基于云平台的微服务单元化架构。具体到客户信息系统来说，在业务架构方面，采用领域驱动设计的理念，按对公客户信息、个人客户信息、公共服务、客户合约视图服务等业务领域进行了水平拆分，降低业务耦合；在系统架构方面，一是使用全行统一的技术中台开发框架和 DevOps 质量门禁流水线，确保代码符合开发规范；二是运用分布式核心网关、分布式注册中心、配置中心为基础的微服务运行框架，实现了应用报文和日志统一、单元化路由管控、灰度验证、应用配置分离；三是通过企业级运维平台，实现变更和操作自动化、生产监控和故障告警；四是依托云平台提供的云原生服务互联、服务发现、容器伸缩以及分布式数据库的容灾切换能力实现了应用的高可用、可扩展、易运维。这些能力的实现与本次参评的DevOps应用设计的可扩展性、可伸缩性、可观测性等六个标准不谋而合。![](../Images/b28303109d2a624eff748c4ac9d3ff7f.png)中国农业银行研发中心 应用开发一部专家 刘国兴

**Q：此次通过评估的过程顺利吗？遇到什么困难？如何解决的？**

**刘国兴：**DevOps 应用设计评估的考查范围覆盖了设计、开发、测试、投产、运维等多个环节，如设计环节的微服务业务拆分；开发环节的服务间调用方式、接口兼容性；测试环节的自动化测试、挡板测试；投产环节的变更、验证自动化；运维环节的监控、告警和故障处置等。得益于农业银行较为完善的开发规范、全面的开发平台、完整的DevOps 流水线，以及成熟的基础设施（如微服务网关、注册中心、运维平台、云计算平台等），评估过程总体来说还是比较顺利的。但具体到实施过程中确实也遇到一些困难，比如以前系统的故障告警更多的是从宏观上反映系统的整体运行情况，对于具体的异常部位、异常交易、异常程序或方法的定位大都靠人工分析，可观测性能力提升存在瓶颈。我们一是通过规范直连告警内容，输出了错误码、接口、线程、类等信息，使告警内容更加精准；二是通过对系统运行日志、性能指标、调用关系、运维活动等数据的全域聚合分析，运用我行运维数据分析平台，对此类场景进行深入挖掘，实现了系统故障时的多维异常定位及智能根因分析，能够自动诊断出异常的交易、渠道、省市等维度信息，并智能推荐可能导致故障的根因指标，精准把控关联影响，提高全局洞察分析能力。最终提升了系统整体可观测性指标。

**Q：对于 DevOps 今年的实施，您觉得最大的收获是什么？您的下一步计划是？**

**刘国兴**：经过前期的工作，农行已建成研发工具中台和持续交付流水线，并在研发中心进行了 DevOps 推广。在此基础上，2022年继续扩大了DevOps应用范围，一是向内深化 DevOps 持续交付能力；二是向外开展评级测评；三是向分行输出 DevOps 能力。在此次DevOps应用评级的过程中，最大的收获莫过于项目组学习到了开发、测试、运维、安全各领域标准的设计规范以及先进的业界实践，以指导今后的系统研发工作。下一步项目组将持续对照可扩展性、可伸缩性、可测试性、可观测性、可用性、安全性这6个能力子域的高等级标准进一步提升能力，对各平台工具的系统性、便捷性提出具体优化建议，进一步完善开发、测试、运维、安全体系。

**Q：对于 DevOps 的发展前景，您怎么看？**

**刘国兴**：DevOps 是一种重视开发人员与运维人员之间沟通合作的机制和文化，可以大幅度地帮助企业提质增效，更加安全敏捷地提高企业的市场竞争力，这些能力是当代企业的核心诉求，为 DevOps 赋予了强大生命力和广阔发展空间。希望 DevOps 可以在更多的企业得到应用，切实提升敏捷、高质量的交付能力和IT管控、治理水平。**分布式核心客户信息上云评估现场图：**![](../Images/7088f47b0d8b2ccf7ffbb56e744b1997.png)**分布式核心客户信息上云项目组成员合影：**![](../Images/4e7a805fe818df3baa4a786f6143b101.png)
