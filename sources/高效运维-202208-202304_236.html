一、域

域环境通过活动目录（Active Directory Domain）和域控制器（Domain Controller）为网络提供一种中央集权的访问控制机制，使用户可以在整个网络中使用单一账户登录和访问资源。活动目录是域环境中Windows Server内置的目录服务管理平台。域控制器是活动目录的存储位置，保存着域中所有对象的信息，并提供身份验证和授权服务。域中的对象包括用户帐户、计算机帐户、组、部门、应用程序等。

二、域攻防技战术

域控作为集中管控平台，本身存在SMB、RPC等高危服务、网络穿透性高、影响范围大、潜伏性强等安全风险，往往是攻击者重点“关照”的目标。

1、域攻击技术

根据MITRE ATT&CK攻击模型和PTES渗透测试框架，针对域的攻击技术在信息探测、凭证窃取、权限提升、横向移动、权限维持等阶段具有超过220种攻击技术，例如SPN扫描、密码喷洒、Kerberoasting攻击等。
SPN扫描。SPN（Service Principal Names）是服务器上所运行服务的唯一标识，每个使用Kerberos认证的服务都需要一个SPN。通过SPN扫描可以快速收集、定位域内提供的服务，便于展开下一步攻击，并且微软官方提供SPN扫描方法，很难监测发现。

用户枚举。在Kerberos认证的AS_REQ阶段，传递的AS_REQ数据包包含pre-authentication和client info两个字段，这两个字段分别是client hash加密的时间戳和用户信息。在进行用户枚举的时候只发送client info，AS会根据用户在AD域中存在与否，返回不同的状态信息，可以在不知道用户是否存在、不知道密码的情况下，根据状态信息枚举用户。

密码喷洒。在域内一般会开启锁定阈值策略，密码错误尝试次数超过阈值后用户账号就会被锁定，因此在实战中密码爆破使用较少，一般采用密码喷洒方式。密码喷洒是用一个密码去碰撞大量账号，此方法可以绕开锁定阈值策略，避免账号被锁定。因此在通过用户名枚举获取到域内用户后,可以使用通用密码进行喷洒攻击。在确认用户存在后，可以发送AS-REQ请求，如果密码正确，则返回AS-REP，否则返回KRB5KDC_ERP_PREAUTH_FAILED。
AS-REP Roasting攻击。AS-REP Roasting是一种对用户账户进行离线爆破的攻击方式。该攻击的利用前提是不需要Kerberos预身份验证。攻击者首先使用指定用户去请求票据，域控不会作任何验证就将TGT票据和该用户Hash加密的Session Key返回。攻击者就可以对获取到的用户Hash加密的Session Key进行离线破解，如果破解成功，就能得到该指定用户的密码明文。该攻击方式还需要攻击者拥有足够的计算能力。
Kerberoasting攻击。任何通过Active Directory验证的域用户都可以查询具有服务主体名称（SPN）的用户帐户。这使得攻击者能够访问网络上的计算机，并能够确定支持Kerberos身份验证的所有服务帐户及其用途。攻击者可以使用有效的域用户的身份验证票据去请求运行在服务器上的一个或多个目标服务的服务票据。域控在活动目录中查找SPN，并使用与SPN关联的服务帐户加密票据，以便服务能够验证用户是否可以访问。请求的 Kerberos 服务票证的加密类型是 RC4_HMAC_MD5，即服务帐户的 NTLM Hash用于加密服务票据。攻击者将收到的服务票据离线进行破解，即可得到目标服务帐号的NTLM Hash，称之为 Kerberoasting 攻击。简而言之，在拿到可以注册SPN的域账户或者拿到域控的前提下，攻击者可以为指定的域用户添加一个SPN，并可以随时获得该用户的服务票据，从而经过破解后可以获得明文口令。
DCSync攻击。在AD域中，不同域控每间隔一定时间会进行一次域数据的同步。当一个域控想从其他域控获取数据时，需要向其发起一个 GetNCChanges 请求，该请求的数据包括需要同步的数据。如果需要同步的数据比较多，则会重复上述过程。DCSync攻击就是利用的这个原理，通过DRS服务的 GetNCChanges 接口向域控发起数据同步请求，在不登录域服务器的情况下，即可远程通过域数据同步复制的方式获得用户口令信息。
SYSVOL与GPP漏洞。SYSVOL漏洞指的是AD域中的SYSVOL文件夹存在安全漏洞，可能被攻击者利用来访问敏感信息。SYSVOL文件夹是AD域中的一个共享文件夹，用于存储组策略对象（GPO）中的文件。如果攻击者可以访问SYSVOL文件夹中的文件，就可以获取敏感信息，并可能对AD域造成损害。如果攻击者找到了SYSVOL文件夹中的漏洞，可以通过修改文件内容或者增加新文件，来访问敏感信息或者控制用户和计算机的行为。GPP漏洞指的是AD域中的组策略对象（GPO）存在安全漏洞，可能被攻击者利用来访问敏感信息。GPO是AD域中用于配置用户和计算机策略的一种工具。如果攻击者可以修改GPO中的策略，就可以控制用户和计算机的行为，并可能对AD域造成损害。如果攻击者找到了GPO中的漏洞，可以通过修改策略内容或者增加新策略，来访问敏感信息或者控制用户和计算机的行为。利用SYSVOL和GPP漏洞进行AD域攻击的优点在于，攻击者仅通过修改文件内容或策略，达到控制用户和计算机的目的。但是，寻找SYSVOL文件夹或GPO中的漏洞需要花费大量时间，并且攻击行为可能会被AD域的安全系统发现，导致攻击失败。
Windows提权漏洞。MS14-068漏洞是位于kdcsvc.dll域控制器的KDC服务中的漏洞，它允许经过身份验证的用户在其获得的身份验证票据TGT中伪造插入任意的PAC。普通域用户可以通改变后PAC的伪造票据获得管理员权限，即能够将域内一台机器提升到域控权限。烂土豆提权漏洞（CVE-2016-3225）是Microsoft服务器消息块(SMB)中存在特权提升漏洞，本地攻击者可通过转发适用于在同一计算机上运行的其他服务的身份验证请求，利用该漏洞使用提升的特权执行任意代码。域控Netlogon特权提升漏洞(CVE-2020-1472) 是Netlogon协议认证的加密模块存在的缺陷导致的，当使用Netlogon远程协议建立与域控制器连接的易受攻击的Netlogon安全通道时，攻击者可以通过调用Netlogon中RPC函数NetrServerPasswordSet2重置域控的密码，以域控的身份进行Dcsync，获取域管权限。AD域权限提升漏洞（CVE-2022-26963）是当Windows系统的AD证书服务（CS）在域上运行时，由于机器账户中的dNSHostName属性不具有唯一性，域中普通用户可以将其更改为高权限的域控机器账户属性，然后从AD证书服务中获取域控机器账户的证书，导致域中普通用户权限提升为域管理员权限。

哈希传递攻击（PTH）。哈希传递攻击是指攻击者可以通过捕获与账户相关的密码散列值（NTLM Hash）来进行攻击。由于在 Windows 系统 NTLM 认证的 TYPE 3 消息计算 Response 的时候，客户端使用用户的 NTLM Hash 进行计算，因此在模拟用户登录或对访问资源的用户进行身份认证的时候，是不需要用户明文密码，只需要用户Hash。攻击者可以利用 NTLM  Hash 直接远程登录目标主机或反弹 Shell。在域环境中，用户登录计算机时一般使用域账户，大量计算机在安装时会使用相同的本地管理员账户和密码，因此，攻击者可以使用哈希传递攻击的方法来登录内网中的其他主机。使用该方法，攻击者不需要花费时间来对Hash进行爆破，在内网渗透中使用PTH进行横向移动是非常经典的手段。

黄金票据。在Kerberos认证的TGS_REQ阶段，Client将发送大致三种数据。两种加密的，一种不加密的。加密内容包括TGT、Login Session key加密的时间戳，不加密内容为要访问的服务名称等。当TGS收到请求后，将会检查自身是否存在客户端所请求的服务。如果服务存在，通过krbtgt的NTLM Hash解密TGT获得Login Session key，使用Login Session key去解密数据。因此，如果攻击者获取了krbtgt的密码或NTLM Hash，就能够解密或加密TGT，从而伪造任意用户。由于krbtgt账户一般不会被登录，且密码一般要求定期修改，几乎不可能在拿到域控之前获得krbtgt账户的密码或hash，因此“黄金票据”一般用作后期维持权限。
DCShadow攻击。DCShadow攻击是指在拥有域管理员权限的前提下，攻击者可以在活动目录中创建伪造的域控，使其被其他域控认可并能够参与域复制，通过强制触发域复制，将预先设定的对象或对象属性复制到正在运行域服务器中。DCShadow攻击需要域管权限，常用作持久化利用。面对层出不穷的攻击手段，AD域防护依旧存在不少痛点。首先，不少企业缺乏AD域基线管理，域控用户权限管理较为复杂，域账户涉及的员工、系统无法及时更新清理，大部分运维人员安全意识薄弱，管理不规范。其次，攻击过程中非法域用户行为隐蔽，难以发现，域内日志解析难度大，域内流量无法分析，安全监控和检测手段不足。面对攻击，企业的终端威胁检测与响应能力有限，自动化处置困难。

2、域防守技术

针对AD域防护的难点，结合域攻击技战术，通过对域环境加强安全管理、精细化网络隔离、部署蜜罐主动防御技术、持续监控运营等方面提升域的安全防护能力。
收敛攻击面，规范域管理。一是无论生产环境还是测试环境，要求所有域控统一操作系统并配置相同，统一更新补丁，定期交叉检查，杜绝补丁未打、漏打的低级错误，及时评估和清理域控上不必要的第三方应用和服务，缩小攻击利用面。二是梳理域控服务器的直接管理员账户、间接管理账户和相关影子管理账户，按照最小授权原则，从管理特权组中移除不必要的用户。三是建设完善AD域安全基线，所有的安全策略均通过活动目录组策略及Windows系统自身安全特性实现，并且通过新组策略配置，不修改现有组策略，主要包括用户权限分配策略、身份验证协议选项、UAC配置策略、Windows高级日志审计策略等。
实施域控网络隔离。一是在域管理员通过堡垒机访问域控的路径中，部署专用的安全管理工作站，供域管理员专人使用，限制仅有安全管理工作站一条路径访问域控。二是实施域控网络隔离，启用域控系统内置防火墙，部署相关防火墙策略，仅允许安全管理工作站访问。三是在所有域控上禁止通过PSExec进行远程执行等，实现域控管理通道与业务通道的隔离与独立，让攻击者找不到入侵路径。
配置蜜罐，诱导攻击。在域环境中，攻击者会尝试使用其他用户的凭据，利用其他主机来混淆已有的日志和流量。可以通过设置用户蜜罐，主动探测潜在攻击行为，只要入侵者对特定账户进行特殊操作（如侦测其相关属性、登录位置），即发出相关警告，实现积极防御效果。
部署域控防护平台，持续监控运营。一是针对域控服务器实施监测。启用Windows高级日志审计策略，主要包括配置账户登录、账户管理、详细跟踪、登录注销等安全审核日志；设置域控安全日志大小为300M以上，启用安全日志存档属性，保留时间在6个月以上。通过日志采集与分析系统采集登录日志事件，监控域管理员的登录事件。在域控服务器上部署微软官方产品ATA轻型网关，采集Kerberos、DNS、RPC、NTLM等常见网络流量。二是部署域控安全防护产品，实现对域控服务器的安全监控与响应。通过agent或镜像流量的方式采集域内日志、流量以及域内实体数据，发现包括信息探测、凭据窃取、横向移动、权限提示、权限维持、防御绕过等多种攻击方式，并基于模型构建攻击行为模型，通过偏移量分析，识别高级未知的攻击行为。三是开展常态化全面域基线扫描、域漏洞监测、内网渗透、钓鱼演练、红蓝对抗等，持续验证和运营智域高级，强化域安全问题的分析、运营和处置能力。

三、域控防护总结

域作为企业办公网络的核心，关乎整个企业网络的安全。针对域的防护工作至关重要，日常工作中要根据最小授权原则收敛攻击面，规范域管理，做到域控网络隔离。为应对恶意攻击，应提前部署蜜罐诱导，部署预控防护平台，持续监控攻击行为。AD域安全防护是一项艰巨的工作，不仅需要部署完善的安防设备、持续监控运营，更需要规范员工行为，提升员工安全意识。
