国内外大型企业实践表明，标准化和工具赋能是企业成功的关键所在。DevOps 标准及基于标准的 DevOps 持续交付流水线平台和项目实践，可以较大幅度地提质增效，更加安全敏捷地提高企业市场竞争力！“以评促建，以评促改”，以评估为抓手，让 DevOps 标准更快更好落地，助力企业数字化转型。

2022年12月26日，**中国信息通信研究院隆重公布了 DevOps 系列标准最新批次评估结果**。交通银行股份有限公司（简称“交通银行”）参与评估的项目为****新基金养老模块项目、云跨行项目****及****惠民就医项目****，三个项目均顺利通过信通院《研发运营一体化（ DevOps ）能力成熟度模型》**持续交付 3 级**评估，代表交通银行的 DevOps 相关能力达到国内领先水平。目前，交通银行共有 6 个项目通过了 DevOps 持续交付标准评估，1 个项目通过了 DevSecOps 标准评估。

此次，我们采访了交通银行软件开发中心总经理刘雷先生，一同深聊团队在项目参与评估时的细节和故事，分享交通银行 DevOps 实践的经验。

**\- Q&A -**![](../Images/03732ba3c707d4507f1d0c21ac787ea2.png)交通银行软件开发中心总经理  刘雷

**Q：您好，请介绍一下您和您的企业，以及此次参与评估的项目。**

**刘雷：**我是交通银行软件开发中心总经理刘雷，首先非常感谢中国信通院评审专家对交通银行 DevOps 转型成果的肯定。

交通银行是一家有着百年历史的国有金融企业，也是国内唯一总部在沪的国有大型商业银行。交通银行一直以来秉承科技是第一生产力，持续推进金融科技改革，积极践行数字化转型。自2002年以来，交行的信息化建设历经数据大集中、“531” 工程、“新531”工程等阶段，金融科技工作在深化改革、科技赋能、数据治理、架构转型、风险防控、稳定运行各方面取得积极成效。为提升数字经营能力，启动数字化转型工程，推动实现新金融模式、新业务价值增长，开启数字化交行新征程。

本次参评共有三个项目，一是新基金养老模块，该项目承担我行个人养老金投资基金的功能建设职责，与中国证券登记结算有限公司进行养老业务交互,完成信息交互、养老账户管理及处理账户行资金清算功能，同时为客户提供全面便捷的个人养老基金服务。二是企业资金服务云系统，该系统以实现企业集团提高资金运营效率、降低资金成本、防控资金风险为目标，针对资金管理需要，利用银企直连接口，为集团企业等客户提供优质的财务管理服务。三是惠民就医产品，该产品是一款面向参保用户发放专项就医信用额度的数字化信用支付产品，为用户提供在线签约、支付、退款、还款服务，为医院提供医疗机构签约、对账清算服务。

**Q：恭喜贵行通过 DevOps 标准评估，此次贵行三个项目均通过持续交付标准 3 级评估，表明达到了国内领先水平，请说一下您此时的感受。 **

**刘雷：**很高兴我行新基金养老、惠民就医和云跨行三个项目通过了持续交付 3 级评估，标志着我行 DevOps 能力达到业界领先水平，是对我行 DevOps 推广和落地工作的肯定，也是我行在开发运维一体化流程建设中的一项重要成果。非常感谢信通院各位专家在此次评估中给予的指导和帮助。

本次评估是继2021年智慧人资和跨境金融通过持续交付3级评估后的第二批试点项目，三个项目通过持续交付 3 级评估，标志着我行在 DevOps 规模化推广中更进一步，为后续全面提升工具平台和项目组 DevOps 水平奠定了强有力的基础。

**Q：贵公司是如何决定加入 DevOps 标准评估工作中的？**

**刘雷：**DevOps 成熟度标准是由信通院牵头制定，其持续交付部分对开发、测试、运维一体化流程的实施有重要指导作用，通过 DevOps 标准指导进行差异分析，对标行业最佳实践，以评促改以评促建，可以快速提升 DevOps 水平。

为助力数字化转型，推进金融与科技的深度融合，对科技侧提出了更高的要求。DevOps 在数字化转型工作中有着重要作用，在 DevOps 领域的探索和实践可以将业界最佳实践与交通银行实际工作相结合，从而进一步打造企业级 DevOps 全流程体系与平台，实现需求、开发、测试、运维管理的一体化与可视化。我行2019年启动 DevOps 和工具平台建设，2021年智慧人资和跨境金融项目作为我行首批 DevOps 试点项目通过了持续交付 3 级评估，打通了开发测试运维一体化流程。在2022年，为进一步提升 DevOps 水平，扩大 DevOps 落地实施的广度和深度，完善开发运维流程，选取异地项目进行改进评估，由点及面全面提升我行统一工具平台和整体项目组 DevOps 水平。

**Q：通过 DevOps 标准评估对您企业带来了什么帮助？对贵团队有哪些影响？**

**刘雷：**今年三个项目通过 DevOps 持续交付 3 级评估标志着我行 DevOps 水平已达到业界领先水平，对我行 DevOps 能力提升起到了重要作用，助力我行加快金融科技数字化转型。在组织级方面，通过 DevOps 标准评估，进一步完善并提升了组织级的流程体系，完善了工具平台的支撑能力，实现开发、测试、运维的一体化流转，提升了工具平台的自动化能力以及统一度量平台的过程管理和监控能力，为后续大规模推广奠定了强有力的基础。

在参评团队方面，研发团队根据 DevOps 标准进行了基于标准的最佳实践，研发交付全过程更加标准化。通过迭代进行持续改进，不断压降技术债务，以端到端交付流水线为核心，通过统一工程作业平台打通各项工程活动，实现构建到发布的全流程自动化，减少人工干预的同时提升了产品交付效率和质量。此外，通过 DevOps 实践，形成了融合协作的 DevOps 文化，通过统一度量平台进行度量指标统一管理和过程监控，持续关注度量并依其改进，实现项目快速迭代以增强业务响应能力。

**Q：您可否详细的介绍一下，通过本次评估有哪些数据指标可以直观的体现项目改进成果？**

**刘雷：**通过本次评估，对我行已有的度量平台和度量指标进行完善，查漏补缺，形成一套贯穿研发全流程的效能度量体系，实现从提出需求到发布运维的端到端数据可视化全景视图。项目团队通过持续关注度量结果并进行持续改进，实现效率提升。三个参评项目的改进效果主要提升在以下几个方面：自动构建成功率90%以上、日均构建次数5次以上、接口测试覆盖率100%、集成修复3小时以内，最快30分钟以内、流水线平均时长10分钟以内等。各个项目团队具体工程能力如下：

**Q：对于此次参评的项目，其IT系统有哪些特色，当时是怎么规划和设计的？**

**刘雷：**我行自去年参评 DevOps 成熟度标准以来，目前已有两批试点项目通过持续交付3级标准，第一批试点项目通过 DevOps 持续交付标准评估，我行迈出了 DevOps 标准提升的第一步；第二批试点主要从两个方面选定参评项目，一是选取异地项目同时参评，通过多分中心试点，提升参评项目团队的改进积极性；通过不同类型项目选取，提升 DevOps 项目改进的广度，实现多分中心多项目 DevOps 能力全面提升；二是选取重点新项目，如基金养老、惠民就医（场景金融）等项目，通过重点项目的重视度以及影响力，提升 DevOps 标准在我行的推广效果，树立我行重点项目 DevOps 最佳实践标杆，同时为后续 DevOps 的规模化推广奠定基础。

**Q：此次通过评估的过程顺利吗？遇到什么困难？如何解决的？**

**刘雷：**本次评估在我行各中心的共同努力下，通过迭代改进逐步缩小与标准的差距，最终通过了评估。结果是成功的，但过程是艰辛的，主要体现在以下几个方面：

一是需求多工期紧，本次试点选取的项目大都是重点项目，重点项目的共同点是需求多工期紧，且大部分需求不允许延期。在这样的大前提下，参与 DevOps 标准的改进工作压力是很大的，项目组不畏艰难，合理安排需求开发和改进项结合改进，将改进项拆分到需求迭代中完成，加班加点任劳任怨，在4个月的改进后，完成了 DevOps 能力质的提升。

二是异地项目差异性大，本次三个参评项目分隔三地，且项目类型不同，技术栈不同，对组织级平台改造提出了很大的挑战。工具平台项目组在分析不同项目的差异之后，快速制定方案，项目组周期性沟通紧密合作；遇到问题不急不躁，从平台的功能和项目组的使用方面综合考虑进行改进，最后不辱使命，在满足项目组改进功能的同时，提升了平台的各项能力。

**Q：对于 DevOps 今年的实施，您觉得最大的收获是什么？您的下一步计划是？ **

**刘雷：**今年试点的三个持续交付项目通过持续交付正式评估，标志着我行 DevOps 能力达到了业界领先水平。通过 DevOps 标准评估，我们明确了目标和改进方向，以端到端交付流水线为核心，打通各项工程活动，为研发人员提供统一的工程作业平台，规范研发交付全过程，内嵌质量标准，实现统一的过程管理和监控。目前工程作业平台已支持交通银行200多套主系统，流水线实现了构建、部署一体化，对于通过平台完成构建、部署制品，可通过制品晋级的方式同步至生产环境，通过制品一次构建多次部署，实现了制品单一可信，保证了投产包的完整性、安全性。开发、测试、投产一体化的全流程支撑项目组更快、更安全的交付产品，提升了研运质效。

后续将结合我行实际情况持续和深入地开展优化和实践落地，主要围绕以下方面，一是对标信通院的 DevOps 标准做本地化改造，建立适合交行的 DevOps 标准，二是进一步完善已有 DevOps 工具平台，做好更大范围的推广和落地，提升组织级的 DevOps 能力，三是结合我行十四五金融科技规划，建立企业级 DevOps 工具平台，支持全集团总分行研发，实现研发全过程可视化、云上和云下标准化以及自动化持续交付能力。

**Q：对于 DevOps 的发展前景，您怎么看？**

**刘雷：**在金融行业数字化转型工作中引入 DevOps 至关重要，DevOps 将助力打造企业级全流程体系与平台，实现需求、开发、测试、运维管理的一体化与可视化方面。2022年在人行的十四五科技规划中明确提出“借助业务开发运维一体化 (BizDevOps）、最小化可行产品（MVP）等“小步快跑” 方式搭建低成本试错、快速迭代的交付模式“，结合 BizDevOps 标准的制定和落地，将持续优化完善产品开发和交付质量。由此可见，DevOps 和 BizDevOps 在打造一体化运维平台，实现全流程线上敏捷高质效交付中的重要作用。我们也会继续关注 DevOps 的前沿发展并保持探索和实践，持续推进我行 DevOps 和 BizDevOps 建设，以高水平金融科技能力赋能业务高质量发展！

**研发运营一体化（DevOps）能力成熟度模型介绍：**《研发运营一体化（DevOps）能力成熟度模型》系列标准是由中国信息通信研究院牵头，云计算开源产业联盟、高效运维社区、BATJ等顶级互联网公司以及各大金融、通信企业共同制定的国内外首个 DevOps 系列标准，是最完整、最权威、最具行业指导性的研发运营一体化（DevOps）能力标准之一。由中国信息通信研究院主导的 DevOps 标准已由工信部发布并被众多金融、通信和互联网等行业名企纷纷采用并通过评估。

与此同时，DevOps 标准已于2020年7月在联合国直属标准化组织 ITU-T 正式结项，成为全球首个 DevOps 国际标准。研发运营一体化（DevOps）总体架构可划分过程（敏捷开发管理、持续交付、技术运营）、应用设计、安全及风险管理、系统和工具、业务价值管理、合作开发运维、持续测试等。
