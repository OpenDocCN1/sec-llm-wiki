**赵韵东：**农业银行研发中心作为承载农业银行信息化建设和金融科技创新重任的总行直属部门，为农行各境内外分支机构及控股子公司，在零售银行、公司银行、投资银行、基金管理、金融租赁、资产管理、人寿保险等多业务领域提供完善、可靠的金融交易支撑，为全球逾8亿客户提供高效稳健的金融交易服务。中国农业银行在此次 DevOps 领域持续交付、安全管控、应用设计、智能运维四大领域10个项目取得了优异的成绩。研发支持服务平台（谛听）-开学项目、全文检索服务平台（ARROW）项目、制裁风险智能管控平台项目、农银理财TA系统灵动产品项目、个人客户权益中心、智慧医疗平台项目六个项目顺利通过 DevOps 持续交付标准3级评估！手机银行支付结算模块、个人网上贷款平台“微捷贷"产品两个项目顺利通过 DevSecOps 2 级评估，同业首家获得双模块贯标评估！应用设计分布式客户信息（BDCI）项目业界首个通过 DevOps 应用设计标准 3 级能力评估！运维数据分析平台（孔明）项目通过 AIOps 系统和工具能力成熟度优秀级评估！覆盖多种技术栈，云上云下、前中后台、服务端移动端、微服务架构等方面，通过工具、流程、规范三方面的建设，打通了需求、设计、开发、测试、部署、运维、安全等环节并形成闭环管理，实现可靠可重复、高效灵活的价值交付。**Q：恭喜贵行通过 DevOps 及 AIOps 多项标准的评估，请说一下您此时的感受。****赵韵东：**我行的项目这次能顺利通过评估，我们感到很荣幸。在这里首先要感谢信通院对我行的大力支持，感谢各位评估专家全程细致的测评，为我行后续 DevOps 建设各个领域的优化方向和建设思路给出了具体而实际的建议。项目结合自身系统和团队的特点，查漏补缺，切实提升了系统的持续交付能力、安全管控、应用设计、智能运维水平，在团队中贯彻了 DevOps 理念。评估过程中我们得到了专家的肯定和认可，这不仅是对我行评估系统 DevOps 能力的肯定，也是对农行 DevOps 能力规模化全面推广的认可。  
这次评估验证了农业银行组织级的持续交付、安全管控、应用设计、智能运维水平。DevOps 持续交付标方面，继我行本部6个项目成功通过评估，六个研发分部再创佳绩。DevSecOps 方面，我行成为金融同业首家获得信通院 DevSecOps“开发+交付”双模块贯标评估。DevOps 应用设计评估，我行是业界首评，荣获了三级评估，树立了应用设计实践的行业标杆。以及通过了信通院 AIOps 工具与能力成熟度优秀级评估，标志着农业银行在 AIOps 智能运维能力上达到同业领先水平，是对农业银行极大的肯定。后续，我们将持续沉淀最佳实践，拓展 DevOps 应用建设范围，助推数字化转型。**Q：贵行目前评估的范围涉及了 DevOps 标准的持续交付、应用设计、安全及风险管理等，选择这些技术领域参评请问贵行有哪些考虑？****赵韵东：**2019年，农业银行在数字化转型背景下，启动了 DevOps 建设，与此同时，基于 DevOps 的建设成果，全面启动了 DevSecOps 体系、应用设计能力、AIOps 的建设，并在今年参与到相关领域的评估工作中，以验证建设成果。近年来，我行从推动创新流程重构、组织架构整合、技术架构升级、管理机制优化等4个层面，将小批量交付、全功能团队、部署流水线等 DevOps 的关键理念、方法、工具融入到业务产品的持续价值交付中，从而构建形成基于 DevOps 的数字化产品创新机制。基于标准的 DevOps 持续交付流水线平台和项目实践，可以较大幅度地提质增效，更加安全敏捷地提高持续交付能力。DevOps 系列标准中的持续交付、应用设计和安全及风险管理，以及智能运维等覆盖了软件价值交付端到端的全过程，不仅是软件工程层面的变革，也是企业文化及管理流程的变革。随着业务线上化的发展趋势，以及众多前沿技术的引入，针对金融行业产品进行的攻击手段和攻击形态层出不穷，同时国家和监管机构对金融安全日益重视，这就给金融企业研发运营安全能力提出了更高的要求。农业银行作为国家关键信息基础设施运营机构之一，更需要高度重视网络安全威胁的防护和抵御，不断提升产品安全水平。**Q：继过往6个项目通过持续交付标准评估后，本次又有6个项目参评，基于怎样的考虑？后续还会有哪些规划？****赵韵东：**两批项目的评估使命不同，但都意义非凡。我行前6个 DevOps 试点项目通过 DevOps 标准（持续交付部分）三级评估，验证了 DevOps 建设的成果，也开启了我行规划化运用 DevOps 能力的新纪元。2021年，我行启动 DevOps 全面推广，覆盖全行18个业务条线，包括所有开发测试部门，DevOps 一体化研发体系已进入规模化应用阶段，总行系统应推尽推，分行系统试点推广，在500余个总行系统模块、4家试点分行进行一体化研发能力落地实施。应用成效显著，支持业务价值快速进入市场，提供更佳的客户体验，更好的业务连续性。在全面推广的同时，通过外部评估验证应用成效。  
今年再次有6个项目通过了信通院 DevOps 持续交付三级评估，以业界先进标准助力一体化研发体系的持续提升，赋能价值交付，为金融同业输出优秀且全面的 DevOps 最佳实践。我行以持续交付的成果为基础，“以评促建，以评促改”，以评估为抓手，可让 DevOps 标准更快更好落地，助力企业数字化转型。“心有所信，方能远行”，数智时代正当时，中国农业银行在数字化转型的浪潮中，将继续乘风破浪，加大科技支撑力度，深化全职能高效能团队建设，业技融合、研测一体，全链条密切协作，同时继续融合云原生、大数据、XOps等众多领域的多维升级，持续提升业务价值的快速交付水平，助力金融服务的高质量发展！**Q：可否详细的介绍一下，有哪些数据指标可以直观的体现参评项目的改进成果？****赵韵东：**通过本次评估，持续交付能力、持续交付能力、安全管控、应用设计、智能运维水平保持领先水平。我们可以从数据上直观了解项目成果。例如，运维分析活动周期由2人天下降到0.5人天，应急辅助决策数据获取时间由10分钟下降到1分钟，健康风险巡检从1人天下降到5分钟。随着 DevSecOps 体系建设的推进，以及安全工具实现与流水线的集成，企业级安全漏洞数量已呈现了明显的下降态势。典型高危安全漏洞检出率已实现显著压降，以业务逻辑类高危漏洞为例，实现了同比42.7%的降幅。可见，农业银行 DevSecOps 体系建设，不仅在试点项目的研发运营中实现了良好的落地，而且在组织级的安全水平的提升上，也收获了良好的反馈和成效。**Q：为什么选择这些项目来评估，其IT系统有哪些特色，当时是怎么规划和设计的？****赵韵东：**一方面，掌上银行支付结算产品、微捷贷等都是暴露在互联网上的面客类应用系统，面对的安全风险较高。另一方面，所对应的业务又都是农业银行的重要业务，用户基数大、受众广、业务价值高。另外数据分析平台（孔明）是我行智能运维转型的关键产品，其“数据赋能、场景驱动”的建设理念深度契合 AIOps 智能运维理念，选择该产品参加 AIOps 工具评估就是为了检验农行 AIOps 建设成果，为下一步优化做准备。数据分析平台建设过程中坚持“数据、工具、场景”三管齐下，一方面夯实数据和工具基础，提升数据质量，提高分析效率，一方面注重场景实效，落地风险挖掘、业务态势分析、智能根因分析等多个 AIOps 场景，切实解决运维痛点问题。

**Q：通过评估的过程顺利吗？遇到什么困难？如何解决的？****王利强：**DevOps 是提升整体效能的基础工作，价值重大，意义深远，我们也不惧挑战。在此过程中，有几点让我印象深刻的挑战：一是跨部门组织协调方面，本次工程横跨两中心近 20 个部门，协调难度之大可想而知。二是工具链本地化建设方面，基于既有自研和已购工具做定制化开发，投入成本很大，困难点多。三是度量体系建设方面，应该说度量是看似简单实则很难的一个领域，尤其要结合企业管理导向和评估要求，以往企业更关注组织级数据，评估则更注重项目过程数据，所以我们几乎是从头开始搭建。四是对标准要求的理解和认知方面，确保各工作条线深刻理解、与达成一致也经历了一个较长的过程。五是恰逢新冠肺炎疫情，无法现场办公，沟通成本大大增加。但农行研发人不畏艰辛、合力攻坚，通过多次召开专题会、多部门骨干人员协同钻研、针对性的排查问题等方式，共同推进 DevOps 各项能力落地。比如 DevSecOps 领域涉及到的职能条线、工作团队几乎是最广泛的，尤其是在农业银行这样规模的企业，各团队分工具体而明确，使得 DevSecOps 贯标前的改进工作，涉及众多职能，如基础设施管理、数据管理、第三方管理、研发项目管理、工具平台建设以及安全研发管理和安全运营，这些基本上都是分属于不同的部门。为了解决跨部门沟通协作问题，在 DevSecOps 贯标工作伊始，我们便组建了专项工作柔性团队，以多种形式定期组织会议就 DevSecOps 体系建设进展、遇到的问题和困难以及下一步工作计划进行沟通会商，从而有效推动各项工作的开展。再比如本次 AIOps 评估需要演示完整的根因定位过程，因为这个功能的特殊性，无法直接演示真实生产故障定位的过程，需要在模拟环境完整进行复现，而复现过程存在关联系统多、数据维度多、技术环节复杂等困难。面对这些困难，项目组积极协调各关联系统，逐一梳理准备各类数据，针对不同各类故障场景完整复现了真实排障过程，顺利通过了评估。**Q：对于 DevOps 和 AIOps 今年的实施，您觉得最大的收获是什么？您的下一步计划是？** **王利强：**本次贯标给我们中心 DevOps 建设再次给予肯定，也让 DevOps 建设的目标更加清晰具体、可落地。后续中心一则将考虑新标准如敏捷开发管理和持续测试等的贯标落地、来实现完整的端到端的 DevOps 全体系贯通。二则将进一步持续深化 DevOps 建设，完善 DevOps 体系，优化工具、流程、规范、数据可视化，培养自有 DevOps 人才队伍建设，通过度量反馈来驱动改进，把 DevOps 做实、做强，提升科技支撑能力，赋能研发中心数字化转型，助力金融科技创新和我行市场竞争力。**Q：请问贵行对于金融科技创新，持续提升科技赋能水平方面有哪些目标和规划？****王利强：**银行业是金融科技应用前沿阵地，产品创新需求尤为活跃，构建适合经营策略稳健、产品体系复杂、组织架构相对传统等大型银行特点的产品创新机制尤为重要。中国农业银行经过持续的探索优化，建立起“技术创新双循环”的产品创新体制，顺畅数字化转型之路。一方面深化金融科技外循环，以业务需求为牵引，由业务创新带动技术创新，使金融科技赋能业务发展。在疫情的影响下，社会经济形态已经发生了微妙变化，“宅经济、线上化、零接触”型的商品交易及服务需求更加迫切，信息安全要求更高，为了快速响应业务诉求，促使普惠金融、小微金融、线上信贷、风控等系统持续创新优化，引入5G消息、低代码开发等技术创新，快速响应市场变化，保障业务高质量交付。另一方面提振金融科技内循环，激发技术发展的内生动力，保持技术前瞻性，做厚技术密度，做强技术平台，自动化产品研发过程，形成业务拉动与技术驱动双循环相互促进的技术创新格局。从数据驱动价值、效率叠加价值、体验定义价值三个层面入手，运用大数据、数据挖掘、XOPS等技术，将小批量交付、自动部署流水线、微服务、Docker等关键理念、方法、工具融入到传统产品创新机制，从而构建形成数字化产品创新机制，更有利于支撑快速交付模式，促进业务价值的提升。

**研发运营一体化（DevOps）能力成熟度模型介绍：**《研发运营一体化（DevOps）能力成熟度模型》系列标准是由中国信息通信研究院牵头，云计算开源产业联盟、高效运维社区、BATJ等顶级互联网公司以及各大金融、通信企业共同制定的国内外首个 DevOps 系列标准，是最完整、最权威、最具行业指导性的研发运营一体化（DevOps）能力标准之一。由中国信息通信研究院主导的 DevOps 标准已由工信部发布并被众多金融、通信和互联网等行业名企纷纷采用并通过评估。

与此同时，DevOps 标准已于2020年7月在联合国直属标准化组织 ITU-T 正式结项，成为全球首个 DevOps 国际标准。研发运营一体化（DevOps）总体架构可划分过程（敏捷开发管理、持续交付、技术运营）、应用设计、安全及风险管理、系统和工具、业务价值管理、合作开发运维、持续测试等。
