国内外大型企业实践表明，标准化和工具赋能是企业成功的关键所在。DevOps 标准及基于标准的 DevOps 持续交付流水线平台和项目实践，可以较大幅度地提质增效，更加安全敏捷地提高企业市场竞争力！“以评促建，以评促改”，以评估为抓手，让 DevOps 标准更快更好落地，助力企业数字化转型。  

2022年10月28日，中国信息通信研究院隆重公布了 DevOps 系列标准及 AIOps 系列标准最新批次评估结果。

宁波银行股份有限公司（以下简称“宁波银行”）本次参评的项目为**财资金融服务系统融资中心项目**，该项目顺利通过由中国信息通信研究院开展的《研发运营一体化（ DevOps ）能力成熟度模型》**持续交付 3 级评估**，代表宁波银行的 DevOps 能力达到国内领先水平。

**评估单位：中国信息通信研究院**

此次，我们采访了宁波银行总行金融科技部副总经理程帅先生，一同深聊团队在项目参与评估时的细节和故事，分享宁波银行 DevOps 实践的经验。  

**\-Q&A-**

![](../Images/e8d3d3589f9f10d1f70cb3479710f0ba.png)  
宁波银行总行金融科技部副总经理程帅

**Q：您好，请介绍一下您和您的企业，以及此次参与评估的项目。**

**程帅：**我是宁波银行总行金融科技部程帅。长期以来，宁波银行一贯重视科技赋能，目前总行科技部行员超 1500 人，2020 年我行提出了“ISMART+”智慧银行战略，实施系统化、数字化、智能化的三化发展。本次参评的项目是财资金融系统融资中心，作为财资大管家系统群的重要子系统，按照财资大管家2023版的需求针对融资中心业务功能模块全面优化升级，主要包括：  

1.  细化用户权限，形成内部信贷模块。将原离线登记模块中，债务人、担保人等为集团内部成员单位的数据单独剥离，组成内部信贷模块，实现针对内部用户的统筹管理；
    
2.  配合核心系统、信贷系统改造，使用最新的后台系统，降低交易失败率，提升效率；
    
3.  新增监管中心融资查询模块，实现融资数据实时监控，降低管理成本；
    
4.  优化交易，查询速度，简化流程，减少非必要操作，提升用户体验。

**Q：恭喜您通过 DevOps 标准评估，此次贵公司项目通过的是持续交付3级，表明达到了国内领先水平，请说一下您此时的感受。**  

**程帅：**首先非常高兴，财资金融服务系统能在 5 个多月时间完成 DevOps 持续交付3级能力的评估，非常感谢信通院各位专家在评估过程中的专业指导和帮助。本项目是我行第二个通过信通院 DevOps 持续交付标准 3 级能力评估的项目，能在这么短的时间完成评估，说明通过评估改进确实在能力上带给我们很大的提升，通过“以评促改，以评促建”，更加坚定了我们全面深化推进 DevOps 实践的信心与决心。

**Q：贵公司是如何决定加入 DevOps 标准评估工作中的？**  

**程帅：**宁波银行始终贯彻科技赋能，不断夯实金融科技基础设施与能力，全面推进数字化转型实践，高质量支撑全行业务的稳健发展。我行自 2020 年启动 DevOps 建设以来，针对平台建设、人员赋能、敏捷转型进行了一系列的探索。通过本次标准评估，一方面通过以评促改，对现有成果进行检验和总结；另一方面也是借此机会，借鉴业界领先的同行经验，更加体系化提升软件的持续交付能力。

**Q：通过 DevOps 标准评估对您企业带来了什么帮助？对贵团队有哪些影响？**  

**程帅：**本次评估是我行全行推广 DevOps 中首个直接对客系统，再一次对我行工程能力平台建设、工程教练的培养、度量反馈机制进行了检验和改进，为后续全行工程能力推广树立了标杆。

从宁波银行团队内来说，产品、测试、研发、运维各职能角色对需求的精细化管理、高质量的代码和测试、高效的交付、及时反馈和响应的闭环有了更深刻的实践和探索，形成了一套行之有效的工作方法和制度。从跨团队来讲，通过研发团队、平台团队的协同攻坚，平台团队深入到一线研发用户的真实诉求场景，对平台进行改良和优化；研发团队对平台的使用、理解、建议和认同，更有利于我行平台能力的进一步提升和赋能。

**Q：您可否详细的介绍一下，通过本次评估有哪些数据指标可以直观的体现项目改进成果？**  

**程帅：**通过本次评估改进，我们可以从数据上直观了解项目成果，例如：小微需求从45人天下降到25人天，集成响应时间从0.5 天下降到1小时，投产频率从每月2次提升到每周一次。其它改进数据如下图：

![](../Images/fda3feaceccc90c476c4631cd53fb4e6.png)

**Q：对于此次参评的项目，其IT系统有哪些特色，当时是怎么规划和设计的？**  

**程帅：**我们从系统的重要程度、难题攻克的代表性、历史包袱等多个角度进行考量，最终选择了本系统。融资中心作为财资大管家系统群的重要子系统，改造价值高；复杂的外围系统和业务协同，能代表各类对客系统普遍面临的难题；历史包袱适中，系统改得动但又不至于太容易而没有挑战性。

**Q：此次通过评估的过程顺利吗？遇到什么困难？如何解决的？**  

**程帅：**宁波银行对本次评估给予了高度重视，并且前期做了充分的调研、做了充分的准备工作，包括结合我行内部推行的 DevOps 体系建设、研发一体化平台的使用、配置管理团队的组建、测试管理平台、环境管理平台的推广使用等，所以整体上还是比较顺利的。但是在项目实施过程中也确实遇到了不少实际问题，比如：

1.  多平台的协同问题：职能化团队分工下，各个管理平台、工具平台未有效协同，为取得更快速、高效的交付能力，研发团队和平台团队通过数据共享、API 调用等多种方式把多个平台进行串联和管控，最终实现了多项流程的一键操作；
    
2.  需求方面的粗颗粒度：由于融资业务的复杂背景，业务需求常常庞大而复杂，变更频繁。为了达到快速、稳定、可靠的交付，项目组和产品同学花大力气一遍一遍进行拆分、细化，并协同测试同学进行论证，最终实现了更加精细化的需求管理，也反向提高了需求的质量。

**Q：对于 DevOps 今年的实施，您觉得最大的收获是什么？您的下一步计划是？  
**

**程帅：**在本次参评项目的实施过程中，我们把 DevOps 业界的优秀理论结合我行的工程建设进行了良好实践，不仅培养和锻炼了一批在各个领域有丰富经验的 DevOps 教练，也促进了项目团队、平台团队这样跨部门的协同攻坚能力，项目团队中各个角色对高质量交付能力的认同和践行，也是我们非常大的收获。

接下来，我们会将对DevOps工程能力要求的理解、实践经验沉淀为组织的规则和指导要求，进一步优化全行 DevOps 实践要求和方法论，把评审实践中行之有效的方法在全行进行推广，包括敏捷实践中用户故事的精细拆分、配套自动化流水线工具、及时反馈和跟进机制、度量和改进、自动化测试等。

**Q：对于 DevOps 的发展前景，您怎么看？**  

**程帅：**DevOps 是数字化转型的有力抓手，是快速交付业务价值、赋能业务发展的基础保障。DevOps 首先聚焦在持续交付过程，以提高效率减少浪费、促进研发运维融合为目标，这是在科技管理以致企业管理方面是永不会过时的话题。而随着 DevOps 近几年的发展，出现了越来越多好的实践和技术，例如：AIOps、ChatOps，并且也逐步扩展深入到了安全、业务等领域。我们会以我行的实际情况出发，借鉴参考业界的前沿发展在 DevOps 方面进行持续的探索和实践。

**研发运营一体化（DevOps）能力成熟度模型介绍：**《研发运营一体化（DevOps）能力成熟度模型》系列标准是由中国信息通信研究院牵头，云计算开源产业联盟、高效运维社区、BATJ等顶级互联网公司以及各大金融、通信企业共同制定的国内外首个 DevOps 系列标准，是最完整、最权威、最具行业指导性的研发运营一体化（DevOps）能力标准之一。由中国信息通信研究院主导的 DevOps 标准已由工信部发布并被众多金融、通信和互联网等行业名企纷纷采用并通过评估。

与此同时，DevOps 标准已于2020年7月在联合国直属标准化组织 ITU-T 正式结项，成为全球首个 DevOps 国际标准。DevOps 标准评估体系主要包括敏捷开发管理、持续交付、技术运营、应用设计、安全及风险管理、系统和工具等部分。
