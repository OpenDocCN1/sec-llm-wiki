国内外大型企业实践表明，标准化和工具赋能是企业成功的关键所在。DevOps 标准及基于标准的 DevOps 持续交付流水线平台和项目实践，可以较大幅度地提质增效，更加安全敏捷地提高企业市场竞争力！“以评促建，以评促改”，以评估为抓手，让 DevOps 标准更快更好落地，助力企业数字化转型。

2022年10月28日，中国信息通信研究院隆重公布了 DevOps 系列标准及 AIOps 系列标准最新批次评估结果。

中国民生银行股份有限公司（以下简称“中国民生银行”）本次参评的项目为集中运营业务处理系统项目，该项目顺利通过由中国信息通信研究院开展的《研发运营一体化（ DevOps ）能力成熟度模型》技术运营标准评估，代表中国民生银行在 DevOps 相关领域能力达到国内先进水平。
中国民生银行是全国性股份制银行首家通过中国信息通信研究院 DevOps 技术运营标准评估的企业。
评估单位：中国信息通信研究院

此次，我们采访了中国民生银行信息科技部副总经理吕晓强先生、信息科技部副总经理彭真山先生和信息科技部运营业务板块总监龚育民先生，一同深聊团队在项目参与评估时的细节和故事，分享中国民生银行 DevOps 实践的经验。


- Q&A -

中国民生银行

信息科技部副总经理 吕晓强


Q：恭喜您通过 DevOps 标准评估，此次贵公司项目通过的是技术运营 2 级，达到国内先进水平，麻烦您介绍一下此时感受~
吕晓强：很高兴能够顺利通过本次评估，这代表中国信息通信研究院对我行技术运营能力的肯定。中国民生银行是首个通过 DevOps 技术运营标准 2 级的股份制银行，并且在疫情影响下，项目按预期计划完成，表现了我们的决心和冲劲，感谢信通院各位专家在标准评估过程中对于我行的指导和帮助，同时非常感谢参评项目组全体人员的辛勤付出与努力。

Q：通过此次 DevOps 标准技术运营部分评估对贵团队意味着什么？具体有哪些改进？

吕晓强：本次 DevOps 技术运营标准的参评团队成员来自于集中运营项目组、应用运维中心、生产调度中心、系统管理中心和生产管理中心，大家跨越条线，打破知识壁垒，临时组成参评项目组，并且按计划完成项目目标，本身就是一次突破。这也正是DevOps最核心的理念，有了这次经验，我们会在今后研发运维一体化的方向上走的更有信心。同时，在我们仔细解读了技术运营的标准，并深入剖析了我行现有的能力后，证实了数据中心技术运营能力在建设思路和规划上，与信通院标准是一致的，也更加坚定了我们的决心。在评估初期，由于部分平台建设刚起步，例如容量与成本、用户体验部分能力域相对薄弱，但通过对标准的解读和咨询专家的辅导，我们也在最终评估时完成了目标。

Q： 关于 DevOps ，接下来团队有什么样的计划？

吕晓强：通过这次评估，我们不仅培养了 DevOps 团队，也沉淀了相关知识和能力。接下来我们计划用 DevOps 标准，结合我行科技特点，形成技术规范，把技术规范落到流程和工具上，最终实现以点带线，以线成面，以面扩体的效应。


中国民生银行

信息科技部副总经理 彭真山


Q：此次通过评估的过程顺利吗？遇到什么困难？如何解决的？

彭真山：本次评估总体来说比较顺利。首先，这得益于各级领导对项目组的大力支持，先后从相关条线、中心挑选了多名骨干成员协助项目组进行攻坚克难；其次，整个项目组成员目标一致，相互协作，勇于担当，使得项目顺利通过评估；最后，感谢大家在本次评估过程中付出的努力。

Q：关于 DevOps 标准，您怎么看，对您企业带来了什么帮助？

彭真山：DevOps 标准是由信通院牵头，各大厂、金融、证券、保险、通信等行业共同编写制定，工信部发布的具有指导意义的 DevOps 能力标准。DevOps 国际标准也已于2020年7月在国际电信联盟ITU-T成功获批。该标准包含持续交付、技术运营、安全及风险管理、系统和工具、敏捷等10个标准，涵盖了企业级IT能力的大部分内容，是一套比较全面，且非常落地的指导标准。我们通过它来实现自查、自证、对照和衡量，以先进的标准为参考和依据，来不断的提升和完善自我。

Q：关于  DevOps  的发展前景，您怎么看？

彭真山：从 DevOps 提出到现在，我们可以发现，它并不是一套固定的流程或技术，而是一种方法论。随着IT技术的进步，DevOps本身也一直在成长，它包含敏捷、微服务、标准化、自动化、智能化、合作、文化等。可以说只要以提高IT服务交付效率和质量为目的的东西，都可以算 DevOps，所以在某种程度上来说，DevOps 的发展前景，就是IT技术的发展前景。


中国民生银行信息科技部

运营业务板块总监 龚育民


Q：请您介绍一下此次参与评估的项目。

龚育民：集中运营业务处理系统基于流程引擎、规则引擎以及自主研发平台建设，是我行非常重要的作业类业务支撑系统。该系统通过对中后台作业的全面标准化、自动化、智能化和集约化处理，全面提升我行作业业务处理效能和客户体验，并有效防范作业风险。目前该系统已实现结算业务，信贷业务，财务报账业务，库房业务，账户开户业务，远程银行业务，综合业务等作业的集约化处理。

Q：为什么选择该项目进行技术运营评估？

龚育民：随着我行集中化运营工作的不断深入推进，运营业务处理的敏捷性、专业性以及运营业务的精益化管理日益成为需要我们重点关注和突破的内容。为此，作为我行运营业务的重要承载平台---集中运营业务处理系统，其数字化水平、智能化程度、业务响应敏捷度、系统稳定性和可靠性等也就成为我们技术团队需要重点实现和保障的内容。而DevOps作为一套研发运营一体化的国际化技术运营标准，对服务交付敏捷性、系统运行可靠性和安全性、服务提供的可持续性等都有详细的标准和认证指导，刚好能有效帮助项目组达成上述既定目标。

Q：对于此次参评的项目，其 IT 系统有哪些特色，当时是怎么规划和设计的？
龚育民：集中运营业务处理系统的应用架构分展现层、接入层、集成层、中台层，系统整体按云原生架构开发设计，基础技术平台全部采用行内自研技术框架，前端微前端，后端微服务，并按业务领域切分，支持多团队多模块协作共享开发，通过前端组件共享，后端服务共享能大大提升开发效率。

研发运营一体化（DevOps）能力成熟度模型介绍：
《研发运营一体化（DevOps）能力成熟度模型》系列标准是由中国信息通信研究院牵头，云计算开源产业联盟、高效运维社区、BATJ等顶级互联网公司以及各大金融、通信企业共同制定的国内外首个 DevOps 系列标准，是最完整、最权威、最具行业指导性的研发运营一体化（DevOps）能力标准之一。由中国信息通信研究院主导的 DevOps 标准已由工信部发布并被众多金融、通信和互联网等行业名企纷纷采用并通过评估。

与此同时，DevOps 标准已于2020年7月在联合国直属标准化组织 ITU-T 正式结项，成为全球首个 DevOps 国际标准。DevOps 标准评估体系主要包括敏捷开发管理、持续交付、技术运营、应用设计、安全及风险管理、系统和工具等部分。
