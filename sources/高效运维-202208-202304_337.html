国内外大型企业实践表明，标准化和工具赋能是企业成功的关键所在。DevOps 标准及基于标准的 DevOps 持续交付流水线平台和项目实践，可以较大幅度地提质增效，更加安全敏捷地提高企业市场竞争力！“以评促建，以评促改”，以评估为抓手，让 DevOps 标准更快更好落地，助力企业数字化转型。

2022年10月28日，中国信息通信研究院隆重公布了 DevOps 系列标准及 AIOps 系列标准最新批次评估结果。

招商证券股份有限公司（以下简称“招商证券”）本次参评的项目为新一代场外衍生品管理系统项目和大投行业务平台底稿管理系统项目，两个项目均顺利通过由中国信息通信研究院开展的《研发运营一体化（ DevOps ）能力成熟度模型》持续交付 3 级评估，代表招商证券的 DevOps 能力达到国内领先水平。

招商证券是华南地区首家一次性两个项目通过中国信息通信研究院 DevOps 持续交付标准评估的企业。

评估单位：中国信息通信研究院

中国信息通信研究院云计算与大数据研究所副所长魏凯公布评估结果：

此次，我们采访了招商证券总裁助理、首席数字官、首席网络安全官胡滔女士和招商证券金融科技中心总经理邓曙光先生，一同深聊团队在项目参与评估时的细节和故事，分享招商证券 DevOps 实践的经验。
- Q&A -

招商证券股份有限公司总裁助理

首席数字官 首席网络安全官 胡滔


Q：胡总您好，请介绍一下您的企业，以及此次参与评估的项目。

胡滔：招商证券是具有百年历史的招商局集团旗下的证券公司，也是国内拥有证券市场业务全牌照的一流券商。致力于建设“特色鲜明、创新引领、质量第一、贡献卓越的中国最佳投资银行”。公司拥有多层次客户服务渠道，在国内设有259家营业部，同时在香港、英国、韩国、新加坡设有子公司。公司在托管业务竞争中始终保持领先地位，其中私募基金托管产品数量连续八年排名证券行业第一。

去年，招商证券制定“十四五”数字化规划，确立了具有招证特色的“1633”数字化战略布局，打造以客户为中心、以业务为引领、平台化运作的数字化金融科技体系，全面赋能财富管理、机构、企业、投资研究等业务。经过一年多的落地，逐步形成三个数字化飞轮。第一个飞轮是组织能力升级。公司专门成立了专门的数字化转型委员会、工作小组及PMO，强化数字化转型的组织保障；成立金融科技武汉分中心，进一步充实数字化发展的人才队伍；推进数字化产品经理制逐步落地，打通业务与技术连通的最后一公里。第二个飞轮是技术能力提升。2021年我们全面启动了“对标互联网，领跑行业”的技术目标，重点夯实安全运营、敏捷交付、自主可控、数据驱动、数字基建5大核心能力。DevOps就是敏捷交付的重要组成部分。第三个飞轮是业务价值的创造。围绕着用户爽、协同易、业务赢的业务目标，我们在六大业务域的价值持续深耕，包括招商证券APP、Geetek机构交易平台、新一代场外衍生品管理系统、大投行业务平台等。

本次我们参与持续交付 3 级评估的项目是“新一代场外衍生品管理系统”、“大投行业务平台底稿管理系统”。其中，新一代场外衍生品管理系统是公司适应创新性机构交易业务转型的重要基础设施工程，对标国际投行合成PB，支持跨市场、多品种、全流程的场外衍生品展业平台，该项目也是2022年深圳市金融创新奖的一等奖获奖项目。大投行业务平台底稿管理系统则是投行质量管理的核心系统，在同业评比中系统能力排名靠前获得了监管加分。

Q：恭喜贵公司项目通过了 DevOps 持续交付 3 级标准评估，表明达到了国内领先水平，请说一下您此时的感受。

胡滔：很高兴能够通过 DevOps 持续交付能力成熟度 3 级评估，表明了团队和平台已具备研发全流程自动化交付的能力。部分能力项还达到了4 级水平，包括体系化的制品管理策略、持续集成问题的反馈和解决可在几小时内完成、代码质量检查完全自动化等方面。取得这样的成果，是对两个项目团队技术工程能力的认可，也是对我们 DevOps 研发数字化体系建设成果的肯定。这是招商证券首次参加并通过 DevOps 持续交付评估，极大地鼓舞了公司 DevOps 能力建设工作，肯定了目前我们研发能力水平，对我公司推进研发数字化转型具有里程碑意义。

Q：贵公司是如何决定加入 DevOps 标准评估工作中的？

胡滔：金融科技中心自身的数字化是公司业务数字化的基础，金融科技中心的使命是打造一个更“聪明”的组织，DevOps 研发数字化体系建设就是要让金融科技中心更“聪明”，从而支持并带动整个组织变“聪明”。通过 DevOps 研发数字化体系建设，金融科技中心能够打造“敏捷集团军”的能力、建成“透明型”组织、形成闭环工作思维。DevOps 研发数字化体系从全流程、全体系出发进行建设，将业务、需求、研发、运维作为一个整体来考虑，做到业务需求全覆盖，打造一体化的研发运营体系。DevOps 标准评估作为体系建设的一部分，一是通过对标行业标准，找到差距并自我改进；二是通过以评促建，增强研发过程规范，提升研发交付质量，三是沉淀招证成熟度模型，通过模型推动“敏捷集团军”的能力建设。

Q：通过 DevOps 标准评估对您的企业带来了什么帮助？对贵团队有哪些影响？

胡滔：DevOps 持续交付标准评估对金融科技中心 DevOps 研发数字化体系具有重要的指导意义。一是通过两个参评项目，为研发数字化及 DevOps 全面推广树立了标杆，后续我们希望以点带面，以面带体，推广至更多的项目，全面提升金科数字化能力建设；二是系统性、体系化地打造了研发质量管理体系，完善了组织级 DevOps 持续交付流水线平台工具，形成了组织级持续交付实践规范，建立了研发全流程质量控制体系；三是强化了专业化人才能力建设，孵化了一批专业的 DevOps 工程教练，营造了“价值导向、思辨创新、追求卓越、担当自省”的文化氛围，进而打造开放、探索、分享的学习型文化组织。

两个参评团队也深有感悟，他们表示，DevOps 标准评估不仅要求团队掌握工具，本质上要求项目团队建立起一个实践-反馈-实践的协作闭环，让 DevOps 理念不断深入到团队的每一位成员，使其跳出具体开发环节，看到研发的全貌，感受到个人对团队效率的影响，意识到测试的重要性，追求以自动化的方式提升效率，关注度量数据促进团队改进，共同打造主动分享的学习型团队。


招商证券股份有限公司

金融科技中心总经理 邓曙光


Q：邓总您好，可否详细的介绍一下，通过本次评估有哪些数据指标可以直观的体现项目改进成果？

邓曙光：通过本次持续交付三级标准评估，团队在交付质量、交付效率、研发产能等方面均有了显著的提升，主要效果展现在以下几个方面：需求交付周期从30天缩短至单周，构建时长从30分钟缩短至分钟级，构建修复时长从几小时缩短至30分钟内，投产频率从 1次/月 提升至4次/月，日均提交代码从17次提升至25次，建立了单元、接口、UI自动化的全面测试体系，接口测试覆盖率达到100%。

新一代场外衍生品管理系统

大投行业务平台底稿管理系统

Q：对于此次参评的项目，其IT系统有哪些特色，当时是怎么规划和设计的？

邓曙光：本次参评的两个项目有着不同的业务特点和技术架构，我们希望通过这两个互有差异的项目，来提炼研发规范和标准。新一代场外衍生品管理系统打破了证券公司长期以来核心技术系统依赖于外购的局面，通过运用云原生的微服务技术，创新性地将业务开展的各个环节独立成十几个不同的子系统，并通过接口对接，实现了业务开展的全流程电子化。应中国证监会对投行工作底稿电子化存管要求，我司自主设计、自主研发的大投行业务平台底稿管理系统，采用底稿与项目相结合的产品方案，将底稿管理贯穿于投行项目承做、发行、后续等多个环节，同时系统集成了OCR、智能审稿、文档对比、错别字检测、银行流水核查等智能工具，大大提升了底稿制作、审核效率。

Q：此次通过评估的过程顺利吗？遇到什么困难？如何解决的？

邓曙光：本次的评估有很大的挑战，在建设过程中遇到的主要困难如下：

一是需要兼顾大量紧急的业务需求和参评改造任务，人力资源异常紧缺。我们要在一个后端15万行、前端9万行代码体量的系统中落地 DevOps 标准，尤其是在项目进度高度紧张的时候，这是一个非常有挑战的事情。为了打赢这场攻坚战，在组织层面，集中力量针对评估项优化平台与工具，提供组织级规范和标准；在团队层面，不仅在日常中不断宣导和对齐 DevOps 认识，还注重让事实说话，尽快地构建出自动化的闭环研发流程，让真实的效果引导团队，逐渐让团队转换观念，认识到 DevOps 是提升研发效率的方法和工具。

二是在自动化测试方面，搭建分层自动化测试体系工作量大。过级系统代码体量大，团队首次探索前端单元测试，要做到单测覆盖率全量代码覆盖50%以上，自动化接口测试全量代码覆盖100%，挑战性大，突破点多。面对挑战，团队成员主动担责，积极参与改进，同时联合组织级团队开展自动化测试专项突破工作。

三是外包人员占项目团队人数半数以上，能力参差不齐且频繁更替。通过评估，帮助项目团队解决了因大规模借助外部开发资源，带来的人员、效率、交付管理的问题。我们在建立自动化研发流程中，认真落实评估标准对研发流程的每一项要求，不忽视每一个“可有可无”的细节、不放过每一个“举手之劳”的手动操作，真正让 DevOps 理念内化于所建立的研发流程，让流程指导、约束、发挥外包人员的生产力，让团队具备杆杠借力的能力。

Q：对于 DevOps 今年的实施，您觉得最大的收获是什么？您的下一步计划是？

邓曙光：最大的收获是两个参评的项目通过了 DevOps 持续交付三级标准评估，我们充分学习了业界先进的经验，不仅提升了两个项目团队的工程技术能力，完善了组织级平台和规范，更是为我司树立了标杆，明确了改进方向，是推动研发数字化转型的关键里程碑。

下一步我们将结合信通院 DevOps 标准和两个项目团队过级经验，进行本土化改造，建立招商证券内部 DevOps 能力成熟度模型，引导团队向更好的技术管理持续改进；同时，进一步落实研发数字化和 DevOps 全面推广工作，将本次取得的项目成果作为最佳实践进行推广，以全面提升各研发团队在持续交付工程实践领域的能力。

Q：对于 DevOps 的发展前景，您怎么看？

邓曙光：在业务需求敏捷化的背景下，需要研发团队快速响应业务需求，DevOps 正是通过工具及自动化的流程，使得发布能够更加的频繁可靠，DevOps 能够很好的赋能研发数字化转型，为业务更快响应市场变化提供能力支撑。从精益思维出发，我们可以看到 DevOps 的必然发展方向，会延伸到业务端，业务是产品开发和运维的源头，一个完整的价值流必须从源头开始。在中国人民银行印发《金融科技发展规划（2022-2025年）》中也提出“重塑智能高效服务流程，以产品敏捷交付为主线制定清晰研发工作规程，借助业务开发运维一体化(BizDevOps)搭建快速迭代的交付模式”。未来我们也会持续关注DevOps的前沿发展并保持探索和实践，持续推进招商证券研发数字化转型，打通组织中的各个职能环节，实现业务、开发和运维的一体化运行，形成高效和精准的业务交付、业务反馈和业务调整闭环，赋能数字业务的发展和激发数字业务的创新。

研发运营一体化（DevOps）能力成熟度模型介绍：
《研发运营一体化（DevOps）能力成熟度模型》系列标准是由中国信息通信研究院牵头，云计算开源产业联盟、高效运维社区、BATJ等顶级互联网公司以及各大金融、通信企业共同制定的国内外首个 DevOps 系列标准，是最完整、最权威、最具行业指导性的研发运营一体化（DevOps）能力标准之一。由中国信息通信研究院主导的 DevOps 标准已由工信部发布并被众多金融、通信和互联网等行业名企纷纷采用并通过评估。

与此同时，DevOps 标准已于2020年7月在联合国直属标准化组织 ITU-T 正式结项，成为全球首个 DevOps 国际标准。DevOps 标准评估体系主要包括敏捷开发管理、持续交付、技术运营、应用设计、安全及风险管理、系统和工具等部分。
