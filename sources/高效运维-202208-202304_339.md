国内外大型企业实践表明，标准化和工具赋能是企业成功的关键所在。DevOps 标准及基于标准的 DevOps 持续交付流水线平台和项目实践，可以较大幅度地提质增效，更加安全敏捷地提高企业市场竞争力！“以评促建，以评促改”，以评估为抓手，让 DevOps 标准更快更好落地，助力企业数字化转型。2022年10月28日，**中国信息通信研究院隆重公布了 DevOps 系列标准及 AIOps 系列标准最新批次评估结果。**中国移动通信集团辽宁有限公司（以下简称“辽宁移动”）本次参评的项目为**辽宁移动渠道管理系统项目**，该项目顺利通过由中国信息通信研究院开展的《研发运营一体化（ DevOps ）能力成熟度模型》持续交付 3 级评估，代表辽宁移动的 DevOps 能力达到国内领先水平。

**评估单位：中国信息通信研究院**

此次，我们采访了辽宁移动信息技术中心总经理王欣先生和辽宁移动 DevOps 项目负责人高旭阳先生，一同深聊团队在项目参与评估时的细节和故事，分享辽宁移动 DevOps 实践的经验。**\- Q&A -**

辽宁移动

信息技术中心总经理 王欣

  

**Q：您好，请介绍一下您和您的企业，以及此次参与评估的项目。****王欣：**辽宁移动隶属于中国移动通信集团，负责中国移动在辽宁的网络建设和业务经营，为地方社会提供全方位的数字化服务。在省委省政府和集团公司的战略指导下，经过辽宁移动人数十载的不懈努力，移动客户规模突破3000万，家庭客户达到600万户，服务企事业单位40万家，累计纳税350亿元，是辽宁地区网络规模最大、客户数量最多的数字化服务商。本次参与评估的项目是渠道管理系统（CMOP）项目，该项目是面向全省渠道线条的人员使用的统一门户。该系统主要目标是建设互联网化的“一站式”办公管理平台，支持渠道基础信息、日常工作、考核管理等能力，是辽宁网格集中化运营的重要载体。**Q：恭喜您通过 DevOps 标准评估，此次贵公司项目通过的是持续交付3级，表明达到了国内领先水平，请说一下您此时的感受。****王欣：**本次能够通过 DevOps 持续交付标准3级评估实属不易，首先要感谢信通院对我们的指导和帮助，也感谢集团公司、省公司领导对 DevOps 转型给予的肯定和帮助。此次通过 DevOps 标准评估是辽宁移动IT实施敏捷、精益转型的里程碑，感谢辽宁公司信息技术中心同事为研发运营一体化（DevOps）建设工作付出的辛勤劳动，同时也感谢相关单位及合作伙伴的大力支持。**Q：贵公司是如何决定加入 DevOps 标准评估工作中的？****王欣：**辽宁移动信息技术中心 DevOps 转型工作始于2018年11月。由于快速增长的业务需求与有限研发资源之间一直存在矛盾，如何提高研发效能、快速上线业务需求、支撑市场发展以及助力组织数智化转型，是IT支撑系统始终面临的挑战。因此，辽宁移动以渠道集中化平台为试点，通过引入敏捷方法论，探索基于Scrum方法的敏捷开发组织和流程体系，建设 DevOps 工具链，进行持续集成和持续部署，实现业务系统的快速迭代。同时我们也看到了与业界先进水平的差距，研发运营一体化（DevOps）能力成熟度模型为软件工程能力全面对标提供了指引和参考，所以我们决定以CMOP项目作为参评项目，通过新建完整的 DevOps 工具链，完成 DevOps 体系和文化建设，完成在此项目中的工程实践，并将此工程实践在组织级进行推广。**Q：通过 DevOps 标准评估对您企业带来了什么帮助？对贵团队有哪些影响？****王欣：**此次通过 DevOps 持续交付标准3级评估对于辽宁移动意义重大，包括以下几个方面：  

*   **IT转型方面：**通过此次标准评估，重构了IT生产关系，实现了从业务到开发再到运维的流程贯通，实现了高效的业务交付、开发运行和反馈闭环，推动了传统研发模式向双模研发模式的转变，促进了供给侧结构性改革，让IT交付节奏跟上业务发展的需要，整体交付效率相较此前提升了30%。
*   **团队建设方面：**通过此次标准评估，在实践中提升团队人员能力水平，打破传统开发、测试、运维团队独立模式，成功打造一支能够应对市场和技术环境快速变化的跨职能和自组织团队。团队成员由原来的专业化分工向全栈工程师转型。目前全栈工程师数量达到80%，充分实现了组织内人员复用。
*   **管理实践方面：**DevOps 标准评估助力辽宁移动 DevOps 研发运营一体化体系的优化。辽宁移动自2018年开始，结合运营商研发运维现状，逐步建立了自身特色的 DevOps 体系，但是并不完整和健全。DevOps 标准评估实现了软件交付生命周期的全覆盖，在深度和广度上具有参考和指导意义，可以帮助我们了解 DevOps 能力现状，并推进 DevOps 转型在企业的落地。
*   **工程实践方面：**DevOps 标准评估助力辽宁移动 DevOps 工具平台演进。辽宁移动通过引入自动化测试、持续集成/持续部署工具，实现系统版本发布和上线部署的统一管控，打造了贯穿需求全生命周期的 DevOps 平台，通过流程引擎将需求开发、质量保证、投产部署的价值交付链串接起来。为项目管理人员、开发人员和测试人员提供统一的自助服务。此次参与 DevOps 持续交付标准评估，与行业先进案例对标，完善了敏捷开发流程，拓展了研发运营一体化平台，建立敏捷人才培养机制，实现组织的敏捷转型，帮助组织响应数智化变革的要求。
    

**Q：对于 DevOps 的发展前景，您怎么看？****王欣：**DevOps 打破IT开发部门和IT运维部门之间的隔阂，包括技术、流程和组织上的隔阂。一体化是手段，最终的成果必须体现为顺畅的业务交付和连续稳定的系统运行。而这一切都必须以业务为源头，打通从业务到开发再到运维的整个流程，实现业务、产品和运维的有机融合，形成高效的业务交付、运行和反馈闭环。在数智化转型的大趋势下，运营商始终将提供卓越的信息化服务、满足人民美好生活需要作为奋斗目标，紧紧抓住“人心红利”，通过供给侧结构性改革，不断丰富产品权益，提高服务质量，赢得客户信赖，提高客户的满意度和获得感。供给侧结构性改革需要具备越来越快的IT交付能力和稳定高效的IT服务支撑能力，未来仍需要通过深化 DevOps 实践，进一步修炼内功，获得技术革新和组织效能的提升，从而赋能创新。另一方面，在持续交付的同时还需要考虑将业务侧融入到 DevOps 体系中，因此 BizDevOps 也必将成为 DevOps 演进的未来趋势。

**Q：您可否详细的介绍一下，通过本次评估有哪些数据指标可以直观的体现项目改进成果？****高旭阳：**通过此次 DevOps 持续交付标准3级评估，团队在持续交付七个能力子域均获得了显著提升，业务上线周期缩短，能够更快的、高质量的响应业务的变化和需求。如下图所示，可以详细看到参与评估带来的改进：![](../Images/2521b59ed042fdd195fe7ccf4c4dac63.png)**Q：对于此次参评的项目，其IT系统有哪些特色，当时是怎么规划和设计的？****高旭阳：**此次参评的项目是“渠道管理系统项目”，是互联网化的“一站式”办公管理平台。系统采用容器部署方式，依托容器云平台提供的统一云原生技术底座，通过弹性计算实现资源弹性调度。由于项目的主要用户为辽宁移动渠道和网格人员一线营人员，业务需求非常活跃，对响应及时度要求非常高，每月需求交付量35-40个，因此采用敏捷开发模式，支撑需求的快速迭代和发布能力。**Q：此次通过评估的过程顺利吗？遇到什么困难？如何解决的？****高旭阳：**总体而言，在此次参与持续交付标准评估的过程中遇到了一些问题和挑战，我们结合专家建议和自身实践，克服了困难，顺利的完成了评估，可以总结为以下几点：**一是在开展 DevOps  转型实践的过程中，并未形成可复制的系统方法论，尤其是缺乏相关领域的人才**。为此，我们加入了由中国信息通信研究院指导，云计算开源产业联盟、开放运维联盟联合发起的“企业级 DevOps 赋能（共促）计划”，和更多优秀企业交流学习，了解行业最佳实践；另外我们派遣骨干人员参加外部学习，先后16人次通过相关培训认证，为后续推广 DevOps 储备了充足的人才。**二是面对全新开发模式与系统工具，付出了一定的学习成本。**如编译方式由ANT转为Maven；版本控制工具由SVN切换为Git并且引入制品库Nexus，开发人员需要自行写编写单元测试等。通过对开发、测试和运维人员进行培训和选取试点团队进行转型两方面举措，逐步推广全新的开发模式及系统工具，减少模式和工具更换对整个团队的影响。**三是 DevOps 理念与公司现行的IT管理要求相冲突。**如 DevOps 强调单一可信数据源，代码要求一次编译，在不同环境进行部署。而传统情况下，出于安全性的考虑，测试环境与生产环境是隔离的，需要将测试环境验证过的代码在生产环境重新编译打包。

针对与公司现行IT管理要求的冲突，我们经过咨询行业专家，结合本地开发实际的特点，采用其它替代方式来满足 DevOps 的要求。如测试环境和生产环境隔离的问题，我们将部署环境由虚拟机切换为容器，将代码与环境分别打包，生成为一个镜像，通过制品晋级由测试制品库晋级到生产制品库，生产环境拉取生产制品镜像并进行部署，来解决该问题。

**Q：对于 DevOps 今年的实施，您觉得最大的收获是什么？您的下一步计划是？****高旭阳：**最大的收获是实现了渠道管理系统项目从业务到开发再到运维的流程贯通，实现了高效的业务交付、开发运行和反馈闭环，推动了传统研发模式向敏捷研发模式的转变，促进了供给侧改革，有效提升内外部客户满意度。项目构建了以交付高质量、高价值需求为导向的研发模式，实现了业务敏捷开发和持续交付能力的跨越式增强，有效响应客户需求。下一步计划将成功经验复制推广到CRM全域，在推广的同时保持对各个项目差异化的实践和创新，需进一步打通信息屏障，为更多的产品赋能；同时，进一步提升 DevOps 平台的通用性和扩展性，探索跨团队的规模化敏捷协同及持续集成，进行基础设施即代码等实践，对团队也是新的机遇和挑战。**辽宁移动渠道管理系统项目****团队评估现场：**

**研发运营一体化（DevOps）能力成熟度模型介绍：**《研发运营一体化（DevOps）能力成熟度模型》系列标准是由中国信息通信研究院牵头，云计算开源产业联盟、高效运维社区、BATJ等顶级互联网公司以及各大金融、通信企业共同制定的国内外首个 DevOps 系列标准，是最完整、最权威、最具行业指导性的研发运营一体化（DevOps）能力标准之一。由中国信息通信研究院主导的 DevOps 标准已由工信部发布并被众多金融、通信和互联网等行业名企纷纷采用并通过评估。

与此同时，DevOps 标准已于2020年7月在联合国直属标准化组织 ITU-T 正式结项，成为全球首个 DevOps 国际标准。DevOps 标准评估体系主要包括敏捷开发管理、持续交付、技术运营、应用设计、安全及风险管理、系统和工具等部分。
