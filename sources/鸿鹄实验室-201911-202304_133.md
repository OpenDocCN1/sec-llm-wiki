# Controller 任务发布流程分析

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzU0MjUxNjgyOQ==&mid=2247489568&idx=1&sn=f3c891b1c162043b1d270024fc143281&chksm=fb182b12cc6fa20464ab283f284de4a9bddc00bc7c4baf273e24d5672048dc874cd6065524b7&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzU0MjUxNjgyOQ==&mid=2247489568&idx=1&sn=f3c891b1c162043b1d270024fc143281&chksm=fb182b12cc6fa20464ab283f284de4a9bddc00bc7c4baf273e24d5672048dc874cd6065524b7&scene=27#wechat_redirect)

这是\[**信安成长计划**\]的第 7 篇文章

  

0x00 目录  

0x01 Controller->TeamServer

0x02 TeamServer->Beacon

0x03 流程图

  

所有的任务在 Controller 处理以后，都会直接发送到 TeamServer，接着等待 Beacon 回连的时候将任务取走，文章以 shell whoami 为例

  

0x01 Controller->TeamServer

当在 Console 中输入命令回车后，会进入 BeaconConsole 进行处理

  

![](../Images/bf9375f8ec1423f68e19b88d9196c523.png)

  

专门来处理 shell 命令，命令解析 popString 所返回的就是要执行的命令 whoami

  

![](../Images/c0c6045d65ce4b364cc104b0dced180c.png)

  

接着会在 TaskBeacon 中处理执行逻辑，因为只有一个 Beacon 就直接跟入了

  

![](../Images/8810cbef617492368e38ece378a26fad.png)

  

然后就是构造任务了，将信息处理后用于 Beacon 去解析执行

  

![](../Images/2e434748c1a5d55b7d19a800234153be.png)

  

之后会先打印执行日志，然后才是真正的传递了

  

![](../Images/777589d6f888ddb6b06296003da8f33c.png)

  

日志记录也是一样通过 TeamQueue 传给 TeamServer

  

![](../Images/a2f75788398db03c01ad9815562e0d45.png)

  

TeamServer 在 ManageUser 中接到日志

  

![](../Images/9215195aa15c11637137156194fe40a9.png)

  

在处理以后直接添加广播将信息发送出去

  

![](../Images/84b1bbace6af53c8ad4ba23f784ef54b.png)

  

然后通过 BroadcastWriter 写回给 Controller

  

![](../Images/c6ff11b34a38a9d47152781d9095a506.png)

  

接着 Controller 将任务发送给 TeamServer

  

![](../Images/4a49f90e636148ce2019f142beb9d103.png)

  

TeamServer 在接到以后同样走对应的处理逻辑

  

![](../Images/0197e89a4679b5e9dd4ba70ff56e4f48.png)

  

从两个参数中取出 BeaconId 和任务，然后进入 BeaconData 处理逻辑

  

![](../Images/1c6b00b3e51034fe716de1a96ebf8642.png)

  

这里的有用代码也就是 else 中的 add 了，上面的判断是 CS 的一个暗桩，运行三十分钟后再执行命令就会直接发布退出任务

  

![](../Images/30b8db0ab53d94a8b5f8935f0ce45013.png)

  

在将任务添加到 List 以后，也会将 BeaconId 记录下来

  

![](../Images/fc0b37f09133554e7e970beb4474826a.png)

  

到这里任务的发布就完成了

  

  

0x02 TeamServer->Beacon

在 Beacon 回心跳包的时候，会来请求任务

  

![](../Images/4a191520601405a3916fd00d48b14053.png)

  

直接从任务队列中取出数据

  

![](../Images/2b5c1790abd2abd4513e3f084eb401f3.png)

  

然后循环添加，并将添加过的移除，如果任务大于指定大小的话就会跳出循环

  

![](../Images/b45b726ba47562b0aa440a04aac59317.png)

  

最后将任务队列返回

  

![](../Images/41260e8eeed4ab3fcdf4958ae9821d9d.png)

  

之后再相应的将其他的内容取出

  

![](../Images/1732717d33332eb7356676a9f9df462e.png)

  

最后构造并返回，这里会进行打印日志的操作，输出发送了的命令的长度

  

![](../Images/dda9f4e5e326404ea2127c1fd66e7724.png)

  

在返回之后会对数据进行加密

  

![](../Images/8fbd2e5bd3ca6d28c14001c984b2ac7f.png)

  

首先会根据 BeaconId 取出对应的 AESKey 和 HmacSHA256Key

  

![](../Images/2f92e182df80e766d282cd0673092a06.png)

  

之后写入系统时间/1000，任务长度，任务数据，并对其进行补齐，添加 A，补够 16 的整数倍

  

![](../Images/f3e4117be402431f627b5d1534ca7194.png)

  

然后进行 AES 加密

  

![](../Images/f766d612cc5b8682e2355ed440b08aa7.png)

  

接着对数据进行 Hmac

  

![](../Images/e4ae8b3ee7aa8c3790f8e7b446a1dafb.png)

  

之后将 AES 加密后的任务写入，并将 Hmac 的前 16 位拼接到后面

  

![](../Images/73a5d101e5f57c817fc46f26996c84c1.png)

  

之后便返回给 Beacon 了

  

![](../Images/2a999d4dc957a6ab3a7810b753c28157.png)
