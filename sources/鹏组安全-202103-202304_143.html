 代码审计


  


        使用源代码审计工具进行排查（误报率很高）


        可以看到在ad_js.php中可能存在sql注入，我们通过phpsotorm来调试

查看sd_js.php ，可能注入的语句

$ad = $db->getone("SELECT * FROM ".table('ad')." WHERE ad_id =".$ad_id);

        getone()是自定义的函数，用来查询数据库，代码如下：（可双击选中该函数，然后右键单击定位函数，发现在：/uploads/include/mysql.class.php文件中，双击直接可定位到在文件中的位置）

主要是插入到数据库查询语句中的$ad_id没有经过任何的过滤，因而导致了SQL注入。

        在$ad_id这里下个断点，传入ad_id=1, 1传入了$as_id

        再 $ad 打个断点，跳转到了自定义table函数 ，table函数功能是：进行对数据表加blue前缀，返回blue_ad

        下一步，跳到了mysql.class.php文件里，又有个自定义函数，getone方法没有对传入的参数做过滤，直接执行sql语句

function getone($sql, $type=MYSQL_ASSOC){      $query = $this->query($sql,$this->linkid);      $row = mysql_fetch_array($query, $type);      return $row;    }

        下一步，返回一个关联数组,mysql_fetch_array函数从结果集中取得一行作为关联数组。

        $ad['time_set']==0进行判断，由于表中没有id=1的内容，所以$ad为flase。

        将查询到的结果返回到web界面的源代码中

        虽然有过滤，但是过滤的是string类型的注入，而执行的sql语句不需要闭合。这里的过滤基本上没用。就造成了int型注入。
