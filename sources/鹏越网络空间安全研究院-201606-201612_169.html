【摘要】 在工业互联网应用中，Web实时通信是影响其发展的主要因素。文章分析了传统模式存在的不足，提出了 Web Socket 与消息队列机制实现 Web 应用的方案，服务端接收 Web Socket 客户端的订阅请求，设备状态信息以发布模式推送到客户端，从而解决了传统 Web 实时通信中的问题。


【关键词】实时通信; Web Socket; 消息机制; Ｒedis

 

1传统模式的问题


当前，越来越多的工业控制应用需要以 Web 方式运行，在浏览器或手机上能够实时显示设备数据，动态构画曲线，对设备进行实时控制。Web 应用的信息交互采用了请求 / 响应模式，客户端通过 HTTP 协议向服务器端口发送请求，服务器对请求进行响应，向客户端发送信息，最后客户端负责信息的呈现。这种无状态的通信模式，双方只在请求/响应时产生连接，有效地提高了服务器的吞吐能力。但由于服务器不能主动与客户端通信，对于设备监控实时性高的应用来说，信息的同步尤为重要，是迫切需要解决的问题。现在 的 实 时 应 用 大 多 采 用 了 AJAX (AsynchronousJavascript And XML) 轮询或 Applet 和 Flash通讯。

(1) AJAX 轮询，主要是通过 Java Script 按指定的频率请求服务器信息来动态修改网页内容，无论服务器有没有信息，轮询始终进行且频繁发生。

(2) Applet 和 Flash，通过 Socket 编程以达到与服务器的长连接的全双工通信，但由于使用插件和缺少一致的安全协议等原因，不能适用移动互联网环境。

 

2实时通信的设计


Web Socket 设计的目的就是为了解决 Web 的实时通信，通过在HTTP 协议中加入 Connection: Up-grade 和 Upgrade: websocket 等协议头向服务器发出请求，服务器响应返回一组特定的协议头，创建 TCP连接，双方就可以进行通信。客户端是通过 JavaScript 访问指定的 UＲL 来获取连接的，Web Socket 相比以往的实现方案有着更好的性能。Web Scocket 解决了服务器与客户端之间的实时通信问题，但服务器还不知道什么时间有数据要传递给客户端，为避免使用轮询方式，可以采用消息机制的订阅/发布模式。设备发布数据，服务器根据当前订阅者分别进行消息传递，最终能够实现服务器向客户端的实时信息推送。Ｒedis 是一种基于键/值类型的实时数据库，支持服务器集群，可以用作应用的缓存，有着很高的并发性能，它支持多种键/值类型，同时还支持对消息队列的订阅 /发布模式。根据 Web Socket 的特点，我们在服务端使用Ｒe-dis 进行改进，使用消息机制来解决实时通信的问题，让订阅/发布模式取代轮询，让不同的浏览器向服务器订阅设备消息，整体逻辑如图 1 所示。

运行的基本流程: 

(1) 客户端根据 url 发送 Websocket 连接请求，与服务器握手创建连接。

(2) 服务器端接收请求后创建服务对象，并自动调用 on Open方法实现初始化 redis 客户端连接。客户端在连接创建后也调用 on Open 方法，并向服务端发起初始请求，一般包括了请求设备的 ID 信息。

(3) 服务端收到客户端发出的连接请求后也会调用自己的 on-Open 方法初始化 redis 客户端的创建。

(4) 客户端通过 on Open 事件的处理方法向服务器发送消息，服务端将在 on Message 方法接收到客户端提交的消息。

(5) 服务端根据客户端提交的设备号创建对Ｒedis 消息队列的监听器，完成消息订阅，从而将Ｒedis 消息队列的消息不间断地转发至客户端，达到实时通信的目的。客户端关闭连接或退出会导致服务端的 on Close 方法被调用，完成资源的释放。

4小结
