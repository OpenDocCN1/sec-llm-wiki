# 【鹏越·工控安全】专题系列（142）——基于编程数据的工控终端设备漏洞挖掘方法(上)

本章首先分析了工控终端设备漏洞被利用的可能，之后分析了系统对于工控终端设备漏洞挖掘的适用性，提出来一种新的工控设备漏洞挖掘技术。改进了数据样本的来源，使用编程数据作为数据样本。在变异函数方面，引进了遗传算法改进了原有的简单变异。最后，改进了模糊器，使用编程软件设计模糊器以适应工控设备的漏洞挖掘。

  

** 一、面向工控终端设备漏洞挖掘方法分析**

**1.1工控终端设备漏洞挖掘可行性分析**

**（1****）工控终端设备**

工控系统通常包含以下系统组件：安全边界与企业或其他非关键网络中隔离、远程访问第三方进入或网络、网络架构交换机、路由器、防火墙、访问控制、网络设计、网络流量分析什么是在网络中运行、主机操作系统加强、应用程序它们如何与其他应用程序和终端设备通信、终端设备、、控制器、智能传送器。

其中，控制程序状态的终端设备或者嵌入式系统是工业控制系统的核心。这些设备预先配置好定制的指令集，用以控制工厂或设施在控制过程中的变化。这些设备都被连接工厂固定设备上、监测温度、压力、水位、或流量的改变，然后发信号给其他工厂设备像录、阀门、发电机等控制其打开或关闭，或者维持系统在恒定的状态。

**（2）工控终端设备漏洞挖掘的可行性**

工控终端设备，它曾经通过串行电缆和专有协议连接到计算机网络，现在则通过以太网电缆和标准化的通信协议连接到计算机网络。供应商提供许多这样的设备，拥有嵌入服务器、开放的服务，有些设备能够通过不安全的之类的协议连接到他们。某款工控终端设备的开放端口图如下所示。

![](../Images/f5d606193c9f292877ff9ef7cd32ace6.png)  

  

这些开放端口工控终端设备漏洞被利用形成了可能，给工控系统造成了巨大的隐患。

 

**（3****）工控终端设备漏洞挖掘困难性**

由第二章工控漏洞的分析可知，工控终端设备的漏洞数目不多，但是危害极大，一般是高危漏洞。由于这些终端设备下直接连接现场设备，直接控制生产等实际流程，一旦受到攻击，其后果是造成非常直接的损失，如爆炸、停机甚至人员伤亡。

对工控设备的这些网络攻击测试不可以运行在实际的系统中，因为这些攻击是设计用来测试设备最大的极限性能，所以这些攻击测试都应该运行在模拟平台或者正在开发、测试的网络中。

由于工控终端设备往往不公开其内部结构，目前对于其内部结构相关研究也比较少，况且工控终端设备品牌众多，体系也各不相同，这是目前并没有直接针对工控终端设备的漏洞挖掘方法的重要原因，这也直接导致工控终端设备漏洞数量不多。

根据第二章工控漏洞的统计分析，工控的漏洞挖掘总数己经开始下降，工控软件的漏洞挖掘己到瓶颈，为了挖掘出新的漏洞，本文把研究目标定位在工控终端设备。

  

**1.2．IT系统漏洞挖掘方法适用性分析**

IT系统的漏洞挖掘方法按照对目标的了解程度主要分为白盒、黑盒和灰盒方法。白盒方法是指有源代码的、对目标完全了解的情况下进行漏洞挖掘，主要方式有源代码审计等；灰盒是指对于目标设备有部分了解的情况下进行的漏洞挖掘的方法，包括二进制插桩、动态污点分析等；黑盒是指对目标完全不了解的情况下进行的漏洞挖掘，典型的代表是模糊测试（Fuzzing）。这些技术对于工控终端设备的适用性如表所示：

![](../Images/1f376d5ee29e1029cb924cc210afb2ea.png)

现阶段，对于工控终端设备的内部结构并不了解，逆向工控终端设备的发展处于起步阶段，因此无法采用其它的漏洞挖掘手段，本项目采用测试这些工控系统中终端设备的漏洞。

  

**二、改进的工控设备漏洞挖掘方法**

**2.1网络协议模糊测试的缺陷**

根据研宄现状的分析，现在针对工控设备的漏洞挖掘方法主要是通过网络协议的模糊测试，且大部分都是基于生成的网络协议模糊测试。这些模糊测试存在以下的缺陷：

**（1****）工控协议解析困难**

现在模糊测试的一个非常严峻的问题就是测试用例命中率过低，尤其是对工控设备。由于对工控协议不了解，导致工控设备拒绝很多模糊器发送的测试用例甚至中断连接。对于一些公开的协议，可以查询协议的公开文档，但是工业控制系统的协议很多都是私有协议。对于私有协议的解析，则相当困难，需要大量的技术。况且工控协议数量众多，逐个去解析无疑是一个很难完成的任务。

**（2****）针对性不强**

目前大部分的模糊测试测试用例生成都是基于工控协议的，而工控设备怎么样去处理这些测试用例就没有认真考虑，从而导致测试用例的盲目性，并不能对工控设备的某一个处理流程。为了提出一种新的方法解决上述的问题，本文提出了基于编程数据的测试用例生成和基于遗传算法的变异函数设计以及改进的内存模糊器的一种模糊测试的方法。

  

**2.2****漏洞挖掘方法总体思路**

为了解决现有模糊测试方法的工控协议解析困难以及针对性不强的问题，本文设计了一种基于编程数据的模糊测试方法。具体架构如图所示：

![](../Images/a37c4dd3b365d0c4f879e2dc33181b18.png)

  

图示中我们选取软件与硬件编程数据为输入，经过模糊测试后，对工控设备进行漏洞挖掘。其中模糊测试包含以下四个模块：

**（1****）测试用例生成模块**。模糊测试首先都要解决测试用例的来源的问题。本文分析了工业控制系统中的数据中的网络数据，把工控数据分为三类：软件与硬件编程数据、软件与硬件监控数据、软件与信息管理系统的数据。其中工控软件通过编程控制硬件的核心逻辑，编程数据能够触及工控硬件的操作系统，更能有效挖掘出漏洞，本文选取该数据作为模糊测试测试用例来源。

**（2****）基于遗传算法的数据变异模块。**数据变异是模糊测试的核心，其功能就是生成大量非预期的数据，这些非预期的数据才有可能触发安全漏洞。本文根据工控软硬件编程数据的特点，采用了遗传算法进行数据变异方法的设计。

**（3****）内存模糊器模块。**该模块是用来执行测试用例的。在前两个模块处理完后，得到非预期的数据，这些数据通过内存模糊器模块发送到目标设备上。为避免盲目发包造，大量的资源浪费，提高效率，需要分析目标系统，针对目标系统做出调整，建测试流程提高模糊测试的有效性。本文采用了对编程软件进行逆向工程的方法设计了一种改进的使用内存数据模糊测试方法执行测试用例。

**（4****）异常监控模块**。这是每一个模糊测试的关键部分，漏洞触发的一个重要表现就是出现异常，异常监控就是用来捕获异常，进而分析是不是安全漏洞。针对工控硬件设备的特点，本文采用心跳包的异常检测方法。

  

 **3****改进的工控漏洞挖掘方法关键技术**

在上一小节中，我们提出了如图所描述的工控设备漏洞挖掘框架，在这个框架中，我们在测试用例生成、变异函数和内存模糊器这三个关键环节进行了重点设计，并将在本小节中进行详细描述。

**3.1基于编程数据的测试用例生成方法设计**

工业控制系统网络数据流量分析。工业控制系统网络分为信息网络、监控网络、现场网络。这三层网络中’都有大量的数据，本文将这些数据主要可以分为三类：软件与硬件编程数据、软件与硬件监控数据、软件与信息管理网络的通信数据。如下图所示：  

![](../Images/20b2df58e5de646420082d51dbdb40dd.png)

**（1****）软件与硬件编程数据**

软件与硬件编程数据是指工程师在工程师站通过专业的编程软件对工控终端硬件设备编程时产生的数据。

**（I****）工控编程作用**

现阶段，工业控制系统终端硬件设备为了满足通用性强、使用方便、适应面广、可靠性高、抗干扰能力强等需求，都具有一定的编程能力。常见的工业控制系统终端硬件设备如、、控制卡等，提供编程能力支持，且具有编程方便，现场可修改程序等特点。

工控终端设备专为在工业环境应用而设计。它们通常釆用一类可编程的存储器，用于其内部存储程序，执行逻辑运算、顺序控制、定时、计数与算术操作等面向用户的指令，并通过数字或模拟输入、输出控制各种类型的机械或生产过程。

**（II****）工控编程工具**

工控终端设备的编程往往通过专用软件进行。比如西门子公司为其工控产品如SIMATIC S7、M7、C7和基于PC的WinAC提供了STEP7编程软件；施耐德系列的工控终端硬件设备拥有通用的一体化编程软件Unity Pro等。

工业控制系统的编程己有了国际标准：。该标准规定的编程语言包括图形化编程语言和文本化编程语言。图形化编程语言包括：梯形图、功能块图、顺序功能图、文本化编程语言包括：指令表和结构化文本的编程语言是工作组对世界范围的厂家的编程语言合理地吸收、借鉴的基础上形成的一套针对工业控制系统的国际编程语言标准，它不但适用于系统，而且还适用于更广泛的工业控制领域。

**（III）工控编程和计算机编程的区别**

工控编程不同于计算机编程，工程师在屏幕上设计过程控制流程图和电气原理系统图，然后由计算机工程师站自动生成执行程序这样就不要求控制工程师有很多计算机软件编程的知识和技巧，甚至可以说不需要以前的严格意义上的软件设计工作，就可以完成工控软件的开发。这不仅使工控软件开发的质量和效率大大提高，而且可以使控制工程师无需大量的精力和时间耗费在繁琐的编程工作中，而是把更多的注意力放在控制策略和工厂自动化的需求分析和研宄中。

**（IV****）工控编程数据的意义**

但是同时计算机自动生成执行程序需要通过网络如工业以太网或串口网络下载到工业控制系统终端硬件设备中，这样我们就可以通过抓取数据包等方式获取工业控制系统终端硬件编程数据，这些数据及工控终端硬件设备的执行逻辑，对于硬件终端的漏洞挖掘有着重要意义。
