【鹏越·工控安全】专题系列（98）——工业控制系统漏洞库设计与实现

摘要：该文通过研究国内外工业控制系统(ICS)漏洞库及建设现状，设计并实现了一个专注于工业控制系统漏洞发布、检索及管理的工业控制系统漏洞数据库。文中漏洞库的设计结合工业控制系统漏洞的特点及其与传统漏洞属性的差异，建立了工业控制系统漏洞库描述模型。同时，兼顾漏洞信息收集的覆盖率和漏洞信息发布的标准化，能够更好地支持工业控制系统漏洞信息的收集、跟踪及漏洞数据的分析、研究，为工业控制系统安全研究提供了丰富的.数据支撑。

0 引言

随着计算机和网络技术的发展，特别是信息化与工业化深度融合以及物联网的快速发展，越来越多的通用协议、硬件和软件在工业控制系统产品中采用，并以各种方式与互联网等公共网络连接。通用开发标准与互联网技术的广泛使用，成熟的 IT 及互联网技术不断地被引入到工业控制系统中，使得针对工业控制系统的攻击行为大幅度增长[1- 2]，同时，工业控制系统信息安全问题也日益突出。

近年来 ， 工业控制系统的漏洞不断被发掘出来 ，PLC、DCS、SCADA 乃至应用软件均被发现存在大量信息安全漏洞，如 ABB 施耐德电气(Schneider)、通用电气(GE)、研华科技(Advantech)及罗克韦尔(Rockwell)等工业
控制系统厂商产品的各种信息安全漏洞。由于工业控制系统开发时仅重视系统功能实现，缺乏相应的安全考虑，现有的工业控制系统中难免会存在可能危及系统安全的漏洞或系统配置问题，这些暴露在网络中的安全漏洞一旦遭到攻击，轻则干扰系统运行、泄露敏感信息，重则有可能造成严重的生产安全事件[3]。因此，我们需要采取有效的措施减少信息安全问题造成的损失和破坏，而
构建工业控制系统漏洞库是降低威胁非常有效的手段。一般来讲，工业控制系统和普通信息系统安全最显著的不同是工业控制系统更加关注高可用性，而普通信息系统对机密性的要求更高。所以，本文的工业控制系统漏洞库既要保留传统漏洞库的特点和部分属性描述，兼容国际漏洞标准，也要适应工业控制系统漏洞所带来的新要求新变化，为广大工业控制系统用户、厂商及研究者提供一个更有效、更准确、更完备的漏洞信息共享平台。

1工业控制系统

漏洞库概述

1.1 工业控制系统漏洞

绿盟科技的 2014 年度工业控制系统安全研究报告表明，截止到 2014 年各大漏洞共享平台公开的工业控制系统相关漏洞，仍然是以国际著名的工业控制系统生产厂商为主，如西门子、施耐德电气、通用电气、研华科技及罗克韦尔等的产品漏洞数占比明显领先于其他厂商。据统计，这些漏洞以 SCADA/HMI 系统相关的漏洞为主，其占比超过 40%，PLC 相关的漏洞接近 30%，DCS及 OPC 相关的漏洞各占将近 10%。这说明工业控制系统攻防双方都可能把主要精力放在了工业控制系统的控制设备或管理软件系统的安全性分析之上，当然，工业控制系统的网络设备及工业网络管理软件的脆弱性也受到了一定得关注，其相关的公开漏洞占比合计约 8%[4]。
美国 NSTB 对国家基础设施行业进行抽样评估后，将识别到的工业控制系统安全缺陷及漏洞情况归纳如表 1 所示[5]


目前专门对工业控制系统相关的漏洞进行分类收录的安全漏洞库较少，多数漏洞共享平台是将其与普通信息系统漏洞统一收录。工业控制系统漏洞的研究人员经过在各漏洞共享平台搜索、筛选，将相关漏洞信息收集、整理后，才能开展分析研究活动。本文设计的漏洞库系统解决了研究者前期搜集整理漏洞信息的工作繁琐问题，同时提供了界面友好操作方便的检索服务。

1.2 与传统漏洞库的区别

1)漏洞评级关注点不同
工业控制系统漏洞所影响的对象一般是使用工业控制系统产品的能源、交通、化工等基础设施生产或使用单位，其风险评级不能像 CVSS通用缺陷评估系统那样，根据漏洞固有特性、随时间而变的特性、与用户环境相关的独特性等对漏洞风险等级进行度量。目前比较流行的漏洞评级方法有 NVD、US- CERT、Secunia、X- Force等安全机构，以及 Symantec、RedHat、Microsoft 等生产厂商所制定的度量标准，多是对产品脆弱性进行定性评估，并且是静态的，这样给风险评估、应急响应等带来很大的不确定性。
为了解决这些问题，美国基础设施顾问委员会提出了一个开放的、动态的、适用于不同环境的定量评估方法 CVSS(CommonVulnerabilityScoringSystem)。尽管 CVSS的提出解决了漏洞评级当时存在的一些问题，但其未包含工业控制系统漏洞所特有的评估要素，如威胁对象类型、使用权限、攻击途径、攻击位置等。如攻击位置若位于工业控制系统网络架构的生产设备层时，即便其他方面的评估值很低，总体值也应被修正为高风险。因此，本漏洞库采用优化的漏洞评级方法 CVRS(CommonVulnerabilityRatingSystem) 对工业控制系统漏洞进行评级[6]。

 

2)漏洞收集方式不同
传统漏洞信息大多通过类似 NVD、CVE、国家信息安全漏洞共享平台、中国国家信息安全漏洞库等国家级漏洞平台或 Wooyun[7]、Sebug 等民间平台公布，而工业控制系统则通过 ICS- CERT、CNVD 的工控系统行业漏洞平台[8]、工业控制系统生产厂商官网等进行公布，国内专业工控系统漏洞库较少，CNVD 的工控系统行业漏洞平台主要通过对 CVE 相关漏洞的分类整理进行收集，未能较突出地体现工业控制系统漏洞的重要性和危害性。多数收录工业控制系统漏洞的机构组织仅将从 CVE 官网搜集的漏洞进行简单罗列和展示，未进行更深一步的分析和评级。
本漏洞库将综合搜集官方及民间公布的工业控制系统漏洞，并对其进行重新评级，按照行业领域、生产厂
商、威胁程度等方式进行合理的分类整理，使得漏洞具有更强的内在关联性、版本连续性及信息完整性，为工控安全研究者和设备使用单位提供更有价值的参考。
3)漏洞验证机制不同
得益于传统信息系统运行环境的兼容性和硬件高性能，传统漏洞的验证往往可以通过漏洞扫描器中的自动化 POC 完成验证过程。而工业控制系统运行环境实时性的要求苛刻，设计之初未考虑抗网络攻击功能，硬件冗余性较差，如果使用自动化扫描进行漏洞验证，很可能会造成工业控制系统崩溃或运行错误，从而影响整个生产进程。因此，工业控制系统的漏洞验证大多需在实验环境或镜像环境中进行。
4)修复时机不同
工业控制系统漏洞的生命周期与传统漏洞有所差异，由于漏洞影响目标的特殊性及系统补丁兼容性差等原因，即使在生产厂商发布解决方案或更新补丁以后，为防止生产设备或工控系统不能正常运转，控制系统使用商通常也不会马上对漏洞系统或产品进行修复。因此，对于工业控制系统漏洞的修复，往往要经过较长时间的分析研究和实验论证，才能确定能否直接修复漏洞或需要设计针对性的防御方案来抵抗攻击。而普通信息系统的漏洞大都可以支持在线修复，不会影响信息系统的实时运行和业务连续性。

2漏洞管理系统

设计方案

2.1 工业控制系统漏洞分类和模型

漏洞类型是描述系统漏洞的特征属性，可以从以下几方面概括其特征：漏洞的攻击利用途径、漏洞形成的主要原因、漏洞对系统造成的危害、漏洞的影响对象属性、漏洞的发布时间等。

由于工业控制系统更强调对系统的控制能力，其所关注的安全问题多是放置违规越权操作、避免业务中断、保障控制系统实时性以及生产制造正常运行等。在分析工业控制系统漏洞时，按照漏洞可能造成的危害分为：越权执行、越权写入、越权读取、拒绝服务、身份验证机制缺陷、权限管理机制失效等；按照漏洞的攻击利用途径分为：远程服务器漏洞、远程客户端漏洞及本地漏洞；按照漏洞的影响对象属性分为：ICS 产品、ICS 主机和 ICS网络。其中越权执行，指缓冲区溢出、命令执行、SQL 注入等可以直接对系统造成较大程度控制的漏洞。

越权写入，指能以某种方式在系统上写入文件、修改用户密码和系统配置等，但无法直接执行代码的漏洞。越权读取，指能读取指定或任意文件、内存信息等的漏洞。拒绝服务，指可导致进程崩溃、死锁等，使软件无法正常工作的漏洞[4]。
为实现对国内外漏洞标准的兼容，并使得漏洞库的数据结构合理清晰，便于漏洞的发布、检索以及后期的系统扩展。在研究工业控制系统与普通信息系统漏洞异同的基础上，参考《 漏洞标识与描述规范》 以及国内外主流漏洞库的结构模型[9]，本文对工业控制系统漏洞属性进行了分析归纳，提炼出 9 个属性群组描述工业控制系统漏洞信息，漏洞库结构，其中,包括基本信息(信息来源、来源编号、漏洞名称、漏洞描述、发布时间、更新时间)，评级(级别编号、CVSS 评分、危害等级、攻击复杂度、利用权限、攻击前提)，类型(使用领域、影响对象、攻击途径)，影响软硬件(受影响对象、描述、所属厂商、工作层级)，修补方案(修补建议、方案来源)，厂商信息(厂商所属地、名称、描述)，漏洞提供者(姓名、联系方式、工作单位)，类型描述(名称、描述)，安全事件(简述、详情、涉及漏洞)。
使用上述描述方法把多维漏洞属性划分成相应的群组，实现了漏洞信息结构化存储，不仅方便用户根据需要获取关注的漏洞信息，还便于漏洞库管理人员能够灵活地对漏洞信息进行更新和维护。另外，该漏洞库模型为每条漏洞信息设置来源编号和内部编号，满足在不同场合对漏洞进行引用和溯源的需要。

2.2 工业控制系统漏洞库系统架构

本文设计的工业控制系统漏洞库系统使用 B/S 架构实现。用户界面直观友好，用户能够在短时间内熟悉系统并掌握操作流程；管理员可以根据需要方便地管理漏洞类型、漏洞详情、评论内容等，用户也可以通过搜索或分类方便地查看漏洞信息；用户能够以留言评论的形式与管理员进行交流互动。同时，管理维护相对简单，系统的升级和扩展更加便捷。如图 1 所示。

 
漏洞分类展示平台和发布管理平台基于 Linux 平台和 Django 框架开发，使用 Apache 作为 Web 服务器；功能层的漏洞报告下载、属性提取等功能用 Python 语言开发；数据层选择 MySQL 关系数据库存储数据和漏洞镜像。工业控制系统漏洞库的设计主要针对工业控制系统漏洞的特点进行。整个漏洞库分为视图层、功能层和数据层。视图层分为两部分，漏洞分类展示平台用于向用户提供漏洞检索、查询及浏览的平台，漏洞库管理后台主要用于进行漏洞信息的发布、人员权限的管理并提供漏洞的检索统计。功能层主要用于实现漏洞信息的管理、文件生成、下载、规范化和人员及其权限的管理等逻辑处理过程。数据层主要用于存储漏洞信息、用户信息等数据。

2.3.1 权限管理模块
由于工业控制系统漏洞可能涉及较重要领域的漏洞信息，因此要实施规范的用户角色管理并执行严格的权限访问控制方案，要求漏洞库用户全部实名注册并进行身份验证。漏洞库用户角色主要分为游客、会员、漏洞库管理员及超级管理员，具体的权限分配如表 2 所示。


另外，对通过 Web 页面提交的漏洞信息进行加密传输，要求通过邮件提交漏洞的用户采取加密措施，保证未验证漏洞在上报过程中不被未知人员窃听截获，给用户和厂商造成不必要的损失。

2.3.2 登录模块
会员通过输入正确的用户名、密码等身份信息登录系统，登录模块负责完成对用户身份的验证、密码管理等功能。同时，登录模块设计了友好的错误提示，对于输入数据的格式，前后端都有验证，既保证了用户体验度，又确保了系统的安全性。
2.3.3 人员管理模块
对于长期运行的系统，随着系统使用人员的流动或者恶意注册用户的增加，管理员就需要对系统中的注册用户进行审计清理。通过人员管理模块，管理员可以对不同权限级别的管理员及普通用户进行增删改操作。
2.3.4 漏洞展示平台
漏洞展示平台面向所有用户。用户可以通过平台浏览已发布的漏洞信息，进行漏洞的查询检索并下载查询结果或统计数据。平台通过页面提供详细完整的漏洞信息和强大的查询检索功能，帮助用户轻松找到自己关心的某个或某类漏洞，并在查看安全事件内容的时方便查看事件中涉及的漏洞情况。

2.3.5 漏洞库管理模块
漏洞管理引擎是将漏洞自动检索和个人上报的漏洞信息进行汇总整理后，得到规范的漏洞信息，然后发布到漏洞展示平台上。漏洞库管理员通过管理模块将漏洞属性、信息描述、风险等级等上报到漏洞库，同时系统根据 CVRS评级方法计算其危害程度。管理模块留有漏洞自动检索上报时的接口，方便自动检索功能的扩展。会员用户还可以通过系统的漏洞生成插件下载指定的
漏洞信息报告。

3 结束语

完善的安全漏洞数据库是建立信息与网络威胁预警机制必须的信息资源，工业控制系统的安全关系国家基础设施的安危，因此，对漏洞信息进行分析、总结、积累，建立漏洞库是十分必要的。文中对工业控制系统漏洞分类、漏洞库模型及系统设计进行了探讨，并实现了基于工业控制系统漏洞库模型的漏洞库系统，提供工业控制系统漏洞信息共享发布和检索查询等功能，为相关人员学习研究工业控制系统软硬件漏洞，交流工业控制系统安全知识提供平台。
