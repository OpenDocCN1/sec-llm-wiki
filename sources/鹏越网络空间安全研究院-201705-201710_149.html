2、程序设计

2.1使用情景

小明有在电脑上写日记的习惯，但是他的笔记本电脑经常会借给同学使用，他担心自己的个人隐私遭到泄露，于是想对自己的日记和生活照片等文件进行加密。


2.2程序功能设计

经过对需求的初步分析，目标程序是一个能够对常见的小文件（格式包括但不限于txt、doc、jpg）进行加密的程序。针对同学的日常生活习惯，可以得出以下的基本功能特性：

程序小巧快捷

能够批量加密文件

能够自定义加密所用的密钥

解密文件方便

减少不必要的繁琐的设置文件，做到可以打开即用


3、算法设计

3.1 加密方式的选择

由于小明同学是对个人文件的加密，并且要求速度较为快捷，所以不需要采用AES、RSA、IDEA等相对较为复杂的算法。而较为简易的加密算法有：

将文件内容乱序，以达到无法读取明文的效果，解密时候只需要逆乱序即可。

将文件的编码（如ASCII码）按照一定的算子转换为另一编码，使之不可被直接打开，解密时只需要用逆算子即可还原。


而在实际需求中，采用文本替换的方式来进行加密会遇到很大的问题。被加密的文件不限于txt纯文本文件，而需要让程序支持doc等编码复杂的文件会使得代码量急剧上升。并且对于JPG等图片文件而言，文本替换是不可行的。


但是我们可以发现，在计算机系统中，任何的文件本质都是一段二进制的数据，所以在二进制的层面上对文件进行加密，可以有效的提升程序的兼容性，减少程序的复杂程度，并且，由于cpu的内部构造原因，程序对二进制数据的操作速度要远胜于对文本型数据的操作速度。


在二进制数据的处理中，常用运算有：按位与、按位或、按位异或、去反、左移、右移等。左移右移操作有丢失数据的风险，且对数据本身无实质性的加密，所以在此处并不打算使用这些运算符。


而异或运算（也称半加运算），是二进制中最特别的一种运算，运算法则为：

a Xor b= (¬a ∧ b) ∨ (a ∧¬b)


运算的实例如下：

A：    1011001

B：    0110011

A Xor B=1101010

由于异或运算的特殊性质，有（A Xor B）Xor B=A

A Xor B=1101010

B=0110011

（A Xor B）Xor B=1011001


3.2 加密密匙的获得

所以在加密的运算中，如果使用异或运算，可以实现加密与解密操作统一，从而减少了代码的复杂程度，并且可以大大加强程序使用的方便性。


如何形成加密的密钥？程序可以自带一个默认的加密密钥，但是有很多情况下，用户希望自定义密钥。很多情况下，用户所自定义的密钥长度是不能确定的，为了结局词问题，我们可以采用循环密钥的方法来对文件进行加密。例如文件内容是“abcdefg”，用户输入的密钥是“!@#”，那么我们可以进行如下运算：

a  b  c  d  e  f  g

^ 1  2  3  1  2  3  1


这样可以解决无法预料用户密钥长度的问题。


4、程序实现

4.1 原始程序

按照最基本的加密算法，可以很轻松的实现程序设计的最基本功能。


4.2 进一步提升

但是有几点附加功能的实现需要对程序进一步修改。首先是文件的批量加密问题，如果用通常程序的实现方式，需要手动一个个地输入所需要加密的文件，那么会使效率大打折扣。但是如果我们的加密程序能批量获取文件名，那么就方便多了。但是由于程序的main函数不能被其他函数所调用，所以要想让main获得参数，传统的方法是在命令行下输入程序的文件名，然后再一个个地输入参数，输入格式如下：

C:\>可执行文件名 参数 参数……


而在windows图形界面下，我们可以将文件拖动到另一个程序上打开，把A文件拖动到B程序上打开等价于：

B程序所在目录\> B.exe  A.File


而要使main能够接受参数，根据C++的规定，要将main的定义写成：

Int main (int argc,const char *argv[])

{

....

}


其中，argv[]与*argv等价，都表示的是一个数组的头地址，所以也可以用如下写法：

Int main (int argc,const char **argv)

{

....

}


其中，argc整形变量记录的是传入的参数个数，由系统传入参数的时候确定，但是由于程序本身文件名占用了一个参数，所以argc的值等于参数个数+1。例如：

./test.exe a b c d

a b c d 分别为四个参数，其关系为 :

argc = 5

argv[0]=./test.exe

argv[1]=a

argv[2]=b

argv[3]=c

argv[4]=d


在实现中，我们只需要将加密部分用模块化编程，单独写成一个函数，在main中读取待加密的文件，然后对每个文件分别调用加密函数即可。

我们将程序设计成拖动文件到程序上后加密，而用户习惯性地双击打开此程序的时候，我们希望能显示一则使用说明，所以在main中，应对argv=1，即用户直接打开了程序，没传入其他参数的时候，进行特判。

if(argc==1)

{

Guider();

return 0;

}


而对于密码的存储问题，可以从程序相同目录下的encrykey.txt内读取，如果判断没有此文件，或者密码为空，就使用程序内置的密码。
