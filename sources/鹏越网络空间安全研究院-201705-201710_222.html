Senrio 7月曝光的Devil's Ivy（魔鬼的常春藤）漏洞让Axis的数百万物联网设备暴漏于威胁之中。

 

他们发现了一个堆栈缓冲区溢出漏洞 (CVE-2017-9765), 又被称之为Devil's Ivy。该漏洞被从一个第三方的gSOAP (简单对象访问协议)中被发现，能够支持远程代码执行。

 

可怕的是gSOAP 是一个广泛使用的 web 服务工具包, 世界各地的众多开发人员都在使用 gSOAP 作为软件栈的一部分, 以使各种设备能够与互联网进行连接。

 

管理 gSOAP 的公司 Genivia声称有超过1百万的下载者使用 gSOAP , 其中包括：ibm, 微软, adobe 和施乐。可与预见该漏洞的影响范围将会十分“广阔”。仅Axis一个厂商就被发现249种类型的摄像头存在这个漏洞。

 

目前，Genivia 已经发布了一个新的补丁，并通知了客户该漏洞的存在。

 

那么该漏洞细节是什么？

 

在Axis M3004上通过向端口80的 onvif 服务发送一个 post 命令，就可能实现远程执行代码的目的。这里可以利用IDA将传入数据写入堆栈缓冲区。


IDA Pro


Senrio 研究人员通过在 web 服务器激活 ssh, 然后通过 gdbserver (已经安装在摄像头上的) 远程调试服务, 来观察服务和代码执行结果。

 

虽然可以写入堆栈的字节数没有限制, 但不能在它上执行代码, 而且筛选器要求发送的所有值都大于31。这里验证者使用了一种称为返回定向编程 (rop) 的技术, 将地址写入堆栈, 迫使程序在 libc 中执行代码段, 这样就可以绕过不可执行堆栈。

 

通过这项技术, 验证者可分配可执行空间, 将自己的shell复制到该空间, 并定向执行它。由于 axis 的安全设置, 此漏洞仅授予对 shell 的访问权。但是可以利用 onvif 规范执行特权用户才能正常使用的命令,这样黑客就能够将相机重置为出厂默认值, 并控制摄像机, 重新启动, 并更改网络设置。



验证者首先从axis 获取了M3004 相机的最新固件，使用FFS2 文件系统的Jefferson和binwalk提取了文件系统和 linux 内核使用。

 

binwalk 的输出


运行 nmap 扫描相机的开放端口, 发现 1900 (upnp), 3702 (ws-discover) 和 5353 (mdns) 打开。而ws-discover与导入 libsoap.so（Genivia 的gSOAP ）的wsd服务相关。Wsd接受传入的 soap 消息，而可以使用ida pro 查找堆栈缓冲区, 手动跟踪复制到它们的任何数据。

 

从 libsoap 导入的函数


在将传入数据写入0x40 字节堆栈缓冲区的函数 soap_get () 中, 有一段代码在一个循环中将检查数据 结束字符 "？"为结束条件, 而不是计算它写入0x40 字节堆栈缓冲区的字节数。

 

soap_get () 中的易受攻击的代码循环


图中, R6 是计数器, 设置堆栈缓冲区的大小, R9 是堆栈缓冲区指针, 而 R5 是从网络中读取的传入字节。

 

如果 R6 中的数据计数器小于零, 该函数将跳过写入缓冲区, 但继续使用 j_soap_getchar () 读取数据。通过给WSD写足够的数据, 将计数器再包装成正数, 就可以将数据写入堆栈中, 超过0x40 字节限制。由于对传入数据的数量没有限制, 可以使用 netcat 发送。

 

尝试在80端口上发送一个 post 命令给 "/onvif/device_service"（WSD）, 从而触发了漏洞。为了发送0x80000070 字节, 验证者生成了一个文本文件, 以 "post/onvif/device_service" 开头, 后跟一个新行和 "<？" 以指示 soap 消息的开始。用垃圾字节填充文件的其余部分, 然后使用 netcat 发送该文件：

nc [camera_ip] 80 postpwn.txt

 

使用摄像头的嵌入式 web 服务器, 导航到高级菜单, 通过编辑/etc/conf.d/ssh启用 ssh。重新启动摄像头后, 则可以设置的SSH用户名和密码。

 

发现gdbserver 已经安装在摄像头上, 利用其检测服务，发现其果然溢出。

 

利用gdb调试的WSD


但目前堆栈是不可执行的。验证者发现libc处于静态位置，因此可以一起组成 rop 链，让代码片段在 libc 获得执行。

 

/proc/[pid]/maps给出了wsd中libc 的静态位置


使用 ida 和 find 中的 regex 功能手动找到了需要的 rop 地址。首先调用 pvalloc () 分配一个页面对齐的内存缓冲区, 然后使用 strcpy () 将shell从堆栈的较低层复制到缓冲区中。通过调用 mprotect () 来标记缓冲区可执行文件, 然后跳到可执行缓冲区以开始shell。

 

其他设备可能使用 gSOAP 作为 root 用户运行该服务, 但此特定设备仅授予对 shell 的访问权限较低。权限设置位于照相机上的文本文件中, 由wsd用户可写。可以使用sed (通过 busybox 在照相机上可用) 来更改 SystemReboot 命令的权限, 以允许匿名用户使用以下行运行它:

 

SystemReboot=8/SystemReboot=f/access_policy

由上述过程可见物联网设备安全的脆弱程度~！建议尽快升级补丁，或断开互联网连接。
