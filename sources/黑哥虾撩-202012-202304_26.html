二、朝鲜黑客组织多次发起针对网络安全研究者的攻击


2021年1月谷歌TAG披露了一个来自朝鲜的黑客组织，他们通过包括推特、领英、Telegram、Discord、Keybase和邮件等的社交方式，并以技术分析研究成果（blog及样本）为诱饵攻击安全研究人员。国内多名知名安全研究人员曾收到过他们的推特私信进行引诱。随后朝鲜黑客组织进行了多次类似这样的攻击尝试，其中还包括冒充三星招聘人员进行鱼叉式攻击攻击韩国安全公司、利用泄露版的IDA植入恶意文件等等


从攻击次数频率来看，推测还是有不少技术人员中招，要不然他们也不致于多次使用这种招数！事实上可能是因为技术人员对技术研究分享者有天然的后感，这种攻击方式我在10年前有过很多的尝试，比如80vul网站上做水坑攻击（利用xss、json劫持等获取访问者的社交ID）1年多之久，没人发现，在这里顺带再次推荐个我在2012年的写的老ppt 《WEB2.0下的渗透测试》

三、多起供应链安全事件值得深度关注


包括美国爆发“太阳风（SolarWinds）”供应链安全事件、已经涉及我国的SonarQube代码管理系统漏洞事件，当然也包括年末的Log4j2漏洞事件。


SolarWinds事件对于美国来说是影响是巨大的，以至于美国众议院举办相关听证会，美国多个公司及组织耗费几个月的时间进行事件分析溯源，也给网络安全行业带来了新的思考，事实上我是觉得美国在此次事件上应该算是有收益的，通过这次的攻击洗礼最起码让美国意识到了这类攻击的威力后续必然投入更多针对性的防御。 


SonarQube事件的原因是由于2020年的爆发的一个漏洞是由于API未授权导致的源代码被下载的漏洞

事实上这个漏洞知道创宇4040实验室早在2020年7月29日就进行应急（404实验室漏洞快递服务），在2020年8月3日通过Seebug公众号对外发布预警 
404实验室，公众号：Seebug漏洞平台知道创宇404实验室漏洞应急 | SonarQube API未授权下载源代码


直到2021年10月后有人在一个叫RF的“暗网”论坛上非法出售我国“金融、医疗等重要领域的信息系统源码” 
CNCERT，公众号：国家互联网应急中心CNCERT关于近期境外黑客组织攻击我国多个企业窃取源代码数据的通报


Log4j2漏洞事件刚刚发生这里就不重复了，可以参考之前我写的那些文章。这个在后续的漏洞大事件里也会提到，因为考虑到log4j2组件属于基础开源组件的地位这也算是供应链一个重要环节。


由此在上面三个案例：


SolarWinds：代表着商业的软件供应链SonarQube：代表着代码管理系统Log4j2：代表着开源基础组件


这2021年影响最大的三个供应链事件说明一个非常重要问题：

「“安全事件”仍然是网络安全的第一推动力！」
heige，公众号：黑哥说安全谁应该为Log4j2 RCE漏洞负责？


实际上SonarQube的事件针对性就表现得很明显，在Log4j2事件里出现的第一起勒索软件攻击，就是针对我国独有的自主研发的某OA系统，这都是“强针对性”信号！


总之：影响大、针对性强、更复杂隐蔽的“供应链”攻击一定会来，我们需要提前做好积极防御准备！！！


四、10大影响重大的漏洞事件


1、微软Exchange ProxyLogon事件


实际上这个是一个组合攻击，ProxyLogon对应的 CVE-2021-26855 允许攻击者绕过身份认证，然后通过CVE-2021-27065 实现任意文件写入漏洞，写入Webshell达到RCE的目的，“相比漏洞本身我更加在意漏洞后面的故事”，这个漏洞最早是2020年3月volexity披露的一个在野攻击事件，通过他们的分析发现在2021年1月6日（不知道时区）就出现在野攻击，随后2021年3月3日微软紧急发布补丁进行修复，而这个漏洞报告最早可以追溯到2020年1月5日（GMT）由台湾的安全团队DEVCORE报告给微软[注：从https://proxylogon.com/的时间线来看，DEVCORE称在2020年12月发现漏洞]，知道创宇404实验室团队是2021年3月4日后复现的该漏洞并发布预警（据说由此我还被微软的人进行了调查...），随后有多个攻击团队对全球网络进行疯狂的攻击，通过ZoomEye的数据可以看出美国有大量的Exchange部署，由此FBI不得不通过立法来实现“入侵”这些存在漏洞的Exchange的服务器然后删除黑客的后门程序，这也算是创造了历史了！


顺带提一句这个漏洞也由此获得了2021年Pwnies最佳服务端漏洞，当然也由此掀开Exchange漏洞挖掘的热潮，以至于Pwn2own上我记得好像有三支还是四支队伍对Exchange挑战，从微软的致谢榜来看后续还有好几波



2、微软MSHTML 0day CVE-2021-40444事件


 这又是一个在野利用，但是实际上从攻击效果上看我觉得这个漏洞的“品相”不算是最佳的（因为需要点击“编辑”提示），这个漏洞我们也用于了我们内部实战攻击演练对抗，当时还是0day状态从我们攻击对反馈的效果来看成功率为0（当然这个跟我们内部的一些机制有强关联性），这个角度也说明了这个“品相”问题，当时比较郁闷的我们攻击的样本被我们同事上传到了VT，因为太过于逼真以至于很多安全同行通过VT上找到这个样本被误以为是实际在野攻击，我不得不一个一个”公关“。当然在技术角度来讲这个漏洞还是非常不错的，是经典的”猥琐流“应用层逻辑漏洞，最早因为微软的漏洞通告里提到的mshtml的漏洞，导致国际上很多安全同行找到了10几年的文章，实际上最后确定跟我那个文章没有太大的关联性，附上我们知道创宇404实验室团队的分析：https://paper.seebug.org/1718/ 从我们的分析结果推断漏洞发现者的“灵感”来源可能是Zhipeng Huo (@R3dF09) of Tencent Security Xuanwu Lab 发现的CVE-2020-1300：

3、阿帕奇Log4j2 漏洞事件


 这个又是一个创造历史的漏洞，关于这个漏洞我已经写了很多的文章了有需求的可以看看之前写的文章。这个漏洞也随着工信部对阿里云的处理迅速“出圈”，但是本次“出圈”吸引了大量的妖魔鬼怪，甚至还包括不少安全参与者，我只能表示我想回火星！当然这个问题同样参考之前的文章不再强调。这里需要提一点的是，很多人把这个跟之前的漏洞相比，认为从实际攻击效果或者后果，不及历史上微软的一些漏洞，首先我想说的时代不同了场景也不一样实际上是没有可比性的，比如微软的一些漏洞是可以影响个人pc的，而这个多是影响服务器，个人pc可能表现的是某个游戏客户端的攻击。其次这次的攻击“效果”是由于整个互联网网各大安全运维连夜加班应急的效果体现，虽然在技术维度有JDK等问题的限制（当然有个细节很多没有提到Tomcat的链是不受JDK版本影响的），但是无奈Log4j2的应用实在是太大了。所以这也是给我们的启示是跟上面供应链里提到的一样：漏洞（包括0day）并不可怕，只有积极科学应对，加强防御能力才是王道！当然也告诉我们：漏洞（包括0day）始终都是存在的，总有人为了他们的无知懒惰不作为而买单！


4、某演练期间导致0day大爆发


因为规则的原因这个期间爆发了大量的0day漏洞，据说某团队贡献了数以百计的0day漏洞，通过知道创宇参与防御的结合创宇盾及创宇蜜罐等产品成功捕获了多个0day攻击，其中包括weblogic、国内OA系统等漏洞。比较有意思的是利用历史上Chrome的内核漏洞(CVE-2021-21220)来攻击微信，这个主要是由于很多的应用程序使用了老版本的Chrome并没有开启sandbox，这也算是掀起一波小高潮主要针对一些网络安全工具的反溯源攻击等，当然还有见证一下通过抢注云平台微软等大厂过期子域名进行C2上线的大尺度攻击手法等

7、Apache漏洞事件


这个事件包括两个CVE：CVE-2021-41773 及 CVE-2021-42013 从官方及上面google p0的统计来看这个漏洞也存在在野利用阶段。最早这个漏洞由cPanel 安全团队发现，漏洞细节对外曝光是在10月安全研究者通过Apache官方开源的补丁逆向出了细节并公布，最开始大家都以为只能泄露文件代码，随即有研究者发现在cgi模式下可以直接导致RCE，值得8挂的是当时这个漏洞只影响 2.4.49这个版本，而且是非常经典的漏洞模式，以至于很多安全研究者感叹到都21世纪这么久了居然还有这样经典的漏洞，按log4j2漏洞带来的一些“阴谋论”思考，这个漏洞也非常可疑～～！（当然你也可以联想下PHP源码被植入后门代码那个事件）


果不其然，经典的漏洞必然有经典的绕过！在Apache HTTP Server 2.4.50的修复补丁没过几天就被绕过也就是CVE-2021-42013了～～～


8、QNAP NAS多个0day攻击事件


因为这个0day是被爆在黑产勒索组织攻击中的利用，所以没有入上面Google P0统计的法眼，从知道创宇404实验室漏洞应急记录来看在2021就爆发了多次0day RCE漏洞被eCh0raix（⼜名 QNAPCrypt）勒索软件利用，比较有意思的通过官方的QNAP Security Advisories记录来看光带“Ransomware”关键词的安全公告在2021年就达到了9条之多，当然还有很多没有带“Ransomware”同样被用来做勒索攻击的漏洞，随即通过ZoomEye对

app:"QNAP NAS storage-misc httpd"

进行数据趋势分析发现，从2014年到2018年QNAP NAS设备呈增长趋势，从2019年左右暴露在互联网的设备呈现大幅度下降趋势，因为从2019年开始就有勒索软件利用盯上了QNAP NAS


9、Confluence RCE 漏洞事件


Confluence的漏洞还是很受攻击者亲耐的，在2021年9月1日知道创宇404实验室发布了一个关于Confluence Webwork OGNL表达式注入的漏洞（CVE-2021-26084）的漏洞应急报告，一直到2021年11月底位于东莞的某集团公司被黑客入侵后被篡改植入反动标语，最终被有关部门依照相关法规处以10w元罚款！这个跟前面提到的SnoarQube事件一样，如果不积极应对安全漏洞，最终只能被转化为“安全事件”而买单。

五、多起网络安全相关法律法规条例正式发布并执行


其中主要包括2021年9月1日起施行的《关键信息基础设施安全保护条例》《网络产品安全漏洞管理规定》及2021年11月1日正式施行的《中华人民共和国个人信息保护法》，其中对于安全圈关注度比较多的就是《网络产品安全漏洞管理规定》条例了，我记得那时候很多安全从业人员非常担忧这个问题，并且停止了很多技术分享，这个具体问题可以参考光明网对我的采访：https://mp.weixin.qq.com/s/elO0phTZoKe_jXwj_ayhyQ 当然这个规定在Log4j2里的也有热烈的讨论，这里推荐一批来自律师事务所的文章：https://mp.weixin.qq.com/s/G74rn_QRU5JvefIqnmlZSw


在此之外我还需要强调一个可能看起来跟安全没多大关系的通知：《关于进一步防范和处置虚拟货币交易炒作风险的通知》于2021年9月15日人民银行发布，随后火币等多个交易所宣布清退大陆地区用户，目前虚拟货币仍然是区块链技术的主要利用场景，很多业务方受到影响，这势必也影响到安全业务的市场，另外该通知提到了可以依法追究给虚拟货币相关业务提供技术支持的法人有关责任，这也给安全业务公司带来了一定的不确定性！


六、国内网络平台企业赴境外上市带来的数据安全风险


这个主要是滴滴公司上市美股带来的国家联合调查组介入调查，最后滴滴宣布退出美股。这个背后的核心问题是数据安全问题，为此在2022年开年就发布《网络安全审核办法》从2022年2月15日开始施行，这也算是2022年的第一个大事件了。

八、UMN vs Linux Kernel


这个事件其实除了学术界的朋友可能很少有人关注，我最早看到的事件：


Linux 内核项目维护者 Greg Kroah-Hartman 决定禁止美国明尼苏达大学（UMN）为开源 Linux 项目做贡献。其原因是明尼苏达大学的研究人员被发现提交了一系列的恶意代码，或故意在官方 Linux 代码库中引入有安全漏洞的补丁以作为其研究活动的一部分。
Travis，公众号：OSC开源社区因故意引入漏洞，整所大学被禁止为Linux内核做贡献，回应来了！


当时因为没有认真看原始的paper就相关文章所以误解了当时UMN是利用了自己作为开发者的官方信任身份去做的提交，实际UMN相关人员是完全模拟外部提交的代码的方式进行尝试的！这种攻击手段是非常有意思的而且确实存在的攻击方式，近年来针对开发者的攻击导致的安全事件是越来越多，从paper的结果来看UMN的尝试显然是成功的，以至于Linux 内核项目维护者 Greg Kroah-Hartman “恼羞成怒”！


这里我们有必要回到上面提到的供应链安全事件里，比如茄子同学就一直在纠结Log2j4在2013年7月提交的JNDI lookup插件的issue是不是属于这类主动恶意提交的范畴。


针对开发者及开发社区（包括上面漏洞事件里提到日本小哥对代码软件管理的攻击）已经成了一种趋势，越来越多的针对性攻击手段出现。

十、“行为测绘”打开威胁情报新的潘多拉之盒


这个算是“王婆卖瓜”了，但是从我的角度来讲“行为测绘”理念确实是值得推荐的，在2021年算是我们ZoomEye丰收的1年，在国内甚至在国际上我们一如既往收获很多的肯定及认可，比如作为唯一国内厂商入选全球2021 OSINT及网络安全研究者喜欢的搜索引擎榜单，这也算是ZoomEye作为网络安全领域的代表为“中国制造”做了点小小贡献 ，当然在国内第三方调研机构发布的《网络空间资产测绘(CAM)能力指南》里知道创宇ZoomEye获得了创新力、市场执行力、心智占有力三项能力第一，这些都是ZoomEye作为网络空间测绘领导者的强有力的支撑！


在提出“动态测绘”、“交叉测绘”理念后，在2021年正式对外发布“行为测绘”，该理念在基础设施测绘及APT、僵尸网络攻击组织使用资产测绘领域有非常显著的应用，从被动的依赖手机攻击者的样本抓取，转化根据攻击者的使用服务器独有“行为”配置主动探测扫描，实现“一网打尽”的效果，在结合“动态测绘”实现实时动态监控攻击者的网络资产，同时通过增加网络资产指纹的维度弥补了对传统纯粹依靠有限的恶意样本分析进行归类画像的不准等方面的不足。


在现有威胁情报分析领域通过主动网络空间测行为测绘理念，增加不一样的视角及数据维度对攻击者进行画像，无异于打开了一个新的“潘多拉之盒”！
