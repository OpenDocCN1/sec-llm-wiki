笔者心血来潮, 网上下来QQ泄露的群数据库。

压缩文件, 总计 24.5GB, 解压后90+G.

包含两部分信息: 群信息 + 群内成员信息

挂载部分数据库

群信息-1, 群信息数据采用分库分表的方式处理持续增长的数据信息，可扩展性不成问题。一个库包含10张表， 每张表数据量上限100W左右.

群信息-2，只包含基本信息， 群号，Title, 描述

群成员信息-1, 同样采用分库分表, 一库对应100张表。

群成员信息-2, 只包含简单的群组对应关系，没有任何密码之类的泄露。

1. 数据库是SQL Server 2000的版本, 笔者在windows 2012 R2上居然顺利装上了SQL Server 2000. 莫非某巨头现在用的也是SQL SERVER 2000作为数据库SERVER?

2. 以上数据能查询群信息，根据描述进行模糊查找。因为是2011年以前的数据, 很多群已经不存在了，笔者感叹有多少人能够长时间坚持某一项事业？

可以查某个群有哪些成员。

可以查某个QQ号加入过哪些群；

再别的基本就查不出太有用的信息了。

笔者就看到很多taobao店主的2002年左右创建的QQ群, 他们的店好些都是金皇冠的，好生羡慕。

3. 网传以上信息来自2011年的漏洞, 也就是数据泄露2年左右后被纰漏，大多泄露的数据应该都是泄露一段时间后才会流出。

4. 不知道以上数据到底有何商业价值？ 精确定位营销？ 分析这么多数据不是轻松地事。除了精确定位营销，剩下的就是满足一下近似偷窥的欲望， 看看过去10年QQ群发展历程。

不确定以上数据是否被修改过， 也不确定以上表结构是否为生产环境下的表结构, 有大数据业务的朋友可以稍微参考一下以上数据库设计方案。
