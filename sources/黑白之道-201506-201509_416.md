第二个议题是由浙江大学美女教授，南卡终身副教授徐文渊为大家带来的精彩课程《嵌入式系统安全分析\-以攻为防》

![](../Images/00dea58ae554c3df0a0643704a2f12d0.png "1435259884207293.png")

徐文渊教授通过三个实际案例深入浅出的为大家讲解了嵌入式系统三个模块的安全漏洞，分别是通讯模块、传感器和微处理器。

首先，徐文渊教授通过美国的自动抄表系统（AMR）为大家分享了无线传输过程中的安全漏洞，无线电表每过30秒就会自动发送用电信息，电力公司就会派信号接收车到小区收集信号，从而进行抄表。那么无线电表究竟有什么安全漏洞呢?我们又如何分析呢？

由于电表通讯采用私有协议，因此我们通过逆向技术破解了私有协议，识别可用数据，及电表跳频。从而达到监听、篡改电表传输的数据。这里危害显而易见，我们可以篡改用电量，还可以监测邻居们的用电情况，通过用电量统计分析，我们可以知晓邻里的作息时间，家里是否有人等等你意想不到的隐私数据。

第二个是模拟传感器，徐文渊教授介绍到，传感器主要的威胁来自读数没有任何防护，鉴于此，我们可以通过高频干扰这样攻击技术对读数进行保护。徐文渊教授通过视频为大家分享了他们团队的实验过程，在实验中，徐文渊教授团队通过高频干扰技术将原本是音乐播放的录音变成了朗读。同时，在试验中，徐文渊教授团队还通过高频实现干扰心脏起搏器，实现感知心跳信号，助力恢复心跳等功能（PS：汗！小编心想，这项技术即可救人也可杀人啊，还好美女教授心地善良）。

随后徐教授还介绍了通过旁路实时监控设备耗电量的技术，这项技术的监测细粒度可以分析出你打开哪些网站使你的电脑会更加费电。利用此项技术，再通过机器样本学习，就可以通过耗电量识别你究竟用电脑做了什么，访问了哪些网站等，经过测试，识别率高达99%。（PS：小编总感觉怪怪的，好像偷偷看教育片的隐私完全没有了）。

第三个议题是由盘古越狱团队的核心研究人员王铁磊为大家带来的精彩课程《越狱中的非控制流攻击》。

我们只是使用苹果，却无法控制苹果，作为IOS极客的你，将不容错过。

王铁磊开场为我们介绍了IOS的安全体系，例如IOS沙盒的限制，我们要想成功越狱，就需要突破苹果的层层防御，我们越狱的目的就是为了更深入的研究IOS系统，揭开它神秘的面纱，寻求更大自由，同时还可以帮助苹果修复漏洞，使IOS系统更加安全。那么我们如何才能越狱成功呢？总体来说就是通过漏洞突破ios限制，核心大体分为两步，一是攻击IOS内核，第二是对它的代码进行签名欺骗。传统的越狱方法都是通过执行shellcode、heap-sprayin等控制程序控制流，再绕过签名检查（code signing check）从而实现越狱。这些都是传统越狱的方法，盘古却有所不同，我们通过构造假的libmis.Dylib进行签名的欺骗，想办法将代码签名端的x属性打掉等，再利用内核和用户态（userspace）数据传输共享的弱点，通过向用户态写入大量数据打掉Notifymsg，从而达到任意内存写入，结合前面的签名欺骗，从而实现完美越狱。

随后是玄武实验室安全研究员王连赢为大家带来的精彩议题《IE沙箱的攻防对抗》

首先，王连赢为我们分享了IE沙箱从PM模式到EMP模式的发展历程，从Windows Vista开始，IE加入了PM模式，PM模式基于Vista新加入的安全特性，主要是完整性机制（Integrity Machanism），通过设置完整性级别（IL，Integrity Level）来限制对安全对象的访问。 从Windows 8开始，IE加入了EMP模式（Enhanced Protected Mode），EPM包含PM的所有特性，它基于Windows 8的AppContainer来进一步限制沙箱中进程的行为。

PM沙箱针对文件、注册表等安全对象进行了禁止写入的限制，对进程线程进行了禁止读取的限制，通过UIPI（User Interface Privilege Isolation 用户界面权限隔离）来限制窗口消息。那么EMP到底增加了什么呢？在AppContainer中的IE Tab进程若想要访问某个安全对象，则该安全对象的DACL中应至少包含EPM IE Tab AppContainer SID，IE Capability SID：S-1-15-3-4096和ALL APPLICATION PACKAGES中的一个。

针对IE沙箱我们是如何进行逃逸的呢?王连赢结合漏洞实例为大家进行了IE沙箱逃逸的多种逻辑类漏洞的深入的分析。大体可分为如下几种：

1、 **沙箱权限设置不严格**，沙箱中的IE进程权限没有被严格限制，一般是能够写不该写的位置导致了问题。

2、 **Elevation Policy设置不当**，相当于白名单机制，若白名单中的对象提供的服务可用来执行任意代码，就能完成被用来完成IE沙箱逃逸。

3、 **Elevation Policy Check Bypass**，Elevation Policy Check代码逻辑的问题，攻击者可以构造特殊数据绕过。

4、 **Shared Memory标志位修改**，IE共享内存对象（shared memory section object）用来存储IE的一些配置信息，其中一些标志位会影响Broker进程行为，沙箱中的IE Tab进程若能修改共享内存，就会有问题。

5、 **Broker服务接口执行任意代码**，IE通过Broker服务的方式来解决沙箱中的IE Tab进程某些操作需要高权限的问题，某些Broker服务接口就可以帮助攻击者达到执行任意代码的目的。

6、 **IPC通信权限问题**，IPC通信权限设置不当，使得沙箱中的IE Tab进程可以获得IE主进程的额外信息。

随后王连赢通过实际的漏洞案例分别对上述六种沙箱逃逸方法进行了讲解，最后王连赢总结道，基本上IE沙箱和外界通信的所有信道都出过问题，从继续研究的价值上来讲，Broker接口最值得研究。因为IE有很多未文档化的COM接口，可以找Broker进程内存崩溃和Broker进程任意代码执行两种漏洞。

最后一个议题是徐文渊教授的学生，浙江大学博士，闫琛为大家带来的精彩课程《汽车智能化道路上的安全思考》。

闫琛博士介绍到，随着汽车功能越来越多，它们越来越像一个超大型的智能手机，那么它们真的安全吗？我们团队曾经在没有特斯拉汽车钥匙的情况下，启动了特斯拉，在未来，也许智能汽车的越狱也会有一席之地。目前智能汽车的安全现状非常令人担忧，攻击方式也从有线攻击发展到无线攻击，目前已公开的资料显示，黑客可以做到控制汽车车门，汽车方向盘以及油门刹车等。

对于智能汽车，我们如何对它进行攻击呢? 首先智能汽车有十多个对外开放的接口，我们一般是通过OBD接口、keylessentry无钥匙启动接口和蓝牙wifi接口对其进行渗透。一般攻击的步骤通过接口的连接，可以是无线，也可以是有线方式攻击汽车远程信息处理系统，再通过攻击can总线的广播渠道实现对汽车所有嵌入系统的渗透。随后闫琛博士通过深入讲解攻击TPMS（胎压监测系统）为我们解开智能汽车攻击之谜。闫琛博士介绍到，攻击TPMS主要的工作分为两块，第一是逆向工程，通过模拟实验环境，对胎压系统数据包进行分析，通过FSK解调，再通过大量测试，利用假设推理与控制变量法，确定编码方式，效验算法，从而确定数据格式。第二块是距离的测试，我们通过实验，在使用普通天线情况下，结合LAN（低噪声放大器）传输的距离可以达到130米，如果通过设备的改良还可以大量提高传输距离。至此，我们可以在130米外向被攻击的汽车发送篡改伪造后的胎压数据，使得TPMS系统异常报警甚至损坏。

最终闫琛博士忠告我们，没有任何系统是安全的，为了自己的安全不要购买一些新出的，而且功能花哨的汽车，谨慎购买豪车（PS：土豪别再得瑟了），慎用后装汽车产品

汽车智能化是必然趋势，汽车安全将面临更大威胁，我们需要不断打造汽车信息安全系统。
