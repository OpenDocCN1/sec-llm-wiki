软件系统的安全性不可证明，因此从理论上讲，软件必然存在安全缺陷(漏洞)。

　　事实也确系如此，几乎每个厂商的软件产品都存在安全缺陷。以微软为例，根据CVE报告，自2006年开始10年间，该公司被披露的安全漏洞多达3,157个，平均每2天被曝光超过1个漏洞，而其中约50%是涉及允许执行恶意代码的高危漏洞。

　　在被曝光漏洞方面，微软并不孤单，Oracle的漏洞曝光数目也超过了3,100;而被视为较之微软更为安全的苹果公司，其产品在过去十年被曝光漏洞也超过了2,600，与之相对的IBM、 思科和 Adobe的产品也在过去十年被发现了大量的安全漏洞。

　　(上述漏洞细节并未完全公开!)

　　DarkReading给出了过去10年脱颖而出的10大漏洞报告。这里结合Pr0.S的认知与理解，解读如下：

       

　　0X01 OpenSSL Heartbleed Vulnerability (CVE-2014-0160)

　　Heartbleed漏洞，这项严重缺陷的产生是由于未能在memcpy()调用受害用户输入内容作为长度参数之前正确进行边界检查。攻击者可以追踪OpenSSL所分配的64KB缓存、将超出必要范围的字节信息复制到缓存当中再返回缓存内容，这样一来受害者的内存内容就会以每次64KB的速度进行泄露。

　　OpenSSL 库中的Heartbleed(心脏滴血)漏洞，使得原本安全的基于 SSL 的网站和软件面临着规模前所未有的信息失窃的攻击。在Heartbleed 首次披露后，有近三分之一的所有主要网站都被认为存在问题。

　　该漏洞给攻击者偷听网站流量，欺骗用户和服务器，窃取数据提供了可能性。

　　发现该威胁的Codenomicon公司营销副总裁David Chartier说，Heartbleed，可以说是到目前为止，最严重和广泛引用的安全漏洞之一。Heartbleed一个漏洞影响了超过 600,000个网站，并运行攻击者获取私钥和特权的凭据，可以用来窃听、窃取数据，模拟用户，而无需留下痕迹!

　　0X02 DNS Cache Poisoning Issue: Kaminsky Bug (CVE-2008-1447)

        

　　安全研究员dan Kaminsky 2008 披露的 DNS Cache Poisoning( DNS 缓存中毒)漏洞，引发了前所未有地对DNS这种互联网核心基础设施安全的广泛关注。同时，大量世界各地的技术供应商开始了安全修补战役。这种根本性的缺陷，允许黑客在 DNS 协议级别以相对简单的方式进行数据欺骗，并重定网络流量到他们选择的目的地。

　　缓存中毒攻击者(cache poisoning)给DNS服务器注入非法网络域名地址，如果服务器接受这个非法地址，那说明其缓存就被攻击了，而且以后响应的域名请求将会受黑客所控。当这些非法地址进入服务器缓存，用户的浏览器或者邮件服务器就会自动跳转到DNS指定的地址。

　　更为可悲的是由于该漏洞出现在DNS 协议级，由 Kaminsky 的披露引起的疯狂修补努力只能提高攻击者利用该漏洞的难度，无法“根治”。安全专家认为这个问题的唯一真正修补程序应该是DNSSEC(DNS安全扩展)，而这显然目前还难以在世界范围内实施。

　　0X03 GNU Bash Remote Code Execution Vulnerability: Shellshock (CVE-2014-6271)

        

　　Shellshock(破壳)漏洞与Heartbleed，都是有史以来令人印象最为深刻的bug。Shellshock 正式被称为 GNU Bash Remote Code Execution Vulnerability(GNU Bash 远程代码执行漏洞)，影响了大多数版本的 Unix、 Linux 和 Mac OS X ，该漏洞允许攻击者能够在受攻击的系统上执行恶意代码。

　　此漏洞存在与称为 Bash的组件中，是许多 Linux 和 Unix 必备的应用程序，用于输入命令到操作系统。此漏洞允许攻击者能够将恶意代码附加到某些变量，然后将运行操作系统。该 bug 影响了包括 web 服务器，Android 设备，OpenBSD，DHCP 客户端、 SSH 服务器和 Mac OSX 设备等在内的众多类型设备，一些分析师估计，近5000万的互联网连接的设备和 web 服务器当时遇到了该问题。

　　FireEye的威胁研究负责人Darien Kindlund 在一篇博客文章中指出，Shellshock比Heartbleed 更可怕，因为它会影响那些管理数量巨大的互联网服务的服务器。保守估计，影响涉及了 20 %至 50%的web站点。

　　0X04 Stagefright Vulnerabilities: CVE-2015-1538, CVE-2015-1539, CVE-2015-3824, CVE-2015-3826, CVE-2015-3827, CVE-2015-3828

        

　　安全供应商 Zimperium 发现的安卓的Stagefright多媒体框架库中存在多个远程可执行漏洞。该漏洞允许远程代码执行，通过利用发送一个特制的MMS消息。该漏洞对Android 2.2及更新版本均产生影响，对4.1及更新版本影响相对较弱。该漏洞影响了近10亿的 Android 设备。

　　谷歌2015年8月份首次尝试修复，为其Nexus设备产品线共发布了六个补丁，不想其中一个补丁并不完整，以至于打补丁后仍处于风险中。

　　0X05 SSL 3.0 Protocol Vulnerability and POODLE Attack (CVE-2014-3566)

      

　　SSL 3.0 协议漏洞可以使得攻击者打破客户端浏览器和 Web 服务器之间的加密的通讯，窃取身份验证 cookie 和其他数据。

　　POODLE攻击是针对SSLv3中CBC模式加密算法的一种padding oracle攻击。这个攻击方式和之前的BEAST攻击方式很像，可以让攻击者获取SSL通信中的部分信息的明文，比如cookie。和BEAST不同的是，它不需要对明文内容的完全控制，所以操作起来更加贴近实战。POODLE Attack可以发动中间人攻击拦截用户浏览器和HTTPS站点的流量，然后窃取用户的敏感信息，如用户认证的cookies信息、账号信息等。

　　US-CERT对该漏洞的警报指出，虽然 SSL 3.0 是旧的加密标准，但大多数 SSL/TLS 为了实现保持向后兼容 SSL 3.0 与流畅的用户体验，仍受到了POODLE Attack的严重威胁。POODLE Attack利用了当安全的连接尝试失败，服务器将回退到较旧的协议的机制，可以通过触发连接失败，强制系统使用 SSL 3.0， 然后尝试攻击。

　　0X06 Remote Code Execution Vulnerability in Microsoft Server Service (CVE-2008-4250)

        

　　多个版本的 Windows 包括 Windows 2000 SP4，XP SP2 和 SP3 和 Server 2008 服务器服务中的缓冲区溢出漏洞，为攻击者提供了通过远程过程调用有漏洞执行恶意代码的可能。更为危险的是攻击者可以在无需任何身份验证的情况下，在有漏洞的系统上运行任意代码。

　　微软的公告显示，Windows的Server服务在处理特制RPC请求时存在缓冲区溢出漏洞，远程攻击者可以通过发送恶意的RPC请求触发这个溢出，导致完全入侵用户系统，以SYSTEM权限执行任意指令。

　　White Ops的联合创始人兼首席科学家Dan Kaminsky评价，这是个“星级”漏洞，简单、 直接、可靠，更为可怕的是 Windows 网络无处不在~!

　　0X07 Java Serialization Bug

        

　　Java反序列化导致的漏洞原理上和PHP反序列一样，也是由于用户的输入可以控制我们传入的对象。如果服务端程序没有对用户可控的序列化代码进行校验而是直接进行反序列化使用，并且程序中运行一些比较危险的逻辑(如eval，登录验证等)，就会触发一些意想不到的漏洞。大名鼎鼎的WebLogic，JBoss，WebSphere、 OpenNMS、Jenkins... ...全部受此影响。

　　Contrast Security的Jeff Williams指出：这种反序列化类的缺陷，影响了面向对象编程中的构造对象，任何不精心严重的流数据均可影响之。研究人员发现了几种不同的方式来利用这种攻击，但肯定有很多更多的媒介，也正等待着被发现和利用。在网上，该漏洞也被成为2015年被低估的“破坏之王”。

　　0X08 glibc: getaddrinfo stack-based buffer overflow (CVE-2015-7547)

       

　　Google 的安全研究团队披露了glibc getaddrinfo溢出漏洞。经研究发现，所有Debian、Red Hat以及更多其它Linux发行版，只要glibc版本大于2.9就会受到该溢出漏洞影响。攻击者可以通过该漏洞直接批量获取大量主机权限。它影响了数以万计的应用程序，系统和嵌入式设备，包括网络路由器。

　　一个典型场景是，DNS Server Response返回过量的(2048 ) 字节, 导致接下来的response 触发栈溢出。只要使用glibc的getaddrinfo()进行DNS查询，而查询结果是黑客能控制的，那么就可能会被攻击。控制查询结果，可以通过控制DNS服务器，或者中间人攻击，或者控制域名本身(因为查询结果就是域名的信息)让受害者去查询。目前，所有主要的 Linux 发行版本和 glibc 项目均发布了针对这一问题的修补程序。

　　Duo Security的高级安全研究员Mark Loveless评价到：这是一个相当大的问题，因为 DNS 是互联网核心基础设施组件，而这个漏洞有处在 glibc，这使得在大多数 Linux 发行版中使用的核心组件暴露很多系统风险。

　　0X09 Bad USB

       

　　在2014年美国黑帽大会上，柏林SRLabs的安全研究人员JakobLell和独立安全研究人员Karsten Nohl展示了他们称为“BadUSB”(按照BadBIOS命名)的攻击方法，这种攻击方法让USB安全和几乎所有和USB相关的设备(包括具有USB端口的电脑)都陷入相当危险的状态。这是个非传统意义上的安全漏洞。然而，考虑到无处不在使用 USBs，其所涉问题是广泛且可怕的。

　　该漏洞是利用将恶意代码存放在USB设备控制器的固件存储区，而不是存放在其它可以通过USB接口进行读取的存储区域，比如Flash等，这样，杀毒软件或者普通的格式化操作是清除不掉该代码的。受害 USB 设备可以用于偷偷地进行大量的恶意任务包括偷窃数据和文件，安装恶意软件，重定向流量或感染其他 USB 设备。

　　而更为糟糕的是目前尚没有有效的缓解该威胁的方法。

　　0X10 VENOM Vulnerability (CVE-2015-3456)

        

　　CrowdStrike的Jason Geffner发现开源计算机仿真器QEMU中存在一个和虚拟软盘控制器相关的安全漏洞，代号VENOM(毒液)，CVE编号为CVE-2015-3456。利用此漏洞攻击者可以在有问题的虚拟机中进行逃逸,并且可以在宿主机中获得代码执行的权限。

　　毒液吸引了相当大关注的重要原因是，该漏洞为攻击者提供了突破虚拟机的一个方式，允许在相同的共享主机上的其他虚拟机上执行恶意代码。这使得很多人已经推测永远不可能存在一个安全的云环境~!
