# 互联网坏掉了：Facebook、Verizon、微软、苹果、Twitter遭遇重大故障

Verizon、Cloudflare、微软、Facebook、苹果和Twitter都遇到了问题。

  

![](../Images/7ef7f078b7794dd8f5c040afd667c8ad.png)

  

上周，Verizon造成了一次重大的BGP路由错误，导致互联网的大部分品牌（包括CDN公司Cloudflare）局部宕机了一天。本周，互联网的其余公司显然在步Verizon的后尘。

  

  

Cloudflare昨天再次宕机了半小时；这一回，问题出在这家公司自己的身上——我们还在等完整的事后分析报告出来，不过简短的分析报告表明：针对恶意Javascript的防火墙正则表达式规则导致防火墙的CPU使用率急剧上升，严重影响了吞吐量，导致广泛的HTTP 502错误。微软的Office365昨天似乎也遭到了数小时的局部宕机，其服务在一些ISP和路由上正常工作，但在其他ISP和路由上有四小时陷入瘫痪。

  

![](../Images/5f231912631bbee9e3003282007f5f08.png)

第三方用户在downdetector.com上报告Office365在7月2日出现局部故障  

  

Facebook及旗下的WhatsApp和Instagram在今天的大部分时间遭遇了与图像显示有关的大范围故障。这个问题似乎出在一些图像标记中，错误的时间戳数据馈送到该公司的CDN。我查看了我自己的Facebook时间线上的坏图像后发现，不同的时间戳参数嵌入到同样的URL中。使用错误的“oh =”和“oe =”参数（或者根本没有参数）从fbcdn.net加载图像导致了HTTP 403出错信息“错误的URL时间戳”。  

  

如果你深入研究代码，Facebook引用同样的图像URL，锚标记及图像标记中有不同的参数；在图像损坏的帖子中，锚标记中的URL正常工作，但图像标记中的URL却无法正常工作。（从好的方面来说，现在每个人突然注意到这家公司自2017年以来一直在图像中嵌入的AI驱动的隐藏式alt标记。）

  

Twitter的私信服务今天也遇到了一些尚未解释的故障。故障似乎主要发生在美国东部和欧洲，其他地区很少或根本没人在几个第三方故障跟踪网站上报告故障。

  

![](../Images/13d32c6234df06630709595400ba4d0b.png)

  

Twitter的私信服务在7月3日出现故障，如https://outage.report/twitter-direct-messages所示。

  

苹果的“系统状态”页面报告显示，iCloud的日历、联系人和提醒目前都受到持续中断的影响，某些用户可能也会受此影响。

  

下午7时左右，多名网友发微博称平台出现编辑图文无法保存或图片加载失败情况。之后，微信公众号登录界面也无法打开。

  

![](../Images/e3ede2c2e8b5a450662b46c9319f9458.png)

  

似乎没有任何共同的原因将这些故障关联起来，对互联网工程师来说这真是糟糕的一周。
