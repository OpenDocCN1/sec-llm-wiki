# 某次红蓝对抗之Solr-RCE实战绕过

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzAxMjE3ODU3MQ==&mid=2650550179&idx=4&sn=cb951f34fbdd80b73cdbdfc8ec6b208f&chksm=83bd4a47b4cac35132dadbf69ae11b4ac7ced6950b506b1cee34c86ebbb505cc705b1cc14562&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzAxMjE3ODU3MQ==&mid=2650550179&idx=4&sn=cb951f34fbdd80b73cdbdfc8ec6b208f&chksm=83bd4a47b4cac35132dadbf69ae11b4ac7ced6950b506b1cee34c86ebbb505cc705b1cc14562&scene=27#wechat_redirect)

**0x01 前言**

在某次红蓝对抗过程中，要结束的时候突然发现了扫描器爆出了Solr-RCE-CVE-2019-0192漏洞。

  

但是进行测试过程中发现存在各种各样的问题。

![](../Images/96ed73177c3122ace781e63b29e49b54.png)

  

**0x02 绕过1**

进行测试，发现目标只可以执行单命令，返回字段比较少的命令。  

*   
*   

```
whoamiipconfig
```

![](../Images/651e589245e135791db92ee9be9ef499.png)  

执行dir，无法执行。

![](../Images/5b778eb1ed972406852b08dd3632a5eb.png)

  
**注：**想着直接执行ps直接上线就好了，各种尝试之后，后知后觉发现对方不出网

  

**0x03 写Webshell**

发现目标不出网的时候，只有写webshell这一条路子可以走了。但是目标只能执行个别命令还无法解决。

![](../Images/38efb5ac62173ea87aa81007ab12f0f1.png)

  

dir无法执行，陷入了沉思，加入单双引号也不行。根据以前的内网经验是不是系统无法默认调用到dir.exe。  
那么 cmd /c dir是不是可以。![](../Images/f17d1bfabdc473f34ba872677e7cd5d4.png)

  

惊奇的发现，可以完美的执行命令。通过dir找到目录进行写马尝试。  
但是发现目标路由规则写死了，无法直接访问到.jsp的文件。![](../Images/ade910369674c707e47d5c7203d919cd.png)

  

刚开始以为是根目录的问题，发现不止根目录，常用的css/js和img下面的也不行。![](../Images/1eff6c73c29236454cf34b3de5ba48af.png)

  

后续在webshell中看到，翻文件看到了有类似路由机制的验证

![](../Images/ff7788fb56d8ad0f70ca81f002e9c977.png)

  

**0x04 言归正传**

在执行rce的时候，找到了solr的目录，发现这里的.jsp是没有这个验证的。  

![](../Images/2db88d3677c92cae5a69d55a502ffae2.png)  
利用命令执行进行找到该位置，进行写文件。问题来了。echo 写入一直无法写入。。![](../Images/44e83a035d2f1978467755d017ab138d.png)

  

**问题解决：**把这里的特殊字符进行编码后即可成功写入。  
又遇到一个问题，jsp的马子都有%号，这里不论怎么做 %就是写不进去。差点放弃，找不到不带%的马子。

  

**0x05 柳暗花明**

但是想到了上午利用过的Certutil可以进行编码解码，这样就没有特殊字符了。

![](../Images/d150ae48d1a792de95e269107d51d521.png)

  

完全没问题，刚开始一点一点追加，发现下面的会写进去两行![](../Images/375c9db6cb845435e7059d9f53f84a5c.png)

  

看了一下就最后有一个+号，没有特殊字符，全部直接写进去。![](../Images/c19e233f5bb164fb092684b2b6e22e49.png)

  

然后decode进行解码,完美。![](../Images/5fb0daa28e595af7baa279acc202b82b.png)![](../Images/ee88884292186b774b705746c8cccae0.png)

  

访问但是是500，不过确很开心，因为确实写上来。![](../Images/2f48fa39cdf5624100fbb25854b189d3.png)

  

接下来解决为啥500就可以了，type 123.jsp查看一下。![](../Images/9195e834ddfc36d8238e37f04ac93ede.png)

  

发现最后decode的时候，少了一个\>，本地测试，是没有这个问题的。可能是目标一次性字符长度的问题。  
这里很简单了，追加一下就可以了。![](../Images/d22aa4d5d1c1ee93ceb1ad18038f21cc.png)

  

连接成功![](../Images/9594671a90011ebd638bb8f6b1d3da36.png)
