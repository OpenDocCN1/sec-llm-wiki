# 针对微信小程序的渗透测试(附实战)

> 原文：[http://mp.weixin.qq.com/s?\_\_biz=MzAxMjE3ODU3MQ==&mid=2650562953&idx=3&sn=8cc66542b33c0c343e1c21b6fec2f6c0&chksm=83bd046db4ca8d7b30afa32a52ee56bcd9b42c7269045a42896fa3ba3fdef37a3072155b76c8&scene=27#wechat\_redirect](http://mp.weixin.qq.com/s?__biz=MzAxMjE3ODU3MQ==&mid=2650562953&idx=3&sn=8cc66542b33c0c343e1c21b6fec2f6c0&chksm=83bd046db4ca8d7b30afa32a52ee56bcd9b42c7269045a42896fa3ba3fdef37a3072155b76c8&scene=27#wechat_redirect)

![](../Images/495c0590f8941b6954000f1e159d52a9.png)

  

材料准备：

burp suite、模拟器(把微信装好)、node.js、wxappUnpacker、root explorer

操作流程：

步骤1: 配置Burp和模拟器（模拟器需导入ca证书），打开模拟器的WLAN-->高级设置-->输入物理机的ip以及一个没被占用的端口，Burp用于代理该端口

![](../Images/eadac400462f2c9300954a234811c7c2.png)

  

步骤2：打开微信-->随便点击一个小程序进入小程序主界面，然后打开文件管理器

  

![](../Images/e5ca06048b96ce6d2f2d2b7132533d1d.png)

 

 

在/data/data/com.tencent.mm/MicroMsg/xxxxxxx(不同微信文件夹也不同)/appbrand/pkg/目录下存放着刚才访问这个小程序的两个数据包，

 

![](../Images/1b97abc289e763ac0e71d7b5d6b331f2.png)

  

 

两个包分为子包和主包 

压缩后通过模拟器的微信发送到物理机进行反编译

![](../Images/11c0b998024cc3c95c9461b8b2692e59.png)

 

可以直接用notepad++ 但是会有乱码，这里使用git下载的wxappUnpacker进行反编译CMD进入wxappUnpacker的下载目录，安装依赖包

 复制 文本

 

![](../Images/37c63825eb6498c73abf67edcefd3d2b.png)

 

 

依赖包安装好后 使用命令node wuWxapkg.js C:\\xxxxxx\\xxxxxx\\\_-1971317095\_1.wxapkg

进行反编译(如果是子包的话需要加-s参数)

 

![](../Images/40925cda908efecca1d08c4637076a63.png)

反编译完成

接下来就是针对所有js、html进行漏洞分析，寻找突破口

![](../Images/81a56236a2a6c0f994ff5601346c0c1a.png)

 

![](../Images/fcf1477c15cc8198b0130b25f69414b7.png)

 

 

通过简单的信息收集得知该小程序是windows+iis7.5+.net+mssql80、443、3389端口开启从js中得到一个接口用于判断手机号是否注册  

![](../Images/3558a3a372dd62d73c19a13e16f55767.png)

 

通过单引号 和 '--（单引号+mssql闭合） 发现返回包不同 

 

使用单个单引号 报错:系统故障

 

![](../Images/d47336bdcf57da0b0797871162e31d17.png)

 

使用 单引号跟闭合 返回正确数据包  因此判断该处通过单引号闭合

 

![](../Images/de5b8395b1b28ef0ccb009934f14071c.png)

 

最后验证存在SQL注入

 

![](../Images/215aa43ba9e8790e156be56070ab2bfd.png)

 

注入点权限很小 --os-shell权限为iis且注入点只能布尔和延迟，列目录写shell属实浪费时间通过子域名扫描得到后台一枚，且发现该程序居然还是一个通用系统。。  

![](../Images/189e46d606b40b333790e86ca5453594.png)

![](../Images/8be3c056d424608b8087aedabe58c373.png)通过注入点拿到后台账号密码后 就是常规的渗透思路了，本文着重于微信公众号的反编译(最后好像有点跑题)，有不足之处希望私信留言指正！
