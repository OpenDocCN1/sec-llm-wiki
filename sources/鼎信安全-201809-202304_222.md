# **WordPress零日漏洞正在被利用**

**ThePlus Addons for Elementor WordPress****插件中发现的一个严重漏洞可能被利用来获得网站的管理特权。****WordPress****安全公司****Defiant****的****Wordfence****团队警告说，零日漏洞已被广泛利用。**

迄今为止，安装了30,000多个网站当中，The Plus Addons for Elementor是一个高级插件，是用来添加多个可与流行的WordPress网站构建器Elementor一起使用的小部件。

Wordfence解释说，已识别的问题位于添加的小部件之一中，该小部件提供了将用户登录和注册表单插入Elementor页面的功能。

研究人员发现，由于未正确配置功能，攻击者可以在易受攻击的站点上创建新的管理用户帐户，甚至以现有的管理用户身份登录。

建议所有安装有Elementor的Plus插件的用户停用并删除该插件，直到此零日发布修复程序为止。插件添加的所有注册或登录小部件都应删除，并不要在易受攻击的网站上进行注册。

研究人员还注意到，该插件的免费版本，即Elementor Lite的Plus插件，不受同一漏洞的影响。因此，用户应改用免费版本，直到解决漏洞为止。

“应该注意的是，即使您没有使用该插件创建的活动登录或注册页面，该漏洞仍然可以被利用。这意味着任何运行此插件的网站都容易受到攻击。

# **GitHub通知用户可能，“存在严重”的身份验证错误**

**GitHub****周一通知用户，它发现了所谓的****“****极其罕见但可能严重****”****的安全漏洞，该漏洞与某些经过身份验证的会话的处理方式有关。**

微软拥有的软件开发平台表示，该问题已于3月2日发现，并在3月5日推出了初始补丁。第二个补丁于3月8日发布，并且该公司于当天晚上决定使所有经过身份验证的会话均无效。彻底消除被大量攻击的可能性。

GitHub称此漏洞在2月8日至3月5日之间的不同时间存在，是由于竞态条件造成的，这种竞态条件在极少数情况下导致用户会话被路由到另一位经过身份验证的用户的浏览器，从而为第二位用户提供了第一个用户帐户的有效和经过身份验证的会话cookie。

“重要的是要注意，这个问题不是帐户密码，SSH密钥或个人访问令牌（PAT）受到破坏的结果，没有证据表明这是任何其他GitHub系统受到破坏的结果，”注意到GitHub最近任命的首席安全官MikeHanley 。“相反，此问题是由于罕见且孤立的不正确处理经过身份验证的会话造成的。此外，恶意用户不可能故意触发或定向此问题。”

汉利说，他们是从有关异常行为的外部报告中了解到此问题的。

不到0.001％的GitHub.com上经过身份验证的会话受到了影响，该公司表示，没有证据表明其他产品也受到了影响。

“出于谨慎考虑，并且出于对帐户安全性的强烈偏见，我们已使3月8日12:03 UTC之前在GitHub.com上创建的所有会话无效，甚至避免了仍然存在未被检测到的受感染会话的极小可能性修补此漏洞后，” Hanley解释说。

# **Apple位置跟踪系统中的缺陷可能导致用户信息泄漏**

**研究人员在本月发布的一份报告中说，离线查找（****OF****）中发现的漏洞（苹果专有的众包位置跟踪系统）可能被滥用造成用户信息泄漏。**

该系统于2019年推出，依靠蓝牙低功耗（BLE）技术检测\`\`丢失''的设备，并依靠所谓的\`\`查找器''设备的互联网连接将其位置报告给所有者。

苹果的OF网络中有“数以亿计”的设备，这代表了世界上最大的基于人群的位置跟踪系统，随着对非Apple设备的支持，它有望进一步发展。

苹果声称发现者是匿名的，称无法追踪设备所有者，并且位置报告是保密的，但是德国达姆施塔特技术大学的一群学术研究人员发现了可能导致用户信息泄漏的漏洞。

他们说，总的来说，该系统兑现了其对安全性和隐私性的承诺，但是两个设计和实现缺陷可能会导致位置关联攻击以及对过去7天位置历史记录的未经授权访问，从而实质上导致用户取消匿名。

“我们发现总体设计达到了苹果的特定目标。然而，我们发现两种截然不同的设计和执行的漏洞，似乎是苹果的威胁模型之外，但可以为用户带来严重的后果，”学者注意到在他们的研究论文。

研究人员发现，只要同一“发现者”报告了不同所有者的位置，便可以建立关联，这实际上将使苹果公司能够构建社交图谱。

此外，他们发现，由于“缓存的滚动广告密钥以明文形式存储在文件系统中”，恶意macOS应用程序有可能在过去7天为所有用户和设备检索和解密位置报告。

“作为服务提供者的苹果公司（可以推断两个或更多的所有者彼此之间距离很近，因为OF在上传和下载请求中都使用了可识别的信息。执法机构可以利用此问题来匿名化（政治）参与者演示，即使参与者将手机置于飞行模式也是如此。”研究人员指出。

但是，只有在受害者使用“查找我的应用程序”请求定位其设备的情况下，才可能利用此漏洞。研究人员解释说，问题在于，当下载或上传位置报告时，便会显示发现者和所有者设备的身份。

此外，研究人员还发现了macOS上OF实施中的一个安全漏洞，该漏洞可能允许恶意应用程序未经同意即可访问所有所有者设备的位置，从而完全规避了Apple的受限位置API。此外，位置历史记录可能被滥用来生成配置文件和标识用户。

研究人员解释说，该系统假定设备的广告密钥的私有部分仅是用户已知的，并且这些密钥每15分钟更改一次。由于OF允许在一周内检索位置报告，因此苹果服务器上存在总计672个广告密钥的潜在位置报告。

这些广告密钥可能出于性能原因而被缓存，并且在macOS上将它们存储在本地用户和以用户权限运行的任何应用程序可访问的目录中。在iOS上无法访问缓存文件。

研究人员解释说，以用户权限运行的恶意应用程序可以访问密钥缓存目录并读取广告密钥或将其泄露给攻击者，而无需启动应用程序而无需其他用户交互。

有了所有者的密钥，攻击者就可以将受害者的位置报告下载到他们的计算机上，并使用相同的密钥来解密这些报告。

“该攻击实质上使任何第三方应用程序都可以绕过Apple的Core Location API，该API会在应用程序访问设备位置之前强制执行用户的同意。而且，攻击者可以访问所有所有者设备过去7天的位置历史记录。”研究人员解释说。

所发现的漏洞负责向Apple披露，并于2020年9月发布了补丁。Apple将该漏洞称为CVE-2020-9986，将其描述为“文件访问问题”，已通过改善访问限制解决了该问题。
